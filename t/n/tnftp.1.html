TNFTP(1) Manual de comandos generales TNFTP(1)

NOMBRE

tnftp — Programa de transferencia de archivos de Internet

SINOPSIS

tnftp [-46AadefginpRtVv?] [-N netrc] [-o salida] [-P puerto] [-q tiempodesalida] [-r reintento] [-s direccionorigen] [-T dir,max[,inc]] [-x tamanotransferencia] [[usuario@]host [puerto]] [[usuario@]host:[ruta][/]] [file:///ruta] [ftp://[usuario[:contraseña]@]host[:puerto]/ruta[/][;type=tipo]] [http://[usuario[:contraseña]@]host[:puerto]/ruta] [https://[usuario[:contraseña]@]host[:puerto]/ruta] ...

tnftp -u url archivo ...

DESCRIPCIÓN

tnftp es la interfaz de usuario para el protocolo estándar de Internet de Transferencia de Archivos. El programa permite a un usuario transferir archivos desde y hacia un sitio de red remoto.

Los últimos cinco argumentos obtendrán un archivo usando los protocolos FTP o HTTP, o mediante copia directa, en el directorio actual. Esto es ideal para scripts. Consulte AUTO-FETCHING FILES abajo para más información.

Las opciones pueden especificarse en la línea de comandos, o al intérprete de comandos.

-4
Fuerza a tnftp a usar solo direcciones IPv4.
-6
Fuerza a tnftp a usar solo direcciones IPv6.
-A
Forzar modo activo FTP. Por defecto, tnftp intentará usar modo pasivo FTP y recurrirá al modo activo si el servidor no lo soporta. Esta opción hace que tnftp siempre use una conexión activa. Solo es útil para conectarse a servidores muy antiguos que no implementan el modo pasivo correctamente.
-a
Hace que tnftp omita el procedimiento normal de inicio de sesión, y use un inicio de sesión anónimo en su lugar.
-d
Habilita la depuración.
-e
Deshabilita la edición de línea de comandos. Esto es útil para el modo Emacs ange-ftp.
-f
Fuerza una recarga de caché para transferencias que pasan a través de proxies FTP o HTTP.
-g
Deshabilita el globbing de nombres de archivo.
-i
Desactiva las indicaciones interactivas durante transferencias de múltiples archivos.
-N netrc
Usa netrc en lugar de ~/.netrc. Consulte EL ARCHIVO .netrc para más información.
-n
Restringe a tnftp de intentar el “auto-login” al conectarse inicialmente para transferencias que no son de auto-carga. Si el auto-login está habilitado, tnftp verificará el archivo .netrc (ver abajo) en el directorio principal del usuario para una entrada que describa una cuenta en la máquina remota. Si no existe ninguna entrada, tnftp pedirá el nombre de inicio de sesión de la máquina remota (por defecto es la identidad del usuario en la máquina local) y, si es necesario, pedirá una contraseña y una cuenta con las que iniciar sesión. Para anular el auto-login para transferencias de auto-carga, especifique el nombre de usuario (y opcionalmente, la contraseña) según corresponda.
-o salida
Al obtener archivos automáticamente, guarda el contenido en salida. salida se analiza según las CONVENCIONES DE NOMBRADO DE ARCHIVOS abajo. Si salida no es ‘-’ o no empieza con ‘|’, entonces solo el primer archivo especificado se recuperará en salida; todos los demás archivos se recuperarán en el nombre base de su nombre remoto.
-P puerto
Establece el número de puerto a puerto.
-p
Habilita el modo pasivo para usarlo detrás de firewalls de filtrado de conexión. Esta opción ha sido desaprobada ya que tnftp ahora intenta usar el modo pasivo por defecto, recurriendo al modo activo si el servidor no soporta conexiones pasivas.
-q tiempodesalida
Salir si la conexión se ha estancado durante tiempodesalida segundos.
-R
Reiniciar todas las auto-cargas no proxy.
-r espera
Reintentar el intento de conexión si falló, pausando durante espera segundos.
-s direccionorigen
Utiliza direccionorigen como la dirección IP local para todas las conexiones.
-t
Habilita el rastreo de paquetes.
-T direccion,maximo[,incremento]
Establece la tasa máxima de transferencia para direccion a maximo bytes/segundo, y si se especifica, el incremento a incremento bytes/segundo. Consulte rate para más información.
-u url archivo ...
Sube archivos en la línea de comandos a url donde url es uno de los tipos de URL ‘ftp://’ compatibles con la auto-carga (con un nombre de archivo de destino opcional para cargas de un solo archivo), y archivo es uno o más archivos locales para ser subidos.
-V
Deshabilita verbose y progress, anulando el valor por defecto de habilitado cuando la salida es a una terminal.
-v
Habilita verbose y progress. Este es el valor por defecto si la salida es a una terminal (y en el caso de progress, tnftp es el proceso en primer plano). Fuerza tnftp para mostrar todas las respuestas del servidor remoto, así como para informar sobre las estadísticas de transferencia de datos.
-x tamaño_transfer
Establece el tamaño de los búferes de envío y recepción del socket a tamaño_transfer. Consulte xferbuf para obtener más información.
-?
Muestra la ayuda en la salida estándar y sale.

El host del cliente con el que tnftp debe comunicarse puede especificarse en la línea de comandos. Si se hace esto, tnftp intentará inmediatamente establecer una conexión con un servidor FTP en ese host; de lo contrario, tnftp entrará en su intérprete de comandos y esperará instrucciones del usuario. Cuando tnftp está esperando comandos del usuario, se le presenta al usuario el prompt ‘ftp>’. Los siguientes comandos son reconocidos por tnftp:

! [comando [argumentos]]
Invoca un shell interactivo en la máquina local. Si hay argumentos, el primero se toma como un comando a ejecutar directamente, con el resto de los argumentos como sus argumentos.
$ nombre_macro [argumentos]
Ejecuta la macro nombre_macro que fue definida con el comando macdef. Los argumentos se pasan a la macro sin expansiones.
account [contraseña]
Suministra una contraseña adicional requerida por un sistema remoto para acceder a los recursos una vez que se ha completado un inicio de sesión exitosamente. Si no se incluye ningún argumento, se le pedirá al usuario una contraseña de cuenta en modo de entrada sin eco.
append archivo_local [archivo_remoto]
Añade un archivo local a un archivo en la máquina remota. Si archivo_remoto se deja sin especificar, se utiliza el nombre del archivo local al nombrar el archivo remoto, después de haber sido alterado por cualquier configuración de ntrans o nmap. La transferencia de archivos utiliza la configuración actual de type, format, mode y structure.
ascii
Establece el type de transferencia de archivos a ASCII de red. Este es el tipo predeterminado.
bell
Dispone que suene una campana después de completar cada comando de transferencia de archivos.
binary
Establece el type de transferencia de archivos para soportar la transferencia de imágenes binarias.
bye
Termina la sesión FTP con el servidor remoto y sale de tnftp. Un fin de archivo también terminará la sesión y saldrá.
case
Alterna el mapeo de mayúsculas/minúsculas de los nombres de archivo del ordenador remoto durante los comandos get, mget y mput. Cuando case está activado (por defecto está desactivado), los nombres de archivo del ordenador remoto con todas las letras en mayúsculas se escriben en el directorio local con las letras mapeadas a minúsculas.
cd directorio_remoto
Cambia el directorio de trabajo en la máquina remota a directorio_remoto.
cdup
Cambia el directorio de trabajo de la máquina remota al padre del directorio de trabajo remoto actual.
chmod modo archivo_remoto
Cambia los modos de permiso del archivo archivo_remoto en el sistema remoto a modo.
close
Termina la sesión FTP con el servidor remoto y regresa al intérprete de comandos. Se borran todas las macros definidas.
cr
Alterna el stripping del retorno de carro durante la recuperación de archivos de tipo ascii. Los registros se denotan por una secuencia de retorno de carro/nueva línea durante la transferencia de archivos de tipo ascii. Cuando cr está activado (por defecto), los retornos de carro se eliminan de esta secuencia para cumplir con el delimitador de registro de una sola nueva línea de UNIX. Los registros en sistemas remotos no UNIX pueden contener nuevas líneas únicas; cuando se realiza una transferencia de tipo ascii, estas nuevas líneas solo pueden distinguirse de un delimitador de registro cuando cr está desactivado.
debug [valor_debug]
Alterna el modo de depuración. Si se especifica un valor_debug opcional, se utiliza para establecer el nivel de depuración. Cuando la depuración está activada, tnftp imprime cada comando enviado a la máquina remota, precedido por la cadena ‘-->’.
delete archivo_remoto
Elimina el archivo archivo_remoto en la máquina remota.
dir [ruta_remota [archivo_local]]
Imprime un listado del contenido de un directorio en la máquina remota. El listado incluye cualquier información dependiente del sistema que el servidor elija incluir; por ejemplo, la mayoría de los sistemas UNIX producirán la salida del comando ‘ls -l’. Si ruta_remota se deja sin especificar, se utiliza el directorio de trabajo actual. Si el aviso interactivo está activado, tnftp preguntará al usuario para verificar que el último argumento es efectivamente el archivo local de destino para recibir la salida de dir. Si no se especifica ningún archivo local, o si archivo_local es ‘-’, la salida se envía a la terminal.
disconnect
Un sinónimo de close.
edit
Alterna la edición de línea de comandos y la completación de comandos y archivos sensible al contexto. Esto se habilita automáticamente si la entrada proviene de un terminal, y se desactiva en caso contrario.
epsv, epsv4, epsv6
Alterna el uso de los comandos extendidos EPSV y EPRT en todas las conexiones IP, IPv4 e IPv6 respectivamente. Primero intenta EPSV/EPRT, y luego PASV/PORT. Esto está habilitado por defecto. Si un comando extendido falla, esta opción se deshabilitará temporalmente durante la conexión actual, o hasta que se ejecute de nuevo epsv, epsv4 o epsv6.
exit
Un sinónimo de bye.
features
Muestra las características que soporta el servidor remoto (usando el comando FEAT comando).
fget archivo_local
Recupera los archivos listados en archivo_local, que contiene un nombre de archivo por línea.
form formato
Establece el form de transferencia de archivos a formato. El formato predeterminado (y único soportado) es ‘non-print’.
ftp host [puerto]
Un sinónimo de open.
gate [host [puerto]]
Alterna el modo gate-ftp, que se utilizaba para conectarse a través de los proxies TIS FWTK y Gauntlet FTP. Esto no se permitirá si el servidor gate-ftp no ha sido configurado (ya sea explícitamente por el usuario, o desde la variable de entorno FTPSERVER). Si se proporciona host, entonces se habilitará el modo gate-ftp y el servidor gate-ftp se establecerá en host. Si también se proporciona puerto, se utilizará como el puerto al que conectarse en el servidor gate-ftp.
get archivo_remoto [archivo_local]
Recupera el archivo_remoto y lo almacena en la máquina local. Si no se especifica el nombre del archivo local, se le da el mismo nombre que tiene en la máquina remota, sujeto a alteración por la configuración actual de case, ntrans y nmap. Se utilizan las configuraciones actuales de type, form, mode y structure durante la transferencia del archivo.
glob
Alterna la expansión de nombres de archivo para mdelete, mget, mput y mreget. Si se desactiva el globbing con glob, los argumentos de los nombres de archivo se toman literalmente y no se expanden. El globbing para mput se realiza como en csh(1). Para mdelete, mget y mreget, cada nombre de archivo remoto se expande por separado en la máquina remota y las listas no se fusionan. La expansión
del directorio remoto es probable que sea diferente de la expansión del nombre de un archivo ordinario: el resultado exacto depende del sistema operativo extranjero y del servidor FTP, y puede ser previsualizado haciendo ‘mls remote-files -’. Nota: mget, mput y mreget no están diseñados para transferir subárboles completos de directorios de archivos. Eso se puede hacer transfiriendo un archivo tar(1) del subárbol (en modo binario).
hash [tamaño]
Activa o desactiva la impresión del signo de almohadilla (‘#’) para cada bloque de datos transferido. El tamaño de un bloque de datos por defecto es 1024 bytes. Esto se puede cambiar especificando tamaño en bytes. Habilitar hash deshabilita progress.
help [comando]
Imprime un mensaje informativo sobre el significado de comando. Si no se proporciona ningún argumento, tnftp imprime una lista de los comandos conocidos.
idle [segundos]
Establece el temporizador de inactividad en el servidor remoto a segundos segundos. Si se omite segundos, se imprime el temporizador de inactividad actual.
image
Un sinónimo de binary.
lcd [directorio]
Cambia el directorio de trabajo en la máquina local. Si no se especifica ningún directorio, se utiliza el directorio personal del usuario.
less archivo
Un sinónimo de page.
lpage archivo-local
Muestra archivo-local con el programa especificado por la opción set pager.
lpwd
Imprime el directorio de trabajo en la máquina local.
ls [ruta-remota [archivo-local]]
Un sinónimo de dir.
macdef nombre-macro
Define una macro. Las líneas subsiguientes se almacenan como la macro nombre-macro; una línea nula (caracteres de nueva línea consecutivos en un archivo o retornos de carro desde la terminal) termina el modo de entrada de macro. Hay un límite de 16 macros y 4096 caracteres totales en todas las macros definidas. Los nombres de macro pueden tener un máximo de 8 caracteres. Las macros solo son aplicables a la sesión actual en la que se definen (o si se definen fuera de una sesión, a la sesión invocada con el siguiente comando open) y permanecen definidas hasta que se ejecuta un comando close. Para invocar una macro, use el comando $ (ver arriba).

El procesador de macros interpreta ‘$’ y ‘\’ como caracteres especiales. Un ‘$’ seguido de un número (o números) se reemplaza por el argumento correspondiente en la línea de comandos de invocación de la macro. Un ‘$’ seguido de una ‘i’ indica al procesador de macros que la macro que se está ejecutando debe repetirse. En el primer pase, ‘$i’ se reemplaza por el primer argumento en la línea de comandos de invocación de la macro, en el segundo pase se reemplaza por el segundo argumento, y así sucesivamente. Un ‘\’ seguido de cualquier carácter se reemplaza por ese carácter. Utilice el ‘\’ para evitar el tratamiento especial del ‘$’.

mdelete [archivos-remotos]
Elimina los archivos-remotos en la máquina remota.
mdir archivos-remotos archivo-local
Similar a dir, excepto que se pueden especificar varios archivos remotos. Si la solicitud interactiva está activada, tnftp solicitará al usuario que verifique que el último argumento es efectivamente el archivo local de destino para recibir la salida de mdir.
mget archivos-remotos
Expande los archivos-remotos en la máquina remota y realiza un get para cada nombre de archivo producido. Consulte glob para obtener detalles sobre la expansión de nombres de archivo. Los nombres de archivo resultantes se procesarán de acuerdo con las configuraciones de case, ntrans y nmap. Los archivos se transfieren al directorio de trabajo local, que se puede cambiar con lcd directorio; se pueden crear nuevos directorios locales con ! mkdir directorio.
mkdir nombre-directorio
Crea un directorio en la máquina remota.
mls archivos-remotos archivo-local
Similar a ls, excepto que se pueden especificar varios archivos remotos, y el archivo-local debe ser especificado. Si la solicitud interactiva está activada, tnftp solicitará al usuario que verifique que el último argumento es efectivamente el archivo local de destino para recibir la salida de mls.
mlsd [ruta-remota]
Muestra el contenido de ruta-remota (que debería ser por defecto el directorio actual si no se proporciona) en un formato que una máquina pueda analizar, utilizando MLSD. El formato de visualización se puede cambiar con ‘remopts mlst ...’.
mlst [ruta-remota]
Muestra los detalles sobre ruta-remota (que debería ser por defecto el directorio actual si no se proporciona) en un formato que una máquina pueda analizar, utilizando MLST. El formato de visualización se puede cambiar con ‘remopts mlst ...’.
mode nombre-modo
Establece el modo de transferencia de archivos a nombre-modo. El modo por defecto (y el único soportado) es ‘stream’.
modtime archivo-remoto
Muestra la hora de la última modificación del archivo en la máquina remota, en formato RFC 2822.
more archivo
Un sinónimo de page.
mput archivos-locales
Expande comodines en la lista de archivos locales proporcionados como argumentos y realiza un put para cada archivo en la lista resultante. Consulte glob para obtener detalles sobre la expansión de nombres de archivo. Los nombres de archivo resultantes se procesarán de acuerdo con las configuraciones de ntrans y nmap.
mreget archivos-remotos
Como mget, pero realiza un reget en lugar de get.
msend archivos-locales
Un sinónimo de mput.
newer archivo-remoto [archivo-local]
Obtiene el archivo solo si la hora de modificación del archivo remoto es más reciente que la del archivo en el sistema actual. Si el archivo no existe en el sistema actual, el archivo remoto se considera newer. De lo contrario, este comando es idéntico a get.
nlist [ruta-remota [archivo-local]]
Un sinónimo de ls.
nmap [patrón-entrada patrón-salida]
Establece o deshabilita el mecanismo de mapeo de nombres de archivo. Si no se proporcionan argumentos, el mecanismo de mapeo de nombres de archivo se deshabilita. Si se proporcionan argumentos, los nombres de archivo remotos se mapean durante los comandos mput y los comandos put emitidos sin un nombre de archivo remoto de destino especificado. Si se proporcionan argumentos, los nombres de archivo locales se mapean durante los comandos mget y los comandos get emitidos sin un nombre de archivo local de destino especificado. Este comando es útil al conectarse a un ordenador remoto no UNIX con diferentes convenciones o prácticas de nombres de archivo. El mapeo sigue el patrón establecido por patrón-entrada y patrón-salida.

patrón-entrada es una plantilla para los nombres de archivo entrantes (que ya pueden haber sido procesados de acuerdo con las configuraciones de ntrans y case). La creación de plantillas de variables se logra incluyendo las secuencias ‘$1’, ‘$2’, ..., ‘$9’ en patrón-entrada. Utilice ‘\’ para evitar este tratamiento especial del carácter ‘$’. Todos los demás caracteres se tratan literalmente y se utilizan para determinar

nmap [inpattern] valores de variables. Por ejemplo, dado ‘inpattern ’$1.$2’ y el nombre de archivo remoto ‘mydata.data’, ‘$1’ tendría el valor ‘mydata’, y ‘$2’ tendría el valor ‘data’.

El outpattern determina el nombre de archivo resultante. Las secuencias ‘$1’, ‘$2’, ..., ‘$9’ se reemplazan por cualquier valor resultante de la plantilla inpattern. La secuencia ‘$0’ se reemplaza por el nombre de archivo original. Además, la secuencia [seq1,seq2] se reemplaza por seq1 si seq1 no es una cadena nula; de lo contrario, se reemplaza por seq2. Por ejemplo, el comando

nmap $1.$2.$3 [$1,$2].[$2,file]

produciría el nombre de archivo de salida ‘myfile.data’ para los nombres de archivo de entrada ‘myfile.data’ y ‘myfile.data.old’, ‘myfile.file’ para el nombre de archivo de entrada ‘myfile’, y ‘myfile.myfile’ para el nombre de archivo de entrada ‘.myfile’. Se pueden incluir espacios en outpattern, como en el ejemplo:

nmap $1 sed s/ *$// > $1

Utilice el carácter ‘\’ para evitar el tratamiento especial de los caracteres ‘$’, ‘[’, ‘]’ y ‘,’.

ntrans [inchars [outchars]]
Establece o anula el mecanismo de traducción de caracteres de nombres de archivo. Si no se especifican argumentos, se anula el mecanismo de traducción de caracteres de nombres de archivo. Si se especifican argumentos, los caracteres de los nombres de archivo remotos se traducen durante los comandos mput y put emitidos sin un nombre de archivo remoto especificado. Si se especifican argumentos, los caracteres de los nombres de archivo locales se traducen durante los comandos mget y get emitidos sin un nombre de archivo local especificado. Este comando es útil al conectarse a un ordenador remoto no UNIX con diferentes convenciones o prácticas de nombres de archivo. Los caracteres de un nombre de archivo que coinciden con un carácter en inchars se reemplazan por el carácter correspondiente en outchars. Si la posición del carácter en inchars es mayor que la longitud de outchars, el carácter se elimina del nombre del archivo.
open host [port]
Establece una conexión al servidor FTP host especificado. Se puede proporcionar un número de puerto opcional, en cuyo caso, tnftp intentará contactar a un servidor FTP en ese puerto. Si la opción set auto-login está activada (por defecto), tnftp también intentará iniciar sesión automáticamente al usuario en el servidor FTP (ver abajo).
page file
Recupera file y lo muestra con el programa especificado por la opción set pager.
passive [auto]
Alterna el modo pasivo (si no se proporcionan argumentos). Si se proporciona auto, actúa como si FTPMODE estuviera configurado como ‘auto’. Si el modo pasivo está activado (por defecto), tnftp enviará un comando PASV para todas las conexiones de datos en lugar de un comando PORT. El comando PASV solicita que el servidor remoto abra un puerto para la conexión de datos y devuelva la dirección de ese puerto. El servidor remoto escucha en ese puerto y el cliente se conecta a él. Al usar el comando PORT más tradicional, el cliente escucha en un puerto y envía esa dirección al servidor remoto, quien se conecta a ella. El modo pasivo es útil al usar tnftp a través de un enrutador o host de puerta de enlace que controla la direccionalidad del tráfico. (Tenga en cuenta que aunque los servidores FTP deben admitir el comando PASV según la RFC 1123, algunos no lo hacen).
pdir [remote-path]
Ejecuta dir [remote-path] y muestra el resultado con el programa especificado por la opción set pager.
pls [remote-path]
Ejecuta ls [remote-path] y muestra el resultado con el programa especificado por la opción set pager.
pmlsd [remote-path]
Ejecuta mlsd [remote-path] y muestra el resultado con el programa especificado por la opción set pager.
preserve
Alterna la preservación de las horas de modificación en los archivos recuperados.
progress
Alterna la visualización de la barra de progreso de transferencia. La barra de progreso se deshabilitará para una transferencia que tenga local-file como ‘-’ o un comando que comience con ‘|’. Consulte CONVENCIONES DE NOMBRADO DE ARCHIVOS para obtener más información. Habilitar progress deshabilita hash.
prompt
Alterna el aviso interactivo. El aviso interactivo ocurre durante las transferencias de archivos múltiples para permitir al usuario seleccionar archivos para recuperar o almacenar. Si el aviso está desactivado (por defecto está activado), cualquier mget o mput transferirá todos los archivos, y cualquier mdelete eliminará todos los archivos.

Cuando el aviso está activado, los siguientes comandos están disponibles en un aviso:

a
Responde ‘sí’ al archivo actual y responde automáticamente ‘sí’ a cualquier archivo restante para el comando actual.
n
Responde ‘no’ y no transfiere el archivo.
p
Responde ‘sí’ al archivo actual y desactiva el modo de aviso (como si se hubiera ejecutado prompt off).
q
Termina la operación actual.
y
Responde ‘sí’ y transfiere el archivo.
?
Muestra un mensaje de ayuda.

Cualquier otra respuesta responderá ‘sí’ al archivo actual.

proxy ftp-command
Ejecuta un comando FTP en una conexión de control secundaria. Este comando permite la conexión simultánea a dos servidores FTP remotos para transferir archivos entre los dos servidores. El primer comando proxy debe ser un open, para establecer la conexión de control secundaria. Introduzca el comando ‘proxy ?’ para ver otros comandos FTP ejecutables en la conexión secundaria. Los siguientes comandos se comportan de manera diferente cuando van precedidos por proxy: open no definirá nuevas macros durante el proceso de inicio de sesión automático, close no borrará las definiciones de macros existentes, get y mget transfieren archivos del host en la conexión de control primaria al host en la conexión de control secundaria, y put, mput y append transfieren archivos del host en la conexión de control secundaria al host en la conexión de control primaria. Las transferencias de archivos de terceros dependen de la compatibilidad con el comando PASV del protocolo FTP por parte del servidor en la conexión de control secundaria.
put local-file [remote-file]
Almacena un archivo local en la máquina remota. Si remote-file se deja sin especificar, se utiliza el nombre del archivo local después de procesarlo según cualquier configuración de ntrans o nmap al nombrar el archivo remoto. La transferencia de archivos utiliza la configuración actual de type, format, mode y structure.
pwd
Imprime el nombre del directorio de trabajo actual en la máquina remota.
quit
Un sinónimo de bye.

FTP Commands

AUTO-FETCHING FILES

Además de los comandos estándar, esta versión de tnftp admite una función de auto-recuperación. Para habilitar la auto-recuperación, simplemente pase la lista de nombres de host/archivos en la línea de comandos.

Los siguientes formatos son sintaxis válida para un elemento de auto-recuperación:

[user@]host:[path][/]
Formato FTP "clásico".

Si path contiene un carácter de expansión y la expansión está habilitada (ver glob), se realiza el equivalente a mget path.

Si el componente de directorio de path no contiene caracteres de expansión, se almacena localmente con el nombre `basename` (ver basename(1)) de path, en el directorio actual. De lo contrario, se utiliza el nombre remoto completo como nombre local, relativo al directorio raíz local.

ftp://[user[:password]@]host[:port]/path[/][;type=type]
Una URL FTP, recuperada utilizando el protocolo FTP si set ftp_proxy no está definido. De lo contrario, transfiera la URL utilizando HTTP a través del proxy definido en set ftp_proxy. Si set ftp_proxy no está definido y se proporciona user, inicie sesión como user. En este caso, utilice password si se proporciona, de lo contrario solicite al usuario que introduzca una.

Si se proporciona un sufijo de ‘;type=A’ o ‘;type=I’, el tipo de transferencia será ascii o binario (respectivamente). El tipo de transferencia predeterminado es binario.

Para cumplir con RFC 3986, tnftp interpreta la parte path de una URL de auto-recuperación ‘ftp://’ de la siguiente manera:

  • El ‘/’ inmediatamente después del host[:port] se interpreta como un separador antes de path, y no como parte de path en sí.
  • El path se interpreta como una lista de componentes de nombre separados por ‘/’. Para todos los componentes, excepto el último, tnftp realiza el equivalente a un comando cd. Para el último componente de ruta, tnftp realiza el equivalente a un comando get.
  • Los componentes de nombre vacíos, que resultan de ‘//’ dentro de path, o de un ‘/’ adicional al principio de path, causarán el equivalente a un comando cd sin nombre de directorio. Es poco probable que esto sea útil.
  • Cualquier código ‘%XX’ (según RFC 3986) dentro de los componentes de ruta se decodifica, donde XX representa un código de carácter en hexadecimal. Esta decodificación se realiza después de que path se haya dividido en componentes, pero antes de que cada componente se utilice en el equivalente de un comando cd o get. Algunos códigos de uso frecuente son ‘%2F’ (que representa ‘/’) y ‘%7E’ (que representa ‘~’).

La interpretación anterior tiene las siguientes consecuencias:

  • La ruta se interpreta en relación con el directorio de inicio de sesión predeterminado del usuario especificado o del usuario ‘anonymous’. Si se requiere el directorio /, utilice una ruta inicial de ‘%2F’. Si se requiere el directorio de inicio del usuario (y el servidor remoto admite la sintaxis), utilice una ruta inicial de ‘%7Euser/’. Por ejemplo, para recuperar /etc/motd de ‘localhost’ como el usuario ‘myname’ con la contraseña ‘mypass’, use ‘ftp://myname:mypass@localhost/%2fetc/motd’
  • Los comandos exactos cd y get pueden controlarse mediante una elección cuidadosa de dónde usar ‘/’ y dónde usar ‘%2F’ (o ‘%2f’). Por ejemplo, las siguientes URLs corresponden a los equivalentes de los comandos indicados:
    ftp://host/dir1/dir2/file
    cd dir1, cd dir2, get file.
    ftp://host/%2Fdir1/dir2/file
    cd /dir1, cd dir2, get file.
    ftp://host/dir1%2Fdir2/file
    cd dir1/dir2, get file.
  • Debe tener permiso de acceso apropiado para cada uno de los directorios intermedios que se utilizan en el equivalente a un comando cd.

The .netrc File

The .netrc file is a text file in the user’s home directory that contains accounting information and defaults for the FTP client. The file format is:

machine name
login name
password string
account string

Each entry consists of one or more lines. Lines beginning with a ‘#’ are comments. The following tokens are recognized:

machine name
Specifies the name of the remote machine to connect to. The name is the same name used in the ftp command. All subsequent entries in the .netrc file are applicable only to this machine entry, until another machine entry is encountered. If no machine entry is found that matches the target host name, the default entry is used.
login name
Specifies the user name to be used for logging into the remote machine. If this token is omitted, the user’s login name is used. If the auto-login process is invoked and no login token is present for the specified machine, the user is prompted for a login name.
password string
Specifies the password to be used for logging into the remote machine. If this token is omitted, the user is prompted for a password. If the auto-login process is invoked and no password token is present for the specified machine, the user is prompted for a password.

It is strongly recommended that passwords not be stored in the .netrc file. Consider using the getpass command in the .inputrc file to prompt for passwords instead.

account string
Supply an additional account password. If this token is present, the auto-login process will supply the specified string if the remote server requires an additional account password, or the auto-login process will initiate an ACCT command if it does not.
macdef name
Define a macro. This token functions like the tnftp macdef command functions. A macro is defined with the specified name; its contents begin with the next .netrc line and continue until a blank line (consecutive new-line characters) is encountered. Like the other tokens in the .netrc file, a macdef is applicable only to the machine definition preceding it. A macdef entry cannot be used by multiple machine definitions; rather, it must be defined following each machine it is intended to be used with. If a macro named init is defined, it is automatically executed as the last step in the auto-login process. For example, 
default
macdef init
epsv4 off

followed by a blank line.

COMMAND LINE EDITING

tnftp supports interactive command line editing, via the editline(3) library. It is enabled with the edit command, and is enabled by default if input is from a tty. Previous lines can be recalled and edited with the arrow keys, and other GNU Emacs-style editing keys may be used as well.

The editline(3) library is configured with a .editrc file — refer to editrc(5) for more information.

An extra key binding is available to tnftp to provide context sensitive command and filename completion (including remote file completion). To use this, bind a key to the editline(3) command ftp-complete. By default, this is bound to the TAB key.

COMMAND LINE PROMPT

By default, tnftp displays a command line prompt of ‘ftp> ’ to the user. This can be changed with the set prompt command.

A prompt can be displayed on the right side of the screen (after the command input) with the set rprompt command.

The following formatting sequences are replaced by the given information:

%/
The current remote working directory.
%c[[0]n], %.[[0]n]
The trailing component of the current remote working directory, or n trailing components if a digit n is given. If n begins with ‘0’, the number of skipped components precede the trailing component(s) in the format “/<number>trailing” (for ‘%c’) or “...trailing” (for ‘%.’).
%M
The remote host name.
%m
The remote host name, up to the first dot ‘.’.
%n
The remote user name.
%%
A single percent character ‘%’.

EXTENDED PASSIVE MODE AND FIREWALLS

Some firewall configurations do not allow tnftp to use extended passive mode. If you find that even a simple ls appears to hang after printing a message such as this:

229 Entering Extended Passive Mode (|||58551|)

then you will need to disable extended passive mode with epsv4 off. See the above section The .netrc File for an example of how to make this automatic.

ERRORES

La ejecución correcta de muchos comandos depende del comportamiento adecuado del servidor remoto.

Se ha corregido un error en el tratamiento de los retornos de carro en el código de transferencia en modo ascii de 4.2BSD. Esta corrección puede resultar en transferencias incorrectas de archivos binarios hacia y desde servidores 4.2BSD utilizando el tipo ascii. Evite este problema utilizando el tipo de imagen binaria.

tnftp asume que todas las direcciones mapeadas a IPv4 (direcciones IPv6 con una forma como ::ffff:10.1.1.1) indican destinos IPv4 que pueden ser manejados por sockets AF_INET. Sin embargo, en ciertas configuraciones de red IPv6, esta suposición no es cierta. En dicho entorno, las direcciones mapeadas a IPv4 deben pasarse directamente a sockets AF_INET6. Por ejemplo, si su sitio utiliza un traductor SIIT para la traducción de IPv6 a IPv4, tnftp no puede soportar su configuración.
