TRACE-CMD-RESET(1) Manual de libtracefs TRACE-CMD-RESET(1)

NOMBRE

trace-cmd-reset - desactiva todo el rastreo Ftrace para devolver el rendimiento completo

SINOPSIS

trace-cmd reset [OPCIONES]

DESCRIPCIÓN

El comando trace-cmd(1) reset desactiva todo el rastreo de Ftrace. Esto devolverá el rendimiento del sistema al estado anterior a la activación del rastreo. Esto es necesario ya que trace-cmd-record(1), trace-cmd-stop(1) y trace-cmd-extract(1) no deshabilitan el rastreador, incluso después de que los datos se hayan extraído de los búferes. La razón es que el usuario puede querer habilitar manualmente el rastreador con el sistema de archivos pseudo Ftrace, o examinar otras partes de Ftrace para ver lo que hizo trace-cmd. Después de ejecutar el comando reset, los datos en el búfer circular y las opciones que se usaron se pierden.

OPCIONES

Tenga en cuenta que el orden en que se especifican las opciones en la línea de comandos es significativo. Ver EJEMPLOS.

-b tamaño_del_búfer

Cuando el kernel arranca, el búfer circular de Ftrace es de un tamaño mínimo (3 páginas por CPU). La primera vez que se utiliza el rastreador, el tamaño del búfer circular se expande a lo que se estableció (por defecto 1.4 Megabytes por CPU). 
Si no se va a realizar más rastreo, esta opción permite reducir el
tamaño del búfer circular para liberar memoria disponible.
trace-cmd reset -b 1
La instancia del búfer afectada es la(s) especificada(s) por la opción
*-B*, *-t*, o *-a* más reciente:
Cuando se usa después de *-B*, redimensiona la instancia del búfer
que la precede en la línea de comandos.
Cuando se usa después de *-a*, redimensiona todas las instancias del
búfer excepto la superior.
Cuando se usa después de *-t* o antes de cualquier opción *-B* o *-a*,
redimensiona la instancia superior.

-B nombre_del_búfer

Si el kernel soporta múltiples búferes, esto reseteará el rastreo solo para el búfer dado. No afecta a ningún otro búfer. Esto puede usarse varias veces para especificar diferentes búferes. El búfer de nivel superior no se reseteará si se proporciona esta opción (a menos que también se suministre la opción -t).

-a

Resetear el rastreo para todas las instancias de búfer existentes. Cuando se usa esta opción, la instancia de nivel superior no se reseteará a menos que se proporcione -t.

-d

Esta opción elimina el(los) búfer(es) de instancia(s) especificado(s) por la opción -B o -a más reciente. Debido a que el búfer de instancia de nivel superior no se puede eliminar, es inválido usar esto inmediatamente después de -t o antes de cualquier opción -B o -a en la línea de comandos.

-t

Resetea el búfer de instancia de nivel superior. Sin la opción -B o -a, esto es lo mismo que el valor por defecto. Pero si se usa -B o -a, esto es necesario si el búfer de instancia de nivel superior también debe ser reseteado.

-k nombre_de_evento_dinámico

Esta opción permite preservar eventos dinámicos especificados durante el reset. Los parámetros válidos son kprobe, kretprobe, uprobe, uretprobe, eprobe, synth y all (para mantener todos los eventos dinámicos). Esto puede usarse varias veces para especificar diferentes tipos de eventos dinámicos.

EJEMPLOS

Resetear el rastreo para instance-one y establecer su tamaño de búfer por CPU a 4096kb. También elimina instance-two. El nivel superior del búfer y cualquier otra instancia no se ven afectados:

trace-cmd reset -B instance-one -b 4096 -B instance-two -d

Eliminar todos los búferes de instancia. El nivel superior del búfer permanece sin afectar:

trace-cmd reset -a -d

Eliminar todos los búferes de instancia y también resetear el nivel superior del búfer:

trace-cmd reset -t -a -d

Inválido. Este comando implica un intento de eliminar el nivel superior del búfer:

trace-cmd reset -a -t -d

Resetear el nivel superior del búfer y establecer su tamaño de búfer por CPU a 1024kb. Si existen búferes de instancia, no se verán afectados:

trace-cmd reset -b 1024

Evitar que kprobes y kretprobes sean destruidos durante el reset:

trace-cmd reset -k kprobe -k kretprobe
