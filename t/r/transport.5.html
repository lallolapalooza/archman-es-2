TRANSPORT(5) Manual de Formatos de Archivo TRANSPORT(5)

NOMBRE

transport - Formato de tabla de transporte de Postfix

SINOPSIS

postmap /etc/postfix/transport
postmap -q "cadena" /etc/postfix/transport
postmap -q - /etc/postfix/transport <archivo_entrada

DESCRIPCIÓN


La tabla opcional transport(5) especifica un mapeo de direcciones de correo electrónico a transportes de entrega de mensajes y destinos de siguiente salto. Los transportes de entrega de mensajes como local o smtp se definen en el archivo master.cf, y los destinos de siguiente salto suelen ser hosts o nombres de dominio. La tabla es buscada por el demonio trivial-rewrite(8).

Este mapeo anula la selección predeterminada de transporte:siguient_salto que está integrada en Postfix:

local_transport (predeterminado: local:$myhostname)
Este es el valor predeterminado para la entrega final a dominios listados con mydestination, y para destinos [dirección_ip] que coinciden con $inet_interfaces o $proxy_interfaces. El destino predeterminado de siguiente_salto es el nombre de host del MTA.
virtual_transport (predeterminado: virtual:)
Este es el valor predeterminado para la entrega final a dominios listados con virtual_mailbox_domains. El destino predeterminado de siguiente_salto es el dominio del destinatario.
relay_transport (predeterminado: relay:)
Este es el valor predeterminado para la entrega remota a dominios listados con relay_domains. En orden de precedencia decreciente, el destino de siguiente_salto se toma de relay_transport, sender_dependent_relayhost_maps, relayhost, o del dominio del destinatario.
default_transport (predeterminado: smtp:)
Este es el valor predeterminado para la entrega remota a otros destinos. En orden de precedencia decreciente, el destino de siguiente_salto se toma de sender_dependent_default_transport_maps, default_transport, sender_dependent_relayhost_maps, relayhost, o del dominio del destinatario.

Normalmente, la tabla transport(5) se especifica como un archivo de texto que sirve como entrada para el comando postmap(1). El resultado, un archivo indexado en formato dbm o db, se utiliza para búsquedas rápidas por parte del sistema de correo. Ejecute el comando "postmap /etc/postfix/transport" para reconstruir un archivo indexado después de cambiar la tabla de transporte correspondiente.

Cuando la tabla se proporciona a través de otros medios como NIS, LDAP o SQL, las mismas búsquedas se realizan que para los archivos indexados ordinarios.

Alternativamente, la tabla puede proporcionarse como un mapa de expresiones regulares donde los patrones se dan como expresiones regulares, o las búsquedas pueden dirigirse a un servidor basado en TCP. En esos casos, las búsquedas se realizan de manera ligeramente diferente, como se describe a continuación bajo "TABLAS DE EXPRESIÓN REGULAR" o "TABLAS BASADAS EN TCP".

PLIEGUE DE MAYÚSCULAS

La cadena de búsqueda se pliega a minúsculas antes de la búsqueda en la base de datos. A partir de Postfix 2.3, la cadena de búsqueda no se pliega con tipos de bases de datos como regexp: o pcre: cuyos campos de búsqueda pueden coincidir tanto con mayúsculas como con minúsculas.

FORMATO DE TABLA

El formato de entrada para el comando postmap(1) es el siguiente:

patrón resultado
Cuando patrón coincide con la dirección o dominio del destinatario, use el resultado correspondiente.
líneas en blanco y comentarios
Se ignoran las líneas vacías y las líneas que solo contienen espacios en blanco, al igual que las líneas cuyo primer carácter que no es un espacio en blanco es un `#'.
texto de varias líneas
Una línea lógica comienza con texto que no son espacios en blanco. Una línea que comienza con espacios en blanco continúa una línea lógica.

El patrón especifica una dirección de correo electrónico, un nombre de dominio o una jerarquía de nombres de dominio, según se describe en la sección "ORDEN DE BÚSQUEDA DE TABLA".

El resultado tiene el formato transporte:siguient_salto y especifica cómo o dónde entregar el correo. Esto se describe en la sección "FORMATO DE RESULTADO".

ORDEN DE BÚSQUEDA DE TABLA

Con búsquedas en archivos indexados como DB o DBM, o en tablas de red como NIS, LDAP o SQL, los patrones se prueban en el orden que se indica a continuación:

usuario+extensión@dominio transporte:siguient_salto
Entregar correo para usuario+extensión@dominio a través de transporte a siguient_salto.
usuario@dominio transporte:siguient_salto
Entregar correo para usuario@dominio a través de transporte a siguient_salto.
dominio transporte:siguient_salto
Entregar correo para dominio a través de transporte a siguient_salto.
.dominio transporte:siguient_salto
Entregar correo para cualquier subdominio de dominio a través de transporte a siguient_salto. Esto se aplica solo cuando la cadena transport_maps no está listada en la configuración parent_domain_matches_subdomains. De lo contrario, un nombre de dominio coincide consigo mismo y sus subdominios.
* transporte:siguient_salto
El patrón especial * representa cualquier dirección (es decir, funciona como patrón comodín y es exclusivo de las tablas de transporte de Postfix).

Nota 1: la dirección de destinatario nula se busca como $empty_address_recipient@$myhostname (predeterminado: mailer-daemon@hostname).

Nota 2: la búsqueda de usuario@dominio o usuario+extensión@dominio está disponible en Postfix 2.0 y posterior.

FORMATO DE RESULTADO

El resultado de la búsqueda tiene el formato transporte:siguient_salto. El campo transporte especifica un transporte de entrega de correo como smtp o local. El campo siguient_salto especifica dónde y cómo entregar el correo.

El campo de transporte especifica el nombre de un transporte de entrega de correo (el primer nombre de una entrada de servicio de entrega de correo en el archivo master.cf de Postfix).

El campo de siguiente salto generalmente especifica un dominio o nombre de host de destinatario. En el caso del cliente SMTP/LMTP de Postfix, el campo de siguiente salto puede contener una lista de destinos de siguiente salto separados por comas o espacios en blanco (Postfix 3.5 y posterior).

La sintaxis de un destino de siguiente salto depende del transporte. Con SMTP, especifique un servicio en un puerto no predeterminado como host:servicio, y deshabilite las búsquedas DNS de MX (intercambiador de correo) con [host] o [host]:puerto. La forma [] es necesaria cuando se especifica una dirección IP en lugar de un nombre de host.

Un campo transporte nulo y un campo siguient_salto nulo significan "no cambiar": usar el transporte de entrega y la información de siguiente salto que se usaría si la tabla de transporte completa no existiera.

Un campo transporte no nulo con un campo siguient_salto nulo restablece la información de siguiente salto al dominio del destinatario.

Un campo transporte nulo con un campo siguient_salto no nulo no modifica la información de transporte.

EJEMPLOS

Para entregar correo interno directamente, mientras se utiliza un relé de correo para todo lo demás, especifique una entrada nula para los destinos internos (no cambie el transporte de entrega ni la información de siguiente salto) y especifique un comodín para todos los demás destinos.

     my.domain    :
     .my.domain   :
     *            smtp:outbound-relay.my.domain

Para enviar correo para example.com y sus subdominios a través del transporte uucp al host UUCP llamado example:

     example.com      uucp:example
     .example.com     uucp:example

Cuando no se especifica un nombre de host de siguiente salto

EJEMPLOS

Por defecto, las tablas de búsqueda son indexadas, lo que significa que Postfix buscará una entrada exacta para el nombre de dominio de destino especificado. Si no se encuentra ninguna entrada, Postfix buscará entradas para los dominios padre, hasta que se encuentre una coincidencia o se agoten los dominios padre.

La siguiente entrada en la tabla indica que el correo para user@example.com debe ser entregado a través del transporte de correo denominado slow, que podría estar configurado para que solo ejecute un proceso de entrega a la vez:

     example.com      slow:

Cuando no se especifica ningún transporte, Postfix utiliza el transporte que coincide con la clase de dominio de la dirección (ver DESCRIPCIÓN arriba). Las siguientes entradas envían todo el correo para example.com y sus subdominios al host gateway.example.com:

     example.com      :[gateway.example.com]
     .example.com     :[gateway.example.com]

En el ejemplo anterior, los corchetes [] suprimen las búsquedas MX. Esto evita bucles de enrutamiento de correo cuando la máquina es el servidor MX principal para example.com.

En el caso de entrega a través de SMTP o LMTP, se puede especificar host:servicio en lugar de solo un host:

     example.com      smtp:bar.example:2025

Esto dirige el correo para user@example.com al host bar.example en el puerto 2025. En lugar de un número de puerto, se puede usar un nombre simbólico. Especifique [] alrededor del nombre del host si las búsquedas MX deben ser deshabilitadas.

Las entregas a través de SMTP o LMTP admiten múltiples destinos (Postfix >= 3.5):

     example.com      smtp:bar.example, foo.example

Esto intenta entregar a bar.example antes de intentar entregar a foo.example.

El mailer de error puede ser usado para rebotar correos:

     .example.com     error:mail for *.example.com is not deliverable

Esto hace que todo el correo para user@cualquiercosa.example.com sea rebotado.

TABLAS DE EXPRESIONES REGULARES

Esta sección describe cómo cambian las búsquedas de tablas cuando la tabla se proporciona en forma de expresiones regulares. Para una descripción de la sintaxis de las tablas de búsqueda de expresiones regulares, vea regexp_table(5) o pcre_table(5).

Cada patrón es una expresión regular que se aplica a toda la dirección que se está buscando. Por lo tanto, some.domain.hierarchy no se busca a través de sus dominios padre, ni user+foo@domain se busca como user@domain.

Los patrones se aplican en el orden especificado en la tabla, hasta que se encuentre un patrón que coincida con la cadena de búsqueda.

El servidor trivial-rewrite(8) prohíbe la sustitución de expresiones regulares de $1 etc. en tablas de búsqueda de expresiones regulares, ya que eso podría abrir una brecha de seguridad (Postfix versión 2.3 y posteriores).

TABLAS BASADAS EN TCP

Esta sección describe cómo cambian las búsquedas de tablas cuando las búsquedas se dirigen a un servidor basado en TCP. Para una descripción del protocolo de búsqueda cliente/servidor TCP, vea tcp_table(5). Esta característica no está disponible hasta la versión 2.4 de Postfix, inclusive.

Cada operación de búsqueda utiliza la dirección completa del destinatario una sola vez. Por lo tanto, some.domain.hierarchy no se busca a través de sus dominios padre, ni user+foo@domain se busca como user@domain.

Los resultados son los mismos que con las búsquedas de archivos indexados.

PARÁMETROS DE CONFIGURACIÓN

Los siguientes parámetros de main.cf son especialmente relevantes. El texto a continuación solo proporciona un resumen de los parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

empty_address_recipient (MAILER-DAEMON)
El destinatario del correo dirigido a la dirección nula.
parent_domain_matches_subdomains (ver la salida de 'postconf -d')
Una lista de características de Postfix donde el patrón "example.com" también coincide con los subdominios de example.com, en lugar de requerir un patrón explícito ".example.com".
transport_maps (vacío)
Tablas de búsqueda opcionales con mapeos de la dirección del destinatario a (transporte de entrega de mensajes, destino próximo).
