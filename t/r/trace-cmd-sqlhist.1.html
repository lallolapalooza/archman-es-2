TRACE-CMD-SQLHIST(1) Manual de tracefs TRACE-CMD-SQLHIST(1)

NOMBRE

trace-cmd-sqlhist - Utiliza el lenguaje SQL para crear / mostrar la creación de histogramas y eventos sintéticos de tracefs

SINOPSIS

trace-cmd sqlhist [OPCIONES] [COMANDO-SQL-select]

DESCRIPCIÓN

trace-cmd sqlhist(1) tomará una declaración similar a SQL para crear histogramas y eventos sintéticos de tracefs que pueden realizar diversas acciones para el manejo de datos.

El sistema de archivos tracefs interactúa con la infraestructura de trazado de Linux, que tiene varios eventos dinámicos y estáticos en todo el kernel. Cada uno de estos eventos puede tener un "histograma" adjunto, donde los campos del evento definirán los cubos del histograma.

Un evento sintético es una forma de adjuntar dos eventos separados y usar los campos y las marcas de tiempo de esos eventos para crear un nuevo evento dinámico. Este nuevo evento dinámico se llama evento sintético. Los campos de cada evento pueden tener cálculos simples realizados sobre ellos donde, por ejemplo, se puede tomar la diferencia entre un campo de un evento y un campo del otro. Esto también funciona para las marcas de tiempo de los eventos, donde la diferencia de tiempo entre los dos eventos también se puede extraer y colocar en el evento sintético.

Se pueden realizar otras acciones a partir de los campos de los eventos. Se puede tomar una instantánea del búfer de anillo del kernel cuando una variable utilizada en el evento sintético alcanza un máximo, o simplemente cambia.

Los comandos para crear histogramas y eventos sintéticos son complejos y no fáciles de recordar. trace-cmd sqlhist se utiliza para convertir la sintaxis SQL en los comandos necesarios para crear el histograma o el evento sintético.

El COMANDO-SQL-select es una cadena SQL definida por tracefs_sqlhist(3).

Nota: esto debe ejecutarse como root (o sudo) ya que interactuar con el directorio tracefs requiere privilegios de root, a menos que se proporcione la opción -t con una copia del directorio tracefs y sus eventos.

OPCIONES

-n nombre

El nombre del evento sintético a crear. Este evento se puede utilizar como cualquier otro evento y habilitarse a través de trace-cmd record(1).

-t directorio-tracefs

Para probar esto como usuario no root, se puede utilizar una copia del directorio tracefs, y pasar ese directorio con esta opción permitirá que el programa funcione. Obviamente, -e no funcionará como no root porque no podrá ejecutar. 
# mkdir /tmp/tracing
# cp -r /sys/kernel/tracing/events /tmp/tracing
# exit
$ trace-cmd sqlhist -t /tmp/tracing ...

-e

No solo mostrar los comandos para crear el histograma, sino también ejecutarlos. Esto requiere privilegios de root.

-f archivo

En lugar de leer los comandos SQL desde la línea de comandos, léalos desde archivo. Si archivo es -, léalo de la entrada estándar.

-m var

Realiza la acción dada cuando la variable var alcanza un nuevo máximo. Esto no se puede usar con -c. La var debe definirse en el COMANDO-SQL-select.

-c var

Realiza la acción dada cuando la variable var cambia su valor. Esto no se puede usar con -m. La var debe definirse en el COMANDO-SQL-select.

-s

Realiza una instantánea en lugar de llamar al evento sintético.

-T

Realiza tanto una instantánea como un rastreo del evento sintético.

-S campos[,campos]

Guarda los campos dados. Los campos deben ser campos del evento "final" dado en el COMANDO-SQL-select

-B instancia

Para declaraciones simples que solo producen un histograma, la instancia dada aquí será donde se creará el histograma. Esto se ignora para la creación completa de eventos sintéticos, ya que los eventos sintéticos tienen un efecto global en todas las instancias de trazado, mientras que los histogramas solo afectan a una única instancia.

EJEMPLOS

Como se describe anteriormente, para fines de prueba, haga una copia del directorio de eventos:

   $ mkdir /tmp/tracing
   $ sudo cp -r /sys/kernel/tracing/events /tmp/tracing/
   $ sudo chmod -R 0644 /tmp/tracing/

Para un ejemplo de salida de histograma simple usando la copia del directorio tracefs.

   $ trace-cmd sqlhist -t /tmp/tracing/ 'SELECT CAST(call_site as SYM-OFFSET), bytes_req, CAST(bytes_alloc AS _COUNTER_) FROM kmalloc'

Produce la salida:

   echo 'hist:keys=call_site.sym-offset,bytes_req:vals=bytes_alloc' > /sys/kernel/tracing/events/kmem/kmalloc/trigger
