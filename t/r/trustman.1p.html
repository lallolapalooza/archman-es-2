NOMBRE

trustman - Gestiona claves utilizadas como anclas de confianza

SINOPSIS

trustman [opciones]

DESCRIPCIÓN

trustman gestiona las claves utilizadas por DNSSEC como anclas de confianza en cumplimiento con RFC5011. Puede ser utilizado como un demonio para la verificación continua de claves o manualmente para inicialización y verificación de claves de una sola vez.

Por defecto, trustman se ejecuta como un demonio para asegurar que las claves almacenadas localmente en archivos de configuración coincidan todavía con las mismas claves obtenidas de la zona donde están definidas. Además, estas comprobaciones pueden ejecutarse una vez manualmente (-S) y en primer plano (-f).

Para cada comprobación de discrepancia de claves, si se detectan discrepancias de claves, trustman realiza las siguientes operaciones:

- establece un temporizador de retención (hold-down) para claves nuevas;
- establece un temporizador de retención (hold-down) para claves faltantes;
- elimina claves revocadas del archivo de configuración.

En ejecuciones posteriores, se comprueban los temporizadores. Si los temporizadores han expirado, las claves se añaden o eliminan del archivo de configuración, según corresponda.

named.conf y dnsval.conf son los archivos de configuración habituales. Estos archivos deben especificarse en el archivo de configuración de DNSSEC-Tools o en las opciones de la línea de comandos.

OPCIONES

trustman toma varias opciones, cada una de las cuales se describe en esta sección. Cada nombre de opción puede acortarse al número mínimo de caracteres únicos, pero algunas opciones también tienen un alias (como se indica). La forma de una sola letra de cada opción se indica entre paréntesis, por ejemplo: -anchor_data_file (-a).

-anchor_data_file archivo (-a)
Un archivo de datos persistente para almacenar nuevas claves que esperan ser añadidas.
-config archivo (-c)
Crea un archivo de configuración para trustman a partir de las opciones de línea de comandos dadas. El archivo de configuración existente de DNSSEC-Tools se copia al archivo de configuración especificado, y se añaden nuevas entradas de configuración correspondientes a las opciones de la línea de comandos. Las entradas específicas de trustman que ya estén en el archivo de configuración existente serán reemplazadas por nuevas entradas de la línea de comandos. Esto permitirá especificar menos opciones de línea de comandos en el futuro.
-dnsval_conf_file /ruta/a/dnsval.conf (-k)
Un archivo dnsval.conf para leer y, posiblemente, actualizar.
-dtconfig archivo_config (-d)
Nombre de un archivo de configuración alternativo de DNSSEC-Tools que se procesará. Si se especifica, este archivo de configuración se utiliza *en lugar* del archivo de configuración normal de DNSSEC-Tools, *no* además de él. Además, se gestionará antes que los archivos *keyrec*, *rollrec* y las opciones de línea de comandos.
-foreground (-f)
Ejecutar en primer plano. trustman seguirá ejecutándose en un bucle. Para ejecutar una vez, use la opción -single_run en su lugar.
-hold_time segundos (-w)
El valor del temporizador de retención (hold-down). Este es el número de segundos desde el momento en que se encuentra una nueva clave. Generalmente, se debe usar el valor predeterminado y recomendado de 30 días.
-mail_contact_addr direccion_correo (-m)
Dirección de correo electrónico de la persona de contacto a la que se deben enviar los informes.
-monitor (-M)
Indica que trustman se ejecutó desde un sistema de monitorización, y se imprimirá un resumen de los eventos. Especificar esta opción activa automáticamente la opción -single_run y desactiva la opción -verbose.

Esto se desarrolló para usarlo con el sistema de monitorización Nagios, pero puede adaptarse para otros monitores.

-named_conf_file /ruta/a/named.conf (-n)
Un archivo named.conf para leer y, posiblemente, actualizar.
-nomail
Evita que se envíe correo, incluso si se especificó un servidor SMTP en el archivo de configuración. Esto es útil solo para enviar notificaciones a través de stdout (-p) o syslog (-L).
-norevoke
Esta opción desactiva las comprobaciones del bit REVOKE.
-no_error (-N)
Envía un informe incluso cuando no hay errores.
-print (-p)
Registra mensajes en stdout.
-resolv_conf_file archivo_conf (-r)
Un archivo resolv.conf para leer. Se puede especificar */dev/null* para forzar a *libval* a responder la consulta recursivamente en lugar de preguntar a otros servidores de nombres.)
-root_hints_file /ruta/a/root.hints (-o)
Un archivo root.hints para leer.
-single_run (-S)
No hacer bucle, sino ejecutar solo una vez.
-sleeptime segundos (-t)
El número de segundos para esperar entre comprobaciones. El valor predeterminado es 3600 (una hora).
-smtp_server nombre_servidor_smtp (-s)
El servidor SMTP que trustman debe usar para enviar informes por correo.
-syslog (-L)
Registra mensajes en syslog.
-tmp_dir directorio (-T)
Especifica dónde se crearán los archivos temporales. Esto se utiliza al crear nuevas versiones de los archivos dnsval.conf y named.conf antes de que se muevan a su lugar.

Los archivos creados en este directorio se renombrarán a su ubicación final. Debe asegurarse de que este directorio, la ubicación final de dnsval.conf y la ubicación final de named.conf estén en la misma partición de disco. La mayoría de los sistemas operativos solo renombrarán archivos dentro de una partición y darán un error si se les indica que renombren un archivo de una partición a otra.

-zone zona (-z)
La zona a comprobar. Especificar esta opción reemplaza el archivo de configuración predeterminado.
-help (-h)
Muestra un mensaje de ayuda.
-verbose (-v)
Proporciona una salida detallada.
-Version (-V)
Muestra la información de versión de trustman y del paquete DNSSEC-Tools.

CONFIGURACIÓN

Además de los argumentos de la línea de comandos, el archivo dnssec-tools.conf puede configurarse con los siguientes valores para eliminar la necesidad de usar algunas de las opciones de la línea de comandos. Las opciones de la línea de comandos siempre anulan la configuración en el archivo dnssec-tools.conf.

taanchorfile archivo
Esto especifica el archivo donde se mantendrá la información de estado de trustman. Es equivalente a la opción -anchor_data_file.
tacontact correo_contacto
Es equivalente a la opción -mail_contact_addr para especificar a quién se enviarán los avisos por correo electrónico.
tadnsvalconffile archivo
Esto especifica el archivo dnsval.conf a leer y escribir. Es equivalente a la opción -dnsval_conf_file.
tanamedconffile archivo
Esto especifica el archivo named.conf a leer y escribir. Es equivalente a la opción -named_conf_file.

trustman(1p) — Arch Linux man pages

NAME

trustman — manage trust anchors for DNSSEC

SYNOPSIS

trustman [-config file] [-help] [-man] [-version]

trustman [-config file] [-daemon] [-debug level] [-logfile file] [-pidfile file] [-resolv_conf_file file] [-root_hints_file file] [-smtp_server servername] [-tmp_dir directory] [-newkey_file file]

DESCRIPTION

trustman is a tool for managing the trust anchors that are used by DNSSEC. It can be used to perform a variety of functions, including adding new trust anchors, removing existing trust anchors, and checking the validity of trust anchors.

trustman can be run in either an interactive mode or as a daemon. In interactive mode, the user is prompted for commands. In daemon mode, trustman runs in the background and performs its functions automatically.

OPTIONS

The following options are available:

-config file
This specifies the configuration file to use. If this option is not specified, trustman will look for a configuration file named dnssec-tools.conf in the user's home directory or in /etc/dnssec-tools/dnssec-tools.conf.
-daemon
This option causes trustman to run as a daemon in the background. The daemon will periodically check the trust anchors and perform any necessary actions. This option is only valid if the -newkey_file option is also specified.
-debug level
This option specifies the debugging level to use. The higher the level, the more debugging information will be printed.
-help
This option displays a help message and exits.
-logfile file
This option specifies the file to which the daemon's log messages should be written. If this option is not specified, the log messages will be written to syslog.
-man
This option displays the man page for trustman and exits.
-newkey_file file
This option specifies the file to which new keys should be written. This file is used when adding new trust anchors.
-pidfile file
This option specifies the file in which the daemon's process ID (PID) should be written. This is used to manage the daemon process.
-resolv_conf_file file
This option specifies the resolver configuration file to use. This is equivalent to the -resolv.conf.file flag.
-root_hints_file file
This option specifies the root.hints file to read. This is equivalent to the -root.hints.file flag.
-smtp_server servername
This is equivalent to the -smtp.server flag for specifying the SMTP server to which email notices will be sent.
-tmp_dir directory
This specifies where temporary files should be created. This is used when creating new versions of the dnsval.conf and named.conf files before they're moved into place.

See the note about renaming in the description of the -tmp.dir option.

-version
This option displays the version of trustman and exits.

CONFIGURATION

The following configuration directives are available in the configuration file:

tresolvconf file
This specifies the resolver configuration file to use. This is equivalent to the -resolv_conf_file flag.
taroothintsfile file
This specifies the root.hints file to read. This is equivalent to the -root_hints_file flag.
tasmtpserver servername
This is equivalent to the -smtp_server flag for specifying the SMTP server to which email notices will be sent.
tatmpdir directory
This specifies where temporary files should be created. This is used when creating new versions of the dnsval.conf and named.conf files before they're moved into place.

See the note about renaming in the description of the -tmp_dir option.

EXIT CODES

trustman may exit for the following reasons:

0 - Successful execution. In daemon mode, this may just mean
    that the daemon was successfully started. The daemon itself
    may exit with some other error.
1 - Invalid options were specified.
2 - No new-key file was specified.
3 - Unable to open the new-key file.
4 - Unable to determine a set of zones to check.
5 - Some form of file-management error was encountered.
