Paquete: trace-cmd

TRACE-CMD-PROFILE(1) Manual de libtracefs TRACE-CMD-PROFILE(1)

NOMBRE

trace-cmd-profile - perfilar tareas en ejecución en vivo

SINOPSIS

trace-cmd profile [OPCIONES] [comando]

DESCRIPCIÓN

El perfil de trace-cmd(1) comenzará el rastreo igual que trace-cmd-record(1), con la opción --profile, excepto que no escribe en un archivo, sino que leerá los eventos a medida que suceden y actualizará la contabilidad de los eventos. Cuando el rastreo termine, informará los resultados como lo haría trace-cmd-report(1) con su opción --profile. En otras palabras, el comando profile realiza el trabajo de trace-cmd record --profile, y trace-cmd report --profile sin tener que grabar los datos en disco, en el medio.

La ventaja de usar el comando profile es que la perfilación se puede realizar durante un período prolongado donde grabar todos los eventos ocuparía demasiado espacio en disco.

Esto habilitará varios eventos, así como el rastreador de gráficos de funciones con una profundidad de uno (si el kernel lo soporta). Esto es para mostrar dónde las tareas entran y salen del kernel y cuánto tiempo estuvieron en el kernel.

Para deshabilitar el gráfico de funciones de llamada, use la opción -p para habilitar otro rastreador. Para no habilitar ningún rastreador, use -p nop.

Todos los tiempos están actualmente en nanosegundos.

OPCIONES

Estas son las mismas que trace-cmd-record(1) con la opción --profile.

-p rastreador

Establece un plugin de rastreador para ejecutar en lugar del rastreo de gráficos de funciones establecido a profundidad 1. Para no ejecutar ningún rastreador, usa -p nop.

-S

Solo habilita el rastreador o eventos especificados en la línea de comandos. Con esta opción, el rastreador function_graph no se habilita, ni tampoco ningún evento (como sched_switch), a menos que se especifiquen explícitamente en la línea de comandos (por ejemplo, -p function -e sched_switch -e sched_wakeup).

-G

Establece los eventos de interrupción (suaves y duros) como globales (asociados a la CPU en lugar de a las tareas).

-o archivo

Escribe la salida del perfil a archivo. Esto anula --stderr

-H event-hooks

Añade ganchos de eventos personalizados para conectar dos eventos entre sí. El formato es: [<sistema_inicio>:]<evento_inicio>,<coincidencia_inicio>[,<pid_inicio>]/ [<sistema_fin>:]<evento_fin>,<coincidencia_fin>[,<flags>] 
El sistema_inicio:evento_inicio (sistema_inicio es opcional), es el evento que
inicia la temporización.
coincidencia_inicio es el campo en el evento de inicio que debe coincidir con la
coincidencia_fin en el evento de fin.
pid_inicio es opcional, ya que las coincidencias se adjuntan a las tareas que
ejecutan los eventos, si se debe usar otro campo para encontrar esa tarea, entonces
se especifica con pid_inicio.
sistema_fin:evento_fin es el evento que finaliza la temporización (sistema_fin es
opcional).
coincidencia_fin es el campo en coincidencia_fin que coincidirá con el campo
del evento de inicio, coincidencia_inicio.
flags son opcionales y pueden ser los siguientes (sin distinción de mayúsculas y
minúsculas):
p : Los dos eventos están anclados a la misma CPU (inicio y fin ocurren
    en la misma CPU siempre).
s : El evento debe tener una pila rastreada con él (habilita el rastreo de pila
    para el evento de inicio).
g : El evento es global (no asociado a una tarea). pid_inicio
    no es aplicable con esta bandera.

--stderr

Redirige la salida a stderr. La salida del comando que se está ejecutando no se modifica. Esto permite observar la ejecución del comando y guardar la salida del perfil en otro archivo.

--verbose[=nivel]

Establece el nivel de registro. Los niveles de registro soportados son "none", "critical", "error", "warning", "info", "debug", "all" o sus identificadores "0", "1", "2", "3", "4", "5", "6". Establecer el nivel de registro a un valor específico habilita todos los registros de ese nivel y todos los anteriores. El nivel se establecerá por defecto a "info" si no se especifica ninguno. 
Ejemplo: habilita todos los registros críticos, de error y de advertencia
trace-cmd profile --verbose=warning

El conteo de veces que se activó el evento siempre está entre paréntesis (5).

El trazo del gráfico de funciones puede producir demasiada sobrecarga, ya que todavía se activa (simplemente no traza) en todas las funciones. Para limitar las funciones solo a las llamadas al sistema (no interrupciones), agrega la siguiente opción:

-l 'sys_*' -l 'SyS_*'

Para deshabilitar totalmente el trazado de gráficos de funciones, usa:

-p nop

Para usar el trazado de funciones en su lugar (nota, esto no registrará tiempos, sino solo el conteo de veces que se activa una función):

-p function

Para ver el comando ejecutándose pero guardar la salida del perfil en un archivo usa --stderr, y redirige stderr a un archivo

# trace-cmd profile --stderr cyclictest -p 80 -n -t1 2> profile.out

O simplemente usa -o

# trace-cmd profile -o profile.out cyclictest -p 80 -n -t1
