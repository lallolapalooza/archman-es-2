NOMBRE

trivial-rewrite - Demonio de reescritura y resolución de direcciones de Postfix

SINOPSIS

trivial-rewrite [opciones genéricas del demonio Postfix]

DESCRIPCIÓN


El demonio trivial-rewrite(8) procesa tres tipos de solicitudes de servicio del cliente:

reescribir contexto dirección
Reescribe una dirección a formato estándar, de acuerdo con el contexto de reescritura de direcciones:
local
Añade los nombres de dominio especificados con $myorigin o $mydomain a las direcciones incompletas; realiza el procesamiento de swap_bangpath y allow_percent_hack como se describe a continuación, y elimina las direcciones enrutable por ruta de origen (@sitio,@sitio:usuario@dominio) a formato usuario@dominio.
remoto
Añade el nombre de dominio especificado con $remote_header_rewrite_domain a las direcciones incompletas. De lo contrario, el resultado es idéntico al del contexto de reescritura de direcciones local. Esto evita que Postfix añada el dominio local al spam de clientes remotos mal escritos.
resolver remitente dirección
Resuelve la dirección a un cuádruple (transporte, siguientequestion, destinatario, banderas). El significado de los resultados es el siguiente:
transporte
El agente de entrega a usar. Este es el primer campo de una entrada en el archivo master.cf.
siguientequestion
El host al que enviar y, opcionalmente, información del método de entrega.
destinatario
La dirección del destinatario del sobre que se pasa a siguientequestion.
banderas
La clase de dirección, si la dirección requiere reenvío, si la dirección tiene problemas y si la solicitud falló.
verificar remitente dirección
Resuelve la dirección para fines de verificación de direcciones.

GESTIÓN DE PROCESOS DEL SERVIDOR

Los servidores trivial-rewrite(8) se ejecutan bajo el control del servidor maestro de Postfix (master(8)). Cada servidor puede manejar múltiples conexiones simultáneas. Cuando todos los servidores están ocupados mientras un cliente se conecta, el maestro crea un nuevo proceso de servidor, siempre que no se supere el límite de procesos del servidor trivial-rewrite. Cada servidor trivial-rewrite termina después de atender al menos a $max_use clientes o después de $max_idle segundos de inactividad.

ESTÁNDARES

Ninguno. El comando no interactúa con el mundo exterior.

SEGURIDAD

El demonio trivial-rewrite(8) no es sensible a la seguridad. Por defecto, este demonio no habla con usuarios remotos o locales. Puede ejecutarse con privilegios bajos fijos en un entorno chroot.

DIAGNÓSTICOS


Los problemas y transacciones se registran en syslogd(8) o postlogd(8).

PARÁMETROS DE CONFIGURACIÓN

En sistemas de correo con alta carga, puede pasar mucho tiempo antes de que un cambio en main.cf que afecte a trivial-rewrite(8) sea recogido. Use el comando "postfix reload" para acelerar un cambio.

CONTROLES DE COMPATIBILIDAD

resolver_direccion_sin_comillas (yes)
Resuelve una dirección de destinatario de forma segura en lugar de correcta, buscando dentro de las comillas.

Disponible con Postfix versión 2.1 y posteriores:

resolver_dominio_nulo (no)
Resuelve una dirección que termina en el dominio nulo "@" como si se especificara el nombre de host local, en lugar de rechazar la dirección como inválida.

Disponible con Postfix versión 2.3 y posteriores:

resolver_dominio_numerico (no)
Resuelve "usuario@direccionip" como "usuario@[direccionip]", en lugar de rechazar la dirección como inválida.

Disponible con Postfix versión 2.5 y posteriores:

permitir_usuario_minimo (no)
Permite que una dirección de remitente o destinatario tenga `-` como primer carácter.

CONTROLES DE REESCRITURA DE DIRECCIONES

myorigin ($myhostname)
El nombre de dominio del que parece provenir el correo enviado localmente y al que se entrega el correo enviado localmente.
permitir_hack_porcentaje (yes)
Habilita la reescritura de la forma "usuario%dominio" a "usuario@dominio".
anadir_arroba_myorigin (yes)
Con el correo enviado localmente, añade la cadena "@$myorigin" a las direcciones de correo sin información de dominio.
anadir_punto_mydomain (Postfix >= 3.0: no, Postfix < 3.0: yes)
Con el correo enviado localmente, añade la cadena ".$mydomain" a las direcciones que no tienen información de ".dominio".
delimitador_destinatario (vacío)
El conjunto de caracteres que pueden separar el nombre local de una dirección de correo electrónico, el nombre de usuario o un nombre de archivo .forward de su extensión.
intercambiar_bangpath (yes)
Habilita la reescritura de "sitio!usuario" a "usuario@sitio".

Disponible en Postfix 2.2 y posteriores:

dominio_reescritura_cabecera_remoto (vacío)
Reescribe o añade cabeceras de mensajes en correos de clientes remotos si el valor del parámetro remote_header_rewrite_domain no está vacío, actualizando las direcciones incompletas con el dominio especificado en el parámetro remote_header_rewrite_domain , y añadiendo cabeceras faltantes.

trivial-rewrite(8) System Administration Commands

NAME

trivial-rewrite - Simple address rewriting for Postfix

SYNOPSIS

/etc/postfix/trivial-rewrite

DESCRIPTION

The trivial-rewrite(8) table is a simple lookup table that Postfix can use to rewrite mail addresses.

It is typically used in the sender_canonical_maps, recipient_canonical_maps, sender_dependent_relayhost_maps, or smtp_generic_maps Postfix features.

The format of the table is:

    old-address              new-address
    old-domain               new-domain
    @old-domain              @new-domain
    user@old-domain          user@new-domain

The table is searched in the order shown above. The first match determines the rewritten address.

SERVER PROCESS MANAGEMENT

The trivial-rewrite(8) table is typically activated by a Postfix lookup table type such as hash, btree, or regexp. These tables are usually managed by the postmap(8) command. After editing the source file, run postmap(8) to update the database file.

STANDARDS

RFC 5965

SECURITY

The trivial-rewrite(8) table itself does not introduce any security vulnerabilities. However, it is important to ensure that the addresses and domains used in the table are valid and do not lead to unintended mail redirection or spoofing.

DIAGNOSTICS

Postfix logs errors related to table lookups, including issues with the trivial-rewrite(8) table, in the mail log. Common errors include file not found, permission denied, or invalid format.

CONFIGURATION PARAMETERS

The trivial-rewrite(8) table is not directly configured via Postfix parameters. Instead, its usage is determined by the Postfix lookup tables specified in the main.cf configuration file, such as:

  • sender_canonical_maps
  • recipient_canonical_maps
  • smtp_generic_maps

For example, to use trivial-rewrite(8) for sender canonicalization:

    sender_canonical_maps = hash:/etc/postfix/trivial-rewrite

COMPATIBILITY CONTROLS

None.

ADDRESS REWRITING CONTROLS

The trivial-rewrite(8) table provides a basic mechanism for address rewriting. For more advanced rewriting, consider using Postfix's regexp lookup tables or dedicated canonicalization services.

ROUTING CONTROLS

This table is not directly involved in routing decisions but can influence the destination address, which in turn affects routing.

ADDRESS VERIFICATION CONTROLS

This table does not perform address verification.

MISCELLANEOUS CONTROLS

The trivial-rewrite(8) table is suitable for simple, static address mappings. For dynamic or complex rewriting rules, other Postfix features should be considered.

canonical(5), postmap(8), postfix(1)
