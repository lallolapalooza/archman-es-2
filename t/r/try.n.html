try(n)

Paquete: tcl

try(n) Comandos integrados de Tcl try(n)

NOMBRE

try - Capturar y procesar errores y excepciones

SINOPSIS

try cuerpo ?manejador...? ?finally script?

DESCRIPCIÓN

Este comando ejecuta el script cuerpo y, dependiendo del resultado de ese script (salida normal, error o algún otro resultado excepcional), ejecuta un script manejador para lidiar con el caso. Una vez que todo eso ha sucedido, si la cláusula finally está presente, el script que incluye será ejecutado y el resultado del manejador (o del cuerpo si ningún manejador coincidió) se permitirá que continúe propagándose. Nótese que la cláusula finally se procesa incluso si ocurre un error e independientemente de qué manejador, si lo hay, se utilice.

Las cláusulas manejador se expresan cada una como varias palabras, y deben tener una de las siguientes formas:

on código listaVariables script
Esta cláusula coincide si la evaluación de cuerpo se completó con el código de excepción código. El código puede expresarse como un entero o como una de las siguientes palabras literales: ok, error, return, break o continue. Esos literales corresponden a los enteros del 0 al 4 respectivamente.
trap patrón listaVariables script
Esta cláusula coincide si la evaluación de cuerpo resultó en un error y el prefijo del -errorcode del diccionario de estado del intérprete es igual al patrón. El número de palabras de prefijo tomadas del -errorcode es igual a la longitud de la lista de patrón, y los espacios entre palabras se normalizan tanto en el -errorcode como en el patrón antes de la comparación.

La palabra listaVariables en cada manejador siempre se interpreta como una lista de nombres de variables. Si la primera palabra de la lista está presente y no está vacía, nombra una variable en la que se colocará el resultado de la evaluación de cuerpo (del try principal); esto contendrá la forma legible por humanos de cualquier error. Si la segunda palabra de la lista está presente y no está vacía, nombra una variable en la que se colocará el diccionario de opciones del intérprete en el momento en que finalizó la ejecución de cuerpo.

La palabra script de cada manejador también se interpreta siempre de la misma manera: como un script Tcl para evaluar si la cláusula coincide. Si script es un literal “-” y el manejador no es el último, se invoca el script del siguiente manejador en su lugar (al igual que con el comando switch).

Nótese que las cláusulas manejador se comparan en orden, y que la primera que coincide siempre se selecciona. Como máximo, se seleccionará una cláusula manejador. Como consecuencia, un on error enmascarará cualquier trap posterior en el try. Nótese también que on error es equivalente a trap {}.

Si ocurre una excepción (es decir, cualquier resultado que no sea ok) durante la evaluación de la cláusula manejador o de la cláusula finally, el diccionario de estado de la excepción original se agregará al diccionario de estado de la nueva excepción bajo la clave -during.

EJEMPLOS

Asegurarse de que un archivo se cierre sin importar qué suceda:

set f [open /some/file/name a]
try {
    puts $f "algún mensaje"
    # ...
} finally {
    close $f
}

Manejar diferentes razones por las que un archivo no se puede abrir para lectura:

try {
    set f [open /some/file/name r]
} trap {POSIX EISDIR} {} {
    puts "no se pudo abrir /some/file/name: es un directorio"
} trap {POSIX ENOENT} {} {
    puts "no se pudo abrir /some/file/name: no existe"
}
