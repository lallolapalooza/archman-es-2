NOMBRE

trace-cmd-record - graba un rastreo del rastreador interno del kernel Ftrace de Linux

SINOPSIS

trace-cmd record [OPCIONES] [comando]

DESCRIPCIÓN

El comando record de trace-cmd configurará el rastreador del kernel Ftrace de Linux para grabar los plugins o eventos especificados que ocurran mientras se ejecuta el comando. Si no se proporciona ningún comando, grabará hasta que el usuario presione Ctrl-C.

El comando record de trace-cmd configurará el rastreador para comenzar a rastrear los diversos eventos o plugins dados en la línea de comandos. Luego creará un número de procesos de rastreo (uno por CPU) que comenzarán a grabar desde el búfer de anillo del kernel directamente en archivos temporales. Cuando el comando se complete (o se presione Ctrl-C), todos los archivos se combinarán en un archivo trace.dat que se podrá leer más tarde (ver trace-cmd-report(1)).

OPCIONES

-p rastreador

Especifica un rastreador. Los rastreadores suelen hacer más que simplemente rastrear un evento. Rastreadores comunes son: function, function_graph, preemptirqsoff, irqsoff, preemptoff y wakeup. Un rastreador debe ser compatible con el kernel en ejecución. Para ver una lista de rastreadores disponibles, consulte trace-cmd-list(1).

-e evento

Especifica un evento a rastrear. Se han agregado varios puntos de rastreo estáticos al kernel de Linux. Se agrupan por subsistema donde puede habilitar todos los eventos de un subsistema dado o especificar eventos específicos para que se habiliten. El evento tiene el formato "sub-sistema:nombre-del-evento". También puede especificar solo el subsistema sin el :nombre-del-evento o el nombre-del-evento sin el "sub-sistema:". Usar "-e sched_switch" habilitará el evento "sched_switch", mientras que "-e sched" habilitará todos los eventos bajo el subsistema "sched". 
El 'evento' también puede contener expresiones glob. Es decir, " \*stat\* "
seleccionará todos los eventos (o subsistemas) que tengan los caracteres
"stat" en sus nombres.
La palabra clave 'all' se puede usar para habilitar todos los eventos.

-a

Cada evento que se está grabando tiene su archivo de formato de salida guardado en el archivo de salida para poder mostrarlo más tarde. Pero si se habilitan otros eventos en el rastreo sin el conocimiento de trace-cmd, los formatos de esos eventos no se grabarán y trace-cmd report no podrá mostrarlos. Si este es el caso, especifique la opción -a y se guardará el formato para todos los eventos del sistema.

-T

Habilita un volcado de pila en cada evento. Por ejemplo: 
          <idle>-0     [003] 58549.289091: sched_switch:         kworker/0:1:0 [120] R ==> trace-cmd:2603 [120]
          <idle>-0     [003] 58549.289092: kernel_stack:         <volcado de pila>
=> schedule (ffffffff814b260e)
=> cpu_idle (ffffffff8100a38c)
=> start_secondary (ffffffff814ab828)

--func-stack

Habilita un volcado de pila en todas las funciones. Tenga en cuenta que esto solo es aplicable para el rastreador de plugins "function" y solo tendrá efecto si se usa la opción -l y tiene éxito en limitar las funciones. Si el rastreador de funciones no está filtrado y se habilita el volcado de pila, puede bloquear la máquina en vivo.

-f filtro

Especifica un filtro para el evento anterior. Esto debe venir después de un -e. Esto filtrará qué eventos se graban según el contenido del evento. El filtrado se pasa directamente al kernel, por lo que lo que permite el filtrado puede depender de la versión del kernel que tenga. Básicamente, le permitirá usar notación C para verificar si un evento debe procesarse o no.
    ==, >=, <=, >, <, &, |, && y ||
Los anteriores suelen ser seguros de usar para comparar campos.

--no-filter

No filtre los hilos de trace-cmd. Por defecto, los hilos se filtran para no ser rastreados por eventos. Esta opción hará que los hilos de trace-cmd también se rastreen.

-R activador

Especifica un activador para el evento anterior. Esto debe venir después de un -e. Esto agregará un activador dado al evento dado. Para habilitar solo el activador y no el evento en sí, coloque el evento después de la opción -v. 
Consulte Documentation/trace/events.txt en el código fuente del kernel de Linux
para obtener más información sobre los activadores.

-v

Esto hará que todos los eventos especificados después de él en la línea de comandos no se rastreen. Esto es útil para seleccionar un subsistema a rastrear pero dejar fuera varios eventos. Por ejemplo: "-e sched -v -e " \*stat\* "" habilitará todos los eventos en el subsistema sched excepto aquellos que tengan "stat" en sus nombres. 
Nota: la opción -v se tomó de la forma en que grep(1) invierte las
siguientes coincidencias.

-F

Esto filtrará solo el ejecutable que se proporciona en la línea de comandos. Si no se proporciona ningún comando, se filtrará a sí mismo (bastante inútil). Usar -F le permitirá rastrear solo los eventos causados por el comando dado.

-P pid

Similar a -F pero le permite especificar un ID de proceso para rastrear.

-c

Se usa con -F (o -P si el kernel lo soporta) para rastrear también a los hijos del proceso.

--user

Ejecuta el comando especificado como el usuario dado.

-C reloj

Establece el reloj de rastreo a "reloj". 
Use trace-cmd(1) list -C para ver qué relojes están disponibles.

-o archivo-salida

Por defecto, trace-cmd report creará un archivo trace.dat. Puede especificar un archivo diferente para escribir con la opción -o.

-l nombre-función

Esto limitará los rastreadores de function y function_graph a rastrear solo la función dada. Se puede especificar más de un -l en la línea de comandos para rastrear más de una función. Esto admite tanto el análisis completo de expresiones regulares (regex(3)) como el análisis básico de glob. Si el filtro solo tiene caracteres alfanuméricos, _, *, ? y ., se analizará como un glob básico. para forzar que sea una expresión regular, anteponga el filtro con ^ o agréguele $ y luego se analizará como una expresión regular.

-g nombre-función

Esta opción es para el plugin function_graph. Graficará la función dada. Es decir, solo rastreará la función y todas las funciones que llama. Puede tener más de un -g en la línea de comandos.

-n nombre-función

Esto tiene el efecto opuesto a -l. La función dada con la opción -n no se rastreará. Esto tiene prioridad, es decir, si incluye la misma función tanto para -n como para -l, no se rastreará.

-d

Algunos plugins de rastreo habilitan el rastreador de funciones por defecto. Como los rastreadores de latencia. Esta opción evita que el rastreador de funciones se habilite al inicio.

-D

La opción -d intentará usar la opción function-trace para deshabilitar el rastreador de funciones (si está disponible), de lo contrario, utilizará por defecto el archivo proc: /proc/sys/kernel/ftrace_enabled, pero no lo tocará si la opción function-trace está disponible. La opción -D deshabilitará tanto el archivo proc ftrace_enabled como la opción function-trace si existe. 
Tenga en cuenta que esto deshabilita el rastreo de funciones para todos los usuarios,
incluidos los usuarios fuera de los rastreadores de ftrace (stack_tracer, perf, etc.).

-O opción

Ftrace tiene varias opciones que se pueden habilitar o deshabilitar. Esto le permite configurarlas. Agregar el texto no a una opción la deshabilita. Por ejemplo: "-O no graph-time" deshabilitará la opción Ftrace "graph-time".

-s intervalo

Los procesos que trace-cmd crea para grabar desde el búfer de anillo necesitan despertarse para realizar la grabación. Establecer el intervalo en cero hará que los procesos se despierten cada vez que se escriban nuevos datos en el búfer. **trace-cmd**(1)
Linux Trace Toolkit Next Generation

NAME

trace-cmd record - Record trace data from the kernel trace subsystem

SYNOPSIS

trace-cmd record [-e EVENT]... [-p PLUGIN]... [-o OUTPUT_FILE] [-d DIRECTORY] [-w] [-D] [-x] [-t] [-i] [-k] [-V cid:port] [-N host:port] [--date] [--temp DIRECTORY] [--ts-offset offset] [--tsync-interval interval] [--tsc2nsec] [-v] [-h] [COMMAND]

DESCRIPTION

The trace-cmd record command is used to record trace data from the kernel tracing infrastructure (ftrace). It can be used to record events, function tracing, or other types of data the kernel is exposing.

When trace-cmd record is run, it will enable the specified tracing events or plugins and start recording data into the kernel ring buffer. When the command finishes (either by completing the specified COMMAND, or being interrupted by a signal), trace-cmd will then read the data from the ring buffer and save it into a file named trace.dat by default in the current directory.

If a command is given on the command line, trace-cmd will start tracing, execute the command, and then stop tracing when the command exits. If no command is given, trace-cmd will trace until interrupted by a signal (e.g., Ctrl+C).

The -e and -p options can be used multiple times to enable various events and tracer plugins. The order of these options does not matter.

The -B option allows for multiple buffers to be created. Each buffer can be associated with a specific set of events. This allows for more granular control over what data is collected. See the example below.

If the command runs for a long time, or generates a lot of data, the ring buffer may overflow. The default behavior is to drop events when the buffer is full. Options like -m can help manage buffer size to mitigate this.

OPTIONS

-e event
Enable a specific trace event. The available events can be listed using trace-cmd list. Multiple -e options can be given.

-p plugin
Enable a specific tracer plugin. The available tracers can be listed using trace-cmd list. Multiple -p options can be given.

-o output file
Specify the file to write the recorded trace data to. Defaults to trace.dat in the current directory.

-d directory
Specify the directory to write the recorded trace data to. The default directory is the current directory. The trace file will be named trace.dat.

-w
Wait for the trace data. If this option is specified, trace-cmd will not read the trace buffer after the command finishes or tracing is stopped. It will wait until trace data is available from the ring buffer. This is useful when tracing events that happen after the main command finishes.

-D
Daemonize the trace-cmd process. This will run trace-cmd in the background. This is typically used when tracing a long running process or system.

-x
Enable function graph tracing. This is a shortcut for -p function_graph. This tracer records function calls and returns, providing a call graph of the traced code.

-i
Ignore unknown events. If an event specified with -e is not found on the system, trace-cmd will exit with an error by default. This option makes trace-cmd ignore unknown events and continue tracing.

-k
Keep the tracer enabled after recording. By default, trace-cmd disables all tracing and resets the buffers when it finishes. This option prevents that, leaving the tracer and buffers active. This is useful for debugging trace-cmd itself or for chaining multiple tracing commands.

-n interval
Set the sleep interval (in microseconds) for the recording process. This is the time the recording process sleeps between waking up to read from the ring buffer. A longer interval means less overhead but potentially more missed events if the buffer fills up quickly. The default is 1000 microseconds (1 ms).

-r priority
Set the priority for the capture threads. This is useful on busy systems where trace capture threads might be starved, leading to lost events. Setting a real-time priority (FIFO) can help ensure events are captured promptly. Use with caution as it can affect system behavior.

-b size
Set the ring buffer size in kilobytes. This size applies to each per-CPU buffer. For example, on a 4-CPU machine, -b 10000 sets a total buffer size of 40MB (10MB per CPU).

--subbuf-size
Set the size of sub-buffers within the ring buffer. Kernel tracing uses sub-buffers, typically the size of a memory page. Increasing this size can allow for larger events and potentially speed up tracing by reducing the overhead of switching between sub-buffers. The downside is that reading from the ring buffer involves replacing a sub-buffer, which might slightly alter behavior.

-B buffer-name
Create a named buffer. If the kernel supports multiple trace buffers, this option creates or resets a buffer with the given name. Events specified after this option are associated with this named buffer. If no buffer is specified, events are associated with the main (top-level) buffer. Named buffers are removed at the end of execution unless -k is used.

Example: 

trace-cmd record -e sched -B block -e block -B time -e timer sleep 1
This command enables 'sched' events in the main buffer, creates a 'block' buffer and enables 'block' events within it, then creates a 'time' buffer and enables 'timer' events within it, finally sleeping for 1 second.

-m size
Set the maximum per-CPU buffer size in kilobytes. This is useful to prevent running out of disk space during long recordings. Note that the actual size might be slightly different due to rounding to page sizes and the use of two alternating buffers.

-M cpumask
Set the CPU mask for tracing. This affects the most recently specified buffer instance. If given before any buffer instance, it affects the main buffer. The value should be a hexadecimal number. Use -1 to trace all CPUs.

Example: 

trace-cmd record -p function -M c -B events13 -e all -M 5
This command traces functions on CPU C (binary 1100), then sets up a buffer named 'events13' to trace all events on CPU 5 (binary 0101).

-k
Keep tracer enabled. By default, trace-cmd disables tracing and resets buffers upon completion. This option leaves them enabled. Useful for debugging trace-cmd or chaining commands. Note that trace-cmd usually restores the `tracing_on` file state, but this option leaves it set to 0.

-i
Ignore unknown events. By default, trace-cmd exits if an event specified on the command line is not found. This option makes it ignore such events.

-N host:port
Send trace data to a remote machine running trace-cmd listen using UDP packets. This is useful for embedded systems with limited storage or for centralizing trace data. This option is not supported with latency tracer plugins (wakeup, wakeup_rt, irqsoff, preemptoff, preemptirqsoff).

-V cid:port
Connect to a listener running trace-cmd listen -V. This is used when tracing a guest VM and the host is running the listener, or vice versa. Similar limitations to the -N option apply regarding latency tracer plugins.

-t
Use TCP instead of UDP for sending trace data with the -N option. TCP is slower but provides reliable delivery, which might be necessary on unreliable networks or when all data must be guaranteed.

-q | --quiet
Quiet mode. Suppresses normal output, useful when tracing an application to display only the application's output.

--date
Add timestamps to the trace buffer after recording. These timestamps can be mapped to wall-clock time for readable output when analyzing the trace.dat file.

--max-graph-depth depth
Set the maximum depth for the function_graph tracer. A depth of 1 traces only the entry into userspace functions but not those called within the kernel. The default is 0 (no limit).

--cmdlines-size size
Set the size of the saved_cmdlines circular buffer in the kernel. This file maps PIDs to command lines. If full, PIDs might not be resolved in the trace. The kernel default is 128.

--module module
Filter function tracing to a specific module. Equivalent to adding :mod:module to other function filters. If no other function filter is specified, it filters all functions within the specified module.

Examples: 

'--module snd'  is equivalent to  '-l :mod:snd'
'--module snd -l "*jack*"' is equivalent to '-l "*jack*:mod:snd"'
'--module snd -n "*"' is equivalent to '-n :mod:snd'

--proc-map
Save the memory map of the traced process(es) into the trace.dat file. Processes can be specified using -P or as a command.

--profile
Enable profiling tracing. If no tracer is specified (-p), it enables function_graph with a depth of 1 (if supported). It also enables various tracepoints with stack tracing to help identify task blocking times. See trace-cmd-profile(1) for details.

-G
Set interrupt events (soft and hard) as global (associated with CPU instead of tasks). Only works with --profile.

-H event-hooks
Add custom event matching to connect events. When used with --profile, it saves parameters for use with trace-cmd report --profile. Format and usage are described in trace-cmd-profile(1).

Example: 

trace-cmd record -H hrtimer_expire_entry,hrtimer/hrtimer_expire_exit,hrtimer,sp
trace-cmd report --profile
This profiles the time spent between hrtimer_expire_entry and hrtimer_expire_exit.

-S
(For --profile only) Only enable tracers or events explicitly specified on the command line. Prevents automatic enabling of function_graph or default events like sched_switch.

--temp directory
Specify a directory for temporary per-CPU trace files. This is useful if the final output location is not suitable for temporary files, e.g., a network filesystem.

--ts-offset offset
Add an offset to timestamps in the trace.dat file. This offset is applied when reporting, affecting all timestamps by the specified amount. The offset is in raw units (e.g., nanoseconds).

--tsync-interval
Set the interval (in ms) for timestamp synchronization with guests. A negative value disables synchronization. 0 means the offset is calculated only twice (beginning and end). Synchronization requires VSOCK support.

--tsc2nsec
Convert the current clock to nanoseconds using TSC multiplier and shift from the kernel's perf interface. This option assumes the TSC settings are applicable to the chosen clock. Use the -C tsc2nsec clock if unsure.

COMMAND
An optional command to execute. trace-cmd record will trace while this command runs and stop when it exits.

EXAMPLES

Record all scheduling events for 5 seconds:

$ trace-cmd record -e sched_switch -e sched_wakeup -e sched_wakeup_new -e sched_process_exit sleep 5

Record function calls within the kernel for 10 seconds:

$ trace-cmd record -p function -T sleep 10

Record function graph tracing for a specific process (PID 1234) until interrupted:

$ trace-cmd record -P 1234 -x

Record all events, with a buffer size of 32MB, and keep the tracer enabled afterwards:

$ trace-cmd record -b 32768 -k

OPTIONS

--stderr

Haz que la salida vaya a stderr en lugar de stdout, pero la salida del comando ejecutado no se modificará. Esto es útil si deseas monitorear la salida del comando que se está ejecutando, pero no ver la salida de trace-cmd.

--poll

La espera de datos disponibles en los búferes circulares de rastreo puede desencadenar IPIs. Esto podría generar ruido de rastreo inaceptable al rastrear sistemas de baja latencia o en tiempo real. La opción poll fuerza a trace-cmd a usar O_NONBLOCK. Los rastreos se extraen mediante espera activa, lo que consumirá mucha CPU, así que úsala solo cuando sea realmente necesario.

--name

Da un nombre específico al agente actual que se está procesando. Se usa después de -A para dar un nombre a la máquina virtual invitada que se está rastreando. Útil cuando se usa el ID de vsocket en lugar del nombre de la máquina virtual invitada.

--verbose[=nivel]

Establece el nivel de registro. Los niveles de registro admitidos son "none", "critical", "error", "warning", "info", "debug", "all" o sus identificadores "0", "1", "2", "3", "4", "5", "6". Establecer el nivel de registro a un valor específico habilita todos los registros de ese nivel y de todos los niveles anteriores. El nivel será "info" por defecto si no se especifica ninguno. 
Ejemplo: habilita todos los registros críticos, de error y de advertencia
trace-cmd record --verbose=warning

--file-version

Versión deseada del archivo de salida. Las versiones admitidas son 6 o 7.

--compression

Compresión del archivo de salida de rastreo, se puede pasar una de estas cadenas: 
'any'  - selecciona automáticamente el mejor algoritmo de compresión disponible
'none' - no comprime el archivo de rastreo
'name' - el nombre del algoritmo de compresión deseado. Los algoritmos disponibles se pueden listar con
trace-cmd list -c

--proxy vsocket

Usa un proxy vsocket para alcanzar el agente. Actúa igual que -A (para un agente) pero enviará la conexión proxy al agente. Se espera que se ejecute en una máquina virtual invitada privilegiada que el host conoce (como lo indica el cid en la opción -P para el agente).

--daemonize Ejecuta trace-cmd en segundo plano como un demonio después de que haya comenzado la grabación. Crea un archivo pidfile en /var/run/trace-cmd-record.pid con el pid de trace-cmd durante la grabación.
