truncate(2) Manual de llamadas al sistema truncate(2)

NOMBRE

truncate, ftruncate - truncar un archivo a una longitud especificada

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int truncate(const char *path, off_t length);
int ftruncate(int fd, off_t length);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

truncate():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.12: */ _POSIX_C_SOURCE >= 200809L
        || /* glibc <= 2.19: */ _BSD_SOURCE

ftruncate():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.3.5: */ _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPCIÓN

Las funciones truncate() y ftruncate() hacen que el archivo regular nombrado por path o referenciado por fd se trunque a un tamaño de exactamente length bytes.

Si el archivo era previamente más grande que este tamaño, se pierden los datos adicionales. Si el archivo era previamente más corto, se extiende, y la parte extendida se lee como bytes nulos ('\0').

El desplazamiento del archivo no se modifica.

Si el tamaño cambió, entonces los campos st_ctime y st_mtime (respectivamente, tiempo del último cambio de estado y tiempo de la última modificación; ver inode(7)) para el archivo se actualizan, y los bits de modo de conjunto de usuario (set-user-ID) y conjunto de grupo (set-group-ID) pueden ser borrados.

Con ftruncate(), el archivo debe estar abierto para escritura; con truncate(), el archivo debe ser escribible.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

Para truncate():

EACCES
Se deniega el permiso de búsqueda para un componente del prefijo de ruta, o el archivo nombrado no es escribible por el usuario. (Ver también path_resolution(7)).
EFAULT
El argumento path apunta fuera del espacio de direcciones asignado del proceso.
EFBIG
El argumento length es mayor que el tamaño máximo del archivo. (XSI)
EINTR
Mientras estaba bloqueada esperando completar, la llamada fue interrumpida por un manejador de señales; ver fcntl(2) y signal(7).
EINVAL
El argumento length es negativo o mayor que el tamaño máximo del archivo.
EIO
Ocurrió un error de E/S al actualizar el inodo.
EISDIR
El archivo nombrado es un directorio.
ELOOP
Se encontraron demasiados enlaces simbólicos al traducir el nombre de ruta.
ENAMETOOLONG
Un componente de un nombre de ruta excedió los 255 caracteres, o un nombre de ruta completo excedió los 1023 caracteres.
ENOENT
El archivo nombrado no existe.
ENOTDIR
Un componente del prefijo de ruta no es un directorio.
EPERM
El sistema de archivos subyacente no soporta la extensión de un archivo más allá de su tamaño actual.
EPERM
La operación fue impedida por un sello de archivo; ver fcntl(2).
EROFS
El archivo nombrado reside en un sistema de archivos de solo lectura.
ETXTBSY
El archivo es un archivo ejecutable que se está ejecutando.

Para ftruncate() se aplican los mismos errores, pero en lugar de cosas que pueden estar mal con path, tenemos cosas que pueden estar mal con el descriptor de archivo, fd:

EBADF
fd no es un descriptor de archivo válido.
EBADF o EINVAL
fd no está abierto para escritura.
EINVAL
fd no hace referencia a un archivo regular ni a un objeto de memoria compartida POSIX.
EINVAL o EBADF
El descriptor de archivo fd no está abierto para escritura. POSIX permite, y las aplicaciones portables deben manejar, cualquiera de los dos errores para este caso. (Linux produce EINVAL.)

VERSIÓNES

Los detalles en DESCRIPCIÓN son para sistemas compatibles con XSI. Para sistemas no compatibles con XSI, el estándar POSIX permite dos comportamientos para ftruncate() cuando length excede la longitud del archivo (tener en cuenta que truncate() no se especifica en absoluto en tal entorno): devolver un error o extender el archivo. Como la mayoría de las implementaciones UNIX, Linux sigue el requisito XSI al tratar con sistemas de archivos nativos. Sin embargo, algunos sistemas de archivos no nativos no permiten que truncate() y ftruncate() se utilicen para extender un archivo más allá de su longitud actual: un ejemplo notable en Linux es VFAT.

En algunas arquitecturas de 32 bits, la firma de llamada para estas llamadas al sistema difiere, por las razones descritas en syscall(2).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SVr4, 4.2BSD.

Las llamadas al sistema truncate() y ftruncate() originales de Linux no fueron diseñadas para manejar compensaciones de archivos grandes. En consecuencia, Linux 2.4 agregó las llamadas al sistema truncate64() y ftruncate64() que manejan archivos grandes. Sin embargo, estos detalles pueden ser ignorados por las aplicaciones que usan glibc, cuyas funciones envoltorio emplean transparentemente las llamadas al sistema más recientes donde están disponibles.

NOTAS

ftruncate() también puede usarse para establecer el tamaño de un objeto de memoria compartida POSIX; ver shm_open(3).

ERRORES CONOCIDOS

Un error en el archivo de cabecera en glibc 2.12 hizo que el valor mínimo de _POSIX_C_SOURCE necesario para exponer la declaración de ftruncate() fuera 200809L en lugar de 200112L. Esto se ha corregido en versiones posteriores de glibc.

VER TAMBIÉN

truncate(1), open(2), stat(2), path_resolution(7)
