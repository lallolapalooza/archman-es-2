TRAP(1P) Manual del programador de POSIX TRAP(1P)

PROLOGO

Este manual forma parte del Manual del programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página de manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

trap — capturar señales

SINOPSIS

trap n [condición...]
trap [acción condición...]

DESCRIPCIÓN

Si el primer operando es un entero decimal sin signo, el shell tratará todos los operandos como condiciones y restablecerá cada condición a su valor predeterminado. De lo contrario, si hay operandos, el primero se tratará como una acción y los restantes como condiciones.

Si acción es '-', el shell restablecerá cada condición a su valor predeterminado. Si acción está vacía (""), el shell ignorará cada condición especificada si ocurre. De lo contrario, la cadena acción será leída y ejecutada por el shell cuando surja una de las condiciones correspondientes. La acción de trap anulará una acción previa (ya sea la acción predeterminada o una establecida explícitamente). El valor de "$?" después de que se complete la acción de trap será el valor que tenía antes de que se invocara trap.

La condición puede ser EXIT, 0 (equivalente a EXIT), o una señal especificada usando un nombre simbólico, sin el prefijo SIG, tal como se enumera en las tablas de nombres de señales en el archivo de cabecera <signal.h> definido en el volumen de Definiciones Base de POSIX.1-2017, Capítulo 13, Cabeceras; por ejemplo, HUP, INT, QUIT, TERM. Las implementaciones pueden permitir nombres con el prefijo SIG o ignorar mayúsculas/minúsculas en los nombres de señales como una extensión. Establecer una trampa para SIGKILL o SIGSTOP produce resultados indefinidos.

El entorno en el que el shell ejecuta una trap en EXIT será idéntico al entorno inmediatamente después del último comando ejecutado antes de que se tomara la trap en EXIT.

Cada vez que se invoca trap, el operando acción se procesará de manera equivalente a:

eval acción

Las señales que fueron ignoradas al entrar en un shell no interactivo no pueden ser atrapadas ni restablecidas, aunque no es necesario informar de un error al intentar hacerlo. Un shell interactivo puede restablecer o capturar señales ignoradas al entrar. Las trampas permanecerán activas para un shell dado hasta que se cambien explícitamente con otro comando trap.

Cuando se entra en un subshell, las trampas que no están siendo ignoradas se establecerán a las acciones predeterminadas, excepto en el caso de una sustitución de comando que contenga solo un comando trap, cuando las trampas no necesitan ser alteradas. Las implementaciones pueden verificar este caso usando solo análisis léxico; por ejemplo, si `trap` y $( trap -- ) no alteran las trampas en el subshell, casos como asignar var=trap y luego usar $($var) aún pueden alterarlas. Esto no implica que el comando trap no pueda usarse dentro del subshell para establecer nuevas trampas.

El comando trap sin operandos escribirá en la salida estándar una lista de comandos asociados con cada condición. Si el comando se ejecuta en un subshell, la implementación no realiza la verificación opcional descrita anteriormente para una sustitución de comando que contenga solo un comando trap, y no se han ejecutado comandos trap con operandos desde la entrada al subshell, la lista contendrá los comandos que estaban asociados con cada condición inmediatamente antes de que se ingresara el entorno del subshell. De lo contrario, la lista contendrá los comandos actualmente asociados con cada condición. El formato será:

"trap -- %s %s ...\n", <acción>, <condición> ...

El shell formateará la salida, incluido el uso adecuado de las comillas, de modo que sea adecuada para volver a ingresarla al shell como comandos que logren los mismos resultados de captura. Por ejemplo:

save_traps=$(trap)
...
eval "$save_traps"

Los sistemas conformes a XSI también permiten números de señal numéricos para las condiciones correspondientes a los siguientes nombres de señales:

SIGHUP

SIGINT

SIGQUIT
6
SIGABRT
9
SIGKILL

El comando interno trap se ajustará a las Directrices de sintaxis de utilidades, Sección 12.2, del volumen de Definiciones Base de POSIX.1-2017.

ESTADO DE SALIDA

Si el nombre o número de trampa no es válido, se devolverá un estado de salida distinto de cero; de lo contrario, se devolverá cero. Tanto para shells interactivos como no interactivos, los nombres o números de señal inválidos no se considerarán un error de sintaxis y no harán que el shell aborte.

EJEMPLOS

Escribir una lista de todas las trampas y acciones:

trap

Establecer una trampa para que la utilidad logout en el directorio al que se refiere la variable de entorno HOME se ejecute cuando el shell termine:

trap '"$HOME"/logout' EXIT

o:

trap '"$HOME"/logout' 0

Anular las trampas en INT, QUIT, TERM y EXIT:

trap - INT QUIT TERM EXIT

RACIONALE

Las implementaciones pueden permitir nombres de señales en minúsculas como una extensión. Las implementaciones también pueden aceptar los nombres con el prefijo SIG; ninguna shell histórica conocida lo hace. Las utilidades trap y kill en este volumen de POSIX.1-2017 son ahora consistentes en la omisión del prefijo SIG para los nombres de señales. Algunas implementaciones de kill no permiten el prefijo, y kill -l lista las señales sin prefijos.

Capturar SIGKILL o SIGSTOP es sintácticamente aceptado por algunas implementaciones históricas, pero no tiene efecto. Las aplicaciones POSIX portátiles no pueden intentar capturar estas señales.

El formato de salida no es una práctica histórica. Dado que la salida de los comandos trap históricos no es portable (porque los valores numéricos de las señales no son portables) y tuvo que cambiar para serlo, se aprovechó la oportunidad para formatear la salida de manera que un script de shell pudiera usar para guardar y luego reutilizar una trampa si lo deseara.

El KornShell utiliza una trampa ERR que se activa cada vez que set -e causaría

RATIONALE

The exit trap is a useful feature that is not specified in the original Bourne shell specification. Although it has been implemented in some shells, it was not considered a core feature and was therefore not mandated in the POSIX standard. However, it has been included in this volume of POSIX.1‐2001 as an allowable extension.

The text regarding the environment for the EXIT trap invalidates the behavior of some historical versions of interactive shells, which, for example, would close the standard input before executing a trap on 0. For instance, in some historical interactive shell sessions, the following trap on 0 would always print "--":

trap 'read foo; echo "-$foo-"' 0

The command:

trap 'eval " $cmd"' 0

causes the contents of the shell variable cmd to be executed as a command when the shell exits. Using:

trap '$cmd' 0

does not work correctly if cmd contains any special characters, such as quoting or redirections. Using:

trap " $cmd" 0

also works (the leading <space> character protects against unlikely cases where cmd is a decimal integer or begins with '-'), but it expands the cmd variable when the trap command is executed, not when the exit action is executed.
