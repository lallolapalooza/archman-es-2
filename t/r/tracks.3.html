void LIBMTP_destroy_track_t (LIBMTP_track_t * track)

Esto destruye una estructura de metadatos de pista y libera la memoria utilizada por la misma, incluidas todas las cadenas. Nunca vuelvas a utilizar una estructura de metadatos de pista después de llamar a esta función sobre ella.

Parámetros

track los metadatos de la pista a destruir.

LIBMTP_track_t * LIBMTP_Get_Tracklisting_With_Callback (LIBMTP_mtpdevice_t * device, LIBMTP_progressfunc_t const callback, void const *const data)

Esto devuelve una larga lista de todas las pistas disponibles en el dispositivo MTP actual. Las pistas incluyen objetos multimedia, b

música y video pistas. Uso típico:

LIBMTP_track_t *tracklist;
tracklist = LIBMTP_Get_Tracklisting_With_Callback(device, callback, data);
while (tracklist != NULL) {
  LIBMTP_track_t *tmp;
  // Haz algo con cada elemento de la lista aquí...
  tmp = tracklist;
  tracklist = tracklist->next;
  LIBMTP_destroy_track_t(tmp);
}

Si deseas agrupar la lista de pistas por almacenamiento (por unidad de almacenamiento) o organizar las pistas en carpetas, debes desreferenciar el campo storage_id y/o parent_id de la estructura LIBMTP_track_t devuelta. Para organizar por carpetas o archivos, generalmente debes crear los árboles correctos primero mediante llamadas a LIBMTP_Get_Storage() y/o LIBMTP_Get_Folder_List().

Parámetros

device un puntero al dispositivo del que se obtendrá la lista de pistas.
callback una función que se llamará durante la recuperación de la lista de pistas para mostrar barras de progreso, etc., o NULL si no deseas ninguna llamada de retorno.
data un puntero definido por el usuario que se pasa a la función de progreso para pasar algunos datos definidos por el usuario a las actualizaciones de progreso. Si no se usa, configúralo en NULL.

Devoluciones

una lista de pistas que se puede seguir utilizando el campo next de la estructura de datos LIBMTP_track_t. Cada una de las etiquetas de metadatos debe liberarse después de su uso y puede contener solo información parcial de metadatos, es decir, uno o varios campos pueden ser NULL o 0.

LIBMTP_track_t * LIBMTP_Get_Trackmetadata (LIBMTP_mtpdevice_t * device, uint32_t const trackid)

Esta función recupera los metadatos de una sola pista del dispositivo.

¡No llames a esta función repetidamente! Los identificadores de pistas se buscan linealmente O(n) y la llamada puede implicar tráfico USB (lento), así que usa LIBMTP_Get_Tracklisting() y almacena las pistas en caché, preferiblemente como una estructura de datos eficiente como una lista hash.

Parámetros

device un puntero al dispositivo del que se obtienen los metadatos de la pista.
trackid el ID del objeto de la pista de la que deseas los metadatos.

Devoluciones

una entrada de metadatos de pista en caso de éxito o NULL en caso de fallo.

int LIBMTP_Send_Track_From_File (LIBMTP_mtpdevice_t * device, char const *const path, LIBMTP_track_t *const metadata, LIBMTP_progressfunc_t const callback, void const *const data)

Esta función envía una pista desde un archivo local a un dispositivo MTP. Se deben proporcionar un nombre de archivo y un conjunto de metadatos como entrada.

Parámetros

device un puntero al dispositivo al que se enviará la pista.
path el nombre del archivo local que se enviará.
metadata un conjunto de metadatos de pista que se escribirán junto con el archivo. Después de esta llamada, el campo metadata->item_id contendrá el nuevo ID de pista. Otros campos como metadata->filename, metadata->parent_id o metadata->storage_id también pueden cambiar durante esta operación debido a las restricciones del dispositivo, por lo que no confíes en que el contenido de esta estructura se conserve de ninguna manera.
  • metadata->parent_id debe establecerse en el padre (por ejemplo, carpeta) en el que almacenar esta pista. Dado que algunos dispositivos son un poco exigentes sobre dónde se colocan los archivos, se elegirá una carpeta predeterminada si libmtp ha detectado una para el tipo de archivo actual y este parámetro está establecido en 0. Si es 0 y no se puede encontrar ninguna carpeta predeterminada, el archivo se almacenará en la carpeta raíz.
  • metadata->storage_id debe establecerse en el almacenamiento deseado (por ejemplo, tarjeta de memoria o lo que sea que presente su dispositivo) para almacenar esta pista. Establecer esto en 0 almacenará la pista en el almacenamiento principal.

callback una función indicadora de progreso o NULL para ignorar.
data un puntero definido por el usuario que se pasa a la función de progreso para pasar algunos datos definidos por el usuario a las actualizaciones de progreso. Si no se usa, configúralo en NULL.

Devoluciones

0 si la transferencia fue exitosa, cualquier otro valor significa fallo.

This function sends a file to the MTP device. It is intended for files that are already opened and readable.

Parameters

filesize The size of the file in bytes.
fd File descriptor of the file to send.
parent_id The ID of the parent directory where the file should be stored. Use 0 for the root directory.
storage_id The ID of the storage medium where the file should be stored. Use 0 for the primary storage.
callback a progress indicator function or NULL to ignore.
data a user-defined pointer that is passed along to the progress function in order to pass along some user defined data to the progress updates. If not used, set this to NULL.

Returns

0 if the transfer was successful, any other value means failure.

int LIBMTP_Send_Track_From_Handler (LIBMTP_mtpdevice_t * device, MTPDataGetFunc get_func, void * priv, LIBMTP_track_t *const metadata, LIBMTP_progressfunc_t const callback, void const *const data)

This function sends a track from a handler function to an MTP device. A filename and a set of metadata must be given as input.

Parameters

device a pointer to the device to send the track to.
get_func the function to call when we have data.
priv the user-defined pointer that is passed to get_func.
metadata a track metadata set to be written along with the file. After this call the field metadata->item_id will contain the new track ID. Other fields such as the metadata->filename, metadata->parent_id or metadata->storage_id may also change during this operation due to device restrictions, so do not rely on the contents of this struct to be preserved in any way.
  • metadata->parent_id should be set to the parent (e.g. folder) to store this track in. Since some devices are a bit picky about where files are placed, a default folder will be chosen if libmtp has detected one for the current filetype and this parameter is set to 0. If this is 0 and no default folder can be found, the file will be stored in the root folder.
  • metadata->storage_id should be set to the desired storage (e.g. memory card or whatever your device presents) to store this track in. Setting this to 0 will store the track on the primary storage.

callback a progress indicator function or NULL to ignore.
data a user-defined pointer that is passed along to the progress function in order to pass along some user defined data to the progress updates. If not used, set this to NULL.

Returns

0 if the transfer was successful, any other value means failure.

int LIBMTP_Update_Track_Metadata (LIBMTP_mtpdevice_t * device, LIBMTP_track_t const *const metadata)

This function updates the MTP track object metadata on a single file identified by an object ID.

Parameters

device a pointer to the device to update the track metadata on.
metadata a track metadata set to be written to the file. notice that the track_id field of the metadata structure must be correct so that the function can update the right file. If some properties of this metadata are set to NULL (strings) or 0 (numerical values) they will be discarded and the track will not be tagged with these blank values.

Returns

0 on success, any other value means failure. If some or all of the properties fail to update we will still return success. On some devices (notably iRiver T30) properties that exist cannot be updated.
