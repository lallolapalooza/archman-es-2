TRACE-CMD.DAT.V(5) Manual de libtracefs TRACE-CMD.DAT.V(5)

NOMBRE

trace-cmd.dat.v7 - formato de archivo trace-cmd versión 7

SINOPSIS

trace-cmd.dat ignorar

DESCRIPCIÓN

La utilidad trace-cmd(1) produce un archivo "trace.dat". El archivo también puede tener cualquier nombre dependiendo de si el usuario especifica un nombre de salida diferente, pero debe tener un formato binario específico. El archivo es utilizado por trace-cmd para guardar trazas del kernel en él y poder extraer la traza del mismo en un momento posterior (ver trace-cmd-report(1)).

FORMATO INICIAL

Los primeros tres bytes contienen el valor mágico:
0x17 0x08  0x44
Los siguientes 7 bytes contienen los caracteres:
"tracing"
El siguiente conjunto de caracteres contiene una cadena terminada en
null ('\0') que contiene la versión del archivo:
"7\0"
El siguiente byte contiene las banderas de la endianness del archivo:
0 = little endian
1 = big endian
El siguiente byte contiene el número de bytes por valor "long":
4 - valores long de 32 bits
8 - valores long de 64 bits
Nota: Este es el tamaño de long del espacio de usuario del objetivo. No
el tamaño del espacio del kernel.
[ Ahora todos los números se escriben en la endianness definida por el archivo. ]
Los siguientes 4 bytes son una palabra de 32 bits que define cuál era el tamaño
de página de la máquina host trazada.
El encabezado del algoritmo de compresión se escribe a continuación:
   "nombre\0versión\0"
donde "nombre" y "versión" son cadenas, el nombre y la versión del algoritmo de
compresión utilizado para comprimir el archivo de traza. Si el nombre es
"none", los datos en el archivo no están comprimidos.
Los siguientes 8 bytes son un entero de 64 bits, el desplazamiento dentro del
archivo donde se encuentra la primera sección OPTIONS.
El resto del archivo consiste en diferentes secciones. La única obligatoria
es la primera sección OPTIONS, todas las demás son opcionales. La ubicación y
el orden de las secciones no son estrictos. Cada sección comienza con un encabezado:

FORMATO DEL ENCABEZADO DE SECCIÓN

<2 bytes> entero corto sin signo, ID de la sección.
<2 bytes> entero corto sin signo, banderas de sección:
  1 = la sección está comprimida.
<4 bytes> ID de una cadena, descripción de la sección.
<8 bytes> entero largo largo sin signo, tamaño de la sección en el archivo.
Si la sección está comprimida, lo anterior es el tamaño comprimido.
La sección debe ser descomprimida al leer. El formato descrito de
las secciones se refiere a los datos descomprimidos.

FORMATO DE COMPRESIÓN DE LAS SECCIONES DEL ARCHIVO

Algunas de las secciones del archivo pueden estar comprimidas con el algoritmo de
compresión, especificado en el encabezado del algoritmo de compresión. Las secciones
comprimidas tienen un encabezado de compresión, escrito después del encabezado de
sección y justo antes de los datos comprimidos:
  <4 bytes> entero sin signo, tamaño de los datos comprimidos en esta sección.
  <4 bytes> entero sin signo, tamaño de los datos sin comprimir.
  <datos> datos binarios comprimidos, con el tamaño especificado.

FORMATO DE COMPRESIÓN DE LOS DATOS DE TRAZA

Hay dos secciones especiales, BUFFER FLYRECORD y BUFFER LATENCY, que contienen
datos de traza. Estas secciones pueden comprimirse con el algoritmo de compresión,
especificado en el encabezado de compresión. Normalmente, el tamaño de estas
secciones es enorme, por eso su formato de compresión es diferente al de las
otras secciones. Los datos de traza se comprimen en fragmentos. El tamaño de un
fragmento se especifica en el momento de la creación del archivo. El formato de
los datos de traza comprimidos es:
   <4 bytes> entero sin signo, número de fragmentos.
   Siguen los fragmentos comprimidos del número dado. Para cada fragmento:
      <4 bytes> entero sin signo, tamaño de los datos comprimidos en este fragmento.
      <4 bytes> entero sin signo, tamaño de los datos sin comprimir, alineado con el tamaño de página de traza.
      <datos> datos binarios comprimidos, con el tamaño especificado.
Estos fragmentos deben ser descomprimidos al leer. El formato descrito de
los datos de traza se refiere a los datos sin comprimir.

SECCIÓN OPTIONS

ID de Sección: 0
Esta es la única sección obligatoria en el archivo. Puede haber múltiples
secciones de opciones, la primera se encuentra en el desplazamiento especificado
justo después del encabezado del algoritmo de compresión. La sección consta de
múltiples opciones de traza, cada opción tiene el siguiente formato:
  <2 bytes> entero corto sin signo, ID de la opción.
  <4 bytes> entero sin signo, tamaño de los datos de la opción.
  <datos binarios> bytes del tamaño especificado anteriormente, datos de la opción.
Opciones, soportadas por la versión 7 del archivo de traza:
DONE: id 0, tamaño 8
  Esta opción indica el final de la sección de opciones, se escribe
  siempre como la última opción. Los datos de la opción DONE son:
     <8 bytes> entero largo largo sin signo, desplazamiento en el archivo de traza donde
     se encuentra la siguiente sección de opciones. Si este desplazamiento es 0,
     entonces no hay más secciones de opciones.
DATE: id 1, tamaño variable
  Los datos de la opción DATE son una cadena ASCII terminada en nulo, que representa
  la diferencia de tiempo entre las marcas de tiempo de los eventos de traza y la
  Hora del Día Genérica del sistema.
CPUSTAT: id 2, tamaño variable
  Los datos de la opción CPUSTAT son una cadena ASCII terminada en nulo, el contenido
  del archivo "per_cpu/cpu<id>/stats" del directorio de traza. Hay una opción CPUSTAT
  para cada CPU.
BUFFER: id 3, tamaño variable
  La opción BUFFER describe los datos de traza flyrecord guardados en el archivo,
  recogidos de una instancia de traza. Hay una opción BUFFER para cada instancia de
  traza. El formato de los datos de BUFFER es:
    <8 bytes> entero largo largo sin signo, desplazamiento en el archivo de traza donde se
    encuentra la sección BUFFER FLYRECORD, que contiene datos de traza flyrecord.
    <cadena> una cadena ASCII terminada en nulo, nombre de la instancia de traza. Una cadena
    vacía "" se guarda como nombre de la instancia superior.
    <cadena> una cadena ASCII terminada en nulo, reloj de traza utilizado para las marcas de
    tiempo de los eventos en esta instancia de traza.
    <4 bytes> entero sin signo, tamaño de la página del búfer de traza.
    <4 bytes> entero sin signo, número de CPUs con datos de traza.
    Para cada CPU del número anterior:
       <4 bytes> entero sin signo, ID de la CPU.
       <8 bytes> entero largo largo sin signo, desplazamiento en el archivo de traza donde se
       encuentran los datos de traza para esta CPU.
       <8 bytes> entero largo largo sin signo, tamaño de los datos de traza para esta CPU.
TRACECLOCK: id 4, tamaño variable
  Los datos de la opción TRACECLOCK son una cadena ASCII terminada en nulo, el contenido
  del archivo "trace_clock" del directorio de traza.
UNAME: id 5, tamaño variable
  Los datos de la opción UNAME son una cadena ASCII terminada en nulo, que identifica el
  sistema donde se recopilan los datos de traza. La cadena se recupera mediante la llamada
  al sistema uname().
HOOK: id 6, tamaño variable
  Los datos de la opción HOOK son una cadena ASCII terminada en nulo, que describe los
  hooks de eventos: coincidencia de eventos personalizada para conectar dos eventos entre
  sí.
OFFSET: id 7, tamaño variable
  Los datos de la opción OFFSET son una cadena ASCII terminada en nulo, que representa un
  tiempo fijo que se añade a cada marca de tiempo de evento al leer.
CPUCOUNT: id 8, tamaño 4
  Los datos de la opción CPUCOUNT son:
    <4 bytes> entero sin signo, número de CPUs en el sistema.
VERSION: id 9, tamaño variable
  Los datos de la opción VERSION son una cadena ASCII terminada en nulo, que representa la
  versión de la aplicación trace-cmd, utilizada para recopilar estos registros de traza.
PROCMAPS: id 10, tamaño variable
  Los datos de la opción PROCMAPS son una cadena ASCII terminada en nulo, que representa
  el mapa de memoria de cada proceso filtrado trazado. El formato de la cadena es, para
  cada
ch filtered process: <procss ID> <libraries count> <process command> \n <memory start address> <memory end address> <full path of the mapped library file> \n ... línea separada para cada biblioteca, usada por este proceso ... ... 
TRACEID: id 11, tamaño 8
  Los datos de la opción TRACEID son un identificador único de esta sesión de rastreo:
    <8 bytes> entero sin signo long long, identificador de la sesión de rastreo.
TIME_SHIFT: id 12, tamaño variable
  La opción TIME_SHIFT almacena información de sincronización de tiempo, recopilada durante el rastreo del host y el guest.
  Normalmente se guarda en el archivo de rastreo del guest. Esta información se utiliza para
  sincronizar los eventos del guest con los eventos del host
  cuando se muestran todos los archivos de esta sesión de rastreo. El formato de los datos de la opción TIME_SHIFT es:
    <8 bytes> entero sin signo long long, identificador de rastreo del par (normalmente el host).
    <4 bytes> entero sin signo, flags específicos del protocolo de sincronización de tiempo, utilizado en esta
    sesión de rastreo.
    <4 bytes> entero sin signo, número de CPUs rastreadas. Para cada CPU, se registran correcciones de marcas de tiempo:
       <4 bytes> entero sin signo, recuento de las correcciones de marcas de tiempo registradas para esta CPU.
       <array de enteros sin signo long long del recuento anterior>, momentos en que se calculan las correcciones
       <array de enteros sin signo long long del recuento anterior>, desplazamientos de las correcciones
       <array de enteros sin signo long long del recuento anterior>, ratios de escala de las correcciones
GUEST: id 13, tamaño variable
  La opción GUEST almacena información sobre los guests rastreados en esta sesión de rastreo. Normalmente se guarda
  en el archivo de rastreo del host. Hay una opción GUEST separada para cada guest rastreado.
  La información se utiliza al mostrar todos los archivos de esta sesión de rastreo. El formato de
  los datos de la opción GUEST es:
     <string> una cadena ASCII terminada en nulo, nombre del guest.
     <8 bytes> entero sin signo long long, identificador de rastreo del guest para esta sesión.
     <4 bytes> entero sin signo, número de CPUs del guest. Para cada CPU:
        <4 bytes> entero sin signo, ID de la CPU.
        <4 bytes> entero sin signo, PID de la tarea del host, que emula esta CPU del guest.
TSC2NSEC: id 14, tamaño 16
  La opción TSC2NSEC almacena información utilizada para convertir las marcas de tiempo de los eventos TSC a nanosegundos.
  El formato de los datos de la opción TSC2NSEC es:
     <4 bytes> entero sin signo, multiplicador de tiempo.
     <4 bytes> entero sin signo, desplazamiento de tiempo.
     <8 bytes> entero sin signo long long, desplazamiento de tiempo.
STRINGS: id 15, tamaño variable
  La opción STRINGS contiene una lista de cadenas terminadas en nulo que contienen los nombres de las
  otras secciones.
HEADER_INFO: id 16, tamaño 8
  Los datos de la opción HEADER_INFO son:
    <8 bytes> entero sin signo long long, desplazamiento dentro del archivo de rastreo donde se encuentra la sección HEADER INFO.
FTRACE_EVENTS: id 17, tamaño 8
  Los datos de la opción FTRACE_EVENTS son:
    <8 bytes> entero sin signo long long, desplazamiento dentro del archivo de rastreo donde se encuentra la
    sección FTRACE EVENT FORMATS.
EVENT_FORMATS: id 18, tamaño 8
  Los datos de la opción EVENT_FORMATS son:
    <8 bytes> entero sin signo long long, desplazamiento dentro del archivo de rastreo donde se encuentra la
    sección EVENT FORMATS.
KALLSYMS: id 19, tamaño 8
  Los datos de la opción KALLSYMS son:
    <8 bytes> entero sin signo long long, desplazamiento dentro del archivo de rastreo donde se encuentra la
    sección KALLSYMS.
PRINTK: id 20, tamaño 8
  Los datos de la opción PRINTK son:
    <8 bytes> entero sin signo long long, desplazamiento dentro del archivo de rastreo donde se encuentra la
    sección TRACE_PRINTK.
CMDLINES: id 21, tamaño 8
  Los datos de la opción CMDLINES son:
    <8 bytes> entero sin signo long long, desplazamiento dentro del archivo de rastreo donde se encuentra la
    sección SAVED COMMAND LINES.
BUFFER_TEXT: id 22, tamaño
  La opción BUFFER_LAT describe los datos de rastreo de latencia guardados en el archivo. El formato
  de los datos de la opción BUFFER_LAT es:
    <8 bytes> entero sin signo long long, desplazamiento en el archivo de rastreo donde se encuentra la
    sección BUFFER LATENCY, que contiene datos de rastreo de latencia.
    <string> una cadena ASCII terminada en nulo, nombre de la instancia de rastreo. Se guarda una cadena vacía ""
    como nombre de la instancia superior.
    <string> una cadena ASCII terminada en nulo, reloj de rastreo utilizado para las marcas de tiempo de los eventos en
    esta instancia de rastreo.

SECCIÓN DE INFORMACIÓN DE CABECERA

ID de Sección: 16
Los primeros 12 bytes de la sección, después de la cabecera de la sección, contienen la cadena:
"header_page\0"
Los siguientes 8 bytes son una palabra de 64 bits que contiene el tamaño de la
información de la cabecera de página que se almacena a continuación.
El siguiente conjunto de datos tiene el tamaño leído de los 8 bytes anteriores
y contiene los datos recuperados de debugfs/tracing/events/header_page.
Nota: El tamaño del segundo campo \fBcommit\fR contiene el tamaño largo del kernel de destino. Por ejemplo:
campo: local_t commit;        desplazamiento:8;       \fBtamaño:8;\fR   con signo:1;
muestra que el kernel tiene un long de 64 bits.
Los siguientes 13 bytes contienen la cadena:
"header_event\0"
Los siguientes 8 bytes son una palabra de 64 bits que contiene el tamaño de la
información de la cabecera de evento que se almacena a continuación.
El siguiente conjunto de datos tiene el tamaño leído de los 8 bytes anteriores
y contiene los datos recuperados de debugfs/tracing/events/header_event.
Estos datos permiten a la herramienta trace-cmd saber si el formato del búfer circular
del kernel ha realizado algún cambio.

SECCIÓN DE FORMATOS DE EVENTOS FTRACE

ID de Sección: 17
Directamente después de la cabecera de la sección viene la información sobre
los eventos específicos de Ftrace. Estos son los eventos utilizados por los plugins de Ftrace
y no se habilitan mediante el rastreo de eventos.
Los siguientes 4 bytes contienen una palabra de 32 bits con el número de formatos de eventos Ftrace
que se almacenan en el archivo.
Por el número de veces definido por los 4 bytes anteriores está lo siguiente:
8 bytes para el tamaño del archivo de formato de evento Ftrace.
El archivo de formato de evento Ftrace copiado de la máquina de destino:
debugfs/tracing/events/ftrace/<evento>/format

SECCIÓN DE FORMATOS DE EVENTOS

ID de Sección: 18
Directamente después de la cabecera de la sección viene la información sobre
el diseño de los eventos.
Los siguientes 4 bytes son una palabra de 32 bits que contiene el número de
sistemas de eventos que se almacenan en el archivo. Estos son los
directorios en debugfs/tracing/events excluyendo el directorio \fBftrace\fR.
Por el número de veces definido por los 4 bytes anteriores está lo siguiente:
Una cadena terminada en nulo que contiene el nombre del sistema.
4 bytes que contienen una palabra de 32 bits con el número
de eventos dentro del sistema.
Por el número de veces definido en los 4 bytes anteriores está lo siguiente:
8 bytes para el tamaño del archivo de formato de evento.
El archivo de formato de evento copiado de la máquina de destino:
debugfs/tracing/events/<sistema>/<evento>/format

SECCIÓN DE KALLSYMS

ID de Sección: 19
Directamente después de la cabecera de la sección viene la información del mapeo
de direcciones de funciones a nombres de funciones.
Los siguientes 4 bytes son una palabra de 32 bits que contiene el tamaño de los
datos que albergan los mapeos de funciones.
El siguiente conjunto de datos tiene el tamaño definido por los 4 bytes anteriores
y contiene la información del archivo de la máquina de destino:
/proc/kallsyms

SECCIÓN DE TRACE_PRINTK

ID de Sección: 20
Si un desarrollador utilizó trace_printk() dentro del kernel, puede
almacenar la cadena de formato fuera del búfer circular.
Esta información se puede encontrar en:
debugfs/tracing/printk_formats
Los siguientes 4 bytes son una palabra de 32 bits que contiene el tamaño de los
datos que albergan los formatos printk.
El siguiente conjunto de datos tiene el tamaño definido por los 4 bytes anteriores
y contiene la información de debugfs/tracing/printk_formats.

SECCIÓN DE LÍNEAS DE COMANDOS GUARDADAS

ID de Sección: 21
Directamente después de la cabecera de la sección viene la información del mapeo
de un PID a un nombre de proceso.
Los siguientes 8 bytes contienen una palabra de 64 bits que contiene el tamaño de los
datos que mapean el PID a un nombre de proceso.
El siguiente conjunto de datos tiene el tamaño definido por los 8 bytes anteriores
y contiene la información de debugfs/tracing/saved_cmdlines.

SECCIÓN DE BUFFER FLYRECORD

Esta sección contiene datos de rastreo flyrecord, recopilados en una instancia de rastreo.
Los datos se guardan por CPU. Cada sección BUFFER FLYRECORD tiene una opción BUFFER correspondiente,
que contiene información sobre los datos de rastreo de las CPUs guardadas. Se coloca relleno entre
la cabecera de la sección y los datos de la CPU, colocando los datos de la CPU en una posición
alineada con la página (página de destino) en el archivo.
Estos datos se copian directamente del búfer circular de Ftrace y tienen el
mismo formato que el búfer circular especificado por los archivos de cabecera de eventos
cargados en el archivo de formato de cabecera.
La herramienta trace-cmd intentará hacer \fBmmap(2)\fR de los datos página por página con
el tamaño de página del destino, si es posible. Si falla al mapear, simplemente leerá
los datos en su lugar.

SECCIÓN DE TEXTO DEL BÚFER

.ft C
  Section ID: 22
  This section contains latency tracing data, ASCII text taken from the
  target's debugfs/tracing/trace file.
STRINGS SECTION
.ft
Section ID: 15
All strings of the trace file metadata are stored in a string section within the file. The section
contains a list of nul terminated ASCII strings. An ID of the string is used in the file
meta data, which is the offset of the actual string into the string section. Strings can be stored
into multiple string sections in the file.
