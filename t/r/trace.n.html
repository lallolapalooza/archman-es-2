trace(n) Tcl Built-In Commands trace(n)

NOMBRE

trace - Monitorizar accesos a variables, usos de comandos y ejecuciones de comandos

SINOPSIS

trace opción ?arg arg ...?

DESCRIPCIÓN

Este comando provoca que se ejecuten comandos Tcl siempre que se invoquen ciertas operaciones. Las opciónes legales (que pueden ser abreviadas) son:

trace add tipo nombre operaciones ?args?
Donde tipo es command, execution o variable.
trace add command nombre operaciones comandoPrefijo
Organizar para que comandoPrefijo se ejecute (con argumentos adicionales) siempre que el comando nombre sea modificado de una de las maneras indicadas por la lista operaciones. Nombre se resolverá utilizando las reglas habituales de resolución de namespaces utilizadas por los comandos. Si el comando no existe, se lanzará un error.

Operaciones indica qué operaciones son de interés, y es una lista de uno o más de los siguientes elementos:

rename
Invocar comandoPrefijo siempre que se renombre el comando trazado. Tenga en cuenta que renombrar a una cadena vacía se considera eliminación y no será trazado con "rename".
delete
Invocar comandoPrefijo cuando se elimina el comando trazado. Los comandos se pueden eliminar explícitamente usando el comando rename para renombrar el comando a una cadena vacía. Los comandos también se eliminan cuando se elimina el intérprete, pero los traces no se invocarán ya que no hay un intérprete en el que ejecutarlos.

Cuando el trace se activa, dependiendo de las operaciones que se estén trazando, se añaden varios argumentos a comandoPrefijo para que el comando real sea el siguiente:

comandoPrefijo nombreAntiguo nombreNuevo operacion

NombreAntiguo y nombreNuevo dan el nombre actual (antiguo) del comando trazado y el nombre al que se está renombrando (la cadena vacía si es una operación de "delete"). Operacion indica qué operación se está realizando en el comando, y es uno de rename o delete según se definieron anteriormente. La operación de trace no se puede utilizar para evitar que se elimine un comando. Tcl eliminará siempre el comando una vez que el trace se complete. El renombrado o eliminación recursiva no provocará que se evalúen más traces del mismo tipo, por lo que un trace de eliminación que a su vez elimine el comando, o un trace de renombrado que a su vez renombre el comando, no provocará que se produzcan más evaluaciones de trace. Tanto nombreAntiguo como nombreNuevo están completamente calificados con cualquier namespace en el que aparezcan.

trace add execution nombre operaciones comandoPrefijo
Organizar para que comandoPrefijo se ejecute (con argumentos adicionales) siempre que el comando nombre se ejecute, con traces que ocurren en los puntos indicados por la lista operaciones. Nombre se resolverá utilizando las reglas habituales de resolución de namespaces utilizadas por los comandos. Si el comando no existe, se lanzará un error.

Operaciones indica qué operaciones son de interés, y es una lista de uno o más de los siguientes elementos:

enter
Invocar comandoPrefijo siempre que se ejecute el comando nombre, justo antes de que tenga lugar la ejecución real.
leave
Invocar comandoPrefijo siempre que se ejecute el comando nombre, justo después de que tenga lugar la ejecución real.
enterstep
Invocar comandoPrefijo para cada comando Tcl que se ejecute desde el inicio de la ejecución del procedimiento nombre hasta que dicho procedimiento finalice. Se invoca comandoPrefijo justo antes de que tenga lugar la ejecución real del comando Tcl que se está informando. Por ejemplo, si tenemos “proc foo {} { puts "hello" }”, entonces se invocará un trace de enterstep justo antes de que se ejecute “puts "hello"”. Establecer un trace de enterstep en un comando nombre que no se refiere a un procedimiento no generará un error y simplemente se ignorará.
leavestep
Invocar comandoPrefijo para cada comando Tcl que se ejecute desde el inicio de la ejecución del procedimiento nombre hasta que dicho procedimiento finalice. Se invoca comandoPrefijo justo después de que tenga lugar la ejecución real del comando Tcl que se está informando. Establecer un trace de leavestep en un comando nombre que no se refiere a un procedimiento no generará un error y simplemente se ignorará.

Cuando el trace se activa, dependiendo de las operaciones que se estén trazando, se añaden varios argumentos a comandoPrefijo para que el comando real sea el siguiente:

Para operaciones enter y enterstep:

comandoPrefijo cadenaComando operacion

CadenaComando da el comando actual completo que se está ejecutando (el comando trazado para una operación enter, un comando arbitrario para una operación enterstep), incluyendo todos los argumentos en su forma completamente expandida. Operacion indica qué operación se está realizando en la ejecución del comando, y es uno de enter o enterstep según se definieron anteriormente. La operación de trace se puede usar para evitar la ejecución del comando, eliminando el comando en cuestión. Por supuesto, cuando el comando se ejecute posteriormente, ocurrirá un error de "comando inválido".

Para operaciones leave y leavestep:

comandoPrefijo cadenaComando codigo resultado operacion

CadenaComando da el comando actual completo que se está ejecutando (el comando trazado para una operación enter, un comando arbitrario para una operación enterstep), incluyendo todos los argumentos en su forma completamente expandida. Codigo da el código de resultado de esa ejecución, y resultado la cadena de resultado. Operacion indica qué operación se está realizando en la ejecución del comando, y es uno de leave o leavestep según se definieron anteriormente. Tenga en cuenta que la creación de muchos traces de enterstep o leavestep puede llevar a resultados poco intuitivos, ya que los comandos invocados desde un trace pueden a su vez provocar invocaciones de comandos adicionales para otros traces.

ComandoPrefijo se ejecuta en el mismo contexto que el código que invocó la operación trazada: por lo tanto, el comandoPrefijo, si se invoca desde un procedimiento, tendrá acceso a las mismas variables locales que el código en el procedimiento. Este contexto puede ser diferente del contexto en el que se creó el trace. Si comandoPrefijo invoca un procedimiento (lo que normalmente hace), entonces el procedimiento tendrá que usar comandos upvar o uplevel si desea acceder a las variables locales del código que invocó la operación de trace.

Mientras comandoPrefijo se está ejecutando durante un trace de ejecución, los traces en nombre se deshabilitan temporalmente. Esto permite que comandoPrefijo ejecute nombre en su cuerpo sin invocar ningún otro trace nuevamente. Si ocurre un error mientras se ejecuta el comandoPrefijo, entonces el comando nombre en su conjunto devolverá ese mismo error.

Cuando se establecen varios traces en nombre, para las operaciones enter y enterstep, los comandos trazados se invocan en orden inverso a como se crearon originalmente los traces; y para las operaciones leave y leavestep, los comandos trazados se invocan en el orden original de creación.

El comportamiento de los traces de ejecución está actualmente indefinido para un comando nombre importado en otro namespace.

Nombre puede referirse a una variable normal, un elemento de un array o a un array en su conjunto (es decir, nombre puede ser solo el nombre de un array, sin índice entre paréntesis). NOMBRE

trace - Ejecuta un script Tcl en respuesta a cambios en una variable o en la ejecución de comandos.

SINOPSIS

trace option ?arg arg ...?

DESCRIPCIÓN

El comando trace se utiliza para instrumentar el intérprete de Tcl. Permite definir un script Tcl que se ejecutará cada vez que se acceda a una variable o se ejecute un comando. Hay dos tipos de trazas: trazas de variables y trazas de comandos.

trace variable varName ?ops? script
Define una traza de variable para la variable varName. El script script se ejecutará cuando la variable varName sea leída, escrita o eliminada, dependiendo de las operaciones especificadas en ops. Si ops se omite, el script se ejecutará para todas las operaciones (lectura, escritura y eliminación). Las operaciones posibles son:
read
El script se ejecuta cuando se lee la variable.
write
El script se ejecuta cuando se escribe en la variable.
unset
El script se ejecuta cuando se elimina la variable.
trace vdelete varName ?ops?
Elimina las trazas de variable especificadas para la variable varName. Si ops se omite, se eliminan todas las trazas de variable para varName.
trace cmd ops script
Define una traza de comando. El script script se ejecutará antes o después de la ejecución de comandos, dependiendo de ops. Las operaciones posibles son:
enter
El script se ejecuta antes de que se ejecute el comando.
leave
El script se ejecuta después de que se ejecute el comando.
trace cdelete ops
Elimina las trazas de comando especificadas.

EJEMPLOS

set x 10
trace var x w {
    puts "La variable x ha sido escrita con el valor: $x"
}
set x 20
# Salida: La variable x ha sido escrita con el valor: 20

trace var x r {
    puts "La variable x ha sido leída."
}
puts $x
# Salida:
# La variable x ha sido leída.
# 20

trace var x u {
    puts "La variable x ha sido eliminada."
}
unset x
# Salida: La variable x ha sido eliminada.

trace cmd enter {
    puts "Ejecutando comando: $argv0"
}
puts hello
# Salida:
# Ejecutando comando: puts
# hello

trace cmd leave {
    puts "Comando finalizado."
}
puts hello
# Salida:
# Ejecutando comando: puts
# Comando finalizado.

trace cmd enter {
    puts "Entrando en el comando: $argv0"
}
trace cmd leave {
    puts "Saliendo del comando: $argv0"
}
puts hello
# Salida:
# Entrando en el comando: puts
# Saliendo del comando: puts
# hello

set x enterstep
x
  → report y enterstep
    report z enterstep
    report {puts hello} enterstep
    hello

VER TAMBIÉN
