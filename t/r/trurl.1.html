NOMBRE

trurl - transpone URLs

SINOPSIS

trurl [opciones / URLs]

DESCRIPCIÓN

trurl analiza, manipula y muestra URLs y partes de URLs.

Utiliza la definición de URLs del RFC 3986 y el analizador de URLs de libcurl para hacerlo, lo que incluye algunas "extensiones". El soporte para URLs se limita a las URLs "jerárquicas", aquellas que utilizan el separador :// después del esquema.

Normalmente, se le pasan una o más URLs y se decide qué parte de ellas se desea mostrar. Posiblemente modificando la URL también.

trurl conoce las URLs y cada URL consta de hasta diez componentes separados e independientes. Estos componentes pueden ser extraídos, eliminados y actualizados con trurl, y se les hace referencia por sus respectivos nombres: scheme, user, password, options, host, port, path, query, fragment y zoneid.

NORMALIZACIÓN

Cuando se le proporciona una URL para trabajar, trurl la "normaliza". Esto significa que los componentes individuales de la URL se decodifican y luego se vuelven a codificar en la URL y se establecen en la URL.

Ejemplo:

$ trurl 'http://ex%61mple:80/%62ath/a/../b?%2e%FF#tes%74'
http://example/bath/b?.%ff#test

OPCIONES

Las opciones comienzan con uno o dos guiones. Muchas de las opciones requieren un valor adicional junto a ellas.

Cualquier otro argumento se interpreta como un argumento de URL y se trata como si siguiera una opción --url.

El primer argumento que sea exactamente dos guiones (--), marca el final de las opciones; cualquier argumento después del final de las opciones se interpreta como un argumento de URL, incluso si comienza con un guion.

Las opciones largas se pueden proporcionar como --flag argumento o como --flag=argumento.

-a, --append [component]=[datos]
Añade datos a un componente. Esto solo puede añadir datos a los componentes path y query.

Para path, esto codificará la URL y añadirá el nuevo segmento al path, separado por una barra.

Para query, esto codificará la URL y añadirá el nuevo segmento a la query, separado por un ampersand (&). Si el segmento añadido contiene un signo igual (=), ese se mantiene tal cual y ambos lados de la primera ocurrencia se codifican en la URL por separado.

--accept-space
Cuando se establece, trurl intenta aceptar espacios como parte de la URL y en su lugar codifica en la URL dichas ocurrencias en consecuencia.

Según el RFC 3986, un espacio no puede ser legalmente parte de una URL. Esta opción proporciona un esfuerzo para convertir la cadena proporcionada en una URL válida.

--as-idn
Convierte un nombre de host ASCII punycode a su Nombre de Dominio Internacional original en Unicode. Si el nombre de host no utiliza punycode, se utiliza el nombre de host original.
--curl
Solo acepta esquemas de URL compatibles con libcurl.
--default-port
Cuando se establece, trurl utiliza el número de puerto por defecto del esquema para las URLs con un esquema conocido y sin un número de puerto explícito.

Tenga en cuenta que trurl solo conoce los números de puerto por defecto para los esquemas de URL que son compatibles con libcurl.

Dado que, por defecto, trurl elimina los números de puerto por defecto de las URLs con un esquema conocido, esta opción se ignora a menos que también se especifique --get, --json, y/o --keep-port.

-f, --url-file [nombre de archivo]
Lee las URLs a procesar del archivo dado. Utiliza el nombre de archivo - (un solo guion) para indicar a trurl que lea las URLs desde la entrada estándar.

Cada línea debe ser una única URL válida. trurl elimina un carácter de retorno de carro al final de la línea si está presente, elimina todos los caracteres de espacio y tabulación al final, y se salta todas las líneas vacías (después de eliminar los espacios).

La longitud máxima de línea admitida en un archivo de este tipo es de 4094 bytes. Las líneas que superan esa longitud se omiten y se imprime una advertencia en la salida de error estándar cuando se encuentran.

-g, --get [formato]
Muestra texto y datos de URL según la cadena de formato proporcionada. Los componentes de la URL se pueden mostrar cuando se especifican como {componente} o [componente], con el nombre de la parte mostrado dentro de llaves o corchetes. No se pueden mezclar llaves y corchetes para este propósito en la misma línea de comandos.

Los siguientes nombres de componentes están disponibles (sensible a mayúsculas y minúsculas): url, user, password, options, host, port, path, query, fragment y zoneid.

{componente} se expande a nada si el componente dado no tiene valor.

Los componentes se muestran decodificados en la URL por defecto.

La decodificación en URL de un componente puede causar problemas de visualización. Tales problemas hacen que se muestre una advertencia a menos que se use --quiet.

trurl soporta una gama de diferentes calificadores o prefijos para el componente que cambian cómo lo maneja:

Si se especifica url:, como en {url:path}, el componente se mostrará codificado en la URL. Como atajo, url: también funciona escrito como dos puntos simples: {:path}.

Si se especifica strict:, como en {strict:path}, los problemas de decodificación de URL se convierten en errores. En este modo más estricto, un problema de decodificación de URL hace que trurl deje de hacer lo que está haciendo y devuelva el código de salida 10.

Si se especifica must:, como en {must:query}, hace que trurl devuelva un error si el componente solicitado no existe en la URL. Por defecto, un componente faltante simplemente se mostrará en blanco.

Si se especifica default:, como en {default:url} o {default:port}, y el puerto no se especifica explícitamente en la URL, se mostrará el puerto por defecto del esquema si se conoce.

Si se especifica puny:, como en {puny:url} o {puny:host}, se utilizará la versión punycode del nombre de host en la salida. Esta opción es mutuamente excluyente con idn:.

Si se especifica idn:, como en {idn:url} o {idn:host}, se utilizará la versión de Nombre de Dominio Internacional del nombre de host si se proporciona como una versión punycode correctamente codificada. Esta opción es mutuamente excluyente con puny:.

Si se especifica --default-port, todos los formatos se expanden como si usaran default:; y si se usa --punycode, todos los formatos se expanden como si usaran puny:. Tenga en cuenta también que {url} se ve afectado por la opción --keep-port.

Los nombres de host proporcionados como direcciones numéricas IPv6 se proporcionan entre corchetes. Como [fe80::20c:29ff:fe9c:409b].

Los nombres de host proporcionados como direcciones numéricas IPv4 se normalizan y se muestran como cuatro números decimales separados por puntos al ser mostrados.

Puede acceder a claves específicas en la cadena de consulta utilizando el formato {query:clave}. Entonces se muestra el valor de la primera clave coincidente utilizando una coincidencia sensible a mayúsculas y minúsculas. Al extraer una clave de consulta decodificada en URL que contiene %00, ese octeto se reemplaza por un solo punto . en la salida.

Puede acceder a claves específicas en la cadena de consulta y mostrar todos los valores utilizando el formato {query-all:clave}. Esto busca clave de forma sensible a mayúsculas y minúsculas y muestra todos los valores para esa clave separados por espacios.

La cadena de formato admite las siguientes secuencias de barra invertida:

\ - barra invertida

\t - tabulador

\n - nueva línea

\r - retorno de carro

\{ - una llave abierta que no inicia una variable

\[ - un corchete abierto que no inicia una variable

Todo el texto restante en la cadena de formato se muestra tal cual.

-h, --help
Muestra la ayuda.
--iterate [componente]=[item1 item2 ...]
Establece el componente a múltiples valores y muestra el resultado una vez por cada iteración. Varias iteraciones combinadas están permitidas para generar combinaciones, pero solo una opción --iterate por componente. Los elementos listados para iterar deben estar separados por un solo espacio
s.

Ejemplo:

$ trurl example.com --iterate=scheme="ftp https" --iterate=port="22 80"
ftp://example.com:22/
ftp://example.com:80/
https://example.com:22/
https://example.com:80/
--json
Genera como salida objetos JSON con todos los componentes de las URL establecidos. Todos los componentes de la URL que tengan datos se poblarán en el objeto 'parts' usando sus nombres de componente. Ver más abajo para detalles sobre el formato.

Los componentes de la URL se proporcionan decodificados de URL. Cambie esto con --urlencode.

--keep-port
Por defecto, trurl elimina los números de puerto predeterminados de las URL con un esquema conocido, incluso si se especifican explícitamente en la URL de entrada. Esta opción hace que trurl no los elimine.

Ejemplo:

$ trurl https://example.com:443/ --keep-port
https://example.com:443/
--no-guess-scheme
Deshabilita la función de adivinación de esquemas de libcurl. Las URL que no contienen un esquema se tratan como URL inválidas.

Ejemplo:

$ trurl example.com --no-guess-scheme
trurl note: Bad scheme [example.com]
--punycode
Utiliza la versión punycode del nombre de host, que es cómo los Nombres de Dominio Internacionalizados se convierten a ASCII plano. Si el nombre de host no utiliza IDN, se utiliza el nombre ASCII normal.

Ejemplo:

$ trurl http://åäö/ --punycode
http://xn--4cab6c/
--qtrim [qué]
Recorta datos de una consulta.

qué se especifica como el nombre completo de un par nombre/valor, o como un prefijo de palabra (usando un único asterisco final (*)) que hace que trurl elimine las tuplas de la cadena de consulta que coinciden con la instrucción.

Para hacer coincidir un asterisco final literal en lugar de usar un comodín, escápelo con una barra invertida delante. Como \*.

--query-separator [qué]
Especifica la única letra utilizada para separar los pares de consulta. El valor predeterminado es &, pero al menos en el pasado, a veces se han utilizado puntos y coma ; o incluso dos puntos : para este propósito. Si su URL utiliza algo que no sea la letra predeterminada, establecer la correcta asegura que trurl pueda realizar sus operaciones de consulta correctamente.

Ejemplo:

$ trurl "https://curl.se?b=name:a=age" --sort-query --query-separator ":"
https://curl.se/?a=age:b=name
--quiet
Suprime (algunas) notas y advertencias.
--redirect [URL]
Redirige la URL a esta nueva ubicación. La redirección se realiza en la URL base, por lo que, si no se especifica una URL base, no se realiza ninguna redirección.

Ejemplo:

$ trurl --url https://curl.se/we/are.html --redirect ../here.html
https://curl.se/here.html
--replace [datos]
Reemplaza una consulta de URL.

datos puede tener la forma de un valor único, o de un par clave/valor con la forma foo=bar. Si se llama a replace en un elemento que no está en la lista de consultas, trurl ignora ese elemento.

trurl codifica en URL ambos lados del carácter = en el argumento de datos de entrada proporcionado.

--replace-append [datos]
Funciona igual que --replace, pero trurl agrega una cadena de consulta faltante si aún no está en la lista de consultas.
-s, --set [componente][:]=[datos]
Establece este componente de URL. Establecer una cadena vacía ("") borra el componente de la URL.

Los siguientes componentes se pueden establecer: url, scheme, user, password, options, host, port, path, query, fragment y zoneid.

Si se utiliza una simple asignación de =, los datos se codifican en URL cuando se aplican. Si se utiliza :=, se asume que los datos ya están codificados en URL y se almacenan tal cual.

Si se utiliza ?=, la configuración solo se realiza si el componente no está ya establecido. Evita sobrescribir cualquier dato ya establecido.

También puede combinar : y ? en ?:= si lo desea.

Si no se proporciona ningún argumento de URL o --url-file, trurl intenta crear una URL utilizando los componentes proporcionados por las opciones --set. Si no se especifican suficientes componentes, esto falla.

--sort-query
Los tuplas "variable=contenido" en el componente de consulta se ordenan alfabéticamente, sin distinguir entre mayúsculas y minúsculas. Esto ayuda a hacer que las URL sean idénticas que de otro modo solo tendrían sus pares de consulta en órdenes diferentes.
--trim [componente]=[qué]
Obsoleto: use --qtrim.

Recorta datos de un componente. Actualmente, esto solo puede recortar un componente de consulta.

qué se especifica como una palabra completa o como un prefijo de palabra (usando un único asterisco final (*)) que hace que trurl elimine las tuplas de la cadena de consulta que coinciden con la instrucción.

Para hacer coincidir un asterisco final literal en lugar de usar un comodín, escápelo con una barra invertida delante. Como \*.

--url [URL]
Establece la URL de entrada con la que trabajar. La URL puede proporcionarse sin un esquema, lo que entonces típicamente no es una URL legal, pero trurl intenta averiguar qué se pretendía y adivinar qué esquema usar (a menos que se use --no-guess-scheme).

Proporcionar múltiples URL hace que trurl actúe sobre todas las URL de forma secuencial.

Si la URL no se puede analizar por cualquier motivo, trurl simplemente pasa a la siguiente URL proporcionada, a menos que se use --verify.

--urlencode
Genera como salida la versión codificada en URL de los componentes por defecto cuando se usa --get o --json.
-v, --version
Mostrar información de la versión y salir.
--verify
Cuando se proporciona una URL, devuelve un error inmediatamente si no se analiza como una URL válida. En casos normales, trurl puede perdonar una entrada de URL incorrecta.

COMPONENTES DE URL

scheme
Esta es la secuencia de caracteres inicial de una URL, excluyendo el separador "://". No se puede especificar codificada en URL.

Una URL no puede existir sin un esquema, pero a menos que se use --no-guess-scheme, trurl adivina qué esquema se pretendía si no se proporcionó ninguno.

Ejemplos:

$ trurl https://odd/ -g '{scheme}'
https
$ trurl odd -g '{scheme}'
http
$ trurl odd -g '{scheme}' --no-guess-scheme
trurl note: Bad scheme [odd]
user
Después del separador de esquema, puede haber un nombre de usuario. Si termina con dos puntos (:), hay una contraseña. Si termina con un arroba (@), no hay contraseña en la URL.

Ejemplo:

$ trurl https://user%3a%40:secret@odd/ -g '{user}'
user:@
password
Si la contraseña termina con un punto y coma (;), hay un campo de opciones a continuación. Este campo solo es aceptado por trurl para URL que utilizan el esquema IMAP.

Ejemplo:

$ trurl https://user:secr%65t@odd/ -g '{password}'
secret
options
Este campo solo puede terminar con un arroba (@) que separa las opciones del nombre de host. 
$ trurl 'imap://user:pwd;giraffe@odd' -g '{options}'
giraffe

Si el esquema no es IMAP, la parte giraffe se considera en su lugar parte de la contraseña:

$ trurl 'sftp://user:pwd;giraffe@odd' -g '{password}'
pwd;giraffe

Recomendamos encarecidamente a los usuarios que codifiquen en porcentaje ;, : y @ en las URL, por supuesto, para reducir el riesgo de confusiones.

host
El componente host es el nombre de host o una dirección IP numérica. Si se proporciona un nombre de host, puede ser un Nombre de Dominio Internacionalizado con caracteres no ASCII. Se puede proporcionar un nombre de host codificado en URL.

trurl proporciona opciones para trabajar con nombres de host IDN, ya sea como IDN o en su versión punycode.

Ejemplo, convertir un nombre IDN a punycode en la salida:

$ trurl http://åäö/ --punycode
http://xn--4cab6c/

O a la inversa, convertir un nombre de host punycode a su versión IDN:

$ trurl http://xn--4cab6c/ --as-idn
http://åäö/

Si el nombre de host de la URL comienza con un corchete abierto ([), es una dirección IPv6 numérica que también debe terminar con un corchete de cierre (]). trurl normaliza las direcciones IPv6.

Ejemplo:

$ trurl 'http://[2001:9b1:0:0:0:0:7b97:364b]/'
http://[2001:9b1::7b97:364b]/

Se puede especificar una dirección IPv4 numérica usando uno, dos, tres o cuatro números separados por puntos y pueden usar decimal, octal o hexadecimal. trurl normaliza las direcciones proporcionadas y utiliza cuatro números decimales con puntos en su salida.

Ejemplos:

$ trurl http://646464646/
http://38.136.68.134/
$ trurl http://246.646/
http://246.0.2.134/
$ trurl http://246.46.646/
http://246.46.2.134/
$ trurl http://0x14.0xb3022/
http://20.11.48.34/
zoneid
Si el host proporcionado es una dirección IPv6, puede contener un zoneid específico. Normalmente un número o un nombre de interfaz de red.

Ejemplo:

$ trurl 'http://[2001:9b1::f358:1ba4:7b97:364b%enp3s0]/' -g '{zoneid}'
enp3s0
port
Si el host termina con dos puntos (:), a continuación sigue un número de puerto. Es un número decimal de 16 bits que no puede estar codificado en URL.

trurl conoce el número de puerto predeterminado para muchos esquemas de URL, por lo que puede mostrar números de puerto para una URL incluso si no se utilizó ninguno explícitamente en la URL. Con --default-port puede agregar el puerto predeterminado a una URL incluso cuando no se proporciona.

Ejemplo:

$ trurl http:/a --default-port
http://a:80/

De manera similar, trurl normalmente oculta el número de puerto si el número dado es el predeterminado.

Ejemplo:

$ trurl http:/a:80
http://a/

Pero un usuario puede hacer que trurl conserve el puerto incluso si es el predeterminado, con --keep-port.

Ejemplo:

$ trurl http:/a:80 --keep-port
http://a:80/
path
Se asume que una ruta de URL siempre comienza con y contiene al menos una barra (/), incluso si no se proporciona ninguna en la URL.

Ejemplo:

$ trurl http://xn--4cab6c -g '[path]'
/

Al establecer la ruta, trurl insertará una barra inicial si no se proporciona ninguna:

$ trurl http://hello -s path="pony"
http://hello/pony
$ trurl http://hello -s path="/pony"
http://hello/pony

Si la ruta de entrada contiene secuencias "dotdot" o "dot-slash", se normalizan.

Ejemplo:

$ trurl http://hej/one/../two/../three/./four
http://hej/three/four

Puede agregar un nuevo segmento a una ruta existente con --append de esta manera:

$ trurl http://twelve/three?hello --append path=four
http://twelve/three/four?hello
query
La parte de la consulta no incluye el signo de interrogación (?) inicial cuando se extrae con trurl.

Ejemplo:

$ trurl http://horse?elephant -g '{query}'
elephant

Ejemplo, si establece la consulta con un signo de interrogación inicial:

$ trurl http://horse?elephant -s "query=?elephant"
http://horse/?%3felephant

Las partes de la consulta a menudo están compuestas por una serie de pares nombre=valor separados por ampersands (&), y trurl ofrece varias formas de trabajar con ellas.

Agregue un nuevo par nombre=valor a una URL con --append:

$ trurl http://host?name=hello --append query=search=life
http://host/?name=hello&search=life

Puede --replace el valor de un nombre existente específico entre los pares:

$ trurl 'http://alpha?one=real&two=fake' --replace two=alsoreal
http://alpha/?one=real&two=alsoreal

Si el nombre específico que desea reemplazar quizás no existe en la URL, puede optar por reemplazar o agregar el par:

$ trurl 'http://alpha?one=real&two=fake' --replace-append three=alsoreal
http://alpha/?one=real&two=fake&three=alsoreal

Para quizás comparar dos URL usando pares nombre=valor de consulta, ordenarlas primero al menos aumenta las posibilidades de que funcione:

$ trurl "http://alpha/?one=real&two=fake&three=alsoreal" --sort-query
http://alpha/?one=real&three=alsoreal&two=fake

Elimine pares nombre/valor de la URL especificando el nombre exacto o un patrón comodín con --qtrim:

$ trurl 'https://example.com?a12=hej&a23=moo&b12=foo' --qtrim a*'
https://example.com/?b12=foo
fragment
La parte del fragmento no incluye el signo de almohadilla (#) inicial cuando se extrae con trurl.

Ejemplo:

$ trurl http://horse#elephant -g '{fragment}'
elephant

Ejemplo, si establece el fragmento con un signo de almohadilla inicial:

$ trurl "http://horse#elephant" -s "fragment=#zebra"
http://horse/#%23zebra

La parte del fragmento de una URL es solo para fines locales. Los datos que contiene nunca se envían realmente a través de la red cuando se utiliza una URL para transferencias.

url
trurl admite url como un componente con nombre para --get para permitir salidas más potentes, pero por supuesto, no es realmente un "componente"; es la URL completa.

Ejemplo:

$ trurl ftps://example.com:2021/p%61th -g '{url}'
ftps://example.com:2021/path

Formato de salida JSON

La opción --json genera una matriz JSON con uno o más objetos. Uno por cada URL. Cada objeto JSON de URL contiene una serie de propiedades, una serie de pares clave/valor. El conjunto exacto presente depende de la URL dada.

url
Esta clave existe en cada objeto. Es la URL completa. Afectada por --default-port, --keep-port y --punycode.
parts
Esta clave existe en cada objeto y contiene un objeto con una clave para cada uno de los componentes de URL configurables. Si falta un componente, significa que no está presente en la URL. Las partes se decodifican de la URL a menos que se use --urlencode.
parts.scheme
El esquema de la URL.
parts.user
El nombre de usuario.
parts.password
La contraseña.
parts.options
Las opciones. Tenga en cuenta que solo unos pocos esquemas de URL admiten el componente "options".
parts.host
El nombre de host normalizado. Puede ser un nombre UTF-8 si se utilizó un nombre IDN. También puede ser una dirección IPv4 o IPv6 normalizada. Una dirección IPv6 siempre comienza con un corchete ([) y ningún otro nombre de host puede contener dicho símbolo. Si se usa --punycode, se proporciona la versión punycode del host en su lugar.
parts.port
El número de puerto proporcionado como una cadena. Si el número de puerto no se proporcionó en la URL, pero el esquema es conocido y se está usando --default-port, se proporciona el puerto predeterminado para ese esquema.
parts.path
La ruta. Incluyendo la barra inicial.
parts.query
La consulta completa, excluyendo el separador de signo de interrogación.
parts.fragment
El fragmento, excluyendo el separador de almohadilla.
parts.zoneid
El ID de zona, que solo puede estar presente en una dirección IPv6. Cuando esta clave está presente, host es una dirección numérica IPv6.
params
Esta clave contiene una matriz de objetos clave/valor de consulta. Cada par se enumera con "key" y "value" y sus respectivos contenidos en la salida.

Las claves/valores se extraen de la consulta donde están separados por ampersands (&) o el usuario los establece con --query-separator.

Los pares de consulta se enumeran en orden de aparición de izquierda a derecha, pero se pueden ordenar alfabéticamente con --sort-query.

Solo está presente si la URL tiene una consulta.

EJEMPLOS

Reemplazar el nombre de host de una URL
$ trurl --url https://curl.se --set host=example.com
https://example.com/
Crear una URL estableciendo componentes
 $ trurl --set host=example.com --set scheme=ftp
 ftp://example.com/
Redirigir una URL
$ trurl --url https://curl.se/we/are.html --redirect here.html
https://curl.se/we/here.html
Cambiar el número de puerto
Esto también muestra cómo trurl elimina las secuencias "dot-dot" 
$ trurl --url https://curl.se/we/../are.html --set port=8080
https://curl.se:8080/are.html
Extraer la ruta de una URL
$ trurl --url https://curl.se/we/are.html --get '{path}'
/we/are.html
Extraer el puerto de una URL
Esto obtiene el puerto predeterminado según el esquema si el puerto no está configurado en la URL. 
$ trurl --url https://curl.se/we/are.html --get '{default:port}'
443
Agregar un segmento de ruta a una URL
$ trurl --url https://curl.se/hello --append path=you
https://curl.se/hello/you
Agregar un segmento de consulta a una URL
$ trurl --url "https://curl.se?name=hello" --append query=search=string
 https://curl.se/?name=hello&search=string
Leer URL desde stdin
$ cat urllist.txt | trurl --url-file -
\&...
Generar salida JSON
$ trurl "https://fake.host/search?q=answers&user=me#frag" --json
[
  {
    "url": "https://fake.host/search?q=answers&user=me#frag",
    "parts": [
        "scheme": "https",
        "host": "fake.host",
        "path": "/search",
        "query": "q=answers&user=me"
        "fragment": "frag",
    ],
    "params": [
      {
        "key": "q",

EJEMPLOS

Crear una URL modificando un componente específico
$ trurl "https://curl.se/path/index.html" --set host=example.com
https://example.com/path/index.html
Añadir un nuevo parámetro a la cadena de consulta
$ trurl "https://curl.se/path/index.html" --append "query=foo"
https://curl.se/path/index.html?query=foo
Añadir múltiples parámetros a la cadena de consulta
$ trurl "https://curl.se/path/index.html" --append "query=foo" --append "page=5"
https://curl.se/path/index.html?query=foo&page=5
Reemplazar un parámetro de la cadena de consulta
$ trurl "https://curl.se/search?q=bar&page=2" --replace "page=5"
https://curl.se/search?q=bar&page=5
Reemplazar un parámetro de cadena de consulta, añadiéndolo si no existe
$ trurl "https://curl.se/search?q=bar" --replace-append "page=5"
https://curl.se/search?q=bar&page=5
Reemplazar un parámetro de cadena de consulta, eliminándolo si no existe
$ trurl "https://curl.se/search?q=bar&page=2" --replace "page="
https://curl.se/search?q=bar
Eliminar un parámetro de cadena de consulta
$ trurl "https://curl.se/search?q=bar&page=2" --remove "page"
https://curl.se/search?q=bar
Verificar la URL solo si se especificó el esquema
$ trurl "https://curl.se/search?q=fool;page=5" --verify "scheme"
https://curl.se/search?q=fool;page=5
Recuperar un subconjunto de la cadena de consulta y luego modificarlo
$ trurl "https://curl.se?search=fool;page=5" --qtrim "search" --query-separator ";" --set "page=6"
https://curl.se?search=fool;page=6
Aceptar espacios en la ruta de la URL
$ trurl "https://curl.se/este tiene espacio/index.html" --accept-space
https://curl.se/este%20tiene%20espacio/index.html
Crear múltiples variaciones de una URL con diferentes esquemas
$ trurl "https://curl.se/path/index.html" --iterate "scheme=http ftp sftp"
http://curl.se/path/index.html
ftp://curl.se/path/index.html
sftp://curl.se/path/index.html

CÓDIGOS DE SALIDA

trurl devuelve un código de salida distinto de cero para indicar problemas.

1
Un problema con --url-file
2
Un problema con --append
3
Una opción de línea de comandos no tiene argumento
4
Un error en la opción de línea de comandos o una combinación de opciones ilegales.
5
Un problema con --set
6
Sin memoria
7
No se pudo generar una URL válida
8
Un problema con --qtrim
9
Si --verify está configurado y la URL de entrada no se puede analizar.
10
Un problema con --get
11
Un problema con --iterate
12
Un problema con --replace o --replace-append
