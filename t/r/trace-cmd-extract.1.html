NOMBRE

trace-cmd-extract - extrae los datos del trazador Ftrace de Linux.

SINOPSIS

trace-cmd extract [OPCIONES]

DESCRIPCIÓN

La extracción de trace-cmd (trace-cmd extract) se usa normalmente después de trace-cmd-start(1) y trace-cmd-stop(1). Puede usarse después de que el trazador Ftrace se haya iniciado manualmente a través del sistema de archivos pseudo Ftrace.

El comando extract crea un archivo trace.dat que puede ser utilizado por trace-cmd-report(1) para leer. Lee el búfer de anillo interno del kernel para producir el archivo trace.dat.

OPCIONES

-p plugin

Aunque extract no inicia ningún trazado, algunos de los plugins requieren solo leer la salida en formato ASCII. Estos son los trazadores de latencia, ya que los trazadores de latencia tienen un búfer interno separado. Por lo tanto, la opción del plugin solo es necesaria para los plugins wakeup, wakeup-rt, irqsoff, preemptoff y preemptirqsoff. 
Sin esta opción, el comando extract extraerá de los búferes internos de
Ftrace.

-O opción

Si se está extrayendo un trazador de latencia y se usa la opción -p, entonces hay algunas opciones de Ftrace que pueden cambiar el formato. Esto actualizará esas opciones antes de la extracción. Para ver la lista de opciones, consulta trace-cmd-list. Para habilitar una opción, escribe su nombre; para deshabilitarla, añade los caracteres no. Por ejemplo: noprint-parent deshabilitará la opción print-parent que imprime la función padre al imprimir un evento de función.

-o archivo de salida

Por defecto, el comando extract creará un archivo trace.dat. Esta opción cambiará dónde se escribe el archivo.

-s

Extraer del búfer de instantáneas (si el kernel lo soporta).

--date

Esto es lo mismo que la opción --date de trace-cmd-record(1), pero hace que la rutina de extracción deshabilite todo el trazado. Es decir, el final de la extracción realizará algo similar a trace-cmd-reset(1).

-B nombre del búfer

Si el kernel soporta múltiples búferes, esto extraerá el trazado solo para el búfer dado. No afecta a ningún otro búfer. Esto puede usarse varias veces para especificar diferentes búferes. Cuando se usa esta opción, la instancia de nivel superior no se extraerá a menos que se proporcione -t.

-a

Extraer todas las instancias de búfer existentes. Cuando se usa esta opción, la instancia de nivel superior no se extraerá a menos que se proporcione -t.

-t

Extrae el búfer de la instancia de nivel superior. Sin la opción -B o -a, esto es lo mismo que por defecto. Pero si se usa -B o -a, esto es necesario si el búfer de la instancia de nivel superior también debe extraerse.

--verbose[=nivel]

Establece el nivel de registro. Los niveles de registro soportados son "none", "critical", "error", "warning", "info", "debug", "all" o sus identificadores "0", "1", "2", "3", "4", "5", "6". Establecer el nivel de registro a un valor específico habilita todos los registros de ese nivel y todos los niveles anteriores. El nivel se establecerá por defecto en "info" si no se especifica ninguno. 
Ejemplo: habilitar todos los registros críticos, de error y de advertencia
trace-cmd extract --verbose=warning
