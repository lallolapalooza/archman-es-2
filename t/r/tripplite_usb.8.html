TRIPPLITE_USB(8) Manual de NUT TRIPPLITE_USB(8)

NOMBRE

tripplite_usb - Controlador para SAI Tripp Lite USB antiguos (no HID PDC)

SINOPSIS

tripplite_usb -h

tripplite_usb -a NOMBRE_SAI [OPCIONES]

HARDWARE SOPORTADO

Este controlador debería funcionar con SAI Tripp Lite antiguos que se detectan como dispositivos de clase USB HID, pero que no son dispositivos verdaderos de la clase HID Power-Device. Hasta ahora, los dispositivos soportados por tripplite_usb tienen el ID de producto 0001, y las unidades más nuevas (como las que tienen "LCD" en el nombre del modelo) con ID de producto 2001 requieren en su lugar el controlador usbhid-ups(8).

Por favor, informe de éxitos o fracasos a la lista de correo nut-upsuser. Una información clave es el número de protocolo, devuelto en ups.firmware.aux. Además, asegúrese de activar la depuración (-DDD) para obtener mensajes de registro más informativos.

Si su SAI Tripp Lite utiliza un puerto serie, puede que desee investigar los controladores tripplite(8) o tripplitesu(8).

Este controlador ha sido probado con los siguientes modelos:

•INTERNETOFFICE700
•OMNIVS1000
•OMNIVS1500XL (algunas advertencias)
•SMART700USB
•SMART1500RM2U
•SMART2200RMXL2U
•SMART3000RM2U

Si ha utilizado el software PowerAlert de Tripp Lite para conectarse a su SAI, es muy probable que tripplite_usb funcione si utiliza uno de los siguientes protocolos:

•Protocolo 0004
•Protocolo 1001
•Protocolo 2001
•Protocolo 3003
•Protocolo 3005

Por otro lado, si la página web de su SAI en el sitio web de Tripp-Lite dice "El puerto USB compatible con HID también permite la integración directa con las funciones integradas de administración de energía y apagado automático de Windows y MAC OS X", entonces debería usar el controlador usbhid-ups(8).

ARGUMENTOS ADICIONALES

Este controlador soporta las siguientes configuraciones opcionales en el archivo ups.conf(5) (o con -x en la línea de comandos):

port = cadena

Opción requerida para todos los controladores de NUT. Se debe establecer algún valor, típicamente auto para los controladores que manejan conexiones USB.

Nota
Podría ser una ruta de sistema de archivos del dispositivo como /dev/usb/hiddev0, pero el uso actual de la API libusb impide conocer y hacer coincidir por identificadores de este tipo. También pueden ser inherentemente poco fiables (dependientes de reconexiones y orden de enumeración). En este momento, el valor real se ignora, pero sintácticamente todavía debe existir alguna configuración de puerto.

Es posible controlar múltiples unidades SAI simultáneamente ejecutando varias instancias de este controlador, siempre que puedan distinguirse de forma única estableciendo alguna combinación de las opciones vendor, product, vendorid, productid, serial, bus y/o device detalladas a continuación. Para dispositivos o sistemas operativos que no proporcionan información suficiente, la opción allow_duplicates puede ser útil (¡limitada y arriesgada!).

vendorid = expresión regular, productid = expresión regular, vendor = expresión regular, product = expresión regular, serial = expresión regular

Selecciona un SAI específico, en caso de que haya más de uno conectado por USB. Cada opción especifica una expresión regular extendida (ver regex(7) para más información sobre expresiones regulares), que debe coincidir con los valores completos de la cadena de vendedor/producto/serie respectiva del SAI (menos cualquier espacio en blanco circundante), o el código hexadecimal completo de 4 dígitos para vendorid y productid.

Pruebe lsusb(8) o ejecute este controlador NUT con el argumento de línea de comandos -DD para averiguar las cadenas que coinciden.

Ejemplos:

•-x vendor="Foo.Corporation.*"
•-x vendorid="051d*" (APC)
•-x product=".*(Smart|Back)-?UPS.*"

bus = expresión regular

OPCIONAL, NO RECOMENDADO.

Selecciona un SAI en un bus USB específico o un grupo de buses. El argumento es una expresión regular que debe coincidir con el nombre del bus donde está conectado el SAI (por ejemplo, bus="002" o bus="00[2-3]") como se ve en Linux en /sys/bus/usb/devices o lsusb(8); incluyendo ceros iniciales.


Nota
Los números de bus no están garantizados por el sistema operativo para ser estables entre reinicios, recargas del controlador del kernel o reconexiones de dispositivos (por ejemplo, cambiando la población visible de concentradores USB).

device = expresión regular

OPCIONAL, NO RECOMENDADO.

Selecciona un SAI en un dispositivo USB específico o un grupo de dispositivos. El argumento es una expresión regular que debe coincidir con el nombre del dispositivo donde está conectado el SAI (por ejemplo, device="001" o device="00[1-2]") como se ve en Linux en /sys/bus/usb/devices o lsusb(8); incluyendo ceros iniciales.


Nota
Los números de dispositivo no están garantizados por el sistema operativo para ser estables entre reinicios o reconexiones de dispositivos.

busport = expresión regular

OPCIONAL, NO RECOMENDADO.

Si es compatible con el hardware, el sistema operativo y libusb en el despliegue particular, esta opción debería permitir especificar números de puerto físico en un concentrador USB, y a su vez — esto debería ser menos volátil entre reinicios o reconexiones. El valor puede verse en la salida de topología USB de lsusb -tv en sistemas con esa herramienta, por ejemplo.


Nota
Esta opción no es prácticamente soportada por algunas compilaciones de NUT (debería ser ignorada con una advertencia entonces), y no por todos los sistemas en los que NUT puede ejecutarse.

allow_duplicates

OPCIONAL, NO RECOMENDADO.

Si tiene varios dispositivos SAI que no pueden identificarse de forma única por las opciones anteriores (por ejemplo, solo se pueden descubrir VID:PID), esta bandera permite que cada instancia del controlador donde se establece tome la primera coincidencia si está disponible, o continúe intentando con otra.

Normalmente, la inicialización del controlador se abortaría en este punto alegando "Recurso ocupado" o un error similar, asumiendo que el dispositivo, de lo contrario, coincide correctamente, es único y algún otro proceso ya lo está manejando.


Advertencia
¡Esta función es inherentemente no determinista! ¡La asociación del nombre de la instancia del controlador con el dispositivo real puede variar entre ejecuciones!

Si solo le interesa saber que al menos uno de sus SAI sin nombre está en línea, esta opción puede ayudar.

Si realmente necesita saber cuál, ¡no lo hará!

usb_set_altinterface = bAlternateSetting

Forzar una llamada redundante a usb_set_altinterface(), especialmente si es necesario para dispositivos que sirven múltiples roles USB donde el SAI no está representado por la interfaz número 0 (por defecto).

usb_config_index, usb_hid_rep_index, usb_hid_desc_index, usb_hid_ep_in, usb_hid_ep_out

Forzar el uso de índices específicos de interfaz, punto final, descriptor, etc., en lugar de usar por defecto 0 (raramente otros valores en ciertos controladores para algunos dispositivos conocidos por usar números distintos de cero). Especificado como un número hexadecimal.

Como regla general para el descubrimiento de usb_hid_desc_index, puede ver valores más grandes de wDescriptorLength (aproximadamente 600+ bytes) en los informes de lsusb o herramientas similares.

LIBUSB_DEBUG = ENTERO

tripplite_usb(8)

NAME

tripplite_usb — Tripp Lite USB communications driver

SYNOPSIS

nutupsdrv

    -DDDD
    -x DRIVER.ATTRIBUTE=VALUE
    -x DRIVER.ATTRIBUTE=VALUE
    ...

SUPPORTED HARDWARE

This driver is for the Tripp Lite USB communications protocol, which is used by many of the more recent Tripp Lite UPS models.

It is known to work with the following models:

  • OMNIVS1000
  • SMART1500RM2U
  • SMART1500RM2UXL
  • SMART1500XL
  • SMART2200RM2U
  • SMART2200RM2UXL
  • SMART2200XL
  • SMART3000RM2U
  • SMART3000RM2UXL
  • SMART3000XL
  • SMARTINT2200
  • SMARTINT3000
  • SMARTLCD1000
  • SMARTLCD1500
  • SMARTLCD3000
  • SMARTLCD_LCD
  • SMARTM3000
  • SMARTPRO1000
  • SMARTPRO1400
  • SMARTPRO1500
  • SMARTPRO2200
  • SMARTPRO3000

This driver also works with Tripp Lite USB UPS devices that expose the USB HID interface, without the need for specific HID driver support.

EXTRA ARGUMENTS

In addition to the standard nutupsdrv(8) arguments, this driver supports the following values for the -x option:

•vendorid="XXXX"

Select a specific USB vendor ID. The argument is a regular expression that must match the USB vendor ID string.

•productid="XXXX"

Select a specific USB product ID. The argument is a regular expression that must match the USB product ID string.

•bus="X"

Select a specific USB bus number. The argument is a regular expression that must match the USB bus number string.

•device="X"

Select a specific USB device number. The argument is a regular expression that must match the USB device number string.

•serial="SERIAL"

Select a specific USB serial number. The argument is a regular expression that must match the USB serial number string.

•-x upsid="12345"

Select a specific UPS by its unique UPS ID. The argument is a regular expression that must match the UPS ID string. This allows for precise identification of UPS devices when multiple devices of the same make and model are connected. See below regarding how to read and write the ups id (unit id) using upsrw(8).


Notes for tripplite_usb driver handling of common USB matching settings:
•product is a regular expression to match the product string for the UPS. This would be useful if you have two different Tripp Lite UPS models connected to the same monitoring system, and you want to be sure that you shut them down in the correct order.

This regex is matched against the full USB product string as seen in lsusb(8). The ups.model in the upsc(8) output only lists the name after TRIPP LITE, so to match a SMART2200RMXL2U, you could use the regex like .*SMART2200.*.

•The productid is a regular expression which matches the UPS PID as four hexadecimal digits. So far, the only known devices that work with this driver have PID 0001.
•The serial option may be or not be helpful: it does not appear that these particular Tripp Lite UPSes supported by this driver use the iSerial descriptor field to return a serial number. However, in case your unit does, you may specify it here.

offdelay

This setting controls the delay between receiving the "kill" command (-k) and actually cutting power to the computer.

battery_min, battery_max

These floating-point values correspond to the "empty" (10%) and "full" (100%) voltages of the battery. They are used for an approximation of the battery state-of-charge. The calculated battery.charge value will be clamped to the range of 10% through 100%, so the resting voltage of the charged battery can be used for battery_max, and the higher float charge voltage should not cause problems.

RUNTIME VARIABLES

ups.delay.shutdown

This variable is the same as the offdelay setting, but it can be changed at runtime by upsrw(8).

ups.id

Some SMARTPRO models feature an Unit ID (ups.id) that can be set and retrieved. If your UPS supports this feature, this variable will be listed in the output of upsrw(8).

outlet.1.switch

Some Tripp Lite units have a switchable outlet (usually outlet #1) which can be turned on and off by writing 1 or 0, respectively, to outlet.1.switch with upsrw(8).

If your unit has multiple switchable outlets, substitute the outlet number for 1 in the variable name. Be sure to test this first — there is no other way to be certain that the number used by the driver matches the label on the unit.

KNOWN ISSUES AND BUGS

The driver was not developed with any official documentation from Tripp Lite, so certain events may confuse the driver. If you observe any strange behavior, please re-run the driver with -DDD to increase the verbosity.

So far, the Tripp Lite UPSes do not seem to have a serial number or other globally unique identifier accessible through USB. Thus, when monitoring several Tripp Lite USB UPSes, you should use either the bus, device or product configuration options to uniquely specify which UPS a given driver instance should control.

For instance, you can easily monitor an OMNIVS1000 and a SMART1500RM2U at the same time, since they have different USB Product ID strings. If you have two SMART1500RM2U units, you would have to find which USB bus and device number each unit is on (via lsusb(8)).

Some of the SMART*2U models have a configurable Unit ID number, and you can now use the upsid config argument to uniquely specify which UPS a given driver instance should control. This allows for precise identification of UPS devices when multiple devices are connected. To retrieve or set the upsid, you can use the upsrw(8) utility.
