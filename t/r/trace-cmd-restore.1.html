TRACE-CMD-RESTORE(1) Manual de libtracefs TRACE-CMD-RESTORE(1)

NOMBRE

trace-cmd-restore - restaura un registro de traza fallido

SINOPSIS

trace-cmd restore [OPCIONES] [comando] archivo-cpu [archivo-cpu ...]

DESCRIPCIÓN

El comando trace-cmd restore restaurará un archivo de registro de trace-cmd-record(1) fallido. Si por alguna razón un registro de trace-cmd falla, dejará los archivos de datos por CPU y no creará el archivo final trace.dat. trace-cmd restore adjuntará los archivos para crear un archivo trace.dat funcional que pueda ser leído con trace-cmd-report(1).

Cuando se ejecuta trace-cmd record, inicia un proceso por CPU y escribe en un archivo por CPU, usualmente llamado trace.dat.cpuX, donde X representa el número de CPU que se está rastreando. Si se usó la opción -o en trace-cmd record, entonces los archivos de datos de CPU tendrán ese nombre en lugar del nombre trace.dat. Si ocurre un fallo inesperado antes de que el rastreo se complete, los archivos por CPU seguirán existiendo pero no habrá ningún archivo trace.dat para leer. trace-cmd restore le permitirá crear un archivo trace.dat con los datos existentes.

OPCIONES

-c

Crea un archivo trace.dat parcial desde la máquina, para ser utilizado con un trace-cmd restore completo en otro momento. Esta opción es útil para dispositivos embebidos. Si un servidor contiene los archivos de CPU de un trace-cmd record fallido (o trace-cmd listen), trace-cmd restore puede ejecutarse en el dispositivo embebido con la opción -c para obtener toda la información almacenada de ese dispositivo embebido. Luego, el archivo creado podría copiarse al servidor para ejecutar allí trace-cmd restore con los archivos de CPU. 
Si no se especifica *-o*, entonces el archivo creado se llamará
'trace-partial.dat'. Esto se debe a que el archivo no es una versión
completa de algo que trace-cmd-report(1) podría usar.

-t directorio_trazas

Usado con -c, anula la ubicación desde donde leer los eventos. Por defecto, la información de rastreo se lee del directorio debugfs/tracing. -t usará esa ubicación en su lugar. Esto puede ser útil si el archivo trace.dat a crear es de otra máquina. Simplemente comprima con tar -cvf events.tar debugfs/tracing y copie y descomprima ese archivo localmente, y use ese directorio en su lugar.

-k kallsyms

Usado con -c, anula la ubicación desde donde leer el archivo kallsyms. Por defecto, se usa /proc/kallsyms. -k anulará el archivo para leer los kallsyms. Esto puede ser útil si el archivo trace.dat a crear es de otra máquina. Simplemente copie el archivo /proc/kallsyms localmente y use -k para apuntar a ese archivo.

-o salida'

Por defecto, trace-cmd restore creará un archivo trace.dat (o trace-partial.dat si se especifica -c). Puede especificar un archivo diferente para escribir con la opción -o.

-i entrada

Por defecto, trace-cmd restore leerá la información del sistema actual para crear los datos iniciales almacenados en el archivo trace.dat. Si el fallo ocurrió en otra máquina, entonces esa máquina debería haber ejecutado trace-cmd restore con la opción -c para crear el archivo parcial trace.dat. Luego, ese archivo puede copiarse a la máquina actual donde trace-cmd restore usará -i para cargar ese archivo en lugar de leer del sistema actual.

EJEMPLOS

Si ocurrió un fallo en otra máquina, podría ejecutar:

$ trace-cmd restore -c -o box-partial.dat

Luego, en el servidor que tiene los archivos de CPU:

$ trace-cmd restore -i box-partial.dat trace.dat.cpu0 trace.dat.cpu1

Esto crearía un archivo trace.dat para la caja embebida.
