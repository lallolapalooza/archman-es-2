tracefs_cpu_snapshot_open(3)

Paquete: libtracefs

Licencias: GPL-2.0-only, LGPL-2.1-only

LIBTRACEFS(3) Manual de libtracefs LIBTRACEFS(3)

NOMBRE

tracefs_cpu_open, tracefs_cpu_close, tracefs_cpu_alloc_fd, tracefs_cpu_free_fd, tracefs_cpu_snapshot_open - Abrir datos de trace_pipe_raw para lectura

SINOPSIS

#include <tracefs.h>
struct tracefs_cpu *tracefs_cpu_open(struct tracefs_instance *instance,
                                     int cpu, bool nonblock);
void tracefs_cpu_close(struct tracefs_cpu *tcpu);
struct tracefs_cpu *tracefs_cpu_alloc_fd(int fd, int subbuf_size, bool nonblock);
void tracefs_cpu_free_fd(struct tracefs_cpu *tcpu);
struct tracefs_cpu *tracefs_cpu_snapshot_open(struct tracefs_instance *instance,
                                             int cpu, bool nonblock);

DESCRIPCIÓN

Este conjunto de API se puede usar para abrir los datos crudos de los archivos trace_pipe_raw en el sistema de archivos tracefs para leerlos con las funciones de tracefs_cpu_read(3).

tracefs_cpu_open() crea un descriptor que puede leer el archivo tracefs trace_pipe_raw para un cpu dado en una instance dada. Si instance es NULL, se usa el archivo trace_pipe_raw de nivel superior.

tracefs_cpu_close() cierra todos los descriptores de archivo asociados a trace_pipe_raw abiertos por tracefs_cpu_open().

tracefs_cpu_alloc_fd() creará un descriptor tracefs_cpu a partir de un descriptor de archivo existente fd. Esto es útil para usar al conectarse a un socket o tubería donde el otro extremo está alimentando datos de rastreo crudos en el mismo formato que lo haría el archivo trace_pipe_raw (como en el rastreo de invitado a anfitrión). El llamador es responsable de determinar el subbuf_size que se usará para dividir los sub-búferes que se están leyendo desde el descriptor de archivo. El parámetro nonblock se trata igual que el mismo parámetro en tracefs_cpu_open().

tracefs_cpu_free_fd() se usa para liberar el descriptor devuelto por tracefs_cpu_alloc_fd(). Realiza toda la limpieza que realiza tracefs_cpu_close(), y que también podría usarse para liberar el descriptor creado por tracefs_cpu_alloc_fd(), pero también cerrará el descriptor de archivo pasado. Tenga en cuenta que no se debe usar tracefs_cpu_free_fd() en el descriptor devuelto por tracefs_cpu_open() ya que no cerrará el descriptor de archivo creado por él.

tracefs_cpu_snapshot_open() es similar a tracefs_cpu_open() excepto que abre el búfer de instantánea (ver tracefs_snapshot_snap(3)). El búfer de instantánea no tiene un escritor hacia él, solo se crea mediante una acción de instantánea que intercambia el búfer de anillo actual con el búfer de instantánea. El parámetro nonblock, cuando es falso, también actúa de manera un poco diferente aquí. Las lecturas no se ven afectadas por el archivo "buffer_percent". Si el búfer de instantánea está vacío, se bloqueará hasta que ocurra una nueva instantánea.

VALOR DE RETORNO

Tanto tracefs_cpu_open() como *tracefs_cpu_snapshot_open() devuelven un descriptor struct tracefs_cpu que puede ser utilizado por las otras funciones, o NULL en caso de error.

tracefs_cpu_alloc_fd() devuelve un descriptor struct tracefs_cpu que puede ser utilizado por las funciones relacionadas con tracefs_cpu_read(3), donde el descriptor leerá el descriptor de archivo fd proporcionado.

EJEMPLO

Ver tracefs_cpu_read(3) para un ejemplo.
