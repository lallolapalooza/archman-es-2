NOMBRE

trace-cmd-agent - Ejecutar como un agente en una máquina (para ser controlado por otra máquina)

SINOPSIS

trace-cmd agent [OPCIONES]

DESCRIPCIÓN

El agente trace-cmd(1) escucha a través de un vsocket (para máquinas virtuales) o un puerto TCP para conexiones para controlar el rastreo de la máquina. El agente iniciará el rastreo en la máquina local y pasará los datos a la conexión de control.

OPCIONES

-N cliente

Escucha a través de TCP en lugar de un vsocket. Debe pasar un nombre de host o dirección IP del cliente para permitir la conexión. Solo se conectará al cliente especificado. Nota, cualquier proceso en ese cliente puede controlar el agente. 
*¡Esta es una configuración muy insegura. Úsela solo en una red de confianza!*
*¡Úsela solo si la máquina cliente es totalmente confiable!*

-p puerto

Esta opción especificará el puerto al que escuchar.

-D

Esta opción hace que el agente trace-cmd entre en modo demonio y se ejecute en segundo plano.

-P cid

Permite que un agente actúe también como servidor proxy, donde puede ejecutarse en un host y conectarse con un invitado. cid es el ID de contexto (ver vsock(7)) del cliente (por ejemplo, VM invitada) al que permitirá conectarse.

--verbose[=nivel]

Establece el nivel de registro. Los niveles de registro soportados son "none", "critical", "error", "warning", "info", "debug", "all" o sus identificadores "0", "1", "2", "3", "4", "5", "6". Establecer el nivel de registro a un valor específico habilita todos los registros de ese nivel y de todos los niveles anteriores. El nivel será por defecto "info" si no se especifica ninguno. 
Ejemplo: habilita todos los registros críticos, de error y de advertencia
trace-cmd listen --verbose=warning
