NOMBRE

trace-cmd-set - establece un parámetro de configuración del rastreador interno Ftrace de Linux

SINOPSIS

trace-cmd set [OPCIONES] [comando]

DESCRIPCIÓN

El comando set de trace-cmd(1) establecerá un parámetro de configuración del rastreador del kernel de Linux Ftrace. El comando especificado se ejecutará después de que se establezca el estado de ftrace. El estado de ftrace configurado se puede restaurar a los valores predeterminados utilizando el comando trace-cmd-reset(1).

OPCIONES

-p rastreador

Especifica un rastreador. Los rastreadores generalmente hacen más que simplemente rastrear un evento. Los rastreadores comunes son: function, function_graph, preemptirqsoff, irqsoff, preemptoff y wakeup. Un rastreador debe ser compatible con el kernel en ejecución. Para ver una lista de rastreadores disponibles, consulte trace-cmd-list(1).

-e evento

Especifica un evento para rastrear. Se han agregado varios puntos de rastreo estáticos al kernel de Linux. Se agrupan por subsistema, donde puede habilitar todos los eventos de un subsistema determinado o especificar eventos específicos que se habilitarán. El evento tiene el formato "sub-sistema:nombre-del-evento". También puede especificar solo el subsistema sin el :nombre-del-evento o el nombre del evento sin "sub-sistema:". Usar "-e sched_switch" habilitará el evento "sched_switch", mientras que "-e sched" habilitará todos los eventos bajo el subsistema "sched". 
El 'evento' también puede contener expresiones comodín. Es decir, "*stat*" seleccionará todos los eventos (o subsistemas) que tengan los caracteres "stat" en sus nombres.
La palabra clave 'all' se puede usar para habilitar todos los eventos.

-T

Habilita un rastreo de pila en cada evento. Por ejemplo: 
          <idle>-0     [003] 58549.289091: sched_switch:         kworker/0:1:0 [120] R ==> trace-cmd:2603 [120]
          <idle>-0     [003] 58549.289092: kernel_stack:         <stack trace>
=> schedule (ffffffff814b260e)
=> cpu_idle (ffffffff8100a38c)
=> start_secondary (ffffffff814ab828)

--func-stack

Habilita un rastreo de pila en todas las funciones. Tenga en cuenta que esto solo es aplicable para el rastreador del plugin "function", y solo tendrá efecto si se usa la opción -l y tiene éxito al limitar las funciones. Si el rastreador de funciones no está filtrado y el rastreo de pila está habilitado, puede bloquear la máquina en vivo.

-f filtro

Especifica un filtro para el evento anterior. Esto debe venir después de un -e. Esto filtrará qué eventos se registrarán según el contenido del evento. El filtrado se pasa directamente al kernel, por lo que lo que esté permitido dependerá de la versión del kernel que tenga. Básicamente, le permitirá usar notación C para verificar si un evento debe procesarse o no.
    ==, >=, <=, >, <, &, |, && y ||
Los anteriores suelen ser seguros de usar para comparar campos.

-R disparador

Especifica un disparador para el evento anterior. Esto debe venir después de un -e. Esto agregará un disparador dado al evento dado. Para habilitar solo el disparador y no el evento en sí, coloque el evento después de la opción -v. 
Consulte Documentation/trace/events.txt en el código fuente del kernel de Linux para obtener más información sobre los disparadores.

-v

Esto negará las opciones especificadas después de él en la línea de comandos. Afecta a:
     -e: Hace que todos los eventos especificados no se rastreen. Esto es útil para
           seleccionar un subsistema para rastrear pero dejar fuera varios eventos.
           Por ejemplo: "-e sched -v -e "*stat*"" habilitará todos los eventos en
           el subsistema sched excepto aquellos que tengan "stat" en sus nombres.
     -B: Elimina la instancia de ftrace especificada. No debe haber opciones de
           configuración relacionadas con esta instancia en la línea de comandos.
           Por ejemplo: "-v -B bar -B foo" eliminará la instancia bar y creará
           una nueva instancia foo.
    Nota: la opción -v se tomó de la forma en que grep(1) invierte las
    coincidencias siguientes.

-P pid

Esto filtrará solo los identificadores de proceso especificados. El uso de -P le permitirá rastrear solo los eventos causados por el proceso.

-c

Usado -P para rastrear también a los hijos del proceso (si el kernel lo soporta).

--user

Ejecuta el comando especificado tal como está dado por el usuario.

-C reloj

Establece el reloj de rastreo a "reloj". 
Use trace-cmd(1) list -C para ver qué relojes están disponibles.

-l nombre-de-función

Esto limitará los rastreadores function y function_graph para rastrear solo el nombre de función dado. Se pueden especificar más de un -l en la línea de comandos para rastrear más de una función. También se permite el uso limitado de expresiones comodín. Estas son match* para filtrar solo funciones que comienzan con match. *match para filtrar solo funciones que terminan con match. *match\* para filtrar solo funciones que contienen match.

-g nombre-de-función

Esta opción es para el plugin function_graph. Graficará la función dada. Es decir, solo rastreará la función y todas las funciones que llama. Puede haber más de un -g en la línea de comandos.

-n nombre-de-función

Esto tiene el efecto opuesto a -l. La función dada con la opción -n no se rastreará. Esto tiene prioridad, es decir, si incluye la misma función tanto para -n como para -l, no se rastreará.

-d

Algunos plugins de rastreo habilitan el rastreador de funciones por defecto. Como los rastreadores de latencia. Esta opción evita que el rastreador de funciones se habilite al inicio.

-D

La opción -d intentará usar la opción function-trace para deshabilitar el rastreador de funciones (si está disponible), de lo contrario, usará por defecto el archivo proc: /proc/sys/kernel/ftrace_enabled, pero no lo tocará si la opción function-trace está disponible. La opción -D deshabilitará tanto el archivo proc ftrace_enabled como la opción function-trace si existe. 
Nota, esto deshabilita el rastreo de funciones para todos los usuarios, incluidos los usuarios fuera de los rastreadores de ftrace (stack_tracer, perf, etc.).

-O opción

Ftrace tiene varias opciones que se pueden habilitar o deshabilitar. Esto le permite establecerlas. Anexar el texto no a una opción la deshabilita. Por ejemplo: "-O nograph-time" deshabilitará la opción Ftrace "graph-time".

-b tamaño

Esto establece el tamaño del búfer de anillo a tamaño kilobytes. Debido a que el búfer de anillo de Ftrace es por CPU, este tamaño es el tamaño de cada búfer de anillo por CPU dentro del kernel. Usar "-b 10000" en una máquina con 4 CPUs hará que Ftrace tenga un tamaño total de búfer de 40 Megabytes.

-B nombre-del-buffer

Si el kernel admite múltiples búferes, esto agregará un búfer con el nombre dado. Si el nombre del búfer ya existe, ese búfer simplemente se reinicia. 
Después de indicar un nombre de búfer, todos los eventos agregados después se asociarán con ese búfer. Si no se especifica ningún búfer, o si se especifica un evento antes de un nombre de búfer, se asociará con el búfer principal (nivel superior).
trace-cmd set -e sched -B block -e block -B time -e timer sleep 1
Lo anterior habilitará todos los eventos sched en el búfer principal. Luego creará una instancia de búfer 'block' y habilitará todos los eventos de bloque dentro de ese búfer. Se creará una instancia de búfer 'time' y todos los eventos de temporizador se habilitarán para ese evento.

-m tamaño

El tamaño máximo en kilobytes que debe tener un búfer por CPU. Tenga en cuenta que, debido al redondeo al tamaño de página, el número puede no ser totalmente correcto. Además, esto se realiza alternando entre dos búferes que tienen la mitad del tamaño dado, por lo que la salida puede no ser del tamaño dado, incluso si se escribió mucho más. 
Úselo para evitar quedarse sin espacio en disco para ejecuciones largas.

-M máscara-cpu

Se
el cpumask para rastrear. Solo afecta a la última instancia de búfer dada. Si se proporciona antes de cualquier instancia de búfer, entonces afecta al búfer principal. El valor proporcionado debe ser un número hexadecimal. 
trace-cmd set -p function -M c -B events13 -e all -M 5
Si se omite el -M, la máscara permanece igual. Para habilitar todas las
CPUs, pase un valor de '-1'.

-i

Por defecto, si se enumera un evento que trace-cmd no encuentra, saldrá con un error. Esta opción simplemente ignorará los eventos que se enumeran en la línea de comandos pero que no se encuentran en el sistema.

-q | --quiet

Suprime la salida normal, excepto los errores.

--max-graph-depth profundidad

Establece la profundidad máxima a la que el tracer function_graph rastreará una función. Un valor de uno solo mostrará dónde el espacio de usuario entra al kernel, pero no las funciones llamadas en el kernel. El valor predeterminado es cero, lo que significa sin límite.

--cmdlines-size tamaño

Establece el número de entradas que el archivo de rastreo del kernel "saved_cmdlines" puede contener. Este archivo es un búfer circular que almacena el mapeo entre cmdlines y PIDs. Si está lleno, conduce a cmdlines no resueltas ("<...>") dentro del rastreo. El valor predeterminado del kernel es 128.

--module módulo

Filtra el nombre de un módulo en el rastreo de funciones. Es equivalente a agregar :mod:módulo después de todas las demás funciones que se estén filtrando. Si no se enumeran otros filtros de funciones, entonces se filtrarán todas las funciones de los módulos en el filtro. 
'--module snd'  es equivalente a  '-l :mod:snd'
'--module snd -l "*jack*"' es equivalente a '-l "*jack*:mod:snd"'
'--module snd -n "*"' es equivalente a '-n :mod:snd'

--stderr

Dirigir la salida a stderr en lugar de stdout, pero la salida del comando ejecutado no se modificará. Esto es útil si desea monitorear la salida del comando que se está ejecutando, pero no ver la salida de trace-cmd.

--fork

Si se enumera un comando, trace-cmd esperará a que ese comando termine, a menos que se especifique la opción --fork. Luego, se creará un fork del comando y se devolverá inmediatamente.

--verbose[=nivel]

Establece el nivel de registro. Los niveles de registro soportados son "none", "critical", "error", "warning", "info", "debug", "all" o sus identificadores "0", "1", "2", "3", "4", "5", "6". Establecer el nivel de registro a un valor específico habilita todos los registros de ese nivel y de todos los niveles anteriores. El nivel predeterminado será "info" si no se especifica ninguno. 
Ejemplo: habilita todos los registros críticos, de error y de advertencia
trace-cmd set --verbose=warning

EJEMPLOS

Habilita todos los eventos para rastreo:

 # trace-cmd set -e all

Establece el rastreador de funciones:

 # trace-cmd set -p function
