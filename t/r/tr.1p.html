TR(1P) Manual del programador POSIX TR(1P)

PROLOGO

Esta página del manual es parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

tr — traduce caracteres

SINOPSIS

tr [-c|-C] [-s] cadena1 cadena2
tr -s [-c|-C] cadena1
tr -d [-c|-C] cadena1
tr -ds [-c|-C] cadena1 cadena2

DESCRIPCIÓN

La utilidad tr copia la entrada estándar a la salida estándar con sustitución o eliminación de caracteres seleccionados. Las opciones especificadas y los operandos cadena1 y cadena2 controlarán las traducciones que ocurran al copiar caracteres y elementos de ordenación de un solo carácter.

OPCIONES

La utilidad tr se ajustará a las Definiciones Base del volumen de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidades.

Se soportarán las siguientes opciones:

-c
Complementa el conjunto de valores especificados por cadena1. Consulte la sección DESCRIPCIÓN EXTENDIDA.
-C
Complementa el conjunto de caracteres especificados por cadena1. Consulte la sección DESCRIPCIÓN EXTENDIDA.
-d
Elimina todas las ocurrencias de caracteres de entrada que se especifican por cadena1.
-s
Reemplaza instancias de caracteres repetidos con un solo carácter, como se describe en la sección DESCRIPCIÓN EXTENDIDA.

OPERANDOS

Se soportarán los siguientes operandos:

cadena1, cadena2

Cadenas de control de traducción. Cada cadena representará un conjunto de caracteres que se convertirán en una matriz de caracteres utilizada para la traducción. Para una descripción detallada de cómo se interpretan las cadenas, consulte la sección DESCRIPCIÓN EXTENDIDA.

ENTRADA ESTÁNDAR

La entrada estándar puede ser cualquier tipo de archivo.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de tr:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte las Definiciones Base del volumen de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_COLLATE

Determina la localización para el comportamiento de las expresiones de rango y las clases de equivalencia.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en los argumentos) y el comportamiento de las clases de caracteres.
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La salida de tr será idéntica a la entrada, con la excepción de las transformaciones especificadas.

ERROR ESTÁNDAR

La salida de error se utilizará solo para mensajes de diagnóstico.

DESCRIPCIÓN EXTENDIDA

Los operandos cadena1 y cadena2 (si se especifican) definen dos matrices de caracteres. Los constructos en la siguiente lista se pueden usar para especificar caracteres o elementos de ordenación de un solo carácter. Si alguno de los constructos da como resultado elementos de ordenación de varios caracteres, tr excluirá, sin diagnóstico, esos elementos de varios caracteres de la matriz resultante.

caracter
Cualquier carácter no descrito por alguna de las convenciones a continuación se representará a sí mismo.
\octal
Las secuencias octales se pueden usar para representar caracteres con valores codificados específicos. Una secuencia octal consistirá en una barra invertida seguida de la secuencia más larga de uno, dos o tres caracteres de dígito octal (01234567). La secuencia causará que el valor cuya codificación se representa mediante el entero octal de uno, dos o tres dígitos se coloque en la matriz. Los caracteres multibyte requieren múltiples secuencias de escape concatenadas de este tipo, incluida la barra invertida inicial para cada byte.
\caracter
Se soportarán las secuencias de escape con barra invertida en el volumen de Definiciones Base de POSIX.1‐2017, Tabla 5-1, Secuencias de escape y acciones asociadas ('\\', '\a', '\b', '\f', '\n', '\r', '\t', '\v'). Los resultados de usar cualquier otro carácter, que no sea un dígito octal, después de la barra invertida no se especifican. Además, si no hay ningún carácter después de la barra invertida, los resultados no se especifican.
c-c
En la localización POSIX, este constructo representará el rango de elementos de ordenación entre los puntos finales del rango (siempre que ninguno de los puntos finales sea una secuencia octal de la forma \octal), inclusive, según lo definido por la secuencia de ordenación. Los caracteres o elementos de ordenación en el rango se colocarán en la matriz en orden ascendente de ordenación. Si el segundo punto final precede al punto final inicial en la secuencia de ordenación, no se especifica si el rango de elementos de ordenación está vacío o si este constructo se trata como inválido. En localizaciones distintas de la localización POSIX, este constructo tiene un comportamiento no especificado.

Si uno o ambos puntos finales del rango son secuencias octales de la forma \octal, esto representará el rango de valores codificados específicos entre los dos puntos finales del rango, inclusive.

[:clase:]
Representa todos los caracteres que pertenecen a la clase de caracteres definida, según lo definido por la configuración actual de la categoría de localización LC_CTYPE. Los siguientes nombres de clases de caracteres se aceptarán cuando se especifiquen en cadena1:
alnum blank digit lower punct upper
alpha cntrl graph print space xdigit

ESPECIFICACIONES_DE_CLASE_Y_EQUIVALENCIA

Las siguientes expresiones pueden usarse en cualquiera de las cadenas de operandos:

[:nombre:]
Representa todas las teclas o elementos de ordenación que pertenecen a la clase de caracteres nombrada por nombre, según lo definido por la categoría de configuración regional LC_CTYPE. Las clases de caracteres POSIX.1-2017 estándar incluyen las siguientes:
alnum
Caracteres alfanuméricos.
alpha
Caracteres alfabéticos.
cntrl
Caracteres de control.
digit
Dígitos.
graph
Caracteres imprimibles, excepto el espacio.
lower
Caracteres minúsculas.
print
Caracteres imprimibles, incluido el espacio.
punct
Caracteres de puntuación.
space
Caracteres de espacio en blanco.
upper
Caracteres mayúsculas.
xdigit
Dígitos hexadecimales.
El conjunto de caracteres de la clase de caracteres se reconocerá en aquellas configuraciones regionales donde la palabra clave nombre haya recibido una definición de charclass en la categoría LC_CTYPE.

Cuando se especifican ambas opciones -d y -s, se aceptarán nombres de clases de caracteres en string2. De lo contrario, solo los nombres de clases de caracteres lower o upper son válidos en string2 y solo si la clase de caracteres correspondiente (upper y lower, respectivamente) se especifica en la misma posición relativa en string1. Dicha especificación se interpretará como una solicitud de conversión de mayúsculas/minúsculas. Cuando [:lower:] aparece en string1 y [:upper:] aparece en string2, los arrays contendrán los caracteres del mapeo toupper en la categoría LC_CTYPE de la configuración regional actual. Cuando [:upper:] aparece en string1 y [:lower:] aparece en string2, los arrays contendrán los caracteres del mapeo tolower en la categoría LC_CTYPE de la configuración regional actual. El primer carácter de cada par de mapeo estará en el array para string1 y el segundo carácter de cada par de mapeo estará en el array para string2 en la misma posición relativa.

Excepto para la conversión de mayúsculas/minúsculas, los caracteres especificados por una expresión de clase de caracteres se colocarán en el array en un orden no especificado.

Si el nombre especificado para class no define una clase de caracteres válida en la configuración regional actual, el comportamiento no está definido.

[=equiv=]
Representa todos los caracteres o elementos de ordenación que pertenecen a la misma clase de equivalencia que equiv, según lo definido por la configuración actual de la categoría de configuración regional LC_COLLATE. Una expresión de clase de equivalencia solo se permitirá en string1, o en string2 cuando esté siendo utilizada por las opciones combinadas -d y -s. Los caracteres que pertenecen a la clase de equivalencia se colocarán en el array en un orden no especificado.
[x*n]
Representa n ocurrencias repetidas del carácter x. Debido a que esta expresión se utiliza para mapear varios caracteres a uno solo, solo es válida cuando ocurre en string2. Si n se omite o es cero, se interpretará como lo suficientemente grande como para extender la secuencia basada en string2 a la longitud de la secuencia basada en string1. Si n tiene un cero inicial, se interpretará como un valor octal. De lo contrario, se interpretará como un valor decimal.

Cuando la opción -d no se especifica:

*
Si string2 está presente, cada carácter de entrada encontrado en el array especificado por string1 será reemplazado por el carácter en la misma posición relativa en el array especificado por string2. Si el array especificado por string2 es más corto que el especificado por string1, o si un carácter ocurre más de una vez en string1, los resultados no están especificados.
*
Si se especifica la opción -C, los complementos de los caracteres especificados por string1 (el conjunto de todos los caracteres en el conjunto de caracteres actual, según lo definido por la configuración actual de LC_CTYPE, excepto aquellos especificados realmente en el operando string1) se colocarán en el array en secuencia de ordenación ascendente, según lo definido por la configuración actual de LC_COLLATE.
*
Si se especifica la opción -c, los complementos de los valores especificados por string1 se colocarán en el array en orden ascendente por valor binario.
*
Debido a que el orden en que se especifican los caracteres mediante expresiones de clase de caracteres o expresiones de clase de equivalencia no está definido, dichas expresiones solo deben usarse si la intención es mapear varios caracteres en uno solo. Una excepción es la conversión de mayúsculas/minúsculas, como se describe anteriormente.

Cuando se especifica la opción -d:

*
Los caracteres de entrada encontrados en el array especificado por string1 serán eliminados.
*
Cuando se especifica la opción -C con -d, se eliminarán todos los caracteres excepto los especificados por string1. El contenido de string2 se ignora, a menos que también se especifique la opción -s.
*
Cuando se especifica la opción -c con -d, se eliminarán todos los valores excepto los especificados por string1. El contenido de string2 se ignorará, a menos que también se especifique la opción -s.
*
La misma cadena no se puede utilizar tanto para la opción -d como para la opción -s; cuando se especifican ambas opciones, se requerirán tanto string1 (utilizada para la eliminación) como string2 (utilizada para el apisonamiento).

Cuando se especifica la opción -s, después de que se hayan realizado las eliminaciones o traducciones, las secuencias repetidas del mismo carácter se reemplazarán por una ocurrencia del mismo carácter, si el carácter se encuentra en el array especificado por el último operando. Si el último operando contiene una clase de caracteres, como el siguiente ejemplo:

tr -s '[:space:]'

el array del último operando contendrá todos los caracteres de esa clase de caracteres. Sin embargo, en una conversión de mayúsculas/minúsculas, como se describe anteriormente, como:

tr -s '[:upper:]' '[:lower:]'

el array del último operando contendrá solo aquellos caracteres definidos como los segundos caracteres en cada par de caracteres toupper o tolower, según corresponda.

Una cadena vacía utilizada para string1 o string2 produce resultados indefinidos.

Las siguientes secciones son informativas.

USO_DE_APLICACION

Si es necesario, string1 y string2 pueden entrecomillarse para evitar la coincidencia de patrones por parte del shell.

Si un dígito ordinario (que representa a sí mismo) va a seguir a una secuencia octal, la secuencia octal debe usar los tres dígitos completos para evitar ambigüedades.

Cuando string2 es más corta que string1, se produce una diferencia entre los sistemas históricos System V y BSD. Un sistema BSD rellena string2 con el último carácter encontrado en string2. Por lo tanto, es posible hacer lo siguiente:

tr 0123456789 d

lo que traduciría todos los dígitos a la letra 'd'. Dado que esta área no está especificada explícitamente en este volumen de POSIX.1-2017, se permiten ambos comportamientos, el de BSD y el de System V, pero una aplicación compatible no puede depender del comportamiento de BSD. Tendría que codificar el ejemplo de la siguiente manera:

tr 0123456789 '[d*]'

Cabe señalar que, a pesar de las similitudes en apariencia, las cadenas operandos utilizadas por tr no son expresiones regulares.

A diferencia de algunas implementaciones históricas, esta definición de la utilidad tr procesa correctamente los caracteres NUL en su flujo de entrada. Los caracteres NUL se pueden eliminar usando:

tr -d '\000'

EJEMPLOS

1.
El siguiente ejemplo crea una lista de todas las palabras en file1 una por línea en file2, donde una palabra se considera una cadena máxima de letras.
tr -cs "[:alpha:]" "[\n*]" <file1 >file2
2.
El siguiente ejemplo traduce todos los caracteres minúsculas en file1 a mayúsculas y escribe los resultados en la salida estándar.
tr "[:lower:]" "[:upper:]" <file1
3.
Este ejemplo utiliza una clase de equivalencia para identificar variantes acentuadas del carácter base 'e' en file1, que se despojan de signos diacríticos y se escriben en file2.
tr "[=e=]" "[e*]" <file1 >file2

RATIONALE

En algunas propuestas iniciales, se agregó una opción explícita -n para deshabilitar el comportamiento histórico de eliminar los caracteres NUL de la entrada. Se consideró que la eliminación automática de caracteres NUL de la entrada no era una funcionalidad correcta. Sin embargo, la eliminación de -n en una propuesta posterior no elimina el requisito de que tr procese correctamente los caracteres NUL en su flujo de entrada. Los caracteres NUL se pueden eliminar utilizando tr -d '\000'.

Las implementaciones históricas de tr difieren ampliamente en sintaxis y comportamiento. Por ejemplo, la versión BSD no ha necesitado los caracteres de corchete para la secuencia de repetición. La sintaxis de la utilidad tr se basa más estrechamente en el modelo System V y XPG3, al tiempo que intenta acomodar las implementaciones históricas de BSD. En el caso del relleno corto de string2, la decisión fue no especificar el comportamiento y preservar los scripts de System V y XPG3, que podrían tener dificultades con el método de BSD. Se asumió que los usuarios de BSD de tr tendrían que hacer adaptaciones para cumplir con la sintaxis definida aquí. Dado que es posible utilizar la secuencia de repetición para duplicar el comportamiento deseado, mientras que no hay una forma sencilla de lograr el método de System V, este fue el enfoque correcto, aunque no deseable.

El uso de valores octales para especificar caracteres de control, aunque tiene precedentes históricos, no es portable. La introducción de secuencias de escape para caracteres de control debería proporcionar la portabilidad necesaria. Se reconoce que esto puede hacer que algunos scripts históricos fallen.

Una propuesta anterior incluía soporte para elementos de ordenación multicarácter. Se señaló que, si bien tr utiliza algunos elementos sintácticos de los RE, el objetivo de tr es bastante diferente; los rangos, por ejemplo, no tienen un significado similar (``cualquiera de los caracteres en el rango coincide'', versus ``traducir cada carácter en el rango a su contraparte de salida''). Como resultado, se ha eliminado el soporte previamente incluido para elementos de ordenación multicarácter. Lo que queda son rangos en orden de ordenación actual (para admitir, por ejemplo, caracteres acentuados),

RATIONALE

The tr utility is used for character translation or deletion. It operates on character sets and the concept of equivalence classes and character classes. Earlier standards defined character classes and equivalence classes using a syntax that was not entirely consistent with other utilities that processed regular expressions. The XSI extension uses a syntax that is more aligned with the POSIX.1-2001 standard.

The -c option was originally intended to complement the set of characters specified by the first argument. The -s option was intended to squeeze repeated characters in the output. These options are still supported.

The standard defines the following character classes:

[:alnum:] Alphanumeric characters.

[:alpha:] Alphabetic characters.

[:cntrl:] Control characters.

[:digit:] Digits.

[:graph:] Printable characters except space.

[:lower:] Lowercase letters.

[:print:] Printable characters including space.

[:punct:] Punctuation characters.

[:space:] White-space characters.

[:upper:] Uppercase letters.

[:xdigit:] Hexadecimal digits.

Equivalence classes are used to specify characters that are considered equivalent for sorting purposes. For example, in some locales, 'a', 'á', and 'A' might be considered equivalent.

In XPG3, the [:class:] and [=equiv=] conventions are shown with double brackets, as in RE syntax. However, tr does not implement RE principles; it just borrows part of the syntax. Consequently, [:class:] and [=equiv=] should be regarded as syntactical elements on a par with [x*n], which is not an RE bracket expression.

The standard developers will consider changes to tr that allow it to translate characters between different character encodings, or they will consider providing a new utility to accomplish this.

On historical System V systems, a range expression requires enclosing square-brackets, such as:

tr '[a-z]' '[A-Z]'

However, BSD-based systems did not require the brackets, and this convention is used here to avoid breaking large numbers of BSD scripts:

tr a-z A-Z

The preceding System V script will continue to work because the brackets, treated as regular characters, are translated to themselves. However, any System V script that relied on "a‐z" representing the three characters 'a', '-', and 'z' have to be rewritten as "az-".

The ISO POSIX‐2:1993 standard had a -c option that behaved similarly to the -C option, but did not supply functionality equivalent to the -c option specified in POSIX.1‐2008.

The earlier version also said that octal sequences referred to collating elements and could be placed adjacent to each other to specify multi-byte characters. However, it was noted that this caused ambiguities because tr would not be able to tell whether adjacent octal sequences were intending to specify multi-byte characters or multiple single byte characters. POSIX.1‐2008 specifies that octal sequences always refer to single byte binary values when used to specify an endpoint of a range of collating elements.

Earlier versions of this standard allowed for implementations with bytes other than eight bits, but this has been modified in this version.
