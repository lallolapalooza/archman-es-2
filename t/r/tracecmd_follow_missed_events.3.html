tracecmd_follow_missed_events(3)

LIBTRACECMD(3) Manual de libtracefs LIBTRACECMD(3)

NOMBRE

tracecmd_iterate_events, tracecmd_iterate_events_multi, tracecmd_follow_event, tracecmd_follow_missed_events, tracecmd_filter_add, tracecmd_iterate_reset - Leer eventos de un archivo de traza

SINOPSIS

#include <trace-cmd.h>
int tracecmd_iterate_events(struct tracecmd_input *handle,
                            cpu_set_t *cpus, int cpu_size,
                            int (*callback)(struct tracecmd_input *,
                                            struct tep_record *,
                                            int, void *),
                            void *callback_data);
int tracecmd_iterate_events_multi(struct tracecmd_input **handles,
                                  int nr_handles,
                                  int (*callback)(struct tracecmd_input *,
                                                           struct tep_record *,
                                                           int, void *),
                                  void *callback_data);
int tracecmd_iterate_events_reverse(struct tracecmd_input *handle,
                            cpu_set_t *cpus, int cpu_size,
                            int (*callback)(struct tracecmd_input *,
                                            struct tep_record *,
                                            int, void *),
                            void *callback_data, bool cont);
int tracecmd_follow_event(struct tracecmd_input *handle,
                          const char *system, const char *event_name,
                          int (*callback)(struct tracecmd_input *,
                                          struct tep_event *,
                                          struct tep_record *,
                                          int, void *),
                          void *callback_data);
int tracecmd_follow_missed_events(struct tracecmd_input *handle,
                                   int (*callback)(struct tracecmd_input *,
                                                   struct tep_event *,
                                                   struct tep_record *,
                                                   int, void *),
                                   void *callback_data);
struct tracecmd_filter *tracecmd_filter_add(struct tracecmd_input handle,
                                            const char *filter_str, bool neg);
int *tracecmd_iterate_reset(struct tracecmd_input *handle);

DESCRIPCIÓN

Este conjunto de APIs se puede utilizar para iterar sobre eventos después de abrir un archivo de traza utilizando una de las funciones de apertura, como tracecmd_open(3) o tracecmd_open_fd(3).

La función tracecmd_iterate_events() iterará a través de todos los eventos en el archivo de traza definido por handle, donde handle es devuelto por una de las funciones de tracecmd_open(3). Llamará a la función callback() en los eventos de las CPUs definidas por cpus. El cpu_size debe ser el tamaño de cpus (ver CPU_SET(3)). Si cpus es NULL, entonces cpu_size se ignora y callback() se llamará para todos los eventos en todas las CPUs del archivo de traza. El callback_data se pasa a callback() como su último parámetro. callback puede ser NULL, lo cual es útil si se usa tracecmd_follow_event(), pero ten en cuenta que si callback es NULL, entonces callback_data se ignora y no se envía al callback de tracecmd_follow_event().

La función tracecmd_iterate_events_multi() es similar a tracecmd_iterate_events(), excepto que permite iterar sobre más de un archivo de traza. Si se utiliza tracecmd agent(1) para obtener un archivo de traza tanto para el host como para el invitado, asegúrate de que el archivo de traza del host sea la primera entrada en handles y tracecmd_iterate_events_multi() realizará la sincronización de los metadatos para los archivos del invitado que vienen después en handles. handles es un array de descriptores de archivos de traza que fueron abiertos por tracecmd_open(3) y similares. Ten en cuenta que, a diferencia de tracecmd_iterate_events(), tracecmd_iterate_events_multi() no filtra por CPUs, ya que esto haría que la API fuera demasiado compleja al tener que saber en qué handle filtrar las CPUs. Si se desea filtrar por CPU, entonces el callback debe verificar record→cpu y devolver 0 si no es la CPU deseada para procesar. nr_handles indica el número de elementos en handles. El callback_data se pasa al callback como su último parámetro. callback puede ser NULL, lo cual es útil si se usa tracecmd_follow_event(), pero ten en cuenta que si callback es NULL, entonces callback_data se ignora y no se envía al callback de tracecmd_follow_event().

La función tracecmd_iterate_events_reverse() funciona de manera muy similar a como funciona tracecmd_iterate_events(), pero en lugar de llamar a la función callback() para cada evento en orden de marca de tiempo, llamará a la función callback() para cada evento en orden inverso de marca de tiempo. Si cont es falso, comenzará llamando al evento con la marca de tiempo más antigua en el archivo trace.dat. Si cont se establece a verdadero, comenzará donde sea que esté la posición actual de los datos de traza. Por ejemplo, si el callback() devuelve algo distinto de cero, saldrá de la iteración. Si se llama a tracecmd_iterate_events_reverse() de nuevo con cont a verdadero, continuará desde donde lo dejó. Si cont es falso, comenzará de nuevo en el evento con la marca de tiempo más antigua. El handle, cpus, cpu_size y callback_data actúan igual que en tracecmd_iterate_events().

El callback() para tracecmd_iterate_events(), tracecmd_iterate_events_reverse() y tracecmd_iterate_events_multi() es del prototipo:

int callback()(struct tracecmd_input *handle, struct tep_record *record, int cpu, void *data);

El handle es el mismo handle pasado a tracecmd_iterate_events() o el handle actual de handles pasado a tracecmd_iterate_events_multi() al que pertenece el record. El record es el registro de evento actual. El cpu es la CPU actual que se está procesando. Ten en cuenta que, para tracecmd_iterate_events_multi(), puede que no sea la CPU real del archivo, sino la enésima CPU de todos los handles combinados. Usa record→cpu para obtener la CPU real en la que se encuentra el evento.

La función tracecmd_follow_event() se adjuntará a un descriptor de archivo de traza handle y llamará al callback cuando el evento descrito por system y name coincida con un evento en la iteración de tracecmd_iterate_events() o tracecmd_iterate_events_multi(). Ten en cuenta que la cpu es la enésima CPU tanto para tracecmd_iterate_events() como para tracecmd_iterate_events_multi(). Si se necesita la CPU real del record, usa record→cpu. Para tracecmd_iterate_events_multi(), el callback solo se llama si el handle coincide con el descriptor de archivo de traza actual dentro de handles. El callback_data se pasa como el último parámetro a la función callback(). Ten en cuenta que esta función callback() se llamará antes que la función callback() de tracecmd_iterate_events() o tracecmd_iterate_events_multi().

El prototipo de callback() para *tracecmd_follow_event()* es:

int callback()(struct tracecmd_input *handle, struct tep_event *event, struct tep_record *_record, int cpu, void *data);

La función tracecmd_follow_missed_events() se adjuntará a un descriptor de archivo de traza handle y llamará al callback cuando se detecten eventos perdidos. El event contendrá el tipo de evento que es el record. El record contendrá la información de los eventos perdidos. La cpu es la enésima CPU tanto para tracecmd_iterate_events() como para tracecmd_iterate_events_multi(). Si se necesita la CPU para la que son los eventos perdidos, usa record→cpu. Si record→missed_events es un número positivo, entonces contiene el número de eventos perdidos desde el último evento en su CPU, de lo contrario será negativo, y eso significará que el número de eventos perdidos es desconocido pero existen eventos perdidos desde el último evento en la CPU. El callback y callback_data tienen el mismo formato que tracecmd_follow_event() arriba. Los eventos perdidos
