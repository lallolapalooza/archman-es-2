truncate(2) Manual de llamadas al sistema truncate(2)

NOMBRE

truncate, ftruncate - truncar un archivo a una longitud especificada

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int truncate(const char *path, off_t length);
int ftruncate(int fd, off_t length);
Requisitos de macros de prueba de características para glibc (ver feature_test_macros(7)):

truncate():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.12: */ _POSIX_C_SOURCE >= 200809L
        || /* glibc <= 2.19: */ _BSD_SOURCE

ftruncate():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.3.5: */ _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPCIÓN

Las funciones truncate() y ftruncate() hacen que el archivo regular nombrado por path o referenciado por fd sea truncado a un tamaño de exactamente length bytes.

Si el archivo era previamente más grande que este tamaño, los datos adicionales se pierden. Si el archivo era previamente más corto, se extiende y la parte extendida se lee como bytes nulos ('\0').

El desplazamiento del archivo no se modifica.

Si el tamaño cambió, entonces los campos st_ctime y st_mtime (respectivamente, tiempo del último cambio de estado y tiempo de la última modificación; ver inode(7)) para el archivo se actualizan, y los bits de modo set-user-ID y set-group-ID pueden ser limpiados.

Con ftruncate(), el archivo debe estar abierto para escritura; con truncate(), el archivo debe ser escribible.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

Para truncate():

EACCES
Se deniega el permiso de búsqueda para un componente del prefijo de la ruta, o el archivo nombrado no es escribible por el usuario. (Ver también path_resolution(7)).
EFAULT
El argumento path apunta fuera del espacio de direcciones asignado del proceso.
EFBIG
El argumento length es mayor que el tamaño máximo del archivo. (XSI)
EINTR
Mientras estaba bloqueada esperando a completar, la llamada fue interrumpida por un manejador de señales; ver fcntl(2) y signal(7).
EINVAL
El argumento length es negativo o mayor que el tamaño máximo del archivo.
EIO
Ocurrió un error de E/S al actualizar el inodo.
EISDIR
El archivo nombrado es un directorio.
ELOOP
Se encontraron demasiados enlaces simbólicos al traducir el nombre de ruta.
ENAMETOOLONG
Un componente de un nombre de ruta excedió los 255 caracteres, o un nombre de ruta completo excedió los 1023 caracteres.
ENOENT
El archivo nombrado no existe.
ENOTDIR
Un componente del prefijo de la ruta no es un directorio.
EPERM
El sistema de archivos subyacente no admite la extensión de un archivo más allá de su tamaño actual.
EPERM
La operación fue impedida por un sello de archivo; ver fcntl(2).
EROFS
El archivo nombrado reside en un sistema de archivos de solo lectura.
ETXTBSY
El archivo es un archivo ejecutable que se está ejecutando.

Para ftruncate() se aplican los mismos errores, pero en lugar de cosas que pueden estar mal con path, ahora tenemos cosas que pueden estar mal con el descriptor de archivo, fd:

EBADF
fd no es un descriptor de archivo válido.
EBADF o EINVAL
fd no está abierto para escritura.
EINVAL
fd no hace referencia a un archivo regular ni a un objeto de memoria compartida POSIX.
EINVAL o EBADF
El descriptor de archivo fd no está abierto para escritura. POSIX permite, y las aplicaciones portables deben manejar, cualquiera de los dos errores para este caso. (Linux produce EINVAL).

VERSIONES

Los detalles en DESCRIPCIÓN son para sistemas compatibles con XSI. Para sistemas no compatibles con XSI, el estándar POSIX permite dos comportamientos para ftruncate() cuando length excede la longitud del archivo (tener en cuenta que truncate() no está especificado en absoluto en tal entorno): devolver un error o extender el archivo. Como la mayoría de las implementaciones de UNIX, Linux sigue el requisito XSI al tratar con sistemas de archivos nativos. Sin embargo, algunos sistemas de archivos no nativos no permiten usar truncate() y ftruncate() para extender un archivo más allá de su longitud actual: un ejemplo notable en Linux es VFAT.

En algunas arquitecturas de 32 bits, la firma de llamada para estas llamadas al sistema difiere, por las razones descritas en syscall(2).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SVr4, 4.2BSD.

Las llamadas al sistema originales truncate() y ftruncate() de Linux no fueron diseñadas para manejar desplazamientos de archivo grandes. En consecuencia, Linux 2.4 agregó las llamadas al sistema truncate64() y ftruncate64() que manejan archivos grandes. Sin embargo, estos detalles pueden ser ignorados por las aplicaciones que usan glibc, cuyas funciones envoltorio emplean transparentemente las llamadas al sistema más recientes donde están disponibles.

NOTAS

ftruncate() también puede usarse para establecer el tamaño de un objeto de memoria compartida POSIX; ver shm_open(3).

ERRORES CONOCIDOS

Un error en el archivo de cabecera en glibc 2.12 hizo que el valor mínimo de _POSIX_C_SOURCE requerido para exponer la declaración de ftruncate() fuera 200809L en lugar de 200112L. Esto se ha corregido en versiones posteriores de glibc.

VER TAMBIÉN

truncate(1), open(2), stat(2), path_resolution(7)

NOMBRE

truncate64 - truncate, ftruncate, truncate64, ftruncate64 - acortar o extender un archivo a un tamaño determinado.

BIBLIOTECA

Biblioteca C estándar (libc)

SINOPSIS

#include <unistd.h>

int truncate(const char *path, off_t length);
int ftruncate(int fd, off_t length);

#define _FILE_OFFSET_BITS 64
#include <unistd.h>

int truncate64(const char *path, off64_t length);
int ftruncate64(int fd, off64_t length);

DESCRIPCIÓN

La llamada al sistema truncate() acorta o extiende el archivo especificado por path a una longitud de length bytes.

Si el archivo es más largo que length, se descartan los bytes adicionales. Si el archivo es más corto que length, se extiende. Si el archivo es inexistente, se crea un archivo vacío. Si el archivo se extiende, el contenido de los bytes añadidos es indefinido, excepto que las escrituras subsiguientes serán correctas. Las extensiones de archivo son posibles sólo en sistemas de archivos que lo soportan.

La llamada al sistema ftruncate() realiza la misma operación pero opera en el archivo abierto asociado con el descriptor de archivo fd.

Los bytes que están fuera del rango de los datos existentes pero dentro del nuevo tamaño del archivo se muestran como bytes nulos (0) en escrituras posteriores, si el archivo se extiende. Por ejemplo, si un archivo tiene 100 bytes y se llama a ftruncate(fd, 200), las escrituras posteriores en el archivo pueden leerse hasta el byte 199, y los bytes de 100 a 199 se mostrarán como ceros.

Las truncate64() y ftruncate64() son versiones de 64 bits de truncate() y ftruncate(). Se definen si se define _FILE_OFFSET_BITS con el valor 64 antes de incluir cualquier encabezado. Estas versiones utilizan tipos de datos de 64 bits para las longitudes de archivo, permitiendo que los archivos mayores de 2 GiB sean manejados correctamente.

Los permisos de archivo se comprueban usando los permisos del directorio padre, y el propietario se verifica con X_OK y W_OK.

El tamaño del archivo se establece en el valor especificado por length. Si el archivo se acorta, la marca de tiempo de la última modificación del archivo se actualiza.

Si el archivo tiene enlaces duros, el tamaño del archivo se reduce sólo si todos los enlaces duros se apuntan al mismo archivo y todos ellos son acortados. Si no, el tamaño del archivo no se modifica.

Si el archivo es un archivo especial de dispositivo, las operaciones truncate y ftruncate pueden fallar con EIO.

VALOR DE RETORNO

En caso de éxito, se devuelve 0. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EBADF
ftruncate() o ftruncate64(): fd no es un descriptor de archivo válido.
EFBIG
El nuevo tamaño del archivo es mayor que el límite de tamaño de archivo permitido para el proceso (ulimit -f).
EINTR
La llamada fue interrumpida por una señal antes de que pudiera completarse.
EIO
Se produjo un error de E/S al leer o escribir en el dispositivo, o el archivo es un archivo especial de dispositivo.
EISDIR
path o el archivo referido por fd es un directorio.
EMFILE
truncate() o truncate64(): Demasiados archivos abiertos en el proceso. Esto sólo puede ocurrir si el sistema de archivos subyacente crea un nuevo descriptor de archivo para el truncamiento.
ENOSPC
No hay espacio en el dispositivo para extender el archivo.
ENOTDIR
Un componente de path no es un directorio.
ENXIO
path o el archivo referido por fd es un dispositivo especial que no se puede abrir en el modo solicitado.
EOVERFLOW
El nuevo tamaño del archivo es mayor que lo que puede manejar el sistema de archivos.
EPERM
path o el archivo referido por fd es un archivo con un tipo especial que no puede ser truncado (por ejemplo, un socket).
EROFS
El archivo está en un sistema de archivos de solo lectura.
ESPIPE
fd se refiere a una tubería, FIFO o socket.
EINVAL
path o fd no es un archivo válido, o length es negativo.
EACCES
Permiso denegado. Consulte access(2) para obtener más detalles.
ELOOP
Demasiados enlaces simbólicos en path.
ENAMETOOLONG
path es demasiado largo.
ENOENT
El archivo especificado por path no existe.
NFS4ERR_NO_GRACE
ftruncate() sobre un archivo NFS puede fallar con NFS4ERR_NO_GRACE si el servidor está en modo de gracia.

VERSIÓNES

Las funciones truncate() y ftruncate() están disponibles en la mayoría de los sistemas Unix. Las versiones de 64 bits truncate64() y ftruncate64() están disponibles en Linux y otros sistemas que soportan archivos de más de 2 GiB. En la mayoría de los sistemas modernos, la definición de _FILE_OFFSET_BITS de 64 bits hace que truncate() y ftruncate() se mapeen a truncate64() y ftruncate64().

ESTÁNDARES

truncate() y ftruncate() están estandarizados por POSIX.1-2008.

HISTORIA

La llamada al sistema truncate() apareció en AT&T Research UNIX. La llamada al sistema ftruncate() apareció en la versión 6 de Unix.

NOTAS

Si se llama a truncate() con length igual a 0, el archivo se trunca a cero bytes de longitud.

Si el archivo tiene el bit setgid activado, y el usuario que llama no es el propietario del archivo, truncate() puede desactivar el bit setgid si el archivo es un ejecutable.

Tenga cuidado al usar truncate() y ftruncate() en archivos compartidos, ya que pueden causar pérdida de datos si otros procesos están escribiendo en el archivo al mismo tiempo.

ERRORES

Algunos sistemas de archivos pueden no soportar la extensión de archivos. En tales sistemas, ftruncate() fallará con ENOSPC si se intenta extender un archivo.

El comportamiento de truncate() en enlaces simbólicos es indefinido. En algunos sistemas, truncate() opera en el archivo al que apunta el enlace simbólico, mientras que en otros, falla con EISDIR. Se recomienda usar ftruncate() en su lugar si es posible.

VER TAMBIÉN

fallocate(2), open(2), posix_fallocate(3), unlink(2)
