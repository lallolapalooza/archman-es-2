TRACEROUTE(8) Traceroute para Linux TRACEROUTE(8)

NOMBRE

traceroute - imprime la ruta que siguen los paquetes a un host de red

SINOPSIS

traceroute [-46dFITUnreAV] [-f first_ttl] [-g gate,...]
[-i device] [-m max_ttl] [-p port] [-s src_addr]
[-q nqueries] [-N squeries] [-t tos]
[-l flow_label] [-w waittimes] [-z sendwait] [-UL] [-D]
[-P proto] [--sport=port] [-M method] [-O mod_options]
[--mtu] [--back]
host [packet_len]
traceroute6 [opciones]

DESCRIPCIÓN

traceroute rastrea la ruta que siguen los paquetes IP desde una red IP hasta un host determinado. Utiliza el campo de tiempo de vida (TTL) del protocolo IP e intenta obtener una respuesta ICMP TIME_EXCEEDED de cada puerta de enlace a lo largo del camino hacia el host.

traceroute6 es equivalente a traceroute -6

El único parámetro requerido es el nombre o la dirección IP del host de destino host. La longitud del paquete opcional es el tamaño total del paquete de sondeo (60 bytes por defecto para IPv4 y 80 para IPv6). El tamaño especificado puede ser ignorado en algunas situaciones o aumentado hasta un valor mínimo.

Este programa intenta rastrear la ruta que seguiría un paquete IP hasta algún host de Internet lanzando paquetes de sondeo con un TTL (tiempo de vida) pequeño y luego escuchando una respuesta ICMP "tiempo excedido" de una puerta de enlace. Iniciamos nuestros sondeos con un TTL de uno y aumentamos de uno en uno hasta que obtenemos un ICMP "puerto inalcanzable" (o reinicio TCP), lo que significa que llegamos al "host", o alcanzamos un máximo (que por defecto es 30 saltos). Se envían tres sondeos (por defecto) en cada configuración de TTL y se imprime una línea que muestra el TTL, la dirección de la puerta de enlace y el tiempo de ida y vuelta de cada sondeo. La dirección puede ir seguida de información adicional cuando se solicita. Si las respuestas de los sondeos provienen de diferentes puertas de enlace, se imprimirá la dirección de cada sistema que responda. Si no hay respuesta dentro de un tiempo determinado, se imprimirá un "*" (asterisco) para ese sondeo.

Después del tiempo de viaje, se puede imprimir una anotación adicional: !H, !N o !P (host, red o protocolo inalcanzable), !S (ruta de origen fallida), !F (fragmentación necesaria), !X (comunicación prohibida administrativamente), !V (violación de precedencia de host), !C (límite de precedencia en efecto), o !<num> (código de inalcanzabilidad ICMP <num>). Si casi todos los sondeos resultan en algún tipo de inalcanzabilidad, traceroute se dará por vencido y saldrá.

No queremos que el host de destino procese los paquetes de sondeo UDP, por lo que el puerto de destino se establece en un valor improbable (puedes cambiarlo con el flag -p). No hay tal problema para el rastreo ICMP o TCP (para TCP usamos la técnica de medio abierto, que evita que nuestros sondeos sean vistos por las aplicaciones en el host de destino).

En el entorno de red moderno, los métodos tradicionales de traceroute no siempre son aplicables, debido al uso generalizado de firewalls. Dichos firewalls filtran los puertos UDP "improbables", o incluso los ecos ICMP. Para solucionar esto, se implementan algunos métodos de rastreo adicionales (incluido tcp), consulte LISTA DE MÉTODOS DISPONIBLES a continuación. Dichos métodos intentan utilizar un protocolo y puerto de origen/destino específicos, para eludir los firewalls (para ser vistos por los firewalls solo como el inicio de un tipo de sesión de red permitida).

OPCIONES

--help
Imprime información de ayuda y sale.
-4, -6
Fuerza explícitamente el rastreo IPv4 o IPv6. Por defecto, el programa intentará resolver el nombre dado y elegirá el protocolo apropiado automáticamente. Si la resolución de un nombre de host devuelve direcciones IPv4 e IPv6, traceroute utilizará IPv4.
-I, --icmp
Utiliza ECO ICMP para los sondeos
-T, --tcp
Utiliza SYN TCP para los sondeos
-d, --debug
Habilita la depuración a nivel de socket (cuando el kernel de Linux lo soporta)
-F, --dont-fragment
No fragmentes los paquetes de sondeo. (Para IPv4 también establece el bit DF, que indica a los routers intermedios que tampoco fragmenten remotamente).

Variando el tamaño del paquete de sondeo con el parámetro de línea de comandos packet_len, puedes obtener manualmente información sobre la MTU de los saltos individuales de la red. La opción --mtu (ver más abajo) intenta hacer esto automáticamente.

Tenga en cuenta que las características de no fragmentación (como -F o --mtu) solo funcionan correctamente a partir del kernel de Linux 2.6.22. Antes de esa versión, IPv6 siempre se fragmentaba, IPv4 podía usar solo la MTU final descubierta (de la caché de ruta), que puede ser menor que la MTU real de un dispositivo.

-f first_ttl, --first=first_ttl
Especifica con qué TTL empezar. Por defecto es 1.
-g gateway, --gateway=gateway
Indica a traceroute que agregue una opción de enrutamiento de origen IP al paquete saliente que le indica a la red que enrute el paquete a través de la gateway especificada (la mayoría de los routers han deshabilitado el enrutamiento de origen por razones de seguridad). En general, se permiten varias gateways (separadas por comas). Para IPv6, se permite el formato de num,dir..., donde num es un tipo de encabezado de ruta (por defecto es el tipo 2). Tenga en cuenta que el encabezado de ruta tipo 0 ahora está obsoleto (rfc5095).
-i interface, --interface=interface
Especifica la interfaz a través de la cual traceroute debe enviar paquetes. Por defecto, la interfaz se selecciona según la tabla de enrutamiento.
-m max_ttl, --max-hops=max_ttl
Especifica el número máximo de saltos (valor máximo de tiempo de vida) que traceroute sondeará. El valor predeterminado es 30.
-N squeries, --sim-queries=squeries
Especifica el número de paquetes de sondeo enviados simultáneamente. Enviar varios sondeos concurrentemente puede acelerar considerablemente traceroute. El valor predeterminado es 16.
Tenga en cuenta que algunos routers y hosts pueden utilizar la limitación de velocidad ICMP. En tal situación, especificar un número demasiado grande puede provocar la pérdida de algunas respuestas.
-n
No intente mapear direcciones IP a nombres de host al mostrarlos.
-p port, --port=port
Para rastreo UDP, especifica el puerto de destino base que utilizará traceroute (el número de puerto de destino se incrementará con cada sondeo).
Para rastreo ICMP, especifica el valor inicial de secuencia ICMP (también incrementado con cada sondeo).
Para TCP y otros, especifica solo el puerto de destino (constante) al que conectarse.
-t tos, --tos=tos
Para IPv4, establece el valor de Tipo de Servicio (TOS) y Precedencia. Los valores útiles son 16 (baja latencia) y 8 (alto rendimiento). Tenga en cuenta que para usar algunos valores de precedencia TOS, debe ser superusuario.
Para IPv6, establece el valor de Control de Tráfico.
-l flow_label, --flowlabel=flow_label
Utiliza la etiqueta de flujo especificada para los paquetes IPv6.
-w max[,here,near], --wait=max[,here,near]
Determina cuánto tiempo esperar por una respuesta a un sondeo.

Hay tres valores (en general) de punto flotante separados por coma (o una barra). Max especifica el tiempo máximo (en segundos, por defecto 5.0) para esperar, en cualquier caso.

DESCRIPCIÓN

This utility is intended to trace the route packets take to network host. The trace is accomplished by sending packets to the host and observing the Intermediate Syntactic Segmentation.

This utility may be run on an unprivileged host, but it requires root privileges to use some of the more advanced methods. Those are specified with a capital letter in the list below.

SINOPSIS

traceroute [Opción ...] host [paquete ...]

OPCIONES

-F
Don't Fragment packets. Sets the Don't Fragment flag in the IP header. This is set by default for the tcp and syn methods.
-f first_ttl
Sets the first hop value to try. Default is 1.
-I
Use ICMP Echo protocol instead of UDP probes. Use of this requires root privileges.
-i iface
Interface to use. By default, the interface is chosen for the destination host.
-l len
Sets the length of the payload message. Default is 64 bytes.
-m max_ttl
Sets the max number of hops to go. Default is 30.
-N num
Sets the number of probes per hop. Default is 3.
-n
Do not translate addresses to hostnames. If the data is numeric, it is just printed as is.
-O
Print tcp flags and supported options of final tcp replies when the target host is reached. Also determines whether an application listens on the port. Supported tcp options are all that can be set by -T -O, ie. mss, sack, timestamps, window_scaling and fastopen, with the similar output format (a value for mss and just presence for others).
-p port
For the udp method, use port as the destination port. For the tcp method, use port as the destination port. Default is 33434.
-q num
Sets the number of seconds to wait for a response to a probe. Default is 5.
-R
Use ICMP timestamp messages instead of UDP probes. Use of this requires root privileges.
-r
Set the IP_RECVDSTADDR socket option to receive destination-specific routing information. Use of this requires root privileges.
-s addr
Sets the source IP address to use for outgoing packets. Use of this requires root privileges.
-T tos
Sets the Type Of Service field in the IP header to tos. Default is 0.
-w usec
Sets the timeout, in microseconds, to wait for a response to a probe. Default is 5 seconds.
-z secs
Sets the number of seconds to pause between sending probes to consecutive hops. Default is 0.

LISTA DE MÉTODOS DISPONIBLES

The following methods are available:

-U
Use UDP datagrams for probes. The destination port is the specified port number, or 53 (dns) if not specified. By default, this method is used for unprivileged users.
-D
Use DCCP Request packets for probes (rfc4340). The default destination port is 33434.
-I
Use ICMP Echo protocol for probes. Use of this requires root privileges.
-T
Use TCP SYN packets for probes. This method uses the same "half-open technique" as used for the tcp method. The default destination port is 33434.
-P proto
Send raw packets of protocol proto. No protocol-specific headers are used, just IP header only. Implies -N 1 -w 5.
info
Print tcp flags and supported options of final tcp replies when the target host is reached. Allows to determine whether an application listens the port and other useful things. Supported tcp options are all that can be set by -T -O, ie. mss, sack, timestamps, window_scaling and fastopen, with the similar output format (a value for mss and just presence for others).

Default options are syn,sysctl.

tcpconn

An initial implementation of tcp method, simple using connect(2) call, which does full tcp session opening. Not recommended for normal use, because a destination application is always affected (and can be confused).

udp        -U

Use udp datagram with constant destination port (default 53, dns).
Intended to bypass firewall as well.

Note, that unlike in tcp method, the correspond application on the destination host always receive our probes (with random data), and most can easily be confused by them. Most cases it will not respond to our packets though, so we will never see the final hop in the trace. (Fortunately, it seems that at least dns servers replies with something angry).

This method is allowed for unprivileged users.

udplite    -UL

Use udplite datagram for probes (with constant destination port, default 53).

This method is allowed for unprivileged users.
Options:

coverage=num
Set udplite send coverage to num.

dccp    -D

Use DCCP Request packets for probes (rfc4340).

This method uses the same "half-open technique" as used for TCP. The default destination port is 33434.

Options:

service=num
Set DCCP service code to num (default is 1885957735).

raw        -P proto

Send raw packet of protocol proto.
No protocol-specific headers are used, just IP header only.
Implies -N 1 -w 5.
Options:

protocol=proto
Use IP protocol proto (default 253).

NOTAS

To speed up work, normally several probes are sent simultaneously. On the other hand, it creates a "storm of packages", especially in the reply direction. Routers can throttle the rate of icmp responses, and some of replies can be lost. To avoid this, decrease the number of simultaneous probes, or even set it to 1 (like in initial traceroute implementation), i.e. -N 1

The final (target) host can drop some of the simultaneous probes, and might even answer only the latest ones. It can lead to extra "looks like expired" hops near the final hop. We use a smart algorithm to auto-detect such a situation, but if it cannot help in your case, just use -N 1 too.

For even greater stability you can slow down the program's work by -z option, for example use -z 0.5 for half-second pause between probes.

To avoid an extra waiting, we use adaptive algorithm for timeouts (see -w option for more info). It can lead to premature expiry (especially when response times differ at times) and printing "*" instead of a time. In such a case, switch this algorithm off, by specifying -w with the desired timeout only (for example, -w 5).

If some hops report nothing for every method, the last chance to obtain something is to use ping -R command (IPv4, and for nearest 8 hops only).
