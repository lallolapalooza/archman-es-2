TRAFFIC_REPLAY(7) Comandos de Usuario TRAFFIC_REPLAY(7)

NOMBRE

traffic_replay - Herramienta de generación de tráfico de Samba.

SINOPSIS

traffic_replay [-F, --fixed-password <contraseña-de-prueba>] [-T, --packets-per-second <número>] [-S, --scale-traffic <escalar por factor>] [-r, --replay-rate <escalar por factor>] [-D, --duration <segundos>] [--traffic-summary <archivo-de-salida>] [-I, --instance-id <id>] [-K, --prefer-kerberos] [-B, --badpassword-frequency <frecuencia>] [--dns-rate <tasa>] [-t, --timing-data <archivo>] [--random-seed <semilla>] [-U, --username usuario] [--password <contraseña>] [-W --workgroup <grupo-de-trabajo>] [--realm <dominio>] [-s, --config-file <archivo>] [-k, --kerberos <kerberos>] [--ipaddress <dirección>] [-P, --machine-pass] [--option <opción>] [-d, --debuglevel <nivel-de-depuración>] [--conversation-persistence <0-1>] [--latency-timeout <segundos>] [--stop-on-any-error] {archivo-resumen} {nombre-host-dns}

traffic_replay [-G, --generate-users-only] [-F, --fixed-password <contraseña-de-prueba>] [-n, --number-of-users <usuarios-totales>] [--number-of-groups <grupos-totales>] [--average-groups-per-user <número-promedio>] [--group-memberships <membresías-totales>] [--max-members <tamaño-de-grupo>] {nombre-host-dns}

traffic_replay {-c|--clean-up} {nombre-host-dns}

traffic_replay [-h, --help] [-V, --version]

DESCRIPCIÓN

Esta herramienta forma parte del conjunto de herramientas de samba(7).

Esta herramienta genera tráfico para medir el rendimiento de un DC de Samba y para probar hasta qué punto Samba puede escalar a medida que aumenta el tamaño de una red. Puede simular múltiples hosts diferentes realizando múltiples tipos de solicitudes a un DC.

Esta herramienta está diseñada para ejecutarse contra un DC de prueba dedicado (en lugar de un DC activo que está manejando tráfico de red real).

Tenga en cuenta que un efecto secundario de la ejecución de esta herramienta es que se crearán cuentas de usuario en el DC, para probar diversas operaciones de Samba. Dado que la creación de cuentas puede llevar mucho tiempo, estos usuarios permanecerán en el DC por defecto. Para eliminar estas cuentas, use la opción --clean-up.

OPCIONES

-h|--help

Imprime un resumen de las opciones de la línea de comandos.

archivo-resumen

Archivo que contiene el tráfico de red a reproducir. Debe ser un modelo de tráfico (generado por traffic_learner). Basándose en este archivo, esta herramienta generará 'conversaciones' que representan la actividad de Samba entre un host de red y el DC.

nombre-host-dns

El nombre de host DNS completo del DC que se está probando. La actividad de Samba en el archivo-resumen se replicará y dirigirá a este DC. Se recomienda que utilice un DC dedicado para las pruebas y no intente ejecutar esta herramienta contra un DC que esté procesando tráfico de red en vivo.

-F|--fixed-password <contraseña-de-prueba>

Se crean usuarios de prueba cuando se ejecuta esta herramienta, para que se puedan imitar actividades reales de Samba, como la autorización de usuarios. Esta opción especifica la contraseña que se utilizará para cualquier usuario de prueba que se cree.

Tenga en cuenta que los usuarios creados por esta herramienta permanecerán en el DC hasta que ejecute la opción --clean-up. Por lo tanto, la opción fixed-password debe ser la misma cada vez que se ejecute la herramienta, de lo contrario, los usuarios de prueba no se autenticarán correctamente.

random-seed

Un número para inicializar el generador de números aleatorios. Cuando se genera tráfico a partir de un archivo modelo, use esta opción para mantener el tráfico consistente entre múltiples ejecuciones de prueba. Esto le permite comparar el rendimiento de Samba entre diferentes versiones.

Opciones del Modelo de Tráfico

Cuando el archivo-resumen es un modelo de tráfico (producido por traffic_learner), use estas opciones para alterar el tráfico que se genera.

-D|--duration <segundos>

Especifica la duración aproximada en segundos para generar tráfico. El valor predeterminado es 60 segundos.

-T|--packets-per-second <número>

Genera este número de paquetes por segundo, independientemente de la tasa de tráfico de la muestra en la que se basó el modelo. No se puede utilizar con -S.

-S|--scale-traffic <factor>

Aumenta el número de conversaciones en este factor, en relación con la muestra de tráfico original en la que se basó el modelo. Esta opción no afectará la velocidad a la que se envían los paquetes (que todavía se basa en el modelo de tráfico), pero hará que se reproduzcan más conversaciones. No se puede combinar con -T, que establece la tasa de tráfico de una manera diferente.

-r|--replay-rate <factor>

Reproduce el tráfico más rápido por este factor. Esta opción no afectará el número de paquetes enviados, pero los comprimirá en menos conversaciones, lo que puede reducir el uso de recursos.

--traffic-summary <archivo-de-salida>

En lugar de reproducir un modelo de tráfico, esta opción genera un archivo de resumen de tráfico basado en el tráfico que se enviaría. El uso de un modelo de tráfico le permite escalar la tasa de paquetes y el número de paquetes enviados. Sin embargo, el uso de un modelo de tráfico introduce cierta aleatoriedad en la generación de tráfico. Por lo tanto, ejecutar el mismo comando traffic_replay varias veces utilizando un archivo modelo puede dar lugar a algunas diferencias en el tráfico real enviado. Sin embargo, ejecutar el mismo comando traffic_replay varias veces con un archivo de resumen de tráfico siempre resultará en el mismo tráfico enviado.

Para tomar mediciones de rendimiento durante varias ejecuciones de prueba, se recomienda usar esta opción y reproducir el tráfico desde un archivo de resumen de tráfico, o usar la opción --random-seed.

--stop-on-any-error

Cualquier error del cliente provoca la detención de toda la ejecución.

--conversation-persistence <0-1>

La terminación de la conversación (según lo decidido por el modelo) se reinterpreta como una pausa larga con esta probabilidad.

--latency-timeout <segundos>

Espera este tiempo al final de la ejecución para los paquetes de respuesta pendientes. El número de conversaciones que no han terminado al final del tiempo de espera es una métrica de fallo.

--generate-users-only

Añade usuarios/grupos adicionales en el DC para aumentar el tamaño de la DB. Por defecto, esta herramienta crea automáticamente usuarios de prueba que se mapean a las conversaciones de tráfico que se generan. Esta opción permite crear usuarios adicionales además de estos. Tenga en cuenta que estos usuarios adicionales pueden no ser realmente utilizados para la generación de tráfico; la generación de tráfico todavía se basa en el número de conversaciones del archivo modelo/resumen.

La generación de un gran número de usuarios puede llevar mucho tiempo, por lo que esta opción permite que esto se haga solo una vez.

Tenga en cuenta que los usuarios creados permanecerán en el DC hasta que la herramienta se ejecute con la opción --clean-up. Esto significa que es mejor asignar membresías de grupo solo una vez, es decir, ejecutar --clean-up antes de asignar una asignación diferente de membresías de grupo.

-n|--number-of-users <usuarios-totales>

Especifica el número total de usuarios de prueba a crear (excluyendo cualquier cuenta de máquina requerida para el tráfico). Tenga en cuenta que estos usuarios adicionales simplemente pueblan la DB del DC; el tráfico de usuario real generado todavía se basa en el archivo-resumen.

--number-of-groups <grupos-totales>

Crea el número especificado de grupos, para asignarlos a los usuarios de prueba. Tenga en cuenta que los usuarios no se asignan automáticamente a los grupos; use --average-groups-per-user o --group-memberships para hacerlo.

--average-groups-per-user <grupos-promedio>

Asigna aleatoriamente los usuarios de prueba a los grupos de prueba creados. Las membresías de grupo se distribuyen de modo que el promedio general de grupos de los que un usuario es miembro coincida con este número. Algunos usuarios pertenecerán a más grupos y otros a menos. Esta opción es incompatible con la opción --group-membership.

--group-memberships <membresías-totales>

Asigna aleatoriamente los usuarios de prueba a los grupos de prueba creados. Las membresías de grupo se distribuyen de modo que el número total de grupos de los que un usuario es miembro, en todos los usuarios, coincida con este número. Por ejemplo, con 100 usuarios
y 10 grupos, --group-memberships=300 asignaría a un usuario a 3 grupos en promedio. Algunos usuarios pertenecerán a más grupos y otros a menos, pero el total de todos los atributos vinculados de miembros sería 300. Esta opción es incompatible con la opción --average-groups-per-user.

--max-members <tamaño del grupo>

Limita el grupo más grande a este tamaño, incluso si las otras opciones de grupo indican lo contrario.

--clean-up

Limpia los usuarios y grupos que fueron creados por ejecuciones anteriores de esta herramienta. Se recomienda limpiar siempre después de ejecutar la herramienta.

-I|--instance-id <id>

Utiliza esta opción para ejecutar múltiples instancias de la herramienta en el mismo DC al mismo tiempo. Esto añade un prefijo a los usuarios de prueba generados para mantenerlos separados en el DC.

-K|--prefer-kerberos

Utiliza Kerberos para autenticar a los usuarios de prueba.

-B|--badpassword-frequency <frecuencia>

Utiliza esta opción para simular intentos de autenticación de usuarios con una contraseña incorrecta.

--dns-rate <tasa>

Aumenta la tasa a la que se envían los paquetes DNS.

-t|--timing-data <archivo>

Escribe datos de temporización adicionales en el archivo especificado. Esto se utiliza principalmente para opciones de informes, como la generación de gráficos.

Opciones Comunes de Samba

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor por defecto si este parámetro no se especifica es 1 para las aplicaciones cliente.

Cuanto mayor sea este valor, más detalle se registrará en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias serias. El nivel 1 es un nivel razonable para el funcionamiento diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados solo para uso de desarrolladores y generan ENORMES cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro nivel de registro en el archivo /etc/samba/smb.conf.

--debug-stdout

Redirigirá la salida de depuración a STDOUT. Por defecto, todos los clientes registran en STDERR.

--configfile=<archivo de configuración>

El archivo especificado contiene los detalles de configuración requeridos por el cliente. La información en este archivo puede ser general para cliente y servidor o solo proporcionar detalles específicos del cliente, como opciones como client smb encrypt. Consulte /etc/samba/smb.conf para obtener más información. El nombre del archivo de configuración por defecto se determina en tiempo de compilación.

--option=<nombre>=<valor>

Establece la opción de smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluyen un espacio, encierre todo --option=name=value entre comillas.

--realm=REALM

Establece el nombre del reino

-V|--version

Imprime el número de versión del programa.

Opciones de Credenciales

--simple-bind-dn=DN

DN a utilizar para una vinculación simple

--password=CONTRASEÑA

Contraseña

-U USUARIO|--username=USUARIO

Nombre de usuario

-W GRUPO_TRABAJO|--workgroup=GRUPO_TRABAJO

Grupo de trabajo

--use-kerberos=deseado|requerido|apagado

Este parámetro determina si las herramientas cliente de Samba intentarán autenticarse usando Kerberos. Para la autenticación Kerberos, debe usar nombres DNS en lugar de direcciones IP al conectarse a un servicio. Por defecto, las herramientas cliente de Samba intentarán usar la caché de credenciales Kerberos por defecto (ccache). En caso de que la ccache no exista o se haya especificado la opción -U|--user, los clientes pedirán introducir una contraseña y obtendrán un ticket Kerberos (kinit) por usted. Si desea utilizar una caché de credenciales Kerberos alternativa, utilice la opción --use-krb5-ccache.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro client use kerberos en el archivo /etc/samba/smb.conf.

--ipaddress=DIRECCION_IP

Dirección IP del servidor

-P|--machine-pass

Utiliza la contraseña de cuenta de máquina almacenada.

OPERACIONES

Generación de un archivo de resumen de tráfico

Para utilizar esta herramienta, necesita un archivo de resumen de tráfico o un archivo de modelo de tráfico. Para generar cualquiera de estos archivos, necesitará una captura de paquetes de actividad real de Samba en su red.

Utilice Wireshark para realizar una captura de paquetes de su red del tráfico que desea generar. Por ejemplo, si desea simular muchos usuarios iniciando sesión, realice una captura a las 8:30 a.m. cuando los usuarios están iniciando sesión.

A continuación, debe convertir su captura de paquetes en un archivo de resumen de tráfico, utilizando traffic_summary.pl. Básicamente, esto elimina cualquier información sensible de la captura y resume qué tipo de paquete se envió y cuándo.

Consulte la ayuda de traffic_summary.pl --help para obtener más detalles, pero el comando básico se verá algo así:

tshark -r capture.pcapng -T pdml | traffic_summary.pl > traffic-summary.txt

Recreación de un archivo de resumen de tráfico

Una vez que tenga un archivo de resumen de tráfico, puede usarlo para generar tráfico. La herramienta traffic_replay recibe el archivo de resumen de tráfico, junto con el nombre de host DNS completo del DC que se está probando. También debe proporcionar algunas credenciales de usuario y, posiblemente, el reino y el grupo de trabajo de Samba (aunque el reino y el grupo de trabajo pueden determinarse automáticamente, por ejemplo, desde el archivo /etc/smb.conf, si está presente). Por ejemplo:

traffic_replay traffic-summary.txt mi-dc.samdom.example.com -UAdmin%contraseña -W samdom --realm=samdom.example.com --fixed-password=blahblah123!

Esto simplemente regenera la actividad de Samba vista en el resumen de tráfico. El tráfico se agrupa en 'conversaciones' entre un host y el DC. Se crea una cuenta de usuario y una cuenta de máquina en el DC para cada conversación, para permitir que el inicio de sesión y otras operaciones tengan éxito. El script genera los mismos tipos de paquetes que los vistos en el resumen.

La creación de usuarios puede ser un proceso que consume mucho tiempo, especialmente si se generan muchas conversaciones. Para ahorrar tiempo, los usuarios de prueba permanecen en el DC por defecto. Necesitará ejecutar la opción --clean-up para eliminarlos, una vez que haya terminado de generar tráfico. Debido a que los mismos usuarios de prueba se utilizan en múltiples ejecuciones de la herramienta, se debe usar una contraseña consistente para estos usuarios, especificada por la opción --fixed-password.

El beneficio de esta herramienta sobre el simple uso de tcprelay es que el tráfico generado es independiente de cualquier red específica. No se requiere ninguna configuración previa en el DC de prueba. El tráfico ya no contiene detalles sensibles, por lo que el resumen de tráfico podría compartirse potencialmente con otros desarrolladores de Samba.

Sin embargo, recrear un resumen de tráfico directamente tiene ciertas limitaciones en cuanto a lo que realmente se puede hacer. Un enfoque más flexible es generar el tráfico utilizando un archivo de modelo.

Generación de un archivo de modelo de tráfico

Para crear un archivo de modelo de tráfico, simplemente pase el archivo de resumen de tráfico al script traffic_learner. Por ejemplo:

traffic_learner traffic-summary.txt -o traffic-model.txt

Esto genera un modelo de la actividad de Samba en su red. Este archivo de modelo ahora se puede usar para generar tráfico.

Recreación del archivo de modelo de tráfico

La generación de paquetes utilizando un archivo de modelo de tráfico utiliza el mismo comando que un archivo de resumen de tráfico, por ejemplo:

traffic_replay traffic-model.txt mi-dc.samdom.example.com -UAdmin%contraseña

Por defecto, esto generará 60 segundos de tráfico basados en el modelo. Puede especificar un tiempo mayor usando el parámetro --duration.

El tráfico generado es una aproximación de lo que se vio en la captura de red. La generación de tráfico implica cierta aleatoriedad, por lo que ejecutar el mismo comando varias veces puede resultar en un tráfico ligeramente diferente (aunque puede evitar esto especificando la opción --random-seed).

Además de cambiar la duración de ejecución del modelo, también puede cambiar cuántas conversaciones se generan y a qué velocidad se reproduce el tráfico. Para duplicar aproximadamente el número de conversaciones que se reproducen, use --scale-traffic=2 o para reducirlo aproximadamente a la mitad use --scale-traffic=0.5. Para duplicar aproximadamente la velocidad a la que se reproducen las conversaciones, use --replay-rate=2, o para reducirla a la mitad use --replay-rate=0.5

Por ejemplo, para generar aproximadamente 10 veces la cantidad de tráfico vista durante un período de dos minutos (basado en la captura de red), use:

traffic_replay traffic-model.txt mi-dc.samdom.example.com -UAdmin%contraseña --fixed-password=blahblah123! --scale-traffic=10 --duration=120

Escalar el número de usuarios

El rendimiento de un DC de Samba que ejecuta un pequeño subconjunto de usuarios de prueba será diferente al de un DC de Samba completamente poblado que se ejecuta en una red. A medida que aumenta el número de usuarios, aumenta el tamaño de la base de datos y una base de datos muy grande funcionará peor que una base de datos más pequeña.

Para aumentar el tamaño de la base de datos de Samba, esta herramienta también puede crear usuarios y grupos adicionales. Estos usuarios adicionales son básicamente 'relleno' para la base de datos. En realidad, no se utilizarán para generar tráfico, pero pueden ralentizar la autenticación de los usuarios de prueba.

Por ejemplo, para poblar la base de datos con 5000 usuarios adicionales (tenga en cuenta que esto llevará un tiempo), use el comando:

traffic_replay mi-dc.samdom.example.com -UAdmin%contraseña --generate-users-only --fixed-password=blahblah123! --number-of-users=5000

También puede crear grupos y asignar usuarios a grupos. Los usuarios pueden asignarse aleatoriamente a grupos: esto incluye a los usuarios adicionales creados, así como a los usuarios que se mapean a las conversaciones. Utilice --average-groups-per-user o --group-memberships para especificar cuántas membresías de grupo se asignarán a los usuarios de prueba

traffic_replay(7) — Samba — The Software Reimplementation of the SMB/CIFS Network Protocol

NAME

traffic_replay - Replay recorded traffic against a Samba server.

SYNOPSIS

traffic_replay traffic-model.txt server [-Uuser] [-Sshares] [--password=password] [--fixed-password=password] [-wworkers] [-nnumber] [--generate-users-only] [--generate-groups-only] [--number-of-groups=numgroups] [--average-groups-per-user=avg] [--number-of-users=numusers] [--number-of-groups=numgroups]

DESCRIPTION

The traffic_replay utility is used to replay captured network traffic against a Samba server. This is useful for testing the performance and correctness of Samba under realistic load conditions.

It takes a traffic model file (traffic-model.txt) and the target server's hostname or IP address (server) as input. The traffic model file describes the user actions and network operations to be replayed.

OPTIONS

-U user
The username to use for authenticating to the Samba server. If not provided, the current user's username is used.
-S shares
A comma-separated list of shares to connect to. If not provided, all shares on the server will be used.
--password=password
The password for the user specified with -U. This option is deprecated and --fixed-password should be used instead.
--fixed-password=password
The password to use for all users created during the replay. This is useful when you want to simulate multiple users with the same password.
-w workers
The number of worker threads to use for replaying traffic. Defaults to the number of CPU cores.
-n number
The number of times to replay the recorded traffic. Defaults to 1.
--generate-users-only
Generate only the users specified in the traffic model, without replaying any traffic.
--generate-groups-only
Generate only the groups specified in the traffic model, without replaying any traffic.
--number-of-groups=numgroups
Specifies the total number of groups to generate. This option is used in conjunction with user and group generation.
--average-groups-per-user=avg
Specifies the average number of groups each user should belong to when generating users and groups.
--number-of-users=numusers
Specifies the total number of users to generate. This option is used in conjunction with user and group generation.

OPERATIONS

The traffic_replay command can be used to generate users and groups for testing purposes. This is particularly useful when you need to create a large number of test users and assign them to various groups without performing actual network operations.

For example, to assign the users in the replayed conversations into 10 groups on average, use a command like:

traffic_replay traffic-model.txt my-dc.samdom.example.com -UAdmin%password --fixed-password=blahblah123! --generate-users-only --number-of-groups=25 --average-groups-per-user=10

The users created by the test will have names like STGU-0-xyz. The groups generated have names like STGG-0-xyz.
