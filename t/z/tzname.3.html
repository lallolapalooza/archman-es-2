tzset(3) Manual de Funciones de Biblioteca tzset(3)

NOMBRE

tzset, tzname, timezone, daylight - inicializar información de conversión horaria

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <time.h>
void tzset(void);
extern char *tzname[2];
extern long timezone;
extern int daylight;
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

tzset():

    _POSIX_C_SOURCE

tzname:

    _POSIX_C_SOURCE

timezone, daylight:

    _XOPEN_SOURCE
        || /* glibc >= 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE

DESCRIPCIÓN

La función tzset() inicializa la variable tzname a partir de la variable de entorno TZ. Esta función es llamada automáticamente por las otras funciones de conversión horaria que dependen de la zona horaria. En un entorno similar a System-V, también establecerá las variables timezone (segundos al Oeste de UTC) y daylight (a 0 si esta zona horaria no tiene reglas de horario de verano, o a distinto de cero si hay un momento, pasado, presente o futuro en el que se aplica el horario de verano).

La función tzset() inicializa estas variables a valores no especificados si esta zona horaria es una zona horaria geográfica como "America/New_York" (ver más abajo).

Si la variable TZ no aparece en el entorno, se utiliza la zona horaria del sistema. La zona horaria del sistema se configura copiando o enlazando un archivo con formato tzfile(5) a /etc/localtime. Una base de datos de zonas horarias de estos archivos puede encontrarse en el directorio de zonas horarias del sistema (ver la sección ARCHIVOS más abajo).

Si la variable TZ aparece en el entorno, pero su valor está vacío, o su valor no se puede interpretar usando ninguno de los formatos especificados a continuación, entonces se utiliza el Tiempo Universal Coordinado (UTC).

Un valor no vacío de TZ puede tener uno de dos formatos, cualquiera de los cuales puede ir precedido por dos puntos que se ignoran. El primer formato es una cadena de caracteres que representa directamente la zona horaria a utilizar:


std offset[dst[offset][,start[/time],end[/time]]]

No hay espacios en la especificación. La cadena std especifica una abreviatura para la zona horaria y debe tener tres o más caracteres alfabéticos. Cuando se encierra entre los signos de menor que (<) y mayor que (>), el conjunto de caracteres se expande para incluir el signo más (+), el signo menos (-) y dígitos. La cadena offset sigue inmediatamente a std y especifica el valor de tiempo que se añadirá a la hora local para obtener el Tiempo Universal Coordinado (UTC). El offset es positivo si la zona horaria local está al oeste del Meridiano de Greenwich y negativo si está al este. La hora debe estar entre 0 y 24, y los minutos y segundos entre 00 y 59:


[+|-]hh[:mm[:ss]]

La cadena dst y el offset especifican el nombre y el desplazamiento para la zona horaria de ahorro de luz diurna correspondiente. Si se omite el desplazamiento, por defecto es una hora adelantada a la hora estándar.

Los campos start especifican cuándo entra en vigor el horario de verano y el campo end especifica cuándo se vuelve al horario estándar. Estos campos pueden tener los siguientes formatos:

Jn
Esto especifica el día juliano con n entre 1 y 365. Los días bisiestos no se cuentan. En este formato, el 29 de febrero no se puede representar; el 28 de febrero es el día 59 y el 1 de marzo es siempre el día 60.
n
Esto especifica el día juliano basado en cero con n entre 0 y 365. El 29 de febrero se cuenta en los años bisiestos.
Mm.w.d
Esto especifica el día d (0 <= d <= 6) de la semana w (1 <= w <= 5) del mes m (1 <= m <= 12). La semana 1 es la primera semana en la que ocurre el día d y la semana 5 es la última semana en la que ocurre el día d. El día 0 es un domingo.

Los campos time especifican cuándo, en la hora local actualmente en vigor, ocurre el cambio a la otra hora. Usan el mismo formato que offset excepto que la hora puede estar en el rango [-167,  167] para representar horas antes y después del día nombrado. Si se omite, el valor por defecto es 02:00:00.

Aquí hay un ejemplo para Nueva Zelanda, donde la hora estándar (NZST) está 12 horas por delante de UTC, y el horario de verano (NZDT), 13 horas por delante de UTC, se aplica desde el último domingo de septiembre, a la hora por defecto 02:00:00, hasta el primer domingo de abril a las 03:00:00.


TZ="NZST-12:00:00NZDT-13:00:00,M9.5.0,M4.1.0/3"

El segundo —o formato "geográfico"— especifica que la información de la zona horaria debe leerse de un archivo:


espec_archivo

La espec_archivo especifica un archivo en formato tzfile(5) del que leer la información de la zona horaria. Si espec_archivo no comienza con '/', la especificación del archivo es relativa al directorio de zonas horarias del sistema. Si el archivo especificado no se puede leer o interpretar, se utiliza el Tiempo Universal Coordinado (UTC); sin embargo, las aplicaciones no deben depender de valores aleatorios de espec_archivo que representen UTC, ya que los formatos de TZ pueden extenderse en el futuro.

Aquí hay un ejemplo, una vez más para Nueva Zelanda:


TZ="Pacific/Auckland"

ENTORNO

TZ
Si esta variable está establecida, su valor tiene prioridad sobre la zona horaria configurada en el sistema.
TZDIR
Si esta variable está establecida, su valor tiene prioridad sobre la ruta del directorio de la base de datos de zonas horarias configurada en el sistema.

ARCHIVOS

/etc/localtime
El archivo de zona horaria del sistema.
/usr/share/zoneinfo/
El directorio de la base de datos de zonas horarias del sistema.
/usr/share/zoneinfo/posixrules
Cuando una cadena TZ incluye una zona horaria dst sin nada que la siga, se utiliza este archivo para las reglas de inicio/fin. Está en formato tzfile(5). Por defecto, el Makefile de zoneinfo lo enlaza simbólicamente al tzfile de America/New_York.

Las ubicaciones de archivo estándar anteriores son las actuales, pero son configurables cuando se compila glibc.

tzname(3) - Linux manual page

NAME

tzname - time zone name

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <time.h>

extern char *tzname[2];

DESCRIPTION

The tzname array is a two-element array of pointers to characters, which is set by initialization functions such as tzset(3) to hold the time zone designation for standard time and daylight saving time, respectively. The first element (tzname[0]) is the standard time zone name (e.g., "EST"), and the second element (tzname[1]) is the daylight saving time zone name (e.g., "EDT").

These names are usually three-letter abbreviations.

ENVIRONMENT

The tzname array is affected by the TZ environment variable. If TZ is not set, the system's default time zone is used.

FILES

/etc/localtime

/usr/share/zoneinfo/

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

Interface Stability: Volatile
   See intro(2) for details on the stability of the interface described
   below.

STANDARDS

This function is generally a BSD extension, not specified by any POSIX or other standard.

HISTORY

The tzname variable appeared in 3.0BSD.

CAVEATS

The tzname variable is a global variable, and modifying it can have unintended side effects, especially in multithreaded applications. In multithreaded applications, code should instead obtain time zone offset and abbreviations from the tm_gmtoff and tm_zone members of the broken-down time structure tm(3type).

BUGS

Since this function does not report errors, there's no way to know if the value of TZ represents a valid time zone.

SEE ALSO

date(1), gettimeofday(2), time(2), ctime(3), getenv(3), tzfile(5), tzset(3)
