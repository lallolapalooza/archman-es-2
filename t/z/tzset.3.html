tzset(3) Manual de funciones de biblioteca tzset(3)

NOMBRE

tzset, tzname, timezone, daylight - inicializar información de conversión de zona horaria

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <time.h>
void tzset(void);
extern char *tzname[2];
extern long timezone;
extern int daylight;
Requisitos de macros de prueba de características para glibc (consulte feature_test_macros(7)):

tzset():

    _POSIX_C_SOURCE

tzname:

    _POSIX_C_SOURCE

timezone, daylight:

    _XOPEN_SOURCE
        || /* glibc >= 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE

DESCRIPCIÓN

La función tzset() inicializa la variable tzname a partir de la variable de entorno TZ. Esta función se llama automáticamente por las otras funciones de conversión de hora que dependen de la zona horaria. En un entorno similar a System-V, también establecerá las variables timezone (segundos al oeste de UTC) y daylight (a 0 si esta zona horaria no tiene reglas de horario de verano, o a un valor distinto de cero si existe un momento, pasado, presente o futuro en el que se aplica el horario de verano).

La función tzset() inicializa estas variables con valores no especificados si esta zona horaria es una zona horaria geográfica como "America/New_York" (ver más abajo).

Si la variable TZ no aparece en el entorno, se utiliza la zona horaria del sistema. La zona horaria del sistema se configura copiando o creando un enlace a un archivo en formato tzfile(5) en /etc/localtime. Una base de datos de zonas horarias de estos archivos puede ubicarse en el directorio de zonas horarias del sistema (ver la sección ARCHIVOS más abajo).

Si la variable TZ aparece en el entorno, pero su valor está vacío, o su valor no se puede interpretar utilizando alguno de los formatos especificados a continuación, se utiliza el Tiempo Universal Coordinado (UTC).

Un valor no vacío de TZ puede tener uno de dos formatos, cualquiera de los cuales puede ir precedido por dos puntos (:) que se ignoran. El primer formato es una cadena de caracteres que representa directamente la zona horaria a utilizar:


std offset[dst[offset][,start[/time],end[/time]]]

No hay espacios en la especificación. La cadena std especifica una abreviatura para la zona horaria y debe tener tres o más caracteres alfabéticos. Cuando se encierra entre los signos de menor que (<) y mayor que (>), el conjunto de caracteres se expande para incluir el signo más (+), el signo menos (-) y los dígitos. El offset inmediatamente sigue a std y especifica el valor de tiempo que se añadirá a la hora local para obtener el Tiempo Universal Coordinado (UTC). El offset es positivo si la zona horaria local está al oeste del Meridiano de Greenwich y negativo si está al este. La hora debe estar entre 0 y 24, y los minutos y segundos entre 00 y 59:


[+|-]hh[:mm[:ss]]

La cadena dst y el offset especifican el nombre y el desplazamiento para la zona horaria correspondiente de horario de verano. Si se omite el desplazamiento, se utiliza por defecto una hora adelantada respecto a la hora estándar.

Los campos start especifican cuándo entra en vigor el horario de verano y el campo end especifica cuándo se vuelve a la hora estándar. Estos campos pueden tener los siguientes formatos:

Jn
Esto especifica el día juliano con n entre 1 y 365. No se cuentan los días bisiestos. En este formato, el 29 de febrero no se puede representar; el 28 de febrero es el día 59, y el 1 de marzo es siempre el día 60.
n
Esto especifica el día juliano basado en cero con n entre 0 y 365. El 29 de febrero se cuenta en los años bisiestos.
Mm.w.d
Esto especifica el día d (0 <= d <= 6) de la semana w (1 <= w <= 5) del mes m (1 <= m <= 12). La semana 1 es la primera semana en la que ocurre el día d y la semana 5 es la última semana en la que ocurre el día d. El día 0 es un domingo.

Los campos time especifican cuándo, en la hora local actualmente en vigor, ocurre el cambio a la otra hora. Utilizan el mismo formato que offset excepto que la hora puede estar en el rango [-167, 167] para representar horas antes y después del día nombrado. Si se omite, el valor por defecto es 02:00:00.

Aquí hay un ejemplo para Nueva Zelanda, donde la hora estándar (NZST) está 12 horas por delante de UTC, y el horario de verano (NZDT), 13 horas por delante de UTC, se aplica desde el último domingo de septiembre, a la hora por defecto 02:00:00, hasta el primer domingo de abril a las 03:00:00.


TZ="NZST-12:00:00NZDT-13:00:00,M9.5.0,M4.1.0/3"

El segundo formato —o "geográfico"— especifica que la información de la zona horaria debe leerse de un archivo:


filespec

El filespec especifica un archivo en formato tzfile(5) del cual leer la información de la zona horaria. Si filespec no comienza con un '/', la especificación del archivo es relativa al directorio de zonas horarias del sistema. Si el archivo especificado no se puede leer o interpretar, se utiliza el Tiempo Universal Coordinado (UTC); sin embargo, las aplicaciones no deben depender de valores de filespec aleatorios que representen UTC, ya que los formatos de TZ pueden extenderse en el futuro.

Aquí hay un ejemplo, una vez más para Nueva Zelanda:


TZ="Pacific/Auckland"

ENTORNO

TZ
Si esta variable está establecida, su valor tiene prioridad sobre la zona horaria configurada en el sistema.
TZDIR
Si esta variable está establecida, su valor tiene prioridad sobre la ruta del directorio de la base de datos de zonas horarias configurada en el sistema.

ARCHIVOS

/etc/localtime
El archivo de zona horaria del sistema.
/usr/share/zoneinfo/
El directorio de la base de datos de zonas horarias del sistema.
/usr/share/zoneinfo/posixrules
Cuando una cadena TZ incluye una zona horaria dst sin nada que la siga, se utiliza este archivo para las reglas de inicio/fin. Está en formato tzfile(5). Por defecto, el Makefile de zoneinfo lo enlaza con el tzfile de America/New_York.

Las ubicaciones de archivo anteriores son las estándar actuales, pero son configurables cuando se compila glibc.

HISTORIA

tzset()
tzname
POSIX.1-1988, SVr4, 4.3BSD.
timezone
daylight
POSIX.1-2001 (XSI), SVr4, 4.3BSD.

4.3BSD tenía una función char *timezone(zone, dst) que devolvía el nombre de la zona horaria que correspondía a su primer argumento (minutos al oeste de UTC). Si el segundo argumento era 0, se utilizaba el nombre estándar, de lo contrario, la versión de horario de verano.

EATS'>ADVERTENCIAS

Debido a que los valores de tzname, timezone y daylight a menudo no se especifican, y acceder a ellos puede generar comportamiento indefinido en aplicaciones multihilo, el código debería obtener el desplazamiento de la zona horaria y las abreviaturas de los miembros tm_gmtoff y tm_zone de la estructura de tiempo desglosado tm(3type).

ERRORES

Dado que esta función no informa errores, no hay forma de saber si el valor de TZ representa una zona horaria válida.
