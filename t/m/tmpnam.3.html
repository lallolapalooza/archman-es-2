tmpnam(3) Manual de Funciones de Biblioteca tmpnam(3)

NOMBRE

tmpnam, tmpnam_r - crear un nombre para un archivo temporal

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdio.h>
[[deprecated]] char *tmpnam(char *s);
[[deprecated]] char *tmpnam_r(char *s);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

tmpnam_r()

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    Hasta e incluyendo glibc 2.19:
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

Nota: evite usar estas funciones; use mkstemp(3) o tmpfile(3) en su lugar.

La función tmpnam() devuelve un puntero a una cadena que es un nombre de archivo válido, y tal que un archivo con este nombre no existió en algún momento, por lo que los programadores ingenuos pueden pensar que es un nombre adecuado para un archivo temporal. Si el argumento s es NULL, este nombre se genera en un búfer estático interno y puede ser sobrescrito por la siguiente llamada a tmpnam(). Si s no es NULL, el nombre se copia al array de caracteres (de longitud al menos L_tmpnam) apuntado por s y se devuelve el valor s en caso de éxito.

La ruta del archivo creada tiene un prefijo de directorio P_tmpdir. (Tanto L_tmpnam como P_tmpdir se definen en <stdio.h>, al igual que TMP_MAX mencionado a continuación).

La función tmpnam_r() realiza la misma tarea que tmpnam(), pero devuelve NULL (para indicar un error) si s es NULL.

VALOR DE RETORNO

Estas funciones devuelven un puntero a un nombre de archivo temporal único, o NULL si no se puede generar un nombre único.

ERRORES

No se definen errores.

Para una explicación de los términos utilizados en esta sección, ver attributes(7).

HISTORIA

tmpnam()
SVr4, 4.3BSD, C89, POSIX.1-2001. Obsoleto en POSIX.1-2008.
tmpnam_r()
Solaris.

NOTAS

La función tmpnam() genera una cadena diferente cada vez que se llama, hasta TMP_MAX veces. Si se llama más de TMP_MAX veces, el comportamiento es definido por la implementación.

Aunque estas funciones generan nombres difíciles de adivinar, es posible que entre el momento en que se devuelve la ruta y el momento en que el programa la abre, otro programa cree esa ruta usando open(2), o la cree como un enlace simbólico. Esto puede conducir a agujeros de seguridad. Para evitar tales posibilidades, use la bandera O_EXCL de open(2) para abrir la ruta. O mejor aún, use mkstemp(3) o tmpfile(3).

Las aplicaciones portables que usan hilos no pueden llamar a tmpnam() con un argumento NULL si está definida _POSIX_THREADS o _POSIX_THREAD_SAFE_FUNCTIONS.

ERRORES DE PROGRAMACIÓN

Nunca use estas funciones. Use mkstemp(3) o tmpfile(3) en su lugar.

VER TAMBIÉN

mkstemp(3), mktemp(3), tempnam(3), tmpfile(3)
