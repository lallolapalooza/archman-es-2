tm(n) Comandos integrados de Tcl tm(n)

NOMBRE

tm - Instalaciones para localizar y cargar Módulos Tcl

SINOPSIS

::tcl::tm::path add ?ruta...?
::tcl::tm::path remove ?ruta...?
::tcl::tm::path list
::tcl::tm::roots rutas

DESCRIPCIÓN

Este documento describe las instalaciones para localizar y cargar Módulos Tcl (ver DEFINICIÓN DE MÓDULO para la definición de un Módulo Tcl). Los siguientes comandos son compatibles:

::tcl::tm::path add ?ruta...?
Las rutas se añaden al principio de la lista de rutas de módulos, en orden de aparición. Esto significa que el último argumento termina siendo la nueva cabecera de la lista.

El comando impone la restricción de que ninguna ruta puede ser un directorio ancestro de ninguna otra ruta en la lista. Si alguna de las nuevas rutas viola esta restricción, se generará un error antes de que se hayan añadido ninguna de las rutas. En otras palabras, si solo una ruta argumental viola la restricción, no se añadirá ninguna.

Si una ruta ya está presente tal cual, no se generará ningún error y no se tomará ninguna acción.

Las rutas se buscan más tarde en el orden de su aparición en la lista. A medida que se añaden al principio de la lista, se buscan en orden inverso de adición. En otras palabras, las rutas añadidas al final se miran primero.

::tcl::tm::path remove ?ruta...?
Elimina las rutas de la lista de rutas de módulos. El comando ignora silenciosamente todas las rutas que no están en la lista.
::tcl::tm::path list
Devuelve una lista que contiene todas las rutas de módulos registradas, en el orden en que se buscan los módulos.
::tcl::tm::roots rutas
Similar a path add, y superpuesto a ella. Este comando toma un único argumento que contiene una lista de rutas, las extiende con “tclX/site-tcl”, y “tclX/X.y”, para la versión mayor X del intérprete Tcl y la versión menor y menor o igual a la versión menor del intérprete, y añade el conjunto resultante de rutas a la lista de rutas a buscar.

Este comando es utilizado internamente por el sistema para configurar las rutas predeterminadas específicas del sistema.

El comando se ha expuesto para permitir que un sistema de compilación defina rutas raíz adicionales más allá de las descritas en este documento.

DEFINICIÓN DE MÓDULO

Un Módulo Tcl es un Paquete Tcl contenido en un único archivo, y ningún otro archivo requerido por él. Este archivo tiene que ser fuenteable. En otras palabras, un Módulo Tcl siempre se importa a través de:

source archivo_modulo

El comando load no se utiliza directamente. Esta restricción no es una limitación real, como algunos pueden creer. Desde la versión 8.4, el comando source de Tcl lee solo hasta el primer carácter ^Z. Esto nos permite combinar un script Tcl arbitrario con datos binarios arbitrarios en un solo archivo, donde el script procesa los datos adjuntos de cualquier manera que elija para importar y activar completamente el paquete.

El nombre de un archivo de módulo tiene que coincidir con la expresión regular:

([_[:alpha:]][:_[:alnum:]]*)-([[:digit:]].*)\.tm

Los primeros paréntesis de captura proporcionan el nombre del paquete, la segunda cláusula su versión. Además de coincidir con el patrón, el número de versión extraído no debe generar un error cuando se utiliza en el comando:

package vcompare $version 0

ENCONTRANDO MÓDULOS

El árbol de directorios para almacenar módulos Tcl está separado de otras partes del sistema de archivos y es independiente de auto_path.

Los Módulos Tcl se buscan en todos los directorios listados en el resultado del comando ::tcl::tm::path list. Esto se llama la Ruta de módulos. Ni las variables auto_path ni tcl_pkgPath se utilizan. Todos los directorios en la ruta de módulos tienen que obedecer una restricción:

Para dos directorios cualesquiera, ninguno es un directorio ancestro del otro.

Esto es necesario para evitar ambigüedades en los nombres de los paquetes. Si, por ejemplo, los dos directorios “foo/” y “foo/cool” estuvieran en la ruta, un paquete llamado cool::ice podría encontrarse a través de los nombres cool::ice o ice, este último potencialmente ocultando un paquete llamado ice, sin calificar.

Antes de que comience la búsqueda, el nombre del paquete solicitado se traduce a una ruta parcial, utilizando el siguiente algoritmo:

Todas las ocurrencias de “::” en el nombre del paquete se reemplazan por el carácter separador de directorio apropiado para la plataforma en la que nos encontramos. En Unix, por ejemplo, este es “/”.

Ejemplo:

El paquete solicitado es encoding::base64. La ruta parcial generada es “encoding/base64”.

Después de esta traducción, el paquete se busca en todas las rutas de módulos, combinándolas una por una, de la primera a la última con la ruta parcial para formar un patrón de búsqueda completo. Tenga en cuenta que el algoritmo de búsqueda rechaza todos los archivos donde el nombre del archivo no coincide con la expresión regular dada en la sección DEFINICIÓN DE MÓDULO. Para los archivos restantes, se generan scripts de provisión y se añaden a la base de datos de paquetes ifneeded.

El algoritmo recurre al manejador desconocido anterior cuando ninguno de los archivos de módulo encontrados satisface la solicitud. Si la solicitud fue satisfecha, se ignora la recursión.

Tenga en cuenta que los paquetes en forma de módulo no tienen control sobre los scripts de índice y provisión introducidos en la base de datos de paquetes para ellos. Para un archivo de módulo MF, el script de índice es siempre:

package ifneeded PNAME PVERSION [list source MF]

y el script de provisión incrustado en el anterior es:

source MF

Tanto el nombre del paquete PNAME como la versión del paquete PVERSION se extraen del nombre del archivo MF según la definición que aparece a continuación:

MF = /ruta_modulo/PNAME′-PVERSION.tm

Donde PNAME′ es la ruta parcial del módulo tal como se define en la sección ENCONTRANDO MÓDULOS, y se traduce a PNAME cambiando todos los separadores de directorio a “::”, y ruta_modulo es la ruta (de la lista de rutas a buscar) bajo la cual encontramos el archivo del módulo.

Tenga en cuenta también que aquí estamos creando una conexión entre los nombres de los paquetes y las rutas. Tcl distingue entre mayúsculas y minúsculas al comparar nombres de paquetes, pero existen sistemas de archivos que no lo hacen, como NTFS. Afortunadamente, estos sistemas de archivos almacenan la capitalización del nombre, a pesar de no utilizar la información al comparar.

Dados los puntos anteriores, permitimos que los nombres de los paquetes en módulos Tcl tengan mayúsculas y minúsculas mixtas, pero también exigimos que no haya colisiones al comparar nombres de forma insensible a mayúsculas y minúsculas. En otras palabras, si un paquete Foo se implementa en forma de Módulo Tcl, los paquetes como foo, fOo, etc. ya no están permitidos.

RUTAS PREDETERMINADAS

La lista predeterminada de rutas en la ruta de módulos se calcula mediante un tclsh de la siguiente manera, donde X es la versión mayor del intérprete Tcl y y es menor o igual a la versión menor del intérprete Tcl.

Todas las rutas predeterminadas se añaden a la ruta de módulos, incluso aquellas rutas que no existen. Las rutas inexistentes se filtran durante las búsquedas reales. Esto permite a un usuario crear una de las rutas buscadas cuando sea necesario y todas las aplicaciones en ejecución las recogerán automáticamente.

Las rutas se añaden en el orden en que se enumeran a continuación, y para las listas de rutas definidas por una variable de entorno en el orden en que se encuentran en la variable.

RUTAS ESPECÍFICAS DEL SISTEMA

file normalize [info library]/../tclX/X.y
En otras palabras, el intérprete buscará en un directorio especificado por su versión mayor y su menor

NAME

tm - Tcl Modules

SYNOPSIS

package require Tcl
tm _some_options_
tm_load _some_options_
tm_find _some_options_
tm_info _some_options_
tm_version _some_options_
tm_reload _some_options_

DESCRIPTION

The tm command is the Tcl Modules extension. It provides support for loading, finding, and managing Tcl packages.

Note: The tm command is deprecated as of Tcl 8.5 and has been replaced by the package command. However, it is still supported for backward compatibility.

MODULE DEFINITION

A Tcl module is a directory that contains Tcl scripts, compiled extensions, and other files that constitute a package. Modules are typically organized in a hierarchical structure.

FINDING MODULES

The tm command searches for modules in a set of predefined paths. These paths can be extended by the user through environment variables.

DEFAULT PATHS

file normalize [info library]/../tclX/
This path is used to find modules installed with Tcl. X is the major version number of Tcl.

For example, for Tcl 8.4, the paths searched are:

[info library]/../tcl8/

This definition assumes that a package defined for Tcl X.y can also be used by all interpreters which have the same major number X and a minor number greater than or equal to y.

file normalize [info library]/../tclX/X.y
Where X.y is the version of Tcl. This path is used to find modules that are specific to a particular version of Tcl. The minor version y is expected to be less than or equal to the minor version of the interpreter.

For example for Tcl 8.4 the paths searched are:

[info library]/../tcl8/8.4
[info library]/../tcl8/8.3
[info library]/../tcl8/8.2
[info library]/../tcl8/8.1
[info library]/../tcl8/8.0

This definition assumes that a package defined for Tcl X.y can also be used by all interpreters which have the same major number X and a minor number greater than y.

file normalize EXEC/tclX/X.y
Where EXEC is file normalize [info nameofexecutable]/../lib or file normalize [::tcl::pkgconfig get libdir,runtime]

This sets of paths is handled equivalently to the set coming before, except that it is anchored in EXEC_PREFIX. For a build with PREFIX = EXEC_PREFIX the two sets are identical.

SITE SPECIFIC PATHS

file normalize [info library]/../tclX/site-tcl
Note that this is always a single entry because X is always a specific value (the current major version of Tcl).

USER SPECIFIC PATHS

$::env(TCLX_y_TM_PATH)
A list of paths, separated by either : (Unix) or ; (Windows). This is user and site specific as this environment variable can be set not only by the user's profile, but by system configuration scripts as well.
$::env(TCLX.y_TM_PATH)
Same meaning and content as the previous variable. However the use of dot '.' to separate major and minor version number makes this name less to non-portable and its use is discouraged. Support of this variable has been kept only for backward compatibility with the original specification, i.e. TIP 189.

These paths are seen and therefore shared by all Tcl shells in the $::env(PATH) of the user.

Note that X and y follow the general rules set out above. In other words, Tcl 8.4, for example, will look at these 10 environment variables:

$::env(TCL8.4_TM_PATH)  $::env(TCL8_4_TM_PATH)
$::env(TCL8.3_TM_PATH)  $::env(TCL8_3_TM_PATH)
$::env(TCL8.2_TM_PATH)  $::env(TCL8_2_TM_PATH)
$::env(TCL8.1_TM_PATH)  $::env(TCL8_1_TM_PATH)
$::env(TCL8.0_TM_PATH)  $::env(TCL8_0_TM_PATH)
