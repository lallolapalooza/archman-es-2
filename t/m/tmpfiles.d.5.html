DESCRIPCIÓN

Los archivos de configuración de tmpfiles.d proporcionan un mecanismo genérico para definir la creación de archivos regulares, directorios, tuberías y nodos de dispositivo, ajustes a su modo de acceso, propiedad, atributos, asignaciones de cuotas y finalmente su eliminación basada en el tiempo. Se usa comúnmente para archivos y directorios volátiles y temporales (como los ubicados en /run/, /tmp/, /var/tmp/, los sistemas de archivos API como /sys/ o /proc/, así como otros directorios debajo de /var/).

systemd-tmpfiles(8) usa esta configuración para crear archivos y directorios volátiles durante el arranque y para realizar una limpieza periódica después. Consulte systemd-tmpfiles(8) para la descripción de systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service, y las unidades asociadas.

Los demonios del sistema con frecuencia requieren directorios privados de tiempo de ejecución debajo de /run/ para almacenar sockets de comunicación y similares. Para estos, es mejor usar RuntimeDirectory= en sus archivos de unidad (ver systemd.exec(5) para detalles), si no se requiere la flexibilidad proporcionada por tmpfiles.d. Las ventajas son que la configuración requerida por la unidad está centralizada en un solo lugar y que la vida útil del directorio está ligada a la vida útil del propio servicio. De manera similar, se debe usar StateDirectory=, CacheDirectory=, LogsDirectory= y ConfigurationDirectory= para crear directorios debajo de /var/lib/, /var/cache/, /var/log/ y /etc/. tmpfiles.d debe usarse para archivos cuya vida útil sea independiente de cualquier servicio o que requiera una configuración más compleja.

DIRECTORIOS DE CONFIGURACIÓN Y PRECEDENCIA

Cada archivo de configuración debe llamarse en el estilo de paquete.conf o paquete-parte.conf. La segunda variante debe usarse cuando se desea facilitar la sustitución de solo esa parte de la configuración.

Los archivos en /etc/tmpfiles.d sustituyen a los archivos con el mismo nombre en /usr/lib/tmpfiles.d y /run/tmpfiles.d. Los archivos en /run/tmpfiles.d sustituyen a los archivos con el mismo nombre en /usr/lib/tmpfiles.d. Los paquetes deben instalar sus archivos de configuración en /usr/lib/tmpfiles.d. Los archivos en /etc/tmpfiles.d están reservados para el administrador local, quien puede usar esta lógica para sustituir los archivos de configuración instalados por paquetes del proveedor. Todos los archivos de configuración se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en qué directorios residan. Si varios archivos especifican la misma ruta, se aplicará la entrada del archivo con el nombre lexicográficamente anterior (tenga en cuenta que las líneas suprimidas debido a "!" se filtran antes de la aplicación, lo que significa que si una línea temprana lleva el signo de exclamación y se suprime debido a eso, se aplicará una línea posterior que coincida en la ruta). Todas las demás entradas en conflicto se registrarán como errores. Cuando dos líneas son la ruta de prefijo y la ruta de sufijo una de la otra, la línea de prefijo siempre se crea primero, la de sufijo después (y si la eliminación se aplica a la línea, el orden se invierte: la de sufijo se elimina primero, la de prefijo después). Las líneas que toman globs se aplican después de aquellas que no aceptan globs. Si se aplican varias operaciones al mismo archivo (como ajuste de ACL, xattr, atributos de archivo), estas siempre se realizan en el mismo orden fijo. Excepto en esos casos, los archivos/directorios se procesan en el orden en que se enumeran.

Si el administrador desea deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en /etc/tmpfiles.d/ con el mismo nombre de archivo.

FORMATO DEL ARCHIVO DE CONFIGURACIÓN

El formato de configuración es una línea por ruta, que contiene campos de tipo, ruta, modo, propiedad, antigüedad y argumento. Las líneas se separan por saltos de línea, los campos por espacios en blanco:

#Tipo Ruta        Modo Usuario Grupo Antigüedad Argumento...
d     /run/user   0755 root root  10d -
L     /tmp/foobar -    -    -     -   /dev/null

Los campos pueden contener escapes de estilo C. Con la excepción del séptimo campo (el "argumento"), todos los campos pueden estar entre comillas. Tenga en cuenta que cualquier espacio en blanco que se encuentre en la línea después del inicio del campo de argumento se considerará parte del campo de argumento. Para comenzar el campo de argumento con un carácter de espacio en blanco, use escapes de estilo C (por ejemplo, "\x20").

Tipo

El tipo consiste en una sola letra y opcionalmente uno o más caracteres modificadores: un signo más ("+"), un signo de exclamación ("!"), un signo menos ("-"), un signo igual ("="), un carácter de tilde ("~") y/o un símbolo de intercalación ("^").

Los siguientes tipos de línea se entienden:

f, f+

f creará un archivo si aún no existe. Si se proporciona el parámetro de argumento y el archivo no existía, se escribirá en el archivo. f+ creará o truncará el archivo. Si se proporciona el parámetro de argumento, se escribirá en el archivo. No sigue enlaces simbólicos.

w,

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

w+

Escribe el parámetro del argumento a un archivo, si el archivo existe. Si se sufija con +, la línea se añadirá al archivo. Si tu configuración escribe múltiples líneas en el mismo archivo, usa w+. Las líneas de este tipo aceptan globs estilo shell en lugar de nombres de ruta normales. El parámetro del argumento se escribirá sin un salto de línea final. Se interpretan los escapes de barra invertida estilo C. Sigue enlaces simbólicos.

d

Crea un directorio. El modo y la propiedad se ajustarán si se especifican. El contenido de este directorio está sujeto a limpieza basada en tiempo si se especifica el argumento de edad.

D

Similar a d, pero además el contenido del directorio se eliminará cuando se use --remove.

e

Ajusta el modo y la propiedad de los directorios existentes y elimina su contenido basándose en la edad. Las líneas de este tipo aceptan globs estilo shell en lugar de nombres de ruta normales. El contenido de los directorios está sujeto a limpieza basada en tiempo si se especifica el argumento de edad. Si el argumento de edad es "0", el contenido se eliminará incondicionalmente cada vez que se ejecute systemd-tmpfiles(8) --clean.

Para que esta entrada sea útil, se debe especificar al menos uno de los argumentos de modo, usuario, grupo o edad, ya que de lo contrario esta entrada no tendrá efecto. Como excepción, una entrada sin efecto puede ser útil cuando se combina con !, ver los ejemplos.

Añadido en la versión 230.

v

Crea un subvolumen si la ruta aún no existe, el sistema de archivos admite subvolúmenes (btrfs) y el propio sistema está instalado en un subvolumen (específicamente: la raíz / es en sí misma un subvolumen). De lo contrario, crea un directorio normal, de la misma manera que d.

Un subvolumen creado con este tipo de línea no está asignado a ningún grupo de cuotas de nivel superior. Para ello, usa q o Q, que permiten crear jerarquías simples de grupos de cuotas, ver más abajo.

Añadido en la versión 219.

q

Crea un subvolumen o directorio igual que v, pero asigna el subvolumen a los mismos grupos de cuotas de nivel superior que el padre. Esto asegura que los límites y la contabilidad de nivel superior aplicados al subvolumen padre también incluyan el subvolumen especificado. En sistemas de archivos que no son btrfs, este tipo de línea es idéntico a d.

Si el subvolumen ya existe, no se realiza ningún cambio en la jerarquía de cuotas, independientemente de si el subvolumen ya está asociado a un grupo de cuotas o no. Ver también Q más abajo. Ver btrfs-qgroup(8) para detalles sobre el concepto de grupo de cuotas de btrfs.

Añadido en la versión 228.

Q

Crea el subvolumen o directorio igual que v, pero asigna el nuevo subvolumen a un nuevo grupo de cuotas hoja. En lugar de copiar las asignaciones de grupos de cuotas de nivel superior del padre como se hace con q, se determina el grupo de cuotas de nivel más bajo del subvolumen padre que no es el grupo de cuotas hoja. Luego, se inserta un grupo de cuotas "intermediario" que está un nivel por debajo de este nivel y comparte la misma parte del ID que el subvolumen especificado. Si no existe un grupo de cuotas de nivel superior para el subvolumen padre, se inserta en su lugar un nuevo grupo de cuotas en el nivel 255 que comparte el mismo ID que el subvolumen especificado. Este nuevo grupo de cuotas intermediario se asigna luego a los grupos de cuotas de nivel superior del subvolumen padre, y el grupo de cuotas hoja del subvolumen especificado se le asigna.

Efectivamente, esto tiene un efecto similar a q, sin embargo, introduce un nuevo grupo de cuotas de nivel superior para el subvolumen especificado que puede usarse para aplicar límites y contabilidad a todos los subvolúmenes hijos creados dentro de él. Por lo tanto, al crear subvolúmenes solo a través de q y Q, se implementa un concepto de "cuotas de subárbol". Cada subvolumen para el cual se establece Q tendrá un grupo de cuotas de "subárbol" creado, y todos los subvolúmenes hijos creados dentro de él se le asignarán. Cada subvolumen para el cual se establece q no tendrá un grupo de cuotas de "subárbol" de este tipo, pero se asegura que se añadan al mismo grupo de cuotas de "subárbol" que sus padres inmediatos.

Se recomienda usar Q para subvolúmenes que típicamente contienen subvolúmenes adicionales y donde es deseable tener contabilidad y límites de cuota en todos los subvolúmenes hijos juntos. Los ejemplos para Q son típicamente /home/ o /var/lib/machines/. En contraste, q debe usarse para subvolúmenes que usualmente no incluyen subvolúmenes adicionales o donde no se necesitan límites de contabilidad y cuota que se apliquen a todos los subvolúmenes hijos juntos. Los ejemplos para q son típicamente /var/ o /var/tmp/.

Al igual que con q, Q no tiene ningún efecto en la jerarquía de grupos de cuotas si el subvolumen ya existe, independientemente de si el subvolumen ya pertenece a un grupo de cuotas o no.

Añadido en la versión 228.

p, p+

Crea una tubería con nombre (FIFO) si aún no existe. Si se sufija con + y ya existe un archivo donde se creará la tubería, se eliminará y se reemplazará por la tubería.

L, L+, L?

Crea un enlace simbólico si aún no existe. Si se sufija con + y ya existe un archivo o directorio donde se creará el enlace simbólico, se eliminará y se reemplazará por el enlace simbólico. Si se sufija con ? y la ruta de origen no existe, no se crea el enlace simbólico. Si se omite el argumento, se crean enlaces simbólicos a archivos con el mismo nombre que residen en el directorio /usr/share/factory/. Tenga en cuenta que los permisos en los enlaces simbólicos se ignoran.

c, c+

Crea un nodo de dispositivo de caracteres si aún no existe. Si se sufija con + y ya existe un archivo donde se creará el nodo de dispositivo, se eliminará y se reemplazará por el nodo de dispositivo. Se recomienda sufijar esta entrada con un signo de exclamación para crear solo nodos de dispositivo estáticos al arrancar, ya que udev no gestionará nodos de dispositivo estáticos que se crean en tiempo de ejecución.

b, b+

Crea un nodo de dispositivo de bloque si aún no existe. Si se sufija con + y ya existe un archivo donde se creará el nodo de dispositivo, se eliminará y se reemplazará por el nodo de dispositivo. Se recomienda sufijar esta entrada con un signo de exclamación para crear solo nodos de dispositivo estáticos al arrancar, ya que udev no gestionará nodos de dispositivo estáticos que se crean en tiempo de ejecución.

C, C+

Copia recursivamente un archivo o directorio, si los archivos o directorios de destino aún no existen o el directorio de destino está vacío. Tenga en cuenta que este comando no descenderá a subdirectorios si el directorio de destino ya existe y no está vacío, a menos que la acción se sufije con +. En su lugar, la operación de copia completa se omitirá. Si se omite el argumento, se copian archivos del directorio de origen /usr/share/factory/ con el mismo nombre. No sigue enlaces simbólicos. El contenido de los directorios está sujeto a limpieza basada en tiempo si se especifica el argumento de edad.

Ignora una ruta durante la limpieza. Usa este tipo para excluir rutas de la limpieza controlada con el parámetro Age. Las líneas de este tipo aceptan globs estilo shell en lugar de nombres de ruta normales.

r

Elimina un archivo o directorio si existe. Esto no se puede usar para eliminar directorios no vacíos, usa R para eso. Las líneas de este tipo aceptan globs estilo shell en lugar de nombres de ruta normales. No sigue enlaces simbólicos.

Elimina recursivamente una ruta y todos sus subdirectorios (si es un directorio). Las líneas de este tipo aceptan globs estilo shell en lugar de nombres de ruta normales. No sigue enlaces simbólicos.

z

Ajusta el modo de acceso, la propiedad de usuario y grupo, y restaura el contexto de seguridad SELinux de un archivo o directorio, si existe. Las líneas de este tipo aceptan globs estilo shell en lugar de nombres de ruta normales. No sigue enlaces simbólicos.

T

h

Establece atributos de archivo/directorio de Linux. Las líneas de este tipo aceptan globs estilo shell en lugar de nombres de ruta normales.

Modificadores de Tipo

Si se utiliza el signo de exclamación ("!") , esta línea solo es segura de ejecutar durante el arranque y puede romper un sistema en funcionamiento. Las líneas sin el signo de exclamación se presumen seguras de ejecutar en cualquier momento, por ejemplo, durante las actualizaciones de paquetes. systemd-tmpfiles(8) tendrá en cuenta las líneas con un signo de exclamación solo si se proporciona la opción --boot.

Por ejemplo:

# Asegurarse de que se creen por defecto para que nadie más pueda
d /tmp/.X11-unix 1777 root root 10d
# Desenlazar los archivos de bloqueo de X11
r! /tmp/.X[0-9]*-lock

La segunda línea, en contraste con la primera, rompería un sistema en funcionamiento y solo se ejecutaría con --boot.

Si se utiliza el signo de menos ("-"), el fallo de ejecución de esta línea durante la creación (y solo durante la creación) no provocará que la ejecución de systemd-tmpfiles(8) devuelva un error.

Por ejemplo:

# Modificar sysfs pero no fallar si estamos en un contenedor con /proc de solo lectura
w- /proc/sys/vm/swappiness - - - - 10

Si se utiliza el signo de igual ("="), se comprueban los tipos de archivo de los objetos existentes en la ruta especificada y se eliminan si no coinciden. Esto incluye cualquier directorio padre creado implícitamente (que pueden ser directorios o symlinks de directorios). Por ejemplo, si hay una FIFO en lugar de uno de los componentes de la ruta padre, se reemplazará por un directorio.

Si se utiliza el carácter de tilde ("~"), el argumento (es decir, la 6ª columna) se decodifica en Base64[1] antes de su uso. Este modificador solo se admite en tipos de línea que pueden escribir contenido de archivo, es decir, f, f+, w, +. Esto es útil para escribir datos binarios arbitrarios (incluidos saltos de línea y bytes NUL) en archivos. Tenga en cuenta que si se utiliza este modificador, el argumento no está sujeto a expansión de especificadores, ni antes ni después de la decodificación Base64.

Si se utiliza el carácter de intercalación ("^"), la columna del argumento (es decir, la 6ª) toma un nombre de credencial de servicio para leer los datos del argumento. Consulte Credenciales del Sistema y del Servicio[2] para obtener detalles sobre el concepto de credenciales. Este modificador solo se admite en tipos de línea que pueden escribir contenido de archivo, es decir, f, f+, w, w+. Esto es útil para escribir archivos arbitrarios con contenido obtenido de otros lugares, incluidos los gestores de VM o contenedores superiores. Si la credencial especificada no está configurada para el servicio systemd-tmpfiles, la línea se omite silenciosamente. Si se combinan "^" y "~", se aplica la decodificación Base64 al contenido de la credencial.

Si se utiliza el signo de dólar ("$"), el archivo estará sujeto a eliminación cuando se invoque systemd-tmpfiles con el interruptor --purge. Las líneas sin este carácter no se ven afectadas por dicho interruptor.

Tenga en cuenta que para todos los tipos de línea que resultan en la creación de algún tipo de nodo de archivo (es decir, f, d/D/v/q/Q, p, L, c/b y C), los directorios principales se crean implícitamente si es necesario, en propiedad de root con un modo de acceso de 0755. Para crearlos con modos o propiedad diferentes, asegúrese de añadir líneas d apropiadas.

Ruta

La especificación de la ruta del sistema de archivos admite la expansión de especificadores simples, véase más abajo. La ruta (después de la expansión) debe ser absoluta.

Modo

El modo de acceso al archivo que se utilizará al crear este archivo o directorio. Si se omite o se establece en "-" , se utiliza el valor predeterminado: 0755 para directorios, 0644 para todos los demás objetos de archivo. Para las líneas z, Z, si se omite o se establece en "-" , el modo de acceso al archivo no se modificará. Este parámetro se ignora para las líneas x, r, R, L, t y a.

Opcionalmente, si se prefija con "~", el modo de acceso se enmascara en función de los bits de acceso ya establecidos para archivos o directorios existentes: si el archivo existente no tiene bits ejecutables, todos los bits ejecutables también se eliminarán del nuevo modo de acceso. De manera similar, si se eliminan todos los bits de lectura del modo anterior, también se eliminarán del nuevo modo de acceso, y si se eliminan todos los bits de escritura, también se eliminarán del nuevo modo de acceso. Además, el bit sticky/SUID/SGID se elimina a menos que se aplique a un directorio. Esta funcionalidad es particularmente útil en combinación con Z.

Por defecto, el modo de acceso de los inodos listados se establece en el modo especificado independientemente de si se crea uno nuevo o si ya existía. Opcionalmente, si se prefija con ":", el modo de acceso configurado solo se aplicará al crear nuevos inodos, y si el inodo al que se refiere la línea ya existe, su modo de acceso se dejará sin modificar.

Usuario, Grupo

El usuario y grupo que se utilizarán para este archivo o directorio. Puede ser un ID numérico o un nombre de usuario/grupo. Si se omite o se establece en "-" , se utiliza el usuario y grupo del usuario que invoca systemd-tmpfiles(8). Para las líneas z y Z, cuando se omite o se establece en "-" , la propiedad del archivo no se modificará. Estos parámetros se ignoran para las líneas x, r, R, t y a.

Este campo generalmente solo debe hacer referencia a usuarios/grupos del sistema, es decir, usuarios/grupos que se garantiza que se resolverán durante el arranque temprano. Si este campo hace referencia a usuarios/grupos que solo se resolverán durante el arranque posterior (es decir, después de que NIS, LDAP o un servicio de directorio de red similar estén disponibles), es probable que la ejecución de las operaciones declaradas por la línea falle. Consulte también Notas sobre la resolubilidad de nombres de usuario y grupo[3] para obtener más información sobre los requisitos de las definiciones de usuarios/grupos del sistema.

Por defecto, la propiedad de los inodos listados se establece en el usuario/grupo especificado independientemente de si se crea uno nuevo o si ya existía. Opcionalmente, si se prefija con ":", la información de usuario/grupo configurada solo se aplicará al crear nuevos inodos, y si el inodo al que se refiere la línea ya existe, su usuario/grupo se dejará sin modificar.

Antigüedad

El campo de fecha, cuando se establece, se utiliza para decidir qué archivos eliminar al limpiar. Si un archivo o directorio tiene más antigüedad que el tiempo actual menos el campo de antigüedad, se elimina. El formato del campo es una serie de enteros seguidos cada uno de uno de los siguientes sufijos para las unidades de tiempo respectivas: s, m o min, h, d, w, ms y us, que significan segundos, minutos, horas, días, semanas, milisegundos y microsegundos, respectivamente. También se pueden utilizar los nombres completos de las unidades de tiempo.

Si se especifican varios enteros y unidades, los valores de tiempo se suman. Si se proporciona un entero sin unidad, se asume s.

Cuando la antigüedad se establece en cero, los archivos se limpian incondicionalmente.

El campo de antigüedad solo se aplica a las líneas que comienzan con d, D, e, v, q, Q, C, x y X. Si se omite o se establece en "-" , no se realiza ninguna limpieza automática.

Si el campo de antigüedad comienza con un carácter de tilde "~", la limpieza solo se aplica a archivos y directorios un nivel dentro del directorio especificado, pero no a los archivos y directorios inmediatamente dentro de él.

La antigüedad de una entrada del sistema de archivos se determina a partir de su marca de tiempo de última modificación (mtime), su marca de tiempo de último acceso (atime) y (excepto para los directorios) su marca de tiempo de último cambio de estado (ctime). Por defecto, cualquiera de estos tres (o dos) valores evitará la limpieza si es más reciente que la hora actual menos el campo de antigüedad. Para restringir la eliminación en función de un tipo particular de marca de tiempo de archivo, se puede utilizar el argumento age-by.

El argumento age-by anula los tipos de marca de tiempo que se utilizarán para la comprobación de antigüedad. Se puede especificar prefijando el argumento de antigüedad con una secuencia de caracteres para especificar los tipos de marca de tiempo y dos puntos (":"): "age-by...:cleanup-age". El argumento puede consistir en a (A para directorios), b (B para directorios), c (C para directorios) o m (M para directorios). Estos indican respectivamente el tiempo de acceso, creación, último cambio de estado y última modificación de una entrada del sistema de archivos. La letra minúscula significa que el tipo de marca de tiempo dado debe considerarse para archivos, mientras que la letra mayúscula significa que el tipo de marca de tiempo dado debe considerarse para directorios. Consulte los campos de marca de tiempo de archivo de statx(2) para obtener más detalles sobre los tipos de marca de tiempo.

Si no se especifica, el campo age-by por defecto es abcmABM, es decir, por defecto se tienen en cuenta todas las marcas de tiempo de archivo, con la excepción de la marca de tiempo del último cambio de estado (ctime) para los directorios. Esto se debe a que la lógica de envejecimiento en sí misma alterará la ctime cada vez que elimine un archivo dentro de ella. Para garantizar que la ejecución de la lógica de envejecimiento no retroalimente en la siguiente iteración de sí misma, la ctime para los directorios se ignora por defecto.

Por ejemplo:

# Los archivos creados y modificados, y los directorios accedidos hace más de
# una hora en "/tmp/foo/bar", están sujetos a limpieza basada en el tiempo.
d /tmp/foo/bar - - - bmA:1h -

Tenga en cuenta que mientras se ejecuta el algoritmo de envejecimiento, se adquiere un bloqueo de archivo BSD exclusivo (consulte flock(2)) en cada directorio/archivo que el algoritmo decide eliminar. Si el algoritmo de envejecimiento encuentra que ya hay un bloqueo (compartido o exclusivo) adquirido en algún directorio/archivo, se omite (y todo lo que está debajo). NAME

systemd-tmpfiles - create, delete, and clean up volatile and temporary files and directories

SYNOPSIS

systemd-tmpfiles [-h HOME] [-r] [-d] [-q] [-a] [-u] [-w] [-x] [-F] [PATH...]

DESCRIPTION

systemd-tmpfiles is used to manage volatile and temporary files and directories. It is commonly used during system boot to set up runtime directories, and during shutdown to clean them up.

The tool reads configuration files from /usr/lib/tmpfiles.d/*.conf and /etc/tmpfiles.d/*.conf. The configuration files contain directives that define which files and directories should be created, removed, or cleaned up based on their age.

Each file contains a list of lines, which are parsed sequentially. Blank lines and lines starting with # are ignored.

Each non-comment line has the format:

Type Path Mode User Group Age Argument

The fields are:

Type
A single character specifying the action to take. One of the following:
d
Create a directory if it does not exist. If the directory exists, its mode and ownership are updated if they differ, but it is not otherwise touched. This is not a time-based cleanup directive. (See e).
D
Create a directory if it does not exist. If the directory exists, its mode and ownership are updated if they differ. The directory's contents are subject to time-based cleanup (see e). This is useful for directories where time-based cleanup is desired, but the directory itself should always exist.
e
Remove empty files. If the file exists and is empty, it is removed. Otherwise, nothing is done. This directive is not time-based.
E
Remove directories and their contents, if empty. If the directory exists and is empty, it is removed. Otherwise, nothing is done. This directive is not time-based.
x
Remove all files and directories located under the specified path, if they are older than the specified time. This directive is only effective for the contents of directories, not the directory itself. Use this for cleaning up cache directories, for example.
X
Remove all files and directories located under the specified path, if they are older than the specified time. This directive is only effective for the contents of directories, not the directory itself. Use this for cleaning up cache directories, for example. This is similar to x, but it only matches files that are not empty.
c
Create a character device node. The argument field must specify the major/minor pair. No time-based cleanup is performed.
b
Create a block device node. The argument field must specify the major/minor pair. No time-based cleanup is performed.
L
Create a symbolic link. The argument field must specify the target path. No time-based cleanup is performed.
f
Create an empty file if it does not exist. If the file exists, its mode and ownership are updated if they differ, but it is not otherwise touched. No time-based cleanup is performed.
F
Create an empty file if it does not exist. If the file exists, its mode and ownership are updated if they differ, but it is not otherwise touched. The file is removed when the system is shut down. No time-based cleanup is performed.
r
Remove a file or directory, recursively. This is not time-based cleanup. Use with caution.
R
Remove a file or directory, recursively. This is not time-based cleanup. Use with caution. This directive is similar to r, but it only removes files that are not empty.
t
Set extended attributes. For the path, set extended attributes as specified in the argument. This directive is not time-based.
T
Set extended attributes. For the path, set extended attributes as specified in the argument. This directive is not time-based. This directive is similar to t, but it removes all extended attributes previously set on the file.
a
Set Access Control Lists (ACLs). For the path, set ACLs as specified in the argument. This directive is not time-based.
A
Set Access Control Lists (ACLs). For the path, set ACLs as specified in the argument. This directive is not time-based. This directive is similar to a, but it removes all ACLs previously set on the file.
h
Set file attributes. For the path, set file attributes as specified in the argument. This directive is not time-based.
H
Set file attributes. For the path, set file attributes as specified in the argument. This directive is not time-based. This directive is similar to h, but it removes all file attributes previously set on the file.
w
Write a string to a file. The string is specified in the argument field. A newline is appended. If the file does not exist, it is created. If it exists, the string is appended. No time-based cleanup is performed.
C
Copy a file or directory. The argument field specifies the source path. This directive is not time-based.
Z
Set SELinux security context. For the path, set SELinux security context as specified in the argument. This directive is not time-based.
z
Set SELinux security context. For the path, set SELinux security context as specified in the argument. This directive is not time-based. This directive is similar to Z, but it removes all SELinux security contexts previously set on the file.
Path
The absolute path to the file or directory. This field can contain specifiers. For directives that operate on directories (like d, D, x, X, r, R), the path may end in a wildcard. For example, /tmp/file-* will match all files starting with /tmp/file-. For directives that perform cleanup (like x and X), the path must specify a directory. Note that the wildcard matching is done only on the last component of the path.
Mode
The file mode (permissions) for the created file or directory. This field is optional. If omitted or specified as "0-", default permissions are used. For symbolic links and device nodes, this field is ignored. If the field starts with a "-", the mode is interpreted as octal. Otherwise, it is interpreted as symbolic. For example, u=rwx,g=rx,o=rx or 0755.
User
The user name or UID for the created file or directory. This field is optional. If omitted or specified as "-", the file is created with the user and group of the process running systemd-tmpfiles (usually root). This field can contain specifiers.
Group
The group name or GID for the created file or directory. This field is optional. If omitted or specified as "-", the file is created with the user and group of the process running systemd-tmpfiles (usually root). This field can contain specifiers.
Age
The maximum age for files and directories to be removed. This field is optional and only relevant for cleanup directives (x, X). The age is specified as a time interval, e.g. "10d" for 10 days, "1h" for 1 hour, "30m" for 30 minutes, "1w" for 1 week, "52w" for 52 weeks (1 year), "10y" for 10 years. If omitted or specified as "-", no time-based cleanup is performed.
Argument
The meaning of this field depends on the Type. See below.

If a file or directory is to be created, and the path already exists and is a symbolic link, the symbolic link is removed and the file or directory is created. If the path exists and is not a symbolic link, and the directive is not d or D, the file/directory is touched and its metadata updated.

If the user or group fields are specified as "-", the file is created with the user and group of the process running systemd-tmpfiles. This is the default if these fields are omitted entirely.

For cleanup directives (x, X), the age field specifies the maximum age of files and directories to be removed. Files and directories older than this age are removed. If the age is set to 0, all files and directories are removed regardless of age. This is typically used to clean up directories on boot.

If a file is locked using flock(2) or fcntl(2), it will not be removed by time-based cleanup directives. This is useful for files that should only be removed when the process that created them exits.

When processing wildcard paths, only the final component of the path is matched against the wildcard. For example, /tmp/dir/* will match /tmp/dir/file1 and /tmp/dir/file2, but not /tmp/dir/subdir/file3.

It is possible to lock directories or files for removal. If a directory or file is locked by a process, and that process exits, the lock is released. If a directory is locked, all files and subdirectories within it are also considered locked. When a directory or file is locked, it will not be removed by time-based cleanup directives. This behaviour can be used to ensure guaranteed cleanup of files or directories whose lifetime should be aligned with the process that created them by having that process create them in a location monitored by systemd-tmpfiles with an age of "0", and having the process immediately lock the directory or file before using it. Because the BSD lock is process specific, the file is guaranteed to be unlocked as soon as the process exits, meaning that even if the process crashes, those files and directories will be unlocked and cleaned up by systemd-tmpfiles.

Argument

For L lines determines the destination path of the symlink. For c and b, determines the major/minor of the device node, with major and minor formatted as integers, separated by ":", e.g. "1:3". For f and w, the argument may be used to specify a short string that is written to the file, suffixed by a newline. For C, specifies the source file or directory. For t and T, determines extended attributes to be set. For a and A, determines ACL attributes to be set. For h and H, determines the file attributes to set. Ignored for all other lines.

This field can contain specifiers, see below.

SPECIFIERS

Specifiers can be used in the "path" and "argument" fields. An unknown or unresolvable specifier is treated as invalid configuration. The following expansions are understood:

Table 1. Specifiers available

"%B" Operating system build ID The operating system build identifier of the running system, as read from the BUILD_ID= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.
"%C" User cache directory In --user mode, this is the same as $XDG_CACHE_HOME, and /var/cache otherwise.
"%g" User group This is the name of the group running the command. In case of the system instance this resolves to "root".
"%G" User GID This is the numeric GID of the group running the command. In case of the system instance this resolves to 0.
"%h" User home directory This is the home directory of the user running the command. In case of the system instance this resolves to "/root".
"%H" Host name The hostname of the running system.
"%l" Short host name The hostname of the running system, truncated at the first dot to remove any domain component.
"%L" User log directory In --user mode, this is the same as $XDG_STATE_HOME with /log appended, and /var/log otherwise.

"%S" User state directory In --user mode, this is the same as $XDG_STATE_HOME, and /var/lib otherwise.
"%t" User runtime directory In --user mode, this is the same $XDG_RUNTIME_DIR, and /run/ otherwise.
"%T" Directory for temporary files This is either /tmp or the path "$TMPDIR", "$TEMP" or "$TMP" are set to. (Note that the directory may be specified without a trailing slash.)
"%u" User name This is the name of the user running the command. In case of the system instance this resolves to "root".
"%U" User UID This is the numeric UID of the user running the command. In case of the system instance this resolves to 0.
"%v" Kernel release Identical to uname -r output.

"%%" Single percent sign Use "%%" in place of "%" to specify a single percent sign.

EXAMPLES

Example 1. Create directories with specific mode and ownership

screen(1), needs two directories created at boot with specific modes and ownership:

# /usr/lib/tmpfiles.d/screen.conf
d /run/screens  1777 root screen 10d
d /run/uscreens 0755 root screen 10d12h

Contents of /run/screens and /run/uscreens will be cleaned up after 10 and 10½ days, respectively.

Example 2. Create a directory with a SMACK attribute

D /run/cups - - - -
t /run/cups - - - - security.SMACK64=printing user.attr-with-spaces="foo bar"

The directory will be owned by root and have default mode. Its contents are not subject to time-based cleanup, but will be obliterated when systemd-tmpfiles --remove runs.

Example 3. Create a directory and prevent its contents from cleanup

abrt(1), needs a directory created at boot with specific mode and ownership and its content should be preserved from the automatic cleanup applied to the contents of /var/tmp:

# /usr/lib/tmpfiles.d/tmp.conf
d /var/tmp 1777 root root 30d
# /usr/lib/tmpfiles.d/abrt.conf
d /var/tmp/abrt 0755 abrt abrt -

Example 4. Apply clean up during boot and based on time

# /usr/lib/tmpfiles.d/dnf.conf
r! /var/cache/dnf/*/*/download_lock.pid
r! /var/cache/dnf/*/*/metadata_lock.pid
r! /var/lib/dnf/rpmdb_lock.pid
e  /var/cache/dnf/ - - - 30d

The lock files will be removed during boot. Any files and directories in /var/cache/dnf/ will be removed after they have not been accessed in 30 days.

Example 5. Empty the contents of a cache directory on boot

# /usr/lib/tmpfiles.d/krb5rcache.conf
e! /var/cache/krb5rcache - - - 0

Any files and subdirectories in /var/cache/krb5rcache/ will be removed on boot. The directory will not be created.

Example 6. Provision SSH public key access for root user via Credentials in QEMU

-smbios type=11,value=io.systemd.credential.binary:tmpfiles.extra=$(echo -e "d /root/.ssh 0750 root root -\nf~ /root/.ssh/authorized_keys 0600 root root - $(ssh-add -L | base64 -w 0)" | base64 -w 0)

By passing this line to QEMU, the public key of the current user will be encoded in base64, added to a tmpfiles.d line that tells systemd-tmpfiles(8) to decode it into /root/.ssh/authorized_keys, encode that line itself in base64 and pass it as a Credential that will be picked up by systemd from SMBIOS on boot.

/RUN/ AND /VAR/RUN/

/var/run/ is a deprecated symlink to /run/, and applications should use the latter. systemd-tmpfiles will warn if /var/run/ is used.
