NOMBRE

tmate — multiplexor de terminal

SINOPSIS

tmate [-2CluvV] [-c comando-shell] [-f archivo] [-L nombre-socket] [-S ruta-socket] [comando [flags]]

DESCRIPCIÓN

tmate es un multiplexor de terminal: permite crear, acceder y controlar varios terminales desde una sola pantalla. tmate puede ser desconectado de una pantalla y seguir ejecutándose en segundo plano, para luego ser reconectado.

Cuando se inicia tmate, crea una nueva sesión con una única ventana y la muestra en pantalla. Una línea de estado en la parte inferior de la pantalla muestra información sobre la sesión actual y se utiliza para introducir comandos interactivos.

Una sesión es una colección única de terminales virtuales bajo la gestión de tmate. Cada sesión tiene una o más ventanas enlazadas a ella. Una ventana ocupa toda la pantalla y puede ser dividida en paneles rectangulares, cada uno de los cuales es un terminal virtual separado (la página del manual pty(4) documenta los detalles técnicos de los terminales virtuales). Se puede conectar cualquier número de instancias de tmate a la misma sesión, y cualquier número de ventanas puede estar presente en la misma sesión. Una vez que todas las sesiones se eliminan, tmate sale.

Cada sesión es persistente y sobrevivirá a desconexiones accidentales (como tiempos de espera en la conexión ssh(1)) o desconexiones intencionales (con las combinaciones de teclas ‘C-b d’). Se puede reconectar a tmate usando:

$ tmate attach

En tmate, una sesión se muestra en pantalla por un cliente y todas las sesiones son gestionadas por un único servidor. El servidor y cada cliente son procesos separados que se comunican a través de un socket en /tmp.

Las opciones son las siguientes:

-2
Fuerza a tmate a asumir que el terminal soporta 256 colores.
-C
Inicia en modo de control (ver la sección MODO DE CONTROL). Si se proporciona dos veces (-CC) se deshabilita el eco.
-c comando-shell
Ejecuta comando-shell usando el shell por defecto. Si es necesario, se iniciará el servidor tmate para recuperar la opción default-shell. Esta opción es para compatibilidad con sh(1) cuando tmate se utiliza como shell de inicio de sesión.
-f archivo
Especifica un archivo de configuración alternativo. Por defecto, tmate carga el archivo de configuración del sistema desde /etc/tmux.conf, si existe, y luego busca un archivo de configuración de usuario en ~/.tmux.conf y ~/.tmate.conf.

El archivo de configuración es un conjunto de comandos de tmate que se ejecutan en secuencia cuando se inicia el servidor por primera vez. tmate carga los archivos de configuración una vez cuando el proceso del servidor se ha iniciado. El comando source-file puede ser utilizado para cargar un archivo más tarde.

tmate muestra cualquier mensaje de error de los comandos en los archivos de configuración en la primera sesión creada, y continúa procesando el resto del archivo de configuración.

-L nombre-socket
tmate almacena el socket del servidor en un directorio bajo TMUX_TMPDIR o /tmp si no está definido. El socket por defecto se llama default. Esta opción permite especificar un nombre de socket diferente, lo que permite ejecutar varios servidores independientes de tmate. A diferencia de -S, no es necesario una ruta completa: todos los sockets se crean en el mismo directorio.

Si el socket se elimina accidentalmente, la señal SIGUSR1 puede ser enviada al proceso del servidor tmate para recrearlo (tenga en cuenta que esto fallará si faltan directorios padres).

-l
Actúa como un shell de inicio de sesión. Esta bandera actualmente no tiene efecto y es para compatibilidad con otros shells cuando se usa tmate como shell de inicio de sesión.
-S ruta-socket
Especifica una ruta alternativa completa al socket del servidor. Si se especifica -S, no se utiliza el directorio de socket por defecto y se ignora cualquier bandera -L.
-u
tmate intenta adivinar si el terminal probablemente soporta UTF-8 comprobando la primera de las variables de entorno LC_ALL, LC_CTYPE y LANG que esté configurada con la cadena "UTF-8". Esto no siempre es correcto: la bandera -u informa explícitamente a tmate de que se soporta UTF-8.

Tenga en cuenta que tmate en sí mismo siempre acepta UTF-8; esto controla si enviará caracteres UTF-8 al terminal en el que se está ejecutando (si no es así, se reemplazan por ‘_’).

-v
Solicita registro detallado. Esta opción se puede especificar varias veces para aumentar la verbosidad. Los mensajes de registro se guardarán en los archivos tmux-PID-client.log y tmux-PID-server.log en el directorio actual, donde PID es el PID del proceso del servidor o cliente.
-V
Reporta la versión de tmate.
comando [flags]
Esto especifica uno de los conjuntos de comandos utilizados para controlar tmate, como se describe en las siguientes secciones. Si no se especifican comandos, se asume el comando new-session.

COMANDOS

Esta sección contiene una lista de los comandos compatibles con tmate. La mayoría de los comandos aceptan el argumento opcional -t (y a veces -s) con uno de los argumentos cliente-objetivo, sesión-objetivo, ventana-objetivo o panel-objetivo. Estos especifican el cliente, sesión, ventana o panel que un comando debe afectar.

cliente-objetivo es el nombre del archivo pty(4) al que está conectado el cliente, por ejemplo, cualquiera de /dev/ttyp1 o ttyp1 para el cliente conectado a /dev/ttyp1. Si no se especifica ningún cliente, tmate intenta determinar el cliente en uso; si falla, se informa de un error. Los clientes se pueden listar con el comando list-clients.

sesión-objetivo se intenta en orden como:

  1. Un ID de sesión prefijado con un $.
  2. Un nombre exacto de sesión (como lista el comando list-sessions).
  3. El inicio de un nombre de sesión, por ejemplo, ‘misess’ coincidiría con una sesión llamada ‘mysession’.
  4. Un patrón fnmatch(3) que coincide con el nombre de la sesión.

Si el nombre de la sesión va prefijado con un ‘=’, solo se acepta una coincidencia exacta (por lo que ‘=misess’ solo coincidirá exactamente con ‘misess’, no con ‘mysession’).

Si se encuentra una única sesión, se utiliza como sesión objetivo; múltiples coincidencias producen un error. Si se omite una sesión, se utiliza la sesión actual si está disponible; si no hay ninguna sesión actual disponible, se elige la utilizada más recientemente.

ventana-objetivo (o ventana-origen o ventana-destino) especifica una ventana en el formato sesión:ventana. La sesión sigue las mismas reglas que para sesión-objetivo, y la ventana se busca en orden como:

  1. Un token especial, listado a continuación.
  2. Un índice de ventana, por ejemplo, ‘misession:1’ es la ventana 1 en la sesión ‘misession’.
  3. Un ID de ventana, como @1.
  4. Un nombre de ventana exacto, como ‘misession:mi-ventana’.
  5. El inicio de un nombre de ventana, como ‘misession:miventana’.
  6. Como un patrón fnmatch(3) que coincide con el nombre de la ventana.

Al igual que con las sesiones, un prefijo ‘=’ realizará solo una coincidencia exacta. Un nombre de ventana vacío especifica el siguiente índice no utilizado si es apropiado (por ejemplo, los comandos new-window y link-window), de lo contrario, se elige la ventana actual en sesión.

Los siguientes tokens especiales están disponibles para indicar ventanas particulares. Cada uno tiene una forma alternativa de un solo carácter.

Token Significado
{inicio} ^ La ventana con el número más bajo
{fin} $ La ventana con el número más alto
{anterior} ! La última ventana (anteriormente actual)
{siguiente} + La siguiente ventana por número
{previo} - La ventana anterior por número

panel-objetivo (o panel-origen o panel-destino) puede ser un ID de panel o tomar una forma similar a ventana-objetivo pero con la adición opcional de un punto seguido de un índice de panel o ID de panel, por ejemplo: ‘misession:mi-ventana.1’. Si se omite el índice del panel, se utiliza el panel activo actualmente en la ventana especificada. Los siguientes tokens especiales están disponibles para el índice del panel:

Token Significado
{anterior} ! El último panel (anteriormente activo)
{siguiente} + El siguiente panel por número
{previo} - El panel anterior por número
{arriba} El panel superior
{abajo} El panel inferior
{izquierda} El panel más a la izquierda
{derecha} El panel más a la derecha
{arriba-izquierda} El panel superior izquierdo
{arriba-derecha} El panel superior derecho
{abajo-izquierda} El panel inferior izquierdo
{abajo-derecha} El panel inferior derecho
{arriba-de} El panel encima del panel activo
{abajo-de} El panel debajo del panel activo
{izquierda-de} El panel a la izquierda del panel activo
{derecha-de} El panel a la derecha del panel activo

A los tokens ‘+’ y ‘-’ se les puede seguir un desplazamiento, por ejemplo:

select-window -t:+2

Además, sesión-objetivo, ventana-objetivo o panel-objetivo pueden ser un ID de cliente, sesión, ventana o panel respectivamente. Si un objetivo se omite, se intenta el objetivo actual y si eso falla, se utiliza el más reciente que se ajusta a los criterios.

puede consistir completamente en el token ‘{mouse}’ (forma alternativa ‘=’) para especificar el evento más reciente del ratón (ver la sección SOPORTE DEL RATÓN) o ‘{marked}’ (forma alternativa ‘~’) para especificar el panel marcado (ver select-pane -m).

Las sesiones, ventanas y paneles se numeran cada uno con un ID único; los IDs de sesión van precedidos de un ‘$’, las ventanas de un ‘@’, y los paneles de un ‘%’. Estos son únicos y no cambian durante la vida de la sesión, ventana o panel en el servidor tmate. El ID del panel se pasa al proceso hijo del panel en la variable de entorno TMUX_PANE. Los IDs se pueden mostrar usando los formatos ‘session_id’, ‘window_id’, o ‘pane_id’ (ver la sección FORMATOS) y los comandos display-message, list-sessions, list-windows o list-panes.

Los argumentos shell-command son comandos de sh(1). Esto puede ser un solo argumento pasado al shell, por ejemplo:

new-window 'vi /etc/passwd'

Ejecutará:

/bin/sh -c 'vi /etc/passwd'

Adicionalmente, los comandos new-window, new-session, split-window, respawn-window y respawn-pane permiten que shell-command se proporcione como múltiples argumentos y se ejecute directamente (sin ‘sh -c’). Esto puede evitar problemas con el escape de caracteres del shell. Por ejemplo:

$ tmate new-window vi /etc/passwd

Ejecutará vi(1) directamente sin invocar el shell.

command [arguments] se refiere a un comando tmate, pasado con el comando y los argumentos por separado, por ejemplo:

bind-key F1 set-window-option force-width 81

O si se usa sh(1):

$ tmate bind-key F1 set-window-option force-width 81

Se pueden especificar múltiples comandos juntos como parte de una secuencia de comandos. Cada comando debe estar separado por espacios y un punto y coma; los comandos se ejecutan secuencialmente de izquierda a derecha y las líneas que terminan en una barra invertida continúan en la siguiente línea, excepto cuando se escapan con otra barra invertida. Un punto y coma literal puede incluirse escapándolo con una barra invertida (por ejemplo, al especificar una secuencia de comandos para bind-key).

Los comandos de ejemplo de tmate incluyen:

refresh-client -t/dev/ttyp2

rename-session -tfirst newname

set-window-option -t:0 monitor-activity on

new-window ; split-window -d

bind-key R source-file ~/.tmux.conf \; \
	display-message "source-file done"

O desde sh(1):

$ tmate kill-window -t :1

$ tmate new-window \; split-window -d

$ tmate new-session -d 'vi /etc/passwd' \; split-window -d \; attach

CLIENTES Y SESIONES

El servidor tmate gestiona clientes, sesiones, ventanas y paneles. Los clientes se adjuntan a sesiones para interactuar con ellas, ya sea cuando se crean con el comando new-session, o más tarde con el comando attach-session. Cada sesión tiene una o más ventanas enlazadas a ella. Las ventanas pueden enlazarse a múltiples sesiones y están compuestas por uno o más paneles, cada uno de los cuales contiene un pseudo terminal. Los comandos para crear, enlazar y manipular ventanas se cubren en la sección VENTANAS Y PANELES.

Las teclas de palabra siguiente y anterior utilizan el espacio y los caracteres ‘-’, ‘_’ y ‘@’ como delimitadores de palabras por defecto, pero esto se puede ajustar configurando la opción de sesión word-separators. Las tres teclas de espacio siguiente y anterior funcionan de manera similar pero utilizan un espacio solo como separador de palabras.

Los comandos de salto permiten un movimiento rápido dentro de una línea. Por ejemplo, escribir ‘f’ seguido de ‘/’ moverá el cursor al siguiente carácter ‘/’ en la línea actual. Un ‘;’ saltará entonces a la siguiente ocurrencia.

Los comandos en modo de copia pueden ir precedidos por un contador de repetición opcional. Con las asignaciones de teclas vi, se accede a un prefijo usando las teclas numéricas; con emacs, la tecla Alt (meta) y un número inician la entrada del prefijo. Por ejemplo, para mover el cursor diez palabras hacia adelante, use ‘M-1 0 M-f’ en modo emacs, y ‘10w’ en vi.

Las asignaciones de teclas de modo se definen en un conjunto de tablas con nombre: vi-edit y emacs-edit para las teclas utilizadas al editar líneas en el prompt de comandos; vi-choice y emacs-choice para las teclas utilizadas al elegir de listas (como las producidas por el comando choose-window); y vi-copy y emacs-copy utilizadas en modo de copia. Las tablas se pueden ver con el comando list-keys y las teclas se pueden modificar o eliminar con bind-key y unbind-key. Si a append-selection, copy-selection, o start-named-buffer se les da el flag -x, tmate no saldrá del modo de copia después de copiar. copy-pipe copia la selección y la canaliza a un comando. Por ejemplo, lo siguiente vinculará ‘C-w’ para no salir después de copiar y ‘C-q’ para copiar la selección en /tmp además del buffer de pegado:

bind-key -temacs-copy C-w copy-selection -x
bind-key -temacs-copy C-q copy-pipe "cat >/tmp/out"

La tecla del buffer de pegado pega la primera línea de la pila del buffer de pegado superior.

Cada ventana mostrada por tmate puede dividirse en uno o más paneles; cada panel ocupa un área determinada de la pantalla y es una terminal separada. Una ventana puede dividirse en paneles usando el comando split-window. Las ventanas pueden dividirse horizontalmente (con el flag -h) o verticalmente. Los paneles pueden redimensionarse con el comando resize-pane (asignado a ‘C-up’, ‘C-down’, ‘C-left’ y ‘C-right’ por defecto), el panel actual puede cambiarse con el comando select-pane y los comandos rotate-window y swap-pane se pueden usar para intercambiar paneles sin cambiar su posición. Los paneles se numeran a partir de cero en el orden en que se crean.

Hay disponibles varios layouts predefinidos. Estos pueden seleccionarse con el comando select-layout o ciclarse con next-layout (asignado a ‘Space’ por defecto); una vez elegido un layout, los paneles dentro de él pueden moverse y redimensionarse como de costumbre.

Los siguientes layouts son compatibles:

even-horizontal
Los paneles se distribuyen uniformemente de izquierda a derecha en la ventana.
even-vertical
Los paneles se distribuyen uniformemente de arriba a abajo.
main-horizontal
Un panel grande (principal) se muestra en la parte superior de la ventana y los paneles restantes se distribuyen de izquierda a derecha en el espacio sobrante en la parte inferior. Utilice la opción de ventana main-pane-height para especificar la altura del panel superior.
main-vertical
Similar a main-horizontal pero el panel grande se coloca a la izquierda y los otros se distribuyen de arriba a abajo a lo largo de la derecha. Consulte la opción de ventana main-pane-width.
tiled
Los paneles se distribuyen lo más uniformemente posible en la ventana, tanto en filas como en columnas.

Además, select-layout puede usarse para aplicar un layout utilizado previamente; el comando list-windows muestra el layout de cada ventana en un formato adecuado para usar con select-layout. Por ejemplo:

$ tmate list-windows
0: ksh [159x48]
    layout: bb62,159x48,0,0{79x48,0,0,79x48,80,0}
$ tmate select-layout bb62,159x48,0,0{79x48,0,0,79x48,80,0}

tmate ajusta automáticamente el tamaño del layout al tamaño actual de la ventana. Tenga en cuenta que un layout no se puede aplicar a una ventana con más paneles que aquellos de los que se definió originalmente el layout.

ASOCIACIONES DE TECLAS

tmate permite asociar un comando a la mayoría de las teclas, con o sin una tecla de prefijo. Al especificar teclas, la mayoría se representan a sí mismas (por ejemplo, ‘A’ hasta ‘Z’). Las teclas Ctrl pueden prefijarse con ‘C-’ o ‘^’, y Alt (meta) con ‘M-’. OPTIONS

The appearance and behaviour of tmate may be modified by changing the value of various options. There are three types of option: server options, session options and window options.

The tmate server has a set of global options which do not apply to any particular window or session. These are altered with the set-option -s command, or displayed with the show-options -s command.

In addition, each individual session may have a set of session options, and there is a separate set of global session options. Sessions which do not have a particular option configured inherit the value from the global session options. Session options are set or unset with the set-option command and may be listed with the show-options command. The available server and session options are listed under the set-option command.

Similarly, a set of window options is attached to each window, and there is a set of global window options from which any unset options are inherited. Window options are altered with the set-window-option command and can be listed with the show-window-options command. All window options are documented with the set-window-option command.

tmate also supports user options which are prefixed with a ‘@’. User options may have any name, so long as they are prefixed with ‘@’, and be set to any string. For example:

$ tmate setw -q @foo "abc123"
$ tmate showw -v @foo
abc123

Commands which set options are as follows:

set-option [-agoqsuw] [-t target-session | target-window] option value
(alias: set
) Set a window option with -w (equivalent to the set-window-option command), a server option with -s, otherwise a session option. If -g is given, the global session or window option is set. The -u flag unsets an option, so a session inherits the option from the global options (or with -g, restores a global option to the default).

The -o flag prevents setting an option that is already set and the -q flag suppresses errors about unknown or ambiguous options.

With -a, and if the option expects a string or a style, value is appended to the existing setting. For example:

set -g status-left "foo"
set -ag status-left "bar"

Will result in ‘foobar’. And:

set -g status-style "bg=red"
set -ag status-style "fg=blue"

Will result in a red background and blue foreground. Without -a, the result would be the default background and a blue foreground.

Available window options are listed under set-window-option.

value depends on the option and may be a number, a string, or a flag (on, off, or omitted to toggle).

FORMATOS

Ciertos comandos aceptan el flag -F con un argumento formato. Esta es una cadena que controla el formato de salida del comando. Las variables de reemplazo se encierran entre ‘#{’ y ‘}’, por ejemplo ‘#{session_name}’. Las variables posibles se enumeran en la siguiente tabla, o se puede usar el nombre de una opción de tmate para el valor de una opción. Algunas variables tienen un alias más corto, como ‘#S’, y ‘##’ se reemplaza por un solo ‘#’.

Los condicionales están disponibles prefijando con ‘?’ y separando dos alternativas con una coma; si la variable especificada existe y no es cero, se elige la primera alternativa, de lo contrario, se usa la segunda. Por ejemplo ‘#{?session_attached,attached,not attached}’ incluirá la cadena ‘attached’ si la sesión está adjunta y la cadena ‘not attached’ si no lo está, o ‘#{?automatic-rename,yes,no}’ incluirá ‘yes’ si automatic-rename está habilitado, o ‘no’ si no lo está.

Se puede colocar un límite a la longitud de la cadena resultante prefijándola con un ‘=’, un número y dos puntos. Los números positivos se cuentan desde el inicio de la cadena y los negativos desde el final, de modo que ‘#{=5:pane_title}’ incluirá como máximo los primeros 5 caracteres del título del panel, o ‘#{=-5:pane_title}’ los últimos 5 caracteres. Prefijar una variable de tiempo con ‘t:’ la convertirá en una cadena, de modo que si ‘#{window_activity}’ da ‘1445765102’, ‘#{t:window_activity}’ dará ‘Sun Oct 25 09:25:02 2015’. Los prefijos ‘b:’ y ‘d:’ son los de basename(3) y dirname(3) de la variable respectivamente. Un prefijo de la forma ‘s/foo/bar/:’ sustituirá ‘foo’ por ‘bar’ en toda la cadena.

Además, la primera línea de la salida de un comando de shell puede insertarse usando ‘#()’. Por ejemplo, ‘#(uptime)’ insertará el tiempo de actividad del sistema. Al construir formatos, tmate no espera a que los comandos ‘#()’ terminen; en su lugar, se utiliza el resultado anterior de ejecutar el mismo comando, o un marcador de posición si el comando no se ha ejecutado antes. Los comandos se ejecutan con el entorno global de tmate configurado (ver la sección ENTORNO).

NOMBRES Y TÍTULOS

tmate distingue entre nombres y títulos. Las ventanas y sesiones tienen nombres, que pueden usarse para especificarlas en objetivos y se muestran en la línea de estado y en varias listas: el nombre es el identificador de tmate para una ventana o sesión. Solo los paneles tienen títulos. El título de un panel suele ser establecido por el programa que se ejecuta dentro del panel y no es modificado por tmate. Es el mismo mecanismo que se usa para establecer, por ejemplo, el título de la ventana de xterm(1) en un gestor de ventanas de X(7). Las ventanas en sí no tienen títulos; el título de una ventana es el título de su panel activo. tmate en sí puede establecer el título de la terminal en la que se está ejecutando el cliente, consulte la opción set-titles.

El nombre de una sesión se establece con los comandos new-session y rename-session. El nombre de una ventana se establece con una de las siguientes opciones:

  1. Un argumento de comando (como -n para new-window o new-session).
  2. Una secuencia de escape: 
    $ printf '\033kWINDOW_NAME\033\\'
  3. Renombrado automático, que establece el nombre al comando activo en el panel activo de la ventana. Consulte la opción automatic-rename.

Cuando se crea un panel por primera vez, su título es el nombre del host. El título de un panel se puede establecer a través de la secuencia de establecimiento de título OSC, por ejemplo:

$ printf '\033]2;Mi Título\033\\'

ENTORNO

Cuando se inicia el servidor, tmate copia el entorno al entorno global; además, cada sesión tiene un entorno de sesión. Cuando se crea una ventana, se fusionan los entornos de sesión y global. Si una variable existe en ambos, se utiliza el valor del entorno de sesión. El resultado es el entorno inicial que se pasa al nuevo proceso.

La opción de sesión update-environment puede utilizarse para actualizar el entorno de sesión desde el cliente cuando se crea una nueva sesión o se reasocia una antigua. tmate también inicializa la variable TMUX con información interna para permitir la ejecución de comandos desde el interior, y la variable TERM con la configuración de terminal correcta de 'screen'.

LÍNEA DE ESTADO

tmate incluye una línea de estado opcional que se muestra en la última línea de cada terminal. Por defecto, la línea de estado está habilitada (puede ser deshabilitada con la opción de sesión status) y contiene, de izquierda a derecha: el nombre de la sesión actual entre corchetes; la lista de ventanas; el título del panel activo entre comillas dobles; y la hora y fecha.

La línea de estado consta de tres partes: secciones izquierda y derecha configurables (que pueden contener contenido dinámico como la hora o la salida de un comando de shell, consulte las opciones status-left, status-left-length, status-right y status-right-length a continuación), y una lista de ventanas central. MODO DE CONTROL

tmate ofrece una interfaz textual llamada modo de control. Esto permite a las aplicaciones comunicarse con tmate utilizando un protocolo simple solo de texto.

En modo de control, un cliente envía comandos o secuencias de comandos de tmate terminados por saltos de línea en la entrada estándar. Cada comando producirá un bloque de salida en la salida estándar. Un bloque de salida consiste en una línea %begin seguida de la salida (que puede estar vacía). El bloque de salida termina con un %end o %error. %begin y el correspondiente %end o %error tienen dos argumentos: un entero de tiempo (segundos desde la época) y un número de comando. Por ejemplo:

%begin 1363006971 2
0: ksh* (1 panes) [80x24] [layout b25f,80x24,0,0,2] @2 (activo)
%end 1363006971 2

En modo de control, tmate emite notificaciones. Una notificación nunca ocurrirá dentro de un bloque de salida.

Las siguientes notificaciones están definidas:

%exit [razón]
El cliente de tmate está saliendo inmediatamente, ya sea porque no está adjunto a ninguna sesión o ocurrió un error. Si está presente, razón describe por qué el cliente salió.
%layout-change id-ventana layout-ventana layout-visible-ventana flags-ventana

EJEMPLOS

Para crear una nueva sesión de tmate ejecutando vi(1):

$ tmate new-session vi

La mayoría de los comandos tienen una forma más corta, conocida como alias. Para new-session, este es new:

$ tmate new vi

Alternativamente, se acepta la forma más corta no ambigua de un comando. Si hay varias opciones, se listan:

$ tmate n
comando ambiguo: n, podría ser: new-session, new-window, next-window

Dentro de una sesión activa, se puede crear una nueva ventana escribiendo ‘C-b c’ (Ctrl seguido de la tecla ‘b’ seguido de la tecla ‘c’).

Las ventanas se pueden navegar con: ‘C-b 0’ (para seleccionar la ventana 0), ‘C-b 1’ (para seleccionar la ventana 1), y así sucesivamente; ‘C-b n’ para seleccionar la siguiente ventana; y ‘C-b p’ para seleccionar la ventana anterior.

Una sesión se puede desvincular usando ‘C-b d’ (o por un evento externo como la desconexión de ssh(1)) y volver a vincular con:

$ tmate attach-session

Escribir ‘C -b ?’ muestra los enlaces de teclas actuales en la ventana actual; arriba y abajo se pueden usar para navegar por la lista o ‘q’ para salir de ella.

Los comandos que se ejecutarán cuando se inicie el servidor tmate se pueden colocar en el archivo de configuración ~/.tmux.conf. Ejemplos comunes incluyen:

Cambiar la tecla de prefijo predeterminada:

set-option -g prefix C-a
unbind-key C-b
bind-key C-a send-prefix

Desactivar la línea de estado o cambiar su color:

set-option -g status off
set-option -g status-style bg=blue

Establecer otras opciones, como el comando predeterminado, o bloquear después de 30 minutos de inactividad:

set-option -g default-command "exec /bin/ksh"
set-option -g lock-after-time 1800

Crear nuevos enlaces de teclas:

bind-key b set-option status
bind-key / command-prompt "split-window 'exec man %%'"
bind-key S command-prompt "new-window -n %1 'ssh %1'"
