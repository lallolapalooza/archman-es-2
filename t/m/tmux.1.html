NOMBRE

tmux — multiplexor de terminal

SINOPSIS

tmux [-2CDhlNuVv] [-c comando-shell] [-f archivo] [-L nombre-socket] [-S ruta-socket] [-T características] [comando [flags]]

DESCRIPCIÓN

tmux es un multiplexor de terminal: permite crear, acceder y controlar varios terminales desde una sola pantalla. tmux puede desconectarse de una pantalla y continuar ejecutándose en segundo plano, para luego ser reconectado.

tmux, al iniciarse, crea una nueva sesión con una sola ventana y la muestra en pantalla. Una línea de estado en la parte inferior de la pantalla muestra información sobre la sesión actual y se utiliza para introducir comandos interactivos.

Una sesión es una colección única de terminales virtuales bajo la gestión de tmux. Cada sesión tiene una o más ventanas enlazadas a ella. Una ventana ocupa toda la pantalla y puede dividirse en paneles rectangulares, cada uno de los cuales es un terminal virtual separado (la página del manual de pty(4) documenta los detalles técnicos de los terminales virtuales). Se puede conectar cualquier número de instancias de tmux a la misma sesión, y puede haber cualquier número de ventanas en la misma sesión. Una vez que todas las sesiones son eliminadas, tmux se cierra.

Cada sesión es persistente y sobrevivirá a desconexiones accidentales (como un tiempo de espera en la conexión de ssh(1)) o a desconexiones intencionales (con las combinaciones de teclas ‘C-b d’). tmux puede ser reconectado usando:

$ tmux attach

En tmux, una sesión es mostrada en pantalla por un cliente y todas las sesiones son gestionadas por un único servidor. El servidor y cada cliente son procesos separados que se comunican a través de un socket en /tmp.

Las opciones son las siguientes:

-2
Fuerza a tmux a asumir que el terminal soporta 256 colores. Esto es equivalente a -T 256.
-C
Inicia en modo de control (ver la sección MODO DE CONTROL). Dado dos veces (-CC) deshabilita el eco.
-c comando-shell
Ejecuta comando-shell usando el shell predeterminado. Si es necesario, se iniciará el servidor tmux para recuperar la opción default-shell. Esta opción es para compatibilidad con sh(1) cuando tmux se usa como shell de inicio de sesión.
-D
No inicia el servidor tmux como demonio. Esto también desactiva la opción exit-empty. Con -D, no se puede especificar comando.
-f archivo
Especifica un archivo de configuración alternativo. Por defecto, tmux carga el archivo de configuración del sistema desde /etc/tmux.conf, si existe, luego busca un archivo de configuración de usuario en ~/.tmux.conf o $XDG_CONFIG_HOME/tmux/tmux.conf.

El archivo de configuración es un conjunto de comandos de tmux que se ejecutan secuencialmente cuando el servidor se inicia por primera vez. tmux carga los archivos de configuración una vez cuando el proceso del servidor ha comenzado. El comando source-file puede ser usado para cargar un archivo más tarde.

tmux muestra cualquier mensaje de error de los comandos en los archivos de configuración en la primera sesión creada, y continúa procesando el resto del archivo de configuración.

-h
Muestra información de uso y sale.
-L nombre-socket
tmux almacena el socket del servidor en un directorio bajo TMUX_TMPDIR o /tmp si no está definido. El socket predeterminado se llama default. Esta opción permite especificar un nombre de socket diferente, lo que permite ejecutar varios servidores tmux independientes. A diferencia de -S, no es necesario una ruta completa: todos los sockets se crean en un directorio tmux-UID bajo el directorio dado por TMUX_TMPDIR o en /tmp. El directorio tmux-UID es creado por tmux y no debe ser legible, escribible o ejecutable por todos.

Si el socket es eliminado accidentalmente, la señal SIGUSR1 puede ser enviada al proceso servidor de tmux para recrearlo (ten en cuenta que esto fallará si faltan directorios padre).

-l
Comportarse como un shell de inicio de sesión. Esta bandera actualmente no tiene efecto y es para compatibilidad con otros shells cuando se usa tmux como shell de inicio de sesión.
-N
No iniciar el servidor incluso si el comando normalmente lo haría (por ejemplo new-session o start-server).
-S ruta-socket
Especifica una ruta alternativa completa al socket del servidor. Si se especifica -S, no se utiliza el directorio de socket predeterminado y se ignora cualquier bandera -L.
-T características
Establece las características del terminal para el cliente. Esta es una lista separada por comas de características. Ver la opción terminal-features.
-u
Escribe salida UTF-8 al terminal incluso si la primera variable de entorno LC_ALL, LC_CTYPE, o LANG que esté establecida no contiene "UTF-8" o "UTF8".
-V
Reporta la versión de tmux.
-v
Solicita registro detallado. Los mensajes de registro se guardarán en archivos tmux-client-PID.log y tmux-server-PID.log en el directorio actual, donde PID es el PID del proceso servidor o cliente. Si -v se especifica dos veces, se genera un archivo adicional tmux-out-PID.log con una copia de todo lo que tmux escribe en el terminal.

La señal SIGUSR2 puede ser enviada al proceso servidor de tmux para alternar el registro entre activado (como si se hubiera dado -v) y desactivado.

comando [flags]
Esto especifica uno de un conjunto de comandos utilizados para controlar tmux, como se describe en las siguientes secciones. Si no se especifican comandos, se asume el comando en default-client-command, que por defecto es new-session.

%if #{==:#{host},myhost} set -g status-style bg=red %endif

COMANDOS

Esta sección describe los comandos compatibles con tmux. La mayoría de los comandos aceptan el argumento opcional -t (y a veces -s) con uno de cliente-objetivo, sesión-objetivo, ventana-objetivo o panel-objetivo. Estos especifican el cliente, sesión, ventana o panel que un comando debe afectar.

cliente-objetivo debe ser el nombre del cliente, típicamente el archivo pty(4) al que está conectado el cliente, por ejemplo, cualquiera de /dev/ttyp1 o ttyp1 para el cliente conectado a /dev/ttyp1. Si no se especifica ningún cliente, tmux intenta determinar el cliente actualmente en uso; si falla, se informa un error. Los clientes se pueden listar con el comando list-clients.

sesión-objetivo se intenta de la siguiente manera, en orden:

  1. Un ID de sesión prefijado con un $.
  2. Un nombre exacto de una sesión (como se lista en el comando list-sessions).
  3. El inicio de un nombre de sesión, por ejemplo, ‘mysess’ coincidiría con una sesión llamada ‘mysession’.
  4. Un patrón glob(7) que se compara con el nombre de la sesión.

Si el nombre de la sesión está prefijado con un ‘=’, solo se acepta una coincidencia exacta (por lo que ‘=mysess’ solo coincidirá exactamente con ‘mysess’, no con ‘mysession’).

Si se encuentra una sola sesión, se utiliza como sesión objetivo; múltiples coincidencias producen un error. Si se omite una sesión, se utiliza la sesión actual si está disponible; si no hay una sesión actual disponible, se elige la utilizada más recientemente.

ventana-objetivo (o ventana-fuente o ventana-destino) especifica una ventana en el formato sesión:ventana. sesión sigue las mismas reglas que para sesión-objetivo, y ventana se busca en orden como:

  1. Un token especial, listado a continuación.
  2. Un índice de ventana, por ejemplo ‘mysession:1’ es la ventana 1 en la sesión ‘mysession’.
  3. Un ID de ventana, como @1.
  4. Un nombre exacto de ventana, como ‘mysession:mywindow’.
  5. El inicio de un nombre de ventana, como ‘mysession:mywin’.
  6. Como un patrón glob(7) que se compara con el nombre de la ventana.

Al igual que con las sesiones, un prefijo ‘=’ solo realizará una coincidencia exacta. Un nombre de ventana vacío especifica el siguiente índice no utilizado si es apropiado (por ejemplo, los comandos new-window y link-window) de lo contrario, se elige la ventana actual en sesión.

Los siguientes tokens especiales están disponibles para indicar ventanas particulares. Cada uno tiene una forma alternativa de un solo carácter.

Token Significado
{start} ^ La ventana con el número más bajo
{end} $ La ventana con el número más alto
{last} ! La última ventana (previamente actual)
{next} + La siguiente ventana por número
{previous} - La ventana anterior por número

panel-objetivo (o panel-fuente o panel-destino) puede ser un ID de panel o toma una forma similar a ventana-objetivo pero con la adición opcional de un punto seguido de un índice de panel o ID de panel, por ejemplo: ‘mysession:mywindow.1’. Si se omite el índice del panel, se utiliza el panel activo actual en la ventana especificada. Los siguientes tokens especiales están disponibles para el índice del panel:

Token Significado
{last} ! El último panel (previamente activo)
{next} + El siguiente panel por número
{previous} - El panel anterior por número
{top} El panel superior
{bottom} El panel inferior
{left} El panel más a la izquierda
{right} El panel más a la derecha
{top-left} El panel superior izquierdo
{top-right} El panel superior derecho
{bottom-left} El panel inferior izquierdo
{bottom-right} El panel inferior derecho
{up-of} El panel encima del panel activo
{down-of}
El panel debajo del panel activo
{left-of} El panel a la izquierda del panel activo
{right-of} El panel a la derecha del panel activo

Los tokens ‘+’ y ‘-’ pueden ir seguidos de un desplazamiento, por ejemplo:

select-window -t:+2

Además, target-session, target-window o target-pane pueden consistir completamente en el token ‘{mouse}’ (forma alternativa ‘=’) para especificar la sesión, ventana o panel donde ocurrió el evento de ratón más reciente (ver la sección MOUSE SUPPORT) o ‘{marked}’ (forma alternativa ‘~’) para especificar el panel marcado (ver select-pane -m).

Las sesiones, ventanas y paneles se numeran con un ID único; los ID de sesión van precedidos por un ‘$’, las ventanas por un ‘@’ y los paneles por un ‘%’. Estos son únicos y no cambian durante la vida de la sesión, ventana o panel en el servidor tmux. El ID del panel se pasa al proceso hijo del panel en la variable de entorno TMUX_PANE. Los ID se pueden mostrar usando los formatos ‘session_id’, ‘window_id’ o ‘pane_id’ (ver la sección FORMATS) y los comandos display-message, list-sessions, list-windows o list-panes.

shell-command los argumentos son comandos de sh(1). Puede ser un solo argumento pasado al shell, por ejemplo:

new-window 'vi ~/.tmux.conf'

Ejecutará:

/bin/sh -c 'vi ~/.tmux.conf'

Adicionalmente, los comandos new-window, new-session, split-window, respawn-window y respawn-pane permiten que shell-command se proporcione como múltiples argumentos y se ejecute directamente (sin ‘sh -c’). Esto puede evitar problemas con las comillas del shell. Por ejemplo:

$ tmux new-window vi ~/.tmux.conf

Ejecutará vi(1) directamente sin invocar el shell.

command [argument ...] se refiere a un comando de tmux, ya sea pasado con el comando y los argumentos por separado, por ejemplo:

bind-key F1 set-option status off

O pasado como un único argumento de cadena en .tmux.conf, por ejemplo:

bind-key F1 { set-option status off }

Ejemplos de comandos de tmux incluyen:

refresh-client -t/dev/ttyp2

rename-session -tfirst newname

set-option -wt:0 monitor-activity on

new-window ; split-window -d

bind-key R source-file ~/.tmux.conf \; \
	display-message "source-file done"

O desde sh(1):

$ tmux kill-window -t :1

$ tmux new-window \; split-window -d

$ tmux new-session -d 'vi ~/.tmux.conf' \; split-window -d \; attach

CLIENTES Y SESIONES

El servidor tmux gestiona clientes, sesiones, ventanas y paneles. Los clientes se adjuntan a las sesiones para interactuar con ellas, ya sea cuando se crean con el comando new-session, o más tarde con el comando attach-session. Cada sesión tiene una o más ventanas enlazadas en ella. Las ventanas pueden enlazarse a múltiples sesiones y están compuestas por uno o más paneles, cada uno de los cuales contiene un pseudo terminal. Los comandos para crear, enlazar y manipular ventanas se cubren en la sección WINDOWS AND PANES.

Los siguientes comandos están disponibles para gestionar clientes y sesiones:

attach-session [-dErx] [-c working-directory] [-f flags] [-t target-session]
(alias: attach)
Si se ejecuta desde fuera de tmux, adjúntate a target-session en el terminal actual. target-session debe existir ya; para crear una nueva sesión, ver el comando new-session (con -A para crear o adjuntar). Si se usa desde dentro, cambia la sesión adjunta actualmente a target-session. Si se especifica -d, cualquier otro cliente adjunto a la sesión se desadjuntará. Si se usa -x, envía SIGHUP al proceso padre del cliente además de desadjuntar el cliente, lo que típicamente provoca su salida. -f establece una lista separada por comas de indicadores del cliente. Los indicadores son:
active-pane
el cliente tiene un panel activo independiente
ignore-size
el cliente no afecta al tamaño de otros clientes
no-detach-on-destroy
no desadjuntar el cliente cuando la sesión a la que está adjunto sea destruida si hay alguna otra sesión
no-output
el cliente no recibe salida del panel en modo de control
pause-after=seconds
la salida se pausa una vez que el panel está segundos atrasado en modo de control
read-only
el cliente es de solo lectura
wait-exit
esperar una línea de entrada vacía antes de salir en modo de control

Un ‘!’ inicial apaga un indicador si el cliente ya está adjunto. -r es un alias de -f read-only,ignore-size. Cuando un cliente es de solo lectura, solo las teclas enlazadas a los comandos detach-client o switch-client tienen algún efecto. Un cliente con el indicador active-pane permite que el panel activo se seleccione independientemente del panel activo de la ventana utilizado por clientes sin este indicador. Esto solo afecta la posición del cursor y los comandos emitidos desde el cliente; otras características como hooks y estilos continúan usando el panel activo de la ventana.

Si no se inicia ningún servidor, attach-session intentará iniciarlo; esto fallará a menos que las sesiones se creen en el archivo de configuración.

Las reglas de target-session para attach-session se ajustan ligeramente: si tmux necesita seleccionar la sesión usada más recientemente, preferirá la sesión no adjunta usada más recientemente.

-c establecerá el directorio de trabajo de la sesión (usado para nuevas ventanas) a working-directory.

Si se usa -E, la opción update-environment no se aplicará.

detach-client [-aP] [-E shell-command] [-s target-session] [-t target-client]
(alias: detach)
Desconecta el cliente actual si está enlazado a una tecla, el cliente especificado con -t, o todos los clientes actualmente adjuntos a la sesión especificada por -s. La opción -a mata a todos menos al cliente dado con -t. Si se usa -P, envía SIGHUP al proceso padre del cliente, lo que típicamente causa su salida. Con -E, ejecuta shell-command para reemplazar al cliente.
has-session [-t target-session]
(alias: has)
Reporta un error y sale con 1 si la sesión especificada no existe. Si existe, sale con 0.
kill-server
Mata el servidor tmux y los clientes y destruye todas las sesiones.
kill-session [-aC] [-t target-session]
Destruye la sesión dada, cerrando cualquier ventana enlazada a ella y a ninguna otra sesión, y desadjuntando todos los clientes adjuntos a ella. Si se usa -a, se matan todas las sesiones excepto la especificada. El indicador -C borra las alertas (campana, actividad o silencio) en todas las ventanas enlazadas a la sesión.
list-clients [-F format] [-f filter] [-t target-session]
list-clients [] [] [sesión-objetivo] (lsc) Lista todos los clientes conectados al servidor. especifica el formato de cada línea y un filtro. Solo se muestran los clientes para los que el filtro es verdadero. Ver la sección FORMATS. Si se especifica sesión-objetivo, lista solo los clientes conectados a esa sesión. list-commands [] [comando] (lscm) Lista la sintaxis de comando o, si se omite, de todos los comandos soportados por tmux. list-sessions [] [] (ls) Lista todas las sesiones gestionadas por el servidor. especifica el formato de cada línea y un filtro. Solo se muestran las sesiones para las que el filtro es verdadero. Ver la sección FORMATS. lock-client [] (lockc) Bloquea cliente-objetivo, ver el comando lock-server. lock-session [] (locks) Bloquea todos los clientes conectados a sesión-objetivo. new-session [] [] [] [] [] [] [] [] [] [] [comando-shell [argumento ...]] (new) Crea una nueva sesión con el nombre nombre-sesión.

La nueva sesión se adjunta al terminal actual a menos que se proporcione . nombre-ventana y comando-shell son el nombre y el comando de shell a ejecutar en la ventana inicial. Con , el tamaño inicial proviene de la opción global ; y se pueden usar para especificar un tamaño diferente. ‘-’ usa el tamaño del cliente actual si lo hay. Si se proporciona o , la opción se establece para la sesión. establece una lista separada por comas de banderas de cliente (ver attach-session).

La bandera hace que new-session se comporte como attach-session si nombre-sesión ya existe; si se proporciona , se comporta como para attach-session, y se comporta como para attach-session.

Si se proporciona , especifica un grupo de sesiones. Las sesiones del mismo grupo comparten el mismo conjunto de ventanas: las nuevas ventanas se enlazan a todas las sesiones del grupo y cualquier ventana cerrada se elimina de todas las sesiones. main-horizontal
Se muestra un panel grande (principal) en la parte superior de la ventana y los paneles restantes se distribuyen de izquierda a derecha en el espacio sobrante en la parte inferior. Utilice la opción de ventana main-pane-height para especificar la altura del panel superior.
main-horizontal-mirrored
Lo mismo que main-horizontal pero reflejado, de modo que el panel principal esté en la parte inferior de la ventana.
main-vertical
Se muestra un panel grande (principal) a la izquierda de la ventana y los paneles restantes se distribuyen de arriba a abajo en el espacio sobrante a la derecha. Utilice la opción de ventana main-pane-width para especificar el ancho del panel izquierdo.
main-vertical-mirrored
Lo mismo que main-vertical pero reflejado, de modo que el panel principal esté a la derecha de la ventana.
tiled
Los paneles se distribuyen lo más uniformemente posible por la ventana, tanto en filas como en columnas.

Además, se puede utilizar select-layout para aplicar un diseño utilizado previamente. El comando list-windows muestra el diseño de cada ventana en un formato adecuado para su uso con select-layout. Por ejemplo:

$ tmux list-windows
0: ksh [159x48]
    layout: bb62,159x48,0,0{79x48,0,0,79x48,80,0}
$ tmux select-layout 'bb62,159x48,0,0{79x48,0,0,79x48,80,0}'

tmux ajusta automáticamente el tamaño del diseño al tamaño actual de la ventana. Tenga en cuenta que un diseño no se puede aplicar a una ventana con más paneles que aquellos de los que se definió originalmente el diseño.

break-pane [-abdP] [-F formato] [-n nombre-ventana] [-s panel-origen] [-t ventana-destino]
(alias: breakp)
Separa el panel-origen de su ventana contenedora para convertirlo en el único panel de la ventana-destino. Con -a o -b, la ventana se mueve al siguiente índice después o antes (se mueven las ventanas existentes si es necesario). Si se proporciona -d, la nueva ventana no se convierte en la ventana actual. La opción -P imprime información sobre la nueva ventana después de haber sido creada. Por defecto, utiliza el formato ‘#{session_name}:#{window_index}.#{pane_index}’, pero se puede especificar un formato diferente con -F.
capture-pane [-aepPqCJMN] [-b nombre-buffer] [-E linea-fin] [-S linea-inicio] [-t panel-objetivo]
(alias: capturep)
Captura el contenido de un panel. Si se proporciona -p, la salida va a stdout, de lo contrario va al buffer especificado con -b o a un nuevo buffer si se omite. Si se proporciona -a, se utiliza la pantalla alternativa y no se puede acceder al historial. Si no existe una pantalla alternativa, se devolverá un error a menos que se proporcione -q. De manera similar, si el panel está en modo, -M utiliza la pantalla para el modo. Si se proporciona -e, la salida incluye secuencias de escape para los atributos de texto y fondo. -C también escapa los caracteres no imprimibles como octales \xxx. -T ignora las posiciones finales que no contienen un carácter. -N conserva los espacios finales en el final de cada línea y -J conserva los espacios finales y une las líneas envueltas; -J implica -T. -P captura solo la salida que el panel ha recibido y que es el comienzo de una secuencia de escape aún incompleta.

-S y -E especifican los números de línea de inicio y fin, cero es la primera línea del panel visible y los números negativos son líneas del historial. ‘-’ para -S es el inicio del historial y para -E el final del panel visible. Por defecto, se captura solo el contenido visible del panel.

new-window [-abdkPS] [-c start-directory] [-e environment] [-F format] [-n window-name] [-t target-window] [shell-command [argument ...]]
(alias: neww)
Crea una nueva ventana. Con -a o -b, la nueva ventana se inserta en el índice siguiente después o antes de la target-window especificada, moviendo las ventanas hacia arriba si es necesario; de lo contrario, target-window es la ubicación de la nueva ventana.

Si se proporciona -d, la sesión no convierte la nueva ventana en la ventana actual. target-window representa la ventana que se va a crear; si el objetivo ya existe, se muestra un error, a menos que se use la bandera -k, en cuyo caso se destruye. Si se proporciona -S y ya existe una ventana llamada window-name, se selecciona (a menos que también se proporcione -d, en cuyo caso el comando no hace nada).

shell-command es el comando a ejecutar. Si no se especifica shell-command, se utiliza el valor de la opción default-command. -c especifica el directorio de trabajo en el que se crea la nueva ventana.

Cuando el comando del shell finaliza, la ventana se cierra. Consulte la opción remain-on-exit para cambiar este comportamiento.

-e tiene el formato ‘VARIABLE=value’ y establece una variable de entorno para la ventana recién creada; puede especificarse varias veces.

La variable de entorno TERM debe establecerse en ‘screen’ o ‘tmux’ para todos los programas que ejecuten un programa en segundo plano.

new-window [-adkP] [-c start-directory] [-e environment] [-F format] [-n window-name] [-t target-window] [shell-command [argument ...]]
(alias: neww)
Create a new window. If shell-command is specified, it is executed in the new window; otherwise the value of the default-command option is used. The new window is inserted after target-window if -t is used, otherwise it is added to the end of the session.

-a causes the new window to be added to the start of the session.

-d causes the new window to be created without making it the current window.

-k causes any existing window with the same name to be killed before the new one is created.

The -c option specifies the initial directory for the new window. If this is not given, the initial directory is the one specified by the default-directory option. If the default-directory option is not set, the current directory is used.

The -e option takes an environment variable to set, which should be in the form NAME=VALUE. This option can be used multiple times to set multiple variables. The environment is inherited from the parent process unless overridden here.

The -n option specifies a name for the new window. If this is not given, the name is taken from the base name of the shell-command or default-command.

The -P option prints information about the new window after it has been created. By default, it uses the format ‘#{session_name}:#{window_index}’ but a different format may be specified with -F.

inside

tmux. New windows will automatically have ‘TERM=screen’ added to their environment, but care must be taken not to reset this in shell start-up files or by the -e option.

KEY BINDINGS

tmux allows a command to be bound to most keys, with or without a prefix key. When specifying keys, most represent themselves (for example ‘A’ to ‘Z’). Ctrl keys may be prefixed with ‘C-’ or ‘^’, Shift keys with ‘S-’ and Alt (meta) with ‘M-’. In addition, the following special key names are accepted: Up, Down, Left, Right, BSpace, BTab, DC (Delete), End, Enter, Escape, F1 to F12, Home, IC (Insert), NPage/PageDown/PgDn, PPage/PageUp/PgUp, Space, and Tab. Note that to bind the ‘"’ or ‘'’ keys, quotation marks are necessary, for example:

bind-key '"' split-window
bind-key "'" new-window

A command bound to the Any key will execute for all keys which do not have a more specific binding.

Commands related to key bindings are as follows:

bind-key [-nr] [-N note] [-T key-table] key [command [argument ...]]
(alias: bind)

Bind key key to command. Keys are bound in a key table. By default (without -T), the key is bound in the prefix key table. This table is used for keys pressed after the prefix key (for example, by default ‘c’ is bound to new-window in the prefix table, so ‘C-b c’ creates a new window). The root table is used for keys pressed without the prefix key: binding ‘c’ to new-window in the root table (not recommended) means a plain ‘c’ will create a new window. -n is an alias for -T root. Keys may also be bound in custom key tables and the switch-client -T command used to switch to them from a key binding. The -r flag indicates this key may repeat, see the initial-repeat-time and repeat-time options. -N attaches a note to the key (shown with list-keys -N), which can be cleared by passing an empty string. The -r and -N flags can be used without command to alter an existing binding.

To view the default bindings and possible commands, see the list-keys command.

list-keys [-1aN] [-P prefix-string] [-T key-table] [key]
(alias: lsk)

List key bindings. There are two forms: the default lists keys as bind-key commands; -N lists only keys with attached notes and shows only the key and note for each key.

With the default form, all key tables are listed by default. -T lists only keys in key-table.

tmux
NAME

tmux - control multiplexer server

SYNOPSIS

tmux socket-path socket-path command

tmux target-pane key

tmux target-pane command

tmux target-pane key ...

tmux target-pane

tmux key-table key

DESCRIPTION

The tmux utility is a terminal multiplexer that allows a number of terminals to be created, detached from, and re-attached to a process. It maps main terminals onto character cell terminals. As the main terminals are not limited to the number of available physical terminals or any other hardware support, they can be very numerous.

Each tmux command is composed of options, windows and panes.

A window is a single screen containing one or more panes.

A pane is a rectangular region within a window.

The tmux server multiplexes a set of character cell terminals into a single display, allowing viewing and control of multiple terminals from a single client.

When tmux starts, it first checks for an existing server process. If none is found, it starts a new one. It then finds or creates a client attached to the server. The client will create a new session unless one already exists that it can attach to.

If the tmux command is run from within a tmux client, the command is passed to the server to be executed.

If no command is specified, the new-session command is run.

Options are set using the set-option command.

The key-bindings are used to control tmux.

When the tmux client is created, it looks for an existing server process; if none exists, it starts a new one. The client then creates a new session unless it is attached to an existing one.

A new client is created to connect to the server. If no server is running, one is started.

The default key bindings are described below.

The tmux server manages tmux sessions. When the last client detaches, the server continues to run. It can be killed using the kill-server command.

OPTIONS

The appearance and behaviour of tmux may be modified by changing the value of various options. Each option belongs to one or multiple scopes (server, session, window, and pane) and has a type (string, number, key, colour, flag, choice, or command). Values of flag-type options may be one of: 1, on, yes, 0, off, or no; for possible choice values, see the respective option; for key options, the KEY BINDINGS section; and for colour options, the STYLES section.

The tmux server has a set of global server options which do not apply to any particular window or session or pane. These are altered with the set-option -s command, or displayed with the show-options -s command.

In addition, each individual session may have a set of session options, and there is a separate set of global session options. Sessions which do not have a particular option configured inherit the value from the global session options. Session options are set or unset with the set-option command and may be listed with the show-options command. The available server and session options are listed under the set-option command.

Similarly, a set of window options is attached to each window and a set of pane options to each pane. Pane options inherit from window options. This means any pane option may be set as a window option to apply the option to all panes in the window without the option set, for example these commands will set the background colour to red for all panes except pane 0:

set -w window-style bg=red
set -pt:.0 window-style bg=blue

There is also a set of global window options from which any unset window or pane options are inherited. Window and pane options are altered with set-option -w and -p commands and displayed with show-option -w and -p.

tmux also supports user options which are prefixed with a ‘@’. User options may have any name, so long as they are prefixed with ‘@’, and be set to any string. For example:

$ tmux set -wq @foo "abc123"
$ tmux show -wv @foo
abc123

Options are managed with these commands:

EXAMPLE

Start tmux and run the command:

$ tmux new-session -d \; \
    pipe-pane "ls -l" \; \
    split-window -h \; \
    split-window -v \; \
    select-pane -t 1 \; \
    send-keys "htop" C-m

This starts a new detached session, runs ls -l in the initial pane, splits the window horizontally and vertically, selects the second pane, and runs htop in it.

GANCHOS

\n

tmux permite que los comandos se ejecuten con varios\ndisparadores, llamados\nganchos.\nLa mayoría de los comandos de tmux tienen un gancho\nafter\ny hay una serie de ganchos no asociados con comandos.

\n

Los ganchos se almacenan como opciones de matriz, los miembros de la matriz se ejecutan en orden cuando se activa el gancho. Al igual que las opciones, diferentes ganchos pueden ser globales o pertenecer a una sesión, ventana o panel. Los ganchos se pueden configurar con los comandos\nset-hook o set-option y se muestran con\nshow-hooks o show-options\n-H. Los dos comandos siguientes son equivalentes:

\n
\n
set-hook -g pane-mode-changed[42] 'set -g status-left-style bg=red'\nset-option -g pane-mode-changed[42] 'set -g status-left-style bg=red'
\n
\n

Establecer un gancho sin especificar un índice de matriz borra el gancho y establece el primer miembro de la matriz.

\n

El gancho after de un comando se ejecuta después de que se completa, excepto cuando el comando se ejecuta como parte de un gancho en sí. Se nombran con un prefijo\n‘after-’. Por ejemplo, el siguiente comando agrega un gancho para seleccionar el diseño vertical par después de cada\nsplit-window:

\n
\n
set-hook -g after-split-window "selectl even-vertical"
\n
\n

Si un comando falla, se activará el gancho\n‘command-error’. Por ejemplo, esto podría usarse para escribir en un archivo de registro:

\n
\n
set-hook -g command-error "run-shell \"echo 'a tmux command failed' >>/tmp/log\""

FORMATOS

Ciertos comandos aceptan la bandera -F con un argumento format. Esta es una cadena que controla el formato de salida del comando. Las variables de formato están encerradas entre ‘#{’ y ‘}’, por ejemplo ‘#{session_name}’. Las variables posibles se enumeran en la tabla siguiente, o se puede utilizar el nombre de una opción de tmux para el valor de una opción, o el nombre de una variable de entorno. Algunas variables tienen un alias más corto como ‘#S’; ‘##’ se reemplaza por un solo ‘#’, ‘#,’ por una ‘,’ y ‘#}’ por una ‘}’.

Los condicionales están disponibles anteponiendo ‘?’. Por cada par de dos argumentos, si la variable en el primero del par existe y no es cero, se elige el segundo del par, de lo contrario continúa. Si ningún condicional de los argumentos emparejados coincide, se elige el valor predeterminado. Si no hay un argumento final sin emparejar, ese es el valor predeterminado. Si no, el valor predeterminado es la cadena vacía. Por ejemplo ‘#{?session_attached,attached,not attached}’ incluirá la cadena ‘attached’ si la sesión está adjunta y la cadena ‘not attached’ si no lo está, o ‘#{?automatic-rename,yes,no}’ incluirá ‘yes’ si automatic-rename está habilitado, o ‘no’ si no. ‘#{?#{n:window_name},#{window_name} - }’ incluirá el nombre de la ventana con un separador de guion si hay un nombre de ventana, o la cadena vacía si el nombre de la ventana está vacío. ‘#{?session_format,format1,window_format,format2,format3}’ incluirá format1 para un formato de sesión, format2 para un formato de ventana, o format3 para ningún formato de sesión ni de ventana. Los condicionales pueden anidarse arbitrariamente. Dentro de un condicional, ‘,’ y ‘}’ deben escaparse como ‘#,’ y ‘#}’, a menos que formen parte de un reemplazo ‘#{...}’. Por ejemplo:

#{?pane_in_mode,#[fg=white#,bg=red],#[fg=red#,bg=white]}#W

Las comparaciones de cadenas pueden expresarse anteponiendo dos alternativas separadas por comas a ‘==’, ‘!=’, ‘<’, ‘>’, ‘<=’ o ‘>=’ y dos puntos. Por ejemplo ‘#{==:#{host},myhost}’ se reemplazará por ‘1’ si se ejecuta en ‘myhost’, de lo contrario por ‘0’. ‘||’ y ‘&&’ se evalúan como verdaderos si alguna o todas las alternativas separadas por comas son verdaderas, por ejemplo ‘#{||:#{pane_in_mode},#{alternate_on}}’. ‘!’ se evalúa como verdadero si el valor es falso y viceversa, por ejemplo ‘#{!:#{pane_in_mode}}’. ‘!!’ convierte un valor a una forma booleana canónica, 1 para verdadero y 0 para falso, por ejemplo ‘#{!!:non-empty string}’ se evalúa como 1.

Una ‘m’ especifica un patrón glob(7) o una comparación de expresión regular. El primer argumento es el patrón y el segundo la cadena a comparar. Un argumento opcional especifica indicadores: ‘r’ significa que el patrón es una expresión regular en lugar del patrón predeterminado glob(7), y ‘i’ significa ignorar mayúsculas y minúsculas. Por ejemplo: ‘#{m:*foo*,#{host}}’ o ‘#{m/ri:^A,MYVAR}’. Una ‘C’ realiza una búsqueda de un patrón glob(7) o expresión regular en el contenido del panel y se evalúa a cero si no se encuentra, o al número de línea si se encuentra. Al igual que ‘m’, un indicador ‘r’ significa buscar una expresión regular y ‘i’ ignora mayúsculas y minúsculas. Por ejemplo: ‘#{C/r:^Start}’

Se pueden realizar operadores numéricos anteponiendo dos alternativas separadas por comas a una ‘e’ y un operador. Se puede dar un indicador opcional ‘f’ después del operador para usar números de punto flotante, de lo contrario se usan enteros. Esto puede ir seguido de un número que indique el número de decimales a usar para el resultado. Los operadores disponibles son: suma ‘+’, resta ‘-’, multiplicación ‘*’, división ‘/’, módulo ‘m’ o ‘%’ (tenga en cuenta que ‘%’ debe escaparse como ‘%%’ en formatos que también son expandidos por strftime(3)) y operadores de comparación numéricos ‘==’, ‘!=’, ‘<’, ‘<=’, ‘>’ y ‘>=’. Por ejemplo, ‘#{e|*|f|4:5.5,3}’ multiplica 5.5 por 3 para un resultado con cuatro decimales y ‘#{e|%%:7,3}’ devuelve el módulo de 7 y 3. ‘a’ reemplaza un argumento numérico por su equivalente ASCII, por lo que ‘#{a:98}’ resulta en ‘b’. ‘c’ reemplaza un color de tmux por su valor hexadecimal RGB de seis dígitos.

Se puede colocar un límite a la longitud de la cadena resultante anteponiéndola con un ‘=’, un número y dos puntos. Los números positivos cuentan desde el principio de la cadena y los negativos desde el final, por lo que ‘#{=5:pane_title}’ incluirá como máximo los primeros cinco caracteres del título del panel, o ‘#{=-5:pane_title}’ los últimos cinco caracteres. Se puede dar un sufijo o prefijo como segundo argumento; si se proporciona, se añade o antepone a la cadena si la longitud se ha recortado, por ejemplo ‘#{=/5/...:pane_title}’ añadirá ‘...’ si el título del panel tiene más de cinco caracteres. De manera similar, ‘p’ rellena la cadena a un ancho dado, por ejemplo ‘#{p10:pane_title}’ resultará en un ancho de al menos 10 caracteres. Un ancho positivo rellena a la izquierda, uno negativo a la derecha. ‘n’ se expande a la longitud de la variable y ‘w’ a su ancho al mostrarse, por ejemplo ‘#{n:window_name}’. ‘R’ repite el primer argumento un número de veces dado por el segundo argumento, por lo que ‘#{R:a,3}’ resultará en ‘aaa’.

Anteponer ‘t:’ a una variable de tiempo la convertirá en una cadena, así si ‘#{window_activity}’ da ‘1445765102’, ‘#{t:window_activity}’ dará ‘Sun Oct 25 09:25:02 2015’. Añadir ‘p (’ ‘`t/p`’) usará un formato de tiempo más corto pero menos preciso para

tiempos en el pasado. Se puede dar un formato personalizado utilizando un sufijo ‘f’ (tenga en cuenta que ‘%’ debe escaparse como ‘%%’ si el formato se pasa por separado a través de strftime(3), por ejemplo en la opción status-left): ‘#{t/f/%%H#:%%M:window_activity}’, véase strftime(3).

Los prefijos ‘b:’ y ‘d:’ son el basename(3) y dirname(3) de la variable respectivamente. ‘q:’ escapará los caracteres especiales de sh(1) o con un sufijo ‘h’, escapará los caracteres de hash (de modo que ‘#’ se convierte en ‘##’). ‘E:’ expandirá el formato dos veces, por ejemplo ‘#{E:status-left}’ es el resultado de expandir el contenido de la opción status-left en lugar de la opción en sí. ‘T:’ es como ‘E:’ pero también expande los especificadores de strftime(3). ‘S:’, ‘W:’, ‘P:’ o ‘L:’ iterarán sobre cada sesión, ventana, panel o cliente e insertarán el formato una vez por cada uno. ‘L:’, ‘S:’ y ‘W:’ pueden tomar un argumento de ordenación opcional ‘/i’, ‘/n’, ‘/t’ para ordenar por índice, nombre o hora de la última actividad; además ‘/r’ para ordenar en orden inverso. ‘/r’ también se puede usar con ‘P:’ para invertir el orden de ordenación por índice de panel. Por ejemplo, ‘S/nr:’ para ordenar las sesiones por nombre en orden inverso. Para cada uno, se pueden dar dos formatos separados por comas: el segundo se utiliza para la ventana actual, el panel activo o la sesión activa. Por ejemplo, para obtener una lista de ventanas con el formato de la línea de estado:

#{W:#{E:window-status-format} ,#{E:window-status-current-format} }

‘N:’ comprueba si existe un nombre de ventana (sin sufijo o con el sufijo ‘w’) o de sesión (con el sufijo ‘s’), por ejemplo ‘`N/w:foo`’ se reemplaza por 1 si existe una ventana llamada ‘foo’.

Un prefijo de la forma ‘s/foo/bar/:’ sustituirá ‘foo’ por ‘bar’ en todas partes. El primer argumento puede ser una expresión regular extendida y un argumento final puede ser ‘i’ para ignorar mayúsculas/minúsculas, por ejemplo ‘s/a(.)/\1x/i:’ cambiaría ‘abABab’ a ‘bxBxbx’. También se puede usar un carácter delimitador diferente, para evitar colisiones con barras literales en el patrón. Por ejemplo, ‘s|foo/|bar/|:’ sustituirá ‘foo/’ por ‘bar/’ en todas partes.

Se pueden separar múltiples modificadores con un punto y coma (;), como en ‘#{T;=10:status-left}’, lo que limita la cadena resultante expandida por strftime(3) a un máximo de 10 caracteres.

Además, la última línea de la salida de un comando de shell se puede insertar usando ‘#()’. Por ejemplo, ‘#(uptime)’ insertará el tiempo de actividad del sistema. Al construir formatos, tmux no espera a que los comandos ‘#()’ terminen; en su lugar, se utiliza el resultado anterior de ejecutar el mismo comando, o un marcador de posición si el comando no se ha ejecutado antes. Si el comando no ha terminado, se utilizará la línea de salida más reciente, pero la línea de estado no se actualizará más de una vez al segundo. Los comandos se ejecutan usando /bin/sh y con el entorno global de tmux establecido (ver la sección ENTORNO GLOBAL Y DE SESIÓN).

Una ‘l’ especifica que una cadena debe interpretarse literalmente y no expandirse. Por ejemplo ‘#{l:#{?pane_in_mode,yes,no}}’ se reemplazará por ‘#{?pane_in_mode,yes,no}’.

STYLES

tmux offers various options to specify the colour and attributes of aspects of the interface, for example status-style for the status line. In addition, embedded styles may be specified in format options, such as status-left, by enclosing them in ‘#[’ and ‘]’.

A style may be the single term ‘default’ to specify the default style (which may come from an option, for example status-style in the status line) or a space or comma separated list of the following:

fg=colour
Set the foreground colour. The colour is one of: black, red, green, yellow, blue, magenta, cyan, white; if supported the bright variants brightblack, brightred, ...; colour0 to colour255 from the 256-colour set; default for the default colour; terminal for the terminal default colour; or a hexadecimal RGB string such as ‘#rgb’ or ‘#rrggbb’.
bg=colour
Set the background colour. The colour is one of: black, red, green, yellow, blue, magenta, cyan, white; if supported the bright variants brightblack, brightred, ...; colour0 to colour255 from the 256-colour set; default for the default colour; terminal for the terminal default colour; or a hexadecimal RGB string such as ‘#rgb’ or ‘#rrggbb’.
brighten=n
Increase brightness by n (0-1000). A negative value decreases brightness.
dim=n
Decrease brightness by n (0-1000). A negative value increases brightness.
underscore
Set underscore attribute.
blink
Set blink attribute.
reverse
Set reverse attribute.
bold
Set bold attribute.
italics
Set italics attribute.
none
Turn off all attributes.
reset
Turn off all attributes and reset colours to default.

Styles may be combined, for example:

#[fg=red,bg=blue,bold]This is red on blue and bold

If no style is specified, or if an option contains an invalid style, the default style is used.

The following attributes are supported by tmux for use in styles:

attributes
A comma or space separated list of attributes. Supported attributes are bright, dim, reverse, underline, blink, bold, italics.
bg=colour
Set the background colour.
fg=colour
Set the foreground colour.
none
Reset all attributes.
reset
Reset all attributes and colours.

Colours may be specified by name (eg red), number (eg colour0 for the first colour in the 256-colour set) or by RGB value (eg #rgb or #rrggbb).

The following named colours are recognised:

black, red, green, yellow, blue, magenta, cyan, white, default,
terminal, brightblack, brightred, brightgreen, brightyellow,
brightblue, brightmagenta, brightcyan, brightwhite.

If no colour is specified, the default colour is used.

The default colour is the default for the terminal. The terminal colour is the colour currently set in the terminal.

Attributes may be combined with colours, for example:

#[fg=blue,bold]This text is bold blue.

Styles may be embedded within the output of format options. For example, to make the status line left part bold red:

set-option -g status-left '#[fg=red,bold]Hello world #[normal]'

Note the #[normal] or #[reset] at the end to reset the style so that it does not affect subsequent text.

It is also possible to create a style that is the default. This is done by passing the empty string to the relevant option.

set-option -g status-style ""

This resets the style of the status line to the terminal default.

NOMBRES Y TÍTULOS

tmux distingue entre nombres y títulos. Las ventanas y sesiones tienen nombres, que pueden usarse para especificarlas en objetivos y se muestran en la línea de estado y en varias listas: el nombre es el identificador de tmux para una ventana o sesión. Solo los paneles tienen títulos. El título de un panel suele ser establecido por el programa que se ejecuta dentro del panel mediante una secuencia de escape (como establecería el título de la ventana de xterm(1) en X(7)). Las ventanas en sí no tienen títulos; el título de una ventana es el título de su panel activo. tmux puede establecer el título de la terminal en la que se ejecuta el cliente, véase la opción set-titles.

El nombre de una sesión se establece con los comandos new-session y rename-session. El nombre de una ventana se establece con uno de:

  1. Un argumento de comando (como -n para new-window o new-session).
  2. Una secuencia de escape (si la opción allow-rename está activada): 
    $ printf '\033kWINDOW_NAME\033\\'
  3. Renombrado automático, que establece el nombre al comando activo en el panel activo de la ventana. Véase la opción automatic-rename.

Cuando se crea un panel por primera vez, su título es el nombre del host. El título de un panel se puede establecer mediante la secuencia de escape de establecimiento de título, por ejemplo:

$ printf '\033]2;Mi Título\033\\'

También se puede modificar con el comando select-pane -T.

ENTORNO GLOBAL Y DE SESIÓN

Cuando se inicia el servidor, tmux copia el entorno al entorno global; además, cada sesión tiene un entorno de sesión. Cuando se crea una ventana, los entornos de sesión y global se fusionan. Si una variable existe en ambos, se utiliza el valor del entorno de sesión. El resultado es el entorno inicial que se pasa al nuevo proceso.

La opción de sesión update-environment puede utilizarse para actualizar el entorno de sesión desde el cliente cuando se crea una nueva sesión o se reasocia una antigua. tmux también inicializa la variable TMUX con información interna para permitir la ejecución de comandos desde dentro, y la variable TERM con la configuración de terminal correcta de «screen».

Las variables tanto del entorno de sesión como del global pueden marcarse como ocultas. Las variables ocultas no se pasan al entorno de los nuevos procesos y, en su lugar, solo pueden ser utilizadas por tmux (por ejemplo, en formatos, véase la sección FORMATOS).

Los comandos para modificar y ver el entorno son:

set-environment [-Fhgru] [-t sesión-objetivo] variable [valor]
(alias: setenv)
Establece o anula una variable de entorno. Si se usa -g, el cambio se realiza en el entorno global; de lo contrario, se aplica al entorno de sesión para sesión-objetivo. Si está presente -F, entonces valor se expande como un formato. El indicador -u anula una variable. -r indica que la variable debe eliminarse del entorno antes de iniciar un nuevo proceso. -h marca la variable como oculta.
show-environment [-hgs] [-t sesión-objetivo] [variable]
(alias: showenv)
Muestra el entorno para sesión-objetivo o el entorno global con -g. Si se omite variable, se muestran todas las variables. Las variables eliminadas del entorno van prefijadas con «-». Si se usa -s, la salida se formatea como un conjunto de comandos de shell Bourne. -h muestra variables ocultas (omitidas por defecto).

LÍNEA DE ESTADO

tmux incluye una línea de estado opcional que se muestra en la última línea de cada terminal.

Por defecto, la línea de estado está habilitada y tiene una línea de altura (puede ser deshabilitada o hecha de múltiples líneas con la opción de sesión status) y contiene, de izquierda a derecha: el nombre de la sesión actual entre corchetes; la lista de ventanas; el título del panel activo entre comillas dobles; y la hora y fecha.

Cada línea de la línea de estado se configura con la opción status-format. El valor predeterminado i

consta de tres partes: secciones izquierda y derecha configurables (que pueden contener contenido dinámico como la hora o la salida de un comando de shell, véase las opciones status-left, status-left-length, status-right y status-right-length más abajo), y una lista de ventanas central. Por defecto, la lista de ventanas muestra el índice, el nombre y (si lo hay) el indicador de las ventanas presentes en la sesión actual en orden numérico ascendente. Puede personalizarse con las opciones window-status-format y window-status-current-format. El indicador es uno de los siguientes símbolos añadidos al nombre de la ventana:

Símbolo Significado
* Indica la ventana actual.
- Marca la última ventana (seleccionada previamente).

! Se supervisan las alarmas de la ventana y ha ocurrido una alarma en la ventana.
~ La ventana ha estado en silencio durante el intervalo de silencio de supervisión.
M La ventana contiene el panel marcado.
Z El panel activo de la ventana está ampliado.

El símbolo # está relacionado con la opción de ventana monitor-activity. El nombre de la ventana se imprime con colores invertidos si hay una alerta (alarma, actividad o silencio).

El color y los atributos de la línea de estado se pueden configurar, toda la línea de estado utilizando la opción de sesión status-style y las ventanas individuales utilizando la opción de ventana window-status-style.

La línea de estado se actualiza automáticamente a intervalos si ha cambiado, el intervalo puede controlarse con la opción de sesión status-interval.

BUFFERS

tmux mantiene un conjunto de buffers de pegado con nombre. Cada buffer puede ser nombrado explícita o automáticamente. Los buffers con nombre explícito se nombran cuando se crean con los comandos set-buffer o load-buffer, o al renombrar un buffer con nombre automático con set-buffer -n. A los buffers con nombre automático se les da un nombre como ‘buffer0001’, ‘buffer0002’ y así sucesivamente. Cuando se alcanza la opción buffer-limit, se elimina el buffer con nombre automático más antiguo. Los buffers con nombre explícito no están sujetos a buffer-limit y pueden eliminarse con el comando delete-buffer.

Los buffers pueden agregarse usando copy-mode o los comandos set-buffer y load-buffer, y pegarse en una ventana usando el comando paste-buffer. Si se usa un comando de buffer y no se especifica ningún buffer, se asume el buffer con nombre automático agregado más recientemente.

También se mantiene un historial configurable para cada ventana. Por defecto, se conservan hasta 2000 líneas; esto se puede modificar con la opción history-limit (consulte el comando set-option arriba).

Execute shell-command using /bin/sh or (with -C) a tmux command in the background without creating a window. Before being executed, shell-command is expanded using the rules specified in the FORMATS section. With -b, the command is run in the background. -d waits for delay seconds before starting the command. -E redirects the command's stderr to stdout instead of ignoring it. If -c is given, the current working directory is set to start-directory. If -C is not given, any output to stdout is displayed in view mode (in the pane specified by -t or the current pane if omitted) after the command finishes. If the command fails, the exit status is also displayed.
wait-for [-L | -S | -U] channel
(alias: wait)
When used without options, prevents the client from exiting until woken using wait-for -S with the same channel. When -L is used, the channel is locked and any clients that try to lock the same channel are made to wait until the channel is unlocked with wait-for -U.

EXIT MESSAGES

tmux client detaches, it prints a message. This may be one of:

detached (from session ...)

detached and SIGHUP
The client was detached and its parent sent the SIGHUP signal (for example with detach-client -P).
lost tty
The client's tty(4) or pty(4) was unexpectedly destroyed.
terminated
The client was killed with SIGTERM.
too far behind
The client is in control mode and became unable to keep up with the data from tmux.
exited
The server exited when it had no sessions.
server exited
The server exited when it received SIGTERM.
server exited unexpectedly
The server crashed or otherwise exited without telling the client the reason.

MODO DE CONTROL

tmux ofrece una interfaz textual llamada modo de control. Esto permite a las aplicaciones comunicarse con tmux utilizando un protocolo simple solo de texto.

En modo de control, un cliente envía comandos de tmux o secuencias de comandos terminadas por saltos de línea en la entrada estándar. Cada comando producirá un bloque de salida en la salida estándar. Un bloque de salida consiste en una línea %begin seguida de la salida (que puede estar vacía). El bloque de salida termina con un %end o %error. %begin y el coincidente %end o %error tienen tres argumentos: un entero de tiempo (en segundos desde la época), número de comando y banderas (actualmente no utilizadas). Por ejemplo:

%begin 1363006971 2 1
0: ksh* (1 paneles) [80x24] [layout b25f,80x24,0,0,2] @2 (activo)
%end 1363006971 2 1

El comando refresh-client -C puede usarse para establecer el tamaño de un cliente en modo de control.

En modo de control, tmux emite notificaciones. Una notificación nunca ocurrirá dentro de un bloque de salida.

Las siguientes notificaciones están definidas:

%client-detached cliente
El cliente se ha desconectado.
%client-session-changed cliente id-sesión nombre
El cliente ahora está conectado a la sesión con ID id-sesión, que se llama nombre.
%config-error error
Ha ocurrido un error en un archivo de configuración.
%continue id-panel
El panel ha continuado después de ser pausado (si la bandera pause-after está establecida, ver refresh-client -A).
%exit [razón]
El cliente tmux está saliendo inmediatamente, ya sea porque no está conectado a ninguna sesión o porque ocurrió un error. Si está presente, razón describe por qué el cliente salió.
%extended-output id-panel antigüedad ... : valor
Nueva forma de %output enviada cuando la bandera pause-after está establecida. antigüedad es el tiempo en milisegundos durante el cual tmux había almacenado en búfer la salida antes de que se enviara. Cualquier argumento posterior hasta un solo ‘:’ es para uso futuro y debe ser ignorado.
%layout-change id-ventana diseño-ventana diseño-visible-ventana banderas-ventana
El diseño de una ventana con ID id-ventana cambió. El nuevo diseño es diseño-ventana. El diseño visible de la ventana es diseño-visible-ventana y las banderas de la ventana son banderas-ventana.
%message mensaje
Un mensaje enviado con el comando display-message.
%output id-panel valor
Un panel de ventana produjo salida. valor escapa caracteres no imprimibles y barras invertidas como octal \xxx.
%pane-mode-changed id-panel
El panel con ID id-panel ha cambiado de modo.
%paste-buffer-changed nombre
El búfer de pegado nombre ha sido cambiado.
%paste-buffer-deleted nombre
El búfer de pegado nombre ha sido eliminado.
%pause id-panel
El panel ha sido pausado (si la bandera pause-after está establecida).
%session-changed id-sesión nombre
El cliente ahora está conectado a la sesión con ID id-sesión, que se llama nombre.
%session-renamed nombre
La sesión actual fue renombrada a nombre.
%session-window-changed id-sesión id-ventana
La sesión con ID id-sesión cambió su ventana activa a la ventana con ID id-ventana.
%sessions-changed
Se creó o destruyó una sesión.
%subscription-changed nombre id-sesión id-ventana índice-ventana id-panel ... : valor
El valor del formato asociado con la suscripción nombre ha cambiado a valor. Ver refresh-client -B. Cualquier argumento después de id-panel hasta un solo ‘:’ es para uso futuro y debe ser ignora

ENTORNO

Cuando se inicia tmux, inspecciona las siguientes variables de entorno:

EDITOR
Si el comando especificado en esta variable contiene la cadena "vi" y VISUAL no está establecido, se usan las combinaciones de teclas estilo vi. Se ignora por las opciones mode-keys y status-keys.
HOME
El directorio de inicio del usuario. Si no está establecido, se consulta la base de datos de passwd(5).
LC_CTYPE
La codificación de caracteres de locale(1). Se utiliza para dos propósitos distintos. Para la salida a la terminal, se usa UTF-8 si se proporciona la opción -u o si LC_CTYPE contiene "UTF-8" o "UTF8". De lo contrario, solo se escriben caracteres ASCII y los caracteres no ASCII se reemplazan con guiones bajos ("_"). Para la entrada, tmux siempre se ejecuta con una configuración regional UTF-8. Si el sistema operativo proporciona en_US.UTF-8, se utiliza y LC_CTYPE se ignora para la entrada. De lo contrario, LC_CTYPE le dice a tmux cómo se llama la configuración regional UTF-8 en el sistema actual. Si la configuración regional especificada por LC_CTYPE no está disponible o no es una configuración regional UTF-8, tmux sale con un mensaje de error.
LC_TIME
El formato de fecha y hora de locale(1). Se utiliza para los especificadores de formato de strftime(3) dependientes de la configuración regional.
PWD
El directorio de trabajo actual que se establecerá en el entorno global. Esto puede ser útil si contiene enlaces simbólicos. Si el valor de la variable no coincide con el directorio de trabajo actual, la variable se ignora y en su lugar se utiliza el resultado de getcwd(3).
SHELL
La ruta absoluta al shell predeterminado para las nuevas ventanas. Vea la opción default-shell para más detalles.
TMUX_TMPDIR
El directorio padre del directorio que contiene los sockets del servidor. Vea la opción -L para más detalles.
VISUAL
Si el comando especificado en esta variable contiene la cadena "vi", se usan las combinaciones de teclas estilo vi. Se ignora por las opciones mode-keys y status-keys.

EJEMPLOS

Para crear una nueva sesión de tmux ejecutando vi(1):

$ tmux new-session vi

La mayoría de los comandos tienen una forma más corta, conocida como alias. Para new-session, esta es new:

$ tmux new vi

Alternativamente, se acepta la forma más corta no ambigua de un comando. Si hay varias opciones, se listan:

$ tmux n
comando ambiguo: n, podría ser: new-session, new-window, next-window

Dentro de una sesión activa, se puede crear una nueva ventana escribiendo ' C-b c ' (Ctrl seguido de la tecla ' b ' seguida de la tecla ' c ').

Las ventanas se pueden navegar con: ' C-b 0 ' (para seleccionar la ventana 0), ' C-b 1 ' (para seleccionar la ventana 1), y así sucesivamente; ' C-b n ' para seleccionar la siguiente ventana; y ' C-b p ' para seleccionar la ventana anterior.

Una sesión se puede desadjuntar usando ' C-b d ' (o mediante un evento externo como la desconexión de ssh(1)) y readjuntarla con:

$ tmux attach-session

Escribir ' C-b ? ' lista las combinaciones de teclas actuales en la ventana actual; arriba y abajo se pueden usar para navegar por la lista o ' q ' para salir de ella.

Los comandos que se ejecutarán cuando se inicie el servidor de tmux se pueden colocar en el archivo de configuración ~/.tmux.conf. Ejemplos comunes incluyen:

Cambiar la tecla de prefijo predeterminada:

set-option -g prefix C-a
unbind-key C-b
bind-key C-a send-prefix

Desactivar la línea de estado o cambiar su color:

set-option -g status off
set-option -g status-style bg=blue

Establecer otras opciones, como el comando predeterminado, o bloquear después de 30 minutos de inactividad:

set-option -g default-command "exec /bin/ksh"
set-option -g lock-after-time 1800

Crear nuevas combinaciones de teclas:

bind-key b set-option status
bind-key / command-prompt "split-window 'exec man %%'"
bind-key S command-prompt "new-window -n %1 'ssh %1'"

NOMBRE

tmux - multiplexor de terminal

SINAPSIS

tmux [-aA] [-c start-child] [-e display-message-args] [-f file] [-L socket-name] [-N] [-p socket-path] [-S socket-path] [shell-command]

DESCRIPCIÓN

tmux es un multiplexor de terminal que permite a un usuario administrar múltiples terminales dentro de una única pantalla. Permite a los usuarios adjuntar y desadjuntar sesiones de sus terminales. También admite la paginación de salida de comandos, el reordenamiento de ventanas y la canalización de la salida de un panel a otro.

COMANDOS

Esta sección describe los comandos principales de tmux. Los comandos se dividen en categorías como creación de ventanas, gestión de paneles, etc.

new-session
Crea una nueva sesión.
split-window
Divide la ventana actual en dos paneles.
kill-window
Cierra una ventana.

OPCIONES

Esta sección detalla las opciones disponibles para el comando tmux.

-a
Cuando se usa con attach-session, busca el primer adjunto disponible.
-f file
Especifica un archivo de configuración.

ACCESOS DIRECTOS

Tmux utiliza una combinación de teclas predeterminada (Ctrl-b) seguida de otra tecla para ejecutar comandos. Las combinaciones de teclas más comunes incluyen:

  • Ctrl-b c: Crear una nueva ventana.
  • Ctrl-b n: Ir a la siguiente ventana.
  • Ctrl-b p: Ir a la ventana anterior.
  • Ctrl-b &: Cerrar la ventana actual.
  • Ctrl-b %: Dividir el panel verticalmente.
  • Ctrl-b ": Dividir el panel horizontalmente.
  • Ctrl-b <flecha>: Moverse entre los paneles.
