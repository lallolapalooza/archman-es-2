tmpfs(5) Manual de Formatos de Archivo tmpfs(5)

NOMBRE

tmpfs - un sistema de archivos de memoria virtual

DESCRIPCIÓN

La utilidad tmpfs permite la creación de sistemas de archivos cuyos contenidos residen en memoria virtual. Dado que los archivos en dichos sistemas de archivos suelen residir en RAM, el acceso a los archivos es extremadamente rápido.

El sistema de archivos se crea automáticamente al montar un sistema de archivos con el tipo tmpfs mediante un comando como el siguiente:


$ sudo mount -t tmpfs -o size=10M tmpfs /mnt/mytmpfs

Un sistema de archivos tmpfs tiene las siguientes propiedades:

•
El sistema de archivos puede emplear espacio de intercambio cuando la presión de la memoria física lo exige.
•
El sistema de archivos consume solo tanta memoria física y espacio de intercambio como sea necesario para almacenar los contenidos actuales del sistema de archivos.
•
Durante una operación de remontaje (mount -o remount), el tamaño del sistema de archivos puede modificarse (sin perder los contenidos existentes del sistema de archivos).

Si un sistema de archivos tmpfs se desmonta, sus contenidos se descartan (se pierden).

Opciones de Montaje

El sistema de archivos tmpfs soporta las siguientes opciones de montaje:

size=bytes
Especifica un límite superior para el tamaño del sistema de archivos. El tamaño se da en bytes y se redondea hacia arriba a páginas completas. El límite se elimina si el tamaño es 0.
El tamaño puede tener un sufijo k, m o g para Ki, Mi, Gi (kilo binario (kibi), mega binario (mebi) y giga binario (gibi)).
El tamaño también puede tener un sufijo % para limitar esta instancia a un porcentaje de la RAM física.
El valor predeterminado, cuando no se especifica ni size ni nr_blocks, es size=50%.
nr_blocks=bloques
Lo mismo que size, pero en bloques de PAGE_CACHE_SIZE.
Los bloques se pueden especificar con sufijos k, m o g como size, pero no con un sufijo %.
nr_inodes=inodos
El número máximo de inodos para esta instancia. El valor predeterminado es la mitad del número de páginas de RAM física, o (en una máquina con highmem) el número de páginas de RAM de bajo nivel (lowmem), lo que sea menor. El límite se elimina si el número es 0.
Los inodos se pueden especificar con sufijos k, m o g como size, pero no con un sufijo %.
noswap(desde Linux 6.4)
Deshabilita el intercambio. Los remontajes deben respetar la configuración original. Por defecto, el intercambio está habilitado.
mode=modo
Establece los permisos iniciales del directorio raíz.
gid=gid (desde Linux 2.5.7)
Establece el ID de grupo inicial del directorio raíz.
uid=uid (desde Linux 2.5.7)
Establece el ID de usuario inicial del directorio raíz.
huge=opción_huge (desde Linux 4.7.0)
Establece la política de asignación de memoria de tablas grandes (huge table) para todos los archivos en esta instancia (si CONFIG_TRANSPARENT_HUGEPAGE está habilitado).
El valor opción_huge es uno de los siguientes:
never
No asignar tablas grandes. Este es el valor predeterminado.
always
Intentar asignar tablas grandes cada vez que se necesite una nueva página.
within_size
Solo asignar tablas grandes si está completamente dentro de i_size. También respeta las indicaciones de fadvise(2) y madvise(2)
advise
Solo asignar tablas grandes si se solicita con fadvise(2) o madvise(2).
deny
Para uso en emergencias, para forzar la opción de tablas grandes en todos los montajes.
force
Forzar la opción de tablas grandes en todos los montajes; útil para pruebas.
mpol=opción_mpol (desde Linux 2.6.15)
Establece la política de asignación de memoria NUMA para todos los archivos en esta instancia (si CONFIG_NUMA está habilitado).
El valor opción_mpol es uno de los siguientes:
default
Utiliza la política de asignación del proceso (ver set_mempolicy(2)).
prefer:nodo
Preferentemente asignar memoria desde el nodo dado.
bind:nodelist
Asignar memoria solo desde los nodos en nodelist.
interleave
Asignar desde cada nodo por turno.
interleave:nodelist
Asignar desde cada nodo de en turno.
local
Preferentemente asignar memoria desde el nodo local.
En lo anterior, nodelist es una lista separada por comas de números decimales y rangos que especifican nodos NUMA. Un rango es un par de números decimales separados por guiones, los números de nodo más pequeños y más grandes en el rango. Por ejemplo, mpol=bind:0-3,5,7,9-15.

VERSIÓNES

La utilidad tmpfs se añadió en Linux 2.4, como sucesora de la anterior utilidad ramfs, que no proporcionaba verificación de límites ni permitía el uso de espacio de intercambio.

NOTAS

Para que las herramientas y aplicaciones de espacio de usuario puedan crear sistemas de archivos tmpfs, el kernel debe estar configurado con la opción CONFIG_TMPFS.

El sistema de archivos tmpfs soporta atributos extendidos (ver xattr(7)), pero los atributos extendidos de usuario no están permitidos.

Se utiliza un sistema de archivos interno de memoria compartida para la memoria compartida System V ( shmget(2)) y mapeos anónimos compartidos ( mmap(2) con las banderas MAP_SHARED y MAP_ANONYMOUS). Este sistema de archivos está disponible independientemente de si el kernel fue configurado con la opción CONFIG_TMPFS.

Se utiliza un sistema de archivos tmpfs montado en /dev/shm para la implementación de memoria compartida POSIX ( shm_overview(7)) y semáforos POSIX ( sem_overview(7)).

La cantidad de memoria consumida por todos los sistemas de archivos tmpfs se muestra en el campo Shmem de /proc/meminfo y en el campo shared mostrado por free(1).

La utilidad tmpfs se llamaba anteriormente shmfs.
