timerfd_create(2) Manual de llamadas al sistema timerfd_create(2)

NOMBRE

timerfd_create, timerfd_settime, timerfd_gettime - temporizadores que notifican a través de descriptores de archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/timerfd.h>
int timerfd_create(int clockid, int flags);
int timerfd_settime(int fd, int flags,
                    const struct itimerspec *new_value,
                    struct itimerspec *_Nullable old_value);
int timerfd_gettime(int fd, struct itimerspec *curr_value);

DESCRIPCIÓN

Estas llamadas al sistema crean y operan sobre un temporizador que entrega notificaciones de expiración del temporizador a través de un descriptor de archivo. Proporcionan una alternativa al uso de setitimer(2) o timer_create(2), con la ventaja de que el descriptor de archivo puede ser monitorizado por select(2), poll(2) y epoll(7).

El uso de estas tres llamadas al sistema es análogo al uso de timer_create(2), timer_settime(2) y timer_gettime(2). (No hay análogo de timer_getoverrun(2), ya que esa funcionalidad es proporcionada por read(2), como se describe a continuación.)

timerfd_create()

timerfd_create() crea un nuevo objeto temporizador y devuelve un descriptor de archivo que hace referencia a ese temporizador. El argumento clockid especifica el reloj que se utiliza para marcar el progreso del temporizador y debe ser uno de los siguientes:

CLOCK_REALTIME
Un reloj de tiempo real configurable en todo el sistema.
CLOCK_MONOTONIC
Un reloj monotónico creciente no configurable que mide el tiempo desde algún punto indeterminado en el pasado que no cambia después del inicio del sistema.
CLOCK_BOOTTIME (Desde Linux 3.15)
Al igual que CLOCK_MONOTONIC, este es un reloj monotónico creciente. Sin embargo, mientras que el reloj CLOCK_MONOTONIC no mide el tiempo mientras un sistema está suspendido, el reloj CLOCK_BOOTTIME sí incluye el tiempo durante el cual el sistema está suspendido. Esto es útil para aplicaciones que necesitan ser conscientes de la suspensión. CLOCK_REALTIME no es adecuado para tales aplicaciones, ya que ese reloj se ve afectado por cambios discontinuos en el reloj del sistema.
CLOCK_REALTIME_ALARM (desde Linux 3.11)
Este reloj es similar a CLOCK_REALTIME, pero despertará al sistema si está suspendido. El llamador debe tener la capacidad CAP_WAKE_ALARM para establecer un temporizador contra este reloj.
CLOCK_BOOTTIME_ALARM (desde Linux 3.11)
Este reloj es similar a CLOCK_BOOTTIME, pero despertará al sistema si está suspendido. El llamador debe tener la capacidad CAP_WAKE_ALARM para establecer un temporizador contra este reloj.

Consulte clock_getres(2) para obtener más detalles sobre los relojes anteriores.

El valor actual de cada uno de estos relojes se puede obtener usando clock_gettime(2).

A partir de Linux 2.6.27, los siguientes valores se pueden aplicar mediante un OR bit a bit en flags para cambiar el comportamiento de timerfd_create():

TFD_NONBLOCK
Establece el descriptor de estado de archivo O_NONBLOCK en la descripción de archivo abierta (ver open(2)) a la que hace referencia el nuevo descriptor de archivo. Usar esta bandera ahorra llamadas adicionales a fcntl(2) para lograr el mismo resultado.
TFD_CLOEXEC
Establece la bandera de cierre al ejecutar (FD_CLOEXEC) en el nuevo descriptor de archivo. Consulte la descripción de la bandera O_CLOEXEC en open(2) para conocer las razones por las que esto puede ser útil.

En las versiones de Linux hasta e incluyendo 2.6.26, flags debe especificarse como cero.

timerfd_settime()

timerfd_settime() arma (inicia) o desarma (detiene) el temporizador al que hace referencia el descriptor de archivo fd.

El argumento new_value especifica la expiración inicial y el intervalo para el temporizador. La estructura itimerspec utilizada para este argumento se describe en itimerspec(3type).

new_value.it_value especifica la expiración inicial del temporizador, en segundos y nanosegundos. Establecer cualquiera de los campos de new_value.it_value a un valor distinto de cero arma el temporizador. Establecer ambos campos de new_value.it_value a cero desarma el temporizador.

Establecer uno o ambos campos de new_value.it_interval a valores distintos de cero especifica el período, en segundos y nanosegundos, para expiraciones repetidas del temporizador después de la expiración inicial. Si ambos campos de new_value.it_interval son cero, el temporizador expira solo una vez, en el momento especificado por new_value.it_value.

Por defecto, el tiempo de expiración inicial especificado en new_value se interpreta en relación con el tiempo actual en el reloj del temporizador en el momento de la llamada (es decir, new_value.it_value especifica un tiempo relativo al valor actual del reloj especificado por clockid). Se puede seleccionar un tiempo absoluto mediante el argumento flags.

El argumento flags es una máscara de bits que puede incluir los siguientes valores:

TFD_TIMER_ABSTIME
Interpreta new_value.it_value como un valor absoluto en el reloj del temporizador. El temporizador expirará cuando el valor del reloj del temporizador alcance el valor especificado en new_value.it_value.
TFD_TIMER_CANCEL_ON_SET
Si esta bandera se especifica junto con TFD_TIMER_ABSTIME y el reloj para este temporizador es CLOCK_REALTIME o CLOCK_REALTIME_ALARM, entonces marque este temporizador como cancelable si el reloj de tiempo real experimenta un cambio discontinuo (settimeofday(2), clock_settime(2) o similar). Cuando ocurren dichos cambios, una lectura actual o futura del descriptor de archivo fallará con el error ECANCELED.

Si el argumento old_value no es NULL, entonces la estructura itimerspec a la que apunta se utiliza para devolver la configuración del temporizador que estaba vigente en el momento de la llamada; consulte la descripción de timerfd_gettime() a continuación.

timerfd_gettime()

timerfd_gettime() devuelve, en curr_value, una estructura itimerspec que contiene la configuración actual del temporizador al que hace referencia el descriptor de archivo fd.

El campo it_value devuelve la cantidad de tiempo hasta que el temporizador expire la próxima vez. Si ambos campos de esta estructura son cero, entonces el temporizador está actualmente desarmado. Este campo siempre contiene un valor relativo, independientemente de si se especificó la bandera TFD_TIMER_ABSTIME al configurar el temporizador.

El campo it_interval devuelve el intervalo del temporizador. Si ambos campos de esta estructura son cero, entonces el temporizador está configurado para expirar solo una vez, en el momento especificado por curr_value.it_value.

Operación sobre un descriptor de archivo de temporizador

El descriptor de archivo devuelto por timerfd_create() soporta las siguientes operaciones adicionales:

read(2)
Si el temporizador ha expirado ya una o más veces desde que se modificaron sus ajustes por última vez
ed usando timerfd_settime(), o desde la última lectura exitosa read(2), entonces el búfer proporcionado a read(2) devuelve un entero sin signo de 8 bytes (uint64_t) que contiene el número de expiraciones que han ocurrido. (El valor devuelto está en orden de bytes del host, es decir, el orden de bytes nativo para enteros en la máquina host).
Si no han ocurrido expiraciones del temporizador en el momento de la lectura read(2), entonces la llamada se bloquea hasta la próxima expiración del temporizador, o falla con el error EAGAIN si el descriptor de archivo se ha configurado como no bloqueante (mediante el uso de la operación fcntl(2) F_SETFL para establecer la bandera O_NONBLOCK).
Una lectura read(2) falla con el error EINVAL si el tamaño del búfer suministrado es menor que 8 bytes.
Si el reloj asociado es CLOCK_REALTIME o CLOCK_REALTIME_ALARM, el temporizador es absoluto (TFD_TIMER_ABSTIME), y la bandera TFD_TIMER_CANCEL_ON_SET se especificó al llamar a timerfd_settime(), entonces read(2) falla con el error ECANCELED si el reloj de tiempo real experimenta un cambio discontinuo. (Esto permite a la aplicación que lee detectar dichos cambios discontinuos en el reloj).
Si el reloj asociado es CLOCK_REALTIME o CLOCK_REALTIME_ALARM, el temporizador es absoluto (TFD_TIMER_ABSTIME), y la bandera TFD_TIMER_CANCEL_ON_SET *no* se especificó al llamar a timerfd_settime(), entonces un cambio negativo discontinuo en el reloj (por ejemplo, clock_settime(2)) puede hacer que read(2) se desbloquee, pero devuelva un valor de 0 (es decir, no se leyeron bytes), si el cambio de reloj ocurre después de que el tiempo expiró, pero antes de la lectura read(2) en el descriptor de archivo.
poll(2)
select(2)
(y similares)
El descriptor de archivo es legible (el argumento readfds de select(2); la bandera POLLIN de poll(2)) si han ocurrido una o más expiraciones del temporizador.
El descriptor de archivo también soporta las otras APIs de multiplexación de descriptores de archivo: pselect(2), ppoll(2) y epoll(7).
ioctl(2)
Se soporta el siguiente comando específico de timerfd:
TFD_IOC_SET_TICKS (desde Linux 3.17)
Ajusta el número de expiraciones del temporizador que han ocurrido. El argumento es un puntero a un entero de 8 bytes distinto de cero (uint64_t*) que contiene el nuevo número de expiraciones. Una vez establecido el número, se despierta a cualquier proceso en espera del temporizador. El único propósito de este comando es restaurar las expiraciones para fines de punto de control/restauración. Esta operación solo está disponible si el kernel fue configurado con la opción CONFIG_CHECKPOINT_RESTORE.
close(2)
Cuando el descriptor de archivo ya no sea necesario, debe cerrarse. Cuando todos los descriptores de archivo asociados con el mismo objeto de temporizador se hayan cerrado, el temporizador se desarma y sus recursos son liberados por el kernel.

Semántica de fork(2)

Después de un fork(2), el hijo hereda una copia del descriptor de archivo creado por timerfd_create(). El descriptor de archivo se refiere al mismo objeto de temporizador subyacente que el descriptor de archivo correspondiente en el padre, y las lecturas read(2) en el hijo devolverán información sobre las expiraciones del temporizador.

Semántica de execve(2)

Un descriptor de archivo creado por timerfd_create() se conserva a través de execve(2), y continúa generando expiraciones del temporizador si el temporizador estaba armado.

VALOR DE RETORNO

En caso de éxito, timerfd_create() devuelve un nuevo descriptor de archivo. En caso de error, devuelve -1 y se establece errno para indicar el error.

timerfd_settime() y timerfd_gettime() devuelven 0 en caso de éxito; en caso de error, devuelven -1 y establecen errno para indicar el error.

ERRORES

timerfd_create() puede fallar con los siguientes errores:

EINVAL
El clockid no es válido.
EINVAL
flags no es válido; o, en Linux 2.6.26 o anterior, flags es distinto de cero.
EMFILE
Se ha alcanzado el límite por proceso del número de descriptores de archivo abiertos.
ENFILE
Se ha alcanzado el límite a nivel de sistema del número total de archivos abiertos.
ENODEV
No se pudo montar el dispositivo anónimo de inodo (interno).
ENOMEM
No había suficiente memoria del kernel para crear el temporizador.
EPERM
clockid era CLOCK_REALTIME_ALARM o CLOCK_BOOTTIME_ALARM pero el llamador no tenía la capacidad CAP_WAKE_ALARM.

timerfd_settime() y timerfd_gettime() pueden fallar con los siguientes errores:

EBADF
fd no es un descriptor de archivo válido.
EFAULT
new_value, old_value, o curr_value no es un puntero válido.
EINVAL
fd no es un descriptor de archivo timerfd válido.

timerfd_settime() también puede fallar con los siguientes errores:

ECANCELED
Ver NOTAS.
EINVAL
new_value no está inicializado correctamente (uno de los tv_nsec cae fuera del rango de cero a 999,999,999).
EINVAL
flags no es válido.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.25, glibc 2.8.

NOTAS

Supongamos el siguiente escenario para un temporizador CLOCK_REALTIME o CLOCK_REALTIME_ALARM que fue creado con timerfd_create():

(1)
El temporizador ha sido iniciado (timerfd_settime()) con las banderas TFD_TIMER_ABSTIME y TFD_TIMER_CANCEL_ON_SET;
(2)
Posteriormente se realiza un cambio discontinuo (por ejemplo, settimeofday(2)) en el reloj CLOCK_REALTIME; y
(3)
el llamador vuelve a llamar a timerfd_settime() para reactivar el temporizador (sin realizar primero una lectura read(2) en el descriptor de archivo).

En este caso, ocurre lo siguiente:

•
La llamada timerfd_settime() devuelve -1 con errno establecido a ECANCELED. (Esto permite al llamador saber que el temporizador anterior se vio afectado por un cambio discontinuo en el reloj).
•
El temporizador *se reactiva con éxito* con la configuración proporcionada en la segunda llamada a timerfd_settime(). (Esto fue probablemente un accidente de implementación, pero no se corregirá ahora, en caso de que haya aplicaciones que dependan de este comportamiento).

ERRORES

Actualmente, timerfd_create() soporta menos tipos de IDs de reloj que timer_create(2).

El primer argumento especifica el número de segundos para la expiración inicial del temporizador. El segundo argumento especifica el intervalo para el temporizador, en segundos. El tercer argumento especifica el número de veces que el programa permitirá que expire el temporizador antes de terminar. Los argumentos de línea de comandos segundo y tercero son opcionales.

EXAMPLES

   The following program creates a timer that expires after 1 second, and then
   every 2 seconds thereafter. The program reads the timer expiration events
   from the timerfd file descriptor and prints the elapsed time since the timer
   was started.

   $ ./a.out 1 2 5
   0.001:  timer started
   1.001:  read: 1; total=1
   3.001:  read: 2; total=3
   5.001:  read: 2; total=5
   7.001:  read: 2; total=7
   9.001:  read: 2; total=9

   The following program creates a timer that expires after 3 seconds, and then
   never expires again.

   $ ./a.out 3
   0.001:  timer started
   3.001:  read: 3; total=3
