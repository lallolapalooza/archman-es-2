timer_getoverrun(2) Manual de Llamadas al Sistema timer_getoverrun(2)

NOMBRE

timer_getoverrun - obtener el recuento de sobrecargas de un temporizador por proceso POSIX

BIBLIOTECA

Biblioteca en tiempo real (librt, -lrt)

SINOPSIS

#include <time.h>
int timer_getoverrun(timer_t timerid);
Requisitos de Macro de Prueba de Funciones para glibc (véase feature_test_macros(7)):

timer_getoverrun():

    _POSIX_C_SOURCE >= 199309L

DESCRIPCIÓN

timer_getoverrun() devuelve el "recuento de sobrecargas" para el temporizador al que hace referencia timerid. Una aplicación puede utilizar el recuento de sobrecargas para calcular con precisión el número de expiraciones del temporizador que habrían ocurrido durante un intervalo de tiempo determinado. Las sobrecargas del temporizador pueden ocurrir tanto al recibir notificaciones de expiración a través de señales (SIGEV_SIGNAL) como a través de hilos (SIGEV_THREAD).

Cuando las notificaciones de expiración se entregan a través de una señal, las sobrecargas pueden ocurrir de la siguiente manera. Independientemente de si se utiliza una señal en tiempo real o no para las notificaciones del temporizador, el sistema pone en cola como máximo una señal por temporizador. (Este es el comportamiento especificado por POSIX.1. La alternativa, poner en cola una señal por cada expiración del temporizador, podría fácilmente desbordar los límites permitidos para las señales en cola en el sistema.) Debido a los retrasos de programación del sistema, o porque la señal puede estar bloqueada temporalmente, puede haber un retraso entre el momento en que se genera la señal de notificación y el momento en que se entrega (por ejemplo, se captura en un manejador de señales) o se acepta (por ejemplo, utilizando sigwaitinfo(2)). En este intervalo, pueden ocurrir expiraciones adicionales del temporizador. El recuento de sobrecargas del temporizador es el número de expiraciones adicionales del temporizador que ocurrieron entre el momento en que se generó la señal y el momento en que se entregó o aceptó.

Las sobrecargas del temporizador también pueden ocurrir cuando las notificaciones de expiración se entregan a través de la invocación de un hilo, ya que puede haber un retraso arbitrario entre una expiración del temporizador y la invocación del hilo de notificación, y en ese intervalo de retraso, pueden ocurrir expiraciones adicionales del temporizador.

VALOR DE RETORNO

En caso de éxito, timer_getoverrun() devuelve el recuento de sobrecargas del temporizador especificado; este recuento puede ser 0 si no ha ocurrido ninguna sobrecarga. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EINVAL
timerid no es un ID de temporizador válido.

VERSIÓNES

Cuando las notificaciones del temporizador se entregan a través de señales (SIGEV_SIGNAL), en Linux también es posible obtener el recuento de sobrecargas a través del campo si_overrun de la estructura siginfo_t (véase sigaction(2)). Esto permite a una aplicación evitar la sobrecarga de realizar una llamada al sistema para obtener el recuento de sobrecargas, pero es una extensión no portable a POSIX.1.

POSIX.1 discute las sobrecargas del temporizador solo en el contexto de las notificaciones del temporizador que utilizan señales.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

Linux 2.6. POSIX.1-2001.

ERRORES DE PROGRAMACIÓN

POSIX.1 especifica que si el recuento de sobrecargas del temporizador es igual o superior a un máximo definido por la implementación, DELAYTIMER_MAX, entonces timer_getoverrun() debería devolver DELAYTIMER_MAX. Sin embargo, antes de Linux 4.19, si el valor de sobrecarga del temporizador excede el entero máximo representable, el contador se reinicia, comenzando una vez más desde valores bajos. Desde Linux 4.19, timer_getoverrun() devuelve DELAYTIMER_MAX (definido como INT_MAX en <limits.h>) en este caso (y el valor de sobrecarga se reinicia a 0).

EJEMPLOS

Véase timer_create(2).
