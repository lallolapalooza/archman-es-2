NOMBRE

tipc - una herramienta de configuración y gestión de TIPC

SINOPSIS


tipc [ OPCIONES ] COMANDO ARGUMENTOS

COMANDO := { bearer | link | media | nametable | node | socket }

OPCIONES := { -h[ayuda] }

DESCRIPCIÓN

La comunicación transparente entre procesos (TIPC) ofrece transparencia total de direcciones entre procesos, lo que permite que las aplicaciones en un entorno de clúster de computadoras se comuniquen de forma rápida y fiable entre sí, independientemente de su ubicación dentro del clúster.

TIPC se originó en el fabricante de telecomunicaciones Ericsson. La primera versión de código abierto de TIPC se creó en 2000, cuando Ericsson lanzó su primera versión de Linux de TIPC. TIPC se introdujo en el kernel principal de Linux en 2006 y ahora se utiliza ampliamente tanto dentro como fuera de Ericsson.

OPCIONES

-h, --help
Muestra ayuda sobre el último comando dado. Por ejemplo, tipc bearer --help mostrará la ayuda de bearer y tipc --help mostrará la ayuda general. La posición de la opción en la cadena es irrelevante.
-j, -json
Muestra los resultados en notación de objetos de JavaScript (JSON).
-p, -pretty
El formato JSON predeterminado es compacto y más eficiente de analizar, pero difícil de leer para la mayoría de los usuarios. Esta marca agrega sangría para mejorar la legibilidad.

COMANDOS

BEARER
- Muestra o modifica los bearers de TIPC
LINK
- Muestra o modifica los enlaces de TIPC
MEDIA
- Muestra o modifica los medios de TIPC
NAMETABLE
- Muestra la tabla de nombres de TIPC
NODE
- Muestra o modifica los parámetros del nodo TIPC
SOCKET
- Muestra los sockets de TIPC

ARGUMENTOS

Los argumentos de los comandos se describen en una página de manual específica del comando y suelen consistir en comandos anidados junto con pares clave-valor. Si no se proporcionan argumentos, un comando suele mostrar su texto de ayuda. La opción de ayuda explícita -h o --help puede aparecer en cualquier lugar entre los argumentos y mostrará ayuda para el último comando válido dado.

ESTADO DE SALIDA

El estado de salida es 0 si el comando fue exitoso o un entero positivo en caso de fallo.
