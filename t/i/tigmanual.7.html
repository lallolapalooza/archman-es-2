TIGMANUAL(7) Manual de Tig TIGMANUAL(7)

NOMBRE

tigmanual - interfaz en modo texto para Git

SINOPSIS

tig        [opciones] [revisiones] [--] [rutas]
tig show   [opciones] [revisiones] [--] [rutas]
tig blame  [opciones] [rev] [--] ruta
tig status
tig <      [salida del comando Git]

DESCRIPCIÓN

Este es el manual de Tig, la interfaz en modo texto basada en ncurses para git. Tig te permite explorar cambios en un repositorio Git y, además, puede actuar como paginador para la salida de varios comandos Git. Cuando se usa como paginador, mostrará la entrada de stdin y la coloreará.

Al explorar repositorios, Tig utiliza los comandos Git subyacentes para presentar al usuario varias vistas, como un registro de commits resumido y la visualización del commit con el mensaje del commit, el diffstat y el diff.

CONVENCIONES DE LLAMADA

Modo Paginador

Si stdin es una tubería, se ignorarán las opciones de log o diff y se abrirá la vista del paginador cargando datos desde stdin. El modo paginador se puede usar para colorear la salida de varios comandos Git.

Ejemplo de cómo colorear la salida de git-show(1):

$ git show | tig

Opciones de Comandos Git

Todas las opciones de comandos Git especificadas en la línea de comandos se pasarán al comando dado y todas se escaparán de la shell antes de ser pasadas a la shell.


Nota

Si especifica opciones para la vista principal, no debe usar la opción --pretty, ya que esta opción se establecerá automáticamente al formato esperado por la vista principal.

Ejemplo de cómo ver un commit y mostrar información tanto del autor como del committer:

$ tig show --pretty=fuller

Consulte la sección sobre la especificación de revisiones para obtener una introducción a las opciones de revisión admitidas por los comandos Git. Para obtener detalles sobre opciones específicas de comandos Git, consulte la página del manual del comando en cuestión.

EL VISOR

La pantalla consta de una ventana de estado en la última línea de la pantalla y una o más vistas. La opción predeterminada es mostrar solo una vista a la vez, pero es posible dividir tanto la vista principal como la vista de registro para mostrar también el diff del commit.

Si está en la vista de registro y presiona Enter cuando la línea actual es una línea de commit, como:

commit 4d55caff4cc89335192f3e566004b4ceef572521

Dividirá la vista para que la vista de registro se muestre en la ventana superior y la vista de diff en la ventana inferior. Puede cambiar entre las dos vistas presionando Tab. Para maximizar nuevamente la vista de registro, simplemente presione l.

Vistas

Se presentan varias vistas de un repositorio. Cada vista se basa en la salida de un comando externo, la mayoría de las veces git log, git diff o git show.

La vista principal

Es la vista predeterminada y muestra un resumen de una línea de cada commit en la lista de revisiones elegida. El resumen incluye la fecha del committer o autor, el autor, el committer y la primera línea del mensaje del commit. Además, se mostrarán todas las referencias del repositorio, como las etiquetas.

La vista de registro

Presenta una vista más rica del registro de revisiones, mostrando el mensaje completo del registro y el diffstat.

La vista del reflog

Presenta una vista del reflog que permite navegar por el historial del repositorio.

La vista de diff

Muestra el diff del árbol de trabajo actual, es decir, qué ha cambiado desde el último commit, o el diff del commit completo con el mensaje del commit, el diffstat y el diff.

La vista de árbol

Enumera los árboles de directorios asociados con la revisión actual, lo que permite descender o ascender por subdirectorios y ver blobs de archivos.

La vista de blob

Muestra el contenido del archivo o "blob" de datos asociado con un nombre de archivo.

La vista de blame

Muestra el contenido del archivo anotado o "culpado" por los commits.

La vista de refs

Muestra las ramas, remotos y etiquetas en el repositorio.

La vista de estado

Muestra el estado de los archivos en el árbol de trabajo y permite añadir/quitar archivos del staging, así como añadir archivos no rastreados.

La vista de staging

Muestra los cambios de diff para archivos añadidos/no añadidos al staging que se están rastreando o el contenido de archivos no rastreados.

La vista de stash

Muestra la lista de stashes en el repositorio.

La vista de grep

Muestra una lista de archivos y todas las líneas que coinciden con un patrón de búsqueda.

La vista de paginador

Se utiliza para mostrar tanto la entrada de stdin como la salida de los comandos Git introducidos en el prompt interno.

La vista de ayuda

Muestra una referencia rápida de los enlaces de teclas.

Estado de Navegación y Comandos Definidos por el Usuario

El visor mantiene un registro de qué ID de cabeza y commit está viendo actualmente. El ID del commit seguirá la línea del cursor y cambiará cada vez que resalte un commit diferente. Cada vez que reabra la vista de diff, se recargará si el ID del commit ha cambiado. El ID de cabeza se utiliza al abrir la vista principal y la vista de registro para indicar desde qué revisión mostrar el historial.

Algunos de los comandos utilizados o proporcionados por Tig pueden ser configurados. Esto aplica a algunas de las variables de entorno, así como a los comandos externos. Estos comandos definidos por el usuario pueden usar argumentos que se refieren al estado de navegación actual utilizando una de las siguientes variables.

Ejemplo de comandos definidos por el usuario:

•Permitir modificar el último commit: 
bind generic + !git commit --amend
•Copiar el ID del commit al portapapeles: 
bind generic 9 @sh -c "echo -n %(commit) | xclip -selection c"
•Añadir/editar notas para el commit actual usadas durante una revisión: 
bind generic T !git notes edit %(commit)
•Entrar al modo interactivo de `git add` para seleccionar el contenido de archivos de forma granular: 
bind generic I !git add -i %(file)
•Rebase la rama actual sobre la rama seleccionada: 
bind refs 3 !git rebase -i %(branch)

Ventanas de Título

Cada vista tiene una ventana de título que muestra el nombre de la vista, el ID del commit actual si está disponible y dónde está posicionada la vista:

[main] c622eefaa485995320bc743431bae0d497b1d875 - commit 1 de 61             1%

Por defecto, el título de la vista actual se resalta usando negrita. Para vistas de carga larga (que tardan más de 3 segundos) se añadirá el tiempo transcurrido desde el inicio de la carga:

[main] 77d9e40fbcea3238015aea403e06f61542df9a31 - commit 1 de 779 cargando 5s 0%

VARIABLES DE ENTORNO

Varias opciones relacionadas con la interfaz con Git pueden ser configuradas a través de variables de entorno.

Archivos de Configuración

Al iniciar, Tig primero lee el archivo de configuración global del sistema ({sysconfdir}/tigrc por defecto) y luego procede a leer el archivo de configuración del usuario (~/.tigrc o $XDG_CONFIG_HOME/tig/config por defecto). Las rutas a cualquiera de estos archivos pueden ser anuladas a través de las siguientes variables de entorno:

TIGRC_USER

Ruta del archivo de configuración del usuario.

TIGRC_SYSTEM

Ruta del archivo de configuración global del sistema.

Archivos de Historial

Si se compiló con soporte de readline, Tig escribe un historial persistente de comandos y búsquedas en ~/.tig_history o $XDG_DATA_HOME/tig/history.

Referencias del Repositorio

Los commits referenciados por etiquetas y cabezas de rama se marcarán con el nombre de la referencia rodeado por [ y ]:

2006-03-26 19:42 Petr Baudis         | [cogito-0.17.1] Cogito 0.17.1

Si desea limitar qué ramas se muestran, por ejemplo, solo mostrar ramas llamadas master o aquellas que comienzan con el prefijo feature/, puede hacerlo configurando la siguiente variable:

$ TIG_LS_REMOTE="git ls-remote . master feature/*" tig

O configure la variable permanentemente en su entorno.

TIG_LS_REMOTE

Comando para recuperar todas las referencias del repositorio. El comando debe generar datos en el mismo formato que git-ls-remote(1). Por defecto:
git ls-remote .

Opciones de Diff

Es posible alterar cómo se muestran los diffs en la vista de diff. Si, por ejemplo, prefiere que las fechas de commit y de autor se muestren como fechas relativas, use:

$ TIG_DIFF_OPTS="--relative-date" tig

O configure la variable permanentemente en su entorno.

tigmanual(7) — Tig Manual

NAME

tig - an ncurses based text-mode interface for Git

SYNOPSIS

tig [-g] [-i] [-f file] [-c commit] [-r repository] [--] [revision arguments...]

DESCRIPTION

Tig is a small, fast, and friendly text-mode interface to Git. It can be used to view the commit history and the contents of the Git repository index (staging area) and working tree. Tig can also be used to stage and commit changes, and to review diffs. For more details, please refer to the man pages listed in the SEE ALSO section.

CALLING CONVENTIONS

The following is a list of revision arguments that Tig supports. Revision arguments are passed directly to the underlying Git commands without any modification. Therefore, Tig supports all revision arguments that Git supports.

If the first argument does not start with a dash or is not a valid revision name, Tig will treat it as a path name, and will limit the view to revisions that affected that path. Using "--" is recommended to separate revision arguments from path names.

If you want to view the log starting from a specific commit, use "-c" or "--commit":

$ tig -c HEAD

If you want to view the log for a specific repository, use "-r" or "--repository":

$ tig -r /path/to/repo

If you want to view the log starting from a specific file, use "-f" or "--file":

$ tig -f path/to/file

THE VIEWER

Tig displays the commit history in a two-pane view. The left pane shows the commit log, and the right pane shows the diff for the selected commit. The following keys are available:

       p, P        Previous commit / next commit
       n, N        Next commit / previous commit
       ^, $        First commit / last commit
       g           Go to commit
       @           View revision under cursor
       a           View author
       A           View committer
       o           View omitted commits
       i           View information about the selected commit
       I           View information about the selected commit (short)
       t           View commit/tree
       T           View tree
       d           View diff
       D           View diff this commit is a part of
       s           Stage file
       u           Unstage file
       r           Revert commit
       m           Amend commit
       e           Edit commit
       f           Follow file
       F           Follow file with parent
       h           Toggle horizontal split
       v           Toggle vertical split
       q           Quit
       ?           Show help

REVISION SPECIFICATION

This section describes various ways to specify what revisions to display or otherwise limit the view to. Tig does not itself parse the described revision options so refer to the relevant Git man pages for further information. Relevant man pages besides git-log(1) are git-diff(1) and git-rev-list(1).

You can tune the interaction with Git by making use of the options explained in this section. For example, by configuring the environment variable described in the section on diff options.

Limit by Path Name

If you are interested only in those revisions that made changes to a specific file (or even several files) list the files like this:

$ tig Makefile README

To avoid ambiguity with Tig’s subcommands or repository references such as tag names, be sure to separate file names from other Git options using "--". So if you have a file named status it will clash with the status subcommand, and thus you will have to use:

$ tig -- status

Limit by Date or Number

To speed up interaction with Git, you can limit the amount of commits to show both for the log and main view. Either limit by date using e.g. --since=1.month or limit by the number of commits using -n400.

If you are only interested in changes that happened between two dates you can use:

$ tig --after="May 5th" --before="2006-05-16 15:44"

Note

If you want to avoid having to quote dates containing spaces you can use "." instead, e.g. --after=May.5th.

Limiting by Commit Ranges

Alternatively, commits can be limited to a specific range, such as "all commits between tag-1.0 and tag-2.0". For example:

$ tig tag-1.0..tag-2.0

This way of commit limiting makes it trivial to only browse the commits which haven’t been pushed to a remote branch. Assuming origin is your upstream remote branch, using:

$ tig origin..HEAD

will list what will be pushed to the remote branch. Optionally, the ending HEAD can be left out since it is implied.

Limiting by Reachability

Git interprets the range specifier "tag-1.0..tag-2.0" as "all commits reachable from tag-2.0 but not from tag-1.0". Where reachability refers to what commits are ancestors (or part of the history) of the branch or tagged revision in question.

If you prefer to specify which commit to preview in this way use the following:

$ tig tag-2.0 ^tag-1.0

You can think of ^ as a negation operator. Using this alternate syntax, it is possible to further prune commits by specifying multiple branch cut offs.

Combining Revisions Specification

Revision options can to some degree be combined, which makes it possible to say "show at most 20 commits from within the last month that changed files under the Documentation/ directory."

$ tig --since=1.month -n20 -- Documentation/

Examining All Repository References

In some cases, it can be useful to query changes across all references in a repository. An example is to ask "did any line of development in this repository change a particular file within the last week". This can be accomplished using:

$ tig --all --since=1.week -- Makefile
