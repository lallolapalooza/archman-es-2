NOMBRE

timesyncd.conf, timesyncd.conf.d - Archivos de configuración de sincronización de hora de red

SINOPSIS

/etc/systemd/timesyncd.conf
/run/systemd/timesyncd.conf
/usr/local/lib/systemd/timesyncd.conf
/usr/lib/systemd/timesyncd.conf
/etc/systemd/timesyncd.conf.d/*.conf
/run/systemd/timesyncd.conf.d/*.conf
/usr/local/lib/systemd/timesyncd.conf.d/*.conf
/usr/lib/systemd/timesyncd.conf.d/*.conf

DESCRIPCIÓN

Estos archivos de configuración controlan la sincronización de hora de red NTP. Vea systemd.syntax(7) para una descripción general de la sintaxis.

DIRECTORIOS DE CONFIGURACIÓN Y PREFERENCIA

La configuración por defecto se establece durante la compilación, por lo que la configuración solo es necesaria cuando es necesario desviarse de esos valores predeterminados. El archivo de configuración principal se carga desde uno de los directorios listados en orden de prioridad, solo se utiliza el primer archivo encontrado: /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La versión del proveedor del archivo contiene entradas comentadas que muestran los valores predeterminados como guía para el administrador. Las anulaciones locales también se pueden crear creando archivos de inclusión (drop-ins), como se describe a continuación. El archivo de configuración principal también se puede editar para este propósito (o una copia en /etc/ si se distribuye en /usr/), sin embargo, se recomienda usar archivos de inclusión para la configuración local en lugar de modificar el archivo de configuración principal.

Además del archivo de configuración principal, se leen fragmentos de configuración de inclusión de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/ y /etc/systemd/*.conf.d/. Estos archivos de inclusión tienen mayor prioridad y anulan el archivo de configuración principal. Los archivos en los subdirectorios de configuración *.conf.d/ se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en cuál de los subdirectorios residen. Cuando varios archivos especifican la misma opción, para opciones que solo aceptan un valor único, la entrada en el archivo ordenado último tiene prioridad, y para opciones que aceptan una lista de valores, las entradas se recopilan según ocurren en los archivos ordenados.

Cuando los paquetes necesitan personalizar la configuración, pueden instalar archivos de inclusión bajo /usr/. Los archivos en /etc/ están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor. Los archivos de inclusión deben usarse para anular los archivos de inclusión de paquetes, ya que el archivo de configuración principal tiene menor prioridad. Se recomienda prefijar todos los nombres de archivo en estos subdirectorios con un número de dos dígitos y un guion, para simplificar el orden. Esto también define un concepto de prioridades de archivos de inclusión para permitir que los proveedores de OS envíen archivos de inclusión dentro de un rango específico inferior al rango utilizado por los usuarios. Esto debería reducir el riesgo de que los archivos de inclusión de paquetes anulen accidentalmente los archivos de inclusión definidos por los usuarios. Se recomienda utilizar el rango 10-40 para los archivos de inclusión en /usr/ y el rango 60-90 para los archivos de inclusión en /etc/ y /run/, para asegurarse de que los archivos de inclusión locales y transitorios tengan prioridad sobre los archivos de inclusión enviados por el proveedor del sistema operativo.

Para deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en el directorio de configuración en /etc/, con el mismo nombre de archivo que el archivo de configuración del proveedor.

OPCIONES

Las siguientes configuraciones se definen en la sección [Time]:

NTP=

Una lista separada por espacios de nombres de host o direcciones IP de servidores NTP. Durante el tiempo de ejecución, esta lista se combina con cualquier servidor NTP por interfaz adquirido de systemd-networkd.service(8). systemd-timesyncd contactará a todos los servidores configurados del sistema o por interfaz en orden, hasta que uno responda. Cuando se asigna la cadena vacía, la lista de servidores NTP se restablece y todas las asignaciones anteriores no tendrán efecto. Esta configuración tiene como valor predeterminado una lista vacía.

Añadido en la versión 216.

FallbackNTP=

Una lista separada por espacios de nombres de host o direcciones IP de servidores NTP que se utilizarán como servidores NTP de respaldo. Cualquier servidor NTP por interfaz obtenido de systemd-networkd.service(8) tiene prioridad sobre esta configuración, al igual que cualquier servidor establecido a través de NTP= arriba. Por lo tanto, esta configuración solo es relevante si no se conoce ninguna otra información de servidor NTP. Cuando se asigna la cadena vacía, la lista de servidores NTP se restablece y todas las asignaciones anteriores no tendrán efecto. Si no se proporciona esta opción, se utiliza una lista de servidores NTP compilada en el código.

Añadido en la versión 216.

RootDistanceMaxSec=

Distancia raíz máxima aceptable, es decir, el tiempo estimado máximo requerido para que un paquete viaje al servidor al que estamos conectados desde el servidor con el reloj de referencia. Si el servidor actual no cumple con este límite, systemd-timesyncd cambiará a un servidor diferente.

Toma un valor de intervalo de tiempo. La unidad predeterminada son segundos, pero se pueden especificar otras unidades, vea systemd.time(7). El valor predeterminado es 5 segundos.

Añadido en la versión 236.

PollIntervalMinSec=, PollIntervalMaxSec=

Los intervalos de sondeo mínimo y máximo para mensajes NTP. El sondeo comienza en el intervalo de sondeo mínimo y se ajusta dentro de los límites especificados en respuesta a los paquetes recibidos.

Cada configuración toma un valor de intervalo de tiempo. La unidad predeterminada son segundos, pero se pueden especificar otras unidades, vea systemd.time(7). PollIntervalMinSec= tiene como valor predeterminado 32 segundos y no debe ser menor de 16 segundos. PollIntervalMaxSec= tiene como valor predeterminado 34 minutos 8 segundos (2048 segundos) y debe ser mayor que PollIntervalMinSec=.

Añadido en la versión 236.

ConnectionRetrySec=

Especifica el retardo mínimo antes de que se realicen intentos posteriores para contactar a un nuevo servidor NTP.

Toma un valor de intervalo de tiempo. La unidad predeterminada son segundos, pero se pueden especificar otras unidades, vea systemd.time(7). El valor predeterminado es 30 segundos y no debe ser menor de 1 segundo.

Añadido en la versión 248.

SaveIntervalSec=

El intervalo en el que la hora actual se guarda periódicamente en el disco, en ausencia de cualquier sincronización reciente de un servidor NTP. Esto es especialmente útil para sistemas sin conexión con RTC local, ya que garantizará que el reloj del sistema permanezca aproximadamente monotónico entre reinicios.

Toma un valor de intervalo de tiempo. La unidad predeterminada son segundos, pero se pueden especificar otras unidades, vea systemd.time(7). El valor predeterminado es 60 segundos.

Añadido en la versión 250.

VER TAMBIÉN

systemd(1), systemd-timesyncd.service(8), systemd-networkd.service(8)

NOMBRE

timesyncd.conf.d - Archivos de configuración para systemd-timesyncd.service

SINOPSIS

/etc/systemd/timesyncd.conf.d/*.conf

/run/systemd/timesyncd.conf.d/*.conf

/usr/lib/systemd/timesyncd.conf.d/*.conf

DESCRIPCIÓN

El servicio systemd-timesyncd.service es un cliente de sincronización de tiempo simple que implementa el protocolo NTP y el protocolo SNTP. Utiliza los archivos de configuración en los directorios especificados en la lista anterior para su configuración.

Los archivos de configuración se analizan en el orden de los directorios listados. Los archivos en directorios posteriores sobrescriben los de directorios anteriores. Los archivos dentro de un mismo directorio se ordenan alfabéticamente.

Los archivos de configuración son archivos de texto plano que consisten en directivas de configuración. Las directivas se dividen en secciones, indicadas por corchetes, como [Time].

Las directivas de configuración especifican cómo debe comportarse el servicio de sincronización de tiempo. Por ejemplo, las directivas en la sección [Time] controlan la sincronización de tiempo.

DIRECTORIOS DE CONFIGURACIÓN Y PRECEDENCIA

Los archivos de configuración para systemd-timesyncd.service se buscan en los siguientes directorios, en orden de precedencia:

  1. /etc/systemd/timesyncd.conf.d/: Configuración específica del sistema.
  2. /run/systemd/timesyncd.conf.d/: Configuración temporal.
  3. /usr/lib/systemd/timesyncd.conf.d/: Configuración predeterminada proporcionada por el paquete.

Los archivos en directorios posteriores sobrescriben los de directorios anteriores. Los archivos dentro de un mismo directorio se ordenan alfabéticamente. Los archivos con nombres que terminan en .conf son leídos.

OPCIONES

Las opciones de configuración se encuentran en la sección [Time]. Las opciones disponibles son:

  • NTP=: Especifica uno o más servidores NTP para sincronizar la hora. Si se especifican varios servidores, se intentará conectarse a ellos en orden.
  • FallbackNTP=: Especifica uno o más servidores NTP de reserva que se utilizarán si no se puede contactar con ningún servidor NTP especificado en NTP=.
  • RootDistanceSec=: Especifica la distancia máxima permitida a la raíz del árbol de sincronización. Los relojes que estén más lejos de la raíz se considerarán no sincronizados.
  • PollIntervalSec=: Especifica el intervalo de sondeo para los servidores NTP en segundos. El valor predeterminado es 32 segundos.
  • MaxDispersionSec=: Especifica la dispersión máxima permitida del reloj local con respecto a los servidores NTP. Si la dispersión supera este valor, la sincronización se detendrá.
  • ListenAddress=: Especifica las direcciones IP locales en las que se debe escuchar el servicio para las solicitudes NTP.
  • Port=: Especifica el puerto NTP a utilizar. El valor predeterminado es 123.
  • UseNTP=: Habilita o deshabilita la sincronización NTP. El valor puede ser yes o no.
  • UseSNT=: Habilita o deshabilita la sincronización SNTP. El valor puede ser yes o no.

VER TAMBIÉN

systemd-timesyncd.service(8), systemd.conf(5)

NOTAS

La configuración puede ser sobrescrita por archivos en los directorios de precedencia más alta. Si un archivo en /etc/systemd/timesyncd.conf.d/ tiene el mismo nombre que un archivo en /usr/lib/systemd/timesyncd.conf.d/, el archivo en /etc/systemd/timesyncd.conf.d/ tendrá prioridad.

Para que los cambios en la configuración surtan efecto, el servicio systemd-timesyncd.service debe ser reiniciado.
