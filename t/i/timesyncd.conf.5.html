NOMBRE

timesyncd.conf, timesyncd.conf.d — Archivos de configuración de sincronización de hora de red

SINOPSIS

/etc/systemd/timesyncd.conf
/run/systemd/timesyncd.conf
/usr/local/lib/systemd/timesyncd.conf
/usr/lib/systemd/timesyncd.conf
/etc/systemd/timesyncd.conf.d/*.conf
/run/systemd/timesyncd.conf.d/*.conf
/usr/local/lib/systemd/timesyncd.conf.d/*.conf
/usr/lib/systemd/timesyncd.conf.d/*.conf

DESCRIPCIÓN

Estos archivos de configuración controlan la sincronización de hora de red NTP. Consulte systemd.syntax(7) para una descripción general de la sintaxis.

DIRECTORIOS DE CONFIGURACIÓN Y PREFERENCIA

La configuración predeterminada se establece durante la compilación, por lo que la configuración solo es necesaria cuando es necesario desviarse de esos valores predeterminados. El archivo de configuración principal se carga desde uno de los directorios listados en orden de prioridad, solo se utiliza el primer archivo encontrado: /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La versión del proveedor del archivo contiene entradas comentadas que muestran los valores predeterminados como guía para el administrador. También se pueden crear anulaciones locales creando archivos de inclusión (drop-ins), como se describe a continuación. El archivo de configuración principal también se puede editar para este propósito (o una copia en /etc/ si se envía bajo /etc/), sin embargo, se recomienda utilizar archivos de inclusión para la configuración local en lugar de modificaciones al archivo de configuración principal.

Además del archivo de configuración principal, se leen fragmentos de configuración de inclusión (drop-ins) de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/ y /etc/systemd/*.conf.d/. Estos archivos de inclusión tienen mayor prioridad y anulan el archivo de configuración principal. Los archivos en los subdirectorios de configuración *.conf.d/ se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en cuál de los subdirectorios residan. Cuando varios archivos especifican la misma opción, para opciones que solo aceptan un valor único, la entrada en el archivo ordenado al final tiene precedencia, y para opciones que aceptan una lista de valores, las entradas se recopilan a medida que ocurren en los archivos ordenados.

Cuando los paquetes necesitan personalizar la configuración, pueden instalar archivos de inclusión bajo /usr/. Los archivos en /etc/ están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor. Los archivos de inclusión deben usarse para anular los archivos de inclusión de paquetes, ya que el archivo de configuración principal tiene menor precedencia. Se recomienda prefijar todos los nombres de archivo en estos subdirectorios con un número de dos dígitos y un guion, para simplificar el orden. Esto también define un concepto de prioridades de archivos de inclusión para permitir que los proveedores de sistemas operativos envíen archivos de inclusión dentro de un rango específico menor que el rango utilizado por los usuarios. Esto debería reducir el riesgo de que los archivos de inclusión de paquetes anulen accidentalmente los archivos de inclusión definidos por los usuarios. Se recomienda usar el rango 10-40 para los archivos de inclusión en /usr/ y el rango 60-90 para los archivos de inclusión en /etc/ y /run/, para asegurarse de que los archivos de inclusión locales y transitorios tengan prioridad sobre los archivos de inclusión enviados por el proveedor del sistema operativo.

Para deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en el directorio de configuración en /etc/, con el mismo nombre de archivo que el archivo de configuración del proveedor.

OPCIONES

Las siguientes configuraciones se establecen en la sección [Time]:

NTP=

Una lista separada por espacios de nombres de host o direcciones IP de servidores NTP. Durante la ejecución, esta lista se combina con cualquier servidor NTP por interfaz adquirido de systemd-networkd.service(8). systemd-timesyncd se pondrá en contacto con todos los servidores configurados del sistema o por interfaz en orden, hasta que uno responda. Cuando se asigna la cadena vacía, la lista de servidores NTP se restablece y todas las asignaciones previas no tendrán efecto. Esta configuración se establece por defecto en una lista vacía.

Añadido en la versión 216.

FallbackNTP=

Una lista separada por espacios de nombres de host o direcciones IP de servidores NTP que se utilizarán como servidores NTP de respaldo. Cualquier servidor NTP por interfaz obtenido de systemd-networkd.service(8) tiene prioridad sobre esta configuración, al igual que cualquier servidor configurado mediante NTP= arriba. Por lo tanto, esta configuración solo es relevante si no se conoce ninguna otra información del servidor NTP. Cuando se asigna la cadena vacía, la lista de servidores NTP se restablece y todas las asignaciones previas no tendrán efecto. Si no se proporciona esta opción, se utiliza una lista de servidores NTP compilada en el código.

Añadido en la versión 216.

RootDistanceMaxSec=

Distancia raíz máxima aceptable, es decir, el tiempo máximo estimado requerido para que un paquete viaje al servidor con el que estamos conectados desde el servidor con el reloj de referencia. Si el servidor actual no cumple este límite, systemd-timesyncd cambiará a un servidor diferente.

Toma un valor de lapso de tiempo. La unidad predeterminada son los segundos, pero se pueden especificar otras unidades, consulte systemd.time(7). Por defecto es 5 segundos.

Añadido en la versión 236.

PollIntervalMinSec=, PollIntervalMaxSec=

Los intervalos de sondeo mínimo y máximo para los mensajes NTP. El sondeo comienza en el intervalo de sondeo mínimo y se ajusta dentro de los límites especificados en respuesta a los paquetes recibidos.

Cada configuración toma un valor de lapso de tiempo. La unidad predeterminada son los segundos, pero se pueden especificar otras unidades, consulte systemd.time(7). PollIntervalMinSec= tiene un valor predeterminado de 32 segundos y no debe ser inferior a 16 segundos. PollIntervalMaxSec= tiene un valor predeterminado de 34 minutos y 8 segundos (2048 segundos) y debe ser mayor que PollIntervalMinSec=.

Añadido en la versión 236.

ConnectionRetrySec=

Especifica el retraso mínimo antes de que se realicen intentos posteriores para contactar con un nuevo servidor NTP.

Toma un valor de lapso de tiempo. La unidad predeterminada son los segundos, pero se pueden especificar otras unidades, consulte systemd.time(7). Por defecto es 30 segundos y no debe ser inferior a 1 segundo.

Añadido en la versión 248.

SaveIntervalSec=

El intervalo en el que la hora actual se guarda periódicamente en el disco, en ausencia de cualquier sincronización reciente de un servidor NTP. Esto es especialmente útil para sistemas sin conexión con un RTC local, ya que garantizará que el reloj del sistema permanezca aproximadamente monotónico entre reinicios.

Toma un valor de intervalo de tiempo. La unidad predeterminada son los segundos, pero se pueden especificar otras unidades, consulte systemd.time(7). Por defecto es 60 segundos.

Añadido en la versión 250.
