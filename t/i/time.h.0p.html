PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

time.h — tipos de tiempo

SINOPSIS

#include <time.h>

DESCRIPCIÓN

Parte de la funcionalidad descrita en esta página de referencia extiende el estándar ISO C. Las aplicaciones deberán definir la macro de prueba de características apropiada (consulte el volumen de Interfaces del Sistema de POSIX.1‐2017, Sección 2.2, El Entorno de Compilación) para habilitar la visibilidad de estos símbolos en esta cabecera.

La cabecera <time.h> definirá los tipos clock_t, size_t, time_t, según se describe en <sys/types.h>.

La cabecera <time.h> definirá los tipos clockid_t y timer_t según se describe en <sys/types.h>.

La cabecera <time.h> definirá el tipo locale_t según se describe en <locale.h>.

La cabecera <time.h> definirá el tipo pid_t según se describe en <sys/types.h>.

Se declarará el tag sigevent como un tipo de estructura incompleta, cuyos contenidos se describen en la cabecera <signal.h>.

La cabecera <time.h> declarará la estructura tm, que contendrá al menos los siguientes miembros:

int    tm_sec   Segundos [0,60].
int    tm_min   Minutos [0,59].
int    tm_hour  Hora [0,23].
int    tm_mday  Día del mes [1,31].
int    tm_mon   Mes del año [0,11].
int    tm_year  Años desde 1900.
int    tm_wday  Día de la semana [0,6] (Domingo =0).
int    tm_yday  Día del año [0,365].
int    tm_isdst Indicador de horario de verano.

El valor de tm_isdst será positivo si el horario de verano está en vigor, 0 si no lo está, y negativo si la información no está disponible.

La cabecera <time.h> declarará la estructura timespec, que contendrá al menos los siguientes miembros:

time_t  tv_sec    Segundos.
long    tv_nsec   Nanosegundos.

La cabecera <time.h> también declarará la estructura itimerspec, que contendrá al menos los siguientes miembros:

struct timespec  it_interval  Período del temporizador.
struct timespec  it_value     Expiración del temporizador.

La cabecera <time.h> definirá las siguientes macros:

NULL
Como se describe en <stddef.h>.
CLOCKS_PER_SEC
Un número utilizado para convertir el valor devuelto por la función clock() en segundos. El valor será una expresión de tipo clock_t. El valor de CLOCKS_PER_SEC será 1 millón en sistemas conformes a XSI. Sin embargo, puede ser variable en otros sistemas y no se debe asumir que CLOCKS_PER_SEC es una constante en tiempo de compilación.

La cabecera <time.h> definirá las siguientes constantes simbólicas. Los valores tendrán un tipo compatible para asignación con clockid_t.

CLOCK_MONOTONIC

El identificador del reloj monotónico a nivel de sistema, que se define como un reloj que mide el tiempo real, cuyo valor no puede establecerse mediante clock_settime() y que no puede tener saltos de reloj negativos. El salto máximo posible del reloj será definido por la implementación.
CLOCK_PROCESS_CPUTIME_ID

El identificador del reloj de tiempo de CPU asociado al proceso que realiza una llamada a la función clock() o timer*().
CLOCK_REALTIME
El identificador del reloj a nivel de sistema que mide el tiempo real.
CLOCK_THREAD_CPUTIME_ID

El identificador del reloj de tiempo de CPU asociado al hilo que realiza una llamada a la función clock() o timer*().

La cabecera <time.h> definirá la siguiente constante simbólica:

TIMER_ABSTIME
Bandera que indica que el tiempo es absoluto. Para las funciones que toman objetos de temporizador, esto se refiere al reloj asociado al temporizador.

La cabecera <time.h> proporcionará una declaración o definición para getdate_err. El símbolo getdate_err se expandirá a una expresión de tipo int. No se especifica si getdate_err es una macro o un identificador declarado con enlace externo, y si es o no un lvalue modificable. Si se suprime una definición de macro para acceder a un objeto real, o si un programa define un identificador con el nombre getdate_err, el comportamiento es indefinido.

Las siguientes secciones son informativas.

USO DE APLICACIONES

El rango [0,60] para tm_sec permite los ocasionales segundos bisiestos.

tm_year es un valor con signo; por lo tanto, se pueden representar años anteriores a 1900.

Para obtener el número de ticks de reloj por segundo devuelto por la función times(), las aplicaciones deben llamar a sysconf(_SC_CLK_TCK).

RACIONALE

El rango de [0,60] segundos permite segundos bisiestos positivos o negativos. La definición formal de UTC no permite segundos bisiestos dobles, por lo que se ha eliminado toda mención de segundos bisiestos dobles, y el rango se ha reducido de los anteriores [0,61] segundos vistos en versiones anteriores de este estándar.

Ninguna.

NAME

time.h

time and date utilities

SYNOPSIS

#include <time.h>

DESCRIPTION

The <time.h> header file defines structure types and functions that manipulate date and time. POSIX.1 defines the following structure types:

struct tm

This structure contains the following members:

tm_sec
Seconds.
tm_min
Minutes.
tm_hour
Hours.
tm_mday
Day of the month (1-31).
tm_mon
Months since January (0-11).
tm_year
Years since 1900.
tm_wday
Days since Sunday (0-6).
tm_yday
Days since January 1 (0-365).
tm_isdst
Daylight Saving Time flag. (May be greater than 0 if DST is in effect, zero if DST is not in effect, and less than 0 if the information is unknown.)

struct timespec

This structure is defined to hold the seconds and nanoseconds component of a time value. It has the following members:

tv_sec
Seconds.
tv_nsec
Nanoseconds.

struct itimerspec

This structure specifies the expiration interval and the initialization time for timers. It has the following members:

it_interval
The interval for which the timer is armed. struct timespec type.
it_value
The time until the timer expires for the first time. struct timespec type.

structitimerspec

This structure defines the time until the next expiration and the interval between expirations of a timer created by timer_create(). It has the following members:

it_value
The time until the timer expires for the first time.
it_interval
The interval between expirations.

clockid_t

This type is defined to identify a system clock. The following clock IDs are defined:

CLOCK_REALTIME
The system-wide real-time clock. This clock is typically affected by system administrator actions that change the system time and by NTP synchronizations. It should not be used for timing intervals.
CLOCK_MONOTONIC
The system-wide monotonic clock. This clock is not affected by system administrator actions or NTP synchronizations. It should be used for timing intervals.
CLOCK_PROCESS_CPUTIME_ID
A clock that measures the CPU time experienced by the calling process. This clock is specific to the process.
CLOCK_THREAD_CPUTIME_ID
A clock that measures the CPU time experienced by the calling thread. This clock is specific to the thread.

Other clock IDs may be specified by extensions.

APPLICATION USAGE

The POSIX.1 functions defined in this header file are intended to provide a portable interface for manipulating time. Applications should use these functions whenever possible to ensure portability across different systems.

For timing intervals, it is strongly recommended to use CLOCK_MONOTONIC instead of CLOCK_REALTIME, as the latter may jump backwards or forwards due to system time adjustments.

The usleep() function is obsolete and should not be used in new applications. Use nanosleep() instead.

RATIONALE

The POSIX.1 standard defines a set of time-related functions and types that are essential for portable application development. These include functions for converting between time representations, formatting time strings, and measuring time intervals. The standard also specifies different system clocks, each with its own characteristics and use cases.

The inclusion of message queue and semaphore functions within <time.h> is for historical reasons and to maintain compatibility with certain POSIX standards.

The strftime() and strptime() functions provide powerful capabilities for formatting and parsing time strings according to locale-specific conventions.

The sysconf() function allows applications to query system configuration variables, including those related to time and clocks.

FUTURE DIRECTIONS

Future versions of POSIX may introduce additional time-related features or refine existing ones. Developers should consult the latest POSIX standards for the most up-to-date information.
