NOMBRE

tipc-link - mostrar enlaces o modificar propiedades de enlaces

SINOPSIS


tipc link set
[ { priority PRIORIDAD | tolerance TOLERANCIA | window VENTANA } link ENLACE ] |
[ { broadcast [ BROADCAST | REPLICAST | AUTOSELECT [ ratio TAMAÑO ] ] } ]

tipc link get
[ { priority | tolerance | window } link ENLACE ] |
[ { broadcast } ]

tipc link statistics { show [ link ENLACE ] | reset link ENLACE }

tipc link list

tipc link monitor set { threshold }

tipc link monitor get { threshold }

tipc link monitor summary

tipc link monitor list
[ media { eth | ib } device DISPOSITIVO ] |
[ media udp name NOMBRE ]

OPCIONES

Opciones (flags) que se pueden pasar en cualquier parte de la cadena de comandos.

-h, --help
Muestra ayuda sobre el último comando válido. Por ejemplo, tipc link --help mostrará la ayuda de enlaces y tipc --help mostrará la ayuda general. La posición de la opción en la cadena es irrelevante.
-j, -json
Genera resultados en formato JavaScript Object Notation (JSON).
-p, -pretty
El formato JSON predeterminado es compacto y más eficiente de analizar, pero difícil de leer para la mayoría de los usuarios. Esta bandera añade indentación para mejorar la legibilidad.

DESCRIPCIÓN

Estadísticas de enlace

Estado del enlace ACTIVO

Un enlace ACTIVO está sirviendo tráfico. Dos enlaces al mismo nodo pueden volverse ACTIVOS si tienen la misma prioridad de enlace. Si hay más de dos enlaces con la misma prioridad, los enlaces adicionales se pondrán en estado STANDBY (en espera).
Estado del enlace ESPERA

Un enlace en ESPERA tiene una prioridad de enlace menor que un enlace ACTIVO. Un enlace en ESPERA tiene tráfico de control fluyendo y está listo para tomar el relevo si el/los enlace(s) ACTIVO(s) fallan.
MTU

La Unidad Máxima de Transmisión (Maximum Transmission Unit). Los dos puntos finales anuncian su MTU predeterminada o configurada en la configuración inicial del enlace y acordarán usar el valor más bajo de los dos si difieren.
Paquetes

La cantidad total de paquetes TIPC transmitidos o recibidos en un enlace. Incluye paquetes fragmentados y agrupados (bundled).
Fragmentos

Se representa en el formato fragmentos/fragmentados. Donde fragmentados es la cantidad de mensajes de datos que se han roto en fragmentos. Posteriormente, los fragmentos son la cantidad total de paquetes en los que se han roto los mensajes fragmentados.
Paquetes agrupados

Se representa en el formato agrupados/agrupando. Si un enlace se congestiona, intentará agrupar datos de paquetes pequeños agrupando en paquetes de tamaño MTU completo antes de transmitirlos.
Perfil

Muestra el tamaño promedio del paquete en octetos/bytes para una muestra de paquetes. También muestra la distribución del tamaño del paquete de los paquetes muestreados en los siguientes intervalos:

0-64 bytes
64-256 bytes
256-1024 bytes
1024-4096 bytes
4096-16384 bytes
16384-32768 bytes
32768-66000 bytes

Contadores de mensajes

estados - Número de mensajes de estado del enlace

sondas - Mensajes de estado del enlace con el indicador de sonda activado. Generalmente se envían cuando un enlace está inactivo

nacks - Número de paquetes de reconocimiento negativo (NACK) enviados y recibidos por el enlace

defs - Número de paquetes recibidos fuera de orden

dups - Número de paquetes duplicados recibidos

Congestión del enlace
El número de veces que una aplicación ha intentado enviar datos cuando el enlace TIPC estaba congestionado.
Cola de envío
Max es la cantidad máxima de mensajes que han residido en la cola de salida durante el período de recopilación de estadísticas de un enlace.

Avg es el tamaño promedio de la cola de salida durante la vida útil de un enlace.

Propiedades de enlace

prioridad

La prioridad entre enlaces lógicos TIPC hacia un nodo particular. La prioridad del enlace puede variar de 0 (más baja) a 31 (más alta).
tolerancia

La tolerancia del enlace especifica el tiempo máximo en milisegundos que TIPC permitirá que exista un problema de comunicación antes de dar de baja el enlace. El valor predeterminado es 1500 milisegundos.
ventana

La ventana del enlace controla cuántos mensajes sin acuse de recibo puede tener un punto final del enlace en su cola de transmisión antes de que se active el mecanismo de control de congestión de TIPC.

Propiedades del monitor

umbral

El umbral especifica el tamaño del clúster que, al superarse, hará que el algoritmo de monitoreo de enlaces cambie de "malla completa" (full-mesh) a "anillo superpuesto" (overlapping-ring). Si se establece en 0, el monitoreo de anillo superpuesto siempre está activado, y si se establece en un valor mayor que el tamaño del clúster anticipado, el monitoreo de anillo superpuesto se desactiva. El valor predeterminado es 32.

Información del monitor

generación-de-tabla

Representa el recuento de eventos en la lista de monitoreo local de un nodo. Se incrementa cada vez que algo cambia en la lista de monitoreo local, incluidos los cambios en el dominio local.
tamaño-del-clúster

Representa la cuenta actual de miembros del clúster.
algoritmo

El algoritmo de supervisión actual utilizado para el monitoreo de vecinos para el portador. Los valores posibles son malla completa (full-mesh) o anillo superpuesto (overlapping-ring).
estado

El estado del nodo derivado por el nodo local. Los estados posibles son activo (up) o inactivo (down).
monitoreado

Representa el tipo de monitoreo elegido por el nodo local. Los valores posibles son directo (direct) o indirecto (indirect).
generación

Representa la generación del dominio, que es el recuento de eventos en el dominio local de un nodo. Cada vez que algo cambia (se añade/elimina un par, o cambia su estado activo/inactivo), la generación del dominio se incrementa y se envía una nueva versión del registro del nodo para informar a los vecinos sobre este cambio. La generación del dominio ayuda al receptor de un registro de dominio a saber si debe ignorar o procesar el registro.
estado aplicado del nodo

Representa el estado del nodo tal como lo percibe el nodo local, basado en los registros del dominio recibidos de los vecinos. El estado puede ser activo (up) o inactivo (down).

Esta página fue generada el DD de Mes de YYYY a las HH:MM:SS UTC.

s">estado_nodo_aplicado

El estado del nodo informado por el nodo par para los siguientes nodos en la lista de nodos. La lista de nodos es una lista circular de direcciones ascendentes que comienza con el nodo local. Los estados posibles son: U o D. El estado U implica activo y D inactivo.
[estado:nodo_no_aplicado]

Representa los nodos y su estado tal como lo informa el nodo par. Estos nodos no se aplicaron a la lista de monitoreo para este nodo par. Suelen ser transitorios y ocurren durante la fase de inicio del clúster o la reconfiguración de la red. Los estados posibles son: U o D. El estado U implica activo y D inactivo.

Propiedades de difusión

BROADCAST

Fuerza a todo el tráfico multicast a transmitirse solo por difusión, independientemente del tamaño del clúster y el número de destinos.
REPLICAST

Fuerza a todo el tráfico multicast a transmitirse solo por replicast, independientemente del tamaño del clúster y el número de destinos.
AUTOSELECT

Cambio automático a broadcast o replicast según el tamaño del clúster y el número de nodos de destino.
ratio TAMAÑO

Establece el criterio de AUTOSELECT, porcentaje de nodos de destino frente al tamaño del clúster.

EJEMPLOS

tipc link monitor list

Muestra la información de monitoreo de enlaces para los miembros del clúster en el dispositivo data0.

tipc link monitor summary

El comando monitor summary imprime los atributos básicos.

ESTADO DE SALIDA

El estado de salida es 0 si el comando se ejecutó correctamente o un entero positivo en caso de error.
