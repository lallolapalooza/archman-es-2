NOMBRE

tidy - comprobar, corregir y formatear archivos HTML(5)

SINOPSIS

tidy [opciones] [archivo ...] [opciones] [archivo ...] ...

DESCRIPCIÓN

Tidy lee archivos HTML, XHTML y XML y escribe marcado limpio. Para variantes de HTML, detecta, informa y corrige muchos errores comunes de codificación y se esfuerza por producir marcado visualmente equivalente que sea compatible con las especificaciones de HTML y que funcione en la mayoría de los navegadores.

Un uso común de Tidy es convertir HTML plano a XHTML. Para archivos XML genéricos, Tidy se limita a corregir errores básicos de corrección y a formatear.

Si no se especifica ningún archivo de entrada, Tidy lee la entrada estándar. Si no se especifica ningún archivo de salida, Tidy escribe el marcado limpio en la salida estándar. Si no se especifica ningún archivo de errores, Tidy escribe los mensajes en el error estándar.

OPCIONES

Tidy admite dos tipos de opciones. Las opciones puramente de línea de comandos, que comienzan con un guion simple '-', solo se pueden usar en la línea de comandos, no en archivos de configuración. Se enumeran en la primera parte de esta sección. Las opciones de configuración, por otro lado, se pueden pasar en la línea de comandos, comenzando con dos guiones --, o especificarse en un archivo de configuración, usando el nombre de la opción, seguido de dos puntos :, más el valor, sin los guiones iniciales. Se enumeran en la segunda parte de esta sección, con un archivo de configuración de ejemplo.

Para las opciones de línea de comandos que esperan un argumento numérico, se asume un valor predeterminado si no se puede encontrar un valor significativo. Por otro lado, las opciones de configuración no se pueden usar sin un valor; una opción de configuración sin valor se descarta simplemente y se informa como un error.

Usar una opción de línea de comandos es a veces equivalente a establecer el valor de una opción de configuración. La opción y el valor equivalentes se muestran entre paréntesis en la lista a continuación, tal como aparecerían en un archivo de configuración. Por ejemplo, -quiet, -q (quiet: yes) significa que usar la opción de línea de comandos -quiet o -q es equivalente a establecer la opción de configuración quiet a yes.

Las opciones de línea de comandos de una sola letra sin un valor asociado se pueden combinar; por ejemplo, '-i', '-m' y '-u' pueden combinarse como '-imu'.

Manipulación de archivos

-output <archivo>, -o <archivo> (output-file: <archivo>)
escribe la salida en el <archivo> especificado
-config <archivo>
establece opciones de configuración desde el <archivo> especificado
-file <archivo>, -f <archivo> (error-file: <archivo>)
escribe errores y advertencias en el <archivo> especificado
-modify, -m (write-back: yes)
modifica los archivos de entrada originales

Directivas de procesamiento

-indent, -i (indent: auto)
indenta el contenido de los elementos
-wrap <columna>, -w <columna> (wrap: <columna>)
envuelve el texto en la <columna> especificada. Se asume 0 si falta <columna>. Cuando se omite esta opción, se aplica el valor predeterminado de la opción de configuración 'wrap'.
-upper, -u (uppercase-tags: yes)
fuerza que las etiquetas estén en mayúsculas
-clean, -c (clean: yes)
reemplaza las etiquetas FONT, NOBR y CENTER con CSS
-bare, -b (bare: yes)
elimina comillas inteligentes y guiones largos, etc.
-gdoc, -g (gdoc: yes)
produce una versión limpia del HTML exportado por Google Docs
-numeric, -n (numeric-entities: yes)
produce entidades numéricas en lugar de nombradas
-errors, -e (markup: no)
muestra solo errores y advertencias
-quiet, -q (quiet: yes)
suprime la salida no esencial
-omit (omit-optional-tags: yes)
omite etiquetas de inicio y fin opcionales
-xml (input-xml: yes)
especifica que la entrada es XML bien formado
-asxml, -asxhtml (output-xhtml: yes)
convierte HTML a XHTML bien formado
-ashtml (output-html: yes)
fuerza XHTML a HTML bien formado
-access <nivel> (accessibility-check: <nivel>)
realiza comprobaciones adicionales de accesibilidad (<nivel> = 0, 1, 2, 3). Se asume 0 si falta <nivel>.

Las opciones de *Configuración* se pueden especificar anteponiendo a cada opción -- en la línea de comandos, seguido de su valor deseado, O colocando las opciones y valores en un archivo de configuración, y diciéndole a tidy que lea ese archivo con la opción -config:


tidy --opción1 valor1 --opción2 valor2 ...
tidy -config archivo-configuración ...

Las opciones de *Configuración* se pueden agrupar convenientemente en un único archivo de configuración. Un archivo de configuración de Tidy es simplemente un archivo de texto, donde cada opción se lista en una línea separada en el formato


opción1: valor1
opción2: valor2
etc.

Los valores permitidos para una opción dada dependen del Tipo de la opción. Hay cinco Tipos: Booleano, AutoBool, DocType, Enum y String. Los Tipos Booleanos permiten cualquiera de yes/no, y/n, true/false, t/f, 1/0. Los AutoBool permiten auto además de los valores permitidos por los Booleanos. Los Tipos Entero aceptan enteros no negativos. Los Tipos String generalmente no tienen valores predeterminados, y debes proporcionarlos sin comillas (a menos que desees que la salida contenga las comillas literales).

Los Tipos Enum, Encoding y DocType tienen un repertorio fijo de elementos, que se enumeran en las secciones de Valores compatibles a continuación.

Solo necesitas proporcionar opciones y valores para aquellos cuyos valores predeterminados deseas anular, aunque puedes incluir algunas opciones y valores ya predeterminados por razones de documentación y explicidad.

Aquí tienes un archivo de configuración de muestra, con al menos un ejemplo de cada uno de los cinco Tipos:


// opciones de configuración de muestra de Tidy
output-xhtml: yes
add-xml-decl: no
doctype: strict
char-encoding: ascii
indent: auto
wrap: 76
repeated-attributes: keep-last
error-file: errs.txt

A continuación se presenta un resumen y una breve descripción de cada una de las opciones. Se enumeran alfabéticamente dentro de cada categoría.

Opciones de Visualización del Documento

--gnu-emacs Booleano (no si no está establecido)

Esta opción especifica que Tidy debe cambiar el formato de informe de errores y advertencias a un formato que sea más fácilmente analizable por GNU Emacs o algún otro programa. Los cambia del formato predeterminado


línea <número de línea> columna <número de columna> - (Error|Advertencia): <mensaje>

a una forma que incluye el nombre del archivo de entrada:


<nombre de archivo>:<número de línea>:<número de columna>: (Error|Advertencia): <mensaje>

Ver también: --show-filename

--markup Booleano (yes si no está establecido)

Esta opción especifica si Tidy debe generar una versión con formato bonito del código. Nota: Tidy no generará una versión con formato bonito si encuentra errores significativos (ver force-output).
--mute String

Usa esta opción para evitar que Tidy muestre ciertos tipos de salida de informe, por ejemplo, para condiciones que desees ignorar.

Esta opción toma una lista de una o más claves que indican el tipo de mensaje a silenciar. Puedes descubrir estas claves de mensaje usando la opción de configuración mute-id y examinando la salida de Tidy.

Ver también: --mute-id

--mute-id Booleano (no si no está establecido)

Esta opción indica si Tidy debe mostrar los ID de los mensajes con cada uno de sus informes de error. Esto podría ser útil si quisieras usar la opción de configuración mute para filtrar ciertos mensajes del informe.

Ver también: --mute

--quiet Booleano (no si no está establecido)

Cuando está habilitada, esta opción limita la salida no documental de Tidy para informar solo de las advertencias y errores del documento.
--show-body-only Enum (no si no está establecido)

Valores compatibles: no, yes, auto

Esta opción especifica si Tidy debe imprimir solo el contenido de la etiqueta body como un fragmento HTML.

Si se establece en auto, esto se realiza solo si la etiqueta body ha sido inferida.

Útil para incorporar páginas completas existentes como una porción de otra página.

Esta opción no tiene efecto si se solicita salida XML.

--show-errors Entero (6 si no está establecido)

Esta opción especifica el número que Tidy utiliza para determinar si se deben mostrar errores adicionales. Si se establece en 0, entonces no se muestran errores.
--show-filename Booleano (no si no está establecido)

Esta opción especifica si Tidy debe mostrar el nombre del archivo en los mensajes. Ej:


tidy -q -e --show-filename yes index.html


index.html: línea 43 columna 3 - Advertencia: reemplazando bytes UTF-8 inválidos (código de carácter U+00A9)

Ver también: --gnu-emacs

--show-info Booleano (yes si no está establecido)

Esta opción especifica si Tidy debe mostrar mensajes de nivel informativo.
--show-warnings Booleano (yes si no está establecido)

Esta opción especifica si Tidy debe suprimir las advertencias. Esto puede ser útil cuando pocos errores quedan ocultos en un aluvión de advertencias.

Opciones de Entrada y Salida del Documento

--add-meta-charset Booleano (no si no está establecido)

Esta opción, cuando se habilita, agrega un elemento <meta> y establece el atributo charset a la codificación del documento. Establezca esta opción en yes para habilitarla.
--add-xml-decl Booleano (no si no está establecido)

Esta opción especifica si Tidy debe agregar la declaración XML al generar XML o XHTML.

Tenga en cuenta que si la entrada ya incluye una declaración <?xml ... ?>, esta opción será ignorada.

Si la codificación para la salida es diferente de ascii, una de las codificaciones utf*, o raw, entonces la declaración se agrega siempre según lo requiere el estándar XML.

Ver también: --char-encoding, --output-encoding

--add-xml-space Booleano (no si no está establecido)

Esta opción especifica si Tidy debe agregar xml:space="preserve" a elementos como <pre>, <style> y <script> al generar XML.

Esto es necesario si el espacio en blanco en dichos elementos se va a analizar adecuadamente sin tener acceso a la DTD.

--doctype String (auto si no está establecido)

Esta opción especifica la declaración DOCTYPE generada por Tidy.

Si se establece en omit, la salida no contendrá una declaración DOCTYPE. Tenga en cuenta que esto también implica que numeric-entities se establece en yes.

Si se establece en html5, el DOCTYPE se establece en <!DOCTYPE html>.

Si se establece en auto (el valor predeterminado), Tidy hará una suposición educada basada en el contenido del documento. Tenga en cuenta que seleccionar esta opción no cambiará el DOCTYPE del documento actual en la salida.

Si se establece en strict, Tidy establecerá el DOCTYPE a la DTD estricta de HTML4 o XHTML1.

Si se establece en loose, el DOCTYPE se establece a la DTD suelta (transicional) de HTML4 o XHTML1.

Alternativamente, puedes proporcionar una cadena para el identificador público formal (FPI).

Por ejemplo:

doctype: "-//ACME//DTD HTML 3.14159//EN"

Si especifica el FPI para un documento XHTML, Tidy establecerá el identificador del sistema a una cadena vacía. Para un documento HTML, Tidy agrega un identificador del sistema solo si ya estaba presente para preservar el modo de procesamiento de algunos navegadores. Tidy deja el DOCTYPE para documentos XML genéricos sin cambios.

Esta opción no ofrece una validación de la conformidad del documento.

--input-xml Booleano (no si no está establecido)

Esta opción especifica si Tidy debe usar el analizador XML en lugar del HTML con corrección de errores.

parser

--output-html Boolean (no si no está establecido)

Esta opción especifica si Tidy debe generar una salida formateada ("pretty printed"), escribiéndola como HTML.
--output-xhtml Boolean (no si no está establecido)

Esta opción especifica si Tidy debe generar una salida formateada ("pretty printed"), escribiéndola como HTML extensible.

Esta opción hace que Tidy establezca el DOCTYPE y el espacio de nombres predeterminado según corresponda para XHTML, y utilizará el valor corregido en la salida independientemente de otras fuentes.

Para XHTML, las entidades se pueden escribir como entidades nombradas o numéricas según la configuración de numeric-entities.

La capitalización original de las etiquetas y atributos se preservará, independientemente de otras opciones.

--output-xml Boolean (no si no está establecido)

Esta opción especifica si Tidy debe formatear la salida ("pretty print"), escribiéndola como XML bien formado.

Cualquier entidad no definida en XML 1.0 se escribirá como entidades numéricas para permitir su análisis por un analizador XML.

La capitalización original de las etiquetas y atributos se preservará, independientemente de otras opciones.

Opciones de Entrada/Salida de Archivos

--error-file String

Esta opción especifica el archivo de errores que Tidy utiliza para errores y advertencias. Normalmente, los errores y advertencias se envían a stderr.

Ver también: --output-file

--keep-time Boolean (no si no está establecido)

Esta opción especifica si Tidy debe conservar la hora de modificación original de los archivos que Tidy modifica in situ.

Establecer la opción en yes le permite limpiar archivos sin cambiar la fecha de modificación del archivo, lo que puede ser útil con ciertas herramientas que utilizan la fecha de modificación para cosas como el despliegue automático del servidor.

Tenga en cuenta que esta característica no es compatible en algunas plataformas.

--output-file String

Esta opción especifica el archivo de salida que Tidy utiliza para el marcado. Normalmente, el marcado se escribe en stdout.

Ver también: --error-file

--write-back Boolean (no si no está establecido)

Esta opción especifica si Tidy debe escribir el marcado limpio de vuelta en el mismo archivo del que leyó.

Se le aconseja mantener copias de los archivos importantes antes de limpiarlos, ya que en raras ocasiones el resultado puede no ser el esperado.

Opciones de Diagnóstico

--accessibility-check Enum (0 (Tidy Classic) si no está establecido)

Valores admitidos: 0 (Tidy Classic), 1 (Comprobaciones Prioridad 1), 2 (Comprobaciones Prioridad 2), 3 (Comprobaciones Prioridad 3)

Esta opción especifica qué nivel de comprobación de accesibilidad, si es que hay alguna, debe realizar Tidy.

El nivel 0 (Tidy Classic) es equivalente a la comprobación de accesibilidad de Tidy Classic.

Para más información sobre la comprobación de accesibilidad de Tidy, visite la Página de Accesibilidad de Tidy en http://www.html-tidy.org/accessibility/.

--force-output Boolean (no si no está establecido)

Esta opción especifica si Tidy debe producir salida incluso si se encuentran errores.

Use esta opción con cuidado; si Tidy informa de un error, esto significa que Tidy no pudo (o no está seguro de cómo) corregir el error, por lo que la salida resultante puede no reflejar su intención.

--show-meta-change Boolean (no si no está establecido)

Esta opción habilita un mensaje cada vez que Tidy cambia el atributo content de una declaración de meta charset para que coincida con la codificación del documento. Establezca esta opción en yes para habilitarla.
--warn-proprietary-attributes Boolean (yes si no está establecido)

Esta opción especifica si Tidy debe advertir sobre atributos propietarios.

Opciones de Codificación

--char-encoding Encoding (utf8 si no está establecido)

Valores admitidos: raw, ascii, latin0, latin1, utf8, iso2022, mac, win1252, ibm858, utf16le, utf16be, utf16, big5, shiftjis

Esta opción especifica la codificación de caracteres que Tidy utiliza para la entrada y, cuando se establece, elige automáticamente una codificación de caracteres apropiada para la salida. La codificación de salida que Tidy elige puede ser diferente de la codificación de entrada.

Para las codificaciones de entrada ascii, latin0, ibm858, mac y win1252, la opción output-encoding se establecerá automáticamente en ascii. Puede establecer output-encoding manualmente para anular esto.

Para otras codificaciones de entrada, la opción output-encoding se establecerá automáticamente en el mismo valor.

Independientemente del valor preestablecido, puede establecer output-encoding manualmente para anular esto.

Tidy no es un conversor de codificaciones. Aunque las codificaciones Latinas y UTF se pueden mezclar libremente, no es posible convertir codificaciones asiáticas a codificaciones latinas con Tidy.

Ver también: --input-encoding, --output-encoding

--input-encoding Encoding (utf8 si no está establecido)

Valores admitidos: raw, ascii, latin0, latin1, utf8, iso2022, mac, win1252, ibm858, utf16le, utf16be, utf16, big5, shiftjis

Esta opción especifica la codificación de caracteres que Tidy utiliza para la entrada. Tidy hace ciertas suposiciones sobre algunas de las codificaciones de entrada.

Para ascii, Tidy aceptará valores de caracteres Latin-1 (ISO-8859-1) y los convertirá a entidades según sea necesario.

Para raw, Tidy no hará suposiciones sobre los valores de caracteres y los pasará sin cambios a la salida.

Para mac y win1252, se aceptarán valores de caracteres específicos del proveedor y se convertirán a entidades según sea necesario.

Las codificaciones asiáticas como iso2022 se manejarán adecuadamente asumiendo que también se especifica la correspondiente output-encoding.

Tidy no es un conversor de codificaciones. Aunque las codificaciones Latinas y UTF se pueden mezclar libremente, no es posible convertir codificaciones asiáticas a codificaciones latinas con Tidy.

Ver también: --char-encoding

--newline Enum (LF si no está establecido)

Valores admitidos: LF, CRLF, CR

El valor predeterminado es apropiado para la plataforma actual.

Generalmente CRLF en PC-DOS, Windows y OS/2; CR en Classic Mac OS; y LF en cualquier otro lugar (Linux, macOS y Unix).

--output-bom Enum (auto si no está establecido)

Valores admitidos: no, yes, auto

Esta opción especifica si Tidy debe escribir un carácter de Marcador de Orden de Byte Unicode (BOM; también conocido como Espacio de No Separación de Ancho Cero; tiene el valor U+FEFF) al principio de la salida, y solo se aplica a las codificaciones de salida UTF-8 y UTF-16.

Si se establece en auto, esta opción hace que Tidy escriba un BOM en la salida solo si había un BOM al principio de la entrada.

Siempre se escribe un BOM para la salida XML/XHTML utilizando codificaciones de salida UTF-16.

--output-encoding Encoding (utf8 si no está establecido)

Valores admitidos: raw, ascii, latin0, latin1, utf8, iso2022, mac, win1252, ibm858, utf16le, utf16be, utf16, big5, shiftjis

Esta opción especifica la codificación de caracteres que Tidy utiliza para la salida. Algunas de las codificaciones de salida afectan si algunos caracteres se traducen a entidades o no, aunque en todos los casos, algunas entidades se escribirán de acuerdo con otras opciones de configuración de Tidy.

Para las codificaciones de salida ascii, mac y win1252, se utilizarán entidades para todos los caracteres con valores superiores a 127.

Para la salida raw, Tidy escribirá valores superiores a 127 sin traducirlos a entidades.

La salida utilizando latin1 hará que Tidy escriba valores de caracteres superiores a 255 como entidades.

La familia UTF, como utf8, escribirá la salida en la codificación UTF correspondiente.

Las codificaciones de salida asiáticas como iso2022 escribirán la salida en la codificación especificada, asumiendo que se especificó una input-encoding correspondiente.

Tidy no es un conversor de codificaciones. Aunque las codificaciones Latinas y UTF se pueden mezclar libremente, no es posible convertir codificaciones asiáticas a codificaciones latinas con Tidy.

Ver también: --char-encoding

Opciones de Limpieza

--bare Boolean (no si no está establecido)

Esta opción especifica si Tidy debe reemplazar las comillas tipográficas y las rayas de em con ASCII, y producir espacios en lugar de espacios sin interrupción, donde existan en la entrada.
--clean Boolean (no si no está establecido)

Esta opción especifica si Tidy debe realizar la limpieza de algunas etiquetas presentacionales heredadas (actualmente <i>, <b>, <center> con <font>). Si se establece en sí, las etiquetas heredadas se reemplazarán con etiquetas <style> CSS y marcado estructural según corresponda.
--drop-empty-elements Boolean (sí si no está establecido)

Esta opción especifica si Tidy debe descartar los elementos vacíos.
--drop-empty-paras Boolean (sí si no está establecido)

Esta opción especifica si Tidy debe descartar los párrafos vacíos.
--drop-proprietary-attributes Boolean (no si no está establecido)

Esta opción especifica si Tidy debe eliminar los atributos propietarios, como los atributos de enlace de datos de Microsoft. Además, los atributos que no están permitidos en la versión de salida de HTML se descartarán si se usan con strict-tags-attributes.
--gdoc Boolean (no si no está establecido)

Esta opción especifica si Tidy debe habilitar un comportamiento específico para limpiar el HTML exportado desde Google Docs.
--logical-emphasis Boolean (no si no está establecido)

Esta opción especifica si Tidy debe reemplazar cualquier ocurrencia de <i> con <em> y cualquier ocurrencia de <b> con <strong>. Los atributos se conservan sin cambios.

Esta opción se puede configurar independientemente de la opción clean.

--merge-divs Enum (auto si no está establecido)

Valores admitidos: no, sí, auto

Esta opción se puede usar para modificar el comportamiento de clean cuando se establece en sí.

Esta opción especifica si Tidy debe fusionar <div> anidados como <div><div>...</div></div>.

Si se establece en auto, los atributos del <div> interno se mueven al exterior. Los <div> anidados con atributos id no se fusionan.

Si se establece en sí, los atributos del <div> interno se descartan, con la excepción de class y style.

Ver también: --clean, --merge-spans

--merge-spans Enum (auto si no está establecido)

Valores admitidos: no, sí, auto

Esta opción se puede usar para modificar el comportamiento de clean cuando se establece en sí.

Esta opción especifica si Tidy debe fusionar <span> anidados como <span><span>...</span></span>.

El algoritmo es idéntico al utilizado por merge-divs.

Ver también: --clean, --merge-divs

--word-2000 Boolean (no si no está establecido)

Esta opción especifica si Tidy debe hacer grandes esfuerzos para eliminar todo el contenido sobrante que Microsoft Word 2000 inserta al guardar documentos de Word como "páginas web". No maneja imágenes incrustadas ni VML.

Debería considerar guardar usando el comando de Word Guardar como... y eligiendo Página Web, Filtrada.

Opciones de entidades

--ascii-chars Boolean (no si no está establecido)

Se puede usar para modificar el comportamiento de la opción clean cuando se establece en sí.

Si se establece en sí al usar clean, &emdash;, &rdquo; y otras entidades de caracteres nombradas se degradan a sus equivalentes ASCII más cercanos.

Ver también: --clean

--ncr Boolean (sí si no está establecido)

Esta opción especifica si Tidy debe permitir referencias de caracteres numéricos.
--numeric-entities Boolean (no si no está establecido)

Esta opción especifica si Tidy debe generar entidades distintas de las entidades HTML integradas (&amp;, &lt;, &gt; y &quot;) en forma numérica en lugar de nombrada.

Solo se utilizan las entidades compatibles con la declaración DOCTYPE generada.

Las entidades que se pueden representar en la codificación de salida se traducen correspondientemente.

Ver también: --doctype, --preserve-entities

--preserve-entities Boolean (no si no está establecido)

Esta opción especifica si Tidy debe preservar las entidades bien formadas tal como se encuentran en la entrada.
--quote-ampersand Boolean (sí si no está establecido)

Esta opción especifica si Tidy debe generar caracteres & sin adornar como &amp;, solo en doctypes heredados.
--quote-marks Boolean (no si no está establecido)

Esta opción especifica si Tidy debe generar caracteres " como &quot;, como prefieren algunos entornos de edición.

El carácter de apóstrofe ' se escribe como &#39; ya que muchos navegadores web aún no admiten &apos;.

--quote-nbsp Boolean (sí si no está establecido)

Esta opción especifica si Tidy debe generar caracteres de espacio sin separación como entidades, en lugar de como el valor del carácter Unicode 160 (decimal).

Opciones de reparación

--alt-text String

Esta opción especifica el texto predeterminado alt= que Tidy utiliza para los atributos <img> cuando falta el atributo alt=.

Úselo con precaución, ya que es su responsabilidad hacer que sus documentos sean accesibles para las personas que no pueden ver las imágenes.

--anchor-as-name Boolean (sí si no está establecido)

Esta opción controla la eliminación o adición del atributo name en elementos donde puede servir como ancla.

Si se establece en sí, se agrega un atributo name, si aún no existe, junto con un atributo id existente si el DTD lo permite.

Si se establece en no, se elimina cualquier atributo name existente si existe un atributo id o se ha agregado.

--assume-xml-procins Boolean (no si no está establecido)

Esta opción especifica si Tidy debe cambiar el análisis de las instrucciones de procesamiento para requerir ?> como terminador en lugar de >.

Esta opción se establece automáticamente si la entrada es XML.

--coerce-endtags Boolean (sí si no está establecido)

Esta opción especifica si Tidy debe forzar una etiqueta de inicio a una etiqueta de fin en casos donde parece que se pretendía una etiqueta de fin; por ejemplo, dada

<span>foo <b>bar<b> baz</span>

Tidy generará

<span>foo <b>bar</b> baz</span>

--css-prefix String (c si no está establecido)

Esta opción especifica el prefijo que Tidy utiliza para las reglas de estilo.

Por defecto, se utilizará c.

--custom-tags Enum (no si no está establecido)

Valores admitidos: no, blocklevel, empty, inline, pre

Esta opción habilita el uso de etiquetas para elementos personalizados autónomos, por ejemplo, <flag-icon> con Tidy. Las etiquetas personalizadas se deshabilitan si este valor es no. Otros ajustes - blocklevel, empty, inline y pre tratarán todas las etiquetas personalizadas detectadas correspondientemente.

El uso de new-blocklevel-tags, new-empty-tags, new-inline-tags o new-pre-tags anulará el tratamiento de las etiquetas personalizadas por esta opción de configuración. Esto puede ser útil si tiene diferentes tipos de etiquetas personalizadas.

Cuando se habilitan, estas etiquetas se determinan durante el procesamiento de su documento utilizando etiquetas de apertura; las etiquetas de cierre coincidentes se reconocerán en consecuencia y las etiquetas de cierre desconocidas se descartarán.

Ver también: --new-blocklevel-tags, --new-empty-tags, --new-inline-tags, --new-pre-tags

--enclose-block-text Boolean (no si no está establecido)

Esta opción especifica si Tidy debe insertar un elemento <p> para incluir cualquier texto que encuentre en cualquier elemento que permita contenido mixto para HTML transicional pero no para HTML estricto.
--enclose-text Boolean (no si no está establecido)

Esta opción especifica si Tidy debe incluir cualquier texto que encuentre en el elemento body dentro de un elemento <p>.

Esto es útil cuando desea tomar HTML existente y usarlo con una hoja de estilos.

--escape-scripts Boolean (sí si no está establecido)

Esta opción hace que los elementos que parecen etiquetas de cierre, como </g, se escapen a <\/g. Establezca esta opción en no si no desea esto.
--fix-backslash Boolean (sí si no está establecido)

Esta opción especifica si Tidy sen URLs con barras inclinadas /.
--fix-bad-comments Enum (auto si no está configurado)

Valores soportados: no, yes, auto

Esta opción especifica si Tidy debe reemplazar guiones inesperados con caracteres = cuando encuentra guiones adyacentes.

El valor predeterminado es auto que actuará como no para tipos de documentos HTML5, y yes para todos los demás tipos de documentos.

HTML ha abandonado la sintaxis de comentarios SGML y permite guiones adyacentes para todas las versiones de HTML, aunque XML y XHTML no lo hacen. Si planea dar soporte a navegadores antiguos que requieren sintaxis de comentarios SGML, considere establecer este valor en yes.

--fix-style-tags Boolean (yes si no está configurado)

Esta opción especifica si Tidy debe mover todas las etiquetas de estilo al encabezado del documento.
--fix-uri Boolean (yes si no está configurado)

Esta opción especifica si Tidy debe verificar los valores de atributos que contienen URIs en busca de caracteres ilegales y, si se encuentran, escaparlos como recomienda HTML4.
--literal-attributes Boolean (no si no está configurado)

Esta opción especifica cómo Tidy maneja los caracteres de espacio en blanco dentro de los valores de los atributos.

Si el valor es no, Tidy normaliza los valores de los atributos reemplazando cualquier salto de línea o tabulación con un único espacio, y además reemplazando cualquier espacio en blanco contiguo con un único espacio.

Para forzar a Tidy a preservar los valores originales y literales de todos los atributos y asegurar que los espacios en blanco dentro de los valores de los atributos se pasen sin cambios, establezca esta opción en yes.

--lower-literals Boolean (yes si no está configurado)

Esta opción especifica si Tidy debe convertir el valor de un atributo que acepta una lista de valores predefinidos a minúsculas.

Esto es requerido para documentos XHTML.

--repeated-attributes Enum (keep-last si no está configurado)

Valores soportados: keep-first, keep-last

Esta opción especifica si Tidy debe conservar el primer o último atributo, si un atributo se repite, por ejemplo, tiene dos atributos align.

Ver también: --join-classes, --join-styles

--skip-nested Boolean (yes si no está configurado)

Esta opción especifica que Tidy debe omitir etiquetas anidadas al analizar datos de script y estilo.
--strict-tags-attributes Boolean (no si no está configurado)

Esta opción asegura que las etiquetas y atributos sean aplicables para la versión de HTML que Tidy genera. Cuando se establece en yes y el tipo de documento de salida es un doctype estricto, Tidy informará errores. Si el tipo de documento de salida es un doctype suelto o transicional, Tidy informará advertencias.

Además, si drop-proprietary-attributes está habilitado, los atributos no aplicables también serán eliminados.

Cuando se establece en no, estas verificaciones no se realizan.

--uppercase-attributes Enum (no si no está configurado)

Valores soportados: no, yes, preserve

Esta opción especifica si Tidy debe generar los nombres de los atributos en mayúsculas.

Cuando se establece en no, los nombres de los atributos se escribirán en minúsculas. Especificar yes generará los nombres de los atributos en mayúsculas, y preserve se puede usar para dejar los nombres de los atributos sin cambios.

Al usar entrada XML, el caso original siempre se preserva.

--uppercase-tags Boolean (no si no está configurado)

Esta opción especifica si Tidy debe generar los nombres de las etiquetas en mayúsculas.

El valor predeterminado es no, lo que resulta en nombres de etiquetas en minúsculas, excepto para la entrada XML donde se preserva el caso original.

--decorate-inferred-ul Boolean (no si no está configurado)

--escape-cdata Boolean (no si no está configurado)

Esta opción especifica si Tidy debe convertir las secciones <![CDATA[]]> en texto normal.
--hide-comments Boolean (no si no está configurado)

Esta opción especifica si Tidy no debe imprimir comentarios.
--join-classes Boolean (no si no está configurado)

Esta opción especifica si Tidy debe combinar nombres de clase para generar un único nombre de clase nuevo si se detectan múltiples asignaciones de clase en un elemento.
--join-styles Boolean (yes si no está configurado)

Opciones de Enseñanza a Tidy

--new-blocklevel-tags Nombres de Etiquetas

Valores soportados: tagX, tagY, ...

--new-empty-tags Nombres de Etiquetas

Esta opción especifica nuevas etiquetas vacías en línea. Esta opción toma una lista de nombres de etiquetas separada por espacios o comas.

A menos que declare nuevas etiquetas, Tidy se negará a generar un archivo limpiado si la entrada incluye etiquetas desconocidas previamente.

Recuerde declarar también las etiquetas vacías como en línea o de nivel de bloque.

Esta opción se ignora en modo XML.

Ver también: --new-blocklevel-tags, --new-inline-tags, --new-pre-tags, --custom-tags

--new-inline-tags Nombres de Etiquetas

OPTIONS

--indent Boolean (yes if unset)

This option specifies if Tidy should indent the markup.

Indented markup is easier to read. The default is to indent.

If this option is set to no, Tidy will not add any indentation or line breaks beyond what is necessary to conform to the markup language specification. Indentation may introduce newlines that might be considered markup errors by some validators. This option does not affect the indentation of tags within tables and preformatted blocks, or other block-level elements.

Setting indent to yes can expose layout bugs in some browsers.

Use the option indent-spaces to control the number of spaces or tabs output per level of indent, and indent-with-tabs to specify whether spaces or tabs are used.

See also: --indent-spaces

--indent-attributes Boolean (no if unset)

This option specifies if Tidy should begin each attribute on a new line.
--indent-cdata Boolean (no if unset)

This option specifies if Tidy should indent <![CDATA[]]> sections.
--indent-spaces Integer (2 if unset)

This option specifies the number of spaces or tabs that Tidy uses to indent content when indent is enabled.

Note that the default value for this option is dependent upon the value of indent-with-tabs (see also).

See also: --indent

--indent-with-tabs Boolean (no if unset)

This option specifies if Tidy should indent with tabs instead of spaces, assuming indent is yes.

Set it to yes to indent using tabs instead of the default spaces.

Use the option indent-spaces to control the number of tabs output per level of indent. Note that when indent-with-tabs is enabled the default value of indent-spaces is reset to 1.

Note tab-size controls converting input tabs to spaces. Set it to zero to retain input tabs.

--keep-tabs Boolean (no if unset)

With the default no Tidy will replace all source tabs with spaces, controlled by the option tab-size, and the current line offset. Of course, except in the special blocks/elements enumerated below, this will later be reduced to just one space.

If set yes this option specifies Tidy should keep certain tabs found in the source, but only in preformatted blocks like <pre>, and other CDATA elements like <script>, <style>, and other pseudo elements like <?php ... ?>. As always, all other tabs, or sequences of tabs, in the source will continue to be replaced with a space.

--omit-optional-tags Boolean (no if unset)

This option specifies if Tidy should omit optional start tags and end tags when generating output.

Setting this option causes all tags for the <html>, <head>, and <body> elements to be omitted from output, as well as such end tags as </p>, </li>, </dt>, </dd>, </option>, </tr>, </td>, and </th>.

This option is ignored for XML output.

--priority-attributes Nombres de atributos

Valores soportados: atributoX, atributoY, ...

Esta opción permite priorizar la escritura de atributos en documentos ordenados, permitiendo que se escriban antes que los demás atributos de un elemento. Por ejemplo, podrías especificar que id y name se escriban antes que cualquier otro atributo.

Esta opción toma una lista de nombres de atributos separados por espacios o comas.

--punctuation-wrap Booleano (no si no está establecido)

Esta opción especifica si Tidy debe dividir líneas después de ciertos caracteres de puntuación Unicode o chinos.
--sort-attributes Enumerado (none si no está establecido)

Valores soportados: none, alpha

Esta opción especifica que Tidy debe ordenar los atributos dentro de un elemento usando el algoritmo de ordenación especificado. Si se establece a alpha, el algoritmo es una ordenación alfabética ascendente.

Cuando se usa junto con la ordenación por priority-attributes, cualquier ordenación de atributos tendrá lugar después de que se hayan escrito los atributos de prioridad.

Ver también: --priority-attributes

--tab-size Entero (8 si no está establecido)

Esta opción especifica el número de columnas que Tidy utiliza entre las paradas de tabulación sucesivas. Se utiliza para mapear tabulaciones a espacios al leer la entrada.
--tidy-mark Booleano (yes si no está establecido)

Esta opción especifica si Tidy debe añadir un elemento meta a la cabeza del documento para indicar que el documento ha sido ordenado.

Tidy no añadirá un elemento meta si ya existe uno.

--vertical-space Enumerado (no si no está establecido)

Valores soportados: no, yes, auto

Esta opción especifica si Tidy debe añadir algunas líneas en blanco adicionales para mejorar la legibilidad.

El valor predeterminado es no.

Si se establece a auto, Tidy eliminará casi todos los caracteres de nueva línea.

--wrap Entero (68 si no está establecido)

Esta opción especifica el margen derecho que Tidy utiliza para dividir líneas.

Tidy intenta dividir líneas para que no excedan esta longitud.

Establezca wrap a 0 (cero) si desea deshabilitar la división de líneas.

--wrap-asp Booleano (yes si no está establecido)

Esta opción especifica si Tidy debe dividir líneas de texto contenido dentro de elementos pseudo ASP, que se ven así: <% ... %>.
--wrap-attributes Booleano (no si no está establecido)

Esta opción especifica si Tidy debe dividir en líneas los valores de los atributos, lo que significa que si el valor de un atributo hace que una línea exceda el ancho especificado por wrap, Tidy añadirá uno o más saltos de línea al valor, haciendo que se divida en varias líneas.

Tenga en cuenta que esta opción se puede establecer de forma independiente de wrap-script-literals. De forma predeterminada, Tidy reemplaza cualquier nueva línea o tabulación con un solo espacio y reemplaza cualquier secuencia de espacios en blanco con un solo espacio.

Para forzar a Tidy a conservar los valores literales originales de todos los atributos y asegurar que los caracteres de espacio en blanco dentro de los valores de los atributos se transmitan sin cambios, establezca literal-attributes a yes.

Ver también: --wrap-script-literals, --literal-attributes

--wrap-jste Booleano (yes si no está establecido)

Esta opción especifica si Tidy debe dividir líneas de texto contenido dentro de elementos pseudo JSTE, que se ven así: <# ... #>.
--wrap-php Booleano (no si no está establecido)

Esta opción especifica si Tidy debe añadir una nueva línea después de los elementos pseudo PHP, que se ven así: <?php ... ?>.
--wrap-script-literals Booleano (no si no está establecido)

Esta opción especifica si Tidy debe dividir en líneas las cadenas literales que aparecen en atributos de script.

Tidy divide las cadenas literales largas de script insertando un carácter de barra invertida antes del salto de línea.

Ver también: --wrap-attributes

--wrap-sections Booleano (yes si no está establecido)

Esta opción especifica si Tidy debe dividir en líneas el texto contenido dentro de las etiquetas de sección <![ ... ]>.

ENTORNO

HTML_TIDY
Nombre del archivo de configuración predeterminado. Debe ser una ruta absoluta, ya que probablemente invocarás tidy desde diferentes directorios. El valor de HTML_TIDY se analizará después del valor predeterminado compilado (definido con -DTIDY_CONFIG_FILE), pero antes que cualquiera de los archivos especificados con -config.
ARCHIVOS DE CONFIGURACIÓN EN TIEMPO DE EJECUCIÓN
También puedes especificar archivos de configuración en tiempo de ejecución desde los cuales tidy intentará cargar una configuración automáticamente.
El archivo de configuración del sistema en tiempo de ejecución (/etc/tidy.conf), si existe, se cargará y aplicará primero, seguido por el archivo de configuración del usuario en tiempo de ejecución (~/.tidyrc). El uso subsiguiente de una opción específica anulará cualquier uso previo.
Ten en cuenta que si utilizas la variable de entorno HTML_TIDY, el archivo de configuración del usuario en tiempo de ejecución no se usará. Esto es una característica, no un error.
