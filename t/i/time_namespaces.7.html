NOMBRE

time_namespaces - resumen de los namespaces de tiempo de Linux

DESCRIPCIÓN

Los namespaces de tiempo virtualizan los valores de dos relojes del sistema:

•
CLOCK_MONOTONIC (y de forma similar CLOCK_MONOTONIC_COARSE y CLOCK_MONOTONIC_RAW), un reloj no ajustable que representa el tiempo monótono desde —como se describe en POSIX— "un punto no especificado en el pasado".
•
CLOCK_BOOTTIME (y de forma similar CLOCK_BOOTTIME_ALARM), un reloj no ajustable que es idéntico a CLOCK_MONOTONIC, excepto que también incluye el tiempo que el sistema está suspendido.

Por lo tanto, los procesos en un namespace de tiempo comparten valores por namespace para estos relojes. Esto afecta a varias APIs que miden contra estos relojes, incluyendo: clock_gettime(2), clock_nanosleep(2), nanosleep(2), timer_settime(2), timerfd_settime(2), y /proc/uptime.

Actualmente, la única forma de crear un namespace de tiempo es llamando a unshare(2) con el flag CLONE_NEWTIME. Esta llamada crea un nuevo namespace de tiempo pero *no* coloca al proceso llamante en el nuevo namespace. En su lugar, los hijos creados posteriormente por el proceso llamante se colocan en el nuevo namespace. Esto permite que los desplazamientos del reloj (ver más abajo) para el nuevo namespace se establezcan antes de que el primer proceso se coloque en el namespace. El enlace simbólico /proc/pid/ns/time_for_children muestra el namespace de tiempo en el que se crearán los hijos de un proceso. (Un proceso puede usar un descriptor de archivo abierto en este enlace simbólico en una llamada a setns(2) para moverse al namespace.)

/proc/pid/timens_offsets

Asociados a cada namespace de tiempo hay desplazamientos, expresados con respecto al namespace de tiempo inicial, que definen los valores de los relojes monótono y de tiempo de arranque en ese namespace. Estos desplazamientos se exponen a través del archivo /proc/pid/timens_offsets. Dentro de este archivo, los desplazamientos se expresan como líneas que consisten en tres campos delimitados por espacios:


<id-reloj> <offset-secs> <offset-nanosecs>

El id-reloj es una cadena que identifica el reloj cuyos desplazamientos se muestran. Este campo es monotonic, para CLOCK_MONOTONIC, o boottime, para CLOCK_BOOTTIME. Los campos restantes expresan el desplazamiento (segundos más nanosegundos) para el reloj en este namespace de tiempo. Estos desplazamientos se expresan en relación con los valores del reloj en el namespace de tiempo inicial. El valor offset-secs puede ser negativo, sujeto a las restricciones indicadas a continuación; offset-nanosecs es un valor sin signo.

En el namespace de tiempo inicial, el contenido del archivo timens_offsets es el siguiente:


$ cat /proc/self/timens_offsets
monotonic           0         0
boottime            0         0

En un nuevo namespace de tiempo que no ha tenido ningún proceso miembro, los desplazamientos del reloj se pueden modificar escribiendo registros terminados en nueva línea de la misma forma en el archivo timens_offsets. El archivo se puede escribir varias veces, pero después de que el primer proceso haya sido creado o haya entrado en el namespace, las escrituras en este archivo fallan con el error EACCES. Para poder escribir en el archivo timens_offsets, un proceso debe tener la capacidad CAP_SYS_TIME en el namespace de usuario que posee el namespace de tiempo.

Las escrituras en el archivo timens_offsets pueden fallar con los siguientes errores:

EINVAL
Un valor offset-nanosecs es mayor que 999.999.999.
EINVAL
Un valor id-reloj no es válido.
EPERM
El llamante no tiene la capacidad CAP_SYS_TIME.
ERANGE
Un valor offset-secs está fuera de rango. En particular;
•
offset-secs no se puede establecer en un valor que haría que la hora actual en el reloj correspondiente dentro del namespace fuera un valor negativo; y
•
offset-secs no se puede establecer en un valor tal que la hora en el reloj correspondiente dentro del namespace exceda la mitad del valor de la constante del kernel KTIME_SEC_MAX (esto limita el valor del reloj a un máximo de aproximadamente 146 años).

En un nuevo namespace de tiempo creado por unshare(2), el contenido del archivo timens_offsets se hereda del namespace de tiempo del proceso creador.

NOTAS

El uso de namespaces de tiempo requiere un kernel configurado con la opción CONFIG_TIME_NS.

Tenga en cuenta que los namespaces de tiempo no virtualizan el reloj CLOCK_REALTIME. La virtualización de este reloj se evitó por razones de complejidad y sobrecarga dentro del kernel.

Para compatibilidad con la implementación inicial, al escribir un id-reloj en el archivo /proc/pid/timens_offsets, se pueden escribir los valores numéricos de los IDs en lugar de los nombres simbólicos mostrados arriba; es decir, 1 en lugar de monotonic, y 7 en lugar de boottime. Para mayor legibilidad, se prefiere el uso de los nombres simbólicos sobre los números.

La motivación para añadir namespaces de tiempo fue permitir que los relojes monótono y de tiempo de arranque mantuvieran valores consistentes durante la migración de contenedores y la restauración de puntos de control.

EJEMPLOS

La siguiente sesión de shell demuestra el funcionamiento de los namespaces de tiempo. Comenzamos mostrando el número de inodo del namespace de tiempo de un shell en el namespace de tiempo inicial:


$ readlink /proc/$$/ns/time
time:[4026531834]

Continuando en el namespace de tiempo inicial, mostramos el tiempo de actividad del sistema usando uptime(1) y usamos el programa de ejemplo clock_times mostrado en clock_getres(2) para mostrar los valores de varios relojes:


$ uptime --pretty
up 21 hours, 17 minutes
$ ./clock_times
CLOCK_REALTIME : 1585989401.971 (18356 days +  8h 36m 41s)
CLOCK_TAI      : 1585989438.972 (18356 days +  8h 37m 18s)
CLOCK_MONOTONIC:      56338.247 (15h 38m 58s)
CLOCK_BOOTTIME :      76633.544 (21h 17m 13s)

Luego usamos unshare(1) para crear un namespace de tiempo y ejecutar un shell bash(1). Desde el nuevo shell, usamos el comando incorporado echo para escribir registros en el archivo timens_offsets ajustando el desplazamiento para el reloj CLOCK_MONOTONIC en 2 días hacia adelante y el desplazamiento para el reloj CLOCK_BOOTTIME en 7 días hacia adelante:


$ PS1=ns2# sudo unshare -T -- bash --norc
ns2# echo monotonic$((2*24*60*60))0">/proc/$$/timens_offsets"
ns2# echo boottime$((7*24*60*60))0">/proc/$$/timens_offsets"

Arriba, iniciamos el shell bash(1) con la opción --norc para que no se ejecutaran scripts de inicio. Esto asegura que no se creen procesos hijos desde el shell antes de que tengamos la oportunidad de actualizar el archivo timens_offsets.

Luego usamos cat(1) para mostrar el contenido del archivo timens_offsets. La ejecución de cat(1) crea el primer proceso en el nuevo namespace de tiempo, después de lo cual los intentos posteriores de actualizar el archivo timens_offsets producen un error.


ns2# cat /proc/$$/timens_offsets
monotonic      172800         0
boottime       604800         0
ns2# echo "boottime $((9*24*60*60)) 0" > /proc/$$/timens_offsets
bash: echo: write error: Permission denied

Continuando en el nuevo namespace, ejecutamos uptime(1) y el programa de ejemplo clock_times:


ns2# uptime --pretty
up 1
semana, 21 horas, 18 minutos ns2# ./clock_times CLOCK_REALTIME : 1585989457.056 (18356 días + 8h 37m 37s) CLOCK_TAI : 1585989494.057 (18356 días + 8h 38m 14s) CLOCK_MONOTONIC: 229193.332 (2 días + 15h 39m 53s) CLOCK_BOOTTIME : 681488.629 (7 días + 21h 18m 8s)

Del resultado anterior, podemos ver que los relojes monotonic y boot-time tienen valores diferentes en el nuevo espacio de nombres de tiempo.

Examinando los enlaces simbólicos /proc/pid/ns/time y /proc/pid/ns/time_for_children, vemos que el shell es miembro del espacio de nombres de tiempo inicial, pero sus hijos se crean en el nuevo espacio de nombres.


ns2# readlink /proc/$$/ns/time
time:[4026531834]
ns2# readlink /proc/$$/ns/time_for_children
time:[4026532900]
ns2# readlink /proc/self/ns/time  # Crea un proceso hijo
time:[4026532900]

Volviendo al shell en el espacio de nombres de tiempo inicial, vemos que los relojes monotonic y boot-time no se ven afectados por los cambios de timens_offsets que se realizaron en el otro espacio de nombres de tiempo:


$ uptime --pretty
up 21 hours, 19 minutes
$ ./clock_times
CLOCK_REALTIME : 1585989401.971 (18356 days + 8h 38m 51s)
CLOCK_TAI : 1585989438.972 (18356 days + 8h 39m 28s)
CLOCK_MONOTONIC: 56338.247 (15h 41m 8s)
CLOCK_BOOTTIME : 76633.544 (21h 19m 23s)
