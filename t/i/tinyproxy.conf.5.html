TINYPROXY.CONF(5) Manual de Tinyproxy TINYPROXY.CONF(5)

NOMBRE

tinyproxy.conf - Archivo de configuración del demonio proxy HTTP Tinyproxy

SINOPSIS

tinyproxy.conf

DESCRIPCIÓN

tinyproxy(8) lee su archivo de configuración, típicamente almacenado en `/etc/tinyproxy/tinyproxy.conf` (o pasado a Tinyproxy con -c en la línea de comandos). Esta página de manual describe la sintaxis y el contenido del archivo de configuración.

El archivo de configuración de Tinyproxy contiene pares clave-valor, uno por línea. Las líneas que comienzan con `#` y las líneas vacías son comentarios y se ignoran. Las palabras clave no distinguen mayúsculas y minúsculas, mientras que los valores sí. Algunos valores de cadena deben ir entre comillas dobles (") como se indica a continuación.

Las palabras clave posibles y sus descripciones son las siguientes:

User
El usuario con el que debe ejecutarse el proceso Tinyproxy, después de que se haya realizado la vinculación inicial del puerto como usuario `root`. Se puede especificar el nombre de usuario o el UID.
Group
El grupo con el que debe ejecutarse el proceso Tinyproxy, después de que se haya realizado la vinculación inicial del puerto como usuario `root`. Se puede especificar el nombre del grupo o el GID.
Port
El puerto en el que escuchará el servicio Tinyproxy. Si el puerto es menor que 1024, deberá iniciar el proceso Tinyproxy como usuario `root`.
Listen
Por defecto, Tinyproxy escucha conexiones en todas las interfaces disponibles (es decir, escucha en la dirección comodín `0.0.0.0`). Con este parámetro de configuración, se puede indicar a Tinyproxy que escuche solo en una dirección específica.
Bind
Esto permite especificar la dirección a la que Tinyproxy se vinculará para conexiones salientes. Este parámetro se puede especificar varias veces, entonces Tinyproxy intentará todas las direcciones especificadas en orden.
BindSame
Si este parámetro booleano se establece en `yes`, entonces Tinyproxy vinculará la conexión saliente a la dirección IP de la conexión entrante que activó la solicitud saliente.
Timeout
El número máximo de segundos de inactividad que se permite en una conexión antes de que sea cerrada por Tinyproxy.
ErrorFile
Este parámetro controla qué archivo HTML devuelve Tinyproxy cuando ocurre un error HTTP determinado. Toma dos argumentos, el número de error y la ubicación del archivo HTML de error. Encierre la ubicación del archivo entre comillas dobles.
DefaultErrorFile
El archivo de plantilla HTML devuelto cuando ocurre un error para el cual no se ha establecido ningún archivo de error específico. Encierre entre comillas dobles.
StatHost
El nombre de host o la dirección IP que se trata como el `host de estadísticas`. Encierre entre comillas dobles. Cada vez que Tinyproxy recibe una solicitud para el `host de estadísticas` devuelve una página de estadísticas interna en lugar de reenviar la solicitud a ese host. La plantilla para esta página se puede configurar con la opción de configuración `StatFile`. El valor predeterminado de `StatHost` es `tinyproxy.stats`.
StatFile
El archivo HTML que Tinyproxy envía en respuesta a una solicitud para el `host de estadísticas`. Encierre entre comillas dobles. Si este parámetro no está configurado, Tinyproxy devuelve una página de estadísticas básica codificada. Consulte la sección STATHOST en la página de manual de tinyproxy(8) para obtener detalles.

Tenga en cuenta que StatFile y los archivos de error configurados con ErrorFile y DefaultErrorFile son archivos de plantilla que pueden contener algunas variables de plantilla que Tinyproxy expande antes de la entrega. Los ejemplos son "{cause}" para una descripción abreviada del error y "{detail}" para un mensaje de error detallado. La página de manual de tinyproxy(8) contiene una descripción de todas las variables de plantilla.

LogFile
La ubicación del archivo al que Tinyproxy escribe su salida de depuración. Encierre entre comillas dobles. Alternativamente, Tinyproxy puede registrar en syslog -- consulte la opción Syslog.
Syslog
Cuando se establece en `On`, esta opción indica a Tinyproxy que escriba sus mensajes de depuración en syslog en lugar de en un archivo de registro configurado con `LogFile`. Estas dos opciones son mutuamente excluyentes.
LogLevel
Establece el nivel de registro. Se registran los mensajes del nivel establecido y superiores. Por ejemplo, si LogLevel se estableciera en Warning, entonces se mostrarían todos los mensajes de registro desde Warning hasta Critical, pero Notice y por debajo se suprimirían. Los valores permitidos son:
  • Critical (menos verboso)
  • Error
  • Warning
  • Notice
  • Connect (registra conexiones sin el ruido de Info)
  • Info (más verboso)
PidFile
La ubicación del archivo donde el proceso principal de Tinyproxy almacena su ID de proceso para fines de señalización. Encierre entre comillas dobles.
XTinyproxy
Establecer esta opción en `Yes` indica a Tinyproxy que agregue una cabecera `X-Tinyproxy` que contenga la dirección IP del cliente a la solicitud.
Upstream
Esta opción le permite configurar un conjunto de reglas para decidir si se debe utilizar un servidor proxy upstream, basándose en el host o dominio del sitio al que se accede. Las reglas se almacenan en el orden en que se encuentran en el archivo de configuración y la ÚLTIMA regla coincidente gana. Existen las siguientes formas para especificar reglas upstream:
  • upstream tipo:puerto activa el soporte del proxy upstream generalmente.
  • upstream tipo usuario:contraseña@host:puerto hace lo mismo, pero utiliza las credenciales proporcionadas para la autenticación.
  • upstream tipo host:puerto "espec_sitio" activa el proxy upstream para los sitios que coinciden con `espec_sitio`.

    `tipo` puede ser uno de `http`, `socks4`, `socks5`, `none`.

  • upstream none "espec_sitio" desactiva el soporte upstream para los sitios que coinciden con `espec_sitio`, lo que significa que la conexión se realiza directamente.

Se recomienda utilizar direcciones IP sin formato para especificar el host upstream, de modo que no sea necesario realizar una costosa búsqueda de DNS cada vez que se utilice. Las direcciones IPv6 deben ir entre corchetes.

El sitio se puede especificar de varias formas como nombre de host, nombre de dominio o como un rango de IP:

  • nombre coincide exactamente con el host
  • .nombre coincide con cualquier host en el dominio "nombre"
  • . coincide con cualquier host sin dominio (en el dominio 'vacío')
  • IP/bits coincide con red/máscara
  • IP/máscara coincide con red/máscara

Tenga en cuenta que la directiva upstream también se puede utilizar para enrutar nulo un dominio/host de destino específico, por ejemplo: `upstream http 0.0.0.0:0 ".adserver.com"`

MaxClients
Tinyproxy crea un hilo por cada cliente conectado. Esta opción especifica el número máximo absoluto de procesos que se crearán. Con otras palabras, solo pueden conectarse simultáneamente como máximo MaxClients clientes a Tinyproxy.
Allow
Deny
Las opciones `Allow` y `Deny` proporcionan un medio para personalizar qué clientes tienen permitido acceder a Tinyproxy. Se pueden especificar líneas `Allow` y `Deny` varias veces para crear la lista de control de acceso para Tinyproxy. El orden en el archivo de configuración es importante. Si no hay líneas `Allow` o `Deny`, entonces todos los clientes están permitidos. De lo contrario, la acción predeterminada es denegar el acceso. El argumento para `Allow` o `Deny` puede ser una dirección IP única de un host cliente, como `127.0.0.1`, un rango de direcciones IP, como `192.168.0.1/24` o una cadena que se comparará con el final del nombre de host del cliente, es decir, puede ser un nombre de host completo como `host.example.com` o un dominio na

BasicAuth
Configure el nombre de usuario y la contraseña de autenticación básica de HTTP para acceder al proxy. Si se especifican entradas, el acceso solo se concede a los usuarios autenticados. 
BasicAuth usuario contraseña
AddHeader
Configure una o más cabeceras de solicitud HTTP para que se agreguen a las solicitudes HTTP salientes que Tinyproxy realiza. Tenga en cuenta que esta opción no funcionará para el tráfico HTTPS, ya que Tinyproxy no tiene control sobre qué cabeceras se intercambian. 
AddHeader "X-My-Header" "Powered by Tinyproxy"
ViaProxyName
RFC 2616 requiere que los proxies agreguen una cabecera `Via` a las solicitudes HTTP, pero el uso del nombre de host real puede ser una preocupación de seguridad. Si la opción `ViaProxyname` está presente, su valor de cadena se utilizará como el nombre de host en la cabecera Via. De lo contrario, se utilizará el nombre de host del servidor. Encierre entre comillas dobles.
DisableViaHeader
Cuando esto se establece en sí, Tinyproxy NO agrega la cabecera `Via` a las solicitudes. Esto pone virtualmente a Tinyproxy en modo sigiloso. Tenga en cuenta que RFC 2616 requiere que los proxies establezcan la cabecera `Via`, por lo que al habilitar esta opción, rompe el cumplimiento. No desactive la cabecera `Via` a menos que sepa lo que está haciendo...
Filter
Tinyproxy admite el filtrado de sitios web basado en URL o dominios. Esta opción especifica la ubicación del archivo que contiene las reglas de filtro, una regla por línea.

Las reglas se especifican como expresiones regulares POSIX básicas (BRE), a menos que se especifique otro FilterType. Las líneas de comentarios comienzan con un carácter `#`.

Ejemplo de contenido del archivo de filtro:

# filtrar exactamente cnn.com
^cnn\.com$

# filtrar todos los subdominios de cnn.com, pero no cnn.com en sí
.*\.cnn.com$

# filtrar cualquier dominio que tenga cnn.com en él, como xcnn.comfy.org
cnn\.com

# filtrar cualquier dominio que termine en cnn.com
cnn\.com$

# filtrar cualquier dominio que comience con adserver
^adserver
FilterType
Esta opción se puede establecer en `bre`, `ere` o `fnmatch`. Si se establece `bre`, las reglas especificadas en el archivo de filtro se comparan utilizando expresiones regulares POSIX básicas, si se establece en `ere`, utilizando expresiones regulares extendidas POSIX, y si se establece en `fnmatch` utilizando la función `fnmatch` como se especifica en la página man `man 3p fnmatch`. La comparación `fnmatch` es idéntica a lo que se usa en la shell para comparar nombres de archivo, por lo que, por ejemplo, `*.google.com` coincide con todo lo que termina en `.google.com`. Si no sabe qué son las expresiones regulares o está utilizando listas de filtros de fuentes de terceros, `fnmatch` es probablemente lo que desea. También es el método de comparación más rápido de los tres.
FilterURLs
Si esta opción booleana se establece en `Yes` o `On`, se realiza el filtrado de URL en lugar de dominios. El valor predeterminado es filtrar por dominios.

Tenga en cuenta que el filtrado de URL solo funciona en escenarios HTTP simples. Dado que HTTPS se ha vuelto omnipresente en los últimos años, esto solo funcionará en una pequeña fracción de sitios web, por lo que se recomienda no utilizar esta opción.

FilterExtended
Obsoleto. Use `FilterType ere` en su lugar. Si esta opción booleana se establece en `Yes`, entonces se utilizan expresiones regulares POSIX extendidas para comparar las reglas de filtro. El valor predeterminado es utilizar expresiones regulares POSIX básicas.
FilterCaseSensitive
Si esta opción booleana se establece en `Yes`, las reglas de filtro se comparan de forma sensible a mayúsculas y minúsculas. El valor predeterminado es comparar sin distinguir mayúsculas y minúsculas, desafortunadamente. Si establece esto en `Yes`, su comparación será casi el doble de rápida. Esta configuración solo afecta a los FilterTypes `bre` y `ere`, fnmatch siempre distingue entre mayúsculas y minúsculas.
FilterDefaultDeny
La política de filtrado predeterminada es permitir todo lo que no coincida con una regla de filtrado. Establecer `FilterDefaultDeny` en `Yes` cambia la política para denegar todo excepto los dominios o URL que coincidan con las reglas de filtrado. En otras palabras, si se establece en `No`, la lista de filtros actúa como una lista negra, si se establece en `Yes` como una lista blanca.
Anonymous
Si está presente una palabra clave `Anonymous`, se habilita el proxy anónimo. Las cabeceras enumeradas con `Anonymous` se permiten pasar, mientras que todas las demás se deniegan. Si no hay ninguna palabra clave Anonymous presente, se permiten pasar todas las cabeceras. Debe incluir comillas dobles alrededor de las cabeceras.

La mayoría de los sitios requieren que las cookies estén habilitadas para que funcionen correctamente, por lo que deberá permitir el paso de las cookies si accede a esos sitios.

Ejemplo:

Anonymous "Host"
Anonymous "Authorization"
Anonymous "Cookie"
ConnectPort
Esta opción se puede utilizar para especificar los puertos permitidos para el método CONNECT. Si no se encuentra ninguna línea `ConnectPort`, se permiten todos los puertos. Para deshabilitar CONNECT por completo, incluya una única línea ConnectPort con un valor de `0`.
ReversePath
Configure una o más directivas ReversePath para habilitar el soporte de proxy inverso. Con el proxy inverso, es posible hacer que una serie de sitios parezca como si fueran parte de un solo sitio.

Si descomenta las siguientes dos directivas y ejecuta Tinyproxy en su propia computadora en el puerto 8888, puede acceder a example.com, usando http://localhost:8888/example/.

ReversePath "/example/" "http://www.example.com/"
ReverseOnly
Al usar Tinyproxy como proxy inverso, se recomienda ENCARECIDAMENTE que el proxy normal se desactive estableciendo esta opción booleana en `Yes`.
ReverseMagic
Establecer esta opción en `Yes` hace que Tinyproxy utilice una cookie para rastrear las asignaciones del proxy inverso. Si necesita hacer proxy inverso de sitios que tienen enlaces absolutos, debe usar esta opción.
ReverseBaseURL
La URL que se utiliza para acceder a este proxy inverso. La URL se utiliza para reescribir las redirecciones HTTP para que no se escapen del proxy. Si tiene una cadena de proxies inversos, deberá poner la URL más externa aquí (la dirección que el usuario final escribe en su navegador). Si esta opción no está configurada, no se realizará ninguna reescritura de redirecciones.

ERRORES
