NOMBRE

tigrc - Archivo de configuración de Tig

SINOPSIS

set   variable = valor
bind  mapa de teclas tecla acción
color área color de frente color de fondo [atributos]
source ruta

DESCRIPCIÓN

Puede establecer una opción de forma permanente colocando la en el archivo ~/.tigrc. El archivo consta de una serie de comandos. Cada línea del archivo puede contener solo un comando. Los comandos pueden abarcar varias líneas si cada línea termina con un carácter de barra invertida (\).

El signo de almohadilla (#) se utiliza como carácter de comentario. Todo texto después del carácter de comentario hasta el final de la línea se ignora. Puede utilizar comentarios para anotar su archivo de inicialización.

Ciertas opciones se pueden manipular en tiempo de ejecución a través del menú de opciones. Además, las opciones también se pueden activar con el comando de prompt :toggle o introduciendo el comando de configuración en el prompt.

En algunos entornos, la configuración de un usuario se almacenará en la ubicación alternativa $XDG_CONFIG_HOME/tig/config. Para abreviar, este documento se referirá solo a ~/.tigrc.

CONFIGURACIÓN DE GIT

Alternativamente a usar ~/.tigrc, las opciones de Tig se pueden establecer colocándolas en uno de los archivos de configuración de Git, que son leídos por Tig al inicio. Consulte git-config(1) para saber qué archivos usar. El siguiente ejemplo muestra la sintaxis básica para usar en configuraciones, enlaces y colores.

[tig] show-changes = true
[tig "color"] cursor = yellow red bold
[tig "bind"] generic = P parent

Además de las opciones específicas de tig, las siguientes opciones de Git se leen de la configuración de Git:

color.*

Colores para los diversos tipos de UI. Se puede configurar a través de la configuración git-colors.

core.abbrev

El ancho del ID del commit. Consulte también la opción id-width.

core.editor

El comando del editor. Se puede anular estableciendo TIG_EDITOR o GIT_EDITOR.

core.worktree

La ruta a la raíz del árbol de trabajo.

gui.encoding

La codificación a utilizar para mostrar el contenido del archivo.

i18n.commitencoding

La codificación utilizada para los commits. El valor predeterminado es UTF-8.

COMANDO SET

Algunas variables selectivas se pueden configurar mediante el comando set. La sintaxis es:

set variables = valor

Ejemplos:

set commit-order = topo         # Ordenar commits topológicamente
set git-colors = no             # No leer la configuración de colores de Git.
set horizontal-scroll = 33%     # Desplazar 33% del ancho de la vista
set blame-options = -C -C -C    # Líneas de blame de otros archivos
# Envolver nombres de ramas con () y etiquetas con <>
set reference-format = (branch) <tag>
# Configurar columnas de vista de blame usando un comando que abarca varias líneas.
set blame-view = \
        date:default \
        author:abbreviated \
        committer:abbreviated \
        file-name:auto \
        id:yes,color \
        line-number:yes,interval=5 text

O en los archivos de configuración de Git:

[tig]
        line-graphics = no      # Desactivar caracteres gráficos
        tab-size = 8            # Número de espacios por tabulación

El tipo de variables es bool, int, string o mixed.

Valores booleanos válidos

Para establecer una variable booleana a verdadero, use "1", "true" o "yes". Cualquier otro valor establecerá la variable a falso.

Valores enteros válidos

Un entero no negativo.

Valores de cadena válidos

Una cadena de caracteres. Opcionalmente, use ' o " como delimitadores.

Valores mixtos válidos

Estos valores son compuestos de los tipos anteriores. Los valores válidos se especifican en la descripción.

Variables

Las siguientes variables se pueden establecer:

diff-options (string)

Una cadena separada por espacios de opciones de diff a utilizar en la vista de diff. Se utiliza git-show(1) para el formato y siempre pasa --patch-with-stat. Puede controlar la visualización de metadatos de la cabecera del commit, pasando la opción --format. Esta opción anula cualquier opción especificada en la variable de entorno TIG_DIFF_OPTS (descrita en tig(1)), pero ella misma es anulada por las banderas de diff dadas en la invocación de la línea de comandos.

blame-options (string)

Una cadena separada por espacios de opciones de blame predeterminadas. Se puede utilizar para indicar a git-blame(1) cómo detectar el origen de las líneas. Las opciones se ignoran cuando Tig se inicia en modo blame y se le dan opciones de blame en la línea de comandos.

log-options (string)

Una cadena separada por espacios de opciones predeterminadas que se pasarán al comando git-log(1) utilizado por la vista de log. Las opciones pueden ser anuladas por opciones de línea de comandos. Se utiliza internamente para anular configuraciones personalizadas de 'pretty.format' que rompen la vista de log.

main-options (string)

Una cadena separada por espacios de opciones predeterminadas que se pasarán al comando git-log(1) utilizado por la vista principal. Las opciones pueden ser anuladas por opciones de línea de comandos.

reference-format (string)

Una cadena separada por espacios de cadenas de formato utilizadas para formatear nombres de referencia. Envuelva el nombre del tipo de referencia con los caracteres que desea usar para el formato, por ejemplo, [etiqueta] y <remoto>. Si no se especifica ningún formato para etiqueta-local, se utiliza el formato para etiqueta. De manera similar, si no se especifica ningún formato para remoto-seguido, se utiliza el formato para remoto, y si no se especifica ningún formato para ningún otro tipo de referencia, se utiliza el formato para rama. Prefije con hide: para no mostrar ese tipo de referencia, por ejemplo, hide:remote. Los tipos de referencia admitidos son:
•head : El HEAD actual.
•tag : Una etiqueta anotada.
•local-tag : Una etiqueta ligera.
•remote : Un remoto.
•tracked-remote : El remoto seguido por el HEAD actual.
•replace : Una referencia reemplazada.
•branch : Una rama.
•stash : El stash.
•note : Notas.
•prefetch : Refs pre-cargadas por el mantenimiento de git.
•other : Cualquier otra referencia.

line-graphics (mixed) [ascii|default|utf-8|auto|<bool>]

Qué tipo de gráficos de caracteres para dibujar líneas. "auto" significa "utf-8" si la configuración regional es UTF-8, "default" en caso contrario.

truncation-delimiter (mixed) [utf-8|<string>]

Un solo carácter para dibujar donde las columnas se truncan. El valor predeterminado es "~". El valor especial "utf-8" se refiere al carácter "..." ("Elipsis Media Horizontal").

horizontal-scroll (mixed)

Intervalo para desplazarse horizontalmente en cada paso. Se puede especificar como el número de columnas, por ejemplo, 5, o como un porcentaje del ancho de la vista, por ejemplo, 33%, donde el máximo es 100%. Para porcentajes, siempre se asegura que se desplace al menos una columna. El valor predeterminado es desplazar el 50% del ancho de la vista.

git-colors (list)

Una lista separada por espacios de pares "clave=valor" donde la clave es un nombre de color de Git y el valor es un nombre de color de Tig, por ejemplo, "branch.current=main-head" y "grep.filename=grep.file". Establézcalo en "no" para desactivarlo.

show-notes (mixed) [<referencia>|<bool>]

Si mostrar notas para un commit. Cuando se establece en una referencia de notas, la referencia se pasa a git show --notes=. Las notas están habilitadas por defecto.

show-changes (bool)

Si mostrar cambios preparados y no preparados en la vista principal.

show-untracked (bool)

Si mostrar también cambios no rastreados en la vista principal.

vertical-split (mixed) [auto|<bool>]

Si dividir la vista horizontal o verticalmente.

ticamente. "auto" (que es el valor predeterminado) significa que dependerá de las dimensiones de la ventana. Cuando se utiliza orientación vertical completa, y `false` establece la orientación a horizontal.

split-view-height (mixto)

La altura de la vista inferior en una pantalla dividida horizontalmente. Se puede especificar como el número de filas, por ejemplo, 5, o como un porcentaje de la altura de la vista, por ejemplo, 80%, donde el máximo es 100%. Siempre se asegura que la vista más pequeña tenga al menos cuatro filas de altura. El valor predeterminado es 67%.

split-view-width (mixto)

Ancho de la vista más a la derecha en una pantalla dividida verticalmente. Se puede especificar como el número de columnas, por ejemplo, 5, o como un porcentaje del ancho de la vista, por ejemplo, 80%, donde el máximo es 100%. Siempre se asegura que la vista más pequeña tenga al menos cuatro columnas de ancho. El valor predeterminado es 50%.

status-show-untracked-dirs (bool)

Muestra el contenido de directorios no rastreados en la vista de estado (análogo a la opción `git ls-files --directory`). Activado por predeterminado.

status-show-untracked-files (bool)

Muestra archivos no rastreados en la vista de estado (refleja la opción `status.showUntrackedFiles` de Git). Activado por predeterminado.

tab-size (int)

Número de espacios por tabulación. El valor predeterminado es 8 espacios.

diff-context (int)

Número de líneas de contexto a mostrar para las diferencias (diffs).

word-diff (bool)

Muestra una diferencia a nivel de palabra. Solo se admite el modo plano. Desactivado por predeterminado.

diff-highlight (mixto)

Indica si resaltar las diferencias utilizando el programa diff-highlight de Git. El valor predeterminado es `false`. Cuando se establece en `true`, se utiliza diff-highlight; de lo contrario, el valor de la opción se utiliza como la ruta. Cuando esta opción está en efecto, las regiones resaltadas se rigen por los colores `diff-add-highlight` y `diff-del-highlight`.

diff-indicator (bool)

Muestra signos +/- en la vista de diferencias. Activado por predeterminado.

ignore-space (mixto) [no|all|some|at-eol|<bool>]

Ignora los cambios de espacio en la vista de diferencias. Por predeterminado, no se ignoran los cambios de espacio. Cambiar esto a "all", "some" o "at-eol" es equivalente a pasar "--ignore-all-space", "--ignore-space" o "--ignore-space-at-eol" respectivamente a `git diff` o `git show`.

Advertencia: cuando `ignore-space` se establece en `some`, `all` o `at-eol`, las operaciones status-update y status-revert pueden fallar al actualizar o revertir fragmentos que contienen líneas con cambios de espacio. De manera similar, stage-update-line puede fallar al actualizar una línea adyacente a una línea con cambios de espacio.

commit-order (enum) [auto|default|topo|date|author-date|reverse]

Orden de los commits utilizando el orden predeterminado (cronológico inverso), orden topológico, orden por fecha o orden inverso. Cuando se establece en "auto" (que es el valor predeterminado), se utiliza automáticamente el orden topológico en la vista principal cuando el gráfico de commits está habilitado. En repositorios con un historial de commits largo, se recomienda establecer esta opción en "default" para acelerar la carga de la vista principal.

ignore-case (enum) [no|yes|smart-case]

Ignora mayúsculas y minúsculas en las búsquedas. "smart-case" ignora mayúsculas y minúsculas si la cadena de búsqueda no contiene ninguna letra mayúscula. Por predeterminado, la búsqueda distingue entre mayúsculas y minúsculas.

mailmap (bool)

Lee los nombres y direcciones de correo electrónico canónicos para autores y confirmadores de .mailmap. Desactivado por predeterminado. Ver `git-shortlog(1)`.

wrap-lines (bool)

Ajusta las líneas largas. Por predeterminado, las líneas no se ajustan. No es compatible con la numeración de líneas habilitada.

wrap-search (bool)

Envuelve de arriba a abajo o de abajo a arriba al buscar en la vista. Activado por predeterminado.

focus-child (bool)

Indica si enfocar la vista hija cuando se abre. Cuando está desactivado, el foco permanecerá en la vista principal, evitando la recarga de la vista hija al navegar por la vista principal. Verdadero por predeterminado.

send-child-enter (bool)

Indica si enviar las pulsaciones de la tecla "enter" a la vista hija, incluso si la vista principal está activa. Cuando está desactivado, la vista hija debe enfocarse explícitamente para recibir las pulsaciones de la tecla "enter". En la práctica, solo es relevante cuando se establece `focus-child = no`. Verdadero por predeterminado.

editor-line-number (bool)

Indica si pasar el número de línea seleccionado al comando del editor. El número de línea se pasa como `+<número-de-línea>` delante del nombre del archivo. Ejemplo: `vim +10 tig.c`.

history-size (int)

Tamaño del archivo persistente `~/.tig_history` cuando se compila con soporte `readline`. El valor predeterminado es 500. Establézcalo en 0 para deshabilitar.

mouse (bool)

Indica si habilitar el soporte del ratón. Desactivado por predeterminado, ya que hace que la selección de texto desde la terminal sea menos intuitiva. Cuando está habilitado, mantenga presionada la tecla Shift (o Option en Mac) para seleccionar texto. El soporte del ratón requiere que ncurses en sí admita eventos del ratón.

mouse-scroll (int)

Intervalo para desplazarse hacia arriba o hacia abajo usando el ratón. El valor predeterminado es 3 líneas. El soporte del ratón requiere que ncurses en sí admita eventos del ratón y que haya habilitado el soporte del ratón en `~/.tigrc` con `set mouse = true`.

mouse-wheel-cursor (bool)

Indica si preferir mover el cursor en lugar de desplazar la vista al usar la rueda del ratón. Desactivado por predeterminado. Combina bien con `set mouse-scroll = 1`. El soporte del ratón requiere que ncurses en sí admita eventos del ratón y que haya habilitado el soporte del ratón en `~/.tigrc` con `set mouse = true`.

pager-autoscroll (bool)

Indica si desplazar automáticamente la vista del paginador mientras se carga. Mueva el cursor fuera de la última línea para detener el desplazamiento y vuelva a entrar para reanudarlo.

pgrp (bool)

Convierte a tig en líder del grupo de procesos al iniciarse y limpia todos los procesos al salir. Desactivado por predeterminado. No active esta opción si está utilizando una versión de Zsh afectada por zsh-workers/43379. Ejecute `xclip` con `setsid` para mantener el contenido del portapapeles después de salir de tig. Si está utilizando el asistente `git-credential-cache`, establezca la opción `credentialCache.ignoreSIGHUP`.

start-on-head (bool)

Inicia con el cursor en el commit HEAD.

refresh-mode (mixto) [manual|auto|after-command|periodic|<bool>]

Configura cómo se actualizan las vistas en función de las modificaciones en los archivos observados en el repositorio. Cuando se establece en manual, nada se actualiza automáticamente. Cuando se establece en auto, las vistas se actualizan cuando se detecta una modificación en otra vista. Cuando se establece en after-command, solo se actualiza después de regresar de un comando externo. Cuando se establece en periodic, las vistas visibles se actualizan periódicamente utilizando refresh-interval.

refresh-interval (int)

Intervalo en segundos entre las comprobaciones de actualización de las vistas cuando refresh-mode se establece en periodic.

file-args (args)

Argumentos de línea de comandos que se refieren a archivos. Estos se filtran usando `git-rev-parse(1)`.

rev-args (args)

Argumentos de línea de comandos que se refieren a revisiones. Estos se filtran usando `git-rev-parse(1)`.

Configuración de vistas

La configuración de la vista define el orden y las opciones para las diferentes columnas de una vista. Cada configuración de vista espera una lista de especificaciones de columna separadas por espacios. Las especificaciones de columna comienzan con el tipo de columna y pueden ir seguidas opcionalmente por dos puntos (:) y una lista de opciones de columna. Por ejemplo, la siguiente especificación de columna define una columna de autor que muestra el correo electrónico del autor y con un ancho fijo de 20 caracteres: `author:email,width=20`.

El primer valor de opción en una especificación de columna es siempre la opción display. Cuando no se proporciona ningún valor para display, se asume yes. Para las opciones de display que esperan un valor enumerado, esto se resolverá automáticamente al valor enumerado predeterminado. Por ejemplo, `file-name` resolverá automáticamente su configuración de display a auto.

Las especificaciones también se pueden proporcionar para una sola columna, por ejemplo, para anular los valores predeterminados en el archivo `tigrc` del sistema. Para anular una sola columna, use el nombre de la columna como sufijo después del nombre de la configuración de la vista, por ejemplo, `main-view-date` permitirá establecer la fecha en la vista principal.

Ejemplos:

# Habilita tanto los ID como los números de línea en la vista blame
set blame-view = date:default author:full committer:no file-name:auto \
                 id:yes,color line-number:yes,interval=5 text
# Cambia la vista grep para que sea similar al formato de `git grep`
set grep-view = file-name:yes line-number:yes,interval=1 text
# Muestra los tamaños de archivo como unidades
set tree-view = line-number:no,interval=5 mode author:full committer:no \
                file-size:units date:default id:no file-name
# Muestra números de línea por cada 10 líneas en la vista pager
set pager-view = line-number:yes,interval=10 text
# Atajos para cambiar la configuración de la vista para una columna definida previamente
set main-view-date = custom
set main-view-date-format = "%Y-%m-%d %H:%M"
set blame-view-line-number = no
# Usa el orden de commits predeterminado de Git, incluso cuando el gráfico de commits está habilitado.
set commit-order = default

La siguiente lista muestra la configuración de vista disponible y los tipos de columna que admiten:

blob-view, diff-view, log-view, pager-view, stage-view

line-number, text

blame-view

author, committer, date, file-name, id, line-number, text

grep-view

file-name, line-number, text

main-view, reflog-view

author, committer, date, commit-title, id, line-number, ref

refs-view

author, committer, date, commit-title, id, line-number, ref

stash-view

author, date, commit-title, id, line-number

status-view

file-name, line-number, status

tree-view

author, committer, date, id, file-name, file-size, line-number, mode

Tipos de columna admitidos y sus respectivas opciones de columna:

author, committer

•display (mixto) [full|abbreviated|email|email-user|<bool>]: Cómo mostrar los nombres de autor/confirmador. Si se establece en "abbreviated", se mostrarán las iniciales del autor/confirmador.
•width (int): Ancho fijo para la columna. Cuando se establece en un valor entre 1 y 10, el nombre del autor/confirmador se abreviará a las iniciales del autor/confirmador. Cuando se establece en ze
ro, el ancho se ajusta automáticamente para adaptarse al contenido.
•maxwidth (int): Ancho máximo de la columna. Permite el dimensionamiento automático del contenido, hasta este límite. Puede especificarse como el número de columnas, por ejemplo, 15, o como un porcentaje del ancho de la vista, por ejemplo, 20%, donde el máximo es 100%.

commit-title

•graph (mixto) [no|v2|v1]: Si se muestra el gráfico de revisiones en la vista principal al inicio. "v1" se refiere al renderizado antiguo del gráfico, que es menos preciso pero más rápido y, por lo tanto, recomendado en repositorios grandes. Ver también las opciones line-graphics.
•refs (bool): Si se muestran las referencias (ramas, etiquetas y remotos) en la vista principal. Se puede alternar.
•overflow (bool o int): Si se resalta el texto en los títulos de commit que exceden un ancho dado. Cuando se establece en un booleano, habilita o deshabilita el resaltado utilizando el ancho predeterminado de 50 caracteres. Cuando se establece en un entero, el valor asignado se utiliza como el ancho máximo de caracteres.

date

•display (mixto) [relative|relative-compact|custom|default|<bool>]: Cómo mostrar las fechas. Si se establece en "relative" o "relative-compact", se utilizará una fecha relativa, por ejemplo, "hace 2 minutos" o "2m". Si se establece en "custom", se utiliza la cadena de formato strftime(3) especificada en la opción "format".
•use-author (bool): Si se muestra la fecha del autor en lugar de la fecha del commit.
•local (bool): Si es verdadero, utiliza localtime(3) para convertir a la zona horaria local. Tenga en cuenta que las fechas relativas siempre utilizan desplazamientos locales.
•format (string): Cadena de formato para pasar a strftime(3) cuando se ha seleccionado el modo de visualización custom.
•width (int): Ancho fijo para la columna. Cuando se establece en cero, el ancho se ajusta automáticamente para adaptarse al contenido.

file-name

•display (mixto) [auto|always|<bool>]: Cuándo mostrar los nombres de archivo. Si se establece en "auto", los nombres de archivo se muestran solo cuando es necesario, por ejemplo, al ejecutar: tig blame -C <archivo>.
•width (int): Ancho de la columna. Cuando se establece en cero, el ancho se ajusta automáticamente para adaptarse al contenido.
•maxwidth (int): Ancho máximo de la columna. Permite el dimensionamiento automático del contenido, hasta este límite. Puede especificarse como el número de columnas, por ejemplo, 15, o como un porcentaje del ancho de la vista, por ejemplo, 20%, donde el máximo es 100%.

file-size

•display (mixto) [default|units|<bool>]: Cómo mostrar los tamaños de archivo. Cuando se establece en "units", los tamaños se muestran utilizando prefijos binarios, por ejemplo, 12524 bytes se muestra como "12.2K".
•width (int): Ancho fijo para la columna del nombre de archivo. Cuando se establece en cero, el ancho se ajusta automáticamente para adaptarse al contenido.

id

•display (bool): Si se muestran los IDs de commit en la vista principal.
•width (int) : Ancho fijo para la columna del ID de commit. Cuando no está configurado, Tig utilizará el valor de core.abbrev si se encuentra. Ver git-config(1) sobre cómo configurar core.abbrev. Cuando se establece en cero, el ancho se ajusta automáticamente para adaptarse al contenido de los IDs de reflog (por ejemplo, ref/stash@{4}) y, de lo contrario, por defecto a 7.

line-number

•display (bool): Si se muestran los números de línea.
•interval (int): Intervalo entre números de línea.
•width (int): Ancho fijo para la columna. Cuando se establece en cero, el ancho se ajusta automáticamente para adaptarse al contenido.

mode

•display (bool): Si se muestran los modos de archivo.
•width (int): Ancho fijo para la columna. Cuando se establece en cero, el ancho se ajusta automáticamente para adaptarse al contenido.

ref

•display (bool): Si se muestra el nombre de la referencia.
•width (int): Ancho fijo para la columna. Cuando se establece en cero, el ancho se ajusta automáticamente para adaptarse al contenido.
•maxwidth (int): Ancho máximo de la columna. Permite el dimensionamiento automático del contenido, hasta este límite. Puede especificarse como el número de columnas, por ejemplo, 15, o como un porcentaje del ancho de la vista, por ejemplo, 20%, donde el máximo es 100%.

status

•display (mixto) [no|short|long|<bool>]: Cómo mostrar la etiqueta de estado.

text

•commit-title-overflow (bool o int): Si se resaltan los títulos de commit que exceden un ancho dado en la vista de diff. Cuando se establece en un booleano, habilita o deshabilita el resaltado utilizando el ancho predeterminado de 50 caracteres. Cuando se establece en un entero, el valor asignado se utiliza como el ancho máximo de caracteres.

Todas las opciones de columna se pueden alternar. Para las opciones de display, utilice el nombre de la opción como prefijo seguido de un guion y el nombre de la columna. Por ejemplo, :toggle author-display alternará la opción display en la columna author. Para todas las demás opciones, utilice el nombre de la columna seguido de un guion y luego el nombre de la opción como sufijo. Por ejemplo, :toggle commit-title-graph alternará la opción graph en la columna commit-title. Alternativamente, utilice el menú de opciones para manipular las opciones.

BIND COMANDO

Usando comandos bind, las teclas se pueden mapear a una acción cuando se presionan en un mapa de teclas dado. La sintaxis es:

bind keymap key action

Ejemplos:

# Añadir atajo de teclado para saltar rápidamente al siguiente fragmento de diff en la vista de stage
bind stage <Enter> :/^@@
# Deshabilitar el mapeo predeterminado para ejecutar git-gc
bind generic G none
# Comando externo definido por el usuario para modificar el último commit
bind status + !git commit --amend
# Comando interno definido por el usuario que recarga ~/.tigrc
bind generic S :source ~/.tigrc
# Los caracteres codificados en UTF8 se pueden usar como valores de tecla.
bind generic ø @sh -c "printf '%s' %(commit) | pbcopy"

O en los archivos de configuración de Git:

[tig "bind"]
        # 'desvincular' el atajo de teclado predeterminado para salir
        generic = Q none
        # Cherry-pick el commit actual a la rama actual
        main = C !git cherry-pick %(commit)

Las teclas se mapean buscando primero en los atajos de teclado para la vista actual, luego en los atajos de teclado para el mapa de teclas generic, y por último en los atajos de teclado predeterminados. Por lo tanto, los atajos de teclado de la vista anulan los atajos de teclado genéricos, que a su vez anulan los atajos de teclado integrados.

Desvincule un atajo de teclado (unbind) de todos los mapas de teclas a la vez con bind generic key none.

Los atajos de teclado en el prompt de entrada de línea suelen estar gobernados por la biblioteca readline y se configuran por separado en ~/.inputrc. Ver readline(1). Tig respeta, pero no requiere, una sección $if tig en ~/.inputrc.

Mapas de Teclas

Los mapas de teclas válidos son: main, diff, log, reflog, help, pager, status, stage, tree, blob, blame, refs, stash, grep y generic. Utilice generic para establecer el mapeo de teclas en todos los mapas de teclas (que aún pueden ser anulados por un atajo de teclado de vista específico). Utilice search para definir teclas para navegar por los resultados de la búsqueda durante la búsqueda.

Valores de Tecla

Los valores de las teclas nunca deben ir entre comillas. Utilice un carácter codificado en ASCII o UTF8 o uno de los siguientes nombres de teclas simbólicos. Los nombres de teclas simbólicos no distinguen entre mayúsculas y minúsculas y comienzan con "<" y terminan con ">". Utilice <Hash> para enlazar a la tecla #, ya que el signo de almohadilla se utiliza como carácter de comentario. Utilice <LessThan> para enlazar a la tecla <.

<Enter>, <Space>, <Backspace>, <Tab>, <Escape> o <Esc>, <Left>, <Right>, <Up>, <Down>, <Insert> o <Ins>, <Delete> o <Del>, <Hash>, <LessThan> o <LT>, <Home>, <End>, <PageUp> o <PgUp>, <PageDown> o <PgDown>, <ScrollBack> o <SBack>, <ScrollFwd> o <SFwd>, <ShiftTab> o <BackTab>, <ShiftLeft>, <ShiftRight>, <ShiftDelete> o <ShiftDel>, <ShiftHome>, <ShiftEnd>, <SingleQuote>, <DoubleQuote>, <F1> ... <F19>

Para definir mapeos de teclas con la tecla Ctrl, use <Ctrl-key>. Además, las combinaciones de teclas que consisten en una tecla Escape inicial seguida de un valor de tecla normal se pueden enlazar usando <Esc>key.

Ejemplos:

bind main R             refresh
bind main <Down>        next
bind main <Ctrl-f>      scroll-page-down
bind main <Esc>o        options
bind main <ShiftTab>    parent

Notas

•Tig lee las pulsaciones de teclas a través de ncurses y está sujeto a varias limitaciones. Ver ncurses(3x) y terminfo(5) (o termcap).
•Ctrl-m y Ctrl-i no se pueden enlazar ya que entran en conflicto con Enter y Tab respectivamente.
•Las diferencias entre mayúsculas y minúsculas no se pueden distinguir en secuencias de control como Ctrl-f y Ctrl-F.
•Ctrl-<Space> generalmente se traduce a Ctrl-@, que está disponible para enlazar.
•Solo un subconjunto de teclas simbólicas especiales como <ShiftTab> estará disponible en cualquier emulador de terminal dado.
•Ctrl-z se utiliza automáticamente para el control de procesos y suspenderá Tig y abrirá un subshell (use fg para volver a ingresar a Tig).

Acciones

Las acciones se especifican como comandos definidos por el usuario (externos o internos) o utilizando nombres de acción como se describe en las siguientes secciones.

Comando externo definido por el usuario

Estos

Las acciones comienzan con una o más de las siguientes marcas de opción seguidas del comando que debe ejecutarse.

! Ejecuta el comando en primer plano mostrando la salida.
@ Ejecuta el comando en segundo plano sin mostrar salida.
+ Ejecuta el comando de forma síncrona y muestra la primera línea de salida en la barra de estado.
? Pregunta al usuario antes de ejecutar el comando.
< Sale de Tig después de ejecutar el comando.
> Reabre Tig instantáneamente en la última vista mostrada después de ejecutar el comando.

A menos que se especifique lo contrario, los comandos se ejecutan en primer plano mostrando su salida de consola (como si se especificara !). Cuando se especifican múltiples opciones de comando, su comportamiento se combina, por ejemplo, "?<git commit" le preguntará al usuario si desea ejecutar el comando y saldrá de Tig después de completarlo.

Tenga en cuenta que si desea utilizar tuberías o redirección en sus comandos, debe ejecutarlos en un subshell, es decir, incrustar sus comandos en sh -c '<comandos>'.

Navegando por las variables de estado

Los comandos definidos por el usuario pueden hacer referencia opcionalmente al estado interno de Tig utilizando los siguientes nombres de variable, que se sustituyen antes de ejecutar los comandos:

%(head) El ID de head que se está viendo actualmente. Por defecto es HEAD.
%(commit) El ID del commit seleccionado actualmente.
%(blob) El ID del blob seleccionado actualmente.
%(branch) El nombre de la rama seleccionada actualmente.
%(remote) El nombre del remoto seleccionado actualmente. Para ramas remotas, %(branch) contendrá el nombre de la rama.
%(tag) El nombre de la etiqueta seleccionada actualmente.
%(refname) El nombre de referencia seleccionado actualmente, incluido el nombre del remoto para ramas remotas.
%(stash) El nombre del stash seleccionado actualmente.
%(directory) La ruta del directorio actual en la vista de árbol o "." si no está definido.
%(file) El archivo seleccionado actualmente.
%(file_old) El nombre de archivo anterior del archivo seleccionado actualmente.
%(lineno) El número de línea seleccionado actualmente. Por defecto es 0.
%(lineno_old) El número de línea seleccionado actualmente, antes de aplicar el diff. Por defecto es 0.
%(ref) La referencia dada a blame o HEAD si no está definida.
%(revargs) Los argumentos de revisión pasados en la línea de comandos.
%(fileargs) Los argumentos de archivo pasados en la línea de comandos.
%(cmdlineargs) Todas las demás opciones pasadas en la línea de comandos.
%(diffargs) Opciones de diff-options o TIG_DIFF_OPTS utilizadas por la vista diff y stage.
%(blameargs) Opciones de blame-options utilizadas por la vista blame.
%(logargs) Opciones de log-options utilizadas por la vista log.
%(mainargs) Opciones de main-options utilizadas por la vista principal.
%(prompt) Pregunta por el valor del argumento. Opcionalmente, especifica un mensaje personalizado usando "%(prompt Enter branch name: )"
%(text) La columna de texto de la línea seleccionada actualmente.
%(repo:head) El nombre de la rama extraída, por ejemplo, master.
%(repo:head-id) El ID del commit de la rama extraída.
%(repo:remote) El nombre del remoto asociado con la rama extraída, por ejemplo, origin.
%(repo:upstream) La rama upstream asociada con la rama extraída, por ejemplo, origin/master.
%(repo:cdup) La ruta para cambiar al directorio raíz del repositorio, por ejemplo, ../.
%(repo:prefix) El prefijo de ruta del directorio de trabajo actual, por ejemplo, subdir/.
%(repo:git-dir) La ruta al directorio de Git, por ejemplo, /src/repo/.git.
%(repo:worktree) La ruta del árbol de trabajo, si está definido.
%(repo:is-inside-work-tree) Si Tig se está ejecutando dentro de un árbol de trabajo, ya sea verdadero o falso.

Ejemplos:

# Guarda el commit actual como un archivo de parche cuando el usuario selecciona un commit
# en la vista principal y presiona 'S'.
bind main S !git format-patch -1 %(commit)
# Crea y extrae una nueva rama; especifica un mensaje personalizado
bind main B ?git checkout -b "%(prompt Introduce el nombre de la nueva rama: )"
# Muestra estadísticas de commits del autor sobre el que está el cursor
bind main U +sh -c 'git --no-pager shortlog -s --author="$(git show -s --format=%aE %(commit))" </dev/tty'

Comandos avanzados tipo shell

Si su comando requiere el uso de características dinámicas, como subshells, expansión de variables de entorno y control de procesos, esto se puede lograr utilizando un comando de shell:

Ejemplo 1. Configura un enlace para copiar el ID del commit actual al portapapeles.

bind generic I @sh -c "echo -n %(commit) | xclip -selection c"

O utilizando una combinación de alias de Git y comandos externos de Tig. Las siguientes entradas de ejemplo se pueden colocar en el archivo .gitconfig o .git/config:

Ejemplo 2. Configuración de Git que enlaza teclas de Tig a alias de comandos de Git.

[alias]
        gitk-bg = !"gitk HEAD --not $(git rev-parse --remotes) &"
        publish = !"for i in origin public; do git push $i; done"
[tig "bind"]
        generic = V @git gitk-bg
        generic = > !git publish

Comandos internos definidos por el usuario

Las acciones que comienzan con : se ejecutarán e interpretarán como comandos internos y actuarán de manera similar a los comandos ejecutados a través del prompt de Tig. Los comandos internos válidos son opciones del archivo de configuración (como se describe en este documento) y comandos de la vista del paginador. Ejemplos:

# Recarga ~/.tigrc al presionar 'S'
bind generic S :source .tigrc
# Cambia la vista de diff para mostrar todos los cambios de commit independientemente de las limitaciones de archivo
bind diff F :set diff-options = --full-diff
# Muestra la salida de git-reflog(1) en la vista del paginador
bind generic W :!git reflog
# Busca el diff (c)hunk anterior y el siguiente encabezado de diff
bind stage 2 :?^@@
bind stage D :/^diff --(git|cc)
bind main I :toggle id                          # Muestra/oculta la columna ID
bind diff D :toggle diff-options --minimal      # Usa el algoritmo de diff mínimo
bind diff [ :toggle diff-context -3             # Disminuye el contexto (-U arg)
bind diff ] :toggle diff-context +3             # Aumenta el contexto
bind generic V :toggle split-view-height -10%   # Disminuye la altura del divisor

De manera similar a los comandos externos, los comandos de la vista del paginador pueden contener nombres de variable que se sustituirán antes de ejecutar el comando.

COMMANDS

A key is mapped to an action, using the following syntax:

key action

Keys are case-sensitive. If a key is defined more than once, the last definition takes precedence. If a key is not defined, it is ignored. Keys can be defined multiple times for different actions. This allows for alternative bindings.

Keys are defined in the git-tig(1) man page, or in the ~/.config/tig/config or $XDG_CONFIG_HOME/tig/config configuration files. Use the command git-tig(1) to see all available key bindings.

COLOR COMMAND

Color commands control highlighting and the user interface styles. If your terminal supports color, these commands can be used to assign foreground and background combinations to certain areas. Optionally, an attribute can be given as the last parameter. The syntax is:

color area fgcolor bgcolor [attributes]

Examples:

# Override the default terminal colors to white on black.
color default           white   black
# Diff colors
color diff-header       yellow  default
color diff-index        blue    default
color diff-chunk        magenta default
color "Reported-by:"    green   default
# View-specific color
color tree.date         black   cyan    bold
# Custom color
color "/(note|warning|error):/" yellow  default bold

Or in the Git configuration files:

[tig "color"]
        # A strange looking cursor line
        cursor          = red   default underline
        # UI colors
        title-blur      = white blue
        title-focus     = white blue    bold
# View-specific color
[tig "color.tree"]
        date            = cyan  default bold

Area names

Can be either a built-in area name or a custom quoted string. The latter allows custom color rules to be added for lines matching a quoted string. Strings of the form "/.../" are interpreted as regular expressions. Valid built-in area names are described below. Note, all names are case-insensitive, and you may use -, and _ interchangeably, e.g. "Diff-Header" and "DIFF_HEADER" are the same. View-specific colors can be defined by prefixing the view name to the area name, e.g. "stage.diff-chunk" and "diff.diff-chunk".

Color names

Valid colors include: white, black, green, magenta, blue, cyan, yellow, red, default. Use default to refer to the default terminal colors, for example, to keep the background transparent when you are using a terminal with a transparent background.

Colors can also be specified using the keywords color0, color1, ..., colorN-1 (where N is the number of colors supported by your terminal). This is useful when you remap the colors for your display or want to enable colors supported by 88-color and 256-color terminals. Note that the color prefix is optional. If you prefer, you can specify colors directly by their numbers 0, 1, ..., N-1 instead, just like in the configuration file of Git.

Attribute names

Valid attributes include: normal, blink, bold, dim, reverse, standout, and underline. Note, not all attributes may be supported by the terminal.

UI colors

The colors and attributes to be used for the text that is not highlighted or that specify the use of the default terminal colors can be controlled by setting the default color option.

COMANDO SOURCE

Los comandos source permiten leer archivos de configuración adicionales. Los archivos cargados se incluyen in-situ, lo que significa que cuando se encuentra un comando source, el archivo se leerá inmediatamente. Cualquier comando posterior en el archivo de configuración actual tendrá precedencia.

Si la ruta dada no existe, tig procederá con una advertencia. Proporcione el parámetro -q para suprimir la advertencia.

La sintaxis es:

source [-q] ruta

Ejemplos:

source ~/.tig/colorscheme.tigrc
source ~/.tig/keybindings.tigrc
