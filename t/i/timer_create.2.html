timer_create(2) Manual de llamadas al sistema timer_create(2)

NOMBRE

timer_create - crea un temporizador POSIX por proceso

BIBLIOTECA

Biblioteca en tiempo real (librt, -lrt)

SINOPSIS

#include <signal.h>           /* Definición de las constantes SIGEV_* */
#include <time.h>
int timer_create(clockid_t clockid,
                 struct sigevent *_Nullable restrict sevp,
                 timer_t *restrict timerid);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

timer_create():

    _POSIX_C_SOURCE >= 199309L

DESCRIPCIÓN

timer_create() crea un nuevo temporizador de intervalo por proceso. La ID del nuevo temporizador se devuelve en el búfer apuntado por timerid, que debe ser un puntero no nulo. Esta ID es única dentro del proceso, hasta que el temporizador se elimina. El nuevo temporizador está inicialmente desarmado.

El argumento clockid especifica el reloj que el nuevo temporizador utiliza para medir el tiempo. Puede especificarse como uno de los siguientes valores:

CLOCK_REALTIME
Un reloj de tiempo real global del sistema configurable.
CLOCK_MONOTONIC
Un reloj que aumenta monótonamente y no se puede configurar, que mide el tiempo desde algún punto no especificado en el pasado que no cambia después del inicio del sistema.
CLOCK_PROCESS_CPUTIME_ID (desde Linux 2.6.12)
Un reloj que mide el tiempo de CPU (de usuario y de sistema) consumido por (todos los hilos del) proceso de llamada.
CLOCK_THREAD_CPUTIME_ID (desde Linux 2.6.12)
Un reloj que mide el tiempo de CPU (de usuario y de sistema) consumido por el hilo de llamada.
CLOCK_BOOTTIME (Desde Linux 2.6.39)
Al igual que CLOCK_MONOTONIC, este es un reloj que aumenta monótonamente. Sin embargo, mientras que el reloj CLOCK_MONOTONIC no mide el tiempo mientras un sistema está suspendido, el reloj CLOCK_BOOTTIME sí incluye el tiempo durante el cual el sistema está suspendido. Esto es útil para aplicaciones que necesitan ser conscientes de la suspensión. CLOCK_REALTIME no es adecuado para tales aplicaciones, ya que ese reloj se ve afectado por cambios discontinuos en el reloj del sistema.
CLOCK_REALTIME_ALARM (desde Linux 3.0)
Este reloj es similar a CLOCK_REALTIME, pero despertará al sistema si está suspendido. El llamante debe tener la capacidad CAP_WAKE_ALARM para configurar un temporizador contra este reloj.
CLOCK_BOOTTIME_ALARM (desde Linux 3.0)
Este reloj es similar a CLOCK_BOOTTIME, pero despertará al sistema si está suspendido. El llamante debe tener la capacidad CAP_WAKE_ALARM para configurar un temporizador contra este reloj.
CLOCK_TAI (desde Linux 3.10)
Un reloj global derivado del tiempo de reloj de pared pero que cuenta los segundos bisiestos.

Vea clock_getres(2) para más detalles sobre los relojes anteriores.

Además de los valores anteriores, clockid puede especificarse como el clockid devuelto por una llamada a clock_getcpuclockid(3) o pthread_getcpuclockid(3).

El argumento sevp apunta a una estructura sigevent que especifica cómo se debe notificar al llamante cuando el temporizador expire. Para la definición y detalles generales de esta estructura, vea sigevent(3type).

El campo sevp.sigev_notify puede tener los siguientes valores:

SIGEV_NONE
No notificar asincrónicamente cuando expire el temporizador. El progreso del temporizador se puede monitorear usando timer_gettime(2).
SIGEV_SIGNAL
Al expirar el temporizador, generar la señal sigev_signo para el proceso. Vea sigevent(3type) para detalles generales. El campo si_code de la estructura siginfo_t se establecerá en SI_TIMER. En cualquier momento, como máximo una señal se pone en cola para el proceso para un temporizador dado; vea timer_getoverrun(2) para más detalles.
SIGEV_THREAD
Al expirar el temporizador, invocar sigev_notify_function como si fuera la función de inicio de un nuevo hilo. Vea sigevent(3type) para detalles.
SIGEV_THREAD_ID (específico de Linux)
Como para SIGEV_SIGNAL, pero la señal se dirige al hilo cuya ID se proporciona en sigev_notify_thread_id, que debe ser un hilo en el mismo proceso que el llamante. El campo sigev_notify_thread_id especifica una ID de hilo del kernel, es decir, el valor devuelto por clone(2) o gettid(2). Esta bandera está destinada solo para uso por bibliotecas de hilos.

Especificar sevp como NULL es equivalente a especificar un puntero a una estructura sigevent en la que sigev_notify es SIGEV_SIGNAL, sigev_signo es SIGALRM y sigev_value.sival_int es la ID del temporizador.

VALOR DE RETORNO

En caso de éxito, timer_create() devuelve 0 y la ID del nuevo temporizador se coloca en *timerid. En caso de fallo, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EAGAIN
Error temporal durante la asignación en el kernel de estructuras de temporizador.
EINVAL
La ID del reloj, sigev_notify, sigev_signo o sigev_notify_thread_id es inválida.
ENOMEM
No se pudo asignar memoria.
ENOTSUP
El kernel no soporta la creación de un temporizador contra este clockid.
EPERM
clockid era CLOCK_REALTIME_ALARM o CLOCK_BOOTTIME_ALARM pero el llamante no tenía la capacidad CAP_WAKE_ALARM.

VERSIONES

Diferencias entre la biblioteca C y el kernel

Parte de la implementación de la API de temporizadores POSIX es proporcionada por glibc. En particular:

•
Gran parte de la funcionalidad para SIGEV_THREAD se implementa dentro de glibc, en lugar del kernel. (Esto es necesariamente así, ya que el hilo involucrado en el manejo de la notificación es uno que debe ser gestionado por la implementación de hilos POSIX de la biblioteca C). Aunque la notificación entregada al proceso es a través de un hilo, internamente la implementación NPTL utiliza un valor de sigev_notify de SIGEV_THREAD_ID junto con una señal en tiempo real que está reservada por la implementación (ver nptl(7)).
•
La implementación del caso predeterminado donde evp es NULL se maneja dentro de glibc, que invoca la llamada al sistema subyacente con una estructura sigevent adecuadamente poblada.
•
Las IDs de temporizador presentadas a nivel de usuario son mantenidas por glibc, que mapea estas IDs a las IDs de temporizador empleadas por el kernel.

ESTÁNDARES

El estándar POSIX.1-2001 (y posteriores) define esta llamada al sistema.

HISTORIA

Linux 2.6. POSIX.1-2001.

Antes de Linux 2.6, glibc proporcionaba una implementación incompleta en el espacio de usuario (solo temporizadores CLOCK_REALTIME) utilizando hilos POSIX, y antes de glibc 2.17, la implementación recurre a esta técnica en sistemas que ejecutan kernels anteriores a Linux 2.6.

NOTAS

Un programa puede crear múltiples temporizadores de intervalo usando timer_create().

Los temporizadores no son heredados por el hijo de un fork(2), y son desactivados y eliminados durante un execve(2).

El kernel preasigna una "señal en tiempo real encolada" para cada temporizador creado usando timer_create(). En consecuencia, el número de temporizadores está limitado por el límite de recursos RLIMIT_SIGPENDING (ver setrlimit(2)).

Los temporizadores creados por timer_create() se conocen comúnmente como "temporizadores POSIX (de intervalo)". La API de temporizadores POSIX consta de las siguientes interfaces:

timer_create()
Crea un temporizador.
timer_settime(2)
Activa (inicia) o desactiva (detiene) un temporizador.
timer_gettime(2)
Obtiene el tiempo restante hasta la próxima expiración de un temporizador, junto con la configuración del intervalo del temporizador.
timer_getoverrun(2)
Devuelve el recuento de sobrepasos para la última expiración del temporizador.
timer_delete(2)
Desactiva y elimina un temporizador.

Desde Linux 3.10, el archivo /proc/pid/timers puede ser usado para listar los temporizadores POSIX para el proceso con PID pid. Ver proc(5) para más información.

Desde Linux 4.10, el soporte para temporizadores POSIX es una opción configurable que está habilitada por defecto. El soporte del kernel puede ser deshabilitado a través de la opción CONFIG_POSIX_TIMERS.

EJEMPLOS

El siguiente programa toma dos argumentos: un período de espera en segundos y una frecuencia de temporizador en nanosegundos. El programa establece un manejador para la señal que utiliza para el temporizador, bloquea esa señal, crea y activa un temporizador que expira con la frecuencia dada, duerme durante el número especificado de segundos y luego desbloquea la señal del temporizador. Suponiendo que el temporizador expiró al menos una vez mientras el programa dormía, se invocará el manejador de señales, y el manejador mostrará información sobre la notificación del temporizador. El programa termina después de una invocación del manejador de señales.

En el siguiente ejemplo de ejecución, el programa duerme durante 1 segundo, después de crear un temporizador con una frecuencia de 100 nanosegundos. Para cuando la señal se desbloquea y se entrega, ha habido alrededor de diez millones de sobrepasos.


$ ./a.out 1 100;
Estableciendo manejador para la señal 34
Bloqueando señal 34
ID del temporizador es 0x804c008
Durmiendo durante 1 segundos
Desbloqueando señal 34
Capturada señal 34
    sival_ptr = 0xbfb174f4;     *sival_ptr = 0x804c008
    recuento de sobrepasos = 10004886

Fuente del programa

#include <err.h>
#include <signal.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <unistd.h>
#define CLOCKID CLOCK_REALTIME
#define SIG SIGRTMIN
static void
print_siginfo(siginfo_t *si)
{
    int      or;
    timer_t  *tidp;
    tidp = si->si_value.sival_ptr;
    printf("    sival_ptr = %p; ", si->si_value.sival_ptr);
    printf("    *sival_ptr = %#jx\n", (uintmax_t) *tidp);
    or = timer_getoverrun(*tidp);
    if (or == -1)
        err(EXIT_FAILURE, "timer_getoverrun");
    printf("    recuento de sobrepasos = %d\n", or);
}
static void
handler(int sig, siginfo_t *si, void *uc)
{
    /* Tenga en cuenta que llamar a printf() desde un manejador de señales no es seguro
       (y no debe hacerse en programas de producción), ya que
       printf() no es seguro para señales asíncronas; ver signal-safety(7).
       Sin embargo, usamos printf() aquí como una forma sencilla de
       mostrar que el manejador fue llamado.  */
    printf("Capturada señal %d\n", sig);
    print_siginfo(si);
    signal(sig, SIG_IGN);
}
int
main(int argc, char *argv[])
{
    timer_t            timerid;
    sigset_t           mask;
    long long          freq_nanosecs;
    struct sigevent    sev;
    struct sigaction   sa;
    struct itimerspec  its;
    if (argc != 3) {
        fprintf(stderr, "Uso: %s <sleep-secs> <freq-nanosecs>\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }
    /* Establecer manejador para la señal del temporizador.  */
    printf("Estableciendo manejador para la señal %d\n", SIG);
    sa.sa_flags = SA_SIGINFO;
    sa.sa_sigaction = handler;
    sigemptyset(&sa.sa_mask);
    if (sigaction(SIG, &sa, NULL) == -1)
        err(EXIT_FAILURE, "sigaction");
    /* Bloquear temporalmente la señal del temporizador.  */
    printf("Bloqueando señal %d\n", SIG);
    sigemptyset(&mask);
    sigaddset(&mask, SIG);
    if (sigprocmask(SIG_SETMASK, &mask, NULL) == -1)
        err(EXIT_FAILURE, "sigprocmask");
    /* Crear el temporizador.  */
    sev.sigev_notify = SIGEV_SIGNAL;
    sev.sigev_signo = SIG;
    sev.sigev_value.sival_ptr = &timerid;
    if (timer_create(CLOCKID, &sev, &timerid) == -1)
        err(EXIT_FAILURE, "timer_create");
    printf("ID del temporizador es %#jx\n", (uintmax_t) timerid);
    /* Iniciar el temporizador.  */
    freq_nanosecs = atoll(argv[2]);
    its.it_value.tv_sec = freq_nanosecs / 1000000000;
    its.it_value.tv_nsec = freq_nanosecs % 1000000000;
    its.it_interval.tv_sec = its.it_value.tv_sec;
    its.it_interval.tv_nsec = its.it_value.tv_nsec;
    if (timer_settime(timerid, 0, &its, NULL) == -1)
         err(EXIT_FAILURE, "timer_settime");
    /* Dormir un rato; mientras tanto, el temporizador puede expirar
       múltiples veces.  */
    printf("Durmiendo durante %d segundos\n", atoi(argv[1]));
    sleep(atoi(argv[1]));
    /* Desbloquear la señal del temporizador, para que la notificación
       del temporizador pueda ser entregada.  */
    printf("Desbloqueando señal %d\n", SIG);
    if (sigprocmask(SIG_UNBLOCK, &mask, NULL) == -1)
        err(EXIT_FAILURE, "sigprocmask");
    exit(EXIT_SUCCESS);
}
