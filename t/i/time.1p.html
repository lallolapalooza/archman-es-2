TIME(1P) Manual de Programador de POSIX TIME(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual correspondiente de Linux para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

time — mide el tiempo de un comando simple

SINOPSIS

time [-p] utilidad [argumento...]

DESCRIPCIÓN

La utilidad time invocará a la utilidad nombrada por el operando utilidad con los argumentos proporcionados como operandos argumento y escribirá un mensaje en la salida de error estándar que enumere las estadísticas de tiempo de la utilidad. El mensaje incluirá la siguiente información:

*
El tiempo transcurrido (real) entre la invocación de utilidad y su terminación.
*
El tiempo de CPU de usuario, equivalente a la suma de los campos tms_utime y tms_cutime devueltos por la función times() definida en el volumen de Interfaces del Sistema de POSIX.1‐2017 para el proceso en el que se ejecuta utilidad.
*
El tiempo de CPU del sistema, equivalente a la suma de los campos tms_stime y tms_cstime devueltos por la función times() para el proceso en el que se ejecuta utilidad.

La precisión de la medición del tiempo no será inferior a la granularidad definida para el tamaño de la unidad de tick del reloj en el sistema, pero los resultados se informarán en términos de unidades de tiempo estándar (por ejemplo, 0.02 segundos, 00:00:00.02, 1m33.75s, 365.21 segundos), no en números de ticks del reloj.

Cuando time se utiliza como parte de una tubería (pipeline), los tiempos informados no están especificados, excepto cuando es el único comando dentro de un comando de agrupación (consulte la Sección 2.9.4.1, Comandos de Agrupación) en esa tubería. Por ejemplo, los comandos de la izquierda no están especificados; los de la derecha informan sobre las utilidades a y c, respectivamente:

time a | b | c    { time a; } | b | c
a | b | time c    a | b | (time c)

OPCIONES

La utilidad time cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades.

Se soportará la siguiente opción:

-p
Escribe la salida de tiempo en el error estándar en el formato que se muestra en la sección STDERR.

OPERANDOS

Se soportarán los siguientes operandos:

utilidad
El nombre de una utilidad que se va a invocar. Si el operando utilidad nombra alguna de las utilidades internas especiales en la Sección 2.14, Utilidades Internas Especiales, los resultados no están definidos.
argumento
Cualquier cadena que se proporcione como argumento al invocar la utilidad nombrada por el operando utilidad.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de time:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de locale).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos).
LC_MESSAGES

Determina la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico e informativos escritos en el error estándar.
LC_NUMERIC

Determina la configuración regional para el formato numérico.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
PATH
Determina la ruta de búsqueda que se utilizará para localizar la utilidad a invocar; consulte el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 8, Variables de Entorno.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

No se utiliza.

SALIDA DE ERROR ESTÁNDAR

Si se invoca la utilidad utilidad, el error estándar se utilizará para escribir las estadísticas de tiempo y puede utilizarse para escribir un mensaje de diagnóstico si la utilidad termina de forma anormal; de lo contrario, el error estándar se utilizará para escribir mensajes de diagnóstico y también puede usarse para escribir las estadísticas de tiempo.

Si se especifica -p, se utilizará el siguiente formato para las estadísticas de tiempo en la configuración regional POSIX:

"real %f\nuser %f\nsys %f\n", <segundos reales>, <segundos de usuario>,
    <segundos del sistema>

donde cada número de punto flotante se expresará en segundos. La precisión utilizada puede ser menor que los seis dígitos predeterminados de %f, pero será lo suficientemente precisa para acomodar el tamaño del tick del reloj en el sistema (por ejemplo, si hubiera 60 ticks de reloj por segundo, al menos dos dígitos seguirían al carácter radix). El número de dígitos que siguen al carácter radix no será inferior a uno, incluso si esto siempre resulta en un cero final. La implementación puede añadir espacios en blanco e información adicional después del formato que aquí se muestra. La implementación puede añadir también una línea única vacía antes del formato que aquí se muestra.

Ninguna.

ESTADO DE SALIDA

Si se invoca la utilidad utilidad, el estado de salida de time será el estado de salida de utilidad; de lo contrario, la utilidad time saldrá con uno de los siguientes valores:

1‐125
Ocurrió un error en la utilidad time.
  126
Se encontró la utilidad especificada por utilidad pero no se pudo invocar.
  127
No se pudo encontrar la utilidad especificada por utilidad.

CONSECUENCIAS DE ERRORES

Predeterminado.

USO DE APLICACIÓN

Las utilidades command, env, nice, nohup, time y xargs se han especificado para usar el código de salida 127 si ocurre un error, de modo que las aplicaciones puedan distinguir entre "fallo al encontrar una utilidad" y "la utilidad invocada salió con un indicador de error". Se eligió el valor 127 porque no se usa comúnmente para otros significados; la mayoría de las utilidades usan valores pequeños para "errores normales.

El valor 126 se eligió de manera similar para indicar que la utilidad se podía encontrar, pero no invocar. Algunos scripts producen mensajes de error significativos que diferencian los casos 126 y 127. La distinción entre los códigos de salida 126 y 127 se basa en la práctica de KornShell, que utiliza 127 cuando todos los intentos de exec de la utilidad fallan con [ENOENT], y utiliza 126 cuando cualquier intento de exec de la utilidad falla por cualquier otro motivo.

EJEMPLOS

Con frecuencia es deseable aplicar time a pipelines o listas de comandos. Esto se puede hacer colocando pipelines y listas de comandos en un solo archivo; este archivo puede ser invocado como una utilidad, y time se aplica a todo el contenido del archivo.

Alternativamente, el siguiente comando se puede usar para aplicar time a un comando complejo:

time sh -c 'comando-complejo-en-linea'

FUNDAMENTO

Cuando la utilidad time se propuso originalmente para ser incluida en el estándar ISO POSIX‐2:1993, surgieron preguntas sobre su idoneidad para su inclusión, alegando que no era útil para aplicaciones conformes, específicamente:

*
Las definiciones subyacentes de CPU del volumen System Interfaces de POSIX.1‐2017 son vagas, por lo que la salida numérica no se podía comparar con precisión entre sistemas o incluso entre invocaciones.
*
La creación de programas de referencia portátiles estaba fuera del alcance de este volumen de POSIX.1‐2017.

Sin embargo, time encaja en el alcance de la portabilidad del usuario. El juicio humano puede aplicarse al análisis de la salida, y podría ser muy útil en la depuración práctica de aplicaciones o en la provisión de medidas subjetivas del rendimiento del sistema. Por lo tanto, se ha incluido en este volumen de POSIX.1‐2017.

El formato de salida predeterminado se ha dejado sin especificar porque las implementaciones históricas difieren mucho en su estilo de representación de esta salida numérica. La opción -p se inventó para proporcionar a los scripts un medio común de obtener esta información.

En KornShell, time es una palabra reservada del shell que se puede usar para medir el tiempo de un pipeline completo, en lugar de solo un comando simple. La definición POSIX se ha redactado para permitir esta implementación. Se consideró invalidar este enfoque debido al modelo histórico del shell C y del shell System V. Sin embargo, dado que la utilidad time de System V históricamente no ha producido resultados precisos en la medición del tiempo de pipelines (porque los procesos constituyentes no son todos propiedad del mismo proceso padre, como lo permite POSIX), no pareció valioso romper el uso histórico de KornShell.

Se utiliza el término utilidad, en lugar de comando, para resaltar el hecho de que los comandos compuestos del shell, los pipelines, los built-ins especiales, etc., no se pueden usar directamente. Sin embargo, utilidad incluye programas de aplicación de usuario y scripts de shell, no solo las utilidades estándar.
