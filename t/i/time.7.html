time(7) Manual de Información Miscelánea time(7)

NOMBRE

time - descripción general de tiempo y temporizadores

DESCRIPCIÓN

Tiempo real y tiempo de proceso

El tiempo real se define como el tiempo medido desde algún punto fijo, ya sea desde un punto estándar en el pasado (ver la descripción de la Época y el tiempo del calendario a continuación), o desde algún punto (por ejemplo, el inicio) en la vida de un proceso (tiempo transcurrido).

El tiempo de proceso se define como la cantidad de tiempo de CPU utilizado por un proceso. A veces se divide en componentes de usuario y sistema. El tiempo de CPU de usuario es el tiempo dedicado a ejecutar código en modo de usuario. El tiempo de CPU de sistema es el tiempo dedicado por el kernel a ejecutarse en modo de sistema en nombre del proceso (por ejemplo, ejecutando llamadas al sistema). El comando time(1) se puede utilizar para determinar la cantidad de tiempo de CPU consumido durante la ejecución de un programa. Un programa puede determinar la cantidad de tiempo de CPU que ha consumido utilizando times(2), getrusage(2) o clock(3).

El reloj hardware

La mayoría de las computadoras tienen un reloj de hardware (alimentado por batería) que el kernel lee al arrancar para inicializar el reloj del software. Para más detalles, ver rtc(4) y hwclock(8).

El reloj del software, HZ, y jiffies

La precisión de varias llamadas al sistema que establecen tiempos de espera, (por ejemplo, select(2), sigtimedwait(2)) y miden el tiempo de CPU (por ejemplo, getrusage(2)) está limitada por la resolución del reloj del software, un reloj mantenido por el kernel que mide el tiempo en jiffies. El tamaño de un jiffy está determinado por el valor de la constante del kernel HZ.

El valor de HZ varía entre versiones del kernel y plataformas de hardware. En i386 la situación es la siguiente: en kernels hasta e incluyendo Linux 2.4.x, HZ era 100, dando un valor de jiffy de 0.01 segundos; a partir de Linux 2.6.0, HZ se incrementó a 1000, dando un jiffy de 0.001 segundos. Desde Linux 2.6.13, el valor HZ es un parámetro de configuración del kernel y puede ser 100, 250 (el predeterminado) o 1000, produciendo un valor de jiffies de, respectivamente, 0.01, 0.004 o 0.001 segundos. Desde Linux 2.6.20, hay una frecuencia adicional disponible: 300, un número que se divide uniformemente para las frecuencias de video comunes (PAL, 25 Hz; NTSC, 30 Hz).

La llamada al sistema times(2) es un caso especial. Informa tiempos con una granularidad definida por la constante del kernel USER_HZ. Las aplicaciones en espacio de usuario pueden determinar el valor de esta constante usando sysconf(_SC_CLK_TCK).

Relojes del sistema y de proceso; namespaces de tiempo

El kernel soporta una gama de relojes que miden varios tipos de tiempo transcurrido y virtual (es decir, CPU consumida). Estos relojes se describen en clock_gettime(2). Algunos de los relojes se pueden configurar usando clock_settime(2). Los valores de ciertos relojes son virtualizados por namespaces de tiempo; ver time_namespaces(7).

Temporizadores de alta resolución

Antes de Linux 2.6.21, la precisión de las llamadas al sistema de temporizadores y de espera (ver abajo) también estaba limitada por el tamaño del jiffy.

Desde Linux 2.6.21, Linux soporta temporizadores de alta resolución (HRT), opcionalmente configurables a través de CONFIG_HIGH_RES_TIMERS. En un sistema que soporta HRT, la precisión de las llamadas al sistema de espera y temporizadores ya no está restringida por el jiffy, sino que puede ser tan precisa como el hardware lo permita (la precisión de microsegundos es típica del hardware moderno). Puedes determinar si los temporizadores de alta resolución son compatibles comprobando la resolución devuelta por una llamada a clock_getres(2) o mirando las entradas de "resolution" en /proc/timer_list.

Los HRT no son compatibles con todas las arquitecturas de hardware. (El soporte se proporciona en x86, ARM y PowerPC, entre otros).

La Época

Los sistemas UNIX representan el tiempo en segundos desde la Época, 1970-01-01 00:00:00 +0000 (UTC).

Un programa puede determinar el tiempo del calendario a través del reloj CLOCK_REALTIME de clock_gettime(2), que devuelve el tiempo (en segundos y nanosegundos) que ha transcurrido desde la Época; time(2) proporciona información similar, pero solo con precisión hasta el segundo más cercano. El tiempo del sistema se puede modificar usando clock_settime(2).

Tiempo desglosado

Ciertas funciones de biblioteca utilizan una estructura de tipo tm para representar el tiempo desglosado, que almacena el valor del tiempo separado en componentes distintos (año, mes, día, hora, minuto, segundo, etc.). Esta estructura se describe en tm(3type), que también describe funciones que convierten entre el tiempo del calendario y el tiempo desglosado. Las funciones para convertir entre tiempo desglosado y representaciones de cadena imprimibles del tiempo se describen en ctime(3), strftime(3) y strptime(3).

Dormir y establecer temporizadores

Varias llamadas al sistema y funciones permiten a un programa dormir (suspender la ejecución) durante un período de tiempo especificado; ver nanosleep(2), clock_nanosleep(2) y sleep(3).

Varias llamadas al sistema permiten a un proceso establecer un temporizador que expira en algún momento futuro, y opcionalmente en intervalos repetidos; ver alarm(2), getitimer(2), timerfd_create(2) y timer_create(2).

Margen de temporizador

Desde Linux 2.6.28, es posible controlar el valor del "margen de temporizador" para un hilo. El margen de temporizador es el tiempo por el cual el kernel puede retrasar el despertar de ciertas llamadas al sistema que se bloquean con un tiempo de espera. Permitir este retraso permite al kernel coalescer eventos de despertar, reduciendo así posiblemente el número de despertares del sistema y ahorrando energía. Para más detalles, ver la descripción de PR_SET_TIMERSLACK en prctl(2).
