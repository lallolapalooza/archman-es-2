TIMER_GETOVERRUN(3P) Manual del programador de POSIX TIMER_GETOVERRUN(3P)

PROLOG

Esta página del manual forma parte del Manual del programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual correspondiente de Linux para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

timer_getoverrun, timer_gettime, timer_settime — temporizadores por proceso

SINOPSIS

#include <time.h>
int timer_getoverrun(timer_t timerid);
int timer_gettime(timer_t timerid, struct itimerspec *value);
int timer_settime(timer_t timerid, int flags,
    const struct itimerspec *restrict value,
    struct itimerspec *restrict ovalue);

DESCRIPCIÓN

La función timer_gettime() almacenará el tiempo hasta que el temporizador especificado, timerid, expire y el valor de recarga del temporizador en el espacio al que apunta el argumento value. El miembro it_value de esta estructura contendrá el tiempo hasta que expire el temporizador, o cero si el temporizador está desarmado. Este valor se devuelve como el intervalo hasta la expiración del temporizador, incluso si el temporizador se armó con tiempo absoluto. El miembro it_interval de value contendrá el valor de recarga establecido por última vez con timer_settime().

La función timer_settime() establecerá el tiempo hasta la próxima expiración del temporizador especificado por timerid a partir del miembro it_value del argumento value y armará el temporizador si el miembro it_value de value no es cero. Si el temporizador especificado ya estaba armado cuando se llama a timer_settime(), esta llamada restablecerá el tiempo hasta la próxima expiración al valor especificado. Si el miembro it_value de value es cero, el temporizador se desarmará. El efecto de desarmar o restablecer un temporizador con notificaciones de expiración pendientes no está especificado.

Si la bandera TIMER_ABSTIME no está establecida en el argumento flags, timer_settime() se comportará como si el tiempo hasta la próxima expiración se estableciera igual al intervalo especificado por el miembro it_value de value. Es decir, el temporizador expirará después de it_value nanosegundos desde que se realizó la llamada. Si la bandera TIMER_ABSTIME está establecida en el argumento flags, timer_settime() se comportará como si el tiempo hasta la próxima expiración se estableciera igual a la diferencia entre el tiempo absoluto especificado por el miembro it_value de value y el valor actual del reloj asociado con timerid. Es decir, el temporizador expirará cuando el reloj alcance el valor especificado por el miembro it_value de value. Si el tiempo especificado ya ha pasado, la función tendrá éxito y se realizará la notificación de expiración.

El valor de recarga del temporizador se establecerá al valor especificado por el miembro it_interval de value. Cuando un temporizador se arma con un it_interval no cero, se especifica un temporizador periódico o repetitivo.

Los valores de tiempo que se encuentren entre dos múltiplos enteros no negativos consecutivos de la resolución del temporizador especificado se redondearán al múltiplo mayor de la resolución. El error de cuantificación no provocará que el temporizador expire antes de la hora redondeada.

Si el argumento ovalue no es NULL, la función timer_settime() almacenará, en la ubicación a la que apunta ovalue, un valor que representa el tiempo anterior antes de que el temporizador hubiera expirado, o cero si el temporizador fue desarmado, junto con el valor de recarga anterior del temporizador. Los temporizadores no expirarán antes de su tiempo programado.

Solo se pondrá en cola una señal para el proceso para un temporizador dado en cualquier momento. Cuando expira un temporizador para el cual todavía hay una señal pendiente, no se pondrá en cola ninguna señal y se producirá un rebase del temporizador. Cuando una señal de expiración del temporizador es entregada o aceptada por un proceso, la función timer_getoverrun() devolverá el recuento de rebases de expiración del temporizador para el temporizador especificado. El recuento de rebases devuelto contiene el número de expiraciones adicionales del temporizador que ocurrieron entre el momento en que se generó (encoló) la señal y cuando se entregó o aceptó, hasta pero sin incluir un máximo definido por la implementación de {DELAYTIMER_MAX}. Si el número de expiraciones adicionales es mayor o igual a {DELAYTIMER_MAX}, entonces el recuento de rebases se establecerá en {DELAYTIMER_MAX}. El valor devuelto por timer_getoverrun() se aplicará a la entrega o aceptación más reciente de la señal de expiración para el temporizador. Si no se ha entregado ninguna señal de expiración para el temporizador, el valor devuelto por timer_getoverrun() no está especificado.

El comportamiento no está definido si el valor especificado por el argumento timerid a timer_getoverrun(), timer_gettime(), o timer_settime() no corresponde a un ID de temporizador devuelto por timer_create() pero aún no eliminado por timer_delete().

VALOR DE RETORNO

Si la función timer_getoverrun() tiene éxito, devolverá el recuento de rebases de expiración del temporizador como se explicó anteriormente.

Si las funciones timer_gettime() o timer_settime() tienen éxito, se devolverá el valor 0.

Si ocurre un error en alguna de estas funciones, se devolverá el valor -1 y se establecerá errno para indicar el error.

ERRORES

La función timer_settime() fallará si:

EINVAL
Una estructura value especificó un valor de nanosegundo menor que cero o mayor o igual a 1000 millones, y el miembro it_value de esa estructura no especificó cero segundos y nanosegundos.

La función timer_settime() puede fallar si:

EINVAL
El miembro it_interval de value no es cero y el temporizador se creó con notificación mediante la creación de un nuevo hilo (sigev_sigev_notify era SIGEV_THREAD) y se ha establecido una pila fija en el hilo atributo al que apunta sigev_notify_attributes.

EJEMPLOS

Ninguno.

USO EN APLICACIONES

Usar direcciones de pila fijas es problemático cuando la expiración del temporizador se notifica mediante la creación de un nuevo hilo. Dado que no se puede asumir que el hilo creado para una expiración ha terminado antes de la siguiente expiración del temporizador, podría suceder que dos hilos utilicen la misma memoria como pila al mismo tiempo. Esto es inválido y produce resultados no definidos.

FUNDAMENTO

Los relojes prácticos funcionan a una velocidad finita, con velocidades de 100 hercios y 1000 hercios siendo comunes. El inverso de esta velocidad de reloj es la resolución del reloj, también llamada granularidad del reloj, que en cualquier caso se expresa como una duración de tiempo, siendo de 10 milisegundos y 1 milisegundo respectivamente para estas tasas comunes. La granularidad de los relojes prácticos implica que si uno lee un reloj dado dos veces en rápida sucesión, puede obtener el mismo valor de tiempo dos veces; y que los temporizadores deben esperar al siguiente tick del reloj después del tiempo de expiración teórico, para garantizar que un temporizador nunca retorne demasiado pronto. Tenga en cuenta también que la granularidad del reloj puede ser significativamente más gruesa que la resolución del formato de datos utilizado para establecer y obtener valores de tiempo e intervalo. Tenga en cuenta también que algunas implementaciones pueden optar por ajustar los valores de tiempo y/o intervalo para que coincidan exactamente con los ticks del reloj subyacente.

Este volumen de POSIX.1‐2017 define funciones que permiten a una aplicación determinar la resolución admitida por la implementación para los relojes y requiere que una implementación documente la resolución admitida para temporizadores y nanosleep() si difiere de la resolución de reloj admitida. Esto es más un problema de adquisición que un problema de aplicación en tiempo de ejecución.

Si una implementación detecta que el valor especificado por el argumento timerid a timer_getoverrun(), timer_gettime(), o timer_settime() no corresponde a un ID de temporizador devuelto por timer_create() pero aún no eliminado por timer_delete(), se recomienda que la función debería fallar
