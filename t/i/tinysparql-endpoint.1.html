TINYSPARQL-ENDPOINT(1) Manual de TinySPARQL TINYSPARQL-ENDPOINT(1)

NOMBRE

tinysparql-endpoint - Crear un punto final SPARQL

SINOPSIS

tinysparql endpoint [--dbus-service | -b] <nombre_servicio>
                  [--database-path | -d] <ruta_base_datos>
                  [[--ontology | -o] <nombre_ontologia> |
                   [--ontology-path | -p] <ruta_ontologia>]
                  [--http-port] <puerto>
                  [--loopback]
                  [[--system | --session]]

DESCRIPCIÓN

Este comando permite crear puntos finales SPARQL. El punto final podrá manejar consultas SPARQL de selección y actualización, y notificar sobre cambios en él.

El punto final se exporta a través de DBus, accesible mediante el nombre_servicio dado, ya sea utilizándolo en una cláusula SERVICE, o creando una conexión SPARQL dedicada basada en bus.

Al crear una base de datos, se debe proporcionar el nombre_ontologia (o alternativamente, una ruta_ontologia) para generar la base de datos. Si se usa nombre_ontologia, la ontología debe existir en $datadir/tracker/ontologies

Los usuarios deben tener cuidado con la opción --http-port, consideren usarla solo en combinación con la opción --loopback.

La base de datos en sí se almacenará de acuerdo con ruta_base_datos.

OPCIONES

-b, --dbus-service=<nombre_servicio>

Nombre del servicio a utilizar en el punto final.

-d, --database-path=<ruta_base_datos>

La ruta donde se almacenará la base de datos.

-o, --ontology

El nombre de una ontología en $datadir/tracker/ontologies a utilizar en la base de datos construida.

-p, --ontology-path

Ruta completa a una ontología a utilizar en la base de datos construida.

--session

Utilizar el bus de sesión. Este es el valor por defecto.

--system

Utilizar el bus del sistema.

-l, --list

Listar todos los puntos finales SPARQL disponibles en DBus

-L, --list-http

Listar puntos finales SPARQL HTTP locales de red

--http-port

Crea un punto final HTTP que escucha en el puerto especificado.

--loopback

Permite solo conexiones HTTP en el dispositivo de loopback. Solo efectivo con puntos finales HTTP.

EJEMPLOS

Exportar un punto final Nepomuk con el nombre de bus org.example.Example1.

$ tinysparql endpoint -b org.example.Example1 -o nepomuk -d /tmp/example1

Acceder a este punto final con el subcomando tinysparql-sparql(1).

$ tinysparql sparql --dbus-service org.example.Example1 -q "
  SELECT ?s ?o
  WHERE {
    ?u a ?o
  }"

Exportar un punto final Nepomuk a través de HTTP.

$ tinysparql endpoint --http-port 8080 -o nepomuk --loopback

Acceder a este punto final a través de HTTP.

$ tinysparql sparql --remote-service http://127.0.0.1:8080/sparql -q "
  SELECT ?u {
    ?u a rdfs:Resource
  }"
