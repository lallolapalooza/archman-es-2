tic(1M) Comandos de usuario tic(1M)

NOMBRE

tic - compilar descripciones de terminal para terminfo o termcap

SINOPSIS

tic [-01acCDfgGIKLNqrstTUVWx] [-e lista-de-tipos-de-terminal] [-o dir] [-Q[n]] [-R subconjunto] [-v[n]] [-w[n]] archivo

DESCRIPCIÓN

El comando tic traduce un archivo terminfo del formato fuente a formato compilado. El formato compilado es necesario para su uso con las rutinas de biblioteca en ncurses(3X).

Como se describe en term(5), la base de datos puede ser un árbol de directorios (un archivo por entrada de terminal) o una base de datos hash (un registro por entrada). El comando tic escribe solo un tipo de entrada, dependiendo de cómo fue construido:

  • Para árboles de directorios, el directorio de nivel superior, p. ej., /usr/share/terminfo, especifica la ubicación de la base de datos.
  • Para bases de datos hash, se necesita un nombre de archivo. Si el archivo dado no se encuentra con ese nombre, pero se puede encontrar agregando el sufijo ".db", entonces se utiliza ese.
El nombre predeterminado para la base de datos hash es el mismo que el nombre del directorio predeterminado (solo agregando un sufijo ".db").

En cualquier caso (directorio o base de datos hash), tic creará el contenedor si no existe. Para un directorio, este sería el nodo terminal “terminfo”, en contraposición a un archivo “terminfo.db”.

Los resultados se colocan normalmente en la base de datos terminfo del sistema /usr/share/terminfo. La descripción de terminal compilada puede colocarse en una base de datos terminfo diferente. Hay dos formas de lograr esto:

  • Primero, puede anular el predeterminado del sistema utilizando la opción -o, o estableciendo la variable TERMINFO en su entorno de shell a una ubicación de base de datos válida.
  • En segundo lugar, si tic no puede escribir en /usr/share/terminfo o en la ubicación especificada usando su variable TERMINFO, busca el directorio $HOME/.terminfo (o base de datos hash $HOME/.terminfo.db); si esa ubicación existe, la entrada se coloca allí.

Se espera que las bibliotecas que leen entradas terminfo verifiquen en sucesión

  • una ubicación especificada con la variable de entorno TERMINFO,
  • $HOME/.terminfo,
  • directorios listados en la variable de entorno TERMINFO_DIRS,
  • una lista de directorios compilada en el código ( /usr/share/terminfo), y
  • la base de datos terminfo del sistema (/usr/share/terminfo).

La sección Obtención de descripciones compiladas en el manual de terminfo(5) entra en más detalle.

Alias

Este es el mismo programa que infotocap y captoinfo; normalmente estos se enlazan o se copian de este programa:

  • Cuando se invoca como infotocap, tic establece la opción -I.
  • Cuando se invoca como captoinfo, tic establece la opción -C.

OPCIONES

-0
restringe la salida a una sola línea
-1
restringe la salida a una sola columna
-a
indica a tic que conserve las capacidades comentadas en lugar de descartarlas. Las capacidades se comentan prefijándolas con un punto. Esto establece la opción -x, ya que trata las entradas comentadas como nombres definidos por el usuario. Si la fuente es termcap, acepta los nombres de 2 caracteres requeridos por la versión 6. De lo contrario, se ignoran.
-C
Fuerza la traducción de origen a formato termcap. Nota: esto difiere de la opción -C de infocmp(1M) en que no solo traduce nombres de capacidades, sino que también traduce cadenas terminfo a formato termcap. Las capacidades que no son traducibles se dejan en la entrada bajo sus nombres terminfo pero comentadas con dos puntos precedentes. El formato real utilizado incorpora algunas mejoras para caracteres escapados del formato terminfo. Para una traducción más estricta compatible con BSD, agregue la opción -K.
Si esto se combina con -c, tic realiza comprobaciones adicionales para informar casos en los que los valores terminfo no tienen un equivalente exacto en formato termcap. Por ejemplo:
  • sgr generalmente no se convertirá, porque termcap carece de la capacidad de trabajar con más de dos parámetros, y porque termcap carece de muchos de los operadores aritméticos/lógicos utilizados en terminfo.
  • Las capacidades con más de un retraso o con retrasos antes del final de la cadena no se convertirán completamente.
-c
indica a tic que solo verifique archivo en busca de errores, incluyendo problemas de sintaxis y enlaces de uso incorrectos. Si especifica -C (-I) con esta opción, el código imprimirá advertencias sobre entradas que, después de la resolución de uso, tengan más de 1023 (4096) bytes de longitud. Debido a una longitud de búfer fija en bibliotecas termcap antiguas, así como a una comprobación defectuosa de la longitud del búfer (y un límite documentado en terminfo), estas entradas pueden causar core dumps con otras implementaciones.
tic comprueba las capacidades de cadena para asegurar que aquellas con parámetros serán expresiones válidas. Realiza esta comprobación solo para las capacidades de cadena predefinidas; aquellas que se definen con la opción -x se ignoran.
-D
indica a tic que imprima las ubicaciones de la base de datos que conoce y salga. La primera ubicación mostrada es aquella a la que escribiría las descripciones de terminal compiladas. Si tic no puede encontrar una ubicación de base de datos escribible según las reglas resumidas anteriormente, imprimirá un diagnóstico y saldrá con un error en lugar de imprimir una lista de ubicaciones de base de datos.
-e lista
Limita las escrituras y traducciones a la lista separada por comas de tipos de terminal. Si algún nombre o alias de un terminal coincide con uno de los nombres de la lista, la entrada se escribirá o traducirá como normal. De lo contrario, no se generará ninguna salida para ella. El valor de la opción se interpreta como un archivo que contiene la lista si contiene un '/'. (Nota: dependiendo de cómo se compiló tic, esta opción puede requerir -I o -C.)
-f
Muestra cadenas terminfo complejas que contienen expresiones if/then/else/endif indentadas para legibilidad.
-G
Muestra literales constantes en forma decimal en lugar de sus equivalentes de caracteres.
-g
Muestra literales de caracteres constantes en forma entrecomillada en lugar de sus equivalentes decimales.
-I
Fuerza la traducción de origen a formato terminfo.
-K
Suprime algunas extensiones de ncurses de larga data al formato termcap, por ejemplo, "\s" para espacio.
-L
Fuerza la traducción de origen a formato terminfo utilizando los nombres de variables C largas listados en <term.h>
-N
Desactiva los valores predeterminados inteligentes. Normalmente, al traducir de termcap a terminfo, el compilador hace una serie de suposiciones sobre los valores predeterminados de las capacidades de cadena reset1_string, carriage_return, cursor_left, cursor_down, scroll_forward, tab, newline, key_backspace, key_left, y key_down, luego intenta usar capacidades termcap obsoletas para deducir valores correctos. También suprime normalmente la salida de capacidades termcap obsoletas como bs. Esta opción fuerza una traducción más literal que también preserva las capacidades obsoletas.
-odir
Escribe las entradas compiladas en la ubicación de la base de datos dada. Anula la variable de entorno TERMINFO.
-Qn
En lugar de mostrar el origen en formato terminfo (texto), imprime el formato compilado (binario) en hexadecimal o base64.

La opción -Q n, donde n es el número de caracteres hexadecimales a imprimir por línea, se puede usar para la depuración. Sin opción n, se utiliza un valor predeterminado de 16.

Si se utiliza la opción -Q, se pueden especificar las opciones -c y -C o -I.

-q
ignora la validación de la cadena de capacidades de entrada/salida que contienen caracteres que requieren escapes.
-r
normaliza las cadenas de entrada/salida para el uso de termcap.
-s
escribe el código de escape para las capacidades de cadena en su forma más corta y simple.
-t
escribe todas las capacidades en formato de texto (no compilado).
-T
describe el modo de traducción de formato de termcap a terminfo. En este modo, tic imprime las secuencias de escape de termcap que se convierten a terminfo.
-u
realiza una comprobación adicional de las cadenas de entrada/salida. En particular, verifica si las cadenas contienen caracteres de control, y si no, reemplaza las cadenas con caracteres de control por su representación numérica.
-v[n]
escribe las operaciones de tic en la salida estándar. Si se omite n, se imprime un nivel de detalle predeterminado. Si se especifica n, el nivel de detalle es n.
-V
imprime la versión de ncurses y sale.
-w[n]
imprime los resultados de tic en el formato de texto de termcap. Si se omite n, se utiliza un valor predeterminado de 80 caracteres de ancho. Si se especifica n, se establece el ancho en n. Si el ancho es 0, la línea no se romperá.
-W
activa todas las advertencias, incluidas aquellas que se pueden suprimir con otras opciones. (Normalmente solo se muestran las advertencias sobre inconsistencias en el archivo fuente.)
-x
permite la adición de extensiones definidas por el usuario para la base de datos de terminales. Estas extensiones se tratan como capacidades de cadena que contienen expresiones condicionales, por lo que son más flexibles que las capacidades de cadena normales.

ENTRADAS

El archivo de entrada para tic debe estar en el formato descrito en terminfo(5). El archivo puede contener varias entradas de terminal, separadas por el carácter “@”.

EJEMPLOS

Para compilar el archivo my_terminal.src y colocar la salida en la base de datos terminfo predeterminada:

tic my_terminal.src

Para compilar solo las entradas para los terminales `vt100` y `xterm`, y colocar la salida en un directorio específico:

tic -e vt100,xterm -o /usr/local/share/terminfo my_terminal.src

Para verificar la sintaxis de un archivo terminfo sin compilarlo:

tic -c my_terminal.src

Para traducir un archivo termcap a formato terminfo:

tic -C my_terminal.tc

VER TAMBIÉN

infocmp(1M), ncurses(3X), term(5), terminfo(5)

OPTIONS

The tic utility supports the following options:

-0

Use the number 0 as the default number of lines for commands that take a number of lines. For example, use the number 0 for -w.

-1

Use the number 1 as the default number of lines for commands that take a number of lines. For example, use the number 1 for -w.

-a

Append to the terminfo database. Without this option, terminal descriptions are overwritten.

-c

Check the source file for syntax errors, but do not compile it. If the source file contains errors, tic will list them, and exit with a non-zero status. Otherwise, it will exit with status 0.

-C

Translate terminfo source to termcap format.

-en

Use the number n as the default number of lines for commands that take a number of lines. For example, use the number n for -w.

-f

Split long lines when translating from terminfo to termcap format. This is useful for terminals that do not support long lines.

-F

Set the trace level for use with the -v option. The trace level is a number from 0 to 9.

The number of lines is determined by the value of the option's argument:
1
hexadecimal
2
base64
3
hexadecimal and base64
-q
Suppress comments and blank lines when showing translated source.
-Rsubset
Restrict output to a given subset. This option is for use with archaic versions of terminfo like those on SVr1, Ultrix, or HP-UX that do not support the full set of SVR4/XSI Curses terminfo; and outright broken ports like AIX 3.x that have their own extensions incompatible with SVr4/XSI.
Available subsets are
“SVr1”, “Ultrix”, “HP”, “BSD”, and “AIX”
See terminfo(5) for details.
-r
Force entry resolution (so there are no remaining tc capabilities) even when doing translation to termcap format. This may be needed if you are preparing a termcap file for a termcap library (such as GNU termcap through version 1.3 or BSD termcap through 4.3BSD) that does not handle multiple tc capabilities per entry.
-s
Summarize the compile by showing the database location into which entries are written, and the number of entries which are compiled.
-T
eliminates size-restrictions on the generated text. This is mainly useful for testing and analysis, since the compiled descriptions are limited (e.g., 1023 for termcap, 4096 for terminfo).
-t
tells tic to discard commented-out capabilities. Normally when translating from terminfo to termcap, untranslatable capabilities are commented-out.
-U
tells tic to not post-process the data after parsing the source file. Normally, it infers data which is commonly missing in older terminfo data, or in termcaps.
-V
reports the version of ncurses which was used in this program, and exits.
-vn
specifies that (verbose) output be written to standard error trace information showing tic's progress.
The optional parameter n is a number from 1 to 9, inclusive, indicating the desired level of detail of information.
  • If ncurses is built without tracing support, the optional parameter is ignored.
  • If n is omitted, the default level is 1.
  • If n is specified and greater than 1, the level of detail is increased, and the output is written (with tracing information) to the “trace” file.

The debug flag levels are as follows:

1
Names of files created and linked
2
Information related to the “use” facility
3
Statistics from the hashing algorithm
4
Details of extended capabilities
5
(unused)
6
(unused)
7
Entries into the string-table
8
List of tokens encountered by scanner
9
All values computed in construction of the hash table
-W
By itself, the -w option will not force long strings to be wrapped. Use the -W option to do this.
If you specify both -f and -W options, the latter is ignored when -f has already split the line.
-wn
specifies the width of the output. The parameter is optional. If it is omitted, it defaults to 60.
-x
Treat unknown capabilities as user-defined (see user_caps(5)). That is, if you supply a capability name which tic does not recognize, it will infer its type (Boolean, number or string) from the syntax and make an extended table entry for that. User-defined capability strings whose name begins with “k” are treated as function keys.

Parameters

file
contains one or more terminfo terminal descriptions in source format [see terminfo(5)]. Each description in the file describes the capabilities of a particular terminal.
If file is “-”, then the data is read from the standard input. The file parameter may also be the path of a character-device.

Processing

All but one of the capabilities recognized by tic are documented in terminfo(5). The exception is the use capability.

When a use=entry-name field is discovered in a terminal entry currently being compiled, tic reads in the binary from /usr/share/terminfo to complete the entry. (Entries created from file will be used first. tic duplicates the capabilities in entry-name for the current entry, with the exception of those capabilities that explicitly are defined in the current entry.

When an entry, e.g., entry_name_1, contains a use=entry_name_2 field, any canceled capabilities in entry_name_2 must also appear in entry_name_1 before use= for these capabilities to be canceled in entry_name_1.

Total compiled entries cannot exceed 4096 bytes in the legacy storage format, or 32768 using the extended number format. The name field cannot exceed 512 bytes. Terminal names exceeding the maximum alias length (32 characters on systems with long filenames, 14 characters otherwise) will be truncated to the maximum alias length and a warning message will be printed.

FILES

/usr/share/terminfo
compiled terminal description database

NOTES

There is some evidence that historic tic implementations treated description fields with no whitespace in them as additional aliases or short names. This tic does not do that, but it does warn when description fields may be treated that way and check them for dangerous characters.

EXTENSIONS

Unlike the SVr4 tic command, this implementation can actually compile termcap sources. In fact, entries in terminfo and termcap syntax can be mixed in a single source file. See terminfo(5) for the list of termcap names taken to be equivalent to terminfo names.

The SVr4 manual pages are not clear on the resolution rules for use capabilities. This implementation of tic will find use targets anywhere in the source file, or anywhere in the file tree rooted at TERMINFO (if TERMINFO is defined), or in the user's $HOME/.terminfo database (if it exists), or (finally) anywhere in the system's file tree of compiled entries.

The error messages from this tic have the same format as GNU C error messages, and can be parsed by GNU Emacs's compile facility.

Aside from -c and -v, options are not portable:

•
Most of tic's options are not supported by SVr4 tic:
-0 -1 -C -G -I -N -R -T -V -a -e -f -g -o -r -s -t -x
•
The NetBSD tic supports a few of the ncurses options
-a -o -x
and adds -S (a feature which does the same thing as infocmp's -e and -E options).

The SVr4 -c mode does not report bad “use=” links.

System V does not compile entries to or read entries from your $HOME/.terminfo database unless TERMINFO is explicitly set to it.

PORTABILITY

X/Open Curses, Issue 7 (2009) provides a brief description of tic. It lists one option: -c. The omission of -v is unexpected. The change history states that the description is derived from Tru64. According to its manual pages, that system also supported the -v option.

Shortly after Issue 7 was released, Tru64 was discontinued. As of 2019, the surviving implementations of tic are SVr4 (AIX, HP-UX and Solaris), ncurses and NetBSD curses. The SVr4 tic programs all support the -v option. The NetBSD tic program follows X/Open's documentation, omitting the -v option.

The X/Open rationale states that some implementations of tic read terminal descriptions from the standard input if the file parameter is omitted. None of these implementations do that. Further, it comments that some may choose to read from ”./terminfo.src” but that is obsolescent behavior from SVr2, and is not (for example) a documented feature of SVr3.

System V Release 2 provided a tic utility. It accepted a single option: -v (optionally followed by a number). According to Ross Ridge's comment in mytinfo, this version of tic was unable to represent cancelled capabilities.

HISTORIA

Los errores en los enlaces “use=” no se informarían. System V Release 3 documentó algunos mensajes de advertencia que no aparecían en pcurses. Si bien el programa en sí se modificó poco a medida que continuó el desarrollo con System V Release 4, la tabla de capacidades creció de 180 (pcurses) a 464 (Solaris).

En las primeras etapas de desarrollo de ncurses (1993), Zeyd Ben-Halim utilizó la tabla de mytinfo para ampliar la tabla de pcurses a 469 capacidades (456 coincidían con SVr4, 8 eran solo en SVr4, 13 no estaban en SVr4). De esas 13, 11 fueron finalmente descartadas (quizás para que coincidieran con el borrador de X/Open Curses). Las excepciones fueron memory_lock_above y memory_unlock (ver user_caps(5)).

Eric Raymond incorporó partes de mytinfo en ncurses para implementar la conversión de origen termcap a terminfo, y amplió eso para comenzar el desarrollo de la conversión correspondiente de origen terminfo a termcap. Thomas Dickey completó ese desarrollo a lo largo de varios años.

En 1999, Thomas Dickey agregó la opción -x para admitir capacidades definidas por el usuario.

En 2010, Roy Marples proporcionó un programa tic y una biblioteca terminfo para NetBSD. Esa implementación adapta varias características de ncurses, incluida la opción -x de tic.

La opción -c indica a tic que verifique problemas en el archivo fuente terminfo. El desarrollo continuo proporciona verificaciones adicionales:

  • pcurses tenía 8 advertencias
  • ncurses en 1996 tenía 16 advertencias
  • Solaris (SVr4) curses tiene 28 advertencias
  • NetBSD tic en 2019 tiene 19 advertencias.
  • ncurses en 2019 tiene 96 advertencias

La verificación realizada en tic de ncurses ayuda en la conversión a termcap, además de señalar errores e inconsistencias. También se utiliza para garantizar la coherencia con las capacidades definidas por el usuario. Hay 527 capacidades distintas en la base de datos de terminales de ncurses; 128 de ellas están definidas por el usuario.
