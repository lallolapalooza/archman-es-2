tzset(3) Manual de funciones de biblioteca tzset(3)

NOMBRE

tzset, tzname, timezone, daylight — inicializar información de conversión horaria

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <time.h>
void tzset(void);
extern char *tzname[2];
extern long timezone;
extern int daylight;
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

tzset():

    _POSIX_C_SOURCE

tzname:

    _POSIX_C_SOURCE

timezone, daylight:

    _XOPEN_SOURCE
        || /* glibc >= 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE

DESCRIPCIÓN

La función tzset() inicializa la variable tzname a partir de la variable de entorno TZ. Esta función es llamada automáticamente por las otras funciones de conversión horaria que dependen de la zona horaria. En un entorno similar a System-V, también establecerá las variables timezone (segundos al Oeste de UTC) y daylight (a 0 si esta zona horaria no tiene reglas de horario de verano, o a un valor distinto de cero si existe un momento, pasado, presente o futuro en el que se aplica el horario de verano).

La función tzset() inicializa estas variables a valores no especificados si esta zona horaria es una zona horaria geográfica como "America/New_York" (ver abajo).

Si la variable TZ no está presente en el entorno, se usa la zona horaria del sistema. La zona horaria del sistema se configura copiando o enlazando un archivo en formato tzfile(5) a /etc/localtime. Una base de datos de zonas horarias de estos archivos puede estar ubicada en el directorio de zonas horarias del sistema (ver la sección ARCHIVOS abajo).

Si la variable TZ está presente en el entorno, pero su valor está vacío, o su valor no puede ser interpretado usando ninguno de los formatos especificados a continuación, entonces se usa el Tiempo Universal Coordinado (UTC).

Un valor no vacío de TZ puede ser uno de dos formatos, cualquiera de los cuales puede ir precedido por dos puntos (:) que se ignoran. El primer formato es una cadena de caracteres que representa directamente la zona horaria a usar:


std offset[dst[offset][,start[/time],end[/time]]]

No hay espacios en la especificación. La cadena std especifica una abreviatura de la zona horaria y debe tener tres o más caracteres alfabéticos. Cuando se encierra entre los signos menor que (<) y mayor que (>), el conjunto de caracteres se expande para incluir el signo más (+), el signo menos (-) y dígitos. La cadena offset sigue inmediatamente a std y especifica el valor de tiempo que se añadirá a la hora local para obtener el Tiempo Universal Coordinado (UTC). El offset es positivo si la zona horaria local está al oeste del Meridiano de Greenwich y negativo si está al este. La hora debe estar entre 0 y 24, y los minutos y segundos entre 00 y 59:


[+|-]hh[:mm[:ss]]

La cadena dst y el offset especifican el nombre y el desplazamiento para la zona horaria de horario de verano correspondiente. Si se omite el desplazamiento, el valor predeterminado es una hora más que la hora estándar.

Los campos start especifican cuándo entra en vigor el horario de verano y el campo end especifica cuándo se vuelve al horario estándar. Estos campos pueden tener los siguientes formatos:

Jn
Esto especifica el día juliano con n entre 1 y 365. Los días bisiestos no se cuentan. En este formato, el 29 de febrero no se puede representar; el 28 de febrero es el día 59, y el 1 de marzo es siempre el día 60.
n
Esto especifica el día juliano basado en cero con n entre 0 y 365. El 29 de febrero se cuenta en los años bisiestos.
Mm.w.d
Esto especifica el día d (0 <= d <= 6) de la semana w (1 <= w <= 5) del mes m (1 <= m <= 12). La semana 1 es la primera semana en la que ocurre el día d y la semana 5 es la última semana en la que ocurre el día d. El día 0 es un domingo.

Los campos time especifican cuándo, en la hora local actualmente en vigor, ocurre el cambio a la otra hora. Usan el mismo formato que offset excepto que la hora puede estar en el rango [-167,  167] para representar horas antes y después del día nombrado. Si se omite, el valor predeterminado es 02:00:00.

Aquí hay un ejemplo para Nueva Zelanda, donde la hora estándar (NZST) está 12 horas por delante de UTC, y el horario de verano (NZDT), 13 horas por delante de UTC, se aplica desde el último domingo de septiembre, a la hora predeterminada 02:00:00, hasta el primer domingo de abril a las 03:00:00.


TZ="NZST-12:00:00NZDT-13:00:00,M9.5.0,M4.1.0/3"

El segundo —o formato "geográfico"— especifica que la información de la zona horaria debe leerse de un archivo:


filespec

El filespec especifica un archivo en formato tzfile(5) del cual leer la información de la zona horaria. Si filespec no comienza con un '/', la especificación del archivo es relativa al directorio de zonas horarias del sistema. Si el archivo especificado no puede ser leído o interpretado, se usa el Tiempo Universal Coordinado (UTC); sin embargo, las aplicaciones no deben depender de valores de filespec aleatorios que representen UTC, ya que los formatos de TZ pueden extenderse en el futuro.

Aquí hay un ejemplo, una vez más para Nueva Zelanda:


TZ="Pacific/Auckland"

ENTORNO

TZ
Si esta variable está configurada, su valor tiene prioridad sobre la zona horaria configurada en el sistema.
TZDIR
Si esta variable está configurada, su valor tiene prioridad sobre la ruta del directorio de la base de datos de zonas horarias configurada en el sistema.

ARCHIVOS

/etc/localtime
El archivo de zona horaria del sistema.
/usr/share/zoneinfo/
El directorio de la base de datos de zonas horarias del sistema.
/usr/share/zoneinfo/posixrules
Cuando una cadena TZ incluye una zona horaria dst sin nada que le siga, se usa este archivo para las reglas de inicio/fin. Está en formato tzfile(5). Por defecto, el Makefile de zoneinfo lo enlaza simbólicamente al tzfile de America/New_York.

Arriba se encuentran las ubicaciones estándar actuales de los archivos, pero son configurables cuando se compila glibc.

HISTORIA

tzset()
tzname
POSIX.1-1988, SVr4, 4.3BSD.
timezone
daylight
POSIX.1-2001 (XSI), SVr4, 4.3BSD.

4.3BSD tenía una función char *timezone(zone, dst) que devolvía el nombre de la zona horaria correspondiente a su primer argumento (minutos al Oeste de UTC). Si el segundo argumento era 0, se usaba el nombre estándar, de lo contrario, la versión de horario de verano.

ADVERTENCIAS

Dado que los valores de tzname, timezone y daylight a menudo no están especificados, y acceder a ellos puede llevar a un comportamiento indefinido

CAVEATS

In multithreaded applications, code should instead obtain the time zone offset and abbreviations from the tm_gmtoff and tm_zone members of the broken-down time structure tm(3type).

BUGS

Since this function does not report errors, there is no way to know if the value of TZ represents a valid time zone.

VER TAMBIÉN
