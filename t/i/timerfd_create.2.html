NOMBRE

timerfd_create, timerfd_settime, timerfd_gettime - temporizadores que notifican a través de descriptores de archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/timerfd.h>
int timerfd_create(int clockid, int flags);
int timerfd_settime(int fd, int flags,
                    const struct itimerspec *new_value,
                    struct itimerspec *_Nullable old_value);
int timerfd_gettime(int fd, struct itimerspec *curr_value);

DESCRIPCIÓN

Estas llamadas al sistema crean y operan sobre un temporizador que entrega notificaciones de expiración del temporizador a través de un descriptor de archivo. Proporcionan una alternativa al uso de setitimer(2) o timer_create(2), con la ventaja de que el descriptor de archivo puede ser monitoreado por select(2), poll(2) y epoll(7).

El uso de estas tres llamadas al sistema es análogo al uso de timer_create(2), timer_settime(2) y timer_gettime(2). (No hay un análogo de timer_getoverrun(2), ya que esa funcionalidad se proporciona mediante read(2), como se describe a continuación.)

timerfd_create()

timerfd_create() crea un nuevo objeto temporizador y devuelve un descriptor de archivo que se refiere a ese temporizador. El argumento clockid especifica el reloj que se utiliza para marcar el progreso del temporizador y debe ser uno de los siguientes:

CLOCK_REALTIME
Un reloj de tiempo real configurable a nivel de sistema.
CLOCK_MONOTONIC
Un reloj monotónicamente creciente no configurable que mide el tiempo desde algún punto no especificado en el pasado que no cambia después del inicio del sistema.
CLOCK_BOOTTIME (Desde Linux 3.15)
Al igual que CLOCK_MONOTONIC, este es un reloj monotónicamente creciente. Sin embargo, mientras que el reloj CLOCK_MONOTONIC no mide el tiempo mientras un sistema está suspendido, el reloj CLOCK_BOOTTIME sí incluye el tiempo durante el cual el sistema está suspendido. Esto es útil para aplicaciones que necesitan ser conscientes de la suspensión. CLOCK_REALTIME no es adecuado para tales aplicaciones, ya que ese reloj se ve afectado por cambios discontinuos en el reloj del sistema.
CLOCK_REALTIME_ALARM (desde Linux 3.11)
Este reloj es como CLOCK_REALTIME, pero despertará al sistema si está suspendido. El llamador debe tener la capacidad CAP_WAKE_ALARM para configurar un temporizador contra este reloj.
CLOCK_BOOTTIME_ALARM (desde Linux 3.11)
Este reloj es como CLOCK_BOOTTIME, pero despertará al sistema si está suspendido. El llamador debe tener la capacidad CAP_WAKE_ALARM para configurar un temporizador contra este reloj.

Vea clock_getres(2) para más detalles sobre los relojes anteriores.

El valor actual de cada uno de estos relojes se puede obtener usando clock_gettime(2).

A partir de Linux 2.6.27, los siguientes valores se pueden OR-ear bitwise en flags para cambiar el comportamiento de timerfd_create():

TFD_NONBLOCK
Establece el indicador de estado de archivo O_NONBLOCK en la descripción de archivo (ver open(2)) al que se refiere el nuevo descriptor de archivo. Usar esta bandera ahorra llamadas adicionales a fcntl(2) para lograr el mismo resultado.
TFD_CLOEXEC
Establece la bandera de cierre al ejecutar (FD_CLOEXEC) en el nuevo descriptor de archivo. Consulte la descripción de la bandera O_CLOEXEC en open(2) para conocer las razones por las que esto puede ser útil.

En las versiones de Linux hasta la 2.6.26 inclusive, flags debe especificarse como cero.

timerfd_settime()

timerfd_settime() arma (inicia) o desarma (detiene) el temporizador al que se refiere el descriptor de archivo fd.

El argumento new_value especifica la expiración inicial y el intervalo para el temporizador. La estructura itimerspec utilizada para este argumento se describe en itimerspec(3type).

new_value.it_value especifica la expiración inicial del temporizador, en segundos y nanosegundos. Establecer cualquiera de los campos de new_value.it_value a un valor distinto de cero arma el temporizador. Establecer ambos campos de new_value.it_value a cero desarma el temporizador.

Establecer uno o ambos campos de new_value.it_interval a valores distintos de cero especifica el período, en segundos y nanosegundos, para expiraciones repetidas del temporizador después de la expiración inicial. Si ambos campos de new_value.it_interval son cero, el temporizador expira solo una vez, en el momento especificado por new_value.it_value.

Por defecto, el tiempo de expiración inicial especificado en new_value se interpreta en relación con la hora actual en el reloj del temporizador en el momento de la llamada (es decir, new_value.it_value especifica un tiempo relativo al valor actual del reloj especificado por clockid). Se puede seleccionar un tiempo de espera absoluto a través del argumento flags.

El argumento flags es una máscara de bits que puede incluir los siguientes valores:

TFD_TIMER_ABSTIME
Interpreta new_value.it_value como un valor absoluto en el reloj del temporizador. El temporizador expirará cuando el valor del reloj del temporizador alcance el valor especificado en new_value.it_value.
TFD_TIMER_CANCEL_ON_SET
Si se especifica esta bandera junto con TFD_TIMER_ABSTIME y el reloj de este temporizador es CLOCK_REALTIME o CLOCK_REALTIME_ALARM, entonces marque este temporizador como cancelable si el reloj de tiempo real sufre un cambio discontinuo (settimeofday(2), clock_settime(2) o similar). Cuando ocurren tales cambios, una lectura actual o futura de read(2) del descriptor de archivo fallará con el error ECANCELED.

Si el argumento old_value no es NULL, entonces la estructura itimerspec a la que apunta se utiliza para devolver la configuración del temporizador que estaba vigente en el momento de la llamada; vea la descripción de timerfd_gettime() a continuación.

timerfd_gettime()

timerfd_gettime() devuelve, en curr_value, una estructura itimerspec que contiene la configuración actual del temporizador al que se refiere el descriptor de archivo fd.

El campo it_value devuelve la cantidad de tiempo hasta que el temporizador expire la próxima vez. Si ambos campos de esta estructura son cero, entonces el temporizador está actualmente desarmado. Este campo siempre contiene un valor relativo, independientemente de si se especificó la bandera TFD_TIMER_ABSTIME al configurar el temporizador.

El campo it_interval devuelve el intervalo del temporizador. Si ambos campos de esta estructura son cero, entonces el temporizador está configurado para expirar solo una vez, en el momento especificado por curr_value.it_value.

NAME

timerfd_create, timerfd_settime, timerfd_gettime - timer file descriptor facility

SYNOPSIS

#include <sys/timerfd.h>

int timerfd_create(int clockid, int flags);

int timerfd_settime(int fd, int flags,
                    const struct itimerspec *new_value,
                    struct itimerspec *old_value);

int timerfd_gettime(int fd, struct itimerspec *curr_value);

DESCRIPTION

The timerfd_create() function creates a new timerfd file descriptor that will be associated with the timer specified by clockid. The value of clockid can be one of the following:

CLOCK_REALTIME
A system-wide real-time clock that can be set by userspace. See clock_gettime(2).
CLOCK_MONOTONIC
A monotonic clock that never goes backward. It cannot be set by userspace. See clock_gettime(2).
CLOCK_BOOTTIME
(Since Linux 2.6.39) A monotonic clock that includes time elapsed during system suspend. It is not affected by system clock adjustments. See clock_gettime(2).
CLOCK_PROCESS_CPUTIME_ID
(Since Linux 2.6.28) The CPU time of the calling process. See clock_gettime(2).
CLOCK_THREAD_CPUTIME_ID
(Since Linux 2.6.28) The CPU time of the calling thread. See clock_gettime(2).
CLOCK_REALTIME_ALARM
(Since Linux 3.0) A special version of CLOCK_REALTIME that can be used to wake the system from suspend state. Requires the CAP_WAKE_ALARM capability. See clock_gettime(2).
CLOCK_BOOTTIME_ALARM
(Since Linux 3.0) A special version of CLOCK_BOOTTIME that can be used to wake the system from suspend state. Requires the CAP_WAKE_ALARM capability. See clock_gettime(2).

The flags argument specifies characteristics of the timerfd file descriptor. The possible flags are:

TFD_CLOEXEC
Set the close-on-exec flag for the new file descriptor. (See fcntl(2).)
TFD_NONBLOCK
Set the file descriptor to nonblocking mode. (See fcntl(2).)
TFD_SHARED_INC_MAX
(Since Linux 5.11) The timer is created with a shared expiration counter. This flag enables the timer to be used across fork(2) and execve(2) without duplication. See timerfd_create(2).

If flags is 0, then the timerfd file descriptor is created with the close-on-exec flag unset and the file descriptor is opened in blocking mode.

The timerfd_settime() function arms or disarms the timer associated with the file descriptor fd. The new_value argument points to a structure specifying the time when the timer should expire and the interval between successive expirations.

The structure itimerspec is defined as:

struct timespec {
    time_t tv_sec;      /* Seconds */
    long   tv_nsec;     /* Nanoseconds */
};

struct itimerspec {
    struct timespec  it_interval;  /* Interval for periodic timer */
    struct timespec  it_value;     /* Initial expiration time */
};

If new_value.it_interval is nonzero, then the timer is periodic, and its interval is set to the specified time. If new_value.it_interval is zero, then the timer is a non-repeating timer, and it expires only once.

If new_value.it_value is zero, then the timer is disarmed. If new_value.it_value is nonzero, then the timer is armed or rearmed. The time specified in new_value.it_value is the time when the timer should first expire.

The flags argument can be used to modify the behavior of the timer setting. The possible flags are:

TFD_TIMER_ABSTIME
Specifies that the time in new_value.it_value is an absolute time (as measured by the clock specified in clockid when calling timerfd_create()). If this flag is not set, then the time is relative to the current time of the clock.
TFD_TIMER_CANCEL_ON_SET
(Since Linux 2.6.31) If this flag is set, and the timer uses CLOCK_REALTIME or CLOCK_REALTIME_ALARM as its clock, then the timer is automatically canceled if the real-time clock undergoes a discontinuous change (e.g., via clock_settime(2)). See NOTES.

If old_value is not NULL, then it points to a buffer where the previously set timer expiration times and interval are stored. If old_value is NULL, this information is not retrieved.

The timerfd_gettime() function retrieves the "current expiration time" of the timer associated with the file descriptor fd. This time is returned in the buffer pointed to by curr_value. The value returned in curr_value.it_value is the time until the next expiration. If the timer is disarmed, this value is zero. If curr_value.it_interval is zero, then the timer is a non-repeating timer.

read(2) semantics

read(2)
If the timer has already expired one or more times since its settings were last modified using timerfd_settime(), or since the last successful read(2), then the buffer given to read(2) returns an unsigned 8-byte integer (uint64_t) containing the number of expirations that have occurred. (The returned value is in host byte order—that is, the native byte order for integers on the host machine.)
If no timer expirations have occurred at the time of the read(2), then the call either blocks until the next timer expiration, or fails with the error EAGAIN if the file descriptor has been made nonblocking (via the use of the fcntl(2) F_SETFL operation to set the O_NONBLOCK flag).
A read(2) fails with the error EINVAL if the size of the supplied buffer is less than 8 bytes.
If the associated clock is either CLOCK_REALTIME or CLOCK_REALTIME_ALARM, the timer is absolute (TFD_TIMER_ABSTIME), and the flag TFD_TIMER_CANCEL_ON_SET was specified when calling timerfd_settime(), then read(2) fails with the error ECANCELED if the real-time clock undergoes a discontinuous change. (This allows the reading application to discover such discontinuous changes to the clock.)
If the associated clock is either CLOCK_REALTIME or CLOCK_REALTIME_ALARM, the timer is absolute (TFD_TIMER_ABSTIME), and the flag TFD_TIMER_CANCEL_ON_SET was not specified when calling timerfd_settime(), then a discontinuous negative change to the clock (e.g., clock_settime(2)) may cause read(2) to unblock, but return a value of 0 (i.e., no bytes read), if the clock change occurs after the time expired, but before the read(2) on the file descriptor.
poll(2)
select(2)
(and similar)
The file descriptor is readable (the select(2) readfds argument; the poll(2) POLLIN flag) if one or more timer expirations have occurred.
The file descriptor also supports the other file-descriptor multiplexing APIs: pselect(2), ppoll(2), and epoll(7).
ioctl(2)
The following timerfd-specific command is supported:
TFD_IOC_SET_TICKS (since Linux 3.17)
Adjust the number of timer expirations that have occurred. The argument is a pointer to a nonzero 8-byte integer (uint64_t*) containing the new number of expirations. Once the number is set, any waiter on the timer is woken up. The only purpose of this command is to restore the expirations for the purpose of checkpoint/restore. This operation is available only if the kernel was configured with the CONFIG_CHECKPOINT_RESTORE option.
close(2)
When the file descriptor is no longer required it should be closed. When all file descriptors associated with the same timer object have been closed, the timer is disarmed and its resources are freed by the kernel.

fork(2) semantics

After a fork(2), the child inherits a copy of the file descriptor created by timerfd_create(). The file descriptor refers to the same underlying timer object as the corresponding file descriptor in the parent, and read(2)s in the child will return information about expirations of the timer.

execve(2) semantics

A file descriptor created by timerfd_create() is preserved across execve(2), and continues to generate timer expirations if the timer was armed.

RETURN VALUE

On success, timerfd_create() returns a new file descriptor. On error, -1 is returned and errno is set to indicate the error.

timerfd_settime() and timerfd_gettime() return 0 on success; on error they return -1, and set errno to indicate the error.

ERRORS

timerfd_create() can fail with the following errors:

EINVAL
The clockid is not valid.
EINVAL
flags is invalid; or, in Linux 2.6.26 or earlier, flags is nonzero.
EMFILE
The per-process limit on the number of open file descriptors has been reached.
ENFILE
The system-wide limit on the total number of open files has been reached.
ENODEV
Could not mount (internal) anonymous inode device.
ENOMEM
There was insufficient kernel memory to create the timer.
EPERM
clockid was CLOCK_REALTIME_ALARM or CLOCK_BOOTTIME_ALARM but the caller did not have the CAP_WAKE_ALARM capability.

timerfd_settime() and timerfd_gettime() can fail with the following errors:

EBADF
fd is not a valid file descriptor.
EFAULT
new_value, old_value, or curr_value is not a valid pointer.
EINVAL
fd is not a valid timerfd file descriptor.

timerfd_settime() can also fail with the following errors:

ECANCELED
See NOTES.
EINVAL
new_value is not properly initialized (one of the tv_nsec falls outside the range zero to 999,999,999).
EINVAL
flags is invalid.

STANDARDS

Linux.

HISTORY

Linux 2.6.25, glibc 2.8.

NOTES

Suppose the following scenario for CLOCK_REALTIME or CLOCK_REALTIME_ALARM timer that was created with timerfd_create():

(1)
The timer has been started (timerfd_settime()) with the TFD_TIMER_ABSTIME and TFD_TIMER_CANCEL_ON_SET flags;
(2)
A discontinuous change (e.g., settimeofday(2)) is subsequently made to the CLOCK_REALTIME clock; and
(3)
the caller once more calls timerfd_settime() to rearm the timer (without first doing a read(2) on the file descriptor).

In this case the following occurs:

•
The timerfd_settime() returns -1 with errno set to ECANCELED. (This enables the caller to know that the previous timer was affected by a discontinuous change to the clock.)
•
The timer is successfully rearmed with the settings provided in the second timerfd_settime() call. (This was probably an implementation accident, but won't be fixed now, in case there are applications that depend on this behaviour.)

BUGS

Currently, timerfd_create() supports fewer types of clock IDs than timer_create(2).

NAME

timerfd_create, timerfd_settime, timerfd_gettime — Linux timerfd API

LIBRARY

librt (part of libc, hence not strictly necessary to link with librt )

SYNOPSIS 

#include <sys/timerfd.h>

int timerfd_create(int clockid, int flags);

int timerfd_settime(int fd, int flags,
                   const struct itimerspec *new_value,
                   struct itimerspec *old_value);

int timerfd_gettime(int fd, struct itimerspec *curr_value);

DESCRIPTION

The timerfd interface provides a mechanism to timer manage timers using a file descriptor. This allows applications to multiplex timer events along with other I/O events using mechanisms like select(2), poll(2), and epoll(7).

The timerfd_create function creates a new timerfd file descriptor, which is used to perform timer operations. The clockid argument specifies the clock ID to be used for the timer. This can be one of the clock IDs described in clock_gettime(2) (e.g., CLOCK_REALTIME or CLOCK_MONOTONIC). The flags argument is initially 0.

The timerfd_settime function arms or disarms a timer associated with the file descriptor fd. The new_value argument specifies the time when the timer should expire. The flags argument can be 0 or TFD_TIMER_ABSTIME. If TFD_TIMER_ABSTIME is set, then new_value.it_value is interpreted as an absolute time (in the clock specified during timerfd_create). Otherwise, it specifies a relative time.

The structure itimerspec is defined as:

struct itimerspec {
    struct timespec it_interval;  /* Interval for periodic timer */
    struct timespec it_value;     /* Initial expiration time */
};

If old_value is not NULL, then it is set to the previous settings of the timer.

The timerfd_gettime function retrieves the time of the next expiration of the timer associated with the file descriptor fd. The current settings are returned in curr_value.

When a timer expires, the system decrements the remaining time by the interval specified in new_value.it_interval. If new_value.it_interval is zero, the timer is disarmed after the current expiration. If the timer expires when it is already running, the expiration event is lost.

When a timer expires, a count of timer expirations is incremented. This count is stored in the timerfd file descriptor. Each successful read(2) call on the timerfd returns the number of expirations that have occurred since the last read. The number of bytes read is 8 (the size of uint64_t).

If the timerfd is used with poll(2), select(2), or epoll(7), the file descriptor will be marked as ready for reading when the timer expires.

RETURN VALUE

On success, timerfd_create returns a new file descriptor. On failure, -1 is returned, and errno is set appropriately.

On success, timerfd_settime and timerfd_gettime return 0. On failure, they return -1, and errno is set appropriately.

ERRORS

EINVAL

timerfd_create : The value specified by clockid is not supported.

timerfd_settime : Invalid value in new_value (e.g., negative time values).

EBADFD

timerfd_settime or timerfd_gettime : fd is not a valid timerfd file descriptor.

EINTR

timerfd_settime : The call was interrupted by a signal.

STANDARDS

This interface is Linux-specific.

HISTORY

The timerfd interface was introduced in Linux kernel 2.6.27.

NOTES

The timerfd file descriptors are nonblocking by default.

The maximum number of timerfd file descriptors is limited by the RLIMIT_NOFILE resource limit.

The timer associated with a timerfd file descriptor is not affected by fork(2).

BUGS

There are no known bugs.

EXAMPLES

// Example from man page, slightly modified to compile
#define _GNU_SOURCE
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <err.h>
#include <sys/timerfd.h>
#include <unistd.h>
#include <inttypes.h> // For PRIu64

/* Helper function to print elapsed time since program start */
static void print_elapsed_time(void)
{
    static struct timespec start = {0, 0};
    struct timespec curr;
    long secs, nsecs;
    if (start.tv_sec == 0) {
        if (clock_gettime(CLOCK_MONOTONIC, &start) == -1)
            err(EXIT_FAILURE, "clock_gettime");
    }
    if (clock_gettime(CLOCK_MONOTONIC, &curr) == -1)
        err(EXIT_FAILURE, "clock_gettime");
    secs = curr.tv_sec - start.tv_sec;
    nsecs = curr.tv_nsec - start.tv_nsec;
    if (nsecs < 0) {
        secs--;
        nsecs += 1000000000;
    }
    printf("%d.%03d:\t", secs, (nsecs + 500000) / 1000000);
}
int
main(int argc, char *argv[])
{
    int                fd;
    ssize_t            s;
    uint64_t           expir, tot_expir, max_expir;
    struct timespec    now;
    struct itimerspec  new_value;
    if (argc != 2 && argc != 4) {
        fprintf(stderr, "%s init-secs [interval-secs max-num-expir]\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }
    if (clock_gettime(CLOCK_REALTIME, &now) == -1)
        err(EXIT_FAILURE, "clock_gettime");
    /* Create a CLOCK_REALTIME absolute timer with initial
       expiration and interval as specified in command line.  */
    new_value.it_value.tv_sec = now.tv_sec + atoi(argv[1]);
    new_value.it_value.tv_nsec = now.tv_nsec;
    if (argc == 2) {
        new_value.it_interval.tv_sec = 0;
        max_expir = 1;
    } else {
        new_value.it_interval.tv_sec = atoi(argv[2]);
        max_expir = atoi(argv[3]);
    }
    new_value.it_interval.tv_nsec = 0;
    fd = timerfd_create(CLOCK_REALTIME, 0);
    if (fd == -1)
        err(EXIT_FAILURE, "timerfd_create");
    if (timerfd_settime(fd, TFD_TIMER_ABSTIME, &new_value, NULL) == -1)
        err(EXIT_FAILURE, "timerfd_settime");
    print_elapsed_time();
    printf("timer started\n");
    for (tot_expir = 0; tot_expir < max_expir;) {
        s = read(fd, &expir, sizeof(uint64_t));
        if (s != sizeof(uint64_t))
            err(EXIT_FAILURE, "read");
        tot_expir += expir;
        print_elapsed_time();
        printf("read: %" PRIu64 "; total=% " PRIu64 "\n",
               expir, tot_expir);
    }
    exit(EXIT_SUCCESS);
}
