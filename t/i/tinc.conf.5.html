TINC.CONF(5) Manual de formatos de archivo TINC.CONF(5)

NOMBRE

tinc.conf — configuración del demonio tinc

DESCRIPCIÓN

Los archivos en el directorio /etc/tinc/ contienen información de tiempo de ejecución y de seguridad para el demonio tinc.

REDES

Es perfectamente aceptable ejecutar más de un demonio tinc. Sin embargo, en su forma predeterminada, pronto notará que no puede usar dos archivos de configuración diferentes sin la opción -c.

Hemos pensado en otra forma de manejar esto: nombres de red. Esto significa que llama a tinc.conf con la opción -n, que asignará un nombre a este demonio.

El efecto de esto es que el demonio establecerá su raíz de configuración en /etc/tinc/NOMBRE_RED/, donde NOMBRE_RED es su argumento para la opción -n. Notará que los mensajes aparecen en syslog como provenientes de tincd.NOMBRE_RED.

Sin embargo, no es estrictamente necesario llamar a tinc con la opción -n. En este caso, el nombre de red estaría vacío, y se usaría como tal. tinc ahora busca archivos en /etc/tinc/, en lugar de /etc/tinc/NOMBRE_RED/; el archivo de configuración debería ser /etc/tinc/tinc.conf, y ahora se espera que los archivos de configuración de host estén en /etc/tinc/hosts/.

Pero es muy recomendable que use esta característica de tinc, ya que será mucho más claro con quién habla su demonio. Por lo tanto, asumiremos que la usa.

NOMBRES

Cada demonio tinc debe tener un nombre que sea único en la red de la que formará parte. El nombre será utilizado por otros demonios tinc para identificación. El nombre debe declararse en el archivo /etc/tinc/NOMBRE_RED/tinc.conf.

Para facilitar las cosas, elija algo que proporcione nombres únicos y fáciles de recordar a su(s) demonio(s) tinc. Podría intentar cosas como nombres de host, apellidos del propietario o nombres de ubicación.

CLAVES PÚBLICAS/PRIVADAS

Debería usar tincd -K para generar pares de claves públicas/privadas. Generará dos claves. La clave privada debe almacenarse en un archivo separado /etc/tinc/NOMBRE_RED/rsa_key.priv — donde NOMBRE_RED representa la red (ver REDES arriba). La clave pública debe almacenarse en el archivo de configuración del host /etc/tinc/NOMBRE_RED/hosts/NOMBRE — donde NOMBRE representa el nombre del demonio tinc local (ver NOMBRES).

CONFIGURACIÓN DEL SERVIDOR

La configuración del servidor del demonio se realiza en el archivo /etc/tinc/NOMBRE_RED/tinc.conf. Este archivo consta de comentarios (líneas que comienzan con un #) o asignaciones en la forma:

Variable = Valor.

Los nombres de las variables no distinguen entre mayúsculas y minúsculas, y se ignoran los espacios, tabulaciones, saltos de línea y retornos de carro. Nota: no es obligatorio poner el signo =, pero hacerlo mejora la legibilidad. Si lo omite, recuerde reemplazarlo con al menos un carácter de espacio.

La configuración del servidor se complementa con la configuración específica del host (ver la siguiente sección). Aunque todas las opciones de configuración para el host local que se enumeran en este documento también se pueden poner en /etc/tinc/NOMBRE_RED/tinc.conf, se recomienda poner las opciones de configuración específicas del host en el archivo de configuración del host, ya que esto facilita el intercambio con otros nodos.

Aquí están todas las variables válidas, enumeradas en orden alfabético. El valor predeterminado se indica entre paréntesis.

AddressFamily = ipv4 | ipv6 | any (any)
Esta opción afecta la familia de direcciones de los sockets de escucha y salida. Si se selecciona "any", dependiendo del sistema operativo se crearán sockets de escucha IPv4 e IPv6 o solo IPv6.
BindToAddress = dirección [puerto] [experimental]
Si su computadora tiene más de una dirección IPv4 o IPv6, tinc escuchará de forma predeterminada en todas ellas para conexiones entrantes. Se pueden especificar múltiples variables BindToAddress, en cuyo caso se crean sockets de escucha para cada dirección especificada.

Si no se especifica ningún puerto, el socket se vinculará al puerto especificado por la opción Port, o al puerto 655 si no se proporciona ninguno. Para vincularse solo a un puerto específico pero no a una dirección específica, use * para la dirección.

Esta opción puede no funcionar en todas las plataformas.

BindToInterface = interfaz [experimental]
Si su computadora tiene más de una interfaz de red, tinc escuchará de forma predeterminada en todas ellas para conexiones entrantes. Es posible vincularse solo a una interfaz única con esta variable.

Esta opción puede no funcionar en todas las plataformas. Además, en algunas plataformas no se vinculará realmente a una interfaz, sino a la dirección que tenga la interfaz en el momento en que se cree un socket.

Broadcast = no | mst | direct (mst) [experimental]
Esta opción selecciona la forma en que los paquetes de broadcast se envían a otros demonios. NOTA: todos los nodos de una VPN deben usar el mismo modo Broadcast, de lo contrario se pueden formar bucles de enrutamiento.
no
Los paquetes de broadcast nunca se envían a otros nodos.
mst
Los paquetes de broadcast se envían y reenvían a través del Árbol Expansor Mínimo (Minimum Spanning Tree) de la VPN. Esto asegura que los paquetes de broadcast lleguen a todos los nodos.
direct
Los paquetes de broadcast se envían directamente a todos los nodos a los que se puede acceder directamente. Los paquetes de broadcast recibidos de otros nodos nunca se reenvían. Si la opción IndirectData también está configurada, los paquetes de broadcast solo se enviarán a los nodos con los que tengamos una conexión meta.
ConnectTo = nombre
Especifica a qué otro demonio tinc conectarse al inicio. Se pueden especificar múltiples variables ConnectTo, en cuyo caso se establecen conexiones salientes a cada demonio tinc especificado. Los nombres deben ser conocidos por este demonio tinc (es decir, debe haber un archivo de configuración de host para el nombre en la línea ConnectTo).

Si no especifica un host con ConnectTo, tinc no intentará conectarse a otros demonios en absoluto, y en su lugar solo escuchará conexiones entrantes.

DecrementTTL = yes | no (no) [experimental]
Cuando está habilitado, tinc decrementará el campo Time To Live en los paquetes IPv4, o el campo Hop Limit en los paquetes IPv6, antes de reenviar un paquete recibido al dispositivo de red virtual o a otro nodo, y descartará los paquetes que tengan un valor TTL de cero, en cuyo caso enviará un paquete ICMP Time Exceeded de vuelta.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

>No utilice esta opción si usa el modo switch y desea utilizar IPv6.

Device = dispositivo ( /dev/tap0, /dev/net/tun o similar según la plataforma)
El dispositivo de red virtual a utilizar. tinc detectará automáticamente qué tipo de dispositivo es. Tenga en cuenta que solo puede utilizar un dispositivo por demonio. En Windows, utilice Interface en lugar de Device. Las páginas informativas del paquete tinc contienen más información sobre cómo configurar el dispositivo de red virtual.
DeviceType = tipo (depende de la plataforma)
El tipo de dispositivo de red virtual. Tinc normalmente seleccionará automáticamente el tipo correcto de interfaz tun/tap, y esta opción no debe utilizarse. Sin embargo, esta opción se puede utilizar para seleccionar uno de los tipos de interfaz especiales, si se ha compilado con soporte para ellos.
dummy
Utiliza una interfaz dummy. Nunca se leen ni se escriben paquetes en un dispositivo de red virtual. Útil para pruebas, o al configurar un nodo que solo reenvía paquetes para otros nodos.
raw_socket
Abre un socket crudo y lo vincula a una Interface preexistente (eth0 por defecto). Todos los paquetes se leen de esta interfaz. Los paquetes recibidos para el nodo local se escriben en el socket crudo. Sin embargo, al menos en Linux, el sistema operativo no procesa los paquetes IP destinados al host local.
multicast
Abre un socket UDP multicast y lo vincula a la dirección y puerto (separados por espacios) y opcionalmente a un valor TTL especificado con Device. Los paquetes se leen y se escriben en este socket multicast. Esto se puede utilizar para conectarse a instancias UML, QEMU o KVM que escuchen en la misma dirección multicast. NO conecte múltiples demonios tinc a la misma dirección multicast, esto probablemente causará bucles de enrutamiento. Tenga en cuenta también que esto puede causar que los paquetes VPN descifrados se envíen a través de una red real si se configura incorrectamente.
uml (no compilado por defecto)
Crea un socket UNIX con el nombre de archivo especificado por Device, o /var/run/NETNAME.umlsocket si no se especifica. tinc esperará a que una instancia de User Mode Linux se conecte a este socket.
vde (no compilado por defecto)
Utiliza la biblioteca libvdeplug para conectarse a un switch Ethernet distribuido virtual, utilizando el socket UNIX especificado por Device, o /var/run/vde.ctl si no se especifica.
Además, en caso de que tinc no parezca interpretar correctamente los paquetes recibidos del dispositivo de red virtual, se puede usar para cambiar la forma en que se interpretan los paquetes:
tun (BSD y Linux)
Establece el tipo en tun. Dependiendo de la plataforma, esto puede ser con o sin un encabezado de familia de direcciones (ver abajo).
tunnohead (BSD)
Establece el tipo en tun sin un encabezado de familia de direcciones. Tinc esperará que los paquetes leídos del dispositivo de red virtual comiencen con un encabezado IP. En algunas plataformas, los paquetes IPv6 no se pueden leer ni escribir desde el dispositivo en este modo.
tunifhead (BSD)
Establece el tipo en tun con un encabezado de familia de direcciones. Tinc esperará que los paquetes leídos del dispositivo de red virtual comiencen con un encabezado de cuatro bytes que contenga la familia de direcciones, seguido de un encabezado IP. Este modo debería soportar paquetes IPv4 e IPv6.
utun (OS X)
Establece el tipo en utun. Esto solo es compatible con OS X versión 10.6.8 y superior, pero no requiere el módulo tuntaposx. Este modo debería soportar paquetes IPv4 e IPv6.
tap (BSD y Linux)
Establece el tipo en tap. Tinc esperará que los paquetes leídos del dispositivo de red virtual comiencen con un encabezado Ethernet.
DirectOnly = yes | no (no) [experimental]
Cuando esta opción está habilitada, los paquetes que no se pueden enviar directamente al nodo de destino, pero que tendrían que ser reenviados por un nodo intermedio, se descartan en su lugar. Cuando se combina con la opción IndirectData, los paquetes para nodos con los que no tenemos una conexión meta también se descartan.
Forwarding = off | internal | kernel (internal) [experimental]
Esta opción selecciona la forma en que se reenvían los paquetes indirectos.
off
Los paquetes entrantes que no son para el nodo local, pero que deberían reenviarse a otro nodo, se descartan.
internal
Los paquetes entrantes destinados a otro nodo son reenviados internamente por tinc.

Este es el modo predeterminado y, a menos que realmente sepa que necesita otro modo de reenvío, no lo cambie.

kernel
Los paquetes entrantes siempre se envían al dispositivo TUN/TAP, incluso si los paquetes no son para el nodo local. Esto es menos eficiente, pero permite que el kernel aplique sus reglas de enrutamiento y firewall sobre ellos, y también puede ayudar a depurar.
GraphDumpFile = nombre_archivo [experimental]
Si esta opción está presente, tinc volcará el grafo de red actual al archivo nombre_archivo cada minuto, a menos que no haya habido cambios en el grafo. El archivo está en un formato que pueden leer las herramientas de graphviz. Si nombre_archivo comienza con un símbolo de pipe |, entonces el resto del nombre de archivo se interpreta como un comando de shell que se ejecuta, y el grafo se envía a stdin.
Hostnames = yes | no (no)
Esta opción selecciona si las direcciones IP (tanto reales como en la VPN) deben resolverse. Dado que las búsquedas de DNS bloquean, puede afectar la eficiencia de tinc, incluso deteniendo el demonio durante unos segundos cada vez que realiza una búsqueda si su servidor DNS no responde.

Esto no afecta la resolución de nombres de host a direcciones IP de los archivos de configuración del host, sino si los nombres de host deben resolverse durante el registro.

IffOneQueue = yes | no (no) [experimental]
(Solo Linux) Establece la bandera IFF_ONE_QUEUE en los dispositivos TUN/TAP.
Interface = interfaz
Define el nombre de la interfaz correspondiente al dispositivo de red virtual. Dependiendo del sistema operativo y del tipo de dispositivo, esto puede o no establecer el nombre de la interfaz. En Windows, esta variable se utiliza para seleccionar qué interfaz de red se utilizará. Si especificó un Device, esta variable casi siempre ya está correctamente configurada.
KeyExpire = segundos (3600)
Esta opción controla el período de validez de las claves de cifrado utilizadas para cifrar los datos. Es práctica común cambiar las claves a intervalos regulares para dificultar aún más a los crackers, aunque se considera casi imposible descifrar una sola clave.
LocalDiscovery = yes | no (no) [experimental]
Cuando está habilitado, tinc intentará detectar peers que se encuentran en la misma red local. Esto permitirá la comunicación directa utilizando direcciones LAN, incluso si ambos peers están detrás de un NAT y solo se conectan a un tercer nodo fuera del NAT, lo que normalmente evitaría que los peers conozcan la dirección LAN del otro.

Actualmente, el descubrimiento local se implementa enviando paquetes de difusión a la LAN durante la detección de MTU de ruta. Esta característica puede no funcionar en todas las situaciones posibles.

MACExpire = segundos (600)
Esta opción controla el tiempo que se conservan las direcciones MAC antes de eliminarlas. Esto solo tiene efecto cuando Mode está configurado como "switch".
MaxTimeout = segundos (900)
Este es el retraso máximo antes de intentar reconectarse a otros demonios tinc.
Mode = router | switch | hub (router)
Esta opción selecciona la forma en que se enrutan los paquetes a otros demonios.
router
En este modo, las variables Subnet en los archivos de configuración del host se utilizarán para formar una tabla de enrutamiento. En este modo solo se admiten paquetes unicast de protocolos enrutable (IPv4 e IPv6).

Este es el modo predeterminado y, a menos que realmente sepa que necesita otro modo, no lo cambie.

switch
En este modo, las direcciones MAC de los paquetes en la VPN se utilizarán para crear dinámicamente una tabla de enrutamiento, de manera similar a como lo hace un switch Ethernet. Se admiten paquetes unicast, multicast y broadcast de todos los protocolos que se ejecutan sobre Ethernet, a costa de frecuentes solicitudes ARP de difusión y actualizaciones de la tabla de enrutamiento.

Este modo es útil principalmente si desea conectar segmentos Ethernet.

hub
Este modo es casi idéntico al modo switch, pero en lugar de eso, cada paquete se transmitirá a los otros demonios mientras no se administre ninguna tabla de enrutamiento.
Name = nombre [requerido]
Este es el nombre que identifica a este demonio tinc. Debe ser único para la red privada virtual a la que se conectará este demonio. El Nombre solo puede contener caracteres alfanuméricos y de guion bajo. Si Name comienza con un signo $,
entonces se utilizarán los contenidos de la variable de entorno que le sigue. En ese caso, los caracteres no válidos se convertirán en guiones bajos. Si Name es $HOST, pero no existe dicha variable de entorno, el nombre del host se leerá utilizando la llamada al sistema gethostname().
PingInterval = segundos (60)
El número de segundos de inactividad que tinc esperará antes de enviar una sonda al otro extremo.
PingTimeout = segundos (5)
El número de segundos de espera para una respuesta a los pings o para permitir que las conexiones meta se bloqueen. Si el otro extremo no responde dentro de este tiempo, la conexión se terminará y se notificará a los demás.
PriorityInheritance = yes | no (no) [experimental]
Cuando esta opción está habilitada, el valor del campo TOS de los paquetes IPv4 tunelizados se heredará por los paquetes UDP que se envíen.
PrivateKey = clave [obsoleto]
La clave RSA privada de este demonio de tinc. Permitirá a este demonio de tinc autenticarse ante otros demonios.
PrivateKeyFile = nombre_archivo (/etc/tinc/NETNAME/rsa_key.priv)
El archivo donde reside la clave RSA privada de este demonio de tinc.
ProcessPriority = low | normal | high
Cuando se utiliza esta opción, la prioridad del proceso tincd se ajustará. Aumentar la prioridad puede ayudar a reducir la latencia y la pérdida de paquetes en la VPN.
Proxy = socks4 | socks5 | http | exec ... [experimental]
Utiliza un proxy al realizar conexiones salientes. Actualmente se soportan los siguientes tipos de proxy:
socks4 direccion puerto [nombre_usuario]
Se conecta al proxy utilizando el protocolo SOCKS versión 4. Opcionalmente, se puede proporcionar un nombre_usuario que se pasará al servidor proxy. Solo las conexiones IPv4 pueden ser proxificadas usando SOCKS 4.
socks5 direccion puerto [nombre_usuario contraseña]
Se conecta al proxy utilizando el protocolo SOCKS versión 5. Si se proporcionan un nombre_usuario y una contraseña, se utilizará autenticación básica de nombre de usuario/contraseña, de lo contrario, no se utilizará ninguna autenticación.
http direccion puerto
Se conecta al proxy y envía una solicitud HTTP CONNECT.
exec comando
Ejecuta el comando dado, que debe establecer la conexión saliente. Las variables de entorno NAME, NODE, REMOTEADDRES y REMOTEPORT están disponibles.
ReplayWindow = bytes (16)
Este es el tamaño de la ventana de seguimiento de reproducción para cada nodo remoto, en bytes. La ventana es un campo de bits que rastrea 1 paquete por bit, por lo que, por ejemplo, la configuración predeterminada de 16 rastreará hasta 128 paquetes en la ventana. En escenarios de alto ancho de banda, establecer un valor más alto puede reducir la pérdida de paquetes debido a la interacción del seguimiento de reproducción con la pérdida de paquetes subyacente y/o la reordenación. Establecer esto en cero deshabilitará completamente el seguimiento de reproducción y pasará todo el tráfico, pero dejará a tinc vulnerable a ataques de reproducción en su tráfico.
StrictSubnets = yes | no (no) [experimental]
Cuando esta opción está habilitada, tinc solo usará las declaraciones de Subred que estén presentes en los archivos de configuración del host en el directorio local /etc/tinc/NETNAME/hosts/. Las subredes aprendidas a través de conexiones a otros nodos y que no estén presentes en los archivos de configuración locales del host se ignorarán.
TunnelServer = yes | no (no) [experimental]
Cuando esta opción está habilitada, tinc ya no reenviará información entre otros demonios de tinc, y solo permitirá conexiones con nodos para los cuales existan archivos de configuración de host en el directorio local /etc/tinc/NETNAME/hosts/. Establecer esta opción también establece implícitamente StrictSubnets.
UDPRcvBuf = bytes (predeterminado del SO)
Establece el tamaño del búfer de recepción del socket para el socket UDP, en bytes. Si no se establece, el sistema operativo utilizará el tamaño de búfer predeterminado.
UDPSndBuf = bytes (predeterminado del SO)
Establece el tamaño del búfer de envío del socket para el socket UDP, en bytes. Si no se establece, el sistema operativo utilizará el tamaño de búfer predeterminado.

ARCHIVOS DE CONFIGURACIÓN DE HOST

Los archivos de configuración de host contienen toda la información necesaria para establecer una conexión con esos hosts. También se requiere un archivo de configuración de host para el demonio de tinc local, lo utilizará para leer su puerto de escucha, clave pública y subredes.

La idea es que estos archivos sean portátiles. Puede enviar de forma segura su propio archivo de configuración de host a otra persona. Esa otra persona puede copiarlo a su propio directorio de hosts, y entonces su demonio de tinc podrá conectarse a su demonio de tinc. Dado que los archivos de configuración de host solo contienen claves públicas, no se revelan secretos al enviar esta información.

Address = direccion [puerto] [recomendado]
La dirección IP o el nombre de host de este demonio de tinc en la red real. Esto solo se utilizará al intentar establecer una conexión saliente a este demonio de tinc. Opcionalmente, se puede especificar un puerto para usar en esta dirección. Se pueden especificar múltiples variables de Address, en cuyo caso se intentará cada dirección hasta que se establezca una conexión funcional.
Cipher = cifrado (aes-256-cbc)
El algoritmo de cifrado simétrico utilizado para cifrar paquetes UDP. Se reconocen todos los cifrados soportados por LibreSSL u OpenSSL. Además, especificar "none" deshabilitará el cifrado de paquetes. Es mejor usar solo aquellos cifrados que soporten el modo CBC.
ClampMSS = yes | no (yes)
Esta opción especifica si tinc debe limitar el tamaño máximo de segmento (MSS) de los paquetes TCP a la MTU de ruta. Esto ayuda en situaciones donde los mensajes ICMP Fragmentation Needed o Packet too Big son descartados por los firewalls.
Compression = nivel (0)
Esta opción establece el nivel de compresión utilizado para los paquetes UDP. Los valores posibles son 0 (apagado), 1 (zlib rápido) y cualquier entero hasta 9 (zlib mejor), 10 (lzo rápido) y 11 (lzo mejor).
Digest = digest (sha256)
El algoritmo de digest (resumen) utilizado para autenticar paquetes UDP. Se reconocen todos los digests soportados por LibreSSL u OpenSSL. Además, especificar "none" deshabilitará la autenticación de paquetes.
IndirectData = yes | no (no)
Cuando se establece en sí, solo los nodos que ya tienen una conexión meta contigo intentarán establecer comunicación directa contigo. Es mejor dejar esta opción fuera o establecerla en no.
MACLength = longitud (4)
La longitud del código de autenticación de mensajes utilizado para autenticar paquetes UDP. Puede ser cualquier valor desde "0" hasta la longitud del digest producido por el algoritmo de digest.
PMTU = mtu (1514)
Esta opción controla la MTU de ruta inicial a este nodo.
PMTUDiscovery = yes | no (yes)
Cuando esta opción está habilitada, tinc intentará descubrir la MTU de ruta a este nodo. Después de descubrir la MTU de ruta, se aplicará en la VPN.
Port = puerto (655)
El número de puerto en el que este demonio de tinc escucha las conexiones entrantes, que se utiliza si no se especifica un número de puerto en una declaración de Address.
PublicKey = clave [obsoleto]
La clave RSA pública de este demonio de tinc. Se utilizará para verificar criptográficamente su identidad y para establecer una conexión segura.
PublicKeyFile = nombre_archivo [obsoleto]
El archivo donde reside la clave RSA pública de este demonio de tinc.

A partir de la versión 1.0pre4, tinc almacenará la clave pública directamente en el archivo de configuración del host en formato PEM, por lo que las dos opciones anteriores ya no son necesarias. O bien se usa el formato PEM, o bien se debe especificar exactamente una de las dos opciones anteriores en cada archivo de configuración del host, si se quiere poder esta

NAME

tinc

manual page for tinc

DESCRIPTION

tinc is a virtual private network daemon.

NETWORKS

The following configuration variables can be set in tinc.conf, or in host configuration files.

Name
The name of this tinc daemon. This name is used in the host configuration files to identify this daemon.
Device
The name of the virtual network device to create. This defaults to NETNAME, where NETNAME is the name of the network. E.g. for the network myvpn, the device will be myvpn.
Mode
Can be router or switch.

If set to router (the default), tinc will set up a routed network. This means that tinc will advertise your subnets to other nodes, and will try to route packets to them. This requires that you have a working IP routing setup on your kernel.

If set to switch, tinc will set up an Ethernet switch. This means that tinc will learn the MAC addresses of the hosts and bridge them together. This is useful for networks that don't use IP, or for running protocols like OSPF or DHCP that don't work well with routing.

ListenPort
The UDP port to listen on for incoming connections. If not specified, tinc will not listen for incoming connections. This is useful for nodes that only initiate connections themselves.
TunnelEndpoint
This option can be specified multiple times to specify a list of nodes to connect to. tinc will try to connect to all listed nodes. This is useful for setting up a VPN network where not all nodes know about each other.

A TunnelEndpoint can be specified as address:port or hostname:port. If the port is omitted, the default port (64295) is used. If you want to use hostnames, you need to make sure that DNS is working correctly.

For example: TunnelEndpoint = 192.168.1.1:64295 TunnelEndpoint = vpn.example.com

Hostnames
This option can be specified multiple times. It tells tinc to try to connect to the given hostnames. This is useful if you don't know the IP address of the node you want to connect to, or if the IP address might change.

For example: Hostnames = vpn.example.com

Proxy
This option can be specified multiple times. It tells tinc to use the given host as a proxy for outgoing connections. This is useful if you want to connect to a node behind a firewall that only allows outgoing connections.

A Proxy can be specified as address:port or hostname:port. If the port is omitted, the default port (64295) is used. If you want to use hostnames, you need to make sure that DNS is working correctly.

For example: Proxy = 192.168.1.1:64295 Proxy = vpn.example.com

IndirectData
If set to yes, this host will accept indirect data from other hosts. This means that other hosts can send data through this host to reach other hosts. This is required for a hierarchical network setup.
PingTimeout
The number of seconds after which a connection is considered dead if no data has been received. The default is 10 seconds.
ConnectTimeout
The number of seconds to wait for a connection attempt to succeed. The default is 10 seconds.
ResolveTimeout
The number of seconds to wait for a DNS lookup to complete. The default is 5 seconds.
SelfWeight
The weight of this node itself. This is used when comparing subnets. A lower value means higher priority. The default is 10.
ExternalScripts
If set to yes, tinc will execute scripts in /etc/tinc/NETNAME/scripts/. See SCRIPTS for details.

NAMES

Each host in a tinc network is identified by a unique name. This name is used in the host configuration files to refer to other hosts. The name must consist of only alphanumeric characters and hyphens. The name is case-insensitive.

PUBLIC/PRIVATE KEYS

Each host must have a public and private RSA key pair. The private key is stored in ~/.ssh/id_rsa (or ~/.ssh/private_key) and the public key is stored in ~/.ssh/id_rsa.pub (or ~/.ssh/public_key.pub). These files are automatically generated by tinc if they don't exist.

The public key of each host must be distributed to all other hosts in the network. This is done by placing the public key in the host's configuration file. The public key is used to encrypt communication between hosts, ensuring that only the intended recipient can read the messages.

SERVER CONFIGURATION

The server configuration file is located at /etc/tinc/NETNAME/tinc.conf. It contains the following options:

ListenPort = port
The UDP port to listen on for incoming connections. If not specified, tinc will not listen for incoming connections.
IPv6ListenPort = port
The UDP port to listen on for incoming IPv6 connections. If not specified, and IPv6 is enabled, tinc will use the same port as ListenPort.
Interface = name
The name of the virtual network interface to create. Defaults to NETNAME.
Mode = router | switch
The mode of operation. Defaults to router.
Subnet = address[/prefixlength[#weight]]
The subnet which this tinc daemon will serve. tinc tries to look up which other daemon it should send a packet to by searching the appropriate subnet. If the packet matches a subnet, it will be sent to the daemon who has this subnet in his host configuration file. Multiple Subnet variables can be specified.

Subnets can either be single MAC, IPv4 or IPv6 addresses, in which case a subnet consisting of only that single address is assumed, or they can be a IPv4 or IPv6 network address with a prefixlength. For example, IPv4 subnets must be in a form like 192.168.1.0/24, where 192.168.1.0 is the network address and 24 is the number of bits set in the netmask. Note that subnets like 192.168.1.1/24 are invalid! Read a networking HOWTO/FAQ/guide if you don't understand this. IPv6 subnets are notated like fec0:0:0:1::/64. MAC addresses are notated like 0:1a:2b:3c:4d:5e.

A Subnet can be given a weight to indicate its priority over identical Subnets owned by different nodes. The default weight is 10. Lower values indicate higher priority. Packets will be sent to the node with the highest priority, unless that node is not reachable, in which case the node with the next highest priority will be tried, and so on.

TCPOnly = yes | no (no [obsolete])
If this variable is set to yes, then the packets are tunnelled over the TCP connection instead of a UDP connection. This is especially useful for those who want to run a tinc daemon from behind a masquerading firewall, or if UDP packet routing is disabled somehow. Setting this options also implicitly sets IndirectData.

Since version 1.0.10, tinc will automatically detect whether communication via UDP is possible or not.

HOST CONFIGURATION FILES

Each host in a tinc network has its own configuration file. These files are located in /etc/tinc/NETNAME/hosts/. The name of the file is the name of the host. For example, the configuration file for a host named router1 would be /etc/tinc/myvpn/hosts/router1.

Each host configuration file contains the following options:

Address = address
The IP address or hostname of the host. This is used to connect to the host. If a hostname is specified, tinc will try to resolve it using DNS.
Subnet = address[/prefixlength[#weight]]
The subnet(s) that this host is part of. This is used by tinc to determine which host to send packets to. Multiple Subnet variables can be specified.
Port = port
The port number that the tinc daemon on this host is listening on. Defaults to 64295.
Key =
The public RSA key of the host. This is used to encrypt communication between hosts. The key must be in PEM format. If this option is omitted, tinc will try to read the public key from /etc/tinc/NETNAME/hosts/HOST.pub.
PingTimeout = seconds
The number of seconds after which a connection to this host is considered dead if no data has been received. Defaults to 10 seconds.
ConnectTimeout = seconds
The number of seconds to wait for a connection attempt to this host to succeed. Defaults to 10 seconds.
IndirectData = yes | no
If set to yes, this host will accept indirect data from this host. This means that this host can send data through this host to reach other hosts. This is required for a hierarchical network setup.
Proxy = yes | no
If set to yes, this host will act as a proxy for connections to this host. This means that other hosts can connect to this host, and this host will then forward the connection to the actual host. This is useful if the actual host is behind a firewall that only allows outgoing connections.

The Address option is mandatory for all hosts except the local host. The Subnet option is mandatory for all hosts if Mode is set to router.

Example host configuration file:

Address = 192.168.1.1
Subnet = 10.0.0.1/24
Port = 64295
Key = -----BEGIN PUBLIC KEY-----
      ...
      -----END PUBLIC KEY-----

The Key option is optional. If it is omitted, tinc will try to read the public key from /etc/tinc/NETNAME/hosts/HOST.pub.

If Mode is set to router, tinc needs to know which subnets are available. This is done by specifying the Subnet option in the host configuration files. For example, if a host named router2 serves the subnet 192.168.2.0/24, then the configuration file for router2 would contain:

Subnet = 192.168.2.0/24

If a host is not reachable, tinc will try to connect to it via another host. This is called indirect connection. To enable indirect connections, you need to set the IndirectData option to yes in the host configuration file of the host that will be used for indirect connections. You also need to specify the Subnet option for that host.

For example, if host router1 is behind a firewall and can only make outgoing connections, and you want to connect to it via host router2, then the configuration file for router1 would contain:

Address = 192.168.1.1
IndirectData = yes

And the configuration file for router2 would contain:

Address = 192.168.1.2
Subnet = 10.0.0.0/24

This setup would allow tinc to establish a connection with host router1 even though it's behind a firewall. Tinc will automatically try to use indirect connections when needed. It will try to connect directly first, and if that fails, it will try to use an indirect connection. Tinc will also try to establish a direct connection in the background, so that the indirect connection can be replaced by a direct connection later.

SCRIPTS

Apart from reading the server and host configuration files, tinc can also run scripts at certain moments. Below is a list of filenames of scripts and a description of when they are run. A script is only run if it exists and if it is executable.

Scripts are run synchronously; this means that tinc will temporarily stop processing packets until the called script finishes executing. This guarantees that scripts will execute in the exact same order as the events that trigger them. If you need to run commands asynchronously, you have to ensure yourself that they are being run in the background.

Under Windows (not Cygwin), the scripts must have the extension .bat.

/etc/tinc/NETNAME/tinc-up
This is the most important script. If it is present it will be executed right after the tinc daemon has been started and has connected to the virtual network device. It should be used to set up the corresponding network interface, but can also be used to start other things.

Under Windows you can use the Network Connections control panel instead of creating this script.

/etc/tinc/NETNAME/tinc-down
This script is started right before the tinc daemon quits.
/etc/tinc/NETNAME/hosts/HOST-up
This script is started when the tinc daemon with name HOST becomes reachable.
/etc/tinc/NETNAME/hosts/HOST-down
This script is started when the tinc daemon with name HOST becomes unreachable.
/etc/tinc/NETNAME/host-up
This script is started when any host becomes reachable.
/etc/tinc/NETNAME/host-down
This script is started when any host becomes unreachable.
/etc/tinc/NETNAME/subnet-up
This script is started when a Subnet becomes reachable. The Subnet and the node it belongs to are passed in environment variables.
/etc/tinc/NETNAME/subnet-down
This script is started when a Subnet becomes unreachable.

The scripts are started without command line arguments, but can make use of certain environment variables. Under UNIX like operating systems the names of environment variables must be preceded by a $ in scripts. Under Windows, in .bat files, they have to be put between % signs.

NETNAME
If a netname was specified, this environment variable contains it.
NAME
Contains the name of this tinc daemon.
DEVICE
Contains the name of the virtual network device that tinc uses.
INTERFACE
Contains the name of the virtual network interface that tinc uses. This should be used for commands like ifconfig.
NODE
When a host becomes (un)reachable, this is set to its name. If a subnet becomes (un)reachable, this is set to the owner of that subnet.
REMOTEADDRESS
When a host becomes (un)reachable, this is set to its real address.
REMOTEPORT
When a host becomes (un)reachable, this is set to the port number it uses for communication with other tinc daemons.
SUBNET
When a subnet becomes (un)reachable, this is set to the subnet.
WEIGHT
When a subnet becomes (un)reachable, this is set to the subnet weight.

Do not forget that under UNIX operating systems, you have to make the scripts executable, using the command chmod a+x script.

FILES

The most important files are:

/etc/tinc/
The top directory for configuration files.
/etc/tinc/NETNAME/tinc.conf
The default name of the server configuration file for net NETNAME.
/etc/tinc/NETNAME/conf.d/
Optional directory from which any *.conf file will be loaded
/etc/tinc/NETNAME/hosts/
Host configuration files are kept in this directory.
/etc/tinc/NETNAME/tinc-up
If an executable file with this name exists, it will be executed right after the tinc daemon has connected to the virtual network device. It can be used to set up the corresponding network interface.
/etc/tinc/NETNAME/tinc-down
If an executable file with this name exists, it will be executed right before the tinc daemon is going to close its connection to the virtual network device.
