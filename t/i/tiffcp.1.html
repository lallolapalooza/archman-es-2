NOMBRE

tiffcp - copiar (y posiblemente convertir) un archivo TIFF

SINOPSIS

tiffcp [ opciones ] src1.tif … srcN.tif dst.tif

DESCRIPCIÓN

tiffcp combina uno o más archivos creados de acuerdo con el formato de archivo de imagen Etiqueta, Revisión 6.0 en un único archivo TIFF. Dado que el archivo de salida puede comprimirse utilizando un algoritmo diferente al de los archivos de entrada, tiffcp se utiliza más a menudo para convertir entre diferentes esquemas de compresión.

Por defecto, tiffcp copiará todas las etiquetas entendidas en un directorio TIFF de un archivo de entrada al directorio asociado en el archivo de salida.

tiffcp se puede utilizar para reorganizar las características de almacenamiento de datos en un archivo, pero está explícitamente diseñado para no alterar ni convertir el contenido de los datos de imagen de ninguna manera.

OPCIONES

-a
Añadir a un archivo de salida existente en lugar de sobrescribirlo.
-b imagen
restar la siguiente imagen monocromática de todas las demás procesadas. Esto se puede usar para eliminar un sesgo de ruido de un conjunto de imágenes. Esta imagen de sesgo es típicamente una imagen de ruido que la cámara vio con el obturador cerrado.
-B
Forzar la salida a escribirse con orden de bytes Big-Endian. Esta opción solo tiene efecto cuando el archivo de salida se crea o se sobrescribe y no cuando se añade.
-C
Suprimir el uso de "strips chopping" al leer imágenes que tienen una sola tira/mosaico de datos sin comprimir.
-c
Especificar la compresión a usar para los datos escritos en el archivo de salida: -c none para sin compresión, -c packbits para compresión PackBits, -c lzw para compresión Lempel-Ziv & Welch, -c zip para compresión Deflate, -c lzma para compresión LZMA2, -c jpeg para compresión JPEG base, -c g3 para compresión CCITT Group 3 (T.4), -c g4 para compresión CCITT Group 4 (T.6), o -c sgilog para compresión SGILOG.

Por defecto, tiffcp comprimirá los datos de acuerdo con el valor de la etiqueta Compression encontrada en el archivo de origen.

Los algoritmos de compresión CCITT Group 3 y Group 4 solo se pueden usar con datos de nivel binario.

La compresión Group 3 se puede especificar junto con varias opciones específicas de T.4:

  • 1d para codificación 1-dimensional,
  • 2d para codificación 2-dimensional, y
  • fill para forzar que cada línea de escaneo codificada se rellene con ceros para que el código EOL de terminación se encuentre en un límite de byte.

Las opciones específicas de Group 3 se especifican añadiendo una lista separada por : a la opción g3; por ejemplo, -c g3:2d:fill para obtener datos codificados en 2D con EOL alineados por byte.

Las compresiones LZW, Deflate y LZMA2 se pueden especificar junto con un valor de predictor. Un valor de predictor de 2 hace que cada línea de escaneo de la imagen de salida sufra una diferencia horizontal antes de ser codificada; un valor de 1 fuerza a que cada línea de escaneo se codifique sin diferencia. Un valor de 3 es para predicción de punto flotante que puedes usar si los datos codificados están en formato de punto flotante. Las opciones específicas de LZW se especifican añadiendo una lista separada por : a la opción lzw; por ejemplo, -c lzw:2 para compresión LZW con diferencia horizontal.

Los codificadores Deflate y LZMA2 soportan varios niveles de compresión (o preajustes del codificador) establecidos como el carácter p y un número de preajuste. p1 es el más rápido con la peor relación de compresión y p9 es el más lento pero con la mejor relación posible; por ejemplo, -c zip:3:p9 para codificación Deflate con nivel de compresión máximo y predictor de punto flotante.

Para el códec Deflate, y en una compilación de libtiff con libdeflate habilitado, p12 es en realidad el nivel máximo.

Para el códec Deflate, y en una compilación de libtiff con libdeflate habilitado, s0 se puede usar para requerir que se use zlib, y s1 para libdeflate (por defecto usa libdeflate cuando está disponible).

-f orden_relleno
Especificar el orden de relleno de bits a usar al escribir datos de salida. Por defecto, tiffcp creará un nuevo archivo con el mismo orden de relleno que el original. Especificar -f lsb2msb forzará que los datos se escriban con la etiqueta FillOrder establecida en LSB2MSB, mientras que -f msb2lsb forzará que los datos se escriban con la etiqueta FillOrder establecida en MSB2LSB.
-i
Ignorar errores de lectura no fatales y continuar el procesamiento del archivo de entrada.
-l
Especificar la longitud de un mosaico (en píxeles).

tiffcp intenta establecer las dimensiones del mosaico de manera que no aparezcan más de 8 kilobytes de datos en un mosaico.

-L
Forzar la salida a escribirse con orden de bytes Little-Endian. Esta opción solo tiene efecto cuando el archivo de salida se crea o se sobrescribe y no cuando se añade.
-M
Suprimir el uso de archivos mapeados en memoria al leer imágenes.
-o offset
Establecer el offset del directorio inicial.
-p
Especificar la configuración planar a usar al escribir datos de imagen que tienen una muestra de 8 bits por píxel. Por defecto, tiffcp creará un nuevo archivo con la misma configuración planar que el original. Especificar -p contig forzará que los datos se escriban con datos multimuestra empaquetados juntos, mientras que -p separate forzará que las muestras se escriban en planos separados.
-r
Especificar el número de filas (líneas de escaneo) en cada tira de datos escrita en el archivo de salida. Por defecto (o cuando se especifica el valor 0), tiffcp intenta establecer las filas/tira de manera que no aparezcan más de 8 kilobytes de datos en una tira. Si especifica el valor especial -1, resultará en un número infinito de filas por tira. La imagen completa será una sola tira en ese caso.
-s
Forzar que el archivo de salida se escriba con los datos organizados en tiras (en lugar de mosaicos).
-t
Forzar que el archivo de salida se escriba con los datos organizados en mosaicos (en lugar de tiras). Las opciones se pueden usar para forzar que la imagen resultante se escriba como tiras o mosaicos de datos, respectivamente.
-w
Especificar el ancho de un mosaico (en píxeles). :program::tiffcp intenta establecer las dimensiones del mosaico de manera que no aparezcan más de 8 kilobytes de datos en un mosaico.
-x
Forzar que el archivo de salida se escriba con el valor PAGENUMBER en secuencia.
-8
Escribir BigTIFF en lugar del formato TIFF clásico.
-,= caracter
sustituir caracter por , al analizar índices de directorios de imágenes en archivos. Esto es necesario si los nombres de archivo contienen comas. Tenga en cuenta que -,= con un espacio en blanco inmediatamente después deshabilitará por completo el significado especial de la ,. Ver ejemplos.
-m s
Es importante tener en cuenta que la opción -m es un marcador de posición y no se corresponde con una opción documentada en el texto original. Es posible que haya un error tipográfico o que la opción se haya omitido en la documentación.

tiffcp(1) — Arch manual pages

NAME

tiffcp — copy TIFF files

SYNOPSIS

tiffcp [options] input.tif ... output.tif

DESCRIPTION

The tiffcp utility is used to copy TIFF images from one or more input files to one or more output files. The utility can be used to reformat images, to extract selected images from a multi-image file, and to perform simple image manipulations. The input files are concatenated in the order specified on the command line to form the output file. All images within a single input file are copied to the output file in the order they appear in the input file. By default, image data is decompressed and recompressed according to the settings specified in the output file. If no compression is specified for the output file, the compression of the first image is assumed.

The options described below can be used to control the operation of tiffcp.

OPTIONS

-c codec[,predictor]
Specify the codec to use for writing image data. The supported codecs are none, rle, zip (requires libz), lzw, jpeg, oldjpeg, packbits, g3, and g4. For zip and lzw, an optional predictor function can be specified. The supported predictors are none, 2 (horizontal differencing), and 3 (floating point differencing). The default predictor is none. For example, -c lzw,2 specifies LZW compression with horizontal differencing.
-b basefile.tif
Subtract the contents of basefile.tif from the images being copied. This is useful for removing a background or bias image. The basefile must have the same dimensions and bit depth as the images being copied. The subtraction is done on a pixel-by-pixel basis. This option is useful when dealing with image data that has a bias image, such as is common with CCD cameras.
-e last-image
Copy all images up to, but not including, last-image from the first input file. The first image is image 0.
-f photometric
Set the PhotometricInterpretation tag. Supported values are: miniswhite, minisblack, rgb, palette, cmyk, ycbcr, and ciielab.
-i
Ignore existing Image File Directories (IFDs) in input files when copying images. This option is useful for creating a new file without any of the original tags.
-l rowsperstrip
Set the number of rows per strip in the output file. The default is to make each strip the same size as the image. If 0 is specified, the image is written as a single strip.
-p PlanarConfiguration
Set the PlanarConfiguration tag. Supported values are: 1 (contiguous by row) and 2 (separate planes).
-r resolution
Set the resolution (dots per unit) for the output file. The default resolution is 1.
-s subsampling
Set the subsampling value for YCbCr images. The default is 2. Supported values are 1 and 2.
-d
Write output data with the same bit depth as the input data.
-o offset
Set the offset for 32-bit integer samples. Defaults to 0.
-x max-size
Set maximum memory allocation size (in MiB). The default is 256MiB. Set to 0 to disable the limit.

EXAMPLES

The following concatenates two files and writes the result using LZW encoding:

tiffcp -c lzw a.tif b.tif result.tif

To convert a G3 1d-encoded TIFF to a single strip of G4-encoded data the following might be used:

tiffcp -c g4 -r 10000 g3.tif g4.tif

(1000 is just a number that is larger than the number of rows in the source file.)

To extract a selected set of images from a multi-image TIFF file, the file name may be immediately followed by a , separated list of image directory indices. The first image is always in directory 0. Thus, to copy the 1st and 3rd images of image file album.tif to result.tif:

tiffcp album.tif,0,2 result.tif

A trailing comma denotes remaining images in sequence. The following command will copy all image with except the first one:

tiffcp album.tif,1, result.tif

Given file CCD.tif whose first image is a noise bias followed by images which include that bias, subtract the noise from all those images following it (while decompressing) with the command:

tiffcp -c none -b CCD.tif CCD.tif,1, result.tif

If the file above were named CCD,X.tif, the -,= option would be required to correctly parse this filename with image numbers, as follows:

tiffcp -c none -,=% -b CCD,X.tif CCD,X%1%.tif result.tif
