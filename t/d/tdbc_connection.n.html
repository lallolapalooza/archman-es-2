tdbc::connection(n) Conectividad de base de datos TDBC tdbc::connection(n)

NOMBRE

tdbc::connection - Objeto de conexión TDBC

SINOPSIS

package require tdbc 1.0
package require tdbc::driver version
tdbc::driver::connection create db ?-opción valor...?
db configure ?-opción valor...?
db close
db foreignkeys ?-primary tableName? ?-foreign tableName?
db prepare código-sql
db preparecall llamada
db primarykeys tableName
db statements
db resultsets
db tables ?patrón?
db columns tabla ?patrón?
db begintransaction
db commit
db rollback
db transaction script

db allrows ?-as listas|diccionarios? ?-columnsvariable nombre? ?--? código-sql ?diccionario?
db foreach ?-as listas|diccionarios? ?-columnsvariable nombre? ?--? varName códigohql ?diccionario? script

DESCRIPCIÓN

Cada controlador de base de datos para TDBC (Tcl DataBase Connectivity) implementa un objeto de conexión que representa una conexión a una base de datos. Por convención, este objeto es creado por el comando tdbc::driver::connection create. Este comando acepta el nombre de un comando Tcl que representará la conexión y un conjunto posible de opciones (ver OPCIONES DE CONFIGURACIÓN). Establece una conexión a la base de datos y devuelve el nombre del comando Tcl recién creado.

El comando de objeto configure en una conexión de base de datos, si se presenta sin argumentos, devuelve una lista de palabras clave y valores alternos que representan la configuración actual de la conexión. Si se presenta con un solo argumento -opción, devuelve el valor configurado de la opción dada. De lo contrario, debe recibir un número par de argumentos que son opciones y valores alternos. Las opciones especificadas reciben los valores especificados y no se devuelve nada.

El comando de objeto close en una conexión de base de datos cierra la conexión. Todas las sentencias activas y conjuntos de resultados en la conexión se cierran. Cualquier transacción no confirmada se revierte. El comando de objeto se elimina.

El comando de objeto prepare en una conexión de base de datos prepara una sentencia SQL para su ejecución. El argumento código-sql debe contener una única sentencia SQL a ejecutar. Se pueden incluir variables enlazadas. El valor de retorno es un comando Tcl recién creado que representa la sentencia. Ver tdbc::statement para una discusión más detallada del SQL aceptado por el comando de objeto prepare y la interfaz aceptada por una sentencia.

En una conexión de base de datos donde la base de datos y el controlador subyacentes admiten procedimientos almacenados, el comando de objeto preparecall prepara una llamada a un procedimiento almacenado para su ejecución. La sintaxis de la llamada al procedimiento almacenado es:

?varResultado =? procName(?arg ?, arg...?)

El valor de retorno es un comando Tcl recién creado que representa la sentencia. Ver tdbc::statement para la interfaz aceptada por una sentencia.

El comando de objeto statements devuelve una lista de sentencias que han sido creadas por las sentencias prepare y preparecall contra la conexión dada y que aún no se han cerrado.

El comando de objeto resultsets devuelve una lista de conjuntos de resultados que se han obtenido ejecutando sentencias preparadas utilizando la conexión dada y que aún no se han cerrado.

El comando de objeto tables permite al programa consultar la conexión para obtener los nombres de las tablas que existen en la base de datos. El parámetro opcional patrón es un patrón para hacer coincidir el nombre de una tabla. Puede contener los caracteres comodín de SQL '%' y '_'. El resultado es una lista de cadenas de caracteres que son los nombres de las tablas que coinciden con el patrón.

El comando de objeto columns permite al programa consultar la conexión para obtener los nombres de las columnas que existen en una tabla dada. El parámetro opcional patrón es un patrón para hacer coincidir el nombre de una columna. Puede contener los caracteres comodín de SQL '%' y '_'. El resultado es una lista de diccionarios, uno por cada columna de la tabla especificada. Las claves del diccionario pueden incluir al menos las siguientes. Los valores que son NULL o sin sentido en una base de datos dada se omiten.

type
Contiene el tipo de datos de la columna, y generalmente se elegirá del conjunto: bigint, binary, bit, char, date, decimal, double, float, integer, longvarbinary, longvarchar, numeric, real, time, timestamp, smallint, tinyint, varbinary y varchar. (Si la columna tiene un tipo que no se puede representar como uno de los anteriores, type contendrá una descripción del tipo dependiente del controlador).
precision
Contiene la precisión de la columna en bits, dígitos decimales o el ancho en caracteres, según el tipo.
scale
Contiene la escala de la columna (el número de dígitos después del punto decimal), para tipos que admiten el concepto.
nullable
Contiene 1 si la columna puede contener valores NULL, y 0 en caso contrario.

El comando de objeto primarykeys permite al programa consultar la conexión para las claves primarias que pertenecen a una tabla dada. El parámetro tableName identifica la tabla que se está interrogando. El resultado es una lista de diccionarios que enumeran las claves (en un formato similar a la lista devuelta por $connection allrows -as dicts). Las claves del diccionario pueden incluir al menos las siguientes. Los valores que son NULL o sin sentido en una base de datos dada se omiten.

tableCatalog
Nombre del catálogo en el que aparece la tabla.
tableSchema
Nombre del esquema en el que aparece la tabla.
tableName
Nombre de la tabla propietaria de la clave primaria.
constraintCatalog
Nombre del catálogo en el que aparece la restricción de clave primaria. En algunos sistemas de bases de datos, este puede no ser el mismo que el catálogo de la tabla.
constraintSchema
Nombre del esquema en el que aparece la restricción de clave primaria. En algunos sistemas de bases de datos, este puede no ser el mismo que el esquema de la tabla.
constraintName
Nombre de la restricción de clave primaria.
columnName
Nombre de una columna que es miembro de la clave primaria.
ordinalPosition
Posición ordinal de la columna dentro de la clave primaria.

A estas columnas se les pueden añadir otras que sean específicas de un sistema de base de datos en particular.

El comando de objeto foreignkeys permite al programa consultar la conexión para las relaciones de clave externa que se aplican a una tabla en particular. Las relaciones pueden estar restringidas a las claves que aparecen en una tabla en particular (-foreign tableName), las claves que hacen referencia a una tabla en particular (-primary tableName), o ambas. Al menos una de las opciones -primary y -foreign debe ser especificada, aunque algunos controladores enumerarán todas las claves externas en el catálogo actual si ambas opciones se omiten. El resultado del comando de objeto foreignkeys es una lista de diccionarios, con un elemento de lista por cada clave (en un formato similar a la lista devuelta por $connection allrows -as dicts). Las claves del diccionario pueden incluir al menos las siguientes. Los valores que son NULL o sin sentido en una base de datos dada se omiten.

foreignConstraintCatalog
Catálogo en el que aparece la restricción de clave externa.
foreignConstraintSchema
Esquema en el que aparece la restricción de clave externa.
foreignConstraintName
Nombre de la restricción de clave externa.
foreignTableName
Nombre de la tabla que contiene la columna de clave externa.
foreignColumnName
Nombre de la columna que forma parte de la clave externa.
primaryConstraintCatalog
Nombre del catálogo en el que aparece la restricción de clave primaria.
primaryConstraintSchema
Nombre del esquema en el que aparece la restricción de clave primaria.
primaryTableName
Nombre de la tabla que contiene la columna de clave primaria referenciada.
primaryColumnName
Nombre de la columna que forma parte de la clave primaria referenciada.
keySequence
Secuencia de la columna dentro de la clave externa.
updateRule
Regla de actualización para la restricción de clave externa. Los valores posibles incluyen restrict, cascade, set null, no action, y set default.
deleteRule
Regla de eliminación para la restricción de clave externa. Los valores posibles incluyen restrict, cascade, set null, no action, y set default.
deferrability
Indica si la restricción de clave externa es diferible. Los valores posibles son initially deferred, initially immediate, y not deferrable.

A estas columnas se les pueden añadir otras que sean específicas de un sistema de base de datos en particular.

Los comandos de objeto begintransaction, commit, y rollback proporcionan control transaccional sobre las operaciones de base de datos. Solo se puede mantener una transacción activa en un momento dado por conexión. Si se llama a begintransaction cuando ya existe una transacción activa, se genera un error. Si se llama a commit o rollback cuando no hay una transacción activa, también se genera un error.

El comando de objeto transaction ejecuta el script Tcl proporcionado dentro de una transacción. Si el script se ejecuta sin generar un error, la transacción se confirma automáticamente. Si el script genera un error, la transacción se revierte automáticamente. Este es el modo preferido para ejecutar operaciones que deben ser atómicas.

El comando de objeto allrows ejecuta la sentencia SQL proporcionada y devuelve todas las filas resultantes. Si se especifica -as lists, cada fila se devuelve como una lista de valores de columna. Si se especifica -as dicts, cada fila se devuelve como un diccionario con los nombres de columna como claves. Si se especifica -columnsvariable nombre, la lista de nombres de columna se almacena en la variable Tcl con el nombre especificado. El argumento opcional diccionario puede ser un diccionario de opciones de vinculación que se pasan a la sentencia SQL. El comando -- se utiliza para marcar el final de las opciones y el inicio de los argumentos posicionales, lo que permite que los nombres de columna o las sentencias SQL comiencen con un guion.

El comando de objeto foreach es similar a allrows, pero en lugar de devolver todas las filas, itera sobre ellas, ejecutando el script proporcionado para cada fila. La variable Tcl con el nombre varName se establece en el valor de la fila actual en cada iteración. La opción -as lists hace que varName contenga una lista de valores de columna. La opción -as dicts hace que varName contenga un diccionario de nombres de columna a valores de columna. Si se especifica -columnsvariable nombre, la lista de nombres de columna se almacena en la variable Tcl con el nombre especificado. El argumento opcional diccionario puede ser un diccionario de opciones de vinculación que se pasan a la sentencia SQL. El comando -- se utiliza para marcar el final de las opciones y el inicio de los argumentos posicionales.

EJEMPLOS

package require tdbc
package require tdbc::sqlite3

# Abrir una base de datos en memoria
set db [tdbc::sqlite3::connection create myconn]

# Crear una tabla y añadir datos
$db execute {
    CREATE TABLE users (id INTEGER PRIMARY KEY, name VARCHAR(20));
    INSERT INTO users VALUES (1, 'Alice');
    INSERT INTO users VALUES (2, 'Bob');
}

# Recuperar todas las filas como listas
set all_users [$db allrows {SELECT id, name FROM users}]
# all_users contendrá { {1 Alice} {2 Bob} }

# Recuperar todas las filas como diccionarios
set all_users_as_dicts [$db allrows -as dicts {SELECT id, name FROM users}]
# all_users_as_dicts contendrá { {id {1} name {Alice}} {id {2} name {Bob}} }

# Iterar sobre las filas
$db foreach user_data {SELECT id, name FROM users} {
    puts "User ID: [dict get $user_data id], Name: [dict get $user_data name]"
}

# Preparar y ejecutar una consulta con un parámetro
set stmt [$db prepare {SELECT name FROM users WHERE id = ?}]
set alice_name [$stmt firstrow {1}]
puts "Name for ID 1: $alice_name"
$stmt close

# Usar transacciones
$db begintransaction
$db execute {INSERT INTO users VALUES (3, 'Charlie')}
# Si algo sale mal, ejecutar:
# $db rollback
# Si todo va bien, ejecutar:
# $db commit

# Usar el comando de transacción
$db transaction {
    $db execute {INSERT INTO users VALUES (4, 'David')}
    # Si se produce una excepción, la transacción se revertirá automáticamente
}

# Obtener información de la tabla
set table_list [$db tables]
# table_list contendrá {users}

set column_list [$db columns users]
# column_list contendrá { {name id type integer precision {} scale {} nullable 0} {name name type varchar(20) precision {} scale {} nullable 1} }

set primary_keys [$db primarykeys users]
# primary_keys contendrá { {tableCatalog {} tableSchema {} tableName users constraintCatalog {} constraintSchema {} constraintName {} columnName id ordinalPosition 1} }

# Cerrar la conexión
$db close
```

COMMANDS OBJECT

The following object commands are supported on database connections obtained from the tdbc::connection command.

foreignConstraintName
Nombre de la restricción de clave externa.
primaryConstraintCatalog
Catálogo que contiene la restricción de clave primaria (o restricción de clave única) en la columna a la que hace referencia la clave externa.
primaryConstraintSchema
Esquema que contiene la restricción de clave primaria (o restricción de clave única) en la columna a la que hace referencia la clave externa.
primaryConstraintName
Nombre de la restricción de clave primaria (o restricción de clave única) en la columna a la que hace referencia la clave externa.
updateAction
Acción a tomar cuando una sentencia UPDATE invalida la restricción. El valor será CASCADE, SET DEFAULT, SET NULL, RESTRICT, o NO ACTION.
deleteAction
Acción a tomar cuando una sentencia DELETE invalida la restricción. El valor será CASCADE, SET DEFAULT, SET NULL, RESTRICT, o NO ACTION.
primaryCatalog
Nombre del catálogo en el que aparece la tabla primaria (aquella a la que hace referencia la clave externa).
primarySchema
Nombre del esquema en el que aparece la tabla primaria (aquella a la que hace referencia la clave externa).
primaryTable
Nombre de la tabla primaria (aquella a la que hace referencia la clave externa).
primaryColumn
Nombre de la columna a la que hace referencia la clave externa.
foreignCatalog
Nombre del catálogo en el que aparece la tabla que contiene la clave externa.
foreignSchema
Nombre del esquema en el que aparece la tabla que contiene la clave externa.
foreignTable
Nombre de la tabla que contiene la clave externa.
foreignColumn
Nombre de la columna que aparece en la clave externa.
ordinalPosition
Posición de la columna en la clave externa, si la clave es una clave compuesta.

El comando de objeto begintransaction en una conexión de base de datos inicia una transacción en la base de datos. Si la base de datos subyacente no soporta transacciones atómicas, consistentes, aisladas y duraderas, el comando de objeto begintransaction devuelve un error informando el hecho. De manera similar, si se ejecutan múltiples comandos begintransaction sin un comando commit o rollback intermedio, se devuelve un error a menos que la base de datos subyacente soporte transacciones anidadas.

El comando de objeto commit en una conexión de base de datos finaliza la transacción más reciente iniciada por begintransaction y confirma los cambios en la base de datos.

El comando de objeto rollback en una conexión de base de datos deshace la transacción más reciente iniciada por begintransaction. El estado de la base de datos es como si nada hubiera sucedido durante la transacción.

El comando de objeto transaction en una conexión de base de datos presenta una forma sencilla de agrupar una transacción de base de datos. Inicia una transacción y evalúa el argumento script suministrado como un script Tcl en el ámbito del llamador. Si script termina normalmente, o por break, continue, o return, la transacción se confirma (y cualquier acción solicitada por break, continue, o return se lleva a cabo). Si la confirmación falla por cualquier motivo, el error en la confirmación se trata como un error en el script. En caso de error en script o en la confirmación, la transacción se deshace y se relanza el error. Cualquier código de retorno no estándar del script provoca que la transacción se deshaga y luego se relance.

El comando de objeto allrows prepara una sentencia SQL (dada por el parámetro sql-code) para ejecutar contra la base de datos. Luego la ejecuta (ver tdbc::statement para detalles) con el parámetro opcional dictionary que proporciona variables de enlace. Finalmente, utiliza el comando de objeto allrows en el conjunto de resultados (ver tdbc::resultset) para construir una lista de los resultados. Finalmente, tanto el conjunto de resultados como la sentencia se cierran. El valor de retorno es la lista de resultados.

El comando de objeto foreach prepara una sentencia SQL (dada por el parámetro sql-code) para ejecutar contra la base de datos. Luego la ejecuta (ver tdbc::statement para detalles) con el parámetro opcional dictionary que proporciona variables de enlace. Finalmente, utiliza el comando de objeto foreach en el conjunto de resultados (ver tdbc::resultset) para evaluar el script dado para cada fila de los resultados. Finalmente, tanto el conjunto de resultados como la sentencia se cierran, incluso si el script dado resulta en un return, un error, o un código de retorno inusual.

OPCIONES DE CONFIGURACIÓN

Las opciones de configuración aceptadas cuando se crea la conexión y en el comando de objeto configure de la conexión incluyen las siguientes, y pueden incluir otras específicas de un controlador de base de datos.

-encodingnombre
Especifica la codificación que se utilizará al conectarse a la base de datos. El nombre debe ser uno de los nombres aceptados por el comando encoding. Esta opción generalmente no es necesaria; la mayoría de los controladores de bases de datos pueden determinar la codificación en uso por sí mismos.
-isolationnivel
Especifica el nivel de aislamiento de la transacción necesario para las transacciones en la base de datos. Los valores aceptables para nivel se muestran en NIVELES DE AISLAMIENTO DE TRANSACCIÓN.
-timeoutms
Especifica el tiempo máximo de espera para una operación del motor de base de datos antes de informar un error al llamador. El argumento ms indica el tiempo máximo en milisegundos. Un valor de cero (el valor por defecto) especifica que el proceso llamador debe esperar indefinidamente a las operaciones de la base de datos.
-readonlyflag
Especifica que la conexión no modificará la base de datos (si el parámetro booleano flag es verdadero), o que puede modificar la base de datos (si flag es falso). Si flag es verdadero, esta opción puede tener el efecto de elevar el nivel de aislamiento de la transacción a readonly.

NIVELES DE AISLAMIENTO DE TRANSACCIÓN

Los valores aceptables para la opción de configuración -isolation son los siguientes:

readuncommitted
Permite que la transacción lea datos "sucios", es decir, no confirmados. Este nivel de aislamiento puede comprometer la integridad de los datos, no garantiza que se satisfagan las restricciones de clave externa o de unicidad, y en general no garantiza la consistencia de los datos.
readcommitted
Prohíbe que la transacción lea datos "sucios", pero no garantiza lecturas repetibles; si una transacción lee una fila de una base de datos en un momento dado, no hay garantía de que la misma fila esté disponible en un momento posterior dentro de la misma transacción.
repeatableread
Garantiza que cualquier fila de la base de datos, una vez leída, tendrá los mismos valores durante la vida de una transacción. Todavía permite "lecturas fantasma" (es decir, la aparición de nuevas filas si una tabla se consulta por segunda vez).
serializable
El nivel más restrictivo (y más costoso) de aislamiento de transacciones. Cualquier consulta a la base de datos, si se repite, devolverá precisamente los mismos resultados durante la vida de la transacción, exactamente como si la transacción fuera el único usuario de la base de datos.
readonly
Se comporta como serializable en el sentido de que los únicos resultados visibles para la transacción son aquellos que se confirmaron antes del inicio de la transacción, pero prohíbe que la transacción modifique la base de datos.

Una base de datos que no implementa uno de estos niveles de aislamiento utilizará en su lugar el siguiente nivel de aislamiento más restrictivo. Si no se puede obtener el nivel de aislamiento dado, la interfaz de la base de datos lanza un error informando el hecho. El nivel de aislamiento por defecto es readcommitted.

Un script no debe cambiar el nivel de aislamiento cuando una transacción está en curso.
