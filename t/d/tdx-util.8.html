NOMBRE

tdx-util - Utilidad de manipulación de vistas previas para tradindexed

SINOPSIS

tdx-util [-AFcgioO] [-a artículo] [-f estado] [-n newsgrupo] [-p ruta] [-R ruta]

DESCRIPCIÓN

tdx-util es una interfaz administrativa para el método de vistas previas tradindexed para INN. Solo funciona en bases de datos de vistas previas tradindexed, no en ningún otro tipo de vista previa de INN. (Ver los programas dedicados ovdb_stat(8) y ovsqlite-util(8) para los métodos de vista previa ovdb y ovqslite.) Permite al administrador volcar diversa información sobre el estado interno de la vista previa, auditarla en busca de errores y reconstruir porciones de la base de datos de vistas previas.

El método de vista previa tradindexed debería bloquearse correctamente y, por lo tanto, debería ser seguro ejecutar esta utilidad y realizar cualquier operación que realice, incluidas reparaciones completas o reconstrucciones de vistas previas por grupo, mientras el servidor está en ejecución. Sin embargo, tenga en cuenta que algunas de las operaciones realizadas por esta utilidad pueden llevar mucho tiempo y mantendrán bloqueos en la base de datos de vistas previas durante ese período, lo que, dependiendo de lo que esté haciendo el servidor, puede hacer que el servidor se detenga hasta que tdx-util complete su operación.

Las operaciones de volcado son -i, que vuelca el índice maestro de la base de datos de vistas previas; -g, que vuelca el índice de un grupo individual; y -o y -O, que vuelcan la información de vista previa de un grupo particular (incluidos los metadatos adicionales almacenados en el índice) en dos formatos diferentes. Para -g, -o y -O, también se debe proporcionar la opción -n para especificar el newsgrupo sobre el que operar.

Para agregar un nuevo newsgrupo a la base de datos de vistas previas, use -c. Se debe especificar un grupo con -n. Si el estado del grupo es algo diferente de "y", se debe especificar con -f, y los números de artículo bajos y altos se pueden especificar con -a. Si solo se proporciona un número en lugar de un rango, se tomará como el marcador alto y el marcador bajo se establecerá en 1.

Para auditar toda la base de datos de vistas previas en busca de problemas, use -A. Cualquier problema encontrado se informará al error estándar. Use -F para corregir los errores encontrados.

Para reconstruir la base de datos de un newsgrupo en particular, use -R. La opción -R toma una ruta a un directorio que contiene todos los artículos de ese newsgrupo, uno por archivo. Los nombres de los archivos deben ser los números de los artículos de ese grupo. (En otras palabras, este directorio debe ser un directorio de spool tradicional para ese grupo). La opción -n también debe proporcionarse para especificar el newsgrupo para el cual se está reconstruyendo la vista previa.

Para todas las operaciones realizadas por tdx-util, se puede especificar una base de datos de vistas previas diferente a la especificada en inn.conf utilizando la opción -p.

El número de registros de vistas previas almacenados en la base de datos se puede obtener con el comando "inndf -n".

OPCIONES

-a artículo
El número o números de artículo a los que actuar. artículo es un rango NNTP válido, lo que significa que puede ser un solo número de artículo o un rango de números de artículo (como "1-5"). Se puede omitir el inicio o el final (o ambos) del rango, en cuyo caso se establecerán en el primer o último número de artículo del grupo. Por lo tanto, pasar "-" para artículo es equivalente a no usar la opción -a en absoluto.

Solo útil en combinación con las opciones -o y -O para volcar información de vista previa o con -c para especificar los números de artículo bajos y altos al crear un grupo.

-A
Auditar toda la base de datos de vistas previas en busca de problemas. Esto ejecuta las comprobaciones de consistencia internas integradas en la implementación de vistas previas tradindexed, comprobando cosas como la validez y accesibilidad de todas las entradas del índice del grupo, el formato de las entradas de vista previa individuales, la correspondencia de las entradas del índice con los datos de vista previa y cosas similares. No se realizarán cambios en la base de datos, pero los problemas se informarán al error estándar.
-c
Crear un nuevo grupo en la base de datos de vistas previas. El grupo debe especificarse con -n. El estado del newsgrupo por defecto es "y" pero puede establecerse con -f. Los números de artículo bajos y altos por defecto son 1 y 0 respectivamente, pero pueden establecerse con -a. Si solo se proporciona un número a -a, se toma como el número de artículo alto.
-F
Auditar toda la base de datos de vistas previas en busca de problemas, corrigiéndolos a medida que se detectan siempre que sea posible. Esto ejecuta las comprobaciones de consistencia internas integradas en la implementación de vistas previas tradindexed, comprobando cosas como la validez y accesibilidad de todas las entradas del índice del grupo, el formato de las entradas de vista previa individuales, la correspondencia de las entradas del índice con los datos de vista previa y cosas similares. La estrategia utilizada al corregir problemas es descartar los datos que no se pueden recuperar, así que tenga en cuenta que usar esta opción puede resultar en artículos inaccesibles si sus datos de vista previa se han corrompido.

Para ver qué se cambiaría con -F, ejecute tdx-util con -A primero.

-f estado
Al crear un newsgrupo con -c, establecer el estado del grupo recién creado en estado en lugar de "y". Solo útil con -c.
-g
Volcar el índice de un grupo en particular. Los campos son, en orden, el número de artículo, el desplazamiento de los datos de ese artículo en el archivo de datos de vista previa para ese grupo, la longitud de los datos de vista previa, la hora (en segundos desde la época) en que llegó el artículo al servidor, la hora (en segundos desde la época) en que el artículo debería expirar según su campo de encabezado Expires (o 0 si no hay un campo de encabezado Expires), y el token de la API de almacenamiento del artículo.

Si se proporciona esta opción, también se debe proporcionar la opción -n para especificar el newsgrupo sobre el que actuar.

-i
Volcar el índice maestro de la base de datos de vistas previas. Esto contiene información similar al archivo active del servidor, como marcas altas y bajas y estado de moderación, y es la información que nnrpd entrega a los clientes.

Los campos son, en orden, el nombre del newsgrupo, la marca alta, la marca baja, el número base de artículos (el punto en el que comienza el índice del grupo), el recuento de artículos en el grupo, el estado del grupo, la hora (en segundos desde la época) en que se eliminó ese newsgrupo o 0 si no lo ha hecho, y el inodo del archivo de índice para ese grupo.

Se puede especificar un newsgrupo en particular con la opción -n. Si no se proporciona -n, se volcará todo el índice maestro.

-n newsgrupo
Especificar el newsgrupo sobre el que actuar, requerido para las opciones -c, -g, -o, -O y -R, y opcional para la opción -i.
-o
Volcar la información de vista previa para un newsgrupo, en el mismo formato en que se devolvería a los clientes pero con una modificación. Al final de cada entrada se agregarán cuatro piezas de datos adicionales: el número de artículo según el archivo de índice para ese grupo etiquetado con "Article:", el token de la API de almacenamiento para ese artículo etiquetado con "Token:", la fecha de llegada de ese artículo al servidor en formato de fecha RFC 5322 etiquetado con "Arrived:", y la fecha de expiración de ese artículo (del campo de encabezado Expires) en formato de fecha RFC 5322 si existe, etiquetado con "Expires:".

Si se proporciona esta opción, también se debe proporcionar la opción -n para especificar el newsgrupo sobre el que actuar. Por defecto, se vuelca toda la información de vista previa para ese newsgrupo, pero la opción -a puede proporcionarse para restringir el volcado a la información de un solo artículo o un rango de artículos.

-O
Volcar la información de vista previa para un newsgrupo, en el mismo formato en que se devolvería a los clientes pero con una modificación. Appended to the end of each entry will be four additional pieces of data: the article number according to the index file for that group labelled with "Article:", the storage API token for that article labelled with "Token:", the arrival date for that article on the server in RFC 5322 date format labelled with "Arrived:", and the expiration date for that article (from the Expires header field) in RFC 5322 date format if there is any, labelled with "Expires:".

If this option is given, the -n option must also be given to specify the newsgroup on which to act. By default, all of the overview information for that newsgroup is dumped, but the -a option may be given to restrict the dump to the information for a single article or a range of articles.

This differs from the -o option in that it dumps the overview data for a given article or range of articles using the "ovdb_retrieve" functionality.

-p path
Use path as the location of the overview database instead of the one specified in the inn.conf file.
-R path
Rebuild the overview database for a particular newsgroup. path must be the path to a directory containing all of the articles for the newsgroup, in the format required by the traditional news spooling method. The -n option must also be given to specify the newsgroup for which the overview is being rebuilt.

VER TAMBIÉN

tdx-util(8) — Arch manual pages

NAME

tdx-util

administrate the translation database

SYNOPSIS

tdx-util [-A] [-c] [-i] [-p path] [-v] [-C path] [-f mode] [-g] [-n newsgroup] [-O] [-R path] [-a range]

DESCRIPTION

The tdx-util program is used to administer the overview database used by InterNetNews (INN). It can be used to dump, audit, rebuild, or create entries in the overview database.

The overview database consists of a group index, which maps newsgroup names to overview data files, and individual overview data files for each newsgroup, which contain the metadata for each article in that newsgroup.

OPTIONS

-A
Audit the entire overview database for any errors. This is a read-only operation and cannot be combined with any other options.
-C path
Change the overview directory to path. This is used to point to a new location for the overview database, for instance, after moving it or after creating it in a different location.
-c
Create a new overview database. If the database already exists, this option will fail. This option requires the -n, -f, and -a options.
-f mode
Specifies the mode for a new overview database entry. The recognized modes are:
  • m: A standard overview file that is built from the articles in the specified newsgroup.
  • t: An empty overview file that is intended to be populated later.
-g
Dump the group index for the overview database. Each line will contain the newsgroup name, its storage API token, and the low and high article numbers for that newsgroup. The -p option may be used to specify the overview directory.
-i
Dump the master index for the overview database. This consists of the same information as the group index, but it includes all newsgroups in the database. The -p option may be used to specify the overview directory.
-n newsgroup
Specifies the newsgroup on which to act. This option is required for the -c, -g, -O, and -R options.
-O
Dump the overview information for a newsgroup in the format used by overchan as input. Each line will start with the storage API token, the arrival timestamp in seconds since epoch, the expires timestamp in the same format (or 0 if there is no Expires header field), and then the overview data.

If this option is given, the -n option must also be given to specify the newsgroup on which to act. By default, all of the overview information for that newsgroup is dumped, but the -a option may be given to restrict the dump to the information for a single article or a range of article numbers.

-p path
Act on the overview database rooted in path, overriding the overview path specified in inn.conf.
-R path
Rebuild the overview for a given group from the articles stored in path. The articles must be in the form of a traditional spool directory; in other words, each article must be in a separate file and the name of the file must match the article number of the article.

If this option is given, the -n option must also be given to specify the newsgroup on which to act.

-v
Verbose operation. Prints diagnostic messages to standard error.

EXAMPLES

Dump the master index for the overview database in /news/overview, regardless of the overview path specified in inn.conf:

tdx-util -i -p /news/overview

Dump the group index for example.test:

tdx-util -g -n example.test

Dump the complete overview information for example.test:

tdx-util -o -n example.test

Dump the overview information for articles 45 and higher in example.test:

tdx-util -o -n example.test -a 45-

Create an entry for example.test with mode m and low and high article numbers of 4 and 23, respectively.

tdx-util -c -n example.test -f m -a 4-23

Audit the entire overview database for any problems:

tdx-util -A

Rebuild the overview information for example.test from a traditional spool directory:

tdx-util -R <patharticles in inn.conf>/example/test -n example.test

The last command may be useful for recovering from a bad crash or corrupted overview information for a particular group, if you are also using the tradspool article storage method.
