tdbc::odbc(n) Conectividad de Bases de Datos Tcl tdbc::odbc(n)

NOMBRE

tdbc::odbc - Puente TDBC-ODBC

SINOPSIS

package require tdbc::odbc 1.0

tdbc::odbc::connection create db connectionString ?-option value...?
tdbc::odbc::connection new connectionString ?-option value...?

tdbc::odbc::datasources ?-system|-user?

tdbc::odbc::drivers

tdbc::odbc::datasource command driverName ?keyword-value?...

DESCRIPCIÓN

El controlador tdbc::odbc proporciona una interfaz de base de datos que se ajusta a Tcl DataBase Connectivity (TDBC) y permite que un script Tcl se conecte a cualquier base de datos SQL que presente una interfaz ODBC. También se proporciona como un ejemplo de trabajo de cómo escribir un controlador de base de datos en C, de modo que los autores de controladores tengan un punto de partida para un mayor desarrollo.

La conexión a una base de datos ODBC se establece invocando tdbc::odbc::connection create, pasándole el nombre a utilizar como manejador de conexión, seguido de una cadena de conexión ODBC estándar. Como alternativa, se puede utilizar tdbc::odbc::connection new para crear una conexión de base de datos con un nombre asignado automáticamente. El valor de retorno de tdbc::odbc::connection new es el nombre que se eligió para el manejador de conexión.

La cadena de conexión incluirá al menos una palabra clave DRIVER o DSN, y puede incluir otras que estén definidas por un controlador ODBC particular. (Si el sistema ODBC local admite una interfaz gráfica de usuario, la opción -parent (ver más abajo) puede permitir llamar a tdbc::odbc::connection create con una cadena de conexión vacía.)

El efecto secundario de tdbc::odbc::connection create es crear una nueva conexión a la base de datos. Consulte tdbc::connection(n) para obtener detalles sobre cómo utilizar la conexión para manipular una base de datos.

Además de una interfaz TDBC estándar, tdbc::odbc admite tres comandos adicionales. El primero de ellos, tdbc::odbc::datasources, que devuelve una lista Tcl que enumera las fuentes de datos con nombre disponibles para el programa (para conexión con la palabra clave DSN en la cadena de conexión). El resultado de tdbc::odbc::datasources puede limitarse a solo fuentes de datos del sistema o solo a fuentes de datos del usuario incluyendo las opciones -system o -user, respectivamente.

El comando tdbc::odbc::drivers devuelve un diccionario cuyas claves son los nombres de los controladores disponibles para la palabra clave DRIVER en la cadena de conexión, y cuyos valores son descripciones de los controladores.

El comando tdbc::odbc::datasource permite la configuración de fuentes de datos con nombre en aquellos sistemas que admiten la interfaz de programación de aplicaciones del Instalador ODBC. Acepta un comando, que especifica la operación a realizar, el nombre de un driver para la base de datos en cuestión, y un conjunto de pares clave-valor que son interpretados por el controlador dado. El comando debe ser uno de los siguientes:

add
Añade una fuente de datos de usuario. Los pares clave-valor deben incluir al menos una opción DSN que nombre la fuente de datos.
add_system
Añade una fuente de datos del sistema. Los pares clave-valor deben incluir al menos una opción DSN que nombre la fuente de datos.
configure
Configura una fuente de datos de usuario. Los pares clave-valor normalmente incluirán una opción DSN que nombre la fuente de datos. Algunos controladores admitirán otras opciones, como la opción CREATE_DB para el controlador Microsoft Access en Windows.
configure_system
Configura una fuente de datos del sistema.
remove
Elimina una fuente de datos de usuario. Los pares clave-valor deben incluir una opción DSN que especifique la fuente de datos a eliminar.
remove_system
Elimina una fuente de datos del sistema. Los pares clave-valor deben incluir una opción DSN que especifique la fuente de datos a eliminar.

OPCIONES DE CONEXIÓN

El comando de objeto tdbc::odbc::connection create admite las opciones -encoding, -isolation, -readonly y -timeout comunes a todos los controladores TDBC. La opción -encoding solo tendrá éxito si la codificación solicitada es la misma que la codificación del sistema; tdbc::odbc no intenta especificar codificaciones alternativas a un controlador ODBC. (Algunos controladores aceptan especificaciones de codificación en la cadena de conexión.)

Además, si Tk está presente en el intérprete solicitante, y el administrador de controladores ODBC del sistema local admite una interfaz gráfica de usuario, el comando de objeto tdbc::odbc::connection create admite una opción -parent, cuyo valor es el nombre de ruta de una ventana de Tk. Si se especifica esta opción, y una cadena de conexión no especifica toda la información necesaria para conectarse a una interfaz, el administrador de controladores ODBC mostrará un cuadro de diálogo para solicitar cualquier información adicional requerida. El intérprete solicitante se bloqueará hasta que el usuario cierre el cuadro de diálogo, momento en el cual se realizará la conexión.

EJEMPLOS

Dado que las cadenas de conexión ODBC son específicas del controlador, a menudo es difícil encontrar la documentación necesaria para componerlas. Los siguientes ejemplos funcionan en la mayoría de los sistemas Windows y proporcionan al menos algunas cosas útiles que un programa puede hacer.

tdbc::odbc::connection create db \
    "DSN={PAYROLL};UID={aladdin};PWD={Sesame}"
Se conecta a una fuente de datos con nombre "PAYROLL", proporcionando "aladdin" como nombre de usuario y "Sesame" como contraseña. Utiliza db como nombre de la conexión. 
set connString {DRIVER={Microsoft Access Driver (*.mdb)};}
append connString {FIL={MS Access}\;}
append connString {DBQ=} \
    [file nativename [file normalize $fileName]]
tdbc::odbc::connection create db2 -readonly 1 $connString
Abre una conexión a un archivo de base de datos Microsoft Access cuyo nombre está en $fileName. La base de datos se abre en modo de solo lectura. La conexión resultante se llama "db2". 
tdbc::odbc::connection create db3 \
    "DRIVER=SQLite3;DATABASE=$fileName"
Abre una conexión a una base de datos SQLite3 cuyo nombre está en "$fileName". 
tdbc::odbc::datasource add \
    {Microsoft Access Driver (*.mdb)} \
    DSN=MyTestDatabase \
    DBQ=[file native [file normalize $fileName]]
Crea una nueva fuente de datos de usuario con el nombre "MyTestDatabase" enlazada a un archivo Microsoft Access cuya ruta está en "$fileName". No se establece ninguna conexión a la fuente de datos hasta que el programa llama a tdbc::odbc::connection create. 
tdbc::odbc::datasource configure \
    {Microsoft Access Driver (*.mdb)} \
    CREATE_DB=[file native [file normalize $fileName]] \
    General
Crea una nueva base de datos Microsoft Access vacía en el archivo identificado por "$fileName". No se establece ninguna conexión a la base de datos hasta que el programa llama a tdbc::odbc::connection create.

MÉTODOS DE CONEXIÓN ADICIONALES

Además de los métodos habituales en el objeto tdbc::connection(n), las conexiones a una base de datos ODBC admiten un método adicional:

$connection
Este método toma el código SQL nativo del controlador dado sqlStatement y lo evalúa sin prepararlo. La sentencia no se tokeniza y no debe contener sustituciones de variables. La evaluación de sqlStatement produce un conjunto de resultados de cero o más filas. El resultado del comando es una lista de diccionarios, con un elemento de lista por fila en el conjunto de resultados (en un formato similar a la lista devuelta por $connection allrows -as dicts). Este comando no se recomienda para nada donde los métodos habituales prepare o preparecall funcionen correctamente. Se proporciona para que se puedan ejecutar sentencias de lenguaje de gestión de datos que no están implementadas por la API de sentencias preparadas del controlador (como CREATE DATABASE o CREATE PROCEDURE), o que contienen caracteres reservados por el tokenizador.
