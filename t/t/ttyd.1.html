NOMBRE

ttyd - Comparte tu terminal a través de la web

SINOPSIS

ttyd [opciones] <comando> [<argumentos...>]

DESCRIPCIÓN

ttyd es una herramienta de línea de comandos para compartir terminales a través de la web que se ejecuta en sistemas *nix y Windows, con las siguientes características:

  • Construido sobre Libwebsockets con libuv para velocidad
  • Terminal con todas las funciones basado en Xterm.js con soporte CJK (chino, japonés, coreano) e IME
  • Integración gráfica ZMODEM con soporte lrzsz
  • Soporte de salida de imágenes Sixel
  • Soporte SSL basado en OpenSSL
  • Ejecuta cualquier comando personalizado con opciones
  • Soporte de autenticación básica y muchas otras opciones personalizadas
  • Multiplataforma: macOS, Linux, FreeBSD/OpenBSD, OpenWrt/LEDE, Windows

OPCIONES

-p, --port
Puerto de escucha (predeterminado: 7681, usa 0 para puerto aleatorio)

-i, --interface
Interfaz de red a la que enlazar (ej: eth0), o ruta del socket de dominio UNIX (ej: /var/run/ttyd.sock)

-U, --socket-owner
Propietario del archivo de socket de dominio UNIX, cuando está habilitado (ej: usuario:grupo)

-c, --credential USER[:PASSWORD]
Credencial para Autenticación Básica (formato: usuario:contraseña)

-H, --auth-header
Nombre de la cabecera HTTP para el proxy de autenticación, esto configurará ttyd para permitir que un proxy inverso HTTP maneje la autenticación

-u, --uid
ID de usuario con el que ejecutar

-g, --gid
ID de grupo con el que ejecutar

-s, --signal
Señal a enviar al comando al salir de él (predeterminado: 1, SIGHUP)

-w, --cwd
Directorio de trabajo que se establecerá para el programa hijo

-a, --url-arg
Permite al cliente enviar argumentos de línea de comandos en la URL (ej: http://localhost:7681?arg=foo&arg=bar)

-W, --writable
Permite a los clientes escribir en el TTY (solo lectura por defecto)

-t, --client-option
Envía una opción al cliente (formato: clave=valor), repite para añadir más opciones, consulta OPCIONES DEL CLIENTE para más detalles

-T, --terminal-type
Tipo de terminal a reportar, predeterminado: xterm-256color

-O, --check-origin
No permitir conexiones websocket desde un origen diferente

-m, --max-clients
Máximo de clientes a soportar (predeterminado: 0, sin límite)

-o, --once
Aceptar solo un cliente y salir al desconectarse

-q, --exit-no-conn
Salir al desconectarse todos los clientes

-B, --browser
Abrir terminal con el navegador predeterminado del sistema

-I, --index
Ruta del archivo index.html personalizado

-b, --base-path
Ruta base esperada para las solicitudes provenientes de un proxy inverso (ej: /montado/aquí, longitud máxima: 128)

-P, --ping-interval
Intervalo de ping de Websocket (segundos) (predeterminado: 5)

-6, --ipv6
Habilitar soporte IPv6

-S, --ssl
Habilitar SSL

-C, --ssl-cert
Ruta del archivo del certificado SSL

-K, --ssl-key
Ruta del archivo de clave SSL

-A, --ssl-ca
Ruta del archivo CA SSL para la verificación del certificado del cliente

-d, --debug
Establecer nivel de registro (predeterminado: 7)

-v, --version
Imprimir la versión y salir

-h, --help
Imprimir este texto y salir

OPCIONES DEL CLIENTE

ttyd tiene un mecanismo para pasar argumentos de línea de comandos del lado del servidor a la página del navegador, lo que se denomina opciones del cliente:

-t, --client-option     Enviar opción al cliente (formato: clave=valor), repite para añadir más opciones

Uso básico

  • -t rendererType=canvas: usar el renderizador canvas para xterm.js (predeterminado: webgl)
  • -t disableLeaveAlert=true: deshabilitar la alerta de salida de página
  • -t disableResizeOverlay=true: deshabilitar la superposición de redimensionamiento de la terminal
  • -t disableReconnect=true: evitar que la terminal se reconecte en caso de error/cierre de conexión
  • -t enableZmodem=true: habilitar soporte de transferencia de archivos ZMODEM ⟨https://es.wikipedia.org/wiki/ZMODEM⟩ / lrzsz ⟨https://ohse.de/uwe/software/lrzsz.html⟩
  • -t enableTrzsz=true: habilitar soporte de transferencia de archivos trzsz ⟨https://trzsz.github.io⟩
  • -t enableSixel=true: habilitar soporte de salida de imágenes Sixel ⟨https://es.wikipedia.org/wiki/Sixel⟩ (Uso ⟨https://saitoha.github.io/libsixel/⟩)
  • -t titleFixed=hola: establecer un título fijo para la ventana del navegador
  • -t fontSize=20: cambiar el tamaño de fuente de la terminal

Uso avanzado

Puedes usar la opción del cliente para cambiar todas las configuraciones de xterm definidas en ITerminalOptions ⟨https://xtermjs.org/docs/api/terminal/interfaces/iterminaloptions/⟩, ejemplos:

  • -t cursorStyle=bar: establecer el estilo del cursor a bar
  • -t lineHeight=1.5: establecer la altura de línea a 1.5
  • -t 'theme={"background": "green"}': establecer el color de fondo a verde

para probar las opciones de ejemplo anteriores, ejecuta:

ttyd -t cursorStyle=bar -t lineHeight=1.5 -t 'theme={"background": "green"}' bash

EJEMPLOS

ttyd inicia el servidor web en el puerto 7681 por defecto, puedes usar la opción -p para cambiarlo, el comando se iniciará con los argumentos como opciones. Por ejemplo, ejecuta:

ttyd -p 8080 bash -x

Luego abre http://localhost:8080 con un navegador, obtendrás una terminal bash con el modo de depuración habilitado. Más ejemplos:

  • Si quieres iniciar sesión con tus cuentas del sistema en el navegador web, ejecuta ttyd login.
  • Incluso puedes ejecutar un comando que no sea de shell como vim, intenta: ttyd vim, el navegador web te mostrará un editor vim.
  • Compartir un único proceso con múltiples clientes: ttyd tmux new -A -s ttyd vim, ejecuta tmux new -A -s ttyd para conectarte a la sesión de tmux desde la terminal.

Cómo usar SSL

Genera certificados de CA y certificados de servidor/cliente autofirmados:

# Certificado CA (FQDN debe ser diferente al del servidor/cliente)
openssl genrsa -out ca.key 2048
openssl req -new -x509 -days 365 -key ca.key -subj "/C=CN/ST=GD/L=SZ/O=Acme, Inc./CN=Acme Root CA" -out ca.crt
# Certificado de servidor (para múltiples dominios, cambia subjectAltName a: DNS:example.com,DNS:www.example.com)
openssl req -newkey rsa:2048 -nodes -keyout server.key -subj "/C=CN/ST=GD/L=SZ/O=Acme, Inc./CN=localhost" -out server.csr
openssl x509 -sha256 -req -extfile <(printf "subjectAltName=DNS:localhost") -days 365 -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt
# Certificado de cliente (el formato p12/pem puede ser útil para algunos clientes)
openssl req -newkey rsa:2048 -nodes -keyout client.key -subj "/C=CN/ST=GD/L=SZ/O=Acme, Inc./CN=client" -out client.csr
openssl x509 -req -days 365 -in client.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out client.crt
openssl pkcs12 -export -clcerts -in client.crt -inkey client.key -out client.p12
openssl pkcs12 -in client.p12 -out client.pem -clcerts

Luego inicia ttyd:

ttyd --ssl --ssl-cert server.crt --ssl-key server.key --ssl-ca ca.crt bash

Puede que quieras probar la verificación del certificado del cliente con curl(1):

curl --insecure --cert client.p12[:password] -v https://localhost:7681

Si no quieres habilitar la verificación del certificado del cliente, elimina la opción --ssl-ca.

Docker y ttyd

Los contenedores de Docker son entornos aislados que son más seguros, esto es útil para proteger el sistema anfitrión, puede usar ttyd con docker de la siguiente manera:

  • Compartir un único contenedor de docker con múltiples clientes: docker run -it --rm -p 7681:7681 tsl0922/ttyd.
  • Crear un nuevo contenedor de docker para cada cliente: ttyd docker run -it --rm ubuntu.

Proxy inverso Nginx

Configuración de ejemplo para hacer proxy de ttyd en la ruta /ttyd:

location ~ ^/ttyd(.*)$ {
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_pass http://127.0.0.1:7681/$1;
}
