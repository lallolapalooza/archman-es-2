NOMBRE

ttk::intro - Introducción al motor de temas de Tk

DESCRIPCIÓN GENERAL

El conjunto de widgets temáticos de Tk se basa en una versión revisada y mejorada de la TIP #48 (https://tip.tcl-lang.org/48), un motor de estilos especificado. Los conceptos principales se describen a continuación. La idea básica es separar, en la medida de lo posible, el código que implementa el comportamiento de un widget del código que implementa su apariencia. Los enlaces de la clase de widget son principalmente responsables de mantener el estado del widget e invocar callbacks; todos los aspectos de la apariencia del widget son controlados por el estilo del widget (es decir, el estilo de los elementos del widget).

TEMAS

Un tema es una colección de elementos y estilos que determinan el aspecto del conjunto de widgets. Los temas se pueden utilizar para:

  • aislar diferencias de plataforma (X11 vs. Windows clásico vs. XP vs. Aqua ...)
  • adaptarse a limitaciones de pantalla (baja resolución de color, escala de grises, monocromo, pantallas diminutas)
  • accesibilidad (alto contraste, tipo grande)
  • branding de suites de aplicaciones
  • integrarse con el resto del escritorio (Gnome, KDE, Java)
  • y, por supuesto: estética.

ELEMENTOS

Un elemento muestra una parte individual de un widget. Por ejemplo, un widget de barra de desplazamiento vertical contiene los elementos uparrow, downarrow, trough y slider.

Los nombres de los elementos utilizan una notación recursiva de puntos. Por ejemplo, uparrow identifica un elemento de flecha genérico, y Scrollbar.uparrow y Combobox.uparrow identifican elementos específicos del widget. Al buscar un elemento, el motor de estilos busca primero el nombre específico y, si no se encuentra un elemento con ese nombre, busca elementos genéricos eliminando sucesivamente los componentes iniciales del nombre del elemento.

Al igual que los widgets, los elementos tienen opciones que especifican qué mostrar y cómo mostrarlo. Por ejemplo, el elemento text (que muestra una cadena de texto) tiene opciones -text, -font, -foreground, -background, -underline y -width. El valor de una opción de elemento se toma de (en orden de precedencia):

  • una opción del mismo nombre y tipo en el widget que contiene el elemento;
  • una configuración dinámica especificada por style map y el estado actual;
  • la configuración predeterminada especificada por style configure; o
  • el valor predeterminado incorporado del elemento para la opción.

DISEÑOS

Un diseño especifica qué elementos componen un widget y cómo están dispuestos. El motor de diseño utiliza una versión simplificada del algoritmo pack: comenzando con una cavidad inicial igual al tamaño del widget, se asigna a los elementos una parcela dentro de la cavidad a lo largo del lado especificado por la opción -side y se colocan dentro de la parcela de acuerdo con la opción -sticky. Por ejemplo, el diseño de una barra de desplazamiento horizontal es:

ttk::style layout Horizontal.TScrollbar {
    Scrollbar.trough -children {
	Scrollbar.leftarrow -side left -sticky w
	Scrollbar.rightarrow -side right -sticky e
	Scrollbar.thumb -sticky ew
    }
}

Por defecto, el diseño de un widget es el mismo que su nombre de clase. Algunos widgets pueden anular esto (por ejemplo, el widget ttk::scrollbar elige diferentes diseños según la opción -orient).

ESTADOS

En Tk estándar, muchos widgets tienen una opción -state que (en la mayoría de los casos) es normal o disabled. Algunos widgets admiten estados adicionales, como el widget entry que tiene un estado readonly y los diversos tipos de botones que tienen el estado active.

El conjunto de widgets temáticos de Tk generaliza esta idea: cada widget tiene un mapa de bits de indicadores de estado independientes. Los indicadores de estado del widget incluyen active, disabled, pressed, focus, etc. (ver ttk::widget(n) para la lista completa de indicadores de estado).

En lugar de una opción -state, cada widget ahora tiene un comando de widget state que se utiliza para establecer o consultar el estado. Una especificación de estado es una lista de nombres de estado simbólicos que indican qué bits están establecidos, cada uno opcionalmente prefijado con un signo de exclamación que indica que el bit está borrado en su lugar.

Por ejemplo, los enlaces de clase para el widget ttk::button son:

bind TButton <Enter>		{ %W state active }
bind TButton <Leave>		{ %W state !active }
bind TButton <ButtonPress-1>	{ %W state pressed }
bind TButton <Button1-Leave>	{ %W state !pressed }
bind TButton <Button1-Enter>	{ %W state pressed }
bind TButton <ButtonRelease-1>	\
    { %W instate {pressed} { %W state !pressed ; %W invoke } }

Esto especifica que el widget se vuelve active cuando el puntero entra en el widget, y inactivo cuando sale. De manera similar, se vuelve pressed cuando se presiona el botón del ratón, y !pressed en el evento ButtonRelease. Además, el botón se despresiona si el puntero se arrastra fuera del widget mientras se mantiene presionado el Botón-1, y se represe si se arrastra de nuevo hacia adentro. Finalmente, cuando se suelta el botón del ratón, se invoca el -command del widget, pero solo si el botón está actualmente en el estado pressed. (Los enlaces reales son un poco más complicados que los anteriores, pero no mucho).

ESTILOS

Cada widget está asociado con un estilo, que especifica valores para las opciones de los elementos. Los nombres de estilo utilizan una notación de puntos recursiva similar a los diseños y elementos; por defecto, los widgets utilizan el nombre de clase para buscar un estilo en el tema actual. Por ejemplo:

ttk::style configure TButton \
	-background #d9d9d9 \
	-foreground black \
	-relief raised \
	;

Muchos elementos se muestran de manera diferente según el estado del widget. Por ejemplo, los botones tienen un fondo diferente cuando están activos, un primer plano diferente cuando están deshabilitados y un relieve diferente cuando están presionados. El comando style map especifica configuraciones de opciones dinámicas para un estilo particular:

ttk::style map TButton \
	-background [list disabled #d9d9d9  active #ececec] \
	-foreground [list disabled #a3a3a3] \
	-relief [list {pressed !disabled} sunken] \
	;
