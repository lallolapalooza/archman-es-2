NOMBRE

Template::Tools::ttree - Procesa árboles de directorios completos de plantillas

SINOPSIS

ttree [opciones] [archivos]

DESCRIPCIÓN

El script ttree se utiliza para procesar árboles de directorios completos que contienen archivos de plantilla. El resultado del procesamiento de cada archivo se escribe en un archivo correspondiente en un directorio de destino. El script compara los tiempos de modificación de los archivos de origen y destino (donde ya existen) y procesa solo aquellos archivos que han sido modificados. En otras palabras, es el equivalente a 'make' para Template Toolkit.

Soporta una serie de opciones que se pueden utilizar para configurar el comportamiento, definir ubicaciones y establecer opciones de Template Toolkit. El script primero lee el archivo de configuración .ttreerc en el directorio HOME, o un archivo alternativo especificado en la variable de entorno TTREERC. Luego, procesa los argumentos de la línea de comandos, incluyendo cualquier archivo de configuración adicional especificado a través de la opción "-f" (archivo).

El archivo de configuración .ttreerc

Cuando ejecutas ttree por primera vez, te preguntará si quieres que cree un archivo .ttreerc para ti. Este se creará en tu directorio home.

$ ttree
¿Quieres que cree un archivo de ejemplo '.ttreerc' para ti?
(archivo: /home/abw/.ttreerc)   [y/n]: y
/home/abw/.ttreerc creado. Por favor, edítalo en consecuencia y vuelve a ejecutar ttree

El propósito de este archivo es establecer cualquier opción de configuración global que quieras que se aplique cada vez que se ejecuta ttree. Por ejemplo, puedes usar las opciones "ignore" y "copy" / "link" para proporcionar expresiones regulares que especifiquen qué archivos deben ser ignorados y cuáles deben ser copiados o enlazados en lugar de ser procesados como plantillas. También podrías querer establecer indicadores como "verbose" y "recurse" según tu preferencia.

Un .ttreerc mínimo:

# ignorar estos archivos
ignore = \b(CVS|RCS)\b
ignore = ^#
ignore = ~$
# copiar estos archivos
copy   = \.(gif|png|jpg|pdf)$
# recursar en directorios
recurse
# proporcionar información sobre lo que está sucediendo
verbose

En la mayoría de los casos, querrás crear un archivo de configuración de ttree diferente para cada proyecto en el que estés trabajando. La opción "cfg" te permite especificar un directorio donde ttree puede encontrar más archivos de configuración.

cfg = /home/abw/.ttree

La opción de línea de comandos "-f" se puede usar para especificar qué archivo de configuración se debe usar. Puedes especificar un nombre de archivo usando una ruta absoluta o relativa:

$ ttree -f /home/abw/web/example/etc/ttree.cfg
$ ttree -f ./etc/ttree.cfg
$ ttree -f ../etc/ttree.cfg

Si el archivo de configuración no comienza con "/" o "." o algo que parezca una ruta absoluta de MS-DOS (por ejemplo, "C:\\etc\\ttree.cfg"), entonces ttree lo buscará en el directorio especificado por la opción "cfg".

$ ttree -f test1          # /home/abw/.ttree/test1

La opción "cfg" solo se puede usar en el archivo .ttreerc. Todas las demás opciones se pueden usar en el .ttreerc o en cualquier otro archivo de configuración de ttree. Todas ellas también se pueden especificar como opciones de línea de comandos.

Recuerda que .ttreerc siempre se procesa antes que cualquier archivo de configuración especificado con la opción "-f". Ciertas opciones como "lib" se pueden usar cualquier número de veces y acumulan sus valores.

Por ejemplo, considera los siguientes archivos de configuración:

/home/abw/.ttreerc:

cfg = /home/abw/.ttree
lib = /usr/local/tt2/templates

/home/abw/.ttree/myconfig:

lib = /home/abw/web/example/templates/lib

Cuando ttree se invoca de la siguiente manera:

$ ttree -f myconfig

la opción "lib" se establecerá en los siguientes directorios:

/usr/local/tt2/templates
/home/abw/web/example/templates/lib

Cualquier plantilla ubicada en /usr/local/tt2/templates se usará con preferencia a las ubicadas en /home/abw/web/example/templates/lib. Esto puede ser lo que quieres, o puede que no. Por esta razón, es una buena práctica mantener el .ttreerc lo más simple posible y usar diferentes archivos de configuración para cada proyecto de ttree.

Opciones de Directorio

La opción "src" se usa para definir el directorio que contiene las plantillas fuente a procesar. Se puede proporcionar como una opción de línea de comandos o en un archivo de configuración como se muestra aquí:

src = /home/abw/web/example/templates/src

Cada plantilla en este directorio corresponde típicamente a una única página web u otro documento.

La opción "dest" se usa para especificar el directorio de destino para la salida generada.

dest = /home/abw/web/example/html

La opción "lib" se usa para definir uno o más directorios que contienen plantillas de biblioteca adicionales. Estas plantillas no son documentos en sí mismas y típicamente comprenden componentes más pequeños y modulares como encabezados, pies de página y menús que se incorporan en las plantillas de página.

lib = /home/abw/web/example/templates/lib
lib = /usr/local/tt2/templates

La opción "lib" se puede usar repetidamente para agregar más directorios a la ruta de búsqueda.

Se puede pasar una lista de plantillas a ttree como argumentos de línea de comandos.

$ ttree foo.html bar.html

Busca estas plantillas en el directorio "src" y las procesa a través de Template Toolkit, utilizando cualquier componente de plantilla adicional de los directorios "lib". La salida generada se escribe luego en el archivo correspondiente en el directorio "dest".

Si ttree se invoca sin especificar explícitamente ninguna plantilla para procesar, procesará cada archivo en el directorio "src". Si el indicador "-r" (recursar) está activado, entonces adicionalmente iterará a través de subdirectorios y procesará otros archivos de plantilla que encuentre allí.

$ ttree -r

Si una plantilla ha sido procesada previamente, ttree comparará los tiempos de modificación de los archivos de origen y destino. Si la plantilla de origen (o una de la que depende) no ha sido modificada más recientemente que el archivo de salida generado, entonces ttree no la procesará. La opción "-a" (todos) se puede usar para forzar a ttree a procesar todos los archivos independientemente del tiempo de modificación.

$ tree -a

Cualquier plantilla nombrada explícitamente como argumento de línea de comandos siempre se procesa y se omite la comprobación del tiempo de modificación.

Opciones de Archivo

Las opciones "ignore", "copy", "link" y "accept" se usan para especificar regex de Perl para filtrar nombres de archivo. Los archivos que coinciden con cualquiera de las opciones "ignore" no serán procesados. Los archivos restantes que coinciden con cualquiera de las expresiones regulares "copy" o "link" serán copiados o enlazados al directorio de destino. Los archivos que residen en cualquiera de los directorios "copy_dir" también se copian. Los archivos restantes que luego coinciden con cualquiera de los criterios "accept" se procesan a través de Template Toolkit. Si no se especifica ningún parámetro "accept", todos los archivos serán aceptados para su procesamiento si aún no han sido copiados o ignorados.

# ignorar estos archivos
ignore = \b(CVS|RCS)\b
ignore = ^#
ignore = ~$
# copiar estos archivos
copy   = \.(gif|png|jpg|pdf)$
# aceptar solo plantillas .tt2
accept = \.tt2$

NAME

ttree - Template Toolkit file processing utility

SYNOPSIS

ttree [options] <input_file ...>
ttree -h | --help
ttree -v | --version

DESCRIPTION

The ttree utility is a command-line tool for processing one or more Template Toolkit template files. It can be used to render a set of templates into a directory tree, or to simply compile templates into a single output file.

Options are defined using either the --option value syntax or by the use of a configuration file specified using the --config <file> option.

The ttree utility accepts the following options:

Input and Output

The "--output" or "-o" option specifies the output file or directory. If omitted, the output will be directed to STDOUT.

$ ttree --output output.html input.tt
$ ttree --output /tmp/web/ input/*.tt2

The "--src" or "-s" option defines the source directory for input files. Defaults to the current directory.

$ ttree --src templates/ --output html/ *.tt2

The "--lib" or "-l" option defines a library directory for input files. This is where the Template Toolkit will look for files when processing directives like "INCLUDE", "PROCESS", etc. This option can be specified multiple times.

$ ttree --lib templates/ --lib common/ --output html/

The "--define" or "-D" option defines a template variable.

$ ttree --define USER=andy --define HOST=localhost

The "--define" option can also take arguments from a file:

$ ttree -D file.def

The "--vars" option is similar to "--define" but can only be used once and takes a comma-separated list of variables.

$ ttree --vars USER=andy,HOST=localhost

The "--include" or "-I" option is a synonym for "--lib".

The "--plugin" option allows you to specify paths to custom plugin directories.

$ ttree --plugin custom_plugins/

The "--include_plugins" option allows you to specify paths to custom plugin directories that will be searched *in addition* to the standard plugin paths.

$ ttree --include_plugins custom_plugins/

The "--require" option allows you to load Perl modules before processing templates.

$ ttree --require Some::Module

The "--require_all" option loads all modules listed in a file.

$ ttree --require_all modules.lst

The "--compile" or "-c" option causes templates to be compiled to bytecode but not executed.

The "--debug" option enables debugging output for the Template Toolkit.

$ ttree --debug all

The "--trim", "--trim_blocks", "--pre_trim_whitespace", "--post_trim_whitespace", "--epsilon", "--line_numbers", "--tabstop", "--default_dir", "--search_path", "--relative" and "--absolute" options all correspond to Template Toolkit configuration options and control how whitespace is handled, error reporting, and file path resolution.

The "suffix" option is used to define mappings between the file extensions for source templates and the generated output files. The following example specifies that source templates with a ".tt2" suffix should be output as ".html" files:

suffix tt2=html

Or on the command line,

--suffix tt2=html

You can provide any number of different suffix mappings by repeating this option.

The "binmode" option is used to set the encoding of the output file. For example use "--binmode=:utf8" to set the output format to unicode.

Template Dependencies

The "depend" and "depend_file" options allow you to specify how any given template file depends on another file or group of files. The "depend" option is used to express a single dependency.

$ ttree --depend foo=bar,baz

This command line example shows the "--depend" option being used to specify that the foo file is dependant on the bar and baz templates. This option can be used many time on the command line:

$ ttree --depend foo=bar,baz --depend crash=bang,wallop

or in a configuration file:

depend foo=bar,baz
depend crash=bang,wallop

The file appearing on the left of the "=" is specified relative to the "src" or "lib" directories. The file(s) appearing on the right can be specified relative to any of these directories or as absolute file paths.

For example:

$ ttree --depend foo=bar,/tmp/baz

To define a dependency that applies to all files, use "*" on the left of the "=".

$ ttree --depend *=header,footer

or in a configuration file:

depend *=header,footer

Any templates that are defined in the "pre_process", "post_process", "process" or "wrapper" options will automatically be added to the list of global dependencies that apply to all templates.

The "depend_file" option can be used to specify a file that contains dependency information.

$ ttree --depend_file=/home/abw/web/example/etc/ttree.dep

Here is an example of a dependency file:

# This is a comment. It is ignored.
index.html: header footer menubar
header: titlebar hotlinks
menubar: menuitem
# spanning multiple lines with the backslash
another.html: header footer menubar \
sidebar searchform

Lines beginning with the "#" character are comments and are ignored. Blank lines are also ignored. All other lines should provide a filename followed by a colon and then a list of dependant files separated by whitespace, commas or both. Whitespace around the colon is also optional. Lines ending in the "\" character are continued onto the following line.

Files that contain spaces can be quoted. That is only necessary for files after the colon (':'). The file before the colon may be quoted if it contains a colon.

As with the command line options, the "*" character can be used as a wildcard to specify a dependency for all templates.

* : config,header

Template Toolkit Options

ttree also provides access to the usual range of Template Toolkit options. For example, the "--pre_chomp" and "--post_chomp" ttree options correspond to the "PRE_CHOMP" and "POST_CHOMP" options.

Run "ttree -h" for a summary of the options available.
