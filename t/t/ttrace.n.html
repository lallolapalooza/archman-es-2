NOMBRE

ttrace - Inicialización de intérprete basada en trazas

SINOPSIS

package require Tcl 8.4

package require Thread ?2.8?

ttrace::eval arg ?arg ...?

ttrace::enable

ttrace::disable

ttrace::cleanup

ttrace::update ?epoch?

ttrace::getscript

ttrace::atenable cmd arglist body

ttrace::atdisable cmd arglist body

ttrace::addtrace cmd arglist body

ttrace::addscript name body

ttrace::addresolver cmd arglist body

ttrace::addcleanup body

ttrace::addentry cmd var val

ttrace::getentry cmd var

ttrace::getentries cmd ?pattern?

ttrace::delentry cmd

ttrace::preload cmd

DESCRIPCIÓN

Este paquete crea un framework para la replicación bajo demanda del estado del intérprete entre hilos en una aplicación multihilo. Se basa en la mecánica del trazado de comandos de Tcl y el comando y mecanismo unknown de Tcl.

El paquete requiere la extensión de hilos de Tcl, pero puede usarse alternativamente de forma independiente dentro de AOLserver, un servidor web escalable de America Online.

En pocas palabras, un pequeño ejemplo que ilustra el uso de ttrace con la extensión de hilos de Tcl:

    % package require Ttrace
    2.8.0
    % set t1 [thread::create {package require Ttrace; thread::wait}]
    tid0x1802800
    % ttrace::eval {proc test args {return test-[thread::id]}}
    % thread::send $t1 test
    test-tid0x1802800
    % set t2 [thread::create {package require Ttrace; thread::wait}]
    tid0x1804000
    % thread::send $t2 test
    test-tid0x1804000

Como se ve arriba, los comandos ttrace::eval y ttrace::update se utilizan para crear una definición a nivel de hilo de un procedimiento Tcl simple y replicar esa definición en todos los hilos ya existentes o creados posteriormente.

COMANDOS_DE_USUARIO

Esta sección describe los comandos a nivel de usuario. Estos comandos pueden ser utilizados por los escritores de scripts para controlar la ejecución del framework de trazado.

ttrace::eval arg ?arg ...?
Este comando concatena los argumentos dados y evalúa el comando Tcl resultante con el framework de trazado habilitado. Si la ejecución del comando fue exitosa, toma las medidas necesarias para propagar automáticamente el cambio de época de trazado a todos los hilos de la aplicación. Para AOLserver, solo los hilos recién creados reciben realmente el cambio de época. Para la extensión de hilos de Tcl, todos los hilos creados por la extensión se actualizan automáticamente. Si la ejecución del comando resultó en un error de Tcl, no se produce ninguna propagación del estado.

Este es el comando de nivel de usuario más importante del paquete, ya que encapsula la mayoría de los comandos descritos a continuación. Esto simplifica enormemente las cosas, ya que el usuario solo necesita aprender este (único) comando para utilizar eficazmente el paquete. Otros comandos, como se describe a continuación, se incluyen principalmente por razones de completitud.

ttrace::enable
Activa todas las devoluciones de llamada registradas en el framework y inicia una nueva época de trazado. La época de trazado encapsula todos los cambios realizados en el intérprete durante el tiempo que las trazas están activas.
ttrace::disable
Desactiva todas las devoluciones de llamada registradas en el framework y cierra la época de trazado actual.
ttrace::cleanup
Se utiliza para limpiar todos los recursos cargados bajo demanda en el intérprete. Devuelve efectivamente el intérprete Tcl a su estado prístino.
ttrace::update ?epoch?
Se utiliza para actualizar el estado del intérprete para que coincida con la ?época? de trazado opcional. Si la ?época? opcional no se proporciona, toma la época de trazado más reciente.
ttrace::getscript
Devuelve un script Tcl sintetizado que puede ser sourced en cualquier intérprete. Este script prepara el escenario para el comando unknown de Tcl para que pueda cargar recursos trazados desde la base de datos en memoria. Normalmente, este comando es invocado automáticamente por otros comandos de nivel superior como ttrace::eval y ttrace::update.

COMANDOS_DE_DEVOLUCION_DE_LLAMADA

Una palabra por adelantado: el paquete ya incluye devoluciones de llamada para rastrear los siguientes comandos Tcl: proc, namespace, variable, load y rename. Adicionalmente, también se proporciona un conjunto de devoluciones de llamada para rastrear recursos (objetos, clases) para XOTcl v1.3.8+, una extensión OO a Tcl. Esto proporciona una base sólida para resolver la mayoría de las necesidades de la vida real y sirve como ejemplo para las personas que deseen personalizar el paquete para cubrir sus necesidades específicas.

A continuación, encontrará comandos para registrar devoluciones de llamada en el framework y para escribir scripts de devoluciones de llamada. Estas devoluciones de llamada son invocadas por el framework para recopilar cambios en el estado del intérprete, construir una base de datos en memoria, realizar limpiezas personalizadas y otras tareas diversas.

ttrace::atenable cmd arglist body
Registra una devolución de llamada Tcl para ser activada en ttrace::enable. Las devoluciones de llamada registradas se activan por orden FIFO. La definición de la devolución de llamada incluye el nombre de la devolución de llamada, cmd, una lista de argumentos de la devolución de llamada, arglist y el cuerpo de la devolución de llamada. Efectivamente, esto se parece a la interfaz de llamada del comando estándar proc de Tcl.
ttrace::atdisable cmd arglist body
Registra una devolución de llamada Tcl para ser activada en ttrace::disable. Las devoluciones de llamada registradas se activan por orden FIFO. La definición de la devolución de llamada incluye el nombre de la devolución de llamada, cmd, una lista de argumentos de la devolución de llamada, arglist y el cuerpo de la devolución de llamada. Efectivamente, esto se parece a la interfaz de llamada del comando estándar proc de Tcl.
ttrace::addtrace cmd arglist body
Registra una devolución de llamada Tcl para ser activada para rastrear el comando cmd de Tcl. La definición de la devolución de llamada incluye el nombre del comando Tcl a rastrear, cmd, una lista de argumentos de la devolución de llamada, arglist y el cuerpo de la devolución de llamada. Efectivamente, esto se parece a la interfaz de llamada del comando estándar proc de Tcl.
ttrace::addscript name body
Registra una devolución de llamada Tcl para ser activada para construir un script Tcl que se pasará a otros intérpretes. Este script se utiliza para preparar el escenario para el comando unknown de Tcl. Las devoluciones de llamada registradas se activan por orden FIFO. La definición de la devolución de llamada incluye el nombre de la devolución de llamada, name y el cuerpo de la devolución de llamada.
ttrace::addresolver cmd arglist body
Registra una devolución de llamada Tcl para ser activada por el comando Tcl sobrecargado unknown. Las devoluciones de llamada registradas se activan por orden FIFO. Esta devolución de llamada se utiliza para resolver el recurso y cargar el recurso en el intérprete actual.
ttrace::addcleanup body
Registra una devolución de llamada Tcl para ser activada por trace::cleanup. Las devoluciones de llamada registradas se activan por orden FIFO.
ttrace::addentry cmd var val
Añade una entrada a la base de datos con nombre en memoria.
ttrace::getentry cmd var
Devuelve el valor de la entrada de la base de datos con nombre en memoria.
ttrace::getentries cmd ?pattern?
Devuelve una lista de todas las entradas que coinciden con el ?patrón? dado de la base de datos con nombre en memoria.
ttrace::delentry cmd
Elimina una entrada de la base de datos con nombre en memoria.
ttrace::preload cmd
Registra el comando cmd Tcl para ser pre-cargado en el intérprete actual. Esto es particularmente útil para que los comandos de los paquetes externos estén disponibles antes de que las trazas se activen.

ttrace(n) - Arch Linux man pages

NAME

ttrace

command tracing facilities

SYNOPSIS

package require Tcl
package require ttrace

DESCRIPTION

This package provides facilities for tracing Tcl commands in order to build an in-memory database of resources that can be used for state replication across threads or interpreters.

USER COMMANDS

ttrace::getentries cmd ?pattern?
Devuelve los nombres de todas las entradas de la base de datos en memoria con el nombre dado.
ttrace::delentry cmd
Elimina una entrada de la base de datos en memoria con el nombre dado.
ttrace::preload cmd
Registra el comando Tcl que se cargará en el intérprete. Los comandos registrados de esta manera siempre formarán parte del intérprete y no se cargarán bajo demanda mediante el comando unknown de Tcl.

CALLBACK COMMANDS

ttrace::getentries cmd ?pattern?
Returns names of all entries from the named in-memory database.
ttrace::delentry cmd
Deletes an entry from the named in-memory database.
ttrace::preload cmd
Registers the Tcl command to be loaded in the interpreter. Commands registered this way will always be the part of the interpreter and not be on-demand loaded by the Tcl unknown command.

DISCUSSION

Los enfoques comunes de replicación de estado introspectivo utilizan un script Tcl personalizado para introspeccionar el intérprete en ejecución y sintetizar otro script Tcl para replicar este estado en otro intérprete. Este paquete, por el contrario, utiliza rastreos de comandos Tcl. Los rastreos de comandos se registran en comandos Tcl seleccionados, como proc, namespace, load y otros comandos Tcl estándar (y/o definidos por el usuario). Cuando se activan, esos rastreos construyen una base de datos en memoria de los recursos creados. Esta base de datos se utiliza como un repositorio de recursos para el comando Tcl unknown (sobrecargado) que crea el recurso solicitado en el intérprete bajo demanda. De esta manera, los usuarios pueden actualizar solo un intérprete (maestro) en un hilo y replicar ese estado del intérprete (o parte de él) a otros hilos/intérpretes en el proceso.

El beneficio inmediato de tal enfoque es la huella de memoria mucho menor de la aplicación y la creación de hilos mucho más rápida. Al no cargar realmente todos los procedimientos necesarios (y otros recursos) en cada hilo en el momento de la inicialización del hilo, sino al diferir esto hasta el momento en que el recurso se referencia realmente, se pueden lograr mejoras significativas tanto en el consumo de memoria como en el tiempo de inicialización del hilo. Algunas pruebas han demostrado que la huella de memoria de una aplicación Tcl multihilo se redujo más de tres veces y el tiempo de inicio del hilo se redujo aproximadamente 50 veces. Tenga en cuenta que sus resultados pueden variar. Otros beneficios incluyen un control mucho más fino sobre qué (y cuándo) se replica del maestro a otros hilos/intérpretes de Tcl.
