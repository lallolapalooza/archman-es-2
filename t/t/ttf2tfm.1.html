NOMBRE

ttf2tfm - crea archivos métricos TeX a partir de una fuente TrueType

SINOPSIS

ttf2tfm
archivo_ttf[.ttf|.ttc] [-c factor-altura-mayúsculas] [-e factor-extension] [-E id-codificación] [-f índice-fuente] [-l] [-L archivo-ligaduras[.sfd]] [-n] [-N] [-O] [-p archivo_codificación_entrada[.enc]] [-P id-plataforma] [-q] [-r nombre-glifo-antiguo nombre-glifo-nuevo] [-R archivo-reemplazo[.rpl]] [-s factor-inclinación] [-t archivo_codificación_salida[.enc]] [-T archivo_codificación_entrada_salida[.enc]] [-u] [-v archivo-vpl[.vpl]] [-V archivo-vpl-escala[.vpl]] [-w] [-x] [-y factor-desplazamiento-vertical] archivo_tfm[.tfm]]

ttf2tfm --version | --help

DESCRIPCIÓN

Este programa extrae la información métrica y de kerning de una fuente TrueType y la convierte en archivos métricos utilizables por TeX (muy similar a afm2tfm, que forma parte del paquete dvips; consulta sus archivos de información para más detalles sobre los diversos parámetros (especialmente archivos de codificación).

Dado que una fuente TrueType a menudo contiene más de 256 glifos, se necesitan algunos medios para mapear un subconjunto de los glifos TrueType a una fuente TeX. Para hacer esto, se necesitan dos tablas de mapeo: la primera (llamada codificación de `entrada' o `cruda') mapea la fuente TrueType a una fuente TeX cruda (esta tabla de mapeo es utilizada tanto por ttf2tfm como por ttf2pk), y la segunda (llamada codificación de `salida' o `virtual') mapea la fuente TeX cruda a otra fuente TeX (virtual), proporcionando toda la información de kerning y ligaduras necesaria para TeX.

Este mapeo en dos etapas tiene la ventaja de que una fuente cruda puede ser accedida con varias codificaciones LaTeX (por ejemplo, T1 y OT1) a través del mecanismo de fuentes virtuales, y solo se necesita un archivo PK.

Para fuentes CJKV (chino/japonés/coreano/vietnamita antiguo), se proporciona un mecanismo diferente (ver ARCHIVOS DE DEFINICIÓN DE SUBFUENTES a continuación).

PARÁMETROS

La mayoría de los nombres de los interruptores de línea de comandos son los mismos que en afm2tfm por conveniencia. Uno o más espacios entre una opción y su valor son obligatorios; las opciones no se pueden concatenar. Por razones históricas, el primer parámetro no puede ser un interruptor, sino que debe ser el nombre de la fuente.

-c factor-altura-mayúsculas
La altura de las mayúsculas pequeñas creadas con el interruptor -V. El valor predeterminado de este número real es 0.8 veces la altura de los glifos mayúsculos.
Se ignorará en modo subfuente.
-e factor-extension
El factor de extensión para estirar los caracteres horizontalmente. El valor predeterminado de este número real es 1.0; si es menor que 1.0, obtendrá una fuente condensada.
-E id-codificación
El ID de codificación TrueType. El valor predeterminado de este entero no negativo es 1.
Se ignorará si se usa -N.
-f índice-fuente
El índice de la fuente en una Colección TrueType. El predeterminado es la primera fuente (índice 0). [Las colecciones TrueType suelen encontrarse en algunas fuentes CJK; por ejemplo, el primer índice de fuente especifica glifos y métricas para escritura horizontal, y el segundo índice de fuente hace lo mismo para escritura vertical. Las colecciones TrueType suelen tener la extensión `.ttc'.]
Se ignorará para fuentes TrueType ordinarias.
-l
Crea ligaduras en subfuentes entre el primer y segundo byte de todos los códigos de caracteres originales. Ejemplo: El código de carácter 0xABCD se mapea a la posición de carácter 123 en la subfuente 45. Entonces se producirá una ligadura en la subfuente 45 entre las posiciones 0xAB y 0xCD que apunte al carácter 123. Las fuentes del paquete HLaTeX coreano usan esta característica. Tenga en cuenta que esta opción genera ligaduras correctas solo para fuentes TrueType donde el cmap de entrada es idéntico a la codificación de salida. En el caso de HLaTeX, los TTF deben tener el ID de plataforma 3 y el ID de codificación 5.
Se ignorará si no está en modo subfuente.
-L archivo-ligaduras
Igual que -l, pero los códigos de caracteres para las ligaduras se especifican en archivo-ligaduras. Por ejemplo, `-L KS-HLaTeX' genera ligaduras correctas para el paquete HLaTeX coreano independientemente de la plataforma y el ID de codificación de la fuente TrueType utilizada (el archivo KS-HLaTeX.sfd es parte del paquete ttf2pk).
Los archivos de ligaduras tienen el mismo formato y extensión que los archivos SFD. Esta opción se ignorará si no está en modo subfuente.
-n
Usa nombres PS (de glifos) de la fuente TrueType. Solo se utilizan los glifos con una entrada válida en el cmap seleccionado.
Se ignorará en modo subfuente.
-N
Usa solo nombres PS de la fuente TrueType. No se utiliza ningún cmap, por lo que los interruptores -E y -P no tienen efecto, lo que genera un mensaje de advertencia.
Se ignorará en modo subfuente.
-O
Usa valores octales para todos los códigos de caracteres en el archivo VPL en lugar de nombres; esto es útil para fuentes de símbolos o CJK donde los nombres de caracteres como `A' no tienen sentido.
-p archivo_codificación_entrada
El nombre del archivo de codificación de entrada para el mapeo TTF→crudo TeX. Este parámetro debe especificarse en un archivo de mapeo (predeterminado: ttfonts.map) registrado en ttf2pk.cfg para llamadas sucesivas a ttf2pk.
Se ignorará en modo subfuente.
-P id-plataforma
El ID de plataforma TrueType. El valor predeterminado de este entero no negativo es 3.
Se ignorará si se usa -N.
-q
Hace que ttf2tfm sea silencioso. Suprime cualquier salida informativa excepto mensajes de advertencia y error. Para fuentes CJK, la salida puede ser bastante grande si no se especifica este interruptor.
-r nombre-glifo-antiguo nombre-glifo-nuevo
Reemplaza nombre-glifo-antiguo con nombre-glifo-nuevo. Este interruptor es útil si desea dar un nombre a un glifo sin nombre (es decir, un glifo que solo puede representarse con `.gXXX' o `.cXXX') o si desea renombrar un nombre de glifo ya existente. No puede usar las construcciones de nombre de glifo `.gXXX' o `.cXXX' para nombre-glifo-nuevo; son posibles múltiples ocurrencias de -r.
Si está en modo subfuente o si no se especifica ningún archivo de codificación, este interruptor se ignora.
-R archivo-reemplazo
Use este interruptor si tiene muchos pares de reemplazo; se pueden recopilar en un archivo que debería tener la extensión `.rpl'. La sintaxis utilizada en dichos archivos de reemplazo es simple: Cada línea no vacía debe contener un par `nombre-glifo-antiguo nombre-glifo-nuevo' separado por espacios en blanco (sin las comillas). Un signo de porcentaje inicia un comentario de línea; puede continuar una línea en la siguiente línea con una barra invertida como último carácter.
Si está en modo subfuente o si no se especifica ningún archivo de codificación, este interruptor se ignora.
-s factor-inclinación
El factor de oblicuidad para inclinar la fuente, generalmente mucho menor que 1. El valor predeterminado de este número real es 0.0; si el valor es mayor que cero, los caracteres se inclinan hacia la derecha, de lo contrario hacia la izquierda.
-t�
-A0 outencfile
El nombre del archivo de codificación de salida para las fuentes virtuales. Solo se utilizan los caracteres de la fuente TeX sin procesar.
Se ignorará en el modo de subfuente.
-T inoutencfile
Esto es equivalente a `-p inoutencfile -t inoutencfile'.
Se ignorará en el modo de subfuente.
-u
Utilizar solo aquellos caracteres especificados en la codificación de salida, y ningún otro. Por defecto, ttf2tfm intenta incluir todos los caracteres de la fuente virtual, incluso aquellos que no están presentes en la codificación de la fuente virtual (los coloca en posiciones no utilizadas, de forma bastante arbitraria).
Se ignorará en el modo de subfuente.
-v vplfile
Generar un archivo VPL además del archivo TFM. Si no se especifica un archivo de codificación de salida, ttf2tfm utiliza una codificación de fuente por defecto (cmtt10). Nota: ¡Tenga cuidado de usar nombres diferentes para la fuente virtual y la fuente sin procesar!
Se ignorará en el modo de subfuente.
-V scvplfile
Igual que -v, pero la fuente virtual generada es una fuente de mayúsculas pequeñas pseudo obtenida escalando las letras mayúsculas en 0.8 (respectivamente, el valor especificado con -c) para componer minúsculas. Esta fuente maneja letras acentuadas y conserva el kerning adecuado.
Se ignorará en el modo de subfuente.
-w
Generar vectores de codificación PostScript que contengan índices de glifos, utilizados principalmente para incrustar fuentes TrueType en pdfTeX. ttf2tfm toma los nombres TFM y reemplaza la extensión con .enc; es decir, para los archivos foo01.tfm, foo02.tfm, ... crea foo01.enc, foo02.enc, ... en el mismo lugar.
Se ignorará si no está en modo de subfuente.
-x
Rotar todos los glifos 90 grados en sentido antihorario. Si no se proporciona un parámetro -y, los glifos rotados se desplazarán verticalmente hacia abajo en 0.25em.
Se ignorará si no está en modo de subfuente.
-y vertical-shift-factor
Desplazar hacia abajo los glifos rotados la cantidad dada (la unidad es em).
Se ignorará si no está en modo de subfuente o si los glifos no están rotados.
--version
Muestra la versión actual de ttf2tfm y la biblioteca de búsqueda de archivos utilizada (por ejemplo, kpathsea).
--help
Muestra información de uso.

Si no se proporciona un nombre de archivo TFM, se utiliza el nombre del archivo TTF, incluyendo la ruta completa y reemplazando la extensión por `.tfm'.

CMAPS

A diferencia de las fuentes PostScript Type 1 (pero similar al nuevo formato de fuente PostScript CID), la mayoría de las fuentes TrueType tienen más de una tabla de mapeo nativa, también llamada `cmap', que mapea los índices de glifos TTF (internos) a los códigos de caracteres TTF (externos). Ejemplos comunes son una tabla de mapeo a posiciones de caracteres codificados en Unicode y el mapeo estándar de Macintosh.

Tenga en cuenta que la mayoría de las fuentes tienen como máximo dos o tres cmaps, que corresponden a los pares pid/eid (1,0), (3,0) o (3,1) en el caso de fuentes basadas en latín. Las fuentes de Microsoft válidas deben tener una tabla de mapeo (3,1), pero existen algunas fuentes (principalmente fuentes asiáticas) que tienen un cmap (3,1) no codificado en Unicode. La razón de este comportamiento extraño es el hecho de que algunas versiones antiguas de MS Windows rechazarán fuentes que tengan un cmap no-(3,1) (ya que todos los IDs de codificación de Microsoft no-Unicode son para versiones asiáticas de MS Windows).

Las opciones -P y -E de ttf2tfm deben especificarse de la misma manera para ttf2pk; los parámetros correspondientes en un archivo de mapa son `Pid' y `Eid', respectivamente.

El par pid/eid por defecto es (3,1).

De manera similar, una opción -f debe especificarse como el parámetro `Fontindex' en un archivo de mapa.

Si utiliza el modificador -N, se ignoran todos los cmaps, utilizando solo los nombres PostScript de la fuente TrueType. La opción correspondiente en un archivo de mapa es `PS=Only'. Si utiliza el modificador -n, los nombres de glifo por defecto incorporados en ttf2tfm se reemplazan por los nombres de glifo PS encontrados en la fuente. En muchos casos, esto no es lo que desea porque los nombres de glifo en la fuente a menudo son incorrectos o no estándar. La opción correspondiente en un archivo de mapa es `PS=Yes'.

Los nombres de glifo de reemplazo únicos especificados con -r deben proporcionarse directamente como `nombre-glifo-antiguo nombre-glifo-nuevo' en un archivo de mapa; -R es equivalente a la opción `Replacement'.

CODIFICACIONES DE ENTRADA Y SALIDA

Debe especificar los vectores de codificación de la fuente TrueType a la fuente TeX sin procesar y de la fuente TeX sin procesar a la fuente TeX virtual exactamente como con afm2tfm, pero tiene más posibilidades para dirigir los códigos de caracteres. [Con `vector de codificación' se entiende una tabla de mapeo con 256 entradas en forma de vector PostScript; vea el archivo T1-WGL4.enc de este paquete como ejemplo.] Con afm2tfm, debe acceder a cada glifo por su nombre de glifo de Adobe, por ejemplo, `/quotedsingle' o `/Acircumflex'. Esto se ha ampliado con ttf2tfm; ahora puede (y a veces debe) acceder a los puntos de código y/o glifos directamente, utilizando la siguiente sintaxis para especificar la posición del carácter en notación decimal, octal o hexadecimal: `/.c<número-decimal>', `/.c0<número-octal>', o `/.c0x<número-hexadecimal>'. Ejemplos: `/.c72', `/.c0646', `/.c0x48'. Para acceder directamente a un índice de glifo, utilice el carácter `g' en lugar de `c' en la notación recién introducida. Ejemplo: `/.g0x32'. [Nota: La notación `.cXXX' no tiene sentido si se utiliza -N.]

Para los pares pid/eid (1,0) y (3,1), tanto ttf2tfm como ttf2pk reconocen nombres de glifos Adobe predeterminados incorporados; el primero sigue los nombres dados en el Apéndice E del libro `Inside Macintosh', volumen 6, el segundo utiliza los nombres dados en la Especificación TrueType (WGL4, un subconjunto de Unicode). Tenga en cuenta que los nombres Adobe para un glifo dado a menudo no son únicos y a veces difieren, por ejemplo, muchas fuentes PS tienen el glifo `mu', mientras que este glifo se llama `mu1' en el conjunto de caracteres WGL4 para distinguirlo de la letra griega real mu. Tenga en cuenta también que las fuentes OpenType (es decir, TrueType 2.0) utilizan una tabla WGL4 actualizada; utilizamos los datos de la última especificación TrueType publicada (1.66). Puede encontrar esas tablas de mapeo en el archivo de código fuente ttfenc.c.

OPTIONS

ttf2tfm read in and use the PostScript names in the TrueType font itself (stored in the `post' table) instead of the default Adobe glyph names.

Use the -r switch to remap single glyph names and -R to specify a file containing replacement glyph name pairs.

If you don't select an input encoding, the first 256 glyphs of the TrueType font with a valid entry in the selected cmap will be mapped to the TeX raw font (without the -q option, ttf2tfm prints this mapping table to standard output), followed by all glyphs not yet addressed in the selected cmap. However, some code points for the (1,0) pid/eid pair are omitted since they do not represent glyphs useful for TeX: 0x00 (null), 0x08 (backspace), 0x09 (horizontal tabulation), 0x0d (carriage return), and 0x1d (group separator). The `invalid character' with glyph index 0 will be omitted too.

If you select the -N switch, the first 256 glyphs of the TrueType font with a valid PostScript name will be used in case no input encoding is specified. Again, some glyphs are omitted: `.notdef', `.null', and `nonmarkingreturn'.

If you don't select an output encoding, ttf2tfm uses the same mapping table as afm2tfm would use (you can find it in the source code file texenc.c); it corresponds to TeX typewriter text. Unused positions (either caused by empty code points in the mapping table or missing glyphs in the TrueType font) will be filled (rather arbitrarily) with characters present in the input encoding but not specified in the output encoding (without the -q option ttf2tfm prints the final output encoding to standard output). Use the -u option if you want only glyphs in the virtual font which are defined in the output encoding file, and nothing more.

One feature missing in afm2tfm has been added which is needed by LaTeX's T1 encoding: ttf2tfm will construct the glyph `Germandbls' (by simply concatenating two `S' glyphs) even for normal fonts if possible. It appears in the glyph list as the last item, marked with an asterisk. Since this isn't a real glyph it will be available only in the virtual font.

For both input and output encoding, an empty code position is represented by the glyph name `/.notdef'.

In encoding files, you can use `\' as the final character of a line to indicate that the input is continued on the next line. The backslash and the following newline character will be removed.

SUBFONT DEFINITION FILES

CJKV (Chinese/Japanese/Korean/old Vietnamese) fonts usually contain several thousand glyphs; to use them with TeX it is necessary to split such large fonts into subfonts. Subfont definition files (usually having the extension `.sfd') are a simple means to do this smoothly.

A subfont file name usually consists of a prefix, a subfont infix, and a postfix (which is empty in most cases), e.g.


ntukai23 → prefix: ntukai, infix: 23, postfix: (empty)

Here the syntax of a line in an SFD file, describing one subfont:

<whitespace> <infix> <whitespace> <ranges> <whitespace>
<infix> :=
anything except whitespace. It is best to use only alphanumerical characters.
<whitespace> :=
space, formfeed, carriage return, horizontal and vertical tabs -- no newline characters.
<ranges> :=
<ranges> <whitespace> <codepoint> |
<ranges> <whitespace> <range> |
<ranges> <whitespace> <offset> <whitespace> <range>
<codepoint> :=
<number>
<range> :=
<number> `_' <number>
<offset> :=
<number> `:'
<number> :=
hexadecimal (prefix `0x'), decimal, or octal (prefix `0')

A line can be continued on the next line with a backslash ending the line. The ranges must not overlap; offsets have to be in the range 0-255.

Example:


The line


03 10: 0x2349 0x2345_0x2347


assigns to the code positions 10, 11, 12, and 13 of the subfont having the infix `03' the character codes 0x2349, 0x2345, 0x2346, and 0x2347 respectively.

The SFD files in the distribution are customized for the CJK package for LaTeX.

You have to embed the SFD file name into the TFM font name (at the place where the infix will appear) surrounded by two `@' signs, on the command line resp. a map file; both ttf2tfm and ttf2pk switch then to subfont mode.

It is possible to use more than a single SFD file by separating them with commata and no whitespace; for a given subfont, the first file is scanned for an entry, then the next file, and so on. Later entries override entries found earlier (possibly only partially). For example, the first SFD file sets up range 0x10-0xA0, and the next one modifies entries 0x12 and 0x25. As can be easily seen, this algorithm allows for adding and replacing, but not for removing entries.

Subfont mode disables the options -n, -N, -p, -r, -R, -t, -T, -u, -v, -V and -w for ttf2tfm; similarly, no `Encoding' or `Replacement' parameter is allowed in a map file. Single replacement glyph names are ignored too.

ttf2tfm will create all subfont TFM files specified in the SFD files (provided the subfont contains glyphs) in one run.

Example:


The call


ttf2tfm ntukai.ttf ntukai@Big5,Big5-supp@


will use Big5.sfd and Big5-supp.sfd, producing all subfont files ntukai01.tfm, ntukai02.tfm, etc.

RETURN VALUE

ttf2tfm returns 0 on success and 1 on error; warning and error messages are written to standard error.

SOME NOTES ON FILE SEARCHING

Both ttf2pk and ttf2tfm use either the kpathsea, emtexdir, or MiKTeX library for searching files (emtexdir will work only on operating systems which have an MS-DOSish background, i.e. MS-DOS, OS/2, Windows; MikTeX is specific to MS Windows).

As a last resort, both programs can be compiled without a search library; the searched files must be then in the current directory or specified with a path. Default extensions will be appended also (with the exception that only `.ttf' is appended and not `.ttc').

kpathsea

The actual version of kpathsea is displayed on screen if you call either ttf2pk or ttf2tfm with the --version command line switch.

Here is a table of the file type and the corresponding kpathsea variables. TTF2PKINPUTS and TTF2TFMINPUTS are program specific environment variables introduced in kpathsea version 3.2:

.ttf and .ttc TTFONTS
ttf2pk.cfg TTF2PKINPUTS
.map TTF2PKINPUTS
.enc TTF2PKINPUTS, TTF2TFMINPUTS
.rpl TTF2PKINPUTS, TTF2TFMINPUTS
.tfm TFMFONTS
.sfd TTF2PKINPUTS, TTF2TFMINPUTS

Please consult the info files of kpathsea for details on these variables.

You should set the TEXMFCNF variable to the directory where your texmf.cnf configuration file resides.

Here is the proper command to find out to which value a kpathsea variable is set (we use TTFONTS as an example). This is especially useful if a variable isn't set in texmf.cnf or in the environment, thus pointing to the default value which is hard-coded into the kpathsea library.

kpsewhich -progname=ttf2tfm -expand-var='$TTFONTS'

We select the program name also since it is possible to specify variables which are searched only for a certain program -- in our example it would be TTFONTS.ttf2tfm.

A similar but not identical method is to say


kpsewhich -progname=ttf2tfm -show-path='truetype fonts'

[A full list of format types can be obtained by saying `kpsewhich --help' on the command line prompt.] This is exactly how ttf2tfm (and ttf2pk) searches for files; the disadvantage is that all variables are expanded which can cause very long strings.

emtexdir

Here the list of suffixes and their related environment variables to be set in autoexec.bat (resp. in config.sys for OS/2):

.ttf and .ttc TTFONTS
ttf2pk.cfg TTFCFG
.map TTFCFG
.enc TTFCFG
.rpl TTFCFG
.tfm TEXTFM
.sfd TTFCFG

If one of the variables isn't set, a warning message is emitted. The current directory will always be searched. As usual, one exclamation mark appended to a directory path causes subdirectories one level deep to be searched, two exclamation marks cause all subdirectories to be searched. Example:


TTFONTS=c:\fonts\truetype!!;d:\myfonts\truetype!

Constructions like `c:\fonts!!\truetype' aren't possible.

MiKTeX

Both ttf2tfm and ttf2pk have been fully integrated into MiKTeX. Please refer to the documentation of MiKTeX for more details on file searching.

PROBLEMS

El encabezado de los archivos de fuente TFM, que se basa en el formato de los archivos de fuente PostScript Type 1 (PFM), es de solo 60 bytes de longitud. Esto es insuficiente para las fuentes TrueType, que a menudo necesitan una gran cantidad de información adicional, como por ejemplo, información sobre la tabla de kerning de la fuente. Los 60 bytes se distribuyen de la siguiente manera: 2 bytes para el identificador de archivo, 2 bytes para el código de revisión, 2 bytes para el número de pares de caracteres, 2 bytes para el número de extensiones, 2 bytes para el número de caracteres, 2 bytes para el número de bloques de datos, 4 bytes para el tamaño de la tabla de encabezado, 2 bytes para el tamaño del encabezado, 2 bytes para el tamaño de la tabla de encabezado, 2 bytes para el código de revisión, 2 bytes para el número de caracteres, 2 bytes para el número de extensiones, 4 bytes para el tamaño de la tabla de encabezado, 2 bytes para el tamaño del encabezado, 2 bytes para el número de pares de caracteres, 4 bytes para el tamaño de la tabla de encabezado, 4 bytes para el tamaño de la tabla de encabezado, 4 bytes para el tamaño del diseño, 40 bytes para el nombre de la familia, 20 bytes para la codificación y 4 bytes para un byte de cara. Quedan solo 28 bytes para alguna información adicional que es utilizada por ttf2tfm para una cadena de identificación (que es esencialmente una copia de la línea de comandos), y este límite siempre se excede.

La solución óptima es aumentar el valor de max_header_bytes en el archivo vptovf.web (y probablemente pltotf.web también) a, digamos, 400 y recompilar vptovf (y pltotf). De lo contrario, obtendrá algunos mensajes de error (inofensivos) como


Este índice de ENCABEZADO es demasiado grande para el tamaño actual de mi tabla

que se puede ignorar de forma segura.
