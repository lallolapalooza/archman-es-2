turnutils_stunclient(1)

TURN(1) TURN(1)

INFORMACIÓN GENERAL

Un conjunto de programas turnutils_* proporciona cierta funcionalidad de utilidad para ser utilizada en pruebas y en la configuración del servidor TURN.

1.
turnutils_uclient: emula múltiples clientes UDP, TCP, TLS o DTLS. (¡este programa se proporciona solo para fines de prueba!) La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.
2.
turnutils_peer: un servidor "eco" simple sin estado solo UDP, para ser utilizado como servidor final en el patrón de retransmisión ("peer"). Para cada paquete UDP entrante, simplemente lo devuelve. (¡este programa se proporciona solo para fines de prueba!) Cuando los clientes de prueba se comunican de forma cliente a cliente (cuando el programa "turnutils_uclient" se usa con la opción "-y"), no se necesita turnutils_peer.

La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.

3.
turnutils_stunclient: un ejemplo simple de cliente STUN. La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.
4.
turnutils_rfc5769check: una utilidad que verifica la corrección de la implementación del protocolo STUN/TURN. Esta utilidad solo se utiliza para el procedimiento de verificación de compilación, no se copia al destino de instalación.

En el subdirectorio "examples/scripts", encontrará ejemplos de líneas de comandos para ejecutar los programas. Los scripts están pensados para ser ejecutados desde el subdirectorio examples/, por ejemplo:

$ cd examples

$ ./scripts/secure_relay.sh

5.
turnutils_natdiscovery: una utilidad que proporciona descubrimiento de comportamiento NAT según RFC5780. Esta utilidad descubre el mapeo NAT real y el comportamiento de filtrado, etc. ¡Tenga en cuenta que en el lado del servidor TURN se deben configurar dos direcciones IP de escucha diferentes para poder funcionar correctamente!
6.
turnutils_oauth: una utilidad que proporciona la generación (cifrado AEAD), validación y descifrado de access_token. Esta utilidad introduce todas las claves y tiempos de vida y cualquier información relacionada que sea necesaria para la creación y validación de un access_token. Genera un JSON con todos los parámetros OAuth PoP que deben pasarse al cliente. La salida se genera según la RFC7635 Apéndice B, Figura 8.

Para más detalles, y para la estructura de access_token, lea rfc7635, y vea el script en examples/scripts/oauth.sh.

NOMBRE

turnutils_uclient - esta aplicación de emulación de cliente se proporciona solo para fines de prueba.

SINOPSIS

$ turnutils_uclient [-tTSvsyhcxg] [opciones] <dirección-IP-del-Servidor-TURN>

DESCRIPCIÓN

Fue diseñado para simular múltiples clientes. Utiliza la API de E/S asíncrona en libevent para manejar múltiples clientes. Un cliente se conecta al relé, negocia la sesión y envía múltiples mensajes (número configurado) al servidor (relevo), esperando el mismo número de respuestas. La longitud de los mensajes es configurable. El mensaje es un flujo de octetos arbitrario. El número de mensajes a enviar es configurable.

Banderas:

-t
Utiliza TCP para las comunicaciones entre el cliente y el servidor TURN (por defecto es UDP).
-b
Utiliza SCTP para las comunicaciones entre el cliente y el servidor TURN (por defecto es UDP).
-T
Utiliza TCP para el transporte de retransmisión (por defecto - UDP). Implica opciones -t, -y, -c, e ignora las banderas y las opciones -s, -e, -r y -g. Puede usarse junto con -b.
-P
TCP Pasivo (RFC6062 con par activo). Implica -T.
-S
Conexión segura SSL: SSL/TLS para TCP, DTLS para UDP, TLS/SCTP para SCTP.
-U
Conexión segura sin cifrar (suite eNULL): SSL/TLS para TCP, DTLS para UDP.
-v
Detallado.
-s
Utiliza el método "Send" en TURN; por defecto, utiliza Canales TURN.
-y
Utiliza conexiones cliente a cliente: par de canales RTP/RTCP a otro par de canales RTP/RTCP. con esta opción no se utiliza la aplicación turnutils_peer, ya que los puntos finales de retransmisión asignados se comunican entre sí.
-h
Espera indefinidamente después del último paquete enviado.
-c
No crea conexiones rtcp.
-x
Solicita dirección de retransmisión IPv6 (RFC6156).
-X
Dirección de retransmisión IPv4 solicitada explícitamente.
-g
Establece el parámetro DONT_FRAGMENT en las solicitudes TURN.
-D
Realiza relleno de canal obligatorio incluso para UDP (como pjnath).
-N
realiza pruebas negativas (solo algunos casos limitados).
-R
realiza pruebas de protocolo negativas.
-O
Modo ataque DOS.
-M
Utiliza Movilidad TURN ICE.
-I
No establece permisos en los puntos finales de retransmisión TURN (para probar la funcionalidad de retransmisión no estándar del servidor).
-G
Genera solicitudes adicionales (crear permisos, enlazar canal).
-B
Desconexión aleatoria después de unos pocos paquetes iniciales.
-Z
Asignación dual (SSODA). Implica la opción -c.
-J
Utiliza oAuth con la clave de prueba predeterminada kid='north'.

Opciones con valores requeridos:

-l
Longitud del mensaje (Por defecto: 100 Bytes).
-i
Archivo de certificado (solo para conexiones seguras, opcional).
-k
Archivo de clave privada (solo para conexiones seguras).
-E
Archivo CA para la verificación del certificado del servidor, si el certificado del servidor necesita ser verificado.
-p
Puerto del Servidor TURN (Por defecto: 3478 no seguro, 5349 seguro).
-n
Número de mensajes a enviar (Por defecto: 5).
-d
Dispositivo de interfaz local (opcional, solo Linux).
-L
Dirección IP local (opcional).
-m
Número de clientes (Por defecto: 1, 2 o 4, dependiendo de las opciones).
-e
Dirección del par.
-r
Puerto del par (Por defecto: 3480).
-z
Intervalo de paquetes por sesión en milisegundos (Por defecto: 20).
-u
Nombre de usuario STUN/TURN.
-w
Contraseña de usuario STUN/TURN.
-W
Secreto de la API REST de TURN. El secreto en "texto plano", por ejemplo, "north", que se almacena en la columna de valor del secreto turn_secret.

NAME

turnutils_common - a library for turnutils applications

SYNOPSIS

$ turnutils_common [options]

DESCRIPTION

This library implements the common functionality used by the turnutils_uclient and turnutils_restfulapi applications.

The application needs to know the TURN server's authentication mechanism. It can be either a shared secret or a database in the TURN server, that stores the username/realm information.

Options with required values:

-s
This is the secret used for the static authentication. The TURN server knows it. Default value is " 5e884898da28047151d0e56f0911290b ".
-t
This is the TURN REST API URL.
-u
The username used for the TURN authentication. If defined, the application will use the username/password authentication and will fetch the user information from the TURN server's authentication table in the database if dynamic, or the static-auth-secret value set in the configuration file if using static.
-C
This is the timestamp/username separator symbol (character) in TURN REST API. The default value is :.
-F
Cipher suite for TLS/DTLS. Default value is DEFAULT.
-o
the ORIGIN STUN attribute value.
-a
Bandwidth for the bandwidth request in ALLOCATE. The default value is zero.

See the examples in the "examples/scripts" directory.

NAME

turnutils_stunclient - a basic STUN client.

SYNOPSIS

$ turnutils_stunclient [options] <STUN-Server-IP-address>

DESCRIPTION

It sends a "new" STUN RFC 5389 request (over UDP) and shows the reply information.

Options with required values:

-p
STUN server port (Default: 3478).
-L
Local address to use (optional).
-f
Force RFC 5780 processing.

The turnutils_stunclient program checks the results of the first request, and if it finds that the STUN server supports RFC 5780 (the binding response reveals that) then the turnutils_stunclient makes a couple more requests with different parameters, to demonstrate the NAT discovery capabilities.

This utility does not support the "old" "classic" STUN protocol (RFC 3489).

NAME

turnutils_rfc5769check - a utility that tests the correctness of STUN protocol implementation.

SYNOPSIS

$ turnutils_rfc5769check

DESCRIPTION

turnutils_rfc5769check tests the correctness of STUN protocol implementation against the test vectors predefined in RFC 5769 and prints the results of the tests on the screen. This utility is used only for the compilation check procedure, it is not copied to the installation destination.

Usage:

$ turnutils_rfc5769check

NAME

turnutils_natdiscovery - a utility that discovers NAT mapping and filtering behavior according RFC5780.

SYNOPSIS

$ turnutils_natdiscovery [options] <STUN-Server-FQDN-or-IP-address>

DESCRIPTION

turnutils_natdiscovery discovers the NAT Mapping and Filtering behavior, to determine if that NAT is currently using Endpoint-Independent, Address-Dependent, or Address and Port-Dependent Mapping and/or to determine if that NAT is currently using Endpoint-Independent, Address-Dependent, or Address and Port-Dependent Filtering.

Use either -m, -f, -c, -H flag to discover NAT behavior.

Flags:

-m
NAT mapping behavior discovery
-f
NAT filtering behavior discovery
-t
NAT mapping lifetime behavior discovery Requires a timer (-T)
-c
NAT collision behavior discovery
-H
NAT hairpinning behavior discovery
-P
Add 1500 byte Padding to the behavior discovery Applicable with all except NAT mapping Lifetime discovery

Options with required values:

-p
STUN server port (Default: 3478)
-L
Local address to use (optional)
-l
Local port to use (use with -L)
-A
Secondary Local address (optional) Required for collision discovery
-T
Mapping lifetime timer (sec) Used by mapping lifetime behavior discovery

Usage:

$ turnutils_natdiscovery -m -f stun.example.com

NAME

turnutils_oauth - a utility that helps OAuth access_token generation/encryption and validation/decyption

SYNOPSIS

$ turnutils_oauth [options]

DESCRIPTION

turnutils_oauth utility provides help in OAuth access_token encryption and/or decryption with AEAD (Atuthenticated Encryption with Associated Data). It helps for an Auth Server in access_token creation, and also for debugging purposes it helps the access_token validation and decryption. This utility inputs all the keys and lifetimes and any related information that are needed for encryption or decryption of an access_token. It outputs a JSON with all OAuth PoP parameters that need to pass to the client. Output is generated accoriding RFC7635 Appendix B, Figure 8. This utility could help to build an Auth Server service, but be awere that this utility does not generate "session key" / "mac_key" and not verifies lifetime of "session key" / "mac_key" or "Auth key". For more details, and for the access_token structure, read rfc7635, and see the example in examples/scripts/oauth.sh.

Use either -e and/or -d flag to encrypt or decrypt access_token.

Flags:

-h, --help
usage
-v, --verbose
verbose mode
-e, --encrypt
encrypt token
-d, --decrypt
decrypt validate token

Options with required values:

-i, --server-name
server name (max. 255 char)
-j, --auth-key-id
Auth key id (max. 32 char)
-k, --auth-key
base64 encoded Auth key
-l
--auth-key-timestamp Auth key timestamp (sec since epoch)
-m, --auth-key-lifetime
Auth key lifetime in sec
-n, --auth-key-as-rs-alg
Authorization Server(AS) - Resource Server(RS) encryption algorithm
-o, --token-nonce
base64 encoded nonce base64(12 octet) = 16 char
