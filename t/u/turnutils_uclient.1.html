Paquete: coturn

TURN(1) TURN(1)

INFORMACIÓN GENERAL

Un conjunto de programas turnutils_* proporciona algunas funcionalidades de utilidad para pruebas y para la configuración del servidor TURN.

1.
turnutils_uclient: emula múltiples clientes UDP, TCP, TLS o DTLS. (¡este programa se proporciona solo para fines de prueba!) La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.
2.
turnutils_peer: un servidor simple sin estado solo UDP "eco", para ser utilizado como servidor final en el patrón de retransmisión ("peer"). Para cada paquete UDP entrante, simplemente lo reenvía. (¡este programa se proporciona solo para fines de prueba!) Cuando los clientes de prueba se comunican en modo cliente a cliente (cuando el programa "turnutils_uclient" se usa con la opción "-y"), no se necesita turnutils_peer.

La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.

3.
turnutils_stunclient: un ejemplo simple de cliente STUN. La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.
4.
turnutils_rfc5769check: una utilidad que verifica la corrección de la implementación del protocolo STUN/TURN. Esta utilidad solo se usa para el procedimiento de verificación de compilación, no se copia al destino de instalación.

En el subdirectorio "examples/scripts", encontrará ejemplos de líneas de comando para ejecutar los programas. Los scripts están diseñados para ejecutarse desde el subdirectorio examples/, por ejemplo:

$ cd examples

$ ./scripts/secure_relay.sh

5.
turnutils_natdiscovery: una utilidad que proporciona descubrimiento de comportamiento NAT según RFC5780. Esta utilidad descubre el mapeo NAT real y el comportamiento de filtrado, etc. ¡Tenga en cuenta que en el lado del servidor TURN se deben configurar dos direcciones IP de escucha diferentes para poder funcionar correctamente!
6.
turnutils_oauth: una utilidad que proporciona la generación (cifrado AEAD), validación y descifrado de tokens de acceso OAuth. Esta utilidad introduce todas las claves y tiempos de vida y cualquier información relacionada que sea necesaria para la creación y validación de un token de acceso. Genera un JSON con todos los parámetros OAuth PoP que deben pasarse al cliente. La salida se genera según RFC7635 Apéndice B, Figura 8.

Para más detalles y para la estructura del token de acceso, lea rfc7635 y consulte el script en examples/scripts/oauth.sh.

=====================================

NOMBRE

turnutils_uclient - esta aplicación de emulación de cliente se proporciona solo para fines de prueba.

SINOPSIS

$ turnutils_uclient [-tTSvsyhcxg] [opciones] <dirección IP del Servidor TURN>

DESCRIPCIÓN

Fue diseñado para simular múltiples clientes. Utiliza la API de E/S asíncrona en libevent para manejar múltiples clientes. Un cliente se conecta a la retransmisión, negocia la sesión y envía múltiples mensajes (número configurado) al servidor (retransmisión), esperando el mismo número de respuestas. La longitud de los mensajes es configurable. El mensaje es un flujo de octetos arbitrario. El número de mensajes a enviar es configurable.

Indicadores:

-t
Utilizar TCP para las comunicaciones entre el cliente y el servidor TURN (el valor predeterminado es UDP).
-b
Utilizar SCTP para las comunicaciones entre el cliente y el servidor TURN (el valor predeterminado es UDP).
-T
Utilizar TCP para el transporte de retransmisión (predeterminado - UDP). Implica opciones -t, -y, -c e ignora los indicadores y las opciones -s, -e, -r y -g. Se puede usar junto con -b.
-P
TCP Pasivo (RFC6062 con par activo). Implica -T.
-S
Conexión segura SSL: SSL/TLS para TCP, DTLS para UDP, TLS/SCTP para SCTP.
-U
Conexión segura no cifrada (suite eNULL): SSL/TLS para TCP, DTLS para UDP.
-v
Detallado.
-s
Utilizar el método "Send" en TURN; por defecto, utiliza Canales TURN.
-y
Utilizar conexiones cliente a cliente: par de canales RTP/RTCP a otro par de canales RTP/RTCP. Con esta opción, la aplicación turnutils_peer no se utiliza, ya que los puntos finales de retransmisión asignados hablan entre sí.
-h
Permanecer indefinidamente después del último paquete enviado.
-c
No crear conexiones rtcp.
-x
Solicitar dirección de retransmisión IPv6 (RFC6156).
-X
Dirección de retransmisión IPv4 solicitada explícitamente.
-g
Establecer el parámetro DONT_FRAGMENT en las solicitudes TURN.
-D
Rellenar canales obligatoriamente incluso para UDP (como pjnath).
-N
realizar pruebas negativas (solo algunos casos limitados).
-R
realizar pruebas de protocolo negativas.
-O
Modo de ataque DOS.
-M
Utilizar movilidad TURN ICE.
-I
No establecer permisos en los puntos finales de retransmisión TURN (para probar la funcionalidad de retransmisión no estándar del servidor).
-G
Generar solicitudes adicionales (crear permisos, vincular canal).
-B
Desconexión aleatoria después de unos pocos paquetes iniciales.
-Z
Doble asignación (SSODA). Implica la opción -c.
-J
Utilizar OAuth con la clave de prueba predeterminada kid='north'.

Opciones con valores requeridos:

-l
Longitud del mensaje (Predeterminado: 100 Bytes).
-i
Archivo de certificado (solo para conexiones seguras, opcional).
-k
Archivo de clave privada (solo para conexiones seguras).
-E
Archivo CA para la verificación del certificado del servidor, si se debe verificar el certificado del servidor.
-p
Puerto del Servidor TURN (Predeterminados: 3478 sin cifrar, 5349 cifrado).
-n
Número de mensajes a enviar (Predeterminado: 5).
-d
Interfaz de dispositivo local (opcional, solo Linux).
-L
Dirección IP local (opcional).
-m
Número de clientes (Predeterminado: 1, 2 o 4, dependiendo de las opciones).
-e
Dirección del par.
-r
Puerto del par (Predeterminado: 3480).
-z
Intervalo de paquetes por sesión en milisegundos (Predeterminado: 20).
-u
Nombre de usuario STUN/TURN.
-w
Contraseña de usuario STUN/TURN.
-W
Secreto de la API REST de TURN. El secreto "en texto plano", por ejemplo, "north", que se almacena en la columna de valor del secreto turn_
