TURN(1) TURN(1)

INFORMACIÓN GENERAL

Un conjunto de programas turnutils_* proporciona algunas funcionalidades de utilidad para ser utilizadas en pruebas y en la configuración del servidor TURN.

1.
turnutils_uclient: Emula múltiples clientes UDP, TCP, TLS o DTLS. (¡Este programa se proporciona solo para fines de prueba!) La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.
2.
turnutils_peer: Un servidor simple "echo" sin estado solo UDP, para ser utilizado como el servidor final en el patrón de retransmisión ("peer"). Para cada paquete UDP entrante, simplemente lo reenvía. (¡Este programa se proporciona solo para fines de prueba!) Cuando los clientes de prueba se comunican en modo cliente a cliente (cuando el programa "turnutils_uclient" se usa con la opción "-y"), entonces no se necesita turnutils_peer.

La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.

3.
turnutils_stunclient: Un ejemplo simple de cliente STUN. La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.
4.
turnutils_rfc5769check: Una utilidad que verifica la corrección de la implementación del protocolo STUN/TURN. Esta utilidad solo se utiliza para el procedimiento de verificación de compilación, no se copia al destino de instalación.

En el subdirectorio "examples/scripts", encontrará ejemplos de líneas de comandos para ejecutar los programas. Los scripts están pensados para ser ejecutados desde el subdirectorio examples/, por ejemplo:

$ cd examples

$ ./scripts/secure_relay.sh

5.
turnutils_natdiscovery: Una utilidad que proporciona descubrimiento de comportamiento NAT según RFC5780. Esta utilidad descubre el mapeo NAT real y el comportamiento de filtrado, etc. ¡Tenga en cuenta que en el lado del servidor TURN se deben configurar dos direcciones IP de escucha diferentes para poder funcionar correctamente!
6.
turnutils_oauth: Una utilidad que proporciona la **generación** (cifrado AEAD), validación y descifrado de tokens de acceso access_token. Esta utilidad introduce todas las claves y tiempos de vida, y cualquier información relacionada que sea necesaria para la creación y validación de un token de acceso. Genera una salida JSON con todos los parámetros OAuth PoP que deben pasarse al cliente. La salida se genera según RFC7635 Apéndice B, Figura 8.

Para más detalles y para la estructura del token de acceso, lea rfc7635 y vea el script en examples/scripts/oauth.sh.

NOMBRE

turnutils_uclient - esta aplicación de emulación de cliente solo se proporciona para fines de prueba.

SINOPSIS

$ turnutils_uclient [-tTSvsyhcxg] [opciones] <dirección-IP-del-Servidor-TURN>

DESCRIPCIÓN

Fue diseñado para simular múltiples clientes. Utiliza la API de E/S asíncrona en libevent para manejar múltiples clientes. Un cliente se conecta al relé, negocia la sesión y envía múltiples mensajes (número configurado) al servidor (relé), esperando el mismo número de respuestas. La longitud del mensaje es configurable. El mensaje es un flujo de octetos arbitrario. El número de mensajes a enviar es configurable.

Indicadores:

-t
Utiliza TCP para las comunicaciones entre el cliente y el servidor TURN (el valor predeterminado es UDP).
-b
Utiliza SCTP para las comunicaciones entre el cliente y el servidor TURN (el valor predeterminado es UDP).
-T
Utiliza TCP para el transporte de retransmisión (predeterminado: UDP). Implica opciones -t, -y, -c e ignora los indicadores y las opciones -s, -e, -r y -g. Se puede usar junto con -b.
-P
TCP Pasivo (RFC6062 con peer activo). Implica -T.
-S
Conexión SSL segura: SSL/TLS para TCP, DTLS para UDP, TLS/SCTP para SCTP.
-U
Conexión segura sin cifrar (suite eNULL): SSL/TLS para TCP, DTLS para UDP.
-v
Detallado.
-s
Utiliza el método "Send" en TURN; por defecto, utiliza canales TURN.
-y
Utiliza conexiones cliente a cliente: par de canales RTP/RTCP a otro par de canales RTP/RTCP. Con esta opción no se utiliza la aplicación turnutils_peer, ya que los puntos finales de retransmisión asignados se comunican entre sí.
-h
Permanece indefinidamente después del último paquete enviado.
-c
No crea conexiones rtcp.
-x
Solicita dirección de retransmisión IPv6 (RFC6156).
-X
Dirección de retransmisión IPv4 solicitada explícitamente.
-g
Establece el parámetro DONT_FRAGMENT en las solicitudes TURN.
-D
Realiza relleno de canal obligatorio incluso para UDP (como pjnath).
-N
realiza pruebas negativas (solo algunos casos limitados).
-R
realiza pruebas de protocolo negativas.
-O
Modo de ataque DOS.
-M
Utiliza movilidad TURN ICE.
-I
No establece permisos en los puntos finales de retransmisión TURN (para probar la funcionalidad de retransmisión no estándar del servidor).
-G
Genera solicitudes adicionales (crear permisos, canal de enlace).
-B
Desconexión aleatoria después de unos pocos paquetes iniciales.
-Z
Doble asignación (SSODA). Implica la opción -c.
-J
Utiliza oAuth con clave de prueba predeterminada kid='north'.

Opciones con valores requeridos:

-l
Longitud del mensaje (Predeterminado: 100 Bytes).
-i
Archivo de certificado (solo para conexiones seguras, opcional).
-k
Archivo de clave privada (solo para conexiones seguras).
-E
Archivo CA para la verificación del certificado del servidor, si el certificado del servidor debe ser verificado.
-p
Puerto del Servidor TURN (Predeterminados: 3478 no seguro, 5349 seguro).
-n
Número de mensajes a enviar (Predeterminado: 5).
-d
Dispositivo de interfaz local (opcional, solo Linux).
-L
Dirección IP local (opcional).
-m
Número de clientes (Predeterminado: 1, 2 o 4, dependiendo de las opciones).
-e
Dirección del peer.
-r
Puerto del peer (Predeterminado: 3480).
-z
Intervalo de paquetes por sesión en milisegundos (Predeterminado: 20).
-u
Nombre de usuario STUN/TURN.
-w
Contraseña de usuario STUN/TURN.
-W
Secreto de la API REST de TURN. El secreto en "texto plano", por ejemplo, "north", que se almacena en la columna del valor del secreto de turn_
tabla en la base de datos si es dinámica, o el valor static-auth-secret establecido en el archivo de configuración si se usa estático.
-C
Este es el símbolo (carácter) separador de marca de tiempo/nombre de usuario en la API REST de TURN. El valor predeterminado es :.
-F
Suite de cifrado para TLS/DTLS. El valor predeterminado es DEFAULT.
-o
el valor del atributo ORIGIN STUN.
-a
Ancho de banda para la solicitud de ancho de banda en ALLOCATE. El valor predeterminado es cero.

Vea los ejemplos en el directorio "examples/scripts".

NOMBRE

turnutils_stunclient - un cliente STUN básico.

SINOPSIS

$ turnutils_stunclient [opciones] <dirección-IP-del-servidor-STUN>

DESCRIPCIÓN

Envía una solicitud STUN RFC 5389 "nueva" (a través de UDP) y muestra la información de respuesta.

Opciones con valores requeridos:

-p
Puerto del servidor STUN (Predeterminado: 3478).
-L
Dirección local a utilizar (opcional).
-f
Forzar el procesamiento de RFC 5780.

El programa turnutils_stunclient verifica los resultados de la primera solicitud y, si descubre que el servidor STUN admite RFC 5780 (la respuesta de enlace lo revela), entonces turnutils_stunclient realiza un par de solicitudes más con diferentes parámetros, para demostrar las capacidades de descubrimiento de NAT.

Esta utilidad no admite el protocolo STUN "antiguo" "clásico" (RFC 3489).

NOMBRE

turnutils_rfc5769check - una utilidad que prueba la corrección de la implementación del protocolo STUN.

SINOPSIS

$ turnutils_rfc5769check

DESCRIPCIÓN

turnutils_rfc5769check prueba la corrección de la implementación del protocolo STUN contra los vectores de prueba predefinidos en RFC 5769 e imprime los resultados de las pruebas en la pantalla. Esta utilidad se utiliza solo para el procedimiento de verificación de compilación, no se copia al destino de instalación.

Uso:

$ turnutils_rfc5769check

NOMBRE

turnutils_natdiscovery - una utilidad que descubre el mapeo y filtrado NAT según RFC5780.

SINOPSIS

$ turnutils_natdiscovery [opciones] <FQDN o dirección IP del servidor
    STUN>

DESCRIPCIÓN

turnutils_natdiscovery descubre el comportamiento de Mapeo y Filtrado de NAT, para determinar si esa NAT está utilizando actualmente Mapeo Independiente de Punto Final, Dependiente de Dirección, o Dependiente de Dirección y Puerto y/o para determinar si esa NAT está utilizando Filtrado Independiente de Punto Final, Dependiente de Dirección, o Dependiente de Dirección y Puerto.

Use la bandera -m, -f, -c o -H para descubrir el comportamiento de NAT.

Banderas:

-m
Descubrimiento del comportamiento de mapeo de NAT
-f
Descubrimiento del comportamiento de filtrado de NAT
-t
Descubrimiento del comportamiento de la vida útil del mapeo NAT Requiere un temporizador (-T)
-c
Descubrimiento del comportamiento de colisión de NAT
-H
Descubrimiento del comportamiento de hairpinning de NAT
-P
Agrega 1500 bytes de relleno al descubrimiento de comportamiento Aplicable con todo excepto el descubrimiento de vida útil del mapeo de NAT

Opciones con valores requeridos:

-p
Puerto del servidor STUN (Predeterminado: 3478)
-L
Dirección local a utilizar (opcional)
-l
Puerto local a utilizar (usar con -L)
-A
Dirección local secundaria (opcional) Requerido para el descubrimiento de colisiones
-T
Temporizador de vida útil del mapeo (seg) Utilizado por el descubrimiento del comportamiento de vida útil del mapeo

Uso:

$ turnutils_natdiscovery -m -f stun.example.com

NOMBRE

turnutils_oauth - una utilidad que ayuda a la generación/cifrado y validación/descifrado de access_token OAuth

SINOPSIS

$ turnutils_oauth [opciones]

DESCRIPCIÓN

La utilidad turnutils_oauth proporciona ayuda en el cifrado y/o descifrado de access_token OAuth con AEAD (Cifrado Autenticado con Datos Asociados). Ayuda a un Servidor de Autenticación en la creación de access_token y, también con fines de depuración, ayuda a la validación y descifrado de access_token. Esta utilidad introduce todas las claves y vidas útiles, y cualquier información relacionada que sea necesaria para el cifrado o descifrado de un access_token. Produce una salida JSON con todos los parámetros OAuth PoP que deben pasarse al cliente. La salida se genera según RFC7635 Apéndice B, Figura 8. Esta utilidad podría ayudar a construir un servicio de Servidor de Autenticación, pero tenga en cuenta que esta utilidad no genera "clave de sesión" / "mac_key" ni verifica la vida útil de la "clave de sesión" / "mac_key" o la "clave de autenticación". Para más detalles y para la estructura de access_token, lea rfc7635 y vea el ejemplo en examples/scripts/oauth.sh.

Use la bandera -e y/o -d para cifrar o descifrar el access_token.

Banderas:

-h, --help
uso
-v, --verbose
modo detallado
-e, --encrypt
cifrar token
-d, --decrypt
descifrar validar token

Opciones con valores requeridos:

-i, --server-name
nombre del servidor (máximo 255 caracteres)
-j, --auth-key-id
ID de clave de autenticación (máximo 32 caracteres)
-k, --auth-key
Clave de autenticación codificada en base64
-l
--auth-key-timestamp Marca de tiempo de la clave de autenticación (segundos desde la época)
-m, --auth-key-lifetime
Vida útil de la clave de autenticación en segundos
-n, --auth-key-as-rs-alg
Algoritmo de cifrado entre el Servidor de Autorización (AS) y el Servidor de Recursos (RS)
-o, --token-nonce
nonce codificado en base64 base64(12 octetos) = 16 caracteres

NAME

turnutils_oauth — OAuth authentication utility for coturn server

SYNOPSIS

turnutils_oauth [-c key] [-e key] [-a key] [-k key] [-q timestamp] [-r lifetime] [-t token] [-u hmac-alg]

DESCRIPTION

This utility is a command-line tool that can be used to generate and validate OAuth tokens for the turnserver(1). It allows users to create or check authentication tokens based on HMAC-SHA1, HMAC-SHA256, or HMAC-SHA512 algorithms.

OPTIONS

-c, --token-auth
base64 encoded authentication key (mandatory for generation)
-e, --token-encryption
base64 encoded encryption key (mandatory for generation)
-a, --realm
realm for the token (mandatory for generation)
-k, --token-mac-key
base64 encoded MAC key (32 octet) = 44 char
-q, --token-timestamp
timestamp in format 64 bit unsigned (Native format - Unix), so 48 bit for secs since epoch UTC + 16 bit for 1/64000 fractions of a second. e.g.: the actual unixtimestamp 16 bit left shifted. (Default: actual gmtime)
-r, --token-lifetime
lifetime in sec (Default: 3600)
-t, --token
base64 encoded encrypted token for validation and decryption
-u, --hmac-alg
stun client hmac algorithm

Usage:

$ turnutils_oauth
