NOMBRE

tuned.conf - Definición de perfil de TuneD

DESCRIPCIÓN

Esta página del manual documenta el formato de los archivos de definición de perfil de TuneD 2.0. La definición del perfil se almacena en /etc/tuned/profiles/<nombre_perfil>/tuned.conf o en el archivo /usr/lib/tuned/profiles/<nombre_perfil>/tuned.conf donde el directorio /etc/tuned/profiles/ tiene mayor prioridad.

tuned.conf configura el perfil y está en formato de archivo ini.

SECCIÓN PRINCIPAL

La sección principal se llama "[main]" y puede contener las siguientes opciones:

include=
Incluye un perfil con el nombre dado. Esto le permite basar un nuevo perfil en un perfil ya existente. En caso de que haya parámetros conflictivos en el nuevo perfil y el perfil base, se utilizan los parámetros del nuevo perfil.

PLUGINS

Cada otra sección define un plugin. El nombre de la sección se utiliza como nombre para el plugin y se utiliza en los registros para identificar el plugin. Solo puede haber un plugin de un tipo particular que ajuste un dispositivo particular. Los conflictos se resuelven por defecto fusionando las opciones de ambos plugins. Esto se puede cambiar con la opción "replace".

Cada sección de plugin puede contener las siguientes secciones:

type=
Tipo de plugin. Actualmente existen los siguientes plugins upstream: audio, bootloader, cpu, disk, eeepc_she, modules, mounts, net, script, scsi_host, selinux, scheduler, sysctl, sysfs, systemd, usb, video, vm. Esta lista puede estar incompleta. Si instaló TuneD a través de RPM, puede listar los plugins upstream con el siguiente comando: rpm -ql tuned | grep 'plugins/plugin_.*.py$' Consulte el directorio plugins devuelto por este comando para ver todos los plugins (por ejemplo, plugins proporcionados por paquetes de terceros).
devices=
Lista separada por comas de los dispositivos que deben ser ajustados por esta instancia del plugin. Si omite esta opción, se ajustarán todos los dispositivos encontrados.
replace=1
Si hay un conflicto entre dos plugins (lo que significa que dos plugins del mismo tipo intentan configurar los mismos dispositivos), entonces el plugin definido en último lugar reemplaza todas las opciones definidas por el plugin anterior.

Los plugins también pueden tener opciones relacionadas con el plugin.

EJEMPLO

[main]
# Incluye plugins definidos en el perfil "included".
include=included
# Define el plugin my_sysctl
[my_sysctl]
type=sysctl
# Este plugin reemplazará cualquier plugin sysctl definido en el perfil "included"
replace=1
# 256 KB por defecto funciona bien experimentalmente.
net.core.rmem_default = 262144
net.core.wmem_default = 262144
# Define el plugin my_script
# Ambos scripts (profile.sh de este perfil y el script del perfil "included"
# se ejecutarán, porque si no hay la opción "replace=1",
# la acción por defecto es fusionar.
[my_script]
type=script
script=${i:PROFILE_DIR}/profile.sh
