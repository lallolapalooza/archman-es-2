NOMBRE

tune2fs - ajustar parámetros sintonizables del sistema de archivos en sistemas de archivos ext2/ext3/ext4

SINOPSIS

tune2fs [ -l ] [ -c recuentos-máximos-de-montaje ] [ -e comportamiento-ante-errores ] [ -f ] [ -i intervalo-entre-verificaciones ] [ -I nuevo-tamaño-de-inode ] [ -j ] [ -J opciones-de-journal ] [ -m porcentaje-de-bloques-reservados ] [ -o [^]opciones-de-montaje[,...] ] [ -r recuento-de-bloques-reservados ] [ -u usuario ] [ -g grupo ] [ -C recuento-de-montaje ] [ -E opciones-extendidas ] [ -L etiqueta-volumen ] [ -M directorio-últimamente-montado ] [ -O [^]característica[,...] ] [ -Q opciones-de-cuota ] [ -T tiempo-última-verificación ] [ -U UUID ] [ -z archivo-deshacer ] dispositivo

DESCRIPCIÓN

tune2fs permite al administrador del sistema ajustar varios parámetros sintonizables de sistemas de archivos en sistemas de archivos ext2, ext3 o ext4 de Linux. Los valores actuales de estas opciones se pueden mostrar usando la opción -l del programa tune2fs(8), o usando el programa dumpe2fs(8).

El especificador dispositivo puede ser un nombre de archivo (es decir, /dev/sda1), o un especificador LABEL o UUID: "LABEL=etiqueta-volumen" o "UUID=uuid". (es decir, LABEL=home o UUID=e40486c6-84d5-4f2f-b99c-032281799c9d).

OPCIONES

-c recuentos-máximos-de-montaje
Ajusta el número de montajes después de los cuales el sistema de archivos será verificado por e2fsck(8). Si recuentos-máximos-de-montaje es la cadena "random", tune2fs usará un valor aleatorio entre 20 y 40. Si recuentos-máximos-de-montaje es 0 o -1, el número de veces que se monta el sistema de archivos será ignorado por e2fsck(8) y el kernel.

Reorganizar los recuentos de montaje en los que los sistemas de archivos se verifican forzosamente evitará que todos los sistemas de archivos se verifiquen a la vez cuando se usan sistemas de archivos con journal.

La verificación dependiente del recuento de montaje está deshabilitada por defecto para evitar reinicios largos e imprevistos mientras e2fsck hace su trabajo. Si está preocupado por las corrupciones del sistema de archivos causadas por posibles problemas de hardware o errores del kernel, una mejor solución que la verificación dependiente del recuento de montaje es usar el programa e2scrub(8). Sin embargo, esto requiere colocar el sistema de archivos en un volumen LVM.

-C recuento-de-montaje
Establece el número de veces que se ha montado el sistema de archivos. Si se establece en un valor mayor que el parámetro recuentos-máximos-de-montaje establecido por la opción -c, e2fsck(8) verificará el sistema de archivos en el próximo reinicio.
-e comportamiento-ante-errores
Cambia el comportamiento del código del kernel cuando se detectan errores. En todos los casos, un error del sistema de archivos provocará que e2fsck(8) verifique el sistema de archivos en el próximo montaje. comportamiento-ante-errores puede ser una de las siguientes:
continue
Continuar la ejecución normal.
remount-ro
Remontar el sistema de archivos de solo lectura.
panic
Causar un pánico del kernel.
-E opciones-extendidas
Establece opciones extendidas para el sistema de archivos. Las opciones extendidas están separadas por comas y pueden tomar un argumento usando el signo de igual ('='). Las siguientes opciones extendidas son compatibles:
clear_mmp
Restablece el bloque MMP (si existe) a su estado limpio. Úselo solo si está absolutamente seguro de que el dispositivo no está montado ni siendo fscked actualmente, o pueden producirse daños graves en el sistema de archivos. Requiere '-f'.
encoding=nombre-codificación
Habilita la característica casefold en el superbloque y establece nombre-codificación como la codificación a utilizar. Si no se especifica nombre-codificación, se utiliza utf8. La codificación no se puede modificar si casefold estaba habilitado previamente.
encoding_flags=flags-codificación
Define parámetros para operaciones de codificación de caracteres de nombres de archivo. Si un flag no se cambia usando este parámetro, se utiliza su valor predeterminado. flags-codificación debe ser una lista de flags separados por comas para ser habilitados. Los flags no se pueden modificar si casefold estaba habilitado previamente.

El único flag que se puede establecer en este momento es strict, lo que significa que las cadenas inválidas deben ser rechazadas por el sistema de archivos. En la configuración predeterminada, el flag strict está deshabilitado.

force_fsck
Establece un flag en el superbloque del sistema de archivos indicando que se han encontrado errores. Esto forzará la ejecución de fsck en el próximo montaje.
hash_alg=algoritmo-hash
Establece el algoritmo de hash predeterminado utilizado para sistemas de archivos con directorios b-tree hasheados. Los algoritmos válidos aceptados son: legacy, half_md4 y tea.
mmp_update_interval=intervalo
Ajusta el intervalo de actualización inicial de MMP a intervalo segundos. Especificar un intervalo de 0 significa usar el intervalo predeterminado. El intervalo especificado debe ser inferior a 300 segundos. Requiere que la característica mmp esté habilitada.
mount_opts=cadena-opciones-montaje
Establece un conjunto de opciones de montaje predeterminadas que se usarán cuando se monte el sistema de archivos. A diferencia de las opciones de montaje predeterminadas basadas en máscaras de bits que se pueden especificar con la opción -o, cadena-opciones-montaje es una cadena arbitraria con una longitud máxima de 63 bytes, que se almacena en el superbloque.
El controlador del sistema de archivos ext4 primero aplicará las opciones predeterminadas basadas en máscaras de bits, y luego analizará la cadena-opciones-montaje, antes de analizar las opciones de montaje pasadas por el programa mount(8).
Esta configuración del superbloque solo se respeta en kernels 2.6.35+; y no se respeta en absoluto por los controladores de sistemas de archivos ext2 y ext3.
orphan_file_size=tamaño
Establece el tamaño del archivo para rastrear inodos desvinculados pero aún abiertos e inodos con la operación de truncamiento en progreso. Un archivo más grande permite una mejor escalabilidad; reservar algunos bloques por CPU es lo ideal.
stride=tamaño-stride
Configura el sistema de archivos para una matriz RAID con tamaño-stride bloques del sistema de archivos. Este es el número de bloques leídos o escritos en el disco antes de pasar al siguiente disco. Esto afecta principalmente la ubicación de los metadatos del sistema de archivos, como los mapas de bits, en el momento de mke2fs(2) para evitar colocarlos en un solo disco, lo que puede perjudicar el rendimiento. También puede ser utilizado por el asignador de bloques.
stripe_width=ancho-stripe
Configura el sistema de archivos para una matriz RAID con ancho-stripe bloques del sistema de archivos por stripe. Esto suele ser tamaño-stride * N, donde N es el número de discos de datos en la RAID (por ejemplo, RAID 5 N+1, RAID 6 N+2). Esto permite que el asignador de bloques evite escrituras de modificación de paridad en un stripe RAID si es posible al escribir los datos.
test_fs
Establece un flag en el superbloque del sistema de archivos que indica que puede ser montado usando código experimental del kernel, como el sistema de archivos ext4dev.
^test_fs
Borra el flag test_fs, indicando que el sistema de archivos solo debe ser montado usando código de sistemas de archivos de nivel de producción.
-f
Fuerza la operación incluso si el sistema de archivos está montado o tiene errores. Para la mayoría de las operaciones, esto debería ser utilizado con precaución. La opción -f es necesaria si se desea deshabilitar las comprobaciones de montaje o cambiar el tamaño del inodo en un sistema de archivos que no está montado.
-g grupo
Establece el grupo propietario de los bloques de archivos reservados. El valor de grupo puede ser un nombre o un número GID.
-i intervalo-entre-verificaciones
Establece el intervalo máximo entre verificaciones del sistema de archivos. El intervalo se especifica como un tiempo (por ejemplo, "15s" para 15 segundos, "5m" para 5 minutos, "2h" para 2 horas, "7d" para 7 días, "3M" para 3 meses, "1y" para 1 año). Si el intervalo es 0, la verificación basada en el tiempo está deshabilitada. El kernel revisará el sistema de archivos si han pasado más de 18 meses desde la última verificación (siempre que la verificación basada en el tiempo esté habilitada y el sistema de archivos no haya sido montado con la opción -o noatime o -o lazytime).
-I nuevo-tamaño-de-inode
Cambia el tamaño de los inodos a nuevo-tamaño-de-inode bytes. El tamaño debe ser una potencia de 2, y no menor que el tamaño mínimo requerido por el sistema de archivos. Cambiar el tamaño de los inodos solo puede hacerse en un sistema de archivos que no esté montado. Tenga en cuenta que los inodos más pequeños pueden limitar el número de atributos extendidos que se pueden almacenar en un inodo, y los inodos más grandes pueden desperdiciar espacio en sistemas de archivos con muchos archivos pequeños.
-j
Crea un nuevo journal de ext3 añadiendo un nuevo journal de ext3 al sistema de archivos y montando el sistema de archivos en modo ext3. Si el sistema de archivos ya tiene un journal, esta opción lo eliminará y creará uno nuevo. La ubicación y el tamaño del journal pueden ser especificados con la opción -J.
-J journal-options
Opciones para la creación y administración del journal de ext3. Las opciones son separadas por comas. Las siguientes opciones de journal son compatibles:
device=dispositivo-journal
El journal será creado en el dispositivo-journal especificado, en lugar de estar incrustado dentro del sistema de archivos principal. El dispositivo-journal debe ser un sistema de archivos ext2.
size=tamaño-journal
El tamaño del journal en megabytes. El tamaño del journal debe ser una potencia de 2, y no mayor que 102400 (100MB) o menor que 1 o mayor que 1048576 (1GB) si el journal está en un dispositivo separado.
lazy_itable_init
No inicializar completamente el journal al crearlo. Esto hará que el journal se cree más rápido, pero puede retrasar el primer montaje.
discard
Si el dispositivo de journal es un dispositivo de bloque que soporta el comando TRIM (por ejemplo, un SSD), este comando le indicará al dispositivo que los bloques del journal que ya no están en uso pueden ser descartados. Esto puede mejorar el rendimiento y la longevidad del dispositivo.
-L etiqueta-volumen
Establece la etiqueta del volumen para el sistema de archivos. Las etiquetas de volumen no pueden contener más de 16 caracteres.
-m porcentaje-de-bloques-reservados
Establece el porcentaje de bloques reservados para los superusuarios. Esto puede ser un número entre 0 y 99. Por defecto es 5%.
-M directorio-últimamente-montado
Establece el nombre del directorio en el cual el sistema de archivos fue montado por última vez. Esto puede ser útil para el programa e2fsck(8) y para el código del kernel que se encarga de detectar las corrupciones del sistema de archivos.

Esta opción es útil al eliminar la característica del sistema de archivos has_journal de un sistema de archivos que tiene un diario externo (o está corrupto de tal manera que parece tener un diario externo), pero ese diario externo no está disponible. Si el sistema de archivos parece requerir la reproducción del diario, se debe especificar la bandera -f dos veces para proceder.

ADVERTENCIA: Eliminar un diario externo de un sistema de archivos que no se desmontó limpiamente sin reproducir primero el diario externo puede resultar en una pérdida severa de datos y corrupción del sistema de archivos.

-g grupo
Establecer el grupo que puede usar los bloques reservados del sistema de archivos. El parámetro grupo puede ser un gid numérico o un nombre de grupo. Si se proporciona un nombre de grupo, se convierte a un gid numérico antes de almacenarlo en el superbloque.
-i intervalo-entre-comprobaciones[d|m|w]
Ajustar el tiempo máximo entre dos comprobaciones del sistema de archivos. Sin sufijo o d interpretará el número intervalo-entre-comprobaciones como días, m como meses y w como semanas. Un valor de cero deshabilitará la comprobación dependiente del tiempo.

Existen pros y contras al deshabilitar estas comprobaciones periódicas; ver la discusión bajo la opción -c (comprobación dependiente del número de montajes) para más detalles.

-I
Cambiar el tamaño de inodo utilizado por el sistema de archivos. Esto requiere reescribir la tabla de inodos, por lo que requiere que el sistema de archivos se compruebe en busca de consistencia primero usando e2fsck(8). Esta operación también puede llevar un tiempo y el sistema de archivos puede corromperse y perderse datos si se interrumpe mientras se está convirtiendo el sistema de archivos. Se recomienda hacer una copia de seguridad del sistema de archivos antes de cambiar el tamaño de los inodos.
Los sistemas de archivos con un tamaño de inodo de 128 bytes no admiten marcas de tiempo posteriores al 19 de enero de 2038. Los inodos de 256 bytes o más grandes admitirán marcas de tiempo extendidas, identificadores de proyecto y la capacidad de almacenar algunos atributos extendidos en la tabla de inodos para mejorar el rendimiento.
-j
Añadir un diario ext3 al sistema de archivos. Si no se especifica la opción -J, se utilizarán los parámetros de diario predeterminados para crear un diario de tamaño adecuado (dado el tamaño del sistema de archivos) almacenado dentro del sistema de archivos. Tenga en cuenta que debe estar utilizando un kernel con soporte para ext3 para poder utilizar realmente el diario.
Si esta opción se utiliza para crear un diario en un sistema de archivos montado, se creará un archivo inmutable, .journal, en el directorio de nivel superior del sistema de archivos, ya que es la única forma segura de crear el inodo del diario mientras el sistema de archivos está montado. Mientras el diario ext3 es visible, no es seguro eliminarlo ni modificarlo mientras el sistema de archivos está montado; por esta razón, el archivo se marca como inmutable. Al comprobar sistemas de archivos desmontados, e2fsck(8) moverá automáticamente los archivos .journal al inodo del diario reservado e invisible. Para todos los sistemas de archivos, excepto para el sistema de archivos raíz, esto debería ocurrir de forma automática y natural durante el próximo ciclo de reinicio. Dado que el sistema de archivos raíz está montado en modo de solo lectura, se debe ejecutar e2fsck(8) desde un disquete de rescate para efectuar esta transición.
En algunas distribuciones, como Debian, si se utiliza un disco de arranque inicial (initrd), los scripts de initrd convertirán automáticamente un sistema de archivos raíz ext2 a ext3 si el archivo /etc/fstab especifica el sistema de archivos ext3 para el sistema de archivos raíz, para evitar requerir el uso de un disquete de rescate para añadir un diario ext3 al sistema de archivos raíz.
-J opciones-de-diario
Anular los parámetros predeterminados del diario ext3. Las opciones de diario están separadas por comas y pueden tomar un argumento usando el signo de igual ('='). Las siguientes opciones de diario son compatibles:
device=diario-externo
Adjuntar el sistema de archivos al dispositivo de bloque del diario ubicado en diario-externo. El diario externo ya debe haber sido creado usando el comando
mke2fs -O journal_dev diario-externo
Tenga en cuenta que diario-externo debe formatearse con el mismo tamaño de bloque que los sistemas de archivos que lo utilizarán. Además, aunque existe soporte para adjuntar varios sistemas de archivos a un solo diario externo, el kernel de Linux y e2fsck(8) actualmente no admiten diarios externos compartidos.
En lugar de especificar un nombre de dispositivo directamente, diario-externo también se puede especificar mediante LABEL=etiqueta o UUID=UUID para localizar el diario externo por la etiqueta de volumen o UUID almacenados en el superbloque ext2 al inicio del diario. Use dumpe2fs(8) para mostrar la etiqueta de volumen y el UUID de un dispositivo de diario. Consulte también la opción -L de tune2fs(8).
fast_commit_size=tamaño-commit-rápido
Crear un área de diario de confirmación rápida adicional de tamaño tamaño-commit-rápido kilobytes. Esta opción solo es válida si la característica fast_commit está habilitada en el sistema de archivos. Si no se especifica esta opción y si la característica fast_commit está activada, el tamaño del área de confirmación rápida por defecto será tamaño-del-diario / 64 megabytes. El tamaño total del diario con la característica fast_commit activada es tamaño-del-diario + ( tamaño-commit-rápido * 1024) megabytes. El tamaño total del diario no puede ser superior a 10.240.000 bloques del sistema de archivos o la mitad del tamaño total del sistema de archivos (el que sea menor).
location=ubicación-del-diario
Especificar la ubicación del diario. El argumento ubicación-del-diario puede especificarse como un número de bloque, o si el número tiene un sufijo de unidad (por ejemplo, 'M', 'G', etc.), se interpretará como el desplazamiento desde el principio del sistema de archivos.
size=tamaño-del-diario
Crear un diario almacenado en el sistema de archivos de tamaño tamaño-del-diario megabytes. El tamaño del diario debe ser de al menos 1024 bloques del sistema de archivos (es decir, 1 MiB si se usan bloques de 1k, 4 MiB si se usan bloques de 4k, etc.) y no puede ser mayor que 10.240.000 bloques del sistema de archivos. Debe haber suficiente espacio libre en el sistema de archivos para crear un diario de ese tamaño.
Solo una de las opciones size o device puede ser proporcionada para un sistema de archivos.
-l
Listar el contenido del superbloque del sistema de archivos, incluyendo los valores actuales de los parámetros que se pueden configurar con este programa.
-L etiqueta-de-volumen
Establecer la etiqueta del volumen del sistema de archivos. Las etiquetas de sistemas de archivos ext2 pueden tener como máximo 16 caracteres; si etiqueta-de-volumen es más larga que 16 caracteres, tune2fs la truncará e imprimirá una advertencia. Para otros sistemas de archivos que admiten la manipulación de etiquetas en línea y que están montados, tune2fs también funcionará, pero no intentará truncar etiqueta-de-volumen en absoluto. La etiqueta de volumen puede ser utilizada por mount(8), fsck(8) y /etc/fstab(5) (y posiblemente otros) especificando LABEL=etiqueta-de-volumen en lugar de un nombre de dispositivo especial de bloque como /dev/hda5.
-m porcentaje-bloques-reservados
Establecer el porcentaje del sistema de archivos que solo puede ser asignado por procesos privilegiados. Reservar una cierta cantidad de bloques del sistema de archivos para ser utilizados por procesos privilegiados se hace para evitar la fragmentación del sistema de archivos y para permitir que los demonios del sistema, como syslogd(8), continúen funcionando correctamente después de que los procesos no privilegiados no puedan escribir en el sistema de archivos. Normalmente, el porcentaje predeterminado de bloques reservados es del 5%.
-M directorio-ultimo-montaje
Establecer el directorio de último montaje para el sistema de archivos.
-o [^]opción-de-montaje[,...]

Las opciones de montaje predeterminadas pueden ser anuladas por opciones de montaje especificadas en /etc/fstab(5) o en los argumentos de línea de comandos a mount(8). Los kernels más antiguos pueden no admitir esta característica; en particular, los kernels anteriores a 2.4.20 casi con seguridad ignorarán el campo de opciones de montaje predeterminadas en el superbloque.

acl

NAME

tune2fs - ajustar parámetros de un sistema de ficheros ext2

SYNOPSIS

tune2fs [-l] [-c imax_волны] [-C mount_counts] [-e errors_behavior] [-f] [-i imax_чистота] [-j] [-J journal_options] [-K] [-m percentage] [-r percentage] [-s] [-S] [-t last_check_time] [-u user] [-U UUID] [-z undo_file] device

DESCRIPTION

tune2fs se utiliza para ajustar de forma interactiva o no interactiva los parámetros de un sistema de ficheros de Linux ext2. El sistema de ficheros puede ser examinado y sus parámetros modificados modificando los campos de la tabla de superbloques y de inodos del sistema de ficheros. El dispositivo debe ser un dispositivo de bloques que contenga un sistema de ficheros ext2. El sistema de ficheros no debe estar montado, aunque puede ser desmontado mientras se ejecuta tune2fs en él.

Sólo se puede modificar la tabla de superbloques. Por lo tanto, si el superbloque primario está corrupto, puede utilizarse la opción -l para obtener una lista de los superbloques de respaldo y luego reescribir el superbloque primario utilizando la información de un superbloque de respaldo con el comando e2fsck -b.

tune2fs puede usarse para ajustar el número de montaje máximo de inodos y el intervalo de montaje de los sistemas de ficheros.

tune2fs se puede utilizar para habilitar o deshabilitar el comprobado de la consistencia de los sistemas de ficheros en el arranque.

La opción -j se utiliza para añadir un diario ext3 a un sistema de ficheros ext2 existente. Esto se hace creando un nuevo inodo de diario y escribiendo el superbloque de diario en él. Una vez hecho esto, el sistema de ficheros se puede montar como un sistema de ficheros ext3.

OPTIONS

-l
Imprime la información del superbloque del sistema de ficheros. Dado que el superbloque se copia en varios lugares en el dispositivo, el primer superbloque impreso es el superbloque primario. Los superbloques de respaldo se imprimen a continuación. La opción -l puede ser utilizada para obtener una lista de los superbloques de respaldo y luego reescribir el superbloque primario utilizando la información de un superbloque de respaldo con el comando e2fsck -b.
-c imax_волны
Establece el número máximo de montajes permitidos antes de forzar una comprobación de consistencia en el siguiente arranque. Si se establece imax_волны a 0, se deshabilitará esta comprobación.
-C mount_counts
Establece el número de montajes del sistema de ficheros. Esto también reestablece el contador de montajes máximos a cero. Esto también se puede utilizar para reestablecer el contador de montajes máximos a cero.
-e errors_behavior
Establece el comportamiento del sistema de ficheros cuando se encuentran errores. El comportamiento de los errores puede ser uno de los siguientes:
continue
No hacer nada.
remount-ro
Remontar el sistema de ficheros como de sólo lectura.
panic
Provocar un pánico del kernel.
-f
Forzar la finalización de la operación aunque el sistema de ficheros parezca estar en un estado consistente.
-i imax_чистота
Establece el intervalo máximo entre comprobaciones de consistencia automáticas de los sistemas de ficheros. El argumento imax_чистота es un tiempo expresado en días, años o semanas. Si se establece imax_чистота a 0, se deshabilitará esta comprobación. Por ejemplo, "3" significa cada 3 días, "1.5" significa cada 1.5 días. El valor por defecto es 0, lo que significa que no se hace ninguna comprobación de tiempo basada en la edad.
-j
Añadir un diario ext3 al sistema de ficheros existente. Esto crea un nuevo inodo de diario y escribe el superbloque de diario en él. El sistema de ficheros se puede montar como ext3 después de esta operación. Se pueden especificar varias opciones de diario con la opción -J.
-J journal_options
Opciones para el diario ext3. Las opciones están separadas por comas y pueden ser size=journal_size para establecer el tamaño del diario en megabytes, device=external_journal para usar un diario externo en otro dispositivo. Si se especifica un dispositivo externo, este dispositivo debe contener un sistema de ficheros ext3 preexistente que contenga sólo un diario. Las opciones son aplicables sólo si se usa la opción -j.
-K
No exigir que el sistema de ficheros esté limpio. Esto es útil si el sistema de ficheros está dañado.
-m percentage
Establece el porcentaje de bloques reservados para el superusuario. Vea la descripción de la opción -r.
-r percentage
Establece el porcentaje de bloques reservados para el superusuario. Estos bloques reservados son inaccesibles para los usuarios normales y se utilizan para que el sistema de ficheros siga funcionando si la fragmentación alcanza un nivel crítico. El valor por defecto es 5%.
-s
Convertir el sistema de ficheros a un sistema de ficheros de datos pequeño. Sólo se puede hacer si el número de inodos es menor que 11 bloques por inodo. No se puede deshacer.
-S
Deshabilitar el comprobado de la consistencia de los sistemas de ficheros en el arranque. Esto está habilitado por defecto.
-t last_check_time
Establece la hora del último chequeo. El formato es el formato de fecha internacional, con un especificador de hora opcional, es decir, YYYYMMDD[HH[MM[SS]]]. La palabra clave now también se acepta, en cuyo caso la hora del último chequeo se establecerá a la hora actual.
-u user
Establece el usuario que puede utilizar los bloques reservados del sistema de ficheros. user puede ser un uid numérico o un nombre de usuario. Si se da un nombre de usuario, se convierte a un uid numérico antes de ser almacenado en el superbloque.
-U UUID
Establece el identificador único universal (UUID) del sistema de ficheros a UUID. El formato del UUID es una serie de dígitos hexadecimales separados por guiones, así: "c1b9d5a2-f162-11cf-9ece-0020afc76f16". El parámetro UUID también puede ser uno de los siguientes:
clear
limpiar el UUID del sistema de ficheros
random
generar un nuevo UUID generado aleatoriamente
time
generar un nuevo UUID basado en la hora
El UUID puede ser utilizado por mount(8), fsck(8), y /etc/fstab(5) (y posiblemente otros) especificando UUID=uuid en lugar de un nombre de dispositivo especial de bloques como /dev/hda1.
Vea uuidgen(8) para más información. Si el sistema no tiene un buen generador de números aleatorios como /dev/random o /dev/urandom, tune2fs utilizará automáticamente un UUID basado en la hora en lugar de un UUID generado aleatoriamente.
-z undo_file
Antes de sobrescribir un bloque del sistema de ficheros, escribe el contenido antiguo del bloque en un archivo de deshacer. Este archivo de deshacer puede ser utilizado con e2undo(8) para restaurar el contenido antiguo del sistema de ficheros si algo sale mal. Si se pasa la cadena vacía como argumento undo_file, el archivo de deshacer se escribirá en un archivo llamado tune2fs-device.e2undo en el directorio especificado a través de la variable de entorno E2FSPROGS_UNDO_DIR.

ADVERTENCIA: El archivo de deshacer no se puede utilizar para recuperarse de un corte de energía o un fallo del sistema.
