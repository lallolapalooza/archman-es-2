INFORMACIÓN GENERAL

Un conjunto de programas turnutils_* proporciona funcionalidad de utilidad para ser utilizada en pruebas y en la configuración del servidor TURN.

1.
turnutils_uclient: emula múltiples clientes UDP, TCP, TLS o DTLS. (¡este programa se proporciona solo para fines de prueba!) La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.
2.
turnutils_peer: un servidor "echo" simple y sin estado solo UDP, que se utilizará como servidor final en el patrón de retransmisión ("peer"). Para cada paquete UDP entrante, simplemente lo devuelve. (¡este programa se proporciona solo para fines de prueba!) Cuando los clientes de prueba se comunican de forma cliente a cliente (cuando el programa "turnutils_uclient" se utiliza con la opción "-y"), no se necesita turnutils_peer.

La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.

3.
turnutils_stunclient: un ejemplo simple de cliente STUN. La imagen binaria compilada de este programa se encuentra en el subdirectorio bin/.
4.
turnutils_rfc5769check: una utilidad que verifica la corrección de la implementación del protocolo STUN/TURN. Esta utilidad solo se utiliza para el procedimiento de verificación de compilación, no se copia al destino de instalación.

En el subdirectorio "examples/scripts", encontrará ejemplos de líneas de comando para ejecutar los programas. Los scripts están pensados para ser ejecutados desde el subdirectorio examples/, por ejemplo:

$ cd examples

$ ./scripts/secure_relay.sh

5.
turnutils_natdiscovery: una utilidad que proporciona descubrimiento de comportamiento NAT según RFC5780. Esta utilidad descubre el mapeo NAT real y el comportamiento de filtrado, etc. ¡Tenga en cuenta que en el lado del servidor TURN se deben configurar dos direcciones IP de escucha diferentes para poder funcionar correctamente!
6.
turnutils_oauth: una utilidad que proporciona la **generación** (cifrado AEAD), validación y descifrado de access_token de OAuth. Esta utilidad introduce todas las claves y tiempos de vida, y cualquier información relacionada necesaria para la creación y validación de un access_token. Genera un JSON con todos los parámetros OAuth PoP que deben pasarse al cliente. La salida se genera según RFC7635, Apéndice B, Figura 8.

Para más detalles y para la estructura del access_token, lea rfc7635 y consulte el script en examples/scripts/oauth.sh.

NOMBRE

turnutils_uclient - esta aplicación de emulación de cliente se proporciona solo para fines de prueba.

SINOPSIS

$ turnutils_uclient [-tTSvsyhcxg] [opciones] <dirección-IP-del-Servidor-TURN>

DESCRIPCIÓN

Fue diseñado para simular múltiples clientes. Utiliza la API de E/S asíncrona en libevent para manejar múltiples clientes. Un cliente se conecta al relé, negocia la sesión y envía múltiples mensajes (número configurado) al servidor (relé), esperando el mismo número de respuestas. La longitud de los mensajes es configurable. El mensaje es un flujo de octetos arbitrario. El número de mensajes a enviar es configurable.

Flags:

-t
Usar TCP para las comunicaciones entre el cliente y el servidor TURN (por defecto es UDP).
-b
Usar SCTP para las comunicaciones entre el cliente y el servidor TURN (por defecto es UDP).
-T
Usar TCP para el transporte de retransmisión (por defecto - UDP). Implica las opciones -t, -y, -c e ignora los flags y las opciones -s, -e, -r y -g. Puede usarse junto con -b.
-P
TCP Pasivo (RFC6062 con peer activo). Implica -T.
-S
Conexión SSL segura: SSL/TLS para TCP, DTLS para UDP, TLS/SCTP para SCTP.
-U
Conexión segura no cifrada (suite eNULL): SSL/TLS para TCP, DTLS para UDP.
-v
Detallado.
-s
Usar el método "Send" en TURN; por defecto, usa Canales TURN.
-y
Usar conexiones cliente a cliente: par de canales RTP/RTCP a otro par de canales RTP/RTCP. Con esta opción no se usa la aplicación turnutils_peer, ya que los puntos finales de retransmisión asignados se comunican entre sí.
-h
Mantenerse indefinidamente después del último paquete enviado.
-c
No crear conexiones rtcp.
-x
Solicitar dirección de retransmisión IPv6 (RFC6156).
-X
Dirección de retransmisión IPv4 solicitada explícitamente.
-g
Establecer el parámetro DONT_FRAGMENT en las solicitudes TURN.
-D
Realizar relleno de canal obligatorio incluso para UDP (como pjnath).
-N
realizar pruebas negativas (solo casos limitados).
-R
realizar pruebas de protocolo negativas.
-O
Modo de ataque DOS.
-M
Usar Movilidad TURN ICE.
-I
No establecer permisos en los puntos finales de retransmisión TURN (para probar la funcionalidad de retransmisión no estándar del servidor).
-G
Generar solicitudes adicionales (crear permisos, enlazar canal).
-B
Desconexión aleatoria después de unos pocos paquetes iniciales.
-Z
Asignación dual (SSODA). Implica la opción -c.
-J
Usar oAuth con la clave de prueba predeterminada kid='north'.

Opciones con valores requeridos:

-l
Longitud del mensaje (Predeterminado: 100 Bytes).
-i
Archivo de certificado (solo para conexiones seguras, opcional).
-k
Archivo de clave privada (solo para conexiones seguras).
-E
Archivo CA para la verificación del certificado del servidor, si se debe verificar el certificado del servidor.
-p
Puerto del **Servidor TURN** (Predeterminados: 3478 sin cifrar, 5349 cifrado).
-n
Número de mensajes a enviar (Predeterminado: 5).
-d
Interfaz de red local (opcional, solo Linux).
-L
Dirección IP local (opcional).
-m
Número de clientes (Predeterminado: 1, 2 o 4, dependiendo de las opciones).
-e
Dirección del peer.
-r
Puerto del peer (Predeterminado: 3480).
-z
Intervalo de paquetes por sesión en milisegundos (Predeterminado: 20).
-u
Nombre de usuario STUN/TURN.
-w
Contraseña de usuario STUN/TURN.
-W
Secreto de la API REST de TURN. El secreto en "texto plano", p. ej., "north", que se almacena en la columna de valor de la [ ... ]
t tabla en la base de datos si es dinámica, o el valor static-auth-secret establecido en el archivo de configuración si se utiliza uno estático.
-C
Este es el símbolo separador (carácter) de marca de tiempo/nombre de usuario en la API REST de TURN. El valor predeterminado es :.
-F
Suite de cifrado para TLS/DTLS. El valor predeterminado es DEFAULT.
-o
el valor del atributo ORIGIN STUN.
-a
Ancho de banda para la solicitud de ancho de banda en ALLOCATE. El valor predeterminado es cero.

Consulte los ejemplos en el directorio "examples/scripts".

turnutils_peer - un servidor backend simple de eco solo UDP.

SINOPSIS

$ turnutils_peer [-v] [opciones]

DESCRIPCIÓN

Esta aplicación se utiliza únicamente con fines de prueba, como par para la aplicación turnutils_uclient.

Opciones con valores requeridos:

-p
Puerto UDP de escucha (Predeterminado: 3480).
-d
Dispositivo de interfaz de escucha (opcional)
-L
Dirección de escucha del servidor turnutils_peer. Se pueden utilizar múltiples direcciones de escucha, IPv4 e IPv6. Si no se definen direcciones de escucha, escucha en todas las direcciones IPv4 e IPv6.
-v
Detallado

NOMBRE

turnutils_stunclient - un cliente STUN básico.

SINOPSIS

$ turnutils_stunclient [opciones] <dirección-IP-del-servidor-STUN>

DESCRIPCIÓN

Envía una solicitud STUN RFC 5389 "nueva" (sobre UDP) y muestra la información de respuesta.

Opciones con valores requeridos:

-p
Puerto del servidor STUN (Predeterminado: 3478).
-L
Dirección local a utilizar (opcional).
-f
Forzar procesamiento RFC 5780.

El programa turnutils_stunclient verifica los resultados de la primera solicitud y, si encuentra que el servidor STUN admite RFC 5780 (la respuesta de enlace lo revela), entonces turnutils_stunclient realiza un par de solicitudes más con diferentes parámetros, para demostrar las capacidades de descubrimiento de NAT.

Esta utilidad no admite el protocolo STUN "antiguo" "clásico" (RFC 3489).

NOMBRE

turnutils_rfc5769check - una utilidad que prueba la corrección de la implementación del protocolo STUN.

SINOPSIS

$ turnutils_rfc5769check

DESCRIPCIÓN

turnutils_rfc5769check prueba la corrección de la implementación del protocolo STUN contra los vectores de prueba predefinidos en RFC 5769 e imprime los resultados de las pruebas en la pantalla. Esta utilidad se utiliza solo para el procedimiento de verificación de compilación, no se copia al destino de instalación.

Uso:

$ turnutils_rfc5769check

NOMBRE

turnutils_natdiscovery - una utilidad que descubre el mapeo y filtrado NAT según RFC5780.

SINOPSIS

$ turnutils_natdiscovery [opciones] <FQDN o dirección IP del servidor
    STUN>

DESCRIPCIÓN

turnutils_natdiscovery descubre el comportamiento de Mapeo y Filtrado NAT, para determinar si esa NAT está utilizando actualmente Mapeo Independiente de Punto Final, Dependiente de Dirección, o Independiente de Dirección y Puerto y/o para determinar si esa NAT está utilizando Filtrado Independiente de Punto Final, Dependiente de Dirección, o Independiente de Dirección y Puerto.

Utilice la bandera -m, -f, -c, -H para descubrir el comportamiento NAT.

Banderas:

-m
Descubrimiento del comportamiento de mapeo NAT
-f
Descubrimiento del comportamiento de filtrado NAT
-t
Descubrimiento del comportamiento del tiempo de vida del mapeo NAT Requiere un temporizador (-T)
-c
Descubrimiento del comportamiento de colisión NAT
-H
Descubrimiento del comportamiento de retorno de carro NAT
-P
Añade 1500 bytes de relleno al descubrimiento de comportamiento Aplicable con todas las opciones excepto el descubrimiento del tiempo de vida del mapeo NAT

Opciones con valores requeridos:

-p
Puerto del servidor STUN (Predeterminado: 3478)
-L
Dirección local a utilizar (opcional)
-l
Puerto local a utilizar (usar con -L)
-A
Dirección local secundaria (opcional) Requerida para el descubrimiento de colisión
-T
Temporizador de tiempo de vida del mapeo (seg) Utilizado por el descubrimiento del comportamiento del tiempo de vida del mapeo

Uso:

$ turnutils_natdiscovery -m -f stun.example.com

NOMBRE

turnutils_oauth - una utilidad que ayuda a la generación/cifrado y validación/descifrado de access_token OAuth

SINOPSIS

$ turnutils_oauth [opciones]

DESCRIPCIÓN

La utilidad turnutils_oauth proporciona ayuda en el cifrado y/o descifrado de access_token OAuth con AEAD (Cifrado Autenticado con Datos Asociados). Ayuda a un Servidor de Autenticación en la creación de access_token y, también para fines de depuración, ayuda a la validación y descifrado del access_token. Esta utilidad introduce todas las claves y tiempos de vida, y cualquier información relacionada que sea necesaria para el cifrado o descifrado de un access_token. Produce una salida JSON con todos los parámetros OAuth PoP que necesitan pasarse al cliente. La salida se genera según RFC7635 Apéndice B, Figura 8. Esta utilidad podría ayudar a construir un servicio de Servidor de Autenticación, pero tenga en cuenta que esta utilidad no genera la "clave de sesión" / "mac_key" ni verifica el tiempo de vida de la "clave de sesión" / "mac_key" o la "clave de autenticación". Para más detalles, y para la estructura del access_token, lea rfc7635, y vea el ejemplo en examples/scripts/oauth.sh.

Utilice la bandera -e y/o -d para cifrar o descifrar el access_token.

Banderas:

-h, --help
uso
-v, --verbose
modo detallado
-e, --encrypt
cifrar token
-d, --decrypt
descifrar validar token

Opciones con valores requeridos:

-i, --server-name
nombre del servidor (máx. 255 caracteres)
-j, --auth-key-id
id de la clave de autenticación (máx. 32 caracteres)
-k, --auth-key
clave de autenticación codificada en base64
-l
--auth-key-timestamp Marca de tiempo de la clave de autenticación (segundos desde la época)
-m, --auth-key-lifetime
tiempo de vida de la clave de autenticación en segundos
-n, --auth-key-as-rs-alg
algoritmo de cifrado del Servidor de Autorización (AS) - Servidor de Recursos (RS)
-o, --token-nonce
nonce codificado en base64 base64(12 octetos) = 16 caracteres
-p, --token-mac-key
clave MAC codificada en base64 base64(32 octetos) = 44 caracteres
-q, --token-timestamp
marca de tiempo en formato de entero sin signo de 64 bits (Formato nativo - Unix), por lo tanto, 48 bits para segundos desde la época UTC + 16 bits para fracciones de segundo de 1/64000. por ejemplo: la marca de tiempo unix real desplazada 16 bits a la izquierda. (Predeterminado: hora coordinada universal actual)
-r, --token-lifetime
tiempo de vida en segundos (Predeterminado: 3600)
-t, --token
token cifrado codificado en base64 para validación y descifrado
-u, --hmac-alg
algoritmo hmac del cliente stun

Uso:

$ turnutils_natdiscovery
