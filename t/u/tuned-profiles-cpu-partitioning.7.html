TUNED_PROFILES_CPU_PARTITIONING(7) Manual de Información Miscelánea TUNED_PROFILES_CPU_PARTITIONING(7)

NOMBRE

tuned-profiles-cpu-partitioning - Particiona las CPUs en aisladas y de mantenimiento.

DESCRIPCIÓN

Los perfiles cpu-partitioning* particionan las CPUs del sistema en CPUs aisladas y de mantenimiento. Estos perfiles están destinados a cargas de trabajo sensibles a la latencia.

Una CPU aislada incurre en una menor fluctuación y reducidas interrupciones por parte del kernel. Esto se logra limpiando la CPU de procesos del espacio de usuario, hilos del kernel movibles, manejadores de interrupciones, temporizadores del kernel, etc. La única fuente fija de interrupciones es el tick de 1Hz mantenido por el kernel para mantener estadísticas de uso de la CPU. De lo contrario, la fluctuación e interrupciones incurridas, si las hay, dependen de los servicios del kernel utilizados por el hilo que se ejecuta en la CPU aislada. Solo se espera que los hilos que ejecutan un bucle ocupado sin realizar llamadas al sistema, como los controladores del espacio de usuario que acceden directamente al hardware, se interrumpan una vez por segundo por el tick de 1Hz.

Una CPU de mantenimiento es lo opuesto a una CPU aislada. Las CPUs de mantenimiento ejecutan todos los demonios, procesos de shell, hilos del kernel, manejadores de interrupciones y trabajos que pueden ser despachados desde CPUs aisladas, como E/S de disco, trabajo RCU, temporizadores, etc.

PERFILES

Se proporcionan los siguientes perfiles:

cpu-partitioning
Perfil que particiona las CPUs del sistema en CPUs aisladas y de mantenimiento.
cpu-partitioning-powersave
Perfil similar al perfil cpu-partitioning, pero con más flexibilidad en la configuración de los estados C.

CONFIGURACIÓN

El perfil cpu-partitioning se configura editando el archivo /etc/tuned/cpu-partitioning-variables.conf. Hay dos opciones de configuración:

isolated_cores=<LISTA-DE-CPU>
Lista de CPUs a aislar. Esta opción es obligatoria. Cualquier CPU que no esté en esta lista se considera automáticamente una CPU de mantenimiento.
no_balance_cores=<LISTA-DE-CPU>
Lista de CPUs que el kernel no debe considerar al realizar el balanceo de carga de procesos en todo el sistema. Normalmente, esta lista debería ser la misma que isolated_cores=. Esta opción es opcional.

El perfil cpu-partitioning-powersave se configura editando el archivo /etc/tuned/cpu-partitioning-powersave-variables.conf. Admite las mismas opciones que el perfil cpu-partitioning y una opción adicional:

max_power_state=<MAX_CSTATE>
Estado C máximo que los núcleos pueden alcanzar. Puede expresarse como su nombre (C1E) o latencia mínima de activación, en microsegundos. Este parámetro se proporciona tal cual a `force_latency`. El valor predeterminado se establece en "cstate.name:C1|10" para comportarse como el perfil cpu-partitioning.

NOTAS IMPORTANTES

  • El sistema debe reiniciarse después de aplicar los perfiles cpu-partitioning* por primera vez o al cambiar su configuración.
  • Los perfiles cpu-partitioning* se pueden utilizar en máquinas físicas y virtuales.
  • Al usar los perfiles cpu-partitioning* en máquinas físicas, se recomienda encarecidamente "enmascarar" los servicios ksm y ksmtuned en systemd (si están instalados). Esto se puede hacer con el siguiente comando:


    # systemctl mask ksm ksmtuned

  • Los perfiles cpu-partitioning* no utilizan la función isolcpus= del kernel.
  • En un sistema NUMA, se recomienda tener al menos una CPU de mantenimiento por nodo NUMA.
  • Los perfiles cpu-partitioning* no admiten el aislamiento de la caché L3. Esto significa que una CPU de mantenimiento aún puede dañar las entradas de caché pertenecientes a CPUs aisladas. Se recomienda utilizar tecnologías de aislamiento de caché para solucionar este problema, como la Tecnología de Asignación de Caché de Intel.
  • Que el kernel pueda desactivar el tick en CPUs aisladas o no, depende de algunos factores relacionados con el comportamiento del hilo en ejecución. Consulte la documentación de nohz_full en el kernel para obtener más información.
  • El proyecto Linux de tiempo real ha elaborado un documento sobre las mejores prácticas para escribir aplicaciones de tiempo real. Aunque los perfiles cpu-partitioning* no garantizan tiempos de respuesta en tiempo real, muchas de las técnicas para escribir aplicaciones de tiempo real también se aplican a las aplicaciones destinadas a ejecutarse bajo los perfiles cpu-partitioning*. Consulte este documento en https://rt.wiki.kernel.org .
