TCSH(1) Manual de Comandos Generales TCSH(1)

NOMBRE

tcsh — Shell C con autocompletado de nombres de archivo y edición de línea de comandos

SINOPSIS

tcsh [-bcdefFimnqstvVxX] [-Dnombre[=valor]] [arg] ...

tcsh -l

DESCRIPCIÓN

tcsh es una versión mejorada pero completamente compatible de la shell C de Berkeley UNIX, csh(1). Es un intérprete de lenguaje de comandos utilizable tanto como shell de inicio de sesión interactiva como procesador de comandos de scripts de shell. Incluye un editor de línea de comandos (ver El editor de línea de comandos (+)), autocompletado programable de palabras (ver Autocompletado y listado (+)), corrección ortográfica (ver Corrección ortográfica (+)), un mecanismo de historial (ver Sustitución de historial), control de trabajos (ver Trabajos) y una sintaxis similar a C. La sección NUEVAS CARACTERÍSTICAS (+) describe las principales mejoras de tcsh sobre csh(1). A lo largo de este manual, las características de tcsh que no se encuentran en la mayoría de las implementaciones de csh(1) (específicamente, la csh(1) de 4.4BSD) están etiquetadas con ‘(+)’, y las características que están presentes en csh(1) pero no suelen documentarse están etiquetadas con ‘(u)’.

Procesamiento de listas de argumentos

Si el primer argumento (argumento 0) para el shell es ‘-’, entonces es un shell de inicio de sesión. Un shell de inicio de sesión también puede especificarse invocando el shell con la bandera -l como único argumento.

El resto de los argumentos de bandera se interpretan de la siguiente manera:

-b
Fuerza una “ruptura” del procesamiento de opciones, haciendo que cualquier argumento posterior del shell se trate como argumentos no opcionales. Los argumentos restantes no se interpretarán como opciones del shell. Esto puede usarse para pasar opciones a un script de shell sin confusión o posible subterfugio. El shell no ejecutará un script con usuario-ID establecido sin esta opción.
-c
Los comandos se leen del argumento siguiente (que debe estar presente y debe ser un único argumento), se almacenan en la variable de shell command para su referencia y se ejecutan. Cualquier argumento restante se coloca en la variable de shell argv.
-d
El shell carga la pila de directorios desde ~/.cshdirs como se describe en Inicio y finalización, independientemente de si es un shell de inicio de sesión o no. (+)
-Dnombre[=valor]
Establece la variable de entorno nombre a valor. (Solo Domain/OS) (+)
-e
El shell sale si algún comando invocado termina de forma anormal o produce un estado de salida distinto de cero.
-f
El shell no carga ningún archivo de recursos o de inicio, ni realiza ningún Hashing de comandos, y por lo tanto, se inicia más rápido.
-F
El shell usa fork(2) en lugar de vfork(2) para crear procesos. (+)
-i
El shell es interactivo y solicita su entrada de nivel superior, incluso si parece no ser una terminal. Los shells son interactivos sin esta opción si sus entradas y salidas son terminales.
-l
El shell es un shell de inicio de sesión. Aplicable solo si -l es la única bandera especificada.
-m
El shell carga ~/.tcshrc incluso si no pertenece al usuario efectivo. Versiones más nuevas de su(1) pueden pasar -m al shell. (+)
-n
El shell analiza los comandos pero no los ejecuta. Esto ayuda a depurar scripts de shell.
-q
El shell acepta SIGQUIT (ver Manejo de señales) y se comporta cuando se utiliza bajo un depurador. El control de trabajos está deshabilitado. (u)
-s
La entrada de comandos se toma de la entrada estándar.
-t
El shell lee y ejecuta una sola línea de entrada. Un ‘\’ puede usarse para escapar el salto de línea al final de esta línea y continuar en otra línea.
-v
Establece la variable de shell verbose, para que la entrada del comando se muestre después de la sustitución del historial.
-x
Establece la variable de shell echo, para que los comandos se muestren inmediatamente antes de su ejecución.
-V
Establece la variable de shell verbose incluso antes de ejecutar ~/.tcshrc.
-X
Es a -x lo que -V es a -v.
--help
Imprime un mensaje de ayuda en la salida estándar y sale. (+)
--version
Imprime la versión/plataforma/opciones de compilación en la salida estándar y sale. Esta información también está contenida en la variable de shell version. (+)

Después del procesamiento de los argumentos de bandera, si quedan argumentos pero no se dieron las opciones -c, -i, -s, o -t, el primer argumento se toma como el nombre de un archivo de comandos, o “script”, a ejecutar. El shell abre este archivo y guarda su nombre para una posible resustitución por ‘$0’. Debido a que muchos sistemas usan la versión 6 o 7 de las shells, cuyas scripts de shell no son compatibles con esta shell, el shell usa una shell “estándar” para ejecutar un script cuyo primer carácter no es un ‘#’, es decir, que no comienza con un comentario.

Los argumentos restantes se colocan en la variable de shell argv.

Inicio y finalización

Un shell de inicio de sesión comienza ejecutando comandos desde los archivos del sistema /etc/csh.cshrc y /etc/csh.login. Luego ejecuta comandos desde archivos en el directorio home del usuario: primero ~/.tcshrc (+) o, si ~/.tcshrc no se encuentra, ~/.cshrc, luego el contenido de ~/.history (o el valor de la variable de shell histfile) se carga en memoria, luego ~/.login, y finalmente ~/.cshdirs (o el valor de la variable de shell dirsfile) (+). delete-char-or-list-or-eof lista solo al final de la línea; en medio de una línea, elimina el carácter debajo del cursor y en una línea vacía, cierra la sesión o, si la variable ignoreeof está configurada, no hace nada. Los comandos del editor complete-word-fwd y complete-word-back (no enlazados a ninguna tecla por defecto) pueden ser usados para recorrer hacia arriba y hacia abajo la lista de completados posibles, reemplazando la palabra actual con la siguiente o anterior palabra de la lista.

La variable del shell fignore puede ser configurada a una lista de sufijos que serán ignorados por el completado. Considere lo siguiente:

> ls
Makefile        condiments.h~   main.o          side.c
README          main.c          meal            side.o
condiments.h    main.c~
> set fignore = (.o \~)
> emacs ma[^D]
main.c   main.c~  main.o
> emacs ma[tab]
> emacs main.c

‘main.c~’ y ‘main.o’ son ignorados por el completado (pero no por el listado), porque terminan en sufijos en fignore. Nótese que se necesitó una ‘\’ delante de ‘~’ para evitar que fuera expandida a home como se describe en Sustitución de nombres de archivo. fignore es ignorado si solo un completado es posible.

Si la variable del shell complete está configurada a ‘enhance’, el completado 1) ignora mayúsculas y minúsculas y 2) considera puntos, guiones y guiones bajos (‘.’, ‘-’, y ‘_’) como separadores de palabras y considera guiones y guiones bajos como equivalentes. Si tuviera los siguientes archivos

comp.lang.c      comp.lang.perl   comp.std.c++
comp.lang.c++    comp.std.c

y escribiera

mail -f c.l.c[tab]
sería completado a
mail -f comp.lang.c
y al escribir
mail -f c.l.c[^D]
se listarían ‘comp.lang.c’ y ‘comp.lang.c++’.

Al escribir

mail -f c..c++[^D]
se listarían ‘comp.lang.c++’ y ‘comp.std.c++’.

Al escribir

rm a--file[^D]
en el siguiente directorio 
A_silly_file    a-hyphenated-file    another_silly_file

se listarían los tres archivos, porque se ignoran las mayúsculas y minúsculas y los guiones y guiones bajos son equivalentes. Los puntos, sin embargo, no son equivalentes a guiones o guiones bajos.

Si la variable del shell complete está configurada a ‘Enhance’, el completado ignora las mayúsculas y minúsculas y las diferencias entre un guion y un guion bajo separador de palabras solo cuando el usuario escribe un carácter en minúscula o un guion. Escribir un carácter en mayúscula o un guion bajo no coincidirá con el carácter en minúscula o el separador de palabras guion correspondiente.

Al escribir

rm a--file[^D]
en el directorio del ejemplo anterior todavía se listarían los tres archivos, pero al escribir
rm A--file
solo coincidiría ‘A_silly_file’ y al escribir
rm a__file[^D]
solo coincidirían ‘A_silly_file’ y ‘another_silly_file’ porque el usuario utilizó explícitamente un carácter en mayúscula o un guion bajo.

El completado y el listado se ven afectados por varias otras variables del shell: recexact puede ser configurada para completar en la coincidencia única más corta posible, incluso si más escritura podría resultar en una coincidencia más larga:

> ls
fodder   foo      food     foonly
> set recexact
> rm fo[tab]

simplemente emite un pitido, porque ‘fo’ podría expandirse a ‘fod’ o ‘foo’, pero si escribimos otra ‘o’,

> rm foo[tab]
> rm foo

el completado se completa en ‘foo’, aunque ‘food’ y ‘foonly’ también coincidan. autoexpand puede ser configurada para ejecutar el comando del editor expand-history antes de cada intento de completado, autocorrect puede ser configurada para corregir la ortografía de la palabra a completar (ver Corrección ortográfica (+)) antes de cada intento de completado y correct puede ser configurada para completar comandos automáticamente después de presionar intro. matchbeep puede ser configurada para hacer que el completado emita un pitido o no en una variedad de situaciones, y nobeep puede ser configurada para nunca emitir un pitido. nostat puede ser configurada a una lista de directorios y/o patrones que coincidan con directorios para evitar que el mecanismo de completado realice stat(2) en esos directorios. listmax y listmaxrows pueden ser configuradas para limitar el número de elementos y filas (respectivamente) que se listan sin preguntar primero. recognize_only_executables puede ser configurada para hacer que el shell liste solo ejecutables al listar comandos, pero es bastante lento.

Finalmente, el comando incorporado complete puede ser usado para indicarle al shell cómo completar palabras que no sean nombres de archivo, comandos o variables. El completado y el listado no funcionan en patrones glob (ver Sustitución de nombres de archivo), pero los comandos del editor list-glob y expand-glob realizan funciones equivalentes para patrones glob.

Corrección ortográfica (+)

El shell a veces puede corregir la ortografía de nombres de archivo, comandos y variables, así como completarlos y listarlos.

Las palabras individuales pueden ser corregidas ortográficamente con el comando del editor spell-word (generalmente enlazado a M-s y M-S) y el buffer de entrada completo con spell-line (generalmente enlazado a M-$). La variable del shell correct puede ser configurada a ‘cmd’ para corregir el nombre del comando o ‘all’ para corregir la línea completa cada vez que se presiona intro, y autocorrect puede ser configurada para corregir la palabra a completar antes de cada intento de completado.

Cuando la corrección ortográfica se invoca de cualquiera de estas maneras y el shell cree que alguna parte de la línea de comandos está mal escrita, solicita la línea corregida:

> set correct = cmd
> lz /usr/bin
CORRECT>ls /usr/bin (y|n|e|a)?

Se puede responder ‘y’ o espacio para ejecutar la línea corregida, ‘e’ para dejar el comando sin corregir en el buffer de entrada, ‘a’ para abortar el comando como si se hubiera presionado ^C, y cualquier otra cosa para ejecutar la línea original sin cambios.

La corrección ortográfica reconoce completados definidos por el usuario (ver el comando incorporado complete). Si una palabra de entrada en una posición para la cual se define un completado se parece a una palabra en la lista de completados, la corrección ortográfica registra un error de escritura y sugiere la última palabra como corrección. Sin embargo, si la palabra de entrada no coincide con ninguno de los completados posibles para esa posición, la corrección ortográfica no registra un error de escritura.

Al igual que el completado, la corrección ortográfica funciona en cualquier lugar de la línea, empujando el resto de la línea hacia la derecha y posiblemente dejando caracteres adicionales a la derecha del cursor.

Comandos del editor (+)

bindkey lista los enlaces de teclas y bindkey -l lista y describe brevemente los comandos del editor. Solo se describen aquí los comandos del editor nuevos o especialmente interesantes. Ver emacs(1) y vi(1) para descripciones de los enlaces de teclas de cada editor.

El carácter o caracteres a los que cada comando está enlazado por defecto se indica entre paréntesis. ^carácter significa un carácter de control y M-carácter un carácter meta, escrito como escape-carácter (o ^[carácter) en terminales sin tecla meta. Las mayúsculas y minúsculas cuentan, pero los comandos que están enlazados a letras por defecto están enlazados tanto a letras minúsculas como mayúsculas por conveniencia.

Los comandos del editor soportados son:

Mover hacia atrás un carácter. El comportamiento del cursor está modificado por vimode.
backward-delete-word (M-^H, M-^?)
Corta desde el inicio de la palabra actual hasta el cursor - guardado en el búfer de corte. El comportamiento de los límites de palabra se modifica por vimode.
backward-word (M-b, M-B)
Mueve al inicio de la palabra actual. El comportamiento de los límites de palabra y del cursor se modifica por vimode.
beginning-of-line (^A, home)
Mueve al inicio de la línea. El comportamiento del cursor se modifica por vimode.
capitalize-word (M-c, M-C)
Pone en mayúsculas los caracteres desde el cursor hasta el final de la palabra actual. El comportamiento de los límites de palabra se modifica por vimode.
complete-word (tab)
Completa una palabra como se describe en Completado y listado (+).
complete-word-back (no enlazado)
Similar a complete-word-fwd, pero retrocede desde el final de la lista.
complete-word-fwd (no enlazado)
Reemplaza la palabra actual con la primera palabra de la lista de completados posibles. Puede repetirse para avanzar en la lista. Al final de la lista, emite un pitido y vuelve a la palabra incompleta.
complete-word-raw (^X-tab)
Similar a complete-word, pero ignora los completados definidos por el usuario.
copy-prev-word (M-^_)
Copia la palabra anterior en la línea actual al búfer de entrada. Ver también insert-last-word. El comportamiento de los límites de palabra se modifica por vimode.
dabbrev-expand (M-/)
Expande la palabra actual a la más reciente que la precede y para la cual la actual es una subcadena inicial, dando la vuelta a la lista de historial (una vez) si es necesario. Repetir dabbrev-expand sin escribir nada intermedio cambia a la siguiente palabra anterior, etc., omitiendo coincidencias idénticas de forma similar a como lo hace history-search-backward.
delete-char (no enlazado)
Elimina el carácter debajo del cursor. Ver también delete-char-or-list-or-eof. El comportamiento del cursor se modifica por vimode.
delete-char-or-eof (no enlazado)
Realiza delete-char si hay un carácter debajo del cursor o end-of-file en una línea vacía. Ver también delete-char-or-list-or-eof. El comportamiento del cursor se modifica por vimode.

Realiza delete-char si hay un carácter debajo del cursor o list-choices al final de la línea. Ver también delete-char-or-list-or-eof.

Realiza delete-char si hay un carácter debajo del cursor, list-choices al final de la línea o end-of-file en una línea vacía. Corta desde el cursor hasta el final de la palabra actual - guarda en el búfer de corte. El comportamiento de los límites de palabra se modifica por vimode.
down-history (down, ^N)
Similar a up-history, pero avanza, deteniéndose en la línea de entrada original.
downcase-word (M-l, M-L)

Estructura léxica

El shell divide las líneas de entrada en palabras en los espacios en blanco y tabulaciones. Los caracteres especiales ‘&’, ‘|’, ‘;’, ‘<’, ‘>’, ‘(’, y ‘)’, y los caracteres duplicados ‘&&’, ‘||’, ‘<<’, y ‘>>’ son siempre palabras separadas, estén o no rodeadas de espacios en blanco.

Cuando la entrada del shell no es una terminal, el carácter ‘#’ se toma para iniciar un comentario. Cada ‘#’ y el resto de la línea de entrada en la que aparece se descartan antes de un análisis posterior.

Se puede evitar que un carácter especial (incluido un espacio en blanco o una tabulación) tenga su significado especial, y posiblemente se convierta en parte de otra palabra, precediéndolo con una barra invertida (‘\’) o encerrándolo entre comillas simples (‘'’), dobles (‘"’), o invertidas (‘`’). Cuando no se citan de otra manera, una nueva línea precedida por una ‘\’ es equivalente a un espacio en blanco, pero dentro de las comillas esta secuencia da como resultado una nueva línea.

Además, todas las Sustituciones excepto la Sustitución de historial se pueden prevenir encerrando las cadenas (o partes de cadenas) en las que aparecen con comillas simples o citando el(los) carácter(es) crucial(es) (por ejemplo, ‘$’ o ‘`’ para la Sustitución de variables o la Sustitución de comandos respectivamente) con ‘\’. (La sustitución de alias no es una excepción: citar de cualquier manera cualquier carácter de una palabra para la cual se haya definido un alias evita la sustitución del alias. La forma habitual de citar un alias es precederlo con una barra invertida.) La sustitución de historial se previene con barras invertidas pero no con comillas simples. Las cadenas citadas con comillas dobles o invertidas se someten a Sustitución de variables y Sustitución de comandos, pero otras sustituciones se previenen.

El texto dentro de comillas simples o dobles se convierte en una sola palabra (o parte de ella). Los metacaracteres en estas cadenas, incluidos los espacios en blanco y las tabulaciones, no forman palabras separadas. Solo en un caso especial (ver Sustitución de comandos) una cadena entre comillas dobles puede producir partes de más de una palabra; las cadenas entre comillas simples nunca lo hacen. Las comillas invertidas son especiales: señalan la Sustitución de comandos, que puede resultar en más de una palabra.

Las secuencias de escape al estilo C se pueden usar en cadenas entre comillas simples anteponiendo la comilla inicial con ‘$’. (+) Ver Secuencias de escape (+) para una lista completa de secuencias de escape reconocidas.

Citar cadenas complejas, particularmente cadenas que contienen caracteres de cita, puede ser confuso. ¡Recuerda que las comillas no tienen que usarse como en la escritura humana! Puede ser más fácil citar no toda la cadena, sino solo aquellas partes de la cadena que necesitan ser citadas, utilizando diferentes tipos de comillas para hacerlo si es apropiado.

La variable del shell backslash_quote se puede establecer para hacer que las barras invertidas citen siempre ‘\’, ‘'’, y ‘"’ (+). Esto puede facilitar las tareas de citación complejas, pero puede causar errores de sintaxis en los scripts de csh(1).

Sustituciones

Ahora describimos las diversas transformaciones que el shell realiza en la entrada en el orden en que ocurren. Notamos de paso las estructuras de datos involucradas y los comandos y variables que las afectan. Recuerde que las sustituciones se pueden prevenir citando como se describe en Estructura léxica.

Sustitución de historial

Cada comando, o "evento", introducido desde la terminal se guarda en la lista de historial. El comando anterior siempre se guarda, y la variable del shell history se puede establecer en un número para guardar esa cantidad de comandos. La variable del shell histdup se puede establecer para no guardar eventos duplicados o eventos duplicados consecutivos.

Los comandos guardados se numeran secuencialmente a partir de 1 y se marcan con la hora. No suele ser necesario utilizar los números de evento, pero el número de evento actual puede formar parte del prompt colocando un ‘!’ en la variable del shell prompt.

Por defecto, las entradas del historial se muestran imprimiendo cada token analizado separado por un espacio; por lo tanto, el operador de redirección ‘>&!’ se mostrará como ‘> & !’. El shell realmente guarda el historial en formas expandidas y literales (no expandidas). Si la variable del shell histlit está establecida, los comandos que muestran y almacenan el historial utilizan la forma literal.

El comando incorporado history puede imprimir, almacenar en un archivo, restaurar y borrar la lista de historial en cualquier momento, y las variables del shell savehist y histfile se pueden establecer para almacenar la lista de historial automáticamente al cerrar sesión y restaurarla al iniciar sesión.

Las sustituciones de historial introducen palabras de la lista de historial en el flujo de entrada, lo que facilita la repetición de comandos, la repetición de argumentos de un comando anterior en el comando actual, o la corrección de errores ortográficos en el comando anterior con poca escritura y un alto grado de confianza.

Las sustituciones de historial comienzan con el carácter ‘!’. Pueden comenzar en cualquier lugar del flujo de entrada, pero no se anidan. La ‘!’ puede ir precedida por una ‘\’ para evitar su significado especial; por conveniencia, una ‘!’ se pasa sin cambios cuando va seguida de un espacio en blanco, tabulación, nueva línea, ‘=’ o ‘(’.

Las sustituciones de historial también ocurren cuando una línea de entrada comienza con ‘^’; ver Abreviatura de sustitución de historial.

Una referencia de historial puede tener un designador de palabra pero ninguna especificación de evento. Entonces hace referencia al comando anterior.

Continuando con nuestro ejemplo del comando ‘diff’ (evento 12), podríamos haber escrito simplemente

diff !^.old !^
o, para obtener los argumentos en orden inverso, solo
diff !*

La palabra o palabras en una referencia de historial pueden ser editadas, o “modificadas”, al seguirla con uno o más modificadores (con el ‘:’ inicial mostrado), cada uno precedido por un ‘:’:

:Word
Modificador de palabra del historial
:h
Eliminar un componente de ruta final, dejando la cabeza.
:t
Eliminar todos los componentes de ruta iniciales, dejando la cola.
:r
Eliminar una extensión de nombre de archivo ‘.xxx’, dejando el nombre raíz.
:e
Eliminar todo excepto la extensión.
:u
Convertir a mayúsculas la primera letra minúscula.
:l
Convertir a minúsculas la primera letra mayúscula.
:s/l/r/
Sustituir l por r. l es simplemente una cadena como r, no una expresión regular como en el comando epónimo de ed(1). Cualquier carácter puede ser utilizado como delimitador en lugar de ‘/’; un ‘\’ puede ser usado para citar el delimitador dentro de l y r. El carácter ‘&’ en la r se reemplaza por l; ‘\’ también cita ‘&’. Si l está vacío (‘’), se usa la l de una sustitución anterior o la s de una búsqueda anterior o el número de evento en la especificación de evento. Repetir la sustitución anterior.
:g
Aplicar el siguiente modificador una vez a cada palabra.

3

Como ‘:q’, pero divide en palabras en espacios, tabulaciones y nuevas líneas.

Por ejemplo, el comando ‘diff’ (evento 12) en el ejemplo del historial en Especificación de eventos del historial,

diff wumpus.man.old wumpus.man
podría haber sido escrito como

usando ‘:r’ para eliminar ‘.old’ del primer argumento en la misma línea (‘!#^’).

Podríamos escribir

echo hello out there
luego
echo !*:u
para capitalizar ‘hello’,
echo !*:au
para convertir a mayúsculas la primera palabra a ‘HELLO’, o
echo !*:agu
para convertir a mayúsculas todas las palabras.

Podríamos seguir

mail -s "I forgot my password" rot
con

para corregir la ortografía de ‘root’ (ver Modificadores de palabras del historial y Corrección ortográfica (+) para enfoques diferentes).

(+) En csh(1) tal cual, solo un modificador puede ser aplicado a cada expansión de historial o variable. En tcsh, se pueden usar más de uno, por ejemplo

% mv wumpus.man /usr/share/man/man1/wumpus.1
% man !$:t:r
man wumpus

En csh(1), el resultado sería

wumpus.1:r

> mv a.out /usr/games/wumpus
> setenv PATH !$:h:$PATH

setenv PATH /usr/games:/bin:/usr/bin:.

El primer intento tendría éxito en csh(1) pero falla en tcsh, porque tcsh espera otro modificador después del segundo ‘:’ en lugar de ‘$’.

Existe una abreviatura especial para sustituciones; ‘^’, cuando es el primer carácter en una línea de entrada, es equivalente a ‘!:s^’. Así, podríamos seguir el ejemplo de Modificadores de palabras del historial

mail -s "I forgot my password" rot
con
^rot^root
para hacer la corrección ortográfica. Esta es la única sustitución de historial que no comienza explícitamente con ‘!’.

Finalmente, se puede acceder al historial a través del editor, así como a través de las sustituciones descritas. Los comandos del editor up-history y down-history, history-search-backward y history-search-forward, i-search-back y i-search-fwd, vi-search-back y vi-search-fwd, copy-prev-word e insert-last-word buscan eventos en la lista del historial y los copian al búfer de entrada. Sustitución de alias

El shell mantiene una lista de alias que pueden ser establecidos, anulados y mostrados por los comandos alias y unalias. Después de que una línea de comando es analizada en comandos simples (ver Comandos) la primera palabra de cada comando, de izquierda a derecha, se verifica para ver si tiene un alias. Si es así, la primera palabra se reemplaza por el alias. Si el alias contiene una referencia al historial, se somete a Sustitución de historial como si el comando original fuera la línea de entrada anterior. Si el alias no contiene una referencia al historial, la lista de argumentos se deja sin modificar.

Así, si el alias para ‘ls’ fuera

ls -l
el comando
ls /usr
se convertiría en
ls -l /usr
la lista de argumentos aquí sin modificar.

Si el alias para ‘lookup’ fuera

grep !^ /etc/passwd
entonces

se convertiría en
grep bill /e

tc

The tc shell is a command interpreter for the TENEX C Shell.

This file describes the features of tc, specifically how it interprets shell input.

See also tc(1).

PREPROCESSOR DIRECTIVES

The shell performs several preprocessing steps on each command line before executing it. These include alias substitution, variable substitution, and filename (glob) expansion.

Alias substitution

The shell maintains a list of aliases, each of which maps a name to a list of words. The alias and unalias commands manipulate this list. Aliases are used to provide abbreviations for common commands or phrases.

When an alias is defined, it is added to the list of aliases. If the alias name is already defined, the old definition is replaced. If the alias definition contains a metacharacter or references a special shell variable, it may be processed differently. See Special aliases (+).

When a command line is read, the shell checks if the first word corresponds to an alias. If it does, the alias name is replaced by the words in the alias definition. This process is repeated until the first word is no longer an alias. This allows for nested aliases and complex command sequences.

If an alias substitution does not change the first word of the command line, it is flagged to prevent infinite loops. Other loops are detected and result in an error. For example, defining an alias `foo` that expands to `foo` would cause an error.

Aliases can also be used to introduce parser metasyntax. For example,

alias print 'pr \!* | lpr'
defines a “command” (‘print’) which pr(1)s its arguments to the line printer.

Alias substitution is repeated until the first word of the command has no alias. If an alias substitution does not change the first word (as in the previous example) it is flagged to prevent a loop. Other loops are detected and cause an error.

Some aliases are referred to by the shell; see Special aliases (+).

Variable substitution

The shell maintains a list of variables, each of which has as value a list of zero or more words. The values of shell variables can be displayed and changed with the set and unset commands. The system maintains its own list of “environment” variables. These can be displayed and changed with printenv, setenv, and unsetenv.

(+) Variables may be made read-only with

set -r
Read-only variables may not be modified or unset; attempting to do so will cause an error. Once made read-only, a variable cannot be made writable, so
set -r
should be used with caution. Environment variables cannot be made read-only.

Some variables are set by the shell or referred to by it. For instance, the argv variable is an image of the shell's argument list, and words of this variable's value are referred to in special ways. Some of the variables referred to by the shell are toggles; the shell does not care what their value is, only whether they are set or not. For instance, the verbose variable is a toggle which causes command input to be echoed. The -v command line option sets this variable. Special shell variables lists all variables which are referred to by the shell.

Other operations treat variables numerically. The ‘@’ command permits numeric calculations to be performed and the result assigned to a variable. Variable values are, however, always represented as (zero or more) strings. For the purposes of numeric operations, the null string is considered to be zero, and the second and subsequent words of multi-word values are ignored.

After the input line is aliased and parsed, and before each command is executed, variable substitution is performed keyed by ‘$’ characters. This expansion can be prevented by preceding the ‘$’ with a ‘\’ except within ‘"’ pairs where it always occurs, and within ‘'’ pairs where it never occurs. Strings quoted by ‘`’ are interpreted later (see Command substitution) so ‘$’ substitution does not occur there until later, if at all. A ‘$’ is passed unchanged if followed by a blank, tab, or end-of-line.

Input/output redirections are recognized before variable expansion, and are variable expanded separately. Otherwise, the command name and entire argument list are expanded together. It is thus possible for the first (command) word (to this point) to generate more than one word, the first of which becomes the command name, and the rest of which become arguments.

Unless enclosed in ‘"’ or given the ‘:q’ modifier the results of variable substitution may eventually be command and filename substituted. Within ‘"’, a variable whose value consists of multiple words expands to a (portion of a) single word, with the words of the variable's value separated by blanks. When the ‘:q’ modifier is applied to a substitution the variable will expand to multiple words with each word separated by a blank and quoted to prevent later command or filename substitution.

The editor command expand-variables, normally bound to ^X-$, can be used to interactively expand individual variables.

Variable substitution metasequences

The following metasequences are provided for introducing variable values into the shell input:

$name
 
${name}
Substitutes the words of the value of variable name, each separated by a blank. Braces insulate name from following characters which would otherwise be part of it. Shell variables have names consisting of letters and digits starting with a letter. The underscore character is considered a letter. If name is not a shell variable, but is set in the environment, then that value is returned (but some of the other forms given below are not available in this case).
$name[selector]
 
${name[selector]}
Substitutes only the selected words from the value of name. The selector is subjected to ‘$’ substitution and may consist of a single number or two numbers separated by a ‘-’. The first word of a variable's value is numbered ‘1’. If the first number of a range is omitted it defaults to ‘1’. If the last member of a range is omitted it defaults to ‘$#name’. The selector ‘*’ selects all words. It is not an error for a range to be empty if the second argument is omitted or in range.
$0
Substitutes the name of the file from which command input is being read. An error occurs if the name is not known.
$number
 
${number}
Equivalent to ‘$argv[number]’.
$*
Equivalent to ‘$argv’, which is equivalent to ‘$argv[*]’.

Except as noted, it is an error to reference a variable which is not set.

The ‘:’ modifiers described under History word modifiers, except for ‘:p’, can be applied to the substitutions above. More than one may be used. (+) Braces may be needed to insulate a variable substitution from a literal ‘:’ just as with History word modifiers; any modifiers must appear within the braces.

Variable substitution without modifiers

The following substitutions cannot be modified with ‘:’ modifiers:

$?name
 
${?name}
Substitutes the string ‘1’ if name is set, ‘0’ if it is not.
$?0
Substitutes ‘1’ if the current input filename is known, ‘0’ if it is not. Always ‘0’ in interactive shells.
$#name
 
${#name}
Substitutes the number of words in name.
$#
Equivalent to ‘$#argv’. (+)
$%name
 
${%name}
Substitutes the number of characters in name. (+)
$%number
 
${%number}
Substitutes the number of characters in ‘$argv[number]’. (+)
$?
Substitutes the status, with the same interpretation as that returned by the wait command, of the last synchronously executed foreground command.
$!
Substitutes the process number of the last background command executed.
$~
Substitutes the name of the shell.

The ?:, #?, ?, #!, and $~ forms can only appear alone. They are expanded first. They do not prevent subsequent scanning.

Variable substitution

The shell replaces the following input strings with values determined by the shell's state.

$
Equivalent to ‘$status’. (+)
$$
Substitutes the (decimal) process number of the (parent) shell.
$!
Substitutes the (decimal) process number of the last background process started by this shell. (+)
$_
Substitutes the command line of the last command executed. (+)
$<
Substitutes a line from the standard input, with no further interpretation thereafter. It can be used to read from the keyboard in a shell script. (+) While csh(1) always quotes ‘$<’, as if it were equivalent to ‘$<:q’, tcsh does not. Furthermore, when tcsh is waiting for a line to be typed the user may type an interrupt to interrupt the sequence into which the line is to be substituted, but csh(1) does not allow this.
$?<
Substitutes the number of available bytes from the standard input. (This feature might be non-portable.) (+)

Sustitución de comandos, nombres de archivo y pila de directorios

Las sustituciones restantes se aplican selectivamente a los argumentos de los comandos incorporados. Esto significa que las porciones de expresiones que no se evalúan no se someten a estas expansiones. Para comandos que no son internos del shell, el nombre del comando se sustituye por separado de la lista de argumentos. Esto ocurre muy tarde, después de que se realiza la redirección de entrada/salida, y en un hijo del shell principal.

Sustitución de comandos

La sustitución de comandos se indica mediante un comando entre comillas simples (‘`’). La salida de dicho comando se divide en palabras separadas por espacios, tabulaciones y nuevas líneas, y se descartan las palabras nulas. La salida se sustituye y se pone en lugar de la cadena original.

Las sustituciones de comandos dentro de comillas dobles (‘"’) conservan los espacios y las tabulaciones; solo las nuevas líneas fuerzan nuevas palabras. La única nueva línea final no fuerza una nueva palabra en ningún caso. Es posible, por lo tanto, que una sustitución de comandos produzca solo una parte de una palabra, incluso si el comando genera una línea completa.

Por defecto, el shell desde la versión 6.12 reemplaza todos los caracteres de nueva línea y retorno de carro en el comando por espacios. Si esto se desactiva al eliminar la configuración de csubstnonl, las nuevas líneas separan los comandos como de costumbre.

Sustitución de nombres de archivo

Si una palabra contiene alguno de los caracteres ‘*’, ‘?’, ‘[’, o ‘{’ o comienza con el carácter ‘~’, es candidata a la sustitución de nombres de archivo, también conocida como "globbing". Esta palabra se considera entonces un patrón ("patrón de globbing") y se reemplaza con una lista ordenada alfabéticamente de nombres de archivo que coinciden con el patrón.

En los nombres de archivo que coinciden, el carácter ‘.’ al principio de un nombre de archivo o inmediatamente después de una ‘/’, así como el carácter ‘/’, deben coincidir explícitamente (a menos que se establezcan globdot o globstar o ambos (+)). El carácter ‘*’ coincide con cualquier cadena de caracteres, incluida la cadena nula. El carácter ‘?’ coincide con cualquier carácter individual. La secuencia ‘[...]’ coincide con cualquiera de los caracteres encerrados. Dentro de ‘[...]’, un par de caracteres separados por ‘-’ coincide con cualquier carácter léxicamente entre los dos.

(+) Algunos patrones de globbing se pueden negar: La secuencia ‘[^...]’ coincide con cualquier carácter individual no especificado por los caracteres y/o rangos de caracteres en las llaves.

También se puede negar todo un patrón de globbing con ‘^’>:

> echo *
bang crash crunch ouch
> echo ^cr*
bang ouch

Los patrones de globbing que no utilizan ‘?’, ‘*’, o ‘[]’, o que utilizan ‘{}’ o ‘~’ (más abajo) no se niegan correctamente.

La metanotación ‘a{b,c,d}e’ es una abreviatura de ‘abe ace ade’. El orden de izquierda a derecha se conserva:

/usr/source/s1/{oldls,ls}.c
se expande a
/usr/source/s1/oldls.c /usr/source/s1/ls.c
Los resultados de las coincidencias se ordenan por separado a bajo nivel para preservar este orden:
../{memo,*box}
podría expandirse a
../memo ../box ../mbox
(Tenga en cuenta que ‘memo’ no se ordenó con los resultados de la coincidencia de ‘*box’.) No es un error cuando esta construcción se expande a archivos que no existen, pero es posible obtener un error de un comando al que se le pasa la lista expandida. Esta construcción puede anidarse. Como caso especial, las palabras ‘{’, ‘}’, y ‘{}’ se pasan sin cambios.

El carácter ‘~’ al principio de un nombre de archivo se refiere a los directorios de inicio. De pie solo, es decir, ‘~’, se expande al directorio de inicio del invocador tal como se refleja en el valor de la variable de shell home. Cuando va seguido de un nombre que consta de letras, dígitos y caracteres ‘-’, el shell busca un usuario con ese nombre y sustituye su directorio de inicio; por lo tanto

~ken
podría expandirse a
/usr/ken
y
~ken/chmach
podría expandirse a
/usr/ken/chmach
Si el carácter ‘~’ va seguido de un carácter que no sea una letra o ‘/’ o aparece en un lugar que no sea el principio de una palabra, se deja sin cambios. Por lo tanto, un comando como
setenv MANPATH /usr/share/man:/usr/local/share/man:~/lib/man
no realiza la sustitución del directorio de inicio como uno podría esperar.

Es un error que un patrón de globbing que contenga ‘*’, ‘?’, ‘[’, o ‘~’, con o sin ‘^’, no coincida con ningún archivo. Sin embargo, solo un patrón en una lista de patrones de globbing debe coincidir con un archivo (por lo que, por ejemplo,

rm *.a *.c *.o
fallaría solo si no hubiera archivos en el directorio actual que terminaran en ‘.a’, ‘.c’, o ‘.o’), y si la variable de shell nonomatch está configurada, un patrón (o lista de patrones) que no coincide con nada se deja sin cambios en lugar de causar un error.

La variable de shell globstar puede configurarse para permitir ‘**’ o ‘***’ como un patrón de globbing de archivos que coincide con cualquier cadena de caracteres, incluida ‘/’, recorriendo recursivamente cualquier subdirectorio existente. Por ejemplo,

ls **.c
listará todos los archivos .c en el árbol de directorios actual. Si se usa solo, coincidirá con cero o más subdirectorios. Por ejemplo
ls /usr/include/**/time.h
listará cualquier archivo llamado ‘time.h’ en el árbol de directorios de /usr/include;
ls /usr/include/**time.h
coincidirá con cualquier archivo en el árbol de directorios de /usr/include que termine en ‘time.h’; y
ls /usr/include/**time**.h
coincidirá con cualquier archivo .h que contenga ‘time’ ya sea en un nombre de subdirectorio o en el propio nombre de archivo. Para evitar problemas con la recursión, el patrón de globbing ‘**’ no descenderá a un enlace simbólico que contenga un directorio. Para anular esto, use ‘***’ (+)

La variable de shell noglob puede configurarse para evitar la sustitución de nombres de archivo, y el comando del editor expand-glob, normalmente enlazado a ^X-*, se puede usar para expandir interactivamente sustituciones individuales de nombres de archivo.

Sustitución de pila de directorios (+)

La pila de directorios es una lista de directorios, numerados a partir de cero, utilizada por los comandos incorporados pushd, popd y dirs. dirs puede imprimir, almacenar en un archivo, restaurar y borrar la pila de directorios en cualquier momento, y las variables de shell savedirs y dirsfile pueden configurarse para almacenar automáticamente la pila de directorios al cerrar sesión y restaurarla al iniciar sesión. La variable de shell dirstack puede examinarse para ver la pila de directorios y configurarse para colocar directorios arbitrarios en la pila de directorios.

El carácter ‘=’ seguido de uno o más dígitos

se expande a una entrada en la pila de directorios. El caso especial ‘=-’ se expande al último directorio de la pila. Por ejemplo:

> dirs -v
0       /usr/bin
1       /usr/spool/uucp
2       /usr/accts/sys
> echo =1
/usr/spool/uucp
> echo =0/calendar
/usr/bin/calendar
> echo =-
/usr/accts/sys

Las variables del shell noglob y nonomatch, y el comando del editor expand-glob, se aplican a la pila de directorios así como a las sustituciones de nombres de archivo.

Otras sustituciones (+)

Existen varias transformaciones más relacionadas con nombres de archivo, no estrictamente ligadas a las anteriores pero mencionadas aquí por completitud. Cualquier nombre de archivo puede expandirse a una ruta completa cuando la variable symlinks se establece a ‘expand’. Las comillas previenen esta expansión, y el comando del editor normalize-path la realiza bajo demanda. El comando del editor normalize-command expande comandos en PATH a rutas completas bajo demanda. Finalmente, cd y pushd interpretan ‘-’ como el directorio de trabajo anterior (equivalente a la variable del shell owd). Esto no es una sustitución en absoluto, sino una abreviatura reconocida solo por esos comandos. No obstante, también puede ser prevenida por el uso de comillas.

Comandos

Las siguientes tres secciones describen cómo el shell ejecuta comandos y maneja su entrada y salida.

Comandos simples, pipelines y secuencias

Un comando simple es una secuencia de palabras, la primera de las cuales especifica el comando a ejecutar. Una serie de comandos simples unidos por caracteres ‘|’ forma un pipeline. La salida de cada comando en un pipeline se conecta a la entrada del siguiente.

Los comandos simples y los pipelines pueden unirse en secuencias con ‘;’, y se ejecutarán secuencialmente. Los comandos y pipelines también pueden unirse en secuencias con ‘||’ o ‘&&’, indicando, como en el lenguaje C, que el segundo se ejecutará solo si el primero falla o tiene éxito respectivamente.

Un comando simple, pipeline o secuencia puede colocarse entre paréntesis (‘(’ y ‘)’) para formar un comando simple, que a su vez puede ser un componente de un pipeline o secuencia. Un comando, pipeline o secuencia puede ejecutarse sin esperar a que termine, siguiéndolo con un ‘&’.

Ejecución de comandos incorporados y no incorporados

Los comandos incorporados se ejecutan dentro del shell. Si algún componente de un pipeline, excepto el último, es un comando incorporado, el pipeline se ejecuta en un subshell.

Los comandos entre paréntesis siempre se ejecutan en un subshell.

(cd; pwd); pwd

imprime así el directorio home, dejándote donde estabas (imprimiendo esto después del directorio home), mientras que

cd; pwd

te deja en el directorio home. Los comandos entre paréntesis se utilizan más a menudo para evitar que cd afecte al shell actual.

Cuando un comando a ejecutar no se encuentra como comando incorporado, el shell intenta ejecutarlo a través de execve(2). Cada palabra en la variable path nombra un directorio en el que el shell buscará el comando. Si el shell no recibe la opción -f, el shell almacena en caché los nombres de estos directorios en una tabla interna para intentar un execve(2) solo en un directorio donde exista la posibilidad de que resida el comando. Esto acelera enormemente la localización de comandos cuando hay un gran número de directorios en la ruta de búsqueda. Este mecanismo de caché no se utiliza:

  1. Si la caché se desactiva explícitamente mediante unhash.
  2. Si al shell se le dio un argumento -f.
  3. Para cada componente de directorio del vector path que no comience con un ‘/’.
  4. Si el comando contiene un ‘/’.

En los cuatro casos anteriores, el shell concatena cada componente del vector de ruta con el nombre del comando dado para formar un nombre de ruta de un archivo que luego intenta ejecutar. Si la ejecución es exitosa, la búsqueda se detiene.

Si el archivo tiene permisos de ejecución pero no es un ejecutable para el sistema (es decir, no es un binario ejecutable ni un script que especifique su intérprete), se asume que es un archivo que contiene comandos de shell y se genera un nuevo shell para leerlo. El alias especial shell puede configurarse para especificar un intérprete distinto del propio shell.

En sistemas que no entienden la convención de intérprete de scripts ‘#!’, el shell puede compilarse para emularla; véase la variable del shell version. Si es así, el shell comprueba la primera línea del archivo para ver si tiene la forma

#!intérprete arg ...
Si es así, el shell inicia el intérprete con los args dados y le alimenta el archivo a través de la entrada estándar.

Entrada/salida

La entrada y salida estándar de un comando pueden redirigirse con la siguiente sintaxis:

< nombre
Abre el archivo nombre (que primero se expande por variables, comandos y nombres de archivo) como entrada estándar.
<< palabra
Lee la entrada del shell hasta una línea idéntica a palabra. palabra no se somete a sustitución de variables, nombres de archivo o comandos, y cada línea de entrada se compara con palabra antes de que se realicen las sustituciones en esa línea de entrada. A menos que aparezca una barra invertida ( ‘\’), comillas dobles ( ‘"’), comillas simples ( ‘'’) o comillas invertidas ( ‘`’) en palabra, se realizan sustituciones de variables y comandos en las líneas intermedias, permitiendo que la ‘\’ cite ‘$’, ‘\’ y ‘`’. Los comandos sustituidos conservan todos los espacios en blanco, tabuladores y saltos de línea, excepto el salto de línea final que se omite. Si la variable del shell noclobber está establecida, entonces el archivo no debe existir o ser un archivo especial de caracteres (por ejemplo, un terminal o /dev/null) o se producirá un error. Esto ayuda a prevenir la destrucción accidental de archivos. En este caso, las formas con ‘!’ pueden usarse para suprimir esta verificación. Redirección de entrada y salida

The shell can redirect standard input and standard output.

If standard output is not redirected, then text output by builtins, or output by commands run by the shell, is the same as if it had been written directly to the original standard output of the shell. If the shell is interactive, then this is normally the user’s terminal display. Standard input is normally inherited from the parent process.

If standard output is redirected, then the shell creates a pipe to the specified command. Standard input is not affected unless it too is redirected.

Standard input can be redirected from a file using ‘<’.

Standard output can be redirected to a file using ‘>’.

Standard error can be redirected using ‘2>’.

If the shell is run detached from a terminal, then its standard input is the same as that of the parent process, and its standard output and standard error are the same as that of the parent process. A detached command may still attempt to read or write to the controlling terminal of the parent process, but it is unlikely to work as desired.

Note that the default standard input for a command run detached is not the empty file /dev/null, but the original standard input of the shell. If this is a terminal and if the process attempts to read from the terminal, then the process will block and the user will be notified (see Jobs).

Diagnostic output may be directed through a pipe with the standard output. Simply use the form ‘|&’ rather than just ‘|’.

The shell cannot presently redirect diagnostic output without also redirecting standard output, but

( command > output-file ) >& error-file
is often an acceptable workaround. Either output-file or error-file may be /dev/tty to send output to the terminal.

Características

Having described how the shell accepts, parses and executes command lines, we now turn to a variety of its useful features.

Flujo de control

The shell contains a number of commands which can be used to regulate the flow of control in command files (shell scripts) and (in limited but useful ways) from terminal input. These commands all operate by forcing the shell to reread or skip in its input and, due to the implementation, restrict the placement of some of the commands.

The foreach, switch, and while statements, as well as the if ... then ... else form of the if statement, require that the major keywords appear in a single simple command on an input line as shown below.

If the shell's input is not seekable, the shell buffers up input whenever a loop is being read and performs seeks in this internal buffer to accomplish the rereading implied by the loop. (To the extent that this allows, backward gotos will succeed on non-seekable inputs.)

Jobs

The shell associates a job with each pipeline. It keeps a table of current jobs, printed by the jobs command, and assigns them small integer numbers. When a job is started asynchronously with ‘&’, the shell prints a line which looks like

[1] 1234

indicating that the job which was started asynchronously was job number 1 and had one (top-level) process, whose process id was 1234.

If you are running a job and wish to do something else you may hit the suspend key (usually ^Z), which sends a STOP signal to the current job. The shell will then normally indicate that the job has been

Suspended
and print another prompt. If the listjobs shell variable is set, all jobs will be listed like the jobs builtin command; if it is set to ‘long’ the listing will be in long format, like ‘jobs -l’. You can then manipulate the state of the suspended job. You can put it in the “background” with the bg command or run some other commands and eventually bring the job back into the “foreground” with fg. (See also the run-fg-editor editor command.) A ^Z takes effect immediately and is like an interrupt in that pending output and unread input are discarded when it is typed. The wait builtin command causes the shell to wait for all background jobs to complete.

The ^] key sends a delayed suspend signal, which does not generate a STOP signal until a program attempts to read(2) it, to the current job. This can usefully be typed ahead when you have prepared some commands for a job which you wish to stop after it has read them. The ^Y key performs this function in csh(1); in tcsh, ^Y is an editing command. (+)

A job being run in the background stops if it tries to read from the terminal. Background jobs are normally allowed to produce output, but this can be disabled by giving the command

stty tostop
If you set this tty option, then background jobs will stop when they try to produce output like they do when they try to read input.

There are several ways to refer to jobs in the shell. The character ‘%’ introduces a job name. If you wish to refer to job number 1, you can name it as

%1
Just naming a job brings it to the foreground; thus
%1
is a synonym for
fg %1
bringing job 1 back into the foreground. Similarly, typing
%1 &
resumes job 1 in the background, just like
bg %1
A job can also be named by an unambiguous prefix of the string typed in to start it:
%ex
would normally restart a suspended ex(1) job, if there were only one suspended job whose name began with the string ‘ex’. It is also possible to type
%?string
to specify a job whose text contains string, if there is only one such job.

The shell maintains a notion of the current and previous jobs. In output pertaining to jobs, the current job is marked with a ‘+’ and the previous job with a ‘-’. The abbreviations ‘%+’, ‘%’, and (by analogy with the syntax of the history mechanism) ‘%%’ all refer to the current job, and ‘%-’ refers to the previous job.

Información de estado

El shell se entera inmediatamente cada vez que un proceso cambia de estado. Normalmente le informa cuando un trabajo se bloquea para que no sea posible un progreso adicional, pero solo justo antes de imprimir un prompt. Esto se hace para no interrumpir su trabajo. Si, sin embargo, establece la variable del shell notify, el shell le notificará inmediatamente sobre los cambios de estado en los trabajos en segundo plano. También hay un comando incorporado notify que marca un proceso individual para que sus cambios de estado se informen inmediatamente. Por defecto, notify marca el proceso actual; simplemente escriba

notify
después de iniciar un trabajo en segundo plano para marcarlo para la notificación inmediata de estado.

Cuando intente salir del shell mientras hay trabajos detenidos, se le advertirá que

Hay trabajos suspendidos.

Puede usar el comando jobs para ver cuáles son. Si lo hace o intenta salir inmediatamente de nuevo, el shell no le advertirá por segunda vez, y los trabajos suspendidos serán terminados.

Soporte del Sistema de Lenguaje Nativo (+)

El shell es "eight bit clean" (si se compiló así; consulte la variable del shell version) y por lo tanto soporta juegos de caracteres que requieren esta capacidad. El soporte de NLS difiere dependiendo de si el shell se compiló o no para usar el NLS del sistema (de nuevo, consulte version). En cualquier caso, ASCII de 7 bits es el código de caracteres predeterminado (por ejemplo, la clasificación de qué caracteres son imprimibles) y la ordenación, y el cambio de las variables de entorno LANG o LC_CTYPE provoca una comprobación de posibles cambios en estos aspectos.

Al usar el NLS del sistema, se llama a la función setlocale(3) para determinar el código/clasificación de caracteres y la ordenación apropiados (por ejemplo, 'en_CA.UTF-8' produciría 'UTF-8' como código de caracteres). Esta función típicamente examina las variables de entorno LANG y LC_CTYPE; consulte la documentación del sistema para más detalles. Cuando no se usa el NLS del sistema, el shell lo simula asumiendo que se usa el juego de caracteres ISO 8859-1 siempre que las variables LANG y LC_CTYPE estén establecidas, independientemente de sus valores. La ordenación no se ve afectada para el NLS simulado.

Además, tanto con NLS real como simulado, todos los caracteres imprimibles en el rango \200-\377, es decir, aquellos que tienen enlaces M-carácter, se vinculan automáticamente a self-insert-command. El enlace correspondiente para la secuencia escape-carácter, si existe, se deja intacto. Estos caracteres no se vuelven a enlazar si la variable de entorno NOREBIND está establecida. Esto puede ser útil para el NLS simulado o un NLS primitivo que asume ISO 8859-1 completo. De lo contrario, todos los enlaces M-carácter en el rango \240-\377 se deshacen efectivamente. Volver a enlazar explícitamente las teclas relevantes con bindkey es, por supuesto, todavía posible.

Los caracteres desconocidos (es decir, aquellos que no son ni imprimibles ni caracteres de control) se imprimen en el formato \nnn. Si el tty no está en modo de 8 bits, otros caracteres de 8 bits se imprimen convirtiéndolos a ASCII y utilizando el modo destacado. El shell nunca cambia el modo de 7/8 bits del tty y rastrea los cambios iniciados por el usuario en el modo de 7/8 bits. Los usuarios de NLS (o, de hecho, aquellos que quieren usar una tecla meta) pueden necesitar configurar explícitamente el tty en modo de 8 bits a través del comando stty(1) apropiado en, por ejemplo, el archivo ~/.login.

Manejo de señales

Los shells de inicio de sesión ignoran las interrupciones al leer el archivo ~/.logout. El shell ignora las señales de interrupción a menos que se inicie con -q. Los shells de inicio de sesión capturan la señal de terminación, pero los shells no de inicio de sesión heredan el comportamiento de terminación de sus padres. Otras señales tienen los valores que el shell heredó de su padre.

En scripts de shell, el manejo de señales de interrupción y terminación por parte del shell se puede controlar con onintr, y su manejo de cuelgues se puede controlar con hup y nohup.

El shell se cierra ante un cuelgue (consulte también la variable del shell logout). Por defecto, los hijos del shell también lo hacen, pero el shell no les envía un cuelgue cuando se cierra. hup hace que el shell envíe un cuelgue a un hijo cuando se cierra, y nohup configura un hijo para ignorar los cuelgues.

Manejo de terminal (+)

El shell utiliza tres conjuntos diferentes de modos de terminal ("tty"): 'edit', utilizado al editar; 'quote', utilizado al citar caracteres literales; y 'execute', utilizado al ejecutar comandos. El shell mantiene constantes algunas configuraciones en cada modo, por lo que los comandos que dejan el tty en un estado confuso no interfieren con el shell. El shell también coincide con los cambios en la velocidad y el relleno del tty. La lista de modos de tty que se mantienen

constante se puede examinar y modificar con la utilidad incorporada setty. Tenga en cuenta que, aunque el editor utiliza el modo CBREAK (o su equivalente), de todos modos toma los caracteres anticipados de escritura.

Los comandos echotc, settc y telltc se pueden usar para manipular y depurar las capacidades de la terminal desde la línea de comandos.

En sistemas que admiten SIGWINCH o SIGWINDOW, el shell se adapta automáticamente al cambio de tamaño de la ventana y ajusta las variables de entorno LINES y COLUMNS si están establecidas. Si la variable de entorno TERMCAP contiene los campos ‘li#’ y ‘co#’, el shell los ajusta para reflejar el nuevo tamaño de la ventana.

Ahora, algunos ejemplos. Algunos comandos solo toman directorios como argumentos, por lo que no tiene sentido completar archivos planos.

> complete cd 'p/1/d/'

completa solo la primera palabra después de ‘cd’ (‘p/1’) con un directorio. La completación de tipo ‘p’ también se puede usar para acotar la completación de comandos:

> co[^D]
complete compress
> complete -co* 'p/0/(compress)/'
> co[^D]
> compress

Esta completación completa comandos (palabras en la posición 0, ‘p/0’) que comienzan con ‘co’ (coincidiendo así con ‘co*’) a ‘compress’ (la única palabra en la lista). El guion inicial ‘-’ indica que esta completación se usará solo con comandos ambiguos.

> complete find 'n/-user/u/'

es un ejemplo de completación de tipo ‘n’. Cualquier palabra que siga a ‘find’ y que siga inmediatamente a ‘-user’ se completa de la lista de usuarios.

> complete cc 'c/-I/d/'

demuestra la completación de tipo ‘c’. Cualquier palabra que siga a ‘cc’ y que comience con ‘-I’ se completa como un directorio. ‘-I’ no se toma como parte del directorio porque usamos la ‘c’ minúscula.

Diferentes lists son útiles con diferentes comandos.

> complete alias 'p/1/a/'
> complete man 'p/*/c/'
> complete set 'p/1/s/'
> complete true 'p/1/x:Truth has no options./'

Estos completan palabras que siguen a ‘alias’ con alias, ‘man’ con comandos y ‘set’ con variables de shell. true no tiene opciones, por lo que ‘x’ no hace nada al intentar la completación e imprime

Truth has no options.
cuando se listan las opciones de completación.

Tenga en cuenta que el ejemplo de ‘man’, y varios otros ejemplos a continuación, podrían haber usado igualmente ‘'c/*'’ o ‘'n/*'’ como ‘'p/*'’.

Las palabras se pueden completar desde una variable evaluada en el momento de la completación,

> complete ftp 'p/1/$hostnames/'
> set hostnames = (rtfm.mit.edu tesla.ee.cornell.edu)
> ftp [^D]
rtfm.mit.edu tesla.ee.cornell.edu
> ftp [^C]
> set hostnames = (rtfm.mit.edu tesla.ee.cornell.edu uunet.uu.net)
> ftp [^D]
rtfm.mit.edu tesla.ee.cornell.edu uunet.uu.net

o desde un comando ejecutado en el momento de la completación:

> complete kill 'p/*/`ps | awk \{print\ \$1\}`/'
> kill -9 [^D]
23113 23377 23380 23406 23429 23529 23530 PID

Tenga en cuenta que el comando complete no cita sus argumentos por sí mismo, por lo que las llaves, el espacio y el ‘$’ en ‘{print $1}’ deben citarse explícitamente.

Un comando puede tener múltiples completaciones:

> complete dbx 'p/2/(core)/' 'p/*/c/'

completa el segundo argumento para ‘dbx’ con la palabra ‘core’ y todos los demás argumentos con comandos. Tenga en cuenta que la completación posicional se especifica antes de la completación de la siguiente palabra. Debido a que las completaciones se evalúan de izquierda a derecha, si la completación de la siguiente palabra se especificara primero, coincidiría siempre y la completación posicional nunca se ejecutaría. Este es un error común al definir una completación.

El patrón select es útil cuando un comando toma archivos con solo formas particulares como argumentos. Por ejemplo,

> complete cc 'p/*/f:*.[cao]/'

completa los argumentos de ‘cc’ a archivos que terminan solo en ‘.c’, ‘.a’, o ‘.o’. select también puede excluir archivos, usando la negación de un patrón de globbing como se describe en Sustitución de nombres de archivo. Uno podría usar

> complete rm 'p/*/f:^*.{c,h,cc,C,tex,1,man,l,y}/'

para excluir código fuente precioso de la completación de ‘rm’. Por supuesto, todavía se podrían escribir nombres excluidos manualmente o anular el mecanismo de completación usando los comandos del editor complete-word-raw o list-choices-raw.

Las listas ‘C’, ‘D’, ‘F’, y ‘T’ son como ‘c’, ‘d’, ‘f’, y ‘t’ respectivamente, pero usan el argumento select de una manera diferente: para restringir la completación a archivos que comienzan con un prefijo de ruta particular. Por ejemplo, el programa de correo Elm usa ‘=’ como abreviatura del directorio de correo de uno. Uno podría usar

> complete elm c@=@F:$HOME/Mail/@

para completar

elm -f =
como si fuera
elm -f ~/Mail/
Tenga en cuenta que usamos el separador ‘@’ en lugar de ‘/’ para evitar confusiones con el argumento select, y usamos ‘$HOME’ en lugar de ‘~’ porque la sustitución del directorio de inicio solo funciona al principio de una palabra.

suffix se utiliza para añadir un sufijo no estándar (no espacio o ‘/’ para directorios) a las palabras completadas.

> complete finger 'c/*@/$hostnames/' 'p/1/u/@'

completa los argumentos de ‘finger’ de la lista de usuarios, añade un ‘@’, y luego completa después del ‘@’ de la variable ‘hostnames’. Tenga en cuenta de nuevo el orden en que se especifican las completaciones.

Tenga en cuenta que poner un cd, pushd o popd en cwdcmd puede causar un bucle infinito. Es opinión del autor que cualquiera que lo haga obtendrá lo que merece.

Se ejecuta antes de que cada comando sea ejecutado, o cuando el comando cambia de estado. Esto es similar a postcmd, pero no imprime comandos incorporados.

Se invoca mediante el comando del editor run-help. El nombre del comando para el cual se busca ayuda se pasa como argumento único. Por ejemplo, si se hace

entonces se invocará la visualización de ayuda del propio comando, utilizando la convención de llamada de ayuda de GNU.

Actualmente no hay una forma fácil de tener en cuenta varias convenciones de llamada (por ejemplo, el habitual ‘-h’ de Unix), excepto utilizando una tabla de muchos comandos.

Se ejecuta cada tperiod minutos. Esto proporciona un medio conveniente para verificar cambios comunes pero infrecuentes, como correo nuevo. Por ejemplo, si se hace

entonces el programa checknews(1) se ejecuta cada 30 minutos.

Si periodic está establecido pero tperiod no está establecido o está establecido en 0, periodic se comporta como precmd.

precmd
Se ejecuta justo antes de que se imprima cada prompt. Por ejemplo, si se hace 
> alias precmd date

entonces date(1) se ejecuta justo antes de que el shell solicite cada comando.

No hay límites en lo que precmd puede ser configurado para hacer, pero se debe usar discreción.

pondrá la cadena de comando en la barra de título de xterm.

Variables especiales del shell

Las variables descritas en esta sección tienen un significado especial para el shell.

El shell establece addsuffix, argv, autologout, csubstnonl, command, echo_style, edit, gid, group, home, loginsh, oid, path, prompt, prompt2, prompt3, shell, shlvl, tcsh, term, tty, uid, user y version al inicio; no cambian después a menos que sean cambiadas por el usuario. El shell actualiza cwd, dirstack, owd y status cuando es necesario, y establece logout al cerrar sesión.

El shell sincroniza group, home, path, shlvl, term y user con las variables de entorno del mismo nombre: siempre que la variable de entorno cambie, el shell cambia la variable correspondiente del shell para que coincida (a menos que la variable del shell sea de solo lectura) y viceversa. Tenga en cuenta que, aunque cwd y PWD tienen significados idénticos, no se sincronizan de esta manera, y que el shell automáticamente convierte entre los diferentes formatos de path y PATH.

Puede establecerse a varios valores diferentes para controlar la resolución de enlaces simbólicos (‘symlink’):

Si se establece a ‘chase’, siempre que el directorio actual cambie a un directorio que contenga un enlace simbólico, este se expandirá al nombre real del directorio al que apunta el enlace. Esto no funciona para el directorio de inicio del usuario; esto es un error.

> ln -s from/src to/dst

> cd ..; echo $cwd
/tmp/from

Aquí está el comportamiento con symlinks establecido en ‘chase’,

> cd /tmp/to/dst; echo $cwd
/tmp/from/src
> cd ..; echo $cwd
/tmp/from

Aquí está el comportamiento con symlinks establecido en ‘ignore’,

> cd /tmp/to/dst; echo $cwd
/tmp/to/dst
> cd ..; echo $cwd
/tmp/to

Aquí está el comportamiento con symlinks establecido en ‘expand’.

> cd /tmp/to/dst; echo $cwd
/tmp/to/dst
> cd ..; echo $cwd
/tmp/to
> cd /tmp/to/dst; echo $cwd
/tmp/to/dst
> cd ".."; echo $cwd
/tmp/from
> /bin/echo ..
/tmp/to
> /bin/echo ".."
..

Tenga en cuenta que la expansión de ‘expand’:

  1. Funciona igual que ‘ignore’ para comandos integrados como cd.
  2. Se previene mediante comillas.
  3. Ocurre antes de que los nombres de archivo se pasen a comandos no integrados.

Solo necesita incluir las variables que desea cambiar respecto a los valores predeterminados.

La segunda forma "*ext=valor" colorea los nombres de archivo basándose en la extensión. Por ejemplo, usando códigos ISO 6429, para colorear todos los archivos fuente del lenguaje C en azul, especificaría "*.c=34". Esto colorearía en azul (primer plano 34) todos los archivos que terminan en ‘.c’.

Los caracteres de control se pueden escribir tanto en notación de escape estilo C, como en notación ^ estilo stty. La notación estilo C añade ‘^[’ para Escape, ‘_’ para un carácter de espacio normal, y ‘?’ para Delete. Además, el carácter de escape ‘^[’ puede usarse para anular la interpretación predeterminada de ‘^[’, ‘^’, ‘:’ y ‘=’.

Cada nombre de archivo se mostrará en la terminal como

lc código-de-color rc nombre-de-archivo ec

Si el código ‘ec’ está indefinido, se usará en su lugar la secuencia

lc no rc
En general, esto es más conveniente de usar, pero menos general.

Los códigos izquierdo (‘lc’), derecho (‘rc’) y final (‘ec’) se proporcionan para que no tenga que escribir partes comunes una y otra vez y para soportar terminales extraños; por lo general, no necesitará cambiarlos en absoluto a menos que su terminal no use códigos de color ISO 6429 sino un sistema diferente.

Si su terminal utiliza códigos de color ISO 6429, puede componer los códigos de tipo (es decir, todos excepto los códigos ‘lc’, ‘rc’ y ‘ec’) a partir de códigos numéricos de color ISO 6429 separados por ‘;’. Por ejemplo, ‘01;32’ es color verde brillante de primer plano con fondo predeterminado.

HISTORIA

La shell de C se remonta a las versiones de Berkeley de UNIX. Las primeras versiones incluían muchas de las funciones que se encuentran en las shells de comando de otros sistemas, como las de DEC. En particular, TENEX y TOPS-20 tenían una forma de completar el nombre de archivo que se inició al presionar la tecla ESC.

La shell de C de Berkeley, por otro lado, requería la expansión de nombres de archivo con el comodín ‘*’. La shell TENEX y TOPS-20 tenían un mecanismo de entrada de usuario muy flexible. Si el usuario ingresaba una parte de un nombre de archivo, la shell completaría el resto del nombre. Si había varios nombres de archivo posibles, la shell emitiría un pitido. Con el tiempo, esta característica fue ampliada por los usuarios para incluir la completación de nombres de comando y otros identificadores.

DEC, en sus primeros sistemas, proporcionó tanto shells de comando interactivas como capacidades de entrada de usuario extensibles. El sistema operativo TENEX en particular, desarrollado originalmente por Bolt, Beranek and Newman (BBN) para ARPA, implementó muchas de las características que ahora se dan por sentadas en las shells modernas. En particular, TENEX tenía un método de entrada de usuario muy avanzado. Los comandos se ingresaban en la línea de comandos y la shell intentaba interpretarlos. Si el comando era reconocido, se ejecutaba. Si no, la shell buscaba en el entorno del usuario y en las rutas del sistema para ver si podía encontrar una coincidencia. Si había una coincidencia parcial, la shell ofrecía completarla. Esto era particularmente útil para los usuarios que tenían nombres de archivo largos o comandos complicados que recordar. La shell TENEX también admitía la expansión de nombres de archivo, lo que permitía a los usuarios ingresar partes de nombres de archivo y dejar que la shell los completara. La shell también tenía un mecanismo de sustitución de alias, que permitía a los usuarios definir abreviaturas para comandos largos. Por ejemplo, un usuario podría definir un alias para `ls -l` que sería simplemente `ll`. Esto ahorraba tiempo y esfuerzo al escribir comandos frecuentemente utilizados. DEC, sin embargo, mantuvo sistemas incompatibles y, por lo tanto, se encontró apoyando dos sistemas incompatibles en el mismo hardware, ¡pero luego había 6 en el PDP-11!

TENEX, y TOPS-20 hasta la versión 3, tenían completado de comandos a través de una biblioteca de subrutinas a nivel de código de usuario llamada ULTCMD. Con la versión 3, DEC trasladó toda esa capacidad y más al monitor (`kernel' para ustedes, los de Unix), al que se accede mediante el JSYS COMND% (`Jump to SYStem' instruction, el mecanismo de llamada al supervisor [¿mis raíces de IBM también se muestran?]).

El creador de tcsh quedó impresionado por esta característica y varias otras de TENEX y TOPS-20, y creó una versión de csh que las imitaba.

LIMITACIONES

El sistema limita las listas de argumentos a ARG_MAX caracteres.

El número de argumentos para un comando que involucra expansión de nombres de archivo está limitado a 1/6 del número de caracteres permitidos en una lista de argumentos.

Las sustituciones de comandos no pueden sustituir más caracteres de los permitidos en una lista de argumentos.

Para detectar bucles, la shell restringe el número de sustituciones de alias en una sola línea a 20.

ERRORES

Cuando un comando suspendido se reinicia, el shell imprime el directorio en el que se inició si este es diferente del directorio actual. Esto puede ser engañoso (es decir, incorrecto) ya que el trabajo puede haber cambiado de directorio internamente.

Las funciones incorporadas del shell no se pueden detener/reiniciar. Las secuencias de comandos de la forma

a ; b ; c
tampoco se manejan elegantemente al intentar detenerlas. Si suspendes ‘b’, el shell ejecutará inmediatamente ‘c’. Esto es especialmente notable si esta expansión resulta de un alias. Basta con colocar la secuencia de comandos entre ‘()’ para forzarla a una subshell, es decir:

( a ; b ; c )

El control de la salida del tty después de que se inician los procesos es primitivo; quizás esto inspire a alguien a trabajar en una buena interfaz de terminal virtual. En una interfaz de terminal virtual se podrían hacer cosas mucho más interesantes con el control de la salida.

La sustitución de alias se utiliza la mayoría de las veces para simular torpemente procedimientos de shell; se deberían proporcionar procedimientos de shell en lugar de alias.

Las estructuras de control deberían ser analizadas en lugar de ser reconocidas como comandos incorporados. Esto permitiría colocar los comandos de control en cualquier lugar, combinarlos con ‘|’, y usarlos con la metat sintaxis de ‘&’ y ‘;’.

foreach no ignora los here documents al buscar su end.

Debería ser posible usar los modificadores ‘:’ en la salida de sustituciones de comandos.

La actualización de la pantalla para líneas más largas que el ancho de la pantalla es muy deficiente si el terminal no puede mover el cursor hacia arriba (es decir, tipo de terminal ‘dumb’).

HPATH y NOREBIND no necesitan ser variables de entorno.

Los patrones de globbing que no utilizan ‘?’, ‘*’, o ‘[]’, o que utilizan ‘{}’ o ‘~’ no se niegan correctamente.

La forma de comando único de if realiza la redirección de salida incluso si la expresión es falsa y el comando no se ejecuta.

ls-F incluye caracteres de identificación de archivo al ordenar nombres de archivo y no maneja bien los caracteres de control en los nombres de archivo. No se puede interrumpir.

La sustitución de comandos soporta múltiples comandos y condiciones, pero no ciclos ni gotos hacia atrás.
