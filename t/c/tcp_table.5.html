NOMBRE

tcp_table - Protocolo de búsqueda de tabla de cliente/servidor Postfix

SINOPSIS

postmap -q "cadena" tcp:host:puerto
postmap -q - tcp:host:puerto <archivoentrada

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas opcionales para la reescritura de direcciones o el enrutamiento de correo. Estas tablas suelen estar en formato dbm o db. Alternativamente, las búsquedas de tablas pueden dirigirse a un servidor TCP.

Para averiguar qué tipos de tablas de búsqueda admite su sistema Postfix, utilice el comando "postconf -m".

Para probar las tablas de búsqueda, utilice el comando "postmap -q" como se describe en la SINOPSIS anterior.

DESCRIPCIÓN DEL PROTOCOLO

La clase de mapa TCP implementa un protocolo muy simple: el cliente envía una solicitud y el servidor envía una respuesta. Las solicitudes y respuestas se envían como una línea de texto ASCII, terminada por el carácter de nueva línea ASCII. Los parámetros de solicitud y respuesta (ver más abajo) están separados por espacios en blanco.

Las operaciones de envío y recepción deben completarse en 100 segundos.

FORMATO DE SOLICITUD

El protocolo tcp_table solo admite la solicitud de búsqueda. La solicitud tiene el siguiente formato:

get ESPACIO clave NUEVALINEA
Busca datos bajo la clave especificada.

Postfix no generará claves de búsqueda parciales como nombres de dominio sin uno o más subdominios, direcciones de red sin uno o más octetos menos significativos, o direcciones de correo electrónico sin la parte local, extensión de dirección o porción de dominio. Este comportamiento también se encuentra con las tablas cidr:, pcre: y regexp:.

FORMATO DE RESPUESTA

Cada respuesta especifica un código de estado y texto. Las respuestas no deben tener más de 4096 caracteres, incluido el terminador de nueva línea.

500 ESPACIO texto NUEVALINEA
En caso de una solicitud de búsqueda, los datos solicitados no existen. El texto describe la naturaleza del problema.
400 ESPACIO texto NUEVALINEA
Esto indica una condición de error. El texto describe la naturaleza del problema. El cliente debe reintentar la solicitud más tarde.
200 ESPACIO texto NUEVALINEA
La solicitud fue exitosa. En el caso de una solicitud de búsqueda, el texto contiene una versión codificada de los datos solicitados.

CODIFICACIÓN

En los parámetros de solicitud y respuesta, el carácter %, cada carácter no imprimible y cada carácter de espacio en blanco deben ser reemplazados por %XX, donde XX es el valor hexadecimal del carácter ASCII correspondiente. Los códigos hexadecimales se pueden especificar en cualquier caso (mayúsculas, minúsculas, mixto).

El cliente Postfix siempre codifica una solicitud. El servidor puede omitir la codificación siempre que se garantice que la respuesta no contiene el carácter % ni NUEVALINEA.

SEGURIDAD

No utilice tablas de búsqueda TCP para fines de seguridad críticos. La conexión cliente-servidor no está protegida y el servidor no está autenticado.

ERRORES


Actualmente solo se implementa el método de búsqueda.

El cliente no se desconecta cuando la conexión está inactiva durante mucho tiempo.
