DESCRIPCIÓN

Tc se utiliza para configurar el Control de Tráfico en el kernel de Linux. El Control de Tráfico consta de lo siguiente:

SHAPING (Modelado)
Cuando el tráfico se modela, su tasa de transmisión está bajo control. El modelado puede ser más que reducir el ancho de banda disponible; también se utiliza para suavizar ráfagas de tráfico para un mejor comportamiento de la red. El modelado ocurre en la salida (egress).
SCHEDULING (Programación)
Al programar la transmisión de paquetes, es posible mejorar la interactividad del tráfico que la necesita, garantizando al mismo tiempo el ancho de banda para las transferencias masivas. La reordenación también se llama priorización y ocurre solo en la salida (egress).
POLICING (Control)
Mientras que el modelado se ocupa de la transmisión del tráfico, el control se refiere al tráfico entrante. Por lo tanto, el control ocurre en la entrada (ingress).
DROPPING (Descarte)
El tráfico que excede un ancho de banda establecido también puede ser descartado de inmediato, tanto en la entrada (ingress) como en la salida (egress).

El procesamiento del tráfico está controlado por tres tipos de objetos: qdiscs, clases y filtros.

QDISCS

qdisc es la abreviatura de 'queueing discipline' (disciplina de cola) y es fundamental para entender el control de tráfico. Siempre que el kernel necesita enviar un paquete a una interfaz, se **pone en cola** en el qdisc configurado para esa interfaz. Inmediatamente después, el kernel intenta obtener tantos paquetes como sea posible del qdisc, para dárselos al controlador del adaptador de red.

Un qdisc simple es el 'pfifo', que no realiza ningún procesamiento y es una cola pura de Primero en Entrar, Primero en Salir (FIFO). Sin embargo, almacena tráfico cuando la interfaz de red no puede manejarlo momentáneamente.

CLASES

Algunos qdiscs pueden contener clases, que a su vez contienen más qdiscs; el tráfico puede entonces ponerse en cola en cualquiera de los qdiscs internos, que están dentro de las **clases**. Cuando el kernel intenta desencolar un paquete de un qdisc con clases de este tipo, puede provenir de cualquiera de las clases. Un qdisc puede, por ejemplo, priorizar ciertos tipos de tráfico intentando desencolar de ciertas clases antes que de otras.

FILTROS

Un filtro es utilizado por un qdisc con clases para determinar en qué clase se pondrá en cola un paquete. Siempre que llega tráfico a una clase con subclases, necesita ser clasificado. Se pueden emplear varios métodos para hacerlo, uno de ellos son los filtros. Se llaman a todos los filtros adjuntos a la clase, hasta que uno de ellos retorna con un veredicto. Si no se tomó ninguna decisión, pueden estar disponibles otros criterios. Esto difiere según el qdisc.

Es importante notar que los filtros residen **dentro** de los qdiscs; no son los dueños de lo que sucede.

Los filtros disponibles son:

basic
Filtra paquetes basándose en una expresión ematch. Ver tc-ematch(8) para más detalles.
bpf
Filtra paquetes usando (e)BPF, ver tc-bpf(8) para más detalles.
cgroup
Filtra paquetes basándose en el grupo de control de su proceso. Ver tc-cgroup(8) para más detalles.
flow, flower
Clasificadores basados en flujo, filtrando paquetes basándose en su flujo (identificado por claves seleccionables). Ver tc-flow(8) y tc-flower(8) para más detalles.
fw
Filtra basándose en fwmark. Mapea directamente el valor de fwmark a la clase de tráfico. Ver tc-fw(8).
route
Filtra paquetes basándose en la tabla de enrutamiento. Ver tc-route(8) para más detalles.
u32
Filtrado genérico sobre datos de paquetes arbitrarios, asistido por sintaxis para abstraer operaciones comunes. Ver tc-u32(8) para más detalles.
matchall
Filtro de control de tráfico que coincide con todos los paquetes. Ver tc-matchall(8) para más detalles.

QEVENTS

Los qdiscs pueden invocar acciones configuradas por el usuario cuando ocurren ciertos eventos interesantes en el qdisc. Cada qevent puede no ser utilizado, o puede tener un bloque adjunto a él. A este bloque se adjuntan filtros usando la sintaxis "tc block BLOCK_IDX". El bloque se ejecuta cuando ocurre el qevent asociado al punto de adjunción. Por ejemplo, un paquete podría ser descartado o retrasado, etc., dependiendo del qdisc y del qevent en cuestión.

Por ejemplo:

tc qdisc add dev eth0 root handle 1: red limit 500K avpkt 1K \
qevent early_drop block 10
tc filter add block 10 matchall action mirred egress mirror dev eth1

COMANDOS TC

Los siguientes comandos están disponibles para qdiscs, clases y filtros:

add
Añade una qdisc, clase o filtro a un nodo. Para todas las entidades, se debe pasar un parent, ya sea pasando su ID o adjuntándolo directamente a la raíz de un dispositivo. Al crear una qdisc o un filtro, se puede nombrar con el parámetro handle. Una clase se nombra con el parámetro classid.
delete
Se puede eliminar una qdisc especificando su handle, que también puede ser 'root'. Todas las subclases y sus qdiscs hojas se eliminan automáticamente, así como cualquier filtro adjunto a ellas.
change
Algunas entidades se pueden modificar 'en el lugar'. Comparte la sintaxis de 'add', con la excepción de que el handle no se puede cambiar ni el padre. En otras palabras, change no puede mover un nodo.
replace
Realiza una eliminación/adición casi atómica en un ID de nodo existente. Si el nodo aún no existe, se crea.
get
Muestra un único filtro dada la interfaz DEV, qdisc-id, priority, protocol e filter-id.
show
Muestra todos los filtros adjuntos a la interfaz dada. Se debe pasar un ID de padre válido.
link
Solo disponible para qdiscs y realiza un reemplazo donde el nodo debe existir ya.

MONITOR

La utilidad tc puede monitorizar eventos generados por el kernel, como la adición/eliminación de qdiscs, filtros o acciones, o la modificación de las existentes.

El siguiente comando está disponible para monitor:

file
Si se proporciona la opción de archivo, tc no escucha los eventos del kernel, sino que abre el archivo dado y vuelca su contenido. El archivo debe estar en formato binario y contener mensajes netlink.

no termina tc en caso de errores en modo batch. Si hubo errores durante la ejecución de los comandos, el código de retorno de la aplicación será distinto de cero.

Cuando tc monitor se ejecuta, muestra una marca de tiempo corta antes del mensaje del evento en formato:

-echo
Solicita al kernel que envíe la configuración aplicada de vuelta.

tc(8) — tc

NAME

tc — Traffic Control command utility

SYNOPSIS

tc [ OPTIONS ] OBJECT { COMMAND | help }

OBJECT := { qdisc | class | filter | monitor }

OPTIONS := { -s[tats] | -d[etails] | -r[aw] | -i[nfo] | -n[etns]

DESCRIPTION

The tc utility is used to configure network traffic control primitives in the Linux kernel. These primitives allow fine-grained control over the transmission of datagrams from network interfaces.

Traffic control is based on the concept of a tree structure, where the root node represents the network interface. From this root, queuing disciplines (qdiscs) can be attached to shape the traffic. Qdiscs can have child qdiscs or traffic classes attached, allowing for hierarchical control. Filters are used to classify packets and direct them to appropriate qdiscs or actions.

The main objects managed by tc are:

qdisc
Queuing disciplines. These are responsible for scheduling packets for transmission. Examples include FIFO, SFQ, TBF, HFSC, HTB.
class
Traffic classes. Used within classful qdiscs to represent different classes of traffic with distinct service levels.
filter
Packet classifiers. Used to classify incoming packets and direct them to specific qdiscs or actions based on criteria like IP address, port number, or protocol.
monitor
A special mode to dump traffic control events from the kernel.

QDISCS

A queuing discipline (qdisc) is an algorithm that dequeues packets for transmission. Linux traffic control supports two types of qdiscs: classless and classful.

CLASSES

Classes are used to shape traffic within classful qdiscs. They allow for different treatment of different traffic flows.

FILTERS

Filters are used to classify packets and decide their fate. They can direct packets to specific qdiscs, classes, or trigger actions.

QEVENTS

Queuing events are notifications from the kernel about traffic control state changes.

CLASSLESS QDISCS

Classless qdiscs are simple queuing disciplines that do not require traffic classes. They are typically attached directly to the root of the interface.

Common classless qdiscs include:

bfifo
A simple byte-limited FIFO queue.
pfifo
A simple packet-limited FIFO queue.
pfifo_fast
A FIFO qdisc with three configurable bands, intended for general-purpose use.
fq
Fair-queueing qdisc.
fq_codel
Fair-queueing with CoDel AQM.
red
Random Early Detection.
codel
Controlled Delay AQM.
tbf
Token Bucket Filter.
sfq
Stochastic Fairness Queuing.

CONFIGURING CLASSLESS QDISCS

The basic command to add a classless qdisc is:

tc qdisc add dev <device> [ parent <qdisc_id> | root ] [ { line | handle <id> ] [ qdisc_type [ options ] ]

For example, to add a FIFO qdisc to the root of the eth0 interface:

tc qdisc add dev eth0 root pfifo_fast

CLASSFUL QDISCS

Classful qdiscs allow for the creation of traffic classes, enabling more sophisticated bandwidth management and prioritization.

Common classful qdiscs include:

htb
Hierarchical Token Bucket.
hfsc
Hierarchical Fair Service Curve.
prio
Priority qdisc (uses bands).
multiqueue
Multiqueue qdisc (uses bands).
ets
Enhanced Transmission Selection.
choke
Classful H-RED.
cgroup
Control Group qdisc.

THEORY OF OPERATION

The tc utility interacts with the traffic control layer in the Linux kernel. This layer provides primitives for:

Shaping: Smoothing out traffic bursts by delaying packets.

Scheduling: Determining the order in which packets are transmitted.

Policing: Enforcing traffic rate limits and dropping excess packets.

Classification: Categorizing packets based on various criteria.

These primitives are organized hierarchically, starting from the network interface (root qdisc) and extending downwards through classes and filters.

NAMING

In tc, qdiscs, classes and filters can be given human-readable names for easier management. These names are typically presented as key-value pairs.

name
Assigns a name to an object.

Example:

tc class add ... classid 1:1 htb rate 10mbit name myclass

PARAMETERS

The tc utility accepts various parameters to configure the behavior of qdiscs, classes, and filters. These parameters are qdisc-specific and include options like:

rate
Specifies the bandwidth limit.
ceil
Specifies the ceiling bandwidth.
buffer
Specifies the buffer size.
limit
Specifies the maximum queue size.
priority
Specifies the priority level.

TC COMMANDS

The primary commands for each object type are:

add
Adds a new qdisc, class, or filter.
delete
Deletes a qdisc, class, or filter.
show
Displays existing qdiscs, classes, or filters.
change
Modifies an existing qdisc, class, or filter.
replace
Replaces an existing qdisc, class, or filter.

MONITOR

The tc monitor command allows you to observe traffic control events generated by the kernel in real-time.

OPTIONS

-s, --stats
Display statistics for qdiscs, classes, and filters.
-d, --details
Display detailed information.
-r, --raw
Display raw values.
-i, --info
Display general information.
-n, --netns
Operate in a specified network namespace.
tc will not fail if -nm was specified without -cf option but /etc/iproute2/tc_cls file does not exist, which makes it possible to pass -nm option for creating tc alias.
-br, -brief
Print only essential data needed to identify the filter and action (handle, cookie, etc.) and stats. This option is currently only supported by tc filter show and tc actions ls commands.

EXAMPLES

tc -g class show dev eth0

Shows classes as ASCII graph on eth0 interface.

tc -g -s class show dev eth0

Shows classes as ASCII graph with stats info under each class.
