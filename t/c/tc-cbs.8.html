NOMBRE

CBS - Qdisc Credit Based Shaper (CBS)

SINOPSIS

tc qdisc ... dev dev parent classid [ handle major: ] cbs idleslope idleslope sendslope sendslope hicredit hicredit locredit locredit [ offload 0|1 ]

DESCRIPCIÓN

El qdisc CBS (Credit Based Shaper) implementa el algoritmo de modelado definido por la Sección 8.6.8.2 de IEEE 802.1Q-2014, que aplica un método bien definido de limitación de tasa al tráfico.

Esta disciplina de cola está pensada para ser utilizada por aplicaciones TSN (Time Sensitive Networking), los parámetros de CBS se derivan directamente de lo descrito en el Anexo L de la Especificación IEEE 802.1Q-2014. El algoritmo y cómo afecta la latencia se detallan allí.

CBS está destinado a ser instalado bajo otro qdisc que mapea los flujos de paquetes a clases de tráfico, un ejemplo es mqprio(8).

PARÁMETROS

idleslope
Idleslope es la tasa de créditos que se acumula (en kilobits por segundo) cuando hay al menos un paquete esperando transmisión. Los paquetes se transmiten cuando el valor actual de los créditos es igual o superior a cero. Cuando no hay paquetes para transmitir, la cantidad de créditos se establece en cero. Este es el ajuste principal del algoritmo CBS y representa el ancho de banda que se consumirá. Tenga en cuenta que al calcular el idleslope, se debe considerar el tamaño completo del paquete, incluidos los encabezados de todas las capas (es decir, el marco MAC y cualquier sobrecarga de la capa física), como se describe en la sección 34.4 de IEEE 802.1Q-2014.

Como ejemplo, para un marco de Ethernet que transporta 284 bytes de carga útil, y sin etiquetas VLAN, debe agregar 14 bytes para los encabezados de Ethernet, 4 bytes para la secuencia de verificación de trama (CRC) y 20 bytes para la sobrecarga L1: 12 bytes de interpacket gap, 7 bytes de preámbulo y 1 byte de delimitador de inicio de trama. Esto resulta en 322 bytes para el tamaño total del paquete, que luego se utiliza para calcular el idleslope.

sendslope
Sendslope es la tasa de créditos que se agota (debería ser un número negativo de kilobits por segundo) cuando ocurre una transmisión. Se puede calcular de la siguiente manera (Sección 8.6.8.2, elemento g) de IEEE 802.1Q-2014):

sendslope = idleslope - port_transmit_rate

hicredit
Hicredit define la cantidad máxima de créditos (en bytes) que se pueden acumular. Hicredit depende de las características del tráfico que interfiere, 'max_interference_size' es el tamaño máximo de cualquier ráfaga de tráfico que pueda retrasar la transmisión de un marco disponible para transmisión para esta clase de tráfico (Anexo L de IEEE 802.1Q-2014, Ecuación L-3):

hicredit = max_interference_size * (idleslope / port_transmit_rate)

locredit
Locredit es la cantidad mínima de créditos que se puede alcanzar. Es una función del tráfico que fluye a través de este qdisc (Anexo L de IEEE 802.1Q-2014, Ecuación L-2):

locredit = max_frame_size * (sendslope / port_transmit_rate)

offload
Cuando offload es 1, cbs(8) intentará configurar la interfaz de red para que el algoritmo CBS se ejecute en el controlador. El valor predeterminado es 0.

EJEMPLOS

CBS se utiliza para imponer Calidad de Servicio limitando la tasa de datos de una clase de tráfico; para separar los paquetes en clases de tráfico, el usuario puede elegir mqprio(8) y configurarlo de la siguiente manera:

# tc qdisc add dev eth0 handle 100: parent root mqprio num_tc 3 \
	map 2 2 1 0 2 2 2 2 2 2 2 2 2 2 2 2 \
	queues 1@0 1@1 2@2 \
	hw 0

Para reemplazar la disciplina de cola actual por CBS en la disciplina de cola actual conectada a la clase de tráfico número 0, emita:

# tc qdisc replace dev eth0 parent 100:4 cbs \
	locredit -1470 hicredit 30 sendslope -980000 idleslope 20000

Estos valores se obtienen de los siguientes parámetros: idleslope es 20Mbit/s, la tasa de transmisión es 1Gbit/s y el tamaño máximo del marco que interfiere es de 1500 bytes.
