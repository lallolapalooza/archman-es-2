Acción de manipulación de VLAN en tc(8) Linux Acción de manipulación de VLAN en tc(8)

NOMBRE

vlan - módulo de manipulación de vlan

SINOPSIS


tc ... action vlan { pop | pop_eth | PUSH | MODIFY | PUSH_ETH } [ CONTROL ]

PUSH := push [ protocol VLANPROTO ] [ priority VLANPRIO ] id VLANID

MODIFY := modify [ protocol VLANPROTO ] [ priority VLANPRIO ] id VLANID

PUSH_ETH := push_eth dst_mac LLADDR src_mac LLADDR

CONTROL := { reclassify | pipe | drop | continue | pass | goto chain CHAIN_INDEX }

DESCRIPCIÓN

La acción vlan permite realizar la encapsulación o desencapsulación 802.1Q en un paquete, reflejado por los modos de operación POP, PUSH y MODIFY. El modo POP es simple, ya que no se requiere información adicional para simplemente descartar la encapsulación VLAN más externa. Los modos PUSH y MODIFY requieren al menos un VLANID y permiten elegir opcionalmente el VLANPROTO a utilizar.

La acción vlan también se puede usar para agregar o eliminar la cabecera Ethernet base. El modo pop_eth, que no toma argumentos, se utiliza para eliminar la cabecera Ethernet base. Todas las VLAN existentes deben haber sido previamente eliminadas. La operación opuesta, agregar una cabecera Ethernet base, se realiza con el modo push_eth. En ese caso, el paquete no debe tener cabecera MAC (no se permite apilar cabeceras MAC). Este modo es útil principalmente cuando una acción anterior ha encapsulado el marco original completo detrás de una cabecera de red y es necesario anteponer una cabecera Ethernet antes de reenviar el paquete resultante.

OPCIONES

pop
Modo de desencapsulación, no se permiten argumentos adicionales.
push
Modo de encapsulación. Requiere al menos la opción id.
modify
Modo de reemplazo. La etiqueta 802.1Q existente se reemplaza. Requiere al menos la opción id.
pop_eth
Modo de desencapsulación de cabecera Ethernet. Solo funciona en una cabecera Ethernet simple: las VLAN, si las hay, deben eliminarse primero.
push_eth
Modo de encapsulación de cabecera Ethernet. El Ethertype se establece automáticamente utilizando el tipo de cabecera de red. No se permite encadenar cabeceras Ethernet: el paquete no debe tener cabecera MAC al usar este modo. Requiere las opciones dst_mac y src_mac.
id VLANID
Especifica el ID de VLAN en el que encapsular. VLANID es un entero de 16 bits sin signo, el formato se detecta automáticamente (por ejemplo, prefijo con '0x' para interpretación hexadecimal, etc.).
protocol VLANPROTO
Elige el protocolo VLAN a usar. En el momento de escribir esto, el kernel acepta solo 802.1Q o 802.1ad.
priority VLANPRIO
Elige la prioridad VLAN a usar. Número decimal en el rango de 0 a 7.
dst_mac LLADDR
Elige la dirección MAC de destino a usar.
src_mac LLADDR
Elige la dirección MAC de origen a usar.
CONTROL
Cómo continuar después de ejecutar esta acción.
reclassify
Reinicia la clasificación saltando de nuevo al primer filtro adjunto al padre de esta acción.
pipe
Continúa con la siguiente acción, este es el valor predeterminado.
drop
El paquete será descartado sin ejecutar más acciones.
continue
Continúa la clasificación con el siguiente filtro en línea.
pass
Regresa a la qdisc que llama para el procesamiento del paquete. Esto finaliza el proceso de clasificación.

EJEMPLOS

El siguiente ejemplo encapsula los paquetes ICMP entrantes en eth0 desde 10.0.0.2 en el ID de VLAN 123:

#tc qdisc add dev eth0 handle ffff: ingress
#tc filter add dev eth0 parent ffff: pref 11 protocol ip \
	u32 match ip protocol 1 0xff flowid 1:1 \
	    match ip src 10.0.0.2 flowid 1:1 \
	action vlan push id 123

Aquí hay un ejemplo de la función pop: Los paquetes VLAN entrantes en eth0 se desencapsulan y el proceso de clasificación se reinicia para el paquete plano:

#tc qdisc add dev eth0 handle ffff: ingress
#tc filter add dev $ETH parent ffff: pref 1 protocol 802.1Q \
	u32 match u32 0 0 flowid 1:1 \
	action vlan pop reclassify

Para un ejemplo de los modos pop_eth y push_eth, consulte tc-mpls(8).
