NOMBRE

tcprewrite - Reescribe los paquetes en un archivo pcap.

SINOPSIS

tcprewrite [-banderas] [-bandera [valor]] [--nombre-opcion[[=| ]valor]]

Todos los argumentos deben ser opciones.

DESCRIPCIÓN

Tcprewrite es una herramienta para reescribir paquetes almacenados en formato de archivo pcap(3), como los creados por herramientas como tcpdump(1) y wireshark(1). Una vez que un archivo pcap ha tenido sus paquetes reescritos, pueden ser reproducidos en la red usando tcpreplay(1).

tcprewrite actualmente soporta la lectura de los siguientes tipos DLT:

DLT_C_HDLC alias Cisco HDLC

DLT_EN10MB alias Ethernet

DLT_LINUX_SLL alias Linux Cooked Socket

DLT_LINUX_SLL2 alias Linux Cooked Socket v2

DLT_RAW alias RAW IP

DLT_NULL alias BSD Loopback

DLT_LOOP alias OpenBSD Loopback

DLT_IEEE802_11 alias 802.11a/b/g

DLT_IEEE802_11_RADIO alias 802.11a/b/g con cabeceras Radiotap

DLT_JUNIPER_ETHER alias Ethernet Encapsulado de Juniper

DLT_PPP_SERIAL alias PPP sobre Serial

Por favor, consulte la opción --dlt para ver los tipos DLT soportados para escritura.

Las características de edición de paquetes de tcprewrite que distinguen entre tráfico de "cliente" y "servidor" requieren un archivo de caché de tcpprep(1).

Para más detalles, por favor consulte el Manual de Tcpreplay en: http://tcpreplay.appneta.com

OPCIONES

-r cadena, --portmap=cadena

Reescribe puertos TCP/UDP. Esta opción puede aparecer hasta 9999 veces.

Especifique una lista de mapeos de puertos separados por comas que consisten en pares de números de puerto separados por dos puntos. Cada par de puertos separados por dos puntos consiste en el puerto a coincidir seguido del número de puerto a reescribir.

Ejemplos:

    --portmap=80:8000 --portmap=8080:80    # 80->8000 y 8080->80
    --portmap=8000,8080,88888:80           # 3 puertos diferentes se convierten en 80
    --portmap=8000-8999:80                 # puertos 8000 a 8999 se convierten en 80
-s número, --seed=número

Aleatoriza direcciones IPv4/v6 de origen/destino con la semilla dada. Esta opción puede aparecer hasta 1 vez. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: fuzz-seed. Esta opción toma un número entero como argumento.

Causa que las direcciones IPv4/v6 de origen y destino se aleatoricen pseudo-aleatoriamente pero manteniendo las relaciones cliente/servidor. Dado que la aleatorización es determinista basada en la semilla, puede reutilizar el mismo valor de semilla para recrear el tráfico.

-N cadena, --pnat=cadena

Reescribe direcciones IPv4/v6 usando pseudo-NAT. Esta opción puede aparecer hasta 2 veces. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: srcipmap.

Toma una serie de pares de netblocks CIDR separados por comas y dos puntos. Cada par de netblocks se evalúa en orden contra las direcciones IP. Si la dirección IP en el paquete coincide con el primer netblock, se reescribe usando el segundo netblock como máscara contra los bits de orden superior.

Ejemplo IPv4:

    --pnat=192.168.0.0/16:10.77.0.0/16,172.16.0.0/12:10.1.0.0/24
Ejemplo IPv6: 
    --pnat=[2001:db8::/32]:[dead::/16],[2001:db8::/32]:[::ffff:0:0/96]
-S cadena, --srcipmap=cadena

Reescribe direcciones IP de origen IPv4/v6 usando pseudo-NAT. Esta opción puede aparecer hasta 1 vez. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: pnat.

Funciona igual que la opción --pnat, pero solo afecta a las direcciones IP de origen en la cabecera IPv4/v6.

-D cadena, --dstipmap=cadena

Reescribe direcciones IP de destino IPv4/v6 usando pseudo-NAT. Esta opción puede aparecer hasta 1 vez. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: pnat.

Funciona igual que la opción --pnat, pero solo afecta a las direcciones IP de destino en la cabecera IPv4/v6.

-e cadena, --endpoints=cadena

Reescribe direcciones IP para que estén entre dos puntos finales. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con la siguiente opción: cachefile.

Toma un par de direcciones IPv4/v6 separadas por dos puntos que se utilizarán para reescribir todo el tráfico para que parezca que está entre las dos direcciones IP.

Ejemplo IPv4:

    --endpoints=172.16.0.1:172.16.0.2
Ejemplo IPv6: 
    --endpoints=[2001:db8::dead:beef]:[::ffff:0:0:ac:f:0:2]
--tcp-sequence=número

Cambia los números de secuencia (y ACK) de TCP con la semilla dada. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
mayor o igual que 1

El valor predeterminado de número para esta opción es:
0

Cambia todos los números de secuencia TCP y los números de secuencia-acuse relacionados. Serán desplazados en una cantidad aleatoria basada en la semilla proporcionada.

-b, --skipbroadcast

Omitir la reescritura de direcciones IPv4/v6 de broadcast/multicast.

Por defecto, --seed, --pnat y --endpoints reescribirán las direcciones IPv4/v6 y MAC de broadcast y multicast. Establecer esta bandera evitará que las direcciones IPv4/v6 y MAC de broadcast/multicast sean reescritas.

-C, --fixcsum

Forzar el recálculo de sumas de comprobación de cabeceras IPv4/TCP/UDP.

Hace que cada paquete IPv4/v6 recalcule y corrija sus sumas de comprobación. Se habilita automáticamente para paquetes modificados con --seed, --pnat, --endpoints o --fixlen.

--fixhdrlen

Alterar la longitud de la cabecera IP/TCP para que coincida con la longitud del paquete.

Por defecto, tcpreplay enviará paquetes con la longitud original del paquete. Sin embargo, puede que desee que la longitud del paquete se revise al tamaño mínimo del paquete. Usando esta opción, tcpreplay reescribirá (corregirá) la longitud del paquete y recalculará las sumas de comprobación cuando cambie la longitud del paquete. Precaución: pueden ocurrir cambios no deseados en el paquete cuando se especifica esta opción.

-m número, --mtu=número

Anular la longitud MTU predeterminada (1500 bytes). Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
en el rango  1 hasta MAX_SNAPLEN

Anula el tamaño MTU predeterminado de 1500 bytes para determinar la longitud máxima de relleno (--fixlen=pad) o al truncar (--mtu-trunc).

--mtu-trunc

Truncar paquetes más grandes que la MTU especificada. Esta opción puede aparecer hasta 1 vez.

Similar a --fixlen, esta opción truncará los datos en los paquetes desde la Capa 3 en adelante para que no sean más grandes que la MTU.

-E, --efcs

Eliminar las sumas de comprobación Ethernet (FCS) del final de los trames.

¡Nota, esta opción es bastante peligrosa! En realidad, no comprobamos si existe una FCS en el trame, simplemente eliminamos a ciegas los últimos 4 bytes. Por lo tanto, solo debe usar esto si sabe que su sistema operativo proporciona la FCS al leer paquetes crudos.

--ttl=cadena

Modificar el TTL/Límite de saltos de IPv4/v6.

Le permite modificar el TTL/Límite de saltos de todos los paquetes IPv4/v6. Especifique un número para codificar el valor o +/- valor para aumentar o disminuir

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

rease según el valor proporcionado (limitado a 1-255).

Ejemplos:

    --ttl=10
    --ttl=+7
    --ttl=-64
--tos=número

Establece el byte TOS/DiffServ/ECN de IPv4. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
en el rango  0 a 255

Permite anular el valor TOS (también conocido como DiffServ/ECN) en IPv4.

--tclass=número

Establece el byte de Clase de Tráfico de IPv6. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
en el rango  0 a 255

Permite anular el campo de Clase de Tráfico de IPv6.

--flowlabel=número

Establece la Etiqueta de Flujo de IPv6. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
en el rango  0 a 1048575

Permite anular el campo de Etiqueta de Flujo de IPv6 de 20 bits. No tiene efecto en los paquetes IPv4.

-F cadena, --fixlen=cadena

Rellena o trunca los datos del paquete para que coincidan con la longitud de la cabecera. Esta opción puede aparecer hasta 1 vez.

Los paquetes pueden truncarse durante la captura si el snaplen es menor que el paquete. Esta opción le permite modificar el paquete para rellenarlo hasta el tamaño almacenado en la cabecera IPv4/v6 o reescribir la longitud total de la cabecera IP para reflejar la longitud del paquete almacenado.

pad Los paquetes truncados se rellenarán para que la longitud del paquete coincida con la longitud total de IPv4

trunc Los paquetes truncados tendrán su campo de longitud total de IPv4 reescrito para que coincida con la longitud real del paquete

del Elimina el paquete

--fuzz-seed=número

Introduce "fuzzing" en 1 de cada X paquetes. Edita bytes, longitud, o emula la caída de paquetes. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
mayor o igual que 0

El valor predeterminado de número para esta opción es:
0

Este "fuzzing" fue diseñado para probar protocolos de capa 7, como los protocolos VoIP. Modifica aleatoriamente 1 de cada X paquetes (donde X = --fuzz-factor) para que los protocolos con estado cubran más de su código. Las acciones aleatorias de "fuzzing" se centran en el inicio y el final de los datos porque a menudo es la parte de los datos en la que los protocolos de aplicación basan sus decisiones.

Lista de posibles acciones de "fuzzing":
* dejar caer el paquete
* reducir el tamaño del paquete
* editar bytes del paquete:
* No todos los bytes tienen la misma probabilidad de aparecer en la vida real.
Reemplazar con 0x00, 0xFF, o un byte aleatorio con igual probabilidad.
* No todos los bytes tienen la misma importancia en un paquete.
Reemplazar el inicio, el final o el medio del paquete con igual probabilidad.
* no hacer nada (7 de cada 8 paquetes)

--fuzz-factor=número

Establece la relación de "fuzzing" 1 de cada X paquetes (predeterminado 1 de cada 8 paquetes). Esta opción debe aparecer en combinación con las siguientes opciones: fuzz-seed. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
mayor o igual que 1

El valor predeterminado de número para esta opción es:
8

Establece la relación para la opción --fuzz-seed. Por defecto, este valor es 8, lo que significa que 1 de cada 8 paquetes es modificado por "fuzzing". Tenga en cuenta que esta relación se basa en el número aleatorio generado por la semilla de "fuzz" proporcionada. Por lo tanto, por defecto, no se puede esperar que exactamente cada octavo paquete sea modificado.

--skipl2broadcast

Omitir la reescritura de direcciones de Capa 2 de difusión/multidifusión.

Por defecto, la edición de direcciones de Capa 2 reescribirá las direcciones MAC de difusión y multidifusión. Establecer esta bandera evitará que las direcciones MAC de difusión/multidifusión sean reescritas.

--dlt=cadena

Anular la encapsulación DLT de salida. Esta opción puede aparecer hasta 1 vez.

Por defecto, no se realizará ninguna conversión de DLT (tipo de enlace de datos). Para cambiar el tipo DLT de la pcap de salida, seleccione uno de los siguientes valores:

enet Ethernet, también conocido como DLT_EN10MB

hdlc Cisco HDLC, también conocido como DLT_C_HDLC

jnpr_eth Juniper Ethernet DLT_C_JNPR_ETHER

pppserial PPP Serial, también conocido como DLT_PPP_SERIAL

user Tipo de DLT y cabecera de Capa 2 especificada por el usuario

--enet-dmac=cadena

Anular las direcciones MAC de destino de Ethernet. Esta opción puede aparecer hasta 1 vez.

Toma un par de direcciones MAC de Ethernet separadas por comas que reemplazarán la dirección MAC de destino de los paquetes salientes. La primera dirección MAC se utilizará para el tráfico del servidor al cliente y la segunda dirección MAC opcional se utilizará para el tráfico del cliente al servidor.

Ejemplo:

    --enet-dmac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-smac=cadena

Anular las direcciones MAC de origen de Ethernet. Esta opción puede aparecer hasta 1 vez.

Toma un par de direcciones MAC de Ethernet separadas por comas que reemplazarán la dirección MAC de origen de los paquetes salientes. La primera dirección MAC se utilizará para el tráfico del servidor al cliente y la segunda dirección MAC opcional se utilizará para el tráfico del cliente al servidor.

Ejemplo:

    --enet-smac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-subsmac=cadena

Sustituir direcciones MAC. Esta opción puede aparecer hasta 9999 veces.

Permite reescribir las direcciones MAC de Ethernet de los paquetes. Toma un par de direcciones MAC separadas por comas y reescribe todas las ocurrencias de la primera MAC con el valor de la segunda MAC. Ejemplo:

    --enet-subsmac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-mac-seed=número

Aleatorizar direcciones MAC. Esta opción puede aparecer hasta 1 vez. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: enet-smac, enet-dmac, enet-subsmac. Esta opción toma un número entero como argumento.

Permite aleatorizar las direcciones MAC de Ethernet de los paquetes, muy parecido a lo que hace la opción --seed para direcciones IPv4/IPv6.

--enet-mac-seed-keep-bytes=número

Aleatorizar direcciones MAC. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con las siguientes opciones: enet-mac-seed. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
en el rango  1 a 6

Mantiene algunos bytes intactos al usar la opción --enet-mac-seed.

--enet-vlan=cadena

Especifica el modo de etiqueta VLAN 802.1q de Ethernet. Esta opción puede aparecer hasta 1 vez.

Permite reescribir tramas Ethernet para añadir una cabecera 802.1q a las cabeceras estándar Ethernet 802.3 o eliminar la información de etiqueta VLAN 802.1q.

add Añade una cabecera VLAN 802.1q a la cabecera Ethernet 802.3 existente. Si ya existe una cabecera VLAN, se añade una nueva cabecera VLAN fuera de la cabecera existente.

Tenga en cuenta que se le permitirá ejecutar esta opción varias veces para crear más de 2 etiquetas VLAN, sin embargo, esos paquetes serán válidos. Como máximo, debería tener 2 etiquetas VLAN X 802.1q, o una etiqueta VLAN externa 802.1ad y una interna 802.1q.

del Reescribe la cabecera VLAN 802.1q existente como una cabecera Ethernet 802.3.

--enet-vlan-tag=número

Especifica el nuevo valor de etiqueta VLAN 802.1q de Ethernet. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con las siguientes opciones: enet-vlan. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
en el rango  0 a 4095

--enet-vlan-cfi=número

Especifica el valor CFI de VLAN 802.1q de Ethernet. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con las siguientes opciones: enet-vlan. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
en el rango  0 a 1

--enet-vlan-pri=número

Especifica la prioridad VLAN 802.1q de Ethernet. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con las siguientes opciones: enet-vlan. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
en el rango  0 a 7

--enet-vlan-proto=cadena

Especifica el protocolo de etiqueta VLAN 802.1q o 802.1ad. Esta opción puede aparecer hasta 1 vez.

Permite especificar el protocolo de las etiquetas VLAN añadidas.

802.1q Especifica que se añadirán cabeceras VLAN 802.1q. Este es el valor predeterminado.

802.1ad Especifica que se añadirán cabeceras VLAN Q-in-Q 802.1ad. Para crear paquetes válidos, los paquetes de entrada deben tener ya cabeceras VLAN 802.1q.

--hdlc-control=número

Especifica el valor de control HDLC. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento.

La cabecera HDLC de Cisco

OPTIONS

--hdlc-control=number

Specify HDLC control. This option may appear up to 1 times. This option takes an integer number as its argument.

The Cisco HDLC header has a 1 byte "control" field. Aparentemente, este debería ser siempre 0, pero puedes usar cualquier valor de 1 byte.

--hdlc-address=number

Especificar la dirección HDLC. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento.

La cabecera HDLC de Cisco tiene un campo de "dirección" de 1 byte que tiene dos valores válidos:

0x0F Unicast

0xBF Broadcast
Sin embargo, puedes especificar cualquier valor de un solo byte.

--user-dlt=number

Establecer el tipo DLT del archivo de salida. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento.

Establece el valor DLT del archivo pcap de salida.

--user-dlink=string

Reescribir la capa de enlace de datos con datos especificados por el usuario. Esta opción puede aparecer hasta 2 veces.

Proporciona una serie de valores hexadecimales delimitados por comas que se utilizarán para reescribir o crear la cabecera de Capa 2 de los paquetes. La primera instancia de este argumento reescribirá el tráfico tanto del servidor como del cliente, pero si este argumento se especifica una segunda vez, se utilizará para el tráfico del cliente.

Ejemplo:

    --user-dlink=01,02,03,04,05,06,00,1A,2B,3C,4D,5E,6F,08,00
-d number, --dbug=number

Habilitar salida de depuración. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento. El valor de number está restringido a estar: 
en el rango de 0 a 5

El valor predeterminado de number para esta opción es:
0

Si se configura con --enable-debug, puedes especificar un nivel de verbosidad para la salida de depuración. Los números más altos aumentan la verbosidad.

-i string, --infile=string

Archivo pcap de entrada a procesar. Esta opción puede aparecer hasta 1 vez.
-o string, --outfile=string

Archivo pcap de salida. Esta opción puede aparecer hasta 1 vez.
-c string, --cachefile=string

Dividir el tráfico mediante un archivo de caché de tcpprep. Esta opción puede aparecer hasta 1 vez.

Utiliza el archivo de caché de tcpprep para dividir el tráfico basándose en las relaciones cliente/servidor.

-v, --verbose

Imprimir paquetes decodificados mediante tcpdump a STDOUT. Esta opción puede aparecer hasta 1 vez.
-A string, --decode=string

Argumentos pasados al decodificador de tcpdump. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con las siguientes opciones: verbose.

Al habilitar el modo verboso (-v), también puedes especificar uno o más argumentos adicionales para pasar a tcpdump para modificar la forma en que se decodifican los paquetes. Por defecto, se utilizan -n y -l. Asegúrate de citar los argumentos para que no sean interpretados por tcprewrite. Consulta la página del manual de tcpdump(1) para obtener una lista completa de opciones.

--fragroute=string

Analizar el archivo de configuración de fragroute. Esta opción puede aparecer hasta 1 vez.

Habilita técnicas avanzadas de evasión utilizando el motor incorporado de fragroute(8). Consulta la página del manual de fragroute(8) para obtener más detalles. Importante: tcprewrite no soporta los comandos delay, echo ni print.

--fragdir=string

Qué flujos aplicar fragroute: c2s, s2c, ambos. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con las siguientes opciones: cachefile.

Aplica el motor fragroute a los paquetes que van de c2s, s2c o ambos cuando se utiliza un archivo de caché.

--skip-soft-errors

Omitir la escritura de paquetes con errores leves. Esta opción puede aparecer hasta 1 vez.

En algunos casos, los paquetes no pueden ser decodificados o la edición solicitada no es posible. Normalmente, estos paquetes se escriben en el archivo de salida sin editar para que los archivos de caché de tcpprep aún puedan utilizarse, pero si lo deseas, estos paquetes pueden ser suprimidos.

Un ejemplo de esto son los fotogramas de gestión 802.11 que no contienen datos.
