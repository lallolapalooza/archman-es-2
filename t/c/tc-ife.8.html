NOMBRE

IFE - encapsular/desencapsular metadatos

SINOPSIS


tc ... action ife DIRECCIÓN [ ACCIÓN ] [ dst DMAC ] [ src SMAC ] [ type TIPO ] [ CONTROL ] [ index INDICE ]

DIRECCIÓN := { decode | encode }

ACCIÓN := { allow ATTR | use ATTR valor }

ATTR := { mark | prio | tcindex }

CONTROL := { reclassify | use | pipe | drop | continue | ok | goto chain INDICE_CADENA }

DESCRIPCIÓN

La acción ife permite que un lado emisor encapsule metadatos arbitrarios, que luego son desencapsulados por el lado receptor. El emisor se ejecuta en modo de codificación y el receptor en modo de decodificación. Tanto el emisor como el receptor deben especificar el mismo eterType. En el futuro, un eterType registrado puede estar disponible como predeterminado.

OPCIONES

decode
Para el lado receptor; decodificar los metadatos si el paquete coincide.
encode
Para el lado emisor. Codificar los metadatos especificados si el paquete coincide.
allow
Solo en dirección de codificación. Permite codificar metadatos especificados.
use
Solo en dirección de codificación. Forzar la codificación estática de los metadatos especificados.
mark [
valor_u32 ] El valor a establecer para la marca skb. El valor u32 solo es necesario cuando se especifica use. Si el valor de mark es cero, no se codificará, sino que las estadísticas de "excesos" se incrementarán y se tomará la acción CONTROL.
prio [
valor_u32 ] El valor a establecer para la prioridad en la estructura skb. El valor u32 solo es necesario cuando se especifica use.
tcindex [
valor_u16 ] Valor a establecer para el índice de control de tráfico en la estructura skb. El valor u16 solo es necesario cuando se especifica use.
dmac DMAC
smac SMAC
Dirección MAC de destino o de origen opcional de seis bytes a codificar.
type TIPO
EterType opcional de 16 bits a codificar. Si no se especifica, se usará el valor 0xED3E.
CONTROL
Acción a tomar después de una codificación/decodificación.
index INDICE
Asigna un ID único a esta acción en lugar de dejar que el kernel elija uno automáticamente. INDICE es un entero sin signo de 32 bits mayor que cero.

EJEMPLOS

En el lado receptor, coincide con paquetes con eterType 0xdead y reinicia la clasificación para que coincida con ICMP en la siguiente regla, con prioridad 3:

# tc qdisc add dev eth0 handle ffff: ingress
# tc filter add dev eth0 parent ffff: prio 2 protocol 0xdead \
	u32 match u32 0 0 flowid 1:1 \
	action ife decode reclassify
# tc filter add dev eth0 parent ffff: prio 3 protocol ip \
	u32 match ip protocol 0xff flowid 1:1 \
	action continue

Coincide con la marca skb de 17:

# tc filter add dev eth0 parent ffff: prio 4 protocol ip \
	handle 0x11 fw flowid 1:1 \
	action ok

Configura el lado emisor para codificar para los filtros anteriores. Utiliza una dirección IP de destino de 192.168.122.237/24, luego etiqueta con la marca skb de 17 en decimal. Codifica el paquete con eterType 0xdead, añade skb->mark a la lista permitida de metadatos a enviar, y reescribe la dirección MAC de destino a 02:15:15:15:15:15.

# tc qdisc add dev eth0 root handle 1: prio
# tc filter add dev eth0 parent 1: protocol ip prio 10 u32 \
	match ip dst 192.168.122.237/24 \
	match ip protocol 1 0xff \
	flowid 1:2 \
	action skbedit mark 17 \
	action ife encode \
	type 0xDEAD \
	allow mark \
	dst 02:15:15:15:15:15
