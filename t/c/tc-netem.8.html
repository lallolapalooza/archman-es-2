NOMBRE

netem - Emulador de Red

SINOPSIS

tc qdisc ... dev DISPOSITIVO ] add netem OPCIONES

OPCIONES := [ LIMITE ] [ RETRASO ] [ PERDIDA ] [ CORRUPCION ] [ DUPLICACION ] [ REORDENACION ] [ TASA ] [ RANURA ] [ SEMILLA ]

LIMITE := limit paquetes

RETRASO := delay TIEMPO [ JITTER [ CORRELACION ]]]
[ distribution { uniform | normal | pareto | paretonormal } ]

PERDIDA := loss { random PORCENTAJE [ CORRELACION ] |
state p13 [ p31 [ p32 [ p23 [ p14]]]] |
gemodel p [ r [ 1-h [ 1-k ]]] } [ ecn ]

CORRUPCION := corrupt PORCENTAJE [ CORRELACION ]]

DUPLICACION := duplicate PORCENTAJE [ CORRELACION ]]

REORDENACION := reorder PORCENTAJE [ CORRELACION ] [ gap DISTANCIA ]

TASA := rate TASA [ SOBRECARGA_PAQUETE [ TAMAÑO_CELDA [ SOBRECARGA_CELDA ]]]]

RANURA := slot { MIN_RETRASO [ MAX_RETRASO ] |
distribution { uniform | normal | pareto | paretonormal | ARCHIVO } RETRASO JITTER }
[ packets PAQUETES ] [ bytes BYTES ]

SEMILLA := seed VALOR

DESCRIPCIÓN

La disciplina de cola netem proporciona funcionalidad de Emulación de Red para probar protocolos emulando las propiedades de las redes del mundo real.

La disciplina de cola proporciona uno o más impedimentos de red a los paquetes, tales como: retraso, pérdida, duplicación y corrupción de paquetes.

OPCIONES

limit CUENTA
Limita el número máximo de paquetes que la qdisc puede contener al aplicar retraso.
delay
TIEMPO [ JITTER [ CORRELACION ]]]
Retrasa los paquetes antes de enviarlos. Los parámetros opcionales permiten introducir una variación del retraso y una correlación. Los valores de retraso y jitter se expresan en milisegundos; la correlación se establece especificando un porcentaje de cuánto el retraso anterior impactará el valor aleatorio actual.
distribution TIPO
Especifica un patrón para la distribución del retraso.
uniform
Utiliza una distribución equitativa de los retrasos de los paquetes.
normal
Utiliza una distribución gaussiana de los retrasos. A veces llamada Curva de Campana.
pareto
Utiliza una distribución de Pareto de los retrasos de los paquetes. Esto es útil para emular distribuciones de cola larga.
paretonormal
Esta es una mezcla de las distribuciones pareto y normal que tiene propiedades de ambas, Curva de Campana y cola larga.
loss MODELO
Descarta paquetes basándose en un modelo de pérdida. MODELO puede ser uno de
random PORCENTAJE
Cada pérdida de paquete es independiente.
state P13 [ P31 [ P32 [ P23 P14 ]]]
Utiliza una cadena de Markov de 4 estados para describir la pérdida de paquetes.
P13 es la pérdida de paquetes. Los parámetros opcionales extienden el modelo a 2 estados P31, 3 estados P23, P32 y 4 estados P14.

Los estados de la cadena de Markov son:

1
buena recepción de paquetes (sin pérdida).
2
buena recepción dentro de un ráfaga.
3
pérdidas en ráfaga.
4
pérdidas independientes.
gemodel PORCENTAJE [ R [ 1-H [ 1-K ]]]
Utiliza un modelo Gilbert-Elliot (pérdida en ráfaga) basado en:
PORCENTAJE
probabilidad de iniciar estado defectuoso (con pérdidas).
R
probabilidad de salir del estado defectuoso.
1-H
probabilidad de pérdida en estado defectuoso.
1-K
probabilidad de pérdida en estado bueno.
ecn
Utiliza Notificación Explícita de Congestión (ECN) para marcar paquetes en lugar de descartarlos. Se debe usar un modelo de pérdida para que esto se habilite.
corrupt PORCENTAJE
modifica el contenido del paquete en una posición aleatoria basándose en PORCENTAJE.
duplicate PORCENTAJE
crea una copia del paquete antes de ponerlo en cola.
reorder PORCENTAJE
modifica el orden de los paquetes en la cola.
gap DISTANCIA
envía algunos paquetes inmediatamente. Los primeros (DISTANCIA - 1) paquetes se retrasan y el siguiente paquete se envía inmediatamente.
rate TASA [ SOBRECARGA_PAQUETE [ TAMAÑO_CELDA [ SOBRECARGA_CELDA ]]]
Retrasa los paquetes basándose en el tamaño del paquete para emular una velocidad de enlace fija. Parámetros opcionales:
SOBRECARGA_PAQUETE
Especifica una sobrecarga por paquete en bytes. Se utiliza para simular encabezados adicionales de capa de enlace. Se puede usar un valor negativo para simular cuando se elimina el encabezado Ethernet (por ejemplo, -14) o se utiliza compresión de encabezado.
TAMAÑO_CELDA
simula esquemas de capa de enlace como ATM.
SOBRECARGA_CELDA
especifica la sobrecarga por celda.

La limitación de tasa se ve afectada por varios factores, incluida la granularidad del reloj del kernel. Esto se manifestará en una compresión artificial de paquetes (ráfagas).

slot MIN_RETRASO [ MAX_RETRASO ]
permite emular redes segmentadas. Retrasa la entrega de paquetes acumulados dentro de un segmento. Cada segmento disponible se configura con un retraso mínimo para adquirir, y un retraso máximo opcional.
slot distribution
permite la configuración basada en la distribución similar a la opción distribution para retrasos de paquetes.

Estas opciones de segmento pueden proporcionar una aproximación cruda de MACs en ráfaga como DOCSIS, WiFi y LTE.

La emulación de segmentos está limitada por varios factores: la granularidad del reloj del kernel, al igual que con la tasa, e intenta entregar muchos paquetes dentro de un segmento se verá difuminado por la resolución del temporizador, y también por el ancho de banda nativo subyacente.

Es posible combinar segmentación con una tasa, en cuyo caso comportamientos complejos donde ya sea la tasa, o los límites de segmento en bytes o paquetes por segmento, rigen la tasa real entregada.

seed VALOR
Especifica una semilla para guiar y reproducir los eventos de pérdida o corrupción generados aleatoriamente.

LIMITACIONES

Netem está limitado por la granularidad del temporizador en el kernel. La tasa y el retraso pueden verse afectados por las interrupciones del reloj.

La mezcla de formas de reordenación puede llevar a resultados inesperados. Para que cualquier método de reordenación funcione, es necesario algún retraso. Si el retraso es menor que el tiempo de llegada entre paquetes, no se verá ninguna reordenación. Debido a mecanismos como TSQ (TCP Small Queues), para que los resultados de rendimiento de TCP sean realistas, netem debe colocarse en la entrada del host receptor.

LIMITATIONS

Combinar netem con otras colas qdisc es posible pero puede no funcionar siempre porque netem usa el bloque de control skb para establecer retrasos.

EJEMPLOS

# tc qdisc add dev eth0 root netem delay 100ms
Añade una cantidad fija de retraso a todos los paquetes que salen por el dispositivo eth0. Cada paquete tendrá un retraso adicional de 100ms ± 10ms.
# tc qdisc change dev eth0 root netem delay 100ms 10ms 25%
Esto provoca un retraso adicional de 100ms ± 10ms y el valor del siguiente retraso de paquete estará sesgado un 25% respecto al retraso más reciente. Esto no es una correlación estadística real, sino una aproximación.
# tc qdisc change dev eth0 root netem delay 100ms 20ms distribution normal
Esto retrasa los paquetes según una distribución normal (curva de campana) en un rango de 100ms ± 20ms.
# tc qdisc change dev eth0 root netem loss 0.1%
Esto provoca que el 0.1% (es decir, 1 de cada 1000) de los paquetes se descarten aleatoriamente.

También se puede añadir una correlación opcional. Esto hace que el generador de números aleatorios sea menos aleatorio y puede usarse para emular pérdidas de ráfagas de paquetes.

# tc qdisc change dev eth0 root netem duplicate 1%
Esto provoca que el uno por ciento de los paquetes enviados en eth0 se dupliquen.
# tc qdisc change dev eth0 root netem loss 0.3% 25%
Esto provocará que el 0.3% de los paquetes se pierdan, y cada probabilidad sucesiva depende de estar sesgada un 25% respecto a la anterior.

Hay dos formas diferentes de especificar la reordenación. El método `gap` utiliza una secuencia fija y reordena cada N-ésimo paquete.

# tc qdisc change dev eth0 root netem gap 5 delay 10ms
Esto provoca que cada 5º (10º, 15º, ...) paquete se envíe inmediatamente y que cada otro paquete se retrase 10ms. Esto es predecible y útil para pruebas de protocolos base como el reensamblaje.

La forma `reorder` utiliza un porcentaje de los paquetes para que se desordenen.

# tc qdisc change dev eth0 root netem delay 10ms reorder 25% 50%

En este ejemplo, el 25% de los paquetes (con una correlación del 50%) se enviarán inmediatamente, los demás se retrasarán 10ms.

Los paquetes también se reordenarán si el jitter es lo suficientemente grande.

# tc qdisc change dev eth0 root netem delay 100ms 75ms
Si el primer paquete recibe un retraso aleatorio de 100ms (base de 100ms - jitter de 0ms) y el segundo paquete se envía 1ms después y recibe un retraso de 50ms (base de 100ms - jitter de 50ms); el segundo paquete se enviará primero. Esto se debe a que la disciplina de cola `tfifo` dentro de `netem` mantiene los paquetes en orden según el tiempo de envío.

Si no desea este comportamiento, reemplace la disciplina de cola interna `tfifo` con una disciplina de cola FIFO simple.

# tc qdisc add dev eth0 root handle 1: netem delay 10ms 100ms
# tc qdisc add dev eth0 parent 1:1 pfifo limit 1000

Ejemplo de uso de control de velocidad y tamaño de celdas.

# tc qdisc add dev eth0 root netem rate 5kbit 20 100 5
Retrasa todos los paquetes salientes en el dispositivo eth0 con una velocidad de 5kbit, una sobrecarga por paquete de 20 bytes, un tamaño de celda de 100 bytes y una sobrecarga por celda de 5 bytes.

Es posible aplicar selectivamente el deterioro utilizando la clasificación de tráfico.

# tc qdisc add dev eth0 root handle 1: prio
# tc qdisc add dev eth0 parent 1:3 handle 30:    tbf rate 20kbit buffer 1600 limit  3000
# tc qdisc add dev eth0 parent 30:1 handle 31:    netem delay 200ms 10ms distribution normal
# tc filter add dev eth0 protocol ip parent 1:0 prio 3 u32    match ip dst 65.172.181.4/32 flowid 1:3
Este ejemplo utiliza una disciplina de colas de prioridad; se añade un TBF para realizar el control de velocidad; y un retraso `netem` simple. Un filtro clasifica todos los paquetes dirigidos a 65.172.181.4 como de prioridad 3.
