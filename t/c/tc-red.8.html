NOMBRE

red - Detección Temprana Aleatoria (Random Early Detection)

SINOPSIS

tc qdisc ... red limit bytes [ min bytes ] [ max bytes ] avpkt bytes [ burst paquetes ] [ ecn ] [ harddrop ] [ nodrop ] [ bandwidth tasa ] [ probability oportunidad ] [ adaptive ] [ qevent early_drop block índice ] [ qevent mark block índice ]

DESCRIPCIÓN

Random Early Detection es un qdisc sin clases que gestiona el tamaño de su cola de forma inteligente. Las colas regulares simplemente descartan paquetes desde la cola cuando están llenas, lo que puede no ser el comportamiento óptimo. RED también realiza descarte desde la cola (tail drop), pero lo hace de una manera más gradual.

Una vez que la cola alcanza una cierta longitud promedio, los paquetes encolados tienen una probabilidad configurable de ser marcados (lo que puede significar ser descartados). Esta probabilidad aumenta linealmente hasta un punto llamado longitud promedio de cola max, aunque la cola podría volverse más grande.

Esto tiene una serie de beneficios sobre el simple descarte de cola (taildrop), sin ser intensivo en procesador. Previene retransmisiones síncronas después de un pico de tráfico, que causan más retransmisiones, etc.

El objetivo es tener un tamaño de cola pequeño, lo cual es bueno para la interactividad sin perturbar el tráfico TCP/IP con demasiados descartes repentinos después de un pico de tráfico.

Dependiendo de si ECN está configurado, el marcado significa descartar o simplemente marcar un paquete como excedido de límite.

ALGORITMO

El tamaño promedio de la cola se utiliza para determinar la probabilidad de marcado. Este se calcula utilizando una Media Móvil Ponderada Exponencialmente, que puede ser más o menos sensible a los picos.

Cuando el tamaño promedio de la cola está por debajo de min bytes, ningún paquete será marcado. Cuando excede min, la probabilidad de hacerlo aumenta linealmente hasta probability, hasta que el tamaño promedio de la cola alcanza max bytes. Dado que probability normalmente no se establece al 100%, el tamaño de la cola podría concebiblemente superar los max bytes, por lo que el parámetro limit se proporciona para establecer un límite máximo real para el tamaño de la cola.

PARÁMETROS

min
Tamaño promedio de cola en el que el marcado se convierte en una posibilidad. Por defecto: max /3.
max
A este tamaño promedio de cola, la probabilidad de marcado es máxima. Debería ser al menos el doble de min para prevenir retransmisiones síncronas, más alto para min bajos. Por defecto: limit /4.
probability
Probabilidad máxima de marcado, especificada como un número de punto flotante de 0.0 a 1.0. Valores sugeridos son 0.01 o 0.02 (1% o 2%, respectivamente). Por defecto: 0.02.
limit
Límite real sobre el tamaño real (no promedio) de la cola en bytes. Los paquetes adicionales se descartan. Debería configurarse más alto que max + burst. Se recomienda configurarlo unas cuantas veces más alto que max.
burst
Se utiliza para determinar la rapidez con la que el tamaño promedio de la cola se ve influenciado por el tamaño real de la cola. Valores más grandes hacen que el cálculo sea más lento, permitiendo ráfagas de tráfico más largas antes de que comience el marcado. Experimentos reales respaldan la siguiente guía: (min+min+max)/(3*avpkt).
avpkt
Especificado en bytes. Se utiliza junto con burst para determinar la constante de tiempo para los cálculos del tamaño promedio de la cola. 1000 es un buen valor.
bandwidth
Esta tasa se utiliza para calcular el tamaño promedio de la cola después de un tiempo inactivo. Debería configurarse al ancho de banda de su interfaz. ¡No significa que RED limitará la velocidad por usted! Opcional. Por defecto: 10Mbit.
ecn
Como se mencionó anteriormente, RED puede 'marcar' o 'descartar'. La Notificación Explícita de Congestión permite a RED notificar a los hosts remotos que su tasa excede la cantidad de ancho de banda disponible. Los hosts no capaces de ECN solo pueden ser notificados descartando un paquete. Si se especifica este parámetro, los paquetes que indiquen que sus hosts respetan ECN solo serán marcados y no descartados, a menos que el tamaño de la cola alcance limit bytes. Recomendado.
harddrop
Si el tamaño promedio de la cola del flujo está por encima de max bytes, este parámetro fuerza un descarte en lugar de un marcado ECN.
nodrop
Con este parámetro, el tráfico que debería ser marcado, pero que no es capaz de ECN, se encola. Sin el parámetro, se descarta tempranamente.
adaptive
(Añadido en linux-3.3) Establece RED en modo adaptativo como se describe en http://icir.org/floyd/papers/adaptiveRed.pdf 
El objetivo de Adaptive RED es hacer que 'probability' sea un valor dinámico entre 1% y 50% para alcanzar la cola promedio objetivo:
(max - min) / 2

QEVENTS

Vea tc (8) para algunas notas generales sobre qevents. El qdisc RED soporta los siguientes qevents:

early_drop
El bloque asociado se ejecuta cuando los paquetes son descartados tempranamente. Esto incluye paquetes no-ECT en modo ECN.
mark
El bloque asociado se ejecuta cuando los paquetes son marcados en modo ECN.

EJEMPLO

# tc qdisc add dev eth0 parent 1:1 handle 10: red
limit 400000 min 30000 max 90000 avpkt 1000
burst 55 ecn adaptive bandwidth 10Mbit

NAME

tc-red - Random Early Detection (RED) queueing discipline

SYNOPSIS

tc qdisc add ... red

tc qdisc replace ... red

DESCRIPTION

RED is a queue management algorithm that aims to avoid network congestion by detecting and dropping packets early. It works by probabilistically dropping packets when the average queue length exceeds a certain threshold. This allows TCP congestion control to react before the queue is full, thus preventing global synchronization and improving network performance.

OPTIONS

min
The minimum average queue length. When the average queue length is below this value, no packets are dropped.
max
The maximum average queue length. When the average queue length is above this value, all packets are dropped.
avp
The average packet size. Used to calculate the time intervals for sampling the queue length. Defaults to 1000 bytes.
proba
The probability of dropping a packet when the average queue length is between min and max. This probability increases linearly from 0 at min to 1 at max.
ecn
Enable ECN (Explicit Congestion Notification) marking. If set, packets are marked instead of dropped when congestion is detected.

EXAMPLE

Add a RED queueing discipline to the eth0 interface with a minimum average queue length of 10 packets, a maximum of 30 packets, and a maximum drop probability of 0.02:

tc qdisc add dev eth0 parent 1:1 handle 10: red min 10 max 30 avp 1000 pro_b 0.02
