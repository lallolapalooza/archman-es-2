INTRODUCCIÓN

Tcl incluye una biblioteca de procedimientos de Tcl para funciones de uso común. Los procedimientos definidos en la biblioteca de Tcl son genéricos y adecuados para su uso por muchas aplicaciones diferentes. La ubicación de la biblioteca de Tcl se devuelve con el comando info library. Además de la biblioteca de Tcl, cada aplicación normalmente tendrá su propia biblioteca de procedimientos de soporte; la ubicación de esta biblioteca normalmente se indica mediante el valor de la variable global $app_library, donde app es el nombre de la aplicación. Por ejemplo, la ubicación de la biblioteca Tk se mantiene en la variable tk_library.

Para acceder a los procedimientos de la biblioteca de Tcl, una aplicación debe "sourcear" el archivo init.tcl en la biblioteca, por ejemplo con el comando Tcl

source [file join [info library] init.tcl]

Si se invoca el procedimiento de biblioteca Tcl_Init desde el procedimiento Tcl_AppInit de una aplicación, esto ocurre automáticamente. El código en init.tcl definirá el procedimiento unknown y organizará la carga de los otros procedimientos bajo demanda utilizando el mecanismo de carga automática definido a continuación.

PROCEDIMIENTOS DE COMANDO

Los siguientes procedimientos se proporcionan en la biblioteca de Tcl:

auto_execok cmd
Determina si existe un archivo ejecutable o una instrucción incorporada en el shell con el nombre cmd. Si es así, devuelve una lista de argumentos que se pasarán a exec para ejecutar el archivo ejecutable o la instrucción incorporada en el shell denominada por cmd. Si no, devuelve una cadena vacía. Este comando examina los directorios en la ruta de búsqueda actual (dada por la variable de entorno PATH) en su búsqueda de un archivo ejecutable llamado cmd. En plataformas Windows, la búsqueda se expande con los mismos directorios y extensiones de archivo que se utilizan para exec. Auto_execok recuerda información sobre búsquedas anteriores en un array llamado auto_execs; esto evita la búsqueda de ruta en llamadas futuras para el mismo cmd. El comando auto_reset puede usarse para forzar que auto_execok olvide su información en caché.
auto_import patrón
Auto_import se invoca durante namespace import para ver si los comandos importados especificados por patrón residen en una biblioteca cargada automáticamente. Si es así, los comandos se cargan para que estén disponibles para el intérprete para crear los enlaces de importación. Si los comandos no residen en una biblioteca cargada automáticamente, auto_import no hace nada. La coincidencia de patrones se realiza de acuerdo con las reglas de coincidencia de namespace import.
auto_load cmd
Este comando intenta cargar la definición de un comando Tcl llamado cmd. Para hacer esto, busca una ruta de carga automática, que es una lista de uno o más directorios. La ruta de carga automática se da mediante la variable global auto_path si existe. Si no existe la variable auto_path, entonces se usa la variable de entorno TCLLIBPATH, si existe. De lo contrario, la ruta de carga automática consta solo del directorio de la biblioteca Tcl. Dentro de cada directorio en la ruta de carga automática debe haber un archivo tclIndex que describa uno o más comandos definidos en ese directorio y un script para evaluar para cargar cada uno de los comandos. El archivo tclIndex debe generarse con el comando auto_mkindex. Si se encuentra cmd en un archivo de índice, el script apropiado se evalúa para crear el comando. El comando auto_load devuelve 1 si cmd se creó correctamente. El comando devuelve 0 si no había una entrada de índice para cmd o si el script no definió realmente cmd (por ejemplo, porque la información del índice está desactualizada). Si ocurre un error al procesar el script, ese error se devuelve. Auto_load solo lee la información del índice una vez y la guarda en el array auto_index; llamadas futuras a auto_load verifican cmd en el array en lugar de volver a leer los archivos de índice. La información del índice en caché se puede eliminar con el comando auto_reset. Esto forzará a que el próximo comando auto_load recargue la base de datos de índices desde el disco.
auto_mkindex dir patrón patrón ...
Genera un índice adecuado para su uso por auto_load. El comando busca en dir todos los archivos cuyos nombres coincidan con cualquiera de los argumentos patrón (la coincidencia se realiza con el comando glob), genera un índice de todos los procedimientos de comandos Tcl definidos en todos los archivos coincidentes y almacena la información del índice en un archivo llamado tclIndex en dir. Si no se proporciona ningún patrón, se asumirá el patrón *.tcl. Por ejemplo, el comando
auto_mkindex foo *.tcl

leerá todos los archivos .tcl en el subdirectorio foo y generará un nuevo archivo de índice foo/tclIndex.

Auto_mkindex analiza los scripts Tcl ejecutándolos en un intérprete hijo y monitoreando los comandos proc y namespace que se ejecutan. Las extensiones pueden usar el paquete (no documentado) auto_mkindex_parser para registrar otros comandos que pueden contribuir al índice de carga automática. Tendrá que leer auto.tcl para ver cómo funciona esto.

Auto_mkindex_old (que tiene la misma sintaxis que auto_mkindex) analiza los scripts Tcl de una manera relativamente poco sofisticada: si alguna línea contiene la palabra “proc” como sus primeros caracteres, se asume que es una definición de procedimiento y la siguiente palabra de la línea se toma como el nombre del procedimiento. Las definiciones de procedimientos que no aparecen de esta manera (por ejemplo, tienen espacios antes de proc) no se indexarán. Si su script contiene código “peligroso”, como código de inicialización global o nombres de procedimientos con caracteres especiales como $, *, [ o ], estará más seguro usando auto_mkindex_old.

auto_reset
Destruye toda la información almacenada en caché por auto_execok y auto_load. Esta información se volverá a leer del disco la próxima vez que se necesite. Auto_reset también elimina cualquier procedimiento listado en el índice de carga automática, para que se carguen copias nuevas de ellos la próxima vez que se utilicen.
auto_qualify comando espacio_de_nombres
Calcula una lista de nombres completamente calificados para comando. Esta lista refleja la ruta que sigue un intérprete Tcl estándar para la búsqueda de comandos: primero busca el comando en el espacio de nombres actual y luego en el espacio de nombres global. En consecuencia, si comando es relativo y espacio_de_nombres no es ::, la lista devuelta tiene dos elementos: comando con el ámbito del espacio de nombres espacio_de_nombres, como si fuera un comando en el espacio de nombres espacio_de_nombres; y comando como si fuera un comando en el espacio de nombres global. De lo contrario, si comando es absoluto (comienza con ::) o espacio_de_nombres es ::, la lista contiene solo comando como si fuera un comando en el espacio de nombres global.

Auto_qualify es utilizada por las facilidades de carga automática en Tcl, tanto para producir índices de carga automática como pkgIndex.tcl, como para realizar la carga automática real de funciones en tiempo de ejecución.

INTRODUCCION

Estas son rutinas de ayuda para el sistema de carga automática de Tcl. El sistema de carga automática permite a las aplicaciones cargar comandos individualmente a medida que son necesarios, en lugar de tener que cargarlos todos al inicio de la aplicación. Esto reduce el tiempo de inicio y el consumo de memoria de las aplicaciones. Los comandos discutidos aquí son usados por el manejador de comandos desconocido, el cual es activado cuando un comando que no está definido es invocado.

El procedimiento auto_execok se usa para determinar si un comando dado existe como un archivo ejecutable. auto_load se usa para cargar comandos desde un archivo que los define. auto_load_index es un procedimiento que se usa para obtener el índice de comandos de un archivo de índice de paquete. auto_mkindex se usa para generar los archivos de índice de paquetes. auto_qualify se usa para generar un nombre de comando cualificado. auto_reset se usa para borrar la caché de autoejecución y carga. parray se usa para imprimir los nombres y valores de los elementos de un array. tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter, y tcl_wordBreakBefore son procedimientos de ayuda que se usan para determinar los límites de palabras en una cadena.

PROCEDIMIENTOS DE COMANDO

auto_exec ?name?
Este procedimiento es llamado por el comando unknown para determinar si un comando existe como un archivo ejecutable. Si name se proporciona, auto_exec retornará el nombre completo del archivo ejecutable si existe, o una cadena vacía si no existe. Si name no se proporciona, auto_exec retornará una lista de todos los comandos conocidos como ejecutables. El procedimiento unknown utiliza esta información para ejecutar automáticamente comandos que no están definidos en el intérprete actual. La información sobre los comandos ejecutables se almacena en la variable global auto_execs.
auto_execok ?name?
Similar a auto_exec, pero solo retorna un valor booleano (1 si el comando es ejecutable, 0 si no lo es). Esto se usa para verificar si un comando puede ser ejecutado sin tener que obtener el nombre del archivo. La información se almacena y se recupera de la variable global auto_execs.
auto_import ?name?
Este procedimiento es llamado por el comando unknown para determinar si un comando definido por un paquete puede ser importado. Si name se proporciona, auto_import intentará importar el comando y retornará 1 si tiene éxito, o 0 si no. Si name no se proporciona, auto_import retornará una lista de todos los comandos importables. Los procedimientos de carga automática de paquetes se buscan en las carpetas especificadas en la variable global auto_path.
auto_load ?name?
Este procedimiento es llamado por el comando unknown para cargar un comando que no está definido. Si name se proporciona, auto_load intentará cargar el comando desde un archivo de carga automática y retornará 1 si tiene éxito, o 0 si no. Si name no se proporciona, auto_load retornará una lista de todos los comandos disponibles para carga automática. Los procedimientos de carga automática se buscan en las carpetas especificadas en la variable global auto_path.
auto_load_index ?name?
Este procedimiento es llamado por el comando unknown para obtener el índice de comandos de un archivo de índice de paquete. Si name se proporciona, auto_load_index retornará la lista de comandos disponibles en ese archivo de índice. Si name no se proporciona, auto_load_index retornará una lista de todos los archivos de índice de paquete disponibles. Los archivos de índice de paquete se buscan en las carpetas especificadas en la variable global auto_path.
auto_mkindex ?dir? ?pattern?
Genera automáticamente archivos de índice Tcl en el directorio especificado por dir. Si pattern se proporciona, solo se generarán índices para los archivos que coincidan con el patrón. El patrón utiliza las mismas reglas de coincidencia que el comando string match. Por defecto, si no se proporciona dir, se utiliza el directorio de la biblioteca Tcl. Si no se proporciona pattern, se utiliza el patrón *.tcl. El archivo de índice generado contiene procedimientos Tcl que son usados por auto_load_index para determinar qué comandos están disponibles en un directorio dado.
auto_qualify ?name? ?searchlist?
Este procedimiento se usa para determinar si un comando dado name necesita ser cualificado con un prefijo de paquete. Si name ya está cualificado (contiene ::), se retorna tal como está. Si no, se busca en la searchlist (una lista de prefijos de paquete) para ver si el comando pertenece a alguno de esos paquetes. Si se encuentra una coincidencia, se retorna el nombre cualificado. Si no se proporciona searchlist, se utiliza la lista de paquetes disponibles. Si name no puede ser cualificado, se retorna tal como está.
auto_reset
Este procedimiento se usa para borrar la caché de autoejecución y carga. Cuando un comando es ejecutado automáticamente o cargado, la información sobre él se almacena en caché para acelerar futuras invocaciones. auto_reset vacía esta caché, forzando a Tcl a volver a buscar los comandos la próxima vez que se necesiten. Esto es útil después de que se han modificado los scripts de carga automática o los archivos de índice.
tcl_endOfWord str start
Retorna el índice de la primera ubicación de fin de palabra que ocurre después de un índice de inicio start en la cadena str. Una ubicación de fin de palabra se define como el primer carácter no palabra que sigue al primer carácter palabra después del punto de inicio. Retorna -1 si no hay más ubicaciones de fin de palabra después del punto de inicio. Ver la descripción de tcl_wordchars y tcl_nonwordchars abajo para más detalles sobre cómo Tcl determina qué caracteres son caracteres de palabra.
tcl_startOfNextWord str start
Retorna el índice de la primera ubicación de inicio de palabra que ocurre después de un índice de inicio start en la cadena str. Una ubicación de inicio de palabra se define como el primer carácter palabra que sigue a un carácter no palabra. Retorna -1 si no hay más ubicaciones de inicio de palabra después del punto de inicio.
tcl_startOfPreviousWord str start
Retorna el índice de la primera ubicación de inicio de palabra que ocurre antes de un índice de inicio start en la cadena str. Retorna -1 si no hay más ubicaciones de inicio de palabra antes del punto de inicio.
tcl_wordBreakAfter str start
Retorna el índice del primer límite de palabra después del índice de inicio start en la cadena str. Retorna -1 si no hay más límites después del punto de inicio en la cadena dada. El índice retornado se refiere al segundo carácter del par que comprende un límite.
tcl_wordBreakBefore str start
Retorna el índice del primer límite de palabra antes del índice de inicio start en la cadena str. Retorna -1 si no hay más límites antes del punto de inicio en la cadena dada. El índice retornado se refiere al segundo carácter del par que comprende un límite.
parray arrayName ?pattern?
Imprime en la salida estándar los nombres y valores de todos los elementos en el array arrayName, o solo los nombres que coinciden con pattern (usando las reglas de coincidencia de string match) y sus valores si se proporciona pattern. arrayName debe ser un array accesible para el llamador de parray. Puede ser local o global.

VARIABLES

Las siguientes variables globales son definidas o usadas por los procedimientos de la biblioteca Tcl. Se dividen en dos clases amplias, manejo de comandos y paquetes desconocidos, y determinación de cuáles son las palabras.

VARIABLES DE AUTOCARGA Y GESTIÓN DE PAQUETES

auto_execs
Usada por auto_execok para registrar información sobre si comandos particulares existen como archivos ejecutables.
auto_index
Usada por auto_load para guardar la información del índice leída del disco.
auto_noexec
Si se establece a cualquier valor, entonces unknown no intentará auto-ejecutar ningún comando.
auto_noload
Si se establece a cualquier valor, entonces unknown no intentará auto-cargar ningún comando.
auto_path
Si se establece, entonces debe contener una lista Tcl válida que indique directorios a buscar durante las operaciones de autogarga (incluyendo archivos de índice de paquetes al usar el manejador predeterminado de package unknown). Esta variable se inicializa durante el inicio para contener, en orden: los directorios listados en la variable de entorno TCLLIBPATH, el directorio nombrado por la variable global tcl_library, el directorio padre de tcl_library, los directorios listados en la variable tcl_pkgPath. Ubicaciones adicionales para buscar archivos e índices de paquetes normalmente deberían agregarse a esta variable usando lappend.
env(TCL_LIBRARY)
Si se establece, entonces especifica la ubicación del directorio que contiene los scripts de biblioteca (el valor de esta variable se asignará a la variable tcl_library y por lo tanto será retornado por el comando info library). Si esta variable no se establece, se utiliza un valor predeterminado.
env(TCLLIBPATH)
Si se establece, entonces debe contener una lista Tcl válida que indique directorios a buscar durante las operaciones de autogarga. Los directorios deben especificarse en formato Tcl, usando “/” como separador de ruta, independientemente de la plataforma. Esta variable solo se utiliza al inicializar la variable auto_path.

VARIABLES DE DETERMINACIÓN DE LÍMITES DE PALABRA

Estas variables solo se usan en los comandos tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter, y tcl_wordBreakBefore.

tcl_nonwordchars
Esta variable contiene una expresión regular que es utilizada por rutinas como tcl_endOfWord para identificar si un carácter es parte de una palabra o no. Si el patrón coincide con un carácter, el carácter se considera un carácter no palabra. En plataformas Windows, los espacios, tabulaciones y saltos de línea se consideran caracteres no palabra. Bajo Unix, todo excepto números, letras y guiones bajos se consideran caracteres no palabra.
tcl_wordchars
Esta variable contiene una expresión regular que es utilizada por rutinas como tcl_endOfWord para identificar si un carácter es parte de una palabra o no. Si el patrón coincide con un carácter, el carácter se considera un carácter palabra. En plataformas Windows, las palabras están compuestas por cualquier carácter que no sea un espacio, tabulación o salto de línea. Bajo Unix, las palabras están compuestas por números, letras o guiones bajos.
