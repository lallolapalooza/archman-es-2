INTRODUCCIÓN

Tcl incluye una biblioteca de procedimientos de Tcl para funciones comúnmente necesarias. Los procedimientos definidos en la biblioteca Tcl son genéricos y adecuados para ser utilizados por muchas aplicaciones diferentes. La ubicación de la biblioteca Tcl se devuelve con el comando info library. Además de la biblioteca Tcl, cada aplicación normalmente tendrá también su propia biblioteca de procedimientos de soporte; la ubicación de esta biblioteca normalmente se da por el valor de la variable global app_library, donde app es el nombre de la aplicación. Por ejemplo, la ubicación de la biblioteca Tk se mantiene en la variable tk_library.

Para acceder a los procedimientos de la biblioteca Tcl, una aplicación debería cargar (source) el archivo init.tcl en la biblioteca, por ejemplo con el comando Tcl

source [file join [info library] init.tcl]

Si se invoca el procedimiento de biblioteca Tcl_Init desde el procedimiento Tcl_AppInit de una aplicación, esto ocurre automáticamente. El código en init.tcl definirá el procedimiento unknown y organizará que los otros procedimientos se carguen bajo demanda utilizando el mecanismo de carga automática (auto-load) definido a continuación.

PROCEDIMIENTOS DE COMANDO

Los siguientes procedimientos se proporcionan en la biblioteca Tcl:

auto_execok cmd
Determina si existe un archivo ejecutable o un comando interno de shell con el nombre cmd. Si es así, devuelve una lista de argumentos que se pasarán a exec para ejecutar el archivo ejecutable o el comando interno de shell llamado por cmd. Si no, devuelve una cadena vacía. Este comando examina los directorios en la ruta de búsqueda actual (dada por la variable de entorno PATH) en su búsqueda de un archivo ejecutable llamado cmd. En plataformas Windows, la búsqueda se expande con los mismos directorios y extensiones de archivo que utiliza exec. Auto_execok recuerda información sobre búsquedas previas en un array llamado auto_execs; esto evita la búsqueda en la ruta en llamadas futuras para el mismo cmd. El comando auto_reset puede usarse para forzar a auto_execok a olvidar su información cacheada.
auto_import patrón
Auto_import es invocado durante namespace import para ver si los comandos importados especificados por patrón residen en una biblioteca cargada automáticamente. Si es así, los comandos se cargan para que estén disponibles para el intérprete para crear los enlaces de importación. Si los comandos no residen en una biblioteca cargada automáticamente, auto_import no hace nada. La coincidencia de patrones se realiza de acuerdo con las reglas de coincidencia de namespace import.
auto_load cmd
Este comando intenta cargar la definición de un comando Tcl llamado cmd. Para hacer esto, busca en una *ruta de carga automática* (auto-load path), que es una lista de uno o más directorios. La ruta de carga automática se da por la variable global auto_path si existe. Si no existe la variable auto_path, entonces se usa la variable de entorno TCLLIBPATH, si existe. De lo contrario, la ruta de carga automática consiste solo en el directorio de la biblioteca Tcl. Dentro de cada directorio en la ruta de carga automática debe haber un archivo tclIndex que describe uno o más comandos definidos en ese directorio y un script para evaluar para cargar cada uno de los comandos. El archivo tclIndex debe ser generado con el comando auto_mkindex. Si se encuentra cmd en un archivo de índice, entonces se evalúa el script apropiado para crear el comando. El comando auto_load devuelve 1 si cmd se creó exitosamente. El comando devuelve 0 si no había una entrada de índice para cmd o si el script no definió realmente cmd (por ejemplo, debido a que la información del índice está desactualizada). Si ocurre un error al procesar el script, ese error se devuelve. Auto_load solo lee la información del índice una vez y la guarda en el array auto_index; las llamadas futuras a auto_load buscan cmd en el array en lugar de volver a leer los archivos de índice. La información cacheadada del índice puede eliminarse con el comando auto_reset. Esto forzará al próximo comando auto_load a recargar la base de datos del índice desde el disco.
auto_mkindex dir patrón patrón ...
Genera un índice adecuado para su uso por auto_load. El comando busca en dir todos los archivos cuyos nombres coincidan con alguno de los argumentos patrón (la coincidencia se realiza con el comando glob), genera un índice de todos los procedimientos de comando Tcl definidos en todos los archivos coincidentes, y almacena la información del índice en un archivo llamado tclIndex en dir. Si no se da ningún patrón, se asumirá un patrón de *.tcl. Por ejemplo, el comando
auto_mkindex foo *.tcl

leerá todos los archivos .tcl en el subdirectorio foo y generará un nuevo archivo de índice foo/tclIndex.

Auto_mkindex analiza los scripts Tcl cargándolos en un intérprete hijo y monitoreando los comandos proc y namespace que se ejecutan. Las extensiones pueden usar el paquete (no documentado) auto_mkindex_parser para registrar otros comandos que puedan contribuir al índice de carga automática. Tendrás que leer auto.tcl para ver cómo funciona esto.

Auto_mkindex_old (que tiene la misma sintaxis que auto_mkindex) analiza los scripts Tcl de una manera relativamente poco sofisticada: si alguna línea contiene la palabra “proc” como sus primeros caracteres, se asume que es una definición de procedimiento y la siguiente palabra de la línea se toma como el nombre del procedimiento. Las definiciones de procedimiento que no aparecen de esta manera (por ejemplo, tienen espacios antes de proc) no serán indexadas. Si tu script contiene código “peligroso”, como código de inicialización global o nombres de procedimiento con caracteres especiales como $, *, [ o ], estarás más seguro usando auto_mkindex_old.

auto_reset
Destruye toda la información cacheada por auto_execok y auto_load. Esta información se volverá a leer desde el disco la próxima vez que sea necesaria. Auto_reset también elimina cualquier procedimiento listado en el índice de carga automática, para que se carguen copias nuevas de ellos la próxima vez que se utilicen.
auto_qualify comando espacio_de_nombres
Calcula una lista de nombres completamente calificados para comando. Esta lista refleja la ruta que sigue un intérprete Tcl estándar para la búsqueda de comandos: primero busca el comando en el espacio de nombres actual y luego en el espacio de nombres global. En consecuencia, si comando es relativo y espacio_de_nombres no es ::, la lista devuelta tiene dos elementos: comando con ámbito de espacio_de_nombres, como si fuera un comando en el espacio de nombres espacio_de_nombres; y comando como si fuera un comando en el espacio de nombres global. De lo contrario, si comando es absoluto (comienza con ::), o espacio_de_nombres es ::, la lista contiene solo comando como si fuera un comando en el espacio de nombres global.

Auto_qualify es utilizado por las facilidades de carga automática en Tcl, tanto para producir índices de carga automática como pkgIndex.tcl, como para realizar la carga automática real de funciones en tiempo de ejecución.

NAME

tcl_findLibrary - find and source a Tcl library script

SYNOPSIS

tcl_findLibrary initScript varName enVarName ?basenameversion?

INTRODUCTION

This procedure is used to find and source Tcl scripts that are part of a Tk or Tcl extension's library. It searches a series of standard directories and, if the script is found, sources it into the current interpreter.

COMMAND PROCEDURES

tcl_findLibrary initScript varName enVarName ?basenameversion?
This is a standard search procedure for use by extensions during their initialization. They call this procedure to look for their script library in several standard directories. The last component of the name of the library directory is normally basenameversion (e.g., tk8.0), but it might be “library” when in the build hierarchies. The initScript file will be sourced into the interpreter once it is found. The directory in which this file is found is stored into the global variable varName. If this variable is already defined (e.g., by C code during application initialization) then no searching is done. Otherwise the search looks in these directories: the directory named by the environment variable enVarName; relative to the Tcl library directory; relative to the executable file in the standard installation bin or bin/arch directory; relative to the executable file in the current build tree; relative to the executable file in a parallel build tree.
parray arrayName ?pattern?
Prints on standard output the names and values of all the elements in the array arrayName, or just the names that match pattern (using the matching rules of string match) and their values if pattern is given. ArrayName must be an array accessible to the caller of parray. It may be either local or global.

WORD BOUNDARY HELPERS

These procedures are mainly used internally by Tk.

tcl_endOfWord str start
Returns the index of the first end-of-word location that occurs after a starting index start in the string str. An end-of-word location is defined to be the first non-word character following the first word character after the starting point. Returns -1 if there are no more end-of-word locations after the starting point. See the description of tcl_wordchars and tcl_nonwordchars below for more details on how Tcl determines which characters are word characters.
tcl_startOfNextWord str start
Returns the index of the first start-of-word location that occurs after a starting index start in the string str. A start-of-word location is defined to be the first word character following a non-word character. Returns -1 if there are no more start-of-word locations after the starting point.
tcl_startOfPreviousWord str start
Returns the index of the first start-of-word location that occurs before a starting index start in the string str. Returns -1 if there are no more start-of-word locations before the starting point.
tcl_wordBreakAfter str start
Returns the index of the first word boundary after the starting index start in the string str. Returns -1 if there are no more boundaries after the starting point in the given string. The index returned refers to the second character of the pair that comprises a boundary.
tcl_wordBreakBefore str start
Returns the index of the first word boundary before the starting index start in the string str. Returns -1 if there are no more boundaries before the starting point in the given string. The index returned refers to the second character of the pair that comprises a boundary.

VARIABLES

The following global variables are defined or used by the procedures in the Tcl library. They fall into two broad classes, handling unknown commands and packages, and determining what are words.

AUTOLOADING AND PACKAGE MANAGEMENT VARIABLES

auto_execs
Used by auto_execok to record information about whether particular commands exist as executable files.
auto_index
Used by auto_load to save the index information read from disk.
auto_noexec
If set to any value, then unknown will not attempt to auto-exec any commands.
auto_noload
If set to any value, then unknown will not attempt to auto-load any commands.
auto_path
If set, then it must contain a valid Tcl list giving directories to search during auto-load operations (including for package index files when using the default package unknown handler). This variable is initialized during startup to contain, in order: the directories listed in the TCLLIBPATH environment variable, the directory named by the tcl_library global variable, the parent directory of tcl_library, the directories listed in the tcl_pkgPath variable. Additional locations to look for files and package indices should normally be added to this variable using lappend.
env(TCL_LIBRARY)
If set, then it specifies the location of the directory containing library scripts (the value of this variable will be assigned to the tcl_library variable and therefore returned by the command info library). If this variable is not set then a default value is used.
env(TCLLIBPATH)
If set, then it must contain a valid Tcl list giving directories to search during auto-load operations. Directories must be specified in Tcl format, using “/” as the path separator, regardless of platform. This variable is only used when initializing the auto_path variable.

WORD BOUNDARY DETERMINATION VARIABLES

These variables are only used in the tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter, and tcl_wordBreakBefore commands.

tcl_nonwordchars
This variable contains a regular expression that is used by routines like tcl_endOfWord to identify whether a character is part of a word or not. If the pattern matches a character, the character is considered to be a non-word character. On Windows platforms, spaces, tabs, and newlines are considered non-word characters. Under Unix, everything but numbers, letters and underscores are considered non-word characters.
tcl_wordchars
This variable contains a regular expression that is used by routines like tcl_endOfWord to identify whether a character is part of a word or not. If the pattern matches a character, the character is considered to be a word character. On Windows platforms, words are comprised of any character that is not a space, tab, or newline. Under Unix, words are comprised of numbers, letters or underscores.
