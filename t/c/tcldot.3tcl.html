NOMBRE

tcldot - manipulación de grafos en tcl

SINOPSIS

#!/usr/local/bin/tclsh
package require Tcldot

USO

Requiere las facilidades de carga dinámica de tcl7.6 o posterior.

INTRODUCCIÓN

tcldot es una extensión de tcl cargada dinámicamente que incorpora las facilidades de grafos dirigidos de dot(1), y las facilidades de grafos no dirigidos de neato(1), dentro de tcl y proporciona un conjunto de comandos para controlar dichas facilidades. tcldot convierte dot y neato de herramientas de procesamiento por lotes a un conjunto de facilidades de manipulación de grafos interpretado y, si es necesario, interactivo.

COMANDOS

tcldot inicialmente añade solo tres comandos a tcl, a saber: dotnew, dotread, y dotstring. Estos comandos devuelven un manejador para el grafo que acaba de ser creado y dicho manejador puede ser utilizado como un comando para acciones posteriores sobre el grafo.

Todos los demás "comandos" son de la forma:

manejador <método> parámetros

Muchos de los métodos devuelven manejadores de grafos, nodos o aristas, que a su vez están registrados como comandos.

Los métodos se describen en detalle a continuación, pero en resumen:

Los métodos de grafo son:

addedge, addnode, addsubgraph, countedges, countnodes, layout, listattributes, listedgeattributes, listnodeattributes, listedges, listnodes, listnodesrev, listsubgraphs, render, rendergd, queryattributes, queryedgeattributes, querynodeattributes, queryattributevalues, queryedgeattributevalues, querynodeattributevalues, setattributes, setedgeattributes, setnodeattributes, showname, write.

Los métodos de nodo son:

addedge, listattributes, listedges, listinedges, listoutedges, queryattributes, queryattributevalues, setattributes, showname.

Los métodos de arista son:

delete, listattributes, listnodes, queryattributes, queryattributevalues, setattributes, showname.
dotnew tipoGrafo ?nombreAtributo valorAtributo? ?...?

crea un nuevo grafo vacío y devuelve su manejadorGrafo.

tipoGrafo puede ser cualquiera soportado por dot(1) a saber: "graph," "digraph," "graphstrict," o "digraphstrict." (En digraphs las aristas tienen una dirección de cola a cabeza. Los grafos "Strict" o digraphs colapsan múltiples aristas entre el mismo par de nodos en una sola arista.)

Siguiendo el parámetro obligatorio tipoGrafo el comando dotnew aceptará un número arbitrario de pares nombre/valor de atributo para el grafo. Ciertos atributos especiales de grafo y valores permitidos se describen en dot(1), pero el programador puede inventar y asignar arbitrariamente valores a atributos adicionales además de estos. En dot el nombre del atributo está separado del valor por un carácter "=". En tcldot el "=" ha sido reemplazado por un " " (espacio) para ser más consistente con la sintaxis de tcl. ej.

    set g [dotnew digraph rankdir LR]
dotread manejadorArchivo

lee una descripción en lenguaje dot de un grafo desde un archivo previamente abierto identificado por el manejadorArchivo. El comando devuelve el manejadorGrafo del grafo recién leído. ej.

    set f [open test.dot r]
    set g [dotread $f]
dotstring cadena

lee una descripción en lenguaje dot de un grafo desde una cadena Tcl; El comando devuelve el manejadorGrafo del grafo recién leído. ej.

    set g [dotstring $cadenaSintaxisDot]
manejadorGrafo addnode ?nombreNodo? ?nombreAtributo valorAtributo? ?...?

crea un nuevo nodo en el grafo cuyo manejador es manejadorGrafo y devuelve su manejadorNodo. El manejador de un nodo es una cadena como: "node0" donde el valor entero es diferente para cada nodo. Puede haber un número arbitrario de pares nombre/valor de atributo para el nodo. Ciertos atributos especiales de nodo y valores permitidos se describen en dot(1), pero el programador puede inventar y asignar arbitrariamente valores a atributos adicionales además de estos. ej.

    set n [$g addnode "N" label "Nodo\nSuperior" shape triangle eggs easyover]
Una posible causa de confusión en tcldot es la distinción entre manejadores, nombres, etiquetas y variables. La distinción radica principalmente en quién los posee. Los manejadores son propiedad de tcldot y se garantiza que son únicos dentro de una sesión de intérprete. Típicamente, los manejadores se asignan a variables, como "n" arriba, para su manipulación dentro de un script de tcl. Las variables son propiedad del programador. Los nombres son propiedad de la aplicación que está utilizando el grafo, típicamente los nombres son importantes al leer un grafo de un programa o archivo externo. Las etiquetas son el texto que se muestra con el nodo (o arista) cuando se visualiza el grafo, las etiquetas son significativas para el lector del grafo. Solo los manejadores y las variables son esenciales para la capacidad de tcldot de manipular grafos abstractos. Si no se especifica un nombre, este toma por defecto la representación en cadena del manejador; si no se especifica una etiqueta, esta toma por defecto el nombre.
manejadorGrafo addedge nodoCola nodoCabeza ?nombreAtributo valorAtributo? ?...?

crea una nueva arista en el grafo cuyo manejador es manejadorGrafo y devuelve su manejadorArista. nodoCola y nodoCabeza pueden ser especificados por su manejadorNodo o por su nombreNodo. ej.

    set n [$g addnode]
    set m [$g addnode]
    $g addedge $n $m label "NM"
    $g addnode N
    $g addnode M
    $g addedge N M label "NM"
El argumento se reconoce como un manejador si es posible y por lo tanto es mejor evitar nombres como "node6" para los nodos. Si existe la posibilidad de conflicto, use findnode para traducir explícitamente de nombres a manejadores. ej. 
    $g addnode "node6"
    $g addnode "node99"
    $g addedge [$g findnode "node6"] [$g findnode "node99"]
Puede haber un número arbitrario de pares nombre/valor de atributo para la arista. Ciertos atributos especiales de arista y valores permitidos se describen en dot(1), pero el programador puede inventar y asignar arbitrariamente valores a atributos adicionales además de estos.
manejadorGrafo addsubgraph ?nombreGrafo? ?nombreAtributo valorAtributo? ?...?

crea un nuevo subgrafo en el grafo y devuelve su manejadorGrafo. Si se omite el nombreGrafo entonces el nombre del subgrafo toma por defecto su manejadorGrafo. Puede haber un número arbitrario de pares nombre/valor de atributo para el subgrafo. Ciertos atributos especiales de grafo y valores permitidos se describen en dot(1), pero el programador puede inventar y asignar arbitrariamente valores a atributos adicionales además de estos. ej.

    set sg [$g addsubgraph dinglefactor 6]
Los clusters, como se describen en dot(1), se crean dando al subgrafo un nombre que comienza con la cadena: "cluster". El cluster puede ser etiquetado usando el atributo label. ej. 
    set cg [$g addsubgraph cluster_A label dongle dinglefactor 6]
manejadorNodo addedge nodoCabeza ?nombreAtributo valorAtributo? ?...?

crea una nueva arista desde el nodo cola identificado por el manejadorNodo hasta el nodoCabeza que puede ser especificado ya sea por manejadorNodo o por nombreNodo (con preferencia a reconocer el argumento como manejador). El grafo en el que se dibuja es el grafo en el que ambos nodos son miembros. Puede haber un número arbitrario de pares nombre/valor de atributo para la arista. Estos atributos de arista y permisos

graphHandle delete
nodeHandle delete
edgeHandle delete

Elimina todas las estructuras de datos asociadas con el grafo, nodo o arista del almacenamiento interno del intérprete. La eliminación de un nodo también resulta en la eliminación de todas las aristas adyacentes a ese nodo. La eliminación de un grafo también resulta en la eliminación de todos los nodos y subgrafos dentro de ese grafo (y por lo tanto, todas las aristas también). El retorno de estos comandos de eliminación es una cadena nula.

graphHandle countnodes
graphHandle countedges

Devuelve el número de nodos o aristas en el grafo.

graphHandle listedges
graphHandle listnodes
graphHandle listnodesrev
graphHandle listsubgraphs
nodeHandle listedges
nodeHandle listinedges
nodeHandle listoutedges
edgeHandle listnodes

Cada uno devuelve una lista de manejadores de grafos, nodos o aristas, según corresponda.

graphHandle findnode nodeName
graphHandle findedge tailnodeName headNodeName
nodeHandle findedge nodeName

Cada uno devuelve el manejador del elemento si se encuentra, o un error si no se encuentra ninguno. Para grafos no estrictos cuando hay múltiples aristas entre dos nodos, findedge devolverá una arista arbitraria del conjunto.

graphHandle showname
nodeHandle showname
edgeHandle showname

Cada uno devuelve el nombre del elemento. Los nombres de las aristas tienen el formato: "a->b" donde "a" y "b" son los nombres de los nodos y el conector "->" indica la dirección de la arista de cola a cabeza. En grafos no dirigidos se utiliza el conector "--".

graphHandle setnodeattributes attributeName attributeValue ?...?
graphHandle setedgeattributes attributeName attributeValue ?...?

Establece uno o más nombres/valores de atributos por defecto que se aplicarán a todos los nodos (aristas) a menos que sean anulados por subgrafos o atributos por nodo (por arista).

graphHandle listnodeattributes
graphHandle listedgeattributes

Devuelve una lista de nombres de atributos.

graphHandle querynodeattributes attributeName ?...?
graphHandle queryedgeattributes attributeName ?...?

Devuelve una lista de valores de atributos por defecto, un valor por cada uno de los nombres de atributos proporcionados con el comando.

graphHandle querynodeattributes attributeName ?...?
graphHandle queryedgeattributes attributeName ?...?

Devuelve una lista de pares de nombres de atributos y valores de atributos por defecto, un par por cada uno de los nombres de atributos proporcionados con el comando.

graphHandle setattributes attributeName attributeValue ?...?
nodeHandle setattributes attributeName attributeValue ?...?
edgeHandle setattributes attributeName attributeValue ?...?

Establece uno o más pares de nombre/valor de atributos para una instancia específica de grafo, nodo o arista.

graphHandle listattributes
nodeHandle listattributes
edgeHandle listattributes

Devuelve una lista de nombres de atributos (los valores de los atributos se proporcionan mediante queryattribute

graphHandle queryattributes attributeName ?...?
nodeHandle queryattributes attributeName ?...?
edgeHandle queryattributes attributeName ?...?

Devuelve una lista de valores de atributos, un valor por cada uno de los nombres de atributos proporcionados con el comando.

graphHandle queryattributevalues attributeName ?...?
nodeHandle queryattributevalues attributeName ?...?
edgeHandle queryattributevalues attributeName ?...?

Devuelve una lista de pares de nombres de atributos y valores de atributos, un valor por cada uno de los nombres de atributos proporcionados con el comando.

graphHandle layout ?dot|neato|circo|twopi|fdp|nop?

Anota el grafo con información de diseño. Este comando toma un grafo abstracto y le añade información de forma y posición de acuerdo con las reglas del motor de diseño para un diseño de grafo estéticamente agradable. Si no se especifica el motor de diseño, por defecto se usará dot para grafos dirigidos y neato en caso contrario. Si se especifica el motor nop, se utilizará la información de diseño del grafo de entrada. El resultado del diseño se almacena como pares de nombre/valor de atributos adicionales en el grafo, los nodos y las aristas. Estos atributos están pensados para ser interpretados por comandos posteriores de write o render.

graphHandle write fileHandle format ?dot|neato|circo|twopi|fdp|nop?

Escribe un grafo al archivo abierto representado por fileHandle en un formato específico. Los formatos posibles son: "ps" "mif" "plain" "dot" "gif" "ismap" Si el diseño aún no se ha realizado, se hará como parte de esta operación utilizando las mismas reglas para seleccionar el motor de diseño que para el comando layout.

graphHandle rendergd gdHandle

Genera una representación de un grafo en una estructura gifImage nueva o existente (ver gdTcl(1) ). Devuelve el gdHandle de la imagen. Si el diseño aún no se ha realizado, se hará como parte de esta operación utilizando las mismas reglas para seleccionar el motor de diseño que para el comando layout.

graphHandle render ?canvas ?dot|neato|circo|twopi|fdp|nop??

Si no se proporciona ningún argumento canvas, render devuelve una cadena de comandos que, al evaluarse, renderizarán el grafo en un lienzo Tk cuyo canvasHandle está disponible en la variable $c

Si se proporciona un argumento canvas, entonces render produce un conjunto de comandos para canvas en lugar de $c.

Si el diseño aún no se ha realizado, se hará como parte de esta operación utilizando las mismas reglas para seleccionar el motor de diseño que para el comando layout.

    #!/usr/local/bin/wish
    package require Tcldot
    set c [canvas .c]
    pack $c
    set g [dotnew digraph rankdir LR]
    $g setnodeattribute style filled color white
    [$g addnode Hello] addedge [$g addnode World!]
    $g layout
    if {[info exists debug]} {
        puts [$g render]         ;# ver qué produce render
    }
    eval [$g render]

Render genera una serie de comandos de lienzo para cada elemento del grafo, por ejemplo, un nodo típicamente consta de dos elementos en el lienzo, uno para la forma y otro para la etiqueta. Los elementos del lienzo se etiquetan automáticamente (Ver canvas(n)) por los comandos generados por render. Las etiquetas tienen una de las dos formas: los elementos de texto se etiquetan con 0<handle> y las formas y líneas se renderizan con 1<handle>.

El etiquetado se puede utilizar para reconocer cuándo un usuario quiere interactuar con un grafo
