TC(8) Linux TC(8)

NOMBRE

tbf - Filtro de cubo de tokens (Token Bucket Filter)

SINOPSIS

tc qdisc ... tbf rate tasa burst bytes/celda ( latency ms | limit bytes ) [ mpu bytes [ peakrate tasa mtu bytes/celda ] ]

burst también se conoce como buffer y maxburst. mtu también se conoce como minburst.

DESCRIPCIÓN

El Filtro de Cubo de Tokens (Token Bucket Filter) es una disciplina de cola (queueing discipline) de clase disponible para el control de tráfico con el comando tc(8).

TBF es un modelador (shaper) puro y nunca programa tráfico. No es conservador de trabajo (non-work-conserving) y puede auto-ralentizarse, aunque haya paquetes disponibles, para asegurar que no se exceda la tasa configurada. Es capaz de modelar hasta 1mbit/s de tráfico normal con una ráfaga mínima ideal, enviando datos exactamente a las tasas configuradas.

Son posibles tasas mucho mayores, pero a costa de perder la ráfaga mínima. En ese caso, los datos se extraen de la cola en promedio a la tasa configurada, pero pueden enviarse mucho más rápido en escalas de tiempo de milisegundos. Debido a las colas adicionales que residen en los adaptadores de red, esto a menudo no es un problema.

ALGORITMO

Como su nombre indica, el tráfico se filtra basándose en el gasto de **tokens**. Los tokens corresponden aproximadamente a bytes, con la restricción adicional de que cada paquete consume algunos tokens, sin importar lo pequeño que sea. Esto refleja el hecho de que incluso un paquete de tamaño cero ocupa el enlace durante algún tiempo.

En el momento de la creación, el TBF se llena con tokens que corresponden a la cantidad de tráfico que se puede enviar en una sola ráfaga. Los tokens llegan a una tasa constante, hasta que el cubo se llena.

Si no hay tokens disponibles, los paquetes se ponen en cola, hasta un límite configurado. El TBF calcula ahora el déficit de tokens y se ralentiza hasta que el primer paquete de la cola pueda ser enviado.

Si no es aceptable enviar paquetes a máxima velocidad, se puede configurar una tasa pico (peakrate) para limitar la velocidad a la que el cubo se vacía. Esta tasa pico se implementa como un segundo TBF con un cubo muy pequeño, para que no haga ráfagas.

Para lograr la perfección, el segundo cubo puede contener solo un paquete, lo que lleva al límite de 1mbit/s mencionado anteriormente.

Este límite se debe al hecho de que el kernel solo puede ralentizarse como mínimo 1 'jiffy', que depende de HZ como 1/HZ. Para un modelado perfecto, solo se puede enviar un paquete por jiffy; para HZ=100, esto significa 100 paquetes de un promedio de 1000 bytes cada uno, lo que corresponde aproximadamente a 1mbit/s.

PARÁMETROS

Vea tc(8) para saber cómo especificar las unidades de estos valores.

limit o latency
Limit es el número de bytes que pueden estar en cola esperando a que haya tokens disponibles. También puede especificar esto de la otra manera estableciendo el parámetro latency, que especifica la cantidad máxima de tiempo que un paquete puede permanecer en el TBF. El último cálculo tiene en cuenta el tamaño del cubo, la tasa y posiblemente la tasa pico (si está establecida). Estos dos parámetros son mutuamente excluyentes.
burst
También conocido como buffer o maxburst. Tamaño del cubo, en bytes. Esta es la cantidad máxima de bytes para los que los tokens pueden estar disponibles instantáneamente. En general, las tasas de modelado más altas requieren un buffer más grande. Para 10mbit/s en Intel, ¡necesita al menos 10kbyte de buffer si quiere alcanzar la tasa configurada!

Si su buffer es demasiado pequeño, los paquetes pueden ser descartados porque llegan más tokens por tick de temporizador de los que caben en su cubo. El tamaño mínimo del buffer se puede calcular dividiendo la tasa por HZ.

Los cálculos de uso de tokens se realizan utilizando una tabla que por defecto tiene una resolución de 8 paquetes. Esta resolución se puede cambiar especificando el tamaño de la **celda** con el burst. Por ejemplo, para especificar un buffer de 6000 bytes con un tamaño de celda de 16 bytes, establezca un burst de 6000/16. Probablemente nunca tendrá que establecer esto. Debe ser una potencia entera de 2.

mpu
Un paquete de tamaño cero no utiliza ancho de banda cero. Para Ethernet, ningún paquete utiliza menos de 64 bytes. La Unidad Mínima de Paquete (Minimum Packet Unit) determina el uso mínimo de tokens (especificado en bytes) para un paquete. Por defecto es cero.
rate
La perilla de velocidad. ¡Vea las observaciones anteriores sobre los límites! Vea tc(8) para las unidades.

Además, si se desea una tasa pico, los siguientes parámetros están disponibles:

peakrate
Tasa máxima de vaciado del cubo. La tasa pico no necesita ser establecida, solo es necesaria si se requiere un modelado perfecto en la escala de milisegundos.
mtu/minburst
Especifica el tamaño del cubo de la tasa pico. Para una precisión perfecta, debería establecerse en el MTU de la interfaz. Si se necesita una tasa pico, pero se acepta cierta ráfaga, este tamaño puede aumentarse. Un minburst de 3000 bytes permite alrededor de 3mbit/s de tasa pico, dados paquetes de 1000 bytes.

Al igual que el tamaño de burst regular, también puede especificar un tamaño de **celda**.

EJEMPLO & USO

Para adjuntar un TBF con una tasa máxima sostenida de 0.5mbit/s, una tasa pico de 1.0mbit/s, un buffer de 5 kilobytes, con un tamaño de cola pre-cubo calculado para que el TBF cause como máximo 70ms de latencia, con comportamiento de tasa pico perfecto, emita:

# tc qdisc add dev eth0 handle 10: root tbf rate 0.5mbit \
burst 5kb latency 70ms peakrate 1mbit \
minburst 1540

Para adjuntar una qdisc interna, por ejemplo sfq, emita:

# tc qdisc add dev eth0 parent 10:1 handle 100: sfq

Sin qdisc interna, la cola TBF actúa como bfifo. Si la qdisc interna se cambia, el límite/latencia ya no será efectivo.
