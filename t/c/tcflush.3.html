DESCRIPCIÓN

Las funciones termios describen una interfaz de terminal general que se proporciona para controlar los puertos de comunicación asíncrona.

La estructura termios

Muchas de las funciones descritas aquí tienen un argumento termios_p que es un puntero a una estructura termios. Esta estructura contiene al menos los siguientes miembros:


tcflag_t c_iflag;      /* modos de entrada */
tcflag_t c_oflag;      /* modos de salida */
tcflag_t c_cflag;      /* modos de control */
tcflag_t c_lflag;      /* modos locales */
cc_t     c_cc[NCCS];   /* caracteres especiales */

Los valores que se pueden asignar a estos campos se describen a continuación. En el caso de los primeros cuatro campos de máscara de bits, las definiciones de algunas de las banderas asociadas que se pueden establecer solo se exponen si se define una macro de prueba de funcionalidad específica (ver feature_test_macros(7)), como se indica entre corchetes ("[]").

En las descripciones a continuación, "no en POSIX" significa que el valor no está especificado en POSIX.1-2001, y "XSI" significa que el valor está especificado en POSIX.1-2001 como parte de la extensión XSI.

Constantes de bandera de c_iflag:

IGNBRK
Ignorar condición BREAK en la entrada.
BRKINT
Si IGNBRK está configurado, un BREAK se ignora. Si no está configurado pero BRKINT está configurado, entonces un BREAK provoca que las colas de entrada y salida se vacíen, y si la terminal es la terminal de control de un grupo de procesos en primer plano, se enviará una señal SIGINT a este grupo de procesos en primer plano. Cuando ni IGNBRK ni BRKINT están configurados, un BREAK se lee como un byte nulo ('\0'), excepto cuando PARMRK está configurado, en cuyo caso se lee como la secuencia \377 \0 \0.
IGNPAR
Ignorar errores de trama y errores de paridad.
PARMRK
Si este bit está configurado, los bytes de entrada con errores de paridad o trama se marcan al pasarse al programa. Este bit solo es significativo cuando INPCK está configurado y IGNPAR no está configurado. La forma en que se marcan los bytes erróneos es con dos bytes precedentes, \377 y \0. Por lo tanto, el programa en realidad lee tres bytes por cada byte erróneo recibido de la terminal. Si un byte válido tiene el valor \377, y ISTRIP (ver abajo) no está configurado, el programa podría confundirlo con el prefijo que marca un error de paridad. Por lo tanto, un byte válido \377 se pasa al programa como dos bytes, \377 \377, en este caso.
Si ni IGNPAR ni PARMRK están configurados, lea un carácter con error de paridad o error de trama como \0.
INPCK
Habilitar la verificación de paridad de entrada.
ISTRIP
Eliminar el octavo bit.
INLCR
Traducir NL a CR en la entrada.
IGNCR
Ignorar retorno de carro en la entrada.
ICRNL
Traducir retorno de carro a nueva línea en la entrada (a menos que IGNCR esté configurado).
IUCLC
(no en POSIX) Mapear caracteres en mayúsculas a minúsculas en la entrada.
IXON
Habilitar control de flujo XON/XOFF en la salida.
IXANY
(XSI) Escribir cualquier carácter reiniciará la salida detenida. (El valor predeterminado es permitir que solo el carácter START reinicie la salida).
IXOFF
Habilitar control de flujo XON/XOFF en la entrada.
IMAXBEL
(no en POSIX) Hacer sonar la campana cuando la cola de entrada está llena. Linux no implementa este bit, y actúa como si siempre estuviera configurado.
IUTF8 (desde Linux 2.6.4)
(no en POSIX) La entrada es UTF8; esto permite que el borrado de caracteres se realice correctamente en modo codificado.

Constantes de bandera de c_oflag:

OPOST
Habilitar procesamiento de salida definido por la implementación.
OLCUC
(no en POSIX) Mapear caracteres en minúsculas a mayúsculas en la salida.
ONLCR
(XSI) Mapear NL a CR-NL en la salida.
OCRNL
Mapear CR a NL en la salida.
ONOCR
No generar CR en la columna 0.
ONLRET
El carácter NL se asume que realiza la función de retorno de carro; la idea del kernel de la columna actual se establece en 0 después de NL y CR.
OFILL
Enviar caracteres de relleno para un retraso, en lugar de usar un retraso temporizado.
OFDEL
El carácter de relleno es ASCII DEL (0177). Si no está configurado, el carácter de relleno es ASCII NUL ('\0'). (No implementado en Linux.)
NLDLY
Máscara de retraso de nueva línea. Los valores son NL0 y NL1. [requiere _BSD_SOURCE o _SVID_SOURCE o _XOPEN_SOURCE]
CRDLY
Máscara de retraso de retorno de carro. Los valores son CR0, CR1, CR2 o CR3. [requiere _BSD_SOURCE o _SVID_SOURCE o _XOPEN_SOURCE]
TABDLY
Máscara de retraso de tabulación horizontal. Los valores son TAB0, TAB1, TAB2, TAB3 (o XTABS, pero ver la sección BUGS). Un valor de TAB3, es decir, XTABS, expande las tabulaciones a espacios (con paradas de tabulación cada ocho columnas). [requiere _BSD_SOURCE o _SVID_SOURCE o _XOPEN_SOURCE]

Máscara de retraso de retroceso. Los valores son BS0 o BS1. (Nunca se ha implementado). [requiere _BSD_SOURCE o _SVID_SOURCE o _XOPEN_SOURCE]
VTDLY
Máscara de retraso de tabulación vertical. Los valores son VT0 o VT1.

c_lflag flag constants:

ISIG
Habilitar señales generadas por caracteres de control.
ICANON
Habilitar modo canónico (edición de línea).
ECHO
Habilitar eco de caracteres de entrada.
ECHOE
(XSI) Si ICANON está configurado, la combinación ERASE (normalmente Control-H, Backspace) borra cada carácter de la línea de entrada, y EWL (normalmente Control-W) borra la palabra hasta el inicio de la palabra. Si ECHOE está configurado, el comportamiento de ERASE es borrar cada carácter de entrada de forma visual (es decir, la salida de ERASE se imprime); si ECHOKE está configurado, la salida de EW se imprime. Si ni ECHOE ni ECHOKE están configurados, el comportamiento de ERASE es borrar y luego imprimir un carácter de retroceso, un espacio y un carácter de retroceso.
ECHONL
(XSI) Si ICANON está configurado, el carácter de nueva línea NL se ecoea.
NOFLSH
(XSI) Deshabilitar el vaciado de colas de entrada/salida al generar señales.
XCASE
(no en POSIX) Si ICANON y XCASE están configurados, las letras mayúsculas se imprimen como minúsculas en la entrada y se convierte a mayúsculas en la salida. Si solo XCASE está configurado, las letras mayúsculas se imprimen como minúsculas en la salida.
TOSTOP
(no en POSIX) Enviar SIGSTOP al proceso en primer plano al intentar escribir en la terminal. Esto se usa para evitar que los trabajos en segundo plano impriman en la pantalla.
ECHOKE
(No en POSIX) Borra la línea de entrada si se configura ICANON. El comportamiento es similar a configurar ECHOE y luego borrar la palabra hasta el principio de la palabra. Linux no implementa este bit.
FLUSH
(No en POSIX) Si está configurado, el carácter de vaciado (véase más abajo) vaciará las colas de entrada y salida.
PENDIN
(XSI) Si está configurado, los caracteres que se han leído pero no se han procesado aún (por ejemplo, al deshabilitar ICANON) se trataran como si se hubieran introducido de nuevo después de que se configure una señal de rearme (por ejemplo, cuando se vuelve a habilitar ICANON).
IEXTEN
(XSI) Habilitar caracteres de control de entrada extendidos (por ejemplo, DSUSP, REPRINT, WERASE).

tcgetattr

La función tcgetattr() obtiene los parámetros de control asociados con el descriptor de archivo fd (que debe referirse a una terminal) y los almacena en la estructura a la que apunta termios_p.

tcsetattr

La función tcsetattr() establece los parámetros de control asociados con el descriptor de archivo fd a partir de la estructura a la que apunta termios_p. El argumento optional_actions especifica cuándo se deben realizar los cambios:

TCSANOW
los cambios surten efecto inmediatamente.
TCSADRAIN
los cambios surten efecto después de que todos los caracteres escritos en el descriptor de archivo fd se hayan transmitido. Este valor debería usarse cuando se cambian los atributos que afectan la transmisión, como la velocidad en baudios.
TCSAFLUSH
los cambios surten efecto después de que todos los caracteres escritos en el descriptor de archivo fd se hayan transmitido, y se descartan todos los caracteres que aún no se han leído de la entrada. Este valor debería usarse cuando se cambian los atributos que afectan la recepción.

La estructura termios_p se pasa como un puntero constante en la llamada a tcsetattr, por lo que el llamador no debe modificar la estructura después de la llamada. En su lugar, se utiliza un puntero no constante para tcgetattr.

tcsendbreak

La función tcsendbreak() envía una condición de BREAK en la terminal especificada por fd. Si duration es cero, envía un BREAK de 0.25 a 0.5 segundos de duración. Si duration es distinto de cero, envía un BREAK cuya duración es de aproximadamente duration * 100 milisegundos. La interpretación de los valores de duración es dependiente de la implementación y puede no ser precisa.

tcdrain

La función tcdrain() espera hasta que todos los caracteres en la cola de salida para el descriptor de archivo fd se hayan transmitido.

tcflush

La función tcflush() descarta información en colas de transmisión o recepción de terminales. El argumento queue_selector especifica qué colas se ven afectadas:

TCIFLUSH
descarta la entrada recibida que no se ha leído.
TCOFLUSH
descarta la salida que no se ha transmitido.
TCIOFLUSH
descarta tanto la entrada recibida que no se ha leído como la salida que no se ha transmitido.

tcflow

La función tcflow() suspende o reanuda la transmisión o recepción de datos en el descriptor de archivo fd. El argumento action especifica la acción a realizar:

TCOOFF
suspende la transmisión de salida.
TCOON
reanuda la transmisión de salida suspendida.
TCIOFF
envía un carácter de detención de flujo (XOFF) para suspender la recepción de entrada.
TCION
envía un carácter de inicio de flujo (XON) para reanudar la recepción de entrada suspendida.

cfmakeraw

La función cfmakeraw() configura la estructura termios_p para un modo "raw" (crudo). En este modo, la entrada no se procesa, la salida tampoco, no se generan señales, y los caracteres de control se deshabilitan. El bit IEXTEN se desactiva y el resto de los bits de control de entrada, salida y local se desactivan. Los bits de control se establecen para obtener una entrada de 8 bits sin paridad y una salida de 8 bits. El bit CS8 se configura, y CSTOPB se desactiva.

cfgetospeed, cfgetispeed

Las funciones cfgetospeed() y cfgetispeed() devuelven la velocidad de salida y entrada respectivamente, tomadas de la estructura termios_p.

cfsetospeed, cfsetispeed, cfsetspeed

Las funciones cfsetospeed() y cfsetispeed() establecen la velocidad de salida y entrada respectivamente, tomadas de la estructura termios_p, al valor speed. El valor B0 colgará la línea.

La función cfsetspeed() es un sinónimo de cfsetospeed().

El valor de speed debe ser uno de los valores definidos previamente (por ejemplo, B9600).

VALOR DE RETORNO

En caso de éxito, la mayoría de estas funciones devuelven 0. Las funciones cfgetispeed() y cfgetospeed() devuelven la velocidad de línea apropiada. En caso de error, devuelven -1 y establecen errno para indicar el error.

ERRORES

EBADF
El descriptor de archivo fd no es válido.
EINTR
Una llamada fue interrumpida por una señal mientras esperaba.
EINVAL
El descriptor de archivo fd no está asociado con una terminal, o el valor de optional_actions, queue_selector, action, o speed no es válido.
ENOTTY
El descriptor de archivo fd no está asociado con una terminal.

ESTÁNDARES

El estándar POSIX.1-2001 y versiones posteriores cubren la mayoría de estas funciones. Las funciones cfmakeraw y cfsetspeed no forman parte de POSIX. La extensión XSI (POSIX.1-2001) cubre algunas banderas adicionales y caracteres de control.

HISTORIA

El estándar POSIX.1 definió originalmente la interfaz termios. BSD introdujo cfmakeraw y las funciones cfget* / cfset* con nombres ligeramente diferentes. Linux implementa la interfaz POSIX.

En versiones anteriores de Linux, cfsetispeed y cfsetospeed solo aceptaban los valores B0 y B9600. Se han ampliado para aceptar todas las velocidades definidas.

BUGS

El estándar POSIX permite que los bits de control de retraso de tabulación (TABDLY) contengan el valor XTABS (que está definido como TAB3). Sin embargo, XTABS tiene un significado adicional: expande las tabulaciones a espacios. El comportamiento de TAB3 es dependiente de la implementación, y en algunos sistemas (incluyendo Linux) TAB3 no expande las tabulaciones a espacios.

El bit IMAXBEL en c_iflag no se implementa en Linux y se actúa como si siempre estuviera configurado.

El bit ECHOKE en c_lflag no se implementa en Linux.

Los valores de duración para tcsendbreak() no siempre son precisos.

Constantes de flags de c_lflag:

ISIG

ICANON

XCASE

En la salida, los caracteres en mayúsculas van precedidos por \\ y los caracteres en minúsculas se convierten a mayúsculas. [requiere _BSD_SOURCE o _SVID_SOURCE o _XOPEN_SOURCE]
ECHO
Hace eco de los caracteres de entrada.
ECHOE
Si ICANON también está activado, el carácter ERASE borra el carácter de entrada anterior, y WERASE borra la palabra anterior.
ECHOK
Si ICANON también está activado, el carácter KILL borra la línea actual.
ECHONL
Si ICANON también está activado, hace eco del carácter NL incluso si ECHO no está activado.
ECHOCTL
(no está en POSIX) Si ECHO también está activado, los caracteres especiales de la terminal distintos de TAB, NL, START y STOP se hacen eco como ^X, donde X es el carácter con código ASCII 0x40 mayor que el carácter especial. Por ejemplo, el carácter 0x08 (BS) se hace eco como ^H. [requiere _BSD_SOURCE o _SVID_SOURCE]
ECHOPRT
(no está en POSIX) Si ICANON y ECHO también están activados, los caracteres se imprimen a medida que se borran. [requiere _BSD_SOURCE o _SVID_SOURCE]
ECHOKE
(no está en POSIX) Si ICANON también está activado, KILL se hace eco borrando cada carácter de la línea, como se especifica en ECHOE y ECHOPRT. [requiere _BSD_SOURCE o _SVID_SOURCE]
DEFECHO
(no está en POSIX) Hace eco solo cuando un proceso está leyendo. (No implementado en Linux.)
FLUSHO
(no está en POSIX; no soportado en Linux) La salida se está vaciando. Este flag se activa/desactiva al escribir el carácter DISCARD. [requiere _BSD_SOURCE o _SVID_SOURCE]
NOFLSH
Deshabilita el vaciado de las colas de entrada y salida al generar señales para los caracteres INT, QUIT y SUSP.
TOSTOP
Envía la señal SIGTTOU al grupo de procesos de un proceso en segundo plano que intenta escribir en su terminal de control.
PENDIN
(no está en POSIX; no soportado en Linux) Todos los caracteres en la cola de entrada se reimprimen cuando se lee el siguiente carácter. ( bash(1) maneja el typeahead de esta manera.) [requiere _BSD_SOURCE o _SVID_SOURCE]
IEXTEN
Habilita el procesamiento de entrada definido por la implementación. Este flag, así como ICANON, deben estar habilitados para que los caracteres especiales EOL2, LNEXT, REPRINT, WERASE sean interpretados, y para que el flag IUCLC sea efectivo.

El array c_cc define los caracteres especiales de la terminal. Los índices simbólicos (valores iniciales) y el significado son:

VDISCARD
(no está en POSIX; no soportado en Linux; 017, SI, Ctrl-O) Alterna: inicia/detiene el descarte de la salida pendiente. Reconocido cuando IEXTEN está activado, y luego no se pasa como entrada.
VDSUSP
(no está en POSIX; no soportado en Linux; 031, EM, Ctrl-Y) Carácter de suspensión retardada (DSUSP): envía la señal SIGTSTP cuando el carácter es leído por el programa del usuario. Reconocido cuando IEXTEN y ISIG están activados, y el sistema soporta control de trabajos, y luego no se pasa como entrada.
VEOF
(004, EOT, Ctrl-D) Carácter de fin de archivo (EOF). Más precisamente: este carácter hace que el búfer tty pendiente se envíe al programa de usuario en espera sin esperar al fin de línea. Si es el primer carácter de la línea, la llamada a read(2) en el programa del usuario devuelve 0, lo que significa fin de archivo. Reconocido cuando ICANON está activado, y luego no se pasa como entrada.
VEOL
(0, NUL) Carácter adicional de fin de línea (EOL). Reconocido cuando ICANON está activado.
VEOL2
(no está en POSIX; 0, NUL) Otro carácter de fin de línea (EOL2). Reconocido cuando ICANON está activado.

Recuperación y cambio de configuración del terminal

tcgetattr() obtiene los parámetros asociados con el objeto al que se refiere *fd*, y los almacena en la estructura *termios* a la que se hace referencia mediante *termios_p*. Esta función puede ser invocada desde un proceso en segundo plano; sin embargo, los atributos del terminal pueden ser modificados posteriormente por un proceso en primer plano.

tcsetattr() establece los parámetros asociados con el terminal (a menos que se requiera soporte del hardware subyacente que no esté disponible) a partir de la estructura *termios* a la que se hace referencia mediante *termios_p*. *optional_actions* especifica cuándo entran en vigor los cambios:

TCSANOW
el cambio ocurre inmediatamente.
TCSADRAIN
el cambio ocurre después de que toda la salida escrita en *fd* haya sido transmitida. Esta opción debe usarse al cambiar parámetros que afectan la salida.
TCSAFLUSH
el cambio ocurre después de que toda la salida escrita en el objeto al que se refiere *fd* haya sido transmitida, y toda la entrada que ha sido recibida pero no leída será descartada antes de que se realice el cambio.

Modo canónico y no canónico

La configuración del flag de canon **ICANON** en *c_lflag* determina si el terminal está operando en modo canónico (**ICANON** establecido) o modo no canónico (**ICANON** no establecido). Por defecto, **ICANON** está establecido.

En modo canónico:

•
La entrada se pone a disposición línea por línea. Una línea de entrada está disponible cuando se escribe uno de los delimitadores de línea (NL, EOL, EOL2; o EOF al inicio de la línea). Excepto en el caso de EOF, el delimitador de línea se incluye en el búfer devuelto por read(2).
•
La edición de línea está habilitada (ERASE, KILL; y si el flag **IEXTEN** está establecido: WERASE, REPRINT, LNEXT). Una llamada a read(2) devuelve como máximo una línea de entrada; si la llamada a read(2) solicitó menos bytes de los que están disponibles en la línea de entrada actual, entonces solo se leen tantos bytes como se solicitaron, y los caracteres restantes estarán disponibles para una futura llamada a read(2).
•
La longitud máxima de línea es de 4096 caracteres (incluido el carácter de nueva línea de terminación); las líneas más largas que 4096 caracteres se truncan. Después de 4095 caracteres, el procesamiento de entrada (por ejemplo, el procesamiento de **ISIG** y **ECHO***) continúa, pero cualquier dato de entrada después de 4095 caracteres hasta (pero sin incluir) cualquier nueva línea de terminación se descarta. Esto asegura que el terminal pueda siempre recibir más entrada hasta que al menos una línea pueda ser leída.

En modo no canónico, la entrada está disponible inmediatamente (sin que el usuario tenga que escribir un carácter delimitador de línea), no se realiza ningún procesamiento de entrada y la edición de línea está deshabilitada. El búfer de lectura solo aceptará 4095 caracteres; esto proporciona el espacio necesario para un carácter de nueva línea si el modo de entrada se cambia a canónico. La configuración de MIN (*c_cc[VMIN]*) y TIME (*c_cc[VTIME]*) determina las circunstancias en las que se completa una llamada a read(2); hay cuatro casos distintos:

MIN == 0, TIME == 0 (lectura de sondeo)
Si hay datos disponibles, read(2) devuelve inmediatamente, con el menor valor entre los bytes disponibles y los bytes solicitados. Si no hay datos disponibles, read(2) devuelve 0.
MIN > 0, TIME == 0 (lectura bloqueante)
read(2) se bloquea hasta que haya disponibles MIN bytes, y devuelve hasta el número de bytes solicitados.
MIN == 0, TIME > 0 (lectura con tiempo de espera)
TIME especifica el límite para un temporizador en décimas de segundo. El temporizador se inicia cuando se llama a read(2). read(2) devuelve ya sea cuando hay al menos un byte de datos disponible, o cuando expira el temporizador. Si el temporizador expira sin que se disponga de ninguna entrada, read(2) devuelve 0. Si ya hay datos disponibles en el momento de la llamada a read(2), la llamada se comporta como si los datos se hubieran recibido inmediatamente después de la llamada.
MIN > 0, TIME > 0 (lectura con tiempo de espera entre bytes)
TIME especifica el límite para un temporizador en décimas de segundo. Una vez que hay disponible un byte inicial de entrada, el temporizador se reinicia después de que se recibe cada byte adicional. read(2) devuelve cuando se cumple alguna de las siguientes condiciones:
•
Se han recibido MIN bytes.
•
El temporizador entre bytes expira.
•
Se han recibido los bytes solicitados por read(2). (POSIX no especifica esta condición de terminación, y en otras implementaciones read(2) no devuelve en este caso).
Dado que el temporizador solo se inicia después de que el byte inicial está disponible, se leerá al menos un byte. Si ya hay datos disponibles en el momento de la llamada a read(2), la llamada se comporta como si los datos se hubieran recibido inmediatamente después de la llamada.

POSIX no especifica si la configuración del flag de estado de archivo **O_NONBLOCK** tiene precedencia sobre la configuración de MIN y TIME. Si **O_NONBLOCK** está establecido, una llamada a read(2) en modo no canónico puede devolver inmediatamente, independientemente de la configuración de MIN o TIME. Además, si no hay datos disponibles, POSIX permite que una llamada a read(2) en modo no canónico devuelva 0, o -1 con *errno* establecido a **EAGAIN**.

Modo bruto (raw)

cfmakeraw() configura el terminal en un modo similar al modo "raw" del antiguo controlador de terminales de la Versión 7: la entrada está disponible carácter por carácter, la eco está deshabilitada y todo el procesamiento especial de los caracteres de entrada y salida del terminal está deshabilitado. Los atributos del terminal se configuran de la siguiente manera:


termios_p->c_iflag &= ~(IGNBRK | BRKINT | PARMRK | ISTRIP
                | INLCR | IGNCR | ICRNL | IXON);
termios_p->c_oflag &= ~OPOST;
termios_p->c_lflag &= ~(ECHO | ECHONL | ICANON | ISIG | IEXTEN);
termios_p->c_cflag &= ~(CSIZE | PARENB);
termios_p->c_cflag |= CS8;

Control de línea

tcsendbreak() transmite una corriente continua de bits de valor cero durante una duración específica, si el terminal está utilizando transmisión de datos serie asíncrona. Si *duration* es cero, transmite bits de valor cero durante al menos 0.25 segundos, y no más de 0.5 segundos. Si *duration* no es cero, envía bits de valor cero durante un período de tiempo indefinido por la implementación.

Si el terminal no está utilizando transmisión de datos serie asíncrona, tcsendbreak() devuelve sin realizar ninguna acción.

tcdrain() espera hasta que toda la salida escrita en el objeto al que se refiere *fd* haya sido transmitida.

tcflush() descarta los datos escritos en el objeto al que se refiere *fd* pero no transmitidos, o los datos recibidos pero no leídos, dependiendo del valor de *queue_selector*:

TCIFLUSH
descarta los datos recibidos pero no leídos.
TCOFLUSH
descarta los datos escritos pero no transmitidos.
TCIOFLUSH
descarta tanto los datos recibidos pero no leídos, como los datos escritos pero no transmitidos.

tcflow() suspende la transmisión o recepción de datos en el objeto al que se refiere *fd*, dependiendo del valor de *action*:

TCOOFF
suspende la salida.
TCOON
reanuda la salida suspendida.
TCIOFF
transmite un carácter STOP, que detiene la transmisión de datos del dispositivo terminal al sistema.
TCION
transmite un carácter START, que inicia la transmisión de datos del dispositivo terminal al sistema.

Por defecto al abrir un archivo de terminal, ni su entrada ni su salida están suspendidas.

Establecer la velocidad a B0 instruye al módem a "colgar". La velocidad de bits real correspondiente a B38400 puede ser modificada con setserial(8).

Las velocidades en baudios de entrada y salida se almacenan en la estructura *termios*.

tcflush(3)

NAME

tcflush - flush terminal I/O buffers

LIBRARY

3 - Standard C Library

SYNOPSIS

#include <termios.h>

int tcflush(int fd, int queueSelector);

DESCRIPTION

The tcflush() function shall discard or flush data read from or written to the object associated with the open file descriptor fd. The action taken is determined by the queueSelector argument, which must be one of the following values:

TCIFLUSH:

Flush all input data that has been received but not yet read.

TCOFLUSH:

Flush all output data that has been transmitted but not yet received by the terminal.

TCIOFLUSH:

Flush all input and output data that has been received but not yet read or transmitted but not yet received by the terminal.

RETURN VALUE

On success, tcflush() shall return 0. On error, it shall return -1 and set errno to indicate the error.

ATTRIBUTES

See attributes(7) for descriptions of the following attributes:

NameAttribute
Interface StabilityUnstable

STANDARDS

POSIX.1-2008.

HISTORY

First introduced in POSIX.1-2001.

NOTES

The tcflush() function is part of the termios interface for controlling asynchronous communications ports.

The termios interface is not available on all systems.

BUGS

None known.
