NOMBRE

tcpflow - grabador de flujos TCP

SINOPSIS

tcpflow [-aBcCDIpsZ] [-b max_bytes] [-d debug_level] [-[eE] scanner] [-f max_fds] [-F[ctTXMkmg]] [-h|--help] [-i iface] [-l archivo1.pcap archivo2.pcap...] [-L semlock] [-m min_bytes] [-o outdir] [-r archivo1.pcap] [-R archivo0.pcap] [-S nombre=valor] [-T[archivo plantilla]] [-U|--relinquish-privileges usuario] [-v|--verbose] [-V|--version] [-w archivo] [-x scanner] [-X archivo.xml] [-z|--chroot directorio] [expresión]

DESCRIPCIÓN

tcpflow es un programa que captura datos transmitidos como parte de conexiones TCP (flujos), y almacena los datos de una manera que es conveniente para el análisis de protocolos o la depuración. En lugar de mostrar información paquete por paquete, tcpflow reconstruye los flujos de datos reales y almacena cada flujo en un archivo separado para análisis posterior. tcpflow entiende los números de secuencia TCP y reconstruirá correctamente los flujos de datos independientemente de las retransmisiones o la entrega desordenada. tcpflow proporciona control sobre los nombres de archivo para la organización automática de conexiones por protocolo, dirección IP o número de conexión, y tiene un sistema sofisticado de plugins para descomprimir conexiones HTTP comprimidas, deshacer la codificación MIME, o llamar a programas proporcionados por el usuario para el post-procesamiento.

Por defecto, tcpflow almacena todos los datos capturados en archivos que tienen nombres de la forma: 

192.168.101.102.02345-010.011.012.013.45103
...donde el contenido del archivo anterior serían datos transmitidos desde el host 192.168.101.102 puerto 2345, al host 10.11.12.13 puerto 45103.

Si desea procesar simplemente unos pocos cientos de miles de paquetes y ver qué tiene, pruebe esto: 

tcpflow -a -o outdir -Fk -r packets.pcap
Esto hará que tcpflow realice (-a) todo el procesamiento, almacene la salida en un directorio llamado outdir, organice la salida en directorios de 1000 conexiones cada uno, y lea su entrada del archivo packets.pcap. Por supuesto, es posible un procesamiento más sofisticado.

OPCIONES

-a
Habilita todo el procesamiento. Igual que -e all.
-B
Forzar salida binaria incluso al imprimir en consola con -C o -c.
-b max_bytes
Especifica el tamaño máximo de un flujo capturado. Cualquier byte más allá de max_bytes desde el primer byte capturado será descartado. El valor por defecto es almacenar un número ilimitado de bytes por flujo. Nota: antes de la versión 1.4, tcpflow solo podía almacenar un máximo de 4GiB por flujo.
-c
Imprimir en consola. Imprime el contenido de los paquetes en stdout a medida que se reciben, sin almacenar ningún dato capturado en archivos (implica -s).
-C
Imprimir en consola sin los detalles de origen y destino del paquete. Imprime el contenido de los paquetes en stdout a medida que se reciben, sin almacenar ningún dato capturado en archivos (implica -s).
-D
La salida de la consola debe ser en hexadecimal.
-d
Nivel de depuración. Establece el nivel de mensajes de depuración impresos en stderr a debug_level. Números más altos producen más mensajes. -d 0 causa una operación completamente silenciosa. -d 1 , el valor por defecto, produce mensajes de estado mínimos. -d 10 produce una salida detallada equivalente a -v. Los números mayores que 10 pueden producir una gran cantidad de información de depuración útil solo para los desarrolladores.
-E name
Deshabilita todos los escáneres y luego habilita el escáner name
-e name
Habilita el escáner name.
-e all
Habilita todos los escáneres. Igual que -a
-e http
Realiza post-procesamiento HTTP ("After" processing). Si el archivo de salida es 
208.111.153.175.00080-192.168.001.064.37314,

Entonces el post-procesamiento creará los archivos: 
208.111.153.175.00080-192.168.001.064.37314-HTTP
208.111.153.175.00080-192.168.001.064.37314-HTTPBODY

Si el HTTPBODY fue comprimido con GZIP, puede obtener un tercer archivo también: 
208.111.153.175.00080-192.168.001.064.37314-HTTPBODY-GZIP

Información adicional sobre estos flujos, como su valor hash MD5, también se escribe en el archivo de informe DFXML.
-e python -S py_path=ruta -S py_module=modulo -S py_function=foo
Post-procesa la carga útil TCP por una función externa de python.

La función python debe tomar un único parámetro de cadena. La función python puede devolver una cadena (de lo contrario, la función no debe devolver nada). La cadena devuelta (si la hay) se escribe en el archivo de informe DFXML dentro de la etiqueta XML <scan_python_result>...</scan_python_result>. Un script python de ejemplo está disponible dentro del código fuente de tcpflow en el directorio python/plugins.

Ejemplo:

    tcpflow -r mi.cap -e python -S py_path=python/plugins -S py_module=samplePlugin -S py_function=sampleFunction
-F[formato]
Especifica el formato para los nombres de archivo de salida.
Especificadores de formato:
c
Añade el contador de conexión a TODOS los nombres de archivo.
t
Antepone a cada nombre de archivo una marca de tiempo Unix (segundos desde la época).
T
Antepone a cada nombre de archivo una marca de tiempo ISO-8601.
X
No genera ningún archivo (aparte del archivo de informe DFXML).
-FM
Incluye el MD5 de cada flujo en el archivo de informe DFXML.
-FX
Suprime completamente la salida de archivos, el archivo de informe DFXML aún se produce.
-Fk
organiza la salida en directorios de 1K
-Fm
organiza la salida en directorios de 1M (2 niveles)
-Fg
organiza la salida en directorios de 1G (3 niveles)
-fmax_fds
Máximo de descriptores de archivo utilizados. Limita el número de descriptores de archivo utilizados por tcpflow a max_fds. Los números más altos utilizan más recursos del sistema, pero generalmente funcionan mejor. Si el sistema operativo subyacente soporta la llamada al sistema setrlimit(), se pedirá al sistema operativo que aplique el límite solicitado. El valor por defecto es que tcpflow utilice el número máximo de descriptores de archivo permitidos por el sistema operativo. La opción -v informará cuántos descriptores de archivo está utilizando tcpflow.
-g
Salida de la información del flujo a la consola en varios colores. (Azul para flujos del cliente al servidor, rojo para flujos del servidor al cliente, verde para flujos indefinidos). Nota: Esta opción era diferente de tcpflow 1.3 (-e) y 1.4.4 (-J).
-h --help
Ayuda. Imprime información de uso y sale.
-hh
Más ayuda. Imprime más información de uso y sale.
-i iface
Nombre de la interfaz. Captura paquetes de la interfaz de red llamada iface. Si no se especifica ninguna interfaz con -i, libpcap usará un valor predeterminado razonable automáticamente.
-I
Almacena las marcas de tiempo de recepción (de paquetes TCP) en un archivo complementario *.findx. Por lo tanto, cada flujo tendrá dos archivos: (1) el archivo habitual que contiene los bytes de carga útil y (2) el archivo de texto que contiene las marcas de tiempo correspondientes. Este último archivo *.findx tiene tres columnas utilizando el carácter pipe '|' como separador: 
    índice-byte|marca-de-tiempo|longitud
La columna índice-byte es la posición dentro del archivo que contiene los bytes de carga útil. La columna marca-de-tiempo representa el número de segundos desde la época como un número de punto flotante. La precisión es de microsegundos, pero también puede ser de nanosegundos en una futura versión de tcpflow. La columna longitud es el número de bytes sucesivos afectados por la marca-de-tiempo y puede incluir varios marcos TCP (paquetes TCP). La extensión findx puede provenir del hecho de que las marcas de tiempo están indexadas por marco.
-L nombre_bloqueo_sem
Especifica que nombre_bloqueo_sem debe usarse como un semáforo Unix para evitar que dos copias diferentes de tcpflow ejecutándose en dos procesos diferentes pero que envían a la misma salida estándar impriman una encima de la otra. Esta es una aplicación de semáforos nombrados de Unix; apuesto a que nunca has visto uno antes.
-l
Trata los siguientes argumentos como nombres de archivo con un comando -r asumido antes de cada uno. Esto te permite leer muchos archivos a la vez con globbing del shell. Por ejemplo, para procesar todos los archivos pcap en el directorio actual, usa esto: 
tcpflow -o out -a -l *.pcap

-m tamaño_min
Fuerza un nuevo archivo de salida de conexión cuando hay un salto en la sesión TCP de tamaño_min bytes o más.
-o directorio_salida
Especifica el directorio de salida donde se escribirán los archivos de transcripción.
-P
Sin purga. Normalmente tcpflow elimina conexiones de la tabla hash después de que la conexión se cierra con un FIN. Esto conserva memoria, pero consume tiempo de CPU adicional. Seleccionar esta opción hace que el `std::tr1::unordered_map` crezca sin límites, como lo hacía tcpflow antes de la versión 1.1. Esto hace que tcpflow se ejecute más rápido si hay menos de 10 millones de conexiones, pero puede llevar a errores de falta de memoria.
-p
Sin modo promiscuo. Normalmente, tcpflow intenta poner la interfaz de red en modo promiscuo antes de capturar paquetes. La opción -p le indica a tcpflow que *no* ponga la interfaz en modo promiscuo. Ten en cuenta que ya podría estar en modo promiscuo por alguna otra razón.
-q
Modo silencioso --- no imprimir advertencias. Actualmente, la única advertencia que imprime tcpflow es una advertencia cuando se crean más de 10.000 archivos, lo que indica que el usuario debería haber proporcionado las opciones -Fk, -Fm o -Fg. Podríamos tener otras advertencias en el futuro.
--renunciar-privilegios=nombre_usuario
Cuando tcpflow se ejecuta como root, esta opción cambia el ID de usuario y el ID de grupo para escribir archivos propiedad de nombre_usuario. El ID de grupo es el primero de la lista de grupos de nombre_usuario. Esta operación se realiza justo después de abrir el dispositivo de captura o justo después de abrir el primer archivo de entrada PCAP. Esta opción no admite archivos de entrada múltiples legibles solo por root, ya que los privilegios de root se descartan después de abrir el primer archivo (por ejemplo, -r acceso-solo-root.pcap -R solo-root.pcap -l solo-root*.pcap). Esta opción tiene el mismo comportamiento que la opción de tcpdump(1) con el mismo nombre --renunciar-privilegios
-r
Leer desde archivo. Lee paquetes del archivo, que fue creado utilizando la opción -w de tcpdump(1). Esta opción puede repetirse cualquier número de veces. Se utiliza la entrada estándar si el archivo es "-". Ten en cuenta que para que esta opción sea útil, se debe usar la opción -s de tcpdump para establecer el snaplen en el MTU de la interfaz (por ejemplo, 1500) mientras se capturan paquetes.
-R
Leer desde un archivo, pero solo para completar flujos TCP. Esta opción se utiliza cuando tcpflow se usa para procesar una serie de archivos que se capturan con el tiempo. Para cada período de tiempo *n*, el archivo archivo(n).pcap debe procesarse con -R archivo(n).pcap, mientras que archivo(n-1).pcap debe procesarse con -r archivo(n-1).pcap.
-Snombre=valor
Establece un parámetro nombre igual a valor para un complemento. Usa -hh para averiguar todos los parámetros que se pueden establecer.
-s
Eliminar no imprimibles. Convierte todos los caracteres no imprimibles al carácter "." antes de imprimir paquetes en la consola o almacenarlos en un archivo.
-T[formato]
Especifica una plantilla arbitraria para los nombres de archivo.
%A
se expande a la dirección IP de origen.
%a
se expande al puerto de origen de la IP.
%B
se expande a la dirección IP de destino.
%b
se expande al puerto de destino de la IP.
%T
se expande a la marca de tiempo en formato ISO8601.
%t
se expande a la marca de tiempo en formato Unix time_t.
%V
se expande a "--" si hay una VLAN presente.
%v
se expande al número de VLAN si hay una VLAN presente.
%C
se expande a "c" si el recuento de conexiones > 0.
%c
se expande al recuento de conexiones si el recuento de conexiones > 0.
%#
siempre se expande al recuento de conexiones.
%N
(número_de_conexión ) % 1000
%K
(número_de_conexión / 1000) % 1000
%M
(número_de_conexión / 1000000) % 1000
%G
(número_de_conexión / 1000000000) % 1000
%%
imprime un "%".

Cuando se utiliza la opción -T, tcpflow ignora las opciones -Fk, -Fm y -Fg. Sin embargo, la opción -T gestiona los '/' dentro del patrón de plantilla de nombres de archivo para crear subdirectorios. Por ejemplo, la siguiente línea creará un árbol de directorios out/IP-origen/puerto-origen/IP-destino/puerto-destino.

    tcpflow -r packets.pcap -o out -T %A/%a/%B/%b/%c%N.flow
-V --version
Imprime el número de versión y sale.
-v --verbose
Operación detallada. Describe detalladamente la operación de tcpflow. Equivalente a -d 10.
-w archivo.pcap
Escribe los paquetes que no fueron procesados en archivo.pcap. Típicamente, estos serán paquetes UDP.
-X archivo.xml
Escribe un informe DFXML en archivo.xml. El archivo contiene un registro de cada conexión TCP, cómo se compiló el programa tcpflow y el ordenador en el que se ejecutó tcpflow. Por defecto, tcpflow escribe el informe DFXML en el archivo report.xml.
-Z
No descomprimir flujos comprimidos con gzip. -K Conservar la estructura pcap aislada por flujo.
expresion
selecciona qué paquetes serán capturados. Si no se proporciona ninguna expresion, se capturarán todos los paquetes de la red. De lo contrario, solo se capturarán los paquetes para los que la expresion sea 'verdadera'.
Para la sintaxis de la expresion, consulta pcap-filter(7).
El argumento expresion se puede pasar a tcpflow como un único argumento del shell, o como múltiples argumentos del shell, lo que sea más conveniente. Generalmente, si la expresión contiene metacaracteres del shell, como barras invertidas para escapar nombres de protocolo, es más fácil pasarla como un único argumento entre comillas en lugar de escapar los metacaracteres del shell. Los argumentos múltiples se concatenan con espacios antes de ser analizados.

Informe DFXML

El informe DFXML es el archivo XML escrito por tcpflow para proporcionar detalles de compilación de tcpflow, argumentos de línea de comandos e información sobre los flujos procesados.

Por defecto, el archivo DFXML se llama report.xml. Pero este nombre de archivo se puede cambiar usando la opción de línea de comandos -X.

El archivo DFXML respeta el esquema DFXML definido por el proyecto https://github.com/dfxml-working-group/dfxml_schema.
Además, tcpflow agrega dos etiquetas XML adicionales, como se ilustra en el siguiente ejemplo:


<tcpflow startime='2017-07-22T00:12:21.962782Z' endtime='2017-07-22T00:12:22.097591Z'
         family='2' mac_daddr='40:3d:78:57:ed:d4' mac_saddr='00:c5:42:d2:cb:f2'
         src_ipn='141.134.34.12' dst_ipn='192.168.0.40' srcport='80' dstport='38797'
         packets='4' len='677' caplen='611' />
<tcpflow:result scanner="python" path="python/plugins" module="samplePlugin"
                function="sampleFunction">bla bla bla</tcpflow:result>

La primera etiqueta XML <tcpflow> proporciona información sobre el flujo capturado. Esta etiqueta debería renombrarse como <tcpflow:cap> en una futura versión para ajustarse mejor al esquema DFXML.

La segunda etiqueta XML <tcpflow:result> recopila los resultados del procesamiento. Por el momento, solo el escáner *python* utiliza esta función.

Los atributos XML de <tcpflow> son:

  • startime Hora de recepción del primer paquete
  • endtime Hora de recepción del último paquete
  • family
  • mac_daddr Dirección MAC de destino del primer paquete (impreso si hay alguno)
  • mac_saddr Dirección MAC de origen del primer paquete (impreso si hay alguno)
  • src_ipn IP de origen
  • dst_ipn IP de destino
  • srcport Puerto fuente TCP
  • dstport Puerto destino TCP

    NAME

    tcpflow

    capture, process, and record network connections

    SYNOPSIS

    tcpflow [ -a ] [ -b bufsiz ] [ -c ] [ -d debuglevel ] [ -e script ] [ -F format ] [ -h ] [ -i interface ] [ -l ] [ -m maxbytes ] [ -o dir ] [ -p ] [ -q ] [ -r file ] [ -s ] [ -t ] [ -v ] [ -w file ] [ -X xmlfile ] [ -Z compressformat ] expression

    DESCRIPTION

    The tcpflow utility captures network traffic, processes it into individual TCP flows, and writes the data from each flow to a separate file. The files are named according to the source and destination IP addresses and ports.

    Data is written to files in the current directory, or in the directory specified by the -o option.

    tcpflow uses the pcap library to capture packets from a network interface or to read them from a saved capture file. It applies the filter specified by the expression argument to select the packets to process.

    OPTIONS

    • -a, --all-applications
      Process all applications, not just those explicitly enabled with -e.
    • -b, --buffer-size bufsiz
      Set the pcap buffer size to bufsiz bytes. Defaults to 1048576.
    • -c, --continue-old-flows
      Continue processing old flows. If tcpflow is restarted, it will try to reopen existing flow files and continue writing to them.
    • -d, --debug-level debuglevel
      Set the debug level to debuglevel. Higher values increase verbosity.
    • -e, --enable-application script
      Enable the application handler specified by script. This can be a built-in handler (e.g., http, smtp, ftp) or a Python script. This option can be specified multiple times.
    • -F, --output-format format
      Set the output format. Supported formats are plaintext (default), hex, and binascii.
    • -h, --help
      Print a help message and exit.
    • -i, --interface interface
      Listen on the specified network interface. If not specified, tcpflow will try to find a suitable interface.
    • -l, --log-failed-flows
      Log flows that encountered errors during processing.
    • -m, --max-bytes maxbytes
      Stop processing after maxbytes bytes have been captured.
    • -o, --output-dir dir
      Write output files to the specified dir.
    • -p, --monitor-passive
      Run in passive mode, do not put the interface into promiscuous mode.
    • -q, --quiet
      Suppress informational messages.
    • -r, --read-file file
      Read packets from file instead of a live network interface.
    • -s, --suppress-zeros
      Do not write zero-filled buffers for missing payload data.
    • -t, --print-ascii
      Print ASCII output for each flow.
    • -v, --verbose
      Increase verbosity.
    • -w, --write-pcap file
      Write all packets captured to file in pcap format.
    • -X, --xml-log xmlfile
      Write a DFXML log of the captured flows to xmlfile.
    • -Z, --compress-program compressformat
      Compress output files using the specified program (e.g., gzip, bzip2, lzma).

    DFXML report

    When the -X option is used, tcpflow writes a Digital Forensics XML (DFXML) report. The report contains information about each captured flow, including:

    • packets Number of packets
    • out_of_order_count Number of times tcpflow has replaced missing payload by zeros in the flow file, for example when capture does not contain the TCP session begin (printed if any)
    • violations Number of protocol violations (printed if any)
    • len Sum of un-truncated length of all packet data (including headers, see https://stackoverflow.com/q/1491660)
    • caplen Sum of captured bytes of all packet data (including headers, printed if different from len)

    The XML attributes of <tcpflow:result> are:

    • scanner Name of the scanner
    • path Directory of the scanner module (printed if relevant)
    • module Module name (printed if relevant, used to indicate the python script)
    • function Function name (printed if relevant, used to indicate the function within the python module)

    EXAMPLES

    To record all packets arriving at or departing from sundown and extract all of the HTTP attachments:

    tcpflow -e http -o outdir host sundown

    To record traffic between helios and either hot or ace and bin the results into 1000 files per directory and calculate the MD5 of each flow:

    tcpflow -X report.xml -e md5 -o outdir -Fk host helios and \( hot or ace \)

    BUGS

    Please send bug reports to simsong@acm.org.

    tcpflow currently does not understand IP fragments. Flows containing IP fragments will not be recorded correctly.
