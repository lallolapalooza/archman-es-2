tclvars(n) Comandos integrados de Tcl tclvars(n)

NOMBRE

argc, argv, argv0, auto_path, env, errorCode, errorInfo, tcl_interactive, tcl_library, tcl_nonwordchars, tcl_patchLevel, tcl_pkgPath, tcl_platform, tcl_precision, tcl_rcFileName, tcl_traceCompile, tcl_traceExec, tcl_wordchars, tcl_version - Variables usadas por Tcl

DESCRIPCIÓN

Las siguientes variables globales son creadas y gestionadas automáticamente por la biblioteca Tcl. Excepto donde se indica a continuación, estas variables normalmente deben ser tratadas como de solo lectura por el código específico de la aplicación y por los usuarios.

auto_path
Si está establecida, debe contener una lista Tcl válida que indique directorios a buscar durante las operaciones de auto-carga (incluyendo archivos de índice de paquetes cuando se usa el manejador predeterminado package unknown). Esta variable se inicializa durante el inicio para contener, en orden: los directorios listados en la variable de entorno TCLLIBPATH, el directorio nombrado por la variable global tcl_library, el directorio padre de tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, los directorios listados en la variable tcl_pkgPath. Ubicaciones adicionales para buscar archivos e índices de paquetes normalmente deben agregarse a esta variable usando lappend.

Existen variables adicionales relacionadas con la gestión de paquetes. Se detallan más aspectos en la sección VARIABLES de la página del manual library.

env
Esta variable es mantenida por Tcl como un array cuyos elementos son las variables de entorno del proceso. Leer un elemento devolverá el valor de la variable de entorno correspondiente. Establecer un elemento del array modificará la variable de entorno correspondiente o creará una nueva si aún no existe. Desestablecer un elemento de env eliminará la variable de entorno correspondiente. Los cambios en el array env afectarán el entorno que se pasa a los hijos mediante comandos como exec. Si todo el array env se desestablece, entonces Tcl dejará de monitorizar los accesos a env y no actualizará las variables de entorno.

En Windows, las variables de entorno PATH y COMSPEC en cualquier capitalización se convierten automáticamente a mayúsculas. Por ejemplo, la variable PATH podría ser exportada por el sistema operativo como "path", "Path", "PaTh", etc., lo que haría que el código Tcl, de otro modo sencillo, tenga que soportar muchos casos especiales. Todas las demás variables de entorno heredadas por Tcl se dejan sin modificar. Establecer una variable de array env a vacía es lo mismo que desestablecerla, ya que este es el comportamiento del sistema operativo Windows subyacente. Cabe señalar que depender de una variable de entorno existente y vacía no funcionará en Windows y se desaconseja para uso multiplataforma.

Los siguientes elementos de env son especiales para Tcl:

env(HOME)
Esta variable de entorno, si está establecida, indica la ubicación del directorio considerado como el directorio personal del usuario actual, y al que se cambiará al invocar cd sin argumentos o solo con "~" como argumento. La mayoría de las plataformas la establecen correctamente por defecto; normalmente no necesita ser establecida por código de usuario.
env(TCL_LIBRARY)
Si está establecida, especifica la ubicación del directorio que contiene los scripts de biblioteca (el valor de esta variable se asignará a la variable tcl_library y, por lo tanto, será devuelto por el comando info library). Si esta variable no está establecida, se utiliza un valor predeterminado.

¡Nota que esta variable de entorno *no* debería ser establecida normalmente!

env(TCLLIBPATH)
Si está establecida, debe contener una lista Tcl válida que indique directorios a buscar durante las operaciones de auto-carga. Los directorios deben ser especificados en formato Tcl, usando "/" como separador de ruta, independientemente de la plataforma. Esta variable solo se usa al inicializar la variable auto_path.
env(TCL_TZ), env(TZ)
Estas especifican la zona horaria predeterminada utilizada para analizar y formatear horas y fechas en el comando clock. En muchas plataformas, la variable de entorno TZ es configurada por el sistema operativo.
env(LC_ALL), env(LC_MESSAGES), env(LANG)
Estas variables de entorno son utilizadas por el paquete msgcat para determinar qué localización usar para formatear mensajes.
env(TCL_INTERP_DEBUG_FRAME)
Si existe, tiene el mismo efecto que ejecutar interp debug {} -frame 1 como el primer comando de cada nuevo intérprete Tcl.
errorCode
Esta variable contiene el valor de la opción de retorno -errorcode establecida por el error más reciente ocurrido en este intérprete. Este valor de lista representa información adicional sobre el error en un formato que es fácil de procesar con programas. El primer elemento de la lista identifica una clase general de errores y determina el formato del resto de la lista. Los siguientes formatos para las opciones de retorno -errorcode son utilizados por el núcleo de Tcl; las aplicaciones individuales pueden definir formatos adicionales.
ARITH código mensaje
Este formato se usa cuando ocurre un error aritmético (por ejemplo, un intento de dividir cero entre cero en el comando expr). código identifica el error preciso y mensaje proporciona una descripción legible del error. código será DIVZERO (por un intento de dividir por cero), DOMAIN (si un argumento está fuera del dominio de una función, como acos(-3)), IOVERFLOW (por desbordamiento de enteros), OVERFLOW (por desbordamiento de punto flotante), o UNKNOWN (si la causa del error no puede ser determinada).

La detección de estos errores depende en parte del hardware subyacente y las bibliotecas del sistema.

CHILDKILLED pid nombre_señal mensaje
Este formato se usa cuando un proceso hijo ha sido terminado debido a una señal. El elemento pid será el identificador del proceso (en decimal). El elemento nombre_señal será el nombre simbólico de la señal que causó la terminación del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGPIPE. El elemento mensaje será un breve mensaje legible que describe la señal, como "escritura en tubería sin lectores" para SIGPIPE.
CHILDSTATUS pid código
Este formato se usa cuando un proceso hijo ha terminado con un estado de salida distinto de cero. El elemento pid será el identificador del proceso (en decimal) y el elemento código será el código de salida devuelto por el proceso (también en decimal).
CHILDSUSP pid nombre_señal mensaje
Este formato se usa cuando un proceso hijo ha sido suspendido debido a una señal. El elemento pid será el identificador del proceso, en decimal. El elemento nombre_señal será el nombre simbólico de la señal que causó la suspensión del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGTTIN. El elemento mensaje será un breve mensaje legible que describe la señal, como "lectura de tty en segundo plano" para SIGTTIN.
NONE
Este formato se usa para errores en los que no hay información adicional disponible para un error aparte del mensaje devuelto con el error. En estos casos, la opción de retorno -errorcode consistirá en una lista que contiene un solo elemento cuyo contenido es NONE.
POSIX nombreErr mensaje
Si el primer elemento es POSIX, entonces el error ocurrió durante una llamada al kernel POSIX. El elemento nombreErr contendrá el nombre simbólico del error que ocurrió, como ENOENT; este será uno de los valores definidos en el archivo de inclusión errno.h. El elemento mensaje
errorInfo
Esta variable contiene una cadena de texto que representa el rastreo de pila de Tcl del último error que ocurrió. Si el error fue causado por un script, entonces la cadena contendrá información sobre los comandos que se estaban ejecutando en el momento del error. Si el error se originó en el código C de Tcl (por ejemplo, un error de asignación de memoria), entonces la cadena contendrá información de depuración que puede ser útil para el desarrollador de Tcl. La información en errorInfo es similar a la disponible con el comando catch, pero está disponible en un nivel más bajo. Tcl no limpia automáticamente el valor de errorInfo; se debe borrar explícitamente (por ejemplo, asignando una cadena vacía a ella) después de que el error haya sido manejado.
tcl_interactive
Este variable booleana es 1 si el intérprete Tcl está siendo ejecutado de forma interactiva (es decir, si la entrada proviene de un terminal), y 0 en caso contrario. Esta variable se establece durante la inicialización de Tcl, pero puede ser modificada por el usuario. Puede ser útil para controlar el comportamiento del script Tcl, como la impresión de mensajes de bienvenida o la espera de entrada del usuario.
tcl_library
Esta variable de solo lectura contiene la ruta al directorio que contiene la biblioteca de scripts de Tcl (incluyendo comandos y módulos). Tcl utiliza esta ruta para encontrar archivos de biblioteca cuando se utilizan comandos como source o package require. El valor de esta variable se inicializa durante el inicio de Tcl, basándose en la ubicación de los archivos ejecutables de Tcl o en la variable de entorno TCL_LIBRARY.
tcl_nonwordchars
Esta variable contiene un conjunto de caracteres que Tcl considera no constituyentes de una "palabra" para fines de análisis de texto. Se utiliza principalmente para la división de palabras en comandos como string split y para la delimitación de tokens en el análisis de Tcl. Los caracteres en esta variable se añaden a los caracteres que ya se consideran separadores de palabras (como espacios en blanco).
tcl_patchLevel
Esta variable de solo lectura contiene una cadena que representa el nivel de parche de la versión de Tcl que se está ejecutando. Por ejemplo, podría ser "8.6.8". Es útil para determinar la versión exacta de Tcl utilizada por un script o aplicación.
tcl_pkgPath
Esta variable contiene una lista de directorios que Tcl utiliza para buscar archivos de índice de paquetes (por ejemplo, tclIndex) cuando se requiere un paquete. Se inicializa durante el inicio de Tcl y puede ser modificada por el usuario para incluir directorios adicionales donde se almacenan los paquetes. Sin embargo, se recomienda añadir directorios a auto_path en su lugar.
tcl_platform
Esta variable de solo lectura contiene una cadena de texto que describe la plataforma subyacente en la que se está ejecutando Tcl. El formato exacto puede variar, pero típicamente incluye información sobre el sistema operativo, la arquitectura del procesador y la versión de Tcl. Por ejemplo, podría ser "unix" o "windows".
tcl_precision
Esta variable controla el número de dígitos significativos utilizados en la representación de cadenas de números de punto flotante y en los resultados de operaciones de punto flotante. Su valor predeterminado es 12. Cambiar este valor puede afectar la precisión de los cálculos de punto flotante y la representación de los resultados.
tcl_rcFileName
Esta variable contiene el nombre del archivo de inicialización que Tcl busca al comenzar una sesión interactiva. Si el intérprete Tcl está configurado para ejecutar un archivo de inicialización, su nombre se almacena en esta variable. Este archivo puede contener comandos Tcl que se ejecutan automáticamente al inicio, como la configuración de variables o la carga de bibliotecas.
tcl_traceCompile
Esta variable se utiliza para habilitar o deshabilitar el rastreo de la compilación de scripts Tcl en código bytecode. Si se establece en 1, Tcl registrará información sobre el proceso de compilación. Esto puede ser útil para depurar o analizar el rendimiento de los scripts Tcl.
tcl_traceExec
Similar a tcl_traceCompile, esta variable se utiliza para habilitar o deshabilitar el rastreo de la ejecución de código bytecode Tcl. Si se establece en 1, Tcl registrará información sobre la ejecución del código compilado. Esto puede ser útil para depurar o analizar el rendimiento de los scripts Tcl.
tcl_wordchars
Esta variable contiene un conjunto de caracteres que Tcl considera que forman parte de una "palabra" para fines de análisis de texto. Se utiliza principalmente para la división de palabras en comandos como string split y para la delimitación de tokens en el análisis de Tcl. Los caracteres en esta variable se añaden a los caracteres que ya se consideran constituyentes de una palabra (como letras y números).
tcl_version
Esta variable de solo lectura contiene una cadena que representa la versión de Tcl que se está ejecutando. Por ejemplo, podría ser "8.6". Es útil para determinar la versión de Tcl utilizada por un script o aplicación y para garantizar la compatibilidad.

errorInfo
Esta variable contiene el valor de la opción de retorno -errorinfo establecida por el error más reciente ocurrido en este intérprete. Este valor de cadena contendrá una o más líneas que identifican los comandos y procedimientos Tcl que se estaban ejecutando cuando ocurrió el error más reciente. Su contenido toma la forma de un rastreo de pila que muestra los diversos comandos anidados de Tcl que se habían invocado en el momento del error.
tcl_library
Esta variable contiene el nombre de un directorio que contiene la biblioteca del sistema de scripts de Tcl, como los utilizados para la carga automática. El valor de esta variable se devuelve mediante el comando info library. Consulte la entrada del manual library para obtener detalles sobre las instalaciones proporcionadas por la biblioteca de scripts de Tcl. Normalmente, cada aplicación o paquete tendrá su propia biblioteca de scripts específica de la aplicación además de la biblioteca de scripts de Tcl; cada aplicación debe establecer una variable global con un nombre como $app_library (donde app es el nombre de la aplicación) para contener el nombre de archivo de red del directorio de la biblioteca de esa aplicación. El valor inicial de tcl_library se establece cuando se crea un intérprete buscando en varios directorios diferentes hasta que se encuentra uno que contiene un script de inicio de Tcl apropiado. Si la variable de entorno TCL_LIBRARY existe, entonces se verifica primero el directorio que nombra. Si TCL_LIBRARY no está configurada o no se refiere a un directorio apropiado, Tcl verifica varios otros directorios basándose en una ubicación predeterminada compilada, la ubicación del binario que contiene la aplicación y el directorio de trabajo actual.
tcl_patchLevel
Cuando se crea un intérprete, Tcl inicializa esta variable para contener una cadena que indica el nivel de parche actual para Tcl, como 8.4.16 para Tcl 8.4 con los primeros dieciséis parches oficiales, o 8.5b3 para la tercera versión beta de Tcl 8.5. El valor de esta variable se devuelve mediante el comando info patchlevel.
tcl_pkgPath
Esta variable contiene una lista de directorios que indican dónde se instalan normalmente los paquetes. No se utiliza en Windows. Típicamente contiene una o dos entradas; si contiene dos entradas, la primera es normalmente un directorio para paquetes dependientes de la plataforma (por ej., binarios de bibliotecas compartidas) y la segunda es normalmente un directorio para paquetes independientes de la plataforma (por ej., archivos de script). Típicamente, un paquete se instala como un subdirectorio de una de las entradas en la variable tcl_pkgPath. Los directorios en la variable tcl_pkgPath se incluyen por defecto en la variable auto_path, por lo que se buscan automáticamente ellos y sus subdirectorios inmediatos en busca de paquetes durante los comandos package require. Nota: tcl_pkgPath no está destinado a ser modificado por la aplicación. Su valor se agrega a auto_path al inicio; los cambios en tcl_pkgPath no se reflejan en auto_path. Si desea que Tcl busque directorios adicionales para paquetes, debe agregar los nombres de esos directorios a auto_path, no a tcl_pkgPath.
tcl_platform
Esta es una matriz asociativa cuyos elementos contienen información sobre la plataforma en la que se está ejecutando la aplicación, como el nombre del sistema operativo, su número de versión actual y el conjunto de instrucciones de la máquina. Los elementos que se enumeran a continuación siempre estarán definidos, pero pueden tener cadenas vacías como valores si Tcl no pudo recuperar ninguna información relevante. Además, las extensiones y las aplicaciones pueden agregar valores adicionales a la matriz. Los elementos predefinidos son:
byteOrder
El orden de bytes nativo de esta máquina: littleEndian o bigEndian.
debug
Si esta variable existe, el intérprete se compiló y enlazó con un tiempo de ejecución de C habilitado para depuración. Esta variable solo existirá en Windows, por lo que los escritores de extensiones pueden especificar qué paquete cargar dependiendo de la biblioteca de tiempo de ejecución de C que esté en uso. Esto no es una indicación de que este núcleo contenga símbolos.
engine
El nombre de la implementación del lenguaje Tcl. Cuando el intérprete se crea por primera vez, esto siempre se establece en la cadena Tcl.
machine
El conjunto de instrucciones ejecutado por esta máquina, como intel, PPC, 68k o sun4m. En máquinas UNIX, este es el valor devuelto por uname -m.
os
El nombre del sistema operativo que se ejecuta en esta máquina, como Windows NT o SunOS. En máquinas UNIX, este es el valor devuelto por uname -s.
osVersion
El número de versión del sistema operativo que se ejecuta en esta máquina. En máquinas UNIX, este es el valor devuelto por uname -r.
pathSeparator
El carácter que debe usarse para dividir las variables de entorno tipo PATH en su lista correspondiente de nombres de directorios.
platform
Ya sea windows o unix. Esto identifica el entorno operativo general de la máquina.
pointerSize
Esto da el tamaño del puntero nativo de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(void*) en C.)
threaded
Si esta variable existe, el intérprete se compiló con hilos habilitados.
user
Esto identifica al usuario actual basándose en la información de inicio de sesión disponible en la plataforma. Este valor proviene de las llamadas del sistema getuid() y getpwuid() en Unix, y el valor de la llamada del sistema GetUserName() en Windows.
wordSize
Esto da el tamaño de la palabra nativa de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(long) en C.)
tcl_precision
Esta variable controla el número de dígitos a generar al convertir valores de punto flotante a cadenas. Su valor predeterminado es 0. Las aplicaciones no deben cambiar este valor; se proporciona para compatibilidad con código heredado.
El valor predeterminado de 0 es especial, lo que significa que Tcl debe convertir números usando la menor cantidad de dígitos posible sin dejar de distinguir cualquier número de punto flotante de sus vecinos más cercanos. Difiere de usar un valor arbitrariamente alto para tcl_precision en que un número inexacto como 1.4 se convertirá como 1.4 en lugar de 1.3999999999999999 aunque este último esté más cerca del valor exacto del número binario.
Si tcl_precision no es cero, entonces cuando Tcl convierte un número de punto flotante, crea una representación decimal de como máximo tcl_precision dígitos significativos; el resultado puede ser más corto si el resultado más corto representa el número original exactamente. Si no existe un resultado de como máximo tcl_precision dígitos que sea una representación exacta del número original, se elige el que esté más cerca del número original. Si el número original se encuentra precisamente entre dos representaciones decimales igualmente precisas, se elige la que tenga un valor par para el dígito menos significativo; por ejemplo, si tcl_precision es 3, entonces 0.3125 se convertirá a 0.312, no a 0.313, mientras que 0.6875 se convertirá a 0.688, no a 0.687. Se eliminan los ceros finales que queden.
un valor de tcl_precision de 17 dígitos es "perfecto" para punto flotante IEEE, ya que permite que los valores de doble precisión se conviertan a cadenas y de vuelta a binario sin pérdida de información. Por esta razón, a menudo se ve como un valor en código heredado que debe ejecutarse en versiones de Tcl anteriores a 8.5. Ya no se recomienda; como se señaló anteriormente, un valor cero es el método preferido.
Todos los intérpretes en un hilo comparten un único valor de tcl_precision: cambiarlo en un intérprete afectará a todos los demás intérpretes. A los intérpretes seguros no se les permite modificar la variable.
Los valores válidos para tcl_precision van de 0 a 17.
tcl_rcFileName
Esta variable se utiliza durante la inicialización para indicar el nombre de un archivo de inicio específico del usuario. Si lo establece la inicialización específica de la aplicación, el código de inicio de Tcl verificará la existencia de este archivo y lo fuenteará si existe. Por ejemplo, para wish la variable se establece en ~/.wishrc para Unix y ~/wishrc.tcl para Windows.
tcl_traceCompile
El valor de esta variable se puede establecer para controlar cuánta información de rastreo se muestra durante la compilación de bytecode. Por defecto, tcl_traceCompile es cero y no se muestra información. Establecer tcl_traceCompile en 1 genera un resumen de una línea en stdout cada vez que se compila un procedimiento o un comando de nivel superior. Establecerlo en 2 genera una lista detallada en stdout de las instrucciones de bytecode emitidas durante cada compilación. Esta variable es útil para rastrear posibles problemas con el compilador de Tcl.
Esta variable y funcionalidad solo existen si TCL_COMPILE_DEBUG se definió durante la compilación de Tcl.

NAME

tclvars - Tcl global variables

DESCRIPTION

Tcl provides a number of global variables that can be used to query and control the Tcl environment.

tcl_traceExec
El valor de esta variable se puede establecer para controlar cuánta información de rastreo se muestra durante la ejecución del código de bytes. Por defecto, tcl_traceExec es cero y no se muestra información. Establecer tcl_traceExec a 1 genera un rastreo de una línea en stdout en cada llamada a un procedimiento de Tcl. Establecerlo a 2 genera una línea de salida cada vez que se invoca cualquier comando de Tcl que contenga el nombre del comando y sus argumentos. Establecerlo a 3 produce un rastreo detallado que muestra el resultado de la ejecución de cada instrucción de código de bytes. Tenga en cuenta que cuando tcl_traceExec es 2 o 3, comandos como set e incr que han sido completamente reemplazados por una secuencia de instrucciones de código de bytes no se muestran. Establecer esta variable es útil para rastrear posibles problemas con el compilador e intérprete de código de bytes.
Esta variable y funcionalidad solo existen si TCL_COMPILE_DEBUG se definió durante la compilación de Tcl.
tcl_wordchars
El valor de esta variable es una expresión regular que se puede establecer para controlar qué se consideran caracteres de “palabra”, para instancias como seleccionar una palabra haciendo doble clic en el texto en Tk. Depende de la plataforma. En Windows, por defecto es \S, lo que significa cualquier cosa que no sea un espacio Unicode. De lo contrario, por defecto es \w, que es cualquier carácter de palabra Unicode (número, letra o guion bajo).
tcl_nonwordchars
El valor de esta variable es una expresión regular que se puede establecer para controlar qué se consideran caracteres de “no palabra”, para instancias como seleccionar una palabra haciendo doble clic en el texto en Tk. Depende de la plataforma. En Windows, por defecto es \s, lo que significa cualquier espacio Unicode. De lo contrario, por defecto es \W, que es cualquier cosa que no sea un carácter de palabra Unicode (número, letra o guion bajo).
tcl_version
Cuando se crea un intérprete, Tcl inicializa esta variable para que contenga el número de versión de esta versión de Tcl en el formato x.y. Los cambios en x representan cambios importantes con probables incompatibilidades y los cambios en y representan pequeñas mejoras y correcciones de errores que conservan la compatibilidad hacia atrás. El valor de esta variable es devuelto por el comando info tclversion.

OTHER GLOBAL VARIABLES

Las siguientes variables solo están garantizadas que existen en los ejecutables tclsh y wish; la biblioteca Tcl no las define por sí misma, pero muchos entornos Tcl sí lo hacen.

argc
El número de argumentos para tclsh o wish.
argv
Lista de Tcl de argumentos para tclsh o wish.
argv0
El script que tclsh o wish comenzó a ejecutar (si se especificó) o de lo contrario el nombre por el cual se invocó tclsh o wish.
tcl_interactive
Contiene 1 si tclsh o wish se está ejecutando interactivamente (no se especificó ningún script y la entrada estándar es un dispositivo tipo terminal), 0 de lo contrario.

EXAMPLES

Para agregar un directorio a la colección de ubicaciones buscadas por package require, por ejemplo, debido a algunos paquetes específicos de la aplicación que se utilizan, es necesario actualizar la variable auto_path:

lappend ::auto_path [file join [pwd] "theLibDir"]

Una forma simple, aunque no muy robusta, de manejar argumentos de línea de comandos de la forma “-foo 1 -bar 2” es cargarlos en una matriz después de haber cargado primero la configuración predeterminada:

array set arguments {-foo 0 -bar 0 -grill 0}
array set arguments $::argv
puts "foo is $arguments(-foo)"
puts "bar is $arguments(-bar)"
puts "grill is $arguments(-grill)"

La variable global argv0 se puede usar (en conjunto con el comando info script) para determinar si el script actual se está ejecutando como el script principal o se está cargando como una biblioteca. Esto es útil porque permite que un solo script se use tanto como biblioteca como demostración de esa biblioteca:

if {$::argv0 eq [info script]} {
