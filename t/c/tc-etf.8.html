NOMBRE

ETF - Cola de prioridad Earliest TxTime First (ETF)

SINOPSIS

tc qdisc ... dev dev parent classid [ handle major: ] etf clockid clockid [ delta delta_nsecs ] [ deadline_mode ] [ offload ]

DESCRIPCIÓN

La cola de prioridad ETF (Earliest TxTime First) permite a las aplicaciones controlar el instante en que un paquete debe ser extraído de la capa de control de tráfico hacia el dispositivo de red. Si se configura offload y es compatible con la tarjeta de interfaz de red, también controlará cuándo salen los paquetes del controlador de red.

ETF logra esto almacenando en búfer los paquetes hasta un tiempo configurable antes de su tiempo de transmisión (es decir, txtime o deadline), lo que se puede configurar mediante la opción delta.

La cola de prioridad utiliza internamente un árbol rb para que los paquetes estén siempre "ordenados" por su txtime y se extraigan siguiendo el txtime (siguiente) más temprano primero.

Se basa en la opción de socket SO_TXTIME y en el campo CMSG SCM_TXTIME en cada paquete para configurar el comportamiento de los sockets dependientes del tiempo: el clockid que se utilizará como referencia, si el modo esperado de txtime para ese socket es el modo deadline o estricto, y si se deben informar las caídas de paquetes en la cola de errores del socket. Consulte socket(7) para obtener más información.

La cola de prioridad etf descartará cualquier paquete con un txtime en el pasado, o si un paquete expira mientras espera ser extraído.

Esta disciplina de cola está destinada a ser utilizada por aplicaciones TSN (Time Sensitive Networking), y expone una funcionalidad de modelado de tráfico que comúnmente es documentada como "Launch Time" o "Time-Based Scheduling" por los fabricantes y la documentación de los controladores de red.

ETF está pensado para ser instalado bajo otra cola de prioridad que mapea flujos de paquetes a clases de tráfico; un ejemplo es mqprio(8).

PARÁMETROS

clockid

Especifica el reloj que será utilizado por el temporizador interno de la cola de prioridad para medir el tiempo y programar eventos. La cola de prioridad espera que los paquetes que pasen por ella utilicen este mismo clockid como referencia de sus marcas de tiempo txtime. Descartará los paquetes provenientes de sockets que no cumplan con eso.

Para más información sobre tiempo y relojes en Linux, por favor consulte time(7) y clock_gettime(3).

delta

Después de encolar o desencolar un paquete, la cola de prioridad programará su próximo tiempo de activación para el siguiente txtime menos este valor delta. Esto significa que delta puede ser utilizado como un factor de corrección para la latencia del programador de un sistema. Este valor debe ser especificado en nanosegundos. El valor predeterminado es 0 nanosegundos.
deadline_mode

Cuando se establece deadline_mode, la cola de prioridad manejará txtime con una semántica diferente, cambiando de un tiempo de transmisión 'estricto' a una fecha límite (deadline). En la práctica, esto significa que durante el flujo de extracción, etf(8) establecerá el txtime del paquete que se está extrayendo a 'ahora'. El valor predeterminado es que esta opción esté deshabilitada.
offload

Cuando se establece offload, etf(8) intentará configurar la interfaz de red para habilitar la arbitraje de transmisión basada en tiempo en el controlador. Esta característica se conoce comúnmente como "Launch Time" o "Time-Based Scheduling" en la documentación de los controladores de red. El valor predeterminado es que esta opción esté deshabilitada.
skip_sock_check

etf(8) actualmente descarta cualquier paquete que no tenga un socket asociado o si el socket no tiene la opción de socket SO_TXTIME establecida. Sin embargo, esto no funcionará si el launchtime es establecido por otra entidad dentro del kernel (por ejemplo, alguna otra cola de prioridad). Establecer skip_sock_check omitirá la verificación de un socket asociado con el paquete.

EJEMPLOS

ETF se utiliza para hacer cumplir una Calidad de Servicio. Controla cuándo debe extraerse y transmitirse cada paquete, y puede usarse para limitar la tasa de datos de una clase de tráfico. Para separar los paquetes en clases de tráfico, el usuario puede elegir mqprio(8) y configurarlo de la siguiente manera:

# tc qdisc add dev eth0 handle 100: parent root mqprio num_tc 3 \
	map 2 2 1 0 2 2 2 2 2 2 2 2 2 2 2 2 \
	queues 1@0 1@1 2@2 \
	hw 0

Para reemplazar la disciplina de cola actual por ETF en la clase de tráfico número 0, ejecute:

# tc qdisc replace dev eth0 parent 100:1 etf \
	clockid CLOCK_TAI delta 300000 offload

Con las opciones anteriores, etf se configurará para usar CLOCK_TAI como su clockid_t, programará paquetes 300 us antes de su txtime y habilitará la funcionalidad en la tarjeta de interfaz de red. El modo deadline no se configurará para este modo.
