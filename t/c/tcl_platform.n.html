tclvars(n) Tcl Built-In Commands tclvars(n)

NAME

argc, argv, argv0, auto_path, env, errorCode, errorInfo, tcl_interactive, tcl_library, tcl_nonwordchars, tcl_patchLevel, tcl_pkgPath, tcl_platform, tcl_precision, tcl_rcFileName, tcl_traceCompile, tcl_traceExec, tcl_wordchars, tcl_version - Variables used by Tcl

DESCRIPTION

The following global variables are created and managed automatically by the Tcl library. Except where noted below, these variables should normally be treated as read-only by application-specific code and by users.

auto_path
If set, then it must contain a valid Tcl list giving directories to search during auto-load operations (including for package index files when using the default package unknown handler). This variable is initialized during startup to contain, in order: the directories listed in the TCLLIBPATH environment variable, the directory named by the tcl_library global variable, the parent directory of tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, the directories listed in the tcl_pkgPath variable. Additional locations to look for files and package indices should normally be added to this variable using lappend.

Additional variables relating to package management exist. More details are listed in the VARIABLES section of the library manual page.

env
This variable is maintained by Tcl as an array whose elements are the environment variables for the process. Reading an element will return the value of the corresponding environment variable. Setting an element of the array will modify the corresponding environment variable or create a new one if it does not already exist. Unsetting an element of env will remove the corresponding environment variable. Changes to the env array will affect the environment passed to children by commands like exec. If the entire env array is unset then Tcl will stop monitoring env accesses and will not update environment variables.

Under Windows, the environment variables PATH and COMSPEC in any capitalization are converted automatically to upper case. For instance, the PATH variable could be exported by the operating system as “path”, “Path”, “PaTh”, etc., causing otherwise simple Tcl code to have to support many special cases. All other environment variables inherited by Tcl are left unmodified. Setting an env array variable to blank is the same as unsetting it as this is the behavior of the underlying Windows OS. It should be noted that relying on an existing and empty environment variable will not work on Windows and is discouraged for cross-platform usage.

The following elements of env are special to Tcl:

env(HOME)
This environment variable, if set, gives the location of the directory considered to be the current user's home directory, and to which a call of cd without arguments or with just “~” as an argument will change into. Most platforms set this correctly by default; it does not normally need to be set by user code.
env(TCL_LIBRARY)
If set, then it specifies the location of the directory containing library scripts (the value of this variable will be assigned to the tcl_library variable and therefore returned by the command info library). If this variable is not set then a default value is used.

Note that this environment variable should not normally be set.

env(TCLLIBPATH)
If set, then it must contain a valid Tcl list giving directories to search during auto-load operations. Directories must be specified in Tcl format, using “/” as the path separator, regardless of platform. This variable is only used when initializing the auto_path variable.
env(TCL_TZ), env(TZ)
These specify the default timezone used for parsing and formatting times and dates in the clock command. On many platforms, the TZ environment variable is set up by the operating system.
env(LC_ALL), env(LC_MESSAGES), env(LANG)
These environment variables are used by the msgcat package to determine what locale to format messages using.
env(TCL_INTERP_DEBUG_FRAME)
If existing, it has the same effect as running interp debug {} -frame 1 as the very first command of each new Tcl interpreter.
errorCode
This variable holds the value of the -errorcode return option set by the most recent error that occurred in this interpreter. This list value represents additional information about the error in a form that is easy to process with programs. The first element of the list identifies a general class of errors, and determines the format of the rest of the list. The following formats for -errorcode return options are used by the Tcl core; individual applications may define additional formats.
ARITH code msg
This format is used when an arithmetic error occurs (e.g. an attempt to divide zero by zero in the expr command). Code identifies the precise error and msg provides a human-readable description of the error. Code will be either DIVZERO (for an attempt to divide by zero), DOMAIN (if an argument is outside the domain of a function, such as acos(-3)), IOVERFLOW (for integer overflow), OVERFLOW (for a floating-point overflow), or UNKNOWN (if the cause of the error cannot be determined).

Detection of these errors depends in part on the underlying hardware and system libraries.

CHILDKILLED pid sigName msg
This format is used when a child process has been killed because of a signal. The pid element will be the process's identifier (in decimal). The sigName element will be the symbolic name of the signal that caused the process to terminate; it will be one of the names from the include file signal.h, such as SIGPIPE. The msg element will be a short human-readable message describing the signal, such as “write on pipe with no readers” for SIGPIPE.
CHILDSTATUS pid code
This format is used when a child process has exited with a non-zero exit status. The pid element will be the process's identifier (in decimal) and the code element will be the exit code returned by the process (also in decimal).
CHILDSUSP pid sigName msg
This format is used when a child process has been suspended because of a signal. The pid element will be the process's identifier, in decimal. The sigName element will be the symbolic name of the signal that caused the process to suspend; this will be one of the names from the include file signal.h, such as SIGTTIN. The msg element will be a short human-readable message describing the signal, such as “background tty read” for SIGTTIN.
NONE
This format is used for errors where no additional information is available for an error besides the message returned with the error. In these cases the -errorcode return option will consist of a list containing a single element whose contents are NONE.
POSIX errName msg
If the first element is POSIX, then the error occurred during a POSIX kernel call. The errName element will contain the symbolic name of the error that occurred, such as ENOENT; this will be one of the values defined in the include file errno.h. The msg element is a short human-readable message describing the error, such as “no such file or directory” for ENOENT.
Windows errCode msg
This format is used for errors that occur during Windows API calls. The errCode is the Windows system error code (in decimal), and msg is the message associated with that code. This value can be converted to a symbolic name using the Tcl_Win32Error function.
errorInfo
This variable holds the detailed error message from the most recent error that occurred in this interpreter. This is the same information as is returned by the error command with no arguments, and typically includes a stack trace of Tcl commands that led to the error. This variable is only set when an error occurs; if no error has occurred then reading it will yield an empty string.
tcl_interactive
This variable is set to 1 if Tcl was started in interactive mode (e.g., from the command line without arguments or with -i specified), and 0 otherwise. It is read-only.
tcl_library
This variable holds the name of the directory containing Tcl's Tcl-based library procedures. This is the value that is used by the package require command to find Tcl packages. Tcl determines the value of this variable by first checking if the env(TCL_LIBRARY) environment variable is set. If it is set, its value is used. Otherwise, Tcl uses a hard-coded default value. This variable is read-only.
tcl_nonwordchars
This variable contains a string of characters that Tcl will treat as separators between words, in addition to whitespace. The default value is typically a subset of the characters that are part of the default tcl_wordchars string. This variable is read-only.
tcl_patchLevel
This variable holds a string identifying the patch level of the Tcl library, such as "8.6.8". This variable is read-only.
tcl_platform
This variable holds an array containing information about the operating system and hardware Tcl is running on. The actual elements may vary between platforms, but typically include:
tcl_platform(endian)
The endianness of the machine, either "little" or "big".
tcl_platform(os)
The name of the operating system, e.g., "windows", "unix".
tcl_platform(osVersion)
The version of the operating system.
tcl_platform(wordSize)
The size of a machine word in bytes (e.g., 4 or 8).
tcl_platform(user)
The login name of the user running the Tcl interpreter.
tcl_platform(userUid)
The user ID of the user running the Tcl interpreter.
tcl_platform(groupUid)
The group ID of the user running the Tcl interpreter.
This variable is read-only.
tcl_precision
This variable controls the number of digits of precision used when converting floating-point numbers to or from strings. The default value is 12. This variable is read-only.
tcl_rcFileName
If Tcl is started interactively, this variable holds the name of the script file to be sourced for initialization. The default value is ".tclshrc". This variable is read-only.
tcl_traceCompile
If this variable is set to a non-empty string, Tcl will compile commands with tracing enabled. This is primarily for debugging the Tcl compiler. Setting this variable to a non-empty string has the same effect as running the command set trace(compile) 1.
tcl_traceExec
If this variable is set to a non-empty string, Tcl will execute commands with tracing enabled. This is primarily for debugging the Tcl interpreter. Setting this variable to a non-empty string has the same effect as running the command set trace(exec) 1.
tcl_wordchars
This variable contains a string of characters that Tcl will treat as part of a word, in addition to alphanumeric characters. The default value typically includes characters like “_” and characters within the current locale's letter and number categories. This variable is read-only.
tcl_version
This variable holds a string identifying the version of the Tcl interpreter, such as "8.6". This variable is read-only.
argv
This variable holds a list of the command-line arguments passed to the Tcl script. The first element of the list corresponds to the first argument after the script name, and so on. This variable is read-only.
argv0
This variable holds the name of the script file being executed. If the script was typed directly into the interpreter (interactive mode), this variable holds the name of the interpreter (e.g., "tclsh"). This variable is read-only.
argc
This variable holds an integer value representing the number of elements in the argv list. This variable is read-only.
tcl_pkgPath
This variable holds a list of directories where Tcl should look for packages. This variable is initialized by Tcl and should generally not be modified. Additional package locations should be added to auto_path using lappend.

TCL ...
Indica algún tipo de problema generado en relación con Tcl, por ejemplo, un error al buscar un canal o una variable.

Para establecer la opción de retorno -errorcode, las aplicaciones deben usar procedimientos de biblioteca como Tcl_SetObjErrorCode, Tcl_SetReturnOptions y Tcl_PosixError, o pueden invocar la opción -errorcode del comando return. Si no se ha utilizado ninguno de estos métodos para establecer el código de error, el intérprete de Tcl restablecerá la variable a NONE después del próximo error.

errorInfo
Esta variable contiene el valor de la opción de retorno -errorinfo establecida por el error más reciente que ocurrió en este intérprete. Este valor de cadena contendrá una o más líneas que identifican los comandos y procedimientos de Tcl que se estaban ejecutando cuando ocurrió el error más reciente. Su contenido tiene la forma de un rastreo de pila que muestra los diversos comandos anidados de Tcl que se habían invocado en el momento del error.
tcl_library
Esta variable contiene el nombre de un directorio que contiene la biblioteca del sistema de scripts de Tcl, como los utilizados para la carga automática. El valor de esta variable se devuelve mediante el comando info library. Consulte la entrada de manual de library para obtener detalles sobre las instalaciones proporcionadas por la biblioteca de scripts de Tcl. Normalmente, cada aplicación o paquete tendrá su propia biblioteca de scripts específica de la aplicación, además de la biblioteca de scripts de Tcl; cada aplicación debe establecer una variable global con un nombre como $app_library (donde app es el nombre de la aplicación) para contener el nombre de archivo de red del directorio de la biblioteca de esa aplicación. El valor inicial de tcl_library se establece cuando se crea un intérprete, buscando varios directorios diferentes hasta que se encuentra uno que contiene un script de inicio de Tcl adecuado. Si la variable de entorno TCL_LIBRARY existe, entonces se verifica primero el directorio que nombra. Si TCL_LIBRARY no está configurada o no se refiere a un directorio adecuado, entonces Tcl verifica varios otros directorios basándose en una ubicación predeterminada compilada, la ubicación del binario que contiene la aplicación y el directorio de trabajo actual.
tcl_patchLevel
Cuando se crea un intérprete, Tcl inicializa esta variable para que contenga una cadena que indique el nivel de parche actual para Tcl, como 8.4.16 para Tcl 8.4 con los primeros dieciséis parches oficiales, o 8.5b3 para la tercera versión beta de Tcl 8.5. El valor de esta variable se devuelve mediante el comando info patchlevel.
tcl_pkgPath
Esta variable contiene una lista de directorios que indican dónde se instalan normalmente los paquetes. No se usa en Windows. Típicamente contiene una o dos entradas; si contiene dos entradas, la primera suele ser un directorio para paquetes dependientes de la plataforma (por ejemplo, bibliotecas compartidas binarias) y la segunda suele ser un directorio para paquetes independientes de la plataforma (por ejemplo, archivos de script). Típicamente, un paquete se instala como un subdirectorio de una de las entradas de la variable tcl_pkgPath. Los directorios de la variable tcl_pkgPath se incluyen por defecto en la variable auto_path, por lo que se buscan automáticamente ellos y sus subdirectorios inmediatos durante los comandos package require. Nota: tcl_pkgPath no está destinado a ser modificado por la aplicación. Su valor se agrega a auto_path al arranque; los cambios en tcl_pkgPath no se reflejan en auto_path. Si desea que Tcl busque directorios adicionales para paquetes, debe agregar los nombres de esos directorios a auto_path, no a tcl_pkgPath.
tcl_platform
Esta es una matriz asociativa cuyos elementos contienen información sobre la plataforma en la que se está ejecutando la aplicación, como el nombre del sistema operativo, su número de versión actual y el conjunto de instrucciones de la máquina. Los elementos que se enumeran a continuación siempre estarán definidos, pero pueden tener cadenas vacías como valores si Tcl no pudo recuperar información relevante. Además, las extensiones y aplicaciones pueden agregar valores adicionales a la matriz. Los elementos predefinidos son:
byteOrder
El orden de bytes nativo de esta máquina: littleEndian o bigEndian.
debug
Si esta variable existe, el intérprete se compiló y enlazó con un tiempo de ejecución C habilitado para depuración. Esta variable solo existirá en Windows, por lo que los escritores de extensiones pueden especificar qué paquete cargar dependiendo de la biblioteca de tiempo de ejecución C que se esté utilizando. Esto no indica que este núcleo contenga símbolos.
engine
El nombre de la implementación del lenguaje Tcl. Cuando se crea el intérprete por primera vez, esto siempre se establece en la cadena Tcl.
machine
El conjunto de instrucciones ejecutado por esta máquina, como intel, PPC, 68k o sun4m. En máquinas UNIX, este es el valor devuelto por uname -m.
os
El nombre del sistema operativo que se ejecuta en esta máquina, como Windows NT o SunOS. En máquinas UNIX, este es el valor devuelto por uname -s.
osVersion
El número de versión del sistema operativo que se ejecuta en esta máquina. En máquinas UNIX, este es el valor devuelto por uname -r.
pathSeparator
El carácter que se debe utilizar para dividir las variables de entorno tipo PATH en su lista correspondiente de nombres de directorios.
platform
Ya sea windows o unix. Esto identifica el entorno operativo general de la máquina.
pointerSize
Esto da el tamaño del puntero nativo de la máquina en bytes (estrictamente, es igual al resultado de evaluar sizeof(void*) en C).
threaded
Si esta variable existe, el intérprete se compiló con hilos habilitados.
user
Esto identifica al usuario actual basándose en la información de inicio de sesión disponible en la plataforma. Este valor proviene de las llamadas del sistema getuid() y getpwuid() en Unix, y del valor de la llamada del sistema GetUserName() en Windows.
wordSize
Esto da el tamaño de la palabra nativa de la máquina en bytes (estrictamente, es igual al resultado de evaluar sizeof(long) en C).
tcl_precision
Esta variable controla el número de dígitos a generar al convertir valores de punto flotante a cadenas. Por defecto es 0. Las aplicaciones no deben cambiar este valor; se proporciona para compatibilidad con código heredado.
El valor predeterminado de 0 es especial, lo que significa que Tcl debe convertir números usando la menor cantidad de dígitos posible sin dejar de distinguir cualquier número de punto flotante de sus vecinos más cercanos. Se difiere de usar un valor arbitrariamente alto para tcl_precision en que un número inexacto como 1.4 se convertirá como 1.4 en lugar de 1.3999999999999999, aunque este último está más cerca del valor exacto del número binario.
Si tcl_precision no es cero, entonces cuando Tcl convierte un número de punto flotante, crea una representación decimal de como máximo tcl_precision dígitos significativos; el resultado puede ser más corto si el resultado más corto representa el número original exactamente. Si ningún resultado de como máximo tcl_precision dígitos es una representación exacta del número original, se elige el que está más cerca del número original. Si el número original se encuentra precisamente entre dos representaciones decimales igualmente precisas, se elige la que tenga un valor par para el dígito menos significativo; por ejemplo, si tcl_precision es 3, entonces 0.3125 se convertirá a 0.312, no a 0.313, mientras que 0.6875 se convertirá a 0.688, no a 0.687. Se eliminan las cadenas de ceros finales que queden.
un valor de tcl_precision de 17 dígitos es "perfecto" para punto flotante IEEE, ya que permite que los valores de doble precisión se conviertan a cadenas y de vuelta a binario sin pérdida de información. Por esta razón, a menudo se ve como un valor en código heredado que debe ejecutarse en versiones de Tcl anteriores a la 8.5. Ya no se recomienda; como se señaló anteriormente, un valor cero es el método preferido.
Todos los intérpretes en un hilo comparten un único valor de tcl_precision: cambiarlo en un intérprete afectará a todos los demás intérpretes. A los intérpretes seguros no se les permite modificar la variable.
Los valores válidos para tcl_precision van de 0 a 17.
tcl_rcFileName
Esta variable se utiliza durante la inicialización para indicar el nombre de un archivo de inicio específico del usuario. Si lo establece la inicialización específica de la aplicación, el código de inicio de Tcl verificará la existencia de este archivo y lo cargará (source) si existe. Por ejemplo, para wish la variable se establece en ~/.wishrc para Unix y en ~/wishrc.tcl para Windows.
tcl_traceCompile
El valor de esta variable se puede establecer para controlar cuánta información de rastreo se muestra durante la compilación de bytecode. Por defecto, tcl_traceCompile es cero y no se muestra información. Establecer tcl_traceCompile en 1 genera un resumen de una línea en stdout cada vez que se compila un procedimiento o un comando de nivel superior. Establecerlo en 2 genera un listado detallado en stdout de las instrucciones de bytecode emitidas durante cada compilación. Esta variable es útil para rastrear posibles problemas con el compilador de Tcl.
Esta variable y funcionalidad solo existen si TCL_COMPILE_DEBUG se definió durante la compilación de Tcl.

NAME

tclvars - Tcl global variables

DESCRIPTION

Tcl provides a number of global variables that can be used to query and control the Tcl environment. The following variables are part of the core Tcl library.

tcl_traceExec
The value of this variable can be set to control how much tracing information is displayed during bytecode execution. By default, tcl_traceExec is zero and no information is displayed. Setting tcl_traceExec to 1 generates a one-line trace in stdout on each call to a Tcl procedure. Setting it to 2 generates a line of output whenever any Tcl command is invoked that contains the name of the command and its arguments. Setting it to 3 produces a detailed trace showing the result of executing each bytecode instruction. Note that when tcl_traceExec is 2 or 3, commands such as set and incr that have been entirely replaced by a sequence of bytecode instructions are not shown. Setting this variable is useful in tracking down suspected problems with the bytecode compiler and interpreter.
This variable and functionality only exist if TCL_COMPILE_DEBUG was defined during Tcl's compilation.
tcl_wordchars
The value of this variable is a regular expression that can be set to control what are considered “word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \S, meaning anything but a Unicode space character. Otherwise it defaults to \w, which is any Unicode word character (number, letter, or underscore).
tcl_nonwordchars
The value of this variable is a regular expression that can be set to control what are considered “non-word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \s, meaning any Unicode space character. Otherwise it defaults to \W, which is anything but a Unicode word character (number, letter, or underscore).
tcl_version
When an interpreter is created Tcl initializes this variable to hold the version number for this version of Tcl in the form x.y. Changes to x represent major changes with probable incompatibilities and changes to y represent small enhancements and bug fixes that retain backward compatibility. The value of this variable is returned by the info tclversion command.

OTHER GLOBAL VARIABLES

The following variables are only guaranteed to exist in tclsh and wish executables; the Tcl library does not define them itself but many Tcl environments do.

argc
The number of arguments to tclsh or wish.
argv
Tcl list of arguments to tclsh or wish.
argv0
The script that tclsh or wish started executing (if it was specified) or otherwise the name by which tclsh or wish was invoked.
tcl_interactive
Contains 1 if tclsh or wish is running interactively (no script was specified and standard input is a terminal-like device), 0 otherwise.

EXAMPLES

To add a directory to the collection of locations searched by package require, e.g., because of some application-specific packages that are used, the auto_path variable needs to be updated:

lappend ::auto_path [file join [pwd] "theLibDir"]

A simple though not very robust way to handle command line arguments of the form “-foo 1 -bar 2” is to load them into an array having first loaded in the default settings:

array set arguments {-foo 0 -bar 0 -grill 0}
array set arguments $::argv
puts "foo is $arguments(-foo)"
puts "bar is $arguments(-bar)"
puts "grill is $arguments(-grill)"

The argv0 global variable can be used (in conjunction with the info script command) to determine whether the current script is being executed as the main script or loaded as a library. This is useful because it allows a single script to be used as both a library and a demonstration of that library:

if {$::argv0 eq [info script]} {
    # running as: tclsh example.tcl
} else {
    package provide Example 1.0
}
