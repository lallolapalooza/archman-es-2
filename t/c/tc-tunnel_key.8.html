NOMBRE

tunnel_key - Manipulación de metadatos de túnel

SINOPSIS


tc ... action tunnel_key { unset | SET }

SET := set src_ip DIRECCION dst_ip DIRECCION id CLAVE_ID dst_port PUERTO_UDP tos TOS ttl TTL [ csum | nocsum ]

DESCRIPCIÓN

La acción tunnel_key combinada con un dispositivo de túnel IP compartido, permite realizar la encapsulación o desencapsulación de IP en un paquete, reflejada por los modos de operación UNSET y SET. El modo UNSET es opcional; incluso sin usarlo, la información de metadatos se liberará automáticamente cuando finalice el procesamiento del paquete. La función UNSET se puede usar en casos donde el tráfico se reenvía entre dos túneles, donde los metadatos del primer túnel se usarán para la encapsulación realizada por el segundo túnel. El modo SET requiere la dirección IP de origen y destino DIRECCION y el ID de clave del túnel CLAVE_ID que será utilizado por el dispositivo compartido del túnel IP para crear la cabecera del túnel. La acción tunnel_key solo es útil en combinación con una acción mirred redirect a un dispositivo de túnel IP compartido que utilizará los metadatos (para SET ) y anulará los metadatos creados por él (para UNSET ).

OPCIONES

unset
Anula los metadatos del túnel creados por el dispositivo de túnel IP. Esta función no es obligatoria y solo se puede usar en algunos casos de uso específicos (como se explicó anteriormente).
set
Establece los metadatos del túnel a ser utilizados por el dispositivo de túnel IP. Requiere las opciones src_ip y dst_ip. id , dst_port , geneve_opts , vxlan_opts y erspan_opts son opcionales.
id
ID del túnel (por ejemplo, VNI en un túnel VXLAN)
src_ip
Dirección IP de origen de la cabecera externa (IPv4 o IPv6)
dst_ip
Dirección IP de destino de la cabecera externa (IPv4 o IPv6)
dst_port
Puerto UDP de destino de la cabecera externa
geneve_opts
Opciones de longitud variable de Geneve. geneve_opts se especifica en el formato CLASE:TIPO:DATOS, donde CLASE se representa como un valor hexadecimal de 16 bits, TIPO como un valor hexadecimal de 8 bits y DATOS como un valor hexadecimal de longitud variable. Adicionalmente, se pueden listar múltiples opciones usando un delimitador de coma.
vxlan_opts
Opciones de metadatos de Vxlan. vxlan_opts se especifica en el formato GBP, como un número de 32 bits. No se admiten opciones múltiples.
erspan_opts
Opciones de metadatos de Erspan. erspan_opts se especifica en el formato VERSION:INDICE:DIR:HWID, donde VERSION se representa como un número de 8 bits, INDICE como un número de 32 bits, DIR y HWID como un número de 8 bits. No se admiten opciones múltiples. Tenga en cuenta que INDICE se utiliza cuando VERSION es 1, y DIR y HWID se utilizan cuando VERSION es 2.
tos
TOS de la cabecera externa
ttl
TTL de la cabecera externa
[no]csum
Controla la suma de verificación UDP externa. Cuando se establece en csum (que es el valor predeterminado), la suma de verificación UDP externa se calcula y se incluye en los paquetes. Cuando se establece en nocsum, la suma de verificación UDP externa es cero. Tenga en cuenta que al usar sumas de verificación UDP cero con IPv6, el otro extremo del túnel debe estar configurado para aceptar dichos paquetes. En Linux, esta sería la opción udp6zerocsumrx para la interfaz del túnel VXLAN.
Si usa nocsum con IPv6, asegúrese de saber lo que está haciendo. Las sumas de verificación UDP cero proporcionan una protección más débil contra paquetes corruptos. Consulte la RFC6935 para obtener más detalles.
nofrag
deshabilita la fragmentación IP.

EJEMPLOS

El siguiente ejemplo encapsula paquetes ICMP entrantes en eth0 en un túnel vxlan, estableciendo los metadatos a VNI 11, IP de origen 11.11.0.1 y IP de destino 11.11.0.2, y redirigiendo el paquete con los metadatos al dispositivo vxlan0, que realizará la encapsulación real utilizando los metadatos:

#tc qdisc add dev eth0 handle ffff: ingress
#tc filter add dev eth0 protocol ip parent ffff: \
  flower \
    ip_proto icmp \
  action tunnel_key set \
    src_ip 11.11.0.1 \
    dst_ip 11.11.0.2 \
    id 11 \
  action mirred egress redirect dev vxlan0

Aquí hay un ejemplo de la función unset: El tráfico VXLAN entrante con IPs externas y VNI 11 se desencapsula por vxlan0 y los metadatos se anulan antes de redirigirlos al dispositivo tunl1:

#tc qdisc add dev eth0 handle ffff: ingress
#tc filter add dev vxlan0 protocol ip parent ffff:   flower \
	  enc_src_ip 11.11.0.2 enc_dst_ip 11.11.0.1 enc_key_id 11 	action tunnel_key unset 	action mirred egress redirect dev tunl1
