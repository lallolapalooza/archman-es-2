INTRODUCCIÓN

Tcl incluye una biblioteca de procedimientos Tcl para funciones de uso común. Los procedimientos definidos en la biblioteca Tcl son genéricos y adecuados para ser utilizados por muchas aplicaciones diferentes. La ubicación de la biblioteca Tcl se devuelve con el comando info library. Además de la biblioteca Tcl, cada aplicación normalmente tendrá su propia biblioteca de procedimientos de soporte; la ubicación de esta biblioteca normalmente se proporciona mediante el valor de la variable global $app_library, donde app es el nombre de la aplicación. Por ejemplo, la ubicación de la biblioteca Tk se guarda en la variable tk_library.

Para acceder a los procedimientos de la biblioteca Tcl, una aplicación debe obtener el archivo init.tcl de la biblioteca, por ejemplo, con el comando Tcl

source [file join [info library] init.tcl]

Si se invoca el procedimiento de la biblioteca Tcl_Init desde el procedimiento Tcl_AppInit de una aplicación, esto ocurre automáticamente. El código en init.tcl definirá el procedimiento unknown y se encargará de que los demás procedimientos se carguen bajo demanda utilizando el mecanismo de carga automática definido a continuación.

PROCEDIMIENTOS DE COMANDO

Los siguientes procedimientos se proporcionan en la biblioteca Tcl:

auto_execok cmd
Determina si existe un archivo ejecutable o un comando interno del shell con el nombre cmd. Si es así, devuelve una lista de argumentos que se pasarán a exec para ejecutar el archivo ejecutable o el comando interno del shell llamado por cmd. Si no, devuelve una cadena vacía. Este comando examina los directorios en la ruta de búsqueda actual (proporcionada por la variable de entorno PATH) en su búsqueda de un archivo ejecutable llamado cmd. En plataformas Windows, la búsqueda se expande con los mismos directorios y extensiones de archivo que utiliza exec. Auto_execok recuerda información sobre búsquedas anteriores en un array llamado auto_execs; esto evita la búsqueda en la ruta en llamadas futuras para el mismo cmd. El comando auto_reset puede usarse para forzar que auto_execok olvide su información en caché.
auto_import patrón
Auto_import se invoca durante namespace import para ver si los comandos importados especificados por patrón residen en una biblioteca de carga automática. Si es así, los comandos se cargan para que estén disponibles para el intérprete para la creación de los enlaces de importación. Si los comandos no residen en una biblioteca de carga automática, auto_import no hace nada. La coincidencia de patrones se realiza de acuerdo con las reglas de coincidencia de namespace import.
auto_load cmd
Este comando intenta cargar la definición de un comando Tcl llamado cmd. Para ello, busca una ruta de carga automática, que es una lista de uno o más directorios. La ruta de carga automática se proporciona mediante la variable global auto_path si existe. Si no existe la variable auto_path, se utiliza la variable de entorno TCLLIBPATH si existe. De lo contrario, la ruta de carga automática consta únicamente del directorio de la biblioteca Tcl. Dentro de cada directorio de la ruta de carga automática debe haber un archivo tclIndex que describa uno o más comandos definidos en ese directorio y un script para evaluar y cargar cada uno de los comandos. El archivo tclIndex debe ser generado con el comando auto_mkindex. Si cmd se encuentra en un archivo de índice, se evalúa el script apropiado para crear el comando. El comando auto_load devuelve 1 si cmd se creó exitosamente. El comando devuelve 0 si no había ninguna entrada de índice para cmd o si el script no definió realmente cmd (por ejemplo, porque la información del índice está desactualizada). Si ocurre un error al procesar el script, se devuelve ese error. Auto_load solo lee la información del índice una vez y la guarda en el array auto_index; las llamadas futuras a auto_load verifican si cmd está en el array en lugar de volver a leer los archivos de índice. La información del índice en caché se puede eliminar con el comando auto_reset. Esto obligará al próximo comando auto_load a recargar la base de datos de índices desde el disco.
auto_mkindex dir patrón patrón ...
Genera un índice adecuado para su uso por auto_load. El comando busca en dir todos los archivos cuyos nombres coincidan con alguno de los argumentos patrón (la coincidencia se realiza con el comando glob), genera un índice de todos los procedimientos de comandos Tcl definidos en todos los archivos coincidentes y almacena la información del índice en un archivo llamado tclIndex en dir. Si no se proporciona ningún patrón, se asumirá un patrón de *.tcl. Por ejemplo, el comando
auto_mkindex foo *.tcl

leerá todos los archivos .tcl en el subdirectorio foo y generará un nuevo archivo de índice foo/tclIndex.

Auto_mkindex analiza los scripts Tcl ejecutándolos en un intérprete hijo y monitoreando los comandos proc y namespace que se ejecutan. Las extensiones pueden usar el paquete (no documentado) auto_mkindex_parser para registrar otros comandos que pueden contribuir al índice de carga automática. Tendrás que leer auto.tcl para ver cómo funciona.

Auto_mkindex_old (que tiene la misma sintaxis que auto_mkindex) analiza los scripts Tcl de una manera relativamente poco sofisticada: si alguna línea contiene la palabra “proc” como sus primeros caracteres, se asume que es una definición de procedimiento y la siguiente palabra de la línea se toma como el nombre del procedimiento. Las definiciones de procedimientos que no aparecen de esta manera (por ejemplo, tienen espacios antes de proc) no se indexarán. Si tu script contiene código “peligroso”, como código de inicialización global o nombres de procedimientos con caracteres especiales como $, *, [ o ], estás más seguro usando auto_mkindex_old.

auto_reset
Destruye toda la información cacheada por auto_execok y auto_load. Esta información se volverá a leer desde el disco la próxima vez que se necesite. Auto_reset también elimina cualquier procedimiento listado en el índice de carga automática, de modo que se carguen copias nuevas de ellos la próxima vez que se utilicen.
auto_qualify comando namespace
Calcula una lista de nombres completamente calificados para comando. Esta lista refleja la ruta que sigue un intérprete Tcl estándar para la búsqueda de comandos: primero busca el comando en el namespace actual y luego en el namespace global. En consecuencia, si comando es relativo y namespace no es ::, la lista devuelta tiene dos elementos: comando con el scope de namespace, como si fuera un comando en el namespace namespace; y comando como si fuera un comando en el namespace global. De lo contrario, si comando es absoluto (comienza con ::) o namespace es ::, la lista contiene solo comando como si fuera un comando en el namespace global.

Auto_qualify es utilizado por las facilidades de carga automática en Tcl, tanto para producir índices de carga automática como pkgIndex.tcl, como para realizar la carga automática real de funciones en tiempo de ejecución.

tcl_findLibrary nombreBase versión parche scriptInicial nombreVarEntrada nombreVar

Este es el procedimiento de búsqueda de bibliotecas de nivel más bajo. Busca en la jerarquía de directorios una biblioteca que coincida con los criterios especificados. Su propósito es encontrar un script de inicialización para una biblioteca dada (por ejemplo, Tk, Itcl) y devolver la ruta completa a ese script. El procedimiento busca en varias ubicaciones posibles, como las entradas en auto_path, y también utiliza información relativa al ejecutable Tcl.

Los argumentos son los siguientes:

nombreBase
El nombre base del directorio de la biblioteca (por ejemplo, "tk" o "itcl").
versión
El número de versión de la biblioteca (por ejemplo, "8.5").
parche
El número de parche de la biblioteca (por ejemplo, "2").
scriptInicial
El nombre del script de inicialización (por ejemplo, "init.tcl"). Se buscará el archivo scriptInicial dentro de un subdirectorio de la biblioteca que coincida con la versión y el parche.
nombreVarEntrada
El nombre de la variable Tcl que contendrá la lista de directorios donde se buscará la biblioteca (por ejemplo, "auto_path").
nombreVar
El nombre de la variable Tcl que contendrá la ruta completa del script de inicialización una vez encontrado.

El procedimiento intenta encontrar la biblioteca buscando subdirectorios que coincidan con el patrón [i]nombreBase[/i]/[i]versión[/i]/[i]scriptInicial[/i] o [i]nombreBase[/i]/[i]versión[/i] dentro de los directorios especificados en la variable [i]nombreVarEntrada[/i]. Si se encuentra el script, su ruta completa se almacena en la variable especificada por [i]nombreVar[/i] y el procedimiento devuelve 1. Si no se encuentra el script, el procedimiento devuelve 0.

El procedimiento también maneja las versiones de parche y puede buscar el script de inicialización en el directorio de la biblioteca Tcl si no se encuentra en ningún otro lugar.

parray nombreArray ?patrón?
Imprime los elementos de un array Tcl. Si no se especifica un patrón, se imprimen todos los elementos del array llamado nombreArray. Si se especifica un patrón, solo se imprimen los elementos cuyos nombres de índice coincidan con el patrón. El patrón utiliza las mismas reglas de coincidencia que el comando glob. El comando parray imprime el nombre del índice y el valor asociado de cada elemento correspondiente. Si no existe el array especificado, se produce un error.
tcl_endOfWord str inicio
Este comando devuelve el índice del primer carácter que está *después* del final de una palabra en la cadena str, comenzando la búsqueda desde el índice inicio. Una "palabra" se define como una secuencia de caracteres alfanuméricos (incluyendo el guión bajo) o una secuencia de caracteres no alfanuméricos. El comando considera los caracteres de puntuación y los espacios en blanco como delimitadores de palabras. Si inicio está fuera de los límites de la cadena, el comportamiento no está especificado. Si la cadena está vacía o no contiene palabras, el resultado puede ser el final de la cadena o un comportamiento indefinido.
tcl_startOfNextWord str inicio
Devuelve el índice del primer carácter de la siguiente palabra en la cadena str, comenzando la búsqueda desde el índice inicio. Si se encuentra una palabra, se devuelve el índice del primer carácter de esa palabra. Si no hay más palabras después del índice inicio, se devuelve la longitud de la cadena.
tcl_startOfPreviousWord str inicio
Devuelve el índice del primer carácter de la palabra anterior en la cadena str, comenzando la búsqueda desde el índice inicio. Si se encuentra una palabra anterior, se devuelve el índice del primer carácter de esa palabra. Si no hay más palabras antes del índice inicio, se devuelve 0.
tcl_wordBreakAfter str inicio
Devuelve el índice del primer carácter después de un punto de interrupción de palabra en la cadena str, comenzando la búsqueda desde el índice inicio. Los puntos de interrupción de palabra se definen como los lugares entre dos caracteres adyacentes donde uno es un carácter de palabra (alfanumérico o guión bajo) y el otro no lo es, o viceversa. Si no hay un punto de interrupción de palabra después del índice inicio, se devuelve la longitud de la cadena.
tcl_wordBreakBefore str inicio
Devuelve el índice del primer carácter antes de un punto de interrupción de palabra en la cadena str, comenzando la búsqueda desde el índice inicio. Los puntos de interrupción de palabra se definen de manera similar a tcl_wordBreakAfter. Si no hay un punto de interrupción de palabra antes del índice inicio, se devuelve 0.

NOMBRE

tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter, tcl_wordBreakBefore - helpers for determining word boundaries

SINOPSIS

This is a standard search procedure for use by extensions during their initialization. They call this procedure to look for their script library in several standard directories. The last component of the name of the library directory is normally basenameversion (e.g., tk8.0), but it might be “library” when in the build hierarchies. The initScript file will be sourced into the interpreter once it is found. The directory in which this file is found is stored into the global variable varName. If this variable is already defined (e.g., by C code during application initialization) then no searching is done. Otherwise the search looks in these directories: the directory named by the environment variable enVarName; relative to the Tcl library directory; relative to the executable file in the standard installation bin or bin/arch directory; relative to the executable file in the current build tree; relative to the executable file in a parallel build tree.
parray nombreArray ?patrón?
Imprime en la salida estándar los nombres y valores de todos los elementos de la matriz nombreArray, o solo aquellos nombres que coincidan con patrón (usando las reglas de coincidencia de string match) y sus valores si se proporciona patrón. nombreArray debe ser una matriz accesible para el llamador de parray. Puede ser local o global.

AYUDAS DE LÍMITE DE PALABRA

Estos procedimientos se utilizan principalmente internamente en Tk.

tcl_endOfWord str inicio
Devuelve el índice de la primera ubicación de fin de palabra que ocurre después de un índice de inicio inicio en la cadena str. Una ubicación de fin de palabra se define como el primer carácter no palabra que sigue al primer carácter palabra después del punto de partida. Devuelve -1 si no hay más ubicaciones de fin de palabra después del punto de partida. Consulte la descripción de tcl_wordchars y tcl_nonwordchars a continuación para obtener más detalles sobre cómo Tcl determina qué caracteres son caracteres de palabra.
tcl_startOfNextWord str inicio
Devuelve el índice de la primera ubicación de inicio de palabra que ocurre después de un índice de inicio inicio en la cadena str. Una ubicación de inicio de palabra se define como el primer carácter palabra que sigue a un carácter no palabra. Devuelve -1 si no hay más ubicaciones de inicio de palabra después del punto de partida.
tcl_startOfPreviousWord str inicio
Devuelve el índice de la primera ubicación de inicio de palabra que ocurre antes de un índice de inicio inicio en la cadena str. Devuelve -1 si no hay más ubicaciones de inicio de palabra antes del punto de partida.
tcl_wordBreakAfter str inicio
Devuelve el índice del primer límite de palabra después del índice de inicio inicio en la cadena str. Devuelve -1 si no hay más límites después del punto de partida en la cadena dada. El índice devuelto se refiere al segundo carácter del par que comprende un límite.
tcl_wordBreakBefore str inicio
Devuelve el índice del primer límite de palabra antes del índice de inicio inicio en la cadena str. Devuelve -1 si no hay más límites antes del punto de partida en la cadena dada. El índice devuelto se refiere al segundo carácter del par que comprende un límite.

VARIABLES

Las siguientes variables globales son definidas o utilizadas por los procedimientos en la biblioteca Tcl. Se dividen en dos clases amplias, que manejan comandos y paquetes desconocidos, y determinan qué son las palabras.

VARIABLES DE AUTOCARGA Y GESTIÓN DE PAQUETES

auto_execs
Utilizado por auto_execok para registrar información sobre si comandos particulares existen como archivos ejecutables.
auto_index
Utilizado por auto_load para guardar la información del índice leída del disco.
auto_noexec
Si se establece en cualquier valor, entonces unknown no intentará auto-ejecutar ningún comando.
auto_noload
Si se establece en cualquier valor, entonces unknown no intentará auto-cargar ningún comando.
auto_path
Si se establece, entonces debe contener una lista Tcl válida que proporcione directorios para buscar durante las operaciones de auto-carga (incluyendo los archivos de índice de paquetes cuando se utiliza el manejador predeterminado de package unknown). Esta variable se inicializa durante el inicio para contener, en orden: los directorios listados en la variable de entorno TCLLIBPATH, el directorio denominado por la variable global tcl_library, el directorio padre de tcl_library, los directorios listados en la variable tcl_pkgPath. Las ubicaciones adicionales para buscar archivos e índices de paquetes normalmente deberían añadirse a esta variable usando lappend.
env(TCL_LIBRARY)
Si se establece, entonces especifica la ubicación del directorio que contiene los scripts de biblioteca (el valor de esta variable se asignará a la variable tcl_library y, por lo tanto, será devuelto por el comando info library). Si esta variable no está establecida, se utiliza un valor predeterminado.
env(TCLLIBPATH)
Si se establece, entonces debe contener una lista Tcl válida que proporcione directorios para buscar durante las operaciones de auto-carga. Los directorios deben especificarse en formato Tcl, usando “/” como separador de ruta, independientemente de la plataforma. Esta variable solo se utiliza al inicializar la variable auto_path.

VARIABLES DE DETERMINACIÓN DE LÍMITES DE PALABRA

Estas variables solo se utilizan en los comandos tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter y tcl_wordBreakBefore.

tcl_nonwordchars
Esta variable contiene una expresión regular que es utilizada por rutinas como tcl_endOfWord para identificar si un carácter es parte de una palabra o no. Si el patrón coincide con un carácter, el carácter se considera un carácter no palabra. En plataformas Windows, los espacios, tabulaciones y saltos de línea se consideran caracteres no palabra. En Unix, todo lo que no sean números, letras y guiones bajos se considera caracteres no palabra.
tcl_wordchars
Esta variable contiene una expresión regular que es utilizada por rutinas como tcl_endOfWord para identificar si un carácter es parte de una palabra o no. Si el patrón coincide con un carácter, el carácter se considera un carácter palabra. En plataformas Windows, las palabras están compuestas por cualquier carácter que no sea un espacio, tabulación o salto de línea. En Unix, las palabras están compuestas por números, letras o guiones bajos.
