NOMBRE

tcpreplay - Reproduce tráfico de red almacenado en archivos pcap

SINOPSIS

tcpreplay [-flags] [-flag [valor]] [--nombre-opcion[[=| ]valor]] <archivo(s)_pcap> | <directorio(s)_pcap>

tcpreplay es una herramienta para reproducir tráfico de red desde archivos guardados con tcpdump u otras herramientas que escriben archivos pcap(3).

DESCRIPCIÓN

La operación básica de tcpreplay es reenviar todos los paquetes del archivo(s) de entrada a la velocidad a la que fueron grabados, o a una tasa de datos especificada, hasta la máxima capacidad del hardware.

Opcionalmente, el tráfico puede dividirse entre dos interfaces, escribirse en archivos, filtrarse y editarse de diversas maneras, proporcionando los medios para probar firewalls, NIDS y otros dispositivos de red.

Para más detalles, por favor consulte el Manual de Tcpreplay en: http://tcpreplay.appneta.com

OPCIONES

-d número, --dbug=número

Habilita la salida de depuración. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento. El valor de número está restringido a: 
en el rango de 0 a 5

El número predeterminado para esta opción es:
0

Si se configuró con --enable-debug, entonces puede especificar un nivel de verbosidad para la salida de depuración. Los números más altos aumentan la verbosidad.

-q, --quiet

Modo silencioso.

Imprime nada excepto las estadísticas al final de la ejecución.

-T cadena, --timer=cadena

Selecciona el modo de temporización de paquetes: select, ioport, gtod, nano. Esta opción puede aparecer hasta 1 vez. La cadena predeterminada para esta opción es:
gtod

Permite seleccionar el método de temporización de paquetes a utilizar:

nano - Usa la API nanosleep()

select - Usa la API select()

ioport - Escribe en el puerto de E/S i386 0x80

gtod [predeterminado] - Usa un bucle gettimeofday()

--maxsleep=número

Duerme no más de X milisegundos entre paquetes. Esta opción toma un número entero como argumento. El número predeterminado para esta opción es:
0

Establece un límite para el número máximo de milisegundos que tcpreplay dormirá entre paquetes. Evita efectivamente retrasos largos entre paquetes sin afectar a la mayoría de los paquetes. Predeterminado: deshabilitado.

-v, --verbose

Imprime paquetes decodificados a través de tcpdump en STDOUT. Esta opción puede aparecer hasta 1 vez.
-A cadena, --decode=cadena

Argumentos pasados al decodificador tcpdump. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con las siguientes opciones: verbose.

Al habilitar el modo verboso (-v), también puede especificar uno o más argumentos adicionales para pasar a tcpdump para modificar la forma en que se decodifican los paquetes. Por defecto, se utilizan -n y -l. Asegúrese de citar los argumentos como: -A "-axxx" para que no sean interpretados por tcpreplay. Consulte la página del manual de tcpdump(1) para ver una lista completa de opciones.

-K, --preload-pcap

Pre carga los paquetes en la RAM antes de enviarlos.

Esta opción carga los pcap especificados en la RAM antes de comenzar a enviar para mejorar el rendimiento de la reproducción, aunque introduce un impacto en el rendimiento al inicio. La precarga se puede utilizar con o sin --loop. Esta opción también suprime la recopilación de estadísticas de flujo para cada iteración, lo que puede reducir significativamente el uso de memoria. Las estadísticas de flujo se predicen basándose en las opciones proporcionadas y las estadísticas recopiladas de la primera iteración del bucle.

-c cadena, --cachefile=cadena

Divide el tráfico a través de un archivo de caché de tcpprep. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con la siguiente opción: intf2. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: dualfile.

Si tiene un archivo pcap que desea utilizar para enviar tráfico bidireccional a través de un dispositivo (firewall, router, IDS, etc.), utilizando tcpprep puede crear un archivo de caché que tcpreplay utilizará para dividir el tráfico entre dos interfaces de red.

-2, --dualfile

Reproduce dos archivos a la vez desde un tap de red. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con la siguiente opción: intf2. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: cachefile.

Si capturó tráfico de red utilizando un tap de red, puede terminar con dos archivos pcap, uno para cada dirección. Esta opción reproducirá estos dos archivos al mismo tiempo, uno en cada interfaz, y los intercalará utilizando las marcas de tiempo de cada uno.

-i cadena, --intf1=cadena

Interfaz de salida para tráfico de cliente a servidor/RX/primario. Esta opción puede aparecer hasta 1 vez. Esta opción es un miembro de la clase de opciones intf1.

Interfaz de red requerida utilizada para enviar todo el tráfico o el tráfico marcado como 'primario' a través de tcpprep. El tráfico primario suele ser de cliente a servidor o entrante (RX) en interfaces virtuales khial.

-I cadena, --intf2=cadena

Interfaz de salida para tráfico de servidor a cliente/TX/secundario. Esta opción puede aparecer hasta 1 vez.

Interfaz de red opcional utilizada para enviar tráfico marcado como 'secundario' a través de tcpprep. El tráfico secundario suele ser de servidor a cliente o saliente (TX) en interfaces virtuales khial. Generalmente, solo tiene sentido usar esta opción con --cachefile.

-w cadena, --write=cadena

Nombre del archivo pcap para recibir salidas de tráfico. Esta opción puede aparecer hasta 1 vez. Esta opción es un miembro de la clase de opciones intf1. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: intf2.

Nombre opcional del archivo pcap utilizado para recibir tráfico.

--include=cadena

Envía solo números de paquetes seleccionados. Esta opción puede aparecer hasta 1 vez. Esta opción no debe aparecer en combinación con la siguiente opción: exclude.

Anula el valor predeterminado de procesar todos los paquetes almacenados en el archivo de captura y solo envía los paquetes que forman parte de una lista suministrada de números de paquetes.

    -x P:1-5,9,15,72-
saltaría los paquetes del 1 al 5, el noveno y el decimoquinto paquete, y los paquetes del 72 hasta el final del archivo.
--exclude=cadena

Envía todos los paquetes excepto los números de paquetes seleccionados. Esta opción puede aparecer hasta 1 vez. Esta opción no debe aparecer en combinación con la siguiente opción: include.

Anula el valor predeterminado de procesar todos los paquetes almacenados en el archivo de captura y solo envía los paquetes que NO forman parte de una lista suministrada de números de paquetes.

    -x P:1-5,9,15,72-
saltaría los paquetes del 1 al 5, el noveno y el decimoquinto paquete, y los paquetes del 72 hasta el final del archivo.
--listnics

Lista las interfaces de red disponibles y sale.
-l número, --loop=número

Retraso entre iteraciones del bucle en segundos. Esta opción toma un número entero como argumento. El valor de número está restringido a ser: 
mayor o igual a 0

El número predeterminado para esta opción es:
0
-r número, --rate=número

Velocidad de reproducción en paquetes/segundo. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento. El valor de número está restringido a ser: 
mayor o igual a 0

El número predeterminado para esta opción es:
0

Esto le permite reproducir el tráfico a una velocidad determinada. Por defecto, tcpreplay reproducirá el tráfico a la velocidad a la que se capturó.

Replay packets for X seconds. This option may appear up to 1 times. This option takes an integer number as its argument. The value of number is constrained to being:

Limit playback speed to packets per second.

EJEMPLOS

Replay traffic from file traffic.pcap on interface eth0 at near line rate:

    tcpreplay traffic.pcap

Replay traffic from file traffic.pcap on interface eth0 at 1000 packets per second:

    tcpreplay -i eth0 --pps --rate=1000 traffic.pcap

Replay traffic from directory pcaps/:

    tcpreplay pcaps/

Replay traffic from file traffic.pcap on interface eth0 twice, with 1 second delay between loops:

    tcpreplay --loop=2 --loopdelay=1 traffic.pcap

Replay traffic from file traffic.pcap, sending client-to-server traffic on eth0 and server-to-client traffic on eth1:

    tcpprep --cachefile=traffic.cache traffic.pcap
    tcpreplay --cachefile=traffic.cache --intf1=eth0 --intf2=eth1 traffic.pcap

--pktlen

Anular el snaplen y usar la longitud real del paquete. Esta opción puede aparecer hasta 1 vez.

Por defecto, tcpreplay enviará paquetes basándose en el tamaño del "snaplen" almacenado en el archivo pcap, que suele ser lo correcto. Sin embargo, ocasionalmente, las herramientas almacenan más bytes de los que indican. Al especificar esta opción, tcpreplay ignorará el campo snaplen e intentará enviar paquetes basándose en la longitud original del paquete. Pueden ocurrir cosas malas si especifica esta opción.

-L número, --limit=número

Limitar el número de paquetes a enviar. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento. El valor de número está restringido a ser: 
mayor o igual que 1

El número por defecto para esta opción es:
-1

Por defecto, tcpreplay enviará todos los paquetes. Alternativamente, puede especificar un número máximo de paquetes a enviar.

--duration=número

Limitar el número de segundos a enviar. Esta opción puede aparecer hasta 1 vez. Esta opción toma un número entero como argumento. El valor de número está restringido a ser: 
mayor o igual que 1

El número por defecto para esta opción es:
-1

Por defecto, tcpreplay enviará todos los paquetes. Alternativamente, puede especificar un número máximo de segundos a transmitir.

-x cadena, --multiplier=cadena

Modificar la velocidad de reproducción a un múltiplo dado. Esta opción puede aparecer hasta 1 vez. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: pps, mbps, oneatatime, topspeed.

Especifique un valor para modificar la velocidad de reproducción de paquetes. Ejemplos:

        2.0 reproducirá el tráfico al doble de la velocidad capturada
        0.7 reproducirá el tráfico al 70% de la velocidad capturada
-p cadena, --pps=cadena

Reproducir paquetes a un número dado de paquetes por segundo. Esta opción puede aparecer hasta 1 vez. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: multiplier, mbps, oneatatime, topspeed.

Especifique un valor para regular la reproducción de paquetes a una tasa específica de paquetes por segundo. Ejemplos:

        200 reproducirá el tráfico a 200 paquetes por segundo
        0.25 reproducirá el tráfico a 15 paquetes por minuto
-M cadena, --mbps=cadena

Reproducir paquetes a Mbps dados. Esta opción puede aparecer hasta 1 vez. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: multiplier, pps, oneatatime, topspeed.

Especifique un valor de punto flotante para la tasa de Mbps a la que tcpreplay debe enviar paquetes.

-t, --topspeed

Reproducir paquetes lo más rápido posible. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: mbps, multiplier, pps, oneatatime.
-o, --oneatatime

Reproducir un paquete a la vez por cada entrada del usuario. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: mbps, pps, multiplier, topspeed.

Le permite avanzar un paquete o varios a la vez.

--pps-multi=número

Número de paquetes a enviar por cada intervalo de tiempo. Esta opción debe aparecer en combinación con las siguientes opciones: pps. Esta opción toma un número entero como argumento. El valor de número está restringido a ser: 
mayor o igual que 1

El número por defecto para esta opción es:
1

Al intentar enviar paquetes a tasas muy altas, el tiempo entre cada paquete puede ser tan corto que es imposible dormir con precisión durante el período de tiempo requerido. Esta opción le permite enviar varios paquetes a la vez, lo que permite tiempos de espera más largos que se pueden implementar con mayor precisión.

--unique-ip

Modificar las direcciones IP en cada iteración del bucle para generar flujos únicos. Esta opción debe aparecer en combinación con las siguientes opciones: loop.

Asegura que los paquetes IPv4 e IPv6 sean únicos para cada iteración de --loop. Esto se hace de manera que no alterará la CRC del paquete y, por lo tanto, generalmente no afectará el rendimiento. Esta opción aumentará significativamente los flujos/segundo generados en múltiples iteraciones de bucle.

--unique-ip-loops=cadena

Número de veces que se repite el bucle antes de asignar una nueva IP única. Esta opción puede aparecer hasta 1 vez. Esta opción debe aparecer en combinación con las siguientes opciones: unique-ip.

Número de iteraciones de --loop antes de que se asigne una nueva IP única. El valor por defecto es 1. Asume tanto --loop como --unique-ip.

--netmap

Escribir paquetes directamente en el adaptador de red habilitado para netmap.

Esta función detectará los controladores de red compatibles con netmap en sistemas Linux y BSD. Si se detectan, el controlador de red se omite durante la ejecución, y los búferes de red se escribirán directamente. Esto le permitirá alcanzar velocidades de línea completas en adaptadores de red genéricos, similares a las velocidades alcanzadas por los generadores de tráfico de red comerciales. Tenga en cuenta que omitir el controlador de red interrumpirá otras aplicaciones conectadas a través de la interfaz de prueba. Consulte INSTALL para obtener más información.

Esta función también se puede habilitar especificando una interfaz como 'netmap:<intf>' o 'vale:<intf>'. Por ejemplo, 'netmap:eth0' especifica netmap sobre la interfaz eth0.

--nm-delay=número

Retardo de inicio de Netmap. Esta opción toma un número entero como argumento. El número por defecto para esta opción es:
10

Número de segundos de espera después de que se cargue netmap. Requerido para asegurar que las interfaces estén completamente activas antes de la transmisión de netmap. Requiere la opción netmap. El valor por defecto es 10 segundos.

--no-flow-stats

Suprimir la impresión y el seguimiento del recuento de flujos, tasas y expiraciones.

Suprime la recopilación y la impresión de estadísticas de flujos. Esta opción puede mejorar el rendimiento cuando no se utiliza la opción --preload-pcap, de lo contrario, su única función es suprimir la impresión.

La función de flujo rastreará e imprimirá estadísticas de los flujos que se están enviando. Un flujo se define de forma general como una combinación única de una tupla de 5 elementos, es decir, IP de origen, IP de destino, puerto de origen, puerto de destino y protocolo.

Si se especifica --loop, los flujos de una iteración a la siguiente no serán únicos, a menos que los paquetes se alteren. Utilice --unique-ip o tcpreplay-edit para alterar los paquetes entre iteraciones.

--flow-expiry=número

Número de segundos de inactividad antes de que un flujo se considere expirado. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: no-flow-stats. Esta opción toma un número entero como argumento. El valor de número está restringido a ser: 
mayor o igual que 0

El número por defecto para esta opción es:
0

Esta opción rastreará e informará sobre las expiraciones de flujos basándose en los tiempos de inactividad de los flujos. Las marcas de tiempo dentro del archivo pcap se utilizan para determinar la expiración, no la marca de tiempo real de los paquetes que se reproducen. Por ejemplo, un valor de 30 sugiere que si no se ve tráfico en un flujo durante 30 segundos, cualquier tráfico posterior se consideraría un nuevo flujo y, por lo tanto, incrementará las estadísticas de flujos y flujos por segundo (fps).

Esta opción se puede utilizar para optimizar la configuración de tiempo de espera de flujos para productos de flujo. Establecer el tiempo de espera bajo puede provocar que los flujos se caigan cuando en realidad el flujo solo responde lentamente. Configurar los tiempos de espera de sus flujos demasiado altos puede aumentar los recursos requeridos por su producto de flujo.

Tenga en cuenta que usar esta opción al reproducir a velocidades superiores a las originales puede generar recuentos inflados de flujos y fps.

El valor por defecto es 0 (sin expiración) y un valor típico es de 30-120 segundos.
