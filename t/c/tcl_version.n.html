tclvars(n) Comandos integrados de Tcl tclvars(n)

NOMBRE

argc, argv, argv0, auto_path, env, errorCode, errorInfo, tcl_interactive, tcl_library, tcl_nonwordchars, tcl_patchLevel, tcl_pkgPath, tcl_platform, tcl_precision, tcl_rcFileName, tcl_traceCompile, tcl_traceExec, tcl_wordchars, tcl_version - Variables utilizadas por Tcl

DESCRIPCIÓN

Las siguientes variables globales son creadas y gestionadas automáticamente por la biblioteca Tcl. Excepto donde se indica a continuación, estas variables normalmente deben ser tratadas como de solo lectura por el código específico de la aplicación y por los usuarios.

auto_path
Si está configurada, debe contener una lista Tcl válida que indique los directorios a buscar durante las operaciones de carga automática (incluyendo los archivos de índice de paquetes cuando se utiliza el controlador predeterminado package unknown). Esta variable se inicializa durante el inicio para contener, en orden: los directorios listados en la variable de entorno TCLLIBPATH, el directorio nombrado por la variable global tcl_library, el directorio padre de tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, los directorios listados en la variable tcl_pkgPath. Ubicaciones adicionales para buscar archivos e índices de paquetes normalmente deben agregarse a esta variable usando lappend.

Existen variables adicionales relacionadas con la gestión de paquetes. Se detallan más en la sección VARIABLES de la página del manual library.

env
Esta variable es mantenida por Tcl como un array cuyos elementos son las variables de entorno del proceso. Leer un elemento devolverá el valor de la variable de entorno correspondiente. Establecer un elemento del array modificará la variable de entorno correspondiente o creará una nueva si no existe. Quitar un elemento de env eliminará la variable de entorno correspondiente. Los cambios en el array env afectarán al entorno que se pasa a los hijos mediante comandos como exec. Si se quita todo el array env, Tcl dejará de monitorizar los accesos a env y no actualizará las variables de entorno.

En Windows, las variables de entorno PATH y COMSPEC en cualquier combinación de mayúsculas y minúsculas se convierten automáticamente a mayúsculas. Por ejemplo, la variable PATH puede ser exportada por el sistema operativo como “path”, “Path”, “PaTh”, etc., lo que hace que el código Tcl simple tenga que soportar muchos casos especiales. Todas las demás variables de entorno heredadas por Tcl se mantienen sin modificaciones. Establecer una variable de array env a vacío es lo mismo que quitarla, ya que este es el comportamiento del sistema operativo Windows subyacente. Cabe señalar que depender de una variable de entorno existente y vacía no funcionará en Windows y se desaconseja su uso entre plataformas.

Los siguientes elementos de env son especiales para Tcl:

env(HOME)
Esta variable de entorno, si está configurada, indica la ubicación del directorio considerado como el directorio de inicio del usuario actual, y al cual se cambiará al ejecutar cd sin argumentos o solo con “~” como argumento. La mayoría de las plataformas lo configuran correctamente por defecto; normalmente no necesita ser configurado por el código del usuario.
env(TCL_LIBRARY)
Si está configurada, especifica la ubicación del directorio que contiene los scripts de biblioteca (el valor de esta variable se asignará a la variable tcl_library y, por lo tanto, lo devolverá el comando info library). Si esta variable no está configurada, se utiliza un valor predeterminado.

Tenga en cuenta que esta variable de entorno *no* debe ser configurada normalmente.

env(TCLLIBPATH)
Si está configurada, debe contener una lista Tcl válida que indique los directorios a buscar durante las operaciones de carga automática. Los directorios deben especificarse en formato Tcl, usando “/” como separador de ruta, independientemente de la plataforma. Esta variable solo se utiliza al inicializar la variable auto_path.
env(TCL_TZ), env(TZ)
Estos especifican la zona horaria predeterminada utilizada para analizar y formatear fechas y horas en el comando clock. En muchas plataformas, la variable de entorno TZ la configura el sistema operativo.
env(LC_ALL), env(LC_MESSAGES), env(LANG)
Estas variables de entorno son utilizadas por el paquete msgcat para determinar qué local se debe utilizar para formatear los mensajes.
env(TCL_INTERP_DEBUG_FRAME)
Si existe, tiene el mismo efecto que ejecutar interp debug {} -frame 1 como primer comando de cada nuevo intérprete Tcl.
errorCode
Esta variable contiene el valor de la opción de retorno -errorcode establecida por el error más reciente ocurrido en este intérprete. Este valor de lista representa información adicional sobre el error en un formato fácil de procesar por programas. El primer elemento de la lista identifica una clase general de errores y determina el formato del resto de la lista. Los siguientes formatos para las opciones de retorno -errorcode son utilizados por el núcleo de Tcl; las aplicaciones individuales pueden definir formatos adicionales.
ARITH código mensaje
Este formato se utiliza cuando ocurre un error aritmético (por ejemplo, un intento de dividir cero por cero en el comando expr). Código identifica el error preciso y mensaje proporciona una descripción legible del error. Código será DIVZERO (por intento de dividir por cero), DOMAIN (si un argumento está fuera del dominio de una función, como acos(-3)), IOVERFLOW (por desbordamiento de enteros), OVERFLOW (por desbordamiento de punto flotante), o UNKNOWN (si la causa del error no se puede determinar).

La detección de estos errores depende en parte del hardware y las bibliotecas del sistema subyacentes.

CHILDKILLED pid nombre_señal mensaje
Este formato se utiliza cuando un proceso hijo ha sido terminado debido a una señal. El elemento pid será el identificador del proceso (en decimal). El elemento nombre_señal será el nombre simbólico de la señal que provocó la terminación del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGPIPE. El elemento mensaje será un mensaje corto y legible que describe la señal, como “write on pipe with no readers” para SIGPIPE.
CHILDSTATUS pid código
Este formato se utiliza cuando un proceso hijo ha salido con un estado de salida distinto de cero. El elemento pid será el identificador del proceso (en decimal) y el elemento código será el código de salida devuelto por el proceso (también en decimal).
CHILDSUSP pid nombre_señal mensaje
Este formato se utiliza cuando un proceso hijo ha sido suspendido debido a una señal. El elemento pid será el identificador del proceso, en decimal. El elemento nombre_señal será el nombre simbólico de la señal que provocó la suspensión del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGTTIN. El elemento mensaje será un mensaje corto y legible que describe la señal, como “background tty read” para SIGTTIN.
NONE
Este formato se utiliza para errores en los que no hay información adicional disponible más allá del mensaje devuelto con el error. En estos casos, la opción de retorno -errorcode consistirá en una lista que contiene un solo elemento cuyo contenido es NONE.

TCL ...
Indica algún tipo de problema generado en relación con Tcl mismo, por ejemplo, un fallo al buscar un canal o una variable.

Para establecer la opción de retorno -errorcode, las aplicaciones deben usar procedimientos de biblioteca como Tcl_SetObjErrorCode, Tcl_SetReturnOptions y Tcl_PosixError, o pueden invocar la opción -errorcode del comando return. Si no se ha utilizado ninguno de estos métodos para establecer el código de error, el intérprete de Tcl restablecerá la variable a NONE después del próximo error.

errorInfo
Esta variable contiene el valor de la opción de retorno -errorinfo establecida por el error más reciente que ocurrió en este intérprete. Este valor de cadena contendrá una o más líneas que identifican los comandos y procedimientos de Tcl que se estaban ejecutando cuando ocurrió el error más reciente. Su contenido tiene la forma de un rastreo de pila que muestra los diversos comandos anidados de Tcl que se habían invocado en el momento del error.
tcl_library
Esta variable contiene el nombre de un directorio que contiene la biblioteca del sistema de scripts de Tcl, como los utilizados para la carga automática. El valor de esta variable es devuelto por el comando info library. Consulte la entrada de manual de library para obtener detalles sobre las instalaciones proporcionadas por la biblioteca de scripts de Tcl. Normalmente, cada aplicación o paquete tendrá su propia biblioteca de scripts específica de la aplicación además de la biblioteca de scripts de Tcl; cada aplicación debe establecer una variable global con un nombre como $app_library (donde app es el nombre de la aplicación) para contener el nombre de archivo de red del directorio de la biblioteca de esa aplicación. El valor inicial de tcl_library se establece cuando se crea un intérprete buscando en varios directorios diferentes hasta que se encuentra uno que contiene un script de inicio de Tcl apropiado. Si la variable de entorno TCL_LIBRARY existe, entonces se verifica primero el directorio al que apunta. Si TCL_LIBRARY no está configurada o no se refiere a un directorio apropiado, entonces Tcl verifica varios otros directorios basándose en una ubicación predeterminada compilada, la ubicación del binario que contiene la aplicación y el directorio de trabajo actual.
tcl_patchLevel
Cuando se crea un intérprete, Tcl inicializa esta variable para que contenga una cadena que indique el nivel de parche actual para Tcl, como 8.4.16 para Tcl 8.4 con los primeros dieciséis parches oficiales, o 8.5b3 para la tercera versión beta de Tcl 8.5. El valor de esta variable es devuelto por el comando info patchlevel.
tcl_pkgPath
Esta variable contiene una lista de directorios que indican dónde se instalan normalmente los paquetes. No se utiliza en Windows. Normalmente contiene una o dos entradas; si contiene dos entradas, la primera es normalmente un directorio para paquetes dependientes de la plataforma (por ejemplo, bibliotecas compartidas binarias) y la segunda es normalmente un directorio para paquetes independientes de la plataforma (por ejemplo, archivos de script). Normalmente, un paquete se instala como un subdirectorio de una de las entradas de la variable tcl_pkgPath. Los directorios de la variable tcl_pkgPath se incluyen por defecto en la variable auto_path, por lo que se buscan automáticamente ellos y sus subdirectorios inmediatos en busca de paquetes durante los comandos package require. Nota: tcl_pkgPath no está destinada a ser modificada por la aplicación. Su valor se añade a auto_path al arranque; los cambios en tcl_pkgPath no se reflejan en auto_path. Si desea que Tcl busque directorios adicionales para paquetes, debe añadir los nombres de esos directorios a auto_path, no a tcl_pkgPath.
tcl_platform
Esta es una matriz asociativa cuyos elementos contienen información sobre la plataforma en la que se está ejecutando la aplicación, como el nombre del sistema operativo, su número de versión actual y el conjunto de instrucciones de la máquina. Los elementos que se enumeran a continuación siempre estarán definidos, pero pueden tener cadenas vacías como valores si Tcl no pudo recuperar ninguna información relevante. Además, las extensiones y aplicaciones pueden añadir valores adicionales a la matriz. Los elementos predefinidos son:
byteOrder
El orden de bytes nativo de esta máquina: littleEndian o bigEndian.
debug
Si esta variable existe, entonces el intérprete se compiló y enlazó con un tiempo de ejecución de C habilitado para depuración. Esta variable solo existirá en Windows, por lo que los escritores de extensiones pueden especificar qué paquete cargar dependiendo de la biblioteca de tiempo de ejecución de C que se esté utilizando. Esto no es una indicación de que este núcleo contenga símbolos.
engine
El nombre de la implementación del lenguaje Tcl. Cuando se crea el intérprete por primera vez, siempre se establece en la cadena Tcl.
machine
El conjunto de instrucciones ejecutado por esta máquina, como intel, PPC, 68k o sun4m. En máquinas UNIX, este es el valor devuelto por uname -m.
os
El nombre del sistema operativo que se ejecuta en esta máquina, como Windows NT o SunOS. En máquinas UNIX, este es el valor devuelto por uname -s.
osVersion
El número de versión del sistema operativo que se ejecuta en esta máquina. En máquinas UNIX, este es el valor devuelto por uname -r.
pathSeparator
El carácter que debe usarse para dividir variables de entorno tipo PATH en su lista correspondiente de nombres de directorio.
platform
windows o unix. Esto identifica el entorno operativo general de la máquina.
pointerSize
Esto da el tamaño del puntero nativo de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(void*) en C).
threaded
Si esta variable existe, entonces el intérprete se compiló con hilos habilitados.
user
Esto identifica al usuario actual basándose en la información de inicio de sesión disponible en la plataforma. Este valor proviene de las llamadas al sistema getuid() y getpwuid() en Unix, y del valor de la llamada al sistema GetUserName() en Windows.
wordSize
Esto da el tamaño de la palabra nativa de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(long) en C).
tcl_precision
Esta variable controla el número de dígitos a generar al convertir valores de punto flotante a cadenas. Por defecto es 0. Las aplicaciones no deben cambiar este valor; se proporciona para compatibilidad con código heredado.
El valor predeterminado de 0 es especial, lo que significa que Tcl debe convertir números utilizando tantos dígitos como sea posible sin dejar de distinguir cualquier número de punto flotante de sus vecinos más cercanos. Difiere de usar un valor arbitrariamente alto para tcl_precision en que un número inexacto como 1.4 se convertirá como 1.4 en lugar de 1.3999999999999999, aunque este último esté más cerca del valor exacto del número binario.
Si tcl_precision no es cero, entonces cuando Tcl convierte un número de punto flotante, crea una representación decimal de como máximo tcl_precision dígitos significativos; el resultado puede ser más corto si el resultado más corto representa el número original exactamente. Si no hay ningún resultado de como máximo tcl_precision dígitos que sea una representación exacta del número original, se elige el que esté más cerca del número original. Si el número original se encuentra precisamente entre dos representaciones decimales igualmente precisas, se elige la que tenga un valor par para el dígito menos significativo; por ejemplo, si tcl_precision es 3, entonces 0.3125 se convertirá en 0.312, no en 0.313, mientras que 0.6875 se convertirá en 0.688, no en 0.687. Se recortan los ceros finales que queden.
Un valor de tcl_precision de 17 dígitos es "perfecto" para punto flotante IEEE, ya que permite que los valores de doble precisión se conviertan a cadenas y de vuelta a binario sin pérdida de información. Por esta razón, a menudo se ve como un valor en código heredado que debe ejecutarse en versiones de Tcl anteriores a la 8.5. Ya no se recomienda; como se señaló anteriormente, un valor cero es el método preferido.
Todos los intérpretes de un hilo comparten un único valor de tcl_precision: cambiarlo en un intérprete afectará a todos los demás intérpretes. A los intérpretes seguros no se les permite modificar la variable.
Los valores válidos para tcl_precision van de 0 a 17.
tcl_rcFileName
Esta variable se utiliza durante la inicialización para indicar el nombre de un archivo de inicio específico del usuario. Si es establecida por la inicialización específica de la aplicación, el código de inicio de Tcl verificará la existencia de este archivo y lo cargará (source) si existe. Por ejemplo, para wish la variable se establece en ~/.wishrc para Unix y en ~/wishrc.tcl para Windows.
tcl_traceCompile
El valor de esta variable se puede establecer para controlar cuánta información de rastreo se muestra durante la compilación de bytecode. Por defecto, tcl_traceCompile es cero y no se muestra información. Establecer tcl_traceCompile en 1 genera un resumen de una línea en stdout cada vez que se compila un procedimiento o un comando de nivel superior. Establecerlo en 2 genera una lista detallada en stdout de las instrucciones de bytecode emitidas durante cada compilación. Esta variable es útil para rastrear posibles problemas con el compilador de Tcl.
Esta variable y funcionalidad solo existen si TCL_COMPILE_DEBUG se definió durante la compilación de Tcl.

NAME

tcl_traceExec, tcl_wordchars, tcl_nonwordchars, tcl_version — Tcl global variables

DESCRIPTION

tcl_traceExec
El valor de esta variable puede establecerse para controlar cuánta información de rastreo se muestra durante la ejecución del bytecode. Por defecto, tcl_traceExec es cero y no se muestra información. Establecer tcl_traceExec a 1 genera un rastreo de una línea en stdout en cada llamada a un procedimiento Tcl. Establecerlo a 2 genera una línea de salida cada vez que se invoca cualquier comando Tcl que contenga el nombre del comando y sus argumentos. Establecerlo a 3 produce un rastreo detallado que muestra el resultado de la ejecución de cada instrucción de bytecode. Tenga en cuenta que cuando tcl_traceExec es 2 o 3, los comandos como set e incr que han sido completamente reemplazados por una secuencia de instrucciones de bytecode no se muestran. Establecer esta variable es útil para rastrear posibles problemas con el compilador e intérprete de bytecode.
Esta variable y funcionalidad solo existen si TCL_COMPILE_DEBUG se definió durante la compilación de Tcl.
tcl_wordchars
El valor de esta variable es una expresión regular que se puede establecer para controlar qué se consideran caracteres de “palabra”, para instancias como la selección de una palabra con doble clic en el texto en Tk. Depende de la plataforma. En Windows, por defecto es \S, lo que significa cualquier cosa que no sea un espacio Unicode. De lo contrario, por defecto es \w, que es cualquier carácter de palabra Unicode (número, letra o guión bajo).
tcl_nonwordchars
El valor de esta variable es una expresión regular que se puede establecer para controlar qué se consideran caracteres de “no palabra”, para instancias como la selección de una palabra con doble clic en el texto en Tk. Depende de la plataforma. En Windows, por defecto es \s, lo que significa cualquier carácter de espacio Unicode. De lo contrario, por defecto es \W, que es cualquier cosa que no sea un carácter de palabra Unicode (número, letra o guión bajo).
tcl_version
Cuando se crea un intérprete, Tcl inicializa esta variable para que contenga el número de versión de esta versión de Tcl en el formato x.y. Los cambios en x representan cambios importantes con probables incompatibilidades y los cambios en y representan pequeñas mejoras y correcciones de errores que conservan la compatibilidad con versiones anteriores. El valor de esta variable se devuelve mediante el comando info tclversion.

OTRAS VARIABLES GLOBALES

Las siguientes variables solo se garantizan que existen en los ejecutables tclsh y wish; la biblioteca Tcl no las define por sí misma, pero muchos entornos Tcl sí lo hacen.

argc
El número de argumentos para tclsh o wish.
argv
Lista Tcl de argumentos para tclsh o wish.
argv0
El script que tclsh o wish comenzó a ejecutar (si se especificó) o, de lo contrario, el nombre por el cual se invocó tclsh o wish.
tcl_interactive
Contiene 1 si tclsh o wish se están ejecutando interactivamente (no se especificó ningún script y la entrada estándar es un dispositivo similar a una terminal), 0 en caso contrario.

EJEMPLOS

Para agregar un directorio a la colección de ubicaciones buscadas por package require, por ejemplo, debido a algunos paquetes específicos de la aplicación que se utilizan, es necesario actualizar la variable auto_path:

lappend ::auto_path [file join [pwd] "theLibDir"]

Una forma simple, aunque no muy robusta, de manejar argumentos de línea de comandos de la forma “-foo 1 -bar 2” es cargarlos en un array después de haber cargado primero la configuración predeterminada:

array set arguments {-foo 0 -bar 0 -grill 0}
array set arguments $::argv
puts "foo es $arguments(-foo)"
puts "bar es $arguments(-bar)"
puts "grill es $arguments(-grill)"

La variable global argv0 se puede usar (junto con el comando info script) para determinar si el script actual se está ejecutando como el script principal o se carga como una biblioteca. Esto es útil porque permite que un solo script se utilice tanto como biblioteca como demostración de esa biblioteca:

if {$::argv0 eq [info script]} {
    # ejecutándose como: tclsh example.tcl
} else {
    package provide Example 1.0
}
