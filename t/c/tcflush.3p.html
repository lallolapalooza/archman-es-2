TCFLUSH(3P) Manual del programador POSIX TCFLUSH(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

tcflush — vacía datos de salida no transmitidos, datos de entrada no leídos, o ambos

SINOPSIS

#include <termios.h>
int tcflush(int fildes, int queue_selector);

DESCRIPCIÓN

Al completarse correctamente, tcflush() vaciará los datos escritos en el objeto al que se refiere fildes (un descriptor de archivo abierto asociado a una terminal) pero no transmitidos, o los datos recibidos pero no leídos, dependiendo del valor de queue_selector:

*
Si queue_selector es TCIFLUSH, vaciará los datos recibidos pero no leídos.
*
Si queue_selector es TCOFLUSH, vaciará los datos escritos pero no transmitidos.
*
Si queue_selector es TCIOFLUSH, vaciará tanto los datos recibidos pero no leídos como los datos escritos pero no transmitidos.

Los intentos de usar tcflush() desde un proceso que es miembro de un grupo de procesos en segundo plano en un fildes asociado a su terminal de control provocarán que el grupo de procesos reciba una señal SIGTTOU. Si el hilo que llama está bloqueando las señales SIGTTOU o el proceso está ignorando las señales SIGTTOU, se permitirá al proceso realizar la operación y no se enviará ninguna señal.

VALOR DEVUELTO

Al completarse correctamente, se devolverá 0. De lo contrario, se devolverá -1 y errno se establecerá para indicar el error.

ERRORES

La función tcflush() fallará si:

EBADF
El argumento fildes no es un descriptor de archivo válido.
EINVAL
El argumento queue_selector no es un valor compatible.
EIO
El grupo de procesos del proceso de escritura está huerfano, el hilo que llama no está bloqueando SIGTTOU y el proceso no está ignorando SIGTTOU.
ENOTTY
El archivo asociado con fildes no es una terminal.
