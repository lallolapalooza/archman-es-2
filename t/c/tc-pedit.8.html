NOMBRE

pedit - acción genérica de editor de paquetes

SINOPSIS


tc ... action pedit [ex] munge { OPERACION_CRUDA | OPERACION_EN_CAPAS | OPERACION_EN_CAPAS_EXTENDIDA } [ CONTROL ]

OPERACION_CRUDA := offset OFFSET { u8 | u16 | u32 } [ AT_SPEC ] CMD_SPEC

AT_SPEC := at AT offmask MASK shift SHIFT

OPERACION_EN_CAPAS := { ip CAMPO_CABECERA_IP | ip CAMPO_MAS_ALLA_CABECERA_IP } CMD_SPEC

OPERACION_EN_CAPAS_EXTENDIDA := { eth CAMPO_CABECERA_ETH | ip CAMPO_CABECERA_IP | ip CAMPO_CABECERA_IP_EX | ip6 CAMPO_CABECERA_IP6 | tcp CAMPO_CABECERA_TCP | udp CAMPO_CABECERA_UDP } CMD_SPEC

CAMPO_CABECERA_ETH := { src | dst | type }

CAMPO_CABECERA_IP := { src | dst | tos | dsfield | ihl | protocol | precedence | nofrag | firstfrag | ce | df }

CAMPO_MAS_ALLA_CABECERA_IP := { dport | sport | icmp_type | icmp_code }

CAMPO_CABECERA_IP_EX := { ttl }

CAMPO_CABECERA_IP6 := { src | dst | traffic_class | flow_lbl | payload_len | nexthdr | hoplimit }

CAMPO_CABECERA_TCP := { sport | dport | flags }

CAMPO_CABECERA_UDP := { sport | dport }

CMD_SPEC := { clear | invert | set VAL | add VAL | decrement | preserve } [ retain RVAL ]

CONTROL := { reclassify | pipe | drop | shot | continue | pass | goto chain INDICE_CADENA }

DESCRIPCIÓN

La acción pedit se puede usar para cambiar datos arbitrarios de paquetes. La ubicación de los datos a cambiar se puede especificar indicando un desplazamiento y un tamaño como en OPERACION_CRUDA, o para valores de cabecera nombrando la cabecera y el campo a editar, el tamaño se elige automáticamente basándose en el tamaño del campo de cabecera.

OPCIONES

ex
Usa pedit extendido. OPERACION_EN_CAPAS_EXTENDIDA y las operaciones CMD_SPEC de suma/decremento solo están permitidas en este modo.
offset DESPLAZAMIENTO { u32 | u16 | u8 }
Especifica el desplazamiento donde cambiar los datos. DESPLAZAMIENTO es un entero con signo, su base se elige automáticamente (p. ej., hexadecimal si va precedido por 0x u octal si va precedido por 0). El segundo argumento especifica la longitud de los datos a cambiar, que son cuatro bytes (u32), dos bytes (u16) o un solo byte (u8).
at EN offmask MASK shift SHIFT
Esta es una parte opcional de OPERACION_CRUDA que permite tener un DESPLAZAMIENTO variable dependiendo de los datos del paquete en el desplazamiento EN, que se combina con AND binario con MASK y se desplaza a la derecha por SHIFT antes de sumarlo a DESPLAZAMIENTO.
eth CAMPO_CABECERA_ETH
Cambia un campo de cabecera ETH. Las palabras clave soportadas para CAMPO_CABECERA_ETH son:
src
dst
Dirección MAC de origen o destino en el formato estándar: XX:XX:XX:XX:XX:XX
type
Tipo Ether en valor numérico
ip CAMPO_CABECERA_IP
Cambia un campo de cabecera IPv4. Las palabras clave soportadas para CAMPO_CABECERA_IP son:
src
dst
Dirección IP de origen o destino, un valor de cuatro bytes.
tos
dsfield
precedence
Campo Tipo de Servicio, un valor de ocho bits.
ihl
Cambia el campo Longitud de Cabecera IP, un valor de cuatro bits.
protocol
Campo Protocolo de la siguiente capa, un valor de ocho bits.
nofrag
firstfrag
ce
df
mf
Cambia las banderas de la cabecera IP. Ten en cuenta que el valor a pasar al comando set no es solo un valor de bit, sino el byte completo que incluye el campo de banderas. Aunque solo se respetan los bits relevantes de ese valor, el resto se ignora.
ip CAMPO_MAS_ALLA_CABECERA_IP
Soportado solo para la operación en capas no extendida. Se pasa al kernel como desplazamientos relativos al inicio de la cabecera IP y asume que la cabecera IP es de tamaño mínimo (20 bytes). Las palabras clave soportadas para CAMPO_MAS_ALLA_CABECERA_IP son:
dport
sport
Números de puerto de destino o origen, un valor de 16 bits. De hecho, las cabeceras IPv4 no contienen esta información. En su lugar, esto establecerá un desplazamiento que se ajusta al menos a TCP y UDP si la cabecera IP es de tamaño mínimo (20 bytes). Si no es así, hará cosas inesperadas.
icmp_type
icmp_code
De nuevo, esto permite cambiar datos más allá de la propia cabecera IP. Asume que hay una cabecera ICMP inmediatamente después de la cabecera IP (de tamaño mínimo). Si no es así o esta última es mayor que el mínimo de 20 bytes, esto hará cosas inesperadas. Estos campos son valores de ocho bits.
ip CAMPO_CABECERA_IP_EX
Soportado solo cuando se usa ex. Las palabras clave soportadas para CAMPO_CABECERA_IP_EX son:
ttl
ip6 CAMPO_CABECERA_IP6
Las palabras clave soportadas para CAMPO_CABECERA_IP6 son:
src
dst
traffic_class
flow_lbl
payload_len
nexthdr
hoplimit
tcp CAMPO_CABECERA_TCP
Las palabras clave soportadas para CAMPO_CABECERA_TCP son:
sport
dport
Número de puerto TCP de origen o destino, un valor de 16 bits.
flags
udp CAMPO_CABECERA_UDP

NOMBRE

tc-pedit - packet editor action

SINOPSIS

tc ... action pedit [obj OBJ] [cmd CMD] [index INDEX] [off OFF] [mask MASK] [fmt FMT] [ex]

DESCRIPCIÓN

The pedit action allows modification of packet data. It is used for example in order to implement transparent proxying or NAT, or to modify packet headers for other reasons.

The action has the following syntax:

pedit PED_CMD at PED_OFF to PED_VAL [mask PED_MASK] [off PED_OFF2] [fmt PED_FMT] [ex]

Where PED_CMD is one of the following keywords:

pedit
Can be used multiple times to specify several modifications.
munge
Modify the field at PED_OFF by using the value specified in PED_VAL. The size of the field is determined by PED_FMT. If mask is present, only the bits that are set in PED_MASK will be modified.
save
Save the field at PED_OFF into the buffer provided by PED_OFF2. The size of the field is determined by PED_FMT. If mask is present, only the bits that are set in PED_MASK will be saved.
load
Load the field from PED_OFF2 into the field at PED_OFF. The size of the field is determined by PED_FMT. If mask is present, only the bits that are set in PED_MASK will be loaded.

PED_OFF specifies the offset from the beginning of the packet, in bytes. PED_OFF2 specifies another offset from the beginning of the packet, in bytes. PED_VAL is the value to be used for modifications, or it can be an offset too.

PED_MASK is a bitmask. If present, only bits that are set in the mask will be affected.

PED_FMT specifies the size of the field and is one of the following keywords:

u8
u16
u32
u64
eth
Ethernet header fields.
ip
IP header fields.
ip6
IP header fields.
tcp
TCP header fields.
udp
UDP header fields.
icmp
ICMP header fields.
icmp6
ICMP header fields.
arp
ARP header fields.
ldh
Lowest 16 bits of a 32 bits field.
mdh
Middle 16 bits of a 32 bits field.
hld
Highest 16 bits of a 32 bits field.
sport
Source TCP or UDP port number, a 16-bit value.
dport
Source or destination TCP port number, a 16-bit value.
clear
Clear the addressed data (i.e., set it to zero).
invert
Swap every bit in the addressed data.
set VAL
Set the addressed data to a specific value. The size of VAL is defined by either one of the u32, u16 or u8 keywords in RAW_OP, or the size of the addressed header field in LAYERED_OP.
add VAL
Add the addressed data by a specific value. The size of VAL is defined by the size of the addressed header field in EXTENDED_LAYERED_OP. This operation is supported only for extended layered op.
decrement
Decrease the addressed data by one. This operation is supported only for ip ttl and ip6 hoplimit.
preserve
Keep the addressed data as is.
retain RVAL
This optional extra part of CMD_SPEC allows one to exclude bits from being changed. Supported only for 32 bits fields or smaller.
CONTROL
The following keywords allow one to control how the tree of qdisc, classes, filters and actions is further traversed after this action.
reclassify
Restart with the first filter in the current list.
pipe
Continue with the next action attached to the same filter.
drop
shot
Drop the packet.
continue
Continue classification with the next filter in line.
pass
Finish classification process and return to calling qdisc for further packet processing. This is the default.

EJEMPLOS

Siendo capaz de editar datos de paquetes, uno podría hacer todo tipo de cosas, como por ejemplo implementar redirección de puertos. Ciertamente no es la aplicación más útil, pero como ejemplo debería ser suficiente:

Primero, se necesitan configurar qdiscs para adjuntar filtros. Para la ruta de recepción, un simple qdisc ingress será suficiente, para la ruta de transmisión es necesario un qdisc con clase (HTB en este caso):

tc qdisc replace dev eth0 root handle 1: htb
tc qdisc add dev eth0 ingress handle ffff:

Finalmente, se puede añadir un filtro con acción pedit para cada dirección. En este caso, se utiliza u32 coincidiendo con el número de puerto de origen, mientras que pedit realiza la reescritura real:

tc filter add dev eth0 parent 1: u32 \
	match ip dport 23 0xffff \
	action pedit pedit munge ip dport set 22
tc filter add dev eth0 parent ffff: u32 \
	match ip sport 22 0xffff \
	action pedit pedit munge ip sport set 23
tc filter add dev eth0 parent ffff: u32 \
	match ip sport 22 0xffff \
	action pedit ex munge ip dst set 192.168.1.199
tc filter add dev eth0 parent ffff: u32 \
	match ip sport 22 0xffff \
	action pedit ex munge ip6 dst set fe80::dacb:8aff:fec7:320e
tc filter add dev eth0 parent ffff: u32 \
	match ip sport 22 0xffff \
	action pedit ex munge eth dst set 11:22:33:44:55:66
tc filter add dev eth0 parent ffff: u32 \
	match ip dport 23 0xffff \
	action pedit ex munge tcp dport set 22

Para reescribir solo una parte de un campo, use la directiva retain. Por ejemplo, para sobrescribir la parte DSCP de un dsfield con $DSCP, sin tocar ECN:

tc filter add dev eth0 ingress flower ... \
	action pedit ex munge ip dsfield set $((DSCP << 2)) retain 0xfc

Y viceversa, para establecer ECN a, por ejemplo, 1 sin afectar a DSCP:

tc filter add dev eth0 ingress flower ... \
	action pedit ex munge ip dsfield set 1 retain 0x3
