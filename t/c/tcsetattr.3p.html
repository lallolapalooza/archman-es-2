TCSETATTR(3P) Manual del programador POSIX TCSETATTR(3P)

PRÓLOGO

Esta página del manual es parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

tcsetattr — establecer los parámetros asociados a la terminal

SINOPSIS

#include <termios.h>
int tcsetattr(int fildes, int optional_actions,
    const struct termios *termios_p);

DESCRIPCIÓN

La función tcsetattr() establecerá los parámetros asociados a la terminal a la que se refiere el descriptor de archivo abierto fildes (un descriptor de archivo abierto asociado a una terminal) desde la estructura termios referenciada por termios_p de la siguiente manera:

*
Si optional_actions es TCSANOW, el cambio se realizará inmediatamente.
*
Si optional_actions es TCSADRAIN, el cambio se realizará después de que toda la salida escrita en fildes sea transmitida. Esta función debe usarse al cambiar parámetros que afectan la salida.
*
Si optional_actions es TCSAFLUSH, el cambio se realizará después de que toda la salida escrita en fildes sea transmitida, y toda la entrada recibida hasta el momento pero no leída se descartará antes de que se realice el cambio.

Si la velocidad de baudios de salida almacenada en la estructura termios apuntada por termios_p es la velocidad de baudios cero, B0, las líneas de control del módem ya no se afirmarán. Normalmente, esto desconectará la línea.

Si la velocidad de baudios de entrada almacenada en la estructura termios apuntada por termios_p es 0, la velocidad de baudios de entrada dada al hardware será la misma que la velocidad de baudios de salida almacenada en la estructura termios.

La función tcsetattr() devolverá éxito si pudo realizar alguna de las acciones solicitadas, incluso si algunas de las acciones solicitadas no pudieron realizarse. Establecerá todos los atributos que la implementación soporta según lo solicitado y dejará sin cambios todos los atributos no soportados por la implementación. Si ninguna parte de la solicitud puede ser atendida, devolverá -1 y establecerá errno a [EINVAL]. Si las velocidades de baudios de entrada y salida difieren y son una combinación no soportada, ninguna de las velocidades de baudios se cambiará. Una llamada posterior a tcgetattr() devolverá el estado real del dispositivo terminal (reflejando tanto los cambios realizados como los no realizados en la llamada anterior a tcsetattr()). La función tcsetattr() no cambiará los valores encontrados en la estructura termios bajo ninguna circunstancia.

El efecto de tcsetattr() no está definido si el valor de la estructura termios apuntada por termios_p no se derivó del resultado de una llamada a tcgetattr() en fildes; una aplicación solo debe modificar campos y banderas definidos por este volumen de POSIX.1-2017 entre la llamada a tcgetattr() y tcsetattr(), dejando sin modificar todos los demás campos y banderas.

Ninguna acción definida por este volumen de POSIX.1-2017, aparte de una llamada a tcsetattr(), un cierre del último descriptor de archivo en el sistema asociado a este dispositivo terminal, o una apertura del primer descriptor de archivo en el sistema asociado a este dispositivo terminal (usando la bandera O_TTY_INIT si no es cero y el dispositivo no es un pseudoterminal), causará que alguno de los atributos del terminal definidos por este volumen de POSIX.1-2017 cambie.

Si tcsetattr() se llama desde un proceso que es miembro de un grupo de procesos en segundo plano en un fildes asociado a su terminal de control:

*
Si el hilo que llama está bloqueando las señales SIGTTOU o el proceso está ignorando las señales SIGTTOU, la operación se completa normalmente y no se envía ninguna señal.
*
De lo contrario, se enviará una señal SIGTTOU al grupo de procesos.

VALOR DEVUELTO

Al completarse con éxito, se devolverá 0. De lo contrario, se devolverá -1 y se establecerá errno para indicar el error.

ERRORES

La función tcsetattr() fallará si:

EBADF
El argumento fildes no es un descriptor de archivo válido.
EINTR
Una señal interrumpió tcsetattr().
EINVAL
El argumento optional_actions no es un valor soportado, o se intentó cambiar un atributo representado en la estructura termios a un valor no soportado.
EIO
El grupo de procesos del proceso de escritura está huérfano, el hilo que llama no está bloqueando SIGTTOU y el proceso no está ignorando SIGTTOU.
ENOTTY
El archivo asociado con fildes no es una terminal.

Las siguientes secciones son informativas.

EJEMPLOS

Ninguno.

USO POR LA APLICACIÓN

Si se intenta cambiar las velocidades de baudios, las aplicaciones deben llamar a tcsetattr() y luego llamar a tcgetattr() para determinar qué velocidades de baudios se seleccionaron realmente.

En general, hay dos razones para que una aplicación cambie los parámetros asociados a un dispositivo terminal:

1.
El dispositivo ya tiene configuraciones de parámetros de trabajo pero la aplicación necesita un comportamiento diferente, como el modo no canónico en lugar del modo canónico. La aplicación establece (o borra) solo unas pocas banderas o valores c_cc[]. Típicamente, el dispositivo terminal en este caso es la terminal de control para el proceso o un pseudoterminal.
2.
El dispositivo es un módem o un equipo similar conectado por una línea serie, y no estaba abierto antes de que la aplicación lo abriera. En este caso, la aplicación necesita inicializar todas las configuraciones de parámetros "desde cero". Sin embargo, dado que la estructura termios puede incluir parámetros estándar y no estándar, la aplicación no puede simplemente inicializar toda la estructura de forma arbitraria (por ejemplo, usando memset()) ya que esto podría hacer que algunos de los parámetros no estándar se establezcan incorrectamente, resultando en un comportamiento no conforme del dispositivo terminal. Por el contrario, la aplicación no puede simplemente establecer los parámetros estándar, asumiendo que los parámetros no estándar ya tendrán valores adecuados, ya que el dispositivo podría haber sido utilizado previamente con configuraciones de parámetros no conformes (y algunas implementaciones conservan las configuraciones de un uso a otro). La solución es abrir el dispositivo terminal usando la bandera O_TTY_INIT para inicializar el dispositivo terminal con configuraciones de parámetros conformes, obtener esas configuraciones usando tcgetattr(), y luego establecer todos los parámetros estándar a los valores deseados.

FUNDAMENTO

La función tcsetattr() puede ser interrumpida en las siguientes situaciones:

*
Se interrumpe mientras espera que la salida se vacíe.
*
Se llama desde un proceso en un grupo de procesos en segundo plano y se captura SIGTTOU.

Véase también la sección FUNDAMENTO en tcgetattr().

DIRECCIONES FUTURAS

El uso de una velocidad de baudios de entrada de 0 para establecer la tasa de entrada igual a la tasa de salida puede no ser necesariamente soportado en una versión futura de este volumen de POSIX.1-2017.

NAME

tcsetattr - set the parameters associated with the terminal

SYNOPSIS

#include <termios.h>

int tcsetattr(int fd, int optional_actions, const struct termios *termios_p);

DESCRIPTION

The tcsetattr() function sets the parameters associated with the terminal associated with the file descriptor fd to the values specified by the termios structure pointed to by termios_p.

The optional_actions argument specifies when the changes should be made, and can be one of the following values:

TCSANOW: The changes occur immediately.

TCSADRAIN: The changes occur after all output written to fd has been transmitted. This is useful after modifying settings that affect output, like character size or timing.

TCSAFLUSH: The changes occur after all output written to fd has been transmitted, and all input remaining on the file descriptor is discarded before the changes are made. This is useful when settings that affect input are changed.

RETURN VALUE

On success, tcsetattr() returns 0. On error, it returns -1 and sets errno to indicate the error.

ERRORS

EBADF: The file descriptor fd is not valid.

EINTR: A signal was caught during the execution of this function.

EPERM: The calling process does not have the appropriate permission to change the terminal attributes.

ENOTTY: The file descriptor fd is not associated with a terminal.
