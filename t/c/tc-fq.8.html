NOMBRE

FQ - Control de tráfico Fair Queue

SINOPSIS

tc qdisc ... fq [ limit PAQUETES ] [ flow_limit PAQUETES ] [ quantum BYTES ] [ initial_quantum BYTES ] [ maxrate TASA ] [ buckets NÚMERO ] [ orphan_mask NÚMERO ] [ pacing | nopacing ] [ ce_threshold TIEMPO ]

DESCRIPCIÓN

FQ (Fair Queue) es un planificador de paquetes sin clases diseñado principalmente para tráfico generado localmente. Está diseñado para lograr el espaciado por flujo. FQ realiza separación de flujos y es capaz de respetar los requisitos de espaciado establecidos por la pila TCP. Todos los paquetes pertenecientes a un socket se consideran un 'flujo'. Para paquetes no locales (carga de trabajo del enrutador), se utiliza el hash del paquete como respaldo.

Una aplicación puede especificar una tasa de espaciado máxima utilizando la llamada setsockopt SO_MAX_PACING_RATE. Este planificador de paquetes agrega retraso entre paquetes para respetar la limitación de tasa establecida en cada socket. Tenga en cuenta que después de linux-4.20, linux adoptó EDT (Earliest Departure Time) y TCP establece directamente el Tiempo de Salida apropiado para cada skb.

La salida ocurre de forma circular. Se reserva una cola FIFO especial para paquetes de alta prioridad (prioridad TC_PRIO_CONTROL), dichos paquetes siempre se sacan primero.

FQ no es conservador de trabajo.

El espaciado TCP es bueno para flujos con tiempos de inactividad, ya que la ventana de congestión permite que la pila TCP ponga en cola un número potencialmente grande de paquetes. Esto elimina la opción de 'arranque lento después de inactividad', que afecta negativamente a los flujos de BDP grandes y a las aplicaciones que entregan fragmentos de datos, como las transmisiones de video.

PARÁMETROS

limit

Límite estricto del tamaño real de la cola. Cuando se alcanza este límite, se descartan los nuevos paquetes. Si el valor se reduce, se descartan paquetes para cumplir el nuevo límite. Por defecto es 10000 paquetes.

flow_limit

Límite estricto del número máximo de paquetes en cola por flujo. El valor por defecto es 100.

quantum

El crédito por ronda de extracción RR, es decir, la cantidad de bytes que un flujo puede extraer a la vez. Un valor mayor significa un período de tiempo más largo antes de que se atienda el siguiente flujo. Por defecto son 2 * MTU de la interfaz bytes.

initial_quantum

El crédito de tasa de envío inicial, es decir, la cantidad de bytes que un nuevo flujo puede extraer inicialmente. Esto está destinado específicamente a permitir el uso de IW10 sin retrasos adicionales. Por defecto son 10 * MTU de la interfaz, es decir, 15140 para 'ethernet estándar'.

maxrate

Tasa máxima de envío de un flujo. Por defecto es ilimitada. La configuración específica de la aplicación a través de SO_MAX_PACING_RATE se ignora solo si es mayor que este valor.

buckets

El tamaño de la tabla hash utilizada para la búsqueda de flujos. A cada cubo se le asigna un árbol rojo-negro para una clasificación eficiente de colisiones. Por defecto: 1024.

orphan_mask

Para paquetes que no pertenecen a un socket, fq puede enmascarar una parte de skb->hash y reducir el número de cubos asociados con el tráfico. Este es un mecanismo de prevención de ataques DDoS, y el valor predeterminado es 1023 (lo que significa que no se asignan más de 1024 flujos para estos paquetes)

[no]pacing

Habilita o deshabilita el espaciado de flujo. Por defecto está habilitado.

ce_threshold

Establece un umbral por encima del cual todos los paquetes se marcan con ECN Congestion Experienced. Esto es útil para algoritmos de control de congestión del tipo DCTCP que requieren marcado en umbrales de cola muy bajos.

EJEMPLOS

#tc qdisc add dev eth0 root fq ce_threshold 4ms
#tc -s -d qdisc show dev eth0
qdisc fq 8001: dev eth0 root refcnt 2 limit 10000p flow_limit 100p buckets 1024 orphan_mask 1023 quantum 3028b initial_quantum 15140b low_rate_threshold 550Kbit refill_delay 40.0ms ce_threshold 4.0ms
