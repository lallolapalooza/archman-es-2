NOMBRE

tclsh - Shell simple que contiene el intérprete Tcl

SINOPSIS

tclsh ?-encoding nombre? ?archivoNombre arg arg ...?

DESCRIPCIÓN

Tclsh es una aplicación similar a un shell que lee comandos Tcl desde su entrada estándar o desde un archivo y los evalúa. Si se invoca sin argumentos, se ejecuta interactivamente, leyendo comandos Tcl de la entrada estándar e imprimiendo los resultados de los comandos y los mensajes de error en la salida estándar. Se ejecuta hasta que se invoca el comando exit o hasta que alcanza el fin de archivo en su entrada estándar. Si existe un archivo .tclshrc (o tclshrc.tcl en las plataformas Windows) en el directorio personal del usuario, el tclsh interactivo evalúa el archivo como un script Tcl justo antes de leer el primer comando de la entrada estándar.

ARCHIVOS DE SCRIPT

Si se invoca tclsh con argumentos, los primeros argumentos especifican el nombre de un archivo de script y, opcionalmente, la codificación de los datos de texto almacenados en ese archivo de script. Cualquier argumento adicional se pone a disposición del script como variables (ver más abajo). En lugar de leer comandos de la entrada estándar, tclsh leerá comandos Tcl del archivo especificado; tclsh saldrá cuando alcance el fin de archivo. El fin de archivo puede estar marcado por el fin físico del medio o por el carácter “\032” (“\u001a”, control-Z). Si este carácter está presente en el archivo, la aplicación tclsh leerá texto hasta, pero sin incluir, el carácter. Una aplicación que requiera este carácter en el archivo puede codificarlo de forma segura como “\032”, “\x1A”, o “\u001a”; o puede generarlo mediante comandos como format o binary. No hay evaluación automática de .tclshrc cuando se presenta el nombre de un archivo de script en la línea de comandos de tclsh, pero el archivo de script siempre puede sourcelo si se desea.

Si creas un script Tcl en un archivo cuya primera línea es

#!/usr/local/bin/tclsh

entonces puedes invocar el archivo de script directamente desde tu shell si marcas el archivo como ejecutable. Esto asume que tclsh se ha instalado en la ubicación predeterminada en /usr/local/bin; si se ha instalado en otro lugar, deberás modificar la línea anterior para que coincida. Muchos sistemas UNIX no permiten que la línea #! supere los 30 caracteres de longitud, así que asegúrate de que el ejecutable tclsh sea accesible con un nombre de archivo corto.

Un enfoque aún mejor es iniciar tus archivos de script con las siguientes tres líneas:

#!/bin/sh
# la siguiente línea reinicia usando tclsh \
exec tclsh "$0" ${1+"$@"}

Este enfoque tiene tres ventajas sobre el enfoque del párrafo anterior. Primero, la ubicación del binario tclsh no necesita estar codificada en el script: puede estar en cualquier lugar de tu ruta de búsqueda del shell. Segundo, evita el límite de 30 caracteres del nombre de archivo en el enfoque anterior. Tercero, este enfoque funcionará incluso si tclsh es en sí mismo un script de shell (esto se hace en algunos sistemas para manejar múltiples arquitecturas o sistemas operativos: el script tclsh selecciona uno de varios binarios para ejecutar). Las tres líneas hacen que tanto sh como tclsh procesen el script, pero exec solo lo ejecuta sh. sh procesa el script primero; trata la segunda línea como un comentario y ejecuta la tercera línea. La declaración exec hace que el shell deje de procesar y, en su lugar, inicie tclsh para reprocesar todo el script. Cuando tclsh se inicia, trata las tres líneas como comentarios, ya que la barra invertida al final de la segunda línea hace que la tercera línea se trate como parte del comentario en la segunda línea.

Debes tener en cuenta que también es una práctica común instalar tclsh con su número de versión como parte del nombre. Esto tiene la ventaja de permitir que múltiples versiones de Tcl existan en el mismo sistema a la vez, pero también la desventaja de dificultar la escritura de scripts que se inicien uniformemente en diferentes versiones de Tcl.

VARIABLES

Tclsh establece las siguientes variables globales de Tcl, además de las creadas por la propia biblioteca Tcl (como env, que mapea variables de entorno como PATH a Tcl):

argc
Contiene un recuento del número de argumentos arg (0 si no hay ninguno), sin incluir el nombre del archivo de script.
argv
Contiene una lista Tcl cuyos elementos son los argumentos arg, en orden, o una cadena vacía si no hay argumentos arg.
argv0
Contiene archivoNombre si se especificó. De lo contrario, contiene el nombre por el cual se invocó tclsh.
tcl_interactive
Contiene 1 si tclsh se está ejecutando interactivamente (no se especificó archivoNombre y la entrada estándar es un dispositivo similar a una terminal), 0 en caso contrario.

INDICADORES

Cuando tclsh se invoca interactivamente, normalmente solicita cada comando con “% ”. Puedes cambiar el indicador estableciendo las variables globales tcl_prompt1 y tcl_prompt2. Si la variable tcl_prompt1 existe, debe consistir en un script Tcl para imprimir un indicador; en lugar de imprimir un indicador, tclsh evaluará el script en tcl_prompt1. La variable tcl_prompt2 se utiliza de manera similar cuando se presiona una nueva línea pero el comando actual aún no está completo; si tcl_prompt2 no está establecido, no se imprime ningún indicador para comandos incompletos.
