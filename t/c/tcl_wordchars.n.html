tclvars(n) Comandos integrados de Tcl tclvars(n)

NOMBRE

argc, argv, argv0, auto_path, env, errorCode, errorInfo, tcl_interactive, tcl_library, tcl_nonwordchars, tcl_patchLevel, tcl_pkgPath, tcl_platform, tcl_precision, tcl_rcFileName, tcl_traceCompile, tcl_traceExec, tcl_wordchars, tcl_version - Variables usadas por Tcl

DESCRIPCIÓN

Las siguientes variables globales son creadas y gestionadas automáticamente por la biblioteca Tcl. Excepto donde se indica a continuación, estas variables normalmente deben ser tratadas como de solo lectura por el código específico de la aplicación y por los usuarios.

auto_path
Si está establecida, debe contener una lista Tcl válida que especifique directorios a buscar durante las operaciones de auto-carga (incluyendo archivos de índice de paquetes cuando se usa el manejador predeterminado package unknown). Esta variable se inicializa durante el inicio para contener, en orden: los directorios listados en la variable de entorno TCLLIBPATH, el directorio nombrado por la variable global tcl_library, el directorio padre de tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, los directorios listados en la variable tcl_pkgPath. Ubicaciones adicionales para buscar archivos e índices de paquetes normalmente deben añadirse a esta variable usando lappend.

Existen variables adicionales relacionadas con la gestión de paquetes. Se incluyen más detalles en la sección VARIABLES de la página del manual library.

env
Esta variable es mantenida por Tcl como un array cuyos elementos son las variables de entorno del proceso. Leer un elemento devolverá el valor de la variable de entorno correspondiente. Establecer un elemento del array modificará la variable de entorno correspondiente o creará una nueva si no existe. Desestablecer un elemento de env eliminará la variable de entorno correspondiente. Los cambios en el array env afectarán al entorno que se pasa a los hijos mediante comandos como exec. Si se desestablece todo el array env, Tcl dejará de monitorear los accesos a env y no actualizará las variables de entorno.

En Windows, las variables de entorno PATH y COMSPEC en cualquier capitalización se convierten automáticamente a mayúsculas. Por ejemplo, la variable PATH podría ser exportada por el sistema operativo como "path", "Path", "PaTh", etc., lo que obligaría al código Tcl, de lo contrario simple, a admitir muchos casos especiales. Todas las demás variables de entorno heredadas por Tcl se dejan sin modificar. Establecer una variable del array env a una cadena vacía es lo mismo que desestablecerla, ya que este es el comportamiento del sistema operativo Windows subyacente. Cabe señalar que depender de una variable de entorno existente y vacía no funcionará en Windows y se desaconseja para su uso multiplataforma.

Los siguientes elementos de env son especiales para Tcl:

env(HOME)
Esta variable de entorno, si está establecida, indica la ubicación del directorio considerado como el directorio de inicio del usuario actual, y al cual un comando cd sin argumentos o solo con "~" como argumento se dirigirá. La mayoría de las plataformas configuran esto correctamente por defecto; normalmente no necesita ser establecido por código de usuario.
env(TCL_LIBRARY)
Si está establecida, especifica la ubicación del directorio que contiene los scripts de biblioteca (el valor de esta variable se asignará a la variable tcl_library y, por lo tanto, será devuelto por el comando info library). Si esta variable no está establecida, se usa un valor predeterminado.

Tenga en cuenta que esta variable de entorno *normalmente no* debería establecerse.

env(TCLLIBPATH)
Si está establecida, debe contener una lista Tcl válida que especifique directorios a buscar durante las operaciones de auto-carga. Los directorios deben especificarse en formato Tcl, utilizando "/" como separador de ruta, independientemente de la plataforma. Esta variable solo se utiliza al inicializar la variable auto_path.
env(TCL_TZ), env(TZ)
Estos especifican la zona horaria predeterminada utilizada para analizar y formatear horas y fechas en el comando clock. En muchas plataformas, la variable de entorno TZ es configurada por el sistema operativo.
env(LC_ALL), env(LC_MESSAGES), env(LANG)
Estas variables de entorno son utilizadas por el paquete msgcat para determinar qué localización usar para formatear mensajes.
env(TCL_INTERP_DEBUG_FRAME)
Si existe, tiene el mismo efecto que ejecutar interp debug {} -frame 1 como el primer comando de cada nuevo intérprete Tcl.
errorCode
Esta variable contiene el valor de la opción de retorno -errorcode establecida por el error más reciente que ocurrió en este intérprete. Este valor de lista representa información adicional sobre el error en un formato que es fácil de procesar con programas. El primer elemento de la lista identifica una clase general de errores y determina el formato del resto de la lista. Los siguientes formatos para las opciones de retorno -errorcode son utilizados por el núcleo de Tcl; las aplicaciones individuales pueden definir formatos adicionales.
ARITH código msg
Este formato se utiliza cuando ocurre un error aritmético (por ejemplo, un intento de dividir cero por cero en el comando expr). código identifica el error preciso y msg proporciona una descripción legible por humanos del error. código será DIVZERO (por un intento de dividir por cero), DOMAIN (si un argumento está fuera del dominio de una función, como acos(-3)), IOVERFLOW (por desbordamiento de enteros), OVERFLOW (por desbordamiento de punto flotante) o UNKNOWN (si la causa del error no puede ser determinada).

La detección de estos errores depende en parte del hardware y las bibliotecas del sistema subyacentes.

CHILDKILLED pid sigName msg
Este formato se utiliza cuando un proceso hijo ha sido terminado debido a una señal. El elemento pid será el identificador del proceso (en decimal). El elemento sigName será el nombre simbólico de la señal que causó la terminación del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGPIPE. El elemento msg será un mensaje corto legible por humanos que describe la señal, como "escritura en tubería sin lectores" para SIGPIPE.
CHILDSTATUS pid code
Este formato se utiliza cuando un proceso hijo ha salido con un estado de salida distinto de cero. El elemento pid será el identificador del proceso (en decimal) y el elemento code será el código de salida devuelto por el proceso (también en decimal).
CHILDSUSP pid sigName msg
Este formato se utiliza cuando un proceso hijo ha sido suspendido debido a una señal. El elemento pid será el identificador del proceso, en decimal. El elemento sigName será el nombre simbólico de la señal que causó la suspensión del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGTTIN. El elemento msg será un mensaje corto legible por humanos que describe la señal, como "lectura tty en segundo plano" para SIGTTIN.
NONE
Este formato se utiliza para errores en los que no hay información adicional disponible para un error aparte del mensaje devuelto con el error. En estos casos, la opción de retorno -errorcode consistirá en una lista que contiene un solo elemento cuyo contenido es NONE.
POSIX errName msg
Si el primer elemento es POSIX, entonces el error ocurrió durante una llamada al sistema POSIX. El elemento errName contendrá el nombre simbólico del error que ocurrió, como ENOENT; este será uno de los valores definidos en el archivo de inclusión errno.h. El elemento msg
errorInfo
Esta variable contiene información de rastreo adicional asociada con el error más reciente que ocurrió en este intérprete. El formato de esta variable es una cadena de caracteres que describe una pila de llamadas a procedimientos. El primer marco de pila de la pila es la llamada que produjo el error; los marcos subsiguientes representan las llamadas que llevaron a esa llamada.
tcl_interactive
Esta variable se establece en 1 si Tcl se está ejecutando en modo interactivo (es decir, leyendo comandos de una terminal) y en 0 en caso contrario. Normalmente se establece durante el inicio de Tcl.
tcl_library
Esta variable contiene la ruta al directorio que contiene los scripts biblioteca de Tcl. Normalmente se establece durante el inicio de Tcl y no debe ser modificada por el código de usuario. Se puede acceder a su valor usando el comando info library.
tcl_nonwordchars
Esta variable contiene un conjunto de caracteres que Tcl considera como separadores de palabras además de los caracteres de espacio en blanco estándar. Los caracteres en esta variable se utilizan para dividir cadenas en palabras cuando se utilizan comandos de nivel superior de Tcl, como split. El valor inicial de esta variable incluye caracteres de puntuación como “!$(){}”, etc. Esta variable puede ser modificada por el usuario, pero solo debería hacerse con cuidado.
tcl_patchLevel
Esta variable de solo lectura contiene una cadena de caracteres que identifica la versión de parche específica de Tcl que se está ejecutando. Esto puede ser útil para la compatibilidad de versiones.
tcl_pkgPath
Si está establecida, debe contener una lista Tcl válida de directorios donde buscar archivos de índice de paquetes para la auto-carga de paquetes. Esta variable puede ser establecida por el usuario o por el script de inicio de la aplicación. Si no está establecida, Tcl utiliza un conjunto de rutas predeterminadas.
tcl_platform
Esta variable contiene información sobre la plataforma en la que se está ejecutando Tcl. El valor es un diccionario que contiene claves como "os", "osVersion", "machine", "user", y "endian" (la última puede ser "little" o "big"). Esta información se puede utilizar para escribir código que se adapte a diferentes entornos.
tcl_precision
Esta variable controla la precisión (número de dígitos significativos) utilizada al realizar conversiones entre cadenas y números de punto flotante. El valor predeterminado es 12. Cambiar esta variable puede afectar la precisión de los cálculos de punto flotante.
tcl_rcFileName
Si se establece, este nombre de archivo se utiliza como el archivo de inicio personalizado para la entrada interactiva de Tcl. Si no se establece, Tcl busca `.tclshrc` en el directorio de inicio del usuario.
tcl_traceCompile
Si se establece en un valor distinto de cero, Tcl rastreará el proceso de compilación de scripts Tcl. Esto se utiliza principalmente para depuración y optimización.
tcl_traceExec
Si se establece en un valor distinto de cero, Tcl rastreará el proceso de ejecución de código Tcl. Esto se utiliza principalmente para depuración y análisis de rendimiento.
tcl_wordchars
Esta variable contiene un conjunto de caracteres que Tcl considera como parte de una palabra (junto con los caracteres alfanuméricos y el guion bajo). Los caracteres en esta variable se utilizan para determinar los límites de las palabras durante el análisis de comandos. El valor inicial de esta variable incluye caracteres de puntuación comunes como “_-”. Esta variable puede ser modificada por el usuario, pero solo debería hacerse con cuidado.
tcl_version
Esta variable de solo lectura contiene una cadena de caracteres que identifica la versión principal de Tcl que se está ejecutando. Por ejemplo, podría ser "8.6" o "8.7".
argv
Esta variable es una lista Tcl que contiene los argumentos de la línea de comandos pasados al script Tcl. El primer elemento de la lista es el primer argumento de la línea de comandos, el segundo es el segundo, y así sucesivamente. Los argumentos se dividen según las reglas de análisis de Tcl, por lo que las comillas y los caracteres de escape se manejan automáticamente.
argv0
Esta variable contiene el nombre del script Tcl que se está ejecutando, o el nombre del comando con el que se inició Tcl si se está ejecutando en modo interactivo. Si el script se invocó con una ruta relativa, argv0 contendrá esa ruta relativa. Si se invocó con una ruta absoluta, argv0 contendrá la ruta absoluta.
argc
Esta variable es un entero que contiene el número de argumentos de la línea de comandos pasados al script Tcl. Es equivalente a la longitud de la lista argv.
será un mensaje legible por humanos correspondiente a errName, como "no existe tal archivo o directorio" para el caso ENOENT.
TCL ...
Indica algún tipo de problema generado en relación con Tcl en sí, por ejemplo, un fallo al buscar un canal o una variable.

Para establecer la opción de retorno -errorcode, las aplicaciones deben usar procedimientos de biblioteca como Tcl_SetObjErrorCode, Tcl_SetReturnOptions y Tcl_PosixError, o pueden invocar la opción -errorcode del comando return. Si no se ha utilizado ninguno de estos métodos para establecer el código de error, el intérprete de Tcl restablecerá la variable a NONE después del siguiente error.

errorInfo
Esta variable contiene el valor de la opción de retorno -errorinfo establecida por el error más reciente ocurrido en este intérprete. Este valor de cadena contendrá una o más líneas que identifican los comandos y procedimientos de Tcl que se estaban ejecutando cuando ocurrió el error más reciente. Su contenido tiene la forma de un rastreo de pila que muestra los diversos comandos anidados de Tcl que se habían invocado en el momento del error.
tcl_library
Esta variable contiene el nombre de un directorio que contiene la biblioteca del sistema de scripts de Tcl, como los utilizados para la carga automática. El valor de esta variable lo devuelve el comando info library. Consulte la entrada del manual library para obtener detalles sobre las instalaciones proporcionadas por la biblioteca de scripts de Tcl. Normalmente, cada aplicación o paquete tendrá su propia biblioteca de scripts específica de la aplicación, además de la biblioteca de scripts de Tcl; cada aplicación debe establecer una variable global con un nombre como $app_library (donde app es el nombre de la aplicación) para contener el nombre de archivo de red del directorio de la biblioteca de esa aplicación. El valor inicial de tcl_library se establece cuando se crea un intérprete buscando varios directorios diferentes hasta que se encuentra uno que contiene un script de inicio de Tcl apropiado. Si la variable de entorno TCL_LIBRARY existe, se verifica primero el directorio que nombra. Si TCL_LIBRARY no está establecida o no se refiere a un directorio apropiado, Tcl verifica varios otros directorios basándose en una ubicación predeterminada compilada, la ubicación del binario que contiene la aplicación y el directorio de trabajo actual.
tcl_patchLevel
Cuando se crea un intérprete, Tcl inicializa esta variable para que contenga una cadena que indique el nivel de parche actual para Tcl, como 8.4.16 para Tcl 8.4 con los primeros dieciséis parches oficiales, o 8.5b3 para la tercera versión beta de Tcl 8.5. El valor de esta variable lo devuelve el comando info patchlevel.
tcl_pkgPath
Esta variable contiene una lista de directorios que indican dónde se instalan normalmente los paquetes. No se utiliza en Windows. Típicamente contiene una o dos entradas; si contiene dos entradas, la primera es normalmente un directorio para paquetes dependientes de la plataforma (por ejemplo, binarios de bibliotecas compartidas) y la segunda es normalmente un directorio para paquetes independientes de la plataforma (por ejemplo, archivos de script). Típicamente, un paquete se instala como un subdirectorio de una de las entradas de la variable tcl_pkgPath. Los directorios en la variable tcl_pkgPath se incluyen por defecto en la variable auto_path, por lo que ellos y sus subdirectorios inmediatos se buscan automáticamente para encontrar paquetes durante los comandos package require. Nota: tcl_pkgPath no está destinado a ser modificado por la aplicación. Su valor se agrega a auto_path al inicio; los cambios en tcl_pkgPath no se reflejan en auto_path. Si desea que Tcl busque directorios adicionales para paquetes, debe agregar los nombres de esos directorios a auto_path, no a tcl_pkgPath.
tcl_platform
Este es un array asociativo cuyos elementos contienen información sobre la plataforma en la que se está ejecutando la aplicación, como el nombre del sistema operativo, su número de versión actual y el conjunto de instrucciones de la máquina. Los elementos que se enumeran a continuación siempre estarán definidos, pero pueden tener cadenas vacías como valores si Tcl no pudo recuperar ninguna información relevante. Además, las extensiones y aplicaciones pueden agregar valores adicionales al array. Los elementos predefinidos son:
byteOrder
El orden de bytes nativo de esta máquina: littleEndian o bigEndian.
debug
Si existe esta variable, entonces el intérprete se compiló y se enlazó con un tiempo de ejecución de C habilitado para depuración. Esta variable solo existirá en Windows, por lo que los escritores de extensiones pueden especificar qué paquete cargar dependiendo de la biblioteca de tiempo de ejecución de C que se esté utilizando. Esto no es una indicación de que este núcleo contenga símbolos.
engine
El nombre de la implementación del lenguaje Tcl. Cuando se crea el intérprete por primera vez, este siempre se establece en la cadena Tcl.
machine
El conjunto de instrucciones ejecutado por esta máquina, como intel, PPC, 68k o sun4m. En máquinas UNIX, este es el valor devuelto por uname -m.
os
El nombre del sistema operativo que se ejecuta en esta máquina, como Windows NT o SunOS. En máquinas UNIX, este es el valor devuelto por uname -s.
osVersion
El número de versión del sistema operativo que se ejecuta en esta máquina. En máquinas UNIX, este es el valor devuelto por uname -r.
pathSeparator
El carácter que debe usarse para dividir las variables de entorno tipo PATH en su lista correspondiente de nombres de directorios.
platform
O bien windows o unix. Esto identifica el entorno operativo general de la máquina.
pointerSize
Esto da el tamaño del puntero nativo de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(void*) en C).
threaded
Si existe esta variable, entonces el intérprete se compiló con hilos habilitados.
user
Esto identifica al usuario actual basándose en la información de inicio de sesión disponible en la plataforma. Este valor proviene de las llamadas al sistema getuid() y getpwuid() en Unix, y del valor de la llamada al sistema GetUserName() en Windows.
wordSize
Esto da el tamaño de la palabra nativa de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(long) en C).
tcl_precision
Esta variable controla el número de dígitos a generar al convertir valores de punto flotante a cadenas. Por defecto es 0. Las aplicaciones no deben cambiar este valor; se proporciona para la compatibilidad con código heredado.
El valor predeterminado de 0 es especial, lo que significa que Tcl debe convertir números usando la menor cantidad de dígitos posible sin dejar de distinguir ningún número de punto flotante de sus vecinos más cercanos. Difiere de usar un valor arbitrariamente alto para tcl_precision en que un número inexacto como 1.4 se convertirá como 1.4 en lugar de 1.3999999999999999, aunque este último esté más cerca del valor exacto del número binario.
Si tcl_precision no es cero, entonces cuando Tcl convierte un número de punto flotante, crea una representación decimal de como máximo tcl_precision dígitos significativos; el resultado puede ser más corto si el resultado más corto representa el número original exactamente. Si ningún resultado de como máximo tcl_precision dígitos es una representación exacta del número original, se elige el que está más cerca del número original. Si el número original se encuentra precisamente entre dos representaciones decimales igualmente precisas, se elige la que tiene un valor par para el dígito menos significativo; por ejemplo, si tcl_precision es 3, entonces 0.3125 se convertirá en 0.312, no en 0.313, mientras que 0.6875 se convertirá en 0.688, no en 0.687. Se recortarán los ceros finales que queden.
un valor de tcl_precision de 17 dígitos es "perfecto" para punto flotante IEEE, en el sentido de que permite convertir valores de doble precisión a cadenas y de nuevo a binario sin pérdida de información. Por esta razón, a menudo se verá como un valor en código heredado que debe ejecutarse en versiones de Tcl anteriores a la 8.5. Ya no se recomienda; como se mencionó anteriormente, el valor cero es el método preferido.
Todos los intérpretes de un hilo comparten un único valor de tcl_precision: cambiarlo en un intérprete afectará a todos los demás intérpretes. Los intérpretes seguros no tienen permitido modificar la variable.
Los valores válidos para tcl_precision van de 0 a 17.
tcl_rcFileName
Esta variable se utiliza durante la inicialización para indicar el nombre de un archivo de inicio específico del usuario. Si la inicialización específica de la aplicación la establece, el código de inicio de Tcl verificará la existencia de este archivo y lo source-ará si existe. Por ejemplo, para wish la variable se establece en ~/.wishrc para Unix y ~/wishrc.tcl para Windows.
tcl_traceCompile
El valor de esta variable se puede establecer para controlar cuánta información de rastreo se muestra durante la compilación de bytecode. Por defecto, tcl_traceCompile es cero y no se muestra información. Establecer tcl_traceCompile en 1 genera un resumen de una línea en stdout cada vez que se compila un procedimiento o un comando de nivel superior. Establecerlo en 2 genera una lista detallada en stdout de las instrucciones de bytecode emitidas durante cada compilación. Esta variable es útil para rastrear posibles problemas con el compilador de Tcl.
Esta variable y funcionalidad solo existen si TCL_COMPILE_DEBUG se definió durante la compilación de Tcl.

OTRAS VARIABLES GLOBALES

Las siguientes variables solo están garantizadas de existir en los ejecutables tclsh y wish; la biblioteca Tcl no las define por sí misma pero muchos entornos Tcl sí lo hacen.

argc
El número de argumentos para tclsh o wish.
argv
Lista Tcl de argumentos para tclsh o wish.
argv0
El script que tclsh o wish comenzó a ejecutar (si se especificó) o de lo contrario el nombre con el que se invocó tclsh o wish.
tcl_interactive
Contiene 1 si tclsh o wish se está ejecutando interactivamente (no se especificó ningún script y la entrada estándar es un dispositivo tipo terminal), 0 en caso contrario.

EJEMPLOS

Para agregar un directorio a la colección de ubicaciones buscadas por package require, por ejemplo, debido a algunos paquetes específicos de la aplicación que se utilizan, es necesario actualizar la variable auto_path:

lappend ::auto_path [file join [pwd] "theLibDir"]

Una forma simple, aunque no muy robusta, de manejar argumentos de línea de comandos de la forma "-foo 1 -bar 2" es cargarlos en una matriz después de haber cargado primero los ajustes predeterminados:

array set arguments {-foo 0 -bar 0 -grill 0}
array set arguments $::argv
puts "foo is $arguments(-foo)"
puts "bar is $arguments(-bar)"
puts "grill is $arguments(-grill)"

La variable global argv0 se puede usar (en conjunto con el comando info script) para determinar si el script actual se está ejecutando como el script principal o se está cargando como una biblioteca. Esto es útil porque permite que un solo script se utilice tanto como biblioteca como demostración de esa biblioteca:

if {$::argv0 eq [info script]} {
    # ejecutando como: tclsh example.tcl
} else {
    package provide Example 1.0
}

TRAZA DE EJECUCIÓN

tcl_traceExec
El valor de esta variable se puede establecer para controlar cuánta información de trazado se muestra durante la ejecución del bytecode. Por defecto, tcl_traceExec es cero y no se muestra información. Establecer tcl_traceExec a 1 genera una traza de una línea en stdout en cada llamada a un procedimiento Tcl. Establecerlo a 2 genera una línea de salida cada vez que se invoca cualquier comando Tcl que contenga el nombre del comando y sus argumentos. Establecerlo a 3 produce una traza detallada que muestra el resultado de la ejecución de cada instrucción de bytecode. Tenga en cuenta que cuando tcl_traceExec es 2 o 3, comandos como set e incr que han sido completamente reemplazados por una secuencia de instrucciones de bytecode no se muestran. Establecer esta variable es útil para rastrear problemas sospechosos con el compilador e intérprete de bytecode.
Esta variable y funcionalidad solo existen si TCL_COMPILE_DEBUG se definió durante la compilación de Tcl.
tcl_wordchars
El valor de esta variable es una expresión regular que se puede establecer para controlar qué se consideran caracteres de “palabra”, para instancias como seleccionar una palabra haciendo doble clic en el texto en Tk. Depende de la plataforma. En Windows, su valor predeterminado es \S, lo que significa cualquier carácter que no sea un espacio Unicode. De lo contrario, su valor predeterminado es \w, que es cualquier carácter de palabra Unicode (número, letra o guion bajo).
tcl_nonwordchars
El valor de esta variable es una expresión regular que se puede establecer para controlar qué se consideran caracteres “no de palabra”, para instancias como seleccionar una palabra haciendo doble clic en el texto en Tk. Depende de la plataforma. En Windows, su valor predeterminado es \s, lo que significa cualquier carácter de espacio Unicode. De lo contrario, su valor predeterminado es \W, que es cualquier cosa excepto un carácter de palabra Unicode (número, letra o guion bajo).
tcl_version
Cuando se crea un intérprete, Tcl inicializa esta variable para que contenga el número de versión de esta versión de Tcl en el formato x.y. Los cambios en x representan cambios importantes con probables incompatibilidades y los cambios en y representan mejoras menores y correcciones de errores que conservan la compatibilidad con versiones anteriores. El valor de esta variable se devuelve con el comando info tclversion.
