NOMBRE

police - acción de policía

SINOPSIS


tc ... action police [ rate TASA burst BYTES[/BYTES] ] [ pkts_rate TASA pkts_burst PAQUETES] [ mtu BYTES[/BYTES] ] [ peakrate TASA ] [ overhead BYTES ] [ linklayer TIPO ] [ CONTROL ]

tc ... filter ... [ estimator MUESTRA PROMEDIO ] action police avrate TASA [ CONTROL ]

CONTROL := conform-exceed EXCEEDACT[/NOTEXCEEDACT

EXCEEDACT/NOTEXCEEDACT := { pipe | ok | reclassify | drop | continue | goto chain INDICE_CADENA }

DESCRIPCIÓN

La acción police permite limitar la tasa de bytes o paquetes del tráfico que coincide con el filtro al que está adjunto.

Hay dos algoritmos diferentes disponibles para medir la tasa de bytes: El primero utiliza un doble cubo de tokens interno y se configura utilizando los parámetros rate, burst, mtu, peakrate, overhead y linklayer. El segundo utiliza un mecanismo de muestreo en el kernel. Se puede ajustar finamente utilizando el parámetro del filtro estimator.

Hay un algoritmo disponible para medir la tasa de paquetes y es similar al primer algoritmo descrito para la tasa de bytes. Se configura utilizando los parámetros pkt_rate y pkt_burst.

Al menos uno de los parámetros rate y pkt_rate debe estar configurado.

OPCIONES

rate TASA
La tasa máxima de bytes de los paquetes que pasan por esta acción. Aquellos que la excedan serán tratados como se define en la opción conform-exceed.
burst BYTES[/BYTES]
Establece el estallido máximo permitido en bytes, opcionalmente seguido por una barra ('/') y el tamaño de la celda que debe ser una potencia de 2.
pkt_rate TASA
La tasa máxima de paquetes o paquetes que pasan por esta acción. Aquellos que la excedan serán tratados como se define en la opción conform-exceed.
pkt_burst PAQUETES
Establece el estallido máximo permitido en paquetes.
mtu BYTES[/BYTES]
Este es el tamaño máximo de paquete manejado por el policer (los más grandes se tratarán como si hubieran excedido la tasa configurada). Establecer este valor correctamente mejorará la precisión del planificador. El formato del valor es idéntico a burst arriba. Por defecto es ilimitado.
peakrate TASA
Establece la tasa máxima de vaciado del cubo, excediendo la rate.
avrate TASA
Utiliza un estimador de tasa de ancho de banda en el kernel y compara la TASA dada con él.
overhead BYTES
Tiene en cuenta la sobrecarga del protocolo de los dispositivos de salida de encapsulación al calcular la rate y la peakrate.
linklayer TIPO
Especifica el tipo de capa de enlace. TIPO puede ser uno de ethernet (el predeterminado), atm o adsl (que son sinónimos). Se utiliza para alinear las tablas de tasas precalculadas con los tamaños de celda ATM, para ethernet no se realiza ninguna acción.
estimator MUESTRA PROMEDIO
Ajusta el estimador de tasa de paquetes en el kernel. MUESTRA y PROMEDIO son valores de tiempo y controlan la frecuencia con la que se toman las muestras y el período de tiempo durante el cual se construye un promedio.
conform-exceed EXCEEDACT[/NOTEXCEEDACT]
Define cómo manejar los paquetes que exceden o cumplen el límite de ancho de banda configurado. Los valores posibles son:
continue
No hacer nada, simplemente continuar con la siguiente acción en la línea.
drop
Descartar el paquete inmediatamente.
shot
Este es un sinónimo de drop.
ok
Aceptar el paquete. Este es el valor predeterminado para los paquetes que cumplen.
pass
Este es un sinónimo de ok.
reclassify
Tratar el paquete como si no coincidiera con el filtro al que está adjunta esta acción y continuar con el siguiente filtro en la línea (si lo hay). Este es el valor predeterminado para los paquetes que exceden.
pipe
Pasar el paquete a la siguiente acción en la línea.

EJEMPLOS

Una aplicación típica de la acción police es hacer cumplir la tasa de tráfico de entrada descartando los paquetes excedentes. Aunque es mejor hacerlo en el lado del remitente, especialmente en escenarios sin control mutuo (por ejemplo, con proveedores de dial-up), esto es a menudo lo mejor que se puede hacer para mantener bajas las latencias bajo alta carga. Lo siguiente establece la policía de ancho de banda de entrada a 1mbit/s usando la qdisc ingress y el filtro u32:

# tc qdisc add dev eth0 handle ffff: ingress
# tc filter add dev eth0 parent ffff: u32 \
	match u32 0 0 \
	police rate 1mbit burst 100k

Como una acción no puede existir por sí sola, siempre debe haber un filtro involucrado como enlace entre qdisc y acción. El ejemplo anterior utiliza u32 para ello, que está configurado para coincidir efectivamente con cualquier paquete (pasándolo a la acción police).
