NOMBRE

ct - acción de seguimiento de conexiones de tc

SINOPSIS


tc ... action ct commit [ force ] [ zone ZONA ] [ mark MASCARA_MARCA ] [ label MASCARA_ETIQUETA ] [ nat NAT_ESPEC ]

tc ... action ct [ nat ] [ zone ZONA ]

tc ... action ct clear

DESCRIPCIÓN

La acción ct es una acción de tc para enviar paquetes e interactuar con el módulo netfilter conntrack.

Puede (como se muestra en la sinopsis, en orden):

Enviar el paquete a conntrack y confirmar la conexión, mientras se configura una marca de 32 bits, una etiqueta de 128 bits y nat src/dst.

Enviar el paquete a conntrack, que marcará el paquete con el estado de la conexión y los metadatos configurados (marca/etiqueta), y ejecutará el nat previamente configurado.

Borrar el estado de seguimiento de conexión y los metadatos del paquete.

OPCIONES

zone ZONA
Especifica un número de zona de conntrack al que enviar el paquete a conntrack.
mark MASCARA_MARCA
Especifica una marca enmascarada de 32 bits para establecer para la conexión (solo válido con commit).
label MASCARA_ETIQUETA
Especifica una etiqueta enmascarada de 128 bits para establecer para la conexión (solo válido con commit).
nat NAT_ESPEC
Donde NAT_ESPEC := {src|dst} addr addr1[-addr2] [port port1[-port2]]

Especifica el rango de nat src/dst a configurar para la conexión (solo válido con commit).

src/dst - configura nat src o dst
addr1/addr2 - direcciones IPv4/IPv6
port1/port2 - números de puerto
nat
Restaura cualquier nat previamente configurado.
clear
Elimina cualquier estado de conntrack y metadatos (marca/etiqueta) del paquete (debe ser la única opción especificada).
force
Fuerza la dirección de conntrack para conexiones previamente confirmadas, de modo que la dirección actual se convierta en la dirección original (solo válido con commit).

EJEMPLOS

Ejemplo que muestra un firewall con NAT en la zona de conntrack 2 y el uso de marcas de conntrack:

#Añadir qdisc de entrada en las interfaces eth0 y eth1
$ tc qdisc add dev eth0 ingress
$ tc qdisc add dev eth1 ingress
#Configurar filtros en eth0, permitiendo abrir nuevas conexiones en la zona 2, y realizando nat src + marca para cada nueva conexión
$ tc filter add dev eth0 ingress prio 1 chain 0 proto ip flower ip_proto tcp ct_state -trk \
action ct zone 2 pipe action goto chain 2
$ tc filter add dev eth0 ingress prio 1 chain 2 proto ip flower ct_state +trk+new \
action ct zone 2 commit mark 0xbb nat src addr 5.5.5.7 pipe action mirred egress redirect dev eth1
$ tc filter add dev eth0 ingress prio 1 chain 2 proto ip flower ct_zone 2 ct_mark 0xbb ct_state +trk+est \
action ct nat pipe action mirred egress redirect dev eth1
#Configurar filtros en eth1, permitiendo solo conexiones establecidas de la zona 2, y nat inverso (dst nat en este caso)
$ tc filter add dev eth1 ingress prio 1 chain 0 proto ip flower ip_proto tcp ct_state -trk \
action ct zone 2 pipe action goto chain 1
$ tc filter add dev eth1 ingress prio 1 chain 1 proto ip flower ct_zone 2 ct_mark 0xbb ct_state +trk+est \
action ct nat pipe action mirred egress redirect dev eth0
