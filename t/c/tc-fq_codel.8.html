NOMBRE

CoDel - Cola Justa (FQ) con Retraso Controlado (CoDel)

SINOPSIS

tc qdisc ... fq_codel [ limit PAQUETES ] [ flows NÚMERO ] [ target TIEMPO ] [ interval TIEMPO ] [ quantum BYTES ] [ ecn | noecn ] [ ce_threshold TIEMPO ] [ ce_threshold_selector VALOR/MÁSCARA ] [ memory_limit BYTES ]

DESCRIPCIÓN

FQ_Codel (Fair Queuing Controlled Delay) es una disciplina de cola que combina la Cola Justa con el esquema AQM CoDel. FQ_Codel utiliza un modelo estocástico para clasificar los paquetes entrantes en diferentes flujos y se utiliza para proporcionar una cuota justa de ancho de banda a todos los flujos que utilizan la cola. Cada uno de estos flujos es gestionado por la disciplina de cola CoDel. Se evita la reordenación dentro de un flujo ya que Codel utiliza internamente una cola FIFO.

PARÁMETROS

limit

tiene la misma semántica que codel y es el límite estricto del tamaño real de la cola. Cuando se alcanza este límite, los paquetes entrantes se descartan. El valor predeterminado es 10240 paquetes.

memory_limit

establece un límite en el número total de bytes que se pueden poner en cola en esta instancia de FQ-CoDel. Se aplicará el menor de los límites de paquetes del parámetro limit y el límite de memoria. El valor predeterminado es 32 MB.

flows

es el número de flujos en los que se clasifican los paquetes entrantes. Debido a la naturaleza estocástica del hash, múltiples flujos pueden terminar siendo hasheados en la misma ranura. Los flujos más nuevos tienen prioridad sobre los más antiguos. Este parámetro solo se puede establecer en el momento de la carga, ya que se debe asignar memoria para la tabla hash. El valor predeterminado es 1024.

target

tiene la misma semántica que codel y es el retraso de cola persistente/en espera aceptable mínimo. Este retraso mínimo se identifica rastreando el retraso mínimo local de la cola que experimentan los paquetes. El valor predeterminado es 5ms.

interval

tiene la misma semántica que codel y se utiliza para asegurar que el retraso mínimo medido no se vuelva demasiado obsoleto. El retraso mínimo debe experimentarse en la última época de longitud interval. Debería establecerse en el orden del RTT en el peor de los casos a través del cuello de botella para dar a los puntos finales tiempo suficiente para reaccionar. El valor predeterminado es 100ms.

quantum

es el número de bytes utilizado como 'déficit' en el algoritmo de cola justa. El valor predeterminado se establece en 1514 bytes, lo que corresponde a la MTU de Ethernet más la longitud de la cabecera de hardware de 14 bytes.

ecn | noecn

tiene la misma semántica que codel y se puede utilizar para marcar paquetes en lugar de descartarlos. Si se ha habilitado ecn, se puede utilizar noecn para desactivarlo y viceversa. A diferencia de codel, ecn está activado por defecto.

ce_threshold

establece un umbral por encima del cual todos los paquetes se marcan con ECN Congestion Experienced. Esto es útil para algoritmos de control de congestión tipo DCTCP que requieren marcado en umbrales de cola muy bajos.

ce_threshold_selector

establece un filtro para que la característica ce_threshold se aplique solo a un subconjunto del tráfico visto por el qdisc. Si se establece, se aplicará el valor MASK como una operación AND bit a bit al byte diffserv/ECN de la cabecera IP, y solo si el resultado de este enmascaramiento es igual a VALOR, se aplicará la lógica de ce_threshold al paquete.

drop_batch

establece el número máximo de paquetes a descartar cuando se exceden limit o memory_limit. El valor predeterminado es 64.

EJEMPLOS

#tc qdisc add dev eth0 root fq_codel
#tc -s qdisc show
qdisc fq_codel 8002: dev eth0 root refcnt 2 limit 10240p flows 1024 quantum 1514
target 5.0ms interval 100.0ms ecn
Sent 428514 bytes 2269 pkt (dropped 0, overlimits 0 requeues 0)
backlog 0b 0p requeues 0
maxpacket 256 drop_overlimit 0 new_flow_count 0 ecn_mark 0
new_flows_len 0 old_flows_len 0

#tc qdisc add dev eth0 root fq_codel limit 2000 target 3ms interval 40ms noecn
#tc -s qdisc show
qdisc fq_codel 8003: dev eth0 root refcnt 2 limit 2000p flows 1024 quantum 1514 target 3.0ms interval 40.0ms

backlog 0b 0p requeues 34869
maxpacket 65226 drop_overlimit 0 new_flow_count 73 ecn_mark 0
new_flows_len 1 old_flows_len 3
