GATE(8) Linux GATE(8)

NOMBRE

gate - Acción de puerta de flujo

SINOPSIS

tc ... action gate [ base-time TIEMPO_BASE ] [ clockid ID_RELOJ ] sched-entry <estado puerta> <intervalo 1> [ <prioridad interna> <octetos máximos> ] sched-entry <estado puerta> <intervalo 2> [ <prioridad interna> <octetos máximos> ] sched-entry <estado puerta> <intervalo 3> [ <prioridad interna> <octetos máximos> ] ...... sched-entry <estado puerta> <intervalo N> [ <prioridad interna> <octetos máximos> ]

DESCRIPCIÓN

La acción GATE permite que los paquetes de entrada especificados se pasen en una ranura de tiempo específica, o se descarten en una ranura de tiempo específica. El filtro tc filtra los paquetes de entrada, y la acción tc gate especificará en qué ranura de tiempo y cuántos bytes pueden pasar estos paquetes al dispositivo y en qué ranura de tiempo se descartarán los paquetes. La acción gate también asigna un tiempo base para indicar cuándo comienza la lista de entradas. Luego, la acción gate comenzará a repetir la lista de entradas de la puerta cíclicamente en el tiempo base de inicio. Para la simulación por software, la acción gate requiere que el usuario asigne el tipo de reloj de referencia de tiempo.

PARÁMETROS

tiempo-base

Especifica el instante en nanosegundos, definiendo el tiempo en que comienza la programación. Si 'tiempo-base' es un tiempo pasado, la programación comenzará en

tiempo-base + (N * tiempo-ciclo)

donde N es el entero más pequeño tal que el tiempo resultante sea mayor que "ahora", y "tiempo-ciclo" es la suma de todos los intervalos de las entradas en la programación. Sin especificar tiempo-base, el valor predeterminado será 0.

id-reloj

Especifica el reloj que será utilizado por el temporizador interno del qdisc para medir el tiempo y programar eventos. No es válido si la acción gate se utiliza para descargar el filtro. Por ejemplo, el comando de filtro tc con el parámetro skip_sw.
entrada-programada

Puede haber múltiples parámetros entrada-programada en una única programación. Cada uno tiene el formato:

entrada-programada <estado puerta> <intervalo> [ <prioridad interna> <octetos máximos> ]

<estado puerta> significa los estados de la puerta. 'abrir' mantiene la puerta abierta, 'cerrar' mantiene la puerta cerrada.
<intervalo> significa cuántos nanosegundos dura esta ranura de tiempo.
<prioridad interna> significa el valor de prioridad interna. El número de la cola de recepción interna para este flujo. "-1" significa comodín. <prioridad interna> y <octetos máximos> pueden omitirse, por defecto son "-1", lo que significa que ambos
valores son "-1" para esta <entrada-programada>.
<octetos máximos> significa cuántos octetos pueden pasar en esta ranura de tiempo. Se descartan si se excede el límite. "-1" significa comodín. <octetos máximos> pueden omitirse, por defecto son "-1", lo que significa que el valor es "-1" para esta <entrada-programada>.
Tenga en cuenta que <prioridad interna> y <octetos máximos> no tienen ningún significado para el estado de la puerta si es "cerrar" en una "entrada-programada". Todos los paquetes se descartan cuando la "entrada-programada" tiene el estado "cerrar".

EJEMPLOS

El siguiente ejemplo muestra cómo el filtro tc filtra los paquetes con IP de origen coincidente con 192.168.0.20, mantendrá la puerta abierta durante 200 ms y limitará el tráfico a 8 MB en esta entrada programada. Luego, mantendrá la puerta de tráfico cerrada durante 100 ms. Los paquetes que lleguen en estado de puerta cerrada serán descartados. Luego, el ciclo ejecutará las entradas de la puerta periódicamente. La programación comenzará en el instante 200.0s utilizando la referencia CLOCK_TAI. La programación se compone de dos entradas, cada una de 300 ms de duración.

# tc qdisc add dev eth0 ingress
# tc filter add dev eth0 parent ffff: protocol ip \
           flower skip_hw src_ip 192.168.0.20 \
           action gate index 2 clockid CLOCK_TAI \
           base-time 200000000000ns \
           sched-entry open 200000000ns -1 8000000b \
           sched-entry close 100000000ns

Los siguientes comandos son un ejemplo para filtrar un flujo de MAC de origen coincidente con los paquetes icmp 10:00:80:00:00:00 que serán descartados en cualquier momento con un ciclo de 200 ms. Con un tiempo base predeterminado de 0 y un clockid de CLOCK_TAI como predeterminado.

# tc qdisc add dev eth0 ingress
# tc filter add dev eth0 parent ffff:  protocol ip \
	flower ip_proto icmp dst_mac 10:00:80:00:00:00 \
	action gate index 12 sched-entry close 200000000ns
