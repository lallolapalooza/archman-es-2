DESCRIPCIÓN

Las funciones termios describen una interfaz de terminal general que se proporciona para controlar puertos de comunicación asíncronos.

La estructura termios

Muchas de las funciones descritas aquí tienen un argumento termios_p que es un puntero a una estructura termios. Esta estructura contiene al menos los siguientes miembros:


tcflag_t c_iflag;      /* modos de entrada */
tcflag_t c_oflag;      /* modos de salida */
tcflag_t c_cflag;      /* modos de control */
tcflag_t c_lflag;      /* modos locales */
cc_t     c_cc[NCCS];   /* caracteres especiales */

Los valores que se pueden asignar a estos campos se describen a continuación. En el caso de los cuatro primeros campos de máscara de bits, las definiciones de algunas de las banderas asociadas que se pueden establecer solo se exponen si se define una macro de prueba de características específica (consulte feature_test_macros(7)), como se indica entre corchetes ("[]").

En las descripciones siguientes, "no en POSIX" significa que el valor no está especificado en POSIX.1-2001, y "XSI" significa que el valor está especificado en POSIX.1-2001 como parte de la extensión XSI.

Constantes de bandera de c_iflag:

IGNBRK
Ignorar la condición de BREAK en la entrada.
BRKINT
Si se establece IGNBRK, se ignora un BREAK. Si no está establecido pero BRKINT sí lo está, un BREAK provoca el vaciado de las colas de entrada y salida, y si el terminal es el terminal de control de un grupo de procesos en primer plano, enviará una señal SIGINT a este grupo de procesos en primer plano. Cuando no están establecidos ni IGNBRK ni BRKINT, un BREAK se lee como un byte nulo ('\0'), excepto cuando se establece PARMRK, en cuyo caso se lee como la secuencia \377 \0 \0.
IGNPAR
Ignorar errores de trama y errores de paridad.
PARMRK
Si se establece este bit, los bytes de entrada con errores de paridad o trama se marcan al pasarlos al programa. Este bit solo es significativo cuando se establece INPCK y no se establece IGNPAR. La forma en que se marcan los bytes erróneos es con dos bytes precedentes, \377 y \0. Por lo tanto, el programa en realidad lee tres bytes por un byte erróneo recibido del terminal. Si un byte válido tiene el valor \377, y ISTRIP (ver más abajo) no está establecido, el programa podría confundirlo con el prefijo que marca un error de paridad. Por lo tanto, un byte \377 válido se pasa al programa como dos bytes, \377 \377, en este caso.
Si no están establecidos ni IGNPAR ni PARMRK, leer un carácter con error de paridad o error de trama como \0.
INPCK
Habilitar la verificación de paridad de entrada.
ISTRIP
Eliminar el octavo bit.
INLCR
Traducir NL a CR en la entrada.
IGNCR
Ignorar retorno de carro en la entrada.
ICRNL
Traducir retorno de carro a nueva línea en la entrada (a menos que se establezca IGNCR).
IUCLC
(no en POSIX) Mapear caracteres en mayúsculas a minúsculas en la entrada.
IXON
Habilitar el control de flujo XON/XOFF en la salida.
IXANY
(XSI) Escribir cualquier carácter reiniciará la salida detenida. (El predeterminado es permitir que solo el carácter START reinicie la salida).
IXOFF
Habilitar el control de flujo XON/XOFF en la entrada.
IMAXBEL
(no en POSIX) Hacer sonar el timbre cuando la cola de entrada está llena. Linux no implementa este bit y actúa como si siempre estuviera establecido.
IUTF8 (desde Linux 2.6.4)
(no en POSIX) La entrada es UTF8; esto permite que el borrado de caracteres se realice correctamente en modo cocido.

Constantes de bandera de c_oflag:

OPOST
Habilitar procesamiento de salida definido por la implementación.
OLCUC
(no en POSIX) Mapear caracteres en minúsculas a mayúsculas en la salida.
ONLCR
(XSI) Mapear NL a CR-NL en la salida.
OCRNL
Mapear CR a NL en la salida.
ONOCR
No generar CR en la columna 0.
ONLRET
Se asume que el carácter NL realiza la función de retorno de carro; la idea del kernel de la columna actual se establece en 0 después de NL y CR.
OFILL
Enviar caracteres de relleno para un retardo, en lugar de usar un retardo con tiempo.
OFDEL
El carácter de relleno es DEL ASCII (0177). Si no está establecido, el carácter de relleno es NUL ASCII ('\0'). (No implementado en Linux.)
NLDLY
Máscara de retardo de nueva línea. Los valores son NL0 y NL1. [requiere _BSD_SOURCE o _SVID_SOURCE o _XOPEN_SOURCE]
CRDLY
Máscara de retardo de retorno de carro. Los valores son CR0, CR1, CR2 o CR3. [requiere _BSD_SOURCE o _SVID_SOURCE o _XOPEN_SOURCE]
TABDLY
Máscara de retardo de tabulación horizontal. Los valores son TAB0, TAB1, TAB2, TAB3 (o XTABS, pero consulte la sección BUGS). Un valor de TAB3, es decir, XTABS, expande las tabulaciones a espacios (con paradas de tabulación cada ocho columnas). [requiere _BSD_SOURCE o _SVID_SOURCE o _XOPEN_SOURCE]

NOMBRE

termios - POSIX terminal control definitions

SINOPSIS

<termios.h>

DESCRIPCIÓN

The POSIX standard defines a set of constants and structure members for controlling terminals. These are accessible via the <termios.h> header file.

The main structure is:

struct termios {
    tcflag_t c_iflag;        /* input flags */
    tcflag_t c_oflag;        /* output flags */
    tcflag_t c_cflag;        /* control flags */
    tcflag_t c_lflag;        /* local flags */
    cc_t     c_cc[NCCS];     /* control characters */
};

The POSIX standard defines the values for the fields as follows:

c_iflag
Flag constants for input modes:
BRKINT
If set, a break condition causes a SIGINT signal to be sent to the foreground process group. If PARMRK is not set, break is ignored.
ICRNL
Translate the carriage return character to the newline character on input.
IGNBRK
Ignore break conditions on input.
IGNCR
Ignore carriage return on input.
IGNPAR
Ignore characters with parity errors.
INLCR
Translate the newline character to the carriage return character on input.
INPCK
Enable input parity checking. This can be used in conjunction with the PARMRK or IGNPAR flags.
ISTRIP
Strip the high-order bit from input characters.
IUCLC
(not in POSIX; not supported under Linux) Translate uppercase characters to lowercase on input. [requires _BSD_SOURCE or _SVID_SOURCE or _XOPEN_SOURCE]
IXANY
Any character can be used to restart output which has been stopped by the IXOFF flag. (The default is that only the IXON flag's start character can restart output.)
IXOFF
Enable the receiving of the STOP character to cause the input queue to be searched for the output STOP character, and the transmission stopped when found. Output is not restarted until the receiving of the START character is detected.
IXON
Enable the sending of the STOP character when the output queue is full, and the receiving of the START character to the same. This is used for software flow control.
PARMRK
If PARMRK is set, mark parity errors. When a byte with a parity error is received, the system prefixes it with two 0x00 bytes and it is given to the user program. If IGNPAR is also set, parity errors are ignored. If INPCK is also set, parity checking is enabled.
c_oflag
Flag constants for output modes:
OPOST
Enable implementation-defined output processing.
ONLCR
Translate the newline character to the carriage return-newline sequence on output.
NOFLSH
Disable flushing the input and output queues when generating signals for the INT, QUIT, and SUSP characters.
OCRNL
Translate the carriage return character to the newline character on output.
OFDEL
Bel character is sent as decimal value 0177 (DEL) rather than as 007 (BEL), when the delay flag is set to achieve a delay.
OFILL
Send fill characters for delays instead of timing out. This flag is ignored unless a delay flag is set.
NL0
(000000) Don't delay on newline.
NL1
(000004) Delay on newline.
NL_MASK
(000014)
CR0
(000000) Don't delay on carriage return.
CR1
(000004) Delay on carriage return.
CR2
(000010) Delay on carriage return.
CR3
(000014) Delay on carriage return.
CR_MASK
(000014)
TAB0
(000000) Don't delay on horizontal tabs.
TAB1
(000010) Delay on horizontal tabs.
TAB2
(000100) Delay on horizontal tabs.
TAB3
(000110) Delay on horizontal tabs.
TAB_MASK
(000110)
BS0
(000000) Don't delay on backspace.
BS1
(000010) Delay on backspace.
BS_MASK
(000010)
VT0
(000000) Don't delay on vertical tabs.
VT1
(000100) Delay on vertical tabs.
VT_MASK
(000100)
FF0
(000000) Don't delay on form feed.
FF1
(000100) Delay on form feed.
FF_MASK
(000100)
TANDEM
(not in POSIX) Enable TANDEM mode (deprecated synonym for IXOFF). [requires _BSD_SOURCE or _SVID_SOURCE]
c_cflag
Flag constants for control modes:
CBAUD
(not in POSIX) Baud speed mask (4+1 bits). [requires _BSD_SOURCE or _SVID_SOURCE]
CBAUDEX
(not in POSIX) Extra baud speed mask (1 bit), included in CBAUD. [requires _BSD_SOURCE or _SVID_SOURCE]
(POSIX dice que la velocidad en baudios se almacena en la estructura termios sin especificar dónde exactamente, y proporciona cfgetispeed() y cfsetispeed() para acceder a ella. Algunos sistemas usan bits seleccionados por CBAUD en c_cflag, otros sistemas usan campos separados, por ejemplo, sg_ispeed y sg_ospeed.)
CSIZE
Máscara de tamaño de carácter. Los valores son CS5, CS6, CS7 o CS8.
CSTOPB
Establece dos bits de parada, en lugar de uno.
CREAD
Habilita el receptor.
PARENB
Habilita la generación de paridad en la salida y la comprobación de paridad para la entrada.
PARODD
Si está establecido, la paridad para la entrada y la salida es impar; de lo contrario, se utiliza paridad par.
HUPCL
Baja las líneas de control del módem después de que el último proceso cierre el dispositivo (hang up).
CLOCAL
Ignora las líneas de control del módem.
LOBLK
(no en POSIX) Bloquea la salida de una capa de shell no actual. Para uso de shl (capas de shell). (No implementado en Linux.)
CIBAUD
(no en POSIX) Máscara para velocidades de entrada. Los valores de los bits CIBAUD son los mismos que los valores de los bits CBAUD, desplazados a la izquierda IBSHIFT bits. [requiere _BSD_SOURCE o _SVID_SOURCE] (No implementado en glibc, soportado en Linux a través de las llamadas ioctl TCGET* y TCSET*; ver ioctl_tty(2))
CMSPAR
(no en POSIX) Usa paridad "stick" (mark/space) (soportado en ciertos dispositivos seriales): si PARODD está establecido, el bit de paridad es siempre 1; si PARODD no está establecido, entonces el bit de paridad es siempre 0. [requiere _BSD_SOURCE o _SVID_SOURCE]
CRTSCTS
(no en POSIX) Habilita el control de flujo RTS/CTS (hardware). [requiere _BSD_SOURCE o _SVID_SOURCE]
c_lflag
Flag constants for local modes:
ISIG
Cuando se recibe cualquiera de los caracteres INTR, QUIT, SUSP o DSUSP, genera la señal correspondiente.
ICANON
Habilita el modo canónico (descrito a continuación).
XCASE
(no en POSIX; no soportado bajo Linux) Si ICANON también está establecido, la terminal es solo mayúsculas. La entrada se convierte a minúsculas, excepto los caracteres precedidos por \. En la salida, los caracteres en mayúsculas van precedidos por \ y los caracteres en minúsculas se convierten a mayúsculas. [requiere _BSD_SOURCE o _SVID_SOURCE o _XOPEN_SOURCE]
ECHO
Eco de los caracteres de entrada.
ECHOE
Si ICANON también está establecido, el carácter ERASE borra el carácter de entrada anterior, y WERASE borra la palabra anterior.
ECHOK
Si ICANON también está establecido, el carácter KILL borra la línea actual.
ECHONL
Si ICANON también está establecido, hace eco del carácter NL incluso si ECHO no está establecido.
ECHOCTL
(no en POSIX) Si ECHO también está establecido, los caracteres especiales de la terminal distintos de TAB, NL, START y STOP se muestran como ^X, donde X es el carácter con código ASCII 0x40 mayor que el carácter especial. Por ejemplo, el carácter 0x08 (BS) se muestra como ^H. [requiere _BSD_SOURCE o _SVID_SOURCE]
ECHOPRT
(no en POSIX) Si ICANON y ECHO también están establecidos, los caracteres se imprimen mientras se están borrando. [requiere _BSD_SOURCE o _SVID_SOURCE]
ECHOKE
(no en POSIX) Si ICANON también está establecido, KILL se muestra borrando cada carácter de la línea, como se especifica por ECHOE y ECHOPRT. [requiere _BSD_SOURCE o _SVID_SOURCE]
DEFECHO
(no en POSIX) Eco solo cuando un proceso está leyendo. (No implementado en Linux.)
FLUSHO
(no en POSIX; no soportado bajo Linux) Se está vaciando la salida. Esta bandera se activa/desactiva al presionar el carácter DISCARD. [requiere _BSD_SOURCE o _SVID_SOURCE]
NOFLSH
Deshabilita el vaciado de las colas de entrada y salida al generar señales para los caracteres INT, QUIT y SUSP.
TOSTOP
Envía la señal SIGTTOU al grupo de procesos de un proceso en segundo plano que intenta escribir en su terminal de control.
PENDIN
(no en POSIX; no soportado bajo Linux) Todos los caracteres en la cola de entrada se reimprimen cuando se lee el siguiente carácter. (bash(1) maneja el typeahead de esta manera). [requiere _BSD_SOURCE o _SVID_SOURCE]
IEXTEN
Habilita el procesamiento de entrada definido por la implementación. Esta bandera, así como ICANON, deben estar habilitadas para que los caracteres especiales EOL2, LNEXT, REPRINT, WERASE sean interpretados, y para que la bandera IUCLC sea efectiva.

El array c_cc define los caracteres especiales de la terminal. Los índices simbólicos (valores iniciales) y el significado son:

VDISCARD
(no en POSIX; no soportado bajo Linux; 017, SI, Ctrl-O) Activar/desactivar el descarte de salida pendiente. Reconocido cuando IEXTEN está establecido, y luego no se pasa como entrada.
VDSUSP
(no en POSIX; no soportado bajo Linux; 031, EM, Ctrl-Y) Carácter de suspensión retardada (DSUSP): envía la señal SIGTSTP cuando el carácter es leído por el programa de usuario. Reconocido cuando IEXTEN y ISIG están establecidos, y el sistema soporta control de trabajos, y luego no se pasa como entrada.
VEOF
(004, EOT, Ctrl-D) Carácter de fin de archivo (EOF). Más precisamente: este carácter hace que el búfer tty pendiente se envíe al programa de usuario en espera sin esperar el fin de línea. Si es el primer carácter de la línea, la llamada a read(2) en el programa de usuario devuelve 0, lo que significa fin de archivo. Reconocido cuando ICANON está establecido, y luego no se pasa como entrada.
VEOL
(0, NUL) Carácter adicional de fin de línea (EOL). Reconocido cuando ICANON está establecido.
VEOL2
(no en POSIX; 0, NUL) Otro carácter de fin de línea (EOL2). Reconocido cuando ICANON está establecido.
VERASE
(0177, DEL, rubout, o 010, BS, Ctrl-H, o también #) Carácter de borrado (ERASE). Este borra el carácter anterior no borrado, pero no borra más allá de EOF o del principio de línea. Reconocido cuando ICANON está establecido, y luego no se pasa como entrada.
VINTR
(003, ETX, Ctrl-C, o también 0177, DEL, rubout) Carácter de interrupción (INTR). Envía la señal SIGINT. Reconocido cuando ISIG está establecido, y luego no se pasa como entrada.
VKILL
(025, NAK, Ctrl-U, o Ctrl-X, o también @) Carácter de borrado de línea (KILL). Este borra la entrada desde el último EOF o principio de línea. Reconocido cuando ICANON está establecido, y luego no se pasa como entrada.
VLNEXT
(no en POSIX; 026, SYN, Ctrl-V) Siguiente literal (LNEXT). Comilla el siguiente carácter de entrada, privándolo de su posible significado especial. Reconocido cuando IEXTEN está establecido, y luego no se pasa como entrada.
VMIN
Número mínimo de caracteres para lectura no canónica (MIN).
VQUIT
(034, FS, Ctrl-\) Carácter de salida (QUIT). Envía la señal SIGQUIT. Reconocido cuando ISIG está establecido, y luego no se pasa como entrada.
VREPRINT
(no en POSIX; 022, DC2, Ctrl-R) Reimprimir caracteres no leídos (REPRINT). Reconocido cuando ICANON y IEXTEN están establecidos, y luego no se pasa como entrada.
VSTART
(021, DC1, Ctrl-Q) Carácter de inicio (START). Reinicia la salida detenida por el carácter Stop. Reconocido cuando IXON está establecido, y luego no se pasa como entrada.
VSTATUS
(no en POSIX; no soportado bajo Linux; solicitud de estado: 024, DC4, Ctrl-T). Carácter de estado (STATUS). Muestra información de estado en la terminal, incluyendo el estado del proceso en primer plano y la cantidad de tiempo de CPU que ha consumido. También envía una señal SIGINFO (no soportada en Linux) al grupo de procesos en primer plano.
VSTOP
(023, DC3, Ctrl-S) Carácter de parada (STOP). Detiene la salida hasta que se presiona el carácter Start. Reconocido cuando IXON está establecido, y luego no se pasa como entrada.
VSUSP
(032, SUB, Ctrl-Z) Carácter de suspensión (SUSP). Envía la señal SIGTSTP. Reconocido cuando ISIG está establecido, y luego no se pasa como entrada.
VSWTCH
(no en POSIX;
no soportado en Linux; 0, NUL) Carácter de cambio (SWTCH). Usado en System V para cambiar de intérprete en capas de intérprete, un predecesor del control de trabajos del intérprete.
VTIME
Tiempo de espera en décimas de segundo para lectura no canónica (TIME).
VWERASE
(no en POSIX; 027, ETB, Ctrl-W) Borrar palabra (WERASE). Reconocido cuando ICANON y IEXTEN están configurados, y entonces no se pasa como entrada.

Un carácter especial individual del terminal puede ser deshabilitado estableciendo el valor del elemento correspondiente de c_cc a _POSIX_VDISABLE.

Los valores de subíndice simbólicos anteriores son todos diferentes, excepto que VTIME y VMIN pueden tener el mismo valor que VEOL y VEOF, respectivamente. En modo no canónico, el significado del carácter especial es reemplazado por el significado del tiempo de espera. Para una explicación de VMIN y VTIME, ver la descripción del modo no canónico a continuación.

Obtencion y cambio de la configuración del terminal

tcgetattr() obtiene los parámetros asociados con el objeto referenciado por fd y los almacena en la estructura termios referenciada por termios_p. Esta función puede ser invocada desde un proceso en segundo plano; sin embargo, los atributos del terminal pueden ser posteriormente modificados por un proceso en primer plano.

tcsetattr() establece los parámetros asociados con el terminal (a menos que se requiera soporte del hardware subyacente que no esté disponible) a partir de la estructura termios referenciada por termios_p. optional_actions especifica cuándo los cambios entran en vigor:

TCSANOW
el cambio ocurre inmediatamente.
TCSADRAIN
el cambio ocurre después de que toda la salida escrita en fd haya sido transmitida. Esta opción debe usarse al cambiar parámetros que afectan la salida.
TCSAFLUSH
el cambio ocurre después de que toda la salida escrita en el objeto referenciado por fd haya sido transmitida, y toda la entrada recibida pero no leída será descartada antes de que se realice el cambio.

Modo canonical y no canonical

La configuración del flag canon ICANON en c_lflag determina si el terminal está operando en modo canónico (ICANON configurado) o modo no canónico (ICANON sin configurar). Por defecto, ICANON está configurado.

En modo canónico:

•
La entrada se hace disponible línea por línea. Una línea de entrada está disponible cuando se teclea uno de los delimitadores de línea (NL, EOL, EOL2; o EOF al inicio de la línea). Excepto en el caso de EOF, el delimitador de línea se incluye en el buffer devuelto por read(2).
•
La edición de línea está habilitada (ERASE, KILL; y si el flag IEXTEN está configurado: WERASE, REPRINT, LNEXT). Una llamada a read(2) devuelve como máximo una línea de entrada; si la llamada a read(2) solicitó menos bytes de los disponibles en la línea de entrada actual, entonces solo se leen tantos bytes como se solicitaron, y los caracteres restantes estarán disponibles para una futura llamada a read(2).
•
La longitud máxima de línea es de 4096 caracteres (incluyendo el carácter de nueva línea final); las líneas más largas que 4096 caracteres se truncan. Después de 4095 caracteres, el procesamiento de entrada (por ejemplo, el procesamiento de ISIG y ECHO*) continúa, pero cualquier dato de entrada después de 4095 caracteres hasta (pero sin incluir) cualquier nueva línea terminadora se descarta. Esto asegura que el terminal siempre pueda recibir más entrada hasta que al menos una línea pueda ser leída.

En modo no canónico, la entrada está disponible inmediatamente (sin que el usuario tenga que escribir un carácter delimitador de línea), no se realiza ningún procesamiento de entrada y la edición de línea está deshabilitada. El buffer de entrada solo aceptará 4095 caracteres; esto proporciona el espacio necesario para un carácter de nueva línea si el modo de entrada se cambia a canónico. La configuración de MIN (c_cc[VMIN]) y TIME (c_cc[VTIME]) determina las circunstancias en las que una llamada a read(2) se completa; hay cuatro casos distintos:

MIN == 0, TIME == 0 (lectura de sondeo)
Si hay datos disponibles, read(2) devuelve inmediatamente, con la menor cantidad entre los bytes disponibles y los bytes solicitados. Si no hay datos disponibles, read(2) devuelve 0.
MIN > 0, TIME == 0 (lectura bloqueante)
read(2) se bloquea hasta que MIN bytes estén disponibles, y devuelve hasta la cantidad de bytes solicitados.
MIN == 0, TIME > 0 (lectura con tiempo de espera)
TIME especifica el límite de un temporizador en décimas de segundo. El temporizador se inicia cuando se llama a read(2). read(2) devuelve ya sea cuando hay al menos un byte de datos disponible, o cuando expira el temporizador. Si el temporizador expira sin que se disponga de entrada, read(2) devuelve 0. Si los datos ya están disponibles en el momento de la llamada a read(2), la llamada se comporta como si los datos se hubieran recibido inmediatamente después de la llamada.
MIN > 0, TIME > 0 (lectura con tiempo de espera entre bytes)
TIME especifica el límite de un temporizador en décimas de segundo. Una vez que se dispone de un byte inicial de entrada, el temporizador se reinicia después de que se recibe cada byte adicional. read(2) devuelve cuando se cumple alguna de las siguientes condiciones:
•
Se han recibido MIN bytes.
•
El temporizador entre bytes expira.
•
Se han recibido los bytes solicitados por read(2). (POSIX no especifica esta condición de terminación, y en otras implementaciones read(2) no devuelve en este caso.)
Dado que el temporizador solo se inicia después de que el byte inicial está disponible, se leerá al menos un byte. Si los datos ya están disponibles en el momento de la llamada a read(2), la llamada se comporta como si los datos se hubieran recibido inmediatamente después de la llamada.

POSIX no especifica si la configuración del flag de estado de archivo O_NONBLOCK tiene precedencia sobre la configuración de MIN y TIME. Si O_NONBLOCK está configurado, una llamada a read(2) en modo no canónico puede devolver inmediatamente, independientemente de la configuración de MIN o TIME. Además, si no hay datos disponibles, POSIX permite que una llamada a read(2) en modo no canónico devuelva 0, o -1 con errno establecido a EAGAIN.

Modo raw

cfmakeraw() configura el terminal en un modo similar al modo "raw" del antiguo controlador de terminal de la Versión 7: la entrada está disponible carácter por carácter, el eco está deshabilitado y todo el procesamiento especial de los caracteres de entrada y salida del terminal está deshabilitado. Los atributos del terminal se configuran de la siguiente manera:


termios_p->c_iflag &= ~(IGNBRK | BRKINT | PARMRK | ISTRIP
                | INLCR | IGNCR | ICRNL | IXON);
termios_p->c_oflag &= ~OPOST;
termios_p->c_lflag &= ~(ECHO | ECHONL | ICANON | ISIG | IEXTEN);
termios_p->c_cflag &= ~(CSIZE | PARENB);
termios_p->c_cflag |= CS8;

Control de línea

tcsendbreak() transmite una corriente continua de bits de valor cero durante una duración específica, si el terminal está utilizando transmisión de datos serie asíncrona. Si duration es cero, transmite bits de valor cero durante al menos 0.25 segundos y no más de 0.5 segundos. Si duration no es cero, envía bits de valor cero durante un período de tiempo indefinido por la implementación.

Si el terminal no está utilizando transmisión de datos serie asíncrona, tcsendbreak() devuelve sin realizar ninguna acción.

tcdrain() espera hasta que toda la salida escrita en el objeto referenciado por fd haya sido transmitida.

tcflush() descarta los datos escritos en el objeto referenciado por fd pero no transmitidos, o los datos recibidos pero no leídos, dependiendo del valor de queue_selector:

TCIFLUSH
descarta los datos recibidos pero no leídos.
TCOFLUSH
descarta los datos escritos pero no transmitidos.
TCIOFLUSH
descarta tanto los datos recibidos pero no leídos como los datos escritos pero no transmitidos.

tcflow() suspende la transmisión o recepción de datos en el objeto referenciado por fd, dependiendo del valor de action:

TCOOFF
suspende la salida.
TCOON
reanuda la salida suspendida.
TCIOFF
transmite un carácter STOP, que detiene la transmisión de datos del dispositivo terminal al sistema.
TCION
transmite un carácter START, que inicia la transmisión de datos del dispositivo terminal al sistema.

Por defecto al abrir un archivo de terminal, ni su entrada ni su salida están suspendidas.

Establecer la velocidad a B0 instruye al módem a "colgar". La velocidad de bits real correspondiente a B38400 puede ser alterada con setserial(8).

tcsetattr(3)

NOMBRE

tcsetattr - Establecer atributos de terminal

BIBLIOTECA

Funciones de control de terminal (libcurses, -lcurses)

SINOPSIS

#include <termios.h>

int tcsetattr(int fd, int optional_actions, const struct termios *termios_p);

DESCRIPCIÓN

La función tcsetattr establece los atributos del terminal asociados con el descriptor de archivo fd a partir de la estructura termios_p. El argumento optional_actions controla cuándo se realizan los cambios de atributos:

TCSANOW
Los cambios se realizan inmediatamente.
TCSADRAIN
Los cambios se realizan después de que todos los caracteres de salida en el descriptor de archivo fd se hayan transmitido.
TCSAFLUSH
Los cambios se realizan después de que todos los caracteres de salida en el descriptor de archivo fd se hayan transmitido, y todos los caracteres de entrada que no se hayan leído se descartan.

VALOR DE RETORNO

En caso de éxito, tcsetattr devuelve 0. En caso de error, devuelve -1 y establece errno para indicar el error.

ATRIBUTOS

Para obtener explicaciones de los siguientes campos, consulte termios(3).

ESTÁNDARES

POSIX.1-2001, POSIX.1-2008.

HISTORIA

El estándar POSIX introdujo por primera vez esta función.

NOTAS

La estructura termios y las constantes relacionadas se definen en el archivo de cabecera <termios.h>.

ERRORES

Ninguno conocido.
