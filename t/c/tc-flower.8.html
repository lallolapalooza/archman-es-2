NOMBRE

flower - filtro de control de tráfico basado en flujos

SINOPSIS


tc filter ... flower [ LISTA_COINCIDENCIAS ] [ action ESPECIFICACION_ACCION ] [ classid CLASSID ] [ hw_tc TCID ]

LISTA_COINCIDENCIAS := [ LISTA_COINCIDENCIAS ] COINCIDENCIA

COINCIDENCIA := { indev nombre_iface | verbose | skip_sw | skip_hw | { dst_mac | src_mac } LLADDR_ENMASCARADO | vlan_id VID | vlan_prio PRIORIDAD | vlan_ethtype { ipv4 | ipv6 | TIPO_ETH } | cvlan_id VID | cvlan_prio PRIORIDAD | cvlan_ethtype { ipv4 | ipv6 | TIPO_ETH } | pppoe_sid PSID | ppp_proto { ip | ipv6 | mpls_uc | mpls_mc | PROTO_PPP } | mpls LISTA_LSE | mpls_label ETIQUETA | mpls_tc TC | mpls_bos BOS | mpls_ttl TTL | l2tpv3_sid LSID | ip_proto { tcp | udp | sctp | icmp | icmpv6 | l2tp | PROTO_IP } | ip_tos IP_TOS_ENMASCARADO | ip_ttl TTL_IP_ENMASCARADO | { dst_ip | src_ip } PREFIJO | { dst_port | src_port } { NUMERO_ENMASCARADO | puerto_min-puerto_max } | tcp_flags FLAGS_TCP_ENMASCARADOS | type TIPO_ENMASCARADO | code CODIGO_ENMASCARADO | { arp_tip | arp_sip } PREFIJO_IPV4 | arp_op { request | reply | OP } | { arp_tha | arp_sha } LLADDR_ENMASCARADO | enc_key_id ID_LLAVE | { enc_dst_ip | enc_src_ip } { direccion_ipv4 | direccion_ipv6 } | enc_dst_port numero_puerto | enc_tos TOS | enc_ttl TTL | { geneve_opts | vxlan_opts | erspan_opts | gtp_opts | pfcp_opts } OPCIONES | ip_flags FLAGS_IP | l2_miss L2_MISS | cfm OPCIONES_CFM | enc_flags LISTA_FLAGS_ENC }

DESCRIPCIÓN

El filtro flower coincide con flujos con el conjunto de claves especificado y les asigna un ID de clase elegido arbitrariamente a los paquetes que pertenecen a ellos. Adicionalmente (o alternativamente) se puede llamar a una acción del framework de acciones genéricas.

OPCIONES

action ESPECIFICACION_ACCION
Aplica una acción del framework de acciones genéricas a los paquetes coincidentes.
classid CLASSID
Especifica una clase a la que pasar los paquetes coincidentes. CLASSID tiene el formato X:Y, mientras que X e Y se interpretan como números en formato hexadecimal.
hw_tc TCID
Especifica una clase de tráfico de hardware a la que pasar los paquetes coincidentes. TCID está en el rango de 0 a 15.
indev nombre_iface
Coincide con el nombre de la interfaz entrante. Obviamente, esto solo tiene sentido para flujos reenviados. nombre_iface es el nombre de una interfaz que debe existir en el momento de la invocación de tc.
verbose
Habilita el registro detallado, incluyendo errores de descarga cuando no se usa el flag skip_sw.
skip_sw
No procesar el filtro por software. Si el hardware no tiene soporte de descarga para este filtro, o si la descarga de TC no está habilitada para la interfaz, la operación fallará.
skip_hw
No procesar el filtro por hardware.
dst_mac LLADDR_ENMASCARADO
src_mac LLADDR_ENMASCARADO
Coincide con la dirección MAC de origen o destino. Opcionalmente se puede proporcionar una máscara para limitar los bits de la dirección que se comparan. La máscara se proporciona siguiendo la dirección con una barra y luego la máscara. Puede proporcionarse en formato LLADDR, en cuyo caso es una máscara bit a bit, o como número de bits altos a comparar. Si falta la máscara, se asume una coincidencia en todos los bits.
num_of_vlans NUM
Coincide con el número de etiquetas VLAN en el paquete. NUM puede ser 0 o un entero positivo pequeño. Típicamente en el rango 0-4.
vlan_id VID
Coincide con el ID de la etiqueta VLAN. VID es un valor decimal sin signo de 12 bits.
vlan_prio PRIORIDAD
Coincide con la prioridad de la etiqueta VLAN. PRIORIDAD es un valor decimal sin signo de 3 bits.
vlan_ethtype TIPO_ETH_VLAN
Coincide con el protocolo de capa tres. TIPO_ETH_VLAN puede ser ipv4, ipv6 o un valor hexadecimal sin signo de 16 bits. Para coincidir con un paquete QinQ, debe ser 802.1Q o 802.1AD.
cvlan_id VID
Coincide con el ID de la etiqueta VLAN interna QinQ. VID es un valor decimal sin signo de 12 bits.
cvlan_prio PRIORIDAD
Coincide con la prioridad de la etiqueta VLAN interna QinQ. PRIORIDAD es un valor decimal sin signo de 3 bits.
cvlan_ethtype TIPO_ETH_VLAN
Coincide con el protocolo de capa tres QinQ. TIPO_ETH_VLAN puede ser ipv4, ipv6 o un valor hexadecimal sin signo de 16 bits.
pppoe_sid PSID
Coincide con el ID de sesión PPPoE. PSID es un valor decimal sin signo de 16 bits.
ppp_proto PROTO_PPP
Coincide con el protocolo de capa tres PPP. PROTO_PPP puede ser ip, ipv6, mpls_uc, mpls_mc o un valor hexadecimal sin signo de 16 bits.
mpls LISTA_LSE
Coincide con la pila de etiquetas MPLS. LISTA_LSE es una lista de Entradas de Pila de Etiquetas, cada una introducida por la palabra clave lse. Esta opción no se puede usar junto con las opciones autónomas mpls_label, mpls_tc, mpls_bos y mpls_ttl.
lse OPCIONES_LSE
Coincide con una Entrada de Pila de Etiquetas MPLS. OPCIONES_LSE es una lista de opciones que describen las propiedades de la LSE a comparar.
depth PROFUNDIDAD
La profundidad de la Entrada de Pila de Etiquetas a considerar. La profundidad comienza en 1 (la Entrada de Pila de Etiquetas más externa). La profundidad máxima utilizable puede estar limitada por el kernel. Esta opción es obligatoria. PROFUNDIDAD es un valor decimal sin signo de 8 bits.
label ETIQUETA
Coincide con el campo Etiqueta MPLS en la profundidad especificada. ETIQUETA es un valor decimal sin signo de 20 bits.
tc TC
Coincide con el campo Clase de Tráfico MPLS en la profundidad especificada. TC es un valor decimal sin signo de 3 bits.
bos BOS
Coincide con el campo Bottom Of Stack (BOS) MPLS en la profundidad especificada. BOS es un valor decimal de 1 bit.
ttl TTL
Coincide con el campo Time To Live (TTL) MPLS en la profundidad especificada. TTL es un
mpls_label LABEL
Coincide con el campo Etiqueta MPLS. LABEL es un valor decimal sin signo de 20 bits.
mpls_tc TC
Coincide con el campo Clase de Tráfico MPLS. TC es un valor decimal sin signo de 3 bits.
mpls_bos BOS
Coincide con el campo Bottom Of Stack (BOS) MPLS. BOS es un valor decimal de 1 bit.
mpls_ttl TTL
Coincide con el campo Time To Live (TTL) MPLS. TTL es un valor decimal sin signo de 8 bits.
l2tpv3_sid LSID
Coincide con el ID de sesión L2TPv3. LSID es un valor decimal sin signo de 32 bits.
ip_proto PROTO_IP
Coincide con el protocolo IP. PROTO_IP puede ser tcp, udp, sctp, icmp, icmpv6, l2tp o un valor decimal sin signo de 8 bits.
ip_tos IP_TOS_ENMASCARADO
Coincide con el campo ToS (Type of Service) de IP. El valor puede ser un decimal o hexadecimal sin signo de 8 bits. Si se proporciona una máscara (por ejemplo, 0x1e/0xe0), solo se compararán los bits enmascarados.
ip_ttl TTL_IP_ENMASCARADO
Coincide con el campo TTL de IP. El valor puede ser un decimal o hexadecimal sin signo de 8 bits. Si se proporciona una máscara (por ejemplo, 0x3e/0xe0), solo se compararán los bits enmascarados.
dst_ip PREFIJO
src_ip PREFIJO
Coincide con la dirección IP de origen o destino. PREFIJO es una dirección IP en notación CIDR (por ejemplo, 192.168.1.0/24).
dst_port NUMERO_ENMASCARADO
src_port NUMERO_ENMASCARADO
Coincide con el puerto de origen o destino. NUMERO_ENMASCARADO puede ser un número decimal o hexadecimal sin signo de 16 bits, o un rango de puertos (por ejemplo, 1024-4096). Si se proporciona una máscara (por ejemplo, 0x10/0x20), solo se compararán los bits enmascarados.
tcp_flags FLAGS_TCP_ENMASCARADOS
Coincide con los flags TCP. Se especifican como una lista de flags, seguida opcionalmente por una máscara (por ejemplo, "fin/syn,ack"). Los flags disponibles son: fin, syn, rst, psh, ack, urg.
type TIPO_ENMASCARADO
Coincide con el tipo ICMP. TIPO_ENMASCARADO puede ser un número decimal o hexadecimal sin signo de 8 bits, o un rango (por ejemplo, "8-10").
code CODIGO_ENMASCARADO
Coincide con el código ICMP. CODIGO_ENMASCARADO puede ser un número decimal o hexadecimal sin signo de 8 bits, o un rango (por ejemplo, "0-2").
arp_tip PREFIJO_IPV4
arp_sip PREFIJO_IPV4
Coincide con la IP de destino o origen de ARP. PREFIJO_IPV4 es una dirección IPv4 en notación CIDR.
arp_op OP
Coincide con el código de operación ARP. OP puede ser request, reply o un número decimal o hexadecimal sin signo de 8 bits.
arp_tha LLADDR_ENMASCARADO
arp_sha LLADDR_ENMASCARADO
Coincide con la dirección MAC de destino o origen de ARP.
enc_key_id ID_LLAVE
Coincide con el ID de clave de encapsulación (IPsec). ID_LLAVE es un valor decimal o hexadecimal sin signo de 32 bits.
enc_dst_ip direccion_ipv4
enc_src_ip direccion_ipv4
Coincide con la dirección IP de destino o origen encapsulada (por ejemplo, en túneles VXLAN, Geneve). Puede ser una dirección IPv4 o IPv6.
enc_dst_port numero_puerto
Coincide con el puerto de destino encapsulado.
enc_tos TOS
Coincide con el campo ToS de IP encapsulado.
enc_ttl TTL
Coincide con el campo TTL de IP encapsulado.
geneve_opts OPCIONES
Coincide con las opciones del encabezado Geneve. El formato de las opciones es una lista separada por comas de pares clave=valor. Consulte la documentación de `tc-geneve(8)` para obtener más detalles.
vxlan_opts OPCIONES
Coincide con las opciones del encabezado VXLAN. El formato de las opciones es una lista separada por comas de pares clave=valor. Consulte la documentación de `tc-vxlan(8)` para obtener más detalles.
erspan_opts OPCIONES
Coincide con las opciones del encabezado ERSPAN. Consulte la documentación de `tc-erspan(8)` para obtener más detalles.
gtp_opts OPCIONES
Coincide con las opciones del encabezado GTP. Consulte la documentación de `tc-gtp(8)` para obtener más detalles.
pfcp_opts OPCIONES
Coincide con las opciones del encabezado PFCP. Consulte la documentación de `tc-pfcp(8)` para obtener más detalles.
ip_flags FLAGS_IP
Coincide con los flags de fragmentación IP. Los flags disponibles son: frag_mf, frag_df, frag_more.
l2_miss L2_MISS
Si se establece en 1, este filtro coincidirá con paquetes que no tienen una entrada en la tabla de conmutación L2 (para switches compatibles con OpenFlow o similar). Esto es útil para la detección de nuevos flujos.
cfm OPCIONES_CFM
Coincide con campos relacionados con Connectivity Fault Management (CFM). Las opciones disponibles son:
cfmmdl NIVEL
Coincide con el nivel de dominio MEP (Maintenance Endpoint) de CFM (0-7).
op OPCODIGO
Coincide con el código de operación de mensaje CFM (0-27).
enc_flags LISTA_FLAGS_ENC
Coincide con flags relacionados con la encapsulación y la checksum. Las opciones son:
[no]tuncsum
Coincide con la flag de checksum de túnel. Utilice tuncsum para coincidir con checksum válido, notuncsum para checksum inválido.
[no]tundf
Coincide con la flag de "don't fragment" de túnel. Utilice tundf para coincidir con el flag DF establecido, notundf para no establecido.
[no]tunoam
Coincide con la flag de "overhead acknowledge" de túnel.
[no]tuncrit
Coincide con la flag de "critical" de túnel.

Cada clave de coincidencia se puede especificar una vez, excepto indev y las llaves de encapsulación (enc_*), que pueden especificarse varias veces para coincidir con flujos que pasan por múltiples túneles o interfaces.

Las llaves de coincidencia para las que no se proporciona una máscara se comparan exactamente. Las llaves de coincidencia que aceptan máscaras se pueden especificar con una máscara bit a bit (por ejemplo, src_mac 00:11:22:33:44:55/ff:ff:ff:00:00:00) o como un número de bits altos a comparar (por ejemplo, dst_ip 192.168.1.0/24).

Los valores numéricos pueden ser decimales, hexadecimales (prefijados con 0x) o, para direcciones MAC, en notación estándar. Los rangos se pueden especificar como min-max.

El orden de las claves de coincidencia no importa.

EJEMPLOS

Para redirigir todo el tráfico de la interfaz eth0 con MAC 00:01:02:03:04:05 al classid 1:10:

tc filter add dev eth0 parent 1:0 protocol ip prio 1 \
    flower indev eth0 src_mac 00:01:02:03:04:05 \
    classid 1:10

Para marcar paquetes que van al puerto 80 de la IP 192.168.1.1 con la acción `flow action reclassify`:

tc filter add dev eth0 parent 1:0 protocol ip prio 1 \
    flower dst_ip 192.168.1.1 dst_port 80 \
    action flow action reclassify

Para redirigir paquetes VLAN con ID 100 y prioridad 3 al classid 1:20:

tc filter add dev eth0 parent 1:0 protocol 802.1Q prio 1 \
    flower vlan_id 100 vlan_prio 3 \
    classid 1:20

Para redirigir paquetes con dos etiquetas VLAN (QinQ), donde la etiqueta externa es 100 y la interna es 200, al classid 1:30:

tc filter add dev eth0 parent 1:0 protocol 802.1Q prio 1 \
    flower vlan_id 100 cvlan_id 200 \
    classid 1:30

Para redirigir paquetes VXLAN con VNI 12345 y destino 10.0.0.1 al classid 1:40:

tc filter add dev eth0 parent 1:0 protocol udp prio 1 \
    flower dst_ip 10.0.0.1 encap vxlan id 12345 \
    classid 1:40

La opción se puede describir en el formato GBP/GBP_MASK, donde GBP se representa como un número de 32 bits. erspan_opts OPTIONS no admite múltiples opciones y consta de una clave seguida de una barra y la máscara correspondiente. Si falta la máscara, tc asume una coincidencia de longitud completa. La opción se puede describir en el formato VERSION:INDEX:DIR:HWID/VERSION:INDEX_MASK:DIR_MASK:HWID_MASK, donde VERSION se representa como un número de 8 bits, INDEX como un número de 32 bits, DIR y HWID como un número de 8 bits. No se admiten múltiples opciones. Tenga en cuenta que INDEX/INDEX_MASK se utiliza cuando VERSION es 1, y DIR/DIR_MASK y HWID/HWID_MASK se utilizan cuando VERSION es 2. gtp_opts OPTIONS no admite múltiples opciones y consta de una clave seguida de una barra y la máscara correspondiente. Si falta la máscara, tc-flower(8) - Arch Linux

NAME

tc-flower - Filter for tc, using a generic flow classifier

SYNOPSIS

tc filter add ... flower
match ... action ...

DESCRIPTION

The flower classifier is a generic classifier that is able to match on a wide range of packet metadata and payload. It is designed to replace the older tc classifiers like tc-u32, tc-route, tc-fw and others.

The syntax for adding a rule is:

tc filter add ... flower [ match ... ] [ action ... ]

The possible matches are keywords followed by their corresponding values. The available matches are:

Match on source MAC address.

Match on the TCP flags. The flags are represented in hexadecimal. Possible flags are SYN, ACK, FIN, RST, PSH, URG, and their combinations. Mask is applied implicitly.

Match on the MPLS traffic class. The option can be described in the form PDU_TYPE:QFI/PDU_TYPE_MASK:QFI_MASK where both PDU_TYPE and QFI are represented as a 8bit hexadecimal values. pfcp_opts OPTIONS does not support multiple options. It consists of a key followed by a slash and corresponding mask. If the mask is missing, tc assumes a full-length match. The option can be described in the form TYPE:SEID/TYPE_MASK:SEID_MASK where TYPE is represented as a 8bit number, SEID is represented by 64bit. Both TYPE and SEID are provided in hex.
ip_flags IP_FLAGS
IP_FLAGS may be either frag, nofrag, firstfrag or nofirstfrag where frag and nofrag could be used to match on fragmented packets or not, respectively. firstfrag and nofirstfrag can be used to further distinguish fragmented packet. firstfrag can be used to indicate the first fragmented packet. nofirstfrag can be used to indicates subsequent fragmented packets or non-fragmented packets.
l2_miss L2_MISS
Match on layer 2 miss in the bridge driver's FDB / MDB. L2_MISS may be 0 or 1. When 1, match on packets that encountered a layer 2 miss. When 0, match on packets that were forwarded using an FDB / MDB entry. Note that broadcast packets do not encounter a miss since a lookup is not performed for them.

Match on Connectivity Fault Management (CFM) fields. CFM_OPTIONS is a list of options that describe the properties of the CFM information fields to match.

Match on the Maintenance Domain (MD) level field. LEVEL is an unsigned 3 bit value in decimal format.
op OPCODE
Match on the CFM opcode field. OPCODE is an unsigned 8 bit value in decimal format.
enc_flags ENCFLAG-LIST
Match on tunnel control flags. ENCFLAG-LIST is a list of the following tunnel control flags: [no]tuncsum, [no]tundf, [no]tunoam, [no]tuncrit, each separated by '/'.

NOTES

As stated above where applicable, matches of a certain layer implicitly depend on the matches of the next lower layer. Precisely, layer one and two matches (indev, dst_mac, src_mac and enc_flags) have no dependency, MPLS and layer three matches (mpls, mpls_label, mpls_tc, mpls_bos, mpls_ttl, ip_proto, dst_ip, src_ip, arp_tip, arp_sip, arp_op, arp_tha, arp_sha and ip_flags) depend on the protocol option of tc filter, layer four port matches (dst_port and src_port) depend on ip_proto being set to tcp, udp or sctp, and finally ICMP matches (code and type) depend on ip_proto being set to icmp or icmpv6.

There can be only used one mask per one prio. If user needs to specify different mask, he has to use different prio.
