TCPSPRAY(1) Manual del usuario TCPSPRAY(1)

NOMBRE

tcpspray - herramienta de medición de ancho de banda TCP/IP (cliente Discard y Echo)

SINOPSIS

tcpspray [-46ev] [-b tamaño_bloque] [-d espera_µs] [ -f nombre_archivo] [-n cantidad] <nombre_host> [puerto]

DESCRIPCIÓN

tcpspray utiliza el protocolo Discard o Echo (RFC 863 o RFC 862, respectivamente) para realizar mediciones de ancho de banda de sesiones TCP entre el sistema local y un servidor Discard o Echo.

Los hosts basados en Unix pueden proporcionar servidores Discard y/o Echo con el super-servidor de Internet inetd. En Windows NT, el componente opcional protocolos de red simples hará lo mismo.

Se debe especificar el nombre o la dirección del nodo servidor. tcpspray intentará automáticamente usar IPv6 cuando esté disponible. Si no, o si falla, recurrirá a IPv4. Sin embargo, tcpspray4 o tcpspray6 solo intentan usar IPv4 o IPv6, respectivamente.

OPCIONES

-4 o --ipv4
Forzar el uso de TCP sobre IPv4.
-6 o --ipv6
Forzar el uso de TCP sobre IPv6.
-b tamaño_bloque o --bsize tamaño_bloque
Enviar un bloque del tamaño de bytes especificado (por defecto: 1024).
-d espera_µs o --delay espera_µs
Espera la cantidad dada de microsegundos después de enviar cualquier dato antes de intentar enviar el siguiente. No hay retraso por defecto.
-e o --echo
Usar el protocolo Echo en lugar de Discard. tcpspray medirá el tiempo requerido para enviar datos y recibirlos de vuelta, en lugar de simplemente enviarlos.
-f nombre_archivo o --fill nombre_archivo
Leer datos del archivo especificado para rellenar los bloques enviados. Si el archivo es más pequeño que el tamaño de los bloques, o si no se especificó ningún archivo, los bytes restantes del final se establecerán a cero.
-h o --help
Mostrar ayuda y salir.
-n cantidad_bloques o --count cantidad_bloques
Enviar la cantidad especificada de bloques de datos para las mediciones (por defecto: 100).
-V o --version
Mostrar la versión del programa y la licencia y salir.
-v o --verbose
Mostrar información más detallada. En particular, tcpspray imprimirá un punto cada vez que se envíe un bloque. Si se usa el protocolo Echo (opción -e), los puntos se borrarán a medida que se reciben los datos.

DIAGNÓSTICOS

Si no recibe respuesta mientras sabe que el host remoto está activo, lo más probable es que no tenga un servicio Discard/Echo en ejecución, o que estos servicios estén bloqueados por un cortafuegos. Ejecutar tcptraceroute6(8) o tcptraceroute(8) hacia el host remoto IPv6 o IPv4, respectivamente, podría ayudar a detectar tal situación.

SEGURIDAD

tcpspray no requiere ningún privilegio para ejecutarse.

VER TAMBIÉN

tcp(7), inetd(8), tcptraceroute6(8), tcptraceroute(8)
