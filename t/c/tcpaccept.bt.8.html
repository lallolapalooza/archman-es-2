NOMBRE

tcpaccept.bt - Rastrea conexiones TCP pasivas (accept()). Utiliza bpftrace/eBPF

SINOPSIS

tcpaccept.bt

DESCRIPCIÓN

Esta herramienta rastrea conexiones TCP pasivas (por ejemplo, a través de una llamada al sistema accept(); connect() son conexiones activas). Esto puede ser útil para la resolución general de problemas para ver qué nuevas conexiones está aceptando el servidor local.

Esto utiliza el rastreo dinámico de la función de socket del kernel inet_csk_accept() (desde tcp_prot.accept), y necesitará ser modificado para coincidir con los cambios del kernel.

Esta herramienta solo rastrea los accept() de TCP exitosos. Los intentos de conexión a puertos cerrados no se mostrarán (esos se pueden rastrear a través de otras funciones).

Dado que esto utiliza BPF, solo el usuario root puede usar esta herramienta.

REQUISITOS

CONFIG_BPF y bpftrace.

EJEMPLOS

Rastrea todas las conexiones TCP pasivas (accept()):
# tcpaccept.bt

CAMPOS

HORA(s)
Hora de la llamada, en formato HH:MM:SS.
PID
ID del proceso.
COMM
Nombre del proceso.
RADDR
Dirección IP remota.
RPORT
Puerto remoto.
LADDR
Dirección IP local.
LPORT
Puerto local.
BL
Cola de espera de accept() actual frente a la cola máxima.

SOBRECARGA

Esto rastrea la función de kernel inet_csk_accept e imprime la salida para cada evento. La tasa de esto depende de su aplicación de servidor. Si es un servidor web o proxy que acepta decenas de miles de conexiones por segundo, la sobrecarga de esta herramienta puede ser medible (aunque, sigue siendo mucho mejor que rastrear cada paquete). Si es menos de mil por segundo, se espera que la sobrecarga sea insignificante. Pruebe y comprenda esta sobrecarga antes de usarla.
