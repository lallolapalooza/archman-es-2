NOMBRE

drr - planificador deficit round robin (round robin con déficit)

SINOPSIS

tc qdisc ... add drr [ quantum bytes ]

DESCRIPCIÓN

El Planificador Deficit Round Robin es una disciplina de cola classful (basada en clases) como un reemplazo más flexible para Stochastic Fairness Queuing (SFQ).

A diferencia de SFQ, no hay colas integradas: necesita agregar clases y luego configurar filtros para clasificar los paquetes en consecuencia. Esto puede ser útil, por ejemplo, para usar colas RED con diferentes configuraciones para tráfico específico. No hay una clase predeterminada: si un paquete no se puede clasificar, se descarta.

ALGORITMO

A cada clase se le asigna un contador de déficit, inicializado en quantum.

DRR mantiene una lista interna de clases ''activas'' cuyas colas no están vacías. Esta lista se utiliza para la extracción. Se extrae un paquete de la clase al principio de la lista si el tamaño del paquete es menor o igual al contador de déficit. Si el contador es demasiado pequeño, se incrementa en quantum y el planificador pasa a la siguiente clase en la lista activa.

PARÁMETROS

quantum
Cantidad de bytes que se permite extraer a un flujo antes de que el planificador pase a la siguiente clase. Por defecto es la MTU de la interfaz. El valor mínimo es 1.

EJEMPLO & USO

Para adjuntar a la interfaz eth0, usando la MTU de la interfaz como su quantum:

# tc qdisc add dev eth0 handle 1 root drr

Agregando dos clases:

# tc class add dev eth0 parent 1: classid 1:1 drr
# tc class add dev eth0 parent 1: classid 1:2 drr

También necesita agregar al menos un filtro para clasificar los paquetes.

# tc filter add dev eth0 protocol .. classid 1:1

Al igual que SFQ, DRR solo es útil cuando posee la cola; es un planificador puro y no retrasa paquetes. Adjuntar colas no que work-conserving como tbf a él no tiene sentido; otras colas en la lista activa también se volverán inactivas hasta que la operación de extracción se complete. Incruste DRR dentro de otra cola como HTB o HFSC para asegurar que posea la cola.

Puede imitar el comportamiento de SFQ asignando paquetes a las clases adjuntas usando el filtro de flujo:

tc qdisc add dev .. drr

for i in .. 1024;do
tc class add dev .. classid $handle:$(print %x $i)
tc qdisc add dev .. fifo limit 16
done

tc filter add .. protocol ip .. $handle flow hash keys src,dst,proto,proto-src,proto-dst divisor 1024 perturb 10

FUENTE

o
M. Shreedhar y George Varghese "Efficient Fair Queuing using Deficit Round Robin", Proc. SIGCOMM 95.

NOTAS

Esta implementación no descarta paquetes de la cola más larga en caso de desbordamiento, ya que los límites son manejados por las colas hijas individuales.
