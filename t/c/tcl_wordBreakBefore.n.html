INTRODUCCIÓN

Tcl incluye una biblioteca de procedimientos de Tcl para funciones de uso común. Los procedimientos definidos en la biblioteca de Tcl son genéricos y adecuados para su uso por muchas aplicaciones diferentes. La ubicación de la biblioteca de Tcl la devuelve el comando info library. Además de la biblioteca de Tcl, cada aplicación normalmente tendrá su propia biblioteca de procedimientos de soporte; la ubicación de esta biblioteca normalmente se indica mediante el valor de la variable global $app_library, donde app es el nombre de la aplicación. Por ejemplo, la ubicación de la biblioteca Tk se mantiene en la variable tk_library.

Para acceder a los procedimientos de la biblioteca de Tcl, una aplicación debe cargar el archivo init.tcl de la biblioteca, por ejemplo, con el comando Tcl

source [file join [info library] init.tcl]

Si se invoca el procedimiento de biblioteca Tcl_Init desde el procedimiento Tcl_AppInit de una aplicación, esto ocurre automáticamente. El código en init.tcl definirá el procedimiento unknown y organizará la carga de los demás procedimientos bajo demanda utilizando el mecanismo de carga automática definido a continuación.

PROCEDIMIENTOS DE COMANDO

Los siguientes procedimientos se proporcionan en la biblioteca de Tcl:

auto_execok cmd
Determina si existe un archivo ejecutable o una orden interna del shell con el nombre cmd. Si es así, devuelve una lista de argumentos que se pasarán a exec para ejecutar el archivo ejecutable o la orden interna del shell denominada por cmd. Si no, devuelve una cadena vacía. Este comando examina los directorios en la ruta de búsqueda actual (proporcionada por la variable de entorno PATH) en su búsqueda de un archivo ejecutable con el nombre cmd. En plataformas Windows, la búsqueda se amplía con los mismos directorios y extensiones de archivo que utiliza exec. Auto_execok recuerda información sobre búsquedas anteriores en un array denominado auto_execs; esto evita la búsqueda de ruta en llamadas futuras para el mismo cmd. El comando auto_reset puede usarse para forzar a auto_execok a olvidar su información en caché.
auto_import patrón
Auto_import se invoca durante namespace import para ver si los comandos importados especificados por patrón residen en una biblioteca cargada automáticamente. Si es así, los comandos se cargan para que estén disponibles para el intérprete para crear los enlaces de importación. Si los comandos no residen en una biblioteca cargada automáticamente, auto_import no hace nada. La coincidencia de patrones se realiza de acuerdo con las reglas de coincidencia de namespace import.
auto_load cmd
Este comando intenta cargar la definición de un comando Tcl denominado cmd. Para hacer esto, busca en una ruta de carga automática, que es una lista de uno o más directorios. La ruta de carga automática se proporciona mediante la variable global auto_path si existe. Si no existe la variable auto_path, entonces se utiliza la variable de entorno TCLLIBPATH, si existe. De lo contrario, la ruta de carga automática consta solo del directorio de la biblioteca Tcl. Dentro de cada directorio en la ruta de carga automática debe haber un archivo tclIndex que describe uno o más comandos definidos en ese directorio y un script para evaluar y cargar cada uno de los comandos. El archivo tclIndex debe generarse con el comando auto_mkindex. Si cmd se encuentra en un archivo de índice, se evalúa el script apropiado para crear el comando. El comando auto_load devuelve 1 si cmd se creó correctamente. El comando devuelve 0 si no hubo una entrada de índice para cmd o si el script en realidad no definió cmd (por ejemplo, porque la información del índice está desactualizada). Si ocurre un error al procesar el script, ese error se devuelve. Auto_load solo lee la información del índice una vez y la guarda en el array auto_index; las llamadas posteriores a auto_load buscan cmd en el array en lugar de volver a leer los archivos de índice. La información del índice en caché se puede eliminar con el comando auto_reset. Esto forzará al próximo comando auto_load a recargar la base de datos de índices desde el disco.
auto_mkindex dir patrón patrón ...
Genera un índice adecuado para su uso por auto_load. El comando busca en dir todos los archivos cuyos nombres coincidan con cualquiera de los argumentos patrón (la coincidencia se realiza con el comando glob), genera un índice de todos los procedimientos de comandos Tcl definidos en todos los archivos coincidentes y almacena la información del índice en un archivo llamado tclIndex en dir. Si no se proporciona ningún patrón, se asumirá un patrón de *.tcl. Por ejemplo, el comando
auto_mkindex foo *.tcl

leerá todos los archivos .tcl en el subdirectorio foo y generará un nuevo archivo de índice foo/tclIndex.

Auto_mkindex analiza los scripts Tcl cargándolos en un intérprete hijo y monitorizando los comandos proc y namespace que se ejecutan. Las extensiones pueden utilizar el paquete (no documentado) auto_mkindex_parser para registrar otros comandos que pueden contribuir al índice de carga automática. Tendrás que leer auto.tcl para ver cómo funciona esto.

Auto_mkindex_old (que tiene la misma sintaxis que auto_mkindex) analiza los scripts Tcl de una manera relativamente poco sofisticada: si alguna línea contiene la palabra “proc” como sus primeros caracteres, se asume que es una definición de procedimiento y la siguiente palabra de la línea se toma como el nombre del procedimiento. Las definiciones de procedimientos que no aparecen de esta manera (por ejemplo, tienen espacios antes de proc) no se indexarán. Si tu script contiene código “peligroso”, como código de inicialización global o nombres de procedimientos con caracteres especiales como $, *, [ o ], estarás más seguro usando auto_mkindex_old.

auto_reset
Destruye toda la información almacenada en caché por auto_execok y auto_load. Esta información se volverá a leer desde el disco la próxima vez que se necesite. Auto_reset también elimina cualquier procedimiento listado en el índice de carga automática, de modo que se carguen copias nuevas de ellos la próxima vez que se utilicen.
auto_qualify comando namespace
Calcula una lista de nombres completamente calificados para comando. Esta lista refleja la ruta que sigue un intérprete Tcl estándar para la búsqueda de comandos: primero busca el comando en el namespace actual y luego en el namespace global. En consecuencia, si comando es relativo y namespace no es ::, la lista devuelta tiene dos elementos: comando con ámbito de namespace, como si fuera un comando en el namespace namespace; y comando como si fuera un comando en el namespace global. De lo contrario, si comando es absoluto (comienza con ::), o namespace es ::, la lista contiene solo comando como si fuera un comando en el namespace global.

Auto_qualify es utilizada por las facilidades de carga automática en Tcl, tanto para producir índices de carga automática como pkgIndex.tcl, como para realizar la carga automática real de funciones en tiempo de ejecución.

NOMBRE

tcl_wordBreakAfter, tcl_wordBreakBefore, tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord - ayuda para determinar los límites de palabras

SINOPSIS

tcl_endOfWord str start
tcl_startOfNextWord str start
tcl_startOfPreviousWord str start
tcl_wordBreakAfter str start
tcl_wordBreakBefore str start

DESCRIPCIÓN

Estas rutinas son útiles para dividir el texto en palabras, de forma similar a como lo hacen los editores de texto. Son principalmente para uso interno de Tk, pero pueden ser llamadas directamente por las aplicaciones Tcl.

tcl_endOfWord str start
Devuelve el índice de la primera ubicación de fin de palabra que ocurre después de un índice de inicio start en la cadena str. Una ubicación de fin de palabra se define como el primer carácter que no es de palabra después del primer carácter de palabra después del punto de partida. Devuelve -1 si no hay más ubicaciones de fin de palabra después del punto de partida. Consulte la descripción de tcl_wordchars y tcl_nonwordchars a continuación para obtener más detalles sobre cómo Tcl determina qué caracteres son caracteres de palabra.
tcl_startOfNextWord str start
Devuelve el índice de la primera ubicación de inicio de palabra que ocurre después de un índice de inicio start en la cadena str. Una ubicación de inicio de palabra se define como el primer carácter de palabra que sigue a un carácter que no es de palabra. Devuelve -1 si no hay más ubicaciones de inicio de palabra después del punto de partida.
tcl_startOfPreviousWord str start
Devuelve el índice de la primera ubicación de inicio de palabra que ocurre antes de un índice de inicio start en la cadena str. Devuelve -1 si no hay más ubicaciones de inicio de palabra antes del punto de partida.
tcl_wordBreakAfter str start
Devuelve el índice del primer límite de palabra después del índice de inicio start en la cadena str. Devuelve -1 si no hay más límites después del punto de partida en la cadena dada. El índice devuelto se refiere al segundo carácter del par que comprende un límite.
tcl_wordBreakBefore str start
Devuelve el índice del primer límite de palabra antes del índice de inicio start en la cadena str. Devuelve -1 si no hay más límites antes del punto de partida en la cadena dada. El índice devuelto se refiere al segundo carácter del par que comprende un límite.

PROCEDIMIENTOS DE COMANDO

unknown args
Este procedimiento se llama cuando se invoca un comando que no está definido. Los procedimientos de carga automática y de carga de paquetes solo se llaman si el comando se define como parte de la inicialización de la aplicación, de lo contrario, se llama a este procedimiento. Este es un procedimiento de búsqueda estándar para que lo utilicen las extensiones durante su inicialización. Llaman a este procedimiento para buscar su biblioteca de scripts en varios directorios estándar. El último componente del nombre del directorio de la biblioteca es normalmente basenameversion (por ejemplo, tk8.0), pero podría ser “library” cuando está en las jerarquías de compilación. El archivo initScript se cargará en el intérprete una vez que se encuentre. El directorio en el que se encuentra este archivo se almacena en la variable global varName. Si esta variable ya está definida (por ejemplo, por código C durante la inicialización de la aplicación), no se realiza ninguna búsqueda. De lo contrario, la búsqueda busca en estos directorios: el directorio nombrado por la variable de entorno enVarName; relativo al directorio de la biblioteca Tcl; relativo al archivo ejecutable en el directorio bin o bin/arch estándar de instalación; relativo al archivo ejecutable en el árbol de compilación actual; relativo al archivo ejecutable en un árbol de compilación paralelo.
parray arrayName ?pattern?
Imprime en la salida estándar los nombres y valores de todos los elementos del array arrayName, o solo los nombres que coinciden con pattern (usando las reglas de coincidencia de string match) y sus valores si se proporciona pattern. ArrayName debe ser un array accesible al llamador de parray. Puede ser local o global.

VARIABLES

Las siguientes variables globales son definidas o utilizadas por los procedimientos de la biblioteca Tcl. Se dividen en dos clases amplias: manejo de comandos y paquetes desconocidos, y determinación de qué son las palabras.

VARIABLES DE AUTOCARGA Y GESTIÓN DE PAQUETES

auto_execs
Utilizado por auto_execok para registrar información sobre si comandos particulares existen como archivos ejecutables.
auto_index
Utilizado por auto_load para guardar la información del índice leída del disco.
auto_noexec
Si se establece en cualquier valor, entonces unknown no intentará ejecutar automáticamente ningún comando.
auto_noload
Si se establece en cualquier valor, entonces unknown no intentará cargar automáticamente ningún comando.
auto_path
Si se establece, entonces debe contener una lista Tcl válida que indique los directorios que se buscarán durante las operaciones de carga automática (incluyendo los archivos de índice de paquetes cuando se utiliza el manejador predeterminado package unknown). Esta variable se inicializa durante el inicio para contener, en orden: los directorios enumerados en la variable de entorno TCLLIBPATH, el directorio nombrado por la variable global tcl_library, el directorio padre de tcl_library, los directorios enumerados en la variable tcl_pkgPath. Las ubicaciones adicionales para buscar archivos e índices de paquetes normalmente deberían agregarse a esta variable usando lappend.
env(TCL_LIBRARY)
Si se establece, entonces especifica la ubicación del directorio que contiene los scripts de la biblioteca (el valor de esta variable se asignará a la variable tcl_library y, por lo tanto, será devuelto por el comando info library). Si esta variable no está establecida, se utiliza un valor predeterminado.
env(TCLLIBPATH)
Si se establece, entonces debe contener una lista Tcl válida que indique los directorios que se buscarán durante las operaciones de carga automática. Los directorios deben especificarse en formato Tcl, usando “/” como separador de ruta, independientemente de la plataforma. Esta variable solo se utiliza al inicializar la variable auto_path.

VARIABLES DE DETERMINACIÓN DE LÍMITES DE PALABRAS

Estas variables solo se utilizan en los comandos tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter y tcl_wordBreakBefore.

tcl_nonwordchars
Esta variable contiene una expresión regular que utilizan rutinas como tcl_endOfWord para identificar si un carácter es parte de una palabra o no. Si el patrón coincide con un carácter, se considera que el carácter es un carácter que no es de palabra. En plataformas Windows, los espacios, tabulaciones y saltos de línea se consideran caracteres que no son de palabra. En Unix, todo lo que no sean números, letras y guiones bajos se considera carácter que no es de palabra.
tcl_wordchars
Esta variable contiene una expresión regular que utilizan rutinas como tcl_endOfWord para identificar si un carácter es parte de una palabra o no. Si el patrón coincide con un carácter, se considera que el carácter es un carácter de palabra. En plataformas Windows, las palabras están compuestas por cualquier carácter que no sea un espacio, tabulación o salto de línea. En Unix, las palabras están compuestas por números, letras o guiones bajos.
