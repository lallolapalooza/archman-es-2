NOMBRE

sfq - Stochastic Fairness Queueing

SINOPSIS

tc qdisc ... [ divisor tamaño_tabla_hash ] [ limit paquetes ] [ perturb segundos ] [ quantum bytes ] [ flows número ] [ depth número ] [ headdrop ] [ redflowlimit bytes ] [ min bytes ] [ max bytes ] [ avpkt bytes ] [ burst paquetes ] [ probability P ] [ ecn ] [ harddrop ]

DESCRIPCIÓN

Stochastic Fairness Queueing es una disciplina de cola sin clases disponible para el control de tráfico con el comando tc(8).

SFQ no da forma al tráfico, solo programa la transmisión de paquetes, basándose en 'flujos'. El objetivo es garantizar la equidad para que cada flujo pueda enviar datos por turnos, evitando así que un solo flujo ahogue al resto.

Esto puede tener, de hecho, cierto efecto en la mitigación de un intento de Denegación de Servicio.

SFQ es conservador de trabajo y, por lo tanto, siempre entrega un paquete si tiene uno disponible.

ALGORITMO

Al encolar, cada paquete se asigna a un bucket de hash, basándose en el valor de hash del paquete. Este valor de hash se obtiene de un clasificador de flujo externo (usa tc filter para configurarlo) o de un clasificador interno predeterminado si no se ha configurado ningún clasificador externo.

Cuando se utiliza el clasificador interno, sfq utiliza:

(i)
Dirección de origen
(ii)
Dirección de destino
(iii)
Puerto de origen y destino

Si están disponibles. SFQ conoce ipv4 e ipv6 y también UDP, TCP y ESP. Los paquetes con otros protocolos se hashifican basándose en la representación de 32 bits de su destino y origen. Un flujo corresponde principalmente a una conexión TCP/IP.

Cada uno de estos buckets debería representar un flujo único. Como múltiples flujos pueden ser hashificados al mismo bucket, el algoritmo de hash interno de sfq puede ser perturbado en intervalos configurables para que la falta de equidad dure solo un corto tiempo. Sin embargo, la perturbación puede causar una reordenación inadvertida de paquetes. Después de linux-3.3, no hay problema de reordenación de paquetes, pero sí posibles pérdidas de paquetes si el re-hash alcanza un límite (número de flujos o paquetes por flujo).

Al desencolar, cada bucket de hash con datos se consulta en modo round robin.

Antes de linux-3.3, la longitud máxima de SFQ en tiempo de compilación es de 128 paquetes, que se pueden distribuir en hasta 128 buckets de 1024 disponibles. En caso de desbordamiento, se realiza tail-drop en el bucket más lleno, manteniendo así la equidad.

Después de linux-3.3, la longitud máxima de SFQ es de 65535 paquetes y el límite del divisor es de 65536. En caso de desbordamiento, se realiza tail-drop en el bucket más lleno, a menos que se haya solicitado headdrop.

PARÁMETROS

divisor
Se puede usar para establecer un tamaño de tabla hash diferente, disponible a partir del kernel 2.6.39. El divisor especificado debe ser una potencia de dos y no puede ser mayor que 65536. Valor predeterminado: 1024.
limit
Límite superior de SFQ. Se puede usar para reducir la longitud predeterminada de 127 paquetes. Después de linux-3.3, se puede aumentar.
depth
Límite de paquetes por flujo (después de linux-3.3). Predeterminado a 127 y se puede reducir.
perturb
Intervalo en segundos para la perturbación del algoritmo de cola. Predeterminado a 0, lo que significa que no ocurre ninguna perturbación. No lo configures demasiado bajo, ya que cada perturbación puede causar reordenación o pérdidas de paquetes. Valor recomendado: 60. Este valor no tiene efecto cuando se utiliza clasificación de flujo externa. Es mejor aumentar el valor del divisor para reducir el riesgo de colisiones de hash.
quantum
Cantidad de bytes que un flujo puede desencolar durante una ronda del proceso round robin. Predeterminado al MTU de la interfaz, que también es el valor recomendado y el valor mínimo.
flows
Después de linux-3.3, es posible cambiar el límite predeterminado de flujos. Valor predeterminado: 127.
headdrop
El comportamiento predeterminado de SFQ es realizar tail-drop de paquetes de un flujo. Puedes solicitar headdrop en su lugar, ya que se sabe que proporciona una mejor retroalimentación para los flujos TCP.
redflowlimit
Configura el módulo RED opcional encima de cada flujo SFQ. El principio de Random Early Detection es realizar marcas o descartes de paquetes de forma probabilística. (ver man tc-red para detalles sobre RED) 
redflowlimit configura el límite estricto del tamaño de la cola real (no promedio) por flujo SFQ en bytes.
min
Tamaño de cola promedio en el que la marcación se convierte en una posibilidad. Predeterminado a max /3.
max
Con este tamaño de cola promedio, la probabilidad de marcación es máxima. Predeterminado a redflowlimit /4.
probability
Probabilidad máxima de marcación, especificada como un número de punto flotante de 0.0 a 1.0. Valor predeterminado: 0.02.
avpkt
Especificado en bytes. Se usa con burst para determinar la constante de tiempo para los cálculos del tamaño promedio de la cola. Valor predeterminado: 1000.
burst
Se utiliza para determinar la rapidez con la que el tamaño promedio de la cola se ve influenciado por el tamaño real de la cola. 
Valor predeterminado es:
(2 * min + max) / (3 * avpkt)
ecn
RED puede 'marcar' o 'descartar'. Explicit Congestion Notification permite a RED notificar a los hosts remotos que su tasa excede la cantidad de ancho de banda disponible. Los hosts no compatibles con ECN solo pueden ser notificados descartando un paquete. Si se especifica este parámetro, los paquetes que indican que sus hosts respetan ECN solo se marcarán y no se descartarán, a menos que el tamaño de la cola alcance depth paquetes.
harddrop
Si el tamaño promedio de la cola del flujo está por encima de max bytes, este parámetro fuerza un descarte en lugar de una marcación ecn.

EJEMPLO & USO

Para adjuntar al dispositivo ppp0:

# tc qdisc add dev ppp0 root sfq

Por favor, ten en cuenta que SFQ, como todas las qdiscs no modeladoras (conservadoras de trabajo), solo es útil si posee la cola. Este es el caso cuando la velocidad del enlace es igual al ancho de banda realmente disponible. Esto se aplica a módems telefónicos regulares, conexiones ISDN y enlaces Ethernet directos no conmutados.

En la mayoría de los casos, los módems por cable y los dispositivos DSL no entran en esta categoría. Lo mismo ocurre cuando se está conectado a un switch y se intenta enviar datos a un segmento congestionado también conectado al switch.

En este caso, la cola efectiva no reside dentro de Linux y, por lo tanto, no está disponible para la programación.

Incrusta SFQ en una qdisc con clases para asegurarte de que posea la cola.

Es posible usar clasificadores externos con sfq, por ejemplo, para hashificar el tráfico basándose solo en las direcciones IP de origen/destino:

# tc filter add ... flow hash keys src,dst perturb 30 divisor 1024

Ten en cuenta que el divisor dado debe coincidir con el utilizado por sfq. Si has cambiado el valor predeterminado de 1024 de sfq, usa el mismo valor también para el filtro de hash de flujo.

Ejemplo de sfq con modo RED opcional:

# tc qdisc add dev eth0 parent 1:1 handle 10: sfq limit 3000 flows 512 divisor 16384
redflowlimit 100000 min 8000 max 60000 probability 0.20 ecn headdrop
