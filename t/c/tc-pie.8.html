NOMBRE

PIE - Algoritmo de gestión activa de colas Proportional Integral controller-Enhanced (MEJORADO)

SINOPSIS

tc qdisc ... pie [ limit PAQUETES ] [ target TIEMPO ] [ tupdate TIEMPO ] [ alpha int ] [ beta int ] [ ecn | noecn ] [ bytemode | nobytemode ] [ dq_rate_estimator | no_dq_rate_estimator ]

DESCRIPCIÓN

Proportional Integral controller-Enhanced (PIE) es un esquema de gestión activa de colas basado en la teoría de control. Se basa en el controlador proporcional integral pero tiene como objetivo controlar el retardo. Los principales objetivos de diseño son:
o Control de baja latencia
o Alta utilización del enlace
o Implementación sencilla
o Estabilidad garantizada y respuesta rápida

ALGORITMO

PIE está diseñado para controlar el retardo de forma eficaz. Primero, se estima una tasa de desapilamiento promedio basada en la cola en espera. La tasa se utiliza para calcular el retardo actual. Luego, de forma periódica, el retardo se utiliza para calcular la probabilidad de caída. Finalmente, a la llegada, se cae (o se marca) un paquete según esta probabilidad.

PIE realiza ajustes a la probabilidad basándose en la tendencia del retardo, es decir, si está subiendo o bajando. El retardo converge rápidamente al valor objetivo especificado.

alpha y beta son parámetros elegidos estáticamente para controlar el crecimiento de la probabilidad de caída y se determinan mediante enfoques teóricos de control. alpha determina cómo la desviación entre la latencia actual y la objetivo cambia la probabilidad. beta aplica ajustes adicionales dependiendo de la tendencia de la latencia.

La probabilidad de caída se utiliza para marcar paquetes en modo ecn. Sin embargo, al igual que en RED, más allá del 10% de los paquetes se caen según esta probabilidad. El modo byte se utiliza para descartar paquetes proporcionalmente al tamaño del paquete.

Se pueden encontrar más detalles en el artículo citado a continuación.

PARÁMETROS

limit

límite del tamaño de la cola en paquetes. Los paquetes entrantes se descartan cuando se alcanza este límite. El valor predeterminado es 1000 paquetes.

target

es el retardo de cola esperado. El retardo objetivo predeterminado es 15ms.

tupdate

es la frecuencia a la que se calcula la probabilidad de caída del sistema. El valor predeterminado es 15ms.

alpha

beta

alpha y beta son parámetros elegidos para controlar la probabilidad de caída. Deben estar en el rango entre 0 y 32.

ecn | noecn

se utiliza para marcar paquetes en lugar de descartarlos. ecn para activar el modo ecn, noecn para desactivar el modo ecn. Por defecto, ecn está desactivado.

bytemode | nobytemode

se utiliza para escalar la probabilidad de caída proporcionalmente al tamaño del paquete. bytemode para activar el modo byte, nobytemode para desactivar el modo byte. Por defecto, bytemode está desactivado.

dq_rate_estimator | no_dq_rate_estimator

se utiliza para calcular el retardo utilizando la ley de Little. dq_rate_estimator para activar el estimador de tasa de desapilamiento, no_dq_rate_estimator para desactivar el estimador de tasa de desapilamiento. Por defecto, dq_rate_estimator está desactivado.
