NOMBRE

CAKE - Common Applications Kept Enhanced (CAKE)

SINOPSIS

[ bandwidth TASA | unlimited* | autorate-ingress ]
[ rtt TIEMPO | datacentre | lan | metro | regional | internet* | oceanic | satellite | interplanetary ]
[ besteffort | diffserv8 | diffserv4 | diffserv3* ]
[ flowblind | srchost | dsthost | hosts | flows | dual-srchost | dual-dsthost | triple-isolate* ]
[ nat | nonat* ]
[ wash | nowash* ]
[ split-gso* | no-split-gso ]
[ ack-filter | ack-filter-aggressive | no-ack-filter* ]
[ memlimit LIMITE ]
[ fwmark MASCARA ]
[ ptm | atm | noatm* ]
[ overhead N | conservative | raw* ]
[ mpu N ]
[ ingress | egress* ]
(* marca los valores predeterminados)

DESCRIPCIÓN

CAKE (Common Applications Kept Enhanced) es una disciplina de cola con capacidad de modelado que utiliza tanto AQM como FQ. Combina COBALT, que es un algoritmo AQM que combina Codel y BLUE, un modelador que opera en modo de déficit y una variante de DRR++ para el aislamiento de flujos. Se utiliza un hashing asociativo por conjuntos de 8 vías para eliminar virtualmente las colisiones de hash. La cola de prioridad está disponible a través de una implementación simplificada de diffserv. La compensación de sobrecarga para varios esquemas de encapsulación está estrechamente integrada.

Todas las configuraciones son opcionales; las configuraciones predeterminadas se eligen para ser sensatas en la mayoría de los despliegues comunes. La mayoría de las personas solo necesitarán configurar el parámetro bandwidth para obtener resultados útiles, pero se recomienda encarecidamente la lectura de las secciones Compensación de sobrecarga y Tiempo de ida y vuelta.

PARÁMETROS DEL MODELADOR

CAKE utiliza un modelador en modo de déficit, que no exhibe el estallido inicial típico de los modeladores de tipo token-bucket. Automáticamente generará ráfagas precisamente tanto como sea necesario para mantener el rendimiento configurado. Como tal, es muy sencillo de configurar.

unlimited (predeterminado)

Sin límite en el ancho de banda.
bandwidth TASA

Establece la tasa del modelador. Consulte tc(8) o los ejemplos a continuación para ver los detalles del valor de TASA.
autorate-ingress

Estimación automática de capacidad basada en el tráfico que llega a este qdisc. Esto es más útil con enlaces celulares, que tienden a cambiar de calidad aleatoriamente. Se puede usar un parámetro bandwidth junto con esto para especificar una estimación inicial. El modelador se establecerá periódicamente a un ancho de banda ligeramente por debajo de la tasa estimada. Este estimador no puede estimar el ancho de banda de los enlaces que están aguas abajo de sí mismo.

PARÁMETROS DE COMPENSACIÓN DE SOBRECARGA

El tamaño de cada paquete en el cable puede diferir del que ve Linux. Los siguientes parámetros permiten a CAKE compensar esta diferencia considerando internamente que cada paquete es más grande de lo que Linux le informa. Para ayudar a los usuarios que no son ingenieros de redes expertos, se han proporcionado palabras clave para representar una serie de tecnologías de enlace comunes.

Especificación Manual de Sobrecarga

overhead BYTES

Añade BYTES al tamaño de cada paquete. BYTES puede ser negativo; se aceptan valores entre -64 y 256 (inclusive).
mpu BYTES

Redondea cada paquete (incluida la sobrecarga) hasta una longitud mínima de BYTES. BYTES no puede ser negativo; se aceptan valores entre 0 y 256 (inclusive).
atm

Compensa el marcado de celdas ATM, que normalmente se encuentra en enlaces ADSL. Esto se realiza después del parámetro overhead anterior. ATM utiliza celdas fijas de 53 bytes, cada una de las cuales puede transportar 48 bytes de carga útil.
ptm

Compensa el marcado PTM, que normalmente se encuentra en enlaces VDSL2 y utiliza un esquema de marcado 64b/65b. Es aún más eficiente simplemente reducir el ancho de banda del modelador especificado por un factor de 64/65 o 0.984. Consulte ITU G.992.3 Anexo N e IEEE 802.3 Sección 61.3 para obtener detalles.
noatm

Desactiva la compensación ATM y PTM.

PARÁMETROS DE SOBRECARGA DE PAQUETES

CAKE puede aplicarse a diferentes tecnologías de red, cada una con su propia sobrecarga de protocolo inherente. La sobrecarga de protocolo se añade al tamaño real del paquete para determinar la cantidad total de datos que se envían por el enlace. Los siguientes parámetros especifican esta sobrecarga de protocolo.

overhead VALUE

Establece el valor de sobrecarga de encabezado a VALUE. El valor se especifica en bytes. El valor predeterminado es 0.
mpu VALUE

Establece la Unidad de Embalaje Mínima (MPU) a VALUE. Esto se usa a veces para determinar la sobrecarga de paquetes de forma más precisa que el simple encabezado. El valor predeterminado es 0.
atm

Activa la sobrecarga específica de ATM. Esto añade 5 bytes de sobrecarga de adaptación ATM y 5 bytes de encabezado de célula ATM al paquete.
noatm (predeterminado)

Desactiva la sobrecarga específica de ATM.
ptm

Activa la sobrecarga específica de Packet Transfer Mode (PTM), utilizada a menudo en conexiones de fibra hasta el hogar (FTTH). Esto añade 4 bytes de encabezado Ethernet y 4 bytes de PTM-FCS (Frame Check Sequence) al paquete.
Sobrecarga de PTM: 1B Inicio de trama (S) + 1B Fin de trama (Ck) + 2B TC-CRC (PTM-FCS)
Sobrecarga de Ethernet: 6B MAC de destino + 6B MAC de origen + 2B ethertype + 4B Comprobación de secuencia de trama

Consulte también la sección Factores de corrección de Ethernet más abajo.

Palabra clave de sobrecarga de cable DOCSIS

DOCSIS es el estándar universal para proporcionar servicio de Internet a través de la infraestructura de televisión por cable.

En este caso, la sobrecarga real en el cable es menos importante que el tamaño del paquete que el equipo de cabecera utiliza para dar forma y medir. Se especifica que sea una trama Ethernet que incluye la CRC (también conocida como FCS).

docsis

Equivalente a overhead 18 mpu 64 noatm

Palabras clave de sobrecarga de Ethernet

ethernet

Tiene en cuenta la preámbulo de Ethernet, el interframe gap y la secuencia de comprobación de trama (Frame Check Sequence). Utilice esta palabra clave cuando el cuello de botella para el que se está dando forma sea un cable Ethernet real. Equivalente a overhead 38 mpu 84 noatm
ether-vlan

Añade 4 bytes a la compensación de sobrecarga, teniendo en cuenta una cabecera VLAN IEEE 802.1Q adjunta a la cabecera de trama Ethernet. NB: Algunos ISP usan uno o incluso dos de estos dentro de PPPoE; esta palabra clave se puede repetir según sea necesario para expresarlo.

PARÁMETROS DE TIEMPO DE IDA Y VUELTA

La gestión activa de colas (AQM) consiste en incrustar señales de congestión en el flujo de paquetes, que los receptores utilizan para instruir a los remitentes para que reduzcan la velocidad cuando la cola está persistentemente ocupada. CAKE utiliza la señalización ECN cuando está disponible, y caídas de paquetes en caso contrario, según una combinación de los algoritmos AQM Codel y BLUE llamada COBALT.

Latencias muy cortas requieren una respuesta AQM muy rápida para controlar adecuadamente la latencia. Sin embargo, una respuesta tan rápida tiende a perjudicar el rendimiento cuando el RTT real es relativamente largo. CAKE permite especificar el RTT que asume para ajustar varios parámetros. Los RTT reales dentro de un orden de magnitud de esto generalmente funcionarán bien tanto para el rendimiento como para la gestión de la latencia.

En la configuración 'lan' y por debajo, las constantes de tiempo son de magnitud similar a la fluctuación (jitter) en el propio kernel de Linux, por lo que la congestión podría señalarse prematuramente. Los flujos se volverán entonces escasos y el rendimiento total se reducirá, dejando poca o ninguna contrapresión para que la lógica de equidad funcione. Use la configuración "metro" para LAN locales a menos que tenga un kernel personalizado.

rtt TIEMPO

Especifica manualmente un RTT.
datacentre

Solo para redes de 10GigE+ de extremadamente alto rendimiento.
Equivalente a rtt 100us.
lan

Para redes puramente Ethernet (no Wi-Fi), en casa o en la oficina. No use esto cuando esté dando forma a un enlace de acceso a Internet.
Equivalente a rtt 1ms.
metro

Para tráfico principalmente dentro de una misma ciudad.
Equivalente a rtt 10ms.
regional

Para tráfico principalmente dentro de un país de tamaño europeo.
Equivalente a rtt 30ms.
internet (predeterminado)

Esto es adecuado para la mayoría del tráfico de Internet.
Equivalente a rtt 100ms.
oceanic

Para tráfico de Internet con latencia generalmente superior a la media, como la sufrida por los residentes de Australasia.
Equivalente a rtt 300ms.
satellite

Para tráfico a través de satélites geoestacionarios.
Equivalente a rtt 1000ms.
interplanetary

Así llamado porque Júpiter está aproximadamente a 1 hora luz de la Tierra. Use esto para deshabilitar (casi) completamente las acciones de AQM.
Equivalente a rtt 3600s.

PARÁMETROS DE AISLAMIENTO DE FLUJOS

Con el aislamiento de flujos habilitado, CAKE coloca los paquetes de diferentes flujos en diferentes colas, cada una de las cuales mantiene su propio estado AQM. Los paquetes de cada cola se sirven de manera equitativa, según un algoritmo DRR++ que minimiza la latencia para flujos "escasos". CAKE utiliza un algoritmo de hash asociativo de conjuntos para minimizar las colisiones de flujos.

Estas palabras clave especifican si se desea equidad basada en la dirección de origen, la dirección de destino, los flujos individuales o cualquier combinación de ellas.

flowblind

Deshabilita el aislamiento de flujos; todo el tráfico pasa por una única cola para cada "tin" (lata).
srchost

Los flujos se definen solo por la dirección de origen. Podría ser útil en la ruta de egreso de un backhaul de ISP.
dsthost

Los flujos se definen solo por la dirección de destino. Podría ser útil en la ruta de ingreso de un backhaul de ISP.
hosts

Los flujos se definen por pares de hosts de origen-destino. Esto es aislamiento de host, en lugar de aislamiento de flujo.
flows

Los flujos se definen por la tupla completa de 5 elementos: dirección de origen, dirección de destino, protocolo de transporte, puerto de origen y puerto de destino. Este es el tipo de aislamiento de flujos realizado por SFQ y fq_codel.
dual-srchost

Los flujos se definen por la tupla de 5 elementos, y la equidad se aplica primero sobre las direcciones de origen, luego sobre los flujos individuales. Bueno para usar en tráfico de egreso desde una LAN a Internet, donde evitará que cualquier host de la LAN monopolice el enlace ascendente, independientemente del número de flujos que utilice.
dual-dsthost

Los flujos se definen por la tupla de 5 elementos, y la equidad se aplica primero sobre las direcciones de destino, luego sobre los flujos individuales. Bueno para usar en tráfico de ingreso a una LAN desde Internet, donde evitará que cualquier host de la LAN monopolice el enlace descendente, independientemente del número de flujos que utilice.
triple-isolate (predeterminado)

Los flujos se definen por la tupla de 5 elementos, y la equidad se aplica sobre las direcciones de origen *y* destino de manera inteligente (es decir, no simplemente por pares de hosts), y también sobre los flujos individuales. Úselo si no está seguro de si usar dual-srchost o dual-dsthost; hará ambos trabajos a la vez, evitando que cualquier host en *cualquiera* de los lados del enlace lo monopolice con un gran número de flujos.
nat

Indica a Cake que realice una búsqueda NAT antes de aplicar las reglas de aislamiento de flujos, para determinar las direcciones y números de puerto reales del paquete, a fin de mejorar la equidad entre los hosts "dentro" de la NAT. Esto no tiene un efecto práctico en los modos "flowblind" o "flows", o si la NAT se realiza en un host diferente.
nonat (predeterminado)

Cake no realizará una búsqueda NAT. El aislamiento de flujos se realizará utilizando las direcciones y números de puerto visibles directamente en la interfaz a la que está conectado Cake.

PARÁMETROS DE COLA DE PRIORIDAD

CAKE puede dividir el tráfico en "tins" (latas) basándose en el campo Diffserv. Cada "tin" tiene su propio conjunto independiente de colas de aislamiento de flujos, y se atiende según un algoritmo WRR. Para evitar incentivos perversos de marcado Diffserv, los pesos de los "tin" tienen un valor de "prioridad compartida" cuando el ancho de banda utilizado por ese "tin" está por debajo de un umbral, y un valor más bajo de "ancho de banda compartido" cuando está por encima. El ancho de banda se compara con el umbral utilizando el mismo algoritmo que el shaper en modo déficit.

No se proporciona personalización detallada de los parámetros de los "tin". Los siguientes preajustes realizan todos los ajustes necesarios, en relación con el ancho de banda actual del shaper y la configuración de RTT.

besteffort

Deshabilita la cola de prioridad al colocar todo el tráfico en un solo "tin".
precedence

Habilita la interpretación heredada del campo "Precedence" de TOS. Se desaconseja firmemente el uso de este preajuste en Internet moderno.
diffserv4

Proporciona una implementación Diffserv de propósito general con cuatro "tins":

• Bulk (CS1, LE en el kernel v5.9+), umbral del 6,25%, generalmente de baja prioridad.
• Best Effort (general), umbral del 100%.
• Video (AF4x, AF3x, CS3, AF2x, CS2, TOS4, TOS1), umbral del 50%.
• Voz (CS7, CS6, EF, VA, CS5, CS4), umbral del 25%.

diffserv3 (predeterminado)

Proporciona una implementación Diffserv simple y de propósito general con tres "tins":

• Bulk (CS1, LE en el kernel v5.9+), umbral del 6,25%, generalmente de baja prioridad.
• Best Effort (general), umbral del 100%.
• Voz (CS7, CS6, EF, VA, TOS4), umbral del 25%, intervalo Codel reducido.

fwmark MASK

Esta opción activa la anulación basada en fwmark de la selección de "tin" de CAKE.

NAME

cake - Common Applications Kept Explained

SYNOPSIS

tc qdisc add ... cake [ bandwidth RATE ] [ rtt TIME ] [ token_budget BYTES ] [ wash ] [ init ] [ ingress ] [ memlimit LIMIT ] [ split-gso | no-split-gso ] [ disable-split-icmp46 | enable-split-icmp46 ] [ ecn | noecn ] [ raw-sockets | no-raw-sockets ] [ fwmark MASK ] [ diffserv[3|4|8] | simple | besteffort | virgin | compat | nodata ] [ triple-isolate | dual-isolate | isolate | no-isolate ] [ ports | tos | localnet ] [ ack | loss ] [ smart | priority ] [ flows N ] [ hostfs N ] [ hosts N ] [ orphans N ] [ rlims ] [ crabs ] [ ack-filter ] [ tin N ]

DESCRIPTION

Cake is a queuing discipline for traffic control that aims to provide a simple, fair, and effective queuing mechanism. It is designed to be easy to configure and manage, while still providing advanced features such as traffic shaping, bandwidth management, and quality of service (QoS) prioritization.

Cake operates by dividing network traffic into different "tins" or queues, each with its own set of parameters and policies. This allows for fine-grained control over how different types of traffic are handled, ensuring that important traffic receives priority and that overall network performance is optimized.

SHAPER PARAMETERS

bandwidth RATE

Sets the maximum bandwidth available to CAKE. This value is used to calculate the shaper's target and interval parameters.

The RATE can be specified in bits per second (e.g., 10Mbit, 1Gbit) or bytes per second (e.g., 100MByte).

rtt TIME

Sets the round-trip time (RTT) of the network link. This value is used by CAKE to estimate the bufferbloat and adjust its queuing behavior accordingly. The TIME can be specified in seconds (e.g., 0.1s, 1s).

A typical value for broadband connections is 100ms.

token_budget BYTES

Sets the token bucket size for CAKE. This parameter controls the amount of bursting traffic that can be sent without being penalized. The BYTES value specifies the size of the bucket in bytes.

This is used in conjunction with the bandwidth parameter to define the traffic shaping characteristics.

diffserv3

Enables DiffServ (Differentiated Services) mode with 3 priority levels (Bulk, Best Effort, Voice). This is a common QoS setting.

This mode uses the DSCP (Differentiated Services Code Point) field of the IP header to classify traffic into the appropriate priority level.

diffserv4

Enables DiffServ mode with 4 priority levels.
diffserv8

Enables DiffServ mode with 8 priority levels.
simple

Enables a simplified queuing mode with a single priority level. This is useful for basic traffic shaping and bandwidth management.
besteffort

Enables best-effort queuing mode, where all traffic is treated equally.
virgin

Enables virgin mode, which disables all classification and queuing logic, effectively acting as a simple FIFO queue.
compat

Enables compatibility mode, which adjusts CAKE's behavior to be compatible with older versions or other queuing disciplines.
nodata

Disables data queueing. CAKE will only manage control traffic.
triple-isolate

Enables triple isolation mode, which isolates traffic based on source IP, destination IP, and source port. This provides the highest level of traffic separation.
dual-isolate

Enables dual isolation mode, which isolates traffic based on source IP and destination IP.
isolate

Enables isolation mode, which isolates traffic based on source IP address.
no-isolate

Disables traffic isolation. All traffic is treated as belonging to a single flow.
ports

Enables port-based isolation. Traffic is isolated based on source and destination port numbers.
tos

Enables Type of Service (ToS) based isolation. Traffic is isolated based on the ToS field in the IP header.
localnet

Enables local network isolation. Traffic is isolated based on whether it is destined for the local network or not.
ack

Enables ACK filtering. CAKE prioritizes ACK packets to improve TCP performance.
loss

Enables loss-based prioritization. CAKE prioritizes traffic that is likely to be dropped.
smart

Enables smart queuing, which dynamically adjusts queuing behavior based on network conditions.
priority

Enables priority queuing, allowing certain types of traffic to be given higher priority than others.
flows N

Sets the maximum number of active flows to N. A flow is defined as a unique combination of source IP address, destination IP address, source port, and destination port.
hostfs N

Sets the maximum number of flows per host to N. This limits the number of flows that a single host can have active simultaneously.
hosts N

Sets the maximum number of hosts to N. This parameter is used in conjunction with host-based isolation to limit the number of distinct hosts that CAKE will track.
orphans N

Sets the maximum number of orphan flows to N. Orphan flows are flows that cannot be matched to any specific host or tin.
rlims

Enables resource limits for flows. This allows setting limits on bandwidth, latency, and other resources for individual flows.
crabs

Enables CRABS (Complex Real-time Adaptive Bandwidth Shaping) algorithm. This algorithm provides more advanced and adaptive bandwidth shaping capabilities.
ack-filter

Enables ACK filtering. This option helps to reduce the impact of ACK packets on network performance by filtering out redundant or unnecessary ACKs.

OVERHEAD COMPENSATION PARAMETERS

overhead BYTES

Specifies the average per-packet overhead in bytes. This includes Ethernet header, VLAN tags, and any other protocol overhead that is not accounted for by the MTU. This value is used to accurately calculate bandwidth usage and queue sizes.

By default, this value is set to 38 bytes.

mpu BYTES

Specifies the minimum packet unit in bytes. This is the smallest packet size that CAKE will consider for queuing and shaping. Packets smaller than this value will be padded to the MPU size.

By default, this value is set to 64 bytes.

ROUND TRIP TIME PARAMETERS

rtt TIME

Sets the round-trip time (RTT) of the network link. This value is used by CAKE to estimate the bufferbloat and adjust its queuing behavior accordingly. The TIME can be specified in seconds (e.g., 0.1s, 1s).

A typical value for broadband connections is 100ms.

ECN AND FWARK PARAMETERS

ecn

Enables Explicit Congestion Notification (ECN). When ECN is enabled, CAKE will mark packets with ECN flags instead of dropping them when congestion is detected. This allows end-hosts to react to congestion before packet loss occurs, potentially improving throughput and reducing latency.
noecn

Disables Explicit Congestion Notification (ECN). Packets will be dropped when congestion is detected.
fwmark MASK

Specifies a bitmask that will be applied to the fwmark associated with each packet. If the result of this masking is non-zero, the result will be right-shifted by the number of least-significant unset bits in the mask value, and the result will be used as the tin number for that packet. This can be used to set policies in a firewall script that will override CAKE's built-in tin selection.

OTHER PARAMETERS

ingress

Indicates that CAKE is running in ingress mode (i.e. running on the downlink of a connection). This changes the shaper to also count dropped packets as data transferred, as these will have already traversed the link before CAKE can choose what to do with them.

In addition, the AQM will be tuned to always keep at least two packets queued per flow. The reason for this is that retransmits are more expensive in ingress mode, since dropped packets have to traverse the link again; thus, keeping a minimum number of packets queued will improve throughput in cases where the number of active flows are so large that they saturate the link even at their minimum window size.

memlimit LIMIT

Limit the memory consumed by Cake to LIMIT bytes. Note that this does not translate directly to queue size (so do not size this based on bandwidth delay product considerations, but rather on worst case acceptable memory consumption), as there is some overhead in the data structures containing the packets, especially for small packets.

By default, the limit is calculated based on the bandwidth and RTT settings.

wash

Traffic entering your diffserv domain is frequently mis-marked in transit from the perspective of your network, and traffic exiting yours may be mis-marked from the perspective of the transiting provider.

Apply the wash option to clear all extra diffserv (but not ECN bits), after priority queuing has taken place.

If you are shaping inbound, and cannot trust the diffserv markings (as is the case for Comcast Cable, among others), it is best to use a single queue "besteffort" mode with wash.

split-gso

This option controls whether CAKE will split General Segmentation Offload (GSO) super-packets into their on-the-wire components and dequeue them individually.

Super-packets are created by the networking stack to improve efficiency. However, because they are larger they take longer to dequeue, which translates to higher latency for competing flows, especially at lower bandwidths. CAKE defaults to splitting GSO packets to achieve the lowest possible latency. At link speeds higher than 10 Gbps, setting the no-split-gso parameter can increase the maximum achievable throughput by retaining the full GSO packets.

OVERRIDING CLASSIFICATION WITH TC FILTERS

CAKE supports overriding of its internal classification of packets through the tc filter mechanism. Packets can be assigned to different priority tins by setting the priority field on the skb, and the flow hashing can be overridden by setting the classid parameter.

Tin override

To assign a priority tin, the major number of the priority field needs to match the qdisc handle of the cake instance; if it does, the minor number will be interpreted as the tin index. For example, to classify all ICMP packets as 'bulk', the following filter can be used:

# tc qdisc replace dev eth0 handle 1: root cake diffserv3
# tc filter add dev eth0 parent 1: protocol ip prio 1 \
  u32 match icmp type 0 0 action skbedit priority 1:1

Flow hash override

To override flow hashing, the classid can be set. CAKE will interpret the major number of the classid as the host hash used in host isolation mode, and the minor number as the flow hash used for flow-based queueing. One or both of those can be set, and will be used if the relevant flow isolation parameter is set (i.e., the major number will be ignored if CAKE is not configured in hosts mode, and the minor number will be ignored if CAKE is not configured in flows mode).

This example will assign all ICMP packets to the first queue:

# tc qdisc replace dev eth0 handle 1: root cake
# tc filter add dev eth0 parent 1: protocol ip prio 1 \
  u32 match icmp type 0 0 classid 0:1

If only one of the host and flow overrides is set, CAKE will compute the other hash from the packet as normal. Note, however, that the host isolation mode works by assigning a host ID to the flow queue; so if overriding both host and flow, the same flow cannot have more than one host assigned. In addition, it is not possible to assign different source and destination host IDs through the override mechanism; if a host ID is assigned, it will be used as both source and destination host.

NAME

tc-cake - Codel Aggregating Queue Discipline

SYNOPSIS

tc ... qdisc add dev DEVICE ... cake

tc ... qdisc replace dev DEVICE ... cake

DESCRIPTION

Cake is a queueing discipline for traffic control that aims to provide a simple, yet effective, way of managing network bandwidth. It integrates several advanced features into a single, easy-to-use package.

Cake is a successor to the fq_codel queueing discipline and provides many of the same benefits, such as fairness and low latency, while adding further improvements.

OPTIONS

Cake supports a variety of options to configure its behavior. These options can be specified after the cake keyword.

FLOW ISOLATION PARAMETERS

  • flows <N>: Specifies the number of flows to isolate. A flow is defined by a unique combination of source and destination IP address and port.
  • dual-isolate: Enables dual isolation, separating ingress and egress traffic.

PRIORITY QUEUE PARAMETERS

  • priority_levels <N>: Defines the number of priority levels. Higher priority traffic is handled before lower priority traffic.

OTHER PARAMETERS

  • bandwidth <RATE>: Sets the bandwidth limit for the interface.
  • limit <PACKETS>: Sets the maximum number of packets in the queue.
  • κος <TIME>: Sets the target queue delay.
  • drop_batch <PACKETS>: Configures batch dropping of packets.
  • ecn: Enables Explicit Congestion Notification (ECN).
  • diffservin: Enables DiffServ Aware Queuing on ingress.
  • diffservout: Enables DiffServ Aware Queuing on egress.
  • irtt <TIME>: Sets the initial round-trip time.
  • quantum <BYTES>: Sets the quantum for weighted fair queuing.

OVERRIDING CLASSIFICATION WITH TC FILTERS

While cake aims to provide automatic classification, it is possible to override its behavior using standard tc filter commands. This allows for more fine-grained control over traffic management.

EXAMPLES

Enable cake with flow isolation on eth0:

tc qdisc add dev eth0 root cake flows 1024

Enable cake with dual isolation and ECN:

tc qdisc add dev eth0 root cake dual-isolate ecn

Set a bandwidth limit and target queue delay:

tc qdisc add dev eth0 root cake bandwidth 100Mbit limit 1000 kós 10ms
