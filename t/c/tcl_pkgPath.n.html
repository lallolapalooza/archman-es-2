tcl_pkgPath(n)

Paquete: tcl

Licencias: TCL

tclvars(n) Comandos integrados de Tcl tclvars(n)

NOMBRE

argc, argv, argv0, auto_path, env, errorCode, errorInfo, tcl_interactive, tcl_library, tcl_nonwordchars, tcl_patchLevel, tcl_pkgPath, tcl_platform, tcl_precision, tcl_rcFileName, tcl_traceCompile, tcl_traceExec, tcl_wordchars, tcl_version - Variables usadas por Tcl

DESCRIPCIÓN

Las siguientes variables globales son creadas y gestionadas automáticamente por la biblioteca Tcl. Excepto donde se indica a continuación, estas variables normalmente deben ser tratadas como de solo lectura por el código específico de la aplicación y por los usuarios.

auto_path
Si está configurada, debe contener una lista válida de Tcl que indique los directorios a buscar durante las operaciones de carga automática (incluyendo los archivos de índice de paquetes cuando se usa el manejador predeterminado package unknown). Esta variable se inicializa durante el inicio para contener, en orden: los directorios listados en la variable de entorno TCLLIBPATH, el directorio nombrado por la variable global tcl_library, el directorio padre de tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, los directorios listados en la variable tcl_pkgPath. Ubicaciones adicionales para buscar archivos e índices de paquetes normalmente deben agregarse a esta variable usando lappend.

Existen variables adicionales relacionadas con la gestión de paquetes. Se incluyen más detalles en la sección VARIABLES de la página del manual de library.

env
Esta variable es mantenida por Tcl como un array cuyos elementos son las variables de entorno del proceso. Leer un elemento devolverá el valor de la variable de entorno correspondiente. Establecer un elemento del array modificará la variable de entorno correspondiente o creará una nueva si aún no existe. Deshacer un elemento de env eliminará la variable de entorno correspondiente. Los cambios en el array env afectarán el entorno pasado a los hijos por comandos como exec. Si todo el array env se deshace, Tcl dejará de monitorizar los accesos a env y no actualizará las variables de entorno.

En Windows, las variables de entorno PATH y COMSPEC en cualquier combinación de mayúsculas y minúsculas se convierten automáticamente a mayúsculas. Por ejemplo, la variable PATH puede ser exportada por el sistema operativo como “path”, “Path”, “PaTh”, etc., lo que hace que el código Tcl simple tenga que admitir muchos casos especiales. Todas las demás variables de entorno heredadas por Tcl se dejan sin modificar. Establecer una variable del array env a vacío es lo mismo que deshacerla, ya que este es el comportamiento del sistema operativo Windows subyacente. Cabe señalar que depender de una variable de entorno existente y vacía no funcionará en Windows y se desaconseja para uso multiplataforma.

Los siguientes elementos de env son especiales para Tcl:

env(HOME)
Esta variable de entorno, si está configurada, indica la ubicación del directorio que se considera el directorio de inicio del usuario actual, y al cual se cambiará una llamada a cd sin argumentos o solo con “~” como argumento. La mayoría de las plataformas lo configuran correctamente por defecto; normalmente no necesita ser configurado por código de usuario.
env(TCL_LIBRARY)
Si está configurada, especifica la ubicación del directorio que contiene los scripts de la biblioteca (el valor de esta variable se asignará a la variable tcl_library y, por lo tanto, será devuelto por el comando info library). Si esta variable no está configurada, se utiliza un valor predeterminado.

Tenga en cuenta que esta variable de entorno *no* debe configurarse normalmente.

env(TCLLIBPATH)
Si está configurada, debe contener una lista válida de Tcl que indique los directorios a buscar durante las operaciones de carga automática. Los directorios deben especificarse en formato Tcl, utilizando “/” como separador de ruta, independientemente de la plataforma. Esta variable solo se utiliza al inicializar la variable auto_path.
env(TCL_TZ), env(TZ)
Estos especifican la zona horaria predeterminada utilizada para analizar y formatear horas y fechas en el comando clock. En muchas plataformas, la variable de entorno TZ es configurada por el sistema operativo.
env(LC_ALL), env(LC_MESSAGES), env(LANG)
Estas variables de entorno son utilizadas por el paquete msgcat para determinar qué localización utilizar para formatear los mensajes.
env(TCL_INTERP_DEBUG_FRAME)
Si existe, tiene el mismo efecto que ejecutar interp debug {} -frame 1 como el primer comando de cada nuevo intérprete Tcl.
errorCode
Esta variable contiene el valor de la opción de retorno -errorcode establecida por el error más reciente ocurrido en este intérprete. Este valor de lista representa información adicional sobre el error en un formato fácil de procesar por programas. El primer elemento de la lista identifica una clase general de errores y determina el formato del resto de la lista. Los siguientes formatos para las opciones de retorno -errorcode son utilizados por el núcleo de Tcl; las aplicaciones individuales pueden definir formatos adicionales.
ARITH código mensaje
Este formato se utiliza cuando ocurre un error aritmético (por ejemplo, un intento de dividir cero entre cero en el comando expr). Código identifica el error preciso y mensaje proporciona una descripción legible del error. Código será DIVZERO (para un intento de dividir por cero), DOMAIN (si un argumento está fuera del dominio de una función, como acos(-3)), IOVERFLOW (para desbordamiento de enteros), OVERFLOW (para desbordamiento de punto flotante) o UNKNOWN (si la causa del error no puede ser determinada).

La detección de estos errores depende en parte del hardware subyacente y las bibliotecas del sistema.

CHILDKILLED pid sigName mensaje
Este formato se utiliza cuando un proceso hijo ha sido terminado debido a una señal. El elemento pid será el identificador del proceso (en decimal). El elemento sigName será el nombre simbólico de la señal que causó la terminación del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGPIPE. El elemento mensaje será un mensaje corto legible que describe la señal, como “escritura en tubería sin lectores” para SIGPIPE.
CHILDSTATUS pid código
Este formato se utiliza cuando un proceso hijo ha salido con un estado de salida distinto de cero. El elemento pid será el identificador del proceso (en decimal) y el elemento código será el código de salida devuelto por el proceso (también en decimal).
CHILDSUSP pid sigName mensaje
Este formato se utiliza cuando un proceso hijo ha sido suspendido debido a una señal. El elemento pid será el identificador del proceso, en decimal. El elemento sigName será el nombre simbólico de la señal que causó la suspensión del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGTTIN. El elemento mensaje será un mensaje corto legible que describe la señal, como “lectura de tty en segundo plano” para SIGTTIN.
NONE
Este formato se utiliza para errores para los cuales no hay información adicional disponible aparte del mensaje devuelto con el error. En estos casos, la opción de retorno -errorcode consistirá en una lista que contiene un solo elemento cuyo contenido es NONE.
POSIX nombreError mensaje
Si el primer elemento es POSIX, entonces el error ocurrió durante una llamada al kernel POSIX. El elemento nombreError contendrá el nombre simbólico del error que ocurrió, como ENOENT; este será uno de los valores definidos en el archivo de inclusión errno.h. El elemento mensaje será un mensaje legible por humanos correspondiente a errName, como "no existe tal archivo o directorio" para el caso ENOENT.
TCL ...
Indica algún tipo de problema generado en relación con Tcl mismo, por ejemplo, una falla al buscar un canal o una variable.

Para establecer la opción de retorno -errorcode, las aplicaciones deben usar procedimientos de biblioteca como Tcl_SetObjErrorCode, Tcl_SetReturnOptions y Tcl_PosixError, o pueden invocar la opción -errorcode del comando return. Si no se han utilizado ninguno de estos métodos para establecer el código de error, el intérprete de Tcl restablecerá la variable a NONE después del próximo error.

errorInfo
Esta variable contiene el valor de la opción de retorno -errorinfo establecida por el error más reciente que ocurrió en este intérprete. Este valor de cadena contendrá una o más líneas que identifican los comandos y procedimientos de Tcl que se estaban ejecutando cuando ocurrió el error más reciente. Su contenido tiene la forma de un rastreo de pila que muestra los diversos comandos anidados de Tcl que se habían invocado en el momento del error.
tcl_library
Esta variable contiene el nombre de un directorio que contiene la biblioteca del sistema de scripts de Tcl, como los utilizados para la carga automática. El valor de esta variable es devuelto por el comando info library. Consulte la entrada del manual library para obtener detalles sobre las instalaciones proporcionadas por la biblioteca de scripts de Tcl. Normalmente, cada aplicación o paquete tendrá su propia biblioteca de scripts específica de la aplicación además de la biblioteca de scripts de Tcl; cada aplicación debe establecer una variable global con un nombre como $app_library (donde app es el nombre de la aplicación) para contener el nombre de archivo de red del directorio de biblioteca de esa aplicación. El valor inicial de tcl_library se establece cuando se crea un intérprete buscando en varios directorios diferentes hasta que se encuentra uno que contiene un script de inicio de Tcl apropiado. Si la variable de entorno TCL_LIBRARY existe, entonces el directorio que nombra se verifica primero. Si TCL_LIBRARY no está configurada o no se refiere a un directorio apropiado, entonces Tcl verifica varios otros directorios basándose en una ubicación predeterminada compilada, la ubicación del binario que contiene la aplicación y el directorio de trabajo actual.
tcl_patchLevel
Cuando se crea un intérprete, Tcl inicializa esta variable para contener una cadena que indica el nivel de parche actual para Tcl, como 8.4.16 para Tcl 8.4 con los primeros dieciséis parches oficiales, o 8.5b3 para la tercera versión beta de Tcl 8.5. El valor de esta variable es devuelto por el comando info patchlevel.
tcl_pkgPath
Esta variable contiene una lista de directorios que indican dónde se instalan normalmente los paquetes. No se usa en Windows. Típicamente contiene una o dos entradas; si contiene dos entradas, la primera es normalmente un directorio para paquetes dependientes de la plataforma (por ejemplo, binarios de bibliotecas compartidas) y la segunda es normalmente un directorio para paquetes independientes de la plataforma (por ejemplo, archivos de script). Típicamente, un paquete se instala como un subdirectorio de una de las entradas en la variable tcl_pkgPath. Los directorios en la variable tcl_pkgPath se incluyen por defecto en la variable auto_path, por lo que se buscan automáticamente ellos y sus subdirectorios inmediatos en busca de paquetes durante los comandos package require. Nota: tcl_pkgPath no está destinado a ser modificado por la aplicación. Su valor se agrega a auto_path al arranque; los cambios en tcl_pkgPath no se reflejan en auto_path. Si desea que Tcl busque directorios adicionales para paquetes, debe agregar los nombres de esos directorios a auto_path, no a tcl_pkgPath.
tcl_platform
Este es un array asociativo cuyos elementos contienen información sobre la plataforma en la que se está ejecutando la aplicación, como el nombre del sistema operativo, su número de versión actual y el conjunto de instrucciones de la máquina. Los elementos enumerados a continuación siempre estarán definidos, pero pueden tener cadenas vacías como valores si Tcl no pudo recuperar ninguna información relevante. Además, las extensiones y las aplicaciones pueden agregar valores adicionales al array. Los elementos predefinidos son:
byteOrder
El orden de bytes nativo de esta máquina: littleEndian o bigEndian.
debug
Si esta variable existe, entonces el intérprete se compiló y enlazó con un tiempo de ejecución C habilitado para depuración. Esta variable solo existirá en Windows, por lo que los escritores de extensiones pueden especificar qué paquete cargar dependiendo de la biblioteca de tiempo de ejecución C que se esté utilizando. Esto no es una indicación de que este núcleo contenga símbolos.
engine
El nombre de la implementación del lenguaje Tcl. Cuando se crea el intérprete por primera vez, este siempre se establece en la cadena Tcl.
machine
El conjunto de instrucciones ejecutado por esta máquina, como intel, PPC, 68k o sun4m. En máquinas UNIX, este es el valor devuelto por uname -m.
os
El nombre del sistema operativo que se ejecuta en esta máquina, como Windows NT o SunOS. En máquinas UNIX, este es el valor devuelto por uname -s.
osVersion
El número de versión del sistema operativo que se ejecuta en esta máquina. En máquinas UNIX, este es el valor devuelto por uname -r.
pathSeparator
El carácter que debe usarse para dividir variables de entorno tipo PATH en su lista correspondiente de nombres de directorios.
platform
Ya sea windows o unix. Esto identifica el entorno operativo general de la máquina.
pointerSize
Esto da el tamaño del puntero nativo de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(void*) en C.)
threaded
Si esta variable existe, entonces el intérprete se compiló con hilos habilitados.
user
Esto identifica al usuario actual basándose en la información de inicio de sesión disponible en la plataforma. Este valor proviene de las llamadas del sistema getuid() y getpwuid() en Unix, y del valor de la llamada del sistema GetUserName() en Windows.
wordSize
Esto da el tamaño de la palabra nativa de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(long) en C.)
tcl_precision
Esta variable controla el número de dígitos a generar al convertir valores de punto flotante a cadenas. Por defecto es 0. Las aplicaciones no deben cambiar este valor; se proporciona para la compatibilidad con código legado.
El valor predeterminado de 0 es especial, lo que significa que Tcl debe convertir números usando la menor cantidad de dígitos posible, sin dejar de distinguir cualquier número de punto flotante de sus vecinos más cercanos. Se diferencia de usar un valor arbitrariamente alto para tcl_precision en que un número inexacto como 1.4 se convertirá como 1.4 en lugar de 1.3999999999999999, aunque este último está más cerca del valor exacto del número binario.
Si tcl_precision no es cero, entonces cuando Tcl convierte un número de punto flotante, crea una representación decimal de como máximo tcl_precision dígitos significativos; el resultado puede ser más corto si el resultado más corto representa el número original exactamente. Si no existe un resultado de como máximo tcl_precision dígitos que sea una representación exacta del número original, se elige el que está más cerca del número original. Si el número original se encuentra precisamente entre dos representaciones decimales igualmente precisas, se elige la que tiene un valor par para el dígito menos significativo; por ejemplo, si tcl_precision es 3, entonces 0.3125 se convertirá a 0.312, no a 0.313, mientras que 0.6875 se convertirá a 0.688, no a 0.687. Se recortarán las cadenas de ceros finales que queden.
un valor de tcl_precision de 17 dígitos es "perfecto" para punto flotante IEEE en el sentido de que permite que los valores de doble precisión se conviertan a cadenas y de vuelta a binario sin pérdida de información. Por esta razón, a menudo se verá como un valor en código legado que debe ejecutarse en versiones de Tcl anteriores a la 8.5. Ya no se recomienda; como se señaló anteriormente, un valor cero es el método preferido.
Todos los intérpretes en un hilo comparten un único valor de tcl_precision: cambiarlo en un intérprete afectará a todos los demás intérpretes. A los intérpretes seguros no se les permite modificar la variable.
Los valores válidos para tcl_precision oscilan entre 0 y 17.
tcl_rcFileName
Esta variable se utiliza durante la inicialización para indicar el nombre de un archivo de inicio específico del usuario. Si se establece mediante la inicialización específica de la aplicación, el código de inicio de Tcl verificará la existencia de este archivo y lo ejecutará si existe. Por ejemplo, para wish la variable se establece en ~/.wishrc para Unix y ~/wishrc.tcl para Windows.
tcl_traceCompile
El valor de esta variable se puede establecer para controlar cuánta información de rastreo se muestra durante la compilación de bytecode. Por defecto, tcl_traceCompile es cero y no se muestra información. Establecer tcl_traceCompile en 1 genera un resumen de una línea en stdout cada vez que se compila un procedimiento o un comando de nivel superior. Establecerlo en 2 genera una lista detallada en stdout de las instrucciones de bytecode emitidas durante cada compilación. Esta variable es útil para rastrear posibles problemas con el compilador de Tcl.
Esta variable y funcionalidad solo existen si TCL_COMPILE_DEBUG se definió durante la compilación de Tcl.

NAME

tcl_pkgPath \- control variables for Tcl's library search path

SYNOPSIS

auto_path tcl_pkgPath tcl_traceExec tcl_wordchars tcl_nonwordchars tcl_version

DESCRIPTION

The Tcl library itself is organized into a set of directories containing supporting scripts and compiled code. When the package require command is invoked, Tcl searches for the package in a list of directories that is stored in the global variable auto_path. The auto_path variable is a Tcl list containing directory names. Initially, auto_path contains a set of standard directories in which Tcl is installed. Additional directories can be added to auto_path by editing it or by using commands such as lappend.

The tcl_pkgPath variable is also a list of directory names. It is used by the Tcl package manager for finding packages. The contents of tcl_pkgPath are a subset of the contents of auto_path.

tcl_traceExec
The value of this variable can be set to control how much tracing information is displayed during bytecode execution. By default, tcl_traceExec is zero and no information is displayed. Setting tcl_traceExec to 1 generates a one-line trace in stdout on each call to a Tcl procedure. Setting it to 2 generates a line of output whenever any Tcl command is invoked that contains the name of the command and its arguments. Setting it to 3 produces a detailed trace showing the result of executing each bytecode instruction. Note that when tcl_traceExec is 2 or 3, commands such as set and incr that have been entirely replaced by a sequence of bytecode instructions are not shown. Setting this variable is useful in tracking down suspected problems with the bytecode compiler and interpreter.
This variable and functionality only exist if TCL_COMPILE_DEBUG was defined during Tcl's compilation.
tcl_wordchars
The value of this variable is a regular expression that can be set to control what are considered “word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \S, meaning anything but a Unicode space character. Otherwise it defaults to \w, which is any Unicode word character (number, letter, or underscore).
tcl_nonwordchars
The value of this variable is a regular expression that can be set to control what are considered “non-word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \s, meaning any Unicode space character. Otherwise it defaults to \W, which is anything but a Unicode word character (number, letter, or underscore).
tcl_version
When an interpreter is created Tcl initializes this variable to hold the version number for this version of Tcl in the form x.y. Changes to x represent major changes with probable incompatibilities and changes to y represent small enhancements and bug fixes that retain backward compatibility. The value of this variable is returned by the info tclversion command.

OTHER GLOBAL VARIABLES

The following variables are only guaranteed to exist in tclsh and wish executables; the Tcl library does not define them itself but many Tcl environments do.

argc
The number of arguments to tclsh or wish.
argv
Tcl list of arguments to tclsh or wish.
argv0
The script that tclsh or wish started executing (if it was specified) or otherwise the name by which tclsh or wish was invoked.
tcl_interactive
Contains 1 if tclsh or wish is running interactively (no script was specified and standard input is a terminal-like device), 0 otherwise.

EXAMPLES

To add a directory to the collection of locations searched by package require, e.g., because of some application-specific packages that are used, the auto_path variable needs to be updated:

lappend ::auto_path [file join [pwd] "theLibDir"]

A simple though not very robust way to handle command line arguments of the form “-foo 1 -bar 2” is to load them into an array having first loaded in the default settings:

array set arguments {-foo 0 -bar 0 -grill 0}
array set arguments $::argv
puts "foo is $arguments(-foo)"
puts "bar is $arguments(-bar)"
puts "grill is $arguments(-grill)"

The argv0 global variable can be used (in conjunction with the info script command) to determine whether the current script is being executed as the main script or loaded as a library. This is useful because it allows a single script to be used as both a library and a demonstration of that library:

if {$::argv0 eq [info script]} {
    # running as: tclsh example.tcl
} else {
    package provide Example 1.0
}
