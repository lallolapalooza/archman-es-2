NOMBRE

flow - filtro de control de tráfico basado en flujos

SINOPSIS

Modo de mapeo:

tc filter ... flow map key CLAVE [ OPS ] [ OPCIONES ]
Modo de hashing:

tc filter ... flow hash keys LISTA_CLAVES [ perturb segundos ] [ OPCIONES ]


OPS := [ OPS ] OP

OPCIONES := [ divisor NUM ] [ baseclass ID ] [ match EMATCH_TREE ] [ action ACCION_ESPEC ]

LISTA_CLAVES := [ LISTA_CLAVES ] CLAVE

OP := { or | and | xor | rshift | addend } NUM

ID := X:Y

CLAVE := { src | dst | proto | proto-src | proto-dst | iif | priority | mark | nfct | nfct-src | nfct-dst | nfct-proto-src | nfct-proto-dst | rt-classid | sk-uid | sk-gid | vlan-tag | rxhash }

DESCRIPCIÓN

El clasificador flow está destinado a extender las capacidades de hashing de SFQ sin codificar nuevas funciones hash. También permite mapeos deterministas de claves a clases.

OPCIONES

action ACCION_ESPEC
Aplica una acción del framework de acciones genéricas a los paquetes que coincidan.
baseclass ID
Un desplazamiento para el ID de clase resultante. ID puede ser root, none o un ID de clase hexadecimal en el formato [X:]Y. X debe coincidir con el manejador principal del qdisc/clase (si se omite, se elige automáticamente el valor correcto). Si se omite todo el baseclass, Y toma el valor predeterminado de 1.
divisor NUM
Número de cubos a utilizar para la clasificación. Las claves se calculan módulo NUM.
hash keys LISTA_CLAVES
Realiza una operación jhash2 sobre las claves en LISTA_CLAVES, el resultado (módulo el divisor si se proporciona) se toma como ID de clase, opcionalmente desplazado por el valor de baseclass. Es posible especificar un intervalo (en segundos) después del cual la fuente de entropía de jhash2 se recrea utilizando el parámetro perturb.
map key CLAVE
Los datos del paquete identificados por CLAVE se traducen a IDs de clase para enviar el paquete. El valor puede ser modificado por OPS antes de usarlo para el mapeo. Se aplican en el orden listado aquí:
and NUM
Realiza una operación AND bit a bit con el valor numérico NUM.
or NUM
Realiza una operación OR bit a bit con el valor numérico NUM.
xor NUM
Realiza una operación XOR bit a bit con el valor numérico NUM.
rshift NUM
Desplaza el valor de CLAVE hacia la derecha en NUM bits.
addend NUM
Suma NUM al valor de CLAVE.
Para las operaciones or, and, xor y rshift, se asume que NUM es un valor entero sin signo de 32 bits. Para la operación addend, NUM puede ser mucho más complejo: puede ir prefijado por un signo menos ('-') para causar una resta en lugar de una suma, y para las claves src, dst, nfct-src y nfct-dst puede proporcionarse en notación de dirección IP. Ver abajo un ejemplo ilustrativo.
match EMATCH_TREE
Coincide con paquetes utilizando la infraestructura de coincidencias extendidas. Consulte tc-ematch(8) para una descripción detallada de la sintaxis permitida en EMATCH_TREE.

CLAVES

En el modo de mapeo, se utiliza una única clave (después de una permutación opcional) para construir un ID de clase. El ID resultante es deducible en la mayoría de los casos. En el modo de hashing, se pueden especificar varias claves que luego se hashean y la salida se utiliza como ID de clase. Este ID no es deducible de antemano, e incluso puede cambiar con el tiempo para un flujo dado si se ha proporcionado un intervalo de perturb.

El rango de IDs de clase puede limitarse con la opción divisor, que se utiliza para el módulo.

src, dst
Utiliza la dirección de origen o destino como clave. En caso de IPv4 y TIPC, este es el valor real de la dirección. Para IPv6, la dirección de 128 bits se pliega en un valor de 32 bits haciendo XOR de las cuatro palabras de 32 bits. En todos los demás casos, se utiliza la dirección de socket interna del kernel (después de plegarse a 32 bits en sistemas de 64 bits).
proto
Utiliza el número de protocolo de capa cuatro como clave.
proto-src
Utiliza el puerto de origen de capa cuatro como clave. Si no está disponible, se utiliza la dirección de socket interna del kernel en su lugar.
proto-dst
Utiliza el puerto de destino de capa cuatro como clave. Si no está disponible, se utiliza la dirección de entrada del kernel asociada después de hacer XOR con el número de protocolo de capa tres del paquete.
iif
Utiliza el índice de la interfaz de entrada como clave.
priority
Utiliza la prioridad del paquete como clave. Normalmente, este es el valor DSCP/ECN de la cabecera IP.
mark
Utiliza la marca fwmark de netfilter como clave.
nfct
Utiliza la dirección de la entrada de conntrack asociada como clave.
nfct-src, nfct-dst, nfct-proto-src, nfct-proto-dst
Estas son variantes conscientes de conntrack de src, dst, proto-src y proto-dst. En caso de NAT, estos son básicamente los valores de la cabecera del paquete antes de que se aplicara NAT.
rt-classid
Utiliza el ámbito de la entrada de la tabla de enrutamiento de destino del paquete como clave.
sk-uid
sk-gid
Para paquetes generados localmente, utiliza el ID de usuario o grupo al que pertenece el socket de origen como clave.
vlan-tag
Utiliza el ID de VLAN del paquete como clave.
rxhash
Utiliza el hash de flujo como clave.

EJEMPLOS

Hashing SFQ clásico:
tc filter add ... flow hash \
	keys src,dst,proto,proto-src,proto-dst divisor 1024
Hashing SFQ clásico, pero usando información de conntrack para funcionar correctamente en combinación con NAT:
tc filter add ... flow hash \
	keys nfct-src,nfct-dst,proto,nfct-proto-src,nfct-proto-dst \
	divisor 1024
Mapear IPs de destino de 192.168.0.0/24 a classids 1-256:
tc filter add ... flow map \
	key dst addend -192.168.0.0 divisor 256
Alternativa a lo anterior:
tc filter add ... flow map \
	key dst and 0xff
Lo mismo, pero en orden inverso:
tc filter add ... flow map \
	key dst addend 192.168.0.0 divisor 256
Usar el paquete de datos de capa 4:
tc filter add ... flow map \
	key proto-dst
Hacer que el primer cuarto de los puertos de destino se usen para clasificar:
tc filter add ... flow map \
	key proto-dst rshift 6
Usar el netfilter mark:
tc filter add ... flow map key mark
Usar el netfilter mark, pero solo los 16 bits inferiores:
tc filter add ... flow map \
	key mark and 0xffff
Usar el Netfilter mark, pero invertir la dirección de búsqueda. Útil para aplicar la misma política a flujos que tienen marcas opuestas:
tc filter add ... flow map \
	key mark xor 0xffffffff
Usar la interfaz de entrada y el protocolo de capa 4:
tc filter add ... flow hash \
	keys iif,proto divisor 256
Ejemplo de una combinación compleja: Mapear la dirección IP de destino (pre-NAT) de flujos que utilizan el protocolo TCP (6) a 256 cubos, usando la dirección IP de destino pre-NAT como clave base:
tc filter add ... flow map \
	key nfct-dst \
	proto 6 \
	action pass \
	divisor 256
Combinar la clave de origen y destino y calcular el hash:
tc filter add ... flow hash \
	keys src,dst divisor 1024
Combinar la clave de origen y destino y calcular el hash, pero con una fuente de entropía que se actualiza cada 600 segundos:
tc filter add ... flow hash \
	keys src,dst perturb 600 divisor 1024

tc-flow.8.en

NAME

tc-flow - filter flow

SYNOPSIS

tc filter add ... flow map \
	key KEY_SPEC [OPTIONS]

DESCRIPTION

The flow filter is a simple filter that maps traffic flow identifiers to integer values.

This can be used to distribute traffic among multiple queues or other filters based on flows.

The mapping is achieved using a simple hash function. The input to the hash function is constructed from the packet header fields specified in KEY_SPEC.

OPTIONS

The following options are available:

--hash hash_type
Specifies the hashing algorithm to use. Supported types are:
symmetric
Symmetric hashing, where the order of keys does not matter.
random
Random hashing, where a random seed is used.
--random-seed
seed Specifies the random seed to use for random hashing.

KEYS

The following key specifications are supported:

dst
Destination IP address.
src
Source IP address.
proto
IP protocol.
sport
Source port.
dport
Destination port.
mask MASK
Applies a bitmask to the key. For example, to use only the lower 8 bits of the destination IP address, use dst and 0xff.
xor XOR
Applies a bitwise XOR operation to the key. For example, to invert the lower 8 bits of the destination IP address, use dst and 0xff xor 0xff.

Multiple keys can be combined using the and operator.

EXAMPLES

tc filter add ... flow map \
	key dst and 0xff xor 0xff
