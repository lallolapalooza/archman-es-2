NOMBRE

mirred - acción de espejo/redireccionamiento

SINOPSIS


tc ... action mirred DIRECCION ACCION [ index INDICE ] DESTINO

DIRECCION := { ingress | egress }

DESTINO := { DEV | BLOQUE }

DEV := dev NOMBRE_DISPOSITIVO

BLOQUE := blockid ID_BLOQUE

ACCION := { mirror | redirect }

DESCRIPCIÓN

La acción mirred permite el espejo (copia) o redireccionamiento (robo) de paquetes. El espejo es lo que a veces se denomina Switch Port Analyzer (SPAN) y se usa comúnmente para analizar y/o depurar flujos. Al hacer espejo a un bloque de tc, el paquete se espejará a todos los puertos del bloque, con excepción del puerto de entrada del paquete, si ese puerto forma parte del bloque de tc. El redireccionamiento es similar al espejo, excepto que el comportamiento es hacer espejo a los primeros N-1 puertos del bloque y redireccionar al último (tenga en cuenta que el puerto donde llegó el paquete no será espejado ni redirigido).

OPCIONES

ingress
egress
Especifica la dirección en la que aparecerá el paquete en la interfaz de destino.
mirror
redirect
Define si el paquete debe ser copiado (mirror) o movido (redirect) a la interfaz o bloque de destino.
index INDICE
Asigna un ID único a esta acción en lugar de dejar que el kernel elija uno automáticamente. INDICE es un entero sin signo de 32 bits mayor que cero.
dev NOMBRE_DISPOSITIVO
Especifica la interfaz de red a la que se redirigirá o espejará el paquete.
blockid ID_BLOQUE
Especifica el bloque de tc al que se redirigirá o espejará el paquete.

EJEMPLOS

Limitar el ancho de banda de entrada en eth0 a 1 mbit/s, redirigir el tráfico excedente a lo para fines de depuración:

# tc qdisc add dev eth0 handle ffff: clsact
# tc filter add dev eth0 ingress u32 \
	match u32 0 0 \
	action police rate 1mbit burst 100k conform-exceed pipe \
	action mirred egress redirect dev lo

Espejar todos los paquetes ICMP entrantes en eth0 a una interfaz dummy para su examen con, por ejemplo, tcpdump:

# ip link add dummy0 type dummy
# ip link set dummy0 up
# tc qdisc add dev eth0 handle ffff: clsact
# tc filter add dev eth0 ingress protocol ip \
	u32 match ip protocol 1 0xff \
	action mirred egress mirror dev dummy0

Usando una interfaz ifb, es posible enviar tráfico de entrada a través de una instancia de sfq:

# modprobe ifb
# ip link set ifb0 up
# tc qdisc add dev ifb0 root sfq
# tc qdisc add dev eth0 handle ffff: clsact
# tc filter add dev eth0 ingress u32 \
	match u32 0 0 \
	action mirred egress redirect dev ifb0

LIMITACIONES

El kernel restringe la anidación a cuatro niveles para evitar la posibilidad de bucles de anidamiento.

No redirija de un dispositivo IFB a otro. IFB es un caso muy especializado de dispositivo de redireccionamiento de paquetes. Redirigir de ifbX a ifbY provocará la caída de todos los paquetes.
