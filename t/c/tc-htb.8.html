HTB(8) Linux HTB(8)

NOMBRE

HTB - Hierarchy Token Bucket

SINOPSIS

tc qdisc ... dev dev ( parent classid | root) [ handle major: ] htb [ default minor-id ] [ r2q divisor ] [ offload ]

tc class ... dev dev parent major:[minor] [ classid major:minor ] htb rate rate [ ceil rate ] burst bytes [ cburst bytes ] [ prio priority ] [ quantum bytes ]

DESCRIPCIÓN

HTB permite controlar el ancho de banda de salida en un enlace dado. Permite simular varios enlaces más lentos y enviar diferentes tipos de tráfico en diferentes enlaces simulados. En ambos casos, debes especificar cómo dividir el enlace físico en enlaces simulados y cómo decidir qué enlace simulado usar para un paquete determinado que se enviará.

HTB da forma al tráfico basándose en el algoritmo Token Bucket Filter, que no depende de las características de la interfaz y, por lo tanto, no necesita conocer el ancho de banda subyacente de la interfaz de salida.

ALGORITMO DE APLICACIÓN

La aplicación funciona como se documenta en tc-tbf (8).

CLASIFICACIÓN

Dentro de una instancia de HTB pueden existir muchas clases. Cada una de estas clases contiene otra cola, por defecto tc-pfifo(8).

Al poner en cola un paquete, HTB comienza en la raíz y utiliza varios métodos para determinar qué clase debe recibir los datos.

En ausencia de opciones de configuración poco comunes, el proceso es bastante sencillo. En cada nodo buscamos una instrucción y luego vamos a la clase a la que nos refiere la instrucción. Si la clase encontrada es un nodo hoja vacío (sin hijos), ponemos en cola el paquete allí. Si aún no es un nodo hoja, hacemos todo el proceso nuevamente comenzando desde ese nodo.

Las siguientes acciones se realizan, en orden, en cada nodo que visitamos, hasta que una nos envíe a otro nodo o termine el proceso.

(i)
Consultar los filtros adjuntos a la clase. Si se envía a un nodo hoja, hemos terminado. De lo contrario, reiniciar.
(ii)
Si ninguna de las opciones anteriores devolvió una instrucción, poner en cola en este nodo.

Este algoritmo asegura que un paquete siempre termine en algún lugar, incluso mientras estás ocupado construyendo tu configuración.

ALGORITMO DE COMPARTICIÓN DE ENLACE

PENDIENTE

QDISC

La raíz de un árbol de clases de cola HTB tiene los siguientes parámetros:

parent major:minor | root
Este parámetro obligatorio determina la ubicación de la instancia HTB, ya sea en la raíz de una interfaz o dentro de una clase existente.
handle major:
Como todas las demás colas, la HTB puede tener un identificador. Debe consistir únicamente en un número principal, seguido de dos puntos. Opcional, pero muy útil si se generarán clases dentro de esta cola.
default minor-id
El tráfico no clasificado se envía a la clase con este id. menor.
r2q divisor
Divisor utilizado para calcular los valores de quantum para las clases. Las clases dividen la tasa por este número. El valor predeterminado es 10.
offload
Descarga el algoritmo HTB al hardware (requiere soporte del controlador y del dispositivo).

CLASES

Las clases tienen una gran cantidad de parámetros para configurar su funcionamiento.

parent major:minor
Ubicación de esta clase dentro de la jerarquía. Si está conectada directamente a una cola y no a otra clase, se puede omitir el número menor. Obligatorio.
classid major:minor
Al igual que las colas, las clases pueden tener nombre. El número principal debe ser igual al número principal de la cola a la que pertenece. Opcional, pero necesario si esta clase va a tener hijos.
prio priority
En el proceso de ronda, las clases con el campo de prioridad más bajo se intentan primero para los paquetes.
rate rate
Tasa máxima garantizada para esta clase y todos sus hijos. Obligatorio.
ceil rate
Tasa máxima a la que una clase puede enviar, si su padre tiene ancho de banda de sobra. Por defecto es la tasa configurada, lo que implica que no se permite pedir prestado.
burst bytes
Cantidad de bytes que se pueden enviar a velocidad ceil, en exceso de la tasa configurada. Debe ser al menos tan alta como el ráfaga más alta de todos los hijos.
cburst bytes
Cantidad de bytes que se pueden enviar a velocidad 'infinita', en otras palabras, tan rápido como la interfaz pueda transmitirlos. Para una compensación perfecta, debería ser como máximo un paquete promedio. Debe ser al menos tan alta como el cburst más alto de todos los hijos.
quantum bytes
Número de bytes a servir de esta clase antes de que el planificador pase a la siguiente clase. El valor predeterminado es la tasa dividida por el parámetro r2q de la cola. Si se especifica, se ignora r2q.

NOTAS

Debido a las restricciones de tiempo de Unix, la tasa máxima de `ceil` no es infinita y de hecho puede ser bastante baja. En Intel, hay 100 eventos de temporizador por segundo, la tasa máxima es la tasa a la que se envían `burst` bytes en cada tic del temporizador. A partir de esto, se puede calcular el tamaño mínimo de ráfaga para una tasa dada. Para i386, una tasa de 10Mbit requiere una ráfaga de 12 kilobytes, ya que 100 * 12 kb * 8 es igual a 10Mbit.
