tset(1) Comandos de usuario tset(1)

NOMBRE

tset, reset - inicializa o resetea el estado de la terminal

SINOPSIS

tset [-IQVcqrsw] [-] [-e caracter] [-i caracter] [-k caracter] [-m mapeo] [tipo-terminal]
reset [-IQVcqrsw] [-] [-e caracter] [-i caracter] [-k caracter] [-m mapeo] [tipo-terminal]

DESCRIPCIÓN

tset — inicialización

Este programa inicializa las terminales.

Primero, tset recupera la configuración del modo de terminal actual para tu terminal. Lo hace probando sucesivamente

  • el descriptor de error estándar,
  • la salida estándar,
  • la entrada estándar y
  • en última instancia “/dev/tty”

para obtener la configuración de la terminal. Habiendo recuperado esta configuración, tset recuerda qué descriptor de archivo utilizará al actualizar la configuración.

A continuación, tset determina el tipo de terminal que estás utilizando. Esta determinación se realiza de la siguiente manera, utilizando el primer tipo de terminal encontrado.

1. El argumento terminal especificado en la línea de comandos.

2. El valor de la variable de entorno TERM.

3. (Solo en sistemas BSD.) El tipo de terminal asociado al dispositivo de salida de error estándar en el archivo /etc/ttys. (En hosts System V y sistemas que usan esa convención, getty(8) realiza esta tarea estableciendo TERM de acuerdo con el tipo que se le pasa desde /etc/inittab.)

4. El tipo de terminal predeterminado, “unknown”, no es adecuado para aplicaciones curses.

Si el tipo de terminal no se especificó en la línea de comandos, se aplican los mapeos de la opción -m; consulte la subsección “Mapeo de Tipos de Terminal”. Luego, si el tipo de terminal comienza con un signo de interrogación (“?”), se le pide al usuario confirmación del tipo de terminal. Una respuesta vacía confirma el tipo, o, se puede ingresar otro tipo para especificar un nuevo tipo. Una vez determinado el tipo de terminal, se recupera la descripción de la terminal. Si no se encuentra ninguna descripción de terminal para ese tipo, se le pide al usuario otro tipo de terminal.

Una vez recuperada la descripción de la terminal,

•
si la opción “-w” está habilitada, tset puede actualizar el tamaño de la ventana de la terminal.
Si el tamaño de la ventana no se puede obtener del sistema operativo, pero la descripción de la terminal (o el entorno, por ejemplo, las variables LINES y COLUMNS lo especifican), úselo para establecer la noción del sistema operativo sobre el tamaño de la ventana.
  • si la opción “-c” está habilitada, se configuran los caracteres de retroceso, interrupción y eliminación de línea (entre muchas otras cosas)
  • a menos que la opción “-I” esté habilitada, las cadenas de inicialización de la terminal y de tabulación se envían a la salida de error estándar, y tset espera un segundo (en caso de que se emitiera un reinicio de hardware).
  • Finalmente, si los caracteres de borrado, interrupción y eliminación de línea han cambiado, o no están configurados en sus valores predeterminados, sus valores se muestran en la salida de error estándar.

reset — reinicialización

Cuando se invoca como reset, tset establece los modos de terminal en valores “sanos”:

  • establece modos cocidos y de eco,
  • desactiva los modos cbreak y raw,
  • activa la traducción de nueva línea y
  • restaura cualquier carácter especial no establecido a sus valores predeterminados

antes de realizar la inicialización de la terminal descrita anteriormente. Además, en lugar de usar las cadenas de inicialización de la terminal, utiliza las cadenas de reinicio de la terminal.

El comando reset es útil después de que un programa muere dejando la terminal en un estado anormal:

  • es posible que tengas que escribir


    <LF>reset<LF>

    (el carácter de avance de línea es normalmente control-J) para que la terminal funcione, ya que el retorno de carro puede que ya no funcione en el estado anormal.

  • Además, la terminal a menudo no mostrará el comando.

Establecer el Entorno

A menudo es deseable introducir el tipo de terminal y la información sobre las capacidades de la terminal en el entorno del shell. Esto se hace con la opción -s.

Cuando se especifica la opción -s, los comandos para introducir la información en el entorno del shell se escriben en la salida estándar. Si la variable de entorno SHELL termina en “csh”, los comandos son para csh(1), de lo contrario, son para sh(1). Los comandos de csh establecen y anulan la variable del shell noglob, dejándola anulada. La siguiente línea en los archivos .login o .profile inicializará correctamente el entorno:


eval `tset -s opciones ... `

Mapeo de Tipos de Terminal

Cuando la terminal no está cableada en el sistema (o la información actual del sistema es incorrecta) el tipo de terminal derivado del archivo /etc/ttys o la variable de entorno TERM es a menudo algo genérico como network, dialup, o unknown. Cuando tset se usa en un script de inicio, a menudo es deseable proporcionar información sobre el tipo de terminal utilizado en dichos puertos.

Las opciones -m mapean de algún conjunto de condiciones a un tipo de terminal, es decir, para decirle a tset “Si estoy en este puerto a una velocidad particular, supón que estoy en ese tipo de terminal”.

El argumento de la opción -m consiste en un tipo de puerto opcional, un operador opcional, una especificación de velocidad en baudios opcional, un carácter de dos puntos opcional (“:”) y un tipo de terminal. El tipo de puerto es una cadena (delimitada por el operador o el carácter de dos puntos). El operador puede ser cualquier combinación de “>”, “<”, “@”, y “!”; “>” significa mayor que, “<” significa menor que, “@” significa igual a y “!” invierte el sentido de la prueba. La velocidad en baudios se especifica como un número y se compara con la velocidad de la salida de error estándar (que debería ser la terminal de control). El tipo de terminal es una cadena.

Si el tipo de terminal no se especifica en la línea de comandos, se aplican los mapeos de -m al tipo de terminal. Si el tipo de puerto y la velocidad en baudios coinciden con el mapeo, el tipo de terminal especificado en el mapeo reemplaza el tipo actual. Si se especifica más de un mapeo, se utiliza el primer mapeo aplicable.

Por ejemplo, considere el siguiente mapeo: dialup>9600:vt100. El tipo de puerto es dialup , el operador es >, la especificación de velocidad en baudios es 9600, y el tipo de terminal es vt100. El resultado de este mapeo es especificar que si el tipo de terminal es dialup, y la velocidad en baudios es mayor que 9600 baudios, se utilizará el tipo de terminal vt100.

Si no se especifica velocidad en baudios, el tipo de terminal coincidirá con cualquier velocidad en baudios. Si no se especifica tipo de puerto, el tipo de terminal coincidirá con cualquier tipo de puerto. Por ejemplo, -m dialup:vt100 -m :?xterm hará que cualquier puerto dialup, independientemente de la velocidad en baudios, coincida con el tipo de terminal vt100, y cualquier tipo de puerto no dialup coincida con el tipo de terminal ?xterm. Tenga en cuenta que, debido al signo de interrogación inicial, se le preguntará al usuario en un puerto predeterminado si realmente está utilizando una terminal xterm.

No se permiten caracteres de espacio en blanco en el argumento de la opción -m. Además, para evitar problemas con meta-caracteres, se sugiere colocar todo el argumento de la opción -m entre comillas simples, y que los usuarios de csh inserten una barra invertida (“\”) antes de cualquier signo de exclamación (“!”).

OPCIONES

Las opciones son las siguientes:

-c
Establecer caracteres y modos de control.
-e caracter
Establece el carácter de borrado a ch.
-I
No envía las cadenas de inicialización del terminal o de tabulación al terminal.
-i ch
Establece el carácter de interrupción a ch.
-k ch
Establece el carácter de borrado de línea a ch.
-m mapping
Especifica una asignación de un tipo de puerto a un terminal; véase el subapartado "Asignación de tipo de terminal".
-Q
No muestra ningún valor para los caracteres de borrado, interrupción y borrado de línea. Normalmente, tset muestra los valores de los caracteres de control que difieren de los valores predeterminados del sistema.
-q
El tipo de terminal se muestra en la salida estándar y el terminal no se inicializa de ninguna manera. La opción "-" por sí sola es equivalente pero arcaica.
-r
Imprime el tipo de terminal en la salida de error estándar.
-s
Imprime la secuencia de comandos de shell para inicializar la variable de entorno TERM en la salida estándar; véase el subapartado "Configuración del entorno".
-V
informa la versión de ncurses que se utilizó en este programa y finaliza.
-w
Redimensiona la ventana para que coincida con el tamaño deducido a través de setupterm(3X). Normalmente, esto no tiene ningún efecto, a menos que setupterm no pueda detectar el tamaño de la ventana.

Los argumentos de las opciones -e, -i y -k pueden introducirse como caracteres reales o utilizando la notación "sombrero", es decir, el control-h puede especificarse como "^H" o "^h".

Si no se proporciona ni -c ni -w, se asumen ambas opciones.

AMBIENTE

El comando tset utiliza las siguientes variables de entorno:

SHELL
indica a tset si debe inicializar TERM utilizando la sintaxis de sh(1) o csh(1).
TERM
Denota el tipo de su terminal. Cada tipo de terminal es distinto, aunque muchos son similares.
TERMCAP
puede denotar la ubicación de una base de datos termcap. Si no es una ruta de archivo absoluta, por ejemplo, comienza con una "/", tset elimina la variable del entorno antes de buscar la descripción del terminal.

ARCHIVOS

/etc/ttys
base de datos de mapeo de nombre de puerto del sistema a tipo de terminal (solo versiones BSD).
/usr/share/terminfo
directorio de la base de datos compilada de descripciones de terminales

PORTABILIDAD

Ni IEEE Std 1003.1/The Open Group Base Specifications Issue 7 (POSIX.1-2008) ni X/Open Curses Issue 7 documentan tset o reset.

La utilidad tput de AT&T (AIX, HP-UX, Solaris) incorporó la manipulación del modo del terminal, así como características basadas en termcap, como el restablecimiento de las tabulaciones de tset en BSD (4.1c), presumiblemente con la intención de hacer obsoleto a tset. Sin embargo, cada uno de esos sistemas todavía proporciona tset. De hecho, la utilidad comúnmente utilizada reset es siempre un alias para tset.

La utilidad tset proporciona compatibilidad con versiones anteriores con entornos BSD; en la mayoría de los sistemas Unix modernos, /etc/inittab y getty(8) pueden establecer TERM apropiadamente para cada línea de acceso telefónico, obviando lo que fue el uso más importante de tset. Esta implementación se comporta como la versión 4.4BSD de tset, con algunas excepciones que consideraremos ahora.

Algunas opciones son diferentes porque la variable TERMCAP ya no se admite en ncurses basado en terminfo:

  • La opción -S de la versión BSD de tset ya no funciona; imprime un mensaje de error en la salida estándar y finaliza.
  • La opción -s solo establece TERM, no TERMCAP.

Había una característica no documentada de 4.4BSD que al invocar tset a través de un enlace llamado "TSET" (o cualquier otro nombre que comience con una letra mayúscula) configuraba el terminal para usar solo mayúsculas. Esta característica se ha omitido.

Las opciones -A, -E, -h, -u y -v se eliminaron de la utilidad tset en 4.4BSD. Ninguna de ellas estaba documentada en 4.3BSD y todas tienen una utilidad limitada en el mejor de los casos. Las opciones -a, -d y -p tampoco están documentadas ni son útiles, pero se conservaron ya que parecen estar en uso generalizado. Se recomienda encarecidamente que cualquier uso de estas tres opciones se cambie para usar la opción -m en su lugar. Por lo tanto, las opciones -a, -d y -p se omiten en el resumen de uso anterior.

Sistemas muy antiguos, por ejemplo, 3BSD, utilizaban un controlador de terminal diferente que fue reemplazado en 4BSD a principios de la década de 1980. Para dar cabida a esos sistemas más antiguos, la versión 4BSD de tset proporcionaba una opción -n para especificar que se debía usar el nuevo controlador de terminal. Esta implementación no ofrece esa opción.

Todavía es aceptable especificar las opciones -e, -i y -k sin argumentos, aunque se recomienda encarecidamente que dicho uso se corrija para especificar explícitamente el carácter.

A partir de 4.4BSD, ejecutar tset como reset ya no implica la opción -Q. Además, se ha eliminado la interacción entre la opción - y el argumento terminal en algunas implementaciones históricas de tset.

Las opciones -c y -w no se encuentran en implementaciones anteriores. Sin embargo, se proporcionó una característica diferente de cambio de tamaño de ventana en 4.4BSD.

  • En 4.4BSD, tset utiliza el tamaño de la ventana de la descripción de termcap para establecer el tamaño de la ventana si tset no puede obtener el tamaño de la ventana del sistema operativo.
  • En ncurses, tset obtiene el tamaño de la ventana usando setupterm(3X), que puede provenir del sistema operativo, las variables de entorno LINES y COLUMNS o la descripción del terminal.

La obtención del tamaño de la ventana a partir de la descripción del tipo de terminal es común a ambas implementaciones, pero se considera obsoleta. Su único uso práctico es para terminales de hardware. En general, el tamaño de la ventana permanecerá sin inicializar solo si hubo un problema para obtener el valor del sistema operativo (y setupterm aún fallaría). Las variables de entorno LINES y COLUMNS pueden ser útiles para solucionar problemas de tamaño de ventana, pero tienen la desventaja de que si la ventana se redimensiona, sus valores deben recalcularse y reasignarse. El programa resize(1) distribuido con xterm(1) ayuda en esta actividad.

HISTORIA

Un comando reset escrito por Kurt Shoens apareció en 1BSD (marzo de 1978). Establecía los caracteres erase y kill a ^H (retroceso) y @ respectivamente. Mark Horton mejoró este reset en 3BSD (octubre de 1979), añadiendo caracteres intr, quit, start/stop y eof, además de modificar el programa para evitar modificar cualquier configuración del usuario. Esa versión de reset no utilizaba termcap.

Eric Allman escribió un comando tset distinto para 1BSD, utilizando un precursor de termcap llamado ttycap. Los comentarios de Allman en el código fuente indican que comenzó a trabajar en octubre de 1977, continuando el desarrollo durante los años siguientes. A finales de 1979, se había migrado a termcap y manejaba la variable TERMCAP. Comentarios posteriores indican que tset se modificó en septiembre de 1980 para usar la lógica copiada del programa "reset" de 3BSD cuando se invocaba como reset. Esta versión apareció en 4.1cBSD, a finales de 1982. Otros desarrolladores como Keith Bostic y Jim Bloom continuaron modificando tset hasta el lanzamiento de 4.4BSD en 1993.

La implementación de ncurses fue adaptada ligeramente de las fuentes de 4.4BSD para usar la API de terminfo por Eric S. Raymond <esr@snark.thyrsus.com>.
