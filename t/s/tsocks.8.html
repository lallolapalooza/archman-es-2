TSOCKS(8) Manual del Administrador del Sistema TSOCKS(8)

NOMBRE

tsocks - Biblioteca para interceptar conexiones de red salientes y redirigirlas a través de un servidor SOCKS.

SINOPSIS

Establece LD_PRELOAD para cargar la biblioteca y luego usa las aplicaciones de forma normal

La sintaxis para forzar la precarga de la biblioteca para diferentes shells se especifica a continuación:

Bash, Ksh y Bourne shell -

export LD_PRELOAD=/lib/libtsocks.so

C Shell -

setenv LD_PRELOAD=/lib/libtsocks.so

Este proceso se puede automatizar (para usuarios de Bash, Bourne y Korn shell) para un solo comando o para todos los comandos en una sesión de shell utilizando el script tsocks(1)

También puedes configurar tsocks de tal manera que todos los procesos la utilicen automáticamente, una configuración muy útil. Para más información sobre esta configuración, consulta la sección CAVEATS de esta página del manual.

DESCRIPCIÓN

tsocks es una biblioteca para permitir el proxy SOCKS transparente. Envuelve la función normal connect(). Cuando se intenta una conexión, consulta el archivo de configuración (que se define en tiempo de configuración pero por defecto es /etc/tsocks.conf) y determina si la dirección IP especificada es local. Si no lo es, la biblioteca redirige la conexión a un servidor SOCKS especificado en el archivo de configuración. Luego negocia esa conexión con el servidor SOCKS y la devuelve al programa que la llama.

tsocks está diseñado para su uso en máquinas que están protegidas por firewall de Internet. Evita la necesidad de recompilar aplicaciones como lynx o telnet para que puedan usar SOCKS para acceder a Internet. Se comporta de manera muy similar a las pilas TCP/IP "SOCKSified" vistas en otras plataformas.

ARGUMENTOS

La mayoría de los argumentos para tsocks se proporcionan en el archivo de configuración (cuya ubicación se define en tiempo de configuración con el argumento --with-conf=<archivo> pero por defecto es /etc/tsocks.conf). La estructura de este archivo se documenta en tsocks.conf(8)

Algunas opciones de configuración se pueden especificar en tiempo de ejecución utilizando variables de entorno de la siguiente manera:

TSOCKS_CONFFILE
Esta variable de entorno anula la ubicación predeterminada del archivo de configuración de tsocks. Esta variable no se respeta si el programa en el que tsocks está incrustado tiene el bit setuid activado. Además, esta variable de entorno puede ser eliminada de tsocks con el argumento --disable-envconf al configurar en tiempo de compilación.
TSOCKS_DEBUG
Esta variable de entorno establece el nivel de salida de depuración que debe generar tsocks (la salida de depuración se genera en la salida estándar de error). Si esta variable no está presente por defecto, el nivel de registro se establece en 0, lo que indica que solo se deben mostrar los mensajes de error. Establecerlo en valores más altos hará que tsocks genere más mensajes describiendo lo que está haciendo. Si se establece en -1, tsocks no generará ningún mensaje de error o depuración. Esto solo es necesario si la salida de tsocks interfiere con un programa en el que está incrustado. La salida de mensajes se puede eliminar permanentemente de tsocks especificando la opción --disable-debug a configure en tiempo de compilación.
TSOCKS_DEBUG_FILE
Esta opción se puede utilizar para redirigir la salida de tsocks (que normalmente se enviaría a la salida estándar de error) a un archivo. Esta variable no se respeta si el programa en el que tsocks está incrustado tiene el bit setuid activado. Para programas donde la salida de tsocks interfiere con la operación normal, esta opción es generalmente mejor que deshabilitar mensajes (con TSOCKS_DEBUG = -1).
TSOCKS_USERNAME
Esta variable de entorno se puede utilizar para especificar el nombre de usuario que se utilizará cuando los servidores SOCKS de la versión 5 soliciten autenticación de nombre de usuario/contraseña. Esto anula el nombre de usuario predeterminado que se puede especificar en el archivo de configuración usando 'default_user', consulte tsocks.conf(8) para obtener más información. Esta variable se ignora para los servidores SOCKS de la versión 4.
TSOCKS_PASSWORD
Esta variable de entorno se puede utilizar para especificar la contraseña que se utilizará cuando los servidores SOCKS de la versión 5 soliciten autenticación de nombre de usuario/contraseña. Esto anula la contraseña predeterminada que se puede especificar en el archivo de configuración usando 'default_pass', consulte tsocks.conf(8) para obtener más información. Esta variable se ignora para los servidores SOCKS de la versión 4.

PROBLEMAS DE DNS

tsocks normalmente no podrá enviar consultas DNS a través de un servidor SOCKS, ya que SOCKS V4 funciona sobre TCP y DNS normalmente utiliza UDP. Las versiones 1.5 y posteriores proporcionan un método para forzar que las búsquedas de DNS utilicen TCP, lo que las hace proxyables. Esta opción solo se puede habilitar en tiempo de compilación, consulte el archivo INSTALL para obtener más información.

ERRORES

tsocks generará mensajes de error y los imprimirá en stderr cuando haya problemas con el archivo de configuración o la negociación SOCKS con el servidor si la variable de entorno TSOCKS_DEBUG no está establecida en -1 o si no se especificó --disable-debug en tiempo de compilación. Esta salida puede causar algunos problemas con programas que redirigen la salida estándar de error.

ADVERTENCIAS

En la configuración anterior, tsocks no podrá proporcionar proxy SOCKS a aplicaciones setuid o aplicaciones que no se ejecuten desde un shell. Puede forzar que todas las aplicaciones precarguen la biblioteca (LD_PRELOAD) colocando la ruta a libtsocks en /etc/ld.so.preload. Asegúrese de introducir correctamente la ruta completa de la biblioteca en este archivo si lo hace. Si se equivoca, NO PODRÁ HACER NADA con la máquina y tendrá que arrancarla con un disco de rescate y eliminar el archivo (o probar el programa saveme, consulte el archivo INSTALL para más información). ESTO ES UNA ***ADVERTENCIA***, tenga cuidado. Asegúrese también de que la biblioteca esté en el sistema de archivos raíz, ya que todo saldrá mal si el directorio en el que se encuentra no está disponible en el momento del arranque.

ERRORES CONOCIDOS

tsocks solo puede proxyar conexiones TCP salientes.

tsocks NO funciona correctamente con sockets asíncronos (aunque sí funciona con sockets no bloqueantes). Este error sería muy difícil de solucionar y parece que no hay demanda para él (no conozco ninguna aplicación importante que utilice sockets asíncronos).

tsocks NO cumple totalmente con el RFC en su implementación de la versión 5 de SOCKS, solo admite los métodos de autenticación de 'nombre de usuario y contraseña' o 'sin autenticación'. El RFC especifica que GSSAPI debe ser compatible con cualquier implementación que cumpla. No he hecho esto, ¿alguien quiere ayudar?

tsocks puede forzar al resolvedor libc a usar TCP para consultas de nombres, si lo hace, lo hace independientemente de si el DNS a consultar es local o no. Esto introduce sobrecarga y solo debe usarse cuando sea necesario.

tsocks utiliza características del cargador dinámico ELF para interceptar llamadas de funciones dinámicas de los programas en los que está incrustado. Como resultado, no puede rastrear las acciones de ejecutables enlazados estáticamente, ejecutables no ELF o ejecutables que realizan llamadas al sistema directamente con la trampa de llamada al sistema o a través de la rutina syscall().

tsocks(8)

NAME

tsocks - transparently socksifies TCP connections

SYNOPSIS

tsocks [-v] [-c] command [args...]

tsocks [-v] [-c] program [args...]

DESCRIPTION

This manual page documents the current version of tsocks.

tsocks socksifies TCP connections transparently. It works by preloading a shared library (libtsocks.so) that intercepts socket calls and redirects them through a SOCKS server.

This is particularly useful for programs that do not have native SOCKS support. For example, it can be used to make older IRC clients that do not support SOCKS work through a SOCKS proxy.

The configuration file for tsocks is located at /etc/tsocks.conf.

-v Verbose mode. Prints connection information to stderr.

-c Turn off checking of the remote hostname. This is useful if your SOCKS server does not support remote hostname resolution.
