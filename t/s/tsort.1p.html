TSORT(1P) Manual de Programador de POSIX TSORT(1P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

tsort — ordenación topológica

SINOPSIS

tsort [archivo]

DESCRIPCIÓN

El utilitario tsort escribirá en la salida estándar una lista totalmente ordenada de elementos compatible con un orden parcial de elementos contenido en la entrada. La aplicación debe asegurarse de que la entrada consista en pares de elementos (cadenas no vacías) separados por caracteres de espacio en blanco. Los pares de elementos diferentes indican orden. Los pares de elementos idénticos indican presencia, pero no orden.

OPCIONES

Ninguna.

OPERANDOS

Se soportará el siguiente operando:

archivo
Un nombre de ruta de un archivo de texto a ordenar. Si no se proporciona ningún operando de archivo, se utilizará la entrada estándar.

ENTRADA ESTÁNDAR

La entrada estándar se utilizará si no se especifica ningún operando de archivo, y se utilizará si el operando archivo es '-' y la implementación trata el '-' como entrada estándar. De lo contrario, la entrada estándar no se utilizará. Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

El archivo de entrada será un archivo de texto.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de tsort:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no estén establecidas o estén vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a multi-byte en argumentos y archivos de entrada).
LC_MESSAGES

Determinar la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La salida estándar será un archivo de texto que consistirá en la lista ordenada producida a partir de la entrada parcialmente ordenada.

ERROR ESTÁNDAR

El error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO DE APLICACIONES

La variable LC_COLLATE puede no afectar las acciones de tsort. El orden de salida no es lexicográfico, sino que depende de los pares de elementos dados como entrada.

EJEMPLOS

El comando:

tsort <<EOF
a b c c d e
g g
f g e f
h h
EOF

produce la salida:

a
b
c
d
e
f
g
h

RACIONALE

Ninguno.

DIRECCIONES FUTURAS

Ninguna.

SYNOPSIS

tsort [-bc] [file...]

DESCRIPTION

tsort lee pares de líneas de los archivos de entrada especificados (o de la entrada estándar si no se especifican archivos), ordena las líneas basándose en las relaciones de orden indicadas y escribe las líneas resultantes en la salida estándar.

OPERANDS

Los operandos son nombres de archivos que contienen los datos a ordenar. Si no se especifican archivos, se lee de la entrada estándar.

STDIN

Si no se especifican archivos, tsort lee de la entrada estándar.

INPUT FILES

Los archivos de entrada deben contener líneas con formato de pares. Cada línea debe contener dos elementos separados por un espacio en blanco. El primer elemento representa un nodo y el segundo elemento representa un nodo que depende del primero. Por ejemplo, "A B" significa que A debe preceder a B.

ENVIRONMENT VARIABLES

tsort no utiliza variables de entorno específicas para su funcionamiento.

ASYNCHRONOUS EVENTS

tsort no responde a eventos asíncronos.

STDOUT

La salida estándar contiene las líneas de entrada ordenadas de acuerdo con las dependencias especificadas.

STDERR

tsort escribe mensajes de error a la salida de error estándar.

OUTPUT FILES

tsort no produce archivos de salida por defecto. La salida se redirige a la salida estándar.

EXTENDED DESCRIPTION

tsort es una utilidad de ordenación topológica. Dada una lista de dependencias, donde se indica que un elemento debe aparecer antes que otro, tsort genera una secuencia lineal de los elementos que satisface todas las dependencias.

El algoritmo utilizado por tsort es el algoritmo de ordenación topológica de Kahn, que se basa en el cálculo de grados de entrada de los nodos.

EXIT STATUS

  • 0: Éxito.
  • 1: Error en la entrada.
  • 2: Se ha detectado un ciclo en las dependencias.

CONSEQUENCES OF ERRORS

Si se produce un error de entrada (por ejemplo, formato de línea incorrecto), tsort imprimirá un mensaje de error a stderr y saldrá con un estado de salida de 1.

Si se detecta un ciclo en las dependencias (lo que hace imposible una ordenación topológica), tsort imprimirá un mensaje de error a stderr y saldrá con un estado de salida de 2.

APPLICATION USAGE

tsort se utiliza típicamente para ordenar tareas o paquetes que tienen dependencias entre sí. Por ejemplo, para instalar paquetes de software donde algunos paquetes deben instalarse antes que otros.

El formato de entrada es crucial. Cada línea debe ser un par de elementos (generalmente cadenas de texto) separados por un solo espacio en blanco. Los elementos pueden ser nombres de archivos, nombres de tareas, identificadores, etc.

EXAMPLES

Ejemplo 1: Ordenar dependencias de compilación

Supongamos que tenemos un archivo llamado deps.txt con el siguiente contenido:

libpng jpeg
libjpeg png
app libpng
app libjpeg

Esto significa que libpng y libjpeg deben compilarse antes que app, y libpng depende de libjpeg.

Para obtener un orden de compilación válido, ejecutaríamos:

tsort deps.txt

Una posible salida sería:

libjpeg
libpng
app

Ejemplo 2: Entrada desde la entrada estándar

Podríamos canalizar la salida de otro comando a tsort:

echo "a b" | tsort
echo "b c" | tsort

Esto es equivalente a tener un archivo con las líneas "a b" y "b c", y tsort produciría una salida ordenada.

RATIONALE

tsort implementa la ordenación topológica, una operación fundamental en la teoría de grafos y la informática. Es esencial para gestionar dependencias y asegurar que los elementos se procesen en un orden lógico y factible. La simplicidad de su interfaz y su enfoque en la ordenación basada en dependencias lo convierten en una herramienta valiosa para tareas de gestión de sistemas y compilación.

FUTURE DIRECTIONS

No hay planes de desarrollo o direcciones futuras específicas mencionadas para tsort. Se considera una utilidad madura y estable.
