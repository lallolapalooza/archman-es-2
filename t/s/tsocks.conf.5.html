TSOCKS.CONF(5) Manual de formatos de archivo TSOCKS.CONF(5)

NOMBRE

tsocks.conf - archivo de configuración para tsocks(8)

DESCRIPCIÓN GENERAL

La configuración de tsocks puede variar desde dos líneas hasta cientos de líneas, según las necesidades de cada sitio. La idea básica es definir cualquier red a la que la máquina pueda acceder directamente (es decir, sin el uso de un servidor SOCKS) y definir uno o más servidores SOCKS que se utilizarán para acceder a otras redes (incluyendo un servidor 'predeterminado').

Las redes locales se declaran usando la palabra clave 'local' en el archivo de configuración. Cuando las aplicaciones intentan conectarse a máquinas en redes marcadas como locales, tsocks no intentará utilizar un servidor SOCKS para negociar la conexión.

Obviamente, si una conexión no es a una red accesible localmente, necesitará ser redirigida a través de un servidor SOCKS. Sin embargo, muchas instalaciones tienen varios servidores SOCKS diferentes para acceder a diferentes redes internas (y externas). Las rutas se declaran como bloques en el archivo de configuración. Es decir, comienzan con una línea 'path {' en el archivo de configuración y terminan con una línea '}'. Dentro de este bloque, se deben utilizar directivas para declarar un servidor SOCKS (como se documenta más adelante en esta página del manual) y directivas 'reaches' se deben utilizar para declarar redes e incluso puertos de destino en esas redes a las que se debe utilizar este servidor. Nota: Cada ruta DEBE definir un servidor SOCKS y contener una o más directivas 'reaches'.

Las directivas de declaración de servidor SOCKS que no están contenidas dentro de un bloque 'path' definen el servidor SOCKS predeterminado. Si tsocks necesita conectarse a una máquina a través de un servidor SOCKS (es decir, no es una red declarada como 'local') y ninguna ruta ha declarado que puede alcanzar esa red a través de una directiva 'reaches', este servidor se utiliza para negociar la conexión.

SINTAXIS DE CONFIGURACIÓN

La estructura básica de todas las líneas en el archivo de configuración es:

<directiva> = <parámetros>

La excepción a esto son los bloques 'path' que se ven así:

path {
<directiva> = <parámetros>
}

Las líneas vacías se ignoran y toda la entrada en una línea después de un carácter '#' se ignora.

DIRECTIVAS

Las siguientes directivas se utilizan en el archivo de configuración de tsocks:

server
La dirección IP del servidor SOCKS (por ejemplo, "server = 10.1.4.253"). Solo se puede especificar un servidor por bloque de ruta, o uno fuera de un bloque de ruta (para definir el servidor predeterminado). A menos que se especificara --disable-hostnames al compilar, el servidor se puede especificar como un nombre de host (por ejemplo, "server = socks.nec.com").
server_port
El puerto en el que el servidor SOCKS recibe solicitudes. Solo se puede especificar un puerto de servidor por bloque de ruta, o uno fuera de una ruta (para el servidor predeterminado). Esta directiva no es necesaria si el servidor está en el puerto estándar (1080).
server_type
Versión SOCKS utilizada por el servidor. Se admiten las versiones 4 y 5 (pero ambas solo para la operación de conexión). El valor predeterminado es 4. Solo se puede especificar un tipo de servidor por bloque de ruta, o uno fuera de una ruta (para el servidor predeterminado).

Puede usar la utilidad inspectsocks para determinar el tipo de servidor, consulte la sección 'UTILIDADES' más adelante en esta página del manual.

default_user
Esto especifica el nombre de usuario predeterminado que se utilizará para la autenticación de nombre de usuario y contraseña en SOCKS versión 5. Para determinar el nombre de usuario a usar (si el servidor SOCKS requiere autenticación de nombre de usuario y contraseña), tsocks primero busca la variable de entorno TSOCKS_USERNAME, luego busca esta opción de configuración y luego intenta obtener el nombre de usuario local. Esta opción no es válida para servidores SOCKS versión 4. Solo se puede especificar un usuario predeterminado por bloque de ruta, o uno fuera de una ruta (para el servidor predeterminado).
default_pass
Esto especifica la contraseña predeterminada que se utilizará para la autenticación de nombre de usuario y contraseña en SOCKS versión 5. Para determinar la contraseña a usar (si el servidor SOCKS requiere autenticación de nombre de usuario y contraseña), tsocks primero busca la variable de entorno TSOCKS_PASSWORD, luego busca esta opción de configuración. Esta opción no es válida para servidores SOCKS versión 4. Solo se puede especificar una contraseña predeterminada por bloque de ruta, o una fuera de una ruta (para el servidor predeterminado).
local
Un par IP/Subred que especifica una red a la que se puede acceder directamente sin redirigir a través de un servidor SOCKS (por ejemplo, "local = 10.0.0.0/255.0.0.0"). Obviamente, todas las direcciones IP de los servidores SOCKS deben estar en redes especificadas como locales, de lo contrario, tsocks necesitaría un servidor SOCKS para llegar a los servidores SOCKS.
reaches
Esta directiva solo es válida dentro de un bloque de ruta. Su parámetro se forma como IP[:puerto_inicio-puerto_fin]/Subred y especifica una red (y un rango de puertos en esa red) a la que se puede acceder mediante el servidor SOCKS especificado en este bloque de ruta. Por ejemplo, en un bloque de ruta "reaches = 150.0.0.0:80-1024/255.0.0.0" indica a tsocks que el servidor SOCKS especificado en el bloque de ruta actual se utilizará para acceder a cualquier IP en el rango 150.0.0.0 a 150.255.255.255 cuando la solicitud de conexión sea para los puertos 80-1024.

UTILIDADES

tsocks viene con dos utilidades que pueden ser útiles para crear y verificar el archivo de configuración de tsocks.

inspectsocks
inspectsocks se puede utilizar para determinar la versión SOCKS que soporta un servidor. Inspectsocks toma como argumentos la dirección IP/nombre del servidor SOCKS y opcionalmente el número de puerto para socks (por ejemplo, 'inspectsocks socks.nec.com 1080'). Luego inspecciona ese servidor para intentar determinar la versión que soporta ese servidor.
validateconf
validateconf se puede utilizar para verificar el archivo de configuración. Comprueba el formato del archivo y también el contenido en busca de errores. Después de leer el archivo, vuelca la configuración en la pantalla de una manera formateada y legible. Esto puede ser extremadamente útil para depurar problemas.

validateconf puede leer un archivo de configuración desde una ubicación distinta a la especificada al compilar con la opción de línea de comandos -f <nombre_archivo>.

Normalmente, validateconf simplemente vuelca la configuración leída en la pantalla (en un formato legible y agradable), sin embargo, también tiene un útil modo de 'prueba'. Cuando se le pasa un nombre de host/IP en la línea de comandos como -t <nombre_host/ip>, validateconf determina cuál de los servidores SOCKS especificados en el archivo de configuración sería utilizado por tsocks para acceder al host especificado.
