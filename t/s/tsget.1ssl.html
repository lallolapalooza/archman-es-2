NOMBRE

tsget - Cliente HTTP/HTTPS de sellado de tiempo

SINOPSIS

tsget -h url_servidor [-e extensión] [-o salida] [-v] [-d] [-k clave_privada.pem] [-p contraseña_clave] [-c certificado_cliente.pem] [-C certs_CA.pem] [-P ruta_CA] [-r archivos] [-g socket_EGD] [solicitud ...]

DESCRIPCIÓN

Este comando se puede utilizar para enviar una solicitud de sellado de tiempo, tal como se especifica en RFC 3161, a un servidor de sellado de tiempo a través de HTTP o HTTPS y almacenar la respuesta del sellado de tiempo en un archivo. No se puede utilizar para crear las solicitudes y verificar las respuestas; debe usar openssl-ts(1) para hacerlo. Este comando puede enviar varias solicitudes al servidor sin cerrar la conexión TCP si se especifican más de una solicitud en la línea de comandos.

Este comando envía la siguiente solicitud HTTP por cada solicitud de sellado de tiempo:

POST url HTTP/1.1
User-Agent: OpenTSA tsget.pl/<versión>
Host: <host>:<puerto>
Pragma: no-cache
Content-Type: application/timestamp-query
Accept: application/timestamp-reply
Content-Length: longitud del cuerpo
...solicitud binaria especificada por el usuario...

Espera una respuesta de tipo application/timestamp-reply, que se escribe en un archivo sin ninguna interpretación.

OPCIONES

-h url_servidor
La URL del servidor HTTP/HTTPS que escucha las solicitudes de sellado de tiempo.
-e extensión
Si no se proporciona la opción -o, este argumento especifica la extensión de los archivos de salida. El nombre base del archivo de salida será el mismo que el de los archivos de entrada. La extensión predeterminada es .tsr. (Opcional)
-o salida
Esta opción solo se puede especificar cuando se envía una sola solicitud al servidor. La respuesta del sellado de tiempo se escribirá en el archivo de salida dado. '-' significa salida estándar. En caso de solicitudes de sellado de tiempo múltiples o la ausencia de este argumento, los nombres de los archivos de salida se derivarán de los nombres de los archivos de entrada y del argumento de extensión predeterminado o especificado. (Opcional)
-v
El nombre de la solicitud que se está procesando actualmente se imprime en la salida de error estándar. (Opcional)
-d
Activa el modo detallado para el módulo subyacente WWW::Curl::Easy. Puede ver mensajes de depuración detallados para la conexión. (Opcional)
-k clave_privada.pem
(HTTPS) En caso de autenticación de cliente basada en certificado a través de HTTPS, clave_privada.pem debe contener la clave privada del usuario. El archivo de clave privada puede estar opcionalmente protegido con una contraseña. La opción -c también debe especificarse. (Opcional)
-p contraseña_clave
(HTTPS) Especifica la contraseña para la clave privada especificada por el argumento -k. Si se omite esta opción y la clave está protegida con contraseña, se le pedirá. (Opcional)
-c certificado_cliente.pem
(HTTPS) En caso de autenticación de cliente basada en certificado a través de HTTPS, certificado_cliente.pem debe contener el certificado X.509 del usuario. La opción -k también debe especificarse. Si no se especifica esta opción, no se realizará ninguna autenticación de cliente basada en certificado. (Opcional)
-C certs_CA.pem
(HTTPS) El almacén de certificados de CA de confianza. La cadena de certificados del certificado del par debe incluir uno de los certificados de CA especificados en este archivo. Se debe proporcionar la opción -C o la opción -P en caso de HTTPS. (Opcional)
-P ruta_CA
(HTTPS) La ruta que contiene los certificados de CA de confianza para verificar el certificado del par. El directorio debe estar preparado con openssl-rehash(1). Se debe proporcionar la opción -C o la opción -P en caso de HTTPS. (Opcional)
-r archivos
Consulte "Opciones de estado aleatorio" en openssl(1) para obtener más información.
-g socket_EGD
El nombre de un socket EGD para obtener datos aleatorios. (Opcional)
solicitud ...
Lista de archivos que contienen solicitudes de sellado de tiempo codificadas en DER según RFC 3161. Si no se especifican solicitudes, se enviará una única solicitud al servidor y se leerá desde la entrada estándar. (Opcional)

VARIABLES DE ENTORNO

La variable de entorno TSGET puede contener opcionalmente argumentos predeterminados. El contenido de esta variable se añade a la lista de argumentos de la línea de comandos.

EJEMPLOS

Los ejemplos a continuación presuponen que file1.tsq y file2.tsq contienen solicitudes de sellado de tiempo válidas, que tsa.opentsa.org escucha en el puerto 8080 para solicitudes HTTP y en el puerto 8443 para solicitudes HTTPS, y que el servicio TSA está disponible en la ruta absoluta /tsa.

Obtener una respuesta de sellado de tiempo para file1.tsq a través de HTTP, la salida se escribe en file1.tsr:

tsget -h http://tsa.opentsa.org:8080/tsa file1.tsq

Obtener una respuesta de sellado de tiempo para file1.tsq y file2.tsq a través de HTTP mostrando el progreso, la salida se escribe en file1.reply y file2.reply respectivamente:

tsget -h http://tsa.opentsa.org:8080/tsa -v -e .reply \
      file1.tsq file2.tsq

Crear una solicitud de sellado de tiempo, escribirla en file3.tsq, enviarla al servidor y escribir la respuesta en file3.tsr:

openssl ts -query -data file3.txt -cert | tee file3.tsq \
      | tsget -h http://tsa.opentsa.org:8080/tsa \
      -o file3.tsr

Obtener una respuesta de sellado de tiempo para file1.tsq a través de HTTPS sin autenticación de cliente:

tsget -h https://tsa.opentsa.org:8443/tsa \
      -C cacerts.pem file1.tsq

Obtener una respuesta de sellado de tiempo para file1.tsq a través de HTTPS con autenticación de cliente basada en certificado (pedirá la contraseña si client_key.pem está protegido):

tsget -h https://tsa.opentsa.org:8443/tsa -C cacerts.pem \
      -k client_key.pem -c client_cert.pem file1.tsq

Puede acortar la línea de comandos anterior si utiliza la variable de entorno TSGET. Los siguientes comandos hacen lo mismo que el ejemplo anterior:

TSGET='-h https://tsa.opentsa.org:8443/tsa -C cacerts.pem \
      -k client_key.pem -c client_cert.pem'
export TSGET
tsget file1.tsq
