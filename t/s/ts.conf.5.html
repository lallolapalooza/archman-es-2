NOMBRE

ts.conf - Archivo de configuración para tslib, que controla las pantallas táctiles para dispositivos integrados.

DESCRIPCIÓN

La idea de tslib es tener una biblioteca central que proporcione servicios estándar y un conjunto de plugins para gestionar la conversión y el filtrado según sea necesario.

Los plugins para una pantalla táctil en particular son cargados automáticamente por la biblioteca bajo el control de un archivo de configuración estático, /etc/ts.conf. /etc/ts.conf proporciona a la biblioteca información básica de configuración. Cada línea especifica un módulo y los parámetros para ese módulo. Los módulos se cargan en orden, y el primero procesa los datos de la pantalla táctil primero. Por ejemplo:

  module_raw input
  module variance delta=30
  module dejitter delta=100
  module linear

VARIABLES DE ENTORNO

Las versiones más recientes del controlador de entrada tslib de Xorg usan hal para configurar la pantalla táctil dentro de Xorg. Las variables de entorno solo son necesarias para los comandos de tslib.

TSLIB_TSDEVICE

Si no se encuentra el dispositivo de pantalla táctil predeterminado, establezca la variable de entorno TSLIB_TSDEVICE al dispositivo de pantalla táctil a utilizar.

Predeterminado al usar ts_setup(): Intentamos abrir /dev/input/ts, /dev/input/touchscreen y /dev/touchscreen/ucb1x00 y en Linux, luego escaneamos /dev/input/event* para el primer dispositivo con la propiedad INPUT_PROP_DIRECT.

TSLIB_CONSOLEDEVICE

Dispositivo de consola predeterminado de tslib.

Predeterminado: /dev/tty

TSLIB_CALIBFILE

Almacena los datos de calibración obtenidos usando ts_calibrate.

Predeterminado: /etc/pointercal

TSLIB_CONFFILE

Establece una ubicación diferente para el propio archivo de configuración ts.conf.

Predeterminado: /etc/ts.conf.

TSLIB_FBDEVICE

Dispositivo de framebuffer a utilizar para el soporte de pantalla táctil.

Predeterminado: /dev/fb0.

TSLIB_PLUGINDIR

Directorio de plugins para tslib.

Predeterminado: /usr/lib/$triplet/ts0/ donde triplet es la ruta MultiArch, por ejemplo, arm-linux-gnueabi.

PARÁMETROS DE MÓDULO

dejitter

Elimina el jitter en las coordenadas X e Y. Esto se logra aplicando un filtro de suavizado ponderado. Las muestras más recientes tienen más peso; las muestras anteriores tienen menos peso. Esto permite lograr una tasa de entrada/salida de 1:1.
•delta

Distancia al cuadrado entre dos muestras ((X2-X1)^2 + (Y2-Y1)^2) que define el umbral de movimiento rápido. Si el lápiz se mueve rápido, no es factible suavizar el movimiento del lápiz, además el movimiento rápido no es preciso de todos modos; por lo tanto, si se detecta movimiento rápido, el módulo simplemente descarta el historial y simplemente copia la entrada a la salida.

linear

Módulo de escalado lineal, utilizado principalmente para la conversión de coordenadas de pantalla táctil a coordenadas de pantalla.
•rot

Rotación de las coordenadas táctiles. 0=no, 1=CW (sentido horario), 2=UD (arriba-abajo), 3=CCW (sentido antihorario). Predeterminado: la rotación de pantalla que se utilizó con ts_calibrate (opción -r).

•xyswap

Intercambia las coordenadas X e Y; ya no se usa ni se necesita si se utiliza la nueva utilidad de calibración lineal ts_calibrate.

•pressure_offset

Desplazamiento aplicado al valor de presión. Predeterminado: 0.

•pressure_mul

Factor para multiplicar el valor de presión. Predeterminado: 1.

•pressure_div

Valor para dividir el valor de presión. Predeterminado: 1.

iir

Filtro de respuesta impulsional finita. Similar a dejitter, este es un filtro de suavizado para eliminar ruido de bajo nivel. Existe una compensación entre la eliminación de ruido (suavizado) y la capacidad de respuesta. Los parámetros N y D especifican el nivel de suavizado en forma de una fracción (N/D).
•N

Numerador de la fracción de suavizado. Predeterminado: 0.

•D

Denominador de la fracción de suavizado. Predeterminado: 1.

pthres

Filtro de umbral de presión. Dado que una liberación es siempre presión 0 y una pulsación es siempre >= 1, esto descarta las muestras por debajo/encima del umbral de presión especificado.
•pmin

Valor mínimo de presión para que una muestra sea válida. Predeterminado: 1.

•pmax

Valor máximo de presión para que una muestra sea válida. Predeterminado: INT_MAX.

crop

Ignora los puntos táctiles fuera del framebuffer.

debounce

Mecanismo simple de debounce que descarta eventos de entrada durante el tiempo especificado después de que se ha detenido un gesto táctil.
•drop_threshold

descarta eventos hasta este número de milisegundos después del último evento de liberación. Predeterminado: 0.

skip

Omite nhead muestras después de la pulsación y ntail muestras antes de la liberación. Esto debería ayudar si para el dispositivo las primeras o últimas muestras no son fiables.
•nhead

Número de eventos a descartar después de la presión. Predeterminado: 1.

•ntail

Número de eventos a descartar antes de la liberación. Predeterminado: 1.

median

Similar a lo que hace el filtro de varianza, el filtro de mediana suprime picos en el gesto.
•depth

Número de muestras a las que aplicar el filtro de mediana. Predeterminado: 3.

invert

Invierte los valores en la dirección X y/o Y alrededor de un valor dado.
•x0

Valor del eje X (horizontal) alrededor del cual invertir. Predeterminado: 0.

•y0

Valor del eje Y (horizontal) alrededor del cual invertir. Predeterminado: 0.

lowpass

Filtro paso bajo de promediado exponencial simple.
•factor

Valores de punto flotante entre 0 y 1. Predeterminado: 0.4.

•threshold

Distancia mínima en x o y entre dos muestras para empezar a aplicar el filtro. Predeterminado: 2.

evthres

Número de muestras necesarias del dispositivo después de considerarse un toque válido. Este filtro descartará un toque si hay muy pocas muestras entre "abajo" y "arriba".
•N

Número mínimo de eventos necesarios entre "abajo" y "arriba". Predeterminado: 5.

variance

Intenta hacer lo mejor posible para filtrar el ruido aleatorio proveniente de los ADC de la pantalla táctil. Esto se logra limitando la velocidad de movimiento de la muestra a algún valor (por ejemplo, el lápiz no debería moverse más rápido que algún umbral).

Este es un filtro voraz, es decir, produce menos muestras en la salida de las que recibe en la entrada. **No hay soporte multitáctil** para este filtro.

•delta

Establece la distancia al cuadrado en unidades de pantalla táctil entre la posición anterior y la actual del lápiz (por ejemplo, (X2-X1)^2 + (Y2-Y1)^2). Esto define el criterio para determinar si dos muestras están cerca o lejos una de la otra.

Si la distancia entre la muestra anterior y la actual es grande, la muestra se marca como ruido potencial. Esto no significa aún que será descartada; si la siguiente lectura está cerca de ella, se considerará solo un evento de movimiento rápido regular, y pasará a la siguiente capa. Además, si la muestra después del ruido potencial está lejos de ambas muestras discutidas previamente, esto también se considera un evento de movimiento rápido y la muestra pasa al flujo de salida.

soporte de hardware


En Linux, use module_raw input si puede. Los otros módulos de acceso directo son controladores de espacio de usuario específicos del dispositivo. Si necesita alguno de ellos, habilítelo explícitamente al compilar tslib. La lista de módulos habilitados por defecto podría reducirse en el futuro. module_raw input también soporta multitáctil (MT).
