NOMBRE

tgtd - El Demonio de Destino SCSI

SINOPSIS

tgtd

tgtd [-C --control-port <ENTERO>] [-d --debug <ENTERO>] [-f --foreground] [-h --help] [--iscsi <...>]

DESCRIPCIÓN

Tgtd es un demonio de Destino SCSI. Se puede usar para proporcionar servicio de destino SCSI a una red. El servicio más común es iSCSI, pero también se admiten otros servicios.

TIPOS DE DISPOSITIVOS

Tgtd proporciona soporte tanto para la emulación como para el paso directo de dispositivos reales.

    Tgtd puede emular los siguientes tipos de dispositivos:
    disk       : Dispositivo de disco normal. Emula un disco duro SCSI.
    tape       : Dispositivo de cinta. Emula una unidad de cinta SCSI.
    cd         : Dispositivo de CD. Emula un grabador de DVD SCSI.
    changer    : Cambiador de medios. Emula el dispositivo cambiador para una biblioteca de cintas virtual o un jukebox de DVD.

OPCIONES

-d --debug <ENTERO>

Establecer a un valor distinto de cero para activar mensajes de depuración adicionales que se registrarán.

-f --foreground

Ejecutar el demonio en primer plano.

-h --help

Imprimir texto de ayuda en la pantalla.

-C --control-port <ENTERO>

Este comando se utiliza para especificar el puerto de control a utilizar para esta instancia de tgtd. Esto permite ejecutar múltiples instancias de TGTD en un host.

TGTADM tiene un argumento coincidente para controlar a qué instancia conectarse.

--iscsi <...>

Opciones específicas de iSCSI. Consulte la sección ISCSI a continuación para ver las opciones específicas de este frontend.

OPCIONES ISCSI

Estos parámetros se aplican solo al frontend iSCSI.

portal=<direccion-ip[:puerto]>

Esta opción se utiliza para enlazar tgtd a una dirección IP/portal y/o puerto específico. Por defecto, tgtd se enlazará al puerto 3260 en la dirección comodín. La parte de la dirección IP (antes de los ":") puede omitirse para designar la dirección comodín con un puerto no predeterminado.

Ejemplo: enlazar tgtd a una dirección y puerto específicos

	tgtd --iscsi portal=192.0.2.1:3260

Ejemplo: enlazar tgtd a cualquier dirección pero a un puerto no predeterminado

	tgtd --iscsi portal=:3251

nop_interval=<entero>

Esto establece el intervalo predeterminado para enviar NOP-OUT para sondear los iniciadores conectados. Este parámetro solo controla el valor predeterminado para los destinos. Los destinos individuales se pueden controlar usando tgtadm.

El valor predeterminado es 0, lo que significa que la función está desactivada. TGTD no enviará ninguna sonda NOP-OUT.

nop_count=<entero>

Esto establece el valor predeterminado de cuántas sondas fallidas deben ocurrir antes de que TGTD considere que el iniciador está muerto y cierre la sesión. Este parámetro solo controla el valor predeterminado para los destinos. Los destinos individuales se pueden controlar usando tgtadm.

El valor predeterminado es 0.

Ejemplo: enviar NOP-OUT cada 5 segundos y abortar la sesión después de 6 fallos.

	tgtd --iscsi portal=192.0.2.1:3260,nop_interval=5,nop_count=6

VARIABLES DE ENTORNO

TGT_IPC_SOCKET=<ruta>

Cuando se establece, tgtd y tgtadm utilizarán la ruta especificada como socket IPC en lugar de la predeterminada '/var/run/tgtd/socket.0'
