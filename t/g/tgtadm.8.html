NOMBRE

tgtadm - Utilidad de Administración de Destino SCSI de Linux

SINOPSIS

tgtadm [OPCIONES]... [-C --control-port <puerto>] [-L --lld <controlador>] [-o --op <operación>] [-m --modo <modo>] [-t --tid <id>] [-T --targetname <nombre_destino>] [-y --blocksize <tamaño>] [-Y --device-type <tipo>] [-l --lun <lun>] [-b --backing-store <ruta>] [-f --bsoflags {directo|sinc}] [-S --bsopts {opciones_de_almacenamiento_de_respaldo cadena>}] [-E --bstype <tipo>] [-I --initiator-address <dirección>] [-Q --initiator-name <nombre>] [-n --name <parámetro>] [-v --value <valor>] [-P --params <param=valor[,param=valor...]>] [-F --force] [-h --help]

DESCRIPCIÓN

tgtadm se utiliza para monitorizar y modificar todo sobre el software de destino SCSI de Linux: destinos, volúmenes, etc.

OPCIONES

-C, --control-port <puerto>

Es posible ejecutar múltiples instancias concurrentes de tgtd en un host. Este argumento se utiliza para controlar en qué instancia operará el comando tgtadm.

-y, --blocksize <tamaño>

Los dispositivos de bloque se crean con un tamaño de bloque predeterminado de 512 bytes. Este argumento se puede utilizar para crear dispositivos de bloque con diferentes tamaños de bloque.
Ejemplo:
tgtadm --lld iscsi --mode logicalunit --op new \
       --tid <TID> --lun <LUN> \
       -b <archivo_respaldo> --blocksize=4096

-Y, --device-type <tipo>

Al crear una LUN, este parámetro especifica el tipo de dispositivo que se creará. El valor predeterminado es disco.
Los tipos de dispositivo posibles son:
    disk    : emular un dispositivo de disco
    tape    : emular un lector de cinta
    ssc     : igual que tape
    cd      : emular una unidad de DVD
    changer : emular un dispositivo de cambiador de medios
    pt      : tipo de paso para exportar un dispositivo /dev/sg

-E, --bstype <tipo>

Al crear una LUN, este parámetro especifica el tipo de almacenamiento de respaldo que se utilizará.
Los tipos de respaldo posibles son:
    rdwr    : Usar E/S de archivo normal. Este es el valor predeterminado para dispositivos de disco
    aio     : Usar E/S asíncrona
    rbd     : Usar el dispositivo de bloque RADOS distribuido de Ceph
    sg      : Tipo de respaldo especial para dispositivos de paso
    ssc     : Tipo de respaldo especial para emulación de cinta

--lld <controlador> --op new --mode target --tid <id> --targetname <nombre>

Añadir un nuevo destino con <id> y <nombre>.

--lld <controlador> --op delete --mode target --tid <id>

Eliminar un destino específico con <id>. El destino no debe tener ningún nexus I_T activo.

--lld <controlador> --op delete --force --mode target --tid <id>

Eliminar un destino específico forzosamente con <id>.

--lld <controlador> --op show --mode target

Mostrar todos los destinos.

--lld <controlador> --op show --mode target --tid <id>

Mostrar los parámetros del destino de un destino con <id>.

--lld <controlador> --op new --mode logicalunit --tid <id> --lun <lun> --backing-store <ruta> --bsopts=<opciones_almacenamiento_respaldo>

Añadir una nueva unidad lógica con <lun> al destino específico con <id>. La unidad lógica se ofrece a los iniciadores. <ruta> debe ser un archivo de dispositivo de bloque (incluyendo dispositivos LVM y RAID) o archivos regulares, o un nombre de imagen o instantánea de RBD para --bstype rbd. lun0 está reservado para un dispositivo especial creado automáticamente. 
Ejemplo:
Si tgt está compilado con el respaldo de bs_rbd para
imágenes RBD de Ceph (ver tgtadm --mode system --op show para
verificar), configurar un destino que mapee la imagen rbd
llamada "rbdimage", y pasar opciones a bs_rbd:
tgtadm --lld iscsi --op new --mode logicalunit --tid 1 \
--lun 1 --bstype=rbd --backing-store=rbdimage \
--bsopts="conf=/etc/ceph/ceph.conf;id=tgt"

--lld <controlador> --op delete --mode logicalunit --tid <id> --lun <lun>

Eliminar la unidad lógica específica con <lun> que tiene el destino con <id>.

--lld <controlador> --op bind --mode target --tid <id> --initiator-address <dirección>

Añadir la dirección a las listas de acceso del destino con <id>. Los iniciadores con la dirección pueden acceder al destino. 'ALL' es una dirección especial para permitir que todos los iniciadores accedan a un destino.

--lld <controlador> --op bind --mode target --tid <id> --initiator-name <nombre>

Añadir el nombre del iniciador a las listas de acceso del destino con <id>. Los iniciadores con los nombres pueden acceder al destino.

--lld <controlador> --op unbind --mode target --tid <id> --initiator-address <dirección>

Eliminar la dirección de las listas de acceso del destino con <id>.

--lld <controlador> --op unbind --mode target --tid <id> --initiator-name <nombre>

Eliminar el nombre del iniciador de las listas de acceso del destino con <id>.

--lld <controlador> --op update --mode target --tid <id> --name=<parámetro> --value=<valor>

Cambiar el valor del <parámetro> del destino con <id> a <valor>.

--lld <controlador> --op update --mode target --tid <id> --params parameter=value<,...>

Establece/cambia el valor de uno o más parámetros del destino.

--lld <controlador> --op update --mode logicalunit --tid <id> --lun <id> --params parameter=value<,...>

Establece/cambia el valor de uno o más parámetros de la unidad lógica.

--lld <controlador> --op start --mode lld

Inicia el controlador lld especificado sin reiniciar el proceso tgtd. Se puede utilizar para inicializar el controlador lld en caso de que los módulos requeridos se cargaran después de que tgtd ya se hubiera ejecutado.

--help

Muestra una lista de opciones disponibles y sale.

PARÁMETROS DE LUN

Estos parámetros solo son aplicables para "--mode logicalunit".

vendor_id=<cadena>

Este parámetro establece la cadena de Identificación del Vendedor que una LUN informará en los datos de INQUIRY.

product_id=<cadena>

Este parámetro establece la cadena de Identificación del Producto que una LUN informará en los datos de INQUIRY.

product_rev=<cadena>

Este parámetro establece la cadena de Revisión del Producto que una LUN informará en los datos de INQUIRY.
Ejemplo:
tgtadm --lld iscsi --mode logicalunit --op update \
       --tid <TID> --lun <LUN> \
       --params vendor_id=TGTD,product_id=VirtualHD,product_rev=0103

removable=<0|1>

Esto se puede usar para anular/cambiar la configuración predeterminada del indicador de extraíble. Los dispositivos de disco tienen como valor predeterminado no extraíbles, mientras que los dispositivos de DVD y CINTA tienen como valor predeterminado extraíbles.

sense_format=<0|1>

Este indicador controla el formato de los datos de sentido que devolverá el dispositivo. 0 = Formato de sentido clásico, 1 = Formato de descriptor de soporte.

online=<0|1>

Esto controla si un dispositivo está en línea o no.

Los dispositivos están en línea de forma predeterminada cuando se crean, pero se pueden poner fuera de línea usando este parámetro. El comportamiento de los dispositivos fuera de línea depende del tipo de dispositivo. Un dispositivo MMC/DVD que está fuera de línea informará que no hay disco en la unidad, pero la unidad MMC/DVD en sí misma todavía puede ser comunicada. Todos los demás tipos de dispositivos fallarán todas las E/S con un código de sentido de No Listo.

Ejemplo:
tgtadm --lld iscsi --mode logicalunit --op update \
       --tid 1 --lun 1 \
       --params removable=1,sense_format=1,online=1

mode_page=<cadena-de-bytes>

Este parámetro se utiliza para establecer páginas de modo específicas para el dispositivo y la página de modo

NAME

tgtadm

utility to administer the TGT iSCSI target.

SYNOPSIS

tgtadm [--lld lld] [--op operation] [--mode mode] [--tid targetid] [--lun lunid] [--sid sessionid] [--cid connectionid] [--param name=value] [--name name] [--value value]

DESCRIPTION

The tgtadm utility is used to administer the TGT iSCSI target daemon (tgtd). It allows you to configure targets, LUNs, portals, and connections.

The following are the most common operations:

  • Show information about the target, LUNs, sessions, etc.
  • Add new targets, LUNs, etc.
  • Delete targets, LUNs, etc.
  • Update parameters for targets, LUNs, etc.

Most operations require the tgtadm utility to be run as root.

OPTIONS

--lld lld
Specifies the link layer discovery protocol to use. Currently, only iscsi is supported.
--op operation
Specifies the operation to perform. Valid operations include: show, new, delete, update.
--mode mode
Specifies the mode to operate on. Valid modes include: target, logicalunit, portal, conn, session, sys.
--tid targetid
Specifies the target ID to operate on. This is usually an integer assigned when the target is created.
--lun lunid
Specifies the LUN ID to operate on. This is usually an integer assigned when the LUN is created.
--sid sessionid
Specifies the session ID to operate on.
--cid connectionid
Specifies the connection ID to operate on.
--param name=value
Specifies parameters for an operation. The format is name=value.
--name name
Specifies the name of a system parameter to update.
--value value
Specifies the value of a system parameter to update.

LUN PARAMETERS

When creating a new logical unit (LUN) for a target, the following parameters can be specified using the --param option:

path=filename
The path to the backing storage file or block device.
type=cd/dvd|disk
The type of the storage device. Defaults to disk.
scsi_id=value
The SCSI Target Identifier for the LUN. Defaults to 0x00010001.
scsi_sn=value
The SCSI Serial Number for the LUN. Defaults to a random value.
Example:
tgtadm --lld iscsi --op new --mode logicalunit --tid 1 --lun 1 -p \
    path=/srv/tgt/disk.img,type=disk,scsi_id=0x1000001,scsi_sn=mySerial001

SMC SPECIFIC LUN PARAMETERS

Additional parameters for SMC devices (e.g., tape drives) can be set:

empty=true|false
Sets the media to be empty or not.
nocd=true|false
Sets the media to be not present or present.
Example:
tgtadm --lld iscsi --op update --mode logicalunit --tid 1 --lun 1 -P \
    empty=true,nocd=true

PASSTHROUGH DEVICES

Block devices can be used directly as LUNs. This is often referred to as a passthrough device.

Example:
tgtadm --lld iscsi --op new --mode logicalunit --tid 1 --lun 2 -p \
    path=/dev/sdb,type=disk

HEADER DIGEST AND DATA DIGEST

The TGTD can be configured to use header and data digests for iSCSI connections. This can be set either globally using the tgtd command-line or for individual targets using the tgtadm command.

The following parameters can be set for a target:

header_digest
Specifies the header digest method. Values can be CRC32C, None.
data_digest
Specifies the data digest method. Values can be CRC32C, None.
Example:
tgtadm --op update --mode target --tid 1 -n header_digest -v CRC32C
tgtadm --op update --mode target --tid 1 -n data_digest -v CRC32C

CHAP AUTHENTICATION

CHAP authentication can be enabled for targets. This requires setting up a CHAP secret for the target and providing credentials for initiators.

To set the CHAP username and secret for a target:

tgtadm --lld iscsi --op update --mode target --tid 1 -n chap_username -v myuser
tgtadm --lld iscsi --op update --mode target --tid 1 -n chap_secret -v mysecret

To enable CHAP authentication for a target:

tgtadm --lld iscsi --op update --mode target --tid 1 -n chap_enable -v Yes

To view CHAP settings for a target:

tgtadm --lld iscsi --op show --mode target
Target 1: iqn.ronnie.test
    System information:
        Driver: iscsi
        State: ready
        CHAP authentication: Yes
        CHAP username: myuser
    Account information:
        ronnie

NOP-OUT PROBES

TGTD can send NOP-OUT probes to connected initiators to determine when an initiator is dead and then automatically clear and tear down the TCP connection. This can either be set as a global default from the tgtd command-line or it can be set for individual targets using the tgtadm command.

Check the current NOP-OUT setting

The tgtadm command is used to view the current setting for if/when to send NOP-OUT probes to connected initiators.

If the target is configured to send NOP-OUT probes this will show up as two parameter lines in the target printout. If the target is not configured to send NOP-OUT these lines will not be printed at all.

tgtadm --lld iscsi --op show --mode target
Target 1: iqn.ronnie.test
    System information:
        Driver: iscsi
        State: ready
        Nop interval: 5
        Nop count: 5
    I_T nexus information:

Setting NOP-OUT for a target

The tgtadm command is used to change the NOP-OUT settings.

tgtadm --op update --mode target --tid 1 -n nop_count -v 5
tgtadm --op update --mode target --tid 1 -n nop_interval -v 5

ISCSI PORTALS

iSCSI portals can be viewed, added and removed at runtime.

List portals

This command is used to list the current iSCSI portals defined on the target:

tgtadm --lld iscsi --op show --mode portal
Portal: 10.1.1.101:3260,1
Portal: 127.0.0.1:3260,1

Add portal

This command is used to add a portal to the target :

tgtadm --lld iscsi --op new --mode portal --param portal=10.1.1.101:3260

Remove portal

This command is used to remove a portal from the target :

tgtadm --lld iscsi --op delete --mode portal --param portal=10.1.1.101:3260

ISCSI CONNECTIONS

iSCSI connections can be viewed and forced closed at runtime.

List all active connections for a target

This command is used to list the all the active iSCSI connections to the target with connection id, initiator name and ip address for the initiator :

tgtadm --lld iscsi --op show --mode conn --tid 1
Session: 2
    Connection: 0
        Initiator: iqn.2008-11.org.linux-kvm:
        IP Address: 127.0.0.1

Close an existing connection

This command is used to close an iSCSI connection. Note that forcibly closing iSCSI connections can lead to data-loss.

tgtadm --lld iscsi --op delete --mode conn --tid 1 --sid 2 --cid 0

ONLINE/OFFLINE STATUS

Tgtd LUNs can be in online or offline status. LUNs that are Offline behave slightly different depending on the device type. Offline devices behave as if there is no media available and any operations that access media will fail with an check-condition error.

Devices can not be set to Offline mode while there are "PREVENT ALLOW MEDIUM REMOVAL" locks on the device. Similarly media in Online devices can not be software ejected while there are such locks on the device (the 'eject' command will fail).

Show Online/Offline status

Finding the Online/Offline status of a LUN is done through the tgtd command. If "Prevent removal" is "Yes" this indicates that an application holds a "prevent media removal" lock on the device.

tgtadm --lld iscsi --mode target --op show
...
        LUN: 2
            Type: cd/dvd
            SCSI ID: IET     00010002
            SCSI SN: beaf12
            Size: 3432 MB, Block size: 1
            Online: Yes
            Removable media: Yes
            Prevent removal: Yes
...

Changing a LUN to Offline

A LUN is changed to Offline status using the tgtadm command. When devices are set Offline these devices will behave as if there is no media loaded into the drive.

Change a LUN to become offline. (no disk in the drive)

tgtadm --tid 1 --lun 2 --op update --mode logicalunit -P Online=No

ISNS PARAMETERS

iSNS configuration for a target is by using the tgtadm command.

iSNSServerIP

This specifies the IP address of the iSNS server. TGTD only supprots one iSNS server.
Example:
tgtadm --op update --mode sys --name iSNSServerIP --value 192.168.11.133

iSNS

This setting enables(on)/disables(off) iSNS.
Example:
tgtadm --op update --mode sys --name iSNS --value On

iSNSServerPort

This setting specifies the port to use for iSNS.
Example:
tgtadm --op update --mode sys --name iSNSServerPort --value 3205

iSNSAccessControl

Enable/disable access control for iSNS.
Example:
tgtadm --op update --mode sys --name iSNSAccessControl --value Off
