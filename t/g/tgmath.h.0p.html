NOMBRE

tgmath.h — macros genéricas de tipo

SINOPSIS

#include <tgmath.h>

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es involuntario. Este volumen de POSIX.1‐2017 se remite al estándar ISO C.

La cabecera <tgmath.h> incluirá las cabeceras <math.h> y <complex.h> y definirá varias macros genéricas de tipo.

De las funciones contenidas en las cabeceras <math.h> y <complex.h> sin sufijo f (float) o l (long double), varias tienen uno o más parámetros cuyo tipo real correspondiente es double. Para cada una de estas funciones, excepto modf(), j0(), j1(), jn(), y0(), y1(), y yn(), existirá una macro genérica de tipo correspondiente. Los parámetros cuyo tipo real correspondiente es double en la sinopsis de la función son parámetros genéricos. El uso de la macro invoca una función cuyo tipo real correspondiente y dominio de tipo se determinan por los argumentos de los parámetros genéricos.

El uso de la macro invoca una función cuyos parámetros genéricos tienen el tipo real correspondiente determinado de la siguiente manera:

*
Primero, si algún argumento para parámetros genéricos tiene el tipo long double, el tipo determinado es long double.
*
De lo contrario, si algún argumento para parámetros genéricos tiene el tipo double o es de tipo entero, el tipo determinado es double.
*
De lo contrario, el tipo determinado es float.

Para cada función sin sufijo en la cabecera <math.h> para la cual existe una función en la cabecera <complex.h> con el mismo nombre excepto por un prefijo c, la macro genérica de tipo correspondiente (para ambas funciones) tiene el mismo nombre que la función en la cabecera <math.h>. La macro genérica de tipo correspondiente para fabs() y cabs() es fabs().

Si al menos un argumento para un parámetro genérico es complejo, entonces el uso de la macro invoca una función compleja; de lo contrario, el uso de la macro invoca una función real.

Para cada función sin sufijo en la cabecera <math.h> sin un contraparte con prefijo c en la cabecera <complex.h>, excepto modf(), j0(), j1(), jn(), y0(), y1(), y yn(), la macro genérica de tipo correspondiente tiene el mismo nombre que la función. Estas macros genéricas de tipo son:

atan2() cbrt() ceil() copysign() erf() erfc() exp2() expm1() fdim() floor() fma() fmax() fmin() fmod() frexp() hypot() ilogb() ldexp() lgamma() llrint() llround() log10() log1p() log2() logb() lrint() lround() nearbyint() nextafter() nexttoward() remainder() remquo() rint() round() scalbln() scalbn() tgamma() trunc()

Si todos los argumentos para parámetros genéricos son reales, entonces el uso de la macro invoca una función real; de lo contrario, el uso de la macro resulta en comportamiento indefinido.

Para cada función sin sufijo en la cabecera <complex.h> que no sea una contraparte con prefijo c de una función en la cabecera <math.h>, la macro genérica de tipo correspondiente tiene el mismo nombre que la función. Estas macros genéricas de tipo son:

carg() cimag() conj() cproj() creal()

El uso de la macro con cualquier argumento real o complejo invoca una función compleja.

NAME

tgmath.h - type-generic math macros

SYNOPSIS

#include <tgmath.h>

DESCRIPTION

The <tgmath.h> header defines type-generic macros that allow a single mathematical function name to operate on arguments of different types. For each function that has multiple real-valued versions (e.g., sin(), sinf(), sinl()), and for each function that has both real-valued and complex-valued versions (e.g., carg(), cargf(), cargl()), a type-generic macro is provided. When the macro is invoked, it is expanded to the appropriate function call based on the types of the arguments.

The type-generic macros are defined in <tgmath.h>. When <tgmath.h> is included, the corresponding functions are not declared unless the appropriate <math.h> or <complex.h> header is also included. If both <math.h> and <complex.h> are included, and the corresponding functions are declared by both, the behavior is unspecified.

If the macro name is not specified in the following tables, the corresponding function is not specified by POSIX.1‐2017.

A function is specified with a synopsis using arguments of various types:

double sin(double);
float sinf(float);
long double sinl(long double);
double complex csin(double complex);
float complex csinf(float complex);
long double complex csinl(long double complex);

When sin is used as a type-generic macro, the compiler determines the type of the argument and expands to the appropriate function call. If the argument is of type double, it expands to sin(). If the argument is of type float, it expands to sinf(). If the argument is of type long double, it expands to sinl(). If the argument is of type double complex, it expands to csin(). If the argument is of type float complex, it expands to csinf(). If the argument is of type long double complex, it expands to csinl().

If there are multiple arguments that determine the type, the type is determined by the first argument that has a type specified in the synopsis.

If the arguments are of integer types, they are converted to double and the double version of the function is invoked.

If the type-generic macro is invoked with a complex type argument, and the corresponding complex function is not declared, the behavior is undefined.

The type-generic macros are:

Macros for Real Functions:

acos, asin, atan, atan2, ceil, cos,
cosh, exp, fabs, floor, fmod, frexp,
hypot, ldexp, log, log10, modf,
pow, sin, sinh, sqrt, tan, tanh

Macros for Real Functions (with different argument types):

remainder, remquo

Macros for Real Functions (with different return types):

exp2, expm1, fmax, fmin, ilogb,
log1p, log2, logb, nearbyint, nextafter,
nexttoward, round, scalb, scalbln,
tgamma

Macros for Complex Functions:

cabs, cacos, cacosh, carg, casin,
casinh, catan, catanh, cbrt, ccos,
ccosh, cexp, cimag, clog, conj,
copysign, cpow, cproj, creal, csin,
csinh, csqrt, ctan, ctanh

Macros for Argument or Return Type Determination:

For the following macros, the type is determined by the type of the first argument. If the first argument is an integer type, it is converted to double.

significand

Macros for Argument Type Determination (Complex only):

carg, cimag, conj, cproj, creal

Macros for Return Type Determination (Complex only):

cabs

Macros for Type Determination (Mixed Real and Complex):

If the argument is a real type, the real function is called. If the argument is a complex type, the complex function is called.

cbrt, exp2, expm1, ilogb, log1p,
log2, logb, pow, sqrt

Macros for Type Determination (Complex or Real):

If the argument is a real type, the real function is called. If the argument is a complex type, the complex function is called.

acos, asin, atan, atan2, cos,
cosh, exp, log, log10, sin,
sinh, tan, tanh

Macros for Type Determination (Mixed):

If the arguments are real types, the real function is called. If the arguments are complex types, the complex function is called. If one argument is real and the other is complex, the complex function is called after converting the real argument to complex.

cpow

Macros for Real Functions (Return type determined by argument type):

The type is determined by the type of the arguments. If the arguments are integer types, they are converted to double.

fmax, fmin, nextafter, nexttoward,
copysign, remainder

Type Determination for Specific Functions:

The type of the macro call is determined by the type of the arguments. If there are multiple arguments, the type is determined by the first argument whose type is specified in the synopsis.

If an argument is an integer type, it is converted to double.

If the arguments are of type float, the macro expands to the corresponding f-suffixed function.

If the arguments are of type long double, the macro expands to the corresponding l-suffixed function.

If the arguments are of type double, the macro expands to the function without a suffix.

If the arguments are of type double complex, the macro expands to the corresponding c-prefixed function.

If the arguments are of type float complex, the macro expands to the corresponding cf-prefixed function.

If the arguments are of type long double complex, the macro expands to the corresponding cl-prefixed function.

APPLICATION USAGE

The <tgmath.h> header should be included in place of <math.h> and/or <complex.h> when using the type-generic macros.

RATIONALE

Type-generic macros allow calling a function whose type is determined by the argument type, as is the case for C operators such as '+' and '*'. For example, with a type-generic cos() macro, the expression cos((float)x) will have type float. This feature enables writing more portably efficient code and alleviates need for awkward casting and suffixing in the process of porting or adjusting precision. Generic math functions are a widely appreciated feature of Fortran.

The only arguments that affect the type resolution are the arguments corresponding to the parameters that have type double in the synopsis. Hence the type of a type-generic call to nexttoward(), whose second parameter is long double in the synopsis, is determined solely by the type of the first argument.

The term ``type-generic'' was chosen over the proposed alternatives of intrinsic and overloading. The term is more specific than intrinsic, which already is widely used with a more general meaning, and reflects a closer match to Fortran's generic functions than to C++ overloading.

The macros are placed in their own header in order not to silently break old programs that include the <math.h> header; for example, with:

printf ("%e", sin(x))

modf(double, double *) is excluded because no way was seen to make it safe without complicating the type resolution.

The implementation might, as an extension, endow appropriate ones of the macros that POSIX.1‐2008 specifies only for real arguments with the ability to invoke the complex functions.

POSIX.1‐2008 does not prescribe any particular implementation mechanism for generic macros. It could be implemented simply with built-in macros. The generic macro for sqrt(), for example, could be implemented with:

#undef sqrt
#define sqrt(x) __BUILTIN_GENERIC_sqrt(x)

Generic macros are designed for a useful level of consistency with C++ overloaded math functions.

The great majority of existing C programs are expected to be unaffected when the <tgmath.h> header is included instead of the <math.h> or <complex.h> headers. Generic macros are similar to the ISO/IEC 9899:1999 standard library masking macros, though the semantic types of return values differ.

The ability to overload on integer as well as floating types would have been useful for some functions; for example, copysign(). Overloading with different numbers of arguments would have allowed reusing names; for example, remainder() for remquo(). However, these facilities would have complicated the specification; and their natural consistent use, such as for a floating abs() or a two-argument atan(), would have introduced further inconsistencies with the ISO/IEC 9899:1999 standard for insufficient benefit.

The ISO C standard in no way limits the implementation's options for efficiency, including inlining library functions.
