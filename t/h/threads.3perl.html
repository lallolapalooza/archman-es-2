threads(3perl) Guía de Programación para Perl threads(3perl)

NOMBRE

threads - Hilos basados en intérprete de Perl

VERSIÓN

Este documento describe la versión 2.43 de threads

ADVERTENCIA

Los "hilos basados en intérprete" proporcionados por Perl no son el sistema rápido y ligero para la multitarea que uno podría esperar o desear. Los hilos se implementan de una manera que los hace fáciles de usar incorrectamente. Pocas personas saben cómo usarlos correctamente o podrán brindar ayuda.

El uso de hilos basados en intérprete en perl está oficialmente desaconsejado.

SINOPSIS

use threads ('yield',
             'stack_size' => 64*4096,
             'exit' => 'threads_only',
             'stringify');
sub start_thread {
    my @args = @_;
    print('Hilo iniciado: ', join(' ', @args), "\n");
}
my $thr = threads->create('start_thread', 'argumento');
$thr->join();
threads->create(sub { print("Soy un hilo\n"); })->join();
my $thr2 = async { foreach (@archivos) { ... } };
$thr2->join();
if (my $err = $thr2->error()) {
    warn("Error del hilo: $err\n");
}
# Invocar hilo en contexto de lista (implícito) para que pueda devolver una lista
my ($thr) = threads->create(sub { return (qw/a b c/); });
# o especificar contexto de lista explícitamente
my $thr = threads->create({'context' => 'list'},
                          sub { return (qw/a b c/); });
my @resultados = $thr->join();
$thr->detach();
# Obtener el objeto de un hilo
$thr = threads->self();
$thr = threads->object($tid);
# Obtener el ID de un hilo
$tid = threads->tid();
$tid = $thr->tid();
$tid = "$thr";
# Dar a otros hilos la oportunidad de ejecutarse
threads->yield();
yield();
# Listas de hilos no desvinculados
my @hilos = threads->list();
my $num_hilos = threads->list();
my @corriendo = threads->list(threads::running);
my @esperando = threads->list(threads::joinable);
# Probar objetos de hilo
if ($thr1 == $thr2) {
    ...
}
# Gestionar el tamaño de la pila del hilo
$tamano_pila = threads->get_stack_size();
$tamano_antiguo = threads->set_stack_size(32*4096);
# Crear un hilo con un contexto y tamaño de pila específicos
my $thr = threads->create({ 'context'    => 'list',
                            'stack_size' => 32*4096,
                            'exit'       => 'thread_only' },
                          \&foo);
# Obtener el contexto del hilo
my $wantarray = $thr->wantarray();
# Comprobar el estado del hilo
if ($thr->is_running()) {
    sleep(1);
}
if ($thr->is_joinable()) {
    $thr->join();
}
# Enviar una señal a un hilo
$thr->kill('SIGUSR1');
# Salir de un hilo
threads->exit();

DESCRIPCIÓN

Desde Perl 5.8, la programación de hilos ha estado disponible utilizando un modelo llamado *hilos de intérprete*, que proporciona un nuevo intérprete de Perl para cada hilo y, por defecto, resulta en que no se comparte información de datos o estado entre hilos.

(Antes de Perl 5.8, *5005threads* estaba disponible a través de la API de "Thread.pm". Este modelo de hilos ha sido deprecado y se eliminó a partir de Perl 5.10.0).

Como se mencionó anteriormente, todas las variables son, por defecto, locales al hilo. Para usar variables compartidas, también necesitas cargar threads::shared:

use threads;
use threads::shared;

Al cargar threads::shared, debes "use threads" antes de "use threads::shared". ("threads" emitirá una advertencia si lo haces al revés).

Se recomienda encarecidamente habilitar los hilos mediante "use threads" lo antes posible en tu script.

Si es necesario, los scripts se pueden escribir para que se ejecuten tanto en Perls con hilos como sin ellos:

my $puede_usar_hilos = eval 'use threads; 1';
if ($puede_usar_hilos) {
    # Hacer el procesamiento usando hilos
    ...
} else {
    # Hacerlo sin usar hilos
    ...
}
$thr = threads->create(FUNCION, ARGUMENTOS)
Esto creará un nuevo hilo que comenzará la ejecución con la función de punto de entrada especificada y le dará la lista de *ARGUMENTOS* como parámetros. Devolverá el objeto de hilos correspondiente, o "undef" si la creación del hilo falló.

FUNCION puede ser el nombre de una función, una subrutina anónima o una referencia de código.

my $thr = threads->create('nombre_func', ...);
    # o
my $thr = threads->create(sub { ... }, ...);
    # o
my $thr = threads->create(\&func, ...);

El método "->new()" es un alias de "->create()".

$thr->join()
Esto esperará a que el hilo correspondiente complete su ejecución. Cuando el hilo finaliza, "->join()" devolverá el(los) valor(es) de retorno de la función de punto de entrada.

El contexto (vacío, escalar o lista) para el(los) valor(es) de retorno para "->join()" se determina en el momento de la creación del hilo.

# Crear hilo en contexto de lista (implícito)
my ($thr1) = threads->create(sub {
                                my @resultados = qw(a b c);
                                return (@resultados);
                             });
#   o (explícito)
my $thr1 = threads->create({'context' => 'list'},
                           sub {
                                my @resultados = qw(a b c);
                                return (@resultados);
                           });
# Recuperar resultados de lista del hilo
my @res1 = $thr1->join();
# Crear hilo en contexto escalar (implícito)
my $thr2 = threads->create(sub {
                                my $resultado = 42;
                                return ($resultado);
                             });
# Recuperar resultado escalar del hilo
my $res2 = $thr2->join();
# Crear un hilo en contexto vacío (explícito)
my $thr3 = threads->create({'void' => 1},
                           sub { print("Hola, mundo\n"); });
# Unir el hilo en contexto vacío (es decir, sin valor de retorno)
$thr3->join();

Llamar a "->join()" o "->detach()" en un hilo ya unido causará un error.

$thr->detach()
Hace que el hilo no sea unible y causa que cualquier valor de retorno eventual sea descartado. Cuando el programa sale, cualquier hilo desvinculado que todavía esté en ejecución se termina silenciosamente.

Si el programa sale sin que todos los hilos hayan sido unidos o desvinculados, se emitirá una advertencia.

Llamar a "->join()" o "->detach()" en un hilo ya desvinculado causará un error.

threads->detach()
Método de clase que permite a un hilo desvincularse.
threads->self()
Método de clase que permite a un hilo obtener su propio objeto threads.
$thr->tid()
Devuelve el ID del hilo. Los IDs de hilo son enteros únicos, siendo el hilo principal en un programa 0, e incrementando en 1 por cada hilo creado.
threads->tid()
Método de clase que permite a un hilo obtener su propio ID.
"$thr"
Si agregas la opción de importación "stringify" a tu declaración "use threads", entonces usar un objeto de hilos en una cadena o contexto de cadena (por ejemplo, como clave de hash) hará que su ID se use como valor: 
use threads qw(stringify);
my $thr = threads->create(...);
print("Hilo $thr iniciado\n");  # Imprime: Hilo 1 iniciado
threads->object($tid)
Esto devolverá el objeto threads para el hilo *activo* asociado con el ID de hilo especificado. Si $tid es el valor para el hilo actual, entonces esta llamada funciona igual que "->self()". De lo contrario, devuelve "undef" si no hay ningún hilo asociado con el TID, si el hilo está unido o desvinculado, si no se especifica ningún TID o si el TID especificado es undef.

YIELDING CPU TIME

threads->yield()
This is a suggestion to the OS to let this thread yield CPU time to other threads. What actually happens is highly dependent upon the underlying thread implementation.

You may do "use threads qw(yield)", and then just use yield() in your code.

threads->list()
threads->list(threads::all)
threads->list(threads::running)
threads->list(threads::joinable)
With no arguments (or using "threads::all") and in a list context, returns a list of all non-joined, non-detached threads objects. In a scalar context, returns a count of the same.

With a true argument (using "threads::running"), returns a list of all non-joined, non-detached threads objects that are still running.

With a false argument (using "threads::joinable"), returns a list of all non-joined, non-detached threads objects that have finished running (i.e., for which "->join()" will not block).

$thr1->equal($thr2)
Tests if two threads objects are the same thread or not. This is overloaded to the more natural forms: 
if ($thr1 == $thr2) {
    print("Threads are the same\n");
}
# or
if ($thr1 != $thr2) {
    print("Threads differ\n");
}

(Thread comparison is based on thread IDs.)

async BLOCK;
"async" creates a thread to execute the block immediately following it. This block is treated as an anonymous subroutine, and so must have a semicolon after the closing brace. Like "threads->create()", "async" returns a threads object.
$thr->error()
Threads are executed in an "eval" context. This method will return "undef" if the thread terminates normally. Otherwise, it returns the value of $@ associated with the thread's execution status in its "eval" context.
$thr->_handle()
This private method returns a pointer (i.e., the memory location expressed as an unsigned integer) to the internal thread structure associated with a threads object. For Win32, this is a pointer to the "HANDLE" value returned by "CreateThread" (i.e., "HANDLE *"); for other platforms, it is a pointer to the "pthread_t" structure used in the "pthread_create" call (i.e., "pthread_t *").

This method is of no use for general Perl threads programming. Its intent is to provide other (XS-based) thread modules with the capability to access, and possibly manipulate, the underlying thread structure associated with a Perl thread.

threads->_handle()
Class method that allows a thread to obtain its own handle.

EXITING A THREAD

The usual method for terminating a thread is to return() from the entry point function with the appropriate return value(s).

threads->exit()
If needed, a thread can be exited at any time by calling "threads->exit()". This will cause the thread to return "undef" in a scalar context, or the empty list in a list context.

When called from the main thread, this behaves the same as exit(0).

threads->exit(status)
When called from a thread, this behaves like "threads->exit()" (i.e., the exit status code is ignored).

When called from the main thread, this behaves the same as exit(status).

die()
Calling die() in a thread indicates an abnormal exit for the thread. Any $SIG{__DIE__} handler in the thread will be called first, and then the thread will exit with a warning message that will contain any arguments passed in the die() call.
exit(status)
Calling exit() inside a thread causes the whole application to terminate. Because of this, the use of exit() inside threaded code, or in modules that might be used in threaded applications, is strongly discouraged.

If exit() really is needed, then consider using the following:

threads->exit() if threads->can('exit');   # Thread friendly
exit(status);
use threads 'exit' => 'threads_only'
This globally overrides the default behavior of calling exit() inside a thread, and effectively causes such calls to behave the same as "threads->exit()". In other words, with this setting, calling exit() causes only the thread to terminate.

Because of its global effect, this setting should not be used inside modules or the like.

The main thread is unaffected by this setting.

threads->create({'exit' => 'thread_only'}, ...)
This overrides the default behavior of exit() inside the newly created thread only.
$thr->set_thread_exit_only(boolean)
This can be used to change the exit thread only behavior for a thread after it has been created. With a true argument, exit() will cause only the thread to exit. With a false argument, exit() will terminate the application.

The main thread is unaffected by this call.

threads->set_thread_exit_only(boolean)
Class method for use inside a thread to change its own behavior for exit().

The main thread is unaffected by this call.

THREAD STATE

The following boolean methods are useful in determining the state of a thread.

$thr->is_running()
Returns true if a thread is still running (i.e., if its entry point function has not yet finished or exited).
$thr->is_joinable()
Returns true if the thread has finished running, is not detached and has not yet been joined. In other words, the thread is ready to be joined, and a call to "$thr->join()" will not block.
$thr->is_detached()
Returns true if the thread has been detached.
threads->is_detached()
Class method that allows a thread to determine whether or not it is detached.

THREAD CONTEXT

As with subroutines, the type of value returned from a thread's entry point function may be determined by the thread's context: list, scalar or void. The thread's context is determined at thread creation. This is necessary so that the context is available to the entry point function via wantarray(). The thread may then specify a value of the appropriate type to be returned from "->join()".

Explicit context

Because thread creation and thread joining may occur in different contexts, it may be desirable to state the context explicitly to the thread's entry point function. This may be done by calling "->create()" with a hash reference as the first argument:

my $thr = threads->create({'context' => 'list'}, \&foo);
...
my @results = $thr->join();

In the above, the threads object is returned to the parent thread in scalar context, and the thread's entry point function "foo" will be called in list (array) context such that the parent thread can receive a list (array) from the "->join()" call. ('array' is synonymous with 'list'.)

Similarly, if you need the threads object, but your thread will not be returning a value (i.e., void context), you would do the following:

my $thr = threads->create({'context' => 'void'}, \&foo);
...
$thr->join();

The context type may also be used as the key in the hash reference followed by a true value:

threads->create({'scalar' => 1}, \&foo);
...
my ($thr) = threads->list();
my $result = $thr->join();

Implicit context

If not explicitly stated, the thread's context is implied from the context of the "->create()" call:

# Create thread in list context
my ($thr) = threads->create(...);
# Create thread in scalar context
my $thr = threads->create(...);
# Create thread in void context
threads->create(...);

$thr->wantarray()

This returns the thread's context in the same manner as wantarray().

threads->wantarray()

This returns the context of the main thread.

wantarray()

Clase método para devolver el contexto del hilo actual. Esto devuelve el mismo valor que ejecutar wantarray() dentro de la función de punto de entrada del hilo actual.

TAMAÑO_DE_LA_PILADE_HILOS

El tamaño por defecto de la pila por hilo para diferentes plataformas varía significativamente, y es casi siempre mucho mayor de lo que se necesita para la mayoría de las aplicaciones. En Win32, el makefile de Perl establece explícitamente la pila por defecto a 16 MB; en la mayoría de las otras plataformas, se utiliza el valor por defecto del sistema, que de nuevo puede ser mucho mayor de lo necesario.

Ajustando el tamaño de la pila para que refleje con mayor precisión las necesidades de su aplicación, puede reducir significativamente el uso de memoria de su aplicación y aumentar el número de hilos que se ejecutan simultáneamente.

Tenga en cuenta que en Windows, la granularidad de asignación del espacio de direcciones es de 64 KB, por lo tanto, establecer la pila más pequeña que eso en Win32 Perl no ahorrará más memoria.

threads->get_stack_size();
Devuelve el tamaño por defecto actual de la pila por hilo. El valor por defecto es cero, lo que significa que se está utilizando el tamaño de pila por defecto del sistema.
$size = $thr->get_stack_size();
Devuelve el tamaño de la pila para un hilo en particular. Un valor de retorno de cero indica que se utilizó el tamaño de pila por defecto del sistema para el hilo.
$old_size = threads->set_stack_size($new_size);
Establece un nuevo tamaño por defecto de pila por hilo y devuelve la configuración anterior.

Algunas plataformas tienen un tamaño mínimo de pila de hilos. Intentar establecer el tamaño de la pila por debajo de este valor generará una advertencia y se utilizará el tamaño mínimo de pila.

Algunas plataformas Linux tienen un tamaño máximo de pila. Establecer un tamaño de pila demasiado grande provocará que la creación de hilos falle.

Si es necesario, $new_size se redondeará al múltiplo más cercano del tamaño de página de memoria (generalmente 4096 u 8192).

Los hilos creados después de que se establezca el tamaño de la pila llamarán entonces a pthread_attr_setstacksize() (para plataformas pthreads), o proporcionarán el tamaño de la pila a CreateThread() (para Win32 Perl).

(Obviamente, esta llamada no afecta a ningún hilo existente en este momento.)

use threads ('stack_size' => VALUE);
Esto establece el tamaño por defecto de la pila por hilo al inicio de la aplicación.
$ENV{'PERL5_ITHREADS_STACK_SIZE'}
El tamaño por defecto de la pila por hilo puede establecerse al inicio de la aplicación mediante la variable de entorno "PERL5_ITHREADS_STACK_SIZE": 
PERL5_ITHREADS_STACK_SIZE=1048576
export PERL5_ITHREADS_STACK_SIZE
perl -e'use threads; print(threads->get_stack_size(), "\n")'

Este valor anula cualquier parámetro "stack_size" proporcionado a "use threads". Su propósito principal es permitir el establecimiento del tamaño de pila por hilo para aplicaciones con hilos heredadas.

threads->create({'stack_size' => VALUE}, FUNCTION, ARGS)
Para especificar un tamaño de pila particular para cualquier hilo individual, llame a "->create()" con una referencia a hash como primer argumento: 
my $thr = threads->create({'stack_size' => 32*4096},
                          \&foo, @args);
$thr2 = $thr1->create(FUNCTION, ARGS)
Esto crea un nuevo hilo ($thr2) que hereda el tamaño de la pila de un hilo existente ($thr1). Esto es un atajo para lo siguiente: 
my $stack_size = $thr1->get_stack_size();
my $thr2 = threads->create({'stack_size' => $stack_size},
                           FUNCTION, ARGS);

SEÑALIZACIÓN DE HILOS

Cuando las señales seguras están activas (el comportamiento por defecto - ver "Señales inseguras" para más detalles), entonces las señales pueden ser enviadas y actuadas por hilos individuales.

$thr->kill('SIG...');
Envía la señal especificada al hilo. Los nombres de señal y los números de señal (positivos) son los mismos que los soportados por kill(). Por ejemplo, 'SIGTERM', 'TERM' y (dependiendo del sistema operativo) 15 son argumentos válidos para "->kill()".

Devuelve el objeto de hilo para permitir el encadenamiento de métodos:

$thr->kill('SIG...')->join();

Los manejadores de señales deben configurarse en los hilos para las señales sobre las que se espera que actúen. Aquí tienes un ejemplo para *cancelar* un hilo:

use threads;
sub thr_func
{
    # Manejador de señales de 'cancelación' del hilo
    $SIG{'KILL'} = sub { threads->exit(); };
    ...
}
# Crea un hilo
my $thr = threads->create('thr_func');
...
# Señaliza al hilo para que termine, y luego sepáralo
# para que se limpie automáticamente
$thr->kill('KILL')->detach();

Aquí tienes otro ejemplo simplista que ilustra el uso de la señalización de hilos en conjunción con un semáforo para proporcionar capacidades rudimentarias de *suspensión* y *reanudación*:

use threads;
use Thread::Semaphore;
sub thr_func
{
    my $sema = shift;
    # Manejador de señales de 'suspensión/reanudación' del hilo
    $SIG{'STOP'} = sub {
        $sema->down();      # Hilo suspendido
        $sema->up();        # Hilo reanudado
    };
    ...
}
# Crea un semáforo y pásalo a un hilo
my $sema = Thread::Semaphore->new();
my $thr = threads->create('thr_func', $sema);
# Suspende el hilo
$sema->down();
$thr->kill('STOP');
...
# Permite que el hilo continúe
$sema->up();

ADVERTENCIA: La capacidad de señalización de hilos proporcionada por este módulo no envía realmente señales a través del sistema operativo. *Emula* señales a nivel de Perl de tal manera que los manejadores de señales se llaman en el hilo apropiado. Por ejemplo, enviar "$thr->kill('STOP')" no suspende realmente un hilo (o todo el proceso), pero sí provoca que se llame a un manejador $SIG{'STOP'} en ese hilo (como se ilustra anteriormente).

Como tal, las señales que normalmente no serían apropiadas para usar en el comando kill() (por ejemplo, "kill('KILL', $$)") están bien para usarlas con el método "->kill()" (de nuevo, como se ilustra anteriormente).

Correspondientemente, enviar una señal a un hilo no interrumpe la operación en la que el hilo está trabajando actualmente: la señal actuará después de que la operación actual se haya completado. Por ejemplo, si el hilo está *atascado* en una llamada de E/S, enviarle una señal no interrumpirá la llamada de E/S de tal manera que la señal se actúe de inmediato.

Enviar una señal a un hilo terminado/finalizado se ignora.

Hilo # terminado anormalmente: ...
Un hilo terminó de alguna manera que no sea simplemente regresar de su función de punto de entrada, o usando "threads->exit()". Por ejemplo, el hilo puede haber terminado debido a un error, o usando "die".
Usando el tamaño mínimo de pila de hilos de #

Fallo en la creación de hilos: pthread_attr_setstacksize(SIZE) devolvió 22

Si es necesario, las advertencias de hilos se pueden suprimir usando:

no warnings 'threads';

en el ámbito apropiado.

ERRORES

Esta Perl no fue compilada para soportar hilos
La copia particular de Perl que está intentando usar no fue compilada usando la opción de configuración "useithreads".

Tener soporte para hilos requiere que toda la Perl y todos los módulos XS en la instalación de Perl sean recompilados; no es solo una cuestión de añadir el módulo de hilos (es decir, las Perl con y sin hilos son binariamente incompatibles).

No se puede cambiar el tamaño de la pila de un hilo existente
El tamaño de la pila de los hilos existentes actualmente no se puede cambiar, por lo tanto, lo siguiente resulta en el error anterior: 
$thr->set_stack_size($size);
No se pueden señalar hilos sin señales seguras
Las señales seguras deben estar activas para usar el método de señalización "->kill()". Ver "Señales inseguras" para más detalles.
Nombre de señal no reconocido: ...
La copia particular de Perl que está intentando usar no soporta la señal especificada que se utiliza en una llamada "->kill()".

ERRORES Y LIMITACIONES

Antes de considerar publicar un informe de error, consulte, y posiblemente publique un mensaje en el foro de discusión para ver si lo que ha encontrado es un problema conocido.

Módulos seguros para hilos
Ver "Haciendo que su módulo sea seguro para hilos" en perlmod
Usar módulos no seguros para hilos
Desafortunadamente, es posible que encuentre módulos de Perl que no sean seguros para hilos. Por ejemplo, pueden hacer que el intérprete de Perl falle durante la ejecución o que se vuelque al terminar. Dependiendo del módulo y de los requisitos de su aplicación, puede ser posible sortear estas dificultades.

Si el módulo solo se usará dentro de un hilo, puede intentar cargar el módulo desde dentro de la función de punto de entrada del hilo usando "require" (e "import" si es necesario):

sub thr_func
{
    require Unsafe::Module
    # Unsafe::Module->import(...);
    ....
}

Si el módulo es necesario dentro del hilo principal, intente modificar su aplicación para que el módulo se cargue (nuevamente usando "require" y "->import()") después de que se hayan iniciado todos los hilos, y de tal manera que no se inicien otros hilos después.

Si lo anterior no funciona o no es adecuado para su aplicación, registre un informe de error en https://rt.cpan.org/Public/ contra el módulo problemático.

Consumo de memoria
En la mayoría de los sistemas, la creación y destrucción frecuente y continua de hilos puede provocar un crecimiento cada vez mayor en el consumo de memoria del intérprete de Perl. Si bien es fácil simplemente lanzar hilos y luego "->join()" o "->detach()", para aplicaciones de larga duración, es mejor mantener un grupo de hilos y reutilizarlos para el trabajo necesario, utilizando colas para notificar a los hilos sobre el trabajo pendiente. La distribución CPAN de este módulo contiene un ejemplo simple (examples/pool_reuse.pl) que ilustra la creación, el uso y el monitoreo de un grupo de hilos reutilizables.
Directorio de trabajo actual
En todas las plataformas excepto MSWin32, la configuración del directorio de trabajo actual se comparte entre todos los hilos, de modo que cambiarlo en un hilo (por ejemplo, usando chdir()) afectará a todos los hilos de la aplicación.

En MSWin32, cada hilo mantiene su propia configuración del directorio de trabajo actual.

Configuraciones regionales
Antes de Perl 5.28, las configuraciones regionales no se podían usar con hilos, debido a varias condiciones de carrera. A partir de esa versión, en sistemas que implementan funciones de configuración regional seguras para hilos, se pueden usar hilos, con algunas advertencias. Esto incluye Windows a partir de Visual Studio 2005, y sistemas compatibles con POSIX 2008. Ver "Operación multihilo" en perllocale.

Cada hilo (excepto el hilo principal) se inicia utilizando la configuración regional C. El hilo principal se inicia como todos los demás programas de Perl; ver "ENVIRONMENT" en perllocale. Puede cambiar las configuraciones regionales en cualquier hilo tantas veces como desee.

Si desea heredar la configuración regional del hilo padre, puede, en el padre, establecer una variable de la siguiente manera:

$foo = POSIX::setlocale(LC_ALL, NULL);

y luego pasar a threads->create() una subrutina que incluya $foo. Luego, en el hijo, dice

POSIX::setlocale(LC_ALL, $foo);

O puede usar las facilidades en threads::shared para pasar $foo; o si el entorno no ha cambiado, en el hijo, haga

POSIX::setlocale(LC_ALL, "");
Variables de entorno
Actualmente, en todas las plataformas excepto MSWin32, todas las llamadas al sistema (por ejemplo, usando system() o backticks) realizadas desde hilos utilizan la configuración de variables de entorno del hilo principal. En otras palabras, los cambios realizados en %ENV en un hilo no serán visibles en las llamadas al sistema realizadas por ese hilo.

Para sortear esto, establezca variables de entorno como parte de la llamada al sistema. Por ejemplo:

my $msg = 'hello';
system("FOO=$msg; echo \$FOO");   # Muestra 'hello' en STDOUT

En MSWin32, cada hilo mantiene su propio conjunto de variables de entorno.

Captura de señales
Las señales son capturadas por el hilo principal (ID de hilo = 0) de un script. Por lo tanto, configurar manejadores de señales en hilos para fines distintos de "SEÑALIZACIÓN DE HILOS" como se documenta anteriormente no logrará lo que se pretende.

Esto es especialmente cierto si se intenta capturar "SIGALRM" en un hilo. Para manejar alarmas en hilos, configure un manejador de señales en el hilo principal y luego use "SEÑALIZACIÓN DE HILOS" para transmitir la señal al hilo:

# Crear hilo con una tarea que puede caducar
my $thr = threads->create(sub {
    threads->yield();
    eval {
        $SIG{ALRM} = sub { die("Timeout\n"); };
        alarm(10);
        ...  # Hacer el trabajo aquí
        alarm(0);
    };
    if ($@ =~ /Timeout/) {
        warn("Tarea en hilo caducada\n");
    }
};
# Configurar manejador de señales para transmitir SIGALRM al hilo
$SIG{ALRM} = sub { $thr->kill('ALRM') };
... # El hilo principal continúa trabajando
Hilos padre-hijo
En algunas plataformas, puede que no sea posible destruir hilos padre mientras todavía existan hilos hijo.
Señales inseguras
Desde Perl 5.8.0, las señales se han vuelto más seguras en Perl al posponer su manejo hasta que el intérprete esté en un estado seguro. Ver "Señales Seguras" en perl58delta y "Señales Diferidas (Señales Seguras)" en perlipc para más detalles.

Las señales seguras son el comportamiento predeterminado, y el antiguo comportamiento de señalización inmediata e insegura solo está en efecto en las siguientes situaciones:

  • Perl se ha compilado con "PERL_OLD_SIGNALS" (ver "perl -V").
  • La variable de entorno "PERL_SIGNALS" se establece en "unsafe" (ver "PERL_SIGNALS" en perlrun).
  • Se utiliza el módulo Perl::Unsafe::Signals.

Si las señales inseguras están en efecto, el manejo de señales no es seguro para hilos, y el método de señalización "->kill()" no se puede usar.

Identidad de los objetos devueltos desde hilos
Cuando un valor se devuelve desde un hilo a través de una operación "join", el valor y todo lo que referencia se copia al hilo que se une, de manera muy similar a como se copian los valores al crear un hilo. Esto funciona bien para la mayoría de los tipos de valores, incluidos arreglos, hashes y subrutinas. La copia se aplica recursivamente a los elementos de arreglos, escalares de referencia, variables abarcadas por subrutinas y otros tipos de referencias.

Sin embargo, todo lo referenciado por el valor devuelto es una copia nueva en el hilo que se une, incluso si un objeto devuelto en el hilo hijo hubiera sido una copia de algo que existía previamente en el hilo padre. Después de unirse, el padre tendrá, por lo tanto, un duplicado de cada objeto de este tipo. Esto a veces importa, especialmente si el objeto se muta; esto puede importar especialmente para datos privados a los que una subrutina devuelta proporciona acceso.

Devolución de objetos bendecidos desde hilos
Devolver objetos bendecidos desde hilos no funciona. Dependiendo de las clases involucradas, puede ser posible sortear esto devolviendo una versión serializada del objeto (por ejemplo, usando Data::Dumper o Storable) y luego reconstituyéndolo en el hilo que se une. Si está usando Perl 5.10.0 o posterior, y si la clase admite objetos compartidos, puede pasarlos a través de colas compartidas.
Bloques END en hilos
Es posible agregar bloques END a hilos usando require o eval con el código apropiado. Estos bloques "END" se ejecutarán cuando el intérprete del hilo sea destruido (es decir, ya sea durante una llamada a "->join()", o al finalizar el programa).

Sin embargo, llamar a cualquier método de hilos en un bloque "END" de este tipo muy probablemente fallará (por ejemplo, la aplicación puede colgarse o generar un error) debido a los mutexes que se necesitan para controlar la funcionalidad dentro del módulo de hilos.

Por esta razón, el uso de bloques "END" en hilos está fuertemente desaconsejado.

Manos de directorios abiertos
En perl 5.14 y versiones posteriores, en sistemas que no son Windows que no admiten la función C "fchdir", los manejadores de directorios (ver opendir) no se copiarán a los nuevos hilos. Puede usar la variable "d_fchdir" en Config.pm para determinar si su sistema la admite.

En versiones anteriores de perl, el lanzamiento de hilos con manejadores de directorios abiertos hacía fallar el intérprete. [perl #75154] https://rt.perl.org/rt3/Public/Bug/Display.html?id=75154

Hilos desvinculados y destrucción global
Si el hilo principal sale mientras hay hilos desvinculados que todavía se están ejecutando, entonces la fase de destrucción global de Perl no se ejecuta porque de lo contrario ciertas estructuras globales que controlan la operación de los hilos y que se asignan en la memoria del hilo principal podrían destruirse antes de que se destruya el hilo desvinculado.

Si está utilizando algún código que requiere la ejecución de la fase de destrucción global para la limpieza (por ejemplo, eliminación de archivos temporales), entonces no utilice hilos desvinculados, sino que una todos los hilos antes de salir del programa.

Errores de Perl y la versión CPAN de threads

BUGS AND LIMITATIONS

•
Se han reportado fallos en versiones antiguas de Perl que causan condiciones de carrera y otros problemas al usar hilos. Estos pueden manifestarse incluso al usar la última versión de hilos de CPAN. No hay una solución alternativa para esto más que actualizar a la última versión de Perl.
•
Incluso con la última versión de Perl, se sabe que ciertas construcciones con hilos pueden generar mensajes de advertencia sobre escalares filtrados o escalares no referenciados. Sin embargo, tales advertencias son inofensivas y pueden ignorarse de forma segura.

Puede buscar informes de errores relacionados con hilos en https://rt.cpan.org/Public/. Si es necesario, envíe nuevos errores, problemas, parches, etc. a: https://rt.cpan.org/Public/Dist/Display.html?Name=threads
