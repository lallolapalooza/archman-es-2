NOMBRE

thermald - iniciar el demonio térmico de Linux

SINOPSIS

thermald [ OPCIONES ]

DESCRIPCIÓN

thermald es un demonio de Linux utilizado para prevenir el sobrecalentamiento de las plataformas. Este demonio monitorea la temperatura y aplica compensación utilizando los métodos de enfriamiento disponibles.

Por defecto, monitorea la temperatura de la CPU utilizando los sensores de temperatura digitales de CPU disponibles y mantiene la temperatura de la CPU bajo control, antes de que el HW tome acciones correctivas agresivas.

El demonio térmico busca sensores térmicos y controladores de enfriamiento térmico en el sysfs térmico de Linux (/sys/class/thermal) y construye una lista de sensores y controladores de enfriamiento. Cada uno de los sensores térmicos puede estar opcionalmente enlazado a un controlador de enfriamiento por los controladores del kernel. En este caso, el núcleo térmico del kernel de Linux puede tomar acciones directamente basándose en los puntos de activación de temperatura, para cada sensor y dispositivo de enfriamiento asociado. Por ejemplo, una temperatura de activación X en un sensor puede asociarse a un controlador de enfriamiento Y. Por lo tanto, cuando la temperatura del sensor = X, el controlador de enfriamiento "Y" se activa.

El demonio térmico permite cambiar esta relación o añadir una nueva a través de un archivo de configuración térmica (thermal-conf.xml). Este archivo se crea automáticamente (thermal-conf.xml.auto) y se utiliza, si la plataforma tiene una tabla de relaciones térmicas ACPI. Si no, esto debe configurarse manualmente.

Para la configuración manual, consulte la página del manual de thermal-conf.xml.

En algunas plataformas más nuevas, la creación automática del archivo de configuración la realiza una herramienta complementaria "dptfxtract". Esta herramienta se puede descargar desde "https://github.com/intel/dptfxtract". Se sugiere como parte del proceso de instalación, ejecutar dptfxtract.

Puede haber múltiples archivos de configuración. El usuario puede seleccionar un archivo de configuración a través de la opción -config-file para anular la selección predeterminada. La selección predeterminada elige uno de los archivos en el siguiente orden:

- /etc/thermald/thermal-conf.xml.auto

- /var/run/thermald/thermal-conf.xml.auto

- /etc/thermald/thermal-conf.xml

(*Asumiendo que se usa el prefijo de configuración=/ durante la compilación.)

Existe otra herramienta complementaria "ThermalMonitor", que presenta una interfaz gráfica. Esto permite el monitoreo de sensores y el cambio de puntos de activación térmicos para dar al usuario más control. El código fuente de "ThermalMonitor" es parte del código fuente de thermald en GitHub, en la carpeta tools.

OPCIONES

-h, --help
Muestra las opciones de ayuda.
--version
Imprime la versión de thermald y sale.
--no-daemon
No te conviertas en un demonio: El valor predeterminado es el modo demonio.
--loglevel=info
Severidad del registro: nivel info y superior.
--loglevel=debug
Severidad del registro: nivel debug y superior: Registro máximo.
--poll-interval
Intervalo de sondeo en segundos: Sondea los cambios de temperatura de la zona. Para deshabilitar el sondeo, establezca en cero. El sondeo solo se puede deshabilitar si los sensores de temperatura disponibles pueden notificar el cambio de temperatura de forma asíncrona.
--dbus-enable
Habilitar Dbus.
--exclusive-control
Actuar como controlador térmico exclusivo. Esto utilizará el gobernador del espacio de usuario para el sysfs térmico y tomará el control.
--ignore-cpuid-check
Ignorar la comprobación de cpuid para modelos de CPU compatibles.
--config-file
Especifica la ruta de thermal-conf.xml e ignora el thermal-conf.xml predeterminado.
--ignore-default-control
Ignorar el control de temperatura predeterminado de la CPU. Seguir estrictamente thermal-conf.xml o thermal-conf.xml.auto.
--workaround-enabled
Habilitar soluciones especiales para el límite de potencia RAPL MMIO y el desplazamiento TCC cada 30 segundos. Esto ayuda a deshabilitar RAPL MMIO cuando no se usa y ajustar el desplazamiento TCC en ciertas laptops Lenovo.
--disable-active-power
Deshabilitar la gestión activa de energía. Esto no establecerá límites de potencia activos usando RAPL MMIO. Esto puede resultar en un rendimiento restringido, si el sistema arranca con límites de potencia más bajos.
--adaptive
Usar tablas adaptativas DPTF cuando estén presentes. Esto ignorará la configuración de thermald a través de archivos xml.
--test-mode
Forzar el uso del modo adaptativo y salir si no es compatible, en lugar de reiniciar en modo no adaptativo. Esta opción es principalmente para desarrolladores.
--systemd
Asumir que thermald es iniciado por systemd. Esto evitará que se ejecute como demonio independientemente de la opción --no-daemon.
--ignore-critical-trip
Si la configuración definió un punto de temperatura crítica, que es demasiado bajo, esta opción evitará apagar el sistema al alcanzar este límite de temperatura.
