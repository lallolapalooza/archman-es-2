NOMBRE

thermal-conf.xml - Archivo de configuración para el demonio térmico

SINOPSIS

$(TDCONFDIR)/etc/thermald/thermal-conf.xml

DESCRIPCIÓN

thermal-conf.xml es un archivo de configuración para el demonio térmico. Se utiliza para configurar sensores térmicos, zonas y dispositivos de enfriamiento. La ubicación de este archivo depende de la opción de configuración utilizada durante el tiempo de compilación.

La terminología utilizada en este archivo se ajusta a la especificación "Advanced Configuration and Power Interface Specification". El modelo térmico ACPI se basa en regiones de plataforma conceptuales llamadas zonas térmicas que contienen físicamente dispositivos, sensores térmicos y controles de enfriamiento. Por ejemplo, una zona térmica puede ser una CPU o la tapa de un portátil. Una zona puede contener múltiples sensores para monitorear la temperatura. Un dispositivo de enfriamiento proporciona una interfaz para reducir la temperatura de un dispositivo de origen, lo que provoca un aumento de la temperatura. Un ejemplo de dispositivo de enfriamiento es un ventilador (FAN) o algún controlador de Linux que pueda limitar la velocidad del dispositivo de origen.

Una configuración de zona térmica incluye uno o más puntos de disparo (trip points). Un punto de disparo es una temperatura a la que se necesita activar un dispositivo de enfriamiento.

Un dispositivo de enfriamiento puede ser activo o pasivo. Un ejemplo de dispositivo activo es un ventilador (FAN), que no reducirá el rendimiento a costa de consumir más energía y ruido. Un dispositivo pasivo utiliza la limitación del rendimiento para controlar la temperatura. Además de los dispositivos de enfriamiento presentes en el sysfs térmico, los siguientes dispositivos de enfriamiento están integrados en thermald, que pueden usarse como tipos de dispositivos de enfriamiento válidos:

  • rapl_controller
  • intel_pstate
  • cpufreq
  • LCD

El sysfs térmico de Linux (/sys/class/thermal) proporciona una forma de representar la configuración ACPI por plataforma. El gobernador térmico del kernel utiliza estos datos para mantener bajo control las temperaturas de la plataforma. Pero existen algunas limitaciones que thermald intenta resolver. Por ejemplo:

  • Si los datos ACPI no están optimizados o tienen errores. En este caso, thermal-conf.xml se puede usar para corregir el comportamiento sin cambiar la BIOS.
  • Puede haber zonas térmicas expuestas por el sysfs térmico sin acciones de enfriamiento asociadas. En este caso, thermal-conf.xml se puede usar para vincular los dispositivos de enfriamiento a esas zonas.
  • El mejor método de enfriamiento puede no estar en el sysfs térmico. En este caso, thermal-conf.xml se puede usar para vincular una zona a un dispositivo de enfriamiento externo.
  • Especificar relaciones térmicas. Una zona puede ser influenciada por múltiples dispositivos de origen con diferentes grados. En este caso, thermal-conf.xml se puede usar para definir la influencia relativa para aplicar compensación.

FORMATO DEL ARCHIVO

El formato del archivo de configuración cumple con las especificaciones XML. Se define un conjunto de etiquetas para definir la plataforma, los sensores, las zonas, los dispositivos de enfriamiento y los puntos de disparo.

<ThermalConfiguration>
  <Platform>
    <Name>Nombre de plataforma de ejemplo</Name>
    <!-- UUID es opcional, si está presente se comparará. Tanto el nombre del producto
         como el UUID pueden contener comodín "*", que coincide con cualquier
         plataforma. -->
    <UUID>UUID de ejemplo</UUID>
    <!-- el formato del archivo de configuración cumple con las especificaciones XML.
         Se define un conjunto de etiquetas para definir la plataforma, los sensores,
         las zonas, los dispositivos de enfriamiento y los puntos de disparo. -->
    <ProductName>Nombre de producto de ejemplo</ProductName>
    <Preference>QUIET|PERFORMANCE</Preference>
    <!-- El modo Quiet solo usará el dispositivo de enfriamiento pasivo. "PERFORMANCE"
         solo seleccionará dispositivos activos. -->
    <ThermalSensors>
      <ThermalSensor>
        <!-- Nuevo sensor con un tipo y ruta -->
        <Type>ejemplo_sensor_1</Type>
        <Path>/alguna/ruta</Path>
        <AsyncCapable>0</AsyncCapable>
      </ThermalSensor>
      <ThermalSensor>
        <!-- Ya presente en el sysfs térmico, habilita esto o
             agrega/cambia la configuración. Por ejemplo, aquí indicamos
             que el sensor puede realizar eventos asíncronos para evitar sondeos. -->
        <Type>ejemplo_sensor_termico_sysfs</Type>
        <!-- Si es capaz de asincronía, entonces no necesitamos hacer sondeos. -->
        <AsyncCapable>1</AsyncCapable>
      </ThermalSensor>
    </ThermalSensors>
    <ThermalZones>
      <ThermalZone>
        <Type>Tipo de zona de ejemplo</Type>
        <TripPoints>
          <TripPoint>
            <SensorType>ejemplo_sensor_1</SensorType>
            <!-- Temperatura a la que se tomará una acción. -->
            <Temperature> 75000 </Temperature>
            <!-- max/passive/active. Si se especifica un tipo MAX,
                 el demonio usará control PID para limitar agresivamente
                 y evitar alcanzar esta temperatura. -->
            <type>max</type>
            <!-- SEQUENTIAL | PARALLEL. Cuando se viola la temperatura del punto de
                 disparo, se puede activar un número de dispositivos de enfriamiento.
                 Si el tipo de control es SEQUENTIAL, agotará el primer dispositivo de
                 enfriamiento antes de intentar el siguiente. -->
            <ControlType>SEQUENTIAL</ControlType>
            <CoolingDevice>
              <index>1</index>
              <type>ejemplo_dispositivo_enfriamiento</type>
              <!-- La influencia se usará para ordenar los dispositivos de enfriamiento.
                   El primer dispositivo de enfriamiento que se utilizará será el que tenga
                   la mayor influencia. -->
              <influence> 100 </influence>
              <!-- Retraso en el uso de este dispositivo de enfriamiento; esto también
                   toma algún tiempo para enfriar realmente una zona. -->
              <SamplingPeriod> 12 </SamplingPeriod>
              <!-- Establece un estado específico de este dispositivo de enfriamiento
                   cuando se viola este punto de disparo. -->
              <TargetState> 6 </TargetState>
            </CoolingDevice>
          </TripPoint>
        </TripPoints>
      </ThermalZone>
    </ThermalZones>
    <CoolingDevices>
      <CoolingDevice>
        <!-- El dispositivo de enfriamiento se puede especificar por un tipo y opcionalmente
             una ruta de sysfs. Si el tipo ya está presente en el sysfs térmico,
             no se necesita una ruta. La compensación puede usar min/max y tamaño de paso
             para enfriar el sistema progresivamente.
             El período de amortiguación (DebouncePeriod) se puede usar para forzar un período
             de espera para la acción. -->
        <Type>ejemplo_dispositivo_enfriamiento</Type>
        <MinState>0</MinState>
        <IncDecStep>10</IncDecStep>
        <ReadBack> 0 </ReadBack>
        <MaxState>50</MaxState>
        <DebouncePeriod>5000</DebouncePeriod>
        <!-- Si no hay parámetros PID, la compensación aumenta por pasos
             y exponencialmente (si un solo paso no es capaz de cambiar
             la tendencia).
             Alternativamente, se pueden especificar parámetros PID, entonces el siguiente
             paso usará cálculo PID utilizando las constantes PID proporcionadas. -->
        <PidControl>
          <kp>0.001</kp>
          <kd>0.0001</kd>
          <ki>0.0001</ki>
        </PidControl>
        <!-- Escribe un prefijo adjunto al valor del estado, como abajo,
             el prefijo es "level ". Preservará los espacios tal como se ingresaron
             al escribir en sysfs. -->
        <WritePrefix>level </WritePrefix>
      </CoolingDevice>
    </CoolingDevices>
  </Platform>
</ThermalConfiguration>

EJEMPLOS DE CONFIGURACIÓN

Ejemplo 1: Esta es una configuración muy simple para cambiar el límite pasivo de la CPU. En lugar del valor predeterminado, se utiliza esta nueva temperatura de 86 °C en la configuración. Esto comenzará a enfriar una vez que la temperatura alcance los 86 °C.

<?xml version="1.0"?>
<ThermalConfiguration>
  <Platform>
    <Name>Anular valor predeterminado pasivo de la CPU</Name>
    <ProductName>*</ProductName>
    <Preference>QUIET</Preference>
    <ThermalZones>
      <ThermalZone>
        <Type>cpu</Type>
        <TripPoints>
          <TripPoint>
            <Temperature>86000</Temperature>
            <type>passive</type>
          </TripPoint>
        </TripPoints>
      </ThermalZone>
    </ThermalZones>
  </Platform>
</ThermalConfiguration>
