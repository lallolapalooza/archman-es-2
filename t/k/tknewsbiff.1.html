TKNEWSBIFF(1) Manual de comandos generales TKNEWSBIFF(1)

NOMBRE

tknewsbiff - muestra una ventana cuando llega noticias

SINOPSIS

tknewsbiff [ servidor o archivo-de-configuración ]

INTRODUCCIÓN

tknewsbiff muestra una ventana cuando hay noticias no leídas en tus grupos de noticias favoritos y elimina la ventana después de que hayas leído las noticias. tknewsbiff opcionalmente puede reproducir un sonido, iniciar tu lector de noticias, etc.

SELECCIÓN DE GRUPOS DE NOTICIAS

Por defecto, el archivo de configuración ~/.tknewsbiff describe cómo se comporta tknewsbiff. La sintaxis sigue las reglas habituales de Tcl; sin embargo, incluso si no conoces Tcl, todas las configuraciones excepto las más esotéricas serán obvias.

Cada grupo de noticias (o conjunto de grupos de noticias) a vigilar se describe usando el comando "watch". Por ejemplo:

watch dc.dining
watch nist.*
watch comp.unix.wizard  -threshold 3
watch *.sources.*       -threshold 20

Para cada patrón de grupo de noticias, cualquier grupo de noticias que coincida y al que estés suscrito (según tu archivo newsrc) es elegible para ser reportado. Por defecto, tknewsbiff informa sobre el grupo de noticias si hay al menos un artículo no leído. El indicador "-threshold" cambia el umbral al siguiente número. Por ejemplo, "-threshold 3" significa que debe haber al menos tres artículos no leídos antes de que tknewsbiff informe sobre el grupo de noticias.

Si no se proporcionan comandos watch (o no existe un archivo de configuración), se vigilan todos los grupos a los que estás suscrito.

Para suprimir grupos de noticias que de otro modo serían reportados, usa el comando "ignore". Por ejemplo, lo siguiente coincide con todos los grupos de noticias comp.* y nist.* excepto nist.posix o los grupos .d (discusión):

watch comp.*
watch nist.*
ignore nist.posix.*
ignore *.d

El indicador "-new" describe un comando que se ejecutará cuando se informe por primera vez sobre un grupo de noticias con noticias no leídas. Por ejemplo, las siguientes líneas invocan el comando UNIX "play" para reproducir un sonido.

watch dc.dining -new "exec play /usr/local/sounds/yumyum.au"
watch rec.auto* -new "exec play /usr/local/sounds/vroom.au"

Puedes reducir la verbosidad de las acciones definiendo procedimientos. Por ejemplo, si tienes muchos indicadores -new que reproducen archivos de sonido, podrías definir un procedimiento de sonido. Esto permitiría que la especificación -new fuera mucho más corta.

proc play {sound} {
	exec play /usr/local/sounds/$sound.au
}
watch dc.dining -new "play yumyum"
watch rec.auto* -new "play vroom"

Como nota al margen, puedes poner un "&" al final de un comando "exec" para que los comandos se ejecuten de forma asíncrona. Sin embargo, probablemente no sea una buena idea hacer esto al reproducir archivos de sonido de todos modos.

"newsgroup" es una variable de solo lectura que contiene el nombre del grupo de noticias que se está reportando. Esto es útil cuando la acción se activa por un patrón. Por ejemplo, la siguiente línea podría ejecutar el nombre del grupo de noticias a través de un sintetizador de voz:

watch * -new {
	exec play herald.au
	exec speak "New news has arrived in $newsgroup."
}

El indicador "-display" describe un comando que se ejecutará cada vez que se informe sobre un grupo de noticias con noticias no leídas. El comando especial "display" es el comando por defecto. Programa que $newsgroup se escriba en la pantalla de tknewsbiff cuando se vuelva a escribir. Por ejemplo, al proporcionar explícitamente un indicador -display que omita el comando display, puedes deshabilitar la visualización de grupos de noticias que ya se informan a través de -new.

watch dc.dining -new {exec play yumyum.au} -display {}

Si deseas ejecutar una acción repetidamente y *aún así* mostrar el grupo de noticias de la manera predeterminada, invoca explícitamente el comando display a través del indicador -display. Por ejemplo:

watch *security* -display {
	exec play red-alert.au
	display
}

Las acciones asociadas con los indicadores -new y -display se ejecutan solo una vez para cada grupo de noticias coincidente. El comando ejecutado es el asociado con el primer patrón en el archivo de configuración que coincide y observa el umbral dado.

Cualquier comando que simplemente se liste en el archivo de configuración se ejecuta cada vez antes del bucle de actualización en tknewsbiff. El procedimiento reservado (pero definido por el usuario) "user" se ejecuta inmediatamente después de que los grupos de noticias se programan para ser escritos en la pantalla y antes de que se escriban realmente.

Por ejemplo, supongamos que aparecen artículos no leídos en varios grupos rec.auto y reproduces el mismo sonido para cada uno. Para evitar reproducir el sonido varias veces seguidas, haz que el comando -new simplemente establezca un indicador. En el procedimiento user, reproduce el sonido si el indicador está establecido (y luego restablece el indicador).

El procedimiento user también podría usarse para iniciar un lector de noticias. Esto evitaría la posibilidad de iniciar múltiples lectores de noticias solo porque múltiples grupos de noticias contenían artículos no leídos. (Por supuesto, se debería hacer una comprobación para asegurarse de que un lector de noticias no esté ya en ejecución).

MÁS VARIABLES

Las siguientes líneas de ejemplo muestran variables que pueden afectar el comportamiento de tknewsbiff

set delay          120
set server         news.nist.gov
set server_timeout 60
set newsrc         ~/.newsrc
set width          40
set height         20
set active_file    /usr/news/lib/active

tknewsbiff alterna entre la comprobación de noticias no leídas y el dormir (similar a muchos estudiantes universitarios). La variable "delay" describe cuántos segundos dormir.

La variable "server" nombra un servidor de noticias NNTP. El valor predeterminado es "news". La variable "server" solo se usa si la variable "active_file" no está establecida.

La variable "server_timeout" describe cuántos segundos esperar una respuesta del servidor antes de rendirse. -1 significa esperar para siempre o hasta que el servidor expire. El valor predeterminado es 60 segundos.

La variable "newsrc" describe el nombre de tu archivo .newsrc. Por defecto, tknewsbiff busca en tu directorio de inicio un archivo newsrc. Se utiliza un newsrc específico del servidor si se encuentra. Por ejemplo, si has configurado el servidor como "cubit.nist.gov", entonces tknewsbiff busca ~/.newsrc-cubit.nist.gov. (Esta es la convención de Emacs gnus, que es muy conveniente cuando lees noticias de múltiples servidores.) Si no hay un newsrc específico del servidor, tknewsbiff usa ~/.newsrc.

La variable "width" describe el ancho que tknewsbiff usará para mostrar información. Si los nombres de los grupos de noticias son lo suficientemente largos, se truncarán para que los recuentos de artículos aún se puedan mostrar. Puedes redimensionar manualmente la ventana para ver lo que se truncó. Sin embargo, si tu archivo de configuración establece la variable width, la ventana se restaurará a ese tamaño la próxima vez que tknewsbiff verifique si hay noticias no leídas y actualice su visualización.

La variable "height" describe la altura máxima que tknewsbiff usará para mostrar información. Si se informan menos grupos de noticias, tknewsbiff reducirá la ventana apropiadamente. Puedes redimensionar manualmente la ventana, pero si tu archivo de configuración establece la variable height, la ventana se restaurará a ese tamaño la próxima vez que tknewsbiff verifique si hay noticias no leídas y actualice su visualización.

La variable "active_file" describe el nombre del archivo activo de noticias. Si se establece, el archivo activo se lee directamente en preferencia a usar NNTP (incluso si la variable "server" está establecida). Esto es particularmente útil para probar nuevos archivos de configuración, ya que puedes editar un archivo activo falso y luego hacer clic en el botón 2 para ver inmediatamente cómo responde tknewsbiff (ver BOTONES a continuación).

Si la variable de entorno DOTDIR está establecida, su valor se utiliza como un directorio en el que encontrar todos los archivos ocultos en lugar de desde el directorio de inicio. En particular, esto afecta al archivo de configuración de tknewsbiff y al archivo .newsrc (suponiendo que la variable newsrc no esté establecida explícitamente).

VIGILANCIA DE DIFERENTES SERVIDORES DE NOTICIAS

Para vigilar múltiples servidores, ejecuta tknewsbiff varias veces. (Dado que necesitas diferentes archivos .newsrc y los servidores tienen diferentes grupos de noticias y números de artículos de todos modos, no tiene sentido intentar hacer esto en un solo proceso).

NAME

tknewsbiff

notify user of unread news

SYNOPSIS

tknewsbiff [ -display ] [ -delay ] [ -script ] [ config_file ]

INTRODUCTION

Tknewsbiff monitors newsgroups for new articles. When new articles are found, it pops up a window listing the newsgroups and the number of unread articles in each. It is written in Tcl/Tk, and thus should be quite portable.

Tknewsbiff can be used to notify you of new articles on a remote news server, or it can monitor the active file on a local machine. The former is the default.

Tknewsbiff has an associated configuration file, which is usually named .tknewsbiff in your home directory. This file can be used to customize the behavior of tknewsbiff. See the CONFIGURATION FILE section for more details.

SELECTING NEWSGROUPS

There are two ways to tell tknewsbiff which newsgroups to watch. Either by using the -watch and -ignore flags, or by setting up the watch and ignore lists in the configuration file.

The -watch flag takes a list of newsgroup patterns as arguments. All newsgroups that match any of these patterns will be watched. If no -watch flag is given, all newsgroups are watched by default.

The -ignore flag takes a list of newsgroup patterns as arguments. All newsgroups that match any of these patterns will be ignored. These patterns are checked *after* the -watch patterns. So if a newsgroup is matched by both -watch and -ignore, it will be watched.

Newsgroup patterns are strings that can contain the wildcard characters

`*" and `?". A `*" matches any sequence of zero or more characters, and a `?" matches any single character. Patterns are matched against the full newsgroup name.

For example:

tknewsbiff -watch '*comp.sources.*' -ignore '*.bugs'

This command will watch all newsgroups under comp.sources, except for those ending in .bugs.

If you use the command line flags, they override the settings in the configuration file.

MORE VARIABLES

The following variables can be set in the configuration file:

server
The news server to connect to. If not specified, tknewsbiff will try to guess from the NNTPSERVER environment variable, or use the default news server.
delay
The interval, in seconds, between checks for new news. Default is 600 (10 minutes).
watch
A Tcl list of newsgroup patterns to watch. Defaults to watching all newsgroups.
ignore
A Tcl list of newsgroup patterns to ignore. Defaults to an empty list.
display
A Tcl list of newsgroup patterns to display. If specified, only newsgroups matching these patterns will be shown in the pop-up window. This overrides watch and ignore.
newsrc
The name of the file to use for tracking read/unread articles. Defaults to ~/.newsrc.
newsrc_read
The name of the file to use for tracking read articles. If this variable is set, tknewsbiff will not modify the newsrc file. Instead, it will read the list of seen articles from newsrc_read. This is useful if you use another newsreader that updates your newsrc file.
active_file
The name of the active file to use. If not specified, tknewsbiff will try to read it from the server.
geometry
The geometry string for the pop-up window. Default is to let Tk decide.
title
The title of the pop-up window. Default is "tknewsbiff".
font
The font to use for the text in the pop-up window.
fg
bg
Foreground and background colors for the text in the pop-up window.

WATCHING DIFFERENT NEWS SERVERS

The news server to contact can be specified in a number of ways. You can specify it on the command line as the last argument. You can set the variable server in the configuration file. Or you can set the environment variable NNTPSERVER.

If you specify the server on the command line, it overrides the configuration file, which overrides the environment variable.

If you specify the server name as a path (e.g. /news/server), tknewsbiff will look for a configuration file named .tknewsbiff-server in your home directory. For example, if you run:

tknewsbiff /news/server

tknewsbiff will look for the configuration file ~/.tknewsbiff-server. The following two commands will both use that configuration file.

tknewsbiff server
tknewsbiff ~/.tknewsbiff-server

In both cases, the actual server to contact is set by the value of the server variable in the configuration file.

If no configuration file is found, the argument is used as the server to contact. This allows tknewsbiff to be run with no preparation whatsoever.

If the argument is the special keyword "active" (or ends in "/active"), it is used as the name of an active file. This is in turn used to initialize the variable "active_file" so that tknewsbiff reads from the active file directly rather than using NNTP.

Creating your own active file is a convenient way of testing your configuration file. For example, after running the following command, you can repeatedly edit your active file and trigger the update-now command (either by pressing button 2 or setting the delay variable very low) to see how tknewsbiff responds.

The active file must follow the format of a real active file. The format is one newsgroup per line. After the newsgroup name is the number of the highest article, the lowest article. Lastly is the letter y or m. m means the newsgroup is moderated. y means posting is allowed.

WINDOW

When unread news is found, a window is popped up. The window lists the names of the newsgroups and the number of unread articles in each (unless suppressed by the -display flag). When there is no longer any unread news, the window disappears (although the process continues to run).

BUTTONS

Button or key bindings may be assigned by bind commands. Feel free to change them. The default bind commands are:

bind .list <1> help
bind .list <2> update-now
bind .list <3> unmapwindow

By default button 1 (left) is bound to "help". The help command causes tknewsbiff to pop up a help window.

By default, button 2 (middle) is bound to "update-now". The update-now command causes tknewsbiff to immediately check for unread news. If your news server is slow or maintains a very large number of newsgroups, or you have a large number of patterns in your configuration file, tknewsbiff can take considerable time before actually updating the window.

By default, button 3 (right) is bound to "unmapwindow". The unmapwindow command causes tknewsbiff to remove the window from the display until the next time it finds unread news. (The mapwindow command causes tknewsbiff to restore the window.)

As an example, here is a binding to pop up an xterm and run rn when you hold down the shift key and press button 1 in the listing window.

bind .list <Shift-1> {
	exec xterm -e rn &
}

Here is a similar binding. However it tells rn to look only at the newsgroup that is under the mouse when you pressed it. (The "display_list" variable is described later in this man page.)

bind .list <Shift-1> {
	exec xterm -e rn [lindex $display_list [.list nearest %y]] &
}

OTHER COMMANDS AND VARIABLES

Built-in commands already mentioned are: watch, ignore, display, help, update-now, unmapwindow, and mapwindow.

Any Tcl and Tk command can also be given. In particular, the list of newsgroups is stored in the list widget ".list", and the scroll bar is stored in the scrollbar widget ".scroll". So for example, if you want to change the foreground and background colors of the newsgroup list, you can say:

.list config -bg honeydew1 -fg orchid2

These can also be controlled by the X resource database as well. However, the configuration file allows arbitrarily complex commands to be evaluated rather than simple assignments.

Certain Tcl/Tk commands can disrupt proper function of tknewsbiff. These will probably be obvious to anyone who knows enough to give these commands in the first place. As a simple example, the program assumes the font in the list box is of fixed width. The newsgroups will likely not align if you use a variable-width font.

The following variables are accessible and can be used for esoteric uses. All other variables are private. Private variables and commands begin with "_" so you don't need to worry about accidental collisions.

The array "db" is a database which maintains information about read and unread news. db($newsgroup,hi) is the highest article that exists. db($newsgroup,seen) is the highest article that you have read.

A number of lists maintain interesting information. "active_list" is a list of known newsgroups. "seen_list" is a list of newsgroups that have been seen so far as the -new and -display flags are being processed. "previous_seen_list" is "seen_list" from the previous cycle. "ignore_list" is the list of newsgroup patterns to ignore. "watch_list" is the list of newsgroup patterns to watch. "display_list" is the list of newsgroup will be displayed at the next opportunity.

UPDATING YOUR FILES

tknewsbiff automatically rereads your configuration file each time it wakes up to check for unread news. To force tknewsbiff to reread the file immediately (such as if you are testing a new configuration or have just modified your newsrc file), press button 2 in the display (see BUTTONS above).

CAVEATS

tknewsbiff defines the number of unread articles as the highest existing article minus the highest article that you've read. So if you've read the last article in the newsgroup but no others, tknewsbiff thinks there are no unread articles. (It's impossible to do any better by reading the active file and it would be very time consuming to do this more accurately via NNTP since servers provide no efficient way of reporting their own holes in the newsgroups.) Fortunately, this definition is considered a feature by most people. It allows you to read articles and then mark them "unread" but not have tknewsbiff continue telling you that they are unread.

UNWARRANTED CONCERNS

Your news administrator may wonder if many people using tknewsbiff severely impact an NNTP server. In fact, the impact is negligible even when the delay is very low. To gather all the information it needs, tknewsbiff uses a single NNTP query - it just asks for the active file. The NNTP server does no computation, formatting, etc, it just sends the file. All the interesting processing happens locally in the tknewsbiff program itself.
