CALLBACKS DE MANEJADOR DE EVENTOS

El entorno de aplicación Aqua/macOS define una serie de eventos adicionales a los que las aplicaciones deben responder. Estos eventos son mapeados por Tk a llamadas a comandos en el espacio de nombres ::tk::mac; a menos que se indique lo contrario, si el comando está ausente, no se realizará ninguna acción.

::tk::mac::DoScriptFile
El manejador de Apple Events predeterminado para AEDoScriptHandler. Este comando ejecuta un archivo Tcl cuando un AppleScript envía un comando "do script" a Wish con una ruta de archivo como parámetro.
::tk::mac::DoScriptText
El manejador de Apple Events predeterminado para AEDoScriptHandler. Este comando ejecuta código Tcl cuando un AppleScript envía un comando "do script" a Wish con código Tcl o un procedimiento Tcl como parámetro.
::tk::mac::ShowPreferences
El manejador de Apple Events predeterminado para kAEShowPreferences, "pref". El elemento de menú "Preferencias" del menú de la aplicación solo se habilita cuando este proc está definido. Típicamente este comando se usa para envolver un comando de preferencias propio específico, que muestra una ventana de preferencias. Algo como:
proc ::tk::mac::ShowPreferences {} {
    setPref
}
::tk::mac::OpenApplication
Si se define un proc con este nombre, este proc se activará cuando tu aplicación se abra inicialmente. Es el manejador de Apple Events predeterminado para kAEOpenApplication, "oapp".
::tk::mac::ReopenApplication
Si se define un proc con este nombre, es el manejador de Apple Events predeterminado para kAEReopenApplication, "rapp", el Apple Event enviado cuando tu aplicación se abre estando ya en ejecución (por ejemplo, al hacer clic en su icono en el Dock). Aquí hay un ejemplo que restaura una ventana minimizada al hacer clic en el icono del Dock:
proc ::tk::mac::ReopenApplication {} {
    if {[wm state .] eq "withdrawn"} {
        wm state . normal
    } else {
        wm deiconify .
    }
    raise .
}
::tk::mac::OpenDocument file...
Si se define un proc con este nombre, es el manejador de Apple Events predeterminado para kAEOpenDocuments, "odoc", el Apple Event enviado cuando se le pide a tu aplicación que abra uno o más documentos (por ejemplo, arrastrando y soltando sobre la app o abriendo un documento de un tipo asociado a la app). El proc debe tomar como argumentos las rutas a los archivos que se abrirán, así:
proc ::tk::mac::OpenDocument {args} {
    foreach f $args {my_open_document $f}
}
::tk::mac::PrintDocument file...
Si se define un proc con este nombre, es el manejador de Apple Events predeterminado para kAEPrintDocuments, "pdoc", el Apple Event enviado cuando se le pide a tu aplicación que imprima un documento. Toma una sola ruta de archivo absoluta como argumento.
::tk::mac::Quit
Si se define un proc con este nombre, es el manejador de Apple Events predeterminado para kAEQuitApplication, "quit", el Apple Event enviado cuando se le pide a tu aplicación que se cierre, por ejemplo, a través del elemento de menú "Quit" en el menú de la aplicación, el elemento de menú "Quit" en el menú del Dock, o durante un cierre de sesión/reinicio/apagado etc. Si no se define, se llama a exit en su lugar.
::tk::mac::OnHide
Si se define, se llama cuando tu aplicación recibe un evento kEventAppHidden, por ejemplo, a través del elemento de menú "Hide" en los menús de la aplicación o del Dock.
::tk::mac::OnShow
Si se define, se llama cuando tu aplicación recibe un evento kEventAppShown, por ejemplo, a través del elemento de menú "Show All" en el menú de la aplicación, o al hacer clic en el icono del Dock de una aplicación oculta.
::tk::mac::ShowHelp
Personaliza el comportamiento del menú de Ayuda de Apple; si este procedimiento no está definido, el elemento de menú de Ayuda "TuApp Help" específico de la plataforma realiza la acción Cocoa predeterminada de mostrar el Libro de Ayuda configurado en el Info.plist de la aplicación (o muestra una alerta si no está configurado ningún Libro de Ayuda).
::tk::mac::PerformService
Ejecuta un procedimiento Tcl llamado desde el menú "Services" de macOS en el elemento de menú de la aplicación. El elemento de menú "Services" permite la comunicación entre aplicaciones; los datos de una aplicación, como el texto seleccionado, se pueden enviar a otra aplicación para su procesamiento, por ejemplo, a Safari como elemento de búsqueda para Google, o a TextEdit para ser agregado a un archivo. Un ejemplo del proc está a continuación, y debe ser reescrito en un script de aplicación para su personalización:
proc ::tk::mac::PerformService {} {
    set data [clipboard get]
    $w insert end $data
}
Tenga en cuenta que el mecanismo para recuperar los datos es del portapapeles; no hay otra forma compatible de obtener los datos. Si el proceso de Servicios no es deseado, las claves NSServices se pueden eliminar del archivo Info.plist de la aplicación. El código subyacente que soporta este comando también permite que los widgets text, entry y ttk::entry accedan a servicios de otras aplicaciones a través del menú Services. La clave NSPortName en el archivo Info.plist de Wish está actualmente configurada como "Wish"; si un desarrollador cambia el nombre del ejecutable de Wish a algo
diferente, esta clave debe modificarse con el mismo nombre.
::tk::mac::LaunchURL URL...
Si se define, lanza una URL dentro de Tk. Esto se usaría si una aplicación Tk quisiera manejar una URL, como mostrar datos de un feed RSS, en lugar de lanzar una aplicación predeterminada para manejar la URL, aunque puede definirse como tal. Wish incluye un esquema de URL de ejemplo de "foo://" en la clave CFBundleURLSchemes de su archivo Info.plist; esto debe personalizarse para el esquema de URL específico que el desarrollador desee soportar.
::tk::mac::GetAppPath
Devuelve la ruta del archivo de la aplicación actual.

DIÁLOGOS ADICIONALES

Aqua/macOS define diálogos adicionales que las aplicaciones deben soportar.

::tk::mac::standardAboutPanel
Trae al frente el panel "Acerca de" estándar de Cocoa con la información rellenada desde los archivos del paquete de la aplicación. El panel muestra el icono de la aplicación y los valores asociados a las claves info.plist llamadas CFBundleName, CFBundleShortVersionString, NSAboutPanelOptionVersion y NSHumanReadableCopyright. Si un archivo llamado Credits.html o Credits.rtf existe en el directorio Resources del paquete, su contenido se mostrará en un cuadro de texto desplazable en la parte inferior del diálogo. Consulte la documentación para -[NSApplication orderFrontStandardAboutPanelWithOptions:] para más detalles. También se proporciona un "hook" para un diálogo de Acerca de personalizado. Si se define un proc Tcl llamado tkAboutDialog en el intérprete principal, ese procedimiento será llamado en lugar de abrir standardAboutPanel.

CONFIGURACIÓN DEL SISTEMA

Hay una serie de opciones de configuración globales adicionales que controlan los detalles de cómo Tk renderiza por defecto.

::tk::mac::useCompatibilityMetrics boolean
Preserva la compatibilidad con métricas antiguas de Tk/Aqua; establecer en false para un espaciado más nativo.
::tk::mac::CGAntialiasLimit limit
Establece el límite de suavizado; las líneas más finas que limit píxeles no se suavizarán. Entero, establecido en 0 por defecto, haciendo que todas las líneas se suavicen.
::tk::mac::antialiasedtext number
Establece texto con suavizado. Controla el suavizado de texto

::tk::mac::useThemedToplevel booleano
Establece las ventanas de nivel superior para que se dibujen con el fondo moderno grisáceo / pinstripe de Mac. Equivalente a configurar la ventana de nivel superior con “-background systemWindowHeaderBackground”, o a usar un ttk::frame.

COMANDOS DE SOPORTE

::tk::mac::iconBitmap nombre ancho alto -tipo valor
Renderiza iconos y mapas de bits nativos en aplicaciones Tk (incluyendo cualquier archivo de imagen legible por NSImage). Un nombre de mapa de bits nativo se interpreta de la siguiente manera (en orden):
  • nombre de icono incorporado predefinido de 32x32 (stop, caution, document, etc.)
  • nombre, tal como lo define tk::mac::iconBitmap
  • nombre de imagen de imagen NSImage nombrada
  • cadena de URL de imagen NSImage
  • nombre de tipo OSType de 4 caracteres del icono de IconServices

Los argumentos ancho y alto para tk::mac::iconBitmap definen las dimensiones de la imagen a crear, y -tipo debe ser uno de los siguientes:

-archivo
icono del archivo en la ruta dada
-tipoArchivo
icono del tipo de archivo dado
-tipoOs
icono del tipo de archivo OSType de 4 caracteres dado
-tipoSistema
icono para el tipo de archivo OSType de 4 caracteres de IconServices dado
-imagenNombrada
NSImage nombrada para el nombre dado
-archivoImagen
imagen en la ruta dada
