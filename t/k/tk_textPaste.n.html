Nombre en la línea de comandos: -tabs
Nombre en la base de datos: tabs
Clase en la base de datos: Tabs
Especifica un conjunto de tabulaciones para la ventana. El valor de la opción consiste en una lista de distancias en pantalla que dan las posiciones de las tabulaciones, cada una de las cuales es una distancia relativa al borde izquierdo del widget (excluyendo bordes, relleno, etc.). Cada posición puede ir seguida opcionalmente en el siguiente elemento de la lista de una de las palabras clave left, right, center o numeric, que especifica cómo justificar el texto relativo a la tabulación. Left es el valor predeterminado; hace que el texto que sigue al carácter de tabulación se posicione con su borde izquierdo en la posición de tabulación. Right significa que el borde derecho del texto que sigue al carácter de tabulación se posiciona en la posición de tabulación, y center significa que el texto se centra en la posición de tabulación. Numeric significa que el punto decimal en el texto se posiciona en la posición de tabulación; si no hay punto decimal, el dígito menos significativo del número se posiciona justo a la izquierda de la posición de tabulación; si no hay número en el texto, el texto se justifica a la derecha en la posición de tabulación. Por ejemplo, “-tabs {2c left 4c center}” crea tres tabulaciones con intervalos de dos centímetros; las dos primeras usan justificación a la izquierda y la tercera usa justificación al centro.

Si la lista de tabulaciones no tiene suficientes elementos para cubrir todas las tabulaciones en una línea de texto, Tk extrapola nuevas tabulaciones utilizando el espaciado y la alineación de la última tabulación de la lista. Las distancias de tabulación deben ser estrictamente positivas y deben aumentar siempre de una tabulación a la siguiente (si no, se produce un error). El valor de la opción -tabs puede ser anulado por opciones -tabs en las etiquetas.

Si no se especifica ninguna opción -tabs, o si se especifica como una lista vacía, Tk utiliza tabulaciones predeterminadas espaciadas cada ocho (tamaño promedio) caracteres. Para lograr un espaciado estándar diferente, por ejemplo, cada 4 caracteres, simplemente configure el widget con “-tabs "[expr {4 * [font measure $font 0]}] left" -tabstyle wordprocessor”.

DESCRIPCIÓN

El comando text crea una nueva ventana (dada por el argumento pathName) y la convierte en un widget de texto. Opciones adicionales, descritas anteriormente, pueden especificarse en la línea de comandos o en la base de datos de opciones para configurar aspectos del texto, como su color de fondo predeterminado y su relieve. El comando text devuelve el nombre de ruta de la nueva ventana.

Un widget de texto muestra una o más líneas de texto y permite que ese texto sea editado. Los widgets de texto admiten cuatro tipos diferentes de anotaciones en el texto, llamadas etiquetas, marcas, ventanas incrustadas o imágenes incrustadas. Las etiquetas permiten mostrar diferentes porciones del texto con diferentes fuentes y colores. Además, los comandos Tcl se pueden asociar con etiquetas para que los scripts se invoquen cuando ocurren acciones particulares, como pulsaciones de teclas y clics del ratón en rangos específicos del texto. Consulte TAGS más abajo para obtener más detalles.

La segunda forma de anotación consiste en marcadores flotantes en el texto llamados "marcas". Las marcas se utilizan para realizar un seguimiento de varias posiciones interesantes en el texto a medida que se edita. Consulte MARKS más abajo para obtener más detalles.

La tercera forma de anotación permite que ventanas arbitrarias se incrusten en un widget de texto. Consulte EMBEDDED WINDOWS más abajo para obtener más detalles.

La cuarta forma de anotación permite que imágenes Tk se incrusten en un widget de texto. Consulte EMBEDDED IMAGES más abajo para obtener más detalles.

El widget de texto también tiene un mecanismo incorporado de deshacer/rehacer. Consulte THE UNDO MECHANISM más abajo para obtener más detalles.

El widget de texto permite la creación de widgets pares. Estos son otros widgets de texto que comparten los mismos datos subyacentes (texto, marcas, etiquetas, imágenes, etc.). Consulte PEER WIDGETS más abajo para obtener más detalles.

ÍNDICES

Muchos de los comandos del widget para textos toman uno o más índices como argumentos. Un índice es una cadena utilizada para indicar un lugar particular dentro de un texto, como un lugar para insertar caracteres o un extremo de un rango de caracteres para eliminar. Los índices tienen la sintaxis

base modificador modificador modificador ...
Donde base da un punto de partida y los modificadores ajustan el índice desde el punto de partida (por ejemplo, mover hacia adelante o hacia atrás un carácter). Cada índice debe contener una base, pero los modificadores son opcionales. La mayoría de los modificadores (como se documenta a continuación) permiten un submodificador opcional. Los submodificadores válidos son any y display. Si el submodificador está abreviado, entonces debe ir seguido de un espacio en blanco, pero de lo contrario no necesita haber espacio entre el submodificador y el siguiente modificador. Típicamente, el submodificador display ajusta el significado del siguiente modificador para que se refiera a unidades visuales o no elididas en lugar de unidades lógicas, pero esto se explica para cada caso relevante a continuación. Finalmente, donde count se usa como parte de un modificador, puede ser positivo o negativo, por lo que “base - -3 líneas” es perfectamente válido (y equivalente a “base +3líneas”).

La base de un índice debe tener una de las siguientes formas:

línea.carácter
Indica el carácter'avo carácter de la línea línea. Las líneas se numeran a partir de 1 para la coherencia con otros programas UNIX que utilizan este esquema de numeración. Dentro de una línea, los caracteres se numeran a partir de 0. Si carácter es end, se refiere al carácter de nueva línea que termina la línea.
@x,y
Indica el carácter que cubre el píxel cuyas coordenadas x e y dentro de la ventana del texto son x e y.
end
Indica el final del texto (el carácter justo después de la última nueva línea).
marca
Indica el carácter justo después de la marca cuyo nombre es marca (consulte MARKS para obtener detalles).
etiqueta.first
Indica el primer carácter en el texto que ha sido etiquetado con etiqueta. Esta forma genera un error si actualmente no hay caracteres etiquetados con etiqueta.
etiqueta.last
Indica el carácter justo después del último carácter en el texto que ha sido etiquetado con etiqueta. Esta forma genera un error si actualmente no hay caracteres etiquetados con etiqueta.
nombreRuta
Indica la posición de la ventana incrustada cuyo nombre es nombreRuta. Esta forma genera un error si no existe una ventana incrustada con el nombre dado.
nombreImagen
Indica la posición de la imagen incrustada cuyo nombre es nombreImagen. Esta forma genera un error si no existe una imagen incrustada con el nombre dado.

Si la base pudiera coincidir con más de una de las formas anteriores, por ejemplo, si una marca y un nombreImagen tuvieran el mismo valor, entonces la forma anterior en la lista anterior tiene precedencia. Si los modificadores siguen al índice base, cada uno de ellos debe tener una de las formas que se enumeran a continuación. Las palabras clave como chars y wordend pueden abreviarse siempre que la abreviatura sea inequívoca.

MARCAS

La segunda forma de anotación en los widgets de texto es una marca. Las marcas se utilizan para recordar lugares particulares en un texto. Son algo así como etiquetas, en el sentido de que tienen nombres y se refieren a lugares en el archivo, pero una marca no está asociada con caracteres particulares. En cambio, una marca está asociada con el espacio entre dos caracteres. Solo se puede asociar una posición con una marca en un momento dado. Si se eliminan los caracteres alrededor de una marca, la marca permanecerá; simplemente tendrá nuevos caracteres vecinos. En contraste, si se eliminan los caracteres que contienen una etiqueta, la etiqueta ya no tendrá una asociación con los caracteres del archivo. Las marcas se pueden manipular con el comando de widget “pathName mark”, y sus ubicaciones actuales se pueden determinar utilizando el nombre de la marca como índice en los comandos del widget.

Cada marca también tiene una “gravedad”, que es left (izquierda) o right (derecha). La gravedad de una marca especifica qué sucede con la marca cuando se inserta texto en el punto de la marca. Si una marca tiene gravedad izquierda, entonces la marca se trata como si estuviera unida al carácter de su izquierda, por lo que la marca permanecerá a la izquierda de cualquier texto insertado en la posición de la marca. Si la marca tiene gravedad derecha, el nuevo texto insertado en la posición de la marca aparecerá a la izquierda de la marca (para que la marca permanezca en la posición más a la derecha). La gravedad de una marca por defecto es right.

El espacio de nombres para las marcas es diferente del de las etiquetas: el mismo nombre se puede usar tanto para una marca como para una etiqueta, pero se referirán a cosas diferentes.

Dos marcas tienen un significado especial. Primero, la marca insert está asociada con el cursor de inserción, como se describe en EL CURSOR DE INSERCIÓN más abajo. Segundo, la marca current está asociada con el carácter más cercano al ratón y se ajusta automáticamente para seguir la posición del ratón y cualquier cambio en el texto del widget (una excepción: current no se actualiza en respuesta a los movimientos del ratón si un botón del ratón está presionado; la actualización se pospondrá hasta que se suelten todos los botones del ratón). Ninguna de estas marcas especiales puede ser eliminada. Con la excepción de estas dos marcas especiales, todas las marcas se comparten entre los widgets de texto pares, y pueden ser manipuladas en igualdad de condiciones desde cualquier par.

VENTANAS EMBEBIDAS

La tercera forma de anotación en los widgets de texto es una ventana embebida. Cada anotación de ventana embebida hace que se muestre una ventana en un punto particular del texto. Puede haber cualquier número de ventanas embebidas en un widget de texto, y cualquier widget puede usarse como ventana embebida (sujeto a las reglas habituales de gestión de geometría, que requieren que la ventana de texto sea el padre de la ventana embebida o un descendiente de su padre).

La posición de la ventana embebida en la pantalla se actualizará a medida que el texto se modifique o se desplace, y se mapeará y desmapeará a medida que entre y salga del área visible del widget de texto. Cada ventana embebida ocupa un espacio de índice de una unidad en el widget de texto, y puede ser referida por el nombre de su ventana embebida o por su posición en el espacio de índice del widget. Si se elimina el rango de texto que contiene la ventana embebida, la ventana se destruye. De manera similar, si se destruye el widget de texto en su conjunto, se destruye la ventana.

UNDO MECHANISM

The text widget supports undo/redo capabilities. The user can configure whether the undo mechanism is enabled, and the maximum number of undo levels, with the -undo and -maxundo options, respectively. These options are set when the text widget is created. The undo mechanism is enabled by default, with 10000 levels of undo available. The modified flag is set true whenever the text widget's contents are changed by the user. The modified flag is reset true whenever the user performs an undo operation or a redo operation. In addition, the text widget will automatically disable undo/redo operations when the modified flag is set true by the user (via the edit undo or edit redo commands), until the flag has been reset again.

See below for the pathName edit widget command that controls the undo mechanism.

PEER WIDGETS

The text widget has a separate store of all its data concerning each line's textual contents, marks, tags, images and windows, and the undo stack.

While this data store cannot be accessed directly (i.e. without a text widget as an intermediary), multiple text widgets can be created, each of which present different views on the same underlying data. Such text widgets are known as peer text widgets.

As text is added, deleted, edited and coloured in any one widget, and as images, marks, tags are adjusted, all such changes will be reflected in all peers.

All data and markup is shared, except for a few small details. First, the sel tag may be set and configured (in its display style) differently for each peer. Second, each peer has its own insert and current mark positions (but all other marks are shared). Third, embedded windows, which are arbitrary other widgets, cannot be shared between peers. This means the -window option of embedded windows is independently set for each peer (it is advisable to use the -create script capabilities to allow each peer to create its own embedded windows as needed). Fourth, all of the configuration options of each peer (e.g. -font, etc) can be set independently, with the exception of -undo, -maxundo, -autoseparators (i.e. all undo, redo and modified state issues are shared).

Finally any single peer need not contain all lines from the underlying data store. When creating a peer, a contiguous range of lines (e.g. only lines 52 through 125) may be specified. This allows a peer to contain just a small portion of the overall text. The range of lines will expand and contract as text is inserted or deleted. The peer will only ever display complete lines of text (one cannot share just part of a line). If the peer's contents contracts to nothing (i.e. all complete lines in the peer widget have been deleted from another widget), then it is impossible for new lines to be inserted. The peer will simply become an empty shell on which the background can be configured, but which will never show any content (without manual reconfiguration of the start and end lines). Note that a peer which does not contain all of the underlying data store still has indices numbered from “1.0” to “end”. It is simply that those indices reflect a subset of the total data, and data outside the contained range is not accessible to the peer. This means that the command peerName index end may return quite different values in different peers. Similarly, commands like peerName tag ranges will not return index ranges outside that which is meaningful to the peer. The configuration options -startline and -endline may be used to control how much of the underlying data is contained in any given text widget.

Note that peers are really peers. Deleting the “original” text widget will not cause any other peers to be deleted, or otherwise affected.

See below for the pathName peer widget command that controls the creation of peer widgets.

ASYNCHRONOUS UPDATE OF LINE HEIGHTS

In order to maintain a responsive user-experience, the text widget calculates lines metrics (line heights in pixels) asynchronously. Because of this, some commands of the text widget may return wrong results if the asynchronous calculations are not finished at the time of calling. This applies to pathName count -ypixels and pathName yview.

Again for performance reasons, it would not be appropriate to let these commands always wait for the end of the update calculation each time they are called. In most use cases of these commands a more or less inaccurate result does not really matter compared to execution speed.

In case accurate result is needed (and if the text widget is managed by a geometry manager), one can resort to pathName sync and pathName pendingsync to control the synchronization of the view of text widgets.

The <<WidgetViewSync>> virtual event fires when the line heights of the text widget become obsolete (due to some editing command or configuration change), and again when the internal data of the text widget are back in sync with the widget view. The detail field (%d substitution) is either true (when the widget is in sync) or false (when it is not).

pathName sync, pathName pendingsync and <<WidgetViewSync>> apply to each text widget independently of its peers.

Examples of use:

## Example 1:
# immediately complete line metrics at any cost (GUI unresponsive)
$w sync
$w yview moveto $fraction
## Example 2:
# synchronously wait for up-to-date line metrics (GUI responsive)
# before executing the scheduled command, but don't block execution flow
$w sync -command [list $w yview moveto $fraction]
## Example 3:
# init
set yud($w) 0
proc updateaction w {
set ::yud($w) 1
# any other update action here...
}
# runtime, synchronously wait for up-to-date line metrics (GUI responsive)
$w sync -command [list updateaction $w]
vwait yud($w)
$w yview moveto $fraction
## Example 4:
# init
set todo($w) {}
proc updateaction w {
foreach cmd $::todo($w) {uplevel #0 $cmd}
set todo($w) {}
}
# runtime
lappend todo($w) [list $w yview moveto $fraction]
$w sync -command [list updateaction $w]
## Example 5:
# init
set todo($w) {}
bind $w <<WidgetViewSync>> {
if {%d} {
foreach cmd $todo(%W) {eval $cmd}
set todo(%W) {}
}
}
# runtime
if {![$w pendingsync]} {
$w yview moveto $fraction
} else {
lappend todo($w) [list $w yview moveto $fraction]
}

WIDGET COMMAND

The text command creates a new Tcl command whose name is the same as the path name of the text's window. This command may be used to invoke various operations on the widget. It has the following general form:

pathName option ?arg arg ...?
PathName is the name of the command, which is the same as the text widget's path name. Option and the args determine the exact behavior of the command. The following commands are possible for text widgets:
pathName bbox index
Returns a list of four elements describing the screen area of the character given by index. The first two elements of the list give the x and y coordinates of the upper-left corner of the area occupied by the character, and the last two elements give the width and height of the area. If the character is only partially visible on the screen, then the return value reflects just the visible part. If the character is not visible on the screen then the return value is an empty list.
pathName cget option
Returns the current value of the configuration option given by option. Option may have any of the values accepted by the text command.
pathName compare index1 op index2
Compares the indices given by index1 and index2 according to the relational operator given by op, and returns 1 if the relationship is satisfied and 0 if it is not. Op must be one of the operators <, <=, ==, >=, >, or !=. If op is == then 1 is returned if the two indices refer to the same character, if op is < then 1 is returned if index1 refers to an earlier character in the text than index2, and so on.
pathName configure ?option? ?value option value ...?
Query or modify the configuration options of the widget. If no option is specified, returns a list describing all of the available options for pathName (see Tk_ConfigureInfo for information on the format of this list). If option is specified with no value, then the command returns a list describing the one named option (this list will be identical to the corresponding sublist of the value returned if no option is specified). If one or more option-value pairs are specified, then the command modifies the given widget option(s) to have the given value(s); in this case the command returns an empty string. Option may have any of the values accepted by the text command.

Counts and returns the number of items between index1 and index2, where index1 refers to the first character that is counted and index2 refers to the first character that is not counted. The option argument determines what is counted. The following options are supported:
-displaylines
cuenta todas las líneas de visualización (es decir, contando una por cada vez que una línea se ajusta) desde la línea del primer índice hasta, pero sin incluir, la línea de visualización del segundo índice. Por lo tanto, si ambos están en la misma línea de visualización, se devolverá cero. Por definición, las líneas de visualización son visibles y, por lo tanto, esto solo cuenta porciones de líneas visibles reales.
-indices
cuenta todos los caracteres y ventanas o imágenes incrustadas (es decir, todo lo que cuenta en el espacio de índices del widget de texto), ya sea que estén omitidos o no.
-lines
cuenta todas las líneas lógicas (independientemente del ajuste) desde la línea del primer índice hasta, pero sin incluir, la línea del segundo índice. Por lo tanto, si ambos están en la misma línea, se devolverá cero. Las líneas lógicas se cuentan si están actualmente visibles (no omitidas) o no.

cuenta el número de píxeles horizontales desde el primer píxel del primer índice hasta (pero sin incluir) el primer píxel del segundo índice. cuenta el número de píxeles verticales desde el primer píxel del primer índice hasta (pero sin incluir) el primer píxel del segundo índice. Si ambos índices están en la misma línea de visualización, se devolverá cero. Para contar el número total de píxeles verticales en el widget de texto, usa “.text count -ypixels 1.0 end”, y para asegurar que esto esté actualizado, usa “.text count -update -ypixels 1.0 end”.

El comando devuelve un entero positivo o negativo que corresponde al número de elementos contados entre los dos índices. Se devuelve un entero por cada opción de conteo dada, por lo que se devuelve una lista si se suministró más de una opción. Por ejemplo, “.text count -xpixels -ypixels 1.3 4.5” es perfectamente válido y devolverá una lista de dos elementos.

pathName debug ?boolean?
Si se especifica boolean, debe tener uno de los valores verdaderos o falsos aceptados por Tcl_GetBoolean. Si el valor es verdadero, se activarán las comprobaciones de consistencia internas en el código B-tree asociado con los widgets de texto. Si boolean tiene un valor falso, las comprobaciones de depuración se desactivarán. En cualquier caso, el comando devuelve una cadena vacía. Si boolean no se especifica, el comando devuelve on u off para indicar si la depuración está activada o no. Hay un único interruptor de depuración compartido por todos los widgets de texto: activar o desactivar la depuración en cualquier widget la activa o desactiva para todos los widgets. Para widgets con grandes cantidades de texto, las comprobaciones de consistencia pueden causar una ralentización notable.

Cuando la depuración está activada, las rutinas de dibujo del widget de texto establecen las variables globales tk_textRedraw y tk_textRelayout a las listas de índices que se redibujan. Los valores de estas variables son probados por el conjunto de pruebas de Tk.

pathName delete index1 ?index2 ...?
Elimina un rango de caracteres del texto. Si se especifican tanto index1 como index2, elimina todos los caracteres que comienzan con el proporcionado por index1 y se detienen justo antes de index2 (es decir, el carácter en index2 no se elimina). Si index2 no especifica una posición posterior en el texto que index1, no se eliminan caracteres. Si index2 no se especifica, se elimina el único carácter en index1. Se ordenan y el texto se elimina desde el último rango hasta el primer rango para que el texto eliminado no cause efectos secundarios de desplazamiento de índice no deseados. Si se proporcionan varios rangos con el mismo índice de inicio, se utiliza el rango más largo. Si se proporcionan rangos superpuestos, se fusionarán en extensiones que no causen la eliminación de texto fuera de los rangos dados debido al texto desplazado durante la eliminación.

pathName search ?switches? patrón índice ?stopIndex?
Busca en el texto de pathName comenzando en índice un rango de caracteres que coincida con patrón. Si se encuentra una coincidencia, se devuelve el índice del primer carácter de la coincidencia como resultado; de lo contrario, se devuelve una cadena vacía. Se pueden especificar uno o más de los siguientes modificadores (o abreviaturas de los mismos) para controlar la búsqueda:
-forwards
La búsqueda procederá hacia adelante a través del texto, encontrando el primer rango coincidente que comience en o después de la posición dada por índice. Este es el valor predeterminado.
-backwards
La búsqueda procederá hacia atrás a través del texto, encontrando el rango coincidente más cercano a índice cuyo primer carácter esté antes de índice (no se permite que esté en índice). Tenga en cuenta que, por diversas razones, las búsquedas hacia atrás pueden ser sustancialmente más lentas que las búsquedas hacia adelante (particularmente cuando se usa -regexp), por lo que se recomienda que el código crítico para el rendimiento utilice búsquedas hacia adelante.
-exact
Utiliza coincidencia exacta: los caracteres del rango coincidente deben ser idénticos a los de patrón. Este es el valor predeterminado.
-regexp
Trata patrón como una expresión regular y coincide con ella contra el texto usando las reglas para expresiones regulares (ver el comando regexp y la página re_syntax para más detalles). La coincidencia predeterminada pasa automáticamente las opciones -lineanchor y -linestop al motor regexp (a menos que se use -nolinestop), de modo que ^$ coincida con el principio y el final de la línea, y ., [^ las secuencias nunca coincidirán con el carácter de nueva línea \n.
-nolinestop
Esto permite que las secuencias . y [^ coincidan con el carácter de nueva línea \n, lo cual de lo contrario no harán (ver el comando regexp para más detalles). Esta opción solo tiene sentido si -regexp también se especifica, de lo contrario se generará un error. Por ejemplo, para coincidir con todo el texto, use “pathName search -nolinestop -regexp ".*" 1.0”.
-nocase
Ignora las diferencias de mayúsculas y minúsculas entre el patrón y el texto.
-count nombreVar
El argumento que sigue a -count da el nombre de una variable; si se encuentra una coincidencia, el número de posiciones de índice entre el principio y el final del rango coincidente se almacenará en la variable. Si no hay imágenes o ventanas incrustadas en el rango coincidente (y no hay caracteres omitidos si no se da -elide), esto es equivalente al número de caracteres coincidentes. En cualquier caso, el rango matchIdx a matchIdx + $count chars devolverá todo el texto coincidente.
-all
Encuentra todas las coincidencias en el rango dado y devuelve una lista de los índices del primer carácter de cada coincidencia. Si se da un modificador -count nombreVar, entonces nombreVar también se establece en una lista que contiene un elemento por cada coincidencia exitosa. Tenga en cuenta que, incluso para búsquedas exactas, los elementos de esta lista pueden ser diferentes, si hay imágenes, ventanas o texto oculto incrustados. Las búsquedas con -all se comportan de manera muy similar al comando Tcl regexp -all, en el sentido de que las coincidencias superpuestas normalmente no se devuelven. Por ejemplo, aplicar una búsqueda -all del patrón “\w+” contra “hello there” solo coincidirá dos veces, una por cada palabra, y coincidir “Z[a-z]+Z” contra “ZooZooZoo” solo coincidirá una vez.
-overlap
Al realizar búsquedas -all, el comportamiento normal es que las coincidencias que se superponen a una coincidencia ya encontrada no se devuelven. Este modificador cambia ese comportamiento para que se devuelvan todas las coincidencias que no están completamente incluidas dentro de otra coincidencia. Por ejemplo, aplicar una búsqueda -overlap del patrón “\w+” contra “hello there” solo coincidirá dos veces (es decir, no hay diferencia con solo -all), pero coincidir “Z[a-z]+Z” contra “ZooZooZoo” ahora coincidirá dos veces. Se generará un error si este modificador se usa sin -all.
-strictlimits
Al realizar cualquier búsqueda, el comportamiento normal es que los límites de inicio y fin se verifican con respecto al inicio del texto coincidente. Con la bandera -strictlimits, todo el rango coincidente debe estar dentro de los límites de inicio y fin especificados para que la coincidencia sea válida.
-elide
Busca también texto omitido (oculto). Por defecto, solo se busca texto mostrado.
--
Este modificador no tiene ningún efecto excepto terminar la lista de modificadores: el siguiente argumento se tratará como patrón incluso si comienza con -.

El rango coincidente puede estar dentro de una sola línea de texto, o abarcar varias líneas (si partes del patrón pueden coincidir con una nueva línea). Para la coincidencia de expresiones regulares, se pueden usar las diversas características de coincidencia de nueva línea, como $ para coincidir con el final de una línea, ^ para coincidir con el principio de una línea, y para controlar si . puede coincidir con una nueva línea. Si se especifica stopIndex, la búsqueda se detiene en ese índice: para búsquedas hacia adelante, no se considerará ninguna coincidencia en o después de stopIndex; para búsquedas hacia atrás, no se considerará ninguna coincidencia anterior a stopIndex en el texto. Si se omite stopIndex, se buscará en todo el texto: cuando se llega al principio o al final del texto, la búsqueda continúa en el otro extremo hasta que se vuelve a alcanzar la ubicación de inicio; si se especifica stopIndex, no ocurrirá ninguna envoltura. Esto significa que, por ejemplo, si la búsqueda es -forwards pero stopIndex está antes en el texto que startIndex, nunca se encontrará nada. ISSUES CONOCIDOS

ISSUES RELACIONADOS CON CARACTERES E INDICES

Antes de Tk 8.5, el widget usaba la cadena “chars” para referirse a posiciones de índice (que incluían caracteres, ventanas incrustadas e imágenes incrustadas). A partir de Tk 8.5, el widget de texto maneja por separado y correctamente “chars” e “indices”. Sin embargo, por compatibilidad hacia atrás, los modificadores de índice “+N chars” y “-N chars” continúan refiriéndose a índices. Se deben usar cualquiera de las formas completas “+N any chars” o “-N any chars”, etc. para referirse a índices de caracteres reales. Esta confusión puede ser corregida en una futura versión haciendo que el widget interprete correctamente “+N chars” como un sinónimo de “+N any chars”.

ISSUES DE RENDIMIENTO

Los widgets de texto deben ejecutarse eficientemente bajo una variedad de condiciones. El widget de texto utiliza aproximadamente 2-3 bytes de memoria principal por cada byte de texto, por lo que textos que contengan un megabyte o más deberían ser prácticos en la mayoría de las estaciones de trabajo. El texto se representa internamente con una estructura de árbol B modificada que hace que las operaciones sean relativamente eficientes incluso con textos grandes. Las etiquetas se incluyen en la estructura del árbol B de tal manera que permite que las etiquetas abarquen rangos grandes o tengan muchos rangos pequeños y disjuntos sin pérdida de eficiencia. Las marcas también se implementan de tal manera que permite un gran número de marcas. En la mayoría de los casos, está bien tener grandes cantidades de etiquetas únicas, o una etiqueta que tenga muchos rangos distintos.

Un problema de rendimiento puede surgir si tiene cientos o miles de etiquetas diferentes que comparten las siguientes características: los rangos primero y último de cada etiqueta están cerca del principio y del final del texto, respectivamente, o un único rango de etiqueta cubre la mayor parte del widget de texto. El costo de agregar y eliminar etiquetas como estas es proporcional al número de otras etiquetas con las mismas propiedades. En contraste, no hay problema en tener miles de etiquetas distintas si sus rangos generales están localizados y distribuidos uniformemente por todo el texto.

Las líneas de texto muy largas pueden ser costosas, especialmente si tienen muchas marcas y etiquetas dentro de ellas.

La línea de visualización con el cursor de inserción se redibuja cada vez que el cursor parpadea, lo que provoca un flujo constante de tráfico gráfico. Establezca el atributo -insertofftime a 0 para evitar esto.

BUGS CONOCIDOS

El subcomando pathName search -regexp intenta realizar una coincidencia de expresiones regulares sofisticada a través de múltiples líneas de manera eficiente (desde Tk 8.5), examinando cada línea individualmente y luego en pequeños grupos de líneas, ya sea buscando hacia adelante o hacia atrás. Bajo ciertas condiciones, el resultado de la búsqueda puede diferir del obtenido al aplicar la misma expresión regular a todo el texto del widget de una sola vez. Por ejemplo, al buscar con una expresión regular codiciosa, el widget continuará intentando agregar líneas adicionales a la coincidencia siempre que se cumpla una de dos condiciones: o bien la biblioteca de expresiones regulares de Tcl devuelve un código que indica que es posible una coincidencia más larga (pero existen errores conocidos en Tcl que implican que este código no siempre se devuelve correctamente); o si cada línea adicional agregada resulta en al menos una coincidencia parcial con el patrón. Esto significa que en el caso en que la primera línea adicional agregada no produzca una coincidencia y el sistema de expresiones regulares de Tcl devuelva el código incorrecto y agregar una segunda línea adicional sí coincidiría, el widget de texto devolverá el resultado incorrecto. En la práctica, este es un problema raro, pero puede ocurrir, por ejemplo:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\ncccc\nbbbb\naaaa\n"
.t search -regexp -- {(a+|b+\nc+\nb+)+\na+} 1.0
no encontrará una coincidencia cuando existe una de 19 caracteres que comienza con el primer “b”.

Siempre que una posible coincidencia esté completamente contenida dentro de otra, el comando de búsqueda intentará asegurar que solo se devuelva la coincidencia más grande. Al realizar búsquedas de expresiones regulares hacia atrás, es posible que Tcl no siempre logre esto, en el caso en que una coincidencia sea precedida por una o más coincidencias cortas y no superpuestas, todas ellas precedidas por una coincidencia grande que realmente las abarca a todas. El algoritmo de búsqueda utilizado por el widget no retrocede arbitrariamente en busca de una posible coincidencia que podría cubrir grandes porciones del widget. Por ejemplo:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\nbbbb\nbbbb\nbbbb\n"
.t search -regexp -backward -- {b+\n|a+\n(b+\n)+} end
coincide en “5.0” cuando una coincidencia verdaderamente codiciosa coincidiría en “1.0”. De manera similar, si agregamos -all a este caso, coincide en todos los “5.0”, “4.0”, “3.0” y “1.0”, cuando en realidad solo debería coincidir en “1.0” ya que esa coincidencia engloba a todas las demás.

    NAME

    tk_textPaste — Insert text into a text widget

    SYNOPSIS

    tk_textPaste widget ?"-format" format ?"-text" text?

    DESCRIPTION

    The tk_textPaste command is used to paste text into the specified text widget. The command can accept a list of formats to paste, and will use the first format that is available on the clipboard and supported by the widget.

    widget
    The name of the text widget into which to paste the text.
    -format format
    Specifies the desired format to paste. If this option is not provided, the command will attempt to paste any available format.
    -text text
    Specifies the text to paste. If this option is not provided, the command will retrieve the text from the clipboard.

    The command returns 1 if the text was successfully pasted, and 0 otherwise.

    EXAMPLES

    # Paste text from the clipboard into the text widget "myText"
tk_textPaste myText

# Paste specific text into the text widget "myText"
tk_textPaste myText -text "Hello, world!"

# Attempt to paste text in RTF format into the text widget "myText"
tk_textPaste myText -format RTF
