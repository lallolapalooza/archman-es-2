OPTIONS

Command-Line Name:	-tabstyle
Database Name:	tabStyle
Database Class:	TabStyle
Specifies how tab characters are displayed. The value must be tab, tabs, spaces, or none. If the value is tab, tabs are displayed as single characters. If the value is tabs, tabs are displayed as characters, but the widget draws spaces to fill in the space between the tab character and the next tab stop. If the value is spaces, tabs are converted to a number of space characters sufficient to reach the next tab stop. If the value is none, tab characters are not displayed at all, and the space they occupy is instead filled with spaces. The value of the -tabstyle option can be overridden by -tabstyle options in tags.
Command-Line Name:	-undo
Database Name:	undo
Database Class:	Undo
Specifies a boolean indicating whether the undo mechanism is active or not.
Command-Line Name:	-width
Database Name:	width
Database Class:	Width
Specifies the desired width for the window in units of characters for the font specified by the -font option. If the font does not have a uniform width, the width of the character “0” is used to translate from character units to screen units.
Command-Line Name:	-wrap
Database Name:	wrap
Database Class:	Wrap
Specifies how to handle lines in the text that are too long to be displayed in a single line of the text's window. The value must be none, char, or word. A wrap mode of none means that each line of text appears as exactly one line on the screen; extra characters that do not fit on the screen are not displayed. In the other modes, each line of text will be broken into several screen lines if necessary to keep all characters visible. In char mode, a screen line break may occur after any character; in word mode, a line break will only be made at word boundaries.

DESCRIPCIÓN

The text command creates a new window (given by the pathName argument) and makes it into a text widget. Additional options, described above, may be specified on the command line or in the option database to configure aspects of the text such as its default background color and relief. The text command returns the path name of the new window.

A text widget displays one or more lines of text and allows that text to be edited. Text widgets support four different kinds of annotations on the text, called tags, marks, embedded windows or embedded images. Tags allow different portions of the text to be displayed with different fonts and colors. In addition, Tcl commands can be associated with tags so that scripts are invoked when particular actions such as keystrokes and mouse button presses occur in particular ranges of the text. See TAGS below for more details.

The second form of annotation consists of floating markers in the text called “marks”. Marks are used to keep track of various interesting positions in the text as it is edited. See MARKS below for more details.

The third form of annotation allows arbitrary windows to be embedded in a text widget. See EMBEDDED WINDOWS below for more details.

The fourth form of annotation allows Tk images to be embedded in a text widget. See EMBEDDED IMAGES below for more details.

The text widget also has a built-in undo/redo mechanism. See THE UNDO MECHANISM below for more details.

The text widget allows for the creation of peer widgets. These are other text widgets which share the same underlying data (text, marks, tags, images, etc). See PEER WIDGETS below for more details.

ÍNDICES

Many of the widget commands for texts take one or more indices as arguments. An index is a string used to indicate a particular place within a text, such as a place to insert characters or one endpoint of a range of characters to delete. Indices have the syntax

base modifier modifier modifier ...
Where base gives a starting point and the modifiers adjust the index from the starting point (e.g. move forward or backward one character). Every index must contain a base, but the modifiers are optional. Most modifiers (as documented below) allow an optional submodifier. Valid submodifiers are any and display. If the submodifier is abbreviated, then it must be followed by whitespace, but otherwise there need be no space between the submodifier and the following modifier. Typically the display submodifier adjusts the meaning of the following modifier to make it refer to visual or non-elided units rather than logical units, but this is explained for each relevant case below. Lastly, where count is used as part of a modifier, it can be positive or negative, so “base - -3 lines” is perfectly valid (and equivalent to “base +3lines”).

The base for an index must have one of the following forms:

line.char
Indicates the char'th character on line line. Lines are numbered starting from 1 for consistency with other UNIX programs using this numbering scheme. Within a line, characters are numbered starting from 0. If char is end, it refers to the newline character that ends the line.
@x,y
Indicates the character that covers the pixel whose x and y coordinates within the text's window are x and y.
end
Indicates the end of the text (the character just after the last newline).
mark
Indicates the character just after the mark named mark (see MARKS for details).
tag.first
Indicates the first character in the text that has been tagged with tag. This form generates an error if no characters are currently tagged with tag.
tag.last
Indicates the character just after the last one in the text that has been tagged with tag. This form generates an error if no characters are currently tagged with tag.
pathName
Indicates the position of the embedded window named pathName. This form generates an error if there is no embedded window with the given name.
imageName
Indicates the position of the embedded image named imageName. This form generates an error if there is no embedded image with the given name.

If the base could match more than one of the above forms, such as a mark and imageName both having the same value, then the form that appears earlier in the list above takes precedence. If modifiers follow the base index, each one of them must have one of the forms listed below. Keywords such as chars and wordend may be abbreviated as long as the abbreviation is unambiguous.

+ count ?submodifier? chars
Adjust the index forward by count characters, moving to later lines in the text if necessary. If there are fewer than count characters in the text after the current index, then the index is set to the last index in the text. Spaces on either side of count are optional. If the display submodifier is given, elided characters are skipped over without being counted. If any is given, then all characters are counted. For historical reasons, if neither modifier is given, then the count actually takes place in units of index positions (see INDICES for details). This behavior may be changed in a future major release, so if you need an index count, you are encouraged to use indices instead wherever possible.
- count ?submodifier? chars
Adjust the index backward by count characters, moving to earlier lines in the text if necessary. If there are fewer than count characters in the text before the current index, then the index is set to the first index in the text (1.0). Spaces on either side of count are optional. If the display submodifier is given, elided characters are skipped over without being counted. If any is given, then all characters are counted. For historical reasons, if neither modifier is given, then the count actually takes place in units of index positions (see INDICES for details). This behavior may be changed in a future major release, so if you need an index count, you are encouraged to use indices instead wherever possible.
+ count ?submodifier? indices
Adjust the index forward by count index positions, moving to later lines in the text if necessary. If there are fewer than count index positions in the text after the current index, then the index is set to the last index position in the text. Spaces on either side of count are optional. Note that an index position is either a single character or a single embedded image or embedded window. If the display submodifier is given, elided indices are skipped over without being counted. If any is given, then all indices are counted; this is also the default behavior if no modifier is given.
- count ?submodifier? indices
Adjust the index backward by count index positions, moving to earlier lines in the text if necessary. If there are fewer than count index positions in the text before the current index, then the index is set to the first index position (1.0) in the text. Spaces on either side of count are optional. If the display submodifier is given, elided indices are skipped over without being counted. If any is given, then all indices are counted; this is also the default behavior if no modifier is given.
+ count ?submodifier? lines
Adjust the index forward by count lines, retaining the same character position within the line. If there are fewer than count lines after the line containing the current index, then the index is set to refer to the same character position on the last line of the text. Then, if the line is not long enough to contain a character at the indicated character position, the character position is adjusted to refer to the last character of the line (the newline). Spaces on either side of count are optional. If the display submodifier is given, then each visual display line is counted separately. Otherwise, if any (or no modifier) is given, then each logical line (no matter how many times it is visually wrapped) counts just once. If the relevant lines are not wrapped, then these two methods of counting are equivalent.

MODIFICADORES DE ÍNDICE

Además de los índices simples como se describe en la sección ``ÍNDICES”, los índices también pueden modificarse mediante la adición de modificadores. Los modificadores son opcionales y se pueden agregar en cualquier punto de un índice, como se muestra en la siguiente sintaxis:

indexModifier ::=
    ?submodifier?
    ( count | line | lines | word | words | char | chars | all )
    | ?submodifier? before | ?submodifier? after
    | ?submodifier? insert | ?submodifier? delete
    | ?submodifier? window | ?submodifier? image
    | ?submodifier? linestart | ?submodifier? lineend
    | ?submodifier? wordstart | ?submodifier? wordend
- count ?submodifier? lines
Ajusta el índice hacia atrás por count líneas lógicas, conservando la misma posición de carácter dentro de la línea. Si hay menos de count líneas antes de la línea que contiene el índice actual, entonces establece el índice para que se refiera a la misma posición de carácter en la primera línea del texto. Luego, si la línea no es lo suficientemente larga para contener un carácter en la posición de carácter indicada, ajusta la posición de carácter para que se refiera al último carácter de la línea (la nueva línea). Los espacios a ambos lados de count son opcionales. Si se proporciona el submodificador display, entonces cada línea de visualización se cuenta por separado. De lo contrario, si se proporciona any (o ningún modificador), entonces cada línea lógica (sin importar cuántas veces se ajuste visualmente) cuenta solo una vez. Si las líneas relevantes no se ajustan, entonces estos dos métodos de conteo son equivalentes.
?submodifier? linestart
Ajusta el índice para que se refiera al primer índice en la línea. Si el submodificador display se proporciona, este es el primer índice en la línea de visualización, de lo contrario, en la línea lógica.
?submodifier? lineend
Ajusta el índice para que se refiera al último índice en la línea (la nueva línea). Si se proporciona el submodificador display, este es el último índice en la línea de visualización, de lo contrario, en la línea lógica.
?submodifier? wordstart
Ajusta el índice para que se refiera al primer carácter de la palabra que contiene el índice actual. Una palabra consiste en cualquier número de caracteres adyacentes que sean letras, dígitos o guiones bajos, o un solo carácter que no sea uno de estos. Si se proporciona el submodificador display, esto solo examina caracteres no elididos, de lo contrario, todos los caracteres (elididos o no) son examinados.
?submodifier? wordend
Ajusta el índice para que se refiera al carácter justo después del último carácter de la palabra que contiene el índice actual. Si el índice actual se refiere al último carácter del texto, entonces no se modifica. Si se proporciona el submodificador display, esto solo examina caracteres no elididos, de lo contrario, todos los caracteres (elididos o no) son examinados.

Si hay más de un modificador presente, se aplican en orden de izquierda a derecha. Por ejemplo, el índice “end - 1 chars” se refiere al penúltimo carácter del texto y “insert wordstart - 1 c” se refiere al carácter justo antes del primero en la palabra que contiene el cursor de inserción. Los modificadores se aplican uno por uno en este orden de izquierda a derecha, y después de cada paso el índice resultante se limita a ser un índice válido en el widget de texto. Por lo tanto, por ejemplo, el índice “1.0 -1c +1c” se refiere al índice “2.0”.

Donde los modificadores resultan en cambios de índice por líneas de visualización, caracteres de visualización o índices de visualización, y la base se refiere a un índice dentro de una etiqueta elidida, esa índice base se considera equivalente al primer índice no elidido siguiente.

ETIQUETAS

La primera forma de anotación en los widgets de texto es una etiqueta. Una etiqueta es una cadena textual que se asocia con algunos de los caracteres en un texto. Las etiquetas pueden contener caracteres arbitrarios, pero probablemente sea mejor evitar el uso de los caracteres “ ” (espacio), + o -: estos caracteres tienen un significado especial en los índices, por lo que las etiquetas que los contienen no se pueden usar como índices. Puede haber cualquier número de etiquetas asociadas con los caracteres en un texto. Cada etiqueta puede referirse a un solo carácter, un rango de caracteres o varios rangos de caracteres. Un carácter individual puede tener cualquier número de etiquetas asociadas.

Se define un orden de prioridad entre las etiquetas, y este orden se utiliza en la implementación de algunas de las funciones relacionadas con las etiquetas descritas a continuación. Cuando se define una etiqueta (al asociarla con caracteres o al establecer sus opciones de visualización o al vincular comandos a ella), se le otorga una prioridad mayor que a cualquier etiqueta existente. El orden de prioridad de las etiquetas puede redefinirse utilizando los comandos del widget “pathName tag raise” y “pathName tag lower”.

Las etiquetas sirven para tres propósitos en los widgets de texto. Primero, controlan la forma en que se muestra la información en la pantalla. Por defecto, los caracteres se muestran según lo determinado por las opciones -background, -font y -foreground para el widget de texto. Sin embargo, las opciones de visualización pueden asociarse con etiquetas individuales utilizando el comando del widget “pathName tag configure”. Si un carácter ha sido etiquetado, entonces las opciones de visualización asociadas con la etiqueta anulan el estilo de visualización predeterminado. Las siguientes opciones son actualmente compatibles para las etiquetas:

-background color
Color especifica el color de fondo a utilizar para los caracteres asociados con la etiqueta. Puede tener cualquiera de las formas aceptadas por Tk_GetColor.
-bgstipple bitmap
Bitmap especifica un mapa de bits que se utiliza como patrón de tramado para el fondo. Puede tener cualquiera de las formas aceptadas por Tk_GetBitmap. Si no se ha especificado bitmap, o si se especifica como una cadena vacía, entonces se utilizará un relleno sólido para el fondo.
-borderwidth pixels
Pixels especifica el ancho de un borde a dibujar alrededor de la etiqueta utilizando cualquiera de las formas aceptadas por Tk_GetPixels. Esta opción debe usarse junto con la opción -relief para proporcionar el borde deseado.
-elide boolean
Elide especifica si los datos deben ser elididos. Los datos elididos (caracteres, imágenes, ventanas incrustadas, etc.) no se muestran y no ocupan espacio en la pantalla, pero más adelante se comportan como datos normales.
-fgstipple bitmap
Bitmap especifica un mapa de bits que se utiliza como patrón de tramado al dibujar texto y otra información de primer plano, como subrayados. Puede tener cualquiera de las formas aceptadas por Tk_GetBitmap. Si no se ha especificado bitmap, o si se especifica como una cadena vacía, entonces se utilizará un relleno sólido.
-font fontName
FontName es el nombre de una fuente a utilizar para dibujar caracteres. Puede tener cualquiera de las formas aceptadas por Tk_GetFont.
-foreground color
Color especifica el color a utilizar al dibujar texto y otra información de primer plano, como subrayados. Puede tener cualquiera de las formas aceptadas por Tk_GetColor.
-justify justify
Si el primer carácter no elidido de una línea de visualización tiene una etiqueta para la cual se ha especificado esta opción, entonces justify determina cómo justificar la línea. Debe ser uno de left, right o center. Si una línea se ajusta, entonces la justificación de cada línea en la pantalla está determinada por el primer carácter no elidido de esa línea de visualización.
-lmargin1 pixels
Si el primer carácter no elidido de una línea de texto tiene una etiqueta para la cual se ha especificado esta opción, entonces pixels especifica cuánto se debe indentar la línea desde el borde izquierdo de la ventana. Pixels puede tener cualquiera de las formas estándar para distancias de pantalla. Si una línea de texto se ajusta, esta opción solo se aplica a la primera línea en la visualización; la opción -lmargin2 controla la indentación para las líneas subsiguientes.
-lmargin2 pixels
Si el primer carácter no elidido de una línea de visualización tiene una etiqueta para la cual se ha especificado esta opción, y si la línea de visualización no es la primera para su línea de texto (es decir, la línea de texto se ha ajustado), entonces pixels especifica cuánto se debe indentar la línea desde el borde izquierdo de la ventana. Pixels puede tener cualquiera de las formas estándar para distancias de pantalla. Esta opción solo se usa cuando el ajuste está habilitado, y solo se aplica a la segunda y posteriores líneas de visualización para una línea de texto.
-lmargincolor color
Color especifica el color de fondo a utilizar en las regiones que no contienen caracteres porque están indentadas por -lmargin1 o -lmargin2. Puede tener cualquiera de las formas aceptadas por Tk_GetColor. Si no se ha especificado color, o si se especifica como una cadena vacía, entonces el color utilizado es especificado por la opción de etiqueta -background (o, si esto también no se especifica, por la opción de widget -background).
-offset pixels
Pixels especifica una cantidad por la cual la línea base del texto debe desplazarse verticalmente desde la línea base de la línea general, en píxeles. Por ejemplo, un desplazamiento positivo se puede usar para superíndices y un desplazamiento negativo se puede usar para subíndices. Pixels puede tener cualquiera de las formas estándar para distancias de pantalla.
-overstrike boolean
Especifica si se debe dibujar o no una línea horizontal a través del medio de los caracteres. Boolean puede tener cualquiera de las formas aceptadas por Tcl_GetBoolean.
-overstrikefg color
Color especifica el color a utilizar al mostrar el tachado. Puede tener cualquiera de las formas aceptadas por Tk_GetColor. Si no se ha especificado color, o si se especifica como una cadena vacía, entonces se utiliza el color especificado por la opción de etiqueta -foreground.
-relief relief
Relief especifica el estilo de relieve a utilizar para dibujar el borde, en cualquiera de las formas aceptadas por Tk_GetRelief. Esta opción se utiliza junto con la opción -borderwidth para habilitar la apariencia de borde deseada.
-rmargin pixels
Si el primer carácter no elidido de una línea de visualización tiene una etiqueta para la cual se ha especificado esta opción, entonces pixels especifica qué margen dejar entre el final de la línea y el borde derecho de la ventana. Pixels puede tener cualquiera de las formas estándar para distancias de pantalla. Esta opción solo se utiliza cuando el ajuste está habilitado. Si una línea de texto se ajusta, el margen derecho de cada línea en la vi
splay está determinado por el primer carácter no omitido de esa línea de visualización.
-rmargincolor color
Color especifica el color de fondo a utilizar en las regiones que no contienen caracteres porque están indentadas por -rmargin. Puede tener cualquiera de las formas aceptadas por Tk_GetColor. Si no se ha especificado color, o si se especifica como una cadena vacía, entonces el color utilizado es el especificado por la opción de etiqueta -background (o, si esta también no se especifica, por la opción del widget -background).
-selectbackground color
Color especifica el color de fondo a utilizar al mostrar elementos seleccionados. Puede tener cualquiera de las formas aceptadas por Tk_GetColor. Si no se ha especificado color, o si se especifica como una cadena vacía, entonces se utiliza el color especificado por la opción de etiqueta -background.
-selectforeground color
Color especifica el color de primer plano a utilizar al mostrar elementos seleccionados. Puede tener cualquiera de las formas aceptadas por Tk_GetColor. Si no se ha especificado color, o si se especifica como una cadena vacía, entonces se utiliza el color especificado por la opción de etiqueta -foreground.
-spacing1 píxeles
Píxeles especifica cuánto espacio adicional se debe dejar encima de cada línea de texto, utilizando cualquiera de las formas estándar para distancias en pantalla. Si una línea se ajusta, esta opción solo se aplica a la primera línea en la pantalla.
-spacing2 píxeles
Para las líneas que se ajustan, esta opción especifica cuánto espacio adicional dejar entre las líneas de visualización de una sola línea de texto. Píxeles puede tener cualquiera de las formas estándar para distancias en pantalla.
-spacing3 píxeles
Píxeles especifica cuánto espacio adicional se debe dejar debajo de cada línea de texto, utilizando cualquiera de las formas estándar para distancias en pantalla. Si una línea se ajusta, esta opción solo se aplica a la última línea en la pantalla.
-tabs lista_de_tabuladores
Lista_de_tabuladores especifica un conjunto de tabuladores en la misma forma que para la opción -tabs del widget de texto. Esta opción solo se aplica a una línea de visualización si se aplica al primer carácter no omitido en esa línea de visualización. Si esta opción se especifica como una cadena vacía, cancela la opción, dejándola sin especificar para la etiqueta (el valor predeterminado). Si la opción se especifica como una cadena no vacía que es una lista vacía, como -tags { }, entonces solicita tabuladores de 8 caracteres predeterminados como se describe para la opción de widget -tags.
-tabstyle estilo
Estilo especifica el estilo de tabulación tabular o procesador de textos a utilizar para el widget de texto. Esta opción solo se aplica a una línea de visualización si se aplica al primer carácter no omitido en esa línea de visualización. Si esta opción se especifica como una cadena vacía, cancela la opción, dejándola sin especificar para la etiqueta (el valor predeterminado).
-underline booleano
Booleano especifica si se debe dibujar o no un subrayado debajo de los caracteres. Puede tener cualquiera de las formas aceptadas por Tcl_GetBoolean.
-underlinefg color
Color especifica el color a utilizar al mostrar el subrayado. Puede tener cualquiera de las formas aceptadas por Tk_GetColor. Si no se ha especificado color, o si se especifica como una cadena vacía, entonces se utiliza el color especificado por la opción de etiqueta -foreground.
-wrap modo
Modo especifica cómo manejar las líneas que son más anchas que la ventana del texto. Esta opción solo se aplica a una línea de visualización si se aplica al primer carácter no omitido en esa línea de visualización. Tiene los mismos valores legales que la opción -wrap para el widget de texto: none, char o word. Si se especifica esta opción de etiqueta, anula la opción -wrap para el widget de texto.

Si un carácter tiene varias etiquetas asociadas, y si sus opciones de visualización entran en conflicto, se utilizan las opciones de la etiqueta de mayor prioridad. Si una opción de visualización particular no se ha especificado para una etiqueta particular, o si se especifica como una cadena vacía, entonces esa opción nunca se utilizará; se utilizará la opción de la etiqueta de prioridad inmediatamente superior. Si ninguna etiqueta especifica una opción de visualización particular, se utilizará el estilo predeterminado del widget.

El segundo propósito de las etiquetas son las vinculaciones de eventos. Puede asociar vinculaciones a una etiqueta de manera muy similar a como puede asociar vinculaciones a una clase de widget: cada vez que ocurran eventos X particulares en caracteres con la etiqueta dada, se ejecutará un comando Tcl dado. Las vinculaciones de etiquetas se pueden usar para dar comportamientos a rangos de caracteres; entre otras cosas, esto permite implementar características similares a hipertexto. Para obtener detalles, consulte la descripción del comando de widget “pathName tag bind” a continuación. Las vinculaciones de etiquetas se comparten entre todos los widgets pares (incluidas las vinculaciones para la etiqueta especial sel).

El tercer uso de las etiquetas es en la gestión de la selección. Ver LA SELECCIÓN a continuación. Con la excepción de la etiqueta especial sel, todas las etiquetas se comparten entre widgets de texto pares, y pueden ser manipuladas en igualdad de condiciones desde cualquier widget de este tipo. La etiqueta sel existe por separado e independientemente en cada widget de texto par (pero cualquier vinculación de etiqueta a sel se comparte).

MARCAS

La segunda forma de anotación en los widgets de texto es una marca. Las marcas se utilizan para recordar lugares particulares en un texto. Son algo así como las etiquetas, en que tienen nombres y se refieren a lugares en el archivo, pero una marca no está asociada con caracteres particulares. En cambio, una marca se asocia con el espacio entre dos caracteres. Solo se puede asociar una posición con una marca en cualquier momento dado. Si los caracteres alrededor de una marca se eliminan, la marca permanecerá; simplemente tendrá nuevos caracteres vecinos. En contraste, si se eliminan los caracteres que contienen una etiqueta, la etiqueta ya no tendrá una asociación con los caracteres en el archivo. Las marcas pueden ser manipuladas con el comando de widget “pathName mark”, y sus ubicaciones actuales pueden determinarse utilizando el nombre de la marca como un índice en los comandos del widget.

Cada marca también tiene una “gravedad”, que es izquierda o derecha. La gravedad de una marca especifica qué sucede con la marca cuando se inserta texto en el punto de la marca. Si una marca tiene gravedad izquierda, la marca se trata como si estuviera unida al carácter de su izquierda, por lo que la marca permanecerá a la izquierda de cualquier texto insertado en la posición de la marca. Si la marca tiene gravedad derecha, el nuevo texto insertado en la posición de la marca aparecerá a la izquierda de la marca (de modo que la marca permanezca más a la derecha). La gravedad de una marca es derecha por defecto.

El espacio de nombres para las marcas es diferente al de las etiquetas: se puede usar el mismo nombre tanto para una marca como para una etiqueta, pero se referirán a cosas diferentes.

Dos marcas tienen un significado especial. Primero, la marca insert está asociada con el cursor de inserción, como se describe en EL CURSOR DE INSERCIÓN a continuación. Segundo, la marca current está asociada con el carácter más cercano al ratón y se ajusta automáticamente para seguir la posición del ratón y cualquier cambio en el texto del widget (una excepción: current no se actualiza en respuesta a los movimientos del ratón si un botón del ratón está presionado; la actualización se pospondrá hasta que se suelten todos los botones del ratón). Ninguna de estas marcas especiales puede ser eliminada. Con la excepción de estas dos marcas especiales, todas las marcas se comparten entre los widgets de texto pares, y pueden ser manipuladas en igualdad de condiciones desde cualquier par.

VENTANAS EMPOTRADAS

La tercera forma de anotación en los widgets de texto es una ventana empotrada. Cada anotación de ventana empotrada hace que se muestre una ventana en un punto particular del texto. Puede haber cualquier número de ventanas empotradas en un widget de texto, y cualquier widget puede usarse como ventana empotrada (sujeto a las reglas habituales de gestión de geometría, que requieren que la ventana de texto sea el padre de la ventana empotrada o un descendiente de su padre).

La posición de la ventana empotrada en la pantalla se actualizará a medida que el texto se modifique o se desplace, y se mapeará y desmapeará a medida que entre y salga del área visible del widget de texto. Cada ventana empotrada ocupa una unidad de espacio de índice en el widget de texto, y puede ser referenciada por el nombre de su ventana empotrada o por su posición en el espacio de índice del widget. Si se elimina el rango de texto que contiene la ventana empotrada, la ventana se destruirá. De manera similar, si se elimina el widget de texto en su totalidad, la ventana se destruirá.

Omitir una ventana empotrada inmediatamente después de programarla para su creación a través de pathName window create index -create evitará que se cree efectivamente. Desomitir una ventana empotrada omitida programada para su creación a través de pathName window create index -create activará automáticamente el script de creación asociado. Después de destruir una ventana empotrada omitida, esta última no se recreará automáticamente.

Cuando se agrega una ventana empotrada a un widget de texto con el comando de widget pathName window create, se le pueden asociar varias opciones de configuración. Estas opciones se pueden modificar posteriormente con el comando de widget pathName window configure. Las siguientes opciones se admiten actualmente:

-align dónde
Si la ventana no es tan alta como la línea en la que se muestra, esta opción determina dónde se muestra la ventana en la línea. Dónde debe tener uno de los valores top (alinear la parte superior de la ventana con la parte superior de la línea), center (centrar la ventana dentro del rango de la línea), bottom (alinear la parte inferior de la ventana con la parte inferior del área de la línea) o baseline (alinear la parte inferior de la ventana con la línea base de la línea).
-create script
Especifica un script Tcl que puede ser evaluado para crear la ventana para el
anotación. Si no se ha especificado la opción -window para la anotación, este script se evaluará cuando la anotación esté a punto de mostrarse en pantalla. Script debe crear una ventana para la anotación y devolver el nombre de esa ventana como resultado. Se realizarán dos sustituciones en script antes de la evaluación. %W se sustituirá por el nombre del widget de texto padre, y %% se sustituirá por un único %. Si la ventana de la anotación debe ser eliminada alguna vez, script se evaluará de nuevo la próxima vez que se muestre la anotación.
-padx píxeles
Píxeles especifica la cantidad de espacio adicional que se dejará a cada lado de la ventana incrustada. Puede tener cualquiera de las formas habituales definidas para una distancia de pantalla.
-pady píxeles
Píxeles especifica la cantidad de espacio adicional que se dejará en la parte superior y en la parte inferior de la ventana incrustada. Puede tener cualquiera de las formas habituales definidas para una distancia de pantalla.
-stretch booleano
Si la altura solicitada de la ventana incrustada es menor que la altura de la línea en la que se muestra, esta opción se puede utilizar para especificar si la ventana debe estirarse verticalmente para llenar su línea. Si también se ha especificado la opción -pady, se conservará el relleno solicitado, incluso si la ventana se estira.
-window rutaNombre
Especifica el nombre de una ventana que se mostrará en la anotación. Tenga en cuenta que si se ha establecido una rutaNombre, la configuración posterior de una ventana a una cadena vacía no eliminará el widget correspondiente a la antigua rutaNombre. Más bien, eliminará la asociación entre la antigua rutaNombre y el widget de texto. Si se utilizan varios widgets hermanos, generalmente es más sencillo utilizar la opción -create si se desean ventanas incrustadas en cada hermano.

IMÁGENES INCRUSTADAS

La forma final de anotación en los widgets de texto es una imagen incrustada. Cada anotación de imagen incrustada provoca que se muestre una imagen en un punto particular del texto. Puede haber cualquier número de imágenes incrustadas en un widget de texto, y una imagen particular puede incrustarse en varios lugares del mismo widget de texto.

La posición de la imagen incrustada en la pantalla se actualizará a medida que el texto se modifique o se desplace. Cada imagen incrustada ocupa un espacio de índice de una unidad en el widget de texto, y puede ser referenciada ya sea por su posición en el espacio de índice del widget, o por el nombre que se le asigna cuando la imagen se inserta en el widget de texto con rutaNombre image create. Si se elimina el rango de texto que contiene la imagen incrustada, esa copia de la imagen se elimina de la pantalla.

Omitir una imagen incrustada inmediatamente después de programar su creación a través de rutaNombre image create índice -create evitará que se cree efectivamente. Mostrar de nuevo una imagen incrustada omitida programada para su creación a través de rutaNombre image create índice -create activará automáticamente el script de creación asociado. Después de destruir una imagen incrustada omitida, esta no se recreará automáticamente.

Cuando se añade una imagen incrustada a un widget de texto con el comando de widget rutaNombre image create, se devuelve un nombre único para esta instancia de la imagen. Este nombre puede utilizarse para referirse a esta instancia de imagen. El nombre se toma como el valor de la opción -name (descrita a continuación). Si no se proporciona la opción -name, se utiliza el nombre de la imagen -image en su lugar. Si el nombreImagen ya está en uso en el widget de texto, se añade #nn al final del nombreImagen, donde nn es un entero arbitrario. Esto asegura que el nombreImagen sea único. Una vez que este nombre se asigna a esta instancia de la imagen, no cambia, aunque los valores de -image o -name se puedan cambiar con rutaNombre image configure.

Cuando se añade una imagen incrustada a un widget de texto con el comando de widget rutaNombre image create, se pueden asociar varias opciones de configuración con ella. Estas opciones se pueden modificar más tarde con el comando de widget rutaNombre image configure. Las siguientes opciones son compatibles actualmente:

-align dónde
Si la imagen no tiene la misma altura que la línea en la que se muestra, esta opción determina dónde se muestra la imagen en la línea. Dónde debe tener uno de los valores top (alinear la parte superior de la imagen con la parte superior de la línea), center (centrar la imagen dentro del rango de la línea), bottom (alinear la parte inferior de la imagen con la parte inferior del área de la línea), o baseline (alinear la parte inferior de la imagen con la línea base de la línea).
-image imagen
Especifica el nombre de la imagen de Tk que se mostrará en la anotación. Si imagen no es una imagen de Tk válida, se devolverá un error.
-name nombreImagen
Especifica el nombre por el cual se puede referenciar esta instancia de imagen en el widget de texto. Si no se proporciona nombreImagen, se utiliza en su lugar el nombre de la imagen de Tk. Si el nombreImagen ya está en uso, se añade #nn al final del nombre como se describe anteriormente.
-padx píxeles
Píxeles especifica la cantidad de espacio adicional que se dejará a cada lado de la imagen incrustada. Puede tener cualquiera de las formas habituales definidas para una distancia de pantalla.
-pady píxeles
Píxeles especifica la cantidad de espacio adicional que se dejará en la parte superior y en la parte inferior de la imagen incrustada. Puede tener cualquiera de las formas habituales definidas para una distancia de pantalla.

LA SELECCIÓN

El soporte para la selección se implementa a través de etiquetas. Si la opción -exportselection para el widget de texto es verdadera, la etiqueta sel se asociará con la selección:

[1]
Siempre que los caracteres se etiqueten con sel, el widget de texto reclamará la propiedad de la selección.
[2]
Los intentos de recuperar la selección serán atendidos por el widget de texto, devolviendo todos los caracteres con la etiqueta sel.
[3]
Si la selección es reclamada por otra aplicación o por otra ventana dentro de esta aplicación, la etiqueta sel se eliminará de todos los caracteres del texto.
[4]
Siempre que el rango de la etiqueta sel cambie, se generará un evento virtual <<Selection>>. También podría generarse cuando la selección se ve afectada pero no realmente modificada. Además, múltiples cambios de selección podrían ocurrir antes de que los eventos puedan ser procesados, lo que lleva a múltiples eventos con la misma selección visible.

La etiqueta sel se define automáticamente cuando se crea un widget de texto, y no se puede eliminar con el comando de widget “rutaNombre tag delete”. Además, las opciones -selectbackground, -selectborderwidth y -selectforeground para el widget de texto están vinculadas a las opciones -background, -borderwidth y -foreground para la etiqueta sel: los cambios en cualquiera de ellas se reflejarán automáticamente en la otra. También la opción -inactiveselectbackground para el widget de texto se utiliza en lugar de -selectbackground cuando el widget de texto no tiene el foco. Esto permite un control programático sobre la visualización de la etiqueta sel para ventanas de primer plano y de fondo, o para que sel no se muestre en absoluto (cuando -inactiveselectbackground está vacío) para ventanas de fondo. Cada widget de texto hermano tiene su propia etiqueta sel que puede configurarse y establecerse por separado.

EL CURSOR DE INSERCIÓN

La marca llamada insert tiene un significado especial en los widgets de texto. Se define automáticamente cuando se crea un widget de texto y no se puede desestablecer con el comando de widget “rutaNombre mark unset”. La marca insert representa la posición del cursor de inserción, y el cursor de inserción se dibujará automáticamente en este punto siempre que el widget de texto tenga el foco de entrada.

EL INDICADOR MODIFICADO

El widget de texto puede realizar un seguimiento de los cambios en el contenido del widget mediante el indicador modificado. Insertar o eliminar texto establecerá este indicador. El indicador se puede consultar, establecer y borrar programáticamente. Cada vez que el indicador cambia de estado, se genera un evento virtual <<Modified>>. Consulte el comando de widget rutaNombre edit modified para obtener más detalles.

EL MECANISMO DE DESHACER

El widget de texto tiene un mecanismo ilimitado de deshacer y rehacer (cuando la opción de widget -undo es verdadera) que registra cada acción de inserción y eliminación en una pila.

Se insertan límites (llamados "separadores") entre las acciones de edición. El propósito de estos separadores es agrupar inserciones, eliminaciones y reemplazos en una única acción de edición compuesta. Al deshacer un cambio, se deshace todo lo que hay entre dos separadores. Los cambios deshechos se mueven a la pila de rehacer, de modo que una edición deshecha puede ser rehecha de nuevo. La pila de rehacer se borra cada vez que se registran nuevas acciones de edición en la pila de deshacer. Las pilas de deshacer y rehacer se pueden borrar para mantener su profundidad bajo control.

Los separadores se insertan automáticamente cuando la opción de widget -autoseparators es verdadera. También puede insertar separadores programáticamente. Si ya hay un separador en la parte superior de la pila de deshacer, no se insertará otro. Esto significa que dos separadores en la pila de deshacer siempre están separados por al menos una acción de inserción o eliminación.

El evento virtual <<UndoStack>> se genera cada vez que la pila de deshacer o la pila de rehacer se vacía o se llena.

El mecanismo de deshacer también está vinculado al indicador modificado. Esto significa que deshacer o rehacer cambios puede devolver un widget de texto modificado al estado no modificado o viceversa. El indicador modificado se establecerá automáticamente al estado apropiado. Este acoplamiento automático no afecta

UNDO

El mecanismo de deshacer y rehacer se implementa mediante una pila. El comando text tiene dos opciones de configuración para controlar esta funcionalidad: -undo y -maxundo.

La opción -undo tiene dos valores: 0 y 1. Si está establecido a 0 (que es el valor predeterminado), no se mantiene ninguna pila de deshacer y las llamadas a comandos como undo o redo fallarán.

Si se establece a 1, el widget de texto mantendrá una pila de cambios. Cada vez que se modifica el contenido del widget de texto mediante una operación que cambia el texto (como insertar o eliminar texto), el estado anterior se guarda en la pila de deshacer. Cada entrada en la pila de deshacer representa un solo cambio atómico. Por ejemplo, insertar varias líneas de texto se registrará como una sola entrada de deshacer, pero eliminar el texto seleccionado podría generar múltiples entradas de deshacer si hay varias etiquetas que afectan a la eliminación.

La opción -maxundo controla el tamaño máximo de la pila de deshacer. Si el número de cambios guardados excede este límite, las entradas más antiguas se eliminarán de la pila para hacer sitio a las nuevas. Si se establece a 0, no hay límite en el número de entradas que se pueden almacenar, lo que permite deshacer todos los cambios realizados desde que se habilitó la funcionalidad de deshacer.

Un conjunto de operaciones de deshacer y rehacer se agrupa automáticamente hasta que el indicador modified se establece en 1. La opción modified se establece cuando un cambio entra en la pila de deshacer y se restablece cuando se produce un evento de deshacer o rehacer. Esto significa que todas las operaciones de deshacer y rehacer se agrupan en un único cambio hasta que el usuario realiza un cambio manual o se restablece explícitamente el indicador modified.

Consulte a continuación el comando de widget pathName edit que controla el mecanismo de deshacer.

PEER WIDGETS

El widget de texto tiene un almacén separado de todos sus datos relacionados con el contenido textual de cada línea, marcas, etiquetas, imágenes y ventanas, y la pila de deshacer.

Si bien no se puede acceder directamente a este almacén de datos (es decir, sin un widget de texto como intermediario), se pueden crear múltiples widgets de texto, cada uno de los cuales presenta diferentes vistas sobre los mismos datos subyacentes. Dichos widgets de texto se conocen como widgets de texto pares.

A medida que se añaden, eliminan, editan y colorean textos en cualquiera de los widgets, y a medida que se ajustan imágenes, marcas y etiquetas, todos estos cambios se reflejarán en todos los pares.

Todos los datos y el marcado se comparten, excepto por algunos detalles menores. Primero, la etiqueta sel puede establecerse y configurarse (en su estilo de visualización) de manera diferente para cada par. Segundo, cada par tiene sus propias posiciones de marca insert y current (pero todas las demás marcas se comparten). Tercero, las ventanas incrustadas, que son otros widgets arbitrarios, no se pueden compartir entre pares. Esto significa que la opción -window de las ventanas incrustadas se establece de forma independiente para cada par (se aconseja utilizar las capacidades de script -create para permitir que cada par cree sus propias ventanas incrustadas según sea necesario). Cuarto, todas las opciones de configuración de cada par (por ejemplo, -font, etc.) se pueden establecer de forma independiente, con la excepción de -undo, -maxundo, -autoseparators (es decir, todos los problemas de estado de deshacer, rehacer y modificado se comparten).

Finalmente, cualquier par individual no necesita contener todas las líneas del almacén de datos subyacente. Al crear un par, se puede especificar un rango contiguo de líneas (por ejemplo, solo las líneas 52 a 125). Esto permite que un par contenga solo una pequeña porción del texto general. El rango de líneas se expandirá y contraerá a medida que se inserten o eliminen textos. El par solo mostrará líneas completas de texto (no se puede compartir solo una parte de una línea). Si el contenido del par se contrae a nada (es decir, todas las líneas completas en el widget par se han eliminado de otro widget), entonces es imposible insertar nuevas líneas. El par simplemente se convertirá en una carcasa vacía sobre la que se puede configurar el fondo, pero que nunca mostrará contenido (sin una reconfiguración manual de las líneas de inicio y fin). Tenga en cuenta que un par que no contiene todos los datos subyacentes todavía tiene índices numerados desde “1.0” hasta “end”. Es simplemente que esos índices reflejan un subconjunto de los datos totales, y los datos fuera del rango contenido no son accesibles para el par. Esto significa que el comando peerName index end puede devolver valores bastante diferentes en diferentes pares. De manera similar, los comandos como peerName tag ranges no devolverán rangos de índices fuera de lo que es significativo para el par. Las opciones de configuración -startline y -endline se pueden utilizar para controlar cuánto de los datos subyacentes se contiene en cualquier widget de texto dado.

Tenga en cuenta que los pares son realmente pares. Eliminar el widget de texto “original” no provocará la eliminación de ningún otro par ni lo afectará de ninguna otra manera.

Consulte a continuación el comando de widget pathName peer que controla la creación de widgets pares.

ACTUALIZACIÓN ASÍNCRONA DE ALTURAS DE LÍNEA

Para mantener una experiencia de usuario receptiva, el widget de texto calcula las métricas de las líneas (alturas de las líneas en píxeles) de forma asíncrona. Debido a esto, algunos comandos del widget de texto pueden devolver resultados incorrectos si los cálculos asíncronos no han finalizado en el momento de la llamada. Esto se aplica a pathName count -ypixels y pathName yview.

Nuevamente, por razones de rendimiento, no sería apropiado permitir que estos comandos esperen siempre al final del cálculo de actualización cada vez que se llaman. En la mayoría de los casos de uso de estos comandos, un resultado más o menos inexacto realmente no importa en comparación con la velocidad de ejecución.

En caso de que se necesite un resultado preciso (y si el widget de texto está gestionado por un gestor de geometría), se puede recurrir a pathName sync y pathName pendingsync para controlar la sincronización de la vista de los widgets de texto.

El evento virtual <<WidgetViewSync>> se dispara cuando las alturas de las líneas del widget de texto quedan obsoletas (debido a algún comando de edición o cambio de configuración), y de nuevo cuando los datos internos del widget de texto vuelven a estar sincronizados con la vista del widget. El campo de detalle (%d sustitución) es verdadero (cuando el widget está sincronizado) o falso (cuando no lo está).

pathName sync, pathName pendingsync y <<WidgetViewSync>> se aplican a cada widget de texto independientemente de sus pares.

Ejemplos de uso:

## Ejemplo 1:
# completar inmediatamente las métricas de línea a cualquier coste (GUI no responde)
$w sync
$w yview moveto $fraction
## Ejemplo 2:
# esperar de forma síncrona a métricas de línea actualizadas (GUI responde)
# antes de ejecutar el comando programado, pero no bloquear el flujo de ejecución
$w sync -command [list $w yview moveto $fraction]
## Ejemplo 3:
# inicialización
set yud($w) 0
proc updateaction w {
set ::yud($w) 1
# cualquier otra acción de actualización aquí...
}
# tiempo de ejecución, esperar de forma síncrona a métricas de línea actualizadas (GUI responde)
$w sync -command [list updateaction $w]
vwait yud($w)
$w yview moveto $fraction
## Ejemplo 4:
# inicialización
set todo($w) {}
proc updateaction w {
foreach cmd $::todo($w) {uplevel #0 $cmd}
set todo($w) {}
}
# tiempo de ejecución
lappend todo($w) [list $w yview moveto $fraction]
$w sync -command [list updateaction $w]
## Ejemplo 5:
# inicialización
set todo($w) {}
bind $w <<WidgetViewSync>> {
if {%d} {
foreach cmd $todo(%W) {eval $cmd}
set todo(%W) {}
}
}
# tiempo de ejecución
if {![$w pendingsync]} {
$w yview moveto $fraction
} else {
lappend todo($w) [list $w yview moveto $fraction]
}

COMANDO DE WIDGET

El comando text crea un nuevo comando Tcl cuyo nombre es el mismo que el nombre de ruta de la ventana del texto. Este comando se puede utilizar para invocar varias operaciones en el widget. Tiene la siguiente forma general:

pathName option ?arg arg ...?

pathName es el nombre del comando, que es el mismo que el nombre de ruta del widget de texto. option y los args determinan el comportamiento exacto del comando. Los siguientes comandos son posibles para los widgets de texto:

pathName bbox index
Devuelve una lista de cuatro elementos que describen el área de pantalla del carácter dado por index. Los dos primeros elementos de la lista proporcionan las coordenadas x e y de la esquina superior izquierda del área ocupada por el carácter, y los dos últimos elementos proporcionan el ancho y la altura del área. Si el carácter solo es parcialmente visible en la pantalla, el valor devuelto refleja solo la parte visible. Si el carácter no es visible en la pantalla, el valor devuelto es una lista vacía.
pathName cget option
Devuelve el valor actual de la opción de configuración dada por option. option puede tener cualquiera de los valores aceptados por el comando text.
pathName compare index1 op index2
Compara los índices dados por index1 y index2 según el operador relacional dado por op, y devuelve 1 si la relación se satisface y 0 si no. op debe ser uno de los operadores <, <=, ==, >=, >, o !=. Si op es ==, se devuelve 1 si los dos índices se refieren al mismo carácter, si op es <, se devuelve 1 si index1 se refiere a un carácter anterior en el texto que index2, y así sucesivamente.
pathName configure ?option? ?value option value ...?
Consulta o modifica las opciones de configuración del widget. Si no se especifica ningún option, devuelve una lista que describe todas las opciones disponibles para pathName (consulte Tk_ConfigureInfo para obtener información sobre el formato de esta lista). Si se especifica option sin value, el comando devuelve una lista que describe la opción con el nombre especificado (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica ningún option). Si se especifican uno o más pares option-value, el comando modifica la(s) opción(es) del widget dada(s) para que tengan el(los) valor(es) dado(s); en este caso, el comando devuelve una cadena vacía. option puede tener cualquiera de los valores aceptados por el comando text.
pathName count ?options? index1 index2
Cuenta el número de elementos relevantes entre los dos índices. Si index1 está después de index2, el resultado será un número negativo (y esto se aplica a cada una de las opciones posibles). Los elementos reales que se cuentan dependen de las opciones dadas. El resultado es una lista de enteros, uno para el resultado de cada opción de conteo dada. Las opciones de conteo válidas son -chars, -displaychars, -displayindices, -displaylines, -indices, -lines, -xpixels y -ypixels. El valor predeterminado, si no se especifica ninguna opción, es -indices. Hay una opción adicional posible -update que es un modificador. Si se da (y si el widget de texto está gestionado por un gestor de geometría), entonces todas las opciones subsiguientes aseguran que cualquier información potencialmente obsoleta se recalcule. Actualmente, esto solo tiene algún efecto para el conteo -ypixels (que, si no se da -update, utilizará el valor almacenado en caché actual del widget de texto para cada línea). Esta opción -update está obsoleta por pathName sync, pathName pendingsync y <<WidgetViewSync>>. Las opciones de conteo se interpretan de la siguiente manera:
-chars
cuenta todos los caracteres, estén o no elididos. No cuenta ventanas incrustadas ni imágenes.
-displaychars
cuenta todos los caracteres no elididos.
-displayindices
cuenta todos los caracteres, ventanas e imágenes no elididos.
-displaylines
cuenta
pathName count option ?index1 index2?
Counts items between index1 and index2. The default for index1 is the beginning of the text (``1.0'') and the default for index2 is the end of the text (``end''). The exact items counted depend on the option argument, which may have any of the following values:
-displaylines
cuenta todas las líneas de visualización (es decir, contando una por cada vez que una línea se ajusta) desde la línea del primer índice hasta, pero sin incluir, la línea de visualización del segundo índice. Por lo tanto, si ambos están en la misma línea de visualización, se devolverá cero. Por definición, las líneas de visualización son visibles y, por lo tanto, esto solo cuenta porciones de líneas visibles reales.
-indices
cuenta todos los caracteres y ventanas o imágenes incrustadas (es decir, todo lo que cuenta en el espacio de índices del widget de texto), ya sea que estén elididos o no.
-lines
cuenta todas las líneas lógicas (independientemente del ajuste) desde la línea del primer índice hasta, pero sin incluir, la línea del segundo índice. Por lo tanto, si ambos están en la misma línea, se devolverá cero. Las líneas lógicas se cuentan ya sea que sean actualmente visibles (no elididas) o no.
-xpixels
cuenta el número de píxeles horizontales desde el primer píxel del primer índice hasta (pero sin incluir) el primer píxel del segundo índice. Para contar el ancho total deseado del widget de texto (suponiendo que el ajuste no está habilitado), primero encuentre la línea más larga y luego use ``.text count -xpixels "${line}.0" "${line}.0 lineend''.
-ypixels
cuenta el número de píxeles verticales desde el primer píxel del primer índice hasta (pero sin incluir) el primer píxel del segundo índice. Si ambos índices están en la misma línea de visualización, se devolverá cero. Para contar el número total de píxeles verticales en el widget de texto, use ``.text count -ypixels 1.0 end'', y para asegurarse de que esto está actualizado, use ``.text count -update -ypixels 1.0 end''.

El comando devuelve un entero positivo o negativo correspondiente al número de elementos contados entre los dos índices. Se devuelve un entero de este tipo por cada opción de conteo dada, por lo que se devuelve una lista si se proporcionó más de una opción. Por ejemplo, ``.text count -xpixels -ypixels 1.3 4.5'' es perfectamente válido y devolverá una lista de dos elementos.

pathName debug ?boolean?
Si se especifica boolean, debe tener uno de los valores verdaderos o falsos aceptados por Tcl_GetBoolean. Si el valor es verdadero, se activarán las comprobaciones de consistencia internas en el código B-tree asociado con los widgets de texto. Si boolean tiene un valor falso, las comprobaciones de depuración se desactivarán. En cualquier caso, el comando devuelve una cadena vacía. Si boolean no se especifica, el comando devuelve on u off para indicar si la depuración está activada o desactivada. Hay un único interruptor de depuración compartido por todos los widgets de texto: activarlo o desactivarlo en cualquier widget lo activa o desactiva para todos los widgets. Para widgets con grandes cantidades de texto, las comprobaciones de consistencia pueden causar una ralentización notable.

Cuando la depuración está activada, las rutinas de dibujo del widget de texto establecen las variables globales tk_textRedraw y tk_textRelayout a las listas de índices que se redibujan. Los valores de estas variables son probados por el conjunto de pruebas de Tk.

pathName delete index1 ?index2 ...?
Elimina un rango de caracteres del texto. Si se especifican tanto index1 como index2, entonces se eliminan todos los caracteres comenzando por el dado por index1 y deteniéndose justo antes de index2 (es decir, el carácter en index2 no se elimina). Si index2 no especifica una posición posterior en el texto a index1, no se eliminan caracteres. Si no se especifica index2, se elimina el único carácter en index1. Los intentos de eliminar caracteres de una manera que deje el texto sin una nueva línea como último carácter serán ajustados por el widget de texto para evitar esto. En particular, la eliminación de líneas completas de texto hasta el final del texto también eliminará el carácter de nueva línea justo antes del bloque eliminado para que sea reemplazado por la nueva nueva línea final del widget de texto. El comando devuelve una cadena vacía. Si se proporcionan más índices, se eliminarán varios rangos de texto. Todos los índices se verifican primero en busca de validez antes de realizar cualquier eliminación. Se ordenan y el texto se elimina del último rango al primer rango para que el texto eliminado no cause efectos secundarios de cambio de índice no deseados. Si se proporcionan varios rangos con el mismo índice de inicio, se utilizará el rango más largo. Si se proporcionan rangos superpuestos, se fusionarán en tramos que no causen la eliminación de texto fuera de los rangos dados debido al texto desplazado durante la eliminación.
pathName dlineinfo index
Devuelve una lista con cinco elementos que describen el área ocupada por la línea de visualización que contiene index. Los dos primeros elementos de la lista dan las coordenadas x e y de la esquina superior izquierda del área ocupada por la línea, los terceros y cuartos elementos dan el ancho y la altura del área, y el quinto elemento da la posición de la línea base para la línea, medida hacia abajo desde la parte superior del área. Toda esta información se mide en píxeles. Si el modo de ajuste actual es none y la línea se extiende más allá de los límites de la ventana, el área devuelta refleja toda el área de la línea, incluidas las partes que están fuera de la ventana. Si la línea es más corta que el ancho total de la ventana, el área devuelta refleja solo la porción de la línea que está ocupada por caracteres y ventanas incrustadas. Si la línea de visualización que contiene index no es visible en la pantalla, el valor devuelto es una lista vacía.
pathName dump ?switches? index1 ?index2?
Devuelve el contenido del widget de texto desde index1 hasta, pero sin incluir, index2, incluido el texto e información sobre marcas, etiquetas y ventanas incrustadas. Si no se especifica index2, por defecto es un carácter después de index1. La información se devuelve en el siguiente formato:

key1 value1 index1 key2 value2 index2 ...

Los posibles valores de key son text, mark, tagon, tagoff, image y window. El value correspondiente es el texto, el nombre de la marca, el nombre de la etiqueta, el nombre de la imagen o el nombre de la ventana. La información del index es el índice de inicio del texto, la marca, la transición de etiqueta, la imagen o la ventana. Se pueden especificar una o más de las siguientes opciones (o sus abreviaturas) para controlar la volcación:

-all
Devuelve información sobre todos los elementos: texto, marcas, etiquetas, imágenes y ventanas. Este es el valor predeterminado.
-command command
En lugar de devolver la información como resultado de la operación de volcado, invoca el command en cada elemento del widget de texto dentro del rango. El comando tiene tres argumentos añadidos antes de ser evaluado: la key, el value y el index.
-image
Incluye información sobre imágenes en los resultados del volcado.
-mark
Incluye información sobre marcas en los resultados del volcado.
-tag
Incluye información sobre transiciones de etiquetas en los resultados del volcado. La información de etiquetas se devuelve como elementos tagon y tagoff que indican el inicio y el final de cada rango de cada etiqueta, respectivamente.
-text
Incluye información sobre texto en los resultados del volcado. El valor es el texto hasta el siguiente elemento o el final del rango indicado por index2. Un elemento de texto no abarca saltos de línea. Un bloque de texto de varias líneas que no contiene marcas ni transiciones de etiquetas aún se volcará como un conjunto de segmentos de texto que cada uno termina con un salto de línea. El salto de línea es parte del valor.
-window
Incluye información sobre ventanas incrustadas en los resultados del volcado. El valor de una ventana es su ruta de Tk, a menos que la ventana aún no se haya creado. (Debe tener un script de creación). En este caso, se devuelve una cadena vacía, y debe consultar la ventana por su posición de índice para obtener más información.
pathName edit option ?arg arg ...?
Este comando controla el mecanismo de deshacer y el indicador de modificación. El comportamiento exacto del comando depende del argumento option que sigue al argumento edit. Actualmente se admiten las siguientes formas del comando:
pathName edit canredo
Devuelve un booleano verdadero si se puede rehacer, es decir, cuando la pila de rehacer no está vacía. De lo contrario, devuelve falso.
pathName edit canundo
Devuelve un booleano verdadero si se puede deshacer, es decir, cuando la pila de deshacer no está vacía. De lo contrario, devuelve falso.
pathName edit modified ?boolean?
Si no se especifica boolean, devuelve el indicador modificado del widget. Los comandos de inserción, eliminación, edición de deshacer y edición de rehacer o el usuario pueden establecer o borrar el indicador modificado. Si se especifica boolean, establece el indicador modificado del widget a boolean.
pathName edit redo
Cuando la opción -undo es verdadera, vuelve a aplicar las últimas ediciones deshechas siempre que no se hayan realizado otras ediciones desde entonces. Genera un error cuando la pila de rehacer está vacía. No hace nada cuando la opción -undo es falsa.
pathName edit reset
Borra las pilas de deshacer y rehacer.
pathName edit separator
Inserta un separador (límite) en la pila de deshacer. No hace nada cuando la opción -undo es falsa.
pathName edit undo
Deshace la última acción de edición cuando la opción -undo es verdadera. Una acción de edición se define como todos los comandos de inserción y eliminación
en el búfer de deshacer entre dos separadores. Genera un error cuando el búfer de deshacer está vacío. No hace nada cuando la opción -undo es falsa.
pathName get ?-displaychars? ?--? index1 ?index2 ...?
Devuelve un rango de caracteres del texto. El valor de retorno serán todos los caracteres del texto comenzando por el cuyo índice es index1 y terminando justo antes del que cuyo índice es index2 (el carácter en index2 no será devuelto). Si index2 se omite entonces se devuelve el carácter único en index1. Si no hay caracteres en el rango especificado (p. ej., index1 está más allá del final del archivo o index2 es menor o igual a index1) entonces se devuelve una cadena vacía. Si el rango especificado contiene ventanas incrustadas, no se incluye información sobre ellas en la cadena devuelta. Si se dan múltiples pares de índices, se devolverán múltiples rangos de texto en una lista. Los rangos inválidos no se representarán con cadenas vacías en la lista. Los rangos se devuelven en el orden en que se pasan a pathName get. Si se proporciona la opción -displaychars, entonces, dentro de cada rango, solo se devolverán aquellos caracteres que no estén elididos. Esto puede tener el efecto de que algunos de los rangos devueltos sean cadenas vacías.
pathName image option ?arg arg ...?
Este comando se utiliza para manipular imágenes incrustadas. El comportamiento del comando depende del argumento option que sigue al argumento image. Actualmente se admiten las siguientes formas del comando:
pathName image cget index option
Devuelve el valor de una opción de configuración para una imagen incrustada. Index identifica la imagen incrustada y option especifica una configuración específica. opción, que debe ser una de las enumeradas en la sección EMBEDDED IMAGES.
pathName image configure index ?option value ...?
Consulta o modifica las opciones de configuración de una imagen incrustada. Si no se especifica option, devuelve una lista que describe todas las opciones disponibles para la imagen incrustada en index (ver Tk_ConfigureInfo para información sobre el formato de esta lista). Si se especifica option sin value, entonces el comando devuelve una lista que describe la única opción nombrada (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica option). Si se especifican uno o más pares option-value, entonces el comando modifica la(s) opción(es) dada(s) para que tengan el(los) valor(es) dado(s); en este caso el comando devuelve una cadena vacía. Ver EMBEDDED IMAGES para información sobre las opciones que son compatibles.
pathName image create index ?option value ...?
Este comando crea una nueva anotación de imagen, que aparecerá en el texto en la posición dada por index. Se puede especificar cualquier número de pares option-value para configurar la anotación. Devuelve un identificador único que puede usarse como índice para referirse a esta imagen. Ver EMBEDDED IMAGES para información sobre las opciones que son compatibles, y una descripción del identificador devuelto.
pathName image names
Devuelve una lista cuyos elementos son los nombres de todas las instancias de imágenes actualmente incrustadas en window.
pathName index index
Devuelve la posición correspondiente a index en el formato line.char donde line es el número de línea y char es el número de carácter. Index puede tener cualquiera de los formatos descritos en INDICES arriba.
pathName insert index chars ?tagList chars tagList ...?
Inserta todos los argumentos chars justo antes del carácter en index. Si index se refiere al final del texto (el carácter después de la última nueva línea) entonces el nuevo texto se inserta justo antes de la última nueva línea en su lugar. Si hay un único argumento chars y no hay tagList, entonces el nuevo texto recibirá las etiquetas que estén presentes tanto en el carácter anterior como en el carácter posterior al punto de inserción; si una etiqueta está presente en solo uno de estos caracteres entonces no se aplicará al nuevo texto. Si se especifica tagList entonces consiste en una lista de nombres de etiquetas; los nuevos caracteres recibirán todas las etiquetas de esta lista y ninguna otra, independientemente de las etiquetas presentes alrededor del punto de inserción. Si hay múltiples pares de argumentos chars-tagList, producen el mismo efecto que si se hubiera emitido un comando de widget pathName insert separado para cada par, en orden. El último argumento tagList puede omitirse.
pathName mark option ?arg arg ...?
Este comando se utiliza para manipular marcas. El comportamiento exacto del comando depende del argumento option que sigue al argumento mark. Actualmente se admiten las siguientes formas del comando:
pathName mark gravity markName ?direction?
Si direction no se especifica, devuelve left o right para indicar a cuál de sus caracteres adyacentes está unida markName. Si se especifica direction, debe ser left o right; la gravedad de markName se establece al valor dado.
pathName mark names
Devuelve una lista cuyos elementos son los nombres de todas las marcas que están actualmente establecidas.
pathName mark next index
Devuelve el nombre de la siguiente marca en o después de index. Si index se especifica en forma numérica, entonces la búsqueda de la siguiente marca comienza en ese índice. Si index es el nombre de una marca, entonces la búsqueda de la siguiente marca comienza inmediatamente después de esa marca. Esto aún puede devolver una marca en la misma posición si hay múltiples marcas en el mismo índice. Estas semánticas significan que la operación mark next se puede usar para recorrer todas las marcas en un widget de texto en el mismo orden que la información de marca devuelta por la operación pathName dump. Si se ha establecido una marca en el índice especial end, entonces aparece como después de end con respecto a la operación pathName mark next. Se devuelve una cadena vacía si no hay marcas después de index.
pathName mark previous index
Devuelve el nombre de la marca en o antes de index. Si index se especifica en forma numérica, entonces la búsqueda de la marca anterior comienza con el carácter justo antes de ese índice. Si index es el nombre de una marca, entonces la búsqueda de la siguiente marca comienza inmediatamente antes de esa marca. Esto aún puede devolver una marca en la misma posición si hay múltiples marcas en el mismo índice. Estas semánticas significan que la operación pathName mark previous se puede usar para recorrer todas las marcas en un widget de texto en el orden inverso al de la información de marca devuelta por la operación pathName dump. Se devuelve una cadena vacía si no hay marcas antes de index.
pathName mark set markName index
Establece la marca llamada markName a una posición justo antes del carácter en index. Si markName ya existe, se mueve de su posición anterior; si no existe, se crea una nueva marca. Este comando devuelve una cadena vacía.
pathName mark unset markName ?markName markName ...?
Elimina la marca correspondiente a cada uno de los argumentos markName. Las marcas eliminadas no serán utilizables en índices y no serán devueltas por llamadas futuras a “pathName mark names”. Este comando devuelve una cadena vacía.
pathName peer option args
Este comando se utiliza para crear y consultar pares de widgets. Tiene dos formas, dependiendo de option:
pathName peer create newPathName ?options?
Crea un widget de texto par con el newPathName dado, y cualquier opción de configuración estándar opcional (como para el comando text). Por defecto, el par tendrá la misma línea de inicio y fin que el widget padre, pero estas pueden ser anuladas con las opciones de configuración estándar.
pathName peer names
Devuelve una lista de pares de este widget (esto no incluye el widget en sí). El orden dentro de esta lista no está definido.
pathName pendingsync
Devuelve 1 si los cálculos de las alturas de línea no están actualizados, 0 en caso contrario.
pathName replace index1 index2 chars ?tagList chars tagList ...?
Reemplaza el rango de caracteres entre index1 y index2 con los caracteres y etiquetas dados. Ver la sección sobre pathName insert para una explicación del manejo de los argumentos tagList..., y la sección sobre pathName delete para una explicación del manejo de los índices. Si index2 corresponde a un índice anterior en el texto que index1, se generará un error.

La eliminación y la inserción se organizan de manera que no se produzca un desplazamiento innecesario de la ventana o un movimiento del cursor de inserción. Además, los búferes de deshacer/rehacer se modifican correctamente, si las operaciones de deshacer están activas en el widget de texto. El comando devuelve una cadena vacía.

pathName scan opción argumentos

pathName search ?switches? patrón índice ?stopIndex?
Busca el texto en pathName comenzando en índice por un rango de caracteres que coincida con patrón. Si se encuentra una coincidencia, se devuelve el índice del primer carácter de la coincidencia como resultado; de lo contrario, se devuelve una cadena vacía. Se pueden especificar uno o más de los siguientes modificadores (o abreviaturas de estos) para controlar la búsqueda:
-forwards
La búsqueda procederá hacia adelante a través del texto, encontrando el primer rango coincidente que comience en o después de la posición dada por índice. Este es el valor predeterminado.
-backwards
La búsqueda procederá hacia atrás a través del texto, encontrando el rango coincidente más cercano a índice cuyo primer carácter esté antes de índice (no se permite que esté en índice). Tenga en cuenta que, por diversas razones, las búsquedas hacia atrás pueden ser sustancialmente más lentas que las búsquedas hacia adelante (particularmente al usar -regexp), por lo que se recomienda que el código crítico para el rendimiento utilice búsquedas hacia adelante.
-exact
Utiliza coincidencia exacta: los caracteres en el rango coincidente deben ser idénticos a los de patrón. Este es el valor predeterminado.
-regexp
Trata patrón como una expresión regular y la compara con el texto utilizando las reglas para expresiones regulares (ver el comando regexp y la página re_syntax para detalles). La coincidencia predeterminada pasa automáticamente las opciones -lineanchor y -linestop al motor de expresiones regulares (a menos que se use -nolinestop), de modo que ^$ coincida con el principio y el final de la línea, y ., [^ las secuencias nunca coincidirán con el carácter de nueva línea \n.
-nolinestop
Esto permite que las secuencias . y [^ coincidan con el carácter de nueva línea \n, lo que de lo contrario no harán (ver el comando regexp para detalles). Esta opción solo es significativa si también se proporciona -regexp, de lo contrario se producirá un error. Por ejemplo, para coincidir con todo el texto, use “pathName search -nolinestop -regexp “.*” 1.0”.
-nocase
Ignora las diferencias de mayúsculas y minúsculas entre el patrón y el texto.
-count varName
El argumento que sigue a -count proporciona el nombre de una variable; si se encuentra una coincidencia, el número de posiciones de índice entre el principio y el final del rango coincidente se almacenará en la variable. Si no hay imágenes o ventanas incrustadas en el rango coincidente (y no hay caracteres elididos si no se proporciona -elide), esto es equivalente al número de caracteres coincidentes. En cualquier caso, el rango matchIdx a matchIdx + $count chars devolverá todo el texto coincidente.
-all
Encuentra todas las coincidencias en el rango dado y devuelve una lista de los índices del primer carácter de cada coincidencia. Si se proporciona un modificador -count varName, entonces varName también se establece en una lista que contiene un elemento por cada coincidencia exitosa. Tenga en cuenta que, incluso para búsquedas exactas, los elementos de esta lista pueden ser diferentes, si hay imágenes, ventanas o texto oculto incrustado. Las búsquedas con -all se comportan de manera muy similar al comando Tcl regexp -all, en el sentido de que las coincidencias superpuestas normalmente no se devuelven. Por ejemplo, aplicar una búsqueda -all del patrón “\w+” contra “hello there” solo coincidirá dos veces, una por cada palabra, y coincidir “Z[a-z]+Z” contra “ZooZooZoo” solo coincidirá una vez.
-overlap
Al realizar búsquedas -all, el comportamiento normal es que las coincidencias que se superponen con una coincidencia ya encontrada no se devuelven. Este modificador cambia ese comportamiento para que se devuelvan todas las coincidencias que no estén completamente incluidas dentro de otra coincidencia. Por ejemplo, aplicar una búsqueda -overlap del patrón “\w+” contra “hello there” solo coincidirá dos veces (es decir, no hay diferencia con solo -all), pero coincidir “Z[a-z]+Z” contra “ZooZooZoo” ahora coincidirá dos veces. Se producirá un error si este modificador se utiliza sin -all.
-strictlimits
Al realizar cualquier búsqueda, el comportamiento normal es que los límites de inicio y fin se verifican con respecto al inicio del texto coincidente. Con la bandera -strictlimits, todo el rango coincidente debe estar dentro de los límites de inicio y fin especificados para que la coincidencia sea válida.
-elide
Busca también el texto elidido (oculto). Por defecto, solo se busca el texto visible.
--
Este modificador no tiene ningún efecto excepto terminar la lista de modificadores: el siguiente argumento se tratará como patrón incluso si comienza con -.

El rango de coincidencia puede estar dentro de una sola línea de texto o abarcar varias líneas (si partes del patrón pueden coincidir con una nueva línea). Para la coincidencia de expresiones regulares, se pueden usar las diversas características de coincidencia de nueva línea como $ para coincidir con el final de una línea, ^ para coincidir con el principio de una línea, y para controlar si . puede coincidir con una nueva línea. Si se especifica stopIndex, la búsqueda se detiene en ese índice: para búsquedas hacia adelante, no se considerará ninguna coincidencia en o después de stopIndex; para búsquedas hacia atrás, no se considerará ninguna coincidencia anterior en el texto que stopIndex. Si se omite stopIndex, se buscará todo el texto: cuando se llega al principio o al final del texto, la búsqueda continúa en el otro extremo hasta que se vuelve a alcanzar la ubicación de inicio; si se especifica stopIndex, no ocurrirá ningún retorno de carro. Esto significa que, por ejemplo, si la búsqueda es -forwards pero stopIndex está antes en el texto que startIndex, nunca se encontrará nada. Los únicos eventos para los que se pueden especificar asociaciones son aquellos relacionados con el ratón y el teclado (como Enter, Leave, ButtonPress, Motion y KeyPress) o eventos virtuales. Las asociaciones de eventos de ratón y teclado para un widget de texto utilizan respectivamente las marcas current e insert descritas en MARKS arriba. Un evento Enter se activa para una etiqueta cuando la etiqueta se hace presente por primera vez en el carácter actual, y un evento Leave se activa para una etiqueta cuando deja de estar presente en el carácter actual. Los eventos Enter y Leave pueden ocurrir ya sea porque la marca current se movió o porque el carácter en esa posición cambió. Tenga en cuenta que estos eventos son diferentes de los eventos Enter y Leave para ventanas. Los eventos del ratón se dirigen al carácter actual, mientras que los eventos del teclado se dirigen al carácter de inserción. Si se utiliza un evento virtual en una asociación, esa asociación solo se puede activar si el evento virtual está definido por un evento subyacente relacionado con el ratón o el teclado.

Es posible que el carácter actual tenga varias etiquetas, y que cada una de ellas tenga una asociación para una secuencia de eventos particular. Cuando esto ocurre, se invoca una asociación por cada etiqueta, en orden de menor prioridad a mayor prioridad. Si hay múltiples asociaciones coincidentes para una sola etiqueta, se elige la asociación más específica (consulte la entrada del manual del comando bind para obtener detalles). Los comandos continue y break dentro de los scripts de asociación se procesan de la misma manera que para las asociaciones creadas con el comando bind.

Si se crean asociaciones para el widget en su conjunto utilizando el comando bind, estas asociaciones complementarán las asociaciones de etiquetas. Las asociaciones de etiquetas se invocarán primero, seguidas de las asociaciones para la ventana en su conjunto.

ASOCIACIONES

Tk crea automáticamente asociaciones de clase para los textos que les dan el siguiente comportamiento predeterminado. En las descripciones a continuación, "palabra" depende del valor de la variable tcl_wordchars. Ver tclvars(n).

[1]
Hacer clic en el botón del ratón 1 posiciona el cursor de inserción en el borde más cercano del carácter debajo del cursor del ratón, establece el foco de entrada en este widget y borra cualquier selección en el widget. Arrastrar con el botón del ratón 1 marca una selección entre el cursor de inserción y el carácter debajo del ratón.
[2]
Hacer doble clic con el botón del ratón 1 selecciona la palabra debajo del ratón y posiciona el cursor de inserción al principio de la palabra. Arrastrar después de un doble clic marcará una selección que consiste en palabras completas.
[3]
Hacer triple clic con el botón del ratón 1 selecciona la línea debajo del ratón y posiciona el cursor de inserción al principio de la línea. Arrastrar después de un triple clic marcará una selección que consiste en líneas completas.
[4]
Los extremos de la selección se pueden ajustar arrastrando con el botón del ratón 1 mientras se mantiene presionada la tecla Shift; esto ajustará el extremo de la selección que estaba más cerca del cursor del ratón cuando se presionó el botón 1. Si el botón se hace doble clic antes de arrastrar, la selección se ajustará en unidades de palabras completas; si se hace triple clic, la selección se ajustará en unidades de líneas completas.

El widget text se utiliza para mostrar y editar texto que puede tener una variedad de formatos. El texto se organiza en líneas y caracteres. Cada carácter tiene una posición de índice que se puede especificar de varias maneras (consulte la sección ÍNDICES).

El widget text soporta las siguientes características:

Texto y formato
El texto se puede insertar, eliminar y modificar utilizando los comandos del widget. Los atributos de formato, como la fuente, el color y el estilo, se pueden aplicar a rangos específicos de texto utilizando etiquetas (consulte la sección ETIQUETAS).

Se puede seleccionar texto dentro del widget, y las operaciones de copiar, cortar y pegar están disponibles. El texto seleccionado se puede exportar al portapapeles del sistema si la opción -exportselection está activada.
Búsqueda y reemplazo
Se puede buscar texto dentro del widget utilizando cadenas literales o expresiones regulares. También se pueden realizar reemplazos.
Desplazamiento
El widget text se puede asociar con barras de desplazamiento para permitir el desplazamiento a través de grandes cantidades de texto.
Ventanas y imágenes incrustadas
Se pueden incrustar ventanas y imágenes dentro del texto. Esto permite crear interfaces de usuario complejas y mostrar información gráfica junto con el texto.
Deshacer/Rehacer
Si la opción -undo está activada, el widget registrará las ediciones para permitir la deshacer y rehacer acciones.

PROBLEMAS CONOCIDOS

PROBLEMAS RELACIONADOS CON CARACTERES E ÍNDICES

Antes de Tk 8.5, el widget utilizaba la cadena "chars" para referirse a posiciones de índice (que incluían caracteres, ventanas incrustadas e imágenes incrustadas). A partir de Tk 8.5, el widget maneja por separado y correctamente "chars" e "índices". Sin embargo, para compatibilidad con versiones anteriores, los modificadores de índice "+N chars" y "-N chars" continúan refiriéndose a índices. Se debe usar cualquiera de las formas completas "+N any chars" o "-N any chars", etc., para referirse a índices de caracteres reales. Esta confusión puede corregirse en una futura versión al hacer que el widget interprete correctamente "+N chars" como un sinónimo de "+N any chars".

PROBLEMAS DE RENDIMIENTO

Los widgets de texto deberían funcionar de manera eficiente en una variedad de condiciones. El widget de texto utiliza aproximadamente 2-3 bytes de memoria principal por cada byte de texto, por lo que los textos que contienen un megabyte o más deberían ser prácticos en la mayoría de las estaciones de trabajo. El texto se representa internamente con una estructura de árbol B modificada que hace que las operaciones sean relativamente eficientes, incluso con textos grandes. Las etiquetas se incluyen en la estructura del árbol B de manera que permite que las etiquetas abarquen grandes rangos o tengan muchos rangos pequeños y disjuntos sin pérdida de eficiencia. Las marcas también se implementan de manera que permite un gran número de marcas. En la mayoría de los casos, está bien tener un gran número de etiquetas únicas, o una etiqueta que tenga muchos rangos distintos.

Un problema de rendimiento puede surgir si tiene cientos o miles de etiquetas diferentes que todas tienen las siguientes características: los primeros y últimos rangos de cada etiqueta están cerca del principio y del final del texto, respectivamente, o un único rango de etiqueta cubre la mayor parte del widget de texto. El costo de agregar y eliminar etiquetas como estas es proporcional al número de otras etiquetas con las mismas propiedades. En contraste, no hay problema con tener miles de etiquetas distintas si sus rangos generales están localizados y distribuidos uniformemente por todo el texto.

Las líneas de texto muy largas pueden ser costosas, especialmente si tienen muchas marcas y etiquetas dentro de ellas.

La línea de visualización con el cursor de inserción se redibuja cada vez que el cursor parpadea, lo que provoca un flujo constante de tráfico gráfico. Establezca el atributo -insertofftime a 0 para evitar esto.

ERRORES CONOCIDOS

El subcomando pathName search -regexp intenta realizar coincidencias sofisticadas de expresiones regulares en varias líneas de manera eficiente (desde Tk 8.5), examinando cada línea individualmente y luego en pequeños grupos de líneas, ya sea buscando hacia adelante o hacia atrás. Bajo ciertas condiciones, el resultado de la búsqueda puede diferir del que se obtiene al aplicar la misma expresión regular a todo el texto del widget de una vez. Por ejemplo, al buscar con una expresión regular codiciosa, el widget continuará intentando agregar líneas adicionales a la coincidencia siempre que se cumpla una de las dos condiciones: o bien la biblioteca de expresiones regulares de Tcl devuelve un código para indicar que es posible una coincidencia más larga (pero existen errores conocidos en Tcl que significan que este código no siempre se devuelve correctamente); o si cada línea adicional agregada resulta en al menos una coincidencia parcial con el patrón. Esto significa que en el caso en que la primera línea adicional agregada no resulte en ninguna coincidencia y el sistema de expresiones regulares de Tcl devuelva el código incorrecto y la adición de una segunda línea adicional realmente coincida, el widget de texto devolverá el resultado incorrecto. En la práctica, este es un problema raro, pero puede ocurrir, por ejemplo:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\ncccc\nbbbb\naaaa\n"
.t search -regexp -- {(a+|b+\nc+\nb+)+\na+} 1.0
no encontrará una coincidencia cuando exista una de 19 caracteres que comience con el primer "b".

Siempre que una posible coincidencia esté completamente contenida dentro de otra, el comando de búsqueda intentará asegurar que solo se devuelva la coincidencia más grande. Al realizar búsquedas de expresiones regulares hacia atrás, es posible que Tcl no siempre logre esto, en el caso de que una coincidencia esté precedida por una o más coincidencias cortas y que no se solapen, todas ellas precedidas por una coincidencia grande que en realidad las abarca a todas. El algoritmo de búsqueda utilizado por el widget no mira arbitrariamente hacia atrás en busca de una posible coincidencia que pueda cubrir grandes porciones del widget. Por ejemplo:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\nbbbb\nbbbb\nbbbb\n"
.t search -regexp -backward -- {b+\n|a+\n(b+\n)+} end
coincide en "5.0" cuando una coincidencia codiciosa real coincidiría en "1.0". De manera similar, si agregamos -all a este caso, coincide en todos los "5.0", "4.0", "3.0" y "1.0", cuando en realidad solo debería coincidir en "1.0" ya que esa coincidencia abarca todas las demás.
