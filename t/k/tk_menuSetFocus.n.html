NOMBRE

menu, tk_menuSetFocus - Crear y manipular widgets de 'menu' y barras de menú

SINOPSIS

menu nombreRuta ?opciones?
tk_menuSetFocus nombreRuta

OPCIONES ESTÁNDAR

-activebackground	-borderwidth	-foreground
-activeborderwidth	-cursor	-relief
-activeforeground	-disabledforeground	-takefocus
-background	-font

Consulte la entrada del manual de options para obtener más detalles sobre las opciones estándar.

OPCIONES ESPECÍFICAS DEL WIDGET

Nombre de línea de comandos:	-postcommand
Nombre de base de datos:	postCommand
Clase de base de datos:	Command
Si se especifica esta opción, proporciona un comando Tcl para ejecutar cada vez que se publica el menú. El comando es invocado por el comando del widget post antes de publicar el menú. Tenga en cuenta que en Tk 8.0 en Macintosh y Windows, todos los comandos de publicación en un sistema de menús se ejecutan antes de que se publiquen esos menús. Esto se debe a las limitaciones de los administradores de menús de las plataformas individuales.
Nombre de línea de comandos:	-selectcolor
Nombre de base de datos:	selectColor
Clase de base de datos:	Background
Para las entradas de menú que son botones de selección (check buttons) o botones de radio (radio buttons), esta opción especifica el color a mostrar en el indicador cuando el botón de selección o el botón de radio está seleccionado.
Nombre de línea de comandos:	-tearoff
Nombre de base de datos:	tearOff
Clase de base de datos:	TearOff
Esta opción debe tener un valor booleano válido, que especifica si el menú debe incluir o no una entrada de "desprendible" (tear-off) en la parte superior. Si es así, existirá como la entrada 0 del menú y las demás entradas comenzarán a numerarse a partir de 1. Las vinculaciones de menú predeterminadas hacen que el menú se desprenda cuando se invoca la entrada desprendible. Esta opción se ignora en Aqua/macOS, donde los menús no se pueden desprender.
Nombre de línea de comandos:	-tearoffcommand
Nombre de base de datos:	tearOffCommand
Clase de base de datos:	TearOffCommand
Si esta opción tiene un valor no vacío, especifica un comando Tcl a invocar cada vez que el menú se desprenda. El comando real consistirá en el valor de esta opción, seguido de un espacio, seguido del nombre de la ventana del menú, seguido de un espacio, seguido del nombre de la ventana del menú desprendido. Por ejemplo, si el valor de la opción es “a b” y el menú .x.y se desprende para crear un nuevo menú .x.tearoff1, se invocará el comando “a b .x.y .x.tearoff1”. Esta opción se ignora en Aqua/macOS, donde los menús no se pueden desprender.
Nombre de línea de comandos:	-title
Nombre de base de datos:	title
Clase de base de datos:	Title
La cadena se utilizará para titular la ventana creada cuando se desprenda este menú. Si el título es NULL, la ventana tendrá el título del botón de menú o el texto del elemento en cascada desde el cual se invocó este menú.
Nombre de línea de comandos:	-type
Nombre de base de datos:	type
Clase de base de datos:	Type
Esta opción puede ser menubar, tearoff o normal, y se establece cuando se crea el menú. Si bien la cadena devuelta por la base de datos de configuración cambiará si se modifica esta opción, esto no afecta el comportamiento del widget de menú. Esto es utilizado por el mecanismo de clonación y normalmente no se establece fuera de la biblioteca de Tk.

INTRODUCCIÓN

El comando menu crea una nueva ventana de nivel superior (dada por el argumento nombreRuta) y la convierte en un widget de menú. Ese widget de menú puede usarse como una ventana emergente o aplicarse a un toplevel (con su opción -menu) para convertirlo en la barra de menú de ese toplevel. Opciones adicionales, descritas anteriormente, pueden especificarse en la línea de comandos o en la base de datos de opciones para configurar aspectos del menú, como sus colores y fuente. El comando menu devuelve su argumento nombreRuta. En el momento en que se invoca este comando, no debe existir una ventana llamada nombreRuta, pero el padre de nombreRuta debe existir.

Un menú es un widget que muestra una colección de entradas de una línea dispuestas en una o más columnas. Existen varios tipos diferentes de entradas, cada una con propiedades diferentes. Las entradas de diferentes tipos pueden combinarse en un solo menú. Las entradas de menú no son lo mismo que los widgets de entrada. De hecho, las entradas de menú ni siquiera son widgets distintos; todo el menú es un solo widget.

Las entradas de menú se muestran con hasta tres campos separados. El campo principal es una etiqueta en forma de cadena de texto, un bitmap o una imagen, controlado por las opciones -label, -bitmap e -image para la entrada. Si se especifica la opción -accelerator para una entrada, se mostrará un segundo campo de texto a la derecha de la etiqueta. El acelerador típicamente describe una secuencia de teclas que se puede usar en la aplicación para producir el mismo resultado que invocar la entrada del menú. Esta es una opción de visualización, no establece realmente la vinculación correspondiente (que se puede lograr utilizando el comando bind). El tercer campo es un indicador. El indicador está presente solo para las entradas de tipo checkbutton o radiobutton. Indica si la entrada está seleccionada o no, y se muestra a la izquierda de la cadena de la entrada.

En uso normal, una entrada se activa (se muestra de manera diferente) cada vez que el puntero del ratón está sobre la entrada. Si se suelta un botón del ratón sobre la entrada, esta se invoca. El efecto de la invocación es diferente para cada tipo de entrada; estos efectos se describen a continuación en las secciones sobre entradas individuales.

Las entradas pueden ser deshabilitadas, lo que hace que sus etiquetas y aceleradores se muestren con colores más tenues. Las vinculaciones de menú predeterminadas no permitirán que una entrada deshabilitada se active o invoque. Las entradas deshabilitadas pueden ser rehabilitadas, momento en el cual volverá a ser posible activarlas e invocarlas.

Cada vez que la entrada activa de un menú cambia, se envía un evento virtual <<MenuSelect>> al menú. Luego, el elemento activo se puede consultar desde el menú, y se puede tomar una acción, como establecer texto de ayuda sensible al contexto para la entrada.

TIPOS DE ENTRADAS

ENTRADAS DE COMANDO

El tipo de entrada de menú más común es una entrada de comando, que se comporta de manera muy similar a un widget de botón. Cuando se invoca una entrada de comando, se ejecuta un comando Tcl. El comando Tcl se especifica con la opción -command.

ENTRADAS DE SEPARADOR

Un separador es una entrada que se muestra como una línea divisoria horizontal. Un separador no puede activarse ni invocarse, y no tiene más comportamiento que su apariencia visual.

ENTRADAS DE BOTÓN DE SELECCIÓN

Una entrada de menú de tipo checkbutton se comporta de manera muy similar a un widget de checkbutton. Cuando se invoca, alterna entre los estados seleccionado y deseleccionado. Cuando la entrada está seleccionada, se almacena un valor particular en una variable global particular (según lo determinado por las opciones -onvalue y -variable para la entrada); cuando la entrada está deseleccionada, se almacena otro valor (determinado por la opción -offvalue) en la variable global. Se muestra un cuadro indicador a la izquierda de la etiqueta en una entrada de checkbutton. Si la entrada está seleccionada, el centro del indicador se mostrará en el color dado por la opción -selectcolor para la entrada; de lo contrario, el centro del indicador se mostrará en el color de fondo del menú. Si se especifica una opción -command para una entrada de checkbutton, su valor se evalúa como un comando Tcl cada vez que se invoca la entrada; esto ocurre después de alternar el estado seleccionado de la entrada.

Una entrada de menú de tipo radiobutton se comporta de manera muy similar a un widget de radiobutton. OPTIONS

Menu widgets have the same general configuration options as other scale widgets. See the options -background, -borderwidth, -cursor, -disabledforeground, -font, -foreground, -relief, -takefocus, and -visual.

In addition, menu widgets have the following configuration options:

-activebackground ?color?
Specifies the background color for menu entries that are currently active. Defaults to the value of the -selectcolor option if set, otherwise to the system default.
-activeforeground ?color?
Specifies the foreground color for menu entries that are currently active. Defaults to the system default.
-borderwidth ?number?
Specifies the width of the border around the menu widget. Defaults to 1. See also the standard -borderwidth option.
-font ?font?
Specifies the font for the text in the menu entries. Defaults to the system default font.
-menuattributes ?attributes?
Specifies a list of attributes that will be applied to the menu widget. This option is not supported on all platforms. Defaults to empty.
-padx ?amount?
Specifies a padding amount to be added to the left and right of each menu entry. Defaults to 0.
-pady ?amount?
Specifies a padding amount to be added to the top and bottom of each menu entry. Defaults to 0.
-relief ?relief?
Specifies the appearance of the border around the menu widget. Defaults to flat. See the standard -relief option for details.
-selectcolor ?color?
Specifies the color to be used for the indicator of a selected checkbutton or radiobutton entry. Defaults to the system default.
-takefocus ?boolean?
Specifies whether the menu widget should receive focus when the user tabs through the widgets. Defaults to true.
-tearoff ?boolean?
Specifies whether the menu should have a tear-off button at the top. The default is true. A value of false disables the tear-off feature. This option can only be set at creation time.
-title ?string?
Specifies a title for the menu. This is primarily used for menubars. The title will be displayed at the top of the menu on systems that support this feature. Defaults to empty.

MENU ENTRY OPTIONS

Most menu entries support the following options, which may be specified when the entry is created or modified with the add or entryconfigure widget commands:

-accelerator ?key?
Specifies a key sequence that will be displayed to the right of the entry's label. This is purely decorative and does not cause any key bindings to be created. Defaults to empty.
-bitmap ?bitmap?
Specifies a bitmap to be displayed to the left of the entry's label. If specified, this overrides the -image option. Defaults to empty.
-command ?script?
Specifies a Tcl script to be executed when the menu entry is invoked. Defaults to empty.
-discriminator ?color?
Specifies the color of the checkmark or radiobutton indicator. Defaults to the system default.
-elementborderwidth ?amount?
Specifies the width of the border around elements within the menu entry. This is only supported on some platforms. Defaults to 0.
-font ?font?
Specifies the font for the entry's label. Defaults to the menu's default font.
-foreground ?color?
Specifies the foreground color for the entry's label. Defaults to the menu's default foreground color.
-image ?imageName?
Specifies an image to be displayed to the left of the entry's label. If specified, this overrides the -bitmap option. Defaults to empty.
-label ?string?
Specifies the text label for the menu entry. Defaults to empty.
-menu ?menuName?
Specifies that this entry is a cascade entry and that menuName is the menu to be popped up. Defaults to empty.
-mnemonic ?key?
Specifies a mnemonic character in the entry's label. This is indicated by underlining the character. The mnemonic can be activated by pressing the Alt key in combination with the specified character. Defaults to no mnemonic.
-normalize ?boolean?
If set to true, the label and accelerator text are automatically scaled to fit the menu entry. Defaults to true.
-selectcolor ?color?
Specifies the color to be used for the indicator of a selected checkbutton or radiobutton entry. Defaults to the menu's default selectcolor.
-state ?normal|disabled|active?
Specifies the state of the entry. normal means it is active and can be selected, disabled means it is grayed out and cannot be selected, and active means it is currently highlighted. Defaults to normal.
-underline ?index?
Specifies the character position of the mnemonic within the label. This option overrides the -mnemonic option. Defaults to -1 (no mnemonic).
-variable ?name?
Specifies the name of a Tcl variable that is associated with the menu entry. This option is only valid for checkbutton and radiobutton entries. Defaults to empty.

COMMAND ENTRIES

A command entry is created with the type command. When the entry is invoked, the script specified by the -command option is executed. If the entry is disabled, the command is not executed.

CHECKBUTTON ENTRIES

A checkbutton entry is created with the type checkbutton. It is associated with a Tcl variable specified by the -variable option. If the variable exists, its value determines the state of the checkbutton: 0 for off, 1 for on. If the variable does not exist, it is created with the value 0. When the checkbutton is selected or deselected, the associated variable is updated. A checkmark is displayed to the left of the label in each checkbutton entry. If the entry is selected then the checkmark is displayed in the color given by the -selectcolor option for the entry; otherwise the checkmark is displayed in the background color for the menu. If a -command option is specified for a checkbutton entry, then its value is evaluated as a Tcl command each time the entry is invoked; this happens after the associated variable is updated.

RADIOBUTTON ENTRIES

A radiobutton entry is created with the type radiobutton. It is associated with a Tcl variable specified by the -variable option. If the variable exists, its value determines the state of the radiobutton. When a radiobutton is selected, its associated variable is set to the value specified by the entry's -value option. This action causes any previously-selected entry in the same group to deselect itself. Once an entry has become selected, any change to the entry's associated variable will cause the entry to deselect itself. Grouping of radiobutton entries is determined by their associated variables: if two entries have the same associated variable then they are in the same group. An indicator diamond is displayed to the left of the label in each radiobutton entry. If the entry is selected then the indicator's center is displayed in the color given by the -selectcolor option for the entry; otherwise the indicator's center is displayed in the background color for the menu. If a -command option is specified for a radiobutton entry, then its value is evaluated as a Tcl command each time the entry is invoked; this happens after selecting the entry.

CASCADE ENTRIES

A cascade entry is one with an associated menu (determined by the -menu option). Cascade entries allow the construction of cascading menus. The postcascade widget command can be used to post and unpost the associated menu just next to of the cascade entry. The associated menu must be a child of the menu containing the cascade entry (this is needed in order for menu traversal to work correctly).

A cascade entry posts its associated menu by invoking a Tcl command of the form

menu post x y
where menu is the path name of the associated menu, and x and y are the root-window coordinates of the upper-right corner of the cascade entry. On Unix, the lower-level menu is unposted by executing a Tcl command with the form 
menu unpost
where menu is the name of the associated menu. On other platforms, the platform's native code takes care of unposting the menu.

If a -command option is specified for a cascade entry then it is evaluated as a Tcl command whenever the entry is invoked. This is not supported on Windows.

TEAR-OFF ENTRIES

A tear-off entry appears at the top of the menu if enabled with the -tearoff option. It is not like other menu entries in that it cannot be created with the add widget command and cannot be deleted with the delete widget command. When a tear-off entry is created it appears as a dashed line at the top of the menu. Under the default bindings, invoking the tear-off entry causes a torn-off copy to be made of the menu and all of its submenus.

MENUBARS

Any menu can be set as a menubar for a toplevel window (see toplevel command for syntax). On the Macintosh, whenever the toplevel is in front, this menu's cascade items will appear in the menubar across the top of the main monitor. On Windows and Unix, this menu's items will be displayed in a menubar across the top of the window. These menus will behave according to the interface guidelines of their platforms. For every menu set as a menubar, a clone menu is made. See the CLONES section for more information.

As noted, menubars may behave differently on different platforms. One example of this concerns the handling of checkbuttons and radiobuttons within the menu. While it is permitted to put these menu elements on menubars, they may not be drawn with indicators on some platforms, due to system restrictions.

SPECIAL MENUS IN MENUBARS

Certain menus in a menubar will be treated specially. On the Macintosh, access to the special Application, Window and Help menus is provided. On Windows, access to the Windows System menu in each window is provided. On X Windows, a special right-justified help menu may be provided if Motif menu compatibility is enabled. In all cases, these menus must be created with the command name of the menubar menu concatenated with the special name. So for a menubar named .menubar, on the Macintosh, the special menus would be .menubar.apple, .menubar.window and .menubar.help; on Windows, the special menu would be .menubar.system; on X Windows, the help menu would be .menubar.help.

When Tk sees a .menubar.apple menu as the first menu in a menubar on the Macintosh, that menu's contents make up the first items of the Application menu whenever the window containing the menubar is in front. After all of the Tk-defined items, the menu will have a separator, followed by all standard Application menu items. Such a .apple menu must be present in a menu when that menu is first configured as a toplevel's menubar, otherwise a default application menu (hidden from Tk) will be inserted into the menubar at that time and subsequent addition of a .apple menu will no longer result in it becoming the Application menu.

When Tk sees a .menubar.window menu on the Macintosh, the menu's contents are inserted into the standard Window menu of the user's menubar whenever the window's menubar is in front. The first items in the menu are provided by macOS, and the names of the current toplevels are automatically appended after all the Tk-defined items and a separator. The Window menu on the Mac also allows toggling the window into a fullscreen state, and managing a tabbed window interface (multiple windows grouped into a single window) if supported by that version of the operating system.

When Tk sees a .menubar.help menu on the Macintosh, the menu's contents are appended to the standard Help menu of the user's menubar whenever the window's menubar is in front. The first items in the menu are provided by macOS.

When Tk sees a System menu on Windows, its items are appended to the system menu that the menubar is attached to. This menu is tied to the application icon and can be invoked with the mouse or by typing Alt+Spacebar. Due to limitations in the Windows API, any font changes, colors, images, bitmaps, or tearoff images will not appear in the system menu.

When Tk sees a Help menu on X Windows and Motif menu compatibility is enabled the menu is moved to be last in the menubar and is right justified. Motif menu compatibility is enabled by setting the Tk option *Menu.useMotifHelp to true or by calling tk::classic::restore menu.

CLONES

When a menu is set as a menubar for a toplevel window, or when a menu is torn off, a clone of the menu is made. This clone is a menu widget in its own right, but it is a child of the original. Changes in the configuration of the original are reflected in the clone. Additionally, any cascades that are pointed to are also cloned so that menu traversal will work right. Clones are destroyed when either the tearoff or menubar goes away, or when the original menu is destroyed.

WIDGET COMMAND

The menu command creates a new Tcl command whose name is pathName. This command may be used to invoke various operations on the widget. It has the following general form:

pathName option ?arg arg ...?
Option and the args determine the exact behavior of the command.

Many of the widget commands for a menu take as one argument an indicator of which entry of the menu to operate on. These indicators are called indexes and may be specified in any of the following forms:

active
Indicates the entry that is currently active. If no entry is active then this form is equivalent to none. This form may not be abbreviated.
end
Indicates the bottommost entry in the menu. If there are no entries in the menu then this form is equivalent to none. This form may not be abbreviated.
last
Same as end.
none
Indicates “no entry at all”; this is used most commonly with the activate option to deactivate all the entries in the menu. In most cases the specification of none causes nothing to happen in the widget command. This form may not be abbreviated.
@x,y
Indicates the entry that covers the point in the menu's window specified by x and y (in pixel coordinates). If no entry covers that point, then this form is equivalent to none. If only a single number is specified, it is treated as the y-coordinate.
number
Specifies the entry numerically, where 0 corresponds to the top-most entry of the menu, 1 to the entry below it, and so on.
pattern
If the index does not satisfy one of the above forms then this form is used. Pattern is pattern-matched against the label of each entry in the menu, in order from the top down, until a matching entry is found. The rules of string match are used.

If the index could match more than one of the above forms, then the form earlier in the above list takes precedence.

The following widget commands are possible for menu widgets:

pathName activate index
Change the state of the entry indicated by index to active and redisplay it using its active colors. Any previously-active entry is deactivated. If index is specified as none, or if the specified entry is disabled, then the menu ends up with no active entry. Returns an empty string.
pathName add type ?option value option value ...?
Add a new entry to the bottom of the menu. The new entry's type is given by type and must be one of cascade, checkbutton, command, radiobutton, or separator, or a unique abbreviation of one of the above. If additional arguments are present, they specify the options listed in the MENU ENTRY OPTIONS section below. The add widget command returns an empty string.
pathName cget option
Returns the current value of the configuration option given by option. Option may have any of the standard menu widget options or any of the menu entry options. For menu entry options, the index argument must be specified to indicate which entry's option is to be returned.
pathName delete first ?last?
Delete one or more entries from the menu. first and last are indexes specifying the range of entries to delete. If last is not specified, only the entry indicated by first is deleted. Returns an empty string.
pathName disable index
Disable the entry indicated by index. A disabled entry will appear grayed out and cannot be selected. Returns an empty string.
pathName entrycget index option
Returns the current value of the configuration option option for the specified entry. See the MENU ENTRY OPTIONS section for a list of valid options. See the INDEXES section for a description of index.
pathName entryconfigure index ?option value option value ...?
Modify the configuration options for the specified entry. See the MENU ENTRY OPTIONS section for a list of valid options. See the INDEXES section for a description of index.
pathName find option
Searches the menu for an entry that matches the given option and returns the index of the first matching entry. Returns none if no entry matches. Valid options are:
-active
Find the active entry.
-byvalue value
Find the first entry whose associated variable has the specified value.
-byvariable name
Find the first entry associated with the specified variable name.
pathName get index
Returns the value associated with the entry specified by index. For command and cascade entries, this is an empty string. For checkbutton entries, it is 0 or 1, corresponding to the state of the associated variable. For radiobutton entries, it is the value associated with the entry if it is selected, or an empty string otherwise.
pathName index index
Returns the numerical index corresponding to the specified index. This is useful for converting symbolic indices like active or end into numerical ones.
pathName invoke index
Invokes the command associated with the entry specified by index. This is equivalent to the user selecting the entry. Returns an empty string.
pathName post x y
Posts the menu at the specified screen coordinates x and y. The coordinates are relative to the root window. This command is typically used to display popup menus.
pathName put index
Activates the specified entry, making it the "active" entry for keyboard navigation. Returns an empty string.
pathName scan option
Controls the behavior of the menu during mouse-based scrolling.
scan mark x y
Records the position x, y as the starting point for a scan.
scan dragto x y
Simulates dragging the menu contents. The menu scrolls up or down depending on the direction of the movement from the initial scan mark.
Returns an empty string.
pathName see index
Adjusts the menu's view so that the specified entry is visible. If the entry is already visible, this command does nothing. Returns an empty string.
pathName separator ?option value ...?
Adds a separator line to the bottom of the menu. The available options are the same as for other menu entries, but typically only -background, -foreground, and -relief are meaningful.
pathName subarray first ?last?
Returns a list of lists, where each inner list describes an entry in the menu. The inner lists contain the type of the entry and its configuration options. The first and last arguments specify the range of entries to return. If last is omitted, only the entry specified by first is returned.
pathName type index
Returns the type of the entry specified by index (e.g., cascade, checkbutton, command, radiobutton, separator).
pathName unpost
Unposts the menu if it is currently displayed. Returns an empty string.

CONFIGURACIONES DE MENÚ

Los enlaces predeterminados admiten cuatro formas diferentes de usar menús:

Menús Desplegables en la Barra de Menú
Este es el caso más común. Crea un widget de menú que se convertirá en la barra de menú. Luego, agrega entradas de cascada a este menú, especificando los menús desplegables que desea usar en su barra de menú. Luego, crea todos los menús desplegables. Una vez que haya hecho esto, especifique el menú utilizando la opción -menu del comando del widget toplevel. Consulte la entrada del manual de toplevel para obtener detalles.
Menús Desplegables en Botones de Menú
Esta es la forma compatible de usar barras de menú. Crea un widget de botón de menú para cada menú de nivel superior, y típicamente organiza una serie de botones de menú en una fila en una ventana de barra de menú. También crea los menús de nivel superior y cualquier submenú en cascada, y los une con opciones -menu en los botones de menú y entradas de menú en cascada. El menú de nivel superior debe ser un hijo del botón de menú, y cada submenú debe ser un hijo del menú que lo referencia. Una vez que haya hecho esto, los enlaces predeterminados permitirán a los usuarios navegar e invocar el árbol de menús a través de su botón de menú; consulte la entrada del manual de menubutton para obtener detalles.
Menús Emergentes
Los menús emergentes típicamente se muestran en respuesta a un clic de un botón del ratón o una pulsación de tecla. Crea los menús emergentes y cualquier submenú en cascada, luego llama al procedimiento tk_popup en el momento apropiado para mostrar el menú de nivel superior.
Menús de Opciones
Un menú de opciones consta de un botón de menú con un menú asociado que permite seleccionar uno de varios valores. El valor actual se muestra en el botón de menú y también se almacena en una variable global. Utilice el procedimiento tk_optionMenu para crear botones de menú de opciones y sus menús.
Menús Desprendibles
Crea un menú desprendible invocando la entrada de desprendimiento en la parte superior de un menú existente. Los enlaces predeterminados crearán un nuevo menú que es una copia del menú original y lo dejarán publicado permanentemente como una ventana de nivel superior. El menú desprendible se comporta igual que el menú original.

ENLACES PREDETERMINADOS

Tk crea automáticamente enlaces de clase para los menús que les dan el siguiente comportamiento predeterminado:

[1]
Cuando el ratón entra en un menú, la entrada debajo del cursor del ratón se activa; a medida que el ratón se mueve por el menú, la entrada activa cambia para seguir al ratón.
[2]
Cuando el ratón sale de un menú, todas las entradas del menú se desactivan, excepto en el caso especial en que el ratón se mueve de un menú a un submenú en cascada.
[3]
Cuando se suelta un botón sobre un menú, se invoca la entrada activa (si la hubiera). El menú también se despublica a menos que sea un menú desprendible.
[4]
Las teclas Espacio y Intro invocan la entrada activa y despublican el menú.
[5]
Si alguna de las entradas de un menú tiene letras subrayadas con la opción -underline, entonces al presionar una de las letras subrayadas (o su equivalente en mayúsculas o minúsculas) se invoca esa entrada y se despublica el menú.
[6]
La tecla Escape aborta una selección de menú en curso sin invocar ninguna entrada. También despublica el menú a menos que sea un menú desprendible.
[7]
Las teclas Arriba y Abajo activan la siguiente entrada superior o inferior en el menú. Cuando se alcanza un extremo del menú, la entrada activa vuelve al otro extremo.
[8]
La tecla Izquierda se mueve al siguiente menú a la izquierda. Si el menú actual es un submenú en cascada, entonces el submenú se despublica y la entrada de menú actual se convierte en la entrada de cascada en el padre. Si el menú actual es un menú de nivel superior publicado desde un botón de menú, entonces el botón de menú actual se despublica y se publica el siguiente botón de menú a la izquierda. De lo contrario, la tecla no tiene efecto. El orden izquierdo-derecho de los botones de menú está determinado por su orden de apilamiento: Tk asume que el botón de menú más bajo (que por defecto es el primero en crearse) está a la izquierda.
[9]
La tecla Derecha se mueve al siguiente menú a la derecha. Si la entrada actual es una entrada de cascada, entonces el submenú se publica y la entrada de menú actual se convierte en la primera entrada del submenú. De lo contrario, si el menú actual se publicó desde un botón de menú, entonces el botón de menú actual se despublica y se publica el siguiente botón de menú a la derecha.

Las entradas de menú deshabilitadas no responden: no se activan y ignoran las pulsaciones y liberaciones del botón del ratón.

Varios de los enlaces utilizan el comando tk_menuSetFocus. Este comando guarda el foco actual y establece el foco en el argumento pathName, que es un widget de menú.

El comportamiento de los menús se puede cambiar definiendo nuevos enlaces para widgets individuales o redefiniendo los enlaces de clase.
