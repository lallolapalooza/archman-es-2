Nombre de base de datos:	autoSeparators
Clase de base de datos:	AutoSeparators
Especifica un booleano que indica si se insertan automáticamente separadores en la pila de deshacer. Solo tiene sentido cuando la opción -undo es verdadera.
Nombre de línea de comandos:	-blockcursor
Nombre de base de datos:	blockCursor
Clase de base de datos:	BlockCursor
Especifica un booleano que indica si el cursor de inserción parpadeante debe dibujarse como un bloque del tamaño de un carácter. Si es falso (por defecto), se utiliza una línea vertical delgada para el cursor de inserción.
Nombre de línea de comandos:	-endline
Nombre de base de datos:	endLine
Clase de base de datos:	EndLine
Especifica un índice de línea entero que representa la línea del almacén de texto subyacente que debe estar justo después de la última línea contenida en el widget. Esto permite que un widget de texto refleje solo una porción de un texto más grande. En lugar de un entero, se puede proporcionar la cadena vacía a esta opción de configuración, lo que configurará el widget para que termine en la última línea del almacén de texto.
Nombre de línea de comandos:	-height
Nombre de base de datos:	height
Clase de base de datos:	Height
Especifica la altura deseada para la ventana, en unidades de caracteres de la fuente dada por la opción -font. Debe ser al menos uno.
Nombre de línea de comandos:	-inactiveselectbackground
Nombre de base de datos:	inactiveSelectBackground
Clase de base de datos:	Foreground
Especifica el color a utilizar para la selección (la etiqueta sel) cuando la ventana no tiene el foco de entrada. Si está vacía, {}, entonces no se muestra ninguna selección cuando la ventana no tiene el foco.
Nombre de línea de comandos:	-insertunfocussed
Nombre de base de datos:	insertUnfocussed
Clase de base de datos:	InsertUnfocussed
Especifica cómo mostrar el cursor de inserción cuando el widget no tiene el foco. Debe ser none (por defecto), que significa no mostrar el cursor, hollow que significa mostrar un cuadro hueco, o solid que significa mostrar un cuadro sólido. Tenga en cuenta que hollow y solid aparecerán muy similares cuando la opción -blockcursor sea falsa.
Nombre de línea de comandos:	-maxundo
Nombre de base de datos:	maxUndo
Clase de base de datos:	MaxUndo
Especifica el número máximo de acciones de deshacer compuestas en la pila de deshacer. Un valor cero o negativo implica una pila de deshacer ilimitada.
Nombre de línea de comandos:	-spacing1
Nombre de base de datos:	spacing1
Clase de base de datos:	Spacing1
Solicita espacio adicional encima de cada línea de texto en el widget, utilizando cualquiera de las formas estándar para distancias de pantalla. Si una línea se ajusta, esta opción solo se aplica a la primera línea en la pantalla. Esta opción puede ser anulada con opciones -spacing1 en las etiquetas.

Solicita espacio adicional debajo de cada línea de texto en el widget, utilizando cualquiera de las formas estándar para distancias de pantalla. Si una línea se ajusta, esta opción solo se aplica a la última línea en la pantalla. Esta opción puede ser anulada con opciones -spacing3 en las etiquetas.
Nombre de línea de comandos:	-startline
Nombre de base de datos:	startLine
Clase de base de datos:	StartLine
Especifica un índice de línea entero que representa la primera línea del almacén de texto subyacente que debe contener el widget. Esto permite que un widget de texto refleje solo una porción de un texto más grande. En lugar de un entero, se puede proporcionar la cadena vacía a esta opción de configuración, lo que configurará el widget para que comience en la primera línea del almacén de texto.
Nombre de línea de comandos:	-state
Nombre de base de datos:	state
Clase de base de datos:	State
Especifica uno de los dos estados para el texto: normal o disabled. Si el texto está deshabilitado, no se pueden insertar ni eliminar caracteres y no se mostrará ningún cursor de inserción, incluso si el foco de entrada está en el widget.
Nombre de línea de comandos:	-tabs
Nombre de base de datos:	tabs
Clase de base de datos:	Tabs
Especifica un conjunto de tabulaciones para la ventana. El valor de la opción consiste en una lista de distancias de pantalla que dan las posiciones de las tabulaciones, cada una de las cuales es una distancia relativa al borde izquierdo del widget (excluyendo bordes, relleno, etc.). Cada posición puede ir seguida opcionalmente en el siguiente elemento de la lista de una de las palabras clave left, right, center o numeric, que especifica cómo justificar el texto con respecto a la tabulación. Left es el valor por defecto; hace que el texto que sigue al carácter de tabulación se posicione con su borde izquierdo en la posición de tabulación. Right significa que el borde derecho del texto que sigue al carácter de tabulación se posiciona en la posición de tabulación, y center significa que el texto se centra en la posición de tabulación. Numeric significa que el punto decimal del texto se posiciona en la posición de tabulación; si no hay punto decimal, el dígito menos significativo del número se posiciona justo a la izquierda de la posición de tabulación; si no hay número en el texto, el texto se justifica a la derecha en la posición de tabulación. Por ejemplo, "-tabs {2c left 4c 6c center}" crea tres tabulaciones en intervalos de dos centímetros; las dos primeras usan justificación izquierda y la tercera usa justificación central.

Si la lista de tabulaciones no tiene suficientes elementos para cubrir todas las tabulaciones en una línea de texto, Tk extrapola nuevas tabulaciones utilizando el espaciado y la alineación de la última tabulación de la lista. Las distancias de tabulación deben ser estrictamente positivas y siempre deben aumentar de una tabulación a la siguiente (si no, se genera un error). El valor de la opción -tabs puede ser anulado por opciones -tabs en las etiquetas.

Si no se especifica ninguna opción -tabs, o si se especifica como una lista vacía, entonces Tk utiliza tabulaciones por defecto espaciadas cada ocho caracteres (tamaño promedio). Para lograr un espaciado estándar diferente, por ejemplo cada 4 caracteres, simplemente configure el widget con "-tabs {[expr {4 * [font measure $font 0]}] left} -tabstyle wordprocessor".

Nombre de línea de comandos:	-tabstyle
Nombre de base de datos:	tabStyle
Clase de base de datos:	TabStyle
Especifica cómo interpretar la relación entre las tabulaciones en una línea y las tabulaciones en el texto de esa línea. El valor debe ser tabular (por defecto) o wordprocessor. Tenga en cuenta que las tabulaciones se interpretan a medida que se encuentran en el texto. Si el estilo de tabulación es tabular, entonces el n-ésimo carácter de tabulación en el texto de la línea se asociará con la n-ésima tabulación definida para esa línea. Si la coordenada x del carácter de tabulación cae a la derecha de la n-ésima tabulación, se insertará un espacio como respaldo. Si el estilo de tabulación es wordprocessor, entonces cualquier carácter de tabulación que se esté colocando utilizará (y se definirá por) la primera tabulación a la derecha de
los caracteres precedentes ya dispuestos en esa línea. El valor de la opción -tabstyle puede ser anulado por opciones -tabstyle en las etiquetas. 
Nombre en la línea de comandos:	-undo
Nombre en la base de datos:	undo
Clase de la base de datos:	Undo
Especifica un booleano que indica si el mecanismo de deshacer está activo o no.
Nombre en la línea de comandos:	-width
Nombre en la base de datos:	width
Clase de la base de datos:	Width
Especifica el ancho deseado para la ventana en unidades de caracteres de la fuente dada por la opción -font. Si la fuente no tiene un ancho uniforme, se utiliza el ancho del carácter “0” para la traducción de unidades de caracteres a unidades de pantalla.
Nombre en la línea de comandos:	-wrap
Nombre en la base de datos:	wrap
Clase de la base de datos:	Wrap
Especifica cómo manejar las líneas en el texto que son demasiado largas para ser mostradas en una sola línea de la ventana del texto. El valor debe ser none, char o word. Un modo de ajuste (wrap) none significa que cada línea de texto aparece exactamente como una línea en la pantalla; los caracteres adicionales que no caben en la pantalla no se muestran. En los otros modos, cada línea de texto se dividirá en varias líneas de pantalla si es necesario para mantener todos los caracteres visibles. En el modo char, un salto de línea de pantalla puede ocurrir después de cualquier carácter; en el modo word, un salto de línea solo se hará en los límites de las palabras.

DESCRIPCIÓN

El comando text crea una nueva ventana (dada por el argumento pathName) y la convierte en un widget de texto. Opciones adicionales, descritas anteriormente, pueden especificarse en la línea de comandos o en la base de datos de opciones para configurar aspectos del texto tales como su color de fondo predeterminado y su relieve. El comando text devuelve el nombre de ruta de la nueva ventana.

Un widget de texto muestra una o más líneas de texto y permite que ese texto sea editado. Los widgets de texto soportan cuatro tipos diferentes de anotaciones en el texto, llamadas etiquetas (tags), marcas (marks), ventanas incrustadas (embedded windows) o imágenes incrustadas (embedded images). Las etiquetas permiten que diferentes porciones del texto se muestren con diferentes fuentes y colores. Además, se pueden asociar comandos Tcl con las etiquetas para que los scripts se invoquen cuando ocurren acciones particulares, como pulsaciones de teclas y ratón, en rangos específicos del texto. Ver ETIQUETAS más abajo para más detalles.

La segunda forma de anotación consiste en marcadores flotantes en el texto llamados "marcas". Las marcas se utilizan para mantener un registro de varias posiciones interesantes en el texto a medida que se edita. Ver MARCAS más abajo para más detalles.

La tercera forma de anotación permite incrustar ventanas arbitrarias en un widget de texto. Ver VENTANAS INCRUSTADAS más abajo para más detalles.

La cuarta forma de anotación permite incrustar imágenes Tk en un widget de texto. Ver IMÁGENES INCRUSTADAS más abajo para más detalles.

El widget de texto también tiene un mecanismo de deshacer/rehacer incorporado. Ver EL MECANISMO DE DESHACER más abajo para más detalles.

El widget de texto permite la creación de widgets "peer" (pares). Estos son otros widgets de texto que comparten los mismos datos subyacentes (texto, marcas, etiquetas, imágenes, etc.). Ver WIDGETS PEER más abajo para más detalles.

ÍNDICES

Muchos de los comandos de widget para textos toman uno o más índices como argumentos. Un índice es una cadena utilizada para indicar un lugar particular dentro de un texto, como un lugar para insertar caracteres o un punto final de un rango de caracteres a eliminar. Los índices tienen la sintaxis

base modificador modificador modificador ...
Donde base da un punto de partida y los modificadores ajustan el índice desde el punto de partida (por ejemplo, moverse hacia adelante o hacia atrás un carácter). Cada índice debe contener una base, pero los modificadores son opcionales. La mayoría de los modificadores (como se documenta a continuación) permiten un submodificador opcional. Los submodificadores válidos son any y display. Si el submodificador está abreviado, debe ir seguido de un espacio en blanco, pero de lo contrario, no es necesario ningún espacio entre el submodificador y el siguiente modificador. Típicamente, el submodificador display ajusta el significado del siguiente modificador para que se refiera a unidades visuales o no elididas en lugar de unidades lógicas, pero esto se explica para cada caso relevante a continuación. Por último, donde count se usa como parte de un modificador, puede ser positivo o negativo, por lo que "base - -3 líneas" es perfectamente válido (y equivalente a "base +3líneas").

La base de un índice debe tener una de las siguientes formas:

linea.caracter
Indica el caracter del carácter en la línea linea. Las líneas se numeran desde 1 para consistencia con otros programas UNIX que utilizan este esquema de numeración. Dentro de una línea, los caracteres se numeran desde 0. Si caracter es end, se refiere al carácter de nueva línea que finaliza la línea.
@x,y
Indica el carácter que cubre el píxel cuyas coordenadas x e y dentro de la ventana del texto son x e y.
end
Indica el final del texto (el carácter justo después de la última nueva línea).
marca
Indica el carácter justo después de la marca cuyo nombre es marca (ver MARCAS para detalles).
etiqueta.first
Indica el primer carácter en el texto que ha sido etiquetado con etiqueta. Esta forma genera un error si actualmente no hay caracteres etiquetados con etiqueta.
etiqueta.last
Indica el carácter justo después del último carácter en el texto que ha sido etiquetado con etiqueta. Esta forma genera un error si actualmente no hay caracteres etiquetados con etiqueta.
nombreRuta
Indica la posición de la ventana incrustada cuyo nombre es nombreRuta. Esta forma genera un error si no hay ninguna ventana incrustada con el nombre dado.
nombreImagen
Indica la posición de la imagen incrustada cuyo nombre es nombreImagen. Esta forma genera un error si no hay ninguna imagen incrustada con el nombre dado.

Si la base pudiera coincidir con más de una de las formas anteriores, como una marca y un nombreImagen que tienen el mismo valor, entonces la forma anterior en la lista anterior tiene precedencia. Si los modificadores siguen al índice base, cada uno de ellos debe tener una de las formas listadas a continuación. Palabras clave como chars y wordend pueden abreviarse siempre que la abreviatura sea inequívoca.

+ cuenta ?submodificador? chars
Ajusta el índice hacia adelante en cuenta caracteres, moviéndose a líneas posteriores en el texto si es necesario. Si hay menos de cuenta caracteres en el texto después del índice actual, entonces establece el índice al último índice del texto. Los espacios a cada lado de cuenta son opcionales. Si se proporciona el submodificador display, se omiten los caracteres elididos sin contarlos. Si se proporciona any, se cuentan todos los caracteres. Por razones históricas, si no se proporciona ningún modificador, el recuento se realiza en unidades de posiciones de índice (ver ÍNDICES para más detalles). Este comportamiento puede cambiar en una futura versión principal, por lo que si necesita un recuento de índice, se le anima a usar indices en su lugar siempre que sea posible.
- cuenta ?submodificador? chars
Ajusta el índice hacia atrás en cuenta caracteres, moviéndose a líneas anteriores en el texto si es necesario. Si hay menos de cuenta caracteres en el texto antes del índice actual, entonces establece el índice al primer índice del texto (1.0). Los espacios a cada lado de cuenta son opcionales. Si se proporciona el submodificador display, se omiten los caracteres elididos sin contarlos. Si se proporciona any, se cuentan todos los caracteres. Por razones históricas, si no se proporciona ningún modificador, el recuento se realiza en unidades de posiciones de índice (ver ÍNDICES para más detalles). Este comportamiento puede cambiar en una futura versión principal, por lo que si necesita un recuento de índice, se le anima a usar indices en su lugar siempre que sea posible.
+ cuenta ?submodificador? indices
Ajusta el índice hacia adelante en cuenta posiciones de índice, moviéndose a líneas posteriores en el texto si es necesario. Si hay menos de cuenta posiciones de índice en el texto después del índice actual, entonces establece el índice a la última posición de índice del texto. Los espacios a cada lado de cuenta son opcionales. Tenga en cuenta que una posición de índice es ya sea un solo carácter o una sola imagen o ventana incrustada. Si se proporciona el submodificador display, se omiten los índices elididos sin contarlos. Si se proporciona any, se cuentan todos los índices; este también es el comportamiento predeterminado si no se proporciona ningún modificador.
- cuenta ?submodificador? indices
Ajusta el índice hacia atrás en cuenta posiciones de índice, moviéndose a líneas anteriores en el texto si es necesario. Si hay menos de cuenta posiciones de índice en el texto antes del índice actual, entonces establece el índice a la primera posición de índice (1.0) en el texto. Los espacios a cada lado de cuenta son opcionales. Si se proporciona el submodificador display, se omiten los índices elididos sin contarlos. Si se proporciona any, se cuentan todos los índices; este también es el comportamiento predeterminado si no se proporciona ningún modificador.
+ cuenta ?submodificador? lines
Ajusta el índice hacia adelante en cuenta líneas, conservando la misma posición de carácter dentro de la línea. Si hay menos de cuenta líneas después de la línea que contiene el índice actual, entonces establece el índice para que se refiera a la misma posición de carácter en la última línea del texto. Luego, si la línea no es lo suficientemente larga para contener un carácter en la posición de carácter indicada, ajusta la posición de carácter para que se refiera al último carácter de la línea (la nueva línea). Los espacios a cada lado de cuenta son opcionales. Si se proporciona el submodificador display, cada línea de pantalla visual se cuenta por separado. De lo contrario, si se proporciona any (o ningún modificador), cada línea lógica (sin importar cuántas veces se ajuste visualmente) cuenta solo una vez. Si las líneas relevantes no se ajustan, estos dos métodos de conteo son equivalentes.

TAGS

The first form of annotation is a tag. Tags are named groups of characters. Each character can be a member of any number of tags. Tags can be used to associate attributes with characters (like colors, fonts, or underlining) or to associate event bindings with characters. Tags are created and manipulated using the tag widget command.

The display attributes for a tag are specified using options that have the same names as widget configuration options, prefixed with a dash. For example, the foreground color for a tag is specified with the -foreground option.

-background color
Color specifies the background color to use for characters in this tag. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color specified by the -background widget option is used.
-bgstipple tileName
TileName specifies a stipple pattern to use for the background color. It is specified as a name in the form accepted by Tk_GetSashStipple. If tileName has not been specified, or if it is specified as an empty string, then the background color is drawn solid.
-borderwidth pixels
Pixels specifies the width of the border to draw around characters in this tag. It may have any of the standard forms for screen distances. This option is only used if the -relief option is specified as something other than flat.
-bold
If this option is present, characters in this tag will be displayed in a bold font. This option is a convenience and is equivalent to setting the font family to a bold variant.
-borderrelief relief
Relief specifies the style of the border to draw around characters in this tag. It may have any of the standard forms for border relief: flat, raised, sunken, ridge, or groove. The default is flat.
-dispindent pixels
Pixels specifies the amount of extra indentation to apply to a line if the first non-elided character on that line is part of this tag. This applies only to the first non-elided character on a display line. It can be useful for creating bulleted or numbered lists. It may have any of the standard forms for screen distances.
-elide boolean
Boolean specifies whether or not to elide characters. This option may have any of the forms accepted by Tcl_GetBoolean. When true, the characters are not displayed. This is most useful for implementing features such as folding or hidden text. Note that elided text still occupies space in the widget, and can be selected and modified.
-face fontFamily
FontFamily specifies the font family to use for characters in this tag. If not specified, the default font family is used.
-italic
If this option is present, characters in this tag will be displayed in an italic font. This option is a convenience and is equivalent to setting the font family to an italic variant.
-justify justify
Justify specifies how to align lines of text within the widget. It may have one of the values left, center, or right. This option only applies to a display line if it applies to the first non-elided character on that display line. If this option is specified as an empty string, it cancels the option, leaving it unspecified for the tag (the default).
-leftmargin pixels
Pixels specifies the indentation for the left margin of the text. This applies to all lines that do not have a preceding display indent. It may have any of the standard forms for screen distances.
-offset pixels
Pixels specifies a vertical offset for characters. Positive values move characters up, negative values move them down. This is typically used for creating superscripts and subscripts. It may have any of the standard forms for screen distances.
-overstrike
If this option is present, characters in this tag will be displayed with a line drawn through them.
-relief relief
Relief specifies the border relief to use for the text. This option only applies to a display line if it applies to the first non-elided character on that display line. It may have any of the standard forms for border relief: flat, raised, sunken, ridge, or groove. The default is flat.
-rmargin pixels
Pixels specifies the indentation for the right margin of the text. This applies to all lines that do not have characters extending beyond this margin. It may have any of the standard forms for screen distances.
-rmargincolor color
Color specifies the background color to use in regions that do not contain characters because they are indented by -rmargin. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color used is specified by the -background tag option (or, if this is also unspecified, by the -background widget option).
-selectbackground color
Color specifies the background color to use when displaying selected items. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color specified by the -background tag option is used.
-selectforeground color
Color specifies the foreground color to use when displaying selected items. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color specified by the -foreground tag option is used.
-spacing1 pixels
Pixels specifies how much additional space should be left above each text line, using any of the standard forms for screen distances. If a line wraps, this option only applies to the first line on the display.
-spacing2 pixels
For lines that wrap, this option specifies how much additional space to leave between the display lines for a single text line. Pixels may have any of the standard forms for screen distances.
-spacing3 pixels
Pixels specifies how much additional space should be left below each text line, using any of the standard forms for screen distances. If a line wraps, this option only applies to the last line on the display.
-tabs tabList
TabList specifies a set of tab stops in the same form as for the -tabs option for the text widget. This option only applies to a display line if it applies to the first non-elided character on that display line. If this option is specified as an empty string, it cancels the option, leaving it unspecified for the tag (the default). If the option is specified as a non-empty string that is an empty list, such as -tags { }, then it requests default 8-character tabs as described for the -tags widget option.
-tabstyle style
Style specifies either the tabular or wordprocessor style of tabbing to use for the text widget. This option only applies to a display line if it applies to the first non-elided character on that display line. If this option is specified as an empty string, it cancels the option, leaving it unspecified for the tag (the default).
-underline boolean
Boolean specifies whether or not to draw an underline underneath characters. It may have any of the forms accepted by Tcl_GetBoolean.
-underlinefg color
Color specifies the color to use when displaying the underline. It may have any of the forms accepted by Tk_GetColor. If color has not been specified, or if it is specified as an empty string, then the color specified by the -foreground tag option is used.
-wrap mode
Mode specifies how to handle lines that are wider than the text's window. This option only applies to a display line if it applies to the first non-elided character on that display line. It has the same legal values as the -wrap option for the text widget: none, char, or word. If this tag option is specified, it overrides the -wrap option for the text widget.

If a character has several tags associated with it, and if their display options conflict, then the options of the highest priority tag are used. If a particular display option has not been specified for a particular tag, or if it is specified as an empty string, then that option will never be used; the next-highest-priority tag's option will used instead. If no tag specifies a particular display option, then the default style for the widget will be used.

The second purpose for tags is event bindings. You can associate bindings with a tag in much the same way you can associate bindings with a widget class: whenever particular X events occur on characters with the given tag, a given Tcl command will be executed. Tag bindings can be used to give behaviors to ranges of characters; among other things, this allows hypertext-like features to be implemented. For details, see the description of the “pathName tag bind” widget command below. Tag bindings are shared between all peer widgets (including any bindings for the special sel tag).

The third use for tags is in managing the selection. See THE SELECTION below. With the exception of the special sel tag, all tags are shared between peer text widgets, and may be manipulated on an equal basis from any such widget. The sel tag exists separately and independently in each peer text widget (but any tag bindings to sel are shared).

MARKS

The second form of annotation in text widgets is a mark. Marks are used for remembering particular places in a text. They are something like tags, in that they have names and they refer to places in the file, but a mark is not associated with particular characters. Instead, a mark is associated with the gap between two characters. Only a single position may be associated with a mark at any given time. If the characters around a mark are deleted the mark will still remain; it will just have new neighbor characters. In contrast, if the characters containing a tag are deleted then the tag will no longer have an association with characters in the file. Marks may be manipulated with the “pathName mark” widget command, and their current locations may be determined by using the mark name as an index in widget commands.

Each mark also has a “gravity”, which is either left or right. The gravity for a mark specifies what happens to the mark when text is inserted at the point of the mark. If a mark has left gravity, then the mark is treated as if it were attached to the character on its left, so the mark will remain to the left of any text inserted at the mark position. If the mark has right gravity, new text inserted at the mark position will appear to the left of the mark (so that the mark remains rightmost). The gravity for a mark defaults to right.

The name space for marks is different from that for tags: the same name may be used for both a mark and a tag, but they will refer to different things.

Two marks have special significance. First, the mark insert is associated with the insertion cursor, as described under THE INSERTION CURSOR below. Second, the mark current is associated with the character closest to the mouse and is adjusted automatically to track the mouse position and any changes to the text in the widget (one exception: current is not updated in response to mouse motions if a mouse button is down; the update will be deferred until all mouse buttons have been released). Neither of these special marks may be deleted. With the exception of these two special marks, all marks are shared between peer text widgets, and may be manipulated on an equal basis from any peer.

EMBEDDED WINDOWS

The third form of annotation in text widgets is an embedded window. Each embedded window annotation causes a window to be displayed at a particular point in the text. There may be any number of embedded windows in a text widget, and any widget may be used as an embedded window (subject to the usual rules for geometry management, which require the text window to be the parent of the embedded window or a descendant of its parent).

The embedded window's position on the screen will be updated as the text is modified or scrolled, and it will be mapped and unmapped as it moves into and out of the visible area of the text widget. Each embedded window occupies one unit's worth of index space in the text widget, and it may be referred to either by the name of its embedded window or by its position in the widget's index space. If the range of text containing the embedded window is deleted then the window is destroyed. Similarly if the text widget as a whole is deleted, then the window is destroyed.

Eliding an embedded window immediately after scheduling it for creation via pathName window create index -create will prevent it from being effectively created. WIDGETS PARES

El widget de texto tiene un almacén de datos separado para todo lo relacionado con el contenido textual de cada línea, marcas, etiquetas, imágenes y ventanas, y la pila de deshacer.

Si bien este almacén de datos no es accesible directamente (es decir, sin un widget de texto como intermediario), se pueden crear múltiples widgets de texto, cada uno de los cuales presenta diferentes vistas sobre los mismos datos subyacentes. Dichos widgets de texto se conocen como widgets de texto pares.

A medida que se agrega, elimina, edita y colorea texto en cualquiera de los widgets, y a medida que se ajustan imágenes, marcas y etiquetas, todos estos cambios se reflejarán en todos los pares.

Todos los datos y el marcado se comparten, a excepción de algunos pequeños detalles. Primero, la etiqueta sel puede establecerse y configurarse (en su estilo de visualización) de manera diferente para cada par. Segundo, cada par tiene sus propias posiciones de marca insert y current (pero todas las demás marcas se comparten). Tercero, las ventanas incrustadas, que son otros widgets arbitrarios, no se pueden compartir entre pares. Esto significa que la opción -window de las ventanas incrustadas se establece de forma independiente para cada par (es aconsejable utilizar las capacidades de script -create para permitir que cada par cree sus propias ventanas incrustadas según sea necesario). Cuarto, todas las opciones de configuración de cada par (por ejemplo, -font, etc.) se pueden configurar de forma independiente, con la excepción de -undo, -maxundo, -autoseparators (es decir, todos los problemas de estado de deshacer, rehacer y modificado se comparten).

Finalmente, cualquier par individual no necesita contener todas las líneas del almacén de datos subyacente. Al crear un par, se puede especificar un rango contiguo de líneas (por ejemplo, solo las líneas 52 a 125). Esto permite que un par contenga solo una pequeña porción del texto general. El rango de líneas se expandirá y contraerá a medida que se inserta o elimina texto. El par solo mostrará líneas de texto completas (no se puede compartir solo una parte de una línea). Si el contenido del par se contrae a nada (es decir, todas las líneas completas en el widget par se han eliminado de otro widget), entonces es imposible insertar nuevas líneas. El par simplemente se convertirá en una carcasa vacía en la que se puede configurar el fondo, pero que nunca mostrará ningún contenido (sin reconfiguración manual de las líneas de inicio y fin). Tenga en cuenta que un par que no contenga todo el almacén de datos subyacente todavía tiene índices numerados desde "1.0" hasta "end". Es simplemente que esos índices reflejan un subconjunto de los datos totales, y los datos fuera del rango contenido no son accesibles para el par. Esto significa que el comando peerName index end puede devolver valores bastante diferentes en diferentes pares. De manera similar, los comandos como peerName tag ranges no devolverán rangos de índices fuera de lo que es significativo para el par. Las opciones de configuración -startline y -endline se pueden utilizar para controlar cuánto de los datos subyacentes contiene un widget de texto determinado.

Tenga en cuenta que los pares son realmente pares. Eliminar el widget de texto "original" no provocará la eliminación de ningún otro par, ni les afectará de otra manera.

Ver abajo el comando de widget pathName peer que controla la creación de widgets pares.

ACTUALIZACIÓN ASÍNCRONA DE LAS ALTURAS DE LÍNEA

Para mantener una experiencia de usuario receptiva, el widget de texto calcula las métricas de línea (alturas de línea en píxeles) de forma asíncrona. Debido a esto, algunos comandos del widget de texto pueden devolver resultados incorrectos si los cálculos asíncronos no han finalizado en el momento de la llamada. Esto se aplica a pathName count -ypixels y pathName yview.

Nuevamente, por razones de rendimiento, no sería apropiado permitir que estos comandos esperen siempre el final del cálculo de actualización cada vez que se llaman. En la mayoría de los casos de uso de estos comandos, un resultado más o menos inexacto no es realmente importante en comparación con la velocidad de ejecución.

En caso de que se necesite un resultado preciso (y si el widget de texto está administrado por un gestor de geometría), se puede recurrir a pathName sync y pathName pendingsync para controlar la sincronización de la vista de los widgets de texto.

El evento virtual <<WidgetViewSync>> se activa cuando las alturas de línea del widget de texto se vuelven obsoletas (debido a algún comando de edición o cambio de configuración), y nuevamente cuando los datos internos del widget de texto vuelven a estar sincronizados con la vista del widget. El campo de detalle (%d sustitución) es verdadero (cuando el widget está sincronizado) o falso (cuando no lo está).

pathName sync, pathName pendingsync y <<WidgetViewSync>> se aplican a cada widget de texto independientemente de sus pares.

Ejemplos de uso:

## Ejemplo 1:
# completar métricas de línea inmediatamente a toda costa (GUI no responde)
$w sync
$w yview moveto $fraction
## Ejemplo 2:
# esperar síncronamente métricas de línea actualizadas (GUI responde)
# antes de ejecutar el comando programado, pero sin bloquear el flujo de ejecución
$w sync -command [list $w yview moveto $fraction]
## Ejemplo 3:
# init
set yud($w) 0
proc updateaction w {
set ::yud($w) 1
# cualquier otra acción de actualización aquí...
}
# runtime, esperar síncronamente métricas de línea actualizadas (GUI responde)
$w sync -command [list updateaction $w]
vwait yud($w)
$w yview moveto $fraction
## Ejemplo 4:
# init
set todo($w) {}
proc updateaction w {
foreach cmd $::todo($w) {uplevel #0 $cmd}
set todo($w) {}
}
# runtime
lappend todo($w) [list $w yview moveto $fraction]
$w sync -command [list updateaction $w]
## Ejemplo 5:
# init
set todo($w) {}
bind $w <<WidgetViewSync>> {
if {%d} {
foreach cmd $todo(%W) {eval $cmd}
set todo(%W) {}
}
}
# runtime
if {![$w pendingsync]} {
$w yview moveto $fraction
} else {
lappend todo($w) [list $w yview moveto $fraction]
}

COMANDO DEL WIDGET

El comando text crea un nuevo comando Tcl cuyo nombre es el mismo que el nombre de ruta de la ventana del texto. Este comando se puede utilizar para invocar varias operaciones en el widget. Tiene la siguiente forma general:

pathName option ?arg arg ...?
PathName es el nombre del comando, que es el mismo que el nombre de ruta del widget de texto. Option y los args determinan el comportamiento exacto del comando. Los siguientes comandos son posibles para los widgets de texto:
pathName bbox index
Devuelve una lista de cuatro elementos que describen el área de pantalla del carácter dado por index. Los dos primeros elementos de la lista dan las coordenadas x e y de la esquina superior izquierda del área ocupada por el carácter, y los dos últimos elementos dan el ancho y la altura del área. Si el carácter solo es parcialmente visible en la pantalla, el valor de retorno reflejará solo la parte visible. Si el carácter no es visible en la pantalla, el valor de retorno es una lista vacía.
pathName cget option
Devuelve el valor actual de la opción de configuración dada por option. Option puede tener cualquiera de los valores aceptados por el comando text.
pathName compare index1 op index2
Compara los índices dados por index1 y index2 según el operador relacional dado por op, y devuelve 1 si la relación se cumple y 0 si no. Op debe ser uno de los operadores <, <=, ==, >=, >, o !=. Si op es ==, se devuelve 1 si los dos índices se refieren al mismo carácter, si op es <, se devuelve 1 si index1 se refiere a un carácter anterior en el texto que index2, y así sucesivamente.

Consulta o modifica las opciones de configuración del widget. Si no se especifica ninguna option, devuelve una lista que describe todas las opciones disponibles para pathName (consulte Tk_ConfigureInfo para obtener información sobre el formato de esta lista). Si se especifica option sin value, el comando devuelve una lista que describe la opción con nombre (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica ninguna option). Si se especifican uno o más pares option-value, el comando modifica las opciones del widget dadas para que tengan los valores dados; en este caso, el comando devuelve una cadena vacía. Option puede tener cualquiera de los valores aceptados por el comando text.

cuenta todas las líneas lógicas (independientemente del ajuste) desde la línea del primer índice hasta, pero sin incluir, la línea del segundo índice. Por lo tanto, si ambos están en la misma línea, se devolverá cero. Las líneas lógicas se cuentan si son actualmente visibles (no elididas) o no.
-xpixels
cuenta el número de píxeles horizontales desde el primer píxel del primer índice hasta (pero sin incluir) el primer píxel del segundo índice. Para contar el ancho total deseado del widget de texto (suponiendo que el ajuste no está habilitado), primero encuentra la línea más larga y luego usa ".text count -xpixels "${line}.0" "${line}.0 lineend"".
-ypixels
cuenta el número de píxeles verticales desde el primer píxel del primer índice hasta (pero sin incluir) el primer píxel del segundo índice. Si ambos índices están en la misma línea de visualización, se devolverá cero. Para contar el número total de píxeles verticales en el widget de texto, usa ".text count -ypixels 1.0 end", y para asegurarte de que esté actualizado, usa ".text count -update -ypixels 1.0 end".

El comando devuelve un entero positivo o negativo correspondiente al número de elementos contados entre los dos índices. Se devuelve un entero por cada opción de conteo dada, por lo que se devuelve una lista si se proporcionó más de una opción. Por ejemplo, ".text count -xpixels -ypixels 1.3 4.5" es perfectamente válido y devolverá una lista de dos elementos.

pathName debug ?booleano?
Si se especifica booleano, debe tener uno de los valores verdaderos o falsos aceptados por Tcl_GetBoolean. Si el valor es verdadero, se activarán las comprobaciones internas de consistencia en el código B-tree asociado con los widgets de texto. Si booleano tiene un valor falso, las comprobaciones de depuración se desactivarán. En cualquier caso, el comando devuelve una cadena vacía. Si no se especifica booleano, el comando devuelve on u off para indicar si la depuración está activada o no. Hay un único interruptor de depuración compartido por todos los widgets de texto: activar o desactivar la depuración en cualquier widget la activa o desactiva para todos los widgets. Para widgets con grandes cantidades de texto, las comprobaciones de consistencia pueden causar una ralentización notable.

Cuando la depuración está activada, las rutinas de dibujo del widget de texto establecen las variables globales tk_textRedraw y tk_textRelayout a las listas de índices que se redibujan. Los valores de estas variables son probados por el conjunto de pruebas de Tk.

pathName delete índice1 ?índice2 ...?
Elimina un rango de caracteres del texto. Si se especifican tanto índice1 como índice2, entonces se eliminan todos los caracteres comenzando por el dado por índice1 y terminando justo antes de índice2 (es decir, el carácter en índice2 no se elimina). Si índice2 no especifica una posición posterior en el texto que índice1, entonces no se eliminan caracteres. Si no se especifica índice2, se elimina el único carácter en índice1. Los intentos de eliminar caracteres de una manera que deje el texto sin una nueva línea como último carácter serán ajustados por el widget de texto para evitar esto. En particular, la eliminación de líneas completas de texto hasta el final del texto también eliminará el carácter de nueva línea justo antes del bloque eliminado para que sea reemplazado por la nueva última línea del widget de texto. El comando devuelve una cadena vacía. Si se proporcionan más índices, se eliminarán varios rangos de texto. Todos los índices se verifican primero para verificar su validez antes de realizar cualquier eliminación. Se ordenan y el texto se elimina desde el último rango hasta el primer rango para que el texto eliminado no cause efectos secundarios de desplazamiento de índice no deseados. Si se proporcionan varios rangos con el mismo índice de inicio, se utiliza el rango más largo. Si se proporcionan rangos superpuestos, se fusionarán en tramos que no causen la eliminación de texto fuera de los rangos dados debido al texto desplazado durante la eliminación.
pathName dlineinfo índice
Devuelve una lista con cinco elementos que describen el área ocupada por la línea de visualización que contiene índice. Los dos primeros elementos de la lista dan las coordenadas x e y de la esquina superior izquierda del área ocupada por la línea, los tercer y cuarto elementos dan el ancho y la altura del área, y el quinto elemento da la posición de la línea base para la línea, medida hacia abajo desde la parte superior del área. Toda esta información se mide en píxeles. Si el modo de ajuste actual es none y la línea se extiende más allá de los límites de la ventana, el área devuelta refleja toda el área de la línea, incluidas las porciones que están fuera de la ventana. Si la línea es más corta que el ancho completo de la ventana, el área devuelta refleja solo la porción de la línea que está ocupada por caracteres y ventanas incrustadas. Si la línea de visualización que contiene índice no es visible en la pantalla, el valor de retorno es una lista vacía.
pathName dump ?switches? índice1 ?índice2?
Devuelve el contenido del widget de texto desde índice1 hasta, pero sin incluir, índice2, incluido el texto e información sobre marcas, etiquetas y ventanas incrustadas. Si no se especifica índice2, por defecto será un carácter después de índice1. La información se devuelve en el siguiente formato:

clave1 valor1 índice1 clave2 valor2 índice2 ...

Los posibles valores de clave son text, mark, tagon, tagoff, image y window. El valor correspondiente es el texto, el nombre de la marca, el nombre de la etiqueta, el nombre de la imagen o el nombre de la ventana. La información del índice es el índice de inicio del texto, marca, transición de etiqueta, imagen o ventana. Se pueden especificar una o más de las siguientes opciones (o sus abreviaturas) para controlar el volcado:

-all
Devuelve información sobre todos los elementos: texto, marcas, etiquetas, imágenes y ventanas. Este es el valor predeterminado.
-command comando
En lugar de devolver la información como resultado de la operación de volcado, invoca el comando en cada elemento del widget de texto dentro del rango. El comando tiene tres argumentos añadidos antes de ser evaluado: la clave, el valor y el índice.
-image
Incluye información sobre imágenes en los resultados del volcado.
-mark
Incluye información sobre marcas en los resultados del volcado.
-tag
Incluye información sobre transiciones de etiquetas en los resultados del volcado. La información de etiquetas se devuelve como elementos tagon y tagoff que indican el inicio y el final de cada rango de cada etiqueta, respectivamente.
-text
Incluye información sobre texto en los resultados del volcado. El valor es el texto hasta el siguiente elemento o el final del rango indicado por índice2. Un elemento de texto no abarca nuevas líneas. Un bloque de texto de varias líneas que no contiene marcas ni transiciones de etiquetas se volcará como un conjunto de segmentos de texto que cada uno termina con una nueva línea. La nueva línea es parte del valor.
-window
Incluye información sobre ventanas incrustadas en los resultados del volcado. El valor de una ventana es su nombre de ruta de Tk, a menos que la ventana aún no se haya creado. (Debe tener un script de creación.) En este caso, se devuelve una cadena vacía y debe consultar la ventana por su posición de índice para obtener más información.
pathName edit opción ?arg arg ...?
Este comando controla el mecanismo de deshacer y el indicador de modificado. El comportamiento exacto del comando depende del argumento opción que sigue al argumento edit. Actualmente se admiten las siguientes formas del comando:
pathName edit canredo
Devuelve un booleano verdadero si se puede rehacer, es decir, cuando la pila de rehacer no está vacía. De lo contrario, devuelve falso.
pathName edit canundo
Devuelve un booleano verdadero si se puede deshacer, es decir, cuando la pila de deshacer no está vacía. De lo contrario, devuelve falso.
pathName edit modified ?booleano?
Si no se especifica booleano, devuelve el indicador de modificado del widget. Los comandos de inserción, eliminación, edición de deshacer y edición de rehacer o el usuario pueden establecer o borrar el indicador de modificado. Si se especifica booleano, establece el indicador de modificado del widget a booleano.
pathName edit redo
Cuando la opción -undo es verdadera, vuelve a aplicar las últimas ediciones deshechas siempre que no se hayan realizado otras ediciones desde entonces. Genera un error cuando la pila de rehacer está vacía. No hace nada cuando la opción -undo es falsa.

Borra las pilas de deshacer y rehacer.

Inserta un separador (límite) en la pila de deshacer. No hace nada cuando la opción -undo es falsa.

Deshace la última acción de edición cuando la opción -undo es verdadera. Una acción de edición se define como todos los comandos de inserción y eliminación
que se registran en la pila de deshacer entre dos separadores. Genera un error cuando la pila de deshacer está vacía. No hace nada cuando la opción -undo es falsa.
pathName get ?-displaychars? ?--? index1 ?index2 ...?
Devuelve un rango de caracteres del texto. El valor de retorno serán todos los caracteres del texto que comienzan con el índice index1 y terminan justo antes del índice index2 (el carácter en index2 no se devolverá). Si se omite index2, se devuelve el carácter único en index1. Si no hay caracteres en el rango especificado (por ejemplo, index1 está más allá del final del archivo o index2 es menor o igual a index1), se devuelve una cadena vacía. Si el rango especificado contiene ventanas incrustadas, no se incluye información sobre ellas en la cadena devuelta. Si se proporcionan varios pares de índices, se devolverán varios rangos de texto en una lista. Los rangos no válidos no se representarán con cadenas vacías en la lista. Los rangos se devuelven en el orden en que se pasan a pathName get. Si se proporciona la opción -displaychars, entonces, dentro de cada rango, solo se devolverán aquellos caracteres que no estén omitidos. Esto puede tener el efecto de que algunos de los rangos devueltos sean cadenas vacías.
pathName image option ?arg arg ...?
Este comando se utiliza para manipular imágenes incrustadas. El comportamiento del comando depende del argumento option que sigue al argumento image. Las siguientes formas del comando se soportan actualmente:
pathName image cget index option
Devuelve el valor de una opción de configuración para una imagen incrustada. Index identifica la imagen incrustada, y option especifica una opción de configuración particular, que debe ser una de las listadas en la sección IMÁGENES INCRUSTADAS.

Consulta o modifica las opciones de configuración de una imagen incrustada. Si no se especifica option, devuelve una lista que describe todas las opciones disponibles para la imagen incrustada en index (consulte Tk_ConfigureInfo para obtener información sobre el formato de esta lista). Si se especifica option sin value, el comando devuelve una lista que describe la opción nombrada (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especificó ninguna option). Si se especifican uno o más pares option-value, el comando modifica la(s) opción(es) dada(s) para que tengan el(los) valor(es) dado(s); en este caso, el comando devuelve una cadena vacía. Consulte IMÁGENES INCRUSTADAS para obtener información sobre las opciones que se soportan.
pathName image create index ?option value ...?
Este comando crea una nueva anotación de imagen, que aparecerá en el texto en la posición dada por index. Se puede especificar cualquier número de pares option-value para configurar la anotación. Devuelve un identificador único que puede usarse como índice para referirse a esta imagen. Consulte IMÁGENES INCRUSTADAS para obtener información sobre las opciones que se soportan y una descripción del identificador devuelto.
pathName image names
Devuelve una lista cuyos elementos son los nombres de todas las instancias de imagen actualmente incrustadas en window.
pathName index index
Devuelve la posición correspondiente a index en el formato línea.carácter donde línea es el número de línea y carácter es el número de carácter. Index puede tener cualquiera de los formatos descritos en ÍNDICES arriba.
pathName insert index chars ?tagList chars tagList ...?
Inserta todos los argumentos chars justo antes del carácter en index. Si index se refiere al final del texto (el carácter después de la última nueva línea), el nuevo texto se inserta justo antes de la última nueva línea. Si hay un único argumento chars y ninguna tagList, el nuevo texto recibirá las etiquetas que estén presentes tanto en el carácter anterior como en el carácter posterior al punto de inserción; si una etiqueta está presente solo en uno de estos caracteres, no se aplicará al nuevo texto. Si se especifica tagList, consiste en una lista de nombres de etiquetas; los nuevos caracteres recibirán todas las etiquetas de esta lista y ninguna otra, independientemente de las etiquetas presentes alrededor del punto de inserción. Si hay varios pares de argumentos chars-tagList, producen el mismo efecto que si se hubiera emitido un comando de widget pathName insert separado para cada par, en orden. Se puede omitir el último argumento tagList.
pathName mark option ?arg arg ...?
Este comando se utiliza para manipular marcas. El comportamiento exacto del comando depende del argumento option que sigue al argumento mark. Las siguientes formas del comando se soportan actualmente:
pathName mark gravity markName ?direction?
Si no se especifica direction, devuelve left o right para indicar a cuál de sus caracteres adyacentes está adjunta markName. Si se especifica direction, debe ser left o right; la gravedad de markName se establece en el valor dado.
pathName mark names
Devuelve una lista cuyos elementos son los nombres de todas las marcas que están actualmente establecidas.
pathName mark next index
Devuelve el nombre de la siguiente marca en o después de index. Si index se especifica en forma numérica, la búsqueda de la siguiente marca comienza en ese índice. Si index es el nombre de una marca, la búsqueda de la siguiente marca comienza inmediatamente después de esa marca. Esto aún puede devolver una marca en la misma posición si hay varias marcas en el mismo índice. Estas semánticas significan que la operación mark next se puede usar para recorrer todas las marcas en un widget de texto en el mismo orden que la información de marca devuelta por la operación pathName dump. Si una marca se ha establecido en el índice especial end, entonces parece estar después de end con respecto a la operación pathName mark next. Se devuelve una cadena vacía si no hay marcas después de index.
pathName mark previous index
Devuelve el nombre de la marca en o antes de index. Si index se especifica en forma numérica, la búsqueda de la marca anterior comienza con el carácter justo antes de ese índice. Si index es el nombre de una marca, la búsqueda de la siguiente marca comienza inmediatamente antes de esa marca. Esto aún puede devolver una marca en la misma posición si hay varias marcas en el mismo índice. Estas semánticas significan que la operación pathName mark previous se puede usar para recorrer todas las marcas en un widget de texto en orden inverso al de la información de marca devuelta por la operación pathName dump. Se devuelve una cadena vacía si no hay marcas antes de index.
pathName mark set markName index
Establece la marca llamada markName en una posición justo antes del carácter en index. Si markName ya existe, se mueve de su posición anterior; si no existe, se crea una nueva marca. Este comando devuelve una cadena vacía.
pathName mark unset markName ?markName markName ...?
Elimina la marca correspondiente a cada uno de los argumentos markName. Las marcas eliminadas no serán utilizables en índices y no serán devueltas por llamadas futuras a “pathName mark names”. Este comando devuelve una cadena vacía.
pathName peer option args
Este comando se utiliza para crear y consultar pares de widgets. Tiene dos formas, dependiendo de option:
pathName peer create newPathName ?options?
Crea un widget de texto par con el nombre newPathName dado, y cualquier opción de configuración estándar opcional (como para el comando text). Por defecto, el par tendrá la misma línea de inicio y fin que el widget padre, pero estas se pueden anular con las opciones de configuración estándar.
pathName peer names
Devuelve una lista de los pares de este widget (esto no incluye el propio widget). El orden dentro de esta lista no está definido.
pathName pendingsync
Devuelve 1 si los cálculos de altura de línea no están actualizados, 0 en caso contrario.
pathName replace index1 index2 chars ?tagList chars tagList ...?
Reemplaza el rango de caracteres entre index1 y index2 con los caracteres y etiquetas dados. Consulte la sección sobre pathName insert para una explicación del manejo de los argumentos tagList..., y la sección sobre pathName delete para una explicación del manejo de los índices. Si index2 corresponde a un índice anterior en el texto que index1, se generará un error.

La eliminación y la inserción se organizan de manera que no se produzcan desplazamientos innecesarios de la ventana ni movimientos del cursor de inserción. Además, la pila de deshacer/rehacer se modifica correctamente, si las operaciones de deshacer están activas en el widget de texto. El comando devuelve una cadena vacía.

pathName scan option args
Este comando se utiliza para implementar el escaneo en textos. Tiene dos formas, dependiendo de option:
pathName scan mark x y
Registra x e y y la vista actual en la ventana de texto, para uso en conjunción con comandos posteriores de pathName scan dragto. Típicamente este comando está asociado a una pulsación de botón del ratón en el widget. Devuelve una cadena vacía.
pathName scan dragto x y
Este comando calcula la diferencia entre sus argumentos x e y y los argumentos x e y del último comando pathName scan mark para el widget. Luego ajusta la vista por 10 veces la diferencia en las coordenadas. Este comando está típicamente asociado a eventos de movimiento del ratón en el widget, para producir el efecto de arrastrar el texto a alta velocidad por la ventana. El valor de retorno es una cadena vacía.
pathName search ?switches? pattern index ?stopIndex?
Busca el texto en pathName comenzando en index por un rango de caracteres que coincida con pattern. Si se encuentra una coincidencia, se devuelve el índice del primer carácter de la coincidencia como resultado; de lo contrario, se devuelve una cadena vacía. Se puede especificar uno o más de los siguientes modificadores (o abreviaturas de los mismos) para controlar la búsqueda:
-forwards
La búsqueda procederá hacia adelante a través del texto, encontrando el primer rango coincidente que comience en o después de la posición dada por index. Este es el valor predeterminado.
-backwards
La búsqueda procederá hacia atrás a través del texto, encontrando el rango coincidente más cercano a index cuyo primer carácter esté antes de index (no se permite que esté en index). Tenga en cuenta que, por una variedad de razones, las búsquedas hacia atrás pueden ser sustancialmente más lentas que las búsquedas hacia adelante (particularmente cuando se usa -regexp), por lo que se recomienda que el código crítico para el rendimiento utilice búsquedas hacia adelante.
-exact
Utilizar coincidencia exacta: los caracteres en el rango coincidente deben ser idénticos a los de pattern. Este es el valor predeterminado.
-regexp
Tratar pattern como una expresión regular y coincidirla con el texto utilizando las reglas para expresiones regulares (consulte el comando regexp y la página re_syntax para obtener detalles). La coincidencia predeterminada pasa automáticamente las opciones -lineanchor y -linestop al motor regexp (a menos que se use -nolinestop), de modo que ^$ coincidan con el principio y el final de la línea, y ., [^ las secuencias nunca coincidirán con el carácter de nueva línea \n.
-nolinestop
Esto permite que . y [^ las secuencias coincidan con el carácter de nueva línea \n, lo que de lo contrario no harán (consulte el comando regexp para obtener detalles). Esta opción solo es significativa si también se proporciona -regexp, y de lo contrario se generará un error. Por ejemplo, para coincidir con todo el texto, use “pathName search -nolinestop -regexp ".*" 1.0”.
-nocase
Ignorar las diferencias de mayúsculas y minúsculas entre el patrón y el texto.
-count varName
El argumento que sigue a -count indica el nombre de una variable; si se encuentra una coincidencia, el número de posiciones de índice entre el principio y el final del rango coincidente se almacenará en la variable. Si no hay imágenes o ventanas incrustadas en el rango coincidente (y no hay caracteres elididos si no se proporciona -elide), esto es equivalente al número de caracteres coincidentes. En cualquier caso, el rango matchIdx a matchIdx + $count chars devolverá todo el texto coincidente.
-all
Encontrar todas las coincidencias en el rango dado y devolver una lista de los índices del primer carácter de cada coincidencia. Si se proporciona un modificador -count varName, entonces varName también se establece en una lista que contiene un elemento por cada coincidencia exitosa. Tenga en cuenta que, incluso para búsquedas exactas, los elementos de esta lista pueden ser diferentes, si hay imágenes incrustadas, ventanas o texto oculto. Las búsquedas con -all se comportan de manera muy similar al comando Tcl regexp -all, en el sentido de que las coincidencias superpuestas normalmente no se devuelven. Por ejemplo, aplicar una búsqueda -all del patrón “\w+” contra “hello there” solo coincidirá dos veces, una por cada palabra, y hacer coincidir “Z[a-z]+Z” contra “ZooZooZoo” solo coincidirá una vez.
-overlap
Al realizar búsquedas -all, el comportamiento normal es que las coincidencias que se superponen a una coincidencia ya encontrada no se devuelven. Este modificador cambia ese comportamiento para que se devuelvan todas las coincidencias que no están completamente dentro de otra coincidencia. Por ejemplo, aplicar una búsqueda -overlap del patrón “\w+” contra “hello there” solo coincidirá dos veces (es decir, no es diferente de solo -all), pero hacer coincidir “Z[a-z]+Z” contra “ZooZooZoo” ahora coincidirá dos veces. Se generará un error si se utiliza este modificador sin -all.
-strictlimits
Al realizar cualquier búsqueda, el comportamiento normal es que los límites de inicio y fin se comprueban con respecto al inicio del texto coincidente. Con la bandera -strictlimits, todo el rango coincidente debe estar dentro de los límites de inicio y fin especificados para que la coincidencia sea válida.
-elide
Buscar también texto elidido (oculto). Por defecto, solo se busca el texto mostrado.
--
Este modificador no tiene ningún efecto, excepto terminar la lista de modificadores: el siguiente argumento se tratará como pattern, incluso si comienza con -.

El rango coincidente puede estar dentro de una sola línea de texto, o abarcar varias líneas (si partes del patrón pueden coincidir con una nueva línea). Para la coincidencia de expresiones regulares, se pueden utilizar las diversas características de coincidencia de nuevas líneas como $ para coincidir con el final de una línea, ^ para coincidir con el principio de una línea, y para controlar si . puede coincidir con una nueva línea. Si se especifica stopIndex, la búsqueda se detiene en ese índice: para las búsquedas hacia adelante, no se considerará ninguna coincidencia en o después de stopIndex; para las búsquedas hacia atrás, no se considerará ninguna coincidencia anterior a stopIndex. Si se omite stopIndex, se buscará todo el texto: cuando se alcanza el principio o el final del texto, la búsqueda continúa en el otro extremo hasta que se vuelve a alcanzar la ubicación de inicio; si se especifica stopIndex, no se producirá ninguna envoltura. Esto significa que, por ejemplo, si la búsqueda es -forwards pero stopIndex está más atrás en el texto que startIndex, nunca se encontrará nada. pathName see index
Ajusta la vista en la ventana para que el carácter dado por index sea completamente visible. Si index ya es visible, el comando no hace nada. pathName sync ?-command command?
Controla la sincronización de la vista del widget de texto.

pathName tag option ?arg arg ...?
Este comando se utiliza para manipular etiquetas. El comportamiento exacto del comando depende del argumento option que sigue al argumento tag. Las siguientes formas del comando son actualmente compatibles:
pathName tag add tagName index1 ?index2 index1 index2 ...?

PATHNAME

pathName index first ?last?
Returns a list containing the character indices of the first and last characters in the range first to last. If last is not specified, it defaults to first. The indices in the returned list are suitable for use in other text commands. If the indices are invalid, an error occurs.
pathName insert index ?chars?
Inserts the string chars into the text at the position given by index. If chars is not specified, it defaults to an empty string. If the insertion causes the text to wrap, the insertion point is moved to the beginning of the new line.
pathName mark set markName index
Creates a new mark named markName and associates it with the character at index. Marks are useful for remembering locations in the text. If a mark with the name markName already exists, its position is updated to index. Marks are not deleted when text is inserted or deleted, but they can be explicitly deleted with the mark delete command.
pathName scan mark x y
This command is used in conjunction with the scan dragto command to implement scanning. It records the coordinates x and y as the starting point for a scan. Typically, this is called when mouse button 1 is pressed.
pathName scan dragto x y
This command is used in conjunction with the scan mark command to implement scanning. It computes the distance from the current coordinates x y to the coordinates saved by the last scan mark command. It then scrolls the widget view by that amount. This command is typically called in the event loop when mouse button 1 is dragged.
pathName see index
Adjusts the view in the widget's window so that the character at index is visible. If the character is already visible, the command does nothing. If the character is not visible, the widget attempts to make it visible by scrolling the window.

Adjusts the end of the selection nearest the mouse cursor to the specified index. This command is typically used in conjunction with the scan mark and scan dragto commands to implement selection adjustment.

Clears the selection in the widget. If first and last are specified, only the portion of the selection between first and last is cleared. If only first is specified, then the selection is cleared from first to the end of the selection.

Returns the contents of the selection as a string. If first and last are specified, only the portion of the selection between first and last is returned. XVIEW

pathName xview option args
This command is used to query and change the horizontal position of the text in the widget's window. It can take any of the following forms:
pathName xview
Returns a list containing two elements. Each element is a real fraction between 0 and 1; together they describe the portion of the document's horizontal span that is visible in the window. For example, if the first element is .2 and the second element is .6, 20% of the text is off-screen to the left, the middle 40% is visible in the window, and 40% of the text is off-screen to the right. The fractions refer only to the lines that are actually visible in the window: if the lines in the window are all very short, so that they are entirely visible, the returned fractions will be 0 and 1, even if there are other lines in the text that are much wider than the window. These are the same values passed to scrollbars via the -xscrollcommand option.
pathName xview moveto fraction
Adjusts the view in the window so that fraction of the horizontal span of the text is off-screen to the left. Fraction is a fraction between 0 and 1.
pathName xview scroll number what
This command shifts the view in the window left or right according to number and what. What must be units, pages or pixels. If what is units or pages then number must be an integer, otherwise number may be specified in any of the forms acceptable to Tk_GetPixels, such as “2.0c” or “1i” (the result is rounded to the nearest integer value. If no units are given, pixels are assumed). If what is units, the view adjusts left or right by number average-width characters on the display; if it is pages then the view adjusts by number screenfuls; if it is pixels then the view adjusts by number pixels. If number is negative then characters farther to the left become visible; if it is positive then characters farther to the right become visible.
pathName yview ?args?
This command is used to query and change the vertical position of the text in the widget's window. It can take any of the following forms:
pathName yview
Returns a list containing two elements, both of which are real fractions between 0 and 1. The first element gives the position of the first visible pixel of the first character (or image, etc) in the top line in the window, relative to the text as a whole (0.5 means it is halfway through the text, for example). The second element gives the position of the first pixel just after the last visible one in the bottom line of the window, relative to the text as a whole. These are the same values passed to scrollbars via the -yscrollcommand option.
pathName yview moveto fraction
Adjusts the view in the window so that the pixel given by fraction appears at the top of the top line of the window. Fraction is a fraction between 0 and 1; 0 indicates the first pixel of the first character in the text, 0.33 indicates the pixel that is one-third the way through the text; and so on. Values close to 1 will indicate values close to the last pixel in the text (1 actually refers to one pixel beyond the last pixel), but in such cases the widget will never scroll beyond the last pixel, and so a value of 1 will effectively be rounded back to whatever fraction ensures the last pixel is at the bottom of the window, and some other pixel is at the top.
pathName yview scroll number what
This command adjust the view in the window up or down according to number and what. What must be units, pages or pixels. If what is units or pages then number must be an integer, otherwise number may be specified in any of the forms acceptable to Tk_GetPixels, such as “2.0c” or “1i” (the result is rounded to the nearest integer value. If no units are given, pixels are assumed). If what is units, the view adjusts up or down by number lines on the display; if it is pages then the view adjusts by number screenfuls; if it is pixels then the view adjusts by number pixels. If number is negative then earlier positions in the text become visible; if it is positive then later positions in the text become visible.

ASPECTOS CONOCIDOS

ASPECTOS RELACIONADOS CON CARACTERES E INDICES

Antes de Tk 8.5, el widget usaba la cadena “chars” para referirse a posiciones de índice (que incluían caracteres, ventanas incrustadas e imágenes incrustadas). A partir de Tk 8.5, el widget de texto maneja por separado y correctamente “chars” e “indices”. Sin embargo, para compatibilidad con versiones anteriores, los modificadores de índice “+N chars” y “-N chars” continúan refiriéndose a índices. Se debe usar cualquiera de las formas completas “+N any chars” o “-N any chars” etc. para referirse a índices de caracteres reales. Esta confusión puede ser corregida en una futura versión haciendo que el widget interprete correctamente “+N chars” como un sinónimo de “+N any chars”.

ASPECTOS DE RENDIMIENTO

Los widgets de texto deberían funcionar eficientemente bajo una variedad de condiciones. El widget de texto utiliza aproximadamente 2-3 bytes de memoria principal por cada byte de texto, por lo que textos que contengan un megabyte o más deberían ser prácticos en la mayoría de las estaciones de trabajo. El texto se representa internamente con una estructura de árbol B modificada que hace que las operaciones sean relativamente eficientes incluso con textos grandes. Las etiquetas se incluyen en la estructura del árbol B de manera que permite que las etiquetas abarquen rangos grandes o tengan muchos rangos pequeños y disjuntos sin pérdida de eficiencia. Las marcas también se implementan de manera que permite un gran número de marcas. En la mayoría de los casos, está bien tener un gran número de etiquetas únicas, o una etiqueta que tenga muchos rangos distintos.

Un problema de rendimiento puede surgir si tiene cientos o miles de etiquetas diferentes que comparten las siguientes características: los primeros y últimos rangos de cada etiqueta están cerca del principio y del final del texto, respectivamente, o un único rango de etiqueta cubre la mayor parte del widget de texto. El costo de agregar y eliminar etiquetas de este tipo es proporcional al número de otras etiquetas con las mismas propiedades. En contraste, no hay problema en tener miles de etiquetas distintas si sus rangos generales están localizados y distribuidos uniformemente por todo el texto.

Líneas de texto muy largas pueden ser costosas, especialmente si tienen muchas marcas y etiquetas dentro de ellas.

La línea de visualización con el cursor de inserción se redibuja cada vez que el cursor parpadea, lo que provoca un flujo constante de tráfico gráfico. Establezca el atributo -insertofftime a 0 para evitar esto.

ERRORES CONOCIDOS

El subcomando pathName search -regexp intenta realizar una coincidencia de expresiones regulares sofisticada en múltiples líneas de manera eficiente (desde Tk 8.5), examinando cada línea individualmente, y luego en pequeños grupos de líneas, ya sea buscando hacia adelante o hacia atrás. Bajo ciertas condiciones, el resultado de la búsqueda puede diferir del obtenido al aplicar la misma expresión regular a todo el texto del widget de una sola vez. Por ejemplo, al buscar con una expresión regular codiciosa (greedy), el widget continuará intentando agregar líneas adicionales a la coincidencia siempre que una de dos condiciones sea verdadera: o bien la biblioteca de expresiones regulares de Tcl devuelve un código para indicar que es posible una coincidencia más larga (pero hay errores conocidos en Tcl que significan que este código no siempre se devuelve correctamente); o si cada línea adicional agregada resulta en al menos una coincidencia parcial con el patrón. Esto significa que en el caso en que la primera línea adicional agregada no resulte en ninguna coincidencia y el sistema de expresiones regulares de Tcl devuelva el código incorrecto y agregar una segunda línea adicional realmente coincidiría, el widget de texto devolverá el resultado incorrecto. En la práctica, este es un problema raro, pero puede ocurrir, por ejemplo:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\ncccc\nbbbb\naaaa\n"
.t search -regexp -- {(a+|b+\nc+\nb+)+\na+} 1.0
no encontrará una coincidencia cuando existe una de 19 caracteres que comienza en el primer “b”.

Siempre que una posible coincidencia esté completamente incluida en otra, el comando de búsqueda intentará asegurarse de que solo se devuelva la coincidencia más grande. Al realizar búsquedas de expresiones regulares hacia atrás, es posible que Tcl no siempre logre esto, en el caso en que una coincidencia esté precedida por una o más coincidencias cortas y no superpuestas, todas ellas precedidas por una coincidencia grande que en realidad las abarca a todas. El algoritmo de búsqueda utilizado por el widget no busca arbitrariamente lejos para una posible coincidencia que podría cubrir grandes porciones del widget. Por ejemplo:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\nbbbb\nbbbb\nbbbb\n"
.t search -regexp -backward -- {b+\n|a+\n(b+\n)+} end

    tk_textCopy

    tk_textCopy — Copies and pastes text between the widget and the selection.

    SYNOPSIS

    tk_textCopy widget selection

    DESCRIPTION

    The tk_textCopy command is used to copy text from the widget to the specified selection and paste text from the specified selection to the widget. The widget argument is the name of a Tk text widget. The selection argument is the name of the selection to use, typically PRIMARY or CLIPBOARD.

    The command is used internally by the Tk text widget for cut, copy, and paste operations. It is not intended to be called directly by user applications.

    APPLICABILITY

    The tk_textCopy command is applicable to Tk text widgets.

    WIDGET CONTENTS

    The Tk text widget contains text that can be manipulated by various commands. This includes the ability to copy and paste text to and from selections.

    DATA FORMATS

    The tk_textCopy command handles text data in various formats, including plain text and rich text.
