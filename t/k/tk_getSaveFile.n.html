tk_getOpenFile(n) Comandos integrados de Tk tk_getOpenFile(n)

NOMBRE

tk_getOpenFile, tk_getSaveFile - mostrar un cuadro de diálogo para que el usuario seleccione un archivo para abrir o guardar.

SINOPSIS

tk_getOpenFile ?opción valor ...?
tk_getSaveFile ?opción valor ...?

DESCRIPCIÓN

Los procedimientos tk_getOpenFile y tk_getSaveFile muestran un cuadro de diálogo para que el usuario seleccione un archivo para abrir o guardar. El comando tk_getOpenFile generalmente se asocia con el comando Abrir en el menú Archivo. Su propósito es que el usuario seleccione un archivo existente *solo*. Si el usuario ingresa un archivo que no existe, el cuadro de diálogo le muestra un mensaje de error y requiere que el usuario proporcione una selección alternativa. Si una aplicación permite al usuario crear archivos nuevos, debería hacerlo proporcionando un comando de menú Nuevo separado.

El comando tk_getSaveFile generalmente se asocia con el comando Guardar como en el menú Archivo. Si el usuario ingresa un archivo que ya existe, el cuadro de diálogo solicita al usuario confirmación sobre si el archivo existente debe ser sobrescrito o no.

Los siguientes pares de opción-valor son posibles como argumentos de línea de comandos para estos dos comandos:

-command cadena
Especifica el prefijo de un comando Tcl para invocar cuando el usuario cierra el diálogo después de haber seleccionado un elemento. Esta devolución de llamada no se llama si el usuario canceló el diálogo. El comando real consiste en cadena seguido de un espacio y el valor seleccionado por el usuario en el diálogo. Esto solo está disponible en macOS.
-confirmoverwrite booleano
Configura cómo reacciona el diálogo de Guardar cuando el archivo seleccionado ya existe y al guardarlo se sobrescribiría. Un valor verdadero solicita que se presente un diálogo de confirmación al usuario. Un valor falso solicita que la sobrescritura se realice sin confirmación. El valor predeterminado es verdadero.
-defaultextension extensión
Especifica una cadena que se agregará al nombre del archivo si el usuario ingresa un nombre de archivo sin extensión. El valor predeterminado es una cadena vacía, lo que significa que no se agregará ninguna extensión al nombre del archivo en ningún caso. Esta opción se ignora en macOS, que no requiere extensiones para los nombres de archivo, y la implementación de UNIX adivina valores razonables para esto a partir de la opción -filetypes cuando esta no se proporciona.
-filetypes listaPatronesArchivo
Si existe una lista de Tipos de archivo en el cuadro de diálogo de archivos en la plataforma particular, esta opción proporciona los tiposdearchivo en esta lista. Cuando el usuario elige un tipo de archivo en la lista, solo se listan los archivos de ese tipo. Si esta opción no se especifica, o si se establece en la lista vacía, o si la lista de Tipos de archivo no es compatible con la plataforma particular, entonces se listan todos los archivos independientemente de su tipo. Consulte la sección ESPECIFICACIÓN DE PATRONES DE ARCHIVO a continuación para una discusión sobre el contenido de listaPatronesArchivo.
-initialdir directorio
Especifica que los archivos en directorio se muestren cuando aparezca el diálogo. Si este parámetro no se especifica, el directorio inicial predeterminado es el directorio de trabajo actual en sistemas que no son Windows y en sistemas Windows anteriores a Vista. En sistemas Vista y posteriores, el directorio inicial predeterminado es el último directorio seleccionado por el usuario para la aplicación. Si el parámetro especifica una ruta relativa, el valor de retorno convertirá la ruta relativa a una ruta absoluta.
-initialfile nombrearchivo
Especifica un nombre de archivo que se mostrará en el diálogo cuando aparezca.
-message cadena
Especifica un mensaje para incluir en el área de cliente del diálogo. Esto solo está disponible en macOS.
-multiple booleano
Permite al usuario seleccionar múltiples archivos en el diálogo Abrir.
-parent ventana
Hace que ventana sea el padre lógico del diálogo de archivo. El diálogo de archivo se muestra encima de su ventana padre. En macOS, esto convierte el diálogo de archivo en una hoja adjunta a la ventana padre.
-title cadenaTítulo
Especifica una cadena para mostrar como título del cuadro de diálogo. Si esta opción no se especifica, se muestra un título predeterminado.
-typevariable nombreVariable
La variable global nombreVariable se utiliza para preseleccionar el filtro que se usará de listaFiltros cuando se abra el cuadro de diálogo y se actualiza cuando se cierra el cuadro de diálogo, al último filtro seleccionado. La variable se lee una vez al principio para seleccionar el filtro apropiado. Si la variable no existe, o su valor no coincide con ningún tipo de filtro, o está vacía ({}), el cuadro de diálogo volverá al comportamiento predeterminado de seleccionar el primer filtro de la lista. Si se cancela el diálogo, la variable no se modifica.

Si el usuario selecciona un archivo, tanto tk_getOpenFile como tk_getSaveFile devuelven la ruta completa de este archivo. Si el usuario cancela la operación, ambos comandos devuelven la cadena vacía.

ESPECIFICACIÓN DE PATRONES DE ARCHIVO

El valor listaPatronesArchivo proporcionado por la opción -filetypes es una lista de patrones de archivo. Cada patrón de archivo es una lista del formato

nombreTipo {extensión ?extensión ...?} ?{tipoMac ?tipoMac ...?}?
nombreTipo es el nombre del tipo de archivo descrito por este patrón de archivo y es la cadena de texto que aparece en la lista Tipos de archivo. extensión es una extensión de archivo para este patrón de archivo. tipoMac es un tipo de archivo de Macintosh de cuatro caracteres. La lista de tipoMac es opcional y puede omitirse para aplicaciones que no necesitan ejecutarse en la plataforma Macintosh.

Varios patrones de archivo pueden tener el mismo nombreTipo, en cuyo caso se refieren al mismo tipo de archivo y comparten la misma entrada en la lista. Cuando el usuario selecciona una entrada en la lista, se listan todos los archivos que coinciden con al menos uno de los patrones de archivo correspondientes a esa entrada. Por lo general, cada patrón de archivo corresponde a un tipo de archivo distinto. El uso de más de un patrón de archivo para un tipo de archivo solo es necesario en la plataforma Macintosh.

En la plataforma Macintosh, un archivo coincide con un patrón de archivo si su nombre coincide con al menos una de las extensiones Y pertenece al menos a uno de los tipoMac del patrón de archivo. Por ejemplo, el patrón de archivo Archivos de código fuente C en el código de ejemplo coincide con archivos que tienen una extensión .c Y pertenecen al tipoMac TEXTO. Para usar la regla OR en su lugar, puede usar dos patrones de archivo, uno solo con las extensiones y otro solo con el tipoMac. El tipo de archivo Archivos GIF en el código de ejemplo coincide con archivos que *o* tienen una extensión .gif *o* pertenecen al tipoMac GIFF.

En las plataformas Unix y Windows, un archivo coincide con un patrón de archivo si su nombre coincide con al menos una de las extensiones del patrón de archivo. Los tipoMac se ignoran.

ESPECIFICACIÓN DE EXTENSIONES

En las plataformas Unix y Macintosh, las extensiones se comparan utilizando la coincidencia de patrones estilo glob. En la plataforma Windows, las extensiones son comparadas por el sistema operativo subyacente. Los tipos de extensiones posibles son:

(1)
la extensión especial “*” coincide con cualquier archivo;
(2)
la extensión especial “” coincide con cualquier archivo que no tenga una extensión (es decir, el nombre del archivo no contiene un punto decimal);
(3)
cualquier cadena de caracteres que no contenga caracteres comodín (* y ?).

Debido a las diferentes reglas de coincidencia de patrones en las diversas plataformas, para garantizar la portabilidad, no se permiten caracteres comodín en las extensiones, excepto como en la extensión especial “*”. Las extensiones sin un punto decimal

tk_getOpenFile (3)

NAME

tk_getOpenFile, tk_getSaveFile, tk_getDirectory — get a file name from the user

SYNOPSIS

tk_getOpenFile?options?
tk_getSaveFile?options?
tk_getDirectory?options?

DESCRIPTION

These commands pop up a dialog box allowing the user to select or enter a file name, or to select a directory. The dialog box is implemented using the Tk widget set. The commands return the name of the selected file or directory, or an empty string if the user cancels the operation.

The general form of the commands is:

tk_getOpenFile ?-option value? ?-option value? ...

The available options are:

Command Specific Options

-filetypes ?typelist?
Specifies the types of files that will be displayed in the file selection dialog. This is a list of lists, where each inner list describes a file type. Each file type list can contain one or two elements. The first element is a human-readable description of the file type (e.g., "Text Files"). The second element is a pattern or a list of patterns that specify the file extensions for that file type (e.g., ".txt" or "*.tcl"). If the description is omitted, only the pattern is used. If the pattern is omitted, all files are shown. A special file type with an empty pattern will be used to display files of a specific type. If the type is a single character it will be used to filter by that character. The default is to show all files.
-initialdir ?dirName?
Specifies the initial directory to display in the dialog. If this option is omitted, the current working directory is used.
-initialfile ?fileName?
Specifies the initial file name to display in the dialog. This is useful for pre-filling the file name field when saving a file.
-parent ?window?
Specifies the parent window for the dialog. If this option is omitted, the dialog will be attached to the root window.
-title ?string?
Specifies the title to be displayed in the dialog's title bar.

SPECIFYING FILE PATTERNS

File patterns are used to filter the files displayed in the dialog. The following wildcard characters are supported:

*
Matches any sequence of characters.
?
Matches any single character.
[chars]
Matches any one of the characters in chars.
[^chars]
Matches any character except those in chars.

For example, the pattern *.tcl matches all files with the .tcl extension.

SPECIFYING EXTENSIONS

The -filetypes option can be used to specify a list of file extensions to be displayed. Each entry in the list is a tuple containing a description and a pattern. For example:

set types {
    {{Text Files}       {.txt}        }
    {{TCL Scripts}      {.tcl}        }
    {{C Source Files}   {.c}      TEXT}
    {{GIF Files}        {.gif}        }
    {{GIF Files}        {}        GIFF}
    {{All Files}        *             }
}

In this example, the first file type is "Text Files" and it matches files with the .txt extension. The third file type is "C Source Files" and it matches files with the .c extension. The fifth file type has no description and an empty pattern, which means it will display files with the extension starting with G I F F. The last file type "All Files" matches all files.

The special character sequences like TEXT and GIFF are used to filter files based on their content. These are platform-dependent and may not work on all systems.

EXAMPLE

set types {
    {{Text Files}       {.txt}        }
    {{TCL Scripts}      {.tcl}        }
    {{C Source Files}   {.c}      TEXT}
    {{GIF Files}        {.gif}        }
    {{GIF Files}        {}        GIFF}
    {{All Files}        *             }
}
set filename [tk_getOpenFile -filetypes $types]
if {$filename ne ""} {
    # Open the file ...
}
