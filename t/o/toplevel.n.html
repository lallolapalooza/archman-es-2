NOMBRE

toplevel - Crear y manipular widgets de ventana principal y emergente 'toplevel'

SINOPSIS

toplevel nombreRuta ?opciones?

OPCIONES ESTÁNDAR

-borderwidth	-highlightcolor	-pady
-cursor	-highlightthickness	-relief
-highlightbackground	-padx	-takefocus

Ver la entrada del manual de opciones para más detalles sobre las opciones estándar.

OPCIONES ESPECÍFICAS DEL WIDGET

Nombre en la línea de comandos:	-background
Nombre en la base de datos:	background
Clase en la base de datos:	Background
Esta opción es la misma que la opción estándar -background, excepto que su valor también puede especificarse como una cadena vacía. En este caso, el widget no mostrará fondo ni borde, y no se consumirán colores de su mapa de colores para su fondo y borde.
Nombre en la línea de comandos:	-class
Nombre en la base de datos:	class
Clase en la base de datos:	Class
Especifica una clase para la ventana. Esta clase se utilizará al consultar la base de datos de opciones para las demás opciones de la ventana, y también se utilizará posteriormente para otros fines, como los enlaces. Algunos gestores de ventanas muestran el nombre de la clase para las ventanas en su dock, mientras que otros muestran el título de la ventana. La opción -class no se puede cambiar con el comando de widget configure.
Nombre en la línea de comandos:	-colormap
Nombre en la base de datos:	colormap
Clase en la base de datos:	Colormap
Especifica un mapa de colores a utilizar para la ventana. El valor puede ser new, en cuyo caso se crea un nuevo mapa de colores para la ventana y sus hijos, o el nombre de otra ventana (que debe estar en la misma pantalla y tener la misma representación visual que nombreRuta), en cuyo caso la nueva ventana utilizará el mapa de colores de la ventana especificada. Si no se especifica la opción -colormap, la nueva ventana utiliza el mapa de colores predeterminado de su pantalla. Esta opción no se puede cambiar con el comando de widget configure.
Nombre en la línea de comandos:	-container
Nombre en la base de datos:	container
Clase en la base de datos:	Container
El valor debe ser un booleano. Si es verdadero, significa que esta ventana se utilizará como un contenedor en el que se incrustará alguna otra aplicación (por ejemplo, un toplevel de Tk puede incrustarse usando la opción -use). La ventana admitirá los protocolos del gestor de ventanas apropiados para cosas como las solicitudes de geometría. La ventana no debe tener hijos propios en esta aplicación. Esta opción no se puede cambiar con el comando de widget configure.
Nombre en la línea de comandos:	-height
Nombre en la base de datos:	height
Clase en la base de datos:	Height
Especifica la altura deseada para la ventana en cualquiera de los formatos aceptables por Tk_GetPixels. Si esta opción es menor o igual a cero, la ventana no solicitará ningún tamaño.
Nombre en la línea de comandos:	-menu
Nombre en la base de datos:	menu
Clase en la base de datos:	Menu
Especifica un widget de menú a utilizar como barra de menú. En Macintosh, la barra de menú se mostrará en la parte superior del monitor principal. En Microsoft Windows y todas las plataformas UNIX, el menú aparecerá en la ventana toplevel como parte del adorno de ventana mantenido por el gestor de ventanas.
Nombre en la línea de comandos:	-screen
Nombre en la base de datos:	
Clase en la base de datos:
Especifica la pantalla en la que colocar la nueva ventana. Se puede utilizar cualquier nombre de pantalla válido, incluso uno asociado a una pantalla diferente. Por defecto, utiliza la misma pantalla que su padre. Esta opción es especial ya que no se puede especificar a través de la base de datos de opciones y no se puede modificar con el comando de widget configure.
Nombre en la línea de comandos:	-use
Nombre en la base de datos:	use
Clase en la base de datos:	Use
Esta opción se utiliza para incrustar. Si el valor no es una cadena vacía, debe ser el identificador de ventana de una ventana contenedora, especificado como una cadena hexadecimal como las devueltas por el comando winfo id. El widget toplevel se creará como hijo de la contenedora dada en lugar de la ventana raíz de la pantalla. Si la ventana contenedora está en una aplicación Tk, debe ser un widget frame o toplevel para el cual se especificó la opción -container. Esta opción no se puede cambiar con el comando de widget configure.
Nombre en la línea de comandos:	-visual
Nombre en la base de datos:	visual
Clase en la base de datos:	Visual
Especifica información visual para la nueva ventana en cualquiera de los formatos aceptados por Tk_GetVisual. Si esta opción no se especifica, la nueva ventana utilizará la representación visual predeterminada de su pantalla. La opción -visual no se puede modificar con el comando de widget configure.
Nombre en la línea de comandos:	-width
Nombre en la base de datos:	width
Clase en la base de datos:	Width
Especifica el ancho deseado para la ventana en cualquiera de los formatos aceptables por Tk_GetPixels. Si esta opción es menor o igual a cero, la ventana no solicitará ningún tamaño.

DESCRIPCIÓN

El comando toplevel crea un nuevo widget toplevel (dado por el argumento nombreRuta). Opciones adicionales, descritas arriba, se pueden especificar en la línea de comandos o en la base de datos de opciones para configurar aspectos del toplevel, como su color de fondo y su relieve. El comando toplevel devuelve el nombre de ruta de la nueva ventana.

Un toplevel es similar a un frame, excepto que se crea como una ventana de nivel superior: su padre X es la ventana raíz de una pantalla en lugar del padre lógico de su nombre de ruta Tk. El propósito principal de un toplevel es servir como contenedor para cuadros de diálogo y otras colecciones de widgets. Las únicas características visibles de un toplevel son su color de fondo y un borde 3D opcional para hacer que el toplevel parezca elevado o hundido.

COMANDO WIDGET

El comando toplevel crea un nuevo comando Tcl cuyo nombre es el mismo que el nombre de ruta de la ventana del toplevel. Este comando se puede utilizar para invocar varias operaciones en el widget. Tiene la siguiente forma general:

nombreRuta opción ?arg arg ...?

NombreRuta es el nombre del comando, que es el mismo que el nombre de ruta del widget toplevel. Opción y los args determinan el comportamiento exacto del comando. Los siguientes comandos son posibles para los widgets toplevel:

nombreRuta cget opción
Devuelve el valor actual de la opción de configuración dada por opción. Opción puede tener cualquiera de los valores aceptados por el comando toplevel.
nombreRuta configure ?opción? ?valor opción valor ...?
Consulta o modifica las opciones de configuración del widget. Si no se especifica ninguna opción, devuelve una lista que describe todas las opciones disponibles para nombreRuta (consulte Tk_ConfigureInfo para obtener información sobre el formato de esta lista). Si se especifica opción sin ningún valor, el comando devuelve una lista que describe la opción con ese nombre (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica ninguna opción). Si se especifican uno o más pares opción-valor, el comando modifica las opciones del widget dadas para que tengan los valores dados; en este caso, el comando devuelve una cadena vacía. Opción puede tener cualquiera de los valores aceptados por el comando toplevel.

ENLACES

Cuando se crea un nuevo toplevel, no tiene enlaces de eventos por defecto: los toplevels no están pensados para ser interactivos.

Tenga en cuenta que los enlaces en toplevels pueden recibir eventos de subwidgets.

DESCRIPTION

The toplevel command creates a new top-level window, which is a window that is not part of any other window. It is typically used for dialog boxes, tear-off menus, and other independent windows. The new window is a child of the specified parent window, or of the root window if no parent is specified. The command returns the name of the new top-level window.

The created window can be manipulated using the standard widget commands, such as configure, cget, and destroy.

WIDGET COMMAND

The toplevel command can also be used to query and configure existing top-level windows. When called with an existing top-level window name as the first argument, it behaves like the standard widget command for that window.

BINDINGS

The toplevel widget does not have any built-in bindings.
