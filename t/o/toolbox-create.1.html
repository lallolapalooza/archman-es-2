NOMBRE

toolbox-create - Crear un nuevo contenedor Toolbx

SINOPSIS

toolbox create [--authfile ARCHIVO]
[--distro DISTRO | -d DISTRO]
[--image NOMBRE | -i NOMBRE]
[--release RELEASE | -r RELEASE]
[CONTENEDOR]

DESCRIPCIÓN

Crea un nuevo contenedor Toolbx. Luego puedes usar el comando toolbox enter para interactuar con el contenedor en cualquier momento.

Un contenedor Toolbx es un contenedor OCI creado a partir de una imagen OCI. En Fedora, la imagen predeterminada se conoce como fedora-toolbox:N, donde N es la versión del sistema anfitrión. Si la imagen no está presente localmente, se descarga de un registro conocido como registry.fedoraproject.org. Se pueden usar otras imágenes en otros sistemas operativos anfitriones. Si el anfitrión no es reconocido, se usará la imagen de Fedora.

El contenedor se crea con podman create y su punto de entrada se establece en toolbox init-container.

Por defecto, un contenedor Toolbx se nombra según su imagen correspondiente. Si la imagen tenía una etiqueta, entonces la etiqueta se incluye en el nombre del contenedor, pero se separa por un guion, no por dos puntos. Se puede asignar un nombre diferente usando el argumento CONTENEDOR.

Configuración del contenedor

Un contenedor Toolbx se integra perfectamente con el resto del sistema operativo al proporcionar acceso al directorio personal del usuario, los sockets de Wayland y X11, la red (incluido Avahi), dispositivos extraíbles (como memorias USB), el journal de systemd, el agente SSH, D-Bus, ulimits, /dev y la base de datos de udev, etc.

El ID de usuario y los detalles de la cuenta del anfitrión se propagan al contenedor Toolbx, se deshabilita la separación de etiquetas SELinux y el sistema de archivos del anfitrión puede ser accedido por el contenedor en /run/host. El contenedor tiene acceso a las credenciales Kerberos del anfitrión si está configurado para usar cachés KCM.

Un contenedor Toolbx puede ser identificado por la etiqueta com.github.containers.toolbox o el archivo /run/.toolboxenv.

El punto de entrada de un contenedor Toolbx es el comando toolbox init-container, que juega un papel en la configuración del contenedor, junto con las opciones pasadas a podman create.

Punto de entrada

Una característica clave de los contenedores Toolbx es su punto de entrada, el comando toolbox init-container.

Los contenedores OCI son inherentemente inmutables. Las opciones de configuración pasadas a través de podman create se incorporan a la definición del contenedor OCI y no se pueden cambiar más tarde. Esto significa que los cambios y mejoras realizados en versiones más recientes de Toolbx no se pueden aplicar a contenedores Toolbx preexistentes creados por versiones anteriores de Toolbx. Esto se evita utilizando el punto de entrada para configurar el contenedor en tiempo de ejecución.

El punto de entrada de un contenedor Toolbx personaliza el contenedor para que se ajuste al usuario actual asegurando que tenga un usuario que coincida con el del anfitrión y le otorga acceso sudo y root.

Archivos de configuración cruciales, como /etc/host.conf, /etc/hosts, /etc/localtime, /etc/resolv.conf y /etc/timezone, dentro del contenedor se mantienen sincronizados con el anfitrión. El punto de entrada también monta enlazados varios subconjuntos de la jerarquía del sistema de archivos del anfitrión a sus ubicaciones correspondientes dentro del contenedor para proporcionar una integración perfecta con el anfitrión. Esto incluye /run/libvirt, /run/systemd/journal, /run/udev/data, /var/lib/libvirt, /var/lib/systemd/coredump, /var/log/journal y otros.

En algunos sistemas operativos anfitriones, rutas importantes como /home, /media o /mnt son enlaces simbólicos a otras ubicaciones. El punto de entrada asegura que las rutas dentro del contenedor coincidan con las del anfitrión, para evitar confusiones innecesarias.

OPCIONES

--authfile ARCHIVO

Ruta a un ARCHIVO con credenciales para autenticarse en el registro para imágenes privadas. El ARCHIVO generalmente se establece usando podman login y será utilizado por podman pull para obtener la imagen.

La ubicación predeterminada para ARCHIVO es $XDG_RUNTIME_DIR/containers/auth.json y su formato se especifica en containers-auth.json(5).

--distro DISTRO, -d DISTRO

Crea un contenedor Toolbx para un sistema operativo DISTRO diferente al del anfitrión. No se puede usar con --image. Debe ir acompañado de --release a menos que el DISTRO seleccionado coincida con el anfitrión.

--image NOMBRE, -i NOMBRE

Cambia el NOMBRE de la imagen utilizada para crear el contenedor Toolbx. Esto es útil para crear contenedores a partir de imágenes creadas personalmente. No se puede usar con --distro y --release.

Si NOMBRE no contiene un registro, se consultará el almacenamiento local de imágenes y, si no está presente allí, se descargará de un registro remoto adecuado.

--release RELEASE, -r RELEASE

Crea un contenedor Toolbx para una versión RELEASE de sistema operativo diferente a la del anfitrión. No se puede usar con --image.

EJEMPLOS

Crear el contenedor Toolbx predeterminado que coincide con el SO anfitrión

$ toolbox create

Crear el contenedor Toolbx predeterminado para Fedora 36

$ toolbox create --distro fedora --release f36

Crear un contenedor Toolbx personalizado a partir de una imagen personalizada

$ toolbox create --image bar foo

Crear un contenedor Toolbx personalizado a partir de una imagen personalizada que es privada

$ toolbox create --authfile ~/auth.json --image registry.example.com/bar
