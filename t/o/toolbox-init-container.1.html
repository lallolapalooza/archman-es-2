NOMBRE

toolbox-init-container - Inicializa un contenedor en ejecución

SINOPSIS

toolbox init-container --gid GID
--home HOME
--home-link
--media-link
--mnt-link
--shell SHELL
--uid UID
--user USER

DESCRIPCIÓN

Inicializa un contenedor recién creado que está en ejecución. Está pensado principalmente para ser utilizado como punto de entrada para todos los contenedores de Toolbx, y debe ejecutarse dentro del contenedor que se va a inicializar. No se espera que sea invocado directamente por humanos, y no se puede usar en el host.

Una característica clave de los contenedores de Toolbx es su punto de entrada, el comando toolbox init-container.

Los contenedores OCI son inherentemente inmutables. Las opciones de configuración pasadas a través de podman create se integran en la definición del contenedor OCI, y no se pueden cambiar más tarde. Esto significa que los cambios y mejoras realizados en versiones más recientes de Toolbx no se pueden aplicar a contenedores de Toolbx preexistentes creados por versiones anteriores de Toolbx. Esto se evita utilizando el punto de entrada para configurar el contenedor en tiempo de ejecución.

El punto de entrada de un contenedor de Toolbx personaliza el contenedor para que se ajuste al usuario actual asegurando que tenga un usuario que coincida con el del host, y le otorga acceso sudo y root.

Archivos de configuración cruciales, como /etc/host.conf, /etc/hosts, /etc/localtime, /etc/resolv.conf y /etc/timezone, dentro del contenedor se mantienen sincronizados con el host. El punto de entrada también monta enlaces a varios subconjuntos de la jerarquía del sistema de archivos del host en sus ubicaciones correspondientes dentro del contenedor para proporcionar una integración fluida con el host. Esto incluye /run/libvirt, /run/systemd/journal, /run/udev/data, /var/lib/libvirt, /var/lib/systemd/coredump, /var/log/journal y otros.

En algunos sistemas operativos host, rutas importantes como /home, /media o /mnt son enlaces simbólicos a otras ubicaciones. El punto de entrada asegura que las rutas dentro del contenedor coincidan con las del host, para evitar confusiones innecesarias.

OPCIONES

Se entienden las siguientes opciones:

--gid GID

Pasa GID como el ID de grupo numérico del usuario del host al contenedor de Toolbx.

--home HOME

Crea un usuario dentro del contenedor de Toolbx cuyo directorio de inicio sea HOME. Esta opción es obligatoria.

--home-link

Convierte /home en un enlace simbólico a /var/home.

--media-link

Convierte /media en un enlace simbólico a /run/media.

--mnt-link

Convierte /mnt en un enlace simbólico a /var/mnt.

--monitor-host

Obsoleto, no hace nada.

Los archivos de configuración cruciales dentro del contenedor de Toolbx siempre se mantienen sincronizados con sus contrapartes en el host, y varios subconjuntos del sistema de archivos del host siempre se montan mediante enlaces a sus ubicaciones correspondientes dentro del contenedor de Toolbx.

--shell SHELL

Crea un usuario dentro del contenedor de Toolbx cuyo shell de inicio sea SHELL. Esta opción es obligatoria.

--uid UID

Crea un usuario dentro del contenedor de Toolbx cuyo ID de usuario numérico sea UID. Esta opción es obligatoria.

--user USER

Crea un usuario dentro del contenedor de Toolbx cuyo nombre de inicio sea LOGIN. Esta opción es obligatoria.
