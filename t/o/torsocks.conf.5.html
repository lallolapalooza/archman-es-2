NOMBRE

torsocks.conf — Archivo de configuración para torsocks(8)

RESUMEN

Por defecto, torsocks asumirá que debe conectarse al proxy SOCKS de Tor ejecutándose en 127.0.0.1 en el puerto 9050. Esta es la dirección y puerto por defecto para el servidor socks de Tor en la mayoría de las instalaciones. Si estás ejecutando una instalación normal de Tor y no tienes requisitos especiales, entonces no deberías necesitar crear, editar o invocar un archivo de configuración al usar torsocks.

Tu instalación de torsocks incluye un archivo de configuración por defecto que contiene valores sensatos para usar con la mayoría de las instalaciones de Tor. La ubicación de instalación de tu archivo de configuración por defecto es:

/etc/tor/torsocks.conf

Para poder usar un archivo de configuración, debes establecer la variable de entorno TORSOCKS_CONF_FILE con la ubicación del archivo.

Si TORSOCKS_CONF_FILE no está establecida, torsocks intentará leer el archivo de configuración en /etc/tor/torsocks.conf. Si ese archivo no se puede leer, torsocks usará valores por defecto sensatos para la mayoría de las instalaciones de Tor, es decir, asumirá que deseas usar un proxy SOCKS ejecutándose en 127.0.0.1 (localhost) en el puerto 9050.

CONFIGURACIÓN

SINTAXIS

La estructura básica de todas las líneas en el archivo de configuración es:

<directiva> <parámetros>

Las líneas vacías se ignoran y toda la entrada en una línea después de un carácter '#' se ignora.

DIRECTIVAS

Las siguientes directivas se utilizan en el archivo de configuración de torsocks:

TorAddress ip_addr
La dirección IP del servidor SOCKS de Tor (ej. "server = 10.1.4.253"). Solo se puede especificar un servidor. Actualmente, torsocks NO soporta nombres de host. (por defecto: 127.0.0.1)
TorPort puerto
El puerto en el que el servidor SOCKS de Tor recibe peticiones. (por defecto: 9050)
OnionAddrRange subred/máscara
Los sitios ocultos de Tor no tienen direcciones IP reales. Esto especifica qué rango de direcciones IP se entregarán a la aplicación como "cookies" para nombres .onion. Por supuesto, debes elegir un bloque de direcciones al que nunca vayas a necesitar conectarte realmente. Esto es similar a la característica MapAddress del demonio principal de tor. (por defecto: 127.42.42.0/24)
SOCKS5Username nombre_usuario
Nombre de usuario a utilizar para el método de autenticación SOCKS5 que hace que las conexiones a Tor utilicen un circuito diferente al de otros flujos existentes. Si se establece, también se debe especificar SOCKS5Password. (Por defecto: ninguno).
SOCKS5Password contraseña
Contraseña a utilizar para el método de autenticación SOCKS5 que hace que las conexiones a Tor utilicen un circuito diferente al de otros flujos existentes. Si se establece, también se debe especificar SOCKS5Username. (Por defecto: ninguno).
AllowInbound 0|1
Permitir conexiones entrantes, lo que significa que listen() y accept()/accept4() se permitirán para direcciones distintas de localhost, de modo que la aplicación pueda manejar conexiones entrantes. Nota: los sockets Unix están permitidos. (Por defecto: 0)
AllowOutboundLocalhost 0|1|2
Permitir conexiones salientes a la interfaz de bucle invertido, lo que significa que connect() se permitirá para conectarse a direcciones localhost omitiendo Tor. Si se establece en 1, se permitirán conexiones TCP. Si se establece en 2, se permitirán tanto conexiones TCP/IP como UDP. Esta opción no debe ser utilizada por la mayoría de los usuarios. (Por defecto: 0)
IsolatePID 0|1
Establece Torsocks para usar un nombre de usuario/contraseña SOCKS5 generado automáticamente basado en el ID del proceso y la hora actual, lo que hace que las conexiones a Tor utilicen un circuito diferente al de otros flujos existentes en Tor por proceso. Si se establece, las opciones SOCKS5Username y SOCKS5Password no deben establecerse. (Por defecto: 0)

EJEMPLO


$ export TORSOCKS_CONF_FILE=$PWD/torsocks.conf
$ torsocks ssh cuenta@servidorssh.com
