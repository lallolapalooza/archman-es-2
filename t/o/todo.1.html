listar

Lista tareas (predeterminado). Filtra las tareas completadas o canceladas por defecto.

Si no se proporcionan argumentos, se mostrarán todas las listas y solo se mostrarán las tareas incompletas. De lo contrario, solo se mostrarán las tareas de la lista especificada.

ej:
? - todo listar muestra todas las tareas no terminadas de todas las listas. - `todo listar trabajo muestra todas las tareas no terminadas de la lista `trabajo'.

Esta es la acción predeterminada al ejecutar

`
todo'.

Los siguientes comandos pueden filtrar aún más las tareas mostradas, o incluir aquellas omitidas por defecto:

DESCRIPTION

Todoman is a simple, standards-based, cli todo (aka: task) manager. Todos are stored into icalendar files, which means you can sync them via CalDAV using, for example, vdirsyncer.

USAGE

The default action is list, which outputs all tasks for all calendars, each with a semi-permanent unique id:

1 [ ] !!! 2015-04-30 Close bank account @work (0%)
2 [ ] !              Send minipimer back for warranty replacement @home (0%)
3 [X]     2015-03-29 Buy soy milk @home (100%)
4 [ ] !!             Fix the iPad's screen @home (0%)
5 [ ] !!             Fix the Touchpad battery @work (0%)

The columns, in order, are:

  • An id.
  • Whether the task has been completed or not.
  • An !!! indicating high priority, !! indicating medium priority, ! indicating low priority tasks.
  • The due date.
  • The task summary.
  • The list the todo is from; it will be hidden when filtering by one list, or if the database only contains a single list.
  • The completed percentage.

The id is retained by todoman until the next time you run the flush command.

To operate on a todo, the id is what's used to reference it. For example, to edit the Buy soy milk task from the example above, the proper command is todo edit 3, or todo undo 3 to un-mark the task as done.

Editing tasks can only be done via the TUI interface for now, and cannot be done via the command line yet.

INTEGRATIONS

When attempting to integrate todoman into other systems or parse its output, you're advised to use the --porcelain flag, which will print all output in a pre-defined format that will remain stable regardless of user configuration or version.

The format is JSON, with a single array containing each todo as a single entry (object). Fields will always be present; if a todo does not have a value for a given field, it will be printed as null.

Fields MAY be added in future, but will never be removed.

Conky

Adding ${execi 30 todo} inside the text section will display the output of the command and update it every 30 seconds.

SORTING

The tasks can be sorted with the --sort argument. Sorting may be done according to the following fields:

  • description
  • location
  • status
  • summary
  • uid
  • rrule
  • percent_complete
  • priority
  • sequence
  • categories
  • completed_at
  • created_at
  • dtstamp
  • start
  • due
  • last_modified

It is possible to prepend a - to a field to sort by that field in ascending order (by default they are sorted in descending order).

Example:

todo list --sort due,-priority

NAME

todo - una utilidad para gestionar listas de tareas pendientes

TODO

Este es un archivo de documentación muy básico. Por favor, siéntete libre de enviarme un parche para mejorarlo.

DESCRIPTION

El comando «todo» es una herramienta de línea de comandos para la gestión de listas de tareas pendientes. Permite añadir, eliminar, completar, listar y buscar tareas. También admite la priorización de tareas, el establecimiento de fechas límite y la organización de tareas en proyectos.

USAGE

todo [comando] [opciones]

Comandos disponibles:

  • add: Añade una nueva tarea.
  • list: Lista las tareas pendientes.
  • done: Marca una tarea como completada.
  • remove: Elimina una tarea.
  • search: Busca tareas.
  • projects: Lista los proyectos disponibles.

Opciones:

  • -p, --project <nombre>: Especifica el proyecto de la tarea.
  • -d, --due <fecha>: Establece la fecha límite de la tarea.
  • -P, --priority <prioridad>: Establece la prioridad de la tarea.

SYNCHRONIZATION

La utilidad «todo» se puede sincronizar con varios servicios en la nube, como Dropbox o Google Drive, para mantener las listas de tareas pendientes actualizadas en todos los dispositivos. La configuración de la sincronización se realiza a través del archivo de configuración.

INTERACTIVE SHELL

«todo» proporciona un shell interactivo que permite ejecutar comandos sin tener que escribir el nombre del comando repetidamente. Para iniciar el shell interactivo, ejecuta: todo shell.

INTEGRATIONS

«todo» se puede integrar con otras herramientas y servicios, como clientes de correo electrónico y aplicaciones de calendario, para crear un flujo de trabajo más eficiente.

SORTING

Las tareas se pueden ordenar de varias maneras, como por fecha límite, prioridad o fecha de creación. La opción de ordenación se puede especificar al listar las tareas: todo list --sort due.

CONFIGURING

La configuración de «todo» se realiza a través de un archivo de configuración. Este archivo permite personalizar el comportamiento de la utilidad, como las opciones de sincronización, las integraciones y la apariencia.

CONFIGURATION FILE

El archivo de configuración se encuentra en ~/.config/todo/config.yaml. Si el archivo no existe, se creará con valores predeterminados cuando se ejecute el comando por primera vez.

SAMPLE CONFIGURATION

sync:
  provider: dropbox
  token: YOUR_DROPBOX_TOKEN

projects:
  - name: Work
    color: blue
  - name: Personal
    color: green

timezone: Europe/Madrid

COLOR AND DISPLAYNAME

Puedes asignar colores y nombres de visualización a los proyectos en el archivo de configuración. Esto ayuda a distinguir visualmente las tareas de diferentes proyectos.

TIMEZONE

Establece tu zona horaria en el archivo de configuración para asegurar que las fechas límite y las horas se muestren correctamente.

CAVEATS

Ten en cuenta que la sincronización con servicios en la nube puede introducir latencia. Se recomienda realizar copias de seguridad periódicas de tus datos.

CONTRIBUTING

Se aceptan contribuciones. Por favor, consulta el archivo CONTRIBUTING.md en el repositorio del proyecto para más detalles.
