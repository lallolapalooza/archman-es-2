NOMBRE

toolbox - Herramienta para entornos interactivos de línea de comandos en Linux

SINOPSIS

toolbox [--assumeyes | -y]
[--help | -h]
[--log-level NIVEL]
[--log-podman]
[--verbose | -v]
COMANDO [ARGUMENTOS...]

DESCRIPCIÓN

Toolbx es una herramienta para Linux que permite el uso de entornos interactivos de línea de comandos para el desarrollo de software y la resolución de problemas del sistema operativo anfitrión, sin necesidad de instalar software en el anfitrión. Está construida sobre Podman y otras tecnologías de contenedores estándar de OCI.

Los entornos de Toolbx tienen acceso transparente al directorio `home` del usuario, a los sockets Wayland y X11, a la red (incluyendo Avahi), a dispositivos extraíbles (como memorias USB), al journal de systemd, al agente SSH, D-Bus, ulimits, /dev y la base de datos udev, etc..

Esto es particularmente útil en sistemas operativos basados en OSTree como Fedora CoreOS y Silverblue. La intención de estos sistemas es desalentar la instalación de software en el anfitrión, y en su lugar instalar software como (o en) contenedores — en su mayoría, ni siquiera tienen gestores de paquetes como DNF o YUM. Esto hace que sea difícil configurar un entorno de desarrollo o solucionar problemas del sistema operativo de la manera habitual.

Toolbx resuelve este problema proporcionando un contenedor totalmente mutable dentro del cual se puede instalar el desarrollo favorito y las herramientas de solución de problemas, editores y SDKs. Por ejemplo, es posible hacer yum install ansible sin afectar al sistema operativo base.

Sin embargo, esta herramienta no *requiere* usar un sistema basado en OSTree. Funciona igual de bien en Fedora Workstation y Server, y es una forma útil de adoptar gradualmente la contenerización.

El entorno de Toolbx se basa en una imagen OCI. En Fedora, esta es la imagen fedora-toolbox. Esta imagen se utiliza para crear un contenedor de Toolbx que ofrece el entorno interactivo de línea de comandos.

Tenga en cuenta que Toolbx no ofrece ninguna garantía de seguridad más allá de lo que ya está disponible en el entorno de línea de comandos habitual en el anfitrión con el que todo el mundo está familiarizado.

Distribuciones de sistema operativo soportadas

Por defecto, Toolbx intenta usar una imagen que coincida con la distribución del sistema operativo anfitrión para crear contenedores. Si el anfitrión no es compatible, recurre a una imagen de Fedora. Los sistemas operativos anfitriones compatibles son:

  • Arch Linux
  • Fedora
  • Red Hat Enterprise Linux >= 8.5
  • Ubuntu

Sin embargo, es posible crear contenedores para una distribución diferente mediante el uso de las opciones --distro y --release que son aceptadas por los comandos relevantes, o sus contrapartes en el archivo de configuración. El indicador --distro especifica el nombre de la distribución, y --release especifica su versión. Las combinaciones admitidas son:

Distribución Versión
arch latest o rolling
fedora <versión> o f<versión>, por ejemplo, 36 o f36
rhel <mayor>.<menor>, por ejemplo, 8.5
ubuntu <AA>.<MM>, por ejemplo, 22.04

USO

Crear un contenedor de Toolbx:

[usuario@hostname ~]$ toolbox create
Se requiere una imagen para crear el contenedor de toolbox.
¿Descargar registry.fedoraproject.org/fedora-toolbox:36 (294.1MB)? [s/N]: s
Contenedor creado: fedora-toolbox-36
Entrar con: toolbox enter
[usuario@hostname ~]$

Entrar en el contenedor de Toolbx:

[usuario@hostname ~]$ toolbox enter
⬢[usuario@toolbox ~]$

Eliminar el contenedor de Toolbx:

[usuario@hostname ~]$ toolbox rm fedora-toolbox-36
[usuario@hostname ~]$

OPCIONES GLOBALES

Se reconocen las siguientes opciones:

--assumeyes, -y

Responder automáticamente sí a todas las preguntas.

--help, -h

Imprimir una sinopsis de este manual y salir.

--log-level=nivel

Registrar mensajes por encima del nivel especificado: debug, info, warn, error, fatal o panic (por defecto: error)

--log-podman

Mostrar mensajes de registro de las invocaciones de Podman basadas en el nivel de registro especificado por la opción log-level.

--verbose, -v

Igual que --log-level=debug. Usa -vv para incluir --log-podman.

COMANDOS

Comandos para trabajar con contenedores e imágenes de Toolbx:

toolbox-create(1)

Crear un nuevo contenedor de Toolbx.

toolbox-enter(1)

Entrar en un contenedor de Toolbx para uso interactivo.

toolbox-help(1)

Mostrar información de ayuda sobre Toolbx.

toolbox-init-container(1)

Inicializar un contenedor en ejecución.

toolbox-list(1)

Listar contenedores e imágenes de Toolbx existentes.

toolbox-rm(1)

Eliminar uno o más contenedores de Toolbx.

toolbox-rmi(1)

Eliminar una o más imágenes de Toolbx.

toolbox-run(1)

Ejecutar un comando en un contenedor de Toolbx existente.
