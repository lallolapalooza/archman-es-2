DESCRIPCIÓN

Python es un lenguaje de programación interpretado, interactivo y orientado a objetos que combina una notable potencia con una sintaxis muy clara. Para una introducción a la programación en Python, consulta el Tutorial de Python. La Referencia de la Biblioteca de Python documenta los tipos, constantes, funciones y módulos integrados y estándar. Finalmente, el Manual de Referencia de Python describe la sintaxis y la semántica del lenguaje central con (quizás demasiados) detalles. (Estos documentos pueden encontrarse a través de los RECURSOS DE INTERNET a continuación; también pueden estar instalados en tu sistema.)

La potencia básica de Python puede extenderse con tus propios módulos escritos en C o C++. En la mayoría de los sistemas, dichos módulos pueden cargarse dinámicamente. Python también es adaptable como lenguaje de extensión para aplicaciones existentes. Consulta la documentación interna para obtener pistas.

La documentación de los módulos y paquetes de Python instalados se puede ver ejecutando el programa pydoc.

OPCIONES DE LÍNEA DE COMANDOS

-B
No escribir archivos .pyc al importar. Ver también PYTHONDONTWRITEBYTECODE.
-b
Emitir advertencias sobre str(instancia_bytes), str(instancia_bytearray) y comparaciones de bytes/bytearray con str. (-bb: emitir errores)
-c comando
Especifica el comando a ejecutar (ver siguiente sección). Esto termina la lista de opciones (las opciones siguientes se pasan como argumentos al comando).
--check-hash-based-pycs modo
Configura cómo Python evalúa la actualidad de los archivos .pyc basados en hash.
-d
Activa la salida de depuración del analizador (solo para expertos, dependiendo de las opciones de compilación).
-E
Ignora variables de entorno como PYTHONPATH y PYTHONHOME que modifican el comportamiento del intérprete.
-h , -? , --help
Imprime el uso del ejecutable del intérprete y sale.
--help-env
Imprime ayuda sobre variables de entorno específicas de Python y sale.
--help-xoptions
Imprime ayuda sobre las opciones -X específicas de la implementación y sale.
--help-all
Imprime información completa de uso y sale.
-i
Cuando se pasa un script como primer argumento o se usa la opción -c, entra en modo interactivo después de ejecutar el script o el comando. No lee el archivo $PYTHONSTARTUP. Esto puede ser útil para inspeccionar variables globales o un rastreo de pila cuando un script genera una excepción.
-I
Ejecuta Python en modo aislado. Esto también implica -E, -P y -s. En modo aislado, sys.path no contiene ni el directorio del script ni el directorio user's site-packages. Todas las variables de entorno PYTHON* también se ignoran. Pueden imponerse restricciones adicionales para evitar que el usuario inyecte código malicioso.
-m nombre-modulo
Busca en sys.path el módulo nombrado y ejecuta el archivo .py correspondiente como un script. Esto termina la lista de opciones (las opciones siguientes se pasan como argumentos al módulo).
-O
Elimina las declaraciones assert y cualquier código condicional al valor de __debug__; aumenta el nombre de archivo para los archivos compilados (bytecode) añadiendo .opt-1 antes de la extensión .pyc.
-OO
Hace -O y además descarta los docstrings; cambia el nombre de archivo para los archivos compilados (bytecode) añadiendo .opt-2 antes de la extensión .pyc.
-P
No antepone automáticamente una ruta potencialmente insegura a sys.path, como el directorio actual, el directorio del script o una cadena vacía. Ver también la variable de entorno PYTHONSAFEPATH.
-q
No imprime los mensajes de versión y derechos de autor. Estos mensajes también se suprimen en modo no interactivo.
-R
Activa la aleatorización de hash. Esta opción solo tiene efecto si la variable de entorno PYTHONHASHSEED está configurada en 0, ya que la aleatorización de hash está activada por defecto.
-s
No añadir el directorio de sitio del usuario a sys.path.
-S
Deshabilita la importación del módulo site y las manipulaciones dependientes del sitio de sys.path que esto implica. También deshabilita estas manipulaciones si site se importa explícitamente más tarde.
-u
Fuerza que los flujos stdout y stderr no tengan búfer. Esta opción no tiene efecto en el flujo stdin.
-v
Imprime un mensaje cada vez que se inicializa un módulo, mostrando el lugar (nombre de archivo o módulo incorporado) desde el cual se carga. Cuando se usa dos veces, imprime un mensaje por cada archivo que se comprueba al buscar un módulo. También proporciona información sobre la limpieza del módulo al salir.
-V , --version
Imprime el número de versión de Python del ejecutable y sale. Cuando se usa dos veces, imprime más información sobre la compilación.
-W argumento
Control de advertencias. La maquinaria de advertencias de Python, por defecto, imprime mensajes de advertencia en sys.stderr.

Los ajustes más simples aplican una acción particular incondicionalmente a todas las advertencias emitidas por un proceso (incluso aquellas que de otro modo son ignoradas por defecto):


-Wdefault # Advertir una vez por ubicación de llamada
-Werror # Convertir a excepciones
-Walways # Advertir cada vez
-Wall # Igual que -Walways
-Wmodule # Advertir una vez por módulo que llama
-Wonce # Advertir una vez por proceso Python
-Wignore # Nunca advertir

Los nombres de acción pueden abreviarse según se desee y el intérprete resolverá a el nombre de acción apropiado. Por ejemplo, -Wi es lo mismo que -Wignore .

La forma completa del argumento es: acción:mensaje:categoría:módulo:número-línea

Los campos vacíos coinciden con todos los valores; los campos vacíos finales pueden omitirse. Por ejemplo -W ignore::DeprecationWarning ignora todas las advertencias DeprecationWarning.

El campo acción es como se explicó anteriormente, pero solo se aplica a las advertencias que coinciden con los campos restantes.

El campo mensaje debe coincidir con el mensaje de advertencia completo impreso; esta coincidencia no distingue entre mayúsculas y minúsculas.

El campo categoría coincide con la categoría de advertencia (ej: "DeprecationWarning"). Debe ser un nombre de clase; la coincidencia prueba si la categoría de advertencia real del mensaje es una subclase de la categoría de advertencia especificada.

El campo módulo coincide con el nombre del módulo (totalmente calificado); esta coincidencia distingue entre mayúsculas y minúsculas.

El campo número-línea coincide con el número de línea, donde cero coincide con todos los números de línea y es por lo tanto equivalente a un número de línea omitido.

* Añade un filtro de advertencia por defecto, como -W default
* Instala ganchos de depuración en los asignadores de memoria: véase la

* Habilita el módulo faulthandler para volcar el traceback de Python en caso de

* Habilita el modo de depuración de asyncio
* Establece el atributo dev_mode de sys.flags a True

-X importtime: muestra cuánto tiempo tarda cada importación. Muestra el nombre del módulo,

-X faulthandler: habilita faulthandler


-X frozen_modules=[on|off]: si los módulos congelados deben
ser utilizados o no.

-X gil=[0|1]: habilita (1) o deshabilita (0) el GIL; también

Solo disponible en compilaciones configuradas con --disable-gil.

Esto ayuda a evitar ataques de denegación de servicio al analizar datos no confiables.

-X perf: soporta el perfilador "perf" de Linux; también PYTHONPERFSUPPORT=1


-X perf_jit: soporta el perfilador "perf" de Linux con soporte DWARF;

-X presite=MOD: importa este módulo antes de site; también PYTHON_PRESITE
Esto solo funciona en compilaciones de depuración.


-X pycache_prefix=PATH: habilita la escritura de archivos .pyc en un árbol

-X showrefcount: muestra el recuento de referencias total y el número de bloques

-X tracemalloc: comienza a rastrear las asignaciones de memoria de Python usando

Omite la primera línea de la fuente. Esto está destinado solo a un hack específico de DOS. Advertencia: ¡los números de línea en los mensajes de error estarán desfasados!

INTERFAZ DEL INTÉRPRETE

La interfaz del intérprete se asemeja a la del shell de UNIX: cuando se llama con la entrada estándar conectada a un dispositivo tty, solicita comandos y los ejecuta hasta que se lee un EOF; cuando se llama con un nombre de archivo como argumento o con un archivo como entrada estándar, lee y ejecuta un *script* de ese archivo; cuando se llama con -c comando, ejecuta las sentencias de Python dadas como *comando*. Aquí *comando* puede contener múltiples sentencias separadas por saltos de línea. ¡El espacio en blanco inicial es significativo en las sentencias de Python! En modo no interactivo, toda la entrada se analiza antes de ejecutarse.

Si está disponible, el nombre del script y los argumentos adicionales posteriores se pasan al script en la variable de Python sys.argv, que es una lista de cadenas (debe *importar sys* primero para poder acceder a ella). Si no se proporciona un nombre de script, sys.argv[0] es una cadena vacía; si se usa -c, sys.argv[0] contiene la cadena '-c'. Tenga en cuenta que las opciones interpretadas por el propio intérprete de Python no se colocan en sys.argv.

En modo interactivo, el prompt principal es `>>>'; el segundo prompt (que aparece cuando un comando no está completo) es `...'. Los prompts se pueden cambiar asignando a sys.ps1 o sys.ps2. El intérprete sale cuando lee un EOF en un prompt. Cuando ocurre una excepción no controlada, se imprime un traceback y el control vuelve al prompt principal; en modo no interactivo, el intérprete sale después de imprimir el traceback. La señal de interrupción genera la excepción KeyboardInterrupt; otras señales de UNIX no son capturadas (excepto que SIGPIPE a veces se ignora, en favor de la excepción IOError). Los mensajes de error se escriben en stderr.

ARCHIVOS Y DIRECTORIOS

Estos están sujetos a diferencias según las convenciones de instalación local; ${prefix} y ${exec_prefix} dependen de la instalación y deben interpretarse como para el software GNU; pueden ser los mismos. El valor por defecto para ambos es /usr/local.

${exec_prefix}/bin/python
Ubicación recomendada del intérprete.

${prefix}/lib/python<version>
${exec_prefix}/lib/python<version>

Ubicaciones recomendadas de los directorios que contienen los módulos estándar.

${prefix}/include/python<version>
${exec_prefix}/include/python<version>

Ubicaciones recomendadas de los directorios que contienen los archivos de inclusión necesarios para desarrollar extensiones de Python y embeber el intérprete.

VARIABLES DE ENTORNO

PYTHONASYNCIODEBUG
Si esta variable de entorno se establece en una cadena no vacía, habilita el modo de depuración del módulo asyncio.
PYTHON_BASIC_REPL
Si esta variable se establece en cualquier valor, el intérprete no intentará cargar el REPL basado en Python que requiere curses y readline, y en su lugar utilizará el REPL tradicional basado en el analizador.
PYTHONBREAKPOINT
Si esta variable de entorno se establece en 0, deshabilita el depurador predeterminado. Se puede establecer al llamable de su depurador de elección.
PYTHONCOERCECLOCALE
Si se establece en el valor 0, hace que la aplicación de línea de comandos principal de Python omita la coerción de las locales C y POSIX heredadas basadas en ASCII a una alternativa más capaz basada en UTF-8.
PYTHON_COLORS
Si esta variable se establece en 1, el intérprete coloreará varios tipos de salida. Establecerla en 0 desactiva este comportamiento.
PYTHON_CPU_COUNT
Si esta variable se establece en un entero positivo, anula los valores de retorno de os.cpu_count y os.process_cpu_count.
Véase también la opción -X cpu_count.
PYTHONDEBUG
Si esto se establece en una cadena no vacía, es equivalente a especificar la opción -d. Si se establece en un entero, es equivalente a especificar -d varias veces.
PYTHONEXECUTABLE
Si esta variable de entorno está establecida, sys.argv[0] se establecerá a su valor en lugar del valor obtenido a través del tiempo de ejecución C. Solo funciona en Mac OS X.
PYTHONFAULTHANDLER
Si esta variable de entorno se establece en una cadena no vacía, faulthandler.enable() se llama al inicio: instala un manejador para las señales SIGSEGV, SIGFPE, SIGABRT, SIGBUS y SIGILL para volcar el traceback de Python.
Esto es equivalente a la opción -X faulthandler.
PYTHON_FROZEN_MODULES
Si esta variable se establece en on u off, determina si
o no se congelan los módulos son ignorados por la maquinaria de importación. Un valor de on significa que se importan y off significa que se ignoran. El valor predeterminado es on para compilaciones no depuradas (el caso normal) y off para compilaciones depuradas.
Ver también la opción -X frozen_modules.
PYTHON_GIL
Si esta variable está configurada en 1, el bloqueo global del intérprete (GIL) se forzará a activarse. Configurarla en 0 fuerza la desactivación del GIL. Solo disponible en compilaciones configuradas con --disable-gil.
Esto es equivalente a la opción -X gil.
PYTHON_HISTORY
Esta variable de entorno se puede utilizar para establecer la ubicación de un archivo de historial (en Unix, es ~/.python_history por defecto).
PYTHONNODEBUGRANGES
Si esta variable está configurada, deshabilita la inclusión de las tablas que mapean información de ubicación adicional (línea final, desplazamiento de columna de inicio y desplazamiento de columna final) a cada instrucción en los objetos de código. Esto es útil cuando se desean objetos de código y archivos pyc más pequeños, así como para suprimir los indicadores visuales de ubicación adicionales cuando el intérprete muestra rastreos.
PYTHONDONTWRITEBYTECODE
Si esto está configurado como una cadena no vacía, es equivalente a especificar la opción -B (no intentar escribir archivos .pyc).
PYTHONDEVMODE
Si esta variable de entorno está configurada como una cadena no vacía, habilita el "modo de desarrollo" de Python, introduciendo verificaciones adicionales en tiempo de ejecución que son demasiado costosas para ser habilitadas por defecto.
Esto es equivalente a la opción -X dev.
PYTHONHASHSEED
Si esta variable está configurada en "random", se utiliza un valor aleatorio para sembrar los hashes de los objetos str y bytes.

Si PYTHONHASHSEED está configurado como un valor entero, se utiliza como una semilla fija para generar el hash() de los tipos cubiertos por la aleatorización de hashes. Su propósito es permitir la repetición de hashes, como para las pruebas automáticas del propio intérprete, o para permitir que un clúster de procesos de python comparta valores de hash.

El entero debe ser un número decimal en el rango [0,4294967295]. Especificar el valor 0 deshabilitará la aleatorización de hashes.

PYTHONHOME
Cambia la ubicación de las bibliotecas estándar de Python. Por defecto, las bibliotecas se buscan en ${prefix}/lib/python<version> y ${exec_prefix}/lib/python<version>, donde ${prefix} y ${exec_prefix} son directorios dependientes de la instalación, ambos por defecto a /usr/local. Cuando $PYTHONHOME está configurado como un solo directorio, su valor reemplaza tanto a ${prefix} como a ${exec_prefix}. Para especificar diferentes valores para estos, configure $PYTHONHOME a ${prefix}:${exec_prefix}.
PYTHONINSPECT
Si esto está configurado como una cadena no vacía, es equivalente a especificar la opción -i.
PYTHONINTMAXSTRDIGITS
Limita el número máximo de caracteres de dígitos en un valor entero al convertir desde una cadena y al convertir un entero de nuevo a una cadena. Un valor de 0 deshabilita el límite. Las conversiones hacia o desde bases 2, 4, 8, 16 y 32 nunca se limitan.
Esto es equivalente a la opción -X int_max_str_digits=NÚMERO .
PYTHONIOENCODING
Si esto se configura antes de ejecutar el intérprete, anula la codificación utilizada para stdin/stdout/stderr, con la sintaxis nombrecodificación:manejadorexcepción La parte manejadorexcepción es opcional y tiene el mismo significado que en str.encode. Para stderr, la parte manejadorexcepción se ignora; el manejador siempre será ´backslashreplace´.
PYTHONMALLOC
Configura los asignadores de memoria de Python y/o instala ganchos de depuración. Los asignadores de memoria disponibles son malloc y pymalloc. Los ganchos de depuración disponibles son debug, malloc_debug y pymalloc_debug.
Cuando Python se compila en modo de depuración, el valor predeterminado es pymalloc_debug y los ganchos de depuración se utilizan automáticamente. De lo contrario, el valor predeterminado es pymalloc.
PYTHONMALLOCSTATS
Si está configurado como una cadena no vacía, Python imprimirá estadísticas del asignador de memoria pymalloc cada vez que se cree una nueva arena de objetos pymalloc, y al apagar.
Esta variable se ignora si la variable de entorno $PYTHONMALLOC se utiliza para forzar el asignador malloc(3) de la biblioteca C, o si Python está configurado sin soporte para pymalloc.
PYTHONNOUSERSITE
Si esto está configurado como una cadena no vacía, es equivalente a especificar la opción -s (no añadir el directorio de sitio de usuario a sys.path).
PYTHONOPTIMIZE
Si esto está configurado como una cadena no vacía, es equivalente a especificar la opción -O. Si se configura como un entero, es equivalente a especificar -O varias veces.
PYTHONPATH
Aumenta la ruta de búsqueda predeterminada para archivos de módulo. El formato es el mismo que el $PATH del shell: uno o más nombres de ruta de directorio separados por dos puntos. Los directorios inexistentes se ignoran silenciosamente. La ruta de búsqueda predeterminada depende de la instalación, pero generalmente comienza con ${prefix}/lib/python<version> (ver PYTHONHOME arriba). La ruta de búsqueda predeterminada siempre se añade a $PYTHONPATH. Si se proporciona un argumento de script, el directorio que contiene el script se inserta en la ruta delante de $PYTHONPATH. La ruta de búsqueda se puede manipular desde dentro de un programa Python como la variable sys.path.
PYTHON_PERF_JIT_SUPPORT
Si esta variable está configurada en un valor distinto de cero, habilita el soporte para el perfilador Linux perf para que las llamadas de Python puedan ser detectadas por él utilizando información DWARF. Configurarlo en 0 lo deshabilita.
Ver también la opción -X perf_jit.
PYTHONPERFSUPPORT
Si esta variable está configurada en un valor distinto de cero, habilita el soporte para el perfilador Linux perf para que las llamadas de Python puedan ser detectadas por él. Configurarlo en 0 lo deshabilita.
Ver también la opción -X perf.
PYTHONPLATLIBDIR
Anula sys.platlibdir.
PYTHONPROFILEIMPORTTIME
Si esta variable de entorno está configurada como una cadena no vacía, Python mostrará cuánto tiempo tarda cada importación. Esto es exactamente equivalente a configurar -X importtime en la línea de comandos.
PYTHONPYCACHEPREFIX
Si esto está configurado, Python escribirá archivos .pyc en un árbol de directorios espejo en esta ruta, en lugar de en directorios __pycache__ dentro del árbol de origen.
Esto es equivalente a especificar la opción -X pycache_prefix=RUTA .
PYTHONSAFEPATH
Si esto está configurado como una cadena no vacía, no anteponer automáticamente una ruta potencialmente insegura a sys.path, como el directorio actual, el directorio del script o una cadena vacía. Ver también la opción -P.
PYTHONSTARTUP
Si este es el nombre de un archivo legible, los comandos de Python en ese archivo se ejecutan antes de que se muestre el primer prompt en modo interactivo. El archivo se ejecuta en el mismo espacio de nombres donde se ejecutan los comandos interactivos, para que los objetos definidos o importados en él puedan ser utilizados sin calificar en la sesión interactiva. También puedes cambiar los prompts sys.ps1 y sys.ps2 en este archivo.
PYTHONTRACEMALLOC
Si esta variable de entorno está configurada como una cadena no vacía, comienza a rastrear las asignaciones de memoria de Python utilizando el módulo tracemalloc.
El valor de la variable es el número máximo de marcos almacenados en un rastreo de una traza. Por ejemplo, PYTHONTRACEMALLOC=1 almacena solo el marco más reciente.
PYTHONUNBUFFERED
Si esto está configurado como una cadena no vacía, es equivalente a especificar la opción -u.
PYTHONUSERBASE
Define el directorio base del usuario, que se utiliza para calcular la ruta del directorio del usuario site-packages y las rutas de instalación para python -m pip install --user.
PYTHONUTF8
Si está configurado en 1, habilita el "Modo UTF-8" de Python. Configurarlo en 0 lo deshabilita.
PYTHONVERBOSE
Si esto está configurado como una cadena no vacía, es equivalente a especificar la opción -v. Si se configura como un entero, es equivalente a especificar -v varias veces.
PYTHONWARNDEFAULTENCODING
Si esta variable de entorno está configurada como una cadena no vacía, emite una EncodingWarning cuando se utiliza la codificación predeterminada específica de la configuración regional.
PYTHONWARNINGS
Si esto está configurado como una cadena separada por comas, es equivalente a especificar la opción -W para cada valor separado.

NAME

python - Python programming language interpreter

SYNOPSIS

python [options] [script [argument ...]]

python [options] -m module [argument ...]

python [options]

python -c code [options]

python -V [--version]

python -h [--help]

DESCRIPTION

Python is an interpreted, high-level, general-purpose programming language. Python's design philosophy emphasizes code readability with its notable use of significant indentation. Its language constructs and object-oriented approach aim to help programmers write clear, logical code for small and large-scale projects.

The python interpreter executes Python code from the specified script file or from the command line. If no script is given, the interpreter enters interactive mode, prompting for input. The interpreter can also be used to run a specific module using the -m option or to execute a short piece of code using the -c option.

COMMAND LINE OPTIONS

python accepts a number of command-line options:

-b --optimize-ast Optimize the AST after compilation. This is done by default with -O or -OO.

-c code Specify the program to be run via the string passed as argument. If this option is given, the first item in sys.argv will be a string like `"-c"`. If there is not enough arguments, the interpreter will exit.

-d PYTHON_DEBUG Turn on parser debugging output (for experts only).

-E --ignore-environment Ignore the PYTHON* environment variables, except for PYTHON_SELFTEST and PYTHON_FORKPTY_TEST. See below.

-i --inspect-code When a script is passed as first argument, run the script, then enter interactive mode. -i also causes the script's raw bytecode to be dumped to standard output.

-m module Specify the module to be run as a script. The path searched for this module is described in PYTHONPATH. If this option is given, the first item in sys.argv will be the module name. If this option is given, the interpreter will not search for the module on the path, but only in sys.path.

-O --optimize-level Optimize Python bytecode. Passing this option tells the compiler to optimize the bytecode. The optimization level is specified by an integer argument. There are currently two optimization levels: 1 and 2. A value of 1 enables basic optimizations. A value of 2 enables more advanced optimizations.

-OO Do further optimizations which destroy unused string constants, etc. This can make certain programs run slightly faster. However, this can also make debugging harder.

-S --skip-imports Don't try to import the site module and the other initialization modules. This can be useful for some kinds of debugging.

-v --verbose Print a message each time a module is initialized, when the initialization is lazy. Also prints a destructor debugging message which can show module reference counts still alive after shutting down the interpreter into a file under the path given as the value to this environment variable.

-X opt (Experimental) Set Python execution option. The currently available options are:

PYTHON_DEBUG
If this variable is set, the interpreter will print debugging output. This only works on debug builds.
PYTHON_FORKPTY_TEST
If this variable is set to a string containing the path to a file, the interpreter will print debugging output related to the forkpty system call into that file. This only works on debug builds.
PYTHON_PRESERVE_DEBUGGING_INFO
If this variable is set to a string containing the path to a file, the interpreter will print debugging output related to reference counts still alive after shutting down the interpreter into a file under the path given as the value to this environment variable.
PYTHON_PRESITE
If this variable is set to a module, that module will be imported early in the interpreter lifecycle, before the site module is executed, and before the __main__ module is created. This only works on debug builds.
This is equivalent to the -X presite=module option.

ENVIRONMENT VARIABLES

The behavior of the Python interpreter can be modified by several environment variables.

PYTHONPATH
This variable is used to specify the search path for module files. It should be a list of directories, separated by colons (or semicolons on Windows). If set, the interpreter will search for modules in these directories in the order they appear in the variable before searching the standard library locations.
PYTHONSTARTUP
If this variable is set to the name of a file, the Python interpreter will execute the contents of this file when it starts up in interactive mode. The full path to the file must be specified.
PYTHONCASEOK
If this variable is set, the interpreter will perform case-insensitive module name matching. This is only effective on systems that support it.
PYTHONHOME
If this variable is set, it overrides the default location of Python's standard library and compiled files (*.pyc). It should be set to a string containing two directory names separated by colons: the first is the prefix for the standard library, and the second is the prefix for the site-specific libraries. If the second directory is omitted, the search for modules will include the standard library location.
PYTHONMALLOC
Set the Python memory allocator. For example, set it to 'malloc', 'debug', or 'sys'. The default is 'malloc'.
PYTHONUNBUFFERED
If this variable is set, the Python I/O streams (sys.stdout and sys.stderr) are unbuffered. This means that output is written immediately, without waiting for a buffer to fill. This can be useful for debugging or for applications that require real-time output.
PYTHONFPEMASK
A string representing a floating-point exception mask. This is used to control which floating-point exceptions are trapped by the system. Consult your system documentation for details on the format of this string.
PYTHONHASHSEED
If this variable is set to an integer, it initializes the hash seed for string, bytes and datetime hashing. This can be used to make hashing results reproducible across different Python runs. A value of 'random' (the default) means the hash seed is initialized randomly. A value of '0' means the hash seed is set to 0. Values between 1 and 4095 are used as the hash seed.
PYTHONDEBUG
If this variable is set, the interpreter will print debugging output. This only works on debug builds.
PYTHONSELFTEST
If this variable is set to a string containing the path to a file, the interpreter will print debugging output related to reference counts still alive after shutting down the interpreter into a file under the path given as the value to this environment variable.
PYTHONPRESITE
If this variable is set to a module, that module will be imported early in the interpreter lifecycle, before the site module is executed, and before the __main__ module is created. This only works on debug builds.
This is equivalent to the -X presite=module option.
