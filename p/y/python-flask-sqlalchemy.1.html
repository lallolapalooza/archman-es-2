GUÍA DEL USUARIO

Inicio Rápido

Flask-SQLAlchemy simplifica el uso de SQLAlchemy manejando automáticamente la creación, uso y limpieza de los objetos SQLAlchemy con los que normalmente trabajarías. Aunque añade algunas características útiles, sigue funcionando como SQLAlchemy.

Esta página te guiará a través del uso básico de Flask-SQLAlchemy. Para ver todas las capacidades y personalización, consulta el resto de esta documentación, incluyendo la documentación de la API del objeto SQLAlchemy.

Consulta la Documentación de SQLAlchemy

Esta guía asume que estás usando SQLAlchemy 2.x, que tiene una nueva API para definir modelos y mejor soporte para anotaciones de tipo de Python y clases de datos. Si estás usando SQLAlchemy 1.x, consulta Guía Rápida Legado.

Instalación

$ pip install -U Flask-SQLAlchemy

Inicializar la Extensión

Primero crea el objeto db usando el constructor SQLAlchemy.

from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from sqlalchemy.orm import DeclarativeBase
class Base(DeclarativeBase):
  pass
db = SQLAlchemy(model_class=Base)

Obtén más información sobre cómo personalizar la clase base del modelo en Modelos y Tablas.

Acerca del objeto SQLAlchemy

Una vez construido, el objeto db te da acceso a la clase db.Model para definir modelos, y a db.session para ejecutar consultas.

El objeto SQLAlchemy también acepta argumentos adicionales para personalizar los objetos que gestiona.

Configurar la Extensión

El siguiente paso es conectar la extensión a tu aplicación Flask. La única configuración de la aplicación Flask requerida es la clave SQLALCHEMY_DATABASE_URI. Esta es una cadena de conexión que le dice a SQLAlchemy con qué base de datos conectarse.

Crea tu objeto de aplicación Flask, carga cualquier configuración y luego inicializa la clase de extensión SQLAlchemy con la aplicación llamando a db.init_app. Este ejemplo se conecta a una base de datos SQLite, que se almacena en la carpeta de instancias de la aplicación.

# crea la app
app = Flask(__name__)
# configura la base de datos SQLite, relativa a la carpeta de instancias de la app
app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///project.db"
# inicializa la app con la extensión
db.init_app(app)

Consulta Configuración para una explicación de las cadenas de conexión y qué otras claves de configuración se utilizan.

Definir Modelos

Crea una subclase de db.Model para definir una clase modelo. El modelo generará un nombre de tabla convirtiendo el nombre de clase CamelCase a snake_case.

from sqlalchemy import Integer, String
from sqlalchemy.orm import Mapped, mapped_column
class User(db.Model):
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    username: Mapped[str] = mapped_column(String, unique=True, nullable=False)
    email: Mapped[str] = mapped_column(String)

Consulta Modelos y Tablas para más información sobre cómo definir y crear modelos y tablas.

Crear las Tablas

Después de definir todos los modelos y tablas, llama a SQLAlchemy.create_all() para crear el esquema de tablas en la base de datos. Esto requiere un contexto de aplicación. Como no estás en una solicitud en este punto, crea uno manualmente.

with app.app_context():
    db.create_all()

Si defines modelos en otros módulos, debes importarlos antes de llamar a create_all, de lo contrario SQLAlchemy no los conocerá.

Consultar los Datos

Dentro de una vista de Flask o un comando CLI, puedes usar db.session para ejecutar consultas y modificar datos de modelos.

SQLAlchemy define automáticamente un método __init__ para cada modelo que asigna cualquier argumento de palabra clave a las columnas de base de datos correspondientes y otros atributos.

db.session.add(obj) añade un objeto a la sesión, para ser insertado. Modificar los atributos de un objeto actualiza el objeto. db.session.delete(obj) elimina un objeto. Recuerda llamar a db.session.commit() después de modificar, añadir o eliminar cualquier dato.

Qué recordar

En su mayor parte, debe usar SQLAlchemy como de costumbre. La instancia de extensión SQLAlchemy crea, configura y da acceso a lo siguiente:

  • Clase base de modelos declarativos SQLAlchemy.Model. Establece el nombre de la tabla automáticamente en lugar de necesitar __tablename__.
  • SQLAlchemy.session es una sesión que está limitada al contexto actual de la aplicación Flask. Se limpia después de cada solicitud.
  • SQLAlchemy.metadata y SQLAlchemy.metadatas dan acceso a cada metadato definido en la configuración.
  • SQLAlchemy.engine y SQLAlchemy.engines dan acceso a cada motor definido en la configuración.
  • SQLAlchemy.create_all() crea todas las tablas.
  • Debe estar en un contexto activo de aplicación Flask para ejecutar consultas y acceder a la sesión y al motor.

Configuración

Claves de Configuración

La configuración se carga desde app.config de Flask cuando se llama a SQLAlchemy.init_app(). La configuración no se vuelve a leer después de eso. Por lo tanto, toda la configuración debe realizarse antes de inicializar la aplicación.

flask_sqlalchemy.config.SQLALCHEMY_DATABASE_URI
La URI de conexión a la base de datos utilizada para el motor predeterminado. Puede ser una cadena o una instancia de URL de SQLAlchemy. Consulte a continuación y en Configuración del motor para ver ejemplos.

Se debe establecer al menos una de estas y SQLALCHEMY_BINDS.

Cambiado en la versión 3.0: Ya no usa por defecto una base de datos SQLite en memoria si no se establece.

flask_sqlalchemy.config.SQLALCHEMY_ENGINE_OPTIONS
Un diccionario de argumentos para pasar a sqlalchemy.create_engine() para el motor predeterminado.

Esto tiene prioridad sobre el argumento engine_options para SQLAlchemy, que se puede utilizar para establecer opciones predeterminadas para todos los motores.

Cambiado en la versión 3.0: Solo se aplica al bind predeterminado.

Añadido en la versión 2.4.

flask_sqlalchemy.config.SQLALCHEMY_BINDS
Un diccionario que mapea claves de bind a opciones de motor. El valor puede ser una cadena o una instancia de URL de SQLAlchemy. O puede ser un diccionario de argumentos, incluida la clave url, que se pasará a sqlalchemy.create_engine(). La clave None se puede usar para configurar el bind predeterminado, pero SQLALCHEMY_ENGINE_OPTIONS y SQLALCHEMY_DATABASE_URI tienen prioridad.

Se debe establecer al menos una de estas y SQLALCHEMY_DATABASE_URI.

Añadido en la versión 0.12.

flask_sqlalchemy.config.SQLALCHEMY_ECHO
El valor predeterminado para echo y echo_pool para cada motor. Esto es útil para depurar rápidamente las conexiones y las consultas emitidas desde SQLAlchemy.

Cambiado en la versión 3.0: Establece echo_pool además de echo.

flask_sqlalchemy.config.SQLALCHEMY_RECORD_QUERIES
Si está habilitado, se registrará información sobre cada consulta durante una solicitud. Utilice get_recorded_queries() para obtener una lista de las consultas que se emitieron durante la solicitud.

Cambiado en la versión 3.0: No habilitado automáticamente en modo debug o de prueba.

flask_sqlalchemy.config.SQLALCHEMY_TRACK_MODIFICATIONS
Si está habilitado, se registrarán todas las operaciones de insert, update y delete en los modelos, y luego se enviarán en las señales models_committed y before_models_committed cuando se llame a session.commit().

Cambiado en la versión 3.0: Deshabilitado por defecto.

Añadido en la versión 2.0.

Cambiado en la versión 3.1: Eliminado SQLALCHEMY_COMMIT_ON_TEARDOWN.

Cambiado en la versión 3.0: Eliminados SQLALCHEMY_NATIVE_UNICODE, SQLALCHEMY_POOL_SIZE, SQLALCHEMY_POOL_TIMEOUT, SQLALCHEMY_POOL_RECYCLE y SQLALCHEMY_MAX_OVERFLOW.

Opciones Predeterminadas del Controlador

Se establecen algunas opciones predeterminadas para los motores SQLite y MySQL para hacerlos más utilizables por defecto en aplicaciones web.

Las rutas de archivo relativas de SQLite son relativas a la ruta de instancia de Flask en lugar del directorio de trabajo actual. Las bases de datos en memoria utilizan un pool estático y check_same_thread para funcionar entre solicitudes.

Los servidores MySQL (y MariaDB) están configurados para cerrar las conexiones inactivas durante 8 horas, lo que puede provocar un error como 2013: Lost connection to MySQL server during query. Se utiliza un valor predeterminado de pool_recycle de 2 horas (7200 segundos) para recrear las conexiones antes de que finalice ese tiempo de espera.

Precedencia de Configuración del Motor

Dado que Flask-SQLAlchemy tiene soporte para múltiples motores, existen reglas sobre qué configuración anula a otra. La mayoría de las aplicaciones solo tendrán una base de datos y solo necesitarán usar SQLALCHEMY_DATABASE_URI y SQLALCHEMY_ENGINE_OPTIONS.

  • Si se proporciona el argumento engine_options a SQLAlchemy, este establece opciones predeterminadas para _todos_ los motores. SQLALCHEMY_ECHO establece el valor predeterminado tanto para echo como para echo_pool para todos los motores.
  • Las opciones para cada motor en SQLALCHEMY_BINDS anulan esos valores predeterminados.
  • SQLALCHEMY_ENGINE_OPTIONS anula la clave None en SQLALCHEMY_BINDS, y SQLALCHEMY_DATABASE_URI anula la clave url en las opciones de ese motor.

Tiempos de Espera

Ciertas bases de datos pueden configurarse para cerrar conexiones inactivas después de un período de tiempo. MySQL y MariaDB están configurados para esto por defecto, pero los servicios de bases de datos también pueden configurar este tipo de límite. Esto puede resultar en un error como 2013: Lost connection to MySQL server during query.

Si encuentra este error, intente establecer pool_recycle en las opciones del motor a un valor inferior al tiempo de espera de la base de datos.

Alternativamente, puede intentar establecer pool_pre_ping si espera que la base de datos cierre conexiones con frecuencia, como si se está ejecutando en un contenedor que pueda reiniciarse.

Modelos y Tablas

Utilice la clase db.Model para definir modelos, o la clase db.Table para crear tablas. Ambas manejan las claves de bind de Flask-SQLAlchemy para asociarse con un motor específico.

Inicializando la Clase Base

Crea una subclase de una de esas clases:

from sqlalchemy import MetaData
class Base(DeclarativeBase):
    metadata = MetaData(naming_convention={
        "ix": 'ix_%(column_0_label)s',
        "uq": "uq_%(table_name)s_%(column_0_name)s",
        "ck": "ck_%(table_name)s_%(constraint_name)s",
        "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
        "pk": "pk_%(table_name)s"
    })

Inicializar la Extensión

Una vez que hayas definido una clase base, crea el objeto db usando el constructor SQLAlchemy.

Crea una subclase de db.Model para crear una clase de modelo. A diferencia de SQLAlchemy puro, el modelo de Flask-SQLAlchemy generará automáticamente un nombre de tabla si __tablename__ no está establecido y se define una columna de clave primaria.

from sqlalchemy.orm import Mapped, mapped_column
class User(db.Model):
    id: Mapped[int] = mapped_column(db.Integer, primary_key=True)
    username: Mapped[str] = mapped_column(db.String, unique=True, nullable=False)
    email: Mapped[str] = mapped_column(db.String)

Definir un modelo no lo crea en la base de datos. Usa create_all() para crear los modelos y tablas después de definirlos. Si defines modelos en submódulos, debes importarlos para que SQLAlchemy los conozca antes de llamar a create_all.

Crea instancias de db.Table para definir tablas. La clase toma un nombre de tabla, luego cualquier columna y otras partes de la tabla como columnas y restricciones. A diferencia de SQLAlchemy puro, el argumento metadata no es necesario. Se elegirá un metadato basado en el argumento bind_key, o se usará el predeterminado.

Una razón común para crear una tabla directamente es al definir relaciones de muchos a muchos. La tabla de asociación no necesita su propia clase de modelo, ya que se accederá a ella a través de los atributos de relación relevantes en los modelos relacionados.

import sqlalchemy as sa
user_book_m2m = db.Table(
    "user_book",
    sa.Column("user_id", sa.ForeignKey(User.id), primary_key=True),
    sa.Column("book_id", sa.ForeignKey(Book.id), primary_key=True),
)

Reflexión de Tablas

Si te conectas a una base de datos que ya tiene tablas, SQLAlchemy puede detectar ese esquema y crear tablas con columnas automáticamente. Esto se llama reflexión. Esas tablas también pueden asignarse a clases de modelo con el atributo __table__ en lugar de definir el modelo completo.

Llama al método reflect() en la extensión. Reflejará todas las tablas para cada bind key. El atributo tables de cada metadato contendrá los objetos de tabla detectados.

with app.app_context():
    db.reflect()
class User:
    __table__ = db.metadatas["auth"].tables["user"]

En la mayoría de los casos, será más mantenible definir las clases de modelo tú mismo. Solo necesitas definir los modelos y columnas que realmente utilizarás, incluso si te conectas a un esquema más amplio. Los IDEs conocerán los atributos disponibles, y las herramientas de migración como Alembic podrán detectar cambios y generar migraciones de esquema.

Modificación y Consulta de Datos

Inserción, Actualización, Eliminación

Para insertar datos, pasa el objeto modelo a db.session.add():

user = User()
db.session.add(user)
db.session.commit()

Para actualizar datos, modifica los atributos en los objetos modelo:

user.verified = True
db.session.commit()

Para eliminar datos, pasa el objeto modelo a db.session.delete():

db.session.delete(user)
db.session.commit()

Después de modificar los datos, debes llamar a db.session.commit() para confirmar los cambios en la base de datos. De lo contrario, se descartarán al final de la solicitud.

Seleccionar

user = db.session.execute(db.select(User).filter_by(username=username)).scalar_one()
users = db.session.execute(db.select(User).order_by(User.username)).scalars()

Consultas para Vistas

Si escribes una función de vista de Flask, a menudo es útil devolver un error 404 No Encontrado para las entradas que faltan. Flask-SQLAlchemy proporciona algunos métodos de consulta adicionales.

  • SQLAlchemy.get_or_404() lanzará un 404 si la fila con el id dado no existe, de lo contrario devolverá la instancia.
  • SQLAlchemy.first_or_404() lanzará un 404 si la consulta no devuelve ningún resultado, de lo contrario devolverá el primer resultado.
  • SQLAlchemy.one_or_404() lanzará un 404 si la consulta no devuelve exactamente un resultado, de lo contrario devolverá el resultado.
@app.route("/user-by-id/<int:id>")
def user_by_id(id):
    user = db.get_or_404(User, id)
    return render_template("show_user.html", user=user)
@app.route("/user-by-username/<username>")
def user_by_username(username):
    user = db.one_or_404(db.select(User).filter_by(username=username))
    return render_template("show_user.html", user=user)

Puedes añadir un mensaje personalizado al error 404:

user = db.one_or_404(
    db.select(User).filter_by(username=username),
    description=f"No user named '{username}'."
)

Contexto de la Aplicación Flask

Se requiere un contexto de aplicación Flask activo para realizar consultas y acceder a db.engine y db.session. Esto se debe a que la sesión está limitada al contexto para que se limpie correctamente después de cada solicitud o comando CLI.

Independientemente de cómo se inicialice una aplicación con la extensión, no se almacena para su uso posterior. En su lugar, la extensión utiliza el proxy current_app de Flask para obtener la aplicación activa, lo que requiere un contexto de aplicación activo.

Contexto Automático

Cuando Flask está manejando una solicitud o un comando CLI, se activará automáticamente un contexto de aplicación. Por lo tanto, no necesita hacer nada especial para usar la base de datos durante las solicitudes o los comandos CLI.

Contexto Manual

Si intenta utilizar la base de datos cuando no hay un contexto de aplicación activo, verá el siguiente error.

RuntimeError: Working outside of application context.
This typically means that you attempted to use functionality that needed
the current application. To solve this, set up an application context
with app.app_context(). See the documentation for more information.

Si se encuentra en una situación en la que necesita la base de datos y no tiene un contexto, puede activar uno con app_context. Esto es común al llamar a db.create_all para crear las tablas, por ejemplo.

def create_app():
    app = Flask(__name__)
    app.config.from_object("project.config")
    import project.models
    with app.app_context():
        db.create_all()
    return app

Pruebas

Si prueba su aplicación utilizando el cliente de pruebas de Flask para realizar solicitudes a sus puntos finales, el contexto estará disponible como parte de la solicitud. Si necesita probar algo sobre su base de datos o modelos directamente, en lugar de a través de una solicitud, deberá activar un contexto manualmente.

Solo active un contexto exactamente dónde y durante el tiempo que sea necesario para cada prueba. No active un contexto de aplicación globalmente para cada prueba, ya que esto puede interferir con la forma en que se limpia la sesión.

def test_user_model(app):
    user = User()
    with app.app_context():
        db.session.add(user)
        db.session.commit()

Si se encuentra escribiendo muchas pruebas de este tipo, puede usar una fixture de pytest para activar un contexto para una prueba específica.

import pytest
@pytest.fixture
def app_ctx(app):
    with app.app_context():
        yield
@pytest.mark.usefixtures("app_ctx")
def test_user_model():
    user = User()
    db.session.add(user)
    db.session.commit()

Bases de Datos Múltiples con Binds

SQLAlchemy puede conectarse a más de una base de datos a la vez. Se refiere a diferentes motores como "binds". Flask-SQLAlchemy simplifica cómo funcionan los binds asociando cada motor con una cadena corta, una "clave de bind", y luego asociando cada modelo y tabla con una clave de bind. La sesión elegirá qué motor utilizar para una consulta basándose en la clave de bind del elemento que se consulta. Si no se proporciona ninguna clave de bind, se utiliza el motor predeterminado.

Configuración de Binds

El bind predeterminado todavía se configura estableciendo SQLALCHEMY_DATABASE_URI, y SQLALCHEMY_ENGINE_OPTIONS para cualquier opción de motor. Los binds adicionales se proporcionan en SQLALCHEMY_BINDS, un diccionario que mapea claves de bind a URLs de motor. Para especificar opciones de motor para un bind, el valor puede ser un diccionario de opciones de motor con la clave "url", en lugar de solo una cadena de URL.

SQLALCHEMY_DATABASE_URI = "postgresql:///main"
SQLALCHEMY_BINDS = {
    "meta": "sqlite:////path/to/meta.db",
    "auth": {
        "url": "mysql://localhost/users",
        "pool_recycle": 3600,
    },
}

Definición de Modelos y Tablas con Binds

Flask-SQLAlchemy creará metadatos y un motor para cada bind configurado. Los modelos y tablas con una clave de bind se registrarán con los metadatos correspondientes, y la sesión los consultará utilizando el motor correspondiente.

Para establecer el bind de un modelo, establezca el atributo de clase __bind_key__. No establecer una clave de bind es equivalente a establecerla en None, la clave predeterminada.

class User(db.Model):
    __bind_key__ = "auth"
    id = db.Column(db.Integer, primary_key=True)

Los modelos que heredan de este modelo compartirán la misma clave de bind, o pueden anularla.

Para establecer el bind de una tabla, pase el argumento de palabra clave bind_key.

user_table = db.Table(
    "user",
    db.Column("id", db.Integer, primary_key=True),
    bind_key="auth",
)

En última instancia, la sesión busca la clave de bind en los metadatos asociados con el modelo o la tabla. Esa asociación ocurre durante la creación. Por lo tanto, cambiar la clave de bind después de crear un modelo o tabla no tendrá ningún efecto.

Acceso a Metadatos y Motores

Es posible que necesite inspeccionar los metadatos o el motor de un bind. Tenga en cuenta que debe ejecutar consultas a través de la sesión, no directamente en el motor.

El motor predeterminado es SQLAlchemy.engine, y los metadatos predeterminados son SQLAlchemy.metadata. SQLAlchemy.engines y SQLAlchemy.metadatas son diccionarios que mapean todas las claves de bind.

Creación y Eliminación de Tablas

Los métodos create_all() y drop_all() operan en todos los binds por defecto. El argumento bind_key para estos métodos puede ser una cadena o None para operar en un solo bind, o una lista de cadenas o None para operar en un subconjunto de binds. Dado que estos métodos acceden a los motores, deben llamarse dentro de un contexto de aplicación.

# create tables for all binds
db.create_all()
# create tables for the default and "auth" binds
db.create_all(bind_key=[None, "auth"])
# create tables for the "meta" bind
db.create_all(bind_key="meta")
# drop tables for the default bind
db.drop_all(bind_key=None)

Personalización Avanzada

Los diversos objetos gestionados por la extensión se pueden personalizar pasando argumentos al constructor de SQLAlchemy.

Clase de Modelo

Todos los modelos de SQLAlchemy heredan de una clase base declarativa. Esto se expone como db.Model en Flask-SQLAlchemy, de la cual heredan todos los modelos. Esto se puede personalizar creando una subclase de la predeterminada y pasando la clase personalizada a model_class.

El siguiente ejemplo da a cada modelo una clave primaria entera, o una clave externa para la herencia de tabla unida.

NOTA:

Las claves primarias enteras para todo no son necesariamente el mejor diseño de base de datos (eso depende de los requisitos de su proyecto), esto es solo un ejemplo.
from sqlalchemy import Integer, String, ForeignKey
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, declared_attr
class Base(DeclarativeBase):
    @declared_attr.cascading
    @classmethod
    def id(cls):
        for base in cls.__mro__[1:-1]:
            if getattr(base, "__table__", None) is not None:
                    return mapped_column(ForeignKey(base.id), primary_key=True)
            else:
                return mapped_column(Integer, primary_key=True)
db = SQLAlchemy(app, model_class=Base)
class User(db.Model):
    name: Mapped[str] = mapped_column(String)
class Employee(User):
    title: Mapped[str] = mapped_column(String)

Modelos Abstractos y Mixins

Si el comportamiento solo es necesario en algunos modelos en lugar de en todos, utilice una clase base de modelo abstracto para personalizar solo esos modelos. Por ejemplo, si algunos modelos deben rastrear cuándo se crean o actualizan.

from datetime import datetime
from sqlalchemy import DateTime, Integer, String
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, declared_attr
class TimestampModel(db.Model):
    __abstract__ = True
    created: Mapped[datetime] = mapped_column(DateTime, nullable=False, default=datetime.utcnow)
    updated: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
class Author(db.Model):
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    username: Mapped[str] = mapped_column(String, unique=True, nullable=False)
class Post(TimestampModel):
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    title: Mapped[str] = mapped_column(String, nullable=False)

Esto también se puede hacer con una clase mixin, heredando de db.Model por separado.

class TimestampMixin:
    created: Mapped[datetime] = mapped_column(DateTime, nullable=False, default=datetime.utcnow)
    updated: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
class Post(TimestampMixin, db.Model):
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    title: Mapped[str] = mapped_column(String, nullable=False)

Desactivación de la Generación de Nombres de Tablas

Algunos proyectos prefieren establecer __tablename__ manualmente para cada modelo en lugar de depender de la detección y generación de nombres de tablas de Flask-SQLAlchemy. La forma sencilla de lograrlo es establecer cada __tablename__ y no modificar la clase base. Sin embargo, la generación del nombre de la tabla se puede desactivar estableciendo disable_autonaming=True en el constructor de SQLAlchemy.

class Base(sa_orm.DeclarativeBase):
    pass
db = SQLAlchemy(app, model_class=Base, disable_autonaming=True)

Clase de Sesión

La clase Session de Flask-SQLAlchemy elige qué motor consultar basándose en la clave de enlace asociada al modelo o tabla. Sin embargo, existen otras estrategias, como el particionamiento horizontal, que se pueden implementar con una clase de sesión diferente. La clave class_ del argumento session_options de la extensión se utiliza para cambiar la clase de sesión.

Flask-SQLAlchemy siempre pasará la instancia de la extensión como argumento db a la sesión, por lo que debe aceptarlo para seguir funcionando. Esto se puede utilizar para acceder a db.engines.

from sqlalchemy.ext.horizontal_shard import ShardedSession
from flask_sqlalchemy.session import Session
class CustomSession(ShardedSession, Session):
    ...
db = SQLAlchemy(session_options={"class_": CustomSession})

Clase de Consulta

ADVERTENCIA:

La interfaz de consulta se considera obsoleta en SQLAlchemy. Esto incluye session.query, Model.query, db.Query y relaciones lazy="dynamic". Prefiera utilizar session.execute(select(...)) en su lugar.

Es posible personalizar la interfaz de consulta utilizada por la sesión, los modelos y las relaciones. Esto se puede usar para agregar métodos de consulta adicionales. Por ejemplo, podría agregar un método get_or que obtiene una fila o devuelve un valor predeterminado.

from flask_sqlalchemy.query import Query
class GetOrQuery(Query):
    def get_or(self, ident, default=None):
        out = self.get(ident)
        if out is None:
            return default
        return out
db = SQLAlchemy(query_class=GetOrQuery)
user = User.query.get_or(user_id, anonymous_user)

Al pasar el argumento query_class, se personalizarán db.Query, db.session.query, Model.query y las relaciones db.relationship(lazy="dynamic"). También es posible personalizar estos de forma individual para cada objeto.

Para personalizar la propiedad query de un modelo específico, establezca el atributo query_class en la clase del modelo.

class User(db.Model):
    query_class = GetOrQuery

Para personalizar una relación dinámica específica, pase el argumento query_class a la relación.

db.relationship(User, lazy="dynamic", query_class=GetOrQuery)

Para personalizar solo session.query, pase la clave query_cls al argumento session_options del constructor.

db = SQLAlchemy(session_options={"query_cls": GetOrQuery})
