FLASK-PARANOID(1) Flask-Paranoid FLASK-PARANOID(1)

NOMBRE

flask-paranoid - Documentación de Flask-Paranoid [imagen: flask-paranoid] [imagen]

Flask-Paranoid es una extensión simple para el microframework Flask que protege la aplicación contra ciertos ataques en los que la cookie de sesión del usuario es robada y luego utilizada por el atacante.

Cuando un cliente se conecta a la aplicación por primera vez, se genera y almacena un token que representa ciertas características de este cliente. En solicitudes sucesivas enviadas por este cliente, este token se regenera y se compara con el almacenado. Si los tokens son diferentes, se asume que el cliente está enviando solicitudes desde un entorno diferente al en el que se creó originalmente la sesión, por lo que en este caso la sesión se destruye y la solicitud se rechaza como medida preventiva.

Por defecto, el token se genera a partir de la dirección IP y el agente de usuario del cliente. Esto significa que si se roba una cookie de sesión de usuario y luego se utiliza desde una ubicación diferente o desde un navegador diferente, el token generado cambiará y eso bloqueará esta solicitud "diferente".

La idea se basa en la función de protección de sesión sólida de Flask-Login, pero generalizada para que también pueda ser utilizada fuera del contexto de Flask-Login. La generación y el almacenamiento del token pueden personalizarse para adaptarse a diferentes tipos de aplicaciones.

Aquí hay una aplicación simple que utiliza Flask-Paranoid para proteger la sesión del usuario:

from flask import Flask
from flask_paranoid import Paranoid
app = Flask(__name__)
app.config['SECRET_KEY'] = '¡clave-ultra-secreta!'
paranoid = Paranoid(app)
paranoid.redirect_view = '/'
@app.route('/')
def index():
    return render_template('index.html')

En este ejemplo, el token paranoico calculado en la solicitud inicial de un cliente se almacenará en la sesión del usuario. Si una solicitud posterior genera un token diferente, la sesión se borrará y luego se redirigirá a la URL raíz, obligando al posible atacante a iniciar sesión nuevamente.

La única configuración es lo que determina la acción que se toma cuando se detecta una sesión inválida, después de que la sesión se borra. El valor predeterminado es devolver un error 401 al cliente.

Para redirigir a una URL dada, establezca paranoid.redirect_view en la ubicación deseada:

paranoid.redirect_view = '/login'

También se admiten URL absolutas:

paranoid.redirect_view = 'https://www.google.com'

Para redirigir a una ruta registrada de Flask, establezca paranoid.redirect_view en el nombre del endpoint deseado:

paranoid.redirect_view = 'index'

Para redirigir a una ruta dentro de un blueprint, use la misma sintaxis que la función url_for():

paranoid.redirect_view = 'auth.login'

Para que la extensión invoque una función de devolución de llamada que genere la respuesta, use el decorador paranoid.on_invalid_session. La función debe devolver una respuesta válida de Flask:

@paranoid.on_invalid_session
def invalid_session():
    return 'por favor inicie sesión', 401

Dado que esta extensión anula la función similar en Flask-Login, se recomienda que al usar ambas extensiones en una aplicación, la protección de sesión se desactive en Flask-Login:

login_manager.session_protection = None

Flask-Paranoid detecta si se está utilizando Flask-Login y, en ese caso, borra la cookie de "recordarme" además de la sesión del usuario cuando se detecta una sesión inválida.

Flask-Paranoid permite a las aplicaciones personalizar su funcionamiento interno mediante el uso de subclases.

CAMBIAR EL ALGORITMO DE GENERACIÓN DE TOKEN

La implementación predeterminada crea un hash SHA256 de la dirección IP del cliente y el agente de usuario.

Para utilizar un algoritmo de generación de tokens diferente, anule el método create_token:

class MyParanoid(Paranoid):
    def create_token(self):
        pass

Este método se invoca en el contexto de una solicitud, por lo que puede acceder al objeto request para obtener información sobre el cliente.

CAMBIAR DÓNDE SE ALMACENA EL TOKEN

La implementación predeterminada escribe el token paranoico en session['_paranoid_token'].

Si se desea un mecanismo de almacenamiento diferente, anule los métodos write_token_to_session() y get_token_from_session():

class MyParanoid(Paranoid):
    def write_token_to_session(self, token):
        pass
    def get_token_from_session(self):
        pass

Un caso de uso complicado es cuando esta extensión se utiliza con un proyecto de API que no utiliza la sesión de usuario y en su lugar proporciona tokens de autenticación a los clientes. En tal caso, la función de generación de tokens de la aplicación puede mejorarse para incluir el token paranoico. Por ejemplo:

def get_token(username, password):
    if validate_user(username, password):
        return encode_jwt(claims={'username': username,
                                  'paranoid_token': paranoid.create_token()})

Y luego los métodos de almacenamiento de tokens se pueden anular de la siguiente manera:

class MyParanoid(Paranoid):
    def write_token_to_session(self, token):
        # no hay nada que hacer aquí, el token paranoico se inserta en el JWT
        # por la aplicación
        pass
    def get_token_from_session(self):
        claims = decode_jwt(request.headers['X-API-TOKEN'])
        if 'paranoid_token' not in claims:
            abort(401)
        return claims['paranoid_token']

En este ejemplo, encode_jwt y decode_jwt son funciones de aplicación que trabajan con tokens JWT. El cliente se autentica pasando el token JWT en la cabecera X-API-TOKEN.

USAR UN MECANISMO DE LIMPIEZA DE SESIÓN DIFERENTE

Por defecto, esta extensión vacía el contenido de la sesión del usuario y, si se utiliza Flask-Login, también elimina su cookie de "recordarme".

Para cambiar o reemplazar el algoritmo de limpieza de sesión, anule el método clear_session():

class MyParanoid(Paranoid):
    def clear_session(self, response):
        pass

El argumento response que se pasa a este método es el objeto de respuesta que se devolverá al cliente después de que la sesión se haya limpiado. Cualquier cookie que necesite ser eliminada o modificada debe incluirse en este objeto de respuesta.

flask-paranoid 1.0.1-2

NOMBRE

flask-paranoid - Añade seguridad a las sesiones de Flask.

SINOPSIS

flask-paranoid es una extensión de Flask que añade algunas características de seguridad a las sesiones de Flask.

DESCRIPCIÓN

flask-paranoid te permite hacer lo siguiente:

  • Fuerza la regeneración del token de sesión en cada solicitud para prevenir ataques de fijación de sesión.

  • Cambia el nombre de la cookie de sesión para que no sea el valor predeterminado de Flask. Esto es útil si estás ejecutando varias aplicaciones en el mismo subdominio.

  • Permite que el usuario sea redirigido a una página específica cuando se le pregunta por una sesión que ha expirado, en lugar de simplemente devolver un error 403.

  • Permite que el token de sesión se almacene en un lugar diferente en lugar de la cookie. Por ejemplo, podría almacenarse en el encabezado de la solicitud.

  • Permite especificar un mecanismo de limpieza de sesiones personalizado.

INSTALACIÓN

Instala flask-paranoid usando pip:

pip install flask-paranoid

CONFIGURACIÓN

Para usar flask-paranoid, simplemente inicializa la extensión con tu aplicación Flask:

from flask import Flask
from flask_paranoid import Paranoid

app = Flask(__name__)
paranoid = Paranoid(app)

Puedes configurar flask-paranoid usando los siguientes parámetros:

  • SESSION_REGENERATE_EACH_REQUEST (booleano): Si se establece en True, el token de sesión se regenerará en cada solicitud. El valor predeterminado es True.

  • SESSION_COOKIE_NAME (cadena): El nombre de la cookie de sesión. El valor predeterminado es 'session'.

  • SESSION_LOGOUT_REDIRECT (cadena): La URL a la que se redirigirá al usuario cuando se le pida una sesión expirada. El valor predeterminado es None.

  • SESSION_TOKEN_STORE (cadena): La ubicación donde se almacenará el token de sesión. Los valores posibles son 'cookie' o 'header'. El valor predeterminado es 'cookie'.

  • SESSION_TOKEN_HEADER_NAME (cadena): Si SESSION_TOKEN_STORE se establece en 'header', este es el nombre del encabezado que se usará para almacenar el token de sesión. El valor predeterminado es 'X-Session-Token'.

  • SESSION_CLEANUP_MECHANISM (cadena): El mecanismo de limpieza de sesiones a utilizar. Los valores posibles son 'auto', 'manual' o 'none'. El valor predeterminado es 'auto'.

USO BÁSICO

Una vez que hayas configurado flask-paranoid, puedes usarlo como lo harías normalmente con las sesiones de Flask:

from flask import Flask, session

app = Flask(__name__)
app.secret_key = 'your secret key'  # Necesario para las sesiones de Flask

@app.route('/')
def index():
    if 'username' in session:
        return f'Hola, {session["username"]}!'
    return '¡Hola, mundo!'

@app.route('/login', methods=['POST'])
def login():
    session['username'] = request.form['username']
    return 'Has iniciado sesión.'

@app.route('/logout')
def logout():
    session.pop('username', None)
    return 'Has cerrado sesión.'

SEGURIDAD DE SESIÓN

flask-paranoid ayuda a mejorar la seguridad de la sesión de las siguientes maneras:

  • Prevención de fijación de sesión: Por defecto, flask-paranoid regenera el token de sesión en cada solicitud. Esto significa que incluso si un atacante intercepta el token de sesión de un usuario, el token cambiará en la siguiente solicitud, haciendo que el token interceptado sea inútil.

  • Nombres de cookies personalizados: Al cambiar el nombre de la cookie de sesión, puedes evitar conflictos con otras aplicaciones que se ejecutan en el mismo dominio o subdominio. Esto también puede dificultar que un atacante adivine el nombre de tu cookie de sesión.

REDIRECT DE INICIO DE SESIÓN

Si la configuración SESSION_LOGOUT_REDIRECT está establecida en una URL, los usuarios que intenten acceder a un recurso que requiere una sesión iniciada pero cuya sesión ha expirado serán redirigidos a esa URL. Esto proporciona una experiencia de usuario más fluida que simplemente mostrar un error 403.

Por ejemplo, para redirigir a los usuarios a la página de inicio de sesión:

app.config['SESSION_LOGOUT_REDIRECT'] = '/login'

REGENERACIÓN DE TOKEN

Por defecto, flask-paranoid regenera el token de sesión en cada solicitud. Puedes deshabilitar este comportamiento estableciendo SESSION_REGENERATE_EACH_REQUEST en False:

app.config['SESSION_REGENERATE_EACH_REQUEST'] = False

Sin embargo, se recomienda encarecidamente mantener la regeneración de tokens habilitada para la seguridad.

CAMBIAR EL ALGORITMO DE AUTENTICACIÓN

flask-paranoid utiliza el algoritmo itsdangerous para la firma de los tokens de sesión. Puedes cambiar el algoritmo predeterminado si es necesario:

from itsdangerous import JWSSerializer

app.config['SESSION_SERIALIZER'] = JWSSerializer('your_secret_key', serializer=json.dumps, deserializer=json.loads)

CAMBIAR DÓNDE SE ALMACENA EL TOKEN

Por defecto, el token de sesión se almacena en una cookie. Puedes cambiar esto para que se almacene en un encabezado de solicitud estableciendo SESSION_TOKEN_STORE en 'header':

app.config['SESSION_TOKEN_STORE'] = 'header'
app.config['SESSION_TOKEN_HEADER_NAME'] = 'X-My-Custom-Header'

USAR UN MECANISMO DIFERENTE PARA LIMPIAR SESIONES

El mecanismo de limpieza de sesiones predeterminado es 'auto', que limpia las sesiones expiradas automáticamente. Puedes cambiar esto a 'manual' o 'none':

app.config['SESSION_CLEANUP_MECHANISM'] = 'manual'

Cuando se establece en 'manual', deberás llamar explícitamente a paranoid.cleanup() para limpiar las sesiones expiradas.

Cuando se establece en 'none', no se realizará ninguna limpieza automática de sesiones.
