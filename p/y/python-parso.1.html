NOMBRE

parso - Documentación de parso

Versión v0.8.5. (Instalación)

Parso es un analizador de Python que soporta recuperación de errores y análisis de ida y vuelta para diferentes versiones de Python (en múltiples versiones de Python). Parso también es capaz de listar múltiples errores de sintaxis en tu archivo python.

Parso consta de una pequeña API para analizar Python y analizar el árbol de sintaxis.

Un ejemplo simple:

>>> import parso
>>> module = parso.parse('hello + 1', version="3.9")
>>> expr = module.children[0]
>>> expr
PythonNode(arith_expr, [<Name: hello@1,0>, <Operator: +>, <Number: 1>])
>>> print(expr.get_code())
hello + 1
>>> name = expr.children[0]
>>> name
<Name: hello@1,0>
>>> name.end_pos
(1, 5)
>>> expr.end_pos
(1, 9)

Para listar múltiples problemas:

>>> grammar = parso.load_grammar()
>>> module = grammar.parse('foo +\nbar\ncontinue')
>>> error1, error2 = grammar.iter_errors(module)
>>> error1.message
'SyntaxError: invalid syntax'
>>> error2.message
"SyntaxError: 'continue' not properly in loop"

DOCUMENTACIÓN

Instalación y Configuración

La forma preferida (pip)

En cualquier sistema, puedes instalar parso directamente desde el índice de paquetes de Python usando pip:

sudo pip install parso

Desde git

Si quieres instalar la versión de desarrollo actual (rama master):

Para instalarlo, navega al directorio que contiene setup.py en tu consola y escribe:

sudo python setup.py install

Uso

parso trabaja con gramáticas. Puedes simplemente crear gramáticas de Python llamando a parso.load_grammar(). Las gramáticas (con un tokenizador personalizado y árboles de análisis personalizados) también se pueden crear instanciando directamente parso.Grammar(). Más información sobre los objetos resultantes se puede encontrar en la documentación del árbol de análisis.

La forma más sencilla de usar parso es sin siquiera cargar una gramática (parso.parse()):

>>> import parso
>>> parso.parse('foo + bar')
<Module: @1-1>

Carga de una Gramática

Típicamente, si quieres trabajar con una versión específica de Python, usa:

parso.load_grammar(*, version: str = None, path: str = None)
Carga una parso.Grammar. La versión predeterminada es la versión actual de Python.
Parámetros
  • version (str) -- Una cadena de versión de python, por ejemplo version='3.8'.
  • path (str) -- Una ruta a un archivo de gramática

Métodos de Gramática

Obtendrás un objeto de gramática que puedes usar para analizar código y encontrar problemas en él:

class parso.Grammar(text: str, *, tokenizer, parser=<class 'parso.parser.BaseParser'>, diff_parser=None)
parso.load_grammar() devuelve instancias de esta clase.

La creación de gramáticas personalizadas no-python llamando a esto no está soportada todavía.

Recuperación de Errores

parso es capaz de encontrar múltiples errores en tu código fuente. Iterar a través de esos errores produce las siguientes instancias:

class parso.normalizer.Issue(node, code, message)
code
Un código entero que representa el tipo de error.
message
Un mensaje (cadena de texto) para el problema.
start_pos
La posición de inicio del error como una tupla (línea, columna). Como siempre en parso, la primera línea es 1 y la primera columna 0.

Utilidad

parso también ofrece algunas funciones de utilidad que pueden ser realmente útiles:

parso.parse(code=None, **kwargs)
Una función de utilidad para evitar cargar gramáticas. Los parámetros se documentan en parso.Grammar.parse().
Parámetros
version (str) -- La versión utilizada por parso.load_grammar().
parso.split_lines(string: str, keepends: bool = False) -> Sequence[str]
Destinado a código Python. A diferencia de str.splitlines() de Python, considera los saltos de página y otros caracteres especiales como texto normal. Solo divide en \n y \r\n. También es diferente: Devuelve [""] para una entrada de cadena vacía.

En Python 2.7, los saltos de página se usan como caracteres normales al usar str.splitlines. Sin embargo, en Python 3, en algún momento se decidió dividir también por saltos de página.

parso.python_bytes_to_unicode(source: str | bytes, encoding: str = 'utf-8', errors: str = 'strict') -> str
Comprueba las BOM de unicode y las declaraciones de codificación PEP 263. Luego devuelve un objeto unicode como en bytes.decode().
Parámetros
  • encoding -- Ver la documentación de bytes.decode().
  • errors -- Ver la documentación de bytes.decode(). errors puede ser 'strict', 'replace' o 'ignore'.

Utilizado Por

  • jedi (que es utilizado por IPython y muchos plugins de editor).
  • mutmut (probador de mutaciones)

Árbol del Analizador Sintáctico

El árbol del analizador sintáctico se devuelve al llamar a parso.Grammar.parse().

NOTA:

Ten en cuenta que las posiciones de parso siempre se basan en 1 para las líneas y en 0 para las columnas. Esto significa que la primera posición en un archivo es (1, 0).

Árbol del Analizador Sintáctico de Python

Este es el árbol de sintaxis para las sintaxis de Python 3. Las clases representan elementos de sintaxis como funciones e importaciones.

Hay mucha lógica aquí que facilita que Jedi (y otras bibliotecas) trabajen con un árbol de sintaxis de Python.

Al usar parso.tree.NodeOrLeaf.get_code() en un módulo, puede obtener la representación 1 a 1 de la entrada dada al analizador. Esto es importante si desea refactorizar un árbol de analizador.

>>> from parso import parse
>>> parser = parse('import os')
>>> module = parser.get_root_node()
>>> module
<Module: @1-1>

Cualquier subclas de Scope, incluido Module, tiene un atributo iter_imports:

>>> list(module.iter_imports())
[<ImportName: import os@1,0>]

Cambios en la Gramática de Python

Algunas cosas han cambiado al mirar los archivos de gramática de Python:

  • Param no existe en los archivos de gramática de Python. Es esencialmente parte de un nodo parameters. parso lo divide para facilitar el análisis de los parámetros. Sin embargo, esto solo facilita el manejo del árbol de sintaxis, no cambia realmente la sintaxis válida.
  • Algunos nodos como lambdef y lambdef_nocond se han fusionado en el árbol de sintaxis para facilitar su manejo.

Development

If you want to contribute anything to parso, just open an issue or pull request to discuss it. We welcome changes! Please check the CONTRIBUTING.md file in the repository, first.

Deprecations Process

The deprecation process is as follows:

1.
A deprecation is announced in the next major/minor release.
2.
We wait either at least a year & at least two minor releases until we remove the deprecated functionality.
