INSTALACIÓN DE FLASK-MAIL

Instala con pip y easy_install:

pip install Flask-Mail

o descarga la última versión desde el control de versiones:

git clone https://github.com/mattupstate/flask-mail.git
cd flask-mail
python setup.py install

Si estás utilizando virtualenv, se asume que estás instalando flask-mail en el mismo entorno virtual que tu(s) aplicación(es) Flask.

CONFIGURACIÓN DE FLASK-MAIL

Flask-Mail se configura a través de la API de configuración estándar de Flask. Estas son las opciones disponibles (cada una se explica más adelante en la documentación):

  • MAIL_SERVER : por defecto 'localhost'
  • MAIL_PORT : por defecto 25
  • MAIL_USE_TLS : por defecto False
  • MAIL_USE_SSL : por defecto False
  • MAIL_DEBUG : por defecto app.debug
  • MAIL_USERNAME : por defecto None
  • MAIL_PASSWORD : por defecto None
  • MAIL_DEFAULT_SENDER : por defecto None
  • MAIL_MAX_EMAILS : por defecto None
  • MAIL_SUPPRESS_SEND : por defecto app.testing
  • MAIL_ASCII_ATTACHMENTS : por defecto False

Además, la opción de configuración estándar de Flask TESTING es utilizada por Flask-Mail en pruebas unitarias (ver abajo).

Los correos electrónicos se gestionan a través de una instancia de Mail:

from flask import Flask
from flask_mail import Mail
app = Flask(__name__)
mail = Mail(app)

En este caso, todos los correos electrónicos se envían utilizando los valores de configuración de la aplicación que se pasó al constructor de la clase Mail.

Alternativamente, puedes configurar tu instancia de Mail más tarde, en el momento de la configuración, utilizando el método init_app:

mail = Mail()
app = Flask(__name__)
mail.init_app(app)

En este caso, los correos electrónicos se enviarán utilizando los valores de configuración del contexto global current_app de Flask. Esto es útil si tienes varias aplicaciones ejecutándose en el mismo proceso pero con diferentes opciones de configuración.

ENVÍO DE MENSAJES

Para enviar un mensaje, primero crea una instancia de Message:

from flask_mail import Message
@app.route("/")
def index():
    msg = Message("Hola",
                  sender="from@example.com",
                  recipients=["to@example.com"])

Puedes establecer las direcciones de correo electrónico del destinatario inmediatamente, o individualmente:

msg.recipients = ["you@example.com"]
msg.add_recipient("somebodyelse@example.com")

Si has establecido MAIL_DEFAULT_SENDER, no necesitas establecer el remitente del mensaje explícitamente, ya que utilizará este valor de configuración por defecto:

msg = Message("Hola",
              recipients=["to@example.com"])

Si el remitente es una tupla de dos elementos, se dividirá en nombre y dirección:

msg = Message("Hola",
              sender=("Yo", "me@example.com"))
assert msg.sender == "Yo <me@example.com>"

El mensaje puede contener un cuerpo y/o HTML:

msg.body = "probando"
msg.html = "<b>probando</b>"

Finalmente, para enviar el mensaje, utilizas la instancia de Mail configurada con tu aplicación Flask:

mail.send(msg)

EMAILS MASIVOS

Normalmente en una aplicación web enviarás uno o dos correos electrónicos por solicitud. En ciertas situaciones, podrías querer poder enviar quizás decenas o cientos de correos electrónicos en un solo lote, probablemente en un proceso externo como un script de línea de comandos o un cronjob.

En ese caso, haces las cosas de manera un poco diferente:

with mail.connect() as conn:
    for user in users:
        message = '...'
        subject = "hola, %s" % user.name
        msg = Message(recipients=[user.email],
                      body=message,
                      subject=subject)
        conn.send(msg)

La conexión a tu servidor de correo se mantiene activa y se cierra automáticamente una vez que todos los mensajes han sido enviados.

Algunos servidores de correo establecen un límite en la cantidad de correos enviados en una sola conexión. Puedes establecer la cantidad máxima de correos electrónicos a enviar antes de reconectar especificando la configuración MAIL_MAX_EMAILS.

ARCHIVOS ADJUNTOS

Agregar archivos adjuntos es sencillo:

with app.open_resource("image.png") as fp:
    msg.attach("image.png", "image/png", fp.read())

Consulta la API para más detalles.

Si MAIL_ASCII_ATTACHMENTS se establece en True, los nombres de archivo se convertirán a un equivalente ASCII. Esto puede ser útil al usar un relé de correo que modifica el contenido del correo y estropea la especificación Content-Disposition cuando los nombres de archivo están codificados en UTF-8. La conversión a ASCII es una eliminación básica de caracteres no ASCII. Debería funcionar bien para cualquier carácter unicode que pueda descomponerse por NFKD en uno o más caracteres ASCII. Si necesitas romanización/transliteración (es decir, ß → ss), tu aplicación debería hacerlo y pasar una cadena ASCII adecuada.

PRUEBAS UNITARIAS Y SUPRESIÓN DE CORREOS

Cuando envías mensajes dentro de pruebas unitarias, o en un entorno de desarrollo, es útil poder suprimir el envío de correos electrónicos.

Si la configuración TESTING se establece en True, los correos electrónicos serán suprimidos. Llamar a send() en tus mensajes no resultará en que se envíen realmente mensajes.

Alternativamente, fuera de un entorno de pruebas, puedes establecer MAIL_SUPPRESS_SEND en False. Esto tendrá el mismo efecto.

Sin embargo, sigue siendo útil llevar un registro de los correos electrónicos que se habrían enviado cuando estás escribiendo pruebas unitarias.

Para llevar un registro de los correos electrónicos enviados, utiliza el método record_messages:

with mail.record_messages() as outbox:
    mail.send_message(subject='probando',
                      body='prueba',
                      recipients=emails)
    assert len(outbox) == 1
    assert outbox[0].subject == "probando"

El outbox es una lista de instancias de Message enviadas.

El paquete blinker debe estar instalado para que este método funcione.

Ten en cuenta que la forma anterior de hacer las cosas, adjuntar el outbox al objeto g, ahora está obsoleta.

SOPORTE DE SEÑALES

Añadido en la versión 0.4.

Flask-Mail ahora proporciona soporte de señales a través de una señal email_dispatched. Esta se envía cada vez que se envía un correo electrónico (incluso si el correo no se envía realmente, es decir, en un entorno de pruebas).

Una función que se conecta a la señal email_dispatched toma una instancia de Message como primer argumento y la instancia de la app de Flask como argumento opcional:

def log_message(message, app):
    app.logger.debug(message.subject)
email_dispatched.connect(log_message)
