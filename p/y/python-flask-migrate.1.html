NOMBRE

flask-migrate - Documentación de Flask-Migrate

Flask-Migrate es una extensión que maneja migraciones de bases de datos SQLAlchemy para aplicaciones Flask usando Alembic. Las operaciones de la base de datos se ponen a disposición a través de la interfaz de línea de comandos de Flask.

¿POR QUÉ USAR FLASK-MIGRATE VS. ALEMBIC DIRECTAMENTE?

Flask-Migrate es una extensión que configura Alembic de la manera correcta para trabajar con tu aplicación Flask y Flask-SQLAlchemy. En términos de las migraciones de base de datos reales, todo es manejado por Alembic, así que obtienes exactamente la misma funcionalidad.

INSTALACIÓN

Instala Flask-Migrate con pip:

pip install Flask-Migrate

EJEMPLO

Esta es una aplicación de ejemplo que maneja migraciones de bases de datos a través de Flask-Migrate:

from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate
app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///app.db'
db = SQLAlchemy(app)
migrate = Migrate(app, db)
class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(128))

Con la aplicación anterior, puedes crear un repositorio de migración con el siguiente comando:

$ flask db init

Esto añadirá una carpeta migrations a tu aplicación. El contenido de esta carpeta debe ser añadido al control de versiones junto con tus otros archivos fuente.

Luego puedes generar una migración inicial:

Luego puedes aplicar los cambios descritos por el script de migración a tu base de datos:

$ flask db upgrade

Cada vez que los modelos de la base de datos cambien, repite los comandos migrate y upgrade.

Para sincronizar la base de datos en otro sistema, simplemente refresca la carpeta migrations desde el control de versiones y ejecuta el comando upgrade.

Para ver todos los comandos disponibles, ejecuta este comando:

$ flask db --help

Ten en cuenta que el script de la aplicación debe estar configurado en la variable de entorno FLASK_APP para que todos los comandos anteriores funcionen, tal como lo requiere el comando flask.

Si el nombre del grupo de comandos db es inconveniente, se puede cambiar a uno diferente con el argumento command pasado a la clase Migrate:

migrate = Migrate(app, db, command='migrate')

OPCIONES DE CONFIGURACIÓN DE ALEMBIC

A partir de la versión 4.0, Flask-Migrate habilita automáticamente las siguientes opciones que están deshabilitadas por defecto en Alembic:

  • compare_type=True: Esta opción configura el subsistema de generación automática de migraciones para detectar cambios en los tipos de columna.
  • render_as_batch=True: Esta opción genera scripts de migración usando modo batch, un modo operativo que soluciona las limitaciones de muchos comandos ALTER en la base de datos SQLite implementando un flujo de trabajo de "mover y copiar". Habilitar este modo no debería marcar ninguna diferencia al trabajar con otras bases de datos.
migrate = Migrate(app, db, render_as_batch=False)

CALLBACKS DE CONFIGURACIÓN

A veces las aplicaciones necesitan insertar dinámicamente su propia configuración en la configuración de Alembic. Una función decorada con el callback configure se invocará después de que la configuración sea leída y antes de que sea aplicada. La función puede modificar el objeto de configuración o reemplazarlo con uno diferente.

@migrate.configure
def configure_alembic(config):
    # modificar objeto de configuración
    return config

Se pueden definir múltiples callbacks de configuración simplemente decorando múltiples funciones. El orden en el que se invocan múltiples callbacks es indeterminado.

SOPORTE PARA MÚLTIPLES BASES DE DATOS

Para crear un repositorio de migración de múltiples bases de datos, añade el argumento --multidb al comando init:

$ flask db init --multidb

Con este comando, el repositorio de migración se configurará para seguir las migraciones en tu base de datos principal y en cualquier base de datos adicional definida en la opción de configuración SQLALCHEMY_BINDS.

REFERENCIA DE COMANDOS

Flask-Migrate expone una clase llamada Migrate. Esta clase contiene toda la funcionalidad de la extensión.

El siguiente ejemplo inicializa la extensión con la interfaz de línea de comandos estándar de Flask:

from flask_migrate import Migrate
migrate = Migrate(app, db)

Los dos argumentos para Migrate son la instancia de la aplicación y la instancia de la base de datos Flask-SQLAlchemy. El constructor de Migrate también acepta argumentos de palabra clave adicionales, que se pasan al método EnvironmentContext.configure() de Alembic. Como es estándar para todas las extensiones Flask, Flask-Migrate puede ser inicializado usando el método init_app también:

from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate
db = SQLAlchemy()
migrate = Migrate()
def create_app():
     """Patrón de factoría de aplicaciones"""
     ...
     ...
     db.init_app(app)
     migrate.init_app(app, db)
     ...
     ...
     return app

Después de que la extensión es inicializada, un grupo db será añadido a las opciones de línea de comandos con varios subcomandos. A continuación se presenta una lista de los subcomandos disponibles:

NAME

python-flask-migrate — SQLAlchemy/Alembic scripting support for Flask applications

SYNOPSIS

flask db command [OPTIONS]

DESCRIPTION

Flask-Migrate is a Flask-Migrate extension that handles SQLAlchemy database migrations for Flask applications using Alembic.

WHY USE FLASK-MIGRATE VS. ALEMBIC DIRECTLY?

Flask-Migrate is a thin wrapper around Alembic. The goal is to make Alembic easy to use in a Flask application. It provides a Flask command-line interface (CLI) integration for Alembic. It also automatically discovers your Flask application's configuration and database models.

With Flask-Migrate, you don't need to worry about configuring Alembic. Flask-Migrate handles all of that for you. It also automatically discovers your Flask application's database models, so you don't have to manually register them with Alembic.

If you need more advanced features, you can always use Alembic directly. However, for most Flask applications, Flask-Migrate is sufficient.

INSTALLATION

Install Flask-Migrate using pip:

pip install Flask-Migrate

Then, initialize Flask-Migrate in your Flask application:

from flask import Flask
from flask_migrate import Migrate

app = Flask(__name__)
# ... other Flask app configurations ...
db = SQLAlchemy(app)
migrate = Migrate(app, db)

This will create a migrations directory in your project, which will store your database migration scripts.

EXAMPLE

Here is a simple example of how to use Flask-Migrate:

from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate

app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///mydatabase.db'
db = SQLAlchemy(app)
migrate = Migrate(app, db)

class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)

if __name__ == '__main__':
    app.run(debug=True)

Once you have your Flask application set up, you can use the Flask-Migrate CLI commands to manage your database migrations:

  • flask db init: Initialize the migrations repository.

  • flask db migrate: Create a new migration script based on changes in your models.

  • flask db upgrade: Apply the migrations to your database.

  • flask db downgrade: Revert the last migration.

ALEMBIC CONFIGURATION OPTIONS

Flask-Migrate uses Alembic's configuration file, alembic.ini, to control its behavior. You can customize Alembic's settings by editing this file. Some common options include:

  • script_location: The directory where Alembic stores its migration scripts. Defaults to migrations/.

  • sqlalchemy.url: The database connection URL. This can be overridden by the Flask application's configuration.

  • revision_environment: Set to true to enable revision environment configuration.

For a full list of Alembic configuration options, refer to the Alembic documentation.

CONFIGURATION CALLBACKS

Flask-Migrate allows you to hook into Alembic's configuration process using callback functions. You can define these callbacks in your application's env.py file (located within the migrations directory).

Common callbacks include:

  • target_metadata: Set this to your SQLAlchemy metadata object. Flask-Migrate will automatically discover this if you have a single SQLAlchemy instance in your app.

  • configure_logger: A function to configure Alembic's logger.

Example env.py snippet:

# ... other imports ...
from my_flask_app import db as current_db
from my_flask_app.models import Base  # Assuming Base is your declarative base

def run_migrations_online():
    # ... Alembic configuration ...
    target_metadata = Base.metadata
    # ... rest of the configuration ...

run_migrations_online()

Note that if you have multiple databases, you'll need to manually configure target_metadata and potentially other settings within env.py.

MULTIPLE DATABASE SUPPORT

Flask-Migrate supports multiple databases. To configure multiple databases, you need to:

  • Define multiple SQLAlchemy instances in your Flask application.

  • Explicitly provide the database instances and metadata to the Migrate constructor.

  • Manually configure your env.py file to handle multiple metadata objects and connection URLs.

Example initialization:

from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate

db1 = SQLAlchemy()
db2 = SQLAlchemy()
migrate = Migrate(db1, db2) # Pass multiple db instances

For more details on configuring multiple databases, refer to the Flask-Migrate documentation on multiple databases.

COMMAND REFERENCE

The flask db command provides the following subcommands:

  • init: Initialize the migrations repository. Creates the migrations directory and a basic alembic.ini file.

  • migrate: Generate a new migration script. Compares your current models with the database schema and creates a script to reconcile them.

    migrate -m "Migration message": Add a descriptive message to the migration.

  • upgrade: Apply pending migrations to the database. Migrates the database to the latest revision.

    upgrade [revision]: Upgrade to a specific revision.

  • downgrade: Revert the last applied migration.

    downgrade [revision]: Downgrade to a specific revision.

  • show [revision]: Show the difference between the database schema and the given revision.

  • edit [revision]: Edit a specific migration script.

  • history: List migration history.

  • stamp [revision]: Directly stamp a revision onto the database without running migrations. Useful for setting the initial state.

API REFERENCE

Flask-Migrate exposes an API that can be used for more programmatic control over migrations.

The main class is Migrate:

class
Migrate(app=None, db=None, **kwargs)

When initializing Migrate, you can pass your Flask app and SQLAlchemy db objects. Additional keyword arguments are passed directly to Alembic's configuration.

You can also use the underlying Alembic API directly by importing it:

  • from flask_migrate import upgrade, downgrade, migrate, init, stamp, revision, show, history, edit

These functions allow you to trigger migration actions from within your Python code. The configuration of the process will be overridden by Alembic according to the contents of the alembic.ini file.

  • For greater scripting flexibility you can also use the API exposed by Alembic directly.
