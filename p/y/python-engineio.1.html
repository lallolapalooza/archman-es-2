python-engineio - Documentación de python-engineio

Este proyecto implementa un cliente y servidor Engine.IO basado en Python que puede ejecutarse de forma independiente o integrado con una variedad de frameworks y aplicaciones web de Python.

COMIENZO

¿Qué es Engine.IO?

Engine.IO es un protocolo de transporte ligero que permite la comunicación bidireccional en tiempo real basada en eventos entre clientes (típicamente, aunque no siempre, navegadores web) y un servidor. Las implementaciones oficiales de los componentes cliente y servidor están escritas en JavaScript. Este paquete proporciona implementaciones de Python de ambos, cada una con variantes estándar y para asyncio.

El protocolo Engine.IO es extremadamente simple. Una vez que se establece una conexión entre un cliente y un servidor, cualquiera de los lados puede enviar "mensajes" al otro lado. Los manejadores de eventos proporcionados por las aplicaciones en ambos extremos se invocan cuando se recibe un mensaje, o cuando una conexión se establece o se interrumpe.

Ejemplos de Cliente

El siguiente ejemplo muestra un cliente simple de Python:

import engineio
eio = engineio.Client()
@eio.on('connect')
def on_connect():
    print('conexión establecida')
@eio.on('message')
def on_message(data):
    print('mensaje recibido con ', data)
    eio.send({'response': 'mi respuesta'})
@eio.on('disconnect')
def on_disconnect():
    print('desconectado del servidor')
eio.connect('http://localhost:5000')
eio.wait()

Y aquí hay un cliente similar escrito usando el cliente oficial Engine.IO de Javascript:

<script src="/ruta/a/engine.io.js"></script>
<script>
    var socket = eio('http://localhost:5000');
    socket.on('open', function() { console.log('conexión establecida'); });
    socket.on('message', function(data) {
        console.log('mensaje recibido con ' + data);
        socket.send({response: 'mi respuesta'});
    });
    socket.on('close', function() { console.log('desconectado del servidor'); });
</script>

Características del Cliente

  • Puede conectarse a otros servidores compatibles con Engine.IO además del de este paquete.
  • Compatible con Python 3.6+.
  • Dos versiones del cliente, una para Python estándar y otra para asyncio.
  • Utiliza una arquitectura basada en eventos implementada con decoradores que oculta los detalles del protocolo.
  • Implementa transportes HTTP long-polling y WebSocket.

Ejemplos de Servidor

La siguiente aplicación es un ejemplo básico que utiliza el servidor asíncrono Eventlet:

import engineio
import eventlet
eio = engineio.Server()
app = engineio.WSGIApp(eio, static_files={
    '/': {'content_type': 'text/html', 'filename': 'index.html'}
})
@eio.on('connect')
def connect(sid, environ):
    print("conectar ", sid)
@eio.on('message')
def message(sid, data):
    print("mensaje ", data)
    eio.send(sid, 'respuesta')
@eio.on('disconnect')
def disconnect(sid):
    print('desconectar ', sid)
if __name__ == '__main__':
    eventlet.wsgi.server(eventlet.listen(('', 5000)), app)

A continuación se muestra una aplicación similar, codificada para asyncio y el servidor web Uvicorn:

  • La clase engineio.Client() crea un cliente compatible con la biblioteca estándar de Python.
  • La clase engineio.AsyncClient() crea un cliente compatible con el paquete asyncio.

Los métodos de los dos clientes son los mismos, siendo la única diferencia que en el cliente asyncio la mayoría de los métodos se implementan como corrutinas.

Instalación

Para instalar el cliente estándar de Python junto con sus dependencias, use el siguiente comando:

pip install "python-engineio[client]"

Si en su lugar planea usar el cliente asyncio, entonces use este:

pip install "python-engineio[asyncio_client]"

Creación de una Instancia de Cliente

Para instanciar un cliente Engine.IO, simplemente cree una instancia de la clase de cliente apropiada:

import engineio
# Python estándar
eio = engineio.Client()
# asyncio
eio = engineio.AsyncClient()

Definición de Manejadores de Eventos

Para responder a eventos activados por la conexión o el servidor, se deben definir funciones manejadoras de eventos usando el decorador on:

@eio.on('connect')
def on_connect():
    print('¡Estoy conectado!')
@eio.on('message')
def on_message(data):
    print('¡He recibido un mensaje!')
@eio.on('disconnect')
def on_disconnect(reason):
    print('¡Estoy desconectado! razón:', reason)

Para el servidor asyncio, los manejadores de eventos pueden ser funciones regulares como las anteriores, o también pueden ser corrutinas:

@eio.on('message')
async def on_message(data):
    print('¡He recibido un mensaje!')

El argumento dado al decorador on es el nombre del evento. Los eventos que se soportan son connect, message y disconnect.

El argumento data pasado al manejador del evento 'message' contiene datos específicos de la aplicación proporcionados por el servidor con el evento.

Conexión a un Servidor

La conexión a un servidor se establece llamando al método connect():

eio.connect('http://localhost:5000')

En el caso del cliente asyncio, el método es una corrutina:

await eio.connect('http://localhost:5000')

Tras la conexión, el servidor asigna al cliente un identificador de sesión único. La aplicación puede encontrar este identificador en el atributo sid:

print('mi sid es', eio.sid)

Envío de Mensajes

El cliente puede enviar un mensaje al servidor utilizando el método send():

eio.send({'foo': 'bar'})

O en el caso de asyncio, como una corrutina:

await eio.send({'foo': 'bar'})

El único argumento proporcionado al método son los datos que se pasan al servidor. Los datos pueden ser de tipo str, bytes, dict o list. Los datos incluidos dentro de diccionarios y listas también están limitados a estos tipos.

El método send() se puede invocar dentro de un manejador de eventos como respuesta a un evento del servidor, o en cualquier otra parte de la aplicación, incluyendo tareas en segundo plano.

Desconexión del Servidor

En cualquier momento, el cliente puede solicitar ser desconectado del servidor invocando el método disconnect():

eio.disconnect()

Para el cliente asyncio, esto es una corrutina:

await eio.disconnect()

Gestión de Tareas en Segundo Plano

Cuando se establece una conexión de cliente con el servidor, se crearán algunas tareas en segundo plano para mantener la conexión activa y gestionar los eventos entrantes. La aplicación que se ejecuta en el hilo principal es libre de realizar cualquier trabajo, ya que esto no impedirá el funcionamiento del cliente Engine.IO.

Si la aplicación no tiene nada que hacer en el hilo principal y solo quiere esperar hasta que termine la conexión, puede llamar al método wait():

eio.wait()

O en la versión asyncio:

await eio.wait()

Para comodidad de la aplicación, se proporciona una función auxiliar para iniciar una tarea personalizada en segundo plano:

def mi_tarea_en_segundo_plano(mi_argumento)
    # ¡haz algún trabajo en segundo plano aquí!
    pass
eio.start_background_task(mi_tarea_en_segundo_plano, 123)

Los argumentos pasados a este método son la función de segundo plano y cualquier argumento posicional o de palabra clave para invocar la función.

Aquí está la versión asyncio:

async def mi_tarea_en_segundo_plano(mi_argumento)
    # ¡haz algún trabajo en segundo plano aquí!
    pass
eio.start_background_task(mi_tarea_en_segundo_plano, 123)

Tenga en cuenta que esta función no es una corrutina, ya que no espera a que termine la función de segundo plano, pero la función de segundo plano sí lo hace.

El método sleep() es una segunda función de conveniencia que se proporciona en beneficio de las aplicaciones que trabajan con sus propias tareas en segundo plano:

eio.sleep(2)

O para asyncio:

await eio.sleep(2)

El único argumento pasado al método es el número de segundos para dormir.

Depuración y Solución de Problemas

Para ayudarle a depurar problemas, el cliente se puede configurar para que muestre registros en la terminal:

import engineio
# Python estándar
eio = engineio.Client(logger=True)
# asyncio
eio = engineio.AsyncClient(logger=True)

El argumento logger se puede establecer en True para mostrar registros en stderr, o en un objeto compatible con el paquete logging de Python, donde se emitirán los registros. Un valor de False deshabilita el registro.

El registro puede ayudar a identificar la causa de los problemas de conexión, desconexiones inesperadas y otros problemas.

EL SERVIDOR ENGINE.IO

Este paquete contiene dos servidores Engine.IO:

  • La clase engineio.Server() crea un servidor compatible con la biblioteca estándar de Python.
  • La clase engineio.AsyncServer() crea un servidor compatible con el paquete asyncio.

Los métodos de ambos servidores son los mismos, con la única diferencia de que en el servidor asyncio la mayoría de los métodos se implementan como corrutinas.

Instalación

Para instalar el servidor Engine.IO de Python, utilice el siguiente comando:

pip install "python-engineio"

Además del servidor, deberá seleccionar un marco o servidor asíncrono para usar junto con él. La lista de paquetes compatibles se cubre en la sección Estrategias de Despliegue.

Creación de una Instancia de Servidor

Un servidor Engine.IO es una instancia de la clase engineio.Server. Esta instancia se puede transformar en una aplicación WSGI estándar envolviéndola con la clase engineio.WSGIApp:

import engineio
# crear un servidor Engine.IO
eio = engineio.Server()
# envolver con una aplicación WSGI
app = engineio.WSGIApp(eio)

Para servidores basados en asyncio, la clase engineio.AsyncServer proporciona la misma funcionalidad, pero en un formato amigable para corrutinas. Si se desea, la clase engineio.ASGIApp puede transformar el servidor en una aplicación ASGI estándar:

# crear un servidor Engine.IO
eio = engineio.AsyncServer()
# envolver con aplicación ASGI
app = engineio.ASGIApp(eio)

Estos dos envoltorios también pueden actuar como intermediarios, reenviando cualquier tráfico que no esté destinado al servidor Engine.IO a otra aplicación. Esto permite que los servidores Engine.IO se integren fácilmente en aplicaciones WSGI o ASGI existentes:

from wsgi import app  # una aplicación Flask, Django, etc.
app = engineio.WSGIApp(eio, app)

Servir Archivos Estáticos

El servidor Engine.IO se puede configurar para servir archivos estáticos a los clientes. Esto es particularmente útil para entregar archivos HTML, CSS y JavaScript a los clientes cuando este paquete se utiliza sin un marco web complementario.

Los archivos estáticos se configuran con un diccionario de Python en el que cada par clave/valor es una regla de mapeo de archivo estático. En su forma más simple, este diccionario tiene una o más URLs de archivo estático como claves y los archivos correspondientes en el servidor como valores:

archivos_estaticos = {
    '/': 'latency.html',
    '/static/engine.io.js': 'static/engine.io.js',
    '/static/style.css': 'static/style.css',
}

Con este ejemplo de configuración, cuando el servidor recibe una solicitud para / (la URL raíz), devolverá el contenido del archivo latency.html en el directorio actual y asignará un tipo de contenido basado en la extensión del archivo, en este caso text/html.

Los archivos con las extensiones de archivo .html, .css, .js, .json, .jpg, .png, .gif y .txt se reconocen automáticamente y se les asigna el tipo de contenido correcto. Para archivos con otras extensiones de archivo o sin extensión de archivo, se utiliza el tipo de contenido application/octet-stream como predeterminado.

Si se desea, se puede especificar un tipo de contenido explícito para un archivo estático de la siguiente manera:

archivos_estaticos = {
    '/': {'filename': 'latency.html', 'content_type': 'text/plain'},
}

También es posible configurar un directorio completo en una sola regla, de modo que todos los archivos de él se sirvan como archivos estáticos:

archivos_estaticos = {
    '/static': './public',
}

En este ejemplo, cualquier archivo con URL que comience con /static se servirá directamente desde la carpeta public en el directorio actual, por lo que, por ejemplo, la URL /static/index.html devolverá el archivo local ./public/index.html y la URL /static/css/styles.css devolverá el archivo local ./public/css/styles.css.

Si se solicita una URL que termina en /, se le anexa un nombre de archivo predeterminado de index.html. En el ejemplo anterior, una solicitud para la URL /static/ devolvería el archivo local ./public/index.html. El nombre de archivo predeterminado para servir URL que terminan en barra se puede establecer en el diccionario de archivos estáticos con una clave vacía:

archivos_estaticos = {
    '/static': './public',
    '': 'image.gif',
}

Con esta configuración, una solicitud para /static/ devolvería el archivo local ./public/image.gif. También se puede especificar un tipo de contenido no estándar si es necesario:

archivos_estaticos = {
    '/static': './public',
    '': {'filename': 'image.gif', 'content_type': 'text/plain'},
}

Configuración de Archivos Estáticos

Para que el servidor sea capaz de servir archivos estáticos (por ejemplo, el cliente JavaScript), se debe proporcionar un diccionario de mapeo de rutas a archivos o directorios al argumento static_files de las clases engineio.WSGIApp o engineio.ASGIApp:

# para aplicaciones WSGI estándar
eio = engineio.Server()
app = engineio.WSGIApp(eio, static_files=static_files)
# para aplicaciones ASGI basadas en asyncio
eio = engineio.AsyncServer()
app = engineio.ASGIApp(eio, static_files=static_files)

La precedencia de enrutamiento en estas dos clases es la siguiente:

  • Primero, la ruta se verifica contra la ruta de Engine.IO.
  • A continuación, la ruta se verifica contra la configuración de archivos estáticos, si está presente.
  • Si la ruta no coincidió con la ruta de Engine.IO ni con ningún archivo estático, el control se pasa a la aplicación secundaria si está configurada, de lo contrario, se devuelve un error 404.

Nota: el servicio de archivos estáticos está destinado exclusivamente al uso en desarrollo y, como tal, carece de características importantes como el almacenamiento en caché. No lo utilice en un entorno de producción.

Definición de Manejadores de Eventos

Para responder a eventos activados por la conexión o por el cliente, se deben definir funciones manejadoras de eventos utilizando el decorador on:

@eio.on('connect')
def on_connect(sid):
    print('¡Un cliente se conectó!')
@eio.on('message')
def on_message(sid, data):
    print('¡Recibí un mensaje!')
@eio.on('disconnect')
def on_disconnect(sid, reason):
    print('¡Cliente desconectado! motivo:', reason)

Para el servidor asyncio, los manejadores de eventos pueden ser funciones normales como las anteriores, o también pueden ser corrutinas:

@eio.on('message')
async def on_message(sid, data):
    print('¡Recibí un mensaje!')

El argumento que se pasa al decorador on es el nombre del evento. Los eventos que son compatibles son connect, message y disconnect.

El argumento sid que se pasa a todos los manejadores de eventos es un identificador de conexión para el cliente. Todos los eventos de un cliente usarán el mismo valor sid.

El manejador connect es el lugar donde el servidor puede realizar la autenticación. El valor devuelto por este manejador se usa para determinar si la conexión se acepta o se rechaza. Cuando el manejador no devuelve ningún valor (que es lo mismo que devolver None) o cuando devuelve True, la conexión se acepta. Si el manejador devuelve False o cualquier tipo de dato compatible con JSON (cadena, entero, lista o diccionario), la conexión se rechaza. Una conexión rechazada activa una respuesta con un código de estado 401.

El argumento data que se pasa al manejador del evento 'message' contiene datos específicos de la aplicación proporcionados por el cliente con el evento.

El manejador disconnect se invoca para desconexiones iniciadas por el cliente, desconexiones iniciadas por el servidor o desconexiones accidentales, por ejemplo, debido a fallos de red. El segundo argumento que se pasa a este manejador proporciona el motivo de la desconexión. Ejemplo:

@eio.on('disconnect')
def on_disconnect(sid, reason):
    if reason == eio.reason.CLIENT_DISCONNECT:
        print('el cliente se fue')
    elif reason == eio.reason.SERVER_DISCONNECT:
        print('el cliente fue expulsado')
    else:
        print(f'motivo de desconexión: {reason}')

Envío de Mensajes

El servidor puede enviar un mensaje a cualquier cliente usando el método send():

eio.send(sid, {'foo': 'bar'})

O en el caso de asyncio, como una corrutina:

await eio.send(sid, {'foo': 'bar'})

El primer argumento proporcionado al método es el identificador de conexión para el cliente receptor. El segundo argumento son los datos que se pasan al servidor. Los datos pueden ser de tipo str, bytes, dict o list. Los datos incluidos dentro de diccionarios y listas también están restringidos a estos tipos.

El método send() puede invocarse dentro de un manejador de eventos como respuesta a un evento del cliente, o en cualquier otra parte de la aplicación, incluyendo tareas en segundo plano.

Sesiones de Usuario

El servidor puede mantener información específica de la aplicación en una sesión de usuario dedicada a cada cliente conectado. Las aplicaciones pueden usar la sesión de usuario para escribir cualquier detalle sobre el usuario que deba conservarse durante toda la vida de la conexión, como nombres de usuario o identificadores de usuario.

Los métodos save_session() y get_session() se utilizan para almacenar y recuperar información en la sesión de usuario:

@eio.on('connect')
def on_connect(sid, environ):
    username = authenticate_user(environ)
    eio.save_session(sid, {'username': username})
@eio.on('message')
def on_message(sid, data):
    session = eio.get_session(sid)
    print('mensaje de ', session['username'])

Para el servidor asyncio, estos métodos son corrutinas:

@eio.on('connect')
async def on_connect(sid, environ):
    username = authenticate_user(environ)
    await eio.save_session(sid, {'username': username})
@eio.on('message')
async def on_message(sid, data):
    session = await eio.get_session(sid)
    print('mensaje de ', session['username'])

La sesión también se puede manipular con el gestor de contexto session():

@eio.on('connect')
def on_connect(sid, environ):
    username = authenticate_user(environ)
    with eio.session(sid) as session:
        session['username'] = username
@eio.on('message')
def on_message(sid, data):
    with eio.session(sid) as session:
        print('mensaje de ', session['username'])

Para el servidor asyncio, se utiliza un gestor de contexto asíncrono:

@eio.on('connect')
def on_connect(sid, environ):
    username = authenticate_user(environ)
    async with eio.session(sid) as session:
        session['username'] = username
@eio.on('message')
def on_message(sid, data):
    async with eio.session(sid) as session:
        print('mensaje de ', session['username'])

Nota: el contenido de la sesión de usuario se destruye cuando el cliente se desconecta.

Estrategias de Despliegue

Las siguientes secciones describen una variedad de estrategias de despliegue para servidores Engine.IO.

Uvicorn, Daphne y otros servidores ASGI

La clase engineio.ASGIApp es una aplicación compatible con ASGI que puede reenviar el tráfico de Engine.IO a una instancia de engineio.AsyncServer:

eio = engineio.AsyncServer(async_mode='asgi')
app = engineio.ASGIApp(eio)

Si se desea, la clase engineio.ASGIApp puede reenviar cualquier tráfico que no sea de Engine.IO a otra aplicación ASGI, lo que permite desplegar una aplicación web ASGI estándar y el servidor Engine.IO como un paquete:

eio = engineio.AsyncServer(async_mode='asgi')
app = engineio.ASGIApp(eio, other_app)

La instancia de ASGIApp es una instancia ASGI totalmente compatible que puede desplegarse con un servidor web compatible con ASGI.

Aiohttp

Las instancias de la clase engineio.AsyncServer utilizarán automáticamente aiohttp para operaciones asíncronas si la biblioteca está instalada. Para solicitar explícitamente su uso, se puede proporcionar la opción async_mode en el constructor:

Eventlet con Gunicorn

Una alternativa a ejecutar el servidor WSGI de eventlet como se indicó anteriormente es usar gunicorn, un servidor web completo de Python puro. A continuación se muestra el comando para lanzar la aplicación bajo gunicorn:

$ gunicorn -k eventlet -w 1 module:app

Debido a limitaciones en su algoritmo de balanceo de carga, gunicorn solo se puede usar con un proceso de trabajador, por lo que se requiere la opción -w 1. Tenga en cuenta que un solo trabajador de eventlet puede manejar un gran número de clientes concurrentes.

Otra limitación al usar gunicorn es que el transporte WebSocket no está disponible, ya que este transporte requiere extensiones al estándar WSGI.

Nota: Eventlet proporciona una función monkey_patch() que reemplaza todas las funciones de bloqueo de la biblioteca estándar con versiones asíncronas equivalentes. Si bien python-engineio no requiere monkey patching, es probable que otras bibliotecas, como los controladores de bases de datos, lo requieran.

Notas de escalabilidad

Engine.IO es un protocolo con estado, lo que dificulta la escalabilidad horizontal. Para implementar un clúster de procesos Engine.IO alojados en uno o varios servidores, se deben cumplir las siguientes condiciones:

  • Cada proceso de servidor Engine.IO debe ser capaz de manejar múltiples solicitudes concurrentemente. Esto es necesario porque los clientes de sondeo largo envían dos solicitudes en paralelo. Los procesos de trabajador que solo pueden manejar una solicitud a la vez no son compatibles.
  • El balanceador de carga debe configurarse para reenviar siempre las solicitudes de un cliente al mismo proceso. Los balanceadores de carga llaman a esto sesiones persistentes o afinidad de sesión.

Controles entre orígenes

Por razones de seguridad, este servidor aplica una política del mismo origen por defecto. En términos prácticos, esto significa lo siguiente:

  • Si una solicitud HTTP o WebSocket entrante incluye la cabecera Origin, esta cabecera debe coincidir con el esquema y el host de la URL de conexión. En caso de discrepancia, se devuelve una respuesta con código de estado 400 y se rechaza la conexión.
  • No se imponen restricciones a las solicitudes entrantes que no incluyen la cabecera Origin.

Si es necesario, la opción cors_allowed_origins se puede utilizar para permitir otros orígenes. Este argumento se puede establecer como una cadena para definir un único origen permitido, o como una lista para permitir varios orígenes. Se puede utilizar un valor especial de '*' para indicar al servidor que permita todos los orígenes, pero esto debe hacerse con precaución, ya que podría hacer que el servidor sea vulnerable a ataques de falsificación de solicitud entre sitios (CSRF).

NAME¶

engine.io – Transport Layer for Realtime Bi-directional Communications

GETTING STARTED¶

Engine.IO is a Node.js library that implements the WebSocket protocol with fallback options for older browsers and networks. It is designed to provide a robust and reliable real-time communication channel between clients and servers.

To get started, you can install Engine.IO via npm:

npm install engine.io

Here is a basic example of how to set up an Engine.IO server and client:

Server:

const http = require('http');
const engine = require('engine.io');

const server = http.createServer();
const eio = engine.attach(server);

eio.on('connection', socket => {
  console.log('Client connected:', socket.id);

  socket.on('message', data => {
    console.log('Message from client:', data);
    socket.send('Hello from server!');
  });

  socket.on('close', () => {
    console.log('Client disconnected:', socket.id);
  });
});

server.listen(3000, () => {
  console.log('Server listening on port 3000');
});

Client:

<script src="https://cdnjs.cloudflare.com/ajax/libs/engine.io-client/5.3.1/engine.io.min.js"></script>
<script>
  const socket = eio('http://localhost:3000');

  socket.onopen = () => {
    console.log('Connected to server');
    socket.send('Hello from client!');
  };

  socket.onmessage = event => {
    console.log('Message from server:', event.data);
  };

  socket.onclose = () => {
    console.log('Disconnected from server');
  };

  socket.onerror = error => {
    console.error('Socket error:', error);
  };
</script>

THE ENGINE.IO CLIENT¶

The Engine.IO client is a JavaScript library that can be included in web pages or used in Node.js environments. It handles the connection to the Engine.IO server and provides a simple API for sending and receiving messages.

Key features of the client include:

  • Automatic detection and use of the best available transport (WebSocket, XHR long-polling).
  • Automatic reconnection in case of network failures.
  • Support for message fragmentation and reassembly.

The client can be used in a browser by including the script tag as shown in the previous example, or in Node.js by installing the engine.io-client package:

npm install engine.io-client

And then used in your JavaScript code:

const eio = require('engine.io-client');

const socket = eio('ws://localhost:3000'); // or http://localhost:3000

socket.on('open', () => {
  console.log('Connected');
  socket.send('Hello');
});

socket.on('message', data => {
  console.log('Received:', data);
});

socket.on('close', () => {
  console.log('Disconnected');
});

THE ENGINE.IO SERVER¶

The Engine.IO server is a Node.js library that provides the backend for real-time communication. It listens for incoming connections from Engine.IO clients and manages the communication channels.

The server can be integrated with existing HTTP servers (e.g., from Node.js's built-in `http` module or frameworks like Express). It supports various transports and handles the complexities of maintaining persistent connections.

When a client connects, the server emits a `connection` event with a `socket` object. This `socket` object represents the connection to the client and provides methods for sending messages and listening for client events like `message` and `close`.

The server also handles heartbeats to ensure that connections are kept alive and detects disconnections promptly.

API REFERENCE¶

The Engine.IO API is designed to be simple and intuitive. Here are some of the key components:

Engine.IO Server¶

`engine.attach(server, [options])`: Attaches Engine.IO to an existing HTTP server.

`eio.on('connection', (socket) => {})`: Event handler for new client connections.

`socket.send(data)`: Sends data to the connected client.

`socket.on('message', (data) => {})`: Event handler for incoming messages from the client.

`socket.on('close', () => {})`: Event handler for client disconnections.

Engine.IO Client¶

`eio(url, [options])`: Creates a new Engine.IO client instance and connects to the specified URL.

`socket.send(data)`: Sends data to the server.

`socket.onopen`: Event handler for successful connection.

`socket.onmessage`: Event handler for incoming messages from the server.

`socket.onclose`: Event handler for disconnections.

`socket.onerror`: Event handler for errors.
