PYENV(1) Manual de Comandos Generales PYENV(1)

NOMBRE

pyenv - Gestión simple de versiones de Python

SINOPSIS

pyenv <comando> [<argumentos>]

DESCRIPCIÓN

pyenv te permite cambiar fácilmente entre múltiples versiones de Python. Es simple, discreto y sigue la tradición UNIX de herramientas de un solo propósito que hacen una cosa bien.


Para empezar a usar pyenv

1.
Añade lo siguiente a $HOME/.bashrc
if command -v pyenv 1>/dev/null 2>&1; then
   eval "$(pyenv init - bash)" 
fi

Al añadir esta línea se habilitan los shims. Asegúrate de que esta línea se coloque hacia el final del archivo de configuración del shell, ya que manipula PATH durante la inicialización.

Nota sobre Debian:
Modifica solo tu archivo ~/.bashrc en lugar de crear
~/.bash_profile
Nota sobre Zsh: Modifica tu archivo ~/.zshrc en lugar de ~/.bashrc

Advertencia: Si configuraste tu sistema de tal manera que la variable BASH_ENV apunte a .bashrc. Casi con toda seguridad deberías colocar la línea mencionada anteriormente en .bash_profile y no en .bashrc. De lo contrario, podrías observar un comportamiento extraño, como que pyenv entre en un bucle infinito. Ver #264 https://github.com/pyenv/pyenv/issues/264 para más detalles.

2.
Reinicia tu shell para que los cambios en el PATH surtan efecto. Ya puedes empezar a usar pyenv.
exec "$SHELL"
3.
Instala versiones de Python en $(pyenv root)/versions. Por ejemplo, para descargar e instalar Python 3.6.12, ejecuta:
pyenv install 3.6.12

NOTA: Si necesitas pasar opciones de configuración para la compilación, por favor usa la variable de entorno CONFIGURE_OPTS. Si tienes problemas para instalar una versión de Python, visita la página de wiki sobre Problemas Comunes de Compilación https://github.com/pyenv/pyenv/wiki/Common-build-problems

Nota sobre Proxy: Si usas un proxy, exporta las variables de entorno HTTP_PROXY y HTTPS_PROXY.

Dejar de usar pyenv

La simplicidad de pyenv hace que sea fácil deshabilitarlo temporalmente o desinstalarlo del sistema. Para deshabilitar que pyenv gestione tus versiones de Python, simplemente elimina la línea de pyenv init de la configuración de inicio de tu shell. Esto eliminará el directorio de shims de pyenv del PATH, y futuras invocaciones como python ejecutarán la versión de Python del sistema, como antes de pyenv.

pyenv seguirá siendo accesible en la línea de comandos, pero tus aplicaciones Python no se verán afectadas por el cambio de versión.

COMPARACIÓN

pyenv hace...

  • Te permite cambiar la versión global de Python por usuario.
  • Proporciona soporte para versiones de Python por proyecto.
  • Te permite sobrescribir la versión de Python con una variable de entorno.
  • Busca comandos en múltiples versiones de Python a la vez. Esto puede ser útil para probar en diferentes versiones de Python con tox

A diferencia de pythonbrew y pythonz, pyenv no...

  • Depende de Python mismo. pyenv se ha creado con scripts puros de shell. No hay problema de arranque de Python.
  • Necesita ser cargado en tu shell. En cambio, el enfoque de shims de pyenv funciona añadiendo un directorio a tu $PATH.
  • Gestiona virtualenv. Por supuesto, puedes crear virtualenv tú mismo, o usar pyenv-virtualenv para automatizar el proceso.

Cómo Funciona

A un alto nivel, pyenv intercepta los comandos de Python usando ejecutables shim inyectados en tu PATH, determina qué versión de Python ha sido especificada por tu aplicación y pasa tus comandos a la instalación correcta de Python.

Entender PATH

Cuando ejecutas un comando como python o pip, tu sistema operativo busca en una lista de directorios para encontrar un archivo ejecutable con ese nombre. Esta lista de directorios reside en una variable de entorno llamada PATH, con cada directorio en la lista separado por dos puntos:

/usr/local/bin:/usr/bin:/bin

Los directorios en PATH se buscan de izquierda a derecha, por lo que un ejecutable coincidente en un directorio al principio de la lista tiene precedencia sobre otro al final. En este ejemplo, el directorio /usr/local/bin se buscará primero, luego /usr/bin

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

, luego /bin.

Entendiendo los Shims

pyenv funciona insertando un directorio de shims al principio de tu PATH:

$(pyenv root)/shims:/usr/local/bin:/usr/bin:/bin

A través de un proceso llamado rehashing, pyenv mantiene shims en ese directorio para que coincidan con cada comando de Python (python, pip, etc.) en cada versión instalada de Python.

Los shims son ejecutables ligeros que simplemente pasan tu comando a pyenv. Así que, con pyenv instalado, cuando ejecutas, digamos, pip, tu sistema operativo hará lo siguiente:

  • Buscará en tu PATH un archivo ejecutable llamado pip.
  • Encontrará el shim de pyenv llamado pip al principio de tu PATH.
  • Ejecutará el shim llamado pip, que a su vez pasará el comando a pyenv.

Eligiendo la Versión de Python

Cuando ejecutas un shim, pyenv determina qué versión de Python usar leyendo de las siguientes fuentes, en este orden:

1.
La variable de entorno PYENV_VERSION (si está especificada). Puedes usar el comando pyenv shell para establecer esta variable de entorno en tu sesión de shell actual.
2.
El archivo específico de la aplicación .python-version en el directorio actual (si está presente). Puedes modificar el archivo .python-version del directorio actual con el comando pyenv local.
3.
El primer archivo .python-version encontrado (si lo hay) buscando en cada directorio padre, hasta llegar a la raíz de tu sistema de archivos.
4.
El archivo global $(pyenv root)/version. Puedes modificar este archivo usando el comando pyenv global. Si el archivo de versión global no está presente, pyenv asume que quieres usar el Python del "sistema". (En otras palabras, la versión que se ejecutaría si pyenv no estuviera en tu PATH).

NOTA: Puedes activar múltiples versiones al mismo tiempo, incluyendo múltiples versiones de Python2 o Python3 simultáneamente. Esto permite el uso paralelo de Python2 y Python3, y es requerido con herramientas como tox. Por ejemplo, para configurar tu PATH para usar primero tu Python del sistema y Python3 (configurados a 2.7.9 y 3.4.2 en este ejemplo), pero también tener Python 3.3.6, 3.2 y 2.5 disponibles en tu PATH, uno primero haría pyenv install de las versiones faltantes, luego establecería pyenv global system 3.3.6 3.2 2.5. En este punto, uno debería poder encontrar la ruta ejecutable completa a cada una de estas usando pyenv which, por ejemplo, pyenv which python2.5 (debería mostrar $(pyenv root)/versions/2.5/bin/python2.5), o pyenv which python3.4 (debería mostrar la ruta al Python del sistema). También puedes especificar múltiples versiones en un archivo .python-version, separadas por saltos de línea o cualquier espacio en blanco. hy

Localizando la Instalación de Python

Una vez que pyenv ha determinado qué versión de Python ha especificado tu aplicación, pasa el comando a la instalación de Python correspondiente.

Cada versión de Python se instala en su propio directorio bajo

$(pyenv root)/versions.

Por ejemplo, podrías tener estas versiones instaladas:

  • $(pyenv root)/versions/2.7.8/
  • $(pyenv root)/versions/3.4.2/
  • $(pyenv root)/versions/pypy-2.4.0/

En lo que respecta a pyenv, los nombres de versión son simplemente los directorios en $(pyenv root)/versions.

Gestionando Entornos Virtuales

Hay un plugin de pyenv llamado pyenv-virtualenv que viene con varias características para ayudar a los usuarios de pyenv a gestionar entornos virtuales creados por virtualenv o Anaconda. Dado que el script activate de esos entornos virtuales dependen de la mutación de la variable $PATH del shell interactivo del usuario, interceptará los ganchos de ejecución de comandos estilo shim de pyenv. Recomendamos instalar pyenv-virtualenv también si tienes planes de jugar con esos entornos virtuales.

Configuración Avanzada

Omite esta sección a menos que necesites saber qué hace cada línea en tu perfil de shell.

pyenv init es el único comando que se pasa de la raya de cargar comandos adicionales en tu shell. Viniendo de rvm, algunos de ustedes podrían oponerse a esta idea. Esto es lo que pyenv init hace realmente:

1.
Configura tu ruta de shims. Este es el único requisito para que pyenv funcione correctamente. Puedes hacerlo manualmente anteponiendo $(pyenv root)/shims a tu $PATH.
2.
Reconstruye los shims. De vez en cuando necesitarás reconstruir tus archivos de shim. Hacer esto en init asegura que todo esté actualizado. Siempre puedes ejecutar pyenv rehash manualmente. Puedes deshabilitar esta funcionalidad agregando --no-rehash al final de la línea de comandos de pyenv init.
3.
Instala el despachador sh. Esta parte también es opcional, pero permite a pyenv y a sus plugins cambiar variables en tu shell actual, haciendo posibles comandos como pyenv shell. El despachador sh no hace nada loco como sobrescribir cd o hackear tu prompt de shell, pero si por alguna razón necesitas que pyenv sea un script real en lugar de una función de shell, puedes omitirlo de forma segura.

Para ver exactamente lo que sucede internamente por ti mismo, ejecuta "pyenv init -".

Desinstalando versiones de Python

Con el tiempo, acumularás versiones de Python en tu directorio $(pyenv root)/versions.

Para eliminar versiones antiguas de Python, usa el comando pyenv uninstall para automatizar el proceso de eliminación.

Alternativamente, simplemente haz rm -rf del directorio de la versión que deseas eliminar. Puedes encontrar el directorio de una versión particular de Python con el comando pyenv prefix,

por ejemplo, pyenv prefix 2.6.8.

Referencia de Comandos

Los subcomandos más comunes son:

comandos pyenv

Lista todos los comandos pyenv disponibles.

pyenv local

Establece una versión local de Python específica para la aplicación escribiendo el nombre de la versión en un archivo .python-version en el directorio actual. Esta versión anula la versión global, y puede ser anulada por sí misma al establecer la variable de entorno PYENV_VERSION o con el comando pyenv shell.

$ pyenv local 2.7.6

Cuando se ejecuta sin un número de versión, pyenv local informa la versión local configurada actualmente. También puedes deshacer la configuración de la versión local:

$ pyenv local --unset

Versiones anteriores de pyenv almacenaban las especificaciones de versión local en un archivo llamado .pyenv-version. Para compatibilidad con versiones anteriores, pyenv leerá una versión local especificada en un archivo .pyenv-version, pero un archivo .python-version en el mismo directorio tendrá prioridad.

Puedes especificar múltiples versiones como Python local a la vez.

Digamos que tienes dos versiones 2.7.6 y 3.3.3. Si prefieres 2.7.6 sobre 3.3.3,

$ pyenv local 2.7.6 3.3.3
$ pyenv versions
  system
* 2.7.6 (establecido por /Users/yyuu/path/to/project/.python-version)
* 3.3.3 (establecido por /Users/yyuu/path/to/project/.python-version)
$ python --version
Python 2.7.6
$ python2.7 --version
Python 2.7.6
$ python3.3 --version
Python 3.3.3

o, si prefieres 3.3.3 sobre 2.7.6,

$ pyenv local 3.3.3 2.7.6
$ pyenv versions
  system
* 2.7.6 (establecido por /Users/yyuu/path/to/project/.python-version)
* 3.3.3 (establecido por /Users/yyuu/path/to/project/.python-version)
  venv27
$ python --version
Python 3.3.3
$ python2.7 --version
Python 2.7.6
$ python3.3 --version
Python 3.3.3

pyenv global

Establece la versión global de Python a utilizar en todos los shells escribiendo el nombre de la versión en el archivo ~/.pyenv/version. Esta versión puede ser anulada por un archivo .python-version específico de la aplicación, o al establecer la variable de entorno PYENV_VERSION.

$ pyenv global 2.7.6

El nombre especial de versión system le indica a pyenv que use el Python del sistema (detectado buscando en tu $PATH).

Cuando se ejecuta sin un número de versión, pyenv global informa la versión global configurada actualmente.

Puedes especificar múltiples versiones como Python global a la vez.

Digamos que tienes dos versiones 2.7.6 y 3.3.3. Si prefieres 2.7.6 sobre 3.3.3,

$ pyenv global 2.7.6 3.3.3
$ pyenv versions
  system
* 2.7.6 (establecido por /Users/yyuu/.pyenv/version)
* 3.3.3 (establecido por /Users/yyuu/.pyenv/version)
$ python --version
Python 2.7.6
$ python2.7 --version
Python 2.7.6
$ python3.3 --version
Python 3.3.3

o, si prefieres 3.3.3 sobre 2.7.6,

$ pyenv global 3.3.3 2.7.6
$ pyenv versions
  system
* 2.7.6 (establecido por /Users/yyuu/.pyenv/version)
* 3.3.3 (establecido por /Users/yyuu/.pyenv/version)
  venv27
$ python --version
Python 3.3.3
$ python2.7 --version
Python 2.7.6
$ python3.3 --version
Python 3.3.3

pyenv shell

Establece una versión de Python para la sesión de shell actual mediante la configuración de la variable de entorno PYENV_VERSION.

$ pyenv shell 2.7.6

Cuando se ejecuta sin un argumento, pyenv shell muestra la versión de shell configurada actualmente.

Para deshacer la configuración de la versión de shell (lo que hará que pyenv recurra a las configuraciones de versión local o global), ejecuta pyenv shell --unset.

$ pyenv shell --unset

Puedes especificar múltiples versiones a la vez. Las versiones se evaluarán en orden, de izquierda a derecha. La primera versión que se encuentre en tu PATH tendrá prioridad.

Por ejemplo, si tienes instaladas las versiones 2.7.6 y 3.3.3:

$ pyenv shell 3.3.3 2.7.6
$ python --version
Python 3.3.3

Para establecer tu versión de shell a la del sistema:

$ pyenv shell system

Estas configuraciones se pueden anular utilizando el comando pyenv exec.

pyenv versions

Lista todas las versiones de Python instaladas.

Una versión con un asterisco (*) al principio de la línea es la versión actualmente activa.

$ pyenv versions
  system
* 2.7.6 (set by /Users/yyuu/path/to/project/.python-version)
  3.3.3
  venv27

Las versiones de Python instaladas pueden incluir un prefijo de versión para indicar la versión de Python principal y la versión de instalación de Python, o la versión de instalación de la herramienta de compilación de Python si se especifica. Por ejemplo, las versiones de Python de CPython pueden ser enumeradas así:

$ pyenv versions
  system
* 2.7.6/3.3.3 (set by /Users/yyuu/path/to/project/.python-version)
  3.3.3
  venv27

Si hay configuraciones de versión activa para más de una versión de Python, las versiones se enumerarán por orden de prioridad.

La siguiente tabla muestra las diferentes formas en que se pueden listar las versiones de Python, y la versión resultante:

versión versión de shell versión local versión global versión resultante
-- -- 2.7.6 3.3.3 2.7.6
-- 3.3.3 2.7.6 -- 3.3.3
-- -- -- 3.3.3 3.3.3
-- system -- -- system
-- -- -- -- system

En el caso de que haya múltiples versiones de Python configuradas como activas a la vez, y más de una versión de Python configurada como activa de manera distinta (por ejemplo, una versión de Python 2 y una de Python 3), el subcomando pyenv versions listará todas las versiones de Python activas, y marcará con un asterisco la versión que sería ejecutada si se invocara el comando python.

Por ejemplo, si se configura una versión de shell para 3.4.2 y una versión global para 2.7.6, y las versiones instaladas son 2.7.6 y 3.4.2:

$ pyenv shell 3.4.2
$ pyenv global 2.7.6
$ pyenv versions
  system
* 2.7.6 (set by /Users/yyuu/.pyenv/version)
  3.4.2 (set by PYENV_VERSION environment variable)
$ python --version
Python 3.4.2

Si no hay una versión de shell configurada, pero hay una versión local configurada para 2.7.6 y una versión global para 3.4.2:

$ pyenv local 2.7.6
$ pyenv global 3.4.2
$ pyenv versions
  system
* 2.7.6 (set by /Users/yyuu/path/to/project/.python-version)
  3.4.2 (set by /Users/yyuu/.pyenv/version)
$ python --version
Python 2.7.6

pyenv which

Para cada comando en la lista de argumentos, encuentra y muestra la ruta completa al ejecutable que pyenv utilizaría.

$ pyenv which python
/Users/yyuu/.pyenv/versions/2.7.6/bin/python

Si un comando dado no se encuentra en ninguna de las versiones de Python instaladas, se devolverá un error.

Este comando también funciona para buscar ejecutables dentro de entornos virtuales, pero solo si el entorno virtual se ha activado usando pyenv-virtualenv.

$ pyenv shell my-virtualenv
$ pyenv which python
/Users/yyuu/.pyenv/versions/my-virtualenv/bin/python

pyenv rehash

Reconstruye los shims de los ejecutables instalados en cada versión de Python.

Ejecuta este comando después de instalar nuevas versiones de Python o nuevos ejecutables en las versiones existentes de Python.

pyenv install

Instala una versión especificada de Python.

Consulta la salida de pyenv install --list para ver una lista de todas las versiones de Python disponibles para instalar.

$ pyenv install 2.7.6

Si deseas compilar Python con opciones específicas, puedes establecer la variable de entorno CFLAGS.

$ CFLAGS="-I/usr/local/opt/openssl/include" pyenv install 2.7.6

También puedes consultar la documentación de compilación para más información sobre las variables de entorno de compilación.

Nota: Si tu instalación de Python tiene dependencias que no están instaladas, la compilación puede fallar. Por ejemplo, si faltan las dependencias necesarias para compilar Python 2.7.6, obtendrás un error similar a:

ERROR: The Python executable "python" doesn't exist at
"/Users/yyuu/.pyenv/versions/2.7.6/bin/python" or the file is not executable.
This can happen if you are trying to run a newly installed Python version
before the installation has finished.

En este caso, verifica que todas las dependencias necesarias estén instaladas en tu sistema antes de intentar instalar Python.

pyenv uninstall

Desinstala una versión especificada de Python.

$ pyenv uninstall 2.7.6

Si la versión de Python especificada tiene el estado de instalación de `pending`, entonces el comando pyenv uninstall borrará el código fuente de esa versión de Python.

Si la versión de Python especificada tiene el estado de instalación de `installed`, entonces el comando pyenv uninstall borrará tanto el código fuente como los binarios de esa versión de Python.

Si se especifica una versión de Python con el estado de instalación de `pending`, pero el código fuente de esa versión de Python se ha borrado, entonces el comando pyenv uninstall no hará nada. Esto se debe a que no se puede desinstalar una versión de Python que no esté instalada. Si la versión de Python ya se ha instalado, el comando pyenv uninstall eliminará solo el código fuente y dejará los binarios de esa versión.

pyenv version

Muestra la versión de Python actualmente activa.

Si hay múltiples versiones de Python activas, este comando mostrará la versión que sería utilizada si se invocara el comando python.

$ pyenv version
2.7.6 (set by /Users/yyuu/path/to/project/.python-version)

Si la versión de Python actual es la versión del sistema, este comando mostrará:

$ pyenv version
system

Este comando también mostrará la fuente de la versión activa, ya sea la variable de entorno PYENV_VERSION, el archivo .python-version en el directorio actual o en un directorio padre, o el archivo global ~/.pyenv/version.

pyenv versions --global --local --shell

Muestra todas las versiones de Python actualmente configuradas para el entorno global, local o de shell.

Si no se proporciona ninguna opción, se mostrarán todas las versiones de Python instaladas.

$ pyenv versions --global
2.7.6
3.3.3
$ pyenv versions --local
2.7.6
$ pyenv versions --shell
3.3.3

pyenv prefix

Para cada comando en la lista de argumentos, encuentra y muestra la ruta de instalación del prefijo de la versión de Python especificada.

$ pyenv prefix 2.7.6
/Users/yyuu/.pyenv/versions/2.7.6

Si se especifica una versión de Python que no está instalada, se devolverá un error.

pyenv completions

Imprime la información de autocompletado de shell para pyenv.

Consulta la documentación de tu shell para obtener información sobre cómo habilitar el autocompletado.

pyenv help

Muestra ayuda sobre los comandos de pyenv.

pyenv shell

Establece una versión de Python específica del shell configurando la variable de entorno PYENV_VERSION en tu shell. Esta versión anula las versiones específicas de la aplicación y la versión global.

$ pyenv shell pypy-2.2.1

Cuando se ejecuta sin un número de versión, pyenv shell informa el valor actual de PYENV_VERSION. También puedes anular la versión del shell:

$ pyenv shell --unset

Ten en cuenta que necesitarás tener la integración de shell de pyenv habilitada (paso 3 de las instrucciones de instalación) para poder usar este comando. Si prefieres no usar la integración de shell, puedes simplemente establecer tú mismo la variable PYENV_VERSION:

$ export PYENV_VERSION=pypy-2.2.1

Puedes especificar varias versiones a través de PYENV_VERSION a la vez.

$ pyenv shell 2.7.6 3.3.3
$ pyenv versions

* 3.3.3 (establecido por la variable de entorno PYENV_VERSION)
$ python --version
Python 2.7.6
$ python2.7 --version
Python 2.7.6
$ python3.3 --version
Python 3.3.3

o, si prefieres 3.3.3 sobre 2.7.6,

$ pyenv shell 3.3.3 2.7.6
$ pyenv versions
  system
* 2.7.6 (establecido por la variable de entorno PYENV_VERSION)
* 3.3.3 (establecido por la variable de entorno PYENV_VERSION)
  venv27
$ python --version
Python 3.3.3
$ python2.7 --version
Python 2.7.6
$ python3.3 --version
Python 3.3.3

pyenv install

Instala una versión de Python

Uso: pyenv install [-f] [-kvp] <version>
       pyenv install [-f] [-kvp] <archivo-definicion>
       pyenv install -l|--list
  -l, --list             Lista todas las versiones disponibles
  -f, --force            Instala incluso si la versión parece estar ya
  					instalada
  -s, --skip-existing    Omite la instalación si la versión parece estar ya
  					instalada
  Opciones de python-build:
  -k, --keep        Mantén el árbol de fuentes en $PYENV_BUILD_ROOT después de
                    la instalación (por defecto es $PYENV_ROOT/sources)
  -v, --verbose     Modo verboso: imprime el estado de compilación en la salida
                    estándar
  -p, --patch       Aplica un parche desde la entrada estándar antes de compilar
  -g, --debug       Compila una versión de depuración

Para listar todas las versiones disponibles de Python, incluyendo Anaconda, Jython, pypy y stackless, usa:

$ pyenv install --list

Luego instala las versiones deseadas:

$ pyenv install 2.7.6
$ pyenv install 2.6.8
$ pyenv versions

pyenv uninstall

Desinstala versiones de Python.

Uso: pyenv uninstall [-f|--force] <version> ...
   -f  Intenta eliminar la versión especificada sin preguntar
       por confirmación. Si la versión no existe, no
       muestres un mensaje de error.

pyenv rehash

Instala "shims" para todos los binarios de Python conocidos por pyenv (es decir, ~/.pyenv/versions/*/bin/*). Ejecuta este comando después de instalar una nueva versión de Python o un paquete que proporcione binarios.

$ pyenv rehash

pyenv version

Muestra la versión de Python activa actualmente, junto con información sobre cómo se estableció.

$ pyenv version
2.7.6 (establecido por /home/yyuu/.pyenv/version)

pyenv versions

Lista todas las versiones de Python conocidas por pyenv y muestra un asterisco junto a la versión activa actualmente.

$ pyenv versions

  2.6.8

pyenv which

Muestra la ruta completa al ejecutable que pyenv invocará cuando ejecutes el comando dado.

$ pyenv which python3.3
/home/yyuu/.pyenv/versions/3.3.3/bin/python3.3

pyenv whence

Lista todas las versiones de Python que tienen instalado el comando dado.

$ pyenv whence 2to3
2.6.8
2.7.6
3.3.3

Variables de entorno

Puedes afectar cómo opera pyenv con las siguientes configuraciones:

nombre (por defecto)
descripción
PYENV_VERSION
Especifica la versión de Python a utilizar. Ver también pyenv shell
PYENV_ROOT (~/.pyenv)
Define el directorio bajo el cual residen las versiones de Python y los "shims". Ver también pyenv root
PYENV_DEBUG
Muestra información de depuración.
También como: pyenv --debug <subcomando>
PYENV_HOOK_PATH
Lista separada por dos puntos de las rutas donde se buscan los ganchos de pyenv.
PYENV_DIR ($PWD)
Directorio desde donde empezar a buscar archivos .python-version.
HTTP_PROXY,HTTPS_PROXY
Variables de proxy
CONFIGURE_OPTS
Pasa opciones de configuración a la compilación.
PYTHON_BUILD_ARIA2_OPTS
Se utiliza para pasar parámetros adicionales a aria2 https://aria2.github.io/ Si el binario aria2c está disponible en PATH, pyenv usa aria2c en lugar de curl o wget para descargar el código fuente de Python. Si tienes una conexión a internet inestable, puedes usar esta variable para instruir a aria2 para que acelere la descarga. En la mayoría de los casos, solo necesitarás usar -x 10 -k 1M como valor para la variable de entorno PYTHON_BUILD_ARIA2_OPTS
