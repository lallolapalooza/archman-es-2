NOMBRE

tasklib - Documentación de tasklib

Soporta Python 3.5 y superior, con taskwarrior 2.4.x y superior. Las versiones anteriores de taskwarrior no han sido probadas y pueden no funcionar.

REQUISITOS

•
taskwarrior v2.4.x o superior, aunque se recomienda la versión menor más reciente.

INSTALACIÓN

Instalar vía pip (recomendado):

pip install tasklib

O clonar desde github:

git clone https://github.com/robgolding/tasklib.git
cd tasklib
python setup.py install

INICIALIZACIÓN

Opcionalmente, inicializa la instancia de TaskWarrior con data_location (el directorio de la base de datos). Si aún no existe, se creará automáticamente a menos que se especifique create=False.

La ubicación por defecto es la misma que la de taskwarrior:

>>> tw = TaskWarrior(data_location='~/.task', create=True)

La instancia TaskWarrior también utilizará tu configuración .taskrc (para que reconozca los mismos UDA que tu binario de task, utilice la misma configuración, etc.). Para anular la ubicación de .taskrc, usa taskrc_location=~/some/different/path.

CREACIÓN DE TAREAS

Para crear una tarea, simplemente crea un nuevo objeto Task:

>>> new_task = Task(tw, description="tirar la basura")

Esta tarea aún no está guardada en TaskWarrior (igual que en Django), hasta que llames al método .save():

>>> new_task.save()

Puedes establecer cualquier atributo como argumento de palabra clave al objeto Task:

>>> complex_task = Task(tw, description="finalmente arreglar la ducha", due=datetime(2015,2,14,8,0,0), priority='H')

o estableciendo los atributos uno por uno:

>>> complex_task = Task(tw)
>>> complex_task['description'] = "finalmente arreglar la ducha"
>>> complex_task['due'] = datetime(2015,2,14,8,0,0)
>>> complex_task['priority'] = 'H'

MODIFICACIÓN DE TAREAS

Para modificar un objeto Task creado o recuperado, usa acceso similar a un diccionario:

>>> homework = tw.tasks.get(tags__contain='chores')
>>> homework['project'] = 'Home'

El cambio no se propagará a TaskWarrior hasta que ejecutes el método save():

>>> homework.save()

Los atributos, que se mapean a objetos nativos de Python, se convierten. Ver la sección Atributos de Tarea.

ATRIBUTOS DE TAREA

Los atributos de los objetos de tarea son accesibles a través de índices, así:

>>> task = tw.tasks.pending().get(tags__contain='work')  # Solo hay una tarea pendiente con la etiqueta 'work'
>>> task['description']
'Upgrade Ubuntu Server'
>>> task['id']
15
>>> task['due']
datetime.datetime(2015, 2, 5, 0, 0, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> task['tags']
['work', 'servers']

Los siguientes campos se deserializan en objetos Python:

  • due, wait, scheduled, until, entry: deserializados a un objeto datetime
  • annotations: deserializados a una lista de objetos TaskAnnotation
  • tags: deserializados a una lista de cadenas
  • depends: deserializados a un conjunto de objetos Task

Los atributos deben establecerse utilizando la representación correcta de Python, que se serializará al formato correcto cuando se guarde la tarea.

PROPIEDADES DE TAREA

Tasklib define varias propiedades en el objeto Task, para mayor comodidad:

>>> t.save()
>>> t.saved
True
>>> t.pending
True
>>> t.active
False
>>> t.start()
>>> t.active
True
>>> t.done()
>>> t.completed
True
>>> t.pending
False
>>> t.delete()
>>> t.deleted
True

OPERACIONES SOBRE TAREAS

Después de modificar uno o más atributos, simplemente llama a save() para escribir esos cambios en la base de datos:

>>> task = tw.tasks.pending().get(tags__contain='work')
>>> task['due'] = datetime(year=2014, month=1, day=5)
>>> task.save()

Para marcar una tarea como completada, usa done():

>>> task = tw.tasks.pending().get(tags__contain='work')
>>> task.done()
>>> len(tw.tasks.pending().filter(tags__contain='work'))
0

Para eliminar una tarea, usa delete():

>>> task = tw.tasks.get(description="tarea añadida por error")
>>> task.delete()

Para actualizar un objeto de tarea con valores de la base de datos de TaskWarrior, usa refresh(). Ejemplo:

>>> task = Task(tw, description="aprender a cocinar")
>>> task.save()
>>> task['id']
5
>>> task['tags']
[]

Ahora, supongamos que modificamos la tarea usando la interfaz de TaskWarrior en otro terminal:

$ task 5 modify +someday
Task 5 modified.

Volviendo al proceso de python abierto:

>>> task['tags']
[]
>>> task.refresh()
>>> task['tags']
['someday']

Las tareas también pueden iniciarse y detenerse. Usa start() y stop() respectivamente:

>>> task.start()
>>> task['start']
datetime.datetime(2015, 7, 16, 18, 48, 28, tzinfo=<DstTzInfo 'Europe/Prague' CEST+2:00:00 DST>)
>>> task.stop()
>>> task['start']
>>> task.done()
>>> task['end']
datetime.datetime(2015, 7, 16, 18, 49, 2, tzinfo=<DstTzInfo 'Europe/Prague' CEST+2:00:00 DST>)

RECUPERACIÓN DE TAREAS

tw.tasks es un objeto TaskQuerySet que emula la API de QuerySet de Django. Para obtener todas las tareas (incluyendo las completadas):

>>> tw.tasks.all()
['First task', 'Completed task', 'Deleted task', ...]

FILTRADO

Filtra tareas usando la misma sintaxis familiar:

>>> tw.tasks.filter(status='pending', tags__contains=['work'])
['Upgrade Ubuntu Server']

Los argumentos de filtro se pasan al comando task (__ se reemplaza por un punto), por lo que el ejemplo anterior es equivalente al siguiente comando:

$ task status:pending tags.contain=work

Las tareas también se pueden filtrar usando comandos crudos, así:

>>> tw.tasks.filter('status:pending +work')
['Upgrade Ubuntu Server']

Alt

esta práctica se desaconseja, ya que al usar comandos sin procesar puede perder algo de la portabilidad de sus comandos en diferentes versiones de TaskWarrior.

Sin embargo, puede mezclar comandos sin procesar con filtros de palabras clave, como en el ejemplo dado:

>>> tw.tasks.filter('+BLOCKING', project='Home')  # Obtiene todas las tareas BLOQUEADAS en el proyecto Home
['Fix the toilette']

Esta puede ser una forma ingeniosa de utilizar sintaxis que tasklib aún no admite. El ejemplo anterior es excelente, ya que las etiquetas virtuales no funcionan igual que las ordinarias, es decir:

>>> tw.tasks.filter(tags=['BLOCKING'])
>>> []

no funcionará.

Existen funciones incorporadas para recuperar tareas pendientes y completadas:

>>> tw.tasks.pending().filter(tags__contain='work')
['Upgrade Ubuntu Server']
>>> len(tw.tasks.completed())
227

Utilice get() para devolver la única tarea en un TaskQuerySet, o lanzar una excepción:

>>> tw.tasks.get(tags__contain='work')['status']
'pending'
>>> tw.tasks.get(status='completed', tags__contains='work')  # El estado de la única tarea con la etiqueta work es pendiente, por lo que esto debería fallar
Traceback (most recent call last):
  File ""<stdin>"", line 1, in <module>
  File "tasklib/task.py", line 224, in get
    'Lookup parameters were {0}'.format(kwargs))
tasklib.task.DoesNotExist: Task matching query does not exist. Lookup parameters were {'status': 'completed', 'tags__contains': ['work']}
>>> tw.tasks.get(status='pending')
Traceback (most recent call last):
  File ""<stdin>"", line 1, in <module>
  File "tasklib/task.py", line 227, in get
    'Lookup parameters were {1}'.format(num, kwargs))
ValueError: get() returned more than one Task -- it returned 23! Lookup parameters were {'status': 'pending'}

Además, dado que los filtros devuelven TaskQuerySets, puede apilar filtros uno encima de otro:

>>> home_tasks = tw.tasks.filter(project='Wife')
>>> home_tasks.filter(due__before=datetime(2015,2,14,14,14,14))  # Lo que tengo que hacer antes del día de San Valentín
['Prepare surprise birthday party']

IGUALDAD DE OBJETOS TASK

Dos Tareas se consideran iguales si tienen el mismo UUID:

>>> task1 = Task(tw, description="Pet the dog")
>>> task1.save()
>>> task2 = tw.tasks.get(description="Pet the dog")
>>> task1 == task2
True

Si compara las dos tareas sin guardar, se consideran iguales solo si es el mismo objeto Python:

>>> task1 = Task(tw, description="Pet the cat")
>>> task2 = Task(tw, description="Pet the cat")
>>> task1 == task2
False
>>> task3 = task1
>>> task3 == task1
True

ACCESO A LOS VALORES ORIGINALES

Para acceder al estado guardado de la Tarea, utilice acceso similar a un diccionario a través del atributo original:

>>> t = Task(tw, description="tidy up")
>>> t.save()
>>> t['description'] = "tidy up the kitchen and bathroom"
>>> t['description']
"tidy up the kitchen and bathroom"
>>> t.original['description']
"tidy up"

Cuando guarde la tarea, los valores originales se actualizarán para reflejar el estado guardado de la tarea:

>>> t.save()
>>> t.original['description']
"tidy up the kitchen and bathroom"

MANEJO DE FECHAS Y HORAS

Cualquier atributo similar a una marca de tiempo de las tareas se convierte en objetos datetime con información de zona horaria. Para lograr esto, Tasklib utiliza el módulo Python zoneinfo, que trae la base de datos de zonas horarias de Olsen a Python.

Esto le protege de detalles molestos como los cambios de horario de verano o la conversión entre diferentes zonas horarias. Por ejemplo, para listar todas las tareas que vencen a medianoche si se encuentra actualmente en Berlín:

>>> myzone = zoneinfo.ZoneInfo('Europe/Berlin')
>>> midnight = datetime(2015,2,2,0,0,0,tzinfo=myzone)
>>> tw.tasks.filter(due__before=midnight)

Sin embargo, esto sigue siendo un poco tedioso. Por eso, el objeto TaskWarrior es capaz de detectar automáticamente la zona horaria, utilizando el módulo Python tzlocal. Si la zona horaria de su sistema está configurada como 'Europe/Berlin', el siguiente ejemplo funcionará de la misma manera que el anterior:

>>> tw.tasks.filter(due__before=datetime(2015,2,2,0,0,0))

También puede usar fechas simples al filtrar:

>>> tw.tasks.filter(due__before=date(2015,2,2))

En tal caso, se utiliza las 00:00:00 como componente de hora.

Por supuesto, puede usar objetos datetime ingenuos (sin zona horaria) al inicializar un objeto Task o al asignar valores a atributos datetime:

>>> t = Task(tw, description="Buy new shoes", due=date(2015,2,5))
>>> t['due']
datetime.datetime(2015, 2, 5, 0, 0, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> t['due'] = date(2015,2,6,15,15,15)
>>> t['due']
datetime.datetime(2015, 2, 6, 15, 15, 15, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)

Sin embargo, dado que los datetimes con y sin información de zona horaria no son comparables en Python, esto puede causar algunos comportamientos inesperados:

>>> from datetime import datetime
>>> now = datetime.now()
>>> t = Task(tw, description="take out the trash now")
>>> t['due'] = now
>>> now
datetime.datetime(2015, 2, 1, 19, 44, 4, 770001)
>>> t['due']
datetime.datetime(2015, 2, 1, 19, 44, 4, 770001, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> t['due'] == now
Traceback (most recent call last):
  File ""<stdin>"", line 1, in <module>
TypeError: can't compare offset-naive and offset-aware datetimes

Si desea comparar un valor datetime con información de zona horaria con un valor datetime ingenuo, primero debe localizar el valor ingenuo:

>>> from datetime import datetime
>>> now = datetime.now().astimezone()
>>> t['due'] = now
>>> now
datetime.datetime(2015, 2, 1, 19, 44, 4, 770001, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> t['due'] == now
True

Además, tenga en cuenta que no importa si los objetos datetime con información de zona horaria están configurados en la misma zona horaria:

>>> import zoneinfo
>>> t['due']
datetime.datetime(2015, 2, 1, 19, 44, 4, 770001, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> now.astimezone(zoneinfo.ZoneInfo('UTC'))
datetime.datetime(2015, 2, 1, 18, 44, 4, 770001, tzinfo=<UTC>)
>>> t['due'] == now.astimezone(zoneinfo.ZoneInfo('UTC'))
True

Nota: El siguiente comportamiento solo está disponible para TaskWarrior >= 2.4.0.

Existe un tercer enfoque para configurar valores de fecha y hora, que aprovecha el comando 'task calc'. Simplemente puede asignar cualquier atributo datetime a cualquier cadena que contenga una expresión de tiempo con formato de TaskWarrior aceptable:

$ task calc now + 1d
2015-07-17T21:17:54

Esta sintaxis se puede utilizar en el intérprete de Python de la siguiente manera:

>>> t['due'] = "now + 1d"
>>> t['due']
datetime.datetime(2015, 7, 17, 21, 19, 31, tzinfo=<DstTzInfo 'Europe/Berlin' CEST+2:00:00 DST>)

Se puede ver fácilmente que la cadena con la expresión de tiempo formateada por TaskWarrior se convierte automáticamente en un datetime nativo en la zona horaria local.

Para obtener la lista de formatos y palabras clave aceptables, consulte:

  • http://taskwarrior.org/docs/dates.html
  • http://taskwarrior.org/docs/named_dates.html

Sin embargo, dado que cada asignación de este tipo implica una llamada a 'task calc' para la conversión, podría causar algunos problemas de rendimiento al asignar cadenas a atributos datetime repetidamente, de manera automatizada.

TRABAJO CON ANOTACIONES

Las anotaciones de las tareas se representan en tasklib mediante objetos TaskAnnotation. Estos son muy parecidos a los objetos Task, aunque muy simplificados.

>>> annotated_task = tw.tasks.get(description='Annotated task')
>>> annotated_task['annotations']
[Yeah, I am annotated!]

Las anotaciones solo tienen definidos los valores entry (entrada) y description (descripción):

>>> annotation = annotated_task['annotations'][0]
>>> annotation['entry']
datetime.datetime(2015, 1, 3, 21, 13, 55, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> annotation['description']
u'Yeah, I am annotated!'

Para añadir una anotación a una Tarea, utilice add_annotation():

>>> task = Task(tw, description="new task")
>>> task.add_annotation("we can annotate any task")
Traceback (most recent call last):
  File ""<stdin>"", line 1, in <module>
    File "build/bdist.linux-x86_64/egg/tasklib/task.py", line 355, in add_annotation
tasklib.task.NotSaved: Task needs to be saved to add annotation

Sin embargo, la Tarea debe guardarse antes de poder añadirle una anotación:

>>> task.save()
>>> task.add_annotation("we can annotate saved tasks")
>>> task['annotations']
[we can annotate saved tasks]

Para eliminar la anotación, pase su descripción al método remove_annotation():

>>> task.remove_annotation("we can annotate saved tasks")

Alternativamente, puede pasar el objeto TaskAnnotation en sí:

>>> task.remove_annotation(task['annotations'][0])

RUNNING CUSTOM COMMANDS

Para ejecutar comandos personalizados, usa el método execute_command() del objeto TaskWarrior:

>>> tw = TaskWarrior()
>>> tw.execute_command(['log', 'Finish high school.'])
[u'Logged task.']

Puedes usar el argumento de palabra clave config_override para especificar un diccionario de anulaciones de configuración:

>>> tw.execute_command(['3', 'done'], config_override={'gc': 'off'}) # Will mark 3 as completed and it will retain its ID

Adicionalmente, puedes usar el flag return_all=True, que devuelve un triplete (stdout, sterr, return_code), y allow_failure=False, que evitará que tasklib lance una excepción si el binario de task devolvió un código de retorno distinto de cero:

>>> tw.execute_command(['invalidcommand'], allow_failure=False, return_all=True)
([u''],
 [u'Using alternate .taskrc file /home/tbabej/.taskrc',
  u"[task next rc:/home/tbabej/.taskrc rc.recurrence.confirmation=no rc.json.array=off rc.confirmation=no rc.bulk=0 rc.dependency.confirmation=no description ~ 'invalidcommand']",
  u'Configuration override rc.recurrence.confirmation:no',
  u'Configuration override rc.json.array:off',
  u'Configuration override rc.confirmation:no',
  u'Configuration override rc.bulk:0',
  u'Configuration override rc.dependency.confirmation:no',
  u'No matches.',
  u'There are local changes.  Sync required.'],
 1)

SETTING CUSTOM CONFIGURATION VALUES

Por defecto, TaskWarrior usa los valores de configuración almacenados en tu .taskrc. Para ver qué anulaciones de valor de configuración se pasan a cada comando de task ejecutado, echa un vistazo al atributo overrides del objeto TaskWarrior:

>>> tw.overrides
{'confirmation': 'no', 'data.location': '/home/tbabej/.task'}

Para pasar tus propias anulaciones de configuración, solo necesitas actualizar este diccionario:

>>> tw.overrides.update({'hooks': 'off'})  # tasklib no activará los hooks

CREATING HOOK SCRIPTS

Desde la versión 2.4.0, TaskWarrior tiene soporte para scripts de hook. Tasklib proporciona algunas utilidades muy útiles para escribirlos. Con tasklib, escribir estos se convierte en pan comido:

#!/usr/bin/python
from tasklib.task import Task
task = Task.from_input()
# ... <custom logic>
print task.export_data()

Por ejemplo, un plugin que asignara la prioridad "H" a cualquier tarea que contenga tres signos de exclamación en la descripción, iría así:

#!/usr/bin/python
from tasklib.task import Task
task = Task.from_input()
if "!!!" in task['description']:
    task['priority'] = "H"
print task.export_data()

Tasklib puede detectar automáticamente si se está ejecutando en el evento on-modify, que proporciona más entrada que el evento on-add, y lee los datos en consecuencia.

¡Esto significa que el ejemplo anterior funciona tanto para los eventos on-add como para on-modify!

En consecuencia, puedes crear un solo archivo de hook para los eventos on-add y on-modify, y solo necesitas crear un enlace simbólico para el otro. Esto elimina la necesidad de mantener dos copias del mismo código base y/o código repetitivo.

En los eventos on-modify, tasklib carga tanto la versión original como la versión modificada de la tarea en el objeto Task devuelto. Para acceder a los datos originales (de solo lectura), usa el atributo tipo diccionario original:

>>> t = Task.from_input()
>>> t['description']
"Modified description"
>>> t.original['description']
"Original description"

WORKING WITH UDAS

Dado que TaskWarrior lee tu .taskrc, no necesitas definir ningún UDA en el diccionario de configuración de TaskWarrior, como se describió anteriormente. Supongamos que tenemos un UDA de estimación en el .taskrc:

uda.estimate.type = numeric

Podemos simplemente filtrar y crear tareas usando el UDA de estimación directamente:

>>> tw = TaskWarrior()
>>> task = Task(tw, description="Long task", estimate=1000)
>>> task.save()
>>> task['id']
1

Esto se guarda como un UDA en TaskWarrior:

$ task 1 export
{"id":1,"description":"Long task","estimate":1000, ...}

También podemos especificar UDAs como argumentos en TaskFilter:

>>> tw.tasks.filter(estimate=1000)
Long task

SYNCING

Si has configurado las variables de configuración necesarias en tu .taskrc, la sincronización es tan fácil como:

>>> tw = TaskWarrior()
>>> tw.execute_command(['sync'])

Si deseas usar un servidor/credenciales no estándar, necesitarás proporcionar anulaciones de configuración a la instancia TaskWarrior. Actualiza el diccionario config con los valores que deseas anular, y luego podemos ejecutar el comando de sincronización usando el método execute_command():

>>> tw = TaskWarrior()
>>> sync_config = {
...     'taskd.certificate': '/home/tbabej/.task/tbabej.cert.pem',
...     'taskd.credentials': 'Public/tbabej/34af54de-3cb2-4d3d-82be-33ddb8fd3e66',
...     'taskd.server': 'task.server.com:53589',
...     'taskd.ca': '/home/tbabej/.task/ca.cert.pem',
...     'taskd.trust': 'ignore hostname'}
>>> tw.config.update(sync_config)
>>> tw.execute_command(['sync'])
