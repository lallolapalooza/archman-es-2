LA CLASE PERIPHERAL

La clase Peripheral de Bluepy encapsula una conexión a un periférico Bluetooth LE. Creas un objeto Peripheral directamente especificando su dirección MAC; cuando se establece la conexión, los servicios y características que ofrece ese dispositivo pueden ser descubiertos y leídos o escritos.

Constructor

Peripheral([deviceAddr=None[, addrType=ADDR_TYPE_PUBLIC[, iface=None]]])
Si deviceAddr no es None, crea un objeto Peripheral y establece una conexión con el dispositivo indicado por deviceAddr. deviceAddr debe ser una cadena que contenga seis bytes hexadecimales separados por dos puntos, por ejemplo: "11:22:33:ab:cd:ed".

Si deviceAddr es None, crea un objeto Peripheral no conectado. Debes llamar al método connect() sobre este objeto (pasándole una dirección de dispositivo) antes de que sea utilizable.

El parámetro addrType puede usarse para seleccionar entre tipos de dirección fijos (btle.ADDR_TYPE_PUBLIC) y aleatorios (btle.ADDR_TYPE_RANDOM), dependiendo de lo que requiera el periférico objetivo. Consulte la sección 10.8 de la especificación Bluetooth 4.0 para más detalles.

El parámetro iface permite establecer la interfaz Bluetooth sobre la cual se realizará la conexión. En Linux, 0 significa /dev/hci0, 1 significa /dev/hci1 y así sucesivamente.

deviceAddr también puede ser un objeto ScanEntry. En este caso, la dirección del dispositivo, el tipo de dirección y el número de interfaz se toman de los valores de ScanEntry, y los parámetros addrType e iface se ignoran.

El constructor lanzará una BTLEException si falla la conexión con el dispositivo.

Métodos de instancia

connect(addr[, addrType=ADDR_TYPE_PUBLIC[, iface=None]])
Establece una conexión con el dispositivo indicado por addr, con el tipo de dirección addrType y el número de interfaz iface (ver el constructor Peripheral para detalles). Solo debes llamar a este método si el Peripheral no está conectado (es decir, si no pasaste un addr al constructor); un objeto periférico dado no puede ser reconectado una vez conectado.
disconnect()
Cierra la conexión con el dispositivo y libera los recursos del sistema operativo asociados. Aunque el destructor de Python para un Peripheral intentará llamar a este método, no debes confiar en que esto ocurra en ningún momento determinado. Por lo tanto, llama siempre explícitamente a disconnect() si has terminado de comunicarte con un dispositivo.
getState()
Devuelve una cadena que indica el estado del dispositivo. Los estados posibles son: "conn" - conectado, "disc" - desconectado, "scan" - escaneando y "tryconn" - conectando.
getServices()
Devuelve una lista de objetos Service que representan los servicios ofrecidos por el periférico. Esto realizará el descubrimiento de servicios Bluetooth si aún no se ha hecho; de lo contrario, devolverá una lista en caché de servicios inmediatamente.

En Python 3.x, esto devuelve un objeto de vista de diccionario, no una lista.

getServiceByUUID(uuidVal)
Devuelve una instancia de un objeto Service que tiene el UUID indicado. uuidVal puede ser un objeto UUID, o cualquier cadena o entero que pueda usarse para construir un objeto UUID. El método devolverá inmediatamente si el servicio fue descubierto previamente (por ejemplo, mediante getServices()), y consultará al periférico de lo contrario. Lanza una BTLEEException si no se encuentra el servicio.
getCharacteristics(startHnd=1, endHnd=0xFFFF, uuid=None)
Devuelve una lista que contiene objetos Characteristic para el periférico. Si no se proporcionan argumentos, devolverá todas las características. Si se proporcionan startHnd y/o endHnd, la lista se restringe a las características cuyos manejadores estén dentro del rango dado; ten en cuenta que generalmente es más conveniente usar Service.getCharacteristics() para obtener las características asociadas a un servicio particular. Alternativamente, se puede especificar uuid para localizar una característica con un valor UUID particular. uuid puede ser cualquier cadena, entero o tipo UUID que pueda usarse para construir un objeto UUID.

Si no se encuentran características coincidentes, devuelve una lista vacía.

getDescriptors(startHnd=1, endHnd=0xFFFF)
Devuelve una lista que contiene objetos Descriptor para el periférico. Si no se proporcionan argumentos, devolverá todos los descriptores. Si se proporcionan startHnd y/o endHnd, la lista se restringe a los descriptores cuyos manejadores estén dentro del rango dado. De nuevo, generalmente es más conveniente usar Service.getDescriptors() para obtener los descriptores asociados a un servicio particular.

Si no se encuentran descriptores coincidentes, devuelve una lista vacía.

withDelegate(delegate)
Esto almacena una referencia a un objeto "delegado", que se llama cuando ocurren eventos asíncronos como notificaciones Bluetooth. Debe ser una subclase de la clase DefaultDelegate. Consulte Trabajo con notificaciones para más información. Este método devuelve el objeto Peripheral.
setDelegate(delegate)
(obsoleto desde 0.9.10) Igual que withDelegate().
waitForNotifications(timeout)
Bloquea hasta que se reciba una notificación del periférico, o hasta que haya transcurrido el timeout dado (en segundos). Si se recibe una notificación, se llamará al método handleNotification() del objeto delegado, y waitForNotifications() devolverá True.

Si no se recibe nada antes de que transcurra el tiempo de espera, esto devolverá False.

writeCharacteristic(handle, val, withResponse=False)
Escribe los datos val (de tipo str en Python 2.x, byte en 3.x) en la característica identificada por el manejador handle, que debe ser un entero en el rango de 1 a 65535. Esto es útil si conoces el manejador de una característica, pero no tienes un objeto Characteristic.

Si withResponse es verdadero, esperará confirmación de que la escritura fue exitosa por parte del dispositivo.

readCharacteristic(handle)
Lee el valor actual de la característica identificada por handle. Esto es útil si conoces el manejador de la característica.
but do not have a suitable Characteristic object.

Propiedades

Todas las propiedades listadas a continuación son de solo lectura.

addr
Dirección MAC del dispositivo (como una cadena hexadecimal separada por dos puntos).
addrType
Tipo de dirección del dispositivo - uno de ADDR_TYPE_PUBLIC o ADDR_TYPE_RANDOM; esto será una cadena imprimible.

Número de interfaz Bluetooth (0 = /dev/hci0) utilizada para la conexión.

LA CLASE SCANNER

Un objeto Scanner se utiliza para escanear dispositivos LE que están transmitiendo datos publicitarios. En la mayoría de las situaciones, esto dará un conjunto de dispositivos disponibles para la conexión. (Tenga en cuenta, sin embargo, que los dispositivos Bluetooth LE pueden aceptar conexiones sin transmitir datos publicitarios, o pueden transmitir datos publicitarios pero no aceptar conexiones).

Constructor

Scanner([index=0])
Crea e inicializa un nuevo objeto escáner. index identifica la interfaz Bluetooth a utilizar (donde 0 es /dev/hci0, etc.). El escaneo no comienza hasta que se llaman los métodos start() o scan() - ver abajo para más detalles.

Métodos de instancia

withDelegate(delegate)
Almacena una referencia a un objeto delegate, que recibe llamadas de retorno cuando se reciben transmisiones de dispositivos. Vea la documentación de DefaultDelegate para más detalles.
scan([timeout = 10])
Escanea dispositivos durante el timeout dado en segundos. Durante este período, se realizarán llamadas de retorno al objeto delegate. Cuando el tiempo de espera finaliza, el escaneo se detendrá y el método devolverá una lista (o una vista en Python 3.x) de objetos ScanEntry para todos los dispositivos descubiertos durante ese tiempo.

scan() es equivalente a llamar a los métodos clear(), start(), process() y stop() en orden.

clear()
Borra el conjunto actual de dispositivos descubiertos.
start()
Habilita la recepción de transmisiones publicitarias de periféricos. Debe llamarse antes de llamar a process().
process([timeout = 10])
Espera transmisiones publicitarias y llama al objeto delegate cuando se reciben. Regresa después del período de timeout dado en segundos. Esto puede llamarse múltiples veces (entre llamadas a start() y stop()).
stop()
Deshabilita la recepción de transmisiones publicitarias. Debe llamarse después de que process() haya regresado.
getDevices()
Devuelve una lista (una vista en Python 3.x) de objetos ScanEntry para todos los dispositivos que han sido descubiertos (desde la última llamada a clear()).

Código de ejemplo

El código básico para ejecutar un escaneo de dispositivos LE durante 10 segundos sigue este ejemplo:

# importar las partes necesarias de la biblioteca bluepy
from bluepy.btle import Scanner, DefaultDelegate
# crear una clase delegada para recibir los paquetes de transmisión BLE
class ScanDelegate(DefaultDelegate):
    def __init__(self):
        DefaultDelegate.__init__(self)
    # cuando este script de python descubre un paquete de transmisión BLE, imprime un mensaje con la dirección MAC del dispositivo
    def handleDiscovery(self, dev, isNewDev, isNewData):
        if isNewDev:
            print "Discovered device", dev.addr
        elif isNewData:
            print "Received new data from", dev.addr
# crear un objeto escáner que envía paquetes de transmisión BLE al ScanDelegate
scanner = Scanner().withDelegate(ScanDelegate())
# crear una lista de dispositivos únicos que el escáner descubrió durante un escaneo de 10 segundos
devices = scanner.scan(10.0)
# para cada dispositivo en la lista de dispositivos
for dev in devices:
    # imprimir la dirección MAC del dispositivo, su tipo de dirección
    # y la Indicación de Intensidad de Señal Recibida que muestra qué tan fuerte fue la señal cuando el script recibió la transmisión.
    print "Device %s (%s), RSSI=%d dB" % (dev.addr, dev.addrType, dev.rssi)
    # Para cada uno de los elementos de datos publicitarios del dispositivo, imprima una descripción del tipo de datos y el valor de los datos en sí
    # getScanData devuelve una lista de tuplas: adtype, desc, value
    # donde AD Type significa "tipo de datos publicitarios", según se define en la convención de Bluetooth:
    # https://www.bluetooth.com/specifications/assigned-numbers/generic-access-profile
    # desc es una descripción legible por humanos del tipo de datos y value son los datos en sí
    for (adtype, desc, value) in dev.getScanData():
        print "  %s = %s" % (desc, value)

Para un escaneo continuo, siga este ejemplo:

# importar las partes necesarias de la biblioteca bluepy
from bluepy.btle import Scanner, DefaultDelegate
# crear una clase delegada para recibir los paquetes de transmisión BLE
class ScanDelegate(DefaultDelegate):
    def __init__(self):
        DefaultDelegate.__init__(self)
    # cuando este script de python descubre un paquete de transmisión BLE, imprime un mensaje con la dirección MAC del dispositivo
    def handleDiscovery(self, dev, isNewDev, isNewData):
        if isNewDev:
            print "Discovered device", dev.addr
        elif isNewData:
            print "Received new data from", dev.addr
# crear un objeto escáner que envía paquetes de transmisión BLE al ScanDelegate
scanner = Scanner().withDelegate(ScanDelegate())
# iniciar el escáner y mantener el proceso en ejecución
scanner.start()
while True:
    print "Still running..."
    scanner.process()

TENGA EN CUENTA que (1) el escaneo LE debe ejecutarse como root y (2) el código de escaneo continuo nunca se completa, por lo que deberá hacer cosas útiles en el método handleDiscovery() de su delegado.

Consulte la documentación de ScanEntry para obtener información disponible a través del parámetro dev pasado al delegado.

LA CLASE SCANENTRY

Un objeto ScanEntry contiene información recibida de un dispositivo Bluetooth LE recibido durante la operación de Scanner. Esto incluye parámetros necesarios para conectarse al dispositivo (dirección MAC, tipo de dirección), y datos publicitarios (como su nombre o servicios disponibles) proporcionados en las transmisiones del dispositivo.

Constructor

Los objetos ScanEntry son creados por la clase Scanner, y no deben ser creados por el usuario.

Métodos de instancia

getDescription(adtype)
Devuelve una descripción legible por humanos del código de 'tipo' de datos publicitarios adtype. Por ejemplo, un valor de adtype de 9 devolvería la cadena "Complete Local Name". Vea los números asignados del Perfil de Acceso Genérico en https://www.bluetooth.org/en-us/specification/assigned-numbers/generic-access-profile para una lista completa.
getValueText(adtype)
Devuelve una representación de cadena legible por humanos de los datos publicitarios para el código adtype. Valores como el 'nombre local' se devuelven como cadenas directamente; otros valores se convierten a cadenas hexadecimales. Si los datos solicitados no están disponibles, se devuelve None.
getScanData()
Devuelve una lista de tuplas (adtype, description, value) que contienen el código del tipo AD, la descripción legible por humanos y el valor (tal como lo reportan getDescription() y getValueText()) para todos los elementos de datos publicitarios disponibles.

LA CLASE SCANENTRY

Los objetos ScanEntry contienen información sobre un dispositivo LE encontrado durante un escaneo. Son devueltos por el método discover() de la clase Scanner.

Constructor

ScanEntry()
Inicializa la instancia del objeto.

Propiedades

Todas las propiedades enumeradas a continuación son de solo lectura.

addr
La dirección MAC (o identificador de dispositivo) del dispositivo escaneado.
addrType
El tipo de dirección del dispositivo (p.ej. 'random' o 'public').
iface
El índice de la interfaz Bluetooth a través de la cual se recibió la entrada de escaneo.
rssi
La potencia de la señal recibida (en dBm).
connectable
Valor booleano que indica si el dispositivo puede ser conectado.
rawData
Los datos de publicidad brutos recibidos del dispositivo, como una cadena de bytes.
metadata
Lista de tuplas (tipo de dato, valor) que representan los diferentes campos encontrados en los datos de publicidad. Por ejemplo: (2, "XXYYZZ") donde 2 es el tipo de dato para el nombre localizado y "XXYYZZ" es el nombre.
commonName
Si el dispositivo anuncia un nombre (usando el tipo de dato de publicidad 0x08 o 0x09), este será el nombre devuelto. De lo contrario, será None.
localName
Similar a commonName, pero solo devuelve el nombre si se encontró específicamente usando el tipo de dato de publicidad 0x08 (nombre localizado corto) o 0x09 (nombre localizado completo).
txPower
La potencia de transmisión del dispositivo, si está disponible en los datos de publicidad.
serviceUUIDs
Una lista de UUIDs de servicio anunciados por el dispositivo.
manufacturerData
Diccionario que contiene datos específicos del fabricante anunciados por el dispositivo. Las claves son identificadores de fabricante (enteros de 16 bits) y los valores son cadenas de bytes.
serviceData
Diccionario que contiene datos de servicio anunciados por el dispositivo. Las claves son UUIDs de servicio y los valores son cadenas de bytes.
updateCount
Recuento entero del número de paquetes de publicidad recibidos del dispositivo hasta el momento (desde que se llamó a clear() en el objeto Scanner que lo encontró).

LA CLASE DEFAULTDELEGATE

Las funciones de bluepy que reciben mensajes Bluetooth de forma asíncrona - como notificaciones, indicaciones y datos de publicidad - transmiten esta información al usuario llamando a métodos en un objeto 'delegate'.

Para ser útil, el objeto delegate será de una clase creada por el usuario. DefaultDelegate de Bluepy es una clase base para esto; deberías anular algunos o todos los métodos aquí con tu propio código específico de la aplicación.

Constructor

DefaultDelegate()
Inicializa la instancia del objeto.

Métodos de Instancia

handleNotification(cHandle, data)
Se llama cuando se recibe una notificación o indicación de un objeto Peripheral conectado. cHandle es el manejador (entero) para la característica; esto se puede usar para distinguir entre notificaciones de múltiples fuentes en el mismo peripheral. data son los datos de la característica (un tipo str en Python 2.x, y bytes en 3.x).
handleDiscovery(scanEntry, isNewDev, isNewData)
Se llama cuando se reciben datos de publicidad de un dispositivo LE mientras un objeto Scanner está activo. scanEntry contiene información del dispositivo y datos de publicidad; consulta la clase ScanEntry para más detalles. isNewDev es True si el dispositivo (identificado por su dirección MAC) no ha sido visto antes por el escáner, y False en caso contrario. isNewData es True si hay datos de publicidad nuevos o actualizados disponibles.

LA CLASE SERVICE

Un objeto Service LE de Bluetooth representa una colección de characteristics y descriptors que están todos relacionados con una función particular del peripheral. Esto permite descubrir characteristics particulares sin tener que enumerar todo lo que ofrece ese peripheral.

Constructor

No deberías construir objetos Service directamente. En su lugar, usa los métodos getServices() o getServiceByUUID() de un objeto Peripheral conectado.

Métodos de Instancia

getCharacteristics([forUUID=None])
Devuelve una lista de objetos Characteristic asociados con el servicio. Si esto no se ha hecho antes, se consulta al peripheral. De lo contrario, se devuelve una lista en caché. Si se proporciona forUUID, puede ser un objeto UUID o un valor utilizado para construir uno. En este caso, la lista devuelta, que puede estar vacía, contiene cualquier characteristic asociada con el servicio que coincida con ese UUID.

Propiedades

Todas las propiedades enumeradas a continuación son de solo lectura.

uuid
El UUID de Bluetooth para este servicio.
peripheral
El objeto Peripheral del dispositivo al que pertenece el servicio.

LA CLASE CHARACTERISTIC

Una "characteristic" LE de Bluetooth representa un elemento de datos corto que se puede leer o escribir. Estas pueden ser fijas (p.ej., una cadena que representa el nombre del fabricante) o cambiar dinámicamente (como la temperatura actual o el estado de un botón). La mayor parte de la interacción con los peripherals LE de Bluetooth se realiza leyendo o escribiendo characteristics.

Constructor

No deberías construir objetos Characteristic directamente. En su lugar, usa el método getCharacteristics() de un objeto Peripheral conectado.

Métodos de Instancia

read()
Lee el valor actual de una characteristic como una cadena de bytes. Para Python 2.x este es un valor de tipo str, y en Python 3.x es de tipo bytes. Esto se puede usar con el módulo struct para extraer valores enteros de los datos.
write(data[, withResponse=False])
Escribe los data dados a la characteristic. data debe ser de tipo str para Python 2.x, y de tipo bytes para Python 3.x. Bluetooth LE permite al remitente solicitar al peripheral que envíe una respuesta para confirmar que los datos han sido recibidos. Establecer el parámetro withResponse a True realizará esta solicitud. Se lanzará una BTLEException si el proceso de confirmación falla.
supportsRead()
Devuelve True si la characteristic puede ser leída (como lo indican sus propiedades) y False en caso contrario.
propertiesToString()
Devuelve una cadena que describe las propiedades de la characteristic ('READ', 'WRITE', etc.).
getHandle()
Devuelve el valor entero de 16 bits utilizado para identificar la characteristic en el protocolo GATT subyacente. Esto puede ser útil para distinguir entre notificaciones de diferentes characteristics (ver Working with notifications para más información).

Propiedades

Todas las propiedades enumeradas a continuación son de solo lectura.

uuid
El UUID de Bluetooth para esta characteristic.
peripheral
El objeto Peripheral del dispositivo al que pertenece la characteristic.
properties
Una máscara de bits de las propiedades de la characteristic.

LA CLASE DESCRIPTOR

La clase Descriptor es un marcador de posición. Actualmente, bluepy no admite ninguna operación útil con descriptores.

TRABAJANDO CON NOTIFICACIONES

En bluepy, las notificaciones se procesan creando un objeto "delegate" y registrándolo con el Peripheral. Se llama a un método en el delegate cada vez que se recibe una notificación del peripheral, como se muestra a continuación:

handleNotification(cHandle, data)
Se llama cuando se ha recibido una notificación de un Peripheral. Normalmente llamarás al método waitForNotifications() del peripheral para permitir esto, pero ten en cuenta que un dispositivo LE de Bluetooth puede transmitir notificaciones en cualquier momento. Esto significa que handleNotification() potencialmente puede ser llamado cuando cualquier llamada de BluePy esté en progreso.

WORKING WITH NOTIFICATIONS

Notifications are handled by defining a delegate object and passing it to the Peripheral object using the setDelegate() method. When a notification is received, the handleNotification() method of the delegate object is called.

The delegate object is required to have a method with the following signature:

handleNotification(self, cHandle, data)
The cHandle parameter is the GATT 'handle' for the characteristic which is sending the notification. If a peripheral sends notifications for more than one characteristic, this may be used to distinguish them. The 'handle' value can be found by calling the getHandle() method of a Characteristic object.
The data parameter is a str (Python 2.x) or bytes (Python 3.x) value containing the notification data. It is recommended you use Python's struct module to unpack this, to allow portability between language versions.

It is recommended that the class used for the delegate object is derived from btle.DefaultDelegate. This will ensure that an appropriate default method exists for any future calls which may be added to the delegate interface.

Example code

Code to receive notifications from a peripheral can follow the outline below:

import btle
class MyDelegate(btle.DefaultDelegate):
    def __init__(self, params):
        btle.DefaultDelegate.__init__(self)
        # ... initialise here
    def handleNotification(self, cHandle, data):
        # ... perhaps check cHandle
        # ... process 'data'
# Initialisation  -------
p = btle.Peripheral( address )
p.setDelegate( MyDelegate(params) )
# Setup to turn notifications on, e.g.
#   svc = p.getServiceByUUID( service_uuid )
#   ch = svc.getCharacteristics( char_uuid )[0]
#   ch.write( setup_data )
# Main loop --------
while True:
    if p.waitForNotifications(1.0):
        # handleNotification() was called
        continue
    print "Waiting..."
    # Perhaps do something else here
