python-ptrace(1)

PYTHON-PTRACE(1) python-ptrace PYTHON-PTRACE(1)

NOMBRE

Este proyecto ya no se mantiene y está buscando un nuevo mantenedor.

python-ptrace es un depurador que utiliza ptrace (llamada al sistema de Linux, BSD y Darwin para rastrear procesos) escrito en Python.

  • Documentación de python-ptrace
  • python-ptrace en GitHub
  • python-ptrace en el Quiosco de Python (PyPI)

python-ptrace es un proyecto de código abierto escrito en Python bajo licencia GNU GPLv2. Soporta Python 3.6 y versiones posteriores.

CARACTERÍSTICAS

  • API de objetos Python de alto nivel: PtraceDebugger y PtraceProcess
  • Capaz de controlar múltiples procesos: captura eventos fork en Linux
  • Lee/escribe bytes en direcciones arbitrarias: cuida la alineación de memoria y divide los bytes en palabras de CPU
  • Ejecución paso a paso utilizando ptrace_singlestep() o interrupción de hardware 3
  • Puede usar el desensamblador distorm
  • Volca registros, mapeos de memoria, pila, etc.
  • Trazador y analizador de llamadas al sistema (comando strace.py)

Estado:

  • Sistemas operativos soportados: Linux, FreeBSD, OpenBSD
  • Arquitecturas soportadas: x86, x86_64 (Linux), PPC (Linux), ARM (Linux EAPI)

Características faltantes:

  • Símbolos: no es posible detenerse en una función o leer el valor de una variable
  • Sin soporte para lenguaje C: ¡el depurador muestra código ensamblador, no tu código C (C++ u otro lenguaje)!
  • Sin soporte para hilos (threads)

Uso de python-ptrace

Hola Mundo

Ejemplo corto que se adjunta a un proceso en ejecución. Obtiene el puntero de instrucción, ejecuta un solo paso y obtiene el nuevo puntero de instrucción:

import ptrace.debugger
import signal
import subprocess
import sys
def debugger_example(pid):
    debugger = ptrace.debugger.PtraceDebugger()
    print("Adjuntando el proceso en ejecución %s" % pid)
    process = debugger.addProcess(pid, False)
    # process es una instancia de PtraceProcess
    print("IP antes: %#x" % process.getInstrPointer())
    print("Ejecutando un solo paso")
    process.singleStep()
    # singleStep() devuelve el control al proceso. Tenemos que esperar
    # hasta que el proceso sea atrapado de nuevo para recuperar el control sobre el
    # proceso.
    process.waitSignals(signal.SIGTRAP)
    print("IP después: %#x" % process.getInstrPointer())
    process.detach()
    debugger.quit()
def main():
    args = [sys.executable, '-c', 'import time; time.sleep(60)']
    child_popen = subprocess.Popen(args)
    debugger_example(child_popen.pid)
    child_popen.kill()
    child_popen.wait()
if __name__ == "__main__":
    main()

API

PtraceProcess

La clase PtraceProcess es una ayuda para manipular un proceso rastreado.

Ejemplo:

tracer = PtraceProcess(pid)              # adjuntar el proceso
tracer.singleStep()                      # ejecutar una instrucción
tracer.cont()                            # continuar ejecución
tracer.syscall()                         # detenerse en la próxima llamada al sistema
tracer.detach()                          # desadjuntar el proceso
# Obtener estado
tracer.getreg('al')                      # obtener el valor del registro AL
regs = tracer.getregs()                  # leer todos los registros
bytes = tracer.readBytes(regs.ax, 10)    # leer 10 bytes
tracer.dumpCode()                        # volcar código (como ensamblador o hexadecimal si falta el desensamblador)
tracer.dumpStack()                       # volcar pila (palabras de memoria alrededor de ESP)
# Modificar el proceso
shellcode = '...'
ip = tracer.getInstrPointer()            # obtener registro EIP/RIP
bytes = tracer.writeBytes(ip, shellcode) # escribir algunos bytes
tracer.setreg('ebx', 0)                  # establecer el registro EBX a cero

Lee el código fuente de ptrace/debugger/process.py para ver más métodos.

gdb.py

gdb.py es un depurador de línea de comandos *similar a gdb*, pero con menos características: sin soporte de símbolos, sin soporte del lenguaje C, sin soporte de hilos, etc.

Algunos comandos

  • cont: continuar la ejecución
  • stepi: ejecutar una instrucción
  • step: ejecutar una instrucción, pero sin entrar en las llamadas

Escribe help para listar todos los comandos disponibles.

Características

•

Eventos de proceso de python-ptrace

Eventos de proceso

Todos los eventos de proceso se basan en la clase ProcessEvent.

  • ProcessExit: el proceso salió con un código de salida, fue terminado por una señal o salió de forma anormal
  • ProcessSignal: el proceso recibió una señal
  • NewProcessEvent: se creó un nuevo proceso, por ejemplo, después de una llamada al sistema fork()

Atributos:

  • Todos los eventos tienen un atributo "process"
  • ProcessExit tiene los atributos "exitcode" y "signum" (ambos pueden ser None)
  • ProcessSignal tiene los atributos "signum" y "name"

Para NewProcessEvent, usa el atributo parent del proceso para obtener el proceso padre.

Nota: ProcessSignal tiene un método display() para mostrar su contenido. Úsalo justo después de recibir el mensaje porque lee la memoria del proceso para analizar las razones por las que se envió la señal.

Esperar cualquier evento de proceso

La función más genérica es waitProcessEvent(): espera cualquier evento de proceso (salida, señal o nuevo proceso):

event = debugger.waitProcessEvent()

Para esperar una o más señales, usa los métodos waitSignals(). Sin argumento, espera cualquier señal. Los eventos diferentes de señales se generan como excepciones de Python. Ejemplos:

signal = debugger.waitSignals()
signal = debugger.waitSignals(SIGTRAP)
signal = debugger.waitSignals(SIGINT, SIGTERM)

Nota: signal es un objeto ProcessSignal, usa signal.signum para obtener el número de la señal.

Esperar eventos de un proceso específico

Para esperar cualquier evento de un proceso, usa el método waitEvent():

event = process.waitEvent()

Para esperar una o más señales, usa el método waitSignals(). Sin argumento, espera cualquier señal. Otros eventos del proceso se generan como excepciones de Python. Ejemplos:

signal = process.waitSignals()
signal = process.waitSignals(SIGTRAP)
signal = process.waitSignals(SIGINT, SIGTERM)

Nota: Al igual que debugger.waitSignals(), signal es un objeto ProcessSignal.

Manejo de señales de python-ptrace

Introducción

PtraceSignal intenta mostrar información útil cuando se recibe una señal. Dependiendo del número de señal, muestra diferente información.

Utiliza la instrucción actual decodificada como código ensamblador para comprender por qué se genera la señal.

Solo Intel x86 (i386, quizás x86_64) es compatible actualmente.

Cuando un proceso recibe una señal, python-ptrace intenta explicar por qué se emitió la señal.
