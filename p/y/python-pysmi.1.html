DOCUMENTACIÓN

Documentación de PySMI

La biblioteca PySMI es altamente modular. El componente de nivel superior se llama compiler (compilador) y actúa como el objeto principal orientado al usuario. La mayoría de los otros componentes se enchufan al objeto compiler antes de su uso.

Normalmente, el usuario solicita al compiler que realice cierta transformación del módulo MIB nombrado. El compilador:

  • Busca en sus fuentes de datos el módulo MIB dado (identificado por nombre), anotando sus últimas fechas de modificación.
  • Busca en los repositorios gestionados por el compilador de módulos MIB ya convertidos, módulos que sean más recientes que el módulo MIB fuente correspondiente.
  • Si se encuentra un módulo MIB transformado recientemente, el procesamiento se detiene aquí.
  • De lo contrario, el compilador pasa el contenido del módulo MIB ASN.1 al componente lexer (analizador léxico).
  • El lexer devuelve una secuencia de contenidos MIB ASN.1 tokenizados. El compilador luego pasa esa secuencia de tokens al componente parser (analizador sintáctico).
  • El parser ejecuta el algoritmo LR sobre el MIB tokenizado, transformando así el contenido del MIB en un Árbol de Sintaxis Abstracta (AST) y también anotando qué otros módulos MIB se refieren desde el MIB que se está analizando.
  • En caso de fallo del parser, lo que generalmente es una indicación de sintaxis MIB ASN.1 rota, el compilador puede intentar obtener el contenido del MIB pre-transformado de la fuente configurada. Este proceso se llama borrowing (préstamo) en PySMI.
  • En caso de que el parser se complete con éxito, el compilador pasará el AST producido al componente code generator (generador de código).
  • El generador de código recorre su AST de entrada y realiza la transformación real de los datos.
  • Los pasos anteriores pueden repetirse para cada uno de los módulos MIB a los que se hace referencia, ya que el parser los descubre. Una vez que no quedan dependencias sin resolver, el compilador llamará a su componente writer (escritor) para almacenar todos los módulos MIB transformados.

La ubicación de los módulos MIB ASN.1 y el sabor de su sintaxis, así como el formato de transformación deseado, se determinan por los componentes respectivos elegidos y configurados para el compilador.

La herramienta mibdump

La herramienta mibdump.py es un frontend de línea de comandos para la biblioteca PySMI. Esta herramienta se puede utilizar para descargar y transformar automáticamente módulos MIB SNMP en varios formatos.

Especificando la fuente MIB

La opción --mib-source se puede dar varias veces. Cada instancia de --mib-source debe especificar una URL donde se deben buscar y descargar los módulos MIB ASN.1. En este momento se admiten tres métodos de origen MIB:

  • Archivos locales. Este podría ser un directorio de nivel superior donde se encuentran los archivos MIB. Los subdirectorios también se recorrerán automáticamente. Ejemplo: file:///usr/share/snmp
  • Archivos ZIP que contienen archivos MIB. Los subdirectorios y los archivos ZIP incrustados se recorrerán automáticamente. Ejemplo: zip://mymibs.zip
  • HTTP/HTTPS. Una URL completamente especificada donde el nombre del módulo MIB se especifica mediante un marcador de posición @mib@. Cuando se busca un MIB específico, PySMI reemplazará ese marcador de posición con el nombre del módulo MIB que está buscando. Ejemplo: http://mibs.snmplabs.com/asn1/@mib@
  • SFTP/FTP. Una URL completamente especificada que incluye nombre de usuario y contraseña FTP. El nombre del módulo MIB se especifica mediante un marcador de posición @mib@. Cuando se busca un MIB específico, PySMI reemplazará ese marcador de posición con el nombre del módulo MIB que está buscando. Ejemplo: http://mibs.snmplabs.com/asn1/@mib@

Al intentar obtener un módulo MIB, la herramienta mibdump.py intentará cada uno de los transportes --mib-source configurados en el orden de especificación hasta el primer acierto exitoso.

Por defecto, mibdump.py buscará:

  • file:///usr/share/snmp
  • http://mibs.snmplabs.com/asn1/@mib@

Una vez que se proporcione otra opción --mib-source, esos predeterminados no se usarán y deberían ser proporcionados manualmente a mibdump.py si es necesario.

Nombres de módulos MIB difusos

No existe una convención única sobre cómo deben nombrarse los archivos de módulos MIB. Por defecto, mibdump.py intentará varias posibilidades al tratar de encontrar un archivo que contenga un módulo MIB específico. Intentará mayúsculas y minúsculas, un archivo con el nombre del módulo MIB, intentará agregar diferentes extensiones al archivo (.mib, .my, etc.), intentará agregar/cortar la parte '-MIB' del nombre del archivo. Si nada coincide, mibdump.py considerará que el --mib-source probado no contiene el módulo MIB que está buscando.

Sin embargo, existe una pequeña posibilidad de que la coincidencia difusa resulte en la obtención de un MIB incorrecto. Si eso sucede, puede deshabilitar la difusividad anterior proporcionando a mibdump.py la bandera --disable-fuzzy-source.

Evitar transformaciones excesivas

Puede suceder que muchos módulos MIB hagan referencia a un único módulo MIB común. En ese caso, m

ibdump.py puede transformarlo muchas veces a menos que le diga a mibdump.py dónde buscar MIBs ya transformadas. Ese lugar podría ser, por supuesto, un directorio donde mibdump.py escribe sus transformaciones y/o algunas otras ubicaciones locales.

La opción --mib-searcher especifica un directorio local o un paquete Python importable (aplicable a la transformación de pysnmp) que contiene módulos MIB transformados. Se pueden proporcionar varias opciones --mib-searcher; mibdump.py utilizará cada una de ellas en el orden de especificación hasta el primer acierto.

Si no se encuentra ningún módulo MIB transformado, mibdump.py continuará ejecutando su ciclo de transformación completo.

Por defecto, mibdump.py utilizará:

  • --mib-searcher=$HOME/.pysnmp/mibs
  • --mib-searcher=pysnmp_mibs

Una vez que se proporcione otra opción --mib-searcher, los valores predeterminados no se utilizarán y deberán proporcionarse manualmente a mibdump.py si es necesario.

Lista_negra_de_MIBs

Algunas MIBs pueden no ser transformadas automáticamente a otra forma y, por lo tanto, deben excluirse explícitamente del procesamiento. Dichas MIBs normalmente se implementan manualmente para cada formato de MIB de destino. Los ejemplos incluyen MIBs que contienen tipos SMI base o definiciones de MACRO ASN.1 (SNMPv2-SMI, SNMPV2-TC), MIBs compiladas inicialmente pero modificadas posteriormente manualmente y otras.

La lista predeterminada de MIBs en lista negra para el destino de transformación de pysnmp es: RFC-1212, RFC-1215, RFC1065-SMI, RFC1155-SMI, RFC1158-MIB, RFC1213-MIB, SNMP-FRAMEWORK-MIB, SNMP-TARGET-MIB, SNMPv2-CONF, SNMPv2-SMI, SNMPv2-TC, SNMPv2-TM, TRANSPORT-ADDRESS-MIB.

Si necesita modificar esta lista, utilice la opción --mib-stub.

Manejo_de_MIBs_rotas

Curiosamente, algunas MIBs de proveedores muy prominentes parecen ser sintácticamente incorrectas. Esto hace que los compiladores de MIB fallen en tales MIBs. Si bien muchas implementaciones de compiladores de MIB (incluido PySMI) introducen soluciones alternativas y relajaciones de gramática que permiten compilar MIBs ligeramente rotas, las MIBs severamente rotas no se pueden compilar de manera confiable.

Como otra solución alternativa, PySMI ofrece la característica de "borrow" (tomar prestado). Permite a PySMI obtener MIBs ya transformadas incluso si la ASN.1 MIB correspondiente no se puede encontrar o analizar.

La fuente predeterminada de MIBs precompiladas para el destino pysnmp es:

  • http://mibs.snmplabs.com/pysnmp/fulltexts/@mib@
  • http://mibs.snmplabs.com/pysnmp/notexts/@mib@

Si desea modificar esta lista predeterminada, utilice una o más opciones --mib-borrower.

Elección_de_la_transformación_de_destino

El diseño de PySMI permite que muchos formatos de transformación sean soportados en forma de componentes especializados de generación de código. Por el momento, PySMI puede producir MIBs en forma de clases pysnmp y documentos JSON.

El esquema del documento JSON está elegido para preservar la mayor cantidad de información de la MIB posible. No se conoce ningún esquema JSON establecido por los autores.

Configuración del directorio de destino

Por defecto, mibdump.py escribe las MIBs de pysnmp en:

  • $HOME/.pysnmp/mibs (en UNIX)
  • @HOME@PySNMP ConfigurationMIBs (en Windows)

y archivos JSON en el directorio de trabajo actual.

Utilice la opción --destination-directory para cambiar el directorio de salida predeterminado.

Realización_de_transformación_incondicional

Por defecto, PySMI evitará crear nuevas transformaciones si ya existen versiones suficientemente nuevas. Al utilizar la opción --rebuild, puede engañar a PySMI para que realice la transformación solicitada para todos los módulos MIB dados.

Ignorar errores de transformación

Por defecto, PySMI se detendrá ante el primer error fatal ocurrido durante la transformación de una serie de MIBs. Si desea que PySMI ignore los errores fatales y, por lo tanto, omita la MIB fallida, utilice la opción --ignore-errors.

Tenga en cuenta que omitir la transformación de MIBs que son importadas por otras MIBs podría hacer que las MIBs dependientes sean inconsistentes para su uso.

Omitir_dependencias

La mayoría de las MIBs dependen de otras MIBs para su funcionamiento. Esto se indica mediante la declaración IMPORT en el lenguaje ASN.1. PySMI intenta transformar todas las MIBs IMPORTadas por la MIB que se está transformando. Esto se hace de manera recursiva.

Al usar la bandera --no-dependencies, puede indicarle a PySMI que no transforme ninguna MIB aparte de las que se solicitaron explícitamente para ser transformadas.

Tenga en cuenta que omitir las dependencias puede hacer que todo el conjunto de MIBs transformadas sea inconsistente.

Generación_de_textos_de_MIB

La mayoría de las MIBs son muy verbosas. Contienen muchas descripciones y aclaraciones orientadas al ser humano escritas en inglés claro. Esos textos pueden ser útiles para las aplicaciones del navegador MIB (para mostrar esos textos a un operador humano), pero podrían no tener sentido en otras aplicaciones.

Para ahorrar espacio y tiempo de CPU, PySMI no incluye por defecto esos textos en las MIBs transformadas. Sin embargo, esto se puede revertir agregando la opción --generate-mib-texts.

Cuando se generan textos de MIB, los espacios en blanco y saltos de línea se eliminan por defecto. A veces, esto rompe el "arte ASCII" si aparece en los textos de la MIB. Para preservar el formato de texto original, se puede usar la opción --keep-texts-layout.

Construcción_de_índices_de_MIB

Si se proporciona la opción --build-index, dependiendo del formato de destino elegido, la herramienta mibdump.py puede crear (o actualizar un índice existente) documento que contiene información de la MIB en un formato conveniente para consultar las propiedades fundamentales de los archivos MIB.

Pequeñas optimizaciones

Hay algunas opciones que pueden mejorar el rendimiento de PySMI.

La opción --cache-directory se puede utilizar para apuntar a un directorio temporal escribible donde el analizador de PySMI (por ejemplo, Ply) almacenaría sus tablas de búsqueda.

Por defecto, PySMI al realizar la transformación al formato pysnmp también precompilará el código fuente de Python a bytecode del intérprete. Eso lleva tiempo y espacio. Si no desea almacenar en caché el bytecode de Python o hacerlo más tarde, utilice la opción --no-python-compile.

La herramienta mibcopy

La herramienta mibcopy.py intenta normalizar el nombre del archivo MIB.

Resulta que a veces los proveedores nombran sus MIBs de cualquier manera posible, no necesariamente según el nombre canónico de la MIB. Esto causa problemas a los consumidores de MIB, ya que es posible que no puedan localizar la MIB que necesitan en el sistema de archivos.

La forma en que funciona mibcopy.py es que intenta leer la MIB del archivo dado (o todos los archivos de un directorio o archivo dado), analiza el nombre canónico de la MIB del contenido del archivo. Basándose en esto, la herramienta intenta renombrar el archivo MIB al nombre que es el mismo que el nombre canónico de la MIB. Si mibcopy.py encuentra un archivo con el mismo nombre ya presente en el sistema de archivos, lo lee para ver su fecha de revisión. Luego, la herramienta compara las fechas de revisión de los archivos MIB en colisión y sobrescribe el archivo infractor o descarta el archivo que se está copiando por estar obsoleto.

El objetivo final es terminar con las últimas versiones de los archivos MIB, todos nombrados según sus nombres canónicos.

Biblioteca PySMI

El objeto MibCompiler es la interfaz superior para las funciones de la biblioteca PySMI. Une las piezas de la infraestructura del compilador, de otro modo aisladas, y gestiona el flujo de trabajo de la transformación de MIBs ASN.1.

Este ejemplo muestra algunas de sus características:

from pysmi.reader import HttpReader
from pysmi.searcher import StubSearcher
from pysmi.writer import CallbackWriter
from pysmi.parser import SmiStarParser
from pysmi.codegen import JsonCodeGen
from pysmi.compiler import MibCompiler
inputMibs = ['IF-MIB', 'IP-MIB']
httpSources = [('mibs.snmplabs.com', 80, '/asn1/@mib@')]
# almacena los MIBs compilados llamando a esta función
def store_mibs(mibName, jsonDoc, cbCtx):
    print('# MIB module %s' % mibName)
    print(jsonDoc)
mibCompiler = MibCompiler(
    SmiStarParser(), JsonCodeGen(), CallbackWriter(store_mibs)
)
# extrae MIBs ASN.1 a través de HTTP
mibCompiler.addSources(*[HttpReader(*x) for x in httpSources])
# nunca recompila MIBs con MACROs ASN.1
mibCompiler.addSearchers(StubSearcher(*JsonCodeGen.baseMibs))
status = mibCompiler.compile(*inputMibs)
print(status)

Fuentes MIB

PySMI ofrece un puñado de mecanismos de transporte distintos para obtener MIBs por nombre desde ubicaciones específicas. En todos los casos, la coincidencia del nombre del módulo MIB con el nombre del archivo puede no ser exacta: se puede realizar alguna coincidencia aproximada de nombres para mitigar posibles cambios en el nombre del archivo MIB.

Lector de archivos locales

La instancia de la clase FileReader busca archivos MIB en los directorios dados en el host que ejecuta PySMI.

Lector de archivos ZIP

La instancia de la clase ZipReader busca archivos MIB en un archivo ZIP local. Se recorrerán los subdirectorios ZIP y los archivos ZIP incrustados.

Lector HTTP

La instancia de la clase HttpReader intenta descargar archivos MIB utilizando la URL configurada.

Lector FTP

La instancia de la clase FtpReader intenta descargar archivos MIB desde el servidor FTP configurado.

Lector de retorno de llamada

La instancia de la clase CallbackReader intenta obtener archivos MIB llamando a un objeto de usuario.

Compilación condicional

Hay casos en los que la transformación MIB puede o no debe realizarse. Tales casos incluyen:

  • MIBs fundamentales que contienen piezas implementadas manualmente o MACROs ASN.1
  • MIBs obsoletos completamente reimplementados dentro de MIBs modernos
  • MIBs ya transformados

MibCompiler espera que el usuario proporcione un objeto searcher que permita o omita la transformación MIB para un nombre particular basándose en la razón que conozca.

Buscador de archivos Python

Los MIBs transformados que se guardaron en forma de archivos Python pueden ser verificados con instancias de la clase PyFileSearcher.

Buscar paquetes Python

Algunos MIBs, con mayor frecuencia los básicos, pueden almacenarse en un paquete Python. Su existencia puede verificarse con las instancias de la clase PyPackageSearcher.

Ignorar MIBs incondicionalmente

Los MIBs fundamentales u obsoletos que nunca deben transformarse pueden excluirse ciegamente listando sus nombres en la instancia de la clase StubSearcher.

Configuración del analizador

Los MIBs pueden estar escritos en una de las dos versiones principales del lenguaje SMI (v1 y v2). Algunos MIBs pueden contener errores típicos.

PySMI ofrece una forma de personalizar el analizador para consumir cualquiera de las gramáticas SMI principales, así como para recuperarse de errores conocidos en los archivos MIB.

Analizador SMI

Los MIBs SNMP están escritos en dos tipos de lenguajes especiales: SMIv1 y SMIv2. La primera versión SMI está obsoleta, la mayoría de los MIBs ahora están escritos en la gramática SMIv2. También hay esfuerzos dirigidos a mejorar SMIv2, pero esos MIBs son minoritarios en el momento de esta escritura.

PySMI está diseñado para manejar tanto SMIv1 como SMIv2. La forma en que se hace es que SMIv2 se considera el más básico y completo, mientras que SMIv1 es una especialización de la sintaxis SMIv2.

Para que un usuario adquiera un analizador SMIv2, se debe llamar a la función parserFactory con el objeto de dialecto SMI.

El objeto analizador debe pasarse al objeto MibCompiler.

NOTA:

Por favor, tenga en cuenta que la función parserFactory devuelve una clase, no una instancia de clase. Asegúrese de instanciarla al pasarla al constructor de la clase MibCompiler.

Dialectos del lenguaje SMI

PySMI ofrece una colección preconstruida de opciones de relajación de gramática de analizador para simplificar su uso:

  • pysmi.parser.dialect.smiV2 - gramática SMIv2 canónica
  • pysmi.parser.dialect.smiV1 - gramática SMIv1 canónica
  • pysmi.parser.dialect.smiV1Relaxed - gramática SMIv1 relajada que permite algunas desviaciones

El objeto gramática debe pasarse a la función parserFactory.

from pysmi.parser.dialect import smiV1
from pysmi.parser.smi import parserFactory
SmiV1Parser = parserFactory(**smiV1)

Aparentemente, muchos MIBs de producción se distribuyeron en condiciones sintácticamente rotas. PySMI intenta solucionar tales problemas permitiendo algunas relajaciones adicionales de la gramática SMI. Puede habilitar todas esas relajaciones a la vez para maximizar el número de MIBs, encontrados en la naturaleza, compilados con éxito.

from pysmi.parser.dialect import smiV1Relaxed
from pysmi.parser.smi import parserFactory
RelaxedSmiV1Parser = parserFactory(**smiV1Relaxed)

Ejemplos

Los siguientes ejemplos se centran en varias características de la biblioteca PySMI.

Compilar MIBs en JSON

Busca MIBs ASN.1 específicas en sitios Web y FTP configurados, las compila en documentos JSON y las imprime en la salida estándar.

Intenta dar soporte tanto a las variantes SMIv1 como SMIv2 de SMI, así como a desviaciones populares de la sintaxis oficial encontradas en la práctica.

from pysmi.reader import FileReader, HttpReader
from pysmi.searcher import StubSearcher
from pysmi.writer import CallbackWriter
from pysmi.parser import SmiStarParser
from pysmi.codegen import JsonCodeGen
from pysmi.compiler import MibCompiler
# from pysmi import debug
# debug.setLogger(debug.Debug('reader', 'compiler'))
inputMibs = ['IF-MIB', 'IP-MIB']
srcDirectories = ['/usr/share/snmp/mibs']
httpSources = [
    ('mibs.snmplabs.com', 80, '/asn1/@mib@')
]
def printOut(mibName, jsonDoc, cbCtx):
    print('\n\n# MIB module %s' % mibName)
    print(jsonDoc)
# Initialize compiler infrastructure
mibCompiler = MibCompiler(
    SmiStarParser(), JsonCodeGen(), CallbackWriter(printOut)
)
# search for source MIBs here
mibCompiler.addSources(*[FileReader(x) for x in srcDirectories])
# search for source MIBs at Web sites
mibCompiler.addSources(*[HttpReader(*x) for x in httpSources])
# never recompile MIBs with MACROs
mibCompiler.addSearchers(StubSearcher(*JsonCodeGen.baseMibs))
# run recursive MIB compilation
results = mibCompiler.compile(*inputMibs)
print('\n# Results: %s' % ', '.join(['%s:%s' % (x, results[x]) for x in results]))

Compilar MIBs desde la web

Busca MIBs ASN.1 específicas en sitios Web y FTP configurados, las compila en formato pysnmp y guarda los módulos Python como archivos de texto plano en un directorio local.

Intenta dar soporte tanto a las variantes SMIv1 como SMIv2 de SMI, así como a desviaciones populares de la sintaxis oficial encontradas en la práctica.

En este ejemplo, deshabilitamos la comprobación automática de dependencias en la compilación de MIBs utilizando la opción noDeps.

Además, no comprobamos si el archivo de destino ya existe, por lo que la compilación de MIBs se produce en cada invocación.

from pysmi.reader import HttpReader
from pysmi.reader import FtpReader
from pysmi.searcher import StubSearcher
from pysmi.writer import PyFileWriter
from pysmi.parser import SmiStarParser
from pysmi.codegen import PySnmpCodeGen
from pysmi.compiler import MibCompiler
inputMibs = ['IF-MIB', 'IP-MIB']
httpSources = [
    ('mibs.snmplabs.com', 80, '/asn1/@mib@')
]
ftpSources = [
    ('ftp.cisco.com', '/pub/mibs/v2/@mib@')
]
dstDirectory = '.pysnmp-mibs'
# Initialize compiler infrastructure
mibCompiler = MibCompiler(
    SmiStarParser(), PySnmpCodeGen(), PyFileWriter(dstDirectory)
)
# search for source MIBs at Web and FTP sites
mibCompiler.addSources(*[HttpReader(*x) for x in httpSources])
mibCompiler.addSources(*[FtpReader(*x) for x in ftpSources])
# never recompile MIBs with MACROs
mibCompiler.addSearchers(StubSearcher(*PySnmpCodeGen.baseMibs))
# run non-recursive MIB compilation
results = mibCompiler.compile(*inputMibs, **dict(noDeps=True))
print('Results: %s' % ', '.join(['%s:%s' % (x, results[x]) for x in results]))

Compilar MIBs SMIv1/v2

Busca MIBs ASN.1 específicas en directorios locales configurados, las compila en formato pysnmp si aún no se ha hecho y guarda los módulos Python como archivos de texto plano en un directorio local.

Intenta dar soporte tanto a las variantes SMIv1 como SMIv2 de SMI, así como a desviaciones populares de la sintaxis oficial encontradas en la práctica.

Al determinar si la compilación es necesaria, comprueba todos los lugares conocidos donde las MIBs de pysnmp podrían encontrarse.

Puedes forzar la recompilación de MIBs pasando el indicador rebuild al compilador de MIBs (ver abajo).

La invocación predeterminada del compilador de MIBs no genera comentarios y textos [potencialmente grandes] que se encuentran en las MIBs. Si los necesitas en los módulos MIB de pysnmp, simplemente pasa el indicador genTexts al compilador de MIBs.

from pysmi.reader import FileReader
from pysmi.searcher import PyFileSearcher, PyPackageSearcher, StubSearcher
from pysmi.writer import PyFileWriter
from pysmi.parser import SmiStarParser
from pysmi.codegen import PySnmpCodeGen
from pysmi.compiler import MibCompiler
inputMibs = ['IF-MIB', 'IP-MIB']
srcDirectories = ['/usr/share/snmp/mibs']
dstDirectory = '.pysnmp-mibs'
# Initialize compiler infrastructure
mibCompiler = MibCompiler(SmiStarParser(),
                          PySnmpCodeGen(),
                          PyFileWriter(dstDirectory))
# search for source MIBs here
mibCompiler.addSources(*[FileReader(x) for x in srcDirectories])
# check compiled MIBs in our own productions
mibCompiler.addSearchers(PyFileSearcher(dstDirectory))
# ...and at default PySNMP MIBs packages
mibCompiler.addSearchers(*[PyPackageSearcher(x) for x in PySnmpCodeGen.defaultMibPackages])
# never recompile MIBs with MACROs
mibCompiler.addSearchers(StubSearcher(*PySnmpCodeGen.baseMibs))
# run [possibly recursive] MIB compilation
results = mibCompiler.compile(*inputMibs)  #, rebuild=True, genTexts=True)
print('Results: %s' % ', '.join(['%s:%s' % (x, results[x]) for x in results]))

Compilar MIBs SMIv2

Invoca una función de devolución de llamada de usuario para proporcionar texto de MIB, compila la cadena de texto dada en formato MIB de pysnmp y pasa los resultados a otra función de devolución de llamada de usuario para su almacenamiento.

Aquí esperamos tratar solo con MIBs válidas para SMIv2.

Usamos la opción noDeps para evitar que el compilador de MIBs intente compilar también las MIBs IMPORTadas.

import sys
from pysmi.reader import CallbackReader
from pysmi.searcher import StubSearcher
from pysmi.writer import CallbackWriter
from pysmi.parser import SmiV2Parser
from pysmi.codegen import PySnmpCodeGen
from pysmi.compiler import MibCompiler
inputMibs = ['IF-MIB', 'IP-MIB']
srcDir = '/usr/share/snmp/mibs/'  # we will read MIBs from here
# Initialize compiler infrastructure
mibCompiler = MibCompiler(
    SmiV2Parser(),
    PySnmpCodeGen(),
    # out own callback function stores results in its own way
    CallbackWriter(lambda m, d, c: sys.stdout.write(d))
)
# our own callback function serves as a MIB source here
mibCompiler.addSources(
  CallbackReader(lambda m, c: open(srcDir+m+'.txt').read())
)
# never recompile MIBs with MACROs
mibCompiler.addSearchers(StubSearcher(*PySnmpCodeGen.baseMibs))
# run non-recursive MIB compilation
results = mibCompiler.compile(*inputMibs, **dict(noDeps=True))
print('Results: %s' % ', '.join(['%s:%s' % (x, results[x]) for x in results]))

Tomar prestadas MIBs pysnmp en caso de fallo

Busca MIBs ASN.1 específicas en sitios Web/FTP configurados. Si no se encuentra la MIB requerida o su compilación falla por alguna razón, intenta descargar la versión precompilada de la MIB fallida y almacenarla localmente como si la hubiéramos compilado.

from pysmi.reader import HttpReader
from pysmi.searcher import PyFileSearcher
from pysmi.searcher import StubSearcher
from pysmi.borrower import PyFileBorrower
from pysmi.writer import PyFileWriter
from pysmi.parser import SmiStarParser
from pysmi.codegen import PySnmpCodeGen
from pysmi.compiler import MibCompiler
# from pysmi import debug
# debug.setLogger(debug.Debug('borrower', 'reader', 'searcher'))
inputMibs = ['BORROWED-MIB']
httpSources = [
    ('mibs.snmplabs.com', 80, '/asn1/@mib@')
]
httpBorrowers = [
    ('mibs.snmplabs.com', 80, '/pysnmp/notexts/@mib@')
]
dstDirectory = '.pysnmp-mibs'
# Initialize compiler infrastructure
mibCompiler = MibCompiler(
    SmiStarParser(), PySnmpCodeGen(), PyFileWriter(dstDirectory)
)
# search for source MIBs at Web sites
mibCompiler.addSources(*[HttpReader(*x) for x in httpSources])
# never recompile MIBs with MACROs
mibCompiler.addSearchers(StubSearcher(*PySnmpCodeGen.baseMibs))
# check compiled/borrowed MIBs in our own productions
mibCompiler.addSearchers(PyFileSearcher(dstDirectory))
# search for compiled MIBs at Web sites if source is not available or broken
mibCompiler.addBorrowers(*[PyFileBorrower(HttpReader(*x)).setOptions(genTexts=False) for x in httpBorrowers])
# run non-recursive MIB compilation
results = mibCompiler.compile(*inputMibs)
print('Results: %s' % ', '.join(['%s:%s' % (x, results[x]) for x in results]))
