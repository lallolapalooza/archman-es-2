flask-principal - Documentación de Flask-Principal

"Yo soy lo que soy"

INTRODUCCIÓN

Flask-Principal proporciona un marco muy flexible para conectar proveedores de dos tipos de servicios, a menudo ubicados en diferentes partes de una aplicación web:

1.
Proveedores de autenticación
2.
Proveedores de información del usuario

Por ejemplo, un proveedor de autenticación puede ser oauth, utilizando Flask-OAuth, y la información del usuario puede almacenarse en una base de datos relacional. La flexibilidad del marco se proporciona mediante el uso de señales como interfaz.

Los componentes principales son la Identidad, las Necesidades, el Permiso y el Contexto de Identidad.

1.
La Identidad representa al usuario y se almacena/carga desde varias ubicaciones (por ejemplo, sesión) para cada solicitud. La Identidad es el avatar del usuario para el sistema. Contiene los derechos de acceso que tiene el usuario.
2.
Una Necesidad es la unidad más pequeña de control de acceso y representa un parámetro específico para la situación. Por ejemplo, "tiene el rol de administrador", "puede editar publicaciones de blog".

Las Necesidades son cualquier tupla, o probablemente podrían ser objetos como prefieras, pero una tupla se ajusta perfectamente. Los tipos de Necesidad pre-diseñados (para ahorrarte escritura) son pares de (método, valor) donde el método se utiliza para especificar cosas comunes como "role", "user", etc. Y el valor es el valor. Un ejemplo de esto es ('role', 'admin'). Lo que sería una Necesidad para un rol de administrador. O Triples para casos de uso como "El permiso para editar una instancia particular de un objeto o fila", que podría representarse como el triple ('article', 'edit', 46), donde 46 es la clave/ID para esa fila/objeto.

Esencialmente, cómo y qué son las Necesidades depende en gran medida del usuario, y está diseñado de forma flexible para que se pueda lograr cualquier efecto utilizando instancias personalizadas como Necesidades.

Mientras que una Necesidad es un permiso para acceder a un recurso, una Identidad debería proporcionar un conjunto de Necesidades a las que tiene acceso.

3.
Un Permiso es un conjunto de requisitos, cualquiera de los cuales debe estar presente para acceder a un recurso.
4.
Un Contexto de Identidad es el contexto de una identidad determinada contra un Permiso determinado. Se puede utilizar como administrador de contexto o como decorador.

PROTECCIÓN DE ACCESO A RECURSOS

Para los usuarios de Flask-Principal (no para los proveedores de autenticación), la restricción de acceso es fácil de definir tanto como decorador como administrador de contexto. Se presenta un ejemplo simple de inicio rápido con comentarios:

from flask import Flask, Response
from flask.ext.principal import Principal, Permission, RoleNeed
app = Flask(__name__)
# cargar la extensión
principals = Principal(app)
# Crear un permiso con una sola Necesidad, en este caso una RoleNeed.
admin_permission = Permission(RoleNeed('admin'))
# proteger una vista con un principal para esa necesidad
@app.route('/admin')
@admin_permission.require()
def do_admin_index():
    return Response('Solo si eres administrador')
# esta vez proteger con un administrador de contexto
@app.route('/articles')
def do_articles():
    with admin_permission.require():
        return Response('Solo si eres administrador')

PROVEEDORES DE AUTENTICACIÓN

Los proveedores de autenticación deben usar la señal identity-changed para indicar que una solicitud ha sido autenticada. Por ejemplo, el siguiente código es un ejemplo hipotético de cómo se podría combinar la popular extensión Flask-Login http://packages.python.org/Flask-Login/ con Flask-Principal:

from flask import Flask, current_app, request, session
from flask.ext.login import LoginManager, login_user, logout_user, \
     login_required, current_user
from flask.ext.wtf import Form, TextField, PasswordField, Required, Email
from flask.ext.principal import Principal, Identity, AnonymousIdentity, \
     identity_changed
app = Flask(__name__)
Principal(app)
login_manager = LoginManager(app)
@login_manager.user_loader
def load_user(userid):
    # Devolver una instancia del modelo User
    return datastore.find_user(id=userid)
class LoginForm(Form):
    email = TextField()
    password = PasswordField()
@app.route('/login', methods=['GET', 'POST'])
def login():
    # Un formulario de inicio de sesión hipotético que utiliza Flask-WTF
    form = LoginForm()
    # Validar la entrada del formulario
    if form.validate_on_submit():
        # Recuperar el usuario del almacén de datos hipotético
        user = datastore.find_user(email=form.email.data)
        # Comparar contraseñas (usar hash de contraseñas en producción)
        if form.password.data == user.password:
            # Mantener la información del usuario en la sesión usando Flask-Login
            login_user(user)
            # Informar a Flask-Principal que la identidad ha cambiado
            identity_changed.send(current_app._get_current_object(),
                                  identity=Identity(user.id))
            return redirect(request.args.get('next') or '/')
    return render_template('login.html', form=form)
@app.route('/logout')
@login_required
def logout():
    # Eliminar la información del usuario de la sesión
    logout_user()
    # Eliminar las claves de sesión establecidas por Flask-Principal
    for key in ('identity.name', 'identity.auth_type'):
        session.pop(key, None)
    # Informar a Flask-Principal que el usuario es anónimo
    identity_changed.send(current_app._get_current_object(),
                          identity=AnonymousIdentity())
    return redirect(request.args.get('next') or '/')

PROVEEDORES DE INFORMACIÓN DEL USUARIO

Los proveedores de información del usuario deben conectarse a la señal identity-loaded para agregar cualquier información adicional a la instancia de Identidad, como roles. El siguiente es otro ejemplo hipotético que utiliza Flask-Login y podría combinarse con el ejemplo anterior. Muestra cómo se podría usar un esquema de permisos basado en roles:

from flask.ext.login import current_user
from flask.ext.principal import identity_loaded, RoleNeed, UserNeed
@identity_loaded.connect_via(app)
def on_identity_loaded(sender, identity):
    # Establecer el objeto de usuario de la identidad
    identity.user = current_user
    # Agregar la UserNeed a la identidad
    if hasattr(current_user, 'id'):
        identity.provides.add(UserNeed(current_user.id))
    # Suponiendo que el modelo User tiene una lista de roles, actualizar la
    # identidad con los roles que proporciona el usuario
    if hasattr(current_user, 'roles'):
        for role in current_user.roles:
            identity.provides.add(RoleNeed(role.name))

PROTEGIENDO ENDPOINTS

To protect an endpoint, you will want to create a Permission object, and then check for its existence before allowing access.

@app.route('/logout')
@principal.user_loader
def logout():
    # Log out the user and remove the identity from the session.
    return 'Logged out'

To protect an endpoint, you will want to create a Permission object, and then check for its existence before allowing access.

@app.route('/profile')
@principal.require_login
def profile():
    return render_template('profile.html')

To protect an endpoint, you will want to create a Permission object, and then check for its existence before allowing access.

@app.route('/dashboard')
@principal.require_permission('read_dashboard')
def dashboard():
    return render_template('dashboard.html')

This is the simplest way to protect endpoints. However, it is possible to protect endpoints that require specific information about the user.

For instance, if the user model has a list of posts the user has authored, add the needs to the identity

if hasattr(current_user, 'posts'):
    for post in current_user.posts:
        identity.provides.add(EditBlogPostNeed(unicode(post.id)))

The next step will be to protect the endpoint that allows a user to edit an article. This is done by creating a permission object on the fly using the ID of the resource, in this case the blog post:

@app.route('/posts/<post_id>', methods=['PUT', 'PATCH'])
def edit_post(post_id):
    permission = EditBlogPostPermission(post_id)
    if permission.can():
        # Save the edits ...
        return render_template('edit_post.html')
    abort(403)  # HTTP Forbidden

INICIANDO LA EXTENSIÓN

class flask_principal.Principal(app=None, use_sessions=True, skip_static=False)
Extensión Principal
Parámetros
  • app -- La aplicación flask a extender
  • use_sessions -- Si usar sesiones para extraer y almacenar identificación.
  • skip_static -- Si ignorar endpoints estáticos.
identity_loader(f)
Decorador para definir una función como cargador de identidad.

Una función cargadora de identidad se llama antes de la solicitud para encontrar cualquier identidad proporcionada. La primera identidad encontrada se usa para cargar.

Por ejemplo:

app = Flask(__name__)
principals = Principal(app)
@principals.identity_loader
def load_identity_from_weird_usecase():
    return Identity('ali')
identity_saver(f)
Decorador para definir una función como guardador de identidad.

Un guardador de identidad se llama cuando la identidad se establece para persistirla para la próxima solicitud.

Por ejemplo:

app = Flask(__name__)
principals = Principal(app)
@principals.identity_saver
def save_identity_to_weird_usecase(identity):
    my_special_cookie['identity'] = identity
set_identity(identity)
Establece la identidad actual.
Parámetros
identity -- La identidad a establecer

TIPOS PRINCIPALES

class flask_principal.Permission(*needs)
Representa necesidades, cualquiera de las cuales debe estar presente para acceder a un recurso
Parámetros
needs -- Las necesidades para este permiso
allows(identity)
Si la identidad puede acceder a este permiso.
Parámetros
identity -- La identidad
can()
Si el contexto requerido para este permiso tiene acceso

Esto crea un contexto de identidad y prueba si puede acceder a este permiso

difference(other)
Crea un nuevo permiso que consiste en los requisitos de este permiso y no en el otro.
issubset(other)
Si las necesidades de este permiso son un subconjunto de otro
Parámetros
other -- El otro permiso
require(http_exception=None)
Crea un principal para este permiso.

El principal puede ser utilizado como un gestor de contexto, o un decorador.

Si se pasa http_exception, se llamará a abort() con el código de excepción HTTP. De lo contrario, se lanzará una excepción PermissionDenied si la identidad no cumple los requisitos.

Parámetros
http_exception -- el código de excepción HTTP (403, 401 etc)
reverse()
Devuelve la inversa del estado actual (necesidades->exclusiones, exclusiones->necesidades)
test(http_exception=None)
Comprueba si el permiso está disponible y lanza la excepción relevante si no lo está. Esto es útil si solo quieres comprobar el permiso sin envolver todo en un bloque require().

Esto es equivalente a:

with permission.require():
    pass
union(other)
Crea un nuevo permiso con los requisitos de la unión de este y el otro.
Parámetros
other -- El otro permiso
class flask_principal.Identity(id, auth_type=None)
Representa la identidad del usuario.
Parámetros
  • id -- El id del usuario
  • auth_type -- El tipo de autenticación utilizado para confirmar la identidad del usuario.

La identidad se utiliza para representar la identidad del usuario en el sistema. Este objeto se crea al iniciar sesión, o al comienzo de la solicitud tal como se carga desde la sesión del usuario.

Una vez cargada, se envía a través de la señal identity-loaded, y debe poblarse con información adicional requerida.

Las necesidades que son proporcionadas por esta identidad deben añadirse al conjunto provides después de la carga.

can(permission)
Si la identidad tiene acceso al permiso.
Parámetros
permission -- El permiso para probar la provisión.
class flask_principal.AnonymousIdentity
Una identidad anónima
class flask_principal.IdentityContext(permission, http_exception=None)
El contexto de una identidad para un permiso.

Nota:

El principal es usualmente creado por la llamada al método flaskext.Permission.require para casos de uso normales.

El principal se comporta como un gestor de contexto o un decorador. Se comprueba si el permiso está disponible en la identidad, y si está disponible, el flujo continúa (gestor de contexto) o se ejecuta la función (decorador).

can()
Si la identidad tiene acceso al permiso
http_exception
El permiso de este principal
property identity
La identidad de este principal

TIPOS DE NECESIDADES PREDEFINIDOS

class flask_principal.Need(method, value)
Una necesidad requerida

Esto es solo una tupla nombrada, y prácticamente cualquier tupla servirá.

El atributo method puede usarse para buscar el elemento 0, y el atributo value puede usarse para buscar el elemento 1.

flask_principal.RoleNeed
alias de functools.partial(<class 'flask_principal.Need'>, 'role')
flask_principal.UserNeed
alias de functools.partial(<class 'flask_principal.Need'>, 'id')
class flask_principal.ItemNeed(method, value, type)
Una necesidad de ítem requerida

Una necesidad de ítem es solo una tupla nombrada, y prácticamente cualquier tupla servirá. Además de otras Necesidades, hay un tipo

e, por ejemplo, esto podría especificarse como:

ItemNeed('update', 27, 'posts')
('update', 27, 'posts') # o así

Y eso podría describir el permiso para actualizar una entrada de blog particular. En realidad, el desarrollador es libre de elegir la convención que tengan los permisos.

SEÑALES

identity_changed
Señal enviada cuando la identidad de una solicitud ha sido cambiada.
identity_loaded
Señal enviada cuando la identidad ha sido inicializada para una solicitud.
