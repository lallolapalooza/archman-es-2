readv(2) Manual de llamadas al sistema readv(2)

NOMBRE

readv, writev, preadv, pwritev, preadv2, pwritev2 - leer o escribir datos en múltiples búferes

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/uio.h>
ssize_t readv(int fd, const struct iovec *iov, int iovcnt);
ssize_t writev(int fd, const struct iovec *iov, int iovcnt);
ssize_t preadv(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t pwritev(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t preadv2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);
ssize_t pwritev2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

preadv(), pwritev():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE

DESCRIPCIÓN

La llamada al sistema readv() lee iovcnt búferes del archivo asociado con el descriptor de archivo fd en los búferes descritos por iov ("entrada dispersa").

La llamada al sistema writev() escribe iovcnt búferes de datos descritos por iov en el archivo asociado con el descriptor de archivo fd ("salida reunida").

El puntero iov apunta a un array de estructuras iovec, descritas en iovec(3type).

La llamada al sistema readv() funciona igual que read(2) excepto que se llenan múltiples búferes.

La llamada al sistema writev() funciona igual que write(2) excepto que se escriben múltiples búferes.

Los búferes se procesan en orden de array. Esto significa que readv() llena completamente iov[0] antes de proceder a iov[1], y así sucesivamente. (Si no hay suficientes datos, entonces no se llenarán todos los búferes apuntados por iov). De manera similar, writev() escribe el contenido completo de iov[0] antes de proceder a iov[1], y así sucesivamente.

Las transferencias de datos realizadas por readv() y writev() son atómicas: los datos escritos por writev() se escriben como un único bloque que no se mezcla con las escrituras de otros procesos; análogamente, se garantiza que readv() lee un bloque contiguo de datos del archivo, independientemente de las operaciones de lectura realizadas en otros hilos o procesos que tengan descriptores de archivo que se refieran a la misma descripción de archivo abierta (ver open(2)).

preadv() y pwritev()

La llamada al sistema preadv() combina la funcionalidad de readv() y pread(2). Realiza la misma tarea que readv(), pero añade un cuarto argumento, offset, que especifica la posición del archivo en la que se realizará la operación de entrada.

La llamada al sistema pwritev() combina la funcionalidad de writev() y pwrite(2). Realiza la misma tarea que writev(), pero añade un cuarto argumento, offset, que especifica la posición del archivo en la que se realizará la operación de salida.

La posición del archivo no se modifica por estas llamadas al sistema. El archivo al que se refiere fd debe ser capaz de buscar.

preadv2() y pwritev2()

Estas llamadas al sistema son similares a las llamadas preadv() y pwritev(), pero añaden un quinto argumento, flags, que modifica el comportamiento por llamada.

A diferencia de preadv() y pwritev(), si el argumento offset es -1, se utiliza la posición actual del archivo y se actualiza.

El argumento flags contiene una operación OR a nivel de bits de cero o más de las siguientes banderas:

RWF_DSYNC (desde Linux 4.7)
Proporciona un equivalente por escritura del flag open(2) O_DSYNC. Este flag solo tiene sentido para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema.
RWF_HIPRI (desde Linux 4.6)
Lectura/escritura de alta prioridad. Permite a los sistemas de archivos basados en bloques usar sondeo del dispositivo, lo que proporciona menor latencia, pero puede usar recursos adicionales. (Actualmente, esta funcionalidad solo es utilizable en un descriptor de archivo abierto con el flag O_DIRECT).
RWF_SYNC (desde Linux 4.7)
Proporciona un equivalente por escritura del flag open(2) O_SYNC. Este flag solo tiene sentido para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema.
RWF_NOWAIT (desde Linux 4.14)
No espere por datos que no estén disponibles inmediatamente. Si se especifica este flag, la llamada al sistema preadv2() retornará instantáneamente si tuviera que leer datos del almacenamiento subyacente o esperar un bloqueo. Si se leyeron algunos datos, devolverá el número de bytes leídos. Si no se leyeron bytes, devolverá -1 y establecerá errno a EAGAIN (pero ver BUGS). Actualmente, este flag solo tiene sentido para preadv2().
RWF_APPEND (desde Linux 4.16)
Proporciona un equivalente por escritura del flag open(2) O_APPEND. Este flag solo tiene sentido para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema. El argumento offset no afecta la operación de escritura; los datos siempre se añaden al final del archivo. Sin embargo, si el argumento offset es -1, se actualiza la posición actual del archivo.
RWF_NOAPPEND (desde Linux 6.9)
No honrar el flag open(2) O_APPEND. Este flag solo tiene sentido para pwritev2(). Históricamente, Linux honraba el flag O_APPEND si estaba configurado e ignoraba el argumento offset, lo cual es un error. Para pwritev2(), el argumento offset se honra como se espera si el flag RWF_NOAPPEND está configurado, lo mismo que si el flag O_APPEND no estuviera configurado.
RWF_ATOMIC (desde Linux 6.11)
Requiere que las escrituras en archivos regulares en sistemas de archivos basados en bloques se emitan con protección contra escritura partida. La protección contra escritura partida significa que, en caso de fallo de alimentación o de otro tipo de hardware, todos los datos de la escritura se almacenarán o ninguno, pero nunca una mezcla de datos antiguos y nuevos. Este flag solo tiene sentido para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema. La longitud total de escritura debe ser potencia de 2 y debe estar en el rango [stx_atomic_write_unit_min, stx_atomic_write_unit_max]. La escritura debe realizarse en una posición alineada de forma natural dentro del archivo con respecto a la longitud total de escritura. Por ejemplo, se permite una escritura de longitud 32KiB en una posición de archivo de 32KiB, pero no se permite una escritura de longitud 32KiB en una posición de archivo de 48KiB. El límite superior de iovcnt para pwritev2() se proporciona en el valor de stx_atomic_write_segments_max. La protección contra escritura partida solo funciona con el flag O_DIRECT, es decir, las escrituras en caché no son compatibles. Para garantizar la coherencia de la escritura entre el estado en memoria del archivo y el dispositivo de almacenamiento, se debe especificar O_SYNC o O_DSYNC para open(2). Las mismas garantías de E/S sincronizada descritas en open(2) se proporcionan cuando se utilizan estos flags o sus flags y llamadas al sistema equivalentes (por ejemplo, si se especifica RWF_SYNC para pwritev2()).
RWF_DONTCACHE (desde Linux 6.14)
No poner en caché.

Si se especifica tanto RWF_SYNC como RWF_DSYNC, se producirá un error con EINVAL.

Los flags RWF_APPEND y RWF_NOAPPEND no se pueden utilizar juntos, y su uso provocará un error con EINVAL.

VALOR DE RETORNO

En caso de éxito, estas llamadas al sistema devuelven el número de bytes leídos o escritos. Este número puede ser menor que el número solicitado debido al final del archivo (para lecturas) o a la cantidad de datos que se pueden escribir.

En caso de error, estas llamadas al sistema devuelven -1 y establecen errno para indicar el error.

ERRORES

Los errores son los mismos que los de read(2) y write(2), además de los siguientes:

EAGAIN
El descriptor de archivo está marcado como no bloqueante y la operación habría bloqueado.
EBADF
El descriptor de archivo fd no es válido o no está abierto para la operación solicitada.
EFBIG
El archivo es un archivo regular, offset + bytes a escribir es mayor que el tamaño máximo permitido del archivo.
EINTR
Se recibió una señal antes de que se completara la operación.
EINVAL
El argumento iovcnt es menor o igual que 0, o mayor que UIO_MAXIOV. O, el puntero iov es NULL. O, el puntero iov apunta a una estructura iovec que contiene un puntero NULL o un tamaño negativo. O, se especificaron flags inválidos o conflictivos (para preadv2()/pwritev2()).
ENOTSUP
El archivo no es un archivo regular y no soporta la búsqueda (para preadv()/pwritev()).
EOVERFLOW
El archivo es un archivo regular y el offset especificado estaba fuera del alcance del archivo.
POSIX_FADV_RANDOM
El descriptor de archivo está asociado con un archivo abierto con la bandera O_RANDOM (ver open(2)).
SEEK_DATA o SEEK_HOLE
El descriptor de archivo está asociado con un archivo abierto con la bandera O_SEARCH (ver open(2)).

CONFORMIDAD

Las llamadas readv() y writev() son parte de POSIX.1-2001 y posteriores. Las llamadas preadv() y pwritev() son parte de POSIX.1-2008 y posteriores. Las llamadas preadv2() y pwritev2() son específicas de Linux.

pwritev(2) — Linux manual pages

NAME

pwritev, pwritev2, writev - escribir datos en un buffer disperso en un conjunto de buffers

LIBRARY

Funciones de E/S de biblioteca estándar (funciones de E/S de biblioteca estándar), enlazando con -lc

SYNOPSIS

#include <sys/uio.h>

ssize_t writev(int fd, const struct iovec *iov, int iovcnt);
ssize_t pwritev(int fd, const struct iovec *iov, int iovcnt, off_t offset);
ssize_t pwritev2(int fd, const struct iovec *iov, int iovcnt, off_t offset, int flags);

DESCRIPTION

Las llamadas al sistema writev(), pwritev() y pwritev2() son similares a write(2) y pread(2), respectivamente, pero en lugar de transferir datos desde/hacia un único buffer, transfieren datos desde/hacia un array de buffers especificado por el argumento iov.

El argumento iov es un puntero a un array de estructuras iovec, cada una de las cuales especifica un buffer en el disco. La estructura iovec se define en <sys/uio.h> como:

struct iovec {
    void  *iov_base;    /* Puntero al buffer */
    size_t iov_len;     /* Número de bytes a transferir desde/hacia el buffer */
};

El argumento iovcnt especifica el número de estructuras iovec en el array iov.

writev() escribe iovcnt buffers de datos que comienzan en la dirección especificada por iov en el descriptor de archivo fd. La escritura se realiza secuencialmente desde cada buffer en el orden en que aparecen en el array iov.

pwritev() es idéntico a writev() excepto que realiza la escritura en la ubicación del archivo especificada por offset sin cambiar el puntero de archivo. Si offset es negativo, la operación falla con EINVAL.

pwritev2() es idéntico a pwritev() excepto que también acepta un argumento flags adicional que modifica el comportamiento de la llamada al sistema. Los siguientes valores de flags están definidos:

RWF_HIPRI
Aumenta la prioridad de la operación de E/S. Este flag se ignora actualmente en la mayoría de los sistemas de archivos.
RWF_DSYNC
Realiza una operación de escritura síncrona de datos y metadatos. Similar a llamar a fdatasync(2). Solo los datos y los metadatos requeridos para acceder a los datos escritos se escribirán físicamente en el almacenamiento. Para una operación de escritura atómica, use RWF_SYNC.
RWF_SYNC
Realiza una operación de escritura síncrona de datos y metadatos. Similar a llamar a fsync(2). Solo los datos y los metadatos requeridos para acceder a los datos escritos se escribirán físicamente en el almacenamiento. Para una operación de escritura atómica, use RWF_SYNC.
RWF_NOWAIT
Permite que la operación de E/S se ejecute en segundo plano. La llamada al sistema regresa inmediatamente. La operación de E/S real puede ser completada más tarde. Este flag puede ser usado para evitar bloquear el hilo que llama para operaciones de E/S largas. No se garantiza que la operación de E/S se complete después de que la llamada al sistema regresa.
RWF_APPEND
Abre el archivo en modo de anexión. Cada operación de escritura se realizará en la posición actual del archivo, independientemente del valor de offset. Este flag se introduce en Linux 5.1 y no se encuentra en otras plataformas.
RWF_DATASYNC
Similar a RWF_DSYNC, pero solo garantiza la sincronización de los datos. Los metadatos no se sincronizan necesariamente. Este flag se introduce en Linux 5.1 y no se encuentra en otras plataformas.
RWF_DIRECT
Realiza una operación de E/S directa. Esto significa que los datos se transfieren directamente entre el espacio de usuario y el dispositivo de almacenamiento, omitiendo la caché de páginas. Las escrituras con este flag también se comportan como si se hubiera especificado RWF_SYNC en términos de sincronización de datos y metadatos.
RWF_KEEP_PAGES
Si se especifica con una operación de lectura, esto evita que las páginas leídas se eliminen de la caché de páginas después de la operación. Para escrituras, esto evita que las páginas escritas se eliminen de la caché de páginas después de la operación.
RWF_DONTCACHE
Las operaciones de lectura o escritura en un archivo regular podarán el contenido instanciado de la caché de páginas cuando la operación se complete. Esto es diferente de la E/S normal en búfer, donde los datos normalmente permanecen en la caché hasta que se recuperan debido a la presión de memoria. Si los rangos de la E/S leída o escrita ya estaban en la caché antes de esta lectura o escritura, esos rangos no se podarán al completar la E/S.
Además, cualquier rango ennegrecido por una operación de escritura con RWF_DONTCACHE establecido se eliminará para escritura. Esto es similar a llamar a sync_file_range(2) con SYNC_FILE_RANGE_WRITE para iniciar la escritura en el rango dado. RWF_DONTCACHE es una pista, o mejor esfuerzo, donde no se dan garantías estrictas sobre el estado de la caché de páginas una vez que la operación se completa.
Si se utiliza en un sistema de archivos o dispositivo de bloques que no lo admite, devolverá -1 y errno se establecerá en EOPNOTSUPP.

RETURN VALUE

En caso de éxito, readv(), preadv() y preadv2() devuelven el número de bytes leídos; writev(), pwritev() y pwritev2() devuelven el número de bytes escritos.

Tenga en cuenta que no es un error que una llamada exitosa transfiera menos bytes de los solicitados (ver read(2) y write(2)).

En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORS

Los errores son los dados para read(2) y write(2). Además, preadv(), preadv2(), pwritev() y pwritev2() también pueden fallar por las mismas razones que lseek(2). Adicionalmente, se definen los siguientes errores:

EINVAL
La suma de los valores iov_len desborda un valor ssize_t.
EINVAL
Si se especifica RWF_ATOMIC, la combinación de la suma de los valores iov_len y el valor offset no cumple con las reglas de protección contra escrituras rasgadas de longitud y desplazamiento.
EINVAL
El recuento de vectores, iovcnt, es menor que cero o mayor que el máximo permitido. Si se especifica RWF_ATOMIC, este máximo se da por el valor stx_atomic_write_segments_max de statx.
EOPNOTSUPP
RWF_DONTCACHE se estableció en flags y el archivo no lo admite.
EOPNOTSUPP
Se especifica un flag desconocido en flags.

VERSIONS

Diferencias entre la biblioteca C y el kernel

Las llamadas al sistema preadv() y pwritev() en bruto tienen firmas de llamada que difieren ligeramente de las de las funciones de envoltura correspondientes de la biblioteca C de GNU que se muestran en el SINOPSIS. El argumento final, offset, se desempaqueta en las funciones de envoltura en dos argumentos en las llamadas al sistema:

unsigned long pos_l, unsigned long pos

Estos argumentos contienen, respectivamente, los 32 bits de orden bajo y de orden alto de offset.

Diferencias históricas entre la biblioteca C y el kernel

Para lidiar con el hecho de que IOV_MAX era tan bajo en versiones tempranas de Linux, las funciones de envoltura de glibc para readv() y writev() hicieron un trabajo adicional si detectaban que la llamada al sistema subyacente fallaba porque se excedía este límite. En el caso de readv(), la función de envoltura asignó un búfer temporal lo suficientemente grande para todos los elementos especificados por iov, pasó ese búfer en una llamada a read(2), copió datos del búfer a las ubicaciones especificadas por los campos iov_base de los elementos de iov y luego liberó el búfer. La función de envoltura para writev() realizó la tarea análoga utilizando un búfer temporal y una llamada a write(2).

La necesidad de este esfuerzo adicional en las funciones de envoltura de glibc desapareció con Linux 2.2 y posteriores. Sin embargo, glibc continuó proporcionando este comportamiento hasta glibc 2.10. A partir de glibc 2.9, las funciones de envoltura proporcionan este comportamiento solo si la biblioteca detecta que el sistema está ejecutando un kernel de Linux anterior a Linux 2.6.18 (una versión de kernel seleccionada arbitrariamente). Y desde glibc 2.20 (que requiere un mínimo de Linux 2.6.32), las funciones de envoltura de glibc simplemente invocan directamente las llamadas al sistema.

NOTES

POSIX.1 permite que una implementación establezca un límite en el número de elementos que se pueden pasar en iov. Una implementación puede anunciar su límite definiendo IOV_MAX en <limits.h> o en tiempo de ejecución a través del valor de retorno de sysconf(_SC_IOV_MAX). En los sistemas Linux modernos, el límite es 1024. En los días de Linux 2.0, este límite era 16.

BUGS

Linux 5.9 y Linux 5.10 tienen un error donde preadv2() con el flag RWF_NOWAIT puede devolver 0 incluso cuando no está al final del archivo.

EXAMPLES

El siguiente ejemplo de código demuestra el uso de writev():


char          *str0 = "hello ";
char          *str1 = "world\n";
ssize_t       nwritten;
struct iovec  iov[2];
iov[0].iov_base = str0;
iov[0].iov_len = strlen(str0);
iov[1].iov_base = str1;
iov[1].iov_len = strlen(str1);
nwritten = writev(STDOUT_FILENO, iov, 2);
