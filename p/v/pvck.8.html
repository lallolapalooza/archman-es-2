pvck — Comprueba metadatos en volúmenes físicos

DESCRIPCIÓN

pvck comprueba y repara metadatos LVM en PVs.

Opciones de volcado

headers
Imprime las cabeceras y estructuras de LVM en disco: label_header, pv_header, mda_header(s) y texto de metadatos. Se imprimen advertencias si algún valor es incorrecto. La label_header y la pv_header existen ambas en un sector de 512 bytes, usualmente el segundo sector del dispositivo. Una mda_header existe en un sector de 512 bytes en el desplazamiento de 4096 bytes. Una segunda mda_header puede existir opcionalmente cerca del final del dispositivo. El texto de metadatos existe en un área (aproximadamente 1MiB por defecto) inmediatamente después del sector mda_header. El texto de metadatos se comprueba pero no se imprime (ver otras opciones).

metadata
Imprime el texto de metadatos VG de LVM actual (o lo guarda en un archivo), usando las cabeceras para localizar la copia más reciente de los metadatos. Si las cabeceras están dañadas, es posible que los metadatos no se encuentren (ver metadata_search). Usa --settings "mda_num=2" para buscar en mda2 (la segunda mda al final del dispositivo, si se usa). El texto de metadatos se imprime en la salida estándar o se guarda en un archivo con --file.

metadata_all
Lista todas las versiones de metadatos VG encontradas en el área de metadatos, usando las cabeceras para localizar los metadatos. Copias completas de todos los metadatos se guardan en un archivo con la opción --file. Si las cabeceras están dañadas, es posible que los metadatos no se encuentren (ver metadata_search). Usa --settings "mda_num=2" como arriba. Usa -v para incluir descripciones y fechas al listar las versiones de metadatos.

metadata_search
Lista todas las versiones de metadatos VG encontradas en el área de metadatos, buscando ubicaciones comunes para que los metadatos puedan encontrarse si las cabeceras están dañadas. Copias completas de todos los metadatos se guardan en un archivo con la opción --file. Para guardar una versión específica de metadatos, usa --settings "metadata_offset=<desplazamiento>", donde el desplazamiento se toma de la lista de versiones encontradas. Usa -v para incluir descripciones y fechas al listar las versiones de metadatos.

metadata_area
Guarda toda el área de texto de metadatos en un archivo sin procesar.

Opciones de reparación

--repair
Repara cabeceras y metadatos en un PV. Utiliza un archivo de entrada de metadatos que fue extraído por --dump, o un archivo de copia de seguridad (de /etc/lvm/backup). Cuando sea posible, usa metadatos guardados por --dump de otro PV en el mismo VG (o de una segunda área de metadatos en el PV).

Hay casos en los que se necesita especificar el UUID del PV para el PV que se está reparando. Se especifica usando --settings "pv_uuid=<UUID>". En particular, si el nombre del dispositivo para el PV que se está reparando no coincide con el nombre del dispositivo anterior del PV, LVM podría no ser capaz de determinar el UUID correcto del PV. Cuando las cabeceras están dañadas en más de un PV en un VG, es importante que el usuario determine el UUID correcto del PV y lo especifique en --settings. De lo contrario, podría usarse un UUID de PV incorrecto si los nombres de dispositivo se han intercambiado desde la última vez que se escribieron los metadatos.

Si un PV no tiene áreas de metadatos y la pv_header está dañada, la reparación no sabrá que no debe crear áreas de metadatos durante la reparación. Por defecto, reparará los metadatos en mda1. Para reparar sin áreas de metadatos, usa --settings "mda_offset=0 mda_size=0".

Hay casos en los que la reparación debe ejecutarse en todos los PVs del VG (usando el mismo archivo de metadatos): si todos los PVs del VG están dañados, si se usa una versión antigua de metadatos, o si se usa un archivo de copia de seguridad en lugar de metadatos en bruto (obtenidos de pvck dump).

Usar --repair es equivalente a ejecutar --repairtype pv_header seguido de --repairtype metadata.

--repairtype pv_header
Repara el sector de cabecera, que contiene la pv_header y la label_header.

--repairtype metadata
Repara la mda_header y el texto de metadatos. Requiere que las cabeceras estén correctas (no dañadas o ya reparadas).

--repairtype label_header
Repara los campos de la label_header, dejando la pv_header (en el mismo sector) sin cambios. (normalmente se debería usar repairtype pv_header en su lugar).

Configuración

La opción --settings controla o anula ciertos comportamientos de volcado o reparación. Todos los valores de desplazamiento y tamaño en la configuración están en bytes (no se reconocen unidades). Estas configuraciones están sujetas a cambios.

mda_num=1|2
Selecciona qué área de metadatos se debe utilizar. Por defecto se utiliza la primera área de metadatos (1). mda1 siempre se encuentra en el desplazamiento de 4096. mda2, al final del dispositivo, a menudo no existe (no se crea por defecto). Si mda1 está borrada, mda2, si existe, a menudo todavía contendrá metadatos.

metadata_offset=bytes
Selecciona el texto de metadatos en este desplazamiento. Usar con metadata_search para imprimir/guardar una instancia de texto de metadatos.

mda_offset=bytes mda_size=bytes
Se refiere a una ubicación y tamaño de área de metadatos (mda). Un mda incluye una mda_header y un búfer circular de texto de metadatos. Establecer esto fuerza a metadata_search a buscar metadatos en el área dada en lugar de las ubicaciones estándar. Cuando se establece en cero con repair, indica que no deben existir áreas de metadatos.

mda2_offset=bytes mda2_size=bytes
Al reparar una pv_header, esto fuerza un desplazamiento y tamaño específicos para mda2 que deben registrarse en la pv_header.

pv_uuid=uuid
Especifica el UUID del PV del dispositivo que se está reparando. Cuando no se especifica, repair intentará determinar el UUID correcto del PV emparejando un nombre de dispositivo en los metadatos.

device_size=bytes
data_offset=bytes
Al reparar una pv_header, device_size, data_offset y pvid se pueden especificar directamente, en cuyo caso estos valores no se toman de un archivo de metadatos (de donde normalmente provienen), y el archivo de metadatos puede omitirse. data_offset es la ubicación de inicio del primer extent físico (datos), que sigue al área de metadatos.

NAME

pvck — Check and repair physical volume metadata

SYNOPSIS

pvck [-a | --available] [-b | --partial] [-f | --force] [-n | --noheadings] [-o <report file> | --reportfile <report file>] [-t <max> | --test <max>] [-v | --verbose] [-y | --yes] [PhysicalVolume···]

DESCRIPTION

The pvck command checks the metadata for the specified physical volume(s) (PVs) for consistency and can repair metadata corruption. It can check a PV or a list of PVs, or it can check all PVs found in the system.

If no PhysicalVolume arguments are given, pvck checks all physical volumes in the system which are not yet activated.

pvck is primarily used to check for errors and to fix common inconsistencies. It should not be used for regular PV management. Use commands like pvcreate, pvremove, pvresize, pvmove, etc., for that.

USAGE

pvck [-a | --available] [-b | --partial] [-f | --force] [-n | --noheadings] [-o <report file> | --reportfile <report file>] [-t <max> | --test <max>] [-v | --verbose] [-y | --yes] [PhysicalVolume···]

OPTIONS

See lvm(8) for common options.

-a
--available Check all physical volumes that are available but not yet activated. This is the default if no PhysicalVolume arguments are given.
-b
--partial Check all physical volumes that are available in partial provisioning state.
-f
--force Force. Try to fix errors even if it is risky.
-n
--noheadings Suppress the column and section headers in the output.
-o <report file>
--reportfile <report file> Redirect all report output to the specified file. The default is to print to standard output.
-t <max>
--test <max> Test mode. Report errors but do not attempt to correct them. The argument <max> is the maximum number of errors to report. This is not used by pvck.
-v
--verbose Enable verbose mode.
-y
--yes Assume yes to all questions. Without this option, pvck will prompt the user before making any changes.

VARIABLES

See lvm(8) for common options.

ENVIRONMENT VARIABLES

See lvm(8) for common options.

EXAMPLES

Check and repair metadata on physical volume /dev/sdb1:

pvck -y /dev/sdb1

Check all available physical volumes for metadata errors and report any found issues to stdout:

pvck
