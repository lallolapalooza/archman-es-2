PVCREATE(8) Manual del Administrador del Sistema PVCREATE(8)

NOMBRE

pvcreate — Inicializar volúmenes físicos para su uso por LVM

SINOPSIS

pvcreate argumentos_posicionales
[ argumentos_opcionales ]

DESCRIPCIÓN

pvcreate inicializa un Volumen Físico (PV) en un dispositivo para que el dispositivo sea reconocido como perteneciente a LVM. Esto permite que el PV se utilice en un Grupo de Volúmenes (VG). Se escribe una etiqueta de disco LVM en el dispositivo y se inicializan las áreas de metadatos de LVM. Un PV puede colocarse en un dispositivo o partición completa.

Utilice vgcreate(8) para crear un nuevo VG en el PV, o vgextend(8) para añadir el PV a un VG existente. Utilice pvremove(8) para eliminar la etiqueta de disco LVM del dispositivo.

La opción de forzar (`force`) creará un PV sin confirmación. Repetir la opción de forzar (-ff) creará forzosamente un PV, anulando las comprobaciones que normalmente lo impiden, por ejemplo, si el PV ya está en un VG.

Ubicación, tamaño y alineación de metadatos

La etiqueta de disco LVM comienza a 512 bytes del inicio del dispositivo, y tiene un tamaño de 512 bytes.

El área de metadatos de LVM comienza en un desplazamiento (desde el inicio del dispositivo) igual al tamaño de página de la máquina que crea el PV (a menudo 4 KiB). El área de metadatos contiene una cabecera de 512 bytes y un búfer circular de varios KiB que contiene copias de texto de los metadatos del VG.

Con la configuración predeterminada, la primera extensión física (PE), que contiene datos de LV, está a 1 MiB del inicio del dispositivo. Esta ubicación está controlada por default_data_alignment en lvm.conf, que está establecido en 1 (MiB) por defecto. El `pe_start` será un múltiplo de esta cantidad de MiB. Esta ubicación puede verificarse con:
pvs -o pe_start PV

El tamaño del área de metadatos de LVM es el espacio entre el inicio del área de metadatos y la primera PE. Cuando los metadatos comienzan a 4 KiB y la primera PE está a 1024 KiB, el tamaño del área de metadatos es 1020 KiB. Esto se puede verificar con:
pvs -o mda_size PV

El `mda_size` no se puede aumentar después de pvcreate, por lo que si se necesitan metadatos más grandes, deben configurarse durante pvcreate. Siempre deben caber dos copias de los metadatos del VG dentro del área de metadatos, por lo que el tamaño máximo de metadatos del VG es alrededor de la mitad del `mda_size`. Esto se puede verificar con:
vgs -o mda_free VG

Se puede establecer un área de metadatos más grande con --metadatasize. El `mda_size` resultante puede ser mayor que el especificado debido a que `default_data_alignment` coloca `pe_start` en un límite de MiB, y al hecho de que el área de metadatos se extiende hasta la primera PE. Con metadatos que comienzan en 4 KiB y `default_data_alignment` 1 (MiB), establecer --metadatasize 2048k da como resultado `pe_start` de 3 MiB y `mda_size` de 3068 KiB. Alternativamente, --metadatasize 2044k da como resultado `pe_start` en 2 MiB y `mda_size` de 2044 KiB.

La alineación de `pe_start` descrita anteriormente puede ser anulada automáticamente en función de las propiedades del dispositivo md o de las propiedades de E/S del dispositivo reportadas en sysfs. Estos ajustes automáticos se pueden habilitar/deshabilitar usando las configuraciones de lvm.conf `md_chunk_alignment` y `data_alignment_offset_detection`.

Para utilizar una alineación de `pe_start` diferente, utilice la opción --dataalignment. La opción --metadatasize también se usaría típicamente en este caso porque el tamaño del área de metadatos también determina la ubicación de `pe_start`. Al usar estas dos opciones juntas, `pe_start` se calcula como: inicio del área de metadatos (tamaño de página), más el --metadatasize especificado, redondeado al siguiente múltiplo de --dataalignment. Con metadatos que comienzan en 4 KiB, --metadatasize 2048k, y --dataalignment 128k, `pe_start` es 2176 KiB y `mda_size` es 2172 KiB. El `pe_start` de 2176 KiB es el múltiplo par más cercano de 128 KiB que proporciona al menos 2048 KiB de espacio de metadatos. Siempre verifique la alineación y el tamaño de metadatos resultantes al usar estas opciones.

Para desplazar un valor de `pe_start` alineado, use la opción --dataalignmentoffset. La alineación de `pe_start` se calcula como se describió anteriormente, y luego se suma el valor especificado con --dataalignmentoffset para producir el valor final de `pe_start`.

OPCIONES

--bootloaderareasize Tamaño[m|UNIDAD]
Reserva espacio para el cargador de arranque entre el área de metadatos de LVM y la primera PE. El área del cargador de arranque está reservada para que los cargadores de arranque incrusten sus propios datos o metadatos; LVM no la usará. El área del cargador de arranque comienza donde estaría ubicada la primera PE. La primera PE se desplaza por el tamaño del área del cargador de arranque, y luego se desplaza más si es necesario para que coincida con la alineación de los datos. El inicio del área del cargador de arranque siempre está alineado, ver también --dataalignment y --dataalignmentoffset. El área del cargador de arranque puede ser más grande de lo solicitado debido a la alineación, pero nunca es menor que el tamaño solicitado. Para ver el inicio y el tamaño del área del cargador de arranque de un PV existente, utilice pvs -o +pv_ba_start,pv_ba_size.
--commandprofile Cadena
El perfil de comando a utilizar para la configuración del comando. Consulte lvm.conf(5) para obtener más información sobre perfiles.
--config Cadena
Configuraciones para el comando. Estas anulan los ajustes de lvm.conf(5). El argumento Cadena utiliza el mismo formato que lvm.conf(5), o puede usar la sintaxis de sección/campo. Consulte lvm.conf(5) para obtener más información sobre la configuración.
--dataalignment Tamaño[k|UNIDAD]
Alinea el inicio de un área de datos de PV con un múltiplo de este número. Para ver la ubicación de la primera Extensión Física (PE) de un PV existente, utilice pvs -o +pe_start. Además, puede ser desplazado por un desplazamiento de alineación, consulte --dataalignmentoffset. Especifique también un tamaño de PE apropiado al crear un VG.
--dataalignmentoffset Tamaño[k|UNIDAD]
Desplaza el inicio del área de datos del PV por este desplazamiento adicional.
-d|--debug ...
Establece el nivel de depuración. Repita de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción se puede repetir, o acepta una lista de dispositivos separada por comas. Esto anula la configuración de dispositivos en lvm.conf.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

OPTIONS

--devicesfile String
Un archivo que lista los dispositivos que LVM debe utilizar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración de lvm.conf(5) devices/devicesfile y devices/use_devicesfile.
--driverloaded y|n
Si se establece en no, el comando no intentará utilizar device-mapper. Para pruebas y depuración.
-f|--force ...
Anula varias comprobaciones, confirmaciones y protecciones. Utilizar con extrema precaución.
-h|--help
Muestra el texto de ayuda.
--journal String
Registra información en el registro de systemd. Esta información es adicional a la información habilitada por la configuración de registro/registro de lvm.conf. comando: registra información sobre el comando. salida: registra la salida predeterminada del comando. depuración: registra la depuración completa del comando.
--labelsector Number
Por defecto, el PV se etiqueta con un identificador LVM2 en su segundo sector (sector 1). Esto le permite usar un sector diferente cerca del inicio del disco (entre 0 y 3 inclusive; consulte LABEL_SCAN_SECTORS en el código fuente). Úselo con cuidado.
--lockopt String
Se utiliza para pasar opciones para casos especiales a lvmlockd. Consulte lvmlockd(8) para más información.
--longhelp
Muestra el texto de ayuda detallado.
--metadataignore y|n
Especifica la propiedad metadataignore de un PV. Si es sí, se ignoran las áreas de metadatos en el PV, y lvm no almacenará metadatos en las áreas de metadatos del PV. Si es no, lvm almacenará metadatos en el PV.
--metadatasize Size[m|UNIT]
La cantidad aproximada de espacio utilizada para cada área de metadatos de VG. El tamaño puede ser redondeado.
-M|--metadatatype lvm2
Especifica el tipo de metadatos en disco a utilizar. lvm2 (o solo 2) es el formato actual y estándar. lvm1 (o solo 1) ya no se utiliza.
--nohints
No utilizar el archivo de pistas para localizar dispositivos para PVs. Un comando puede leer más dispositivos para encontrar PVs cuando no se usan pistas. El comando seguirá realizando la invalidación estándar del archivo de pistas cuando sea apropiado.
--nolocking
Deshabilita el bloqueo. Usar con precaución, los comandos concurrentes pueden producir resultados incorrectos.
--norestorefile
En conjunción con --uuid, esto permite especificar un uuid sin requerir además que se proporcione una copia de seguridad de los metadatos.
--profile String
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
--[pv]metadatacopies 0|1|2
El número de áreas de metadatos que se reservarán en un PV para almacenar metadatos de VG. Cuando es 2, se almacena una copia de los metadatos de VG al principio del PV y una segunda copia al final. Cuando es 1, se almacena una copia de los metadatos de VG al principio del PV. Cuando es 0, no se almacenan copias de los metadatos de VG en el PV dado. Esto puede ser útil en VGs que contienen muchos PVs (esto impone limitaciones a la capacidad de usar vgsplit más tarde).
-q|--quiet ...
Suprimir la salida y los mensajes de registro. Anula --debug y --verbose. Repetir una vez para suprimir también cualquier indicación con la respuesta 'no'.
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente por la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe va precedido del nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que es más compatible con el estándar JSON. Consulte lvmreport(7) para más información.
--restorefile String
En conjunción con --uuid, lee el archivo (producido por vgcfgbackup), extrae la ubicación y el tamaño de los datos en el PV, y asegura que los metadatos producidos por el programa sean consistentes con el contenido del archivo, es decir, las extensiones físicas estarán en el mismo lugar y no serán sobrescritas por nuevos metadatos. Esto proporciona un mecanismo para actualizar el formato de metadatos o para añadir/eliminar áreas de metadatos. Usar con cuidado.
--setphysicalvolumesize Size[m|UNIT]
Anula el tamaño detectado automáticamente del PV. Usar con cuidado, o antes de reducir el tamaño físico del dispositivo.
-t|--test
Ejecutar en modo de prueba. Los comandos no actualizarán los metadatos. Esto se implementa deshabilitando toda escritura de metadatos pero devolviendo éxito a la función que llama. Esto puede llevar a mensajes de error inusuales en operaciones de varias etapas si una herramienta depende de leer metadatos que cree que han cambiado pero no lo han hecho.
-u|--uuid String
Especifica un UUID para el dispositivo. Sin esta opción, se genera un UUID aleatorio. Esta opción es necesaria antes de restaurar una copia de seguridad de metadatos LVM en un dispositivo de reemplazo; consulte vgcfgrestore(8). Como tal, el uso de --restorefile es obligatorio a menos que se use --norestorefile. Todos los PV deben tener UUIDs únicos, y LVM evitará ciertas operaciones si se ven múltiples dispositivos con el mismo UUID. Consulte vgimportclone(8) para más información.
-v|--verbose ...
Establece el nivel de detalle. Repetir de 1 a 4 veces para aumentar el detalle de los mensajes enviados a stdout y stderr.
--version
Muestra información de la versión.
-y|--yes
No solicitar confirmación interactivamente sino asumir siempre la respuesta sí. Usar con extrema precaución. (Para un no automático, ver -qq.)
-Z|--zero y|n
Controla si se borran los primeros 4 sectores (2048 bytes) del dispositivo. Por defecto, se borran estos sectores a menos que se especifiquen uno o ambos de los siguientes: --restorefile o --uuid.

VARIABLES

PV
Nombre del Volumen Físico, una ruta de dispositivo bajo /dev. Para comandos que gestionan extensiones físicas, un argumento posicional PV generalmente acepta un sufijo que indica un rango (o múltiples rangos) de extensiones físicas (PEs). Cuando se omite la primera PE, se asume el inicio del dispositivo, y cuando se omite la última PE, se asume el final.
Rango de inicio y fin (inclusivo): PV[:PE-PE] ...
Rango de inicio y longitud (contando desde 0): PV[:PE+PE] ...
String
Consulte la descripción de la opción para obtener información sobre el contenido de la cadena.
Size[UNIT]
Tamaño es un número de entrada que acepta una unidad opcional. Las unidades de entrada siempre se tratan como valores base dos, independientemente de si están en mayúsculas o minúsculas, por ejemplo, 'k' y 'K' se refieren a 1024. La unidad de entrada predeterminada se especifica por letra, seguida de |UNIT. UNIT representa otras unidades de entrada posibles: b|B son bytes, s|S son sectores de 512 bytes, k|K son KiB, m|M son MiB, g|G son GiB, t|T son TiB, p|P son PiB, e|E son EiB. (Esto no debe confundirse con el control de salida --units, donde las letras mayúsculas significan múltiplos de 1000).

VARIABLES DE ENTORNO

Consulte lvm(8) para obtener información sobre las variables de entorno utilizadas por lvm. Por ejemplo, LVM_VG_NAME generalmente puede sustituir a un parámetro VG requerido.

EJEMPLOS

Inicializar una partición y un dispositivo completo.
pvcreate /dev/sdc4 /dev/sde

Si un dispositivo es una unidad de sector de 4 KiB que compensa el particionamiento de Windows (el sector 7 es el bloque lógico alineado más bajo, los sectores de 4 KiB comienzan en LBA -1, y en consecuencia el sector 63 está alineado en un límite de 4 KiB) tenga esto en cuenta manualmente al inicializar para su uso por LVM.
pvcreate --dataalignmentoffset 7s /dev/sdb

NAME

pvcreate — Create a new physical volume for use by LVM

SYNOPSIS

pvcreate [-f|--force] [-y|--yes] [-Z|--zero[|nozero]] [-u|--uuid PhysicalVolume] [-x|--restorefile Filename] [PhysicalVolumePath...]

pvcreate [-h|--help] [-M|--metadatatype type] [-m|--metacopy Number] [-k|--setphysicalvolumesize Size] [PhysicalVolumePath...]

pvcreate [-v|--verbose] [-d|--debug] [-f|--force] [-y|--yes] [-t|--test] [-h|--help] [--version]

DESCRIPTION

pvcreate is used to initialize a disk or a partition for use by Volume Manager. The tool scans the specified device for LVM2 metadata and, if none is found, it writes new LVM2 metadata to the beginning of the device.

The metadata area is used to store information about the Volume Group, Logical Volumes and Physical Volumes. It is important to ensure that the metadata area is not overwritten by any other application.

The metadata area size can be controlled using the pvcreate(8) command-line option --metadatatype. The default metadata area size is 2MiB.

If a device is already in use for LVM2, pvcreate will refuse to initialize it, unless the --force option is given.

If the --restorefile option is given, then pvcreate will attempt to restore metadata from the given file instead of writing new metadata.

USAGE

pvcreate initializes a new physical volume.

The device specified by PhysicalVolumePath is scanned for LVM2 metadata. If no metadata is found, new metadata is written to the device. The size of the metadata area is determined by the --metadatatype option. The default metadata area size is 2MiB.

If the device is already in use for LVM2, pvcreate will refuse to initialize it, unless the --force option is given.

The --restorefile option allows restoring metadata from a file.

OPTIONS

-f, --force
Force the initialization of the device even if it is already in use for LVM2.
-y, --yes
Do not prompt for confirmation before initializing the device.
-Z, --zero[|nozero]
Overwrite any existing data on the device with zeros. The default is to not overwrite existing data. The option nozero disables this behavior.
-u, --uuid PhysicalVolume
Generate a new UUID for the Physical Volume. If no UUID is given, a new one is generated.
-x, --restorefile Filename
Restore metadata from the given file. This option is useful for recovering from accidental metadata corruption.
-h, --help
Display a help message and exit.
-M, --metadatatype type
Set the metadata type. The available types are lvm-metadata(8).
-m, --metacopy Number
Set the number of metadata copies. The default is 1.
-k, --setphysicalvolumesize Size
Set the size of the physical volume. This is useful for creating physical volumes that are smaller than the actual device size. The size is specified in bytes with optional suffixes like k, m, g, t, p, e, z, y (for KiB, MiB, GiB, TiB, PiB, EiB, ZiB, YiB).
-v, --verbose
Enable verbose output.
-d, --debug
Enable debug output.
-t, --test
Perform a dry run with no changes made.
--version
Display version information and exit.

VARIABLES

This command does not use any LVM variables.

ENVIRONMENT VARIABLES

The following environment variables are respected by this command:

LVM_FORCE_METADATA_RESIZE
If set to 1, then pvcreate will attempt to resize the metadata area if it's too small. This can be useful if you are restoring metadata from an older LVM version.
LVM_METADATA_TYPE
Sets the default metadata type. If not set, then lvm-metadata(8) is used.
LVM_METADATA_COPY_COUNT
Sets the default number of metadata copies. If not set, then 1 is used.
LVM_RESTOREFILE
Sets the default restore file. If not set, then no restore file is used.

EXAMPLES

Initialize the device /dev/sda1 as a physical volume for LVM:

pvcreate /dev/sda1

Initialize the device /dev/sdb1 as a physical volume for LVM, forcing initialization even if it's already in use, and do not prompt for confirmation:

pvcreate --force --yes /dev/sdb1

Initialize the device /dev/sdc1 as a physical volume for LVM, restoring metadata from the file /etc/lvm/backup/vg0:

pvcreate --restorefile /etc/lvm/backup/vg0 /dev/sdc1
