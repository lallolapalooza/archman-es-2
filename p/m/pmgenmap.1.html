PMGENMAP(1) Manual de Comandos Generales PMGENMAP(1)

NOMBRE

pmgenmap - generar código C para simplificar el manejo de métricas de rendimiento

SINOPSIS

pmgenmap [archivo_entrada]

DESCRIPCIÓN

Dada una o más listas de nombres de métricas en archivo_entrada o en la entrada estándar, pmgenmap genera declaraciones C y macros de cpp(1) adecuadas para ser utilizadas en la Interfaz de Programación de Métricas de Rendimiento (PMAPI) en la salida estándar.

Las declaraciones producidas por pmgenmap simplifican la codificación para aplicaciones cliente que utilizan la PMAPI.

La entrada debe consistir en una o más listas de nombres de métricas de la forma:

nombrelista {
    nombremetrica1 nombresimbolico1
    nombremetrica2 nombresimbolico2
    ...
}

lo que generará declaraciones C y de cpp(1) de la forma:

char *nombrelista[] = {
#define nombresimbolico1 0
    "nombremetrica1",
#define nombresimbolico2 1
    "nombremetrica2",
    ...
};

Las declaraciones de matrices producidas son adecuadas como parámetros para pmLookupName(3) y las constantes definidas con #define pueden usarse para indexar los vsets en la estructura pmResult devuelta por una llamada a pmFetch(3).

Obviamente, nombrelista debe cumplir las reglas de nomenclatura de identificadores C, cada nombresimbolico debe cumplir las reglas de nomenclatura de macros de cpp(1), y se espera que cada nombremetrica sea un nombre de métricas de rendimiento válido (ver PMNS(5) para más detalles).

La entrada puede incluir líneas de comentarios estilo sh, es decir, con un `#' como primer carácter no en blanco de una línea, y estas se traducen en la salida a comentarios C de una o varias líneas al estilo K&R. Por ejemplo, la entrada:

# bloque inicial de comentarios multilínea
# grupo de inicialización
foo {
        a.b.c   UNO
        d.e.f.g DOS
        # bloque incrustado de
        # comentarios multilínea y texto de relleno aburrido
        xx.yy.zz        TRES
}
# comentario de una sola línea al final

Produce la siguiente salida:

/*
 * bloque inicial de comentarios multilínea
 * grupo de inicialización
 */
char *foo[] = {
#define UNO 0
        "a.b.c",
#define DOS 1
        "d.e.f.g",
/*
 * bloque incrustado de
 * comentarios multilínea y texto de relleno aburrido
 */
#define TRES 2
        "xx.yy.zz",
};
/* comentario de una sola línea al final */

EJEMPLOS

Por brevedad, hemos eliminado el código de manejo de errores y asumido que las métricas elegidas no tienen valores múltiples.

El archivo de entrada

misstats {
    kernel.percpu.cpu.idle     IDLE
    kernel.percpu.cpu.sys      SYS
    kernel.percpu.cpu.user     USER
    hinv.ncpu                       NCPU
}

produce el siguiente código C, adecuado para #include:

/*
 * Mapa del Espacio de Nombres de Métricas de Rendimiento
 * Construido por pmgenmap desde el archivo
 * mystats.metrics
 * el Mié 28 Dic 19:44:17 EST 1994
 *
 * ¡No edite este archivo!
 */
char *mystats[] = {
#define IDLE    0
        "kernel.percpu.cpu.idle",
#define SYS     1
        "kernel.percpu.cpu.sys",
#define USER    2
        "kernel.percpu.cpu.user",
#define NCPU    3
        "hinv.ncpu",
};

Usando el código generado por pmgenmap, ahora podemos obtener fácilmente métricas del Subsistema de Recolección de Métricas de Rendimiento (PMCS) de la siguiente manera:

#define MAX_PMID 4
    int         trip = 0;
    int         numpmid = sizeof(mystats)/sizeof(mystats[0]);
    double      duracion;
    pmResult    *resp;
    pmResult    *prev;
    pmID        pmidlist[MAX_PMID];
    pmNewContext(PM_CONTEXT_HOST, "localhost");
    pmLookupName(numpmid, mystats, pmidlist);
    pmFetch(numpmid, pmidlist, &resp);
    printf("%d CPUs: %d usr   %d sys   %d   idle0,
           resp->vset[NCPU]->vlist[0].value.lval,
           resp->vset[USER]->vlist[0].value.lval,
           resp->vset[SYS]->vlist[0].value.lval,
           resp->vset[IDLE]->vlist[0].value.lval);

Algunas llamadas para asegurar la portabilidad han sido eliminadas del código anterior por claridad; el ejemplo anterior no debe usarse como plantilla para programar. En particular, se usaron los valores crudos de las métricas cuando se debería haber llamado a pmLookupDesc(3) para determinar la semántica de cada métrica.

Ejemplos más completos que demuestran el uso de pmgenmap y que pueden usarse como base para el desarrollo de programas se incluyen en las demos de PCP, por ejemplo, $PCP_DEMOS_DIR/pmclient.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).
