DESCRIPCIÓN

pmDiscoverSetup y las funciones relacionadas son una parte integral de la biblioteca API libpcp_web, tal como se usa y se describe en pmwebapi(3), pmproxy(1), pmseries(1) y otros lugares. Estas funciones proporcionan un mecanismo asíncrono impulsado por eventos para descubrir automáticamente archivos PCP creados por pmlogger(1) y cualquier otra aplicación capaz de escribir archivos PCP. Esto incluye pmrep(1) y otras aplicaciones que utilizan la API LOGIMPORT(3) para importar datos de rendimiento en la infraestructura PCP y escribir archivos PCP.

Los servicios de la API pmDiscover descubren, monitorean y gestionan dinámicamente directorios de archivos PCP a medida que se crean, se escribe en ellos, se comprimen y eventualmente se eliminan. El ciclo de vida subyacente del archivo normalmente es gestionado por la infraestructura de gestión de archivos PCP (ver pmlogger_daily(1)). Los archivos descubiertos que están activos (actualmente en proceso de escritura) se "siguen" para extraer datos de rendimiento casi en vivo/tiempo real, que luego se pasan a través de callbacks registrados para su posterior procesamiento, por ejemplo, para agregar los datos a un servidor de clave-valor. Los archivos que están comprimidos o inactivos son rastreados/monitoreados pero **NO** se les hace "log-tailing" - esto es porque los archivos comprimidos nunca crecen y, por lo tanto, el "log-tailing" nunca descubriría datos nuevos. Consulte la opción --load en pmseries(1) para conocer un mecanismo compatible para ingerir archivos PCP previamente recopilados (inactivos), ya sean comprimidos o no, en un servidor de clave-valor.

Las rutinas de pmDiscover se pueden configurar para descubrir y monitorear automáticamente archivos PCP en uno o más directorios según lo especificado en el pmDiscoverModule, que se configura inicialmente llamando a pmDiscoverSetConfiguration para crear un module de tipo pmDiscoverModule, como se describe anteriormente. El module resultante se pasa luego a pmDiscoverSetup junto con una estructura inicializada de callbacks de tipo pmDiscoverCallBacks.

La configuración de un módulo de descubrimiento y callbacks normalmente declararía una instancia de pmDiscoverSettings, por ejemplo:

#include <pcp/pmwebapi.h>
static pmDiscoverSettings someapp_discover = {
    .callbacks.on_source        = pmSomeappDiscoverSource,
    .callbacks.on_closed        = pmSomeappDiscoverClosed,
    .callbacks.on_labels        = pmSomeappDiscoverLabels,
    .callbacks.on_metric        = pmSomeappDiscoverMetric,
    .callbacks.on_values        = pmSomeappDiscoverValues,
    .callbacks.on_indom         = pmSomeappDiscoverInDom,
    .callbacks.on_text          = pmSomeappDiscoverText,
    .module.on_info             = someapp_logging_function,
};

Y luego inicializar esto con llamadas API similares a las siguientes:

pmDiscoverSetEventLoop(&someapp_discover.module, myevents);
pmDiscoverSetConfiguration(&someapp_discover.module, myconfig);
pmDiscoverSetMetricRegistry(&someapp_discover.module, metric_registry);
pmDiscoverSetup(&someapp_discover.module, &someapp_discover.callbacks, &privatedata);

El código anterior debe implementar cada uno de los callbacks declarados, etc., para hacer lo que sea necesario con los datos pasados al callback. Los prototipos de estos callbacks se encuentran en el encabezado pmwebapi.h. Los callbacks se realizarán de forma asíncrona, a medida que se descubren o eliminan archivos y a medida que se escriben nuevos datos en los archivos de volumen y metadatos de archivo activos.

En el caso de pmproxy(1), se registran callbacks para capturar datos de rendimiento, que luego se envían a un servidor de clave-valor para consultas de series temporales rápidas y escalables por parte de los clientes de los servicios de la API REST PMWEBAPI(3). Dichos clientes incluyen la aplicación pmseries(1) y pmproxy(1), que es el servidor backend de la API REST para grafana-pcp, una fuente de datos nativa de grafana-server(1) para PCP.

DIAGNÓSTICOS

Generalmente cero en caso de éxito, o en caso de error un código de retorno negativo, ver pmerr(1).

ARCHIVOS

El directorio de archivos predeterminado es $PCP_ARCHIVE_DIR, que normalmente es /var/log/pcp/pmlogger. La API desciende recursivamente por todos los subdirectorios y también descubre dinámicamente cualquier nuevo directorio o archivo encontrado en ellos.
