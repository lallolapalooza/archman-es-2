rpc(3) Manual de funciones de biblioteca rpc(3)

NOMBRE

rpc - rutinas de biblioteca para llamadas a procedimientos remotos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS Y DESCRIPCIÓN

Estas rutinas permiten a programas C realizar llamadas a procedimientos en otras máquinas a través de la red. Primero, el cliente llama a un procedimiento para enviar un paquete de datos al servidor. Al recibir el paquete, el servidor llama a una rutina de despacho para realizar el servicio solicitado y luego envía una respuesta. Finalmente, la llamada al procedimiento retorna al cliente.

Para hacer uso de estas rutinas, incluya el archivo de cabecera <rpc/rpc.h>.

Los prototipos a continuación hacen uso de los siguientes tipos:

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Consulte los archivos de cabecera para ver las declaraciones de los tipos AUTH, CLIENT, SVCXPRT y XDR.

void auth_destroy(AUTH *auth);
Una macro que destruye la información de autenticación asociada con auth. La destrucción generalmente implica la desasignación de estructuras de datos privadas. El uso de auth no está definido después de llamar a auth_destroy().
AUTH *authnone_create(void);
Crea y devuelve un manejador de autenticación RPC que pasa información de autenticación no utilizable con cada llamada a procedimiento remoto. Esta es la autenticación predeterminada utilizada por RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crea y devuelve un manejador de autenticación RPC que contiene información de autenticación. El parámetro host es el nombre de la máquina en la que se creó la información; uid es el ID de usuario del usuario; gid es el ID de grupo actual del usuario; n y aup_gids se refieren a una matriz contada de grupos a los que pertenece el usuario. Es fácil hacerse pasar por un usuario.
AUTH *authunix_create_default(void);
Llama a authunix_create() con los parámetros apropiados.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Llama al procedimiento remoto asociado con prognum, versnum y procnum en la máquina host. El parámetro in es la dirección del(los) argumento(s) del procedimiento, y out es la dirección donde colocar el(los) resultado(s); inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento. Esta rutina devuelve cero si tiene éxito, o el valor de enum clnt_stat convertido a entero si falla. La rutina clnt_perrno() es útil para traducir estados de error a mensajes.
Advertencia: llamar a procedimientos remotos con esta rutina utiliza UDP/IP como transporte; consulte clntudp_create() para conocer las restricciones. No tiene control de tiempos de espera ni de autenticación utilizando esta rutina.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similar a callrpc(), excepto que el mensaje de llamada se transmite a todas las redes de difusión conectadas localmente. Cada vez que recibe una respuesta, esta rutina llama a eachresult(), cuya forma es:

eachresult(char *out, struct sockaddr_in *addr);

donde out es el mismo que out pasado a clnt_broadcast(), excepto que la salida del procedimiento remoto se decodifica allí; addr apunta a la dirección de la máquina que envió los resultados. Si eachresult() devuelve cero, clnt_broadcast() espera más respuestas; de lo contrario, retorna con el estado apropiado.
Advertencia: los sockets de difusión están limitados en tamaño a la unidad de transferencia máxima del enlace de datos. Para ethernet, este valor es 1500 bytes.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Una macro que llama al procedimiento remoto procnum asociado con el manejador del cliente, clnt, que se obtiene con una rutina de creación de cliente RPC como clnt_create(). El parámetro in es la dirección del(los) argumento(s) del procedimiento, y out es la dirección donde colocar el(los) resultado(s); inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento; tout es el tiempo permitido para que regresen los resultados.
clnt_destroy(CLIENT *clnt);
Una macro que destruye el manejador RPC del cliente. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluido el propio clnt. El uso de clnt no está definido después de llamar a clnt_destroy(). Si la biblioteca RPC abrió el socket asociado, también lo cerrará. De lo contrario, el socket permanecerá abierto.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Rutina genérica de creación de cliente. host identifica el nombre del host remoto donde se encuentra el servidor. proto indica qué tipo de protocolo de transporte usar. Los valores actualmente soportados para este campo son “udp” y “tcp”. Se establecen tiempos de espera predeterminados, pero se pueden modificar usando clnt_control().
Advertencia: usar UDP tiene sus inconvenientes. Dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede usar para procedimientos que aceptan argumentos grandes o devuelven resultados enormes.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Una macro utilizada para cambiar o recuperar diversa información sobre un objeto cliente. req indica el tipo de operación, y info es un puntero a la información. Tanto para UDP como para TCP, los valores soportados de req y sus tipos de argumento y lo que hacen son:

CLSET_TIMEOUT  struct timeval // establecer tiempo de espera total
CLGET_TIMEOUT  struct timeval // obtener tiempo de espera total

Nota: si establece el tiempo de espera usando clnt_control(), el parámetro de tiempo de espera pasado a clnt_call() será ignorado en todas las llamadas futuras.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtener dirección del servidor

Las siguientes operaciones son válidas solo para UDP:

CLSET_RETRY_TIMEOUT  struct timeval // establecer el tiempo de espera de reintento
CLGET_RETRY_TIMEOUT  struct timeval // obtener el tiempo de espera de reintento

El tiempo de espera de reintento es el tiempo que "UDP RPC" espera la respuesta del servidor antes de retransmitir la solicitud.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Una macro que libera cualquier dato asignado por el sistema RPC/XDR cuando decodificó los resultados de una llamada RPC. El parámetro out es la dirección de los resultados, y outproc es la rutina XDR que describe los resultados. Esta rutina devuelve uno si los resultados se liberaron correctamente y cero en caso contrario.

*errp);
Una macro que copia la estructura de error del manejador del cliente a la estructura en la dirección errp.
void clnt_pcreateerror(const char *s);
Imprime un mensaje en la salida de error estándar indicando por qué no se pudo crear un manejador RPC de cliente. El mensaje va precedido por la cadena s y dos puntos. Se utiliza cuando falla una llamada a clnt_create(), clntraw_create(), clnttcp_create() o clntudp_create().
void clnt_perrno(enum clnt_stat stat);
Imprime un mensaje en la salida de error estándar correspondiente a la condición indicada por stat. Se utiliza después de callrpc().
clnt_perror(CLIENT *clnt, const char *s);
Imprime un mensaje en la salida de error estándar indicando por qué falló una llamada RPC; clnt es el manejador utilizado para realizar la llamada. El mensaje va precedido por la cadena s y dos puntos. Se utiliza después de clnt_call().
char *clnt_spcreateerror(const char *s);
Al igual que clnt_pcreateerror(), excepto que devuelve una cadena en lugar de imprimir en la salida de error estándar.
Errores: devuelve un puntero a datos estáticos que se sobrescriben en cada llamada.
char *clnt_sperrno(enum clnt_stat stat);
Toma los mismos argumentos que clnt_perrno(), pero en lugar de enviar un mensaje a la salida de error estándar indicando por qué falló una llamada RPC, devuelve un puntero a una cadena que contiene el mensaje. La cadena termina con un salto de línea.
clnt_sperrno() se utiliza en lugar de clnt_perrno() si el programa no tiene una salida de error estándar (como es muy probable que no la tenga un programa que se ejecute como servidor), o si el programador no desea que el mensaje se imprima con printf(3), o si se desea un formato de mensaje diferente al que soporta clnt_perrno(). Nota: a diferencia de clnt_sperror() y clnt_spcreateerror(), clnt_sperrno() devuelve un puntero a datos estáticos, pero el resultado no se sobrescribirá en cada llamada.
char *clnt_sperror(CLIENT *rpch, const char *s);
Al igual que clnt_perror(), excepto que (al igual que clnt_sperrno()) devuelve una cadena en lugar de imprimir en la salida de error estándar.
Errores: devuelve un puntero a datos estáticos que se sobrescriben en cada llamada.
CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);
Esta rutina crea un cliente RPC de juguete para el programa remoto prognum, versión versnum. El transporte utilizado para pasar mensajes al servicio es en realidad un búfer dentro del espacio de direcciones del proceso, por lo que el servidor RPC correspondiente debería residir en el mismo espacio de direcciones; consulte svcraw_create(). Esto permite simular RPC y obtener sobrecargas RPC, como tiempos de ida y vuelta, sin ninguna intervención del kernel. Esta rutina devuelve NULL si falla.
CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza TCP/IP como transporte. El programa remoto se encuentra en la dirección de Internet *addr. Si addr->sin_port es cero, entonces se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio remoto portmap para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece sockp. Dado que RPC basado en TCP utiliza E/S con búfer, el usuario puede especificar el tamaño de los búferes de envío y recepción con los parámetros sendsz y recvsz; los valores cero eligen valores predeterminados adecuados. Esta rutina devuelve NULL si falla.
CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, entonces se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio remoto portmap para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de tiempo wait hasta que se recibe una respuesta o hasta que la llamada caduca. El tiempo total para que la llamada caduque lo especifica clnt_call().
Advertencia: dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede utilizar para procedimientos que aceptan argumentos grandes o devuelven resultados enormes.
CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);
Esta rutina crea un cliente RPC para el programa remoto prognum, en versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, entonces se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio remoto portmap para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de tiempo wait hasta que se recibe una respuesta o hasta que la llamada caduca. El tiempo total para que la llamada caduque lo especifica clnt_call().
Esto permite al usuario especificar el tamaño máximo del paquete para enviar y recibir mensajes RPC basados en UDP.
void get_myaddress(struct sockaddr_in *addr);
Rellena la dirección IP de la máquina en *addr, sin consultar las rutinas de la biblioteca que manejan /etc/hosts. El número de puerto siempre se establece en htons(PMAPPORT).
struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);
Una interfaz de usuario para el servicio portmap, que devuelve una lista de los mapeos actuales de programas RPC a puertos en el host ubicado en la dirección IP *addr. Esta rutina puede devolver NULL. El comando rpcinfo -p utiliza esta rutina.
unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);
Una interfaz de usuario para el servicio portmap, que devuelve el número de puerto en el que espera un servicio que admite el número de programa prognum, la versión versnum y habla el protocolo de transporte asociado con protocol. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Un valor de retorno de cero significa que el mapeo no existe o que el sistema RPC no pudo contactar al servicio remoto portmap. En este último caso, la variable global rpc_createerr contiene el estado RPC.
enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);
Una interfaz de usuario para el servicio portmap, que instruye a portmap en el host en la dirección IP *addr para realizar una llamada RPC en su nombre a un procedimiento en ese host. El parámetro *portp se modificará al número de puerto del programa si el procedimiento tiene éxito. Las definiciones de los otros parámetros se discuten en callrpc() y clnt_call(). Este procedimiento debe utilizarse para una llamada de "ping" y nada más. Véase también clnt_broadcast().
bool_t pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);
Una interfaz de usuario para el servicio portmap, que establece un mapeo entre el triple [prognum,versnum,protocol] y port en el servicio portmap de la máquina. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Esta rutina devuelve uno si tiene éxito, cero en caso contrario. Se realiza automáticamente por svc_register().
bool_t pmap_unset(unsigned long prognum, unsigned long versnum);
Una interfaz de usuario para el servicio portmap, que destruye todos los mapeos entre el triple [prognum,versnum,*] y puertos en el servicio portmap de la máquina. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.
int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);
Registra el procedimiento procname con el paquete de servicios RPC. Si llega una solicitud para el programa prognum, versión versnum y procedimiento procnum, se llama a procname con un puntero a sus parámetros; procname debe devolver un puntero a sus resultados estáticos; inproc se utiliza para decodificar los parámetros mientras que outproc se utiliza para codificar los resultados. Esta rutina devuelve cero si el registro tuvo éxito, -1 en caso contrario.
Advertencia: los procedimientos remotos registrados de esta forma se acceden utilizando el transporte UDP/IP RPC SERVICE INTERFACE The functions, variables, and structures described in this page are part of the Network-directed Remote Procedure Call (RPC) package. They allow a programmer to implement RPC services. The following are the public interfaces to the RPC service package. Data Structures struct rpc_createerr rpc_createerr; A global variable whose value is set by any RPC client creation routine that does not succeed. Use the routine clnt_pcreateerror() to print the reason why. fd_set svc_fdset; A global variable reflecting the RPC service side's read file descriptor bit mask; it is suitable as a parameter to the select(2) system call. This is of interest only if a service implementor does their own asynchronous event processing, instead of calling svc_run(). This variable is read-only (do not pass its address to select(2)!), yet it may change after calls to svc_getreqset() or any creation routines. int svc_fds; Similar to svc_fdset, but limited to 32 file descriptors. This interface is obsoleted by svc_fdset. struct sockaddr_in *svc_getcaller(SVCXPRT *xprt); The approved way of getting the network address of the caller of a procedure associated with the RPC service transport handle, xprt. Service Creation and Destruction SVCXPRT *svcfd_create(int fd, unsigned int sendsize, unsigned int recvsize); Create a service on top of any open file descriptor. Typically, this file descriptor is a connected socket for a stream protocol such as TCP. sendsize and recvsize indicate sizes for the send and receive buffers. If they are zero, a reasonable default is chosen. SVCXPRT *svcraw_create(void); This routine creates a toy RPC service transport, to which it returns a pointer. The transport is really a buffer within the process's address space, so the corresponding RPC client should live in the same address space; see clntraw_create(). This routine allows simulation of RPC and acquisition of RPC overheads (such as round trip times), without any kernel interference. This routine returns NULL if it fails. SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size, unsigned int recv_buf_size); This routine creates a TCP/IP-based RPC service transport, to which it returns a pointer. The transport is associated with the socket sock, which may be RPC_ANYSOCK, in which case a new socket is created. If the socket is not bound to a local TCP port, then this routine binds it to an arbitrary port. Upon completion, xprt->xp_sock is the transport's socket descriptor, and xprt->xp_port is the transport's port number. This routine returns NULL if it fails. Since TCP-based RPC uses buffered I/O, users may specify the size of buffers; values of zero choose suitable defaults. SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize, unsigned int recosize); This routine creates a UDP/IP-based RPC service transport, to which it returns a pointer. The transport is associated with the socket sock, which may be RPC_ANYSOCK, in which case a new socket is created. If the socket is not bound to a local UDP port, then this routine binds it to an arbitrary port. Upon completion, xprt->xp_sock is the transport's socket descriptor, and xprt->xp_port is the transport's port number. This routine returns NULL if it fails. This allows the user to specify the maximum packet size for sending and receiving UDP-based RPC messages. SVCXPRT *svcudp_create(int sock); This call is equivalent to svcudp_bufcreate(sock,SZ,SZ) for some default size SZ. void svc_destroy(SVCXPRT *xprt); A macro that destroys the RPC service transport handle, xprt. Destruction usually involves deallocation of private data structures, including xprt itself. Use of xprt is undefined after calling this routine. Service Dispatching bool_t svc_register(SVCXPRT *xprt, unsigned long prognum, unsigned long versnum, typeof(void (struct svc_req *, SVCXPRT *)) *dispatch, unsigned long protocol); Associates prognum and versnum with the service dispatch procedure, dispatch. If protocol is zero, the service is not registered with the portmap service. If protocol is nonzero, then a mapping of the triple [prognum,versnum,protocol] to xprt->xp_port is established with the local portmap service (generally protocol is zero, IPPROTO_UDP or IPPROTO_TCP). The procedure dispatch has the following form: dispatch(struct svc_req *request, SVCXPRT *xprt); The svc_register() routine returns one if it succeeds, and zero otherwise. void svc_unregister(unsigned long prognum, unsigned long versnum); Remove all mapping of the double [prognum,versnum] to dispatch routines, and of the triple [prognum,versnum,*] to port number. void svc_run(void); This routine never returns. It waits for RPC requests to arrive, and calls the appropriate service procedure using svc_getreq() when one arrives. This procedure is usually waiting for a select(2) system call to return. void svc_getreqset(fd_set *rdfds); This routine is of interest only if a service implementor does not call svc_run(), but instead implements custom asynchronous event processing. It is called when the select(2) system call has determined that an RPC request has arrived on some RPC socket(s); rdfds is the resultant read file descriptor bit mask. The routine returns when all sockets associated with the value of rdfds have been serviced. void svc_getreq(int rdfds); Similar to svc_getreqset(), but limited to 32 file descriptors. This interface is obsoleted by svc_getreqset(). Argument and Reply Handling svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in); A macro that decodes the arguments of an RPC request associated with the RPC service transport handle, xprt. The parameter in is the address where the arguments will be placed; inproc is the XDR routine used to decode the arguments. This routine returns one if decoding succeeds, and zero otherwise. svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in); A macro that frees any data allocated by the RPC/XDR system when it decoded the arguments to a service procedure using svc_getargs(). This routine returns 1 if the results were successfully freed, and zero otherwise. bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out); Called by an RPC service's dispatch routine to send the results of a remote procedure call. The parameter xprt is the request's associated transport handle; outproc is the XDR routine which is used to encode the results; and out is the address of the results. This routine returns one if it succeeds, zero otherwise. Error Handling void svcerr_auth(SVCXPRT *xprt, enum auth_stat why); Called by a service dispatch routine that refuses to perform a remote procedure call due to an authentication error. void svcerr_decode(SVCXPRT *xprt); Called by a service dispatch routine that cannot successfully decode its parameters. See also svc_getargs(). void svcerr_noproc(SVCXPRT *xprt); Called by a service dispatch routine that does not implement the procedure number that the caller requests. void svcerr_noprog(SVCXPRT *xprt); Called when the desired program is not registered with the RPC package. Service implementors usually do not need this routine. void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers, unsigned long high_vers); Called when the desired version of a program is not registered with the RPC package. Service implementors usually do not need this routine. void svcerr_systemerr(SVCXPRT *xprt); Called by a service dispatch routine when it detects a system error not covered by any particular protocol. For example, if a service can no longer allocate storage, it may call this routine. void svcerr_weakauth(SVCXPRT *xprt); Called by a service dispatch routine that refuses to perform a remote procedure call due to insufficient authentication parameters. The routine calls svcerr_auth(xprt, AUTH_TOOWEAK). XDR Utility Routines bool_t xdr_accepted_reply(XDR *xdrs, struct accepted_reply *ar); Used for encoding RPC reply messages. This routine is useful for users who wish to generate RPC-style messages without using the RPC package. bool_t xdr_authunix_parms(XDR *xdrs, struct authunix_parms *aupp); Used for describing UNIX credentials. This routine is useful for users who wish to generate these credentials without using the RPC authentication package. void xdr_callhdr(XDR *xdrs, struct rpc_msg *chdr); Used for describing RPC call header messages. This routine is useful for users who wish to generate RPC-style messages without using the RPC package. bool_t xdr_callmsg(XDR *xdrs Used for describing RPC call messages.

SYNOPSIS AND DESCRIPTION

bool_t xdr_accepted_reply(XDR *xdrs, struct rpc_msg *cmsg);
Se utiliza para describir mensajes de respuesta de llamada RPC. Esta rutina es útil para los usuarios que desean generar mensajes de estilo RPC sin usar el paquete RPC.
bool_t xdr_authunix_parms(XDR *xdrs, struct authunix_parms *aup);
Se utiliza para describir parámetros de autenticación de UNIX RPC. Esta rutina es útil para los usuarios que desean generar mensajes de estilo RPC sin usar el paquete RPC.
bool_t xdr_callhdr(XDR *xdrs, struct rpc_msg *cmsg);
Se utiliza para describir encabezados de mensajes de llamada RPC. Esta rutina es útil para los usuarios que desean generar mensajes de estilo RPC sin usar el paquete RPC.
bool_t xdr_callmsg(XDR *xdrs, struct rpc_msg *cmsg);
Se utiliza para describir mensajes de llamada RPC. Esta rutina es útil para los usuarios que desean generar mensajes de estilo RPC sin usar el paquete RPC.
bool_t xdr_opaque_auth(XDR *xdrs, struct opaque_auth *ap);
Se utiliza para describir mensajes de información de autenticación RPC. Esta rutina es útil para los usuarios que desean generar mensajes de estilo RPC sin usar el paquete RPC.
bool_t xdr_pmap(XDR *xdrs, struct pmap *regs);
Se utiliza para describir parámetros de varios procedimientos de portmap, externamente. Esta rutina es útil para los usuarios que desean generar estos parámetros sin usar la interfaz pmap.
bool_t xdr_pmaplist(XDR *xdrs, struct pmaplist **rp);

Se utiliza para describir mensajes de respuesta RPC. Esta rutina es útil para los usuarios que desean generar mensajes de estilo RPC sin usar el paquete RPC.
void xprt_register(SVCXPRT *xprt);
Después de crear los manejadores de transporte de servicios RPC, deben registrarse en el paquete de servicios RPC. Esta rutina modifica la variable global svc_fds. Los implementadores de servicios generalmente no necesitan esta rutina.
void xprt_unregister(SVCXPRT *xprt);
Antes de destruir un manejador de transporte de servicios RPC, debe darse de baja en el paquete de servicios RPC. Esta rutina modifica la variable global svc_fds. Los implementadores de servicios generalmente no necesitan esta rutina.
