PMRECORD(3) Manual de funciones de biblioteca PMRECORD(3)

NOMBRE

pmRecordSetup, pmRecordAddHost, pmRecordControl - soporte para modo de grabación para clientes PMAPI

SINOPSIS

#include <pcp/pmafm.h>

FILE *pmRecordSetup(const char *folio,
const char *creator, int replay);

int pmRecordAddHost(const char *host,
int isdefault, pmRecordHost **rhp);

int pmRecordControl(pmRecordHost *rhp,
int request, const char *options);

cc ... -lpcp_gui

DESCRIPCIÓN

Estas rutinas pueden ser utilizadas para crear un archivo de Performance Co-Pilot (PCP) "sobre la marcha" para dar soporte a servicios de "modo de grabación" para aplicaciones cliente PMAPI.

Cada "sesión" de modo de grabación involucra uno o más archivos PCP, cada uno creado utilizando un proceso dedicado de pmlogger(1), con un formato general de Folio de Archivo como lo entiende pmafm(1), para nombrar y recolectar todos los archivos asociados con una única sesión de grabación.

La estructura pmRecordHost se utiliza para mantener información de estado entre el creador de la sesión de grabación y el(los) proceso(s) pmlogger asociado(s). La estructura se define como:

typedef struct {
    FILE   *f_config;    /* el llamador escribe la configuración de pmlogger aquí */
    int    fd_ipc;       /* canal IPC a pmlogger */
    char   *logfile;     /* nombre de ruta completo para el archivo de registro de errores de pmlogger */
    pid_t  pid;          /* id de proceso para pmlogger */
    int    status;       /* estado de salida, -1 si es desconocido */
} pmRecordHost;

Las rutinas se utilizan en combinación para crear una sesión de grabación de la siguiente manera.

1.
Llamar a pmRecordSetup para establecer una nueva sesión de grabación. Se creará un nuevo Folio de Archivo utilizando el nombre folio; si el archivo o directorio folio ya existe, o si el archivo folio no puede ser creado, esto es un error. La aplicación que está creando la sesión se identifica mediante creator (lo más probable es que sea el mismo que el nombre global de la aplicación PMAPI, tal como lo devuelve pmGetProgname(3)). Si la aplicación sabe cómo crear su propio archivo de configuración para reproducir la sesión grabada, entonces replay debe ser distinto de cero.

pmRecordSetup devuelve un flujo stdio al cual la aplicación debe escribir el texto del archivo de configuración de reproducción requerido, si lo hay.

2.
Para cada host que se incluirá en la sesión de grabación, llame a pmRecordAddHost. Se devuelve una nueva estructura pmRecordHost a través de rhp. Se asume que pmcd(1) se está ejecutando en host, ya que así es como pmlogger(1) obtendrá las métricas de rendimiento requeridas.

Si este host es el host por defecto para esta sesión de grabación, entonces isdefault debe ser distinto de cero. Esto asegurará que el archivo correspondiente aparezca primero en el folio de archivos de PCP, y por lo tanto, las herramientas utilizadas para reproducir el folio de archivos tomarán la determinación correcta del archivo asociado con el host por defecto. Como máximo un host por sesión de grabación puede ser nominado como host por defecto.

La aplicación que llama debe escribir la configuración deseada de pmlogger en el flujo stdio devuelto a través del campo f_config en la estructura pmRecordHost.

3.
Opcionalmente, agregue argumentos a la línea de comandos que se utilizarán para lanzar pmlogger(1) llamando a pmRecordControl con una request de PM_REC_SETARG. El argumento se pasa a través de options y se requiere una llamada a pmRecordControl por cada argumento distinto.

Se puede agregar un argumento para una instancia particular de pmlogger identificada por rhp, o si el argumento rhp es NULL, el argumento se agrega para todas las instancias de pmlogger que se lanzarán en la sesión de grabación actual.

Independientemente de cualquier llamada a pmRecordControl con una request de PM_REC_SETARG, cada instancia de pmlogger se lanzará automáticamente con los siguientes argumentos: -c, -h, -l, -x y el nombre base para el archivo PCP.

4.
Para iniciar la sesión de grabación, llame a pmRecordControl con una request de PM_REC_ON, y rhp debe ser NULL. Esto lanzará un proceso pmlogger(1) por cada host en la sesión de grabación, e inicializará los campos fd_ipc, logfile, pid y status en la(s) estructura(s) pmRecordHost asociada(s).
5.
Para terminar una instancia de pmlogger identificada por rhp, llame a pmRecordControl con una request de PM_REC_OFF. Si el argumento rhp a pmRecordControl es NULL, la solicitud de terminación se difunde a todos los procesos pmlogger en la sesión de grabación actual.

Un diálogo informativo es generado directamente por cada proceso pmlogger y por lo tanto, tenga en cuenta los comentarios sobre la disposición de la salida de pmlogger a continuación.

Alternativamente, pmlogger puede iniciarse con opciones para limitar la duración del registro, por ejemplo, los argumentos -T o -s, en cuyo caso no es necesario llamar a pmRecordControl con una request de PM_REC_OFF y no se genera ningún diálogo.

6.
Para mostrar el estado actual de la instancia de pmlogger identificada por rhp, llame a pmRecordControl con una request de PM_REC_STATUS. Si el argumento rhp a pmRecordControl es NULL, la solicitud de estado se difunde a todos los procesos pmlogger en la sesión de grabación actual.

La visualización es generada directamente por cada proceso pmlogger y por lo tanto, tenga en cuenta los comentarios sobre la disposición de la salida de pmlogger a continuación.

7.
Para desvincular una instancia de pmlogger identificada por rhp y permitirle continuar independientemente de la aplicación que lanzó la sesión de grabación, llame a pmRecordControl con una request de PM_REC_DETACH. Si el argumento rhp a pmRecordControl es NULL, la solicitud de desvinculación se difunde a todos los procesos pmlogger en la sesión de grabación actual.

Un diálogo informativo es generado directamente por cada proceso pmlogger y por lo tanto, tenga en cuenta los comentarios sobre la disposición de la salida de pmlogger a continuación.

La aplicación que llama no debe cerrar ninguno de los flujos stdio devueltos; esto será hecho por pmRecordControl cuando se inicie la grabación.

Una vez que se haya iniciado pmlogger para una sesión de grabación, pmlogger asumirá la responsabilidad de cualquier diálogo con el usuario en caso de que la aplicación que lanzó la sesión de grabación salga, particularmente sin terminar la sesión de grabación.

Por defecto, la información y los diálogos de pmlogger se mostrarán utilizando pmquery(1) asumiendo que la mayoría de las aplicaciones que desean lanzar una sesión de grabación se basan en GUI. En caso de que pmquery no logre mostrar la información (por ejemplo, porque la variable de entorno DISPLAY no está configurada), pmlogger escribirá en su propio flujo stderr (no en el flujo stderr del proceso lanzador); la salida se asignará al archivo XXXXXX.host.log descrito en la sección ARCHIVOS a continuación. Para mayor comodidad, el nombre de ruta completo a este archivo se proporciona a través del campo logfile en la estructura pmRecordHost.

Si el argumento options a pmRecordControl no es NULL, esta cadena puede usarse para pasar argumentos adicionales a pmquery(1) en aquellos casos en que se vaya a mostrar un diálogo. Un uso de esta capacidad sería proporcionar una cadena -geometry para controlar la colocación del diálogo.

La terminación prematura de un proceso pmlogger lanzado puede determinarse utilizando la estructura pmRecordHost, llamando a select(2) en el campo fd_ipc o sondeando el campo status que contendrá el estado de terminación de waitpid(2) si se conoce, de lo contrario -1.

See also pmlogger(1).

DIAGNÓSTICOS

pmRecordSetup puede devolver NULL en caso de error. Compruebe errno para conocer la causa real, pero el valor EINVAL típicamente indica que el orden de las llamadas a estas rutinas no es correcto (hay un estado obvio asociado con la sesión de grabación actual que se mantiene a través de las llamadas a estas rutinas). Por ejemplo, las siguientes llamadas producirían este error EINVAL: llamar a pmRecordControl antes de llamar a pmRecordAddHost al menos una vez, o llamar a pmRecordAddHost antes de llamar a pmRecordSetup.

pmRecordControl y pmRecordAddHost devuelven 0 si tienen éxito, de lo contrario, un valor menor que 0 adecuado para ser decodificado con pmErrStr(3) en caso de fallo. El valor -EINVAL tiene la misma interpretación que si errno se estableciera en EINVAL como se describe anteriormente.

pmRecordControl devolverá PM_ERR_IPC si el proceso asociado pmlogger ya ha terminado.

ARCHIVOS

Estas rutinas crean una serie de archivos en el mismo directorio que el archivo folio especificado en la llamada a pmRecordSetup. En todos los casos, el componente ``XXXXXX'' es el resultado de llamar a mktemp(3).

XXXXXX
Si replay no es cero, este es el archivo de configuración de repetición del creador; de lo contrario, un archivo de control vacío, utilizado para garantizar la unicidad.
folio
El Folio de Archivo PCP, adecuado para su uso con pmafm(1).
XXXXXX.host.config
La configuración de pmlogger(1) para cada host; si el mismo host se utiliza en diferentes llamadas a pmRecordAddHost dentro de la misma sesión de grabación, entonces una de las letras ``a'' a ``z'' se añadirá a la parte ``XXXXXX'' de todos los nombres de archivo asociados para asegurar la unicidad.
XXXXXX.host.log
stdout y stderr para la instancia de pmlogger(1) para cada host.
XXXXXX.host.{0,meta,index}
Los archivos que componen un único archivo PCP para cada host.
