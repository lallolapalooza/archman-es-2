PMIECTL(1) Manual de Comandos Generales PMIECTL(1)

NOMBRE

pmiectl - gestionar y controlar motores de inferencia de Performance Co-Pilot

SINOPSIS

pmiectl [-afmNV?] [-C check_args] [-c clase] [-i ident] [-p política] comando [host ...]

DESCRIPCIÓN

pmiectl puede ser usado para gestionar instancias no primarias del motor de inferencia Performance Co-Pilot (PCP) pmie(1). Esto sería más relevante en una ``granja'' de motores de inferencia PCP donde muchas instancias de pmie(1) estarían evaluando reglas contra los datos de rendimiento recolectados de pmcd(1) en muchos hosts remotos.

La instancia primaria de pmie(1) está estrechamente vinculada al proceso local pmcd(1) y como consecuencia comparte la misma infraestructura de control, es decir, systemd(1) o los ``scripts rc'' de inicio de PCP init(1). Es por esto que la instancia primaria de pmie(1) no puede ser gestionada con pmiectl.

Para brevedad en la descripción a continuación, el término ``instancia'' significa una instancia de pmie(1).

Todas las instancias gestionadas por pmiectl, pmie_check(1) y pmie_daily(1) se adhieren a las siguientes reglas:

1.
Cada instancia obtiene datos de rendimiento de un único pmcd(1) (es decir, un host), pero cada pmcd(1) puede estar proporcionando datos de rendimiento a cero, una o más instancias de pmie(1) ejecutándose en uno o más hosts.
2.
En el host local, cada instancia de pmie(1) debe especificarse una vez en un archivo de control de pmie_check(1) y pmie(1) crea un archivo de registro único, nombrado en el 4º parámetro de la entrada del archivo de control asociado (ver la sección CONFIGURACIÓN de pmie_check(1)).
3.
Cada instancia pertenece exactamente a una clase, opcionalmente nombrada usando una asignación $clase=... en el archivo de control asociado. La clase especial predeterminada está reservada para todas las instancias que no tienen una asignación asociada de $clase=.... Para fines de informes (consultar el comando resumen abajo), la instancia primaria de pmie(1) se asigna automáticamente a la clase especial primaria.

Cada ejecución de pmiectl gestiona una o más instancias actualizando los archivos de control asociados y luego ejecutando pmie_check(1) para efectuar el cambio deseado.

Los argumentos host son usualmente nombres de host válidos. Para todos los comandos excepto crear y cond-crear (descritos abajo) los argumentos host también pueden ser expresiones regulares de egrep(1) que coincidan con la totalidad de un nombre de host válido, por lo que el patrón utilizado es en realidad ^host$. Por ejemplo foo.* (coincide con todos los nombres de host que comienzan con ``foo'') o .*foo (coincide con todos los nombres de host que terminan con ``foo'') o .*[fF][oO][oO].* (coincide con todos los nombres de host que contienen ``foo'' en mayúsculas, minúsculas o mixtas).

La combinación de una clase de la opción opcional -c (o predeterminada) y los argumentos host para cada comando identifica un objetivo de conjunto de instancias a las cuales se debe aplicar la operación del comando.

La opción -i puede ser usada con los comandos crear o cond-crear para anular la identidad de la instancia que se especifica en la sección ident del archivo de política de clase (ver la sección ARCHIVO DE POLÍTICA DE CLASE abajo). Dado que el identificador debe ser único entre todas las instancias y todas las clases, solo tiene sentido usar esta opción cuando hay un único argumento host.

Dadas las tareas que pmiectl realiza, normalmente debe ser ejecutado como ``root'', las excepciones son el comando estado o cuando se especifica la opción -N.

COMANDOS

comando es uno de los siguientes:

comprobar
Verifica el estado de todas las instancias de pmie configuradas actualmente y reinicia cualquiera que haya fallado. Si se proporciona el indicador -m en plataformas systemd(1), también migra los procesos que coinciden (y los nuevos) al servicio pmie_farm.
crear
Crea nuevas instancias en la clase nombre_clase (predeterminado por defecto) para los hosts host. El nombre de la clase se usa para identificar un archivo de política de clase (ver la sección ARCHIVO DE POLÍTICA DE CLASE abajo) que proporciona una plantilla para cada nuevo archivo de control con %h reemplazado por host y %i reemplazado por el identificador (único) de la instancia de la sección ident del archivo de política de clase o ident de la opción -i.

La opción -p puede ser utilizada para identificar un archivo de política de clase distinto del que se encuentra en la ubicación estándar, es decir, $PCP_SYSCONF_DIR/pmie/class.d/nombre_clase.

Se debe especificar al menos un host para el comando crear.

cond-crear
Similar a crear pero la instancia solo se creará si una de las condiciones en la sección de creación de los archivos de política de clase asociados se evalúa como verdadera.

Si se especifica una opción -c, entonces solo se considerará la clase nombre_clase, de lo contrario se considerarán todas las clases. En este último caso, si ninguna de las condiciones en alguna de las clases se evalúa como verdadera, se utiliza la clase especial pmfind (esta es la clase ``predeterminada'' para el comando cond-crear cuando todo lo demás falla).

Si más de una clase se evalúa como verdadera, se crea un archivo de configuración de pmie(1) compuesto y la instancia también se asigna a la clase especial pmfind. El archivo de configuración compuesto puede contener una mezcla de cláusulas de configuración explícitas y cláusulas de configuración condicionales más generales según lo entiende la herramienta pmieconf(1).

iniciar
Inicia el conjunto de instancias objetivo.

Si el conjunto objetivo contiene intencionalmente más de una instancia, entonces se debe usar la opción -a (esto está diseñado para reducir el riesgo de iniciar accidentalmente un número potencialmente grande de procesos pmie(1)).

Si una instancia en el conjunto objetivo ya está iniciada, no se realiza ningún cambio (ver el comando reiniciar para forzar el lanzamiento de nuevas instancias).

detener
Detiene el conjunto de instancias objetivo.

Si el conjunto objetivo contiene intencionalmente más de una instancia, entonces se debe usar la opción -a (esto está diseñado para reducir el riesgo de detener accidentalmente un número potencialmente grande de procesos pmie(1)).

Si una instancia en el conjunto objetivo ya está detenida, se emite una advertencia pero no se realiza ningún cambio.

reiniciar
Detiene y luego inicia el conjunto de instancias objetivo.

Si el conjunto objetivo contiene intencionalmente más de una instancia, entonces se debe usar la opción -a (esto está diseñado para reducir el riesgo de detener y reiniciar accidentalmente un número potencialmente grande de procesos pmie(1)).

Si una instancia en el conjunto objetivo ya está detenida, se emite una advertencia antes de que la instancia sea iniciada.

estado
Reporta el estado del conjunto de instancias objetivo. Si no se especifica la opción -c y no hay argumentos host, es decir, el conjunto objetivo está vacío, entonces se reportarán todas las instancias.
destruir
Destruye el conjunto de instancias objetivo. Al final de esta operación, los procesos pmie(1) asociados serán

Si el conjunto de destino contiene intencionadamente más de una instancia, entonces se debe usar la opción -a (esto está diseñado para reducir el riesgo de terminar accidentalmente un número potencialmente grande de procesos pmie(1) y eliminar sus configuraciones de pmie_check(1)).

El archivo de política enlazado a la clase de una instancia a destruir puede contener una sección destroy que puede influir en si y cómo la operación de destrucción debe realizarse. Esto puede requerir una opción -p para encontrar el archivo de política de clase asociado.

La verificación de la política de clase se puede omitir utilizando la opción de línea de comandos -f (forzar).

ARCHIVO_DE_POLÍTICA_DE_CLASE

Un archivo de política de clase contiene un número de secciones, cada sección comienza con una línea que simplemente empieza con el nombre de la sección rodeado por ``['' y ``]''.

Las líneas que comienzan con una almohadilla (#) se tratan como comentarios y se ignoran. Las líneas en blanco o vacías también se ignoran.

La ubicación típica del archivo de política para la clase foo es $PCP_SYSCONF_DIR/pmie/class.d/foo.

[class]
La sección opcional del nombre de la clase nombra la clase. Si falta, el nombre del archivo de política (despojado de cualquier prefijo de directorio) se utiliza como el nombre de la clase.
[ident]
La sección ident especifica la plantilla que se utilizará para el identificador de instancia que se le dará a cada miembro de la clase. Este identificador debe ser único entre todas las instancias y todas las clases, y debe ser un nombre de archivo válido en el sistema de archivos local, por lo que normalmente contendrá el nombre de la clase y la macro %h, por ejemplo, foo-%h. La macro se reemplaza por el host cuando se crea cada instancia.
[control]
La sección control consiste en una o más líneas de texto de plantilla que se utilizarán para crear el archivo de control para cada instancia. Esto debe incluir al menos la línea de control de pmie_check(1) para especificar cómo iniciar el proceso asociado de pmie(1); esta línea contiene campos separados por espacios en blanco de la siguiente manera:
1.
el nombre del host, usualmente la macro %h
2.
n para indicar que esta es una instancia no primaria
3.
el indicador de "socks", típicamente n
4.
la ruta utilizada por pmie(1) para el archivo de registro; esto debe ser único y generalmente se especifica utilizando la macro de pmie_check(1) PCP_LOG_DIR como inicio de la ruta, seguido de pmie, y luego el directorio único de la instancia %i, por ejemplo, PCP_LOG_DIR/pmie/%i/pmie.log
5.
parámetros adicionales para pmie(1) que probablemente incluirán al menos una opción -c para proporcionar un archivo de configuración que describe qué reglas deben evaluarse para las instancias de esta clase, que puede ser la misma para todas las instancias de esta clase, o puede incluir la macro %i para usar un archivo de configuración diferente para cada instancia. Tenga en cuenta que si este archivo de configuración no existe, será creado usando pmieconf(1) la primera vez que se ejecute pmie_check(1).

Antes de la línea de control debería haber una línea que defina la versión de la línea de control que sigue, es decir,
$version=1.1
Si esto falta, pmiectl asumirá que la versión es 1.1 e insertará la línea cuando se cree la instancia.

pmiectl también agregará el nombre de la clase durante la creación. por ejemplo,
$class=foo

Dentro de una plantilla de línea de control, se admite una forma simple de sustitución paramétrica. La macro ENV(spec) se reemplaza por texto utilizando variables de entorno de la siguiente manera:

  • Si spec tiene la forma var entonces se usa el valor de $var del entorno. Si $var no está definido o tiene el valor de una cadena vacía, esto es un error.
  • Si spec tiene la forma var:default entonces si $var del entorno está definido y no es una cadena vacía, se usa el valor de $var, de lo contrario se usa el valor default. La sustitución es simple, por lo que cualquier espacio en blanco entre el : y el ) se incluye en default, y default no puede contener un ).

Como ejemplo
# unset PMPROXY_PORT; PMPROXY_HOST=foobar.com pmiectl create ...
con una línea de plantilla de control de clase de política que incluye http://ENV(PMPROXY_HOST):ENV(PMPROXY_PORT:44322)
generará una línea de control que incluye
http://foobar.com:44322

[create]
La sección create define las condiciones que deben cumplirse antes de que se cree una instancia con el comando cond-create. La intención es permitir que se tomen diferentes decisiones cuando se descubre un nuevo host que ejecuta pmcd(1), por ejemplo, por pmfind(1).

Cada línea no en blanco en la sección create es una condición de la forma función(arg), donde función es una de las siguientes:

existe
arg es el nombre de una métrica de rendimiento y existe se evalúa como verdadero si esa métrica existe en el Espacio de Nombres de Métricas de Rendimiento (PMNS) en el host remoto
valores
arg es el nombre de una métrica de rendimiento en el PMNS remoto y valores se evalúa como verdadero si alguna instancia de esa métrica tiene un valor en el host remoto
condición
arg es una expresión de métrica derivada en el formato compatible con pmRegisterDerived(3), y condición se evalúa como verdadero si el valor de esa expresión en el host remoto es mayor que cero
nombre_host
arg es una expresión regular al estilo de egrep(1) y nombre_host se evalúa como verdadero si el nombre del host remoto coincide con arg
[destroy]
La sección destroy define la política que se aplicará cuando se destruya una instancia.

La intención es permitir que se tomen diferentes decisiones cuando el servicio de descubrimiento, por ejemplo, pmfind(1), nota que un host asociado con una instancia ya no está presente. Pero en la versión actual esto no está implementado y la sintaxis y semántica de la sección destroy aún no están definidas.

Un ejemplo de archivo de política de clase es el siguiente:

# archivo de política para la clase foo
[class]
foo
[ident]
foo-%h
[control]
$version=1.1
%h n n PCP_LOG_DIR/pmie/%i/pmie.log -c foo-metrics.config
[create]
# coincide con todos los hosts
hostname(.*)
[destroy]
# aún por definir

OPCIONES

Las opciones de línea de comandos disponibles son:

-a, --all
Aplicar la acción a todas las instancias coincidentes. Por defecto, solo se espera y actúa sobre una definición de instancia.
-c clase, --class=clase
Establecer el nombre de la clase a la que pertenecen las instancias de pmie(1) como clase.
-C argumentos_verificación, --checkargs=argumentos_verificación
argumentos_verificación son argumentos de línea de comandos adicionales para pmie_check(1) cuando se llama. Esto es muy útil para opciones como -V. Se pueden usar múltiples opciones -C y los diversos argumentos de argumentos_verificación se acumularán y todos se pasarán a pmie_check(1).
-f, --force
Forzar la acción si es posible.
-i identificador, --ident=identificador
Anular el identificador de instancia con identificador. Esta opción solo se aplica a los comandos create y cond-create.
-N, --showme
Ejecuta pmiectl en modo "mostrarme" o "simulacro" donde se muestra la intención del comando, pero no se realizan cambios.
-m, --migrate
Cuando se usa con los comandos create o check en plataformas systemd(1), también migra los procesos pmie nuevos o existentes no primarios al servicio pmie_farm. Esto normalmente lo hace automáticamente el servicio pmie_farm_check, que está basado en temporizador (por lo que puede haber un retraso de unos minutos antes de que se inicie la migración automática).
-p política, --policy=política
Usar política como el archivo de política de clase. Por defecto es $PCP_SYSCONF_DIR/pmie/class.d/<clase>.
-V, --verbose
Habilitar el modo detallado. Usar esta opción dos veces aumenta la verbosidad. La salida detallada se escribe en stderr.
-?, --help
Mostrar mensaje de uso y salir.

ENTORNO_PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).
