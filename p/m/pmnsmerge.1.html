NOMBRE

pmnsmerge - fusiona múltiples versiones de un PMNS de Performance Co-Pilot

SINOPSIS

$PCP_BINADM_DIR/pmnsmerge [-adfxv] [-D debug] archivo_entrada [...] archivo_salida

DESCRIPCIÓN

pmnsmerge fusiona múltiples instancias de un Espacio de Nombres de Métricas de Rendimiento (PMNS), tal como lo usan los componentes de Performance Co-Pilot (PCP).

Cada argumento archivo_entrada nombra un archivo que incluye la raíz de un PMNS, de la forma


root {
    /* contenido arbitrario */
}

El orden en que se procesan los archivos archivo_entrada se determina por la presencia o ausencia de líneas de control incrustadas de la forma

#define _DATESTAMP AAAA MM DD

Los archivos sin una línea de control se procesan primero y en el orden en que aparecen en la línea de comandos. Los otros archivos se procesan luego en orden de _DATESTAMP ascendente.

La opción -a suprime la reordenación de argumentos y procesa todos los archivos en el orden en que aparecen en la línea de comandos.

La fusión procede comparando nombres en el PMNS, solo se consideran los nombres nuevos en cada PMNS, y estos se añaden después de las métricas existentes con el prefijo coincidente más largo posible en sus nombres. Por ejemplo, la fusión de estos dos PMNS de entrada


root {                    root {
                              surprise  1:1:3
    mine       1:1:1          mine      1:1:1
    foo                       foo
                              yawn
    yours      1:1:2
}                         }
foo {                     foo {
    fumble     1:2:1
                              mumble    1:2:3
    stumble    1:2:2          stumble   1:2:2
}                         }
                          yawn {
                              sleepy    1:3:1
                          }

Produce el PMNS resultante en salida.


root {
    mine      1:1:1
    foo
    yours     1:1:2
    surprise  1:1:3
    yawn
}
foo {
    fumble    1:2:1
    stumble   1:2:2
    mumble    1:2:3
}
yawn {
    sleepy    1:3:1
}

Para evitar la sobrescritura accidental de archivos PMNS, se espera que archivo_salida no exista cuando pmnsmerge comience. La opción -f permite que un archivo_salida existente sea eliminado (si es posible) y truncado antes de que comience la escritura.

Normalmente se permiten nombres duplicados para el mismo Identificador de Métrica de Rendimiento (PMID) en un PMNS. La opción -d es la opción por defecto y se incluye por compatibilidad retroactiva. La opción -x invierte el comportamiento por defecto y pmnsmerge informará un error y saldrá con un estado distinto de cero si se encuentra un nombre duplicado para un PMID en cualquiera de los archivos PMNS de entrada o en el PMNS de salida fusionado.

La opción -v produce una línea de salida diagnóstica a medida que se procesa cada archivo_entrada.

Una vez completada toda la fusión, pmnsmerge intentará cargar el espacio de nombres resultante usando pmLoadASCIINameSpace(3) - si esto falla por alguna razón, archivo_salida se creará de todos modos, pero pmnsmerge informará el problema y saldrá con un estado distinto de cero.

Usar pmnsmerge con un único argumento de entrada permite verificar ese archivo PMNS. Además de la verificación sintáctica, especificar -x también habilitará una comprobación de nombres duplicados para todos los PMID.

OPCIONES

Las opciones disponibles en la línea de comandos son:

-a
Procesa los archivos en el orden de la línea de comandos.
-d, --dupok
Permite nombres de métrica duplicados por PMID. Esta es la opción predeterminada.
-f, --force
Sobrescribe el archivo de salida si ya existe.
-v, --verbose
Procesamiento de entrada detallado.
-x, --nodups
No permite nombres de métrica duplicados por PMID.
-?, --help
Muestra el mensaje de uso y sale.

SALVEDADES

Una vez que ha comenzado la escritura del nuevo archivo archivo_salida, las señales SIGINT, SIGHUP y SIGTERM serán ignoradas para proteger la integridad del nuevo archivo.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio usados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a depurar problemas, aunque la información es a veces críptica y está destinada principalmente a orientar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

VER TAMBIÉN
