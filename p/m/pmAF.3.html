NOMBRE

__pmAFsetup, __pmAFregister, __pmAFunregister, __pmAFblock, __pmAFunblock, __pmAFisempty - servicios de cola de eventos para callbacks asíncronos periódicos

SINOPSIS EN C

#include "pmapi.h"
#include "libpcp.h"

int __pmAFsetup(const struct timeval *start,
const struct timeval *delta, void *data, void (*func)(int, void *));

int __pmAFregister(const struct timeval *delta,
void *data, void (*func)(int, void *));

int __pmAFunregister(int afid);
void __pmAFblock(void);
void __pmAFunblock(void);
int __pmAFisempty(void);

cc ... -lpcp

ADVERTENCIA

Esta documentación está destinada al uso interno de los desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las APIs de PCP que se garantizan que permanecerán fijas en las distintas versiones, y pueden no funcionar, o proporcionar una semántica diferente en algún momento futuro.

DESCRIPCIÓN

Las rutinas implementan una cola de eventos y un marco de trabajo de callbacks que soporta la evaluación periódica de una serie de eventos con diferentes frecuencias para aplicaciones de Performance Co-Pilot (PCP).

La aplicación pmlogger(1), el PMDA pmdatrace(1) y el PMDA pmdahotproc(1) son los principales usuarios de estos servicios.

Se crea un evento llamando a __pmAFsetup o __pmAFregister y, si tiene éxito, el valor de retorno es un número de evento mayor que cero. El evento tiene datos de evento asociados identificados por el puntero opaco data. El evento ocurrirá con una frecuencia delta y cada vez que ocurra el evento, se llamará a la función func con el número de evento y los datos del evento como argumentos.

Si se utiliza __pmAFsetup, el primer evento se programa para el tiempo actual más start; de lo contrario, si se utiliza __pmAFregister, el primer evento se programa para el tiempo actual más delta.

func se llama en un contexto de manejador de señales SIGALRM, por lo que las rutinas que se pueden llamar de forma segura desde func están restringidas al conjunto llamado seguro para señales asíncronas. En particular, no debe haber llamadas de E/S estándar ni llamadas a ninguna de las rutinas de malloc(3) para modificar el estado del heap. Consulte la Sección Puntero a una Función del documento POSIX.1-2013 en https://pubs.opengroup.org/
onlinepubs/9699919799/functions/V2_chap02.html para una descripción más completa.

La clase más segura y sencilla de rutinas func son aquellas que realizan un procesamiento mínimo, establecen algún estado global y regresan. El trabajo real asociado con el evento se realiza posteriormente desde el bucle principal de la aplicación cuando se detecta el cambio de estado global.

Una vez que ocurre el evento y se ejecuta el callback, el evento se volverá a programar para delta en el futuro, excepto si todos los campos de delta son cero, en cuyo caso el evento no se volverá a programar (un evento de "un solo disparo").

Internamente, los eventos se procesan en serie, por lo que no hay posibilidad de callbacks anidados o reentrantes desde las rutinas de gestión de eventos.

Dado un número de evento afid, __pmAFunregister eliminará permanentemente la entrada correspondiente de la cola de eventos.

Para controlar el procesamiento de la cola de eventos, se pueden usar __pmAFblock y __pmAFunblock para bloquear y desbloquear explícitamente la distribución de eventos. Esto es más útil cuando el llamador desea configurar una serie de eventos a través de __pmAFsetup o __pmAFregister y completar la fase de registro antes de que ocurra el primer callback del evento.

Una llamada a __pmAFisempty devuelve 1 o 0, dependiendo de si la cola de eventos está vacía o no.

CAVEATS ADICIONALES

Estas rutinas dependen de setitimer(2) y manipulan el manejo de señales SIGALRM, por lo que probablemente no sean adecuadas para aplicaciones que requieren acceso directo y concurrente a estos servicios y recursos.

Si las funciones de callback son lentas o se retrasan, es posible que la programación de eventos se retrase y nunca se ponga al día. Cuando esto comienza a suceder, los eventos se omiten silenciosamente y se reprograman lo antes posible en el futuro, de acuerdo con el programa fijo definido por el momento de la llamada a __pmAFsetup y el valor de los argumentos start y delta (o definido por el momento de la llamada a __pmAFregister y el valor del argumento delta).

Además, la semántica del temporizador (o temporizadores) y el estado global necesario para soportar estos servicios exigen que las aplicaciones que llaman a estas rutinas lo hagan desde un único hilo. Esta restricción se impone en la PMAPI(3), donde las rutinas pueden devolver el código de error PM_ERR_THREAD si la biblioteca detecta llamadas desde más de un hilo.

DIAGNÓSTICOS

__pmAFsetup, __pmAFregister y __pmAFunregister devuelven valores menores que cero en caso de error. Estos valores son códigos de error de PCP y se pueden usar para generar mensajes de error a través de pmErrStr(3).

Las rutinas admiten el trazado de depuración estándar de PCP, y la opción af (o -D af en la línea de comandos) producirá diagnósticos en la salida de error estándar que rastrean la encolación y ejecución de eventos.
