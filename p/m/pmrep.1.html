NOMBRE

pmrep, pcp2csv - reporte de métricas de rendimiento

SINOPSIS

pmrep [-12357CdgGHIjkLmnprRuUvVxz?] [-4 accion] [-6 metrica-ordenar] [-8|-9 limite] [-a archivo] [-A alinear] [--archive-folio folio] [-b|-B escala-espacio] [-c configuracion] [--container contenedor] [-D depurar] [--daemonize] [-e derivada] [-E lineas] [-f formato] [-F archivo-salida] [-h host] [-i instancias] [--include-texts] [-J rango] [-K espec] [-l delimitador] [-N predicado] [--no-inst-info] [-o salida] [-O origen] [-P|-0 precision] [-q|-Q escala-conteo] [-s muestras] [-S hora-inicio] [-t intervalo] [-T hora-fin] [-w|-W ancho] [-X etiqueta] [-y|-Y escala-tiempo] [-Z zona-horaria] espec-metrica [...]

DESCRIPCIÓN

pmrep es una herramienta personalizable para reportar métricas de rendimiento. Cualquier métrica de rendimiento disponible, en vivo o archivada, del sistema y/o de aplicaciones, puede ser seleccionada para el reporte usando una de las alternativas de salida listadas abajo junto con las opciones de formato aplicables.

pmrep recopila valores de métricas seleccionadas a través de las facilidades de Performance Co-Pilot (PCP), ver PCPIntro(1). Las métricas a reportar se especifican en la línea de comandos, en archivos de configuración, o ambos. Las métricas pueden ser convertidas y escaladas automáticamente usando las facilidades de PCP, ya sea por defecto o mediante especificaciones de escalado por métrica. Además de las métricas existentes, se pueden definir métricas derivadas usando las expresiones aritméticas descritas en pmRegisterDerived(3).

Se incluye por defecto una amplia gama de conjuntos de métricas (ver abajo), proporcionando reportes sobre detalles por proceso, rendimiento NUMA, imitando otras herramientas como sar(1) y más, ver los archivos de configuración de pmrep en $PCP_SYSCONF_DIR/pmrep (típicamente /etc/pcp/pmrep) para más detalles. La autocompletación para opciones, métricas y conjuntos de métricas está disponible para bash y zsh.

A menos que se dirija a otro host con la opción -h, pmrep se conectará al Demon de Recopilación de Métricas de Rendimiento (PMCD, ver pmcd(1)) en el host local.

La opción -a hace que pmrep use el conjunto de archivos especificado en lugar de conectarse a un PMCD. Las opciones -a y -h son mutuamente excluyentes.

La opción -L hace que pmrep use un contexto local para recopilar métricas de PMDAs DSO (Agentes de Dominio de Métricas de Rendimiento, "plugins") en el host local sin PMCD. Solo algunas métricas están disponibles en este modo. Las opciones -a, -h y -L son mutuamente excluyentes.

Las métricas de interés se nombran en los argumentos espec-metrica. Si un espec-metrica especifica un nodo no hoja en el Espacio de Nombres de Métricas de Rendimiento (PMNS), entonces pmrep descenderá recursivamente el PMNS y reportará sobre todos los nodos hoja (es decir, métricas) para ese espec-metrica. Use pminfo(1) para listar todas las métricas (nodos hoja de PMNS) y sus descripciones.

Un espec-metrica tiene tres formas diferentes. Primero, en la línea de comandos puede empezar con dos puntos (":") para indicar un conjunto-metrica que se leerá de los archivos de configuración de pmrep (ver -c y pmrep.conf(5)), el cual puede consistir en cualquier número de métricas. Segundo, un espec-metrica que empieza sin dos puntos especifica un nodo PMNS como se describe arriba, opcionalmente seguido de definiciones de formato de salida de métrica. Esta forma, llamada forma compacta, de un espec-metrica se define de la siguiente manera:


metrica[,etiqueta[,instancias[,unidad/escala[,tipo[,ancho[,precision[,limite]]]]]]]

Un nodo PMNS válido (metrica) es obligatorio. Puede ser seguido por una etiqueta de texto utilizada con la salida *stdout*. La definición opcional de instancias restringe la reporte *csv* y *stdout* a las instancias especificadas de la métrica, de modo que las instancias no coincidentes serán filtradas (ver -i). Una unidad/escala opcional es aplicable para métricas no cadena compatibles dimensionalmente. Ver abajo para especificaciones de *unidad/escala* soportadas. Por defecto, las métricas de contador acumulativo se convierten a tasas; un tipo opcional puede ser establecido a raw para deshabilitar esta conversión de tasas. Para la salida *stdout*, un ancho numérico puede ser usado para establecer el ancho de la columna de salida para esta métrica. Las cadenas demasiado anchas en la salida serán truncadas para caber en la columna. Una precision específica de métrica puede ser proporcionada para valores de salida numéricos no enteros. Finalmente, un limite específico de métrica puede ser establecido para filtrar valores numéricos según el límite.

Como caso especial para métricas que son contadores con unidades de tiempo (nanosegundos a horas), la unidad/escala puede ser usada para cambiar el reporte por defecto (por ejemplo, milisegundos / segundo) a normalizar en el rango de cero a uno estableciendo esto a sec (ver también -y y -Y).

El siguiente espec-metrica solicita que la métrica kernel.all.sysfork sea reportada bajo la etiqueta de texto forks, convirtiéndose a la tasa por defecto de la métrica count/s en una columna de 8 de ancho. Aunque las definiciones en esta forma compacta son opcionales, siempre deben proporcionarse en el orden especificado arriba, por lo tanto las comas.


kernel.all.sysfork,forks,,,,8

La tercera forma de un espec-metrica, la *forma detallada*, se describe y es válida solo en pmrep.conf(5).

Las métricas derivadas se especifican como métricas de nodo hoja PMNS regulares.

Las opciones a través de valores de entorno (ver pmGetOptions(3)) anulan los valores por defecto incorporados correspondientes (si los hay). Las opciones de archivo de configuración anulan las variables de entorno correspondientes (si las hay). Las opciones de línea de comandos anulan las opciones de archivo de configuración correspondientes (si las hay).

pcp2csv es un alias para pmrep.

OPCIONES

Las opciones disponibles en la línea de comandos son:

-0 precision, --precision-force=precision
Similar a -P pero esta opción anulará las especificaciones por métrica.
-1, --dynamic-header
Imprime un nuevo encabezado ajustado dinámicamente cada vez que ocurren cambios en la disponibilidad de valores de métricas e instancias. Por defecto, se imprime un encabezado estático que nunca cambia una vez. Ver también -4, -7, y -E.
-2, --overall-rank
Realiza un ranking general de instancias en el archivo. Por defecto, el ranking (ver -J) y el reporte ocurren en cada intervalo. Con esta opción, todas las instancias y valores se rankean antes de que se imprima un resumen. Ver pmlogsummary(1) para alternativas adicionales de reporte de resumen de archivos, incluyendo promedios y tiempos pico para valores.
-3, --overall-rank-alt
Similar a -2 pero imprime las instancias de métricas en formato espec-metrica de pmrep, para permitir seleccionar fácilmente las instancias para una mayor investigación.
-4 accion, --names-change=accion
Especifica qué acción tomar al recibir un evento de cambio de nombres de métricas durante el muestreo. Estos eventos ocurren cuando un PMDA descubre nuevas métricas después de un tiempo de iniciado, e informa a las herramientas cliente en ejecución como pmrep. Los valores válidos para acción son update (refrescar métricas en muestreo), ignore (no hacer nada - el comportamiento por defecto) y abort (salir del programa si ocurre tal evento). update implica --dynamic-header.
-5, --ignore-unknown
Ignora silenciosamente cualquier nombre de métrica que no pueda ser resuelto. Debe encontrarse al menos una métrica para que la herramienta comience.
-6, --sort-metric=metrica-ordenar
Especifica una métrica de referencia para ordenar la salida por valores con -X. Por defecto, el orden de clasificación es descendente; prefijar el nombre de la métrica con el signo menos ("-") cambiará el orden a ascendente. Ver también -J y -N.
-7, --fixed-header
Con -X imprime un encabezado fijo una vez (a menos que se use -E) incluyendo todas las métricas que se están reportando. A diferencia del encabezado estático por defecto, esta opción muestra todas las métricas en una sola línea horizontal y luego las columnas de valores debajo de cada métrica.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Solo se informan las instancias con valores disponibles. A diferencia de la cabecera dinámica, la cabecera no se actualiza incluso si los valores de algunas métricas posteriormente se vuelven (no) disponibles. Ver también -1 y -E.
-8 límite, --limit-filter=límite
Limita los resultados a instancias con valores por encima/por debajo del límite. Un entero positivo incluirá las instancias con valores iguales o superiores al límite en el informe. Un entero negativo incluirá las instancias con valores iguales o inferiores al límite en el informe. Un valor de cero no realiza ningún filtrado por límite. Esta opción *no* anulará las posibles especificaciones por métrica. Ver también -J y -N.
-9 límite, --limit-filter-force=límite
Similar a -8, pero esta opción *sí* anulará las especificaciones por métrica.
-a archivo, --archive=archivo
Los valores de métricas de rendimiento se recuperan del conjunto de archivos de archivo Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contenga uno o más archivos. Ver también -u.
-A alineación, --align=alineación
Forza que la muestra inicial se alinee en el límite de una unidad de tiempo natural alineación. Consulte PCPIntro(1) para una descripción completa de la sintaxis de alineación.
--archive-folio=folio
Lee los archivos de origen de métricas del folio de archivos PCP creado por herramientas como pmchart(1) o, con menos frecuencia, manualmente con mkaf(1).
-b escala, --space-scale=escala
Unidad/escala para métricas de espacio (bytes), los valores posibles incluyen bytes, Kbytes, KB, Mbytes, MB, etc. Esta opción no anulará posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-B escala, --space-scale-force=escala
Similar a -b, pero esta opción *sí* anulará las especificaciones por métrica.
-c config, --config=config
Especifica el archivo o directorio de config a usar. En caso de que config sea un directorio, se incluirán todos los archivos que terminen en .conf. El valor predeterminado es el primero encontrado de: ./pmrep.conf, $HOME/.pmrep.conf, $HOME/pcp/pmrep.conf, $PCP_SYSCONF_DIR/pmrep/pmrep.conf y $PCP_SYSCONF_DIR/pmrep. Ver pmrep.conf(5).
--container=contenedor
Obtiene métricas de rendimiento del contenedor especificado, ya sea local o remoto (ver -h).
-C, --check
Sale antes de informar cualquier valor, pero después de analizar la configuración y las métricas e imprimir posibles cabeceras.
-d, --delay
Al reproducir desde un archivo, esta opción solicita que se aplique el retraso en tiempo real predominante entre muestras (ver -t) para efectuar una pausa, en lugar del comportamiento predeterminado de reproducir a toda velocidad.
--daemonize
Se demoniza al inicio.
-e derivado, --derived=derivado
Especifica métricas de rendimiento derivadas. Si derivado comienza con una barra (``/'') o un punto (``.'') se interpretará como un archivo de configuración de métricas derivadas de PCP, de lo contrario se interpretará como expresiones de métricas derivadas separadas por comas o puntos y comas. Para una descripción completa de las métricas derivadas y los archivos de configuración de métricas derivadas de PCP, consulte pmLoadDerivedConfig(3) y pmRegisterDerived(3). Alternativamente, usar la sintaxis de configuración de pmrep.conf(5) permite definir métricas derivadas como parte de los conjuntos de métricas.

En caso de problemas con métricas derivadas, revise detalladamente las páginas de manual mencionadas anteriormente y asegúrese de que todas las métricas requeridas estén disponibles, especialmente al usar archivos. Use -Dderive para ver información de depuración adicional sobre el análisis de métricas derivadas.

-E líneas, --repeat-header=líneas
Repite la cabecera cada líneas de salida. Cuando no se utiliza -1 o -7, use auto para repetir la cabecera basándose en la altura de la terminal. Ver también -1 y -7.
-f formato, --timestamp-format=formato
Usa la cadena de formato para dar formato a la marca de tiempo. El formato se usará con el método datetime.strftime de Python, que es en su mayoría el mismo que el descrito en strftime(3). Una cadena de formato vacía (es decir, "") eliminará las marcas de tiempo de la salida. Predeterminado a %H:%M:%S al usar el destino de salida stdout. Predeterminado a %Y-%m-%d %H:%M:%S al usar el destino de salida csv.
-F archivo_salida, --output-file=archivo_salida
Especifica el archivo de salida archivo_salida. Ver -o.
-g, --separate-header
Imprime el número de columna y la información completa de la métrica, una por línea, antes de imprimir los valores de la métrica.
-G, --no-globals
No incluye métricas globales en el informe (ver pmrep.conf(5)).
-h host, --host=host
Obtiene métricas de rendimiento de pmcd(1) en host, en lugar de localhost, que es el predeterminado.
-H, --no-header
No imprime ninguna cabecera.
-i instancias, --instances=instancias
Recupera y reporta solo las instancias de métrica especificadas. Por defecto se reportan todas las instancias presentes inicialmente, excepto al escribir un archivo (ver -o), donde también se reportarán todas las instancias futuras.

Las instancias especificadas se filtran de las instancias presentes inicialmente cuando la herramienta se está iniciando. Por lo tanto, las instancias que coincidirían con el filtro que aparecen después de que la herramienta ha comenzado no se informarán; use -j para cambiar esto.

Esta es una opción global que se utiliza para todas las métricas de valor conjunto, a menos que se proporcione un filtro de instancia específico de métrica como parte de un metricspec. Por defecto, las métricas "planas" de valor único sin instancias todavía se informan como de costumbre; use -v para cambiar esto.

instancias es una lista separada por comas de una o más especificaciones de filtro de instancia. Los filtros que contienen comas o espacios en blanco deben entrecomillarse con comillas simples (') o dobles ("). Tenga en cuenta que como parte de un metricspec en la línea de comandos, una lista con más de un filtro, tanto la lista como cada filtro deben entrecomillarse como se muestra a continuación. También es posible definir un solo filtro con barras (|) como separador de instancias de expresión regular para facilitar el entrecomillado, ver más abajo.

Se permiten múltiples opciones -i como una forma alternativa de especificar más de un filtro de instancia no específico de métrica.

Un filtro de instancia individual puede ser uno de los siguientes:

nombre
Nombre completo de la instancia. Por ejemplo, sda para instancias disk.dev o eth0 para instancias network.interface.
PID
ID de proceso para instancias proc.
comando
Nombre base de un proceso para instancias proc. Por ejemplo, pmcd coincidiría con todos los procesos pmcd(1) independientemente de su ruta o PID.
regex
Expresión regular. Por ejemplo, .*python.* coincidiría con todas las instancias que tengan la cadena python como parte de su nombre de instancia, lo que significa que coincidiría con todos los procesos Python independientemente de su ruta, PID o versión.

Como ejemplo, lo siguiente informaría las mismas instancias: 

$ pmrep -i '. minute' kernel.all.load
$ pmrep -i '1 minute','5 minute' kernel.all.load
$ pmrep -i "'1 minute','5 minute'" kernel.all.load
$ pmrep -i '1 minute' -i '5 minute' kernel.all.load
$ pmrep kernel.all.load,,"'1 minute','5 minute'"
$ pmrep kernel.all.load,,'1 minute|5 minute'


Sin embargo, esto informaría solo la instancia de 1 minuto: 

$ pmrep -i '1 minute','5 minute' kernel.all.load,,'1 minute'


Y esto informaría todas las instancias (debido a la regex por métrica): 

$ pmrep -i '1 minute','5 minute' 'kernel.all.load,,.*'


-I, --ignore-incompat
Ignora métricas incompatibles. Por defecto, las métricas incompatibles (es decir, su tipo no es compatible o no se pueden escalar como se solicitó) harán que pmrep termine con un mensaje de error. Con esta opción, todas las métricas incompatibles se omiten silenciosamente del informe. Esto puede ser especialmente útil al solicitar nodos no terminales del árbol PMNS para el informe.
--include-texts
Al escribir un archivo PCP, incluye textos de ayuda de métricas PCP en el archivo creado.
-j, --live-filter
Realiza filtrado en vivo de instancias. Esto permite capturar todas las instancias nombradas incluso si los procesos se reinician en algún momento (a diferencia de sin filtrado en vivo). Realizar filtrado en vivo sobre un gran número de instancias agregará algo de sobrecarga interna, por lo que se recomienda un poco de precaución por parte del usuario. Ver también -1 y -n.
-J rango, --rank=rango
Limita los resultados a las rango instancias más altas/bajas de métricas de valor conjunto. Un entero positivo incluirá las instancias de mayor valor en el informe. Un entero negativo incluirá las instancias de menor valor en el
reporting. Un valor de cero no realiza ninguna clasificación. La clasificación no implica ordenación, véase -6. Véase también -2 y -8.
-k, --extended-csv
Escribir salida CSV extendida, similar a sadf(1).
-K espec, --spec-local=espec
Al obtener métricas de un contexto local (véase -L), la opción -K se puede usar para controlar las PMDA DSO que deben hacerse accesibles. El argumento espec cumple la sintaxis descrita en pmSpecLocalPMDA(3). Se pueden usar varias opciones -K.
-l delimitador, --delimiter=delimitador
Especificar el delimitador que separa cada columna de la salida csv o stdout. El valor predeterminado para stdout son dos espacios (`` '') y una coma (``,'') para csv. Al usar un delimitador que no sea un espacio en blanco, todas las instancias del delimitador en los valores de cadena se reemplazarán por el carácter de guion bajo (``_''). Tenga en cuenta que muchos conjuntos de métricas predeterminados especifican un delimitador (que puede no ser una coma), por lo que podría ser necesario usar esta opción con conjuntos de métricas para establecer explícitamente el delimitador como coma para la salida CSV, es decir, --delimiter=,
-L, --local-PMDA
Usar un contexto local para recopilar métricas de las PMDA DSO en el host local sin PMCD. Véase también -K.
-m, --include-labels
Incluir etiquetas de métricas PCP en la salida.
-n, --invert-filter
Realizar la clasificación antes del filtrado en vivo. Por defecto, el filtrado en vivo de instancias (cuando se solicita, véase -j) ocurre antes de la clasificación de instancias (cuando se solicita, véase -J). Con esta opción, la lógica se invierte y la clasificación ocurre antes del filtrado en vivo.
-N predicado, --predicate=predicado
Especificar una lista separada por comas de métricas de referencia de filtro de predicado. Por defecto, la clasificación (véase -J) se realiza para cada métrica individualmente. Con predicados, la clasificación se realiza solo para las métricas de predicado especificadas. Al informar, el resto de las métricas que comparten el mismo dominio de instancia (véase PCPIntro(1)) que el predicado incluirán solo las instancias de mayor/menor rango del predicado correspondiente. La clasificación no implica ordenación, véase -6.

Así, por ejemplo, utilizando proc.memory.rss (tamaño de memoria residente del proceso) como métrica de predicado junto con proc.io.total_bytes y mem.util.used como métricas a informar, solo se incluirán los procesos que usan más/menos (según -J) memoria al informar los bytes totales escritos por los procesos. Dado que mem.util.used es una métrica de valor único (por lo tanto, no comparte el mismo dominio de instancia que las métricas relacionadas con el proceso), se informará como de costumbre.

--no-inst-info
Omitir la información de instancia de las cabeceras. No aplicable con cabecera separada (véase -g).
-o salida, --output=salida
Usar el destino de salida para informar. El destino predeterminado es stdout. Las alternativas de destino de salida disponibles son:
archivo
Registrar métricas en un archivo PCP que luego se puede reproducir con herramientas PCP, incluido el propio pmrep. Véase LOGARCHIVE(5) y PCPIntro(1) para obtener detalles sobre los archivos de archivo PCP. Requiere -F.
csv
Imprimir métricas en formato CSV (sujeto a opciones de formato).
stdout
Imprimir métricas en stdout (formato sujeto a opciones de formato).
-O origen, --origin=origen
Al informar métricas archivadas, comience a informar en el origen dentro de la ventana de tiempo (véase -S y -T). Consulte PCPIntro(1) para una descripción completa de la sintaxis de origen.
-p, --timestamps
Imprimir marcas de tiempo. Por defecto no se imprimen marcas de tiempo.
-P precisión, --precision=precisión
Usar precisión para los valores numéricos de salida no enteros. Si el valor es demasiado ancho para su columna, la precisión se reduce uno por uno hasta que el valor encaja, o no se imprime si no lo hace. El valor predeterminado es usar 3 decimales (cuando sea aplicable). Esta opción no anulará las posibles especificaciones por métrica.
-q escala, --count-scale=escala
Unidad/escala para métricas de recuento, los valores posibles incluyen count x 10^-1, count, count x 10, count x 10^2, y así sucesivamente desde 10^-8 hasta 10^7. (Estos valores son actualmente sensibles a los espacios.) Esta opción no anulará las posibles especificaciones por métrica. Véase también pmParseUnitsStr(3).
-Q escala, --count-scale-force=escala
Similar a -q pero esta opción sí anulará las especificaciones por métrica.
-r, --raw
Salida de valores de métricas crudos, no convertir contadores acumulativos a tasas. Al escribir archivos, siempre se utilizan valores crudos. Esta opción sí anulará las posibles especificaciones por métrica.
-R, --raw-prefer
Similar a -r pero esta opción no anulará las especificaciones por métrica.
-s muestras, --samples=muestras
El argumento muestras define el número de muestras a recuperar y reportar. Si muestras es 0 o -s no se especifica, pmrep tomará muestras e informará continuamente (en modo de tiempo real) o hasta el final del conjunto de archivos PCP (en modo de archivo). Véase también -T.
-S horainicio, --start=horainicio
Al informar métricas archivadas, el informe se restringirá a aquellos registros registrados en o después de horainicio. Consulte PCPIntro(1) para una descripción completa de la sintaxis de horainicio.
-t intervalo, --interval=intervalo
Establecer el intervalo de informe a algo distinto del segundo predeterminado. El argumento intervalo sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos). Véase también las opciones -T y -u.
-T horafin, --finish=horafin
Al informar métricas archivadas, el informe se restringirá a aquellos registros registrados antes o en horafin. Consulte PCPIntro(1) para una descripción completa de la sintaxis de horafin.

Cuando se usa para definir el tiempo de ejecución antes de que pmrep salga, si no se proporciona ninguna muestra (véase -s), entonces el número de muestras informadas depende del intervalo (véase -t). Si se proporcionan muestras, el intervalo se ajustará para permitir informar de muestras durante el tiempo de ejecución. En caso de que se proporcionen -T, -s y -t, horafin determinará la hora real en que se ejecutará pmrep.

-u, --no-interpol
Al informar métricas archivadas, por defecto los valores se informan de acuerdo con el intervalo de muestra seleccionado (opción -t), no de acuerdo con el intervalo de registro real en un archivo. A tal efecto, PCP interpola los valores a informar basándose en los registros del archivo. Con la opción -u se habilita el informe no interpolado, se informa cada valor registrado para las métricas seleccionadas y se ignora el intervalo de muestra solicitado (-t).

Así, por ejemplo, si un archivo PCP contiene valores registrados cada 10 segundos y el intervalo de muestra solicitado es de 1 hora, por defecto pmrep utilizará un esquema de interpolación para calcular los valores de las métricas solicitadas a partir de los valores registrados en las proximidades de esas métricas solicitadas y se informarán valores cada hora. Con -u se informan todos los registros cada 10 segundos tal cual (los valores informados aún están sujetos a conversión de tasa, use -r o -R para deshabilitar).

-U, --no-unit-info
Omitir información de unidades de las cabeceras.
-v, --omit-flat
Informar solo métricas de valor conjunto con instancias (por ejemplo, disk.dev.read) y omitir métricas "planas" de valor único sin instancias (por ejemplo, kernel.all.sysfork). Véase -i y -I.
-V, --version
Mostrar número de versión y salir.
-w ancho, --width=ancho
Establecer el ancho de columna de la salida stdout. Las cadenas se truncarán a este ancho. El ancho predeterminado es el más corto que pueda contener la etiqueta de texto de la métrica, el mínimo forzado es 3. Esta opción no anulará las posibles especificaciones por métrica.
-W ancho, --width-force=ancho
Similar a -w pero esta opción sí anulará las especificaciones por métrica.
-x, --extended-header
Imprimir cabecera extendida.
-X etiqueta, --colxrow=etiqueta
Intercambiar columnas y filas en la salida stdout, informando una instancia por línea, usando etiqueta como la etiqueta de texto para la columna de instancia. Usar una cadena vacía ("") para habilitar el intercambio sin una etiqueta de columna específica. Este cambio en la salida permite usar grep(1) para filtrar resultados o para más cerca

OPTIONS

-y escala, --time-scale=escala
Unidad/escala para métricas de tiempo, los valores posibles incluyen nanosec, ns, microsec, us, millisec, ms, y así sucesivamente hasta hour, hr. Esta opción *no* anulará las posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-Y escala, --time-scale-force=escala
Similar a -y pero esta opción *sí* anulará las especificaciones por métrica.
-z, --hostzone
Utilizar la zona horaria local del host que es la fuente de las métricas de rendimiento, según lo identificado por las opciones -h o -a. El valor predeterminado es usar la zona horaria del host local.
-Z zonaHoraria, --timezone=zonaHoraria
Utilizar zonaHoraria para la fecha y hora. zonaHoraria está en el formato de la variable de entorno TZ tal como se describe en environ(7). Tenga en cuenta que al incluir una cadena de zona horaria en la salida, se utilizan compensaciones UTC de estilo ISO 8601 (por lo que algo como -Z EST+5 se convertirá en UTC-5).
-?, --help
Mostrar mensaje de uso y salir.

EJEMPLOS

Los siguientes ejemplos utilizan las instalaciones estándar de PCP para recopilar los valores de las métricas, no se necesitan utilidades externas. Los conjuntos de métricas referenciados que comienzan con dos puntos son parte de la configuración predeterminada de pmrep. Con bash y zsh, la tecla de tabulación completa las opciones, métricas y, después de dos puntos, los conjuntos de métricas disponibles.

Mostrar métricas de la interfaz de red en el host local:

$ pmrep network.interface.total.bytes

Mostrar todas las métricas de red salientes para la interfaz wlan0:

$ pmrep -i wlan0 -v network.interface.out

Mostrar el uso total de slab (en MB) de dos instancias de slab específicas:

$ pmrep mem.slabinfo.slabs.total_size,,'kmalloc-4k|xfs_inode',MB

Mostrar información similar a vmstat(8) con marca de tiempo utilizando megabytes en lugar de kilobytes y también incluir el número de inodos utilizados:

$ pmrep -p -B MB :vmstat vfs.inodes.count

Mostrar lecturas y escrituras de disco por dispositivo desde el host server1 utilizando un intervalo de dos segundos y un formato de salida CSV similar a sadf(1):

$ pmrep -h server1 -t 2s -o csv -k disk.dev.read disk.dev.write

Mostrar procesos que utilizan al menos 100 MB de memoria con encabezados dinámicos, además usar -g para mostrar los nombres de instancia (proceso) completos:

$ pmrep -b MB --limit-filter 100 --dynamic-header proc.memory.rss

Mostrar el conjunto predefinido de métricas del archivo pmrep.conf(5) predeterminado que contiene detalles sobre las solicitudes de E/S de los procesos pmlogger actuales:

$ pmrep -gp -i pmlogger :proc-io

Mostrar los tres procesos que más CPU consumen:

$ pmrep -1gUJ 3 proc.hog.cpu

Mostrar información similar a sar -w y sar -W al mismo tiempo del archivo PCP ./20150921.09.13 mostrando valores registrados entre las 3 PM y las 5 PM:

$ pmrep -a ./20150921.09.13 -S @15:00 -T @17:00 :sar-w :sar-W

Grabar la información más relevante de CPU, memoria y E/S de todos los procesos Java en el sistema, presentes y futuros, en un archivo ./a con un intervalo de un minuto en cada minuto completo en un proceso en segundo plano:

$ pmrep --daemonize -A 1m -t 1m -i '.*java.*' -j -o archive -F ./a \
    :proc-info :proc-cpu :proc-mem :proc-io

Grabar métricas de servidor de directorios 389, sistema de archivos XFS y CPU/memoria/disco cada cinco segundos durante cinco minutos en un archivo PCP ./a:

$ pmrep -t 5s -T 5m -o archive -F ./a ds389 xfs kernel.all.cpu mem disk

Grabar información de memoria y E/S de procesos para aquellos procesos que son los tres procesos que más consumen memoria:

$ pmrep -o archive -F ./a -J 3 -N proc.memory.rss proc.memory proc.io

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede utilizar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para variables de entorno que afectan a las herramientas de PCP, ver pmGetOptions(3).

De particular interés, PCP_DISCRETE_ONCE se puede establecer para garantizar que los valores de métricas discretas se informen solo una vez, a menos que cambien en algún momento.

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información es a veces críptica y está destinada principalmente a guiar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmrep son las siguientes:

Opción Descripción
