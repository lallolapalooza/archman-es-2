NOMBRE

pmGetArchiveEnd - localizar el final lógico del archivo para un conjunto de archivos

SINOPSIS C

#include <pcp/pmapi.h>

int pmGetArchiveEnd(struct timespec *tp);

cc ... -lpcp

DESCRIPCIÓN

Suponiendo que el contexto actual de PMAPI está asociado con un conjunto de archivos, pmGetArchiveEnd intentará encontrar el final lógico del archivo (después del último registro completo en el conjunto de archivos) y devolverá la última marca de tiempo registrada a través de tp. Esta marca de tiempo puede pasarse a pmSetMode(3) para posicionar de manera fiable el contexto en el último registro válido del archivo, por ejemplo, en preparación para lecturas posteriores en orden cronológico inverso.

Para archivos que no se están escribiendo de forma concurrente, el final físico del archivo y el final lógico del archivo coinciden. Sin embargo, si un archivo está siendo escrito por pmlogger(1) al mismo tiempo que una aplicación intenta leer el archivo, el final lógico del archivo puede estar antes del final físico del archivo debido al almacenamiento en búfer de escritura que no está alineado con los límites de los registros lógicos.

pmGetArchiveEnd devuelve un error menor que cero si el contexto no es válido ni está asociado con un conjunto de archivos, o si el conjunto de archivos está gravemente corrupto. De lo contrario, el valor de retorno es 0 si no ha habido ningún cambio de estado desde la última llamada, o 1 si el final lógico del archivo ha avanzado desde la última llamada.

En ausencia de un error, el resultado devuelto a través de tp está bien definido.

Tanto pmGetArchiveEnd como preservan el estado de posicionamiento del archivo antes de esta llamada a la función.

COMPATIBILIDAD

Antes de PCP 7.0 y libpcp.so.4, el argumento tp era una struct timeval. Para admitir la transición de PMAPI, se pueden utilizar la interfaz y la semántica antiguas si las aplicaciones se enlazan con libpcp.so.3 o se recompilan con -DPMAPI_VERSION=2.

Durante un tiempo en PCP 6.x hubo una rutina con la misma semántica que la actual pmGetArchiveEnd llamada pmGetHighResArchiveEnd, aunque ahora está obsoleta y el soporte en tiempo de compilación para pmGetHighResArchiveEnd se eliminará en una versión futura.

DIAGNÓSTICOS

PM_ERR_NOCONTEXT
el contexto PMAPI actual es inválido o no está asociado con un conjunto de archivos
PM_ERR_LOGREC
el conjunto de archivos está suficientemente dañado, que no se puede encontrar ni un solo registro válido

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede utilizarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5). Los valores de estas variables se pueden obtener programáticamente utilizando la función pmGetConfig(3).
