PMLOADDERIVEDCONFIG(3) Manual de Funciones de Biblioteca PMLOADDERIVEDCONFIG(3)

NOMBRE

pmLoadDerivedConfig - cargar definiciones de métricas derivadas desde archivos

C SINOPSIS

#include <pcp/pmapi.h>

int pmLoadDerivedConfig(char *path);

cc ... -lpcp

DESCRIPCIÓN

Las métricas derivadas pueden ser usadas para extender las métricas disponibles con nuevas métricas (derivadas) usando expresiones aritméticas simples. Las definiciones de estas métricas pueden ser persistidas y cargadas programáticamente por herramientas de monitorización usando pmLoadDerivedConfig.

El parámetro path define una lista de archivos y/o directorios separada por dos puntos (la sintaxis es la misma que para la variable $PATH de sh(1)), desde los cuales se obtendrán las especificaciones de métricas derivadas. Los componentes de path se expanden a una lista de archivos de la siguiente manera: si un componente es un archivo, entonces ese archivo se añade a la lista; de lo contrario, si un componente es un directorio, se realiza un descenso recursivo para enumerar todos los archivos debajo de ese directorio y estos se añaden a la lista. Cada archivo en la lista resultante se analiza en orden, y de acuerdo con la sintaxis de métricas derivadas descrita a continuación.

Cada línea de los archivos identificados por path es una línea de comentario (con un ``#'' en la primera posición de la línea) o la declaración de una métrica de rendimiento derivada, especificada como:

  • el nombre de la métrica derivada, utilizando la misma sintaxis de ``notación de puntos'' que se utiliza para las métricas de rendimiento de PCP, véase PCPIntro(1) y PMNS(5).
  • un signo igual (``='')
  • una expresión válida para una métrica derivada, como se describe en pmRegisterDerived(3).

Por cada línea que contenga una definición de métrica derivada, se llama a pmRegisterDerived(3) para registrar la nueva métrica derivada.

Una vez declarada una métrica derivada, se le pueden asignar atributos adicionales con una línea de la forma:

  • el nombre de la métrica derivada,
  • un paréntesis izquierdo, un tipo de atributo y un paréntesis derecho,
  • un signo igual (``=''),
  • un valor de atributo.

Actualmente, el tipo de atributo puede ser oneline o helptext para designar el texto de ayuda ``en una línea'' o expandido asociado con la métrica derivada, véase pmLookupText(3).

El valor de atributo puede ser texto arbitrario que siga al ``='' y termine al final de la línea, o una cadena delimitada por comillas simples (') o dobles ("). En este último caso, el valor de atributo puede abarcar múltiples líneas, y se soporta un mecanismo de escape simple, es decir, para cualquier carácter ``x'', ``\x'' se reemplaza por ``x'' (esto permite escapar comillas dentro de una cadena, por ejemplo), y hay un caso especial cuando el ``\'' está al final de la línea en cuyo caso el siguiente salto de línea no se incluye en el valor de atributo.

Fuera de los valores de atributo, se ignora el espacio en blanco en las líneas, y se ignoran por completo las líneas en blanco.

Dado que pmLoadDerivedConfig puede procesar muchos archivos, cada uno de los cuales puede contener muchas especificaciones de métricas derivadas, no es posible proporcionar un estado de error específico en el retorno. Por lo tanto, el resultado de pmLoadDerivedConfig será el número de métricas derivadas cargadas con éxito desde los archivos en el path dado. Los errores catastróficos, como no poder abrir uno de los archivos en el path dado, causarán un retorno inmediato con un valor negativo que puede pasarse a pmErrStr(3) para obtener el mensaje de error asociado.

Cuando se encuentran errores en las especificaciones de métricas derivadas, se generan mensajes de diagnóstico por pmRegisterDerived(3) y se muestran a través de pmprintf(3).

pmUnregisterDerived(3) puede usarse para anular la definición de una métrica derivada por nombre, lo que elimina todas las instancias de la métrica derivada en todos los contextos, independientemente de cómo se definió la métrica derivada.

EJEMPLO

# definiciones de ejemplo de métricas derivadas
bad_in_pkts = network.interface.in.errors + network.interface.in.drops
# nota que lo siguiente necesitaría estar en una sola línea ...
disk.dev.read_pct = 100 * delta(disk.dev.read) /
            (delta(disk.dev.read) + delta(disk.dev.write))
disk.dev.read_pct(oneline) = porcentaje de lecturas de disco
disk.dev.read_pct(helptext) = '\
Porcentaje de lecturas de disco en comparación con el número total de
lecturas de disco y escrituras de disco.'

VER TAMBIÉN

PCPIntro(1), sh(1), PMAPI(3), pmLookupText(3), pmRegisterDerived(3), pmUnregisterDerived(3), pmprintf(3) y PMNS(5).
