NOMBRE

pmdabcc - PMDA de BCC de PCP

DESCRIPCIÓN

pmdabcc es un Agente de Dominio de Métricas de Rendimiento (PMDA) de Performance Co-Pilot (PCP) que extrae datos de rendimiento en vivo de programas extendidos de BPF (Berkeley Packet Filter) en el kernel utilizando el frontend de Python de BCC (BPF Compiler Collection).

pmdabcc carga y actúa como puente para cualquier número de módulos de Python PMDA de BCC de PCP configurados y separados que ejecutan programas BPF. Las herramientas y programas de Python BCC existentes deberían poder utilizarse con los módulos PMDA de BCC de PCP con un esfuerzo razonable.

Consulte la documentación de BPF y BCC para obtener una descripción detallada de ambos.

CONFIGURACIÓN

pmdabcc lee un archivo de configuración obligatorio de estilo ini:

$PCP_PMDAS_DIR/bcc/bcc.conf

Este archivo debe contener una sección [pmda]. Las siguientes opciones de PMDA están disponibles (se muestran sus valores predeterminados entre paréntesis), las opciones marcadas con un asterisco (*) se pueden anular en secciones de configuración específicas del módulo:

modules (sin definir)
El PMDA pmdabcc lee la configuración específica del módulo para cada módulo listado en la lista separada por comas de modules (obligatorio).
prefix (bcc.) *
Por defecto, todas las métricas de los módulos aparecerán bajo el árbol de espacio de nombres de métricas de rendimiento (PMNS) de bcc. El prefix (opcional) se puede usar para cambiar este prefijo genérico.
process_refresh (0)
Ver más abajo.
module_failure_fatal (True)
Un valor booleano para module_failure_fatal (opcional) controla si un módulo que falla al compilar debe hacer que todo el PMDA se aborte (este es el valor predeterminado) o si debe iniciarse con módulos que posiblemente sigan funcionando. Los errores de configuración del módulo y los errores internos (como fallar al registrar las métricas PMNS proporcionadas, ver PMNS(5)) siempre provocarán que el PMDA falle.

En particular, la opción process aceptada por algunos módulos evalúa los PID y nombres de procesos dados en el momento de la inicialización del PMDA/módulo y aplica un filtrado solo a los procesos encontrados en esa etapa. Esto se debe a que el programa BPF en el kernel se compila en el momento de la inicialización del módulo y, lo que es más importante, a menudo se ejecutan en áreas críticas de rendimiento donde no es aceptable realizar búsquedas de nombres de procesos cada vez que el programa BPF procesa una solicitud. Para permitir que los módulos monitoreen procesos con nombre (por ejemplo, process = java) incluso si se reinician, process_refresh debe establecerse en un entero no negativo N para actualizar dinámicamente los procesos monitoreados cada N segundos. En caso de que aparezcan nuevos procesos que coincidan con el filtro de procesos, el programa BPF en ejecución actual se detiene y se instala un nuevo programa BPF con información PID actualizada (y si ya no hay PID que coincidan con el filtro, el programa BPF se detendrá para evitar cualquier sobrecarga innecesaria).

Para cada module listado en modules, se debe definir una sección [module] correspondiente que contenga al menos las siguientes opciones:

module
Define el nombre real del archivo del módulo Python que se cargará durante el inicio del PMDA en el subdirectorio modules de la instalación del PMDA BCC de PCP.
cluster
Especifica el ID de clúster único (ver PMNS(5)) para las métricas proporcionadas por el módulo bajo la ruta PMNS.

Todos los módulos aceptan, pero no necesariamente usan, la opción booleana debug.

Los módulos también pueden admitir opciones de configuración adicionales específicas del módulo; consulte el archivo de configuración predeterminado para ver las opciones que admiten.

INSTALACIÓN

Para instalar, se debe hacer lo siguiente como root:

# cd $PCP_PMDAS_DIR/bcc
# ./Install

Para desinstalar, se debe hacer lo siguiente como root:

# cd $PCP_PMDAS_DIR/bcc
# ./Remove

pmdabcc es lanzado por pmcd(1) y nunca debe ser ejecutado directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o se elimina.

En caso de que module_failure_fatal esté establecido en False, la instalación del PMDA se considerará exitosa incluso si algunos o incluso todos los módulos configurados fallan al cargarse; en tales casos, los valores de métrica proporcionados por los módulos que fallan no estarán disponibles. El archivo de registro del agente pmdabcc (ver más abajo) contendrá información detallada sobre la activación de cada módulo.

Algunos módulos comenzarán a proporcionar valores solo después de haber recopilado datos de la actividad del sistema relacionada. Por ejemplo, el módulo tcpperpid no proporcionará ningún valor a menos que haya procesos generando tráfico TCP en el sistema.

ARCHIVOS

$PCP_PMDAS_DIR/bcc/bcc.conf
archivo de configuración para el agente pmdabcc
$PCP_PMDAS_DIR/bcc/modules/*.{py,python}
módulos Python PMDA BCC de PCP disponibles para el agente pmdabcc
$PCP_PMDAS_DIR/bcc/Install
script de instalación para el agente pmdabcc
$PCP_PMDAS_DIR/bcc/Remove
script para deshacer la instalación del agente pmdabcc
$PCP_LOG_DIR/pmcd/bcc.log
archivo de registro predeterminado para mensajes del agente pmdabcc

Tenga en cuenta que el valor habitual/predeterminado para $PCP_PMDAS_DIR es /var/lib/pcp/pmdas y el valor predeterminado para $PCP_LOG_DIR es /var/log/pcp, pero estas configuraciones dependen de la plataforma.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).
