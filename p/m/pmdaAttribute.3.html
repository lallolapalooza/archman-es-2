PMDAATTRIBUTE(3) Manual de funciones de biblioteca PMDAATTRIBUTE(3)

NOMBRE

pmdaAttribute - informa a un PMDA sobre los atributos de conexión del cliente

SINOPSIS

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaAttribute(int context,
int key, char *value, int length, pmdaExt *pmda);

cc ... -lpcp_pmda -lpcp

DESCRIPCIÓN

Como parte de la API del Agente de Dominio de Métricas de Rendimiento (PMDA) (ver PMDA(3)), pmdaAttribute es la llamada de retorno genérica para responder a los atributos de conexión del cliente. Estos atributos incluyen información de credenciales del cliente, como el ID de usuario y el ID de grupo.

Un PMDA que admita atributos de conexión proporcionará una devolución de llamada privada pmdaAttribute mediante asignación a version.six.attribute de la estructura pmdaInterface, e implementará lógica personalizada para cualquier par de atributos clave-valor de su interés.

Todos los atributos están asociados con un contexto de cliente específico, y estos pueden identificarse de forma única utilizando el primer argumento ctx. El PMDA debe rastrear las conexiones y desconexiones de clientes utilizando la interfaz pmdaSetEndContextCallBack(3), como resultado. La interfaz pmdaGetContext(3) también puede ser particularmente útil.

Todos los atributos se pasan como pares clave-valor y el valor siempre se pasa como una cadena terminada en nulo de la longitud dada. Esto incluye atributos numéricos como el ID de usuario.

Los atributos más comunes serían PCP_ATTR_USERID y PCP_ATTR_GROUPID, pero otros también pueden pasarse opcionalmente (como PCP_ATTR_USERNAME) si están disponibles. Algunos atributos serán consumidos por pmcd y nunca se pasarán a los PMDA, como PCP_ATTR_PASSWORD. Una lista completa de todos los atributos posibles se puede encontrar en las cabeceras mencionadas anteriormente, todos tienen el prefijo PCP_ATTR.

ADVERTENCIA

El PMDA debe estar utilizando PMDA_INTERFACE_6 o posterior, según se especifica en la llamada a pmdaDSO(3) o pmdaDaemon(3).

DIAGNÓSTICOS

pmdaAttribute debe devolver cero en caso de éxito o un código de retorno negativo para indicar un error al manejar el atributo. Este código de retorno no se puede utilizar para indicar que se debe denegar el acceso a un cliente; dicha funcionalidad debe ser realizada por el agente en respuesta a las devoluciones de llamada para el cliente en cuestión (utilizando PM_ERR_PERMISSION para esas devoluciones de llamada específicas, para ese cliente específico. En otras palabras, los errores se pasarán a PMCD, pero no hay garantía de que el error se devuelva al cliente y resulte en la terminación del cliente, por ejemplo.

VER TAMBIÉN

PMAPI(3), PMDA(3), pmdaDaemon(3), pmdaDSO(3), pmdaMain(3) y pmdaGetContext(3).
