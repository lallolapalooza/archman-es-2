pmiAddInstance(3)

PMIADDINSTANCE(3) Manual de funciones de biblioteca PMIADDINSTANCE(3)

NOMBRE

pmiAddInstance - agregar un elemento a un dominio de instancia en un contexto LOGIMPORT

SINOPSIS C

#include <pcp/pmapi.h>
#include <pcp/import.h>

int pmiAddInstance(pmInDom indom,
const char *instance, int inst);

cc ... -lpcp_import -lpcp

SINOPSIS PERL

use PCP::LogImport;

pmiAddInstance($indom, $instance, $inst);

DESCRIPCIÓN

Como parte de la API de importación de registros de Performance Co-Pilot (ver LOGIMPORT(3)), pmiAddInstance agrega un nuevo elemento al dominio de instancias identificado por indom.

indom normalmente se construiría usando la macro pmInDom_build, por ejemplo pmInDom_build(PMI_DOMAIN,0) para el primer dominio de instancias en el Dominio de Métricas de Rendimiento PMI_DOMAIN (que es el predeterminado para todos los metadatos creados por la biblioteca LOGIMPORT).

La nueva instancia debe tener tanto un nombre externo (instance) como un identificador de instancia interno (inst) que sea único entre todas las instancias en el dominio de instancias indom. Existe una "regla de unicidad" especial para instance que impone pmLookupInDom(3), a saber, que el nombre de instancia externo debe ser único en los caracteres iniciales que no sean espacios, por ejemplo, los nombres de instancia "foo" y "foo bar" se consideran iguales por esta regla y no están permitidos en el mismo dominio de instancias, pero "foo" y "foobar" estarían permitidos.

Una vez definido, el nombre de instancia externo se puede usar en llamadas a pmiGetHandle(3) y/o pmiPutValue(3) con el nombre de una métrica definida sobre el mismo dominio de instancias.

DIAGNÓSTICOS

pmiAddInstance devuelve cero si tiene éxito, de lo contrario, un valor negativo que se puede convertir en un mensaje de error llamando a pmiErrStr(3).

VER TAMBIÉN

LOGIMPORT(3), pmiAddMetric(3), pmiErrStr(3), pmiGetHandle(3), pmiPutValue(3), pmiPutText(3), pmiPutLabel(3) y pmLookupInDom(3).
