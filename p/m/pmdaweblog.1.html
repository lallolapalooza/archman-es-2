PMDAWEBLOG(1) Manual de comandos generales PMDAWEBLOG(1)

NOMBRE

pmdaweblog - agente de dominio de métricas de rendimiento (PMDA) para registros de servidores Web

SINOPSIS

$PCP_PMDAS_DIR/weblog/pmdaweblog [-Cp] [-D debug] [-d dominio] [-h archivo_de_ayuda] [-i puerto] [-l archivo_de_registro] [-n segundos_inactivos] [-S num] [-t retraso] [-u socket] [-U nombre_usuario] archivo_de_configuracion

DESCRIPCIÓN

pmdaweblog es un Agente de Dominio de Métricas de Rendimiento (PMDA(3)) que escanea los registros de servidores Web para extraer métricas que caracterizan la actividad del servidor Web. Estas métricas de rendimiento se ponen a disposición a través de la infraestructura del Performance Co-Pilot (PCP).

El archivo_de_configuracion especifica qué servidores Web deben ser monitoreados, sus registros de acceso y registros de error asociados, y un esquema basado en expresiones regulares para extraer información detallada sobre cada acceso Web. Este archivo se mantiene como parte de la instalación y/o desinstalación del PMDA mediante los scripts Install y Remove en el directorio $PCP_PMDAS_DIR/weblog. Para más detalles, consulte la sección a continuación sobre la instalación.

Una vez iniciado, pmdaweblog monitorea un conjunto de archivos de registro y, en respuesta a una solicitud de información, procesará cualquier información nueva que se haya agregado a los archivos de registro, similar a un tail(1). También hay un "catch up" periódico para procesar nueva información de todos los archivos de registro, y un esquema para detectar la rotación de los archivos de registro.

Como todos los demás PMDA, pmdaweblog es lanzado por pmcd(1) usando opciones de línea de comandos especificadas en $PCP_PMCDCONF_PATH - el script Install solicitará valores apropiados para las opciones de línea de comandos y actualizará $PCP_PMCDCONF_PATH.

Una breve descripción de las opciones de línea de comandos de pmdaweblog sigue:

-C
Verifica la configuración y sale.
-d dominio
Especifica el número de dominio. Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y consistente. Es decir, dominio debe ser diferente para cada PMDA en el mismo host, y se debe usar el mismo número de dominio para el PMDA pmdaweblog en todos los hosts.

Para la mayoría de las instalaciones, el dominio predeterminado encapsulado en el archivo $PCP_PMDAS_DIR/weblog/domain.h será suficiente. Para valores alternativos, verifique $PCP_PMCDCONF_PATH para los valores de dominio que ya están en uso en este host, y el archivo $PCP_VAR_DIR/pmns/stdpmid contiene un repositorio de asignaciones de dominio "bien conocidas" que probablemente deberían evitarse.

-h archivo_de_ayuda
Obtiene el texto de ayuda del archivo_de_ayuda proporcionado en lugar de la ubicación predeterminada.
-i puerto
Se comunica con pmcd(1) en el puerto de Internet especificado (que puede ser un número o un nombre).
-l archivo_de_registro
Ubicación del archivo de registro. Por defecto, un archivo de registro llamado weblog.log se escribe en el directorio actual de pmcd(1) cuando se inicia pmdaweblog, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de registro no se puede crear o no es escribible, la salida se escribe en la salida estándar de error en su lugar.
-n segundos_inactivos
Si un archivo de registro del servidor Web no ha sido modificado durante segundos_inactivos segundos, el archivo se cerrará y se reabrirá. Esta es la única forma en que pmdaweblog puede detectar cualquier rotación asíncrona de los registros por parte de scripts administrativos del servidor Web. El período predeterminado es de 20 segundos. Este valor puede cambiarse dinámicamente usando pmstore(1) para modificar el valor de la métrica de rendimiento web.config.check.
-p
Se comunica con pmcd(1) a través de una tubería.
-S num
Especifica el número máximo de servidores Web por sproc. Puede ser deseable (desde una perspectiva de latencia y balanceo de carga) o necesario (debido a los límites de descriptores de archivos) delegar la responsabilidad de escanear los archivos de registro del servidor Web a varios sprocs. pmdaweblog asegurará que cada sproc maneje los archivos de registro de como máximo num servidores Web. El valor predeterminado es 80 servidores Web por sproc.
-t retraso
Para evitar la necesidad de escanear una gran cantidad de información de los registros del servidor Web en respuesta a una sola solicitud de métricas de rendimiento, todos los archivos de registro se verificarán al menos una vez cada retraso segundos. El valor predeterminado es 15 segundos. Este valor puede cambiarse dinámicamente usando pmstore(1) para modificar el valor de la métrica de rendimiento web.config.catchup.
-u socket
Se comunica con pmcd(1) a través del socket de dominio Unix dado.
-U
Cuenta de usuario bajo la cual ejecutar el agente. El valor predeterminado es la cuenta no privilegiada "pcp" en versiones recientes de PCP, pero en versiones anteriores se usaba la cuenta de superusuario ("root") por defecto.

INSTALACIÓN

El marco de PCP permite que las métricas se recopilen en un host y se monitoreen desde otro. Estos hosts se denominan hosts recolectores y monitores, respectivamente. Un host puede ser tanto un recolector como un monitor.

Los hosts recolectores requieren la instalación del agente, mientras que los hosts monitores no requieren ninguna instalación de agente.

Para los hosts recolectores, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/weblog
# ./Install

El procedimiento de instalación solicita una instalación predeterminada o no predeterminada. Una instalación predeterminada buscará configuraciones de servidor conocidas y configurará automáticamente el PMDA para cualquier archivo de registro de servidor que se encuentre. Una instalación no predeterminada recorrerá cada servidor, solicitando al usuario otras configuraciones de servidor y argumentos para pmdaweblog. El resultado final de una instalación de recolector es la creación de un archivo de configuración que se pasa a pmdaweblog a través del argumento archivo_de_configuracion.

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/weblog
# ./Remove

pmdaweblog es lanzado por pmcd(1) y nunca debe ser ejecutado directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o se elimina.

CONFIGURACIÓN

El archivo de configuración para el PMDA weblog es un archivo ASCII que puede modificarse fácilmente. Las líneas vacías y las líneas que comienzan con '#' se ignoran. Todas las demás líneas deben ser una expresión regular o una especificación de servidor.

Las expresiones regulares, que se utilizan tanto en los archivos de registro de acceso como en los de error, deben tener el formato:


regex nombre_regex patron_regex
o


regex_posix nombre_regex orden patron_regex_posix

El nombre_regex es una palabra que identifica de forma única la expresión regular. Esta es la referencia utilizada en la especificación del servidor. El patron_regex para los registros de acceso tiene el formato descrito para regcmp(3). El patron_regex_posix para los registros de acceso tiene el formato descrito para regcomp(3). El argumento orden se explica a continuación. La forma Posix debería estar disponible en todas las plataformas.

La expresión regular requiere la especificación de hasta cuatro argumentos que se extraerán de cada línea de un registro de acceso del servidor Web, dependiendo del tipo de servidor. En el caso más común hay dos argumentos que representan el método y el tamaño.

Para la versión no Posix, el argumento $0 debe contener el método: GET, HEAD, POST o PUT. El método PUT se trata como un sinónimo de POST, y cualquier otra cosa se clasifica como OT

NAME

pmdaweblog

Performance Metrics Domain Agent for Web server access logs

SYNOPSIS

$PCP_PMDAS_DIR/weblog/Install [-d]

$PCP_PMDAS_DIR/weblog/Remove [-d]

pmdaweblog [-D debug]

DESCRIPTION

The pmdaweblog Performance Metrics Domain Agent (PMDA) is a Performance Co-Pilot (PCP) agent that exports performance metrics from web server access and error logs. It supports several web server formats including NCSA, CERN, Netscape, Apache, and Squid. The PMDA can be configured to monitor multiple web servers and log files simultaneously. The metrics exposed by this PMDA include the number of requests, response times, status codes, and bandwidth consumed.

The PMDA reads web server log files and parses them using regular expressions. It can be configured using a text file, typically located at $PCP_VAR_DIR/config/web/weblog.conf, which specifies the web servers to monitor, their log file locations, and the regular expressions to use for parsing the logs.

The PMDA exposes metrics such as:

  • Number of requests per second.
  • Average response time.
  • Number of requests by status code (e.g., 200 OK, 404 Not Found).
  • Bandwidth transferred.

The PMDA can be installed and removed using the provided Install and Remove scripts.

INSTALLATION

To install the pmdaweblog PMDA, run the Install script as root:

# $PCP_PMDAS_DIR/weblog/Install

This script will create the necessary symbolic links and configuration files, and will register the PMDA with the PCP control daemon (pmcd). The -d option can be used to perform a debug installation.

To remove the pmdaweblog PMDA, run the Remove script as root:

# $PCP_PMDAS_DIR/weblog/Remove

This script will unregister the PMDA from pmcd and remove the created symbolic links and configuration files.

CONFIGURATION

The pmdaweblog PMDA is configured using a text file, typically located at $PCP_VAR_DIR/config/web/weblog.conf. This file contains definitions of regular expressions used to parse log files and specifications of the web servers to be monitored.

The configuration file consists of two main types of definitions: regex and server.

REGULAR EXPRESSIONS

Regular expressions are defined using the regex keyword. They are used to extract fields from log lines. The syntax is:

regex RegexName pattern

Where:

RegexName
A unique name for the regular expression.
pattern
A regular expression that matches a log line and captures fields that will be used as metrics. The captured fields are assigned numbers based on their order of appearance. These numbers are used in the server definitions to specify which captured field corresponds to which metric.

The following fields can be extracted from log lines:

method
The HTTP request method (e.g., GET, POST).
size
The size of the request in bytes. A size of "-" or " " is treated as unknown.
client_status
The HTTP status code returned to the client browser.
server_status
The HTTP status code returned to the server from a remote host (used for caching servers).

For example, a non-Posix regex for CERN/NCSA logs might look like this:

regex CERN "([A-Za-z][-A-Za-z]+)$0 .*" [-0-9]+ ([-0-9]+)$1

In this example:

  • The RegexName is CERN.
  • The pattern is "([A-Za-z][-A-Za-z]+)$0 .*" [-0-9]+ ([-0-9]+)$1.
  • The first captured group ([A-Za-z][-A-Za-z]+) is assigned to metric type $0 (method).
  • The second captured group ([-0-9]+) is assigned to metric type $1 (size).

There is a special case for RegexName SQUID, which extracts 4 parameters but uses text-based status codes.

If POSIX compliant regular expressions are used, the order of parameters needs to be explicitly specified. The syntax is:

regex_posix RegexName order pattern

Where:

order
A comma-separated list of numbers (1-4) or keywords indicating the order of the metrics (e.g., method,size, 1,2,3,4, or - for error logs). A hyphen (-) indicates that the content is ignored.

For example, a Posix regex for CERN/NCSA logs:

regex_posix CERN method,size ][ \]+"([A-Za-z][-A-Za-z]+) \
[^"]*" [-0-9]+ ([-0-9]+)

Here, method,size explicitly defines the order of the captured groups.

SERVER SPECIFICATIONS

Web servers are monitored using the server keyword. The syntax is:

server serverName on|off accessRegex accessFile errorRegex errorFile

Where:

serverName
A unique name for the web server instance. This name is used for PCP instance domains.
on|off
Specifies whether the server should be monitored. This can be changed dynamically using pmstore for the metric web.perserver.watched.
accessRegex
The name of the regular expression defined earlier to parse the access log.
accessFile
The path to the access log file.
errorRegex
The name of the regular expression defined earlier to parse the error log.
errorFile
The path to the error log file.

Log files do not need to exist when the PMDA is installed. The PMDA will check for them periodically and open them when they become available.

Example server specifications:

# Netscape Server on Port 80
server 127.55.555.555:80 on CERN /logs/access CERN_err /logs/errors
# FTP Server
server ftpd on SYSLOG_FTP /var/log/messages SYSLOG_FTP_err /var/log/messages

CAVEATS

Specifying regular expressions with an incorrect number of arguments (more than 2 for access logs, or any for error logs) may cause the PMDA to behave incorrectly or crash due to limitations in the regex(3) interface.

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.

Debugging options specific to pmdaweblog are as follows:

Option Description
appl0 initialization, configfile parsing and log file processing
appl1 timer operations, log file probing
appl2 IPC with worker processes, log lines processed
