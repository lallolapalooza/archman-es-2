NOMBRE

pmSeriesQuery, pmSeriesWindow, pmSeriesValues, pmSeriesLoad - consulta rápida y escalable de series temporales

SINOPSIS C

#include <pcp/pmwebapi.h>

int pmSeriesQuery(pmSeriesSettings *sp,
sds *query, pmSeriesFlags flags, void *arg);

int pmSeriesWindow(pmSeriesSettings *sp,
sds *window, pmSeriesTimeWindow *window, void *arg);

int pmSeriesValues(pmSeriesSettings *sp,
pmSeriesTimeWindow *window, int count, sds *series, void *arg);

int pmSeriesLoad(pmSeriesSettings *sp,
sds *query, pmSeriesFlags flags, void *arg);

cc ... -lpcp_web

DESCRIPCIÓN

La búsqueda de identificadores y valores de series temporales usando los servicios de series temporales rápidas y escalables del Performance Co-Pilot (PCP) se logra utilizando la utilidad pmseries(1) y el servicio asociado de API REST pmproxy(1).

La implementación de estas facilidades es compartida y también está disponible para que la usen otros programas. La funcionalidad se proporciona a través de APIs asíncronas, que funcionan de manera basada en eventos, donde se invocan callbacks por cada conjunto de identificadores de series o estructuras de valores que se devuelven. Estos callbacks deben ser registrados usando pmSeriesSetup(3) antes de realizar cualquier llamada a la API de consulta.

Como patrón general, estas interfaces toman un parámetro opaco (puntero void *), arg. Este puntero se pasará sin cambios y típicamente se usa para acceder a una estructura de datos que mantiene el estado dentro del programa que llama.

Dependiendo de la cadena query de pmseries proporcionada, pmSeriesQuery opera en uno de dos modos.

En primer lugar, si no se proporciona ninguna especificación de ventana de tiempo (entre corchetes), la interfaz devolverá solo los identificadores de series coincidentes y ningún valor. Estos identificadores se devuelven a través del callback on_match registrado usando pmSeriesSetup. Si la expresión query incluye llamadas a funciones u operadores aritméticos (en lugar de nombres de métricas simples), el identificador devuelto se crea dinámicamente y se asocia persistentemente con la expresión. La expresión query se puede recuperar con la llamada a la API pmSeriesExprs(3). Ver también PMWEBAPI(3) y la opción -e de pmseries(1).

El segundo modo es donde se utiliza una especificación de ventana de tiempo en la cadena query, o cuando se utiliza la interfaz pmSeriesValues. Este modo proporciona valores y marcas de tiempo para todos los identificadores de series temporales coincidentes que tengan puntos de datos dentro de la ventana de tiempo proporcionada. En este caso, los resultados se devuelven a través del callback on_value registrado usando pmSeriesSetup. Una rutina auxiliar para crear una estructura de ventana de tiempo a partir de una especificación de tiempo entre corchetes se proporciona en forma de pmSeriesWindow.

Metadatos adicionales (nombres de métricas, etiquetas, unidades, semántica, tipo, etc.) sobre las series temporales coincidentes y sus valores se pueden obtener utilizando las interfaces descritas en la página del manual pmSeriesDescs(3).

Típicamente, la carga de series temporales es manejada automáticamente por el demonio pmproxy, que utiliza la serie de interfaces pmDiscoverSetup(3) para detectar y cargar automáticamente series temporales registradas de pmlogger(1). Sin embargo, también es posible cargar manualmente series temporales desde un archivo PCP usando la interfaz pmSeriesLoad. La cadena query proporcionada debe proporcionar un archivo o directorio del que cargar datos usando la palabra clave source.path.

DIAGNÓSTICO

Donde estas funciones devuelven un código de estado, este es siempre cero en caso de éxito. En caso de fallo, se devuelve un código de error PMAPI negativo.

VER TAMBIÉN

pmproxy(1), pmlogger(1), pmSeriesSetup(3), pmSeriesDescs(3), pmDiscoverSetup(3), PMAPI(3) y PMWEBAPI(3).
