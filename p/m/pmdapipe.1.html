PMDAPIPE(1) Manual de comandos generales PMDAPIPE(1)

NOMBRE

pmdapipe - agente de dominio de métricas de rendimiento (PMDA) de captura de salida de comandos

SINOPSIS

$PCP_PMDAS_DIR/pipe/pmdapipe [-c archivo de configuración] [-D depuración] [-d dominio] [-l archivo de registro] [-m memoria]

DESCRIPCIÓN

pmdapipe es un Agente de Dominio de Métricas de Rendimiento (PMDA) configurable para monitorizar la salida de comandos. Puede considerarse análogo a un intérprete de comandos restringido, donde las opciones se pueden pasar a comandos preestablecidos, y cada línea de su salida se convierte en un evento de rendimiento. Estos eventos pueden ser consumidos por herramientas cliente como pmval(1).

El PMDA pipe exporta tanto métricas de estilo de evento que reflejan registros de eventos con marca de tiempo para la salida de comandos orientada a texto, como las métricas más ortodoxas de estilo de muestra, como recuentos de eventos y valores de tamaño de rendimiento.

El PMDA se configura a través de un archivo de configuración que contiene una línea para cada proceso cuya salida se puede capturar, como se describe en la sección ``CONFIGURACIÓN'' a continuación.

A continuación se presenta una breve descripción de las opciones de línea de comandos de pmdapipe:

-c
especifica un archivo de configuración alternativo para el PMDA. Por defecto, se utiliza un archivo llamado $PCP_PMDAS_DIR/pipe/pipe.conf y cualquier archivo ubicado en el directorio $PCP_SYSCONF_DIR/pipe.conf.d/.
-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y consistente. Es decir, el dominio debe ser diferente para cada PMDA en el mismo host, y se debe usar el mismo número de dominio para el mismo PMDA en todos los hosts.
-l
Ubicación del archivo de registro. Por defecto, se escribe un archivo de registro llamado pipe.log en el directorio actual de pmcd(1) cuando se inicia pmdapipe, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de registro no se puede crear o no es escribible, la salida se envía a la salida estándar de error en su lugar.
-m
Limita la memoria física utilizada por el PMDA para almacenar en búfer los registros de eventos a tamaño máximo bytes. A medida que los eventos de registro llegan al PMDA, deben almacenarse en búfer hasta que las herramientas cliente individuales soliciten el siguiente lote desde su lote anterior de eventos. El máximo predeterminado es de 2 megabytes.

CONFIGURACIÓN

El conjunto de comandos de tubería permitidos se configura mediante archivo(s) de texto simple. El formato es una sola línea para cada comando seguido de una sección opcional de control de acceso.

Se permiten líneas en blanco y comentarios (incluso se alientan) en el archivo de configuración. Un comentario comienza con un carácter '#' y termina al final de la línea.

Cada línea de configuración de comando tiene el formato:

instancia nombre de usuario comando opciones

Donde,

instancia
es una cadena que identifica el comando de tubería, también exportada como el identificador de instancia de métrica.
nombre de usuario
es el nombre de la cuenta de usuario bajo la cual se debe ejecutar el comando (por ejemplo, "root")
comando
es la ruta al binario que se ejecutará para generar la salida de tubería
opciones
es una lista opcional separada por espacios de parámetros para pasar al comando
Esta lista de opciones puede contener parámetros numéricos prefijados por el signo de dólar, y estos serán sustituidos con valores proporcionados por el usuario en el momento en que se ejecute el comando (similar a la sustitución de parámetros del shell).

Los parámetros se pasan como una única cadena separada por espacios o comas a la métrica pipe.firehose, utilizando la interfaz pmStore(3). El comando pmval proporciona acceso de almacenamiento a través de su opción -x. Los parámetros proporcionados por el usuario están restringidos a contener caracteres alfanuméricos.

La sección de control de acceso del archivo debe comenzar con una línea de la forma:

[access]

Pueden aparecer espacios en blanco iniciales y finales alrededor y dentro de los corchetes, y el caso de la palabra clave access se ignora. No puede aparecer ningún otro texto en la línea excepto un comentario final.

Después de esta línea, el resto del archivo de configuración debe contener líneas que permitan o denieguen el uso de comandos desde usuarios o grupos específicos.

Los nombres de usuario y grupo se verificarán utilizando los archivos locales /etc/passwd y /etc/groups (o un servicio de directorio alternativo), utilizando las rutinas getpwent(3) y getgrent(3).

El acceso para usuarios o grupos se permite o deniega especificando declaraciones de la forma:

allow user nombre de usuario : instancia
disallow user nombre de usuario : instancia
allow group nombre de grupo : instancia
disallow group nombre de grupo : instancia

Los nombres de usuario y grupo se verificarán utilizando los archivos locales /etc/passwd y /etc/groups (o un servicio de directorio alternativo), utilizando las rutinas getpwent(3) y getgrent(3).

El comodín ``*'' se puede usar para referirse a todos los nombres de instancia.

INSTALACIÓN

Si desea acceso a los nombres, texto de ayuda y valores para las métricas de rendimiento de tubería, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/pipe
# ./Install

Este es un proceso de instalación interactivo que solicita la ruta de cada archivo de registro a monitorizar (o comando a ejecutar), un nombre de instancia de métrica para identificarlo y si el acceso debe restringirse (consulte la opción -x de pmval(1) para más detalles).

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/pipe
# ./Remove

pmdapipe es iniciado por pmcd y nunca debe ejecutarse directamente. Los scripts de Instalación y Eliminación notifican a pmcd cuando el agente se instala o elimina.

EJEMPLOS

A continuación se presenta un ejemplo simple de configuración de pmdapipe y el uso de las métricas de tubería para ejecutar el comando btrace, por el usuario bob:


bob> cat $PCP_PMDAS_DIR/pipe/pipe.conf
# instancia      usuario      comando
rw_syscalls     root      perf script rw-by-file $1
bdev_trace      root      btrace -w $1 /dev/$2
[access]
allow user bob : *;
allow user jane : bdev_trace;
allow group perf : rw_syscalls;
bob> pmval -i bdev_trace -x '5 sda' pipe.firehose
 8,2  5  1  0.000000000 25227  A  WS 734332384 + 24 <- (253,2) 734330336
 8,0  5  2  0.000000414 25227  A  WS 735358432 + 24 <- (8,2) 734332384
 8,0  5  3  0.000000756 25227  Q  WS 735358432 + 24 [qemu-kvm]
 [...5 segundos de duración]
bob>

directorio que contiene archivos de configuración adicionales para las métricas de tubería

PCP ENVIRONMENT

Las siguientes variables de entorno pueden ser utilizadas para modificar el comportamiento de las utilidades de Performance Co-Pilot (PCP):

$PCP_CONF
Este es el nombre del archivo de configuración principal para las utilidades de PCP. Si no está configurado, el valor por defecto es /etc/pcp.conf.
$PCP_TMP
Este es el directorio donde las utilidades de PCP guardarán archivos temporales. Si no está configurado, el valor por defecto es /var/tmp.
$PCP_SOCKET
Este es el nombre del socket de dominio Unix para la comunicación entre las utilidades de PCP y el demonio de control de PCP (PCP Daemons). Si no está configurado, el valor por defecto es /var/run/pcproot/pcp.
$PCP_LOG_DIR
Este es el directorio donde se almacenan los archivos de registro de PCP. Si no está configurado, el valor por defecto es /var/log/pcp.
$PCP_PID_DIR
Este es el directorio donde se almacenan los archivos PID de los demonios de PCP. Si no está configurado, el valor por defecto es /var/run/pcp.
$PCP_DEMUX_PORT
Este es el número de puerto para el servicio de multiplexación de PCP. Si no está configurado, el valor por defecto es 44321.
$PCP_USER
Este es el nombre de usuario bajo el cual se ejecutan los demonios de PCP. Si no está configurado, el valor por defecto es pcp.
$PCP_GROUP
Este es el nombre del grupo bajo el cual se ejecutan los demonios de PCP. Si no está configurado, el valor por defecto es pcp.

OPCIONES DE DEBUGGING

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información es a veces críptica y está principalmente destinada a guiar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; utilice pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmdapipe son las siguientes:

Opción Descripción
appl0 procesamiento y generación de eventos, interacciones con pmcd(1), manejo de contexto de cliente, ejecución de comandos
appl1 controles de acceso, diagnósticos de usuario y grupo
appl2 manejo de configfile, diagnósticos de argumentos de comando inválidos, manejo de select(2)
