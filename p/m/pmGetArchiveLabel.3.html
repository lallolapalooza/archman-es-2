PMGETARCHIVELABEL(3) Manual de funciones de biblioteca PMGETARCHIVELABEL(3)

NOMBRE

pmGetArchiveLabel - obtener el registro de etiqueta de un conjunto de archivos de métricas de rendimiento

SINOPSIS C

#include <pcp/pmapi.h>

int pmGetArchiveLabel(pmLogLabel *lp);

cc ... -lpcp

DESCRIPCIÓN

Dentro del marco del Performance Co-Pilot (PCP), los archivos de valores de métricas de rendimiento pueden ser acumulados y guardados usando el programa pmlogger(1) y la interfaz de programación LOGIMPORT(3).

Las rutinas pmGetArchiveLabel pueden ser usadas para obtener el registro de etiqueta de un conjunto de archivos que ya ha sido abierto usando pmNewContext(3), o pmDupContext(3), y por lo tanto asociado con el contexto actual de la Interfaz de Programación de Aplicaciones de Métricas de Rendimiento (PMAPI).

El resultado devuelto a través del puntero lp es una estructura que debe ser pre-asignada por el llamador y tiene el siguiente formato (definido en pmapi.h).


typedef struct {
  int        magic;       /* PM_LOG_MAGIC | número de versión del formato de archivo */
  pid_t      pid;         /* PID del registrador */
  struct timespec start;  /* inicio de este archivo */
  char       hostname[PM_MAX_HOSTNAMELEN];   /* nombre completo del host de recolección */
  char       timezone[PM_MAX_TIMEZONELEN];   /* $TZ genérico, comprimido */
  char       zoneinfo[PM_MAX_ZONEINFOLEN];   /* $TZ de la plataforma local */
} pmLogLabel;

pmGetArchiveLabel puede ser usado con archivos de versión 2 o versión 3, sin embargo, puede ser necesario algún mapeo con los archivos de la versión 2 más antigua, por ejemplo, la hora de start solo tiene resolución de microsegundos y el campo zoneinfo no está presente. Para información detallada sobre el formato del archivo en disco, consulte LOGARCHIVE(5).

Para una aplicación que usa pmGetArchiveLabel, la información más útil de la etiqueta del archivo probablemente estará en los campos start, hostname, timezone, y zoneinfo.

El campo zoneinfo contiene la información de zona horaria más detallada disponible, y debe usarse si está presente (cadena de longitud no cero). Solo no estará presente en el caso de archivos de versión 2; este es un nuevo campo agregado como parte del formato de versión 3. El campo timezone siempre estará presente, sin embargo, es el valor de zona horaria 'comprimido' y en ciertas situaciones no es la zona horaria más precisa.

Para aplicaciones más antiguas que usan pmGetArchiveLabel, la información más útil de la etiqueta del archivo probablemente estará en los campos ll_start, ll_hostname o ll_tz. Tenga en cuenta que el tamaño del campo ll_hostname es PM_LOG_MAXHOSTLEN (64 bytes) que es menor que MAXHOSTNAMELEN (ver gethostbyname(3)) en algunas plataformas. Estas semánticas son necesarias para mantener la compatibilidad con versiones anteriores del formato de archivo PCP.

pmGetArchiveLabel devuelve cero en caso de éxito.

COMPATIBILIDAD

Antes de PCP 7.0 y libpcp.so.4, la estructura pmLogLabel era algo diferente. Para soportar la transición de PMAPI, la interfaz y las semánticas antiguas pueden usarse si las aplicaciones se enlazan con libpcp.so.3 o se recompilan con -DPMAPI_VERSION=2.

Durante un tiempo en PCP 6.x, existió una rutina con la misma semántica que la actual pmGetArchiveLabel llamada pmGetHighResArchiveLabel y una estructura con la misma definición que pmLogLabel llamada pmHighResLogLabel, aunque estas están ahora en desuso y el soporte en tiempo de compilación para pmGetHighResArchiveLabel y pmHighResLogLabel se eliminará en una futura versión.

DIAGNÓSTICOS

PM_ERR_NOCONTEXT
el contexto PMAPI actual es inválido o no está asociado con un conjunto de archivos

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5). Los valores para estas variables se pueden obtener programáticamente utilizando la función pmGetConfig(3).
