PMFIND_CHECK(1) Manual de Comandos Generales PMFIND_CHECK(1)

NOMBRE

pmfind_check - administración del descubrimiento del recopilador de Performance Co-Pilot

SINOPSIS

$PCP_BINADM_DIR/pmfind_check [-CNV?] [-l archivo_log]

DESCRIPCIÓN

Este script de shell se utiliza para integrar los mecanismos de descubrimiento del servicio recopilador de Performance Co-Pilot (ver PCPIntro(1)) con la administración de servicios de pmie(1) y pmlogger(1), de modo que múltiples hosts recopiladores puedan ser monitoreados desde un único host centralizado. Es importante notar que el servicio pmfind está estrechamente integrado con los servicios pmie y pmlogger, y estos también deben estar habilitados si los servicios van a ser iniciados para cada sistema recopilador que pmfind descubra.

pmfind_check está diseñado para ser habilitado a través de un demonio de gestión de servicios como systemd(1) en Linux. Se ejecuta desde un temporizador de sistema (ya sea por systemd o por cron en otros sistemas). Una vez por intervalo de temporizador, pmfind intenta descubrir sistemas recopiladores de PCP. Para cada sistema único encontrado, pmfind_check crea entradas de control de pmie_check y pmlogger_check, de modo que estos últimos procesos puedan gestionar un servicio pmie y pmlogger para cada sistema recopilador descubierto.

Cuando se ejecuta a través de systemd, estos procesos se iniciarán inmediatamente porque systemd monitorea los archivos de control del servicio en busca de cambios. Con systemd, también puede iniciar un descubrimiento de servicios inmediato con pmfind y pmfind_check modificando el directorio $PCP_SYSCONF_DIR/pmfind de cualquier manera.

Cuando se ejecuta desde cron, la próxima invocación (también basada en temporizador) de pmie_check o pmlogger_check iniciará y gestionará los procesos pmie y pmlogger asociados.

Las entradas de control creadas por pmfind_check siguen la convención de archivos individuales para cada host recopilador. Los archivos se nombran utilizando el identificador de origen (único) que pmfind calcula. Este identificador es un hash calculado en base a etiquetas de contexto (no opcionales) disponibles en cada host recopilador, y es el mismo identificador de origen que reportan y usan pminfo(1) y pmseries(1).

OPCIONES

Las opciones de línea de comandos disponibles son:

-C, --contenedores
Esta opción hace que pmfind_check consulte a cada sistema recopilador descubierto también por contenedores en ejecución, los cuales serán monitoreados individualmente.
-l archivo, --archivo_log=archivo
Para asegurar que no se envíe correo electrónico involuntariamente cuando estos scripts se ejecutan desde cron(8), los diagnósticos siempre se envían a archivos de log. Por defecto, este archivo es $PCP_LOG_DIR/pmfind/pmfind_check.log, pero esto puede cambiarse usando la opción -l. Si este archivo de log ya existe cuando el script comienza, se renombrará con un sufijo .prev (sobrescribiendo cualquier archivo de log guardado anteriormente) antes de que se generen los diagnósticos en el nuevo archivo de log.
-N, --mostrarmeyo
Esta opción habilita un modo de "mostrarme", donde las acciones de los programas se muestran, pero no se ejecutan, al estilo de "make -n". El uso de -N junto con -V maximiza las capacidades de diagnóstico para depuración.
-V, --verbose
La salida de la ejecución de los scripts por cron puede ser extendida usando la opción -V a los scripts, lo que habilitará el rastreo detallado de su actividad. Por defecto, los scripts no generan ninguna salida a menos que se encuentre alguna condición de error o advertencia. El uso de -N junto con -V maximiza las capacidades de diagnóstico para depuración.
-?, --ayuda
Mostrar mensaje de uso y salir.

CONFIGURACIÓN

Las opciones de línea de comandos pasadas a pmie y pmlogger pueden ser personalizadas a través del archivo de configuración $PCP_SYSCONFIG_DIR/pmfind.

Consulte las páginas del manual de pmie_check y pmlogger_check para obtener detalles sobre el formato del archivo de control generado por pmfind_check.

Por defecto, el archivo de log pmie de cada sistema recopilador se creará en $PCP_LOG_DIR/pmie/fuente y los archivos de archivo pmlogger se crearán debajo de $PCP_ARCHIVE_DIR/fuente. Esto es consistente con la forma en que pmie(1) y pmlogger(1) mantienen sus archivos de log y de archivo.

Las entradas típicas de crontab(5) para la ejecución periódica de pmfind_check se encuentran en $PCP_SYSCONF_DIR/pmfind/crontab (a menos que se instale por defecto en /etc/cron.d ya) y se muestran a continuación.

# cada minuto, descubre servicios remotos de PCP
*       *       *       *       *       $PCP_BINADM_DIR/pmfind_check
Cuando se usa systemd(1) en Linux, no se necesitan entradas de crontab ya que se utilizan en su lugar los mecanismos de temporizador y ruta proporcionados por systemd.

ARCHIVOS

$PCP_PMIECONTROL_PATH.d
Archivos de control del motor de inferencia de PCP para cada fuente de métrica descubierta, típicamente uno por host o contenedor.
Advertencia: los archivos aquí contenidos no deben ser escribibles por ningún usuario que no sea root.
$PCP_PMLOGGERCONTROL_PATH.d
Archivos de control del registrador de PCP para cada fuente de métrica descubierta, típicamente uno por host o contenedor.
Advertencia: los archivos aquí contenidos no deben ser escribibles por ningún usuario que no sea root.
$PCP_SYSCONFIG_DIR/pmfind
Argumentos de línea de comandos predeterminados para pmie y pmlogger, y otros parámetros pasados a pmfind.
$PCP_SYSCONF_DIR/pmfind/crontab
Ejemplo de crontab para ejecución automatizada del script por root - solo existe si la plataforma no soporta el mecanismo de /etc/cron.d.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

pmfind_check(1)

SYNOPSIS

pmfind_check [-h] [-l] [-c config] [pattern]

DESCRIPTION

pmfind_check searches for PCP metrics and instances whose names match the specified pattern. If no pattern is specified, pmfind_check will list all available metrics and instances.

OPTIONS

-h
Print a help message and exit.
-l
List all available metrics and instances, regardless of the pattern.
-c config
Use the specified configuration file. If not specified, the default configuration file is used.

CONFIGURATION

The configuration file is used to specify the sources to search for metrics and instances. The file is divided into sections, each representing a source. The following options are available:

source
The name of the source.
path
The path to the source.

FILES

/etc/pmfind_check.conf
Default configuration file.

PCP ENVIRONMENT

See pmfind_check(1) for details on the PCP environment.
