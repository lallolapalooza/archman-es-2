NOMBRE

pmdaperfevent - agente de dominio de métricas de rendimiento de contadores de rendimiento de hardware (PMDA)

SINOPSIS

$PCP_PMDAS_DIR/perfevent/pmdaperfevent [-d dominio] [-l archivo_log] [-U nombre_usuario] [-i puerto] [-p] [-u socket] [-6]

DESCRIPCIÓN

pmdaperfevent es un Agente de Dominio de Métricas de Rendimiento (PMDA) que configura y lee los contadores de rendimiento de hardware utilizando la API perf_event del kernel de Linux.

El PMDA perfevent exporta métricas para los contadores de rendimiento de hardware que son configurables desde la API perf_event del kernel de Linux. El PMDA utiliza la biblioteca libpfm4 para acceder a los contadores de rendimiento de hardware, por lo que cualquier contador que sea compatible con libpfm4 debería estar disponible. También se incluye la capacidad de leer los contadores Intel RAPL mediante acceso directo a MSR. El PMDA admite la carga automática de diferentes contadores para cada arquitectura de hardware. Se utiliza un único archivo de configuración para especificar los contadores deseados para cada unidad de monitoreo de rendimiento (PMU) de hardware. El archivo de configuración permite programar diferentes contadores en diferentes CPUs y admite la asignación rotatoria de contadores "uncore" necesarios para algunos chips AMD.

El PMDA también cuenta eventos expuestos en el kernel a través del directorio /sys/bus/event_source/devices. El nombre del dispositivo PMU y el nombre del evento deben mencionarse en el archivo de configuración. De lo contrario, la métrica no estará disponible para monitorear a través de este PMDA.

El PMDA configura los contadores para contar eventos tanto en modo usuario como en modo kernel. Esto significa que los contadores de hardware no están disponibles para su uso por aplicaciones de usuario normales sin privilegios cuando están en uso por el PMDA. El PMDA proporciona un mecanismo para deshabilitar temporalmente los contadores a nivel de sistema para permitir que los usuarios normales puedan usar los contadores si lo desean. Consulte perfalloc(1) para obtener detalles.

Tenga en cuenta que pmdaperfevent se ve afectado por el valor de la configuración kernel.perf_event_paranoid, que se puede ajustar con sysctl(8).

A continuación, se incluye una breve descripción de las opciones de línea de comandos de pmdaperfevent:

-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y consistente. Es decir, dominio debe ser diferente para cada PMDA en el mismo host, y se debe usar el mismo número de dominio para el mismo PMDA en todos los hosts.
-l
Ubicación del archivo de registro. Por defecto, se escribe un archivo de registro llamado perfevent.log en el directorio actual de pmcd(1) cuando se inicia pmdaperfevent, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de registro no se puede crear o no es escribible, la salida se escribe en el error estándar en su lugar.
-U
Cuenta de usuario bajo la cual se ejecutará el agente. El valor por defecto es la cuenta privilegiada de "root".
-i
escuchar en el número de puerto dado para la conexión desde pmcd(1)
-p
comunicarse con pmcd(1) a través de stdin/stdout
-u
esperar que pmcd(1) se conecte en el socket de dominio de unix dado
-6
esperar que pmcd(1) se conecte en el puerto ipv6 dado (número o nombre)

INSTALACIÓN

El PMDA perfevent no está activado por defecto. Para instalar el PMDA, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/perfevent
# ./Install

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/perfevent
# ./Remove

pmdaperfevent es lanzado por pmcd(1) y nunca debe ejecutarse directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o elimina.

ACTUALIZACIÓN

Algunos nombres de métricas han cambiado a partir de la versión 3.10.8 para cumplir mejor con las convenciones de PMNS. Se puede usar pmlogrewrite(1) para actualizar archivos antiguos. Una utilidad auxiliar, $PCP_PMDAS_DIR/perfevent/perfevent-makerewrite.pl generará un archivo de configuración adecuado para usar con pmlogrewrite(1) para actualizar los nombres de las métricas en archivos existentes.

ERRORES

Cada evento se coloca en su propio grupo y no hay forma de agrupar eventos relacionados para garantizar que estén activos simultáneamente. Una solución a esto es asegurarse de que el número de eventos configurados sea menor o igual al número de contadores de hardware disponibles. Esto significa que los eventos no serán multiplexados en el tiempo por el kernel y estarán activos simultáneamente.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

    pmdaperfevent - un script de controlador de PMDA para eventos de rendimiento del kernel de Linux

    Sinopsis

    pmdaperfevent [ -h | --help ] [ -V | --version ] [ interval [ pcp_options ] ]

    Descripción

    pmdaperfevent es un script que actúa como un controlador para el PMDA de eventos de rendimiento (perf_event) de PCP, permitiendo la recolección de métricas de eventos de rendimiento del kernel de Linux.

    El script se invoca típicamente por el sistema de control de PCP (como pmcd) y no se espera que el usuario final lo ejecute directamente, a menos que esté configurando o depurando el PMDA.

    Cuando se ejecuta, pmdaperfevent inicializa la recolección de contadores de eventos de rendimiento especificados (a través de la configuración del PMDA) y publica las métricas resultantes en el espacio de nombres de Performance Co-Pilot (PCP).

    Los eventos de rendimiento del kernel se basan en la interfaz perf_events de Linux, que proporciona un mecanismo para medir la actividad del hardware y del kernel, como caídas de caché, instrucciones ejecutadas, ciclos de reloj, etc.

    Opciones

    El script pmdaperfevent puede aceptar las siguientes opciones:

    • -h, --help: Muestra un mensaje de ayuda y sale.
    • -V, --version: Muestra la información de la versión y sale.

    Además de estas opciones, el script también puede aceptar un argumento interval y argumentos pcp_options que se pasan al demonio de recolección de PCP (pmlogger) si se está ejecutando en ese modo. El interval especifica el intervalo de muestreo en segundos.

    Ejemplos

    Para ejecutar pmdaperfevent en modo de depuración con un intervalo de muestreo de 10 segundos y pasar opciones adicionales a pmlogger:

    $ pmdaperfevent 10 --archive async -o myarchive

    Esto iniciaría la recolección de métricas de eventos de rendimiento cada 10 segundos, archivaría los datos de forma asíncrona en un archivo llamado myarchive.
