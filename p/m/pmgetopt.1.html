NOMBRE

pmgetopt - Analizador de opciones de scripts de shell de Performance Co-Pilot

SINOPSIS

$PCP_BINADM_DIR/pmgetopt [-u?] [-c archivo] [-D depuración] [-p nombre] [--] [parámetros]

DESCRIPCIÓN

pmgetopt se utiliza para realizar el análisis de opciones de línea de comandos para scripts de shell utilizados en el conjunto de herramientas Performance Co-Pilot (PCP). También se utiliza para generar mensajes de uso para esos scripts.

Los parámetros dados a pmgetopt toman dos formas: inicialmente, se pasan opciones específicas de pmgetopt, terminadas mediante el mecanismo --. Posteriormente, todos los parámetros pasados al script de shell deben pasarse (generalmente esto es simplemente la variable "$@").

OPCIONES

Las opciones de línea de comandos disponibles son:

-c=archivo, --config=archivo
Se pasa un archivo de configuración archivo en el formato descrito a continuación a pmconfig utilizando esta opción. Si se omite esta opción, pmconfig leerá su configuración desde el flujo de entrada estándar.
-p=nombre, --progname=nombre
Al analizar los parámetros del script de shell que llama, los mensajes de error y uso contendrán el nombre del programa dado en lugar de referirse a pmgetopt como la fuente del error.
-u, --usage
Se puede generar un mensaje de uso apropiado para que el script de shell que llama lo presente como propio utilizando esta opción.
-?, --help
Muestra el mensaje de uso para pmgetopt y sale.

pmgetopt analiza los parámetros dados y produce una salida en un formato adecuado para ser incluido (sourced) en el script de shell que llama. Cuando tanto las formas cortas como las largas de un argumento están permitidas por la especificación, pmgetopt siempre indicará la forma corta para un procesamiento más simple del shell. Si se presentan argumentos que no coinciden con la configuración, se generará una solicitud de mensaje de uso (-?) para que el script que llama responda. Los parámetros que no sean opciones se repetirán al script que llama precedidos por el delimitador de doble guion. Por lo tanto, un script debe dejar de manejar opciones cuando se detecte este delimitador y comenzar a manejar cualquier argumento que no sea una opción.

A diferencia del comando interno del shell getopt, las variables como $OPTARG no se establecen y el script que llama normalmente empleará el uso de los comandos internos del shell eval, set y el shift posicional para asegurar que el procesamiento de opciones ocurra correctamente.

CONFIGURACIÓN

El formato de configuración utilizado por pmgetopt está destinado a reflejar de cerca el mensaje de uso que se generaría en presencia de argumentos inválidos (o la opción -?, --help).

Hay principalmente dos tipos de línea de configuración: comandos y opciones. Los comandos permiten pasar metadatos al proceso de análisis de opciones, y las opciones son las opciones de línea de comandos permitidas que aceptará el script de shell. Las líneas de comando van precedidas por el carácter de almohadilla (#), mientras que las líneas de opción siempre comenzarán con un guion (simple o doble). Cualquier otra línea en la configuración, que puede incluir encabezados de uso o texto descriptivo, no afecta al análisis de opciones y se copiará sin modificaciones al mensaje de uso.

El conjunto de comandos es: getopt (proporcionar la especificación de opción de argumento corto manualmente, si no está presente se generará a partir de las opciones presentadas), usage (proporcionar un resumen de una línea utilizado en el encabezado del mensaje de uso, que será precedido por el progname antes de informar), y end, que informa a pmgetopt que deje de procesar comandos y opciones posteriores; cualquier texto posterior encontrado se agregará simplemente al mensaje de uso.

Existe una notación abreviada para cada una de las opciones estándar de PCP, como se describe en PCPIntro(1). Si alguna de estas opciones (por ejemplo, --host) aparece como una sola palabra en cualquier línea, se transformará en la opción apropiada para el script de shell, incluyendo todos los metadatos sobre esa opción (si acepta un argumento, formas de opción cortas y largas, etc.).

El uso del símbolo de igual ("=") indica la presencia de un argumento requerido para cualquier opción, tanto para formas cortas como largas. Cualquier opción no estándar debe ir acompañada de una descripción no vacía de ese argumento.

EJEMPLOS

Como ejemplo, la siguiente es una configuración válida: 

# Uso: [opciones] nodo...
Opciones:
    --archive
    -d, --delay            pausa entre actualizaciones para reproducir archivo
    --host
    --interval
    -i=INST, --insts=INST  lista de instancias de métricas separadas por comas
    -r                     mostrar contadores brutos (sin conversión de tasa)
    --width=N              establecer el ancho de cada columna de salida
    --timezone


Esta configuración producirá el siguiente mensaje de uso, cuando se ejecute como se muestra. 

$ pmgetopt --usage --progname=clusterstat -- "$@"
Uso: clusterstat [opciones] nodo...
Opciones:
  -a ARCHIVO, --archive=ARCHIVO
                        fuente de métricas es un archivo PCP
  -d, --delay           pausa entre actualizaciones para reproducir archivo
  -h HOST, --host=HOST  fuente de métricas es PMCD en host
  -t DELTA, --interval=DELTA
                        intervalo de muestreo
  -i INST, --insts=INST lista de instancias de métricas separadas por comas
  -r                    mostrar contadores brutos (sin conversión de tasa)
  --width=N             establecer el ancho de cada columna de salida
  -Z TZ, --timezone=TZ  establecer la zona horaria de reporte
  -?, --help            mostrar este mensaje de uso y salir


Varios ejemplos de uso de pmgetopt forman parte del conjunto de herramientas PCP, en particular los scripts pcp(1) y pmlogmv(1) proporcionan buenos ejemplos de referencia.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede utilizar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a resolver problemas, aunque la información a veces es críptica y está destinada principalmente a guiar a los desarrolladores en lugar de a los usuarios finales. depuración es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

VER TAMBIÉN

pcp(1), pmlogmv(1), pmgetopt_r(3), pcp.conf(5) y pcp.env(5).

NOMBRE

pmgetopt - analizar opciones para herramientas PCP

SINOPSIS

pmgetopt [-?] [-a] [-c config] [-d] [-D debug] [-h] [-i] [-k] [-l] [-m] [-n] [-o] [-p] [-r] [-s] [-t] [-u] [-v versión] [-w] [-- argumentos]

DESCRIPCIÓN

pmgetopt es una utilidad que lee las opciones de la línea de comandos y las traduce a la entrada estándar o a un archivo especificado, siguiendo el formato de entrada estándar de las herramientas Performance Co-Pilot (PCP). Está diseñado para facilitar la implementación de interfaces de línea de comandos consistentes para las herramientas PCP.

pmgetopt procesa los argumentos de la línea de comandos, aplica opciones de configuración y genera una salida formateada que puede ser consumida por otras herramientas PCP.

OPCIONES

  • -?, --help: Muestra un mensaje de ayuda y sale.
  • -a, --all: Habilita todas las opciones de depuración.
  • -c config, --config= config: Especifica un archivo de configuración.
  • -d, --debug: Habilita la depuración básica.
  • -D debug, --debug-mask= debug: Establece una máscara de depuración específica.
  • -h, --host: Incluye el nombre del host en la salida.
  • -i, --instance: Incluye la instancia de métrica en la salida.
  • -k, --kernel: Incluye información del kernel en la salida.
  • -l, --long: Formato de salida largo.
  • -m, --metrics: Incluye nombres de métricas en la salida.
  • -n, --nodelim: Usa un delimitador de nodo.
  • -o, --output archivo: Escribe la salida en el archivo especificado.
  • -p, --port: Incluye información del puerto en la salida.
  • -r, --raw: Formato de salida sin procesar.
  • -s, --summary: Muestra un resumen de las opciones procesadas.
  • -t, --timestamp: Incluye marcas de tiempo en la salida.
  • -u, --user: Incluye información del usuario en la salida.
  • -v versión, --version= versión: Especifica la versión de la salida.
  • -w, --wide: Formato de salida ancho.
  • --: Indica el final de las opciones de pmgetopt, los argumentos restantes se procesan como argumentos de la herramienta.

CONFIGURACIÓN

pmgetopt puede ser configurado mediante un archivo especificado con la opción -c. Este archivo puede contener directivas para modificar el comportamiento de pmgetopt, como establecer opciones predeterminadas o definir formatos de salida personalizados.

La sintaxis del archivo de configuración es la siguiente:

# Comentario
OPCIÓN=valor
OPCIÓN

Las opciones disponibles en el archivo de configuración corresponden a las opciones de la línea de comandos, pero sin el guion inicial.

EJEMPLOS

Ejemplo 1: Procesar opciones básicas y mostrar salida en la consola.

$ pmgetopt -h -m -- -s mi_servidor
# Host: mi_servidor
# Metrics:

Ejemplo 2: Escribir la salida formateada en un archivo.

$ pmgetopt -t -o salida.log -- -s otro_servidor

Esto procesará las opciones y escribirá la salida formateada, incluyendo marcas de tiempo, en el archivo salida.log.

ENTORNO_PCP

pmgetopt utiliza varias variables de entorno que pueden influir en su comportamiento:

  • PCP_CONFIG_PATH: Directorio donde buscar archivos de configuración.
  • PCP_DEBUG: Máscara de depuración para habilitar salidas de depuración.

OPCIONES_DE_DEPURACIÓN

pmgetopt soporta varias opciones de depuración para ayudar a diagnosticar problemas:

  • -d, --debug: Habilita la salida de depuración básica.
  • -a, --all: Habilita todas las opciones de depuración.
  • -D <debug>, --debug-mask=<debug>: Permite especificar una máscara de bits para habilitar conjuntos específicos de salidas de depuración. Por ejemplo, -D 1 podría habilitar la depuración de análisis de opciones, mientras que -D 2 podría habilitar la depuración de manejo de archivos. Consulte la documentación de PCP para obtener una lista completa de las máscaras de depuración disponibles.
