PMLOGLABEL(1) Manual de comandos generales PMLOGLABEL(1)

NOMBRE

pmloglabel - comprobar y reparar la etiqueta de un archivo de métricas de rendimiento

SINOPSIS

pmloglabel [-lLsv?] [-D debug] [-h hostname] [-p pid] [-V version] [-Z timezone] archivo

DESCRIPCIÓN

pmloglabel verifica, informa y puede modificar todos los detalles de las etiquetas en cada uno de los archivos de un archivo de Performance Co-Pilot (PCP). El nombre base del archivo es archivo y debe haber sido creado previamente usando pmlogger(1).

Cada uno de los archivos de un archivo de PCP (metadatos, índice temporal y uno o más volúmenes de datos) debe contener una etiqueta válida al principio, de lo contrario, las herramientas de PCP se negarán a abrir el archivo.

Por lo tanto, la función principal de pmloglabel es poder reparar cualquier campo de etiqueta inconsistente o corrupto, de modo que no se pierda todo el archivo. No comprobará el resto del archivo, pero le dará una buena oportunidad para recuperar datos que de otro modo se habrían perdido. En conjunto, pmloglabel y pmlogextract pueden producir un archivo PCP válido a partir de muchas formas de corrupción.

Tenga en cuenta que si se encuentra que el índice temporal está corrupto, el archivo "*.index" puede ser movido de manera segura a un lado y el archivo seguirá siendo accesible, sin embargo, las recuperaciones pueden tardar más sin el índice.

OPCIONES

Las opciones de línea de comandos disponibles son:

-h hostname, --host=hostname
Modifica el hostname registrado en la etiqueta del archivo, para todos los archivos del archivo.
-l, --label
Muestra la etiqueta del archivo, mostrando la versión del formato del archivo, la hora y fecha de inicio y fin (actual) del archivo, y el host desde el cual se recopilaron los valores de las métricas de rendimiento.
-L
Al igual que -l, pero un poco más detallado, mostrando también la zona horaria y el identificador del proceso creador de la etiqueta del archivo.
-p pid, --pid=pid
Establece el identificador del proceso almacenado en la etiqueta del archivo a pid, para todos los archivos del archivo.
-s
Reescribe los valores centinela que preceden y siguen a la etiqueta del archivo, para todos los archivos del archivo.
-v, --verbose
Modo detallado. Se produce información adicional de progreso en cada paso.
-V version, --version=version
Estampa el número de version en el campo del número mágico al principio de la etiqueta del archivo, para todos los archivos del archivo.
-Z timezone, --timezone=timezone
Cambia la zona horaria en las etiquetas del archivo a timezone en el formato de la variable de entorno TZ como se describe en environ(7).
-?, --help
Muestra el mensaje de uso y sale.

EJEMPLOS

Lo siguiente demuestra el uso de pmloglabel para encontrar y luego corregir un campo corrupto (PID) en la etiqueta del índice temporal de un archivo llamado "20080125".


$ pmlogdump -l 20080125
pmlogdump: No se puede abrir el archivo "20080125": registro de etiqueta ilegal al inicio de un archivo de PCP
$ pmloglabel 20080125
PID (5264/5011) no coincide entre el índice temporal y el volumen de datos 0
$ pmloglabel -p 5264 20080125
$ pmlogdump -l 20080125
Etiqueta de registro (Versión del formato de registro 2)
Métricas de rendimiento del host fw1
  comenzando el vie 25 ene 00:10:09.341 2008
  finalizando el sáb 26 ene 00:09:54.344 2008

ESTADO DE SALIDA

pmloglabel sale con estado 0 si las etiquetas del archivo están limpias. Si se invoca incorrectamente, el estado de salida será 1. Si se detecta corrupción y aún existe al final, el estado de salida será 2. Si se solicita escribir las etiquetas del archivo y algún aspecto de esa escritura falla, entonces el estado de salida será 3.

ARCHIVOS

$PCP_LOG_DIR/pmlogger/<hostname>
Directorio predeterminado para los archivos de PCP que contienen valores de métricas de rendimiento recopilados del host <hostname>.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información es a veces críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
