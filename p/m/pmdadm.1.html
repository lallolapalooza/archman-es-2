NOMBRE

pmdadm - Device Mapper PMDA

SINOPSIS

$PCP_PMDAS_DIR/dm/pmdadm [-D debug]

DESCRIPCIÓN

pmdadm es un Agente de Dominio de Métricas de Rendimiento (PMDA) que exporta valores métricos para Device Mapper en el sistema local.

Este PMDA recopila sus datos a través de la utilidad dmsetup(8) y la API de dmstats, y requiere que el programa esté instalado para funcionar. Además, se debe crear al menos una región de estadísticas usando la utilidad dmstats(8) para obtener valores de contador básicos. Ver más abajo para ejemplos.

Tenga en cuenta que la recopilación de estadísticas de device-mapper no está habilitada por defecto y no es persistente tras los reinicios (a menos que un administrador del sistema haya configurado algo para que se ejecute en rc.local o equivalente). Esto se debe a que existen sobrecargas asociadas con la recopilación de estadísticas. Además, el PMDA pmdadm no habilita automáticamente ninguna recopilación de estadísticas porque puede que no sea el único consumidor de los datos.

INSTALACIÓN

Instale el PMDA de DM usando el script de Instalación como root:

# cd $PCP_PMDAS_DIR/dm
# ./Install

Para desinstalar, se debe hacer lo siguiente como root:

# cd $PCP_PMDAS_DIR/dm
# ./Remove

pmdadm es lanzado por pmcd(1) y nunca debe ser ejecutado directamente. Los scripts Install y Remove notifican a pmcd cuando el agente es instalado o removido.

CONFIGURACIÓN

Este PMDA utiliza la API de dmstats (la biblioteca de soporte de device-mapper en el espacio de usuario) para capturar datos de rendimiento de device-mapper.
Usando este PMDA, los usuarios necesitan la biblioteca de soporte de device-mapper en el espacio de usuario (libdevmapper) y la herramienta de línea de comandos en el espacio de usuario dmstats(8). Antes de que las métricas de device-mapper estén disponibles para PCP, se deben crear regiones de estadísticas. Por ejemplo, para habilitar estadísticas básicas para todos los dispositivos lógicos de device-mapper locales, use el siguiente comando:

# dmstats create --alldevices

Para crear regiones de estadísticas con límites de histograma especificados, use lo siguiente:

# dmstats create --alldevices --bounds histogram_boundaries

Especifique los límites de un histograma de latencia a rastrear para la región como una lista separada por comas de valores de latencia. Los valores de latencia se dan en nanosegundos. Un sufijo de unidad opcional de ns, us, ms o s puede ser dado después de cada valor para especificar unidades de nanosegundos, microsegundos, milisegundos o segundos respectivamente. Por ejemplo,

# dmstats create --alldevices --bounds 10us,30us,50us,70us,90us

Más detalles y ejemplos más complejos se pueden encontrar en dmstats(8).

MÉTRICAS

Contadores Básicos
Los contadores básicos proporcionan acceso a los datos brutos del contador del kernel, permitiendo que otro programa realice un procesamiento adicional.
El Kernel proporciona trece contadores separados para cada área de estadísticas. Los primeros once coinciden con los contadores proporcionados en /proc/diskstats o /sys/block/*/*/stat. El par final proporciona contadores separados para el tiempo de lectura y escritura.
dmstats.read
Número de lecturas completadas en este intervalo por dispositivo de device-mapper.
dmstats.reads_merged
Número de lecturas fusionadas en este intervalo por dispositivo de device-mapper.
dmstats.read_bytes
Número de kbytes leídos en este intervalo por dispositivo de device-mapper.
dmstats.reads_time
Duración acumulada de todas las solicitudes de lectura por dispositivo de device-mapper.
dmstats.write
Número de escrituras completadas en este intervalo por dispositivo de device-mapper.
dmstats.writes_merged
Número de escrituras completadas en este intervalo por dispositivo de device-mapper.
dmstats.write_bytes
Número de kbytes escritos en este intervalo por dispositivo de device-mapper.
dmstats.writes_time
Duración acumulada de todas las solicitudes de escritura por dispositivo de device-mapper.
dmstats.in_progress
Número de solicitudes en curso por dispositivo de device-mapper.
dmstats.io_ticks
Nanosegundos dedicados a atender solicitudes por dispositivo de device-mapper.
dmstats.queue_ticks
Este campo se incrementa en cada inicio de E/S, finalización de E/S, fusión de E/S o lectura de estas estadísticas por el número de E/S en curso multiplicado por el número de nanosegundos dedicados a E/S desde la última actualización de este campo. Esto puede proporcionar una medida fácil tanto del tiempo de finalización de la E/S como de la acumulación de cola.
dmstats.read_ticks
Nanosegundos dedicados a atender lecturas por dispositivo de device-mapper.
dmstats.write_ticks
Nanosegundos dedicados a atender escrituras por dispositivo de device-mapper.
Campos de Histograma
Los histogramas miden la distribución de frecuencia de los intervalos de latencia de E/S especificados por el usuario. Los límites de los "bins" del histograma se especifican al crear una región.
El nombre de la instancia representa el nombre del dispositivo, el ID de la región y los límites de los "bins".
dmstats.histogram.hist_count
Una lista de los recuentos del histograma para el área de estadísticas actual en orden de valor de latencia ascendente. Cada valor representa el número de E/S con tiempos de latencia que caen en el rango de tiempo de ese "bin" durante el período de muestreo.
dmstats.histogram.hist.bins
El número de "bins" del histograma de latencia configurados para el área.

EJEMPLOS

# dmstats create looptest0 --bounds 10us,30us,50us
looptest0: Created new region with 1 area(s) as region ID 0


# pminfo -f dmstats.read dmstats.histogram.hist_count

dmstats.read
inst [0 or "looptest0"] value 4099

dmstats.histogram.hist_count
inst [0 or "looptest0:0:0s"] value 1
inst [1 or "looptest0:0:10us"] value 3752
inst [2 or "looptest0:0:30us"] value 250
inst [3 or "looptest0:0:50us"] value 96

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede ser utilizada para especificar una alternativa
