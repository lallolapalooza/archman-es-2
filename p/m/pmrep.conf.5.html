PMREP.CONF(5) Manual de Formatos de Archivo PMREP.CONF(5)

NOMBRE

pmrep.conf - archivo de configuración de pmrep

DESCRIPCIÓN

pmrep es una herramienta personalizable para reportar métricas de rendimiento. Cualquier métrica de rendimiento disponible, en vivo o archivada, del sistema y/o de la aplicación, puede ser seleccionada para su reporte usando una de las alternativas de salida disponibles junto con las opciones de formato aplicables.

Las métricas de interés se nombran en los argumentos metricspec en la línea de comandos de pmrep. Estos metricspecs definen métricas individuales o conjuntos de métricas de rendimiento predefinidos para ser leídos de los archivos de configuración descritos a continuación. Para detalles de los argumentos de la línea de comandos, consulte pmrep(1).

El archivo de configuración pmrep.conf permite establecer valores de tiempo de ejecución predeterminados y definir cualquier número de metricsets personalizados para pmrep. Un metricset es un conjunto arbitrario de métricas de rendimiento definido por el usuario. Esto permite a los usuarios crear metricsets específicamente diseñados y particularmente relevantes para su aplicación o entorno. En lugar de depender de lo que proporcionan las herramientas existentes o recopilar los datos necesarios con varias utilidades disjuntas, los usuarios pueden definir metricsets personalizados simplemente editando pmrep.conf. Consulte a continuación la especificación del metricset.

En caso de que los archivos de configuración de pmrep se lean de un directorio, los valores para las secciones [options] y [global] se combinarán de cada archivo donde estén definidos. La última definición de una directiva es la que prevalece, lo que significa que se utilizará la última definición en caso de que se defina varias veces. Sin embargo, las secciones de metricset personalizadas no se combinarán, solo se utilizará la última definición encontrada para el reporte.

Las opciones a través de valores de entorno (ver pmGetOptions(3)) anulan los valores predeterminados incorporados correspondientes (si los hay). Las opciones del archivo de configuración anulan las variables de entorno correspondientes (si las hay). Las opciones de la línea de comandos anulan las opciones del archivo de configuración correspondientes (si las hay).

FORMATO DEL ARCHIVO

El archivo tiene una sintaxis de estilo ini y consta de secciones y configuraciones. Una sección comienza con el nombre de la sección entre corchetes y continúa hasta que comienza la siguiente sección. Un ejemplo de sección con dos configuraciones sigue:

[sección]
clave = valor
clave2 = valor2

Los tipos de datos admitidos para los valores son cadena, entero y booleano. Los valores no deben ser entrecomillados, excepto cuando el valor consiste únicamente en espacios en blanco (es decir, un separador de columnas solo de espacios en blanco).

Un comentario de línea comienza con un signo de almohadilla (``#'') o un punto y coma (``;''). No se admiten comentarios en línea.

pmrep.conf debe ser legible por el usuario que invoca pmrep.

Cualquier opción descrita a continuación con una opción de línea de comandos correspondiente contiene una descripción funcional adicional en pmrep(1).

SECCIONES ESPECIALES

La sección [options]

La sección [options] se lee cada vez que se ejecuta pmrep y define las opciones predeterminadas de tiempo de ejecución. Estas opciones pueden ser anuladas por opciones específicas del metricspec o por opciones de la línea de comandos. Las métricas no están permitidas en esta sección.

Configuraciones permitidas

version (entero)

Indica la versión del archivo de configuración. El valor predeterminado es 1. El único valor admitido actualmente es 1.

source (cadena)

Indica la fuente de las métricas. Se interpreta como un archivo de métricas de PCP si el valor contiene una barra (``/''). Si se establece en el carácter especial ``@'', se utiliza el contexto de PMDA DSO local. De lo contrario, se interpreta como un nombre de host. Los parámetros correspondientes de la línea de comandos son -a, -h y -L. El valor predeterminado es local: (ver PCPIntro(1)).

output (cadena)

Indica el destino de la salida. Opción de línea de comandos correspondiente: -o. Para destinos de salida admitidos, consulte pmrep(1). El valor predeterminado es stdout.

speclocal (cadena)

Indica los PMDA DSO locales que se harán disponibles al usar el contexto de PMDA DSO local. Opción de línea de comandos correspondiente: -K. Para la descripción de la sintaxis, consulte pmSpecLocalPMDA(3). Use un punto y coma (``;'') para separar más de un spec. No definido por defecto.

derived (cadena)

Especificaciones de métricas derivadas. Opción de línea de comandos correspondiente: -e. Para la descripción de la sintaxis, consulte pmrep(1). No definido por defecto.

daemonize (booleano)

Indica si se debe convertir en un demonio al iniciar. Opción de línea de comandos correspondiente: --daemonize. El valor predeterminado es no.

header (booleano)

Indica si se deben imprimir las cabeceras. Opción de línea de comandos correspondiente: -H. El valor predeterminado es sí.

instinfo (booleano)

Indica si se debe incluir información de instancia como parte de las cabeceras. Opción de línea de comandos correspondiente: --no-inst-info. El valor predeterminado es sí.

unitinfo (booleano)

Indica si se debe incluir información de unidades como parte de las cabeceras. Opción de línea de comandos correspondiente: -U. El valor predeterminado es sí.

globals (booleano)

Indica si se deben incluir las métricas de la sección [global] (ver más abajo) para el reporte. Opción de línea de comandos correspondiente: -G. El valor predeterminado es sí.

timestamp (booleano)

Indica si se debe imprimir la marca de tiempo. Opción de línea de comandos correspondiente: -p. El valor predeterminado es no.

samples (entero)

Indica el número de muestras a imprimir. Opción de línea de comandos correspondiente: -s. No definido por defecto (significa un número ilimitado de muestras si no está limitado por otras opciones).

interval (cadena)

Indica el intervalo entre muestras. Opción de línea de comandos correspondiente: -o. Sigue la sintaxis de tiempo descrita en PCPIntro(1). El valor predeterminado es 1s.

delay (booleano)

Indica si se debe pausar entre muestras al reproducir desde un archivo en lugar de reproducir a toda velocidad. Opción de línea de comandos correspondiente: -d. El valor predeterminado es no.

type (cadena)

Indica si se deben emitir valores de métricas en bruto al deshabilitar todas las conversiones de tasas o convertir contadores acumulativos en tasas (predeterminado). Opción de línea de comandos correspondiente: -r. Los valores permitidos son default o raw.

type_prefer (cadena)

Igual que type pero no anula las posibles especificaciones de tipo por métrica. Opción de línea de comandos correspondiente: -R. Los valores permitidos son default o raw.

ignore_incompat (booleano)

Indica que las métricas incompatibles deben ser ignoradas. Opción de línea de comandos correspondiente: -I. El valor predeterminado es no.

ignore_unknown (booleano)

Indica que las métricas desconocidas deben ser ignoradas. Opción de línea de comandos correspondiente: -5. El valor predeterminado es no.

names_change (cadena)

Indica la acción a tomar ante cambios en PMNS durante el muestreo. Opción de línea de comandos correspondiente: -4. El valor predeterminado es ignore.

instances (cadena)

Indica las instancias a reportar. Opción de línea de comandos correspondiente: -i. No definido (se reportan todas las instancias) por defecto.

live_filter (booleano)

Indica que el filtrado en vivo debe estar habilitado. Opción de línea de comandos correspondiente: -j. El valor predeterminado es no.

rank (entero)

Indica el valor a utilizar para clasificar instancias. Opción de línea de comandos correspondiente: -J. No definido (se reportan todas las instancias) por defecto.

overall_rank (booleano)

Indica que se debe realizar una clasificación general. Opción de línea de comandos correspondiente: -2. El valor predeterminado es no.

overall_rank_alt (booleano)

Indica que se debe realizar una clasificación general con formato de salida alternativo. Opción de línea de comandos correspondiente: -3. El valor predeterminado es no.

NAME

pmrep.conf - pmrep(1) configuration file format

DESCRIPTION

The pmrep(1) utility uses configuration files to define default options, known metricsets and derived metrics.

Configuration files are processed in the following order:

  1. The command line options override any settings from configuration files.
  2. The configuration file specified with the pmrep(1) --config option.
  3. The file pmrep.conf(5) in the user’s home directory (~/.pcp/pmrep.conf).
  4. The system wide configuration file ($PCP_SYSCONF_DIR/pmrep/pmrep.conf).

Multiple configuration files may be present and are processed in the order mentioned above. If a configuration file contains duplicate sections, only the first occurrence is used.

FILE FORMAT

The configuration file is a text file composed of sections, comments and directives.

Sections are delimited by square brackets, e.g. [section]. The first section may optionally be preceded by a [options] section that affects the global behavior of pmrep.

Comments start with a hash mark (#) and extend to the end of the line.

Directives are key-value pairs, separated by an equals sign (=). Keys and values are case-sensitive. Values can be strings, integers, or booleans (yes/no).

Strings can be enclosed in double quotes ("). Any characters can be used within double quotes, including spaces and the equals sign. Double quotes inside a quoted string must be escaped with a backslash (\).

The directives are described in the following sections.

SPECIAL SECTIONS

[options]
This section is optional and must appear at the beginning of the file. It contains directives that affect the global behavior of pmrep. Supported directives are:
timestamp [yes|no] [default: yes]
If set to yes, a timestamp is printed before each line of output.
interval time [default: 1s]
The interval for fetching performance metrics. time is a string representing a time duration, e.g. 1s, 100ms, 2m.
extheader [yes|no] [default: no]
If set to yes, print an extended header line before the first line of output.
repeat_header [auto|yes|no] [default: auto]
If set to yes, print the header line before each line of output. If set to auto, the header is repeated every 100 lines.
space_scale unit [default: bytes]
Specifies the scale unit for displaying byte counts. Supported units are B (bytes), KB, MB, GB, TB, PB.
delimiter char [default: \t]
Specifies the delimiter character between columns. Defaults to a tab character. Use " " for a space.
precision digits [default: 0]
Specifies the number of digits after the decimal point for floating point numbers.
[global]
This section can be used to define global metrics, which are then available to all metricsets. Directives are of the form:
name = metric[,pmid][,...] [,instances] [,width]
Defines a derived metric named name. The metric is a PCP metric name or a comma-separated list of metric names. If provided, pmid is the numeric Performance Metrics Identifier. instances can be a comma-separated list of instance names or all. width specifies the minimum field width for this metric in the output. See also METRICSET SPECIFICATION.
name.formula = expression
Defines a derived metric name using a formula. The expression can involve other derived metrics or PCP metrics. See pmRegisterDerived(3) for details on the formula syntax.
name.width = width
Specifies the minimum field width for the derived metric name.
name.label = label
Specifies a custom label for the derived metric name.

CUSTOM SECTIONS

Any section not starting with an underscore (_) is treated as a metricset definition. The name of the section is the name of the metricset.

Supported directives within a metricset section are:

source = hostname[:port]
Specifies the Performance Metrics Data Access (PMDA) source host. Defaults to localhost.
set = metric[,pmid][,...] [,instances] [,width]
Defines a metricset. The metric is a PCP metric name or a comma-separated list of metric names. If provided, pmid is the numeric Performance Metrics Identifier. instances can be a comma-separated list of instance names or all. width specifies the minimum field width for this metric in the output. See also METRICSET SPECIFICATION.
set.formula = expression
Defines a derived metric within the metricset using a formula. The expression can involve other derived metrics or PCP metrics. See pmRegisterDerived(3) for details on the formula syntax.
set.width = width
Specifies the minimum field width for the derived metric within the metricset.
set.label = label
Specifies a custom label for the derived metric within the metricset.
globals [yes|no] [default: yes]
If set to yes, metrics defined in the [global] section are included in this metricset.
timestamp [yes|no]
Overrides the global timestamp setting for this metricset.
interval time
Overrides the global interval setting for this metricset.
extheader [yes|no]
Overrides the global extheader setting for this metricset.
repeat_header [auto|yes|no]
Overrides the global repeat_header setting for this metricset.
space_scale unit
Overrides the global space_scale setting for this metricset.
delimiter char
Overrides the global delimiter setting for this metricset.
precision digits
Overrides the global precision setting for this metricset.

All other directives are interpreted as metric specifications for the current metricset, following the same syntax as the set directive.

METRICSET SPECIFICATION

A metric specification defines which performance metrics to collect and how to display them. The general syntax is:

metric spec = name[,pmid][,...] [,instances] [,width]

Where:

name
The name of the metric or a comma-separated list of metric names. This can also be a comma-separated list of derived metric names defined in the [global] section or in the current metricset.
pmid
Optional. The numeric Performance Metrics Identifier (PMID) of the metric. If specified, it overrides the metric name lookup.
instances
Optional. A comma-separated list of instance names to fetch, or the keyword all to fetch all available instances.
width
Optional. The minimum field width for this metric in the output. If the value is negative, the field is right-aligned.

Verbose Form

The verbose form of a metric specification allows specifying options for individual metrics within a metricset. It uses the dot notation, e.g.:

metric.option = value

For example:

kernel.all.sysfork = forks,,,,8

This defines a metric named kernel.all.sysfork with a display width of 8. The commas are used as placeholders for missing fields (pmid, instances).

The following options are supported:

pmid
The numeric PMID.
instances
A comma-separated list of instance names or all.
width
The minimum field width.
label
A custom label for the metric.
scale
Scale factor for the metric value.
unit
Unit of the metric (e.g., "B", "K", "M", "G").
precision
Number of digits after the decimal point.
delimiter
Delimiter for the output.

If a metric specification does not contain a dot (.), it is assumed to be the simple form.

EXAMPLE

The following example configuration file defines several options and metricsets:

[options]
timestamp = yes
interval = 2s
extheader = yes
repeat_header = auto
space_scale = MB
[global]
kernel.all.sysfork = forks,,,,8
cacheall = mem.util.allcache
cacheall.formula = mem.util.bufmem + mem.util.cached + mem.util.slab
cacheall.width = 12
[db1]
source = db-host1.example.com
set = postgresql
[db2]
source = db-host2.example.com
set = postgresql
[sar-w]
header = yes
unitinfo = no
globals = no
timestamp = yes
precision = 2
delimiter = " "
kernel.all.sysfork = proc/s,,,,12
kernel.all.pswitch = cswch/s,,,,9

This configuration defines the following:

  • Global options: timestamps enabled, interval of 2 seconds, extended header, auto repeat header, and space scale in MB.
  • A global derived metric cacheall that sums up buffer cache, page cache and slab cache, with a field width of 12.
  • Two metricsets, db1 and db2, both fetching PostgreSQL metrics from different hosts. The set = postgresql directive uses the verbose form by not specifying a dot. This implies all metrics related to the postgresql PMDA are included.
  • A metricset sar-w that mimics the output of the sar -w command. It has its own header, no unit information, does not include global metrics, has timestamps enabled, precision of 2, and uses a space as a delimiter. It explicitly defines the metrics kernel.all.sysfork and kernel.all.pswitch with specific instance names and widths.

The system default pmrep configuration files contain many more examples. The tab key on the command line after a colon completes available metricsets (with bash and zsh).

FILES

$PCP_SYSCONF_DIR/pmrep/.conf
system provided default pmrep configuration files

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).
