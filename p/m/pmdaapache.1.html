PMDAAPACHE(1) Manual de comandos generales PMDAAPACHE(1)

NOMBRE

pmdaapache - agente de dominio de métricas de rendimiento del servidor web Apache2 (PMDA)

SINOPSIS

$PCP_PMDAS_DIR/apache/pmdaapache [-D debug] [-d dominio] [-l logfile] [-U usuario] [-S servidor] [-P puerto] [-L ubicacion]

DESCRIPCIÓN

pmdaapache es un Agente de Dominio de Métricas de Rendimiento (PMDA) que extrae métricas de rendimiento que describen el estado de un servidor web Apache.

El PMDA apache exporta métricas que miden la tasa de peticiones, tamaños acumulados de peticiones, tiempo de actividad y varios estados de conexión para clientes activos.

Esta información se obtiene realizando una petición HTTP a la URL de estado del servidor, la cual debe estar habilitada en el archivo de configuración httpd.conf.

ExtendedStatus on
<Location /server-status>
SetHandler server-status
Order deny,allow
Deny from all
Allow from localhost
</Location>

A continuación se incluye una breve descripción de las opciones de línea de comandos de pmdaapache:

-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y coherente. Es decir, dominio debe ser diferente para cada PMDA en el mismo host, y el mismo número de dominio debe usarse para el mismo PMDA en todos los hosts.
-l
Ubicación del archivo de registro. Por defecto, se escribe un archivo de registro llamado apache.log en el directorio actual de pmcd(1) cuando se inicia pmdaapache, es decir, $PCP_LOG_DIR/pmcd . Si el archivo de registro no se puede crear o no es escribible, la salida se escribe en el error estándar en su lugar.
-S
Consultar la información de estado de Apache desde el servidor nombrado en lugar del host local.
-P
Consultar la información de estado de Apache desde el puerto dado en lugar del predeterminado (80).
-L
Especificar una ubicacion alternativa para encontrar la página server-status.
-U
Cuenta de usuario bajo la cual se ejecutará el agente. El valor predeterminado es la cuenta sin privilegios "pcp" en las versiones actuales de PCP, pero en versiones anteriores se utilizaba la cuenta de superusuario ("root") por defecto.

INSTALACIÓN

Si desea acceso a los nombres, texto de ayuda y valores de las métricas de rendimiento de apache, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/apache
# ./Install

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/apache
# ./Remove

pmdaapache es iniciado por pmcd(1) y nunca debe ser ejecutado directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o se elimina.

ARCHIVOS

$PCP_PMCDCONF_PATH
opciones de línea de comandos utilizadas para iniciar pmdaapache
$PCP_PMDAS_DIR/apache/help
archivo de texto de ayuda predeterminado para las métricas de apache
$PCP_PMDAS_DIR/apache/Install
script de instalación para el agente pmdaapache
$PCP_PMDAS_DIR/apache/Remove
script para deshacer la instalación del agente pmdaapache
$PCP_LOG_DIR/pmcd/apache.log
archivo de registro predeterminado para mensajes de error y otra información de pmdaapache

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a depurar problemas, aunque la información a veces es críptica y está destinada principalmente a guiar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas de pmdaapache son las siguientes:

Opción Descripción
appl0 rastrea cada llamada a refreshData()
appl1 informa de los errores detectados en refreshData()
appl2 descarga los datos internos después de cada llamada a refreshData()
