PMLOGGER_CHECK(1) Manual general de comandos PMLOGGER_CHECK(1)

NOMBRE

pmlogger_check - administración de archivos de archivo de Performance Co-Pilot

SINOPSIS

$PCP_BINADM_DIR/pmlogger_check [-CNnPpqsTV?] [-c control] [-l logfile]

DESCRIPCIÓN

pmlogger_check y las herramientas relacionadas pmlogger_daily(1), junto con los archivos de control asociados (ver pmlogger.control(5)), pueden ser utilizados para crear un régimen personalizado de administración y gestión de archivos históricos de datos de rendimiento dentro de la infraestructura de Performance Co-Pilot (ver PCPIntro(1)).

pmlogger_check puede ejecutarse en cualquier momento del día y está destinado a verificar que un conjunto deseado de procesos pmlogger(1) esté en ejecución. Si no es así, (re)inicia los procesos de logger ausentes. Por defecto, pmlogger_check también llama a pmlogger_daily(1) con una opción -K para ejecutar cualquier tarea de compresión de archivo requerida.

OPCIONES

-C
Esta opción hace que pmlogger_check consulte la información del nivel de ejecución del servicio del sistema para pmlogger, y la utilice para determinar si iniciar procesos o no.
-c control, --control=control
Tanto pmlogger_check como pmlogger_daily(1) son controlados por archivos de control de logger de PCP (ver pmlogger.control(5)) que especifican las instancias de pmlogger a gestionar. El archivo de control predeterminado es $PCP_PMLOGGERCONTROL_PATH, pero se puede especificar uno alternativo usando la opción -c. Si existe el directorio $PCP_PMLOGGERCONTROL_PATH.d (o control.d de la opción -c), el contenido de cualquier archivo de control adicional allí se añadirá al archivo de control principal (que debe existir).
-l archivo, --logfile=archivo
Para asegurar que no se envíe correo electrónico no intencionalmente cuando estos scripts se ejecutan desde cron(8) o systemd(1), los diagnósticos siempre se envían a archivos de registro. Por defecto, este archivo es $PCP_LOG_DIR/pmlogger/pmlogger_check.log, pero esto puede cambiarse usando la opción -l. Si este archivo de registro archivo ya existe cuando el script comienza, se renombrará con un sufijo .prev (sobrescribiendo cualquier archivo de registro guardado anteriormente) antes de generar los diagnósticos en el archivo de registro. Las opciones -l y -t no pueden usarse juntas.
-N, --showme
Esta opción habilita un modo "show me" (muéstrame), donde las acciones se repiten, pero no se ejecutan, al estilo de "make -n". Usar -N junto con -V maximiza las capacidades de diagnóstico para la depuración.
-n, --noerror
Fuerza el estado de salida a ser 0, excepto para errores catastróficos. Útil cuando se llama desde una unidad de servicio o temporizador de systemd(1) para que la unidad asociada no se marque como fallida de una manera que impida su ejecución posterior desde systemd(1).
-P, --only-primary
Si se especifica esta opción para pmlogger_check, solo se procesará la entrada del logger principal en los archivos de control. Este es el opuesto lógico de la opción -p descrita anteriormente y está destinado a ser utilizado por scripts RC que inician solo el logger principal, como la unidad pmlogger.service. Las opciones -p y -P son mutuamente excluyentes.
-p, --skip-primary
Si se especifica esta opción para pmlogger_check, se ignorará cualquier línea de los archivos de control para el pmlogger *principal*. Esta opción está destinada a entornos donde algún demonio del sistema, como systemd(1), es responsable de controlar (iniciar, detener, reiniciar, etc.) el pmlogger *principal*.
-q, --quick
Si se especifica esta opción para pmlogger_check, el script realizará un "arranque rápido", evitando cualquier procesamiento opcional como llamar a pmlogger_daily(1) para realizar tareas de compresión de archivo.
-s, --stop
El uso de esta opción proporciona la funcionalidad inversa de pmlogger_check, permitiendo que el conjunto de procesos pmlogger se apague limpiamente.
-T, --terse
Esta opción para pmlogger_check produce una salida menos detallada que la predeterminada. Esto es más adecuado para una "granja" de pmlogger donde se espera que muchas instancias de pmlogger estén en ejecución.
-V, --verbose
La opción -V habilita el rastreo detallado. Por defecto, pmlogger_check no genera ninguna salida a menos que se encuentre alguna condición de error o advertencia. Una segunda opción -V aumenta la verbosidad. Usar -N junto con -V maximiza las capacidades de diagnóstico para la depuración.
-?, --help
Muestra el mensaje de uso y sale.

CONFIGURACIÓN

Consulte pmlogger.control(5) para una descripción de los archivos de control que se utilizan para controlar qué instancias de pmlogger y qué archivos se gestionan mediante pmlogger_check y pmlogger_daily(1).

La utilidad pmlogctl(1) puede invocar pmlogger_check usando el comando sudo(1) para ejecutarlo bajo la cuenta de usuario ``pcp'' de $PCP_USER. Si sudo está configurado con la opción no predeterminada requiretty (ver más abajo), pmlogger_check puede fallar al ejecutarse debido a que no tiene una tty configurada. Este problema puede resolverse añadiendo una segunda línea (expanda $PCP_BINADM_DIR según su plataforma) al archivo de configuración de /etc/sudoers de la siguiente manera:

Defaults requiretty
Defaults!$PCP_BINADM_DIR/pmlogger_check !requiretty

Tenga en cuenta que la cuenta PCP no privilegiada bajo la cual se ejecutan estos comandos utiliza /sbin/nologin como shell, por lo que la opción requiretty es ineficaz aquí y es seguro deshabilitarla de esta manera.

ARCHIVOS

$PCP_VAR_DIR/config/pmlogger/config.default
ubicación predeterminada del archivo de configuración de pmlogger para el logger principal local, típicamente generado automáticamente por pmlogconf(1).
$PCP_ARCHIVE_DIR/<hostname>
ubicación predeterminada para los archivos de información de rendimiento recopilados del host hostname
$PCP_ARCHIVE_DIR/<hostname>/lock
archivo de bloqueo transitorio para garantizar la exclusión mutua durante la administración de pmlogger para el host hostname - si está presente, puede eliminarse de forma segura si ni pmlogger_daily(1) ni pmlogger_check se están ejecutando
$PCP_ARCHIVE_DIR/<hostname>/Latest
folio de archivo de PCP creado por mkaf(1) para el archivo lanzado más recientemente que contiene métricas de rendimiento del host hostname
$PCP_LOG_DIR/NOTICES
archivo de "notificaciones" de PCP utilizado por pmie(1) y similares
$PCP_LOG_DIR/pmlogger/pmlogger_check.log
si la ejecución anterior de pmlogger_check produjo alguna salida, esta se guarda aquí. El caso normal es que no haya salida, en cuyo caso el archivo no existe.
$PCP_ARCHIVE_DIR/SaveLogs
si este directorio existe, el archivo de registro del argumento -l para pmlogger_check se guardará en este directorio con el nombre del formato <fecha>-pmlogger_check.log.<pid>. Esto permite inspeccionar el archivo de registro en un momento posterior, incluso si se han lanzado varias ejecuciones de pmlogger_check en el ínterin. Dado que las herramientas de administración de archivos de PCP se ejecutan bajo la cuenta $PCP_USER ``pcp'', $PCP_ARCHIVE_DIR/SaveLogs típicamente necesita ser propiedad del usuario ``pcp''.

$PCP_ARCHIVE_DIR/<hostname>/SaveLogs
si este directorio existe, entonces el archivo de registro del argumento -l de un pmlogger(1) recién lanzado para hostname se guardará en este directorio con el nombre archive.log, donde archive es el nombre base de los archivos de archivo pmlogger(1) de PCP asociados. Esto permite inspeccionar el archivo de registro en un momento posterior, incluso si se han lanzado varias instancias de pmlogger(1) para hostname en el ínterin. Dado que las herramientas de administración de archivos de PCP se ejecutan bajo la cuenta de usuario ``pcp'' de $PCP_USER, $PCP_ARCHIVE_DIR/<hostname>/SaveLogs típicamente necesita ser propiedad del usuario ``pcp''.

ENTORNO DE PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

El comportamiento predeterminado, cuando la configuración de pmlogger(1) proviene de pmlogconf(1), es regenerar el archivo de configuración y verificar si hay cambios cada vez que se inicia pmlogger(1) desde pmlogger_check. Si la configuración de PMDA es estable, esto no es necesario, y establecer $PMLOGGER_CHECK_SKIP_LOGCONF en yes deshabilita la regeneración y la verificación.
