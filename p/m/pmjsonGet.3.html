NOMBRE

pmjsonGet, pmjsonPrint, pmjsonInit, pmjsonInitIndom - Ayudantes de cadenas JSON y extracción de métricas

SINOPSIS

#include <pcp/pmapi.h>
#include <pcp/pmjson.h>

typedef int (*json_get)(void *buffer,
int length, void *data);

int pmjsonGet(json_metric_desc *json_metrics,
int nmetrics, pmInDom indom, json_get callback, void *data);

int pmjsonPrint(FILE *fp,
json_flag *output_flags, const char *json_pointer, json_get callback, void *data);

int pmjsonInit(int fd,
json_metric_desc *json_metrics, int nmetrics);

int pmjsonInitIndom(int fd,
json_metric_desc *json_metrics, int nmetrics, pmInDom indom);

cc ... -lpcp_web

DESCRIPCIÓN

pmjsonGet realiza la extracción de valores de métricas de cadenas JSON para un Agente de Dominio de Métricas de Rendimiento (PMDA(3)). Las métricas y las instancias se definen mediante el parámetro json_metrics. El resultado del análisis es la extracción de valores para las métricas solicitadas (según se define en el campo json_pointer) en el campo values.

También se proporciona una utilidad de diagnóstico simple para informar cadenas JSON como una conveniencia. Su argumento output_flags le permite admitir una variedad de formatos de salida alternativos, incluido JSON mínimo (sin espacios en blanco opcionales), formato bonito y un subconjunto simple de YAML.

json_metrics es la matriz de la estructura json_metric_desc que contiene el puntero JSON a los datos de la métrica, posibles indicadores para verificar los datos, el número de valores (en el caso de una matriz), pmAtomValue donde se almacenan los datos, así como el dominio de instancia en caso de que el PMDA tenga múltiples dominios de instancia. El número de elementos en la matriz json_metrics se indica mediante el parámetro nmetrics.

Se proporcionan interfaces para casos comunes: pmjsonInit especifica una llamada a la funcionalidad de análisis JSON y extracción de valores de métricas donde no hay dominios de instancia (o el PMDA desea realizar operaciones de dominio de instancia por sí mismo) y donde los datos se pueden leer directamente de un descriptor de archivo abierto. pmjsonInitIndom es similar, pero utiliza la función pmdaCacheStore(3) siempre que sea posible.

La cadena JSON debe ser proporcionada por la función *callback*. A esta función se le pasa un *buffer* de memoria de *length* bytes y un puntero *data* de usuario opaco que no cambia desde la llamada original a pmjsonGet o pmjsonPrint. El resultado devuelto debe ser el número de bytes escritos en *buffer*, cero cuando no hay más datos disponibles o menos de cero en caso de error.

indom es el dominio de instancia que se pasará a pmdaCacheStore.

typedef struct json_metrics_desc {
    char          *json_pointer;  /* puntero json a la métrica */
    int           flags;          /* indicadores para verificar si están establecidos */
    int           num_values;     /* número de valores */
    pmAtomValue   values;         /* valor de la métrica */
    char          *dom;           /* dominio de instancia */
} json_metric_desc;

La sintaxis del Puntero JSON sigue actualmente a RFC6901 al especificar una ubicación de métricas dentro del documento JSON.

EJEMPLO

Para el documento JSON de ejemplo:

{
    "Name": "/clever_almeida",
    "State": {
        "Dead": false,
        "Error": "",
        "ExitCode": 0,
        "FinishedAt": "2016-07-18T21:21:20.332488706Z",
        "OOMKilled": false,
        "Paused": false,
        "Pid": 0,
        "Restarting": false,
        "Running": false,
        "StartedAt": "2016-07-18T14:10:58.52487316Z"
    }
}

Una posible matriz json_metric correspondiente sería la siguiente para el Pid, el Nombre y las métricas para indicar si el contenedor se está ejecutando, pausado o reiniciando.

static json_metric_desc json_metrics[] = {
    { "State/Pid", 0, 1, {0}, ""},
    { "Name", 0, 1, {0}, ""},
    { "State/Running", CONTAINER_FLAG_RUNNING, 1, {0}, ""},
    { "State/Paused", CONTAINER_FLAG_PAUSED, 1, {0}, ""},
    { "State/Restarting", CONTAINER_FLAG_RESTARTING, 1, {0}, ""},
};

CÓDIGO DE RETORNO

Las funciones devuelven cero si la operación fue exitosa, de lo contrario, devuelven un código de error adecuado para pasarlo a pmErrStr_r(3).
