NOMBRE

pmlogreduce - reducción temporal de archivos de Performance Co-Pilot

SINOPSIS

pmlogreduce [-z?] [-A align] [-D debug] [-s samples] [-S starttime] [-t interval] [-T endtime] [-v volsamples] [-Z timezone] input output

DESCRIPCIÓN

pmlogreduce lee un conjunto de archivos de Performance Co-Pilot (PCP) identificados por input y crea un archivo PCP reducido temporalmente en output. input es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos. La reducción de datos implica la reducción estadística y temporal de muestras con un intervalo de muestreo de salida definido por la opción -t en el archivo output (independiente de los intervalos de muestreo en los archivos input), y está controlado además por otros argumentos de la línea de comandos.

Para algunas métricas, la reducción temporal de datos no será útil, por lo que para métricas con tipos PM_TYPE_AGGREGATE o PM_TYPE_EVENT, se emite una advertencia si estas métricas se encuentran en input y serán omitidas y no aparecerán en el archivo output.

OPCIONES

Las opciones disponibles en la línea de comandos son:

-A align, --align=align
Especifica una alineación "natural" de los tiempos de muestra de salida; consulte PCPIntro(1).
-s samples, --samples=samples
El argumento samples define el número de muestras que se escribirán en output. Si samples es 0 o no se especifica -s, pmlogreduce tomará muestras hasta el final del conjunto de archivos PCP, o hasta el final de la ventana de tiempo según lo especificado por -T, lo que ocurra primero. La opción -s anulará la opción -T si ocurre antes.
-S starttime, --start=starttime
Define el inicio de una ventana de tiempo para restringir las muestras recuperadas de los archivos input; consulte PCPIntro(1).
-t interval, --interval=interval
Las muestras consecutivas en el archivo output aparecerán con un delta de tiempo definido por interval; consulte PCPIntro(1). Tenga en cuenta que el valor predeterminado es 600 (segundos, es decir, 10 minutos).
-T endtime, --finish=endtime
Define la terminación de una ventana de tiempo para restringir las muestras recuperadas de los archivos input; consulte PCPIntro(1).
-v volsamples
El archivo output es potencialmente un conjunto de datos multivolumen, y la opción -v hace que pmlogreduce inicie un nuevo volumen después de que se hayan escrito volsamples registros en el archivo output.

Independientemente de cualquier opción -v, cada volumen de un archivo está limitado a no más de 2^31 bytes, por lo que pmlogreduce creará automáticamente un nuevo volumen para el archivo antes de que se alcance este límite.

-z, --hostzone
Utiliza la zona horaria local del host de los archivos input al mostrar la fecha y hora, o al interpretar las opciones -S y -T. El valor predeterminado es usar inicialmente la zona horaria del host local.
-Z timezone, --timezone=timezone
Utiliza timezone al mostrar la fecha y hora, o al interpretar las opciones -S y -T. Timezone está en el formato de la variable de entorno TZ según se describe en environ(7).
-?, --help
Muestra el mensaje de uso y sale.

REDUCCIÓN DE DATOS

La reducción estadística y temporal sigue las siguientes reglas:

1.
Los registros consecutivos de input se leen sin interpolación, y se escribe como máximo un registro de salida por cada interval, resumiendo los datos de rendimiento durante ese período.
2.
Si la semántica de una métrica indica que es instantánea o discreta, el valor de output se calcula como la media aritmética de las observaciones (si las hay) durante cada interval.
3.
Si la semántica de una métrica indica que es un contador, se aplican las siguientes transformaciones:
a)
Las métricas con precisión de 32 bits se promueven a precisión de 64 bits.
b)
Se detecta cualquier desbordamiento de contador (wrap) y se realiza el ajuste apropiado en el valor de la métrica durante cada interval. Esto será correcto en el caso de un solo desbordamiento de contador, pero **subestimará** silenciosamente en el caso de que ocurra más de un desbordamiento de contador entre observaciones consecutivas en los archivos input, y **sobreestimará** silenciosamente en el caso de que ocurra un reinicio del contador entre observaciones consecutivas en los archivos input; desafortunadamente, estas situaciones no pueden detectarse, pero se cree que son eventos raros para el tipo de entornos de monitoreo de producción donde es más probable que se implemente pmlogreduce.
4.
Cualquier cambio en los dominios de instancia, y de hecho en todos los metadatos, se preserva.
5.
Cualquier registro de "marca" en los archivos input (como los creados por pmlogextract(1)) se preservará en el archivo output, por lo que se mantienen los períodos en los que no hay datos disponibles, y la interpolación de datos **no** se realizará a través de estos períodos cuando el archivo output se procese posteriormente con aplicaciones de PCP.

ADVERTENCIAS

Las métricas de preámbulo (pmcd.pmlogger.archive, pmcd.pmlogger.host y pmcd.pmlogger.port), que son registradas automáticamente por pmlogger al inicio del archivo, pueden no estar presentes en el archivo de salida creado por pmlogreduce. Estas métricas solo son relevantes mientras se está creando el archivo y no tienen significado una vez que ha finalizado la grabación.

DIAGNÓSTICOS

Todas las condiciones de error detectadas por pmlogreduce se informan en stderr con una explicación textual (aunque a veces concisa).

Si los archivos input están corruptos (esto puede suceder si la instancia de pmlogger que escribe el archivo muere repentinamente), pmlogreduce detectará e informará la posición de la corrupción en el archivo, y cualquier información posterior de los archivos input no será procesada.

Si se detecta algún error, pmlogreduce saldrá con un estado distinto de cero.

ARCHIVOS

Para cada uno de los archivos input y output, se utilizan varios archivos físicos.

archive.meta
metadatos (descripciones de métricas, dominios de instancias, etc.) para el archivo
archive.0
volumen inicial de valores de métricas (los volúmenes subsiguientes tienen los sufijos 1, 2, ...) - para input, estos archivos pueden haber sido previamente comprimidos con bzip2(1) o gzip(1) y por lo tanto pueden tener un sufijo adicional .bz2 o .gz.
archive.index
índice temporal para soportar acceso rápido y aleatorio a los otros archivos en el archivo.

PCP ENVIRONMENT

The environment variables listed below are used by PCP to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.

Debugging options specific to pmlogger are as follows:

Option Description
appl0 initialization and time window
appl1 report new metric-instance observations
appl2 report scan start and end times, dump input and output records
