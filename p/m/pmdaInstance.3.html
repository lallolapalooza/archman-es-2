pmdaInstance(3)

Paquete: pcp

PMDAINSTANCE(3) Manual de funciones de biblioteca PMDAINSTANCE(3)

NOMBRE

pmdaInstance - devuelve descripciones de instancias para un PMDA

C SINOPSIS

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaInstance(pmInDom indom,
int inst, char *name, pmInResult **result, pmdaExt *pmda);

cc ... -lpcp_pmda -lpcp

DESCRIPCIÓN

pmdaInstance utiliza las estructuras de datos estándar de PMDA(3) para devolver información concerniente al dominio de instancia indom.

La estructura result es construida por pmdaInstance y contendrá uno o más nombres/identificadores de instancia según lo especificado por los argumentos inst y name.

Si inst tiene el valor PM_IN_NULL y name es una cadena nula, result contendrá todos los nombres e identificadores de instancia en el dominio de instancia.

Si inst es PM_IN_NULL pero name es el nombre de una instancia en el dominio de instancia indom, entonces result contendrá el identificador de instancia para el nombre de instancia name. Tenga en cuenta que si name no contiene espacios, se realiza una coincidencia parcial hasta el primer espacio en el nombre de la instancia, es decir, ``1'' coincidirá con el nombre de instancia ``1 minute''. Si name contiene un espacio incrustado, no se realiza coincidencia parcial y name debe coincidir exactamente con uno de los nombres de instancia.

Si name es una cadena nula pero inst es un identificador de instancia en el dominio de instancia indom, entonces result contendrá el nombre de la instancia inst. La estructura result se asigna con malloc(3) y debe ser liberada por el llamador con free(3).

NOMBRES DE INSTANCIA MULTIDIMENSIONALES

Además de la descripción anterior de name, el conjunto de reglas que describen los nombres de instancia externos se proporciona en la página del manual de pmdaCacheStore(3).

Los dominios de instancia añaden otra dimensión (conjunto de valores) a las métricas. Sin embargo, esto puede no ser suficiente para describir situaciones complejas de dominios de instancia multidimensionales. Para este caso, el enfoque utilizado por varios PMDA es estructurar los nombres de instancia externos utilizando un delimitador (``/'' o ``::'' son los más comúnmente utilizados) para permitir la separación de las otras dimensiones. En esta situación, las etiquetas del dominio de instancia deben utilizarse para definir nombres para cada componente del nombre de instancia. Esto permite que las herramientas cliente de PMAPI(3) identifiquen y refinen las búsquedas de valores a dimensiones específicas de interés.

Por ejemplo, algunos dominios de instancia de cgroup (grupo de control) del kernel de Linux son multidimensionales. El dominio de instancia representa valores individuales tanto en grupos de control como en CPU, lo que lo convierte en un dominio de instancia bidimensional. Los nombres de instancia asociados con este indom de métricas de cgroup se han estructurado utilizando el delimitador ``::'' para separar las dos dimensiones. El dominio de instancia en sí ha sido etiquetado en consecuencia, como sigue.

$ pminfo --desc --fetch --labels cgroup.cpuacct.usage_percpu
cgroup.cpuacct.usage_percpu
Tipo de datos: entero sin signo de 64 bits  InDom: 3.22 0xc00016
Semántica: contador  Unidades: nanoseg
inst [0 o "/::cpu0"] valor 713787
inst [1 o "/::cpu1"] valor 353969
inst [2 o "/app::cpu0"] valor 407816
inst [3 o "/app::cpu1"] valor 202747
inst [0 o "/::cpu0"] etiquetas {"device_type":"cpu","cgroup":"/","cpu":0}
inst [1 o "/::cpu1"] etiquetas {"device_type":"cpu","cgroup":"/","cpu":1}
inst [2 o "/app::cpu0"] etiquetas {"device_type":"cpu","cgroup":"/app","cpu":0}
inst [3 o "/app::cpu1"] etiquetas {"device_type":"cpu","cgroup":"/app","cpu":1}

$ pminfo --labels 3.22
InDom: 3.22 0xc00016
etiquetas {"device_type":"cpu"}

Como se muestra arriba, las instancias individuales heredan las etiquetas del dominio de instancia, y el PMDA también aplica etiquetas adicionales por instancia que describen los nombres individuales de cgroup y CPU. Cuando este modelo ha sido utilizado por el PMDA, las herramientas cliente de PMAPI pueden restringir sus consultas a las instancias de métricas de cgroup: en el ejemplo, restringiendo al procesador ``cpu0'' usando la etiqueta ``cpu'', quizás, o solo a las métricas del cgroup ``/app'' usando la etiqueta ``cgroup''.

Además, utilizando este esquema de etiquetado, las herramientas cliente también pueden correlacionar instancias relacionadas en diferentes dominios de instancia.

$ pminfo --desc --fetch --labels kernel.percpu.cpu.irq.soft
kernel.percpu.cpu.irq.soft
Tipo de datos: entero sin signo de 64 bits  InDom: 60.0 0xf000000
Semántica: contador  Unidades: milliseg
inst [0 o "cpu0"] valor 6770
inst [1 o "cpu1"] valor 100
inst [0 o "cpu0"] etiquetas {"device_type":"cpu"}
inst [1 o "cpu1"] etiquetas {"device_type":"cpu"}

$ pminfo --labels 60.0
InDom: 60.0 0xf000000
etiquetas {"device_type":"cpu"}

Aunque estas dos métricas tienen dominios de instancia diferentes (60.0 y 3.22 respectivamente) y provienen de diferentes PMDA, la etiqueta ``device_type'' identifica el dispositivo común al que se relacionan estos valores.

ADVERTENCIA

El PMDA debe usar PMDA_INTERFACE_2 o posterior, como se especifica en la llamada a pmdaDSO(3) o pmdaDaemon(3). Si se realiza el etiquetado de nombres de instancia multidimensionales, el PMDA debe usar PMDA_INTERFACE_7 o posterior.

Debido a la coincidencia parcial opcional hasta el primer espacio en el nombre de la instancia, el desarrollador de **PMDA** debe asegurarse de que si se permiten espacios en los nombres de instancia, los nombres sean únicos hasta el primer espacio.

DIAGNÓSTICOS

Si ocurre algún error durante la ejecución de pmdaInstance, la estructura result se desasigna. Si el dominio de instancia indom no es compatible con el PMDA, pmdaInstance devolverá PM_ERR_INDOM.

Si inst o name no corresponden a ninguna instancia en el dominio indom, pmdaInstance devolverá PM_ERR_INST.
