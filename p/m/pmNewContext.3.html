PMNEWCONTEXT(3) Manual de Funciones de Biblioteca PMNEWCONTEXT(3)

NOMBRE

pmNewContext - establecer un nuevo contexto PMAPI

SINOPSIS

#include <pcp/pmapi.h>

int pmNewContext(int type, const char *name);

cc ... -lpcp

DESCRIPCIÓN

Una aplicación que utiliza la Interfaz de Programación de Aplicaciones de Métricas de Rendimiento (PMAPI) puede manipular varios contextos concurrentes, cada uno asociado con una fuente de métricas de rendimiento, por ejemplo pmcd(1) en algún host, o un conjunto de archivos de métricas de rendimiento como los creados por pmlogger(1), o una conexión independiente en el host local que no involucre a pmcd(1).

pmNewContext se puede usar para establecer un nuevo contexto. La fuente de las métricas se identifica mediante name, y puede ser ya sea un nombre de host (type es PM_CONTEXT_HOST), o una lista separada por comas de nombres que se refieren a un conjunto de archivos (type es PM_CONTEXT_ARCHIVE). Cada elemento de la lista puede ser el nombre base común a todos los archivos físicos de un archivo o el nombre de un directorio que contiene archivos.

Para un type de PM_CONTEXT_HOST, además de identificar un host, name también puede usarse para codificar información adicional opcional en forma de un número de puerto de pmcd(1), un nombre de host de pmproxy(1) y un número de puerto de proxy. Por ejemplo, el name "app23:14321,4321@firewall.example.com:11111" especifica una conexión en el puerto 14321 (o el puerto 4321 si 14321 no está disponible) a pmcd(1) en el host app23 a través del puerto 11111 a pmproxy(1) en el host firewall.example.com.

Alternativamente, para un type de PM_CONTEXT_HOST, name puede ser unix: para una conexión de socket de dominio Unix autenticada a pmcd(1) en el localhost o local: para una conexión autenticada a pmcd(1) en el localhost a través de un socket de dominio Unix si está disponible, de lo contrario a través de una conexión de socket de Internet a localhost. local: es la opción predeterminada para la mayoría de las aplicaciones al llamar a pmNewContext para establecer un contexto para pmcd(1) en el host local.

Para un type de PM_CONTEXT_ARCHIVE, cada elemento de la lista de nombres en name también puede ser el nombre de cualquiera de los archivos físicos de un archivo, por ejemplo myarchive.meta (el archivo de metadatos) o myarchive.index (el índice temporal) o myarchive.0 (el primer volumen de datos del archivo) o myarchive.0.bz2 o myarchive.0.bz (el primer volumen de datos comprimido con bzip2(1)) o myarchive.0.gz o myarchive.0.Z o myarchive.0.z (el primer volumen de datos comprimido con gzip(1)), myarchive.1 o myarchive.3.bz2 o myarchive.42.gz etc.

Si se especifican varios archivos para un type de PM_CONTEXT_ARCHIVE, existen algunas restricciones en los archivos dentro del conjunto:

  • Todos los archivos deben haber sido generados en el mismo host.
  • Los archivos no deben solaparse en el tiempo.
  • Todos los archivos deben haber sido creados usando la misma zona horaria.
  • El PMID de cada métrica debe ser el mismo en todos los archivos. Actualmente se toleran múltiples PMIDs utilizando el primer PMID definido para cada métrica e ignorando los posteriores PMIDs.
  • El tipo de cada métrica debe ser el mismo en todos los archivos.
  • La semántica de cada métrica debe ser la misma en todos los archivos.
  • Las unidades de cada métrica deben ser las mismas en todos los archivos.
  • El dominio de instancias de cada métrica debe ser el mismo en todos los archivos.

En el caso en que type sea PM_CONTEXT_LOCAL, name se ignora y el contexto utiliza una conexión independiente a los métodos PMDA utilizados por pmcd(1). El mecanismo en la biblioteca utiliza la misma arquitectura de "plugins" que opera entre pmcd(1) y los PMDAs DSO, por lo que las operaciones implican llamadas a funciones en lugar de paso de mensajes IPC; para contextos PM_CONTEXT_LOCAL esto puede significar menor latencia para operaciones como pmFetch(3), pero a costa de un mayor tiempo de inicialización y posibles diferencias de control de acceso en comparación con pmcd(1). Cuando se utiliza este tipo de contexto, el rango de métricas de rendimiento accesibles se limita a las de los PMDAs DSO definidos en el archivo de configuración de pmcd(1) /etc/pcp/pmcd/pmcd.conf, por lo que aquellos informados por el comando


$ awk '$3 == "dso" {print}' /etc/pcp/pmcd/pmcd.conf

o alternativamente informados por el comando


$ pminfo -f pmcd.agent.type | grep 'value 0'

Esto generalmente significa el PMDA que exporta métricas del sistema operativo y el "pmcd", "pmproxy" y puede incluir algunos otros como "mmv". Se pueden usar PMDAs DSO alternativos, consulte pmSpecLocalPMDA(3).

En el caso en que type sea PM_CONTEXT_HOST, se pueden añadir indicadores adicionales a type para indicar si la conexión a pmcd(1) debe estar cifrada (PM_CTXFLAG_SECURE), debe estar cifrada si es posible (PM_CTXFLAG_RELAXED), es diferida (PM_CTXFLAG_SHALLOW), debe usar autenticación (PM_CTXFLAG_AUTH), debe ser una conexión a un contenedor (PM_CTXFLAG_CONTAINER), o si el descriptor de archivo utilizado para comunicarse con pmcd(1) no debe compartirse entre contextos (PM_CTXFLAG_EXCLUSIVE). Tanto los indicadores PM_CTXFLAG_SHALLOW como PM_CTXFLAG_EXCLUSIVE ahora están obsoletos y se ignoran.

Cuando type es PM_CONTEXT_ARCHIVE, se pueden añadir indicadores adicionales a type para un manejo restringido del archivo adecuado para aplicaciones que conocen la estructura de los archivos PCP, a saber PM_CTXFLAG_NO_FEATURE_CHECK (no verificar la compatibilidad de características para los registros de etiquetas de archivos), PM_CTXFLAG_METADATA_ONLY (abrir solo los metadatos, no el o los volúmenes de datos ni el índice) y PM_CTXFLAG_LAST_VOLUME (abrir el archivo al inicio del último volumen de datos, en lugar del inicio predeterminado del primer volumen de datos).

Se pueden especificar varios indicadores mediante la operación "or" a nivel de bits de las macros PM_CTXFLAG, pero no todas las combinaciones tienen sentido, por ejemplo, si se especifican PM_CTXFLAG_METADATA_ONLY y PM_CTXFLAG_LAST_VOLUME, PM_CTXFLAG_METADATA_ONLY tiene prioridad.

El perfil de instancia inicial se configura para seleccionar todas las instancias en todos los dominios de instancia. En el caso de un conjunto de archivos, la hora de recolección inicial también se establece en cero, de modo que una llamada inicial a pmFetch(3) resultará en la devolución del conjunto de métricas más antiguo del conjunto de archivos.

Una vez establecido, la asociación entre un contexto y una fuente de métricas es fija durante la vida útil del contexto; sin embargo, se proporcionan rutinas para manipular de forma independiente tanto el perfil de instancia (ver pmAddProfile(3) y pmDelProfile(3)) como la hora de recolección para archivos (ver pmSetMode(3)).

pmNewContext devuelve un manejador que puede ser utilizado con llamadas posteriores a pmUseContext(3).

El nuevo contexto permanece como el contexto PMAPI actual para todas las llamadas posteriores en PMAPI, hasta que se realice otra llamada a pmNewContext(3), o el contexto se cambie explícitamente con una llamada a pmDupContext(3) o pmUseContext(3), o se destruya usando pmDestroyContext(3).

Al intentar conectarse a un pmcd(1) remoto en una máquina que se está iniciando, pmNewContext podría bloquearse durante mucho tiempo hasta que la máquina remota finalice su inicialización. pmNewContext abortará y devolverá un error si la conexión no se ha establecido después de que haya transcurrido un intervalo especificado. El intervalo predeterminado es de 5 segundos. Esto se puede modificar estableciendo PMCD_CONNECT_TIMEOUT en el entorno a un número real de segundos para el tiempo de espera deseado. Esto es más útil en casos donde el host remoto está al final de una red de área local (LAN).

pmNewContext(3) — PCP Performance Co-Pilot

NAME

pmNewContext, pmDupContext, pmDestroyContext, pmWhichContext, pmUseContext, pmReconnectContext - crear, duplicar, destruir, consultar, utilizar o reconectar un contexto de cliente de Performance Co-Pilot (PCP)

C SYNOPSIS

#include <pmapi.h>

PM_CONTEXT_LOCAL()
PM_CONTEXT_HOST(const char *host)
PM_CONTEXT_ARCHIVE(const char *archive)
PM_CONTEXT_TRACE(const char *trace)
PM_CONTEXT_PID(pid_t pid)
PM_CONTEXT_PROCESS(pid_t pid)

int
pmNewContext(
    int             type,
    void            *desc
);

int
pmDupContext(
    int             context
);

int
pmDestroyContext(
    int             context
);

int
pmWhichContext(void
);

int
pmUseContext(
    int             context
);

int
pmReconnectContext(
    int             context
);

DESCRIPTION

pmNewContext crea un nuevo contexto de cliente de PCP y devuelve un descriptor entero no negativo que puede ser utilizado en llamadas posteriores a la PMAPI(3) para recuperar métricas de la fuente de datos especificada.

El parámetro type especifica la fuente de datos, y debe ser uno de los siguientes valores:

PM_CONTEXT_LOCAL
Para acceder a las métricas de un sistema localmente, directamente desde los módulos de gestión de rendimiento (PMDAs) del kernel y del espacio de usuario.
PM_CONTEXT_HOST
Para acceder a las métricas de un sistema remoto especificado por el parámetro desc, que debe ser un puntero a una cadena de caracteres que contenga el nombre de host o la dirección IP.
PM_CONTEXT_ARCHIVE
Para acceder a las métricas de un archivo de registro de PCP, especificado por el parámetro desc, que debe ser un puntero a una cadena de caracteres que contenga el nombre del archivo o la ruta del directorio. Se pueden especificar varios archivos, separados por comas, o un directorio que contenga archivos de registro de PCP. pmNewContext utiliza una estrategia de búsqueda para encontrar los archivos de registro relevantes.
PM_CONTEXT_TRACE
Para acceder a las métricas de un archivo de registro de rastreo de kernel, especificado por el parámetro desc, que debe ser un puntero a una cadena de caracteres que contenga el nombre del archivo.
PM_CONTEXT_PID
Para adjuntarse al proceso especificado por el parámetro desc, que debe ser un puntero a un entero que contenga el ID del proceso (PID). Este contexto solo está disponible si los PMDAs de espacio de usuario correspondientes están instalados y habilitados.
PM_CONTEXT_PROCESS
Similar a PM_CONTEXT_PID, pero se utiliza para adjuntarse al proceso especificado por el parámetro desc. A diferencia de PM_CONTEXT_PID, este contexto puede ser utilizado para adjuntarse a un proceso que ya ha terminado.

El valor devuelto por pmNewContext se puede utilizar como argumento para otras funciones de la PMAPI(3). Si se produce un error, se devuelve un valor negativo.

pmDupContext duplica un contexto existente. Esto es útil cuando varios hilos o partes de una aplicación necesitan acceder a las mismas métricas de la misma fuente de datos.

pmDestroyContext destruye un contexto existente, liberando todos los recursos asociados. Es importante llamar a pmDestroyContext para cada contexto creado con pmNewContext o pmDupContext cuando ya no se necesite.

pmWhichContext devuelve el descriptor del contexto actual que está siendo utilizado por la aplicación. Si no se ha establecido ningún contexto, se devuelve -1.

pmUseContext establece el contexto especificado como el contexto actual para todas las llamadas posteriores a la PMAPI(3). Esto es útil cuando se trabaja con múltiples contextos simultáneamente.

pmReconnectContext intenta reconectar un contexto existente que se ha desconectado. Esto es útil en entornos de red inestables donde las conexiones pueden interrumpirse. La reconexión puede implicar un tiempo de espera más largo para establecer la conexión correctamente.

CAVEATS

Al usar un tipo de PM_CONTEXT_LOCAL, el PMDA del sistema operativo puede exportar estructuras de datos directamente desde el kernel, lo que significa que el llamador de pmNewContext debe ser un programa ejecutable compilado para el mismo formato de código objeto que el kernel arrancado.

Además, las aplicaciones que utilizan un contexto PM_CONTEXT_LOCAL deben ser de un solo hilo, ya que los diversos PMDAs de DSO pueden no ser seguros para subprocesos. Esta restricción se aplica en la PMAPI(3), donde las rutinas pueden devolver el código de error PM_ERR_THREAD si la biblioteca detecta llamadas de más de un hilo.

Las aplicaciones que utilizan gethostbyname(3) deben tener cuidado, ya que los campos estáticos en struct hostent pueden no conservarse en algunas llamadas a PMAPI(3). En particular, tanto pmNewContext(3) como pmReconnectContext(3) pueden llamar internamente a gethostbyname(3).

DIAGNOSTICS

PM_ERR_PERMISSION

Sin permiso para realizar la operación solicitada

PM_ERR_CONNLIMIT

Límite de conexión de PMCD para este host excedido

PM_ERR_NOCONTEXT

El tipo de contexto solicitado no fue PM_CONTEXT_LOCAL, PM_CONTEXT_HOST o PM_CONTEXT_ARCHIVE.

PM_ERR_LOGOVERLAP

Los archivos se superponen en el tiempo

PM_ERR_LOGHOST

Los archivos difieren por host

PM_ERR_LOGCHANGETYPE

El tipo de una métrica difiere entre archivos

PM_ERR_LOGCHANGESEM

La semántica de una métrica difiere entre archivos

PM_ERR_LOGCHANGEINDOM

El dominio de instancia de una métrica difiere entre archivos

PM_ERR_LOGCHANGEUNITS

Las unidades de una métrica difieren entre archivos

ENVIRONMENT

PMCD_CONNECT_TIMEOUT
Período de tiempo de espera (en segundos) para los intentos de conexión a pmcd(1).
PMCD_PORT
Puerto(s) TCP/IP para conectarse a pmcd(1), históricamente fue 4321 y más recientemente el puerto registrado oficialmente 44321; en la versión actual, pmcd escucha en ambos puertos como una disposición transitoria. Si se utiliza, debe establecerse como una lista de números de puerto separados por comas.
