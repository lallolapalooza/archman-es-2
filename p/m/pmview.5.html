PMVIEW(5) Manual de Formatos de Archivo PMVIEW(5)

NOMBRE

pmview - formato de archivo de configuración para vistas de rendimiento

DESCRIPCIÓN

Esta página del manual describe la versión 2.1 del formato de archivo de configuración de pmview (1).

El formato de configuración soporta métricas de múltiples hosts o archivos. Un archivo de configuración puede especificar métricas sin fuente, con diferentes hosts y diferentes archivos. Sin embargo, un archivo de configuración que contenga archivos solo puede tener un archivo por host. Cuando está en modo "replay", cualquier métrica con fuentes específicas de host requiere que se especifique un archivo para ese host en la línea de comandos o como fuente para una métrica anterior. El archivo debe ser el mismo archivo (basado en una comparación de cadenas de los nombres de archivo) de cualquier archivo especificado en el archivo de configuración para el mismo host.

Los controles de tiempo listarán todos los hosts que se especifican en la línea de comandos y en el archivo de configuración en la lista de zonas horarias (ver pmtime(1)).

El formato del archivo de configuración se basa en una cuadrícula bidimensional que puede contener una variedad de barras, pilas, enlaces, tuberías, etiquetas y otras cuadrículas. Las cuadrículas redimensionan cada columna y fila para que coincidan con el tamaño del elemento más grande en esa columna o fila. Un archivo de configuración que contenga solo un objeto no requiere una cuadrícula. El archivo de configuración pmview comienza con una cabecera de identificación en la primera línea que no sea un comentario:


pmview Version 2.1 [línea_de_comandos]

La línea_de_comandos opcional debe ser la línea de comandos con la que se lanzó la herramienta, si el archivo de configuración ha sido generado por otra herramienta. Esto es útil para aplicaciones que se reiniciarán automáticamente en el próximo inicio de sesión, después de que el usuario haya cerrado sesión mientras pmview aún estaba en ejecución. Se debe tener cuidado para asegurar que el comando especificado sea una ruta completa o que se encuentre en el PATH disponible al iniciar sesión.

Todas las líneas que comienzan con ``#'' se tratan como comentarios y se ignoran. De lo contrario, todos los espacios, tabulaciones y saltos de línea se tratan como espacios en blanco, por lo que múltiples comandos pueden estar en la misma línea.

La sintaxis para especificar valores en el archivo de configuración es consistente para todos los comandos, a saber:

color
Un color debe ser uno de los aproximadamente 20 nombres de color de Qt (consulte la clase QColor en https://doc.qt.io/qt-5/qcolor.html#predefined-colors), o un valor hexadecimal de color HTML (entre comillas, por ejemplo, "#ff6347"), o tres valores reales normalizados que representan la saturación de rojo, verde y azul. Por ejemplo, los siguientes colores son idénticos:


rojo
"#ff0000"
1.0 0.0 0.0
int
Un número entero.
métrica
Una métrica consiste en una fuente opcional (host o archivo), el nombre de la métrica, una lista de instancias opcional inmediatamente después del nombre, seguida del máximo (o valor de normalización). Se utiliza dos puntos (``:'') para separar un nombre de host de la métrica, y una barra diagonal (``/'') para separar un nombre de archivo de la métrica. Las instancias se encierran entre corchetes y se separan por comas. Cada instancia puede encerrarse entre comillas.
Por ejemplo, algunas métricas legales son: 


kernel.all.cpu.idle 4000
mihost:kernel.all.cpu.idle[cpu0,"cpu3"] 1000.0
/ruta/a/miarchivo/kernel.all.cpu.idle[cpu1] 1000

Para ayudar al proceso de coincidencia de nombres de instancia, se realizan dos comparaciones adicionales más allá de una simple comparación de cadenas. Si el nombre de instancia contiene espacios, solo la primera palabra del nombre de instancia debe coincidir con la instancia, asumiendo que la primera palabra es única. Si la primera palabra no es única, solo se seleccionará la primera instancia coincidente. La segunda comparación ocurre si la primera palabra es un número con ceros iniciales. Cualquier cero inicial se omitirá antes de volver a comparar la primera palabra. Esto permite que los IDs de proceso utilizados en las métricas de proc se coincidan fácilmente, sin especificar el nombre completo de la instancia. Por ejemplo, para visualizar el tiempo de usuario y sistema de init, use la especificación de métrica


proc.psusage.utime[1]	1000
proc.psusage.stime[1]	1000

nombre
Un nombre para un objeto al que se puede hacer referencia más adelante en el archivo de configuración. Los nombres deben ser una sola palabra que conste de todos los caracteres alfanuméricos, así como guiones bajos, guiones y dos puntos. Se recomienda que los nombres no comiencen con un guion bajo, ya que esto puede interpretarse como una palabra clave.
posición
Esta es la posición del objeto dentro de la cuadrícula. La sintaxis de una posición es:

[ [x z] [ [ancho profundidad] [alineación] ] ]
x
La coordenada horizontal (de izquierda a derecha) del objeto, comenzando en 0. El valor predeterminado de x es 0.
z
La coordenada vertical (de arriba a abajo) del objeto, comenzando en 0. El valor predeterminado de z es 0.
ancho
El número de columnas ocupadas por el objeto. El valor predeterminado de ancho es 1.
profundidad
El número de filas ocupadas por el objeto. El valor predeterminado de profundidad es 1.
alineación
El borde o esquina con el que se alinea el objeto. Las alineaciones posibles incluyen: norte, sur, este, oeste, noreste, noroeste, sureste, suroeste y centro. También se aceptan abreviaturas como se y SE. La alineación predeterminada es centro.
El tamaño de un objeto puede no conocerse, ya que el número de instancias para algunas métricas variará entre hosts y configuraciones de PMDA. Por lo tanto, la posición del objeto se puede utilizar para especificar el tamaño probable del objeto, para que la posición de los objetos circundantes se ajuste adecuadamente.
Las siguientes son posiciones legales:

0 5
El objeto está centrado en la posición de la cuadrícula 0,5, ocupando 1 cuadrado de la cuadrícula.

1 2 norte
El objeto está alineado con el borde norte de la posición 1,2, ocupando 1 cuadrado de la cuadrícula.

2 2 2 1 este
El objeto está alineado con el borde este de la posición 3,2 y ocupa 2 cuadrados de la cuadrícula (2,2 y 3,2).
cadena
Una cadena es una serie de caracteres encerrados entre comillas dobles. Una cadena no puede contener saltos de línea ni comillas dobles escapadas.

Hay varios parámetros que pueden afectar el tamaño, la forma y el color de los objetos cuando se muestran. Estos parámetros están definidos por ámbito, de modo que solo alteran los objetos definidos más adelante en el mismo ámbito. Por lo tanto, la configuración de parámetros en la parte superior de un archivo de configuración afecta a toda la escena, a menos que se cambien más adelante en el archivo. La mayoría de estos parámetros también son recursos.

_barLength int
La longitud del lado de los bloques _bar y _stack. El valor predeterminado es 28.
_barHeight int
La altura máxima de los bloques _bar y _stack. El valor predeterminado es 80.
_baseColor color
El color de los planos base de _bar, _grid y _stack. El valor predeterminado es "#262626" (es decir, gris15).
_baseHeight int
La altura de los planos base de _bar, _grid y _stack. El valor predeterminado es 2.
_gapWidth int
El espacio entre bloques en un objeto _bar en el eje X. El valor predeterminado es 8.
_gapDepth int
El espacio entre bloques en un objeto _bar en el eje Z. El valor predeterminado es 8.
_gapLabel int
El espacio entre la base de un objeto _bar y cualquier etiqueta de métrica o instancia. El valor predeterminado es 6.
_gridWidth int
El ancho mínimo de una columna _grid. El valor predeterminado es 20.
_gridDepth int

_labelMargin int
El margen alrededor de un objeto _label. El valor por defecto es 5.
_labelColor color
El color de las etiquetas de _label y _bar. El valor por defecto es blanco.
_marginWidth int
El ancho adicional de un plano base de _bar, _grid y _stack más allá de los objetos en el plano. El valor por defecto es 8.
_marginDepth int
La profundidad adicional de un plano base de _bar, _grid y _stack más allá de los objetos en el plano. El valor por defecto es 8.

Longitud total de una _pipe. El valor por defecto es el valor de _barHeight.
_scale real
La escala aplicada a toda la escena. Este parámetro puede no ser utilizado dentro de ningún objeto, solo en la parte superior del archivo de configuración. El valor por defecto es 1.0.

Para simplificar la especificación de colores, se pueden usar una _colorList y una _colorScale para definir colores para un objeto que tiene métricas asociadas, es decir, _bar, _stack o _pipe. Una lista de colores puede definirse dentro de un objeto, o nombrarse y definirse en la parte superior de un archivo de configuración. Una lista de colores con nombre puede ser referenciada dentro de múltiples objetos:

_colorList nombre ( color [color...] )
Asocia los colores a la lista de colores nombre. La asignación de colores a los bloques depende del tipo de objeto. Por ejemplo, la lista de colores llamada foo tiene el mismo color tres veces: 
_colorList foo ( red "#ff0000" 1.0 0.0 0.0 )
_colorScale nombre color ( color real [color real...] )
Asocia los colores y reales con la lista de colores nombre. El color inicial es el color por defecto del objeto. El objeto cambiará de color a los otros colores cuando el valor normalizado del objeto sea igual o mayor que cada real. Por lo tanto, cada real debe ser mayor que el real anterior, y debe estar en el rango de 0.0 a 1.0. Esta escala cambia gradualmente de azul a rojo:
_colorScale coldToHot blue ( "#7f00ff" 0.3
                             purple 0.6
                             "#ff007f" 0.8
                             red 0.95)

Hay varios tipos de objetos diferentes que se pueden encontrar en una escena pmview: _bar, _stack, _pipe, _grid, _link y _label. También está _xing, que es un tipo especial de _link. Los objetos _bar, _stack y _pipe son modulados por valores métricos, un _label es texto fijo, _link y _xing son interconexiones y un _grid es un contenedor de objetos, incluyendo otros objetos _grid, que controla la disposición de la escena. Un objeto _grid solo es necesario si hay dos o más objetos en la escena.

Los objetos _bar, _grid y _stack pueden tener planos base que proporcionan un punto de referencia para los bloques a medida que cambian de altura. Se puede aplicar una etiqueta al plano base del objeto _grid si está _shown con:


_baseLabel nombre|cadena

_baseLabel debe usarse dentro del alcance del objeto _bar, _grid o _stack relevante. Los primeros caracteres ``\n'' en la cadena se reemplazarán por un salto de línea. Los caracteres ``\n'' subsiguientes se ignorarán.

Para que una escena sea válida, debe contener al menos un objeto modulado.

Los objetos se definen como:

_bar [opciones] ( [lista-métricas] [lista-colores] [lista-etiquetas] )
Un objeto _bar representa una colección de bloques. El número de bloques depende del número de métricas y instancias de métricas asignadas al objeto. Por defecto, los bloques se modulan cambiando la altura de cada bloque. Alternativamente, los bloques pueden modularse cambiando el color, o tanto la altura como el color. Cada color en la lista-colores se asigna a cada métrica. Por lo tanto, múltiples instancias de la misma métrica tendrán el mismo color. Las opciones que se pueden pasar a un objeto _bar son:
pos
La posición del objeto _bar dentro del objeto _grid actual.
_col|_row
Posiciona los bloques de manera que cada instancia esté en una columna (_col) o una fila (_row). Esto implica que cada métrica diferente estará en una fila o columna separada, respectivamente. El valor por defecto es _col.
_show|_hide
¿Es visible el plano base? El valor por defecto es _show.
_ymod|_colormod|_colorymod
Modula los bloques ajustando su altura (_ymod), color (_colormod) o ambos (altura y color) (_colorymod).
_cube|_cylinder
Establece la forma de los bloques. El valor por defecto es _cube.
_groupbymetric|_groupbyinst|_groupbyrow||groupbycol
Establece la agrupación de bloques al lanzar otras herramientas. Para herramientas como pmchart(1), algunas vistas pueden generar muchos gráficos pequeños que no se pueden dibujar completamente dentro de la pantalla. Otro problema es que puede ser más apropiado generar gráficos con la misma instancia en cada gráfico, en lugar de la misma métrica. Los especificadores de grupo controlan el algoritmo utilizado para que se dibuje un gráfico separado para cada especificación de _metrics (_groupbymetric), para la primera, segunda, etc. instancia de cada _metric (_groupbyinst), o por las filas y columnas del objeto _bar dependiendo de _row o _col. El valor por defecto es _groupbymetric.

Las opciones deben especificarse en este orden, aunque las opciones precedentes no son obligatorias. Por lo tanto, esto es legal:


_bar _hide _cylinder ( ... )

Las métricas, colores y etiquetas se especifican entre corchetes en cualquier orden. Solo la lista-métricas es obligatoria.

lista-métricas
Una lista de métricas de _bar contiene una lista de nombres de métricas, valores de normalización y una etiqueta opcional para la métrica: 
_metrics ( métrica real [cadena] [métrica real [cadena]...] )
lista-colores
Una lista de colores de _bar puede ser una lista de colores con nombre definida anteriormente, o una lista de colores sin nombre. Se debe usar una lista _colorScale cuando se utilizan la modulación _colormod o _colorymod. Por lo tanto, la sintaxis para las listas de colores dentro de un objeto _bar es cualquiera de: 
_colorList nombre
_colorList ( color [color...] )
_colorScale nombre
_colorScale color ( color real [color real...] )
lista-etiquetas
Además de las etiquetas para cada métrica en la lista-métricas, se pueden definir etiquetas de métrica e instancia usando las declaraciones _metriclabels y _instlabels. La posición de las etiquetas alrededor del objeto _bar depende de la orientación _row o _col de las métricas e instancias, y de si la etiqueta se lee _towards (hacia) el objeto _bar, o _away (lejos). El valor por defecto es _towards. 
_metriclabels [_away|_towards] ( nombre|cadena [nombre|cadena...] )
_instlabels [_away|_towards] ( nombre|cadena
[nombre|cadena...] )
_grid [pos] [_show|_hide] ( objetos )
Un objeto _grid es un contenedor para objetos, incluyendo otros objetos _grid. Las filas y columnas de un objeto _grid se redimensionan al tamaño del objeto más grande en la fila o columna. Si un objeto abarca varias filas y/o columnas, esas filas y columnas pueden ser redimensionadas parcialmente para contener el objeto. Sin embargo, el redimensionamiento de filas y columnas para objetos que ocupan un solo cuadrado de la cuadrícula ocurre después del redimensionamiento para objetos que ocupan solo un cuadrado de la cuadrícula.

Una colisión entre objetos que ocupan los mismos cuadrados se informará como un mensaje de error y el objeto posterior será ignorado.

Las opciones de un objeto _grid controlan la posición (pos) del objeto _grid en el _grid padre, e indican si mostrar (_show) u ocultar (_hide) el plano base del _grid. Por defecto, el plano base está oculto.

Los parámetros descritos anteriormente pueden especificarse dentro de los corchetes de un objeto _grid, sin embargo, solo se aplican a los objetos dentro del _grid, no al _grid en sí. Para que un parámetro se aplique a un objeto _grid, debe especificarse antes de la declaración del objeto _grid.

_label [opciones] cadena
Un objeto _label dibuja el contenido de cadena en la posición, orientación y tamaño especificados en las opciones:
pos
La posición del objeto _label en el objeto _grid actual.
_left|_right|_up|_down
La orientación de la cadena. La dirección indica la dirección en la que se lee la etiqueta. Por lo tanto, _right es el valor por defecto ya que la cadena se lee de izquierda a derecha.
_small|_medium|_large
El tamaño de la fuente. El valor por defecto es _medium.
_link pos [cadena]
Un objeto _link dibuja una tubería redonda horizontal recta o en forma de L con un diámetro igual al 80% de la _baseHeight de un _grid contenedor. Las propiedades del objeto se definen mediante las opciones:
pos

pmview(5) — Performance Co-Pilot — Arch Linux

NAME

pmview - Performance Co-Pilot visualization tool configuration syntax

DESCRIPTION

The pmview syntax is used to describe the layout of visualizations. This specification describes the available objects and their associated syntax.

_label col row string
Adds a text label to the visualization. The col and row parameters specify the location of the label on the grid. The string parameter is the text to be displayed.
_link col1 row1 col2 row2 [label]
Draws a link between two points on the grid. The first two parameters define the starting point, and the next two parameters define the ending point. An optional label can be provided. The size of the link is determined by the distance between the two points. The alignment value is used to decide the orientation of the link (links are always aligned at the center): east and west links are straight and going from left to right, north and south links are straight and going from far end of the grid to near end, northeast, northwest, southeast and southwest links are L-shaped and connect the corresponding points of the compass, i.e. a northeast link takes on the general shape of the Latin letter ``L''.
string
sets the ``tag'' for the _link which will be displayed in the text window when the pointer is over the link.
_pipe pos ( [metric-list] [color-list] [tag] )
A _pipe object represent a set of cylinders, placed on top of each other and oriented parallel to the base plane. The diameter of a _pipe is equal to 80% of _baseHeight. The number of blocks is dependent on the number of metric instances in the metric-list. The colors in the color-list are assigned in turn to each cylinder in the _pipe. The length of the _pipe is defined by the _pipeLength.
pos
defines the position of the _pipe on the enclosing _grid and its orientation with alignment field used to define at which end of the pipe to stack the colored cylinders. The cylinders are stacked at the corresponding point of the compass and the pipe's direction is from the point of the compass towards the center of the compass. Only east, west, north, and south are valid values for the pipe's alignment.
The metrics, colors and label may be specified within the brackets in any order. Only the metric-list is mandatory.
metric-list
A _pipe metric list contains a list of metric names and normalization values: 
_metrics ( metric real [metric real...] )
color-list
A _pipe color list may be named color list that was defined earlier, or an unnamed color list: 
_colorList name
_colorList ( color [color...] )
tag
A _pipe may have a ``tag'' for the filler block (unanimated block on the ``other'' end of the pipe) which will be displayed in the text window when the pointer is over that end of the pipe. 
_pipeTag name|string
_stack [options] ( [metric-list] [color-list] [label] )
A _stack object represents a set of blocks placed vertically on top of each other. The number of blocks is dependent on the number of metric instances in the metric-list. The colors in the color-list are assigned to each block in the _stack. By default, the height of the _stack will be the sum of the height of each block. The options that may be passed to a _stack object are:
pos
The position of the _stack object within the current _grid object.
_show|_hide
Is the base plane visible? Default is _show.
_utilmod|_fillmod
Force the height of the stack to always be the maximum height. This is achieved by normalizing the height of each block (_utilmod), or by adding a grey block to the top of the stack (_fillmod).
_cube|_cylinder
Set the shape of the blocks. The default is _cube.

The options must be specified in this order, although preceding options are not required. Therefore, this is legal:


_stack 1 1 _north _utilmod ( ... )

The metrics, colors and label may be specified within the brackets in any order. Only the metric-list is mandatory.

metric-list
A _stack metric list contains a list of metric names and normalization values: 
_metrics ( metric real [metric real...] )
color-list
A _stack color list may be named color list that was defined earlier, or an unnamed color list: 
_colorList name
_colorList ( color [color...] )
label
A _fillmod type _stack may have a label for the filler block: 
_stackLabel name|string
_xing col row columns rows dir1 ... dir4
A _xing is a special kind of link which is used to draw a pair of links which cross each other. To convey the visual impression that the links do not join, one of the links is drawn as a ``broken'' cylinder. col and row define the position on the enclosing grid. columns and rows define the size of the bounding box. The end points of the crossing cylinders are placed exactly in the center of the corner cells of the bounding box and four small cylinders or stubs are used to join the perimeter of the bounding box with the end points on the crossing cylinders. Four dir values define the orientation of the stubs, starting at the upper left corner of the _xing and proceeding clockwise, such that respective stubs are used to join the point of the compass with the center on the cell (see example).

EXAMPLE

This simple example illustrates the use of parameters and different object types:


pmview Version 2.1
# Use a lighter grey for the base planes
_baseColor "#7f7f7f"
# Define colors for CPU object
_colorList cpu ( blue2 red2 yellow2 cyan2 green2 )
# The top grid object, but hide it from view
_grid _hide (
# Show the current load in a bar object
   _bar 0 0 (
       _baseLabel "Load averages over a\n1, 5 and 15 minute interval"
       _metrics (
		kernel.all.load[1] 1 "1"
		kernel.all.load[5] 1 "5"
		kernel.all.load[15] 1 "15"
	)
	_colorList ( blue blue blue )
    )
# Add a label below the load bars
    _label 0 1 "Load"
# Change the color of the base plane for later objects
    _baseColor "#fba2f5" # pink
# Show the CPU usage over all CPUs in a utilization stack
    _stack 2 0 _south _utilmod (
	_baseLabel "CPU Utilization over all CPUs"
	_metrics (
		kernel.all.cpu.user 1000
		kernel.all.cpu.sys 1000
		kernel.all.cpu.intr 1000
		kernel.all.cpu.wait.total 1000
		kernel.all.cpu.idle 1000
	)
	_colorList cpu
    )
# Add a label below the CPU stack
    _label 2 1 "CPU"
# Create a separate grid for links and pipes
    _marginWidth 1
    _marginDepth 1
    _gridSpace  12
    _grid 0 3 5 4 _hide (
	_pipeLength 12
	_baseHeight 12
	# Add  a pipe and a link with western orientation
	_pipe 0 0 west (
	    _pipeTag "West pipe"
	    _metrics (
		kernel.all.cpu.user 1000
		kernel.all.cpu.sys 1000
		kernel.all.cpu.idle 1000
	    )
	    _colorList cpu
	)
	_link 0 2 west "West link"
	# Add xing
	_xing 1 0 3 3 west east east west
	# Add a link and a pipe with eastern orientation
	_pipe 4 0 east (
	    _pipeTag "East Pipe"
	    _metrics (
		kernel.all.cpu.user 1000
		kernel.all.cpu.sys 1000
		kernel.all.cpu.idle 1000
	    )
	    _colorList cpu
	)
	_link 4 2 east "East link"
    )
)
