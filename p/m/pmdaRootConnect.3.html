NOMBRE

int pmdaRootContainerProcessID(int fd,
char *name, int namelen);

int pmdaRootContainerCGroupName(int fd,
char *name, int namelen, char *buffer, int buflen);

int pmdaRootProcessStart(int fd,
int ipctype, char *label, int labellen, const char *args, int argslen, int *pid, int *infd, int *outfd);

cc ... -lpcp_pmda -lpcp

DESCRIPCIÓN

pmdaRootConnect inicializa un canal IPC entre un proceso coleccionista de PCP - ya sea un PMDA(3) o el propio pmcd(1) - y el servidor pmdaroot(1).

En caso de éxito, el valor de retorno de pmdaRootConnect es un descriptor de archivo de socket de dominio unix(7), que puede pasarse posteriormente a cada una de las otras API descritas aquí. Este canal se puede utilizar para realizar una escalada limitada de privilegios para escenarios específicos necesarios por los servicios de recolección de PCP. El canal se puede desactivar utilizando la interfaz pmdaRootShutdown.

CONTENEDORES

Se proporcionan varias interfaces para acceder a las facilidades de contenedores de las distribuciones Linux modernas, según lo necesiten varios agentes que accedan a características del kernel relacionadas con contenedores.

pmdaRootContainerHostName permite buscar el nombre de host actual para un contenedor con nombre en nombre de un proceso no privilegiado, a través de la llamada al sistema setns(3) en Linux. En caso de éxito, el nombre de host se devuelve en el buffer suministrado, de tamaño buflen, y el valor de retorno indica la longitud del nombre de host.

pmdaRootContainerProcessID realiza una traducción de nombre a identificador de proceso; en caso de éxito, el valor de retorno es el identificador del primer proceso iniciado (proceso 1) en el contenedor con nombre.

pmdaRootContainerCGroupName rellena el buffer suministrado con los nombres específicos del motor de los grupos de control del kernel que se han utilizado para construir el contenedor identificado por name. Cuando tiene éxito, el valor de retorno indica la longitud del nombre del cgroup resuelto para el contenedor.

El nombre del contenedor es interpretado por pmdaroot(1), que intenta hacer coincidir el nombre especificado con una de las implementaciones de contenedores de las que tiene conocimiento. Por lo tanto, el argumento name se interpreta potencialmente de manera diferente, dependiendo del motor de contenedores instalado, según lo determine internamente pmdaroot).

En el caso del motor de contenedores Docker, por ejemplo, un nombre de contenedor válido puede ser el identificador hash único, el nombre legible por humanos o cualquier subcadena de identificador única. Este es el algoritmo utilizado por las propias herramientas cliente de Docker.

PROCESOS

Se proporciona un segundo conjunto de interfaces que permiten al sistema coleccionista iniciar procesos hijos privilegiados. En particular, estos son utilizados por pmcd(1) para que pueda iniciar PMDAs privilegiados incluso cuando se ejecuta bajo una cuenta no privilegiada.

Estas interfaces permiten iniciar procesos (pmdaRootProcessStart), recuperarlos al finalizar (pmdaRootProcessWait) y terminarlos forzosamente mediante señales (pmdaRootProcessTerminate). En esta etapa, solo están destinadas a ser utilizadas por el propio pmcd y, como tales, se describen aquí solo por completitud.

DIAGNÓSTICOS

Todas las interfaces de pmdaRoot devolverán códigos de estado negativos adecuados para pasarlos a pmErrStr_r(3).

VER TAMBIÉN

pmcd(1), pmdaroot(1), pmErrStr_r(3), PMDA(3), setns(3) y unix(7).
