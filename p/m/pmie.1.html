PMIE(1) Manual de Comandos Generales PMIE(1)

NOMBRE

pmie - motor de inferencia para métricas de rendimiento

SINOPSIS

pmie [-bCdeFfPqvVWxXz?] [-a archivo] [-A alinear] [-c config] [-D debug] [-h host] [-l archivo_log] [-m nota] [-j archivo_stomp] [-n archivo_pmns] [-o formato] [-O offset] [-S hora_inicio] [-t intervalo] [-T hora_fin] [-U usuario] [-Z zona_horaria] [archivo ...]

DESCRIPCIÓN

pmie acepta una colección de expresiones aritméticas, lógicas y reglas a ser evaluadas con frecuencias especificadas. Los datos base para las expresiones consisten en valores de métricas de rendimiento entregados en tiempo real desde cualquier host que ejecute el Demonio de Recolección de Métricas de Rendimiento (PMCD), o usando datos históricos de archivos de Performance Co-Pilot (PCP).

Además de computar valores aritméticos y lógicos, pmie puede ejecutar acciones (alertas emergentes, escribir mensajes en el log del sistema y lanzar programas) en respuesta a condiciones especificadas. Tales acciones son extremadamente útiles para detectar, monitorear y corregir problemas relacionados con el rendimiento.

Las expresiones a ser evaluadas se leen de archivos de configuración especificados por uno o más argumentos archivo. En ausencia de algún archivo, las expresiones se leen de la entrada estándar.

La salida de pmie se dirige a la salida estándar y al error estándar de la siguiente manera:

salida_estándar
Valores de expresión impresos en el modo detallado -v y la salida de acciones print.
error_estándar
Mensajes de error y advertencia para cualquier problema sintáctico o semántico durante el análisis de expresiones, y cualquier problema semántico o de disponibilidad de métricas de rendimiento durante la evaluación de expresiones.

OPCIONES

Las opciones de línea de comandos disponibles son:

-a archivo, --archivo=archivo
archivo que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos escritos por pmlogger(1). Múltiples instancias del flag -a pueden aparecer en la línea de comandos para especificar una lista de conjuntos de archivos. En este caso, se requiere que solo un conjunto de archivos esté presente para cualquier host. Además, cualquier nombre de host explícito que ocurra en una expresión de pmie debe coincidir con el nombre de host registrado en una de las etiquetas de archivo. En el caso de múltiples conjuntos de archivos, las marcas de tiempo registradas en los archivos se utilizan para garantizar la consistencia temporal.
-A alinear, --alinear=alinear
Forzar que la ventana de tiempo inicial se alinee en el límite de una unidad de tiempo natural alinear. Consulte PCPIntro(1) para una descripción completa de la sintaxis para alinear.
-b, --buffer
La salida será con buffer de línea y la salida estándar estará conectada al error estándar. Esto es más útil para ejecución en segundo plano junto con la opción -l. La opción -b siempre se usa para instancias de pmie lanzadas desde pmie_check(1).
-c config, --config=config
Una alternativa a especificar archivo al final de la línea de comandos.
-C, --check
Analizar el(los) archivo(s) de configuración y salir antes de realizar cualquier evaluación. Se informan los errores en el archivo de configuración.
-d, --interactivo
Normalmente pmie se lanzaría como un proceso no interactivo para monitorear y gestionar el rendimiento de uno o más hosts. Sin embargo, dada la flag -d, la ejecución es interactiva y se presenta al usuario un menú de opciones. El modo interactivo es útil principalmente para depurar nuevas expresiones.
-e, --timestamp
Cuando se usa con -V, -v o -W, esta opción fuerza que se informen marcas de tiempo con cada expresión. Las marcas de tiempo están en formato ctime(3), encerradas entre paréntesis y aparecen después del nombre de la expresión y antes del valor de la expresión, ej. 
expr_1 (Mar 6 19:55:10 2001): 12
-f, --foreground
Si se especifica la opción -l y no hay opción -a (es decir, monitoreo en tiempo real) entonces pmie se ejecuta como un demonio en segundo plano (en todos los demás casos, el primer plano es el predeterminado). Las opciones -f (y -F, ver abajo) fuerzan que pmie se ejecute en primer plano, independientemente de cualquier otra opción.
-F, --systemd
Al igual que -f, la opción -F ejecuta pmie en primer plano, pero también realiza algunas tareas de mantenimiento (como crear un archivo PID, cambiar el ID de usuario y notificar a systemd(1) cuando pmie ha comenzado o se está cerrando). Esto está destinado a usarse cuando pmie es lanzado desde systemd(1) y la daemonización ya se ha realizado. Las opciones -f y -F son mutuamente excluyentes.
-h host, --host=host
Por defecto, los datos de rendimiento se obtienen del host local (en modo de tiempo real) o del host del primer conjunto de archivos nombrados en la línea de comandos (en modo de archivo). El argumento host anula este valor predeterminado. No anula los hosts nombrados explícitamente en las expresiones que se evalúan. El argumento host se interpreta como una especificación de conexión para pmNewContext, y posteriormente se mapea al nombre de host autoinformado del pmcd remoto para fines de informe. Ver también las sustituciones %h vs. %c en las cadenas de acción de reglas a continuación.
-j archivo
Se carga una configuración alternativa del protocolo STOMP desde archivo_stomp. Si esta opción no se utiliza, y la acción stomp se utiliza en alguna regla, se usará la ubicación predeterminada $PCP_SYSCONF_DIR/pmie/config/stomp.
-l archivo_log, --archivo_log=archivo_log
El error estándar se envía a archivo_log.
-m nota, --nota=nota
Se utiliza para indicar desde dónde se ha lanzado pmie, por ejemplo, pmie_check(1) y pmie_daily(1) usan -m pmie_check y esto es utilizado por pmie para determinar si necesita ser reiniciado en caso de que el nombre de host de PMCD cambie, como se describe en la sección CAMBIOS DE NOMBRE DE HOST a continuación.
-n archivo_pmns, --namespace=archivo_pmns
Se carga un Espacio de Nombres de Métricas de Rendimiento (PMNS) alternativo desde el archivo archivo_pmns.
-o formato, --formato=formato
Al procesar datos de rendimiento de un archivo, la opción -o puede usarse para especificar un formato de salida alternativo cuando se ejecuta una acción de regla. Ver la sección DIFERENCIAS EN MODO HOST Y ARCHIVO para una descripción de cómo puede construirse el formato de salida.
-O origen, --origen=origen
Especificar el origen de la ventana de tiempo. Ver PCPIntro(1) para una descripción completa de esta opción.
-P, --primario
Identifica esta como la instancia primaria de pmie para un host. Ver la sección ``REINICIO AUTOMÁTICO'' a continuación para más detalles.
-q, --quiet
Suprime los mensajes de diagnóstico que se imprimirían en la salida estándar por defecto, especialmente el mensaje "evaluador saliendo" ya que puede confundir a los scripts.
-S hora_inicio, --inicio=hora_inicio
Especificar la hora_inicio de la ventana de tiempo. Ver PCPIntro(1) para una descripción completa de esta opción.
-t intervalo, --intervalo=intervalo
Especificar el intervalo entre muestras en tiempo real. Ver PCPIntro(1) para una descripción completa de esta opción.
-T hora_fin, --fin=hora_fin
Especificar la hora_fin de la ventana de tiempo. Ver PCPIntro(1) para una descripción completa de esta opción.
-U usuario, --usuario=usuario
Especificar el usuario (nombre de usuario o UID numérico) bajo el cual se ejecutará pmie. Si se especifica la opción -f o -F, pmie se ejecutará bajo el usuario especificado, después de haber sido iniciado como el usuario que ejecuta el comando. Si el usuario especificado no puede ser encontrado o si no se puede ejecutar el programa debido a problemas de permisos, se informará un error.
-V, --version
Versión de PCP.
-v, --verbose
Modo detallado. Cuando se usa con -V, -e o -W, cada expresión se imprime con su valor y marca de tiempo (si se especifica -e).
-W, --showstate
Similar al modo detallado -v, pero también muestra el estado (por ejemplo, instanciado, pendiente, inactivo) de cada expresión.
-x, --singlepass
Procesar los archivos de entrada solo una vez. Normalmente, cuando se leen datos de un archivo, pmie puede leerlos hasta dos veces. La primera vez para determinar los tipos y la disponibilidad de todas las métricas, y la segunda vez para realizar la evaluación. La opción -x fuerza a que se realice la evaluación en una sola pasada, lo que puede ser útil para archivos de solo lectura donde los permisos impiden el acceso repetido.
-X, --nowild
Deshabilitar el soporte de metadatos para métricas con comodines. Esto deshabilita la capacidad de usar comodines en las métricas de un script y debe ser usado solo cuando se usa la opción -x (singlepass). Si se usa -X sin -x, se producirá un error.
-z, --zero
Establecer la hora de inicio del período de muestreo en cero.
-Z zona_horaria, --timezone=zona_horaria
Especificar la zona_horaria para la recuperación de datos. Ver PCPIntro(1) para una descripción completa de esta opción.
?
Imprimir un mensaje de uso y salir.

OPTIONS

-a archive, --archive=archive
Extract performance metrics from a set of disk archives named archive. See pcarchiver(1) for a complete description of the archive format and syntax for specifying multiple archives.
-c config, --config=config
Specify the name of the configuration file containing the pmie expressions and associated actions. The default is $PCP_PMIE_CONFFILE, which is typically /etc/pcp/pmie.conf.
-d, --daemon
Run pmie as a daemon. When run in this mode, pmie can be controlled using the Control-C mechanism. To terminate pmie, send it an interrupt signal (SIGINT). For full details on controlling pmie when run as a daemon, see pmie(1).
-e domain, --domain=domain
Specify the domain number of the performance metric domain to be used for PCP data. This is an optional argument and defaults to domain 0 if not supplied. This option is of primary use in conjunction with the pmie(1) command.
-h host, --host=host
Extract performance metrics from a local or remote Performance Metrics Collector (PMCD), specified by host. The default is to use the Performance Metrics Collector daemon on the local machine.
-i instance, --instance=instance
When used in conjunction with the pmie(1) command, this option restricts the set of instances for which the performance metrics are extracted. The instance argument is a comma-separated list of instance names or numbers. If the performance metric does not support instance discovery, then this option is ignored.
-m metric, --metric=metric
Specify the performance metric identifier that should be extracted. This option can be used multiple times to extract multiple performance metrics. When used in conjunction with the pmie(1) command, this option can be used to restrict the set of performance metrics that are evaluated.
-O config, --origconfig=config
Specify the name of the original configuration file. This option is used when processing archives that contain derived metric values, which were originally generated by pmie(1).
-p port, --port=port
Specify the port number to be used for communication with PMCD. The default is the value defined by the PMCD_PORT environment variable or 4444 if the environment variable is not set.
-q, --quickstart
Run in quickstart mode. This mode bypasses the normal initialization processing and loads the default rule set. This option is primarily useful for debugging.
-s start_time, --start=start_time
Specify the start_time for the time window. See PCPIntro(1) for complete description of this option.
-t interval, --interval=interval
The interval argument follows the syntax described in PCPIntro(1), and in the simplest form may be an unsigned integer (the implied units in this case are seconds). The value is used to determine the sample interval for expressions that do not explicitly set their sample interval using the pmie variable delta described below. The default is 10.0 seconds.
-T endtime, --finish=endtime
Specify the endtime of the time window. See PCPIntro(1) for complete description of this option.
-U username, --username=username
User account under which to run pmie. The default is the current user account for interactive use. When run as a daemon, the unprivileged "pcp" account is used in current versions of PCP, but in older versions the superuser account ("root") was used by default.
-v
Unless one of the verbose options -V, -v or -W appears on the command line, expressions are evaluated silently, the only output is as a result of any actions being executed. In the verbose mode, specified using the -v flag, the value of each expression is printed as it is evaluated. The values are in canonical units; bytes in the dimension of ``space'', seconds in the dimension of ``time'' and events in the dimension of ``count''. See pmLookupDesc(3) for details of the supported dimension and scaling mechanisms for performance metrics. The verbose mode is useful in monitoring the value of given expressions, evaluating derived performance metrics, passing these values on to other tools for further processing and in debugging new expressions.
-V, --verbose
This option has the same effect as the -v option, except that the name of the host and instance (if applicable) are printed as well as expression values.
-W
This option has the same effect as the -V option described above, except that for boolean expressions, only those names and values that make the expression true are printed. These are the same names and values accessible to rule actions as the %h, %i, %c and %v bindings, as described below.
-x, --secret-agent
Execute in domain agent mode. This mode is used within the Performance Co-Pilot product to derive values for summary metrics, see pmdasummary(1). Only restricted functionality is available in this mode (expressions with actions may not be used).
-X, --secret-applet
Run in secret applet mode (thin client).
-z, --hostzone
Change the reporting timezone to the timezone of the host that is the source of the performance metrics, as identified via either the -h option or the first named set of archives (as described above for the -a option).
-Z timezone, --timezone=timezone
Change the reporting timezone to timezone in the format of the environment variable TZ as described in environ(7).
-?, --help
Display usage message and exit.

EJEMPLOS

Los siguientes ejemplos de expresiones demuestran algunas de las capacidades del motor de inferencia.

El directorio $PCP_DEMOS_DIR/pmie contiene una serie de otros ejemplos anotados de expresiones de pmie.

La variable delta controla la frecuencia de evaluación de la expresión. Especifique que las expresiones subsiguientes se evalúen una vez por segundo, hasta nuevo aviso:

delta = 1 sec;

Si la tasa total de cambio de contexto supera los 10000 por segundo por CPU, muestre un notificador de alarma:

kernel.all.pswitch / hinv.ncpu > 10000 count/sec
-> alarm "high context switch rate %v";

Si la alta tasa de cambio de contexto se mantiene durante 10 muestras consecutivas, inicie top(1) en una ventana de xterm(1) para monitorear procesos, pero hágalo como máximo una vez cada 5 minutos:

all_sample (
    kernel.all.pswitch @0..9 > 10 Kcount/sec * hinv.ncpu
) -> shell 5 min "xterm -e 'top'";

Las siguientes reglas se evalúan una vez cada 20 segundos:

delta = 20 sec;

Si algún disco está realizando más de 60 E/S por segundo, imprima un mensaje identificando el disco ocupado en la salida estándar e inicie dkvis(1):

some_inst (
    disk.dev.total > 60 count/sec
) -> print "busy disks:" " %i" &
     shell 5 min "dkvis";

Refine la regla anterior para que solo se aplique entre las 9 a.m. y las 5 p.m., y para que se requieran 3 de 4 muestras consecutivas para superar el umbral antes de ejecutar la acción:

$hour >= 9 && $hour <= 17 &&
some_inst (
  75 %_sample (
    disk.dev.total @0..3 > 60 count/sec
  )
) -> print "disks busy for 20 sec:" " [%h]%i";

Las siguientes dos reglas se evalúan una vez cada 10 minutos:

delta = 10 min;

Si el sistema de archivos / o /usr está lleno en más del 95%, muestre una alarma emergente, pero no si ya se ha mostrado en las últimas 4 horas:

filesys.free #'/dev/root' /
    filesys.capacity #'/dev/root' < 0.05
-> alarm 4 hour "root filesystem (almost) full";
filesys.free #'/dev/usr' /
    filesys.capacity #'/dev/usr' < 0.05
-> alarm 4 hour "/usr filesystem (almost) full";

La siguiente regla requiere una máquina que admita las métricas de lmsensors. Si la temperatura ambiente de la máquina aumenta más de 2 grados en un intervalo de 10 minutos, escriba una entrada en el registro del sistema:

lmsensors.coretemp_isa.temp1 @0 - lmsensors.coretemp_isa.temp1 @1 > 2
-> alarm "temperature rising fast" &
   syslog "machine room temperature rise alarm";

Y algo interesante si tienes problemas de rendimiento con tu base de datos Oracle:

// back to 30sec evaluations
delta = 30 sec;
sid = "ptg1";		# $ORACLE_SID setting
lid = "223";		# latch ID from v$latch
lru = "#'$sid/$lid cache buffers lru chain'";
host = ":moomba.melbourne.sgi.com";
gets = "oracle.latch.gets $host $lru";
total = "oracle.latch.gets $host $lru +
         oracle.latch.misses $host $lru +
         oracle.latch.immisses $host $lru";
$total > 100 && $gets / $total < 0.2
-> alarm "high lru latch contention in database $sid";

El siguiente ruleset emitirá exactamente un mensaje dependiendo de la disponibilidad y el valor del promedio de carga de 1 minuto.

delta = 1 minute;
ruleset
     kernel.all.load #'1 minute' > 10 * hinv.ncpu ->
         print "extreme load average %v"
else kernel.all.load #'1 minute' > 2 * hinv.ncpu ->
         print "moderate load average %v"
unknown ->
         print "load average unavailable"
otherwise ->
         print "load average OK"
;

La siguiente regla emitirá un mensaje cuando algún sistema de archivos esté lleno en más del 75% y se esté llenando a una tasa que, si se mantiene, llenaría el sistema de archivos al 100% en menos de 30 minutos.

some_inst (
    100 * filesys.used / filesys.capacity > 75 &&
    filesys.used + 30min * (rate filesys.used) > filesys.capacity
) -> print "filesystem will be full within 30 mins:" " %i";

Si la métrica mypmda.errors cuenta errores, la siguiente regla emitirá un mensaje si la tasa de errores supera 1 por segundo, siempre que el recuento de errores sea inferior a 100.

mypmda.errors > 1 && instant mypmda.errors < 100
-> print "high error rate: %v";

INICIO RÁPIDO

El lenguaje de especificación de pmie es potente y extenso.

Para acelerar el desarrollo rápido de reglas de pmie, la herramienta pmieconf(1) proporciona una facilidad para generar un archivo de configuración de pmie a partir de un conjunto de reglas generalizadas de pmie. El conjunto de reglas suministrado cubre una amplia gama de escenarios de rendimiento.

La Guía del Usuario y Administrador de Performance Co-Pilot proporciona un capítulo detallado estilo tutorial que cubre pmie.

SINTAXIS DE EXPRESIÓN

Esta descripción es concisa e informal. Para una descripción más completa, consulte la Guía del Usuario y Administrador de Performance Co-Pilot.

Una especificación de pmie es una secuencia de expresiones terminadas con punto y coma.

Los operadores básicos están modelados en los operadores aritméticos, relacionales y booleanos del lenguaje de programación C. Las reglas de precedencia son las esperadas, aunque se recomienda el uso de paréntesis para mejorar la legibilidad y eliminar la ambigüedad.

Los operandos son nombres de métricas de rendimiento (ver PMNS(5)) y las constantes literales normales.

Los operandos que involucran métricas de rendimiento pueden producir conjuntos de valores, como resultado de la enumeración en las dimensiones de **hosts**, **instancias** y **tiempo**. Calificadores especiales pueden aparecer después de un nombre de métrica de rendimiento para definir la enumeración en cada dimensión. Por ejemplo,


kernel.percpu.cpu.user :foo :bar #cpu0 @0..2

define 6 valores correspondientes al tiempo dedicado a ejecutar en modo de usuario en la CPU 0 en los hosts ``foo'' y ``bar'' durante las últimas 3 muestras consecutivas. La interpretación predeterminada en ausencia de los calificadores : (host), # (instancia) y @ (tiempo) son todas las instancias en el momento de la muestra más reciente para la fuente predeterminada de métricas de rendimiento de PCP.

Los nombres de host e instancia que no siguen las reglas para variables en lenguajes de programación, es decir, alfabéticos seguidos opcionalmente por alfanuméricos, deben incluirse entre comillas simples.

La evaluación de expresiones sigue la ley de la "menor sorpresa". Donde el rendimiento

cs tienen la semántica de un contador, pmie convertirá automáticamente a una tasa basada en muestras consecutivas y el intervalo de tiempo entre estas muestras. Todas las expresiones numéricas se evalúan en doble precisión y, cuando sea apropiado, se escalan automáticamente a unidades canónicas de "bytes", "segundos" y "recuentos".

Una regla es una forma especial de expresión que especifica una condición o expresión lógica, un operador especial (->) y acciones que se realizarán cuando la condición sea verdadera.

La siguiente tabla resume los operadores básicos de pmie:

Operadores Explicación
+ - * / Aritméticos
< <= == >= > != Relacionales (comparación de valores)
! && || Booleanos
-> Regla
rising Booleano, transición de falso a verdadero
falling Booleano, transición de verdadero a falso
rate Conversión explícita a tasa (raramente requerida)
instant Sin conversión automática a tasa (raramente requerida)

Todos los operadores son compatibles con operandos y expresiones de valor numérico. Para operandos de valor de cadena, es decir, constantes de cadena literales encerradas entre comillas dobles o métricas con un tipo de datos de cadena (PM_TYPE_STRING), solo se admiten los operadores == y !=.

Los operadores rate y instant son la inversa lógica del otro, por lo que una expresión aritmética expr es igual a rate instant expr. Los casos más útiles implican el uso de rate con una métrica que no es un contador para determinar la tasa de cambio a lo largo del tiempo o instant con una métrica que es un contador para determinar si el valor actual está por encima o por debajo de algún umbral.

Los operadores de agregación pueden usarse para agregar o resumir a lo largo de una dimensión de una expresión de valor de conjunto. Los siguientes operadores de agregación mapean de una expresión lógica a una expresión lógica de menor dimensión.

Operadores Tipo Explicación
some_inst some_host some_sample Existencial Verdadero si al menos un miembro del conjunto es verdadero en la dimensión asociada
all_inst all_host all_sample Universal Verdadero si todos los miembros del conjunto son verdaderos en la dimensión asociada
N%_inst N%_host N%_sample Porcentaje Verdadero si al menos el N por ciento de los miembros del conjunto son verdaderos en la dimensión asociada

Los siguientes operadores instanciales pueden usarse para filtrar o limitar una expresión lógica de valor de conjunto, basándose en la coincidencia de expresiones regulares de los nombres de instancia. La expresión lógica debe ser un conjunto que involucre la dimensión de las instancias, y la expresión regular tiene el formato utilizado por egrep(1) o las Expresiones Regulares Extendidas de regcomp(3).

Operadores Explicación
match_inst Para cada valor de la expresión lógica que es "verdadero", el resultado es "verdadero" si el nombre de instancia asociado coincide con la expresión regular. De lo contrario, el resultado es "falso".
nomatch_inst Para cada valor de la expresión lógica que es "verdadero", el resultado es "verdadero" si el nombre de instancia no coincide con la expresión regular. De lo contrario, el resultado es "falso".

Por ejemplo, la siguiente expresión será "verdadera" para discos conectados a los controladores 2 o 3 que realizan más de 20 operaciones por segundo:

match_inst "^dks[23]d" disk.dev.total > 20;

Los siguientes operadores de agregación mapean de una expresión aritmética a una expresión aritmética de menor dimensión.

Operadores Tipo Explicación
min_inst min_host min_sample Extremos Valor mínimo entre todos los miembros del conjunto en la dimensión asociada
max_inst max_host max_sample Extremos Valor máximo entre todos los miembros del conjunto en la dimensión asociada
sum_inst sum_host sum_sample Agregado Suma de valores entre todos los miembros del conjunto en la dimensión asociada
avg_inst avg_host avg_sample Agregado Valor promedio entre todos los miembros del conjunto en la dimensión asociada

Los operadores de agregación count_inst, count_host y count_sample mapean de una expresión lógica a una expresión aritmética de menor dimensión contando el número de miembros del conjunto para los cuales la expresión es verdadera en la dimensión asociada.

Para las reglas de acción, las siguientes acciones están definidas:

Operadores Explicación
alarm Generar una alarma visible con xconfirm(1)
print Mostrar en la salida estándar
shell Ejecutar con sh(1)
stomp Enviar un mensaje STOMP a un servidor JMS
syslog Añadir un mensaje al archivo de registro del sistema

Múltiples acciones pueden separarse por los operadores & y | para especificar respectivamente la ejecución secuencial (ambas acciones se ejecutan) y la ejecución alternativa (la segunda acción solo se ejecutará si la ejecución de la primera acción devuelve un estado de error distinto de cero).

Los argumentos para las acciones son un tiempo de supresión opcional y luego una o más expresiones (una cadena es una expresión en este contexto). Las cadenas que aparecen como argumentos de una acción pueden incluir los siguientes selectores especiales que se reemplazarán en el momento en que se ejecute la acción.

%h
Nombre(s) del host que hacen que la expresión de nivel superior más a la izquierda en la condición sea verdadera.
%c
Cadena(s) de especificación de conexión o archivos para que una herramienta PCP acceda a los hosts o archivos que hacen que la expresión de nivel superior más a la izquierda en la condición sea verdadera.
%i
Instancia(s) que hacen que la expresión de nivel superior más a la izquierda en la condición sea verdadera.
%v
Un valor de la expresión de nivel superior más a la izquierda en la condición para cada par de host e instancia que hace que la condición sea verdadera.

Tenga en cuenta que la expansión de los selectores especiales se realiza repitiendo todo el argumento una vez por cada enlace único a cualquiera de los selectores especiales que califican. Por ejemplo, si una regla fuera verdadera para el host mumble con instancias grunt y snort, y para el host fumble la instancia puff hiciera verdadera la regla, entonces la acción

...
-> shell myscript "Warning: %h:%i busy ";
ejecutará myscript con la cadena de argumento "Warning: mumble:grunt busy Warning: mumble:snort busy Warning: fumble:puff busy".

En comparación, si la acción

...
-> shell myscript "Warning! busy:" " %h:%i";
se ejecutara en las mismas circunstancias, entonces myscript se ejecutaría con la cadena de argumento "Warning! busy: mumble:grunt mumble:snort fumble:puff".

La semántica de la expansión de los selectores especiales conduce a un patrón de uso común en una acción, donde un argumento es una constante (no contiene selectores especiales), el segundo argumento contiene los selectores especiales deseados con caracteres separadores mínimos, y un tercer argumento opcional proporciona un postfijo constante (por ejemplo, para terminar cualquier cita de argumento del primer argumento). Si es necesario un postprocesamiento (por ejemplo, en myscript), puede proporcionar la enumeración necesaria sobre cada expansión única de la cadena que contiene solo los selectores especiales.

Para condiciones complejas, los enlaces a estos selectores no son obvios. Se recomienda encarecidamente que pmie se utilice en modo de depuración (especificar la opción de línea de comandos -W en particular) durante el desarrollo de reglas.

EXPRESIONES BOOLEANAS

Las expresiones de pmie que tienen la semántica de una

Boolean, por ejemplo. foo.bar > 10 o some_inst ( my.table < 0 ) se asignan los valores true o false o unknown. Un valor es unknown si uno o más de los valores métricos subyacentes no están disponibles, por ejemplo, si pmcd(1) en el host no puede ser contactado, la métrica no está en el archivo PCP, no hay valores disponibles actualmente, se han obtenido insuficientes valores para calcular un valor convertido por tasa o se han obtenido insuficientes valores para instanciar el número requerido de muestras en el dominio temporal.

Los operadores booleanos siguen las reglas normales de la lógica de Kleene (también conocida como lógica de 3 valores) al combinar valores que incluyen unknown:

A and B B
true false unknown
A true true false unknown
false false false false
unknown unknown false unknown
A or B B
true false unknown
A true true true true
false true false unknown
unknown true unknown unknown
A not A
true false
false true
unknown unknown

CONJUNTOS DE REGLAS

La cláusula ruleset se utiliza para definir un conjunto de reglas y acciones que se evalúan en orden hasta que se ejecuta alguna acción, momento en el cual las reglas y acciones restantes se omiten hasta que el ruleset se programa nuevamente para su evaluación. La palabra clave else se utiliza para separar las reglas. Después de una o más reglas regulares (con un predicado y una acción), un ruleset puede incluir opcionalmente una cláusula
unknown -> acción
, seguida opcionalmente por una cláusula
otherwise -> acción
.

Si todos los predicados en las reglas se evalúan como unknown y se ha especificado una cláusula unknown, se ejecutará la acción asociada con la cláusula unknown.

Si ningún predicado de regla es true y la acción unknown no está especificada o no se ejecuta y se ha especificado una cláusula otherwise, se ejecutará la acción asociada con la cláusula otherwise.

FACTORES DE ESCALA

Los factores de escala se pueden añadir a expresiones aritméticas y obligan a una escala lineal del valor a unidades canónicas. Los factores de escala simples se construyen a partir de las palabras clave: nanosecond, nanosec, nsec, microsecond, microsec, usec, millisecond, millisec, msec, second, sec, minute, min, hour, byte, Kbyte, Mbyte, Gbyte, Tbyte, count, Kcount y Mcount, y el operador /, por ejemplo ``Kbytes / hour''.

MACROS

Los macros se definen utilizando expresiones de la forma:


nombre = valor_constante;

Donde nombre sigue las reglas normales para variables en lenguajes de programación, es decir, alfabético opcionalmente seguido de alfanuméricos. valor_constante debe ser una expresión constante, ya sea una cadena (entre comillas dobles) o una expresión aritmética seguida opcionalmente por un factor de escala.

Los macros se expanden cuando su nombre, precedido por un dólar ($) aparece en una expresión, y los macros pueden anidarse dentro de una cadena valor_constante.

Se entienden los siguientes nombres de macro reservados.

minute
Minuto actual de la hora.
hour
Hora actual del día, en el rango de 0 a 23.
day
Día actual del mes, en el rango de 1 a 31.
month
Mes actual del año, en el rango de 0 (enero) a 11 (diciembre).
year
Año actual.
day_of_week
Día actual de la semana, en el rango de 0 (domingo) a 6 (sábado).
delta
Intervalo de muestra en vigor para esta expresión.

Las fechas y horas se presentan en la zona horaria de reporte (ver la descripción de las opciones de línea de comandos -Z y -z anteriores).

REINICIO AUTOMATICO

A menudo es útil que los procesos pmie se inicien y se detengan al arrancar o apagar el host local, o cuando se ha detectado que ya no se están ejecutando (cuando han salido inesperadamente por alguna razón). Consulte pmie_check(1) para obtener más detalles sobre cómo automatizar este proceso.

Opcionalmente, cada sistema que ejecuta pmcd(1) también puede configurarse para ejecutar una instancia ``primaria'' de pmie. Esta instancia de pmie se inicia mediante $PCP_RC_DIR/pmie y se ve afectada por los archivos $PCP_SYSCONF_DIR/pmie/control, $PCP_SYSCONF_DIR/pmie/control.d (use chkconfig(8), systemctl(1) o comandos similares específicos de la plataforma para activar o desactivar la instancia primaria de pmie) y $PCP_VAR_DIR/config/pmie/config.default (el archivo de configuración inicial predeterminado para la primaria de pmie).

La instancia primaria de pmie se identifica mediante la opción -P. Puede haber como máximo una instancia ``primaria'' de pmie en cada sistema. La instancia primaria de pmie (si la hay) debe estar en ejecución en el mismo host que el pmcd(1) al que se conecta (si la hay), por lo que las opciones -h y -P son mutuamente excluyentes.

MONITORIZACIÓN DE EVENTOS

Es común que los sistemas de producción se monitoricen en una ubicación central. Tradicionalmente, en los sistemas UNIX esto lo han realizado las instalaciones de registro del sistema (consulte logger(1) y syslogd(1)). En Windows, la comunicación con el registro de eventos del sistema se gestiona mediante pcp-eventlog(1).

pmie encaja en este modelo cuando las reglas utilizan la acción syslog. Tenga en cuenta que si la cadena de acción comienza con -p (prioridad) y/o -t (etiqueta), estas se extraen de la cadena y se tratan de la misma manera que en logger(1) y pcp-eventlog(1).

Sin embargo, también es común tener otros marcos de monitorización de eventos, en los que puede desear incorporar eventos de rendimiento de pmie. A menudo puede utilizar la acción shell para enviar eventos a estos marcos, ya que generalmente proporcionan su programa para inyectar eventos en el marco desde fuentes externas.

Una opción final es el uso de la acción stomp (Streaming Text Oriented Messaging Protocol), que permite a pmie conectarse a un servidor JMS (Java Messaging System) central y enviar eventos al tema de PMIE. Se pueden escribir herramientas para extraer estos mensajes de texto y presentarlos al personal de operaciones (a través de ventanas emergentes de escritorio, etc.). El uso de la acción stomp requiere la configuración de un archivo de configuración de stomp, que especifica la ubicación del host del servidor JMS, el número de puerto y el nombre de usuario/contraseña.

El formato de este archivo es el siguiente:

host=messages.sgi.com   # este es el servidor JMS (requerido)
port=61616              # y escucha aquí (requerido)
timeout=2               # segundos de espera para el servidor (opcional)
username=joe            # (requerido)
password=j03ST0MP       # (requerido)
topic=PMIE              # tema JMS para mensajes de pmie (opcional)

El valor de timeout especifica el tiempo (en segundos) que pmie debe esperar acuses de recibo del servidor JMS después de enviar un mensaje (según lo requiere el protocolo STOMP). Tenga en cuenta que al iniciar, pmie esperará indefinidamente una conexión y no comenzará la evaluación de reglas hasta que se haya establecido esa conexión inicial. Si la conexión al servidor JMS se pierde en algún momento mientras pmie está en ejecución, pmie intentará reconectarse en cada evaluación verdadera posterior de una regla con una acción stomp, pero no más de una vez por minuto. Esto es para evitar contribuir a la congestión de la red. En esta situación, donde la conexión STOMP con el servidor JMS se ha cortado, la acción stomp devolverá un valor de error distinto de cero.

DIFERENCIAS EN LOS MODOS DE HOST Y ARCHIVO

Cuando se ejecuta en modo host, el intervalo delta para cada regla determina un retraso en tiempo real entre la evaluación de reglas, por lo que pmie pasa la mayor parte de su tiempo durmiendo y esperando la próxima evaluación programada de reglas.

Cuando se ejecuta en modo archivo, pmie utiliza el intervalo delta de cada regla para determinar con qué frecuencia se evalúan las reglas contra los datos del archivo, pero a diferencia del modo host, no hay retrasos en tiempo real, ya que el archivo se "reproduce" lo más rápido posible.

En modo archivo, cuando el predicado de una regla se evalúa como verdadero, la acción se modifica, de modo que en lugar de publicar en syslog o generar una alarma visible o ejecutar un comando shell o enviar un mensaje stomp, pmie imprime el nombre de la acción, la marca de tiempo del archivo en la que el predicado de la regla que activa la acción fue verdadero y todos los argumentos que se habrían pasado a la acción real en modo host.

Por ejemplo, dada la regla:

delta = 10 sec;
kernel.all.nprocs > 10 * hinv.ncpu -> print "lotsaprocs:" " %v";
cuando se ejecuta contra un archivo, la salida aparece como: 

print Mon Sep  4 00:10:21 2017: lotsaprocs: 1292
print Mon Sep  4 00:10:31 2017: lotsaprocs: 1294
print Mon Sep  4 00:10:41 2017: lotsaprocs: 1291
...

La justificación es que el contexto en el que se habría ejecutado la acción (en modo host) fue en un momento pasado y posiblemente en un host diferente (si el archivo se recopiló de un host, pero pmie se está ejecutando en un host diferente). Por lo tanto, inundar syslog con mensajes engañosos, una avalancha de alarmas visuales, muchos mensajes STOMP o un comando de shell que podría ni siquiera funcionar en el host donde se está ejecutando pmie, son ejemplos de "maldad" a evitar. En su lugar, la salida es texto en un formato regular adecuado para el postprocesamiento con una variedad de filtros y herramientas de análisis de rendimiento.

El formato de salida se puede cambiar usando la opción -o que consiste en caracteres literales con los siguientes tokens de "metacampos" incrustados:

%a
El nombre de la acción, por ejemplo, print, syslog, etc.
%d
La fecha y hora en formato ctime(3) en que se habría ejecutado la acción.
%f
El nombre del archivo de configuración que contiene la acción que se está ejecutando, o <stdin> si las reglas se leyeron de la entrada estándar.
%l
El número de línea (aproximado) en el archivo de configuración de la acción que se está ejecutando.
%m
El componente del mensaje de la acción.
%u
La fecha y hora en que se habría ejecutado la acción en formato extendido ctime(3) con precisión de microsegundos para la hora.
%%
Un carácter de porcentaje literal.

El formato de salida predeterminado es equivalente a un *formato* de %a %d: %m.

SEÑALES

Si se envía una señal SIGHUP a pmie, el *logfile* se cerrará, se desvinculará y se reabrirá. Esto lo utiliza pmie_daily(1) para lograr la rotación de registros nocturna.

La mayor parte del tiempo pmie está durmiendo, esperando hasta que el próximo conjunto de reglas necesite ser evaluado. Enviar una señal SIGUSR1 a pmie hará que los detalles del próximo conjunto de reglas se vuelquen en el *logfile*, incluido cuánto dura el sueño actual y cuánto tiempo queda. La programación de las reglas no se ve alterada por esta acción.

CAMBIOS DEL NOMBRE DEL HOST

El nombre de host del PMCD que proporciona métricas a pmie se utiliza de varias maneras.

El nombre de host de PMCD se utiliza internamente para proporcionar un valor para las sustituciones de %h en las cadenas de acciones de reglas.

Para las instancias de pmie que utilizan un PMCD local y que son lanzadas y gestionadas por pmie_check(1) y pmie_daily(1) (o los servicios de systemd(1) o cron(8) que utilizan estos scripts), el nombre de host local también puede utilizarse para construir el nombre de un directorio donde se almacenan los registros de pmie para un host, por ejemplo, $PCP_LOG_DIR/pmie/<hostname>.

El nombre de host del host PMCD puede cambiar durante el arranque, cuando el sistema pasa de un nombre de host temporal a un nombre de host persistente, o por acción administrativa explícita en cualquier momento después de que el sistema se haya iniciado. Cuando esto ocurre, pmie puede necesitar tomar una acción especial, específicamente si la instancia de pmie se lanzó desde pmie_check(1) o pmie_daily(1), entonces pmie debe salir. En circunstancias normales, systemd(1) o cron(8) lanzarán un nuevo pmie poco después, y esta nueva instancia de pmie estará operando en el contexto del nuevo nombre de host para el host donde se está ejecutando PMCD.

ERRORES

El escáner léxico y el analizador intentarán recuperarse después de un error en las expresiones de entrada. El análisis se reanuda después de omitir la entrada hasta el siguiente punto y coma (;), sin embargo, durante este proceso de omisión, el escáner ignora los comentarios y las cadenas, por lo que un punto y coma incrustado puede hacer que el análisis se reanude en un lugar inesperado. Este comportamiento es en gran medida inofensivo, ya que hasta que no se corrija el error de sintaxis inicial, pmie no intentará ninguna evaluación de expresiones.

ARCHIVOS

$PCP_DEMOS_DIR/pmie/*
reglas de ejemplo anotadas
$PCP_VAR_DIR/pmns/*
archivos de especificación PMNS predeterminados
$PCP_TMP_DIR/pmie
pmie mantiene archivos en este directorio para identificar las instancias de pmie en ejecución y para exportar información en tiempo de ejecución sobre cada instancia - estos datos forman la base de las métricas de rendimiento de pmcd.pmie
$PCP_PMIECONTROL_PATH
el conjunto predeterminado de instancias de pmie para iniciar en el arranque - consulte ENTORNO_PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Al ejecutar acciones de shell, pmie sobrescribe dos variables - IFS y PATH - en el entorno del proceso hijo. IFS se establece en "\t\n". PATH se establece en una combinación de una ruta predeterminada para todas las plataformas ("/usr/sbin:/sbin:/usr/bin:/bin") y varios componentes configurables. Estos son (en este orden): $PCP_BIN_DIR, $PCP_BINADM_DIR y $PCP_PLATFORM_PATHS.

Al ejecutar acciones de alarma emergente, pmie utilizará el valor de $PCP_XCONFIRM_PROG como programa de notificación visual para ejecutar. Esto generalmente se establece en pmconfirm(1), un cuadro de diálogo multiplataforma.
