PMFIND(1) Manual de Comandos Generales PMFIND(1)

NOMBRE

pmfind - encontrar servicios PCP en la red

SINOPSIS

pmfind [-CqrSV?] [-D depuración] [-m mecanismo] [-s servicio] [-t tiempo_de_espera]

DESCRIPCIÓN

pmfind busca instancias del servicio PCP especificado que se anuncian en la red e imprime una lista de URLs correspondientes a los servicios descubiertos. Se puede usar en conjunción con pmfind_check(1) para automatizar la monitorización de sistemas recolectores de PCP remotos.

OPCIONES

Las opciones de línea de comandos disponibles son:

-C, --contenedores
Realiza también el descubrimiento de contenedores, para cada servicio pmcd(1) descubierto.
-m mecanismo, --mecanismo=mecanismo
Esta opción establece el mecanismo que pmfind utiliza al realizar el descubrimiento de servicios. Por defecto, o si se especifica la palabra clave all, se usarán todos los mecanismos disponibles (iterativamente). Consulte la sección ``MECANISMOS'' para obtener una descripción de cada mecanismo de descubrimiento disponible.
-q, --tranquilo
Esta opción suprime toda la salida en el flujo de salida estándar.
-r, --resolver
Solicita que se intente la resolución de nombres DNS para las direcciones de los servicios descubiertos. Por defecto, se muestran las direcciones de red de los servicios descubiertos.
-s servicio, --servicio=servicio
Por defecto, pmfind buscará todos los servicios PCP compatibles, sin embargo, se puede especificar un servicio PCP específico para descubrir usando la opción -s. Los servicios compatibles son pmcd(1) y pmproxy(1).
-S, --fuentes
Informa los identificadores de fuente para cada servicio pmcd(1) descubierto. Estos identificadores son únicos para cada host y se forman utilizando las etiquetas de contexto (no opcionales) disponibles para cada recolector PCP. Dado que el proceso de descubrimiento a menudo identificará múltiples rutas hacia un host recolector individual, esta opción es una parte importante del proceso de uso de pmfind en conjunción con pmfind_check(1), para asegurar que solo se inicie un proceso pmie(1) y/o pmlogger(1) por cada host recolector descubierto. Los identificadores de fuente informados por pmfind son los mismos que los informados por los comandos pminfo(1) y pmseries(1).
-t segundos, --tiempo_de_espera=segundos
Establece el tiempo máximo en segundos que pmfind tardará antes de interrumpir el descubrimiento de servicios. El argumento tiempo es un número de punto flotante que representa el número de segundos antes de que expire. El valor predeterminado es tomar todo el tiempo necesario para completar el proceso.
-V, --version
Muestra el número de versión y sale.
-?, --ayuda
Muestra el mensaje de uso y sale.

MECANISMOS

Los mecanismos compatibles para el descubrimiento de servicios son:

avahi
Busca servicios que se estén anunciando usando mDNS a través de avahi-daemon(8). Se puede añadir un sufijo opcional ",timeout=N" para limitar el tiempo de espera para el avahi-daemon. N es un número de punto flotante que especifica el número de segundos de espera. El valor predeterminado es 0.5 segundos. Este tiempo de espera también puede especificarse configurando la variable de entorno AVAHI_DISCOVERY_TIMEOUT con el número deseado de segundos. Si se especifican ambos, el valor especificado en la variable de entorno tiene precedencia.
probe=<dirección_red>/<bits_máscara>
Sondea activamente la subred dada para los servicios PCP solicitados. <dirección_red> es una dirección de red Inet o IPv6 y <bits_máscara> es el número de bits utilizados para definir la subred. Por ejemplo, 192.168.1.0/24 define una subred de 8 bits que consta de las direcciones 192.168.1.0 a 192.168.1.255. Se puede añadir un sufijo opcional ",maxThreads=N" para limitar el número de hilos utilizados durante el sondeo. El valor predeterminado es el valor de FD_SETSIZE (que suele ser 1024) o el número de direcciones en la subred, el que sea menor. Se puede añadir un sufijo opcional ",timeout=N" para limitar el tiempo dedicado a esperar cada intento de conexión. N es un número de punto flotante que especifica el número de segundos de espera. El valor predeterminado es 0.02 segundos (20 milisegundos).
shell
Sondea la lista de direcciones proporcionadas por scripts para los servicios PCP solicitados. También se pueden proporcionar varios parámetros opcionales, separados por comas. La opción "path=DIR" especifica el directorio donde se encuentran los comandos como pcp-kube-pods(1) (por defecto es $PCP_BINADM_DIR/discover/). Esta configuración se puede restringir aún más a un comando individual usando la opción command=CMD, pero por defecto se utilizan todos los comandos disponibles de la ruta (path). La opción "maxThreads=N" limita el número de hilos utilizados durante el sondeo. El valor predeterminado es el valor de FD_SETSIZE (que suele ser 1024) o el número de direcciones devueltas por los scripts, el que sea menor. La opción "timeout=N" puede añadirse para limitar el tiempo dedicado a esperar cada intento de conexión. N es un número de punto flotante que especifica el número de segundos de espera. El valor predeterminado es 0.02 segundos (20 milisegundos).

SEÑALES

pmfind interrumpirá el proceso de descubrimiento de servicios cuando reciba una de las siguientes señales: SIGHUP, SIGPIPE, SIGINT, SIGTERM, SIGXFSZ, SIGXCPU. pmfind informará cualquier resultado descubierto hasta el punto de la interrupción.

DIAGNÓSTICOS

El valor del estado de salida del comando es cero cuando se localizaron servicios con éxito, uno si no se encontró ningún servicio y dos si ocurrió un error.

En caso de error, se generará un mensaje en la salida estándar de errores que está destinado a ser autoexplicativo.

ARCHIVOS

$PCP_BINADM_DIR/discover
ruta predeterminada a los scripts de descubrimiento de direcciones

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --depurar habilita la salida de diagnósticos adicionales en stderr para ayudar a depurar problemas, aunque la información a veces es críptica y está destinada principalmente a guiar a los desarrolladores en lugar de a los usuarios finales. depuración es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
