PMDAPROC(1) Manual de Comandos Generales PMDAPROC(1)

NOMBRE

pmdaproc - agente de dominio de métricas de rendimiento de procesos (PMDA)

SINOPSIS

$PCP_PMDAS_DIR/proc/pmdaproc [-AL] [-D debug] [-d dominio] [-l logfile] [-r cgroup] [-U username]

DESCRIPCIÓN

pmdaproc es un Agente de Dominio de Métricas de Rendimiento (PMDA) que extrae métricas de rendimiento que describen el estado de los procesos individuales que se ejecutan en un sistema Linux.

El PMDA proc exporta métricas que miden el uso de memoria, procesador y otros recursos de cada proceso, así como información de resumen recopilada de todos los procesos en ejecución. El PMDA utiliza las credenciales pasadas por la herramienta de monitoreo PMAPI(3) que identifican al usuario que solicita la información, para garantizar que el PMDA solo devuelva los valores a los que el usuario tiene permiso de acceder. Esto implica que el PMDA cambia temporalmente sus identificadores efectivos de usuario y grupo durante la duración de las solicitudes de instancias y valores. En otras palabras, las llamadas al sistema para extraer información se realizan como el usuario que originó la solicitud y no como un usuario privilegiado. Los mecanismos disponibles para la transferencia de credenciales de usuario se describen con más detalle en la página PCPIntro(1).

A continuación, se incluye una breve descripción de las opciones de línea de comandos de pmdaproc:

-A
Deshabilita el uso de las credenciales proporcionadas por las herramientas cliente de PMAPI y simplemente ejecuta todo bajo la cuenta "root". Consulte la sección CONFIGURACIÓN DE ACCESO a continuación para un control más detallado al usar pmcd(1) con autenticación de cliente remota. Habilite esta opción solo si comprende los riesgos involucrados y está seguro de que todos los accesos remotos provendrán de usuarios benévolos. Si está habilitado, los clientes remotos no autenticados de PMAPI podrán acceder a valores de métricas de rendimiento potencialmente sensibles que un cliente no autenticado de PMAPI normalmente no podría. Consulte CVE-2011-2495 y CVE-2012-3419 para obtener detalles adicionales.
-L
Cambia el dominio de instancia por proceso utilizado por la mayoría de las métricas de pmdaproc para incluir también los hilos.
-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y coherente. Es decir, dominio debe ser diferente para cada PMDA en el mismo host, y el mismo número de dominio debe usarse para el mismo PMDA en todos los hosts.
-l
Ubicación del archivo de registro. Por defecto, se escribe un archivo de registro llamado proc.log en el directorio actual de pmcd(1) cuando se inicia pmdaproc, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de registro no se puede crear o no es escribible, la salida se escribe en el error estándar en su lugar.
-r
Restringe el conjunto de procesos exportados en el dominio de instancia por proceso solo a aquellos procesos que están contenidos en el contenedor de recursos cgroup especificado. Esta opción proporciona una granularidad opcional más fina al monitoreo y también se puede usar para reducir los recursos consumidos por pmdaproc durante las solicitudes de instancias y valores.
-U
Cuenta de usuario bajo la cual ejecutar el agente. El valor predeterminado es la cuenta privilegiada "root", con cambio de seteuid (2) y setegid (2) para acceder a la mayoría de la información.

RESUMEN DE HOTPROC

El Agente de Dominio de Métricas de Rendimiento (PMDA) pmdaproc incluye un conjunto adicional de métricas por proceso con un dominio de instancias de procesos restringido a un conjunto "interesante" o "caliente". A diferencia de las métricas estándar exportadas por el PMDA proc, que tienen un dominio de instancia igual a los procesos actuales, las métricas hot tienen un dominio de instancia que es un subconjunto de este. Este dominio de instancia hotproc está determinado por un predicado configurable evaluado en un intervalo de actualización.

Además de las métricas equivalentes por proceso de proc, hotproc proporciona una métrica cpuburn que especifica la utilización de la CPU del proceso durante el intervalo de actualización, métricas total que indican cuánto tiempo de CPU disponible representan los procesos "interesantes", métricas predicate que muestran los valores de las variables reservadas (ver más abajo) que se están utilizando en el predicado de hotproc, y métricas control para controlar el agente.

CONFIGURACIÓN DE HOTPROC

El archivo de configuración consta de un predicado utilizado para determinar si un proceso debe estar en el conjunto interesante o no.

Se puede encontrar un archivo de configuración de ejemplo en $PCP_PMDAS_DIR/proc/samplehotproc.conf

Este archivo con cualquier modificación puede copiarse a $PCP_PMDAS_DIR/proc/hotproc.conf para configurar las métricas hot. Las interfaces pmstore(1) y pmStore(3) también se pueden usar (descritas a continuación).

El predicado se describe utilizando el lenguaje especificado a continuación. Los símbolos se basan en los utilizados por los lenguajes C(1) y awk(1).

Conectivas Booleanas
&& (y), || (o), ! (no), () (anulación de precedencia)
Comparadores numéricos
< , <= , > , >= , == , !=
Comparadores de cadenas
== , !=
Comparadores de Cadenas/Patrones
~ (la cadena coincide con el patrón) , !~ (la cadena no coincide con el patrón)
Variables reservadas
uid (id de usuario; tipo entero) uname (nombre de usuario; tipo cadena), gid (id de grupo; tipo entero) gname (nombre de grupo; tipo cadena), fname (nombre de archivo del proceso; tipo cadena), psargs (nombre de archivo del proceso con argumentos; tipo cadena), cpuburn (utilización de CPU; tipo flotante), iodemand (demanda de E/S - Kbytes leídos/escritos por segundo; tipo flotante), ctxswitch (número de cambios de contexto por segundo; tipo flotante), syscalls (número de llamadas al sistema por segundo; tipo flotante), virtualsize (tamaño virtual en Kbytes; tipo flotante), residentsize (tamaño residente en Kbytes; tipo flotante), iowait (espera de E/S bloqueada y cruda en segs/seg; tipo flotante), schedwait (tiempo de espera en la cola de ejecución en segs/seg; tipo flotante).
Valores literales
1234 (entero positivo), 0.35 (flotante positivo), "foobar" (cadena; delimitada por "), /[fF](o)+bar/ (patrón; delimitado por /), true (booleano), false (booleano)
Comentarios
#esto es un comentario (desde # hasta el final de la línea).
Ejemplos

cpuburn > 0.2 # utilización de CPU de más del 20%
cpuburn > 0.2 && uname == "root"
cpuburn > 0.2 && (uname == "root" || uname == "hot")
psargs ~ /pmda/ && cpuburn > 0.4

Las métricas hotproc.predicate pueden usarse para ver cuáles son los valores de las variables reservadas que se utilizaron en el predicado en la última actualización. No cubren las variables reservadas que ya se exportan en otros lugares. Una métrica hotproc.predicate puede no tener un valor si no se hace referencia a ella en el predicado de configuración.

ACCESO A LA CONFIGURACIÓN

El acceso a las métricas por proceso está controlado por varios factores.

Al utilizar conexiones locales que autentican automáticamente, como a través del contexto de estilo "unix:" o "local:", las herramientas cliente tendrán acceso completo a estas métricas como si estuvieran obteniendo las métricas directamente como el usuario que ejecuta la herramienta cliente.

Al utilizar pmcd con clientes remotos y autenticados, es posible especificar un conjunto de nombres de usuario a los que se les permite el acceso a las métricas de procesos.

Se puede utilizar un archivo de configuración $PCP_SYSCONF_DIR/proc/access.conf para ajustar este comportamiento, y admite dos palabras clave:

allowed
Una lista separada por comas de nombres de usuario autenticados a los que se les permitirá el acceso a las métricas por proceso. La obtención de muestras se realiza como el usuario root.
mapped
Un valor booleano; cuando es verdadero, indica que los nombres de usuario autenticados se mapearán a los nombres de cuenta de usuario del sistema local (esto requiere un mapeo de nombres de usuario uno a uno entre la cuenta y el nombre de usuario autenticado basado en SASL, aplicado por pmcd(1)). La obtención de muestras se realiza como ese usuario local.

INSTALACIÓN

El proc PMDA está instalado y disponible por defecto. Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/proc
# ./Remove

Si desea establecer acceso a los nombres, texto de ayuda y valores para las métricas de rendimiento de procesos una vez más, después de la eliminación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/proc
# ./Install

pmdaproc es lanzado por pmcd(1) y nunca debe ser ejecutado directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o elimina.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede utilizarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información a veces es críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmdaproc son las siguientes:

Opción Descripción
appl0 manejo de cgroups
appl1 procesamiento de actualización, incluyendo métricas de hotproc
appl2 operaciones de PMNS
appl3 métricas de contabilidad de procesos
