PMPROXY(1) Manual de Comandos Generales PMPROXY(1)

NOMBRE

pmproxy - proxy para el colector y consulta de métricas de rendimiento

SINOPSIS

pmproxy [-AdfFt?] [-c archivo_config] [-D debug] [-h host[,host ...] [-i direccion_ip] [-l archivo_log] [-L bytes] [-p puerto[,puerto ...] [-r puerto[,puerto ...] [-s nombre_socket] [-U nombre_usuario] [-x archivo_salida]

DESCRIPCIÓN

pmproxy actúa como un proxy de protocolo, permitiendo a los clientes de monitorización Performance Co-Pilot (PCP) conectarse directa o indirectamente a uno o más servidores pmcd(1) y/o servidores de clave-valor (como https://valkey.io/).

En su modo de operación por defecto, pmproxy proporciona la API REST para servicios PCP (ver PMWEBAPI(3) para detalles). Esto incluye el suministro de una interfaz de texto Open Metrics - https://openmetrics.io - para métricas PCP en /metrics, acceso en tiempo real a métricas PCP a través de las interfaces /pmapi, y acceso a las capacidades de consulta de series temporales PCP rápidas y escalables ofrecidas en conjunción con un servidor clave-valor (ver pmseries(1) para detalles) a través de las interfaces REST /query.

pmproxy puede ser desplegado en un dominio de cortafuegos, o en un nodo "head" de un clúster donde la dirección IP (Protocolo de Internet) de los hosts donde se ejecutan pmcd(1) y/o un servidor clave-valor (como https://valkey.io/) puede ser desconocida para los clientes de monitorización PCP, pero donde la dirección IP del host que ejecuta pmproxy es conocida por estos clientes. De manera similar, los clientes pueden tener conectividad de red solo al host donde se ejecuta pmproxy, mientras que existe conectividad de red desde ese host a los hosts de interés donde se ejecutan pmcd(1) y/o un servidor clave-valor.

El comportamiento de los clientes de monitorización PCP se controla ya sea a través de la variable de entorno PMPROXY_HOST o mediante la especificación extendida de nombre de host (ver PCPIntro(1) para detalles). Si no se utiliza ninguno de estos mecanismos, los clientes realizarán sus conexiones PMAPI(3) directamente a pmcd. Si se utiliza la sintaxis de proxy de host o se establece PMPROXY_HOST, entonces este debe ser el nombre de host o la dirección IP del sistema donde se ejecuta pmproxy, y los clientes se conectarán a pmcd o a un servidor clave-valor indirectamente a través de los servicios de proxy de protocolo de pmproxy.

OPCIONES

Las opciones de línea de comandos disponibles son:

-A
Desactivar la publicidad del servicio. Por defecto, pmproxy anunciará su presencia en la red utilizando cualquier mecanismo disponible (como Avahi/DNS-SD), ayudando a las herramientas de monitorización remota a encontrarlo. Estos mecanismos se desactivan con esta opción.
-c archivo_config, --config=archivo_config
Especificar la ruta a un archivo de configuración opcional archivo_config, con formato como se describe en la sección ``CONFIGURACIÓN''. Esta opción implica que pmproxy se está ejecutando en modo timeseries.
-d, --deprecated
Por defecto, pmproxy prefiere ejecutarse en el nuevo modo timeseries, proporcionando APIs REST, E/S de red asíncrona, series temporales escalables y conexiones seguras usando OpenSSL. Sin embargo, los despliegues heredados pueden desear usar la implementación original síncrona de pmproxy usando la red libpcp; esto se puede lograr usando esta opción. Tenga en cuenta que las opciones -d y -t son mutuamente excluyentes.
-f, --foreground
Por defecto, pmproxy se inicia como un demonio. La opción -f indica que debe ejecutarse en primer plano. Esto es más útil cuando se intenta diagnosticar problemas con el establecimiento de conexiones.
-F, --systemd
Al igual que -f, la opción -F ejecuta pmproxy en primer plano, pero también realiza algunas tareas de mantenimiento (como crear un archivo "pid" y cambiar el ID de usuario). Esto está destinado a ser usado cuando pmproxy se lanza desde systemd(1) y el "daemonizado" ya ha sido realizado por systemd(1) y no necesita ser realizado de nuevo por pmproxy, que es el caso cuando ni -f ni -F se especifican.

Como máximo una de las opciones -f y -F puede ser especificada.

-h host, --keyhost=host
Especificar un servidor clave-valor alternativo host al que conectarse para la consulta de series temporales, anulando cualquier configuración del archivo de configuración. Esta opción implica que pmproxy se está ejecutando en modo timeseries.
-i direccion_ip, --interface=direccion_ip
Esta opción generalmente solo se usa en hosts con más de una interfaz de red (muy común para cortafuegos y hosts "head" donde es probable que se despliegue pmproxy para arbitrar el acceso a una red interna). Si no se especifican opciones -i, pmproxy acepta conexiones de clientes PCP en cualquiera de las direcciones IP de su host. La opción -i se utiliza para especificar explícitamente una dirección IP en la que se deben aceptar las conexiones de clientes PCP. direccion_ip debe estar en el formato estándar de puntos (por ejemplo, 100.23.45.6). La opción -i puede usarse múltiples veces para definir una lista de direcciones IP. Cuando se especifica una o más opciones -i, los intentos de conexión realizados en otras direcciones IP serán rechazados.
-l archivo_log, --log=archivo_log
Por defecto, se escribe un archivo de registro llamado pmproxy.log en el directorio actual. La opción -l hace que el archivo de registro se escriba en un archivo_log dado en lugar del predeterminado. Si este archivo_log no se puede crear o no es escribible, la salida se escribe en el error estándar en su lugar.
-L bytes
Los PDUs recibidos por pmproxy de los clientes de monitorización PCP están restringidos a un tamaño máximo de 65536 bytes por defecto para defenderse contra ataques de Denegación de Servicio. La opción -L puede usarse para cambiar el tamaño máximo del PDU entrante.
-p puerto, --port=puerto
Especificar un número de puerto alternativo para escuchar las conexiones de clientes. El valor por defecto es 44322.
-r puerto, --keyport=puerto
Especificar un número de puerto de servidor clave-valor alternativo al que conectarse para la consulta de series temporales, anulando cualquier configuración del archivo de configuración. Esta opción implica que pmproxy se está ejecutando en modo timeseries.
-s nombre_socket, --socket=nombre_socket
Especificar la ruta a un socket de dominio unix local (solo para plataformas que admitan esta familia de sockets). El valor por defecto es $PCP_RUN_DIR/pmproxy.socket. Esta opción implica que pmproxy se está ejecutando en modo timeseries.
-t, --timeseries
Operar en modo de descubrimiento automático de series temporales de archivos. Este modo de operación habilitará las APIs REST PMWEBAPI(3), detectará dinámica y automáticamente los archivos del sistema activos que están siendo escritos por pmlogger(1) y los importará a un servidor clave-valor (como https://valkey.io/), para consultas rápidas y escalables de series temporales descritas en pmseries(1). Tenga en cuenta que en este modo de operación, pmproxy solo "sigue la cola" (log-tails) e ingiere los archivos en crecimiento activo, p. ej., como los escritos por una o más instancias de pmlogger(1). Cuando se descubre un archivo por primera vez (generalmente pero no limitado al inicio de pmproxy), se carga toda la metainformación y se envía al servidor clave-valor configurado, sin embargo, tenga en cuenta que solo se ingieren los datos de valor de métricas de archivo **nuevos** del extremo final de cada archivo. Los archivos comprimidos nunca crecen, por lo que se ignoran. Consulte la opción --load de pmseries(1) para ver un mecanismo compatible para cargar manualmente todo el contenido de los archivos.
-U nombre_usuario, --user=nombre_usuario
Ejecutar pmproxy como el usuario especificado nombre_usuario y su grupo principal. Por defecto, pmproxy se ejecuta como el usuario root. Esto es útil para evitar ejecutar el demonio como root innecesariamente.
-x archivo_salida, --pid=archivo_salida
Escribir el PID del proceso principal de pmproxy en el archivo especificado archivo_salida. El PID se escribe antes de que pmproxy intente daemonizarse.
-?, --help
Mostrar un mensaje de uso y salir.

CONFIGURACIÓN

El archivo de configuración opcional de pmproxy contiene directivas de configuración que se dividen en tres tipos:

DIRECTIVE
Establece el valor de una directiva de configuración.
HOST
Especifica un servidor remoto de metadatos y métricas que debe ser gestionado por el proxy. El primer host especificado se considera el host de "reproducción" por defecto. En el modo de series temporales, los hosts también se usan para el almacenamiento de series temporales.
KEYVAL
Especifica un servidor clave-valor remoto para el almacenamiento de series temporales y la recuperación de metadatos. Si se especifica, esta directiva tiene prioridad sobre la directiva HOST para el almacenamiento de series temporales.

Las directivas válidas son:

archive pathname
Especifica un directorio que contiene archivos de registro PCP que deben ser importados y servidos. Los nombres de archivo deben terminar en ".pmrecord" o ".pmdat".
auth pathname
Especifica un archivo que contiene credenciales de autenticación para servidores remotos.
bind ipaddr
Especifica una dirección IP local a la que unirse para escuchar conexiones entrantes. Esto es equivalente a usar la opción -i.
cache bytes
Establece el tamaño de la caché de metadatos. El valor por defecto es 409600 bytes.
daemon {yes|no}
Controla si pmproxy debe ejecutarse como un demonio en segundo plano. Por defecto es "yes".
debug flags
Establece las banderas de depuración. Ver la opción -D.
host hostname [port]
Especifica un host remoto para el backend de pmcd. El port es opcional y por defecto es 44321.
keyhost hostname [port]
Especifica un host remoto para el backend de series temporales. El port es opcional y por defecto es 44322.
keyval hostname [port]
Especifica un host remoto para el backend de clave-valor. El port es opcional y por defecto es 44322.
logfile pathname
Especifica la ruta del archivo de registro. Ver la opción -l.
listen port
Especifica un puerto para escuchar las conexiones entrantes. Ver la opción -p.
pdu_limit bytes
Establece el límite de tamaño para los PDUs entrantes. Ver la opción -L.
port port
Es sinónimo de listen.
protodebug flags
Establece las banderas de depuración de protocolo.
socket pathname
Especifica la ruta a un socket de dominio Unix. Ver la opción -s.
ssl_cafile pathname
Especifica el archivo CA para la verificación del certificado SSL.
ssl_certfile pathname
Especifica el archivo de certificado para la autenticación SSL.
ssl_keyfile pathname
Especifica el archivo de clave para la autenticación SSL.
ssl_strict {yes|no}
Controla si las conexiones SSL deben ser estrictas. Por defecto es "yes".
user username
Especifica el usuario bajo el cual ejecutar pmproxy. Ver la opción -U.

La configuración del archivo de configuración es la siguiente:

# Opcional: configuración principal
[pmproxy]
# Configuración de la API REST (opcional)
[webapi]
    port=44322
    # Opcional: config. de series temporales para la API REST
    # keyhost=localhost
    # keyport=44322

# Configuración del proxy de series temporales (obligatorio para modo timeseries)
[timeseries]
    # Host y puerto del backend de series temporales
    # Solo se requiere uno de los siguientes: keyhost o host.
    # keyhost = localhost
    # host = localhost
    keyport = 44322
    # Opcional: auth = /etc/pcp/pmproxy.auth
    # Opcional: archive = /var/log/pcp/pmlogger/
    # Opcional: cache = 409600
    # Opcional: debug = "pdu trace"
    # Opcional: protodebug = "all"
    # Opcional: logfile = /var/log/pcp/pmproxy.log
    # Opcional: user = pcp
    # Opcional: ssl_certfile = /etc/pcp/pmproxy.crt
    # Opcional: ssl_keyfile = /etc/pcp/pmproxy.key
    # Opcional: ssl_cafile = /etc/pcp/ca.crt
    # Opcional: ssl_strict = yes

EJEMPLOS

Para iniciar pmproxy en modo proxy de series temporales en el puerto 44322, escuchando en todas las interfaces, y reenviando las solicitudes a pmcd en el host remoto 'pmserver' en el puerto 44321, y a un servidor clave-valor en 'kvserver' en el puerto 44322:

Utilizando la línea de comandos:

$ pmproxy -t -h pmserver -p 44322 -r 44322 -i 192.168.1.100 -i 10.0.0.100

En este caso, pmproxy escuchará en las interfaces 192.168.1.100 y 10.0.0.100 en el puerto 44322. Las solicitudes de series temporales se reenviarán al servidor clave-valor en 'kvserver' en el puerto 44322. Las solicitudes de métricas PCP se reenviarán al servidor pmcd en 'pmserver' en el puerto 44321.

Utilizando un archivo de configuración

# /etc/pcp/pmproxy.conf
[pmproxy]
    daemon=yes
    logfile=/var/log/pcp/pmproxy.log
    port=44322
    user=pcp

[timeseries]
    host=pmserver
    keyhost=kvserver
    keyport=44322

Ejecute pmproxy con el archivo de configuración:

$ pmproxy -c /etc/pcp/pmproxy.conf

Para iniciar pmproxy en el modo tradicional (no series temporales), escuchando en el puerto 44322 y reenviando las solicitudes a 'pmserver' en el puerto 44321:

$ pmproxy -p 44322 -h pmserver

Para iniciar pmproxy en modo de primer plano para depuración:

$ pmproxy -f

OPTIONS

-c archive
Used to activate the caching of metric value data from previously collected (inactive) archives, whether compressed or not. It would be normal, though not mandated, for a set of archives being manually loaded to cover the same time period, e.g. archive data for a particular week for one or more hosts in the same data-centre.
-U username, --username=username
Assume the identity of the given username before starting to accept incoming packets from PCP monitoring clients.
-x outfile
Before the pmproxy logfile can be opened, pmproxy may encounter a fatal error which prevents it from starting. By default the output describing this error is sent to /dev/tty but it may redirected to outfile.
-?, --help
Display usage message and exit.

CONFIGURACIÓN

When running in the timeseries mode of operation, runtime configuration is relatively complex and typically handled via the $PCP_SYSCONF_DIR/pmproxy/pmproxy.conf file. This file is in the common ``ini'' format, with section headers and individual variables and values with each section. The configuration file installed as part of PCP documents every available section and option.

At a high level, the [pmproxy] section can be used to explicitly enable or disable each of the different protocols.

The [http] section provides fine-tuning over HTTP server settings used by pmproxy. chunksize sets the chunked transfer encoding buffer size, and defaults to the system pagesize. Access control HTTP protocol settings can be adjusted using the Access-Control-Allow-Headers and Access-Control-Max-Age options. Discussion of these HTTP protocol headers is beyond the scope of this document, but suitable default values are described within the pmproxy.conf configuration file.

The [keys] section allows connection information for one or more backing key-value server processes to be configured (hostnames and ports). Note to access multiple (scalable) key-value servers, the servers variable in this section can be a comma-separated list of hostname:port pairs. Alternatively, it can be a single key-value server host that will be queried using the "CLUSTER INFO" command to automatically configure multiple backing hosts.

In earlier versions of PCP (before 6) an alternative configuration setting section was used for this purpose - key-value servers were specified in the [pmseries] section and this is still accepted as a fallback for backwards compatibility.

ARRANCAR Y PARAR PMPROXY

Normally, pmproxy is started automatically at boot time and stopped when the system is being brought down. Under certain circumstances it is necessary to start or stop pmproxy manually. To do this one must become superuser and type

# $PCP_RC_DIR/pmproxy start

to start pmproxy, or

# $PCP_RC_DIR/pmproxy stop

to stop pmproxy. Starting pmproxy when it is already running is the same as stopping it and then starting it again.

Normally pmproxy listens for PCP client connections on TCP/IP port number 44322 (as well as 44323 with timeseries enabled) registered at https://www.iana.org/. Either the environment variable PMPROXY_PORT or the -p command line option may be used to specify alternative port number(s) when pmproxy is started; in each case, the specification is a comma-separated list of one or more numerical port numbers. Should both methods be used or multiple -p options appear on the command line, pmproxy will listen on the union of the set of ports specified via all -p options and the PMPROXY_PORT environment variable. If non-default ports are used with pmproxy care should be taken to ensure that PMPROXY_PORT is also set in the environment of any client application that will connect to pmproxy, or that the extended host specification syntax is used (see PCPIntro(1) for details).

DIAGNÓSTICO

If pmproxy is already running the message "Error: OpenRequestSocket bind: Address already in use" will appear. This may also appear if pmproxy was shutdown with an outstanding request from a client. In this case, a request socket has been left in the TIME_WAIT state and until the system closes it down (after some timeout period) it will not be possible to run pmproxy.

In addition to the standard PCP debugging options, see pmdbg(1), pmproxy currently supports the debugging option context for tracing client connections and disconnections.

FICHEROS

$PCP_PMPROXYOPTIONS_PATH
command line options for pmproxy when launched from $PCP_RC_DIR/pmproxy All the command line option lines should start with a hyphen as the first character.
$PCP_SYSCONFIG_DIR/pmproxy
Environment variables that will be set when pmproxy executes. Only settings of the form "PMPROXY_VARIABLE=value" will be honoured.
./pmproxy.log
(or $PCP_LOG_DIR/pmproxy/pmproxy.log when started automatically)
All messages and diagnostics are directed here
/etc/pki/tls
default OpenSSL certificate database directory, optionally used for Secure Socket Layer connection in timeseries mode of operation. These certificates can be created and queried using the openssl tool, amongst others.

ENTORNO

In addition to the PCP environment variables described in the PCP ENVIRONMENT section below, there are several environment variables that influence the interactions between a PCP monitoring client, pmproxy and pmcd.

PMCD_PORT
For the PCP monitoring client this (or the default port number) is passed to pmproxy and used to connect to pmcd. In the environment of pmproxy PMCD_PORT is not used.
PMPROXY_HOST
For the PCP monitoring client this is the hostname or IP address of the host where pmproxy is running. In recent versions of PCP (since version 3) this has been superseded by the extended hostname syntax (see PCPIntro(1) for details).
PMPROXY_PORT
For the PCP monitoring client this is the port on which pmproxy will accept connections. The default is 44322, as well as 44323 with timeseries enabled.
PMCD_CONNECT_TIMEOUT, PMCD_RECONNECT_TIMEOUT and PMCD_REQUEST_TIMEOUT
(see PCPIntro(1)) For the PCP monitoring client, setting these environment variables will modify the timeouts used for interactions between the client and pmproxy (independent of which pmcd is being used). For pmproxy these same environment variables control the timeouts between pmproxy and all pmcd(1) instances (independent of which monitoring client is involved).

If set to the value 1, the PMPROXY_LOCAL environment variable will cause pmproxy to run in a localhost-only mode of operation, where it binds only to the loopback interface.

The PMPROXY_MAXPENDING variable can be set to indicate the maximum length to which the queue of pending client connections may grow.

ENTORNO PCP

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

OPCIONES DE DEPURACIÓN

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.

Debugging options specific to pmproxy are as follows:

Option Description
appl0 client connections and disconnections
appl1 desperate logging mode, where a period followed by the PID of pmproxy is inserted in the name of Rlogfile before the last period, so for example pmproxy.log becomes pmproxy.<pid>.log
appl2 log incoming HTTP URLs (this is also enabled by the http debugging option, but the latter has broader scope because it turns on debugging in the libraries that pmproxy uses)
