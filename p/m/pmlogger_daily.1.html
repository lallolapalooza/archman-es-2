PMLOGGER_DAILY(1) Manual de Comandos Generales PMLOGGER_DAILY(1)

NOMBRE

pmlogger_daily - administración de archivos de archivo de Performance Co-Pilot

SINOPSIS

$PCP_BINADM_DIR/pmlogger_daily [-DEfKMNnoPpQrRVzZ?] [-c control] [-k tiempo] [-l archivo_log] [-m direcciones] [-s tamaño] [-t deseado] [-x tiempo] [-X programa] [-Y regex]

DESCRIPCIÓN

pmlogger_daily y las herramientas relacionadas pmlogger_check(1) junto con los archivos de control asociados (ver pmlogger.control(5)) pueden ser utilizados para crear un régimen personalizado de administración y gestión para archivos históricos de datos de rendimiento dentro de la infraestructura de Performance Co-Pilot (ver PCPIntro(1)).

pmlogger_daily está destinado a ser ejecutado una vez al día, preferiblemente temprano en la mañana, tan pronto como sea posible después de la medianoche. Su tarea es agregar, rotar y realizar mantenimiento general en uno o más conjuntos de archivos PCP.

Para acomodar la evolución de los PMDAs y los cambios en los entornos de registro de producción, pmlogger_daily se integra con pmlogrewrite(1) para permitir la reescritura opcional y automática de archivos antes de fusionarlos. Si existen reglas globales de reescritura que se aplicarán a todos los archivos mencionados en los archivos de control, cree el directorio $PCP_SYSCONF_DIR/pmlogrewrite y coloque cualquier regla de reescritura de pmlogrewrite(1) en este directorio. Para reglas de reescritura que son específicas de una sola familia de archivos, use el nombre del directorio del archivo de control (es decir, el cuarto campo) y cree un archivo, un directorio o un enlace simbólico llamado pmlogrewrite dentro de este directorio y coloque las reglas de reescritura requeridas en el archivo pmlogrewrite o en archivos dentro del subdirectorio pmlogrewrite. pmlogger_daily elegirá las reglas de reescritura del directorio del archivo si existen, luego las reglas de reescritura de $PCP_SYSCONF_DIR/pmlogrewrite si ese directorio existe, de lo contrario, no se intentará ninguna reescritura.

Como mecanismo alternativo, si el archivo $PCP_LOG_DIR/pmlogger/.NeedRewrite existe cuando pmlogger_daily comienza, esto se trata de la misma manera que especificar -R en la línea de comandos y se eliminará $PCP_LOG_DIR/pmlogger/.NeedRewrite una vez que se complete toda la reescritura.

OPCIONES

-c control, --control=control
Tanto pmlogger_daily como pmlogger_check(1) son controlados por archivos de control de logger PCP que especifican las instancias de pmlogger(1) a ser gestionadas. El archivo predeterminado de control es $PCP_PMLOGGERCONTROL_PATH, pero se puede especificar uno alternativo usando la opción -c. Si el directorio $PCP_PMLOGGERCONTROL_PATH.d (o control.d de la opción -c) existe, entonces el contenido de cualquier archivo control adicional allí se agregará al archivo de control principal (que debe existir).
-D, --noreport
No realizar el procesamiento condicional de pmlogger_daily_report(1) como se describe a continuación.
-E, --expunge
Esta opción hace que pmlogger_daily pase el indicador -E a pmlogger_merge(1) para expurgar métricas con inconsistencias de metadatos y continuar en lugar de fallar. Esto está destinado a la rotación diaria automatizada de archivos, donde es muy deseable que la fusión, reescritura y compresión diarias desatendidas tengan éxito. Para más detalles, ver pmlogger_merge(1) y la descripción del indicador -x en pmlogextract(1).
-f, --force
Esta opción obliga a pmlogger_daily a intentar acciones de compresión. No se recomienda usar esta opción en producción.
-k tiempo, --discard=tiempo
Después de un período de tiempo, los archivos PCP antiguos se descartan. tiempo es una especificación de tiempo en la sintaxis de find-filter(1), es decir, DD[:HH[:MM]]. Las partes opcionales HH (horas) y MM (minutos) son 0 si no se especifican. Por predeterminado, el tiempo es 14:0:0 o 14 días, pero puede cambiarse usando esta opción.

Se reconocen algunos valores especiales para el tiempo, a saber, 0 para no conservar ningún archivo más allá de los que están siendo escritos actualmente por pmlogger(1), y forever o never para evitar que se descarten archivos.

El tiempo también puede establecerse usando la variable $PCP_CULLAFTER, establecida en el entorno o en un archivo de control. Si tanto $PCP_CULLAFTER como -k especifican valores diferentes para el tiempo, se utiliza el valor de la variable de entorno y se emite una advertencia, es decir, si $PCP_CULLAFTER está establecido en el archivo de control, anula -k dado en la línea de comandos.

Tenga en cuenta que la semántica del tiempo es que se mide desde el momento de la última modificación de cada archivo, y no desde la fecha de creación original del archivo. Esto tiene implicaciones sutiles para la compresión (ver más abajo): el proceso de compresión resulta en la creación de nuevos archivos que tienen nuevos tiempos de modificación. En este caso, el período de tiempo (re)inicia desde el momento de la compresión.

-K
Cuando se especifica esta opción para pmlogger_daily, solo se intentan las tareas de compresión, por lo que no hay rotación de pmlogger, ni eliminación, ni reescritura, etc. Cuando se usa -K y un período de 0 está en efecto (desde -x en la línea de comandos o $PCP_COMPRESSAFTER en el entorno o a través del archivo de control), esto está destinado a entornos donde se desea comprimir los archivos antes de que ocurra el procesamiento diario programado. Para lograr esto, una vez que pmlogger_check(1) ha completado el procesamiento regular, llama a pmlogger_daily solo con la opción -K. Siempre que $PCP_COMPRESSAFTER esté establecido en 0 junto con cualquier otra opción de compresión requerida para que coincida con la invocación programada de pmlogger_daily, esto comprimirá todos los volúmenes excepto los que están siendo escritos actualmente por pmlogger(1). Si $PCP_COMPRESSAFTER está establecido en un valor mayor que cero, entonces ejecutar manualmente pmlogger_daily con la opción -x puede ser usado para comprimir volúmenes que son más jóvenes que el tiempo de $PCP_COMPRESSAFTER. Esto puede ser usado para recuperar espacio en el sistema de archivos comprimiendo volúmenes antes de lo que normalmente se habrían comprimido. Tenga en cuenta que dado que el valor predeterminado de $PCP_COMPRESSAFTER es 0 días, la opción -x no tiene ningún efecto a menos que el archivo de control haya sido editado y $PCP_COMPRESSAFTER se haya establecido en un valor mayor que 0.

El valor predeterminado de $PCP_COMPRESSAFTER es 0 si zstd(1) está instalado, o si xz(1) está instalado y la biblioteca lzma está disponible (como se informa para la opción transparent_decompress por pmconfig(1)). De lo contrario, el valor predeterminado de $PCP_COMPRESSAFTER es never.

-l archivo, --logfile=archivo
Para asegurar que no se envíe correo no intencional cuando estos scripts se ejecutan desde cron(8) o systemd(1), los diagnósticos siempre se envían a archivos de registro. Por defecto, este archivo es $PCP_LOG_DIR/pmlogger/pmlogger_daily.log pero esto puede ser cambiado usando la opción -l. Si este archivo de registro ya existe cuando el script comienza, se renombrará con un sufijo de .prev (sobrescribiendo cualquier archivo de registro guardado anteriormente) antes de que se generen los diagnósticos en el archivo de registro. Las opciones -l y -t no pueden usarse juntas.
