PMDALOGGER(1) Manual de Comandos Generales PMDALOGGER(1)

NOMBRE

pmdalogger - agente de dominio de métricas de rendimiento de archivos de registro (PMDA)

SINOPSIS

$PCP_PMDAS_DIR/logger/pmdalogger [-D debug] [-d dominio] [-l logfile] [-m memoria] [-s intervalo] [-U usuario] [archivo_config]

DESCRIPCIÓN

pmdalogger es un Agente de Dominio de Métricas de Rendimiento (PMDA) configurable para monitorizar archivos de registro. Puede considerarse análogo a la opción -f de tail(1) y convierte cada nueva línea de registro en un evento de rendimiento. Fue el primer PMDA en hacer un uso extensivo de métricas de eventos, que pueden ser consumidas por herramientas cliente como pmevent(1).

El PMDA logger exporta métricas de estilo evento que reflejan registros de eventos con marca de tiempo para texto registrado en un archivo (o conjunto de archivos o salida de un proceso), así como las métricas más ortodoxas de estilo muestra, como recuentos de eventos y valores de tamaño de rendimiento.

El PMDA se configura a través de un archivo_config que contiene una línea por cada fuente de eventos (archivo o proceso). Este archivo es configurado por el script de Instalación descrito en la sección posterior sobre ``INSTALACIÓN'' del PMDA.

A continuación se presenta una breve descripción de las opciones de línea de comandos de pmdalogger:

-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y consistente. Es decir, dominio debe ser diferente para cada PMDA en el mismo host, y se debe usar el mismo número de dominio para el mismo PMDA en todos los hosts.
-l
Ubicación del archivo de registro. Por defecto, un archivo de registro llamado logger.log se escribe en el directorio actual de pmcd(1) cuando se inicia pmdalogger, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de registro no puede ser creado o no es escribible, la salida se escribe en el error estándar en su lugar.
-m
Limita la memoria física utilizada por el PMDA para almacenar en búfer los registros de eventos a tamañomax bytes. A medida que llegan los eventos de registro al PMDA, deben ser almacenados en búfer hasta que las herramientas cliente individuales soliciten el siguiente lote desde su lote anterior de eventos. El máximo por defecto es de 2 megabytes.
-s
Establece el intervalo de sondeo para detectar líneas de registro recién llegadas. Refleja la misma opción del comando tail(1).
-U
Cuenta de usuario bajo la cual se ejecutará el agente. Por defecto es la cuenta no privilegiada "pcp" en las versiones actuales de PCP, pero en versiones anteriores se utilizaba la cuenta de superusuario ("root") por defecto.

INSTALACIÓN

Si desea acceso a los nombres, texto de ayuda y valores de las métricas de rendimiento de logger, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/logger
# ./Install

Este es un proceso de instalación interactivo que solicita la ruta de cada archivo de registro a monitorizar (o comando a ejecutar), un nombre de instancia métrica para identificarlo, y si el acceso debe ser restringido (consulte la opción -x de pmevent(1) para más detalles).

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/logger
# ./Remove

pmdalogger es lanzado por pmcd(1) y nunca debe ser ejecutado directamente. Los scripts de Instalación y Eliminación notifican a pmcd(1) cuando el agente se instala o elimina.

ARCHIVOS

$PCP_PMCDCONF_PATH
opciones de línea de comandos utilizadas para lanzar pmdalogger
$PCP_PMDAS_DIR/logger/logger.conf
archivo de configuración por defecto para las métricas de logger
$PCP_PMDAS_DIR/logger/help
archivo de texto de ayuda por defecto para las métricas de logger
$PCP_PMDAS_DIR/logger/Install
script de instalación para el agente pmdalogger
$PCP_PMDAS_DIR/logger/Remove
script para deshacer la instalación del agente pmdalogger
$PCP_LOG_DIR/pmcd/logger.log
archivo de registro por defecto para mensajes de error y otra información de pmdalogger

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede ser utilizada para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información a veces es críptica y está destinada principalmente a guiar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmdalogger son las siguientes:

Opción Descripción
appl0 procesamiento de archivo_config y configuración de PMNS
appl1 carga de datos de eventos desde los archivos de registro
appl2 interacción con pmcd(1).
