pmDiscoverServices(3)

Paquete: pcp

Licencias: GPL-2.0-or-later, LGPL-2.1-or-later, CC-BY-3.0

PMDISCOVERSERVICES(3) Manual de funciones de la biblioteca PMDISCOVERSERVICES(3)

NOMBRE

pmDiscoverServices, __pmDiscoverServicesWithOptions - descubre servicios de PCP en la red

SINOPSIS

#include <pcp/pmapi.h>

int pmDiscoverServices(const char *service,
const char *mechanism, char ***urls);

#include <pcp/libpcp.h>

int __pmDiscoverServicesWithOptions(const char *service,
const char *mechanism, const char *optionsString, const volatile unsigned *flags, char ***urls);

cc ... -lpcp

ADVERTENCIA

Esta documentación está destinada al uso interno de desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las APIs de PCP que se garantiza que permanecerán fijas entre versiones, y pueden no funcionar, o pueden proporcionar una semántica diferente en algún momento en el futuro.

DESCRIPCIÓN

Dado un nombre de servicio de PCP, identificado por service, y utilizando el tipo de descubrimiento especificado opcionalmente en mechanism, pmDiscoverServices devuelve, a través de urls, una lista de URLs que representan los servicios descubiertos en la red.

La función interna __pmDiscoverServicesWithOptions realiza la misma función y añade argumentos para opciones globales y un mecanismo para interrumpir el proceso de descubrimiento.

La utilidad pmfind(1) proporciona acceso desde la línea de comandos a ambas interfaces.

Llamar a

pmDiscoverServices(service, mechanism, urls)

es equivalente a llamar a

__pmDiscoverServicesWithOptions(service, mechanism, NULL, NULL, urls);

service especifica el servicio de PCP a descubrir. Los servicios soportados actualmente son PM_SERVER_SERVICE_SPEC y PM_SERVER_PROXY_SPEC que buscan servidores pmcd(1) y pmproxy(1) respectivamente.

mechanism especifica el estilo de descubrimiento a utilizar.

Los mecanismos soportados actualmente son:

avahi
Esto busca servicios que se están anunciando usando mDNS a través de avahi-daemon(8). Se puede añadir un sufijo opcional ",timeout=N" para especificar el tiempo de espera de descubrimiento en múltiplos de punto flotante de un segundo. El tiempo de espera por defecto es 0.5 segundos, que puede ser anulado por la variable de entorno AVAHI_DISCOVERY_TIMEOUT, también especificada en múltiplos de punto flotante de un segundo. Si ambos se especifican, el valor especificado en la variable de entorno tiene prioridad.
probe=<dirección-red>/<bits-máscara>
Sondea activamente la subred dada para los servicios de PCP solicitados. <dirección-red> es una dirección de red inet o ipv6 y <bits-máscara> es el número de bits utilizados para definir la subred. Por ejemplo, 192.168.1.0/24 define una subred de 8 bits que consiste en las direcciones 192.168.1.0 a 192.168.1.255. Se puede añadir un sufijo opcional ",maxThreads=N" para limitar el número de hilos utilizados durante el sondeo. El valor por defecto es el valor de __FD_SETSIZE (que suele ser 1024) o el número de direcciones en la subred, el que sea menor. Se puede añadir un sufijo opcional ",timeout=N" para especificar el tiempo de espera para cada intento de conexión en múltiplos de punto flotante de un segundo. El valor por defecto es 0.02 segundos (20 milisegundos).
shell
Sondea la lista de direcciones proporcionadas por scripts para los servicios de PCP solicitados. También se pueden proporcionar varios parámetros opcionales separados por comas. En primer lugar, la opción "path=DIR" especifica el directorio donde se encuentran los comandos como pcp-kube-pods(1) (el valor por defecto es $PCP_BINADM_DIR/discover/). Esta configuración puede ser restringida aún más a un comando individual usando la opción command=CMD, pero el valor por defecto es usar todos los comandos disponibles del path. La opción "maxThreads=N" limita el número de hilos utilizados durante el sondeo. El valor por defecto es el valor de __FD_SETSIZE (que suele ser 1024) o el número de direcciones devueltas por los scripts, el que sea menor. La opción "timeout=N" puede añadirse para limitar la cantidad de tiempo dedicada a esperar cada intento de conexión. N es un número de punto flotante que especifica el número de segundos de espera. El valor por defecto es 0.02 segundos (20 milisegundos).

mechanism también puede ser NULL, lo que significa que se utilizarán todos los mecanismos de descubrimiento disponibles.

Para __pmDiscoverServicesWithOptions, optionsString especifica opciones globales que se aplicarán al proceso de descubrimiento. Las opciones están separadas por comas y pueden ser una o más de las siguientes:

resolve
Esto solicita que se intente la resolución de nombres DNS para las direcciones de los servicios descubiertos.
timeout=N
Esto especifica un período de tiempo de espera después del cual se interrumpirá el proceso de descubrimiento. N es un número de punto flotante que representa el número de segundos antes de que expire el tiempo de espera.

optionsString también puede ser NULL, lo que significa que no se especifican opciones globales.

Para __pmDiscoverServicesWithOptions, flags especifica un puntero a un objeto de tipo unsigned que es una máscara de bits de opciones/estados para el proceso de descubrimiento. Las banderas soportadas son:

PM_SERVICE_DISCOVERY_RESOLVE
Especificar esta bandera es equivalente a especificar resolve en optionsString
PM_SERVICE_DISCOVERY_INTERRUPTED
Esta bandera debe estar desestablecida al llamar a __pmDiscoverServicesWithOptions, pero puede ser establecida asincrónicamente (por un manejador de interrupciones, por ejemplo) para interrumpir el proceso de descubrimiento de servicios.

flags también puede ser NULL, lo que indica que no hay banderas establecidas.

pmDiscoverServices y __pmDiscoverServicesWithOptions devolverán el número de servicios descubiertos, o un valor menor que cero en caso de error. El valor cero indica que no se descubrieron servicios.

La lista resultante de punteros, urls, y los valores (las URLs) a los que apuntan los punteros habrán sido asignados por pmDiscoverServices o __pmDiscoverServicesWithOptions con una única llamada a malloc(3), y es responsabilidad del llamante de pmDiscoverServices o __pmDiscoverServicesWithOptions llamar a free(urls) para liberar el espacio cuando ya no se necesite.

Cuando ocurre un error, o no se descubren servicios, urls no está definido (no se habrá asignado espacio, por lo que llamar a free(3) es una muy mala idea).

ENTORNO DE PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5). Los valores para estas variables pueden obtenerse programáticamente usando la función pmGetConfig(3).

DIAGNÓSTICOS

-EINVAL
Se ha especificado un argumento inválido.
-ENOMEM
No se ha podido asignar la memoria necesaria para procesar la solicitud.
-EOPNOTSUPP
El mechanism especificado no es compatible.
