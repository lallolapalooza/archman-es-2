PMLOGGER_DAILY_REPORT(1) Manual de comandos generales PMLOGGER_DAILY_REPORT(1)

NOMBRE

pmlogger_daily_report - escribir informes de resumen diario de Performance Co-Pilot

SINOPSIS

$PCP_BINADM_DIR/pmlogger_daily_report [-ApV?] [-a archivo_archivo] [-f archivo_salida] [-h nombre_host] [-l archivo_log] [-o directorio] [-t intervalo]

DESCRIPCIÓN

pmlogger_daily_report escribe informes de resumen de rendimiento diario, muy parecidos a los producidos por sadc(1) y la utilidad sa2(8).

Todos los argumentos de la línea de comandos son opcionales y están destinados a ser autoexplicativos.

Por defecto, los informes no se generan, pero si el paquete pcp-zeroconf ha sido instalado (habrá archivos en $PCP_VAR_DIR/config/pmlogconf/zeroconf) entonces las métricas necesarias se habrán incluido en el archivo de configuración predeterminado de pmlogger(1) y se generarán los informes.

Los informes se generan (por defecto) poco después de la medianoche, una vez que pmlogger_daily(1) ha completado la fusión de cualquier archivo parcial para generar un archivo para la actividad de ayer.

Cada informe de resumen de rendimiento se llama sarXX (donde XX es el día del mes de ayer). El archivo_salida puede cambiarse con la opción -f. El informe se escribirá en el directorio $PCP_LOG_DIR/sa por defecto, pero esto puede cambiarse con la opción -o a un directorio diferente.

Tenga en cuenta que existen opciones de línea de comandos lo suficientemente flexibles para que pmlogger_daily_report se utilice para leer cualquier archivo_archivo y escribir el informe en cualquier directorio de salida.

Si no se proporciona la opción -a, el archivo de entrada predeterminado es $PCP_ARCHIVE_DIR/HOSTNAME/YYYYMMDD, donde HOSTNAME es por defecto el nombre del host local (a menos que se cambie con la opción -h) y YYYYMMDD es el nombre base del archivo fusionado de ayer, tal como lo producen pmlogger(1) y pmlogger_daily(1). Si archivo_archivo es un directorio, entonces pmlogger_daily_report utilizará todos los archivos PCP encontrados en ese directorio para escribir el informe (esto se conoce como modo multiarchivo, y puede ser considerablemente más lento que especificar un solo archivo como entrada).

Los informes en sí mismos son creados por la utilidad pmrep(1) utilizando su archivo de configuración predeterminado, consulte pmrep.conf(5). Las entradas de configuración de pmrep(1) utilizadas para escribir los informes están actualmente codificadas en el script pmlogger_daily_report.

Finalmente, los archivos de entrada deben contener suficientes métricas según lo necesite pmrep(1) para escribir el informe. En plataformas que lo admiten, el paquete pcp-zeroconf configura el registro PCP según sea necesario para esto; por lo tanto, pmlogger_daily_report debe usarse con la configuración de pmlogger(1) que se configura con pcp-zeroconf. Como su nombre indica, pcp-zeroconf no requiere configuración adicional después de la instalación para capturar los archivos necesarios para pmlogger_daily_report.

OPCIONES

Las opciones disponibles en la línea de comandos son:

-a archivo
Especifica un archivo de entrada o directorio alternativo archivo.
-A
Utiliza los tiempos de inicio y fin del archivo de entrada para el informe, en contraposición al comportamiento predeterminado de 24 horas desde la medianoche de ayer.
-f nombre_archivo
Especifica un nombre_archivo de salida alternativo. -h nombre_host Especifica un nombre_host alternativo para usar dentro de la ruta del archivo de entrada predeterminado.
-l archivo, --logfile=archivo
Para garantizar que no se envíe correo no intencionalmente cuando este script se ejecuta desde pmlogger_daily(1), los diagnósticos siempre se envían a un archivo de registro. Por defecto, este archivo es $PCP_LOG_DIR/pmlogger/pmlogger_daily_report.log, pero esto puede cambiarse usando la opción -l. Si este archivo de registro ya existe cuando el script comienza, se renombrará con un sufijo .prev (sobrescribiendo cualquier archivo de registro guardado anteriormente) antes de que se generen los diagnósticos al archivo de registro.
-p
Si se especifica esta opción, se consulta el estado del procesamiento diario y, si el informe no se ha realizado en las últimas 24 horas, se realiza ahora. Con esta opción, pmlogger_daily_report simplemente sale si el procesamiento del día anterior ya se ha realizado.

Esta opción ya no es necesaria, ya que la consulta de pmlogger_daily(1) garantizará que se genere el informe, sin embargo, la opción se conserva por compatibilidad con versiones anteriores.

-t intervalo
Especifica el intervalo de muestreo utilizado al generar el informe, en el formato descrito en PCPIntro(1). El valor predeterminado es cada 10 minutos.
-V, --verbose
La salida de la ejecución del script puede extenderse usando esta opción, que habilita el rastreo detallado de la actividad. Por defecto, el script no genera ninguna salida de registro a menos que se encuentre alguna condición de error o advertencia.
-?, --help
Muestra el mensaje de uso y sale.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

VER TAMBIÉN

PCPIntro(1), pmlogger_daily(1), pmlogger(1), pmrep(1), sadc(1) y sa2(8).
