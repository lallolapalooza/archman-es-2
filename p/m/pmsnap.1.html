PMSNAP(1) Manual de Comandos Generales PMSNAP(1)

NOMBRE

pmsnap - genera imágenes de instantáneas de resumen de rendimiento

SINOPSIS

$PCP_BINADM_DIR/pmsnap [-NV?] [-c configuraciones] [-C directorio] [-f formato] [-n nombres] [-o directorio]

DESCRIPCIÓN

pmsnap es un script de shell que normalmente se ejecuta periódicamente desde crontab(1) para generar imágenes gráficas de los gráficos de rendimiento de pmchart(1). Estas imágenes pueden estar en cualquiera de los formatos soportados por pmchart, incluyendo png, bmp y jpeg, y pueden ser incorporadas al contenido ofrecido por el servidor web local. Por defecto, pmsnap no genera ninguna salida textual a menos que se encuentre alguna condición de error o advertencia.

pmsnap genera imágenes según su archivo de control, $PCP_PMSNAPCONTROL_PATH (o dir/control si se especifica la opción -C), y utiliza archivos creados por pmlogger(1) o folios de archivos de PCP creados por pmafm(1) y pmlogger_check(1). Antes de intentar configurar pmsnap, se recomienda encarecidamente que se configure pmlogger según las descripciones en pmlogger_daily(1), pmlogger_check(1) y pmlogger(1).

Una vez que se ha configurado pmlogger, es necesario configurar pmsnap de la siguiente manera:

1.
Edite el archivo de control $PCP_PMSNAPCONTROL_PATH. La sintaxis de este archivo se describe en el comentario al inicio del archivo y se proporciona un ejemplo para gráficos de rendimiento "Resumen" de una y doce horas para el host local. Los argumentos adecuados para pmchart también se describen en el comentario. El usuario debe consultar pmchart para más detalles. Tenga en cuenta que cuando se ejecuta pmsnap, sustituye globalmente la cadena LOCALHOSTNAME por el nombre del host local en el archivo de control.
2.
Pruebe la configuración ejecutando
$PCP_BINADM_DIR/pmsnap. Sin ningún argumento, pmsnap procesará cada línea que no sea un comentario en $PCP_PMSNAPCONTROL_PATH. Las imágenes de salida se colocarán en los archivos nombrados en el primer campo de cada línea del archivo de control, con la extensión del formato de archivo si es necesario. Si estos nombres de archivo no comienzan con / o ., se asumen relativos a dir, como se especifica con la opción -o. El dir por defecto es el directorio actual. Tenga en cuenta que si pmlogger se ha iniciado recientemente (hace unos 15 minutos), es posible que no se produzcan imágenes de instantáneas y no se emitirán mensajes de error; la razón es que pmchart no puede usar archivos muy cortos y, por lo tanto, pmsnap tampoco. Para fines de depuración, se debe usar la opción -V.
3.
Agregue una entrada apropiada para pmsnap en el crontab del usuario root. Se proporciona un ejemplo en $PCP_VAR_DIR/config/pmlogger/crontab.
4.
Incorpore las imágenes de pmsnap al contenido WWW local. Por lo general, las páginas WWW utilizan imágenes relativas a una raíz de documento particular, por lo que a menudo es conveniente usar la opción de línea de comandos -o para especificar un subdirectorio del contenido WWW local, y luego crear una página web en este directorio que muestre las imágenes de instantánea con texto y otro contenido apropiado para el entorno local.

Una página HTML de ejemplo, adecuada para la instantánea Resumen, puede encontrarse en $PCP_VAR_DIR/config/pmsnap/Summary.html.

Aunque pmsnap intenta vaciar los búferes de salida de stdio(3) en los procesos relevantes de pmlogger antes de generar imágenes de instantánea, esto puede fallar por diversas razones y no se emitirá ningún mensaje de error.

pmsnap no debe invocarse inmediatamente después de que pmlogger_daily haya rotado los registros, ya que los nuevos archivos serán demasiado cortos para obtener resultados significativos. Tenga en cuenta, sin embargo, que pmsnap no informará de errores de pmchart por no poder cumplir con la opción -A en archivos muy cortos. En estos casos, no se informará ningún error y no se producirán imágenes de salida.

OPCIONES

Las opciones de línea de comandos disponibles son:

-c patrón-config
Procesar solo las líneas del archivo de control que coincidan con la expresión regular patrón-config en la columna Config.
-C directorio
El archivo control se encuentra en el directorio directorio en lugar de la ubicación predeterminada $PCP_PMSNAPCONTROL_PATH.
-f formato
Establecer el formato de imagen de salida. El formato predeterminado es png.
-n patrón-nombre
Procesar solo las líneas del archivo de control que coincidan con la expresión regular patrón-nombre (ver egrep(1)) en la columna Nombre.
-N
Habilitar un modo "muéstrame", donde las acciones se repiten, pero no se ejecutan, al estilo de "make -n". Usar -N junto con -V maximiza las capacidades de diagnóstico para la depuración.
-o directorio
Las imágenes de salida con nombres de archivo que no comienzan con / o . se colocarán en un directorio relativo a directorio; de lo contrario, el directorio de salida es relativo al directorio actual (es decir, el valor predeterminado para directorio es ./). Tenga en cuenta que directorio debe ser una ruta de directorio escribible y puede estar en un sistema de archivos NFS o CIFS.
-V
Habilitar el modo detallado.
-?
Mostrar mensaje de uso y salir.

Cuando se usan -n o -c, pmsnap solo procesará las líneas del archivo de control que coincidan con todos los patrones suministrados. Si no se proporcionan patrones, se procesarán todas las líneas. Estos argumentos permiten múltiples entradas para pmsnap en crontab para que diferentes imágenes de resumen de rendimiento puedan generarse en diferentes momentos o con diferentes frecuencias.

ARCHIVOS

$PCP_PMSNAPCONTROL_PATH
Archivo de control de pmsnap
$PCP_VAR_DIR/config/pmsnap/Summary
vista de resumen para pmchart
$PCP_VAR_DIR/config/pmsnap/Summary.html
página HTML de ejemplo para la instantánea de resumen
$PCP_LOG_DIR/pmlogger/<hostname>/Latest
folio de archivo de PCP para el host hostname, como lo genera pmlogger_check
$PCP_VAR_DIR/config/pmlogger/crontab
entrada de ejemplo de crontab
