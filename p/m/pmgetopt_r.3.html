PMGETOPTIONS(3) Manual de funciones de biblioteca PMGETOPTIONS(3)

NOMBRE

pmgetopt_r, pmGetOptions, pmGetContextOptions, pmFreeOptions, pmUsageMessage - manejo de línea de comandos para herramientas PMAPI

SINOPSIS

#include <pcp/pmapi.h>

int pmgetopt_r(int argc, char *const *argv, pmOptions *opts);
int pmGetOptions(int argc,
char *const *argv, pmOptions *opts);

int pmGetContextOptions(int ctx, pmOptions *opts);
void pmUsageMessage(pmOptions *opts);
void pmFreeOptions(pmOptions *opts);

cc ... -lpcp

DESCRIPCIÓN

La función pmGetOptions proporciona servicios de procesamiento de opciones de línea de comandos tanto para herramientas de monitor como de colector de PMAPI(3). Está modelada sobre las variantes seguras para hilos de la API getopt_long(3) de GNU, y difiere principalmente en su enfoque en proporcionar un procesamiento generalizado para las opciones de línea de comandos de PCP (de facto) estándar descritas en PCPIntro(1). Estas opciones comunes incluyen la especificación de host y archivo, ventanas de tiempo, zonas horarias, recuentos de muestras, intervalos de tiempo, y así sucesivamente.

La interfaz principal es pmGetOptions, a la que se le deben pasar el recuento de argumentos argc y el array argv, tal como se pasan a la función main() al invocar el programa. El argumento final opts describe el conjunto de opciones largas y cortas que la herramienta está preparada para procesar, y otra metadato sobre cómo deben procesarse esas opciones.

La interfaz pmgetopt_r, utilizada internamente por pmGetOptions, se comporta de manera similar, pero no realiza ningún procesamiento de opciones común. Es más adecuada para procesos colectores de PCP, mientras que las herramientas de monitor de PCP tienden a usar pmGetOptions.

El argumento opts consiste en un array de entradas pmLongOpts que describen los argumentos, así como la estructura envolvente pmOptions, que se definen de la siguiente manera (los campos internos no se presentan, por brevedad):

typedef struct {
    const char *        long_opt;
    int                 has_arg;
    int                 short_opt;
    const char *        argname;
    const char *        message;
} pmLongOptions;
typedef struct {
    int                 version;
    int                 flags;
    const char *        short_options;
    pmLongOptions *     long_options;
    const char *        short_usage;
    pmOptionOverride    override;
    int                 index;
    int                 optind;
    int                 opterr;
    int                 optopt;
    char                *optarg;
    /* [campos internos, indocumentados] */
    int                 errors;
    int                 context; /* PM_CONTEXT_{HOST,ARCHIVE,LOCAL} */
    int                 nhosts;
    int                 narchives;
    char **             hosts;
    char **             archives;
    struct timespec     start;
    struct timespec     finish;
    struct timespec     origin;
    struct timespec     interval;
    char *              align_optarg;
    char *              start_optarg;
    char *              finish_optarg;
    char *              origin_optarg;
    char *              guiport_optarg;
    char *              timezone;
    int                 samples;
    int                 guiport;
    int                 padding;
    unsigned int        guiflag : 1;
    unsigned int        tzflag  : 1;
    unsigned int        nsflag  : 1;
    unsigned int        Lflag   : 1;
    unsigned int        zeroes  : 28;
} pmOptions;

Los campos iniciales flags y version describen cómo se debe interpretar el resto de la estructura pmOptions. Estos campos pueden estar a cero, especificando una interpretación predeterminada. Alternativamente, la macro PMAPI_VERSION puede usarse para especificar el nivel de la API a usar (actualmente, se permiten valores de 3 o menos). La versión 2 es la predeterminada, la versión 3 introduce campos de ventana de tiempo e intervalo de alta resolución (es decir, usando struct timespec en lugar de struct timeval). Al usar esta última forma, antes de incluir <pcp/pmapi.h>, la macro PMAPI_VERSION debe establecerse en 3 para asegurar que la disposición correcta de la estructura pmOptions sea utilizada por la aplicación. El campo flags puede usarse para modificar el comportamiento del procesamiento de opciones, como se describe en la sección "VALORES DE FLAGS" a continuación.

El array de estructuras pmLongOpts long_options debe estar terminado por un centinela y la macro PMAPI_OPTIONS_END puede usarse para efectuar esta terminación. Las entradas individuales dentro del array long_options pueden ser de dos tipos: cabeceras de opciones o opciones reales. Una cabecera de opciones se construye usando la macro PMAPI_OPTIONS_HEADER, y se usa para agrupar opciones en el mensaje de uso. Se puede insertar texto libre en el mensaje de uso en cualquier punto usando la macro PMAPI_OPTIONS_TEXT; esto está destinado a texto explicativo adicional que cubra el uso detallado que va más allá del alcance de las cabeceras u opciones individuales. De lo contrario, la entrada del array especifica una opción. Estas deben tener nombre (long_opt) si se permite una forma de opción larga, especificar si toman un argumento (has_arg), especificar el argumento de variante de un solo carácter (short_opt) si se permite una forma de opción corta, y finalmente especificar cómo presentar la opción en el mensaje de uso. Este último componente consiste en una descripción corta, de una sola palabra, del argumento opcional (argname) y una descripción de una línea de lo que hace la opción de línea de comandos (message).

La cadena short_usage también se usa solo al construir el mensaje de uso. Forma el componente del mensaje de uso que sigue al nombre del programa (es decir, argv[0]).

La cadena opcional short_options es la cadena normal de especificación de opciones de línea de comandos de getopt, usando caracteres individuales (aquellos con argumentos se designan como tales usando el carácter ':') - como lo usan todas las implementaciones de getopt.

Se proporciona una instalación para extender el conjunto existente de opciones comunes con opciones adicionales, así como para reasignar las opciones estándar a roles no estándar para herramientas individuales. Esto último se logra mediante el método override, que permite proporcionar una función de devolución de llamada que se llamará al recibir cada argumento, antes del procesamiento común. Si esta devolución de llamada devuelve un valor no cero, el procesamiento común se cortocircuitará para esa opción; de lo contrario, el procesamiento continúa. Por lo tanto, cada herramienta cliente es libre de elegir exactamente cuáles de las opciones estándar desea admitir; pueden ser todas, algunas o ninguna, y sin importar lo que elijan, cada herramienta siempre tiene acceso a la capacidad de análisis de opciones largas y a la instalación de generación de mensajes de uso.

Los campos restantes de la estructura pmOptions se rellenan como resultado del procesamiento de los argumentos y son en gran medida autoexplicativos. Se pospone una mayor discusión de estos en la sección "VALORES DE FLAGS". El campo error contiene un recuento de errores detectados durante el procesamiento de opciones. Estos pueden ser errores de uso o de tiempo de ejecución, según lo indique el campo flags (establecido y pasado al llamador). Típicamente, una herramienta de línea de comandos fallará al iniciarse correctamente y producirá un mensaje de error (por ejemplo, a través de pmUsageMessage) si el campo error no es cero al final de pmGetOptions o pmGetContextOptions.

Algunos post-procesamientos de opciones de línea de comandos solo pueden realizarse una vez que la herramienta ha establecido un contexto PMAPI a través de pmNewContext(3). Este procesamiento incluye el uso de zonas horarias conscientes del contexto (-z), y el procesamiento de ventanas de tiempo (-A, -O, -S, -T) que pueden verse afectadas por la zona horaria, por ejemplo. La función pmGetContextOptions está disponible para tales situaciones y completa cualquier procesamiento restante de opts con respecto al identificador de contexto ctx dado.

La función pmUsageMessage genera un mensaje de uso para la herramienta, e incluye tanto las opciones estándar de PCP como las opciones personalizadas para cada herramienta, según lo especificado por el array pmLongOptions. Admite la agrupación de opciones (a través de PMAPI_OPTIONS_HEADER) así como el formato ordenado de todas las opciones - cortas y largas - sus argumentos y mensajes explicativos individuales. Construirá este mensaje de uso usando pmprintf(3) sobre el cual emitirá un único pmflush(3) antes de devolver el control al llamador, siempre que el flag PM_OPTFLAG_USAGE_ERR esté establecido en flags, lo cual ocurrirá automáticamente durante el análisis de opciones, cuando se detecten errores de uso.

PMFREEOPTIONS(3)

LibPCP

NAME

pmFreeOptions, pmGetOptions, pmOptionsHelp, pmUsageMessage - process command line options for Performance Co-Pilot (PCP)

SYNOPSIS

cc -l - $PCP_FINISH_TIME -T --finish fin de la ventana de tiempo $PCP_INTERVAL -t --interval intervalo de muestreo $PCP_TIMEZONE -Z --timezone establecer la zona horaria de informes $PCP_HOSTZONE -z --hostzone establecer la zona horaria de informes a la hora local de la fuente de métricas

COMPATIBILIDAD

Antes de PCP 7.0 y libpcp.so.4, los miembros start, finish, origin e interval de la estructura pmOptions eran struct timeval. Para soportar la transición de PMAPI, las viejas interfaces y semánticas pueden ser usadas si las aplicaciones están enlazadas con libpcp.so.3 o recompiladas con -DPMAPI_VERSION=2.

VALOR DE RETORNO

La función pmGetOptions retorna cuando detecta una opción de línea de comandos que no es una del conjunto estándar de PCP, o cuando se alcanza el fin de las opciones de la línea de comandos (en cuyo punto se retorna -1). Tanto las rutinas pmgetopt_r como pmGetOptions retornan el control al llamador de la misma manera que una llamada regular a getopt, con el valor de retorno indicando ya sea el fin de todo el procesamiento (-1), o la forma de un solo carácter de la opción que se está procesando actualmente, o cero para el caso especial de opción larga solamente. Para todos los casos de procesamiento de opciones, se retorna la estructura opts que contiene los campos optarg, opterr, optopt, optind e index rellenados como de costumbre (NO use el optarg o optind globales de la biblioteca C de su plataforma, estos **NO** serán modificados).

pmGetOptions no retorna al llamador cuando se están procesando opciones estándar de PCP (aunque el mecanismo de override puede ser usado para detectar tales opciones si es necesario).

La función pmGetContextOptions retorna cero en caso de éxito, o un código de error negativo de PCP en caso de fallo. El campo error dentro del parámetro opts también será distinto de cero en este último caso.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ son usadas para parametrizar los nombres de archivos y directorios usados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede ser usada para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5). Los valores para estas variables pueden obtenerse programáticamente usando la función pmGetOptions(3).
