PMLOGCOMPRESS(1) Manual de Comandos Generales PMLOGCOMPRESS(1)

NOMBRE

pmlogcompress, pmlogdecompress - comprimir y descomprimir archivos de archivo PCP

SINOPSIS

pmlogcompress [-NV?] [-A arg] [-c proglist] [-f prog] [-l límite] [-o tipo] [-Z mín] archivo ...
pmlogdecompress [-NV?] [-t dir] archivo ...

DESCRIPCIÓN

pmlogcompress y pmlogdecompress soportan la compresión y descompresión de los archivos que componen un archivo de Performance Co-Pilot (PCP); consulte LOGARCHIVE(5) para una explicación de los diversos archivos que son componentes de un archivo PCP.

Los argumentos archivo pueden ser el nombre de un archivo individual en un archivo PCP o el nombre base de un archivo PCP, al estilo generado por pmlogbasename(1). En el primer caso, pmlogcompress comprimirá (o pmlogdecompress descomprimirá) solo ese archivo, pero en el segundo caso pmlogcompress intentará comprimir (o para pmlogdecompress descomprimir) **todos** los archivos que forman parte del archivo PCP asociado.

Para la descompresión, la extensión del nombre de cada archivo asociado con archivo determina la herramienta de descompresión a utilizar.

OPCIONES

Las opciones de línea de comandos disponibles son:

-A arg, --argumento=arg
arg se utiliza como argumento para el programa de compresión; probablemente sea útil con la opción -f para que la elección del programa de compresión sea determinista.

El procesamiento de arg no es sofisticado, por lo que se deben evitar las variables de entorno incrustadas, los caracteres de escape, los caracteres de "glob" del shell y los espacios en blanco.

Se permiten múltiples opciones -A y se utilizarán **todos** los argumentos arg.

-c proglist, --comando=proglist
Dependiendo de otras opciones de línea de comandos y de la disponibilidad de programas de compresión instalados, la elección del programa al comprimir puede variar. La opción -c permite proporcionar una **lista** de programas de compresión, ya sea con múltiples opciones -c y/o separando los nombres de programas en proglist por dos puntos, al estilo de la notación $PATH del shell.

El valor predeterminado para proglist es zstd:xz:bzip2:gzip.

-f prog, --usar=prog
Si solo se debe considerar un programa para la compresión, esto puede especificarse usando la opción -f. El efecto es el mismo que si solo se usara una opción -c, y proglist contuviera exactamente un nombre de programa, a saber prog.
-l límite, --límite-inferior=límite
Al comprimir, no considerar archivos más pequeños que límite (bytes).

El valor predeterminado para límite es 4096.

-N, --mostrar
No hacer nada, pero mostrar qué comandos se habrían ejecutado.
-o tipo, --optimizar=tipo
Al comprimir, la opción -o intentará elegir el programa de compresión de proglist (ver la opción -c arriba) que haga el "mejor" trabajo, donde tipo puede ser espacio para elegir el programa de compresión que produce el archivo de salida más pequeño, o tiempo para elegir el programa de compresión que utiliza menos tiempo de CPU.

Si archivo es un nombre base de archivo, entonces se seleccionará el archivo más grande de los que forman parte del archivo PCP asociado para la prueba, de lo contrario se utilizará archivo para la prueba.

El uso de esta opción significa que cada uno de los archivos archivo seleccionados se comprimirá varias veces, por lo que es probable que -o se use en experimentos con -N (y posiblemente -V) para determinar la mejor herramienta de compresión para el entorno local y los archivos PCP.

-t dir, --directorio=dir
Al descomprimir, los archivos comprimidos (por defecto) serán reemplazados por su equivalente descomprimido. La opción -t cambia este comportamiento para crear un duplicado, sin comprimir, del archivo en el directorio dir.

Si archivo es un archivo individual, entonces solo ese archivo se descomprime en dir, pero si archivo es un nombre base de archivo, entonces **todos** los archivos de archivo se copiarán, y posiblemente se descomprimirán, en dir.

Si un archivo **no** está comprimido, se intentará primero crear un enlace físico en dir con ln(1) y si esto falla, se hará una copia con cp(1).

dir debe existir antes de que se ejecute pmlogdecompress.

-V, --verboso
Aumentar verbosidad.
-Z mín, --mín-tamaño-zstd=mín
xz(1) produce archivos comprimidos más pequeños para archivos de entrada pequeños, pero en algún momento el archivo de entrada se vuelve lo suficientemente grande como para que zstd(1) produzca archivos comprimidos más pequeños y zstd es típicamente mucho más rápido.

Cuando tanto xz como zstd están en consideración (ver la opción -c arriba), la opción -Z permite al usuario ajustar dónde ocurre el cambio de xz a zstd; los archivos de entrada más pequeños que mín (en bytes) se comprimirán con xz, de lo contrario se usará zstd.

El valor predeterminado para mín es 52428800 (50MiB).

-?, --ayuda
Mostrar mensaje de uso y salir.

NOTA

Para la mayoría de los usuarios, estas herramientas no se utilizarán directamente porque la compresión y descompresión explícitas de los archivos PCP no son necesarias.

Más bien, si la compresión del archivo está habilitada, esto se hará indirectamente desde los scripts de gestión de archivos PCP pmlogger_check(1), pmlogger_daily(1) y pmlogger_rewrite(1).

La descompresión se maneja de forma transparente durante la reproducción del archivo por las rutinas que implementan la Interfaz de Programación de Métricas de Rendimiento (PMAPI).
