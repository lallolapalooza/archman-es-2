PMLOGCONF(1) Manual de Comandos Generales PMLOGCONF(1)

NOMBRE

pmlogconf - crear/editar un archivo de configuración de pmlogger

SINOPSIS

pmlogconf [-cqrvV?] [-d dir_grupos] [-D depuracion] [-g etiqueta_grupo] [-h host] [-s archivo_grupo] archivo_config

DESCRIPCION

pmlogconf puede usarse para crear y modificar un archivo de configuración genérico para el archivador de PCP, pmlogger(1).

Si archivo_config no existe, pmlogconf creará un archivo de configuración genérico con un conjunto predeterminado de métricas habilitadas e intervalos de registro.

Una vez creado, archivo_config puede usarse con la opción -c de pmlogger(1) para seleccionar métricas de rendimiento y especificar intervalos de registro para un archivo PCP.

Si archivo_config existe, pmlogconf solicitará entrada al usuario para habilitar o deshabilitar grupos de métricas de rendimiento relacionadas y para controlar el intervalo de registro de cada grupo habilitado.

La selección de grupo requiere una respuesta simple de y (sí) o n (no) a la solicitud ¿Registrar este grupo?.

Otras respuestas en este punto pueden usarse para seleccionar funciones de control adicionales como las siguientes:

m
Informar los nombres de las métricas en el grupo actual.
q
Terminar con la selección de grupos (salir) y no realizar más cambios en este grupo ni en ninguno posterior.
/patron
No realizar cambios en este grupo pero buscar un grupo que contenga patron en la descripción del grupo o los nombres de las métricas asociadas.

Se especifica un intervalo de registro respondiendo a la solicitud ¿Intervalo de registro? con las palabras clave once o default o una especificación de intervalo válida de pmlogger(1) de la forma ``every N unidades_tiempo'' o simplemente ``N unidades_tiempo '' (el every es opcional) donde N es un entero sin signo y unidades_tiempo es una de las palabras clave msec, millisecond, sec, second, min, minute, hour o la forma plural de una de las palabras clave.

Cuando se ejecuta desde procesos de registro automatizado, la opción -c se utiliza para indicar que pmlogconf está en modo de auto-creación y no se realiza ningún diálogo interactivo. El archivo de salida archivo_config tiene un mensaje de comentario adicional y una marca de tiempo que indica este hecho, para que pueda ser identificado y posteriormente actualizado usando -c nuevamente. Esta opción no es adecuada para el uso interactivo de la herramienta.

La opción -q suprime el diálogo de intervalo de registro y conserva el intervalo actual de archivo_config.

Se puede habilitar una salida más detallada con la opción -v.

ARCHIVOS DE CONFIGURACION DE GRUPOS

Cuando se crea un archivo_config inicial, las especificaciones predeterminadas provienen de un conjunto de archivos de grupo debajo de dir_grupos especificado con la opción -d (el dir_grupos predeterminado es $PCP_VAR_DIR/config/pmlogconf, que es lo más comúnmente correcto, por lo que la opción -d rara vez se usa en la práctica).

La estructura de directorios debajo de dir_grupos es arbitraria, ya que todos los archivos regulares se encontrarán mediante recorrido recursivo y se considerarán; por lo tanto, los productos adicionales y los desarrolladores de PMDA pueden extender fácilmente los predeterminados disponibles para pmlogconf agregando nuevos directorios y/o archivos de grupo debajo de dir_grupos.

Estos archivos de grupo se procesan de las siguientes maneras:

  • Cuando se crea un nuevo archivo_config, se procesan todos los archivos de grupo.
  • Cada vez que se ejecuta pmlogconf con un archivo_config existente, se recorre dir_grupos para ver si se han definido nuevos grupos y deben considerarse para su inclusión en archivo_config.
  • Cuando pmlogconf procesa un grupo en archivo_config que está habilitado, la lista de métricas asociadas con el grupo se toma del archivo de grupo (y reemplaza cualquier lista anterior de métricas asociadas con este grupo en archivo_config).
  • Cuando se especifica la opción de línea de comandos -r (reprobe) o -c (auto-crear), cada grupo (no solo los recién descubiertos) se reprocesa para ver si debe considerarse para su inclusión en archivo_config.
  • Si se encuentra un grupo en archivo_config pero el grupo correspondiente no existe debajo de dir_grupos (como sería el caso cuando un grupo se vuelve obsoleto por una actualización de PCP), el manejo del grupo depende del modo en que se ejecuta pmlogconf. Con -c, el grupo correspondiente se elimina de archivo_config; de lo contrario, el grupo correspondiente no se modifica en archivo_config. En ambos casos, se emite una advertencia.

Cada archivo de grupo está estructurado de la siguiente manera:

  • La primera línea debe contener #pmlogconf-setup 2.0
  • Otras líneas que comienzan con # se tratan como comentarios.
  • Las líneas en blanco se ignoran.
  • Una o más líneas que comienzan con la palabra clave ident se usan para proporcionar la descripción legible por humanos del grupo.
  • Las líneas no en blanco que comienzan con espacio en blanco definen métricas que se asociarán con este grupo, una por línea. Cada especificación de métrica sigue las reglas para una configuración de pmlogger(1), es decir, el nombre de un nodo no hoja en el PMNS (lo que implica todos los nombres descendientes en el PMNS), o el nombre de un nodo hoja en el PMNS seguido opcionalmente por uno o más nombres de instancia encerrados entre ``['' y ``]'' .
  • Debe estar presente una línea de control que comience con una de las palabras clave probe o force.
  • Una línea de control de intervalo de registro opcional comienza con la palabra clave delta seguida de una de las especificaciones de intervalo de pmlogger(1) descritas anteriormente.
  • Las líneas de métricas derivadas opcionales comienzan con la palabra clave define y tienen el formato:

define nombre expresión
donde nombre es el nombre de una métrica derivada y expresión es una expresión de métrica derivada. Consulte pmRegisterDerived(3) para las descripciones sintácticas y semánticas de nombre y expresión. Una vez definido, nombre puede usarse como la métrica en una línea de control probe posterior, lo que permite la expresión de guardas más complejas para la inclusión condicional de métricas en archivo_config.

Tenga en cuenta que nombre debe ser único en **todos** los archivos de grupo y no debe colisionar con un nombre existente en el PMNS. Por lo tanto, puede ser necesario adoptar una convención de nombres adecuada cuando se crean los archivos de grupo.

•
Las líneas de control probe tienen el formato:

probe métrica [condición [regla_estado] ]
donde métrica es el nombre de una métrica de PCP (debe ser un nodo hoja en el PMNS, no se permite especificación de instancia y no debe ser una métrica derivada, aparte de una mencionada en una línea de control define anterior) y la condición opcional es la palabra clave exists (verdadero si métrica existe, es decir, está definida en el PMNS) o la palabra clave values (verdadero si métrica existe en el PMNS y tiene una o más valores actuales) o una expresión de la forma
op val donde op es uno de los operadores de awk(1) (==, !=, >, >=, <, <=, ~ (coincidencia de expresión regular) o !~ (coincidencia de expresión regular negada)) y val es un valor (secuencia arbitraria de caracteres, excluyendo un espacio) y la condición es verdadera si existe alguna instancia de métrica que hace que la expresión sea verdadera.

Si la condición falta, el valor predeterminado es exists.

Cuando se proporciona una condición explícita, también puede haber una regla_estado opcional de la forma
? estado_verdadero : estado_falso donde estado_verdadero (se aplica si la condición es verdadera) y estado_falso (se aplica si la condición es falsa) provienen de las palabras clave include (incluir y habilitar el grupo y las métricas asociadas en archivo_config), available (incluir y deshabilitar el grupo en archivo_config - se necesita una acción de usuario de y como se describió anteriormente para habilitar el grupo y agregar las métricas asociadas a archivo_config) o exclude (el grupo no se considera para su inclusión en archivo_config).

El valor por defecto de state_rule es
? available : exclude

•
Las líneas de control force comienzan con la palabra clave force seguida de uno de los estados definidos anteriormente, de modo que una de las acciones include, exclude o available se aplica incondicionalmente al grupo.

La sondeo solo se realiza cuando se está agregando un nuevo grupo a configfile o cuando se especifica la opción de línea de comandos -r. La evaluación de las condiciones de sondeo se realiza contactando con pmcd(1) en hostname (por defecto: local).

OPCIONES

Las opciones de línea de comandos disponibles son:

-c
Habilita el modo no interactivo de creación automática.
-d groupsdir, --groups=groupsdir
Especifica la ruta al directorio groupsdir.
-g grouptag, --group=grouptag
Consulta el estado de registro para el grupo de registro específico denominado grouptag.
-h host, --host=host
La fuente de métricas de rendimiento es pmcd(1) en host, en lugar de en el localhost por defecto.
-q, --quiet
Modo silencioso, suprime el diálogo del intervalo de registro.
-r, --reprobe
Reconsidera la inclusión de cada grupo en configfile.
-s groupfile, --setup=groupfile
Informa el estado de registro por defecto para el único grupo de registro en groupfile. Esta es una salida equivalente a la producida por el script de shell retirado pmlogconf-setup de versiones anteriores de PCP.
-v, --verbose
Habilita el modo detallado.
-V, --version
Muestra el número de versión y sale.
-?, --help
Muestra el mensaje de uso y sale.

EJEMPLOS

El siguiente archivo de grupo demuestra la mayoría de los elementos sintácticos admitidos.

#pmlogconf-setup 2.0
ident   Archivo de grupo de ejemplo
ident   ... más descripción
delta   1 minuto
probe   sample.secret.foo.one values ? include : exclude
        sample.secret.foo.one
        sample.secret.foo.bar   # no terminal en el PMNS
        sample.colour [ red green ]

En el siguiente ejemplo (se han agregado barras invertidas para facilitar la lectura, la cláusula define está en una sola línea), las métricas mumble se incluirán en configfile si la métrica mumble.foo es conocida y tiene al menos una instancia (y valor) o si la métrica mumble.bar es conocida y tiene al menos una instancia (y valor):

#pmlogconf-setup 2.0
ident   Ejemplo de métrica derivada con alternancia
define  mumble.check = \
            (defined(mumble.foo) ? count(mumble.foo) : 0) + \
            (defined(mumble.bar) ? count(mumble.bar) : 0)
probe   mumble.check > 0 ? include : exclude
        mumble

El siguiente ejemplo utiliza una métrica derivada para acceder a una instancia de métrica particular en una línea de control probe.

#pmlogconf-setup 2.0
ident   Ejemplo de métrica derivada que usa una sola instancia de métrica
define  fumble_log = fumble.control[verbose_log]
probe   fumble_log > 0 ? include : exclude
        fumble.detailed

MIGRACIÓN

La versión actual de pmlogconf (2.0) admite un formato ligeramente diferente para configfile en comparación con versiones anteriores. Si se presenta una configfile de versión antigua a pmlogconf, se convertirá al nuevo formato.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

pmlogconf anula cualquier variable de entorno $PCP_DERIVED_CONFIG a una cadena vacía, por razones de rendimiento y para evitar la inclusión de métricas derivadas en configfile.

pmlogconf respeta la variable de entorno $PMCD_WAIT_TIMEOUT al sondeo y creación de nuevos archivos de configuración de pmlogger. Utiliza un valor de tiempo de espera por defecto de 10 segundos para esto, en ausencia de una configuración de entorno.

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información es a veces críptica y está destinada principalmente a proporcionar orientación para desarrolladores en lugar de usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
