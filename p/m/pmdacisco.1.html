PMDACISCO(1) Manual general de comandos PMDACISCO(1)

NOMBRE

pmdacisco - Agente de dominio de métricas de rendimiento de enrutadores Cisco (PMDA)

SINOPSIS

$PCP_PMDAS_DIR/cisco/pmdacisco [-D debug] [-d dominio] [-l archivo_log] [-U nombre_usuario] [-P contraseña] [-r refrescar] [-s prompt] [-M nombre_usuario] [-x puerto] host:especificacion_interfaz [...]
$PCP_PMDAS_DIR/cisco/parse [opciones] host:especificacion_interfaz [...]
$PCP_PMDAS_DIR/cisco/probe [-D debug] [-P contraseña] [-s prompt] [-U nombre_usuario] [-x puerto] host

DESCRIPCIÓN

pmdacisco es un Agente de Dominio de Métricas de Rendimiento (PMDA) que extrae métricas de rendimiento de uno o más enrutadores Cisco.

A continuación se presenta una breve descripción de las opciones de línea de comandos de pmdacisco:

-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y consistente. Es decir, dominio debe ser diferente para cada PMDA en el mismo host, y el mismo número de dominio debe usarse para el mismo PMDA en todos los hosts.
-l
Ubicación del archivo de registro. Por defecto, se escribe un archivo de registro llamado cisco.log en el directorio actual de pmcd(1) cuando se inicia pmdacisco, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de registro no se puede crear o no se puede escribir en él, la salida se escribe en el error estándar en su lugar.
-P
Por defecto, se asume que no se requiere contraseña a nivel de usuario para acceder al puerto telnet de Cisco. Si se han habilitado contraseñas a nivel de usuario en los Cisco, estas contraseñas deben especificarse a pmdacisco. Si se especifica con la opción -P, contraseña se utilizará como la contraseña de usuario predeterminada para todos los Cisco. Consulte también la sección IDENTIFICACIÓN DE INTERFAZ a continuación.
-r
pmdacisco actualizará los valores actuales de todas las métricas de rendimiento contactando a cada enrutador Cisco una vez cada refrescar segundos. El valor predeterminado de refrescar es 120 segundos.
-s
El prompt del comando Cisco termina con la cadena prompt. El valor predeterminado es ``>''. La única forma en que pmdacisco puede sincronizar el envío de comandos y el análisis de la salida es reconociendo prompt como una cadena única que aparece al final de toda la salida, es decir, como el prompt del comando cuando espera el siguiente comando.
-U
Por defecto, se asume que no se requiere inicio de sesión con nombre de usuario para acceder al puerto telnet de Cisco. Si se ha habilitado el inicio de sesión con nombre de usuario en los Cisco, los nombres de usuario correspondientes deben especificarse a pmdacisco. Si se especifica con la opción -U, nombre_usuario se utilizará como el nombre de usuario de inicio de sesión predeterminado para todos los Cisco. Consulte también la sección IDENTIFICACIÓN DE INTERFAZ a continuación.
-M
Cuenta de usuario bajo la cual se ejecutará el agente. El valor predeterminado es la cuenta no privilegiada "pcp" en las versiones actuales de PCP, pero en versiones anteriores se utilizaba la cuenta de superusuario ("root") por defecto.
-x
Conéctese al Cisco a través del puerto TCP número puerto en lugar del predeterminado 23 para una conexión telnet.

Para cada interfaz, una vez establecida la conexión telnet, pmdacisco está dispuesto a esperar hasta 5 segundos para que el Cisco proporcione una nueva instantánea de la información solicitada. Si esto no ocurre, la conexión telnet se rompe y no se devuelven valores. Esto evita que pmdacisco ocupe los puertos telnet del Cisco esperando indefinidamente cuando la respuesta del enrutador no es la esperada, por ejemplo, si el formato de la salida de ``show int'' cambia, o si el comando es erróneo porque una interfaz ya no está configurada en el enrutador.

IDENTIFICACIÓN DE INTERFAZ

Dado que cada enrutador Cisco puede admitir múltiples interfaces de red y/o múltiples protocolos de comunicación, es necesario indicar a pmdacisco qué interfaces se deben monitorizar.

Los argumentos host:especificacion_interfaz en la línea de comandos definen una interfaz particular en un enrutador Cisco particular. host debe ser un nombre de host o una dirección IP en "notación de punto" que identifique el puerto telnet de un enrutador Cisco particular. Hay varios componentes de la especificacion_interfaz, como se indica a continuación.

protocolo
Una de las abreviaturas a, B, E, e, f, G, h, s o Vl respectivamente para ATM, BRI (ISDN), FastEthernet, Ethernet, FDDI, GigabitEthernet, HSSI, serial o Vlan.
interfaz
Dependiendo del modelo del Cisco, será un entero, por ejemplo, s0, o un entero seguido de una barra (``/'') seguida de una identificación de subinterfaz en una de las diversas formas sintácticas, por ejemplo, e1/0, G0/0/1 o s4/2.1.

Para descubrir las interfaces válidas en un Cisco en particular, conéctese al puerto telnet (usando telnet(1)) e introduzca el comando "show int" y busque los identificadores de interfaz después de las palabras clave "Ethernet", "Fddi", "Serial", etc.

Alternativamente, ejecute el comando probe.

nombre_usuario
Si hay un inicio de sesión con nombre de usuario, y es diferente al predeterminado (ver -U arriba), se puede especificar opcionalmente aquí agregando "@" y el nombre de usuario al final de especificacion_interfaz.
contraseña
Si hay una contraseña a nivel de usuario, y es diferente a la predeterminada (ver -P arriba), se puede especificar opcionalmente aquí agregando un signo de interrogación (``?'') y la contraseña al final de especificacion_interfaz.
prompt
Si el prompt del comando Cisco es diferente al predeterminado (ver -s arriba), se puede especificar opcionalmente aquí agregando un signo de exclamación (``!'') y el prompt al final de especificacion_interfaz.

Los siguientes son ejemplos de argumentos de especificacion_interfaz válidos. 

my-router:e1/2
123.456.789.0:s0
wancisco:f2/3?trust_me
somecisco:G1/0!myprompt
cisco34.foo.bar.com:e2?way2cool
mycisco:s2/2.1@mylogin
yourcisco:E0/0@yourlogin?yourpassword
mycisco:E0/0@mylogin?mypassword!myprompt

UTILIDADES AUXILIARES

El comando probe se puede usar para descubrir los nombres de todas las interfaces para un enrutador Cisco particular identificado por host. El argumento -P es el mismo que para pmdacisco.

El comando parse toma exactamente los mismos argumentos que pmdacisco, pero se ejecuta fuera del control de cualquier pmcd(1) y, por lo tanto, se puede usar para diagnosticar problemas con el manejo de un enrutador Cisco particular y/o una de sus interfaces.

Puede producirse una verbosidad de diagnóstico adicional utilizando la opción de línea de comandos -D appl0,appl1,appl2. appl0 registra eventos de conexión y desconexión, progreso del inicio de sesión, flujo de control de alto nivel y estadísticas extraídas. appl1 rastrea todos los comandos enviados al dispositivo Cisco. appl2 registra la tokenización y el análisis de la salida del dispositivo Cisco. Los diagnósticos se generan en el error estándar a medida que se obtienen y analizan las muestras.

INSTALACIÓN

Si desea acceso a los nombres, texto de ayuda y valores de las métricas de rendimiento de Cisco, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/cisco
# ./Install

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/cisco
# ./Remove

pmdacisco es lanzado por pmcd(1) y nunca debe ejecutarse directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o desinstala.

VER TAMBIÉN

pmcd(1), pcpintro(1) y telnet(1).

ARCHIVOS

$PCP_PMCDCONF_PATH
opciones de línea de comandos usadas para lanzar pmdacisco
$PCP_PMDAS_DIR/cisco/help
archivo de texto de ayuda predeterminado para las métricas de Cisco
$PCP_PMDAS_DIR/cisco/Install
script de instalación para el agente pmdacisco
$PCP_PMDAS_DIR/cisco/Remove
script para deshacer la instalación del agente pmdacisco
$PCP_LOG_DIR/pmcd/cisco.log
archivo de registro predeterminado para mensajes de error y otra información de pmdacisco

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información es a veces críptica y está destinada principalmente a guiar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmdacisco son las siguientes:

Opción Descripción
appl0 inicialización, detalles del proceso trabajador, actualización de datos, tiempos de espera
appl1 solicitudes enviadas al dispositivo Cisco
appl2 analizador léxico y sintáctico para la salida del dispositivo Cisco

VER TAMBIÉN

pmcd(1), pcp.conf(5) y pcp.env(5).
