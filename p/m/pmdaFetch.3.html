Paquete: pcp

PMDAFETCH(3) Manual de Funciones de Biblioteca PMDAFETCH(3)

NOMBRE

pmdaFetch, pmdaSetFetchCallBack - llenar una estructura pmResult con los valores de métricas solicitados

SINOPSIS C

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaFetch(int numpmid,
pmID *pmidlist, pmResult **resp, pmdaExt *pmda);

void pmdaSetFetchCallBack(pmdaInterface *dispatch,
pmdaFetchCallBack callback);

cc ... -lpcp_pmda -lpcp

DESCRIPCIÓN

pmdaFetch es una llamada de retorno genérica utilizada por un PMDA(3) para procesar una solicitud de obtención de pmcd(1). La solicitud de pmcd se inicia mediante un cliente que llama a pmFetch(3).

Este es uno de los pocos callbacks genéricos en libpcp_pmda (ver PMDA(3)) que está incompleto, requiriendo un método adicional pmdaFetchCallBack propio. El callback adicional debe registrarse usando pmdaSetFetchCallBack y el método pmdaFetchCallBack tiene el siguiente prototipo:

int func(pmdaMetric *mdesc, unsigned int inst, pmAtomValue *avp)

pmdaFetch asignará y redimensionará la estructura de resultado resp, para almacenar valores para las numpmid métricas listadas en pmidlist.

Para cada instancia listada en el perfil (ver pmdaProfile(3)) de cada métrica listada en pmidlist, se llama al método pmdaFetchCallBack para llenar la estructura pmAtomValue identificada por avp con un valor para un par métrica-instancia específico identificado por el descriptor de métrica mdesc y la instancia inst. Este valor se copia luego en la estructura pmResult.

El método pmdaFetchCallBack debe devolver un valor menor que cero para un error, y los casos más probables serían PM_ERR_PMID si la métrica identificada por mdesc no es conocida por el método, o PM_ERR_INST si el método cree que la instancia inst no es conocida para la métrica identificada por mdesc.

Los códigos de error de éxito dependen de la versión de PMDA_INTERFACE que esté utilizando el PMDA.

Si el PMDA está utilizando PMDA_INTERFACE_2, entonces en caso de éxito, el método pmdaFetchCallBack debe devolver 0.

Si el PMDA está utilizando PMDA_INTERFACE_3 o PMDA_INTERFACE_4, entonces en caso de éxito, el método pmdaFetchCallBack debe devolver 1 si se devuelve un valor a través de avp, de lo contrario 0 si actualmente no hay valores disponibles para el par métrica-instancia solicitado, aunque mdesc e inst parezcan razonables.

Si el PMDA está utilizando PMDA_INTERFACE_5 o posterior, entonces en caso de éxito, el método pmdaFetchCallBack debe devolver PMDA_FETCH_STATIC (1) si el valor devuelto a través de avp puede ser ignorado por pmdaFetch una vez que se ha copiado en la estructura pmResult, de lo contrario PMDA_FETCH_DYNAMIC (2) si el valor devuelto a través de avp utiliza los campos vp o cp de pmAtomValue y el valor asociado (buffer) fue asignado usando uno de malloc(3), calloc(3), realloc(3), strdup (3), etc. y pmdaFetch debe liberar la memoria llamando a free(3) una vez que se ha asignado un nuevo buffer y se ha copiado el valor, de lo contrario PMDA_FETCH_NOVALUES (0) si actualmente no hay valores disponibles para el par métrica-instancia solicitado, aunque mdesc e inst parezcan razonables.

Si el método pmdaFetchCallBack devuelve un valor para una instancia de una métrica de tipo PM_TYPE_STRING o PM_TYPE_AGGREGATE, se necesita un cuidado especial: el método debe utilizar un buffer estático, establecer avp->cp o avp->vp a la dirección del buffer y devolver PMDA_FETCH_STATIC, o utilizar un buffer asignado dinámicamente, mantener una referencia estática a la dirección del buffer, devolver PMDA_FETCH_STATIC y liberar (free (3)) o redimensionar (realloc (3)) o reutilizar el buffer la próxima vez que se llame al método pmdaFetchCallBack, de lo contrario usar un buffer asignado dinámicamente y devolver PMDA_FETCH_DYNAMIC.

EJEMPLO

Los siguientes fragmentos de código son para un PMDA hipotético que tiene métricas (A, B, C y D) y un dominio de instancia (X) con dos instancias (X1 y X2). Las tablas de descripción del dominio de instancia y las métricas (ver pmdaInit(3)) podrían definirse como:

static pmdaInstid _X[] = {
    { 0, "X1" }, { 1, "X2" }
};

static pmdaIndom indomtab[] = {
#define X_INDOM 0
    { 0, 2, _X },
};

static pmdaMetric metrictab[] = {
/* A */
    { (void *)0,
      { PMDA_PMID(0,0), PM_TYPE_32, PM_INDOM_NULL,
        PM_SEM_INSTANT, {0,0,0,0,0,0} }, },
/* B */
    { (void *)0,
      { PMDA_PMID(0,1), PM_TYPE_DOUBLE, X_INDOM,
        PM_SEM_INSTANT, {0,1,0,0,PM_TIME_SEC,0} }, },
/* C */
    { (void *)0,
      { PMDA_PMID(0,2), PM_TYPE_STRING, PM_INDOM_NULL,
        PM_SEM_INSTANT, {0,0,0,0,0,0} }, },
/* D */
    { (void *)0,
      { PMDA_PMID(0,3), PM_TYPE_STRING, PM_INDOM_NULL,
        PM_SEM_INSTANT, {0,0,0,0,0,0} }, },
};

Un método pmdaFetchCallBack para ser llamado desde pmdaFetch podría definirse como:

int
myFetchCallBack(pmdaMetric *mdesc, unsigned int inst, pmAtomValue *avp)
{
  static char sbuf[20]; // reutilizar este buffer
  char        *dbuf;    // asignado con malloc
  switch (pmID_item(mdesc->m_desc.pmid)) {
    case 0:
      /* asignar algún valor para la métrica A */;
      avp->l = ...
      break;
    case 1:
      switch (inst) {
          case 0:
	      /* asignar un valor para la métrica B, instancia X1 */;
              avp->d = ...
              break;
          case 1:
	      /* asignar un valor para la métrica B, instancia X2 */;
              avp->d = ...
              break;
          default:
              return PM_ERR_INST;
      }
    case 2:
      /* colocar valor para la métrica C en dbuf[] */
      memcpy(dbuf, ...);
      avp->cp = dbuf;
      break;
    case 3:
      avp->cp = (char *)malloc(somesize);
      /* colocar valor en avp->cp */
      pmsprintf(avp->cp, somesize, ...);
      return PMDA_FETCH_DYNAMIC;
    default:
      return PM_ERR_PMID;
  }
  return PMDA_FETCH_STATIC;
}

ADVERTENCIA

El PMDA debe estar usando PMDA_INTERFACE_2 o posterior, como se especifica en la llamada a pmdaDSO(3) o pmdaDaemon(3).

DIAGNÓSTICOS

Los siguientes mensajes de error indican que hay una discrepancia entre el espacio de nombres y las tablas pmdaMetric y pmdaIndom pasadas a pmdaInit(3), y el callback de obtención registrado:

pmdaFetch: La métrica solicitada métrica no está definida
Una métrica solicitada métrica no está listada en la tabla pmdaMetric. El espacio de nombres para este PMDA(3) puede contener métricas adicionales.
pmdaFetch: PMID pmid no manejado por el callback de obtención
El método pmdaFetchCallBack ha devuelto PM_ERR_PMID. Esto indica que una métrica puede estar listada en la tabla pmdaMetric, pero no es compatible con el método callback.
pmdaFetch: La instancia inst de PMID pmid no manejada por el callback de obtención
El método pmdaFetchCallBack ha devuelto PM_ERR_INST. Esto indica que una instancia de métrica está listada en la tabla pmdaIndom, pero no es compatible con el método callback.
pmdaFetch: Error en el callback de obtención:
El método pmdaFetchCallBack devolvió un resultado diferente de PMDA_FETCH_NOVALUES, PMDA_FETCH_STATIC, PMDA_FETCH_DYNAMIC, PM_ERR_PMID o PM_ERR_INST.
pmdaFetch: El tipo de descriptor (type) para la métrica pmid es incorrecto
El tipo de datos type especificado para la métrica pmid en la tabla pmdaMetric es ilegal.

pmdaFetch devolverá -errno si ocurrió un error

pmdaFetch(3)

NAME

pmdaFetch - Fetch an array of Performance Metrics Values

C SYNOPSIS

#include <pcp/pmapi.h>


int pmdaFetch(int item, const char *fname, pmResult **result);

DESCRIPTION

The pmdaFetch function is a helper function that is used by PMDAs to fetch performance metric values.

The pmdaFetch function is a wrapper around the underlying PMAPI(3) call to pmFetch(3). It is intended for use within a PMDA to simplify the process of retrieving metric values from the Performance Metrics Collector Daemon (PMCD) when the PMDA is running as a client, or from local kernel sources.

The item argument is the performance metric identifier for which values are to be fetched. The fname argument is the name of the source of the metric, typically the name of the PMDA itself, or NULL if the metric is to be fetched from the default source (usually PMCD).

The result argument is a pointer to a pointer to a pmResult(3) structure. On successful return, this structure will be populated with the fetched metric values. The caller is responsible for freeing this structure using pmFreeResult(3).

If the call to pmFetch(3) is successful, pmdaFetch returns 0. On failure, it returns a negative error code, which can be one of the PM_ERR_ values defined in <pcp/pmapi.h>.

EXAMPLE

The following example shows how a PMDA might use pmdaFetch to retrieve the value of a metric:

    #include <pcp/pmapi.h>
    #include <pcp/pmda.h>

    int
    my_pmda_fetch(pmResult **result)
    {
        int err;
        pmID m_id;

        /* Assume m_id is already set to the correct PMID */
        err = pmdaFetch(m_id, NULL, result);
        if (err != 0) {
            /* Handle error */
            return err;
        }

        /* Process the fetched values in (*result)->vstat[] */
        /* ... */

        /* Free the result when done */
        pmFreeResult(*result);
        return 0;
    }

CAVEAT

The pmdaFetch function allocates memory for the pmResult(3) structure. The caller is responsible for freeing this memory using pmFreeResult(3) to avoid memory leaks.

DIAGNOSTICS

The pmdaFetch function returns a negative error code on failure. The specific error code indicates the nature of the failure. Common error codes include:

PM_ERR_PMDAID
Invalid performance metric identifier.
PM_ERR_GENERIC
A generic error occurred.
PM_ERR_IPC
An error occurred during inter-process communication.

Refer to the pmapi(3) manual page for a complete list of error codes.

It is important to check the return value of pmdaFetch and handle any errors appropriately. Failure to do so may lead to unexpected behavior or crashes.

The pmResult(3) structure contains an array of pmAtomValue(3) structures. Care should be taken when accessing these values, especially when dealing with different data types. The pmdaFetch function itself handles the allocation and copying of the pmResult(3) structure or copying the value from the pmAtomValue(3).
