pmdaGetOpt(3)

Paquete: pcp

Licencias: GPL-2.0-or-later, LGPL-2.1-or-later, CC-BY-3.0

PMDAGETOPTIONS(3) Manual de funciones de la biblioteca PMDAGETOPTIONS(3)

NOMBRE

pmdaGetOpt, pmdaGetOptions - obtener opciones de los argumentos, analizando opciones genéricas de PMDA

SINOPSIS

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaGetOptions(int argc,
char *const *argv, pmdaOptions *opts, pmdaInterface *dispatch);

int pmdaGetOpt(int argc,
char *const *argv, const char *optstring, pmdaInterface *dispatch, int *err);

cc ... -lpcp_pmda -lpcp

DESCRIPCIÓN

Estas funciones son envoltorios para pmgetopt_r(3). El comportamiento de cada función es que se asume que ciertas opciones tienen un comportamiento predefinido que inicializa varios campos en la estructura pmdaInterface. La interfaz pmdaGetOptions permite dar tanto opciones cortas como largas, mientras que pmdaGetOpt solo permite opciones de forma corta.

Las opciones que tanto pmdaGetOptions como pmdaGetOpt capturarán son:

-Despecif_debug
Establece las opciones de depuración de PMAPI(3) a especif_debug, como se describe en PCPIntro(1). Se utiliza para controlar los niveles de salida de traza durante la depuración.
-ddominio
Establece el número de dominio de este agente.
-harchivo_ayuda
Obtiene el texto de ayuda (ver pmdaText(3)) para las métricas de este archivo en lugar de la ruta especificada con pmdaDSO(3) o pmdaDaemon(3).
-ipuerto
Espera que PMCD se conecte en el puerto inet (número o nombre).
-6puerto
Espera que PMCD se conecte en el puerto ipv6 (número o nombre).
-larchivo_log
Redirige la salida de diagnóstico y traza a archivo_log.
-p
Espera que PMCD proporcione entrada/salida estándar por tubería.
-usocket
Espera que PMCD se conecte en el socket de dominio unix.

La interfaz pmdaGetOptions también capturará las siguientes opciones y las almacenará dentro del parámetro opts:

-Unombre_usuario
Establece la cuenta de usuario bajo la cual debe ejecutarse el PMDA.

Solo se puede especificar una de las opciones -i, -6, -p y -u. Si no se proporciona ninguna de estas tres opciones, se asume una tubería (-p). Cuando pmdaGetOpt encuentra estas opciones, la opción se procesa y se examina la siguiente opción. Por lo tanto, pmdaGetOpt solo devolverá cuando se encuentre una opción que no sea las enumeradas anteriormente, o se llegue al final de la lista. El valor devuelto será el argumento o EOF, respectivamente.

Un PMDA puede controlar qué opciones aceptará el programa con el argumento opts u optstring. Para aceptar todas las opciones, el PMDA debe llamar a pmdaGetOptions con el campo short_options de la estructura opts establecido en la macro PMDA_OPTIONS, o pmdaGetOpt con la cadena de opciones "D:d:h:i:l:pu:". Cualquier opción específica del PMDA debe añadirse a estas cadenas al estilo de getopt(3), y será devuelta tanto por pmdaGetOptions como por pmdaGetOpt si se encuentran.

Cuando se detecta un error de uso de opción en la línea de comandos en la interfaz pmdaGetOptions, el campo de error de la estructura opts contendrá un recuento de errores distinto de cero.

pmdaGetOpt toma un puntero a un int, err, que se utiliza como contador de errores. Esta variable debe inicializarse a cero antes de llamar a pmdaGetOpt por primera vez, y comprobarse cuando pmdaGetOpt devuelva EOF.

Ni pmdaGetOptions ni pmdaGetOpt modifican sus parámetros argc o argv.

Las variables globales utilizadas por la interfaz getopt (3) del sistema también pueden ser utilizadas por el llamante de pmdaGetOpt dentro del bucle de análisis de argumentos.

Por otro lado, la interfaz pmdaGetOptions no utiliza variables globales en absoluto (ni las lee ni las modifica). En su lugar, estas variables se pueden acceder a través de los campos opts del mismo nombre.

ADVERTENCIA

Las opciones -D, -d, -i, -l, -p y -u no pueden ser reutilizadas para otros propósitos por el PMDA, a menos que se utilice el método override proporcionado por la interfaz pmdaGetOptions, que opera de la misma manera que se describe para la interfaz pmGetOptions(3) utilizada por las herramientas cliente de PMAPI.

El PMDA debe estar utilizando PMDA_INTERFACE_2 o posterior, como se especifica en la llamada a pmdaDSO(3) o pmdaDaemon(3).

DIAGNÓSTICOS

Tanto pmdaGetOptions como pmdaGetOpt mostrarán los mismos mensajes de error que getopt.

VER TAMBIÉN
