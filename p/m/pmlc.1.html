NOMBRE

pmlc - configurar interactivamente el pmlogger de Performance Co-Pilot activo

SINOPSIS

pmlc [-eiPz?] [-D depuración] [-h host] [-n archivo pmns] [-p puerto] [-Z zona horaria] [pid]

DESCRIPCIÓN

pmlc puede usarse para cambiar las métricas e instancias que un pmlogger(1) escribe en un archivo de Performance Co-Pilot (ver PCPIntro(1)), la frecuencia con la que se recopilan las métricas y si el registro es obligatorio, consultivo, activado o desactivado. También informa el estado actual de registro de métricas e instancias. pmlc puede usarse para controlar instancias de pmlogger en hosts remotos así como en el host local.

Normalmente pmlc opera en el Espacio de Nombres de Métricas de Rendimiento (PMNS) distribuido, sin embargo si se especifica la opción -n se carga un PMNS local alternativo del archivo archivo pmns.

Si se especifica la opción -P, pmlc intentará iniciar una conexión con el pmlogger primario en el host local. Si se especifica la opción -p, entonces pmlc intentará iniciar una conexión con el pmlogger en este puerto TCP/IP. Alternativamente, si se especifica pid, se intentará una conexión con la instancia de pmlogger con ese identificador de proceso al inicio. La opción -h solo puede usarse si también se especifican -P, -p puerto o un pid. En ese caso, pmlc se conectará inicialmente a la instancia de pmlogger (remota) especificada en host en lugar del host local. Si la conexión con la instancia de pmlogger especificada no se puede establecer, pmlc comenzará sin conexión. Estas opciones típicamente permiten que el mismo archivo de comandos de pmlc se dirija a múltiples instancias de pmlogger variando los argumentos de la línea de comandos. Tenga en cuenta que -P, -p puerto, pid y -h se usan solo al hacer una conexión inicial a una instancia de pmlogger. No se usan como valores predeterminados si se realizan conexiones posteriores interactivamente (ver el comando connect abajo).

Por defecto, pmlc muestra la hora según la zona horaria local del sistema donde se ejecuta pmlc. La opción -Z cambia la zona horaria a zona horaria en el formato de la variable de entorno TZ, como se describe en environ(7). La opción -z cambia la zona horaria a la zona horaria de la instancia de pmlogger de la que se está obteniendo información. Solo se puede especificar una de las opciones -z o -Z.

Si la entrada estándar proviene de una tty, pmlc es interactivo, con indicaciones. La bandera -i puede usarse para forzar el comportamiento interactivo y se usa típicamente junto con -e para mostrar toda la entrada del comando en la salida estándar.

COMANDOS

Los siguientes comandos pueden usarse:

mostrar [ registradores ] [ @host ]
Muestra las identidades de proceso de todas las instancias de pmlogger que se ejecutan en el host local (o host, si se especifica). El pid del pmlogger primario está entre paréntesis porque se puede referir a él como "primario" además de por su pid.
conectar pid [ @host ]


conectar primario [ @host ]
Conecta pmlc al proceso pmlogger especificado. Cualquier conexión existente a una instancia de pmlogger se cierra primero. Cada instancia de pmlogger aceptará como máximo una conexión a la vez, por lo que si la conexión se establece con éxito, su pmlc será el único que controle la instancia de pmlogger a la que está conectado.
nuevo volumen
Este comando solo funciona mientras hay una conexión establecida con una instancia de pmlogger. Le indica al pmlogger que cierre el volumen actual del archivo y abra un nuevo volumen. Los volúmenes cerrados pueden ser comprimidos y/o movidos a un sistema remoto, almacenamiento remoto o almacenamiento fuera de línea, por ejemplo, como parte de un procedimiento regular de gestión de archivos para controlar el tamaño de los archivos físicos en el sistema donde se ejecuta pmlogger.
estado
Este comando solo funciona mientras hay una conexión establecida con una instancia de pmlogger. Imprime información sobre el estado de la instancia de pmlogger y su archivo asociado.
zona-horaria local | registrador | "zona horaria"
Este comando establece la zona horaria utilizada cuando se imprimen las horas. local significa usar la zona horaria de la máquina donde se ejecuta pmlc. registrador significa usar la zona horaria de la máquina donde se ejecuta la instancia de pmlogger. Alternativamente, se puede proporcionar una zona horaria explícita entre comillas (consulte TZ en environ(7) para obtener detalles). La zona horaria predeterminada es local a menos que se hayan especificado las opciones -z o -Z en la línea de comandos.
vaciar
Este comando solo funciona mientras hay una conexión establecida con una instancia de pmlogger y solicita a la instancia de pmlogger que vacíe en disco todos los búferes asociados con el archivo actual. Para los que recuerdan las versiones antiguas, sync es un sinónimo de vaciar. En las versiones actuales de pmlogger(1) todas las escrituras no son cacheadas y están alineadas con los registros lógicos en los archivos externos, por lo que este comando no logra nada, pero se conserva por compatibilidad hacia atrás.
desconectar
Desconecta pmlc de la instancia de pmlogger actual, si la hay.
dormir retraso
Pausa pmlc durante retraso milisegundos. Esto puede ser útil en el uso de scripts de pmlc para permitir que la instancia de pmlogger actual avance en las solicitudes recientes antes de consultar el estado.
ayuda
Muestra un resumen de los comandos disponibles.

h y ? son sinónimos de ayuda.

salir
Sale de pmlc.

Los comandos restantes consultan y cambian el estado de registro de métricas e instancias. Solo funcionarán si pmlc tiene una conexión con una instancia de pmlogger. Las métricas se pueden especificar como nombres completamente calificados (por ejemplo, hinv.ncpu) o subárboles del PMNS (por ejemplo, hinv) que se expanden para incluir todas las métricas en el subárbol (por ejemplo, hinv.ncpu, hinv.cpuclock, etc.). Las listas de métricas se pueden especificar encerrándolas entre llaves con espacios o una coma entre métricas (por ejemplo, {hinv.ncpu hinv.ndisk}). Los subárboles de métricas se pueden incluir en dichas listas.

Cada especificación individual de métrica puede calificarse adicionalmente con una lista de instancias separada por espacios o comas entre corchetes (por ejemplo, kernel.all.load["1 minuto", "5 minutos"]). Se pueden usar nombres de instancias externos o identificadores numéricos internos de instancias o ambos en la misma lista (por ejemplo, sample.colour.[red,1,"blue"]). Si se aplica una calificación de instancia a un subárbol del PMNS, todas las métricas del subárbol deben tener el mismo dominio de instancia. Las calificaciones de instancia no se pueden aplicar a listas completas de métricas, pero pueden aparecer dentro de dichas listas.

Si no se especifican instancias para una métrica, se utilizan todas las instancias. Todas las instancias significa todas las instancias disponibles en el momento en que la instancia de pmlogger en cuestión recupera las métricas para registrarlas. Si un dominio de instancia cambia con el tiempo, esto no es lo mismo que el conjunto de instancias mostradas por pmlc, que solo puede mostrar las instancias disponibles actualmente. Para evitar errores involuntarios, solo las instancias que están actualmente disponibles para pmlc pueden aparecer en las especificaciones de instancia.

consultar listamétricas
Se muestra el estado de registro actual de cada métrica (e instancias, donde sea aplicable) en listamétricas. Esto incluye el estado de registro (por ejemplo, activado, quizás, desactivado) y el intervalo de registro para cada métrica (y instancia) solicitada. Las siguientes abreviaturas relativas a métricas (e instancias) pueden aparecer en la salida: adv, consultivo; mand, obligatorio; nl, no registrado (no en el archivo); na, en el archivo pero no actualmente disponible.

Las siguientes opciones de registro pueden seguir a una métrica:

on
Registra la métrica (y todas sus instancias, si las tiene).
off
No registra la métrica.
adv
Registra la métrica solo si la está registrando otra instancia de pmlogger en el mismo host.
force
Similar a on, pero se usa para asegurarte de que un pmlogger esté registrando algo que podría haber sido desactivado por un usuario con privilegios menores. Solo el usuario root puede usar esta opción.
interval valor
Establece el intervalo de muestreo para la métrica especificada en valor segundos. El valor predeterminado es de 60 segundos.

La opción mandatory (o mand) se puede usar para dar el valor predeterminado de on para una métrica dada. La opción advisory (o adv) es la configuración predeterminada si no se especifica nada.

Por ejemplo, para asegurarte de que se registra el número de CPU, pero solo si otro pmlogger también lo está registrando, y para establecer el intervalo de registro de las cargas de disco en 120 segundos, usaría:

pmlc> query hinv.ncpu
pmlc> adv hinv.ncpu
pmlc> on disk.all.read active
pmlc> interval 120 disk.all.read active

Las opciones on, off, adv y force pueden aparecer en cualquier orden en una línea de comandos. Cada una de estas opciones se aplica a todas las métricas especificadas en la línea de comandos que la sigue hasta que se encuentra otra de estas opciones o un comando.

Si se usa la opción -z o -Z al inicio, entonces solo se pueden consultar las métricas que se sabe que existen en el PMNS y que son de interés para el sistema. Las métricas que se saben que existen se pueden consultar más fácilmente si se utilizan las opciones -p o -P para conectarse a una instancia de pmlogger.

benchmark metriclist
Esto se comporta de forma idéntica al comando query, excepto que las métricas y las instancias solicitadas se convierten en "obligatorias" en lugar de "consultivas".
mandatory metriclist
Esto se comporta de forma idéntica al comando query, excepto que las métricas y las instancias solicitadas se convierten en "obligatorias" en lugar de "consultivas".
off metriclist
Esto se comporta de forma idéntica al comando query, excepto que las métricas y las instancias solicitadas se convierten en "no registradas" (desactivadas).
indom metric
Muestra los dominios de instancia disponibles para la métrica especificada en metric.
instances metric
Muestra las instancias disponibles para la métrica especificada en metric.

Nota: si se desea una lista de todas las instancias de una métrica, debe usar `pmlc` para conectar a una instancia de pmlogger en ejecución y luego usar el comando `indom` seguido del nombre de la métrica. Por ejemplo: `pmlc`> `connect 12345` `pmlc`> `indom disk.all.read`

OPTIONS

-D depuración
Establece el nivel de depuración de pmlc a depuración. Los valores positivos de depuración activan más mensajes de depuración. El valor 0 desactiva todos los mensajes de depuración.
-e
Establece la salida de los comandos emitidos en la salida estándar. Esto puede ser útil cuando se usa pmlc en un script, pero es más comúnmente usado en conjunto con -i.
-h host
Especifica un host remoto en el que se ejecuta el pmlogger. Esta opción solo tiene sentido cuando se usa con -p o -P.
-i
Fuerza el modo interactivo. Esto es útil cuando se ejecuta pmlc desde un script y se desea que espere las entradas del usuario.
-n archivo pmns
Carga el PMNS desde el archivo especificado en archivo pmns en lugar del PMNS predeterminado.
-p puerto
Especifica el número de puerto de TCP/IP en el que se está ejecutando el pmlogger. Esto es útil si el pmlogger no se está ejecutando en el puerto predeterminado.
-P
Intenta conectarse al pmlogger primario en el host local.
-z
Utiliza la zona horaria del pmlogger.
-Z zona horaria
Utiliza la zona horaria especificada. La zona horaria debe tener el formato de la variable de entorno TZ.
?
Imprime un mensaje de uso y sale.

EjEMPLOS

Para obtener una lista de todos los pmloggers activos en el host local y su estado actual:

$ pmlc show

Para conectarse a un pmlogger con PID 12345 y luego mostrar el estado de todas las métricas de la CPU:

$ pmlc connect 12345
pmlc> query cpu

Para asegurarse de que se registra la métrica de uso de memoria física y establecer su intervalo de registro en 30 segundos:

pmlc> mandatory pmNed/physmem.bytes.total
pmlc> interval 30 pmNed/physmem.bytes.total

Para desconectarse de un pmlogger y salir de pmlc:

pmlc> disconnect
pmlc> quit

COMMAND SYNTAX

The pmlc utility supports the following commands:

add host
Add a pmlogger(1) instance running on host to the list of known logger instances. Initially, the connections to these instances are not established. See also connect. The host may be specified as a hostname or an IP address.
connect logger
Establish a connection to the specified logger instance. The instance is identified by the hostname of the machine on which it is running, possibly followed by : and the port number if it is not the primary port (see -p option). If logger is omitted, then pmlc attempts to connect to all known logger instances. See also add.
disconnect [ logger ]
Disconnect from the specified logger instance. If logger is omitted, then pmlc disconnects from all connected logger instances. See also connect.
log control metriclist
Control logging for a list of metrics. See the description of the control argument below.
query logger
Check the status of the specified logger instance. If logger is omitted, then pmlc queries all connected logger instances. The status may include information about any volumes, trace files, and the current logging state for all metrics and instances.
show [ loggers ]
Display a list of known logger instances. If the optional argument loggers is supplied, then pmlc will query each known logger instance and display its current status.
timeout seconds
Set the connection timeout to seconds. If seconds is 0, then pmlc will block indefinitely. The default is 10 seconds.

The metriclist argument is a comma-separated list of metric names. A metric name may be followed by an instance specifier. The instance specifier may be a specific instance name, a numeric instance identifier, or a wildcard pattern. If no instance specifier is given, then the metric name applies to all instances of that metric. Metrics and instances are identified by Performance Metrics Name Space (PMNS) names. Metric names may be prefixed with the name of a Performance Metrics Domain (PMD) to disambiguate. Metric names and instance names are case-insensitive. Instance names are available from its Performance Metrics Domain Agent (PMDA). Where appropriate, an instance name will appear last on a line preceded by its numeric internal instance identifier.

[ log ] mandatory on interval metriclist
This form of the log command turns on logging for the metrics (and any instances) in metriclist. interval specifies how often the specified metrics/instances should be logged. once indicates that the metrics/instances should appear at most once in the archive. More often one would use the optional keyword every followed by a positive number and one of millisecond (or msec), second (or sec), minute (or min), hour or their plurals.

Note that the keyword default which may be used for the default interval in a pmlogger(1) configuration file cannot be used in pmlc.

Internal limitations require the interval to be less than (approximately) 74 hours. An interval value of zero is a synonym for once.

[ log ] mandatory off metriclist
This tells the pmlogger instance not to archive any of the metrics/instances in metriclist.
[ log ] mandatory maybe metriclist
This tells the pmlogger instance to honor any subsequent advisory logging requests for the metrics/instances in metriclist. If the current logging state of the metrics/instances is mandatory (either on or off) the new state will be set to maybe (effectively advisory off). If the current state of the metrics/instances is already advisory (either on or off) the state(s) for the metrics/instances will remain as they are.
[ log ] advisory on interval metriclist


[ log ] advisory off metriclist
Advisory logging is only applicable if the last logging state specified for a metric/instance was "mandatory maybe" (which permits subsequent advisory logging control) or if the logging state is already advisory. These two statements turn advisory logging on or off (respectively) for the specified metrics/instances.

The interpretation for interval is as above for the mandatory case.

There is no continuation character required for commands that span lines.

The word at may be used interchangeably with @.

A request to archive all instances of a metric will supersede any prior request to log either all or specific instances of a metric (if the request specifies a permissible transition in the logging state). A request to archive specific instances of a metric when all instances of a metric are already being logged is refused by pmlogger.

OPTIONS

The available command line options are:

-e, --echo
Echo all command input on standard output.
-h host, --host=host
Connect pmlogger on host, rather than on the default localhost.
-i, --interactive
Force interactive behavior.
-n pmnsfile, --namespace=pmnsfile
Load an alternative Performance Metrics Name Space (PMNS(5)) from the file pmnsfile.
-p port, --port=port
Connect to the primary pmlogger on TCP/IP port port.
-P, --primary
Connect to the primary pmlogger.
-z, --logzone
Use local time of the pmlogger as the reporting timezone.
-Z timezone, --timezone=timezone
Use timezone for the date and time. Timezone is in the format of the environment variable TZ as described in environ(7).
-?, --help
Display usage message and exit.

ACCESS CONTROL

pmlc may have restricted access to and control over pmlogger(1) processes.

If a pmlogger(1) is unable to export its control information to the local pmcd(1), then that pmlogger(1) cannot cannot be connected to nor controlled by pmlc. In practice, this means the pmlogger(1) process has to be owned by the user ``pcp'' and/or the group ``pcp''. If pmlogger(1) is running on the host ``foo'' then use ``pminfo -f -h foo pmcd.pmlogger'' to verify that the pmlogger(1) of interest is known to pmcd(1), alternatively pmlogger(1) instances that are not reported from the pmlc show loggers @foo command are not known to pmcd(1) on the host ``foo''.

If pmlogger(1) is launched with a configuration file that contains an [access] section, then pmlc will be unable to connect to that pmlogger(1) unless the access controls allow some access from the host where pmlc is being run. Minimally this requires the enquire access to be permitted in the pmlogger(1) access control section.

If pmlc is able to connect to the pmlogger(1) of interest, then the following table summarizes the permissions needed to perform different pmlc commands:

pmlc command Required pmlogger access
show loggers Any
connect Any of enquire, advisory or mandatory
status Any of enquire, advisory or mandatory
query ... Any of enquire, advisory or mandatory
disconnect Any
log advisory ... advisory
log mandatory ... mandatory
new volume mandatory

CAVEATS

If all instances of a metric are being logged and a request is made to log specific instances of the metric with the same state and frequency, the request may appear to succeed, even though pmlogger has refused the request. This is not normally a problem, as the required information will still be placed into the archive by pmlogger.

However in the case where the metric is to be logged once, the outcome is not what might be expected. When pmlogger receives a request to archive a metric once, it places the current value(s) of the metric into the archive as soon as it can, regardless of whether the metric is already in the archive. This may be used to force values into the archive. When a request to archive specific instances of a metric arrives and is refused because all instances of the metric are already being logged, pmlogger does not place values for the instances requested into the archive. It returns the current logging state for each instance requested to pmlc. The requested and returned states are identical, so pmlc doesn't raise an error as it should.

To ensure that only certain instances of a metric are being logged, one should always turn off logging for all instances of the metric prior to turning on logging for the specific instances required.

DIAGNOSTICS

Most error or warning messages are self-explanatory. A message of the form

Warning: unable to change logging state for...
followed by a list of metrics (and possibly instances) indicates that pmlogger refused the request for the metrics (and instances) that appear. Any metrics (and instances) that were specified but do not appear in the message have had their logging state updated successfully (no news is good news). Usually this warning results from requesting advisory logging when a mandatory control is already in place, or requesting logging for specific instances when all instances are already being logged.

ENVIRONMENT

If the PMLOGGER_REQUEST_TIMEOUT environment variable is not set or set to 0 (zero), then pmlc will block until a connection is established with pmlogger(1) on the requested port. If PMLOGGER_REQUEST_TIMEOUT is set to a value greater than zero, then pmlc will fail with an error after that many seconds if a connection isn't established. This may be used by administrative scripts such as pmlogger_daily(1) to poll pmlogger when is starting up until it is ready and listening on it's control port.

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

DEBUGGING OPTIONS

The pmlc utility uses the standard PCP debugging facilities. The DEBUG environment variable may be used to control the verbosity of diagnostic messages generated by PCP tools.
