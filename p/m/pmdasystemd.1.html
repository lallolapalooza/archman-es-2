PMDASYSTEMD(1) Manual de comandos generales PMDASYSTEMD(1)

NOMBRE

pmdasystemd - agente de dominio de métricas de rendimiento de systemd (PMDA)

SINOPSIS

$PCP_PMDAS_DIR/systemd/pmdasystemd [-f] [-D depuración] [-d dominio] [-l archivo_log] [-m memoria] [-s intervalo] [-U nombre_usuario]

DESCRIPCIÓN

pmdasystemd es un agente de dominio de métricas de rendimiento (PMDA) para monitorizar archivos de log de systemd. Puede considerarse análogo a la opción -f de journalctl(1) y convierte cada nueva línea de log en un evento de rendimiento, adecuado para ser consumido por herramientas cliente de PMAPI(3) como pmevent(1).

El PMDA de systemd exporta métricas de tipo evento que reflejan registros de eventos con marca de tiempo para mensajes registrados en los logs del sistema, así como métricas más ortodoxas de tipo muestra, como recuentos de mensajes y valores de tamaño de rendimiento.

A continuación se describe brevemente las opciones de línea de comandos de pmdasystemd:

-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y consistente. Es decir, dominio debe ser diferente para cada PMDA en el mismo host, y se debe usar el mismo número de dominio para el mismo PMDA en todos los hosts.
-f
Deshabilita el filtrado de registros por uid/gid. Por defecto, se usarán las credenciales de usuario y grupo para filtrar los registros de log devueltos a la herramienta cliente, evitando la exposición de información a usuarios arbitrarios. Esta opción deshabilita eso, así que úsela solo con extrema precaución.
-l
Ubicación del archivo de log. Por defecto, se escribe un archivo de log llamado systemd.log en el directorio actual de pmcd(1) cuando se inicia pmdasystemd, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de log no se puede crear o no es escribible, la salida se escribe en el error estándar en su lugar.
-m
Limita la memoria física utilizada por el PMDA para almacenar en búfer los registros de eventos a tamañomax bytes. A medida que los eventos de log llegan al PMDA, deben almacenarse en búfer hasta que las herramientas cliente individuales soliciten el siguiente lote desde su lote anterior de eventos. El máximo por defecto es de 2 megabytes.
-s
Establece el intervalo de sondeo para detectar líneas de log recién llegadas. Refleja la misma opción del comando tail(1).
-U
Cuenta de usuario bajo la cual ejecutar el agente. El valor por defecto es la cuenta de usuario "adm".

INSTALACIÓN

Si desea acceder a los nombres, textos de ayuda y valores de las métricas de rendimiento de systemd, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/systemd
# ./Install

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/systemd
# ./Remove

pmdasystemd es lanzado por pmcd(1) y nunca debe ser ejecutado directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o se elimina.

ARCHIVOS

$PCP_PMCDCONF_PATH
opciones de línea de comandos utilizadas para lanzar pmdasystemd
$PCP_PMDAS_DIR/systemd/help
archivo de texto de ayuda por defecto para las métricas de systemd
$PCP_PMDAS_DIR/systemd/Install
script de instalación para el agente pmdasystemd
$PCP_PMDAS_DIR/systemd/Remove
script para deshacer la instalación del agente pmdasystemd
$PCP_LOG_DIR/pmcd/systemd.log
archivo de log por defecto para mensajes de error y otra información de pmdasystemd

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información a veces es críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. depuración es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmdasystemd son las siguientes:

Opción Descripción
appl0 filtrado de registros del journal, control de acceso, interacciones con pmcd(1)
appl2 seguimiento de llamadas a select(2)
