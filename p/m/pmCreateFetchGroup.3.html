DESCRIPCIÓN

Las funciones de fetchgroup implementan un mecanismo basado en registro para obtener grupos de métricas de rendimiento, incluyendo la automatización para conversiones generales de unidades, tasas y tipos, así como codificaciones convenientes de instancias y valores. Constituyen una alternativa potente y compacta a la secuencia clásica de la Interfaz de Programación de Aplicaciones de Métricas de Rendimiento (PMAPI(3)) de funciones separadas de búsqueda, verificación, obtención, iteración, extracción y conversión.

La idea general consiste en dos etapas. En la etapa de configuración, la aplicación identifica las métricas de interés por nombre y con las conversiones deseadas, y registra una ubicación de salida única pmAtomValue donde el sistema fetchgroup depositará posteriormente el resultado. También es posible identificar una métrica con un dominio de instancia y registrar un vector único de objetos pmAtomValue para ellas. En la etapa de operación, una simple función pmFetchGroup obtiene, decodifica, convierte y almacena todas las métricas en sus destinos, donde la aplicación puede leerlas directamente. Esta función puede ser llamada repetidamente, y cada vez se almacenarán nuevos valores pmAtomValue en los mismos destinos. Se pueden solicitar conversiones de tasa entre muestras consecutivas.

Cada fetchgroup se asocia con un contexto PMAPI privado, por lo que puede manipular perfiles de instancia y otros estados similares sin interrumpir otros contextos. El perfil de instancia se manipula para optimizar las búsquedas de elementos individuales, incluso si algunos son métricas derivadas. Este contexto PMAPI privado pertenece al fetchgroup, se utiliza para todas sus operaciones internas y será destruido.

Se pueden usar múltiples fetchgroups de forma concurrente e independiente. Se utiliza un tipo opaco pmFG para identificar un fetchgroup, que se pasa a todas las llamadas de función relacionadas.

Creación de un fetchgroup

int pmCreateFetchGroup(pmFG *ptr,
int type, const char *name);

Esta función crea un nuevo fetchgroup, asociado con un nuevo contexto PMAPI. Los parámetros type y name se transmiten a pmNewContext(3) para la creación del contexto. El identificador del fetchgroup se devuelve en caso de éxito a través del puntero ptr. Este objeto se utiliza posteriormente como parámetro para todas las demás funciones de fetchgroup. El contexto PMAPI privado se puede acceder con pmGetFetchGroupContext, si es necesario.

El código de retorno normal de la función es cero, y ptr se establece. Esta función puede fallar en caso de errores de pmNewContext o de asignación de memoria. Estos se indican con un código de retorno negativo y un valor ptr borrado.

Obtención del contexto PMAPI privado

int pmGetFetchGroupContext(pmFG pmfg);

Esta función devuelve el contexto PMAPI privado utilizado por el fetchgroup dado. Se puede utilizar de forma segura para ajustar algunos parámetros de configuración del contexto, como a través de pmSetMode(3), antes de que comiencen la extensión y la obtención del fetchgroup.

Sin embargo, la *mutación* de este contexto por funciones PMAPI después de este momento puede interrumpir la funcionalidad del fetchgroup. Por ejemplo, una llamada a pmSetMode podría invalidar un paso de tiempo de conversión de tasa.

El código de retorno normal de la función es el número de contexto.

Extensión de un fetchgroup con una instancia de métrica de interés

int pmExtendFetchGroup_item(pmFG pmfg,
const char *metric, const char *instance, const char *scale, pmAtomValue *out_value, int out_type, int *out_sts);

Esta función registra el interés en una única métrica y una instancia opcional. El nombre de la métrica se proporciona en el parámetro obligatorio metric, que se verifica inmediatamente a través de pmLookupName(3) y otras llamadas. Si y solo si la métrica tiene un dominio de instancia, la instancia específica de interés puede ser nombrada por el parámetro instance, que se verifica inmediatamente a través de pmNameInDom(3); de lo contrario, pase NULL. Si el contexto fetchgroup es un conjunto de archivos, es posible que el par métrica / instancia aún no esté definido en el origen de tiempo actual. Por lo tanto, esta función puede intentar buscar hasta el *final* del conjunto actual de archivos *temporalmente* para reintentar la búsqueda de métrica / instancia.

El parámetro opcional scale especifica las conversiones de unidad/escala/tasa deseadas para el valor de la métrica. Puede tomar los siguientes valores:

NULL
Sin conversión de unidad/escala. Si la métrica tiene semántica PM_SEM_COUNTER, realiza la conversión de tasa.
rate
Realiza la conversión de tasa independientemente de la semántica, y sin conversión de unidad/escala.
instant
No realiza conversión de tasa independientemente de la semántica, y sin conversión de unidad/escala.
EXPRESIÓN
Realiza la conversión de unidad/escala/tasa según lo especificado por la EXPRESIÓN, que es analizada por pmParseUnitsStr(3). Esto puede ser útil para asegurar una escala canónica para el valor de la métrica resultante, independiente de la versión o configuración de PCP. La dimensionalidad debe coincidir con la métrica, excepto si se solicita la conversión de tasa, en cuyo caso la dimensión de tiempo debe ser una menos que la dimensión de tiempo de la métrica. Tenga en cuenta que el tipo de conversión de tasa realizado aquí coincide con la función *rate(x)* en las expresiones de métricas derivadas, en que se calcula como la diferencia ingenua entre los valores anteriores y actuales de una métrica, dividida por el tiempo transcurrido. Por ejemplo, si un contador se desborda, o un valor que no es un contador disminuye, se puede calcular una tasa *negativa*.

El parámetro opcional pero habitual out_value especifica el pmAtomValue donde el resultado convertido se almacenará posteriormente.

DESCRIPTION

The fetchgroup API allows applications to efficiently fetch a collection of performance metrics, possibly from different sources and with different attributes, in a single call to the Performance Co-Pilot (PCP) collector daemon, pmcd(1).

A fetchgroup is created using pmCreateFetchGroup. The ctx_type and source arguments are the same as for pmUseContext(3).

Subsequent calls to the pmExtendFetchGroup_* functions add metrics to the fetchgroup. The arguments name, units, interval and type are used to specify the metric name, requested units, requested interval (e.g. "1 minute"), and desired result type, respectively. The type argument should be one of the PM_TYPE_* constants defined in <pcp/pmapi.h>. If units or interval are specified as NULL, then the default units or interval will be used.

pmExtendFetchGroup_item is used to add a single metric value to the fetchgroup. The value will be returned via the pval argument, which must point to a valid pmAtomValue structure. If psts is non-NULL, it points to an integer that will be updated with the status code for this specific metric/instance. A value of 0 indicates success.

pmExtendFetchGroup_indom is used to add all instances of a metric that has an instance domain. The pinstnames argument is used to return the instance names (strings), pval to return the metric values, psts to return status codes for each instance, maxinst is the maximum number of instances that can be stored, and pnuminst is updated with the actual number of instances fetched.

pmExtendFetchGroup_timeval is used to specify a timestamp that will be returned by pmFetchGroup. The timestamp is updated on each call to pmFetchGroup.

pmExtendFetchGroup_timestamp is used to specify a timestamp that will be returned by pmFetchGroup. The timestamp is updated on each call to pmFetchGroup. The actual type of the timestamp is not specified and it is recommended to use pmExtendFetchGroup_timeval instead.

Once all metrics have been added to the fetchgroup, the pmFetchGroup function is called to fetch all the requested metric values. All the pmAtomValue and status variables previously registered with the pmExtendFetchGroup_* functions will be updated. The return value of pmFetchGroup is a status code for the overall operation.

A return value of 0 from pmFetchGroup indicates that all metrics were fetched successfully. If any metric encountered an error during fetching, the return value will be negative, and the individual status codes (if provided) should be checked for details.

Clearing a fetchgroup

int pmClearFetchGroup(pmFG pmfg);

When the current fetch state of a fetchgroup is no longer needed, it may be explicitly reset with this function. It releases any dynamically stored state but keeps the private PMAPI context intact for subsequent use (i.e. no change to the context is made at all and the context remains at the current fetch offset). It frees any pointers such as indom instance names or strings that may have been stored in output variables.

Destroying a fetchgroup

int pmDestroyFetchGroup(pmFG pmfg);

When the fetchgroup is no longer needed, it may be explicitly freed with this function. It releases any dynamically stored state, as well as the private PMAPI context. It clears frees any pointers such as indom instance names or strings that may have been stored in output variables.

EXAMPLE

The following program demonstrates fetchgroup usage. Run it with different $PCP_DISK_UNITS environment variables to see different unit/rate conversion in effect.

#include <pcp/pmapi.h>
#include <stdio.h>
#define pcpassert(sts) \
    while (sts<0) { fprintf(stderr, "%s\n", pmErrStr(sts)); exit(42); }
int main()
{
    pmFG fg;
    pmAtomValue v, v2;
    enum { v3_maxnum = 100 };
    pmAtomValue v3_values[v3_maxnum];
    char *v3_names[v3_maxnum];
    int v3_stss[v3_maxnum];
    unsigned int v3_num;
    int sts, i;
    char *diskunits = getenv("PCP_DISK_UNITS");
    struct timeval t;
    sts = pmCreateFetchGroup(&fg, PM_CONTEXT_HOST, "local:");
    pcpassert(sts);
    sts = pmExtendFetchGroup_item(fg, "kernel.all.load", "1 minute",
                                  NULL, &v, PM_TYPE_FLOAT, NULL);
    pcpassert(sts);
    sts = pmExtendFetchGroup_item(fg, "kernel.all.idletime", NULL,
                                  "hour", &v2, PM_TYPE_DOUBLE, NULL);
    pcpassert(sts);
    sts = pmExtendFetchGroup_indom(fg, "disk.dev.total", diskunits,
                                   NULL, v3_names,
                                   v3_values, PM_TYPE_STRING,
                                   v3_stss, v3_maxnum, &v3_num, NULL);
    pcpassert(sts);
    sts = pmExtendFetchGroup_timeval(fg, &t);
    pcpassert(sts);
    for (i=0; i < 10; i++) {
        unsigned int j;
        char stamp[28];
        sts = pmFetchGroup(fg);
        pcpassert(sts);
        printf("%s", pmCtime(&t.tv_sec, stamp));
        printf("1-minute load: %f; idletime: %f h\n", v.f, v2.d);
        for (j=0; j < v3_num; j++) {
            if (v3_stss[j] == 0)
                 printf("disk %s i/o operations (%s): %s\n",
                        v3_names[j] ? v3_names[j] : "?",
                        diskunits ? diskunits : "-",
                        v3_values[j].cp);
        }
        sleep(1);
    }
    sts = pmDestroyFetchGroup(fg);
    pcpassert(sts);
    return 0;
}

UNUSUAL SITUATIONS

The fetchgroup API supports only the numeric, string and event metric types. Aggregates are rejected during pmExtendFetchGroup_*.

Any strings supplied by the fetchgroup API to the application are "owned" by the API. The application should consider them read-only, so it should not modify them nor free them.

Error codes are always negative integers, whether returned from fetchgroup functions as return value, or stored in out_sts type variables. Normal result codes are always zero.

Because of the unique ways in which extracted data is shared between the application and a fetchgroup, the functions in this API are not protected by the multi-threading mutexes conventional in other parts of PMAPI. Specifically, for any given pmFG, it is not safe to concurrently call two or more fetchgroup API functions, nor to traverse the registered output variables while calling one of the functions. Instead, the calling application must ensure that only one thread at a time uses these calls and the registered output variables. On the other hand, concurrency between different pmFG instances is unrestricted, because they share no global data.

Any pointers passed to a successful pmFetchGroupExtent_* call must stay valid throughout the lifetime of the fetchgroup, since future pmFetchGroup calls may write into them.

DIAGNOSTICS

The fetchgroup API offers several options for collecting diagnostics. Negative integer error codes may be returned from each function for serious conditions.

In addition, each output pmAtomValue may have a corresponding integer variable, where pmFetchGroup can store per-metric per-instance error codes.

As an alternative, per-metric per-instance error conditions are also signalled by setting the corresponding pmAtomValue to a sentinel value. If unambiguous and precise error detection is not required, this may be sufficient. The sentinel value is negative one for all integers (including unsigned integers - i.e. all bits are set), NaN for floating point types, a NULL pointer for strings, and 0.0s for the timestamp. The fetchgroup API guarantees that once an output pmAtomValue is registered (during a successful pmExtendFetchGroup_* call), it will be cleared to the sentinel value or to a valid converted metric value, from the time of registration until the pmDestroyFetchGroup call.

COMPATIBILITY

Prior to PCP 7.0 the pmExtendFetchGroup_timestamp was an alias for pmExtendFetchGroup_timeval. To support PMAPI transition, the old interface and semantics can be used if applications are recompiled with -DPMAPI_VERSION=2.

pmExtendFetchGroup_timestamp although this is now deprecated and compile-time support will be removed in a future release.
