PMDAMMV(1) Manual de Comandos Generales PMDAMMV(1)

NOMBRE

pmdammv - agente de dominio de métricas de rendimiento (PMDA) de valores mapeados en memoria

SINOPSIS

$PCP_PMDAS_DIR/mmv/pmdammv [-D depuración] [-d dominio] [-l archivo_log] [-U nombre_usuario]

DESCRIPCIÓN

pmdammv es un Agente de Dominio de Métricas de Rendimiento (PMDA) que exporta métricas de rendimiento a nivel de aplicación utilizando archivos mapeados en memoria. Ofrece una instalación de métricas de extremadamente bajo overhead, muy adecuada para aplicaciones de larga duración y críticas, donde es deseable tener información de métricas de rendimiento y disponibilidad habilitada permanentemente.

El PMDA mmv exporta la instrumentación que se ha agregado a una aplicación usando las APIs de MMV (consulte mmv_stats_init(3) y mmv(5) para más detalles). Estas APIs se pueden llamar desde varios lenguajes, incluyendo C, C++, Perl, Python, Java (a través de la biblioteca separada de clase "Parfait") y GoLang (a través de la biblioteca separada "Speed").

A continuación, se presenta una breve descripción de las opciones de línea de comandos de pmdammv:

-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y consistente. Es decir, dominio debe ser diferente para cada PMDA en un host y se debe usar el mismo número de dominio para el mismo PMDA en todos los hosts.
-l
Ubicación del archivo de registro. Por defecto, se escribe un archivo de registro llamado mmv.log en el directorio actual de pmcd(1) cuando se inicia pmdammv, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de registro no se puede crear o no es escribible, la salida se redirige al error estándar.
-U
Cuenta de usuario bajo la cual se ejecutará el agente. Por defecto, es la cuenta no privilegiada "pcp" en las versiones actuales de PCP, pero en versiones anteriores se usaba la cuenta de superusuario ("root") por defecto.

INSTALACIÓN

Primero, se debe elegir y establecer un modelo de seguridad para la comunicación entre procesos entre las aplicaciones instrumentadas y pmdammv (que se ejecuta como una biblioteca compartida dentro de pmcd).

Esta comunicación se produce a través de archivos mapeados en memoria en una ubicación conocida tanto por pmdammv como por las aplicaciones instrumentadas. Esa ubicación es $PCP_TMP_DIR/mmv, aunque a menudo está oculta detrás de APIs de aplicaciones como "Parfait" y mmv_stats_init(3). Los permisos establecidos en este directorio indican el modelo de seguridad en uso.

El método más seguro es utilizar un grupo no privilegiado existente que sea compartido por las aplicaciones instrumentadas, pmcd y pmdammv, como el grupo "pcp".

# . /etc/pcp.env
# mkdir -m 775 $PCP_TMP_DIR/mmv
# chgrp pcp $PCP_TMP_DIR/mmv

Dado que este método requiere que las aplicaciones instrumentadas usen este grupo no predeterminado (ver newgrp(1) y setgid(2)), una alternativa común implica el uso de un directorio $PCP_TMP_DIR/mmv escribible por todos con el bit pegajoso activado (similar a /tmp y /var/tmp, por ejemplo).

Esto permite que cualquier aplicación, ejecutándose bajo cualquier cuenta de usuario, se comunique con el PMDA (que se ejecuta bajo la cuenta "pcp" por defecto). Esto puede no ser deseable para todos los entornos y se deben considerar las implicaciones de seguridad de cualquier configuración de directorio de este tipo (clases similares de problemas existen como los que afectan a los directorios temporales del sistema).

pmdammv está habilitado por defecto en todas las instalaciones modernas de PCP, y por lo tanto, los nombres, texto de ayuda y valores para las métricas de rendimiento de mmv están disponibles sin el proceso habitual de Instalación de PMDA ./Install.

Si el directorio $PCP_TMP_DIR/mmv no existe, el script ./Install se puede usar para crear un directorio escribible por todos con el bit pegajoso activado para la comunicación. Esto es para compatibilidad hacia atrás, así como para facilitar su uso; para usar este mecanismo, haga lo siguiente como root:

# rmdir $PCP_TMP_DIR/mmv
# cd $PCP_PMDAS_DIR/mmv
# ./Install

Este proceso de instalación no sobrescribirá ningún directorio $PCP_TMP_DIR/mmv existente.

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/mmv
# ./Remove

pmdammv es lanzado por pmcd y nunca debe ejecutarse directamente. Los scripts Install y Remove notifican a pmcd cuando el agente se instala o se elimina.

ARCHIVOS

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información a veces es críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. depuración es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmdammv son las siguientes:

Opción Descripción
appl0 diagnósticos detallados

pmdammv(1)

NAME

pmdammv - A PostgreSQL utility to convert binary dump files to text format.

SYNOPSIS

pmdammv [OPTION...] [INFILE [OUTFILE]]

DESCRIPTION

pmdammv reads a PostgreSQL archive dump in the custom archive format created by pg_dump (when used with the -Fc option) and outputs the content in plain text SQL format.

If INFILE is not specified, standard input is used. If OUTFILE is not specified, standard output is used.

OPTIONS

pmdammv accepts the following command-line options. See pg_restore(1) for more details about them, as pmdammv is just a wrapper around pg_restore in text mode.

  • -?, --help: Show help, and exit.
  • -a, --data-only: Dump only the data, not the schema.
  • -b, --blobs: Dump large objects.
  • -c, --clean: Output commands to clean (drop) database objects before creating them.
  • -C, --create: Output commands to create the database itself before restoring.
  • -d, --dbname=DBNAME: Connect to the database with the specified name.
  • -e, --encoding=ENCODING: Dump the data in the specified encoding.
  • -f, --file=FILENAME: Write all SQL commands to the specified file.
  • -F, --format=FORMAT: Specify the format of the archive. Alternative formats are c, d, t, p.
  • -j, --jobs=NUM: Run mais restores in parallel using NUM jobs at a time.
  • -n, --schema=SCHEMA: Dump only the schema, or only data from schemas that match Schema.
  • -N, --exclude-schema=SCHEMA: Do not dump schemas that match Schema.
  • -O, --no-owner: Do not write commands to set ownership of objects to match the original database.
  • -P, --disable-triggers: Dump commands to disable triggers on table data.
  • -R, --no-privileges, --no-acl: Do not dump access privileges (grant/revoke commands).
  • -s, --schema-only: Dump only the schema, not data.
  • -S, --superuser=USERNAME: Specify the superuser user name to use.
  • -t, --table=TABLE: Dump only tables that match TABLE.
  • -T, --exclude-table=TABLE: Do not dump tables that match TABLE.
  • -v, --verbose: Specify verbose mode.
  • -V, --version: Print pmdammv version information, and exit.
  • --disable-quotes: Disable quoting of identifiers.
  • --enable-quotes: Enable quoting of identifiers.
  • --exit-on-error: Exit if an error is encountered.
  • --force-overwrite: Overwrite the output file if it exists.
  • --no-comments: Do not write comments into the dump.
  • --no-publications: Do not dump publications.
  • --no-security-labels: Do not dump security labels.
  • --no-subscriptions: Do not dump subscriptions.
  • --no-tablespaces: Do not dump tablespace information.
  • --no-unlogged-table-data: Do not dump data for unlogged tables.
  • --on-error-stop: Stop processing when an error is encountered.
  • --section=SECTION: Only restore the named section, or sections (e.g. ‘pre-data’, ‘data’, ‘post-data’).
  • --use-list=FILENAME: Dump only the items in FILENAME, and directories named from the command line.

ENVIRONMENT

This utility, like most PostgreSQL utilities, uses environment variables of the libpq connection library. The environment variables `PGHOST`, `PGPORT`, `PGDATABASE` and `PGPASSWORD` can be set to control the connection parameters. For more details, refer to the documentation of libpq environment variables.

DEBUGGING OPTIONS

pmdammv supports the following debugging options:

  • -d, --debug=LEVEL: Set the debugging level.
  • --debug-directory=DIR: Set the directory for debugging files.
  • --debug-file=FILE: Set the file for debugging output.
