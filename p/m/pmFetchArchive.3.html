PMFETCHARCHIVE(3) Manual de funciones de biblioteca PMFETCHARCHIVE(3)

NOMBRE

pmFetchArchive, - obtener valores de métricas de rendimiento directamente de los archivos

SINOPSIS C

#include <pcp/pmapi.h>

int pmFetchArchive(pmResult **result);

cc ... -lpcp

DESCRIPCIÓN

La API pmFetchArchive es una variante de la interfaz pmFetch(3) que solo puede usarse cuando el contexto actual de la Interfaz de Programación de Aplicaciones de Métricas de Rendimiento (PMAPI) está asociado con un conjunto de archivos.

El result se instancia con todas las métricas (e instancias) del siguiente registro de archivo, por lo tanto, no hay una noción de una lista de métricas deseadas, y el perfil de instancia del contexto PMAPI se ignora.

pmFetchArchive puede devolver un result en el que numpmid es cero. Este es un registro de <marca> que indica una discontinuidad temporal en la serie temporal de métricas de rendimiento. Esto puede suceder en el límite entre archivos en un conjunto o si el archivo asociado con el contexto PMAPI actual se creó usando pmlogextract(1) para concatenar dos o más archivos PCP, y el registro de <marca> marca un punto en el tiempo entre el final de un archivo de entrada y el inicio del siguiente archivo de entrada.

Se espera que pmFetchArchive se use para crear utilidades que escaneen conjuntos de archivos, mientras que el acceso más común a los archivos sería a través de la interfaz pmFetch.

Para omitir registros dentro del conjunto de archivos, use pmSetMode(3) para cambiar la hora de recopilación dentro del contexto PMAPI actual, luego llame a pmFetchArchive

Tenga en cuenta que el result devuelto por pmFetchArchive se asigna dinámicamente y debe liberarse usando pmFreeResult(3), pero no free(3). Consulte pmFetch(3) y pmFreeResult(3) para más detalles.

pmFetchArchive devuelve cero si tiene éxito.

DIAGNÓSTICOS

PM_ERR_NOTARCHIVE
el contexto PMAPI actual no está asociado con un conjunto de archivos

COMPATIBILIDAD

Antes de PCP 7.0, el campo timestamp en la estructura pmResult era una struct timeval. Para admitir la transición de PMAPI, la interfaz y las semánticas antiguas pueden usarse si las aplicaciones se recompilan con -DPMAPI_VERSION=2.

Durante un tiempo en PCP 6.x, existió una rutina con la misma semántica que la actual pmFetchArchive llamada pmFetchHighResArchive, y una estructura con la misma definición que la actual estructura pmResult llamada pmResultHighRes, aunque ambas ahora están obsoletas y el soporte en tiempo de compilación para pmFetchHighResArchive y pmResultHighRes se eliminará en una versión futura.

VER TAMBIÉN

PMAPI(3), pmFetch(3), pmFreeResult(3), pmNewContext(3), pmSetMode(3) y pmTrimNameSpace(3).
