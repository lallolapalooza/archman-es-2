PMPROBE(1) Manual general de comandos PMPROBE(1)

NOMBRE

pmprobe - sondeo ligero para métricas de rendimiento

SINOPSIS

pmprobe [-dfFiILvVz?] [-a archivo] [-b tamaño_lote] [--container=nombre] [-D depuracion] [--derived=archivo] [-h nombre_host] [-K espec] [-n archivo_pmns] [-O tiempo] [-Z zona_horaria] [nombre_metrica ...]

DESCRIPCIÓN

pmprobe determina la disponibilidad de métricas de rendimiento exportadas a través de las facilidades del Performance Co-Pilot (PCP).

Las métricas de interés se nombran en los argumentos nombre_metrica. Si nombre_metrica es un nodo hoja en el Espacio de Nombres de Métricas de Rendimiento (PMNS(5)), entonces pmprobe descenderá recursivamente el PMNS e informará sobre todos los nodos hoja. Si no se proporciona ningún argumento nombre_metrica, se usa la raíz del espacio de nombres.

Esta expansión recursiva del PMNS puede ser inhibida por la opción -F (ir más rápido), que reduce el número de viajes de ida y vuelta a pmcd(1) cuando se sabe de antemano que los argumentos nombre_metrica son nodos hoja.

El formato de salida es espartano y está destinado a ser utilizado en scripts de envoltura que crean archivos de configuración para otras herramientas de PCP. Por defecto, hay una línea de salida por métrica, con el nombre de la métrica seguido de un recuento del número de valores disponibles. Las condiciones de error se codifican como un recuento de valor negativo (según los protocolos de PMAPI(3), pero pueden ser decodificadas usando pmerr(1)) y seguidas por una descripción textual del error.

A menos que se dirija a otro host con la opción -h, pmprobe contactará con el Demonio del Recolector de Métricas de Rendimiento (PMCD) en el host local.

La opción -a hace que pmprobe use el conjunto de archivos de archivo especificado en lugar de conectarse a un PMCD.

La opción -L hace que pmprobe use un contexto local para recolectar métricas de los PMDAs en el host local sin PMCD. Solo algunas métricas están disponibles en este modo.

Las opciones -a, -h y -L son mutuamente excluyentes.

OPCIONES

Las opciones de línea de comandos disponibles son:

-a archivo, --archive=archivo
Los valores de las métricas de rendimiento se recuperan del conjunto de archivos de archivo del Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos.
-b, --batch
Esta opción puede usarse para definir el número máximo de métricas a obtener en una sola solicitud para la opción -v y cualquier solicitud de pmLookupName(3) que pmprobe llame con una lista de nombres de métricas hoja. El valor por defecto para tamaño_lote es 128. Esta opción es útil para evitar limitaciones en los tamaños de las solicitudes PDU y también para escalonar las recuperaciones, que de lo contrario podrían caducar si pmcd(1) o un PMDA es lento en responder, particularmente si se sondean un gran número de métricas.
--container=contenedor
Especificar un contenedor individual para ser consultado.
-d, --version
Mostrar el número de versión y salir.
--derived=dmfile
El argumento dmfile especifica un archivo que contiene definiciones de métricas derivadas en el formato descrito para pmLoadDerivedConfig(3). Esta opción proporciona una forma de cargar definiciones de métricas derivadas que es una alternativa al uso más genérico de la variable de entorno PCP_DERIVED_CONFIG como se describe en PCPIntro(1). Usar la opción --derived y la variable de entorno PCP_DERIVED_CONFIG para especificar la **misma** configuración es una mala idea, así que elija uno u otro método.
-f, --force
Cuando se usa con -i o -I, el conjunto de instancias reportadas serán todas las conocidas en la fuente de los datos de rendimiento. Por defecto, el conjunto de instancias reportadas son aquellas para las que hay valores disponibles actualmente, lo que puede ser menor que el conjunto reportado con -f.
-F, --faster
Asumir que los nombres de métrica dados son nodos hoja de PMNS.
-h host, --host=host
Conectarse a pmcd(1) en host, en lugar de en el localhost por defecto.
-i, --internal
Informar los identificadores internos de cada instancia. Los valores están en decimal y prefijados por ``?'' . Como caso especial, la cadena literal PM_IN_NULL se informa para métricas singulares.
-I, --external
Informar los identificadores externos de cada instancia. La cadena literal PM_IN_NULL se informa para métricas singulares.
-K espec, --spec-local=espec
Al usar la opción -L/ para obtener métricas de un contexto local, esta opción controla los PMDAs DSO que deben ser accesibles. El argumento espec se ajusta a la sintaxis descrita en pmSpecLocalPMDA(3). Se puede usar más de una opción -K.
-L, --local-PMDA
Usar un contexto local para recolectar métricas de PMDAs DSO en el host local sin PMCD. Ver también -K.
-n archivo_pmns, --namespace=archivo_pmns
Normalmente pmprobe opera en el Espacio de Nombres de Métricas de Rendimiento (PMNS) distribuido, sin embargo, si se especifica la opción -n, se carga un archivo PMNS local alternativo del archivo archivo_pmns.
-O tiempo, --origin=tiempo
Cuando se usa en conjunción con una fuente de métricas de archivo y las opciones -f/, el argumento tiempo define un origen de tiempo en el que se deben obtener las métricas del conjunto de archivos. Consulte PCPIntro(1) para una descripción completa de esta opción y la sintaxis del argumento tiempo.
-v, --values
Informar el valor de cada instancia, según las reglas de formato de pmPrintValue(3). Al obtener de un conjunto de archivos, solo se mostrarán las instancias presentes en el primer registro de archivo para una métrica; ver también la opción -O. La opción -v es mutuamente excluyente con las opciones -I o -i.
-V, --verbose
Esta opción proporciona un resumen críptico del número de mensajes enviados y recibidos a través de la interfaz PMAPI.
-z, --hostzone
Cambiar la zona horaria de reporte a la zona horaria local en el host que es la fuente de las métricas de rendimiento, según se identifica a través de las opciones -h o -a.
-Z zona_horaria, --timezone=zona_horaria
Por defecto, pmprobe informa la hora del día según la zona horaria local en el sistema donde se ejecuta pmprobe. La opción -Z cambia la zona horaria a zona_horaria en el formato de la variable de entorno TZ como se describe en environ(7).
-?, --help
Mostrar mensaje de uso y salir.

EJEMPLOS

$ pmprobe disk.dev
disk.dev.read 2
disk.dev.write 2
disk.dev.total 2
disk.dev.blkread 2
disk.dev.blkwrite 2
disk.dev.blktotal 2
disk.dev.active 2
disk.dev.response 2

$ pmprobe -I disk.dev.read disk.dev.write disk.

EJEMPLOS

En el siguiente ejemplo, se consulta el número de agentes y la versión del demonio de control de Performance Co-Pilot (PMCD).

$ pmprobe -v pmcd.numagents pmcd.version
pmcd.numagents 1 9
pmcd.version 1 "5.0.0"

El siguiente ejemplo muestra cómo consultar las métricas de disco.

$ pmprobe -v disk.dev.read disk.dev.write disk.all.total
disk.dev.read 2 "sda" "sdb"
disk.dev.write 2 "sda" "sdb"
disk.all.total 1 4992466

Si una métrica no se encuentra, el comportamiento predeterminado es no mostrar nada. Esto se puede cambiar usando la opción -T.

$ pmprobe -v disk.dev.read disk.dev.write disk.all.total
disk.dev.read 2 "sda" "sdb"
disk.dev.write 2 "sda" "sdb"
disk.all.total 1 4992466

$ pmprobe -v pmcd.numagents pmcd.version pmcd.control.timeout
pmcd.numagents 1 9
pmcd.version 1 "5.0.0"
pmcd.control.timeout 1 5

$ pmprobe -v disk.dev.total disk.all.total
disk.dev.total -1012 Unknown metric name
disk.all.total 1 4992466

ARCHIVOS

$PCP_VAR_DIR/pmns/*
archivos de especificación de PMNS predeterminados

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para las variables de entorno que afectan a las herramientas de PCP, consulte pmGetOptions(3).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información a veces es críptica y está destinada principalmente a orientar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmprobe son las siguientes:

Opción Descripción
appl0 información de lotes cuando se usa -b
