PMLOGPUSH(1) Manual de comandos generales PMLOGPUSH(1)

NOMBRE

pmlogpush - enviar un archivo a un servidor pmproxy remoto

SINOPSIS

pmlogpush [-vV?] [-D debug] [-h host] [-p port] [-s unix] [-Z timezone] archivo

DESCRIPCIÓN

pmlogpush envía el contenido de un archivo Performance Co-Pilot (PCP) a un servidor HTTP (típicamente a un demonio pmproxy(1) remoto) utilizando el subconjunto de API del registrador dentro de PMWEBAPI(5). El archivo debe haber sido creado previamente usando pmlogger(1).

Este archivo debe estar completo y finalizado (no en proceso de escritura). La funcionalidad comparable está disponible directamente desde pmlogger utilizando la opción -R, para enviar archivos de forma remota mientras se están escribiendo activamente.

OPCIONES

Las opciones disponibles en la línea de comandos son:

-h nombre_host, --host=nombre_host
El nombre_host para el servidor pmproxy remoto que recibirá el archivo PCP dado.
-p puerto, --port=puerto
Número de puerto del socket de Internet donde el servidor pmproxy remoto está escuchando, esperando recibir el archivo PCP dado. El puerto por defecto es 44322.
-s ruta, --unix=ruta
La ruta del socket de dominio Unix donde un servidor pmproxy local está escuchando (localmente), esperando recibir el archivo PCP dado.
-v, --verbose
Aumenta la información diagnóstica informada mientras se ejecuta pmlogpush.
-?, --help
Muestra el mensaje de uso y sale.
-V, --version
Muestra el número de versión y sale.

ARCHIVOS

$PCP_LOG_DIR/pmproxy/<nombre_host>
Directorio por defecto para los archivos PCP enviados creados (remotamente) por el servidor pmproxy receptor. El nombre_host se extrae del archivo dado, al igual que la hora de inicio de la grabación; juntos, estas propiedades se utilizan para nombrar el archivo enviado en el extremo receptor (es decir, por el servidor pmproxy).

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede utilizarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información es a veces críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado. La opción de depuración http es de particular interés para esta utilidad.

VER TAMBIÉN

PCPIntro(1), pmlogger(1), pmproxy(1), PMWEBAPI(3), pcp.conf(5) y pcp.env(5).
