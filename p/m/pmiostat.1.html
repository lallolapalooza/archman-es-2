PCP-IOSTAT(1) Manual de Comandos Generales PCP-IOSTAT(1)

NOMBRE

pmiostat, pcp-iostat - informe de estadísticas de E/S de bloque

SINOPSIS

pcp [opciones de pcp] iostat [-u?] [-G método] [-P precisión] [-R patrón] [-x [dm][,t][,h][,noidle]]

DESCRIPCIÓN

pcp-iostat informa de estadísticas de E/S para dispositivos SCSI (por defecto) u otros dispositivos (si se especifica la opción -x).

OPCIONES

Cuando se invoca a través del comando pcp(1), las opciones de pcp -A/--align, -a/--archive, -h/--host, -O/--origin, -S/--start, -s/--samples, -T/--finish, -t/--interval, -v/--version, -Z/--timezone y -z/--hostzone están indirectamente disponibles; consulte PCPIntro(1) para una descripción completa de estas opciones.

Las opciones adicionales de línea de comandos disponibles para pcp-iostat son:

-G método, --aggregate=método
Especifica que las estadísticas de los nombres de dispositivo que coinciden con la expresión regular especificada con la opción -R regex deben agregarse según el método. Tenga en cuenta que esto es una agregación basada en nombres de dispositivo coincidentes (no agregación temporal). Cuando se usa -G, la columna del nombre del dispositivo se informa como método(regex), por ejemplo, si se especifica -G sum -R 'sd(a|b)$', la columna del dispositivo será sum(sd(a|b)$) y se informarán las estadísticas sumadas para sda y sdb en las columnas restantes. Si se especifica -G pero no se especifica -R, la regex predeterminada es .*, es decir, coincide con todos los nombres de dispositivo. Si método es sum, las estadísticas se suman. Esto incluye la columna %util, que por lo tanto puede superar el 100% si coinciden más de un nombre de dispositivo. Si método es avg, las estadísticas se suman y luego se promedian dividiendo por el número de nombres de dispositivo coincidentes. Si método es min o max, se informan las estadísticas mínimas o máximas para los dispositivos coincidentes, respectivamente.
-P N, --precision=N
Esto indica la precisión (número de decimales) a informar. La precisión predeterminada N puede establecerse en algo diferente al valor predeterminado (2). Tenga en cuenta que los campos avgrq-sz y avgqu-sz siempre se informan con N+1 decimales de precisión. Estos campos suelen tener valores inferiores a 1.
-R patrón, --regex=patrón
Esto restringe el informe a los nombres de dispositivo que coinciden con una expresión regular patrón. El patrón dado se busca como una expresión regular estilo perl, y coincidirá con cualquier parte de un nombre de dispositivo. Por ejemplo, '^sd[a-zA-Z]+' coincidirá con todos los nombres de dispositivo que comienzan con 'sd' seguidos de uno o más caracteres alfabéticos. Por ejemplo, '^sd(a|b)$' solo coincidirá con 'sda' y 'sdb'. Por ejemplo, 'sda$' coincidirá con 'sda' pero no con 'sdab'. Consulte también la opción -G para ver las opciones de agregación.
-u, --no-interpolation
Al reproducir un conjunto de archivos, por defecto los valores se informan de acuerdo con el intervalo de muestra solicitado (opción -t), no de acuerdo con el intervalo real registrado en los archivos. Sin esta opción, PCP interpola los valores a informar basándose en los registros del conjunto de archivos, lo que es particularmente útil cuando se utiliza la opción -t para reproducir un conjunto de archivos con un intervalo de muestreo más largo que el con el que se grabó originalmente el(los) archivo(s). Con la opción -u, se habilita la generación de informes sin interpolación: cada valor se informa de acuerdo con el intervalo de grabación nativo en el conjunto de archivos. Cuando se especifica la opción -u, la opción -t no tiene sentido y es incompatible porque el intervalo de reproducción es siempre el mismo que el intervalo de grabación en el conjunto de archivos. Además, -u solo tiene sentido al reproducir archivos, consulte la opción -a en PCPIntro(1), por lo que si se especifica -u, también se debe especificar -a.
-V, --version
Muestra el número de versión y sale.
-x opciones separadas por comas
Especifica una lista separada por comas de una o más opciones de informe extendido como sigue:
dm - informa estadísticas para dispositivos lógicos de device-mapper en lugar de dispositivos SCSI,
t - antepone a cada línea del informe una marca de tiempo en formato ctime(3),
h - omite el encabezado, que de lo contrario se informa cada 24 muestras,
noidle - No muestra estadísticas para dispositivos inactivos.
-?, --help
Muestra el mensaje de uso y sale.

INFORME

Las columnas en el informe pcp-iostat tienen la siguiente interpretación:

Timestamp
Cuando se especifica la opción -x t, esta columna es la marca de tiempo en formato ctime(3).
Device
Especifica el nombre del dispositivo scsi, o si se especifica -x dm, el nombre del dispositivo lógico de device-mapper. Cuando se especifica -G, esto es reemplazado por el método de agregación y la expresión regular; consulte las opciones -G y -R anteriores.
rrqm/s
El número de solicitudes de lectura expresado como una tasa por segundo que fueron fusionadas durante el intervalo de informe por el programador de E/S.
wrqm/s
El número de solicitudes de escritura expresado como una tasa por segundo que fueron fusionadas durante el intervalo de informe por el programador de E/S.
r/s
El número de solicitudes de lectura completadas por el dispositivo (después de las fusiones), expresado como una tasa por segundo durante el intervalo de informe.
w/s
El número de solicitudes de escritura completadas por el dispositivo (después de las fusiones), expresado como una tasa por segundo durante el intervalo de informe.
rkB/s
El volumen promedio de datos leídos del dispositivo expresado en KBytes/segundo durante el intervalo de informe.
wkB/s
El volumen promedio de datos escritos al dispositivo expresado en KBytes/segundo durante el intervalo de informe.
avgrq-sz
El tamaño promedio de la solicitud de E/S, tanto de lectura como de escritura, al dispositivo expresado en Kbytes durante el intervalo de informe.
avgqu-sz
La longitud promedio de la cola de solicitudes de lectura y escritura al dispositivo durante el intervalo de informe.
await
El tiempo promedio en milisegundos que las solicitudes de lectura y escritura estuvieron en cola (y se atendieron) en el dispositivo durante el intervalo de informe.
r_await
El tiempo promedio en milisegundos que las solicitudes de lectura estuvieron en cola (y se atendieron) en el dispositivo durante el intervalo de informe.
w_await
El tiempo promedio en milisegundos que las solicitudes de escritura estuvieron en cola (y se atendieron) en el dispositivo durante el intervalo de informe.
%util
El porcentaje de tiempo durante el intervalo de informe que el dispositivo estuvo ocupado procesando solicitudes. Un valor del 100% indica saturación del dispositivo.

AMBIENTE PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

pmiostat(1) — Performance Co-Pilot

NAME

pmiostat - reporting iostat statistics for Performance Co-Pilot

SYNOPSIS

pmiostat [-a] [-d] [-E end_time] [-h] [-i interval] [-l logfile] [-N domainlist] [-P processorlist] [-S start_time] [-t] [-u] [-V] [inst,...]

DESCRIPTION

pmiostat is a front-end to the Performance Co-Pilot (PCP) system that attempts to emulate the behaviour of the standard Unix iostat(1) utility. It reports system-wide statistics and per-processor or per-disk statistics, similar to the standard iostat(1) command.

The reporting interval may be specified in seconds (if the value is an integer) or minutes (if the value contains a decimal point). If no interval is specified, the default reporting interval is 5 seconds.

The available performance metrics are selected from the ISA framework, and the full list of available metrics can be obtained using the pminfo(1) command.

OPTIONS

The available command line options are:

-a
Report all available disk metrics. By default, only a subset of disk metrics are reported.
-d
Report per-disk statistics. By default, only system-wide disk statistics are reported.
-E end_time
Exit at the specified end_time. This is only relevant when processing a PCP archive. The time may be specified in the same format as for -S.
-h
When processing a PCP archive, print the hostname specified in the archive header. By default, the hostname is not printed.
-i interval
Set the reporting interval to interval seconds. The default is 5 seconds.
-l logfile
Write the collected performance metrics to the specified logfile in PCP archive format. This is useful for later archival and analysis of the performance data.
-N domainlist
A comma-separated list of domain names for the performance metrics to be reported. By default, all domains are searched.
-P processorlist
A comma-separated list of processors for which per-processor statistics are to be reported. The default is to report per-processor statistics for all available processors.
-S start_time
Start reporting at the specified start_time. This is only relevant when processing a PCP archive. The time may be specified as:
A date and time, in the format ``YYYY-MM-DD HH:MM:SS''.
A relative time offset from the current time, in the format ``[DDd][HHh][MMm][SSs]''.
A PCP archive timestamp, as generated by pmlogger(1).
-t
Print the current time. This is useful when logging performance data to a PCP archive and you want to see the actual time that the data was collected.
-u
Report per-processor statistics. By default, only system-wide statistics are reported.
-V
Verbose mode. Print version number and exit.

REPORT

The following performance metrics are reported:

System-wide disk statistics:

tps
total number of transfers per second that issued to/from the device.
rd_sec/s
the number of sectors read from the device per second.
wr_sec/s
the number of sectors written to the device per second.
avque
the average number of requests outstanding for the device during the sample period.

Per-disk statistics:

device
the name of the device.
rrqm/s
the number of read requests queued up for processing per second.
wrqm/s
the number of write requests queued up for processing per second.
r_await
the average queue length of the requests outstanding of the device during the sample period.
w_await
the average queue length of the requests outstanding of the device during the sample period.
svctm
the average service time (or I/O completion time) for I/O requests issued to the device.
%util
close to 100% means that the device can't handle all the I/O requests it gets in time.

Per-processor statistics:

%user
percentage of CPU time spent in user mode.
%nice
percentage of CPU time spent in user mode with high priority.
%system
percentage of CPU time spent in kernel mode.
%iowait
percentage of time that there were running but unrunnable processes waiting for I/O to complete.
%idle
percentage of time that the CPU was idle and available.

PCP ENVIRONMENT

See pcp.conf(5) for a description of the local environment for controlling PCP collection of performance metrics.

For environment variables affecting PCP tools, see pmGetOptions(3).

DEBUGGING OPTIONS

The -D or --debug pcp option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.
