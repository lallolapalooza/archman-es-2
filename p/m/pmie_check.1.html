PMIE_CHECK(1) Manual de comandos generales PMIE_CHECK(1)

NOMBRE

pmie_check, pmie_daily - administración del motor de inferencia Performance Co-Pilot

SINOPSIS

$PCP_BINADM_DIR/pmie_check [-CNPpsTV?] [-c control] [-l logfile]
$PCP_BINADM_DIR/pmie_daily [-NV?] [-c control] [-k discard] [-l logfile] [-m addresses] [-x compress] [-X program] [-Y regex]

DESCRIPCIÓN

Esta serie de scripts de shell y archivos de control asociados pueden usarse para crear un régimen personalizado de administración y gestión para el motor de inferencia de Performance Co-Pilot (ver PCPIntro(1)), pmie(1).

pmie_check puede ejecutarse en cualquier momento del día y verifica que se esté ejecutando un conjunto deseado de procesos pmie. Si no es así, (re)inicia cualquier proceso del motor de inferencia faltante.

pmie_daily está destinado a ejecutarse una vez al día, preferiblemente a primera hora de la mañana, lo más pronto posible después de la medianoche. Su tarea es rotar los archivos de registro de los procesos pmie en ejecución; estos archivos pueden crecer sin límite si se utiliza la acción "print" o si cualquier otra acción de pmie escribe en sus flujos de salida estándar/error estándar. Después de un tiempo, los archivos de registro antiguos de pmie se descartan.

OPCIONES

Las opciones de línea de comandos disponibles son:

-c control, --control=control
Tanto pmie_check como pmie_daily son controlados por archivos de control del motor de inferencia de PCP que especifican las instancias de pmie a gestionar. El archivo de control predeterminado es $PCP_PMIECONTROL_PATH, pero se puede especificar uno alternativo usando la opción -c. Si existe el directorio $PCP_PMLOGGERCONTROL_PATH.d (o control.d de la opción -c), entonces el contenido de cualquier archivo control adicional allí se agregará al archivo de control principal (que debe existir).
-C
Esta opción hace que pmie_check consulte la información del nivel de ejecución del servicio del sistema para pmie y la utilice para determinar si iniciar o no los procesos.
-k period, --discard=period
El período de retención de registros es de 14 días por defecto, pero esto puede cambiarse usando esta opción. Se reconocen dos valores especiales para el período de descarte, a saber, 0 para no conservar ningún archivo de registro más allá del actual, y forever para evitar que se descarten archivos de registro.
-l file, --logfile=file
Para garantizar que no se envíe correo no deseado involuntariamente cuando estos scripts se ejecutan desde cron(8), los diagnósticos siempre se envían a archivos de registro. Por defecto, estos archivos son $PCP_LOG_DIR/pmie/pmie_daily.log y $PCP_LOG_DIR/pmie/pmie_check.log, pero esto puede cambiarse usando la opción -l. Si este archivo de registro file ya existe cuando el script comienza, se renombrará con un sufijo .prev (sobrescribiendo cualquier archivo de registro guardado anteriormente) antes de que se generen diagnósticos en el nuevo archivo de registro.
-m addresses, --mail=addresses
El uso de esta opción hace que pmie_daily construya un resumen de los archivos de registro generados para todos los hosts monitoreados en las últimas 24 horas (se eliminan las líneas que coinciden con " OK "), y envíe ese resumen por correo electrónico al conjunto de direcciones separadas por espacios.
-N, --showme
Esta opción habilita un modo "muéstrame", donde las acciones de los programas se repiten, pero no se ejecutan, al estilo de "make -n". Usar -N junto con -V maximiza las capacidades de diagnóstico para la depuración.
-s, --stop
El uso de esta opción proporciona la funcionalidad inversa de pmie_check, permitiendo que el conjunto de procesos pmie se apague limpiamente.
-p, --skip-primary
Si se especifica esta opción para pmie_check, se ignorará cualquier línea de los archivos de control para el pmie primario. Esta opción está destinada a entornos donde algún demonio del sistema, como systemd(1), es responsable de controlar (iniciar, detener, reiniciar, etc.) el pmie primario.
-P, --only-primary
Si se especifica esta opción para pmie_check, solo se procesará la entrada del pmie primario en los archivos de control. Este es el opuesto lógico de la opción -p descrita anteriormente y está destinado a ser utilizado por scripts RC que inician solo el pmie primario, como la unidad pmie.service. Las opciones -p y -P para pmie_check son mutuamente excluyentes.
-T, --terse
Esta opción para pmie_check produce una salida menos detallada que la predeterminada. Esto es más adecuado para una "granja" de pmie donde se espera que muchas instancias de pmie estén en ejecución.
-V, --verbose
La salida de la ejecución cron de los scripts puede extenderse usando la opción -V de los scripts, lo que habilitará el rastreo detallado de su actividad. Por defecto, los scripts no generan ninguna salida a menos que se encuentre alguna condición de error o advertencia. Usar -N junto con -V maximiza las capacidades de diagnóstico para la depuración.
-x period, --compress-after=period
Los archivos de registro pueden comprimirse opcionalmente después de un cierto período para conservar espacio en disco. Esto es particularmente útil para un gran número de procesos pmie bajo el control de pmie_check. La opción -x especifica el número de días después de los cuales comprimir los archivos de datos de archivo.
-X program, --compressor=program
Esta opción especifica el programa a utilizar para la compresión; por defecto es xz(1).
-Y regex, --regex=regex
Esta opción permite especificar una expresión regular para omitir archivos del conjunto de archivos que coinciden para la compresión; esto permite comprimir solo el archivo de datos y también evita que el programa intente comprimirlo más de una vez. La regex predeterminada es
"\.(meta|index|Z|gz|bz2|zip|xz|lzma|lzo|lz4|zst)$"
- tales archivos se filtran usando la opción -v de egrep(1).
-?, --help
Muestra el mensaje de uso y sale.

pmie_check(1) — Performance Co-Pilot

NAME

pmie_check — verify and manage Performance Metrics Inference Engine (PMIE) instances

SYNOPSIS

pmie_check [-a] [-d] [-f] [-k] [-l] [-C cache]

pmie_check [-c control] [-C cache]

pmie_check [-h]

DESCRIPTION

The pmie_check utility is used to control the Performance Metrics Inference Engine (PMIE) pmie(1). It is usually invoked by a system daemon or a user crontab entry.

When invoked with no arguments, pmie_check reads the Performance Co-Pilot (PCP) inference engine control file, $PCP_PMIECONTROL_PATH, identifies all configured PMIE instances, and checks if each instance is running. If a PMIE instance is not running, pmie_check attempts to start it.

The -a, -d, -f, -k, and -l options select specific actions to be performed on all PMIE instances found in the control file:

-a
Attempt to start all PMIE instances that are not currently running.
-d
Perform daily maintenance on all PMIE instances. This is typically invoked by the pmie_daily(8) script.
-f
Force the start of all PMIE instances. If an instance is already running, it will be killed and restarted.
-k
Kill all PMIE instances.
-l
List all PMIE instances currently running.

The -c option allows specification of an alternative control file.

The -C option specifies the cache file to use for metric values, as described in pmie(1).

The -h option prints a help message and exits.

OPTIONS

See the DESCRIPTION section.

CONFIGURATION

The default control file, $PCP_PMIECONTROL_PATH, is a text file containing zero or more lines. Each line describes a single PMIE instance and consists of whitespace-separated fields:

1.
The first field is the hostname of the host that is the default source of the performance metrics for this pmie instance.
2.
The second field indicates if this is a primary pmie instance (y) or not (n). Since the primary inference engine must run on the local host, and there may be at most one primary for a particular host, this field can be y for at most one pmie instance, in which case the host name must be the name of the local host. When generating pmie configuration files, the primary clause indicates that pmieconf(1) should enable all rules in the primary group, in addition to all other default rules.
3.
The third field indicates whether this pmie instance needs to be started under the control of pmsocks(1) to connect to a pmcd through a firewall (y or n).
4.
The fourth field is the name of the pmie activity log file. A useful convention is that pmie instances monitoring the local host with hostname myhost are maintained in the directory $PCP_LOG_DIR/pmie/myhost, while activity logs for the remote host mumble are maintained in $PCP_LOG_DIR/pmie/mumble. This is consistent with the way pmlogger(1) maintains its activity logs and archive files.
5.
All other fields are interpreted as arguments to be passed to pmie(1). Most typically this would be the -c option.

The following sample control lines specify one pmie instance monitoring the local host (wobbly), and another monitoring performance metrics from the host splat.

wobbly  n  PCP_LOG_DIR/pmie/wobbly  -c config.default
splat   n  PCP_LOG_DIR/pmie/splat   -c splat/cpu.conf

Typical crontab(5) entries for periodic execution of pmie_daily and pmie_check are given in $PCP_SYSCONF_DIR/pmie/crontab (unless installed by default in /etc/cron.d already) and shown below.

# daily processing of pmie logs
08      0       *       *       *       $PCP_BINADM_DIR/pmie_daily
# every 30 minutes, check pmie instances are running
28,58   *       *       *       *       $PCP_BINADM_DIR/pmie_check
When using systemd(1) on Linux, no crontab entries are needed as the timer mechanism provided by systemd is used instead.

The pmiectl(1) utility may invoke pmie_check using the sudo(1) command to run it under the $PCP_USER ``pcp'' account. If sudo is configured with the non-default requiretty option (see below), pmie_check may fail to run due to not having a tty configured. This issue can be resolved by adding a second line (expand $PCP_BINADM_DIR according to your platform) to the /etc/sudoers configuration file as follows:

Defaults requiretty
Defaults!$PCP_BINADM_DIR/pmie_check !requiretty

Note that the unprivileged PCP account under which these commands run uses /sbin/nologin as the shell, so the requiretty option is ineffective here and safe to disable in this way.

FILES

$PCP_PMIECONTROL_PATH
the default PCP inference engine control file
Warning: this file must not be writable by any user other than root.
$PCP_PMIECONTROL_PATH.d
optional directory containing additional PCP inference engine control files, typically one per host
Warning: this files herein must not be writable by any user other than root.
$PCP_SYSCONF_DIR/pmie/crontab
sample crontab for automated script execution by $PCP_USER (or root) - exists only if the platform does not support the /etc/cron.d mechanism.
$PCP_VAR_DIR/config/pmie/config.default
default pmie configuration file location for a localhost inference engine, typically generated automatically by pmieconf(1).
$PCP_LOG_DIR/pmie/pmie_check.log
default location for the pmie_check log file. When run as a daemon service, if the pmie process failed to start or exited early, there may be error messages in this file, particularly if the daemon could not open it's own log file.
$PCP_LOG_DIR/pmie/pmie_daily.log
default location for error messages generated during the daily pmie service maintenance operations.
$PCP_LOG_DIR/pmie/<hostname>
default directory location for the pmie log file for the host hostname
$PCP_LOG_DIR/pmie/<hostname>/lock
transient lock file to guarantee mutual exclusion during pmie administration for the host hostname - if present, can be safely removed if neither pmie_daily nor pmie_check are running
$PCP_LOG_DIR/NOTICES
PCP ``notices'' file used by pmie(1) and friends

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).
