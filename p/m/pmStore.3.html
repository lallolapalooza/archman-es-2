PMSTORE(3) Manual de funciones de biblioteca PMSTORE(3)

NOMBRE

pmStore - modificar valores de métricas de rendimiento

SINOPSIS C

#include <pcp/pmapi.h>

int pmStore(const pmResult *result);

cc ... -lpcp

DESCRIPCIÓN

En algunos casos especiales puede ser útil modificar los valores actuales de las métricas de rendimiento, por ejemplo, para restablecer un contador a cero, o para modificar una "métrica" que es una variable de control para algún agente que recopila métricas de rendimiento.

pmStore es el inverso ligero de pmFetch(3).

El llamador debe construir la estructura de datos result (por supuesto, esta podría haber sido devuelta por una llamada anterior a pmFetch(3)).

Es un error pasar un result a pmStore en el que el campo numval dentro de cualquiera de las estructuras pmValueSet tenga un valor menor que uno.

El contexto actual de la Interfaz de Programación de Aplicaciones de Métricas de Rendimiento (PMAPI) debe ser uno con un host como fuente de métricas, y se cambiará el valor actual de las métricas nominadas, es decir, pmStore no se puede utilizar para realizar cambios retrospectivos en la información de los archivos, o en el pasado reciente para fuentes de métricas en tiempo real.

El código de retorno de pmStore es cero para éxito.

DIAGNÓSTICOS

PM_ERR_GENERIC
Al menos una de las modificaciones fue rechazada. No hay otro estado disponible por debajo de la PMAPI (¡esta es la parte ligera de la funcionalidad!). En casos donde el resultado de almacenar en métricas individuales es importante, el llamador debe hacer una llamada a pmStore por cada métrica. Por otro lado, se puede realizar una modificación masiva en una sola llamada para situaciones en las que el resultado no es crítico.
PM_ERR_NOTHOST
El contexto PMAPI actual es un archivo en lugar de un host, o es un host que no está configurado en la hora actual, es decir, ha sido "rebobinado" al pasado reciente usando pmSetMode(3).
PM_ERR_TOOSMALL
El número de métricas especificadas en result es menor que uno.
PM_ERR_VALUE
Uno o más de los pmValueSets en result tienen un campo numval con un valor menor que uno.

COMPATIBILIDAD

Antes de PCP 7.0, el campo timestamp en la estructura pmResult era un struct timeval. Para soportar la transición de PMAPI, la interfaz y semántica antiguas pueden usarse si las aplicaciones se recompilan con -DPMAPI_VERSION=2.

Durante un tiempo en PCP 6.x existió una rutina con la misma semántica que la actual pmStore llamada pmStoreHighRes, y una estructura con la misma definición que la actual estructura pmResult llamada pmResultHighRes, aunque ambas ahora están obsoletas y el soporte a nivel de compilación para pmStoreHighRes y pmResultHighRes se eliminará en una versión futura.

VER TAMBIÉN

PMAPI(3), pmFetch(3) y pmSetMode(3).
