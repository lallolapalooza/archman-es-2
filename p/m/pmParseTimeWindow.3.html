pmParseTimeWindow(3)

Paquete: pcp

Licencias: GPL-2.0-or-later, LGPL-2.1-or-later, CC-BY-3.0

PMPARSETIMEWINDOW(3) Manual de funciones de biblioteca PMPARSETIMEWINDOW(3)

NOMBRE

pmParseTimeWindow - analizar los argumentos de línea de comandos de la ventana de tiempo

SINOPSIS

#include <pcp/pmapi.h>

int pmParseTimeWindow(const char *swStart,
const char *swEnd, const char *swAlign, const char *swOffset, const struct timespec *logStart, const struct timespec *logEnd, struct timespec *rsltStart, struct timespec *rsltEnd, struct timespec *rsltOffset, char **errMsg);

cc ... -lpcp

DESCRIPCIÓN

pmParseTimeWindow está diseñado para encapsular la interpretación de las opciones de línea de comandos -S, -T, -A y -O utilizadas por las aplicaciones de Performance Co-Pilot (PCP) para definir una ventana de tiempo de interés. La ventana de tiempo se define por una hora de inicio y una hora de fin que restringen el intervalo de tiempo durante el cual la aplicación PCP recuperará y mostrará métricas de rendimiento. En ausencia de las opciones -O y -A para especificar un origen de muestra inicial y una alineación de tiempo (ver más abajo), la aplicación PCP recuperará la primera muestra al inicio de la ventana de tiempo.

La sintaxis y el significado de los diversos formatos de argumento para estas opciones se describen en PCPIntro(1).

USO

pmParseTimeWindow espera ser llamado con el argumento de la opción -S como swStart, el argumento de la opción -T como swEnd, el argumento de la opción -A como swAlign, y el argumento de la opción -O como swOffset. Cualquiera o todos estos parámetros pueden ser NULL para indicar que la opción de línea de comandos correspondiente no estaba presente.

Si la aplicación está utilizando un conjunto de archivos PCP como fuente de métricas de rendimiento, también debe proporcionar la hora de la primera entrada del archivo como logStart, y la hora de la última entrada del archivo como logEnd. Consulte pmGetArchiveLabel(3) y pmGetArchiveEnd(3) para saber cómo obtener los valores de estas horas.

Si la aplicación está manipulando varios archivos simultáneos, el llamador debe resolver cómo se definirá la ventana de tiempo predeterminada (la unión de los intervalos de tiempo en todos los archivos es una interpretación probable).

Si la aplicación está utilizando una transmisión en vivo de datos de rendimiento, logStart debe ser la hora actual (pero podría alinearse en el siguiente segundo, por ejemplo), mientras que logEnd debe tener su componente tv_sec establecido en PM_MAX_TIME_T.

Las estructuras rsltStart, rsltEnd y rsltOffset deben ser asignadas antes de llamar a pmParseTimeWindow.

También necesita configurar la zona horaria de informes actual de PCP para reflejar correctamente los parámetros de línea de comandos -z y -Z antes de llamar a estas rutinas. Consulte pmUseZone(3) y sus amigos para obtener información sobre cómo se hace esto.

DIAGNÓSTICOS

Si la conversión es exitosa, pmParseTimeWindow devuelve 1 y rellena rsltStart, rsltEnd y rsltOffset con las horas de inicio, fin y desplazamiento de la ventana de tiempo definida por los parámetros de entrada. El parámetro errMsg no se modifica cuando pmParseTimeWindow devuelve 1.

Si la conversión es exitosa, pero la alineación solicitada no se pudo realizar (por ejemplo, el conjunto de archivos PCP es demasiado corto), la alineación se ignora, se rellenan rsltStart, rsltEnd y rsltOffset, y pmParseTimeWindow devuelve 0. En este caso, errMsg apuntará a un mensaje de advertencia en un búfer asignado dinámicamente. El llamador es responsable de liberar el búfer llamando a free(3).

Si las cadenas de argumento no pudieron ser analizadas, pmParseTimeWindow devuelve -1. En este caso, errMsg apuntará a un mensaje de error en un búfer asignado dinámicamente. El llamador es responsable de liberar el búfer llamando a free(3).

COMPATIBILIDAD

Antes de PCP 7.0 y libpcp.so.4, los argumentos logStart, logEnd, rsltStart, rsltEnd y rsltOffset eran struct timeval. Para admitir la transición de PMAPI, la interfaz y la semántica antiguas pueden usarse si las aplicaciones se enlazan con libpcp.so.3 o se recompilan con -DPMAPI_VERSION=2.

Hace tiempo, en PCP 6.x, había una rutina con la misma semántica que la actual pmParseTimeWindow llamada pmParseHighResTimeWindow, aunque ahora está obsoleta y el soporte en tiempo de compilación para pmParseHighResTimeWindow se eliminará en una futura versión.
