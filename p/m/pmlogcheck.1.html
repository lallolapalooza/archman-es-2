PMLOGCHECK(1) Manual de Comandos Generales PMLOGCHECK(1)

NOMBRE

pmlogcheck - comprueba si hay datos inválidos en un archivo PCP

SINOPSIS

pmlogcheck [-lmvwz?] [-D debug] [-n pmnsfile] [-S inicio] [-T fin] [-Z zona_horaria] archivo ...

DESCRIPCIÓN

pmlogcheck imprime información sobre la naturaleza de cualquier dato inválido que detecte en los archivos de PCP.

Cada archivo tiene el nombre base archivo y debe haber sido creado previamente usando pmlogger(1). Alternativamente, archivo puede ser el nombre de un archivo físico que forma parte de un archivo PCP.

Cuando se presentan múltiples opciones de archivo, se comprobarán todos los archivos PCP correspondientes, sin embargo, si las opciones de archivo son nombres de archivo, cada archivo PCP asociado se comprobará como máximo una vez.

OPCIONES

Las opciones de línea de comandos disponibles son:

-l, --etiqueta
Imprime la etiqueta del archivo, mostrando la versión del formato del archivo, la hora y fecha de inicio y (actual) finalización del archivo, y el host desde el cual se recopilaron los valores de las métricas de rendimiento.
-m, --solo-metadatos
Omite el Paso 3 (ver más abajo) y solo comprueba los metadatos del archivo. Esto puede ejecutarse sustancialmente más rápido en casos donde los datos del volumen no necesitan ser comprobados, especialmente en archivos con volúmenes de datos comprimidos.
-n archivo-pmns, --namespace=archivo-pmns
Carga un Espacio de Nombres de Métricas de Rendimiento (PMNS(5)) alternativo del archivo archivo-pmns.
-S inicio, --start=inicio
Especifica el inicio de la ventana de tiempo sobre la cual se deben comprobar las métricas en el Paso 3 (ver más abajo). Consulte PCPIntro(1) para una descripción completa de la sintaxis para inicio.
-T fin, --finish=fin
Especifica el fin de la ventana de tiempo sobre la cual se deben comprobar las métricas en el Paso 3 (ver más abajo). Consulte PCPIntro(1) para una descripción completa de la sintaxis para fin.
-v, --verbose
Habilita el modo detallado.
-w, --no-wrap
Suprime la notificación de desbordamientos de contadores.
-z, --zona-host
Usa la zona horaria local del host que es la fuente del archivo de métricas de rendimiento. El valor predeterminado es usar la zona horaria del host local.
-Z zona_horaria, --timezone=zona_horaria
Usa zona_horaria para la fecha y hora. Zona_horaria está en el formato de la variable de entorno TZ como se describe en environ(7). El valor predeterminado es usar la zona horaria del host local.
-?, --help
Muestra el mensaje de uso y sale.

OPERACIÓN

La comprobación procede en varios pasos, cada uno diseñado para validar relaciones semánticas cada vez más complejas entre la información de un archivo PCP.

Paso 0

Cada archivo físico del archivo PCP se procesa para asegurar que los registros de etiqueta sean válidos y consistentes, y que cada archivo contenga un número integral de registros físicos con campos de encabezado y pie de página correctos.

Cualquier error en esta etapa suele ser fatal. El archivo PCP probablemente está dañado más allá de la reparación, y no se intentan más pasos de pmlogcheck.

Paso 1

Valida la integridad del índice temporal, normalmente archivo.index.

Dado que el índice temporal es (estrictamente hablando) opcional, los errores en esta etapa se manejan marcando el índice como incorrecto e ignorándolo para el resto de los pasos de pmlogcheck.

La reparación permanente se puede lograr eliminando el archivo del índice temporal y luego haciendo una copia del archivo PCP usando pmlogrewrite(1) o pmlogextract(1). Esto creará un nuevo índice temporal para el archivo copiado como efecto secundario.

Paso 2

Valida la integridad del archivo de metadatos, normalmente archivo.meta.

Paso 3

Valida la integridad de cada uno de los volúmenes del archivo PCP, normalmente archivo.0, archivo.1, etc.

Hay algunas comprobaciones básicas de integridad para asegurar que la codificación de los valores para cada métrica permanece consistente y que los valores están bien formados en todas las observaciones del archivo.

Además, se espera que las marcas de tiempo de las observaciones aumenten monótonamente a medida que se recorre el archivo.

Se presta atención adicional a las métricas de contador (tipo de pmLookupDesc(3) es PM_SEM_COUNTER) que se espera que tengan valores monótonamente crecientes. Si los valores no son monótonamente crecientes, esto puede sugerir que ha ocurrido un desbordamiento de contador o que ha habido alguna interrupción o reinicio en la fuente subyacente de los datos de rendimiento que no se captura en el archivo.

Para cada métrica de contador que se haya detectado como desbordada en algún momento del archivo, pmlogcheck produce una salida que describe el nombre de la métrica (con identificadores de instancia cuando sea apropiado), el tipo de almacenamiento interno para la métrica, el valor de la métrica antes del desbordamiento del contador (con su marca de tiempo asociada) y el valor de la métrica después del desbordamiento (también con una marca de tiempo).

La opción -w puede usarse para suprimir la notificación de desbordamientos de contadores.

pmlogcheck produce dos formatos de marca de tiempo diferentes, dependiendo del intervalo sobre el cual se ejecuta. Para un intervalo mayor de 24 horas, se muestra la fecha además de la hora en que ocurrió el desbordamiento del contador. Si la extensión de los datos que se están comprobando es inferior a 24 horas, se utiliza un formato más preciso (la hora se muestra con precisión de milisegundos, pero sin la fecha).

EJEMPLOS

Los siguientes son todos equivalentes: 

$ pmlogcheck miarchivo
$ pmlogcheck miarchivo.0
$ pmlogcheck miarchivo.meta
$ pmlogcheck miarchivo.0 miarchivo.meta


Si el directorio actual contiene varios archivos PCP, entonces el comando 

$ pmlogcheck *.meta*


los comprobará todos, ya que hay un archivo .meta por cada archivo PCP, pero este archivo puede haber sido comprimido (de ahí el * al final).

FICHEROS

$PCP_VAR_DIR/pmns/*
archivos de especificación PMNS predeterminados
$PCP_LOG_DIR/pmlogger/<nombre_host>
directorio predeterminado para los archivos PCP que contienen datos de rendimiento recopilados del host nombre_host.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).
