PMCPP(1) Manual de Comandos Generales PMCPP(1)

NOMBRE

pmcpp - preprocesador simple para Performance Co-Pilot

SINOPSIS

pmcpp [-Prs?] [-D nombre[=valor] ...] [-I dir ...] [[archivo_entrada] [archivo_salida]]

DESCRIPCIÓN

pmcpp proporciona un preprocesador muy simple diseñado originalmente para manipular archivos del Espacio de Nombres de Métricas de Rendimiento (PMNS) para Performance Co-Pilot (PCP), pero que luego se generalizó para proporcionar bloques condicionales, procesamiento de archivos de inclusión, ejecución de comandos shell en línea y sustitución de macros para archivos arbitrarios. Se usa más comúnmente de forma interna para procesar los archivos PMNS después de que se llama a pmLoadNameSpace(3) o pmLoadASCIINameSpace(3) y para preprocesar los archivos de configuración para pmlogger(1).

Las líneas de entrada se leen de archivo_entrada (o de la entrada estándar si no se especifica archivo_entrada), se procesan y se escriben en archivo_salida (salida estándar si no se especifica archivo_salida).

Todos los comentarios estilo C de la forma /* ... */ se eliminan del flujo de entrada.

No hay macros predefinidas para pmcpp, aunque las macros pueden definirse en la línea de comandos usando la opción -D, donde nombre y valor deben seguir las mismas reglas descritas a continuación para la directiva #define.

pmcpp acepta las siguientes directivas en el flujo de entrada (como cpp(1)):

  • #include "nombre_archivo"
    o
    #include <nombre_archivo>
    En cualquier caso, la ruta de búsqueda de directorios para nombre_archivo intenta primero nombre_archivo, luego el directorio de archivo_entrada de la línea de comandos (si existe), seguido de cualquier directorio nombrado en los argumentos de línea de comandos -I, y finalmente el directorio $PCP_VAR_DIR/pmns (este último es por compatibilidad retroactiva con versiones anteriores de pmcpp y el uso implícito desde pmLoadASCIINameSpace(3)). Las directivas #include pueden anidarse, hasta una profundidad máxima de 5.
  • #shell "comando"
    o
    #shell 'comando'
    El comando shell se ejecutará y la salida estándar se insertará en el flujo de datos para ser procesado por pmcpp. Funcionalmente, esto es similar a una directiva #include, excepto que las líneas de entrada se leen de un comando en lugar de un archivo. La directiva #shell es más útil para incluir o excluir directivas #define o #undef basadas en la lógica de ejecución en tiempo de ejecución en el comando.
  • #define nombre valor
    o
    #define nombre "valor"
    o
    #define nombre 'valor'
    Define un valor para la macro nombre, que debe ser un nombre válido al estilo C, por lo que un carácter alfabético o guion bajo inicial seguido de cero o más caracteres alfanuméricos o guiones bajos. valor es opcional (y por defecto es una cadena vacía). No hay mecanismo de escape de caracteres, pero se pueden usar comillas simples o dobles para definir un valor con caracteres especiales o espacios en blanco horizontales incrustados (sin saltos de línea).
  • #undef nombre
    Elimina la definición de macro, si la hay, para nombre.
  • #ifdef nombre
    ...
    #endif
    o
    #ifndef nombre
    ...
    #endif
    Las líneas circundantes se eliminarán o incluirán, dependiendo de si la macro nombre está definida o no.
  • #else
    Dentro de un bloque #ifdef o #ifndef, se puede usar #else para delimitar las líneas a incluir si la condición "if" anterior es falsa.

La sustitución de macros se logra dividiendo el flujo de entrada en palabras separadas por espacios en blanco o caracteres que no son válidos en un nombre de macro, es decir, no alfanuméricos y no guion bajo. Cada palabra se verifica y si coincide con un nombre de macro, la palabra se reemplaza por el valor de la macro, de lo contrario, la palabra permanece sin cambios.

Generalmente hay una línea de salida por cada línea de entrada, aunque la línea puede estar vacía si el texto ha sido eliminado debido al manejo de comentarios o directivas condicionales. Cuando hay un cambio en el flujo de entrada, se genera una línea de salida adicional con el formato:

# número_línea "nombre_archivo"

para indicar que la siguiente línea de salida corresponde a la línea número número_línea del archivo de entrada nombre_archivo.

OPCIONES

Las opciones disponibles en la línea de comandos son:

-D nombre[=valor], --define=nombre[=valor]
Define una macro con un valor opcional, como se describió anteriormente.
-I dir, --include=dir
Un directorio adicional para buscar archivos de inclusión.
-P
Suprime la generación de líneas de marcadores de línea, descritas anteriormente.
-s, --shell
Cambia el estilo de entrada esperado de tipo C a tipo shell (donde # es un prefijo de comentario). Esto fuerza los siguientes cambios en el comportamiento de pmcpp:
  • El carácter de prefijo de control cambia de # a %, por lo que, por ejemplo, %include en lugar de #include, y %ifdef en lugar de #ifdef.
  • No se realiza ninguna eliminación de comentarios estilo C.
-r, --restrict
Proporciona un control más fino de la expansión de macros; esta opción restringe la sustitución de macros a palabras que coinciden con los patrones #nombre o #{nombre} o, si se especifica -s, entonces %nombre o %{nombre}. En este modo, el nombre de la macro solo en el flujo de entrada nunca se expandirá, sin embargo, en las líneas de control (como #ifdef) el nombre de la macro debe aparecer solo sin el carácter de prefijo o las llaves (consulte los EJEMPLOS a continuación).
-?, --help
Muestra el mensaje de uso y sale.

Las características importantes de cpp(1) que NO son soportadas por pmcpp incluyen:

  • Macros con parámetros: las macros de pmcpp solo soportan sustitución de cadenas sin parámetros.
  • #if expr
    ...
    #endif
  • Uso anidado de #ifdef o #ifndef.
  • Eliminación de comentarios estilo C++, como en //.
  • Recuperación de errores: el primer error encontrado por pmcpp será fatal.
  • Opciones de línea de comandos de cpp(1) como -o, -W, -U y -x.

pmcpp(1) - Arch manual pages

NAME

pmcpp - Preprocessor for PCP client configuration files

SYNOPSIS

pmcpp [options] [defines...] [input file]

DESCRIPTION

The pmcpp utility is a simple C preprocessor adapted for use with PCP client configuration files. It is typically used to process the standard PCP client configuration file '/etc/pcp.conf', but can be used on any text file that uses C-style preprocessor directives.

The primary use of pmcpp is to support conditional inclusion of configuration directives based on the presence or absence of pre-defined macros.

The default behavior is to read from standard input and write to standard output.

OPTIONS

Supported options:

-D name[=value]
Define a macro name, optionally with a string value. This is equivalent to the C preprocessor's #define directive.
-I path
Add path to the list of directories to search for include files specified by #include directives.
-U name
Undefine a macro name.
-C
Make the preprocessor copy comments from the input to the output.
-c
Make the preprocessor copy comments from the input to the output, and replace each input comment beginning with a newline with a single newline in the output.
-H
Print the names of included files.
-P
Inhibit the addition of line number information (like #line "file" lineno) to the output.
-R
Print the names of files included via #include directives in the output.
-s
Inhibit the addition of leading newlines to the output.
-r
Inhibit the addition of trailing newlines to the output.
-W
Enable all warnings.
-w
Disable all warnings.
-Warning
Disable warnings specified by Warning. Consult the documentation for the underlying C preprocessor for a list of possible warnings.
+Warning
Enable warnings specified by Warning. Consult the documentation for the underlying C preprocessor for a list of possible warnings.
-X directive
Do not process the specified preprocessor directive. Multiple -X options can be used.
--help
Display help text and exit.
--version
Display version information and exit.

EXAMPLES

The following examples show the behavior of pmcpp with and without the -D option.

Command: pmcpp Command: pmcpp -D want_cpu
Input Output
# get logging frequencies # get logging frequencies
# e.g. dk_freq macro # e.g. dk_freq macro
%include "frequencies" log mandatory on 1min { disk.dev }
log mandatory on %dk_freq { # note no %want_cpu here
disk.dev %ifdef want_cpu %define cpu_pfx 'kernel.all.cpu.' log mandatory on %cpu_freq { %{cpu_pfx}user %{cpu_pfx}sys } %endif
}
# note no %want_cpu here
%ifdef want_cpu
%define cpu_pfx 'kernel.all.cpu.'

%{cpu_pfx}user

}
%endif

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).
