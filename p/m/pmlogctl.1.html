PMLOGCTL(1) Manual de comandos generales PMLOGCTL(1)

NOMBRE

pmlogctl - administra y controla los archivadores de Performance Co-Pilot

SINOPSIS

pmlogctl [-afmNV?] [-C check_args] [-c clase] [-i ident] [-p política] comando [host ...]

DESCRIPCIÓN

pmlogctl puede usarse para administrar instancias *no primarias* del archivador de Performance Co-Pilot (PCP) pmlogger(1). Esto sería más relevante en una "granja" de archivadores de PCP donde muchas instancias de pmlogger(1) crearían archivos de datos de rendimiento recopilados desde pmcd(1) en muchos hosts remotos.

La instancia *primaria* de pmlogger(1) está estrechamente vinculada al proceso local de pmcd(1) y, como consecuencia, comparte la misma infraestructura de control, a saber systemd(1) o los "scripts rc" de PCP init(1). Es por eso que la instancia *primaria* de pmlogger(1) *no puede* ser administrada con pmlogctl.

Para brevedad en la descripción a continuación, el término "instancia" significa una instancia de pmlogger(1).

Todas las instancias administradas por pmlogctl, pmlogger_check(1) y pmlogger_daily(1) cumplen las siguientes reglas:

1.
Cada instancia extrae datos de rendimiento de un único pmcd(1) (es decir, un host), pero cada pmcd(1) puede proporcionar datos de rendimiento a cero, una o más instancias de pmlogger(1) ejecutándose en uno o más hosts.
2.
En el host local, cada instancia de pmlogger(1) debe especificarse una vez en un archivo de control de pmlogger_check(1) y pmlogger(1) crea archivos en un directorio único, nombrado en el 4to parámetro de la entrada del archivo de control asociada (ver la sección CONFIGURACIÓN de pmlogger_check(1)).
3.
Cada instancia pertenece exactamente a una clase, nombrada opcionalmente usando una asignación $clase=... en el archivo de control asociado. La clase especial default está reservada para todas las instancias que no tienen una asignación asociada de $clase=.... Para fines de informes (consultar el comando summary a continuación), la instancia *primaria* de pmlogger(1) se asigna automáticamente a la clase especial primary.

Cada ejecución de pmlogctl administra una o más instancias, actualizando los archivos de control asociados y luego ejecutando pmlogger_check(1) para efectuar el cambio deseado.

Los argumentos host suelen ser nombres de host válidos. Para todos los comandos *excepto* create y cond-create (descritos a continuación), los argumentos host también pueden ser expresiones regulares de egrep(1) que coinciden con la totalidad de un nombre de host válido, por lo que el patrón utilizado es realmente ^host$. Por ejemplo, foo.* (coincide con todos los nombres de host que comienzan con "foo") o .*foo (coincide con todos los nombres de host que terminan en "foo") o .*[fF][oO][oO].* (coincide con todos los nombres de host que contienen "foo" en mayúsculas, minúsculas o mixtas).

La combinación de una clase de la opción opcional -c (o default) y los argumentos host para cada comando identifica un *conjunto objetivo* de instancias al que se aplicará la operación comando.

La opción -i puede usarse con los comandos create o cond-create para anular la identidad de la instancia que se especifica en la sección de identificación del archivo de política de clase (ver la sección ARCHIVO DE POLÍTICA DE CLASE a continuación). Dado que el identificador debe ser único entre todas las instancias y todas las clases, solo tiene sentido usar esta opción cuando hay un único argumento host.

Dadas las tareas que pmlogctl está realizando, generalmente debe ejecutarse como "root", excepto los comandos status o cuando se especifica la opción -N.

COMANDOS

comando es uno de los siguientes:

check
Verifica el estado de todas las instancias de pmlogger configuradas actualmente y reinicia las que han fallado. Si se proporciona la bandera -m en plataformas systemd(1), también migra los procesos coincidentes (y nuevos) al servicio pmlogger_farm.
create
Crea nuevas instancias en la clase clase_nombre (default por defecto) para los hosts host. El nombre de la clase se usa para identificar un archivo de política de clase (ver la sección ARCHIVO DE POLÍTICA DE CLASE a continuación) que proporciona una plantilla para cada nuevo archivo de control con %h reemplazado por host y %i reemplazado por el identificador (único) de la instancia de la sección de identificación del archivo de política de clase o ident de la opción -i.

La opción -p puede usarse para identificar un archivo de política de clase diferente al que se encuentra en la ubicación estándar, es decir, $PCP_SYSCONF_DIR/pmlogger/class.d/clase_nombre.

Se debe especificar al menos un host para el comando create.

cond-create
Similar a create pero la instancia solo se creará si una de las condiciones en la sección de creación de los archivos de política de clase asociados se evalúa como verdadera.

Si se especifica una opción -c, entonces solo se considerará la clase clase_nombre, de lo contrario se considerarán *todas* las clases. En este último caso, si ninguna de las condiciones en alguna de las clases se evalúa como verdadera, se utiliza la clase especial pmfind (esta es la clase ``default'' para el comando cond-create cuando todo lo demás falla).

Si más de una clase se evalúa como verdadera, se crea un archivo de configuración de pmlogger(1) compuesto y la instancia también se asigna a la clase especial pmfind. El archivo de configuración compuesto puede contener una mezcla de cláusulas de configuración explícitas y cláusulas de configuración condicionales más generales, según lo entiende la herramienta pmlogconf(1).

start
Inicia el conjunto objetivo de instancias.

Si el conjunto objetivo contiene intencionalmente más de una instancia, se debe usar la opción -a (esto está diseñado para reducir el riesgo de iniciar accidentalmente un número potencialmente grande de procesos de pmlogger(1)).

Si una instancia en el conjunto objetivo ya está iniciada, no se realiza ningún cambio (ver el comando restart para forzar el lanzamiento de nuevas instancias).

stop
Detiene el conjunto objetivo de instancias.

Si el conjunto objetivo contiene intencionalmente más de una instancia, se debe usar la opción -a (esto está diseñado para reducir el riesgo de detener accidentalmente un número potencialmente grande de procesos de pmlogger(1)).

Si una instancia en el conjunto objetivo ya está detenida, se emite una advertencia.

restart
Detiene y luego inicia el conjunto objetivo de instancias.

Si el conjunto objetivo contiene intencionalmente más de una instancia, se debe usar la opción -a (esto está diseñado para reducir el riesgo de detener y luego iniciar accidentalmente un número potencialmente grande de procesos de pmlogger(1)).

Si una instancia en el conjunto objetivo ya está detenida, se emite una advertencia antes de iniciar la instancia.

status
Informa el estado del conjunto objetivo de instancias. Si no se especifica la opción -c y no hay argumentos host, es decir, el conjunto objetivo está vacío, se informarán *todas* las instancias.
destroy

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

>
Destruye el conjunto de instancias objetivo. Al finalizar esta operación, los procesos pmlogger(1) asociados se habrán detenido y se habrá eliminado la información pertinente del archivo de control.

Si el conjunto objetivo contiene intencionadamente más de una instancia, se debe usar la opción -a (esto está diseñado para reducir el riesgo de terminar accidentalmente un número potencialmente grande de procesos pmlogger(1) y eliminar sus configuraciones de pmlogger_check(1)).

El archivo de políticas vinculado a la clase de una instancia a destruir puede contener una sección destroy que puede influir en si y cómo se debe realizar la operación de destrucción. Esto puede requerir la opción -p para encontrar el archivo de políticas de clase asociado.

La comprobación de políticas de clase puede omitirse utilizando la opción de línea de comandos -f (force).

ARCHIVO DE POLÍTICAS DE CLASE

Un archivo de políticas de clase contiene varias secciones; cada sección comienza con una línea que simplemente empieza con el nombre de la sección entrecorchado por ``['' y ``]''.

Las líneas que comienzan con un signo de almohadilla (#) se tratan como comentarios y se ignoran. Las líneas en blanco o vacías también se ignoran.

La ubicación típica del archivo de políticas para la clase foo es $PCP_SYSCONF_DIR/pmlogger/class.d/foo.

[class]
La sección opcional de nombre de clase nombra la clase. Si falta, el nombre del archivo de políticas (despojado de cualquier prefijo de directorio) se utiliza como nombre de la clase.
[ident]
La sección ident especifica la plantilla que se utilizará para el identificador de instancia que se asignará a cada miembro de la clase. Este identificador debe ser único entre todas las instancias y todas las clases, y debe ser un nombre de archivo válido en el sistema de archivos local, por lo que normalmente contendrá el nombre de la clase y la macro %h, por ejemplo, foo-%h. La macro se reemplaza por el host cuando se crea cada instancia.
[control]
La sección control consiste en una o más líneas de texto plantilla que se utilizarán para crear el archivo de control para cada instancia. Esto debe incluir al menos la línea de control de pmlogger_check(1) para especificar cómo iniciar el proceso pmlogger(1) asociado; esta línea contiene campos separados por espacios en blanco de la siguiente manera:
1.
el nombre del host, usualmente la macro %h
2.
n para indicar que esta es una instancia no principal
3.
el indicador de ``socks'', típicamente n
4.
el directorio en el que se crearán los archivos de registro de pmlogger(1); esto necesita ser único y generalmente se especifica usando la macro de pmlogger_check(1) PCP_ARCHIVE_DIR como inicio de la ruta, seguido del identificador de instancia, usualmente la macro %i, por ejemplo, PCP_ARCHIVE_DIR/%i
5.
parámetros adicionales para pmlogger(1) que probablemente incluyan al menos una opción -c para proporcionar un archivo de configuración que describa qué métricas se deben registrar para las instancias de esta clase, que puede ser la misma para todas las instancias de esta clase, o puede incluir la macro %i para usar un archivo de configuración diferente para cada instancia. Tenga en cuenta que si este archivo de configuración no existe, se creará usando pmlogconf(1) la primera vez que se ejecute pmlogger_check(1).

Antes de la línea de control debe haber una línea que defina la versión de la línea de control que sigue, es decir,
$version=1.1
Si esto falta, pmlogctl asumirá que la versión es 1.1 e insertará la línea cuando se cree la instancia.

pmlogctl también agregará el nombre de la clase durante la creación. por ejemplo,
$class=foo

Dentro de una plantilla de línea de control, se admite una forma simple de sustitución paramétrica. La macro ENV(spec) se reemplaza por texto usando variables de entorno de la siguiente manera:

  • Si spec tiene la forma var, entonces se usa el valor de $var del entorno. Si $var no está definido o tiene el valor de una cadena vacía, esto es un error.
  • Si spec tiene la forma var:default, entonces si $var del entorno está definido y no es una cadena vacía, se usa el valor de $var; de lo contrario, se usa el valor default. La sustitución es simple, por lo que cualquier espacio en blanco entre el : y el ) se incluye en default, y default no puede contener un ).

Como ejemplo
# unset PMPROXY_PORT; PMPROXY_HOST=foobar.com pmlogctl create ...
con una línea de plantilla de control de clase de política que incluye http://ENV(PMPROXY_HOST):ENV(PMPROXY_PORT:44322)
generará una línea de control que incluye
http://foobar.com:44322

[create]
La sección create define las condiciones que deben cumplirse antes de que se cree una instancia con el comando cond-create. La intención es permitir tomar diferentes decisiones cuando se descubre un nuevo host que ejecuta pmcd(1), por ejemplo, por pmfind(1).

Cada línea no en blanco en la sección create es una condición de la forma function(arg), donde function es una de las siguientes:

exists
arg es el nombre de una métrica de rendimiento y exits se evalúa como verdadero si esa métrica existe en el Espacio de Nombres de Métricas de Rendimiento (PMNS) en el host remoto
values
arg es el nombre de una métrica de rendimiento en el PMNS remoto y values se evalúa como verdadero si alguna instancia de esa métrica tiene un valor en el host remoto
condition
arg es una expresión de métrica derivada en el formato compatible con pmRegisterDerived(3), y condition se evalúa como verdadero si el valor de esa expresión en el host remoto es mayor que cero
hostname
arg es una expresión regular al estilo de egrep(1) y hostname se evalúa como verdadero si el nombre del host remoto coincide con arg
[destroy]
La sección destroy define la política que se aplicará cuando se destruya una instancia.

La intención es permitir tomar diferentes decisiones cuando el servicio de descubrimiento, por ejemplo, pmfind(1), nota que un host asociado con una instancia ya no está presente. Pero en la versión actual esto no está implementado y la sintaxis y semántica de la sección destroy aún no están definidas.

Un archivo de políticas de clase de ejemplo es el siguiente:

# archivo de políticas para la clase foo
[class]
foo
[ident]
foo-%h
[control]
$version=1.1
%h n n PCP_ARCHIVE_DIR/%i -c foo-metrics.config
[create]
# coincide con todos los hosts
hostname(.*)
[destroy]
# aún por definir

OPCIONES

Las opciones de línea de comandos disponibles son:

-a, --all
Aplica la acción a todas las instancias coincidentes. Por defecto, solo se espera y se actúa sobre una definición de instancia.
-c clase, --class=clase
Establece el nombre de la clase a la que pertenecen las instancias de pmlogger(1) como clase.
-C check_args, --checkargs=check_args
check_args son argumentos de línea de comandos adicionales para pmlogger_check(1) cuando se llama. Esto es más útil para opciones como -V. Se pueden usar múltiples opciones -C y los diversos argumentos check_args se acumularán y se pasarán todos a pmlogger_check(1).
-f, --force
Fuerza la acción si es posible.
-i ident, --ident=ident
Anula el identificador de instancia con ident. Esta opción se aplica solo a los comandos create y cond-create.
-N, --showme
Ejecuta pmlogctl en modo ``mostrarme'' o ``ejecución de prueba'' donde se muestra la intención del comando, pero no se realizan cambios.
-m, --migrate
Cuando se usa con los comandos create o check en plataformas systemd(1), también migra procesos pmlogger no primarios nuevos o existentes al servicio pmlogger_farm. Esto normalmente lo realiza automáticamente el servicio pmlogger_farm_check, que se basa en temporizadores (por lo que puede haber un retraso de unos minutos antes de que se inicie la migración automática).
-p política, --policy=política
Utiliza política como archivo de políticas de clase. Por defecto, es $PCP_SYSCONF_DIR/pmlogger/class.d/<clase>.
-V, --verbose
Habilita el modo detallado. Usar esta opción dos veces aumenta la verbosidad. La salida detallada se escribe en stderr.
-?, --help
Muestra el mensaje de uso y sale.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede utilizarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).
