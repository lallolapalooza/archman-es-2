pmLookupDesc(3)

Paquete: pcp

PMLOOKUPDESC(3) Manual de funciones de biblioteca PMLOOKUPDESC(3)

NOMBRE

pmLookupDesc, pmLookupDescs - obtener descripciones para métricas de rendimiento

SINOPSIS C

#include <pcp/pmapi.h>

int pmLookupDesc(pmID pmid, pmDesc *desc);
int pmLookupDescs(int numpmid, pmID *pmids, pmDesc *descs);

cc ... -lpcp

DESCRIPCIÓN

Dada una Identificación de Métrica de Rendimiento (PMID) como pmid, la rutina pmLookupDesc rellena la estructura pmDesc dada, apuntada por el parámetro desc, desde el contexto actual de la Interfaz de Programación de Aplicaciones de Métricas de Rendimiento (PMAPI).

La variante pmLookupDescs proporciona funcionalidad equivalente para numpmid métricas a la vez, con la matriz pmids proporcionando los identificadores de métrica a buscar. Es más eficiente a medida que aumenta el número de métricas, ya que evita la latencia de ida y vuelta de múltiples solicitudes individuales. Tenga en cuenta que el protocolo de error garantiza que existe una relación 1:1 entre los elementos de descs y pmids, por lo tanto, ambas listas contienen exactamente numpmid elementos. Por esta razón, se espera que el llamador haya preasignado una matriz de tamaño adecuado para descs.

La estructura pmDesc proporciona toda la información necesaria para describir y manipular una métrica de rendimiento a través de la PMAPI, y tiene la siguiente declaración.

/* Descriptor de Métrica de Rendimiento */
typedef struct {
    pmID    pmid;   /* identificador único */
    int     type;   /* tipo de datos base (ver abajo) */
    pmInDom indom;  /* dominio de instancia */
    int     sem;    /* semántica del valor (ver abajo) *
    pmUnits units;  /* dimensión y unidades (ver abajo) */
} pmDesc;
/* pmDesc.type -- tipo de datos de los valores de métrica */
#define PM_TYPE_NOSUPPORT        -1    /* no implementado en esta versión */
#define PM_TYPE_32               0    /* entero con signo de 32 bits */
#define PM_TYPE_U32              1    /* entero sin signo de 32 bits */
#define PM_TYPE_64               2    /* entero con signo de 64 bits */
#define PM_TYPE_U64              3    /* entero sin signo de 64 bits */
#define PM_TYPE_FLOAT            4    /* punto flotante de 32 bits */
#define PM_TYPE_DOUBLE           5    /* punto flotante de 64 bits */
#define PM_TYPE_STRING           6    /* matriz de char */
#define PM_TYPE_AGGREGATE        7    /* datos binarios arbitrarios */
#define PM_TYPE_AGGREGATE_STATIC 8    /* puntero estático a agregado */
#define PM_TYPE_EVENT            9    /* pmEventArray empaquetado */
#define PM_TYPE_UNKNOWN          255  /* usado en pmValueBlock, no en pmDesc */
/* pmDesc.sem -- semántica/interpretación de los valores de métrica */
#define PM_SEM_COUNTER  1  /* contador acumulativo (incremento monotónico) */
#define PM_SEM_INSTANT  3  /* valor instantáneo, dominio continuo */
#define PM_SEM_DISCRETE 4  /* valor instantáneo, dominio discreto */

El campo type en pmDesc describe varias codificaciones (o formatos) para el valor de una métrica.

Si un valor se cuenta en la instrumentación base subyacente con menos de 32 bits de precisión entera, es responsabilidad del Agente de Dominio de Métricas de Rendimiento (PMDA) promocionar el valor a un entero de 32 bits antes de que sea exportado al Subsistema de Recolección de Métricas de Rendimiento (PMCS); es decir, las aplicaciones por encima de la PMAPI nunca tienen que lidiar con contadores de 8 o 16 bits.

Si el valor de una métrica de rendimiento es de tipo PM_TYPE_AGGREGATE, PM_TYPE_AGGREGATE_STATIC, PM_TYPE_EVENT o PM_TYPE_STRING, la interpretación del valor es desconocida para el PMCS. En estos casos, la aplicación que utiliza el valor y el PMDA que proporciona el valor deben tener algún entendimiento común sobre cómo está estructurado e interpretado el valor.

Se asume que cada valor para una métrica de rendimiento se extrae de un conjunto de valores que pueden ser descritos en términos de su dimensionalidad y escala por una codificación compacta de la siguiente manera. La dimensionalidad se define por una potencia, o índice, en cada una de 3 dimensiones ortogonales, a saber, Espacio, Tiempo y Conteo (o Eventos, que no tienen dimensión). Por ejemplo, el rendimiento de E/S podría representarse como           -1 Espacio.Tiempo
mientras que el total acumulado de llamadas al sistema es Conteo, la asignación de memoria es Espacio y el tiempo de servicio promedio es           -1 Tiempo.Conteo
En cada dimensión existen una serie de valores de escala comunes que pueden utilizarse para codificar mejor rangos que de otro modo agotarían la precisión de un valor de 32 bits. Esta información está codificada en la estructura pmUnits que está incrustada en la estructura pmDesc.

/*
 * Codificación para las unidades (dimensiones Tiempo y Espacio) y la escala
 * para los valores de las métricas de rendimiento
 *
 * Por ejemplo, una estructura pmUnits de
 *      { 1, -1, 0, PM_SPACE_MBYTE, PM_TIME_SEC, 0 }
 * representa Mbytes/seg, mientras que
 *      { 0, 1, -1, 0, PM_TIME_HOUR, 6 }
 * representa horas/millones de eventos
 */
typedef struct {
    int dimSpace:4;             /* dimensión espacio */
    int dimTime:4;              /* dimensión tiempo */
    int dimCount:4;             /* dimensión evento */
    unsigned int scaleSpace:4;  /* uno de PM_SPACE_* abajo */
    unsigned int scaleTime:4;   /* uno de PM_TIME_* abajo */
    int scaleCount:4;           /* uno de PM_COUNT_* abajo */
} pmUnits;                      /* unidades dimensionales y escala del valor */
/* pmUnits.scaleSpace */
#define PM_SPACE_BYTE   0       /* bytes */
#define PM_SPACE_KBYTE  1       /* Kilobytes (1024) */
#define PM_SPACE_MBYTE  2       /* Megabytes (1024^2) */
#define PM_SPACE_GBYTE  3       /* Gigabytes (1024^3) */
#define PM_SPACE_TBYTE  4       /* Terabytes (1024^4) */
#define PM_SPACE_PBYTE	5	/* pebibytes (1024^5) */
#define PM_SPACE_EBYTE	6	/* exbibytes (1024^6) */
#define PM_SPACE_ZBYTE	7	/* zebibytes (1024^7) */
#define PM_SPACE_YBYTE	8	/* yobibytes (1024^8) */
/* pmUnits.scaleTime */
#define PM_TIME_NSEC    0       /* nanosegundos */
#define PM_TIME_USEC    1       /* microsegundos */
#define PM_TIME_MSEC    2       /* milisegundos */
#define PM_TIME_SEC     3       /* segundos */
#define PM_TIME_MIN     4       /* minutos */
#define PM_TIME_HOUR    5       /* horas */
/*
 * pmUnits.scaleCount (ej. contar eventos, llamadas al sistema, interrupciones,
 * etc.) estas son simplemente potencias de 10, y no se enumeran aquí,
 * ej. 6 para 10^6, o -3 para 10^-3
 */
#define PM_COUNT_ONE    0       /* 1 */

Se proporcionan rutinas especiales (por ejemplo, pmExtractValue(3), pmConvScale(3)) para manipular valores en conjunción con la estructura pmUnits que define la dimensión y escala de los valores para una métrica de rendimiento particular.

Por debajo de la PMAPI, la información necesaria para completar la estructura pmDesc se obtiene de los PMDA, y de esta manera el formato y la escala de las métricas de rendimiento pueden cambiar dinámicamente, a medida que los PMDA y su instrumentación subyacente evolucionan con el tiempo. En particular, cuando algunas métricas se vuelven repentinamente de 64 bits de longitud, o cambian sus unidades de Mbytes a Gbytes, las aplicaciones bien escritas que utilizan los servicios proporcionados por la PMAPI continuarán funcionando correctamente.

DIAGNÓSTICO

Estas rutinas devuelven un código de error negativo para indicar fallo.

PM_ERR_PMID
El PMID solicitado no es conocido por el PMCS
PM_ERR_NOAGENT
El PMDA responsable de proporcionar la métrica no está disponible actualmente

pmLookupDesc devuelve cero para indicar éxito.

El resultado de pmLookupDescs depende de la presencia de cualquier fallo de búsqueda, su gravedad y el número de métricas que se están buscando.

1.
Si no hay fallos de búsqueda, el valor de retorno será numpmid.
2.
Si se encuentra un error fatal, el valor de retorno será menor que 0. Por ejemplo, PM_ERR_IPC.
3.
Si numpmid es mayor que uno y se encuentran errores no fatales, el valor de retorno es el número de descriptores de métricas que se han buscado con éxito (mayor o igual a cero y menor o igual a numpmid).
4.
Si numpmid es uno y se encuentra un error no fatal, el valor de retorno es el código de error (menor que cero).

Cuando se encuentran errores, las métricas que no se pueden buscar resultan en que el elemento descriptor correspondiente de descs tenga su campo pmid establecido en PM_ID_NULL. El protocolo de error ligeramente rebuscado permite búsquedas masivas, y luego la investigación para obtener más detalles del error en caso de un fallo específico.
