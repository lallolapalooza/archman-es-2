PMSETMODE(3) Manual de Funciones de Biblioteca PMSETMODE(3)

NOMBRE

pmSetMode - establece los parámetros de tiempo y modo de recolección para el contexto actual de PMAPI

C SINOPSIS

#include <pcp/pmapi.h>

int pmSetMode(int mode,
const struct timespec *when, const struct timespec *delta);

cc ... -lpcp

DESCRIPCIÓN

pmSetMode se utiliza para definir el tiempo de recolección y/o el modo de acceso a métricas de rendimiento y metadatos en el contexto actual de la Interfaz de Programación de Aplicaciones de Métricas de Rendimiento (PMAPI). Este modo afecta la semántica de las llamadas posteriores a las siguientes rutinas de PMAPI: pmFetch(3), pmFetchArchive(3), pmLookupDesc(3), pmGetInDom(3), pmLookupInDom(3), pmLookupLabels(3) y pmNameInDom(3).

Diseñadas principalmente para el análisis retrospectivo de métricas de rendimiento de un archivo PCP, las opciones descritas a continuación permiten a una aplicación implementar la búsqueda en un tiempo arbitrario dentro del archivo, reproducción, avance rápido, retroceso, etc., alternando llamadas a pmSetMode y pmFetch(3).

Si mode es PM_MODE_LIVE, toda la información se recupera del pool activo de métricas de rendimiento en el momento en que se realiza la llamada a PMAPI, y los otros dos parámetros de pmSetMode (when y delta) se ignoran. PM_MODE_LIVE es el modo predeterminado cuando se crea un nuevo contexto PMAPI con el tipo PM_CONTEXT_HOST (es decir, recuperando métricas de pmcd (1)) o PM_CONTEXT_LOCAL, y este mode rara vez se usa en llamadas a pmSetMode

Los otros valores de mode se utilizan con archivos PCP donde el contexto PMAPI asociado debe ser del tipo PM_CONTEXT_ARCHIVE (cuando se creó con pmNewContext(3)) y el parámetro when define el tiempo actual dentro del archivo. Todas las solicitudes de valores de métricas y metadatos (descripciones de métricas e identificadores de instancias de los dominios de instancias) se procesarán para reflejar el estado en el archivo en el momento actual.

Al seleccionar un valor para when, la hora de inicio del archivo se puede establecer a partir del campo ll_start en la estructura devuelta por una llamada a pmGetArchiveLabel(3) o el campo start en la estructura devuelta por una llamada a pmGetArchiveLabel(3), y la hora de finalización del archivo se puede establecer llamando a pmGetArchiveEnd(3)

Como caso especial, si when es NULL, los argumentos mode y delta se usan como se describe a continuación, pero la hora actual en el archivo no se modifica.

MODO DE ARCHIVO BASADO EN TIEMPO

Si mode es PM_MODE_INTERP, a medida que se recuperan los valores de las métricas del archivo con pmFetch(3), el tiempo actual se devuelve como la marca de tiempo en la estructura pmResult y el tiempo actual avanza; si delta es positivo, el tiempo actual avanza, de lo contrario, el tiempo actual retrocede. El ajuste del tiempo actual se aplica incluso si pmFetch(3) no logra devolver valores para ninguna métrica o devuelve un error, por ejemplo, PM_ERR_EOL porque el tiempo actual está fuera del rango definido por los registros en el archivo.

Cuando se solicitan valores de métricas a través de pmFetch(3), el tiempo actual puede no coincidir exactamente con los momentos en que se han registrado valores en el archivo, por lo que los valores de métricas devueltos se calculan a partir de los valores de métricas observados en el archivo (generalmente en momentos cercanos al tiempo actual).

Para métricas con semántica de PM_SEM_COUNTER, el valor calculado se basa en la interpolación lineal entre la última observación antes del tiempo actual y la primera observación después del tiempo actual.

Para métricas con semántica de PM_SEM_INSTANT o PM_SEM_DISCRETE, el valor calculado se basa en valores en el vecindario del tiempo actual.

Los algoritmos utilizados en estos cálculos dependen de la semántica de las métricas y la serie temporal de valores observados en el archivo; una explicación más completa se puede encontrar en el documento técnico Explaining Value Interpolation with PCP Archives en https://pcp.io/papers/archive-interpolation.pdf.

MODOS DE ARCHIVO BASADOS EN REGISTROS

Si mode es PM_MODE_FORW o PM_MODE_BACK, cuando se solicitan valores de métricas a través de pmFetch(3), el archivo se escaneará en dirección hacia adelante (PM_MODE_FORW) o hacia atrás (PM_MODE_BACK) en el tiempo, hasta que se encuentre un registro de archivo con valores para al menos una de las métricas solicitadas. Este registro de archivo se utiliza para proporcionar tantas métricas solicitadas como sea posible y se devuelven con la marca de tiempo si el registro en el archivo, que se convierte en el nuevo tiempo actual.

Tenga en cuenta que cualquier métrica solicitada a través de pmFetch(3) que no tenga un valor en el registro del archivo en el nuevo tiempo actual no devolverá ningún valor, por lo que este modo es más útil para archivos donde todas las métricas de interés se han registrado regularmente al mismo tiempo en el archivo. De lo contrario, cada pmFetch(3) contendrá solo el subconjunto de las métricas solicitadas y cualquier instancia asociada encontrada en el registro de archivo calificado.

El parámetro delta se ignora, ya que el tiempo actual es impulsado por la marca de tiempo en el registro de archivo coincidente. Por lo tanto, no hay un concepto de avance a través del archivo en intervalos de tiempo regulares con este modo, aunque si las métricas solicitadas aparecen a intervalos regulares en el archivo, el tiempo actual puede avanzar por intervalos regulares, pero esto es serendipia.

Si no se pueden encontrar métricas calificadas en la dirección de búsqueda solicitada antes de que se encuentre el final o el principio del archivo, pmFetch(3) devuelve el indicador de error especial, PM_ERR_EOL.

RECOMENDACIONES

Al procesar archivos PCP, se prefiere PM_MODE_INTERP porque:

  • Esto maximiza la información que se devolverá en cada pmFetch(3)
  • Esto devuelve valores a intervalos regulares de tiempo actual, independientemente de la frecuencia de registro de las métricas solicitadas en el archivo.
  • Esto funciona con cualquier archivo PCP, a diferencia de los modos basados en registros que pueden funcionar de manera aceptable para archivos con registro regular de todas las métricas solicitadas, pero pueden fallar en informar resultados completos o útiles para otros archivos.
  • Este modo proporciona la coincidencia semántica más cercana a PM_MODE_LIVE y conduce a la menor sorpresa para el usuario al pasar de la monitorización en tiempo real al análisis retrospectivo.

EJEMPLOS

Para reproducir métricas interpoladas de un archivo a intervalos de 10 segundos, se podría utilizar el siguiente fragmento de código:

struct timeval mytime;
int mydelta = 10 * 1000;      /* msec */
pmLogLabel label;
pmResult result;
pmNewContext(PM_CONTEXT_ARCHIVE, "myarchive");
pmGetArchiveLabel(&label);
mytime = label.ll_start;
pmSetMode(PM_MODE_INTERP, &mytime, mydelta)
while (pmFetch(numpmid, pmidlist, &result) != PM_ERR_EOL) {
    /*
     * procesar valores de métricas interpoladas a las
     * result->timestamp
     */
    . . .
    pmFreeResult(result);
}

El siguiente fragmento de código puede usarse para volcar valores de métricas seleccionadas en un archivo en secuencia temporal inversa.

struct timespec mytime;
pmResult result;
pmNewContext(PM_CONTEXT_ARCHIVE, "myarchive");
pmGetArchiveEnd(&mytime);
pmSetMode(PM_MODE_BACK, &mytime, NULL);
while (pmFetch(npmid, pmidlist, &result) != PM_ERR_EOL) {
    /*
     * procesar valores de métricas registrados a las
     * result->timestamp
     */
    . . .
    pmFreeResult(result);
}

COMPATIBILIDAD

El comportamiento de PM_MODE_INTERP se ha modificado para usar interpolación lineal para contadores y un método de vecindad para instantáneas para proporcionar valores más precisos.

COMPATIBILITY

Antes de PCP 7.0, el argumento when era una struct timeval y el argumento delta era un int (en unidades de milisegundos). Para soportar la transición de PMAPI, la interfaz y la semántica antiguas pueden ser utilizadas si las aplicaciones se recompilan con -DPMAPI_VERSION=2.

Durante un tiempo en PCP 6.x, existió una rutina con la misma semántica que la actual pmSetMode llamada pmSetModeHighRes, aunque ahora está obsoleta y el soporte a nivel de compilación para pmSetModeHighRes será eliminado en una futura versión.

DIAGNOSTICS

PM_ERR_MODE
El parámetro mode es inválido
