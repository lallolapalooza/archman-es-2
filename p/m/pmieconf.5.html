PMIECONF(5) Manual de formatos de archivo PMIECONF(5)

NOMBRE

pmieconf - reglas y personalizaciones generalizadas de pmie

DESCRIPCIÓN

Los formatos de archivo pmieconf son utilizados por la herramienta pmieconf(1) como una forma de generalizar los conjuntos de reglas de pmie(1) para que puedan configurarse fácilmente para diferentes sistemas y entornos. Aquí se discuten dos formatos de archivo completamente diferentes (aunque estrechamente relacionados), a saber, ``pmieconf-rules'' y ``pmieconf-pmie''.

El directorio $PCP_VAR_DIR/config/pmieconf contiene información sobre todas las reglas y variables generalizadas predeterminadas del sistema pmie, incluidos los valores predeterminados para todas las variables. Estos archivos están en el formato pmieconf-rules. Aunque se pueden agregar nuevos archivos pmieconf-rules, los archivos en este directorio nunca deben modificarse. En su lugar, utilice la utilidad pmieconf para cambiar los valores de las variables en el archivo de configuración pmie.

El formato pmieconf-pmie permite personalizaciones específicas del sitio de las reglas contenidas en los archivos pmieconf-rules y sus variables asociadas. El formato pmieconf-pmie es generado por pmieconf y no debe ser editado manualmente. Este archivo generado está en el formato pmie, con información adicional al principio del archivo; por lo tanto, el formato pmieconf-pmie es un superconjunto del formato de archivo pmie (extendido para contener personalizaciones de las reglas generalizadas, pero también conteniendo las reglas de rendimiento reales para que pmie las evalúe) que también puede ser analizado por pmie (todas las extensiones están ocultas dentro de comentarios y, por lo tanto, no tienen significado para pmie en sí mismo).

El archivo $PCP_VAR_DIR/config/pmieconf/config.pmie contiene la configuración del sistema local para las variables configurables de pmieconf. La configuración de variables en este archivo reemplaza los valores predeterminados especificados en $PCP_VAR_DIR/config/pmieconf/*/*.

SINTAXIS PMIECONF-PMIE

Todas las líneas de personalización de reglas en una especificación válida de pmieconf-pmie están precedidas por ``//'' y se encuentran al principio del archivo; esto permite que los archivos que contienen una especificación de pmieconf-pmie sean analizados con éxito por pmie. Un pmieconf-pmie siempre debe tener la primera línea con el formato:

    // pmieconf-pmie version pmieconf_path

La version especifica qué versión de la sintaxis pmieconf-pmie se debe utilizar para analizar este archivo. Actualmente, la única versión compatible es 1. La pmieconf_path especifica la ruta a los archivos pmieconf-rules que fueron utilizados por pmieconf para generar este archivo. Esto se discute en la página del manual de pmieconf(1) (vea la opción -r).

El resto de la especificación consiste en entradas de una línea para cada una de las variables modificadas. La sintaxis de cada línea es:

    // rule_version rule_name rule_variable = value

La rule_version y rule_name se utilizan para identificar la regla con la que asociar la personalización. Estos van seguidos del nombre de la rule_variable (es decir, la variable de la regla rule_name que ha sido cambiada) para la cual se utilizará el nuevo value.

Una especificación pmieconf-pmie debe terminar con la palabra clave ``end''. Esto es utilizado por pmieconf para distinguir dónde terminan las personalizaciones y comienza el componente de regla pmie real.

EJEMPLO PMIECONF-PMIE

El siguiente ejemplo es un archivo válido en formato pmieconf-pmie, tal como lo genera pmieconf. Para realizar cambios manualmente que sean preservados por pmieconf, consulte los comentarios contenidos en el archivo generado (abajo) sobre dónde se deben realizar dichos cambios.

    // pmieconf-pmie 1 $PCP_VAR_DIR/config/pmieconf
    // 1 memory.exhausted delta = "4 minutes"
    // 1 memory.exhausted enabled = yes
    // 1 memory.exhausted pcplog_action = yes
    // end
    //
    // --- INICIO DE SECCIÓN GENERADA (no cambie esta sección) ---
    //     generado por pmieconf en:  [FECHAHORA]
    //
    // 1 memory.exhausted
    delta = 4 minutes;
    some_host (
        ( avg_sample (swap.pagesout @0..9 ) ) > 0 &&
        30 %_sample swap.pagesout >= 5
    ) -> shell 10 min "$PCP_BINADM_DIR/pmpost Severe demand for real memory" \
            " %vpgsout/s@%h";
    // --- FIN DE SECCIÓN GENERADA (los cambios a continuación se conservarán) ---

Para ver cómo funciona todo esto, puede generar este archivo de la siguiente manera:

    # cat - | pmieconf -f /tmp/pmieconf.out \
        -r $PCP_VAR_DIR/config/pmieconf/memory:$PCP_VAR_DIR/config/pmieconf/global
    modify memory.exhausted delta "4 minutes"
    modify memory.exhausted enabled yes
    modify memory.exhausted pcplog_action yes
    ^D
    #

Luego verifique que el archivo generado sea un archivo de configuración válido de pmie usando:

    # pmie -C /tmp/pmieconf.out

Esto analiza el archivo y luego sale después de informar cualquier error de sintaxis. ¡Ahora reemplace -C con -v (arriba) y observe cómo pmie hace su trabajo!

SINTAXIS PMIECONF-RULES

Una especificación de pmieconf-rules consta de varios objetos de datos separados que juntos forman una especificación de regla completa (tenga en cuenta que una especificación puede abarcar varios archivos e incluso varios subdirectorios). Cada objeto debe tener una cadena de identificador y un tipo de datos, seguido de una lista (opcional) de atributos.

La especificación genérica de un objeto pmieconf-rules es, por lo tanto:

    type identifier [ attribute = value ]* ;

El conjunto de types válidos es: ``rule'' (definición de regla), ``string'' (cadena arbitraria, entre comillas dobles), ``double'', ``integer'', ``unsigned'', ``percent'' (número real entre 0 y 100), ``hostlist'' (lista de nombres de host separados por espacios), ``instlist'' (lista de nombres de instancia métrica separados por espacios), y los cuatro tipos de acción de pmie, a saber, ``print'', ``shell'', ``alarm'' y ``syslog''.

Los nombres de las reglas utilizan el carácter ``.'' para introducir el concepto de un grupo de reglas, por ejemplo, ``memory.exhausted'' asocia esta regla con el grupo ``memory''. pmieconf puede operar tanto a nivel de grupos de reglas como de reglas individuales. El nombre de grupo ``global'' está reservado y no se puede utilizar con ninguna regla.

Por lo general, cuando se crea un objeto, se asocia con la regla actual. Sin embargo, si el nombre de un objeto va precedido por el nombre de grupo reservado ``global'', ese objeto es visible para todas las reglas.

El conjunto de attributes válidos es: ``help'' (texto descriptivo sobre este objeto), ``modify'' (value es sí/no, indica si pmieconf debe permitir cambios), ``enabled'' (value es sí/no, indica si está activado o desactivado; solo tiene significado para reglas y acciones), ``display'' (sí/no; indica si pmieconf debe mostrar este objeto), ``default'' (value determinado por type, y es el valor predeterminado para este objeto), y específicos para objetos de tipo regla son los atributos ``version'', ``predicate'' y ``enumerate''. ``version'' y ``predicate'' son bastante autoexplicativos (``predicate'' debe equivaler a una regla pmie válida cuando se expande), pero ``enumerate'' requiere una mayor discusión.

La cláusula ``enumerate'' es útil cuando se desea generar múltiples reglas pmie similares a partir de un único predicado. Esto es más útil para definiciones de reglas que desean utilizar la cláusula ``some_inst'' en el lenguaje pmie en múltiples hosts. Para que una regla utilice estos juntos, debe estar segura de que la lista de instancias es la misma en todos los hosts monitoreados. Esto rara vez es cierto, por lo que el atributo ``enumerate'' nos permite generar múltiples reglas, expandidas sobre variables de tipo ``instlist'' o ``hostlist''. Estas variables componen el valor para el atributo ``enumerate'', que es una lista separada por espacios de nombres de variables ``instlist'' o ``hostlist''.

Los objetos se pueden incorporar a otras definiciones de objetos utilizando la sintaxis $identifier$. Vea el ejemplo más adelante para obtener más información sobre la utilidad de esto.

Cuando pmieconf está generando el archivo de configuración pmie, mira cada regla habilitada con N acciones habilitadas (donde N > 0) y expande la cadena:

    // "version" identifier
    delta = $delta$;
    "predicate" -> $threshold$ $action1$ & ... & $actionN$;

pmieconf(5) - pmieconf - Performance Co-Pilot

NAME

pmieconf-rules, pmieconf-pmie - pmieconf rule definitions

DESCRIPTION

The pmieconf utility uses configuration files to define rules and related metrics, used by the Performance Metrics Investigator (PMIE) daemon to perform system resource monitoring.

There are two main types of configuration files:

pmieconf-pmie files
These files contain definitions for PMIE rules, specifying conditions that trigger alerts. They are typically located in $PCP_VAR_DIR/config/pmieconf/.
pmieconf-rules files
These files contain definitions for individual rules that can be referenced within pmieconf-pmie files. They are often organized in subdirectories based on resource types (e.g., memory, network).

The configuration files use a specific syntax described below.

PMIECONF-PMIE SYNTAX

A pmieconf-pmie configuration file contains a series of rule definitions. Each rule definition has the following structure:

    rule    <rule_name>
            default = "<default_message>"
            predicate = "<condition_expression>"
            enabled = <yes|no>
            version = <version_number>
            help    = "<help_text>";
  • rule: Keyword indicating the start of a rule definition. <rule_name> is a unique identifier for the rule.
  • default: Specifies the default alert message when the rule is triggered. Can use variables defined elsewhere.
  • predicate: A boolean expression that defines the condition for triggering the alert. This expression can reference other rules or metrics. It uses Performance Metrics Domain (PMID) specifiers and operators.
  • enabled: A boolean value (yes/no) to enable or disable the rule.
  • version: An integer representing the rule version.
  • help: A descriptive string explaining the purpose and meaning of the rule.

Additionally, pmieconf-pmie files can define global variables that can be used across multiple rules:

    variable    <variable_name>
                default = "<default_value>"
                modify  = <yes|no>
                display = <yes|no>;

    string      <string_name>
                default = "<default_string>"
                modify  = <yes|no>
                display = <yes|no>;
  • variable: Defines a numeric variable.
  • string: Defines a string variable.
  • default: The default value for the variable.
  • modify: Allows the variable's value to be modified (yes/no).
  • display: Controls whether the variable is displayed in status outputs (yes/no).

PMIECONF-PMIE EXAMPLE

Here is an example of a pmieconf-pmie file defining a simple alert:

    variable threshold
            default = 100
            modify  = yes
            display = yes;

    rule    disk.full
            default = "Disk partition $mountpt$ is becoming full"
            predicate =
    "host(
        $free%_diskspace$ @default < $threshold$
    )"
            enabled = yes
            version = 1
            help    = "The available free space on the specified disk partition is below the threshold.";

PMIECONF-RULES SYNTAX

pmieconf-rules files are used to define reusable rule components or individual rules that can be included or referenced by pmieconf-pmie files. The syntax is similar to pmieconf-pmie files, but typically focuses on defining a single rule or a set of related metrics/variables.

    rule    <rule_name>
            default = "<default_message>"
            predicate = "<condition_expression>"
            enabled = <yes|no>
            version = <version_number>
            help    = "<help_text>";

    variable    <variable_name>
                default = "<default_value>"
                modify  = <yes|no>
                display = <yes|no>;

    string      <string_name>
                default = "<default_string>"
                modify  = <yes|no>
                display = <yes|no>;

    action      <action_name>
                default = "<action_command>"
                modify  = <yes|no>
                display = <yes|no>;

The action keyword defines a command to be executed when a rule is triggered. The predicate can invoke these actions using the $actionN$ syntax, where N is the action number.

The delta, threshold, and action variables are defined globally (using the "global" keyword) for all rules, but can, of course, be changed at the level of an individual rule or rule group.

PMIECONF-RULES EXAMPLE

The following is an example of a single pmieconf-rules specification, showing a number of different aspects of the language discussed above. The example defines a rule ("memory.exhausted") and a string ("rule").

    rule    memory.exhausted
            default = "$rule$"
            predicate =
    "some_host (
        ( avg_sample (swap.pagesout $hosts$ @0..9 ) ) > 0 &&
        $pct$ %_sample swap.pagesout $hosts$ @0..9 >= $threshold$
    )"
            enabled = yes
            version = 1
            help    =
    "The system is swapping modified pages out of main memory to the
    swap partitions, and has been doing this on at least pct of the
    last 10 evaluations of this rule.
    There appears to be insufficient main memory to meet the resident
    demands of the current workload.";
    string  rule
            default = "Severe demand for real memory"
            modify  = no
            display = no;

Note that for the above rule to be complete, "threshold" and "pct" would also need to be defined - for the full expression of this rule, refer to $PCP_VAR_DIR/config/pmieconf/memory/exhausted.

FILES

$PCP_VAR_DIR/config/pmieconf/*/*
generalized system resource monitoring rules
$PCP_VAR_DIR/config/pmieconf/config.pmie
default super-user settings for system resource monitoring rules
$HOME/.pcp/pmie/config.pmie
default user settings for system resource monitoring rules
