pmiAddMetric(3)

Paquete: pcp

PMIADDMETRIC(3) Manual de funciones de biblioteca PMIADDMETRIC(3)

NOMBRE

pmiAddMetric - añade una nueva definición de métrica a un contexto LOGIMPORT

SINOPSIS C

#include <pcp/pmapi.h>
#include <pcp/import.h>

int pmiAddMetric(const char *name,
pmID pmid, int type, pmInDom indom, int sem, pmUnits units);

cc ... -lpcp_import -lpcp

SINOPSIS Perl

use PCP::LogImport;

pmiAddMetric($name,
$pmid, $type, $indom, $sem, $units);

DESCRIPCIÓN

Como parte de la API de importación de registros de Performance Co-Pilot (ver LOGIMPORT(3)), pmiAddMetric se utiliza para definir una nueva métrica. El nombre de la métrica debe seguir las convenciones de nomenclatura descritas en PCPIntro(1) y debe ser único para cada contexto de LOGIMPORT.

Los otros argumentos son, en efecto, los campos de una estructura pmDesc. Consulte pmLookupDesc(3) para obtener una descripción completa de los valores y semántica de los componentes de esta estructura, y por lo tanto, de los valores de argumento válidos para pmiAddMetric.

El identificador interno para la métrica puede ser proporcionado usando el argumento pmid y debe ser único para cada contexto de LOGIMPORT. El valor para pmid que típicamente se construiría usando la macro pmID_build, por ejemplo, pmID_build(PMI_DOMAIN, 0, 3) para la cuarta métrica en el primer "cluster" de métricas en el Dominio de Métricas de Rendimiento PMI_DOMAIN (que es el predeterminado para todos los metadatos creados por la biblioteca LOGIMPORT). Alternativamente, pmid puede ser PM_IN_NULL y pmiAddMetric asignará un pmid único (aunque esto significa que el pmid permanece opaco y la aplicación debe usar pmiPutValue(3) o pmiPutValueHandle(3) y no puede usar pmiPutResult(3) para añadir valores de datos al archivo PCP).

type define el tipo de datos de la métrica y debe ser uno de los valores PM_TYPE_... definidos en <pcp/import.h>.

El dominio de instancias para la métrica se define por indom y puede ser PM_INDOM_NULL para una métrica con un valor singular, de lo contrario, el valor para indom normalmente se construiría usando la macro pmInDom_build, por ejemplo, pmInDom_build(LOGIMPORT,0) para el primer dominio de instancias en el Dominio de Métricas de Rendimiento LOGIMPORT (que es el predeterminado para todos los metadatos creados por la biblioteca LOGIMPORT). Múltiples métricas pueden compartir el mismo dominio de instancias si tienen valores para un conjunto similar (o más usualmente, idéntico) de instancias.

La semántica de la métrica (contador, valor instantáneo, etc.) se especifica mediante el argumento sem, que normalmente sería el resultado de una llamada al método constructor de conveniencia pmiUnits(3).

DIAGNÓSTICOS

pmiAddMetric devuelve cero si tiene éxito, de lo contrario, un valor negativo que puede convertirse en un mensaje de error llamando a pmiErrStr(3).

VER TAMBIÉN
