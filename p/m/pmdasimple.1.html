PMDASIMPLE(1) Manual de comandos generales PMDASIMPLE(1)

NOMBRE

pmdasimple - agente de dominio de métricas de rendimiento simple (PMDA)

SINOPSIS

$PCP_PMDAS_DIR/simple/pmdasimple [-D debug] [-d dominio] [-i puerto] [-l archivo_log] [-p] [-U usuario] [-u socket]

DESCRIPCIÓN

pmdasimple es un Agente de Dominio de Métricas de Rendimiento (PMDA) simple que exporta un pequeño número de métricas de rendimiento sintéticas.

El PMDA simple se distribuye como código fuente y está diseñado para ayudar a los desarrolladores de PMDA. En términos de tamaño de código y funcionalidades, es más complejo que el PMDA trivial, aproximadamente igual que el PMDA txmon y menos complejo que el PMDA de ejemplo. El código fuente del PMDA simple es una buena plantilla a partir de la cual se pueden desarrollar PMDAs personalizados de producción.

A continuación se presenta una breve descripción de las opciones de línea de comandos de pmdasimple:

-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y coherente. Es decir, dominio debe ser diferente para cada PMDA en un mismo host, y se debe usar el mismo número de dominio para el mismo PMDA en todos los hosts.
-i
Espera que PMCD se conecte a pmdasimple en el puerto TCP/IP especificado. puerto puede ser un número de puerto o un nombre de puerto.
-l
Ubicación del archivo de log. Por defecto, se escribe un archivo de log llamado simple.log en el directorio actual de pmcd(1) cuando se inicia pmdasimple, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de log no se puede crear o no es escribible, la salida se escribe en la salida de error estándar.
-p
Espera que PMCD cree una tubería y la conexión a pmdasimple se realice a través de la entrada estándar y la salida estándar. Este es el modo de conexión predeterminado.
-u
Espera que PMCD se conecte a pmdasimple en el socket de dominio de Unix llamado socket.
-U
Cuenta de usuario bajo la cual se ejecutará el agente. El valor predeterminado es la cuenta "pcp" sin privilegios en las versiones actuales de PCP, pero en versiones anteriores se usaba la cuenta superusuario ("root") por defecto.

Se puede especificar como máximo una de las opciones -i, -p y -u.

INSTALACIÓN

Si desea acceder a los nombres, texto de ayuda y valores de las métricas de rendimiento simples, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/simple
# ./Install

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/simple
# ./Remove

pmdasimple es lanzado por pmcd(1) y nunca debe ser ejecutado directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o se elimina.

ARCHIVOS

$PCP_PMCDCONF_PATH
opciones de línea de comandos utilizadas para lanzar pmdasimple
$PCP_PMDAS_DIR/simple/help
archivo de texto de ayuda predeterminado para las métricas simples
$PCP_PMDAS_DIR/simple/Install
script de instalación para el agente pmdasimple
$PCP_PMDAS_DIR/simple/Remove
script para deshacer la instalación del agente pmdasimple
$PCP_PMDAS_DIR/simple/simple.conf
archivo de configuración para el dominio de instancias dinámicas que subyace a la métrica de rendimiento simple.now. Para una descripción, consulte el archivo de texto de ayuda, o ejecute el comando

$ pminfo -T simple.now

$PCP_PMDAS_DIR/simple/*.pmda_simple.so
La versión DSO del PMDA. El mismo código fuente se utiliza para crear tanto la versión DSO como la versión de demonio del PMDA simple, y una u otra puede instalarse como parte del diálogo en el script Install.
$PCP_LOG_DIR/pmcd/simple.log
archivo de log predeterminado para mensajes de error y otra información de pmdasimple

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información es a veces críptica y está destinada principalmente a guiar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
