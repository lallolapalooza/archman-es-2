pmExtractValue(3)

Paquete: pcp

Licencias: GPL-2.0-or-later, LGPL-2.1-or-later, CC-BY-3.0

PMEXTRACTVALUE(3) Manual de funciones de biblioteca PMEXTRACTVALUE(3)

NOMBRE

pmExtractValue - extraer un valor de métrica de rendimiento de una estructura pmResult

SINOPSIS C

#include <pcp/pmapi.h>

int pmExtractValue(int valfmt,
const pmValue *ival, int itype, pmAtomValue *oval, int otype);

cc ... -lpcp

DESCRIPCIÓN

La estructura pmValue está incrustada dentro de la estructura pmResult que se utiliza para devolver una o más métricas de rendimiento; véase pmFetch(3).

Todos los valores de métrica de rendimiento pueden estar codificados en una unión pmAtomValue, definida como sigue;

typedef union {
    __int32_t    l;     /* 32 bits con signo */
    __uint32_t   ul;    /* 32 bits sin signo */
    __int64_t    ll;    /* 64 bits con signo */
    __uint64_t   ull;   /* 64 bits sin signo */
    float        f;     /* punto flotante de 32 bits */
    double       d;     /* punto flotante de 64 bits */
    char         *cp;   /* puntero a char */
    pmValueBlock *vbp;  /* puntero a pmValueBlock */
} pmAtomValue;

La rutina pmExtractValue proporciona un mecanismo conveniente para extraer valores de la parte pmValue de una estructura pmResult, convirtiendo opcionalmente el tipo de datos y poniendo el resultado a disposición del programador de la aplicación.

itype define el tipo de datos del valor de entrada contenido en ival según el formato de almacenamiento definido por valfmt (véase pmFetch(3)). otype define el tipo de datos del resultado que se colocará en oval.

El valor para itype se extrae típicamente de una estructura pmDesc, después de una llamada a pmLookupDesc(3) para una métrica de rendimiento particular.

El valor otype debe ser uno de los valores definidos PM_TYPE_..., que tienen una correspondencia 1:1 con los campos de la unión pmAtomValue.

Normalmente, el parámetro valfmt se extraería de la misma estructura pmResult que proporciona el parámetro ival, y si valfmt especifica PM_VAL_INSITU, entonces los siguientes tipos de entrada no están permitidos, ya que estos no se pueden codificar en 32 bits; __int64_t, __uint64_t, double, char * y void * y los valores itype correspondientes son PM_TYPE_64, PM_TYPE_U64, PM_TYPE_DOUBLE, PM_TYPE_STRING, PM_TYPE_AGGREGATE y PM_TYPE_EVENT (o PM_TYPE_HIGHRES_EVENT) respectivamente. Si valfmt especifica PM_VAL_SPTR o PM_VAL_DPTR, entonces el valor se extraerá de la estructura pmValueBlock asociada, y las opciones __int32_t, __uint32_t y float (itype siendo PM_TYPE_32, PM_TYPE_U32 y PM_TYPE_FLOAT respectivamente) no están permitidas, ya que PM_VAL_INSITU es la codificación apropiada para estas.

La siguiente tabla define las diversas posibilidades para la conversión de tipos: el tipo de entrada (itype) se muestra verticalmente y el tipo de salida (otype) se muestra horizontalmente. Y significa que la conversión es siempre aceptable, N significa que la conversión nunca se puede realizar (la función devuelve PM_ERR_CONV), P significa que la conversión puede perder precisión (pero no se devuelve ningún estado de error), T significa que el resultado puede estar sujeto a truncamiento de orden superior (en cuyo caso la función devuelve PM_ERR_TRUNC) y S significa que la conversión puede ser imposible debido al signo del valor de entrada (en cuyo caso la función devuelve PM_ERR_SIGN). Si ocurre un error, el valor representado por oval será cero (o NULL).

No se admite ninguna conversión que involucre los tipos PM_TYPE_EVENT, PM_TYPE_HIGHRES_EVENT o PM_TYPE_AGGR, y la etiqueta ``BLOB'' en la tabla siguiente cubre los tres tipos.

      | 32  |  U32  | 64  |  U64  | FLOAT | DBLE | STRNG | BLOB
======|=====|=======|=====|=======|=======|======|=======|======
32    |  Y  |   S   |  Y  |   S   |   P   |  P   |   Y   |  N
U32   |  T  |   Y   |  Y  |   Y   |   P   |  P   |   Y   |  N
64    |  T  |  T,S  |  Y  |   S   |   P   |  P   |   Y   |  N
U64   |  T  |   T   |  T  |   Y   |   P   |  P   |   Y   |  N
FLOAT | P,T | P,T,S | P,T | P,T,S |   Y   |  Y   |   P   |  N
DBLE  | P,T | P,T,S | P,T | P,T,S |   P   |  Y   |   P   |  N
STRNG |  N  |   N   |  N  |   N   |   N   |  N   |   Y   |  N
BLOB  |  N  |   N   |  N  |   N   |   N   |  N   |   N   |  N

En los casos en que podrían ocurrir múltiples errores de conversión, se notificará el primer error encontrado, y el orden de comprobación no está definido.

Si la conversión de salida es a uno de los tipos puntero, es decir, otype es PM_TYPE_STRING o PM_TYPE_AGGREGATE, entonces el búfer de valor habrá sido asignado por pmExtractValue(3) usando malloc(3), y es responsabilidad del llamador liberar el espacio cuando ya no sea necesario.

Aunque esta función parece bastante compleja, ha sido construida para ayudar al desarrollo de herramientas de rendimiento que deseen convertir valores, cuyo tipo solo se conoce a través del campo type en una estructura pmDesc, a un tipo canónico para procesamiento local. Consulte las funciones pmFetchGroup para una alternativa más sencilla.

DIAGNÓSTICOS

PM_ERR_CONV

Conversión imposible, marcada con N en la tabla anterior

PM_ERR_TRUNC

Ocurrió truncamiento de orden superior

PM_ERR_SIGN

Se intentó la conversión de un valor negativo a un tipo sin signo
