PMATRYDELTAINDOM(3) Manual de funciones de biblioteca PMATRYDELTAINDOM(3)

NOMBRE

pmaTryDeltaInDom - intenta traducir un registro indom físico de un ``indom completo'' a un ``indom delta''

C SINOPSIS

#include <pcp/pmapi.h>
#include <pcp/libpcp.h>
#include <pcp/archive.h>

int pmaTryDeltaInDom(__pmLogCtl *lcp,
__int32_t **rbuf, __pmLogInDom *lidp);

cc ... -lpcp_archive -lpcp

ADVERTENCIA

Esta documentación está destinada al uso interno de los desarrolladores de Performance Co-Pilot (PCP).

Estas interfaces no forman parte de las API de PCP que se garantiza que permanecerán fijas entre versiones, y pueden no funcionar o proporcionar semánticas diferentes en algún momento futuro.

DESCRIPCIÓN

El dominio de instancia de entrada se pasa como un registro de metadatos físico a través de rbuf o en formato ``cargado'' identificado por lidp. Como estos son formatos alternativos para el dominio de instancia de entrada, pmaTryDeltaInDom exige que **exactamente** uno de rbuf y lidp sea **NULL**, de lo contrario, el valor de retorno es -2.

El dominio de instancia de entrada está en camino de ser escrito en el archivo identificado por lcp.

Si es posible, el dominio de instancia se convertirá al formato ``delta indom'', y el dominio de instancia convertido se devolverá a través de rbuf o lidp (el que no sea **NULL**). Si se realiza la conversión, cualquier almacenamiento asociado con el dominio de instancia de entrada se habrá liberado.

El formato ``delta indom'' solo se admite para archivos de la Versión 3 y es responsabilidad del llamador determinar si la llamada a pmaTryDeltaInDom es apropiada.

Para determinar si el formato ``delta indom'' es la codificación más eficiente, pmaTryDeltaInDom mantiene una caché por dominio de instancia del último dominio de instancia ``completo'' visto. Para evitar la corrupción de datos, esto significa que pmaTryDeltaInDom primero copia el dominio de instancia de entrada. La copia y la caché son gestionadas de forma privada por pmaTryDeltaInDom, por lo que el llamador no es consciente de esta actividad.

El esquema de caché requiere que el llamador deba llamar a pmaTryDeltaInDom para **cada** registro de dominio de instancia, independientemente de si es probable que el formato ``delta indom'' sea apropiado.

DIAGNÓSTICOS Y VALORES DE RETORNO

En varios lugares, los errores fatales activarán un mensaje de error y forzarán la salida de la aplicación.

Un valor de retorno de -1 indica que rbuf no era **NULL** y que el registro físico en él no era un registro **TYPE_INDOM** (dominio de instancia ``completo'' de la Versión 3) como se esperaba. Un valor de retorno de 1 significa que rbuf o lidp ha sido reescrito y ahora es un registro **TYPE_INDOM_DELTA**. De lo contrario, el valor de retorno es 0.

VER TAMBIÉN
