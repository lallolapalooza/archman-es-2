NOMBRE

__pmFaultInject, __pmFaultSummary, PM_FAULT_POINT, PM_FAULT_RETURN, PM_FAULT_CHECK, PM_FAULT_CLEAR - Infraestructura de Inyección de Fallos para QA

SINOPSIS C

#include <pcp/pmapi.h>
#include <pcp/fault.h>

void __pmFaultInject(const char *ident, int class);
void __pmFaultSummary(FILE *f);

PM_FAULT_POINT(ident, class);
PM_FAULT_RETURN(retvalue);
PM_FAULT_CHECK;
PM_FAULT_CLEAR;

cc -DPM_FAULT_INJECTION=1 ... -lpcp_fault

DESCRIPCIÓN

Como parte de los cambios dirigidos por la cobertura en QA en PCP 3.6, se hizo aparente que necesitábamos alguna forma de ejercitar las rutas de código ``poco comunes'' asociadas con la detección y recuperación de errores.

Las facilidades descritas a continuación proporcionan una infraestructura básica de inyección de fallos (solo para libpcp en esta etapa, aunque el mecanismo es mucho más general y podría extenderse fácilmente).

Se requiere una compilación especial para crear libpcp_fault y el archivo de cabecera asociado <pcp/fault.h>. Una vez hecho esto, las nuevas aplicaciones de QA pueden compilarse con -DPM_FAULT_INJECTION=1 y/o las aplicaciones existentes pueden ser ejercitadas en presencia de inyección de fallos forzando el uso de libpcp_fault en preferencia a libpcp como se describe a continuación.

En el código a probar, __pmFaultInject define un punto de fallo en el que se puede inyectar un fallo de tipo class. ident es una cadena para identificar de forma única el punto de fallo en todo el código fuente de PCP, por lo que algo como "libpcp/" __FILE__ ":<número>" funciona perfectamente. La cadena ident también determina si se inyectará un fallo en tiempo de ejecución o no; consulte la sección CONTROL EN TIEMPO DE EJECUCIÓN a continuación. class selecciona un tipo de fallo, utilizando uno de los siguientes valores definidos (esta lista puede crecer con el tiempo):

PM_FAULT_ALLOC
Provocará que la siguiente llamada a malloc(3), realloc(3) o strdup(3) falle, devolviendo NULL y estableciendo errno a ENOMEM. Podríamos extender la cobertura a todas las rutinas relacionadas con malloc, pero estas tres son suficientes para cubrir la gran mayoría de los usos dentro de libpcp.
PM_FAULT_CALL
Provocará que la siguiente llamada a una rutina instrumentada falle devolviendo un código de error (posiblemente el nuevo código PM_ERR_FAULT). El código de error real se define en la macro PM_FAULT_RETURN al principio de una rutina instrumentada. Inicialmente, solo __pmRegisterAnon(3) (devuelve PM_ERR_FAULT), __pmGetPDU(3) (devuelve PM_ERR_TIMEOUT) y __pmAllocResult(3) (devuelve NULL) fueron instrumentadas como prueba de concepto para esta parte de la facilidad, sin embargo, otras rutinas pueden tener esta capacidad de inyección de fallos añadida con el tiempo.
PM_FAULT_MISC
La clase ``otra'', actualmente utilizada con PM_FAULT_CHECK como se describe a continuación.

Para permitir que la inyección de fallos coexista dentro del código fuente de producción, PM_FAULT_POINT es una macro que no emite código por defecto, pero cuando se define PM_FAULT_INJECTION, se convierte en una llamada a __pmFaultInject. En todo libpcp usamos PM_FAULT_POINT y no __pmFaultInject para que tanto libpcp como libpcp_fault puedan compilarse desde el mismo código fuente.

Del mismo modo, la macro PM_FAULT_RETURN no emite código a menos que se defina PM_FAULT_INJECTION; en ese caso, si se ha armado un fallo de tipo PM_FAULT_CALL con __pmFaultInject, la rutina que la envuelve retorna con el valor de función retvalue.

La macro PM_FAULT_CHECK devuelve un valor que puede ser 0 o 1. Si se define PM_FAULT_INJECTION, y se ha armado un fallo de tipo PM_FAULT_MISC con __pmFaultInject, el valor es 1; de lo contrario, es 0.

PM_FAULT_CHECK se usa con mayor frecuencia junto con la macro PM_FAULT_POINT con la clase PM_FAULT_MISC para armar potencialmente un disparador, luego probar PM_FAULT_CHECK y si este tiene el valor 1, entonces la macro PM_FAULT_CLEAR se usa para borrar cualquier fallo armado, y se ejecuta el código de inyección de fallos.

Esto se ilustra en el siguiente ejemplo de src/libpcp/src/exec.c:

    pid = fork();
    /* begin fault-injection block */
    PM_FAULT_POINT("libpcp/" __FILE__ ":4", PM_FAULT_MISC);
    if (PM_FAULT_CHECK) {
	PM_FAULT_CLEAR;
	if (pid > (pid_t)0)
	    kill(pid, SIGKILL);
	setoserror(EAGAIN);
	pid = -1;
    }
    /* end fault-injection block */

Un resumen de los puntos de fallo vistos y los fallos inyectados se produce en el flujo estándar f por __pmFaultSummary.

Se definen un rastreo adicional (a través de -Dfault o pmDebugOptions.fault) y un nuevo código de error PMAPI (PM_ERR_FAULT), aunque estos solo se verán o usarán en libpcp_fault. Si pmDebugOptions.fault está establecido la primera vez que se llama a __pmFaultInject, entonces __pmFaultSummary se llamará automáticamente para informar en stderr cuando la aplicación salga (a través de atexit(3)).

La inyección de fallos no puede anidarse. Cada llamada a __pmFaultInject borra cualquier inyección de fallo previa que se haya armado, pero aún no ejecutado.

La infraestructura de inyección de fallos no es segura para hilos y solo debe usarse con aplicaciones que se sepa que son de un solo hilo.

CONTROL EN TIEMPO DE EJECUCIÓN

Por defecto, no se habilita ninguna inyección de fallos en tiempo de ejecución, incluso cuando se llama a __pmFaultInject.

Los fallos se habilitan selectivamente utilizando un archivo de control, identificado por la variable de entorno $PM_FAULT_CONTROL; si no está establecida, no se habilitan fallos.

El archivo de control (si existe) se lee la primera vez que se llama a __pmFaultInject, y contiene líneas de la forma: ident op número
que definen los guardias de inyección de fallos.

ident es una cadena de punto de fallo (como se define por una llamada a __pmFaultInject, o más comúnmente la macro PM_FAULT_POINT). Por lo tanto, se necesita acceso al código fuente de libpcp para determinar las cadenas ident disponibles y su semántica.

op es uno de los operadores de estilo C >=, >, ==, <, <=, != o % y número es un entero sin signo. op número es opcional y el valor por defecto es >0

La semántica de los guardias de inyección de fallos es que cada vez que se llama a __pmFaultInject para un ident particular, se incrementa un contador de disparos (el primer disparo es 1); si la expresión de estilo C contador_disparos op número tiene el valor 1 (es decir, verdadero para la mayoría de los ops, o el resto es igual a 1 para el operador %), entonces se armará un fallo del class definido para el punto de fallo asociado con ident, y se ejecutará lo antes posible.

Dentro del archivo de control, las líneas en blanco se ignoran y las líneas que comienzan con # se tratan como comentarios.

Para una aplicación existente enlazada con libpcp, la inyección de fallos aún se puede utilizar forzando el uso de libpcp_fault en lugar de libpcp. El siguiente ejemplo muestra cómo se podría hacer esto.

EJEMPLOS

Consulte el código fuente de PCP y PCP QA.

Las definiciones de macros se encuentran en src/include/pcp/fault.h.

src/libpcp/src/fault.c contiene toda la implementación subyacente.

src/libpcp_fault y src/libpcp_fault/src contienen la receta y los Makefiles para crear e instalar libpcp_fault.so y <pcp/fault.h>.

PM_FAULT_RETURN se utilizó inicialmente en los siguientes archivos fuente de libpcp: derive_parser.y.in, pdu.c y result.c.

PM_FAULT_POINT se utilizó inicialmente en los siguientes archivos fuente de libpcp: derive_parser.y.in, desc.c, e_indom.c, e_labels.c, err.c, events.c, exec.c, fetch.c, help.c, instance.c, interp.c, labels.c, logmeta.c, pmns.c, p_profile.c y store.c.

El grupo de pruebas de QA ``fault'' muestra ejemplos de uso de archivos de control. Para ver qué pruebas están involucradas

$ cd qa
$ check -n -g fault

DIAGNÓSTICOS

Algunos errores no recuperables se informan en stderr.

ENTORNO

PM_FAULT_CONTROL
Ruta completa al archivo de control de inyección de fallos.
LD_PRELOAD
Forzar el uso de libpcp_fault en lugar de libpcp.
