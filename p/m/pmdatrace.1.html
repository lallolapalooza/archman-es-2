PMDATRACE(1) Manual de Comandos Generales PMDATRACE(1)

NOMBRE

pmdatrace - agente de dominio de métricas de rendimiento a nivel de aplicación

SINOPSIS

$PCP_PMDAS_DIR/trace/pmdatrace [-D debug] [-d dominio] [-l logfile] [-A acceso] [-I puerto] [-M usuario] [-N buckets] [-T periodo] [-U unidades]

DESCRIPCIÓN

pmdatrace es un Agente de Dominio de Métricas de Rendimiento (PMDA) que exporta métricas de rendimiento de transacciones desde procesos de aplicación que utilizan la biblioteca pcp_trace descrita en pmdatrace(3).

A continuación se presenta una breve descripción de las opciones de línea de comandos de pmdatrace:

-d
Es absolutamente crucial que el número de dominio de métricas de rendimiento especificado aquí sea único y consistente. Es decir, dominio debe ser diferente para cada PMDA en un host, y el mismo número de dominio debe usarse para el mismo PMDA en todos los hosts.
-l
Ubicación del archivo de registro. Por defecto, se escribe un archivo de registro llamado trace.log en el directorio actual de pmcd(1) cuando se inicia pmdatrace, es decir, $PCP_LOG_DIR/pmcd. Si el archivo de registro no se puede crear o no es escribible, la salida se escribe en el error estándar en su lugar.
-A
Control de acceso basado en host para pmdatrace. acceso debe ser una especificación de permitir o denegar, usando permitir:hostspec:maxconns o denegar:hostspec, donde `permitir' y `denegar' son palabras clave, `hostspec' es una especificación de host que cumple con el formato utilizado tanto por pmcd(1) como por pmlogger(1), y `maxconns' es el número máximo de conexiones permitidas desde un `hostspec' dado. Usar un número máximo de conexiones de cero especifica un número ilimitado de conexiones para el `hostspec' asociado.
-I
Comuníquese con los clientes de pcp_trace a través del puerto de Internet especificado. Esto se puede especificar alternativamente configurando $PCP_TRACE_PORT en el entorno a algún número de puerto válido (el uso de la opción -I anula esto). El número de puerto por defecto es 4323.
-T
periodo define el período de agregación utilizado para calcular los promedios y extremos recientes. Se especifica como un intervalo de tiempo usando la sintaxis descrita en PCPIntro(1) para el argumento común de PCP -t, por ejemplo, 30 seconds o 1 min. El valor predeterminado es 60 segundos.
-M
Cuenta de usuario bajo la cual se ejecutará el agente. Por defecto es la cuenta no privilegiada "pcp" en las versiones actuales de PCP, pero en versiones anteriores se utilizaba la cuenta de superusuario ("root") por defecto.
-N
Internamente, el periodo de agregación se divide en bucket divisiones, y el promedio móvil se recalcula cada periodo/bucket segundos. Por ejemplo, los valores predeterminados corresponden a -T 60 y -N 12, lo que significa que el promedio se recalcula cada cinco segundos para un período que cubre los 60 segundos anteriores.
-U
Esta opción permite configurar la dimensión y escala asociadas con la métrica de valor de observación. unidades es una cadena separada por comas de seis valores enteros, que son la dimensión de espacio, dimensión de tiempo, dimensión de conteo, escala de espacio, escala de tiempo y escala de conteo, respectivamente. La dimensión y escala por defecto es "none", que es equivalente a presentar "0,0,0,0,0,0" como argumento a -U. Las unidades asociadas con una métrica se ven más fácilmente usando la opción -d (descripción de métrica) de pminfo(1). El script de Instalación descrito a continuación recorre explícitamente esta opción, por lo que se recomienda utilizar el script de Instalación para construir la especificación de unidades.

Esencialmente, las métricas exportadas proporcionan estadísticas sobre el tiempo de finalización de cada transacción, y un recuento promedio de transacciones completadas y puntos de vigilancia superados durante un periodo de tiempo determinado.

INSTALACIÓN

Para que un host exporte los nombres, el texto de ayuda y los valores de las métricas de rendimiento de Trace, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/trace
# ./Install

Si desea deshacer la instalación, haga lo siguiente como root:

# cd $PCP_PMDAS_DIR/trace
# ./Remove

pmdatrace es lanzado por pmcd(1) y nunca debe ser ejecutado directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o se elimina.

ARCHIVOS

$PCP_PMCDCONF_PATH
opciones de línea de comandos utilizadas para lanzar pmdatrace
$PCP_PMDAS_DIR/trace/help
archivo de texto de ayuda predeterminado para las métricas de Trace
$PCP_DEMOS_DIR/trace/*
programas de ejemplo que utilizan la biblioteca pcp_trace
$PCP_PMDAS_DIR/trace/Install
script de instalación para el agente pmdatrace
$PCP_PMDAS_DIR/trace/Remove
script para deshacer la instalación de pmdatrace
$PCP_LOG_DIR/pmcd/trace.log
archivo de registro predeterminado para mensajes de error y otra información de pmdatrace

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información a veces es críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmdatrace son las siguientes:

Opción Descripción
appl0 análisis de autenticación, cambios de cliente, IPC, actualizaciones de datos y metadatos de métricas
appl1 datos brutos para métricas de tasa
