PMLOGEXTRACT(1) Manual de Comandos Generales PMLOGEXTRACT(1)

NOMBRE

pmlogextract - reducir, extraer, concatenar y fusionar archivos de Performance Co-Pilot

SINOPSIS

pmlogextract [-dfmwxz?] [-c archivo_config] [-D debug] [-S hora_inicio] [-s muestras] [-T hora_fin] [-V version] [-v tamaño_volumen] [-Z zona_horaria] entrada [...] salida

DESCRIPCIÓN

pmlogextract lee uno o más archivos de Performance Co-Pilot (PCP) identificados por entrada y crea un archivo PCP fusionado y/o reducido en salida. Cada argumento entrada es un nombre o una lista de nombres separada por comas, y cada nombre es el nombre de un archivo de un archivo o el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos. La naturaleza de la fusión se controla por el número de archivos entrada, mientras que la naturaleza de la reducción de datos se controla por los argumentos de la línea de comandos. Los argumentos entrada deben ser archivos creados por pmlogger(1) con datos de rendimiento recopilados del **mismo** host, pero usualmente en diferentes períodos de tiempo y posiblemente (aunque no usualmente) con diferentes métricas de rendimiento registradas.

Si solo se especifica una entrada, el comportamiento por defecto simplemente copia el archivo PCP de entrada (con posible conversión a una versión más reciente del formato de archivo, ver -V abajo), al archivo PCP de salida. Cuando se especifican dos o más archivos PCP como entrada, los archivos se fusionan (o concatenan) y se escriben en salida.

En el archivo salida se puede insertar un registro <mark> en un momento justo después del final de cada archivo de entrada para indicar una posible discontinuidad temporal entre el final de un archivo de entrada y el inicio del siguiente archivo de entrada. Ver la sección REGISTROS DE MARCA más abajo para más información. No hay registro de <mark> después del final del **último** (en orden temporal) de los registros del(los) archivo(s) de entrada.

OPCIONES

Las opciones disponibles en la línea de comandos son:

-c config, --config=config
Extrae solo las métricas especificadas en config del(los) archivo(s) PCP de entrada. La sintaxis de config aceptada por pmlogextract se explica con más detalle en la sección SINTAXIS DEL ARCHIVO DE CONFIGURACIÓN.
-d, --desperate
Modo desesperado. Normalmente, si ocurre un error fatal, se elimina todo rastro del archivo PCP de salida parcialmente escrito. Con la opción -d, el archivo de salida no se elimina.
-f, --first
Para la mayoría de los usos comunes, todos los archivos de entrada se habrán recopilado en la misma zona horaria. Pero si este no es el caso, pmlogextract debe elegir una de las zonas horarias de los archivos de entrada para usarla como la zona horaria del archivo de salida. Por defecto, se usa la zona horaria del **último** archivo de entrada. La opción -f fuerza a usar la zona horaria del **primer** archivo de entrada.
-m, --mark
Como se describe en la sección REGISTROS DE MARCA más abajo, a veces es posible omitir de forma segura los registros de <mark> del archivo de salida. Si se especifica la opción -m, se omite la prueba epílogo y prólogo y siempre se insertará un registro de <mark> al final de cada archivo de entrada (excepto el último). Este es el comportamiento original de pmlogextract.
-S hora_inicio, --start=hora_inicio
Define el inicio de una ventana de tiempo para restringir los registros procesados; consulte PCPIntro(1). Ver también la opción -w.
-s muestras, --samples=muestras
El argumento muestras define el número de muestras (o registros) que se escribirán en salida. Si muestras es 0 o no se especifica -s, pmlogextract continuará hasta el final de todos los archivos de entrada o hasta el final de la ventana de tiempo según se especifica en -T, lo que ocurra primero. La opción -s anulará la opción -T si ocurre antes.
-T hora_fin, --finish=hora_fin
Define el final de una ventana de tiempo para restringir los registros procesados; consulte PCPIntro(1). Ver también la opción -w.
-V version, --outputversion=version
Cada archivo PCP tiene una versión para el formato de registro físico, actualmente 2 o 3. Por defecto, el archivo de salida se crea con una versión igual al **máximo** de la versión de los archivos de entrada. La opción -V puede usarse para forzar explícitamente la versión para salida, siempre que version no sea menor que la versión del archivo que se habría elegido según la regla por defecto.

Por ejemplo, especificar -V 3 puede usarse para producir un archivo de salida versión 3 a partir de archivos de entrada que podrían ser una mezcla de versión 2 y/o versión 3.

-v tamaño_volumen
El archivo de salida es potencialmente un conjunto de datos de múltiples volúmenes, y la opción -v hace que pmlogextract inicie un nuevo volumen después de alcanzar un tamaño de volumen de archivo de tamaño_volumen. Si tamaño_volumen es un entero, entonces se escribirán como máximo tamaño_volumen registros por volumen. Si tamaño_volumen es un entero con el sufijo b o bytes, entonces se escribirán como máximo tamaño_volumen bytes por volumen. Otras unidades de tamaño de archivo viables incluyen: K, Kb, KiB, Kbyte, Kilobyte para kilobytes y M, Mb, MiB, Mbyte, Megabyte para megabytes y G, Gb, GiB, Gbyte, Gigabyte para gigabytes. Estas unidades pueden tener opcionalmente el sufijo s y pueden ser de mayúsculas y minúsculas mixtas. Alternativamente, tamaño_volumen puede ser un entero o un número de punto flotante con sufijo de unidad de tiempo como se describe en PCPIntro(1) para el argumento intervalo (a la opción de línea de comandos estándar de PCP -t). 
Algunos ejemplos de diferentes formatos:
-s 100
-s 100bytes
-s 100K
-s 100Mb
-s 10Gbyte
-s 10mins
-s 1.5hours

Por defecto, pmlogextract produce el menor número posible de volúmenes.

Independientemente de cualquier opción -v, cada volumen de un archivo no puede exceder los 2^31 bytes, por lo que pmlogextract creará automáticamente un nuevo volumen para el archivo antes de que se alcance este límite.

-w
Donde -S y -T especifican una ventana de tiempo dentro del mismo día, la bandera -w hará que los datos dentro de la ventana de tiempo se extraigan para **cada** día en el archivo. Por ejemplo, las opciones -w -S @11:00 -T @15:00 especifican que pmlogextract solo debe incluir registros de archivo para los períodos de 11 a.m. a 3 p.m. cada día. Cuando se usa -w, el archivo de salida contendrá registros de <mark> para indicar la discontinuidad temporal entre el final de una ventana de tiempo y el inicio de la siguiente.
-x
Se espera que los metadatos (nombre, PMID, tipo, semántica y unidades) de cada métrica sean consistentes en todos los archivos PCP de entrada en los que aparezca esa métrica. En casos raros, por ejemplo, en desarrollo, en QA y cuando se actualiza un PMDA, esto puede no ser así y pmlogextract informará el problema y abortará sin crear el archivo de salida. Esto se hace para que el problema pueda ser corregido con pmlogrewrite(1) antes de reintentar la fusión. En entornos no atendidos o de QA, puede ser preferible forzar la fusión y omitir las métricas con metadatos que no coinciden. La opción -x hace esto.
-Z zona_horaria, --timezone=zona_horaria

Especifica la zona_horaria que se utilizará para interpretar las marcas de tiempo especificadas por las opciones -S y -T. Si esta opción no se especifica, el comportamiento predeterminado es interpretar las marcas de tiempo en relación con la hora local de la máquina que ejecuta pmlogextract.

REGISTROS DE MARCA

Las marcas de tiempo en los archivos PCP se registran en segundos desde la época del sistema Unix. Para archivos recopilados a lo largo de períodos de tiempo suficientemente largos, es posible que la hora del sistema de la máquina que registra los datos se haya ajustado y, por lo tanto, se introduzcan discontinuidades temporales.

Para detectar estas discontinuidades y, en algunos casos, para permitir la fusión segura de múltiples archivos en un único archivo PCP, se insertan registros de <mark> en los archivos PCP. Estos registros marcan el final de un archivo fuente y el inicio del siguiente.

pmlogextract intenta ser inteligente al insertar estos registros de marca. Si el final de un archivo fuente de entrada coincide exactamente con el principio del siguiente archivo fuente de entrada, y si los datos del archivo de salida aún están en el mismo segundo de tiempo del sistema que el último registro del archivo de entrada anterior, entonces pmlogextract asumirá que no hay una discontinuidad y omitirá el registro de marca.

Si esta prueba de omisión falla, se insertará un registro de marca. Esto se hace para asegurarse de que no se pierda ninguna información debido a la posible discontinuidad temporal. Si la opción -m no se especifica, entonces la prueba de omisión se aplica a todos los archivos de entrada (excepto el último).

SINTAXIS DEL ARCHIVO DE CONFIGURACIÓN

El archivo de configuración especificado por la opción -c puede contener una lista de nombres de métricas o nombres de métricas con caracteres comodín, uno por línea. Las líneas que comienzan con '#' se tratan como comentarios.

Por ejemplo, el siguiente archivo de configuración:

# Esto es un comentario
cpu
load
mem
net.*

Solo extraerá métricas que comiencen con "cpu", "load" y "mem", y todas las métricas que comiencen con "net.". Las métricas que no coincidan con estos patrones serán omitidas del archivo de salida.

EJEMPLOS

Para concatenar los archivos de registro archive.1 y archive.2 en un nuevo archivo archive.merged:

$ pmlogextract archive.1 archive.2 archive.merged

Para extraer métricas relacionadas con la CPU del archivo archive.old y guardarlas en archive.cpu.new:

$ pmlogextract -c cpu_metrics.conf archive.old archive.cpu.new

Donde cpu_metrics.conf es un archivo de configuración que contiene una lista de nombres de métricas de CPU.

Para extraer datos del archivo archive.log entre las 10 AM y las 11 AM y guardarlos en archive.10-11am:

$ pmlogextract -S @10:00 -T @11:00 archive.log archive.10-11am

Para extraer datos solo de las primeras 1000 muestras del archivo archive.log y guardarlos en archive.first1000:

$ pmlogextract -s 1000 archive.log archive.first1000

Para fusionar tres archivos archive.1, archive.2 y archive.3 en un solo archivo archive.all, y asegurarse de que el archivo de salida sea del formato más reciente (versión 3):

$ pmlogextract -V 3 archive.1 archive.2 archive.3 archive.all

OPTIONS

-z, --hostzone
Use la zona horaria local del host de los archivos de entrada al mostrar la fecha y hora en los diagnósticos. El valor predeterminado es utilizar inicialmente la zona horaria del host local.
-?, --help
Muestra el mensaje de uso y sale.

SINTAXIS DEL ARCHIVO DE CONFIGURACIÓN

El archivo de configuración contiene las métricas de interés; solo aquellas métricas (o instancias) mencionadas explícita o implícitamente en el archivo de configuración se incluirán en el archivo de salida. Cada especificación debe comenzar en una nueva línea y puede abarcar varias líneas en el archivo de configuración. También se pueden especificar instancias, pero son opcionales. El formato para cada especificación es

        métrica
o
        métrica [ instancia ... ]

donde métrica puede ser un nodo hoja o un nodo no hoja del Espacio de Nombres de Métricas de Rendimiento (PMNS, consulte PMNS(5)). Si una métrica se refiere a un nodo no hoja en el PMNS, pmlogextract descenderá recursivamente por el PMNS e incluirá todas las métricas correspondientes a los nodos hoja descendientes.

Las instancias son opcionales y se especifican como una lista separada por espacios (o comas) de identificadores de instancia, con la lista entre corchetes. Cada identificador de instancia puede ser un número o una cadena (entre comillas simples o dobles). Se asume que los identificadores de instancia que son números son identificadores de instancia internos; de lo contrario, se asumen que los valores de cadena son identificadores de instancia externos; consulte pmGetInDom(3) para obtener más información. Si no se proporcionan instancias, se extraerán todas las instancias de las métricas asociadas.

Se ignora cualquier espacio en blanco adicional y se pueden agregar comentarios con un prefijo de `#`.

EJEMPLO DE ARCHIVO DE CONFIGURACIÓN

Este es un ejemplo de un archivo de configuración válido:


#
# archivo de configuración para pmlogextract
#


kernel.all.cpu
kernel.percpu.cpu.sys ["cpu0","cpu1"]
disk.dev ["dks0d1"]

REGISTROS DE MARCA

Cuando más de un archivo de entrada contribuye con datos de rendimiento al archivo de salida, se pueden insertar registros de <mark> para indicar una posible discontinuidad temporal en los datos de rendimiento.

Un registro de <mark> contiene una marca de tiempo y ningún dato de rendimiento, y se utiliza para indicar que existe un período de tiempo en el archivo PCP donde no conocemos los valores de **ninguna** métrica de rendimiento, porque no hubo ningún pmlogger(1) recopilando datos de rendimiento durante este período. Dado que estos períodos a menudo se asocian con el reinicio de un servicio o de pmcd(1) o un reinicio del sistema, puede haber una duda considerable sobre la continuidad de los datos de rendimiento a través de este período de tiempo.

La mayoría de los archivos actuales se crean con un registro de prologue al principio y un registro de epilogue al final. Estos registros identifican el estado de pmcd(1) en ese momento y pueden ser utilizados por pmlogextract para determinar que no hay discontinuidad entre el final de un archivo y el siguiente registro de salida, y en consecuencia, el registro de <mark> puede omitirse de forma segura del archivo de salida.

El razonamiento detrás de los registros de <mark> puede ser demostrado con un ejemplo. Considere un archivo de entrada que comienza a las 00:10 y termina a las 09:15 del mismo día, y otro archivo de entrada que comienza a las 09:20 del mismo día y termina a las 00:10 de la mañana siguiente. Este sería un caso muy común para archivos gestionados y rotados por pmlogger_check(1) y pmlogger_daily(1).

El archivo de salida creado por pmlogextract contendría:
00:10.000    primer registro del primer archivo de entrada
...
09:15.000    último registro del primer archivo de entrada
09:15.001    registro de <mark>
09:20.000    primer registro del segundo archivo de entrada
...
01:10.000    último registro del segundo archivo de entrada

El período de tiempo donde faltan los datos de rendimiento comienza justo después de las 09:15 y termina justo antes de las 09:20. Cuando el archivo de salida se procesa con cualquiera de las herramientas de informe de PCP, se utiliza el registro de <mark> para indicar un período de datos faltantes. Por ejemplo, utilizando el archivo de salida anterior, imagine que se estuviera informando la tasa promedio de E/S en intervalos de 30 minutos alineados en la hora y la media hora. El contador de E/S es un contador, por lo que la tasa promedio de E/S requiere dos valores válidos de tiempos de muestra consecutivos. Habría valores para todos los intervalos que terminan a las 09:00, luego ningún valor a las 09:30 debido al registro de <mark>, luego ningún valor a las 10:00 porque el valor "anterior" a las 09:30 no está disponible, luego la tasa se informaría nuevamente a las 10:30 y continuaría cada 30 minutos hasta el último valor informado a la 01:00.

La presencia de registros de <mark> en un archivo PCP se puede establecer usando pmlogdump(1) donde una marca de tiempo y la anotación <mark> se utilizan para indicar un registro de <mark>.

VERIFICACIONES DE METADATOS

Cuando se especifica más de un archivo de entrada, pmlogextract realiza una serie de verificaciones para garantizar que los metadatos sean consistentes para las métricas que aparecen en más de uno de los archivos de entrada. Estas verificaciones incluyen:

  • el tipo de datos de la métrica es el mismo
  • la semántica de la métrica es la misma
  • las unidades de la métrica son las mismas
  • la métrica es siempre singular o siempre tiene el mismo dominio de instancia
  • las métricas con el mismo nombre tienen el mismo PMID
  • las métricas con el mismo PMID tienen el mismo nombre

Si alguna de estas verificaciones falla, pmlogextract informa los detalles y aborta sin crear el archivo de salida.

Para abordar estos problemas semánticos, utilice pmlogrewrite(1) para traducir los archivos de entrada a archivos equivalentes con metadatos consistentes antes de usar pmlogextract.

Consulte las opciones de línea de comandos -x y -d anteriores para conocer alternativas al manejo predeterminado de errores durante las verificaciones de metadatos.

ADVERTENCIAS

Las métricas de prologue (pmcd.pmlogger.archive, pmcd.pmlogger.host y pmcd.pmlogger.port), que son registradas automáticamente por pmlogger al inicio del archivo, pueden no estar presentes en el archivo de salida de pmlogextract. Estas métricas solo son relevantes mientras se está creando el archivo y no tienen ninguna importancia una vez que ha finalizado la grabación.

DIAGNÓSTICOS

Todas las condiciones de error detectadas por pmlogextract se informan en stderr con una explicación textual (aunque a veces sea breve).

Si uno de los archivos de entrada no contiene registros de archivo, se emite una advertencia de "archivo vacío" y ese archivo se ignora.

Si uno de los archivos de entrada está corrupto (esto puede suceder si la instancia de pmlogger que escribe el archivo muere súbitamente), pmlogextract detectará e informará la posición de la corrupción en el archivo, y la información posterior de ese archivo no se procesará.

Si se detecta algún error, pmlogextract saldrá con un estado distinto de cero.

ARCHIVOS

Para cada uno de los archivos de entrada y salida, se utilizan varios archivos físicos.

archivo.meta
metadatos (descripciones de métricas, dominios de instancias, etc.) para el archivo
archivo.0
volumen inicial de valores de métricas (volúmenes posteriores tienen sufijos 1, 2, ...) - para la entrada, estos archivos pueden haber sido previamente comprimidos con bzip2(1) o gzip(1) y, por lo tanto, pueden tener un sufijo adicional .bz2 o .gz.
archivo.index
índice temporal para admitir acceso aleatorio rápido a los otros archivos en el archivo.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para las variables de entorno que afectan a las herramientas de PCP, consulte pmGetOptions(3).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información es a veces críptica y está destinada principalmente a guiar a los desarrolladores en lugar de a los usuarios finales. debug es una lista de opciones de depuración separada por comas; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para pmlogger son las siguientes:

Opción Descripción
appl0 Aplica una opción de depuración particular a un subproceso de aplicación. El número específico del subproceso es el valor de debug. La opción de depuración para el subproceso es el valor de debug con el sufijo numérico agregado. Por ejemplo, si debug es ``trace:appl0=1,read:appl1=1'', entonces la opción de depuración trace se aplicará al subproceso de aplicación 0 y la opción read se aplicará al subproceso de aplicación 1.
conf Muestra el contenido de la tabla de configuración de métricas.
fetch Genera un registro de la actividad de recuperación de métricas.
file Genera un registro de la actividad de escritura y cierre de archivos.
pmda Genera un registro de la actividad de PMDA.
trace Genera un registro de la actividad de E/S del sistema de archivos.
