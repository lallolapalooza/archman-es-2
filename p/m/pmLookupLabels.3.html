NOMBRE

pmLookupLabels, pmGetInstancesLabels, pmGetItemLabels, pmGetClusterLabels, pmGetInDomLabels, pmGetDomainLabels, pmGetContextLabels - recuperar etiquetas asociadas con valores de métricas de rendimiento

SINOPSIS C

#include <pcp/pmapi.h>

int pmLookupLabels(pmID pmid, pmLabelSet **labelsets);

int pmGetInstancesLabels(pmInDom indom, pmLabelSet **labelsets);
int pmGetItemLabels(pmID pmid, pmLabelSet **labelsets);
int pmGetClusterLabels(pmID pmid, pmLabelSet **labelsets);
int pmGetInDomLabels(pmInDom indom, pmLabelSet **labelsets);
int pmGetDomainLabels(int domain, pmLabelSet **labelsets);
int pmGetContextLabels(pmLabelSet **labelsets);

cc ... -lpcp

SINOPSIS PYTHON

from pcp import pmapi

labelsets = pmapi.pmContext().pmLookupLabels(pmid)

labelsets = pmapi.pmContext().pmGetInstancesLabels(indom)
labelsets = pmapi.pmContext().pmGetItemLabels(pmid)
labelsets = pmapi.pmContext().pmGetClusterLabels(pmid)
labelsets = pmapi.pmContext().pmGetInDomLabels(indom)
labelsets = pmapi.pmContext().pmGetDomainLabels(domain)
labelsets = pmapi.pmContext().pmGetContextLabels()

DESCRIPCIÓN

Las etiquetas son pares de nombre:valor asociados con valores de métricas de rendimiento con el propósito de adjuntar metadatos de métricas adicionales a los valores. Estos metadatos son menos estructurados y existen por separado del descriptor de métricas disponible para cada métrica de PCP desde pmLookupDesc(3).

Al igual que los metadatos del descriptor de métricas, las etiquetas son una parte integral de la identidad de cada métrica y rara vez, si es que alguna vez, deberían cambiar.

La rutina pmLookupLabels es una interfaz de conveniencia que proporciona la recuperación de todas las etiquetas asociadas con un solo identificador de métrica de rendimiento, pmid, **excepto** las etiquetas a nivel de instancias. Las etiquetas a nivel de instancias deben recuperarse por separado con una llamada a pmGetInstancesLabels porque diferentes instancias de métricas pueden tener etiquetas con el mismo nombre de etiqueta. La función pmLookupLabels no realiza ningún almacenamiento en caché de etiquetas internamente.

Para la eficiencia en la comunicación y el almacenamiento dentro de los diversos componentes del PMCS (Sistema de Recolección de Métricas de Rendimiento), las etiquetas se mantienen utilizando una jerarquía. El conjunto de etiquetas asociadas con cualquier valor de métrica individual consiste en la unión de las etiquetas de cada uno de estos conjuntos de etiquetas:

1. Etiquetas globales (se aplican a todos los valores de métricas de un contexto de host o archivo)
pmGetContextLabels
proporciona los labelsets asociados con todos los valores de métricas de una fuente dada (contexto PMAPI).
2. Etiquetas de dominio (se aplican a cada métrica dentro de un PMDA)
pmGetDomainLabels
proporciona los labelsets asociados con el identificador de domain.
3. Etiquetas de Dominio de Instancia (se aplican a todas las métricas que comparten ese indom)
pmGetInDomLabels
proporciona los labelsets asociados con el identificador de dominio de instancia indom.
4. Etiquetas de clúster (se aplican a un grupo de métricas dentro de un dominio)
pmGetClusterLabels
proporciona los labelsets asociados con el clúster de métricas (dominio, clúster) identificado por pmid.
5. Etiquetas de elemento (se aplican a una métrica de rendimiento individual)
pmGetItemLabels
proporciona los labelsets asociados con el elemento de métrica (dominio, clúster, elemento) identificado por pmid.
6. Etiquetas de instancia (se aplican a instancias individuales de una métrica)
pmGetInstancesLabels
proporciona el conjunto de identificadores de instancia y etiquetas en labelsets para cada instancia asociada con el identificador de dominio de instancia indom. El valor de retorno indica el número de elementos en el resultado, un labelsets por cada instancia.

Estos labelsets independientes se pueden fusionar usando pmMergeLabelSets(3) para formar el conjunto completo de todas las etiquetas asociadas con un valor dado. Tenga en cuenta que los conjuntos de etiquetas devueltos por pmGetInstancesLabels se pueden recorrer, pero no se deben fusionar, ya que es poco probable que los nombres de las etiquetas sean únicos para diferentes instancias del indom dado.

SINTAXIS DE ETIQUETA

Las etiquetas se almacenan y comunican dentro de PCP utilizando el formato JSONB. Este formato es una forma restringida de JSON adecuada para indexación y otras operaciones. En formato JSONB, se descartan los espacios en blanco insignificantes y no se conserva el orden de los nombres de las etiquetas. Sin embargo, dentro del PMCS, siempre se mantiene un espacio de claves ordenado lexicográficamente. No se permiten nombres de etiquetas duplicados. Se presenta solo la etiqueta con la precedencia más alta. Si se presentan nombres duplicados en el mismo nivel jerárquico, solo uno se conservará (exactamente cuál gana es arbitrario, así que no dependa de esto).

Todos los pares nombre:valor presentes se convertirán al formato JSONB y se fusionarán con el conjunto existente de etiquetas para la entidad solicitada (contexto, dominio, indom, métrica o instancia).

Los nombres de las etiquetas están además restringidos al mismo conjunto de reglas definidas para los nombres de subárboles de PMNS.

Cada componente en un nombre de etiqueta debe comenzar con un carácter alfabético y ser seguido por cero o más caracteres tomados del alfabeto, los dígitos y el carácter de guion bajo ("_"). Para los caracteres alfabéticos en un nombre, se distinguen mayúsculas y minúsculas.

El valor de una etiqueta ofrece una libertad significativamente mayor y puede ser cualquier valor válido según lo definido por la especificación JSON (https://www.json.org). Los espacios en blanco redundantes siempre se eliminan dentro del PMCS.

PRECEDENCIA

El conjunto completo de etiquetas asociadas con cualquier valor de métrica se construye a partir de varias fuentes y pueden existir nombres de etiquetas duplicados en cualquier punto de la jerarquía de origen. Sin embargo, al evaluar el conjunto de etiquetas (fusionando etiquetas de las diferentes fuentes), se utiliza el concepto JSONB de presentar solo etiquetas únicas. Por lo tanto, es importante definir reglas de precedencia para que se pueda definir un conjunto determinista de etiquetas con nombres únicos.

Como regla general, las etiquetas más cercanas a los nodos hoja de PMNS y a los valores de métricas tienen precedencia:

1. Etiquetas de contexto global
(según lo informado por la métrica pmcd.labels) son la menor precedencia.
2. Etiquetas de dominio
(para todas las métricas e instancias de un PMDA) tienen la siguiente precedencia más alta.
3. Etiquetas de Dominio de Instancia
asociadas con un InDom tienen la siguiente precedencia más alta.
4. Etiquetas de clúster de métricas
asociadas con un clúster PMID tienen la siguiente precedencia más alta.
5. Etiquetas de elementos de métricas
asociadas con un PMID individual tienen la siguiente precedencia más alta.
6. Etiquetas de instancia
asociadas con un identificador de instancia de métrica tienen la mayor precedencia.
