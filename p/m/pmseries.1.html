PMSERIES(1) Manual de Comandos Generales PMSERIES(1)

NOMBRE

pmseries - muestra información sobre series temporales de métricas de rendimiento

SINOPSIS

pmseries [-adFiIlLmMnqsStvV?] [-c config] [-D debug] [-g patrón] [-h host] [-p puerto] [-w ventana] [-Z zona horaria] [consulta | etiquetas ... | series ... | fuente ... ]

DESCRIPCIÓN

pmseries muestra varios tipos de información sobre métricas de rendimiento disponibles a través de las instalaciones escalables de series temporales del Performance Co-Pilot (PCP) y un almacén de datos distribuido de clave-valor como https://valkey/io/.

Por defecto, pmseries se comunica con un servidor local de clave-valor, sin embargo, las opciones -h y -p pueden usarse para especificar un servidor de clave-valor alternativo. Si esta instancia es un nodo dentro de un clúster, todas las demás instancias del clúster se descubrirán y usarán automáticamente.

pmseries se ejecuta en varios modos diferentes: consultando identificadores de series temporales, metadatos o valores (ya almacenados en el almacén de clave-valor), o cargando manualmente series temporales. Este último modo generalmente solo se usa para cargar archivos (inactivos) recopilados previamente, ya que pmproxy(1) realiza automáticamente esta función para instancias locales de pmlogger(1) "en vivo" (en crecimiento activo), cuando se ejecuta en su modo predeterminado de series temporales. Consulte la sección CARGA DE SERIES TEMPORALES a continuación y la opción -L para obtener más detalles.

Sin opciones de línea de comandos que especifiquen lo contrario, pmseries emitirá una consulta de series temporales para encontrar series temporales y valores coincidentes. Todas las series temporales se identifican mediante un hash SHA-1 único que siempre se muestra en un formato legible de 40 dígitos hexadecimales. Estos hashes se forman utilizando los metadatos asociados con cada métrica.

Es importante destacar que esto incluye todos los metadatos de las métricas (etiquetas, nombres, descriptores). Las etiquetas de métricas en particular son (en la medida de lo posible) únicas para cada máquina; en Linux, por ejemplo, las etiquetas asociadas con cada métrica incluyen el /etc/machine-id único, el nombre del host, el nombre de dominio y otras etiquetas de máquina generadas automáticamente, así como cualquier etiqueta definida por el administrador de /etc/pcp/labels. Estas etiquetas se pueden mostrar con pminfo(1) y la métrica pmcd.labels.

Consulte pmLookupLabels(3), pmLookupInDom(3), pmLookupName(3) y pmLookupDesc(3) para obtener información detallada sobre las etiquetas de métricas y otros metadatos de métricas utilizados en el cálculo del hash de identificador de cada serie temporal.

Los identificadores de series temporales proporcionan un identificador de nivel superior (e independiente de la máquina) que los identificadores de métricas de rendimiento tradicionales de PCP (pmID), los identificadores de dominios de instancias (pmInDom) y los nombres de métricas. Consulte PCPIntro(1) para obtener más detalles sobre estos identificadores tradicionales. Sin embargo, pmseries utiliza identificadores de series temporales de manera muy similar a como pminfo(1) utiliza el dominio interno de nivel inferior, los identificadores de métricas y los nombres de métricas.

El modo predeterminado de operación de pmseries (es decir, sin opciones de línea de comandos) depende de los argumentos que se le presenten. Si todos los argumentos que no son opciones parecen ser identificadores de series temporales (en formato de 40 dígitos hexadecimales), pmseries informará metadatos para estas series temporales; consulte la opción -a para obtener detalles. De lo contrario, los parámetros se tratarán como una consulta de series temporales.

CONSULTAS DE SERIES TEMPORALES

Las expresiones de consulta se forman utilizando el lenguaje de consultas de pmseries descrito a continuación, pero pueden ser tan simples como un nombre de métrica.

El siguiente es un ejemplo de consulta de series temporales de todos los hosts que coinciden con un patrón de nombre de métrica (usando globbing):

$ pmseries kernel.all.cpu*
1d7b0bb3f6aec0f49c54f5210885464a53629b60
379db729afd63fb9eff436625bd6c55a7adc5cfd
3dd3b45bb05f96636043e5d58b52b441ce542285
[...]
ed2bf325ff6dc7589ec966698e5404b67252306a
dcb2a032a308b5717bf605ba8f8737e9c6e1ed19

Para identificar los operandos de la expresión de series temporales, el lenguaje de consulta utiliza la sintaxis general:

[nombre.de.métrica] '{calificadores de metadatos}' '[especificación de tiempo]'

El componente nombre.de.métrica restringe la consulta de series temporales a cualquier nombre de métrica PCP coincidente (la lista de nombres de métricas para un archivo PCP o un host en vivo se informa con pminfo(1) sin argumentos adicionales además de --host o --archive). La sintaxis de pmseries se extiende sobre la de pminfo y permite la coincidencia de patrones basada en glob(7) dentro del nombre de la métrica. Lo anterior describe los operandos disponibles como hojas de las expresiones de pmseries, que pueden incluir funciones, operadores aritméticos y otras características. Consulte la sección EXPRESIONES a continuación para obtener más detalles.

CALIFICADORES DE METADATOS Y OPERADORES DE METADATOS

Los calificadores de metadatos están encerrados entre llaves ("{}") y restringen aún más los resultados de la consulta a operandos de series temporales con diversas propiedades de metadatos. Estos calificadores se basan en nombres de métricas o instancias, y valores de etiquetas de métricas, y toman la forma general nombre.metadatos OPERADOR valor, como:

instance.name == "cpu0"
metric.name != "kernel.all.pswitch"

Al usar nombres de etiquetas, el calificador de metadatos es opcional y se puede omitir, como:

label.hostname == "www.acme.com"
hostname == "www.acme.com"

Para nombres de métricas e instancias solo se aplican los operadores de cadenas, pero para los valores de etiquetas de métricas todos los operadores están disponibles. El conjunto de operadores disponibles es:

Operadores booleanos

Todos los valores de cadenas (etiquetas, métricas e instancias) y numéricos (etiquetas) se pueden probar para igualdad ("==") o desigualdad ("!=").

Operadores de cadena

Las cadenas pueden estar sujetas a coincidencia de patrones en forma de coincidencia de glob ("~~"), coincidencia de expresiones regulares ("=~") y no coincidencia de expresiones regulares ("!~"). El operador ":" es equivalente a "~~", es decir, coincidencia de glob.

Operadores relacionales (solo valores numéricos de etiquetas)

Los valores numéricos de etiquetas pueden estar sujetos a los operadores menor que ("<"), mayor que (">"), menor o igual ("<="), mayor o igual (">="), igual ("==") y no igual ("!=").

Operadores lógicos

Múltiples calificadores de metadatos se pueden combinar con los operadores lógicos AND ("&&") y OR ("||") como en muchos lenguajes de programación. El carácter coma (",") es equivalente a AND lógico ("&&").

ESPECIFICACIÓN DE TIEMPO

El componente final (opcional) de una consulta permite al usuario especificar una ventana de tiempo específica de interés. Cualquier especificación de tiempo dará como resultado que se devuelvan valores para todas las series temporales coincidentes solo para la ventana de tiempo especificada.

La especificación está encerrada entre corchetes ("[]") y consta de uno o más componentes separados por comas. Cada componente especifica algún aspecto relacionado con el tiempo, tomando la forma general: palabra clave: valor, como:

samples:10

Recuento de muestras

El número de muestras a devolver, especificado a través de la palabra clave samples o (equivalente) count. El valor proporcionado debe ser un entero positivo. Si no se establece explícitamente una hora de finalización (consulte "Ventana de tiempo" más adelante), entonces la hora más reciente

OPTIONS

Los siguientes operandos pueden ser utilizados para configurar el comportamiento de pmseries(1).

Intervalo de muestras

Se puede solicitar un intervalo entre muestras sucesivas usando la palabra clave interval o (equivalente) delta. El valor proporcionado debe ser un valor numérico o de cadena que será analizado por pmParseInterval(3), como 5 (segundos) o 2min (minutos).

Ventana de tiempo

Tiempos de inicio y fin, y alineaciones, que afectan a los valores devueltos. Las palabras clave coinciden con los parámetros de la función pmParseTimeWindow(3) que se utilizará para analizarlos, y son: start o (equivalente) begin, finish o (equivalente) end, align y offset.

Zonas horarias

Las marcas de tiempo resultantes pueden ser devueltas habiendo sido evaluadas para una zona horaria específica, usando las palabras clave timezone o hostzone. El valor asociado a timezone será interpretado por pmNewZone(3). Un valor true o false debe ser asociado a hostzone, y cuando se establece a true esto tiene el mismo efecto que el descrito por pmNewContextZone(3).

EXPRESIONES

Como se describió anteriormente, los operandos son las hojas de un árbol de expresión de consulta.

[nombre.métrica] '{calificadores de metadatos}' '[especificación de tiempo]'
Nótese que en la mayoría de los ejemplos de expresiones de consulta a continuación, los calificadores de metadatos se han omitido por brevedad. En todos los casos, múltiples series temporales pueden calificar, particularmente para la etiqueta hostname.

En el caso simple, una expresión de consulta consiste en un solo operando y puede ser solo un nombre de métrica. En el caso más general, una expresión de consulta es un operando o el argumento de una función, o dos operandos en una expresión aritmética o lógica binaria. La mayoría de las funciones toman un solo argumento (una expresión), aunque algunas requieren argumentos adicionales, por ejemplo, rescale.

operando | expr operador expr | func(expr[, arg])

Esta gramática muestra que las expresiones pueden anidarse, por ejemplo, usando el operador de adición (+) como ejemplo,

func1(func2(expr))
func1(expr) + func2(expr)
expr + func(expr)
func(expr) + expr
expr + expr

Las reglas que rigen la compatibilidad de operandos en una expresión generalmente dependen de la función y/o los operadores y se describen a continuación individualmente. Una regla importante es que si se especifican ventanas de tiempo, todos los operandos deben cubrir el mismo número de muestras, aunque las ventanas de tiempo pueden diferir individualmente. Si no se proporcionan ventanas de tiempo ni recuentos de muestras, pmseries devolverá un identificador de serie (SID) en lugar de una serie de marcas de tiempo y valores. Este SID puede usarse en posteriores llamadas a la API REST /series/values?series=SID, junto con una ventana de tiempo específica.

Operadores Aritméticos

pmseries admite suma, resta, división y multiplicación en cada valor de la serie temporal de un par binario de operandos. No se admiten operadores unarios o ternarios (todavía). En todos los casos, el dominio de instancias y el número de muestras de los operandos de series temporales deben ser los mismos. Los metadatos (unidades y dimensiones) también deben ser compatibles. Dependiendo de la función, el resultado generalmente tendrá el mismo dominio de instancias y (a menos que se indique lo contrario), las mismas unidades que los operandos. Las dimensiones de los metadatos (espacio, tiempo, conteo) del resultado pueden diferir (ver abajo).

Los operandos de la expresión pueden tener diferentes calificadores, por ejemplo, se pueden realizar aritmética binaria en métricas calificadas por diferentes etiquetas (como hostname), o nombres de métricas. Por ejemplo, para sumar las dos muestras más recientes del contador de cambios de contexto (pswitch) para los hosts node88 y node89, y luego realizar la conversión de tasa:

$ pmseries 'rate(kernel.all.pswitch{hostname:node88}[count:2] +
                 kernel.all.pswitch{hostname:node89}[count:2])'
1cf1a85d5978640ef94c68264d3ae8866cc11f7c
    [Tue Nov 10 14:39:48.771868000 2020] 71.257509 8e0a59304eb99237b89593a3e839b5bb8b9a9924

Tenga en cuenta que la serie temporal de valores resultante tiene una muestra menos que el operando de expresión pasado a la función rate.

Otras reglas para expresiones aritméticas:

1. Si ambos operandos tienen la semántica de un contador, solo se permiten la suma y la resta
2. Si el operando izquierdo es un contador y el derecho no lo es, solo se permiten la multiplicación o la división
3. Si el operando izquierdo no es un contador y el derecho es un contador, solo se permite la multiplicación.
4. Suma y resta: las dimensiones del resultado son las mismas que las dimensiones de los operandos.
5. Multiplicación: las dimensiones del resultado son la suma de las dimensiones de los operandos.
6. División: las dimensiones del resultado son la diferencia de las dimensiones de los operandos.

Funciones

Las funciones de expresión operan en vectores de valores de series temporales y pueden anidarse con otras funciones o expresiones como se describió anteriormente. Cuando un operando tiene múltiples instancias, generalmente habrá un resultado por cada serie de instancias. Por ejemplo, el resultado para

$ pmseries 'min_sample(kernel.all.load[count:100])'

será el valor más pequeño de las 100 muestras más recientes, tratando cada una de las tres instancias de carga promedio como una serie temporal separada. Como ejemplo, para las dos muestras más recientes de cada una de las tres instancias de la métrica de carga promedio:

Algunas funciones de pmseries proporcionan operaciones en los dominios de tiempo e instancias. Por ejemplo, max_inst(expr) encuentra el valor máximo entre las instancias, mientras que max_sample(expr) encuentra el valor máximo a lo largo del tiempo.

Las futuras versiones de pmseries pueden proporcionar funciones que realicen agregación, interpolación, filtrado o transformaciones de otras maneras.

Referencia de Funciones

max_inst(expr) el valor máximo en la serie temporal para cada instancia de expr. Por compatibilidad hacia atrás, el sinónimo max es equivalente a max_inst.

max_sample(expr) el valor máximo en la serie temporal para cada muestra de expr a lo largo del tiempo.

min_inst(expr) el valor mínimo en la serie temporal para cada instancia de expr. Por compatibilidad hacia atrás, el sinónimo min es equivalente a min_inst.

min_sample(expr) el valor mínimo en la serie temporal para cada muestra de expr a lo largo del tiempo.

sum_inst(expr) suma de los valores en la serie temporal para cada instancia de expr. Por compatibilidad hacia atrás, el sinónimo sum es equivalente a sum_inst.

sum_sample(expr) suma de los valores en la serie temporal para cada muestra de expr a lo largo del tiempo.

avg_inst(expr) promedio de los valores en la serie temporal para cada instancia de expr. Por compatibilidad hacia atrás, el sinónimo avg es equivalente a avg_inst.

avg_sample(expr) promedio de los valores en la serie temporal para cada muestra de expr a lo largo del tiempo.

rate(expr) la tasa con respecto al tiempo de cada muestra. El expr dado debe tener la semántica de counter y el resultado tendrá la semántica de instant (la dimensión de tiempo reducida en uno). Además, el resultado tendrá una muestra menos que el operando; esto se debe a que la primera muestra no puede ser convertida a tasa (se requieren dos muestras).

rescale(expr,scale) reescala los valores en la serie temporal para cada instancia de expr a scale (unidades). Tenga en cuenta que expr debe tener semántica instant o discrete (no counter; la conversión a tasa debe hacerse primero si es necesario). Las dimensiones de tiempo, espacio y conteo entre expr y scale deben ser compatibles. Ejemplo: convertir la tasa del contador de rendimiento de lectura para cada instancia de disco y luego reescalar a Mbytes por segundo. Tenga en cuenta que las unidades nativas de disk.dev.read_by

Para más detalles, consulte .BR PMWEBAPI(3) . .PP Si las semánticas de ambos operandos en una expresión aritmética no son un contador (es decir, .B PM_SEM_INSTANT o .B PM_SEM_DISCRETE ) entonces el resultado tendrá semánticas .B PM_SEM_INSTANT a menos que ambos operandos sean .B PM_SEM_DISCRETE en cuyo caso el resultado también es .B PM_SEM_DISCRETE . .SH "METADATOS_DE_SERIES_TEMPORALES" .PP Utilizando opciones de línea de comandos, se puede solicitar a .B pmseries que proporcione metadatos (nombres de métricas, nombres de instancias, etiquetas, descriptores) asociados con series temporales individuales o un grupo de series temporales, por ejemplo: .PP .DM $ pmseries -a dcb2a032a308b5717bf605ba8f8737e9c6e1ed19 dcb2a032a308b5717bf605ba8f8737e9c6e1ed19 PMID: 60.0.21 Data Type: 64-bit unsigned int InDom: PM_INDOM_NULL 0xffffffff Semantics: counter Units: millisec Source: f5ca7481da8c038325d15612bb1c6473ce1ef16f Metric: kernel.all.cpu.nice labels {"agent":"linux","domainname":"localdomain", "groupid":1000,"hostname":"shard", "latitude":-25.28496,"longitude":152.87886, "machineid":"295b16e3b6074cc8bdbda8bf96f6930a", "userid":1000} .DE .PP El conjunto completo de opciones de informes de metadatos de .B pmseries son: .TP .BI \-a , \-\-all Opción de conveniencia para informar todos los metadatos de la serie temporal dada, equivalente a .BI \-deilms . .TP .BI \-d , \-\-desc Descripciones de métricas que detallan el PMID, tipo de datos, semántica de datos, unidades, escala y dominio de instancia asociado. Esta opción tiene un equivalente directo en .BR pminfo(1) . .TP .BI \-F , \-\-fast Consultar o cargar solo metadatos de series, no valores. .TP .BI \-g pattern, \-\-glob=pattern Proporcione un patrón de .BR glob(7) para restringir el informe proporcionado por .BI \-i , \-l , \-m , y .BI \-S . .TP .BI \-i, \-\-instances Descripciones de métricas que detallan el PMID, tipo de datos, semántica de datos, unidades, escala y dominio de instancia asociado. .TP .BI \-I, \-\-fullindom Imprime el InDom en modo detallado. Esta opción tiene un equivalente directo en .BR pminfo(1) . .TP .BI \-l, \-\-labels Imprime conjuntos de etiquetas asociados con métricas e instancias. Las etiquetas son metadatos de métricas opcionales descritos en detalle en .BR pmLookupLabels(3) . Esta opción tiene un equivalente directo en .BR pminfo(1) . .TP .BI \-m, \-\-metrics Imprime nombres de métricas. .TP .BI \-M, \-\-fullpmid Imprime el PMID en modo detallado. Esta opción tiene un equivalente directo en .BR pminfo(1) . .TP .BI \-n, \-\-names Imprime solo nombres de etiquetas separados por comas (no valores) para las etiquetas asociadas con métricas e instancias. .TP .BI \-s, \-\-series Imprime identificadores de series temporales asociados con métricas, instancias y fuentes. Estos identificadores únicos se calculan a partir de etiquetas intrínsecas (no opcionales) y otros metadatos de métricas asociados con cada contexto de PMAPI (fuentes), métricas e instancias. Las conexiones de archivo, contexto local o .BR pmcd(1) para el mismo host producen el mismo identificador de fuente. Esta opción tiene un equivalente directo en .BR pminfo(1) . Consulte también .BR pmLookupLabels(3) y la opción .BI \-l/\-\-labels . .SH "FUENTES_DE_SERIES_TEMPORALES" .PP Una fuente es un identificador único (representado externamente como un hash SHA-1 hexadecimal de 40 bytes) que representa tanto el host en vivo y/o los archivos de donde se originó cada serie temporal. El contexto para un identificador de fuente (obtenido con .BI \-s ) se puede informar con: .TP .BI \-S, \-\-sources Imprime nombres para las fuentes de series temporales. Estos nombres son nombres de host o rutas de archivo completas. .PP Es importante tener en cuenta que las fuentes en vivo y de archivo pueden y generarán el mismo hash de identificador de fuente SHA-1, siempre que las etiquetas de contexto permanezcan iguales para ese host (las etiquetas se almacenan en archivos PCP y también se pueden obtener en vivo desde .BR pmcd(1) ). .SH diseñada y la opción .BI \-L/\-\-load : .PP .DM $ pmseries --load "{source.path: \"\$PCP_LOG_DIR/pmlogger/acme\"}" pmseries: [Info] processed 2275 archive records from [...] .DE .PP Esta consulta debe especificar una ruta de archivo de origen, pero también puede restringir la importación a series temporales específicas (utilizando nombres de métricas, etiquetas, etc.) y a una ventana de tiempo específica utilizando el componente de especificación de tiempo del lenguaje de consulta. .PP Como conveniencia, si el argumento para cargar es una ruta de archivo válida según lo determinado por .BR tiempo) y si se cargan más de .B stream.maxlen entradas (definidas en .I \$PCP_SYSCONF_DIR/pmseries/pmseries.conf ) para una métrica dada, se descartan las entradas más antiguas. .SH "OPCIONES" .PP OPTIONS

-D debug
Enable debugging output. debug is a comma separated list of debugging options. Use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.
-h
Print a help message and exit.
-I initializer
Specify the PMCD connector or PMDAP connector that should be used to access the Performance Metrics Domain Resource (PMDR). See pmConnect(3) for details.
-m
Print only the metadata for the selected timeseries, in the format described in pmSeries(3).
-t timefmt
Specify the output time format. See pmtime(3) for details.
-T context
When fetching metrics, use the specified context instead of the default context. See pmNewContext(3) for details.
-?, --help
Display usage message and exit.

$ pmseries 'kernel.all.load{hostname:"toium"}[count:2]'

    [Thu Nov 14 05:57:16.091546000 2019] 6.7e-01 a60b5b3bf25e71071c41934fa4d7d251f765f30c
    [Thu Nov 14 05:57:16.091546000 2019] 6.4e-01 e1974a062375e6e62370ffadf5b0650dad739480

This query returns the two most recent values for all instances of the kernel.all.load metric with a label.hostname matching the regular expression "toium". This is a set-valued metric (i.e., a metric with an ``instance domain'' which in this case consists of three instances: 1, 5 and 15 minute averages). The first column returned is a timestamp, then a floating point value, and finally an instance identifier timeseries hash (two values returned for three instances, so six rows are returned). PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

The timezone of the Performance Metrics Domain (PMD) is determined by the TZ environment variable, as described in environ(7).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.
