PMDANETCHECK(1) Manual de comandos generales PMDANETCHECK(1)

NOMBRE

pmdanetcheck - PMDA netcheck

DESCRIPCIÓN

pmdanetcheck es un Agente de Dominio de Métricas de Rendimiento (PMDA) de Performance Co-Pilot (PCP) que realiza comprobaciones básicas de red en el host local utilizando módulos simples de Python y, en algunos casos, utilidades externas como ping(1).

pmdanetcheck carga y actúa como puente para cualquier número de módulos PMDA netcheck de PCP configurados y separados que ejecuten código Python o programas externos. Debería ser posible utilizar módulos y programas de Python existentes con módulos PMDA netcheck de PCP con un esfuerzo mínimo.

Tenga en cuenta que en sistemas con SELinux habilitado, para que pmdanetcheck pueda utilizar el comando ping(1), el grupo pcp debe poder crear sockets de Eco ICMP; asegúrese de que el ID del grupo para pcp esté incluido en el rango en /proc/sys/net/ipv4/ping_group_range y consulte icmp(7) para más detalles sobre esto.

CONFIGURACIÓN

pmdanetcheck lee un archivo de configuración obligatorio estilo ini:

$PCP_PMDAS_DIR/netcheck/netcheck.conf

Este archivo debe contener una sección [pmda]. Las siguientes opciones de PMDA están disponibles (sus valores predeterminados se muestran entre paréntesis), las opciones marcadas con un asterisco (*) pueden ser anuladas en secciones de configuración específicas del módulo:

modules (no establecido)
El PMDA pmdanetcheck lee la configuración específica del módulo para cada módulo listado en la lista separada por comas de modules (obligatorio).
hosts (DGW,DNS) *
Una lista de hosts (opcional) separada por comas especifica los hosts para los cuales ejecutar las comprobaciones. Los valores especiales DGW, DNS, NTP se traducirán a la puerta de enlace predeterminada, los servidores de nombres listados en /etc/resolv.conf y los servidores de tiempo listados en /etc/chrony.conf, respectivamente, al iniciar el PMDA.
background_check (Verdadero) *
Un valor booleano para background_check (opcional) controla si se realizan comprobaciones constantemente en segundo plano o solo bajo demanda. Consulte el archivo de configuración predeterminado para obtener más información sobre esto.
check_hosts_parallel (Verdadero) *
check_hosts_parallel (opcional) controla si los módulos deben comprobar los hosts uno por uno o en paralelo.
check_interval (1m) *
check_interval (opcional) especifica el intervalo de tiempo entre dos comprobaciones consecutivas de hosts cuando las comprobaciones se realizan en segundo plano. Consulte PCPIntro(1) para una descripción completa de la sintaxis del intervalo de tiempo.
align_interval (Verdadero) *
align_interval (opcional) especifica si se debe tener en cuenta la duración de la comprobación anterior al pausar entre comprobaciones.
module_failure_fatal (Verdadero)
Un valor booleano para module_failure_fatal (opcional) controla si un módulo que no se inicializa debe hacer que todo el PMDA se cancele (este es el valor predeterminado) o si debe iniciarse con módulos posiblemente funcionales restantes. Los errores de configuración del módulo y los errores internos (como no poder registrar las métricas PMNS proporcionadas, consulte pmns(5)) siempre harán que el PMDA no pueda iniciarse.

Para cada module listado en modules, se debe definir una sección [module] correspondiente. Cada sección [module] puede contener al menos las siguientes opciones (sus valores predeterminados se muestran entre paréntesis):

timeout (1)
Forzar un timeout absoluto (opcional) para cada operación individual de comprobación de red.
debug (Falso)
Habilitar el registro de mensajes de debug internos (raramente utilizado).

Las opciones específicas del módulo que aceptan los módulos se describen en el archivo de configuración predeterminado.

Los módulos esperan que la funcionalidad básica de red esté presente en el sistema, por ejemplo, que la dirección localhost sea accesible.

INSTALACIÓN

Para instalar, se debe hacer lo siguiente como root:

# cd $PCP_PMDAS_DIR/netcheck
# ./Install

Para desinstalar, se debe hacer lo siguiente como root:

# cd $PCP_PMDAS_DIR/netcheck
# ./Remove

pmdanetcheck es lanzado por pmcd(1) y nunca debe ejecutarse directamente. Los scripts Install y Remove notifican a pmcd(1) cuando el agente se instala o se elimina.

En caso de que module_failure_fatal esté configurado como False, la instalación del PMDA se considerará exitosa si algunos (pero no todos) los módulos configurados fallan al cargarse; en tales casos, las métricas proporcionadas por los módulos fallidos no estarán disponibles. El archivo de registro de agente pmdanetcheck (ver abajo) contendrá información detallada sobre la activación de cada módulo.

Los módulos proporcionarán valores reales solo después de haber recopilado datos. Por ejemplo, para el módulo ping, el valor de la métrica es el valor de salida del comando ping(1) y para ping_latency es la latencia promedio de los paquetes según lo informado por ping(1). Para métricas que indican estado, 0 denota éxito. En caso de que una comprobación aún no haya finalizado, su valor de métrica es -1. Si una comprobación se terminó durante la ejecución debido a un tiempo de espera, el valor es -2.

ARCHIVOS

$PCP_PMDAS_DIR/netcheck/netcheck.conf
archivo de configuración para el agente pmdanetcheck
$PCP_PMDAS_DIR/netcheck/netcheck/*.{py,python}
módulos Python PMDA netcheck de PCP para el agente pmdanetcheck
$PCP_PMDAS_DIR/netcheck/Install
script de instalación para el agente pmdanetcheck
$PCP_PMDAS_DIR/netcheck/Remove
script para deshacer la instalación del agente pmdanetcheck
$PCP_LOG_DIR/pmcd/netcheck.log
archivo de registro predeterminado para mensajes del agente pmdanetcheck

Tenga en cuenta que el valor usual/predeterminado para $PCP_PMDAS_DIR es /var/lib/pcp/pmdas y el valor predeterminado para $PCP_LOG_DIR es /var/log/pcp, pero estas configuraciones dependen de la plataforma.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).
