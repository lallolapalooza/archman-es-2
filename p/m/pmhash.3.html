DESCRIPCIÓN

El grupo de rutinas __pmHash implementa un conjunto generalizado de servicios de hashing lineal basados en una clave que es un entero sin signo y datos que es un puntero opaco a la información que el llamador desea asociar con la clave.

El tipo de dato de la clave lo hace adecuado para el acceso hasheado basado en el identificador de métrica (pmID), el número de dominio de instancia (pmInDom) o identificadores de instancia internos dentro de un dominio de instancia.

Puede existir varias tablas hash, cada una identificada por una estructura de control de hash (__pmHashCtl) hcp que es declarada por el llamador e inicializada llamando a __pmHashInit. Consulte las secciones CONTROL DE HASH y NODO DE HASH a continuación para obtener más información sobre las estructuras de datos internas de la tabla hash.

La tabla hash está inicialmente vacía, pero crece dinámicamente aproximadamente duplicando su tamaño a medida que se agregan entradas, y esto puede causar cierta sobrecarga organizativa al volver a enlazar las cadenas de hash cuando la tabla hash crece. Esta sobrecarga se puede evitar llamando opcionalmente a __pmHashPreAlloc con un tamaño inicial de tabla hash de hsize entradas, pero esto debe hacerse después de llamar a __pmHashInit y antes de que se agreguen las entradas.

Las entradas se agregan a una tabla hash llamando a __pmHashAdd. Los datos opacos suelen ser un puntero a un bloque de información adicional que se asociará con la clave, aunque puede ser NULL si no se requiere o no hay información adicional disponible.

Aunque generalmente no es necesario, se pueden almacenar valores de clave duplicados en una tabla hash y __pmHashAdd los agregará silenciosamente (presumiblemente con un puntero de datos diferente). Si se requiere unicidad de las claves, es necesario llamar primero a __pmHashSearch para determinar que no hay una entrada para la clave, antes de llamar a __pmHashAdd.

Las entradas se pueden eliminar de una tabla hash usando __pmHashDel donde la entrada a eliminar es la primera con una clave y un puntero de datos coincidentes. Consulte la nota anterior sobre claves duplicadas para comprender por qué se necesita el parámetro de datos.

__pmHashSearch encuentra la primera entrada con una clave coincidente. Si se almacenan claves duplicadas, el llamador tendrá que seguir la cadena hp->next buscando entradas adicionales con la misma clave. Consulte las secciones CONTROL DE HASH y NODO DE HASH a continuación para obtener más información sobre las estructuras de datos internas de la tabla hash.

__pmHashWalk proporciona una interfaz con estado para recorrer cada nodo en la tabla hash. Se llama primero con state establecido en PM_HASH_WALK_START para recuperar la primera entrada y luego se llama repetidamente con state establecido en PM_HASH_WALK_NEXT para recuperar entradas subsiguientes.

__pmHashWalkCB proporciona un método alternativo para recorrer la tabla hash. La función de devolución de llamada cb se llama con dos argumentos, un puntero a la entrada hash actual y cdata (este último permite al llamador pasar información auxiliar a la función de devolución de llamada, pero puede ser NULL si no se requiere). La función de devolución de llamada debe devolver uno de los siguientes valores __pmHashWalkState:

PM_HASH_WALK_NEXT
continuar el recorrido
PM_HASH_WALK_STOP
terminar el recorrido
PM_HASH_DELETE_NEXT
eliminar el nodo actual de la tabla hash y continuar el recorrido
PM_HASH_DELETE_STOP
eliminar el nodo actual de la tabla hash y terminar el recorrido

__pmHashFree liberará todo el almacenamiento asociado con la tabla hash y devolverá la tabla hash a su estado vacío, igual que después de haber llamado a __pmHashInit. Pero __pmHashFree no puede liberar ningún almacenamiento adjunto a través del argumento data de las llamadas a __pmHashAdd. Por lo tanto, la forma más apropiada de limpiar la tabla hash es recorrer primero la tabla liberando cualquier data y luego llamar a __pmHashFree, como se muestra en el siguiente ejemplo.


__pmHashCtl	hash;
__pmHashWalkState
mycallback(const __pmHashNode *hp, void *cp)
{
    (void)cp;
    if (hp->data) {
	/*
	 * free() si se asignó con malloc() o algún método específico
	 * de datos, por ejemplo, __pmFreeProfile()
	 */
        free(hp->data);
    }
    return PM_HASH_WALK_NEXT;
}
...
    __pmHashWalkCB(mycallback, NULL, &hash);
    __pmHashFree(&hash);
}

__pmHashClear devuelve la tabla hash a su estado vacío, igual que después de haber llamado a __pmHashInit. Tenga en cuenta que __pmHashClear no libera ningún almacenamiento asociado con las entradas hash, y por lo tanto corre el riesgo de fugas de memoria. Sin embargo, el siguiente ejemplo muestra cómo liberar toda la memoria en un único recorrido de la tabla hash con __pmHashWalkCB antes de llamar a __pmHashClear.


__pmHashCtl	hash;
__pmHashWalkState
mycallback(const __pmHashNode *hp, void *cp)
{
    (void)cp;
    if (hp->data) {
	/*
	 * free() si se asignó con malloc() o algún método específico
	 * de datos, por ejemplo, __pmFreeProfile()
	 */
        free(hp->data);
    }
    /*
     * en comparación con el ejemplo anterior, esta diferencia
     * es importante y libera cada nodo hash
     */
    return PM_HASH_DELETE_NEXT;
}
...
    __pmHashWalkCB(mycallback, NULL, &hash);
    __pmHashClear(&hash);
}

CONTROL DE HASH

La estructura __pmHashCtl se define como:


typedef struct __pmHashCtl {
    int                 nodes;
    int                 hsize;
    __pmHashNode        **hash;
    __pmHashNode        *next;
    unsigned int        index;
} __pmHashCtl;

La tabla hash hash contiene hsize entradas, cada una de las cuales puede apuntar a una lista enlazada de nodos hash. El número total de nodos hash se mantiene en nodes. Los campos index y next se utilizan para mantener el estado durante las operaciones de recorrido de la tabla hash.

NODO DE HASH

La estructura __pmHashNode se define como:


typedef struct __pmHashNode {
    struct __pmHashNode *next;
    unsigned int        key;
    void                *data;
} __pmHashNode;

Cada nodo contiene la clave, el puntero opaco (data) y next implementa la lista enlazada de nodos hash de cada entrada en la tabla hash.

DIAGNOSTICS AND RETURN VALUES

There are no specific diagnostic error messages for the __pmHash family of functions. Instead, any error encountered by __pmHashAdd, __pmHashDel, __pmHashSearch, or __pmHashWalk can be turned into an error message by calling pmErrStr(3).

__pmHashAdd returns 1 for success, else a value < 0 to indicate an error, probably from calloc(3).

Return values from __pmHashDel are 0 if no matching entry is found, else 1 if a matching entry was deleted.

__pmHashSearch returns with a pointer to the entry if found, else NULL.

__pmHashWalk returns with a pointer to the next entry if found, else NULL when all entries have been traversed.
