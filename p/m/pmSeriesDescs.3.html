NOMBRE

pmSeriesDescs, pmSeriesLabels, pmSeriesLabelValues, pmSeriesInstances, pmSeriesMetrics, pmSeriesSources - metadatos de series temporales rápidos y escalables

SINOPSIS C

#include <pcp/pmwebapi.h>

int pmSeriesDescs(pmSeriesSettings *sp,
int count, sds *series, void *arg);

int pmSeriesLabels(pmSeriesSettings *sp,
int count, sds *series, void *arg);

int pmSeriesLabelValues(pmSeriesSettings *sp,
int count, sds *labels, void *arg);

int pmSeriesInstances(pmSeriesSettings *sp,
int count, sds *series, void *arg);

int pmSeriesMetrics(pmSeriesSettings *sp,
int count, sds *series, void *arg);

int pmSeriesSources(pmSeriesSettings *sp,
int count, sds *series, void *arg);

cc ... -lpcp_web

DESCRIPCIÓN

Cada métrica de rendimiento y fuente de datos que forma parte del servicio de series temporales rápido y escalable de Performance Co-Pilot (PCP) tiene ciertas propiedades (metadatos) asociadas. Estas propiedades se pueden consultar utilizando las interfaces descritas aquí.

Esta funcionalidad se proporciona a través de APIs asíncronas, que funcionan de forma basada en eventos, donde se invocan devoluciones de llamada para cada estructura de metadatos que se devuelve.

Como patrón general, todas las interfaces en estas APIs que necesitan invocar devoluciones de llamada proporcionadas por el programa llamante (consulte pmSeriesSetup(3)) tomarán un parámetro opaco (puntero void *), arg. Este puntero se pasará sin cambios y normalmente se utiliza para acceder a una estructura de datos que mantiene el estado dentro del programa llamante.

Con un par de excepciones, estas interfaces tienden a operar en uno de dos modos. En primer lugar, hay una invocación disponible para consultar metadatos para un número (distinto de cero) count de series temporales. Un segundo modo, con un count (cero), devuelve todos los metadatos disponibles de ese tipo, en todas las series temporales.

Para recuperar información descriptiva de métricas para una o más series temporales, se utiliza la interfaz pmSeriesDescs. Por cada identificador de series válido proporcionado, se invocará una devolución de llamada proporcionando las unidades de la métrica, la semántica y el tipo, así como otros identificadores asociados a ella (pmID, InDom e identificador de origen). Cuando se emite esta llamada con un valor cero para count, es un error pasar un valor cero o negativo de count a esta interfaz.

Para extraer nombres y valores de etiquetas, se utiliza la interfaz pmSeriesLabels. Con un valor distinto de cero para count de identificadores de series válidos, esta rutina invocará una devolución de llamada una vez por cada nombre de etiqueta y una vez por cada par nombre de etiqueta:valor, para las etiquetas asociadas a esas series temporales. Si se llama con un count de cero, esta interfaz devolverá (a través de la devolución de llamada del nombre de etiqueta) todos los nombres de etiqueta que se han observado hasta la fecha, no asociados con series temporales específicas. La interfaz pmSeriesLabelValues es comparable a este último modo, excepto que devolverá todos los valores de etiqueta que se han observado hasta la fecha para la matriz dada de nombres de labels (no asociados con ningún identificador de serie temporal específico).

pmSeriesInstances se puede utilizar para encontrar metadatos sobre dominios de instancias e identificadores de instancias asociados con un count dado (distinto de cero) de identificadores de series temporales. Si se pasa un valor cero para count, se devolverán todos los nombres de instancia observados hasta la fecha.

pmSeriesMetrics se puede utilizar para encontrar nombres de métricas asociados con un count dado (distinto de cero) de identificadores de series temporales. Si se pasa un valor cero para count, se devolverán todos los nombres de métricas observados hasta la fecha.

pmSeriesSources se puede utilizar para encontrar metadatos sobre la fuente de las métricas, es decir, nombres de host y rutas de archivos de archivo. Si se pasa un valor cero para count, se devolverán todas las fuentes de métricas observadas hasta la fecha.

DIAGNÓSTICOS

Donde estas funciones devuelven un código de estado, este siempre es cero en caso de éxito. En caso de fallo, se devuelve un código de error negativo de PMAPI.
