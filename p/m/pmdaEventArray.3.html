DESCRIPCIÓN

Se anima a un Agente de Dominio de Métricas de Rendimiento (PMDA) que desea exportar registros de eventos (o registros de rastreo) a utilizar una métrica de tipo PM_TYPE_EVENT o PM_TYPE_HIGHRES_EVENT para codificar un grupo de registros de eventos en un solo arreglo empaquetado.

La única diferencia entre los dos tipos de métrica es la resolución de la marca de tiempo asociada con cada una: en formato de alta resolución es a escala de nanosegundos (ver clock_gettime(2)), de lo contrario es en microsegundos (ver gettimeofday(2)). Por simplicidad, solo nos referiremos a la API y estructuras de datos de menor resolución en lo sucesivo; sin embargo, las variantes de mayor resolución tienen nombres similares y se utilizan de la misma manera.

El formato del arreglo empaquetado de registros de eventos se define en <pcp/pmapi.h> y consta de una estructura pmEventArray que contiene un número variable de estructuras pmEventRecord, cada una de las cuales contiene un número variable de estructuras pmEventParameter, que a su vez pueden contener un valor de longitud variable para cada parámetro de cada registro de evento.

Los equivalentes de alta resolución se definen en la misma ubicación, y las estructuras tienen el mismo nombre. Tenga en cuenta que la estructura pmEventParameter no tiene una marca de tiempo asociada, por lo tanto, no tiene un contraparte de alta resolución.

Las rutinas descritas aquí están diseñadas para ayudar al desarrollador de PMDA a construir un arreglo empaquetado de registros de eventos y administrar todas las asignaciones de memoria requeridas para mantener cada instancia de un arreglo de registros de eventos en un búfer contiguo. El uso normal sería como parte del método pmdaFetchCallBack del PMDA.

pmdaEventNewArray se utiliza para crear un nuevo arreglo de eventos. El valor de retorno es un entero pequeño que se utiliza como parámetro idx para las otras rutinas para identificar un arreglo de eventos específico. Si es necesario, un PMDA puede crear y utilizar múltiples arreglos de eventos.

Para iniciar un nuevo ciclo y rellenar un arreglo de eventos desde el principio, llame a pmdaEventResetArray.

Si el PMDA ha terminado con un arreglo de eventos, se puede usar pmdaEventReleaseArray para liberar el almacenamiento subyacente y "cerrar" el arreglo de eventos, de modo que los intentos posteriores de usar idx devuelvan PM_ERR_NOCONTEXT.

Para iniciar un nuevo registro de eventos, use pmdaEventAddRecord. La marca de tiempo del registro de eventos se proporciona a través de tp y el parámetro flags se puede usar para establecer el campo de control que determina el tipo de registro de eventos; flags puede ser el "OR" a nivel de bits de uno o más de los valores PM_EVENT_FLAG_* definidos en <pcp/pmapi.h> (pero tenga en cuenta que PM_EVENT_FLAG_MISSED no debe usarse en este contexto).

Si se han perdido registros de eventos, ya sea porque el PMDA no puede mantenerse al día o porque el cliente PMAPI no puede mantenerse al día, entonces se puede usar pmdaEventAddMissedRecord. idx y tp tienen el mismo significado que para pmdaEventAddRecord y nmissed es el número de registros de eventos que se han perdido en este punto de la serie temporal de registros de eventos. pmdaEventAddMissedRecord puede llamarse varias veces para un solo lote de registros de eventos si hay más de un episodio de "registro de eventos perdido".

Una vez que se ha iniciado un registro de eventos llamando a pmdaEventAddRecord, se pueden agregar uno o más parámetros de evento usando pmdaEventAddParam. Los parámetros pmid y type describen el PMID del parámetro y el tipo de datos (uno de los valores PM_TYPE_* de <pcp/pmapi.h>) del valor que se pasa a través de avp. type debe ser uno en el que el tamaño del valor esté implícito por el type o por la longitud de un valor de cadena (para PM_TYPE_STRING) o codificado dentro de avp->vbp (para PM_TYPE_AGGREGATE).

Una vez construido el arreglo empaquetado, se debe usar pmdaEventGetAddr para inicializar los campos ea_type y ea_len al principio de la estructura pmEventArray y devolver la dirección base del arreglo de eventos que se asigna al campo vp de la estructura pmAtomValue que debe devolver el método pmdaFetchCallBack.

pmdaEventHighResAddParam y pmdaEventHighResGetAddr son nombres anteriores de pmdaEventAddHighResParam y pmdaEventGetHighResAddr (respectivamente) que se han mantenido por compatibilidad.

EJEMPLO

El siguiente código esquelético muestra cómo se podrían usar estas rutinas.

int             sts;
int             myarray;
int             first = 1;
pmEventArray    eap;
if (first) {
   first = 0;
   if ((myarray = pmdaEventNewArray()) < 0) {
      // informar error y fallar
   }
}
pmdaEventResetArray(myarray);
// bucle sobre todos los registros de eventos a exportar
... {
   struct timeval   stamp;
   int              flags;
   // establecer marca de tiempo y establecer flags a 0 o alguna combinación
   // de PM_EVENT_FLAG_POINT, PM_EVENT_FLAG_START, PM_EVENT_FLAG_ID,
   // etc
   if ((sts = pmdaEventAddRecord(myarray, &stamp, flags)) < 0) {
      // informar error y fallar
   }
   // bucle sobre todos los parámetros para este registro de evento
   ... {
      pmID          pmid;
      int           type;
      pmAtomValue   atom;
      // construir pmid, type y atom para el parámetro y
      // su valor
      if ((sts = pmdaEventAddParam(myarray, pmid, type, &atom)) < 0) {
	 // informar error y fallar
      }
   }
   // si se perdieron algunos registros de eventos (podría ser al principio
   // del conjunto exportado, o al final, o en el medio, o
   // una combinación de múltiples episodios de registros perdidos)
   ... {
      int              nmissed;
      struct timeval   stamp;
      if ((sts = pmdaEventAddMissedRecord(myarray, &stamp, nmissed)) < 0) {
	 // informar error y fallar
      }
   }
}
// terminar
eap = pmdaEventGetAddr(myarray);
