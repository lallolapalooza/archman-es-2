PMTIME(3) Manual de funciones de la biblioteca PMTIME(3)

NOMBRE

pmTimeConnect, pmTimeDisconnect, pmTimeRecv, pmTimeSendAck, pmTimeShowDialog - funciones de control de tiempo para sincronizar la posición del archivo y el intervalo de actualización entre una o más aplicaciones

SINOPSIS C

#include <pcp/pmtime.h>

int pmTimeConnect(int port, pmTime *state);
int pmTimeDisconnect(int fd);
int pmTimeSendAck(int fd, struct timeval *fetchTime);
int pmTimeShowDialog(int fd, int show);
int pmTimeRecv(int fd, pmTime *state);

cc ... -lpcp_gui

DESCRIPCIÓN

Estas funciones forman parte de la Interfaz de Programación de Aplicaciones de Métricas de Rendimiento (PMAPI) y están destinadas a proporcionar un mecanismo uniforme para que las aplicaciones reproduzcan datos de archivo y reporten datos en vivo de manera sincronizada en el tiempo.

La estructura pmTime tiene los siguientes campos:

typedef struct {
    unsigned int        magic;
    unsigned int        length;
    pm_tctl_command     command;
    pm_tctl_source      source;
    pm_tctl_state       state;
    pm_tctl_mode        mode;
    struct timeval      delta;
    struct timeval      position;
    struct timeval      start;     /* solo archivo */
    struct timeval      end;       /* solo archivo */
    char                data[0];   /* información de longitud arbitraria (TZ) */
} pmTime;

En el caso más simple, la aplicación debe llamar a pmTimeConnect para conectarse al servidor de control de tiempo, pmtime(1), y luego llamar repetidamente a pmTimeRecv en el bucle principal de la aplicación. En caso de éxito, pmTimeConnect devuelve un descriptor de archivo no negativo. En aplicaciones que tienen múltiples hilos de control, en lugar de bloquearse en pmTimeRecv, el descriptor de archivo puede usarse en llamadas a select(2). En aplicaciones gráficas, el descriptor de archivo puede usarse para interactuar con el bucle de eventos.

El parámetro port de pmTimeConnect es el número de puerto del socket en el que el servidor de control de tiempo está (o estará) escuchando nuevas conexiones.

El parámetro state para pmTimeConnect se utiliza para inicializar un nuevo servidor de control de tiempo o para pasar información adicional a un servidor de control de tiempo existente. Los campos start y finish indican los límites cronológicos de interés para la aplicación. El campo showgui indica si el servidor de control de tiempo debe mostrar u ocultar inicialmente el diálogo. Los campos position, delta y data indican la posición inicial del archivo, el intervalo de actualización, la cadena de zona horaria y la cadena de etiqueta de zona horaria.

pmTimeRecv se bloquea hasta que el servidor de control de tiempo envía un mensaje de comando. Luego, actualiza el parámetro state y devuelve uno de los identificadores de comando PM_TCTL_*.

El comando PM_TCTL_SET indica que la aplicación debe buscar la posición en el archivo (ver pmSetMode(3)) devuelta en el campo position del parámetro state.

El comando PM_TCTL_STEP indica que la aplicación debe realizar una actualización, es decir, avanzar (o retroceder, si delta es negativo) al tiempo indicado por la posición y luego obtener nuevos valores métricos, actualizar la pantalla o lo que sea. Para que varias aplicaciones permanezcan sincronizadas, el servidor de control de tiempo esperará hasta que todas las aplicaciones hayan reconocido que han completado el comando de paso. Las aplicaciones deben llamar a pmTimeSendAck cuando el comando de paso se haya procesado. Tenga en cuenta que PM_TCTL_STEP es el único comando que requiere un acuse de recibo explícito.

El comando PM_TCTL_VCRMODE es utilizado por el servidor de control de tiempo para indicar el modo VCR actual.

El valor se devuelve en el campo mode del parámetro state pasado a pmTimeRecv, y permanece válido hasta que se reciba el siguiente comando PM_TCTL_VCRMODE.

El comando PM_TCTL_TZ indica que la aplicación debe usar una nueva zona horaria, como se indica en el campo newzone del parámetro state.

El comando PM_TCTL_BOUNDS se envía a todas las aplicaciones cuando el servidor de control de tiempo cambia sus límites cronológicos. Esto puede ocurrir cuando una nueva aplicación se conecta al servidor de control de tiempo o el usuario cambia manualmente los límites. La mayoría de las aplicaciones ignorarán este comando.

Los comandos PM_TCTL_GUIHIDE o PM_TCTL_GUISHOW se enviarán a todas las aplicaciones cuando cambie la visibilidad del servidor de control de tiempo. Esto permite a las aplicaciones alterar el texto en menús o botones para reflejar este cambio. Las aplicaciones pueden cambiar la visibilidad del diálogo de control de tiempo utilizando la función pmTimeShowDialog. La visibilidad inicial se determina cuando el diálogo de control de tiempo se crea por primera vez llamando a pmTimeConnect con el campo showgui en el parámetro state establecido en el valor deseado.

La función pmTimeDisconnect puede usarse para cerrar el socket de comandos al servidor de control de tiempo. Esto es útil cuando las aplicaciones necesitan cambiar el modo de conexión, por ejemplo, para divorciarse del servidor de control de tiempo actual y conectarse a uno nuevo.

VER TAMBIÉN

pmtime(1), PMAPI(3) y pmSetMode(3).
