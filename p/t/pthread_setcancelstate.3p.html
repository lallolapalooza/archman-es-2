PTHREAD_SETCANCELSTATE(3P) Manual de Programador POSIX PTHREAD_SETCANCELSTATE(3P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_setcancelstate, pthread_setcanceltype, pthread_testcancel — establecer el estado de cancelabilidad

SINOPSIS

#include <pthread.h>
int pthread_setcancelstate(int state, int *oldstate);
int pthread_setcanceltype(int type, int *oldtype);
void pthread_testcancel(void);

DESCRIPCIÓN

La función pthread_setcancelstate() establecerá de forma atómica tanto el estado de cancelabilidad del hilo que realiza la llamada al state indicado como devolverá el estado de cancelabilidad anterior en la ubicación referenciada por oldstate. Los valores legales para state son PTHREAD_CANCEL_ENABLE y PTHREAD_CANCEL_DISABLE.

La función pthread_setcanceltype() establecerá de forma atómica tanto el tipo de cancelabilidad del hilo que realiza la llamada al type indicado como devolverá el tipo de cancelabilidad anterior en la ubicación referenciada por oldtype. Los valores legales para type son PTHREAD_CANCEL_DEFERRED y PTHREAD_CANCEL_ASYNCHRONOUS.

El estado y el tipo de cancelabilidad de cualquier hilo recién creado, incluyendo el hilo en el que se invocó por primera vez main(), serán respectivamente PTHREAD_CANCEL_ENABLE y PTHREAD_CANCEL_DEFERRED.

La función pthread_testcancel() creará un punto de cancelación en el hilo que realiza la llamada. La función pthread_testcancel() no tendrá ningún efecto si la cancelabilidad está deshabilitada.

VALOR DE RETORNO

Si tiene éxito, las funciones pthread_setcancelstate() y pthread_setcanceltype() devolverán cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_setcancelstate() puede fallar si:

EINVAL
El estado especificado no es PTHREAD_CANCEL_ENABLE o PTHREAD_CANCEL_DISABLE.

La función pthread_setcanceltype() puede fallar si:

EINVAL
El tipo especificado no es PTHREAD_CANCEL_DEFERRED o PTHREAD_CANCEL_ASYNCHRONOUS.

Estas funciones no devolverán un código de error de [EINTR].

Las siguientes secciones son informativas.

EJEMPLOS

Ninguno.

USO DE APLICACIÓN

Para escribir un manejador de señales para una señal asíncrona que pueda ejecutarse de forma segura en un hilo cancelable, se debe usar pthread_setcancelstate() para deshabilitar la cancelación durante la duración de cualquier llamada que realice el manejador de señales y que sea un punto de cancelación. Sin embargo, el estándar no permite que las aplicaciones estrictamente conformes llamen a pthread_setcancelstate() desde un manejador de señales, ya que actualmente no se requiere que sea seguro para señales asíncronas. En implementaciones donde pthread_setcancelstate() no es seguro para señales asíncronas, las alternativas son asegurar que las señales correspondientes se bloqueen durante la ejecución de funciones que no son seguras para cancelación asíncrona o que la cancelación se deshabilite durante los momentos en que esas señales puedan ser entregadas. Se alienta encarecidamente a las implementaciones a que hagan que pthread_setcancelstate() sea seguro para señales asíncronas.

RACIÓNALE

Las funciones pthread_setcancelstate() y pthread_setcanceltype() controlan los puntos en los que un hilo puede ser cancelado de forma asíncrona. Para que el control de cancelación sea utilizable de forma modular, se deben seguir algunas reglas.

Un objeto puede considerarse una generalización de un procedimiento. Es un conjunto de procedimientos y variables globales escritos como una unidad y llamados por clientes que el objeto no conoce. Los objetos pueden depender de otros objetos.

Primero, la cancelabilidad solo debe deshabilitarse a la entrada de un objeto, nunca habilitarse explícitamente. Al salir de un objeto, el estado de cancelabilidad siempre debe restaurarse a su valor de entrada al objeto.

Esto se debe a un argumento de modularidad: si el cliente de un objeto (o el cliente de un objeto que usa ese objeto) ha deshabilitado la cancelabilidad, es porque el cliente no quiere preocuparse por la limpieza si el hilo se cancela mientras ejecuta alguna secuencia de acciones. Si se llama a un objeto en dicho estado y habilita la cancelabilidad y hay una solicitud de cancelación pendiente para ese hilo, entonces el hilo se cancela, en contra del deseo del cliente que lo deshabilitó.

Segundo, el tipo de cancelabilidad puede establecerse explícitamente en *deferred* o *asynchronous* a la entrada de un objeto. Pero al igual que con el estado de cancelabilidad, al salir de un objeto, el tipo de cancelabilidad siempre debe restaurarse a su valor de entrada al objeto.

Finalmente, solo las funciones que sean seguras para la cancelación pueden ser llamadas desde un hilo que sea cancelable de forma asíncrona.

DIRECCIONES FUTURAS

La función pthread_setcancelstate() puede añadirse a la tabla de funciones seguras para señales asíncronas en la Sección 2.4.3, Acciones de Señales.

pthread_setcancelstate(3) - Páginas del manual de Arch Linux

SINÓPSIS

#include <pthread.h>

int pthread_setcancelstate(int state, int *oldstate);

DESCRIPCIÓN

La función pthread_setcancelstate establece el estado de cancelación del hilo llamante.

El parámetro state puede ser:

PTHREAD_CANCEL_ENABLE
Habilita la cancelación asíncrona para el hilo llamante.
PTHREAD_CANCEL_DISABLE
Deshabilita la cancelación asíncrona para el hilo llamante.

Si oldstate no es NULL, apunta a una ubicación de memoria donde se almacenará el estado de cancelación anterior.

La cancelación de un hilo se puede habilitar o deshabilitar. Cuando la cancelación está deshabilitada, las solicitudes de cancelación se posponen hasta que la cancelación se habilita nuevamente.

Cuando la cancelación está habilitada, el hilo puede ser cancelado en puntos de cancelación (consultar pthread_testcancel(3)).

VALOR DE RETORNO

En caso de éxito, pthread_setcancelstate devuelve 0.

En caso de error, devuelve un número de error distinto de cero.

ERRORES

EINVAL
El valor especificado para state no es válido.

EJEMPLOS

// Deshabilitar la cancelación temporalmente
int old_state;
pthread_setcancelstate(PTHREAD_CANCEL_DISABLE, &old_state);

// ... código que no debe ser interrumpido ...

// Restaurar el estado de cancelación anterior
pthread_setcancelstate(old_state, NULL);

USO EN APLICACIONES

Esta función se utiliza para controlar cuándo un hilo puede ser cancelado. Es común deshabilitar la cancelación antes de ejecutar secciones críticas de código que no deben ser interrumpidas, y luego restaurar el estado anterior.

FUNDAMENTO

La capacidad de deshabilitar temporalmente la cancelación es crucial para garantizar la integridad de los datos y evitar condiciones de carrera en código sensible. Permite a los desarrolladores proteger secciones de código de interrupciones inesperadas.
