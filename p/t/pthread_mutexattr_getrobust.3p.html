PTHREAD_MUTEXATTR_GETROBUST(3P) Manual de Programador de POSIX PTHREAD_MUTEXATTR_GETROBUST(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_mutexattr_getrobust, pthread_mutexattr_setrobust — obtener y establecer el atributo robusto del mutex

SINOPSIS

#include <pthread.h>
int pthread_mutexattr_getrobust(const pthread_mutexattr_t *restrict
    attr, int *restrict robust);
int pthread_mutexattr_setrobust(pthread_mutexattr_t *attr,
    int robust);

DESCRIPCIÓN

Las funciones pthread_mutexattr_getrobust() y pthread_mutexattr_setrobust(), respectivamente, obtienen y establecen el atributo robusto del mutex. Este atributo se establece en el parámetro robusto. Los valores válidos para robusto incluyen:

PTHREAD_MUTEX_STALLED

No se toman acciones especiales si el propietario del mutex termina mientras mantiene el bloqueo del mutex. Esto puede provocar interbloqueos si ningún otro hilo puede desbloquear el mutex.
Este es el valor por defecto.
PTHREAD_MUTEX_ROBUST

Si el proceso que contiene el hilo propietario de un mutex robusto termina mientras mantiene el bloqueo del mutex, el siguiente hilo que adquiera el mutex será notificado de la terminación mediante el valor de retorno [EOWNERDEAD] de la función de bloqueo. Si el hilo propietario de un mutex robusto termina mientras mantiene el bloqueo del mutex, el siguiente hilo que intente adquirir el mutex puede ser notificado de la terminación mediante el valor de retorno [EOWNERDEAD]. El hilo notificado puede entonces intentar hacer que el estado protegido por el mutex vuelva a ser consistente y, si tiene éxito, puede marcar el estado del mutex como consistente llamando a pthread_mutex_consistent(). Después de una llamada posterior exitosa a pthread_mutex_unlock(), el bloqueo del mutex se liberará y podrá ser utilizado normalmente por otros hilos. Si el mutex se desbloquea sin una llamada a pthread_mutex_consistent(), estará en un estado permanentemente inutilizable y todos los intentos de bloquear el mutex fallarán con el error [ENOTRECOVERABLE]. La única operación permitida en dicho mutex es pthread_mutex_destroy().

El comportamiento no está definido si el valor especificado por el argumento attr de pthread_mutexattr_getrobust() o pthread_mutexattr_setrobust() no se refiere a un objeto de atributos de mutex inicializado.

VALOR DE RETORNO

Al completarse con éxito, la función pthread_mutexattr_getrobust() devolverá cero y almacenará el valor del atributo robusto de attr en el objeto al que se refiere el parámetro robust. De lo contrario, se devolverá un valor de error para indicar el error. Si se completa con éxito, la función pthread_mutexattr_setrobust() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_mutexattr_setrobust() fallará si:

EINVAL
El valor de robusto no es válido.

Estas funciones no devolverán un código de error de [EINTR].

Ninguno.

USO DE APLICACIONES

Las acciones necesarias para que el estado protegido por el mutex vuelva a ser consistente dependen exclusivamente de la aplicación. Si no es posible hacer que el estado de un mutex sea consistente, se pueden utilizar mutexes robustas para notificar esta situación llamando a pthread_mutex_unlock() sin una llamada previa a pthread_mutex_consistent().

Si el estado se declara inconsistente llamando a pthread_mutex_unlock() sin una llamada previa a pthread_mutex_consistent(), un enfoque posible podría ser destruir el mutex y luego volver a inicializarlo. Sin embargo, debe tenerse en cuenta que esto solo es posible en ciertas situaciones en las que el estado protegido por el mutex debe reinicializarse y lograrse la coordinación con otros hilos bloqueados en el mutex, ya que de lo contrario, una llamada a una función de bloqueo con una referencia a un objeto mutex invalidado por una llamada a pthread_mutex_destroy() resulta en un comportamiento indefinido.

FUNDAMENTO

Si una implementación detecta que el valor especificado por el argumento attr de pthread_mutexattr_getrobust() o pthread_mutexattr_setrobust() no se refiere a un objeto de atributos de mutex inicializado, se recomienda que la función falle e informe de un error [EINVAL].
