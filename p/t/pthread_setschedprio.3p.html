PTHREAD_SETSCHEDPRIO(3P) Manual del programador POSIX PTHREAD_SETSCHEDPRIO(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_setschedprio — acceso dinámico a los parámetros de planificación de hilos (HILOS EN TIEMPO REAL)

SINOPSIS

#include <pthread.h>
int pthread_setschedprio(pthread_t thread, int prio);

DESCRIPCIÓN

La función pthread_setschedprio() establecerá la prioridad de planificación del hilo cuyo ID de hilo se proporciona en thread al valor dado por prio. Consulte Políticas de Planificación para obtener una descripción de cómo esta llamada a función afecta el orden del hilo en la lista de hilos para su nueva prioridad.

Si la función pthread_setschedprio() falla, la prioridad de planificación del hilo de destino no se modificará.

VALOR DE RETORNO

Si tiene éxito, la función pthread_setschedprio() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_setschedprio() puede fallar si:

EINVAL
El valor de prio no es válido para la política de planificación del hilo especificado.
EPERM
El llamante no tiene los privilegios adecuados para establecer la prioridad de planificación del hilo especificado.

La función pthread_setschedprio() no devolverá un código de error de [EINTR].

USO DE LA APLICACIÓN

Ninguno.

JUSTIFICACIÓN

La función pthread_setschedprio() proporciona una forma para que una aplicación aumente temporalmente su prioridad y luego la reduzca nuevamente, sin el efecto secundario no deseado de ceder a otros hilos de la misma prioridad. Esto es necesario si la aplicación va a implementar sus propias estrategias para limitar la inversión de prioridad, como la herencia de prioridad o los techos de prioridad. Esta capacidad es especialmente importante si la implementación no admite las opciones de Protección de Prioridad de Hilo o Herencia de Prioridad de Hilo, pero incluso si esas opciones son compatibles, es necesaria si la aplicación va a limitar la herencia de prioridad para otros recursos, como semáforos.

Los desarrolladores estándar consideraron que, si bien podría ser conceptualmente preferible resolver este problema modificando la especificación de pthread_setschedparam(), era demasiado tarde para hacer tal cambio, ya que puede haber implementaciones que necesitarían ser modificadas. Por lo tanto, se introdujo esta nueva función.

Si una implementación detecta el uso de un ID de hilo después del final de su vida útil, se recomienda que la función falle e informe un error [ESRCH].
