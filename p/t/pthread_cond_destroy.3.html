pthread_cond_init(3) Manual de funciones de biblioteca pthread_cond_init(3)

NOMBRE

pthread_cond_init, pthread_cond_signal, pthread_cond_broadcast, pthread_cond_wait, pthread_cond_timedwait, pthread_cond_destroy - operaciones sobre condiciones

SINOPSIS

#include <pthread.h>
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
int pthread_cond_init(pthread_cond_t *cond,
                      pthread_condattr_t *cond_attr);
int pthread_cond_signal(pthread_cond_t *cond);
int pthread_cond_broadcast(pthread_cond_t *cond);
int pthread_cond_wait(pthread_cond_t *cond, pthread_mutex_t *mutex);
int pthread_cond_timedwait(pthread_cond_t *cond, pthread_mutex_t *mutex,
                      const struct timespec *abstime);
int pthread_cond_destroy(pthread_cond_t *cond);

DESCRIPCIÓN

Una condición (abreviatura de "variable de condición") es un dispositivo de sincronización que permite a los hilos suspender su ejecución y ceder el procesador hasta que algún predicado sobre datos compartidos se cumpla. Las operaciones básicas sobre condiciones son: señalar la condición (cuando el predicado se vuelve verdadero), y esperar la condición, suspendiendo la ejecución del hilo hasta que otro hilo señale la condición.

Una variable de condición siempre debe estar asociada a un mutex, para evitar la condición de carrera donde un hilo se prepara para esperar en una variable de condición y otro hilo señala la condición justo antes de que el primer hilo espere realmente en ella.

pthread_cond_init() inicializa la variable de condición cond, usando los atributos de condición especificados en cond_attr, o atributos por defecto si cond_attr es NULL. La implementación de LinuxThreads no soporta atributos para condiciones, por lo tanto el parámetro cond_attr es en realidad ignorado.

Las variables de tipo pthread_cond_t también pueden ser inicializadas estáticamente, usando la constante PTHREAD_COND_INITIALIZER.

pthread_cond_signal() reinicia uno de los hilos que están esperando en la variable de condición cond. Si ningún hilo está esperando en cond, no ocurre nada. Si varios hilos están esperando en cond, exactamente uno es reiniciado, pero no se especifica cuál.

pthread_cond_broadcast() reinicia todos los hilos que están esperando en la variable de condición cond. No ocurre nada si ningún hilo está esperando en cond.

pthread_cond_wait() desbloquea atómicamente el mutex (según pthread_unlock_mutex()) y espera a que la variable de condición cond sea señalada. La ejecución del hilo se suspende y no consume tiempo de CPU hasta que la variable de condición sea señalada. El mutex debe estar bloqueado por el hilo que llama al entrar en pthread_cond_wait(). Antes de devolver el control al hilo que llama, pthread_cond_wait() vuelve a adquirir el mutex (según pthread_mutex_lock()).

Desbloquear el mutex y suspender en la variable de condición se hace atómicamente. Por lo tanto, si todos los hilos adquieren siempre el mutex antes de señalar la condición, esto garantiza que la condición no puede ser señalada (y por lo tanto ignorada) entre el momento en que un hilo bloquea el mutex y el momento en que espera en la variable de condición. Ver ADVERTENCIAS más abajo.

pthread_cond_timedwait() desbloquea atómicamente mutex y espera en cond, como lo hace pthread_cond_wait(), pero también limita la duración de la espera. Si cond no ha sido señalada dentro del tiempo especificado por abstime, el mutex mutex se vuelve a adquirir y pthread_cond_timedwait() devuelve el error ETIMEDOUT. El parámetro abstime especifica una hora absoluta, con el mismo origen que time(2) y gettimeofday(2): un abstime de 0 corresponde a las 00:00:00 GMT, 1 de enero de 1970.

pthread_cond_destroy() destruye una variable de condición, liberando los recursos que pueda contener. Ningún hilo debe estar esperando en la variable de condición al entrar en pthread_cond_destroy(). En la implementación de LinuxThreads, no se asocian recursos a las variables de condición, por lo tanto pthread_cond_destroy() en realidad no hace nada excepto verificar que la condición no tiene hilos esperando.

CANCELACIÓN

pthread_cond_wait() y pthread_cond_timedwait() son puntos de cancelación. Si un hilo es cancelado mientras está suspendido en una de estas funciones, el hilo reanuda la ejecución inmediatamente, luego bloquea de nuevo el mutex argumento de pthread_cond_wait() y pthread_cond_timedwait(), y finalmente ejecuta la cancelación. En consecuencia, los manejadores de limpieza tienen la garantía de que mutex está bloqueado cuando se les llama.

SEGURIDAD DE SEÑALES ASINCRÓNICAS

Las funciones de condición no son seguras para señales asíncronas, y no deben ser llamadas desde un manejador de señales. En particular, llamar a pthread_cond_signal() o pthread_cond_broadcast() desde un manejador de señales puede causar un bloqueo del hilo que llama.

VALOR DE RETORNO

Todas las funciones de variables de condición devuelven 0 en caso de éxito y un código de error distinto de cero en caso de error.

ERRORES

pthread_cond_init(), pthread_cond_signal(), pthread_cond_broadcast(), y pthread_cond_wait() nunca devuelven un código de error.

La función pthread_cond_timedwait() devuelve los siguientes códigos de error en caso de error:

ETIMEDOUT
La variable de condición no fue señalada hasta el tiempo de espera especificado por abstime .

La función pthread_cond_destroy() devuelve el siguiente código de error en caso de error:

EBUSY
Algunos hilos están actualmente esperando en cond .

VER TAMBIÉN

pthread_condattr_init(3), pthread_mutex_lock(3), pthread_mutex_unlock(3), gettimeofday(2), nanosleep(2).

ADVERTENCIAS

La implementación de las funciones proporcionadas hasta glibc 2.25 utilizaba un bloqueo de datos interno. Este bloqueo no soportaba la herencia de prioridad y estaba sujeto a inversión de prioridad ilimitada, visible en un sistema de tiempo real.

Después de la reescritura de la implementación en glibc 2.25, el uso del bloqueo interno cambió. El bloqueo interno siempre es adquirido por las funciones de señalización pthread_cond_signal() y pthread_cond_broadcast(). La función de espera adquiere el bloqueo si el proceso de espera fue interrumpido. La interrupción puede ser causada, por ejemplo, por un tiempo de espera especificado, y denotada por el valor de error ETIMEDOUTA, o por una señal recibida, que se denota por el valor de error EINTR.

EJEMPLO

Considere dos variables compartidas x e y, protegidas por el mutex mut, y una variable de condición cond que debe ser señalada cada vez que x sea mayor que y.

int x,y;
pthread_mutex_t mut = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

Esperar hasta que x sea mayor que y se realiza de la siguiente manera:

pthread_mutex_lock(&mut);
while (x <= y) {
        pthread_cond_wait(&cond, &mut);
}
/* operar sobre x e y */
pthread_mutex_unlock(&mut);

Las modificaciones en x e y que puedan hacer que x sea mayor que y deben señalar la condición si es necesario:

pthread_mutex_lock(&mut);
/* modificar x e y */
if (x > y) pthread_cond_broadcast(&cond);
pthread_mutex_unlock(&mut);

CAVEATS

Si el tiempo de espera se establece en un valor absoluto, el usuario debe encargarse de obtener el tiempo actual y sumar los segundos y nanosegundos deseados. La llamada a la biblioteca estándar C gettimeofday(3) se puede utilizar para obtener el tiempo actual.

Al llamar a pthread_cond_timedwait(3) y pthread_cond_wait(3), el bloqueo del mutex se puede desbloquear para los demás hilos. Si varios hilos están esperando la misma condición, es posible que solo un hilo se despierte cuando se llame a pthread_cond_signal(). Esto puede ocurrir porque el hilo que llama se detiene inmediatamente después de que se despierta, pero antes de que se libere el mutex. Si varios hilos esperan, en general es mejor usar pthread_cond_broadcast() para asegurarse de que todos los hilos que esperan se despierten.

Si el programador está seguro de que solo un hilo puede estar esperando en la condición (por ejemplo, el único hilo que puede estar interesado en los cambios a x y y), pthread_cond_signal() puede usarse como una alternativa ligeramente más eficiente a pthread_cond_broadcast(). En caso de duda, use pthread_cond_broadcast().

EXAMPLE

Para esperar a que x sea mayor que y con un tiempo de espera de 5 segundos, haga lo siguiente: 

struct timeval now;
struct timespec timeout;
int retcode;
pthread_mutex_lock(&mut);
gettimeofday(&now);
timeout.tv_sec = now.tv_sec + 5;
timeout.tv_nsec = now.tv_usec * 1000;
retcode = 0;
while (x <= y && retcode != ETIMEDOUT) {
        retcode = pthread_cond_timedwait(&cond, &mut, &timeout);
}
if (retcode == ETIMEDOUT) {
        /* ocurrió el tiempo de espera */
} else {
        /* opera en x e y */
}
pthread_mutex_unlock(&mut);
