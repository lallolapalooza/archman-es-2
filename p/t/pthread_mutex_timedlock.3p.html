NOMBRE

pthread_mutex_timedlock — bloquear un mutex

SINOPSIS

#include <pthread.h>
#include <time.h>
int pthread_mutex_timedlock(pthread_mutex_t *restrict mutex,
    const struct timespec *restrict abstime);

DESCRIPCIÓN

La función pthread_mutex_timedlock() bloqueará el objeto mutex referenciado por mutex. Si el mutex ya está bloqueado, el hilo llamante se bloqueará hasta que el mutex esté disponible, como en la función pthread_mutex_lock(). Si el mutex no se puede bloquear sin esperar a que otro hilo desbloquee el mutex, esta espera se terminará cuando expire el tiempo de espera especificado.

El tiempo de espera expirará cuando el tiempo absoluto especificado por abstime pase, medido por el reloj en el que se basan los tiempos de espera (es decir, cuando el valor de ese reloj sea igual o superior a abstime), o si el tiempo absoluto especificado por abstime ya ha pasado en el momento de la llamada.

El tiempo de espera se basará en el reloj CLOCK_REALTIME. La resolución del tiempo de espera será la resolución del reloj en el que se basa. El tipo de datos timespec se define en la cabecera <time.h>.

Bajo ninguna circunstancia fallará la función con un tiempo de espera si el mutex se puede bloquear inmediatamente. La validez del parámetro abstime no necesita ser verificada si el mutex se puede bloquear inmediatamente.

Como consecuencia de las reglas de herencia de prioridad (para mutexes inicializados con el protocolo PRIO_INHERIT), si una espera de mutex temporizada termina porque su tiempo de espera expira, la prioridad del propietario del mutex se ajustará según sea necesario para reflejar el hecho de que este hilo ya no está entre los hilos que esperan el mutex.

Si mutex es un mutex robusto y el proceso que contiene el hilo propietario terminó mientras mantenía el bloqueo del mutex, una llamada a pthread_mutex_timedlock() devolverá el valor de error [EOWNERDEAD]. Si mutex es un mutex robusto y el hilo propietario terminó mientras mantenía el bloqueo del mutex, una llamada a pthread_mutex_timedlock() puede devolver el valor de error [EOWNERDEAD] incluso si el proceso en el que reside el hilo propietario no ha terminado. En estos casos, el mutex está bloqueado por el hilo pero el estado que protege se marca como inconsistente. La aplicación debe asegurarse de que el estado se haga consistente para su reutilización y, cuando eso se complete, llamar a pthread_mutex_consistent(). Si la aplicación no puede recuperar el estado, debe desbloquear el mutex sin una llamada previa a pthread_mutex_consistent(), después de lo cual el mutex se marca como permanentemente inutilizable.

Si mutex no hace referencia a un objeto mutex inicializado, el comportamiento es indefinido.

VALOR DE RETORNO

Si tiene éxito, la función pthread_mutex_timedlock() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_mutex_timedlock() fallará si:

EAGAIN
No se pudo adquirir el mutex porque se ha superado el número máximo de bloqueos recursivos para mutex.
EDEADLK
El tipo de mutex es PTHREAD_MUTEX_ERRORCHECK y el hilo actual ya posee el mutex.
EINVAL
El mutex se creó con el atributo de protocolo que tiene el valor PTHREAD_PRIO_PROTECT y la prioridad del hilo llamante es superior al techo de prioridad actual del mutex.
EINVAL
El proceso o hilo se habría bloqueado y el parámetro abstime especificó un valor de campo de nanosegundos menor que cero o mayor o igual a 1000 millones.
ENOTRECOVERABLE

El estado protegido por el mutex no es recuperable.
EOWNERDEAD

El mutex es un mutex robusto y el proceso que contiene el hilo propietario anterior terminó mientras mantenía el bloqueo del mutex. El bloqueo del mutex será adquirido por el hilo llamante y depende del nuevo propietario hacer que el estado sea consistente.
ETIMEDOUT
No se pudo bloquear el mutex antes de que expirara el tiempo de espera especificado.

La función pthread_mutex_timedlock() puede fallar si:

EDEADLK
Se detectó una condición de interbloqueo.
EOWNERDEAD

El mutex es un mutex robusto y el hilo propietario anterior terminó mientras mantenía el bloqueo del mutex. El bloqueo del mutex será adquirido por el hilo llamante y depende del nuevo propietario hacer que el estado sea consistente.

Esta función no devolverá un código de error de [EINTR].

USO DE APLICACIÓN

Las aplicaciones que han supuesto que los valores de retorno distintos de cero son errores deberán actualizarse para su uso con mutexes robustos, ya que un retorno válido para un hilo que adquiere un mutex que protege un estado actualmente inconsistente es [EOWNERDEAD]. Las aplicaciones que no verifican los valores de retorno de error, debido a que descartan la posibilidad de que tales errores surjan, no deben usar mutexes robustos. Si una aplicación debe funcionar con mutexes normales y robustos, debe verificar todos los valores de retorno de condiciones de error y, si es necesario, tomar las medidas apropiadas.

PROLOG

Este documento proporciona información sobre el comando pthread_mutex_timedlock según lo que se encuentra en el sistema operativo Arch Linux.

NOMBRE

pthread_mutex_timedlock - bloqueo de un mutex con tiempo de espera

SINOPSIS

```c #include <pthread.h> int pthread_mutex_timedlock(pthread_mutex_t *mutex, const struct timespec *abs_timeout); ```

DESCRIPCIÓN

La función pthread_mutex_timedlock bloquea el objeto mutex especificado por mutex. Si el mutex ya está bloqueado por otro hilo, el hilo que realiza la llamada se bloqueará hasta que adquiera el bloqueo del mutex o hasta que el tiempo especificado por abs_timeout expire.

El argumento abs_timeout apunta a una estructura timespec que especifica el tiempo absoluto hasta el cual se intentará adquirir el bloqueo. La hora se mide en segundos y nanosegundos desde la época.

Si el tiempo especificado por abs_timeout ha pasado ya en el momento de la llamada, la función devolverá inmediatamente sin bloquear.

Si la llamada tiene éxito, el hilo que realiza la llamada poseerá el bloqueo del mutex.

VALOR DE RETORNO

En caso de éxito, pthread_mutex_timedlock devuelve 0.

En caso de error, devuelve un número de número de error distinto de cero para indicar el motivo del fallo. Si el tiempo de espera expira antes de que se pueda adquirir el bloqueo, devuelve ETIMEDOUT.

ERRORES

EBUSY
El mutex ya está bloqueado por el hilo que realiza la llamada.
EINVAL
El valor especificado por mutex no es un objeto mutex válido, o abs_timeout no apunta a una estructura timespec válida.
ETIMEDOUT
El tiempo de espera expiró antes de que se pudiera adquirir el bloqueo.
EAGAIN
El mutex no se pudo adquirir porque se alcanzó el número máximo de bloqueos recursivos (solo para mutexes recursivos).
EDEADLK
Se detectó un bloqueo mortal.

EJEMPLOS

```c #include <pthread.h> #include <stdio.h> #include <time.h> pthread_mutex_t my_mutex = PTHREAD_MUTEX_INITIALIZER; void *thread_func(void *arg) { struct timespec ts; clock_gettime(CLOCK_REALTIME, &ts); ts.tv_sec += 2; // Esperar 2 segundos int ret = pthread_mutex_timedlock(&my_mutex, &ts); if (ret == 0) { printf("Mutex adquirido con éxito.\n"); // Hacer algo con el recurso protegido por el mutex pthread_mutex_unlock(&my_mutex); printf("Mutex liberado.\n"); } else if (ret == ETIMEDOUT) { printf("El tiempo de espera para adquirir el mutex expiró.\n"); } else { perror("pthread_mutex_timedlock"); } return NULL; } int main() { pthread_t tid; pthread_mutex_lock(&my_mutex); // Bloquear el mutex inicialmente pthread_create(&tid, NULL, thread_func, NULL); pthread_join(tid, NULL); pthread_mutex_destroy(&my_mutex); return 0; } ```

USO DE LA APLICACIÓN

Esta función se utiliza en programación concurrente para adquirir bloqueos de mutex con un límite de tiempo, lo que permite a los hilos evitar el bloqueo indefinido y manejar situaciones de tiempo de espera.

JUSTIFICACIÓN

La necesidad de un bloqueo de mutex con tiempo de espera surge en escenarios donde la adquisición de un bloqueo podría bloquear indefinidamente un hilo si otro hilo que posee el bloqueo falla o se bloquea de forma permanente. pthread_mutex_timedlock proporciona un mecanismo para evitar tales situaciones, permitiendo a los programas responder a bloqueos fallidos o reintentar la operación después de un período determinado.

DIRECCIONES FUTURAS

Las futuras iteraciones de las páginas de manual podrían incluir ejemplos más complejos que demuestren el manejo de errores y estrategias de reintento avanzadas. También podría haber una mayor discusión sobre el impacto del rendimiento de pthread_mutex_timedlock en comparación con los bloqueos de mutex estándar.
