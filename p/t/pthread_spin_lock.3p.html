PTHREAD_SPIN_LOCK(3P) Manual del programador POSIX PTHREAD_SPIN_LOCK(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_spin_lock, pthread_spin_trylock — bloquear un objeto de bloqueo giratorio (spin lock)

SINOPSIS

#include <pthread.h>
int pthread_spin_lock(pthread_spinlock_t *lock);
int pthread_spin_trylock(pthread_spinlock_t *lock);

DESCRIPCIÓN

La función pthread_spin_lock() bloquea el bloqueo giratorio referenciado por lock. El hilo que llama adquirirá el bloqueo si no está siendo utilizado por otro hilo. De lo contrario, el hilo girará (es decir, no regresará de la llamada pthread_spin_lock()) hasta que el bloqueo esté disponible. Los resultados no están definidos si el hilo que llama tiene el bloqueo en el momento en que se realiza la llamada. La función pthread_spin_trylock() bloqueará el bloqueo giratorio referenciado por lock si no está siendo utilizado por ningún hilo. De lo contrario, la función fallará.

Los resultados no están definidos si se llama a alguna de estas funciones con un bloqueo giratorio no inicializado.

VALOR DEVUELTO

Al completarse con éxito, estas funciones devolverán cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_spin_lock() puede fallar si:

EDEADLK
Se detectó una condición de interbloqueo (deadlock).

La función pthread_spin_trylock() fallará si:

EBUSY
Un hilo tiene actualmente el bloqueo.

Estas funciones no devolverán un código de error de [EINTR].

USO DE LA APLICACIÓN

Las aplicaciones que utilizan esta función pueden estar sujetas a inversión de prioridad, como se discute en el volumen de Definiciones Base de POSIX.1‐2017, Sección 3.291, Inversión de Prioridad.

FUNDAMENTOS RACIONALES

Si una implementación detecta que el valor especificado por el argumento lock a pthread_spin_lock() o pthread_spin_trylock() no se refiere a un objeto de bloqueo giratorio inicializado, se recomienda que la función falle y reporte un error [EINVAL].

Si una implementación detecta que el valor especificado por el argumento lock a pthread_spin_lock() se refiere a un objeto de bloqueo giratorio que el hilo que llama ya posee, se recomienda que la función falle y reporte un error [EDEADLK].
