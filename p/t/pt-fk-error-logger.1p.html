NOMBRE

pt-fk-error-logger - Registra errores de claves foráneas de MySQL.

SINOPSIS

Uso: pt-fk-error-logger [OPCIONES] [DSN]

pt-fk-error-logger registra información sobre errores de claves foráneas en el DSN dado. La información se imprime en "STDOUT", y también se puede guardar en una tabla especificando "--dest". La herramienta se ejecuta para siempre a menos que se especifique "--run-time" o "--iterations".

Imprimir errores de claves foráneas en host1:

pt-fk-error-logger h=host1

Imprimir errores de claves foráneas en host1 una vez y salir:

pt-fk-error-logger h=host1 --iterations 1

Guardar errores de claves foráneas en host1 en percona_schema.fke en host2:

pt-fk-error-logger h=host1 --dest h=host2,D=percona_schema,t=fke

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien probado, pero todas las herramientas de base de datos pueden suponer un riesgo para el sistema y el servidor de base de datos. Antes de usar esta herramienta, por favor:

  • Lea la documentación de la herramienta
  • Revise los "BUGS" conocidos de la herramienta
  • Pruebe la herramienta en un servidor no productivo
  • Haga una copia de seguridad de su servidor de producción y verifique las copias de seguridad

DESCRIPCION

pt-fk-error-logger imprime o guarda el texto de los errores de claves foráneas de "SHOW INNODB STATUS". Los errores no se analizan ni se interpretan de ninguna manera. Los errores de claves foráneas se identifican de forma única por su marca de tiempo. Solo se imprimen o guardan los errores nuevos (más recientes).

Por defecto, la herramienta se ejecuta para siempre, comprobando cada "--interval" segundos si hay nuevos errores de claves foráneas. Especifique "--run-time" y/o "--iterations" para limitar cuánto tiempo se ejecuta la herramienta.

SALIDA

El texto de los errores de claves foráneas de "SHOW ENGINE INNODB STATUS" se imprime en "STDOUT", a menos que se especifique "--quiet". Los errores y advertencias se imprimen en "STDERR".

OPCIONES

Esta herramienta acepta argumentos de línea de comandos adicionales. Consulte la "SINOPSIS" y la información de uso para obtener detalles.

--ask-pass
Solicitar una contraseña al conectar a MySQL.
--charset
forma corta: -A; tipo: string

Codificación de caracteres por defecto. Si el valor es utf8, establece el modo binario de Perl en STDOUT a utf8, pasa la opción mysql_enable_utf8 a DBD::mysql y ejecuta SET NAMES UTF8 después de conectarse a MySQL. Cualquier otro valor establece el modo binario en STDOUT sin la capa utf8 y ejecuta SET NAMES después de conectarse a MySQL.

--config
tipo: Array

Leer esta lista de archivos de configuración separados por comas; si se especifica, esta debe ser la primera opción en la línea de comandos.

--daemonize
Crear un proceso hijo y separarlo del shell. Solo para sistemas operativos POSIX.
--database
forma corta: -D; tipo: string

Conectar a esta base de datos.

--defaults-file
forma corta: -F; tipo: string

Leer solo las opciones de mysql del archivo dado. Debes proporcionar una ruta de archivo absoluta.

--dest
tipo: DSN

Guardar los errores de claves foráneas en esta tabla. El DSN debe especificar una base de datos (D) y una tabla (t).

Los valores del DSN que faltan se heredan del DSN que se está monitoreando, por lo que puedes omitir la mayoría de los valores si estás guardando errores de claves foráneas en el mismo host.

Se sugiere la siguiente tabla:

CREATE TABLE foreign_key_errors (
  ts datetime NOT NULL,
  error text NOT NULL,
  PRIMARY KEY (ts)
)

La única información que se guarda es la marca de tiempo y el texto del error de clave foránea.

--help
Mostrar ayuda y salir.
--host
forma corta: -h; tipo: string

Conectar al host.

--interval
tipo: time; defecto: 30

Con qué frecuencia comprobar si hay errores de claves foráneas.

--iterations
tipo: int

Cuántas veces comprobar si hay errores de claves foráneas. Por defecto, esta opción no está definida, lo que significa un número infinito de iteraciones. La herramienta siempre sale con "--run-time", independientemente del valor especificado para esta opción. Por ejemplo, la herramienta saldrá después de 1 minuto con "--run-time 1m --iterations 4 --interval 30" porque 4 iteraciones a intervalos de 30 segundos tardarían 2 minutos, más que el tiempo de ejecución de 1 minuto.

--log
tipo: string

Imprimir toda la salida en este archivo cuando esté en modo demonio.

--password
forma corta: -p; tipo: string

Contraseña a usar al conectar. Si la contraseña contiene comas, deben escaparse con una barra invertida: "ejemplo\,"

--pid
tipo: string

Crear el archivo PID dado. La herramienta no se iniciará si el archivo PID ya existe y el PID que contiene es diferente del PID actual. Sin embargo, si el archivo PID existe y el PID que contiene ya no se está ejecutando, la herramienta sobrescribirá el archivo PID con el PID actual. El archivo PID se elimina automáticamente cuando la herramienta se cierra.

--port
forma corta: -P; tipo: int

Número de puerto a usar para la conexión.

--quiet
No imprimir errores de claves foráneas; solo imprimir errores y advertencias en "STDERR".
--run-time
tipo: time

Cuánto tiempo ejecutar antes de salir. Por defecto, la herramienta se ejecuta para siempre.

--set-vars
tipo: Array

Establecer las variables de MySQL en esta lista separada por comas de pares "variable=valor".

Por defecto, la herramienta establece:

wait_timeout=10000

Las variables especificadas en la línea de comandos anulan estos valores por defecto. Por ejemplo, especificar "--set-vars wait_timeout=500" anula el valor por defecto de 10000.

La herramienta imprime una advertencia y continúa si una variable no se puede establecer.

--socket
forma corta: -S; tipo: string

Archivo de socket a usar para la conexión.

--user
forma corta: -u; tipo: string

Usuario para iniciar sesión si no es el usuario actual.

--version
Mostrar versión y salir.
--[no]version-check
por defecto: yes

Comprobar la última versión de Percona Toolkit, MySQL y otros programas.

Esta es una característica estándar de "comprobar actualizaciones automáticamente", con dos características adicionales. Primero, la herramienta comprueba su propia versión y también las versiones del siguiente software: sistema operativo, Percona Monitoring and Management (PMM), MySQL, controlador de MySQL para Perl (DBD::mysql) y Percona Toolkit. Segundo, comprueba y advierte sobre versiones con problemas conocidos. Por ejemplo, MySQL 5.5.25 tenía un error crítico y fue relanzado como 5.5.25a.

pt-fk-error-logger(1p) — Percona Toolkit — Arch Linux

NAME

pt-fk-error-logger — Detects and logs foreign key errors

SYNOPSIS

pt-fk-error-logger [OPTIONS] DSN

RISKS

This tool connects to a MySQL server and reads and writes to a table. This can be risky. See https://www.perca.com/doc/percona-toolkit/LATEST/risks.html for details.

DESCRIPTION

This tool detects and logs foreign key errors. It can be run continuously or periodically. When foreign key errors are detected, it logs the errors to a specified table for later analysis. The tool implements a number of strategies for detecting foreign key errors.

The tool checks for version updates when run. See the "VERSION CHECK" section for details.

OUTPUT

The tool logs foreign key errors to the specified table. It also prints status messages to STDOUT and STDERR.

OPTIONS

--config <file>

Read this advanced configuration file. If specified, this option overrides all other configuration files.

--defaults-file <file>

Only read default options from the given file. This option is passed to the MySQL client library.

--help

Show help and exit.

--interval <seconds>

Run the check every N seconds. Defaults to 60 seconds.

--log-table <db.table>

Table in which to store foreign key errors. This table must exist before running the tool. See the "LOG TABLE STRUCTURE" section for the required table structure.

--no-check-replication

Do not check replication status. This is useful if you are not using replication or if you are running the tool on a master.

--no-version-check

Do not check for version updates. See the "VERSION CHECK" section for details.

--run-once

Run the check once and exit.

--set-vars <name>=<value>

Set the value of a MySQL variable. Defaults to "innodb_stats_on_metadata=0". See https://dev.mysql.com/doc/refman/8.0/en/server-system-variables.html#sysvar_innodb_stats_on_metadata.

--sleep <seconds>

Sleep for N seconds before checking foreign keys. Defaults to 0.

--user <user>

User for login.

--password <password>

Password to use when connecting.

--host <host>

Connect to host.

--port <port>

Port number to use for connection.

--socket <socket>

Socket file to use for connection.

--version

Show program name and version, and exit.

DSN OPTIONS

These DSN options are used to create a DSN. Each option is given like "option=value". The options are case-sensitive, so P and p are not the same option. There cannot be whitespace before or after the "=" and if the value contains whitespace it must be quoted. DSN options are comma-separated. See the percona-toolkit manpage for full details.

  • A

    dsn: charset; copy: yes

    Default character set.

  • D

    dsn: database; copy: yes

    Default database.

  • F

    dsn: mysql_read_default_file; copy: yes

    Only read default options from the given file

  • h

    dsn: host; copy: yes

    Connect to host.

  • p

    dsn: password; copy: yes

    Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

  • P

    dsn: port; copy: yes

    Port number to use for connection.

  • S

    dsn: mysql_socket; copy: yes

    Socket file to use for connection.

  • t

    Table in which to store foreign key errors.

  • u

    dsn: user; copy: yes

    User for login if not current user.

  • s

    dsn: mysql_ssl; copy: yes

    Create SSL connection

ENVIRONMENT

The environment variable "PTDEBUG" enables verbose debugging output to STDERR. To enable debugging and capture all output to a file, run the tool like:

PTDEBUG=1 pt-fk-error-logger ... > FILE 2>&1

Be careful: debugging output is voluminous and can generate several megabytes of output.

ATTENTION

Using <PTDEBUG> might expose passwords. When debug is enabled, all command line parameters are shown in the output.

SYSTEM REQUIREMENTS

You need Perl, DBI, DBD::mysql, and some core packages that ought to be installed in any reasonably new version of Perl.
