PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_rwlock_rdlock, pthread_rwlock_tryrdlock — bloquear un objeto de bloqueo de lectura-escritura para lectura

SINOPSIS

#include <pthread.h>
int pthread_rwlock_rdlock(pthread_rwlock_t *rwlock);
int pthread_rwlock_tryrdlock(pthread_rwlock_t *rwlock);

DESCRIPCION

La función pthread_rwlock_rdlock() aplica un bloqueo de lectura al bloqueo de lectura-escritura referenciado por rwlock. El hilo que llama adquiere el bloqueo de lectura si un escritor no tiene el bloqueo y no hay escritores bloqueados en él.

Si se admite la opción de programación de ejecución de hilos y los hilos involucrados en el bloqueo se ejecutan con las políticas de programación SCHED_FIFO o SCHED_RR, el hilo que llama no adquirirá el bloqueo si un escritor lo tiene o si escritores de prioridad más alta o igual están bloqueados en él; de lo contrario, el hilo que llama adquirirá el bloqueo.

Si se admite la opción de programación de ejecución de hilos y los hilos involucrados en el bloqueo se ejecutan con la política de programación SCHED_SPORADIC, el hilo que llama no adquirirá el bloqueo si un escritor lo tiene o si escritores de prioridad más alta o igual están bloqueados en él; de lo contrario, el hilo que llama adquirirá el bloqueo.

Si la opción de programación de ejecución de hilos no se admite, depende de la implementación si el hilo que llama adquiere el bloqueo cuando un escritor no lo tiene y hay escritores bloqueados en él. Si un escritor tiene el bloqueo, el hilo que llama no adquirirá el bloqueo de lectura. Si el bloqueo de lectura no se adquiere, el hilo que llama se bloqueará hasta que pueda adquirir el bloqueo. El hilo que llama puede entrar en deadlock si en el momento en que se realiza la llamada tiene un bloqueo de escritura.

Un hilo puede mantener múltiples bloqueos de lectura concurrentes en rwlock (es decir, llamar con éxito a la función pthread_rwlock_rdlock() n veces). Si es así, la aplicación debe asegurarse de que el hilo realice desbloqueos coincidentes (es decir, llama a la función pthread_rwlock_unlock() n veces).

El número máximo de bloqueos de lectura simultáneos que una implementación garantiza que se pueden aplicar a un bloqueo de lectura-escritura será definido por la implementación. La función pthread_rwlock_rdlock() puede fallar si se excede este máximo.

La función pthread_rwlock_tryrdlock() aplicará un bloqueo de lectura como en la función pthread_rwlock_rdlock(), con la excepción de que la función fallará si la llamada equivalente pthread_rwlock_rdlock() habría bloqueado al hilo que llama. En ningún caso la función pthread_rwlock_tryrdlock() se bloqueará; siempre adquiere el bloqueo o falla y retorna inmediatamente.

Los resultados no están definidos si alguna de estas funciones se llama con un bloqueo de lectura-escritura no inicializado.

Si se entrega una señal a un hilo que espera un bloqueo de lectura-escritura para lectura, al regresar del manejador de señales, el hilo reanuda la espera del bloqueo de lectura-escritura para lectura como si no hubiera sido interrumpido.

VALOR DE RETORNO

Si tiene éxito, la función pthread_rwlock_rdlock() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

La función pthread_rwlock_tryrdlock() devolverá cero si se adquiere el bloqueo de lectura en el objeto de bloqueo de lectura-escritura referenciado por rwlock. De lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_rwlock_tryrdlock() fallará si:

EBUSY
El bloqueo de lectura-escritura no pudo ser adquirido para lectura porque un escritor lo tiene o un escritor con la prioridad adecuada estaba bloqueado en él.

Las funciones pthread_rwlock_rdlock() y pthread_rwlock_tryrdlock() pueden fallar si:

EAGAIN
El bloqueo de lectura no pudo ser adquirido porque se ha superado el número máximo de bloqueos de lectura para rwlock.

La función pthread_rwlock_rdlock() puede fallar si:

EDEADLK
Se detectó una condición de deadlock o el hilo actual ya posee el bloqueo de lectura-escritura para escritura.

Estas funciones no devolverán un código de error de [EINTR].

Las siguientes secciones son informativas.

EJEMPLOS

USO DE APLICACIONES

Las aplicaciones que utilizan estas funciones pueden estar sujetas a inversión de prioridad, como se discute en el volumen de Definiciones Base de POSIX.1‐2017, Sección 3.291, Inversión de Prioridad.

RACIONAMIENTO

Si una implementación detecta que el valor especificado por el argumento rwlock a pthread_rwlock_rdlock() o pthread_rwlock_tryrdlock() no se refiere a un objeto de bloqueo de lectura-escritura inicializado, se recomienda que la función falle y reporte un error [EINVAL].

pthread_rwlock_rdlock(3p) — Arch manual pages

pthread_rwlock_rdlock, pthread_rwlock_unlock, pthread_rwlock_tryrdlock – lock a read-write lock for reading

Library
libpthread
Synopsis
#include <pthread.h>

int pthread_rwlock_rdlock(pthread_rwlock_t *rwlock);
int pthread_rwlock_unlock(pthread_rwlock_t *rwlock);
int pthread_rwlock_tryrdlock(pthread_rwlock_t *rwlock);

DESCRIPTION

The pthread_rwlock_rdlock() function shall lock the read-write lock referred to by rwlock for reading. If the lock is already held for writing, the thread shall block until the lock is released. If the lock is held for reading by other threads, the thread shall acquire the lock and proceed. If the calling thread already holds the lock for reading, the function shall return an error. If the lock is held for reading by one or more threads and for writing by no other threads, the calling thread shall acquire the lock and proceed.

The pthread_rwlock_tryrdlock() function shall attempt to lock the read-write lock referred to by rwlock for reading. If the lock is already held for writing, the function shall return immediately with an error.

The pthread_rwlock_unlock() function shall release the read-write lock referred to by rwlock, which must be held for writing or reading by the calling thread. The function shall behave as if it calls pthread_rwlock_unlock_callout() with appropriate arguments.

If the lock is held for reading by one or more threads and the calling thread has blocked on pthread_rwlock_rdlock() or pthread_rwlock_tryrdlock(), the calling thread shall be woken up and acquire the lock. If there are multiple threads blocked on acquiring the read lock, the selection of which thread will be woken up is implementation-dependent.

If the lock is held for reading by one or more threads and the calling thread has blocked on pthread_rwlock_wrlock(), the calling thread shall not be woken up. The calling thread will only be woken up if the lock is released for writing.

If the lock is held for writing by one thread and the calling thread has blocked on pthread_rwlock_rdlock() or pthread_rwlock_tryrdlock(), the calling thread shall not be woken up. The calling thread will only be woken up if the lock is released for writing.

RETURN VALUE

On successful completion, pthread_rwlock_rdlock() and pthread_rwlock_tryrdlock() shall return 0, and the lock shall be acquired. Otherwise, an error number shall be returned to indicate the error.

On successful completion, pthread_rwlock_unlock() shall return 0. Otherwise, an error number shall be returned to indicate the error.

ERRORS

[EINVAL]
The value specified by rwlock is invalid.
[EAGAIN]
The lock could not be acquired because the maximum number of read or write locks for the object would be exceeded.
[EBUSY]
pthread_rwlock_tryrdlock() could not acquire the lock because it was already held for writing.
[EDEADLK]
The calling thread already holds the lock for reading.
[EINVAL]
The value specified by rwlock is invalid.
[EPERM]
The calling thread does not hold the lock.
