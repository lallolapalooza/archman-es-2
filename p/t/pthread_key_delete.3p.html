PTHREAD_KEY_DELETE(3P) Manual del programador POSIX PTHREAD_KEY_DELETE(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_key_delete — eliminación de claves de datos específicos de hilo

SINOPSIS

#include <pthread.h>
int pthread_key_delete(pthread_key_t key);

DESCRIPCIÓN

La función pthread_key_delete() eliminará una clave de datos específicos de hilo devuelta previamente por pthread_key_create(). Los valores de datos específicos de hilo asociados con key no necesitan ser NULL en el momento en que se llama a pthread_key_delete(). Es responsabilidad de la aplicación liberar cualquier almacenamiento de aplicación o realizar cualquier acción de limpieza para estructuras de datos relacionadas con la clave eliminada o los datos específicos de hilo asociados en cualquier hilo; esta limpieza se puede realizar antes o después de llamar a pthread_key_delete(). Cualquier intento de usar key después de llamar a pthread_key_delete() resulta en un comportamiento indefinido.

La función pthread_key_delete() se podrá llamar desde dentro de funciones destructoras. No se invocarán funciones destructoras mediante pthread_key_delete(). Cualquier función destructora que pueda haberse asociado con key ya no se llamará al salir del hilo.

VALOR DE RETORNO

Si tiene éxito, la función pthread_key_delete() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_key_delete() no devolverá un código de error de [EINTR].

FUNDAMENTOS RACIONALES

Se ha incluido una función de eliminación de claves de datos específicos de hilo para permitir la liberación de los recursos asociados con una clave de datos específicos de hilo no utilizada. Las claves de datos específicos de hilo no utilizadas pueden surgir, entre otros escenarios, cuando se descarga un módulo cargado dinámicamente que asignó una clave.

Las aplicaciones conformes son responsables de realizar cualquier acción de limpieza necesaria para las estructuras de datos asociadas con la clave a eliminar, incluidos los datos a los que hacen referencia los valores de datos específicos de hilo. pthread_key_delete() no realiza ninguna de estas limpiezas. En particular, no se llaman las funciones destructoras. Hay varias razones para esta división de responsabilidad:

1.
Las funciones destructoras asociadas utilizadas para liberar datos específicos de hilo a la salida del hilo solo se garantiza que funcionen correctamente cuando se llaman en el hilo que asignó los datos específicos del hilo. (Los destructores en sí mismos pueden utilizar datos específicos de hilo). Por lo tanto, no se pueden utilizar para liberar datos específicos de hilo en otros hilos en el momento de la eliminación de la clave. Intentar que se llamen desde otros hilos en el momento de la eliminación de la clave requeriría la interrupción asincrónica de otros hilos. Pero dado que los hilos interrumpidos podrían estar en un estado arbitrario, incluido el mantenimiento de bloqueos necesarios para que el destructor se ejecute, este enfoque fallaría. En general, no existe un mecanismo seguro por el cual una implementación pueda liberar datos específicos de hilo en el momento de la eliminación de la clave.
2.
Incluso si hubiera un medio para liberar de forma segura los datos específicos de hilo asociados con las claves a eliminar, hacerlo requeriría que las implementaciones pudieran enumerar los hilos con datos no NULL y potencialmente evitar que creen más datos específicos de hilo mientras ocurre la eliminación de la clave. Este caso especial podría causar sincronización adicional en el caso normal, que de otro modo sería innecesaria.

Para que una aplicación sepa que es seguro eliminar una clave, tiene que saber que todos los hilos que potencialmente puedan usar la clave nunca intentarán usarla de nuevo. Por ejemplo, podría saberlo si todos los hilos cliente han llamado a un procedimiento de limpieza declarando que han terminado con el módulo que se está cerrando, quizás estableciendo un contador de referencias a cero.

Si una implementación detecta que el valor especificado por el argumento key a pthread_key_delete() no se refiere a un valor de clave obtenido de pthread_key_create() o se refiere a una clave que ha sido eliminada con pthread_key_delete(), se recomienda que la función falle e informe de un error [EINVAL].
