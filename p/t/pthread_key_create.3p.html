PTHREAD_KEY_CREATE(3P) Manual del programador POSIX PTHREAD_KEY_CREATE(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_key_create — creación de claves de datos específicas de hilo

SINOPSIS

#include <pthread.h>
int pthread_key_create(pthread_key_t *key, void (*destructor)(void*));

DESCRIPCIÓN

La función pthread_key_create() crea una clave de datos específica de hilo visible para todos los hilos del proceso. Los valores de clave proporcionados por pthread_key_create() son objetos opacos utilizados para localizar datos específicos de hilo. Aunque el mismo valor de clave puede ser utilizado por diferentes hilos, los valores enlazados a la clave por pthread_setspecific() se mantienen por hilo y persisten durante la vida del hilo que llama.

Al crear la clave, el valor NULL se asociará con la nueva clave en todos los hilos activos. Al crear un hilo, el valor NULL se asociará con todas las claves definidas en el nuevo hilo.

Una función destructora opcional puede asociarse con cada valor de clave. Al salir del hilo, si un valor de clave tiene un puntero destructor no NULL, y el hilo tiene un valor no NULL asociado con esa clave, el valor de la clave se establece en NULL, y luego la función apuntada se llama con el valor previamente asociado como su único argumento. El orden de las llamadas al destructor no está especificado si existen múltiples destructores para un hilo al salir de él.

Si, después de que todos los destructores hayan sido llamados para todos los valores no NULL con destructores asociados, todavía existen algunos valores no NULL con destructores asociados, entonces el proceso se repite. Si, después de al menos {PTHREAD_DESTRUCTOR_ITERATIONS} iteraciones de llamadas a destructores para valores no NULL pendientes, todavía existen algunos valores no NULL con destructores asociados, las implementaciones pueden dejar de llamar a los destructores, o pueden continuar llamando a los destructores hasta que no queden valores no NULL con destructores asociados, aunque esto podría resultar en un bucle infinito.

VALOR DE RETORNO

Si tiene éxito, la función pthread_key_create() almacenará el valor de clave recién creado en *key y devolverá cero. De lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_key_create() fallará si:

EAGAIN
El sistema carecía de los recursos necesarios para crear otra clave de datos específica de hilo, o se ha superado el límite impuesto por el sistema en el número total de claves por proceso {PTHREAD_KEYS_MAX}.
ENOMEM
No hay suficiente memoria para crear la clave.

La función pthread_key_create() no devolverá un código de error de [EINTR].

EJEMPLOS

El siguiente ejemplo demuestra una función que inicializa una clave de datos específica de hilo cuando se llama por primera vez y asocia un objeto específico de hilo con cada hilo que llama, inicializando este objeto cuando sea necesario.

static pthread_key_t key;
static pthread_once_t key_once = PTHREAD_ONCE_INIT;
static void
make_key()
{
    (void) pthread_key_create(&key, NULL);
}
func()
{
    void *ptr;
    (void) pthread_once(&key_once, make_key);
    if ((ptr = pthread_getspecific(key)) == NULL) {
        ptr = malloc(OBJECT_SIZE);
        ...
        (void) pthread_setspecific(key, ptr);
    }
    ...
}

Tenga en cuenta que la clave debe inicializarse antes de que se puedan utilizar pthread_getspecific() o pthread_setspecific(). La llamada a pthread_key_create() podría hacerse explícitamente en una rutina de inicialización de módulo, o puede hacerse implícitamente en la primera llamada a un módulo como en este ejemplo. Cualquier intento de usar la clave antes de que se inicialice es un error de programación, lo que hace que el siguiente código sea incorrecto.

static pthread_key_t key;
func()
{
    void *ptr;
   /* ¡¡¡CLAVE NO INICIALIZADA!!! ¡¡¡ESTO NO FUNCIONARÁ!!! */
    if ((ptr = pthread_getspecific(key)) == NULL &&
        pthread_setspecific(key, NULL) != 0) {
        pthread_key_create(&key, NULL);
        ...
    }
}

USO DE LA APLICACIÓN

Ninguno.

FUNDAMENTO

Funciones Destructoras

Normalmente, el valor enlazado a una clave en nombre de un hilo en particular es un puntero al almacenamiento asignado dinámicamente en nombre del hilo que llama. Las funciones destructoras especificadas con pthread_key_create() están destinadas a liberar este almacenamiento cuando el hilo sale. Los manejadores de limpieza de cancelación de hilo no pueden usarse para este propósito porque los datos específicos de hilo pueden persistir fuera del alcance léxico en el que operan los manejadores de limpieza de cancelación.

Si el valor asociado con una clave necesita ser actualizado durante la vida del hilo, puede ser necesario liberar el almacenamiento asociado con el valor antiguo antes de enlazar el nuevo valor. Aunque la función pthread_setspecific() podría hacer esto automáticamente, esta característica no se necesita con tanta frecuencia como para justificar la complejidad adicional. En su lugar, el programador es responsable de liberar el almacenamiento obsoleto:

pthread_getspecific(key, &old);
new = allocate();
destructor(old);
pthread_setspecific(key, new);
Nota:
El ejemplo anterior podría filtrar almacenamiento si se ejecuta con cancelación asíncrona habilitada. No ocurren tales problemas en el estado de cancelación predeterminado si no ocurren puntos de cancelación entre la obtención y el establecimiento.

No existe la noción de una función segura para destructores. Si una aplicación no llama a pthread_exit() desde un manejador de señales, o si bloquea cualquier señal cuyo manejador pueda llamar a pthread_exit() mientras llama a funciones asíncronamente inseguras, todas las funciones pueden ser llamadas de forma segura desde destructores.

Creación de claves de datos no idempotentes

Hubo solicitudes para hacer que pthread_key_create() sea idempotente con respecto a un parámetro de dirección key dado. Esto permitiría a las aplicaciones llamar a pthread_key_create() varias veces para una dirección key dada y garantizar que solo se crearía una clave. Hacer esto requeriría que el valor de la clave se inicializara previamente (posiblemente en tiempo de compilación) a un valor nulo conocido y requeriría que se realizara una exclusión mutua implícita basada en la dirección y el contenido del parámetro key para garantizar que se crearía exactamente una clave.

Desafortunadamente, la exclusión mutua implícita no se limitaría solo a pthread_key_create(). En muchas implementaciones, la exclusión mutua implícita también tendría que ser realizada por pthread_getspecific() y pthread_setspecific() para protegerse contra el uso de valores de clave incompletamente almacenados o aún no visibles. Esto podría aumentar significativamente el costo de operaciones importantes, particularmente pthread_getspecific().

Por lo tanto, esta propuesta fue rechazada. La función pthread_key_create() no realiza ninguna sincronización implícita. Es responsabilidad del programador asegurarse de que se llame exactamente una vez por clave antes de usar la clave. Varios mecanismos sencillos ya se pueden utilizar para lograr esto, incluyendo la llamada a funciones explícitas de inicialización de módulos, el uso de mutex y el uso de pthread_once(). Esto no supone una carga significativa para el programador, no introduce ningún mecanismo de sincronización implícita confuso y potencialmente permite que las operaciones de datos específicas de hilo de uso común sean más eficientes.
