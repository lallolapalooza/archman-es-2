PTHREAD_ONCE(3P) Manual de Programador POSIX PTHREAD_ONCE(3P)

PRÓLOGO

Esta página del manual forma parte del Manual de Programador POSIX. La implementación en Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux) o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_once — inicialización dinámica de paquetes

SINOPSIS

#include <pthread.h>
int pthread_once(pthread_once_t *once_control,
    void (*init_routine)(void));
pthread_once_t once_control = PTHREAD_ONCE_INIT;

DESCRIPCIÓN

La primera llamada a pthread_once() por cualquier hilo en un proceso, con un once_control dado, llamará a init_routine sin argumentos. Las llamadas posteriores a pthread_once() con el mismo once_control no llamarán a init_routine. Al regresar de pthread_once(), init_routine habrá completado. El parámetro once_control determinará si se ha llamado a la rutina de inicialización asociada.

La función pthread_once() no es un punto de cancelación. Sin embargo, si init_routine es un punto de cancelación y se cancela, el efecto sobre once_control será como si pthread_once() nunca se hubiera llamado.

Si la llamada a init_routine se termina con una llamada a longjmp(), _longjmp(), o siglongjmp(), el comportamiento es indefinido.

La constante PTHREAD_ONCE_INIT está definida en la cabecera <pthread.h>.

El comportamiento de pthread_once() es indefinido si once_control tiene duración de almacenamiento automático o no está inicializado por PTHREAD_ONCE_INIT.

VALOR DE RETORNO

Al completarse con éxito, pthread_once() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_once() no devolverá un código de error de [EINTR].

EJEMPLOS

Ninguno.

USO EN APLICACIONES

Si init_routine llama recursivamente a pthread_once() con el mismo once_control, la llamada recursiva no llamará a init_routine especificado, y por lo tanto init_routine no completará, y por lo tanto la llamada recursiva a pthread_once() no regresará. El uso de longjmp(), _longjmp(), o siglongjmp() dentro de un init_routine para saltar a un punto fuera de init_routine evita que init_routine retorne.

FUNDAMENTO

Algunas bibliotecas C están diseñadas para la inicialización dinámica. Es decir, la inicialización global de la biblioteca se realiza cuando se llama al primer procedimiento de la biblioteca. En un programa de un solo hilo, esto normalmente se implementa utilizando una variable estática cuyo valor se comprueba al entrar en una rutina, como sigue:

static int random_is_initialized = 0;
extern void initialize_random(void);
int random_function()
{
    if (random_is_initialized == 0) {
        initialize_random();
        random_is_initialized = 1;
    }
    ... /* Operaciones realizadas después de la inicialización. */
}

Para mantener la misma estructura en un programa multihilo, se necesita una nueva primitiva. De lo contrario, la inicialización de la biblioteca debe realizarse mediante una llamada explícita a una función de inicialización exportada por la biblioteca antes de cualquier uso de la biblioteca.

Para la inicialización de bibliotecas dinámicas en un proceso multihilo, si se utiliza una bandera de inicialización, la bandera debe protegerse contra la modificación simultánea por varios hilos que llaman a la biblioteca. Esto se puede hacer utilizando un mutex (inicializado asignando PTHREAD_MUTEX_INITIALIZER). Sin embargo, la mejor solución es utilizar pthread_once(), que está diseñado exactamente para este propósito, como sigue:

#include <pthread.h>
static pthread_once_t random_is_initialized = PTHREAD_ONCE_INIT;
extern void initialize_random(void);
int random_function()
{
    (void) pthread_once(&random_is_initialized, initialize_random);
    ... /* Operaciones realizadas después de la inicialización. */
}

Si una implementación detecta que el valor especificado por el argumento once_control a pthread_once() no se refiere a un objeto pthread_once_t inicializado por PTHREAD_ONCE_INIT, se recomienda que la función falle y reporte un error [EINVAL].

    pthread_once(3p)

    pthread_once - Pthreads-2008 init once function.

    SYNOPSIS

    #include <pthread.h>

int pthread_once(pthread_once_t *once_control,
       void (*init_routine)(void));

    DESCRIPTION

    The pthread_once() function is used to ensure that a specific initialization routine is executed at most once, even in the presence of multiple threads. The once_control argument is a pointer to a pthread_once_t object that controls the execution of the initialization routine. The init_routine argument is a pointer to a function that takes no arguments and returns void.

    When pthread_once() is called, it checks the state of the once_control object. If the initialization routine has already been executed, pthread_once() returns immediately. If the initialization routine has not yet been executed, pthread_once() calls init_routine(). After init_routine() returns, pthread_once() marks the once_control object to indicate that the initialization has been completed.

    The pthread_once_t object must be initialized using PTHREAD_ONCE_INIT before its first use.

    RETURN VALUE

    On success, pthread_once() returns 0. On error, it returns an error number and the content of once_control is indeterminate.

    ERRORS

    EINVAL
    The value specified by once_control is invalid.

    CONFORMING TO

    POSIX.1-2008.
