NOMBRE

pt-online-schema-change - ALTER de tablas sin bloquearlas.

SINOPSIS

Uso: pt-online-schema-change [OPCIONES] DSN

pt-online-schema-change altera la estructura de una tabla sin bloquear lecturas o escrituras. Especifica la base de datos y la tabla en el DSN. No uses esta herramienta antes de leer su documentación y verificar cuidadosamente tus copias de seguridad.

Añadir una columna a sakila.actor:

pt-online-schema-change --alter "ADD COLUMN c1 INT" D=sakila,t=actor

Cambiar sakila.actor a InnoDB, realizando efectivamente OPTIMIZE TABLE de forma no bloqueante, ya que es una tabla InnoDB existente:

pt-online-schema-change --alter "ENGINE=InnoDB" D=sakila,t=actor

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien probado, pero todas las herramientas de bases de datos pueden suponer un riesgo para el sistema y el servidor de bases de datos. Antes de usar esta herramienta, por favor:

  • Lee la documentación de la herramienta
  • Revisa los "BUGS" conocidos de la herramienta
  • Prueba la herramienta en un servidor no productivo
  • Haz una copia de seguridad de tu servidor de producción y verifica las copias de seguridad

DESCRIPCIÓN

pt-online-schema-change emula la forma en que MySQL altera las tablas internamente, pero trabaja sobre una copia de la tabla que deseas alterar. Esto significa que la tabla original no se bloquea y los clientes pueden continuar leyendo y modificando datos en ella.

pt-online-schema-change funciona creando una copia vacía de la tabla a alterar, modificándola según lo deseado, y luego copiando filas de la tabla original a la nueva tabla. Cuando la copia se completa, mueve la tabla original y la reemplaza con la nueva. Por defecto, también elimina la tabla original.

El proceso de copia de datos se realiza en pequeños fragmentos de datos, que se varían para intentar que se ejecuten en una cantidad de tiempo específica (ver "--chunk-time"). Este proceso es muy similar a cómo funcionan otras herramientas, como pt-table-checksum. Cualquier modificación de datos en las tablas originales durante la copia se reflejará en la nueva tabla, ya que la herramienta crea disparadores (triggers) en la tabla original para actualizar las filas correspondientes en la nueva tabla. El uso de disparadores significa que la herramienta no funcionará si ya existen disparadores definidos en la tabla.

Cuando la herramienta termina de copiar datos a la nueva tabla, utiliza una operación atómica de "RENAME TABLE" para renombrar simultáneamente la tabla original y la nueva. Después de esto, la herramienta elimina la tabla original.

Las claves foráneas complican la operación de la herramienta e introducen riesgos adicionales. La técnica de renombrar atómicamente la tabla original y la nueva no funciona cuando las claves foráneas hacen referencia a la tabla. La herramienta debe actualizar las claves foráneas para que hagan referencia a la nueva tabla después de que el cambio de esquema se complete. La herramienta soporta dos métodos para lograr esto. Puedes leer más sobre esto en la documentación de "--alter-foreign-keys-method".

Las claves foráneas también causan algunos efectos secundarios. La tabla final tendrá las mismas claves foráneas e índices que la tabla original (a menos que especifiques lo contrario en tu sentencia ALTER), pero los nombres de los objetos pueden cambiarse ligeramente para evitar colisiones de nombres de objetos en MySQL y InnoDB.

Por seguridad, la herramienta no modifica la tabla a menos que especifiques la opción "--execute", que no está habilitada por defecto. La herramienta soporta una variedad de otras medidas para prevenir carga no deseada u otros problemas, incluyendo la detección automática de réplicas, la conexión a ellas y el uso de las siguientes comprobaciones de seguridad:

  • En la mayoría de los casos, la herramienta se negará a operar a menos que exista una CLAVE PRIMARIA o un ÍNDICE ÚNICO en la tabla. Ver "--alter" para más detalles.
  • La herramienta se niega a operar si detecta filtros de replicación. Ver "--[no]check-replication-filters" para más detalles.
  • La herramienta pausa la operación de copia de datos si observa alguna réplica que esté retrasada en la replicación. Ver "--max-lag" para más detalles.
  • La herramienta pausa o aborta su operación si detecta demasiada carga en el servidor. Ver "--max-load" y "--critical-load" para más detalles.
  • La herramienta establece "innodb_lock_wait_timeout=1" y (para MySQL 5.5 y más recientes) "lock_wait_timeout=60" para que sea más probable que sea la víctima de cualquier contención de bloqueos y menos probable que interrumpa otras transacciones. Estos valores se pueden cambiar especificando "--set-vars".
  • La herramienta se niega a alterar la tabla si restricciones de clave foránea hacen referencia a ella, a menos que especifiques "--alter-foreign-keys-method".
  • La herramienta no puede alterar tablas MyISAM en nodos de "Percona XtraDB Cluster".

Percona XtraDB Cluster

pt-online-schema-change funciona con Percona XtraDB Cluster (PXC) 5.5.28-23.7 y posteriores, pero hay dos limitaciones: solo se pueden alterar tablas InnoDB y "wsrep_OSU_method" debe estar configurado como "TOI" (total order isolation). La herramienta sale con un error si el host es un nodo del clúster y la tabla es MyISAM o se está convirtiendo a MyISAM ("ENGINE=MyISAM"), o si "wsrep_OSU_method" no es "TOI". No hay forma de deshabilitar estas comprobaciones.

MySQL 5.7 + columnas generadas

La herramienta ignora las columnas "GENERATED" de MySQL 5.7+ ya que el valor para esas columnas se genera de acuerdo con la expresión utilizada para calcular los valores de las columnas.

SALIDA

La herramienta imprime información sobre sus actividades a STDOUT para que puedas ver lo que está haciendo. Durante la fase de copia de datos, imprime informes de "--progress" a STDERR. Puedes obtener información adicional especificando "--print".

Si se especifica "--statistics", al final se imprime un informe de varios recuentos de eventos internos, como:

# Evento  Cuenta
# ======  =====
# INSERT     1

OPCIONES

"--dry-run" y "--execute" son mutuamente excluyentes.

Esta herramienta acepta argumentos de línea de comandos adicionales. Consulta la "SINOPSIS" y la información de uso para obtener detalles.

--alter
tipo: cadena

La modificación del esquema, sin las palabras clave ALTER TABLE. Puedes realizar múltiples modificaciones en la tabla especificándolas con comas. Consulta el manual de MySQL para la sintaxis de ALTER TABLE.

Se aplican las siguientes limitaciones que, si se intentan, provocarán que la herramienta falle de forma impredecible:

  • En casi todos los casos, debe existir una CLAVE PRIMARIA o un ÍNDICE ÚNICO en la tabla. Esto es necesario porque la herramienta crea un disparador (trigger) de eliminación para mantener actualizada la nueva tabla mientras el proceso se ejecuta.

  • La cláusula "RENAME" no se puede utilizar para renombrar la tabla.
  • Las columnas no se pueden renombrar eliminándolas y volviéndolas a agregar con el nuevo nombre. La herramienta no copiará los datos de la columna original a la nueva columna.

    --[no]check-replication-filters
    predeterminado: yes

    Abortar si algún filtro de replicación está establecido en algún servidor. La herramienta busca opciones del servidor que filtren la replicación, como binlog_ignore_db y replicate_do_db. Si encuentra alguno de estos filtros, abortará con un error.

    Si las réplicas están configuradas con alguna opción de filtrado, debe tener cuidado de no modificar ninguna base de datos o tabla que exista en el origen de replicación y no en las réplicas, ya que podría causar un fallo en la replicación. Para obtener más información sobre las reglas de replicación, consulte http://dev.mysql.com/doc/en/replication-rules.html.

    --check-replica-lag
    tipo: string

    Pausar la copia de datos hasta que el retardo de esta réplica sea menor que "--max-lag". El valor es un DSN que hereda las propiedades de las opciones de conexión ("--port", "--user", etc.). Esta opción anula el comportamiento normal de búsqueda y monitorización continua del retardo de replicación en TODAS las réplicas conectadas. Si no desea monitorizar TODAS las réplicas, pero desea que se monitorice más de una, utilice la opción DSN de la opción "--recursion-method" en lugar de esta opción.

    --check-slave-lag
    tipo: string

    Esta opción está obsoleta y se eliminará en futuras versiones. Utilice "--check-replica-lag" en su lugar.

    --chunk-index
    tipo: string

    Preferir este índice para fragmentar tablas. Por defecto, la herramienta elige el índice más apropiado para la fragmentación. Esta opción le permite especificar el índice que prefiere. Si el índice no existe, la herramienta recurrirá a su comportamiento predeterminado de elegir un índice. La herramienta añade el índice a las sentencias SQL en una cláusula "FORCE INDEX". Tenga cuidado al usar esta opción; una mala elección del índice podría causar un mal rendimiento.

    --chunk-index-columns
    tipo: int

    Utilizar solo este número de columnas de la izquierda de un "--chunk-index". Esto solo funciona para índices compuestos y es útil en casos en los que un error en el optimizador de consultas (planificador) de MySQL hace que escanee un gran rango de filas en lugar de usar el índice para localizar los puntos de inicio y fin con precisión. Este problema a veces ocurre en índices con muchas columnas, como 4 o más. Si esto sucede, la herramienta podría imprimir una advertencia relacionada con la opción "--[no]check-plan". Instruir a la herramienta para que use solo las primeras N columnas del índice es una solución alternativa para el error en algunos casos.

    --chunk-size
    tipo: size; predeterminado: 1000

    Número de filas a seleccionar para cada fragmento copiado. Los sufijos permitidos son k, M, G.

    Esta opción puede anular el comportamiento predeterminado, que es ajustar el tamaño del fragmento dinámicamente para intentar que los fragmentos se ejecuten en exactamente "--chunk-time" segundos. Cuando esta opción no se establece explícitamente, su valor predeterminado se utiliza como punto de partida, pero después de eso, la herramienta ignora el valor de esta opción. Sin embargo, si establece esta opción explícitamente, desactiva el comportamiento de ajuste dinámico e intenta que todos los fragmentos tengan exactamente el número de filas especificado.

    --chunk-size-limit
    tipo: float; predeterminado: 4.0

    No copiar fragmentos mucho más grandes que el tamaño de fragmento deseado.

    Cuando una tabla no tiene índices únicos, los tamaños de los fragmentos pueden ser inexactos. Esta opción especifica un límite tolerable máximo para la inexactitud. La herramienta utiliza <EXPLAIN> para estimar cuántas filas hay en el fragmento. Si esa estimación excede el tamaño de fragmento deseado multiplicado por el límite, la herramienta dejará de copiar filas y fallará.

    El valor mínimo para esta opción es 1, lo que significa que ningún fragmento puede ser mayor que "--chunk-size".     --max-lag
    tipo: time; por defecto: 1s

    Pausar la copia de datos hasta que el lag de todas las réplicas sea inferior a este valor. Después de cada consulta de copia de datos (cada fragmento), la herramienta examina el lag de replicación de todas las réplicas a las que se conecta, utilizando Seconds_Behind_Source. );

    OPTIONS

    [--alter-foreign-keys-method=method]

    Determines how foreign key constraints are managed while pt-online-schema-change runs.

    This option affects how foreign keys are handled on the original table and the new table. It is possible that neither method works for your foreign key constraints. In that case, you must manage them manually by setting this option to none.

    Method | Description
-------+------------
alter  | Disable foreign key checks on the original table and enable them
       | on the new table. Foreign keys on the new table are disabled
       | when the new table is created. The ALTER TABLE statement
       | enables foreign keys for the new table.
none   | Do nothing. You must manage foreign keys manually.
rebuild_constraints | For each foreign key constraint on the original table,
       | add a foreign key constraint to the new table. Disable
       | foreign key checks on the original table. When you swap
       | tables, foreign keys on the new table will be disabled.
       | The ALTER TABLE statement rebuilds the foreign keys for
       | the new table.

    The default is rebuild_constraints.

    You may want to set this to none if the foreign keys are complex and your only goal is to alter the table. If you do this, you must manually manage the foreign keys.

    The rebuild_constraints method is the most robust and usually the best choice. It's the default because it's less likely to fail and requires the least amount of manual intervention.

    The rebuild_constraints method requires two "ALTER TABLE ... ENABLE KEYS" operations that can take a long time. Setting this to alter can make the operation faster, but it's less robust and may fail.

    [--alter-foreign-keys-method=method]
