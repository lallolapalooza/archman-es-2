NOMBRE

pthread_mutex_consistent — marca el estado protegido por un mutex robusto como consistente

SINOPSIS

#include <pthread.h>
int pthread_mutex_consistent(pthread_mutex_t *mutex);

DESCRIPCIÓN

Si mutex es un mutex robusto en un estado inconsistente, la función pthread_mutex_consistent() se puede utilizar para marcar de nuevo el estado protegido por el mutex al que se refiere mutex como consistente.

Si un propietario de un mutex robusto termina mientras lo mantiene, el mutex se vuelve inconsistente y el siguiente hilo que adquiera el bloqueo del mutex será notificado del estado mediante el valor de retorno [EOWNERDEAD]. En este caso, el mutex no vuelve a ser utilizable normalmente hasta que el estado se marque como consistente.

Si el hilo que adquirió el bloqueo del mutex con el valor de retorno [EOWNERDEAD] termina antes de llamar a pthread_mutex_consistent() o pthread_mutex_unlock(), el siguiente hilo que adquiera el bloqueo del mutex será notificado sobre el estado del mutex mediante el valor de retorno [EOWNERDEAD].

El comportamiento no está definido si el valor especificado por el argumento mutex a pthread_mutex_consistent() no se refiere a un mutex inicializado.

VALOR DE RETORNO

Al completarse con éxito, la función pthread_mutex_consistent() devolverá cero. De lo contrario, se devolverá un valor de error para indicar el error.

ERRORES

La función pthread_mutex_consistent() fallará si:

EINVAL
El objeto mutex referenciado por mutex no es robusto o no protege un estado inconsistente.

Estas funciones no devolverán un código de error de [EINTR].

USO DE APLICACIONES

La función pthread_mutex_consistent() solo es responsable de notificar a la implementación que el estado protegido por el mutex ha sido recuperado y que las operaciones normales con el mutex pueden reanudarse. Es responsabilidad de la aplicación recuperar el estado para que pueda ser reutilizado. Si la aplicación no puede realizar la recuperación, puede notificar a la implementación que la situación no es recuperable mediante una llamada a pthread_mutex_unlock() sin una llamada previa a pthread_mutex_consistent(), en cuyo caso los hilos posteriores que intenten bloquear el mutex fallarán al adquirir el bloqueo y se les devolverá [ENOTRECOVERABLE].

FUNDAMENTO RACIONAL

Si una implementación detecta que el valor especificado por el argumento mutex a pthread_mutex_consistent() no se refiere a un mutex inicializado, se recomienda que la función falle y reporte un error [EINVAL].
