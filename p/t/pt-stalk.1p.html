NOMBRE

pt-stalk - Recopilar datos forenses de MySQL cuando ocurren problemas.

SINOPSIS

Uso: pt-stalk [OPCIONES]

pt-stalk espera a que ocurra una condición de activación y luego recopila datos para ayudar a diagnosticar problemas. La herramienta está diseñada para ejecutarse como un demonio con privilegios de root, para que pueda diagnosticar problemas intermitentes que no puede observar directamente. También puede usarla para ejecutar un comando personalizado o para recopilar datos bajo demanda sin esperar a que ocurra el activador.

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien verificado, pero todas las herramientas de bases de datos pueden suponer un riesgo para el sistema y el servidor de la base de datos. Antes de usar esta herramienta, por favor:

  • Lea la documentación de la herramienta
  • Revise los "BUGS" conocidos de la herramienta
  • Pruebe la herramienta en un servidor no productivo
  • Haga una copia de seguridad de su servidor de producción y verifique las copias de seguridad

DESCRIPCIÓN

A veces, un problema ocurre con poca frecuencia y durante un corto período de tiempo, dándole ninguna oportunidad de ver el sistema cuando ocurre. ¿Cómo resuelve problemas intermitentes de MySQL cuando no puede observarlos? Para eso existe pt-stalk. Además de usarla cuando hay un problema conocido en sus servidores, es una buena idea ejecutar pt-stalk todo el tiempo, incluso cuando cree que nada está mal. Apreciará los datos que recopila cuando ocurre un problema, ya que problemas como bloqueos de MySQL o picos de actividad típicamente no dejan evidencia para usar en el análisis de causa raíz.

pt-stalk hace dos cosas: observa un servidor MySQL y espera a que ocurra una condición de activación, y recopila datos de diagnóstico cuando esa activación ocurre. Para evitar falsos positivos causados por problemas de corta duración, la condición de activación debe ser verdadera al menos "--cycles" veces antes de que se active una recopilación "--collect".

Para usar pt-stalk de manera efectiva, necesita definir un buen activador. Un buen activador es lo suficientemente sensible como para dispararse de manera confiable cuando ocurre un problema, para que no pierda la oportunidad de resolver problemas. Por otro lado, un buen activador no es propenso a falsos positivos, por lo que no recopila información cuando el servidor funciona normalmente.

Los activadores más confiables para MySQL tienden a ser el número de conexiones al servidor y el número de consultas ejecutándose concurrentemente. Estos están disponibles en el comando SHOW GLOBAL STATUS como Threads_connected y Threads_running. A veces, Threads_connected no es un indicador confiable de problemas, pero Threads_running sí lo es generalmente. Su trabajo, como usuario de la herramienta, es definir una condición de activación apropiada para la herramienta. Elija con cuidado, ya que la calidad de sus resultados dependerá del activador que elija.

Define el activador con las opciones "--function", "--variable", "--threshold" y "--cycles". Los valores predeterminados para estas opciones definen un activador razonable, pero debe ajustarlos o cambiarlos para adaptarse a su sistema y necesidades particulares.

Por defecto, la herramienta pt-stalk observa MySQL para siempre hasta que ocurre el activador, luego recopila datos de diagnóstico durante un tiempo y duerme después para evitar recopilar datos repetidamente si el activador permanece verdadero. El orden general de las operaciones es:

while true; do
   if --variable de --function > --threshold; then
      cycles_true++
      if cycles_true >= --cycles; then
         --notify-by-email
         if --collect; then
            if --disk-bytes-free y --disk-pct-free ok; then
               (--collect para --run-time segundos) &
            fi
            rm archivos en --dest anteriores a --retention-time
         fi
         iter++
         cycles_true=0
      fi
      if iter < --iterations; then
         sleep segundos --sleep
      else
         break
      fi
   else
      if iter < --iterations; then
         sleep segundos --interval
      else
         break
      fi
   fi
done
rm archivos viejos en --dest anteriores a --retention-time
if procesos --collect siguen en ejecución; then
   esperar hasta --run-time * 3 segundos
   matar cualquier proceso --collect restante
fi

Los datos de diagnóstico se escriben en archivos cuyos nombres comienzan con una marca de tiempo, por lo que puede distinguir las muestras entre sí en caso de que la herramienta recopile datos varias veces. La herramienta pt-sift está diseñada para ayudarlo a explorar y analizar las muestras de datos resultantes.

Aunque esto suena lo suficientemente simple, en la práctica hay una serie de sutilezas, como detectar cuándo el disco está empezando a llenarse para que la herramienta no provoque que el servidor se quede sin espacio en disco. Esta herramienta maneja este tipo de problemas potenciales, por lo que es una buena idea usar esta herramienta en lugar de escribir algo desde cero y posiblemente experimentar algunos de los peligros que esta herramienta está diseñada para evitar.

CONFIGURACIÓN

Puede usar los archivos de configuración estándar de Percona Toolkit para establecer opciones de línea de comandos.

Probablemente querrá ejecutar la herramienta como un demonio y personalizar al menos el "--threshold". Aquí hay un archivo de configuración de ejemplo para activarse cuando hay más de 20 consultas ejecutándose a la vez:

daemonize
threshold=20

Si no ejecuta la herramienta como root, deberá especificar varias opciones, como "--pid", "--log" y "--dest", de lo contrario, la herramienta probablemente fallará al iniciarse.

OPCIONES

--ask-pass
Solicitar una contraseña al conectarse a MySQL.
--collect
predeterminado: sí; negable: sí

Recopilar datos de diagnóstico cuando ocurre el activador. Especifique "--no-collect" para que la herramienta observe el sistema pero no recopile datos.

Ver también "--stalk".

--collect-gdb
Recopilar volcados de pila de GDB. Esto se logra adjuntándose a MySQL e imprimiendo volcados de pila de todos los hilos. Esto congelará el servidor durante un período de tiempo, que varía desde un segundo aproximadamente hasta mucho más tiempo en sistemas muy ocupados con mucha memoria y muchos hilos en el servidor. Por esta razón, está deshabilitado por defecto. Sin embargo, si está intentando diagnosticar un bloqueo o congelamiento del servidor, congelar el servidor no causa daño adicional, y los volcados de pila pueden ser vitales para el diagnóstico.

Además de congelar el servidor, también existe el riesgo de que el servidor se bloquee o funcione mal después de que GDB se desconecte de él.

--collect-oprofile
Recopilar datos de oprofile. Esto se logra iniciando una sesión de oprofile, dejándola ejecutarse durante el tiempo de recopilación, y luego deteniéndola y guardando los datos de perfil resultantes en la ubicación predeterminada del sistema. Lea la documentación de oprofile de su sistema para aprender más al respecto.
--collect-strace
Recopilar datos de strace. Esto se logra adjuntando strace al servidor, lo que hará que funcione muy lentamente hasta que strace se desconecte. Las mismas precauciones se aplican a las enumeradas en --collect-gdb. No debe habilitar esta opción junto con --collect-gdb, ya que GDB y strace no pueden adjuntarse al proceso del servidor simultáneamente.
--collect-tcpdump
Recopilar datos de tcpdump. Esta opción hace que tcpdump capture todo el tráfico en todas las interfaces para el puerto en el que escucha MySQL. Más tarde, puede usar pt-query-digest para decodificar el protocolo MySQL y extraer un registro de tráfico de consultas de él.
--config
tipo: string

Lea esta lista de archivos de configuración separados por comas. Si se especifica, esta debe ser la primera opción en la línea de comandos.

--cycles
tipo: int; predeterminado: 5

¿Cuántas veces debe "--variable" ser mayor que "--threshold" antes de activar "--collect"? Esto ayuda a prevenir falsos positivos y hace que la condición de activación sea menos probable que se dispare cuando el problema se recupera rápidamente.

--daemonize
Daemonizar la herramienta. Esto hace que la herramienta se bifurque en segundo plano y registre su salida según lo especificado en --log.
--defaults-file
forma corta: -F; tipo: string

Lea solo las opciones de mysql del archivo dado. Debe proporcionar una ruta de nombre de archivo absoluta.

--dest
tipo: string; predeterminado: /var/lib/pt-stalk

NAME

pt-stalk - Collects performance data and system information from MySQL servers.

SYNOPSIS

pt-stalk [OPTIONS]

RISKS

This tool is designed to collect data from your MySQL servers. It is important to understand the risks associated with its use, including potential performance impacts and data storage requirements. Ensure you have adequate disk space and understand how to interpret the collected data before deploying this tool in a production environment.

DESCRIPTION

pt-stalk is a powerful tool for collecting performance data and system information from MySQL servers. It can be used to diagnose performance issues, troubleshoot problems, and monitor server health over time. The tool can collect a wide range of data, including MySQL status variables, process lists, slow queries, system metrics, and more.

It operates by monitoring the server and collecting data at predefined intervals or when specific events occur. The collected data is stored in files, which can then be analyzed using other tools or scripts.

CONFIGURING

pt-stalk can be configured using command-line options or a configuration file. The configuration file allows for more detailed settings and is recommended for complex setups. Key configuration options include:

  • Connection details for the MySQL server.
  • Data collection intervals and triggers.
  • Types of data to collect.
  • Output file locations and formats.

Refer to the tool's documentation for a complete list of configuration options and examples.

OPTIONS

pt-stalk offers a comprehensive set of options to control its behavior. Some of the most important options include:

--defaults-file, -f
Specify a configuration file to use.
--host, -h
MySQL host to connect to.
--user, -u
MySQL user to connect with.
--password, -p
MySQL password.
--interval, -i
Interval in seconds between data collections.
--collect
Specify which data collectors to enable (e.g., 'status', 'processlist', 'slowlog').
--run-time
Duration in seconds to run the tool.
--log-dir
Directory to store the collected data files.

For a full list of options, see the tool's manual page or run `pt-stalk --help`.

ENVIRONMENT

The tool may use environment variables for connection parameters if not specified on the command line or in a configuration file. For example, MYSQL_HOST, MYSQL_USER, MYSQL_PASSWORD.

SYSTEM REQUIREMENTS

Requires Perl and several Perl modules, including DBD::mysql. Ensure that your system meets the necessary requirements for running Percona Toolkit.

BUGS

Report bugs to the Percona Toolkit bug tracker at https://jira.percona.com/.

ATTENTION

Running this tool can generate a significant amount of data, especially on busy servers. Ensure you have sufficient disk space and that the data collection process does not negatively impact server performance. Monitor your system closely during operation.
