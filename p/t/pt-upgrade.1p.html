pt-upgrade(1p)

Paquete: percona-toolkit

Licencias: GPL

PT-UPGRADE(1) Documentación de Perl contribuida por el usuario PT-UPGRADE(1)

NOMBRE

pt-upgrade - Verifica que los resultados de las consultas sean idénticos en diferentes servidores.

SINOPSIS

Uso: pt-upgrade [OPCIONES] LOGS|RESULTADOS DSN [DSN]

pt-upgrade ejecuta consultas en los "LOGS" de MySQL dados en cada "DSN", compara los resultados e informa cualquier diferencia significativa. La herramienta también puede guardar los resultados para análisis posteriores. "LOGS" puede ser lento, general, binario, tcpdump y "raw".

Compara host2 con host1 usando consultas en "slow.log":

pt-upgrade h=host1 h=host2 slow.log

Compara host2 con resultados guardados de host1:

pt-upgrade h=host1 --save-results host1_results/ slow.log
pt-upgrade host1_results1/ h=host2

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien probado, pero todas las herramientas de bases de datos pueden suponer un riesgo para el sistema y el servidor de la base de datos. Antes de usar esta herramienta, por favor:

  • Lea la documentación de la herramienta
  • Revise los "BUGS" conocidos de la herramienta
  • Pruebe la herramienta en un servidor no productivo
  • Haga una copia de seguridad de su servidor de producción y verifique las copias de seguridad

DESCRIPCIÓN

pt-upgrade ayuda a determinar si es seguro actualizar (o degradar) a una nueva versión de MySQL. Un plan de actualización seguro y conservador tiene varios pasos, uno de los cuales es asegurar que las consultas producirán resultados idénticos en la nueva versión de MySQL.

pt-upgrade ejecuta consultas de los logs lentos, generales, binarios, tcpdump y "raw" en dos servidores, compara muchos aspectos de la ejecución y resultados de cada consulta, e informa cualquier diferencia significativa. Los dos servidores son típicamente servidores de desarrollo, uno ejecutando la versión de producción actual de MySQL y el otro ejecutando la nueva versión de MySQL.

CASOS DE USO

pt-upgrade tiene dos casos de uso. El primer caso canónico es ejecutar "host a host". Se proporciona un archivo de log y dos DSN en la línea de comandos, uno para cada servidor MySQL. Vea el primer ejemplo en la "SINOPSIS". Las consultas se ejecutan y comparan en cada servidor mientras la herramienta se ejecuta. Las consultas con diferencias se imprimen a medida que la herramienta se ejecuta, o cuando termina (ver "CUÁNDO SE INFORMAN LAS CONSULTAS"). Nada se guarda en disco, por lo que este caso de uso requiere menos espacio en disco, pero las consultas deben ejecutarse en ambos servidores si la herramienta se ejecuta de nuevo, incluso si uno de los servidores no ha cambiado. Si hay muchas consultas o su ejecución lleva mucho tiempo, y un servidor no cambia, es posible que desee utilizar el segundo caso de uso.

El segundo caso de uso es ejecutar "resultados de referencia a host". Los resultados de referencia son los resultados completos de un único servidor MySQL, guardados en disco. En este caso, primero debe generar los resultados de referencia con "--save-results", luego ejecutar la herramienta una segunda vez para comparar otro servidor MySQL con los resultados. Vea el segundo ejemplo en la "SINOPSIS". Los resultados se generan típicamente para la versión actual de MySQL, que no cambia. Este caso de uso puede requerir *mucho* espacio en disco porque los resultados (es decir, las filas) de todas las consultas deben guardarse, más otros datos sobre las consultas. Si planea hacer muchas comparaciones contra una versión fija de MySQL, este caso de uso es más eficiente. O si no tiene acceso a ambos servidores al mismo tiempo, este caso de uso le permite "ejecutar ahora, comparar después".

CONSIDERACIONES IMPORTANTES

CONSISTENCIA

Entornos consistentes y datos consistentes son cruciales para obtener un informe preciso. pt-upgrade nunca debe ejecutarse en un servidor de producción o en cualquier servidor activo porque no hay una manera fácil de asegurar una lectura síncrona para cada consulta. Si los datos están cambiando en alguno de los servidores mientras pt-upgrade se está ejecutando, el informe podría contener más falsos positivos que diferencias legítimas. pt-upgrade asume que ambos servidores MySQL son estáticos, inmutables (excepto por cualquier cambio realizado por la herramienta si se ejecuta con "--no-read-only"). Una carga de trabajo de solo lectura no debería afectar a la herramienta, excepto quizás los tiempos de consulta, por lo que se podrían usar réplicas de solo lectura.

COMPARADO CON

En una comparación host a host, los resultados del primer host establecen la norma a la que se comparan los resultados del segundo host. En una comparación de resultados de referencia a host, los resultados de referencia son la norma a la que se compara el host. Frases comparativas como "menor que", "mejor que", etc. significan comparado con la norma.

Por ejemplo, si el tiempo de consulta de un evento es 0.01 en el primer host y 0.5 en el segundo host, es una diferencia significativa porque 0.5 es peor que 0.1, y por lo tanto la consulta será reportada.

SOLO LECTURA

Por defecto, pt-upgrade solo ejecuta "SELECT" y "SET". (Esto no incluye las sentencias 'SELECT...INTO', que no devuelven filas sino que vuelcan la salida a un archivo o variable). Si está utilizando servidores de prueba o desarrollo recreables y desea comparar también las escrituras (por ejemplo, "INSERT", "UPDATE", "DELETE"), especifique "--no-read-only". Si usa un log binario, debe especificar "--no-read-only" porque los logs binarios no contienen sentencias "SELECT". Ver "--[no]read-only".

TRANSACCIONES

La herramienta no crea sus propias transacciones, pero cualquier transacción en el "LOG" se ejecuta tal cual. Dado que los logs son seriales, las transacciones normalmente no deberían ser un problema. Sin embargo, si necesita comparar consultas que están de alguna manera relacionadas transaccionalmente (en cuyo caso probablemente también necesite deshabilitar "--[no]read-only"), entonces pt-upgrade probablemente no hará lo que necesita porque no está diseñado para este propósito.

pt-upgrade se ejecuta con "autocommit=1" por defecto.

LIMITACIÓN

pt-upgrade no tiene opciones de limitación porque la herramienta solo debe ejecutarse en servidores de prueba o desarrollo dedicados. ¡No ejecute pt-upgrade en servidores de producción! Consecuentemente, la herramienta es intensiva en CPU, memoria, disco y red. Ejecuta las consultas lo más rápido posible.

DIFERENCIAS EN CONSULTAS

Las diferencias significativas en las consultas se determinan comparando estos aspectos de cada consulta de ambos hosts:

Número de filas
El número de filas devueltas por la consulta debe ser el mismo. Esto se reporta como "filas faltantes" bajo "Diferencias de filas".
Datos de filas
Los datos de filas devueltos por la consulta deben ser los mismos. Todas las diferencias son significativas: espacios en blanco, precisión de coma flotante, etc.
Advertencias
La consulta no debe producir errores o advertencias, o debe producir los mismos errores o advertencias.
Tiempo de consulta
Una consulta rara vez se ejecuta con un tiempo constante, pero su tiempo de ejecución debe estar dentro del mismo orden de magnitud o ser menor.
Errores de consulta
Si una consulta causa un error SQL en un solo host, esto se reporta como "Errores de consulta". Dado que la consulta funciona en un host, su sintaxis es probablemente válida, y el error se debe a alguna condición única del otro host.
Errores SQL
Si una consulta causa un error SQL en ambos hosts, esto se reporta

REPORTE

A medida que pt-upgrade se ejecuta, imprime las consultas con diferencias tan pronto como puede (ver "CUÁNDO SE REPORTAN LAS CONSULTAS"). Para evitar que el reporte sea demasiado extenso, las consultas no se reportan individualmente sino que se agrupan por huella digital en clases. Una huella digital de consulta es la forma abstracta de una consulta, creada eliminando valores literales, normalizando espacios en blanco, etc. Por lo tanto, estas consultas pertenecen a la misma clase:

SELECT c FROM t WHERE id = 1
SELECT c FROM t WHERE id=5
select  c  from  t  where  id  =  9

La huella digital para esas consultas es:

select c from t where id=?

Cada clase de consulta puede tener hasta "--max-class-size" consultas únicas (1.000 por defecto). Hasta "--max-examples" se reportan para cada tipo de diferencia, por clase de consulta. Por el hecho de pertenecer a la misma clase, un ejemplo de la diferencia de una consulta suele ser representativo de todas las consultas con la misma diferencia, por lo que no es necesario reportar cada ejemplo. El número total de consultas en una clase con una diferencia particular se indica en el reporte.

EJEMPLO

#-----------------------------------------------------------------------
# Registros
#-----------------------------------------------------------------------
Archivo: /opt/mysql/slow.log
Tamaño: 59700
#-----------------------------------------------------------------------
# Hosts
#-----------------------------------------------------------------------
host1:
  DSN:       h=127.1,P=12345
  hostname:  dev1
  MySQL:     MySQL 5.1.68
host2:
  DSN:       h=127.1,P=12348
  hostname:  dev2
  MySQL:     MySQL 5.5.10
########################################################################
# Clase de consulta AAD020567F8398EE
########################################################################
Reportando clase porque tiene diferencias, pero aún no ha sido reportada.
Total de consultas      1
Consultas únicas     1
Consultas descartadas  0
insert into t (id, username) values(?+)
##
## Diferencias de advertencia: 1
##
-- 1.
   Código: 1265
  Nivel: Advertencia
Mensaje: Datos truncados para la columna 'username' en la fila 1
vs.
Sin advertencia 1265
INSERT INTO t (id, username) VALUES (NULL, 'long_username')
#-----------------------------------------------------------------------
# Estadísticas
#-----------------------------------------------------------------------
consultas_fallidas        0
no_select            0
consultas_filtradas      0
consultas_sin_diferencias      0
consultas_leídas          1
consultas_con_diferencias    1
consultas_con_errores   0

Las secciones "Clase de consulta <ID>" son las más importantes porque enumeran las "DIFERENCIAS DE CONSULTA". La primera parte de la sección enumera la razón por la cual se reportó la clase de consulta, seguida de los recuentos de consultas en la clase, seguida de la huella digital que define la clase.

El resto de la sección de la clase de consulta enumera las "DIFERENCIAS DE CONSULTA" que provocaron que la clase fuera reportada. Cada tipo de diferencia comienza con un encabezado de doble almohadilla que enumera el tipo y el número total de consultas en la clase con la diferencia. Luego se enumeran hasta "--max-examples", numerados "-- 1.", "--- 2.", etc. Cada ejemplo enumera la diferencia para el primer y segundo host (respectivo a la sección "Hosts"), seguido de la primera declaración SQL que reveló la diferencia.

CUÁNDO SE REPORTAN LAS CONSULTAS

Una clase de consulta se reporta tan pronto como cualquiera de las "DIFERENCIAS DE CONSULTA" o errores de consulta tiene "--max-examples". De lo contrario, todas las consultas con diferencias se reportan cuando la herramienta finaliza.

Por ejemplo, si se encuentran dos diferencias de tiempo de consulta para una clase de consulta, aún no se reporta. Una vez que se encuentra una tercera diferencia de tiempo de consulta, la clase de consulta se reporta, incluyendo cualquier otra diferencia que también se haya encontrado. Las consultas para la clase continuarán ejecutándose, pero la clase no se reportará nuevamente.

SALIDA

El "REPORTE" se imprime en STDOUT mientras la herramienta se ejecuta. Las advertencias internas, errores y "--progress" se imprimen en STDERR. Para mantenerlos separados, ejecute la herramienta así:

pt-upgrade ... 1>report 2>err &

Luego "tail -f err" mientras la herramienta se está ejecutando para seguir su "--progress".

ESTADO DE SALIDA

En general, la herramienta sale con cero si finalizó normalmente y no hubo advertencias o errores internos, y no se encontraron "DIFERENCIAS DE CONSULTA". De lo contrario, la herramienta sale con un valor distinto de cero con uno o más de los siguientes códigos:

  • 1

    Hubo demasiados errores o advertencias internas; ver STDERR. Ver también "--[no]continue-on-error".

  • 4

    Hubo "DIFERENCIAS DE CONSULTA"; ver el "REPORTE".

  • 8

    El tiempo límite de "--run-time" expiró; la herramienta no terminó de leer los registros o los resultados de referencia.

Otros códigos de salida indican que la herramienta se bloqueó o murió inesperadamente. El error que causó esto debería haberse impreso en STDERR.

Para verificar un código de salida particular, realice una operación lógica "AND" ("&") del estado de salida final con el código de salida. Por ejemplo, el estado de salida 5 implica los códigos 1 y 4 porque "5 & 1" es verdadero, y "5 & 4" es verdadero.

OPCIONES

Esta herramienta acepta argumentos adicionales de línea de comandos. Consulte la "SINOPSIS" y la información de uso para obtener detalles.

--ask-pass
Solicitar una contraseña al conectarse a MySQL.
--charset
forma corta: -A; tipo: string

Juego de caracteres por defecto. Si el valor es utf8, establece el binmode de Perl en STDOUT a utf8, pasa la opción mysql_enable_utf8 a DBD::mysql y ejecuta SET NAMES UTF8 después de conectarse a MySQL. Cualquier otro valor establece el binmode en STDOUT sin la capa utf8 y ejecuta SET NAMES después de conectarse a MySQL.

--config
tipo: Array

Leer esta lista de archivos de configuración separados por comas; si se especifica, esta debe ser la primera opción en la línea de comandos.

--[no]continue-on-error
por defecto: yes

Continuar analizando incluso si hay un error. La herramienta no continuará para siempre: se detiene después de 100 errores, en cuyo caso probablemente haya un error en la herramienta o la entrada no es válida.

--[no]create-upgrade-table
por defecto: yes

Crear la base de datos y tabla "--upgrade-table".

--daemonize
Bifurcar al fondo y desvincularse de la shell. Solo sistemas operativos POSIX.
--database
forma corta: -D; tipo: string

Base de datos por defecto al conectarse a MySQL.

--defaults-file
forma corta: -F; tipo: string

Leer solo las opciones de MySQL del archivo dado. Debe proporcionar una ruta absoluta.

--[no]disable-query-cache
por defecto: yes

"SET SESSION query_cache_type = OFF" para deshabilitar la caché de consultas.

--dry-run
Ejecutar pero no comparar ni ejecutar consultas. Esto es útil para verificar las opciones de la línea de comandos, las conexiones a MySQL y el análisis de registros o resultados de referencia.
--filter
tipo: string

Permitir eventos para los cuales este código Perl devuelve verdadero.

Ver la misma opción en la documentación de pt-query-digest.

--help
Mostrar ayuda y salir.
--host
forma corta: -h; tipo: string

Nombre de host o IP de MySQL.

--ignore-warnings
tipo: Hash

Ignorar estos códigos de advertencia de MySQL al comparar advertencias.

--log
tipo: string

Imprimir STDOUT y STDERR en este archivo cuando se demoniza. Esta opción solo tiene efecto cuando se especifica "--daemonize". El archivo se crea si no existe, de lo contrario la salida se agrega a él.

--max-class-size
tipo: int; por defecto: 1000

Número máximo de consultas únicas en cada clase de consulta. Ver "REPORTE".

--max-examples
tipo: int; por defecto: 3

Número máximo de ejemplos a listar para cada "DIFERENCIAS DE CONSULTA". Una clase de consulta se reporta tan pronto como se encuentran esta cantidad de ejemplos para cualquier tipo de diferencia de consulta.

--password
forma corta: -p; tipo: string

Contraseña de MySQL para el "--user".

--pid
tipo: string

Crear el archivo PID dado. La herramienta no se iniciará si el archivo PID ya existe y el PID que contiene es diferente del PID actual. Sin embargo, si el archivo PID existe y el PID que contiene ya no se está ejecutando, la herramienta sobrescribirá el archivo PID con el PID actual. El archivo PID se elimina automáticamente cuando la herramienta sale.

--port
forma corta: -P; tipo: int

Número de puerto de MySQL.

--progress
tipo: array; por defecto: time,30

Imprimir informes de progreso en STDERR. La herramienta imprime informes de progreso al leer registros o resultados de referencia, estimando aproximadamente cuánto tiempo falta para que finalice.

El valor es una lista separada por comas con dos partes. La primera parte puede ser porcentaje, tiempo o iteraciones; la segunda parte especifica con qué frecuencia se debe imprimir una actualización, en porcentaje, segundos o número de iteraciones.

--[no]read-only
por defecto: yes

Ejecutar solo "SELECT"

--[no]create-upgrade-table

Create the upgrade table if it does not exist. See "--upgrade-table".

--defaults-file
short form: -f; type: string

Read MySQL options from the specified file. Usually "/etc/my.cnf".

--dry-run
type: boolean; default: no

Print the queries that would be executed, but do not run them.

--help
Show help and exit.
--host-check
type: boolean; default: yes

Check if the specified hosts exist and are available.

--init-command
type: string

A command to execute when connecting to MySQL. Useful for setting session variables, such as character set.

--[no]read-only
type: boolean; default: yes

Default mode is read-only. This means that the tool will not execute any queries that modify data, such as "DROP", "DELETE", "UPDATE", "SET".

If "--no-read-only" is specified, all queries are executed: "DROP", "DELETE", "UPDATE", etc. Even when running in default read-only mode, you should use a MySQL user with only "SELECT" privileges to insure against bugs in the tool.

--report
type: Hash; default: hosts, logs, queries, stats

Print these sections of the "REPORT".

--run-time
type: time

How long to run before exiting. By default, the tool runs until it finishes reading the logs or reference results.

--save-results
type: string

Save reference results to this directory. This option works only when one DSN is specified, to generate reference results. When comparing a host to reference results, specify its results directory instead of its DSN. See the second example in the "SYNOPSIS".

Reference results can use a lot of disk space.

--set-vars
type: Array

Set the MySQL variables in this comma-separated list of "variable=value" pairs.

By default, the tool sets:

wait_timeout=10000

Variables specified on the command line override these defaults. For example, specifying "--set-vars wait_timeout=500" overrides the default value of 10000.

The tool prints a warning and continues if a variable cannot be set.

--socket
short form: -S; type: string

Socket file to use for connection.

--type
type: string; default: slowlog

Type of log files. Valid types are:

VALUE    LOG TYPE
=======  ===========================================
slowlog  MySQL slow log
genlog   MySQL general log
binlog   MySQL binary log (converted by mysqlbinlog)
tcpdump  TCP dump file generated by tcpdump command
rawlog   Custom log with one SQL statement per line
--upgrade-table
type: string; default: percona_schema.pt_upgrade

Use this table to clear warnings. To clear all warnings from previous queries, pt-upgrade executes "SELECT * FROM --upgrade-table LIMIT 1" on each host before executing each query.

The table must be database-qualified. The database and table are automatically created unless "--no-create-upgrade-table" is specified (see "--[no]create-upgrade-table"). If the table does not already exist, it is created with this definition:

CREATE TABLE pt_upgrade (
  id INT NOT NULL PRIMARY KEY
)
--user
short form: -u; type: string

MySQL user if not the current system user.

--version
Show version and exit.
--[no]version-check
default: yes

Check for the latest version of Percona Toolkit, MySQL, and other programs.

This is a standard "check for updates automatically" feature, with two additional features. First, the tool checks its own version and also the versions of the following software: operating system, Percona Monitoring and Management (PMM), MySQL, Perl, MySQL driver for Perl (DBD::mysql), and Percona Toolkit. Second, it checks for and warns about versions with known problems. For example, MySQL 5.5.25 had a critical bug and was re-released as 5.5.25a.

A secure connection to Percona’s Version Check database server is done to perform these checks. Each request is logged by the server, including software version numbers and unique ID of the checked system. The ID is generated by the Percona Toolkit installation script or when the Version Check database call is done for the first time.

Any updates or known problems are printed to STDOUT before the tool’s normal output. This feature should never interfere with the normal operation of the tool.

For more information, visit https://www.percona.com/version-check.

--watch-server
type: string

Parse only events for this IP:port for "--type" tcpdump. All other IP addresses are ignored. If not specified, pt-upgrade watches all servers by looking for any IP address using port 3306 or "mysql". If you’re watching a server with a non-standard port, this won’t work, so you must specify the IP address and port to watch.

If you want to watch a mix of servers, some running on standard port 3306 and some running on non-standard ports, you need to create separate tcpdump outputs for the non-standard port servers and then specify this option for each. At present pt-upgrade cannot auto-detect servers on port 3306 and also be told to watch a server on a non-standard port.

DSN OPTIONS

These DSN options are used to create a DSN. Each option is given like "option=value". The options are case-sensitive, so P and p are not the same option. There cannot be whitespace before or after the "=", and if the value contains whitespace it must be quoted. DSN options are comma-separated. See the percona-toolkit manpage for full details.

  • A

    dsn: charset; copy: yes

    Default character set.

  • D

    dsn: database; copy: yes

    Default database.

  • F

    dsn: mysql_read_default_file; copy: yes

    Only read default options from the given file

  • h

    dsn: host; copy: yes

    Connect to host.

  • L

    copy: yes

    Explicitly enable LOAD DATA LOCAL INFILE.

    For some reason, some vendors compile libmysql without the --enable-local-infile option, which disables the statement. This can lead to weird situations, like the server allowing LOCAL INFILE, but the client throwing exceptions if it's used.

    However, as long as the server allows LOAD DATA, clients can easily re-enable it; See https://dev.mysql.com/doc/refman/en/load-data-local-security.html and http://search.cpan.org/~capttofu/DBD-mysql/lib/DBD/mysql.pm. This option does exactly that.

    Although we’ve not found a case where turning this option leads to errors or differing behavior, to be on the safe side, this option is not on by default.

  • p

    dsn: password; copy: yes

    Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

  • P

    dsn: port; copy: yes

    Port number to use for connection.

  • S

    dsn: mysql_socket; copy: yes

    Socket file to use for connection.

  • u

    dsn: user; copy: yes

    User for login if not current user.

  • s

    dsn: mysql_ssl; copy: yes

    Create SSL connection

ENVIRONMENT

The environment variable "PTDEBUG" enables verbose debugging output to STDERR. To enable debugging and capture all output to a file, run the tool like:

PTDEBUG=1 pt-upgrade ... > FILE 2>&1

Be careful: debugging output is voluminous and can generate several megabytes of output.

ATTENTION

Using <PTDEBUG> might expose passwords. When debug is enabled, all command line parameters are shown in the output.

SYSTEM REQUIREMENTS

You need Perl, DBI, DBD::mysql, and some core packages that ought to be installed in any reasonably new version of Perl.
