NOMBRE

pthread_cond_init, pthread_cond_signal, pthread_cond_broadcast, pthread_cond_wait, pthread_cond_timedwait, pthread_cond_destroy - operaciones sobre condiciones

SINOPSIS

#include <pthread.h>
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
int pthread_cond_init(pthread_cond_t *cond,
                      pthread_condattr_t *cond_attr);
int pthread_cond_signal(pthread_cond_t *cond);
int pthread_cond_broadcast(pthread_cond_t *cond);
int pthread_cond_wait(pthread_cond_t *cond, pthread_mutex_t *mutex);
int pthread_cond_timedwait(pthread_cond_t *cond, pthread_mutex_t *mutex,
                      const struct timespec *abstime);
int pthread_cond_destroy(pthread_cond_t *cond);

DESCRIPCIÓN

Una condición (abreviatura de "variable de condición") es un dispositivo de sincronización que permite a los hilos suspender su ejecución y ceder los procesadores hasta que algún predicado sobre datos compartidos se cumpla. Las operaciones básicas sobre condiciones son: señalar la condición (cuando el predicado se vuelve verdadero) y esperar la condición, suspendiendo la ejecución del hilo hasta que otro hilo señale la condición.

Una variable de condición siempre debe estar asociada a un mutex, para evitar la condición de carrera donde un hilo se prepara para esperar en una variable de condición y otro hilo señala la condición justo antes de que el primer hilo realmente espere en ella.

pthread_cond_init() inicializa la variable de condición cond, utilizando los atributos de condición especificados en cond_attr, o atributos predeterminados si cond_attr es NULL. La implementación de LinuxThreads no soporta atributos para condiciones, por lo que el parámetro cond_attr es efectivamente ignorado.

Las variables de tipo pthread_cond_t también pueden ser inicializadas estáticamente, utilizando la constante PTHREAD_COND_INITIALIZER.

pthread_cond_signal() reinicia uno de los hilos que están esperando en la variable de condición cond. Si no hay hilos esperando en cond, no sucede nada. Si varios hilos están esperando en cond, se reinicia exactamente uno, pero no se especifica cuál.

pthread_cond_broadcast() reinicia todos los hilos que están esperando en la variable de condición cond. No sucede nada si no hay hilos esperando en cond.

pthread_cond_wait() desbloquea atómicamente el mutex (según pthread_unlock_mutex()) y espera a que la variable de condición cond sea señalada. La ejecución del hilo se suspende y no consume ningún tiempo de CPU hasta que la variable de condición sea señalada. El mutex debe estar bloqueado por el hilo que llama al entrar en pthread_cond_wait(). Antes de devolver el control al hilo que llama, pthread_cond_wait() vuelve a adquirir el mutex (según pthread_mutex_lock()).

El desbloqueo del mutex y la espera en la variable de condición se realizan de forma atómica. Por lo tanto, si todos los hilos adquieren siempre el mutex antes de señalar la condición, esto garantiza que la condición no puede ser señalada (y por lo tanto ignorada) entre el momento en que un hilo bloquea el mutex y el momento en que espera en la variable de condición. Ver CONSIDERACIONES más abajo.

pthread_cond_timedwait() desbloquea atómicamente el mutex y espera en cond, como lo hace pthread_cond_wait(), pero también limita la duración de la espera. Si cond no ha sido señalada dentro del tiempo especificado por abstime, el mutex mutex se vuelve a adquirir y pthread_cond_timedwait() devuelve el error ETIMEDOUT. El parámetro abstime especifica una hora absoluta, con el mismo origen que time(2) y gettimeofday(2): un abstime de 0 corresponde a las 00:00:00 GMT del 1 de enero de 1970.

pthread_cond_destroy() destruye una variable de condición, liberando los recursos que pueda mantener. Ningún hilo debe estar esperando en la variable de condición al entrar en pthread_cond_destroy(). En la implementación de LinuxThreads, no se asocian recursos con las variables de condición, por lo que pthread_cond_destroy() en realidad no hace nada más que verificar que la condición no tiene hilos esperando.

CANCELACIÓN

pthread_cond_wait() y pthread_cond_timedwait() son puntos de cancelación. Si un hilo es cancelado mientras está suspendido en una de estas funciones, el hilo reanuda inmediatamente su ejecución, luego vuelve a bloquear el mutex argumento de pthread_cond_wait() y pthread_cond_timedwait(), y finalmente ejecuta la cancelación. Consecuentemente, los manejadores de limpieza tienen la garantía de que mutex está bloqueado cuando se les llama.

SEGURIDAD DE SEÑALES ASÍNCRONAS

Las funciones de condición no son seguras para señales asíncronas y no deben ser llamadas desde un manejador de señales. En particular, llamar a pthread_cond_signal() o pthread_cond_broadcast() desde un manejador de señales puede causar un interbloqueo en el hilo que llama.

VALOR DE RETORNO

Todas las funciones de variables de condición devuelven 0 en caso de éxito y un código de error distinto de cero en caso de error.

ERRORES

pthread_cond_init(), pthread_cond_signal(), pthread_cond_broadcast() y pthread_cond_wait() nunca devuelven un código de error.

La función pthread_cond_timedwait() devuelve los siguientes códigos de error en caso de error:

ETIMEDOUT
La variable de condición no fue señalada hasta el tiempo de espera especificado por abstime .

La función pthread_cond_destroy() devuelve el siguiente código de error en caso de error:

EBUSY
Algunos hilos están esperando actualmente en cond .

VER TAMBIÉN

pthread_condattr_init(3), pthread_mutex_lock(3), pthread_mutex_unlock(3), gettimeofday(2), nanosleep(2).

CONSIDERACIONES

La implementación de las funciones proporcionadas hasta glibc 2.25 utilizaba un bloqueo de datos interno. Este bloqueo no soportaba la herencia de prioridad y estaba sujeto a inversión de prioridad ilimitada, visible en un sistema de tiempo real.

Después de la reescritura de la implementación en glibc 2.25, el uso del bloqueo interno cambió. El bloqueo interno siempre es adquirido por las funciones de señalización pthread_cond_signal() y pthread_cond_broadcast(). La función de espera adquiere el bloqueo si el proceso en espera fue interrumpido. La interrupción puede ser causada, por ejemplo, por un tiempo de espera especificado, y se denota por el valor de error ETIMEDOUTA, o por una señal recibida, que se denota por el valor de error EINTR.

EJEMPLO

Considere dos variables compartidas x e y , protegidas por el mutex mut, y una variable de condición cond que debe ser señalada siempre que x sea mayor que y.

int x,y;
pthread_mutex_t mut = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

Esperar hasta que x sea mayor que y se realiza de la siguiente manera:

pthread_mutex_lock(&mut);
while (x <= y) {
        pthread_cond_wait(&cond, &mut);
}
/* operar con x e y */
pthread_mutex_unlock(&mut);

pthread_mutex_lock(&mut);
/* modificar x e y */
if (x > y) pthread_cond_broadcast(&cond);
pthread_mutex_unlock(&mut);

pthread_cond_timedwait(3) — Arch manual pages

NAME

pthread_cond_timedwait, pthread_cond_wait - wait on a condition

SYNOPSIS

#include <pthread.h>

int pthread_cond_timedwait(pthread_cond_t *restrict cond,
    pthread_mutex_t *restrict mutex, const struct timespec *restrict abstime);
int pthread_cond_wait(pthread_cond_t *restrict cond,
    pthread_mutex_t *restrict mutex);

DESCRIPTION

The pthread_cond_timedwait() and pthread_cond_wait() functions atomically release the mutex (as described in pthread_mutex_unlock(3)) and cause the calling thread to block until the condition variable cond is signaled. The calling thread must have mutex locked before calling these functions; the effect is as if pthread_mutex_unlock() is called and then the thread blocks. Upon successful return, the thread reenables the mutex (as if by calling pthread_mutex_lock() again) and returns. The mutex is reacquired before the function returns to the caller.

The pthread_cond_timedwait() function is identical to pthread_cond_wait(), except that it allows for a timeout facility. If the timeout expires before the condition variable is signaled, pthread_cond_timedwait() returns.

The abstime argument to pthread_cond_timedwait() points to a structure that specifies the ceiling of the time for which the thread is to wait. The structure is of type struct timespec, which has at least two members: tv_sec for the seconds and tv_nsec for the nanoseconds.

The value of abstime is interpreted as an absolute time.

The condition variable cond and the mutex mutex must be associated with the same thread. If they are not, the behavior is undefined.

If the calling thread is canceled, it will call pthread_mutex_unlock() on the mutex.

CANCELLATION

Threads may be cancelled at any time while blocked in these functions.

If a thread is canceled while blocked in pthread_cond_timedwait() or pthread_cond_wait(), it will call pthread_mutex_unlock() on the mutex before being canceled. If the thread is canceled while blocked in pthread_cond_timedwait(), it will also call the registered cleanup handler (see pthread_cleanup_push(3)).

ASYNC-SIGNAL SAFETY

None of these functions are async-signal-safe.

RETURN VALUE

On success, these functions return 0 and the thread has reenabled the mutex. Otherwise, an error number will be returned to indicate the error.

ERRORS

pthread_cond_timedwait() and pthread_cond_wait() can fail if:

EINVAL
The value specified by cond or mutex is invalid.
ETIMEDOUT
The timeout expired for pthread_cond_timedwait().
ECANCELED
The thread was canceled.

SEE ALSO

pthread_cond_broadcast(3), pthread_cond_destroy(3), pthread_cond_init(3), pthread_cond_signal(3), pthread_mutex_lock(3), pthread_mutex_unlock(3), pthread_cleanup_pop(3), pthread_create(3), pthread_join(3), futex(2), pthreads(7)

CAVEATS

The implementation of pthread_cond_wait() can be significantly more efficient than calling pthread_cond_signal(). In doubt, use pthread_cond_broadcast().

To wait for x to become greater than y with a timeout of 5 seconds, do:

struct timeval now;
struct timespec timeout;
int retcode;
pthread_mutex_lock(&mut);
gettimeofday(&now);
timeout.tv_sec = now.tv_sec + 5;
timeout.tv_nsec = now.tv_usec * 1000;
retcode = 0;
while (x <= y && retcode != ETIMEDOUT) {
        retcode = pthread_cond_timedwait(&cond, &mut, &timeout);
}
if (retcode == ETIMEDOUT) {
        /* timeout occurred */
} else {
        /* operate on x and y */
}
pthread_mutex_unlock(&mut);

EXAMPLE

The following example waits for a condition signaled by another thread. The condition is that the shared variable x is no longer less than or equal to the shared variable y.

#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define NUM_LOOPS 5
#define MAX_SLEEP 2

pthread_mutex_t mut = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
int x = 0;
int y = 10;
int done = 0;

void *
waiter(void *arg)
{
    int i;
    struct timespec ts;
    int ret;

    pthread_mutex_lock(&mut);

    for (i = 0; i < NUM_LOOPS; ++i) {
        /* Wait for x to be greater than y. */
        while (x <= y && !done) {
            /* Use current time + 1 second for timeout */
            clock_gettime(CLOCK_REALTIME, &ts);
            ts.tv_sec += 1;

            ret = pthread_cond_timedwait(&cond, &mut, &ts);
            if (ret == ETIMEDOUT) {
                printf("waiter: Timeout occurred\n");
            } else if (ret != 0) {
                perror("waiter: pthread_cond_timedwait");
                exit(EXIT_FAILURE);
            } else {
                printf("waiter: Condition met (x=%d, y=%d)\n", x, y);
            }
        }
        if (done) break;
        printf("waiter: operating on x and y\n");
        /* Operate on x and y */
        x += 5;
    }

    done = 1;
    pthread_cond_signal(&cond); /* Signal the other thread we are done */
    pthread_mutex_unlock(&mut);

    return NULL;
}

void *
signaler(void *arg)
{
    int i;
    int ret;

    sleep(1); /* Give waiter a chance to start waiting */

    pthread_mutex_lock(&mut);
    for (i = 0; i < NUM_LOOPS; ++i) {
        while (x <= y && !done) {
            printf("signaler: Incrementing y\n");
            y += 10;
            ret = pthread_cond_signal(&cond);
            if (ret != 0) {
                perror("signaler: pthread_cond_signal");
                exit(EXIT_FAILURE);
            }
        }
        if (done) break;
        /*
         * In a real application, you would likely have a condition
         * that is more complex than simply incrementing y.
         * Here, we just signal to wake up the waiter.
         */
        printf("signaler: Signaling condition\n");
        ret = pthread_cond_signal(&cond);
        if (ret != 0) {
            perror("signaler: pthread_cond_signal");
            exit(EXIT_FAILURE);
        }
        /* Make sure waiter has a chance to run */
        pthread_mutex_unlock(&mut);
        usleep((rand() % MAX_SLEEP) * 100000);
        pthread_mutex_lock(&mut);
    }

    printf("signaler: Done signaling\n");
    pthread_mutex_unlock(&mut);

    return NULL;
}

int
main()
{
    pthread_t tid_waiter, tid_signaler;
    int ret;

    srand(time(NULL));

    ret = pthread_create(&tid_waiter, NULL, waiter, NULL);
    if (ret != 0) {
        perror("main: pthread_create waiter");
        exit(EXIT_FAILURE);
    }

    ret = pthread_create(&tid_signaler, NULL, signaler, NULL);
    if (ret != 0) {
        perror("main: pthread_create signaler");
        exit(EXIT_FAILURE);
    }

    pthread_join(tid_waiter, NULL);
    pthread_join(tid_signaler, NULL);

    printf("main: x = %d, y = %d\n", x, y);

    pthread_mutex_destroy(&mut);
    pthread_cond_destroy(&cond);

    return 0;
}
