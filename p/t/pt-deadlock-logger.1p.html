NOMBRE

pt-deadlock-logger - Registra interbloqueos de MySQL.

SINOPSIS

Uso: pt-deadlock-logger [OPCIONES] DSN

pt-deadlock-logger registra información sobre interbloqueos de MySQL en el DSN dado. La información se imprime en "STDOUT", y también se puede guardar en una tabla especificando "--dest". La herramienta se ejecuta indefinidamente a menos que se especifique "--run-time" o "--iterations".

Imprimir interbloqueos en host1:

pt-deadlock-logger h=host1

Imprimir interbloqueos en host1 una vez y luego salir:

pt-deadlock-logger h=host1 --iterations 1

Guardar interbloqueos en host1 en percona_schema.deadlocks en host2:

pt-deadlock-logger h=host1 --dest h=host2,D=percona_schema,t=deadlocks

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien testeado, pero todas las herramientas de bases de datos pueden suponer un riesgo para el sistema y el servidor de base de datos. Antes de usar esta herramienta, por favor:

  • Lea la documentación de la herramienta
  • Revise los "BUGS" conocidos de la herramienta
  • Pruebe la herramienta en un servidor no productivo
  • Haga una copia de seguridad de su servidor de producción y verifique las copias de seguridad

DESCRIPCIÓN

pt-deadlock-logger imprime información sobre interbloqueos de MySQL consultando y analizando "SHOW ENGINE INNODB STATUS". Cuando ocurre un nuevo interbloqueo, se imprime en "STDOUT" y, si se especifica, se guarda en "--dest".

Solo se imprimen los interbloqueos nuevos. Se crea una huella digital para cada interbloqueo utilizando los valores de servidor, ts e hilo del interbloqueo (incluso si estas columnas no se especifican con "--columns"). Se imprime un interbloqueo si su huella digital es diferente a la huella digital del último interbloqueo.

La sentencia "--dest" utiliza "INSERT IGNORE" para eliminar interbloqueos duplicados, por lo que cada interbloqueo se guarda para cada "--iterations".

SALIDA

Los nuevos interbloqueos se imprimen en "STDOUT", a menos que se especifique "--quiet". Los errores y advertencias se imprimen en "STDERR".

Ver también "--columns" y "--tab".

CONSIDERACIONES Y DETALLES DE INNODB

La salida de InnoDB es difícil de analizar y a veces no hay forma de hacerlo correctamente.

A veces, no toda la información (por ejemplo, el nombre de usuario o la dirección IP) se incluye en la información del interbloqueo. En este caso, la herramienta no tiene nada que poner en esas columnas. También puede ocurrir que la salida del interbloqueo sea tan larga (debido a que había muchos bloqueos) que se trunca por completo.

Aunque generalmente hay dos transacciones involucradas en un interbloqueo, hay más bloqueos que eso; como mínimo, se necesita un bloqueo más que transacciones para crear un ciclo en el grafo de espera. pt-deadlock-logger imprime las transacciones (siempre dos en la salida de InnoDB, incluso cuando hay más transacciones en el grafo de espera) y rellena los bloqueos. Prefiere el bloqueo esperado sobre el mantenido al elegir la información del bloqueo a imprimir, pero puedes deducir el resto con un poco de reflexión. Si ves un bloqueo esperado y uno mantenido, estás mirando el mismo bloqueo, por lo que por supuesto preferirías ver ambos bloqueos esperados y obtener más información. Si los dos bloqueos esperados no están en la misma tabla, más de dos transacciones estuvieron involucradas en el interbloqueo.

Finalmente, ten en cuenta que, como InnoDB no entrecomilla los nombres de usuario con espacios, la herramienta generalmente informará incorrectamente la segunda palabra de estos nombres de usuario como el nombre de host.

OPCIONES

Esta herramienta acepta argumentos de línea de comandos adicionales. Consulte la "SINOPSIS" y la información de uso para obtener detalles.

--ask-pass
Solicita una contraseña al conectarse a MySQL.
--charset
forma corta: -A; tipo: string

Conjunto de caracteres predeterminado. Si el valor es utf8, establece el modo binario de Perl en STDOUT a utf8, pasa la opción mysql_enable_utf8 a DBD::mysql y ejecuta SET NAMES UTF8 después de conectarse a MySQL. Cualquier otro valor establece el modo binario en STDOUT sin la capa utf8 y ejecuta SET NAMES después de conectarse a MySQL.

--clear-deadlocks
tipo: string

Utiliza esta tabla para crear un pequeño interbloqueo. Esto normalmente tiene el efecto de eliminar un interbloqueo enorme, que de lo contrario consume toda la salida de "SHOW INNODB STATUS". La tabla no debe existir. pt-deadlock-logger la creará con la siguiente estructura:

CREATE TABLE percona_schema.clear_deadlocks (
  a INT PRIMARY KEY
) ENGINE=InnoDB

Después de crear la tabla y provocar un pequeño interbloqueo, la herramienta eliminará la tabla nuevamente.

--columns
tipo: Array; predeterminado: server, ts, thread, txn_id, txn_time, user, hostname, ip, db, tbl, idx, lock_type, lock_mode, wait_hold, victim, query

Las columnas son:

server
El servidor (fuente) en el que ocurrió el interbloqueo. Esto podría ser útil si estás rastreando interbloqueos en muchos servidores.
ts
La fecha y hora del último interbloqueo detectado.
thread
El número de hilo de MySQL, que es el mismo que el ID de conexión en SHOW FULL PROCESSLIST.
txn_id
El ID de transacción de InnoDB, que InnoDB expresa como dos enteros sin signo. La herramienta los multiplica para obtener un solo número.
txn_time
Cuánto tiempo estuvo activa la transacción cuando ocurrió el interbloqueo.
user
El nombre de usuario de la base de datos de la conexión.
hostname
El host de la conexión.
ip
La dirección IP de la conexión. Si especificas "--numeric-ip", esta se convierte en un entero sin signo.
db
La base de datos en la que ocurrió el interbloqueo.
tbl
La tabla en la que ocurrió el interbloqueo.
idx
El índice en el que ocurrió el interbloqueo.
lock_type
El tipo de bloqueo que la transacción mantenía sobre el bloqueo que causó el interbloqueo.
lock_mode
El modo de bloqueo del bloqueo que causó el interbloqueo.
wait_hold
Si la transacción estaba esperando el bloqueo o manteniendo el bloqueo. Por lo general, verás los dos bloqueos esperados.
victim
Si la transacción fue seleccionada como víctima del interbloqueo y se deshizo.
query
La consulta que causó el interbloqueo.
--config
tipo: Array

Lee esta lista de archivos de configuración separados por comas; si se especifica, esta debe ser la primera opción en la línea de comandos.

--create-dest-table
Crea la tabla especificada por "--dest".

Normalmente se espera que la tabla "--dest" ya exista. Esta opción hace que pt-deadlock-logger cree la tabla automáticamente utilizando la estructura de tabla sugerida.

--daemonize
Se bifurca en segundo plano y se desvincula del shell. Solo en sistemas operativos POSIX.
--database
forma corta: -D; tipo: string

NAME

pt-deadlock-logger - Percona Toolkit's deadlock logger for MySQL

SYNOPSIS

pt-deadlock-logger [OPTIONS] [DSN]

RISKS

This tool requires SHOW DATABASES, SHOW VIEW, and PROCESS privileges. It also requires SELECT privileges on all tables for which you want to log deadlocks. Granting these privileges to a user could pose a security risk.

The tool writes output to a file. If the file is not properly secured, this could also pose a security risk.

Percona assumes no responsibility for any negative consequences resulting from the use of this tool. Please read and understand the tool's documentation before using it.

DESCRIPTION

Percona Toolkit's pt-deadlock-logger is a Perl script that monitors MySQL for deadlocks and logs them to a file. It accomplishes this by periodically querying SHOW ENGINE INNODB STATUS and parsing the output for deadlock information. If a deadlock is detected, the script logs the event to a specified file.

Deadlocks are a common problem in transactional database systems like MySQL. They occur when two or more transactions are waiting for each other to release locks, creating a circular dependency that prevents any of the transactions from completing. pt-deadlock-logger helps you identify and diagnose these deadlocks by providing detailed logs of the events.

OUTPUT

The tool logs deadlocks to a file specified by the --log-file option. The log file contains information about each deadlock, including:

  • The time of the deadlock.
  • The transactions involved.
  • The queries being executed by each transaction.
  • The locks held and requested by each transaction.
  • The error message from MySQL indicating the deadlock.

The output format is designed to be easily readable and parseable.

INNODB CAVEATS AND DETAILS

This tool is specifically designed to log deadlocks reported by the InnoDB storage engine. It relies on parsing the output of SHOW ENGINE INNODB STATUS. Therefore, it only works for deadlocks that occur within InnoDB transactions.

The tool assumes that deadlocks are reported in the standard format within the LATEST DETECTED DEADLOCK section of the SHOW ENGINE INNODB STATUS output. Changes to this output format in future MySQL versions could potentially break the tool.

OPTIONS

The tool supports a wide range of options to configure its behavior, including:

--log-file
Specifies the file to which deadlock information should be logged.
--interval
The interval in seconds between checks for deadlocks.
--daemonize
Run the tool as a daemon in the background.
--pid-file
Specifies a file to store the process ID when running as a daemon.
--help
Show help message and exit.
--version
Show program version and exit.

For a complete list of options, please refer to the tool's documentation or run pt-deadlock-logger --help.

DSN OPTIONS

The tool accepts standard DSN (Data Source Name) options to connect to the MySQL server. These include:

--host, -h
The host to connect to.
--port, -P
The port number to use.
--user, -u
The user to connect with.
--password, -p
The password to use. If this is omitted, the tool will prompt for it.

Alternatively, you can provide a DSN string like DSN=dbi:mysql:database=test;host=localhost.

ENVIRONMENT

The tool respects the following environment variables:

MYSQL_HOST, MYSQL_PORT, MYSQL_USER, MYSQL_PASSWORD
Can be used to specify connection parameters.

ATTENTION

This tool should be run on a system that has network access to the MySQL server you want to monitor. Ensure that the user account used by the tool has the necessary privileges.

SYSTEM REQUIREMENTS

Perl 5.8 or later. The DBI and DBD::mysql modules.
