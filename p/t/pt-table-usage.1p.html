NOMBRE

pt-table-usage - Analiza cómo las consultas utilizan las tablas.

SINOPSIS

Uso: pt-table-usage [OPCIONES] [ARCHIVOS]

pt-table-usage lee consultas de un log y analiza cómo utilizan las tablas. Si no se especifica ningún ARCHIVO, lee desde la entrada estándar (STDIN). Imprime un informe para cada consulta.

DESCRIPCIÓN

pt-table-usage lee consultas de un log y analiza cómo utilizan las tablas. El log debe estar en formato de log de consultas lentas de MySQL.

El uso de tablas es más que una simple indicación de qué tablas lee o escribe la consulta. También indica el flujo de datos: entrada y salida de datos. La herramienta determina el flujo de datos por los contextos en los que aparecen las tablas. Una sola consulta puede usar una tabla en varios contextos diferentes simultáneamente. La salida de la herramienta lista cada contexto para cada tabla. Esta lista CONTEXTO-TABLA indica cómo fluyen los datos entre las tablas. La sección "SALIDA" enumera los contextos posibles y describe cómo leer un informe de uso de tablas.

La herramienta analiza el flujo de datos hasta el nivel de columnas individuales, por lo que es útil si las columnas se identifican de forma inequívoca en la consulta. Si una consulta utiliza solo una tabla, entonces todas las columnas deben ser de esa tabla, y no hay dificultad. Pero si una consulta utiliza varias tablas y los nombres de las columnas no están calificados por la tabla, entonces es necesario usar "EXPLAIN EXTENDED", seguido de "SHOW WARNINGS", para determinar a qué tablas pertenecen las columnas.

Si la herramienta no conoce la base de datos predeterminada de la consulta, lo que puede ocurrir cuando la base de datos no se imprime en el log, entonces "EXPLAIN EXTENDED" puede fallar. En este caso, puede especificar una base de datos predeterminada con "--database". También puede usar la opción "--create-table-definitions" para ayudar a resolver ambigüedades.

SALIDA

La herramienta imprime un informe de uso para cada tabla en cada consulta, similar a lo siguiente:

Query_id: 0x1CD27577D202A339.1
UPDATE t1
SELECT DUAL
JOIN t1
JOIN t2
WHERE t1
Query_id: 0x1CD27577D202A339.2
UPDATE t2
SELECT DUAL
JOIN t1
JOIN t2
WHERE t1

La primera línea contiene el ID de la consulta, que por defecto es el mismo que el que se muestra en los informes de pt-query-digest. Es una suma MD5 de la "huella digital" de la consulta, que es lo que queda después de eliminar literales, colapsar espacios en blanco y una variedad de otras transformaciones. El ID de la consulta tiene dos partes separadas por un punto: el ID de la consulta y el número de tabla. Si desea utilizar un valor diferente para identificar la consulta, puede especificar la opción "--id-attribute".

El ejemplo anterior muestra dos párrafos para una sola consulta, no dos consultas. Tenga en cuenta que el ID de la consulta es idéntico para ambas, pero el número de tabla es diferente. El número de tabla se incrementa en 1 por cada tabla que la consulta actualiza. Solo las consultas UPDATE de varias tablas pueden actualizar varias tablas con una sola consulta, por lo que el número de tabla es 1 para todos los demás tipos de consultas. (La herramienta no admite consultas DELETE de varias tablas). El ejemplo de salida anterior proviene de esta consulta:

UPDATE t1 AS a JOIN t2 AS b USING (id)
SET a.foo="bar", b.foo="bat"
WHERE a.id=1;

La cláusula "SET" indica que la consulta actualiza dos tablas: "a" alias "t1", y "b" alias "t2".

Después de la primera línea, la herramienta imprime un número variable de líneas CONTEXTO-TABLA. Los contextos posibles son los siguientes:

  • SELECT

    SELECT significa que la consulta recupera datos de la tabla por una de dos razones. La primera es para ser devuelta al usuario como parte de un conjunto de resultados. Solo las consultas SELECT devuelven conjuntos de resultados, por lo que el informe siempre muestra un contexto SELECT para las consultas SELECT.

    El segundo caso es cuando los datos fluyen a otra tabla como parte de un INSERT o UPDATE. Por ejemplo, la consulta UPDATE en el ejemplo anterior tiene el uso:

    SELECT DUAL

    Esto se refiere a:

    SET a.foo="bar", b.foo="bat"

    La herramienta usa DUAL para cualquier valor que no se origine en una tabla, en este caso los valores literales "bar" y "bat". Si esa cláusula "SET" fuera "SET a.foo=b.foo" en su lugar, entonces el uso completo sería:

    Query_id: 0x1CD27577D202A339.1
UPDATE t1
SELECT t2
JOIN t1
JOIN t2
WHERE t1

    La presencia de un contexto SELECT después de otro contexto, como UPDATE o INSERT, indica de dónde la consulta UPDATE o INSERT recupera sus datos. El ejemplo inmediatamente anterior refleja una consulta UPDATE que actualiza filas en la tabla "t1" con datos de la tabla "t2".

  • Cualquier otro verbo

    Cualquier otro verbo, como INSERT, UPDATE, DELETE, etc., puede ser un contexto. Estos verbos indican que la consulta modifica los datos de alguna manera. Si un contexto SELECT sigue a uno de estos verbos, entonces la consulta lee datos de la tabla SELECT y los escribe en esta tabla. Esto ocurre, por ejemplo, con INSERT..SELECT o consultas UPDATE que utilizan valores de tablas en lugar de valores constantes.

    No se admiten estos tipos de consulta: SET, LOAD y DELETE de varias tablas.

  • JOIN

    El contexto JOIN enumera las tablas que se unen, ya sea con un JOIN explícito en la cláusula FROM, o implícitamente en la cláusula WHERE, como "t1.id = t2.id".

  • WHERE

    El contexto WHERE enumera las tablas que se utilizan en la cláusula WHERE para filtrar resultados. Esto no incluye tablas que se unen implícitamente en la cláusula WHERE; esas se enumeran como contextos JOIN. Por ejemplo:

    WHERE t1.id > 100 AND t1.id < 200 AND t2.foo IS NOT NULL

    Resulta en:

    WHERE t1
WHERE t2

    La herramienta solo lista tablas distintas; es por eso que la tabla "t1" solo se lista una vez.

  • TLIST

    El contexto TLIST enumera las tablas a las que accede la consulta, pero que no aparecen en ningún otro contexto. Estas tablas suelen ser un producto cartesiano implícito. Por ejemplo, la consulta "SELECT * FROM t1, t2" resulta en:

    Query_id: 0xBDDEB6EDA41897A8.1
SELECT t1
SELECT t2
TLIST t1
TLIST t2

    En primer lugar, hay dos contextos SELECT, porque "SELECT *" selecciona filas de todas las tablas; "t1" y "t2" en este caso. En segundo lugar, las tablas se unen implícitamente, pero sin ningún tipo de condición de unión, lo que da como resultado un producto cartesiano indicado por el contexto TLIST para cada una.

ESTADO DE SALIDA

pt-table-usage sale con 1 ante cualquier tipo de error, o 0 si no hay errores.

OPTIONS

This tool is a client for MySQL. You can find the full list of client options in the MYSQL_OPTIONS section of the mysql(1) manpage.

The following options are specific to pt-table-usage.

--config
type: string

Read configuration from the specified file. This option may be specified multiple times, and options are read in the order they appear on the command line. If this option is specified, it must be the first option on the command line.

--constant-data-value
type: string; default: DUAL

Table to print as the source for constant data (literals). This is any data not retrieved from tables (or subqueries, because subqueries are not supported). This includes literal values such as strings ("foo") and numbers (42), or functions such as NOW(). For example, in the query "INSERT INTO t (c) VALUES ('a')", the string 'a' is constant data, so the table usage report is:

INSERT t
SELECT DUAL

The first line indicates that the query inserts data into table "t", and the second line indicates that the inserted data comes from some constant value.

--[no]continue-on-error
default: yes

Continue to work even if there is an error.

--create-table-definitions
type: array

Read "CREATE TABLE" definitions from this list of comma-separated files. If you cannot use "--explain-extended" to fully qualify table and column names, you can save the output of "mysqldump --no-data" to one or more files and specify those files with this option. The tool will parse all "CREATE TABLE" definitions from the files and use this information to qualify table and column names. If a column name appears in multiple tables, or a table name appears in multiple databases, the ambiguities cannot be resolved.

--daemonize
Fork to the background and detach from the shell. POSIX operating systems only.
--database
short form: -D; type: string

Default database.

--defaults-file
short form: -F; type: string

Only read mysql options from the given file. You must give an absolute pathname.

--explain-extended
type: DSN

A server to execute EXPLAIN EXTENDED queries. This may be necessary to resolve ambiguous (unqualified) column and table names.

--filter
type: string

Discard events for which this Perl code doesn't return true.

This option is a string of Perl code or a file containing Perl code that is compiled into a subroutine with one argument: $event. If the given value is a readable file, then pt-table-usage reads the entire file and uses its contents as the code.

Filters are implemented in the same fashion as in the pt-query-digest tool, so please refer to its documentation for more information.

--help
Show help and exit.
--host
short form: -h; type: string

Connect to host.

--id-attribute
type: string

Identify each event using this attribute. The default is to use a query ID, which is an MD5 checksum of the query's fingerprint.

--log
type: string

Print all output to this file when daemonized.

--password
short form: -p; type: string

Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

--pid
type: string

Create the given PID file. The tool won't start if the PID file already exists and the PID it contains is different than the current PID. However, if the PID file exists and the PID it contains is no longer running, the tool will overwrite the PID file with the current PID. The PID file is removed automatically when the tool exits.

--port
short form: -P; type: int

Port number to use for connection.

--progress
type: array; default: time,30

Print progress reports to STDERR. The value is a comma-separated list with two parts. The first part can be percentage, time, or iterations; the second part specifies how often an update should be printed, in percentage, seconds, or number of iterations.

--query
type: string

Analyze the specified query instead of reading a log file.

--read-timeout
type: time; default: 0

Wait this long for an event from the input; 0 to wait forever.

This option sets the maximum time to wait for an event from the input. If an event is not received after the specified time, the tool stops reading the input and prints its reports.

This option requires the Perl POSIX module.

--run-time
type: time

How long to run before exiting. The default is to run forever (you can interrupt with CTRL-C).

--set-vars
type: Array

Set the MySQL variables in this comma-separated list of "variable=value" pairs.

By default, the tool sets:

wait_timeout=10000

Variables specified on the command line override these defaults. For example, specifying "--set-vars wait_timeout=500" overrides the defaultvalue of 10000.

The tool prints a warning and continues if a variable cannot be set.

--socket
short form: -S; type: string

Socket file to use for connection.

--user
short form: -u; type: string

User for login if not current user.

--version
Show version and exit.

ENVIRONMENT

The environment variable "PTDEBUG" enables verbose debugging output to STDERR. To enable debugging and capture all output to a file, run the tool like:

PTDEBUG=1 pt-table-usage ... > FILE 2>&1

Be careful: debugging output is voluminous and can generate several megabytes of output.

ATTENTION

Using <PTDEBUG> might expose passwords. When debug is enabled, all command line parameters are shown in the output.

SYSTEM REQUIREMENTS
