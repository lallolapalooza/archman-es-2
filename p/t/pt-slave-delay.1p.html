NOMBRE

pt-slave-delay - Hacer que un servidor esclavo de MySQL se retrase respecto a su maestro.

Esta herramienta está obsoleta y se eliminará en futuras versiones. No soporta MySQL 8.1 o superior.

Utilice la replicación retardada incorporada en su lugar: https://dev.mysql.com/doc/refman/en/replication-delayed.html

SINOPSIS

Uso: pt-slave-delay [OPCIONES] SLAVE_DSN [MASTER_DSN]

pt-slave-delay inicia y detiene un servidor esclavo según sea necesario para que se retrase respecto al maestro. SLAVE_DSN y MASTER_DSN usan sintaxis DSN, y los valores se copian de SLAVE_DSN a MASTER_DSN si se omiten.

Para mantener el host esclavo con un minuto de retraso respecto a su maestro durante diez minutos:

pt-slave-delay --delay 1m --interval 15s --run-time 10m slavehost

DESCRIPCIÓN

"pt-slave-delay" observa a un esclavo e inicia y detiene su hilo SQL de replicación según sea necesario para mantenerlo al menos tan retrasado respecto al maestro como usted solicite. En la práctica, normalmente hará que el esclavo se retrase entre "--delay" y "--delay" + "--interval" respecto al maestro.

Se basa en las posiciones del binlog en los logs de retransmisión del esclavo por defecto, por lo que no es necesario conectarse al maestro. Esto funciona bien si el hilo IO no se retrasa mucho respecto al maestro, lo cual es típico en la mayoría de las configuraciones de replicación; el retraso del hilo IO suele ser de milisegundos en una red rápida. Si el retraso de su hilo IO es demasiado grande para sus propósitos, "pt-slave-delay" también puede conectarse al maestro para obtener información sobre las posiciones del binlog.

Si el hilo I/O del esclavo informa que está esperando a que el hilo SQL libere espacio en el log de retransmisión, "pt-slave-delay" se conectará automáticamente al maestro para encontrar las posiciones del log binario. Si se dan "--ask-pass" y "--daemonize", es posible que esto pueda provocar que solicite una contraseña mientras está en modo demonio. En este caso, sale. Por lo tanto, si cree que su esclavo podría encontrarse con esta condición, asegúrese de especificar explícitamente "--use-master" al usar el modo demonio, o no especifique "--ask-pass".

El SLAVE_DSN y el MASTER_DSN opcional son ambos DSNs. Vea "OPCIONES DSN". Los valores MASTER_DSN omitidos se rellenan con valores de SLAVE_DSN, por lo que no necesita especificarlos en ambos lugares. "pt-slave-delay" lee todos los archivos de opciones normales de MySQL, como ~/.my.cnf, por lo que es posible que ni siquiera necesite especificar el nombre de usuario, la contraseña y otras opciones comunes.

"pt-slave-delay" intenta salir graciosamente atrapando señales como Ctrl-C. No puede omitir "--[no]continue" con una señal atrapable.

PRIVILEGIOS

pt-slave-delay requiere los siguientes privilegios: PROCESS, REPLICATION CLIENT y SUPER.

SALIDA

Si especifica "--quiet", no hay salida. De lo contrario, la salida normal es un mensaje de estado que consiste en una marca de tiempo e información sobre lo que está haciendo "pt-slave-delay": iniciando el esclavo, deteniendo el esclavo o simplemente observando.

NAME

pt-slave-delay

check MySQL slave replication lag

SYNOPSIS

pt-slave-delay --slave <dsn> [OPTIONS]
pt-slave-delay --master <dsn> [OPTIONS]

RISKS

This tool is designed to be safe, but as always, life happens.

When pt-slave-delay runs, it writes a value to the "slave_lag_value" column of the "percona.slave_lag" table. This table must exist on the slave server. The tool creates the table and column if they do not exist. It is very unlikely that this will cause problems, but it's still a possibility. The table is created with the following SQL statement:

CREATE TABLE IF NOT EXISTS percona.slave_lag (
  slave_lag_value INT UNSIGNED NOT NULL PRIMARY KEY
) ENGINE=InnoDB;

DESCRIPTION

This tool checks the replication lag of a MySQL slave server. It works by writing a timestamp to a table on the slave server, then querying the master server for the current time, and then reading the timestamp from the slave table. The difference between the master time and the slave time is the replication lag. The tool can be used to ensure that replication is keeping up or to measure replication lag over time.

The tool operates in two modes:

Slave-centric mode (default):
The tool connects to the slave and writes a timestamp to the "percona.slave_lag" table. It then queries the master for the current time and reads the timestamp back from the slave. The lag is calculated as "master_time - slave_write_time". This mode is useful when you want to monitor the slave's lag from the slave itself.
Master-centric mode:
The tool connects to the master and writes a timestamp to the "percona.slave_lag" table on the slave. It then queries the master for the current time and reads the timestamp back from the slave. The lag is calculated as "master_time - slave_write_time". This mode is useful when you want to monitor the slave's lag from the master.

The tool can also be configured to check the master's binlog position and compare it to the slave's relay log position. This allows for more accurate lag detection, especially in environments with high write loads.

PRIVILEGES

The tool requires the following privileges:

  • On the slave server:
    • CREATE, INSERT, SELECT, and DROP on the "percona.slave_lag" table.
    • RELOAD or SUPER privilege to use SHOW SLAVE STATUS.
  • On the master server:
    • SELECT privilege to read the master's time and binlog position.

OUTPUT

The tool outputs the replication lag in seconds. It can also output the master and slave binlog positions if the corresponding options are specified.

--slave=root:pass@tcp(slave:3306)/ test
--master=root:pass@tcp(master:3306)/ test
LAG: 5s

OPTIONS

--master
short form: -m; type: DSN; required: Yes

DSN for the master server. This is used to query the master's current time and binlog position.

--master-dsn
type: DSN; required: No

DSN for the master server. This is used to query the master's current time and binlog position. This option is only relevant when you are not specifying --slave and want to check the master's binlog position. If you specify this option without giving a MASTER_DSN on the command line, "pt-slave-delay" examines the slave's SHOW SLAVE STATUS to determine the hostname and port for connecting to the master.

pt-slave-delay uses only the MASTER_HOST and MASTER_PORT values from SHOW SLAVE STATUS for the master connection. It does not use the MASTER_USER value. If you want to specify a different username for the master than the one you use to connect to the slave, you should specify the MASTER_DSN option explicitly on the command line.

--slave
short form: -s; type: DSN; required: Yes

DSN for the slave server. This is used to write the timestamp to the "percona.slave_lag" table and to read the slave's current time and binlog position.

--interval
type: integer; default: 1

The interval in seconds between checks. If 0, the tool checks once and exits.

--[no]check-master-position
default: no

Check the master's binlog position. If this option is enabled, the tool will also query the master for its current binlog position and compare it to the slave's relay log position. This provides a more accurate measure of replication lag, especially in high-write environments.

--[no]check-slave-position
default: no

Check the slave's relay log position. If this option is enabled, the tool will query the slave for its current relay log position and compare it to the master's binlog position. This is useful for detecting if the slave has fallen behind the master.

--[no]update-master-position
default: no

Log positions from master, not slave. Don't trust the binlog positions in the slave's relay log. Connect to the master and get binlog positions instead. If you specify this option without giving a MASTER_DSN on the command line, "pt-slave-delay" examines the slave's SHOW SLAVE STATUS to determine the hostname and port for connecting to the master.

"pt-slave-delay" uses only the MASTER_HOST and MASTER_PORT values from SHOW SLAVE STATUS for the master connection. It does not use the MASTER_USER value. If you want to specify a different username for the master than the one you use to connect to the slave, you should specify the MASTER_DSN option explicitly on the command line.

These DSN options are used to create a DSN. Each option is given like "option=value". The options are case-sensitive, so P and p are not the same option.     Default character set.

  • D

    Default database.

  • F

    Only read default options from the given file

  • h

    dsn: host; copy: yes

    Connect to host.

  • p

    dsn: password; copy: yes

    Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

  • P

    Port number to use for connection.

  • S

    dsn: mysql_socket; copy: yes

    Socket file to use for connection.

  • u

    dsn: user; copy: yes

    User for login if not current user.

NAME

pt-slave-delay - Perl tool to measure MySQL slave lag

SYNOPSIS

pt-slave-delay [OPTIONS] [-- []]

DESCRIPTION

This script measures the replication delay on MySQL slaves. It works by creating a table on the master, inserting a row into it, and then checking the slave to see how long it takes for the row to appear. This is a more robust method than simply checking the slave's IO thread and SQL thread running status, as it accounts for query execution time on the slave.
