Paquete: percona-toolkit

PT-REPLICA-RESTART(1) Documentación de Perl aportada por el usuario PT-REPLICA-RESTART(1)

NOMBRE

pt-replica-restart - Observa y reinicia la replicación de MySQL tras errores.

SINOPSIS

Uso: pt-replica-restart [OPCIONES] [DSN]

pt-replica-restart observa una o más réplicas de replicación de MySQL en busca de errores e intenta reiniciar la replicación si se detiene.

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien verificado, pero todas las herramientas de bases de datos pueden representar un riesgo para el sistema y el servidor de base de datos. Antes de usar esta herramienta, por favor:

  • Lee la documentación de la herramienta
  • Revisa los "BUGS" conocidos de la herramienta
  • Prueba la herramienta en un servidor no de producción
  • Haz una copia de seguridad de tu servidor de producción y verifica las copias

DESCRIPCIÓN

pt-replica-restart observa una o más réplicas de replicación de MySQL e intenta omitir sentencias que causan errores. Consulta las réplicas inteligentemente con un tiempo de espera exponencialmente variable. Puedes especificar errores para omitir y ejecutar las réplicas hasta una posición de binlog determinada.

Aunque esta herramienta puede ayudar a una réplica a avanzar más allá de los errores, no debes depender de ella para "arreglar" la replicación. Si los errores de réplica ocurren con frecuencia o inesperadamente, debes identificar y corregir la causa raíz.

SALIDA

pt-replica-restart imprime una línea cada vez que detecta que la réplica tiene un error. Por defecto, esta línea es: una marca de tiempo, información de conexión, relay_log_file, relay_log_pos y last_errno. Puedes agregar más información usando la opción "--verbose". Puedes suprimir toda la salida usando la opción "--quiet".

ESPERA

pt-replica-restart espera inteligentemente entre consultas a la réplica. El tiempo de espera actual varía.

  • El tiempo de espera inicial viene dado por "--sleep".
  • Si comprueba y encuentra un error, reduce a la mitad el tiempo de espera anterior.
  • Si no encuentra ningún error, duplica el tiempo de espera anterior.
  • El tiempo de espera está limitado inferiormente por "--min-sleep" y superiormente por "--max-sleep".
  • Inmediatamente después de encontrar un error, pt-replica-restart asume que es muy probable que ocurra otro error a continuación, por lo que espera el tiempo de espera actual o el tiempo de espera inicial, el que sea menor.

IDS DE TRANSACCIONES GLOBALES

A partir de Percona Toolkit 2.2.8, pt-replica-restart soporta los IDs de Transacciones Globales introducidos en MySQL 5.6.5. Es importante tener en cuenta que:

  • pt-replica-restart no omitirá transacciones cuando se utilizan múltiples hilos de replicación (replica_parallel_workers > 0). pt-replica-restart no conoce el evento GTID de la transacción fallida de un hilo de réplica específico.
  • El comportamiento por defecto es omitir la siguiente transacción de la fuente de la réplica. Las escrituras pueden originarse en diferentes servidores, cada uno con su propio UUID.

    Ver "--source-uuid".

ESTADO DE SALIDA

Un estado de salida de 0 (a veces también llamado valor de retorno o código de retorno) indica éxito. Cualquier otro valor representa el estado de salida del propio proceso Perl, o del último proceso hijo que salió si había múltiples servidores que monitorizar.

COMPATIBILIDAD

pt-replica-restart debería funcionar en muchas versiones de MySQL. La capitalización de muchas columnas de salida de SHOW REPLICA STATUS ha cambiado con el tiempo, por lo que las trata todas como minúsculas.

OPCIONES

Esta herramienta acepta argumentos de línea de comandos adicionales. Consulte la "SINOPSIS" y la información de uso para obtener detalles.

--always
Inicia las réplicas incluso cuando no hay error. Con esta opción habilitada, ¡pt-replica-restart no te permitirá detener la réplica manualmente si no quieres!
--ask-pass
Solicita una contraseña al conectarse a MySQL.
--charset
forma corta: -A; tipo: string

Juego de caracteres por defecto. Si el valor es utf8, establece el modo binario de Perl en STDOUT a utf8, pasa la opción mysql_enable_utf8 a DBD::mysql y ejecuta SET NAMES UTF8 después de conectarse a MySQL. Cualquier otro valor establece el modo binario en STDOUT sin la capa utf8, y ejecuta SET NAMES después de conectarse a MySQL.

--[no]check-relay-log
por defecto: yes

Comprueba el último archivo y posición del relay log antes de comprobar los errores de réplica.

Por defecto, pt-replica-restart no hará nada (solo esperará) si ni el archivo del relay log ni la posición del relay log han cambiado desde la última comprobación. Esto evita bucles infinitos (es decir, reiniciar el mismo error en el mismo archivo de relay log en la misma posición de relay log).

Para ciertos errores de réplica, sin embargo, esta comprobación necesita ser deshabilitada especificando "--no-check-relay-log". ¡No hagas esto a menos que sepas lo que estás haciendo!

--config
tipo: Array

Lee esta lista de archivos de configuración separada por comas; si se especifica, esta debe ser la primera opción en la línea de comandos.

--daemonize
Divide el proceso y lo desvincula de la shell. Solo sistemas operativos POSIX.
--database
forma corta: -D; tipo: string

Base de datos a usar.

--defaults-file
forma corta: -F; tipo: string

Lee solo las opciones de mysql del archivo dado. Debes proporcionar una ruta absoluta.

--error-length
tipo: int

Longitud máxima del mensaje de error a imprimir. Cuando "--verbose" está configurado lo suficientemente alto como para imprimir el error, esta opción truncará el texto del error a la longitud especificada. Esto puede ser útil para evitar saltos de línea en la terminal.

--error-numbers
tipo: hash

Reinicia solo esta lista de errores separada por comas. Hace que pt-replica-restart solo intente reiniciar si el número de error está en esta lista de errores separados por comas. Si detecta un error que no está en la lista, saldrá.

El número de error está en la columna "last_errno" de "SHOW REPLICA STATUS".

--error-text
tipo: string

Reinicia solo los errores que coinciden con este patrón. Una expresión regular de Perl contra la cual se compara el texto del error, si existe. Si el texto del error existe y coincide, pt-replica-restart intentará reiniciar la réplica. Si existe pero no coincide, pt-replica-restart saldrá.

El texto del error está en la columna "last_error" de "SHOW REPLICA STATUS".

--help
Muestra la ayuda y sale.
--host
forma corta: -h; tipo: string

Conectar al host.

--log
tipo: string

Imprime toda la salida en este archivo cuando se ejecuta como demonio.

--master-uuid
tipo: string

Esta opción está obsoleta y será eliminada en futuras versiones. Usa "--source-user" en su lugar.

--max-sleep
tipo: float; por defecto: 64

Segundos máximos de espera.

El tiempo máximo que pt-replica-restart esperará antes de volver a consultar la réplica. Este es también el tiempo que pt-replica-restart esperará a que todas las demás instancias en ejecución terminen si ambas "--stop"

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

--max-sleep
type: float; default: 10.0

The maximum time pt-replica-restart will sleep before polling the replica again. See "SLEEP".

--min-sleep
type: float; default: 0.015625

El tiempo mínimo que pt-replica-restart dormirá antes de volver a consultar la réplica. Véase "SLEEP".

--monitor
Si supervisar la réplica (predeterminado). A menos que especifique explícitamente --monitor, "--stop" lo deshabilitará.
--password
forma corta: -p; type: string

Contraseña a usar al conectar. Si la contraseña contiene comas, deben ser escapadas con una barra invertida: "exam\,ple"

--pid
type: string

Crea el archivo PID dado. La herramienta no se iniciará si el archivo PID ya existe y el PID que contiene es diferente del PID actual. Sin embargo, si el archivo PID existe y el PID que contiene ya no se está ejecutando, la herramienta sobrescribirá el archivo PID con el PID actual. El archivo PID se elimina automáticamente cuando la herramienta sale.

--port
forma corta: -P; type: int

Número de puerto a usar para la conexión.

--quiet
forma corta: -q

Suprime la salida normal (deshabilita "--verbose").

--recurse
type: int; default: 0

Supervisa réplicas del servidor especificado, hasta el número de servidores especificado en la jerarquía. La profundidad por defecto de 0 significa "solo supervisar la réplica especificada".

pt-replica-restart examina "SHOW PROCESSLIST" e intenta determinar qué conexiones son de réplicas, luego se conecta a ellas. Véase "--recursion-method".

La recursión funciona encontrando todas las réplicas al iniciar el programa, luego supervisándolas. Si hay más de una réplica, "pt-replica-restart" usa fork() para supervisarlas.

Esto también funciona si ha configurado sus réplicas para que aparezcan en "SHOW REPLICAS". La configuración mínima para esto es el parámetro "report_host", pero también hay otros parámetros de "report" para el puerto, el nombre de usuario y la contraseña.

--recursion-method
type: array; default: processlist,hosts

Método de recursión preferido utilizado para encontrar réplicas.

Los métodos posibles son:

MÉTODO       USA
===========  ==================
processlist  SHOW PROCESSLIST
hosts        SHOW REPLICAS (SHOW SLAVE HOSTS antes de MySQL 8.1)
none         No encontrar réplicas

El método processlist es preferido porque SHOW REPLICAS no es fiable. Sin embargo, el método hosts es necesario si el servidor utiliza un puerto no estándar (no 3306). Normalmente pt-replica-restart hace lo correcto y encuentra las réplicas, pero puede dar un método preferido y se utilizará primero. Si no encuentra ninguna réplica, se intentarán los otros métodos.

--run-time
type: time

Tiempo para ejecutarse antes de salir. Hace que pt-replica-restart se detenga después de que transcurra el tiempo especificado. Sufijo opcional: s=segundos, m=minutos, h=horas, d=días; si no hay sufijo, se usa s.

--sentinel
type: string; default: /tmp/pt-replica-restart-sentinel

Sale si este archivo existe.

--slave-user
type: string

Esta opción está obsoleta y se eliminará en futuras versiones. Use "--replica-user" en su lugar.

--slave-password
type: string

Esta opción está obsoleta y se eliminará en futuras versiones. Use "--replica-password" en su lugar.

--replica-user
type: string

Establece el usuario que se utilizará para conectarse a las réplicas. Este parámetro permite tener un usuario diferente con menos privilegios en las réplicas, pero ese usuario debe existir en todas las réplicas.

--replica-password
type: string

Establece la contraseña que se utilizará para conectarse a las réplicas. Se puede usar con --replica-user y la contraseña del usuario debe ser la misma en todas las réplicas.

--set-vars
type: Array

Establece las variables de MySQL en esta lista separada por comas de pares "variable=valor".

Por defecto, la herramienta establece:

wait_timeout=10000

Las variables especificadas en la línea de comandos anulan estos valores predeterminados. Por ejemplo, especificar "--set-vars wait_timeout=500" anula el valor predeterminado de 10000.

La herramienta imprime una advertencia y continúa si una variable no se puede establecer.

--skip-count
type: int; default: 1

Número de sentencias a omitir al reiniciar la réplica.

--source-uuid
type: string

Al usar GTID, se debe crear una transacción vacía para omitirla. Si las escrituras provienen de diferentes nodos en el árbol de replicación superior, no es posible saber qué evento de qué UUID omitir.

Por defecto, se omiten las transacciones del origen de la réplica ('Source_UUID' de "SHOW REPLICA STATUS").

Por ejemplo, con

source1 -> replica1 -> replica2

Al omitir eventos en replica2 que se escribieron en source1, debe especificar el UUID de source1, de lo contrario la herramienta usará el UUID de replica1 por defecto.

Véase "GLOBAL TRANSACTION IDS".

--sleep
type: int; default: 1

Segundos de espera iniciales entre la comprobación de la réplica.

Véase "SLEEP".

--socket
forma corta: -S; type: string

Archivo de socket a usar para la conexión.

--stop
Detiene las instancias en ejecución creando el archivo centinela.

Hace que "pt-replica-restart" cree el archivo centinela especificado por "--sentinel". Esto debería tener el efecto de detener todas las instancias en ejecución que estén supervisando el mismo archivo centinela. Si no se especifica "--monitor", "pt-replica-restart" saldrá después de crear el archivo. Si se especifica, "pt-replica-restart" esperará el intervalo dado por "--max-sleep", luego eliminará el archivo y continuará trabajando.

Esto puede ser útil para detener trabajos cron de forma elegante si es necesario, o para reemplazar una instancia en ejecución por otra. Por ejemplo, si desea detener y reiniciar "pt-replica-restart" cada hora (solo para asegurarse de que se reinicia cada hora, en caso de una caída del servidor o algún otro problema), podría usar una línea de "crontab" como esta:

0 * * * * pt-replica-restart --monitor --stop --sentinel /tmp/pt-replica-restartup

El "--sentinel" no predeterminado se asegurará de que el trabajo "cron" horario detenga solo las instancias iniciadas previamente con las mismas opciones (es decir, desde el mismo trabajo "cron").

Véase también "--sentinel".

--until-master
type: string

Esta opción está obsoleta y se eliminará en futuras versiones. Use "--until-source" en su lugar.

--until-source
type: string

Ejecutar hasta este archivo de registro binario y posición del origen. Inicia la réplica y reintenta si falla, hasta que alcance las coordenadas de replicación dadas. Las coordenadas son el archivo de registro y la posición en el origen, dados por relay_source_log_file, exec_source_log_pos. El argumento debe estar en el formato "archivo,pos". Separe el nombre del archivo y la posición con una sola coma y sin espacio.

Esto también provocará que se dé una cláusula UNTIL a START REPLICA.

Después de alcanzar este punto, la réplica debe detenerse y pt-replica-restart saldrá.

--until-relay
type: string

Ejecutar hasta este archivo de registro de retransmisión y posición. Similar a "--until-source", pero en los registros de retransmisión de la réplica en su lugar. Las coordenadas se dan por relay_log_file, relay_log_pos.

--user
forma corta: -u; type: string

Usuario para iniciar sesión si no es el usuario actual.

--verbose
forma corta: -v; acumulativo: sí; default: 1

Añade más información a la salida. Esta bandera se puede especificar varias veces. Por ejemplo, -v -v O -vv. Por defecto (sin bandera verbose) la herramienta muestra información de conexión, una marca de tiempo, relay_log_file, relay_log_pos y last_errno. Una bandera (-v) añade last_error. Véase también "--error-length". Dos banderas (-vv) imprimen el tiempo de espera actual cada vez que pt-replica-restart duerme. Para suprimir toda la salida, use la opción "--quiet".
