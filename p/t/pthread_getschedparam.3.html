pthread_setschedparam(3) Manual de Funciones de Biblioteca pthread_setschedparam(3)

NOMBRE

pthread_setschedparam, pthread_getschedparam - establecer/obtener la política y los parámetros de planificación de un hilo

BIBLIOTECA

Biblioteca de hilos POSIX (libpthread, -lpthread)

SINOPSIS

#include <pthread.h>
int pthread_setschedparam(pthread_t thread, int policy,
                          const struct sched_param *param);
int pthread_getschedparam(pthread_t thread, int *restrict policy,
                          struct sched_param *restrict param);

DESCRIPCIÓN

La función pthread_setschedparam() establece la política de planificación y los parámetros del hilo thread.

policy especifica la nueva política de planificación para thread. Los valores soportados para policy, y sus semánticas, se describen en sched(7).

La estructura apuntada por param especifica los nuevos parámetros de planificación para thread. Los parámetros de planificación se mantienen en la siguiente estructura:


struct sched_param {
    int sched_priority;     /* Prioridad de planificación */
};

Como se puede ver, solo se soporta un parámetro de planificación. Para detalles sobre los rangos permitidos para las prioridades de planificación en cada política de planificación, consulte sched(7).

La función pthread_getschedparam() devuelve la política de planificación y los parámetros del hilo thread, en los búferes apuntados por policy y param, respectivamente. El valor de prioridad devuelto es el establecido por la llamada más reciente a pthread_setschedparam(), pthread_setschedprio(3), o pthread_create(3) que afectó a thread. La prioridad devuelta no refleja ningún ajuste de prioridad temporal como resultado de llamadas a funciones de herencia de prioridad o techo de prioridad (consulte, por ejemplo, pthread_mutexattr_setprioceiling(3) y pthread_mutexattr_setprotocol(3)).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0; en caso de error, devuelven un número de error distinto de cero. Si pthread_setschedparam() falla, la política de planificación y los parámetros de thread no se modifican.

ERRORES

Ambas funciones pueden fallar con el siguiente error:

ESRCH
No se encontró ningún hilo con el ID thread.

pthread_setschedparam() puede adicionalmente fallar con los siguientes errores:

EINVAL
policy no es una política reconocida, o param no tiene sentido para la policy.
EPERM
El llamante no tiene los privilegios apropiados para establecer la política y los parámetros de planificación especificados.

POSIX.1 también documenta un error ENOTSUP ("se intentó establecer la política o los parámetros de planificación a un valor no soportado") para pthread_setschedparam().

NOTAS

Para una descripción de los permisos requeridos para, y el efecto de, cambiar la política de planificación y la prioridad de un hilo, y detalles de los rangos permitidos para las prioridades en cada política de planificación, consulte sched(7).

EJEMPLOS

El programa a continuación demuestra el uso de pthread_setschedparam() y pthread_getschedparam(), así como el uso de varias otras funciones de pthreads relacionadas con la planificación.

En la siguiente ejecución, el hilo principal establece su política de planificación a SCHED_FIFO con una prioridad de 10, e inicializa un objeto de atributos de hilo con un atributo de política de planificación de SCHED_RR y un atributo de prioridad de planificación de 20. El programa luego establece (usando pthread_attr_setinheritsched(3)) el atributo de herencia de planificador del objeto de atributos de hilo a PTHREAD_EXPLICIT_SCHED, lo que significa que los hilos creados usando este objeto de atributos deben tomar sus atributos de planificación del objeto de atributos de hilo. El programa luego crea un hilo usando el objeto de atributos de hilo, y ese hilo muestra su política de planificación y prioridad.


$ su;      # Se necesita privilegio para establecer políticas de planificación

    policy=SCHED_RR, priority=20
    inheritsched is EXPLICIT
Scheduler attributes of new thread
    policy=SCHED_RR, priority=20

En la salida anterior, se puede ver que la política y la prioridad de planificación se tomaron de los valores especificados en el objeto de atributos del hilo.

La siguiente ejecución es la misma que la anterior, excepto que el atributo de herencia de planificador se establece en PTHREAD_INHERIT_SCHED, lo que significa que los hilos creados usando el objeto de atributos de hilo deben ignorar los atributos de planificación especificados en el objeto de atributos y en su lugar tomar sus atributos de planificación del hilo creador.


# ./a.out -mf10 -ar20 -i i;
Scheduler settings of main thread
    policy=SCHED_FIFO, priority=10
Scheduler settings in 'attr'
    policy=SCHED_RR, priority=20
    inheritsched is INHERIT
Scheduler attributes of new thread
    policy=SCHED_FIFO, priority=10

En la salida anterior, se puede ver que la política y la prioridad de planificación se tomaron del hilo creador, en lugar del objeto de atributos del hilo.

Tenga en cuenta que si hubiéramos omitido la opción -i i, la salida habría sido la misma, ya que PTHREAD_INHERIT_SCHED es el valor predeterminado para el atributo de herencia de planificador.

static int
get_policy(char p, int *policy)
{
    switch (p) {
    case 'f': *policy = SCHED_FIFO;     return 1;
    case 'r': *policy = SCHED_RR;       return 1;
    case 'o': *policy = SCHED_OTHER;    return 1;
    default:                            return 0;
    }
}
