NOMBRE

pt-variable-advisor - Analiza variables de MySQL y aconseja sobre posibles problemas.

SINOPSIS

Uso: pt-variable-advisor [OPCIONES] [DSN]

pt-variable-advisor analiza variables y aconseja sobre posibles problemas.

Obtener SHOW VARIABLES de localhost:

pt-variable-advisor localhost

Obtener la salida de SHOW VARIABLES guardada en vars.txt:

pt-variable-advisor --source-of-variables vars.txt

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien probado, pero todas las herramientas de bases de datos pueden representar un riesgo para el sistema y el servidor de bases de datos. Antes de usar esta herramienta, por favor:

  • Lea la documentación de la herramienta
  • Revise los "BUGS" conocidos de la herramienta
  • Pruebe la herramienta en un servidor no de producción
  • Haga una copia de seguridad de su servidor de producción y verifique las copias de seguridad

DESCRIPCIÓN

pt-variable-advisor examina "SHOW VARIABLES" en busca de valores y configuraciones incorrectas según las "REGLAS" descritas a continuación. Informa sobre las variables que coinciden con las reglas, para que pueda encontrar configuraciones erróneas en su servidor MySQL.

REGLAS

Estas son las reglas que pt-variable-advisor aplicará a SHOW VARIABLES. Cada regla tiene tres partes: un ID, una severidad y una descripción.

El ID de la regla es un nombre corto y único para la regla. Generalmente se relaciona con la variable que la regla examina. Si una variable es examinada por varias reglas, los IDs de las reglas se numeran como "-1", "-2", "-N".

La severidad de la regla es una indicación de la importancia de que esta regla coincida con una consulta. Usamos NOTA, ADVERTENCIA y CRÍTICO para denotar estos niveles.

La descripción de la regla es una explicación textual y legible por humanos de lo que significa cuando una variable coincide con esta regla. Dependiendo de la verbosidad del informe que genere, verá más texto en la descripción. Por defecto, solo verá la primera frase, que es una especie de resumen conciso del significado de la regla. Con una mayor verbosidad, verá las frases subsiguientes.

Configurar relay_log_space_limit puede hacer que las réplicas dejen de descargar los registros binarios de su fuente inmediatamente. Si las réplicas han encontrado un límite en el espacio del registro de retransmisión, es posible que las últimas transacciones existan solo en la fuente y ninguna réplica las haya recuperado.

PARÁMETROS DE CONFIGURACIÓN

Estas son las opciones de configuración que se pueden especificar en el archivo de configuración de MySQL, o con la opción --set-vars. Las opciones de configuración son las mismas que las que devuelve SHOW VARIABLES.

binlog_format
severity: warn

El formato de registro binario se establece en ROW o MIXED. Para utilizar la replicación de cambios de esquemas en caliente, debe establecerse en ROW o MIXED.

innodb_flush_log_at_trx_commit
severity: warn

El registro de transacciones se escribe en el registro de transacciones de InnoDB y se vacía en el disco en cada confirmación de transacción. Tener este valor establecido en 0 o 2 reduce la durabilidad de las transacciones de InnoDB.

Para obtener información sobre la configuración de este parámetro, consulte la documentación de InnoDB.

log_bin
severity: warn

Los registros binarios se utilizan para la replicación, pero no se han especificado para registrar el nombre del archivo de registro binario.

log_slave_updates
severity: warn

Cuando se utiliza un esclavo de replicación, las actualizaciones recibidas de un maestro también deben registrarse en el registro binario del esclavo. Esto permite que el esclavo actúe como maestro para otros esclavos.

performance_schema
severity: warn

La dirección de la salida de registro a tablas tiene un alto impacto en el rendimiento.

max_relay_log_size
severity: note

Se define un max_relay_log_size personalizado.

myisam_recover_options
severity: warn

myisam_recover_options debe establecerse en algún valor como BACKUP,FORCE para garantizar que se detecte la corrupción de la tabla.

storage_engine
severity: note

El servidor está utilizando un motor de almacenamiento no estándar por defecto.

sync_binlog
severity: warn

El registro binario está habilitado, pero sync_binlog no está configurado para que cada transacción se vacíe en el registro binario para su durabilidad.

tmp_table_size
severity: note

El tamaño mínimo efectivo de las tablas temporales implícitas en memoria utilizadas internamente durante la ejecución de consultas es min(tmp_table_size, max_heap_table_size), por lo que max_heap_table_size debe ser al menos tan grande como tmp_table_size.

versión antigua de mysql
severity: warn

Estas son las versiones mínimas recomendadas para cada lanzamiento principal: 3.23, 4.1.20, 5.0.37, 5.1.30, 5.5.8, 5.6.10, 5.7.9, 8.0.11. Esta opción no se queja de las versiones de Innovación.

versión de mysql obsoleta
severity: note

Todos los lanzamientos anteriores a 8.0 están ahora oficialmente obsoletos.

OPCIONES

Esta herramienta acepta argumentos de línea de comandos adicionales. Consulte la sección "SINÓPSIS" e información de uso para obtener detalles.

--ask-pass
Solicitar una contraseña al conectarse a MySQL.
--charset
forma corta: -A; tipo: string

Juego de caracteres por defecto. Si el valor es utf8, establece el modo binario de Perl en STDOUT a utf8, pasa la opción mysql_enable_utf8 a DBD::mysql y ejecuta SET NAMES UTF8 después de conectarse a MySQL. Cualquier otro valor establece el modo binario en STDOUT sin la capa utf8, y ejecuta SET NAMES después de conectarse a MySQL.

--config
tipo: Array

Leer esta lista de archivos de configuración separados por comas; si se especifica, esta debe ser la primera opción en la línea de comandos.

--daemonize
Crear un proceso hijo y desvincularlo de la terminal. Solo en sistemas operativos POSIX.
--database
forma corta: -D; tipo: string

Conectarse a esta base de datos.

--defaults-file
forma corta: -F; tipo: string

Leer solo las opciones de MySQL del archivo dado. Debe proporcionar una ruta de acceso absoluta.

--help
Mostrar la ayuda y salir.
--host
forma corta: -h; tipo: string

Conectarse al host.

--ignore-rules
tipo: hash

Ignorar estos IDs de reglas.

Especifique una lista de IDs de reglas separados por comas (por ejemplo, LIT.001,RES.002,etc.) para ignorar.

--password
forma corta: -p; tipo: string

Contraseña a usar al conectarse. Si la contraseña contiene comas, deben escaparse con una barra invertida: "exam\,ple"

--pid
tipo: string

Crear el archivo PID especificado. La herramienta no se iniciará si el archivo PID ya existe y el PID que contiene es diferente del PID actual. Sin embargo, si el archivo PID existe y el PID que contiene ya no se está ejecutando, la herramienta sobrescribirá el archivo PID con el PID actual. El archivo PID se elimina automáticamente cuando la herramienta finaliza.

--port
forma corta: -P; tipo: int

Número de puerto a usar para la conexión.

--set-vars
tipo: Array

Establecer las variables de MySQL en esta lista separada por comas de pares "variable=valor".

Por defecto, la herramienta establece:

wait_timeout=10000

Las variables especificadas en la línea de comandos anulan estos valores predeterminados. Por ejemplo, especificar "--set-vars wait_timeout=500" anula el valor predeterminado de 10000.

La herramienta imprime una advertencia y continúa si una variable no se puede establecer.

--socket
forma corta: -S; tipo: string

Archivo de socket a usar para la conexión.

--source-of-variables
tipo: string; por defecto: mysql

Leer "SHOW VARIABLES" de esta fuente. Los valores posibles son "mysql", "none" o un nombre de archivo. Si se especifica "mysql", también debe especificar un DSN en la línea de comandos.

--user
forma corta: -u; tipo: string

Usuario para iniciar sesión si no es el usuario actual.

--verbose
forma corta: -v; acumulativo: sí; por defecto: 1

Aumentar la verbosidad de la salida. En el nivel de verbosidad predeterminado, el programa imprime solo la primera oración de la descripción de cada regla. En niveles más altos, el programa imprime más de la descripción.

--version
Mostrar la versión y salir.
--[no]version-check
por defecto: sí

Comprobar la última versión de Percona Toolkit, MySQL y otros programas.

Esta es una función estándar de "comprobar actualizaciones automáticamente", con dos funciones adicionales. Primero, la herramienta comprueba su propia versión y también las versiones del siguiente software: sistema operativo, Percona Monitoring and Management (PMM), MySQL, driver de Perl para MySQL (DBD::mysql) y Percona Toolkit. Segundo, comprueba y advierte sobre versiones con problemas conocidos. Por ejemplo, MySQL 5.5.25 tenía un error crítico y se relanzó como 5.5.25a.

Se realiza una conexión segura al servidor de base de datos de comprobación de versiones de Percona para realizar estas comprobaciones. El servidor registra cada solicitud, incluyendo los números de versión del software y el ID único del sistema comprobado. El ID es generado por el script de instalación de Percona Toolkit o cuando se realiza la llamada a la base de datos de comprobación de versiones por primera vez.

Cualquier actualización o problema conocido se imprime en STDOUT antes de la salida normal de la herramienta. Esta función nunca debería interferir con el funcionamiento normal de la herramienta.

Para más información, visite https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

OPCIONES DSN

Estas opciones DSN se utilizan para crear un DSN. Cada opción se proporciona como "opción=valor". Las opciones distinguen entre mayúsculas y minúsculas, por lo que P y p no son la misma opción. No puede haber espacios en blanco antes o después del "=" y si el valor contiene espacios en blanco debe entrecomillarse. Las opciones DSN están separadas por comas. Consulte la página del manual de percona-toolkit para obtener detalles completos.

  • A

    dsn: charset; copia: sí

    Juego de caracteres por defecto.

  • D

    dsn: database; copia: sí

    Base de datos por defecto.

  • F

    dsn: mysql_read_default_file; copia: sí

    Leer solo las opciones por defecto del archivo dado

  • h

    dsn: host; copia: sí

    Conectarse al host.

  • p

    dsn: password; copia: sí

    Contraseña a usar al conectarse. Si la contraseña contiene comas, deben escaparse con una barra invertida: "exam\,ple"

  • P

    dsn: port; copia: sí

    Número de puerto a usar para la conexión.

  • S

    dsn: mysql_socket; copia: sí

    Archivo de socket a usar para la conexión.

  • u

    dsn: user; copia: sí

    Usuario para iniciar sesión si no es el usuario actual.

  • s

    dsn: mysql_ssl; copia: sí

    Crear conexión SSL

AMBIENTE

La variable de entorno "PTDEBUG" habilita la salida de depuración detallada a STDERR. Para habilitar la depuración y capturar toda la salida en un archivo, ejecute la herramienta de la siguiente manera:

PTDEBUG=1 pt-variable-advisor ... > ARCHIVO 2>&1

Tenga cuidado: la salida de depuración es voluminosa y puede generar varios megabytes de salida.

ATENCIÓN

El uso de <PTDEBUG> puede exponer contraseñas. Cuando la depuración está habilitada, todos los parámetros de la línea de comandos se muestran en la salida.

REQUISITOS DEL SISTEMA

SOBRE PERCONA TOOLKIT

Esta herramienta forma parte de Percona Toolkit, una colección de herramientas avanzadas de línea de comandos para MySQL desarrolladas por Percona. Percona Toolkit se bifurcó de dos proyectos en junio de 2011: Maatkit y Aspersa. Esos proyectos fueron creados por Baron Schwartz y desarrollados principalmente por él y Daniel Nichter. Visita http://www.percona.com/software/ para obtener más información sobre otro software gratuito y de código abierto de Percona.
