PTHREAD_MUTEXATTR_DESTROY(3P) Manual del programador POSIX PTHREAD_MUTEXATTR_DESTROY(3P)

PROLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_mutexattr_destroy, pthread_mutexattr_init — destruir e inicializar el objeto de atributos del mutex

SINOPSIS

#include <pthread.h>
int pthread_mutexattr_destroy(pthread_mutexattr_t *attr);
int pthread_mutexattr_init(pthread_mutexattr_t *attr);

DESCRIPCIÓN

La función pthread_mutexattr_destroy() destruye un objeto de atributos de mutex; el objeto se vuelve, en efecto, no inicializado. Una implementación puede hacer que pthread_mutexattr_destroy() establezca el objeto referenciado por attr a un valor no válido.

Un objeto de atributos attr destruido puede ser reinicializado usando pthread_mutexattr_init(); los resultados de referenciar de otra manera el objeto después de que haya sido destruido no están definidos.

La función pthread_mutexattr_init() inicializa un objeto de atributos de mutex attr con el valor predeterminado para todos los atributos definidos por la implementación.

Los resultados no están definidos si pthread_mutexattr_init() se llama especificando un objeto de atributos attr ya inicializado.

Después de que un objeto de atributos de mutex se ha utilizado para inicializar uno o más mutexes, cualquier función que afecte al objeto de atributos (incluida la destrucción) no afectará a ningún mutex inicializado previamente.

El comportamiento no está definido si el valor especificado por el argumento attr a pthread_mutexattr_destroy() no se refiere a un objeto de atributos de mutex inicializado.

VALOR DE RETORNO

Al completarse con éxito, pthread_mutexattr_destroy() y pthread_mutexattr_init() devolverán cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_mutexattr_init() fallará si:

ENOMEM
No hay memoria suficiente para inicializar el objeto de atributos del mutex.

Estas funciones no devolverán un código de error de [EINTR].

RACIONAMIENTO

Si una implementación detecta que el valor especificado por el argumento attr a pthread_mutexattr_destroy() no se refiere a un objeto de atributos de mutex inicializado, se recomienda que la función falle y reporte un error [EINVAL].

Consulte pthread_attr_destroy() para una explicación general de los atributos. Los objetos de atributos permiten a las implementaciones experimentar con extensiones útiles y permiten la extensión de este volumen de POSIX.1‐2017 sin cambiar las funciones existentes. Por lo tanto, proporcionan extensibilidad futura de este volumen de POSIX.1‐2017 y reducen la tentación de estandarizar prematuramente semánticas que aún no están ampliamente implementadas o comprendidas.

Ejemplos de posibles atributos de mutex adicionales que se han discutido son spin_only, limited_spin, no_spin, recursive y metered. (Para explicar qué podrían significar estos últimos atributos: los mutex recursivos permitirían múltiples re-bloqueos por parte del propietario actual; los mutex medidos llevarían registros transparentes de la longitud de la cola, el tiempo de espera y así sucesivamente.) Dado que todavía no hay un acuerdo amplio sobre la utilidad de estos como resultado de la implementación y la experiencia de uso compartidas, aún no se especifican en este volumen de POSIX.1‐2017. Sin embargo, los objetos de atributos de mutex hacen posible probar estos conceptos para una posible estandarización en un momento posterior.

Atributos de Mutex y Rendimiento

Se ha tenido cuidado de garantizar que los valores predeterminados de los atributos del mutex se hayan definido de tal manera que los mutexes inicializados con los valores predeterminados tengan semánticas lo suficientemente simples como para que el bloqueo y desbloqueo se puedan realizar con el equivalente a una instrucción de prueba y conjunto (más posiblemente algunas otras instrucciones básicas).

Existe al menos un método de implementación que se puede utilizar para reducir el costo de las pruebas en el momento del bloqueo si un mutex tiene atributos no predeterminados. Un método de este tipo que una implementación puede emplear (y esto puede ser completamente transparente para aplicaciones POSIX totalmente conformes) es pre-bloquear secretamente cualquier mutex que se inicialice con atributos no predeterminados. Cualquier intento posterior de bloquear dicho mutex hace que la implementación se ramifique a la ``ruta lenta'' como si el mutex no estuviera disponible; luego, en la ruta lenta, la implementación puede hacer el ``trabajo real'' para bloquear un mutex no predeterminado. La operación de desbloqueo subyacente es más complicada, ya que la implementación nunca quiere realmente liberar el pre-bloqueo de este tipo de mutex. Esto ilustra que, dependiendo del hardware, puede haber ciertas optimizaciones que se pueden usar para que los atributos de mutex que se consideran ``más usados con frecuencia'' se puedan procesar de manera más eficiente.

Memoria Compartida entre Procesos y Sincronización

La existencia de funciones de mapeo de memoria en este volumen de POSIX.1‐2017 da lugar a la posibilidad de que una aplicación pueda asignar los objetos de sincronización de esta sección en memoria a la que acceden múltiples procesos (y, por lo tanto, hilos de múltiples procesos).

Para permitir dicho uso, al mismo tiempo que se mantiene el caso usual (es decir, el uso dentro de un solo proceso) de manera eficiente, se ha definido una opción de compartido entre procesos.

Si una implementación soporta la opción _POSIX_THREAD_PROCESS_SHARED, entonces el atributo process-shared puede usarse para indicar que los mutexes o variables de condición pueden ser accedidos por hilos de múltiples procesos.

La configuración predeterminada de PTHREAD_PROCESS_PRIVATE se ha elegido para el atributo process-shared, de modo que los objetos de sincronización más eficientes se crean por defecto.

Las variables de sincronización que se inicializan con el atributo process-shared PTHREAD_PROCESS_PRIVATE solo pueden ser operadas por hilos en el proceso que las inicializó. Las variables de sincronización que se inicializan con el atributo process-shared PTHREAD_PROCESS_SHARED pueden ser operadas por cualquier hilo en cualquier proceso que tenga acceso a ella. En particular, estos procesos pueden existir más allá de la vida útil del proceso inicializador. Por ejemplo, el siguiente código implementa un semáforo de conteo simple en un archivo mapeado que puede ser utilizado por muchos procesos.

Una vez que se crea el archivo, los programas de publicación y espera incrementan y decrementan el semáforo contador (esperando y despertando según sea necesario) a pesar de que no inicializaron el semáforo.

#include "sem.h"
int
main()
{
    semaphore_t *semap;
    semap = semaphore_create("/tmp/semaphore");
    if (semap == NULL)
        exit(1);
    semaphore_close(semap);
    return (0);
}
