Paquete: percona-toolkit

PT-MYSQL-SUMMARY(1) Documentación de Perl contribuida por el usuario PT-MYSQL-SUMMARY(1)

NOMBRE

pt-mysql-summary - Resume la información de MySQL de forma agradable.

SINOPSIS

Uso: pt-mysql-summary [OPCIONES]

pt-mysql-summary resume convenientemente el estado y la configuración de un servidor de base de datos MySQL para que pueda informarse de un vistazo. No es una herramienta de ajuste ni de diagnóstico. Produce un informe que es fácil de comparar y se puede pegar en correos electrónicos sin perder el formato. Debería funcionar bien en cualquier sistema UNIX moderno.

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien comprobado, pero todas las herramientas de bases de datos pueden suponer un riesgo para el sistema y el servidor de la base de datos. Antes de usar esta herramienta, por favor:

  • Lea la documentación de la herramienta
  • Revise los "ERRORES" conocidos de la herramienta
  • Pruebe la herramienta en un servidor no productivo
  • Haga una copia de seguridad de su servidor de producción y verifique las copias de seguridad

DESCRIPCIÓN

pt-mysql-summary funciona conectándose a un servidor de base de datos MySQL y consultándolo para obtener información de estado y configuración. Guarda estos fragmentos de datos en archivos en un directorio temporal, y luego los formatea ordenadamente con awk y otros lenguajes de scripting.

Para usarlo, simplemente ejecútelo. Opcionalmente, agregue un doble guion y luego las mismas opciones de línea de comandos que usaría para conectarse a MySQL, como las siguientes:

pt-mysql-summary --user=root

La herramienta interactúa mínimamente con el servidor en el que se ejecuta. Asume que la ejecutará en el mismo servidor que está inspeccionando y, por lo tanto, asume que podrá encontrar el archivo de configuración my.cnf, por ejemplo. Sin embargo, debería degradarse elegantemente si este no es el caso. Tenga en cuenta, sin embargo, que su salida no indica qué información proviene de la base de datos MySQL y qué proviene del sistema operativo, por lo que es posible generar una salida confusa si ejecuta la herramienta en un servidor y se conecta a un servidor de base de datos MySQL que se ejecuta en otro servidor.

SALIDA

Muchas de las salidas de esta herramienta se redondean deliberadamente para mostrar su magnitud pero no el detalle exacto. Esto se llama redondeo difuso (fuzzy-rounding). La idea es que no importa si un servidor está ejecutando 918 consultas por segundo o 921 consultas por segundo; una variación tan pequeña es insignificante y solo hace que la salida sea difícil de comparar con otros servidores. El redondeo difuso redondea en incrementos más grandes a medida que la entrada crece. Comienza redondeando al más cercano 5, luego al más cercano 10, al más cercano 25, y luego se repite por un factor de 10 mayor (50, 100, 250), y así sucesivamente, a medida que la entrada crece.

Esta sección es un resumen de la salida de SHOW PROCESSLIST. Cada subsección se agrega por un elemento diferente, que se muestra como el encabezado de la primera columna. Cuando se resume por Comando, se incluye cada fila en SHOW PROCESSLIST, pero de lo contrario, las filas cuyo Comando es Sleep se excluyen de las columnas SUM y MAX, para que no sesguen demasiado los números. En el ejemplo que se muestra, el servidor está inactivo excepto por esta herramienta y una réplica conectada, que está ejecutando Binlog Dump.

Las columnas son el número de filas incluidas, el número que no está en estado Sleep, la suma de la columna Time y el valor máximo de la columna Time. Los números están redondeados difusamente.

Esta sección muestra contadores seleccionados de dos instantáneas de SHOW GLOBAL STATUS, recopiladas con aproximadamente 10 segundos de diferencia y redondeadas difusamente. Incluye solo elementos que son contadores de incremento; no incluye números absolutos como la variable de estado Threads_running, que representa un valor actual, en lugar de un número acumulado con el tiempo.

La primera columna es el nombre de la variable, y la segunda columna es el contador de la primera instantánea dividido por 86400 (el número de segundos en un día), por lo que puede ver la magnitud del cambio del contador por día. 86400 redondeado difusamente es 90000, por lo que el contador Uptime siempre debería ser aproximadamente 90000.

La tercera columna es el valor de la primera instantánea, dividido por Uptime y luego redondeado difusamente, por lo que representa aproximadamente la rapidez con la que crece el contador por segundo durante el tiempo de actividad del servidor.

La cuarta columna es la diferencia incremental entre la primera y la segunda instantánea, dividida por la diferencia de tiempo de actividad y luego redondeada difusamente. Por lo tanto, muestra la rapidez con la que crece el contador por segundo en el momento en que se generó el informe.

This section shows a pretty-printed version of the my.cnf file, with comments removed and with whitespace added to align things for easy reading. The tool tries to detect the my.cnf file by looking at the output of ps, and if it does not find the location of the file there, it tries common locations until it finds a file. Note that this file might not actually correspond with the server from which the report was generated. This can happen when the tool isn't run on the same server it's reporting on, or when detecting the location of the configuration file fails.

OPTIONS

All options after -- are passed to "mysql".

--all-databases
mysqldump y resume todas las bases de datos. Ver "--databases".
--ask-pass
Solicitar una contraseña al conectarse a MySQL.
--config
type: string

Leer esta lista de archivos de configuración separados por comas. Si se especifica, debe ser la primera opción en la línea de comandos.

--databases
type: string

mysqldump y resume esta lista de bases de datos separadas por comas. Especifique "--all-databases" en su lugar si desea volcar y resumir todas las bases de datos.

--defaults-file
short form: -F; type: string

Leer solo las opciones de mysql del archivo proporcionado. Debe proporcionar una ruta de nombre de archivo absoluta.

--help
Imprimir ayuda y salir.
--host
short form: -h; type: string

Host al que conectarse.

--list-encrypted-tables
default: false

Incluir una lista de las tablas cifradas en todas las bases de datos. Esto puede causar ralentizaciones ya que consultar

OPTIONS

--ask-pass
type: bool; default: false

Prompt for a password when connecting to MySQL. This is more secure than providing a password on the command line. The password will be prompted for only if the password is not specified.

--bind-address
type: string

Network interface to bind to when connecting. The value is a dotted quad IP address. For example, 192.168.1.1. This option is only used when the underlying database client library supports it. See the documentation for the Perl Net::MySQL module.

--config
short form: -c; type: string

Read these configuration values from the specified file. If the file is not found or is unreadable and not specified in the command line, the tool exits with an error. If specified in the command line, the file is read and then other command-line options override the file. See *percona-toolkit(7)* for details.

--count
type: int; default: 1

Number of times to collect the status counters. A value of 1 collects the counters once. A value of 0 collects the counters indefinitely.

--daemonize
type: bool; default: false

Run tool as a background daemon. This is only supported on Unix-like systems. The tool backgrounds itself, closes all open file descriptors, and writes its process ID to the file specified by the --pidfile option.

--defaults-file
short form: -f; type: string

Only read default options from the given file. Then, override them with any options specified on the command line. See *mysqld_options(5)*.

--help
Print help and exit.

The help message includes the tool’s synopsis, usage, a list of options, and their descriptions. The help message also includes notes about the tool’s risks and system requirements.

--host
short form: -h; type: string

Host name of the MySQL server.

--interval
type: float; default: 1.0

Number of seconds to wait between status collections. This option only applies when --count is greater than 1.

--password
short form: -p; type: string

Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

--pidfile
type: string

File in which to store the process ID. This option is only used when --daemonize is specified.

--port
short form: -P; type: int

Port number to use for connection.

--print-interval
type: bool; default: false

Print the interval between samples. This option only applies when --count is greater than 1.

--read-samples
type: string

Create a report from the files found in this directory.

--save-samples
type: string

Save the data files used to generate the summary in this directory.

--set-vars
type: string

Set MySQL variables in the format name=value[,name=value]... Example: "innodb_buffer_pool_size=1G,join_buffer_size=128M" This option is useful for temporarily setting session variables without changing MySQL server configuration. Be careful when setting variables, as some options may affect the server’s behavior globally.

--sleep
type: int; default: 10

Seconds to sleep when gathering status counters.

--socket
short form: -S; type: string

Socket file to use for connection.

--user
short form: -u; type: string

User for login if not current user.

--version
Print tool’s version and exit.

ENVIRONMENT

The tool respects the following environment variables. Note that you may need to set these variables in your shell environment before running the tool.

PTDEBUG
type: bool; default: false

Enable debugging output. When set to true, the tool prints verbose debugging information to STDERR. This can be useful for diagnosing problems.

SYSTEM REQUIREMENTS

This tool requires Bash v3 or newer, Perl 5.8 or newer, and binutils. These are generally already provided by most distributions. On BSD systems, it may require a mounted procfs.
