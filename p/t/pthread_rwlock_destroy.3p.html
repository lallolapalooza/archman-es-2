PTHREAD_RWLOCK_DESTROY(3P) Manual de Programador POSIX PTHREAD_RWLOCK_DESTROY(3P)

PROLOGO

Esta página del manual forma parte del Manual de Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_rwlock_destroy, pthread_rwlock_init — destruye e inicializa un objeto de bloqueo de lectura-escritura

SINOPSIS

#include <pthread.h>
int pthread_rwlock_destroy(pthread_rwlock_t *rwlock);
int pthread_rwlock_init(pthread_rwlock_t *restrict rwlock,
    const pthread_rwlockattr_t *restrict attr);
pthread_rwlock_t rwlock = PTHREAD_RWLOCK_INITIALIZER;

DESCRIPCION

La función pthread_rwlock_destroy() destruye el objeto de bloqueo de lectura-escritura referenciado por rwlock y libera cualquier recurso utilizado por el bloqueo. El efecto del uso posterior del bloqueo es indefinido hasta que el bloqueo sea reinicializado por otra llamada a pthread_rwlock_init(). Una implementación puede hacer que pthread_rwlock_destroy() establezca el objeto referenciado por rwlock a un valor inválido. Los resultados son indefinidos si pthread_rwlock_destroy() se llama cuando cualquier hilo tiene rwlock. Intentar destruir un bloqueo de lectura-escritura no inicializado resulta en un comportamiento indefinido.

La función pthread_rwlock_init() asignará los recursos necesarios para utilizar el bloqueo de lectura-escritura referenciado por rwlock y lo inicializará en un estado desbloqueado con los atributos referenciados por attr. Si attr es NULL, se utilizarán los atributos de bloqueo de lectura-escritura predeterminados; el efecto es el mismo que pasar la dirección de un objeto de atributos de bloqueo de lectura-escritura predeterminado. Una vez inicializado, el bloqueo puede utilizarse cualquier número de veces sin necesidad de reinicializarlo. Los resultados son indefinidos si se llama a pthread_rwlock_init() especificando un bloqueo de lectura-escritura ya inicializado. Los resultados son indefinidos si se utiliza un bloqueo de lectura-escritura sin haberlo inicializado primero.

Si la función pthread_rwlock_init() falla, rwlock no se inicializará y el contenido de rwlock es indefinido.

Consulte la Sección 2.9.9, Copias de Objetos de Sincronización y Mapeos Alternativos para obtener requisitos adicionales.

En casos donde los atributos predeterminados de bloqueo de lectura-escritura sean apropiados, la macro PTHREAD_RWLOCK_INITIALIZER puede utilizarse para inicializar bloqueos de lectura-escritura. El efecto será equivalente a la inicialización dinámica mediante una llamada a pthread_rwlock_init() con el parámetro attr especificado como NULL, excepto que no se realizan comprobaciones de errores.

El comportamiento es indefinido si el valor especificado por el argumento attr a pthread_rwlock_init() no hace referencia a un objeto de atributos de bloqueo de lectura-escritura inicializado.

VALOR DE RETORNO

Si tiene éxito, las funciones pthread_rwlock_destroy() y pthread_rwlock_init() devolverán cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_rwlock_init() fallará si:

EAGAIN
El sistema carecía de los recursos necesarios (aparte de memoria) para inicializar otro bloqueo de lectura-escritura.
ENOMEM
No hay suficiente memoria para inicializar el bloqueo de lectura-escritura.
EPERM
El llamante no tiene el privilegio para realizar la operación.

Estas funciones no devolverán un código de error de [EINTR].

USO DE APLICACION

Las aplicaciones que utilizan estas y otras funciones relacionadas de bloqueo de lectura-escritura pueden estar sujetas a inversión de prioridad, como se discute en el volumen de Definiciones Base de POSIX.1‐2017, Sección 3.291, Inversión de Prioridad.

RACIONALE

Si una implementación detecta que el valor especificado por el argumento rwlock a pthread_rwlock_destroy() no hace referencia a un objeto de bloqueo de lectura-escritura inicializado, se recomienda que la función falle e informe un error [EINVAL].

Si una implementación detecta que el valor especificado por el argumento attr a pthread_rwlock_init() no hace referencia a un objeto de atributos de bloqueo de lectura-escritura inicializado, se recomienda que la función falle e informe un error [EINVAL].

Si una implementación detecta que el valor especificado por el argumento rwlock a pthread_rwlock_destroy() o pthread_rwlock_init() se refiere a un objeto de bloqueo de lectura-escritura bloqueado, o detecta que el valor especificado por el argumento rwlock a pthread_rwlock_init() se refiere a un objeto de bloqueo de lectura-escritura ya inicializado, se recomienda que la función falle e informe un error [EBUSY].

    SYNOPSIS

    #include <pthread.h>

    int pthread_rwlock_destroy(pthread_rwlock_t *rwlock);

    DESCRIPTION

    The pthread_rwlock_destroy() function shall destroy the read-write lock object referenced by rwlock; the memory locations used by the lock object become invalid. It is undefined which thread will be able to acquire the lock when a read-write lock is initialized with pthread_rwlock_init() and then destroyed using pthread_rwlock_destroy().

    If any threads are still blocked waiting for access to the read-write lock when pthread_rwlock_destroy() is called, the results are undefined.

    The behavior is undefined if the value referred to by rwlock does not refer to an initialized read-write lock object.

    After a read-write lock object has been destroyed, it can be re-initialized to its initial state by another call to pthread_rwlock_init(). Attempting to use a destroyed read-write lock without re-initialization results in undefined behavior.

    RETURN VALUE

    On success, pthread_rwlock_destroy() shall return 0. Otherwise, on error, it shall return an error number to indicate the error.

    ERRORS

    No errors are defined for pthread_rwlock_destroy().
