pthread_setconcurrency(3) Manual de funciones de biblioteca pthread_setconcurrency(3)

NOMBRE

pthread_setconcurrency, pthread_getconcurrency - establecer/obtener el nivel de concurrencia

BIBLIOTECA

Biblioteca de hilos POSIX (libpthread, -lpthread)

SINOPSIS

#include <pthread.h>
int pthread_setconcurrency(int new_level);
int pthread_getconcurrency(void);

DESCRIPCIÓN

La función pthread_setconcurrency() informa a la implementación del nivel de concurrencia deseado por la aplicación, especificado en new_level. La implementación toma esto solo como una pista: POSIX.1 no especifica el nivel de concurrencia que debe proporcionarse como resultado de llamar a pthread_setconcurrency().

Especificar new_level como 0 instruye a la implementación a gestionar el nivel de concurrencia como lo considere apropiado.

pthread_getconcurrency() devuelve el valor actual del nivel de concurrencia para este proceso.

VALOR DE RETORNO

En caso de éxito, pthread_setconcurrency() devuelve 0; en caso de error, devuelve un número de error distinto de cero.

pthread_getconcurrency() siempre tiene éxito, devolviendo el nivel de concurrencia establecido por una llamada anterior a pthread_setconcurrency(), o 0 si pthread_setconcurrency() no se ha llamado previamente.

ERRORES

pthread_setconcurrency() puede fallar con el siguiente error:

EINVAL
new_level es negativo.

POSIX.1 también documenta un error EAGAIN ("el valor especificado por new_level provocaría que un recurso del sistema se excediera").

ESTÁNDARES

POSIX.1-2008.

HISTORIA

glibc 2.1. POSIX.1-2001.

NOTAS

El nivel de concurrencia predeterminado es 0.

Los niveles de concurrencia solo son significativos para las implementaciones de hilos M:N, donde en cualquier momento un subconjunto del conjunto de hilos a nivel de usuario de un proceso puede estar vinculado a un número menor de entidades de planificación del kernel. Establecer el nivel de concurrencia permite a la aplicación dar al sistema una pista sobre el número de entidades de planificación del kernel que deben proporcionarse para la ejecución eficiente de la aplicación.

Tanto LinuxThreads como NPTL son implementaciones de hilos 1:1, por lo que establecer el nivel de concurrencia no tiene significado. En otras palabras, en Linux, estas funciones solo existen por compatibilidad con otros sistemas y no tienen ningún efecto en la ejecución de un programa.
