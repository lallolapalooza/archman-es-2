pthread_join(3) Manual de funciones de biblioteca pthread_join(3)

NOMBRE

pthread_join - esperar a que termine un hilo

BIBLIOTECA

Biblioteca de hilos POSIX (libpthread, -lpthread)

SINOPSIS

#include <pthread.h>
int pthread_join(pthread_t thread, void **retval);

DESCRIPCIÓN

La función pthread_join() espera a que el hilo especificado por thread termine. Si ese hilo ya ha terminado, entonces pthread_join() regresa inmediatamente. El hilo especificado por thread debe ser un hilo unible.

Si retval no es NULL, entonces pthread_join() copia el estado de salida del hilo destino (es decir, el valor que el hilo destino suministró a pthread_exit(3)) en la ubicación apuntada por retval. Si el hilo destino fue cancelado, entonces PTHREAD_CANCELED se coloca en la ubicación apuntada por retval.

Si múltiples hilos intentan unirse simultáneamente con el mismo hilo, los resultados son indefinidos. Si el hilo que llama a pthread_join() es cancelado, entonces el hilo destino permanecerá unible (es decir, no se desacoplará).

VALOR DE RETORNO

En caso de éxito, pthread_join() regresa 0; en caso de error, regresa un número de error.

ERRORES

EDEADLK
Se detectó un bloqueo mutuo (p. ej., dos hilos intentaron unirse entre sí); o thread especifica el hilo que llama.
EINVAL
thread no es un hilo unible.
EINVAL
Otro hilo ya está esperando para unirse con este hilo.
ESRCH
No se pudo encontrar ningún hilo con el ID thread.

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, consulte attributes(7).

Interfaz Atributo Valor
pthread_join () Seguridad de hilos MT-Safe

ESTÁNDARES

POSIX.1-2008.

HISTORIA

POSIX.1-2001.

NOTAS

Después de una llamada exitosa a pthread_join(), se garantiza al llamador que el hilo destino ha terminado. El llamador puede entonces optar por realizar cualquier limpieza necesaria después de la terminación del hilo (p. ej., liberar memoria u otros recursos que se asignaron al hilo destino).

Intentar unirse con un hilo que ya ha sido unido previamente da como resultado un comportamiento indefinido.

No unirse con un hilo que es unible (es decir, uno que no está desacoplado) produce un "hilo zombie". Evite hacer esto, ya que cada hilo zombie consume algunos recursos del sistema, y cuando se acumulan suficientes hilos zombie, ya no será posible crear nuevos hilos (o procesos).

No existe un análogo de pthreads para waitpid(-1, &status, 0), es decir, "unirse con cualquier hilo terminado". Si cree que necesita esta funcionalidad, probablemente necesite reconsiderar el diseño de su aplicación.

Todos los hilos de un proceso son pares: cualquier hilo puede unirse con cualquier otro hilo del proceso.

EJEMPLOS

Consulte pthread_create(3).

VER TAMBIÉN
