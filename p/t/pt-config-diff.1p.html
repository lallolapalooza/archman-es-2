NOMBRE

pt-config-diff - Compara diferencias en archivos de configuración de MySQL y variables del servidor.

SINOPSIS

Uso: pt-config-diff [OPCIONES] CONFIG CONFIG [CONFIG...]

pt-config-diff compara diferencias en archivos de configuración de MySQL y variables del servidor. CONFIG puede ser un nombre de archivo o un DSN. Se deben proporcionar al menos dos fuentes de CONFIG. Al igual que con la utilidad Unix diff estándar, no hay salida si no hay diferencias.

Compara la configuración del host1 de SHOW VARIABLES con el host2:

pt-config-diff h=host1 h=host2

Compara la configuración de la sección [mysqld] en my.cnf con la configuración del host1:

pt-config-diff /etc/my.cnf h=host1

Compara la sección [mysqld] de dos archivos de opciones:

pt-config-diff /etc/my-small.cnf /etc/my-large.cnf

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien testeado, pero todas las herramientas de bases de datos pueden suponer un riesgo para el sistema y el servidor de bases de datos. Antes de usar esta herramienta, por favor:

  • Lea la documentación de la herramienta.
  • Revise los "BUGS" conocidos de la herramienta.
  • Pruebe la herramienta en un servidor no productivo.
  • Haga una copia de seguridad de su servidor productivo y verifique las copias de seguridad.

DESCRIPCIÓN

pt-config-diff compara configuraciones de MySQL examinando los valores de las variables del sistema del servidor de dos o más fuentes de CONFIG especificadas en la línea de comandos. Una fuente de CONFIG puede ser un DSN o un archivo que contenga la salida de "mysqld --help --verbose", "my_print_defaults", "SHOW VARIABLES", o un archivo de opciones (por ejemplo, my.cnf).

Para cada DSN de CONFIG, pt-config-diff se conecta a MySQL y obtiene variables y valores ejecutando "SHOW /*!40103 GLOBAL*/ VARIABLES". Esta es una "configuración activa" porque muestra los valores del servidor con los que MySQL se está ejecutando activamente (actualmente).

Solo se comparan las variables que todas las fuentes de CONFIG tienen, ya que si una variable no está presente, no podemos conocer ni adivinar de forma segura su valor. Por ejemplo, si compara un archivo de opciones (por ejemplo, my.cnf) con una configuración activa (es decir, SHOW VARIABLES desde un DSN de CONFIG), el archivo de opciones probablemente solo tendrá unas pocas variables, mientras que la configuración activa tiene todas las variables. Solo se comparan los valores de las variables presentes en ambas configuraciones.

Los archivos de opciones y los DSN de configuración proporcionan los mejores resultados.

SALIDA

No hay salida cuando no hay diferencias. Cuando hay diferencias, pt-config-diff imprime un informe en STDOUT que se parece a lo siguiente:

2 config differences
Variable                  my.source.cnf   my.replica.cnf
========================= =============== ===============
datadir                   /tmp/12345/data /tmp/12346/data
port                      12345           12346

Comparar variables de MySQL es difícil porque hay muchas variaciones y sutilezas entre las muchas versiones y distribuciones de MySQL. Cuando una comparación falla, la herramienta imprime una advertencia en STDERR, como la siguiente:

Comparing log_error values (mysqld.log, /tmp/12345/data/mysqld.log)
caused an error: Argument "/tmp/12345/data/mysqld.log" isn't numeric
in numeric eq (==) at ./pt-config-diff line 2311.

Por favor, informe de estas advertencias para que las funciones de comparación puedan mejorarse.

ESTADO DE SALIDA

pt-config-diff sale con un estado de salida cero cuando no hay diferencias, y 1 si las hay.

NAME

pt-config-diff - checks for differences in MySQL configuration files.

SYNOPSIS

pt-config-diff [OPTIONS] [DSN]

RISKS

This tool has no known risks.

DESCRIPTION

This tool compares MySQL configuration files and prints the differences. It supports several methods for obtaining the configuration files:

  • MySQL options files: It can read configuration from MySQL options files, such as my.cnf.
  • MySQL server: It can query the MySQL server for its current configuration variables.
  • Percona Server configurations: It can compare Percona Server configuration specific variables.

The tool is useful for identifying differences in configurations across multiple servers, or for checking if a configuration has changed after an upgrade or manual modification.

OUTPUT

The tool prints differences between the configuration files in a human-readable format. It highlights added, removed, or modified parameters.

EXIT STATUS

The exit status is 0 if there are no differences found or if no errors occurred. It is greater than 0 if differences are found or if an error occurred.

OPTIONS

--help
Show help message and exit.
--version
Show program version and exit.
--config FILE
Read this tool's configuration from a file. This option is useful when you have a complex configuration that you want to reuse.
--defaults-file FILE
Read MySQL configuration from the specified file. This option can be specified multiple times. For example: 
pt-config-diff --defaults-file my.cnf --defaults-file other.cnf

This option implies that you want to compare the specified files with each other, or with the configuration on a MySQL server. See DSN OPTIONS for how to specify a DSN for a MySQL server.

--print-all
Print all configuration parameters, including those that are not different.
--skip-real-defaults
Do not read default values from the server. This is useful when you only want to compare specified options files.
--why-not
Explain why Percona Toolkit's version check is disabled.
--version-check[={true|false}]

Enable or disable Percona Toolkit's version check, which pings Percona to check for a new version of the tool. Default is true.

When enabled, Percona Toolkit checks for new versions by connecting to http://api.percona.com. This check is performed once a day, and if a new version is found, it is printed to STDOUT. The version check is asynchronous and does not block the tool's operation. The check is also performed securely using SSL.

A critical bug was found in version 5.5.25. The fix was released as version 5.5.25a. This critical bug was fixed and was re-released as 5.5.25a.

A secure connection to Percona's Version Check database server is done to perform these checks. Each request is logged by the server, including software version numbers and unique ID of the checked system. The ID is generated by the Percona Toolkit installation script or when the Version Check database call is done for the first time.

Any updates or known problems are printed to STDOUT before the tool's normal output. This feature should never interfere with the normal operation of the tool.

For more information, visit https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

DSN OPTIONS

These DSN options are used to create a DSN. Each option is given like "option=value". The options are case-sensitive, so P and p are not the same option. There cannot be whitespace before or after the "=" and if the value contains whitespace it must be quoted. DSN options are comma-separated. See the percona-toolkit manpage for full details.

  • A

    dsn: charset; copy: yes

    Default character set.

  • D

    dsn: database; copy: yes

    Default database.

  • F

    dsn: mysql_read_default_file; copy: yes

    Only read default options from the given file

  • h

    dsn: host; copy: yes

    Connect to host.

  • p

    dsn: password; copy: yes

    Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

  • P

    dsn: port; copy: yes

    Port number to use for connection.

  • S

    dsn: mysql_socket; copy: yes

    Socket file to use for connection.

  • u

    dsn: user; copy: yes

    User for login if not current user.

  • s

    dsn: mysql_ssl; copy: yes

    Create SSL connection

ENVIRONMENT

The environment variable "PTDEBUG" enables verbose debugging output to STDERR. To enable debugging and capture all output to a file, run the tool like:

PTDEBUG=1 pt-config-diff ... > FILE 2>&1

Be careful: debugging output is voluminous and can generate several megabytes of output.

ATTENTION

Using <PTDEBUG> might expose passwords. When debug is enabled, all command line parameters are shown in the output.

SYSTEM REQUIREMENTS

You need Perl, DBI, DBD::mysql, and some core packages that ought to be installed in any reasonably new version of Perl.
