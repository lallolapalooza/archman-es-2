NOMBRE

pt-kill - Mata consultas MySQL que coinciden con ciertos criterios.

SINOPSIS

Uso: pt-kill [OPCIONES] [DSN]

pt-kill mata conexiones MySQL. pt-kill se conecta a MySQL y obtiene consultas de SHOW PROCESSLIST a menos que se proporcione la opción "--test-matching". De lo contrario, lee consultas de uno o más archivos que contienen la salida de SHOW PROCESSLIST. Si el archivo es -, pt-kill lee desde STDIN.

Mata consultas que se ejecutan durante más de 60 s:

pt-kill --busy-time 60 --kill

Imprime, sin matar, consultas que se ejecutan durante más de 60 s:

pt-kill --busy-time 60 --print

Busca procesos inactivos y los mata todos cada 10 s:

pt-kill --match-command Sleep --kill --victims all --interval 10

Imprime todos los procesos de inicio de sesión:

pt-kill --match-state login --print --victims all

Ver qué consultas en la lista de procesos ahora mismo coincidirían:

mysql -e "SHOW PROCESSLIST" > proclist.txt
pt-kill --test-matching proclist.txt --busy-time 60 --print

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien verificado, pero todas las herramientas de bases de datos pueden suponer un riesgo para el sistema y el servidor de base de datos. Antes de usar esta herramienta, por favor:

  • Lea la documentación de la herramienta
  • Revise los "BUGS" conocidos de la herramienta
  • Pruebe la herramienta en un servidor no productivo
  • Haga una copia de seguridad de su servidor de producción y verifique las copias de seguridad

DESCRIPCIÓN

pt-kill captura consultas de SHOW PROCESSLIST, las filtra y luego las mata o las imprime. Esto también se conoce como un "francotirador de consultas lentas" en algunos círculos. La idea es vigilar las consultas que podrían estar consumiendo demasiados recursos y matarlas.

Por brevedad, hablamos de matar consultas, pero es posible que solo se impriman (o se realice alguna otra acción futura) dependiendo de las opciones que se proporcionen.

Normalmente, pt-kill se conecta a MySQL para obtener consultas de SHOW PROCESSLIST. Alternativamente, puede leer la salida de SHOW PROCESSLIST de archivos. En este caso, pt-kill no se conecta a MySQL y "--kill" no tiene ningún efecto. Debería usar "--print" en su lugar al leer archivos. La capacidad de leer un archivo con "--test-matching" le permite capturar SHOW PROCESSLIST y probarlo más tarde con pt-kill para asegurarse de que sus coincidencias matan las consultas adecuadas. Hay muchas reglas especiales que seguir, como "no matar hilos de replicación", ¡así que tenga cuidado de no matar algo importante!

Dos opciones importantes a conocer son "--busy-time" y "--victims". Primero, mientras que la mayoría de las opciones de coincidencia/filtro coinciden con su valor correspondiente de SHOW PROCESSLIST (por ejemplo, "--match-command" coincide con el valor Command de una consulta), el valor Time se coincide con "--busy-time". Vea también "--interval".

Segundo, "--victims" controla qué consultas coincidentes de cada clase se matan. Por defecto, la consulta coincidente con el valor Time más alto se mata (la consulta más antigua). Consulte la siguiente sección, "AGRUPAR, COINCIDIR Y MATAR", para obtener más detalles.

Normalmente necesita especificar al menos una opción "--match", de lo contrario ninguna consulta coincidirá. O, puede especificar "--match-all" para coincidir con todas las consultas que no sean ignoradas por una opción "--ignore".

AGRUPAR, COINCIDIR Y MATAR

Las consultas pasan por varios pasos para determinar cuáles exactamente se matarán (o imprimirán, la acción que sea). Comprender estos pasos le ayudará a coincidir con precisión las consultas que desea.

El primer paso es agrupar las consultas en clases. La opción "--group-by" controla la agrupación. Por defecto, esta opción no tiene valor, por lo que todas las consultas se agrupan en una clase predeterminada. Todos los tipos de coincidencia y filtrado (el siguiente paso) se aplican por clase. Por lo tanto, puede que necesite agrupar consultas para coincidir/filtrar algunas clases pero no otras.

El segundo paso es la coincidencia. La coincidencia implica filtrado, ya que si una consulta no coincide con ciertos criterios, se elimina de su clase. La coincidencia ocurre para cada clase. Primero, las consultas se filtran de su clase por las diversas opciones de "Coincidencias de Consulta" como "--match-user". Luego, clases enteras se filtran por las diversas opciones de "Coincidencias de Clase" como "--query-count".

El tercer paso es la selección de víctimas, es decir, qué consultas coincidentes en cada clase matar. Esto se controla mediante la opción "--victims". Aunque muchas consultas en una clase pueden coincidir, es posible que solo desee matar la consulta más antigua, o todas las consultas, etc.

El cuarto y último paso es tomar alguna acción sobre todas las consultas coincidentes de todas las clases. Las opciones de "Acciones" especifican qué acciones se tomarán. En este paso, ya no hay clases, solo una lista única de consultas para matar, imprimir, etc.

pt-kill matará todas las consultas que coincidan CON CUALQUIERA de los criterios especificados (OR lógico). Por ejemplo, usando:

--busy-time 114 --match-command 'Query|Execute'

matará todas las consultas que tengan busy-time > 114 "O" donde el comando sea "Query" o "Execute".

Si desea matar solo las consultas donde "busy-time" sea mayor que 114 y el comando sea Query o Execute, necesita usar "--kill-busy-commands":

--busy-time 114 --kill-busy-commands 'Query|Execute'

SALIDA

Si solo se proporciona "--kill", no hay salida. Si solo se proporciona "--print", se imprimirá una marca de tiempo y una sentencia KILL para cada consulta que hubiera sido matada, como:

# 2009-07-15T15:04:01 KILL 8 (Query 42 sec) SELECT * FROM huge_table

La línea muestra una marca de tiempo, el Id de la consulta (8), su Tiempo (42 segundos) y su Info (generalmente la consulta SQL).

Si se proporcionan tanto "--kill" como "--print", se matarán las consultas coincidentes y se imprimirá una línea para cada una, similar a la anterior.

Cualquier comando ejecutado por "--execute-command" es responsable de su propia salida y registro. Después de ser ejecutado, pt-kill no tiene control ni interacción con el comando.

--filter
tipo: cadena

Descarta eventos para los que este código Perl no devuelve true.

Esta opción es una cadena de código Perl o un archivo que contiene código Perl que se compila en una subrutina con un argumento: $event. Esto es un hashref. Si el valor proporcionado es un archivo legible, entonces pt-kill lee todo el archivo y utiliza su contenido como código. El archivo no debe contener una línea shebang (#!/usr/bin/perl).

Si el código devuelve true, la cadena de callbacks continúa; de lo contrario, termina. El código es la última declaración en la subrutina, aparte de "return $event". La plantilla de la subrutina es:

sub { $event = shift; filter && return $event; }

Los filtros proporcionados en la línea de comandos se envuelven entre paréntesis, como "( filter )". Para filtros complejos y de varias líneas, debe colocar el código dentro de un archivo para que no se envuelva entre paréntesis. En cualquier caso, el filtro debe producir código sintácticamente válido dado la plantilla. Por ejemplo, una rama if-else proporcionada en la línea de comandos no sería válida:

--filter 'if () { } else { }'  # INCORRECTO

Dado que se proporciona en la línea de comandos, la rama if-else se envolvería entre paréntesis, lo que no es sintácticamente válido. Por lo tanto, para lograr algo más complejo como esto, se requeriría colocar el código en un archivo, por ejemplo, filter.txt:

my $event_ok; if (...) { $event_ok=1; } else { $event_ok=0; } $event_ok

Luego especifique "--filter filter.txt" para leer el código de filter.txt.

Si el código del filtro no compila, pt-kill fallará con un error. Si el código del filtro compila, aún puede ocurrir un error en tiempo de ejecución si el código intenta hacer algo incorrecto (como comparar con un valor indefinido). pt-kill no proporciona salvaguardas, ¡así que codifique con cuidado!

Es permisible que el código tenga efectos secundarios (alterar $event).

--group-by
tipo: cadena

Aplica coincidencias a cada clase de consultas agrupadas por esta columna de SHOW PROCESSLIST. Además de las columnas básicas de SHOW PROCESSLIST (user, host, command, state, etc.), las consultas se pueden hacer coincidir por "fingerprint", que abstrae la consulta SQL en la columna "Info".

Por defecto, las consultas no se agrupan, por lo que las coincidencias y las acciones se aplican a todas las consultas. El agrupamiento permite que las coincidencias y las acciones se apliquen a clases de consultas similares, si alguna consulta de la clase coincide.

Por ejemplo, detectar estampidas de caché (ver "all-but-oldest" en "--victims" para una explicación de ese término) requiere que las consultas se agrupen por el "arg". Esto crea clases de consultas idénticas (sin comentarios). Por lo tanto, las consultas "SELECT c FROM t WHERE id=1" y "SELECT c FROM t WHERE id=1" se agrupan en la misma clase, pero la consulta "SELECT c FROM t WHERE id=3" no es idéntica a las dos primeras consultas, por lo que se agrupa en otra clase. Luego, cuando se especifica "--victims" "all-but-oldest", se matan todas menos la consulta más antigua de cada clase, para cada clase de consultas que coincidan con los criterios de coincidencia.

--[no]version-check
predeterminado: sí

Comprueba la última versión de Percona Toolkit, MySQL y otros programas.

Esta es una característica estándar de "comprobar actualizaciones automáticamente", con dos características adicionales. Primero, la herramienta comprueba su propia versión y también las versiones del siguiente software: sistema operativo, Percona Monitoring and Management (PMM), MySQL, Perl, controlador MySQL para Perl (DBD::mysql) y Percona Toolkit. Cualquier actualización o problema conocido se imprime en STDOUT antes de la salida normal de la herramienta. Esta característica nunca debería interferir con el funcionamiento normal de la herramienta.

Para más información, visita https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

--victims
tipo: string; predeterminado: oldest

Cuáles de las consultas coincidentes en cada clase serán terminadas. Después de que las clases hayan coincidido/filtrado, esta opción especifica cuáles de las consultas coincidentes en cada clase serán terminadas (o impresas, etc.). Los siguientes valores son posibles:

oldest
Solo termina la única consulta más antigua. Esto es para evitar terminar consultas que no son realmente de larga duración, sino que están esperando mucho tiempo. Esto ordena las consultas coincidentes por Tiempo y termina la que tiene el valor de Tiempo más alto.
all
Termina todas las consultas de la clase.
all-but-oldest
Termina todas excepto la consulta más antigua. Esta es la inversa del valor "oldest".

Este valor se puede utilizar para prevenir "cache stampedes" (estampidas de caché), la condición en la que varias consultas idénticas se ejecutan y crean un backlog mientras la primera consulta intenta terminar. Dado que todas las consultas son idénticas, se terminan todas excepto la primera para que pueda completarse y llenar la caché.

--wait-after-kill
tipo: tiempo

Espera después de terminar una consulta, antes de buscar más para terminar. El propósito de esto es dar a las consultas bloqueadas una oportunidad de ejecutarse, para que no terminemos una consulta que está bloqueando a muchas otras y luego terminemos las otras inmediatamente después.

--wait-before-kill
tipo: tiempo

Espera antes de terminar una consulta. El propósito de esto es dar a "--execute-command" una oportunidad de ver la consulta coincidente y recopilar otra información de MySQL o del sistema antes de que sea terminada.

COINCIDENCIAS DE CONSULTAS

Estas opciones filtran las consultas de sus clases. Si una consulta no coincide, se elimina de su clase. Las opciones "--ignore" tienen prioridad. Las coincidencias de comando, db, host, etc. corresponden a las columnas devueltas por SHOW PROCESSLIST: Command, db, Host, etc. Todas las coincidencias de patrones distinguen entre mayúsculas y minúsculas por defecto, pero se pueden hacer que no distingan entre mayúsculas y minúsculas especificando un patrón regex como "(?i-xsm:select)".

Ver también "GROUP, MATCH AND KILL".

--busy-time
tipo: tiempo; grupo: Query Matches

Coincide con consultas que se han estado ejecutando durante más tiempo que este tiempo. Las consultas deben estar en estado Command=Query. Esto coincide con el valor Time de una consulta tal como lo informa SHOW PROCESSLIST.

--idle-time
tipo: tiempo; grupo: Query Matches

Coincide con consultas que han estado inactivas/durmiendo durante más tiempo que este tiempo. Las consultas deben estar en estado Command=Sleep. Esto coincide con el valor Time de una consulta tal como lo informa SHOW PROCESSLIST.

--ignore-command
tipo: string; grupo: Query Matches

Ignora consultas cuyo Comando coincide con esta regex de Perl.

Ver "--match-command".

--ignore-db
tipo: string; grupo: Query Matches

Ignora consultas cuya db (base de datos) coincide con esta regex de Perl.

Ver "--match-db".

--ignore-host
tipo: string; grupo: Query Matches

Ignora consultas cuyo Host coincide con esta regex de Perl.

El valor Host a menudo incluye el puerto, como "host:puerto".

--ignore-info
tipo: string; grupo: Query Matches

Ignora consultas cuya Info (consulta) coincide con esta regex de Perl.

Ver "--match-info".

--[no]ignore-self
predeterminado: sí; grupo: Query Matches

No termina la propia conexión de pt-kill.

--ignore-state
tipo: string; grupo: Query Matches; predeterminado: Locked

Ignora consultas cuyo Estado coincide con esta regex de Perl. El valor predeterminado es evitar que se terminen hilos si están bloqueados esperando a otro hilo.

Ver "--match-state".

--ignore-user
tipo: string; grupo: Query Matches

Ignora consultas cuyo usuario coincide con esta regex de Perl.

Ver "--match-user".

--match-all
grupo: Query Matches

Coincide con todas las consultas que no son ignoradas. Si no se especifican opciones de ignorar, entonces todas las consultas coinciden (excepto los hilos de replicación, a menos que también se especifique "--replication-threads"). Esta opción le permite especificar coincidencias negativas, es decir, "coincidir con todas las consultas *excepto*..." donde las excepciones se definen especificando varias opciones de "--ignore".

Esta opción *no* es lo mismo que "--victims" "all". Esta opción coincide con todas las consultas dentro de una clase, mientras que "--victims" "all" especifica que todas las consultas coincidentes en una clase (sin importar cómo coincidieron) serán terminadas. Normalmente, sin embargo, las dos se usan juntas porque si, por ejemplo, especifica "--victims" "oldest", entonces aunque todas las consultas puedan coincidir, solo la más antigua será terminada.

--match-command
tipo: string; grupo: Query Matches

Coincide solo con consultas cuyo Comando coincide con esta regex de Perl.

Los valores comunes de Comando son:

Query
Sleep
Binlog Dump
Connect
Delayed insert
Execute
Fetch
Init DB
Kill
Prepare
Processlist
Quit
Reset stmt
Table Dump

Ver https://dev.mysql.com/doc/refman/en/general-thread-states.html para una lista completa y descripción de los valores de Comando.

--match-db
tipo: string; grupo: Query Matches

Coincide solo con consultas cuya db (base de datos) coincide con esta regex de Perl.

--match-host
tipo: string; grupo: Query Matches

Coincide solo con consultas cuyo Host coincide con esta regex de Perl.

El valor Host a menudo incluye el puerto, como "host:puerto".

--match-info
tipo: string; grupo: Query Matches

Coincide solo con consultas cuya Info (consulta) coincide con esta regex de Perl.

La columna Info de la lista de procesos muestra la consulta que se está ejecutando o NULL si no se está ejecutando ninguna consulta.

tipo: string; grupo: Query Matches

NAME

pt-kill - kill MySQL queries automatically

SYNOPSIS

pt-kill --print --match-statement 'SELECT.*sleep' h=localhost,u=root,p=foobar
pt-kill --kill --match-user ^repl h=db1,p=secret
pt-kill --kill --interval 1 --busy-time 10 h=db1,p=secret

DESCRIPTION

pt-kill is a tool that monitors the MySQL process list and kills queries based on arbitrary criteria. This can be used to automatically kill long-running queries, lock-inducing queries, queries matching specific patterns, and more. It is intended to be run as a daemon, periodically checking the process list and taking action.

The tool is designed to be flexible and powerful. It can match queries based on a wide variety of criteria, and take various actions, including killing queries, killing connections, or executing arbitrary commands.

See also "GROUP, MATCH AND KILL".

GROUP, MATCH AND KILL

pt-kill works by matching queries against a set of criteria and then taking actions. The matching and actions can be specified in a number of ways:

The --match-* options specify criteria for individual queries.
The --[no]all-databases option enables/disables matching across all databases.
The --[no]grep-all-text option enables/disables grep-like matching on all text.
The --[no]grep-wild-string option enables/disables matching on wild-string comparisons.
The --[no]replication-threads option matches replication threads.
The --test-matching option tests matching options.
The --group-by option groups queries into classes.
The --[no]ignore-self option ignores self-matched queries.
The --run-time and --interval options control how often pt-kill runs.
The --busy-time option specifies the maximum allowed running time for queries.
The --kill-busy-commands option specifies which commands are watched/killed if they run for too long.
The --print, --execute-command, --kill, and --kill-query options specify the actions to take on matched queries.

When "--group-by" is specified, queries are grouped into classes. The class matches (e.g. "--any-busy-time", "--each-busy-time", "--query-count") are applied to these classes. If no "--group-by" is specified, all queries are in a single default class and the class matches apply to the entire process list.

OPTIONS

MATCHING OPTIONS

These options specify criteria for matching queries. Multiple "--match-*" options are ANDed together.

--[no]all-databases
default: no

When specified, queries from all databases are considered. Otherwise, only queries from the default database are considered.

--busy-time
type: time; default: 0

Match queries that have been running longer than this value. The default is 0 which means this match is disabled.

See also "--kill-busy-commands".

--[no]grep-all-text
default: no

When specified, pt-kill will grep all text fields in the process list. This can be slower, but might catch some queries that would otherwise be missed. This option is a shortcut for specifying multiple "--match-regex" options.

--[no]grep-wild-string
default: no

When specified, pt-kill will match queries that contain wild-string comparisons. This can be useful for finding queries that use LIKE operators with wildcard characters.

--group-by
type: string

Group queries by the specified column. For example, "--group-by User,Host" will group queries by user and host. This option is useful for applying actions to groups of queries rather than individual queries.

--[no]ignore-self
default: yes

When specified, pt-kill will ignore queries that it runs itself. This is useful to prevent pt-kill from killing its own queries.

--interval
type: time; default: 1

Check the process list every interval seconds. The default is 1 second.

--match-argument
type: string

Match queries where the argument matches the specified string.

--match-command
type: string

Match queries where the command matches the specified string.

--match-db
type: string

Match queries that are running against the specified database.

--match-host
type: string

Match queries that are running from the specified host.

--match-info-regex
type: regex

Match queries where the info column matches the specified regular expression.

--match-processlist-id
type: int

Match queries where the processlist id matches the specified ID.

--match-query-regex
type: regex

Match queries where the query matches the specified regular expression.

Example: "--match-query-regex 'SELECT.*SLEEP\(10\)'" matches queries that contain "SELECT ... SLEEP(10)".

--match-state-regex
type: regex

Match queries where the state matches the specified regular expression.

--match-user
type: string

Match queries that are running from the specified user.

--match-wild-status
type: string

Match queries that have a status matching the specified wild-string.

--print-all-matched

Print all matched queries to STDOUT. This is useful for debugging and for seeing what would be killed.

--print-match-digest

Print the query digest of all matched queries to STDOUT. This is useful for identifying duplicate queries.

--run-time
type: time; default: 0

Run pt-kill only if at least one query has been running longer than this value. The default is 0 which means this check is disabled.

This option is disabled if "--test-matching" is specified.

--[no]replication-threads
default: no

By default, matches do not apply to replication threads; i.e. replication threads are completely ignored. Specifying this option allows matches to match (and potentially kill) replication threads on replication sources and replicas.

--test-matching
type: array; group: Query Matches

Files with processlist snapshots to test matching options against. Since the matching options can be complex, you can save snapshots of processlist in files, then test matching options against queries in those files.

This option disables "--run-time", "--interval", and "--[no]ignore-self".

CLASS MATCHES

These matches apply to entire query classes. Classes are created by specifying the "--group-by" option, else all queries are members of a single, default class.

See also "GROUP, MATCH AND KILL".

--any-busy-time
type: time; group: Class Matches

Match query class if any query has been running for longer than this time. "Longer than" means that if you specify 10, for example, the class will only match if there's at least one query that has been running for greater than 10 seconds.

See "--each-busy-time" for more details.

--each-busy-time
type: time; group: Class Matches

Match query class if each query has been running for longer than this time. "Longer than" means that if you specify 10, for example, the class will only match if each and every query has been running for greater than 10 seconds.

See also "--any-busy-time" (to match a class if ANY query has been running longer than the specified time) and "--busy-time".

--query-count
type: int; group: Class Matches

Match query class if it has at least this many queries. When queries are grouped into classes by specifying "--group-by", this option causes matches to apply only to classes with at least this many queries. If "--group-by" is not specified then this option causes matches to apply only if there are at least this many queries in the entire SHOW PROCESSLIST.

--verbose
short form: -v

Print information to STDOUT about what is being done.

ACTIONS

These actions are taken for every matching query from all classes. The actions are taken in this order: "--print", "--execute-command", "--kill" / "--kill-query". This order allows "--execute-command" to see the output of "--print" and the query before "--kill" / "--kill-query". This may be helpful because pt-kill does not pass any information to "--execute-command".

See also "GROUP, MATCH AND KILL".

--execute-command
type: string; group: Actions

Execute this command when a query matches.

After the command is executed, pt-kill has no control over it, so the command is responsible for its own info gathering, logging, interval, etc. The command is executed each time a query matches, so be careful that the command behaves well when multiple instances are ran. No information from pt-kill is passed to the command.

See also "--wait-before-kill".

--kill
group: Actions

Kill the connection for matching queries.

This option makes pt-kill kill the connections (a.k.a. processes, threads) that have matching queries. Use "--kill-query" if you only want to kill individual queries and not their connections.

Unless "--print" is also given, no other information is printed that shows that pt-kill matched and killed a query.

See also "--wait-before-kill" and "--wait-after-kill".

--kill-busy-commands
type: string; default: Query

group: Actions

Comma sepatated list of commands that will be watched/killed if they ran for more than "--busy-time" seconds. Default: "Query"

By default, "--busy-time" kills only "Query" commands but in some cases, it is needed to make "--busy-time" to watch and kill other commands. For example, a prepared statement execution command is "Execute" instead of "Query". In this case, specifying "--kill-busy-commands=Query,Execute" will also kill the prepared stamente execution.

--kill-query
group: Actions

Kill matching queries.

This option makes pt-kill kill matching queries. This requires MySQL 5.0 or newer. Unlike "--kill" which kills the connection for matching queries, this option only kills the query, not its connection.

--print
group: Actions

Print a KILL statement for matching queries; does not actually kill queries.

If you just want to see which queries match and would be killed without actually killing them, specify "--print". To both kill and print matching queries, specify both "--kill" and "--print".

--fingerprint
group: Actions

Modifies the "--print" behaviour and forces the query fingerprint to be displayed instead of an original query.

DSN OPTIONS

These DSN options are used to create a DSN. Each option is given like "option=value". The options are case-sensitive, so P and p are not the same option. There cannot be whitespace before or after the "=" and if the value contains whitespace it must be quoted. DSN options are comma-separated. See the percona-toolkit manpage for full details.

  • A

    dsn: charset; copy: yes

    Default character set.

  • D

    dsn: database; copy: yes

    Default database.

  • F

    dsn: mysql_read_default_file; copy: yes

    Only read default options from the given file

  • h

    dsn: host; copy: yes

    Connect to host.

  • p

    dsn: password; copy: yes

    Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

  • P

    dsn: port; copy: yes

    Port number to use for connection.

  • S

    dsn: mysql_socket; copy: yes

    Socket file to use for connection.

  • u

    dsn: user; copy: yes

    User for login if not current user.

  • t

    Table to log actions in, if passed through --log-dsn.

  • s

    dsn: mysql_ssl; copy: yes

    Create SSL connection

ENVIRONMENT

The environment variable "PTDEBUG" enables verbose debugging output to STDERR. To enable debugging and capture all output to a file, run the tool like:

PTDEBUG=1 pt-kill ... > FILE 2>&1

Be careful: debugging output is voluminous and can generate several megabytes of output.

ATTENTION

Using <PTDEBUG> might expose passwords. When debug is enabled, all command line parameters are shown in the output.
