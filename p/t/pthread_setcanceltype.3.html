pthread_setcancelstate(3) Manual de funciones de biblioteca pthread_setcancelstate(3)

NOMBRE

pthread_setcancelstate, pthread_setcanceltype - establecer el estado y el tipo de cancelabilidad

BIBLIOTECA

Biblioteca POSIX threads (libpthread, -lpthread)

SINOPSIS

#include <pthread.h>
int pthread_setcancelstate(int estado, int *oldstate);
int pthread_setcanceltype(int tipo, int *oldtype);

DESCRIPCIÓN

La función pthread_setcancelstate() establece el estado de cancelabilidad del hilo de llamada al valor proporcionado en estado. El estado de cancelabilidad anterior del hilo se devuelve en el búfer al que apunta oldstate. El argumento estado debe tener uno de los siguientes valores:

PTHREAD_CANCEL_ENABLE
El hilo es cancelable. Este es el estado de cancelabilidad predeterminado en todos los hilos nuevos, incluido el hilo inicial. El tipo de cancelabilidad del hilo determina cuándo un hilo cancelable responderá a una solicitud de cancelabilidad.
PTHREAD_CANCEL_DISABLE
El hilo no es cancelable. Si se recibe una solicitud de cancelabilidad, se bloquea hasta que la cancelabilidad se habilita.

La función pthread_setcanceltype() establece el tipo de cancelabilidad del hilo de llamada al valor proporcionado en tipo. El tipo de cancelabilidad anterior del hilo se devuelve en el búfer al que apunta oldtype. El argumento tipo debe tener uno de los siguientes valores:

PTHREAD_CANCEL_DEFERRED
Una solicitud de cancelabilidad se aplaza hasta que el hilo llame posteriormente a una función que sea un punto de cancelación (ver pthreads(7)). Este es el tipo de cancelabilidad predeterminado en todos los hilos nuevos, incluido el hilo inicial.
Incluso con la cancelabilidad diferida, un punto de cancelación en un manejador de señales asíncrono aún puede ser actuado y el efecto es como si fuera una cancelación asíncrona.
PTHREAD_CANCEL_ASYNCHRONOUS
El hilo puede ser cancelado en cualquier momento. (Típicamente, se cancelará inmediatamente al recibir una solicitud de cancelabilidad, pero el sistema no lo garantiza).

La operación de establecer y obtener realizada por cada una de estas funciones es atómica con respecto a otros hilos en el proceso que llaman a la misma función.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0; en caso de error, devuelven un número de error distinto de cero.

ERRORES

La función pthread_setcancelstate() puede fallar con el siguiente error:

EINVAL
Valor inválido para estado.

La función pthread_setcanceltype() puede fallar con el siguiente error:

EINVAL
Valor inválido para tipo.

ESTÁNDARES

POSIX.1-2008.

HISTORIA

glibc 2.0 POSIX.1-2001.

NOTAS

Para obtener detalles sobre lo que sucede cuando se cancela un hilo, consulte pthread_cancel(3).

Deshabilitar brevemente la cancelabilidad es útil si un hilo realiza alguna acción crítica que no debe ser interrumpida por una solicitud de cancelabilidad. Tenga cuidado al deshabilitar la cancelabilidad durante largos períodos, o alrededor de operaciones que puedan bloquearse durante largos períodos, ya que eso hará que el hilo no responda a las solicitudes de cancelabilidad.

Cancelabilidad asíncrona

Establecer el tipo de cancelabilidad en PTHREAD_CANCEL_ASYNCHRONOUS rara vez es útil. Dado que el hilo puede ser cancelado en cualquier momento, no puede reservar recursos de forma segura (por ejemplo, asignar memoria con malloc(3)), adquirir mutex, semáforos o bloqueos, etc. Reservar recursos es inseguro porque la aplicación no tiene forma de saber cuál es el estado de estos recursos cuando se cancela el hilo; es decir, ¿la cancelación ocurrió antes de que se reservaran los recursos, mientras estaban reservados o después de que se liberaran? Además, algunas estructuras de datos internas (por ejemplo, la lista enlazada de bloques libres gestionada por la familia de funciones malloc(3)) pueden quedar en un estado inconsistente si la cancelación ocurre en medio de la llamada a la función. En consecuencia, los manejadores de limpieza dejan de ser útiles.

Las funciones que pueden ser canceladas de forma segura de forma asíncrona se denominan funciones seguras para cancelación asíncrona. POSIX.1-2001 y POSIX.1-2008 solo requieren que pthread_cancel(3), pthread_setcancelstate() y pthread_setcanceltype() sean seguras para cancelación asíncrona. En general, otras funciones de biblioteca no pueden ser llamadas de forma segura desde un hilo con cancelabilidad asíncrona.

Una de las pocas circunstancias en las que la cancelabilidad asíncrona es útil es para la cancelación de un hilo que está en un bucle puramente intensivo en cómputo.

Notas de portabilidad

Las implementaciones de hilos de Linux permiten que el argumento oldstate de pthread_setcancelstate() sea NULL, en cuyo caso la información sobre el estado de cancelabilidad anterior no se devuelve al llamador. Muchas otras implementaciones también permiten un argumento oldstat NULL, pero POSIX.1 no especifica este punto, por lo que las aplicaciones portátiles siempre deben especificar un valor no NULL en oldstate. Un conjunto de declaraciones precisamente análogo se aplica al argumento oldtype de pthread_setcanceltype().
