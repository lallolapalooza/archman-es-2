PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_join — esperar a que termine un hilo

SINOPSIS

#include <pthread.h>
int pthread_join(pthread_t thread, void **value_ptr);

DESCRIPCIÓN

La función pthread_join() suspenderá la ejecución del hilo llamador hasta que el thread objetivo termine, a menos que el thread objetivo ya haya terminado. Al regresar de una llamada exitosa a pthread_join() con un argumento value_ptr no nulo, el valor pasado a pthread_exit() por el hilo que termina se pondrá a disposición en la ubicación referenciada por value_ptr. Cuando una llamada a pthread_join() regresa exitosamente, el hilo objetivo ha terminado. Los resultados de múltiples llamadas simultáneas a pthread_join() especificando el mismo hilo objetivo no están definidos. Si el hilo que llama a pthread_join() es cancelado, entonces el hilo objetivo no deberá ser desvinculado (detached).

No se especifica si un hilo que ha salido pero permanece sin unirse cuenta contra {PTHREAD_THREADS_MAX}.

El comportamiento no está definido si el valor especificado por el argumento thread a pthread_join() no se refiere a un hilo unible.

El comportamiento no está definido si el valor especificado por el argumento thread a pthread_join() se refiere al hilo llamador.

VALOR DE RETORNO

Si tiene éxito, la función pthread_join() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_join() puede fallar si:

EDEADLK
Se detectó un interbloqueo (deadlock).

La función pthread_join() no devolverá un código de error de [EINTR].

Las siguientes secciones son informativas.

EJEMPLOS

A continuación se muestra un ejemplo de creación y eliminación de hilos:

typedef struct {
    int *ar;
    long n;
} subarray;
void *
incer(void *arg)
{
    long i;
    for (i = 0; i < ((subarray *)arg)->n; i++)
        ((subarray *)arg)->ar[i]++;
}
int main(void)
{
    int        ar[1000000];
    pthread_t  th1, th2;
    subarray   sb1, sb2;
    sb1.ar = &ar[0];
    sb1.n  = 500000;
    (void) pthread_create(&th1, NULL, incer, &sb1);
    sb2.ar = &ar[500000];
    sb2.n  = 500000;
    (void) pthread_create(&th2, NULL, incer, &sb2);
    (void) pthread_join(th1, NULL);
    (void) pthread_join(th2, NULL);
    return 0;
}

USO DE APLICACIÓN

Ninguno.

RACIONAMIENTO

La función pthread_join() es una conveniencia que ha demostrado ser útil en aplicaciones multihilo. Es cierto que un programador podría simular esta función si no se proporcionara pasando estado adicional como parte del argumento a la start_routine(). El hilo que termina establecería una bandera para indicar la terminación y transmitiría una condición que forma parte de ese estado; un hilo que se une esperaría en esa variable de condición. Si bien tal técnica permitiría a un hilo esperar condiciones más complejas (por ejemplo, esperar a que múltiples hilos terminen), esperar la terminación de hilos individuales se considera ampliamente útil. Además, la inclusión de la función pthread_join() de ninguna manera impide que un programador codifique esperas tan complejas. Por lo tanto, aunque no es una primitiva, se consideró valiosa la inclusión de pthread_join() en este volumen de POSIX.1‐2017.

La función pthread_join() proporciona un mecanismo simple que permite a una aplicación esperar a que un hilo termine. Después de que el hilo termine, la aplicación puede optar por limpiar los recursos que fueron usados por el hilo. Por ejemplo, después de que pthread_join() regrese, se podría recuperar cualquier almacenamiento de pila proporcionado por la aplicación.

Se debe llamar eventualmente a la función pthread_join() o pthread_detach() para cada hilo que se crea con el atributo detachstate establecido en PTHREAD_CREATE_JOINABLE, para que el almacenamiento asociado con el hilo pueda ser recuperado.

La interacción entre pthread_join() y la cancelación está bien definida por las siguientes razones:

*
La función pthread_join(), como todas las demás funciones no seguras para la cancelación asíncrona, solo se puede llamar con un tipo de cancelabilidad diferida.
*
La cancelación no puede ocurrir en el estado de cancelabilidad deshabilitado.

Por lo tanto, solo es necesario considerar el estado de cancelabilidad predeterminado. Como se especifica, la llamada a pthread_join() es cancelada o tiene éxito, pero no ambas. La diferencia es obvia para la aplicación, ya que se ejecuta un manejador de cancelación o pthread_join() regresa. No hay condiciones de carrera ya que pthread_join() se llamó en el estado de cancelabilidad diferida.

Si una implementación detecta que el valor especificado por el argumento thread a pthread_join() no se refiere a un hilo unible, se recomienda que la función falle e informe un error [EINVAL].

Si una implementación detecta que el valor especificado por el argumento thread a pthread_join() se refiere al hilo llamador, se recomienda que la función falle e informe un error [EDEADLK].

Si una implementación detecta el uso de un ID de hilo después del fin de su vida útil, se recomienda que la función falle e informe un error [ESRCH].

PROLOG

NOMBRE

pthread_join — esperar a que termine un hilo

SINAPSIS

```c #include int pthread_join(pthread_t thread, void **retval); ```

DESCRIPCIÓN

La función pthread_join bloqueará al hilo llamante hasta que el hilo especificado por el argumento thread termine su ejecución. Una vez que el hilo termina, la función pthread_join recupera el estado de salida del hilo terminado. Si retval no es NULL, el valor devuelto por el hilo terminado (el valor pasado a pthread_exit() o el valor devuelto por la función de inicio del hilo) se almacenará en la ubicación de memoria apuntada por retval.

Si el hilo especificado por thread ya ha terminado cuando se llama a pthread_join, la función devolverá inmediatamente. Un hilo puede ser unido una sola vez.

Es importante tener en cuenta que después de que un hilo ha sido unido, sus recursos asociados son liberados por el sistema operativo. Intentar unir un hilo que ya ha sido unido resultará en un comportamiento indefinido.

VALOR DE RETORNO

En caso de éxito, pthread_join devuelve 0. En caso de error, devuelve un número de error distinto de cero.

ERRORES

EINVAL El hilo especificado por thread no es un hilo joinable, o el hilo thread es el mismo que el hilo que llama.

ESRCH No se encontró ningún hilo con el ID especificado por thread.

EDEADLK Se detectó un deadlock. Esto puede ocurrir si un hilo intenta unirse a sí mismo o si se produce un ciclo de dependencias de unión.

EJEMPLOS

pthread_join se utiliza típicamente para esperar a que un hilo hijo termine antes de que el hilo padre continúe. Por ejemplo:

```c #include #include #include void *thread_function(void *arg) { printf("Hilo hijo ejecutándose...\n"); // Hacer algún trabajo aquí pthread_exit((void *)42); // Devolver un valor } int main() { pthread_t tid; void *thread_return; int ret; ret = pthread_create(&tid, NULL, thread_function, NULL); if (ret != 0) { perror("pthread_create"); exit(EXIT_FAILURE); } printf("Hilo padre esperando a que termine el hilo hijo...\n"); ret = pthread_join(tid, &thread_return); if (ret != 0) { perror("pthread_join"); exit(EXIT_FAILURE); } printf("Hilo hijo terminado con valor de retorno: %ld\n", (long)thread_return); printf("Hilo padre continuando...\n"); return 0; } ```

USO DE LA APLICACIÓN

La función pthread_join es fundamental para la gestión de hilos en aplicaciones multihilo. Permite que un hilo espere la finalización de otro hilo, lo que es esencial para la sincronización y la recolección de resultados. Asegurarse de que los hilos se unen adecuadamente es importante para evitar fugas de recursos y comportamientos inesperados.

JUSTIFICACIÓN

La necesidad de pthread_join surge del modelo de concurrencia basado en hilos. Los hilos, a diferencia de los procesos, comparten el mismo espacio de direcciones, lo que permite una comunicación eficiente pero también requiere mecanismos para gestionar su ciclo de vida. pthread_join proporciona una forma segura y estándar de esperar la terminación de un hilo y recuperar su estado de salida.

DIRECCIONES FUTURAS

Las futuras direcciones relacionadas con pthread_join podrían incluir mejoras en el manejo de errores, optimizaciones de rendimiento en sistemas con un gran número de hilos, o la integración con mecanismos de gestión de recursos más avanzados.
