PTHREAD_DETACH(3P) Manual del programador POSIX PTHREAD_DETACH(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual correspondiente de Linux para obtener detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_detach — separar un hilo

SINOPSIS

#include <pthread.h>
int pthread_detach(pthread_t thread);

DESCRIPCIÓN

La función pthread_detach() indicará a la implementación que el almacenamiento para el hilo thread puede ser recuperado cuando dicho hilo termine. Si thread no ha terminado, pthread_detach() no provocará su terminación.

El comportamiento no está definido si el valor especificado por el argumento thread a pthread_detach() no se refiere a un hilo "joinable" (que se puede unir).

VALOR DE RETORNO

Si la llamada tiene éxito, pthread_detach() devolverá 0; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_detach() no devolverá un código de error de [EINTR].

JUSTIFICACIÓN

Las funciones pthread_join() o pthread_detach() deben ser llamadas eventualmente para cada hilo que se crea, de modo que el almacenamiento asociado al hilo pueda ser recuperado.

Se ha sugerido que una función de ``separación'' no es necesaria; el atributo de creación de hilo detachstate es suficiente, ya que un hilo nunca necesita ser separado dinámicamente. Sin embargo, la necesidad surge en al menos dos casos:

1.
En un manejador de cancelación para pthread_join(), es casi esencial tener una función pthread_detach() para separar el hilo en el que pthread_join() estaba esperando. Sin ella, sería necesario que el manejador realizara otra pthread_join() para intentar separar el hilo, lo que retrasaría el procesamiento de cancelación por un período ilimitado e introduciría una nueva llamada a pthread_join(), que podría requerir su propio manejador de cancelación. Una separación dinámica es casi esencial en este caso.
2.
Para separar el ``hilo inicial'' (como puede ser deseable en procesos que configuran hilos de servidor).

Si una implementación detecta que el valor especificado por el argumento thread a pthread_detach() no se refiere a un hilo "joinable", se recomienda que la función falle y reporte un error [EINVAL].

Si una implementación detecta el uso de un ID de hilo después del final de su vida útil, se recomienda que la función falle y reporte un error [ESRCH].
