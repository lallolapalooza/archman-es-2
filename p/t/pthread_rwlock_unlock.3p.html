PROLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_rwlock_unlock — desbloquear un objeto de bloqueo de lectura-escritura

SINOPSIS

#include <pthread.h>
int pthread_rwlock_unlock(pthread_rwlock_t *rwlock);

DESCRIPCIÓN

La función pthread_rwlock_unlock() libera un bloqueo mantenido sobre el objeto de bloqueo de lectura-escritura al que hace referencia rwlock. Los resultados no están definidos si el bloqueo de lectura-escritura rwlock no lo mantiene el hilo que llama.

Si esta función se llama para liberar un bloqueo de lectura del objeto de bloqueo de lectura-escritura y hay otros bloqueos de lectura actualmente mantenidos en este objeto de bloqueo de lectura-escritura, el objeto de bloqueo de lectura-escritura permanece en el estado de bloqueo de lectura. Si esta función libera el último bloqueo de lectura para este objeto de bloqueo de lectura-escritura, el objeto de bloqueo de lectura-escritura se pondrá en el estado desbloqueado sin propietarios.

Si esta función se llama para liberar un bloqueo de escritura para este objeto de bloqueo de lectura-escritura, el objeto de bloqueo de lectura-escritura se pondrá en el estado desbloqueado.

Si hay hilos bloqueados en el bloqueo cuando este se vuelve disponible, la política de planificación determinará qué hilo(s) adquirirán el bloqueo. Si se soporta la opción de planificación de ejecución de hilos, cuando los hilos que ejecutan con las políticas de planificación SCHED_FIFO, SCHED_RR o SCHED_SPORADIC están esperando en el bloqueo, adquirirán el bloqueo en orden de prioridad cuando el bloqueo se vuelva disponible. Para hilos de igual prioridad, los bloqueos de escritura tendrán precedencia sobre los bloqueos de lectura. Si la opción de planificación de ejecución de hilos no se soporta, es una decisión de la implementación si los bloqueos de escritura tienen precedencia sobre los bloqueos de lectura.

Los resultados no están definidos si esta función se llama con un bloqueo de lectura-escritura no inicializado.

VALOR DE RETORNO

Si la operación es exitosa, la función pthread_rwlock_unlock() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_rwlock_unlock() no devolverá un código de error de [EINTR].

FUNDAMENTOS DE LA DECISIÓN

Si una implementación detecta que el valor especificado por el argumento rwlock a pthread_rwlock_unlock() no se refiere a un objeto de bloqueo de lectura-escritura inicializado, se recomienda que la función falle y reporte un error [EINVAL].

Si una implementación detecta que el valor especificado por el argumento rwlock a pthread_rwlock_unlock() se refiere a un objeto de bloqueo de lectura-escritura para el cual el hilo actual no tiene un bloqueo, se recomienda que la función falle y reporte un error [EPERM].
