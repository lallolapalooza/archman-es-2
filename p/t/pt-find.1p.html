NOMBRE

pt-find - Busca tablas de MySQL y ejecuta acciones, como GNU find.

SINOPSIS

Uso: pt-find [OPCIONES] [BASES_DE_DATOS]

pt-find busca tablas de MySQL y ejecuta acciones, como GNU find. La acción predeterminada es imprimir el nombre de la base de datos y la tabla.

Busca todas las tablas creadas hace más de un día, que usan el motor MyISAM, e imprime sus nombres:

pt-find --ctime +1 --engine MyISAM

Busca tablas MyISAM y las convierte a InnoDB:

pt-find --engine MyISAM --exec "ALTER TABLE %D.%N ENGINE=InnoDB"

Busca tablas creadas por un proceso que ya no existe, siguiendo la convención de nombres name_sid_pid, y las elimina.

pt-find --connection-id '\D_\d+_(\d+)$' --server-id '\D_(\d+)_\d+$' --exec-plus "DROP TABLE %s"

Busca tablas vacías en las bases de datos test y junk, y las elimina:

pt-find --empty junk test --exec-plus "DROP TABLE %s"

Busca tablas de más de cinco gigabytes de tamaño total:

pt-find --tablesize +5G

Busca todas las tablas e imprime su tamaño total de datos e índices, y ordena las tablas más grandes primero (sort es un programa diferente, por cierto).

pt-find --printf "%T\t%D.%N\n" | sort -rn

Igual que el anterior, pero esta vez, inserta los datos de vuelta en la base de datos para posteridad:

pt-find --noquote --exec "INSERT INTO sysdata.tblsize(db, tbl, size) VALUES('%D', '%N', %T)"

RIESGOS

Percona Toolkit es maduro, probado en el mundo real y bien verificado, pero todas las herramientas de bases de datos pueden suponer un riesgo para el sistema y el servidor de la base de datos. Antes de usar esta herramienta, por favor:

  • Lea la documentación de la herramienta
  • Revise los "BUGS" conocidos de la herramienta
  • Pruebe la herramienta en un servidor no productivo
  • Haga una copia de seguridad de su servidor de producción y verifique las copias de seguridad

DESCRIPCIÓN

pt-find busca tablas de MySQL que cumplen las pruebas que usted especifica, y ejecuta las acciones que usted especifica. La acción predeterminada es imprimir el nombre de la base de datos y la tabla en STDOUT.

pt-find es más simple que GNU find. No le permite especificar expresiones complicadas en la línea de comandos.

pt-find usa SHOW TABLES cuando es posible, y SHOW TABLE STATUS cuando es necesario.

TIPOS DE OPCIONES

Hay tres tipos de opciones: opciones normales, que determinan algún comportamiento o configuración; pruebas, que determinan si una tabla debe incluirse en la lista de tablas encontradas; y acciones, que hacen algo con las tablas que pt-find encuentra.

pt-find utiliza el análisis estándar de opciones Getopt::Long, por lo que debe usar dobles guiones delante de los nombres de opciones largas, a diferencia de GNU find.

PRUEBAS

La mayoría de las pruebas verifican algún criterio contra una columna de la salida de SHOW TABLE STATUS. Los argumentos numéricos se pueden especificar como +n para mayor que n, -n para menor que n, y n para exactamente n. Todas las opciones numéricas pueden tener un multiplicador de sufijo opcional de k, M o G (1.024, 1.048.576 y 1.073.741.824 respectivamente). Todos los patrones son expresiones regulares de Perl (ver 'man perlre') a menos que se especifiquen como patrones SQL LIKE.

Las fechas y horas se miden todas relativas al mismo instante, cuando pt-find pregunta por primera vez al servidor de base de datos qué hora es. Toda la manipulación de fechas y horas se realiza en SQL, por lo que si dices que encuentres tablas modificadas hace 5 días, eso se traduce a SELECT DATE_SUB(CURRENT_TIMESTAMP, INTERVAL 5 DAY). Si especificas "--day-start", por supuesto que es relativo a CURRENT_DATE en su lugar.

Sin embargo, los tamaños de tabla y otras métricas no son consistentes en un instante en el tiempo. Puede llevar algún tiempo para que MySQL procese todas las consultas SHOW, y pt-find no puede hacer nada al respecto. Estas mediciones son de cuando se toman.

Si necesita alguna prueba que no esté en esta lista, envíe una solicitud de característica en https://jira.percona.com/projects/PT.

tipo: tamaño; grupo: Pruebas

--checksum

--cmin
tipo: tamaño; grupo: Pruebas

La tabla se creó hace n minutos. Esto prueba la columna Create_time.

--collation

--column-name
tipo: string; grupo: Pruebas

Un nombre de columna en la tabla coincide con el patrón.

--column-type

Una columna en la tabla coincide con este tipo (sin distinguir mayúsculas y minúsculas).

Ejemplos de tipos son: varchar, char, int, smallint, bigint, decimal, year, timestamp, text, enum.

--comment
tipo: string; grupo: Pruebas

--connection-id
tipo: string; grupo: Pruebas

El nombre de la tabla tiene un ID de conexión de MySQL inexistente. Esto prueba el nombre de la tabla para un patrón. El argumento para esta prueba debe ser una expresión regular de Perl que capture dígitos como esta: (\d+). Si el nombre de la tabla coincide con el patrón, estos dígitos capturados se toman como el ID de conexión de MySQL de algún proceso. Si la conexión no existe según SHOW FULL PROCESSLIST, la prueba devuelve verdadero. Si el ID de conexión es mayor que el ID de conexión de pt-find, la prueba devuelve falso por seguridad.

¿Por qué querrías hacer esto? Si utilizas replicación basada en declaraciones de MySQL, probablemente conozcas los problemas que pueden causar las tablas temporales. Podrías optar por solucionar esto creando tablas reales con nombres únicos, en lugar de tablas temporales. Una forma de hacerlo es añadir tu ID de conexión al final de la tabla, así: scratch_table_12345. Esto asegura que el nombre de la tabla sea único y te permite tener una forma de encontrar con qué conexión estaba asociada. Y quizás lo más importante, si la conexión ya no existe, puedes asumir que la conexión murió sin limpiar sus tablas, y esta tabla es candidata a ser eliminada.

El argumento a usar para "--connection-id" es "\D_(\d+)$". Eso encuentra tablas con una serie de números al final, precedidos por un guion bajo y algún carácter que no sea un número (este último criterio evita examinar tablas con una fecha al final, lo que la gente tiende a hacer: baron_scratch_2007_05_07, por ejemplo). Es mejor mantener las tablas temporales separadas.

Si haces esto, ¡asegúrate de que el usuario con el que se ejecuta pt-find tenga el privilegio PROCESS! De lo contrario, solo verá conexiones del mismo usuario y podría pensar que algunas tablas están listas para ser eliminadas cuando todavía están en uso. Por seguridad, pt-find lo verifica por ti.

Ver también "--server-id".

--server-id
tipo: string; grupo: Pruebas

El nombre de la tabla contiene el ID del servidor. Si crea tablas temporales con la convención de nomenclatura explicada en "--connection-id", pero también añade el ID del servidor en el que se crean las tablas, entonces puede usar esta coincidencia de patrón para asegurarse de que las tablas solo se eliminen en el servidor en el que se crean. Esto evita que una tabla se elimine accidentalmente en una réplica mientras está en uso (siempre que todos sus IDs de servidor sean únicos, como deberían ser para que la replicación funcione).

Por ejemplo, en la fuente de replicación (ID de servidor 22) crea una tabla llamada scratch_table_22_12345. Si ve esta tabla en la réplica (ID de servidor 23), podría pensar que se puede eliminar de forma segura si no existe tal conexión 12345. Pero si también fuerza que el nombre coincida con el ID del servidor con ""--server-id '\D_(\d+)_\d+$'", la tabla no se eliminará en la réplica.

--tablesize
tipo: tamaño; grupo: Pruebas

La tabla utiliza n bytes de espacio. Esto prueba la suma de las columnas Data_length e Index_length.

tipo: tamaño; grupo: Pruebas

tipo: string; grupo: Pruebas

ACCIONES

NOMBRE

pt-find - encuentra tablas de bases de datos MySQL y ejecuta acciones sobre ellas

SINOPSIS

pt-find --host hostname [--port port] [--user user] [--password password]
    [--ask-pass] [--defaults-file file] [--config-file file]
    [--charset charset] [--databases databases] [--tables tables]
    [--recursion-limit n] [--depth n] [--filter rule]
    [--print | --printf format | --exec sql | --exec-plus sql]
    [--exec-dsn dsn]

RIESGOS

Utilizar PTDEBUG puede exponer contraseñas. Cuando la depuración está activada, todos los parámetros de la línea de comandos se muestran en la salida.

DESCRIPCION

Este script encuentra tablas de bases de datos MySQL y ejecuta acciones sobre ellas. Puede ser útil para realizar operaciones masivas en tablas, como eliminarlas o renombrarlas.

El script busca tablas basándose en varios criterios, como el nombre de la base de datos, el nombre de la tabla, el tamaño, etc. Una vez encontradas las tablas, se pueden ejecutar diferentes acciones sobre ellas.

TIPOS DE OPCIONES

Este script acepta varias opciones para controlar su comportamiento. Las opciones se agrupan en las siguientes categorías:

  • Actions: Especifican la acción a realizar con las tablas encontradas.

OPCIONES

--ejecutar
tipo: string; grupo: Acciones

Ejecuta este SQL con cada elemento encontrado. El SQL puede contener escapes y directivas de formato (ver "--printf").

--ejecutar-dsn
tipo: string; grupo: Acciones

Especifica un DSN en formato clave-valor para usar al ejecutar SQL con "--ejecutar" y "--ejecutar-plus". Cualquier valor no especificado se hereda de los argumentos de la línea de comandos.

--ejecutar-plus
tipo: string; grupo: Acciones

Ejecuta este SQL con todos los elementos a la vez. Esta opción es diferente de "--ejecutar". No hay escapes ni directivas de formato; solo hay un marcador especial para la lista de nombres de bases de datos y tablas, %s. La lista de tablas encontradas se unirá con comas y se sustituirá donde coloques %s.

Podrías usar esto, por ejemplo, para eliminar todas las tablas encontradas:

DROP TABLE %s

Esto es similar a la sintaxis de find de GNU "-exec command {} +".

La acción "--ejecutar-plus" ocurre después de todo lo demás, pero de lo contrario las acciones ocurren en un orden indeterminado. Si necesitas determinismo, presenta una solicitud de característica en https://jira.percona.com/projects/PT.

--imprimir
grupo: Acciones

Imprime el nombre de la base de datos y la tabla, seguido de un salto de línea. Esta es la acción predeterminada si no se especifica ninguna otra acción.

--imprimir-formato
tipo: string; grupo: Acciones

Imprime el formato en la salida estándar, interpretando escapes de '\' y directivas de '%'. Los escapes son caracteres con barra inversa, como \n y \t. Perl interpreta estos, por lo que puedes usar cualquier escape que Perl conozca. Las directivas se reemplazan por %s, y en el momento de escribir esto, no puedes agregar instrucciones de formato especiales, como anchos de campo o alineación.

Aquí hay una lista de las directivas. Ten en cuenta que la mayoría de ellas provienen simplemente de las columnas de SHOW TABLE STATUS. Si la columna es NULL o no existe, obtienes una cadena vacía en la salida. Un carácter % seguido de cualquier carácter que no esté en la siguiente lista se descarta (pero se imprime el otro carácter).

OPCIONES DSN

Estas opciones DSN se utilizan para crear un DSN. Cada opción se proporciona como "opcion=valor". Las opciones distinguen entre mayúsculas y minúsculas, por lo que P y p no son la misma opción. No puede haber espacios en blanco antes o después del "=" y si el valor contiene espacios en blanco debe estar entre comillas. Las opciones DSN se separan con comas. Consulte la página del manual de percona-toolkit para obtener detalles completos.

  • A

    dsn: charset; copia: sí

    Juego de caracteres predeterminado.

  • D

    dsn: database; copia: sí

    Base de datos predeterminada.

  • F

    dsn: mysql_read_default_file; copia: sí

    Lee solo las opciones predeterminadas del archivo dado

  • h

    dsn: host; copia: sí

    Conéctate al host.

  • p

    dsn: password; copia: sí

    Contraseña a usar al conectarse. Si la contraseña contiene comas, deben escaparse con una barra invertida: "exam\,ple"

  • P

    dsn: port; copia: sí

    Número de puerto a usar para la conexión.

  • S

    dsn: mysql_socket; copia: sí

    Archivo de socket a usar para la conexión.

  • u

    dsn: user; copia: sí

    Usuario para iniciar sesión si no es el usuario actual.

  • s

    dsn: mysql_ssl; copia: sí

    Crear conexión SSL

AMBIENTE

La variable de entorno "PTDEBUG" activa la salida de depuración detallada en STDERR. Para activar la depuración y capturar toda la salida en un archivo, ejecuta la herramienta así:

PTDEBUG=1 pt-find ... > ARCHIVO 2>&1

Ten cuidado: la salida de depuración es voluminosa y puede generar varios megabytes de salida.

ATENCION

Usar <PTDEBUG> podría exponer contraseñas. Cuando la depuración está habilitada, todos los parámetros de la línea de comandos se muestran en la salida.

REQUERIMIENTOS DEL_SISTEMA

pt-find

NAME

pt-find - find and kill MySQL processes

SYNOPSIS

pt-find [OPTIONS] --host MASTER_HOST --user USER --password PASS --port PORT \
    --socket SOCKET [WHERE_CONDITIONS]
pt-find [OPTIONS] DSN [WHERE_CONDITIONS]

DESCRIPTION

pt-find is a tool to find and kill MySQL processes.

It is similar to the SHOW PROCESSLIST and KILL commands in MySQL.

pt-find allows you to find processes based on various criteria and then kill them.

OPTIONS

The tool accepts additional command-line arguments as DSN syntax. See DBD::mysql for details.

--host, -h

Connect to this MySQL host.

--user, -u

Don't ask for password. Login as this user.

--password, -p

Password for the user. If this is not specified, then it prompts for it.

--port, -P

Port number to use when connecting.

--socket, -S

Socket file to use when connecting.

--kill

Kill the matching processes.

--kill-age AGE

Kill processes older than AGE. AGE is in seconds, or a string like "1h", "30m".

--idle-timeout IDLE_TIMEOUT

Kill processes that have been idle for longer than IDLE_TIMEOUT.

--busy-timeout BUSY_TIMEOUT

Kill processes that have been busy for longer than BUSY_TIMEOUT.

--print

Print the matching processes to STDOUT.

--print-kill

Print the kill commands for the matching processes.

--quiet, -q

Do not print the header. This is useful for scripting.

--verbose, -v

Print verbose output.

--help

Show help message and exit.

--version

Show program version and exit.

EXAMPLES

# Find all processes
pt-find --host localhost --user root --password mypassword

# Find and kill processes older than 1 hour
pt-find --host localhost --user root --password mypassword --kill-age 1h --kill

# Find and kill processes that have been idle for more than 30 minutes
pt-find --host localhost --user root --password mypassword --idle-timeout 30m --kill

# Find processes that are not sleeping and kill them
pt-find --host localhost --user root --password mypassword --where "state != 'Sleep'" --kill

ATTENTION

Use pt-find with caution. Killing processes can lead to data corruption or other problems if not done carefully.

SYSTEM REQUIREMENTS

Requires Perl and the DBD::mysql module.
