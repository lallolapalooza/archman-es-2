PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pthread_cond_destroy, pthread_cond_init — destruir e inicializar variables de condición

SINOPSIS

#include <pthread.h>
int pthread_cond_destroy(pthread_cond_t *cond);
int pthread_cond_init(pthread_cond_t *restrict cond,
    const pthread_condattr_t *restrict attr);
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

DESCRIPCIÓN

La función pthread_cond_destroy() destruirá la variable de condición dada especificada por cond; el objeto se convertirá, en efecto, en no inicializado. Una implementación puede hacer que pthread_cond_destroy() establezca el objeto al que hace referencia cond en un valor no válido. Una variable de condición destruida puede ser reinicializada usando pthread_cond_init(); los resultados de hacer referencia al objeto de otra manera después de que haya sido destruido no están definidos.

Será seguro destruir una variable de condición inicializada sobre la cual ningún hilo esté actualmente bloqueado. Intentar destruir una variable de condición sobre la cual otros hilos estén actualmente bloqueados da como resultado un comportamiento indefinido.

La función pthread_cond_init() inicializará la variable de condición referenciada por cond con los atributos referenciados por attr. Si attr es NULL, se utilizarán los atributos de variable de condición predeterminados; el efecto es el mismo que pasar la dirección de un objeto de atributos de variable de condición predeterminada. Tras una inicialización exitosa, el estado de la variable de condición se convertirá en inicializado.

Consulte la Sección 2.9.9, Copias de objetos de sincronización y mapeos alternativos para obtener requisitos adicionales.

Intentar inicializar una variable de condición ya inicializada da como resultado un comportamiento indefinido.

En casos donde los atributos de variable de condición predeterminados son apropiados, se puede usar la macro PTHREAD_COND_INITIALIZER para inicializar variables de condición. El efecto será equivalente a la inicialización dinámica mediante una llamada a pthread_cond_init() con el parámetro attr especificado como NULL, excepto que no se realizan comprobaciones de errores.

El comportamiento es indefinido si el valor especificado por el argumento cond a pthread_cond_destroy() no se refiere a una variable de condición inicializada.

El comportamiento es indefinido si el valor especificado por el argumento attr a pthread_cond_init() no se refiere a un objeto de atributos de variable de condición inicializado.

VALOR DE RETORNO

Si tiene éxito, las funciones pthread_cond_destroy() y pthread_cond_init() devolverán cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función pthread_cond_init() fallará si:

EAGAIN
Al sistema le faltaban los recursos necesarios (aparte de la memoria) para inicializar otra variable de condición.
ENOMEM
No hay suficiente memoria para inicializar la variable de condición.

Estas funciones no devolverán un código de error de [EINTR].

Las siguientes secciones son informativas.

EJEMPLOS

Una variable de condición puede ser destruida inmediatamente después de que todos los hilos que estén bloqueados en ella sean despertados. Por ejemplo, considere el siguiente código:

struct list {
    pthread_mutex_t lm;
    ...
}
struct elt {
    key k;
    int busy;
    pthread_cond_t notbusy;
    ...
}
/* Busca un elemento de lista y lo reserva. */
struct elt *
list_find(struct list *lp, key k)
{
    struct elt *ep;
    pthread_mutex_lock(&lp->lm);
    while ((ep = find_elt(l, k) != NULL) && ep->busy)
        pthread_cond_wait(&ep->notbusy, &lp->lm);
    if (ep != NULL)
        ep->busy = 1;
    pthread_mutex_unlock(&lp->lm);
    return(ep);
}
delete_elt(struct list *lp, struct elt *ep)
{
    pthread_mutex_lock(&lp->lm);
    assert(ep->busy);
    ... eliminar ep de la lista ...
    ep->busy = 0;  /* Paranoico. */
(A) pthread_cond_broadcast(&ep->notbusy);
    pthread_mutex_unlock(&lp->lm);
(B) pthread_cond_destroy(&ep->notbusy);
    free(ep);
}

En este ejemplo, la variable de condición y su elemento de lista pueden ser liberados (línea B) inmediatamente después de que todos los hilos que esperan por ella sean despertados (línea A), ya que el mutex y el código aseguran que ningún otro hilo pueda tocar el elemento a eliminar.

USO EN LA APLICACIÓN

Ninguno.

FUNDAMENTO

Si una implementación detecta que el valor especificado por el argumento cond a pthread_cond_destroy() no se refiere a una variable de condición inicializada, se recomienda que la función falle y reporte un error [EINVAL].

Si una implementación detecta que el valor especificado por el argumento cond a pthread_cond_destroy() o pthread_cond_init() se refiere a una variable de condición que está en uso (por ejemplo, en una llamada a pthread_cond_wait()) por otro hilo, o detecta que el valor especificado por el argumento cond a pthread_cond_init() se refiere a una variable de condición ya inicializada, se recomienda que la función falle y reporte un error [EBUSY].

Si una implementación detecta que el valor especificado por el argumento attr a pthread_cond_init() no se refiere a un objeto de atributos de variable de condición inicializado, se recomienda que la función falle y reporte un error [EINVAL].

Consulte también pthread_mutex_destroy().
