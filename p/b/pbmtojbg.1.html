PBMTOJBG(1) Manual de Comandos Generales PBMTOJBG(1)

NOMBRE

pbmtojbg - conversor de mapa de bits portable a archivo JBIG1

SINOPSIS

pbmtojbg [ opciones ] [ archivo-entrada | - [ archivo-salida ]]

DESCRIPCIÓN

Lee un mapa de bits portable (PBM) de un archivo o de la entrada estándar, lo comprime y emite la imagen como un archivo de entidad de imagen binaria JBIG1 (BIE).

JBIG1 es un algoritmo de compresión sin pérdidas muy eficaz para imágenes binarias (un bit por píxel), especialmente adecuado para páginas de documentos escaneados.

Una imagen codificada JBIG1 puede almacenarse en varias resoluciones (modo progresivo). Estas capas de resolución pueden almacenarse todas en un único BIE o en varios archivos BIE separados. Todas las capas de resolución, excepto la más baja, se almacenan simplemente como diferencias con la capa de resolución inferior más cercana, ya que esto requiere menos espacio que codificar la imagen completa cada vez. Cada capa de resolución tiene el doble de píxeles horizontales y verticales que la capa inferior más cercana. Los archivos JBIG1 también pueden almacenar varios bits por píxel como planos de mapa de bits separados, y pbmtojbg puede leer un archivo PGM y transformarlo en un BIE de múltiples planos de bits.

OPCIONES

-
Un guion solo en lugar de un nombre de archivo de entrada hará que pbmtojbg lea los datos de la entrada estándar en lugar de un archivo.
-q
Codifica la imagen en una sola capa de resolución (modo secuencial). Este es generalmente el método de compresión más eficiente. Por defecto, el número de capas de resolución se elige automáticamente de manera que la imagen de la capa más baja no sea mayor de 640 × 480 píxeles. Este es un atajo para -d 0.
-x número
Especifica el tamaño horizontal máximo de la capa de resolución más baja. El valor predeterminado es 640 píxeles.
-y número
Especifica el tamaño vertical máximo de la capa de resolución más baja. El valor predeterminado es 480 píxeles.
-l número
Selecciona la capa de resolución más baja que se escribirá en el BIE. Es posible almacenar las diversas capas de resolución de una imagen JBIG1 en modo progresivo en diferentes BIE. Las opciones -l y -h permiten seleccionar el intervalo de capas de resolución que aparecerá en el BIE creado. La capa de resolución más baja tiene el número 0 y este es también el valor predeterminado. Por defecto, se escribirán todas las capas.
-h número
Selecciona la capa de resolución más alta que se escribirá en el BIE. Por defecto, se escribirán todas las capas. Véase también la opción -l.
-b
Utiliza valores binarios en lugar de palabras de código Gray para codificar los valores de los píxeles en múltiples planos de bits. Esta opción solo tiene efecto si la entrada es un archivo PGM y si se producen más de un plano de bits. Tenga en cuenta que el decodificador debe hacer la misma selección pero no puede determinar a partir del BIE si se utilizaron palabras de código Gray o binarias por el codificador.
-d número
Especifica el número total de capas de resolución diferenciales en las que se dividirá la imagen de entrada además de la capa más baja. Cada capa adicional reduce el tamaño de la capa 0 en un 50%. Esta opción anula las opciones -x y -y, que suelen ser una forma más cómoda de seleccionar el número de capas de resolución.
-s número
El algoritmo JBIG1 divide cada imagen en un número de bandas horizontales. Esta opción especifica que cada banda tendrá número líneas en la capa 0. El valor predeterminado se selecciona de manera que se utilicen aproximadamente 35 bandas para toda la imagen.
-m número
Selecciona el desplazamiento horizontal máximo del píxel de plantilla adaptativa. El codificador JBIG1 utiliza diez píxeles vecinos para estimar la probabilidad de que el siguiente píxel sea blanco o negro. Puede mover uno de estos diez píxeles. Esto es especialmente útil para imágenes ditherizadas, siempre que la distancia de este píxel adaptativo se pueda ajustar al período del patrón dither. Por defecto, se permite que el píxel de plantilla adaptativa se mueva hasta 8 píxeles horizontalmente. Este codificador admite distancias de hasta 127 píxeles. El Anexo A del estándar sugiere que los decodificadores deben admitir al menos una distancia horizontal de 16 píxeles, por lo que usar valores no superiores a 16 para número podría aumentar las posibilidades de interoperabilidad con otras implementaciones JBIG1. Por otro lado, el perfil de aplicación de fax T.85 requiere que los decodificadores admitan desplazamientos horizontales de hasta 127 píxeles, que es el valor máximo permitido por el estándar. (El desplazamiento vertical máximo del píxel de plantilla adaptativa es siempre cero para este codificador).
-t número
Codifica solo el número especificado de los planos de bits más significativos. Esta opción permite reducir la profundidad de un archivo PGM de entrada si no se necesitan todos los bits por píxel en la salida.
-o número
JBIG1 separa una imagen en varias bandas horizontales, capas de resolución y planos, donde cada plano contiene un bit por píxel. Una sola banda en un plano y capa se codifica como una unidad de datos llamada entidad de datos de banda (SDE) dentro del BIE. Hay 12 órdenes posibles diferentes en las que se pueden almacenar las SDE dentro del BIE y número selecciona cuál debe usarse. El orden de las SDE solo es relevante para aplicaciones que desean decodificar un archivo JBIG1 que aún no ha llegado completamente, por ejemplo, desde una conexión de red lenta. Por ejemplo, algunas aplicaciones prefieren que el bucle más externo de los tres (bandas, capas, planos) sea sobre todas las capas, de modo que todos los datos de la capa de resolución más baja se transmitan primero.


Los siguientes valores para número seleccionan estos arreglos de bucles para escribir las SDE (bucle más externo primero):
0 planos, capas, bandas
2 capas, planos, bandas
3 capas, bandas, planos
4 bandas, planos, capas
5 planos, bandas, capas
6 bandas, capas, planos

Todos los bucles cuentan a partir de cero; sin embargo, al sumar 8 al código de orden anterior, el bucle de capas puede invertirse para que cuente hacia abajo hasta cero y luego las capas de mayor resolución se almacenarán antes que las capas inferiores. El orden predeterminado es 3, que escribe primero todos los planos de la primera banda y luego completa la capa 0 antes de continuar con la siguiente capa y así sucesivamente.

-p número
Esta opción permite activar o desactivar varios algoritmos opcionales definidos en el estándar JBIG1. Simplemente sume los números de las siguientes opciones que desea activar para obtener el valor de número:


4 predicción determinista (DPON)
8 predicción típica de capa 0 (TPBON)
16 pred. típica de capa diferencial (TPDON)
64 plantilla de dos líneas de capa 0 (LRLTWO)

Excepto para aplicaciones especiales (como la comunicación con implementaciones del subconjunto JBIG1) y para fines de depuración, normalmente no querrá cambiar nada aquí. El valor predeterminado es 28, que proporciona el mejor resultado de compresión.

-C cadena
Agrega la cadena en un segmento de marcador de comentario al flujo de datos producido. (Actualmente no hay soporte para agregar comentarios que contengan el byte cero).
-c
Determina el movimiento de la plantilla adaptativa como se sugiere en el anexo C del estándar. Por defecto, el cambio de plantilla tiene lugar directamente en la siguiente línea, lo cual es lo más efectivo. Sin embargo, algunos ejemplos de prueba de conformidad en el estándar requieren que el cambio de plantilla adaptativa se retrase hasta la primera línea de la siguiente banda. Esta opción selecciona este comportamiento especial, que normalmente no se requiere, excepto para pasar algunas pruebas de conformidad.
-r
Utiliza el marcador SDRST en lugar del marcador normal SDNORM. La probablemente única aplicación útil de esta opción es generar datos de prueba para verificar si un decodificador JBIG1 ha implementado

pbmtojbg(1) - Arch Linux manual pages

NAME

pbmtojbg – convert PBM images to the JBIG/JBIG1 format

SYNOPSIS

pbmtojbg [‑]
pbmtojbg [‑options]
[pbmfile]

DESCRIPTION

The pbmtojbg program reads PBM images as input and encodes them into the JBIG/JBIG1 format. JBIG1 is a lossless bi-level image compression standard that is particularly suited for scanned documents. The output is written to the standard output, unless specified otherwise.

The input PBM image is read from the file name pbmfile, or from the standard input if no file name is given.

OPTIONS

-c
A normal JBIG1 data stream contains a sequence of stripe data entities (SDEs). Each SDE is terminated by an SDNORM marker, which preserves the state of the arithmetic encoder (and more) for the next stripe in the same layer. The alternative SDRST marker resets this state at the end of the stripe. This option causes SDRST markers to be used instead of SDNORM markers to terminate each stripe data entity. This saves a little space, but makes the resulting file potentially incompatible with some JBIG1 decoders, which may not have implemented SDRST correctly.
-Y number
Some old fax machines could not store a whole page in memory. They had to start transmitting data before the entire page was scanned and its length known. The authors of the standard added a rather ugly hack to the otherwise beautiful JBIG1 format to support this. The NEWLEN marker segment can override the image height stated in the BIE header anywhere later in the data stream. Normally pbmtojbg never generates NEWLEN marker segments, as it knows the correct image height when it outputs the header. This option is solely intended for the purpose of generating test files with NEWLEN marker segments. It can be used to specify a higher initial image height for use in the BIE header, and pbmtojbg will then add a NEWLEN marker segment at the latest possible opportunity to the data stream to signal the correct final height.
-f
This option makes the output file comply to the "facsimile application profile" defined in ITU-T Recommendation T.85. It is a shortcut for -q -o 0 -p 8 -s 128 -t 1 -m 127.
-v
After the BIE has been created, a few technical details of the created file will be listed (verbose mode).

BUGS

Using standard input and standard output for binary data works only on systems where there is no difference between binary and text streams (e.g., Unix). On other systems (e.g., MS-DOS), using standard input or standard output may cause control characters like CR or LF to be inserted or deleted and this will damage the binary data.

STANDARDS

This program implements the JBIG1 image coding algorithm as specified in ISO/IEC 11544:1993 and ITU-T T.82(1993).

AUTHOR

The pbmtojbg program is part of the JBIG-KIT package, which has been developed by Markus Kuhn. The most recent version of this portable JBIG1 library and tools set is available from http://www.cl.cam.ac.uk/~mgk25/jbigkit/.
