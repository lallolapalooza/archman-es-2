pbzip2(1) Manual de Comandos Generales pbzip2(1)

NOMBRE

pbzip2 - compresor de archivos bzip2 paralelo, v1.1.10

SINOPSIS

pbzip2 [ -123456789 ] [ -b#cdfhklm#p#qrS#tvVz ] [ archivos ... ]

DESCRIPCIÓN

pbzip2 es una implementación paralela del compresor de archivos de ordenación de bloques bzip2 que utiliza pthreads y logra una aceleración casi lineal en máquinas SMP. La salida de esta versión es totalmente compatible con bzip2 v1.0.2 o posterior (es decir, cualquier cosa comprimida con pbzip2 se puede descomprimir con bzip2).

pbzip2 debería funcionar en cualquier sistema que tenga un compilador C++ compatible con pthreads (como gcc). Ha sido probado en: Linux, Windows (cygwin), Solaris, Tru64/OSF1, HP-UX e Irix.

La configuración predeterminada para pbzip2 funcionará bien en la mayoría de los casos. El único interruptor que probablemente necesite usar es -d para descomprimir archivos y -p para establecer el número de procesadores que pbzip2 utilizará si la autodetección no es compatible en su sistema, o si desea usar un número específico de CPUs.

OPCIONES

-b#
Donde # es el tamaño del bloque en pasos de 100k (por defecto 9 = 900k)
-c, --stdout
Salida a la salida estándar (stdout)
-d,--decompress
Descomprimir archivo
-f,--force
Forzar, sobrescribir el archivo de salida existente
-h,--help
Imprimir este mensaje de ayuda
-k,--keep
Mantener el archivo de entrada, no eliminarlo
-l,--loadavg
El promedio de carga determina el número máximo de procesadores a usar
-m#
Donde # es el uso máximo de memoria en pasos de 1MB (por defecto 100 = 100MB)
-p#
Donde # es el número de procesadores (por defecto: autodetección)
-q,--quiet
Modo silencioso (por defecto)
-r,--read
Leer el archivo de entrada completo en RAM y dividirlo entre procesadores
-S#
Tamaño de la pila del hilo hijo en pasos de 1KB (tamaño de pila por defecto si no se especifica)
-t,--test
Probar la integridad del archivo comprimido
-v,--verbose
Modo detallado
-V
Mostrar información de versión de pbzip2 y salir
-z,--compress
Comprimir archivo (por defecto)
-1,--fast ... -9,--best
Establecer el tamaño del bloque BWT a 100k .. 900k (por defecto 900k).
--ignore-trailing-garbage=#
Bandera para ignorar basura al final (# = 1 ignorada; # = 0 prohibida)

Si no se proporcionan nombres de archivo, pbzip2 comprime o descomprime desde la entrada estándar a la salida estándar.

TAMAÑOS DE ARCHIVO

Debería poder comprimir archivos de más de 4 GB con pbzip2.

Los archivos que se comprimen con pbzip2 se dividen en piezas y cada pieza individual se comprime. Así es como pbzip2 se ejecuta más rápido en múltiples CPUs, ya que las piezas se pueden comprimir simultáneamente. El archivo .bz2 final puede ser ligeramente más grande que si se hubiera comprimido con el programa bzip2 normal (generalmente menos del 0.2% más grande). Los archivos que se comprimen con pbzip2 también obtendrán una aceleración considerable al descomprimirse usando pbzip2.

Los archivos que se comprimieron usando bzip2 no verán una aceleración, ya que bzip2 empaqueta los datos en un solo bloque que no se puede dividir entre procesadores.

EJEMPLOS

Ejemplo 1: pbzip2 myfile.tar

Este ejemplo comprimirá el archivo "myfile.tar" en el archivo comprimido "myfile.tar.bz2". Utilizará el número de procesadores detectado automáticamente (o 2 procesadores si la autodetección no es compatible) con el tamaño de bloque de archivo predeterminado de 900k y el tamaño de bloque BWT predeterminado de 900k.

Ejemplo 2: pbzip2 -b15k myfile.tar

Este ejemplo comprimirá el archivo "myfile.tar" en el archivo comprimido "myfile.tar.bz2". Utilizará el número de procesadores detectado automáticamente (o 2 procesadores si la autodetección no es compatible) con un tamaño de bloque de archivo de 1500k y un tamaño de bloque BWT de 900k. El archivo "myfile.tar" no se eliminará después de que finalice la compresión.

Ejemplo 3: pbzip2 -p4 -r -5 myfile.tar second*.txt

Este ejemplo comprimirá el archivo "myfile.tar" en el archivo comprimido "myfile.tar.bz2". Utilizará 4 procesadores con un tamaño de bloque BWT de 500k. El tamaño del bloque de archivo será el tamaño de "myfile.tar" dividido por 4 (número de procesadores) para que los datos se dividan uniformemente entre cada procesador. Esto requiere que tenga suficiente RAM para que pbzip2 lea el archivo completo en memoria para su compresión. Luego, Pbzip2 utilizará las mismas opciones para comprimir todos los demás archivos que coincidan con el comodín "second*.txt" en ese directorio.

Ejemplo 4: tar cf myfile.tar.bz2 --use-compress-prog=pbzip2 dir_to_compress/
Ejemplo 4: tar -c directory_to_compress/ | pbzip2 -c > myfile.tar.bz2

Estos ejemplos comprimirán los datos que se pasan a pbzip2 a través de una tubería desde TAR al archivo comprimido "myfile.tar.bz2". Utilizará el número de procesadores detectado automáticamente (o 2 procesadores si la autodetección no es compatible) con el tamaño de bloque de archivo predeterminado de 900k y el tamaño de bloque BWT predeterminado de 900k. TAR está recopilando todos los archivos del directorio "directory_to_compress/" y pasando los datos a pbzip2 mientras trabaja.

Ejemplo 5: pbzip2 -d -m500 myfile.tar.bz2

Este ejemplo descomprimirá el archivo "myfile.tar.bz2" en el archivo descomprimido "myfile.tar". Utilizará el número de procesadores detectado automáticamente (o 2 procesadores si la autodetección no es compatible). Utilizará un máximo de 500 MB de memoria para la descompresión. Los interruptores -b, -r y -1..-9 no son válidos para la descompresión.

Ejemplo 6: pbzip2 -dc myfile.tar.bz2 | tar x

Este ejemplo descomprimirá y desempaquetará el archivo "myfile.tar.bz2", canalizando la salida del pbzip2 en proceso de descompresión a tar.

Ejemplo 7: pbzip2 -c < myfile.txt > myfile.txt.bz2

Este ejemplo leerá myfile.txt desde la entrada estándar, comprimiéndola a la salida estándar, que se redirigirá a myfile.txt.bz2.
