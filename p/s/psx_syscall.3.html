LIBPSX(3) Manual de programador de Linux LIBPSX(3)

NOMBRE

psx_syscall3, psx_syscall6, psx_set_sensitivity - Semántica POSIX para llamadas al sistema

SINOPSIS

#include <sys/psx_syscall.h>
long int psx_syscall3(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3);
long int psx_syscall6(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3,
                      long int arg4, long int arg5, long int arg6);
int psx_set_sensitivity(psx_sensitivity_t sensitivity);
void psx_load_syscalls(long int (**syscall_fn)(long int,
                                    long int, long int, long int),
                       long int (**syscall6_fn)(long int,
                                    long int, long int, long int,
                                    long int, long int, long int));

Cualquier código que utilice una de las funciones anteriores se puede enlazar de la siguiente manera:

ld ... -lpsx -lpthread

gcc ... -lpsx -lpthread

Nota: se necesitan indicadores especiales para que -lcap opere con capacidades de proceso completas cuando se enlaza con -lpsx. Específicamente, utilice el archivo de opciones pkg-config: gcc ... -lcap $(pkg-config --libs --cflags libpsx). Hay más detalles disponibles en la página del manual de cap_get_proc(3).

DESCRIPCIÓN

La biblioteca libpsx intenta llenar un vacío dejado por la implementación de pthreads(7) en Linux. Para ser hilos compatibles con POSIX, a través del mecanismo setxid de nptl(7), glibc mantiene credenciales UID y GID consistentes entre todos los hilos asociados con el proceso actual. Sin embargo, otro estado de credenciales no es compatible con esta abstracción. Para admitir estos atributos de seguridad extendidos administrados por el kernel, libpsx proporciona un par de funciones de envoltura de llamada al sistema más genéricas: psx_syscall3() y psx_syscall6(). Al igual que el mecanismo setxid, la coordinación del estado del hilo se media mediante una señal en tiempo real. Mientras que el mecanismo nptl:setxid utiliza signo=33 (que glibc oculta por debajo de un SIGRTMIN redefinido), libpsx se inserta en la pila del manejador de SIGSYS. Se esfuerza por ser el primer manejador de este tipo, pero actúa como un paso intermedio para otros usos de SIGSYS.

Un truco de macroeficiencia ineficiente admite la pseudofunción psx_syscall() que toma de 1 a 7 argumentos, dependiendo de las necesidades del llamante. La macroeficiencia (que finalmente invoca a __psx_syscall()) rellena la llamada para usar realmente psx_syscall3() o psx_syscall6() con ceros que rellenan los argumentos faltantes. Si bien usar esto en el código fuente lo hará parecer limpio, la huella del código real es mayor. Se le anima a usar las funciones más explícitas psx_syscall3() y psx_syscall6() según sea necesario.

psx_set_sensitivity() cambia el comportamiento de las llamadas al sistema reflejadas: PSX_IGNORE asegura que las diferencias se ignoren (el comportamiento predeterminado); PSX_WARNING imprime una notificación de error estándar sobre cómo difieren los resultados; y PSX_ERROR imprime los detalles del error y genera una señal SIGSYS.

psx_load_syscalls() se puede usar para establecer punteros de función definidos por el llamante para invocar llamadas al sistema de 3 y 6 argumentos. Esta función se puede usar para configurar una biblioteca o un programa para cambiar el comportamiento al enlazarse con libpsx. De hecho, libcap utiliza esta función de libpsx para anular su API predeterminada de llamada al sistema basada en hilos. Al enlazarse con libpsx, libcap puede operar en todos los hilos de un programa multihilo para operar con semántica POSIX.

VALOR DE RETORNO

El valor de retorno para las funciones de llamada al sistema es generalmente el valor devuelto por el kernel, o -1 en caso de error. En tales casos, errno(3) se establece en el valor detallado del error. Las funciones psx_syscall3() y psx_syscall6() intentan una llamada al sistema de un solo hilo y devuelven inmediatamente en caso de error. Si esta llamada tiene éxito, las mismas llamadas al sistema se ejecutan desde un manejador de señales en cada uno de los otros hilos del proceso.

CONFORMIDAD

Las necesidades de libcap(3) para semántica POSIX de manipulación de capacidades. Puede leer más sobre por qué esto es necesario aquí:

https://sites.google.com/site/fullycapable/who-ordered-libpsx

Las versiones de libpsx anteriores a la 2.72 solo admitían pthreads. Desde libpsx-2.72, la biblioteca funciona con todas las implementaciones de hilos de Linux, ya que opera en el nivel de abstracción de hilos más bajo, LWPs.
