PSELECT(3P) Manual del programador POSIX PSELECT(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pselect, select — multiplexación síncrona de E/S

SINOPSIS

#include <sys/select.h>
int pselect(int nfds, fd_set *restrict readfds,
    fd_set *restrict writefds, fd_set *restrict errorfds,
    const struct timespec *restrict timeout,
    const sigset_t *restrict sigmask);
int select(int nfds, fd_set *restrict readfds,
    fd_set *restrict writefds, fd_set *restrict errorfds,
    struct timeval *restrict timeout);
void FD_CLR(int fd, fd_set *fdset);
int FD_ISSET(int fd, fd_set *fdset);
void FD_SET(int fd, fd_set *fdset);
void FD_ZERO(fd_set *fdset);

DESCRIPCIÓN

La función pselect() examinará los conjuntos de descriptores de archivo cuyas direcciones se pasan en los parámetros readfds, writefds y errorfds para ver si algunos de sus descriptores están listos para leer, listos para escribir o tienen una condición excepcional pendiente, respectivamente.

La función select() será equivalente a la función pselect(), excepto en lo siguiente:

*
Para la función select(), el período de tiempo de espera se da en segundos y microsegundos en un argumento de tipo struct timeval, mientras que para la función pselect() el período de tiempo de espera se da en segundos y nanosegundos en un argumento de tipo struct timespec.
*
La función select() no tiene un argumento sigmask; se comportará como lo hace pselect() cuando sigmask es un puntero nulo.
*
Al completarse con éxito, la función select() puede modificar el objeto al que apunta el argumento timeout.

Las funciones pselect() y select() admitirán archivos regulares, dispositivos de terminal y pseudoterminales, archivos basados en STREAMS, FIFOs, tuberías y sockets. El comportamiento de pselect() y select() en descriptores de archivo que se refieren a otros tipos de archivo no está especificado.

El argumento nfds especifica el rango de descriptores a probar. Los primeros nfds descriptores se comprobarán en cada conjunto; es decir, se examinarán los descriptores desde cero hasta nfds-1 en los conjuntos de descriptores.

Si el argumento readfds no es un puntero nulo, apunta a un objeto de tipo fd_set que en la entrada especifica los descriptores de archivo a comprobar si están listos para leer, y en la salida indica qué descriptores de archivo están listos para leer.

Si el argumento writefds no es un puntero nulo, apunta a un objeto de tipo fd_set que en la entrada especifica los descriptores de archivo a comprobar si están listos para escribir, y en la salida indica qué descriptores de archivo están listos para escribir.

Si el argumento errorfds no es un puntero nulo, apunta a un objeto de tipo fd_set que en la entrada especifica los descriptores de archivo a comprobar si hay condiciones de error pendientes, y en la salida indica qué descriptores de archivo tienen condiciones de error pendientes.

Al completarse con éxito, la función pselect() o select() modificará los objetos a los que apuntan los argumentos readfds, writefds y errorfds para indicar qué descriptores de archivo están listos para leer, listos para escribir o tienen una condición de error pendiente, respectivamente, y devolverá el número total de descriptores listos en todos los conjuntos de salida. Para cada descriptor de archivo menor que nfds, el bit correspondiente se establecerá al completarse con éxito si estaba establecido en la entrada y la condición asociada es verdadera para ese descriptor de archivo.

Si ninguno de los descriptores seleccionados está listo para la operación solicitada, la función pselect() o select() se bloqueará hasta que al menos una de las operaciones solicitadas esté lista, hasta que ocurra el timeout, o hasta que sea interrumpida por una señal. El parámetro timeout controla cuánto tiempo tardará la función pselect() o select() antes de agotar el tiempo de espera. Si el parámetro timeout no es un puntero nulo, especifica un intervalo máximo de espera para que se complete la selección. Si expira el intervalo de tiempo especificado sin que ninguna operación solicitada esté lista, la función devolverá. Si el parámetro timeout es un puntero nulo, entonces la llamada a pselect() o select() se bloqueará indefinidamente hasta que al menos un descriptor cumpla los criterios especificados. Para efectuar un sondeo, el parámetro timeout no debe ser un puntero nulo y debe apuntar a una estructura timespec con valor cero.

El uso de un tiempo de espera no afecta a ningún temporizador pendiente configurado por alarm() o setitimer().

Las implementaciones pueden imponer limitaciones en el intervalo máximo de tiempo de espera admitido. Todas las implementaciones admitirán un intervalo máximo de tiempo de espera de al menos 31 días. Si el argumento timeout especifica un intervalo de tiempo de espera mayor que el valor máximo definido por la implementación, se utilizará el valor máximo como valor real de tiempo de espera. Las implementaciones también pueden imponer limitaciones en la granularidad de los intervalos de tiempo de espera. Si el intervalo de tiempo de espera solicitado requiere una granularidad más fina que la admitida por la implementación, el intervalo de tiempo de espera real se redondeará al valor soportado más cercano.

Si sigmask no es un puntero nulo, entonces la función pselect() reemplazará la máscara de señales del llamante por el conjunto de señales apuntado por sigmask antes de examinar los descriptores, y restaurará la máscara de señales del hilo llamante antes de retornar.

Un descriptor se considerará listo para leer cuando una llamada a una función de entrada con O_NONBLOCK desactivado no se bloquee, tanto si la función transfiere datos correctamente como si no. (La función podría devolver datos, una indicación de fin de archivo o un error distinto de uno que indique que está bloqueado, y en cada uno de estos casos el descriptor se considerará listo para leer).

Un descriptor se considerará listo para escribir cuando una llamada a una función de salida con O_NONBLOCK desactivado no se bloquee, tanto si la función transfiere datos correctamente como si no.

Si un socket tiene un error pendiente, se considerará que tiene una condición excepcional pendiente. De lo contrario, lo que constituye una condición excepcional es específico del tipo de archivo. Para un descriptor de archivo para su uso con un socket, es específico del protocolo excepto como se indica a continuación. Para otros tipos de archivo, está definido por la implementación. Si la operación no es significativa para un tipo de archivo particular, pselect() o select() indicarán que el descriptor está listo para operaciones de lectura o escritura, y indicarán que el descriptor no tiene ninguna condición excepcional pendiente.

Si un descriptor se refiere a un socket, la función de entrada implícita es la función recvmsg() con parámetros que solicitan datos normales y auxiliares, de modo que la presencia de cualquiera de los tipos haga que el socket se marque como legible. La presencia de datos fuera de banda se comprobará si la opción de socket SO_OOBINLINE ha sido habilitada, ya que los datos fuera de banda se ponen en cola con los datos normales. Si el socket está actualmente escuchando, entonces se marcará como legible si se ha recibido una solicitud de conexión entrante, y una llamada a la función accept() se completará sin bloquear.

Si un descriptor se refiere a un socket, la función de salida implícita es la función sendmsg() que suministra una cantidad de datos normales igual al valor actual de la opción SO_SNDLOWAT para el socket. Si se ha realizado una llamada no bloqueante a la función connect() para un socket, y el intento de conexión ha tenido éxito o ha fallado dejando un error pendiente, el socket se marcará como escribible.

Un socket se considerará que tiene una condición excepcional pendiente si una operación de recepción con O_NONBLOCK desactivado para la descripción de archivo abierta y con el indicador MSG_OOB establecido devolviera datos fuera de banda sin bloquear. (Es específico del protocolo si el indicador MSG_OOB se utilizaría para leer datos fuera de banda). Un socket también se considerará que tiene una condición excepcional pendiente si hay una marca de datos fuera de banda en la cola de recepción. Otras circunstancias bajo las cuales un socket puede considerarse que tiene una condición excepcional pendiente son específicas del protocolo y definidas por la implementación.

Si los argumentos readfds, writefds y errorfds son todos punteros nulos y el argumento timeout no es un

null pointer, la función pselect() o select() se bloqueará durante el tiempo especificado, o hasta que sea interrumpida por una señal. Si los argumentos readfds, writefds y errorfds son todos punteros nulos y el argumento timeout es un puntero nulo, la función pselect() o select() se bloqueará hasta que sea interrumpida por una señal.

Los descriptores de archivo asociados con archivos regulares siempre seleccionarán verdadero para listo para leer, listo para escribir y condiciones de error.

En caso de fallo, los objetos a los que apuntan los argumentos readfds, writefds y errorfds no se modificarán. Si el intervalo de tiempo de espera expira sin que la condición especificada sea verdadera para alguno de los descriptores de archivo especificados, los objetos a los que apuntan los argumentos readfds, writefds y errorfds tendrán todos los bits establecidos a 0.

Las máscaras de descriptores de archivo de tipo fd_set se pueden inicializar y probar con FD_CLR(), FD_ISSET(), FD_SET() y FD_ZERO(). No se especifica si cada una de estas es una macro o una función. Si se suprime una definición de macro para acceder a una función real, o si un programa define un identificador externo con alguno de estos nombres, el comportamiento no está definido.

FD_CLR(fd, fdsetp) eliminará el descriptor de archivo fd del conjunto al que apunta fdsetp. Si fd no es miembro de este conjunto, no tendrá ningún efecto en el conjunto, ni se devolverá ningún error.

FD_ISSET(fd, fdsetp) evaluará a un valor distinto de cero si el descriptor de archivo fd es miembro del conjunto al que apunta fdsetp, y evaluará a cero en caso contrario.

FD_SET(fd, fdsetp) añadirá el descriptor de archivo fd al conjunto al que apunta fdsetp. Si el descriptor de archivo fd ya está en este conjunto, no tendrá ningún efecto en el conjunto, ni se devolverá ningún error.

FD_ZERO(fdsetp) inicializará el conjunto de descriptores al que apunta fdsetp al conjunto nulo. No se devuelve ningún error si el conjunto no está vacío en el momento en que se invoca FD_ZERO().

El comportamiento de estas macros no está definido si el argumento fd es menor que 0 o mayor o igual que FD_SETSIZE, o si fd no es un descriptor de archivo válido, o si alguno de los argumentos son expresiones con efectos secundarios.

Si un hilo es cancelado durante una llamada a pselect(), la máscara de señales en efecto al ejecutar las funciones de limpieza registradas es la máscara de señales original o la máscara de señales instalada como parte de la llamada a pselect().

VALOR DE RETORNO

Al completarse con éxito, las funciones pselect() y select() devolverán el número total de bits establecidos en las máscaras de bits. De lo contrario, se devolverá -1 y errno se establecerá para indicar el error.

FD_CLR(), FD_SET() y FD_ZERO() no devuelven valor. FD_ISSET() devolverá un valor distinto de cero si el bit para el descriptor de archivo fd está establecido en el conjunto de descriptores de archivo al que apunta fdset, y 0 en caso contrario.

ERRORES

En las siguientes condiciones, pselect() y select() fallarán y establecerán errno a:

EBADF
Uno o más de los conjuntos de descriptores de archivo especificaron un descriptor de archivo que no es un descriptor de archivo válido y abierto.
EINTR
La función fue interrumpida mientras estaba bloqueada esperando que cualquiera de los descriptores seleccionados estuviera listo y antes de que expirara el intervalo de tiempo de espera.

Si SA_RESTART se ha establecido para la señal de interrupción, es definido por la implementación si la función se reinicia o devuelve con [EINTR].

EINVAL
Se especificó un intervalo de tiempo de espera no válido.
EINVAL
El argumento nfds es menor que 0 o mayor o igual que FD_SETSIZE.
EINVAL
Uno de los descriptores de archivo especificados se refiere a un STREAM o multiplexor que está enlazado (directa o indirectamente) aguas abajo de un multiplexor.

FUNDAMENTOS RACIONALES

En versiones anteriores de la especificación UNIX única, la función select() se definía en el encabezado <sys/time.h>. Esto ahora se ha cambiado a <sys/select.h>. El fundamento de este cambio fue el siguiente: la introducción de la función pselect() incluyó el encabezado <sys/select.h> y el encabezado <sys/select.h> define todas las definiciones relacionadas para las funciones pselect() y select(). La retrocompatibilidad con las implementaciones XSI existentes se maneja permitiendo que <sys/time.h> incluya <sys/select.h>.

El código que desea evitar la ambigüedad de la máscara de señales para los manejadores de cancelación de hilos puede instalar un manejador de cancelación adicional que restablezca la máscara de señales al valor esperado.

void cleanup(void *arg)
{
    sigset_t *ss = (sigset_t *) arg;
    pthread_sigmask(SIG_SETMASK, ss, NULL);
}
int call_pselect(int nfds, fd_set *readfds, fd_set *writefds,
    fd_set errorfds, const struct timespec *timeout,
    const sigset_t *sigmask)
{
    sigset_t oldmask;
    int result;
    pthread_sigmask(SIG_SETMASK, NULL, &oldmask);
    pthread_cleanup_push(cleanup, &oldmask);
    result = pselect(nfds, readfds, writefds, errorfds, timeout, sigmask);
    pthread_cleanup_pop(0);
    return result;
}
