NOMBRE

profile-sync-daemon - Vincula y sincroniza perfiles de navegador en RAM (tmpfs) reduciendo así las llamadas a HDD/SSD y acelerando los navegadores.

DESCRIPCIÓN

Profile-sync-daemon (psd) es un pequeño pseudo-demonio diseñado para gestionar el/los perfil(es) del navegador en tmpfs y sincronizar periódicamente de vuelta al disco físico (HDD/SSD). Esto se logra mediante un uso innovador de rsync para mantener la sincronización entre una copia en tmpfs y una copia de respaldo del/los perfil(es) del navegador almacenada en medios físicos. Además, psd presenta varias características de recuperación ante fallos.

Objetivos de diseño de psd:

  • Experiencia de usuario completamente transparente.
  • Reducción del desgaste de discos físicos (particularmente SSD).
  • Velocidad.

Dado que el/los perfil(es), la caché del navegador*, etc. se reubican en tmpfs (disco RAM), las I/O asociadas al uso del navegador también se redirigen del disco físico a la RAM, reduciendo así el desgaste del disco físico y mejorando la capacidad de respuesta del navegador.

*Nota que algunos navegadores como Chrome/Chromium, Firefox (desde la v21), Midori y Rekonq, en realidad mantienen sus directorios de caché separados de su directorio de perfil del navegador. No está dentro del alcance de profile-sync-daemon modificar este comportamiento; los usuarios que deseen reubicar este directorio pueden consultar la siguiente URL para varios soluciones provisionales: https://wiki.archlinux.org/index.php/Chromium_Tips_and_Tweaks#Cache_in_tmpfs

CONFIGURACIÓN

$XDG_CONFIG_HOME/psd/psd.conf (denominado en adelante "el archivo de configuración") contiene todas las configuraciones gestionadas por el usuario.

NOTA: las ediciones realizadas en el archivo de configuración mientras psd está activo solo se aplicarán después de reiniciar el servicio.

  • Habilita opcionalmente el uso de overlayfs para mejorar la velocidad de sincronización y utilizar una menor huella de memoria. Haz esto en la variable USE_OVERLAYFS. El usuario no requerirá derechos sudo sin contraseña para /usr/bin/psd-overlay-helper para usar esta opción y el kernel debe soportar overlayfs versión 22 o superior. Consulta la sección de Preguntas Frecuentes (FAQ) más abajo para obtener detalles adicionales.
  • Opcionalmente, haz que psd resincronice al sistema de archivos antes de una llamada de suspensión. Esto puede ayudar en caso de que el sistema no se reactive correctamente. Haz esto en la variable USE_SUSPSYNC.
  • Define opcionalmente qué navegadores se van a gestionar en el array BROWSERS. Si no se define ninguno, el predeterminado son todos los navegadores detectados.
  • Opcionalmente, deshabilita el uso de instantáneas de recuperación ante fallos (no recomendado). Haz esto en la variable USE_BACKUPS.
  • Define opcionalmente el número de instantáneas de recuperación ante fallos a conservar. Haz esto en la variable BACKUP_LIMIT.

NOTA: ocasionalmente, se realizan actualizaciones/cambios en el archivo de configuración predeterminado (/usr/share/psd/psd.conf) upstream. La copia del usuario ($XDG_CONFIG_HOME/psd/psd.conf) deberá compararse (diff) con ella.

EJECUTANDO PSD

MODO DE VISTA PREVIA

La opción de vista previa se puede llamar para mostrar a los usuarios exactamente qué hará/está haciendo psd según las entradas en el archivo de configuración. También proporcionará información útil como el tamaño del perfil, las rutas y si se han creado instantáneas de recuperación.

 Psd gestionará lo siguiente según la configuración de /home/facade/.config/psd/.psd.conf:

INICIAR Y DETENER PSD

Psd viene con un servicio de usuario de systemd para iniciarlo o detenerlo (psd.service). Además, un temporizador de resincronización proporcionado ejecutará una resincronización por hora de tmpfs de vuelta al disco. El temporizador de resincronización se inicia automáticamente con psd.service, por lo que no es necesario iniciar el temporizador; solo inicia psd.service.

 $ systemctl --user [option] psd.service
Opciones disponibles: start stop enable disable

MODO DE LIMPIEZA

El modo de limpieza eliminará TODAS las instantáneas de recuperación que se hayan acumulado. Solo ejecútalo cuando estés seguro de que ya no se necesitan.

 $ psd c
 Profile-sync-daemon v6.39
 Eliminando 2 directorios de recuperación ante fallos para el perfil /home/facade/.config/chromium
  /home/facade/.config/chromium-backup-crashrecovery-20200423_171359
  /home/facade/.config/chromium-backup-crashrecovery-20200424_112204

NOTA SOBRE PERFILES VINCULADOS

Actualmente, psd no soporta perfiles vinculados y se negará a sincronizar si se detecta uno. Por ejemplo, tu perfil de firefox es ~/.mozilla/firefox/f8cv8bfu.default pero has movido ese directorio a /foo/bar/f8cv8bfu.default y lo has reemplazado con un enlace simbólico:

 $ ls -l ~/.mozilla/firefox
 lrwxrwxrwx 1 facade users  26 Oct  1 17:02 f8cv8bfu.default -> /foo/bar/f8cv8bfu.default
Ejecutar psd en modo de vista previa terminará con un error informándote de esto: 
 $ psd p
 Warning!
 /home/facade/.mozilla/firefox/f8cv8bfu.default parece ser un enlace simbólico, pero estos no están soportados.
 Por favor, haz que el perfil del navegador sea un directorio real e inténtalo de nuevo. Saliendo.
Una solución adecuada para firefox es simplemente editar ~/.mozilla/firefox/profiles.ini definiendo la ruta canónica allí. También necesitas ajustar el indicador IsRelative de la siguiente manera: 
 [Profile0]
 Name=default
 IsRelative=0
 Path=/foo/bar/f8cv8bfu.default
Pueden existir otras soluciones para otros navegadores, pero documentarlas todas aquí está fuera del alcance.

DISTROS SOPORTADAS

Dado que psd es solo un script de bash con un servicio systemd, debería funcionar en cualquier distribución de Linux que ejecute systemd. Varias distros proporcionan un paquete oficial o una opción mantenida por el usuario para instalar psd. También puedes compilar psd desde la fuente. Consulta el sitio web oficial para ver los paquetes disponibles, las dependencias y las instrucciones de instalación.

PREGUNTAS FRECUENTES (FAQ)

P1: ¿Qué es el modo overlayfs?

R1: Overlayfs es un sistema de archivos de unión simple integrado en el kernel de Linux versión 3.18.0. Cuando se utiliza con psd, se puede lograr una menor huella de memoria y operaciones de sincronización más rápidas. La magia está en cómo el montaje overlay solo escribe datos

FAQ

Q1: How is overlayfs mode different from default mode?

A1: In default mode, psd will make a copy of the profile to /run/user// and mount it via tmpfs. At shutdown, the contents of the tmpfs copy is synced back to the original profile directory. Using overlayfs is a variation of this. Instead of copying the entire profile, only the changes are stored in a separate directory. This is generally more efficient, especially for large profiles that have few changes.

Running in overlayfs mode has the exact same recovery features that psd uses in its default mode.

See the example in the PREVIEW MODE section above which shows a system using overlayfs to illustrate the typical memory savings. Note the "overlayfs size" report compared to the total "profile size" report for each profile. Be aware that these numbers will change depending on just how much new data is written to the profile, but in common use cases, the overlayfs size will always be less than the profile size.

Q2: How do I enable overlayfs mode?

A2: First, be sure psd is not active or else any changes to the config file will be ignored until it is restarted. Overlayfs mode is enabled with the USE_OVERLAYFS= variable which should be set to "yes" in the config file. Psd will automatically detect the overlayfs version available to the kernel if it is configured to use one of them. It is recommended to run psd in preview mode to verify that the system can in fact use overlayfs.

Users wanting to use overlayfs mode MUST have sudo rights without password prompt to /usr/bin/psd-overlay-helper or global sudo rights without password prompt. If the user does not have global rights, add the following line to /etc/sudoers after any other lines defining sudo access. It is recommended to use /usr/bin/visudo as root to set this up:

 foo ALL=(ALL) NOPASSWD: /usr/bin/psd-overlay-helper
Q3: Why do I have another browser profile directory "foo-back-ovfs" when I enable overlayfs?

A3: The way overlayfs works is to mount a read-only base copy (so-called lower dir) of the profile, and manage the new data on top of that. In order to avoid resyncing to the read-only filesystem, a copy is used instead. So using overlayfs is a trade-off: faster initial sync times and less memory usage vs. disk space in the home dir.

Q4: I need more memory to accommodate my profile/profiles in /run/user/xxxx. How can I allocate more?

A4: The standard way of controlling the size of /run/user/ is the RuntimeDirectorySize directive in logind.conf (see the man page for logind.conf for more). By default, 10% of physical memory is used but one can increase it safely. Remember that tmpfs only consumes what is actually used; the number specified here is just a maximum allowed.

Q5: My system crashed for some reason and psd didn't sync back. What do I do?

A5: The "last good" backup of the browser profile/profiles should be the filesystem. Upon restarting psd (on a reboot for example), a check is performed to see if the symlink to the tmpfs copy of the profile is invalid. If it is invalid, psd will snapshot the "last good" backup before it rotates it back into place. This is more for a sanity check that psd did no harm and that any data loss was a function of something else.

Q6: Where can I find this snapshot?

A6: It depends on the browser. The snapshot will be located in the same directory as the browser profile and it will contain a date-time-stamp that corresponds to the time at which the recovery took place. For example, a chromium snapshot will be ~/.config/chromium-backup-crashrecovery-20130912_153310 -- of course, the date_time suffix will be different.

Q7: How can I restore the snapshot?

A7: Follow these steps:

1.
Stop psd.
2.
Move the "bad" copy of the profile to a backup (don't blindly delete anything).
3.
Copy the snapshot directory to the name that browser expects.

Example using chromium:

1.
systemctl --user stop psd.service
2.
mv ~/.config/chromium ~/.config/chromium-bad
3.
cp -a ~/.config/chromium-backup-crashrecovery-20130912_153310 ~/.config/chromium

At this point, launch chromium which will use the backup snapshot just copied into place. If all is well, it is safe to delete ~/.config/chromium-bad and the snapshot. Remember, to start psd, no browsers must be open (or psd will refuse to start).

Q8: Can psd delete the snapshots automatically?

A8: Yes, run psd with the "clean" switch to delete snapshots.
