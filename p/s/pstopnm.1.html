NOMBRE

pstopnm - convertir un archivo PostScript a una imagen PNM

SINOPSIS

pstopnm

[-stdout]

[-forceplain]

[-help]

[-dpi=dpi]

[-xsize=píxeles] [-ysize=píxeles]

[-xborder=frac] [-yborder=frac] [-landscape]

[-portrait]

[-nocrop]

[-pbm

|-pgm

|-ppm]

[-llx=s] [-lly=s] [-urx=s] [-ury=s]

[-verbose]

[-xmax=píxeles] [-ymax=píxeles]

[-textalphabits={1,2,4}]

archivo_ps[.ps]

USO DE OPCIONES

Se acepta la abreviatura única mínima de la opción. Puede usar guiones dobles en lugar de un guion simple para denotar opciones. Puede usar espacio en blanco en lugar del signo igual para separar el nombre de una opción de su valor.

DESCRIPCIÓN

Este programa forma parte de Netpbm(1)

pstopnm lee un archivo PostScript como entrada y produce imágenes PBM, PGM o PPM como salida. Este programa simplemente utiliza Ghostscript para renderizar un archivo PostScript con sus controladores de dispositivo PNM. Si no tiene Ghostscript instalado o la versión que tiene instalada no fue compilada con los controladores de dispositivo PNM relevantes, pstopnm fallará. Puede ver si tiene el entorno adecuado emitiendo el comando gs --help. Si responde y enumera bajo 'Controladores disponibles' pbm, pbmraw, pgm, pgmraw, pnm, pnmraw, ppm o ppmraw, está listo.

Es importante entender que pstopnm es un conversor de formatos de archivo de imagen Netpbm solo en el sentido más amplio de la palabra, porque Postscript está lejos de ser un formato de archivo de imagen. Lo que pstopnm realmente es, es un renderizador Postscript, un generador de imágenes. Un lugar donde notará la diferencia es donde espera que pstopnm | pnmtops sea idempotente (lo cual no es el caso). Hay detalles sobre este tipo de conversión a continuación.

pstopnm utiliza el valor de la variable de entorno GHOSTSCRIPT como nombre de archivo para el programa Ghostscript. Si GHOSTSCRIPT no está configurado, pstopnm busca en su PATH un archivo regular llamado gs. Si no encuentra ninguno, asume que Ghostscript está en el archivo /usr/bin/gs.

pstopnm no utiliza las bibliotecas Netpbm para generar los archivos de salida, por lo que puede que no sea totalmente consistente con la mayoría de los programas Netpbm.

archivo_ps[.ps] es el nombre del archivo de entrada. pstopnm añadirá ps al final del nombre que especifique si no existe un archivo con el nombre exacto que especifica, pero sí uno con él añadido. Para la entrada estándar, use - o simplemente no proporcione ningún argumento.

Si usa la opción -stdout o si su entrada es desde la entrada estándar, pstopnm produce imágenes de todas las páginas como un archivo multi-imagen en la salida estándar. De lo contrario, pstopnm crea un archivo para cada página en la entrada PostScript. Los archivos se nombran de la siguiente manera: Si el archivo de entrada se llama archivo_ps.ps, el nombre de los archivos será archivo_ps001.ppm, archivo_ps002.ppm, etc. El sufijo del tipo de archivo es .ppm, .pgm o .pbm, dependiendo de qué tipo de salida elija con las opciones de su invocación. Si el nombre del archivo de entrada no termina en .ps, se utiliza todo el nombre del archivo en el nombre del archivo de salida. Por ejemplo, si el archivo de entrada se llama archivo_ps.old, el nombre del archivo de salida es archivo_ps.old001.ppm, etc.

Tenga en cuenta que la selección del archivo de salida es inconsistente con la mayoría de los programas Netpbm, ya que no utiliza la salida estándar por defecto. Esto se debe a razones históricas, basadas en el hecho de que los formatos Netpbm no siempre contemplaban una secuencia de imágenes en un solo archivo.

Cuando su entrada es desde la entrada estándar, puede alimentar múltiples documentos PostScript encapsulados, uno tras otro, y pstopnm convierte cada documento y lo coloca en el flujo de salida estándar como una imagen. Pero si su entrada es desde un archivo con nombre, pstopnm espera que el archivo sea un archivo PostScript encapsulado, lo que significa que contiene solo un documento PostScript encapsulado. Si el archivo contiene múltiples documentos concatenados, pstopnm ignora todos los documentos excepto el primero. Esta distinción no existe para la entrada PostScript no EPSF; pstopnm genera una imagen de salida por cada página de entrada, independientemente de si la entrada proviene de la entrada estándar o de un archivo con nombre.

Tenga en cuenta que puede generar ambos tipos de archivos: EPSF concatenado y no EPSF multipágina, con pnmtops, seleccionando con la opción -setpage.

Cada imagen de salida contiene un área rectangular de la página a la que pertenece. Consulte la sección Dimensiones para obtener detalles sobre qué parte de la imagen de entrada va a la imagen de salida y cuán grande es en la salida, y qué bordes y márgenes hay en la imagen de salida.

Se ha informado que en algunas entradas PostScript Versión 1, Ghostscript, y por lo tanto pstopnm, no produce ninguna salida. Para resolver este problema, puede convertir el archivo a PostScript Versión 3 con el programa ps2ps. Se informa que el programa pstops no funciona.

Dimensiones

Esta sección describe qué parte de la imagen de entrada se utiliza en la salida y las dimensiones de la salida, incluidos los bordes y el fondo.

Tenga en cuenta que una imagen de salida se asocia con una sola página de entrada.

pstopnm comienza tomando un área rectangular de la página de entrada. A eso se le llama imagen sujeto.

pstopnm puede añadir bordes a la imagen sujeto para formar lo que se llama imagen sujeto con borde.

pstopnm coloca la imagen sujeto con borde en el centro de la imagen de salida y recorta los bordes según sea necesario para ajustarse al tamaño de imagen de salida calculado.

La ubicación de la imagen sujeto en la página de entrada PostScript se define por cuatro números, las coordenadas x e y de la esquina inferior izquierda y la esquina superior derecha. Estas coordenadas suelen especificarse mediante la declaración BoundingBox DSC (un comentario PostScript) en el archivo PostScript, pero pueden ser anuladas por el usuario especificando una o más de las siguientes opciones: -llx, -lly, -urx y -ury.

La presencia y el grosor de un borde que se añadirá a la imagen sujeto para formar la imagen sujeto con borde se controlan mediante las opciones -xborder y -yborder. Si pstopnm no encuentra una declaración BoundingBox en la entrada, y usted no especifica las coordenadas del área de la imagen en la línea de comandos, pstopnm utiliza valores predeterminados. Si su entrada es desde la entrada estándar, pstopnm no utiliza los valores de BoundingBox (debido a la dificultad técnica de extraer esa información y seguir alimentando el archivo a Ghostscript), por lo que debe especificar las coordenadas del área de la imagen o aceptar los valores predeterminados.

El tamaño de la imagen de salida es algo confuso. En un archivo PostScript, las cosas tienen dimensiones espaciales. Por ejemplo, una línea determinada puede tener 3 centímetros de largo. Se supone que una impresora PostScript imprime la línea con una longitud de 3 centímetros, utilizando tantos píxeles como sea necesario, sin tener en cuenta el tamaño de la hoja de papel en la que se imprime. En una imagen PNM, por el contrario, no hay dimensión espacial; solo hay píxeles. Puede tener una línea que tenga 100 píxeles de largo, pero la imagen PNM no dice nada sobre cuánto tiempo debe tener esa línea en una página impresa.

pstopnm desempeña la función de una impresora PostScript. La imagen PNM es una página impresa virtual. pstopnm debe determinar cuántos píxeles utilizará en la imagen de salida para representar una pulgada de imagen de entrada, que es la "resolución del dispositivo de salida". Piense en ello como el número de puntos por pulgada que la impresora virtual imprime en la página virtual.

Lo más sencillo es que usted le diga a pstopnm exactamente qué resolución de dispositivo de salida utilizar, usando la opción -dpi. Si dice, por ejemplo, -dpi=300 y la imagen sujeto con borde es de 2 pulgadas por 3 pulgadas, la salida PNM será de 600 píxeles por 900 píxeles. Usando este método, la resolución del dispositivo de salida debe ser la misma en ambas direcciones.

DESCRIPTION

The pstopnm utility converts PostScript documents to the PNM image format family. It uses Ghostscript to do the actual PostScript processing.

The subject image is the part of the PostScript page that contains your image data. pstopnm adds borders around this image, and then scales the result to the output image dimensions.

The Dimensions section

Determining the output dimensions of pstopnm can be confusing. This section attempts to clarify how it works.

The fundamental parameter is the output device resolution, which you set with -dpi. This is the number of pixels per inch in the output PNM image.

If you specify -dpi, then the output image dimensions are determined by the size of the subject image on the PostScript page, scaled by the output device resolution.

For example, if the subject image is 2 inches wide by 3 inches high, and you specify -dpi=600, then the output image is 1200 pixels wide by 1800 pixels high. Each pixel in the output image represents 1/600 inch of the subject image.

If you don't specify -dpi, then pstopnm derives the resolution from the output size options (-xsize and -ysize) or the -xmax and -ymax options.

Let's consider the case where you specify -xsize=1200 and -ysize=1800, and the bordered subject image is 2 inches wide by 3 inches high. The output image is 1200 by 1800 pixels, with each pixel representing 1/600 inch of input image.

In the unlikely event that you want different output device resolutions in the two directions, you could use -xsize and -ysize to do that. In the above example, if you change -ysize to 900, a pixel still represents 1/600 inch horizontally, but 1/300 inch vertically.

If you specify one of -xsize and -ysize and not the other, pstopnm defaults the other such that the output device resolution is the same in both directions.

The 'x' and 'y' of -xsize and -ysize refer to the image being printed on the page, not the page. So if pstopnm prints it in landscape orientation, 'x' would pertain to the vertical direction on the page, i.e. the vertical direction in the output PNM image.

If you specify -nocrop, pstopnm uses the values of -xmax and -ymax for the output image dimensions. These default to 612 and 792 pixels, respectively.

The final case, the default, is where you don't specify any size or resolution options or -nocrop. This is the most complicated case. In this case, pstopnm first chooses an output device resolution that would generate the number of pixels indicated by -xmax and -ymax from the bordered subject image. Then, based on that resolution, it chooses an output image size that is just large enough to accommodate the subject image (no borders). Remember (above) that pstopnm trims the edges of the bordered subject image to fit the computed output size.

Ghostscript Limitations

Tests done in 2013 with Ghostscript 8.71 indicate that Ghostscript's pgmraw output driver has some kind of rounding error that causes the pixel values to change slightly, and that means pstopnm generates incorrect output when you have monochrome Postscript input. But with color Postscript input, pstopnm uses Ghostscript's ppmraw output driver and generates correct PPM output.

Reversible Conversion

If you're trying to do the equivalent of the naive pnmtops | pstopnm, the following steps will do it.


    $ pnmtops -nocenter -equalpixels -dpi 72 -noturn testimg.ppm > testimg.ps
    $ pstopnm -xborder=0 -yborder=0 -xsize=XSIZE -ysize=YSIZE \
        -portrait -stdout -quiet testimg.ps >testimg2.ppm

XSIZE and YSIZE above are the image dimensions, which you can get from testimg.ps like in the following example (the grep, awk and echo commands are just to help demonstrate how the other commands work - you wouldn't use those in a program).


    $ grep "BoundingBox" testimg.ps
    %%BoundingBox: 0 0 227 149
    $ awk  '/%%BoundingBox/ {print $4,$5}' testimg.ps
     227 149
 
    $ xysize=$(awk  '/%%BoundingBox/ {print "-xsize="$4,"-ysize="$5}' testimg.ps)
    $ echo $xysize
     -xsize=227 -ysize=149
    $ pstopnm -xborder=0 -yborder=0 $xysize -portrait ... testimg.ps

Note that Ghostscript bugs can keep this from doing a perfect reversible conversion.

OPTIONS

-forceplain

forces the output file to be in plain (text) format. Otherwise, it is in raw (binary) format. See pbm(5) , etc.
-llx=bx
selects bx as the lower left corner x coordinate (in inches) on the Postscript input page of the subject image. See the Dimensions section .
-lly=by
selects by as the lower left corner y coordinate (in inches) on the Postscript input page of the subject image. See the Dimensions section .
-landscape
renders the image in landscape orientation.

If you specify neither -portrait nor -landscape, pstopnm chooses the orientation that best fits the image on the output page.

Landscape means printed sideways on the page, not printed the long way. Those are different things if the long edge of the page is the top one.

-portrait
renders the image in portrait orientation.

See -landscape.

-nocrop
This option causes pstopnm to make the output image exactly the dimensions of the bordered subject image. By default, pstopnm makes the output image the dimensions specified by -xmax and -ymax. See the Dimensions section .
-pbm
-pgm
-ppm
selects the format of the output file. By default, all files are rendered as PPM.
-stdout
causes output to go to Standard Output instead of to regular files, one per page (see description of output files above). Use pnmsplit to extract individual pages from Standard Output.
-urx=tx
selects tx as the upper right corner x coordinate (in inches) on the Postscript input page of the subject image. See the Dimensions section .
-ury=ty
selects ty as the upper right corner y coordinate (in inches) on the Postscript input page of the subject image. See the Dimensions section .
-verbose
prints processing information to stdout.
-xborder=frac
specifies that the left and right borders added to the subject image are to be frac times the subject image width. The default value is 0.1. See the Dimensions section .
-xmax=xmax
specifies that the output image is to be xmax pixels wide. The default is 612. See the Dimensions section .
-xsize=xsize
specifies that the output image is to be xsize pixels wide. See the Dimensions section .
-yborder=frac
specifies that the top and bottom borders added to the subject image are to be frac times the subject image height. The default value is 0.1. See the Dimensions section .
-ymax=ymax
specifies that the output image is to be ymax pixels high. The default is 792. See the Dimensions section .
-ysize=ysize
specifies that the output image is to be ymax pixels high. See the Dimensions section .
-dpi=dpi
specifies the output device resolution, in dots per inch, of the Postscript printer that pstopnm simulates. This is the number of PNM pixels pstopnm generates for each inch of image. See the Dimensions section .

This option was new in Netpbm 10.21 (March 2004).

-textalphabits={1,2,4}
This controls subsample antialiasing of text. Antialiasing is a form of smoothing that eliminates jagged edges on characters. Subsample antialiasing is a kind of antialiasing that uses subpixels in a box, and the value of this option is the size of that box. 4 gives you the best looking output, while 1 causes no antialiasing. Smaller numbers make pnmtops use less CPU time.

Pstopnm uses Ghostscript's TextAlphaBits parameter for this.

The default is 4.

This option was new in Netpbm 10.53 (December 2010). Older versions of pstopnm do no antialiasing.

LIMITATIONS

The program will produce incorrect results with PostScript files that initialize the current transformation matrix. In these cases, page translation and rotation will not have any effect. To render these files, probably the best bet is to use the following options:

    pstopnm -xborder 0 -yborder 0 -portrait -nocrop file.ps

Additional options may be needed if the document is supposed to be rendered on a medium different from letter-size paper.

pstopnm - convert PostScript/EPS graphics to PNM images

SYNOPSIS

pstopnm [OPTION]... [input.ps]

OPTION USAGE

The following options are available:

-n
This is the default. It causes ghostscript to produce the output image. The image is then converted by pspp.
-pspp
Only produces the output image of ghostscript. The image is then converted by pspp.
-noautoscale
If no scaling is set, ghostscript will scale it to fit 72 dpi. This option suppresses this automatic scaling. The output image will be the default resolution of the PostScript file (unless -scale is specified).
-scale=N
Scales the output image to N dpi. By default, ghostscript will scale it to fit 72 dpi.
-rotate
Rotates the output image. This is needed for some EPS files that are rotated.
-output=file
Writes the output image to ‘file’ instead of stdout.

DESCRIPTION

Reads a PostScript or Encapsulated PostScript (EPS) file as input and produces a Portable Anymap (PNM) image as output. This is done by running Ghostscript and then processing its output. The default processing is done by pspp.

This program is not intended to be particularly fast. It is intended to be used by other programs that need to convert PostScript to PNM format, rather than for interactive use.

OPTIONS

See OPTION USAGE.

LIMITATIONS

This program requires Ghostscript to be installed on your system.

It may be slow.
