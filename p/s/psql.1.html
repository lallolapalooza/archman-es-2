NOMBRE

psql - terminal interactiva de PostgreSQL

SINOPSIS

psql [opción...] [dbname [usuario]]

DESCRIPCIÓN

psql es un front-end basado en terminal para PostgreSQL. Te permite escribir consultas interactivamente, enviarlas a PostgreSQL y ver los resultados de las consultas. Alternativamente, la entrada puede provenir de un archivo o de argumentos de línea de comandos. Además, psql proporciona una serie de meta-comandos y varias características similares a las del shell para facilitar la escritura de scripts y la automatización de una amplia variedad de tareas.

OPCIONES

-a
--echo-all

Imprime todas las líneas de entrada no vacías en la salida estándar a medida que se leen. (Esto no se aplica a las líneas leídas interactivamente.) Esto es equivalente a establecer la variable ECHO a all.

-A
--no-align

Cambia al modo de salida no alineada. (El modo de salida predeterminado es alineado.) Esto es equivalente a \pset format unaligned.

-b
--echo-errors

Imprime los comandos SQL fallidos en la salida de error estándar. Esto es equivalente a establecer la variable ECHO a errors.

-c comando
--command=comando

Especifica que psql debe ejecutar la cadena de comando dada, comando. Esta opción se puede repetir y combinar en cualquier orden con la opción -f. Cuando se especifica -c o -f, psql no lee comandos de la entrada estándar; en su lugar, termina después de procesar todas las opciones -c y -f en secuencia.

comando debe ser una cadena de comando completamente analizable por el servidor (es decir, no contiene características específicas de psql), o un único comando de barra invertida. Por lo tanto, no puedes mezclar SQL y meta-comandos de psql dentro de una opción -c. Para lograr eso, puedes usar opciones -c repetidas o enviar la cadena a psql, por ejemplo:

psql -c '\x' -c 'SELECT * FROM foo;'

o

echo '\x \\ SELECT * FROM foo;' | psql

(\\ es el meta-comando separador.)

Cada cadena de comando SQL pasada a -c se envía al servidor como una sola solicitud. Debido a esto, el servidor la ejecuta como una sola transacción, incluso si la cadena contiene múltiples comandos SQL, a menos que haya comandos explícitos BEGIN/COMMIT incluidos en la cadena para dividirlos en múltiples transacciones. (Ver Sección 54.2.2.1 para más detalles sobre cómo el servidor maneja cadenas de múltiples consultas.)

Si no se desea ejecutar varios comandos en una transacción, use comandos -c repetidos o alimente múltiples comandos a la entrada estándar de psql, ya sea usando echo como se ilustra arriba, o a través de un here-document del shell, por ejemplo:

psql <<EOF
\x
SELECT * FROM foo;
EOF

--csv

Cambia al modo de salida CSV (Valores Separados por Comas). Esto es equivalente a \pset format csv.

-d dbname
--dbname=dbname

Especifica el nombre de la base de datos a la que conectarse. Esto es equivalente a especificar dbname como el primer argumento no opcional en la línea de comandos. El dbname puede ser una cadena de conexión. Si es así, los parámetros de la cadena de conexión anularán cualquier opción de línea de comandos en conflicto.

-e
--echo-queries

Copia todos los comandos SQL enviados al servidor a la salida estándar también. Esto es equivalente a establecer la variable ECHO a queries.

-E
--echo-hidden

Muestra las consultas reales generadas por \d y otros comandos de barra invertida. Puedes usar esto para estudiar las operaciones internas de psql. Esto es equivalente a establecer la variable ECHO_HIDDEN a on.

-f nombre_archivo
--file=nombre_archivo

Lee comandos del archivo nombre_archivo, en lugar de la entrada estándar. Esta opción se puede repetir y combinar en cualquier orden con la opción -c. Cuando se especifica -c o -f, psql no lee comandos de la entrada estándar; en su lugar, termina después de procesar todas las opciones -c y -f en secuencia. Excepto por eso, esta opción es en gran medida equivalente al meta-comando \i.

Si nombre_archivo es - (guion), entonces se lee la entrada estándar hasta una indicación de EOF o el meta-comando \q. Esto se puede usar para intercalar entrada interactiva con entrada de archivos. Ten en cuenta, sin embargo, que Readline no se utiliza en este caso (igual que si se hubiera especificado -n).

Usar esta opción es sutilmente diferente de escribir psql < nombre_archivo. En general, ambos harán lo que esperas, pero usar -f habilita algunas características útiles como mensajes de error con números de línea. También existe una pequeña posibilidad de que el uso de esta opción reduzca la sobrecarga de inicio. Por otro lado, la variante que utiliza la redirección de entrada del shell está garantizada (en teoría) para producir exactamente la misma salida que habrías recibido si hubieras ingresado todo manualmente.

-F separador
--field-separator=separador

Usa separador como el separador de campos para la salida no alineada. Esto es equivalente a \pset fieldsep o \f.

-h nombre_host
--host=nombre_host

Especifica el nombre del host de la máquina en la que se está ejecutando el servidor. Si el valor comienza con una barra, se utiliza como el directorio para el socket de dominio Unix.

-H
--html

Cambia al modo de salida HTML. Esto es equivalente a \pset format html o al comando \H.

-l
--list

Lista todas las bases de datos disponibles, luego sale. Otras opciones no de conexión se ignoran. Esto es similar al meta-comando \list.

Cuando se utiliza esta opción, psql se conectará a la base de datos postgres, a menos que se nombre una base de datos diferente en la línea de comandos (opción -d o argumento no opcional, posiblemente a través de una entrada de servicio, pero no a través de una variable de entorno).

-L nombre_archivo
--log-file=nombre_archivo

Escribe toda la salida de la consulta en el archivo nombre_archivo, además del destino de salida normal.

-n
--no-readline

No usar Readline para la edición de línea y no usar el historial de comandos (ver la sección llamada "Edición de línea de comandos" a continuación).

-o nombre_archivo
--output=nombre_archivo

Coloca toda la salida de la consulta en el archivo nombre_archivo. Esto es equivalente al comando \o.

-p puerto
--port=puerto

Especifica el puerto TCP o la extensión del archivo de socket de dominio Unix local en el que el servidor está escuchando las conexiones. Por defecto es el valor de la variable de entorno PGPORT o, si no está establecida, el puerto especificado en el momento de la compilación, generalmente 5432.

-P asignación
--pset=asignación

Especifica opciones de impresión, al estilo de \pset. Ten en cuenta que aquí tienes que separar el nombre y el valor con un signo igual en lugar de un espacio. Por ejemplo, para establecer el formato de salida a LaTeX, podrías escribir -P format=latex.

-q
--quiet

Especifica que psql debe hacer su trabajo en silencio. Por defecto, imprime mensajes de bienvenida y varias salidas informativas. Si se usa esta opción, nada de esto sucede. Esto es útil con la opción -c. Esto es equivalente a establecer la variable QUIET a on.

-R separador
--record-separator=separador

Usa separador como el separador de registros para la salida no alineada. Esto es equivalente a \pset recordsep.

-s
--single-step

Ejecuta en modo de un solo paso. Eso significa que se le pregunta al usuario antes de que cada comando se envíe al servidor, con la opción de cancelar la ejecución. Usa esto para depurar scripts.

-S
--single-line

>
Se ejecuta en modo de una sola línea donde un salto de línea termina un comando SQL, al igual que lo hace un punto y coma.

Nota
Este modo se proporciona para aquellos que insisten en él, pero no se les anima necesariamente a utilizarlo. En particular, si mezcla SQL y metacomandos en una línea, el orden de ejecución puede no ser siempre claro para el usuario inexperto.

-t
--tuples-only

Desactiva la impresión de nombres de columnas y pies de página con el recuento de filas de resultados, etc. Esto es equivalente a \t o \pset tuples_only.

-T opciones_tabla
--table-attr=opciones_tabla

Especifica opciones que se colocarán dentro de la etiqueta de tabla HTML. Consulte \pset tableattr para obtener detalles.

-U nombre_usuario
--username=nombre_usuario

Conéctese a la base de datos como el usuario nombre_usuario en lugar del predeterminado. (Debe tener permiso para hacerlo, por supuesto).

-v asignación
--set=asignación
--variable=asignación

Realiza una asignación de variable, similar al metacomando \set. Tenga en cuenta que debe separar el nombre y el valor, si los hay, con un signo igual en la línea de comandos. Para eliminar una variable, omita el signo igual. Para establecer una variable con un valor vacío, use el signo igual pero omita el valor. Estas asignaciones se realizan durante el procesamiento de la línea de comandos, por lo que las variables que reflejan el estado de la conexión se sobrescribirán más tarde.

-V
--version

Imprime la versión de psql y sale.

-w
--no-password

Nunca solicite una contraseña. Si el servidor requiere autenticación de contraseña y no se dispone de una contraseña de otras fuentes, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para introducir una contraseña.

Tenga en cuenta que esta opción permanecerá activa durante toda la sesión y, por lo tanto, afectará tanto al uso del metacomando \connect como al intento de conexión inicial.

-W
--password

Obliga a psql a solicitar una contraseña antes de conectarse a una base de datos, incluso si no se utilizará la contraseña.

Si el servidor requiere autenticación de contraseña y no se dispone de una contraseña de otras fuentes, como un archivo .pgpass, psql solicitará una contraseña en cualquier caso. Sin embargo, psql desperdiciará un intento de conexión al descubrir que el servidor quiere una contraseña. En algunos casos, vale la pena escribir -W para evitar el intento de conexión adicional.

Tenga en cuenta que esta opción permanecerá activa durante toda la sesión y, por lo tanto, afectará tanto al uso del metacomando \connect como al intento de conexión inicial.

-x
--expanded

Activa el modo de formato de tabla expandido. Esto es equivalente a \x o \pset expanded.

-X
--no-psqlrc

No lee el archivo de inicio (ni el archivo psqlrc del sistema ni el archivo ~/.psqlrc del usuario).

-z
--field-separator-zero

Establece el separador de campos para la salida no alineada a un byte cero. Esto es equivalente a \pset fieldsep_zero.

-0
--record-separator-zero

Establece el separador de registros para la salida no alineada a un byte cero. Esto es útil para interactuar, por ejemplo, con xargs -0. Esto es equivalente a \pset recordsep_zero.

-1
--single-transaction

Esta opción solo se puede usar en combinación con una o más opciones -c y/o -f. Hace que psql emita un comando BEGIN antes de la primera opción de este tipo y un comando COMMIT después de la última, lo que envuelve todos los comandos en una sola transacción. Si alguno de los comandos falla y la variable ON_ERROR_STOP estaba configurada, se envía un comando ROLLBACK en su lugar. Esto asegura que todos los comandos se completen correctamente o que no se apliquen cambios.

Si los comandos en sí contienen BEGIN, COMMIT o ROLLBACK, esta opción no tendrá los efectos deseados. Además, si un comando individual no se puede ejecutar dentro de un bloque de transacción, especificar esta opción hará que toda la transacción falle.

-?
--help[=tema]

Muestra ayuda sobre psql y sale. El parámetro opcional tema (predeterminado a options) selecciona qué parte de psql se explica: commands describe los comandos de barra invertida de psql; options describe las opciones de línea de comandos que se pueden pasar a psql; y variables muestra ayuda sobre las variables de configuración de psql.

ESTADO DE SALIDA

psql devuelve 0 a la shell si terminó normalmente, 1 si ocurre un error fatal propio (por ejemplo, falta de memoria, archivo no encontrado), 2 si la conexión con el servidor se interrumpió y la sesión no fue interactiva, y 3 si ocurrió un error en un script y la variable ON_ERROR_STOP estaba configurada.

USO

Conexión a una Base de Datos

psql es una aplicación cliente PostgreSQL normal. Para conectarse a una base de datos, necesita conocer el nombre de su base de datos de destino, el nombre de host y el número de puerto del servidor, y con qué nombre de usuario de base de datos desea conectarse. psql puede ser informado sobre esos parámetros a través de opciones de línea de comandos, específicamente -d, -h, -p y -U respectivamente. Si se encuentra un argumento que no pertenece a ninguna opción, se interpretará como el nombre de la base de datos (o el nombre de usuario de la base de datos, si el nombre de la base de datos ya se proporcionó). No todas estas opciones son necesarias; existen valores predeterminados útiles. Si omite el nombre del host, psql se conectará a través de un socket de dominio Unix a un servidor en el host local, o a través de TCP/IP a localhost en Windows. El número de puerto predeterminado se determina en el momento de la compilación. Dado que el servidor de base de datos utiliza el mismo valor predeterminado, no necesitará especificar el puerto en la mayoría de los casos. El nombre de usuario de base de datos predeterminado es su nombre de usuario del sistema operativo. Una vez determinado el nombre de usuario de la base de datos, se utiliza como nombre de base de datos predeterminado. Tenga en cuenta que no puede conectarse a cualquier base de datos con cualquier nombre de usuario de base de datos. Su administrador de base de datos debería haberle informado sobre sus derechos de acceso.

Cuando los valores predeterminados no son exactamente los correctos, puede ahorrarle escribir mucho configurando las variables de entorno PGDATABASE, PGHOST, PGPORT y/o PGUSER con valores apropiados. (Para variables de entorno adicionales, consulte la Sección 32.15). También es conveniente tener un archivo ~/.pgpass para evitar tener que escribir contraseñas regularmente. Consulte la Sección 32.16 para obtener más información.

Una forma alternativa de especificar parámetros de conexión es en una cadena conninfo o una URI, que se utiliza en lugar de un nombre de base de datos. Este mecanismo le brinda un control muy amplio sobre la conexión. Por ejemplo:

$ psql "service=myservice sslmode=require"
$ psql postgresql://dbmaster:5433/mydb?sslmode=require

De esta manera, también puede usar LDAP para la búsqueda de parámetros de conexión como se describe en la Sección 32.18. Consulte la Sección 32.1.2 para obtener más información sobre todas las opciones de conexión disponibles.

Si la conexión no se pudo realizar por algún motivo (por ejemplo, privilegios insuficientes, el servidor no se está ejecutando en el host de destino, etc.), psql generará un error y terminará.

Si la entrada estándar y la salida estándar son un terminal, entonces psql establece la codificación del cliente en "auto", que detectará la codificación del cliente apropiada a partir de la configuración regional (variable de entorno LC_CTYPE en sistemas Unix). Si esto no funciona como se esperaba, la codificación del cliente se puede anular utilizando la variable de entorno PGCLIENTENCODING.

Introducción de Comandos SQL

En operación normal, psql proporciona un prompt con el nombre de la base de datos a la que psql está conectado actualmente, seguido de la cadena =>. Por ejemplo:

$ psql testdb
psql (18.1)
Escriba "help" para obtener ayuda.
testdb=>

En el prompt, el usuario puede escribir comandos SQL. Normalmente, las líneas de entrada se envían al servidor cuando se alcanza un punto y coma que termina el comando. El final de una línea no termina un comando. Por lo tanto, los comandos se pueden extender a lo largo de varias líneas para mayor claridad. Si el comando se envió y se ejecutó sin errores, los resultados del comando se muestran en la pantalla.

Si los usuarios no confiables tienen acceso a una base de datos que no ha adoptado un patrón de uso seguro de esquemas, comience su sesión eliminando los esquemas escribibles públicamente de search_path. Puede agregar options=-csearch_path= a la cadena de conexión o ejecutar SELECT pg_catalog.set_config('search_path', '', false) antes de otros comandos SQL. Esta consideración no es específica de psql; se aplica a todas las interfaces para ejecutar comandos SQL arbitrarios.

Cada vez que se ejecuta un comando, psql también consulta eventos de notificación asíncrona generados por LISTEN y NOTIFY.

Mientras que los comentarios de bloque estilo C se pasan al servidor para su procesamiento y eliminación, los comentarios estándar SQL son eliminados por psql.

Meta-Comandos

Cualquier cosa que introduzca en psql que comience con una barra invertida sin comillas es un metacomando de psql que es procesado por el propio psql. Estos comandos hacen que psql sea más útil para la administración o la scripting. Los metacomandos a menudo se denominan comandos de barra o barra invertida.

El formato de un comando psql es la barra invertida, seguida inmediatamente por un verbo de comando, y luego los argumentos. Los argumentos se separan del verbo del comando y entre sí por cualquier cantidad de caracteres de espacio en blanco.

Para incluir espacios en blanco en un argumento, puede entrecomillarlo con comillas simples. Para incluir una comilla simple en un argumento, escriba dos comillas simples dentro de texto entre comillas simples. Cualquier cosa contenida entre comillas simples está sujeta además a sustituciones similares a C para \n (nueva línea), \t (tab), \b (retroceso), \r (retorno de carro), \f (salto de página), \dígitos (octal) y \xdígitos (hexadecimal). Una barra invertida que precede a cualquier otro carácter dentro de texto entre comillas simples entrecomilla ese carácter, sea cual sea.

Si un dos puntos sin comillas (:) seguido de un nombre de variable de psql aparece dentro de un argumento, se reemplaza por el valor de la variable

ue, como se describe en la interpolación SQL más adelante. Las formas :'nombre_variable' y :"nombre_variable" descritas allí también funcionan. La sintaxis :{?nombre_variable} permite comprobar si una variable está definida. Se sustituye por TRUE o FALSE. Escapar el dos puntos con una barra invertida lo protege de la sustitución.

Dentro de un argumento, el texto encerrado entre comillas invertidas (` `) se considera un comando de línea que se pasa al shell. La salida del comando (con cualquier salto de línea final eliminado) reemplaza el texto entre comillas invertidas. Dentro del texto encerrado entre comillas invertidas, no se produce ningún procesamiento especial de comillas u otro, excepto que las apariciones de :nombre_variable, donde nombre_variable es un nombre de variable de psql, se reemplazan por el valor de la variable. Además, las apariciones de :'nombre_variable' se reemplazan por el valor de la variable debidamente entrecomillado para que sea un único argumento de comando del shell. (Esta última forma es casi siempre preferible, a menos que esté muy seguro de lo que hay en la variable). Dado que los caracteres de retorno de carro y salto de línea no se pueden entrecomillar de forma segura en todas las plataformas, la forma :'nombre_variable' muestra un mensaje de error y no sustituye el valor de la variable cuando aparecen dichos caracteres en el valor.

Algunos comandos toman un identificador SQL (como un nombre de tabla) como argumento. Estos argumentos siguen las reglas de sintaxis de SQL: las letras sin comillas se fuerzan a minúsculas, mientras que las comillas dobles (") protegen las letras de la conversión de mayúsculas y minúsculas y permiten la incorporación de espacios en blanco en el identificador. Dentro de las comillas dobles, las comillas dobles emparejadas se reducen a una sola comilla doble en el nombre resultante. Por ejemplo, FOO"BAR"BAZ se interpreta como fooBARbaz, y "A weird"" name" se convierte en A weird" name.

El análisis de argumentos se detiene al final de la línea o cuando se encuentra otra barra invertida sin comillas. Una barra invertida sin comillas se toma como el comienzo de un nuevo metacomando. La secuencia especial \\ (dos barras invertidas) marca el final de los argumentos y continúa el análisis de los comandos SQL, si los hay. De esta manera, los comandos SQL y psql pueden mezclarse libremente en una línea. Pero en cualquier caso, los argumentos de un metacomando no pueden continuar más allá del final de la línea.

Muchos de los metacomandos actúan sobre el búfer de consulta actual. Este es simplemente un búfer que contiene el texto del comando SQL que se ha escrito pero que aún no se ha enviado al servidor para su ejecución. Esto incluirá las líneas de entrada anteriores, así como cualquier texto que aparezca antes del metacomando en la misma línea.

Muchos de los metacomandos también permiten añadir x como opción. Esto hará que los resultados se muestren en modo expandido, como si se hubiera usado \x o \pset expanded.

Los siguientes metacomandos están definidos:

\a

Si el formato de salida de tabla actual no está alineado, se cambia a alineado. Si no está alineado, se establece como no alineado. Este comando se mantiene por compatibilidad con versiones anteriores. Consulte \pset para una solución más general.

\bind [ parámetro ] ...

Establece los parámetros de la consulta para la próxima ejecución de la consulta, con los parámetros especificados pasados para cualquier marcador de posición de parámetro ($1, etc.).

Ejemplo:

INSERT INTO tbl1 VALUES ($1, $2) \bind 'primer valor' 'segundo valor' \g

Esto también funciona para comandos de ejecución de consultas además de \g, como \gx y \gset.

Este comando provoca el uso del protocolo de consulta extendido (consulte la Sección 54.1.2), a diferencia de la operación normal de psql, que utiliza el protocolo de consulta simple. Por lo tanto, este comando puede ser útil para probar el protocolo de consulta extendido desde psql. (El protocolo de consulta extendido se utiliza incluso si la consulta no tiene parámetros y este comando especifica cero parámetros). Este comando solo afecta a la próxima consulta ejecutada; todas las consultas posteriores utilizarán el protocolo de consulta simple por defecto.

\bind_named nombre_declaración [ parámetro ] ...

\bind_named es equivalente a \bind, excepto que toma el nombre de una declaración preparada existente como primer parámetro. Una cadena vacía denota la declaración preparada sin nombre.

Ejemplo:

INSERT INTO tbls1 VALUES ($1, $2) \parse stmt1
\bind_named stmt1 'primer valor' 'segundo valor' \g

Este comando provoca el uso del protocolo de consulta extendido (consulte la Sección 54.1.2), a diferencia de la operación normal de psql, que utiliza el protocolo de consulta simple. Por lo tanto, este comando puede ser útil para probar el protocolo de consulta extendido desde psql.

\c o \connect [ -reuse-previous=on|off ] [ dbname [ username ] [ host ] [ port ] | conninfo ]

Establece una nueva conexión a un servidor PostgreSQL. Los parámetros de conexión a utilizar se pueden especificar mediante una sintaxis posicional (uno o más de nombre de base de datos, usuario, host y puerto), o utilizando una cadena de conexión conninfo como se detalla en la Sección 32.1.1. Si no se proporcionan argumentos, se establece una nueva conexión utilizando los mismos parámetros que antes.

Especificar cualquiera de dbname, username, host o port como - es equivalente a omitir ese parámetro.

La nueva conexión puede reutilizar los parámetros de conexión de la conexión anterior; no solo el nombre de la base de datos, usuario, host y puerto, sino también otras configuraciones como sslmode. Por defecto, los parámetros se reutilizan en la sintaxis posicional, pero no cuando se proporciona una cadena conninfo. Pasar un primer argumento de -reuse-previous=on o -reuse-previous=off anula ese valor predeterminado. Si se reutilizan los parámetros, cualquier parámetro que no se especifique explícitamente como parámetro posicional o en la cadena conninfo se toma de los parámetros de la conexión existente. Una excepción es que si la configuración host se cambia de su valor anterior utilizando la sintaxis posicional, cualquier configuración hostaddr presente en los parámetros de la conexión existente se descarta. Además, cualquier contraseña utilizada para la conexión existente solo se reutilizará si no se cambian los ajustes de usuario, host y puerto. Cuando el comando no especifica ni reutiliza un parámetro particular, se utiliza el valor predeterminado de libpq.

Si la nueva conexión se establece correctamente, se cierra la conexión anterior. Si el intento de conexión falla (nombre de usuario incorrecto, acceso denegado, etc.), se mantendrá la conexión anterior si psql está en modo interactivo. Pero al ejecutar un script no interactivo, se cierra la conexión antigua y se informa de un error. Esto puede o no terminar el script; si no lo hace, todos los comandos de acceso a la base de datos fallarán hasta que se ejecute otro comando \connect con éxito. Esta distinción se eligió como una conveniencia para el usuario frente a errores tipográficos por un lado, y un mecanismo de seguridad para que los scripts no actúen accidentalmente sobre la base de datos incorrecta por otro. Tenga en cuenta que cada vez que un comando \connect intenta reutilizar parámetros, los valores reutilizados son los de la última conexión exitosa, no los de ningún intento fallido realizado posteriormente. Sin embargo, en caso de fallo de \connect no interactivo, no se permite reutilizar ningún parámetro más tarde, ya que el script probablemente esperaría que se reutilizaran los valores de la \connect fallida.

Ejemplos:

=> \c mydb myuser host.dom 6432
=> \c service=foo
=> \c "host=localhost port=5432 dbname=mydb connect_timeout=10 sslmode=disable"
=> \c -reuse-previous=on sslmode=require    -- solo cambia sslmode
=> \c postgresql://tom@localhost/mydb?application_name=myapp

\copy { tabla [ ( lista_columnas ) ] } from { 'nombre_archivo' | program 'comando' | stdin | pstdin } [ [ with ] ( opción [, ...] ) ] [ where condición ]
\copy { tabla [ ( lista_columnas ) ] | ( consulta ) } to { 'nombre_archivo' | program 'comando' | stdout | pstdout } [ [ with ] ( opción [, ...] ) ]

Realiza una copia del lado del cliente (frontend). Esta es una operación que ejecuta un comando SQL COPY, pero en lugar de que el servidor lea o escriba el archivo especificado, psql lee o escribe el archivo y enruta los datos entre el servidor y el sistema de archivos local. Esto significa que la accesibilidad y los privilegios de archivo son los del usuario local, no los del servidor, y no se requieren privilegios de superusuario SQL.

Cuando se especifica program, comando es ejecutado por psql y los datos pasados desde o hacia comando se enrutan entre el servidor y el cliente. Nuevamente, los privilegios de ejecución son los del usuario local, no los del servidor, y no se requieren privilegios de superusuario SQL.

Para \copy ... from stdin, las filas de datos se leen de la misma fuente que emitió el comando, continuando hasta que se lee una línea que solo contiene \. o el flujo llega a EOF. Esta opción es útil para poblar tablas en línea dentro de un archivo de script SQL. Para \copy ... to stdout, la salida se envía al mismo lugar que la salida del comando psql, y el estado del comando COPY count no se imprime (ya que podría confundirse con una fila de datos). Para leer/escribir la entrada/salida estándar de psql independientemente de la fuente del comando actual o la opción \o, escriba desde pstdin o a pstdout.

La sintaxis de este comando es similar a la del comando SQL COPY. Todas las opciones distintas de la fuente/destino de datos son como se especifican para COPY. Debido a esto, se aplican reglas de análisis especiales al metacomando \copy. A diferencia de la mayoría de los otros metacomandos, the el resto de la línea se toma siempre como los argumentos de \copy, y no se realizan ni interpolación de variables ni expansión de comillas invertidas en los argumentos.


Consejo
Otra forma de obtener el mismo resultado que \copy ... to es usar el comando SQL COPY ... TO STDOUT y terminarlo con \g nombre_archivo o \g |programa. A diferencia de \copy, este método permite que el comando abarque varias líneas; además, se pueden usar la interpolación de variables y la expansión de comillas invertidas.

Consejo
Estas operaciones no son tan eficientes como el comando SQL COPY con una fuente o destino de datos de archivo o programa, porque todos los datos deben pasar a través de la conexión cliente/servidor. Para grandes cantidades de datos, el comando SQL podría ser preferible.

\crosstabview [ colV [ colH [ colD [ sortcolH ] ] ] ]

Ejecuta el búfer de consulta actual (como \g) y muestra los resultados en una cuadrícula de tabla cruzada. La consulta debe devolver al menos tres columnas. La columna de salida identificada por colV se convierte en un encabezado vertical y la columna de salida identificada por colH se convierte en un encabezado horizontal. colD identifica la columna de salida que se mostrará dentro de la cuadrícula. sortcolH identifica una columna de ordenación opcional para el encabezado horizontal.

Cada especificación de columna puede ser un número de columna (comenzando en 1) o un nombre de columna. Se aplican las reglas habituales de plegado de mayúsculas/minúsculas y de comillas de SQL a los nombres de columna. Si se omite, colV se toma como la columna 1 y colH como la columna 2. colH debe ser diferente de colV. Si no se especifica colD, entonces debe haber exactamente tres columnas en el resultado de la consulta, y la columna que no es ni colV ni colH se toma como colD.

El encabezado vertical, que se muestra como la columna más a la izquierda, contiene los valores encontrados en la columna colV, en el mismo orden que en los resultados de la consulta, pero con duplicados eliminados.

El encabezado horizontal, que se muestra como la primera fila, contiene los valores encontrados en la columna colH, con duplicados eliminados. Por defecto, estos aparecen en el mismo orden que en los resultados de la consulta. Pero si se proporciona el argumento opcional sortcolH, identifica una columna cuyos valores deben ser números enteros, y los valores de colH aparecerán en el encabezado horizontal ordenados según los valores correspondientes de sortcolH.

Dentro de la cuadrícula de tabla cruzada, para cada valor distinto x de colH y cada valor distinto y de colV, la celda ubicada en la intersección (x,y) contiene el valor de la columna colD en la fila del resultado de la consulta para la cual el valor de colH es x y el valor de colV es y. Si no existe tal fila, la celda está vacía. Si existen múltiples filas, se informa un error.

Si se especifica nombre-archivo, se edita el archivo; después de que el editor sale, el contenido del archivo se copia al búfer de consulta actual. O, si el búfer de consulta actual está vacío, la consulta ejecutada más recientemente se copia a un archivo temporal y se edita de la misma manera.

(Por lo tanto, no puede crear scripts que utilicen metacomandos de esta manera. Use \i para eso).

\gset [ prefijo ]

Envía el búfer de consulta actual al servidor y almacena la salida de la consulta en variables de psql (ver Variables abajo). La consulta a ejecutar debe devolver exactamente una fila. Cada columna de la fila se almacena en una variable separada, con el mismo nombre que la columna. Por ejemplo: 
=> SELECT 'hello' AS var1, 10 AS var2
-> \gset
=> \echo :var1 :var2
hello 10

Si especifica un prefijo, esta cadena se antepone a los nombres de las columnas de la consulta para crear los nombres de variables a utilizar:

=> SELECT 'hello' AS var1, 10 AS var2
-> \gset result_
=> \echo :result_var1 :result_var2
hello 10

Si el resultado de una columna es NULL, la variable correspondiente se anula en lugar de establecerse.

Si la consulta falla o no devuelve una fila, no se modifican las variables.

Si el búfer de consulta actual está vacío, se vuelve a ejecutar la consulta enviada más recientemente.

\if expresión
\elif expresión
\else
\endif

Este grupo de comandos implementa bloques condicionales anidables. Un bloque condicional debe comenzar con un \if y terminar con un \endif. Entre ellos puede haber cualquier número de cláusulas \elif, que opcionalmente pueden ir seguidas de una única cláusula \else. Las consultas ordinarias y otros tipos de comandos de barra invertida pueden (y usualmente lo hacen) aparecer entre los comandos que forman un bloque condicional.

Los comandos \if y \elif leen su(s) argumento(s) y los evalúan como una expresión booleana. Si la expresión resulta verdadera, el procesamiento continúa normalmente; de lo contrario, las líneas se saltan hasta que se encuentra un \elif, \else o \endif coincidente. Una vez que una prueba \if o \elif ha tenido éxito, los argumentos de los comandos \elif posteriores en el mismo bloque no se evalúan pero se tratan como falsos. Las líneas posteriores a un \else se procesan solo si ninguna \if o \elif coincidente anterior tuvo éxito.

El argumento expresión de un comando \if o \elif está sujeto a interpolación de variables y expansión de comillas invertidas, al igual que cualquier otro argumento de comando de barra invertida. Después de eso, se evalúa como el valor de una variable de opción de encendido/apagado. Por lo tanto, un valor válido es cualquier coincidencia insesible a mayúsculas y minúsculas no ambigua de uno de: true, false, 1, 0, on, off, yes, no. Por ejemplo, t, T y tR se considerarán verdaderos.

Las expresiones que no se evalúan correctamente como verdaderas o falsas generarán una advertencia y se tratarán como falsas.

Las líneas que se están omitiendo se analizan normalmente para identificar consultas y comandos de barra invertida, pero las consultas no se envían al servidor, y los comandos de barra invertida que no sean condicionales (\if, \elif, \else, \endif) se ignoran. Los comandos condicionales solo se verifican para ver si la anidación es válida. Las referencias a variables en líneas omitidas no se expanden, y la expansión de comillas invertidas tampoco se realiza.

Todos los comandos de barra invertida de un bloque condicional dado deben aparecer en el mismo archivo fuente. Si se llega al final del archivo de entrada principal o a un archivo \include-ado antes de que se cierren todos los bloques \if locales, psql generará un error.

Aquí hay un ejemplo:

-- verificar la existencia de dos registros separados en la base de datos y almacenar
-- los resultados en variables psql separadas
SELECT
    EXISTS(SELECT 1 FROM customer WHERE customer_id = 123) as is_customer,
    EXISTS(SELECT 1 FROM employee WHERE employee_id = 456) as is_employee
\gset
\if :is_customer
    SELECT * FROM customer WHERE customer_id = 123;
\elif :is_employee
    \echo 'is not a customer but is an employee'
    SELECT * FROM employee WHERE employee_id = 456;
\else
    \if yes
        \echo 'not a customer or employee'
    \else
        \echo 'this will never print'
    \endif
\endif

Organiza el guardado de los futuros resultados de la consulta en el archivo nombre_de_archivo o canaliza los futuros resultados al comando de shell comando. Si no se especifica ningún argumento, la salida de la consulta se restablece a la salida estándar.

Si el argumento comienza con |, entonces el resto de la línea se toma como el comando a ejecutar, y ni la interpolación de variables ni la expansión de comillas invertidas se realizan en él. El resto de la línea se pasa literalmente al shell.

“Resultados de la consulta” incluye todas las tablas, respuestas de comandos y avisos obtenidos del servidor de base de datos, así como la salida de varios comandos de barra invertida que consultan la base de datos (como \d); pero no los mensajes de error.


Consejo
Para intercalar texto de salida entre los resultados de la consulta, use \qecho.

\p o \print

Imprime el búfer de consulta actual en la salida estándar. Si el búfer de consulta actual está vacío, se imprime la consulta ejecutada más recientemente en su lugar.

\parse nombre_de_sentencia

Crea una sentencia preparada a partir del búfer de consulta actual, basándose en el nombre de un objeto de sentencia preparada de destino. Una cadena vacía denota la sentencia preparada sin nombre.

Ejemplo:

SELECT $1 \parse stmt1

Este comando provoca el uso del protocolo de consulta extendida, a diferencia de la operación normal de psql, que utiliza el protocolo de consulta simple. Se emitirá un mensaje Parse (F) con este comando, por lo que puede ser útil para probar el protocolo de consulta extendida desde psql. Este comando solo afecta a la siguiente consulta ejecutada; todas las consultas posteriores utilizarán el protocolo de consulta simple por defecto.

\password [ nombre_de_usuario ]

Cambia la contraseña del usuario especificado (por defecto, el usuario actual). Este comando solicita la nueva contraseña, la cifra y la envía al servidor como un comando ALTER ROLE. Esto asegura que la nueva contraseña no aparezca en texto plano en el historial de comandos, el registro del servidor o en cualquier otro lugar.

\prompt [ texto ] nombre

Solicita al usuario que proporcione texto, que se asigna a la variable nombre. Se puede especificar una cadena de solicitud opcional, texto. (Para solicitudes de varias palabras, rodee el texto con comillas simples.)

Por defecto, \prompt utiliza la terminal para entrada y salida. Sin embargo, si se utilizó el modificador de línea de comandos -f, \prompt utiliza la entrada estándar y la salida estándar.

\pset [ opción [ valor ] ]

Este comando establece opciones que afectan la salida de las tablas de resultados de consultas. opción indica qué opción se va a establecer. La semántica de valor varía según la opción seleccionada. Para algunas opciones, omitir valor hace que la opción se active o desactive, como se describe en la opción particular. Si no se menciona dicho comportamiento, omitir valor simplemente muestra la configuración actual.

\pset sin ningún argumento muestra el estado actual de todas las opciones de impresión.

Las opciones de impresión ajustables son:

border

El valor debe ser un número. En general, cuanto mayor sea el número, más bordes y líneas tendrán las tablas, pero los detalles dependen del formato particular. En formato HTML, esto se traducirá directamente en el atributo border=... En la mayoría de los otros formatos, solo los valores 0 (sin borde), 1 (líneas divisorias internas) y 2 (marco de tabla) tienen sentido, y los valores superiores a 2 se tratarán igual que border = 2. Los formatos latex y latex-longtable además permiten un valor de 3 para agregar líneas divisorias entre filas de datos.

columns

Establece el ancho objetivo para el formato de ajuste, y también el límite de ancho para determinar si la salida es lo suficientemente ancha como para requerir el paginador o cambiar a la visualización vertical en modo automático expandido. Cero (el valor predeterminado) hace que el ancho objetivo sea controlado por la variable de entorno COLUMNS, o por el ancho de pantalla detectado si COLUMNS no está establecido. Además, si columns es cero, el formato de ajuste solo afecta la salida de pantalla. Si columns no es cero, la salida de archivos y canalizaciones también se ajusta a ese ancho.

csv_fieldsep

Especifica el separador de campos que se utilizará en el formato de salida CSV. Si el carácter separador aparece en el valor de un campo, ese campo se genera entre comillas dobles, siguiendo las reglas estándar de CSV. El valor predeterminado es una coma.

expanded (o x)

Si se especifica valor, debe ser encendido o apagado, lo que habilitará o deshabilitará el modo expandido, o auto. Si se omite valor, el comando alterna entre los ajustes encendido y apagado. Cuando el modo expandido está habilitado, los resultados de la consulta se muestran en dos columnas, con el nombre de la columna a la izquierda y los datos a la derecha. Este modo es útil si los datos no cabrían en la pantalla en el modo "horizontal" normal. En el ajuste auto, el modo expandido se utiliza siempre que la salida de la consulta tenga más de una columna y sea más ancha que la pantalla; de lo contrario, se utiliza el modo normal. El ajuste auto solo es efectivo en los formatos alineado y envuelto. En otros formatos, siempre se comporta como si el modo expandido estuviera desactivado.

fieldsep

Especifica el separador de campos que se utilizará en el formato de salida no alineado. De esta manera se puede crear, por ejemplo, una salida separada por tabulaciones, que otros programas podrían preferir. Para establecer una tabulación como separador de campos, escriba \pset fieldsep '\t'. El separador de campos predeterminado es '|' (una barra vertical).

fieldsep_zero

Establece el separador de campos a utilizar en el formato de salida no alineado en un byte cero.

footer

Si se especifica valor, debe ser encendido o apagado, lo que habilitará o deshabilitará la visualización del pie de página de la tabla (el recuento (n filas)). Si se omite valor, el comando alterna la visualización del pie de página encendido o apagado.

format

Establece el formato de salida en uno de los siguientes: alineado, asciidoc, csv, html, latex, latex-longtable, troff-ms, no alineado o envuelto. Se permiten abreviaturas únicas.

El formato alineado es la salida de texto estándar, legible por humanos y formateada de manera agradable; este es el valor predeterminado.

El formato no alineado escribe todas las columnas de una fila en una sola línea, separadas por el separador de campos actualmente activo. Esto es útil para crear salidas que puedan ser leídas por otros programas, por ejemplo, formato separado por tabulaciones o por comas. Sin embargo, el carácter separador de campos no se trata de forma especial si aparece en el valor de una columna; por lo tanto, el formato CSV puede ser más adecuado para tales fines.

Formato csv

escribe los valores de las columnas separados por comas, aplicando las reglas de comillas descritas en RFC 4180. Esta salida es compatible con el formato CSV del comando COPY del servidor. Se genera una línea de encabezado con los nombres de las columnas, a menos que el parámetro tuples_only esté activado. No se imprimen títulos ni pies de página. Cada fila se termina con el carácter de fin de línea dependiente del sistema, que suele ser una sola nueva línea (\n) para sistemas tipo Unix o una secuencia de retorno de carro y nueva línea (\r\n) para Microsoft Windows. Los separadores de campos distintos de la coma se pueden seleccionar con \pset csv_fieldsep.

El formato envuelto es como el alineado pero ajusta los valores de datos anchos en varias líneas para que la salida quepa en el ancho de columna objetivo. El ancho objetivo se determina como se describe en la opción columns. Tenga en cuenta que psql no intentará ajustar los títulos de los encabezados de columna; por lo tanto, el formato envuelto se comporta igual que el alineado si el ancho total necesario para los encabezados de columna excede el objetivo.

Los formatos asciidoc, html, latex, latex-longtable y troff-ms generan tablas que están destinadas a ser incluidas en documentos utilizando el lenguaje de marcado respectivo. ¡No son documentos completos! Esto podría no ser necesario en HTML, pero en LaTeX debe tener un envoltorio de documento completo. El formato latex utiliza el entorno tabular de LaTeX. El formato latex-longtable requiere los paquetes de LaTeX longtable y booktabs.

linestyle

Establece el estilo de dibujo de líneas de borde en ascii, old-ascii o unicode. Se permiten abreviaturas únicas. (Eso significa que una letra es suficiente). La configuración predeterminada es ascii. Esta opción solo afecta los formatos de salida alineado y envuelto.

El estilo ascii utiliza caracteres ASCII simples. Las nuevas líneas en los datos se muestran utilizando un símbolo + en el margen derecho. Cuando el formato envuelto ajusta los datos de una línea a la siguiente sin un carácter de nueva línea, se muestra un punto (.) en el margen derecho de la primera línea y nuevamente en el margen izquierdo de la siguiente línea.

El estilo old-ascii utiliza caracteres ASCII simples, utilizando el estilo de formato utilizado en PostgreSQL 8.4 y versiones anteriores. Las nuevas líneas en los datos se muestran utilizando un símbolo: en lugar del separador de columna de la izquierda. Cuando los datos se ajustan de una línea a la siguiente sin un carácter de nueva línea, se utiliza un símbolo; en lugar del separador de columna de la izquierda.

El estilo unicode utiliza caracteres de dibujo de cajas Unicode. Las nuevas líneas en los datos se muestran utilizando un símbolo de retorno de carro en el margen derecho. Cuando los datos se ajustan de una línea a la siguiente sin un carácter de nueva línea, se muestra un símbolo de elipsis en el margen derecho de la primera línea y nuevamente en el margen izquierdo de la siguiente línea.

Cuando la configuración del borde es mayor que cero, la opción linestyle también determina los caracteres con los que se dibujan las líneas de borde. Los caracteres ASCII simples funcionan en todas partes, pero los caracteres Unicode se ven mejor en pantallas que los reconocen.

null

Establece la cadena que se imprimirá en lugar de un valor nulo. El valor predeterminado es no imprimir nada, lo que puede confundirse fácilmente con una cadena vacía. Por ejemplo, uno podría preferir \pset null '(null)'.

numericlocale

Si se especifica valor, debe ser encendido o apagado, lo que habilitará o deshabilitará la visualización de un carácter específico de la configuración regional para separar grupos de dígitos a la izquierda del marcador decimal. Si se omite valor, el comando alterna entre la salida numérica normal y la específica de la configuración regional.

pager

Controla el uso de un programa paginador para la salida de consultas y ayuda de psql. Cuando la opción pager está desactivada, el programa paginador no se utiliza. Cuando la opción pager está activada, el paginador se utiliza cuando es apropiado, es decir, cuando la salida es a una terminal y no cabe en la pantalla. La opción pager también se puede establecer en always, lo que hace que el paginador se utilice para toda la salida de terminal, independientemente de si cabe en la pantalla. \pset pager sin un valor alterna el uso del paginador encendido y apagado.

Si la variable de entorno PSQL_PAGER o PAGER está establecida, la salida que se va a paginar se canaliza al programa especificado. De lo contrario, se utiliza un programa predeterminado dependiente de la plataforma (como more).

psql micro-command reference

This chapter describes the meta-commands available in psql. Meta-commands are commands executed by psql itself, not sent to PostgreSQL for execution. Meta-commands start with a backslash (\).

Some meta-commands are used to set or unset variables that control psql's behavior. These variables are documented in Section 32.2.

There are a few meta-commands that are used to manage pipelined queries, which are described in Section 32.5.

You can type a meta-command name and press Tab to auto-complete the name. Some meta-commands accept arguments. If an argument contains spaces, it must be quoted. The arguments are C-processed if they are enclosed in double quotes or are a single word. Variable interpolation and backquote expansion are performed on arguments unless otherwise noted.

Most meta-commands return a boolean result or nothing at all. If a meta-command returns a string, it is quoted appropriately. Some meta-commands may print output to standard error rather than standard output.

Most meta-commands may be terminated by a semicolon. This is optional, but recommended for consistency.

\startpipeline
\sendpipeline
\syncpipeline
\endpipeline
\flushrequest
\flush
\getresults [ number_results ]

This group of commands implements pipelining of SQL statements. A pipeline must begin with a \startpipeline and end with an \endpipeline. In between there may be any number of \syncpipeline commands, which sends a sync message without ending the ongoing pipeline and flushing the send buffer. In pipeline mode, statements are sent to the server without waiting for the results of previous statements. See Section 32.5 for more details.

All queries executed while a pipeline is ongoing use the extended query protocol. Queries are appended to the pipeline when ending with a semicolon. The meta-commands \bind, \bind_named, \close_prepared or \parse can be used in an ongoing pipeline. While a pipeline is ongoing, \sendpipeline will append the current query buffer to the pipeline. Other meta-commands like \g, \gx or \gdesc are not allowed in pipeline mode.

\flushrequest appends a flush command to the pipeline, allowing to read results with \getresults without issuing a sync or ending the pipeline. \flush can be used to manually push unsent data.

\getresults accepts an optional number_results parameter. If provided, only the first number_results pending results will be read. If not provided or 0, all pending results are read.

When pipeline mode is active, a dedicated prompt variable is available to report the pipeline status. See %P for more details

COPY is not supported while in pipeline mode.

Example:

\startpipeline
        SELECT * FROM pg_class;
        SELECT 1 \bind \sendpipeline
        \flushrequest
        \getresults
        \endpipeline

Espera el número especificado de segundos (predeterminado 2) entre ejecuciones. El tiempo de espera predeterminado se puede cambiar con la variable WATCH_INTERVAL. Para compatibilidad con versiones anteriores, los segundos se pueden especificar con o sin un prefijo interval=. Cada resultado de consulta se muestra con una cabecera que incluye la cadena de título \pset (si existe), la hora desde el inicio de la consulta y el intervalo de retraso.

Si el buffer de consulta actual está vacío, se vuelve a ejecutar la consulta enviada más recientemente.

\x [ encendido | apagado | auto ]

Establece o alterna el modo de formato de tabla expandido. Como tal, es equivalente a \pset expanded.

\z[Sx] [ patrón ]

Enumera tablas, vistas y secuencias con sus privilegios de acceso asociados. Si se especifica un patrón, solo se enumeran las tablas, vistas y secuencias cuyos nombres coinciden con el patrón. Por defecto, solo se muestran los objetos creados por el usuario; proporcione un patrón o el modificador S para incluir objetos del sistema. Si se añade x al nombre del comando, los resultados se muestran en modo expandido.

Este es un alias para \dp (“mostrar privilegios”).

\! [ comando ]

Sin argumentos, se sale a un subshell; psql se reanuda cuando el subshell termina. Con un argumento, ejecuta el comando del shell comando.

A diferencia de la mayoría de los otros meta-comandos, el resto de la línea se toma siempre como los argumentos de \!, y ni la interpolación de variables ni la expansión de comillas invertidas se realizan en los argumentos. El resto de la línea se pasa literalmente al shell.

\? [ tema ]

Muestra información de ayuda. El tema opcional (predeterminado en comandos) selecciona qué parte de psql se explica: comandos describe los comandos de barra invertida de psql; opciones describe las opciones de línea de comandos que se pueden pasar a psql; y variables muestra ayuda sobre las variables de configuración de psql.

\;

La barra invertida seguida de punto y coma no es un meta-comando de la misma manera que los comandos anteriores; en cambio, simplemente hace que se agregue un punto y coma al buffer de consulta sin ningún otro procesamiento.

Normalmente, psql enviará un comando SQL al servidor tan pronto como llegue al punto y coma que finaliza el comando, incluso si queda más entrada en la línea actual. Por lo tanto, por ejemplo, al ingresar

select 1; select 2; select 3;

resultará en que los tres comandos SQL se envíen individualmente al servidor, y los resultados de cada uno se muestren antes de continuar con el siguiente comando. Sin embargo, un punto y coma ingresado como \; no activará el procesamiento del comando, de modo que el comando anterior y el siguiente se combinen efectivamente y se envíen al servidor en una sola solicitud. Así, por ejemplo,

select 1\; select 2\; select 3;

resulta en el envío de los tres comandos SQL al servidor en una sola solicitud, cuando se alcanza el punto y coma no invertido. El servidor ejecuta dicha solicitud como una transacción única, a menos que haya comandos BEGIN/COMMIT explícitos incluidos en la cadena para dividirlos en múltiples transacciones. (Consulte la Sección 54.2.2.1 para obtener más detalles sobre cómo el servidor maneja las cadenas de múltiples consultas).

Patrones

Los diversos comandos \d aceptan un parámetro de patrón para especificar el nombre (o nombres) del objeto a mostrar. En el caso más simple, un patrón es simplemente el nombre exacto del objeto. Los caracteres dentro de un patrón normalmente se convierten a minúsculas, al igual que en los nombres SQL; por ejemplo, \dt FOO mostrará la tabla llamada foo. Al igual que en los nombres SQL, poner comillas dobles alrededor de un patrón detiene la conversión a minúsculas. Si necesita incluir un carácter de comillas dobles real en un patrón, escríbalo como un par de comillas dobles dentro de una secuencia de comillas dobles; de nuevo, esto está de acuerdo con las reglas para identificadores SQL entre comillas. Por ejemplo, \dt "FOO""BAR" mostrará la tabla llamada FOO"BAR (no foo"bar). A diferencia de las reglas normales para nombres SQL, puede poner comillas dobles solo en una parte de un patrón, por ejemplo \dt FOO"FOO"BAR mostrará la tabla llamada fooFOObar.

Cuando el parámetro patrón se omite por completo, los comandos \d muestran todos los objetos que son visibles en la ruta de búsqueda de esquemas actual, lo que equivale a usar * como patrón. (Se dice que un objeto es visible si su esquema contenedor está en la ruta de búsqueda y ningún objeto del mismo tipo y nombre aparece antes en la ruta de búsqueda. Esto es equivalente a la afirmación de que el objeto se puede referenciar por nombre sin calificación de esquema explícita.) Para ver todos los objetos en la base de datos independientemente de la visibilidad, use *.* como patrón.

Dentro de un patrón, * coincide con cualquier secuencia de caracteres (incluyendo ninguno) y ? coincide con cualquier carácter único. (Esta notación es comparable a los patrones de nombres de archivo del shell de Unix.) Por ejemplo, \dt int* muestra tablas cuyos nombres comienzan con int. Pero dentro de comillas dobles, * y ? pierden estos significados especiales y solo se coinciden literalmente.

Un patrón de relación que contiene un punto (.) se interpreta como un patrón de nombre de esquema seguido de un patrón de nombre de objeto. Por ejemplo, \dt foo*.*bar* muestra todas las tablas cuyo nombre de tabla incluye bar y que están en esquemas cuyo nombre de esquema comienza con foo. Cuando no hay ningún punto, el patrón coincide solo con objetos que son visibles en la ruta de búsqueda de esquemas actual. Nuevamente, un punto dentro de comillas dobles pierde su significado especial y se coincide literalmente. Un patrón de relación que contiene dos puntos (.) se interpreta como un nombre de base de datos seguido de un patrón de nombre de esquema seguido de un patrón de nombre de objeto. La parte del nombre de la base de datos no se tratará como un patrón y debe coincidir con el nombre de la base de datos conectada actualmente, de lo contrario, se producirá un error.

Un patrón de esquema que contiene un punto (.) se interpreta como un nombre de base de datos seguido de un patrón de nombre de esquema. Por ejemplo, \dn mydb.*foo* muestra todos los esquemas cuyo nombre de esquema incluye foo. La parte del nombre de la base de datos no se tratará como un patrón y debe coincidir con el nombre de la base de datos conectada actualmente, de lo contrario, se producirá un error.

Los usuarios avanzados pueden usar notaciones de expresiones regulares como clases de caracteres, por ejemplo [0-9] para que coincida con cualquier dígito. Todos los caracteres especiales de expresiones regulares funcionan como se especifica en la Sección 9.7.3, excepto . que se toma como un separador como se mencionó anteriormente, * que se traduce a la notación de expresiones regulares .*, ? que se traduce a ., y $ que se coincide literalmente. Puede emular estos caracteres de patrón según sea necesario escribiendo ? para ., (R+|) para R*, o (R|) para R?. No se necesita $ como carácter de expresión regular ya que el patrón debe coincidir con todo el nombre, a diferencia de la interpretación habitual de las expresiones regulares (es decir, $ se agrega automáticamente a su patrón). Escriba * al principio y/o al final si no desea que el patrón esté anclado. Tenga en cuenta que dentro de las comillas dobles, todos los caracteres especiales de expresiones regulares pierden sus significados especiales y se coinciden literalmente. Además, los caracteres especiales de expresiones regulares se coinciden literalmente en los patrones de nombres de operadores (es decir, el argumento de \do).

Características Avanzadas

Variables

psql proporciona características de sustitución de variables similares a los shells de comandos comunes de Unix. Las variables son simplemente pares de nombre/valor, donde el valor puede ser cualquier cadena de cualquier longitud. El nombre debe consistir en letras (incluidas letras no latinas), dígitos y guiones bajos.

Para establecer una variable, use el meta-comando psql \set. Por ejemplo,

testdb=> \set foo bar

establece la variable foo al valor bar. Para recuperar el contenido de la variable, anteponga dos puntos al nombre, por ejemplo:

testdb=> \echo :foo
bar

Esto funciona tanto en comandos SQL regulares como en meta-comandos; hay más detalles en Interpolación SQL, a continuación.

Si llama a \set sin un segundo argumento, la variable se establece en un valor de cadena vacía. Para eliminar (es decir, borrar) una variable, use el comando \unset. Para mostrar los valores de todas las variables, llame a \set sin ningún argumento.


Nota

Los argumentos de \set están sujetos a las mismas reglas de sustitución que con otros comandos. Por lo tanto, puede construir referencias interesantes como \set :foo 'algo' y obtener "enlaces blandos" o "variables de variables" de Perl o PHP, respectivamente. Desafortunadamente (o afortunadamente), no hay forma de hacer nada útil con estas construcciones. Por otro lado, \set bar :foo es una forma perfectamente válida de copiar una variable.

psql trata un número de estas variables de forma especial. Representan ciertas configuraciones de opciones que se pueden cambiar en tiempo de ejecución alterando el valor de la variable, o en algunos casos representan el estado cambiante de psql. Por convención, los nombres de todas las variables tratadas especialmente consisten en letras ASCII en mayúsculas (y posiblemente dígitos y guiones bajos). Para garantizar la máxima compatibilidad en el futuro, evite usar tales nombres de variables para sus propios fines.

Las variables que controlan el comportamiento de psql generalmente no se pueden eliminar ni establecer en valores inválidos. Se permite un comando \unset pero se interpreta como el establecimiento de la variable a su valor predeterminado. Un comando \set sin un segundo argumento se interpreta como el establecimiento de la variable en encendido, para las variables de control que aceptan ese valor, y se rechaza para otras. Además, las variables de control que aceptan los valores encendido y apagado también aceptarán otras grafías comunes de valores booleanos, como verdadero y falso.

Para posponer la confirmación en este modo, debe ingresar un comando SQL BEGIN o START TRANSACTION. Cuando está desactivado o eliminado, los comandos SQL no se confirman hasta que emita explícitamente COMMIT o END. El modo autocommit-off funciona emitiendo un BEGIN implícito para usted, justo antes de cualquier comando que no esté ya en un bloque de transacción y que no sea en sí mismo un comando BEGIN u otro comando de control de transacción, ni un comando que no se pueda ejecutar dentro de un bloque de transacción (como VACUUM).

Nota
En el modo autocommit-apagado, debe abandonar explícitamente cualquier transacción fallida ingresando ABORT o ROLLBACK. Tenga también en cuenta que
la sesión sin confirmar, su trabajo se perderá.

Interpolación SQL

Una característica clave de las variables de psql es que puede sustituirlas (“interpolarlas”) en sentencias SQL regulares, así como en los argumentos de los metacomandos. Además, psql proporciona mecanismos para asegurar que los valores de las variables utilizados como literales e identificadores SQL estén correctamente entrecomillados. La sintaxis para interpolar un valor sin ningún entrecomillado es anteponer el nombre de la variable con dos puntos (:). Por ejemplo,

testdb=> \set foo 'my_table'
testdb=> SELECT * FROM :foo;

consultaría la tabla my_table. Tenga en cuenta que esto puede ser inseguro: el valor de la variable se copia literalmente, por lo que puede contener comillas desequilibradas o incluso comandos de barra invertida. Debe asegurarse de que tenga sentido donde lo coloque.

Cuando un valor se va a utilizar como literal o identificador SQL, es más seguro asegurarse de que esté entrecomillado. Para entrecomillar el valor de una variable como un literal SQL, escriba dos puntos seguidos del nombre de la variable entre comillas simples. Para entrecomillar el valor como un identificador SQL, escriba dos puntos seguidos del nombre de la variable entre comillas dobles. Estas construcciones manejan correctamente las comillas y otros caracteres especiales incrustados dentro del valor de la variable. El ejemplo anterior se escribiría de forma más segura de esta manera:

testdb=> \set foo 'my_table'
testdb=> SELECT * FROM :"foo";

La interpolación de variables no se realizará dentro de literales e identificadores SQL entrecomillados. Por lo tanto, una construcción como ':foo' no funciona para producir un literal entrecomillado a partir del valor de una variable (y sería inseguro si funcionara, ya que no manejaría correctamente las comillas incrustadas en el valor).

Un ejemplo de uso de este mecanismo es copiar el contenido de un archivo en una columna de tabla. Primero cargue el archivo en una variable y luego interpola el valor de la variable como una cadena entrecomillada:

testdb=> \set content `cat my_file.txt`
testdb=> INSERT INTO my_table VALUES (:'content');

(Tenga en cuenta que esto aún no funcionará si my_file.txt contiene bytes NUL. psql no admite bytes NUL incrustados en valores de variables).

Dado que los dos puntos pueden aparecer legalmente en comandos SQL, un intento aparente de interpolación (es decir, :name, :'name', o :"name") no se reemplaza a menos que la variable nombrada esté actualmente establecida. En cualquier caso, puede escapar un dos puntos con una barra invertida para protegerlo de la sustitución.

La sintaxis especial :{?nombre} devuelve TRUE o FALSE dependiendo de si la variable existe o no, y por lo tanto siempre se sustituye, a menos que el dos puntos se escape con barra invertida.

La sintaxis de dos puntos para variables es SQL estándar para lenguajes de consulta incrustados, como ECPG. Las sintaxis de dos puntos para rebanadas de arreglos y tipos de datos son extensiones de PostgreSQL, que a veces pueden entrar en conflicto con el uso estándar. La sintaxis de dos puntos-comillas para escapar el valor de una variable como un literal o identificador SQL es una extensión de psql.

Indicadores de línea (Prompts)

Los indicadores de línea que emite psql se pueden personalizar a su gusto. Las tres variables PROMPT1, PROMPT2 y PROMPT3 contienen cadenas y secuencias de escape especiales que describen la apariencia del indicador. El Indicador 1 es el indicador normal que se emite cuando psql solicita un nuevo comando. El Indicador 2 se emite cuando se espera más entrada durante la entrada de comandos, por ejemplo, porque el comando no terminó con un punto y coma o una comilla no se cerró. El Indicador 3 se emite cuando está ejecutando un comando SQL COPY FROM STDIN y necesita escribir un valor de fila en la terminal.

El valor de la variable de indicador seleccionada se imprime literalmente, excepto donde se encuentra un signo de porcentaje (%). Dependiendo del siguiente carácter, se sustituye otro texto. Las sustituciones definidas son:

%M

El nombre de host completo (con nombre de dominio) del servidor de la base de datos, o [local] si la conexión es a través de un socket de dominio Unix, o [local:/dir/name], si el socket de dominio Unix no está en la ubicación predeterminada compilada.

%m

El nombre de host del servidor de la base de datos, truncado en el primer punto, o [local] si la conexión es a través de un socket de dominio Unix.

%>

El número de puerto en el que está escuchando el servidor de la base de datos.

%n

El nombre del usuario de la sesión de la base de datos. (La expansión de este valor puede cambiar durante una sesión de base de datos como resultado del comando SET SESSION AUTHORIZATION).

%s

El nombre del servicio.

%/

El nombre de la base de datos actual.

%~

Similar a %/, pero la salida es ~ (tilde) si la base de datos es su base de datos predeterminada.

%#

Si el usuario de la sesión es un superusuario de la base de datos, entonces un #, de lo contrario un >. (La expansión de este valor puede cambiar durante una sesión de base de datos como resultado del comando SET SESSION AUTHORIZATION).

%p

El ID de proceso del backend al que está conectado actualmente.

%P

Estado de la canalización: desactivado cuando no está en una canalización, activado cuando está en una canalización en curso o abortado cuando está en una canalización abortada.

%R

En el indicador 1 normalmente =, pero @ si la sesión está en una rama inactiva de un bloque condicional, o ^ si está en modo de una línea, o ! si la sesión está desconectada de la base de datos (lo que puede suceder si \connect falla). En el indicador 2, %R se reemplaza por un carácter que depende de por qué psql espera más entrada: - si el comando simplemente no ha terminado todavía, * si hay un comentario /* ... */ sin terminar, una comilla simple si hay una cadena entrecomillada sin terminar, una comilla doble si hay un identificador entrecomillado sin terminar, un signo de dólar si hay una cadena entrecomillada con signo de dólar sin terminar, o ( si hay un paréntesis izquierdo sin emparejar. En el indicador 3, %R no produce nada.

%x

Estado de la transacción: una cadena vacía cuando no está en un bloque de transacción, o * cuando está en un bloque de transacción, o ! cuando está en un bloque de transacción fallido, o ? cuando el estado de la transacción es indeterminado (por ejemplo, porque no hay conexión).

%l

El número de línea dentro de la sentencia actual, comenzando desde 1.

%dígitos

Se sustituye el carácter con el código octal indicado.

%:nombre:

El valor de la variable psql nombre. Ver Variables, arriba, para más detalles.

%`comando`

La salida de comando, similar a la sustitución ordinaria de “comillas invertidas”.

%[ ... %]

Los indicadores de línea pueden contener caracteres de control de terminal que, por ejemplo, cambian el color, el fondo o el estilo del texto del indicador, o cambian el título de la ventana de la terminal. Para que las funciones de edición de línea de Readline funcionen correctamente, estos caracteres de control no imprimibles deben designarse como invisibles rodeándolos con %[ y %]. Múltiples pares de estos pueden ocurrir dentro del indicador. Por ejemplo: 
testdb=> \set PROMPT1 '%[%033[1;33;40m%]%n@%/%R%[%033[0m%]%# '

resulta en un indicador en negrita (1;) amarillo sobre negro (33;40) en terminales compatibles con VT100 y capaces de mostrar color.

%w

Espacio en blanco del mismo ancho que la salida más reciente de PROMPT1. Esto se puede usar como una configuración de PROMPT2, de modo que las sentencias de varias líneas se alineen con la primera línea, pero no haya un indicador secundario visible.
Para insertar un signo de porcentaje en su indicador, escriba %%. Los indicadores predeterminados son '%/%R%x%# ' para los indicadores 1 y 2, y '>> ' para el indicador 3.

Edición de línea de comandos

psql utiliza la biblioteca Readline o libedit, si está disponible, para una edición y recuperación de líneas conveniente. El historial de comandos se guarda automáticamente cuando psql se cierra y se recarga cuando psql se inicia. Presione la flecha hacia arriba o control-P para recuperar líneas anteriores.

También puede usar la autocompletación con tabulación para completar palabras clave y nombres de objetos SQL parcialmente escritos en muchos (de ninguna manera todos) contextos. Por ejemplo, al inicio de un comando, escribir ins y presionar TAB completará insert into. Luego, escribir unos pocos caracteres de un nombre de tabla o esquema y presionar TAB completará el nombre incompleto, u ofrecerá un menú de posibles completaciones cuando haya más de una. (Dependiendo de la biblioteca en uso, es posible que necesite presionar TAB más de una vez para obtener un menú).

La autocompletación con tabulación para nombres de objetos SQL requiere enviar consultas al servidor para encontrar coincidencias posibles. En algunos contextos, esto puede interferir con otras operaciones. Por ejemplo, después de BEGIN, será demasiado tarde para emitir SET TRANSACTION ISOLATION LEVEL si se emite una consulta de autocompletación en el medio. Si no desea autocompletación en absoluto, puede desactivarla permanentemente colocando esto en un archivo llamado .inputrc en su directorio de inicio:

$if psql
set disable-completion on
$endif

(Esto no es una característica de psql sino de Readline. Consulte su documentación para obtener más detalles).

La opción de línea de comandos -n (--no-readline) también puede ser útil para deshabilitar el uso de Readline para una única ejecución de psql. Esto evita la autocompletación, el uso o la grabación del historial de línea de comandos y la edición de comandos de varias líneas. Es particularmente útil cuando necesita copiar y pegar texto que contiene caracteres TAB.

FILES

psqlrc y ~/.psqlrc

A menos que se le pase la opción -X, psql intenta leer y ejecutar comandos desde el archivo de inicio del sistema (psqlrc) y luego desde el archivo de inicio personal del usuario (~/.psqlrc), después de conectarse a la base de datos pero antes de aceptar comandos normales. Estos archivos se pueden utilizar para configurar el cliente y/o el servidor a gusto, típicamente con comandos \set y SET.

El archivo de inicio del sistema se llama psqlrc. De forma predeterminada, se busca en el directorio de "configuración del sistema" de la instalación, que se identifica de manera más confiable ejecutando pg_config --sysconfdir. Típicamente, este directorio será ../etc/ relativo al directorio que contiene los ejecutables de PostgreSQL. El directorio donde buscar se puede establecer explícitamente a través de la variable de entorno PGSYSCONFDIR.

El archivo de inicio personal del usuario se llama .psqlrc y se busca en el directorio de inicio del usuario que lo invoca. En Windows, el archivo de inicio personal se llama en su lugar %APPDATA%\postgresql\psqlrc.conf. En cualquier caso, esta ruta de archivo predeterminada se puede anular configurando la variable de entorno PSQLRC.

Tanto el archivo de inicio del sistema como el archivo de inicio personal del usuario pueden ser específicos de la versión de psql agregando un guion y el identificador de la versión principal o secundaria de PostgreSQL al nombre del archivo, por ejemplo, ~/.psqlrc-18 o ~/.psqlrc-18.1. El archivo que coincida de manera más específica se leerá en lugar de un archivo no específico de la versión. Estos sufijos de versión se agregan después de determinar la ruta del archivo como se explicó anteriormente.

.psql_history

El historial de comandos se almacena en el archivo ~/.psql_history, o %APPDATA%\postgresql\psql_history en Windows.

La ubicación del archivo de historial se puede establecer explícitamente a través de la variable psql HISTFILE o la variable de entorno PSQL_HISTORY.

NOTES

•psql funciona mejor con servidores de la misma versión o de una versión anterior. Es particularmente probable que los comandos de barra invertida fallen si el servidor es de una versión más reciente que psql. Sin embargo, los comandos de barra invertida de la familia \d deberían funcionar con servidores de versiones anteriores a 9.2, aunque no necesariamente con servidores más recientes que psql. La funcionalidad general de ejecutar comandos SQL y mostrar resultados de consultas también debería funcionar con servidores de una versión principal más reciente, pero esto no se puede garantizar en todos los casos.

Si desea usar psql para conectarse a varios servidores de diferentes versiones principales, se recomienda que utilice la versión más reciente de psql. Alternativamente, puede conservar una copia de psql de cada versión principal y asegurarse de utilizar la versión que coincida con el servidor respectivo. Pero en la práctica, esta complicación adicional no debería ser necesaria.

•Antes de PostgreSQL 9.6, la opción -c implicaba -X (--no-psqlrc); esto ya no es así.
•Antes de PostgreSQL 8.4, psql permitía que el primer argumento de un comando de barra invertida de una sola letra comenzara directamente después del comando, sin espacios en blanco intermedios. Ahora, se requiere algo de espacio en blanco.

NOTAS PARA USUARIOS DE WINDOWS

psql se compila como una "aplicación de consola". Dado que las ventanas de consola de Windows utilizan una codificación diferente a la del resto del sistema, debe tener especial cuidado al usar caracteres de 8 bits dentro de psql. Si psql detecta una página de códigos de consola problemática, le advertirá al iniciar. Para cambiar la página de códigos de la consola, se necesitan dos cosas:

•Establezca la página de códigos ingresando cmd.exe /c chcp 1252. (1252 es una página de códigos adecuada para alemán; reemplácela con su valor). Si está usando Cygwin, puede poner este comando en /etc/profile.
•Establezca la fuente de la consola en Lucida Console, ya que la fuente de trama no funciona con la página de códigos ANSI.

NAME

psql — PostgreSQL client application

SYNOPSIS

psql [option...] [dbname [username]]

DESCRIPTION

The psql command is PostgreSQL's interactive terminal. It allows the user to interactively enter queries, issue commands to the server, and view query results. It also provides several meta-commands and special variable capabilities for assisting in writing and editing commands and for controlling the output format.

This manual page covers the various features of psql, including its connection parameters, meta-commands, and query execution capabilities.

OPTIONS

The psql command accepts a variety of command-line options to control its behavior, such as connection parameters, input/output handling, and query formatting.

Common options include:

-d dbname
Specifies the name of the database to connect to.
-U username
Specifies the PostgreSQL user name to connect as.
-h host
Specifies the TCP host name or IP address of the machine on which the server is running.
-p port
Specifies the TCP port number on which the server is listening for connections.
-W
Force psql to prompt for a password before connecting to a database.
-f filename
Read commands from the specified file, then exit.
-c command
Execute a single command string, then exit.
-l
List all available databases on the server, then exit.
-t
Print the query results in plain text, with no HTML, LaTeX, or vertical text formatting.
-x
Enable expanded table formatting.

EXIT STATUS

psql returns 0 on successful completion, 1 if a network error occurred, 2 if a problem occurred with the syntax of the command-line arguments, 3 if an error occurred during query execution, 4 if a resource limit was exceeded, and 5 if an internal error occurred.

USAGE

psql can be used in several ways:

  • Interactive terminal: 
    psql -d mydatabase -U myuser
    This starts an interactive session where you can type SQL commands and psql meta-commands.
  • Execute commands from a file: 
    psql -d mydatabase -f commands.sql
    This reads and executes all commands in the file commands.sql.
  • Execute a single command: 
    psql -d mydatabase -c "SELECT version();"
    This executes the specified SQL command and prints the result.

ENVIRONMENT

The psql command is affected by the following environment variables:

PGDATABASE
Default database name.
PGUSER
Default PostgreSQL user name.
PGHOST
Default host name of the machine on which the server is running.
PGPORT
Default TCP port number on which the server is listening.
PGPASSWORD
Default password for user authentication.
PGSERVICE
Default service entry to use for connection parameters.

FILES

/root/.pgpass
Password file for non-interactive connections.
~/.psqlrc
Login-time initialization file.

NOTES

psql provides a rich set of meta-commands, which are commands starting with a backslash (\). These commands allow you to perform various administrative tasks, such as listing tables, describing columns, and controlling output formatting. Some common meta-commands include:

\?
List available meta-commands.
\l
List all databases.
\dt
List tables.
\d table_name
Describe a table.
\conninfo
Display information about the current connection.
\q
Quit psql.

You can also use the psql command line to execute SQL queries directly. The results will be displayed in a formatted table.

NOTES FOR WINDOWS USERS

On Windows, psql can be found in the bin subdirectory of your PostgreSQL installation. You may need to add this directory to your system's PATH environment variable to run psql from any command prompt.
