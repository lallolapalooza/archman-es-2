NOMBRE

select, pselect, FD_CLR, FD_ISSET, FD_SET, FD_ZERO, fd_set - multiplexación de E/S síncrona

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/select.h>
typedef /* ... */ fd_set;
int select(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           struct timeval *_Nullable restrict timeout);
void FD_CLR(int fd, fd_set *set);
int  FD_ISSET(int fd, const fd_set *set);
void FD_SET(int fd, fd_set *set);
void FD_ZERO(fd_set *set);
int pselect(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           const struct timespec *_Nullable restrict timeout,
           const sigset_t *_Nullable restrict sigmask);

DESCRIPCIÓN

ADVERTENCIA: select() solo puede monitorizar descriptores de archivo cuyos números sean menores que FD_SETSIZE (1024), un límite irrazonablemente bajo para muchas aplicaciones modernas, y este límite no cambiará. Todas las aplicaciones modernas deberían usar en su lugar poll(2) o epoll(7), que no sufren esta limitación.

select() permite a un programa monitorizar múltiples descriptores de archivo, esperando hasta que uno o más de los descriptores de archivo estén "listos" para alguna clase de operación de E/S (por ejemplo, entrada posible). Un descriptor de archivo se considera listo si es posible realizar una operación de E/S correspondiente (por ejemplo, read(2), o una write(2) suficientemente pequeña) sin bloquearse.

fd_set

Un tipo de estructura que puede representar un conjunto de descriptores de archivo. Según POSIX, el número máximo de descriptores de archivo en una estructura fd_set es el valor de la macro FD_SETSIZE.

Conjuntos de descriptores de archivo

Los argumentos principales de select() son tres "conjuntos" de descriptores de archivo (declarados con el tipo fd_set), que permiten al llamante esperar tres clases de eventos en el conjunto especificado de descriptores de archivo. Cada uno de los argumentos fd_set puede ser especificado como NULL si no se deben vigilar descriptores de archivo para la clase de eventos correspondiente.

Tenga en cuenta: Al regresar, cada uno de los conjuntos de descriptores de archivo se modifica en el lugar para indicar qué descriptores de archivo están actualmente "listos". Por lo tanto, si se utiliza select() dentro de un bucle, los conjuntos deben reinicializarse antes de cada llamada.

El contenido de un conjunto de descriptores de archivo se puede manipular utilizando las siguientes macros:

FD_ZERO()
Esta macro borra (elimina todos los descriptores de archivo de) set. Debe utilizarse como primer paso en la inicialización de un conjunto de descriptores de archivo.
FD_SET()
Esta macro añade el descriptor de archivo fd a set. Añadir un descriptor de archivo que ya está presente en el conjunto no tiene ningún efecto y no produce un error.
FD_CLR()
Esta macro elimina el descriptor de archivo fd de set. Eliminar un descriptor de archivo que no está presente en el conjunto no tiene ningún efecto y no produce un error.
FD_ISSET()
select() modifica el contenido de los conjuntos según las reglas descritas a continuación. Después de llamar a select(), la macro FD_ISSET() puede utilizarse para comprobar si un descriptor de archivo todavía está presente en un conjunto. FD_ISSET() devuelve un valor distinto de cero si el descriptor de archivo fd está presente en set, y cero si no lo está.

Argumentos

Los argumentos de select() son los siguientes:

readfds
Los descriptores de archivo en este conjunto se vigilan para ver si están listos para lectura. Un descriptor de archivo está listo para lectura si una operación de lectura no se bloqueará; en particular, un descriptor de archivo también está listo en fin de archivo.
Después de que select() haya regresado, readfds se borrará de todos los descriptores de archivo excepto aquellos que estén listos para lectura.
writefds
Los descriptores de archivo en este conjunto se vigilan para ver si están listos para escritura. Un descriptor de archivo está listo para escritura si una operación de escritura no se bloqueará. Sin embargo, incluso si un descriptor de archivo indica que es escribible, una escritura grande aún puede bloquearse.
Después de que select() haya regresado, writefds se borrará de todos los descriptores de archivo excepto aquellos que estén listos para escritura.
exceptfds
Los descriptores de archivo en este conjunto se vigilan para ver si hay "condiciones excepcionales". Para ejemplos de algunas condiciones excepcionales, véase la discusión de POLLPRI en poll(2).
Después de que select() haya regresado, exceptfds se borrará de todos los descriptores de archivo excepto aquellos para los que haya ocurrido una condición excepcional.
nfds
Este argumento debe establecerse en el descriptor de archivo con el número más alto en cualquiera de los tres conjuntos, más 1. Los descriptores de archivo indicados en cada conjunto son comprobados, hasta este límite (pero ver ERRORES).
timeout
El argumento timeout es una estructura timeval (que se muestra a continuación) que especifica el intervalo durante el cual select() debería bloquearse esperando que un descriptor de archivo esté listo. La llamada se bloqueará hasta que:
•
un descriptor de archivo esté listo;
•
la llamada sea interrumpida por un manejador de señales; o
•
el tiempo de espera expire.
Tenga en cuenta que el intervalo timeout se redondeará a la granularidad del reloj del sistema, y los retrasos de planificación del kernel significan que el intervalo de bloqueo puede excederse en una pequeña cantidad.
Si ambos campos de la estructura timeval son cero, entonces select() regresa inmediatamente. (Esto es útil para sondeo.)
Si timeout se especifica como NULL, select() se bloquea indefinidamente esperando que un descriptor de archivo esté listo.

pselect()

La llamada al sistema pselect() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo esté listo o hasta que se capture una señal.

La operación de select() y pselect() es idéntica, aparte de estas tres diferencias:

•
select() utiliza un tiempo de espera que es un struct timeval (con segundos y microsegundos), mientras que pselect() utiliza un struct timespec (con segundos y nanosegundos).
•
select() puede actualizar el argumento timeout para indicar cuánto tiempo quedaba. pselect() no cambia este argumento.
•
select() no tiene el argumento sigmask y se comporta como pselect() llamado con sigmask NULL.

sigmask es un puntero a una máscara de señales (ver sigprocmask(2)); si no es NULL, entonces pselect() primero reemplaza la máscara de señales actual por la que

Aparte de la diferencia en la precisión del argumento timeout, la siguiente llamada a pselect():


ready = pselect(nfds, &readfds, &writefds, &exceptfds,
                timeout, &sigmask);

es equivalente a ejecutar *atmicamente* las siguientes llamadas:


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = select(nfds, &readfds, &writefds, &exceptfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

La razón por la que se necesita pselect() es que si se desea esperar ya sea una señal o a que un descriptor de archivo esté listo, se necesita una prueba atómica para evitar condiciones de carrera. (Suponga que el manejador de señales establece una bandera global y retorna. Luego, una prueba de esta bandera global seguida de una llamada a select() podría colgarse indefinidamente si la señal llegara justo después de la prueba pero justo antes de la llamada. Por el contrario, pselect() permite bloquear primero las señales, manejar las señales que han llegado, luego llamar a pselect() con el sigmask deseado, evitando la carrera.)

El timeout

El argumento timeout para select() es una estructura del siguiente tipo:


struct timeval {
    time_t      tv_sec;         /* segundos */
    suseconds_t tv_usec;        /* microsegundos */
};

El argumento correspondiente para pselect() es una estructura timespec(3).

En Linux, select() modifica timeout para reflejar la cantidad de tiempo no dormido; la mayoría de las otras implementaciones no hacen esto. (POSIX.1 permite cualquiera de los dos comportamientos). Esto causa problemas tanto cuando el código de Linux que lee timeout se porta a otros sistemas operativos, como cuando se porta código a Linux que reutiliza un struct timeval para múltiples select()s en un bucle sin reinicializarlo. Considere timeout como indefinido después de que select() retorne.

VALOR DE RETORNO

En caso de éxito, select() y pselect() devuelven el número de descriptores de archivo contenidos en los tres conjuntos de descriptores devueltos (es decir, el número total de bits establecidos en readfds, writefds, exceptfds). El valor de retorno puede ser cero si el tiempo de espera expiró antes de que algún descriptor de archivo estuviera listo.

En caso de error, se devuelve -1 y se establece errno para indicar el error; los conjuntos de descriptores de archivo no se modifican y timeout se vuelve indefinido.

ERRORES

EBADF
Se proporcionó un descriptor de archivo inválido en uno de los conjuntos. (Quizás un descriptor de archivo que ya estaba cerrado, o uno en el que ha ocurrido un error). Sin embargo, véase ERRORES GRAVES.
EINTR
Se capturó una señal; véase signal(7).
EINVAL
nfds es negativo o excede el límite de recursos RLIMIT_NOFILE (véase getrlimit(2)).
EINVAL
El valor contenido en timeout es inválido.
ENOMEM
No se pudo asignar memoria para tablas internas.

VERSIONES

En otros sistemas UNIX, select() puede fallar con el error EAGAIN si el sistema no puede asignar recursos internos del kernel, en lugar de ENOMEM como lo hace Linux. POSIX especifica este error para poll(2), pero no para select(). Los programas portátiles pueden querer verificar EAGAIN y repetir el bucle, al igual que con EINTR.

NOTAS

La siguiente cabecera también proporciona el tipo fd_set: <sys/time.h>.

Un fd_set es un búfer de tamaño fijo. Ejecutar FD_CLR() o FD_SET() con un valor de fd negativo o igual o mayor que FD_SETSIZE resultará en un comportamiento indefinido. Además, POSIX requiere que fd sea un descriptor de archivo válido.

La operación de select() y pselect() no se ve afectada por la bandera O_NONBLOCK.

El truco de la auto-tubería

En sistemas que carecen de pselect(), se puede lograr una captura de señales fiable (y más portable) utilizando el truco de la auto-tubería. En esta técnica, un manejador de señales escribe un byte en una tubería cuyo otro extremo es monitorizado por select() en el programa principal. (Para evitar posibles bloqueos al escribir en una tubería que puede estar llena o leer de una tubería que puede estar vacía, se utiliza E/S sin bloqueo al leer y escribir en la tubería.)

Emulando usleep(3)

Antes de la aparición de usleep(3), algunos códigos empleaban una llamada a select() con los tres conjuntos vacíos, nfds cero y un timeout no NULL como una forma bastante portable de dormir con precisión sub-segundo.

Correspondencia entre notificaciones de select() y poll()

Dentro del código fuente del kernel de Linux, encontramos las siguientes definiciones que muestran la correspondencia entre las notificaciones de condiciones de lectura, escritura y excepcionales de select() y las notificaciones de eventos proporcionadas por poll(2) y epoll(7):


#define POLLIN_SET  (EPOLLRDNORM | EPOLLRDBAND | EPOLLIN |
                     EPOLLHUP | EPOLLERR)
                   /* Listo para leer */
#define POLLOUT_SET (EPOLLWRBAND | EPOLLWRNORM | EPOLLOUT |
                     EPOLLERR)
                   /* Listo para escribir */
#define POLLEX_SET  (EPOLLPRI)
                   /* Condición excepcional */

Aplicaciones multihilo

Si un descriptor de archivo que está siendo monitorizado por select() se cierra en otro hilo, el resultado no está especificado. En algunos sistemas UNIX, select() se desbloquea y retorna, con una indicación de que el descriptor de archivo está listo (una operación de E/S posterior probablemente fallará con un error, a menos que otro proceso reabra el descriptor de archivo entre el momento en que select() retornó y se realiza la operación de E/S). En Linux (y algunos otros sistemas), cerrar el descriptor de archivo en otro hilo no tiene efecto en select(). En resumen, cualquier aplicación que dependa de un comportamiento particular en este escenario debe considerarse defectuosa.

Diferencias biblioteca C/kernel

El kernel de Linux permite conjuntos de descriptores de archivo de tamaño arbitrario, determinando la longitud de los conjuntos a verificar a partir del valor de nfds. Sin embargo, en la implementación de glibc, el tipo fd_set es de tamaño fijo. Véase también ERRORES GRAVES.

La interfaz pselect() descrita en esta página está implementada por glibc. La llamada al sistema subyacente de Linux se llama pselect6(). Esta llamada al sistema tiene un comportamiento algo diferente de la función envoltorio de glibc.

La llamada al sistema pselect6() de Linux modifica su argumento timeout. Sin embargo, la función envoltorio de glibc oculta este comportamiento utilizando una variable local para el argumento de tiempo de espera que se pasa a la llamada al sistema. Por lo tanto, la función pselect() de glibc no modifica su argumento timeout; este es el comportamiento requerido por POSIX.1-2001.

El argumento final de la llamada al sistema pselect6() no es un puntero sigset_t *, sino una estructura del tipo:


struct {
    const kernel_sigset_t *ss;   /* Puntero al conjunto de señales */
    size_t ss_len;               /* Tamaño (en bytes) del objeto
                                    apuntado por 'ss' */
};

Esto permite que la llamada al sistema obtenga tanto un puntero al conjunto de señales como su tamaño, al tiempo que permite el hecho de que la mayoría de las arquitecturas soportan un máximo de 6 argumentos a una llamada al sistema. Véase sigprocmask(2) para una discusión de la diferencia entre la noción del kernel y la de libc del conjunto de señales.

Detalles históricos de glibc

glibc 2.0 proporcionó una versión incorrecta de pselect() que no tomaba un argumento sigmask.

Desde glibc 2.1 hasta glibc 2.2.1, se debe definir _GNU_SOURCE para obtener la declaración de pselect() desde <sys/select.h>.

NOTES

The range of file
descriptors that can be specified in a file descriptor set. The Linux kernel
imposes no fixed limit, but the glibc implementation makes fd_set a
fixed-size type, with FD_SETSIZE defined as 1024, and the
FD_*() macros operating according to that limit. To monitor file
descriptors greater than 1023, use poll(2) or epoll(7)
instead.

The implementation of the fd_set arguments as value-result
arguments is a design error that is avoided in poll(2) and
epoll(7).

According to POSIX, select() should check all specified
file descriptors in the three file descriptor sets, up to the limit
nfds-1. However, the current implementation ignores any file
descriptor in these sets that is greater than the maximum file descriptor
number that the process currently has open. According to POSIX, any such
file descriptor that is specified in one of the sets should result in the
error EBADF.

Starting with glibc 2.1, glibc provided an emulation of
pselect() that was implemented using sigprocmask(2) and
select(). This implementation remained vulnerable to the very race
condition that pselect() was designed to prevent. Modern versions of
glibc use the (race-free) pselect() system call on kernels where it
is provided.

On Linux, select() may report a socket file descriptor as
"ready for reading", while nevertheless a subsequent read blocks.
This could for example happen when data has arrived but upon examination has
the wrong checksum and is discarded. There may be other circumstances in
which a file descriptor is spuriously reported as ready. Thus it may be
safer to use O_NONBLOCK on sockets that should not block.

On Linux, select() also modifies timeout if the call
is interrupted by a signal handler (i.e., the EINTR error return).
This is not permitted by POSIX.1. The Linux pselect() system call has
the same behavior, but the glibc wrapper hides this behavior by internally
copying the timeout to a local variable and passing that variable to
the system call.

EJEMPLOS

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Watch stdin (fd 0) to see when it has input.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Wait up to five seconds.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Don't rely on the value of tv now! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Data is available now.\n");
        /* FD_ISSET(0, &rfds) will be true.  */
    else
        printf("No data within five seconds.\n");
    exit(EXIT_SUCCESS);
}
