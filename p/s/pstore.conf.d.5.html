NOMBRE

pstore.conf, pstore.conf.d - Archivo de configuración de PStore

SINOPSIS

/etc/systemd/pstore.conf
/run/systemd/pstore.conf
/usr/local/lib/systemd/pstore.conf
/usr/lib/systemd/pstore.conf
/etc/systemd/pstore.conf.d/*.conf
/run/systemd/pstore.conf.d/*.conf
/usr/local/lib/systemd/pstore.conf.d/*.conf
/usr/lib/systemd/pstore.conf.d/*.conf

DESCRIPCIÓN

Este archivo configura el comportamiento de systemd-pstore(8), una herramienta para archivar el contenido del sistema de archivos de almacenamiento persistente, pstore[1].

DIRECTORIOS DE CONFIGURACIÓN Y PRECEDENCIA

La configuración predeterminada se establece durante la compilación, por lo que la configuración solo es necesaria cuando es necesario desviarse de esos valores predeterminados. El archivo de configuración principal se carga desde uno de los directorios listados en orden de prioridad, solo se utiliza el primer archivo encontrado: /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [2], /usr/lib/systemd/. La versión del proveedor del archivo contiene entradas comentadas que muestran los valores predeterminados como guía para el administrador. Las anulaciones locales también se pueden crear creando archivos de configuración adicionales (drop-ins), como se describe a continuación. El archivo de configuración principal también se puede editar para este propósito (o una copia en /etc/ si se distribuye bajo /usr/), sin embargo, se recomienda usar drop-ins para la configuración local en lugar de modificaciones al archivo de configuración principal.

Además del archivo de configuración principal, se leen fragmentos de configuración adicionales (drop-ins) de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/ y /etc/systemd/*.conf.d/. Estos drop-ins tienen mayor precedencia y anulan el archivo de configuración principal. Los archivos en los subdirectorios de configuración *.conf.d/ se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en cuál de los subdirectorios residan. Cuando varios archivos especifican la misma opción, para las opciones que aceptan solo un valor, la entrada en el archivo ordenado último tiene precedencia, y para las opciones que aceptan una lista de valores, las entradas se recopilan a medida que ocurren en los archivos ordenados.

Cuando los paquetes necesitan personalizar la configuración, pueden instalar drop-ins bajo /usr/. Los archivos en /etc/ están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor. Se deben usar drop-ins para anular los drop-ins de paquetes, ya que el archivo de configuración principal tiene menor precedencia. Se recomienda prefijar todos los nombres de archivo en estos subdirectorios con un número de dos dígitos y un guion, para simplificar el ordenamiento. Esto también define un concepto de prioridades de drop-in para permitir a los proveedores de OS enviar drop-ins dentro de un rango específico inferior al rango utilizado por los usuarios. Esto debería disminuir el riesgo de que los drop-ins de paquetes anulen accidentalmente los drop-ins definidos por los usuarios. Se recomienda usar el rango 10-40 para drop-ins en /usr/ y el rango 60-90 para drop-ins en /etc/ y /run/, para asegurarse de que los drop-ins locales y transitorios tengan prioridad sobre los drop-ins enviados por el proveedor del sistema operativo.

Para deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en el directorio de configuración en /etc/, con el mismo nombre de archivo que el archivo de configuración del proveedor.

OPCIONES

Todas las opciones se configuran en la sección [PStore]:

Storage=

Controla dónde archivar (es decir, copiar) los archivos del sistema de archivos pstore. Una de las opciones: "none", "external", y "journal". Cuando es "none", la herramienta sale sin procesar los archivos del sistema de archivos pstore. Cuando es "external" (el valor predeterminado), los archivos se archivan en /var/lib/systemd/pstore/ y se registran en el journal. Cuando es "journal", el contenido del archivo pstore se registra solo en el journal.

Añadido en la versión 243.

Unlink=

Controla si los archivos se eliminan o no de pstore después del procesamiento. Toma un valor booleano. Cuando es verdadero, un archivo pstore se elimina de pstore una vez que ha sido archivado (ya sea en disco o en el journal). Cuando es falso, el procesamiento de los archivos pstore ocurre normalmente, pero los archivos permanecen en pstore. El valor predeterminado es verdadero para mantener el pstore en un estado casi vacío, de modo que el pstore tenga almacenamiento disponible para el próximo evento de error del kernel.

Añadido en la versión 243.

Use

systemd-analyze cat-config systemd/pstore.conf

para mostrar la configuración completa.
