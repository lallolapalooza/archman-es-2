PS(1P) Manual del programador de POSIX PS(1P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual correspondiente de Linux para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

ps — informar sobre el estado de los procesos

SINOPSIS

ps [-aA] [-defl] [-g lista_de_grupos] [-G lista_de_grupos]
    [-n lista_de_nombres] [-o formato]... [-p lista_de_procesos] [-t lista_de_terminales]
    [-u lista_de_usuarios] [-U lista_de_usuarios]

DESCRIPCIÓN

La utilidad ps escribirá información sobre los procesos, sujeta a tener los privilegios apropiados para obtener información sobre dichos procesos.

Por defecto, ps seleccionará todos los procesos con el mismo ID de usuario efectivo que el usuario actual y el mismo terminal de control que el invocador.

OPCIONES

La utilidad ps cumplirá con el volumen de Definiciones Base de POSIX.1-2017, Sección 12.2, Pautas de sintaxis de utilidades.

Se admitirán las siguientes opciones:

-a
Escribe información para todos los procesos asociados a terminales. Las implementaciones pueden omitir los líderes de sesión de esta lista.
-A
Escribe información para todos los procesos.
-d
Escribe información para todos los procesos, excepto los líderes de sesión.
-e
Escribe información para todos los procesos. (Equivalente a -A.)
-f
Genera una lista completa. (Consulte la sección STDOUT para conocer el contenido de una lista completa.)
-g lista_de_grupos
Escribe información para los procesos cuyos líderes de sesión se indican en lista_de_grupos. La aplicación garantizará que lista_de_grupos sea un único argumento en forma de una lista separada por espacios en blanco o comas.
-G lista_de_grupos
Escribe información para los procesos cuyos ID de grupo real se indican en lista_de_grupos. La aplicación garantizará que lista_de_grupos sea un único argumento en forma de una lista separada por espacios en blanco o comas.
-l
Genera una lista larga. (Consulte STDOUT para conocer el contenido de una lista larga.)
-n lista_de_nombres
Especifica el nombre de un archivo de lista_de_nombres del sistema alternativo en lugar del predeterminado. El nombre del archivo predeterminado y el formato de un archivo de lista_de_nombres no están especificados.
-o formato
Escribe información de acuerdo con la especificación de formato dada en formato. Esto se describe completamente en la sección STDOUT. Se pueden especificar múltiples opciones -o; la especificación de formato se interpretarán como la concatenación separada por espacios de todos los argumentos de opción formato.
-p lista_de_procesos
Escribe información para los procesos cuyos números de ID de proceso se indican en lista_de_procesos. La aplicación garantizará que lista_de_procesos sea un único argumento en forma de una lista separada por espacios en blanco o comas.
-t lista_de_terminales
Escribe información para los procesos asociados a terminales indicados en lista_de_terminales. La aplicación garantizará que lista_de_terminales sea un único argumento en forma de una lista separada por espacios en blanco o comas. Los identificadores de terminal se indicarán en un formato no especificado por la implementación. En los sistemas compatibles con XSI, se indicarán en una de las dos formas: el nombre de archivo del dispositivo (por ejemplo, tty04) o, si el nombre de archivo del dispositivo comienza con tty, solo el identificador que sigue a los caracteres tty (por ejemplo, "04").
-u lista_de_usuarios
Escribe información para los procesos cuyos ID de usuario o nombres de inicio de sesión se indican en lista_de_usuarios. La aplicación garantizará que lista_de_usuarios sea un único argumento en forma de una lista separada por espacios en blanco o comas. En la lista, se escribirá el ID de usuario numérico, a menos que se utilice la opción -f, en cuyo caso se escribirá el nombre de inicio de sesión.
-U lista_de_usuarios
Escribe información para los procesos cuyos ID de usuario real o nombres de inicio de sesión se indican en lista_de_usuarios. La aplicación garantizará que lista_de_usuarios sea un único argumento en forma de una lista separada por espacios en blanco o comas.

Con la excepción de -f, -l, -n lista_de_nombres y -o formato, todas las opciones mostradas se utilizan para seleccionar procesos. Si se especifica alguna, se ignorará la lista predeterminada y ps seleccionará los procesos representados por la unión inclusiva de todas las opciones de criterios de selección.

ENTRADA ESTÁNDAR

ARCHIVOS DE ENTRADA

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de ps:

COLUMNS
Anula el tamaño de línea de visualización horizontal seleccionado por el sistema, utilizado para determinar el número de columnas de texto a mostrar. Consulte el volumen de Definiciones Base de POSIX.1-2017, Capítulo 8, Variables de entorno para valores válidos y resultados cuando no está establecida o está vacía.
LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1-2017, Sección 8.2, Variables de internacionalización la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de locale.)
LC_ALL
Si se establece en una cadena de valor no vacía, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a multibyte en argumentos).
LC_MENSAJES

Determina la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida estándar de error y los mensajes informativos escritos en la salida estándar.
LC_TIEMPO
Determina el formato y el contenido de las cadenas de fecha y hora mostradas.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MENSAJES.
TZ
Determina la zona horaria utilizada para calcular las cadenas de fecha y hora que se muestran. Si TZ no está establecida o está vacía, se utilizará una zona horaria predeterminada no especificada.

EVENTOS ASÍNCRONOS

Predeterminado.

NAME

ps - report process status

SYNOPSIS

ps [-a|-A] [-d] [-f] [-F] [-g grouplist] [- G grouplist] [-j] [-l] [-L] [-n namelist] [-o format] [-p proclist] [-P] [-s secs] [-t ttylist] [-T] [-u userlist] [-U userlist] [-x]

DESCRIPTION

The ps utility displays information about the currently active processes.

The output format of ps is described by the -f, -l, -F, -L, -j, -x, -t, -u, -U, -g, -G, -p, -P, -s, and -o options.

If none of the options -a, -A, -g, -G, -u, -U, -p, -t, or -x are specified, the behavior is as if -u and -x were specified. Otherwise, the set of processes selected is the union of the sets of processes specified by the options.

The options -f and -l specify the information to be displayed about each process.

The options -F and -L produce different styles of output. -F requests extra information, and -L requests that long format be used. The specific columns produced by the -F and -L options are determined by the implementation.

The -o option allows the user to specify the output format. The format is specified by a list of keywords, each preceded by the keyword's name. The keywords are separated by blanks or commas. The application shall ensure that the format specification is a single argument.

The following format keywords are supported by the ps utility:

F (l) Flags (octal and additive) associated with the process.
S (l) The state of the process.
UID (f,l) The user ID number of the process owner; the login name is printed under the -f option.
PID (all) The process ID of the process; it is possible to kill a process if this datum is known.
PPID (f,l) The process ID of the parent process.
C (f,l) Processor utilization for scheduling.
PRI (l) The priority of the process; higher numbers mean lower priority.
NI (l) Nice value; used in priority computation.
ADDR (l) The address of the process.
SZ (l) The size in blocks of the core image of the process.
WCHAN (l) The event for which the process is waiting or sleeping; if blank, the process is running.
STIME (f) Starting time of the process.
TTY (all) The controlling terminal for the process.
TIME (all) The cumulative execution time for the process.
CMD (all) The command name; the full command name and its arguments are written under the -f option.

A process that has exited and has a parent, but has not yet been waited for by the parent, shall be marked defunct.

Under the option -f, ps tries to determine the command name and arguments given when the process was created by examining memory or the swap area. Failing this, the command name, as it would appear without the option -f, is written in square brackets.

The -o option allows the output format to be specified under user control.

The application shall ensure that the format specification is a list of names presented as a single argument, <blank> or <comma>-separated. Each variable has a default header. The default header can be overridden by appending an <equals-sign> and the new text of the header. The rest of the characters in the argument shall be used as the header text. The fields specified shall be written in the order specified on the command line, and should be arranged in columns in the output. The field widths shall be selected by the system to be at least as wide as the header text (default or overridden value). If the header text is null, such as -o user=, the field width shall be at least as wide as the default header text. If all header text fields are null, no header line shall be written.

The following names are recognized in the POSIX locale:

ruser
The real user ID of the process. This shall be the textual user ID, if it can be obtained and the field width permits, or a decimal representation otherwise.
user
The effective user ID of the process. This shall be the textual user ID, if it can be obtained and the field width permits, or a decimal representation otherwise.
rgroup
The real group ID of the process. This shall be the textual group ID, if it can be obtained and the field width permits, or a decimal representation otherwise.
group
The effective group ID of the process. This shall be the textual group ID, if it can be obtained and the field width permits, or a decimal representation otherwise.
pid
The decimal value of the process ID.
ppid
The decimal value of the parent process ID.
pgid
The decimal value of the process group ID.
pcpu
The ratio of CPU time used recently to CPU time available in the same period, expressed as a percentage. The meaning of ``recently'' in this context is unspecified. The CPU time available is determined in an unspecified manner.
vsz
The size of the process in (virtual) memory in 1024 byte units as a decimal integer.
nice
The decimal value of the nice value of the process; see nice.
etime
In the POSIX locale, the elapsed time since the process was started, in the form:
[[dd-]hh:]mm:ss

where dd shall represent the number of days, hh the number of hours, mm the number of minutes, and ss the number of seconds. The dd field shall be a decimal integer. The hh, mm, and ss fields shall be two-digit decimal integers padded on the left with zeros.

time
In the POSIX locale, the cumulative CPU time of the process in the form:
[dd-]hh:mm:ss

The dd, hh, mm, and ss fields shall be as described in the etime specifier.

tty
The name of the controlling terminal of the process (if any) in the same format used by the who utility.
comm
The name of the command being executed (argv[0] value) as a string.
args
The command with all its arguments as a string. The implementation may truncate this value to the field width; it is implementation-defined whether any further truncation occurs. It is unspecified whether the string represented is a version of the argument list as it was passed to the command when it started, or is a version of the arguments as they may have been modified by the application. Applications cannot depend on being able to modify their argument list and having that modification be reflected in the output of ps.

Any field need not be meaningful in all implementations. In such a case a <hyphen-minus> ('-') should be output in place of the field value.

Only comm and args shall be allowed to contain <blank> characters; all others shall not. Any implementation-defined variables shall be specified in the system documentation along with the default header and indicating whether the field may contain <blank> characters.

The following table specifies the default header to be used in the POSIX locale corresponding to each format specifier.

The following sections are informative.

APPLICATION USAGE

Things can change while ps is running; the snapshot it gives is only true for an instant, and might not be accurate by the time it is displayed.

The args format specifier is allowed to produce a truncated version of the command arguments. In some implementations, this information is no longer available when the ps utility is executed.

/p>

Si el ancho del campo es demasiado estrecho para mostrar un ID textual, el sistema puede usar una versión numérica. Normalmente, se esperaría que el sistema eligiera anchos de campo lo suficientemente grandes, pero si se seleccionara un gran número de campos para escribir, podría reducir los campos a sus tamaños mínimos para que quepan en una sola línea. Una forma de garantizar un ancho adecuado para los ID textuales es anular la cabecera predeterminada de un campo para hacerla más grande que la mayoría o todos los nombres de usuario o grupo.

No existe un mecanismo de comillas especial para el texto de la cabecera. El texto de la cabecera es el resto del argumento. Si se necesitan múltiples cambios de cabecera, se pueden usar múltiples opciones -o, como:

ps -o "user=Nombre de Usuario" -o pid=ID\ de\ Proceso

En algunas implementaciones, especialmente sistemas de seguridad de múltiples niveles, ps puede estar severamente restringido y producir información solo sobre los procesos hijos propiedad del usuario.

EJEMPLOS

El comando:

ps -o user,pid,ppid=MOM -o args

escribe al menos lo siguiente en la configuración regional POSIX:

  USER   PID   MOM   COMMAND
helene    34    12   ps -o uid,pid,ppid=MOM -o args

El contenido del campo COMMAND no tiene por qué ser el mismo en todas las implementaciones, debido a una posible truncación.

RACIONALE

Hay muy poca similitud entre las implementaciones BSD y System V de ps. Muchas opciones entran en conflicto o tienen usos sutilmente diferentes. Los desarrolladores del estándar intentaron seleccionar un conjunto de opciones para el estándar base que fueran útiles en una amplia gama de sistemas y seleccionaron opciones que se pueden implementar en sistemas basados en BSD y System V sin romper las implementaciones actuales, o donde las opciones son lo suficientemente similares como para que cualquier cambio no sea excesivamente problemático para los usuarios o implementadores.

Se reconoce que en algunas implementaciones, especialmente sistemas de seguridad de múltiples niveles, ps puede ser casi inútil. Por lo tanto, la salida predeterminada se ha elegido de manera que no rompa las implementaciones históricas y también es probable que proporcione al menos alguna información útil en la mayoría de los sistemas.

El principal cambio es la adición de la capacidad de especificación de formato. La motivación para esta invención es proporcionar un mecanismo para que los usuarios accedan a una gama más amplia de información del sistema, si el sistema lo permite, de una manera portable. Los campos elegidos para aparecer en este volumen de POSIX.1‐2017 se obtuvieron después de considerar qué conceptos eran probablemente útiles para el usuario "promedio" y tenían una probabilidad razonable de ser implementados en una amplia gama de sistemas. Nuevamente, se reconoce que no todos los sistemas pueden proporcionar toda la información y, a la inversa, algunos pueden desear proporcionar más. Se espera que el enfoque adoptado sea lo suficientemente flexible y extensible para dar cabida a la mayoría de los sistemas. Se puede esperar que las implementaciones introduzcan nuevos especificadores de formato.

La salida predeterminada debe consistir en una lista corta que contenga el ID del proceso, el nombre del terminal, el tiempo de ejecución acumulativo y el nombre del comando de cada proceso.

La preferencia de los desarrolladores del estándar habría sido hacer la especificación de formato un operando del comando ps. Desafortunadamente, el uso de BSD lo impidió.

En un momento dado, se incluyó un formato para mostrar la matriz de entorno del proceso. Esto se eliminó porque no hay una forma portable de mostrarlo.

La opción -A es equivalente a la opción -g de BSD y a la opción -e de SVID. Debido a que los dos sistemas diferían, se seleccionó un compromiso mnemotécnico.

La opción -a se describe con algún comportamiento opcional porque SVID omite los líderes de sesión, pero BSD no.

En una propuesta temprana, aparecieron especificadores de formato para prioridad y tiempo de inicio. El primero no se definió adecuadamente en este volumen de POSIX.1‐2017 y se eliminó en favor del valor de nice definido; el segundo porque el tiempo transcurrido se consideró más útil.

En una nueva versión BSD de ps, se puede usar la opción -O para escribir toda la información predeterminada, seguida de especificadores de formato adicionales. Esto no se adoptó porque la salida predeterminada depende de la implementación. Sin embargo, esta es una opción útil que debe reservarse para ese propósito. En la opción -o para ps de POSIX Shell and Utilities, el formato es la concatenación de cada -o. Por lo tanto, el usuario puede tener un alias o una función que defina el inicio de su formato deseado y agregar más campos al final de la salida en ciertos casos donde sería útil.

El formato del nombre del terminal no está especificado, pero las descripciones de ps, talk, who y write requieren que todos utilicen el mismo formato.

El campo pcpu indica que el tiempo de CPU disponible se determina de manera no especificada. Esto se debe a que es difícil expresar un algoritmo que sea útil en todas las arquitecturas de máquinas posibles. Las contrapartes históricas de este valor han intentado mostrar el porcentaje de uso en el pasado reciente, como el minuto anterior. Con frecuencia, estos valores para todos los procesos no sumaban 100%. Se alienta a las implementaciones a proporcionar datos en este campo a los usuarios que les ayuden a identificar los procesos que afectan actualmente el rendimiento del sistema.
