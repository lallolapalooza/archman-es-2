NOMBRE

pnmtopalm - convertir una imagen PNM a un mapa de bits Palm

SINOPSIS

pnmtopalm

[-verbose]

[-depth=N]

[-maxdepth=N]

[-colormap]

[-transparent=color]

[-density=N]

[-offset]

[-withdummy] [-scanline-compression | -rle-compression | -packbits-compression]

[archivo_pnm]

Se puede usar la abreviatura única mínima de la opción. Puede usar guiones dobles en lugar de guiones simples para indicar opciones. Puede usar espacios en blanco en lugar del signo igual para separar un nombre de opción de su valor.

DESCRIPCIÓN

Este programa forma parte de Netpbm(1)

pnmtopalm lee una imagen PNM como entrada, desde la entrada estándar o el archivo_pnm y produce un mapa de bits Palm como salida.

Los archivos de mapa de bits Palm son archivos en escala de grises de 1, 2 o 4 bits de ancho, o archivos en color de 8 bits de ancho, por lo que pnmtopalm escala automáticamente los colores para tener un maxval apropiado, a menos que especifique una profundidad o una profundidad máxima. Los archivos de entrada deben tener un número y conjunto de colores apropiados para las restricciones de salida seleccionadas.

Esto a menudo significa que debe procesar la imagen PNM a través de pnmquant o pnmremap antes de pasarla a pnmtopalm. Netpbm viene con varios archivos de mapa de colores que puede usar con pnmremap para este propósito. Son palmgray2.map (4 tonos de gris para una profundidad de 2), palmgray4.map (16 tonos de gris para una profundidad de 4) y palmcolor8.map (232 colores en el mapa de colores predeterminado de Palm). En una instalación estándar de Netpbm, estos se encuentran en el directorio de datos de Netpbm, y puede encontrar el directorio de datos de Netpbm con un comando de shell netpbm-config --datadir.

Ejemplo:

  pnmremap myimage.ppm \
           -mapfile=$(netpbm-config --datadir)/palmgray2.map \
  | pnmtopalm -depth=2 >myimage.palm

Versión del mapa de bits Palm

pnmtopalm genera un mapa de bits Palm de Versión 0, 1, 2 o 3. Genera la versión más antigua (más baja) que puede para la imagen dada y las opciones que especifica.

  • Si especifica una densidad (opción -density) superior a 'baja', la versión es al menos 3.
  • Si especifica transparencia (opción -transparent) o cualquier compresión, la versión es al menos 2.
  • Si especifica un mapa de colores personalizado (opción -colormap), la versión es al menos 1.
  • Si la imagen tiene más de un bit por píxel, la versión es al menos 1. La imagen tiene más de un bit por píxel si la especifica con -depth o si la deja por defecto y la imagen tiene más de dos colores (o tonos de gris).

Todas las versiones de Palm OS pueden leer un mapa de bits de Versión 0. Palm OS 3.0 y posteriores pueden leer un mapa de bits de Versión 1. Palm OS 3.5 y posteriores pueden leer un mapa de bits de Versión 2. Para leer un mapa de bits de Versión 3, necesita Palm OS Garnet o un dispositivo de mano que ejecute el Conjunto de características de pantalla de alta densidad.

OPCIONES

-verbose
Mostrar el formato del archivo de salida.
-depth=N
Producir un archivo de profundidad N, donde N debe ser 1, 2, 4, 8 o 16. Dado que el mapa de colores predeterminado de Palm de 8 bits no es en escala de grises, si la entrada es una imagen en escala de grises o monocromática, la salida nunca tendrá más de 4 bits de profundidad, independientemente de la profundidad especificada. Tenga en cuenta que el color de 8 bits solo funciona en PalmOS 3.5 (y superior), y el color directo de 16 bits solo funciona en PalmOS 4.0 (y superior). Sin embargo, el formato de color directo de 16 bits también es compatible con las diversas versiones de PalmOS 3.x utilizadas en el Handspring Visor, por lo que estas imágenes también pueden funcionar en ese dispositivo.
-maxdepth=N
Producir un archivo de profundidad mínima, pero en cualquier caso menos de N bits de ancho. Si especifica 16 bits, la salida siempre será color directo de 16 bits.
-offset
Establecer el campo nextDepthOffset en el encabezado del archivo palm para indicar el final del archivo (y rellenar el final del archivo a 4 bytes, ya que nextDepthOffset solo puede apuntar a límites de 4 bytes).

Un archivo de imagen palm puede contener múltiples representaciones de la misma imagen, con diferentes profundidades de color, para que un visor pueda elegir una apropiada para la pantalla. El campo nextDepthOffset indica dónde comienza la siguiente representación en el flujo.

pnmtopalm crea un archivo que contiene una sola imagen, pero puede concatenar por separado varios archivos de una sola imagen para crear un archivo de múltiples imágenes. Si hace eso, necesitará usar -offset para que la concatenación resultante sea un flujo correcto.

Por defecto (si no especifica -offset), pnmtopalm genera un campo nextDepthOffset que indica que no hay ninguna imagen siguiente (y no agrega ningún relleno después de la imagen).

La versión 3 de los mapas de bits Palm en realidad tiene un campo nextBitmapOffset en lugar de nextDepthOffset. Lo anterior se aplica a cualquiera de los dos que sea relevante.

La opción -offset es nueva en Netpbm 10.26 (enero de 2005). Antes de eso, pnmtopalm siempre establecía el campo nextDepthOffset en 'ninguno'.

Antes de Netpbm 10.27 (marzo de 2005), no puede usar -offset si crea un raster comprimido (porque pnmtopalm no es lo suficientemente inteligente como para saber el tamaño de la imagen en el momento en que escribe el encabezado). Tampoco puede usarlo con una profundidad de color de 16 bits o con la opción -colormap, por razones muy similares.

-withdummy
Esta opción le indica a pnmtopalm que inserte en el flujo, después de la imagen, un encabezado de imagen ficticio para introducir imágenes posteriores de alta densidad.

Este encabezado de imagen ficticio es una secuencia especial especificada en las especificaciones del mapa de bits Palm. Para un intérprete de mapa de bits Palm más antiguo, parece un encabezado de imagen no válido, por lo que un intérprete de este tipo dejará de leer el flujo allí. Pero un nuevo intérprete de mapa de bits Palm lo reconoce por lo que es (simplemente algo para confundir a un intérprete antiguo) y lo omite. Presumiblemente, agregará imágenes posteriores de alta densidad al flujo que confundirían a un intérprete antiguo.

Si especifica -withdummy, también debe especificar -offset, ya que no tiene ningún sentido de lo contrario.

-withdummy es nuevo en Netpbm 10.27 (marzo de 2005).

-colormap
Construye un mapa de colores personalizado e inclúyelo en el archivo de salida. Palm no recomienda esto, por razones de eficiencia. De lo contrario, pnmtopalm utiliza el mapa de colores predeterminado de Palm para la salida en color.
-transparent=color
Marca un color particular como completamente transparente. El formato para especificar el color es ya sea (cuando por ejemplo naranja) '1.0,0.5,0.0', donde los valores son flotantes entre cero y uno, o con la sintaxis '#RGB', '#RRGGBB' o '#RRRRGGGGBBBB' donde R, G y B son números hexadecimales. La transparencia solo funciona en Palm OS 3.5 y superior.
-scanline-compression
Especifica que el mapa de bits Palm de salida utilizará el esquema de compresión de líneas de escaneo de Palm. La compresión de líneas de escaneo solo funciona en Palm OS 2.0 y superior.
-rle-compression
Especifica que el mapa de bits Palm de salida utilizará el esquema de compresión RLE de Palm. La compresión RLE solo funciona con Palm OS 3.5 y superior.
-packbits-compression
Especifica que el mapa de bits Palm de salida utilizará el esquema de compresión packbits de Palm. La compresión Packbits solo funciona con Palm OS 4.0 y superior.

Esta opción es nueva en Netpbm 10.27 (marzo de 2005).

pnmtopalm(1)

NAME

pnmtopalm - convert PNM images to Palm Bitmap format

SYNOPSIS

pnmtopalm [-width width] [-height height] [-depth depth] [-offset offset] [-withdummy] [-nodummy] [-compress compress] [-packbits] [-nozero] [-opaque] [-transparent transparent_color] [-nodither] [-forcecolor] [-forcegray] [-forcebinary] [-forcepalettized] [-verbose] [-quiet] [pnmfile]

DESCRIPTION

This program converts one or more PNM images into the Palm Bitmap format. This format is used by the Palm OS. It supports multiple depths and different compressions.

The output is written to standard output. The input is read from standard input if pnmfile is not specified or if it is -.

A Palm Bitmap file can contain multiple versions (renditions) of the same bitmap, each at a different color depth. For example, a Palm OS application might include both a 1-bit monochrome version and a 4-bit grayscale version of an icon. The operating system then selects the version most appropriate for the device's display capabilities.

The optional arguments -width, -height, -depth, and -offset allow you to control the characteristics of the generated Palm Bitmap. If these are not specified, the program infers them from the input PNM image.

-width width -height height: These options set the desired width and height of the resulting Palm Bitmap. If not specified, the width and height of the input image are used.

-depth depth: This option sets the color depth of the resulting Palm Bitmap. The allowed values are 1 (monochrome), 4 (16 grayscale levels), 8 (256 colors), and 16 (65536 colors). If not specified, the depth is inferred from the input image type (e.g., PBM for 1-bit, PGM for 8-bit grayscale, PPM for 24-bit color).

-offset offset: This option is used when creating multiple renditions of the same bitmap within a single Palm Bitmap file. It specifies the byte offset of the rendition within the file. This is typically used to construct multi-rendition Palm Bitmaps by concatenating individual renditions together.

-withdummy: This option is used in conjunction with -offset when creating multi-rendition Palm Bitmaps. It indicates that a dummy rendition should be created, which is useful for ensuring proper alignment and compatibility.

-nodummy: This option is the opposite of -withdummy and does not create a dummy rendition.

-compress compress -packbits: These options specify the compression scheme to use for the Palm Bitmap. The default is no compression. -packbits selects the PackBits compression scheme, which is commonly used in Palm Bitmaps.

-nozero: This option prevents zero values from being compressed when using PackBits compression. This can be useful in certain situations to ensure that zero values are always represented explicitly.

-opaque: This option specifies that the bitmap should be treated as opaque, meaning that transparency information will not be used or generated.

-transparent transparent_color: This option sets a specific color to be treated as transparent. The transparent_color can be specified as a color name or an RGB value.

-nodither: This option disables dithering when converting to lower color depths. This can result in a loss of color detail but may produce sharper images in some cases.

The following options control the color space conversion:

  • -forcecolor: Forces the output to be in color, even if the input is grayscale or monochrome.
  • -forcegray: Forces the output to be in grayscale.
  • -forcebinary: Forces the output to be in 1-bit monochrome.
  • -forcepalettized: Forces the output to use a palette (256 colors).

-verbose: Enables verbose output, providing more information about the conversion process.

-quiet: Suppresses all output except for error messages.

OPTIONS

The following options specify the desired resolution of the bitmap. This resolution is not used by the Palm device itself, but is stored in the bitmap header and is used by applications to determine how the bitmap should be scaled when displayed. The value is proportional to the resolution the image should have when displayed. The proportionality factor is up to whatever is doing the displaying, but it's helpful to think of these numbers as being pixels per inch. The allowable values are:

72
108
144
216
288

This option was new in Netpbm 10.27 (March 2005). Earlier Netpbm could not generate Version 3 Palm Bitmaps, so there was no such thing as density.

NOTES

Palm Bitmaps may contains multiple renditions of the same bitmap, in different depths. To construct an N-multiple-rendition Palm Bitmap with pnmtopalm, first construct renditions 1 through N-1 using the -offset option, then construct the Nth image without the -offset option. Then concatenate the individual renditions together in a single file using cat.

If you will include both high density and low density renditions, put the high density images last and when you create the last of the low density images, use the -withdummy option.

If you specify the Palm packbits compression scheme for a 16-bit direct color bitmap, this program generates an invalid bitmap.
