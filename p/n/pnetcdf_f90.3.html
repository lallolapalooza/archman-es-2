PnetCDF(3f) FUNCIONES DE BIBLIOTECA PnetCDF(3f)

NOMBRE

PnetCDF - Biblioteca paralela para acceder a archivos en formato Network Common Data Form (CDF, CDF-2 y CDF-5)

SINOPSIS

use pnetcdf

La mayoría de los sistemas:

mpif90 ... -lpnetcdf

Sistemas CRAY PVP:

f90 -dp -i64 ... -lpnetcdf

VERSIÓN DE LA BIBLIOTECA

Este documento describe las API de PnetCDF para el lenguaje de programación Fortran-90.

character*80 nf90mpi_inq_libvers()

character(len=80) :: nf90mpi_inq_libvers

Devuelve una cadena que identifica la versión de la biblioteca PnetCDF y cuándo se compiló, por ejemplo: "1.14.1 de 2025-07-31".

El comando RCS ident(1) encontrará una cadena como "$Id: @(#) PnetCDF library version 1.14.1 of 2025-07-31 $" en la biblioteca. El comando SCCS what(1) encontrará una cadena como "PnetCDF library version 1.14.1 of 2025-07-31".

DESCRIPCIÓN DE LAS RUTINAS

Todas las funciones de PnetCDF (excepto nf90mpi_inq_libvers() y nf90mpi_strerror()) devuelven un estado entero. Este comportamiento reemplaza el argumento rcode utilizado en versiones anteriores de la biblioteca. Si este valor de estado devuelto no es igual a nf90_noerr (cero), indica que ocurrió un error. Los posibles valores de estado se definen en el módulo pnetcdf.

function nf90mpi_strerror(ncerr)

integer, intent(in) :: ncerr
character(len=80) :: nf90mpi_strerror

Devuelve una traducción textual en cadena del valor ncerr, como "El nombre del atributo o variable contiene caracteres ilegales" o "No existe tal archivo o directorio".

function nf90mpi_create(comm, path, cmode, info, ncid)

integer, intent(in) :: comm
character(len=*), intent(in) :: path
integer, intent(in) :: cmode
integer, intent(in) :: info
integer, intent(out) :: ncid
integer :: nf90mpi_create

Crea un nuevo conjunto de datos netCDF en path colectivamente por un grupo de procesos MPI especificados por comm, devolviendo un ID de netCDF en ncid. El argumento cmode puede incluir el OR a nivel de bits de las siguientes banderas: nf90_noclobber para proteger conjuntos de datos existentes (el predeterminado es nf90_clobber, que los sobrescribe silenciosamente), nf90_64bit_offset para crear un archivo en formato de desplazamiento de 64 bits (CDF-2), en contraposición al formato clásico, el predeterminado, o nf90_64bit_data para crear un archivo en formato de datos de 64 bits (CDF-5). Utilice nf90_64bit_offset o nf90_64bit_data. El formato de desplazamiento de 64 bits permite la creación de archivos muy grandes con muchas menos restricciones que el formato netCDF clásico, pero solo puede ser leído por la biblioteca netCDF versión 3.6 o superior. Se advierte a los usuarios que los archivos que utilizan el formato de desplazamiento de 64 bits no serán reconocidos por aplicaciones netCDF vinculadas a una versión anterior de la biblioteca netCDF a la 3.6. Las aplicaciones vinculadas a la versión 3.6 o superior podrán acceder de forma transparente tanto al formato clásico como al formato de desplazamiento de 64 bits. El formato de datos de 64 bits permite la creación de variables de matriz muy grandes. Los archivos CDF-5 actualmente no serán reconocidos por la biblioteca netCDF 3 o 4.

El argumento cmode debe ser coherente entre todos los procesos MPI que crean colectivamente el archivo. El argumento info es un objeto MPI info. Los usuarios pueden utilizarlo para proporcionar sugerencias de acceso a archivos para mejorar aún más el rendimiento. Las sugerencias incluyen sugerencias existentes de MPI-IO, así como sugerencias definidas y utilizadas en PnetCDF.

Cuando se crea un conjunto de datos netCDF, se abre en modo nf90_write. Cuando esta función devuelve, el nuevo conjunto de datos netCDF está en modo de definición.

function nf90mpi_open(comm, path, mode, info, ncid)

integer, intent(in) :: comm
character(len=*), intent(in) :: path
integer, intent(in) :: mode
integer, intent(in) :: info

integer :: nf90mpi_open

Abre un conjunto de datos netCDF existente en path colectivamente por un grupo de procesos MPI especificados por comm, devolviendo un ID de netCDF en ncid. El tipo de acceso se describe mediante el parámetro mode, que puede incluir el OR a nivel de bits de las siguientes banderas: nf90_write para acceso de lectura/escritura (predeterminado solo lectura).

El argumento mode debe ser coherente entre todos los procesos MPI que abren colectivamente el archivo. El argumento info es un objeto MPI info. Los usuarios pueden utilizarlo para proporcionar sugerencias de acceso a archivos para mejorar aún más el rendimiento. Las sugerencias incluyen sugerencias existentes de MPI-IO, así como sugerencias definidas y utilizadas en PnetCDF.

Pone un conjunto de datos netCDF abierto en modo de definición, para que se puedan añadir o renombrar dimensiones, variables y atributos, y se puedan eliminar atributos.

function nf90mpi_enddef(ncid)

Después de una llamada exitosa, los datos de las variables pueden ser leídos o escritos en el conjunto de datos.

function nf90mpi_sync(ncid)

integer, intent(in) :: ncid

Los datos escritos por las API de PnetCDF pueden ser cacheados por el sistema de archivos local en cada nodo de cómputo. Esta API vacía los datos cacheados llamando a MPI_File_sync.

function nf90mpi_flush(ncid)

Vacía los datos en el búfer.

function nf90mpi_abort(ncid)

integer, intent(in) :: ncid
integer :: nf90mpi_abort

No necesita llamar a esta función. Esta función es llamada automáticamente por nf90mpi_close() si el conjunto de datos netCDF estaba en modo de definición y algo sale mal con la confirmación. Si el conjunto de datos netCDF no está en modo de definición, entonces esta función es equivalente a nf90mpi_close(). Si se llama después de nf90mpi_redef(), pero antes de nf90mpi_enddef(), las nuevas definiciones no se confirman y el conjunto de datos se cierra. Si se llama después de nf90mpi_create() pero antes de nf90mpi_enddef(), el conjunto de datos desaparece.

function nf90mpi_close(ncid)

integer, intent(in) :: ncid
integer :: nf90mpi_close

Cierra un conjunto de datos netCDF abierto. Si el conjunto de datos está en modo de definición, se llamará a nf90mpi_enddef() antes de cerrar. Después de que un conjunto de datos se cierra, su ID puede ser reasignado a otro conjunto de datos.

function nf90mpi_def_var(ncid, name, xtype, dimids, varid)

integer, intent(in) :: ncid
character(len=*), intent(in) :: name
integer, intent(in) :: xtype
integer, optional, dimension(:), intent(in) :: dimids
integer :: nf90mpi_def_var

Agrega una nueva variable a un conjunto de datos netCDF. El conjunto de datos netCDF debe estar en modo de definición. name será el nombre de la variable netCDF. xtype es el tipo externo de netCDF de la variable y debe ser uno de nf90_byte, nf90_char, nf90_short, nf90_int, nf90_float, o nf90_double para los formatos de archivo CDF-1 y CDF-2. CDF-5 define tipos externos adicionales: nf90_ubyte, nf90_ushort, nf90_uint, nf90_int64, y nf90_uint64. El argumento opcional dimids contiene los IDs de dimensión del dominio de la variable netCDF y, en consecuencia, determina el rango de la variable creada: si dimids se omite, entonces la variable netCDF será escalar; si dimids es escalar, entonces la variable netCDF será 1-dimensional; y si dimids es un vector, entonces la variable netCDF tendrá un rango igual al número de elementos en dimids. varid se establecerá como el ID de la variable netCDF.

VER TAMBIÉN

Los siguientes componentes de PnetCDF son útiles para manejar atributos netCDF:

  • nf90mpi_inquire_attribute(3f): Obtiene información sobre un atributo.
  • nf90mpi_get_att(3f): Lee un atributo.
  • nf90mpi_put_att(3f): Escribe un atributo.
  • nf90mpi_attnames(3f): Obtiene los nombres de todos los atributos asociados con una variable.

Consulte también pnetcdf(3f) para obtener una descripción general de la API de PnetCDF.

DESCRIPCIONES COMUNES DE ARGUMENTOS

En esta sección definimos algunos argumentos comunes que se utilizan en la sección "DESCRIPCIONES DE FUNCIONES".

integer ncid
es el ID de netCDF devuelto por una llamada anterior y exitosa a nf90mpi_open() o nf90mpi_create()
character(len=*) name
es el nombre de una dimensión, variable o atributo. Debe comenzar con un carácter alfabético, seguido de cero o más caracteres alfanuméricos incluyendo el guion bajo (_) o el guion (-). La mayúscula/minúscula es significativa. El número máximo de caracteres permitidos es nf90_max_name. Los nombres que comienzan con un guion bajo (_) están reservados para uso de las interfaces netCDF y PnetCDF.
integer xtype
especifica el tipo de dato externo de una variable o atributo netCDF y es uno de los siguientes: nf90_byte, nf90_char, nf90_short, nf90_int, nf90_float, o nf90_double. Estos se utilizan para especificar enteros de 8 bits, caracteres, enteros de 16 bits, enteros de 32 bits, números de punto flotante de 32 bits IEEE y números de punto flotante de 64 bits IEEE, respectivamente.
integer dimids
es un vector de ID de dimensiones y define la forma de una variable netCDF. El tamaño del vector debe ser mayor o igual al rango (es decir, el número de dimensiones) de la variable (ndims). El vector debe estar ordenado por la velocidad con la que varía una dimensión: dimids(1) debe ser el ID de la dimensión más rápidamente variable y dimids(ndims) debe ser el ID de la dimensión más lentamente variable. El número máximo posible de dimensiones para una variable se proporciona mediante la constante simbólica nf90_max_var_dims.
integer dimid
es el ID de una dimensión netCDF. Los ID de dimensiones netCDF se asignan secuencialmente a partir de los enteros positivos comenzando con 1.
integer ndims
es el número total de dimensiones en un conjunto de datos netCDF o el rango (es decir, el número de dimensiones) de una variable netCDF. El valor no debe ser negativo ni mayor que la constante simbólica nf90_max_var_dims.
integer varid
es el ID de una variable netCDF o (para las funciones de acceso a atributos) la constante simbólica nf90_global, que se utiliza para referenciar atributos globales. Los ID de variables netCDF se asignan secuencialmente a partir de los enteros positivos comenzando con 1.
integer natts
es el número de atributos globales en un conjunto de datos netCDF para la función nf90mpi_inquire() o el número de atributos asociados con una variable netCDF para la función nf90mpi_varinq().
integer(kind=MPI_OFFSET) start
especifica el punto de inicio para acceder a los valores de datos de una variable netCDF en términos de las coordenadas indiciales de la esquina de la sección del arreglo. Los índices comienzan en 1; por lo tanto, el primer valor de dato de una variable es (1, 1, ..., 1). El tamaño del vector debe ser al menos el rango de la variable netCDF asociada y sus elementos deben corresponder, en orden, a las dimensiones de la variable.
integer(kind=MPI_OFFSET) stride
especifica el intervalo de muestreo a lo largo de cada dimensión de la variable netCDF. Los elementos del vector de pasos corresponden, en orden, a las dimensiones de la variable netCDF (stride(1)) proporciona el intervalo de muestreo a lo largo de la dimensión que varía más rápidamente de la variable netCDF). Los intervalos de muestreo se especifican en unidades independientes del tipo de elementos (un valor de 1 selecciona elementos consecutivos de la variable netCDF a lo largo de la dimensión correspondiente, un valor de 2 selecciona cada dos elementos, etc.).
integer(kind=MPI_OFFSET) imap
especifica el mapeo entre las dimensiones de una variable netCDF y la estructura en memoria del arreglo de datos interno. Los elementos del vector de mapeo de índices corresponden, en orden, a las dimensiones de la variable netCDF (imap proporciona la distancia entre elementos del arreglo interno que corresponden a la dimensión que varía más rápidamente de la variable netCDF). Las distancias entre elementos se especifican en unidades independientes del tipo de elementos (la distancia entre elementos internos que ocupan ubicaciones de memoria adyacentes es 1 y no la longitud de bytes del elemento como en netCDF 2).

PRELLENADO DE VARIABLES

Antes de la versión 1.6.1, PnetCDF no admite el llenado de datos. El modo de llenado predeterminado en PnetCDF es NF90_NOFILL. Esto es contrario a la biblioteca netCDF, cuyo predeterminado es NF90_FILL. Cuando el modo de llenado está habilitado, PnetCDF establece los valores de todas las variables recién definidas de longitud finita (es decir, aquellas que no tienen una dimensión ilimitada) al valor de llenado dependiente del tipo asociado con cada variable. Esto se hace cuando se llama a nf90mpi_enddef(). El valor de llenado de una variable puede cambiarse del valor predeterminado definiendo el atributo _FillValue para la variable. Este atributo debe tener el mismo tipo que la variable y ser de longitud uno.

Las variables con una dimensión ilimitada no se rellenan en PnetCDF. Esto también es contrario a netCDF, que sí rellena las variables de registro. En PnetCDF, el llenado de una variable de registro debe hacerse llamando a nf90mpi_fill_var_rec(). Tenga en cuenta que esto solo rellena un registro de una variable.

El modo de llenado para todo el archivo se puede establecer mediante nf90mpi_set_fill(). La configuración del modo de llenado por variable también está disponible a través de nf90mpi_def_var_fill(). En PnetCDF, cambiar el modo de llenado debe hacerse en modo de definición. En netCDF, esto solo es cierto para variables de tamaño fijo. Para variables de registro, el cambio del modo de llenado se puede realizar en cualquier momento en netCDF.
