PnetCDF(3) FUNCIONES DE BIBLIOTECA PnetCDF(3)

NOMBRE

PnetCDF - Biblioteca paralela para acceder a archivos en formatos Network Common Data Form (CDF, CDF-2 y CDF-5)

SINOPSIS

#include <pnetcdf.h>

mpicc ... -lpnetcdf

La documentación completa de las bibliotecas PnetCDF se puede encontrar en el sitio web de PnetCDF: http://cucis.ece.northwestern.edu/projects/PnetCDF/.

VERSIÓN DE LA BIBLIOTECA

Este documento describe las APIs de PnetCDF para el lenguaje de programación C.

const char* ncmpi_inq_libvers()

(Corresponde a nc_inq_libvers() en netCDF)

Devuelve una cadena que identifica la versión de la biblioteca PnetCDF y cuándo se compiló, por ejemplo: "1.14.1 de 2025-07-31".

El comando RCS ident(1) encontrará una cadena como "$Id: @(#) PnetCDF library version 1.14.1 of 2025-07-31 $" en la biblioteca. El comando SCCS what(1) encontrará una cadena como "PnetCDF library version 1.14.1 of 2025-07-31".

VALORES DE RETORNO

Todas las funciones PnetCDF (excepto ncmpi_inq_libvers() y ncmpi_strerror()) devuelven un estado entero.

Si este valor de estado devuelto no es igual a NC_NOERR (cero), indica que ocurrió un error. Los posibles valores de estado se definen en el archivo de inclusión del sistema <errno.h> y en "pnetcdf.h".

const char* ncmpi_strerror(int status)

(Corresponde a nc_strerror() en netCDF)

Devuelve una traducción textual en cadena del valor status, como "El nombre del atributo o variable contiene caracteres ilegales" o "No existe tal archivo o directorio".

OPERACIONES DE ARCHIVO

int ncmpi_create(MPI_Comm comm, const char path[], int cmode, MPI_Info info, int* ncid)

(Corresponde a nc_create() en netCDF)

Crea un nuevo conjunto de datos netCDF en path de forma colectiva por un grupo de procesos MPI especificados por comm, devolviendo un ID de netCDF en ncid. El argumento cmode puede incluir el OR a nivel de bits de las siguientes banderas: NC_NOCLOBBER para proteger conjuntos de datos existentes (el valor por defecto es NC_CLOBBER, que los elimina silenciosamente), NC_64BIT_OFFSET para crear un archivo en formato de desplazamiento de 64 bits (CDF-2), en contraposición al formato clásico, el valor por defecto, o NC_64BIT_DATA para crear un archivo en formato de datos de 64 bits (CDF-5). Utilice NC_64BIT_OFFSET o NC_64BIT_DATA. El formato de desplazamiento de 64 bits permite la creación de conjuntos de datos netCDF muy grandes con muchas menos restricciones que el formato clásico, pero solo puede ser leído por la biblioteca netCDF versión 3.6 o superior. Se advierte a los usuarios que los archivos que utilizan el formato de desplazamiento de 64 bits no serán reconocidos por aplicaciones netCDF enlazadas a una versión anterior a la biblioteca netCDF 3.6. Las aplicaciones enlazadas a la versión 3.6 o posterior podrán acceder de forma transparente a ambos formatos, el clásico o el de desplazamiento de 64 bits. El formato de datos de 64 bits permite la creación de variables de matriz muy grandes. Actualmente, los archivos CDF-5 no serán reconocidos por las bibliotecas netCDF 3 o 4.

El argumento cmode debe ser consistente entre todos los procesos MPI que crean colectivamente el archivo. El argumento info es un objeto MPI info. Los usuarios pueden usarlo para proporcionar pistas de acceso a archivos para una mayor mejora del rendimiento. Las pistas incluyen pistas existentes de MPI-IO, así como pistas definidas y utilizadas en PnetCDF.

Cuando se crea un conjunto de datos netCDF, se abre en modo NC_WRITE. Al regresar de esta función, el nuevo conjunto de datos netCDF está en modo de definición.

int ncmpi_open(MPI_Comm comm, const char path[], int mode, MPI_Info info, int* ncid)

(Corresponde a nc_open() en netCDF)

Abre un conjunto de datos netCDF existente en path de forma colectiva por un grupo de procesos MPI especificados por comm, devolviendo un ID de netCDF en ncid. El tipo de acceso se describe mediante el parámetro mode, que puede incluir el OR a nivel de bits de las siguientes banderas: NC_WRITE para acceso de lectura/escritura (por defecto solo lectura).

El argumento mode debe ser consistente entre todos los procesos MPI que abren colectivamente el archivo. El argumento info es un objeto MPI info. Los usuarios pueden usarlo para proporcionar pistas de acceso a archivos para una mayor mejora del rendimiento. Las pistas incluyen pistas existentes de MPI-IO, así como pistas definidas y utilizadas en PnetCDF.

int ncmpi_redef(int ncid)

(Corresponde a nc_redef() en netCDF)

Pone un conjunto de datos netCDF abierto en modo de definición, de modo que se puedan añadir o renombrar dimensiones, variables y atributos, y se puedan eliminar atributos.

int ncmpi_enddef(int ncid)

(Corresponde a nc_enddef() en netCDF)

Saca un conjunto de datos netCDF abierto del modo de definición. Los cambios realizados en el conjunto de datos netCDF mientras estaba en modo de definición se comprueban y se confirman en el disco si no ocurrieron problemas. Después de una llamada exitosa, los datos de las variables pueden ser leídos o escritos en el conjunto de datos.

int ncmpi_sync(int ncid)

(Corresponde a nc_sync() en netCDF)

Los datos escritos por las APIs de PnetCDF pueden ser cacheados por el sistema de archivos local en cada nodo de cálculo. Esta API vacía los datos cacheados llamando a MPI_File_sync.

int ncmpi_abort(int ncid)

(Corresponde a nc_abort() en netCDF)

No es necesario llamar a esta función. Esta función es llamada automáticamente por ncmpi_close() si el netCDF estaba en modo de definición y algo sale mal con la confirmación. Si el conjunto de datos netCDF no está en modo de definición, entonces esta función es equivalente a ncmpi_close(). Si se llama después de ncmpi_redef(), pero antes de ncmpi_enddef(), las nuevas definiciones no se confirman y el conjunto de datos se cierra. Si se llama después de ncmpi_create() pero antes de ncmpi_enddef(), el conjunto de datos desaparece.

int ncmpi_close(int ncid)

(Corresponde a nc_close() en netCDF)

Cierra un conjunto de datos netCDF abierto. Si el conjunto de datos está en modo de definición, se llamará a ncmpi_enddef() antes de cerrar. Después de que un conjunto de datos se cierra, su ID puede ser reutilizado para otro conjunto de datos.

int ncmpi_inq_format(int ncid, int* formatn)

(Corresponde a nc_inq_format() en netCDF)

Utilice estas funciones para averiguar qué hay en un conjunto de datos netCDF. Tras una ejecución exitosa, ndims contendrá el número de dimensiones definidas para este conjunto de datos netCDF, nvars contendrá el número de variables, natts contendrá el número de atributos, y unlimdimid contendrá el ID de la dimensión ilimitada si existe, o -1 en caso contrario. formatn contendrá el número de versión del conjunto de datos <formato>, uno de NC_FORMAT_CLASSIC, NC_FORMAT_64BIT, o NC_FORMAT_64BIT_DATA. Si alguno de los parámetros de retorno es un puntero NULL, entonces la información correspondiente no se devolverá; por lo tanto, no es necesario asignar espacio para ella.

int ncmpi_inq_dimlen(int ncid, int dimid, MPI_Offset* len)

(Corresponds to nc_inq_dimlen() in netCDF)

Use these functions to find out about a dimension. If either the name argument or len argument is a NULL pointer, then the associated information will not be returned. Otherwise, name should be big enough (NC_MAX_NAME) to hold the dimension name as the name will be copied into your storage. The length return parameter, len will contain the size of the dimension. For the unlimited dimension, the returned length is the current maximum value used for writing into any of the variables which use the dimension.

int ncmpi_rename_dim(int ncid, int dimid, const char name[])

(Corresponds to nc_rename_dim() in netCDF)

Renames an existing dimension in an open netCDF dataset. If the new name is longer than the old name, the netCDF dataset must be in define mode. You cannot rename a dimension to have the same name as another dimension.

VARIABLES

int ncmpi_def_var(int ncid, const char name[], nc_type xtype, int ndims, const int dimids[], int* varid)

(Corresponds to nc_def_var() in netCDF)

Adds a new variable to a netCDF dataset. The netCDF must be in define mode. If not NULL, then varid will be set to the netCDF variable ID. ndims will be the number of dimensions for the variable. name will be the name of the netCDF variable. xtype is the external, netCDF type of the variable and should be one of NC_BYTE NC_CHAR, NC_SHORT, NC_INT, NC_FLOAT, or NC_DOUBLE, for CDF-1 and CDF-2 file formats. CDF-5 defines additional external types: NC_UBYTE, NC_USHORT, NC_UINT, NC_INT64, and NC_UINT64. dimids argument is a vector of ndims dimension IDs corresponding to the variable dimensions.

int ncmpi_inq_varid(int ncid, const char name[], int* varid)

DESCRIPCIONES DE ARGUMENTOS COMUNES

ncid: El identificador del dataset netCDF.

varid: El identificador de la variable.

index: Un array de índices que especifica la posición de un único valor de datos dentro de una variable multidimensional. El número de elementos en este array debe ser igual al número de dimensiones de la variable.

start: Un array de índices que especifica el punto de inicio de una sección de datos dentro de una variable multidimensional. El número de elementos en este array debe ser igual al número de dimensiones de la variable.

count: Un array que especifica el número de valores a leer o escribir a lo largo de cada dimensión, comenzando en la posición start. El número de elementos en este array debe ser igual al número de dimensiones de la variable.

stride: Un array que especifica el paso de muestreo para cada dimensión. Por ejemplo, un paso de 1 accede a cada elemento, un paso de 2 accede a cada segundo elemento, etc. El número de elementos en este array debe ser igual al número de dimensiones de la variable.

out: Un puntero al buffer que contiene los datos que se van a escribir en la variable netCDF.

in: Un puntero al buffer donde se almacenarán los datos leídos de la variable netCDF.

Estos punteros se refieren a arrays de tipos de datos básicos (char, uchar, schar, short, int, long, float, double).

Todos los índices de las dimensiones se basan en cero.

Las funciones de escritura (con prefijo put_) no son explícitamente paralelizables. Es decir, si varios procesos intentan escribir en la misma variable netCDF simultáneamente, solo se garantiza el resultado si la operación de escritura es atómica (por ejemplo, escribir un solo elemento) o si todos los procesos escriben en partes no superpuestas de la variable.

Las funciones de lectura (con prefijo get_) son explícitamente paralelizables. Es decir, si varios procesos intentan leer de la misma variable netCDF simultáneamente, todos los procesos leerán los mismos datos.

Las funciones con el sufijo _text son para datos de tipo carácter.

Las funciones con el sufijo _uchar son para datos de tipo carácter sin signo.

Las funciones con el sufijo _schar son para datos de tipo carácter con signo.

Las funciones con el sufijo _short son para datos de tipo entero corto.

Las funciones con el sufijo _int son para datos de tipo entero.

Las funciones con el sufijo _long son para datos de tipo entero largo.

Las funciones con el sufijo _float son para datos de tipo punto flotante.

Las funciones con el sufijo _double son para datos de tipo doble precisión.

Para las funciones que operan en arrays (por ejemplo, put_vara_*, get_vara_*, put_vars_*, get_vars_*, put_var_*, get_var_*), la cantidad de datos especificada por los argumentos count (para *_vara_* y *_vars_*) o implícita por el tamaño de la variable (para *_var_*) debe ser consistente con las dimensiones de la variable. Si no lo es, se devolverá un error NC_EINVAL.

En el caso de operaciones de escritura con paso (put_vars_*) y lectura con paso (get_vars_*), si el vector stride contiene un cero, se producirá un error NC_EINVAL.

COMMON ARGUMENT DESCRIPTIONS

In this section we define some common arguments which are used in the "FUNCTION DESCRIPTIONS" section.

int ncid
is the netCDF ID returned from a previous, successful call to ncmpi_open() or ncmpi_create()
char name[]
is the name of a dimension, variable, or attribute. The names of dimensions, variables and attributes consist of arbitrary sequences of alphanumeric characters (as well as underscore '_', period '.' and hyphen '-'), beginning with a letter or underscore. (However names commencing with underscore are reserved for system use.) Case is significant in netCDF names. A zero-length name is not allowed. As an input argument, it shall be a pointer to a 0-terminated string; as an output argument, it shall be the address of a buffer in which to hold such a string. The maximum allowable number of characters (excluding the terminating 0) is NC_MAX_NAME.
nc_type xtype

es el ID de una variable netCDF o (para las funciones de acceso a atributos) la constante simbólica NC_GLOBAL, que se utiliza para hacer referencia a atributos globales. Los ID de variables netCDF se asignan secuencialmente a partir de los enteros no negativos, comenzando por 0.

es el número de atributos globales en un conjunto de datos netCDF para la función ncmpi_inquire() o el número de atributos asociados a una variable netCDF para la función ncmpi_varinq().
const MPI_Offset index[]
especifica las coordenadas del valor de datos netCDF que se va a acceder. Los índices comienzan en 0; por lo tanto, por ejemplo, el primer valor de datos de una variable bidimensional es (0,0). El tamaño del vector debe ser al menos el rango de la variable netCDF asociada y sus elementos deben corresponder, en orden, a las dimensiones de la variable.
const MPI_Offset start[]
especifica el punto de inicio para acceder a los valores de datos de una variable netCDF en términos de las coordenadas indiciales de la esquina de la sección del array. Los índices comienzan en 0; por lo tanto, el primer valor de datos de una variable es (0, 0, ..., 0). El tamaño del vector debe ser al menos el rango de la variable netCDF asociada y sus elementos deben corresponder, en orden, a las dimensiones de la variable.
const MPI_Offset count[]
especifica el número de índices seleccionados a lo largo de cada dimensión de la sección del array. Por lo tanto, para acceder a un único valor, por ejemplo, especifique count como (1, 1, ..., 1). Tenga en cuenta que, para E/S de paso (strided I/O), este argumento debe ajustarse para ser compatible con los argumentos stride y start de modo que la interacción de los tres no intente acceder a una coordenada de datos inválida. Los elementos del vector count corresponden, en orden, a las dimensiones de la variable.
const MPI_Offset stride[]
especifica el intervalo de muestreo a lo largo de cada dimensión de la variable netCDF. Los elementos del vector de paso corresponden, en orden, a las dimensiones de la variable netCDF (stride[0] da el intervalo de muestreo a lo largo de la dimensión que varía más lentamente de la variable netCDF). Los intervalos de muestreo se especifican en unidades de elementos independientes del tipo (un valor de 1 selecciona elementos consecutivos de la variable netCDF a lo largo de la dimensión correspondiente, un valor de 2 selecciona cada dos elementos, etc.). Un argumento de paso NULL se trata como (1, 1, ... , 1).
const MPI_Offset imap[]
especifica la correspondencia entre las dimensiones de una variable netCDF y la estructura en memoria del array de datos interno. Los elementos del vector de mapeo de índices corresponden, en orden, a las dimensiones de la variable netCDF (imap[0] da la distancia entre elementos del array interno que corresponden a la dimensión que varía más lentamente de la variable netCDF). Las distancias entre elementos se especifican en unidades de elementos independientes del tipo (la distancia entre elementos internos que ocupan ubicaciones de memoria adyacentes es 1 y no la longitud de bytes del elemento como en netCDF 2). Un puntero NULL significa que los valores residentes en memoria tienen la misma estructura que la variable netCDF asociada.

PRELLENADO DE VARIABLES

Antes de la versión 1.6.1, PnetCDF no admite el prellenado de datos. El modo de prellenado predeterminado en PnetCDF es NC_NOFILL. Esto es contrario a la biblioteca netCDF, cuyo valor predeterminado es NC_FILL. Cuando el modo de prellenado está habilitado, PnetCDF establece los valores de todas las variables recién definidas de longitud finita (es decir, aquellas que no tienen una dimensión ilimitada) al valor de prellenado dependiente del tipo asociado a cada variable. Esto se hace cuando se llama a ncmpi_enddef(). El valor de prellenado de una variable se puede cambiar del valor predeterminado definiendo el atributo `_FillValue' para la variable. Este atributo debe tener el mismo tipo que la variable y ser de longitud uno.

Las variables con una dimensión ilimitada no se prellenan en PnetCDF. Esto también es contrario a netCDF, que sí prellena las variables de registro. En PnetCDF, el prellenado de una variable de registro debe hacerse llamando a ncmpi_fill_var_rec(). Tenga en cuenta que esto solo llena un registro de una variable.

El modo de prellenado para todo el archivo se puede establecer mediante ncmpi_set_fill(). El modo de prellenado por variable también está disponible a través de ncmpi_def_var_fill(). En PnetCDF, cambiar el modo de prellenado debe hacerse en modo de definición. En netCDF, esto es cierto solo para variables de tamaño fijo. Para variables de registro, cambiar el modo de prellenado se puede hacer en cualquier momento en NetCDF.
