NOMBRE

pnmtojpeg - convertir imagen PNM a imagen JFIF ('JPEG')

SINOPSIS

pnmtojpeg [-exif=archivoespec] [-calidad=n] [{-escala_grises|-escala_grises}] [-densidad=nxn[dpi,dpcm]] [-optimizar|-optimise] [-rgb] [-progresivo] [-comentario=texto] [-dct={int|fast|float}] [-aritmetico] [-restart=n] [-suavizar=n] [-memoriamaX=n] [-verboso] [-linea_base] [-tablasqt=archivoespec] [-ranurasqt=n[,...]] [-muestra=HxV[,...]] [-escaneos=archivoespec] [-nivelrastreo=N]

nombrearchivo

La abreviatura única mínima de la opción es aceptable. Puede usar guiones dobles en lugar de guiones simples para indicar opciones. Puede usar espacios en blanco en lugar del signo igual para separar un nombre de opción de su valor.

DESCRIPCIÓN

Este programa es parte de Netpbm(1)

pnmtojpeg convierte el archivo de imagen PBM, PGM o PPM nombrado, o la entrada estándar si no se nombra ningún archivo, a un archivo JFIF en la salida estándar.

pnmtojpeg utiliza la biblioteca JPEG del Independent JPEG Group para crear el archivo de salida. Consulte http://www.ijg.org para obtener información sobre la biblioteca.

'JFIF' es el nombre correcto para el formato de imagen comúnmente conocido como 'JPEG'. Estrictamente hablando, JPEG es un método de compresión. El formato de imagen que utiliza compresión JPEG y que es, con diferencia, el más común es JFIF. También existe un subformato de TIFF que utiliza compresión JPEG.

EXIF es un formato de imagen que es un subformato de JFIF (a saber, un archivo JFIF que contiene una cabecera EXIF como marcador APP1). pnmtojpeg crea una imagen EXIF cuando se especifica la opción -exif.

OPCIONES

Las opciones básicas son:

-exif=archivoespec
Esta opción especifica que la imagen de salida será EXIF (un subformato de JFIF), es decir, tendrá una cabecera EXIF como marcador APP1 de JFIF. El contenido de ese marcador es el contenido del archivo especificado. El valor especial - significa que se leerá el contenido de la cabecera EXIF de la entrada estándar. Es inválido especificar la entrada estándar tanto para la cabecera EXIF como para la imagen de entrada.

El archivo EXIF comienza con un campo de dos bytes que es la longitud del archivo, incluyendo el campo de longitud, en binario puro, byte más significativo primero. El valor especial cero para el campo de longitud significa que no habrá cabecera EXIF, es decir, lo mismo que no usar la opción -exif. Esto es útil cuando se convierte un archivo de JFIF a PNM usando jpegtopnm, luego se transforma, luego se vuelve a convertir a JFIF con pnmtojpeg, y no se sabe si incluye o no una cabecera EXIF. jpegtopnm crea un archivo EXIF que contiene solo dos bytes de cero cuando el archivo JFIF de entrada no tiene cabecera EXIF. Por lo tanto, puede transferir cualquier cabecera EXIF del JFIF de entrada al JFIF de salida sin preocuparse de si existe realmente una cabecera EXIF.

El contenido del archivo EXIF después del campo de longitud son los bytes exactos, byte por byte, del marcador APP1, sin contar el campo de longitud, que constituye la cabecera EXIF.

-calidad=n
Escala las tablas de cuantificación para ajustar la calidad de la imagen. n es de 0 (peor) a 100 (mejor); por defecto es 75. Por debajo de 25, se pueden producir imágenes que algunos intérpretes no podrán interpretar. Ver más abajo para más información.
-escala_grises
-escala_grises
-rgb
Estas opciones determinan el espacio de color utilizado en la salida JFIF. -escala_grises (o -escala_grises) significa crear un JFIF en escala de grises, convirtiendo desde una entrada PPM a color si es necesario. -rgb significa crear un JFIF RGB, y el programa falla si la entrada no es PPM.

Si no especifica ninguna, el archivo de salida estará en formato YCbCr si la entrada es PPM, y en formato de escala de grises si la entrada es PBM o PGM.

El formato YCbCr (un color se representa por un valor de intensidad y dos valores de crominancia) generalmente se comprime mucho mejor que RGB (un color se representa por un rojo, un verde y un azul). RGB es raro. Pero puede que pueda convertir entre JFIF y PPM más rápido con RGB, ya que es el mismo espacio de color que utiliza PPM.

El archivo testimg.ppm que viene con Netpbm es 2.3 veces más grande con la opción -rgb que con el valor predeterminado YCbCr, y en un experimento pnmtojpeg tardó un 16% más de tiempo de CPU en convertirlo. El tiempo adicional de CPU probablemente indica que el procesamiento de todos los datos comprimidos adicionales consumió todo el tiempo de CPU ahorrado al no tener que convertir las entradas RGB a YCbCr.

El formato de escala de grises ocupa mucho menos espacio y tarda menos en crearse y procesarse que los formatos de color, incluso si la imagen contiene solo negro, blanco y gris.

La opción -rgb se añadió en Netpbm 10.11 en octubre de 2002.

-densidad=densidad
Esta opción determina la información de densidad (también conocida como resolución) registrada en la imagen de salida JFIF. No afecta al raster en absoluto; solo le dice a quien lea el JFIF cómo interpretar el raster.

El valor de densidad tiene el formato xxy seguido de un especificador de unidad opcional de dpi (puntos por pulgada) o dpcm (puntos por centímetro). Ejemplos: 1x1, 3x2, 300x300dpi, 100x200dpcm. El primer número es la densidad horizontal; el segundo número es la densidad vertical. Cada uno puede ser cualquier entero de 1 a 65535. El especificador de unidad es dpi para puntos por pulgada o dpcm para puntos por centímetro. Si no especifica las unidades, la información de densidad se incluye en el JFIF declarando explícitamente "densidad no especificada" (también interpretado como "desconocido"). Esto puede parecer inútil, pero tenga en cuenta que incluso sin especificar las unidades, los números de densidad indican la relación de aspecto de los píxeles. Por ejemplo, 1x1 le indica que los píxeles son cuadrados. 3x2 le indica que los píxeles son rectángulos verticales.

Tenga en cuenta que si especifica densidades horizontal y vertical diferentes, la imagen JFIF resultante *no* es una representación fiel de la imagen PNM de entrada, porque pnmtojpeg convierte el raster píxel a píxel y los píxeles de una imagen PNM se definen como cuadrados. Por lo tanto, si comienza con una imagen PNM cuadrada y especifica -densidad=3x2, la imagen JFIF resultante es una versión horizontalmente aplastada de la original. Sin embargo, es común utilizar una imagen de entrada que sea una ligera variación de PNM en lugar de PNM verdadero, de modo que los píxeles no sean cuadrados. En ese caso, la opción -densidad apropiada produce una reproducción fiel de la imagen pseudo-PNM de entrada.

El valor predeterminado es 1x1 en unidades no especificadas.

Antes de Netpbm 10.15 (abril de 2003), esta opción no existía y pnmtojpeg siempre creaba un JFIF con una densidad de 1x1 en unidades no especificadas.

-optimizar

Realiza la optimización de los parámetros de codificación de entropía. Sin esto, pnmtojpeg utiliza parámetros de codificación predeterminados. -optimizar generalmente hace que el archivo JFIF sea un poco más pequeño, pero pnmtojpeg se ejecuta algo más lento y necesita mucha más memoria. La calidad de la imagen y la velocidad de descompresión no se ven afectadas por -optimizar.
-progresivo
Crea un archivo JPEG progresivo (ver más abajo).
-comentario=texto
Incluye un marcador de comentario en la salida JFIF, con el texto del comentario texto.

Sin esta opción, no hay marcadores de comentario en la salida.

La opción -calidad le permite intercambiar el tamaño del archivo comprimido contra la calidad de la imagen reconstruida: cuanto mayor sea la configuración de calidad, mayor será el archivo JFIF y más se parecerá la imagen de salida a la entrada original. Normalmente querrá usar la configuración de calidad más baja (archivo más pequeño) que la descompresión

Para este propósito, el ajuste de calidad debe estar entre 50 y 95 para obtener resultados razonables; el valor predeterminado de 75 suele ser el adecuado. Si observa defectos con -quality=75, aumente el valor en 5 o 10 puntos a la vez hasta que esté satisfecho con la imagen resultante. (El ajuste óptimo variará de una imagen a otra).

-quality=100 genera una tabla de cuantización de unos, minimizando la pérdida en el paso de cuantización (pero todavía hay pérdida de información en el submuestreo, así como error de redondeo). Esta configuración es principalmente de interés para fines experimentales. Los valores de calidad superiores a aproximadamente 95 *no* se recomiendan para uso normal; el tamaño del archivo comprimido aumenta drásticamente por apenas una ganancia en la calidad de la imagen de salida.

En la otra dirección, los valores de calidad inferiores a 50 producirán archivos muy pequeños de baja calidad de imagen. Los ajustes alrededor de 5 a 10 podrían ser útiles, por ejemplo, para preparar un índice de una gran biblioteca de imágenes. Pruebe -quality=2 (o similar) para obtener algunos efectos cubistas divertidos. (Nota: los valores de calidad inferiores a aproximadamente 25 generan tablas de cuantización de 2 bytes, que se consideran opcionales en el estándar JFIF. pnmtojpeg emite un mensaje de advertencia cuando se proporciona dicho valor de calidad, ya que algunos otros programas JFIF pueden no poder decodificar el archivo resultante. Utilice -baseline si necesita garantizar la compatibilidad con valores de baja calidad).

La opción -progressive crea un archivo 'JPEG progresivo'. En este tipo de archivo JFIF, los datos se almacenan en múltiples exploraciones de calidad creciente. Si el archivo se está transmitiendo a través de un enlace de comunicación lento, el decodificador puede usar la primera exploración para mostrar una imagen de baja calidad muy rápidamente, y luego puede mejorar la visualización con cada exploración subsiguiente. La imagen final es exactamente equivalente a un archivo JFIF estándar con la misma configuración de calidad, y el tamaño total del archivo es aproximadamente el mismo, a menudo un poco menor.

Precaución: JPEG progresivo aún no está ampliamente implementado, por lo que muchos decodificadores no podrán ver un archivo JPEG progresivo en absoluto.

Si intenta controlar la compensación calidad/tamaño de archivo, puede considerar el formato JPEG2000 en su lugar. Consulte pamtojpeg2k(1)

Opciones para usuarios avanzados:

-dct=int
Utiliza el método DCT entero (predeterminado).
-dct=fast
Utiliza DCT entero rápido (menos preciso).
-dct=float
Utiliza el método DCT de punto flotante. El método de punto flotante es muy ligeramente más preciso que el método entero, pero es mucho más lento a menos que su máquina tenga hardware de punto flotante muy rápido. Tenga en cuenta también que los resultados del método de punto flotante pueden variar ligeramente entre máquinas, mientras que los métodos enteros deberían dar los mismos resultados en todas partes. El método entero rápido es mucho menos preciso que los otros dos.
-arithmetic
Utiliza codificación aritmética. El valor predeterminado es codificación Huffman. La codificación aritmética tiende a producir un resultado más pequeño.

Puede necesitar licencias de patente para usar esta opción. Según el FAQ de JPEG, este método está cubierto por patentes propiedad de IBM, AT&T y Mitsubishi.

El autor del FAQ desaconseja el uso de codificación aritmética (y, por lo tanto, esta opción) porque el ahorro de espacio no es lo suficientemente grande como para justificar los problemas legales.

La mayoría de las bibliotecas JPEG, incluidas las distribuidas por el Independent JPEG Group desde aproximadamente 1998, no son capaces de codificación aritmética. pnmtojpeg utiliza una biblioteca JPEG (vinculada a ella cuando se compiló el ejecutable pnmtojpeg o accesible en su sistema en tiempo de ejecución) para realizar la codificación JPEG. Si pnmtojpeg finaliza con el mensaje, 'Sorry, there are legal restrictions on arithmetic coding' o 'Sorry, arithmetic coding not supported', este es el problema.

-restart=n
Emite un marcador de reinicio JPEG cada n filas de MCU, o cada n bloques de MCU si se añade B al número. -restart 0 (el valor predeterminado) significa sin marcadores de reinicio.
-smooth=n
Suaviza la imagen de entrada para eliminar el ruido de tramado. n, que varía de 1 a 100, indica la fuerza del suavizado. 0 (predeterminado) significa sin suavizado.
-maxmemory=n
Establece un límite para la cantidad de memoria a utilizar en el procesamiento de imágenes grandes. El valor está en miles de bytes, o millones de bytes si se añade M al número. Por ejemplo, -max=4m selecciona 4.000.000 de bytes. Si pnmtojpeg necesita más espacio, utilizará archivos temporales.
-verbose
Imprime en el archivo de error estándar mensajes sobre el proceso de conversión. Esto puede ser útil para depurar problemas.

La opción -restart indica a pnmtojpeg que inserte marcadores adicionales que permitan a un decodificador JPEG resincronizarse después de un error de transmisión. Sin marcadores de reinicio, cualquier daño en un archivo comprimido generalmente arruinará la imagen desde el punto del error hasta el final de la imagen; con marcadores de reinicio, el daño generalmente se limita a la porción de la imagen hasta el siguiente marcador de reinicio. Por supuesto, los marcadores de reinicio ocupan espacio adicional. Recomendamos -restart=1 para imágenes que se transmitirán a través de redes poco fiables como Usenet.

La opción -smooth filtra la entrada para eliminar el ruido de alta frecuencia. Esto es a menudo útil al convertir imágenes tramadas a JFIF: un factor de suavizado moderado de 10 a 50 elimina los patrones de tramado en el archivo de entrada, lo que resulta en un archivo JFIF más pequeño y una imagen de mejor aspecto. Sin embargo, un factor de suavizado demasiado grande difuminará visiblemente la imagen.

Opciones para magos:

-baseline
Forzar la generación de tablas de cuantización compatibles con la línea base. Esto limita los valores de cuantización a 8 bits incluso en configuraciones de baja calidad. (Este modificador tiene un nombre inadecuado, ya que no garantiza que la salida sea realmente JPEG de línea base. Por ejemplo, puede usar -baseline y -progressive juntos.)
-qtables=especificación_archivo
Utiliza las tablas de cuantización dadas en el archivo de texto especificado.
-qslots=n[,...]
Selecciona qué tabla de cuantización utilizar para cada componente de color.
-sample=HxV[,...]
Establece los factores de muestreo JPEG para cada componente de color.
-scans=especificación_archivo
Utiliza el script de escaneo dado en el archivo de texto especificado. Consulte a continuación la información sobre scripts de escaneo.
-tracelevel=N
Establece el nivel de rastreo de depuración que el programa emite mientras se ejecuta. 0 significa ninguno, y es el valor predeterminado. Este nivel controla principalmente el rastreo de la biblioteca JPEG, y puede obtener información bastante interesante sobre el proceso de compresión.

Las opciones de 'mago' están destinadas a la experimentación con JPEG. Si no sabe lo que está haciendo, *no las use*. Estos modificadores se documentan con más detalle en el archivo wizard.doc que viene con la biblioteca JPEG del Independent JPEG Group.

EJEMPLOS

Este ejemplo comprime el archivo PPM foo.ppm con un factor de calidad de 60 y guarda la salida como foo.jpg:

    pnmtojpeg -quality=60 foo.ppm > foo.jpg

Aquí hay un ejemplo más típico. Convierte de BMP a JFIF:

    cat foo.bmp | bmptoppm | pnmtojpeg > foo.jpg

Pérdida JPEG

Cuando comprimes con JPEG, pierdes información, es decir, la imagen resultante tiene una calidad algo menor que la original. Esta es una característica de JPEG en sí, no de ningún programa en particular. Por lo tanto, si haces lo habitual con Netpbm y conviertes de JFIF a PNM, manipulas y luego conviertes de nuevo a JFIF, perderás calidad. Cuanto más lo hagas, más perderás. Los dibujos (gráficos, caricaturas, dibujos lineales y similares con pocos colores y bordes afilados) sufren más.

Para evitar esto, puedes usar un formato de imagen comprimido distinto de JPEG. PNG y JPEG2000 son buenas opciones, y Netpbm contiene convertidores para ellos.

Si necesitas usar JFIF en un dibujo, deberías experimentar con las opciones -quality y -smooth de pnmtojpeg para obtener una conversión satisfactoria. -smooth 10 o similar suele ser útil.

Debido a la pérdida, deberías hacer toda la manipulación que tengas que hacer en la imagen en algún otro formato y convertir a JFIF como último paso. Y si puedes conservar una copia en el formato original, mucho mejor.

La opción -optimize de pnmtojpeg vale la pena usarla cuando estás creando una versión 'final' para publicación o archivo. También es beneficiosa cuando se utilizan configuraciones de baja calidad para crear archivos JFIF muy pequeños; la mejora porcentual suele ser mucho mayor que en archivos más grandes. (Actualmente, el modo -optimize está automáticamente activo cuando se genera un archivo JPEG progresivo).

Puedes realizar transformaciones de volteo y rotación sin pérdida con el programa jpegtran, que se distribuye con la biblioteca JPEG del Independent Jpeg Group. jpegtran ejerce su conocimiento íntimo de la forma en que funciona JPEG para realizar la transformación sin descomprimir realmente la imagen.

Otro programa, cjpeg, es similar. cjpeg es mantenido por el Independent JPEG Group y se distribuye con la biblioteca JPEG que pnmtojpeg utiliza para todo su trabajo de JPEG. Debido a eso, puedes esperar que explote características JPEG más actuales. Además, dado que debes tener la biblioteca para ejecutar pnmtojpeg, pero no viceversa, cjpeg puede estar más comúnmente disponible.

Por otro lado, cjpeg no utiliza las bibliotecas NetPBM para procesar su entrada, como lo hacen todas las herramientas NetPBM como pnmtojpeg. Esto significa que es menos probable que sea coherente con todos los demás programas que manejan los formatos NetPBM. Además, la sintaxis de comandos de pnmtojpeg es coherente con la de las otras herramientas Netpbm, a diferencia de cjpeg.

SCAN SCRIPTS

Use the -scan option to specify a scan script. Or use the -progressive option to specify a particular built-in scan script.

Just what a scan script is, and the basic format of the scan script file, is covered in the wizard.doc file that comes with the Independent JPEG Group's JPEG library. Scan scripts are same for pnmtojpeg as the are for cjpeg.

This section contains additional information that isn't, but probably should be, in that document.

First, there are many restrictions on what is a valid scan script. The JPEG library, and thus pnmtojpeg, checks thoroughly for any lack of compliance with these restrictions, but does little to tell you how the script fails to comply. The messages are very general and sometimes untrue.

To start with, the entries for the DC coefficient must come before any entries for the AC coefficients. The DC coefficient is Coefficient 0; all the other coefficients are AC coefficients. So in an entry for the DC coefficient, the two numbers after the colon must be 0 and 0. In an entry for AC coefficients, the first number after the colon must not be 0.

In a DC entry, the color components must be in increasing order. E.g. '0,2,1' before the colon is wrong. So is '0,0,0'.

In an entry for an AC coefficient, you must specify only one color component. I.e. there can be only one number before the colon.

In the first entry for a particular coefficient for a particular color component, the 'Ah' value must be zero, but the Al value can be any valid bit number. In subsequent entries, Ah must be the Al value from the previous entry (for that coefficient for that color component), and the Al value must be one less than the Ah value.

The script must ultimately specify at least some of the DC coefficient for every color component. Otherwise, you get the error message 'Script does not transmit all the data.' You need not specify all of the bits of the DC coefficient, or any of the AC coefficients.

There is a standard option in building the JPEG library to omit scan script capability. If for some reason your library was built with this option, you get the message 'Requested feature was omitted at compile time.'

JPEGMEM
If this environment variable is set, its value is the default memory limit. The value is specified as described for the -maxmemory option. An explicit -maxmemory option overrides any JPEGMEM.
