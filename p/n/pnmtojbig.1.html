NOMBRE

pnmtojbig - convertidor de PNM a archivo JBIG

SINOPSIS

pnmtojbig

[opciones] [archivo-entrada [archivo-salida]]

DESCRIPCIÓN

Este programa es parte de Netpbm(1)

pnmtojbig lee una imagen PBM o PGM, la comprime y genera un archivo JBIG bi-level image entity (BIE).

JBIG es un algoritmo de compresión sin pérdidas altamente efectivo para imágenes bi-nivel (un bit por píxel), especialmente adecuado para páginas de documentos escaneadas.

Una imagen codificada en JBIG puede almacenarse en varias resoluciones (modo progresivo). Estas capas de resolución pueden almacenarse todas en un único BIE o pueden almacenarse en varios archivos BIE separados. Todas las capas de resolución, excepto la más baja, se almacenan simplemente como diferencias con la capa de resolución inmediatamente inferior, ya que esto requiere menos espacio que codificar la imagen completa cada vez. Cada capa de resolución tiene el doble de píxeles horizontales y verticales que la capa inferior. Los archivos JBIG también pueden almacenar varios bits por píxel como planos de bits separados, y pnmtojbig puede leer un archivo PGM y transformarlo en un BIE de múltiples planos de bits.

OPCIONES

-q
Codifica la imagen en una única capa de resolución (modo secuencial). Este suele ser el método de compresión más eficiente. Por defecto, el número de capas de resolución se elige automáticamente de modo que la imagen de la capa más baja no sea mayor de 640 x 480 píxeles.
-x número
Especifica el tamaño horizontal máximo de la capa de resolución más baja. El valor predeterminado es 640 píxeles.
-y número
Especifica el tamaño vertical máximo de la capa de resolución más baja. El valor predeterminado es 480 píxeles.
-l número
Selecciona la capa de resolución más baja que se escribirá en el BIE. Es posible almacenar las diversas capas de resolución de una imagen JBIG en modo progresivo en diferentes BIE. Las opciones -l y -h permiten seleccionar el intervalo de capas de resolución que aparecerá en el BIE creado. La capa de resolución más baja tiene el número 0 y este es también el valor predeterminado. Por defecto, pnmtojbig escribe todas las capas.
-h número
Selecciona la capa de resolución más alta que se escribirá en el BIE. Por defecto, pnmtojbig escribe todas las capas. Ver también la opción -l.
-b
Utiliza valores binarios en lugar de palabras de código Gray para codificar los valores de los píxeles en múltiples planos de bits. Esta opción solo tiene efecto si la entrada es un archivo PGM y si se producen más de un plano de bits. Tenga en cuenta que el decodificador debe realizar la misma selección, pero no puede determinar a partir del BIE si el codificador utilizó palabras de código Gray o binario.
-d número
Especifica el número total de capas de resolución diferenciales en las que se dividirá la imagen de entrada, además de la capa más baja. Cada capa adicional reduce el tamaño de la capa 0 en un 50%. Esta opción anula las opciones -x e -y, que suelen ser una forma más cómoda de seleccionar el número de capas de resolución.
-s número
El algoritmo JBIG divide cada imagen en un número de franjas horizontales. Esta opción especifica que cada franja tendrá número líneas en la capa 0. El valor predeterminado se selecciona de modo que se utilicen aproximadamente 35 franjas para toda la imagen.
-m número
Selecciona el desplazamiento horizontal máximo del píxel de plantilla adaptativa. El codificador JBIG utiliza varios píxeles vecinos para obtener conocimiento a priori estadístico de la probabilidad de que el siguiente píxel sea negro o blanco. Se puede mover un único píxel de esta plantilla de píxeles de contexto vecino. Especialmente para imágenes tramadas, puede ser una ventaja significativa tener un píxel vecino con una distancia lo suficientemente grande como para cubrir el período de una función de tramado. Por defecto, el píxel de plantilla adaptativa puede moverse hasta 8 píxeles. Este codificador admite hasta 23 píxeles; sin embargo, como los decodificadores solo deben admitir una distancia de al menos 16 píxeles según el estándar, no se recomienda un valor superior a 16 para número con el fin de mantener la interoperabilidad con otras implementaciones de JBIG. El desplazamiento vertical máximo del píxel de plantilla adaptativa es siempre cero.
-t número
Codifica solo el número especificado de los planos de bits más significativos. Esta opción permite reducir la profundidad de un archivo PGM de entrada si no se necesitan todos los bits por píxel en la salida.
-o número
JBIG separa una imagen en varias franjas horizontales, capas de resolución y planos, donde cada plano contiene un bit por píxel. Una única franja en un plano y capa se codifica como una unidad de datos llamada entidad de datos de franja (SDE) dentro del BIE. Hay 12 órdenes diferentes posibles en las que se pueden almacenar las SDE dentro del BIE, y número selecciona cuál se utilizará. El orden de las SDE solo es relevante para las aplicaciones que deseen decodificar un archivo JBIG que aún no ha llegado completamente de, por ejemplo, una conexión de red lenta. Por ejemplo, algunas aplicaciones prefieren que el bucle más externo de los tres (franjas, capas, planos) sea sobre todas las capas, de modo que se transmitan primero todos los datos de la capa de resolución más baja.

Los siguientes valores para número seleccionan estas disposiciones de bucles para escribir las SDE (bucle más externo primero):

0
planos, capas, franjas
2
capas, planos, franjas
3
capas, franjas, planos
4
franjas, planos, capas
5
planos, franjas, capas
6
franjas, capas, planos

Todos los bucles cuentan empezando desde cero, sin embargo, sumando 8 al código de orden anterior, el bucle de capas puede invertirse para que cuente hacia abajo a cero y así las capas de mayor resolución se almacenarán antes que las capas inferiores. El orden predeterminado es 3, que escribe primero todos los planos de la primera franja y luego completa la capa 0 antes de continuar con la siguiente capa, y así sucesivamente.

-p número
Esta opción permite activar o desactivar varios algoritmos opcionales definidos en el estándar JBIG. Simplemente sume los números de las siguientes opciones que desee activar para obtener el valor número:
4
predicción determinista (DPON)
8
predicción típica (TPBON)
16
predicción típica de capa diferencial (TPDON)
64
plantilla de dos líneas de la capa 0 (LRLTWO)

Excepto para aplicaciones especiales (como la comunicación con implementaciones subconjunto de JBIG) y para fines de depuración, normalmente no querrá cambiar nada aquí. El valor predeterminado es 28, que proporciona el mejor resultado de compresión.

-c
El movimiento del píxel de plantilla adaptativa se determina según lo sugerido en el anexo C del estándar. Por defecto, el cambio de plantilla se realiza directamente en la siguiente línea, lo que es más efectivo. Sin embargo, algunos ejemplos de prueba de conformidad en el estándar requieren que el cambio de plantilla adaptativa se retrase hasta la primera línea de la siguiente franja. Esta opción selecciona este comportamiento especial, que normalmente no se requiere, excepto para pasar algunas suites de pruebas de conformidad.
-v
Después de que pnmtojbig cree el BIE, enumera algunos detalles técnicos del archivo creado (modo detallado).

pnmtojbig(1) — Netpbm documentation

NAME

pnmtojbig - convert Netpbm images to JBIG format

SYNOPSIS

pnmtojbig [-verbose] [-blackis1] [-comment comment] [-caller caller] [-creationdate creationdate] [-encoding encoding] [-pagesize pagesize] [-resolution resolution] [-resolutionunit resolutionunit] [-tool tool] [-version version] [-orientation orientation] [-defaultpagesize] [-defaultresolution] [-page page] [-nodisplay] [pnmfile]

DESCRIPTION

pnmtojbig reads Netpbm images as input and converts them to the JBIG image compression format, writing the output to standard output. The input image must be a black and white image (PNM format PBM, PPM, or PGM). If you provide a color image (PPM), it will be dithered to a PBM image.

The program follows the JBIG standard, specifically Annex B. This standard is designed for bi-level images.

The JBIG format itself is a standard for the lossless compression of bi-level images. It is primarily intended for facsimile machines and scanned documents.

The JBIG standard distinguishes between single-plane and multiple-plane bi-level images. In the latter case, the bits within a pixel are treated as separate bi-level images, and they are coded sequentially.

pnmtojbig produces a single-plane JBIG image. Thus, a PNM image with maximum value N (e.g. PGM or PPM with maxval=255) is treated as a single plane.

The default behaviour of pnmtojbig is to assume that 0 is black and the maximum value is white. This is the behaviour specified by the JBIG standard for single-plane bi-level images.

The options described below allow you to modify this behaviour, for example, to explicitly state that 1 is black and 0 is white.

OPTIONS

All options described below can be abbreviated to their first letter. Their order is irrelevant.

-verbose

Enables verbose output. This is useful for debugging.

-blackis1

Inverts the interpretation of the input image. With this option, 1 is interpreted as black and 0 is interpreted as white. This is useful for certain image sources.

-comment comment

Adds a comment to the JBIG file. This can be any arbitrary string.

-caller caller

Sets the caller field in the JBIG file. This field is intended to specify the name of the software that generated the file.

-creationdate creationdate

Sets the creation date field in the JBIG file. The format should be YYYYMMDDHHMMSS.

-encoding encoding

Specifies the encoding method. Options are: \"mixed\" (default), \"bi-level\", and \"gray\". \"mixed\" is the standard JBIG encoding, which uses context-based arithmetic coding. \"bi-level\" uses a simpler binary arithmetic coding. \"gray\" uses a simplified gray-scale coding.

-pagesize pagesize

Sets the page size in the JBIG file. The format is widthxheight. The units are specified by -resolutionunit.

-resolution resolution

Sets the resolution in the JBIG file. The units are specified by -resolutionunit.

-resolutionunit resolutionunit

Sets the resolution unit for the page size and resolution. Valid options are: \"inch\" (default), \"cm\", \"mm\", and \"none\".

-tool tool

Sets the tool field in the JBIG file. This field is intended to specify the name of the tool that generated the file.

-version version

Sets the version field in the JBIG file. This field is intended to specify the version of the tool that generated the file.

-orientation orientation

Sets the orientation of the page. Valid options are: \"normal\" (default), \"90\", \"180\", and \"270\".

-defaultpage

Sets the page size to the default value (10000x10000 pixels).

-defaultresolution

Sets the resolution to the default value (100 dots per inch).

-page page

Sets the page number field in the JBIG file. This is typically used for multi-page documents, though pnmtojbig only produces single-page files.

-nodisplay

Disables the display of the image. This is useful when writing to standard output.

FORMATS

The input format is determined by the pnm header. See pnm(5) for more information.

The output format is JBIG.

EXPLANATION

The JBIG standard distinguishes between foreground and background. The standard says nothing about values for multiple plane BIEs.

pnmtojbig follows Markus Kuhn's implementation of the standard in the pbmtojbg program that comes with his JBIG library: If the BIE is a single plane BIE, zero means white and one means black. If it is a multiple plane BIE, zero means black and the maximal value is white.

STANDARDS

This program implements the JBIG image coding algorithm as specified in ISO/IEC 11544:1993 and ITU-T T.82(1993).

AUTHOR

pnmtojbig is based on the JBIG library by Markus Kuhn, part of his JBIG-KIT package. The pbmtojbg program is part of the JBIG-KIT package. The most recent version of that library and tools set is freely available on the Internet from anonymous ftp server ftp.informatik.uni-erlangen.de in directory pub/doc/ISO/JBIG/.

pnmtojbig is part of the Netpbm package of graphics tools.
