PnetCDF(3f) LIBRARY FUNCTIONS PnetCDF(3f)

NOMBRE

PnetCDF - Biblioteca paralela para acceder a archivos en formato Network Common Data Form (CDF, CDF-2 y CDF-5).

SINÓPSIS

include "pnetcdf.inc"

La mayoría de los sistemas:

mpif77 ... -lpnetcdf

Sistemas CRAY PVP:

f90 -dp -i64 ... -lnetcdf

La documentación completa de las bibliotecas PnetCDF se puede encontrar en el sitio web de PnetCDF: http://cucis.ece.northwestern.edu/projects/PnetCDF/.

VERSIÓN DE LA BIBLIOTECA

Este documento describe las API de PnetCDF para el lenguaje de programación FORTRAN.

character*80 nfmpi_inq_libvers(void)

(Corresponde a nf_inq_libvers() en netCDF)

Devuelve una cadena que identifica la versión de la biblioteca PnetCDF y cuándo se compiló, por ejemplo: "1.14.1 de 2025-07-31".

El comando RCS ident(1) encontrará una cadena como "$Id: @(#) PnetCDF library version 1.14.1 of 2025-07-31 $" en la biblioteca. El comando SCCS what(1) encontrará una cadena como "PnetCDF library version 1.14.1 of 2025-07-31".

VALORES DE RETORNO

Todas las funciones PnetCDF (excepto nfmpi_inq_libvers() y nfmpi_strerror()) devuelven un estado entero.

Si este valor de estado devuelto no es igual a NF_NOERR (cero), indica que ocurrió un error. Los posibles valores de estado se definen en pnetcdf.inc.

character*80 nfmpi_strerror(integer status)

(Corresponde a nf_strerror() en netCDF)

Devuelve una traducción textual en cadena del valor status, como "El nombre del atributo o variable contiene caracteres ilegales" o "No existe tal archivo o directorio".

OPERACIONES DE ARCHIVO

integer function nfmpi_create(integer comm, character*(*) path, integer cmode, integer info, integer ncid)

(Corresponde a nf_create() en netCDF)

Crea un nuevo conjunto de datos netCDF en path colectivamente por un grupo de procesos MPI especificado por comm, devolviendo un ID netCDF en ncid. El argumento cmode puede incluir el OR a nivel de bits de las siguientes banderas: NF_NOCLOBBER para proteger los conjuntos de datos existentes (el predeterminado es NF_CLOBBER, que los elimina silenciosamente), NF_64BIT_OFFSET para crear un archivo en formato de desplazamiento de 64 bits (CDF-2), en lugar del formato clásico, el predeterminado, o NF_64BIT_DATA para crear un archivo en formato de datos de 64 bits (CDF-5). Use NF_64BIT_OFFSET o NF_64BIT_DATA. El formato de desplazamiento de 64 bits permite la creación de conjuntos de datos netCDF muy grandes con muchas menos restricciones que el formato clásico, pero solo puede ser leído por la biblioteca netCDF versión 3.6 o superior. Se advierte a los usuarios que los archivos que utilizan el formato de desplazamiento de 64 bits no serán reconocidos por aplicaciones netCDF enlazadas a una versión anterior a la 3.6 de la biblioteca netCDF. Las aplicaciones enlazadas a la versión 3.6 o superior podrán acceder de forma transparente tanto al formato clásico como al formato de desplazamiento de 64 bits. El formato de datos de 64 bits permite la creación de variables de matrices muy grandes. Los archivos CDF-5 actualmente no serán reconocidos por las bibliotecas netCDF 3 o 4.

El argumento cmode debe ser coherente entre todos los procesos MPI que crean colectivamente el archivo. El argumento info es un objeto de información MPI. Los usuarios pueden usarlo para proporcionar pistas de acceso al archivo para mejorar aún más el rendimiento. Las pistas incluyen pistas existentes de MPI-IO, así como pistas definidas y utilizadas en PnetCDF.

Cuando se crea un conjunto de datos netCDF, se abre en modo NF_WRITE. Cuando esta función devuelve, el nuevo conjunto de datos netCDF está en modo de definición.

integer function nfmpi_open(integer comm, character*(*) path, integer mode, integer info, integer ncid)

(Corresponde a nf_open() en netCDF)

Abre un conjunto de datos netCDF existente en path colectivamente por un grupo de procesos MPI especificado por comm, devolviendo un ID netCDF en ncid. El tipo de acceso se describe mediante el parámetro mode, que puede incluir el OR a nivel de bits de las siguientes banderas: NF_WRITE para acceso de lectura/escritura (predeterminado solo lectura).

El argumento mode debe ser coherente entre todos los procesos MPI que abren colectivamente el archivo. El argumento info es un objeto de información MPI. Los usuarios pueden usarlo para proporcionar pistas de acceso al archivo para mejorar aún más el rendimiento. Las pistas incluyen pistas existentes de MPI-IO, así como pistas definidas y utilizadas en PnetCDF.

integer function nfmpi_redef(integer ncid)

(Corresponde a nf_redef() en netCDF)

Pone un conjunto de datos netCDF abierto en modo de definición, para que se puedan añadir o renombrar dimensiones, variables y atributos, y se puedan eliminar atributos.

integer function nfmpi_enddef(integer ncid)

(Corresponde a nf_enddef() en netCDF)

Saca un conjunto de datos netCDF abierto del modo de definición. Los cambios realizados en el conjunto de datos netCDF mientras estaba en modo de definición se verifican y se confirman en el disco si no ocurrieron problemas. Después de una llamada exitosa, los datos de las variables se pueden leer o escribir en el conjunto de datos.

integer function nfmpi_sync(integer ncid)

(Corresponde a nf_sync() en netCDF)

Los datos escritos por las API de PnetCDF pueden ser almacenados en caché por el sistema de archivos local en cada nodo de cómputo. Esta API vacía los datos en caché llamando a MPI_File_sync.

integer function nfmpi_abort(integer ncid)

(Corresponde a nf_abort() en netCDF)

No necesita llamar a esta función. Esta función es llamada automáticamente por nfmpi_close() si el netCDF estaba en modo de definición y algo sale mal con la confirmación. Si el conjunto de datos netCDF no está en modo de definición, entonces esta función es equivalente a nfmpi_close(). Si se llama después de nfmpi_redef(), pero antes de nfmpi_enddef(), las nuevas definiciones no se confirman y el conjunto de datos se cierra. Si se llama después de nfmpi_create() pero antes de nfmpi_enddef(), el conjunto de datos desaparece.

integer function nfmpi_close(integer ncid)

(Corresponde a nf_close() en netCDF)

Cierra un conjunto de datos netCDF abierto. Si el conjunto de datos está en modo de definición, se llamará a nfmpi_enddef() antes de cerrar. Después de que un conjunto de datos se cierra, su ID puede ser reasignado a otro conjunto de datos.

Renombra una dimensión existente en un dataset netCDF abierto. Si el nuevo nombre es más largo que el antiguo, el dataset netCDF debe estar en modo de definición. No puede renombrar una dimensión para que tenga el mismo nombre que otra dimensión.

VARIABLES

integer function nfmpi_def_var(integer ncid, character*(*) name, integer xtype, integer ndims, integer dimids(1), integer varid)

(Corresponde a nf_def_var() en netCDF)

Añade una nueva variable a un dataset netCDF. El netCDF debe estar en modo de definición. varid se establecerá en el ID de la variable netCDF. ndims será el número de dimensiones para la variable. name será el nombre de la variable netCDF. xtype es el tipo externo de netCDF de la variable y debe ser uno de NF_BYTE NF_CHAR, NF_SHORT, NF_INT, NF_FLOAT, o NF_DOUBLE, para los formatos de archivo CDF-1 y CDF-2. CDF-5 define tipos externos adicionales: NF_UBYTE, NF_USHORT, NF_UINT, NF_INT64, y NF_UINT64. El argumento dimids es un vector de ndims IDs de dimensión que corresponden a las dimensiones de la variable.

A diferencia de las variables, los atributos no tienen funciones separadas para definir y escribir valores. Esta familia de funciones define un nuevo atributo con un valor o cambia el valor de un atributo existente. Si el atributo es nuevo, o si el espacio requerido para almacenar el valor del atributo es mayor que antes, el conjunto de datos netCDF debe estar en modo de definición. El parámetro len es el número de valores de fuera para transferir. A menudo es uno, excepto que para nfmpi_put_att_text() generalmente será len_trim(fuera).

Para estas funciones, el componente de tipo del nombre de la función se refiere al tipo en memoria del valor, mientras que el argumento xtype se refiere al tipo externo para almacenar el valor. Un error NF_ERANGE resulta si una conversión entre estos tipos no es posible. En este caso, el valor se representa con el valor de relleno apropiado para el tipo externo asociado.

entero función nfmpi_inq_attname(entero ncid, entero varid, entero attnum, carácter*(*) nombre)

(Corresponde a nf_inq_attname() en netCDF)

Obtiene el nombre de un atributo, dado su ID de variable y número de atributo. Esta función es útil en aplicaciones genéricas que necesitan obtener los nombres de todos los atributos asociados con una variable, ya que los atributos se acceden por nombre en lugar de por número en todas las demás funciones de atributos. El número de un atributo es más volátil que el nombre, ya que puede cambiar cuando se eliminan otros atributos de la misma variable. Los atributos para cada variable se numeran desde 1 (el primer atributo) hasta nvatts, donde nvatts es el número de atributos para la variable, como se devuelve de una llamada a nfmpi_inq_varnatts().

DESCRIPCION DE ARGUMENTOS COMUNES

En esta sección definimos algunos argumentos comunes que se utilizan en la sección "DESCRIPCIÓN DE FUNCIONES".

integer ncid
es el ID netCDF devuelto por una llamada anterior y exitosa a nfmpi_open() o nfmpi_create()
character*(*) name
es el nombre de una dimensión, variable o atributo. Los nombres de dimensiones, variables y atributos consisten en secuencias arbitrarias de caracteres alfanuméricos (así como guion bajo '_', punto '.' y guion '-'), comenzando con una letra o guion bajo. (Sin embargo, los nombres que comienzan con guion bajo están reservados para uso del sistema). La capitalización es significativa en los nombres de netCDF. No se permite un nombre de longitud cero.

El número máximo de caracteres permitidos
es NF_MAX_NAME.

integer xtype
especifica el tipo de dato externo de una variable o atributo netCDF y es uno de los siguientes: NF_BYTE, NF_CHAR, NF_SHORT, NF_INT, NF_FLOAT, o NF_DOUBLE para los formatos de archivo CDF-1 y CDF-2. Estos se utilizan para especificar enteros de 8 bits, caracteres, enteros de 16 bits, enteros de 32 bits, números de punto flotante IEEE de 32 bits y números de punto flotante IEEE de 64 bits, respectivamente.

CDF-5 define tipos externos adicionales: NF_UBYTE, NF_USHORT, NF_UINT, NF_INT64 y NF_UINT64.

integer dimids(1)
es un vector de IDs de dimensiones y define la forma de una variable netCDF. El tamaño del vector debe ser mayor o igual al rango (es decir, el número de dimensiones) de la variable (ndims). El vector debe ordenarse por la velocidad con la que varía una dimensión: dimids(1) debe ser el ID de la dimensión que varía más rápidamente y dimids(ndims) debe ser el ID de la dimensión que varía más lentamente. El número máximo posible de dimensiones para una variable se da por la constante simbólica NF_MAX_VAR_DIMS.
integer dimid
es el ID de una dimensión netCDF. Los IDs de dimensiones netCDF se asignan secuencialmente a partir de los enteros positivos comenzando con 1.
integer ndims
es el número total de dimensiones en un conjunto de datos netCDF o el rango (es decir, el número de dimensiones) de una variable netCDF. El valor no debe ser negativo ni mayor que la constante simbólica NF_MAX_VAR_DIMS.
integer varid
es el ID de una variable netCDF o (para las funciones de acceso a atributos) la constante simbólica NF_GLOBAL, que se utiliza para referenciar atributos globales. Los IDs de variables netCDF se asignan secuencialmente a partir de los enteros positivos comenzando con 1.
integer natts
es el número de atributos globales en un conjunto de datos netCDF para la función nfmpi_inquire() o el número de atributos asociados con una variable netCDF para la función nfmpi_varinq().
integer(kind=MPI_OFFSET) index(1)
especifica las coordenadas del valor de datos netCDF a acceder. Los índices comienzan en 1; por lo tanto, por ejemplo, el primer valor de datos de una variable bidimensional es (1,1). El tamaño del vector debe ser al menos el rango de la variable netCDF asociada y sus elementos deben corresponder, en orden, a las dimensiones de la variable.
integer(kind=MPI_OFFSET) start(1)
especifica el punto de partida para acceder a los valores de datos de una variable netCDF en términos de las coordenadas indiciales de la esquina de la sección del array. Los índices comienzan en 1; por lo tanto, el primer valor de datos de una variable es (1, 1, ..., 1). El tamaño del vector debe ser al menos el rango de la variable netCDF asociada y sus elementos deben corresponder, en orden, a las dimensiones de la variable.
integer(kind=MPI_OFFSET) count(1)
especifica el número de índices seleccionados a lo largo de cada dimensión de la sección del array. Por lo tanto, para acceder a un solo valor, por ejemplo, especifica count como (1, 1, ..., 1). Ten en cuenta que, para E/S con pasos (strided I/O), este argumento debe ajustarse para ser compatible con los argumentos stride y start de modo que la interacción de los tres no intente acceder a una coordenada de datos inválida. Los elementos del vector count corresponden, en orden, a las dimensiones de la variable.
integer(kind=MPI_OFFSET) stride(1)
especifica el intervalo de muestreo a lo largo de cada dimensión de la variable netCDF. Los elementos del vector de paso corresponden, en orden, a las dimensiones de la variable netCDF (stride(1) proporciona el intervalo de muestreo a lo largo de la dimensión que varía más rápidamente de la variable netCDF). Los intervalos de muestreo se especifican en unidades independientes del tipo de elementos (un valor de 1 selecciona elementos consecutivos de la variable netCDF a lo largo de la dimensión correspondiente, un valor de 2 selecciona cada dos elementos, etc.).
integer(kind=MPI_OFFSET) imap(1)
especifica el mapeo entre las dimensiones de una variable netCDF y la estructura en memoria del array de datos interno. Los elementos del vector de mapeo de índices corresponden, en orden, a las dimensiones de la variable netCDF (_FillValue ' para la variable. Este atributo debe tener el mismo tipo que la variable y tener una longitud de uno.

Las variables con una dimensión ilimitada no se prellenan en PnetCDF. Esto también es contrario a netCDF, que sí prellena las variables de registro. En PnetCDF, el relleno de una variable de registro debe hacerse llamando a nfmpi_fill_var_rec(). Tenga en cuenta que esto solo rellena un registro de una variable.

El modo de relleno para todo el archivo se puede establecer mediante nfmpi_set_fill(). La configuración del modo de relleno por variable también está disponible a través de nfmpi_def_var_fill(). En PnetCDF, cambiar el modo de relleno debe hacerse en modo de definición. En netCDF, esto solo es cierto para variables de tamaño fijo. Para variables de registro, cambiar el modo de relleno se puede hacer en cualquier momento en NetCDF.
