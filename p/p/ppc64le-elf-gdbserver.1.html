GDBSERVER(1) Herramientas de desarrollo GNU GDBSERVER(1)

NOMBRE

gdbserver - Servidor remoto para el depurador GNU

SINOPSIS

gdbserver comunicación programa [argumentos...]

gdbserver --attach comunicación pid

gdbserver --multi comunicación

DESCRIPCIÓN

gdbserver es un programa que permite ejecutar GDB en una máquina diferente a la que ejecuta el programa que se está depurando.

Uso (lado del servidor (objetivo)):

Primero, necesita tener una copia del programa que desea depurar en el sistema de destino. El programa puede ser despojado para ahorrar espacio si es necesario, ya que a gdbserver no le importan los símbolos. Toda la gestión de símbolos es manejada por el GDB que se ejecuta en el sistema anfitrión.

Para usar el servidor, inicie sesión en el sistema de destino y ejecute el programa gdbserver. Debe indicarle (a) cómo comunicarse con GDB, (b) el nombre de su programa y (c) sus argumentos. La sintaxis general es:

destino> gdbserver <comunicación> <programa> [<argumentos> ...]

Por ejemplo, utilizando un puerto serie, podría decir:

destino> gdbserver /dev/com1 emacs foo.txt

Esto le indica a gdbserver que depure emacs con el argumento foo.txt, y que se comunique con GDB a través de /dev/com1. gdbserver ahora espera pacientemente a que el GDB anfitrión se comunique con él.

Para usar una conexión TCP, podría decir:

destino> gdbserver anfitrion:2345 emacs foo.txt

Esto dice prácticamente lo mismo que el último ejemplo, excepto que nos comunicaremos con el GDB del "anfitrion" a través de TCP. El argumento "anfitrion:2345" significa que esperamos ver una conexión TCP desde "anfitrion" al puerto TCP local 2345. (Actualmente, la parte "anfitrion" se ignora). Puede elegir cualquier número para el número de puerto siempre que no entre en conflicto con ningún puerto TCP existente en el sistema de destino. Este mismo número de puerto debe usarse en el comando "target remote" del GDB anfitrión, que se describirá en breve. Tenga en cuenta que si eligió un número de puerto que entra en conflicto con otro servicio, gdbserver imprimirá un mensaje de error y saldrá.

gdbserver también puede adjuntarse a programas en ejecución. Esto se logra a través del argumento --attach. La sintaxis es:

destino> gdbserver --attach <comunicación> <pid>

pid es el ID del proceso de un proceso en ejecución actualmente. No es necesario que gdbserver apunte a un binario del proceso en ejecución.

Para iniciar "gdbserver" sin proporcionar un comando inicial para ejecutar o un ID de proceso al que adjuntarse, use la opción de línea de comandos --multi. En tal caso, debe conectarse usando "target extended-remote" para iniciar el programa que desea depurar.

destino> gdbserver --multi <comunicación>

Uso (lado del anfitrión):

Necesita una copia sin despojar del programa de destino en su sistema anfitrión, ya que GDB necesita examinar sus tablas de símbolos y similares. Inicie GDB como lo haría normalmente, con el programa de destino como primer argumento. (Es posible que deba usar la opción --baud si la línea serie funciona a una velocidad diferente de 9600 baudios). Es decir, "gdb PROG-DESTINO", o "gdb --baud VELOCIDAD PROG-DESTINO". Después de eso, el único comando nuevo que necesita conocer es "target remote" (o "target extended-remote"). Su argumento es un nombre de dispositivo (generalmente un dispositivo serie, como /dev/ttyb), o un descriptor "ANFITRIÓN:PUERTO". Por ejemplo:

(gdb) target remote /dev/ttyb

se comunica con el servidor a través de la línea serie /dev/ttyb, y:

(gdb) target remote anfitrion-el-objetivo:2345

se comunica a través de una conexión TCP al puerto 2345 en el anfitrión `anfitrion-el-objetivo', donde previamente inició gdbserver con el mismo número de puerto. Tenga en cuenta que para las conexiones TCP, debe iniciar gdbserver antes de usar el comando `target remote', de lo contrario, puede recibir un error como `Connection refused'.

gdbserver también puede depurar múltiples inferiores a la vez, descrito en el manual de GDB en el nodo "Inferiors Connections and Programs" -- comando de shell "info -f gdb -n 'Inferiors Connections and Programs'". En tal caso, use la variante del comando GDB "extended-remote":

(gdb) target extended-remote anfitrion-el-objetivo:2345

La opción --multi de gdbserver puede usarse o no en tal caso.

OPCIONES

Hay tres modos diferentes para invocar gdbserver:

  • Depurar un programa específico especificado por su nombre de programa: 
    gdbserver <comunicación> <programa> [<argumentos>...]

    El parámetro comunicación especifica cómo debe el servidor comunicarse con GDB; es un nombre de dispositivo (para usar una línea serie), un número de puerto TCP (":1234"), o "-" o "stdio" para usar stdin/stdout de "gdbserver". Especifique el nombre del programa a depurar en programa. Cualquier argumento restante se pasará al programa sin cambios. Cuando el programa salga, GDB cerrará la conexión y "gdbserver" saldrá.

  • Depurar un programa específico especificando el ID del proceso de un programa en ejecución: 
    gdbserver --attach <comunicación> <pid>

    El parámetro comunicación es como se describió anteriormente. Proporcione el ID del proceso de un programa en ejecución en pid; GDB hará todo lo demás. Al igual que con el modo anterior, cuando el proceso pid salga, GDB cerrará la conexión y "gdbserver" saldrá.

  • Modo multiproceso -- depurar más de un programa/proceso: 
    gdbserver --multi <comunicación>

    En este modo, GDB puede instruir a gdbserver qué comando(s) ejecutar. A diferencia de los otros 2 modos, GDB no cerrará la conexión cuando un proceso que se está depurando salga, por lo que puede depurar varios procesos en la misma sesión.

En cada uno de los modos puede especificar estas opciones:

--help
Lista todas las opciones con explicaciones breves.
--version
Esta opción hace que gdbserver imprima su número de versión y salga.
--attach
gdbserver se adjuntará a un programa en ejecución. La sintaxis es: 
destino> gdbserver --attach <comunicación> <pid>

pid es el ID del proceso de un proceso actualmente en ejecución. No es necesario apuntar gdbserver a un binario del proceso en ejecución.

--multi
Para iniciar "gdbserver" sin proporcionar un comando inicial para ejecutar o un ID de proceso al que adjuntarse, use esta opción de línea de comandos. Luego puede conectarse usando "target extended-remote" e iniciar el programa que desea depurar. La sintaxis es: 
destino> gdbserver --multi <comunicación>
--debug[=opción1,opción2,...]
Instruye a "gdbserver" para que muestre información de estado adicional sobre el proceso de depuración. Esta opción está destinada al desarrollo de "gdbserver" y para informes de errores a los desarrolladores.

Cada opción es el nombre de un componente para el cual se debe habilitar la depuración. La lista de opciones posibles es all, threads, event-loop, remote. La opción especial all habilita todos los componentes. La lista de opciones se procesa de izquierda a derecha, y una opción puede ir precedida del carácter "-" para deshabilitar la salida para ese componente, por lo que podría escribir:

destino> gdbserver --debug=all,-event-loop

para activar la salida de depuración para todos los componentes excepto event-loop. Si no se pasan opciones a --debug, esto se trata como equivalente a --debug=thre

gdbserver(1) — Manual de Arch Linux

NOMBRE

gdbserver — un depurador remoto de servidor

SINOPSIS

gdbserver [opciones] host:port program [argumentos_programa...]

gdbserver [opciones] --attach host:port pid

DESCRIPCION

gdbserver es un programa que se ejecuta en la máquina remota donde se está ejecutando el programa que quieres depurar. Se comunica con el depurador GDB (que se ejecuta en la máquina local) a través de una conexión TCP.

gdbserver se puede utilizar de dos maneras:

  • Ejecutando un programa para depurar:

En este modo, gdbserver se inicia especificando el programa a depurar y sus argumentos. El programa se ejecutará y esperará una conexión de GDB. La sintaxis es:

gdbserver [opciones] host:port programa [argumentos_programa...]

Aquí, host es la dirección IP o el nombre de host de la máquina remota donde se está ejecutando gdbserver, y port es el número de puerto TCP que gdbserver utilizará para escuchar las conexiones de GDB. programa es la ruta al ejecutable que quieres depurar, y argumentos_programa son los argumentos que se pasarán a ese programa.

  • Adjuntando a un proceso existente:

En este modo, gdbserver se adjunta a un proceso ya en ejecución. La sintaxis es:

gdbserver [opciones] --attach host:port pid

Aquí, pid es el ID del proceso al que quieres adjuntarte. El resto de los argumentos son los mismos que en el modo anterior.

Una vez que gdbserver se está ejecutando y escuchando (o adjuntado a un proceso), puedes iniciar GDB en tu máquina local y conectarte a él usando el comando target remote host:port.

OPCIONES

--attach
Adjuntar a un proceso existente en lugar de iniciar uno nuevo.
--debug
Habilita la salida de depuración detallada. Esto puede cambiar en futuras versiones de "gdbserver".
--debug-file=nombre_archivo
Instruye a "gdbserver" para que envíe cualquier salida de depuración al nombre_archivo dado. Esta opción está destinada al desarrollo de "gdbserver" y para informes de errores a los desarrolladores.
--debug-format=opcion1[,opcion2,...]
Instruye a "gdbserver" para que incluya información adicional en cada línea de salida de depuración.
--wrapper
Especifica un envoltorio para lanzar programas para depurar. La opción debe ir seguida del nombre del envoltorio, luego cualquier argumento de línea de comandos para pasar al envoltorio, y luego "--" indicando el final de los argumentos del envoltorio.
--once
Por defecto, gdbserver mantiene el puerto TCP de escucha abierto, de modo que son posibles conexiones adicionales. Sin embargo, si inicias "gdbserver" con la opción --once, dejará de escuchar cualquier intento de conexión posterior después de conectarse a la primera sesión de GDB.

VER TAMBIÉN

La documentación completa de GDB se mantiene como un manual Texinfo. Si los programas "info" y "gdb" y la documentación Texinfo de GDB están correctamente instalados en tu sitio, el comando

info gdb

debería darte acceso al manual completo.
