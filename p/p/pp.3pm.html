pp(3) Documentación de Perl aportada por el usuario pp(3)

NOMBRE

pp - Empaquetador PAR

SINOPSIS

pp [ -ABCEFILMPTSVXacdefghilmnoprsuvxz ] [ archivo_par | archivo_script ]...

EJEMPLOS

Nota: Al ejecutar en Microsoft Windows, el a.out de abajo se reemplazará por a.exe.

% pp hola.pl               # Empaqueta 'hola.pl' en el ejecutable 'a.out'
% pp -o hola hola.pl      # Empaqueta 'hola.pl' en el ejecutable 'hola'
                            # (o 'hola.exe' en Win32)
% pp -o foo foo.pl bar.pl   # Empaqueta 'foo.pl' y 'bar.pl' en 'foo'
% ./foo                     # Ejecuta 'foo.pl' dentro de 'foo'
% mv foo bar; ./bar         # Ejecuta 'bar.pl' dentro de 'foo'
% mv bar baz; ./baz         # Error: No se puede abrir el script perl "baz"
% pp -p archivo             # Crea un archivo PAR, 'a.par'
% pp -o hola a.par         # Empaqueta 'a.par' en el ejecutable 'hola'
% pp -S -o hola archivo     # Combina los dos pasos anteriores
% pp -p -o out.par archivo  # Crea 'out.par' a partir de 'archivo'
% pp -B -p -o out.par archivo  # igual que el anterior, pero empaqueta módulos
                            # principales y elimina cualquier ruta local de @INC
% pp -P -o out.pl archivo  # Crea 'out.pl' a partir de 'archivo'
% pp -B -p -o out.pl archivo  # igual que el anterior, pero empaqueta módulos
                            # principales y elimina cualquier ruta local de @INC
                            # (-B se asume al crear ejecutables)
% pp -e "print 123"         # Empaqueta un one-liner en 'a.out'
% pp -p -e "print 123"      # Crea un archivo PAR 'a.par'
% pp -P -e "print 123"      # Crea un script perl 'a.pl'
% pp -c hola               # Comprueba dependencias de "perl -c hola"
% pp -x hola               # Comprueba dependencias de "perl hola"
% pp -n -x hola            # igual que el anterior, pero omite el escaneo estático
% pp -I /foo hola          # Rutas de inclusión adicionales
% pp -M Foo::Bar hola      # Módulos adicionales en la ruta de inclusión
% pp -M abbrev.pl hola     # Bibliotecas adicionales en la ruta de inclusión
% pp -X Foo::Bar hola      # Excluir módulos
% pp -a data.txt hola      # Archivos de datos adicionales
% pp -r hola               # Empaqueta 'hola' en 'a.out', ejecuta 'a.out'
% pp -r hola a b c         # Empaqueta 'hola' en 'a.out', ejecuta 'a.out'
                            # con los argumentos 'a b c'
% pp hola --log=c          # Empaqueta 'hola' en 'a.out', registra
                            # mensajes en 'c'
# Empaqueta 'hola' en un 'out.exe' sin consola (solo Win32)
% pp --gui -o out.exe hola
% pp @archivo hola.pl         # Empaqueta 'hola.pl' pero lee opciones _adicionales_
                            # del archivo 'archivo'

DESCRIPCIÓN

pp crea ejecutables independientes a partir de programas Perl, utilizando el empaquetador comprimido proporcionado por PAR y heurísticas de detección de dependencias ofrecidas por Module::ScanDeps. Los archivos fuente se comprimen textualmente sin compilación.

Puedes pensar en pp como "perlcc que funciona sin problemas". :-)

Una interfaz gráfica de usuario también está disponible como el comando tkpp.

No proporciona la aceleración del paso de compilación que ofrece perlcc (sin embargo, consulta -f más abajo para ver técnicas compiladas en bytecode y ocultación de código fuente), pero lo compensa con mejor fiabilidad, tamaño de ejecutable más pequeño y recuperación completa del código fuente original.

Cuando se especifica un único programa de entrada, el ejecutable resultante se comportará de manera idéntica a ese programa. Sin embargo, cuando se empaquetan varios programas, el ejecutable producido ejecutará aquel que tenga el mismo nombre base que $0 (es decir, el nombre de archivo utilizado para invocarlo). Si nada coincide, muere con el error "Can't open perl script "$0"".

OPCIONES

Las opciones están disponibles en forma *corta* y *larga*. Por ejemplo, las tres líneas siguientes son equivalentes:

% pp -o output.exe input.pl
% pp --output output.exe input.pl
% pp --output=output.exe input.pl

Dado que las líneas de comando pueden volverse lo suficientemente largas como para alcanzar los límites impuestos por algunos shells, es posible hacer que pp lea algunas de sus opciones de uno o más archivos de texto. El uso básico es simplemente incluir un argumento que comience con un símbolo 'at' (@). Este argumento se interpretará como un archivo del que leer las opciones. Es posible mezclar opciones ordinarias y opciones de @archivo. Esto se implementa utilizando el módulo Getopt::ArgvFile, así que lee su documentación para un uso avanzado. Ten en cuenta que Getopt::ArgvFile se usa aquí con el parámetro "resolveEnvVars=1", es decir, las subcadenas de la forma ${FOO"}" en el contenido de @archivo se reemplazan por el valor de la variable de entorno FOO.

-a, --añadirarchivo=ARCHIVO|DIR
Añade un archivo adicional al paquete. Si el archivo es un directorio, añade recursivamente todos los archivos dentro de ese directorio, tratando los enlaces como archivos reales.

Por defecto, los archivos se colocan bajo "/" dentro del paquete con sus nombres originales. Puedes anular esto añadiendo el nombre del archivo de destino después de un ";", así:

% pp -a "nombre_archivo_antiguo.txt;nombre_archivo_nuevo.txt"
% pp -a "nombre_directorio_antiguo;nombre_directorio_nuevo"

Puedes especificar "-a" múltiples veces.

-A, --listaañadir=ARCHIVO
Lee una lista de nombres de archivos/directorios de ARCHIVO, añadiéndolos al paquete. Cada línea en ARCHIVO se toma como un argumento para el -a anterior.

Puedes especificar "-A" múltiples veces.

-B, --empaquetar
Empaqueta módulos principales en el paquete resultante. Esta opción está habilitada por defecto, excepto cuando se especifica "-p" o "-P".

Desde la versión 0.953 de PAR, esto también elimina cualquier ruta local de la lista de rutas de búsqueda de módulos @INC antes de ejecutar el script contenido.

-C, --limpiar
Limpia los archivos temporales extraídos de la aplicación en tiempo de ejecución. Por defecto, estos archivos se almacenan en caché en el directorio temporal; esto permite que el programa se inicie más rápido la próxima vez.
-c, --compilar
Ejecuta "perl -c archivo_entrada" para determinar dependencias adicionales en tiempo de ejecución.
-cd, --cachedeps=ARCHIVO
Usa ARCHIVO para almacenar en caché las dependencias detectadas. Crea ARCHIVO si no existe. Esto acelerará el proceso de escaneo en ejecuciones posteriores.
-d, --dependiente
Reduce el tamaño del ejecutable al no incluir una copia del intérprete Perl. Los ejecutables creados de esta manera necesitarán una perl5x.dll o libperl.so separada para funcionar correctamente. Esta opción solo está disponible si Perl se compila como una biblioteca compartida.
-e, --eval=CADENA
Empaqueta un one-liner, muy similar a "perl -e '...'"
-E, --evalfeature=CADENA
Se comporta igual que "-e", excepto que habilita implícitamente todas las características opcionales (en la unidad de compilación principal) con Perl 5.10 y posteriores. Ver feature.
-x, --ejecutar
Ejecuta "perl archivo_entrada" para determinar dependencias adicionales en tiempo de ejecución.

Usando esta opción, pp puede detectar el uso de módulos que no se pueden determinar mediante análisis estático del "archivo_entrada". Ejemplos son cosas cargadas por cargadores en tiempo de ejecución como Module::Runtime o cargadores de "plugins" como Module::Loader. Ten en cuenta que los módulos detectados dependen de qué partes de tu programa se ejerciten al ejecutar "archivo_entrada". Por ejemplo, si tu programa termina inmediatamente al ejecutarse como "perl archivo_entrada" porque carece de argumentos obligatorios, entonces esta opción probablemente no tendrá ningún efecto. Puedes usar --xargs para proporcionar argumentos en este caso.

--xargs=CADENA
Proporciona los argumentos especificados en CADENA al programa cuando se ejecuta con la opción -x.

Esto es útil si tu programa necesita argumentos para ejecutar partes de su código que de otra manera no se ejecutarían al ser invocado simplemente como "perl archivo_entrada".

-f, --bytecode
Compila el código fuente a bytecode antes de empaquetarlo. Esto puede aumentar ligeramente el tiempo de arranque del programa, pero oculta el código fuente.
-g, --gui
Crea un ejecutable que se ejecuta como una aplicación de consola o una aplicación GUI (solo en plataformas que lo soportan). En Windows, esto implica la creación de un archivo .exe que no abre una ventana de consola al ejecutarse.
-h, --help
Muestra un resumen de las opciones.
-i, --inplace=ARCHIVO
Modifica un archivo PAR existente. Los archivos PAR suelen ser inmutables; sin embargo, esta opción permite realizar algunas modificaciones (como añadir archivos) sin tener que reconstruir todo el paquete.
-I, --incluirpath=DIR
Añade DIR a la lista de rutas de búsqueda de módulos Perl. Esto será útil si tu script depende de módulos que no están en las rutas de instalación estándar de Perl ni en el directorio actual.
-l, --lib=PATH
Añade una biblioteca al paquete. Esto es similar a "-I", pero el módulo se empaqueta de forma que Perl pueda encontrarlo en tiempo de ejecución sin necesidad de que "-I" se establezca explícitamente.

Se pueden especificar varias bibliotecas.

-L, --liblist=ARCHIVO
Lee una lista de rutas de bibliotecas de ARCHIVO, añadiéndolas al paquete. Cada línea en ARCHIVO se toma como un argumento para -l anterior.

Puedes especificar "-L" múltiples veces.

-m, --modificar=MÓDULO
No empaquetar MÓDULO. Esto es útil si estás creando un ejecutable para un entorno donde MÓDULO ya está disponible (por ejemplo, en el servidor de producción).
-M, --module=MÓDULO
Incluir explícitamente MÓDULO en el paquete. Esto se usa generalmente para asegurar que un módulo se empaqueta aunque el análisis estático no lo detecte.

También puedes usar esto para añadir archivos de código Perl con el sufijo .pl, como si fueran módulos.

Se pueden especificar varios módulos.

-n, --noconfirm
No pedir confirmación antes de sobrescribir archivos existentes.
-o, --output=ARCHIVO
Especifica el nombre del archivo ejecutable o archivo PAR de salida.
-O, --onlyroot
Esto es para el sistema de empaquetado de PAR; por favor, consulta la documentación de PAR::Packer.
-p, --parfile
Crea un archivo PAR en lugar de un ejecutable.
-P, --perlscript
Crea un script Perl empaquetado en lugar de un ejecutable binario. El resultado será un script Perl que, cuando se ejecute, extraerá el contenido del paquete PAR en un directorio temporal y luego ejecutará el script principal.
-r, --run
Crea el ejecutable y luego lo ejecuta inmediatamente. Si se proporcionan argumentos adicionales después del nombre del script, se pasarán al programa ejecutado.
-R, --resolve=PATH
Resuelve rutas relativas de forma explícita. Esto es para el sistema de empaquetado de PAR; por favor, consulta la documentación de PAR::Packer.
-s, --shrink
Intenta eliminar el código fuente innecesario (por ejemplo, comentarios, espacios en blanco) de los archivos Perl empaquetados. Esto puede reducir el tamaño del paquete, pero a costa de la legibilidad y la depuración.
-S, --scan
Escanea el script de entrada para dependencias de módulos. Esto es un sinónimo de "-c".
-t, --tempdir=DIR
Especifica el directorio donde se extraerán los archivos temporales en tiempo de ejecución. Por defecto, se utiliza el directorio temporal del sistema.
-T, --notempdir
No extraer los archivos en un directorio temporal. Esto está destinado a entornos donde no se permite la escritura en directorios temporales, o cuando se quiere evitar la sobrecarga de la extracción de archivos.
-v, --verbose
Imprime más información durante el proceso de empaquetado.
-V, --version
Muestra la versión de pp y sale.
-x, --strip
Elimina la información de depuración (símbolos) del ejecutable resultante (si es un binario nativo).
-X, --exclude=MÓDULO
No incluir MÓDULO en el paquete. Esto es útil para excluir módulos que no son necesarios o que podrían causar conflictos.
-z, --compress=NIVEL
Establece el nivel de compresión (0-9) para el archivo PAR. 0 significa sin compresión, 9 significa máxima compresión. El valor por defecto suele ser bastante alto (6 o 7).

VER TAMBIÉN

PAR::Packer(3pm), perlmod(1).

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

--xargs=CADENA
Si se proporciona -x, divide la "CADENA" usando la función "shellwords" de Text::ParseWords y pasa el resultado como @ARGV al ejecutar "perl inputfile".
-X, --exclude=MÓDULO
Excluye el módulo dado de la ruta de búsqueda de dependencias y del paquete. Si el archivo dado es un ejecutable zip, par o par, todos los archivos dentro del archivo dado (excepto MANIFEST, META.yml y script/*) serán excluidos y el archivo de salida usará el archivo dado en tiempo de ejecución.
-f, --filter=FILTRO
Filtra los scripts fuente con una subclase de PAR::Filter. Puedes especificar múltiples filtros.

Si deseas ocultar el código fuente de miradas indiscretas, esto lo hará:

% pp -f Bleach source.pl

Si te tomas más en serio la ocultación de tu código fuente, deberías echar un vistazo al módulo PAR::Filter::Crypto de Steve Hay. ¡Asegúrate de entender las advertencias de Filter::Crypto!

Nota: La mayoría de los filtros son incompatibles con las secciones "__DATA__" en tu fuente. El ejecutable empaquetado normalmente aborta con un mensaje de error como

readline() on unopened filehandle DATA at (eval 13) line 3.
-g, --gui
Crea un ejecutable que no tenga ventana de consola. Esta opción se ignora en plataformas que no sean MSWin32 o cuando se especifica "-p".
-h, --help
Muestra información básica de uso.
-I, --lib=DIR
Añade el directorio dado a la ruta de búsqueda de módulos de perl. Se puede especificar varias veces.
-l, --link=ARCHIVO|BIBLIOTECA
Añade la biblioteca compartida dada (también conocida como objeto compartido o DLL) al archivo empaquetado. También acepta nombres en rutas de biblioteca; es decir, "-l ncurses" significa lo mismo que "-l libncurses.so" o "-l /usr/local/lib/libncurses.so" en la mayoría de los sistemas Unix. Se puede especificar varias veces.
-L, --log=ARCHIVO
Registra la salida del empaquetado en un archivo en lugar de en stdout.
-F, --modfilter=FILTRO[=EXPRESION_REGULAR],
Filtra los módulos de perl incluidos con una subclase de PAR::Filter. Puedes especificar múltiples filtros.

Por defecto, se aplica el filtro PodStrip. En caso de que cause problemas, puedes desactivarlo estableciendo la variable de entorno "PAR_VERBATIM" a 1.

Desde PAR 0.958, puedes usar una expresión regular opcional (EXPRESION_REGULAR arriba) para seleccionar los archivos en el archivo que deben ser filtrados. La expresión regular se compara con los nombres de los módulos tal como aparecerían como claves en %INC, por ejemplo, "Foo/Bar.pm" para el módulo "Foo::Bar". Ejemplos:

pp -o foo.exe -F 'Bleach=warnings\.pm$' foo.pl

Esto crea un ejecutable binario foo.exe desde foo.pl empaquetando todos los archivos como de costumbre, excepto los archivos que terminan en "warnings.pm", los cuales son filtrados con PAR::Filter::Bleach.

pp -o foo.exe -F 'Bleach=^(?!Win32/)' foo.pl

Esto "blanquea" todos los módulos **excepto** los del espacio de nombres "Win32::".

Nota: La misma restricción sobre las secciones "__DATA__" se aplica como para --filter.

-M, --module=MÓDULO
Añade el módulo especificado al paquete, junto con sus dependencias.

Las siguientes variantes se pueden usar para añadir espacios de nombres de módulos completos:

-M Foo::**
Añade todos los módulos del espacio de nombres "Foo" **excepto** "Foo" mismo, es decir, añade "Foo::Bar", "Foo::Bar::Quux", etc., hasta cualquier profundidad.
-M Foo::*
Añade todos los módulos en el nivel 1 del espacio de nombres "Foo", es decir, añade "Foo::Bar", pero **ni** "Foo::Bar::Quux" **ni** "Foo".
-M Foo::
Atajo para "-M Foo -M Foo:**": todos los módulos en el espacio de nombres "Foo", incluido "Foo" mismo.

En lugar de un nombre de módulo, MÓDULO también puede ser especificado como un nombre de archivo relativo a la ruta @INC, es decir, "-M Module/ScanDeps.pm" significa lo mismo que "-M Module::ScanDeps".

Si MÓDULO tiene una extensión que no es ".pm"/".ix"/".al", no se escaneará en busca de dependencias y se colocará bajo "/" en lugar de bajo "/lib/" dentro del archivo PAR. Este uso está **obsoleto**; considera usar la opción -a en su lugar.

Puedes especificar "-M" varias veces.

-m, --multiarch
Crea un archivo PAR multiarquitectura. Implica -p.
-n, --noscan
Omite el escaneo estático predeterminado por completo, utilizando únicamente dependencias en tiempo de ejecución de -c o -x.
-N, --namespace=ESPACIO_DE_NOMBRES
Añade todos los módulos del espacio de nombres al paquete, junto con sus dependencias. Si "ESPACIO_DE_NOMBRES" es algo como "Foo::Bar", esto añadirá todos los módulos "Foo/Bar/Quux.pm", "Foo/Bar/Fred/Barnie.pm", etc., que se puedan encontrar en tu ruta de búsqueda de módulos. Imita el comportamiento de los cargadores de "plugins" como Module::Loader.

Esto es diferente de usar "-M Foo::Bar::", ya que este último insiste en añadir "Foo/Bar.pm", que podría no existir en el escenario de "plugin" anterior.

Puedes especificar "-N" varias veces.

-o, --output=ARCHIVO
Nombre del archivo para el ejecutable empaquetado final.
-p, --par
Crea solo archivos PAR; no empaqueta en un binario independiente.
-P, --perlscript
Crea un script perl independiente; no empaqueta en un binario independiente.
-r, --run
Ejecuta el script empaquetado resultante después de empaquetarlo.
--reusable
EXPERIMENTAL

Hace que el ejecutable empaquetado sea reutilizable para ejecutar scripts Perl externos arbitrarios como si fueran parte del paquete:

pp -o myapp --reusable someapp.pl
./myapp --par-options --reuse otherapp.pl

La segunda línea ejecutará otherapp.pl en lugar de someapp.pl.

-S, --save
No elimina el archivo PAR generado después del empaquetado.
-s, --sign
Firma criptográficamente el archivo PAR o binario generado usando Module::Signature.
-T, --tempcache
Establece la parte única del programa del nombre del directorio caché que se usa si el programa se ejecuta sin -C. Si no se establece, se usa un hash del ejecutable.

Cuando el programa se ejecuta, su contenido se extrae a un directorio temporal. En sistemas Unix, esto es comúnmente /tmp/par-USUARIO/cache-XXXXXXX. USUARIO se reemplaza por el nombre del usuario que ejecuta el programa, pero "escrito" en hexadecimal. XXXXXXX es un hash del ejecutable o el valor pasado al interruptor "-T" o "--tempcache".

-u, --unicode
Nota: Esta opción se ignora para Perl 5.32 y versiones posteriores.

Empaqueta el soporte Unicode (esencialmente utf8_heavy.pl y todo lo que está debajo del directorio unicore en tu biblioteca de perl).

Esta opción existe porque es imposible detectar mediante análisis estático si tu programa necesita soporte Unicode en tiempo de ejecución. (Nota: Si tu programa contiene "use utf8", esto no implica que necesite soporte Unicode. Simplemente indica que tu código fuente está escrito en UTF-8.)

Si tu programa empaquetado sale con un mensaje de error como

Can't locate utf8_heavy.pl in @INC (@INC contains: ...)

intenta empaquetarlo con "-u" (o usa "-x").

-v, --verbose[=NÚMERO]
Aumenta la verbosidad de la salida; NÚMERO es un entero de 1 a 3, siendo 3 el más verboso. Por defecto es 1 si se especifica sin argumento. Alternativamente, -vv establece el nivel de verbosidad a 2, y -vvv lo establece a 3.
-V, --version
Muestra el número de versión y los derechos de autor de este programa.
-z, --compress

OPTIONS

-z NUMBER
Establece el nivel de compresión zip; NUMBER es un entero entre 0 y 9, 0 = sin compresión, 9 = máxima compresión. El valor predeterminado es 6 si no se usa -z.

ENTORNO

PP_OPTS
Opciones de línea de comandos (switches). Los switches en esta variable se toman como si estuvieran en cada línea de comandos de pp.

NOTAS

Aquí hay algunas recetas que muestran cómo utilizar pp para empaquetar source.pl con todas sus dependencias, en máquinas de destino con diferentes configuraciones esperadas:

Configuración autónoma (Stone-alone):
Para crear un ejecutable autónomo, adecuado para ejecutarse en una máquina que no tiene perl instalado: 
% pp -o packed.exe source.pl        # crea packed.exe
# Ahora, despliega 'packed.exe' en la máquina de destino...
% packed.exe                        # ejecútalo
Solo intérprete Perl, sin módulos principales:
Para crear un archivo .pl empaquetado que incluya módulos principales, adecuado para ejecutarse en una máquina que tiene un intérprete perl, pero donde quieres estar seguro de las versiones de los módulos principales que usa tu programa: 
% pp -B -P -o packed.pl source.pl   # crea packed.pl
# Ahora, despliega 'packed.pl' en la máquina de destino...
% perl packed.pl                    # ejecútalo
Perl con módulos principales instalados:
Para crear un archivo .pl empaquetado sin módulos principales, confiando en el intérprete perl de la máquina de destino y sus bibliotecas principales. Esto produce un archivo significativamente más pequeño que la versión anterior: 
% pp -P -o packed.pl source.pl      # crea packed.pl
# Ahora, despliega 'packed.pl' en la máquina de destino...
% perl packed.pl                    # ejecútalo
Perl con PAR.pm y sus dependencias instaladas:
Crea un archivo y ejecutable separados que utilizan el archivo. Esto se basa en el intérprete perl y las bibliotecas de la máquina de destino. 
% pp -p source.pl                   # crea source.par
% echo "use PAR 'source.par';" > packed.pl;
% cat source.pl >> packed.pl;       # crea packed.pl
# Ahora, despliega 'source.par' y 'packed.pl' en la máquina de destino...
% perl packed.pl                    # ejecútalo, se requieren perl + módulos principales

Ten en cuenta que incluso si tu perl se compiló con una biblioteca compartida, el 'ejecutable autónomo' anterior *no* necesitará un perl5x.dll o libperl.so separado para funcionar correctamente. Pero incluso en este caso, las bibliotecas del sistema subyacentes, como libc, deben ser compatibles entre la máquina host y la máquina de destino. Usa "--dependent" si estás dispuesto a enviar la biblioteca compartida con la aplicación, lo que puede reducir significativamente el tamaño del ejecutable.
