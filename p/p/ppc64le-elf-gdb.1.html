GDB(1) Herramientas de Desarrollo GNU GDB(1)

NOMBRE

gdb - El depurador de GNU

SINOPSIS

gdb [OPCIONES] [programa|programa ID_PROCESO|programa core]

DESCRIPCIÓN

El propósito de un depurador como GDB es permitirte ver qué está sucediendo "dentro" de otro programa mientras se ejecuta, o qué estaba haciendo otro programa en el momento en que falló.

GDB puede hacer cuatro tipos principales de cosas (más otras cosas en apoyo de estas) para ayudarte a detectar errores en el acto:

  • Iniciar tu programa, especificando cualquier cosa que pueda afectar su comportamiento.
  • Hacer que tu programa se detenga bajo condiciones específicas.
  • Examinar qué ha sucedido, cuando tu programa se ha detenido.
  • Cambiar cosas en tu programa, para que puedas experimentar corrigiendo los efectos de un error y seguir aprendiendo sobre otro.

Puedes usar GDB para depurar programas escritos en C, C++, Fortran y Modula-2.

GDB se invoca con el comando del shell "gdb". Una vez iniciado, lee comandos del terminal hasta que le indicas que salga con el comando GDB "quit" o "exit". Puedes obtener ayuda en línea desde el propio GDB usando el comando "help".

Puedes ejecutar "gdb" sin argumentos ni opciones; pero la forma más habitual de iniciar GDB es con un argumento o dos, especificando un programa ejecutable como argumento:

gdb programa

También puedes iniciar con un programa ejecutable y un archivo core especificados:

gdb programa core

Alternativamente, puedes especificar un ID de proceso como segundo argumento o usar la opción "-p", si deseas depurar un proceso en ejecución:

gdb programa 1234
gdb -p 1234

adjuntaría GDB al proceso 1234. Con la opción -p puedes omitir el nombre del archivo del programa.

Aquí tienes algunos de los comandos GDB más frecuentemente necesarios:

break [archivo:][función|línea]
Establecer un punto de interrupción en función o línea (en archivo).
run [lista_argumentos]
Iniciar tu programa (con lista_argumentos, si se especifica).
bt
Traza hacia atrás: mostrar la pila del programa.
print expresión
Mostrar el valor de una expresión.
c
Continuar ejecutando tu programa (después de detenerse, por ejemplo, en un punto de interrupción).
next
Ejecutar la siguiente línea del programa (después de detenerse); pasar por encima de cualquier llamada a función en la línea.
edit [archivo:]función
ver la línea del programa donde se detuvo actualmente.
list [archivo:]función
escribir el texto del programa en las proximidades de donde se detuvo actualmente.
step
Ejecutar la siguiente línea del programa (después de detenerse); entrar en cualquier llamada a función en la línea.
help [nombre]
Mostrar información sobre el comando GDB nombre, o información general sobre el uso de GDB.
quit
exit
Salir de GDB.

Para obtener detalles completos sobre GDB, consulta Using GDB: A Guide to the GNU Source-Level Debugger, por Richard M. Stallman y Roland H. Pesch. El mismo texto está disponible en línea como la entrada "gdb" en el programa "info".

OPCIONES

Cualquier argumento que no sean opciones especifica un archivo ejecutable y un archivo core (o ID de proceso); es decir, el primer argumento encontrado sin una bandera de opción asociada es equivalente a una opción --se, y el segundo, si lo hay, es equivalente a una opción -c si es el nombre de un archivo. Muchas opciones tienen formas largas y abreviadas; ambas se muestran aquí. Las formas largas también se reconocen si las truncas, siempre que se proporcione suficiente parte de la opción para que sea inequívoca.

Las formas abreviadas se muestran aquí con - y las formas largas se muestran con -- para reflejar cómo se muestran en --help. Sin embargo, GDB reconoce todas las siguientes convenciones para la mayoría de las opciones:

"--opción=valor"
"--opción valor"
"-opción=valor"
"-opción valor"
"--o=valor"
"--o valor"
"-o=valor"
"-o valor"

Todas las opciones y argumentos de línea de comandos que proporciones se procesan en orden secuencial. El orden marca la diferencia cuando se utiliza la opción -x.

-s archivo
Lee la tabla de símbolos del archivo.
--write

--exec=archivo

Usa archivo como el archivo ejecutable a ejecutar cuando sea apropiado, y para examinar datos puros junto con un volcado de core.

-c archivo

Ejecuta comandos de GDB desde archivo.

No ejecutar comandos desde ningún archivo de inicialización .gdbinit o .gdbearlyinit.
--quiet

gdb(1) - Arch Linux

NAME

gdb - El depurador de GNU

SYNOPSIS

gdb [option ...]
[program [args ...]]
[-c core]
[-p pid]

DESCRIPTION

GDB, el depurador del proyecto GNU, te permite ver lo que está haciendo otro programa (tu programa "inferior") mientras se ejecuta o lo que hizo antes de que se terminara inesperadamente.

Puedes usar GDB para hacer cuatro tipos de cosas:

  • Iniciar tu programa, especificando cómo debe comportarse en ciertas condiciones.
  • Hacer que tu programa termine o se reinicie.
  • Ver qué estaba sucediendo cuando tu programa se detuvo o se terminó.
  • Cambiar cosas en tu programa, para que puedas continuar experimentando con la corrección de errores.

GDB puede usarse para depurar C, C++, Objective-C, Fortran, Assembly y otros lenguajes. GDB puede operar en una variedad de máquinas y sistemas operativos.

Cuando GDB se inicia, imprime un mensaje de copyright y luego el prompt de GDB, que parece "(>) ".

--batch
Ejecutar en modo batch. Esto es útil para obtener una salida de texto simplificada para depurar un programa en otro ordenador; para hacer este mensaje más útil, el mensaje
Program exited normally.
(que normalmente se emite cada vez que un programa ejecutándose bajo el control de GDB termina) no se emite cuando se ejecuta en modo batch.
--batch-silent
Ejecutar en modo batch, igual que --batch, pero totalmente silencioso. Toda la salida de GDB se suprime (stderr no se ve afectado). Esto es mucho más silencioso que --silent y sería inútil para una sesión interactiva.

Esto es particularmente útil cuando se utilizan objetivos que proporcionan mensajes de Loading section, por ejemplo.

Tenga en cuenta que los objetivos que emiten su salida a través de GDB, en lugar de escribir directamente en "stdout", también se silenciarán.

--args prog [arglist]
Cambiar la interpretación de la línea de comandos para que los argumentos que siguen a esta opción se pasen como argumentos al inferior. Como ejemplo, toma el siguiente comando:
gdb ./a.out -q

Iniciaría GDB con -q, sin imprimir el mensaje introductorio. Por otro lado, usando:

gdb --args ./a.out -q

inicia GDB con el mensaje introductorio y pasa la opción al inferior.

--pid=pid
Adjuntar GDB a un programa ya en ejecución, con el PID pid.
--tui
Abrir la interfaz de usuario de terminal.
--readnow
Leer todos los símbolos del symfile dado en el primer acceso.
--readnever
No leer archivos de símbolos.
--return-child-result
El código de salida de GDB será el mismo que el código de salida del hijo.
--configuration
Imprimir detalles sobre la configuración de GDB y luego salir.
--version
Imprimir información de la versión y luego salir.
--cd=directorio
Ejecutar GDB usando directorio como su directorio de trabajo, en lugar del directorio actual.
--data-directory=directorio
-D
Ejecutar GDB usando directorio como su directorio de datos. El directorio de datos es donde GDB busca sus archivos auxiliares.
--fullname
-f
Emacs establece esta opción cuando ejecuta GDB como un subproceso. Le dice a GDB que emita el nombre de archivo completo y el número de línea de una manera estándar y reconocible cada vez que se muestra un marco de pila (lo que incluye cada vez que el programa se detiene). Este formato reconocible se parece a dos caracteres \032, seguidos del nombre del archivo, el número de línea y la posición del carácter separados por dos puntos, y un salto de línea. El programa de interfaz Emacs-a-GDB utiliza los dos caracteres \032 como una señal para mostrar el código fuente del marco.
-b baudrate
Establecer la velocidad de línea (baudios por segundo o bits por segundo) de cualquier interfaz serie utilizada por GDB para la depuración remota.
-l timeout
Establecer el tiempo de espera, en segundos, para la depuración remota.
--tty=dispositivo
Ejecutar usando dispositivo para la entrada y salida estándar de tu programa.

VER TAMBIÉN

La documentación completa de GDB se mantiene como un manual de Texinfo. Si los programas "info" y "gdb" y la documentación de Texinfo de GDB están instalados correctamente en tu sitio, el comando

info gdb

debería darte acceso al manual completo.
