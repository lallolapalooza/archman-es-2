PPPOE-RELAY(8) Manual del Administrador del Sistema PPPOE-RELAY(8)

NOMBRE

pppoe-relay - agente de retransmisión PPPoE en espacio de usuario.

SINOPSIS

pppoe-relay [opciones]

DESCRIPCIÓN

pppoe-relay es un agente de retransmisión en espacio de usuario para PPPoE (Protocolo Punto a Punto sobre Ethernet) para Linux. pppoe-relay funciona en conjunto con el cliente pppoe y el servidor pppoe-server. Consulte la sección OPERACIÓN más adelante en este manual para obtener detalles sobre cómo funciona pppoe-relay.

OPCIONES

-S interfaz
Añade la interfaz Ethernet interfaz a la lista de interfaces gestionadas por pppoe-relay. Solo se pueden conectar servidores PPPoE a esta interfaz.
-C interfaz
Añade la interfaz Ethernet interfaz a la lista de interfaces gestionadas por pppoe-relay. Solo se pueden conectar clientes PPPoE a esta interfaz.
-B interfaz
Añade la interfaz Ethernet interfaz a la lista de interfaces gestionadas por pppoe-relay. Se pueden conectar tanto clientes como servidores PPPoE a esta interfaz.
-n num
Permite un máximo de num sesiones PPPoE concurrentes. Si no se especifica, el valor predeterminado es 5000. num puede variar entre 1 y 65534.
-i tiempo_espera
Especifica el tiempo de espera de inactividad de la sesión. Si ambos participantes de una sesión están inactivos durante más de tiempo_espera segundos, la sesión se terminará. Si se especifica tiempo_espera como cero, las sesiones nunca se terminarán debido a la inactividad.

Tenga en cuenta que la rutina de expiración de sesiones inactivas nunca se ejecuta con una frecuencia mayor a cada 30 segundos, por lo que el tiempo de espera es aproximado. El valor predeterminado para tiempo_espera es de 600 segundos (10 minutos).

-F
La opción -F hace que pppoe-relay *no* se bifurque en segundo plano; en cambio, permanece en primer plano.
-h
La opción -h imprime un breve mensaje de uso y sale.

OPERACIÓN

pppoe-relay escucha las tramas PPPoE PADI entrantes en todas las interfaces especificadas con las opciones -B o -C. Cuando aparece una trama PADI, pppoe-relay añade una etiqueta Relay-Session-ID y difunde la PADI en todas las interfaces especificadas con las opciones -B o -S (excepto la interfaz en la que llegó la trama).

Cualquier trama PADO recibida se retransmite de vuelta al cliente que envió la PADI (suponiendo que contengan etiquetas Relay-Session-ID válidas). De manera similar, las tramas PADR de los clientes se retransmiten de vuelta al concentrador de acceso coincidente.

Cuando se recibe una trama PADS, pppoe-relay introduce las direcciones MAC y los ID de sesión de ambos participantes en una tabla hash. (El ID de sesión visto por el concentrador de acceso puede ser diferente del visto por el cliente; pppoe-relay debe renumerar las sesiones para evitar la posibilidad de ID de sesión duplicados). Cada vez que un participante envía una trama de sesión, pppoe-relay busca la entrada de sesión en la tabla hash y retransmite la trama al participante correcto.

Cuando se recibe una trama PADT, pppoe-relay la retransmite al participante y elimina la entrada de sesión de su tabla hash.

Si un cliente y un servidor fallan (o se pierden tramas), es posible que nunca se envíen tramas PADT, y la tabla hash de pppoe-relay puede llenarse de sesiones obsoletas. Por lo tanto, una rutina de limpieza de sesiones se ejecuta periódicamente y elimina las sesiones antiguas de la tabla hash. Una sesión se considera "antigua" si no se ha visto tráfico en tiempo_espera segundos. Cuando se elimina una sesión debido a un tiempo de espera, se envía una trama PADT a cada participante para asegurarse de que sean conscientes de que la sesión ha sido eliminada.

EJEMPLOS DE INVOCACIÓN

pppoe-relay -C eth0 -S eth1

El ejemplo anterior retransmite tramas entre clientes PPPoE en la red eth0 y servidores PPPoE en la red eth1.

pppoe-relay -B eth0 -B eth1

Este ejemplo es una retransmisión transparente: las tramas se retransmiten entre cualquier mezcla de clientes y servidores en las redes eth0 y eth1.

pppoe-relay -S eth0 -C eth1 -C eth2 -C eth3

Este ejemplo retransmite tramas entre servidores en la red eth0 y clientes en las redes eth1, eth2 y eth3.
