poll(2) Manual de llamadas al sistema poll(2)

NOMBRE

poll, ppoll - esperar a que ocurra algún evento en un descriptor de archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <poll.h>
int poll(struct pollfd *fds, nfds_t nfds, int timeout);
#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <poll.h>
int ppoll(struct pollfd *fds, nfds_t nfds,
          const struct timespec *_Nullable tmo_p,
          const sigset_t *_Nullable sigmask);

DESCRIPCIÓN

poll() realiza una tarea similar a select(2): espera a que uno de un conjunto de descriptores de archivo esté listo para realizar E/S. La API específica de Linux epoll(7) realiza una tarea similar, pero ofrece características más allá de las que se encuentran en poll().

El conjunto de descriptores de archivo a supervisar se especifica en el argumento fds, que es una matriz de estructuras de la siguiente forma:


struct pollfd {
    int   fd;         /* descriptor de archivo */
    short events;     /* eventos solicitados */
    short revents;    /* eventos devueltos */
};

El llamador debe especificar el número de elementos en la matriz fds en nfds.

El campo fd contiene un descriptor de archivo para un archivo abierto. Si este campo es negativo, entonces se ignora el campo events correspondiente y el campo revents devuelve cero. (Esto proporciona una forma fácil de ignorar un descriptor de archivo para una sola llamada a poll(): simplemente establezca el campo fd en su complemento a nivel de bits).

El campo events es un parámetro de entrada, una máscara de bits que especifica los eventos que interesan a la aplicación para el descriptor de archivo fd. Este campo puede especificarse como cero, en cuyo caso los únicos eventos que se pueden devolver en revents son POLLHUP, POLLERR y POLLNVAL (ver más abajo).

El campo revents es un parámetro de salida, rellenado por el kernel con los eventos que ocurrieron realmente. Los bits devueltos en revents pueden incluir cualquiera de los especificados en events, o uno de los valores POLLERR, POLLHUP o POLLNVAL. (Estos tres bits no son significativos en el campo events y se establecerán en el campo revents siempre que la condición correspondiente sea verdadera).

Si ninguno de los eventos solicitados (y ningún error) ha ocurrido para ninguno de los descriptores de archivo, entonces poll() se bloquea hasta que ocurre uno de los eventos.

Estar "listo" significa que la operación solicitada no se bloqueará; por lo tanto, el sondeo poll() de archivos regulares, dispositivos de bloque y otros archivos sin un semántico de sondeo razonable siempre devuelve instantáneamente como listo para leer y escribir.

Tenga en cuenta que el intervalo de timeout se redondeará hasta la granularidad del reloj del sistema, y los retrasos de programación del kernel significan que el intervalo de bloqueo puede excederse en una pequeña cantidad. Especificar un valor negativo en timeout significa un tiempo de espera infinito. Especificar un timeout de cero hace que poll() devuelva inmediatamente, incluso si ningún descriptor de archivo está listo.

Los bits que se pueden establecer/devolver en events y revents se definen en <poll.h>:

POLLIN
Hay datos para leer.
POLLPRI
Hay alguna condición excepcional en el descriptor de archivo. Las posibilidades incluyen:
•
Hay datos fuera de banda en un socket TCP (ver tcp(7)).
•
Un maestro de pseudoterminal en modo paquete ha visto un cambio de estado en el esclavo (ver ioctl_tty(2)).
•
Un archivo cgroup.events ha sido modificado (ver cgroups(7)).
POLLOUT
La escritura ahora es posible, aunque una escritura mayor que el espacio disponible en un socket o tubería aún se bloqueará (a menos que O_NONBLOCK esté configurado).
POLLRDHUP (desde Linux 2.6.17)
El par del socket de flujo cerró la conexión, o cerró la mitad de escritura de la conexión. El macro de prueba de características _GNU_SOURCE debe definirse (antes de incluir cualquier archivo de cabecera) para obtener esta definición.
POLLERR
Condición de error (solo devuelto en revents; ignorado en events). Este bit también se establece para un descriptor de archivo que se refiere al extremo de escritura de una tubería cuando el extremo de lectura se ha cerrado.
POLLHUP
Colgadura (solo devuelto en revents; ignorado en events). Tenga en cuenta que al leer de un canal como una tubería o un socket de flujo, este evento solo indica que el par cerró su extremo del canal. Las lecturas posteriores del canal devolverán 0 (fin de archivo) solo después de que todos los datos pendientes en el canal hayan sido consumidos.
POLLNVAL
Solicitud inválida: fd no abierto (solo devuelto en revents; ignorado en events).

Al compilar con _XOPEN_SOURCE definido, también tiene lo siguiente, que no transmiten más información que los bits mencionados anteriormente:

POLLRDNORM
Equivalente a POLLIN.
POLLRDBAND
Se pueden leer datos de banda de prioridad (generalmente no utilizados en Linux).
POLLWRNORM
Equivalente a POLLOUT.
POLLWRBAND
Se pueden escribir datos de prioridad.

Linux también conoce, pero no utiliza, POLLMSG.

ppoll()

La relación entre poll() y ppoll() es análoga a la relación entre select(2) y pselect(2): al igual que pselect(2), ppoll() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo esté listo o hasta que se capture una señal.

Aparte de la diferencia en la precisión del argumento timeout, la siguiente llamada a ppoll():


ready = ppoll(&fds, nfds, tmo_p, &sigmask);

es casi equivalente a ejecutar atmicamente las siguientes llamadas:


sigset_t origmask;
int timeout;
timeout = (tmo_p == NULL) ? -1 :
          (tmo_p->tv_sec * 1000 + tmo_p->tv_nsec / 1000000);
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = poll(&fds, nfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

El segmento de código anterior se describe como casi equivalente porque, mientras que un valor de timeout negativo para poll() se interpreta como un tiempo de espera infinito, un valor negativo expresado en *tmo_p resulta en un error de ppoll().

Ver la descripción de pselect(2) para una explicación de por qué ppoll() es necesario.

Si el argumento sigmask se especifica como NULL, no se realiza ninguna manipulación de la máscara de señales (y, por lo tanto, ppoll() difiere de poll() solo en la precisión del argumento timeout).

El argumento tmo_p especifica un límite superior en la cantidad de tiempo que ppoll() se bloqueará. Este argumento es un puntero a una estructura timespec(3).

Si tmo_p se especifica como NULL, entonces ppoll() puede bloquearse indefinidamente.

VALOR DE RETORNO

RETURN VALUE

On success, poll() returns a nonnegative value which is the number of elements in the pollfds whose revents fields have been set to a nonzero value (indicating an event or an error). A return value of zero indicates that the system call timed out before any file descriptors became ready.

On error, -1 is returned, and errno is set to indicate the error.

ERRORS

EFAULT
fds points outside the process's accessible address space. The array given as argument was not contained in the calling program's address space.
EINTR
A signal occurred before any requested event; see signal(7).
EINVAL
The nfds value exceeds the RLIMIT_NOFILE value.
EINVAL
(ppoll()) The timeout value expressed in *tmo_p is invalid (negative).
ENOMEM
Unable to allocate memory for kernel data structures.

VERSIONS

On some other UNIX systems, poll() can fail with the error EAGAIN if the system fails to allocate kernel-internal resources, rather than ENOMEM as Linux does. POSIX permits this behavior. Portable programs may wish to check for EAGAIN and loop, just as with EINTR.

Some implementations define the nonstandard constant INFTIM with the value -1 for use as a timeout for poll(). This constant is not provided in glibc.

C library/kernel differences

The Linux ppoll() system call modifies its tmo_p argument. However, the glibc wrapper function hides this behavior by using a local variable for the timeout argument that is passed to the system call. Thus, the glibc ppoll() function does not modify its tmo_p argument.

The raw ppoll() system call has a fifth argument, size_t sigsetsize, which specifies the size in bytes of the sigmask argument. The glibc ppoll() wrapper function specifies this argument as a fixed value (equal to sizeof(kernel_sigset_t)). See sigprocmask(2) for a discussion on the differences between the kernel and the libc notion of the sigset.

STANDARDS

POSIX.1-2024.

HISTORY

poll()
POSIX.1-2001. Linux 2.1.23.
On older kernels that lack this system call, the glibc poll() wrapper function provides emulation using select(2).
ppoll()
POSIX.1-2024. Linux 2.6.16, glibc 2.4.

NOTES

The operation of poll() and ppoll() is not affected by the O_NONBLOCK flag.

For a discussion of what may happen if a file descriptor being monitored by poll() is closed in another thread, see select(2).

BUGS

See the discussion of spurious readiness notifications under the BUGS section of select(2).

EXAMPLES

The program below opens each of the files named in its command-line arguments and monitors the resulting file descriptors for readiness to read (POLLIN). The program loops, repeatedly using poll() to monitor the file descriptors, printing the number of ready file descriptors on return. For each ready file descriptor, the program:

•
displays the returned revents field in a human-readable form;
•
if the file descriptor is readable, reads some data from it, and displays that data on standard output; and
•
if the file descriptor was not readable, but some other event occurred (presumably POLLHUP), closes the file descriptor.

Suppose we run the program in one terminal, asking it to open a FIFO:


$ mkfifo myfifo;
$ ./poll_input myfifo;

In a second terminal window, we then open the FIFO for writing, write some data to it, and close the FIFO:


$ echo aaaaabbbbbccccc > myfifo;

In the terminal where we are running the program, we would then see:


Opened "myfifo" on fd 3
About to poll()
Ready: 1
  fd=3; events: POLLIN POLLHUP
    read 10 bytes: aaaaabbbbb
About to poll()
Ready: 1
  fd=3; events: POLLIN POLLHUP
    read 6 bytes: ccccc
About to poll()
Ready: 1
  fd=3; events: POLLHUP
    closing fd 3
All file descriptors closed.  Bye.

In the above output, we see that poll() returned three times:

•
On the first return, the bits returned in the revents field were POLLIN, indicating that the file descriptor is readable, and POLLHUP, indicating that the other end of the FIFO has been closed. The program then consumed some of the available input.
•
The second return from poll() also indicated POLLIN and POLLHUP; the program then consumed the last of the available input.
•
On the final return, poll() indicated only POLLHUP on the FIFO, at which point the file descriptor was closed and the program terminated.

Program source

/* poll_input.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <fcntl.h>
#include <poll.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int            ready;
    char           buf[10];
    nfds_t         num_open_fds, nfds;
    ssize_t        s;
    struct pollfd  *pfds;
    if (argc < 2) {
       fprintf(stderr, "Usage: %s file...\n", argv[0]);
       exit(EXIT_FAILURE);
    }
    num_open_fds = nfds = argc - 1;
    pfds = calloc(nfds, sizeof(struct pollfd));
    if (pfds == NULL)
        err(EXIT_FAILURE, "malloc");
    /* Open each file on command line, and add it to 'pfds' array.  */
    for (nfds_t j = 0; j < nfds; j++) {
        pfds[j].fd = open(argv[j + 1], O_RDONLY);
        if (pfds[j].fd == -1)
            err(EXIT_FAILURE, "open");
        printf("Opened \"%s\" on fd %d\n", argv[j + 1], pfds[j].fd);
        pfds[j].events = POLLIN;
    }
    /* Keep calling poll() as long as at least one file descriptor is
       open.  */
    while (num_open_fds > 0) {
        printf("About to poll()\n");
        ready = poll(pfds, nfds, -1);
        if (ready == -1)
            err(EXIT_FAILURE, "poll");
        printf("Ready: %d\n", ready);
        /* Deal with array returned by poll().  */
        for (nfds_t j = 0; j < nfds; j++) {
            if (pfds[j].revents != 0) {
                printf("  fd=%d; events: %s%s%s\n", pfds[j].fd,
                       (pfds[j].revents & POLLIN)  ? "POLLIN "  : "",
                       (pfds[j].revents & POLLHUP) ? "POLLHUP " : "",
                       (pfds[j].revents & POLLERR) ? "POLLERR " : "");
                if (pfds[j].revents & POLLIN) {
                    s = read(pfds[j].fd, buf, sizeof(buf));
                    if (s == -1)
                        err(EXIT_FAILURE, "read");
                    printf("    read %zd bytes: %.*s\n",
                           s, (int) s, buf);
                } else {                /* POLLERR | POLLHUP */
                    printf("    closing fd %d\n", pfds[j].fd);
                    if (close(pfds[j].fd) == -1)
                        err(EXIT_FAILURE, "close");
                    num_open_fds--;
                }
            }
        }
    }
    printf("All file descriptors closed.  Bye.\n");
    exit(EXIT_SUCCESS);
}

ppoll(2)

NAME

ppoll - esperar por eventos en un conjunto de descriptores de archivo, con tiempo de espera, y obtener eventos notificados de forma atómica

SYNOPSIS

#include <poll.h>

int ppoll(struct pollfd *fds, nfds_t nfds,
          const struct timespec *timeout, const sigset_t *sigmask);

DESCRIPTION

La llamada al sistema ppoll es similar a poll (2), pero tiene las siguientes diferencias:

  1. Si timeout no es NULL, entonces apunta a una estructura timespec que especifica el intervalo de tiempo de espera máximo. poll usa una estructura timeval .
  2. El argumento sigmask permite especificar una máscara de señales que se utilizará durante la espera. Si sigmask no es NULL, la máscara de señales se establece en la máscara de señales del hilo antes de que comience la espera, y la máscara de señales se restaura a su valor original después de que ppoll regrese. Si sigmask es NULL, entonces se utiliza la máscara de señales del hilo existente y no se modifica.

Los argumentos fds y nfds son los mismos que para poll . El argumento timeout puede ser NULL, en cuyo caso ppoll esperará indefinidamente.

ppoll devuelve el número de descriptores de archivo en fds que tienen eventos pendientes, o 0 si el tiempo de espera expira, o -1 en caso de error.

RETURN VALUE

En caso de éxito, ppoll devuelve el número de descriptores de archivo que tienen eventos pendientes. Este número es un subconjunto del rango [0, nfds-1] . Una devolución de 0 indica que el tiempo de espera expiró.

En caso de error, ppoll devuelve -1 y errno se establece para indicar el error.

ERRORS

EBADF
Un descriptor de archivo en fds no es válido.
EINTR
Una llamada interrumpida por una señal.
EINVAL
nfds es mayor que FD_SETSIZE ; o fds es NULL; o el valor timeout es inválido.
ENOMEM
No hay suficiente memoria disponible.

VERSIONS

La llamada al sistema ppoll está disponible desde el kernel de Linux 2.6.15.

STANDARDS

ppoll es una extensión de Linux. No forma parte de ningún estándar.

HISTORY

ppoll fue introducida en el kernel de Linux 2.6.15.

NOTES

A diferencia de poll , ppoll acepta un puntero a una estructura timespec para el tiempo de espera, lo que permite una mayor precisión. Además, ppoll permite controlar la máscara de señales durante la espera, lo que puede ser útil para evitar condiciones de carrera con señales.

BUGS

No hay errores conocidos.

EXAMPLES

El siguiente ejemplo muestra cómo usar ppoll para esperar hasta 5 segundos en un descriptor de archivo para entrada:

#include <stdio.h>
#include <stdlib.h>
#include <poll.h>
#include <time.h>
#include <errno.h>
#include <fcntl.h>

int main() {
    struct pollfd fds;
    struct timespec timeout;
    int ret;

    // Abre un descriptor de archivo (ej. stdin)
    fds.fd = STDIN_FILENO;
    fds.events = POLLIN; // Espera por datos de entrada

    // Establece el tiempo de espera a 5 segundos
    timeout.tv_sec = 5;
    timeout.tv_nsec = 0;

    printf("Esperando hasta 5 segundos por entrada...\n");

    ret = ppoll(&fds, 1, &timeout, NULL);

    if (ret == -1) {
        perror("ppoll");
        exit(EXIT_FAILURE);
    } else if (ret == 0) {
        printf("El tiempo de espera expiró.\n");
    } else {
        if (fds.revents & POLLIN) {
            printf("¡Hay datos disponibles para leer!\n");
            // Aquí puedes leer los datos
        }
    }

    return 0;
}
