NOMBRE

ppmtoilbm - convierte una imagen PPM a un archivo ILBM

SINOPSIS

ppmtoilbm

[-maxplanes|-mp N]

[-fixplanes|-fp N]

[-ham6|-ham8]

[ {-dcbits|-dcplanes} r g b ]

[ -normal|-hamif|-hamforce|-24if|-24force| -dcif|-dcforce|-cmaponly ]

[-ecs|-aga]

[-compress|-nocompress]

[-cmethod tipo]

[-map archivo_ppm]

[-savemem]

[archivo_ppm]

DESCRIPCIÓN

Este programa forma parte de Netpbm(1)

ppmtoilbm lee una imagen PPM como entrada. Produce un archivo ILBM como salida. ppmtoilbm entiende los siguientes tipos de ILBM:

  • ILBMs normales con 1-16 planos
  • Amiga HAM con 3-16 planos
  • 24 bits
  • Mapa de colores (solo chunks BMHD y CMAP, nPlanes = 0)
  • Color directo no oficial. 1-16 planos para cada componente de color.

Chunks escritos: BMHD, CMAP, CAMG (solo para HAM), BODY (no para archivos de mapa de colores) chunk DCOL no oficial para ILBM de color directo.

OPCIONES

Las opciones marcadas con (*) pueden ir precedidas de 'no', por ejemplo '-nohamif'. Todas las opciones se pueden abreviar a su prefijo único más corto.

-maxplanes | -mp n
(por defecto 5, mínimo 1, máximo 16) Máximo de planos a escribir en un ILBM normal. Si la imagen no cabe en <n> planos, ppmtoilbm escribe un archivo HAM (si se usa -hamif), un archivo de 24 bits (si se usa -24if) o un archivo de color directo (si se usa -dcif) o aborta con un error.
-fixplanes | -fp n
(mínimo 1, máximo 16) Si se escribe un ILBM normal, tendrá exactamente <n> planos.
-hambits | -hamplanes n
(por defecto 6, mínimo 3, máximo 16) Selecciona el número de planos para la imagen HAM. El hardware Amiga actual soporta 6 y 8 planos, así que por ahora solo deberías usar estos valores.
-normal
Desactiva -hamif/-24if/-dcif, -hamforce/-24force/-dcforce y -cmaponly. También establece el tipo de compresión a byterun1.

Este es el valor por defecto.

-hamif (*)
-24if (*)
-dcif (*)
Escribe un archivo HAM/24 bits/color directo si la imagen no cabe en <maxplanes> planos.
-hamforce (*)
-24force (*)
-dcforce (*)
Escribe un archivo HAM/24 bits/color directo.
-dcbits r g b
-dcplanes r g b
(por defecto 5, mínimo 1, máximo 16). Selecciona el número de bits para rojo, verde y azul en un ILBM de color directo.
-ecs
Atajo para: -hamplanes 6 -maxplanes 5

Este es el valor por defecto.

-aga
Atajo para: -hamplanes 8 -maxplanes 8
-ham6
Atajo para: -hamplanes 6 -hamforce
-ham8
Atajo para: -hamplanes 8 -hamforce
-compress (*)
Este es el valor por defecto. Comprime el chunk BODY. El método de compresión por defecto es byterun1. La compresión requiere construir la imagen ILBM en memoria; desactivar la compresión permite escribir la imagen en flujo, pero el archivo resultante será generalmente entre un 30% y un 50% más grande. Otra alternativa es la opción -savemem, que mantendrá los requisitos de memoria para la compresión al mínimo, pero es muy lenta.
-cmethod none|byterun1
Esta opción hace lo mismo que -compress.
-map archivo_ppm
Escribe un ILBM normal usando los colores en <archivo_ppm> como mapa de colores. El archivo del mapa de colores también determina el número de planos, se ignora una opción -maxplanes o -fixplanes.
-cmaponly
Escribe un archivo de mapa de colores: solo chunks BMHD y CMAP, sin chunk BODY, nPlanes = 0.
-savemem
Ver la opción -compress.

LIMITACIONES

Las imágenes HAM obtendrán siempre un mapa de colores en escala de grises; un algoritmo de selección de color real podría dar mejores resultados. Por otro lado, esto permite la operación fila por fila en imágenes HAM, y todas las imágenes HAM de la misma profundidad (número de planos) comparten un mapa de colores común, lo cual es útil para construir animaciones HAM.
