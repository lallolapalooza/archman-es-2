PPPD(8) Manual del Administrador del Sistema PPPD(8)

NOMBRE

pppd - Demonio del Protocolo Punto a Punto

SINOPSIS

pppd [ opciones ]

DESCRIPCIÓN

PPP es el protocolo utilizado para establecer enlaces de Internet a través de módems de acceso telefónico, conexiones DSL y muchos otros tipos de enlaces punto a punto. El demonio pppd trabaja junto con el controlador PPP del kernel para establecer y mantener un enlace PPP con otro sistema (llamado par) y para negociar las direcciones de Protocolo de Internet (IP) para cada extremo del enlace. Pppd también puede autenticar al par y/o proporcionar información de autenticación al par. PPP se puede usar con otros protocolos de red además de IP, pero este uso es cada vez menos común.

OPCIONES DE USO FRECUENTE

nombre_tty
Utiliza el puerto serie llamado nombre_tty para comunicarse con el par. Si nombre_tty no comienza con una barra (/) , se antepone la cadena "/dev/" a nombre_tty para formar el nombre del dispositivo a abrir. Si no se proporciona un nombre de dispositivo, o si se proporciona el nombre de la terminal conectada a la entrada estándar, pppd utilizará esa terminal y no se bifurcará para ponerse en segundo plano. Un valor para esta opción de una fuente privilegiada no puede ser anulado por un usuario no privilegiado.
velocidad
Una opción que es un número decimal se toma como la velocidad en baudios deseada para el dispositivo serie. En sistemas como Linux, 4.4BSD y NetBSD, se puede especificar cualquier velocidad. Otros sistemas (por ejemplo, SunOS) solo admiten las velocidades en baudios de uso común.
mapa_asincrono mapa
Esta opción establece el Mapa de Caracteres de Control Asíncronos (ACCM) para este extremo del enlace. El ACCM es un conjunto de 32 bits, uno para cada carácter de control ASCII con valores de 0 a 31, donde un bit de 1 indica que el carácter de control correspondiente no debe usarse en los paquetes PPP enviados a este sistema. El mapa se codifica como un número hexadecimal (sin un prefijo 0x) donde el bit menos significativo (00000001) representa el carácter 0 y el bit más significativo (80000000) representa el carácter 31. Pppd le pedirá al par que envíe estos caracteres como una secuencia de escape de 2 bytes. Si se proporcionan varios mapa_asincrono opciones, los valores se combinan mediante OR. Si no se proporciona ninguna opción mapa_asincrono, el valor predeterminado es cero, por lo que pppd le pedirá al par que no escape ningún carácter de control. Para escapar caracteres transmitidos, use la opción escape.
autenticacion
Requerir que el par se autentique antes de permitir el envío o recepción de paquetes de red. Esta opción es la predeterminada si el sistema tiene una ruta predeterminada. Si no se especifica esta opción ni la opción noautenticacion, pppd solo permitirá al par usar direcciones IP a las que el sistema aún no tiene una ruta.
llamada nombre
Lea opciones adicionales del archivo /etc/ppp/peers/nombre. Este archivo puede contener opciones privilegiadas, como noautenticacion, incluso si pppd no está siendo ejecutado por root. La cadena nombre no puede comenzar con / ni incluir .. como componente de ruta de nombre de archivo. El formato del archivo de opciones se describe a continuación.
conectar script
Normalmente hay algo que debe hacerse para preparar el enlace antes de que se pueda iniciar el protocolo PPP; por ejemplo, con un módem de acceso telefónico, se deben enviar comandos al módem para marcar el número de teléfono apropiado. Esta opción especifica un comando para que pppd lo ejecute (pasándolo a un shell) antes de intentar iniciar la negociación PPP. El programa chat (8) es a menudo útil aquí, ya que proporciona una forma de enviar cadenas arbitrarias a un módem y responder a los caracteres recibidos. Un valor para esta opción de una fuente privilegiada no puede ser anulado por un usuario no privilegiado.
crtscts
Especifica que pppd debe configurar el puerto serie para usar control de flujo por hardware utilizando las señales RTS y CTS en la interfaz RS-232. Si no se proporciona la opción crtscts, nocrtscts, cdtrcts o nocdtrcts, la configuración de control de flujo por hardware para el puerto serie no se modifica. Algunos puertos serie (como los puertos serie de Macintosh) carecen de una salida RTS real. Dichos puertos serie usan este modo para implementar el control de flujo unidireccional. El puerto serie suspenderá la transmisión cuando lo solicite el módem (a través de CTS), pero no podrá solicitar al módem que deje de enviar datos a la computadora. Este modo conserva la capacidad de usar DTR como línea de control del módem.
ruta_predeterminada
Agregue una ruta predeterminada a las tablas de enrutamiento del sistema, utilizando el par como puerta de enlace, cuando la negociación IPCP se complete con éxito. Esta entrada se elimina cuando se interrumpe la conexión PPP. Esta opción es privilegiada si se ha especificado la opción noruta_predeterminada.
ruta_predeterminada-metrica
Define la métrica de ruta_predeterminada y solo la agrega si no hay otra ruta predeterminada con la misma métrica. Con el valor predeterminado de -1, la ruta solo se agrega si no hay ninguna ruta predeterminada en absoluto.
reemplazar_ruta_predeterminada
Esta opción es una bandera para la opción ruta_predeterminada. Si ruta_predeterminada está establecida y esta bandera también está establecida, pppd reemplaza una ruta predeterminada existente con la nueva ruta predeterminada. Esta opción es privilegiada.
desconectar script
Ejecute el comando especificado por script, pasándolo a un shell, después de que pppd haya terminado el enlace. Este comando podría, por ejemplo, emitir comandos al módem para que cuelgue si no había señales de control de módem por hardware disponibles. El script de desconexión no se ejecuta si el módem ya ha colgado. Un valor para esta opción de una fuente privilegiada no puede ser anulado por un usuario no privilegiado.
escapar xx,yy,...
Especifica que ciertos caracteres deben ser escapados en la transmisión (independientemente de si el par los solicita que sean escapados con su mapa de caracteres de control asíncrono). Los caracteres que deben ser escapados se especifican como una lista de números hexadecimales separados por comas. Tenga en cuenta que casi cualquier carácter se puede especificar para la opción escapar, a diferencia de la opción mapa_asincrono que solo permite especificar caracteres de control. Los caracteres que no se pueden escapar son aquellos con valores hexadecimales de 0x20 a 0x3f o 0x5e.
archivo nombre
Lea las opciones del archivo nombre (el formato se describe a continuación). El archivo debe ser legible por el usuario que invocó pppd.
iniciar script
Ejecute el comando especificado por script, pasándolo a un shell, para inicializar la línea serie. Este script típicamente usaría el programa chat(8) para configurar el módem y habilitar la respuesta automática. Un valor para esta opción de una fuente privilegiada no puede ser anulado por un usuario no privilegiado.
bloquear
Especifica que pppd debe crear un archivo de bloqueo estilo UUCP para el dispositivo serie para garantizar un acceso exclusivo al dispositivo. Por defecto, pppd no creará un archivo de bloqueo.
mru n
Establece el valor de MRU [Maximum Receive Unit] en n. Pppd le pedirá al par que envíe paquetes de no más de n bytes. El valor de n debe estar entre 128 y 16384; el valor predeterminado es 1500. Un valor de 296 funciona bien en enlaces muy lentos (40 bytes para la cabecera TCP/IP + 256 bytes de datos). Tenga en cuenta que para el protocolo IPv6, el MRU debe ser de al menos 1280.
mtu n
Establece el valor de MTU [Maximum Transmit Unit] en n. A menos que el par solicite un valor menor a través de la negociación MRU, pppd solicitará al código de red del kernel que envíe paquetes de datos de no más de n bytes a través de la interfaz de red PPP. Tenga en cuenta que para el protocolo IPv6, el MTU debe ser de al menos 1280.
pasivo
Indica a pppd que se ponga en modo pasivo y espere a que el par inicie la conexión. Esto es útil para servidores que responden a llamadas entrantes. Si se especifica esta opción, pppd no intentará iniciar la conexión activamente.

PASSIVE

passive
Habilita la opción "passive" en el LCP. Con esta opción, pppd intentará iniciar una conexión; si no se recibe ninguna respuesta del par, pppd simplemente esperará pasivamente un paquete LCP válido del par, en lugar de salir, como lo haría sin esta opción.

OPTIONS

<IP_local>:<IP_remota>
Establece las direcciones IP de la interfaz local y/o remota. Cualquiera de ellas puede omitirse. Las direcciones IP se pueden especificar con un nombre de host o en notación decimal de puntos (por ejemplo, 150.234.56.78). La dirección local por defecto es la (primera) dirección IP del sistema (a menos que se proporcione la opción noipdefault). La dirección remota se obtendrá del par si no se especifica en ninguna opción. Por lo tanto, en casos simples, esta opción no es necesaria. Si se especifica una dirección IP local y/o remota con esta opción, pppd no aceptará un valor diferente del par en la negociación IPCP, a menos que se proporcionen las opciones ipcp-accept-local y/o ipcp-accept-remote, respectivamente.
+ipv6
Habilita los protocolos IPv6CP e IPv6.
ipv6 <identificador_interfaz_local>,<identificador_interfaz_remota>
Establece el identificador de interfaz local y/o remoto de 64 bits. Cualquiera de ellos puede omitirse. El identificador debe especificarse en notación ASCII estándar de direcciones IPv6 (por ejemplo, ::dead:beef). Si se proporciona la opción ipv6cp-use-ipaddr, el identificador local es la dirección IPv4 local y el identificador remoto es la dirección IPv4 remota (ver arriba). Si se proporciona la opción ipv6cp-use-remotenumber, el identificador remoto se establece al valor de la opción remotenumber. En sistemas que admiten un ID persistente único, como EUI-48 derivado de la dirección MAC de Ethernet, se puede usar la opción ipv6cp-use-persistent para establecer el identificador local. De lo contrario, tanto los identificadores locales como los remotos se aleatorizan.
active-filter expresión_filtro
Especifica un filtro de paquetes que se aplicará a los paquetes de datos para determinar qué paquetes se consideran actividad del enlace y, por lo tanto, restablecen el temporizador de inactividad o hacen que el enlace se active en modo de marcación a demanda. Esta opción es útil en conjunción con la opción idle si hay paquetes que se envían o reciben regularmente a través del enlace (por ejemplo, paquetes de información de enrutamiento) que de otra manera impedirían que el enlace pareciera inactivo. La sintaxis de la expresión_filtro es la descrita para tcpdump(1), excepto que los calificadores que son inapropiados para un enlace PPP, como ether y arp, no están permitidos. Generalmente, la expresión del filtro debe ir entre comillas simples para evitar que el espacio en blanco en la expresión sea interpretado por el shell. Esta opción está actualmente disponible solo en Linux y requiere que el kernel se haya configurado para incluir soporte de filtrado PPP (CONFIG_PPP_FILTER). Tenga en cuenta que es posible aplicar diferentes restricciones a los paquetes entrantes y salientes usando los calificadores inbound y outbound.
allow-ip dirección(es)
Permite a los pares usar la dirección IP o subred dada sin autenticarse. El parámetro se analiza igual que cada elemento de la lista de direcciones IP permitidas en los archivos de secretos (ver la sección AUTHENTICATION abajo).
allow-number número
Permite a los pares conectarse desde el número de teléfono dado. Un carácter `*' al final coincidirá con todos los números que comiencen con la parte previa.
bsdcomp nr,nt
Solicita que el par comprima los paquetes que envía, utilizando el esquema BSD-Compress, con un tamaño de código máximo de nr bits, y acepta comprimir los paquetes enviados al par con un tamaño de código máximo de nt bits. Si nt no se especifica, por defecto toma el valor dado para nr. Se pueden usar valores en el rango de 9 a 15 para nr y nt; valores más grandes ofrecen mejor compresión pero consumen más memoria del kernel para los diccionarios de compresión. Alternativamente, un valor de 0 para nr o nt deshabilita la compresión en la dirección correspondiente. Use nobsdcomp o bsdcomp 0 para deshabilitar la compresión BSD-Compress por completo.
ca archivo_ca
(EAP-TLS, o PEAP) Utiliza el archivo archivo_ca como archivo de Autoridad de Certificación (CA) X.509 (en formato PEM), necesario para establecer una conexión EAP-TLS. Esta opción se usa en el lado del cliente en conjunción con las opciones cert y key. Las opciones ca o capath son requeridas para PEAP. EAP-TLS también puede usar la entrada en eaptls-client o eaptls-server para un certificado de CA asociado con un par particular.
capath ruta
(EAP-TLS, o PEAP) Especifica una ubicación que contiene certificados de CA públicos. Las opciones ca o capath son requeridas para PEAP.
cdtrcts
Utiliza un control de flujo de hardware no estándar (es decir, DTR/CTS) para controlar el flujo de datos en el puerto serie. Si no se proporciona la opción crtscts, nocrtscts, cdtrcts ni nocdtrcts, la configuración de control de flujo de hardware para el puerto serie no se modifica. Algunos puertos serie (como los puertos serie de Macintosh) carecen de una salida RTS real. Estos puertos serie usan este modo para implementar un control de flujo bidireccional real. El sacrificio es que este modo de control de flujo no permite usar DTR como línea de control del módem.
cert archivo_cert
(EAP-TLS) Utiliza el archivo archivo_cert como certificado X.509 (en formato PEM), necesario para establecer una conexión EAP-TLS. Esta opción se usa en el lado del cliente en conjunción con las opciones ca y key.
chap-interval n
Si se proporciona esta opción, pppd desafiará al par cada n segundos.
chap-max-challenge n
Establece el número máximo de transmisiones de desafío CHAP a n (por defecto 10).
chap-restart n
Establece el intervalo de reinicio de CHAP (tiempo de espera de retransmisión para los desafíos) a n segundos (por defecto 3).
chap-timeout n
Establece el tiempo de espera para la autenticación CHAP por el par a n segundos (por defecto 60).
chapms-strip-domain
Algunos clientes Windows 9x/ME podrían transmitir el dominio MS antes del nombre de usuario en el nombre de cliente proporcionado. Esta opción permite eliminar el dominio del nombre de cliente en el lado del servidor antes de compararlo con el archivo de secretos.
child-timeout n
Al salir, espera hasta n segundos a que los procesos hijos (como el comando especificado con el comando pty) salgan antes de terminar. Al final del tiempo de espera, pppd enviará una señal SIGTERM a cualquier proceso hijo restante y saldrá. Un valor de 0 significa que no hay tiempo de espera, es decir, pppd esperará hasta que todos los procesos hijos hayan salido.
connect-delay n
Espera hasta n milisegundos después de que el script de conexión termine para recibir un paquete PPP válido del par. Al final de este tiempo, o cuando se reciba un paquete PPP válido del par, pppd iniciará la negociación enviando su primer paquete LCP. El valor por defecto es 1000 (1 segundo). Este período de espera solo se aplica si se utiliza la opción connect o pty.
crl nombre_archivo
(EAP-TLS, o PEAP) Utiliza el archivo nombre_archivo como Lista de Revocación de Certificados para verificar la validez del certificado del par. Esta opción no es obligatoria para establecer una conexión TLS. Vea también la opción crl-dir.
crl-dir directorio
(EAP-TLS, o PEAP) Utiliza el directorio directorio para buscar archivos CRL en formato hash ($hash.r0) para verificar la validez del certificado del par. Esta opción no es obligatoria para establecer una conexión TLS. Vea también la opción crl.
debug
Habilita las instalaciones de depuración de conexión. Si se proporciona esta opción, pppd registrará el contenido de todos los paquetes de control enviados o recibidos en un formato legible. Los paquetes se registran a través de syslog con la instalación daemon y el nivel debug. Esta información se puede dirigir a un archivo configurando apropiadamente /etc/syslog.conf (ver syslog.conf(5)).
default-asyncmap
Deshabilita la negociación asyncmap, forzando que todos los caracteres de control sean escapados tanto para la dirección de transmisión como para la de recepción.
default-mru
Deshabilita la negociación de MRU [Maximum Receive Unit]. Con esta opción, pppd utilizará el valor MRU por defecto de 1500 bytes tanto para la dirección de transmisión como para la de recepción.
defaultroute6
Agrega una ruta IPv6 por defecto a las tablas de enrutamiento del sistema, utilizando el par como gateway, cuando la negociación IPv6CP se completa con éxito. Esta entrada se elimina cuando se interrumpe la conexión PPP. Esta opción es privilegiada si se ha especificado la opción nodefaultroute6. **ADVERTENCIA: No habilite esta opción por defecto**. Las tablas de enrutamiento IPv6 son gestionadas por el kernel (a diferencia de IPv4) y la ruta por defecto IPv6 también es configurada automáticamente por el kernel basándose en los paquetes de anuncio de router ICMPv6. Esta opción puede entrar en conflicto con la configuración de rutas IPv6 del kernel y solo debe usarse para redes IPv6 defectuosas.
deflate nr,nt
Solicita que el par comprima los paquetes que envía, utilizando el esquema Deflate, con un tamaño de ventana máximo de 2**nr bytes, y acepta comprimir los paquetes enviados al par con un tamaño de ventana máximo de 2**nt bytes. Si nt no se especifica, por defecto toma el valor dado para nr. Se pueden usar valores en el rango de 9 a 15 para nr y nt; valores más grandes ofrecen mejor compresión pero consumen más
e kernel memory para diccionarios de compresión. Alternativamente, un valor de 0 para nr o nt deshabilita la compresión en la dirección correspondiente. Usa nodeflate o deflate 0 para deshabilitar completamente la compresión Deflate. (Nota: pppd solicita la compresión Deflate con preferencia sobre BSD-Compress si el par puede hacer cualquiera de las dos.)
demand
Inicia el enlace solo bajo demanda, es decir, cuando hay tráfico de datos. Con esta opción, la dirección IP remota puede ser especificada por el usuario en la línea de comandos o en un archivo de opciones, o si no, pppd usará una dirección arbitraria en el rango 10.x.x.x. Pppd configurará inicialmente la interfaz y la habilitará para tráfico IP sin conectarse al par. Cuando haya tráfico disponible, pppd se conectará al par y realizará la negociación, autenticación, etc. Una vez completado esto, pppd comenzará a pasar paquetes de datos (es decir, paquetes IP) a través del enlace.

La opción demand implica la opción persist. Si este comportamiento no se desea, usa la opción nopersist después de la opción demand. Las opciones idle y holdoff también son útiles en conjunto con la opción demand.

domain d
Añade el nombre de dominio d al nombre del host local para fines de autenticación. Por ejemplo, si gethostname() devuelve el nombre porsche, pero el nombre de dominio completo es porsche.Quotron.COM, puedes especificar domain Quotron.COM. Pppd usaría entonces el nombre porsche.Quotron.COM para buscar secretos en el archivo de secretos, y como el nombre predeterminado para enviar al par al autenticarse ante él. Esta opción es privilegiada.
dryrun
Con la opción dryrun, pppd imprimirá todos los valores de opción que se hayan establecido y luego saldrá, después de analizar la línea de comandos y los archivos de opciones y verificar los valores de las opciones, pero antes de iniciar el enlace. Los valores de las opciones se registran con el nivel info, y también se imprimen en la salida estándar a menos que el dispositivo en la salida estándar sea el dispositivo que pppd usaría para comunicarse con el par.
dump
Con la opción dump, pppd imprimirá todos los valores de opción que se hayan establecido. Esta opción es como la opción dryrun, excepto que pppd procede normalmente en lugar de salir.
enable-session
Habilita la contabilidad de sesiones a través de PAM o wtwp/wtmpx, según corresponda. Cuando PAM está habilitado, las pilas de módulos "account" y "session" de PAM determinan el comportamiento, y se habilitan para todos los protocolos de autenticación PPP. Cuando PAM está deshabilitado, se registran entradas wtmp/wtmpx independientemente de si el nombre del par identifica a un usuario válido en el sistema local, haciendo visibles a los pares en el log de last(1). Esta característica se habilita automáticamente cuando se usa la opción login de pppd. La contabilidad de sesiones está deshabilitada por defecto.
endpoint <epdisc>
Establece el discriminador de punto final enviado por la máquina local al par durante la negociación multilink a <epdisc>. El valor predeterminado es usar la dirección MAC de la primera interfaz ethernet del sistema, si existe, de lo contrario la dirección IPv4 correspondiente al nombre de host, si existe, siempre que no esté en los rangos de direcciones IP multidifusión o asignadas localmente, o la dirección de localhost. El discriminador de punto final puede ser la cadena null o tener el formato tipo:valor, donde tipo es un número decimal o una de las cadenas local, IP, MAC, magic, o phone. El valor es una dirección IP en notación decimal punto para el tipo IP, o una cadena de bytes en hexadecimal, separada por puntos o dos puntos para los otros tipos. Para el tipo MAC, el valor también puede ser el nombre de una interfaz de red ethernet o similar. Esta opción actualmente solo está disponible en Linux.
eap-interval n
Si se proporciona esta opción y pppd autentica al par con EAP (es decir, es el servidor), pppd reiniciará la autenticación EAP cada n segundos. Para EAP SRP-SHA1, consulta también la opción srp-interval, que habilita el desafiado ligero.
eap-max-rreq n
Establece el número máximo de Solicitudes EAP a las que pppd responderá (como cliente) sin recibir Éxito o Fallo EAP. (Predeterminado es 20.)
eap-max-sreq n
Establece el número máximo de Solicitudes EAP que pppd emitirá (como servidor) mientras intenta la autenticación. (Predeterminado es 10.)
eap-restart n
Establece el tiempo de espera de retransmisión para las Solicitudes EAP cuando actúa como servidor (autenticador). (Predeterminado es 3 segundos.)
eap-timeout n
Establece el tiempo máximo de espera para que el par envíe una Solicitud EAP cuando actúa como cliente (autenticado). (Predeterminado es 20 segundos.)
hide-password
Al registrar el contenido de los paquetes PAP, esta opción hace que pppd excluya la cadena de contraseña del registro. Este es el valor predeterminado.
holdoff n
Especifica cuántos segundos esperar antes de reiniciar el enlace después de que se termine. Esta opción solo tiene efecto si se usa la opción persist o demand. El período de espera (holdoff) no se aplica si el enlace se terminó porque estaba inactivo, se agotó el tiempo de conexión, el módem colgó o por solicitud del usuario.
idle n
Especifica que pppd debe desconectarse si el enlace está inactivo durante n segundos. El enlace está inactivo cuando no se envían ni reciben paquetes de datos (es decir, paquetes IP). Nota: no es aconsejable usar esta opción con la opción persist sin la opción demand. Si se proporciona la opción active-filter, los paquetes de datos que sean rechazados por el filtro de actividad especificado también contarán como inactividad del enlace.
ipcp-accept-local
Con esta opción, pppd aceptará la idea del par sobre nuestra dirección IP local, incluso si la dirección IP local se especificó en una opción.
ipcp-accept-remote
Con esta opción, pppd aceptará la idea del par sobre su dirección IP (remota), incluso si la dirección IP remota se especificó en una opción.
ipcp-max-configure n
Establece el número máximo de transmisiones de solicitudes de configuración IPCP a n (predeterminado 10).
ipcp-max-failure n
Establece el número máximo de NAKs de configuración IPCP devueltos antes de comenzar a enviar Rechazos de configuración en su lugar a n (predeterminado 10).
ipcp-max-terminate n
Establece el número máximo de transmisiones de solicitudes de terminación IPCP a n (predeterminado 3).
ipcp-no-address
Deshabilita la negociación de direcciones a través de la opción IPCP IP-Address.
ipcp-no-addresses
Deshabilita la negociación de direcciones a través de la opción IPCP obsoleta IP-Addresses. Pppd por defecto intenta usar la opción IPCP IP-Address de nuevo estilo. Si el par no soporta el nuevo estilo o este está deshabilitado por la opción ipcp-no-address, entonces pppd recurre a la opción obsoleta IP-Addresses de nuevo estilo. Cuando ambos, nuevo estilo y estilo antiguo, están deshabilitados por las opciones ipcp-no-address y ipcp-no-addresses, la negociación de direcciones IP se deshabilita completamente.
ipcp-restart n
Establece el intervalo de reinicio IPCP (tiempo de espera de retransmisión) a n segundos (predeterminado 3).
ipparam string

ARCHIVOS

/etc/ppp/ip-pre-up
Un programa o script que se ejecuta justo antes de que la interfaz de red ppp se active. Se ejecuta con los mismos parámetros que el script ip-up (abajo). En este punto, la interfaz existe y tiene direcciones IP asignadas, pero todavía está inactiva. Esto se puede utilizar para agregar reglas de firewall antes de que cualquier tráfico IP pueda pasar a través de la interfaz. Pppd esperará a que este script finalice antes de activar la interfaz, por lo que este script debe ejecutarse rápidamente.

ADVERTENCIA: Tenga en cuenta que en sistemas donde una sola interfaz soporta múltiples protocolos (Linux), no se garantiza que ip-pre-up se ejecute antes de que la interfaz pase a un estado activo. Aunque la información IP no se conocerá, debería considerar usar net-pre-up en su lugar, o deshabilitar otros NCP de tal manera que IPv4 sea el único protocolo negociado, lo que también garantizará que se llame a ip-pre-up antes de que la interfaz entre en un estado ACTIVO.

/etc/ppp/ip-up
Un programa o script que se ejecuta cuando el enlace está disponible para enviar y recibir paquetes IP (es decir, cuando IPCP se ha activado). Se ejecuta con los parámetros
nombre-interfaz dispositivo-tty velocidad dirección-IP-local dirección-IP-remota ipparam
/etc/ppp/ip-down
Un programa o script que se ejecuta cuando el enlace ya no está disponible para enviar y recibir paquetes IP. Este script se puede usar para deshacer los efectos de los scripts /etc/ppp/ip-up y /etc/ppp/ip-pre-up. Se invoca de la misma manera y con los mismos parámetros que el script ip-up.
/etc/ppp/ipv6-up
Similar a /etc/ppp/ip-up, excepto que se ejecuta cuando el enlace está disponible para enviar y recibir paquetes IPv6. Se ejecuta con los parámetros
nombre-interfaz dispositivo-tty velocidad dirección-local-link-local dirección-remota-local-link-local ipparam
/etc/ppp/ipv6-down
Similar a /etc/ppp/ip-down, pero se ejecuta cuando los paquetes IPv6 ya no pueden transmitirse en el enlace. Se ejecuta con los mismos parámetros que el script ipv6-up.
/etc/ppp/net-init
Este script se ejecutará en el momento en que se conozca el número de unidad ppp. Se esperará a este script y no debería causar retrasos significativos. Se puede usar para actualizar sistemas de contabilidad externos a ppp y proporciona el único punto garantizado donde un script puede ejecutarse conociendo el número de unidad ppp antes de que se inicie LCP. Se ejecuta con los parámetros
nombre-interfaz dispositivo-tty velocidad ipparam
/etc/ppp/net-pre-up
Este script se ejecutará justo antes de que se inicien las negociaciones de NCP, y se garantiza que se ejecutará mientras la interfaz (Linux) y/o las subinterfaces (Solaris), según sea el caso, todavía están inactivas. ppp bloqueará la espera hasta que este script se complete, y la interfaz puede ser renombrada de forma segura en este script (utilizando, por ejemplo, "ip li set dev $1 name ppp-foobar". Los parámetros son los mismos que para net-init.
/etc/ppp/net-down
Este script se ejecutará justo antes de que ppp termine y no se esperará su finalización. Los parámetros son los mismos que para net-init.
/var/run/pppn.pid (BSD o Linux), /etc/ppp/pppn.pid (otros)
ID de proceso para el proceso pppd en la unidad de interfaz ppp n.
/var/run/ppp-name.pid (BSD o Linux),
/etc/ppp/ppp-name.pid (otros) ID de proceso para el proceso pppd para el enlace lógico name (ver la opción linkname).
/var/run/pppd2.tdb
Base de datos que contiene información sobre procesos pppd, interfaces y enlaces, utilizada para hacer coincidir enlaces con paquetes en operación multilink. Puede ser examinada por programas externos para obtener información sobre instancias pppd en ejecución, las interfaces y dispositivos que están utilizando, asignaciones de direcciones IP, etc. /etc/ppp/pap-secrets Nombres de usuario, contraseñas y direcciones IP para la autenticación PAP. Este archivo debe pertenecer a root y no ser legible ni escribible por ningún otro usuario. Pppd registrará una advertencia si no es así.
/etc/ppp/chap-secrets
Nombres, secretos y direcciones IP para la autenticación CHAP/MS-CHAP/MS-CHAPv2. Al igual que con /etc/ppp/pap-secrets, este archivo debe pertenecer a root y no ser legible ni escribible por ningún otro usuario. Pppd registrará una advertencia si no es así.
/etc/ppp/srp-secrets
Nombres, secretos y direcciones IP para la autenticación EAP. Al igual que con /etc/ppp/pap-secrets, este archivo debe pertenecer a root y no ser legible ni escribible por ningún otro usuario. Pppd registrará una advertencia si no es así.
~/.ppp_pseudonym
Pseudónimo SRP-SHA1 guardado en el lado del cliente. Ver la opción srp-use-pseudonym para más detalles.
/etc/ppp/options
Opciones predeterminadas del sistema para pppd, leídas antes que las opciones predeterminadas del usuario o las opciones de la línea de comandos.
~/.ppprc
Opciones predeterminadas del usuario, leídas antes que /etc/ppp/options.nombre-tty.
/etc/ppp/options.nombre-tty
Opciones predeterminadas del sistema para el puerto serie que se está utilizando, leídas después de ~/.ppprc. Al formar la parte nombre-tty de este nombre de archivo, se elimina un /dev/ inicial del nombre del puerto (si está presente), y cualquier barra en la parte restante se convierte en puntos.
/etc/ppp/peers
Un directorio que contiene archivos de opciones que pueden contener opciones privilegiadas, incluso si pppd fue invocado por un usuario distinto de root. El administrador del sistema puede crear archivos de opciones en este directorio para permitir a los usuarios no privilegiados marcar sin requerir que el par se autentique, pero solo a pares de confianza específicos.

NOTAS

Se puede ejercer un cierto grado de control sobre un proceso pppd en ejecución enviándole una señal de la siguiente lista.

SIGINT, SIGTERM
Estas señales hacen que pppd termine el enlace (cerrando LCP), restaure la configuración del dispositivo serie y salga. Si un proceso conector o desconector se está ejecutando actualmente, pppd enviará la misma señal a su grupo de procesos, para terminar el proceso conector o desconector.
SIGHUP
Esta señal hace que pppd termine el enlace, restaure la configuración del dispositivo serie y cierre el dispositivo serie. Si se ha especificado la opción persist o demand, pppd intentará reabrir el dispositivo serie y comenzar otra conexión (después del período de espera). De lo contrario, pppd saldrá. Si se recibe esta señal durante el período de espera, hace que pppd finalice el período de espera inmediatamente. Si se está ejecutando un proceso conector o desconector, pppd enviará la misma señal a su grupo de procesos.
SIGUSR1
Esta señal alterna el estado de la opción debug.
SIGUSR2
Esta señal hace que pppd renegocie la compresión. Esto puede ser útil para volver a habilitar la compresión después de que se haya deshabilitado como resultado de un error fatal de descompresión (los errores fatales de descompresión generalmente indican un error en una u otra implementación).
