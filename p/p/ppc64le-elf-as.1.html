DESCRIPTION

GNU as is really a family of assemblers. If you use (or have used) the GNU assembler on one architecture, you should find a fairly similar environment when you use it on another architecture. Each version has much in common with the others, including object file formats, most assembler directives (often called pseudo-ops) and assembler syntax.

as is primarily intended to assemble the output of the GNU C compiler "gcc" for use by the linker "ld". Nevertheless, we've tried to make as assemble correctly everything that other assemblers for the same machine would assemble. Any exceptions are documented explicitly. This doesn't mean as always uses the same syntax as another assembler for the same architecture; for example, we know of several incompatible versions of 680x0 assembly language syntax.

Each time you run as it assembles exactly one source program. The source program is made up of one or more files. (The standard input is also a file.)

You give as a command line that has zero or more input file names. The input files are read (from left file name to right). A command-line argument (in any position) that has no special meaning is taken to be an input file name.

If you give as no file names it attempts to read one input file from the as standard input, which is normally your terminal. You may have to type ctl-D to tell as there is no more program to assemble.

Use -- if you need to explicitly name the standard input file in your command line.

If the source is empty, as produces a small, empty object file.

as may write warnings and error messages to the standard error file (usually your terminal). This should not happen when a compiler runs as automatically. Warnings report an assumption made so that as could keep assembling a flawed program; errors report a grave problem that stops the assembly.

If you are invoking as via the GNU C compiler, you can use the -Wa option to pass arguments through to the assembler. The assembler arguments must be separated from each other (and the -Wa) by commas. For example:

gcc -c -g -O -Wa,-alh,-L file.c

This passes two options to the assembler: -alh (emit a listing to standard output with high-level and assembly source) and -L (retain local symbols in the symbol table).

Usually you do not need to use this -Wa mechanism, since many compiler command-line options are automatically passed to the assembler by the compiler. (You can call the GNU compiler driver with the -v option to see precisely what options it passes to each compilation pass, including the assembler.)

OPTIONS

@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.

-a[cdghilmns]
Turn on listings, in any of a variety of ways:
-ac
omit false conditionals
-ad
omit debugging directives
-ag
include general information, like as version and options passed
-ah
include high-level source code in the listing
-ai
include low-level source code in the listing
-al
include all source code in the listing
-am
include macro expansions in the listing
-an
no symbols
-ap
print line numbers
-as
variant list format

The default listing format is to omit false conditionals, include debugging directives, and not include any source code. This is the same as using -acd. If you use -a without any arguments, it means -acdh.

The listing is always written to the standard output file. If you use the -o option, the listing is written to a file named outfile.lst.

-b
This option is available on some architectures. It is a synonym for -mbig-endian.
-c
Do not terminate assembly after the first non-fatal error. This is useful when assembling with the compiler driver, which can then report all errors.
-d
This option is available on some architectures. It is a synonym for -mlittle-endian.
-g
Produce debugging information in the output file. This is equivalent to the compiler's -g option.
-h
Output a symbol table listing to the standard error file.
-I dir
Add dir to the list of directories in which to search for assembler include files. This is equivalent to the compiler's -I option.
-J dir
Add dir to the list of directories in which to search for assembler include files. This is equivalent to the compiler's -I option.
-k
Keep the object file even if the assembly fails.
-L
Retain all symbols in the symbol table, including local symbols. This is equivalent to the compiler's -L option.
-march=cpu
Specify the architecture for which to assemble code. The available architectures depend on the target architecture. See the target-specific options below for details.
-mabi=abi
Specify the ABI to use. The available ABIs depend on the target architecture. See the target-specific options below for details.
-mlittle-endian
Use little-endian byte order. This option is available on some architectures.
-mbig-endian
Use big-endian byte order. This option is available on some architectures.
-mpic
Generate position-independent code. This option is available on some architectures.
-mno-pic
Do not generate position-independent code. This option is available on some architectures.
-n
This option is available on some architectures. It is a synonym for -mno-relax.
-o outfile
Use outfile as the object file name. If you do not use this option, the assembler names the object file a.out by default. If you name the output file a.out, and do not use the -g option, the object file is created with mode 0666. Otherwise, it is created with mode 0644. The mode is changed using chmod.
-P
Do not allow the preprocessor to run. This is useful when assembling source code that does not contain any preprocessor directives.
-R
Keep the relocation information in the output file. This is equivalent to the compiler's -R option.
-s
Omit the symbol table from the output file. This is equivalent to the compiler's -s option.
-S
Do not assemble the source file. Instead, write the output of the assembler's macro preprocessor to the standard output file. This is equivalent to the compiler's -S option.
-v
Print the assembler's version number, the version number of the compiler driver that invoked the assembler, and the options that were passed to the assembler.
-version
Print the assembler's version number and exit.
-W
This option is available on some architectures. It is a synonym for -mrelax.
-Woptions
Pass options to the assembler. The options must be separated by commas. This is equivalent to the compiler's -Wa option.
--help
Print a summary of the assembler options on the standard error file and exit.
-Wwarn
Enable warnings for the specified condition. See the target-specific options below for details.
-Wno-warn
Disable warnings for the specified condition. See the target-specific options below for details.
-Xlinker arg
Pass arg to the linker.

-n
Por defecto, x86 GAS reemplaza múltiples instrucciones nop utilizadas para alineación dentro de secciones de código con instrucciones nop de varios bytes como leal 0(%esi,1),%esi. --divide

-mbig-endian
Generate big-endian code. This is the default for the global accumulator branch target with default visibility. The resulting code is slightly bigger. This option only affects the handling of branch instructions.

En el target PE/COFF, esta opción fuerza el uso del formato de archivo de objeto grande, que permite más de 32768 secciones.
-momit-lock-prefix=no
-momit-lock-prefix=yes
Estas opciones controlan cómo el ensamblador debe codificar el prefijo de bloqueo. Esta opción está pensada como una solución alternativa para procesadores que fallan con el prefijo de bloqueo. Esta opción solo se puede usar de forma segura con computadoras de un solo núcleo y un solo hilo. -momit-lock-prefix=yes omitirá todos los prefijos de bloqueo. -momit-lock-prefix=no codificará el prefijo de bloqueo como de costumbre, que es el valor predeterminado.
-mfence-as-lock-add=no
-mfence-as-lock-add=yes
Estas opciones controlan cómo el ensamblador debe codificar lfence, mfence y sfence. -mfence-as-lock-add=yes codificará lfence, mfence y sfence como lock addl $0x0, (%rsp) en modo de 64 bits y lock addl $0x0, (%esp) en modo de 32 bits. -mfence-as-lock-add=no codificará lfence, mfence y sfence como de costumbre, que es el valor predeterminado.
-mrelax-relocations=no
-mrelax-relocations=yes
Estas opciones controlan si el ensamblador debe generar realineaciones de relajación, R_386_GOT32X, en modo de 32 bits, o R_X86_64_GOTPCRELX y R_X86_64_REX_GOTPCRELX, en modo de 64 bits. -mrelax-relocations=yes generará realineaciones de relajación. -mrelax-relocations=no no generará realineaciones de relajación. El valor predeterminado se puede controlar mediante la opción de configuración --enable-x86-relax-relocations.
-malign-branch-boundary=NUM
Esta opción controla cómo el ensamblador debe alinear saltos con prefijos de segmento o NOP. NUM debe ser una potencia de 2. Debe ser 0 o no menos de 16. Los saltos se alinearán dentro del límite de NUM bytes. -malign-branch-boundary=0, que es el valor predeterminado, no alinea saltos.
-malign-branch=TYPE[+TYPE...]
Esta opción especifica los tipos de saltos a alinear. TYPE es una combinación de jcc, que alinea saltos condicionales, fused, que alinea saltos condicionales fusionados, jmp, que alinea saltos incondicionales, call que alinea llamadas, ret, que alinea retornos, indirect, que alinea saltos y llamadas indirectas. El valor predeterminado es -malign-branch=jcc+fused+jmp.
-malign-branch-prefix-size=NUM
Esta opción especifica el número máximo de prefijos en una instrucción para alinear saltos. NUM debe estar entre 0 y 5. El valor predeterminado de NUM es 5.
-mbranches-within-32B-boundaries
Esta opción alinea saltos condicionales, saltos condicionales fusionados y saltos incondicionales dentro de un límite de 32 bytes con hasta 5 prefijos de segmento en una instrucción. Es equivalente a -malign-branch-boundary=32 -malign-branch=jcc+fused+jmp -malign-branch-prefix-size=5. El valor predeterminado no alinea saltos.

Optimiza la codificación de instrucciones con un tamaño de instrucción menor. -O y -O1 codifican las instrucciones de carga de registro de 64 bits con un inmediato de 64 bits como instrucciones de carga de registro de 32 bits con inmediatos de 31 o 32 bits, codifican las instrucciones de borrado de registro de 64 bits como instrucciones de borrado de registro de 32 bits, codifican las instrucciones de borrado de registro vectorial VEX/EVEX de 256/512 bits como instrucciones de borrado de registro vectorial VEX de 128 bits, codifican las instrucciones de carga/almacenamiento de registro vectorial EVEX de 128/256 bits como instrucciones de carga/almacenamiento de registro vectorial VEX, y codifican las instrucciones lógicas enteras empaquetadas EVEX de 128/256 bits como instrucciones lógicas enteras empaquetadas VEX de 128/256 bits.

-O2 incluye la optimización de -O1 además de codificar las instrucciones de borrado de registro vectorial EVEX de 256/512 bits como instrucciones de borrado de registro EVEX de 128 bits. En modo de 64 bits, las instrucciones codificadas con VEX con operandos fuente conmutativos también intercambiarán sus operandos fuente si esto permite usar la forma de prefijo VEX de 2 bytes en lugar de la de 3 bytes. Ciertas formas de AND, así como OR con el mismo operando (de registro) especificado dos veces, también se cambiarán a TEST.

-Os incluye la optimización de -O2 además de codificar las pruebas de registro de 16, 32 y 64 bits con inmediato como prueba de registro de 8 bits con inmediato. -O0 desactiva esta optimización.

Esta optimización está habilitada por defecto. Tenga en cuenta que el ensamblador siempre alineará instrucciones como "LOOP" que tienen requisitos de alineación fijos.
="#longcalls">--longcalls | --no-longcalls
Habilita o deshabilita la transformación de instrucciones de llamada para permitir llamadas a un mayor rango de direcciones. Esta opción debe usarse cuando los destinos de llamada pueden estar potencialmente fuera de rango. Puede degradar tanto el tamaño del código como el rendimiento, pero el enlazador generalmente puede optimizar la sobrecarga innecesaria cuando una llamada termina dentro del rango. El valor predeterminado es --no-longcalls.
--transform | --no-transform
Habilita o deshabilita todas las transformaciones del ensamblador de instrucciones Xtensa, incluyendo tanto la relajación como la optimización. El valor predeterminado es --transform; --no-transform solo debe usarse en los raros casos en que las instrucciones deben ser exactamente como se especifican en el código fuente ensamblado. Usar --no-transform provoca que los operandos de instrucción fuera de rango sean errores.
--rename-section nombreantiguo=nombrenuevo
Renombra la sección nombreantiguo a nombrenuevo. Esta opción puede ser utilizada varias veces para renombrar múltiples secciones.
--trampolines | --no-trampolines
Habilita o deshabilita la transformación de instrucciones de salto para permitir saltos a un mayor rango de direcciones. Esta opción debe usarse cuando los destinos de salto pueden estar potencialmente fuera de rango. En ausencia de tales saltos, esta opción no afecta el tamaño del código ni el rendimiento. El valor predeterminado es --trampolines.
--abi-windowed | --abi-call0
Elige la etiqueta ABI escrita en la sección ".xtensa.info". La etiqueta ABI indica la ABI del código ensamblado. El enlazador emite una advertencia al intentar enlazar archivos objeto con etiquetas ABI inconsistentes. La ABI predeterminada se elige según la configuración del núcleo Xtensa.

@chapter Características dependientes de Z80

Opciones de línea de comandos

-march=CPU[-EXT...][+EXT...]
Esta opción especifica el procesador de destino. El ensamblador emitirá un mensaje de error si se intenta ensamblar una instrucción que no se ejecutará en el procesador de destino. Los siguientes nombres de procesador son reconocidos: "z80", "z180", "ez80", "gbz80", "z80n", "r800". Además del conjunto de instrucciones básico, el ensamblador puede ser informado para aceptar algunas mnemónicas de extensión. Por ejemplo, "-march=z180+sli+infc" extiende z180 con instrucciones SLI e IN F,(C). Las siguientes extensiones son compatibles actualmente: "full" (todas las instrucciones conocidas), "adl" (modo de CPU ADL por defecto, solo eZ80), "sli" (instrucción conocida como SLI, SLL o SL1), "xyhl" (instrucciones con mitades de registros de índice: IXL, IXH, IYL, IYH), "xdcb" (instrucciones como RotOp (II+d),R y BitOp n,(II+d),R), "infc" (instrucción IN F,(C) o IN (C)), "outc0" (instrucción OUT (C),0). Tenga en cuenta que en lugar de extender un conjunto de instrucciones básico, las mnemónicas de extensión que comienzan con "-" revocar la funcionalidad respectiva: "-march=z80-full+xyhl" primero elimina todas las extensiones predeterminadas y solo agrega soporte para mitades de registros de índice.

Si esta opción no se especifica, se asume "-march=z80+xyhl+infc".

-local-prefix=prefijo
Marca todas las etiquetas con el prefijo especificado como locales. Pero dicha etiqueta puede ser marcada explícitamente como global en el código. Esta opción no cambia el prefijo de etiqueta local predeterminado ".L", solo agrega uno nuevo.
-colonless
Acepta etiquetas sin dos puntos. Todos los símbolos al principio de la línea se tratan como etiquetas.
-sdcc
Acepta código ensamblador producido por SDCC.
-fp-s=FORMATO
Formato de números de punto flotante de precisión simple. Predeterminado: ieee754 (32 bits).
-fp-d=FORMATO
Formato de números de punto flotante de doble precisión. Predeterminado: ieee754 (64 bits).
