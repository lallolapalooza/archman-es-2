LD(1) Herramientas de desarrollo de GNU LD(1)

NOMBRE

ld - El enlazador de GNU

SINOPSIS

ld [opciones] archivoobjeto ...

DESCRIPCIÓN

ld combina un número de archivos objeto y de archivo, los relocaliza y enlaza las referencias de símbolos. Normalmente el último paso en la compilación de un programa es ejecutar ld.

ld acepta archivos de lenguaje de comandos del enlazador escritos en un superconjunto de la sintaxis del lenguaje de comandos del enlazador de AT&T, para proporcionar control explícito y total sobre el proceso de enlazado.

Esta página del manual no describe el lenguaje de comandos; consulte la entrada ld en "info" para obtener detalles completos sobre el lenguaje de comandos y sobre otros aspectos del enlazador de GNU.

Esta versión de ld utiliza las bibliotecas generales de BFD para operar en archivos objeto. Esto permite a ld leer, combinar y escribir archivos objeto en muchos formatos diferentes; por ejemplo, COFF o "a.out". Diferentes formatos pueden ser enlazados para producir cualquier tipo de archivo objeto disponible.

Aparte de su flexibilidad, el enlazador de GNU es más útil que otros enlazadores al proporcionar información de diagnóstico. Muchos enlazadores abandonan la ejecución inmediatamente al encontrar un error; siempre que sea posible, ld continúa la ejecución, permitiéndole identificar otros errores (o, en algunos casos, obtener un archivo de salida a pesar del error).

El enlazador de GNU ld está diseñado para cubrir una amplia gama de situaciones y ser lo más compatible posible con otros enlazadores. Como resultado, tiene muchas opciones para controlar su comportamiento.

OPCIONES

El enlazador soporta una gran cantidad de opciones de línea de comandos, pero en la práctica se utilizan pocas en un contexto particular. Por ejemplo, un uso frecuente de ld es enlazar archivos objeto estándar de Unix en un sistema estándar y soportado. En un sistema así, para enlazar un archivo "hello.o":

ld -o <salida> /lib/crt0.o hello.o -lc

Esto indica a ld que produzca un archivo llamado salida como resultado de enlazar el archivo "/lib/crt0.o" con "hello.o" y la biblioteca "libc.a", que provendrá de los directorios de búsqueda estándar. (Vea la discusión de la opción -l abajo.)

Algunas de las opciones de línea de comandos de ld pueden especificarse en cualquier punto de la línea de comandos. Sin embargo, las opciones que se refieren a archivos, como -l o -T, hacen que el archivo sea leído en el punto en que la opción aparece en la línea de comandos, en relación con los archivos objeto y otras opciones de archivo. Repetir opciones no relacionadas con archivos con un argumento diferente tendrá un efecto nulo o anulará las ocurrencias previas (las más a la izquierda en la línea de comandos) de esa opción. Las opciones que pueden especificarse de manera significativa más de una vez se anotan en las descripciones a continuación.

Los argumentos que no son opciones son archivos objeto o archivos que se enlazarán juntos. Pueden seguir, preceder o mezclarse con las opciones de línea de comandos, excepto que un argumento de archivo objeto no puede colocarse entre una opción y su argumento.

Normalmente el enlazador se invoca con al menos un archivo objeto, pero puede especificar otras formas de archivos de entrada binarios usando -l, -R, y el lenguaje de comandos de scripts. Si no se especifican archivos de entrada binarios en absoluto, el enlazador no produce ninguna salida y muestra el mensaje No input files.

Si el enlazador no puede reconocer el formato de un archivo objeto, asumirá que es un script del enlazador. Un script especificado de esta manera aumenta el script principal del enlazador utilizado para el enlace (ya sea el script predeterminado del enlazador o el especificado usando -T). Esta característica permite al enlazador enlazar contra un archivo que parece ser un objeto o un archivo, pero que en realidad solo define algunos valores de símbolos, o usa "INPUT" o "GROUP" para cargar otros objetos. Especificar un script de esta manera solo aumenta el script principal del enlazador, con los comandos adicionales colocados después del script principal; use la opción -T para reemplazar completamente el script predeterminado del enlazador, pero tenga en cuenta el efecto del comando "INSERT".

Para opciones cuyos nombres son una sola letra, los argumentos de la opción deben seguir la letra de la opción sin espacios intermedios, o darse como argumentos separados inmediatamente después de la opción que los requiere.

Para opciones cuyos nombres son múltiples letras, uno o dos guiones pueden preceder el nombre de la opción; por ejemplo, -trace-symbol y --trace-symbol son equivalentes. Nota: hay una excepción a esta regla. Las opciones de múltiples letras que comienzan con una 'o' minúscula solo pueden ser precedidas por dos guiones. Esto es para reducir la confusión con la opción -o. Así, por ejemplo, -omagic establece el nombre del archivo de salida a magic, mientras que --omagic establece el indicador NMAGIC en la salida.

Los argumentos a las opciones de múltiples letras deben estar separados del nombre de la opción por un signo de igual, o darse como argumentos separados inmediatamente después de la opción que los requiere. Por ejemplo, --trace-symbol foo y --trace-symbol=foo son equivalentes. Se aceptan abreviaturas únicas de los nombres de las opciones de múltiples letras.

Nota: si el enlazador se invoca indirectamente, a través de un controlador de compilador (por ejemplo, gcc) entonces todas las opciones de línea de comandos del enlazador deben ir precedidas por -Wl, (o lo que sea apropiado para el controlador de compilador en particular) de esta manera:

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Esto es importante, porque de lo contrario el programa controlador de compilador puede omitir silenciosamente las opciones del enlazador, resultando en un enlace incorrecto. La confusión también puede surgir al pasar opciones que requieren valores a través de un controlador, ya que el uso de un espacio entre la opción y el argumento actúa como un separador y hace que el controlador pase solo la opción al enlazador y el argumento al compilador. En este caso, es más sencillo usar las formas unidas tanto de opciones de una sola letra como de múltiples letras, como:

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

@archivo
Lee las opciones de línea de comandos de archivo. Las opciones leídas se insertan en lugar de la opción @archivo original. Si archivo no existe, o no se puede leer, entonces la opción se tratará literalmente, y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Se puede incluir un carácter de espacio en blanco en una opción rodeando toda la opción con comillas simples o dobles. Se puede incluir cualquier carácter (incluido una barra invertida) prefijando el carácter a incluir con una barra invertida. El archivo puede contener adicionalmente opciones @archivo; tales opciones se procesarán recursivamente.

-a palabra_clave
Esta opción se soporta para compatibilidad con HP/UX. El argumento palabra_clave debe ser una de las cadenas archive, shared o default. -aarchive es funcionalmente equivalente a -Bstatic, y las otras dos palabras clave son funcionalmente equivalentes a -Bdynamic. Esta opción se puede usar cualquier número de veces.

--depaudit BIBLIOTECA-AUDITORIA

Añade BIBLIOTECA-AUDITORIA a la entrada "DT_DEPAUDIT" de la sección dinámica. No se comprobará la existencia de BIBLIOTECA-AUDITORIA, ni utilizará la DT_SONAME especificada en la biblioteca. --enable-linker-version
Habilita la directiva de script de enlazador "LINKER_VERSION", descrita en Datos de la Sección de Salida. Si esta directiva se utiliza en un script de enlazador y esta opción se ha habilitado, entonces se insertará una cadena que contiene la versión del enlazador en el punto actual.

Nota: la ubicación de esta opción en la línea de comandos del enlazador es significativa. Solo afectará a los scripts de enlazador que vengan después en la línea de comandos, o que estén integrados en el enlazador.

--disable-linker-version
Deshabilita la directiva de script de enlazador "LINKER_VERSION", de modo que no inserte una cadena de versión. Este es el valor predeterminado.
--enable-non-contiguous-regions
Esta opción evita generar un error si una sección de entrada no encaja en una sección de salida coincidente. El enlazador intenta asignar la sección de entrada a secciones de salida coincidentes subsiguientes, y solo genera un error si ninguna sección de salida es lo suficientemente grande. Esto es útil cuando hay disponibles varias regiones de memoria no contiguas y la sección de entrada no requiere una en particular. El orden en que se evalúan las secciones de entrada no cambia, por ejemplo: 
MEMORY {
  MEM1 (rwx) : ORIGIN = 0x1000, LENGTH = 0x14
  MEM2 (rwx) : ORIGIN = 0x1000, LENGTH = 0x40
  MEM3 (rwx) : ORIGIN = 0x2000, LENGTH = 0x40
}
SECTIONS {
  mem1 : { *(.data.*); } > MEM1
  mem2 : { *(.data.*); } > MEM2
  mem3 : { *(.data.*); } > MEM3
}

con secciones de entrada:
.data.1: tamaño 8
.data.2: tamaño 0x10
.data.3: tamaño 4

resulta en .data.1 asignada a mem1, y .data.2 y .data.3
asignadas a mem2, aunque .data.3 cabría en mem3.

Esta opción es incompatible con las sentencias INSERT porque cambia la forma en que las secciones de entrada se mapean a las secciones de salida.

--enable-non-contiguous-regions-warnings
Esta opción habilita advertencias cuando "--enable-non-contiguous-regions" permite coincidencias potencialmente inesperadas en el mapeo de secciones, lo que podría llevar a descartar silenciosamente una sección en lugar de fallar porque no encaja en ninguna región de salida.
-e entrada
--entry=entrada
Utiliza entrada como el símbolo explícito para comenzar la ejecución de su programa, en lugar del punto de entrada predeterminado. Si no hay ningún símbolo llamado entrada, el enlazador intentará interpretar entrada como un número, y lo usará como la dirección de entrada (el número se interpretará en base 10; puede usar un prefijo 0x para base 16, o un prefijo 0 para base 8).
--exclude-libs lib,lib,...
Especifica una lista de bibliotecas de archivos de donde los símbolos no deben ser exportados automáticamente. Los nombres de las bibliotecas pueden estar delimitados por comas o dos puntos. Especificar "--exclude-libs ALL" excluye los símbolos de todas las bibliotecas de archivos de la exportación automática. Esta opción solo está disponible para el puerto PE de i386 del enlazador y para puertos con destino ELF. Para i386 PE, los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción. Para puertos con destino ELF, los símbolos afectados por esta opción se tratarán como ocultos.
--exclude-modules-for-implib modulo,modulo,...
Especifica una lista de archivos objeto o miembros de archivo, de los cuales los símbolos no deben ser exportados automáticamente, pero que deben copiarse íntegramente a la biblioteca de importación que se está generando durante el enlace. Los nombres de los módulos pueden estar delimitados por comas o dos puntos, y deben coincidir exactamente con los nombres de archivo utilizados por ld para abrir los archivos; para miembros de archivo, este es simplemente el nombre del miembro, pero para archivos objeto el nombre listado debe incluir y coincidir precisamente con cualquier ruta utilizada para especificar el archivo de entrada en la línea de comandos del enlazador. Esta opción solo está disponible para el puerto PE de i386 del enlazador. Los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción.
-E
--export-dynamic
--no-export-dynamic
Al crear un ejecutable enlazado dinámicamente, el uso de la opción -E o la opción --export-dynamic hace que el enlazador añada todos los símbolos a la tabla de símbolos dinámicos. La tabla de símbolos dinámicos es el conjunto de símbolos que son visibles desde objetos dinámicos en tiempo de ejecución.

Si no utiliza ninguna de estas opciones (o utiliza la opción --no-export-dynamic para restaurar el comportamiento predeterminado), la tabla de símbolos dinámicos normalmente contendrá solo aquellos símbolos que son referenciados por algún objeto dinámico mencionado en el enlace.

Si utiliza "dlopen" para cargar un objeto dinámico que necesita referirse a los símbolos definidos por el programa, en lugar de algún otro objeto dinámico, entonces probablemente necesitará usar esta opción al enlazar el programa mismo.

También puede utilizar la lista dinámica para controlar qué símbolos deben añadirse a la tabla de símbolos dinámicos si el formato de salida lo admite. Consulte la descripción de --dynamic-list.

Tenga en cuenta que esta opción es específica para puertos con destino ELF. Los destinos PE admiten una función similar para exportar todos los símbolos de una DLL o EXE; consulte la descripción de --export-all-symbols a continuación.

--export-dynamic-symbol=glob
Al crear un ejecutable enlazado dinámicamente, los símbolos que coinciden con glob se añadirán a la tabla de símbolos dinámicos. Al crear una biblioteca compartida, las referencias a símbolos que coinciden con glob no se vincularán a las definiciones dentro de la biblioteca compartida. Esta opción es inoperante al crear una biblioteca compartida y no se especifican -Bsymbolic o --dynamic-list. Esta opción solo es significativa en plataformas ELF que admiten bibliotecas compartidas.
--export-dynamic-symbol-list=archivo
Especifique un --export-dynamic-symbol para cada patrón en el archivo. El formato del archivo es el mismo que el nodo de versión sin ámbito ni nombre de nodo. Consulte VERSION para obtener más información.
-EB
Enlaza objetos big-endian. Esto afecta al formato de salida predeterminado.
-EL
Enlaza objetos little-endian. Esto afecta al formato de salida predeterminado.
-f nombre
--auxiliary=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_AUXILIARY al nombre especificado. Esto indica al enlazador dinámico que la tabla de símbolos del objeto compartido debe usarse como un filtro auxiliar en la tabla de símbolos del objeto compartido nombre.

Si más tarde enlaza un programa contra este objeto filtro, entonces, al ejecutar el programa, el enlazador dinámico verá el campo DT_AUXILIARY. Si el enlazador dinámico resuelve algún símbolo del objeto filtro, primero comprobará si hay una definición en el objeto compartido nombre. Si la hay, se utilizará en lugar de la definición en el objeto filtro. El objeto compartido nombre no necesita existir. Por lo tanto, el objeto compartido nombre puede usarse para proporcionar una implementación alternativa de ciertas funciones, quizás para depuración o para rendimiento específico de la máquina.

Esta opción puede especificarse más de una vez. Las entradas DT_AUXILIARY se crearán en el orden en que aparezcan en la línea de comandos.

-F nombre
--filter=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_FILTER al nombre especificado. Esto indica al enlazador dinámico que la tabla de símbolos del objeto compartido que se está creando debe usarse como un filtro para la tabla de símbolos del objeto compartido nombre.

Si más tarde enlaza un programa contra este objeto filtro, entonces, cuando ejecute el programa, el enlazador dinámico verá el campo DT_FILTER. El enlazador dinámico resolverá los símbolos de acuerdo con la tabla de símbolos del objeto filtro como de costumbre, pero en realidad se enlazará a las definiciones encontradas en el objeto compartido nombre. Por lo tanto, el objeto filtro puede usarse para seleccionar un subconjunto de los símbolos proporcionados por el objeto nombre.

Algunos enlazadores antiguos usaban la opción -F en toda una cadena de herramientas de compilación para especificar el formato del archivo objeto tanto para archivos de entrada como de salida. El enlazador GNU utiliza otros mecanismos para este propósito: las opciones -b, --format, --oformat, el comando "TARGET" en los scripts del enlazador y la variable de entorno "GNUTARGET". El enlazador GNU ignorará la opción -F cuando no esté creando un objeto compartido ELF.

-fini=nombre
Al crear un ejecutable o un objeto compartido ELF, llama a NOMBRE cuando el ejecutable o el objeto compartido se descargan, estableciendo DT_FINI a la dirección de la función. Por defecto, el enlazador utiliza "_fini" como la función a llamar.
-g
Ignorado. Proporcionado por compatibilidad con otras herramientas.
-G valor
--gpsize=valor
Establece el tamaño máximo de los objetos a optimizar utilizando el registro GP a tamaño. Esto solo es significativo para formatos de archivo objeto como MIPS ELF que admiten colocar objetos grandes y pequeños en secciones diferentes. Esto se ignora para otros formatos de archivo objeto.
-h nombre
-soname=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_SONAME al nombre especificado. Cuando un ejecutable se enlaza con un objeto compartido que tiene un campo DT_SONAME, entonces cuando el ejecutable se ejecuta, el enlazador dinámico intentará cargar el objeto compartido especificado por el campo DT_SONAME en lugar de usar el nombre de archivo dado al enlazador.
-i
Realiza un enlace incremental (igual que la opción -r).
-init=nombre
Al crear un ejecutable o un objeto compartido ELF, llama a NOMBRE cuando el ejecutable o el objeto compartido se carga, estableciendo DT_INIT a la dirección de la función. Por defecto, el enlazador utiliza "_init" como la función a llamar.
-l especnomb
--library=especnomb
Añade el archivo de archivo o objeto especificado por especnomb a la lista de archivos a enlazar. Esta opción se puede usar cualquier número de veces. Si especnomb tiene el formato :nombrearchivo, ld buscará en la ruta de bibliotecas un archivo llamado nombrearchivo, de lo contrario buscará en la ruta de bibliotecas un archivo llamado libespecnomb.a.

En sistemas que soportan bibliotecas compartidas, ld puede buscar también archivos distintos de libespecnomb.a. Específicamente, en sistemas ELF y SunOS, ld buscará en un directorio una biblioteca llamada libespecnomb.so antes de buscar una llamada libespecnomb.a. (Por convención, una extensión ".so" indica una biblioteca compartida). Tenga en cuenta que este comportamiento no se aplica a :nombrearchivo, que siempre especifica un archivo llamado nombrearchivo.

El enlazador buscará en un archivo solo una vez, en la ubicación donde se especifica en la línea de comandos. Si el archivo define un símbolo que estaba indefinido en algún objeto que apareció antes del archivo en la línea de comandos, el enlazador incluirá los archivos apropiados del archivo. Sin embargo, un símbolo indefinido en un objeto que aparece más tarde en la línea de comandos no hará que el enlazador vuelva a buscar en el archivo.

Vea la opción -( para una forma de forzar al enlazador a buscar archivos varias veces.

Puede listar el mismo archivo varias veces en la línea de comandos.

Este tipo de búsqueda de archivos es estándar para los enlazadores de Unix. Sin embargo, si está utilizando ld en AIX, tenga en cuenta que es diferente del comportamiento del enlazador de AIX.

-L dirbusqueda
--library-path=dirbusqueda
Añade la ruta dirbusqueda a la lista de rutas que ld buscará para bibliotecas de archivo y scripts de control de ld. Puede usar esta opción cualquier número de veces. Los directorios se buscan en el orden en que se especifican en la línea de comandos. Los directorios especificados en la línea de comandos se buscan antes que los directorios predeterminados. Todas las opciones -L se aplican a todas las opciones -l, independientemente del orden en que aparezcan las opciones. Las opciones -L no afectan a cómo ld busca un script del enlazador a menos que se especifique la opción -T.

Si dirbusqueda comienza con "=" o $SYSROOT, entonces este prefijo será reemplazado por el prefijo sysroot, controlado por la opción --sysroot, o especificado cuando se configuró el enlazador.

El conjunto predeterminado de rutas buscadas (sin ser especificadas con -L) depende de qué modo de emulación esté utilizando ld y, en algunos casos, también de cómo fue configurado.

Las rutas también se pueden especificar en un script de enlace con el comando "SEARCH_DIR". Los directorios especificados de esta manera se buscan en el punto en que el script del enlazador aparece en la línea de comandos.

-m emulacion
Emula el enlazador emulacion. Puede listar las emulaciones disponibles con las opciones --verbose o -V.

Si no se utiliza la opción -m, la emulación se toma de la variable de entorno "LDEMULATION", si está definida.

De lo contrario, la emulación predeterminada depende de cómo se configuró el enlazador.

--remap-inputs=patron=nombrearchivo
--remap-inputs-file=archivo
Estas opciones permiten cambiar los nombres de los archivos de entrada antes de que el enlazador intente abrirlos. La opción --remap-inputs=foo.o=bar.o hará que cualquier intento de cargar un archivo llamado foo.o intente cargar en su lugar un archivo llamado bar.o. Se permiten patrones comodín en el primer nombre de archivo, por lo que --remap-inputs=foo*.o=bar.o renombrará cualquier archivo de entrada que coincida con foo*.o a bar.o.

Una forma alternativa de la opción --remap-inputs-file=nombrearchivo permite leer las reasignaciones de un archivo. Cada línea en el archivo puede contener una sola reasignación. Las líneas en blanco se ignoran. Cualquier cosa desde un carácter de almohadilla (#) hasta el final de una línea se considera un comentario y también se ignora. El patrón de asignación puede estar separado del nombre de archivo por espacios en blanco o un carácter de igual (=).

Las opciones se pueden especificar varias veces. Sus contenidos se acumulan. Las reasignaciones se procesarán en el orden en que aparezcan en la línea de comandos y, si provienen de un archivo, en el orden en que aparezcan en el archivo. Si se produce una coincidencia, no se realizará ninguna comprobación adicional para ese nombre de archivo.

Si el nombre de archivo de reemplazo es /dev/null o simplemente NUL, la reasignación hará que el archivo de entrada sea ignorado. Esta puede ser una forma conveniente de experimentar con la eliminación de archivos de entrada de un entorno de compilación complicado.

Tenga en cuenta que esta opción depende de la posición y solo afecta a los nombres de archivo que vienen después de ella en la línea de comandos. Por lo tanto:

ld foo.o --remap-inputs=foo.o=bar.o

No tendrá ningún efecto, mientras que:

ld --remap-inputs=foo.o=bar.o foo.o

Renombrará el archivo de entrada foo.o a bar.o.

Nota: estas opciones también afectan a los archivos a los que se hace referencia mediante las declaraciones INPUT en los scripts del enlazador. Pero dado que los scripts del enlazador se procesan después de leer toda la línea de comandos, la posición de las opciones de reasignación en la línea de comandos no es significativa.

Si la opción verbose está habilitada, se informarán cualquier coincidencia de reasignación, aunque nuevamente la opción verbose debe estar habilitada en la línea de comandos antes de que aparezcan los nombres de archivo reasignados.

Si las opciones -Map o --print-map están habilitadas, la lista de reasignaciones se incluirá en la salida del mapa.

-M
--print-map
Imprime un mapa de enlace en la salida estándar. Un mapa de enlace proporciona información sobre el enlace, incluyendo lo siguiente:
  • Dónde se mapean los archivos objeto en memoria.
  • Cómo se asignan los símbolos comunes.
  • Todos los miembros del archivo incluidos en el enlace, con una mención del símbolo que provocó la inclusión del miembro del archivo.
  • Los valores asignados a los símbolos.

    Nota: es posible que los símbolos cuyos valores se calculan mediante una expresión que involucra una referencia a un valor anterior del mismo símbolo no muestren el resultado correcto en el mapa de enlace. Esto se debe a que el enlazador descarta los resultados intermedios y solo conserva el valor final de una expresión. En tales circunstancias, el enlazador mostrará el valor final entre corchetes. Por lo tanto, por ejemplo, un script de enlazador que contenga:

    foo = 1
foo = foo * 4
foo = foo + 8

    producirá la siguiente salida en el mapa de enlace si se usa la opción -M:

    0x00000001                foo = 0x1
[0x0000000c]                foo = (foo * 0x4)
[0x0000000c]                foo = (foo + 0x8)

    Vea Expressions para

más información sobre expresiones en los scripts del enlazador.

  • Cómo se fusionan las propiedades de GNU.

    Cuando el enlazador fusiona secciones .note.gnu.property de entrada en una única sección .note.gnu.property de salida, algunas propiedades se eliminan o actualizan. Estas acciones se informan en el mapa de enlace. Por ejemplo:

    Se eliminó la propiedad 0xc0000002 para fusionar foo.o (0x1) y bar.o (no encontrada)

    Esto indica que la propiedad 0xc0000002 se elimina de la salida al fusionar las propiedades en foo.o, cuyo valor de propiedad 0xc0000002 es 0x1, y bar.o, que no tiene la propiedad 0xc0000002.

    Se actualizó la propiedad 0xc0010001 (0x1) para fusionar foo.o (0x1) y bar.o (0x1)

    Esto indica que el valor de la propiedad 0xc0010001 se actualiza a 0x1 en la salida al fusionar las propiedades en foo.o, cuya propiedad 0xc0010001 tiene el valor 0x1, y bar.o, cuya propiedad 0xc0010001 tiene el valor 0x1.

  • En algunos destinos ELF, una lista de correcciones insertadas por --relax 
    foo.o: Ajustando salto en 0x00000008 hacia "far" en la sección .text

    Esto indica que el salto en 0x00000008 en foo.o, dirigido al símbolo "far" en la sección .text, ha sido reemplazado por una trampa.

    -Wl,--push-state,--as-needed -libone -libtwo -Wl,--pop-state

    -r
    --relocatable
    Genera una salida reubicable, es decir, genera un archivo de salida que a su vez puede servir como entrada para ld. Esto a menudo se llama enlace parcial. Como efecto secundario, en entornos que admiten números mágicos estándar de Unix, esta opción también establece el número mágico del archivo de salida en "OMAGIC". Si esta opción no se especifica, se produce un archivo absoluto. Al enlazar programas C++, esta opción no resolverá las referencias a constructores; para hacerlo, usa -Ur.

    Esta opción se puede establecer al realizar un enlace parcial (habilitado con la opción -r). En este caso, la raíz de los símbolos conservados debe especificarse explícitamente mediante una de las opciones --entry, --undefined o --gc-keep-exported, o mediante un comando "ENTRY" en el script del enlazador.

    Como extensión de GNU, las secciones de entrada ELF marcadas con el flag "SHF_GNU_RETAIN" no serán recolectadas por la basura.

    --print-gc-sections
    --no-print-gc-sections
    Lista todas las secciones eliminadas por la recolección de basura. La lista se imprime en stderr. Esta opción solo es efectiva si la recolección de basura ha sido habilitada mediante la opción --gc-sections. El comportamiento por defecto (de no listar las secciones que se eliminan) se puede restaurar especificando --no-print-gc-sections en la línea de comandos.
    --gc-keep-exported
    Cuando --gc-sections está habilitado, esta opción evita la recolección de basura de secciones de entrada no utilizadas que contienen símbolos globales con visibilidad por defecto o protegida. Esta opción está destinada a ser utilizada para ejecutables donde las secciones no referenciadas serían recolectadas por la basura independientemente de la visibilidad externa de los símbolos contenidos. Ten en cuenta que esta opción no tiene efecto al enlazar objetos compartidos, ya que ese es el comportamiento por defecto. Esta opción solo se soporta para objetivos de formato ELF.
    --print-output-format
    Imprime el nombre del formato de salida por defecto (posiblemente influenciado por otras opciones de la línea de comandos). Esta es la cadena que aparecería en un comando de script de enlazador "OUTPUT_FORMAT".
    --print-memory-usage
    Imprime el tamaño utilizado, el tamaño total y el tamaño utilizado de las regiones de memoria creadas con el comando MEMORY. Esto es útil en objetivos integrados para tener una vista rápida de la cantidad de memoria libre. El formato de la salida tiene un titular y una línea por región. Es legible tanto para humanos como fácilmente analizable por herramientas. Aquí tienes un ejemplo de salida: 
    Memory region         Used Size  Region Size  %age Used
             ROM:        256 KB         1 MB     25.00%
             RAM:          32 B         2 GB      0.00%
    --help
    Imprime un resumen de las opciones de la línea de comandos en la salida estándar y sale.
    --target-help
    Imprime un resumen de todas las opciones específicas del objetivo en la salida estándar y sale.
    -Map=mapfile
    Imprime un mapa de enlace en el archivo mapfile. Ver la descripción de la opción -M, arriba. Si mapfile es solo el carácter "-", el mapa se escribirá en la salida estándar.

    Especificar un directorio como mapfile hace que el mapa del enlazador se escriba como un archivo dentro del directorio. Normalmente, el nombre del archivo dentro del directorio se calcula a partir del nombre base del archivo de *salida* con ".map" añadido. Sin embargo, si se utiliza el carácter especial "%", este se reemplazará por la ruta completa del archivo de salida. Además, si hay algún carácter después del símbolo %, entonces ".map" ya no se añadirá.

    -o foo.exe -Map=bar                  [Crea ./bar]
-o ../dir/foo.exe -Map=bar           [Crea ./bar]
-o foo.exe -Map=../dir               [Crea ../dir/foo.exe.map]
-o ../dir2/foo.exe -Map=../dir       [Crea ../dir/foo.exe.map]
-o foo.exe -Map=%                    [Crea ./foo.exe.map]
-o ../dir/foo.exe -Map=%             [Crea ../dir/foo.exe.map]
-o foo.exe -Map=%.bar                [Crea ./foo.exe.bar]
-o ../dir/foo.exe -Map=%.bar         [Crea ../dir/foo.exe.bar]
-o ../dir2/foo.exe -Map=../dir/%     [Crea ../dir/../dir2/foo.exe.map]
-o ../dir2/foo.exe -Map=../dir/%.bar [Crea ../dir/../dir2/foo.exe.bar]

    Es un error especificar más de un carácter "%".

    Si el archivo de mapa ya existe, será sobrescrito por esta operación.

    --no-keep-memory
    ld normalmente optimiza la velocidad sobre el uso de memoria almacenando en caché las tablas de símbolos de los archivos de entrada en memoria. Esta opción le indica a ld que en su lugar optimice el uso de memoria, releyendo las tablas de símbolos según sea necesario. Esto puede ser necesario si ld se queda sin espacio de memoria al enlazar un ejecutable grande.
    --no-undefined
    -z defs
    Informa sobre referencias de símbolos no resueltas de archivos objeto regulares. Esto se hace incluso si el enlazador está creando una biblioteca compartida no simbólica. El interruptor --[no-]allow-shlib-undefined controla el comportamiento de cómo informar sobre referencias no resueltas encontradas en bibliotecas compartidas que se están enlazando.

    Los efectos de esta opción se pueden revertir usando "-z undefs".

    --allow-multiple-definition
    -z muldefs
    Normalmente, cuando un símbolo se define varias veces, el enlazador informa de un error fatal. Estas opciones permiten definiciones múltiples y se utilizará la primera definición.
    --allow-shlib-undefined
    --no-allow-shlib-undefined
    Permite o prohíbe símbolos indefinidos en bibliotecas compartidas. Este interruptor es similar a --no-undefined excepto que determina el comportamiento cuando los símbolos indefinidos están en una biblioteca compartida en lugar de un archivo objeto regular. No afecta a cómo se manejan los símbolos indefinidos en archivos objeto regulares.

    El comportamiento por defecto es informar de errores para cualquier símbolo indefinido referenciado en bibliotecas compartidas si el enlazador se está utilizando para crear un ejecutable, pero permitirlos si el enlazador se está utilizando para crear una biblioteca compartida.

    Las razones para permitir referencias de símbolos indefinidos en bibliotecas compartidas especificadas en tiempo de enlace son que:

    • Una biblioteca compartida especificada en tiempo de enlace puede no ser la misma que la que está disponible en tiempo de carga, por lo que el símbolo podría ser resoluble en tiempo de carga.
    • Hay algunos sistemas operativos, por ejemplo BeOS y HPPA, donde los símbolos indefinidos en bibliotecas compartidas son normales.

      Por ejemplo, el kernel de BeOS parchea las bibliotecas compartidas en tiempo de carga para seleccionar la función que sea más apropiada para la arquitectura actual. Esto se utiliza, por ejemplo, para seleccionar dinámicamente una función memset adecuada.

    --error-handling-script=scriptname
    Si se proporciona esta opción, el enlazador invocará a scriptname cada vez que se encuentre un error. Actualmente, sin embargo, solo se admiten dos tipos de error: símbolos faltantes y bibliotecas faltantes. Se pasarán dos argumentos al script: la palabra clave "undefined-symbol" o "missing-lib" y el *nombre* del símbolo indefinido o la biblioteca faltante. La intención es que el script proporcione sugerencias al usuario sobre dónde se podría encontrar el símbolo o la biblioteca. Después de que el script haya terminado, se mostrará el mensaje de error normal del enlazador.

    La disponibilidad de esta opción está controlada por un interruptor de tiempo de configuración, por lo que puede que no esté presente en implementaciones específicas.

    --no-undefined-version
    Normalmente, cuando un símbolo tiene una versión indefinida, el enlazador la ignora. Esta opción prohíbe los símbolos con versión indefinida y, en su lugar, emitirá un error fatal.
    --default-symver
    Crea y utiliza una versión de símbolo por defecto (el soname) para los símbolos exportados sin versión.
    --default-imported-symver
    Crea y utiliza una versión de símbolo predeterminada (el soname) para los símbolos importados sin versión.
    --no-warn-mismatch
    Normalmente ld dará un error si intentas enlazar archivos de entrada que no coinciden por alguna razón, quizás porque han sido compilados para diferentes procesadores o para diferentes ordenes de bytes (endiannesses). Esta opción le dice a ld que debe permitir silenciosamente tales posibles errores. Esta opción solo debe usarse con cuidado, en casos en los que hayas tomado alguna acción especial que asegure que los errores del enlazador son inapropiados.
    --no-warn-search-mismatch
    Normalmente ld dará una advertencia si encuentra una biblioteca incompatible durante una búsqueda de bibliotecas. Esta opción silencia la advertencia.
    --no-whole-archive
    Desactiva el efecto de la opción --whole-archive para los archivos de biblioteca posteriores.
    --noinhibit-exec
    Conserva el archivo de salida ejecutable siempre que aún sea utilizable. Normalmente, el enlazador no producirá un archivo de salida si encuentra errores durante el proceso de enlazado; saldrá sin escribir un archivo de salida cuando emita cualquier error.
    -nostdlib
    Solo busca en los directorios de bibliotecas especificados explícitamente en la línea de comandos. Los directorios de bibliotecas especificados en los scripts del enlazador (incluidos los scripts del enlazador especificados en la línea de comandos) se ignoran.
    --oformat=formato-salida
    ld puede estar configurado para soportar más de un tipo de archivo objeto. Si tu ld está configurado de esta manera, puedes usar la opción --oformat para especificar el formato binario para el archivo objeto de salida. Incluso cuando ld está configurado para soportar formatos de objeto alternativos, normalmente no necesitas especificar esto, ya que ld debería estar configurado para producir como formato de salida predeterminado el formato más habitual en cada máquina. formato-salida es una cadena de texto, el nombre de un formato particular soportado por las bibliotecas BFD. (Puedes listar los formatos binarios disponibles con objdump -i.) El comando del script "OUTPUT_FORMAT" también puede especificar el formato de salida, pero esta opción lo reemplaza.
    --out-implib archivo
    Crea una biblioteca de importación en archivo correspondiente al ejecutable que el enlazador está generando (por ejemplo, un DLL o un programa ELF). Esta biblioteca de importación (que debería llamarse "*.dll.a" o "*.a" para DLLs) puede usarse para enlazar clientes contra el ejecutable generado; este comportamiento hace posible omitir un paso de creación de biblioteca de importación separado (por ejemplo, "dlltool" para DLLs). Esta opción solo está disponible para los puertos del enlazador dirigidos a i386 PE y ELF.
    -pie
    --pic-executable
    Crea un ejecutable independiente de la posición. Esto solo se soporta actualmente en plataformas ELF. Los ejecutables independientes de la posición son similares a las bibliotecas compartidas en que son reubicados por el enlazador dinámico a la dirección virtual que el sistema operativo les asigna (que puede variar entre invocaciones). Al igual que los ejecutables enlazados dinámicamente normales, pueden ser ejecutados y los símbolos definidos en el ejecutable no pueden ser anulados por bibliotecas compartidas.
    -no-pie
    Crea un ejecutable dependiente de la posición. Este es el valor predeterminado.
    -qmagic
    Esta opción se ignora por compatibilidad con Linux.
    -Qy
    Esta opción se ignora por compatibilidad con SVR4.
    --relax
    --no-relax
    Una opción con efectos dependientes de la máquina. Esta opción solo se soporta en algunos objetivos.

    En algunas plataformas, la opción --relax realiza optimizaciones globales específicas del objetivo que se vuelven posibles cuando el enlazador resuelve la direccionamiento en el programa, como relajar modos de dirección, sintetizar nuevas instrucciones, seleccionar versiones más cortas de las instrucciones actuales y combinar valores constantes.

    En algunas plataformas, estas optimizaciones globales en tiempo de enlace pueden hacer imposible la depuración simbólica del ejecutable resultante. Se sabe que este es el caso para la familia de procesadores Matsushita MN10200 y MN10300.

    En plataformas donde la característica es soportada, la opción --no-relax la deshabilitará.

    En plataformas donde la característica no es soportada, tanto --relax como --no-relax son aceptadas, pero ignoradas.

    --retain-symbols-file=nombre-archivo
    Conserva *solamente* los símbolos listados en el archivo nombre-archivo, descartando todos los demás. nombre-archivo es simplemente un archivo plano, con un nombre de símbolo por línea. Esta opción es especialmente útil en entornos (como VxWorks) donde se acumula gradualmente una gran tabla de símbolos global, para conservar memoria en tiempo de ejecución.

    --retain-symbols-file *no* descarta símbolos indefinidos, ni símbolos necesarios para realineaciones (relocations).

    Solo puedes especificar --retain-symbols-file una vez en la línea de comandos. Anula -s y -S.

    -rpath=dir
    Añade un directorio a la ruta de búsqueda de bibliotecas en tiempo de ejecución. Esto se utiliza al enlazar un ejecutable ELF con objetos compartidos. Todos los argumentos de -rpath se concatenan y se pasan al enlazador en tiempo de ejecución, que los utiliza para localizar objetos compartidos en tiempo de ejecución.

    La opción -rpath también se utiliza al localizar objetos compartidos que son requeridos por objetos compartidos incluidos explícitamente en el enlace; véase la descripción de la opción -rpath-link. La búsqueda de -rpath de esta manera solo es soportada por enlazadores nativos y enlazadores cruzados que han sido configurados con la opción --with-sysroot.

    Si no se utiliza -rpath al enlazar un ejecutable ELF, se utilizarán los contenidos de la variable de entorno "LD_RUN_PATH" si está definida.

    La opción -rpath también puede usarse en SunOS. Por predeterminado, en SunOS, el enlazador formará una ruta de búsqueda en tiempo de ejecución a partir de todas las opciones -L que se le proporcionan. Si se utiliza una opción -rpath, la ruta de búsqueda en tiempo de ejecución se formará exclusivamente utilizando las opciones -rpath, ignorando las opciones -L. Esto puede ser útil al usar gcc, que añade muchas opciones -L que pueden estar en sistemas de archivos montados por NFS.

    Para compatibilidad con otros enlazadores ELF, si la opción -R va seguida de un nombre de directorio, en lugar de un nombre de archivo, se trata como la opción -rpath.

    -rpath-link=dir
    Al usar ELF o SunOS, una biblioteca compartida puede requerir otra. Esto ocurre cuando un enlace "ld -shared" incluye una biblioteca compartida como uno de los archivos de entrada.

    Cuando el enlazador encuentra tal dependencia al realizar un enlace no compartido y no relocable, intentará automáticamente localizar la biblioteca compartida requerida e incluirla en el enlace, si no está incluida explícitamente. En tal caso, la opción -rpath-link especifica el primer conjunto de directorios a buscar. La opción -rpath-link puede especificar una secuencia de nombres de directorio, ya sea especificando una lista de nombres separados por dos puntos, o apareciendo varias veces.

    Los tokens $ORIGIN y $LIB pueden aparecer en estos directorios de búsqueda. Se reemplazarán por la ruta completa al directorio que contiene el programa o el objeto compartido en el caso de $ORIGIN y **lib** - para binarios de 32 bits - o **lib64** - para binarios de 64 bits - en el caso de $LIB.

    La forma alternativa de estos tokens - ${ORIGIN} y ${LIB} - también se puede usar. El token $PLATFORM no es compatible.

    Esta opción debe usarse con precaución, ya que anula la ruta de búsqueda que puede haber sido compilada en una biblioteca compartida. En tal caso, es posible utilizar involuntariamente una ruta de búsqueda diferente a la que el enlazador en tiempo de ejecución haría.

    El enlazador utiliza las siguientes rutas de búsqueda para localizar las bibliotecas compartidas requeridas:

    1.
    Cualquier directorio especificado por las opciones -rpath-link.
    2.
    Cualquier directorio especificado por las opciones -rpath. La diferencia entre -rpath y -rpath-link es que los directorios especificados por las opciones -rpath se incluyen en el ejecutable y se utilizan en tiempo de ejecución, mientras que la opción -rpath-link solo es efectiva en tiempo de enlace. La búsqueda de -rpath de esta manera solo es soportada por enlazadores nativos y enlazadores cruzados que han sido configurados con la opción --with-sysroot.
    3.
    En un sistema ELF, para enlazadores nativos, si no se usaron las opciones -rpath y -rpath-link, se buscan los contenidos de la variable de entorno "LD_RUN_PATH".
    4.
    En SunOS, si no se utilizó la opción -rpath, se buscan los directorios especificados usando las opciones -L.
    5.
    Para un enlazador nativo, se buscan los contenidos de la variable de entorno "LD_LIBRARY_PATH".
    6.
    Para un enlazador ELF nativo, se buscan los directorios en "DT_RUNPATH" o "DT_RPATH" de una biblioteca compartida para las bibliotecas compartidas que la requieren. Las entradas "DT_RPATH" se ignoran si existen entradas "DT_RUNPATH".
    7.
    Para un enlazador de un sistema Linux, si el archivo /etc/ld.so.conf existe, la lista de directorios encontrados en ese archivo. Nota: la ruta a este archivo se antepone al valor "sysroot", si está definido, y luego a cualquier cadena "prefix" si el enlazador fue configurado con el
    --prefix=<ruta>
    8.
    Para un enlazador nativo en un sistema FreeBSD, cualquier directorio especificado por la macro "_PATH_ELF_HINTS" definida en el archivo de cabecera elf-hints.h.
    9.
    Cualquier directorio especificado por un comando "SEARCH_DIR" en un script de enlazador dado en la línea de comandos, incluyendo scripts especificados por -T (pero no -dT).
    10.
    Los directorios predeterminados, normalmente /lib y /usr/lib.
    11.
    Cualquier directorio especificado por un LDPT_SET_EXTRA_LIBRARY_PATH de un plugin.
    12.
    Cualquier directorio especificado por un comando "SEARCH_DIR" en un script de enlazador predeterminado.

    Tenga en cuenta que en sistemas basados en Linux existe una advertencia adicional: Si la opción --as-needed está activa y se localiza una biblioteca compartida que normalmente satisfaría la búsqueda y esta biblioteca no tiene la etiqueta DT_NEEDED para libc.so y hay una biblioteca compartida más adelante en el conjunto de directorios de búsqueda que también satisface la búsqueda y esta segunda biblioteca compartida tiene una etiqueta DT_NEEDED para libc.so, entonces se seleccionará la segunda biblioteca en lugar de la primera.

    Si la biblioteca compartida requerida no se encuentra, el enlazador emitirá una advertencia y continuará con el enlace.

    -shared
    -Bshareable
    Crea una biblioteca compartida. Esto actualmente solo se soporta en plataformas ELF, XCOFF y SunOS. En SunOS, el enlazador creará automáticamente una biblioteca compartida si la opción -e no se utiliza y hay símbolos indefinidos en el enlace.
    --sort-common
    --sort-common=ascending
    --sort-common=descending
    Esta opción indica a ld que ordene los símbolos comunes por alineación en orden ascendente o descendente al colocarlos en las secciones de salida apropiadas. Las alineaciones de símbolos consideradas son de dieciséis bytes o más, ocho bytes, cuatro bytes, dos bytes y un byte. Esto es para prevenir huecos entre símbolos debido a restricciones de alineación. Si no se especifica ningún orden de clasificación, se asume el orden descendente.
    --sort-section=name
    Esta opción aplicará "SORT_BY_NAME" a todos los patrones de sección comodín en el script del enlazador.
    --sort-section=alignment
    Esta opción aplicará "SORT_BY_ALIGNMENT" a todos los patrones de sección comodín en el script del enlazador.
    --spare-dynamic-tags=cantidad
    Esta opción especifica el número de ranuras vacías a dejar en la sección .dynamic de los objetos compartidos ELF. Las ranuras vacías pueden ser necesarias para herramientas de postprocesamiento, como el preenlazador. El valor predeterminado es 5.
    --split-by-file[=tamaño]
    Similar a --split-by-reloc pero crea una nueva sección de salida por cada archivo de entrada cuando se alcanza tamaño. tamaño tiene un valor predeterminado de 1 si no se proporciona.
    --split-by-reloc[=cantidad]
    Intenta crear secciones adicionales en el archivo de salida para que ninguna sección de salida individual en el archivo contenga más de cantidad reubicaciones. Esto es útil cuando se generan archivos reubicables enormes para cargarlos en ciertos kernels de tiempo real con el formato de objeto COFF; ya que COFF no puede representar más de 65535 reubicaciones en una sola sección. Tenga en cuenta que esto fallará con formatos de archivo objeto que no soportan secciones arbitrarias. El enlazador no dividirá secciones de entrada individuales para su redistribución, por lo que si una sola sección de entrada contiene más de cantidad reubicaciones, una sección de salida contendrá esa cantidad de reubicaciones. cantidad tiene un valor predeterminado de 32768.
    --stats
    Calcula y muestra estadísticas sobre la operación del enlazador, como el tiempo de ejecución y el uso de memoria.
    --sysroot=directorio
    Utiliza directorio como la ubicación del sysroot, anulando el valor predeterminado de configuración. Esta opción solo es compatible con enlazadores que se configuraron utilizando --with-sysroot.
    --task-link
    Esto se utiliza para objetivos basados en COFF/PE para crear un archivo objeto enlazado a tareas donde todos los símbolos globales se han convertido en estáticos.
    --traditional-format
    Para algunos objetivos, la salida de ld difiere en algunos aspectos de la salida de algún enlazador existente. Este interruptor solicita a ld que utilice el formato tradicional en su lugar.

    Por ejemplo, en SunOS, ld combina entradas duplicadas en la tabla de cadenas de símbolos. Esto puede reducir el tamaño de un archivo de salida con información de depuración completa en más del 30 por ciento. Desafortunadamente, el programa "dbx" de SunOS no puede leer el programa resultante ("gdb" no tiene problemas). El interruptor --traditional-format indica a ld que no combine entradas duplicadas.

    --section-start=nombre_seccion=org
    Ubica una sección en el archivo de salida en la dirección absoluta dada por org. Puede utilizar esta opción tantas veces como sea necesario para ubicar múltiples secciones en la línea de comandos. org debe ser un solo entero hexadecimal; para compatibilidad con otros enlazadores, puede omitir el prefijo 0x asociado normalmente con los valores hexadecimales. Nota: no debe haber espacios en blanco entre nombre_seccion, el signo igual ("=") y org.
    -Tbss=org
    -Tdata=org
    -Ttext=org
    Igual que --section-start, con ".bss", ".data" o ".text" como nombre_seccion.
    -Ttext-segment=org
    Al crear un ejecutable ELF, establecerá la dirección del primer byte del segmento de texto.
    -Trodata-segment=org
    Al crear un ejecutable ELF o un objeto compartido para un objetivo donde los datos de solo lectura están en su propio segmento separado del texto ejecutable, establecerá la dirección del primer byte del segmento de datos de solo lectura.
    -Tldata-segment=org
    Al crear un ejecutable ELF o un objeto compartido para el modelo de memoria medio x86-64, establecerá la dirección del primer byte del segmento ldata.
    --unresolved-symbols=método
    Determina cómo manejar los símbolos no resueltos. Hay cuatro valores posibles para método:
    ignore-all
    No informar de ningún símbolo no resuelto.
    report-all
    Informar de todos los símbolos no resueltos. Este es el valor predeterminado.
    ignore-in-object-files
    Informar de los símbolos no resueltos que están contenidos en bibliotecas compartidas, pero ignorarlos si provienen de archivos objeto regulares.
    ignore-in-shared-libs
    Informar de los símbolos no resueltos que provienen de archivos objeto regulares, pero ignorarlos si provienen de bibliotecas compartidas. Esto puede ser útil al crear un binario dinámico y se sabe que todas las bibliotecas compartidas a las que debería hacer referencia están incluidas en la línea de comandos del enlazador.

    El comportamiento para las bibliotecas compartidas por sí solas también puede ser controlado por la opción --[no-]allow-shlib-undefined.

    Normalmente el enlazador generará un mensaje de error para cada símbolo no resuelto informado, pero la opción --warn-unresolved-symbols puede cambiar esto a una advertencia.

    --dll-verbose
    --verbose[=NÚMERO]
    Muestra el número de versión de ld y lista las emulaciones de enlazador soportadas. Muestra qué archivos de entrada se pueden abrir y cuáles no. Muestra el script del enlazador que está utilizando el enlazador. Si el argumento opcional NÚMERO es > 1, también se mostrará el estado del símbolo del plugin.
    --version-script=archivo-script-versiones
    Especifica el nombre de un script de versiones al enlazador. Esto se utiliza típicamente al crear bibliotecas compartidas para especificar información adicional sobre la jerarquía de versiones de la biblioteca que se está creando. Esta opción solo está completamente soportada en plataformas ELF que soportan bibliotecas compartidas; ver VERSION. Está parcialmente soportada en plataformas PE, que pueden usar scripts de versiones para filtrar la visibilidad de símbolos en modo de exportación automática: los símbolos marcados como local en el script de versiones no se exportarán.
    --warn-common
    Advierte cuando un símbolo común se combina con otro símbolo común o con una definición de símbolo. Los enlazadores Unix permiten esta práctica algo descuidada, pero los enlazadores en algunos otros sistemas operativos no lo hacen. Esta opción le permite encontrar problemas potenciales al combinar símbolos globales. Desafortunadamente, algunas bibliotecas C utilizan esta práctica, por lo que puede recibir algunas advertencias sobre símbolos en las bibliotecas, así como en sus programas.

    Hay tres tipos de símbolos globales, ilustrados aquí con ejemplos de C:

    int i = 1;
    Una definición, que va a la sección de datos inicializada del archivo de salida.
    extern int i;
    Una referencia indefinida, queh no asigna espacio. Debe haber una definición o un símbolo común para la variable en algún lugar.
    int i;
    Un símbolo común. Si hay solo (uno o más) símbolos comunes para una variable, esta se coloca en el área de datos no inicializados del archivo de salida. El enlazador fusiona múltiples símbolos comunes para la misma variable en un único símbolo. Si son de diferentes tamaños, elige el de mayor tamaño. El enlazador convierte un símbolo común en una declaración, si hay una definición de la misma variable.

    La opción --warn-common puede producir cinco tipos de advertencias. Cada advertencia consiste en un par de líneas: la primera describe el símbolo encontrado recientemente y la segunda describe el símbolo anterior encontrado con el mismo nombre. Uno o ambos de los dos símbolos serán un símbolo común.

    1.
    Convertir un símbolo común en una referencia, porque ya existe una definición para el símbolo. 
    <archivo>(<sección>): advertencia: común de `<símbolo>'
   sobrescrito por definición
<archivo>(<sección>): advertencia: definido aquí
    2.
    Convertir un símbolo común en una referencia, porque se encuentra una definición posterior para el símbolo. Este es el mismo caso que el anterior, excepto que los símbolos se encuentran en un orden diferente. 
    <archivo>(<sección>): advertencia: definición de `<símbolo>'
   sobrescribiendo común
<archivo>(<sección>): advertencia: común está aquí
    3.
    Fusionar un símbolo común con un símbolo común anterior del mismo tamaño. 
    <archivo>(<sección>): advertencia: común múltiple
   de `<símbolo>'
<archivo>(<sección>): advertencia: común anterior está aquí
    4.
    Fusionar un símbolo común con un símbolo común anterior más grande. 
    <archivo>(<sección>): advertencia: común de `<símbolo>'
   sobrescrito por común más grande
<archivo>(<sección>): advertencia: común más grande está aquí
    5.
    Fusionar un símbolo común con un símbolo común anterior más pequeño. Este es el mismo caso que el anterior, excepto que los símbolos se encuentran en un orden diferente.

    --warn-constructors
    Advierte si se utilizan constructores globales. Esto solo es útil para unos pocos formatos de archivo objeto. Para formatos como COFF o ELF, el enlazador no puede detectar el uso de constructores globales.
    --warn-execstack
    --warn-execstack-objects
    --no-warn-execstack
    En plataformas ELF, el enlazador puede generar mensajes de advertencia si se le solicita crear un archivo de salida que contenga una pila ejecutable. Hay tres estados posibles:
    1.
    No generar ninguna advertencia.
    2.
    Generar siempre advertencias, incluso si se solicita una pila ejecutable a través de la opción de línea de comandos -z execstack.
    3.
    Generar una advertencia solo si un archivo objeto solicita una pila ejecutable, pero no si se utiliza la opción -z execstack.

    El estado predeterminado depende de cómo se configuró el enlazador cuando se compiló. La opción --no-warn-execstack siempre pone el enlazador en el estado de no advertencias. La opción --warn-execstack pone el enlazador en el estado de advertir siempre. La opción --warn-execstack-objects pone el enlazador en el estado de advertir solo para archivos objeto.

    Nota: Los archivos de entrada en formato ELF pueden especificar que necesitan una pila ejecutable teniendo una sección .note.GNU-stack con el bit ejecutable activado en sus flags de sección. Pueden especificar que no necesitan una pila ejecutable teniendo la misma sección, pero sin el bit de flag ejecutable activado. Si un archivo de entrada no tiene una sección .note.GNU-stack, entonces el comportamiento predeterminado es específico del objetivo. Para algunos objetivos, la ausencia de dicha sección implica que se *requiere* una pila ejecutable. Esto suele ser un problema para archivos ensambladores creados manualmente.

    --error-execstack
    --no-error-execstack
    Si el enlazador va a generar un mensaje de advertencia sobre una pila ejecutable, la opción --error-execstack convertirá esa advertencia en un error en su lugar. Nota: esta opción no cambia el estado de generación de advertencias de execstack del enlazador. Utilice --warn-execstack o --warn-execstack-objects para establecer un estado de advertencia específico.

    La opción --no-error-execstack restaurará el comportamiento predeterminado de generar mensajes de advertencia.

    --warn-multiple-gp
    Advierte si se requieren múltiples valores de puntero global en el archivo de salida. Esto solo es significativo para ciertos procesadores, como Alpha. Específicamente, algunos procesadores colocan constantes de valor grande en una sección especial. Un registro especial (el puntero global) apunta al medio de esta sección, de modo que las constantes se puedan cargar de manera eficiente mediante un modo de direccionamiento relativo al registro base. Dado que el desplazamiento en el modo relativo al registro base es fijo y relativamente pequeño (por ejemplo, 16 bits), esto limita el tamaño máximo del grupo de constantes. Por lo tanto, en programas grandes, a menudo es necesario usar múltiples valores de puntero global para poder direccionar todas las constantes posibles. Esta opción causa una advertencia cuando ocurre este caso.
    --warn-once
    Advertir solo una vez por cada símbolo no resuelto, en lugar de una vez por módulo que se refiere a él.
    --warn-rwx-segments
    --no-warn-rwx-segments
    Advierte si el enlazador crea un segmento cargable de tamaño distinto de cero que tiene los tres flags de permiso de lectura, escritura y ejecución activados. Dicho segmento representa una posible vulnerabilidad de seguridad. Además, se generarán advertencias si se crea un segmento de almacenamiento de hilo local con el flag de permiso de ejecución activado, independientemente de si tiene o no los flags de lectura y/o escritura activados.

    Estas advertencias están habilitadas por defecto. Se pueden deshabilitar mediante la opción --no-warn-rwx-segments y volver a habilitar mediante la opción --warn-rwx-segments.

    --error-rwx-segments
    --no-error-rwx-segments
    Si el enlazador va a generar un mensaje de advertencia sobre un segmento ejecutable y grabable, o un segmento TLS ejecutable, entonces la opción --error-rwx-segments convertirá esta advertencia en un error en su lugar. La opción --no-error-rwx-segments restaurará el comportamiento predeterminado de solo generar un mensaje de advertencia.

    Nota: la opción --error-rwx-segments no activa por sí sola advertencias sobre estos segmentos. Estas advertencias están habilitadas por defecto, si el enlazador fue configurado de esa manera, o a través de la opción de línea de comandos --warn-rwx-segments.

    --warn-section-align
    Advierte si la dirección de una sección de salida se modifica debido a la alineación. Típicamente, la alineación será establecida por una sección de entrada. La dirección solo se modificará si no se especifica explícitamente; es decir, si el comando "SECTIONS" no especifica una dirección de inicio para la sección.
    --warn-textrel
    Advierte si el enlazador agrega DT_TEXTREL a un ejecutable o biblioteca compartida independiente de la posición.
    --warn-alternate-em
    Advierte si un objeto tiene código de máquina ELF alternativo.
    --warn-unresolved-symbols
    Si el enlazador va a reportar un símbolo no resuelto (ver la opción --unresolved-symbols), normalmente generará un error. Esta opción hace que genere una advertencia en su lugar.
    --error-unresolved-symbols
    Esto restaura el comportamiento predeterminado del enlazador de generar errores cuando está reportando símbolos no resueltos.
    --whole-archive
    Para cada archivo de biblioteca mencionado en la línea de comandos después de la opción --whole-archive, incluye cada archivo objeto en el archivo de biblioteca en el enlace, en lugar de buscar en el archivo de biblioteca los archivos objeto requeridos. Esto se usa normalmente para convertir un archivo de biblioteca en una biblioteca compartida, forzando que cada objeto se incluya en la biblioteca compartida resultante. Esta opción se puede usar más de una vez.

    Dos notas al usar esta opción desde gcc: Primero, gcc no conoce esta opción, por lo que debe usar -Wl,-whole-archive. Segundo, no olvide usar -Wl,-no-whole-archive después de su lista de archivos de biblioteca, porque gcc agregará su propia lista de archivos de biblioteca a su enlace y es posible que no desee que esta bandera afecte a esos también.

    --wrap=símbolo
    Utiliza una función envolvente para símbolo. Cualquier referencia no definida a símbolo se resolverá como "__wrap_símbolo". Cualquier referencia no definida a "__real_símbolo" se resolverá como símbolo.

    Esto se puede usar para proporcionar un envoltorio para una función del sistema. La función envolvente debe llamarse "__wrap_símbolo". Si desea llamar a la función del sistema, debe llamar a "__real_símbolo".

    Aquí hay un ejemplo trivial:

    void *
__wrap_malloc (size_t c)
{
  printf ("malloc llamado con %zu\n", c);
  return __real_malloc (c);
}

    Si enlaza otro código con este archivo usando --wrap malloc, entonces todas las llamadas a "malloc" llamarán a la función "__wrap_malloc" en su lugar. La llamada a "__real_malloc" en "__wrap_malloc"<

    llamará a la función "malloc" real.

    Es posible que desee proporcionar también una función "__real_malloc", para que los enlaces sin la opción --wrap tengan éxito. Si lo hace, no debe poner la definición de "__real_malloc" en el mismo archivo que "__wrap_malloc"; si lo hace, el ensamblador puede resolver la llamada antes de que el enlazador tenga la oportunidad de envolverla a "malloc".

    El enlazador solo reemplaza las referencias indefinidas. Por lo tanto, las referencias internas de la unidad de traducción a symbol no se resuelven a "__wrap_symbol". En el siguiente ejemplo, la llamada a "f" en "g" no se resuelve a "__wrap_f".

    int
f (void)
{
  return 123;
}

int
g (void)
{
  return f();
}

    --no-eh-frame-hdr
    Solicita (--eh-frame-hdr) o suprime (--no-eh-frame-hdr) la creación de la sección ".eh_frame_hdr" y la cabecera del segmento ELF "PT_GNU_EH_FRAME".
    --no-ld-generated-unwind-info
    Solicita la creación de información de desenrollado ".eh_frame" para secciones de código generadas por el enlazador como PLT. Esta opción está activada por defecto si se admite la información de desenrollado generada por el enlazador. Esta opción también controla la generación de información de seguimiento de pila ".sframe" para secciones de código generadas por el enlazador como PLT.
    --enable-new-dtags
    --disable-new-dtags
    Este enlazador puede crear las nuevas etiquetas dinámicas en ELF. Pero los sistemas ELF más antiguos pueden no entenderlas. Si especifica --enable-new-dtags, se crearán las nuevas etiquetas dinámicas según sea necesario y se omitirán las etiquetas dinámicas antiguas. Si especifica --disable-new-dtags, no se crearán nuevas etiquetas dinámicas. Por defecto, las nuevas etiquetas dinámicas no se crean. Tenga en cuenta que estas opciones solo están disponibles para sistemas ELF.
    --hash-size=number
    Establece el tamaño por defecto de las tablas hash del enlazador a un número primo cercano a number. Aumentar este valor puede reducir el tiempo que tarda el enlazador en realizar sus tareas, a costa de aumentar los requisitos de memoria del enlazador. Del mismo modo, reducir este valor puede reducir los requisitos de memoria a costa de la velocidad.
    --hash-style=style
    Establece el tipo de tabla(s) hash del enlazador. style puede ser "sysv" para la sección clásica ".hash" de ELF, "gnu" para la sección ".gnu.hash" de estilo GNU nuevo o "both" para ambas tablas hash, la clásica ".hash" de ELF y la nueva estilo GNU ".gnu.hash". El valor por defecto depende de cómo se haya configurado el enlazador, pero para la mayoría de los sistemas basados en Linux será "both".
    --compress-debug-sections=none
    --compress-debug-sections=zlib
    --compress-debug-sections=zlib-gnu
    --compress-debug-sections=zlib-gabi
    --compress-debug-sections=zstd
    En plataformas ELF, estas opciones controlan cómo se comprimen las secciones de depuración DWARF usando zlib.

    --compress-debug-sections=none no comprime las secciones de depuración DWARF. --compress-debug-sections=zlib-gnu comprime las secciones de depuración DWARF y las renombra para que comiencen con .zdebug en lugar de .debug. --compress-debug-sections=zlib-gabi también comprime las secciones de depuración DWARF, pero en lugar de renombrarlas, establece la bandera SHF_COMPRESSED en las cabeceras de las secciones.

    La opción --compress-debug-sections=zlib es un alias de --compress-debug-sections=zlib-gabi.

    --compress-debug-sections=zstd comprime las secciones de depuración DWARF usando zstd.

    Tenga en cuenta que esta opción anula cualquier compresión en las secciones de depuración de entrada, por lo que si un binario se enlaza con --compress-debug-sections=none, por ejemplo, entonces cualquier sección de depuración comprimida en los archivos de entrada se descomprimirá antes de copiarse en el binario de salida.

    El comportamiento de compresión por defecto varía según la plataforma de destino y las opciones de configuración utilizadas para compilar la cadena de herramientas. El valor por defecto se puede determinar examinando la salida de la opción --help del enlazador.

    --reduce-memory-overheads
    Esta opción reduce los requisitos de memoria en tiempo de ejecución de ld, a costa de la velocidad de enlace. Se introdujo para seleccionar el antiguo algoritmo O(n^2) para la generación de archivos de mapa de enlace, en lugar del nuevo algoritmo O(n) que utiliza aproximadamente un 40% más de memoria para el almacenamiento de símbolos.

    Otro efecto del cambio es establecer el tamaño de tabla hash por defecto en 1021, lo que de nuevo ahorra memoria a costa de alargar el tiempo de ejecución del enlazador. Sin embargo, esto no se hace si se ha utilizado el cambio --hash-size.

    El cambio --reduce-memory-overheads también puede ser utilizado para habilitar otras compensaciones en futuras versiones del enlazador.

    --max-cache-size=size
    ld normalmente almacena en caché la información de reubicación y las tablas de símbolos de los archivos de entrada en memoria con tamaño ilimitado. Esta opción establece el tamaño máximo de caché en size.
    --build-id
    --build-id=style
    Solicita la creación de una sección de nota ELF ".note.gnu.build-id" o una sección COFF ".buildid". El contenido de la nota son bits únicos que identifican este archivo enlazado. style puede ser "uuid" para usar 128 bits aleatorios, "sha1" para usar un hash SHA1 de 160 bits sobre las partes normativas del contenido de salida, "md5" para usar un hash MD5 de 128 bits sobre las partes normativas del contenido de salida, o "0xhexstring" para usar una cadena de bits elegida especificada como un número par de dígitos hexadecimales (los caracteres "-" y ":" entre pares de dígitos se ignoran). Si se omite style, se utiliza "sha1".

    Los estilos "md5" y "sha1" producen un identificador que es siempre el mismo en un archivo de salida idéntico, pero será único entre todos los archivos de salida no idénticos. No está pensado para ser comparado como una suma de verificación del contenido del archivo. Un archivo enlazado puede ser modificado posteriormente por otras herramientas, pero la cadena de bits del ID de compilación que identifica el archivo enlazado original no cambia.

    Pasar "none" para style deshabilita la configuración de cualquier opción "--build-id" anterior en la línea de comandos.

    --package-metadata=JSON
    Solicita la creación de una sección de nota ELF ".note.package". El contenido de la nota está en formato JSON, según la especificación de metadatos del paquete. Para más información, consulte: https://systemd.io/ELF_PACKAGE_METADATA/ Si el argumento JSON falta/está vacío, se deshabilitará la creación de la nota de metadatos, si se hubiera habilitado por una ocurrencia anterior de la opción --package-metadata. Si el enlazador se ha compilado con libjansson, se validará la cadena JSON.

Debe nombrar la salida "*.dll" cuando utilice esta opción. Además, el enlazador admite completamente los archivos "*.def" estándar, que se pueden especificar en la línea de comandos del enlazador como un archivo objeto (de hecho, debe preceder a los archivos que exporta símbolos, para asegurar que se enlacen, al igual que un archivo objeto normal).

    Además de las opciones comunes a todos los destinos, el enlazador PE i386 admite opciones de línea de comandos adicionales que son específicas del destino PE i386. Las opciones que toman valores pueden estar separadas de sus valores por un espacio o un signo igual.

    --add-stdcall-alias

    --dll

    --disable-long-section-names
    Las variantes PE del formato de objeto COFF agregan una extensión que permite el uso de nombres de sección más largos que ocho caracteres, el límite normal para COFF. Por defecto, estos nombres están activados.
    permitido en archivos objeto, ya que las imágenes ejecutables completamente enlazadas no llevan la tabla de cadenas COFF necesaria para soportar nombres más largos. Como extensión de GNU, es posible permitir su uso también en imágenes ejecutables, o (probablemente sin sentido) desautorizarlo en archivos objeto, utilizando estas dos opciones.     --enable-stdcall-fixup
    --disable-stdcall-fixup

    --export-all-symbols

    Las siguientes observaciones se refieren a la implementación original de la característica y hoy en día son obsoletas para los destinos Cygwin y MinGW.

    Nota: El uso de la extensión 'auto-import' hará que la sección de texto del archivo de imagen se vuelva escribible. Esto no se ajusta a la especificación del formato PE-COFF publicada por Microsoft.

    Nota: el uso de la extensión 'auto-import' también hará que los datos de solo lectura que normalmente se colocarían en la sección .rdata se coloquen en la sección .data en su lugar. Esto es para solucionar un problema con las constantes que se describe aquí: http://www.cygwin.com/ml/cygwin/2004-09/msg01101.html

    El uso de 'auto-import' generalmente 'funcionará' -- pero a veces puedes ver este mensaje:

    "la variable '<var>' no se puede autoimportar. Por favor, lee la documentación de ld sobre "--enable-auto-import" para más detalles."

    Este mensaje ocurre cuando alguna (sub)expresión accede a una dirección dada finalmente por la suma de dos constantes (las tablas de importación de Win32 solo permiten una). Las instancias donde esto puede ocurrir incluyen accesos a campos miembros de variables de estructura importadas de una DLL, así como el uso de un índice constante en una variable de matriz importada de una DLL. Cualquier variable de varias palabras (matrices, estructuras, long long, etc.) puede desencadenar esta condición de error. Sin embargo, independientemente del tipo de datos exacto de la variable exportada ofensiva, ld siempre la detectará, emitirá la advertencia y saldrá.

    Existen varias formas de abordar esta dificultad, independientemente del tipo de datos de la variable exportada:

    Una forma es usar el interruptor --enable-runtime-pseudo-reloc. Esto deja la tarea de ajustar las referencias en su código cliente para el entorno de ejecución, por lo que este método solo funciona cuando el entorno de ejecución admite esta característica.

    Una segunda solución es forzar una de las 'constantes' a ser una variable -- es decir, desconocida y no optimizable en tiempo de compilación. Para las matrices, hay dos posibilidades: a) hacer que el indexado (la dirección de la matriz) sea una variable, o b) hacer que el índice 'constante' sea una variable. Así:

    extern type extern_array[];
extern_array[1] -->
   { volatile type *t=extern_array; t[1] }

    o

    extern type extern_array[];
extern_array[1] -->
   { volatile int t=1; extern_array[t] }

    Para estructuras (y la mayoría de los otros tipos de datos de varias palabras) la única opción es hacer que la propia estructura (o el long long, o el ...) sea una variable:

    extern struct s extern_struct;
extern_struct.field -->
   { volatile struct s *t=&extern_struct; t->field }

    o

    extern long long extern_ll;
extern_ll -->
  { volatile long long * local_ll=&extern_ll; *local_ll }

    Un tercer método para lidiar con esta dificultad es abandonar 'auto-import' para el símbolo ofensivo y marcarlo con . Sin embargo, en la práctica, esto requiere el uso de #defines en tiempo de compilación para indicar si estás creando una DLL, creando código cliente que se enlazará a la DLL, o simplemente creando/enlazando a una biblioteca estática. Al elegir entre los diversos métodos para resolver el problema de 'dirección directa con desplazamiento constante', debes considerar el uso típico en el mundo real:

    Original:

    --foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

    Solución 1:

    --foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  /* Esta solución alternativa es para win32 y cygwin; no "optimizar" */
  volatile int *parr = arr;
  printf("%d\n",parr[1]);
}

    Solución 2:

    --foo.h
/* Nota: se asume auto-export (sin __declspec(dllexport)) */
#if (defined(_WIN32) || defined(__CYGWIN__)) && \
  !(defined(FOO_BUILD_DLL) || defined(FOO_STATIC))
#define FOO_IMPORT __declspec(dllimport)
#else
#define FOO_IMPORT
#endif
extern FOO_IMPORT int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

    Puede cambiar el comportamiento de ld con las variables de entorno "GNUTARGET", "LDEMULATION" y "COLLECT_NO_DEMANGLE".

    "GNUTARGET" determina el formato de objeto del archivo de entrada si no usa -b (o su sinónimo --format). Su valor debe ser uno de los nombres BFD para un formato de entrada. Sin embargo, el procedimiento de configuración para BFD en cada sistema coloca el formato convencional para ese sistema primero en la lista de búsqueda, por lo que las ambigüedades se resuelven a favor de la convención.
