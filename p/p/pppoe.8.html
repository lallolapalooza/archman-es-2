PPPOE(8) Manual del Administrador del Sistema PPPOE(8)

NOMBRE

pppoe - cliente PPPoE en modo usuario.

SINOPSIS

pppd pty 'pppoe [opciones_pppoe]' [opciones_pppd]

pppoe -A [opciones_pppoe]

DESCRIPCIÓN

pppoe es un cliente en modo usuario para PPPoE (Protocolo Point-to-Point sobre Ethernet) para Linux y otros sistemas UNIX. pppoe trabaja en conjunto con el demonio PPP pppd para proporcionar una conexión PPP sobre Ethernet, tal como la utilizan muchos proveedores de servicios DSL.

OPCIONES

-I interfaz
La opción -I especifica la interfaz Ethernet a utilizar. En Linux, suele ser eth0 o eth1. La interfaz debe estar "arriba" (activada) antes de iniciar pppoe, pero no debe tener una dirección IP configurada.
-T tiempo_espera
La opción -T hace que pppoe salga si no se detecta tráfico de sesión durante tiempo_espera segundos. Recomiendo usar esta opción como una medida de seguridad adicional, pero si lo hace, debe asegurarse de que PPP genera suficiente tráfico para que el tiempo de espera normalmente no se active. La mejor manera de hacerlo es usar la opción lcp-echo-interval para pppd. Debe establecer el tiempo de espera de PPPoE en aproximadamente cuatro veces el intervalo de eco LCP.
-D nombre_archivo
La opción -D hace que cada paquete se vuelque al nombre_archivo especificado. Esto es solo para depuración; produce grandes cantidades de salida y reduce significativamente el rendimiento.
-V
La opción -V hace que pppoe imprima su número de versión y salga.
-A
La opción -A hace que pppoe envíe un paquete PADI y luego imprima los nombres de los concentradores de acceso en cada paquete PADO que reciba. No use esta opción junto con pppd; la opción -A está pensada para ser utilizada interactivamente y proporcionar información interesante sobre el concentrador de acceso.
-S nombre_servicio
Especifica el nombre de servicio deseado. pppoe solo iniciará sesiones con concentradores de acceso que puedan proporcionar el servicio especificado. En la mayoría de los casos, no debe especificar esta opción. Úsela solo si sabe que hay múltiples concentradores de acceso o si sabe que necesita un nombre de servicio específico.
-C nombre_ac
Especifica el nombre del concentrador de acceso deseado. pppoe solo iniciará sesiones con el concentrador de acceso especificado. En la mayoría de los casos, no debe especificar esta opción. Úsela solo si sabe que hay múltiples concentradores de acceso. Si se especifican ambas opciones, -S y -C, ambas deben coincidir para que pppoe inicie una sesión.
-U
Hace que pppoe use la etiqueta Host-Uniq en sus paquetes de descubrimiento. Esto le permite ejecutar múltiples demonios pppoe sin que sus paquetes de descubrimiento interfieran entre sí. Debe proporcionar esta opción a todos los demonios pppoe si pretende ejecutar varios demonios simultáneamente. El valor específico de Host-Uniq utilizado es la representación hexadecimal del PID del proceso pppoe.
-W valor
Hace que pppoe use la etiqueta Host-Uniq en sus paquetes de descubrimiento y, además, establece el valor de Host-Uniq en valor. Úselo con precaución. Tenga en cuenta que -W y -U son mutuamente excluyentes.
-s
Hace que pppoe use encapsulación PPP síncrona. Si usa esta opción, entonces debe usar la opción sync con pppd. Se recomienda usar esta opción si funciona, ya que reduce en gran medida la sobrecarga de CPU de pppoe. Sin embargo, PUEDE ser poco fiable en máquinas lentas: existe una condición de carrera entre pppd escribiendo datos y pppoe leyéndolos. Por esta razón, la configuración predeterminada es asíncrona. Si encuentra errores o bloqueos con PPP Síncrono, desactívelo; ¡no me envíe correos electrónicos solicitando soporte!
-m MSS
Hace que pppoe limite el tamaño máximo del segmento TCP al valor especificado. Debido a la sobrecarga de PPPoE, el tamaño máximo del segmento para PPPoE es menor que para la encapsulación Ethernet normal. Esto podría causar problemas a las máquinas en una LAN detrás de un enrutador que utiliza PPPoE. Si tiene una LAN detrás de un enrutador, y el enrutador se conecta a Internet usando PPPoE, se recomienda encarecidamente usar la opción -m 1412. Esto evita tener que establecer la MTU en todos los hosts de la LAN.
-p archivo
Hace que pppoe escriba su ID de proceso en el archivo especificado. Esto se puede usar para localizar y eliminar procesos pppoe.
-e ses:mac
Hace que pppoe omita la fase de descubrimiento y pase directamente a la fase de sesión. La sesión está dada por ses y la dirección MAC del par por mac. Este modo no está diseñado para uso normal; está diseñado solo para pppoe-server(8).
-n
Hace que pppoe no abra un socket de descubrimiento. Este modo no está diseñado para uso normal; está diseñado solo para pppoe-server(8).
-k
Hace que pppoe termine una sesión existente enviando un marco PADT y luego salga. Debe usar la opción -e junto con esta opción para especificar la sesión a terminar. Esto puede ser útil para terminar sesiones cuando un par defectuoso no se da cuenta de que la sesión ha terminado.
-d
Hace que pppoe realice el descubrimiento y luego salga, después de imprimir la información de la sesión en la salida estándar. La información de la sesión se imprime exactamente en el formato esperado por la opción -e. Esta opción le permite iniciar un descubrimiento PPPoE, realizar otro trabajo y luego iniciar la sesión PPP real. Tenga cuidado; si usa esta opción en un bucle, puede crear muchas sesiones, lo que puede molestar a su par.
-f disc:sess
La opción -f establece los tipos de trama Ethernet para los marcos de descubrimiento y sesión de PPPoE. Los tipos se especifican como números hexadecimales separados por dos puntos. PPPoE estándar usa los tipos de trama 8863:8864. No debe usar esta opción a menos que esté absolutamente seguro de que el par con el que está tratando utiliza tipos de trama no estándar. Si su ISP utiliza tipos de trama no estándar, ¡queje!
-h
La opción -h hace que pppoe imprima información de uso y salga.

PPPOE ANTECEDENTES

PPPoE (Protocolo Point-to-Point sobre Ethernet) se describe en el RFC 2516 y es un protocolo que permite mantener la abstracción de sesión sobre redes Ethernet puenteadas.

PPPoE funciona encapsulando tramas PPP en tramas Ethernet. El protocolo tiene dos etapas distintas: el descubrimiento y la etapa de sesión.

En la etapa de descubrimiento, el host emite una trama especial PADI (PPPoE Active Discovery Initiation) para descubrir cualquier *concentrador de acceso*. Los concentradores de acceso (típicamente, solo un concentrador de acceso) responden con paquetes PADO (PPPoE Active Discovery Offer), anunciando su presencia y los servicios que ofrecen. El host selecciona uno de los concentradores de acceso y transmite un paquete PADR (PPPoE Active Discovery Request), solicitando una sesión. El concentrador de acceso responde con un paquete PADS (PPPoE Active Discovery Session-Confirmation). Luego, el protocolo pasa a la etapa de sesión.

En la etapa de sesión, el host y el concentrador de acceso intercambian tramas PPP incrustadas en tramas Ethernet. La MTU Ethernet normal es de 1500 bytes, pero la sobrecarga de PPPoE más dos bytes de sobrecarga para la trama PPP encapsulada significan que la MTU de la interfaz PPP es como máximo de 1492 bytes. pppoe(8)

NAME

pppoe - Point-to-Point Protocol over Ethernet driver

SYNOPSIS

pppoe [ options ]

DESCRIPTION

The pppoe program implements a Point-to-Point Protocol (PPP) client over an Ethernet network, using the PPPoE (Point-to-Point Protocol over Ethernet) protocol as specified in RFC 2516. It allows you to use a DSL modem or other Ethernet-based connection that requires PPPoE authentication to connect to an ISP.

pppoe acts as a frontend to the pppd(8) program. It handles the PPPoE discovery and session establishment phase, and then invokes pppd(8) to handle the PPP session itself.

OPTIONS

pppoe accepts the following options:

-d
Runs pppoe in the foreground. This is useful for debugging.
-h
Prints a help message and exits.
-i interface
Specifies the Ethernet interface to use for the PPPoE connection. If not specified, pppoe will try to find an unused Ethernet interface with an IP address.
-m size
Sets the PPPoE maximum receive payload size. The default is 1492 bytes.
-p pidfile
Specifies a file to write the process ID (PID) to. This is useful for managing the daemon process.
-s
Runs pppoe as a daemon in the background. This is the default behavior.
-v
Prints version information and exits.

All other arguments are passed directly to pppd(8).

PPPOE BACKGROUND

Normally, PPP uses the Link Control Protocol (LCP) to shut down a PPP link. However, the PPPoE specification allows the link to be shut down with a special PADT (PPPoE Active Discovery Terminate) packet. This client recognizes this packet and will correctly terminate if a terminate request is received for the PPP session.

Setting the MTU of machines behind a firewall to 1412 is recommended to avoid potential problems with excessively large frames. This allows for worst-case TCP and IP options in their respective headers.

DESIGN GOALS

The design goals for this PPPoE client were:

o
It must work.
o
It must be a user-space program, not a kernel patch.
o
The code must be easy to read and maintain.
o
It must be fully compliant with RFC 2516.
o
It must never hang up forever; if the connection is broken, it must detect this and exit, allowing a wrapper script to restart the connection.
o
It must be fairly efficient.

The author believes these goals have been achieved, but welcomes suggestions, patches, and ideas. Contact information can be found on the project's home page: https://dianne.skoll.ca/projects/rp-pppoe/.

NOTES

For best results, you must give pppd an mtu option of 1492. Excessively large frames have been observed to cause problems unless this option is set. Additionally, if pppoe is running on a firewall machine, all machines behind the firewall should have MTU's of 1412.

If you encounter problems, check your system logs. pppoe logs interesting information to syslog. You may need to enable logging of debug-level messages for a complete diagnosis.
