PPTPD.CONF(5) Manual de formatos de archivo PPTPD.CONF(5)

NOMBRE

pptpd.conf - configuración del demonio VPN PPTP

DESCRIPCIÓN

pptpd(8) lee las opciones de este archivo, usualmente /etc/pptpd.conf. La mayoría de las opciones pueden ser anuladas por la línea de comandos. Las direcciones IP locales y remotas para los clientes deben provenir del archivo de configuración o de los archivos de configuración de pppd(8).

OPCIONES

option archivo-opciones
el nombre de un archivo de opciones que se pasará a pppd(8) en lugar del archivo predeterminado /etc/ppp/options para que se puedan proporcionar opciones específicas de PPTP. Equivalente a la opción de línea de comandos --option.
stimeout segundos
número de segundos a esperar por un paquete PPTP antes de crear el programa pptpctrl(8) para manejar al cliente. El valor predeterminado es 10 segundos. Esta es una característica de protección contra ataques de denegación de servicio. Equivalente a la opción de línea de comandos --stimeout.
logwtmp
actualiza wtmp(5) cuando los usuarios se conectan y desconectan. Véase wtmp(1).
debug
activa el modo de depuración, enviando información de depuración a syslog(3). No tiene efecto en la depuración de pppd(8). Equivalente a la opción de línea de comandos --debug.
bcrelay interfaz-interna
activa el modo de retransmisión de broadcast, enviando todos los broadcasts recibidos en la interfaz interna del servidor a los clientes. Equivalente a la opción de línea de comandos --bcrelay.
connections n
limita el número de conexiones de clientes que se pueden aceptar. Si pptpd está asignando direcciones IP (por ejemplo, si no se utiliza delegate), el número de conexiones también está limitado por la opción remoteip. El valor predeterminado es 100.
delegate
delega la asignación de direcciones IP de clientes a pppd(8). Sin esta opción, que es la predeterminada, pptpd gestiona la lista de direcciones IP para los clientes y pasa la siguiente dirección libre a pppd. Con esta opción, pptpd no pasa una dirección, y por lo tanto pppd puede usar radius o chap-secrets para asignar una dirección.
localip especificación-ip
una o varias direcciones IP que se utilizarán en el extremo local de los enlaces PPP tunelizados entre el servidor y el cliente. Si solo se proporciona una dirección, esta dirección se utilizará para todos los clientes. De lo contrario, se debe proporcionar una dirección por cliente, y si no hay direcciones libres, se rechazarán los nuevos clientes. localip será ignorada si se utiliza la opción delegate.
remoteip especificación-ip
una lista de direcciones IP para asignar a clientes PPTP remotos. Cada cliente conectado debe tener una dirección diferente, por lo que debe haber al menos tantas direcciones como clientes simultáneos tenga, y preferiblemente algunas de reserva, ya que no se puede cambiar esta lista sin reiniciar pptpd. Se enviará una advertencia a syslog(3) cuando se agote el grupo de direcciones IP. remoteip será ignorada si se utiliza la opción delegate.
noipparam
por defecto, la dirección IP original del cliente se pasa a los scripts ip-up utilizando la opción ipparam de pppd(8). La opción noipparam evita esto. Equivalente a la opción de línea de comandos --noipparam.
listen dirección-ip
la dirección IP de la interfaz local a la que escuchar las conexiones PPTP entrantes (puerto TCP 1723). Equivalente a la opción de línea de comandos --listen.
vrf nombre-vrf
VRF a utilizar para el socket de escucha TCP, así como para los paquetes GRE. Equivalente a la opción de línea de comandos --vrf.
pidfile archivo-pid
especifica una ubicación alternativa para almacenar el archivo de ID del proceso (predeterminado /var/run/pptpd.pid). Equivalente a la opción de línea de comandos --pidfile.
speed velocidad
especifica una velocidad (en bits por segundo) para pasar al demonio PPP como la velocidad de la interfaz para el par tty/pty. Esto es ignorado por algunos demonios PPP, como el pppd(8) de Linux. El valor predeterminado es 115200 bytes por segundo, que algunas implementaciones interpretan como "sin límite". Equivalente a la opción de línea de comandos --speed.

NOTAS

Una especificación-ip anterior (para las etiquetas localip y remoteip) puede ser una lista de direcciones IP (por ejemplo 192.168.0.2,192.168.0.3), un rango (por ejemplo 192.168.0.1-254 o 192.168.0-255.2) o alguna combinación (por ejemplo 192.168.0.2,192.168.0.5-8). Algunos pares válidos podrían ser (dependiendo del uso de la VPN):

localip 192.168.0.1
remoteip 192.168.0.2-254

o

localip 192.168.1.2-254
remoteip 192.168.0.2-254

LISTA DE VERIFICACIÓN DE ENRUTAMIENTO - PROXYARP

Asigna una sección de tus direcciones LAN para uso de los clientes.

En /etc/ppp/options.pptpd. configura la opción proxyarp. En pptpd.conf no configures la opción localip, pero configura remoteip al rango de direcciones asignado. Habilita el reenvío de paquetes del kernel (por ejemplo, usando /proc/sys/net/ipv4/ip_forward ).

El servidor anunciará los clientes a la LAN usando ARP, proporcionando su propia dirección Ethernet. bcrelay(8) no debería ser requerido.

LISTA DE VERIFICACIÓN DE ENRUTAMIENTO - REENVÍO

Asigna una subred para los clientes que sea enrutable desde tu LAN, pero que no sea parte de tu LAN.

En pptpd.conf configura localip a una única dirección o rango en la subred asignada, configura remoteip a un rango en la subred asignada. Habilita el reenvío de paquetes del kernel (por ejemplo, usando /proc/sys/net/ipv4/ip_forward ). La LAN debe tener una ruta a los clientes usando el servidor como gateway.

El servidor reenviará los paquetes sin cambios entre los clientes y la LAN. Se requerirá bcrelay(8) para soportar protocolos de broadcast como NETBIOS.

LISTA DE VERIFICACIÓN DE ENRUTAMIENTO - ENMASCARAMIENTO

Asigna una subred para los clientes que no sea enrutable desde tu LAN, y que no sea de otra manera enrutable desde el servidor (por ejemplo, 10.0.0.0/24).

Configura localip a una única dirección en la subred (por ejemplo, 10.0.0.1), configura remoteip a un rango para el resto de la subred, (por ejemplo, 10.0.0.2-200). Habilita el reenvío de paquetes del kernel (por ejemplo, usando /proc/sys/net/ipv4/ip_forward ). Habilita el enmascaramiento en eth0 (por ejemplo, iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE ).

El servidor traducirá los paquetes entre los clientes y la LAN. Los clientes aparecerán en la LAN como si tuvieran la dirección correspondiente al servidor. La LAN no necesita tener una ruta explícita a los clientes. Se requerirá bcrelay(8) para soportar protocolos de broadcast como NETBIOS.

REGLAS DE FIREWALL

pptpd(8) acepta conexiones de control en el puerto TCP 1723, y luego utiliza GRE (protocolo 47) para intercambiar paquetes de datos. Añade estas reglas a tu configuración de iptables(8), o úsalas como base para tus propias reglas:

iptables --append INPUT --protocol 47 --jump ACCEPT 

iptables --append INPUT --protocol tcp --match tcp \
         --destinat
