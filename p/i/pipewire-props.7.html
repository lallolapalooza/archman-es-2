NOMBRE

pipewire-props - Referencia de propiedades de objetos de PipeWire.

DESCRIPCIÓN

PipeWire describe y configura elementos de audio y video con objetos de los siguientes tipos principales:

Nodo

Punto final de salida/entrada de audio o video

Dispositivo

Tarjetas de sonido, dispositivos bluetooth, cámaras, etc. Puede tener múltiples nodos.

Monitor

Búsqueda de dispositivos y manejo de conexión/desconexión en caliente

Puerto

Punto final de audio/video en un nodo

Enlace

Conexión entre puertos, que transporta audio/video entre ellos.

Cliente

Aplicación conectada a PipeWire.

Todos los objetos tienen propiedades ("props"), la mayoría de las cuales se pueden establecer en archivos de configuración o en tiempo de ejecución cuando se crea el objeto.

Algunas de las propiedades son "propiedades comunes" (por ejemplo, node.description) y se pueden establecer en todos los objetos del tipo dado. Otras propiedades controlan la configuración de un tipo específico de dispositivo o nodo (ALSA, Bluetooth, ...), y solo tienen significado para esos objetos.

Por lo general, todas las propiedades se configuran en la configuración del gestor de sesión. Para saber cómo configurarlas, consulte la documentación del gestor de sesión. En configuraciones mínimas de PipeWire sin un gestor de sesión, se pueden configurar a través de context.objects en pipewire.conf(5).

Configuración de WirePlumber

PROPIEDADES COMUNES DEL DISPOSITIVO

Estas son propiedades comunes para los dispositivos.

device.name # string

Un nombre (único) para el dispositivo. Puede ser utilizado por la línea de comandos y otras herramientas para identificar el dispositivo.

device.param.PARAM = { ... } # JSON

Establece el valor de un Param del dispositivo a un valor JSON cuando el dispositivo se carga. Esto funciona de manera similar al comando set-param de pw-cli(1). El PARAM debe ser reemplazado por el nombre del Param a establecer, es decir, por ejemplo device.Param.Props = { ... } para establecer Props.

device.plugged # integer

cuándo se creó el dispositivo.

Como un uint64 en nanosegundos.

device.nick # string

un apodo corto para el dispositivo

device.description # string

una descripción de una línea legible por humanos para el dispositivo.

Ej. "Auriculares USB Foobar"

device.serial # string

Número de serie si es aplicable.

device.vendor.id # integer

ID del fabricante si es aplicable

device.vendor.name # string

nombre del fabricante si es aplicable

device.product.id # integer

ID del producto si es aplicable

device.product.name # string

nombre del producto si es aplicable

device.class # string

clase del dispositivo

device.form-factor # string

factor de forma si es aplicable.

Uno de "internal", "speaker", "handset", "tv", "webcam", "microphone", "headset", "headphone", "hands-free", "car", "hifi", "computer", "portable"

device.icon # string

icono para el dispositivo.

Un blob base64 que contiene datos de imagen PNG

device.icon-name # string

un nombre de icono XDG para el dispositivo.

Ej. "sound-card-speakers-usb"

device.intended-roles # string

uso previsto.

Una lista de roles separados por espacios (ver media.role) para los que este dispositivo es particularmente adecuado, debido a la latencia, calidad o factor de forma.

device.disabled = false # boolean

Deshabilita la creación de este dispositivo en el gestor de sesión.

Existen otras propiedades device.* comunes para fines técnicos y que generalmente no son configurables por el usuario.

Nombres de Clave en la documentación de la API para una lista completa.

PROPIEDADES COMUNES DEL NODO

Las propiedades aquí se aplican a flujos de entrada/salida de audio o video en general, y a otros nodos como salidas (sinks) o entradas (sources) que corresponden a dispositivos reales o virtuales.

Propiedades de Identificación

Estas contienen propiedades para identificar el nodo o para mostrar el nodo en una aplicación gráfica.

node.name

Un nombre (único) para el nodo. Esto generalmente se establece en salidas y entradas para identificarlas como destinos para enlazar por el gestor de sesión.

node.description

Una descripción legible por humanos del nodo o flujo.

media.name

Un nombre de medio legible por el usuario, generalmente el artista y el título. Estos se muestran típicamente en aplicaciones orientadas al usuario para informar al usuario sobre los medios que se están reproduciendo actualmente.

media.title

Un título de flujo legible por el usuario.

media.artist

Un artista de flujo legible por el usuario

media.copyright

Información de derechos de autor del flujo legible por el usuario

media.software

Información del software generador del flujo legible por el usuario

media.language

Idioma del flujo en formato POSIX. Ej: es_ES

media.filename

Nombre del archivo para el flujo

media.icon

Icono para los medios, un blob base64 con datos de imagen PNG

media.icon-name

Un nombre de icono XDG para los medios. Ej: audio-x-mp3

media.comment

Comentario adicional del flujo

media.date

Fecha de los medios

media.format

Información del formato del flujo legible por el usuario

object.linger = false

Si el objeto debe sobrevivir a su creador.

device.id

ID del dispositivo al que pertenece el nodo.

Propiedades de Clasificación

Las propiedades de clasificación de un nodo se utilizan para enrutar la señal a su destino y para configurar los ajustes.

media.type

El tipo de medio contiene una categoría amplia de los medios que se están procesando por el nodo. Los valores posibles incluyen "Audio", "Video", "Midi"

media.category

Qué tipo de procesamiento se realiza con los medios. Los valores posibles incluyen:
  • Reproducción: reproducción de medios.
  • Captura: captura de medios.
  • Dúplex: captura y reproducción de medios o procesamiento de medios en general.
  • Monitor: una aplicación de monitorización de medios. No cambia activamente los datos de los medios, pero monitoriza la actividad.
  • Gestor: gestionará el gráfico de medios.

media.role

El caso de uso de los medios. Los valores posibles incluyen:
  • Película: reproducción de películas con audio y video.
  • Música: escucha de música.
  • Cámara: grabación de video desde una cámara.
  • Pantalla: grabación o compartición de la pantalla del escritorio.
  • Comunicación: aplicación de VOIP u otro chat de video.
  • Juego: juego.
  • Notificación: sonidos de notificación del sistema.
  • DSP: procesamiento de filtros y efectos de audio o video.
  • Producción: procesamiento y producción de audio profesional.
  • Accesibilidad: ayuda de audio y visual para accesibilidad.
  • Prueba: programa de prueba.

media.class

La clase de medios se utiliza para clasificar la función del flujo. Los valores posibles incluyen:
  • Video/Source: un productor de video, como una cámara web.
  • Video/Sink: un consumidor de video, como una ventana de visualización.
  • Audio/Source: una fuente de muestras de audio como un micrófono.

A continuación se explica las opciones que se pueden ajustar en el conversor de muestras.

resample.quality = 4

La calidad del remuestreador. de 0 a 14, el valor predeterminado es 4.

Aumentar la calidad resultará en un mejor corte y menos aliasing a expensas de un consumo de CPU (mucho) mayor. La calidad predeterminada de 4 se ha seleccionado como un buen compromiso entre calidad y rendimiento, sin artefactos que están muy por debajo del rango audible.

Ver Infinite Wave para una comparación de rendimiento.

resample.disable = false

Desactiva el remuestreador por completo. El nodo solo podrá negociar con el grafo cuando las tasas de muestreo sean compatibles.

Parámetros del mezclador de canales

Las transmisiones de origen, sumidero, captura y reproducción pueden aplicar mezcla de canales a la señal entrante.

Normalmente, el mezclador de canales no se utiliza para dispositivos; los canales del dispositivo se exponen tal como están. Esta política suele ser impuesta por el gestor de sesiones, por lo que nos remitimos a su documentación.

Las transmisiones de reproducción y captura suelen configurarse con la disposición de canales del sumidero/origen al que se conectan y, por lo tanto, realizarán la mezcla de canales.

El mezclador de canales también implementa un volumen de software. Este ajuste de volumen se realiza en la disposición de canales original. Por ejemplo: una transmisión de reproducción estéreo que se expande a 5.1 tiene 2 controles de volumen, izquierdo y derecho.

channelmix.disable = false

Desactiva el mezclador de canales por completo. La transmisión solo podrá conectarse a orígenes/sumideros compatibles con la misma disposición de canales exacta.

channelmix.min-volume = 0.0

channelmix.max-volume = 10.0

Establece los valores de volumen mínimo y máximo permitidos. Cualquier volumen que se establezca se limitará a estos valores.

channelmix.normalize = false

Asegura que durante dicha mezcla y remuestreo se preserve el nivel original de 0 dB, de modo que nada suene salvajemente más bajo/alto.

Si bien esta opción evita el recorte, en algunos casos puede producir un volumen demasiado bajo. Aumente el volumen en ese caso o desactive la normalización.

channelmix.lock-volumes = false

Desactiva completamente los cambios de volumen o silencio. El valor predeterminado es falso.

channelmix.mix-lfe = true

Mezcla el canal de efectos de baja frecuencia en el canal central frontal o el par estéreo. Esto puede mejorar el rango dinámico de la señal si no hay un subwoofer y los altavoces pueden reproducir la señal de baja frecuencia.

channelmix.upmix = true

Habilita la expansión del canal central frontal (FC) cuando el destino tiene un canal FC. Se utiliza la suma de los canales estéreo y se puede utilizar un filtro de paso bajo opcional (ver channelmix.fc-cutoff).

También habilita la expansión de LFE cuando channelmix.lfe-cutoff se establece en algo diferente de 0 y el destino tiene un canal LFE. El canal LFE se produce sumando los canales estéreo.

Si channelmix.upmix es verdadero, la expansión de los canales traseros también está habilitada y controlada por la propiedad channelmix-upmix-method.

channelmix.upmix-method = psd

Se proporcionan 3 métodos para producir los canales traseros en sonido envolvente:
1.
none. No se producen canales traseros.
2.
simple. Los canales frontales se copian a los traseros. Esto es rápido pero puede producir efectos de fase.
3.
psd. Los canales traseros se producen a partir del sonido ambiental frontal izquierdo y derecho (la diferencia entre los canales). Se añade un retardo y un filtro de fase opcional a la señal trasera para hacer que el sonido sea más amplio.

channelmix.lfe-cutoff = 150

Aplica un filtro de paso bajo a los efectos de baja frecuencia. El valor se expresa en Hz. Los subwoofers típicos tienen un corte alrededor de 150 y 200. El valor predeterminado de 0 desactiva la función.

channelmix.fc-cutoff = 12000

Aplica un filtro de paso bajo a la frecuencia central frontal. El valor se expresa en Hz.

Dado que el canal central frontal contiene los diálogos, una frecuencia de corte típica es de 12000 Hz.

Esta opción solo está activa cuando la expansión está habilitada.

channelmix.rear-delay = 12.0

Aplica un retardo en milisegundos al expandir los canales traseros. Esto mejora la especialización del sonido. Un retardo típico de 12 milisegundos es el valor predeterminado.

Esto solo está activo cuando se utiliza el método de expansión psd.

channelmix.stereo-widen = 0.0

Resta una parte de la señal central frontal de los canales estéreo. Esto mueve los diálogos más hacia el altavoz central y deja el sonido ambiental en los canales estéreo.

Esto solo está activo cuando la expansión está habilitada y se mezcla un canal central frontal.

channelmix.hilbert-taps = 0

Esta opción aplicará un desplazamiento de fase de 90 grados a los canales traseros para mejorar la especialización. Los taps deben estar entre 15 y 255, con resultados más precisos (y mayor consumo de CPU) para valores más altos.

Esto solo está activo cuando se utiliza el método de expansión psd.

dither.noise = 0

Esta opción agregará N bits de datos aleatorios a la señal. Cuando no se especifica dither.method, los datos aleatorios alternarán entre [-(1<<(N-1)), 0] cada 1024 muestras. Con un dither.method, el ruido de dithering se amplifica con 1<<(N-1) bits.

Esto se puede utilizar para mantener algunos amplificadores encendidos durante períodos de silencio. Uno o dos bits de ruido suelen ser suficientes, de lo contrario, el ruido se volverá audible. Esto se usa generalmente junto con session.suspend-timeout-seconds para deshabilitar la suspensión en el gestor de sesiones.

Tenga en cuenta que PipeWire utiliza operaciones de punto flotante con precisión de 24 bits para todo el procesamiento de audio. La conversión a formatos de muestra enteros de 24 bits no tiene pérdidas y la conversión a formatos de muestra enteros de 32 bits simplemente se rellena con 0 bits al final. Esto significa que el ruido de dithering siempre se encuentra solo en los 24 bits más significativos.

dither.method = none

Se puede realizar un dithering opcional en la señal de salida cuantificada.

Hay 6 modos disponibles:

1.
none No se realiza dithering.
2.
rectangular Dithering con una distribución de ruido rectangular. Esto agrega bits aleatorios en el rango [-0.5, 0.5] a la señal con distribución uniforme.
3.
triangular Dithering con una distribución de ruido triangular. Esto agrega bits aleatorios en el rango [-1.0, 1.0] a la señal con distribución triangular alrededor de 0.0.
4.
triangular-hf Dithering con una distribución de ruido triangular inclinada.
5.
wannamaker3 Se realiza un modelado de ruido adicional en el dithering triangular inclinado para mover el ruido a un rango más inaudible. Esto utiliza el filtro de ruido "Ponderado F" descrito por Wannamaker.
6.
shaped5 Se realiza un modelado de ruido adicional en el dithering triangular para mover el ruido a un rango más inaudible. Esto utiliza el filtro de Lipshitz.

El dithering solo es útil para la conversión a un formato con menos de 24 bits y se deshabilitará en caso contrario.

Parámetros de depuración

debug.wav-path = ""

Hace que la transmisión también escriba las muestras crudas en un archivo WAV para fines de depuración.

Otros parámetros

Estos controlan características técnicas de bajo nivel:

clock.quantum-limit

Ver pipewire.conf(5)

resample.peaks = false # booleano

En lugar de remuestrear realmente, produce valores de amplitud pico como salida. Esto se utiliza para la monitorización de volumen, donde se establece como una propiedad de la transmisión de "grabación".

resample.prefill = false # booleano

Rellena los búferes del remuestreador con silencio. Esto afecta a las muestras iniciales producidas por el remuestreador.

adapter.auto-port-config = null # JSON

Si se especifica, configura los puertos del nodo cuando se crea, en lugar de dejar que el gestor de sesiones lo haga. Esto es útil (solo) para configuraciones mínimas sin un gestor de sesiones.

El valor es SPA JSON del tipo:

{
    mode = "none",          # "none", "passthrough", "convert", "dsp"
    monitor = false,        # booleano
    control = false,        # booleano
    position = "preserve"   # "unknown", "aux", "preserve"
}


Ver spa_param_port_config para el significado.

PROPIEDADES ALSA

Propiedades del monitor

alsa.use-acp # booleano

Utiliza Perfiles de Tarjeta ALSA (ACP) para la configuración del dispositivo.

alsa.udev.expose-busy # booleano

Expone la tarjeta ALSA incluso si está ocupada/en uso. Predeterminado: falso. Esto puede ser útil cuando algunos de los PCM están en uso por otras aplicaciones, pero los PCM libres restantes aún deberían exponerse.

Propiedades del dispositivo

api.alsa.path # cadena

Ruta del dispositivo ALSA tal como se puede usar en snd_pcm_open() y snd_ctl_open().

api.alsa.use-ucm = true # booleano

Cuando ACP está habilitado y hay una configuración UCM disponible para un dispositivo, por defecto se utiliza en lugar de los perfiles ACP. Esta opción permite deshabilitar esto y usar los perfiles ACP en su lugar.

Esta opción no hace nada si api.alsa.use-acp está configurado como falso.

api.alsa.soft-mixer = false # booleano

Establecer esta opción en verdadero deshabilitará el mezclador de hardware para el control de volumen y silencio. Toda la gestión del volumen utilizará entonces volumen y silencio de software, dejando el mezclador de hardware intacto. Esto puede ser interesante para solucionar errores en la detección del mezclador o en la notificación de decibelios. El mezclador de hardware todavía se utilizará para silenciar el audio no utilizado
Aquí tienes la traducción del contenido al español, manteniendo la estructura del archivo: ```markdown paths en el dispositivo. Usa api.alsa.disable-mixer-path para deshabilitar también la selección de la ruta del mezclador.

api.alsa.disable-mixer-path = false # booleano

Establecer esta opción en true deshabilitará la selección de la ruta del mezclador de hardware. La ruta del mezclador de hardware es la configuración del mezclador dependiendo de los conectores que se insertan en la tarjeta. Si esto está deshabilitado, tendrás que habilitar y deshabilitar manualmente los controles del mezclador, pero se puede usar para solucionar errores en el mezclador. El mezclador de hardware todavía se usará para el volumen y el silencio. Usa api.alsa.soft-mixer para deshabilitar también el volumen y el silencio de hardware.

api.alsa.ignore-dB = false # booleano

api.alsa.auto-link = false # booleano

latency.internal.rate # entero

Establece estáticamente la latencia sistémica del dispositivo, en muestras a la velocidad de reproducción.

latency.internal.ns # entero

Establece estáticamente la latencia sistémica del dispositivo, en nanosegundos.

Los objetos como dispositivos y nodos también tienen parámetros que se pueden modificar después de que el objeto ha sido creado. Por ejemplo, el perfil de dispositivo activo, los volúmenes de canal, etc.

RUNTIME SETTINGS

Some settings can be applied at runtime via configuration files or environment variables.

PipeWire can be configured by placing files in the ~/.config/pipewire/ or /etc/pipewire/ directories. The configuration files are read in the following order: pipewire.conf, then any files in pipewire.conf.d/ and pipewire.conf.d/*.conf. Customizations should be placed in the user directory ~/.config/pipewire/.

Runtime settings can also be applied by exporting environment variables, for example:

export PIPEWIRE_CONFIG_DIR=~/.config/pipewire
export PIPEWIRE_RUNTIME_DIR=/run/user/1000/pipewire

This allows for applying modifications without replacing system files or putting a modified copy into the ACP directories under ~/.config or /etc.

OTHER OBJECT TYPES

Technically, PipeWire objects is what are manipulated by applications using the PipeWire API.

The list of object types that are usually "exported" (i.e. appear in pw-dump(1) output) is larger than considered above:

  • Node
  • Device
  • Port
  • Link
  • Client
  • Metadata
  • Module
  • Profiler
  • SecurityContext

Monitors do not appear in this list; they are not usually exported, and technically also Device objects. They are considered above as a separate object type because they have configurable properties.

Metadata objects are what is manipulated with pw-metadata(1)

Modules can be loaded in configuration files, or by PipeWire applications.

The Profiler and SecurityContext objects only provide corresponding PipeWire APIs.
