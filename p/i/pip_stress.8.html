NOMBRE

pip_stress - Herencia de prioridad con procesos

SINOPSIS

pip_stress [-u|--usleep TIEMPO]

DESCRIPCIÓN

Este programa demuestra la técnica de usar mutexes de herencia de prioridad (PI) con procesos en lugar de hilos. La forma de hacer esto es obtener una memoria compartida; en este caso, con mmap que respalda un pthread_mutex_t ya que este admitirá PI. Preste especial atención a cómo se inicializa para admitir procesos. La función init_shared_pthread_mutex() hace esto estableciendo el pthread_mutexattr a PTHREAD_PROCESS_SHARED y el protocolo del mutex a PTHREAD_PRIO_INHERIT. En este programa, intentamos a propósito invocar una inversión de prioridad clásica. Un proceso de baja prioridad toma el mutex y realiza algo de trabajo. Un proceso de alta prioridad aparece y se bloquea ya que el mutex está tomado. Un proceso de prioridad media que no requiere el mutex toma entonces el procesador. Debido a que los procesos están restringidos a una CPU, el proceso de baja prioridad nunca progresa porque el proceso de prioridad media se ejecuta en un bucle infinito. Esto es una inversión de prioridad porque el proceso de prioridad media se ejecuta a expensas del proceso de alta prioridad. Sin embargo, dado que hemos utilizado PRIO_INHERIT y estamos ejecutando en una máquina que admite la preempción, el proceso de alta prioridad prestará su prioridad al proceso de baja prioridad, lo que preempirá al proceso de prioridad media. El proceso de baja prioridad liberará el mutex que el proceso de alta prioridad puede obtener. Cuando el proceso de alta prioridad comience a ejecutarse, matará al proceso de prioridad media. La estructura de estado realiza un seguimiento del progreso. Aunque este programa está configurado para desencadenar una inversión, no hay garantía de que la programación lo haga posible. Después de que el programa se complete, informa si ocurrió o no una inversión de prioridad. En cualquier caso, este programa demuestra cómo usar mutexes de herencia de prioridad con procesos. De hecho, sería mejor evitar escenarios en los que ocurra una inversión de prioridad si es posible; este programa intenta desencadenarlos solo para mostrar que funciona. Si tiene dificultades para desencadenar una inversión, simplemente aumente el tiempo que el proceso de baja prioridad duerme mientras tiene el bloqueo (usleep). También tenga en cuenta que debe ejecutarse como un usuario con permiso para cambiar las prioridades de planificación.

OPCIONES

-u TIEMPO,--usleep=TIEMPO
Especifique el tiempo de espera en microsegundos del proceso de baja prioridad. El valor predeterminado es 500.
