pidfile_open(3bsd)

Paquete: libbsd

Licencias: custom

pidfile(3bsd) 3bsd pidfile(3bsd)

NOMBRE

pidfile_open, pidfile_write, pidfile_close, pidfile_remove, pidfile_fileno — biblioteca para el manejo de archivos PID

BIBLIOTECA

biblioteca “libbsd”

SINOPSIS

#include <libutil.h> (Ver libbsd(7) para el uso de la inclusión.)
struct pidfh *
pidfile_open(const char *path, mode_t mode, pid_t *pidptr);

int
pidfile_write(struct pidfh *pfh);

int
pidfile_close(struct pidfh *pfh);

int
pidfile_remove(struct pidfh *pfh);

int
pidfile_fileno(struct pidfh *pfh);

DESCRIPCIÓN

La familia de funciones pidfile permite a los daemons manejar archivos PID. Utiliza flopen(3bsd) para bloquear un archivo PID y detectar daemons que ya se están ejecutando.

La función pidfile_open() abre (o crea) un archivo especificado por el argumento path y lo bloquea. Si el argumento pidptr no es NULL y el archivo no se puede bloquear, la función lo usará para almacenar un PID de un daemon que ya se está ejecutando o -1 en caso de que el daemon aún no haya escrito su PID. La función no escribe el PID del proceso en el archivo aquí, por lo que se puede usar antes de llamar a fork() y salir con un mensaje de error apropiado cuando sea necesario. Si el argumento path es NULL, se usará el archivo /var/run/⟨nombre_prog⟩.pid. La función pidfile_open() establece la bandera close-on-exec O_CLOEXEC al abrir el archivo PID.

La función pidfile_write() escribe el PID del proceso en un archivo previamente abierto. El archivo se trunca antes de escribir, por lo que se admite llamar a la función pidfile_write() varias veces.

La función pidfile_close() cierra un archivo PID. Debe usarse después de que el daemon llame a fork() para iniciar un proceso hijo.

La función pidfile_remove() cierra y elimina un archivo PID.

La función pidfile_fileno() devuelve el descriptor de archivo del archivo PID abierto.

VALORES DE RETORNO

La función pidfile_open() devuelve un puntero válido a una estructura pidfh en caso de éxito, o NULL si ocurre un error. Si ocurre un error, se establecerá errno.


Las funciones pidfile_write(), pidfile_close() y pidfile_remove() devuelven el valor 0 si tienen éxito; de lo contrario, se devuelve el valor -1 y la variable global errno se establece para indicar el error.

La función pidfile_fileno() devuelve el descriptor de archivo de bajo nivel. Devuelve -1 y establece errno si se especifica un pidfh nulo, o si el archivo PID ya no está abierto.

EJEMPLOS

El siguiente ejemplo muestra en qué orden deben usarse estas funciones. Tenga en cuenta que es seguro pasar NULL a las funciones pidfile_write(), pidfile_remove(), pidfile_close() y pidfile_fileno().

struct pidfh *pfh;
pid_t otherpid, childpid;

pfh = pidfile_open("/var/run/daemon.pid", 0600, &otherpid);
if (pfh == NULL) {
	if (errno == EEXIST) {
		errx(EXIT_FAILURE, "El demonio ya se está ejecutando, pid: %jd.",
		    (intmax_t)otherpid);
	}
	/* Si no podemos crear el archivo PID por otras razones, solo advertir. */
	warn("No se puede abrir o crear el archivo PID");
	/*
	 * Aunque pfh es NULL, podemos continuar, ya que las otras funciones pidfile_*
	 * pueden manejar tal situación haciendo nada excepto establecer
	 * errno a EINVAL.
	 */
}

if (daemon(0, 0) == -1) {
	warn("No se puede daemonizar");
	pidfile_remove(pfh);
	exit(EXIT_FAILURE);
}

pidfile_write(pfh);

for (;;) {
	/* Hacer el trabajo. */
	childpid = fork();
	switch (childpid) {
	case -1:
		syslog(LOG_ERR, "No se puede fork(): %s.", strerror(errno));
		break;
	case 0:
		pidfile_close(pfh);
		/* Hacer el trabajo del hijo. */
		break;
	default:
		syslog(LOG_INFO, "Hijo %jd iniciado.", (intmax_t)childpid);
		break;
	}
}

pidfile_remove(pfh);
exit(EXIT_SUCCESS);

ERRORES

La función pidfile_open() fallará si:

[EEXIST]
Algún proceso ya tiene el bloqueo en el archivo PID dado, lo que significa que un daemon ya se está ejecutando. Si el argumento pidptr no es NULL, la función lo usará para almacenar un PID de un daemon que ya se está ejecutando o -1 en caso de que el daemon aún no haya escrito su PID.
[ENAMETOOLONG]
El nombre del archivo PID especificado es demasiado largo.
[EINVAL]
Algún proceso ya tiene el bloqueo en el archivo PID dado, pero el PID leído de él es inválido.

La función pidfile_open() también puede fallar y establecer errno para cualquier error especificado para las llamadas fstat(2), open(2) y read(2).

La función pidfile_write() fallará si:

[EINVAL]
Uso incorrecto de la función. Probablemente se llamó antes de pidfile_open().

La función pidfile_write() también puede fallar y establecer errno para cualquier error especificado para las llamadas fstat(2), ftruncate(2) y write(2).

La función pidfile_close() puede fallar y establecer errno para cualquier error especificado para las llamadas close(2) y fstat(2).

La función pidfile_remove() fallará si:

[EINVAL]
Uso incorrecto de la función. Probablemente se llamó desde un proceso que no hizo pidfile_write().

HISTORIA

Las funciones pidfile_open(), pidfile_write(), pidfile_close() y pidfile_remove() aparecieron por primera vez en FreeBSD 5.5.

La función pidfile_fileno() apareció por primera vez en FreeBSD 10.0.
