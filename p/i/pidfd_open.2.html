pidfd_open(2) Manual de llamadas al sistema pidfd_open(2)

NOMBRE

pidfd_open - obtener un descriptor de archivo que se refiere a una tarea

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/syscall.h>      /* Definición de las constantes SYS_* */
#include <unistd.h>
int syscall(SYS_pidfd_open, pid_t pid, unsigned int flags);

Nota: glibc no proporciona un envoltorio para pidfd_open(), lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema pidfd_open() crea un descriptor de archivo que se refiere a la tarea referenciada por pid. El descriptor de archivo se devuelve como resultado de la función; la bandera close-on-exec se establece en el descriptor de archivo.

El argumento flags tiene el valor 0 o contiene las siguientes banderas:

PIDFD_NONBLOCK (desde Linux 5.10)
Devuelve un descriptor de archivo no bloqueante. Si la tarea a la que se refiere el descriptor de archivo aún no ha terminado, un intento de esperar en el descriptor de archivo usando waitid(2) devolverá inmediatamente el error EAGAIN en lugar de bloquear.
PIDFD_THREAD (desde Linux 6.9)
Crea un descriptor de archivo que se refiere a un hilo específico, en lugar de un proceso (líder del grupo de hilos). Si esta bandera no está establecida, pid debe referirse a un proceso.

VALOR DE RETORNO

En caso de éxito, pidfd_open() devuelve un descriptor de archivo (un entero no negativo). En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EINVAL
flags no es válido.
EINVAL
pid no es válido.
EMFILE
Se ha alcanzado el límite por proceso del número de descriptores de archivo abiertos (véase la descripción de RLIMIT_NOFILE en getrlimit(2)).
ENFILE
Se ha alcanzado el límite del sistema del número total de archivos abiertos.
ENODEV
El sistema de archivos de inodos anónimos no está disponible en este kernel.
ENOMEM
No había suficiente memoria del kernel disponible.
ESRCH
El proceso especificado por pid no existe.

ESTÁNDARES

Linux.

HISTORIA

Linux 5.3.

NOTAS

La siguiente secuencia de código se puede usar para obtener un descriptor de archivo para el hijo de fork(2):


pid = fork();
if (pid > 0) {     /* Si es padre */
    pidfd = pidfd_open(pid, 0);
    ...
}

Incluso si el hijo ya ha terminado en el momento de la llamada a pidfd_open(), su PID no se habrá reciclado y el descriptor de archivo devuelto se referirá al proceso zombi resultante. Tenga en cuenta, sin embargo, que esto solo se garantiza si se cumplen las siguientes condiciones:

•
la disposición de SIGCHLD no se ha establecido explícitamente a SIG_IGN (véase sigaction(2));
•
la bandera SA_NOCLDWAIT no se especificó al establecer un manejador para SIGCHLD o al establecer la disposición de esa señal a SIG_DFL (véase sigaction(2)); y
•
el proceso zombi no fue recuperado en otra parte del programa (por ejemplo, ya sea por un manejador de señales ejecutado de forma asíncrona o por wait(2) o similar en otro hilo).

Si alguna de estas condiciones no se cumple, el proceso hijo (junto con un descriptor de archivo PID que se refiera a él) debería crearse en su lugar utilizando clone(2) con la bandera CLONE_PIDFD.

Casos de uso para descriptores de archivo PID

Un descriptor de archivo PID devuelto por pidfd_open() (o por clone(2) con la bandera CLONE_PID) se puede utilizar para los siguientes propósitos:

•
La llamada al sistema pidfd_send_signal(2) se puede usar para enviar una señal al proceso al que se refiere un descriptor de archivo PID.
•
Un descriptor de archivo PID se puede supervisar usando poll(2), select(2) y epoll(7).
Cuando la tarea a la que se refiere se termina y se convierte en un zombi, estas interfaces indican que el descriptor de archivo es legible (EPOLLIN). Cuando la tarea es reaped, estas interfaces producen un evento de desconexión (hangup) (EPOLLHUP).
Tenga en cuenta, sin embargo, que en la implementación actual, no se puede leer nada del descriptor de archivo (read(2) en el descriptor de archivo falla con el error EINVAL). El comportamiento de sondeo depende de si se utilizó la bandera PIDFD_THREAD al obtener el descriptor de archivo:
•
Con PIDFD_THREAD, el descriptor de archivo se vuelve legible cuando la tarea sale y se convierte en un zombi, incluso si el grupo de hilos no está vacío.
•
Sin PIDFD_THREAD, el descriptor de archivo solo se vuelve legible cuando el último hilo del grupo de hilos sale.
•
Si el descriptor de archivo PID se refiere a un hijo del proceso que llama, entonces se puede esperar usando waitid(2).
•
La llamada al sistema pidfd_getfd(2) se puede usar para obtener una copia duplicada de un descriptor de archivo de otro proceso al que se refiere un descriptor de archivo PID.
•
Un descriptor de archivo PID se puede usar como argumento de setns(2) para moverse a uno o más de los mismos espacios de nombres que el proceso al que se refiere el descriptor de archivo.
•
Un descriptor de archivo PID se puede usar como argumento de process_madvise(2) para proporcionar asesoramiento sobre los patrones de uso de memoria del proceso al que se refiere el descriptor de archivo.

La llamada al sistema pidfd_open() es la forma preferida de obtener un descriptor de archivo PID para un proceso ya existente. La alternativa es obtener un descriptor de archivo abriendo un directorio /proc/pid. Sin embargo, esta última técnica solo es posible si el sistema de archivos proc(5) está montado; además, el descriptor de archivo obtenido de esta manera no es consultable (pollable) y no se puede esperar con waitid(2).

EJEMPLOS

El siguiente programa abre un descriptor de archivo PID para el proceso cuyo PID se especifica como argumento de línea de comandos. Luego, utiliza poll(2) para supervisar el descriptor de archivo en busca de la salida del proceso, indicada por un evento EPOLLIN.

Fuente del programa

#define _GNU_SOURCE
#include <poll.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/syscall.h>
#include <sys/types.h>
#include <unistd.h>
static int
pidfd_open(pid_t pid, unsigned int flags)
{
    return syscall(SYS_pidfd_open, pid, flags);
}
int
main(int argc, char *argv[])
{
    int            pidfd, ready;
    struct pollfd  pollfd;
    if (argc != 2) {
        fprintf(stderr, "Uso: %s <pid>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    pidfd = pidfd_open(atoi(argv[1]), 0);
    if (pidfd == -1) {
        perror("pidfd_open");
        exit(EXIT_FAILURE);
    }
    /* Preparar la estructura pollfd para supervisar el descriptor de archivo PID */
    pollfd.fd = pidfd;
    pollfd.events = POLLIN;
    /* Esperar hasta que el proceso termine */
    printf("Esperando la terminación del proceso %s...\n", argv[1]);
    ready = poll(&pollfd, 1, -1); /* -1 significa esperar indefinidamente */
    if (ready == -1) {
        perror("poll");
        exit(EXIT_FAILURE);
    }
    if (ready == 0) {
        /* Esto no debería suceder con un timeout de -1 */
        fprintf(stderr, "poll() devolvió 0 inesperadamente\n");
        exit(EXIT_FAILURE);
    }
    /* Verificar el evento de salida */
    if (pollfd.revents & POLLIN) {
        printf("El proceso %s ha terminado.\n", argv[1]);
    }
    /* Cerrar el descriptor de archivo PID */
    close(pidfd);
    exit(EXIT_SUCCESS);
}

EJEMPLOS

El siguiente programa abre un descriptor de archivo pidfd para el proceso cuyo ID de proceso (PID) se pasa como argumento de línea de comandos, y luego usa poll(2) para esperar a que el descriptor de archivo pidfd se vuelva legible. El descriptor de archivo pidfd se vuelve legible cuando el proceso asociado termina. El código de ejemplo es el siguiente:

#include <errno.h>
#include <fcntl.h>
#include <poll.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/pidfd.h>
#include <unistd.h>

int
main(int argc, char *argv[])
{
    struct pollfd pollfd;
    int pidfd;
    int ready;

    if (argc != 2) {
        fprintf(stderr, "Usage: %s <pid>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    pidfd = pidfd_open(atoi(argv[1]), 0);
    if (pidfd == -1) {
        perror("pidfd_open");
        exit(EXIT_FAILURE);
    }

    pollfd.fd = pidfd;
    pollfd.events = POLLIN;

    /* Esperar hasta que el proceso termine. El valor de tiempo de espera
       es infinito (-1). */
    ready = poll(&pollfd, 1, -1);
    if (ready == -1) {
        perror("poll");
        exit(EXIT_FAILURE);
    }

    printf("Events (%#x): POLLIN is %sset\n", pollfd.revents,
           (pollfd.revents & POLLIN) ? "" : "not ");

    close(pidfd);
    exit(EXIT_SUCCESS);
}
