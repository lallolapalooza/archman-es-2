pipewire-jack.conf(5) Manual de formatos de archivo pipewire-jack.conf(5)

NOMBRE

pipewire-jack.conf - jack.conf

DESCRIPCIÓN

Archivo de configuración del cliente JACK de PipeWire.

SINOPSIS

$XDG_CONFIG_HOME/pipewire/jack.conf

/etc/pipewire/jack.conf

/usr/share/pipewire/jack.conf

/usr/share/pipewire/jack.conf.d/

/etc/pipewire/jack.conf.d/

$XDG_CONFIG_HOME/pipewire/jack.conf.d/

DESCRIPCIÓN

Configuración de los clientes JACK de PipeWire.

El formato del archivo de configuración y la lógica de búsqueda son los mismos que para pipewire.conf(5).

Se pueden usar archivos de configuración complementarios jack.conf.d/*.conf, y se recomiendan. Ver pipewire.conf(5).

SECCIONES DEL ARCHIVO DE CONFIGURACIÓN

jack.properties

Configuración del cliente JACK.

jack.rules

Reglas de coincidencia de clientes JACK.

Además, también se pueden especificar las secciones de configuración del contexto de PipeWire; ver pipewire.conf(5).

PROPIEDADES JACK

El archivo de configuración puede contener una sección adicional específica de JACK llamada jack.properties de la siguiente manera:

# ~/.config/pipewire/jack.conf.d/custom.conf
jack.properties = {
    #rt.prio             = 88
    #node.latency        = 1024/48000
    #node.lock-quantum   = true
    #node.force-quantum  = 0
    #jack.show-monitor   = true
    #jack.merge-monitor  = true
    #jack.show-midi      = true
    #jack.short-name     = false
    #jack.filter-name    = false
    #jack.filter-char    = " "
    #
    # allow:           No restringir las solicitudes de autoconexión
    # fail-external:   Fallar las solicitudes de autoconexión solo a puertos externos
    # ignore-external: Ignorar las solicitudes de autoconexión solo a puertos externos
    # fail-all:        Fallar todas las solicitudes de autoconexión
    # ignore-all:      Ignorar todas las solicitudes de autoconexión
    #jack.self-connect-mode  = allow
    #jack.locked-process     = true
    #jack.default-as-system  = false
    #jack.fix-midi-events    = true
    #jack.global-buffer-size = false
    #jack.passive-links      = false
    #jack.max-client-ports   = 768
    #jack.fill-aliases       = false
    #jack.writable-input     = false
    #jack.flag-midi2         = false
}

Ver stream.properties en pipewire-client.conf(5) para una explicación de las propiedades genéricas de nodos.

También es posible tener configuraciones por cliente, ver Reglas de Coincidencia más abajo.

rt.prio

Para limitar la prioridad en tiempo real que los clientes jack pueden adquirir.

node.latency

Para forzar un tamaño de búfer mínimo específico para las aplicaciones JACK, configure: 
node.latency = 1024/48000


Esto configura un tamaño de búfer de 1024 muestras a 48KHz. Si el gráfico se está ejecutando a una frecuencia de muestreo diferente, el tamaño del búfer se ajustará en consecuencia.

node.lock-quantum

Para asegurarse de que no haya cambios automáticos de cuantos mientras las aplicaciones JACK se ejecutan, configure: 
node.lock-quantum = true


El cuanto solo se puede cambiar mediante metadatos o cuando una aplicación se inicia con node.force-quantum. Las aplicaciones JACK también podrán usar jack_set_buffersize() para anular el cuanto.

node.force-quantum

Para forzar el cuanto a un valor determinado y evitar cambios en él: 
node.force-quantum = 1024


El cuanto solo se puede cambiar mediante metadatos o cuando una aplicación se inicia con node.force-quantum (o aplicaciones JACK que usan jack_set_buffersize() para anular el cuanto).

jack.show-monitor

Mostrar el cliente Monitor y sus puertos.

jack.merge-monitor

Expone los puertos de captura y los puertos de monitor en el mismo cliente de dispositivo JACK. Así es como JACK presenta los puertos de monitor a los clientes. Sin embargo, el valor predeterminado es *no* unirlos, ya que esto generalmente resulta en interfaces de usuario más fáciles de usar. Se crea un cliente adicional con un sufijo Monitor que contiene los puertos de monitor.

Por ejemplo, esta es (parte de) la salida de jack_lsp con la configuración predeterminada (jack.merge-monitor = false):

Comparar:

jack.merge-monitor = true jack.merge-monitor = false Audio Integrado Analógico Estéreo:playback_FL Audio Integrado Analógico Estéreo:playback_FL Audio Integrado Analógico Estéreo:monitor_FL Audio Integrado Analógico Estéreo Monitor:monitor_FL Audio Integrado Analógico Estéreo:playback_FR Audio Integrado Analógico Estéreo:playback_FR Audio Integrado Analógico Estéreo:monitor_FR Audio Integrado Analógico Estéreo Monitor:monitor_FR

jack.show-midi

Mostrar los clientes MIDI y sus puertos.

jack.short-name

Para usar nombres más cortos para los nombres de los clientes del dispositivo, use jack.short-name = true. Comparar:

jack.short-name = true jack.short-name = false HDA Intel PCH:playback_FL Audio Integrado Analógico Estéreo:playback_FL HDA Intel PCH Monitor:monitor_FL Audio Integrado Analógico Estéreo Monitor:monitor_FL HDA Intel PCH:playback_FR Audio Integrado Analógico Estéreo:playback_FR HDA Intel PCH Monitor:monitor_FR Audio Integrado Analógico Estéreo Monitor:monitor_FR

jack.filter-name

jack.filter-char

Reemplazará todos los caracteres especiales con jack.filter-char. Para los clientes, los caracteres especiales son ()[].:*$ y para los puertos son ()[].*$. Use esta opción cuando un cliente no puede manejar los caracteres especiales. (y una versión anterior de PortAudio se sabía que usaba los nombres de cliente y puerto como una expresión regular, y por lo tanto fallaba cuando había caracteres especiales de expresión regular en el nombre).

jack.self-connect-mode

Restringe a un cliente la realización de conexiones a y desde sí mismo. Los valores posibles y su significado se resumen como:

Valor Comportamiento allow No restringir las solicitudes de autoconexión. fail-external Fallar las solicitudes de autoconexión solo a puertos externos. ignore-external Ignorar las solicitudes de autoconexión solo a puertos externos. fail-all Fallar todas las solicitudes de autoconexión. ignore-all Ignorar todas las solicitudes de autoconexión.

jack.locked-process

Asegura que el proceso y las devoluciones de llamada no puedan ser llamados al mismo tiempo. Esta es la operación normal, pero puede ser deshabilitada en caso de que un cliente específico pueda manejarlo.

jack.default-as-system

Nombra la fuente y el sumidero predeterminados como sistema y numera los puertos para maximizar la compatibilidad con programas JACK.

jack.default-as-system = false jack.default-as-system = true HDA Intel PCH:playback_FL system:playback_1 HDA Intel PCH Monitor:monitor_FL system:monitor_1 HDA Intel PCH:playback_FR system:playback_2 HDA Intel PCH Monitor:monitor_FR system:monitor_2

jack.fix-midi-events

Corrige los eventos NoteOn con una velocidad de 0 a NoteOff. Este es el comportamiento estándar en JACK y, por lo tanto, está habilitado por defecto para maximizar la compatibilidad. Especialmente los plugins LV2 no permiten NoteOn con velocidad 0.

jack.global-buffer-size

Cuando un cliente tiene esta opción, los cambios en el tamaño del búfer se aplicarán globalmente y de forma permanente a todos los clientes de PipeWire que utilicen los metadatos.

jack.passive-links

Hace que los clientes JACK creen enlaces pasivos. Esta opción solo funciona cuando el factory de enlaces del servidor se configuró con la opción allow.link.passive.

jack.max-client-ports

Limita el número de puertos permitidos por cliente a este valor.

jack.fill-aliases

Establece automáticamente alias1 y alias2 en los puertos.

jack.writable-input

Hace que los búferes de entrada sean escribibles. Este es el valor predeterminado porque algunos clientes JACK escriben en el búfer de entrada. Sin embargo, esto puede causar corrupción en otros clientes cuando también están leyendo del búfer.

Establezca esto en true para evitar la corrupción del búfer si solo está tratando con clientes que no tienen errores.

pipewire-jack.conf(5)

NAME

pipewire-jack.conf - PipeWire JACK configuration

DESCRIPTION

The PipeWire JACK library provides a JACK client implementation for PipeWire. This man page describes the configuration options for this library.

The configuration is done through properties that can be set in pipewire.conf(5) or in files within pipewire.conf.d(5).

SYNOPSIS

pipewire.conf(5), pipewire.conf.d(5)

DESCRIPTION

The JACK client library can be configured through a jack.conf file or through environment variables.

The default configuration is usually sufficient for most users. However, for advanced users, it's possible to customize the behavior of the JACK client library.

CONFIGURATION FILE SECTIONS

The configuration is split into several sections within the configuration file.

jack

This section contains the main configuration for the JACK client library.

core
Configuration for the core JACK server.
client
Configuration for JACK clients.
midi
Configuration for MIDI ports.
rules
Rules for matching and acting upon JACK clients and nodes.

JACK PROPERTIES

The following properties can be set in the jack section of the configuration file.

jack.api.version
The JACK API version to use. Defaults to the latest supported version.
jack.client-name
The default client name to use if not specified by the application.
jack.session-manager
The session manager to use. Defaults to PipeWire's internal session manager.
jack.session-cookie
The session cookie to use. Defaults to a random value.
jack.reserve-ports
Whether to reserve ports for clients that don't specify them. Defaults to true.
jack.realtime-scheduling
Whether to use real-time scheduling for JACK clients. Defaults to true.
jack.buffer-size
The default buffer size for JACK clients. Defaults to 1024.
jack.sample-rate
The default sample rate for JACK clients. Defaults to 48000.
jack.latency
The default latency for JACK clients. Specified as samples/rate, e.g. "1024/48000".
jack.ports-by-id
Whether to use port IDs instead of names. Defaults to false.
jack.default-monitor-input
Whether to create a monitor input for each playback port. Defaults to false.
jack.default-monitor-output
jack.disable-port-reordering
Disable port reordering for clients that don't handle it. Defaults to false.
jack.enable-midi2
Enable MIDI2 ports. Defaults to false.

Set this to true for applications that know how to handle MIDI2 ports.

MATCH RULES

jack.rules provides an update-props action that takes an object with properties that are updated on the client and node object of the jack client.

Add a jack.rules section in the config file like this:

# ~/.config/pipewire/jack.conf.d/custom.conf
jack.rules = [
    {
        matches = [
            {
                # all keys must match the value. ! negates. ~ starts regex.
                application.process.binary = "jack_simple_client"
            }
        ]
        actions = {
            update-props = {
                node.latency = 512/48000
            }
        }
    }
    {
        matches = [
            {
                client.name = "catia"
            }
        ]
        actions = {
            update-props = {
                jack.merge-monitor = true
            }
        }
    }
]


Will set the latency of jack_simple_client to 512/48000 and makes Catia see the monitor client merged with the playback client.

ENVIRONMENT VARIABLES

See pipewire(1) for common environment variables. Many of these also apply to JACK client applications.

Environment variables can be used to control the behavior of the PipeWire JACK client library.

PIPEWIRE_NOJACK

PIPEWIRE_INTERNAL

When any of these variables is set, the JACK client library will refuse to open a client. The PIPEWIRE_INTERNAL variable is set by the PipeWire main daemon to avoid self connections.

PIPEWIRE_PROPS

Adds/overrides the properties specified in the jack.conf file. Check out the output of this: 
> PIPEWIRE_PROPS='{ jack.short-name=true jack.merge-monitor=true }' jack_lsp
...
HDA Intel PCH:playback_FL
HDA Intel PCH:monitor_FL
HDA Intel PCH:playback_FR
HDA Intel PCH:monitor_FR
...

PIPEWIRE_LATENCY 

PIPEWIRE_LATENCY=<samples>/<rate> <application>


A quick way to configure the maximum buffer-size for a client. It will run this client with the specified buffer-size (or smaller).

PIPEWIRE_LATENCY=256/48000 jack_lsp is equivalent to PIPEWIRE_PROPS='{ node.latency=256/48000 }' jack_lsp

A better way to start a jack session in a specific buffer-size is to force it with:

pw-metadata -n settings 0 clock.force-quantum <quantum>


This always works immediately and the buffer size will not change until the quantum is changed back to 0.

PIPEWIRE_RATE 

PIPEWIRE_RATE=1/<rate> <application>

A quick way to configure the rate of the graph. It will try to switch the samplerate of the graph. This can usually only be done with the graph is idle and the rate is part of the allowed sample rates.

PIPEWIRE_RATE=1/48000 jack_lsp is equivalent to PIPEWIRE_PROPS='{ node.rate=1/48000 }' jack_lsp

A better way to start a jack session in a specific rate is to force the rate with:

pw-metadata -n settings 0 clock.force-rate <rate>


This always works and the samplerate does not need to be in the allowed rates. The rate will also not change until it is set back to 0.

PIPEWIRE_QUANTUM 

PIPEWIRE_QUANTUM=<buffersize>/<rate> <application>

Is similar to using PIPEWIRE_LATENCY=<buffersize>/<rate> and PIPEWIRE_RATE=1/<rate> (see above), except that it is not just a suggestion but it actively forces the graph to change the rate and quantum. It can be used to set both a buffersize and samplerate at the same time.

When 2 applications force a quantum, the last one wins. When the winning app is stopped, the quantum of the previous app is restored.

PIPEWIRE_LINK_PASSIVE 

PIPEWIRE_LINK_PASSIVE=true qjackctl


Make this client create passive links only. All links created by the client will be marked passive and will not keep the sink/source busy.

You can use this to link filters to devices. When there is no client connected to the filter, only passive links remain between the filter and the device and the device will become idle and suspended.

PIPEWIRE_NODE 

PIPEWIRE_NODE=<id> <application>


Will sort the ports so that only the ports of the node with <id> are listed. You can use this to force an application to only deal with the ports of a certain node, for example when auto connecting.
