NOMBRE

pipewire.conf - pipewire.conf

DESCRIPCIÓN

El archivo de configuración del servidor PipeWire

SINOPSIS

$XDG_CONFIG_HOME/pipewire/pipewire.conf

/etc/pipewire/pipewire.conf

/usr/share/pipewire/pipewire.conf

/usr/share/pipewire/pipewire.conf.d/

/etc/pipewire/pipewire.conf.d/

$XDG_CONFIG_HOME/pipewire/pipewire.conf.d/

DESCRIPCIÓN

PipeWire es un servicio que facilita el intercambio de contenido multimedia entre dispositivos y aplicaciones.

Al iniciarse, el demonio lee un archivo de configuración principal para configurarse. Ejecuta una serie de comandos listados en el archivo de configuración.

El archivo de configuración se busca en el orden listado en la SINOPSIS. Las variables de entorno PIPEWIRE_CONFIG_DIR, PIPEWIRE_CONFIG_PREFIX y PIPEWIRE_CONFIG_NAME se pueden usar para especificar un directorio, subdirectorio y archivo de configuración alternativos respectivamente.

Otros archivos de configuración de PipeWire generalmente siguen la misma lógica de búsqueda, reemplazando pipewire.conf con el nombre del archivo de configuración particular.

ARCHIVOS DE CONFIGURACIÓN DROP-IN

Todos los archivos *.conf en los directorios pipewire.conf.d/ se cargan y se fusionan en la configuración. Las secciones de diccionario se fusionan, sobrescribiendo las propiedades si ya existían, y las secciones de arreglo se añaden. Los archivos drop-in tienen el mismo formato que el archivo de configuración principal, pero solo contienen los ajustes que se modificarán.

Dado que el archivo de configuración pipewire.conf contiene varias partes que deben estar presentes para un funcionamiento correcto, se recomienda usar archivos drop-in para la configuración.

Ejemplo

Un archivo de configuración ~/.config/pipewire/pipewire.conf.d/custom.conf para cambiar el valor de la configuración default.clock.min-quantum en pipewire.conf:

# ~/.config/pipewire/pipewire.conf.d/custom.conf
context.properties = {
    default.clock.min-quantum = 128
}

FORMATO DEL ARCHIVO DE CONFIGURACIÓN

El archivo de configuración está en formato JSON "SPA".

El archivo de configuración contiene claves de nivel superior, que son las secciones. El valor de una sección es un diccionario, { }, o un arreglo, [ ]. Las declaraciones de secciones y elementos de diccionario tienen la forma CLAVE = VALOR, y están separadas por espacios en blanco. Por ejemplo:

context.properties = {  # sección de diccionario de nivel superior
    key1 = value  # un valor simple
    key2 = { key1 = value1 key2 = value2 }  # un diccionario con dos entradas
    key3 = [ value1 value2 ]  # un arreglo con dos entradas
    key4 = [ { k = v1 } { k = v2 } ]  # un arreglo de diccionarios
}
context.modules = [  # sección de arreglo de nivel superior
    value1
    value2
]

Los archivos de configuración también se pueden escribir en sintaxis JSON estándar, pero para una edición manual más fácil, se permite la variante relajada "SPA". En JSON "SPA":

  • : para delimitar claves y valores se puede sustituir por = o un espacio.
  • " alrededor de las claves y las cadenas se pueden omitir siempre que no se utilicen caracteres especiales en las cadenas.
  • , para separar objetos se puede reemplazar con un espacio en blanco.
  • # se puede usar para iniciar un comentario hasta el final de la línea

SECCIONES DEL ARCHIVO DE CONFIGURACIÓN

context.properties

Diccionario. Estas propiedades configuran la instancia de PipeWire.

context.spa-libs

Diccionario. Mapea características de plugins con globs a una biblioteca spa.

context.modules

Arreglo de diccionarios. Cada entrada en el arreglo es un diccionario con el nombre del módulo a cargar, incluyendo args y flags opcionales. La mayoría de los módulos admiten ser cargados varias veces.

context.objects

Arreglo de diccionarios. Cada entrada en el arreglo es un diccionario que contiene el factory para crear un objeto y argumentos adicionales opcionales específicos para ese factory.

context.exec

Arreglo de diccionarios. Cada entrada en el arreglo es un diccionario que contiene la ruta de un programa a ejecutar al inicio y args opcionales.

Este arreglo solía contener una entrada para iniciar el gestor de sesiones, pero este modo de operación ha sido degradado a ayuda para el desarrollo. Evite iniciar un gestor de sesiones de esta manera en un entorno de producción.

node.rules

Arreglo de diccionarios. Reglas de coincidencia para modificar propiedades de nodos en el servidor.

device.rules

Arreglo de diccionarios. Reglas de coincidencia para modificar propiedades de dispositivos en el servidor.

PROPIEDADES DEL CONTEXTO

Propiedades de PipeWire disponibles en context.properties y posibles valores predeterminados.

clock.power-of-two-quantum = true

Las solicitudes de quantum de los clientes y el quantum del grafo final se redondean hacia abajo a una potencia de dos. Un quantum de potencia de dos puede ser más eficiente para muchas tareas de procesamiento.

context.data-loop.library.name.system

El nombre de la biblioteca compartida a usar para las funciones del sistema para el hilo de procesamiento de datos. Esto se puede cambiar típicamente si el hilo de datos se ejecuta en un kernel en tiempo real como EVL.

loop.rt-prio = -1

La prioridad de los bucles de datos. Los bucles de datos se utilizan para programar los nodos en el grafo. Un valor de -1 utiliza la prioridad en tiempo real predeterminada del módulo-rt. Un valor de 0 deshabilita la programación en tiempo real para los bucles de datos.

loop.class = [ data.rt .. ]

Un arreglo de clases de los bucles de datos. Normalmente los nodos se asignan a un bucle por nombre o por clase. Por defecto, los nodos se asignan a la clase data.rt, por lo que es bueno tener también un bucle de datos de esta clase.

context.num-data-loops = 1

El número de bucles de datos a crear. Por defecto, se crea 1 bucle de datos y todos los nodos se programan en este hilo. Un valor de 0 deshabilita los bucles de datos en tiempo real y programa todos los nodos en el hilo principal. Un valor de -1 crea tantos hilos de datos como núcleos de CPU haya.

context.data-loops = [ ... ]

Esto controla los bucles de datos que se crearán para el contexto. Es un arreglo de especificaciones de bucles de datos, una entrada por cada bucle de datos a iniciar: 
# ~/.config/pipewire/pipewire.conf.d/custom.conf
context.data-loops = [
    {
         #library.name.system = support/libspa-support
         loop.rt-prio = -1
         loop.class = [ data.rt .. ]
         thread.name = data-loop.0
         thread.affinity = [ 0 1 ]
    }
    ...
]


Se pueden dar una prioridad específica, clases y un nombre con loop.rt-prio, loop.class y thread.name respectivamente. También es posible fijar el bucle de datos a núcleos de CPU específicos con la propiedad thread.affinity.

core.daemon = false

Hace que el proceso PipeWire, iniciado con esta configuración, sea un proceso demonio. Esto significa que gestionará y programará un grafo para los clientes. También querrá configurar un core.name para darle un nombre conocido.

core.name = pipewire-0

El nombre del contexto PipeWire. Este también será el nombre del socket de PipeWire al que los clientes pueden conectarse.

cpu.zero.denormals = false

Configura la CPU para poner a cero los denormales automáticamente. Esto se habilitará solo para el hilo de procesamiento de datos, cuando esté habilitado.

cpu.vm.name = null

Esto se establecerá automáticamente cuando se cree el contexto y contendrá el nombre de la VM. Se usa típicamente para escribir reglas de coincidencia para establecer propiedades adicionales.

default.clock.rate = 48000

La tasa de reloj predeterminada determina la duración en tiempo real de los quantums min/max/default. Es posible que desee cambiar los quantums cuando cambie la tasa de reloj predeterminada para mantener la misma duración para los quantums.

PECIFICACIONES DE CONFIGURACIÓN DE ARCHIVOS Los archivos de configuración de PipeWire se encuentran en varios directorios y se procesan en un orden específico. La configuración se puede dividir en las siguientes categorías: Propiedades del contexto Bibliotecas SPA Módulos Objetos del contexto Ejecución de comandos Reglas de coincidencia PROPIEDADES DEL CONTEXTO Las propiedades del contexto son valores de configuración generales que afectan el comportamiento de PipeWire. Se pueden configurar en archivos dentro del directorio conf.d/ o directamente en el archivo de configuración principal (pipewire.conf). default.clock.rate = 48000 La frecuencia de muestreo predeterminada utilizada por los nodos del mezclador y la entrada de audio. default.clock.allowed-rates = [ 44100 48000 88200 96000 176400 192000 ] Hasta 32 tasas de muestra alternativas. La tasa de muestra del gráfico se cambiará cuando los dispositivos estén inactivos. Tenga en cuenta que esto no está habilitado de forma predeterminada por ahora debido a varios problemas del kernel y Bluetooth. Tenga en cuenta que los valores cuánticos min/max/predeterminados se escalan cuando cambia la frecuencia de muestreo. default.clock.min-quantum = 32 Quantum mínimo predeterminado. default.clock.max-quantum = 8192 Quantum máximo predeterminado. default.clock.quantum = 1024 Quantum predeterminado utilizado cuando ningún cliente especifica uno. default.clock.quantum-limit = 8192 Quantum máximo para reservar espacio. Este es el tamaño máximo del búfer utilizado en el gráfico, independientemente de la frecuencia de muestreo. default.clock.quantum-floor = 4 Quantum mínimo para reservar espacio. Este es el tamaño mínimo del búfer utilizado en el gráfico, independientemente de la frecuencia de muestreo. default.video.width Ancho de video predeterminado default.video.height Alto de video predeterminado default.video.rate.num Numerador de tasa de video predeterminado default.video.rate.denom Denominador de tasa de video predeterminado library.name.system = support/libspa-support El nombre de la biblioteca compartida a utilizar para las funciones del sistema para el hilo principal. link.max-buffers = 64 El número máximo de búferes a negociar entre nodos. Tenga en cuenta que los clientes de versiones anteriores a la 3 solo pueden admitir 16 búferes. Más búferes es casi siempre peor que menos, en términos de latencia y memoria. log.level = 2 El nivel de registro predeterminado utilizado por el proceso. mem.allow-mlock = true Intenta bloquear la memoria para los procesos de tiempo real. La memoria bloqueada no será intercambiada por el kernel y evitará problemas en los hilos de procesamiento. mem.warn-mlock = false Advertir sobre fallos al bloquear la memoria. mem.mlock-all = false Intenta bloquear toda la memoria actual y futura del proceso. settings.check-quantum = false Verifica si el quantum en la actualización de metadatos de configuración es compatible con los límites configurados. settings.check-rate = false Verifica si la tasa en la actualización de metadatos de configuración es compatible con los límites configurados. support.dbus = true Habilita el soporte de DBus. Esto habilitará el soporte de DBus en los diversos módulos que lo requieran. Deshabilite esto si desea deshabilitar globalmente el soporte de DBus en el proceso. vm.overrides = { default.clock.min-quantum = 1024 } Cualquier propiedad en el objeto de propiedad vm.overrides anulará la propiedad en las propiedades del contexto cuando PipeWire detecte que se está ejecutando en una VM. Esto está obsoleto, use las reglas de propiedades del contexto en su lugar. context.modules.allow-empty = false Por defecto, se registra una advertencia cuando no se cargan módulos de contexto porque es probable que esto indique un problema. Algunas aplicaciones pueden cargar los módulos por sí mismas y, cuando establecen esta propiedad en true, no se registrará ninguna advertencia. Las propiedades del contexto también pueden contener valores personalizados. Por ejemplo, las secciones context.modules y context.objects pueden declarar condiciones adicionales que controlan si un módulo u objeto se carga dependiendo de las propiedades presentes. SPA LIBRARIES Los complementos SPA se cargan según su nombre de fábrica. Este es un nombre bien conocido que describe de forma única las características que debe tener el complemento. La sección context.spa-libs proporciona un mapeo entre el nombre de fábrica y el complemento donde se puede encontrar la fábrica. Los nombres de fábrica pueden contener un comodín para agrupar varias fábricas relacionadas en un solo complemento. El complemento se carga desde el primer nombre de fábrica coincidente. Ejemplo 2 # ~/.config/pipewire/pipewire.conf.d/custom.conf context.spa-libs = { audio.convert.* = audioconvert/libspa-audioconvert avb.* = avb/libspa-avb api.alsa.* = alsa/libspa-alsa api.v4l2.* = v4l2/libspa-v4l2 api.libcamera.* = libcamera/libspa-libcamera api.bluez5.* = bluez5/libspa-bluez5 api.vulkan.* = vulkan/libspa-vulkan api.jack.* = jack/libspa-jack support.* = support/libspa-support video.convert.* = videoconvert/libspa-videoconvert } MÓDULOS Módulos de PipeWire a cargar. Ver libpipewire-modules(7). # ~/.config/pipewire/pipewire.conf.d/custom.conf context.modules = [ #{ name = MODULENAME # ( args = { KEY = VALUE ... } ) # ( flags = [ ( ifexists ) ( nofail ) ] ) # ( condition = [ { KEY = VALUE ... } ... ] ) #} # ] nombre Nombre del módulo a cargar args = { } Argumentos pasados al módulo flags = [ ] Marcas de carga. ifexists para cargar el módulo solo si existe, y nofail para no fallar el inicio de PipeWire si el módulo no se puede cargar. condition = [ ] Una regla de coincidencia coincide con la condición. El módulo se carga solo si una de las expresiones en la matriz coincide con una propiedad del contexto. CONTEXT OBJECTS La sección context.objects le permite crear algunos objetos a partir de fábricas (generalmente creados cargando módulos en context.modules). # ~/.config/pipewire/pipewire.conf.d/custom.conf context.objects = [ #{ factory = # ( args = { = ... } ) # ( flags = [ ( nofail ) ] ) # ( condition = [ { = ... } ... ] ) #} ] Esta sección se puede utilizar para crear nodos o enlaces entre nodos. factory Nombre de la fábrica para crear el objeto. args = { } Argumentos pasados a la fábrica. flags = [ ] Marca nofail para no fallar el inicio de PipeWire si el objeto no se puede cargar. condition = [ ] Una regla de coincidencia coincide con la condición. El objeto se crea solo si una de las expresiones en la matriz coincide con una propiedad del contexto. Ejemplo 3 Este fragmento crea un nuevo nodo de controlador ficticio, pero solo si la propiedad core.daemon es verdadera: # ~/.config/pipewire/pipewire.conf.d/custom.conf context.objects = [ { factory = spa-node-factory args = { factory.name = support.node.driver node.name = Dummy-Driver node.group = pipewire.dummy priority.driver = 20000 }, condition = [ { core.daemon = true } ] } ] EJECUCIÓN DE COMANDOS La sección context.exec se puede utilizar para iniciar comandos arbitrarios como parte de la inicialización del programa PipeWire. # ~/.config/pipewire/pipewire.conf.d/custom.conf context.exec = [ #{ path = # ( args = "" | [ ... ] ) # ( condition = [ { = ... } ... ] ) #} ] path Programa a ejecutar. args Argumentos para el programa. condition Una regla de coincidencia coincide con la condición. El objeto se crea solo si una de las expresiones en la matriz coincide con una propiedad del contexto. Ejemplo 4 El siguiente fragmento ejecuta un comando pactl con los argumentos dados: # ~/.config/pipewire/pipewire.conf.d/custom.conf context.exec = [ { path = "pactl" args = "load-module module-always-sink" } ] REGLAS DE COINCIDENCIA Algunas secciones de archivos de configuración contienen reglas de coincidencia. Esto hace posible realizar alguna acción cuando se crea/actualiza un objeto (generalmente un nodo o un flujo) que coincide con ciertas propiedades. Las reglas generales del objeto siguen el siguiente patrón: = [ { matches = [ # cualquiera de los siguientes conjuntos de propiedades se compara, si # alguno coincide, se ejecutan las acciones { # = # todas las claves deben coincidir con el valor. ! niega. ~ comienza regex. #application.process.binary = "teams" #application.name = "~speech-dispatcher.*" # La ausencia de una propiedad se puede probar comparando con null #pipewire.sec.flatpak = null } { # más coincidencias aquí... } ... ] actions = { = ... } } ] Las reglas de coincidencia son una matriz de reglas. Una regla es siempre un objeto JSON con dos claves: matches y actions. La clave matches se utiliza para definir las condiciones que deben cumplirse para que la regla se evalúe como verdadera, y la clave actions se utiliza para definir las acciones que se realizan cuando la regla se evalúa como verdadera. La clave matches es siempre una matriz JSON de objetos, donde cada objeto define una condición que debe cumplirse. Cada condición es una lista de pares clave-valor, donde la clave es el nombre de la propiedad que se está comparando y el valor es el valor que debe tener la propiedad. Dentro de una condición, todos los pares clave-valor se combinan con un Y lógico, y todas las condiciones en la matriz matches se combinan con un O lógico. La clave actions es siempre un objeto JSON, donde cada par clave-valor define una acción que se realiza cuando la regla se evalúa como verdadera. El nombre de la acción es específico de la regla y está definido por la documentación de la regla, pero lo más frecuente es que vea la acción update-props, que se utiliza para actualizar las propiedades del objeto coincidente. En la matriz matches, también es posible utilizar expresiones regulares para hacer coincidir

MATCH RULES

Las reglas de coincidencia se utilizan para evaluar propiedades arbitrarias en un objeto y determinar si se deben aplicar acciones. Esto se usa principalmente para las reglas de contexto, nodo y dispositivo.

Una regla de coincidencia es una lista de condiciones. Todas las condiciones de la lista deben coincidir para que la regla de coincidencia tenga éxito. Las condiciones se especifican como pares clave-valor, donde la clave es el nombre de la propiedad y el valor es el valor que se debe coincidir.

Por ejemplo, para que coincidan todos los nodos con un nombre que comience con my_, puede usar la siguiente condición:

matches = [
  {
    node.name = "~my_.*"
  }
]

El carácter ~ significa que el valor es una expresión regular. La sintaxis exacta de las expresiones regulares es la sintaxis de expresiones regulares extendidas POSIX, como se describe en la página del manual regex(7).

Además de las expresiones regulares, también puede usar el carácter ! para negar una condición. Por ejemplo, para que coincidan todos los nodos con un nombre que no comience con my_, puede usar la siguiente condición:

matches = [
  {
    node.name = "!~my_.*"
  }
]

El carácter ! se puede usar con o sin una expresión regular. Por ejemplo, para que coincidan todos los nodos con un nombre que no sea igual a my_node, puede usar la siguiente condición:

matches = [
  {
    node.name = "!my_node"
  }
]

El valor null tiene un significado especial; comprueba si la propiedad no está disponible (o no está establecida). Para comprobar si una propiedad no está establecida:

matches = [
  {
    node.name = null
  }
]

Para comprobar la existencia de una propiedad, se puede usar la condición !null, por ejemplo:

matches = [
  {
    node.name = "!null"
  }
  {
    node.name = !null            # sintaxis simplificada
  }
]


Para manejar la cadena "null", es necesario escapar la cadena. Por ejemplo, para comprobar si una propiedad tiene el valor de cadena "null", use:

matches = [
  {
    node.name = "null"
  }
]


Para manejar cualquier cosa que no sea la cadena "null", use:

matches = [
  {
    node.name = "!\"null\""
  }
  {
    node.name = !"null"      # sintaxis simplificada
  }
]

CONTEXT PROPERTIES RULES

context.properties.rules se puede utilizar para actualizar dinámicamente las propiedades basándose en otras propiedades.

Un caso típico es actualizar configuraciones personalizadas cuando se ejecuta dentro de una VM. cpu.vm.name se establece automáticamente cuando se ejecuta en una VM con el nombre de la VM. Se puede escribir una regla de coincidencia para establecer propiedades personalizadas de esta manera:

# ~/.config/pipewire/pipewire.conf.d/custom.conf
context.properties.rules = [
    {   matches = [ { cpu.vm.name = !null } ]
        actions = {
            update-props = {
                # Estas anulaciones solo se aplican cuando se ejecutan en una vm.
                default.clock.min-quantum = 1024
            }
        }
    }
]

NODE RULES

Las node.rules se evalúan cada vez que se establecen o actualizan las propiedades de un nodo. Esto se puede usar en el lado del servidor para anular las propiedades establecidas por el cliente en nodos arbitrarios.

node.rules proporciona una acción update-props que toma un objeto con propiedades que se actualizan en el objeto nodo.

Agregue una sección node.rules en el archivo de configuración de esta manera:

# ~/.config/pipewire/pipewire.conf.d/custom.conf
node.rules = [
    {
        matches = [
            {
                # todas las claves deben coincidir con el valor. ! niega. ~ comienza regex.
                client.name = "jack_simple_client"
            }
        ]
        actions = {
            update-props = {
                node.force-quantum = 512
            }
        }
    }
]

Establecerá la propiedad node.force-quantum de jack_simple_client a 512.

DEVICE RULES

Las device.rules se evalúan cada vez que se establecen o actualizan las propiedades de un dispositivo. Esto se puede usar en el lado del servidor para anular las propiedades establecidas por el cliente en dispositivos arbitrarios.

device.rules proporciona una acción update-props que toma un objeto con propiedades que se actualizan en el objeto dispositivo.

Agregue una sección device.rules en el archivo de configuración de esta manera:

# ~/.config/pipewire/pipewire.conf.d/custom.conf
device.rules = [
    {
        matches = [
            {
                # todas las claves deben coincidir con el valor. ! niega. ~ comienza regex.
                device.name = ""v4l2_device.pci-0000_00_14.0-usb-0_1.2_1.0
            }
        ]
        actions = {
            update-props = {
                device.description = "My Webcam"
            }
        }
    }
]

Establecerá la propiedad device.description del dispositivo con el device.name dado a "My Webcam".
