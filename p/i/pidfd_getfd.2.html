pidfd_getfd(2) Manual de Llamadas al Sistema pidfd_getfd(2)

NOMBRE

pidfd_getfd - obtener un duplicado del descriptor de archivo de otro proceso

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/syscall.h>      /* Definición de las constantes SYS_* */
#include <unistd.h>
int syscall(SYS_pidfd_getfd, int pidfd, int targetfd,
            unsigned int flags);

Nota: glibc no proporciona un envoltorio para pidfd_getfd(), lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema pidfd_getfd() asigna un nuevo descriptor de archivo en el proceso que llama. Este nuevo descriptor de archivo es un duplicado de un descriptor de archivo existente, targetfd, en el proceso al que se refiere el descriptor de archivo PID pidfd.

El descriptor de archivo duplicado se refiere a la misma descripción de archivo abierto (ver open(2)) que el descriptor de archivo original en el proceso al que se refiere pidfd. Por lo tanto, los dos descriptores de archivo comparten el estado del archivo y el desplazamiento del archivo. Además, las operaciones sobre el objeto de archivo subyacente (por ejemplo, la asignación de una dirección a un objeto de socket usando bind(2)) se pueden realizar de manera similar a través del descriptor de archivo duplicado.

La bandera de cierre al ejecutar (FD_CLOEXEC; ver fcntl(2)) se establece en el descriptor de archivo devuelto por pidfd_getfd().

El argumento flags está reservado para uso futuro. Actualmente, debe especificarse como 0.

El permiso para duplicar el descriptor de archivo de otro proceso se rige por una comprobación de modo de acceso de ptrace PTRACE_MODE_ATTACH_REALCREDS (ver ptrace(2)).

VALOR DE RETORNO

En caso de éxito, pidfd_getfd() devuelve un descriptor de archivo (un entero no negativo). En caso de error, devuelve -1 y se establece errno para indicar el error.

ERRORES

EBADF
pidfd no es un descriptor de archivo PID válido.
EBADF
targetfd no es un descriptor de archivo abierto en el proceso al que se refiere pidfd.
EINVAL
flags no es 0.
EMFILE
Se ha alcanzado el límite por proceso en el número de descriptores de archivo abiertos (ver la descripción de RLIMIT_NOFILE en getrlimit(2)).
ENFILE
Se ha alcanzado el límite a nivel de sistema en el número total de archivos abiertos.
EPERM
El proceso que llama no tenía permisos PTRACE_MODE_ATTACH_REALCREDS (ver ptrace(2)) sobre el proceso al que se refiere pidfd.
ESRCH
El proceso al que se refiere pidfd no existe (es decir, ha terminado y se ha esperado por él).

NORMAS

Linux.

HISTORIA

Linux 5.6.

NOTAS

Para una descripción de los descriptores de archivo PID, ver pidfd_open(2).

El efecto de pidfd_getfd() es similar al uso de mensajes SCM_RIGHTS descritos en unix(7), pero difiere en los siguientes aspectos:

•
Para pasar un descriptor de archivo usando un mensaje SCM_RIGHTS, los dos procesos deben primero establecer una conexión de socket de dominio UNIX.
•
El uso de SCM_RIGHTS requiere la cooperación del proceso cuyo descriptor de archivo se está copiando. Por el contrario, no se necesita tal cooperación al usar pidfd_getfd().
•
La capacidad de usar pidfd_getfd() está restringida por una comprobación de modo de acceso de ptrace PTRACE_MODE_ATTACH_REALCREDS.

VER TAMBIÉN

clone3(2), dup(2), kcmp(2), pidfd_open(2)
