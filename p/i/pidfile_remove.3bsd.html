NOMBRE

pidfile_open, pidfile_write, pidfile_close, pidfile_remove, pidfile_fileno — biblioteca para manejo de archivos PID

BIBLIOTECA

biblioteca “libbsd”

SINOPSIS

#include <libutil.h> (Ver libbsd(7) para uso de la inclusión.)
struct pidfh *
pidfile_open(const char *path, mode_t mode, pid_t *pidptr);

int
pidfile_write(struct pidfh *pfh);

int
pidfile_close(struct pidfh *pfh);

int
pidfile_remove(struct pidfh *pfh);

int
pidfile_fileno(struct pidfh *pfh);

DESCRIPCIÓN

La familia de funciones pidfile permite a los demoniossal manejar archivos PID. Utiliza flopen(3bsd) para bloquear un archivo PID y detectar demonios ya en ejecución.

La función pidfile_open() abre (o crea) un archivo especificado por el argumento path y lo bloquea. Si el argumento pidptr no es NULL y el archivo no puede ser bloqueado, la función lo usará para almacenar un PID de un demonio ya en ejecución o -1 en caso de que el demonio aún no haya escrito su PID. La función no escribe el PID del proceso en el archivo aquí, por lo que puede ser utilizada antes de fork() y salir con un mensaje de error adecuado cuando sea necesario. Si el argumento path es NULL, se usará el archivo /var/run/⟨nombre_prog⟩.pid. La función pidfile_open() establece el flag de cierre al ejecutar (close-on-exec) O_CLOEXEC al abrir el archivo PID.

La función pidfile_write() escribe el PID del proceso en un archivo previamente abierto. El archivo se trunca antes de escribir, por lo que se admite llamar a la función pidfile_write() varias veces.

La función pidfile_close() cierra un archivo PID. Debe usarse después de que el demonio fork() para iniciar un proceso hijo.

La función pidfile_remove() cierra y elimina un archivo PID.

La función pidfile_fileno() devuelve el descriptor de archivo para el archivo PID abierto.

VALORES DE RETORNO

La función pidfile_open() devuelve un puntero válido a una estructura pidfh en caso de éxito, o NULL si ocurre un error. Si ocurre un error, errno se establecerá.


Las funciones pidfile_write(), pidfile_close() y pidfile_remove() devuelven el valor 0 si tienen éxito; de lo contrario, se devuelve el valor -1 y la variable global errno se establece para indicar el error.

La función pidfile_fileno() devuelve el descriptor de archivo de bajo nivel. Devuelve -1 y establece errno si se especifica un pidfh nulo, o si el archivo PID ya no está abierto.

EJEMPLOS

El siguiente ejemplo muestra en qué orden deben usarse estas funciones. Tenga en cuenta que es seguro pasar NULL a las funciones pidfile_write(), pidfile_remove(), pidfile_close() y pidfile_fileno().

struct pidfh *pfh;
pid_t otherpid, childpid;

pfh = pidfile_open("/var/run/daemon.pid", 0600, &otherpid);
if (pfh == NULL) {
	if (errno == EEXIST) {
		errx(EXIT_FAILURE, "Daemon ya en ejecución, pid: %jd.",
		    (intmax_t)otherpid);
	}
	/* Si no podemos crear el archivo PID por otras razones, solo advertimos. */
	warn("No se puede abrir o crear el archivo PID");
	/*
	 * Aunque pfh es NULL, podemos continuar, ya que las otras funciones
	 * pidfile_* pueden manejar tal situación haciéndolo nada excepto
	 * estableciendo errno a EINVAL.
	 */
}

if (daemon(0, 0) == -1) {
	warn("No se puede demonizar");
	pidfile_remove(pfh);
	exit(EXIT_FAILURE);
}

pidfile_write(pfh);

for (;;) {
	/* Hacer trabajo. */
	childpid = fork();
	switch (childpid) {
	case -1:
		syslog(LOG_ERR, "No se puede fork(): %s.", strerror(errno));
		break;
	case 0:
		pidfile_close(pfh);
		/* Hacer trabajo del hijo. */
		break;
	default:
		syslog(LOG_INFO, "Hijo %jd iniciado.", (intmax_t)childpid);
		break;
	}
}

pidfile_remove(pfh);
exit(EXIT_SUCCESS);

ERRORES

La función pidfile_open() fallará si:

[EEXIST]
Algún proceso ya tiene el bloqueo sobre el archivo PID dado, lo que significa que un demonio ya está en ejecución. Si el argumento pidptr no es NULL, la función lo usará para almacenar un PID de un demonio ya en ejecución o -1 en caso de que el demonio aún no haya escrito su PID.
[ENAMETOOLONG]
El nombre del archivo PID especificado es demasiado largo.
[EINVAL]
Algún proceso ya tiene el bloqueo sobre el archivo PID dado, pero el PID leído de allí no es válido.

La función pidfile_open() también puede fallar y establecer errno por cualquier error especificado para las llamadas a fstat(2), open(2), y read(2).

La función pidfile_write() fallará si:

[EINVAL]
Uso incorrecto de la función. Probablemente llamada antes de pidfile_open().

La función pidfile_write() también puede fallar y establecer errno por cualquier error especificado para las llamadas a fstat(2), ftruncate(2), y write(2).

La función pidfile_close() puede fallar y establecer errno por cualquier error especificado para las llamadas a close(2) y fstat(2).

La función pidfile_remove() fallará si:

[EINVAL]
Uso incorrecto de la función. Probablemente llamada no desde el proceso que hizo pidfile_write().

La función pidfile_remove() también puede fallar y establecer errno por cualquier error especificado para las llamadas a close(2), fstat(2), write(2), y unlink(2).

pidfile_remove(3bsd) - Arch Linux man pages

NAME

pidfile_fileno, pidfile_open, pidfile_close, pidfile_remove, pidfile_write - manipulate pidfiles

LIBRARY

libbsd (-lbsd)

SYNOPSIS

#include <bsd/stdio.h>

int pidfile_open(const char *path, mode_t mode, pid_t *pid);
int pidfile_write(const char *path, pid_t pid);
int pidfile_close(const char *path);
int pidfile_remove(const char *path);
int pidfile_fileno(const char *path);

DESCRIPTION

A pidfile is a file containing the process ID (PID) of a running daemon. It is used to prevent multiple instances of the same daemon from running simultaneously.

The pidfile_open() function creates and locks a pidfile. If the file specified by path exists, it reads the PID from the file and checks if the process with that PID is still running. If it is, the function returns an error. Otherwise, it overwrites the file with the current process's PID. The function then locks the file to prevent other processes from opening it. The mode parameter specifies the permissions for the created file. The PID is written to the file in ASCII format, followed by a newline character. If pid is not NULL, the PID read from the file (if any) is stored in the location pointed to by pid.

The pidfile_write() function writes the specified pid to the file specified by path. This function should be used after a successful call to pidfile_open() if the PID needs to be updated (e.g., after a fork).

The pidfile_close() function unlocks and removes the pidfile specified by path. This function should be called when the daemon is exiting normally.

The pidfile_remove() function unlocks and removes the pidfile specified by path. This function is similar to pidfile_close() but does not require the file to be locked.

The pidfile_fileno() function returns the file descriptor associated with the pidfile specified by path. This can be useful for redirecting standard input, output, and error streams to the pidfile.

RETURN VALUES

The pidfile_open(), pidfile_write(), pidfile_close(), pidfile_remove() and pidfile_fileno() functions return 0 on success, or -1 on error.

EXAMPLES

Creating a pidfile:

pid_t pid;
if (pidfile_open("/var/run/mydaemon.pid", 0644, &pid) < 0) {
    if (errno == EEXIST) {
        fprintf(stderr, "mydaemon is already running (PID %d).\\n", pid);
        exit(EXIT_FAILURE);
    }
    perror("pidfile_open");
    exit(EXIT_FAILURE);
}
/* Daemonize here */
/* ... */
/* Write the new PID to the pidfile */
if (pidfile_write("/var/run/mydaemon.pid", getpid()) < 0) {
    perror("pidfile_write");
    pidfile_remove("/var/run/mydaemon.pid");
    exit(EXIT_FAILURE);
}
/* ... daemon logic ... */
pidfile_close("/var/run/mydaemon.pid");

ERRORS

[EACCES]
The pidfile could not be created or opened due to lack of permissions.
[EEXIST]
The pidfile already exists and the process specified in it is running.
[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().
[ENOENT]
The pidfile does not exist.

The pidfile_fileno() function will fail if:

[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().

SEE ALSO

open(2), daemon(3), flopen(3bsd)

HISTORY

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() first appeared in FreeBSD 5.5.

The function pidfile_fileno() first appeared in FreeBSD 10.0.
