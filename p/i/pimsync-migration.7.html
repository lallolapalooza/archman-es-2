NOMBRE

pimsync-migration — guía de migración de vdirsyncer a pimsync

DESCRIPCIÓN

Esta guía de migración cubre los cambios a tener en cuenta al migrar de vdirsyncer a pimsync. Está dirigida a usuarios con una configuración funcional de la implementación anterior.

CARACTERÍSTICAS AUSENTES

Las siguientes características están implementadas por vdirsyncer 0.19.3, pero actualmente no están disponibles en pimsync:

  • auth digest Esto necesita ser implementado como un middleware de ‘tower-service’. No debería ser demasiado complicado.
  • partial_sync Este parámetro de configuración probablemente no volverá de la misma manera. Un "espejo" es el sucesor más probable. Con esta directiva establecida, pimsync(1) haría de B un espejo de A. En este modo, solo un almacenamiento DEBE ser definido como read_only.
  • post_hook parámetro de configuración. Las versiones futuras podrían transmitir eventos, permitiendo que manejadores externos reaccionen a ellos en su lugar.
  • start_date, end_date y parámetros de configuración de item_types para almacenamientos CalDav. Estos están planeados, pero sin un marco de tiempo específico.
  • El almacenamiento singlefile, que guarda todos los eventos de un calendario en un solo archivo.

Las siguientes características no están presentes y es poco probable que se implementen sin un caso de uso convincente. Por favor, contacte si necesita alguna de estas:

  • Codificaciones distintas de UTF-8
  • Se sincronizan todos los metadatos. Actualmente no es posible seleccionar campos individuales.
  • El parámetro de configuración fileignoreext.

FORMATO DEL ARCHIVO DE CONFIGURACIÓN

El formato de configuración ha cambiado. El enfoque general es el mismo, pero la sintaxis se ha simplificado enormemente para que los humanos la escriban. Técnicamente, el formato es el formato *scfg*. Está documentado en detalle en pimsync.conf(5).

Lo siguiente:

[pair.contacts]
a = "contacts_local"
b = "contacts_fastmail"
collections = "all"
conflict_resolution = ["nvim", "-d"]

Se convierte en:

pair contacts {
	storage_a contacts_local
	storage_b contacts_fastmail
	collections all
	conflict_resolution nvim -d
}

Y lo siguiente:

[storage.contacts_local]
type = "filesystem"
path = "~/.local/share/contacts/"
fileext = "vcf"

Se convierte en esto:

storage contacts_local {
	type vdir/vcard
	path ~/.local/share/contacts/
	fileext vcf
}

MECANISMOS DE OBTENCIÓN

Se ha eliminado el mecanismo prompt para obtener contraseñas.

Una definición de fetch con un command se vería anteriormente así:

password.fetch = ["command", "hiq", "-dFpassword", "proto=carddavs", "username=…"]

Ahora se proporciona un bloque a password con una única directiva cmd que especifica el comando y sus argumentos.

password {
	cmd hiq -dFpassword proto=carddavs username=…
}

Una definición de fetch con un shell ahora usa una sintaxis similar:

password {
	shell pass show communication/migadu.com | head -1
}

MIGRACIÓN DE OBTENCIÓN / SOLICITUD

Utilice un solicitante externo en su lugar. Para un solicitante con interfaz gráfica, considere usar:

password {
	cmd zenity --password
}

pimsync(1) solicitará las contraseñas en secuencia, por lo que no se requieren consideraciones especiales para evitar solicitudes concurrentes.

EL DESCUBRIMIENTO MANUAL YA NO ES NECESARIO

Ya no es necesario descubrir las colecciones con antelación. Las colecciones se descubren automáticamente si es necesario. El comando discover simplemente imprime las colecciones descubiertas como una conveniencia para configurar colecciones manualmente. No afecta el estado interno de pimsync. Consulte pimsync(1) para más detalles.

CREACIÓN AUTOMÁTICA DE COLECCIONES

Si un par está configurado para sincronizar todas las colecciones desde a y se encuentra una nueva colección en el almacenamiento A, entonces la colección se creará automáticamente en el almacenamiento B. Para escenarios donde la creación automática de colecciones no es deseable, se deben especificar colecciones individuales explícitamente en su lugar.

LAS EJECUCIONES EN SECO AHORA SON POSIBLES

Ahora es posible ejecutar una ejecución en seco, que solo imprime el plan tentativo sin ejecutarlo. La salida es algo escueta en esta etapa y no está en su forma final. Esto se puede usar para auditar nuevas configuraciones y asegurar que las acciones planificadas tengan sentido.

LOS ALMACENAMIENTOS DE SISTEMA DE ARCHIVOS HAN SIDO RENOMBRADOS A VDIR

Las colecciones del sistema de archivos han sido renombradas a vdir. Ahora deben especificar qué tipo de elementos contienen.

Un directorio con archivos icalendar debe especificar:

type = "vdir/icalendar"

Un directorio con archivos vcard debe especificar:

type vdir/vcard

CODIFICACIONES PERSONALIZADAS PARA ALMACENAMIENTO VDIR

El almacenamiento vdir guarda archivos como UTF-8. Si se requiere otra codificación para algún escenario, por favor abra un issue en: https://todo.sr.ht/~whynothugo/pimsync

CAMPO FILESYSTEM FILEEXT

El campo fileext para los almacenamientos del sistema de archivos requería un punto inicial. Este ya no es el caso; el punto no se considera parte de las extensiones y debe omitirse. Omita el punto inicial al migrar configuraciones.

LAS COLECCIONES SE DECLARAN EN UN FORMATO DIFERENTE

Para sincronizar todas las colecciones de ambos lados, use:

collections all

Para sincronizar todas las colecciones presentes en un almacenamiento específico, use:

collections from b

ESPECIFICACIÓN DE COLECCIONES INDIVIDUALES

Las colecciones individuales se pueden especificar por id o por href: archivo ... El id es el nombre del proceso de descubrimiento. archivo ... El href es la ruta completa dentro del almacenamiento.

LAS_COLECCIONES_SE_DECLARAN_EN_UN_FORMATO_DIFERENTE

Generalmente, se recomienda usar un id. Usar href está pensado para situaciones en las que el descubrimiento no es posible o donde varias colecciones tienen el mismo id. Para especificar una sola colección por id, usa:

collection c037725e-e4fd-4b3e-b73d-d5e27d5a90a9

Lo anterior encontrará y sincronizará colecciones con el id dado entre ambos almacenamientos.

Se pueden mapear dos colecciones diferentes en cada lado:

pair my_pair {
	# otros campos aquí

	# primera colección
	collection {
			alias personal
			href_a /calendars/hugo/c037725e-e4fd-4b3e-b73d-d5e27d5a90a9/
			href_b /personal/
	}

	# otra colección
	collection {
			alias work
			id_a work
			href_b /calendars/work/
	}
}

Especificar la colección null ya no está permitido; la configuración debe apuntar a una colección explícita en su lugar.

EL_ALMACENAMIENTO_HTTP_AHORA_SE_LLAMA_WEBCAL

El tipo del almacenamiento http ahora es webcal, para reflejar mejor su naturaleza; otros almacenamientos también usan HTTP internamente.

ID_DE_COLECCIÓN_WEBCAL

Debido a su naturaleza, el almacenamiento WebCal tiene una única colección. Sin embargo, esta colección no tiene un id. Se debe proporcionar explícitamente un id de colección para ella. Esto simplifica las configuraciones donde debe sincronizarse con otro calendario con el mismo id de colección.

storage calendars_lessons {
	type http
	collection_id lessons
	url {
		cmd hiq -dFurl proto=webcal alias=lessons
	}
}

SOLO_LECTURA

La directiva read_only no toma valores. Su presencia hace que un almacenamiento sea de solo lectura. Para hacer un almacenamiento de lectura/escritura, elimina la directiva.

ESTADO

Vdirsyncer mantiene una base de datos de estado para distinguir si un elemento ha cambiado en un lado o en ambos. Pimsync no importa esta base de datos de estado de ninguna manera. Si estás migrando y tienes almacenamientos remotos y locales existentes, asegúrate de que estén sincronizados antes de cambiar. Después de la primera ejecución, pimsync construirá su propia base de datos de estado.

Migrar con almacenamientos desincronizados resultará en conflictos durante la primera ejecución.

CONFIGURACIÓN_TLS

La directiva de configuración verify ahora se llama tls_root.

La directiva de configuración verify_fingerprint ahora se llama tls_fingerprint.

PROBLEMAS

Por favor, reporta problemas en: https://todo.sr.ht/~whynothugo/vdirsyncer-rs

Si tienes una configuración de vdirsyncer que funcione y esta página carece de detalles necesarios al actualizar, por favor, ponte en contacto para que esta documentación pueda ser mejorada.
