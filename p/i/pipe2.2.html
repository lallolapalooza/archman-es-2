pipe(2) Manual de llamadas al sistema pipe(2)

NOMBRE

pipe, pipe2 - crear tubería

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int pipe(int pipefd[2]);
#define _GNU_SOURCE             /* Véase feature_test_macros(7) */
#include <fcntl.h>              /* Definición de las constantes O_* */
#include <unistd.h>
int pipe2(int pipefd[2], int flags);
/* En Alpha, IA-64, MIPS, SuperH y SPARC/SPARC64, pipe() tiene el
   siguiente prototipo; véase VERSIONS */
#include <unistd.h>
struct fd_pair {
    long fd[2];
};
struct fd_pair pipe(void);

DESCRIPCIÓN

pipe() crea una tubería, un canal de datos unidireccional que puede ser usado para la comunicación entre procesos. El array pipefd se usa para devolver dos descriptores de archivo que se refieren a los extremos de la tubería. pipefd[0] se refiere al extremo de lectura de la tubería. pipefd[1] se refiere al extremo de escritura de la tubería. Los datos escritos en el extremo de escritura de la tubería son almacenados en búfer por el kernel hasta que se leen del extremo de lectura de la tubería. Para más detalles, véase pipe(7).

Si flags es 0, entonces pipe2() es lo mismo que pipe(). Los siguientes valores pueden ser combinados mediante OR bit a bit en flags para obtener un comportamiento diferente:

O_CLOEXEC
Establece la bandera close-on-exec (FD_CLOEXEC) en los dos nuevos descriptores de archivo. Véase la descripción de la misma bandera en open(2) para saber por qué esto puede ser útil.
O_DIRECT (desde Linux 3.4)
Crea una tubería que realiza E/S en modo "paquete". Cada write(2) a la tubería se maneja como un paquete separado, y las read(2) desde la tubería leerán un paquete a la vez. Tenga en cuenta los siguientes puntos:
•
Las escrituras de más de PIPE_BUF bytes (véase pipe(7)) se dividirán en múltiples paquetes. La constante PIPE_BUF está definida en <limits.h>.
•
Si una read(2) especifica un tamaño de búfer menor que el siguiente paquete, entonces se leerán el número de bytes solicitados y los bytes excesivos del paquete se desecharán. Especificar un tamaño de búfer de PIPE_BUF será suficiente para leer los paquetes más grandes posibles (véase el punto anterior).
•
Los paquetes de longitud cero no son compatibles. (Una read(2) que especifica un tamaño de búfer de cero es una operación nula y devuelve 0.)
Los kernels más antiguos que no soportan esta bandera lo indicarán mediante un error EINVAL.
Desde Linux 4.5, es posible cambiar la configuración O_DIRECT de un descriptor de archivo de tubería usando fcntl(2).
O_NONBLOCK
Establece la bandera de estado de archivo O_NONBLOCK en las descripciones de archivo abiertas a las que se refieren los nuevos descriptores de archivo. Usar esta bandera ahorra llamadas adicionales a fcntl(2) para lograr el mismo resultado.
O_NOTIFICATION_PIPE
Desde Linux 5.8, el mecanismo general de notificación se construye sobre la tubería, donde el kernel inserta mensajes de notificación en las tuberías abiertas por el espacio de usuario. El propietario de la tubería debe indicar al kernel qué fuentes de eventos observar y también se pueden aplicar filtros para seleccionar qué sub-eventos se colocarán en la tubería.

VALOR DE RETORNO

Al éxito, se devuelve cero. En caso de error, se devuelve -1, errno se establece para indicar el error, y pipefd no se modifica.

En Linux (y otros sistemas), pipe() no modifica pipefd en caso de fallo. Un requisito que estandariza este comportamiento se añadió en POSIX.1-2008 TC2. La llamada al sistema específica de Linux pipe2() tampoco modifica pipefd en caso de fallo.

ERRORES

EFAULT
pipefd no es válido.
EINVAL
(pipe2()) Valor inválido en flags.
EMFILE
Se ha alcanzado el límite por proceso del número de descriptores de archivo abiertos.
ENFILE
Se ha alcanzado el límite global del sistema para el número total de archivos abiertos.
ENFILE
Se ha alcanzado el límite estricto del usuario en la memoria que se puede asignar para tuberías y el llamante no tiene privilegios; véase pipe(7).
ENOPKG
(pipe2()) Se pasó O_NOTIFICATION_PIPE en flags y el soporte para notificaciones (CONFIG_WATCH_QUEUE) no está compilado en el kernel.

VERSIÓNES

La ABI del Sistema V en algunas arquitecturas permite el uso de más de un registro para devolver múltiples valores; varias arquitecturas (en concreto, Alpha, IA-64, MIPS, SuperH y SPARC/SPARC64) (ab)usan esta característica para implementar la llamada al sistema pipe() de forma funcional: la llamada no toma ningún argumento y devuelve un par de descriptores de archivo como valor de retorno en caso de éxito. La función de envoltura pipe() de glibc se encarga de esto de forma transparente. Véase syscall(2) para obtener información sobre los registros utilizados para almacenar el segundo descriptor de archivo.

EJEMPLOS

El siguiente programa crea una tubería y luego llama a fork(2) para crear un proceso hijo; el hijo hereda un conjunto duplicado de descriptores de archivo que se refieren a la misma tubería. Después de la llamada a fork(2), cada proceso cierra los descriptores de archivo que no necesita para la tubería (véase pipe(7)). El padre luego escribe la cadena contenida en el argumento de línea de comandos del programa en la tubería, y el hijo lee esta cadena byte a byte de la tubería y la envía a la salida estándar.

Código fuente del programa

#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int    pipefd[2];
    char   buf;
    pid_t  cpid;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <string>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (pipe(pipefd) == -1)
        err(EXIT_FAILURE, "pipe");
    cpid = fork();
    if (cpid == -1)
        err(EXIT_FAILURE, "fork");
    if (cpid == 0) {    /* El hijo lee de la tubería */
        if (close(pipefd[1]) == -1)  /* Cierra el extremo de escritura no utilizado */
            err(EXIT_FAILURE, "close");
        while (read(pipefd[0], &buf, 1) > 0) {
            if (write(STDOUT_FILENO, &buf, 1) != 1)
                err(EXIT_FAILURE, "write");
        }
        if (write(STDOUT_FILENO, "\n", 1) != 1)
            err(EXIT_FAILURE, "write");
        if (close(pipefd[0]) == -1)
            err(EXIT_FAILURE, "close");
        _exit(EXIT_SUCCESS);
    } else {            /* El padre escribe argv[1] en la tubería */
        if (close(pipefd[0]) == -1)  /* Cierra el extremo de lectura no utilizado */
            err(EXIT_FAILURE, "close");
        if (write(pipefd[1], argv[1], strlen(argv[1])) != strlen(argv[1]))
            err(EXIT_FAILURE, "write");
        if (close(pipefd[1]) == -1)  /* Cierra el extremo de escritura para EOF */
            err(EXIT_FAILURE, "close");
        if (wait(NULL) == -1)
            err(EXIT_FAILURE, "wait");
        exit(EXIT_SUCCESS);
    }
}
pipe2(2) — Arch Linux man pages

NAME

pipe2

crear una tubería (pipe) con atributos especificados

LIBRARY

Librería de C estándar (libc, -lc)

SYNOPSIS

       #include <fcntl.h>
       #include <unistd.h>

       int pipe2(int pipefd[2], int flags);

DESCRIPTION

La llamada al sistema pipe2() es similar a pipe(2), pero permite que el llamante especifique flags para los descriptores de archivo de la tubería. La tubería se crea y sus dos descriptores de archivo se colocan en la matriz apuntada por pipefd. El descriptor de archivo pipefd[0] se abre para lectura y el descriptor de archivo pipefd[1] se abre para escritura.

El argumento flags es una operación OR bit a bit de cero o más de las siguientes banderas:

O_CLOEXEC
Establece el flag de cierre en ejecución (close-on-exec) en ambos descriptores de archivo. Ver fcntl(2) para más detalles.
O_DIRECT
La información I/O se transferirá directamente entre el espacio de usuario y los dispositivos de almacenamiento. Ver open(2) para más detalles.
O_NONBLOCK
Abre ambos extremos de la tubería en modo no bloqueante. Ver fcntl(2) para más detalles.
O_ASYNC
Habilita señales de I/O asíncronas en los descriptores de archivo. Ver fcntl(2) para más detalles.

Si flags es 0, entonces pipe2() se comporta como pipe(2).

La tubería creada no tiene un nombre en el sistema de archivos. Los datos escritos en el extremo de escritura de la tubería pueden ser leídos desde el extremo de lectura. Los datos se almacenan en un buffer hasta que se leen. Si el buffer está lleno, las escrituras pueden bloquearse o fallar con EAGAIN si la tubería se abrió en modo no bloqueante.

Si se intenta leer de una tubería vacía, la operación se bloqueará hasta que haya datos disponibles para leer. Si la tubería se abrió en modo no bloqueante, la operación fallará con EAGAIN.

Si todos los descriptores de archivo para el extremo de escritura de una tubería se cierran, entonces una lectura de la tubería devolverá cero bytes (indicando el fin del archivo). Si se intenta escribir en una tubería cuyos descriptores de archivo de lectura se han cerrado, se generará una señal SIGPIPE al proceso escritor.

Los flags O_NONBLOCK y O_ASYNC se aplican a ambos descriptores de archivo de la tubería.

El flag O_CLOEXEC se aplica a ambos descriptores de archivo de la tubería. Es una forma más robusta de establecer el flag close-on-exec que usar fcntl(2) después de la creación de la tubería.

El flag O_DIRECT se aplica a ambos descriptores de archivo de la tubería. Sin embargo, su comportamiento con tuberías puede no ser el esperado y su uso está desaconsejado. Ver la página del manual de open(2) para más detalles sobre O_DIRECT.

RETURN VALUE

Al éxito, pipe2() devuelve 0. En caso de error, devuelve -1 y errno se establece para indicar el error.

ERRORS

Los siguientes son algunos de los posibles errores que pipe2() puede encontrar:

EAGAIN
Se solicitó O_NONBLOCK y la operación de tubería no se pudo completar inmediatamente (por ejemplo, la tubería está llena).
EBADF
pipefd no es un puntero válido.
EINVAL
Se especificaron flags inválidos en flags.
EMFILE
El proceso ya ha abierto el número máximo de descriptores de archivo.
ENFILE
El sistema ha alcanzado el límite máximo de descriptores de archivo abiertos.
ENOMEM
No hay suficiente memoria del kernel para completar la operación.

VERSIONS

La llamada al sistema pipe2() se introdujo en el kernel Linux 2.6.27.

STANDARDS

Esta llamada al sistema es específica de Linux.

HISTORY

La llamada al sistema pipe2() se introdujo en el kernel Linux 2.6.27.

Los flags O_DIRECT y O_ASYNC se añadieron en Linux 3.1.

EXAMPLES

El siguiente ejemplo crea una tubería, bifurca un proceso hijo, y el hijo escribe una cadena en la tubería. El padre lee la cadena de la tubería y la imprime.

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>
#include <err.h>
#include <sys/wait.h>

    int
    main(int argc, char *argv[])
    {
        int pipefd[2];
        pid_t cpid;
        char buf;

        if (argc != 2) {
            fprintf(stderr, "Usage: %s <string>\n", argv[0]);
            exit(EXIT_FAILURE);
        }

        if (pipe2(pipefd, O_CLOEXEC) == -1) {
            err(EXIT_FAILURE, "pipe");
        }

        cpid = fork();
        if (cpid == -1) {
            err(EXIT_FAILURE, "fork");
        }

        if (cpid == 0) {    /* Child */
            close(pipefd[0]);    /* Close unused read end */
            if (write(pipefd[1], argv[1], strlen(argv[1])) != strlen(argv[1]))
                err(EXIT_FAILURE, "write");
            close(pipefd[1]);    /* Reader will see EOF */
            exit(EXIT_SUCCESS);
        } else {            /* Parent */
            close(pipefd[1]);    /* Close unused write end */
            for (;;) {
                ssize_t numRead = read(pipefd[0], &buf, 1);
                if (numRead == -1) {
                    err(EXIT_FAILURE, "read");
                }

                if (numRead == 0) { /* EOF */
                    break;
                }
                printf("%c", buf);
            }

            putchar('\n');

            if (wait(NULL) == -1)        /* Wait for child */
                err(EXIT_FAILURE, "wait");

            exit(EXIT_SUCCESS);
        }
    }
