pidfd_send_signal(2) System Calls Manual pidfd_send_signal(2)

NOMBRE

pidfd_send_signal - enviar una señal a un proceso especificado por un descriptor de archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/signal.h>     /* Definición de constantes SIG* */
#include <signal.h>           /* Definición de constantes SI_* */
#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_pidfd_send_signal, int pidfd, int sig,
            siginfo_t *_Nullable info, unsigned int flags);

Nota: glibc no proporciona un envoltorio para pidfd_send_signal(), lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema pidfd_send_signal() envía la señal sig al proceso destino al que se refiere pidfd, un descriptor de archivo PID que se refiere a un proceso.

Si el argumento info apunta a un búfer siginfo_t, ese búfer debe estar poblado como se describe en rt_sigqueueinfo(2).

Si el argumento info es un puntero nulo, esto es equivalente a especificar un puntero a un búfer siginfo_t cuyos campos coinciden con los valores que se suministran implícitamente cuando se envía una señal usando kill(2):

•
si_signo se establece en el número de señal;
•
si_errno se establece en 0;
•
si_code se establece en SI_USER;
•
si_pid se establece en el PID del llamante; y
•
si_uid se establece en el ID de usuario real del llamante.

El proceso que llama debe estar en el mismo espacio de nombres PID que el proceso al que se refiere pidfd, o estar en un antecesor de ese espacio de nombres.

El argumento flags permite modificar el ámbito de la señal. Por defecto, el ámbito de la señal se inferirá del argumento pidfd. Por ejemplo, si pidfd se refiere a un hilo específico —es decir, si pidfd se creó a través de pidfd_open(2) usando la bandera PIDFD_THREAD o a través de clone3(2) usando la bandera CLONE_PIDFD junto con la bandera CLONE_THREAD— entonces pasar pidfd a pidfd_send_signal(2) y dejar el argumento flags como 0 hará que la señal se envíe al hilo específico al que se refiere el pidfd.

PIDFD_SIGNAL_THREAD (desde Linux 6.9)
Asegura que la señal se envíe al hilo específico al que se refiere pidfd.
PIDFD_SIGNAL_THREAD_GROUP (desde Linux 6.9)
Si pidfd se refiere a un líder de grupo de hilos, asegura que la señal se envíe al grupo de hilos, incluso si pidfd se creó para referirse a un hilo específico.
PIDFD_SIGNAL_PROCESS_GROUP (desde Linux 6.9)
Si pidfd se refiere a un líder de grupo de procesos, asegura que la señal se envíe al grupo de procesos, incluso si pidfd se creó para referirse a un hilo específico o a un líder de grupo de hilos.

VALOR DE RETORNO

En caso de éxito, pidfd_send_signal() devuelve 0. En caso de error, devuelve -1 y errno se establece para indicar el error.

ERRORES

EBADF
pidfd no es un descriptor de archivo PID válido.
EINVAL
sig no es una señal válida.
EINVAL
El proceso que llama no está en un espacio de nombres PID desde el que pueda enviar una señal al proceso destino.
EINVAL
flags no es válido.
EPERM
El proceso que llama no tiene permiso para enviar la señal al proceso destino.
EPERM
pidfd no se refiere al proceso que llama, y info.si_code es inválido (ver rt_sigqueueinfo(2)).
ESRCH
El proceso destino no existe (es decir, ha terminado y ha sido esperado).

ESTÁNDARES

Linux.

HISTORIA

Linux 5.1.

NOTAS

Descriptores de archivo PID

El argumento pidfd es un descriptor de archivo PID, un descriptor de archivo que se refiere a un proceso. Dicho descriptor de archivo se puede obtener de cualquiera de las siguientes maneras:

•
abriendo un directorio /proc/pid;
•
usando pidfd_open(2); o
•
a través del descriptor de archivo PID que se devuelve en una llamada a clone(2) o clone3(2) que especifica la bandera CLONE_PIDFD.

La llamada al sistema pidfd_send_signal() permite evitar condiciones de carrera que ocurren al usar interfaces tradicionales (como kill(2)) para enviar una señal a un proceso. El problema es que las interfaces tradicionales especifican el proceso destino a través de un ID de proceso (PID), con el resultado de que el remitente puede enviar accidentalmente una señal al proceso incorrecto si el proceso destino originalmente previsto ha terminado y su PID ha sido reciclado para otro proceso. Por el contrario, un descriptor de archivo PID es una referencia estable a un proceso específico; si ese proceso termina, pidfd_send_signal() falla con el error ESRCH.

EJEMPLOS

#define _GNU_SOURCE
#include <fcntl.h>
#include <limits.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/syscall.h>
#include <unistd.h>
static int
pidfd_send_signal(int pidfd, int sig, siginfo_t *info,
                  unsigned int flags)
{
    return syscall(SYS_pidfd_send_signal, pidfd, sig, info, flags);
}
int
main(int argc, char *argv[])
{
    int        pidfd, sig;
    char       path[PATH_MAX];
    siginfo_t  info;
    if (argc != 3) {
        fprintf(stderr, "Uso: %s <pid> <señal>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    sig = atoi(argv[2]);
    /* Obtener un descriptor de archivo PID abriendo el directorio /proc/PID
       del proceso destino.  */
    snprintf(path, sizeof(path), "/proc/%s", argv[1]);
    pidfd = open(path, O_RDONLY);
    if (pidfd == -1) {
        perror("open");
        exit(EXIT_FAILURE);
    }
    /* Poblar una estructura 'siginfo_t' para usarla con
       pidfd_send_signal().  */
    memset(&info, 0, sizeof(info));
    info.si_code = SI_QUEUE;
    info.si_signo = sig;
    info.si_errno = 0;
    info.si_uid = getuid();
    info.si_pid = getpid();
    info.si_value.sival_int = 1234;
    /* Enviar la señal.  */
    if (pidfd_send_signal(pidfd, sig, &info, 0) == -1) {
        perror("pidfd_send_signal");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS);
}

VER TAMBIÉN

Enviar una señal a un proceso usando un descritor de archivo de proceso pidfd_send_signal(2)

NOMBRE

pidfd_send_signal - enviar una señal a un proceso usando un descritor de archivo de proceso

BIBLIOTECA

Interfaz de la biblioteca C, libpthread

SINOPSIS

        #include <sys/types.h>
        #include <signal.h>
        #include <unistd.h>

        int pidfd_send_signal(int pidfd, int sig,
                              siginfo_t *info, unsigned int flags);

DESCRIPCIÓN

La llamada al sistema pidfd_send_signal envía la señal sig al proceso o hilo representado por el descritor de archivo de proceso pidfd. Este descritor de archivo de proceso debe haber sido obtenido previamente mediante una llamada a pidfd_open.

El argumento sig es el número de la señal que se enviará (por ejemplo, SIGKILL, SIGTERM, etc.).

El argumento info es un puntero a una estructura siginfo_t que especifica detalles adicionales sobre la señal. Si info es NULL, entonces no se envían detalles adicionales, y la señal se envía de forma predeterminada.

El argumento flags actualmente solo admite el valor 0. En el futuro, puede admitir otras opciones.

A diferencia de kill() y tgkill(), pidfd_send_signal utiliza un descritor de archivo para especificar el proceso objetivo. Esto proporciona varias ventajas:

  • Seguridad: El descritor de archivo pidfd garantiza que la señal se envía al proceso correcto, incluso si el ID del proceso ha sido reutilizado por otro proceso.
  • Atomicidad: La obtención del descritor de archivo y el envío de la señal pueden verse como una operación más atómica en comparación con la combinación de fork() y kill(), o la espera de un proceso mediante wait() y luego su eliminación.

VALOR DE RETORNO

En caso de éxito, pidfd_send_signal devuelve 0. En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORES

EBADF
El argumento pidfd no es un descritor de archivo válido.
EINVAL
El descritor de archivo pidfd no es un descritor de archivo de proceso válido, o el valor de sig no es una señal válida.
EPERM
El proceso de llamada no tiene permisos para enviar la señal especificada al proceso objetivo.
ESRCH
El proceso objetivo representado por pidfd ya no existe.
ENOTSUP
El valor de flags no es 0.

ESTÁNDARES

La llamada al sistema pidfd_send_signal es una extensión de Linux y no está definida en ningún estándar.

HISTORIA

La llamada al sistema pidfd_send_signal se introdujo en el kernel de Linux 5.1.

NOTAS

Para usar pidfd_send_signal, el programa debe ser compilado con la macro _GNU_SOURCE definida.

El campo si_pid de la estructura siginfo_t se establecerá automáticamente en el PID del proceso que llama.

EJEMPLOS

El siguiente ejemplo muestra cómo enviar la señal SIGTERM a un proceso usando su descritor de archivo de proceso:

#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <fcntl.h>

int main() {
    pid_t pid;
    int pidfd;

    pid = fork();
    if (pid == -1) {
        perror("fork");
        exit(EXIT_FAILURE);
    }

    if (pid == 0) { // Proceso hijo
        printf("Proceso hijo (PID: %d) iniciado. Durmiendo...\n", getpid());
        pause(); // Espera una señal
        printf("Proceso hijo (PID: %d) recibido señal, saliendo.\n", getpid());
        exit(EXIT_SUCCESS);
    } else { // Proceso padre
        printf("Proceso padre (PID: %d) ha creado el hijo (PID: %d).\n", getpid(), pid);

        // Obtener el descritor de archivo de proceso
        pidfd = pidfd_open(pid, 0);
        if (pidfd == -1) {
            perror("pidfd_open");
            exit(EXIT_FAILURE);
        }
        printf("Descritor de archivo de proceso obtenido: %d\n", pidfd);

        // Enviar la señal SIGTERM al proceso hijo
        printf("Enviando SIGTERM al proceso hijo...\n");
        if (pidfd_send_signal(pidfd, SIGTERM, NULL, 0) == -1) {
            perror("pidfd_send_signal");
            close(pidfd);
            exit(EXIT_FAILURE);
        }

        // Esperar a que el proceso hijo termine
        int status;
        waitpid(pid, &status, 0);
        printf("Proceso hijo terminado.\n");

        close(pidfd);
    }

    return 0;
}

VER TAMBIÉN

pidfd_open(2), kill(2), tgkill(2), signal(7)
