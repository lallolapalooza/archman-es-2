PIPESZ(1) Comandos de usuario PIPESZ(1)

NOMBRE

pipesz - establecer o examinar tamaños de búfer de tuberías (pipe) y FIFO

SINOPSIS

pipesz [opciones] [--set tamaño] [--] [comando [argumento] ...]

pipesz [opciones] --get

DESCRIPCIÓN

Las tuberías (pipes) y las FIFO mantienen un búfer interno que se utiliza para transferir datos entre el extremo de lectura y el extremo de escritura. En algunos casos, el tamaño predeterminado de este búfer interno puede no ser el adecuado. Este programa proporciona instalaciones para establecer y examinar el tamaño de estos búferes.

La operación --set establece los tamaños de los búferes de las tuberías. Si se especifica, debe especificarse con un tamaño explícito. De lo contrario, se asume y el tamaño se lee de /proc/sys/fs/pipe-max-size. El kernel puede ajustar tamaño como se describe en fcntl(2). Para determinar los tamaños reales de los búferes establecidos, utilice la opción --verbose. Si no se especifican ni --file ni --fd, --set actúa sobre la salida estándar.

La operación --set permite un comando opcional para ejecutar después de establecer los tamaños de los búferes de las tuberías. Este comando se ejecuta con las tuberías ajustadas.

La operación --get muestra los datos en formato de tabla. La primera columna es el nombre de la tubería tal como se pasó a pipesz. Los descriptores de archivo se nombran como "fd N". La segunda columna es el tamaño, en bytes, del búfer interno de la tubería. La tercera columna es el número de bytes no leídos actualmente en la tubería. Las columnas están separadas por tabulaciones ('\t', ASCII 09h). Si se especifica --verbose, también se emite una cabecera descriptiva. Si no se especifican ni --file ni --fd, --get actúa sobre la entrada estándar.

A menos que se especifique la opción --check, pipesz *no* sale si encuentra un error al manipular un archivo o un descriptor de archivo. Esto permite que pipesz se utilice de forma genérica sin temor a interrumpir la ejecución de tuberías si el tipo de ciertos archivos se cambia más adelante. Para una interrupción mínima, la opción --quiet evita que se emitan advertencias en estos casos.

El kernel impone límites a la cantidad de espacio de búfer de tubería que los procesos no privilegiados pueden utilizar, aunque ver BUGS a continuación. El kernel también se negará a reducir un búfer de tubería si esto causara una pérdida de datos en búfer. Ver pipe(7) para detalles adicionales.

pipesz admite la especificación de varias opciones cortas consecutivamente, en el estilo habitual de getopt(3). El primer argumento que no es una opción se interpreta como comando. Si comando podría comenzar con '-', use '--' para separarlo de los argumentos de pipesz. En scripts de shell, es una buena práctica usar '--' cuando hay expansión de parámetros involucrada. pipesz en sí mismo no lee de la entrada estándar ni escribe en la salida estándar a menos que se especifiquen --get, --help o --version.

OPCIONES

-g, --get

Informa del tamaño de los búferes de las tuberías a la salida estándar y sale. Como comportamiento especial, si no se especifican ni --file ni --fd, se examina la entrada estándar. Es un error especificar esta opción en combinación con --set.

-s, --set tamaño

Establece el tamaño de los búferes de las tuberías, en bytes. Esta opción puede ir seguida de K, M, G, KiB, MiB o GiB para indicar múltiplos de 1024. Se admiten valores fraccionarios en este caso. Se admiten sufijos adicionales pero es poco probable que sean útiles. Si esta opción no se especifica, se utiliza un valor predeterminado, como se describe anteriormente. Si esta opción se especifica varias veces, se emite una advertencia y solo se usa el tamaño especificado por última vez. Como comportamiento especial, si no se especifican ni --file ni --fd, se ajusta la salida estándar. Es un error especificar esta opción en combinación con --get.

-f, --file ruta

Establece el tamaño del búfer de la FIFO o tubería en ruta, en relación con el directorio de trabajo actual. Puede especificar esta opción varias veces para afectar a diferentes archivos y puede hacerlo en combinación con --fd. En general, esta opción se utiliza con FIFO, pero también operará en tuberías anónimas como las que se encuentran en /proc/PID/fd. Los cambios en el tamaño del búfer de las FIFO no se preservan entre reinicios del sistema.

-n, --fd fd

Establece el tamaño del búfer de la tubería o FIFO pasada a pipesz como el número de descriptor de archivo especificado. Puede especificar esta opción varias veces para afectar a diferentes descriptores de archivo y puede hacerlo en combinación con --file. Se proporcionan opciones abreviadas para los casos comunes de fd 0 (stdin), fd 1 (stdout) y fd 2 (stderr). Estos deberían ser suficientes en la mayoría de los casos.

-i, --stdin

Abreviatura de --fd 0.

-o, --stdout

Abreviatura de --fd 1.

-e, --stderr

Abreviatura de --fd 2.

-c, --check

Sale, sin ejecutar comando, en caso de cualquier error al manipular un archivo o descriptor de archivo. El comportamiento predeterminado si no se especifica esto es emitir una advertencia a la salida de error estándar y continuar.

-q, --quiet

No diagnostique errores no fatales a la salida de error estándar. Esta opción no afecta la salida normal de --get, --verbose, --help o --version.

-v, --verbose

Si se especifica con --get, pipesz emitirá una cabecera descriptiva encima de la tabla. De lo contrario, si se especifica, pipesz imprimirá los tamaños reales de los búferes establecidos por el kernel a la salida de error estándar.

-h, --help

Muestra el texto de ayuda y sale.

-V, --version

Muestra la versión y sale.

EJEMPLOS

pipesz dd if=archivo bs=1M | ...

Ejecuta dd(1) con una tubería de salida estándar ampliada, lo que le permite evitar cambios de contexto al pasar grandes bloques.

pipesz -s1M -cf /run/mi-servicio.fifo

Establece el tamaño del búfer de la tubería de una FIFO de servicio a 1.048.576 bytes. Si no se pudo establecer el tamaño del búfer, pipesz sale con un error.

echo hola | pipesz -g

Imprime el tamaño de la tubería utilizada por el shell para pasar entrada a pipesz. Dado que pipesz no lee la entrada estándar, también puede informar de 6 bytes no leídos en la tubería, según los tiempos relativos.

find /proc/PID/fd -exec pipesz -gqf '{}' ';'

Imprime el tamaño y el número de bytes no leídos de todas las tuberías en uso por PID. Si algunas tuberías están rutinariamente llenas, pipesz podría ser capaz de mitigar un cuello de botella en el procesamiento.

NOTAS

Linux admite el ajuste del tamaño de los búferes de las tuberías desde el kernel 2.6.35. Esta versión también introdujo /proc/sys/fs/pipe-max-size.

Este programa utiliza fcntl(2) F_GETPIPE_SZ/F_SETPIPE_SZ para obtener y establecer tamaños de búfer de tubería.

Este programa utiliza ioctl(2) FIONREAD para informar la cantidad de datos no leídos en las tuberías. Si por alguna razón esto falla, la cantidad de datos no leídos se informa como 0.

ERRORES CONOCIDOS

Antes de Linux 4.9, algunos errores afectaron a cómo se aplican ciertos límites de recursos al establecer tamaños de búfer de tubería. Ver pipe(7) para detalles.
