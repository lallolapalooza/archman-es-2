PIMSYNC(1) Manual de Comandos Generales PIMSYNC(1)

NOMBRE

pimsync — sincroniza directorios caldav, carddav, webcal y locales

SINOPSIS

pimsync [-c archivo_config] [-v nivel_log] comando [par…]

pimsync version

DESCRIPCIÓN

pimsync sincroniza calendarios y contactos. Para calendarios, soporta la operación en directorios locales, servidores CalDAV o URLs Webcal. Para contactos, soporta la operación en directorios locales o servidores CardDAV.

La siguiente glosario proporciona una breve descripción general de la terminología relevante:

elemento
Un evento individual, tarea, entrada de diario o contacto.
colección
Un grupo de múltiples elementos. Puede ser (1) un calendario individual que contiene eventos, tareas y/o entradas de diario, o (2) una agenda que contiene contactos.
almacenamiento
Una ubicación que contiene múltiples colecciones. Un único almacenamiento puede ser una cuenta en un servidor CalDAV, o un directorio local que contiene múltiples subdirectorios, cada uno de estos directorios representando un calendario individual.
par
Dos almacenamientos que están configurados para sincronizarse entre sí. Tenga en cuenta que un almacenamiento individual puede formar parte de más de un par.
conflicto
Al sincronizar dos almacenamientos, si un elemento individual ha sido modificado en ambos lados pero tiene contenido diferente en ambos lados, se dice que ese elemento está en conflicto.

OPCIONES

-c archivo_config
Leer el archivo de configuración desde la ruta especificada, en lugar de la predeterminada. Ver ARCHIVOS abajo y pimsync.conf(5).
-v nivel_log
Establecer el registrador a nivel_log, que debe ser uno de trace, debug, info, warn o error. El predeterminado es warn. Al especificar trace, los registros pueden contener datos sensibles, ver CONSIDERACIONES DE SEGURIDAD abajo.

COMANDOS

check [par…]
Verifica la configuración y sale. Valida la configuración en sí misma y asegura que el almacenamiento sea válido. Por ejemplo: un vdir debe ser un directorio existente, y un servidor caldav debe informar sobre sus capacidades CalDAV, etc.
daemon [par…]
Mantiene los almacenamientos sincronizados continuamente. El argumento -r READY_FD puede ser utilizado para proporcionar un descriptor de archivo de notificación de disponibilidad.

Una vez que pimsync ha alcanzado su estado de listo, el demonio monitoreará los almacenamientos en busca de cambios y los sincronizará. En caso de errores no fatales, pimsync continuará ejecutándose en segundo plano y reintentará las operaciones fallidas más tarde.

Los elementos individuales que no se sincronicen se omitirán.

discover [par…]
Descubre e imprime colecciones. Este comando simplemente proporciona información y no altera de ninguna manera el estado interno de pimsync.
resolve-conflicts [par…]
Resuelve manualmente conflictos entre almacenamientos.

Ejecuta un programa externo, especificado en el archivo de configuración, que realiza la resolución de conflictos para cada elemento en conflicto.

Al añadir -n se realiza una ejecución de prueba y no se realizarán operaciones de escritura.

sync [par…]
Sincroniza los almacenamientos una vez y sale. Al añadir -n se realiza una ejecución de prueba y no se realizarán operaciones de escritura.
repair [almacenamiento…]
Repara elementos inválidos. Actualmente, esto añade campos faltantes de UID, pero es probable que se incluyan otras correcciones en el futuro. Se desaconseja encarecidamente reparar ambas colecciones de un par; en su lugar, repara en un almacenamiento y luego sincroniza el par.
version
Imprime información de la versión y sale.

Si se especifica un par, solo opere en el o los pares con el nombre dado.

AMBIENTE

XDG_CONFIG_HOME
Si está definido, busca el archivo de configuración relativo a este directorio. Ver ARCHIVOS abajo.

ARCHIVOS

Si XDG_CONFIG_HOME está definido, la configuración se leerá desde:

$XDG_CONFIG_HOME/pimsync/pimsync.conf

Si lo anterior no está definido, el archivo de configuración se leerá desde:

~/.config/pimsync/pimsync.conf

Ver pimsync.conf(5) para detalles sobre el formato del archivo de configuración.

NOTIFICACIÓN DE DISPONIBILIDAD

La notificación de disponibilidad permite a un gestor de servicios monitorear cuándo pimsync ha comenzado con éxito. Se considera que ha comenzado con éxito cuando el archivo de configuración ha sido analizado y todas las credenciales han sido resueltas. En este punto, no se requerirá más interacción humana.

Una vez que el servicio esté listo, escribirá ‘READY=1’ seguido de un carácter de nueva línea en el descriptor de archivo READY_FD, y luego lo cerrará. Esto es compatible con el mecanismo de notificación de disponibilidad implementado por s6, dinit y systemd.

Ver: https://skarnet.org/software/s6/notifywhenup.html

PRIVACIDAD

Las únicas comunicaciones de red serán con los servidores de los almacenamientos configurados, y el resolvedor DNS configurado localmente.

El archivo de base de datos de estado contiene metadatos de los almacenamientos configurados, sus colecciones y elementos.

VALIDACIÓN DE DATOS

Los datos sincronizados no se validan. Esta es una elección de diseño intencional: si su aplicación de calendario produce eventos que son técnicamente inválidos, pimsync los sincronizará, y usted podrá acceder a los mismos datos exactos en otros hosts. También es posible que necesite sincronizar datos inválidos para corregir la invalidez.

Para mapear elementos entre almacenamientos, pimsync realiza un análisis menor de los elementos para extraer su UID. Los elementos deben ser componentes sintácticamente válidos, incluso si son semánticamente inválidos.

Para interactuar con recursos CalDAV/CardDAV donde no se puede extraer un UID, use el comando repair

CONSIDERACIONES DE SEGURIDAD

Cuando se habilita el descubrimiento de servicios, el nombre de host real y el puerto del servidor DAV se resuelven utilizando registros DNS. Se utiliza el resolvedor DNS del sistema. Se espera que el resolvedor del sistema realice la validación DNSSEC y no devuelva resultados inválidos. Pimsync no realiza la validación DNSSEC por sí mismo.

Pimsync seguirá los enlaces simbólicos al leer elementos. Se debe tener cuidado cuando un usuario tiene permiso de escritura en un almacenamiento, pero otro usuario ejecuta pimsync en ese mismo almacenamiento. Esto puede cambiar en el futuro.

Los elementos a través de los almacenamientos se consideran iguales si comparten el mismo UID. Un actor que puede escribir un solo elemento en un almacenamiento en cualquiera de los lados puede desencadenar potencialmente la sobrescritura de otro elemento en el otro almacenamiento. Un actor que puede escribir en una sola entrada debe considerarse que tiene acceso para manipular todo el almacenamiento.

Pimsync conservará las credenciales en memoria durante toda su vida útil. Cualquier actor con acceso de lectura al espacio de memoria de pimsync puede extraer credenciales secretas de él. Del mismo modo, los volcados de memoria de pimsync no deben compartirse con partes no confiables.

Al registrar con -v trace, los registros PUEDEN contener credenciales, secretos, datos dentro de los elementos del almacenamiento y otra información confidencial.

ALGORITMO DE SINCRONIZACIÓN

Después de que pimsync sincroniza dos almacenamientos, almacenará metadatos de los elementos que ha sincronizado en su base de datos de estado interna. Durante los futuros procesos de sincronización, si los elementos en ambos almacenamientos no coinciden, la base de datos de estado se utiliza para determinar qué lado ha cambiado y qué lado permanece igual que la última vez. Esta información se utiliza luego para planificar cuál de los elementos debe conservarse y cuál debe sobrescribirse. Si ambos elementos han cambiado, se dice que están en conflicto y el conflicto debe resolverse manualmente (Ver RESOLUCIÓN DE CONFLICTOS arriba).

La base de datos de estado asocia los metadatos del elemento con el par de colecciones que se estaban sincronizando entre sí (llamado "mapeo"). Si la configuración cambia y se sincronizan colecciones diferentes entre sí, los datos de estado de sus elementos ya no se aplican y se ignoran. Esto evita el uso accidental de datos incorrectos cuando los mapeos se han reconfigurado.

El algoritmo se basa en gran medida en el original de vdirsyncer(1). Más detalles están disponibles en https://unterwaditzer.net/2016/sync-algorithm.html.

Eliminar la base de datos de estado obligará a pimsync a sincronizar ambos almacenamientos como si fuera la primera vez que los ve. Los elementos que existen y son idénticos en ambos lados estarán bien, pero los elementos que no son idénticos se considerarán en conflicto (ya que pimsync no puede decidir inequívocamente cuál conservar).

PROTECCIONES

Cuando se eliminan todos los elementos de una colección, pimsync(1) asumirá un error del usuario y se negará a operar en esta colección. Este comportamiento se puede deshabilitar con la directiva on_empty. Ver pimsync.conf(5) para más detalles.

PRECAUCIONES

Para almacenamientos de tipo vdir, verificar si un elemento ha sido modificado por un proceso externo está sujeto a condiciones de carrera. Pimsync primero verificará que un elemento no ha sido modificado y luego lo actualizará. Si un programa externo actualiza el mismo elemento entre la verificación y la modificación, esos cambios se perderán. Este problema se debe a limitaciones en las primitivas del sistema de archivos POSIX. Es poco probable que se resuelva.

EJEMPLOS

Ejecutar el demonio con registro detallado:
pimsync -v info daemon
Resolución interactiva de conflictos para el par llamado "contacts":
pimsync resolve-conflicts contacts
Mostrar versión y salir:
pimsync version

ESTÁNDARES

  • Las Extensiones de Calendario para WebDAV (CalDAV) se implementan según lo especificado en la RFC 4791 de la IETF.
  • Las Extensiones de vCard para WebDAV (CardDAV) se implementan según lo especificado en la RFC 4791 de la IETF.
  • El descubrimiento de servicios se implementa según lo especificado en la RFC 6764 de la IETF.
  • El almacenamiento vdir implementa el diseño especificado en la especificación del formato vdir: https://pimutils.org/specs/vdir/
