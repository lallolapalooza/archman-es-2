pidfile(3bsd)

Paquete: libbsd

Licencias: custom

pidfile(3bsd) 3bsd pidfile(3bsd)

NOMBRE

pidfile_open, pidfile_write, pidfile_close, pidfile_remove, pidfile_fileno — biblioteca para manejo de archivos PID

BIBLIOTECA

biblioteca «libbsd»

SINOPSIS

#include <libutil.h> (Ver libbsd(7) para el uso de la inclusión.)
struct pidfh *
pidfile_open(const char *path, mode_t mode, pid_t *pidptr);

int
pidfile_write(struct pidfh *pfh);

int
pidfile_close(struct pidfh *pfh);

int
pidfile_remove(struct pidfh *pfh);

int
pidfile_fileno(struct pidfh *pfh);

DESCRIPCIÓN

La familia de funciones pidfile permite a los demonios manejar archivos PID. Utiliza flopen(3bsd) para bloquear un archivo PID y detectar demonios que ya se están ejecutando.

La función pidfile_open() abre (o crea) un archivo especificado por el argumento path y lo bloquea. Si el argumento pidptr no es NULL y el archivo no se puede bloquear, la función lo usará para almacenar el PID de un demonio que ya se está ejecutando o -1 en caso de que el demonio aún no haya escrito su PID. La función no escribe el PID del proceso en el archivo aquí, por lo que puede usarse antes de hacer fork() y salir con un mensaje de error adecuado cuando sea necesario. Si el argumento path es NULL, se usará el archivo /var/run/⟨nombre_prog⟩.pid. La función pidfile_open() establece la bandera O_CLOEXEC de cierre al ejecutar para el archivo PID al abrirlo.

La función pidfile_write() escribe el PID del proceso en un archivo previamente abierto. El archivo se trunca antes de escribir, por lo que se admite llamar a la función pidfile_write() varias veces.

La función pidfile_close() cierra un archivo PID. Debe usarse después de que el demonio haga fork() para iniciar un proceso hijo.

La función pidfile_remove() cierra y elimina un archivo PID.

La función pidfile_fileno() devuelve el descriptor de archivo del archivo PID abierto.

VALORES DE RETORNO

La función pidfile_open() devuelve un puntero válido a una estructura pidfh en caso de éxito, o NULL si ocurre un error. Si ocurre un error, errno se establecerá.


Las funciones pidfile_write(), pidfile_close() y pidfile_remove() devuelven el valor 0 si tienen éxito; de lo contrario, se devuelve el valor -1 y la variable global errno se establece para indicar el error.

La función pidfile_fileno() devuelve el descriptor de archivo de bajo nivel. Devuelve -1 y establece errno si se especifica un pidfh nulo, o si el archivo PID ya no está abierto.

EJEMPLOS

El siguiente ejemplo muestra en qué orden deben usarse estas funciones. Tenga en cuenta que es seguro pasar NULL a las funciones pidfile_write(), pidfile_remove(), pidfile_close() y pidfile_fileno().

struct pidfh *pfh;
pid_t otherpid, childpid;

pfh = pidfile_open("/var/run/daemon.pid", 0600, &otherpid);
if (pfh == NULL) {
	if (errno == EEXIST) {
		errx(EXIT_FAILURE, "El demonio ya se está ejecutando, pid: %jd.",
		    (intmax_t)otherpid);
	}
	/* Si no podemos crear el archivo PID por otras razones, solo advertir. */
	warn("No se puede abrir o crear el archivo PID");
	/*
	 * Aunque pfh sea NULL, podemos continuar, ya que las otras funciones
	 * pidfile_* pueden manejar tal situación haciendo nada excepto
	 * establecer errno a EINVAL.
	 */
}

if (daemon(0, 0) == -1) {
	warn("No se puede demonizar");
	pidfile_remove(pfh);
	exit(EXIT_FAILURE);
}

pidfile_write(pfh);

for (;;) {
	/* Hacer el trabajo. */
	childpid = fork();
	switch (childpid) {
	case -1:
		syslog(LOG_ERR, "No se puede fork(): %s.", strerror(errno));
		break;
	case 0:
		pidfile_close(pfh);
		/* Hacer el trabajo del hijo. */
		break;
	default:
		syslog(LOG_INFO, "Se inició el hijo %jd.", (intmax_t)childpid);
		break;
	}
}

pidfile_remove(pfh);
exit(EXIT_SUCCESS);

ERRORES

La función pidfile_open() fallará si:

[EEXIST]
Algún proceso ya tiene el bloqueo en el archivo PID dado, lo que significa que un demonio ya se está ejecutando. Si el argumento pidptr no es NULL, la función lo usará para almacenar el PID de un demonio que ya se está ejecutando o -1 en caso de que el demonio aún no haya escrito su PID.
[ENAMETOOLONG]
El nombre del archivo PID especificado es demasiado largo.
[EINVAL]
Algún proceso ya tiene el bloqueo en el archivo PID dado, pero el PID leído de él no es válido.

La función pidfile_open() también puede fallar y establecer errno para cualquier error especificado para las llamadas fstat(2), open(2) y read(2).

La función pidfile_write() fallará si:

[EINVAL]
Uso incorrecto de la función. Probablemente se llamó antes que pidfile_open().

La función pidfile_write() también puede fallar y establecer errno para cualquier error especificado para las llamadas fstat(2), ftruncate(2) y write(2).

La función pidfile_close() puede fallar y establecer errno para cualquier error especificado para las llamadas close(2) y fstat(2).

La función pidfile_remove() fallará si:

[EINVAL]
Uso incorrecto de la función. Probablemente llamado no por el proceso que hizo pidfile_write().

La función pidfile_remove() también puede fallar y establecer errno para cualquier error especificado para las llamadas close(2), fstat(2), write(2) y unlink(2).

man pidfile(3bsd)

NAME

pidfile, pidfile_open, pidfile_write, pidfile_close, pidfile_remove, pidfile_fileno ― create and manage PID files

LIBRARY

Supporting library libbsd

Derived from the NetBSD base system.

SYNOPSIS

#include <bsd/bsd.h>

pidfile_t *
pidfile_open(const char *path, mode_t mode, const char *daemon_name);

int
pidfile_write(pidfile_t *pidf);

int
pidfile_close(pidfile_t *pidf);

int
pidfile_remove(pidfile_t *pidf);

int
pidfile_fileno(pidfile_t *pidf);

DESCRIPTION

A PID file is a file created by a daemon process containing its process ID (PID). This allows other processes to find the daemon and to check if it is running.

The pidfile functions provide an easy way to create and manage PID files. They handle locking the PID file, writing the PID, and removing the PID file upon daemon termination.

The pidfile_open() function creates a new PID file. The path argument is the path to the PID file. The mode argument is the file mode for the PID file, which is used when creating the file. The daemon_name argument is an optional name for the daemon, which is used for logging purposes. If the PID file already exists and is locked by another process, pidfile_open() will fail.

The pidfile_write() function writes the current process ID to the PID file. This function should be called after the daemon has successfully started.

The pidfile_close() function closes the PID file and removes it. This function should be called when the daemon is terminating.

The pidfile_remove() function removes the PID file. This function is similar to pidfile_close() but does not close the file descriptor.

The pidfile_fileno() function returns the file descriptor associated with the PID file. This can be useful for using the PID file with other functions, such as read(2) or write(2).

RETURN VALUES

Upon success, pidfile_open() returns a pointer to a pidfile_t structure. Otherwise, it returns NULL and sets errno to indicate the error.

The functions pidfile_write(), pidfile_close(), pidfile_remove() and pidfile_fileno() return 0 on success, or -1 on error.

EXAMPLES

The following example shows how to use the pidfile functions to create a PID file for a daemon:

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <bsd/bsd.h>

int
main(void) {
        pidfile_t *pidf;

        pidf = pidfile_open("/var/run/mydaemon.pid", 0644, "mydaemon");
        if (pidf == NULL) {
                fprintf(stderr, "Failed to open PID file: %s\n", strerror(errno));
                return 1;
        }

        if (pidfile_write(pidf) == -1) {
                fprintf(stderr, "Failed to write PID to file: %s\n", strerror(errno));
                pidfile_close(pidf);
                return 1;
        }

        // Daemon code goes here

        pidfile_close(pidf);
        return 0;
}

ERRORS

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() may fail and set errno as follows:

[EACCES]
The PID file could not be created because of insufficient permissions.
[EEXIST]
The PID file already exists and is locked by another process.
[EINTR]
A signal interrupted the function before any data was transmitted.
[EINVAL]
Improper function use. For example, a NULL pidf argument was passed.
[EMFILE]
Too many file descriptors are open.
[ENAMETOOLONG]
The specified path name is too long.
[ENOENT]
A component of the path prefix does not exist, or the path prefix specified a directory where a file is to be created.
[ENOMEM]
Insufficient kernel memory was available.
[ENOSPC]
The directory or file system is full.
[ENOTDIR]
A component of the path prefix is not a directory.
[EPERM]
Operation not permitted. The calling process does not have permission to create the file in the specified directory.

The function pidfile_fileno() will fail if:

[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().

SEE ALSO

open(2), daemon(3), flopen(3bsd)

HISTORY

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() first appeared in FreeBSD 5.5.

The function pidfile_fileno() first appeared in FreeBSD 10.0.
