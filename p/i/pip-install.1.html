NOMBRE

pip-install - descripción del comando pip install

DESCRIPCIÓN

Instala paquetes desde:

  • PyPI (y otros índices) usando especificadores de requisitos.
  • URLs de proyectos VCS.
  • Directorios de proyectos locales.
  • Archivos fuente locales o remotos.

pip también soporta la instalación desde "archivos de requisitos", los cuales proporcionan una forma sencilla de especificar un entorno completo que debe ser instalado.

USO

python -m pip install [opciones] <especificador de requisito> [opciones-del-índice-de-paquetes] ...
python -m pip install [opciones] -r <archivo de requisitos> [opciones-del-índice-de-paquetes] ...
python -m pip install [opciones] [-e] <url-proyecto-vcs> ...
python -m pip install [opciones] [-e] <ruta-proyecto-local> ...
python -m pip install [opciones] <url/ruta-archivo> ...

OPCIONES

-r, --requirement <archivo>
Instala desde el archivo de requisitos dado. Esta opción se puede usar múltiples veces.

(variable de entorno: PIP_REQUIREMENT)

-c, --constraint <archivo>
Restringe las versiones usando el archivo de restricciones dado. Esta opción se puede usar múltiples veces.

(variable de entorno: PIP_CONSTRAINT)

--build-constraint <archivo>
Restringe las dependencias de compilación usando el archivo de restricciones dado. Esta opción se puede usar múltiples veces.

(variable de entorno: PIP_BUILD_CONSTRAINT)

--no-deps
No instales las dependencias del paquete.

(variable de entorno: PIP_NO_DEPS, PIP_NO_DEPENDENCIES)

--pre
Incluye versiones pre-release y de desarrollo. Por defecto, pip solo encuentra versiones estables.

(variable de entorno: PIP_PRE)

-e, --editable <ruta/url>
Instala un proyecto en modo editable (es decir, modo "develop" de setuptools) desde una ruta de proyecto local o una URL VCS.

(variable de entorno: PIP_EDITABLE)

--dry-run
No instales nada en realidad, solo imprime lo que se haría. Se puede usar en combinación con --ignore-installed para "resolver" los requisitos.

(variable de entorno: PIP_DRY_RUN)

-t, --target <dir>
Instala paquetes en <dir>. Por defecto, esto no reemplazará los archivos/carpetas existentes en <dir>. Usa --upgrade para reemplazar paquetes existentes en <dir> con nuevas versiones.

(variable de entorno: PIP_TARGET)

--platform <plataforma>
Solo usa wheels compatibles con <plataforma>. Por defecto es la plataforma del sistema en ejecución. Usa esta opción múltiples veces para especificar múltiples plataformas compatibles con el intérprete de destino.

(variable de entorno: PIP_PLATFORM)

--python-version <version-python>
La versión del intérprete de Python a usar para las verificaciones de compatibilidad de wheels y "Requires-Python". Por defecto es una versión derivada del intérprete en ejecución. La versión se puede especificar usando hasta tres enteros separados por puntos (por ejemplo, "3" para 3.0.0, "3.7" para 3.7.0, o "3.7.3"). Una versión mayor-menor también se puede dar como una cadena sin puntos (por ejemplo, "37" para 3.7.0).

(variable de entorno: PIP_PYTHON_VERSION)

--implementation <implementacion>
Solo usa wheels compatibles con la implementación de Python <implementacion>, por ejemplo, 'pp', 'jy', 'cp', o 'ip'. Si no se especifica, se utiliza la implementación del intérprete actual. Usa 'py' para forzar wheels independientes de la implementación.

(variable de entorno: PIP_IMPLEMENTATION)

--abi <abi>
Solo usa wheels compatibles con el abi de Python <abi>, por ejemplo, 'pypy_41'. Si no se especifica, se utiliza la etiqueta abi del intérprete actual. Usa esta opción múltiples veces para especificar múltiples abis compatibles con el intérprete de destino. Generalmente necesitarás especificar --implementation, --platform, y --python-version al usar esta opción.

(variable de entorno: PIP_ABI)

--user
Instala en el directorio de instalación de usuario de Python para tu plataforma. Típicamente ~/.local/, o %APPDATA%Python en Windows. (Ver la documentación de Python para site.USER_BASE para detalles completos).

(variable de entorno: PIP_USER)

--root <dir>
Instala todo relativo a este directorio raíz alternativo.

(variable de entorno: PIP_ROOT)

--prefix <dir>
Prefijo de instalación donde se colocan las carpetas lib, bin y otras carpetas de nivel superior. Ten en cuenta que la instalación resultante puede contener scripts y otros recursos que hagan referencia al intérprete de Python de pip, y no al del --prefix. Ver también la opción --python si la intención es instalar paquetes en otro entorno (posiblemente sin pip).

(variable de entorno: PIP_PREFIX)

--src <dir>
Directorio donde se descargarán los proyectos editables. El valor por defecto en un entorno virtual es "<<ruta-venv>/src". El valor por defecto para instalaciones globales es "<<directorio-actual>/src".

(variable de entorno: PIP_SRC, PIP_SOURCE, PIP_SOURCE_DIR, PIP_SOURCE_DIRECTORY)

-U, --upgrade
Actualiza todos los paquetes especificados a la versión más reciente disponible. El manejo de dependencias depende de la estrategia de actualización utilizada.

(variable de entorno: PIP_UPGRADE)

--upgrade-strategy <estrategia-actualización>
Determina cómo se deben manejar las actualizaciones de dependencias [default: only-if-needed]. "eager" - las dependencias se actualizan independientemente de si la versión instalada actualmente satisface los requisitos del paquete(s) actualizado(s). "only-if-needed" - se actualizan solo cuando no satisfacen los requisitos del paquete(s) actualizado(s).

(variable de entorno: PIP_UPGRADE_STRATEGY)

--force-reinstall
Reinstala todos los paquetes incluso si ya están actualizados.

(variable de entorno: PIP_FORCE_REINSTALL)

-I, --ignore-installed
Ignora los paquetes instalados, sobrescribiéndolos. ¡Esto puede dañar tu sistema si el paquete existente es de una versión diferente o se instaló con un gestor de paquetes diferente!

(variable de entorno: PIP_I

OPTIONS

--ignore-installed
Ignore the set of installed packages; install anyway.

(environment variable: PIP_IGNORE_INSTALLED)

--ignore-requires-python
Ignora la información de Requires-Python.

(environment variable: PIP_IGNORE_REQUIRES_PYTHON)

--no-build-isolation
Desactiva el aislamiento al construir una distribución fuente moderna. Las dependencias de compilación especificadas por PEP 518 deben estar ya instaladas si se utiliza esta opción.

(environment variable: PIP_NO_BUILD_ISOLATION)

--check-build-dependencies
Verifica las dependencias de compilación.

(environment variable: PIP_CHECK_BUILD_DEPENDENCIES)

--break-system-packages
Permite a pip modificar una instalación de Python gestionada externamente.

(environment variable: PIP_BREAK_SYSTEM_PACKAGES)

-C, --config-settings <settings>
Configuración que se pasará al backend de compilación. La configuración tiene el formato CLAVE=VALOR. Utiliza múltiples opciones --config-settings para pasar múltiples claves al backend.

(environment variable: PIP_CONFIG_SETTINGS)

--compile
Compila los archivos fuente de Python a bytecode.

(environment variable: PIP_COMPILE)

--no-compile
No compila los archivos fuente de Python a bytecode.

(environment variable: PIP_NO_COMPILE)

--no-warn-script-location
No emite advertencias al instalar scripts fuera de PATH.

(environment variable: PIP_NO_WARN_SCRIPT_LOCATION)

--no-warn-conflicts
No emite advertencias sobre dependencias rotas.

(environment variable: PIP_NO_WARN_CONFLICTS)

--no-binary <format_control>
No utiliza paquetes binarios. Se puede suministrar varias veces, y cada vez se añade al valor existente. Acepta ":all:" para deshabilitar todos los paquetes binarios, ":none:" para vaciar el conjunto (nota los dos puntos), o uno o más nombres de paquetes separados por comas (sin dos puntos). Ten en cuenta que algunos paquetes son difíciles de compilar y pueden fallar al instalarse cuando se utiliza esta opción.

(environment variable: PIP_NO_BINARY)

--only-binary <format_control>
No utiliza paquetes fuente. Se puede suministrar varias veces, y cada vez se añade al valor existente. Acepta ":all:" para deshabilitar todos los paquetes fuente, ":none:" para vaciar el conjunto, o uno o más nombres de paquetes separados por comas. Los paquetes sin distribuciones binarias fallarán al instalarse cuando se utilice esta opción.

(environment variable: PIP_ONLY_BINARY)

--prefer-binary
Prefiere paquetes binarios sobre paquetes fuente, incluso si los paquetes fuente son más recientes.

(environment variable: PIP_PREFER_BINARY)

--require-hashes
Requiere un hash para verificar cada requisito, para instalaciones repetibles. Esta opción se implica cuando cualquier paquete en un archivo de requisitos tiene una opción --hash.

(environment variable: PIP_REQUIRE_HASHES)

--progress-bar <progress_bar>
Especifica si se debe usar la barra de progreso. En modo 'auto', --quiet suprimirá todas las barras de progreso. [auto, on, off, raw] (por defecto: auto)

(environment variable: PIP_PROGRESS_BAR)

--root-user-action <root_user_action>
Acción si pip se ejecuta como usuario root [warn, ignore] (por defecto: warn)

(environment variable: PIP_ROOT_USER_ACTION)

--report <file>
Genera un archivo JSON que describe lo que pip hizo para instalar los requisitos proporcionados. Se puede usar en combinación con --dry-run e --ignore-installed para 'resolver' los requisitos. Cuando se usa - como nombre de archivo, escribe en stdout. Al escribir en stdout, por favor combínalo con la opción --quiet para evitar mezclar la salida de registro de pip con la salida JSON.

(environment variable: PIP_REPORT)

--group <[path:]group>
Instala un grupo de dependencias con nombre de un archivo "pyproject.toml". Si se proporciona una ruta, el nombre del archivo debe ser "pyproject.toml". Por defecto, utiliza "pyproject.toml" en el directorio actual.

(environment variable: PIP_GROUP)

--no-clean
No limpies los directorios de compilación.

(environment variable: PIP_NO_CLEAN)
