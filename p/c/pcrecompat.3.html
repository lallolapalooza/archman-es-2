PCRECOMPAT(3) Manual de Funciones de Biblioteca PCRECOMPAT(3)

NOMBRE

PCRE - expresiones regulares compatibles con Perl

DIFERENCIAS ENTRE PCRE Y PERL

Este documento describe las diferencias en la forma en que PCRE y Perl manejan las expresiones regulares. Las diferencias descritas aquí se refieren a las versiones 5.10 y superiores de Perl.

1. PCRE tiene solo un subconjunto del soporte Unicode de Perl. Los detalles de lo que sí tiene se dan en la página pcreunicode.

2. PCRE permite cuantificadores de repetición solo en aserciones entre paréntesis, pero no significan lo que podrías pensar. Por ejemplo, (?!a){3} no afirma que los siguientes tres caracteres no sean "a". Solo afirma que el siguiente carácter no es "a" tres veces (en principio: PCRE optimiza esto para ejecutar la aserción solo una vez). Perl permite cuantificadores de repetición en otras aserciones como \b, pero estas no parecen tener ningún uso.

3. Los subpatrones de captura que ocurren dentro de aserciones de lookahead negativo se cuentan, pero sus entradas en el vector de offsets nunca se establecen. Perl a veces (pero no siempre) establece sus variables numéricas desde dentro de aserciones negativas.

4. Aunque los caracteres de cero binario son compatibles en la cadena sujeto, no están permitidos en una cadena de patrón porque se pasa como una cadena C normal, terminada por cero. La secuencia de escape \0 se puede usar en el patrón para representar un cero binario.

5. Las siguientes secuencias de escape de Perl no son compatibles: \l, \u, \L, \U y \N cuando van seguidas de un nombre de carácter o valor Unicode. (\N por sí solo, que coincide con un carácter que no es de nueva línea, es compatible.) De hecho, estas son implementadas por el manejo general de cadenas de Perl y no forman parte de su motor de coincidencia de patrones. Si PCRE encuentra alguna de estas, se genera un error por defecto. Sin embargo, si se establece la opción PCRE_JAVASCRIPT_COMPAT, \U y \u se interpretan como los interpreta JavaScript.

6. Las secuencias de escape de Perl \p, \P y \X solo son compatibles si PCRE se compila con soporte de propiedades de caracteres Unicode. Las propiedades que se pueden probar con \p y \P se limitan a las propiedades de categoría general como Lu y Nd, nombres de scripts como Greek o Han, y las propiedades derivadas Any y L&. PCRE soporta la propiedad Cs (surrogate), que Perl no soporta; la documentación de Perl dice "Debido a que Perl oculta la necesidad del usuario de comprender la representación interna de los caracteres Unicode, no hay necesidad de implementar el concepto algo confuso de los surrogates."

7. PCRE soporta la secuencia de escape \Q...\E para citar subcadenas. Los caracteres intermedios se tratan como literales. Esto es ligeramente diferente de Perl en que $ y @ también se manejan como literales dentro de las comillas. En Perl, causan interpolación de variables (pero por supuesto, PCRE no tiene variables). Tenga en cuenta los siguientes ejemplos:

\Qabc$xyz\E abc$xyz abc seguido del
contenido de $xyz
\Qabc\$xyz\E abc\$xyz abc\$xyz
\Qabc\E\$\Qxyz\E abc$xyz abc$xyz

La secuencia \Q...\E se reconoce tanto dentro como fuera de las clases de caracteres.

8. Bastante obvio, PCRE no soporta las construcciones ({code}) y (??{code}). Sin embargo, hay soporte para patrones recursivos. Esto no está disponible en Perl 5.8, pero sí en Perl 5.10. Además, la característica de "llamada" de PCRE permite llamar a una función externa durante la coincidencia de patrones. Consulte la documentación de pcrecallout para obtener detalles.

9. Los subpatrones que se llaman como subrutinas (ya sea recursivamente o no) siempre se tratan como grupos atómicos en PCRE. Esto es similar a Python, pero diferente a Perl. Los valores capturados que se establecen fuera de una llamada a subrutina pueden ser referenciados desde dentro en PCRE, pero no en Perl. Hay una discusión que explica estas diferencias con más detalle en la sección sobre diferencias de recursión con respecto a Perl en la página pcrepattern.

10. Si se utilizan verbos de control de retroceso en un subpatrón que se llama como subrutina (ya sea recursivamente o no), su efecto se limita a ese subpatrón; no se extiende al patrón circundante. Este no es siempre el caso en Perl. En particular, si (*THEN) está presente en un grupo que se llama como subrutina, su acción se limita a ese grupo, incluso si el grupo no contiene ningún carácter |. Tenga en cuenta que tales subpatrones se procesan como anclados en el punto donde se prueban.

11. Si un patrón contiene más de un verbo de control de retroceso, el primero sobre el que se retrocede actúa. Por ejemplo, en el patrón A(*COMMIT)B(*PRUNE)C, un fallo en B activa (*COMMIT), pero un fallo en C activa (*PRUNE). El comportamiento de Perl es más complejo; en muchos casos es el mismo que PCRE, pero hay ejemplos en los que difiere.

12. La mayoría de los verbos de retroceso en las aserciones tienen sus acciones normales. No se limitan a la aserción.

13. Hay algunas diferencias relacionadas con la configuración de cadenas capturadas cuando parte de un patrón se repite. Por ejemplo, coincidir "aba" con el patrón /^(a(b)?)+$/ en Perl deja $2 sin establecer, pero en PCRE se establece en "b".

14. El manejo de números de subpatrón duplicados y nombres de subpatrón duplicados de PCRE no es tan general como el de Perl. Esto es una consecuencia del hecho de que PCRE funciona internamente solo con números, utilizando una tabla externa para traducir entre números y nombres. En particular, un patrón como (?|(?<a>A)|(?<b>B), donde los dos paréntesis de captura tienen el mismo número pero nombres diferentes, no es compatible y causa un error en tiempo de compilación. Si se permitiera, no sería posible distinguir qué paréntesis coincidieron, ya que ambos nombres mapean al subpatrón de captura número 1. Para evitar esta situación confusa, se produce un error en tiempo de compilación.

15. Perl reconoce comentarios en algunos lugares que PCRE no reconoce, por ejemplo, entre el ( y el ? al principio de un subpatrón. Si se establece el modificador /x, Perl permite espacios en blanco entre ( y ? (aunque las versiones actuales de Perl advierten que esto está obsoleto), pero PCRE nunca lo hace, incluso si la opción PCRE_EXTENDED está establecida.

16. Perl, cuando está en modo de advertencia, emite advertencias para clases de caracteres como [A-\d] o [a-[:digit:]]. Luego trata los guiones como literales. PCRE no tiene características de advertencia, por lo que genera un error en estos casos porque casi con seguridad son errores del usuario.

17. En PCRE, las propiedades de caracteres de mayúsculas/minúsculas Lu y Ll no se ven afectadas cuando se especifica coincidencia sin distinción entre mayúsculas y minúsculas. Por ejemplo, \p{Lu} siempre coincide con una letra mayúscula. Creo que Perl ha cambiado en este aspecto; en la versión en el momento de escribir esto (5.16), \p{Lu} y \p{Ll} coinciden con todas las letras, independientemente de las mayúsculas/minúsculas, cuando se especifica la independencia de mayúsculas/minúsculas.

18. PCRE proporciona algunas extensiones a las facilidades de expresiones regulares de Perl. Perl 5.10 incluye nuevas características que no están en versiones anteriores de Perl, algunas de las cuales (como paréntesis con nombre) han estado en PCRE durante algún tiempo. Esta lista se refiere a Perl 5.10:

(a) Aunque las aserciones de lookbehind en PCRE deben coincidir con cadenas de longitud fija, cada rama alternativa de una aserción de lookbehind puede coincidir con una longitud de cadena diferente. Perl requiere que todas tengan la misma longitud.

(b) Si se establece PCRE_DOLLAR_ENDONLY y no se establece PCRE_MULTILINE, el metacaracter $ solo coincide al final de la cadena.

(c) Si se establece PCRE_EXTRA, una barra invertida seguida de una letra sin significado especial genera un error. De lo contrario, al igual que Perl, la barra invertida se ignora silenciosamente. (Perl puede generar una advertencia).

(d) Si se establece PCRE_UNGREEDY, la codicia de los cuantificadores de repetición se invierte, es decir, por defecto no son codiciosos, pero si van seguidos de un signo de interrogación, lo son.

(e) PCRE_ANCHORED se puede usar en el momento de la coincidencia para forzar que un patrón se pruebe solo en la primera posición de coincidencia en la cadena sujeto.

(f) Las opciones PCRE_NOTBOL, PCRE_NOTEOL, PCRE_NOTEMPTY, PCRE_NOTEMPTY_ATSTART y PCRE_NO_AUTO_CAPTURE para pcre_exec() no tienen equivalentes en Perl.

pcrecompat(3) - PCRE Perl Compatible Regular Expressions

NAME

pcrecompat - PCRE Perl Compatible Regular Expressions

DIFFERENCES BETWEEN PCRE AND PERL

This document describes the differences between the PCRE library and Perl regular expressions.

Perl regular expressions are implemented in the Perl scripting language. PCRE is a set of C functions that implement a regular expression parser and "matcher" using the same, or very similar, syntax and semantics as Perl.

In the absence of a specific instruction to the contrary, PCRE syntax and semantics are identical to Perl's. The differences are detailed below.

It is strongly recommended that you do not rely on these differences. They are documented here because you might encounter them when reading Perl code that uses regular expressions, or because they are historical artifacts. The PCRE project has made a great effort to ensure that PCRE matches Perl as closely as possible, and the goal is to have complete compatibility.

1. Backslash in character sets

In Perl, a backslash character followed by a character that is not a Perl metacharacter is treated as a literal character. For example, the regex [\.] matches a literal dot. However, in PCRE, a backslash followed by a character that does not have a special meaning in that context is treated as an error. If you want to match a literal character in a character set, you should use it without a backslash, e.g. [.].

2. Verbose mode

Perl's verbose mode is activated by the /x modifier. PCRE supports this modifier. Within verbose mode, whitespace is ignored, and characters starting with # are ignored up to the end of the line. The PCRE documentation says that PCRE behaves identically to Perl in verbose mode, except that PCRE does not support the /xx modifier, which allows more whitespace characters (e.g. those that are part of octal or hexadecimal escapes) to be treated literally.

3. Possessive quantifiers

Perl supports possessive quantifiers, e.g. (?>...)*, which are never undone. PCRE also supports possessive quantifiers.

4. Recursion

Perl supports recursion in regular expressions using the (?R) or (?0) constructs. PCRE also supports recursion.

5. Conditional expressions

Perl supports conditional regular expressions of the form (?(condition)yes-pattern|no-pattern). PCRE also supports conditional regular expressions.

6. Lookbehind

Perl supports variable length lookbehind assertions. PCRE supports only fixed length lookbehind assertions.

7. Unicode properties

Perl supports Unicode properties, e.g. \p{Property}. PCRE also supports Unicode properties.

8. Duplicate named subpatterns

Perl allows duplicate names for subpatterns, e.g. (?<name>...) (?<name>...). PCRE does not allow duplicate names for subpatterns.

9. Recursion with named subpatterns

Perl supports recursion with named subpatterns using (?<name>...). PCRE also supports this syntax.

10. Floating point numbers in quantifiers

Perl supports floating point numbers in quantifiers, e.g. (1.5). PCRE does not support floating point numbers in quantifiers.

11. Case-insensitive matching

Perl's /i modifier matches ASCII letters case-insensitively. PCRE's /i modifier matches Unicode letters case-insensitively by default. This can be changed by setting the PCRE_UCP option.

12. \C escape sequence

The \C escape sequence matches a single character, regardless of whether it is single-byte or multi-byte in UTF-8 mode. PCRE does not support the \C escape sequence.

13. Case-insensitive matching of non-alphanumeric characters

In Perl, the /i modifier affects only letters. In PCRE, the /i modifier affects only letters and numbers. This is a bug in PCRE that is unlikely to be fixed.

14. POSIX character classes

Perl supports POSIX character classes, e.g. [[:digit:]]. PCRE supports POSIX character classes.

15. Duplicate named capture groups

Perl allows duplicate names for capture groups, e.g. (?<foo>a) (?<foo>b). PCRE does not allow duplicate names for capture groups.

16. Exhaustive matching

Perl supports exhaustive matching, e.g. /A/gx. PCRE does not support exhaustive matching.

17. Recursion depth limit

Perl has a recursion depth limit of 100000000 by default. PCRE has a recursion depth limit of 10000000 by default. This can be changed by the PCRE_DEPTH_LIMIT option.

18. Atomic grouping

Perl supports atomic grouping, e.g. (?>...). PCRE also supports atomic grouping.

19. Subroutine calls

Perl supports subroutine calls, e.g. (?&name). PCRE also supports subroutine calls.

20. Unknown escapes

In Perl, unknown escape sequences are treated as literal characters. In PCRE, unknown escape sequences are treated as errors.

21. \R in UTF-8 mode

In Perl, \R matches any Unicode newline sequence. In PCRE, \R matches any Unicode newline sequence, except for vertical tab (VT).

22. Nested conditional expressions

Perl supports nested conditional expressions. PCRE also supports nested conditional expressions.

23. Unicode properties in character sets

Perl supports Unicode properties in character sets, e.g. [\p{digit}]. PCRE also supports Unicode properties in character sets.

24. Duplicate named capture groups with different cases

Perl allows duplicate named capture groups with different cases, e.g. (?<foo>a) (?<FOO>b). PCRE does not allow duplicate named capture groups with different cases.

25. \P{...} escapes

Perl supports \P{...} escapes for negation of Unicode properties. PCRE also supports \P{...} escapes.

26. Case-insensitive matching of \W and \w

In Perl, \W and \w are not affected by the /i modifier. In PCRE, \W and \w are affected by the /i modifier.

27. Unicode properties in character sets with negation

Perl supports Unicode properties in character sets with negation, e.g. [^\p{digit}]. PCRE also supports Unicode properties in character sets with negation.

Perl supports variable length lookbehind assertions. PCRE does not support variable length lookbehind assertions.
