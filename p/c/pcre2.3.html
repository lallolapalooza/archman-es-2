PCRE2(3) Manual de Funciones de Biblioteca PCRE2(3)

NOMBRE

PCRE2 - expresiones regulares compatibles con Perl (API revisada)

INTRODUCCIÓN

PCRE2 es el nombre utilizado para una API revisada de la biblioteca PCRE, que es un conjunto de funciones, escritas en C, que implementan la coincidencia de patrones de expresiones regulares utilizando la misma sintaxis y semántica que Perl, con solo unas pocas diferencias. Después de casi dos décadas, las limitaciones de la API original dificultaban cada vez más el desarrollo. La nueva API es más extensible y se simplificó al abolir la función de optimización de "estudio" separada; en PCRE2, los patrones se optimizan automáticamente siempre que es posible. Desde que se bifurcó de PCRE1, el código se ha refactorizado extensamente y se han introducido nuevas características. La antigua biblioteca ahora es obsoleta y ya no se mantiene.

Además de los patrones de expresiones regulares al estilo Perl, hay disponibles características que aparecieron en Python y en el PCRE original antes de aparecer en Perl, utilizando la sintaxis de Python. También hay soporte para algunos elementos de sintaxis de .NET y Oniguruma, y hay opciones para solicitar cambios menores que mejoren la compatibilidad con ECMAScript (JavaScript).

El código fuente de PCRE2 puede compilarse para soportar cadenas de unidades de código de 8 bits, 16 bits o 32 bits, lo que significa que pueden instalarse hasta tres bibliotecas separadas, una para cada tamaño de unidad de código. El tamaño de una unidad de código no está relacionado con el tamaño en bits del hardware subyacente. En un entorno de 64 bits que también soporta aplicaciones de 32 bits, pueden ser necesarias versiones de PCRE2 compiladas en modo de 64 y 32 bits.

El trabajo original para extender PCRE a unidades de código de 16 y 32 bits fue realizado por Zoltan Herczeg y Christian Persch, respectivamente. En los tres casos, las cadenas pueden interpretarse como un carácter por unidad de código, o como Unicode codificado en UTF, con soporte para propiedades de categoría general de Unicode. El soporte de Unicode es opcional en tiempo de compilación (pero es el predeterminado). Sin embargo, el procesamiento de cadenas como unidades de código UTF debe habilitarse explícitamente en tiempo de ejecución. La versión de Unicode en uso se puede descubrir ejecutando


pcre2test -C

Las tres bibliotecas contienen conjuntos idénticos de funciones, con nombres que terminan en _8, _16 o _32, respectivamente (por ejemplo, pcre2_compile_8()). Sin embargo, definiendo PCRE2_CODE_UNIT_WIDTH a 8, 16 o 32, un programa que usa un solo ancho de unidad de código puede ser escrito usando nombres genéricos como pcre2_compile(), y la documentación está escrita asumiendo que este es el caso.

Además de la función de coincidencia compatible con Perl, PCRE2 contiene una función alternativa que coincide con los mismos patrones compilados de una manera diferente. En ciertas circunstancias, la función alternativa tiene algunas ventajas. Para una discusión de los dos algoritmos de coincidencia, consulte la página pcre2matching.

Los detalles de qué características de expresiones regulares de Perl son y no son soportadas por PCRE2 se dan en documentos separados. Vea las páginas pcre2pattern y pcre2compat. Hay un resumen de sintaxis en la página pcre2syntax.

Algunas características de PCRE2 pueden incluirse, excluirse o cambiarse al compilar la biblioteca. La función pcre2_config() permite a un cliente descubrir qué características están disponibles. Las características en sí se describen en la página pcre2build. La documentación sobre la compilación de PCRE2 para varios sistemas operativos se puede encontrar en los archivos README y NON-AUTOTOOLS-BUILD en la distribución fuente.

Las bibliotecas contienen una serie de funciones y tablas de datos internas no documentadas que son utilizadas por más de una de las funciones externas exportadas, pero que no están destinadas a ser utilizadas por llamantes externos. Sus nombres comienzan todos con "_pcre2", lo que esperanzadoramente no provocará ningún conflicto de nombres. En algunos entornos, es posible controlar qué símbolos externos se exportan al compilar una biblioteca compartida, y en estos casos, los símbolos no documentados no se exportan.

CONSIDERACIONES DE SEGURIDAD

Si está utilizando PCRE2 en una aplicación no UTF que permite a los usuarios proporcionar patrones arbitrarios para su compilación, debe ser consciente de una característica que permite a los usuarios activar el soporte UTF desde dentro de un patrón. Por ejemplo, un patrón de 8 bits que comienza con "(*UTF)" activa el modo UTF, que interpreta los patrones y los sujetos como cadenas de unidades de código UTF-8 en lugar de caracteres individuales de 8 bits. Esto hace que tanto el patrón como cualquier dato contra el que coincida se verifiquen para la validez UTF-8. Si la cadena de datos es muy larga, dicha verificación podría consumir suficientes recursos como para que su aplicación pierda rendimiento.

Una forma de protegerse contra esta posibilidad es utilizar la función pcre2_pattern_info() para verificar las opciones del patrón compilado para PCRE2_UTF. Alternativamente, puede establecer la opción PCRE2_NEVER_UTF al llamar a pcre2_compile(). Esto causa un error en tiempo de compilación si el patrón contiene una secuencia de configuración UTF.

El uso de propiedades Unicode para tipos de caracteres como \d también se puede habilitar desde dentro del patrón, especificando "(*UCP)". Esta característica puede ser deshabilitada estableciendo la opción PCRE2_NEVER_UCP.

Si su aplicación es una que soporta UTF, tenga en cuenta que la verificación de validez puede llevar tiempo. Si la misma cadena de datos se va a hacer coincidir muchas veces, puede utilizar la opción PCRE2_NO_UTF_CHECK para la segunda y posteriores coincidencias para evitar ejecutar verificaciones redundantes.

El uso de la secuencia de escape \C en un patrón UTF-8 o UTF-16 puede llevar a problemas, ya que puede dejar el punto de coincidencia actual en el medio de un carácter de múltiples unidades de código. La opción PCRE2_NEVER_BACKSLASH_C puede ser utilizada por una aplicación para bloquear el uso de \C, causando un error de compilación si se encuentra. También es posible compilar PCRE2 con el uso de \C permanentemente deshabilitado.

Otra forma en que se puede ver afectado el rendimiento es ejecutando un patrón que tiene un árbol de búsqueda muy grande contra una cadena que nunca coincidirá. Las repeticiones ilimitadas anidadas en un patrón son un ejemplo común. PCRE2 proporciona cierta protección contra esto: consulte la función pcre2_set_match_limit() en la página pcre2api. Hay una función similar llamada pcre2_set_depth_limit() que se puede utilizar para restringir la cantidad de memoria que se utiliza.

pcre2(3) - PCRE2, Perl-compatible regular expressions, library API

NAME

pcre2 - PCRE2, Perl-compatible regular expressions, library API

INTRODUCTION

The PCRE2 library is a set of functions that implement Perl-compatible regular expressions. It is a new version of the PCRE library, and it is not backward-compatible with PCRE 1. For information about PCRE 1, see the pcre(3) manual page.

PCRE2 supports many Perl regular expression features, including:

  • Character classes
  • Predefined character classes
  • Anchors
  • Assertions
  • Substitutions
  • Capturing groups
  • Non-capturing groups
  • Lookahead and lookbehind assertions
  • Possessive quantifiers
  • Recursion
  • Subroutine calls
  • And more.

PCRE2 is written in C and is designed to be used by C programs. It can also be used by other programming languages through bindings.

SECURITY CONSIDERATIONS

PCRE2 is a powerful tool that can be used to validate user input and perform text processing. However, it can also be used to create regular expressions that are computationally expensive, potentially leading to denial-of-service attacks. It is important to be aware of these risks and to take steps to mitigate them when using PCRE2.

The following are some common security considerations when using PCRE2:

  • Regular expression complexity: Complex regular expressions can be computationally expensive to evaluate. This can lead to denial-of-service attacks where an attacker submits input that causes the regular expression engine to consume excessive CPU time.
  • Denial-of-service attacks: Attackers may try to exploit vulnerabilities in the PCRE2 library to cause denial-of-service attacks. It is important to keep PCRE2 updated to the latest version to ensure that you have the latest security patches.
  • Input validation: Always validate user input before passing it to PCRE2. This can help prevent attackers from exploiting vulnerabilities in the library.
  • Resource limits: Set resource limits on the amount of CPU time and memory that PCRE2 can use. This can help prevent denial-of-service attacks.
  • Error handling: Implement robust error handling to catch and handle any errors that may occur when using PCRE2. This can help prevent unexpected behavior and potential security vulnerabilities.

USER DOCUMENTATION

The PCRE2 library comes with a comprehensive set of documentation that is available in HTML and plain text formats. The documentation can be found in the /usr/share/doc/pcre2/ directory.

The main documentation file is pcre2.html (or pcre2.txt for plain text). It provides a detailed overview of the PCRE2 library, including its features, functions, and usage examples.

In addition to the main documentation, there are also separate manual pages for each PCRE2 function. These manual pages can be accessed using the man command, for example, man pcre2_compile.

For more information about PCRE2, you can also visit the official PCRE2 website: https://www.pcre.org/

AUTHORS

The PCRE2 library was written by Philip Hazel. Additional contributions have been made by the PCRE2 community. For a detailed list of contributors, please refer to the AUTHORS file in the PCRE2 source code distribution.

You can find more information about PCRE2 and its development on the PCRE2 project page: https://github.com/PCRE2Project/pcre2
