NOMBRE

pcre2test - un programa para probar expresiones regulares compatibles con Perl.

SINOPSIS

pcre2test [opciones] [archivo de entrada [archivo de salida]]

pcre2test es un programa de prueba para las bibliotecas de expresiones regulares PCRE2, pero también se puede usar para experimentar con expresiones regulares. Este documento describe las características del programa de prueba; para obtener detalles sobre las expresiones regulares en sí, consulte la documentación de pcre2pattern. Para obtener detalles sobre las llamadas a las funciones de la biblioteca PCRE2 y sus opciones, consulte la documentación de pcre2api.

La entrada para pcre2test es una secuencia de patrones de expresiones regulares y cadenas sujeto para ser emparejadas. También hay líneas de comando para establecer valores predeterminados y controlar algunas acciones especiales. La salida muestra el resultado de cada intento de coincidencia. Los modificadores en las líneas de comando externas o internas, los patrones y las líneas sujeto especifican las opciones de la función PCRE2, controlan cómo se procesa el sujeto y qué salida se produce.

Existen muchos modificadores oscuros, algunos de los cuales están diseñados específicamente para su uso junto con el script de prueba y los archivos de datos que se distribuyen como parte de PCRE2. Todos los modificadores se documentan aquí, algunos sin mucha justificación, pero muchos de ellos probablemente no serán útiles excepto al probar las bibliotecas.

BIBLIOTECAS DE 8-BIT, 16-BIT Y 32-BIT DE PCRE2

Se pueden compilar diferentes versiones de la biblioteca PCRE2 para admitir cadenas de caracteres codificadas en unidades de código de 8 bits, 16 bits o 32 bits. Se pueden instalar una, dos o las tres bibliotecas simultáneamente. El programa pcre2test se puede usar para probar todas las bibliotecas. Sin embargo, su propia entrada y salida siempre están en formato de 8 bits. Al probar las bibliotecas de 16 bits o 32 bits, los patrones y las cadenas sujeto se convierten a formato de 16 bits o 32 bits antes de pasarlos a las funciones de la biblioteca. Los resultados se vuelven a convertir a unidades de código de 8 bits para la salida.

En el resto de este documento, los nombres de las funciones y estructuras de la biblioteca se dan en forma genérica, por ejemplo, pcre2_compile(). Los nombres reales utilizados en las bibliotecas tienen un sufijo _8, _16 o _32, según corresponda.

CODIFICACIÓN DE ENTRADA

La entrada a pcre2test se procesa línea por línea, ya sea llamando a la función fgets() de la biblioteca C, o a través de la biblioteca libreadline o libedit. En algunos entornos Windows, el carácter 26 (hex 1A) provoca un fin de archivo inmediato y no se leen más datos, por lo que se debe evitar este carácter a menos que realmente se desee esa acción.

La entrada se procesa utilizando las funciones de cadena de C, por lo que no debe contener ceros binarios, aunque en entornos similares a Unix, fgets() trata cualquier byte que no sea una nueva línea como caracteres de datos. Se genera un error si se encuentra un cero binario. Por defecto, las líneas sujeto se procesan para buscar escapes de barra invertida, lo que hace posible incluir cualquier valor de dato en las cadenas que se pasan a la biblioteca para emparejar. Para los patrones, existe una facilidad para especificar algunos o todos los caracteres de entrada de 8 bits como pares hexadecimales, lo que hace posible incluir ceros binarios.

Entrada para las bibliotecas de 16-bit y 32-bit

Al probar las bibliotecas de 16 bits o 32 bits, es necesario poder generar puntos de código de caracteres mayores que 255 en las cadenas que se pasan a la biblioteca. Para las líneas sujeto y algunos patrones, se pueden usar secuencias de escape de barra invertida. Además, cuando se establece el modificador utf (ver "Establecimiento de opciones de compilación" a continuación), el patrón y las líneas sujeto siguientes se interpretan como cadenas UTF-8 y se traducen a UTF-16 o UTF-32 según corresponda.

Para pruebas que no sean UTF de caracteres anchos, se puede usar el modificador utf8_input. Este es mutuamente excluyente con utf y solo se permite en modo de 16 bits o 32 bits. Hace que el patrón y las líneas sujeto siguientes se traten como UTF-8 según la definición original (RFC 2279), que permite valores de caracteres de hasta 0x7fffffff. Cada carácter se coloca en una unidad de código de 16 bits o 32 bits (en el caso de 16 bits, los valores mayores que 0xffff provocan un error).

UTF-8 (en su definición original) no es capaz de codificar valores mayores que 0x7fffffff, pero tales valores pueden ser manejados por la biblioteca de 32 bits. Al probar esta biblioteca en modo no UTF con utf8_input activado, si algún carácter está precedido por el byte 0xff (que es un byte inválido en UTF-8), se agregan 0x80000000 al valor del carácter. Para las cadenas sujeto, es preferible usar una secuencia de escape.

OPCIONES DE LÍNEA DE COMANDOS

-8
Si la biblioteca de 8 bits se ha compilado, esta opción hace que se use (este es el valor predeterminado). Si la biblioteca de 8 bits no se ha compilado, esta opción provoca un error.
-16
Si la biblioteca de 16 bits se ha compilado, esta opción hace que se use. Si la biblioteca de 8 bits no se ha compilado, este es el valor predeterminado. Si la biblioteca de 16 bits no se ha compilado, esta opción provoca un error.
-32
Si la biblioteca de 32 bits se ha compilado, esta opción hace que se use. Si no se ha compilado ninguna otra biblioteca, este es el valor predeterminado. Si la biblioteca de 32 bits no se ha compilado, esta opción provoca un error.
-ac
Comportarse como si cada patrón tuviera el modificador auto_callout, es decir, insertar llamadas automáticas en cada patrón que se compila.
-AC
Al igual que -ac, pero además comportarse como si cada línea sujeto tuviera el modificador callout_extra, es decir, mostrar información adicional de las llamadas.
-b
Comportarse como si cada patrón tuviera el modificador fullbincode; se genera la forma binaria interna completa del patrón después de la compilación.
-C
Mostrar el número de versión de la biblioteca PCRE2, y toda la información disponible sobre las características opcionales incluidas, y luego salir con código de salida cero. Todas las demás opciones se ignoran. Si están presentes tanto -C como -LM, se reconoce la que aparezca primero.
-C opción
Mostrar información sobre una opción específica de tiempo de compilación, y luego salir. Esta funcionalidad está destinada a ser utilizada en scripts como RunTest. Las siguientes opciones muestran el valor y establecen el código de salida como se indica:


linksize el tamaño interno de enlace configurado (2, 3 o 4)
el código de salida se establece en el tamaño del enlace
newline la configuración predeterminada de nueva línea:
CR, LF, CRLF, ANYCRLF, ANY o NUL
el código de salida es siempre 0
bsr la configuración predeterminada para lo que coincide \R:
ANYCRLF o ANY
el código de salida es siempre 0

Las siguientes opciones muestran 1 para verdadero o 0 para falso, y establecen el código de salida al mismo valor:


backslash-C se admite \C (no está bloqueado)
ebcdic compilado para un entorno EBCDIC
ebcdic-io si PCRE2 está compilado para EBCDIC, si la entrada y salida de pcre2test
es EBCDIC o ASCII
ebcdic-nl25 si PCRE2 está compilado para EBCDIC, si NL (= LF) es 0x25
(de lo contrario es 0x15, el predeterminado)
jit el soporte just-in-time está disponible
pcre2-16 se compiló la biblioteca de 16 bits
pcre2-32 se compiló la biblioteca de 32 bits
pcre2-8 se compiló la biblioteca de 8 bits
unicode el soporte Unicode está disponible

Tenga en cuenta que la disponibilidad del soporte JIT en la biblioteca no garantiza que pueda ser utilizado, ya que en algunos entornos es incapaz de asignar memoria ejecutable. La opción "jitusable" proporciona información más detallada. Devuelve uno de los siguientes valores:


0 JIT está disponible y es utilizable
1 JIT está disponible pero no puede asignar memoria ejecutable
2 JIT no está disponible
3 Retorno inesperado de la llamada de prueba a pcre2_jit_compile()

Si se proporciona una opción desconocida, se muestra un mensaje de error; el código de salida es 0.

--colour=siempre|automático|nunca, --color=siempre|automático|nunca
Controla la coloración de la salida. El valor predeterminado es automático si la salida es a una terminal y nunca de lo contrario. El valor siempre produce color incluso si la salida no es a una terminal (por ejemplo, si se canaliza a un archivo). El valor automático usa color solo si la salida es a una terminal. El valor nunca deshabilita la coloración.
-d
Comportarse como si cada patrón tuviera el modificador debug, es decir, la salida de depuración se genera para cada patrón compilado.
-e
En el modo de línea de comandos, se procesa la entrada de forma más rápida y sin tantos mensajes de depuración que de otro modo se producirían.

Comportarse como si cada patrón tuviera el modificador escape_cr, es decir, los finales de línea en la cadena sujeto se tratan como \r.

-G
Generar la salida de la opción list_groups. Se imprime una lista de todos los grupos de captura que se encuentran en el patrón. Cada grupo se identifica por su número y por su nombre (si se le dio uno).
-g
Comportarse como si cada patrón tuviera el modificador grp_tab, es decir, la salida de coincidencia se genera en forma de tabla de grupos.
-H
Comportarse como si cada patrón tuviera el modificador start_end, es decir, para cada coincidencia, se imprimen las posiciones inicial y final de la subcadena coincidente.
-h
Comportarse como si cada patrón tuviera el modificador alt_lengths, es decir, se muestra la longitud mínima y máxima de cada coincidencia.
-I
Comportarse como si cada patrón tuviera el modificador match_limit, es decir, se permite que el número de pasos de recursión y de bucle para cada coincidencia sea de un valor configurable en tiempo de ejecución. El valor se establece mediante la opción -M.
-i
Comportarse como si cada patrón tuviera el modificador icase, es decir, se ignora la distinción entre mayúsculas y minúsculas en los caracteres.
-J
Comportarse como si cada patrón tuviera el modificador use_pcre8, es decir, se utiliza la versión de 8 bits de las bibliotecas.
-j
Comportarse como si cada patrón tuviera el modificador use_cpp, es decir, se utiliza la interfaz C++ de las bibliotecas.
-k
Comportarse como si cada patrón tuviera el modificador copy_name_groups, es decir, se copian los nombres de los grupos de captura en la tabla de nombres de grupos.
-L
Imprimir una lista de todas las opciones de compilación y todas las características opcionales que están disponibles en la biblioteca PCRE2, y luego salir. Todas las demás opciones se ignoran.
-LM
Imprimir una lista de todas las características opcionales que están disponibles en la biblioteca PCRE2, y luego salir. Todas las demás opciones se ignoran. Si están presentes tanto -C como -LM, se reconoce la que aparezca primero.
-m
Comportarse como si cada patrón tuviera el modificador multiline, es decir, los anclas ^ y $ coinciden al principio y al final de cada línea dentro de la cadena, respectivamente.
-M num
Establece el límite de coincidencias para el modificador match_limit en el valor num. El valor predeterminado es 10000000.
-N
Comportarse como si cada patrón tuviera el modificador newline_auto, es decir, el tipo de fin de línea se detecta automáticamente a partir de la entrada. Si no se proporciona esta opción, se supone que los finales de línea son CR o CRLF.
-n
Comportarse como si cada patrón tuviera el modificador newline_crlf, es decir, los finales de línea CR y LF se tratan como caracteres de nueva línea.
-O
Comportarse como si cada patrón tuviera el modificador optimize, es decir, se aplica una optimización para acelerar la coincidencia.
-o
Comportarse como si cada patrón tuviera el modificador ungreedy, es decir, los cuantificadores se vuelven no codiciosos.
-P
Comportarse como si cada patrón tuviera el modificador partial, es decir, las coincidencias parciales se permiten si la cadena sujeto no contiene una coincidencia completa.
-p
Comportarse como si cada patrón tuviera el modificador partial_capture, es decir, las subcadenas de captura se obtienen incluso si no coinciden completamente.
-Q
Comportarse como si cada patrón tuviera el modificador caseless, es decir, se ignora la distinción entre mayúsculas y minúsculas en los caracteres.
-q
Comportarse como si cada patrón tuviera el modificador extra, es decir, se genera información adicional para cada coincidencia.
-R
Comportarse como si cada patrón tuviera el modificador recursive, es decir, se permite la recursión en patrones que contienen recursión.
-r
Comportarse como si cada patrón tuviera el modificador dotall, es decir, el carácter punto (.) coincide también con los finales de línea.
-S
Comportarse como si cada patrón tuviera el modificador study, es decir, se realiza un análisis adicional del patrón para acelerar la coincidencia.
-s
Comportarse como si cada patrón tuviera el modificador subproprietary, es decir, se permite el uso de sintaxis no estándar.
-T
Comportarse como si cada patrón tuviera el modificador utf, es decir, las cadenas se tratan como secuencias de caracteres UTF-8. Esto solo funciona si la biblioteca se ha compilado con soporte Unicode.
-t
Comportarse como si cada patrón tuviera el modificador utf8_input, es decir, las cadenas se tratan como secuencias de caracteres UTF-8 en su forma original (RFC 2279). Esto solo funciona si la biblioteca se ha compilado con soporte Unicode.
-V
Comportarse como si cada patrón tuviera el modificador dollar_endall, es decir, el ancla $ coincide al final de la cadena, incluso si no es precedido por un final de línea.
-v
Comportarse como si cada patrón tuviera el modificador notail, es decir, no se calcula la longitud de la subcadena coincidente.
-W
Comportarse como si cada patrón tuviera el modificador newline_any, es decir, se permite cualquier secuencia de fin de línea.
-w
Comportarse como si cada patrón tuviera el modificador long_names, es decir, se permite el uso de nombres largos para grupos de captura.
-X
Comportarse como si cada patrón tuviera el modificador posix, es decir, se utiliza la sintaxis POSIX para las clases de caracteres.
-x
Comportarse como si cada patrón tuviera el modificador no_utf8_checked, es decir, no se realiza la comprobación de validez de UTF-8. Esto solo funciona si la biblioteca se ha compilado con soporte Unicode.
-Y
Comportarse como si cada patrón tuviera el modificador newline_anycrlf, es decir, CR, LF y CRLF se tratan como finales de línea.
-y
Comportarse como si cada patrón tuviera el modificador anchors, es decir, se permite el uso de anclas en patrones que contienen recursión.
-z
Comportarse como si cada patrón tuviera el modificador no_utf8_compile, es decir, no se realiza la compilación de UTF-8. Esto solo funciona si la biblioteca se ha compilado con soporte Unicode.

EL FORMATO DE ENTRADA

La entrada a pcre2test consiste en una secuencia de líneas. Las líneas que no comienzan con un modificador o una barra invertida se tratan como patrones o cadenas sujeto. Las líneas que comienzan con un modificador comienzan con una barra invertida seguida de una o más letras. Los modificadores se aplican a todos los patrones o cadenas siguientes hasta que se cambien o hasta que termine la entrada.

Una línea que comienza con `\` seguido de una letra, seguida de un espacio, se trata como una línea de comando.

Una línea que comienza con `\` seguido de una letra, que no está seguida de un espacio, se trata como una línea de patrón o sujeto. Los modificadores de línea se aplican a los patrones y las cadenas sujeto.

Una línea vacía se ignora.

Una línea que comienza con `#!` se trata como un comentario.

Una línea que comienza con `$=` se trata como una línea de comando.

Una línea que comienza con `$=num` establece el valor de la variable `num` en el valor que sigue. Las variables se pueden usar en patrones y cadenas sujeto.

Una línea que comienza con `$=pattern` establece el patrón de búsqueda predeterminado. Si se encuentran coincidencias, se informan.

Una línea que comienza con `$=subject` establece la cadena sujeto predeterminada.

Una línea que comienza con `$=options` establece las opciones de compilación predeterminadas.

Una línea que comienza con `$=print` imprime el valor de la variable especificada.

Una línea que comienza con `$=quit` sale del programa.

Una línea que comienza con `$=test` ejecuta una prueba.

Una línea que comienza con `$=verbose` alterna el modo detallado.

Una línea que comienza con `$=version` imprime la versión de la biblioteca PCRE2.

Una línea que comienza con `$=write` escribe la cadena especificada en el archivo de salida.

Líneas de patrón y sujeto

Una línea de patrón o sujeto comienza con un carácter que no sea `\` o `=`. El primer carácter se trata como el delimitador de la expresión regular o la cadena sujeto. Los caracteres posteriores se procesan hasta que se encuentra el delimitador correspondiente. Si se encuentra una barra invertida, se procesa una secuencia de escape.

Los caracteres de escape válidos incluyen:

\a
Carácter de alerta (ASCII 7)
\b
Retroceso (ASCII 8)
\e
Escape (ASCII 27)
\f
Avance de página (ASCII 12)
\n
Nueva línea (ASCII 10)
\r
Retorno de carro (ASCII 13)
\t
Tabulación (ASCII 9)
\v
Tabulación vertical (ASCII 11)
\xHH
Carácter hexadecimal con valor HH
\OOOO
Carácter octal con valor OOO
\n
El carácter n
\\
Barra invertida literal

Los modificadores de línea se pueden especificar antes del patrón o la cadena sujeto. Por ejemplo:

\i/foo/i

Esto compila el patrón `/foo/` con el modificador `icase` (ignorar mayúsculas/minúsculas).

EJEMPLOS

Aquí hay algunos ejemplos de uso de pcre2test:

Ejecutar una simple coincidencia:

pcre2test -p'/abc/' -s'abc'

Esto coincidirá con la cadena `abc`.

Usar el modificador `i` (ignorar mayúsculas/minúsculas):

pcre2test -p'/abc/i' -s'ABC'

Esto coincidirá con la cadena `ABC`.

Usar el modificador `m` (multilínea):

pcre2test -p'/^abc$/m' -s"abc\ndef"

Esto coincidirá con la cadena `abc` en la primera línea.

Usar el modificador `x` (espacio en blanco ignorado):

pcre2test -p'/a b c/x' -s'abc'

Esto coincidirá con la cadena `abc`.

Usar el modificador `g` (grupos):

pcre2test -p'/(\w+)\s+(\w+)/g' -s'Hola Mundo'

Esto encontrará dos grupos: `Hola` y `Mundo`.

Usar el modificador `F` (información completa):

pcre2test -p'/(\w+)\s+(\w+)/F' -s'Hola Mundo'

Esto mostrará información completa sobre las coincidencias encontradas.

Usar el modificador `S` (estudio):

pcre2test -p'/(\w+)\s+(\w+)/S' -s'Hola Mundo'

Esto analizará el patrón para acelerar las coincidencias.

Usar el modificador `N` (automático de nueva línea):

pcre2test -p'/abc/N' -s'abc\r\ndef'

Esto coincidirá con la cadena `abc`.

Usar el modificador `T` (UTF-8):

pcre2test -p'/[\p{L}]+/T' -s'你好世界'

Esto coincidirá con la cadena `你好世界`.

Usar el modificador `t` (entrada UTF-8):

pcre2test -p'/abc/t' -s'abc'

Esto tratará la entrada como UTF-8.

Usar el modificador `J` (biblioteca de 8 bits):

pcre2test -p'/abc/' -s'abc' -J

Esto utilizará la biblioteca de 8 bits.

Usar el modificador `j` (interfaz C++):

pcre2test -p'/abc/' -s'abc' -j

Esto utilizará la interfaz C++.

Usar el modificador `b` (código binario completo):

pcre2test -p'/abc/' -s'abc' -b

Esto imprimirá el código binario interno del patrón.

Usar el modificador `d` (depurar):

pcre2test -p'/abc/' -s'abc' -d

Esto generará información de depuración para el patrón.

Usar el modificador `o` (no codicioso):

pcre2test -p'/a*?/' -s'aaaa'

Esto coincidirá con cadenas vacías de forma no codiciosa.

Usar el modificador `P` (parcial):

pcre2test -p'/abc/P' -s'ab'

Esto permitirá una coincidencia parcial.

Usar el modificador `Q` (sin distinción mayúsculas/minúsculas):

pcre2test -p'/abc/Q' -s'ABC'

Esto coincidirá con la cadena `ABC`.

Usar el modificador `R` (recursivo):

pcre2test -p'/(a|b)+R/' -s'abab'

Esto permitirá la recursión en el patrón.

Usar el modificador `r` (dotall):

pcre2test -p'/a.b/r' -s'a\nb'

Esto coincidirá con la cadena `a` seguida de un salto de línea y luego `b`.

Usar el modificador `X` (POSIX):

pcre2test -p'/[[:digit:]]+/' -s'12345'

Esto coincidirá con la cadena `12345`.

Usar el modificador `Y` (anycrlf):

pcre2test -p'/abc/Y' -s'abc\r\ndef'

Esto coincidirá con la cadena `abc`.

Usar el modificador `y` (anclas):

pcre2test -p'/(a(b))+y/' -s'ababa'

Esto permitirá el uso de anclas en patrones recursivos.

Usar el modificador `z` (no compilar UTF-8):

pcre2test -p'/abc/z' -s'abc'

Esto deshabilitará la compilación de UTF-8.

Los efectos de estos modificadores se describen en las siguientes secciones.

Manejo de nueva línea y \R

El modificador bsr especifica qué debe coincidir \R en un patrón. Si se establece en "anycrlf", \R coincide solo con CR, LF o CRLF. Si se establece en "unicode", \R coincide con cualquier secuencia de nueva línea Unicode. El valor predeterminado se puede especificar al compilar PCRE2; si no se hace, el valor predeterminado se establece en Unicode.

El modificador newline especifica qué caracteres se deben interpretar como nuevas líneas, tanto en el patrón como en las líneas sujeto. El tipo debe ser uno de CR, LF, CRLF, ANYCRLF, ANY o NUL (en mayúsculas o minúsculas).

Información sobre un patrón

El modificador debug es una abreviatura de info,fullbincode, que solicita toda la información disponible.

El modificador bincode hace que se muestre una representación del código compilado después de la compilación. Esta información no contiene valores de longitud y desplazamiento, lo que garantiza que se genere la misma salida para diferentes tamaños de enlace internos y diferentes anchos de unidad de código. Al usar bincode, se pueden usar las mismas pruebas de regresión en diferentes entornos.

El modificador fullbincode, por el contrario, *sí* incluye valores de longitud y desplazamiento. Esto se utiliza en algunas pruebas especiales que solo se ejecutan para anchos de unidad de código y tamaños de enlace específicos, y también es útil para pruebas únicas.

El modificador info solicita información sobre el patrón compilado (si está anclado, tiene un primer carácter fijo, etc.). La información se obtiene de la función pcre2_pattern_info(). Aquí hay algunos ejemplos típicos:


re> /(?i)(^a|^b)/m,info

Opciones generales: sin distinción entre mayúsculas y minúsculas, multilínea

re> /(?i)abc/info

"Opciones de compilación" son las especificadas por modificadores; "opciones generales" tienen opciones añadidas que se toman o deducen del patrón. Si ambos conjuntos de opciones son los mismos, solo se muestra una línea de "opciones"; si no hay opciones, la línea se omite. "Primera unidad de código" es donde debe comenzar cualquier coincidencia; si hay más de una, se enumeran como "unidades de código iniciales". "Última unidad de código" es la última unidad de código literal que debe estar presente en cualquier coincidencia. Esta no es necesariamente el último carácter. Estas líneas se omiten si no se registran unidades de código iniciales o finales. La línea de longitud del sujeto se omite cuando se establece no_start_optimize porque la longitud mínima no se calcula cuando nunca se puede usar.

El modificador framesize muestra el tamaño, en bytes, de cada marco de almacenamiento utilizado por pcre2_match() para manejar el backtracking. El tamaño depende del número de paréntesis de captura en el patrón. Se utiliza un vector de estos marcos en el momento de la coincidencia; su tamaño general se muestra cuando se establece el modificador de sujeto heaframes_size.

El modificador callout_info solicita información sobre todos los callouts del patrón. Se muestra una lista de ellos al final de cualquier otra información solicitada. Para cada callout, se da su número o cadena, seguido del elemento que le sigue en el patrón.

Pasando un contexto NULO

Normalmente, pcre2test pasa un bloque de contexto a pcre2_compile(). Sin embargo, si se establece el modificador null_context, se pasa NULL. Esto es para probar que pcre2_compile() se comporta correctamente en este caso (utiliza valores predeterminados).

Pasando un patrón NULO

El modificador null_pattern es para probar el comportamiento de pcre2_compile() cuando el argumento del patrón es NULL. El valor de longitud pasado es el PCRE2_ZERO_TERMINATED predeterminado a menos que se establezca use_length. Cualquier longitud distinta de cero causa un error.

Especificando caracteres del patrón en hexadecimal

El modificador hex especifica que los caracteres del patrón, excepto las subcadenas entre comillas simples o dobles, deben interpretarse como pares de dígitos hexadecimales. Esta característica se proporciona como una forma de crear patrones que contienen ceros binarios y otros caracteres no imprimibles. Se permite espacio en blanco entre pares de dígitos. Por ejemplo, este patrón contiene tres caracteres:


/ab 32 59/hex

Las partes de dicho patrón se toman literalmente si están entre comillas. Este patrón contiene nueve caracteres, de los cuales solo dos se especifican en hexadecimal:


/ab "literal" 32/hex

Ya sea simple

Especificación de la longitud del patrón

Por defecto, los patrones se pasan a las funciones de compilación como cadenas terminadas en nulo, pero pueden pasarse por longitud en lugar de terminar en nulo. El modificador use_length provoca que esto suceda. El uso de una longitud ocurre automáticamente (independientemente de si hex está activado o no) cuando hex está activado, porque los patrones especificados en hexadecimal pueden contener ceros binarios.

Si se utiliza hex o use_length con la API de envoltura POSIX (consulte "Uso de la API de envoltura POSIX" a continuación), la extensión REG_PEND se utiliza para pasar la longitud del patrón.

Especificación de un máximo para búsquedas posteriores variables

Las afirmaciones de búsqueda posterior variables solo se admiten si, para cada una, hay una longitud máxima (en caracteres) que puede coincidir. Existe un límite para esto, cuyo valor predeterminado se puede establecer en el momento de la compilación, con un valor predeterminado final de 255. El modificador max_varlookbehind utiliza la función pcre2_set_max_varlookbehind() para cambiar el límite. Las búsquedas posteriores cuyas ramas coinciden con una longitud fija están limitadas a 65535 caracteres por rama.

Especificación de caracteres anchos en modos de 16 y 32 bits

En los modos de 16 y 32 bits, toda la entrada se trata automáticamente como UTF-8 y se traduce a UTF-16 o UTF-32 cuando se activa el modificador utf. Para probar las bibliotecas de 16 y 32 bits en modo no UTF, se puede usar el modificador utf8_input. Es mutuamente excluyente con utf. Las líneas de entrada se interpretan como UTF-8 como medio para especificar caracteres anchos. Se dan más detalles en "Codificación de entrada" arriba.

Generación de patrones largos y repetitivos

Algunas pruebas utilizan patrones largos que son muy repetitivos. En lugar de crear una línea de entrada muy larga para dicho patrón, puede usar una característica de repetición especial, similar a la descrita para las líneas de asunto anteriores. Si el modificador expand está presente en un patrón, las partes del patrón que tienen la forma


\[<caracteres>]{<contador>}

se expanden antes de que el patrón se pase a pcre2_compile(). Por ejemplo, \[AB]{6000} se expande a "ABAB..." 6000 veces. Esta construcción no se puede anidar. Una secuencia inicial "\[" solo se reconoce si se encuentra más adelante en el patrón "]{" seguido de dígitos decimales y "}". De lo contrario, los caracteres permanecen en el patrón sin modificar. Los modificadores expand y hex son mutuamente excluyentes.

Si parte de un patrón expandido parece una expansión, pero en realidad es parte del patrón real, se puede evitar la expansión no deseada proporcionando dos valores en el cuantificador. Por ejemplo, \[AB]{6000,6000} no se reconoce como un elemento de expansión.

Si el modificador info se activa en un patrón expandido, el resultado de la expansión se incluye en la información que se genera.

Compilación JIT

La compilación Just-In-Time (JIT) es una optimización pesada que puede acelerar enormemente la coincidencia de patrones. Consulte la documentación de pcre2jit para obtener detalles. La compilación JIT ocurre, opcionalmente, después de que un patrón se haya compilado con éxito en una forma interna. El compilador JIT lo convierte en código máquina optimizado. Necesita saber si se van a utilizar las opciones en tiempo de coincidencia PCRE2_PARTIAL_HARD y PCRE2_PARTIAL_SOFT, ya que se genera código diferente para los diferentes casos. Consulte el modificador partial en "Modificadores de asunto" a continuación para obtener detalles sobre cómo se especifican estas opciones para cada intento de coincidencia.

La compilación JIT se solicita mediante el modificador de patrón jit, que opcionalmente puede ir seguido de un signo igual y un número en el rango de 0 a 7. Los tres bits que componen el número especifican qué modos de operación JIT se van a compilar:


1 compilar código JIT para coincidencias no parciales
2 compilar código JIT para coincidencias parciales suaves
4 compilar código JIT para coincidencias parciales duras

Por lo tanto, los valores posibles para el modificador jit son:


0 deshabilitar JIT
1 solo coincidencias normales
2 solo coincidencias parciales suaves
3 coincidencias normales y parciales suaves
4 solo coincidencias parciales duras
6 solo coincidencias parciales suaves y duras
7 los tres modos

Si no se proporciona un número, se asume 7. La frase "coincidencia parcial" significa una llamada a pcre2_match() con la opción PCRE2_PARTIAL_SOFT o PCRE2_PARTIAL_HARD activada. Tenga en cuenta que dicha llamada puede devolver una coincidencia completa; las opciones permiten la posibilidad de una coincidencia parcial, pero no la exigen. Tenga en cuenta también que si solicita la compilación JIT solo para coincidencias parciales (por ejemplo, jit=2) pero no establece el modificador partial en una línea de asunto, esa coincidencia no utilizará código JIT porque no se compiló ninguno para coincidencias no parciales.

Si la compilación JIT es exitosa, el código JIT compilado se utilizará automáticamente cuando se ejecute un tipo de coincidencia apropiado, excepto cuando se especifiquen opciones en tiempo de ejecución incompatibles. Para obtener más detalles, consulte la documentación de pcre2jit. Consulte también el modificador jitstack a continuación para conocer una forma de establecer el tamaño de la pila JIT.

Si se especifica el modificador jitfast, la coincidencia se realiza utilizando la interfaz de "vía rápida" JIT, pcre2_jit_match(), que omite algunas de las comprobaciones de validez que realiza pcre2_match() y, por supuesto, no funciona cuando JIT no es compatible. Si se especifica jitfast sin jit, se asume jit=7.

Si se especifica el modificador jitverify, la información sobre el patrón compilado muestra si la compilación JIT fue exitosa o no. Si se especifica jitverify sin jit, se asume jit=7. Si la compilación JIT es exitosa cuando se activa jitverify, el texto "(JIT)" se agrega a la primera línea de salida después de una coincidencia o no coincidencia cuando se utilizó código compilado JIT en la coincidencia.

Establecer una configuración regional

El modificador locale debe especificar el nombre de una configuración regional, por ejemplo:


/patrón/locale=fr_FR

Se establece la configuración regional dada, se llama a pcre2_maketables() para construir un conjunto de tablas de caracteres para la configuración regional, y luego se pasa a pcre2_compile() al compilar la expresión regular. Las mismas tablas se utilizan al hacer coincidir las siguientes líneas de asunto. El modificador locale solo se aplica al patrón en el que aparece, pero se puede proporcionar en un comando #pattern si se necesita un valor predeterminado. Establecer una configuración regional y tablas de caracteres alternativas son mutuamente excluyentes.

Mostrar memoria del patrón

El modificador memory provoca que se genere el tamaño en bytes de la memoria utilizada para mantener el patrón compilado. Esto no incluye el tamaño del bloque pcre2_code; son solo los datos compilados reales. Si el patrón se pasa posteriormente al compilador JIT, también se genera el tamaño del código compilado JIT. Aquí hay un ejemplo:


re> /a(b)c/jit,memory
Asignación de memoria (espacio de código): 21
Asignación de memoria (código JIT): 1910

Limitar paréntesis anidados

El modificador parens_nest_limit establece un límite en la profundidad de los paréntesis anidados en un patrón. Superar el límite provoca un error de compilación. El valor predeterminado para la biblioteca se establece al compilar PCRE2, pero pcre2test establece su propio valor predeterminado de 220, que es necesario para ejecutar el conjunto de pruebas estándar.

Limitar la longitud del patrón

El modificador max_pattern_length establece un límite, en unidades de código, para la longitud del patrón que aceptará pcre2_compile(). Superar el límite provoca un error de compilación. El valor predeterminado es el número más grande que puede contener una variable PCRE2_SIZE (esencialmente ilimitado).

Limitar el tamaño de un patrón compilado

El modificador max_pattern_compiled_length establece un límite, en bytes, para la cantidad de memoria utilizada por un patrón compilado. Superar el límite provoca un error de compilación. El valor predeterminado es el número más grande que puede contener una variable PCRE2_SIZE (esencialmente ilimitado).

Cuando un patrón con el modificador push se compila correctamente, se inserta en una pila de patrones compilados, y pcre2test espera que la siguiente línea contenga un nuevo patrón (o un comando) en lugar de una línea de sujeto. Mostrando más texto

El modificador aftertext solicita que, además de mostrar la parte de la cadena del sujeto que coincidió con el patrón completo, pcre2test muestre además el resto de la cadena del sujeto. Esto es útil para pruebas en las que el sujeto contiene copias múltiples de la misma subcadena. El modificador allaftertext solicita la misma acción para las subcadenas capturadas, así como para la subcadena coincidente principal. En cada caso, el resto se muestra en la línea siguiente con un carácter de suma (+) después del número de captura.

El modificador allusedtext solicita que se muestre todo el texto que fue consultado durante una coincidencia de patrón exitosa por el intérprete, tanto para coincidencias completas como parciales. Esta función no es compatible con la coincidencia JIT, y si se solicita con JIT se ignora (con un mensaje de advertencia). Establecer este modificador afecta la salida si hay una aserción lookbehind al principio de una coincidencia, o, para una coincidencia completa, una lookahead al final, o si \K se usa en el patrón. Los caracteres que preceden o siguen el inicio y el final de la coincidencia real se indican en la salida con caracteres '<' o '>' debajo de ellos. Aquí hay un ejemplo:


re> /(?<=pqr)abc(?=xyz)/
data> 123pqrabcxyz456\=allusedtext
0: pqrabcxyz
<<< >>>
data> 123pqrabcxy\=ph,allusedtext
Coincidencia parcial: pqrabcxy
<<<

La primera coincidencia completa muestra que la cadena coincidente es "abc", y que las cadenas precedente y siguiente "pqr" y "xyz" fueron consultadas durante la coincidencia (al procesar las aserciones). La coincidencia parcial solo puede indicar la cadena precedente.

El modificador startchar solicita que se indique el carácter de inicio de la coincidencia, si es diferente de la cadena coincidente. La única vez que esto ocurre es cuando se ha procesado \K como parte de la coincidencia. En esta situación, la salida de la cadena coincidente se muestra desde el carácter de inicio en lugar del punto de coincidencia, con caracteres de circunflejo debajo de los caracteres anteriores. Por ejemplo:


re> /abc\Kxyz/
data> abcxyz\=startchar
0: abcxyz
^^^

A diferencia de allusedtext, el modificador startchar se puede usar con JIT. Sin embargo, estos dos modificadores son mutuamente exclusivos.

Mostrando el valor de todos los grupos de captura

El modificador allcaptures solicita que se muestren los valores de todos los paréntesis de captura potenciales después de una coincidencia. Por defecto, solo se muestran aquellos hasta el más alto utilizado efectivamente en la coincidencia (correspondiente al código de retorno de pcre2_match()). Los grupos que no participaron en la coincidencia se muestran como "<unset>". Este modificador no es relevante para la coincidencia DFA (que no realiza capturas) y no se aplica cuando se especifica replace; se ignora, con un mensaje de advertencia, si está presente.

Mostrando el ovector completo, para todos los resultados

El modificador allvector solicita que se muestre todo el ovector, independientemente del resultado de la coincidencia. Compare con allcaptures, que solo muestra hasta el número máximo de grupos de captura para el patrón, y luego solo para una coincidencia completa exitosa que no sea DFA. Este modificador, que actúa después de cualquier resultado de coincidencia, y también para la coincidencia DFA, proporciona un medio para verificar que no haya modificaciones inesperadas en los campos del ovector. Antes de cada intento de coincidencia, el ovector se rellena con un valor especial, y si este se encuentra en ambos elementos de un par de captura, se muestra "<unchanged>". Después de una coincidencia exitosa, esto se aplica a todos los grupos después del grupo de captura máximo para el patrón. En otros casos, se aplica a todo el ovector. Después de una coincidencia parcial, los dos primeros elementos son los únicos que deben establecerse. Después de una coincidencia DFA, la cantidad de ovector que se utiliza depende del número de coincidencias encontradas.

Probando llamadas de patrón

Se proporciona una función de llamada cuando pcre2test llama a las funciones de coincidencia de la biblioteca, a menos que se especifique callout_none. Su comportamiento puede controlarse mediante varios modificadores enumerados anteriormente cuyos nombres comienzan con callout_. Los detalles se dan en la sección titulada "Callouts" más abajo. Las llamadas de prueba desde pcre2_substitute() se describen por separado en "Testing the substitution function" más abajo.

Encontrando todas las coincidencias en una cadena

La búsqueda de todas las coincidencias posibles dentro de un sujeto se puede solicitar mediante el modificador global o altglobal. Después de encontrar una coincidencia, la función de coincidencia se vuelve a llamar para buscar en el resto del sujeto. La diferencia entre global y altglobal es que la primera utiliza el argumento start_offset de pcre2_match() o pcre2_dfa_match() para comenzar la búsqueda en un nuevo punto dentro de toda la cadena (que es lo que hace Perl), mientras que la segunda pasa por un sujeto acortado. Esto marca una diferencia en el proceso de coincidencia si el patrón comienza con una aserción lookbehind (incluyendo \b o \B).

Si se coincide con una cadena vacía, la siguiente coincidencia se realiza con el indicador PCRE2_NOTEMPTY_ATSTART establecido, para buscar otra coincidencia, no vacía, en el mismo punto del sujeto. Esto imita la forma en que Perl maneja tales casos cuando usa el modificador /g o la función split().

Probando las funciones de extracción de subcadenas

Los modificadores copy y get se pueden usar para probar las funciones pcre2_substring_copy_xxx() y pcre2_substring_get_xxx(). Se pueden especificar varias veces, y cada uno puede especificar un nombre o número de grupo de captura, por ejemplo:


abcd\=copy=1,copy=3,get=G1

Si el comando #subject se usa para establecer listas de copia y/o obtención predeterminadas, estas se pueden cancelar especificando un número negativo para cancelar todos los grupos numerados y un nombre vacío para cancelar todos los grupos con nombre.

El modificador getall prueba pcre2_substring_list_get(), que extrae todas las subcadenas capturadas.

Si la línea del sujeto coincide correctamente, las subcadenas extraídas por las funciones de conveniencia se muestran con C, G o L después del número de cadena en lugar de dos puntos. Esto es además de la lista completa normal. La longitud de la cadena (es decir, el retorno de la función de extracción) se indica entre paréntesis después de cada subcadena, seguido del nombre cuando la extracción fue por nombre.

Probando la función de sustitución

Si se establece el modificador replace, se llama a la función pcre2_substitute() en lugar de a una de las funciones de coincidencia (o después de una llamada a pcre2_match() en el caso de PCRE2_SUBSTITUTE_MATCHED). Tenga en cuenta que las cadenas de reemplazo no pueden contener comas, ya que una coma significa el final de un modificador. No se considera que esto sea un problema en un programa de prueba.

Especificar una cadena de reemplazo completamente vacía deshabilita este modificador. Sin embargo, es posible especificar un reemplazo vacío proporcionando una longitud de búfer, como se describe a continuación, para un reemplazo que de otro modo estaría vacío.

A diferencia de las cadenas de sujeto, pcre2test no procesa las cadenas de reemplazo para secuencias de escape. En modo UTF, se verifica si la cadena de reemplazo es una cadena UTF-8 válida. Si es así, se convierte correctamente a una cadena UTF de la anchura de unidad de código apropiada. Si no es una cadena UTF-8 válida, las unidades de código individuales se copian directamente. Esto proporciona un medio para pasar una cadena UTF-8 no válida con fines de prueba.

After a successful substitution, the modified string is output, preceded by the number of replacements. This may be zero if there were no matches. Here is a simple example of a substitution test:


/abc/replace=xxx
=abc=abc=
1: =xxx=abc=
=abc=abc=\=global
2: =xxx=xxx=

Subject and replacement strings should be kept relatively short (fewer than 256 characters) for substitution tests, as fixed-size buffers are used. To make it easy to test for buffer overflow, if the replacement string starts with a number in square brackets, that number is passed to pcre2_substitute() as the size of the output buffer, with the replacement string starting at the next character. Here is an example that tests the edge case:


/abc/
123abc123\=replace=[10]XYZ
1: 123XYZ123
123abc123\=replace=[9]XYZ
Failed: error -48: no more memory

The default action of pcre2_substitute() is to return PCRE2_ERROR_NOMEMORY when the output buffer is too small. However, if the PCRE2_SUBSTITUTE_OVERFLOW_LENGTH option is set (by using the substitute_overflow_length modifier), pcre2_substitute() continues to go through the motions of matching and substituting (but not doing any callouts), in order to compute the size of buffer that is required. When this happens, pcre2test shows the required buffer length (which includes space for the trailing zero) as part of the error message. For example:


/abc/substitute_overflow_length
123abc123\=replace=[9]XYZ
Failed: error -48: no more memory: 10 code units are needed

A replacement string is ignored with POSIX and DFA matching. Specifying partial matching provokes an error return ("bad option value") from pcre2_substitute().

The substitute_subject modifier may be used to test the use of the PCRE2 API, in which a client calls pcre2_match() followed by pcre2_substitute() with PCRE2_SUBSTITUTE_MATCHED, but the client performs an unexpected and unsupported modification of the subject buffer in-place, in between the match and substitution.

Testing substitute callouts

If the substitute_callout modifier is set, a substitution callout function is set up. The null_context modifier must not be set, because the address of the callout function is passed in a match context. When the callout function is called (after each substitution), details of the input and output strings are output. For example:


/abc/g,replace=<$0>,substitute_callout
abcdefabcpqr
1(1) Old 0 3 "abc" New 0 5 "<abc>"
2(1) Old 6 9 "abc" New 8 13 "<abc>"
2: <abc>def<abc>pqr

The first number on each callout line is the count of matches. The parenthesized number is the number of pairs that are set in the ovector (that is, one more than the number of capturing groups that were set). Then are listed the offsets of the old substring, its contents, and the same for the replacement.

By default, the substitution callout function returns zero, which accepts the replacement and causes matching to continue if /g was used. Two further modifiers can be used to test other return values. If substitute_skip is set to a value greater than zero the callout function returns +1 for the match of that number, and similarly substitute_stop returns -1. These cause the replacement to be rejected, and -1 causes no further matching to take place. If either of them are set, substitute_callout is assumed. For example:


/abc/g,replace=<$0>,substitute_skip=1
abcdefabcpqr
1(1) Old 0 3 "abc" New 0 5 "<abc> SKIPPED"
2(1) Old 6 9 "abc" New 6 11 "<abc>"
2: abcdef<abc>pqr
abcdefabcpqr\=substitute_stop=1
1(1) Old 0 3 "abc" New 0 5 "<abc> STOPPED"
1: abcdefabcpqr

If both are set for the same number, stop takes precedence. Only a single skip or stop is supported, which is sufficient for testing that the feature works.

Testing substitute case callouts

If the substitute_case_callout modifier is set, a substitution case callout function is set up. The callout function is called for each substituted chunk which is to be case-transformed.

The callout function passed is a fixed function with implementation for certain behaviours: inputs which shrink when case-transformed; inputs which grow; inputs with distinct upper/lower/titlecase forms. The characters which are not special-cased for testing purposes are left unmodified, as if they are caseless characters.

Setting the JIT stack size

The jitstack modifier provides a way of setting the maximum stack size that is used by the just-in-time optimization code. It is ignored if JIT optimization is not being used. The value is a number of kibibytes (units of 1024 bytes). Setting zero reverts to the default of 32KiB. Providing a stack that is larger than the default is necessary only for very complicated patterns. If jitstack is set non-zero on a subject line it overrides any value that was set on the pattern.

Setting heap, match, and depth limits

The heap_limit, match_limit, and depth_limit modifiers set the appropriate limits in the match context. These values are ignored when the find_limits or find_limits_noheap modifier is specified.

Finding minimum limits

If the find_limits modifier is present on a subject line, pcre2test calls the relevant matching function several times, setting different values in the match context via pcre2_set_heap_limit(), pcre2_set_match_limit(), or pcre2_set_depth_limit() until it finds the smallest value for each parameter that allows the match to complete without a "limit exceeded" error. The match itself may succeed or fail. An alternative modifier, find_limits_noheap, omits the heap limit. This is used in the standard tests, because the minimum heap limit varies between systems. If JIT is being used, only the match limit is relevant, and the other two are automatically omitted.

When using this modifier, the pattern should not contain any limit settings such as (*LIMIT_MATCH=...) within it. If such a setting is present and is lower than the minimum matching value, the minimum value cannot be found because pcre2_set_match_limit() etc. are only able to reduce the value of an in-pattern limit; they cannot increase it.

For non-DFA matching, the minimum depth_limit number is a measure of how much nested backtracking happens (that is, how deeply the pattern's tree is searched). In the case of DFA matching, depth_limit controls the depth of recursive calls of the internal function that is used for handling pattern recursion, lookaround assertions, and atomic groups.

For non-DFA matching, the match_limit number is a measure of the amount of backtracking that takes place, and learning the minimum value can be instructive. For most simple matches, the number is quite small, but for patterns with very large numbers of matching possibilities, it can become large very quickly with increasing length of subject string. In the case of DFA matching, match_limit controls the total number of calls, both recursive and non-recursive, to the internal matching function, thus controlling the overall amount of computing resource that is used.

For both kinds of matching, the heap_limit number, which is in kibibytes (units of 1024 bytes), limits the amount of heap memory used for matching.

Showing MARK names

The mark modifier causes the names from backtracking control verbs that are returned from calls to pcre2_match() to be displayed. If a mark is returned for a match, non-match, or partial match, pcre2test shows it. For a match, it is on a line by itself, tagged with "MK:". Otherwise, it is added to the non-match message.

Showing memory usage

The memory modifier causes pcre2test to log the sizes of all heap memory allocation and freeing calls that occur during a call to pcre2_match() or pcre2_dfa_match(). In the latter case, heap memory is used only when a match requires more internal workspace that the default allocation on the stack, so in many cases there will be no output. No heap memory is allocated during matching with JIT. For this modifier to work, the null_context modifier must not be set on both the pattern and the subject, though it can be set on one or the other.

Showing the heap frame overall vector size

The heapframes_size modifier is relevant for matches using pcre2_match() without JIT. After a match has run (whether successful or not) the size, in bytes, of the allocated heap frames vector that is left attached to the match data block is shown. If the matching action involved several calls to pcre2_match() (for example, global matching or for timing) only the final value is shown.

This modifier is ignored, with a warning, for POSIX or DFA matching. JIT matching does not use the heap frames vector, so the size is always zero, unless there was a previous non-JIT match. Note that specifing a size of zero for the output vector (see below) causes pcre2test to free its match data block (and associated heap frames vector) and allocate a new one.

Setting a starting offset

The offset_start=n modifier sets the starting offset for the match to n units. This is used when testing the matching of substrings.

Configuración de un desplazamiento inicial

El modificador offset establece un desplazamiento en la cadena sujeto donde comienza la coincidencia. Su valor es un número de unidades de código, no de caracteres.

Configuración de un límite de desplazamiento

El modificador offset_limit establece un límite para coincidencias no ancladas. Si no se puede encontrar una coincidencia comenzando en o antes de este desplazamiento en el sujeto, se devuelve una indicación de "sin coincidencia". El valor de los datos es un número de unidades de código, no de caracteres. Cuando se utiliza este modificador, el modificador use_offset_limit debe haber sido establecido para el patrón; de lo contrario, se genera un error.

Configuración del tamaño del vector de salida

El modificador ovector se aplica solo a la línea de sujeto en la que aparece, aunque por supuesto también se puede usar para establecer un valor predeterminado en un comando #subject. Especifica el número de pares de desplazamientos que están disponibles para almacenar información de coincidencia. El valor predeterminado es 15.

Un valor de cero es útil al probar la API POSIX porque hace que regexec() sea llamada con un vector de captura NULL. Cuando no se prueba la API POSIX, se usa un valor de cero para hacer que se llame a pcre2_match_data_create_from_pattern(), para crear un nuevo bloque de coincidencia del tamaño exacto para el patrón. (No es posible crear un bloque de coincidencia con un ovector de longitud cero; siempre hay al menos un par de desplazamientos.) Se libera el bloque de datos de coincidencia antiguo.

Paso del sujeto como terminado en cero

Por defecto, la cadena sujeto se pasa a una función de coincidencia de API nativa con su longitud correcta. Para probar la funcionalidad de pasar una cadena terminada en cero, se proporciona el modificador zero_terminate. Hace que la longitud se pase como PCRE2_ZERO_TERMINATED. Al coincidir a través de la interfaz POSIX, este modificador se ignora, con una advertencia.

Al probar pcre2_substitute(), este modificador también tiene el efecto de pasar la cadena de reemplazo como terminada en cero.

Paso de un contexto, sujeto o reemplazo NULL

Normalmente, pcre2test pasa un bloque de contexto a pcre2_match(), pcre2_dfa_match(), pcre2_jit_match() o pcre2_substitute(). Si se establece el modificador null_context, sin embargo, se pasa NULL. Esto es para probar que las funciones de coincidencia y sustitución se comportan correctamente en este caso (utilizan valores predeterminados). Este modificador no se puede usar con los modificadores find_limits, find_limits_noheap o substitute_callout.

De manera similar, con fines de prueba, si se establece el modificador null_subject o null_replacement, los punteros de cadena sujeto o reemplazo se pasan como NULL, respectivamente, a las funciones relevantes.

LA FUNCIÓN DE COINCIDENCIA ALTERNATIVA

Por defecto, pcre2test utiliza la función de coincidencia PCRE2 estándar, pcre2_match(), para hacer coincidir cada línea de sujeto. PCRE2 también admite una función de coincidencia alternativa, pcre2_dfa_match(), que opera de manera diferente y tiene algunas restricciones. Las diferencias entre las dos funciones se describen en la documentación pcre2matching.

Si se establece el modificador dfa, se utiliza la función de coincidencia alternativa. Esta función encuentra todas las coincidencias posibles en un punto dado del sujeto. Sin embargo, si se establece el modificador dfa_shortest, el procesamiento se detiene después de que se encuentra la primera coincidencia. Esta es siempre la coincidencia más corta posible.

SALIDA PREDETERMINADA DE pcre2test

Esta sección describe la salida cuando se está utilizando la función de coincidencia normal, pcre2_match().

Cuando una coincidencia tiene éxito, pcre2test muestra la lista de subcadenas capturadas, comenzando con el número 0 para la cadena que coincidió con el patrón completo. De lo contrario, muestra "No match" cuando el retorno es PCRE2_ERROR_NOMATCH, o "Partial match:" seguido de la subcadena que coincide parcialmente cuando el retorno es PCRE2_ERROR_PARTIAL. (Tenga en cuenta que esta es la subcadena completa que se inspeccionó durante la coincidencia parcial; puede incluir caracteres antes del inicio real de la coincidencia si participaron una aserción de mirada posterior, \K, \b o \B).

Para cualquier otro retorno, pcre2test muestra el número de error negativo de PCRE2 y una frase descriptiva corta. Si el error es una verificación fallida de cadena UTF, también se muestra el desplazamiento de la unidad de código del inicio del carácter fallido. Aquí hay un ejemplo de una ejecución interactiva de pcre2test.


$ pcre2test
PCRE2 version 10.22 2016-07-29


re> /^abc(\d+)/
data> abc123
0: abc123
1: 123
data> xyz
No match

Las subcadenas de captura no establecidas que no van seguidas de una establecida no son mostradas por pcre2test a menos que se especifique el modificador allcaptures. En el siguiente ejemplo, hay dos subcadenas de captura, pero cuando se hace coincidir la primera línea de datos, la segunda subcadena no establecida no se muestra. Una subcadena no establecida "interna" se muestra como "<unset>", como en la segunda línea de datos.


re> /(a)|(b)/
data> a
0: a
1: a
data> b
0: b
1: <unset>
2: b

Si las cadenas contienen caracteres no imprimibles, se muestran como escapes \xhh si el valor es menor que 256 y el modo UTF no está establecido. De lo contrario, se muestran como escapes \x{hh...}. Ver más abajo para la definición de caracteres no imprimibles. Si se establece el modificador aftertext, la salida para la subcadena 0 se sigue con el resto de la cadena sujeto, identificada por "0+" de esta manera:


re> /cat/aftertext
data> cataract
0: cat
0+ aract

Si se solicita coincidencia global, los resultados de los intentos de coincidencia sucesivos se muestran en secuencia, de esta manera:


re> /\Bi(\w\w)/g
data> Mississippi
0: iss
1: ss
0: iss
1: ss
0: ipp
1: pp

Solo se muestra "No match" si falla el primer intento de coincidencia. Aquí hay un ejemplo de un mensaje de error (el desplazamiento 4 que se especifica con el modificador offset está más allá del final de la cadena sujeto):


re> /xyz/
data> xyz\=offset=4
Error -24 (bad offset value)

Tenga en cuenta que mientras los patrones pueden continuar en varias líneas (se usa un prompt ">" simple para continuaciones), las líneas de sujeto no pueden. Sin embargo, se pueden incluir nuevas líneas en un sujeto por medio del escape \n (o \r, \r\n, etc., dependiendo de la configuración de la secuencia de nueva línea).

SALIDA DE LA FUNCIÓN DE COINCIDENCIA ALTERNATIVA

Cuando se utiliza la función de coincidencia alternativa, pcre2_dfa_match(), la salida consiste en una lista de todas las coincidencias que comienzan en el primer punto del sujeto donde hay al menos una coincidencia. Por ejemplo:


re> /(tang|tangerine|tan)/
data> yellow tangerine\=dfa
0: tangerine
1: tang
2: tan

Usar la función de coincidencia normal en estos datos solo encuentra "tang". La cadena de coincidencia más larga siempre se da primero (y se numera cero). Después de un retorno PCRE2_ERROR_PARTIAL, la salida es "Partial match:", seguido de la subcadena que coincide parcialmente. Tenga en cuenta que esta es la subcadena completa que se inspeccionó durante la coincidencia parcial; puede incluir caracteres antes del inicio real de la coincidencia si participaron una aserción de mirada posterior, \b o \B. (\K no es compatible con la coincidencia DFA).

Si se solicita coincidencia global, la búsqueda de coincidencias adicionales se reanuda al final de la coincidencia más larga. Por ejemplo:


re> /(tang|tangerine|tan)/g
data> yellow tangerine and tangy sultana\=dfa
0: tangerine
1: tang
2: tan
0: tang
1: tan
0: tan

La función de coincidencia alternativa no admite la captura de subcadenas, por lo que los modificadores relacionados con subcadenas capturadas no son relevantes.

REINICIAR DESPUÉS DE UNA COINCIDENCIA PARCIAL

Cuando la función de coincidencia alternativa ha devuelto PCRE2_ERROR_PARTIAL, indicando que el sujeto coincidió parcialmente con el patrón, puede reiniciar la coincidencia con datos adicionales del sujeto mediante el modificador dfa_restart. Por ejemplo:


re> /^\d?\d(jan|feb|mar|apr|may|jun|jul|aug|sep|oct|nov|dec)\d\d$/
data> 23ja\=ps,dfa
Partial match: 23ja
data> n05\=dfa,dfa_restart
0: n05

Para obtener más información sobre la coincidencia parcial, consulte la documentación pcre2partial.
