PCP2JSON(1) Manual de Comandos Generales PCP2JSON(1)

NOMBRE

pcp2json - exportador de métricas pcp-a-json

SINOPSIS

pcp2json [-5CEGHIjLmnrRvVxXz?] [-4 acción] [-8|-9 límite] [-a archivo] [-A alineación] [--archive-folio folio] [-b|-B escala-espacio] [-c config] [--container contenedor] [-D debug] [--daemonize] [-e derivada] [-f formato] [-F archivo-salida] [-h host] [-i instancias] [-J rango] [-K espec] [-N predicado] [-o tiempo-espera] [-O origen] [-p contraseña] [-P|-0 precisión] [-q|-Q escala-cuenta] [-s muestras] [-S tiempo-inicio] [-t intervalo] [-T tiempo-fin] [-u url] [-U usuario] [-y|-Y escala-tiempo] [-Z zona-horaria] espec-métrica [...]

DESCRIPCIÓN

pcp2json es una herramienta personalizable de exportación de métricas de rendimiento de PCP a JSON. Cualquier métrica de rendimiento disponible, en vivo o archivada, del sistema y/o de aplicaciones, puede ser seleccionada para exportar usando argumentos de línea de comandos o un archivo de configuración.

pcp2json es un pariente cercano de pmrep(1). Consulte pmrep(1) para la descripción de espec-métrica aceptada en la línea de comandos de pcp2json. Consulte pmrep.conf(5) para la descripción de la sintaxis del archivo de configuración pcp2json.conf. Esta página describe las opciones específicas de pcp2json y las diferencias del archivo de configuración con pmrep.conf(5). pmrep(1) también enumera algunos ejemplos de uso de los cuales la mayoría son aplicables con pcp2json también.

Solo se admiten las opciones de línea de comandos listadas en esta página; las otras opciones disponibles para pmrep(1) no son compatibles.

Las opciones a través de valores de entorno (ver pmGetOptions(3)) anulan los valores predeterminados incorporados correspondientes (si los hay). Las opciones del archivo de configuración anulan las variables de entorno correspondientes (si las hay). Las opciones de la línea de comandos anulan las opciones del archivo de configuración correspondientes (si las hay).

ARCHIVO DE CONFIGURACIÓN

pcp2json utiliza un archivo de configuración con sintaxis descrita en pmrep.conf(5). Las siguientes opciones son comunes con pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. El resto de las opciones de pmrep.conf son reconocidas pero ignoradas por compatibilidad.

opciones específicas de pcp2json

extended (booleano)

Escribe información extendida sobre las métricas. La opción de línea de comandos correspondiente es -x. Por defecto es no.

everything (booleano)

Escribe todo lo conocido sobre las métricas, incluyendo IDs internos de PCP. Las etiquetas se omiten para compatibilidad con versiones anteriores. Habilite include_labels para incluirlas también. La opción de línea de comandos correspondiente es -X. Por defecto es no.

exact_types (booleano)

Escribe números como tipos de datos numéricos, no como cadenas, perdiendo potencialmente algo de precisión. La opción de línea de comandos correspondiente es -E. Por defecto es no.

url (cadena)

Envía la salida JSON como un POST HTTP a la url dada. La opción de línea de comandos correspondiente es -u. Por defecto es None.

http_pass (cadena)

Usa la contraseña dada para Autenticación Básica al enviar un POST HTTP. La opción de línea de comandos correspondiente es -p. Por defecto es None.

http_user (cadena)

Usa el nombre de usuario dado para Autenticación Básica al enviar un POST HTTP. La opción de línea de comandos correspondiente es -U. Por defecto es None.

http_timeout (número)

Tiempo máximo (en segundos) al enviar un POST HTTP. La opción de línea de comandos correspondiente es -o. Por defecto son 2.5 segundos.

OPCIONES

Las opciones de línea de comandos disponibles son:

-0 precisión, --precision-force=precisión
Como -P pero esta opción anulará las especificaciones por métrica.
-4 acción, --names-change=acción
Especifica qué acción tomar al recibir un evento de cambio de nombres de métricas durante el muestreo. Estos eventos ocurren cuando un PMDA descubre nuevas métricas después de iniciarse, e informa a las herramientas cliente en ejecución como pcp2json. Los valores válidos para acción son update (actualizar métricas que se están muestreando), ignore (no hacer nada - el comportamiento por defecto) y abort (salir del programa si ocurre dicho evento).
-5, --ignore-unknown
Ignora silenciosamente cualquier nombre de métrica que no pueda ser resuelto. Al menos una métrica debe ser encontrada para que la herramienta comience.
-8 límite, --limit-filter=límite
Limita los resultados a instancias con valores por encima/debajo del límite. Un entero positivo incluirá instancias con valores iguales o superiores al límite en el informe. Un entero negativo incluirá instancias con valores iguales o inferiores al límite en el informe. Un valor de cero no realiza ningún filtrado de límite. Esta opción no anulará las posibles especificaciones por métrica. Ver también -J y -N.
-9 límite, --limit-filter-force=límite
Como -8 pero esta opción anulará las especificaciones por métrica.
-a archivo, --archive=archivo
Los valores de las métricas de rendimiento se recuperan del conjunto de archivos de archivo de Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista de nombres separada por comas, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos.
-A alineación, --align=alineación
Fuerza la muestra inicial a alinearse en el límite de una unidad de tiempo natural alineación. Consulte PCPIntro(1) para una descripción completa de la sintaxis para alineación.
--archive-folio=folio
Lee archivos de métricas de origen de los archivos de métricas de PCP folio creados por herramientas como pmchart(1) o, con menos frecuencia, manualmente con mkaf(1).
-b escala, --space-scale=escala
Unidad/escala para métricas de espacio (bytes), los valores posibles incluyen bytes, Kbytes, KB, Mbytes, MB, etcétera. Esta opción no anulará las posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-B escala, --space-scale-force=escala
Como -b pero esta opción anulará las especificaciones por métrica.
-c config, --config=config
Especifica el archivo o directorio de config a usar. En caso de que config sea un directorio, se incluirán todos los archivos que terminen en .conf. El valor por defecto es el primero que se encuentre de: ./pcp2json.conf, $HOME/.pcp2json.conf, $HOME/pcp/pcp2json.conf, y $PCP_SYSCONF_DIR/pcp2json.conf. Para detalles, consulte la sección anterior y pmrep.conf(5).
--container=contenedor
Obtener métricas de rendimiento del contenedor especificado, local o remoto (ver -h).
-C, --check
Salir antes de informar ningún valor, pero después de analizar la configuración y las métricas e imprimir posibles encabezados.
--daemonize
Convertir en demonio al iniciar.
-e derivado, --derived=derivado
Especificar métricas de rendimiento derivadas. Si derivado comienza con una barra ("/") o un punto ("."), se interpretará como un archivo de configuración de métricas derivadas de PCP. De lo contrario, se interpretará como expresiones de métricas derivadas separadas por comas o puntos y comas. Para una descripción completa de las métricas derivadas y los archivos de configuración de métricas derivadas de PCP, consulte pmLoadDerivedConfig(3) y pmRegisterDerived(3). Alternativamente, el uso de la sintaxis de configuración de pmrep.conf(5) permite definir métricas derivadas como parte de conjuntos de métricas.

En caso de problemas con las métricas derivadas, revise detalladamente las páginas del manual mencionadas anteriormente y asegúrese de que todas las métricas requeridas estén disponibles, especialmente al usar archivos. Utilice -Dderive para ver información de depuración adicional sobre el análisis de métricas derivadas.

-E, --exact-types
Escribir números como tipos de datos numéricos, no como cadenas, lo que puede implicar una pérdida de precisión.
-f formato, --timestamp-format=formato
Usar la cadena de formato para formatear la marca de tiempo. El formato se usará con el método datetime.strftime de Python, que es en gran medida el mismo que se describe en strftime(3). El valor predeterminado es %Y-%m-%d %H:%M:%S.
-F archivo de salida, --output-file=archivo de salida
Especificar el archivo de salida archivo de salida.
-G, --no-globals
No incluir métricas globales en el informe (ver pmrep.conf(5)).
-h host, --host=host
Obtener métricas de rendimiento de pmcd(1) en el host, en lugar de en el host local predeterminado.
-H, --no-header
No imprimir ningún encabezado.
-i instancias, --instances=instancias
Recuperar e informar solo las instancias de métricas especificadas. Por defecto, se informan todas las instancias, presentes y futuras.

Consulte pmrep(1) para obtener una descripción completa de esta opción.

-I, --ignore-incompat
Ignorar métricas incompatibles. Por defecto, las métricas incompatibles (es decir, cuyo tipo no es compatible o no se pueden escalar según lo solicitado) harán que pcp2json termine con un mensaje de error. Con esta opción, todas las métricas incompatibles se omiten silenciosamente del informe. Esto puede ser especialmente útil al solicitar nodos no terminales del árbol PMNS para el informe.
-j, --live-filter
Realizar filtrado en vivo de instancias. Esto permite capturar todas las instancias nombradas incluso si los procesos se reinician en algún momento (a diferencia de sin filtrado en vivo). Realizar filtrado en vivo sobre un gran número de instancias agregará cierta sobrecarga interna, por lo que se recomienda un poco de precaución por parte del usuario. Ver también -n.
-J rango, --rank=rango
Limitar los resultados a las instancias de mayor/menor rango de métricas con valores de conjunto. Un entero positivo incluirá las instancias de mayor valor en el informe. Un entero negativo incluirá las instancias de menor valor en el informe. Un valor de cero no realiza ningún ranking. El ranking no implica ordenamiento, ver -6. Ver también -8.
-K espec, --spec-local=espec
Al obtener métricas de un contexto local (ver -L), se puede usar la opción -K para controlar los PMDA DSO que deben ser accesibles. El argumento espec cumple con la sintaxis descrita en pmSpecLocalPMDA(3). Se puede usar más de una opción -K.
-L, --local-PMDA
Usar un contexto local para recopilar métricas de PMDA DSO en el host local sin PMCD. Ver también -K.
-n, --invert-filter
Realizar el ranking antes del filtrado en vivo. Por defecto, el filtrado en vivo de instancias (cuando se solicita, ver -j) ocurre antes del ranking de instancias (cuando se solicita, ver -J). Con esta opción, la lógica se invierte y el ranking ocurre antes del filtrado en vivo.
-m, --include-labels
Incluir etiquetas de métricas PCP en la salida.
-N predicado, --predicate=predicado
Especificar una lista separada por comas de métricas de referencia de filtro de predicado. Por defecto, el ranking (ver -J) se realiza para cada métrica individualmente. Con predicados, el ranking se realiza solo para las métricas de predicado especificadas. Al informar, el resto de las métricas que comparten el mismo dominio de instancia (ver PCPIntro(1)) que el predicado incluirán solo las instancias de mayor/menor rango del predicado correspondiente. El ranking no implica ordenamiento, ver -6.

Por ejemplo, usando proc.memory.rss (tamaño de memoria residente del proceso) como métrica de predicado junto con proc.io.total_bytes y mem.util.used como métricas a informar, solo los procesos que usan más/menos memoria (según -J) se incluirán al informar los bytes totales escritos por los procesos. Dado que mem.util.used es una métrica de valor único (por lo tanto, no comparte el mismo dominio de instancia que las métricas relacionadas con procesos), se informará como de costumbre.

-o, --http-timeout
Tiempo de espera (en segundos) al enviar una solicitud HTTP POST con la opción -u. El valor predeterminado es 2.5 segundos.
-O origen, --origin=origen
Al informar métricas archivadas, se comenzará a informar en origen dentro de la ventana de tiempo (ver -S y -T). Consulte PCPIntro(1) para obtener una descripción completa de la sintaxis de origen.
-p, --http-pass
Contraseña al usar autenticación básica HTTP con la opción -u.
-P precisión, --precision=precisión
Usar precisión para valores numéricos de salida no enteros. El valor predeterminado es usar 3 lugares decimales (cuando sea aplicable). Esta opción *no* anulará las posibles especificaciones por métrica.
-q escala, --count-scale=escala
Unidad/escala para métricas de recuento, los valores posibles incluyen count x 10^-1, count, count x 10, count x 10^2, y así sucesivamente desde 10^-8 hasta 10^7. (Estos valores son sensibles a los espacios en este momento). Esta opción *no* anulará las posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-Q escala, --count-scale-force=escala
Similar a -q, pero esta opción *anulará* las especificaciones por métrica.
-r, --raw
Salida de valores de métricas sin procesar, no convertir contadores acumulativos a tasas. Esta opción *anulará* las posibles especificaciones por métrica.
-R, --raw-prefer
Similar a -r, pero esta opción *no* anulará las especificaciones por métrica.
-s muestras, --samples=muestras
El argumento muestras define el número de muestras a recuperar y reportar. Si muestras es 0 o -s no se especifica, pcp2json tomará muestras e informará continuamente (en modo de tiempo real) o hasta el final del conjunto de archivos PCP (en modo de archivo). Ver también -T.
-S hora de inicio, --start=hora de inicio
Al informar métricas archivadas, el informe se limitará a aquellos registros registrados en o después de la hora de inicio. Consulte PCPIntro(1) para obtener una descripción completa de la sintaxis de hora de inicio.
-t intervalo, --interval=intervalo
Establecer el intervalo de informe en algo diferente al segundo predeterminado. El argumento intervalo sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos). Ver también la opción -T.
-T hora de finalización, --finish=hora de finalización
Al informar métricas archivadas, el informe se limitará a aquellos registros registrados antes o en la hora de finalización. Consulte PCPIntro(1) para obtener una descripción completa de la sintaxis de hora de finalización.

Cuando se usa para definir el tiempo de ejecución antes de que pcp2json salga, si no se proporciona ningún valor para muestras (ver -s), el número de muestras informadas dependerá del intervalo (ver -t). Si se proporciona muestras, el intervalo se ajustará para permitir el informe de muestras durante el tiempo de ejecución. En caso de que se proporcionen -T, -s y -t, la hora de finalización determinará el tiempo real durante el cual se ejecutará pcp2json.

-u, --url
URL para enviar una solicitud HTTP POST (en lugar de la salida estándar predeterminada).
-U, --http-user
Nombre de usuario al usar autenticación básica HTTP con la opción -u.
-v, --omit-fl

OPCIONES

-a archive
Recupera las métricas de rendimiento de un archivo de registro de PCP (ver LOGARCHIVE(5)). Las marcas de tiempo en el archivo de registro se utilizan para determinar el intervalo de tiempo de la consulta. El archivo de registro debe haber sido creado por pmlogrecord(1). Hay varias formas de especificar el nombre del archivo de registro. Si se especifica un nombre de archivo, se espera que sea un archivo de registro obtenido de pmlogextract(1). Si se especifica un directorio, se espera que sea un directorio que contenga un conjunto de archivos de registro que representen un único registro, como los producidos por pmlogger(1). Si el nombre del archivo de registro termina con la extensión .Z, .gz, .bz2 o .lz4, se descomprimirá automáticamente. Se pueden especificar múltiples archivos de registro y se concatenarán para formar una única secuencia temporal.
-c config
Leer la configuración para pcp2json de un archivo especificado por config, en lugar del archivo de configuración predeterminado $PCP_RC_DIR/pcp2json.conf. Ver FILES.
-D debug
Habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas. debug es una lista de opciones de depuración separadas por comas; usa pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
-h host
Recuperar métricas de rendimiento del demonio de recopilación de métricas remotas en host. El valor predeterminado es el host local.
-i
Incluir métricas de instancias. Con esta opción, los nombres de métrica aparecen como name.instance. Esto es lo contrario de la opción -I. Ver también -I.
-I
Omitir métricas de instancias. Con esta opción, los nombres de métrica aparecen como name en lugar de name.instance. Esto es lo contrario de la opción -i. Ver también -i.
-m
Incluir etiquetas de métrica. Con esta opción, todas las métricas se imprimen con sus etiquetas y valores asociados.
-O output
Escribir la salida en el archivo especificado por output en lugar de en la salida estándar.
-p
Solo informar métricas de conjunto de valores con instancias (por ejemplo, disk.dev.read) y omitir métricas ``planas'' de valor único sin instancias (por ejemplo, kernel.all.sysfork). Ver -i y -I.
-V, --version
Mostrar el número de versión y salir.
-x, --with-extended
Escribir información extendida.
-X, --with-everything
Escribir todo lo conocido sobre las métricas, incluyendo los ID internos de PCP. Sin embargo, las etiquetas se omiten por compatibilidad con versiones anteriores; usa -m para incluirlas también.
-y scale, --time-scale=scale
Unidad/escala para métricas de tiempo, los valores posibles incluyen nanosec, ns, microsec, us, millisec, ms, y así sucesivamente hasta hour, hr. Esta opción no anulará las posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-Y scale, --time-scale-force=scale
Similar a -y pero esta opción anulará las especificaciones por métrica.
-z, --hostzone
Usar la zona horaria local del host que es la fuente de las métricas de rendimiento, tal como se identifica mediante las opciones -h o -a. El valor predeterminado es usar la zona horaria del host local.
-Z timezone, --timezone=timezone
Usar timezone para la fecha y hora. Timezone está en el formato de la variable de entorno TZ, como se describe en environ(7). Ten en cuenta que al incluir una cadena de zona horaria en la salida, se utilizan desplazamientos UTC de estilo ISO 8601 (por lo que algo como -Z EST+5 se convertirá en UTC-5).
-?, --help
Mostrar mensaje de uso y salir.

Archivo de configuración de pcp2json (ver -c)

Archivos de configuración de pmrep predeterminados proporcionados por el sistema

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para las variables de entorno que afectan a las herramientas de PCP, consulta pmGetOptions(3).

De particular interés, PCP_DISCRETE_ONCE puede establecerse para garantizar que los valores de métricas discretas se informen solo una vez, a menos que cambien en algún momento.

OPCIONES DE DEPURACION

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información a veces es críptica y está destinada principalmente a orientar a los desarrolladores en lugar de a los usuarios finales. debug es una lista de opciones de depuración separadas por comas; usa pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
