BIBLIOTECAS DE PCRE DE 8-BITOS, 16-BITOS Y 32-BITOS

Además de la compatibilidad con cadenas de caracteres de 8 bits, PCRE también soporta cadenas de 16 bits (desde la versión 8.30) y de 32 bits (desde la versión 8.32), mediante dos bibliotecas adicionales. Pueden compilarse junto con, o en lugar de, la biblioteca de 8 bits. Para evitar demasiada complicación, este documento describe las versiones de 8 bits de las funciones, con solo referencias ocasionales a las bibliotecas de 16 y 32 bits.

Las funciones de 16 y 32 bits operan de la misma manera que sus homólogas de 8 bits; solo utilizan diferentes tipos de datos para sus argumentos y resultados, y sus nombres comienzan con pcre16_ o pcre32_ en lugar de pcre_. Por cada opción que tenga UTF8 en su nombre (por ejemplo, PCRE_UTF8), existen nombres correspondientes de 16 y 32 bits con UTF8 reemplazado por UTF16 o UTF32, respectivamente. Esta funcionalidad es en realidad solo cosmética; los nombres de las opciones de 16 y 32 bits definen los mismos valores de bits.

Las referencias a bytes y UTF-8 en este documento deben leerse como referencias a unidades de datos de 16 bits y UTF-16 al usar la biblioteca de 16 bits, o unidades de datos de 32 bits y UTF-32 al usar la biblioteca de 32 bits, a menos que se especifique lo contrario. Se proporcionan más detalles sobre las diferencias específicas para las bibliotecas de 16 y 32 bits en las páginas pcre16 y pcre32.

RESUMEN DE LA API DE PCRE

PCRE tiene su propia API nativa, descrita en este documento. También existen algunas funciones envoltorio (solo para la biblioteca de 8 bits) que corresponden a la API de expresiones regulares POSIX, pero no dan acceso a toda la funcionalidad. Se describen en la documentación de pcreposix. Ambas APIs definen un conjunto de llamadas a funciones C. También se distribuye con PCRE una envoltura C++ (solo para la biblioteca de 8 bits). Se documenta en la página pcrecpp.

Los prototipos de las funciones C de la API nativa se definen en el archivo de cabecera pcre.h, y en sistemas tipo Unix la biblioteca (de 8 bits) se llama normalmente libpcre. Normalmente se puede acceder a ella añadiendo -lpcre al comando para enlazar una aplicación que use PCRE. El archivo de cabecera define las macros PCRE_MAJOR y PCRE_MINOR para contener los números de versión principal y secundaria de la biblioteca. Las aplicaciones pueden usarlas para incluir compatibilidad con diferentes versiones de PCRE.

En un entorno Windows, si desea enlazar estáticamente un programa aplicación contra un archivo pcre.a que no sea DLL, debe definir PCRE_STATIC antes de incluir pcre.h o pcrecpp.h, ya que de lo contrario las funciones exportadas pcre_malloc() y pcre_free() se declararán como __declspec(dllimport), con resultados no deseados.

Las funciones pcre_compile(), pcre_compile2(), pcre_study() y pcre_exec() se utilizan para compilar y comparar expresiones regulares de manera compatible con Perl. Se proporciona un programa de ejemplo que demuestra la forma más sencilla de utilizarlas en el archivo llamado pcredemo.c en la distribución de código fuente de PCRE. Se incluye un listado de este programa en la documentación de pcredemo, y la documentación de pcresample describe cómo compilarlo y ejecutarlo.

El soporte de compilación justo a tiempo (JIT) es una característica opcional de PCRE que puede compilarse en entornos de hardware apropiados. Acelera enormemente el rendimiento de comparación de muchos patrones. Los programas sencillos pueden solicitar fácilmente que se utilice si está disponible, estableciendo una opción que se ignora cuando no es relevante. Los programas más complicados podrían necesitar utilizar las funciones pcre_jit_stack_alloc(), pcre_jit_stack_free() y pcre_assign_jit_stack() para controlar el uso de memoria del código JIT.

Desde la versión 8.32 también existe una interfaz directa para la ejecución JIT, que proporciona un rendimiento mejorado. Las funciones específicas de JIT se discuten en la documentación de pcrejit.

Una segunda función de comparación, pcre_dfa_exec(), que no es compatible con Perl, también se proporciona. Esta utiliza un algoritmo diferente para la comparación. El algoritmo alternativo encuentra todas las coincidencias posibles (en un punto dado del sujeto), y escanea el sujeto solo una vez (a menos que haya aserciones de retroceso). Sin embargo, este algoritmo no devuelve subcadenas capturadas. En la documentación de pcrematching se describe una explicación de los dos algoritmos de comparación y sus ventajas y desventajas.

MISCELLANEOUS FUNCTIONS

In addition to the main compiling and matching functions, there are convenience functions for extracting captured substrings from a subject string that is matched by pcre_exec(). They are:


pcre_copy_substring()
pcre_copy_named_substring()
pcre_get_substring()
pcre_get_named_substring()
pcre_get_substring_list()
pcre_get_stringnumber()
pcre_get_stringtable_entries()

pcre_free_substring() and pcre_free_substring_list() are also provided, to free the memory used for extracted strings.

The function pcre_maketables() is used to build a set of character tables in the current locale for passing to pcre_compile(), pcre_exec(), or pcre_dfa_exec(). This is an optional facility that is provided for specialist use. Most commonly, no special tables are passed, in which case internal tables that are generated when PCRE is built are used.

The function pcre_fullinfo() is used to find out information about a compiled pattern. The function pcre_version() returns a pointer to a string containing the version of PCRE and its date of release.

The function pcre_refcount() maintains a reference count in a data block containing a compiled pattern. This is provided for the benefit of object-oriented applications.

The global variables pcre_malloc and pcre_free initially contain the entry points of the standard malloc() and free() functions, respectively. PCRE calls the memory management functions via these variables, so a calling program can replace them if it wishes to intercept the calls. This should be done before calling any PCRE functions.

The global variables pcre_stack_malloc and pcre_stack_free are also indirections to memory management functions. These special functions are used only when PCRE is compiled to use the heap for remembering data, instead of recursive function calls, when running the pcre_exec() function. See the pcrebuild documentation for details of how to do this. It is a non-standard way of building PCRE, for use in environments that have limited stacks. Because of the greater use of memory management, it runs more slowly. Separate functions are provided so that special-purpose external code can be used for this case. When used, these functions always allocate memory blocks of the same size. There is a discussion about PCRE's stack usage in the pcrestack documentation.

The global variable pcre_callout initially contains NULL. It can be set by the caller to a "callout" function, which PCRE will then call at specified points during a matching operation. Details are given in the pcrecallout documentation.

The global variable pcre_stack_guard initially contains NULL. It can be set by the caller to a function that is called by PCRE whenever it starts to compile a parenthesized part of a pattern. When parentheses are nested, PCRE uses recursive function calls, which use up the system stack. This function is provided so that applications with restricted stacks can force a compilation error if the stack runs out. The function should return zero if all is well, or non-zero to force an error.

NUEVAS LINEAS

PCRE soporta cinco convenciones diferentes para indicar saltos de línea en cadenas: un solo carácter CR (retorno de carro), un solo carácter LF (salto de línea), la secuencia de dos caracteres CRLF, cualquiera de los tres anteriores, o cualquier secuencia de nueva línea Unicode. Las secuencias de nueva línea Unicode son las tres mencionadas anteriormente, más los caracteres individuales VT (tabulación vertical, U+000B), FF (salto de página, U+000C), NEL (nueva línea, U+0085), LS (separador de línea, U+2028) y PS (separador de párrafo, U+2029).

Cada una de las tres primeras convenciones es utilizada por al menos un sistema operativo como su secuencia de nueva línea estándar. Cuando PCRE se compila, se puede especificar un valor predeterminado. El valor predeterminado por defecto es LF, que es el estándar de Unix. Cuando PCRE se ejecuta, el valor predeterminado puede ser anulado, ya sea al compilar un patrón o al realizar una coincidencia.

En el momento de la compilación, la convención de nueva línea se puede especificar mediante el argumento options de pcre_compile(), o se puede especificar mediante texto especial al principio del propio patrón; esto anula cualquier otra configuración. Ver la página pcrepattern para obtener detalles sobre las secuencias de caracteres especiales.

En la documentación de PCRE, la palabra "nueva línea" se usa para significar "el carácter o par de caracteres que indican un salto de línea". La elección de la convención de nueva línea afecta el manejo de los metacaracteres punto, circunflejo y dólar, el manejo de comentarios # en modo /x y, cuando CRLF es una secuencia de fin de línea reconocida, el avance de la posición de coincidencia para un patrón no anclado. Hay más detalles sobre esto en la sección sobre las opciones de pcre_exec() a continuación.

La elección de la convención de nueva línea no afecta la interpretación de las secuencias de escape \n o \r, ni afecta lo que \R coincide, lo cual se controla de manera similar, pero mediante opciones separadas.

MULTIHILO

Las funciones de PCRE se pueden usar en aplicaciones multihilo, con la advertencia de que las funciones de gestión de memoria apuntadas por pcre_malloc, pcre_free, pcre_stack_malloc y pcre_stack_free, y las funciones de llamada y comprobación de pila apuntadas por pcre_callout y pcre_stack_guard, son compartidas por todos los hilos.

La forma compilada de una expresión regular no se modifica durante la coincidencia, por lo que el mismo patrón compilado puede ser utilizado de forma segura por varios hilos a la vez.

Si se está utilizando la característica de optimización just-in-time, necesita áreas de pila de memoria separadas para cada hilo. Ver la documentación de pcrejit para más detalles.

GUARDAR PATRONES PRECOMPILADOS PARA USO POSTERIOR

La forma compilada de una expresión regular se puede guardar y reutilizar en un momento posterior, posiblemente por un programa diferente, e incluso en un host distinto al que se compiló. Los detalles se proporcionan en la documentación de pcreprecompile, que incluye una descripción de la función pcre_pattern_to_host_byte_order(). Sin embargo, compilar una expresión regular con una versión de PCRE para usarla con una versión diferente no garantiza que funcione y puede provocar fallos.

COMPROBAR OPCIONES DE COMPILACION

int pcre_config(int what, void *where);

La función pcre_config() permite a un cliente de PCRE descubrir qué características opcionales se han compilado en la biblioteca de PCRE. La documentación de pcrebuild tiene más detalles sobre estas características opcionales.

El primer argumento para pcre_config() es un entero, que especifica qué información se requiere; el segundo argumento es un puntero a una variable en la que se coloca la información. El valor devuelto es cero en caso de éxito, o el código de error negativo PCRE_ERROR_BADOPTION si el valor del primer argumento no se reconoce. La siguiente información está disponible:


PCRE_CONFIG_UTF8

La salida es un entero que se establece a uno si el soporte de UTF-8 está disponible; de lo contrario, se establece a cero. Este valor normalmente debería darse a la versión de 8 bits de esta función, pcre_config(). Si se da a la versión de 16 o 32 bits de esta función, el resultado es PCRE_ERROR_BADOPTION.


PCRE_CONFIG_UTF16

La salida es un entero que se establece a uno si el soporte de UTF-16 está disponible; de lo contrario, se establece a cero. Este valor normalmente debería darse a la versión de 16 bits de esta función, pcre16_config(). Si se da a la versión de 8 o 32 bits de esta función, el resultado es PCRE_ERROR_BADOPTION.


PCRE_CONFIG_UTF32

La salida es un entero que se establece a uno si el soporte de UTF-32 está disponible; de lo contrario, se establece a cero. Este valor normalmente debería darse a la versión de 32 bits de esta función, pcre32_config(). Si se da a la versión de 8 o 16 bits de esta función, el resultado es PCRE_ERROR_BADOPTION.


PCRE_CONFIG_UNICODE_PROPERTIES

La salida es un entero que se establece a uno si el soporte para propiedades de caracteres Unicode está disponible; de lo contrario, se establece a cero.


PCRE_CONFIG_JIT

La salida es un entero que se establece a uno si el soporte de compilación just-in-time está disponible; de lo contrario, se establece a cero.


PCRE_CONFIG_JITTARGET

La salida es un puntero a una cadena "const char *" terminada en nulo. Si el soporte JIT está disponible, la cadena contiene el nombre de la arquitectura para la que está configurado el compilador JIT, por ejemplo "x86 32bit (little endian + unaligned)". Si el soporte JIT no está disponible, el resultado es NULL.


PCRE_CONFIG_NEWLINE

La salida es un entero cuyo valor especifica la secuencia de caracteres predeterminada que se reconoce como "nueva línea". Los valores que se admiten en entornos ASCII/Unicode son: 10 para LF, 13 para CR, 3338 para CRLF, -2 para ANYCRLF y -1 para ANY. En entornos EBCDIC, CR, ANYCRLF y ANY producen los mismos valores. Sin embargo, el valor para LF es normalmente 21, aunque algunos entornos EBCDIC usan 37. Los valores correspondientes para CRLF son 3349 y 3365. El valor predeterminado normalmente debería corresponder a la secuencia estándar de su sistema operativo.


PCRE_CONFIG_BSR

La salida es un entero cuyo valor indica qué secuencias de caracteres coincide la secuencia de escape \R por defecto. Un valor de 0 significa que \R coincide con cualquier secuencia de fin de línea Unicode; un valor de 1 significa que \R coincide solo con CR, LF o CRLF. El valor predeterminado puede ser anulado al compilar o al hacer coincidir un patrón.


PCRE_CONFIG_LINK_SIZE

La salida es un entero que contiene el número de bytes utilizados para el enlace interno en expresiones regulares compiladas. Para la biblioteca de 8 bits, el valor puede ser 2, 3 o 4. Para la biblioteca de 16 bits, el valor es 2 o 4 y sigue siendo un número de bytes. Para la biblioteca de 32 bits, el valor es 2 o 4 y sigue siendo un número de bytes. El valor predeterminado de 2 es suficiente para todos menos para los patrones más masivos, ya que permite que el patrón compilado tenga hasta 64K de tamaño. Valores más grandes permiten compilar expresiones regulares más grandes, a costa de una coincidencia más lenta.

OPTIONS DE CONFIGURATION

Les options suivantes peuvent être utilisées avec la fonction pcre_config() pour obtenir diverses informations de configuration concernant la bibliothèque PCRE. Elles sont décrites ci-dessous. Les valeurs retournées sont des entiers ou des chaînes de caractères selon le cas.

Les options disponibles sont:


PCRE_CONFIG_HEAP_LIMIT

La valeur de retour est un entier qui contient le seuil au-dessus duquel l'interface POSIX utilise malloc() pour les vecteurs de sortie. Plus de détails sont fournis dans la documentation de pcreposix.


PCRE_CONFIG_PARENS_LIMIT

La sortie est un entier long qui donne la profondeur maximale d'imbrication des parenthèses (de tout type) dans un motif. Cette limite ne prend pas en compte la pile qui peut déjà être utilisée par l'application appelante. PCRE_CONFIG_MATCH_LIMIT

La sortie est un entier long qui donne la limite par défaut pour le nombre d'appels de fonction de correspondance internes dans une exécution de pcre_exec(). Plus de détails sont donnés avec pcre_exec() ci-dessous.


PCRE_CONFIG_MATCH_LIMIT_RECURSION

La sortie est un entier long qui donne la limite par défaut pour la profondeur de récursion lors de l'appel de la fonction de correspondance interne dans une exécution de pcre_exec(). Plus de détails sont donnés avec pcre_exec() ci-dessous.

La sortie est un entier qui est mis à un si la récursion interne lors de l'exécution de pcre_exec() est implémentée par des appels de fonction récursifs qui utilisent la pile pour se souvenir de leur état. C'est la manière habituelle dont PCRE est compilé. La sortie est zéro si PCRE a été compilé pour utiliser des blocs de données sur le tas au lieu d'appels de fonction récursifs. Dans ce cas, pcre_stack_malloc et pcre_stack_free sont appelés pour gérer les blocs de mémoire sur le tas, évitant ainsi l'utilisation de la pile.

COMPILATION D'UN MOTIF

pcre *pcre_compile(const char *pattern, int options,
     const char **errptr, int *erroffset,
     const unsigned char *tableptr);

pcre *pcre_compile2(const char *pattern, int options,
     int *errorcodeptr,
     const char **errptr, int *erroffset,
     const unsigned char *tableptr);

L'une ou l'autre des fonctions pcre_compile() ou pcre_compile2() peut être appelée pour compiler un motif dans une forme interne. La seule différence entre les deux interfaces est que pcre_compile2() a un argument supplémentaire, errorcodeptr, via lequel un code d'erreur numérique peut être retourné. Pour éviter trop de répétition, nous faisons référence uniquement à pcre_compile() ci-dessous, mais l'information s'applique également à pcre_compile2().

Le motif est une chaîne C terminée par un zéro binaire, et est passé dans l'argument pattern. Un pointeur vers un seul bloc de mémoire obtenu via pcre_malloc est retourné. Ce bloc contient le code compilé et les données associées. Le type pcre est défini pour le bloc retourné; c'est un typedef pour une structure dont le contenu n'est pas défini extérieurement. Il appartient à l'appelant de libérer la mémoire (via pcre_free) lorsqu'elle n'est plus nécessaire.

Bien que le code compilé d'une expression régulière PCRE soit déplaçable, c'est-à-dire qu'il ne dépend pas de l'emplacement de la mémoire, le bloc de données pcre complet n'est pas entièrement déplaçable, car il peut contenir une copie de l'argument tableptr, qui est une adresse (voir ci-dessous).

L'argument options contient divers bits de configuration qui affectent la compilation. Il doit être zéro si aucune option n'est requise. Les options disponibles sont décrites ci-dessous. Certaines d'entre elles (en particulier celles qui sont compatibles avec Perl, mais aussi d'autres) peuvent également être définies et désactivées depuis l'intérieur du motif (voir la description détaillée dans la documentation de pcrepattern). Pour les options qui peuvent être différentes dans différentes parties du motif, le contenu de l'argument options spécifie leur configuration au début de la compilation et de l'exécution. Les options PCRE_ANCHORED, PCRE_BSR_xxx, PCRE_NEWLINE_xxx, PCRE_NO_UTF8_CHECK, et PCRE_NO_START_OPTIMIZE peuvent être définies au moment de la correspondance ainsi qu'au moment de la compilation.

Si errptr est NULL, pcre_compile() retourne NULL immédiatement. Sinon, si la compilation d'un motif échoue, pcre_compile() retourne NULL, et définit la variable pointée par errptr pour pointer vers un message d'erreur textuel. Il s'agit d'une chaîne statique qui fait partie de la bibliothèque. Vous ne devez pas essayer de la libérer. Normalement, le décalage par rapport au début du motif jusqu'à l'unité de données qui était en cours de traitement au moment où l'erreur a été découverte est placé dans la variable pointée par erroffset, qui ne doit pas être NULL (si c'est le cas, une erreur immédiate est signalée). Cependant, pour une chaîne UTF-8 ou UTF-16 invalide, le décalage est celui de la première unité de données du caractère défaillant.

Certaines erreurs ne sont pas détectées avant que tout le motif n'ait été analysé; dans ces cas, le décalage retourné est la longueur du motif. Notez que le décalage est en unités de données, pas en caractères, même en mode UTF. Il peut parfois pointer au milieu d'un caractère UTF-8 ou UTF-16.

Si pcre_compile2() est utilisé à la place de pcre_compile(), et que l'argument errorcodeptr n'est pas NULL, un code d'erreur numérique non nul est retourné via cet argument en cas d'erreur. Ceci s'ajoute au message d'erreur textuel. Les codes et messages d'erreur sont listés ci-dessous.

Si le dernier argument, tableptr, est NULL, PCRE utilise un ensemble par défaut de tables de caractères qui sont construites lors de la compilation de PCRE, en utilisant la locale C par défaut. Sinon, tableptr doit être une adresse qui est le résultat d'un appel à pcre_maketables(). Cette valeur est stockée avec le motif compilé, et utilisée à nouveau par pcre_exec() et pcre_dfa_exec() lors de la correspondance du motif. Pour plus de discussion, voir la section sur le support des locales ci-dessous.

Ce fragment de code montre un appel simple typique à pcre_compile():


pcre *re;
const char *error;
int erroffset;
re = pcre_compile(
"^A.*Z", /* le motif */
0, /* options par défaut */
&error, /* pour le message d'erreur */
&erroffset, /* pour le décalage d'erreur */
NULL); /* utiliser les tables de caractères par défaut */

Les noms suivants pour les bits d'options sont définis dans le fichier d'en-tête pcre.h:


PCRE_ANCHORED

Si ce bit est défini, le motif est forcé d'être "ancré", c'est-à-dire qu'il est contraint de correspondre uniquement au premier point de correspondance dans la chaîne recherchée (la "chaîne objet"). Cet effet peut également être obtenu par des constructions appropriées dans le motif lui-même, ce qui est la seule façon de le faire en Perl.


PCRE_AUTO_CALLOUT

Si ce bit est défini, pcre_compile() insère automatiquement des éléments de rappel (callout), tous avec le numéro 255, avant chaque élément du motif. Pour une discussion sur la fonction de rappel, voir la documentation de pcrecallout.


PCRE_BSR_ANYCRLF
PCRE_BSR_UNICODE

Ces options (qui sont mutuellement exclusives) contrôlent ce que la séquence d'échappement \R correspond. Le choix est soit de correspondre uniquement à CR, LF, ou CRLF, soit de correspondre à toute séquence de nouvelle ligne Unicode. La valeur par défaut est spécifiée lors de la construction de PCRE. Elle peut être remplacée depuis l'intérieur du motif, ou en définissant une option lors de la correspondance du motif compilé.


PCRE_CASELESS

Si ce bit est défini, les lettres du motif correspondent aux lettres majuscules et minuscules. C'est équivalent à l'option /i de Perl, et cela peut être modifié à l'intérieur d'un motif par un réglage d'option (?i). En mode UTF-8, PCRE comprend toujours le concept de casse pour les caractères dont les valeurs sont inférieures à 128, donc la correspondance sans casse est toujours possible. Pour les caractères de valeurs supérieures, le concept de casse est supporté si PCRE est compilé avec le support des propriétés Unicode, mais pas sinon. Si vous souhaitez utiliser la correspondance sans casse pour les caractères égaux ou supérieurs à 128, vous devez vous assurer que PCRE est compilé avec le support des propriétés Unicode ainsi qu'avec le support UTF-8.


PCRE_DOLLAR_ENDONLY

Si ce bit est défini, un métacaractère dollar dans le motif ne correspond qu'à la fin de la chaîne objet. Sans cette option, un dollar correspond également immédiatement avant une nouvelle ligne à la fin de la chaîne (mais pas avant d'autres nouvelles lignes). L'option PCRE_DOLLAR_ENDONLY est ignorée si PCRE_MULTILINE est définie. Il n'y a pas d'équivalent à cette option dans Perl, et aucun moyen de la définir dans un motif.


PCRE_DOTALL

Si ce bit est défini, un métacaractère point dans le motif correspond à un caractère de n'importe quelle valeur, y compris celui qui indique une nouvelle ligne. Cependant, il ne correspond jamais qu'à un seul caractère, même si les nouvelles lignes sont codées en CRLF. Sans cette option, un point ne correspond pas lorsque la position actuelle est sur une nouvelle ligne. Cette option est équivalente à l'option /s de Perl, et elle peut être modifiée à l'intérieur d'un motif par un réglage d'option (?s). Une classe négative telle que [^a] correspond toujours aux caractères de nouvelle ligne, indépendamment du réglage de cette option.


PCRE_DUPNAMES

Si ce bit est défini, les noms utilisés pour identifier les sous-motifs capturants n'ont pas besoin d'être uniques. Cela peut être utile pour certains types de motifs lorsqu'il est connu qu'une seule instance du sous-motif nommé peut jamais correspondre. Il y a plus de détails sur les sous-motifs nommés ci-dessous; voir également la documentation de pcrepattern.


PCRE_EXTENDED

Si ce bit est défini, la plupart des caractères d'espacement dans le motif sont totalement ignorés sauf lorsqu'ils sont échappés ou à l'intérieur d'une classe de caractères. Cependant, l'espacement n'est pas autorisé dans les séquences telles que (?> qui introduisent divers sous-motifs entre parenthèses, ni dans un quantificateur numérique tel que {1,3}. Cependant, l'espacement ignorable est autorisé entre un élément et un quantificateur suivant, et entre un quantificateur et un + suivant qui indique la possessivité.

L'espacement n'incluait pas auparavant le caractère VT (code 11), car Perl ne traitait pas ce caractère comme un espacement. Cependant, Perl a changé à la version 5.18, donc PCRE a suivi à la version 8.34, et VT est maintenant traité comme un espacement.

PCRE_EXTENDED fait également ignorer les caractères entre un # non échappé en dehors d'une classe de caractères et la prochaine nouvelle ligne, inclusivement. PCRE_EXTENDED est équivalent à l'option /x de Perl, et elle peut être modifiée à l'intérieur d'un motif par un réglage d'option (?x).

Les caractères qui sont interprétés comme des nouvelles lignes sont contrôlés par les options passées à pcre_compile() ou par une séquence spéciale au début du motif, comme décrit dans la section intitulée "Conventions de nouvelle ligne" dans la documentation de pcrepattern. Notez que la fin de ce type de commentaire est une séquence de nouvelle ligne littérale dans le motif; les séquences d'échappement qui représentent une nouvelle ligne ne sont pas comptées.

Cette option permet d'inclure des commentaires

Los caracteres de espacio en blanco nunca pueden aparecer dentro de secuencias especiales de caracteres\n en un patrón, por ejemplo, dentro de la secuencia (?( que introduce\n un subpatrón condicional.

\n PCRE_EXTRA

\n

Esta opción se inventó para activar una funcionalidad adicional\n de PCRE que es incompatible con Perl, pero actualmente es de muy poco uso. Cuando se establece, cualquier barra invertida en un patrón seguida de una letra que no tenga un significado especial provoca un error, reservando así estas combinaciones para futuras ampliaciones. Por defecto, al igual que en Perl, una barra invertida seguida de una letra sin significado especial se trata como literal. (Sin embargo, Perl puede ser persuadido para que genere un error para esto, ejecutándolo con la opción -w.) Actualmente no hay otras características controladas por esta opción. También se puede establecer mediante una configuración de opción (?X) dentro de un patrón.

\n

\n PCRE_FIRSTLINE

\n

Si esta opción está configurada, se requiere que un patrón no anclado coincida\n antes o en la primera nueva línea de la cadena sujeto, aunque el texto coincidente puede continuar sobre la nueva línea.

\n

\n
\n PCRE_JAVASCRIPT_COMPAT

\n

Si esta opción está configurada, el comportamiento de PCRE se modifica de algunas maneras para que sea compatible con JavaScript en lugar de Perl. Los cambios son los siguientes:

\n

(1) Un corchete de cierre solitario en un patrón provoca un error de compilación, ya que esto es ilegal en JavaScript (por defecto se trata como un carácter de datos). Por lo tanto, el patrón AB]CD se vuelve ilegal cuando se establece esta opción.

\n

(2) En tiempo de ejecución, una referencia inversa a un grupo de subpatrón no establecido coincide con una cadena vacía (por defecto, esto provoca el fallo de la alternativa de coincidencia actual). Un patrón como (\1)(a) tiene éxito cuando se establece esta opción (suponiendo que pueda encontrar una \"a\" en el sujeto), mientras que falla por defecto, para compatibilidad con Perl.

\n

(3) \\U coincide con un carácter \"U\" en mayúsculas; por defecto, \\U provoca un error de tiempo de compilación (Perl usa \\U para convertir a mayúsculas los caracteres subsiguientes).

\n

(4) \\u coincide con un carácter \"u\" en minúsculas a menos que esté seguido por cuatro dígitos hexadecimales, en cuyo caso el número hexadecimal define el punto de código a coincidir. Por defecto, \\u provoca un error de tiempo de compilación (Perl lo usa para convertir a mayúsculas el carácter siguiente).

\n

(5) \\x coincide con un carácter \"x\" en minúsculas a menos que esté seguido por dos dígitos hexadecimales, en cuyo caso el número hexadecimal define el punto de código a coincidir. Por defecto, al igual que en Perl, siempre se espera un número hexadecimal después de \\x, pero puede tener cero, uno o dos dígitos (por lo que, por ejemplo, \\xz coincide con un carácter cero binario seguido de z).

\n

\n
\n PCRE_MULTILINE

\n

Por defecto, a efectos de coincidencia de \"inicio de línea\" y\n \"fin de línea\", PCRE trata la cadena sujeto como si consistiera en una sola línea de caracteres, incluso si contiene saltos de línea. El\n metacarácter de \"inicio de línea\" (^) solo coincide al principio de la\n cadena, y el metacarácter de \"fin de línea\" ($) solo coincide al final de la\n cadena, o antes de un salto de línea de terminación (excepto cuando\n se establece PCRE_DOLLAR_ENDONLY). Tenga en cuenta, sin embargo, que a menos que se establezca PCRE_DOTALL, el metacarácter de \"cualquier carácter\" (.) no coincide con un salto de línea. Este comportamiento (para ^, $ y punto) es el mismo que en Perl.

\n

Cuando se establece PCRE_MULTILINE, los constructos de \"inicio de línea\" y\n \"fin de línea\" coinciden inmediatamente después o\n inmediatamente antes de los saltos de línea internos en la cadena sujeto, respectivamente, así como al principio y al final. Esto es equivalente a la opción /m de Perl, y se puede cambiar dentro de un patrón mediante una configuración de opción (?m). Si no hay saltos de línea en una cadena sujeto, o no hay ocurrencias de ^ o $ en un patrón, establecer PCRE_MULTILINE no tiene efecto.

\n

\n
\n PCRE_NEVER_UTF

\n

Esta opción bloquea la interpretación del patrón como UTF-8 (o UTF-16 o UTF-32 en las bibliotecas de 16 y 32 bits). En particular, impide que el creador del patrón cambie a interpretación UTF comenzando el patrón con (*UTF). Esto puede ser útil en aplicaciones que procesan patrones de fuentes externas. La combinación de PCRE_UTF8 y\n PCRE_NEVER_UTF también provoca un error.

\n

\n
\n PCRE_NEWLINE_CR\n
\n PCRE_NEWLINE_LF\n
\n PCRE_NEWLINE_CRLF\n
\n PCRE_NEWLINE_ANYCRLF\n
\n PCRE_NEWLINE_ANY

\n

Estas opciones anulan la definición predeterminada de salto de línea que se eligió cuando se compiló PCRE. Establecer la primera o la segunda especifica que un salto de línea está indicado por un solo carácter (CR o LF, respectivamente). Establecer PCRE_NEWLINE_CRLF especifica que un salto de línea está indicado por la secuencia de dos caracteres CRLF. Establecer PCRE_NEWLINE_ANYCRLF especifica que se deben reconocer cualquiera de las tres secuencias anteriores. Establecer PCRE_NEWLINE_ANY especifica que se deben reconocer todas las secuencias de salto de línea Unicode.

\n

En un entorno ASCII/Unicode, las secuencias de salto de línea Unicode son las tres mencionadas, más los caracteres individuales VT (tabulador vertical, U+000B), FF (salto de página, U+000C), NEL (nueva línea, U+0085), LS (separador de línea, U+2028) y PS (separador de párrafo, U+2029). Para la biblioteca de 8 bits, las dos últimas solo se reconocen en modo UTF-8.

\n

Cuando PCRE se compila para ejecutarse en un entorno EBCDIC (mainframe), el código para CR es 0x0d, el mismo que en ASCII. Sin embargo, el código de carácter para LF es normalmente 0x15, aunque en algunos entornos EBCDIC se usa 0x25. Cualquiera de estos que no sea LF se hace corresponder con el carácter NEL de Unicode. Los códigos EBCDIC son todos menores de 256. Para más detalles, consulte la documentación de\n pcrebuild.

\n

La configuración de salto de línea en la palabra de opciones utiliza tres bits que se tratan como un número, dando ocho posibilidades. Actualmente solo se utilizan seis (el valor predeterminado más los cinco valores anteriores). Esto significa que si establece más de una opción de salto de línea, la combinación puede ser o no sensata. Por ejemplo, PCRE_NEWLINE_CR con PCRE_NEWLINE_LF es equivalente a PCRE_NEWLINE_CRLF, pero otras combinaciones pueden dar números no utilizados y causar un error.

\n

La única vez que un salto de línea en un patrón se reconoce especialmente al compilar es cuando se establece PCRE_EXTENDED. CR y LF son caracteres de espacio en blanco, y por lo tanto se ignoran en este modo. Además, un # sin escapar fuera de una clase de caracteres indica un comentario que dura hasta después de la siguiente secuencia de salto de línea. En otras circunstancias, las secuencias de salto de línea en los patrones se tratan como datos literales.

\n

La opción de salto de línea que se establece en tiempo de compilación se convierte en la predeterminada que se utiliza para\n pcre_exec() y pcre_dfa_exec(), pero puede ser anulada.

\n PCRE_NO_AUTO_CAPTURE

\n

Si esta opción está configurada, deshabilita el uso de paréntesis de captura numerados en el patrón. Cualquier paréntesis de apertura que no vaya seguido de ? se comporta como si fuera seguido de ?: pero los paréntesis con nombre aún se pueden usar para capturar (y adquieren números de la forma habitual). No existe un equivalente de esta opción en Perl.

\n PCRE_NO_AUTO_POSSESS

\n

Si esta opción está configurada, deshabilita la\n \"auto-posesión\". Esta es una optimización que, por ejemplo, convierte a+b en a++b para evitar retrocesos en a+ que nunca pueden tener éxito. Sin embargo, si se utilizan llamadas (callouts), la auto-posesión significa que algunas de ellas nunca se toman. Puede establecer esta opción si desea que las funciones de coincidencia realicen una búsqueda completa no optimizada y ejecuten todas las llamadas, pero se proporciona principalmente para fines de prueba.

\n

\n PCRE_NO_START_OPTIMIZE

\n

Esta es una opción que actúa en el momento de la coincidencia; es decir, es realmente una opción para\n pcre_exec() o pcre_dfa_exec(). Si se establece en tiempo de compilación, se recuerda con el patrón compilado y se asume en tiempo de coincidencia. Esto es necesario si desea utilizar la ejecución JIT, ya que el compilador JIT necesita saber si esta opción está configurada o no. Para obtener más detalles, consulte la discusión de PCRE_NO_START_OPTIMIZE a continuación.

\n

\n PCRE_UCP

\n

Esta opción cambia la forma en que PCRE procesa \\B, \\b, \\D, \\d, \\S, \\s, \\W, \\w y algunas de las clases de caracteres POSIX. Por defecto, solo se reconocen los caracteres ASCII, pero si se establece PCRE_UCP, se utilizan propiedades Unicode en su lugar para clasificar los caracteres. Se proporcionan más detalles en la sección sobre tipos de caracteres genéricos en la página\n pcrepattern. Si establece PCRE_UCP, la coincidencia de uno de los elementos que afecta tarda mucho más. La opción solo está disponible si PCRE se ha compilado con soporte de propiedades Unicode.

\n PCRE_UNGREEDY

\n

Esta opción invierte la \"codicia\" de los cuantificadores\n para que no sean codiciosos por defecto, sino que se vuelvan codiciosos si van seguidos de \"?\"\n . No es compatible con Perl. También se puede establecer mediante una configuración de opción (?U) dentro del patrón.

\n PCRE_UTF8

\n

Esta opción hace que PCRE considere tanto el patrón como el sujeto\n como cadenas de caracteres UTF-8 en lugar de cadenas de un solo byte. Sin embargo, solo está disponible cuando PCRE se compila para incluir soporte UTF. Si no es así, el uso de esta opción provoca un error. Los detalles sobre cómo esta opción cambia el comportamiento de PCRE se proporcionan en la página\n pcreunicode.

\n

Cuando se establece PCRE_UTF8, se comprueba automáticamente la validez del patrón como cadena UTF-8.\n Hay una discusión sobre la validez de las cadenas UTF-8 en la página\n pcreunicode. ESTUDIO DE UN PATRÓN

pcre_extra *pcre_study(const pcre *code, int options,
     const char **errptr);

Si un patrón compilado se va a usar varias veces, vale la pena dedicarle más tiempo al análisis para acelerar el tiempo de coincidencia. La función pcre_study() toma un puntero a un patrón compilado como su primer argumento. Si el estudio del patrón produce información adicional que ayudará a acelerar la coincidencia, pcre_study() devuelve un puntero a un bloque pcre_extra, en el cual el campo study_data apunta a los resultados del estudio.

El valor retornado por pcre_study() puede pasarse directamente a pcre_exec() o pcre_dfa_exec(). Sin embargo, un bloque pcre_extra también contiene otros campos que el llamador puede establecer antes de pasar el bloque; estos se describen a continuación en la sección sobre coincidencia de un patrón.

Si el estudio del patrón no produce ninguna información útil, pcre_study() devuelve NULL por defecto. En esa circunstancia, si el programa llamador desea pasar alguno de los otros campos a pcre_exec() o pcre_dfa_exec(), debe configurar su propio bloque pcre_extra. Sin embargo, si se llama a pcre_study() con la opción PCRE_STUDY_EXTRA_NEEDED, devuelve un bloque pcre_extra incluso si el estudio no encontró información adicional. Aún así puede devolver NULL si ocurre un error en pcre_study().

El segundo argumento de pcre_study() contiene bits de opción. Hay tres opciones adicionales además de PCRE_STUDY_EXTRA_NEEDED:


PCRE_STUDY_JIT_COMPILE
PCRE_STUDY_JIT_PARTIAL_HARD_COMPILE
PCRE_STUDY_JIT_PARTIAL_SOFT_COMPILE

Si alguna de estas está establecida y el compilador just-in-time está disponible, el patrón se compila aún más en código máquina que se ejecuta mucho más rápido que la función de coincidencia interpretativa pcre_exec(). Si el compilador just-in-time no está disponible, estas opciones se ignoran. Todos los bits no definidos en el argumento options deben ser cero.

La compilación JIT es una optimización de alto nivel. Puede llevar tiempo analizar los patrones, y para coincidencias únicas y patrones simples, el beneficio de una ejecución más rápida podría verse compensado por un tiempo de estudio mucho más lento. No todos los patrones pueden ser optimizados por el compilador JIT. Para aquellos que no pueden ser manejados, la coincidencia recurre automáticamente al intérprete de pcre_exec(). Para más detalles, consulte la documentación de pcrejit.

El tercer argumento para pcre_study() es un puntero para un mensaje de error. Si el estudio tiene éxito (incluso si no se devuelve ningún dato), la variable a la que apunta se establece en NULL. De lo contrario, se establece para apuntar a un mensaje de error textual. Esta es una cadena estática que forma parte de la biblioteca. No debe intentar liberarla. Debe probar el puntero de error para que sea NULL después de llamar a pcre_study(), para asegurarse de que se ha ejecutado correctamente.

Cuando haya terminado con un patrón, puede liberar la memoria utilizada para los datos del estudio llamando a pcre_free_study(). Esta función se agregó a la API para la versión 8.20. Para versiones anteriores, la memoria podía liberarse con pcre_free(), al igual que el patrón mismo. Esto seguirá funcionando en casos donde no se usa la optimización JIT, pero es aconsejable cambiar a la nueva función cuando sea conveniente.

Esta es una forma típica en que se usa pcre_study() (excepto que en una aplicación real debería haber pruebas de errores):


int rc;
pcre *re;
pcre_extra *sd;
re = pcre_compile("patrón", 0, &error, &erroroffset, NULL);
sd = pcre_study(
re, /* resultado de pcre_compile() */
0, /* sin opciones */
&error); /* establecido a NULL o apunta a un mensaje */
rc = pcre_exec( /* ver abajo para detalles de las opciones de pcre_exec() */
re, sd, "sujeto", 7, 0, 0, ovector, 30);
...
pcre_free_study(sd);
pcre_free(re);

Estudiar un patrón hace dos cosas: primero, se calcula un límite inferior para la longitud de la cadena sujeto que se necesita para que el patrón coincida. Esto no significa que haya cadenas de esa longitud que coincidan, pero garantiza que ninguna cadena más corta coincida. El valor se usa para evitar perder tiempo intentando coincidir con cadenas más cortas que el límite inferior. Puede conocer el valor en un programa llamador a través de la función pcre_fullinfo().

Estudiar un patrón también es útil para patrones no anclados que no tienen un único carácter de inicio fijo. Se crea un mapa de bits de posibles bytes de inicio. Esto acelera la búsqueda de una posición en el sujeto desde la cual comenzar la coincidencia. (En modo de 16 bits, el mapa de bits se usa para valores de 16 bits menores que 256. En modo de 32 bits, el mapa de bits se usa para valores de 32 bits menores que 256).

Estas dos optimizaciones se aplican tanto a pcre_exec() como a pcre_dfa_exec(), y la información también es utilizada por el compilador JIT. Las optimizaciones pueden deshabilitarse estableciendo la opción PCRE_NO_START_OPTIMIZE. Podría querer hacer esto si su patrón contiene llamadas o (*MARK) y desea utilizar estas facilidades en casos donde la coincidencia falla.

PCRE_NO_START_OPTIMIZE se puede especificar en tiempo de compilación o en tiempo de ejecución. Sin embargo, si PCRE_NO_START_OPTIMIZE se pasa a pcre_exec(), (es decir, después de que haya ocurrido cualquier compilación JIT) la ejecución JIT se deshabilita. Para que la ejecución JIT funcione con PCRE_NO_START_OPTIMIZE, la opción debe establecerse en tiempo de compilación.

Hay una discusión más extensa sobre PCRE_NO_START_OPTIMIZE a continuación.

SOPORTE DE LOCALIDAD

PCRE maneja la coincidencia sin distinción entre mayúsculas y minúsculas, y determina si los caracteres son letras, dígitos o cualquier otra cosa, mediante referencia a un conjunto de tablas, indexadas por el punto de código del carácter. Al ejecutarse en modo UTF-8, o en las bibliotecas de 16 o 32 bits, esto se aplica solo a los caracteres con puntos de código inferiores a 256. Por defecto, los puntos de código de mayor valor nunca coinciden con escapes como \w o \d. Sin embargo, si PCRE se compila con soporte de propiedades Unicode, todos los caracteres pueden ser probados con \p y \P, o, alternativamente, la opción PCRE_UCP puede establecerse al compilar un patrón; esto hace que \w y similares utilicen el soporte de propiedades Unicode en lugar de las tablas incorporadas.

El uso de locales con Unicode no se recomienda. Si está manejando caracteres con puntos de código mayores a 128, debería usar soporte Unicode, o usar locales, pero no intentar mezclar ambos.

PCRE contiene un conjunto interno de tablas que se utilizan cuando el último argumento de pcre_compile() es NULL. Estas son suficientes para muchas aplicaciones. Normalmente, las tablas internas solo reconocen caracteres ASCII. Sin embargo, cuando se compila PCRE, es posible hacer que las tablas internas se reconstruyan en el

TABLAS DE CARACTERES

PCRE utiliza tablas internas para definir las propiedades de los caracteres (por ejemplo, si son letras o números) para el rango de caracteres extendido (valores de caracteres entre 128 y 255). Estas tablas se basan en la configuración regional (locale) que estaba en vigor cuando se compiló PCRE desde su código fuente. Si esta configuración regional no es la configuración regional predeterminada del sistema "C", las tablas internas podrían ser diferentes de las que se obtendrían si se invocara la función pcre_maketables() en la configuración regional predeterminada del sistema.

Las tablas internas siempre pueden ser anuladas por tablas suministradas por la aplicación que llama a PCRE. Estas pueden crearse en una configuración regional diferente de la predeterminada. A medida que más y más aplicaciones cambian al uso de Unicode, se espera que la necesidad de este soporte de configuración regional desaparezca.

Las tablas externas se construyen llamando a la función pcre_maketables(), que no tiene argumentos, en la configuración regional relevante. El resultado puede pasarse luego a pcre_compile() tantas veces como sea necesario. Por ejemplo, para construir y utilizar tablas que sean apropiadas para la configuración regional francesa (donde los caracteres acentuados con valores superiores a 128 se tratan como letras), se podría utilizar el siguiente código:


setlocale(LC_CTYPE, "fr_FR");
tables = pcre_maketables();
re = pcre_compile(..., tables);

El nombre de la configuración regional "fr_FR" se usa en Linux y otros sistemas similares a Unix; si está utilizando Windows, el nombre para la configuración regional francesa es "french".

Cuando se ejecuta pcre_maketables(), las tablas se construyen en memoria que se obtiene a través de pcre_malloc. Es responsabilidad del llamador asegurarse de que la memoria que contiene las tablas permanezca disponible durante el tiempo que sea necesaria.

El puntero que se pasa a pcre_compile() se guarda con el patrón compilado, y las mismas tablas se utilizan a través de este puntero por pcre_study() y también por pcre_exec() y pcre_dfa_exec(). Por lo tanto, para cualquier patrón individual, la compilación, el estudio y la coincidencia ocurren todos en la misma configuración regional, pero diferentes patrones pueden ser procesados en diferentes configuraciones regionales.

Es posible pasar un puntero de tabla o NULL (indicando el uso de las tablas internas) a pcre_exec() o pcre_dfa_exec() (ver la discusión a continuación en la sección sobre la coincidencia de un patrón). Esta facilidad se proporciona para su uso con patrones precompilados que se han guardado y recargado. Las tablas de caracteres no se guardan con los patrones, por lo que si se utilizó una tabla no estándar en el momento de la compilación, debe proporcionarse nuevamente cuando se intente coincidir el patrón recargado. Intentar usar esta facilidad para hacer coincidir un patrón en una configuración regional diferente de aquella en la que se compiló es probable que conduzca a resultados anómalos (generalmente incorrectos).

La función pcre_fullinfo() devuelve información sobre un patrón compilado. Reemplaza a la función pcre_info(), que fue eliminada de la biblioteca en la versión 8.30, después de más de 10 años de obsolescencia.

El primer argumento para pcre_fullinfo() es un puntero al patrón compilado. El segundo argumento es el resultado de pcre_study(), o NULL si el patrón no fue estudiado. El tercer argumento especifica qué información se requiere, y el cuarto argumento es un puntero a una variable para recibir los datos. El valor de retorno de la función es cero en caso de éxito, o uno de los siguientes números negativos:


PCRE_ERROR_NULL el argumento code era NULL
el argumento where era NULL
PCRE_ERROR_BADMAGIC el "número mágico" no se encontró
PCRE_ERROR_BADENDIANNESS el patrón se compiló con una endianidad
diferente
PCRE_ERROR_BADOPTION el valor de what era inválido
PCRE_ERROR_UNSET el campo solicitado no está establecido

El "número mágico" se coloca al principio de cada patrón compilado como una verificación simple contra el paso de un puntero de memoria arbitrario. El error de endianidad puede ocurrir si un patrón compilado se guarda y se recarga en un host diferente. Aquí hay una llamada típica de pcre_fullinfo(), para obtener la longitud del patrón compilado:


int rc;
size_t length;
rc = pcre_fullinfo(
re, /* resultado de pcre_compile() */
sd, /* resultado de pcre_study(), o NULL */
PCRE_INFO_SIZE, /* qué se requiere */
&length); /* dónde poner los datos */

Los valores posibles para el tercer argumento se definen en pcre.h, y son los siguientes:


PCRE_INFO_BACKREFMAX

Devuelve el número de la referencia inversa más alta en el patrón. El cuarto argumento debe apuntar a una variable de tipo int. Se devuelve cero si no hay referencias inversas.


PCRE_INFO_CAPTURECOUNT

Devuelve el número de subpatrones de captura en el patrón. El cuarto argumento debe apuntar a una variable de tipo int.


PCRE_INFO_DEFAULT_TABLES

Devuelve un puntero a las tablas de caracteres internas predeterminadas dentro de PCRE. El cuarto argumento debe apuntar a una variable de tipo unsigned char *. Esta llamada de información se proporciona para uso interno de la función pcre_study(). Los llamadores externos pueden hacer que PCRE utilice sus tablas internas pasando un puntero de tabla NULL.


PCRE_INFO_FIRSTBYTE (obsoleto)

Devuelve información sobre la primera unidad de datos de cualquier cadena coincidente, para un patrón no anclado. El nombre de esta opción se refiere a la biblioteca de 8 bits, donde las unidades de datos son bytes. El cuarto argumento debe apuntar a una variable de tipo int. Se utilizan valores negativos para casos especiales. Sin embargo, esto significa que cuando la biblioteca de 32 bits está en modo no UTF-32, no se puede devolver el rango completo de 32 bits de caracteres. Por esta razón, este valor está obsoleto; utilice PCRE_INFO_FIRSTCHARACTERFLAGS y PCRE_INFO_FIRSTCHARACTER en su lugar.

Si hay un primer valor fijo, por ejemplo, la letra "c" de un patrón como (cat|cow|coyote), se devuelve su valor. En la biblioteca de 8 bits, el valor siempre es inferior a 256. En la biblioteca de 16 bits, el valor puede ser hasta 0xffff. En la biblioteca de 32 bits, el valor puede ser hasta 0x10ffff.

Si no hay un primer valor fijo, y si:

(a) el patrón se compiló con la opción PCRE_MULTILINE, y cada rama comienza con "^", o

(b) cada rama del patrón comienza con ".*" y PCRE_DOTALL no está configurado (si lo estuviera, el patrón estaría anclado),

se devuelve -1, lo que indica que el patrón solo coincide al principio de una cadena de sujeto o después de cualquier salto de línea dentro de la cadena. De lo contrario, se devuelve -2. Para patrones anclados, se devuelve -2.


PCRE_INFO_FIRSTCHARACTER

Devuelve el valor de la primera unidad de datos (carácter no UTF) de cualquier cadena coincidente en la situación donde PCRE_INFO_FIRSTCHARACTERFLAGS devuelve 1; de lo contrario, devuelve 0. El cuarto argumento debe apuntar a una variable de tipo uint_t.

En la biblioteca de 8 bits, el valor siempre es inferior a 256. En la biblioteca de 16 bits, el valor puede ser hasta 0xffff. En la biblioteca de 32 bits en modo UTF-32, el valor puede ser hasta 0x10ffff, y hasta 0xffffffff cuando no se utiliza el modo UTF-32.


PCRE_INFO_FIRSTCHARACTERFLAGS

Devuelve información sobre la primera unidad de datos de cualquier cadena coincidente, para un patrón no anclado. El cuarto argumento debe apuntar a una variable de tipo int.

Si hay un primer valor fijo, por ejemplo, la letra "c" de un patrón como (cat|cow|coyote), se devuelve 1, y el valor del carácter se puede recuperar usando PCRE_INFO_FIRSTCHARACTER. Si no hay un primer valor fijo, y si:

(a) el patrón se compiló con la opción PCRE_MULTILINE, y cada rama comienza con "^", o

(b) cada rama del patrón comienza con ".*" y PCRE_DOTALL no está configurado (si lo estuviera, el patrón estaría anclado),

se devuelve 2, lo que indica que el patrón solo coincide al principio de una cadena de sujeto o después de cualquier salto de línea dentro de la cadena. De lo contrario, se devuelve 0. Para patrones anclados, se devuelve 0.


PCRE_INFO_FIRSTTABLE

Si el patrón fue estudiado, y esto resultó en la construcción de una tabla de 256 bits que indica un conjunto fijo de valores para la primera unidad de datos en cualquier cadena coincidente, se devuelve un puntero a la tabla. De lo contrario, se devuelve NULL. El cuarto argumento debe apuntar a una variable de tipo unsigned char *.


PCRE_INFO_HASCRORLF

Devuelve 1 si el patrón contiene alguna coincidencia explícita para los caracteres CR o LF, de lo contrario 0. El cuarto argumento debe apuntar a una variable de tipo int. Una coincidencia explícita es un carácter CR o LF literal, o \r o \n.


PCRE_INFO_JCHANGED

Devuelve 1 si la configuración de opción (?J) o (?-J) se utiliza en el patrón, de lo contrario 0. El cuarto argumento debe apuntar a una variable de tipo int. (?J) y (?-J) establecen y desestablecen respectivamente la opción local PCRE_DUPNAMES.


PCRE_INFO_JIT

Devuelve 1 si el patrón fue estudiado con una de las opciones JIT, y la compilación just-in-time fue exitosa. El cuarto argumento debe apuntar a una variable de tipo int. Un valor de retorno de 0 significa que el soporte JIT no está disponible en esta versión de PCRE, o que el patrón no fue estudiado con una opción JIT, o que el compilador JIT no pudo manejar este patrón en particular. Consulte la documentación de pcrejit para obtener detalles sobre lo que se puede y no se puede manejar.


PCRE_INFO_JITSIZE

Si el patrón fue estudiado exitosamente con una opción JIT, devuelve el tamaño del código compilado JIT, de lo contrario devuelve cero. El cuarto argumento debe apuntar a una variable de tipo size_t.


PCRE_INFO_LASTLITERAL

Devuelve el valor de la unidad de datos literal más a la derecha que debe existir en cualquier cadena coincidente, aparte de su inicio, si tal valor ha sido registrado. El cuarto argumento debe apuntar a una variable de tipo int. Si no existe tal valor, se devuelve -1. Para patrones anclados, un valor literal final solo se registra si sigue algo de longitud variable. Por ejemplo, para el patrón /^a\d+z\d+/, se devuelve el valor "z", pero para /^a\dz\d/, se devuelve -1.

INFORMACIÓN SOBRE EL PATRÓN COMPILADO

Hay una serie de solicitudes de información que se pueden hacer sobre un patrón compilado usando la función pcre_fullinfo().

El primer argumento es el patrón compilado que se va a consultar. El segundo argumento es un valor que especifica qué información se desea. El tercer argumento debe apuntar a una variable de tipo apropiado para recibir la información. El cuarto argumento es el tamaño de esa variable.

Las solicitudes de información disponibles son:

— PCRE_INFO_BACKTRACK_LIMIT
Si el patrón estableció un límite de retroceso mediante la inclusión de un elemento de la forma (*LIMIT_BACKTRACK=nnnn) al principio, se devuelve su valor. El cuarto argumento debe apuntar a una variable de tipo unsigned long int. Si no se ha establecido dicho valor, la llamada a pcre_fullinfo() devuelve el error PCRE_ERROR_UNSET.
— PCRE_INFO_LASTGC
Si se ha especificado un grupo de captura en el patrón, este valor es el número de ese grupo. Los grupos se numeran secuencialmente empezando por 1. Si hay grupos de captura, se devuelve su número más alto. Si no hay grupos de captura, se devuelve 0. El cuarto argumento debe apuntar a una variable int.
— PCRE_INFO_LASTLINE
Si se ha especificado un grupo de captura en el patrón, este valor es el número de línea del patrón en el que apareció por última vez. Si el patrón no se compila de forma extendida, esta información no se registra. El cuarto argumento debe apuntar a una variable int.
— PCRE_INFO_MATCH_LIMIT
Si el patrón estableció un límite de coincidencias mediante la inclusión de un elemento de la forma (*LIMIT_MATCH=nnnn) al principio, se devuelve su valor. El cuarto argumento debe apuntar a una variable unsigned long int. Si no se ha establecido dicho valor, la llamada a pcre_fullinfo() devuelve el error PCRE_ERROR_UNSET.
— PCRE_INFO_MAXLOOKBEHIND
Devuelve la longitud en caracteres (NB no unidades de datos) de la aserción de retroceso más larga del patrón. Esta información es útil cuando se realizan coincidencias de segmentos múltiples utilizando las funciones de coincidencia parcial. Tenga en cuenta que las aserciones simples \b y \B requieren un retroceso de un carácter. \A también registra un retroceso de un carácter, aunque en realidad no inspecciona el carácter anterior. Esto es para garantizar que se conserve al menos un carácter del segmento antiguo al procesar un nuevo segmento. De lo contrario, si no hay retrocesos en el patrón, \A podría coincidir incorrectamente al principio de un nuevo segmento.
— PCRE_INFO_MINLENGTH
Si el patrón se estudió y se calculó una longitud mínima para las cadenas de texto de coincidencia, se devuelve su valor. De lo contrario, el valor devuelto es -1. El valor es un número de caracteres, que en modo UTF puede ser diferente del número de unidades de datos. El cuarto argumento debe apuntar a una variable de tipo int. Un valor no negativo es un límite inferior a la longitud de cualquier cadena coincidente. Puede que no haya ninguna cadena de esa longitud que coincida realmente, pero todas las cadenas que coincidan tendrán al menos esa longitud.
— PCRE_INFO_NAMECOUNT
— PCRE_INFO_NAMEENTRYSIZE
— PCRE_INFO_NAMETABLE
PCRE admite el uso de paréntesis de captura con nombre, así como numerados. Los nombres son solo una forma adicional de identificar los paréntesis, que aún así obtienen números. Se proporcionan varias funciones de conveniencia, como pcre_get_named_substring(), para extraer subcadenas capturadas por nombre. También es posible extraer los datos directamente, convirtiendo primero el nombre en un número para acceder a los punteros correctos en el vector de salida (descrito con pcre_exec() a continuación). Para realizar la conversión, debe utilizar el mapa de nombres a números, que se describe mediante estos tres valores.

El mapa consta de un número de entradas de tamaño fijo. PCRE_INFO_NAMECOUNT proporciona el número de entradas y PCRE_INFO_NAMEENTRYSIZE proporciona el tamaño de cada entrada; ambos devuelven un valor int. El tamaño de la entrada depende de la longitud del nombre más largo. PCRE_INFO_NAMETABLE devuelve un puntero a la primera entrada de la tabla. Se trata de un puntero a char en la biblioteca de 8 bits, donde los dos primeros bytes de cada entrada son el número del paréntesis de captura, con el byte más significativo primero. En la biblioteca de 16 bits, el puntero apunta a unidades de datos de 16 bits, la primera de las cuales contiene el número del paréntesis. En la biblioteca de 32 bits, el puntero apunta a unidades de datos de 32 bits, la primera de las cuales contiene el número del paréntesis. El resto de la entrada es el nombre correspondiente, terminado en nulo.

Los nombres están en orden alfabético. Si se utiliza (?| para crear múltiples grupos con el mismo número, como se describe en la sección sobre números de subpatrón duplicados en la página pcrepattern, los grupos pueden tener el mismo nombre, pero solo hay una entrada en la tabla. No se permiten nombres diferentes para grupos del mismo número. Se permiten nombres duplicados para subpatrones con números diferentes, pero solo si se establece PCRE_DUPNAMES. Aparecen en la tabla en el orden en que se encontraron en el patrón. En ausencia de (?| esto es el orden de número creciente; cuando se usa (?| esto no es necesariamente así, ya que los subpatrones posteriores pueden tener números más bajos.

Como ejemplo sencillo de la tabla de nombres/números, considere el siguiente patrón después de la compilación por la biblioteca de 8 bits (asuma que PCRE_EXTENDED está establecido, por lo que se ignoran los espacios en blanco, incluidas las nuevas líneas):


(?<date> (?<year>(\d\d)?\d\d) -
(?<month>\d\d) - (?<day>\d\d) )

Hay cuatro subpatrones con nombre, por lo que la tabla tiene cuatro entradas, y cada entrada de la tabla tiene ocho bytes de longitud. La tabla es la siguiente, con bytes no imprimibles mostrados en hexadecimal y bytes indefinidos mostrados como ??:


00 01 d a t e 00 ??
00 05 d a y 00 ?? ??
00 04 m o n t h 00
00 02 y e a r 00 ??

Al escribir código para extraer datos de subpatrones con nombre utilizando el mapa de nombres a números, recuerde que la longitud de las entradas probablemente será diferente para cada patrón compilado.


PCRE_INFO_OKPARTIAL

Devuelve 1 si el patrón se puede utilizar para coincidencias parciales con pcre_exec(), de lo contrario, 0. El cuarto argumento debe apuntar a una variable int. A partir de la versión 8.00, esto siempre devuelve 1, ya que se han levantado las restricciones que anteriormente se aplicaban a las coincidencias parciales. La documentación pcrepartial proporciona detalles sobre las coincidencias parciales.


PCRE_INFO_OPTIONS

Devuelve una copia de las opciones con las que se compiló el patrón. El cuarto argumento debe apuntar a una variable unsigned long int. Estos bits de opción son los especificados en la llamada a pcre_compile(), modificados por cualquier configuración de opción de nivel superior al principio del propio patrón. En otras palabras, son las opciones que estarán en vigor cuando comience la coincidencia. Por ejemplo, si el patrón /(?im)abc(?-i)d/ se compila con la opción PCRE_EXTENDED, el resultado es PCRE_CASELESS, PCRE_MULTILINE y PCRE_EXTENDED.

PCRE ancla automáticamente un patrón si todas sus alternativas de nivel superior comienzan con uno de los siguientes:


^ a menos que PCRE_MULTILINE esté configurado
\A siempre
\G siempre
.* si PCRE_DOTALL está configurado y no hay referencias inversas
al subpatrón en el que aparece .*

Para tales patrónes, el bit PCRE_ANCHORED se establece en las opciones devueltas por pcre_fullinfo().


PCRE_INFO_RECURSIONLIMIT

Si el patrón estableció un límite de recursión al incluir un elemento de la forma (*LIMIT_RECURSION=nnnn) al principio, se devuelve el valor. El cuarto argumento debe apuntar a un entero sin signo de 32 bits. Si no se ha establecido dicho valor, la llamada a pcre_fullinfo() devuelve el error PCRE_ERROR_UNSET.


PCRE_INFO_SIZE

Devuelve el tamaño del patrón compilado en bytes (para las tres bibliotecas). El cuarto argumento debe apuntar a una variable de tipo size_t. Este valor no incluye el tamaño de la estructura pcre que devuelve pcre_compile(). El valor que se pasa como argumento a pcre_malloc() cuando pcre_compile() está obteniendo memoria en la que colocar los datos compilados es el valor devuelto por esta opción más el tamaño de la estructura pcre. Estudiar un patrón compilado, con o sin JIT, no altera el valor devuelto por esta opción.


PCRE_INFO_STUDYSIZE

Devuelve el tamaño en bytes (para las tres bibliotecas) del bloque de datos al que apunta el campo study_data en un bloque pcre_extra. Si pcre_extra es NULL, o no hay datos de estudio, se devuelve cero. El cuarto argumento debe apuntar a una variable de tipo size_t. El campo study_data lo establece pcre_study() para registrar información que acelerará la coincidencia (consulte la sección titulada "Estudio de un patrón" arriba). El formato del bloque study_data es privado, pero su longitud se pone a disposición a través de esta opción para que pueda guardarse y restaurarse (consulte la documentación pcreprecompile para obtener más detalles).


PCRE_INFO_REQUIREDCHARFLAGS

Devuelve 1 si hay una unidad de datos literal más a la derecha que debe existir en cualquier cadena coincidente, que no sea al principio. El cuarto argumento debe apuntar a una variable int. Si no existe dicho valor, se devuelve 0. Si se devuelve 1, el valor real del carácter se puede recuperar utilizando PCRE_INFO_REQUIREDCHAR.

Para patrónes anclados, el último valor literal solo se registra si sigue a algo de longitud variable. Por ejemplo, para el patrón /^a\d+z\d+/ se devuelve el valor 1 (con "z" devuelto por PCRE_INFO_REQUIREDCHAR), pero para /^a\dz\d/ el valor devuelto es 0.


PCRE_INFO_REQUIREDCHAR

Devuelve el valor de la unidad de datos literal más a la derecha que debe existir en cualquier cadena coincidente, que no sea al principio, si se ha registrado dicho valor. El cuarto argumento debe apuntar a una variable uint32_t. Si no existe dicho valor, se devuelve 0.

CONTADORES DE REFERENCIA

int pcre_refcount(pcre *code, int adjust);

La función pcre_refcount() se utiliza para mantener un contador de referencias en el bloque de datos que contiene un patrón compilado. Se proporciona para beneficio de aplicaciones que operan de manera orientada a objetos, donde diferentes partes de la aplicación pueden estar utilizando el mismo patrón compilado, pero desea liberar el bloque cuando todas hayan terminado.

Cuando se compila un patrón, el campo del contador de referencias se inicializa a cero. Solo se modifica llamando a esta función, cuya acción es sumar el valor adjust (que puede ser positivo o negativo) a él. El resultado de la función es el nuevo valor. Sin embargo, el valor del contador está restringido a estar entre 0 y 65535, ambos inclusive. Si el nuevo valor está fuera de estos límites, se fuerza al límite apropiado.

Excepto cuando es cero, el contador de referencias no se conserva correctamente si un patrón se compila en un host y luego se transfiere a un host cuyo orden de bytes es diferente. (Este parece ser un escenario muy poco probable.)

int pcre_exec(const pcre *code, const pcre_extra *extra,
     const char *subject, int length, int startoffset,
     int options, int *ovector, int ovecsize);

La función pcre_exec() se llama para hacer coincidir una cadena de texto de sujeto con un patrón compilado, que se pasa en el argumento code. Si el patrón se estudió, el resultado del estudio debe pasarse en el argumento extra. Puede llamar a pcre_exec() con los mismos argumentos code y extra tantas veces como desee, para hacer coincidir diferentes cadenas de texto con el mismo patrón.

Esta función es la principal instalación de coincidencia de la biblioteca y opera de manera similar a Perl. Para uso especializado, también existe una función de coincidencia alternativa, que se describe a continuación en la sección sobre la función pcre_dfa_exec().

En la mayoría de las aplicaciones, el patrón se habrá compilado (y opcionalmente estudiado) en el mismo proceso que llama a pcre_exec(). Sin embargo, es posible guardar patrónes compilados y datos de estudio, y luego usarlos más tarde en diferentes procesos, posiblemente incluso en diferentes hosts. Para una discusión sobre esto, consulte la documentación pcreprecompile.

int ovector[30];

NULL, /* no tenemos */

Datos adicionales para pcre_exec()

Si el argumento extra no es NULL, debe apuntar a un bloque de datos pcre_extra. La función pcre_study() devuelve dicho bloque (cuando no devuelve NULL), pero también puedes crear uno por tu cuenta y pasar información adicional en él. El bloque pcre_extra contiene los siguientes campos (no necesariamente en este orden):


unsigned long int flags;
void *study_data;
void *executable_jit;
unsigned long int match_limit;
unsigned long int match_limit_recursion;
void *callout_data;
const unsigned char *tables;
unsigned char **mark;

En la versión de 16 bits de esta estructura, el campo mark tiene el tipo "PCRE_UCHAR16 **".

En la versión de 32 bits de esta estructura, el campo mark tiene el tipo "PCRE_UCHAR32 **".

El campo flags se utiliza para especificar cuáles de los otros campos están establecidos. Los bits de bandera son:


PCRE_EXTRA_CALLOUT_DATA
PCRE_EXTRA_EXECUTABLE_JIT
PCRE_EXTRA_MARK
PCRE_EXTRA_MATCH_LIMIT
PCRE_EXTRA_MATCH_LIMIT_RECURSION
PCRE_EXTRA_STUDY_DATA
PCRE_EXTRA_TABLES

Otros bits de bandera deben establecerse a cero. El campo study_data y, a veces, el campo executable_jit se establecen en el bloque pcre_extra que devuelve pcre_study(), junto con los bits de bandera apropiados. No debes establecerlos tú mismo, pero puedes añadir al bloque estableciendo otros campos y sus bits de bandera correspondientes.

El campo match_limit proporciona un medio para evitar que PCRE consuma una gran cantidad de recursos al ejecutar patrones que no van a coincidir, pero que tienen un número muy grande de posibilidades en sus árboles de búsqueda. El ejemplo clásico es un patrón que utiliza repeticiones anidadas ilimitadas.

Internamente, pcre_exec() utiliza una función llamada match(), que llama repetidamente (a veces recursivamente). El límite establecido por match_limit se impone al número de veces que se llama a esta función durante una coincidencia, lo que tiene el efecto de limitar la cantidad de retroceso (backtracking) que puede tener lugar. Para patrones que no están anclados, el contador se reinicia desde cero para cada posición en la cadena sujeto.

Cuando se llama a pcre_exec() con un patrón que se estudió con éxito con una opción JIT, la forma en que se ejecuta la coincidencia es completamente diferente. Sin embargo, todavía existe la posibilidad de que la coincidencia se prolongue durante mucho tiempo, y por lo tanto, el valor de match_limit también se utiliza en este caso (pero de una manera diferente) para limitar cuánto tiempo puede continuar la coincidencia.

El valor predeterminado para el límite se puede establecer al compilar PCRE; el valor predeterminado predeterminado es 10 millones, lo que maneja todos los casos excepto los más extremos. Puedes anular el valor predeterminado proporcionando a pcre_exec() un bloque pcre_extra en el que se establece match_limit y se establece PCRE_EXTRA_MATCH_LIMIT en el campo flags. Si se excede el límite, pcre_exec() devuelve PCRE_ERROR_MATCHLIMIT.

Un valor para el límite de coincidencias también puede ser suministrado por un elemento al principio de un patrón de la forma


(*LIMIT_MATCH=d)

donde d es un número decimal. Sin embargo, tal configuración se ignora a menos que d sea menor que el límite establecido por el llamador de pcre_exec() o, si no se establece ningún límite, menor que el predeterminado.

El campo match_limit_recursion es similar a match_limit, pero en lugar de limitar el número total de veces que se llama a match(), limita la profundidad de la recursión. La profundidad de recursión es un número menor que el número total de llamadas, ya que no todas las llamadas a match() son recursivas. Este límite solo es útil si se establece en un valor menor que match_limit.

Limitar la profundidad de la recursión limita la cantidad de pila de la máquina que se puede utilizar o, cuando PCRE se ha compilado para usar memoria en el heap en lugar de la pila, la cantidad de memoria del heap que se puede utilizar. Este límite no es relevante y se ignora cuando la coincidencia se realiza utilizando código compilado JIT.

El valor predeterminado para match_limit_recursion se puede establecer al compilar PCRE; el valor predeterminado predeterminado es el mismo valor que el predeterminado para match_limit. Puedes anular el valor predeterminado proporcionando a pcre_exec() un bloque pcre_extra en el que se establece match_limit_recursion y se establece PCRE_EXTRA_MATCH_LIMIT_RECURSION en el campo flags. Si se excede el límite, pcre_exec() devuelve PCRE_ERROR_RECURSIONLIMIT.

Un valor para el límite de recursión también puede ser suministrado por un elemento al principio de un patrón de la forma


(*LIMIT_RECURSION=d)

donde d es un número decimal. Sin embargo, tal configuración se ignora a menos que d sea menor que el límite establecido por el llamador de pcre_exec() o, si no se establece ningún límite, menor que el predeterminado.

El campo callout_data se utiliza junto con la función de "callout" y se describe en la documentación de pcrecallout.

El campo tables se proporciona para su uso con patrones que han sido precompilados utilizando tablas de caracteres personalizadas, guardados en disco o en otro lugar, y luego recargados, ya que las tablas que se utilizaron para compilar un patrón no se guardan con él. Consulte la documentación de pcreprecompile para una discusión sobre cómo guardar patrones compilados para su uso posterior. Si se pasa NULL usando este mecanismo, se fuerza el uso de las tablas internas de PCRE.

Advertencia: Las tablas que utiliza pcre_exec() deben ser las mismas que se utilizaron cuando se compiló el patrón. Si no es así, el comportamiento de pcre_exec() no está definido. Por lo tanto, cuando un patrón se compila y se compara en el mismo proceso, este campo nunca debe establecerse. En este caso (el más común), el puntero de tabla correcto se pasa automáticamente desde pcre_compile() a pcre_exec() con el patrón compilado.

Si PCRE_EXTRA_MARK se establece en el campo flags, el campo mark debe establecerse para apuntar a una variable adecuada. Si el patrón contiene algún verbo de control de retroceso como (*MARK:NAME), y la ejecución termina con un nombre para devolver, se coloca un puntero a la cadena de nombre (terminada en cero) en la variable apuntada por el campo mark. Los nombres están dentro del patrón compilado; si deseas retener dicho nombre, debes copiarlo antes de liberar la memoria de un patrón compilado. Si no hay ningún nombre que devolver, la variable apuntada por el campo mark se establece en NULL. Para obtener detalles sobre los verbos de control de retroceso, consulte la sección titulada "Control de retroceso" en la documentación de pcrepattern.

Bits de opción para pcre_exec()

Los bits no utilizados del argumento options para pcre_exec() deben ser cero. Los únicos bits que se pueden establecer son PCRE_ANCHORED, PCRE_NEWLINE_xxx, PCRE_NOTBOL, PCRE_NOTEOL, PCRE_NOTEMPTY, PCRE_NOTEMPTY_ATSTART, PCRE_NO_START_OPTIMIZE, PCRE_NO_UTF8_CHECK, PCRE_PARTIAL_HARD y PCRE_PARTIAL_SOFT.

Si el patrón se estudió con éxito con una de las opciones de compilación just-in-time (JIT), las únicas opciones compatibles para la ejecución JIT son PCRE_NO_UTF8_CHECK, PCRE_NOTBOL, PCRE_NOTEOL, PCRE_NOTEMPTY, PCRE_NOTEMPTY_ATSTART, PCRE_PARTIAL_HARD y PCRE_PARTIAL_SOFT. Si se utiliza una opción no compatible, la ejecución JIT se deshabilita y se ejecuta el código interpretativo normal en pcre_exec().


PCRE_ANCHORED

La opción PCRE_ANCHORED limita pcre_exec() a coincidir en la primera posición de coincidencia. Si un patrón se compiló con PCRE_ANCHORED, o resultó estar anclado por su contenido, no se puede hacer que no esté anclado en el momento de la coincidencia.


PCRE_BSR_ANYCRLF
PCRE_BSR_UNICODE

Estas opciones (que son mutuamente excluyentes) controlan lo que coincide la secuencia de escape \R. La elección es coincidir solo CR, LF o CRLF, o coincidir cualquier secuencia de nueva línea Unicode. Estas opciones anulan la elección que se hizo o se asumió por defecto al compilar el patrón.


PCRE_NEWLINE_CR
PCRE_NEWLINE_LF
PCRE_NEWLINE_CRLF
PCRE_NEWLINE_ANYCRLF
PCRE_NEWLINE_ANY

Estas opciones anulan la definición de nueva línea que se eligió o se asumió por defecto al compilar el patrón. Para más detalles, consulte la descripción de pcre_compile() arriba. Durante la coincidencia, la elección de nueva línea afecta el comportamiento de los metacaracteres punto, circunflejo y dólar. También puede alterar la forma en que se avanza la posición de coincidencia después de un fallo de coincidencia para un patrón no anclado.

Cuando se establece PCRE_NEWLINE_CRLF, PCRE_NEWLINE_ANYCRLF o PCRE_NEWLINE_ANY, y un intento de coincidencia para un patrón no anclado falla cuando la posición actual está en una secuencia CRLF, y el patrón no contiene coincidencias explícitas para caracteres CR o LF, la posición de coincidencia se avanza en dos caracteres en lugar de uno, es decir, después del CRLF.

La regla anterior es un compromiso que hace que los casos más comunes funcionen como se espera. Por ejemplo, si el patrón es .+A (y la opción PCRE_DOTALL no está establecida), no coincide con la cadena "\r\nA" porque, después de fallar al principio, omite tanto el CR como el LF antes de reintentar. Sin embargo, el patrón [\r\n]A sí coincide con esa cadena, ya que contiene una referencia explícita a CR o LF, y por lo tanto avanza solo un carácter después del primer fallo.

Una coincidencia explícita de CR o LF es ya sea una aparición literal de uno de esos caracteres, o una de las secuencias de escape \r o \n. Las coincidencias implícitas como [^X] no cuentan, ni tampoco \s (que incluye CR y LF en los caracteres que coincide).

No obstante lo anterior, todavía pueden ocurrir efectos anómalos cuando CRLF es una secuencia de nueva línea válida y aparecen escapes explícitos \r o \n en el patrón.


PCRE_NOTBOL

Esta opción especifica que el primer carácter de la cadena sujeto no es el principio de una línea, por lo que el metacaracter circunflejo no debería coincidir antes de él. Establecer esto sin PCRE_MULTILINE (en el momento de la compilación) hace que el circunflejo nunca coincida. Esta opción afecta solo al comportamiento del metacaracter circunflejo. No afecta a \A.


PCRE_NOTEOL

Esta opción especifica que el final de la cadena sujeto no es el final de una línea, por lo que el metacaracter dólar no debería coincidir

ni siquiera (excepto en modo multilínea) un salto de línea inmediatamente antes. Establecer esto sin PCRE_MULTILINE (en tiempo de compilación) hace que el dólar nunca coincida. Esta opción solo afecta el comportamiento del metacaracter dólar. No afecta a \Z ni a \z.


PCRE_NOTEMPTY

Una cadena vacía no se considera una coincidencia válida si esta opción está activada. Si hay alternativas en el patrón, se prueban. Si todas las alternativas coinciden con la cadena vacía, la coincidencia completa falla. Por ejemplo, si el patrón


a?b?

se aplica a una cadena que no comienza con "a" ni "b", coincide con una cadena vacía al principio del sujeto. Con PCRE_NOTEMPTY activado, esta coincidencia no es válida, por lo que PCRE busca más adelante en la cadena coincidencias de "a" o "b".


PCRE_NOTEMPTY_ATSTART

Esto es similar a PCRE_NOTEMPTY, excepto que se permite una coincidencia de cadena vacía que no esté al principio del sujeto. Si el patrón está anclado, dicha coincidencia solo puede ocurrir si el patrón contiene \K.

Perl no tiene un equivalente directo de PCRE_NOTEMPTY o PCRE_NOTEMPTY_ATSTART, pero tiene un caso especial de coincidencia de patrón de cadena vacía dentro de su función split(), y al usar el modificador /g. Es posible emular el comportamiento de Perl después de coincidir una cadena nula intentando primero la coincidencia nuevamente en el mismo desplazamiento con PCRE_NOTEMPTY_ATSTART y PCRE_ANCHORED, y luego, si eso falla, avanzando el desplazamiento de inicio (ver más abajo) y volviendo a intentar una coincidencia normal. Hay código que demuestra cómo hacer esto en el programa de ejemplo pcredemo. En el caso más general, debe verificar si la convención de saltos de línea reconoce CRLF como un salto de línea y, si es así, y el carácter actual es CR seguido de LF, avanzar el desplazamiento de inicio en dos caracteres en lugar de uno.


PCRE_NO_START_OPTIMIZE

Hay una serie de optimizaciones que pcre_exec() utiliza al inicio de una coincidencia, para acelerar el proceso. Por ejemplo, si se sabe que una coincidencia no anclada debe comenzar con un carácter específico, busca en el sujeto ese carácter y falla inmediatamente si no puede encontrarlo, sin ejecutar realmente la función de coincidencia principal. Esto significa que un elemento especial como (*COMMIT) al principio de un patrón no se considera hasta después de que se haya encontrado un punto de partida adecuado para la coincidencia. Además, cuando se usan llamadas de retorno o elementos (*MARK), estas optimizaciones de "inicio" pueden hacer que se omitan si el patrón nunca se usa realmente. Las optimizaciones de inicio son, en efecto, un pre-escaneo del sujeto que tiene lugar antes de que se ejecute el patrón.

La opción PCRE_NO_START_OPTIMIZE deshabilita las optimizaciones de inicio, lo que posiblemente afecte el rendimiento, pero asegura que en los casos en que el resultado sea "sin coincidencia", las llamadas de retorno ocurran, y que elementos como (*COMMIT) y (*MARK) se consideren en cada posición de inicio posible en la cadena del sujeto. Si PCRE_NO_START_OPTIMIZE se establece en tiempo de compilación, no se puede desestablecer en tiempo de coincidencia. El uso de PCRE_NO_START_OPTIMIZE en tiempo de coincidencia (es decir, pasarlo a pcre_exec()) deshabilita la ejecución JIT; en esta situación, las coincidencias se realizan siempre de forma interpretativa.

Establecer PCRE_NO_START_OPTIMIZE puede cambiar el resultado de una operación de coincidencia. Considere el patrón


(*COMMIT)ABC

Cuando esto se compila, PCRE registra el hecho de que una coincidencia debe comenzar con el carácter "A". Supongamos que la cadena del sujeto es "DEFABC". La optimización de inicio escanea la cadena del sujeto, encuentra "A" y ejecuta el primer intento de coincidencia desde allí. El elemento (*COMMIT) significa que el patrón debe coincidir con la posición de inicio actual, lo que en este caso, ocurre. Sin embargo, si la misma coincidencia se ejecuta con PCRE_NO_START_OPTIMIZE activado, el escaneo inicial de la cadena del sujeto no ocurre. El primer intento de coincidencia se ejecuta comenzando desde "D" y, cuando falla, (*COMMIT) evita que se intenten coincidencias adicionales, por lo que el resultado general es "sin coincidencia". Si el patrón se estudia, se pueden usar más optimizaciones de inicio. Por ejemplo, se puede registrar una longitud mínima para el sujeto. Considere el patrón


(*MARK:A)(X|Y)

La longitud mínima de una coincidencia es un carácter. Si el sujeto es "ABC", habrá intentos de coincidir con "ABC", "BC", "C" y finalmente una cadena vacía. Si el patrón se estudia, el intento final no tiene lugar, porque PCRE sabe que el sujeto es demasiado corto, y por lo tanto (*MARK) nunca se encuentra. En este caso, estudiar el patrón no afecta el resultado general de la coincidencia, que sigue siendo "sin coincidencia", pero afecta la información auxiliar que se devuelve.


PCRE_NO_UTF8_CHECK

Cuando PCRE_UTF8 está activado en tiempo de compilación, la validez del sujeto como cadena UTF-8 se comprueba automáticamente cuando pcre_exec() se llama posteriormente. Toda la cadena se comprueba antes de que se realice cualquier otro procesamiento. El valor de startoffset también se comprueba para asegurar que apunte al inicio de un carácter UTF-8. Hay una discusión sobre la validez de las cadenas UTF-8 en la página pcreunicode. Si se encuentra una secuencia de bytes inválida, pcre_exec() devuelve el error PCRE_ERROR_BADUTF8 o, si PCRE_PARTIAL_HARD está activado y el problema es un carácter truncado al final del sujeto, PCRE_ERROR_SHORTUTF8. En ambos casos, también se puede devolver información sobre la naturaleza precisa del error (ver las descripciones de estos errores en la sección titulada Valores de retorno de error de pcre_exec() más abajo). Si startoffset contiene un valor que no apunta al inicio de un carácter UTF-8 (o al final del sujeto), se devuelve PCRE_ERROR_BADUTF8_OFFSET.

Si ya sabe que su sujeto es válido y desea omitir estas comprobaciones por motivos de rendimiento, puede establecer la opción PCRE_NO_UTF8_CHECK al llamar a pcre_exec(). Es posible que desee hacer esto para la segunda y posteriores llamadas a pcre_exec() si está realizando llamadas repetidas para encontrar todas las coincidencias en una sola cadena de sujeto. Sin embargo, debe asegurarse de que el valor de startoffset apunte al inicio de un carácter (o al final del sujeto). Cuando PCRE_NO_UTF8_CHECK está activado, el efecto de pasar una cadena inválida como sujeto o un valor inválido de startoffset no está definido. Su programa puede fallar o entrar en un bucle.


PCRE_PARTIAL_HARD
PCRE_PARTIAL_SOFT

Estas opciones activan la función de coincidencia parcial. Por compatibilidad con versiones anteriores, PCRE_PARTIAL es un sinónimo de PCRE_PARTIAL_SOFT. Se produce una coincidencia parcial si se llega al final de la cadena del sujeto con éxito, pero no hay suficientes caracteres del sujeto para completar la coincidencia. Si esto ocurre cuando PCRE_PARTIAL_SOFT (pero no PCRE_PARTIAL_HARD) está activado, la coincidencia continúa probando las alternativas restantes. Solo si no se puede encontrar una coincidencia completa, se devuelve PCRE_ERROR_PARTIAL en lugar de PCRE_ERROR_NOMATCH. En otras palabras, PCRE_PARTIAL_SOFT indica que el llamador está preparado para manejar una coincidencia parcial, pero solo si no se puede encontrar una coincidencia completa.

Si PCRE_PARTIAL_HARD está activado, anula PCRE_PARTIAL_SOFT. En este caso, si se encuentra una coincidencia parcial, pcre_exec() devuelve inmediatamente PCRE_ERROR_PARTIAL, sin considerar ninguna otra alternativa. En otras palabras, cuando PCRE_PARTIAL_HARD está activado, una coincidencia parcial se considera más importante que una coincidencia completa alternativa.

En ambos casos, la porción de la cadena que se inspeccionó cuando se encontró la coincidencia parcial se establece como la primera cadena coincidente. Hay una discusión más detallada sobre la coincidencia parcial y de varios segmentos, con ejemplos, en la documentación pcrepartial.

La cadena a coincidir por pcre_exec()

La cadena del sujeto se pasa a pcre_exec() como un puntero en subject, una longitud en length y un desplazamiento de inicio en startoffset. Las unidades para length y startoffset son bytes para la biblioteca de 8 bits, elementos de datos de 16 bits para la biblioteca de 16 bits y elementos de datos de 32 bits para la biblioteca de 32 bits.

Si startoffset es negativo o mayor que la longitud del sujeto, pcre_exec() devuelve PCRE_ERROR_BADOFFSET. Cuando el desplazamiento de inicio es cero, la búsqueda de una coincidencia comienza al principio del sujeto, y este es, con mucho, el caso más común. En modo UTF-8 o UTF-16, el desplazamiento debe apuntar al inicio de un carácter, o al final del sujeto (en modo UTF-32, una unidad de datos equivale a un carácter, por lo que todos los desplazamientos son válidos). A diferencia de la cadena del patrón, el sujeto puede contener ceros binarios.

Un desplazamiento de inicio distinto de cero es útil al buscar otra coincidencia en el mismo sujeto llamando a pcre_exec() nuevamente después de un éxito previo. Establecer startoffset difiere de simplemente pasar una cadena acortada y establecer PCRE_NOTBOL en el caso de un patrón que comienza con algún tipo de búsqueda hacia atrás. Por ejemplo, considere el patrón


\Biss\B

que encuentra ocurrencias de "iss" en medio de palabras. (\B coincide solo si la posición actual en el sujeto no es un límite de palabra). Cuando se aplica a la cadena "Mississippi", la primera llamada a pcre_exec() encuentra la primera ocurrencia. Si se vuelve a llamar a pcre_exec() solo con el resto del sujeto, es decir, "issippi", no coincide, porque \B siempre es falso al principio del sujeto, que se considera un límite de palabra. Sin embargo, si se pasa la cadena completa nuevamente a pcre_exec(), pero con startoffset establecido en 4, encuentra la segunda ocurrencia de "iss" porque puede mirar detrás del punto de inicio para descubrir que está precedido por una letra.

Encontrar todas las coincidencias en un sujeto es complicado cuando el patrón puede coincidir con una cadena vacía. Es posible emular el comportamiento /g de Perl intentando primero la coincidencia nuevamente en el mismo desplazamiento, con las opciones PCRE_NOTEMPTY_ATSTART y PCRE_ANCHORED, y luego, si eso falla, avanzando el desplazamiento de inicio y volviendo a intentar una coincidencia normal. Hay código que demuestra cómo hacer esto en el programa de ejemplo pcredemo. En el caso más general, debe verificar si la convención de saltos de línea reconoce CRLF como un salto de línea y, si es así, y el carácter actual es CR seguido de LF, avanzar el desplazamiento de inicio en dos caracteres en lugar de uno.

Si se pasa un desplazamiento de inicio distinto de cero cuando el patrón está anclado, se realiza un intento de coincidencia en el desplazamiento dado. Esto solo puede tener éxito si el patrón no requiere que la coincidencia esté al principio del sujeto.

Cómo pcre_exec() devuelve subcadenas capturadas

How pcre_exec() returns captured substrings

In general, a pattern matches a certain portion of the subject, and in addition, further substrings from the subject may be picked out by parts of the pattern. Following the usage in Jeffrey Friedl's book, this is called "capturing" in what follows, and the phrase "capturing subpattern" is used for a fragment of a pattern that picks out a substring. PCRE supports several other kinds of parenthesized subpattern that do not cause substrings to be captured.

Captured substrings are returned to the caller via a vector of integers whose address is passed in ovector. The number of elements in the vector is passed in ovecsize, which must be a non-negative number. Note: this argument is NOT the size of ovector in bytes.

The first two-thirds of the vector is used to pass back captured substrings, each substring using a pair of integers. The remaining third of the vector is used as workspace by pcre_exec() while matching capturing subpatterns, and is not available for passing back information. The number passed in ovecsize should always be a multiple of three. If it is not, it is rounded down.

When a match is successful, information about captured substrings is returned in pairs of integers, starting at the beginning of ovector, and continuing up to two-thirds of its length at the most. The first element of each pair is set to the offset of the first character in a substring, and the second is set to the offset of the first character after the end of a substring. These values are always data unit offsets, even in UTF mode. They are byte offsets in the 8-bit library, 16-bit data item offsets in the 16-bit library, and 32-bit data item offsets in the 32-bit library. Note: they are not character counts.

The first pair of integers, ovector[0] and ovector[1], identify the portion of the subject string matched by the entire pattern. The next pair is used for the first capturing subpattern, and so on. The value returned by pcre_exec() is one more than the highest numbered pair that has been set. For example, if two substrings have been captured, the returned value is 3. If there are no capturing subpatterns, the return value from a successful match is 1, indicating that just the first pair of offsets has been set.

If a capturing subpattern is matched repeatedly, it is the last portion of the string that it matched that is returned.

If the vector is too small to hold all the captured substring offsets, it is used as far as possible (up to two-thirds of its length), and the function returns a value of zero. If neither the actual string matched nor any captured substrings are of interest, pcre_exec() may be called with ovector passed as NULL and ovecsize as zero. However, if the pattern contains back references and the ovector is not big enough to remember the related substrings, PCRE has to get additional memory for use during matching. Thus it is usually advisable to supply an ovector of reasonable size.

There are some cases where zero is returned (indicating vector overflow) when in fact the vector is exactly the right size for the final match. For example, consider the pattern


(a)(?:(b)c|bd)

If a vector of 6 elements (allowing for only 1 captured substring) is given with subject string "abd", pcre_exec() will try to set the second captured string, thereby recording a vector overflow, before failing to match "c" and backing up to try the second alternative. The zero return, however, does correctly indicate that the maximum number of slots (namely 2) have been filled. In similar cases where there is temporary overflow, but the final number of used slots is actually less than the maximum, a non-zero value is returned.

The pcre_fullinfo() function can be used to find out how many capturing subpatterns there are in a compiled pattern. The smallest size for ovector that will allow for n captured substrings, in addition to the offsets of the substring matched by the whole pattern, is (n+1)*3.

It is possible for capturing subpattern number n+1 to match some part of the subject when subpattern n has not been used at all. For example, if the string "abc" is matched against the pattern (a|(z))(bc) the return from the function is 4, and subpatterns 1 and 3 are matched, but 2 is not. When this happens, both values in the offset pairs corresponding to unused subpatterns are set to -1.

Offset values that correspond to unused subpatterns at the end of the expression are also set to -1. For example, if the string "abc" is matched against the pattern (abc)(x(yz)?)? subpatterns 2 and 3 are not matched. The return from the function is 2, because the highest used capturing subpattern number is 1, and the offsets for for the second and third capturing subpatterns (assuming the vector is large enough, of course) are set to -1.

Note: Elements in the first two-thirds of ovector that do not correspond to capturing parentheses in the pattern are never changed. That is, if a pattern contains n capturing parentheses, no more than ovector[0] to ovector[2n+1] are set by pcre_exec(). The other elements (in the first two-thirds) retain whatever values they previously had.

Some convenience functions are provided for extracting the captured substrings as separate strings. These are described below.

Error return values from pcre_exec()

If pcre_exec() fails, it returns a negative number. The following are defined in the header file:


PCRE_ERROR_NOMATCH (-1)

The subject string did not match the pattern.


PCRE_ERROR_NULL (-2)

Either code or subject was passed as NULL, or ovector was NULL and ovecsize was not zero.


PCRE_ERROR_BADOPTION (-3)

An unrecognized bit was set in the options argument.


PCRE_ERROR_BADMAGIC (-4)

PCRE stores a 4-byte "magic number" at the start of the compiled code, to catch the case when it is passed a junk pointer and to detect when a pattern that was compiled in an environment of one endianness is run in an environment with the other endianness. This is the error that PCRE gives when the magic number is not present.


PCRE_ERROR_UNKNOWN_OPCODE (-5)

While running the pattern match, an unknown item was encountered in the compiled pattern. This error could be caused by a bug in PCRE or by overwriting of the compiled pattern.


PCRE_ERROR_NOMEMORY (-6)

If a pattern contains back references, but the ovector that is passed to pcre_exec() is not big enough to remember the referenced substrings, PCRE gets a block of memory at the start of matching to use for this purpose. If the call via pcre_malloc() fails, this error is given. The memory is automatically freed at the end of matching.

This error is also given if pcre_stack_malloc() fails in pcre_exec(). This can happen only when PCRE has been compiled with --disable-stack-for-recursion.


PCRE_ERROR_NOSUBSTRING (-7)

This error is used by the pcre_copy_substring(), pcre_get_substring(), and pcre_get_substring_list() functions (see below). It is never returned by pcre_exec().


PCRE_ERROR_MATCHLIMIT (-8)

The backtracking limit, as specified by the match_limit field in a pcre_extra structure (or defaulted) was reached. See the description above.


PCRE_ERROR_CALLOUT (-9)

This error is never generated by pcre_exec() itself. It is provided for use by callout functions that want to yield a distinctive error code. See the pcrecallout documentation for details.


PCRE_ERROR_BADUTF8 (-10)

A string that contains an invalid UTF-8 byte sequence was passed as a subject, and the PCRE_NO_UTF8_CHECK option was not set. If the size of the output vector (ovecsize) is at least 2, the byte offset to the start of the the invalid UTF-8 character is placed in the first element, and a reason code is placed in the second element. The reason codes are listed in the following section. For backward compatibility, if PCRE_PARTIAL_HARD is set and the problem is a truncated UTF-8 character at the end of the subject (reason codes 1 to 5), PCRE_ERROR_SHORTUTF8 is returned instead of PCRE_ERROR_BADUTF8.


PCRE_ERROR_BADUTF8_OFFSET (-11)

The UTF-8 byte sequence that was passed as a subject was checked and found to be valid (the PCRE_NO_UTF8_CHECK option was not set), but the value of startoffset did not point to the beginning of a UTF-8 character or the end of the subject.


PCRE_ERROR_PARTIAL (-12)

The subject string did not match, but it did match partially. See the pcrepartial documentation for details of partial matching.


PCRE_ERROR_BADPARTIAL (-13)

This code is no longer in use. It was formerly returned when the PCRE_PARTIAL option was used with a compiled pattern containing items that were not supported for partial matching. From release 8.00 onwards, there are no restrictions on partial matching.


PCRE_ERROR_INTERNAL (-14)

An unexpected internal error has occurred. This error could be caused by a bug in PCRE or by overwriting of the compiled pattern.


PCRE_ERROR_BADCOUNT (-15)

This error is given if the value of the ovecsize argument is negative.


PCRE_ERROR_RECURSIONLIMIT (-21)

The internal recursion limit, as specified by the match_limit_recursion field in a pcre_extra structure (or defaulted) was reached. See the description above.


PCRE_ERROR_BADNEWLINE (-23)

An invalid combination of PCRE_NEWLINE_xxx options was given.


PCRE_ERROR_BADOFFSET (-24)

The value of startoffset was negative or greater than the length of the subject, that is, the value in length.


PCRE_ERROR_SHORTUTF8 (-25)

This error is returned instead of PCRE_ERROR_BADUTF8 when the subject string ends with a truncated UTF-8 character and the PCRE_PARTIAL_HARD option is set. Information about the failure is returned as for PCRE_ERROR_BADUTF8. It is in fact sufficient to detect this case, but

Este código de error especial PCRE_PARTIAL_HARD precede a la implementación de la información devuelta; se conserva por compatibilidad con versiones anteriores.


PCRE_ERROR_RECURSELOOP (-26)

Este error se devuelve cuando pcre_exec() detecta un bucle de recursión dentro del patrón. Específicamente, significa que o bien el patrón completo o un subpatrón ha sido llamado recursivamente por segunda vez en la misma posición de la cadena sujeto. Este error se produce si se llama a pcre_exec() con un valor negativo para el argumento length.

Los códigos de razón se nombran en el archivo de encabezado pcre.h:

PCRE_UTF8_ERR7
PCRE_UTF8_ERR8
PCRE_UTF8_ERR9

Los dos bits más significativos del segundo, tercer, cuarto, quinto o sexto byte del carácter no tienen el valor binario 0b10 (es decir, o el bit más significativo es 0, o el siguiente bit es 1).


PCRE_UTF8_ERR11
PCRE_UTF8_ERR12

El primer byte de un carácter tiene el valor 0xfe o 0xff. Estos valores nunca pueden ocurrir en una cadena UTF-8 válida.

EXTRACCIÓN DE SUBSTRINGS CAPTURADAS POR NÚMERO

int pcre_copy_substring(const char *subject, int *ovector,
 int stringcount, int stringnumber, char *buffer,
 int buffersize);

int pcre_get_substring(const char *subject, int *ovector,
 int stringcount, int stringnumber,
 const char **stringptr);

int pcre_get_substring_list(const char *subject,
 int *ovector, int stringcount, const char ***listptr);

Las subcadenas capturadas se pueden acceder directamente utilizando los desplazamientos devueltos por pcre_exec() en ovector. Para mayor comodidad, se proporcionan las funciones pcre_copy_substring(), pcre_get_substring() y pcre_get_substring_list() para extraer subcadenas capturadas como cadenas nuevas y separadas, terminadas en nulo. Estas funciones identifican las subcadenas por número. La siguiente sección describe las funciones para extraer subcadenas con nombre.

Una subcadena que contiene un cero binario se extrae correctamente y tiene un cero adicional al final, pero el resultado no es, por supuesto, una cadena C. Sin embargo, puede procesar dicha cadena refiriéndose a la longitud que se devuelve por pcre_copy_substring() y pcre_get_substring(). Desafortunadamente, la interfaz de pcre_get_substring_list() no es adecuada para manejar cadenas que contienen ceros binarios, porque el final de la cadena final no se indica de forma independiente.

Los tres primeros argumentos son los mismos para las tres funciones: subject es la cadena sujeto que acaba de ser comparada con éxito, ovector es un puntero al vector de desplazamientos enteros que se pasó a pcre_exec(), y stringcount es el número de subcadenas que fueron capturadas por la coincidencia, incluida la subcadena que coincidió con la expresión regular completa. Este es el valor devuelto por pcre_exec() si es mayor que cero. Si pcre_exec() devolvió cero, lo que indica que se quedó sin espacio en ovector, el valor pasado como stringcount debe ser el número de elementos en el vector dividido por tres.

Las funciones pcre_copy_substring() y pcre_get_substring() extraen una sola subcadena, cuyo número se proporciona como stringnumber. Un valor de cero extrae la subcadena que coincidió con el patrón completo, mientras que los valores más altos extraen las subcadenas capturadas. Para pcre_copy_substring(), la cadena se coloca en buffer, cuya longitud se da por buffersize, mientras que para pcre_get_substring() se obtiene un nuevo bloque de memoria a través de pcre_malloc, y su dirección se devuelve a través de stringptr. El resultado de la función es la longitud de la cadena, sin incluir el cero terminador, o uno de estos códigos de error:


PCRE_ERROR_NOMEMORY (-6)

El búfer era demasiado pequeño para pcre_copy_substring(), o el intento de obtener memoria falló para pcre_get_substring().


PCRE_ERROR_NOSUBSTRING (-7)

No hay ninguna subcadena cuyo número sea stringnumber.

La función pcre_get_substring_list() extrae todas las subcadenas disponibles y crea una lista de punteros a ellas. Todo esto se hace en un único bloque de memoria que se obtiene a través de pcre_malloc. La dirección del bloque de memoria se devuelve a través de listptr, que también es el inicio de la lista de punteros a cadenas. El final de la lista está marcado por un puntero NULL. El resultado de la función es cero si todo salió bien, o el código de error


PCRE_ERROR_NOMEMORY (-6)

si el intento de obtener el bloque de memoria falló.

Cuando cualquiera de estas funciones encuentra una subcadena que no está establecida, lo que puede suceder cuando el subpatrón de captura número n+1 coincide con alguna parte del sujeto, pero el subpatrón n no se ha utilizado en absoluto, devuelven una cadena vacía. Esto se puede distinguir de una subcadena genuina de longitud cero inspeccionando el desplazamiento apropiado en ovector, que es negativo para las subcadenas no establecidas.

Las dos funciones de conveniencia pcre_free_substring() y pcre_free_substring_list() se pueden utilizar para liberar la memoria devuelta por una llamada anterior de pcre_get_substring() o pcre_get_substring_list(), respectivamente. No hacen más que llamar a la función apuntada por pcre_free, que por supuesto podría ser llamada directamente desde un programa C. Sin embargo, PCRE se utiliza en algunas situaciones en las que se enlaza a través de una interfaz especial a otro lenguaje de programación que no puede usar pcre_free directamente; es para estos casos que se proporcionan las funciones.

EXTRACCIÓN DE UNA SUBcadena POR NOMBRE

Para extraer una subcadena por nombre, primero debes encontrar el número asociado. Por ejemplo, para este patrón


(a+)b(?<xxx>\d+)...

el número de la subcadena llamada "xxx" es 2. Si se sabe que el nombre es único (no se estableció PCRE_DUPNAMES), puedes encontrar el número a partir del nombre llamando a pcre_get_stringnumber(). El primer argumento es el patrón compilado y el segundo es el nombre. El resultado de la función es el número de subcadena, o PCRE_ERROR_NOSUBSTRING (-7) si no hay ninguna subcadena con ese nombre.

Dado el número, puedes extraer la subcadena directamente o utilizar una de las funciones descritas en la sección anterior. Para mayor comodidad, también hay dos funciones que realizan todo el trabajo.

La mayoría de los argumentos de pcre_copy_named_substring() y pcre_get_named_substring() son los mismos que los de las funciones con nombres similares que extraen por número. Como estas se describen en la sección anterior, no se vuelven a describir aquí. Solo hay dos diferencias:

Primero, en lugar de un número de subcadena, se proporciona un nombre de subcadena. Segundo, hay un argumento adicional, dado al principio, que es un puntero al patrón compilado. Esto es necesario para poder acceder a la tabla de traducción de nombres a números.

Estas funciones llaman a pcre_get_stringnumber() y, si tiene éxito, luego llaman a pcre_copy_substring() o pcre_get_substring(), según corresponda. **NOTA:** Si se establece PCRE_DUPNAMES y existen nombres duplicados, el comportamiento puede no ser el que deseas (ver la siguiente sección).

**Advertencia:** Si el patrón utiliza la característica (?| para configurar múltiples subcadenas con el mismo número, como se describe en la sección sobre números de subcadenas duplicados en la página pcrepattern, no puedes usar nombres para distinguir las diferentes subcadenas, porque los nombres no se incluyen en el código compilado. El proceso de coincidencia solo utiliza números. Por esta razón, el uso de diferentes nombres para subcadenas del mismo número causa un error en tiempo de compilación.

NOMBRES DE SUBcadena DUPLICADOS

int pcre_get_stringtable_entries(const pcre *code,
     const char *name, char **first, char **last);

Cuando un patrón se compila con la opción PCRE_DUPNAMES, los nombres para las subcadenas no tienen que ser únicos. (Los nombres duplicados siempre están permitidos para subcadenas con el mismo número, creadas al usar la característica (?|. De hecho, si dichas subcadenas tienen nombre, se requiere que usen los mismos nombres).

Normalmente, los patrones con nombres duplicados son tales que en cualquier coincidencia individual, solo una de las subcadenas con nombre participa. Se muestra un ejemplo en la documentación de pcrepattern.

Cuando existen duplicados, pcre_copy_named_substring() y pcre_get_named_substring() devuelven la primera subcadena correspondiente al nombre dado que esté establecida. Si ninguna está establecida, se devuelve PCRE_ERROR_NOSUBSTRING (-7); no se devuelven datos. La función pcre_get_stringnumber() devuelve uno de los números asociados al nombre, pero no se define cuál es.

Si deseas obtener detalles completos de todas las subcadenas capturadas para un nombre dado, debes usar la función pcre_get_stringtable_entries(). El primer argumento es el patrón compilado y el segundo es el nombre. El tercero y el cuarto son punteros a variables que son actualizadas por la función. Después de que se ejecute, apuntarán a la primera y última entrada en la tabla de nombres a números para el nombre dado. La función en sí devuelve la longitud de cada entrada, o PCRE_ERROR_NOSUBSTRING (-7) si no hay ninguna. El formato de la tabla se describe anteriormente en la sección titulada *Información sobre un patrón*.

Dado todas las entradas relevantes para el nombre, puedes extraer cada uno de sus números y, por lo tanto, los datos capturados, si los hay.

ENCONTRAR TODAS LAS COINCIDENCIAS POSIBLES

La función de coincidencia tradicional utiliza un algoritmo similar a Perl, que se detiene cuando encuentra la primera coincidencia, comenzando en un punto dado de la cadena sujeto. Si deseas encontrar todas las coincidencias posibles, o la coincidencia más larga posible, considera usar la función de coincidencia alternativa (ver abajo) en su lugar. Si no puedes usar la función alternativa, pero aún necesitas encontrar todas las coincidencias posibles, puedes simularlo utilizando la instalación de llamada externa (callout facility), que se describe en la documentación de pcrecallout.

Lo que tienes que hacer es insertar una llamada externa justo al final del patrón. Cuando se llame a tu función de llamada externa, extrae y guarda la subcadena coincidente actual. Luego, devuelve 1, lo que obliga a pcre_exec() a retroceder e intentar otras alternativas. Finalmente, cuando se agoten las coincidencias, pcre_exec() devolverá PCRE_ERROR_NOMATCH.

OBTENER UNA ESTIMACIÓN DEL USO DE LA PILA

La coincidencia de ciertos patrones usando pcre_exec() puede consumir mucha pila de procesos, la cual en ciertos entornos puede ser bastante limitada en tamaño. A algunos usuarios les resulta útil tener una estimación de la cantidad de pila que utiliza pcre_exec(), para ayudarles a establecer límites de recursión, como se describe en la documentación de pcrestack. La estimación que se muestra en pcretest cuando se llama con las opciones -m y -C se obtiene llamando a pcre_exec con los valores NULL, NULL, NULL, -999 y -999 para sus primeros cinco argumentos.

Normalmente, si su primer argumento es NULL, pcre_exec() devuelve inmediatamente el código de error negativo PCRE_ERROR_NULL, pero con esta combinación especial de argumentos, devuelve en su lugar un número negativo cuyo valor absoluto es el tamaño aproximado del marco de pila en bytes. (Se usa un número negativo para que quede claro que no ha ocurrido ninguna coincidencia). El valor es aproximado porque en algunos casos, se producen llamadas recursivas a pcre_exec() cuando hay una o dos variables adicionales en la pila.

Si PCRE se ha compilado para usar el heap en lugar de la pila para la recursión, el valor devuelto es el tamaño de cada bloque que se obtiene del heap.

COINCIDIR UN PATRÓN: LA FUNCIÓN ALTERNATIVA

int pcre_dfa_exec(const pcre *code, const pcre_extra *extra,
     const char *subject, int length, int startoffset,
     int options, int *ovector, int ovecsize,
     int *workspace, int wscount);

La función pcre_dfa_exec() se llama para hacer coincidir una cadena sujeto con un patrón compilado, utilizando un algoritmo de coincidencia que escanea la cadena sujeto solo una vez y no retrocede. Esto tiene características diferentes al algoritmo normal y no es compatible con Perl. Algunas de las características de los patrones PCRE no son compatibles. Sin embargo, hay momentos en los que este tipo de coincidencia puede ser útil. Para una discusión de los dos algoritmos de coincidencia y una lista de las características que pcre_dfa_exec() no admite, consulte la documentación de pcrematching.

Los argumentos de la función pcre_dfa_exec() son los mismos que los de pcre_exec(), más dos adicionales. El argumento ovector se utiliza de manera diferente, y esto se describe a continuación. Los otros argumentos comunes se utilizan de la misma manera que para pcre_exec(), por lo que su descripción no se repite aquí.

Los dos argumentos adicionales proporcionan espacio de trabajo para la función. El vector de espacio de trabajo debe contener al menos 20 elementos. Se utiliza para rastrear múltiples rutas a través del árbol del patrón. Se necesitará más espacio de trabajo para patrones y sujetos donde hay muchas coincidencias potenciales.

Aquí hay un ejemplo de una llamada simple a pcre_dfa_exec():


int rc;
int ovector[10];
int wspace[20];

Bits de opción para pcre_dfa_exec()

Los bits no utilizados del argumento options para pcre_dfa_exec() deben ser cero. Los únicos bits que se pueden establecer son PCRE_ANCHORED, PCRE_NEWLINE_xxx, PCRE_NOTBOL, PCRE_NOTEOL, PCRE_NOTEMPTY, PCRE_NOTEMPTY_ATSTART, PCRE_NO_UTF8_CHECK, PCRE_BSR_ANYCRLF, PCRE_BSR_UNICODE, PCRE_NO_START_OPTIMIZE, PCRE_PARTIAL_HARD, PCRE_PARTIAL_SOFT, PCRE_DFA_SHORTEST y PCRE_DFA_RESTART. Todos menos los últimos cuatro son exactamente los mismos que para pcre_exec(), por lo que su descripción no se repite aquí.


PCRE_PARTIAL_HARD
PCRE_PARTIAL_SOFT

Estos tienen el mismo efecto general que en pcre_exec(), pero los detalles son ligeramente diferentes. Cuando se establece PCRE_PARTIAL_HARD para pcre_dfa_exec(), devuelve PCRE_ERROR_PARTIAL si se llega al final del sujeto y todavía hay al menos una posibilidad de coincidencia que requiere caracteres adicionales. Esto sucede incluso si también se han encontrado algunas coincidencias completas. Cuando se establece PCRE_PARTIAL_SOFT, el código de retorno PCRE_ERROR_NOMATCH se convierte en PCRE_ERROR_PARTIAL si se llega al final del sujeto, no ha habido coincidencias completas, pero todavía hay al menos una posibilidad de coincidencia. La porción de la cadena que se inspeccionó cuando se encontró la coincidencia parcial más larga se establece como la primera cadena coincidente en ambos casos. Hay una discusión más detallada sobre coincidencias parciales y de varios segmentos, con ejemplos, en la documentación de pcrepartial.


PCRE_DFA_SHORTEST

Establecer la opción PCRE_DFA_SHORTEST hace que el algoritmo de coincidencia se detenga tan pronto como haya encontrado una coincidencia. Debido a la forma en que funciona el algoritmo alternativo, esta es necesariamente la coincidencia más corta posible en el primer punto de coincidencia posible en la cadena sujeto.


PCRE_DFA_RESTART

Cuando pcre_dfa_exec() devuelve una coincidencia parcial, es posible llamarla nuevamente, con caracteres sujeto adicionales, y que continúe con la misma coincidencia. La opción PCRE_DFA_RESTART solicita esta acción; cuando se establece, las opciones workspace y wscount deben hacer referencia al mismo vector que antes porque los datos sobre la coincidencia hasta el momento se dejan en ellos después de una coincidencia parcial. Hay más discusión sobre esto.
