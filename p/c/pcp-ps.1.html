PCP-PS(1) Manual de Comandos Generales PCP-PS(1)

NOMBRE

pcp-ps - Informar estadísticas de procesos de Linux.

SINOPSIS

pcp [opciones de pcp] ps [-e] [-U [nombre de usuario]] [-V --version] [-c Nombre del comando] [-P pid1,pid2..] [-p pid1,pid2..] [-o col1,col2... o ALL] [-Z zona horaria] [-z] [-?]

DESCRIPCIÓN

El comando pcp-ps se utiliza para monitorizar procesos individuales en ejecución en el sistema. Utilizando varias opciones, ayuda al usuario a ver información útil relacionada con los procesos. Esta información incluye el porcentaje de CPU, el uso de memoria y pila, la programación y la prioridad. Por defecto, pcp-ps informa datos en vivo para el host local.

OPCIONES

Cuando se invoca a través del comando pcp(1), las opciones -h/--host, -O/--origin, -t/--interval, -Z/--timezone y varias otras *opciones de pcp* están indirectamente disponibles; consulte PCPIntro(1) para una descripción completa de estas opciones.

Las opciones adicionales de línea de comandos disponibles para pcp-ps son:

-e
Mostrar todos los procesos.
PID Identificador del proceso.
TTY La terminal asociada al proceso.
TIME El tiempo acumulado de CPU en formato [DD-]hh:mm:ss (tiempo=TIEMPO).
CMD El nombre de la tarea junto con sus argumentos completos.
-c [nombre del comando]
Mostrar el nombre real del Comando de las tareas monitorizadas en lugar del UID. Si se especifica *nombre del comando*, solo se mostrarán las tareas que pertenecen al comando especificado.
-U [nombre de usuario], --nombre-usuario[=nombre de usuario]
Mostrar el nombre real del usuario de las tareas monitorizadas en lugar del UID. Si se especifica *nombre de usuario*, solo se mostrarán las tareas que pertenecen al usuario especificado.
-V, --version
Imprimir el número de versión y salir.
-p pid1,pid2.., --lista-pid=pid1,pid2..
Mostrar solo procesos con los PID listados.
-P ppid1,ppid2.., --lista-ppid=ppid1,ppid2..
Mostrar solo procesos con los PPID listados.
-o
Formato definido por el usuario.

Es un único argumento en forma de lista separada por espacios o comas, que ofrece una forma de especificar columnas de salida individuales.

Los argumentos para -o son los siguientes:

COL ENCABEZADO DESCRIPCIÓN
%cpu %CPU utilización de cpu del proceso
%mem %MEM memoria física en la máquina expresada como un porcentaje
start INICIO hora en que comenzó el comando
time TIEMPO tiempo acumulado de cpu, usuario + sistema
cls CLS clase de programación del proceso.
cmd CMD ver Nombre de tarea. (alias args, comando).
args COMANDO Para mostrar el nombre completo del programa con sus argumentos (usar en la última posición de la lista -o para ver el comando completo)
pid PID El ID del proceso
ppid PPID ID del proceso padre
pri PRI Prioridad del proceso
state S ver s
rss RSS la memoria física no intercambiada que ha utilizado una tarea
rtprio RTPRIO prioridad en tiempo real
pname Pname Nombre del proceso
tty TT tty (terminal) de control
uid UID ver euid
uname USER ver euser
vsize VSZ ver vsz
wchan WCHAN nombre de la función del kernel en la que el proceso está durmiendo

ESPECIFICADORES DE FORMATO ESTÁNDAR

Aquí están las diferentes palabras clave que se pueden usar para controlar el formato de salida (por ejemplo, con la opción -o) o para ordenar los procesos seleccionados.

Por ejemplo: pcp-ps -o pid,user,args

CÓDIGO ENCABEZADO DESCRIPCIÓN
pid PID un número que representa el ID del proceso
%cpu %CPU % de utilización de la CPU del proceso en formato "##.#". Actualmente, es el tiempo de CPU utilizado dividido por el tiempo que el proceso ha estado ejecutándose (relación tiempo de cpu/tiempo real), expresado como un porcentaje.
%mem %MEM % de la relación del tamaño del conjunto residente del proceso con la memoria física de la máquina, expresado como un porcentaje.
args COMANDO Comando con todos sus argumentos como una cadena. Se pueden mostrar modificaciones a los argumentos. La salida en esta columna puede contener espacios. Un proceso marcado como <defunct> está parcialmente muerto, esperando a ser completamente destruido por su padre. A veces los argumentos del proceso no estarán disponibles; cuando esto ocurra, se imprimirá el nombre del ejecutable entre corchetes.
class CLS clase de programación del proceso. Los valores posibles del campo son: - no se informa TS SCHED_OTHER FF SCHED_FIFO RR SCHED_RR B SCHED_BATCH ISO SCHED_ISO IDL SCHED_IDLE DLN SCHED_DEADLINE ? valor desconocido
s S visualización mínima del estado. Ver también state si desea que se muestre información adicional.
euid EUID ID de usuario efectivo.
vsz VSZ tamaño de memoria virtual del proceso en KiB (unidades de 1024 bytes). Las asignaciones de dispositivos están excluidas actualmente; esto está sujeto a cambios.
euser EUSER nombre de usuario efectivo. Este será el ID de usuario textual, si se puede obtener y el ancho del campo lo permite, o una representación decimal en caso contrario.
All N/A Esta opción muestra USER, PID, PPID, PRI, %CPU, %MEM, VSZ, RSS, S, START, TIME, WCHAN y COMMAND.
-Z zona horaria, --zona-horaria=zona horaria
Por defecto, pcp-ps informa la hora del día según la zona horaria local del sistema donde se ejecuta pcp-ps. La opción -Z cambia la zona horaria a *zona horaria* en el formato de la variable de entorno TZ como se describe en environ(7).
-z , --zonahost
Cambiar la zona horaria de informe a la zona horaria local en el host que es (se cortó el texto aquí)

pcp-ps(1) — PCP Performance Co-Pilot

NAME

pcp-ps(1) - Información de procesos de PCP

SYNOPSIS

pcp-ps [OPCIÓN…] [archivo_pcp]

DESCRIPTION

La utilidad pcp-ps muestra información sobre los procesos que se están ejecutando en un sistema monitorizado por PCP. Su objetivo es ser compatible en línea de comandos y salida con la utilidad ps(1).

Cuando se utiliza para inspeccionar un archivo_pcp que contiene datos de procesos, pcp-ps puede mostrar información histórica.

OPTIONS

-a archivo_pcp
Lee el historial de procesos del archivo_pcp especificado. Si no se especifica, se utiliza el valor predeterminado de los archivos de historial de PCP.
-e
Muestra todos los procesos.
-f
Muestra procesos en formato de pantalla completa.
-g pgrp
Muestra procesos con el grupo de procesos dado.
-j pid
Muestra procesos con el identificador de proceso (PID) dado.
-l
Muestra procesos en formato largo.
-n host…
Se conecta a un host PCP remoto para obtener información de procesos. Múltiples hosts pueden ser especificados, separados por comas.
-o formato
Especifica el formato de salida utilizando especificadores de formato estándar de ps(1).
-p pid
Muestra procesos con los PIDs especificados.
-t tid
Muestra procesos con los identificadores de hilo (TID) especificados.
-u usuario
Muestra procesos del usuario especificado.
-z
Establece la zona horaria de informe para los datos de tiempo en el fichero de archivo. Por defecto, los informes se generan en la zona horaria local. Esto es útil al reproducir un archivo PCP que se capturó en una zona horaria diferente.
-? , ​​--help
Muestra el mensaje de uso y sale.

STANDARD FORMAT SPECIFIERS

pcp-ps soporta la mayoría de los especificadores de formato definidos en ps(1), incluyendo:

  • pid - ID del proceso
  • ppid - ID del proceso padre
  • pgid - ID del grupo de procesos
  • sid - ID de sesión
  • user - Nombre de usuario
  • uid - ID de usuario
  • group - Nombre del grupo
  • gid - ID de grupo
  • comm - Comando
  • args - Argumentos del comando
  • state - Estado del proceso (ej. R, S, D, Z, T)
  • pcpu - Porcentaje de CPU utilizado
  • pmem - Porcentaje de memoria utilizado
  • stime - Hora de inicio del proceso
  • etime - Tiempo transcurrido desde el inicio del proceso
  • rss - Resident Set Size (memoria física)
  • vsz - Virtual memory size (memoria virtual)

NOTES

pcp-ps se inspira en el comando ps(1) y pretende ser compatible en línea de comandos y salida con él.

PCP ENVIRONMENT

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede utilizarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para ver las variables de entorno que afectan a las herramientas de PCP, consulte pmGetOptions(3).
