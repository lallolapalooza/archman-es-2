PCRE_TABLE(5) Manual de formatos de archivo PCRE_TABLE(5)

NOMBRE

pcre_table - formato de las tablas PCRE de Postfix

SINOPSIS

postmap -q "cadena" pcre:/etc/postfix/nombre_archivo
postmap -q - pcre:/etc/postfix/nombre_archivo <archivo_entrada
postmap -hmq - pcre:/etc/postfix/nombre_archivo <archivo_entrada
postmap -bmq - pcre:/etc/postfix/nombre_archivo <archivo_entrada

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas opcionales para la reescritura de direcciones, el enrutamiento de correo o el control de acceso. Estas tablas suelen estar en formato dbm o db.

Alternativamente, las tablas de consulta se pueden especificar en formato de expresiones regulares compatibles con Perl. En este caso, cada entrada se compara con una lista de patrones. Cuando se encuentra una coincidencia, se devuelve el resultado correspondiente y la búsqueda se termina.

Para saber qué tipos de tablas de consulta admite su sistema Postfix, utilice el comando "postconf -m".

Para probar tablas de consulta, utilice el comando "postmap -q" como se describe en la SINOPSIS anterior. Utilice "postmap -hmq - <archivo>" para patrones de header_checks(5), y "postmap -bmq - <archivo>" para body_checks(5) (Postfix 2.6 y posteriores).

Este controlador puede compilarse con la biblioteca pcre2 (Postfix 3.7 y posteriores), o con la biblioteca pcre heredada (todas las versiones de Postfix).

COMPATIBILIDAD

Con Postfix versión 2.2 y anteriores, especifique "postmap -fq" para consultar una tabla que contenga patrones sensibles a mayúsculas y minúsculas. Los patrones no distinguen entre mayúsculas y minúsculas por defecto.

FORMATO DE TABLA

La forma general de una tabla PCRE es:

/patrón/flags resultado
Cuando patrón coincide con la cadena de entrada, utilice el valor resultado correspondiente.
!/patrón/flags resultado
Cuando patrón no coincide con la cadena de entrada, utilice el valor resultado correspondiente.
if /patrón/flags
endif
Si la cadena de entrada coincide con /patrón/, entonces haga coincidir esa cadena de entrada con los patrones entre if y endif. El bloque if..endif puede anidarse.

Nota: no anteponga espacios en blanco a los patrones dentro de if..endif.

Esta característica está disponible en Postfix 2.1 y posteriores.

if !/patrón/flags
endif
Si la cadena de entrada no coincide con /patrón/, entonces haga coincidir esa cadena de entrada con los patrones entre if y endif. El bloque if..endif puede anidarse.

Nota: no anteponga espacios en blanco a los patrones dentro de if..endif.

Esta característica está disponible en Postfix 2.1 y posteriores.

líneas en blanco y comentarios
Se ignoran las líneas vacías y las líneas que solo contienen espacios en blanco, al igual que las líneas cuyo primer carácter que no es un espacio en blanco es un `#'.
texto multilínea
Una línea lógica comienza con texto que no son espacios en blanco. Una línea que comienza con espacios en blanco continúa una línea lógica.

Cada patrón es una expresión regular similar a la de Perl. El delimitador de la expresión puede ser cualquier carácter no alfanumérico, excepto un espacio en blanco o caracteres que tienen un significado especial (tradicionalmente se usa la barra inclinada). La expresión regular puede contener espacios en blanco.

Por defecto, la coincidencia no distingue entre mayúsculas y minúsculas, y los saltos de línea no se tratan como caracteres especiales. El comportamiento se controla mediante indicadores (flags), que se activan o desactivan añadiendo uno o más de los siguientes caracteres después del patrón:

i (por defecto: activado)
Activa o desactiva el indicador de sensibilidad a mayúsculas y minúsculas. Por defecto, la coincidencia no distingue entre mayúsculas y minúsculas.
m (por defecto: desactivado)
Activa o desactiva el indicador MULTILINE de pcre. Cuando este indicador está activado, los metacaracteres ^ y $ coinciden inmediatamente después y antes de un carácter de salto de línea, respectivamente, además de coincidir al principio y al final de la cadena sujeto.
s (por defecto: activado)
Activa o desactiva el indicador DOTALL de pcre. Cuando este indicador está activado, el metacaracter . coincide con el carácter de salto de línea. Con versiones de Postfix anteriores a la 2.0, el indicador está desactivado por defecto, lo cual es inconveniente para la coincidencia de encabezados de mensajes multilínea.
x (por defecto: desactivado)
Activa o desactiva el indicador extendido de pcre. Cuando este indicador está activado, los caracteres de espacio en blanco en el patrón (que no estén en una clase de caracteres) se ignoran. Para incluir un carácter de espacio en blanco como parte del patrón, escápelo con una barra invertida.

Nota: no utilice #comentario después de los patrones.

A (por defecto: desactivado)
Activa o desactiva el indicador ANCHORED de pcre. Cuando este indicador está activado, el patrón se fuerza a estar "anclado", es decir, se restringe a coincidir solo al principio de la cadena que se está buscando (la "cadena sujeto"). Este efecto también se puede lograr con construcciones apropiadas en el propio patrón.
E (por defecto: desactivado)
Activa o desactiva el indicador DOLLAR_ENDONLY de pcre. Cuando este indicador está activado, un metacaracter $ en el patrón solo coincide al final de la cadena sujeto. Sin este indicador, un dólar también coincide inmediatamente antes del último carácter si este es un carácter de salto de línea (pero no antes de otros caracteres de salto de línea). Este indicador se ignora si el indicador MULTILINE de pcre está activado.
U (por defecto: desactivado)
Activa o desactiva el indicador UNGREEDY de pcre. Cuando este indicador está activado, el motor de coincidencia de patrones invierte la "codicia" de los cuantificadores, de modo que no son codiciosos por defecto, pero se vuelven codiciosos si van seguidos de "?". Este indicador también se puede establecer mediante un modificador (?U) dentro del patrón.
X (por defecto: desactivado)
Activa o desactiva el indicador EXTRA de pcre. Cuando este indicador está activado, cualquier barra invertida en un patrón seguida de una letra que no tiene un significado especial provoca un error, reservando así estas combinaciones para futuras expansiones.

Esta característica no es compatible con PCRE2.

ORDEN DE BÚSQUEDA

Los patrones se aplican en el orden especificado en la tabla, hasta que se encuentra un patrón que coincide con la cadena de entrada.

Cada patrón se aplica a toda la cadena de entrada. Dependiendo de la aplicación, esa cadena es un nombre de host de cliente completo, una dirección IP de cliente completa o una dirección de correo completa. Por lo tanto, no se realiza ninguna búsqueda de dominio padre ni de red padre, y las direcciones de correo usuario@dominio no se dividen en sus partes constituyentes usuario y dominio, ni usuario+foo se divide en usuario y foo.

SUSTITUCIÓN DE TEXTO

La sustitución de subcadenas (texto que coincide con patrones dentro de "()") de la expresión coincidente en la cadena de resultado se solicita con $1, $2, etc.; especifique $$ para producir un carácter $ como salida. Las macros en la cadena de resultado pueden necesitar escribirse como ${n} o $(n) si no van seguidas de espacios en blanco. Esta característica no soporta nombres de subcadenas de pcre2.

Nota: dado que los patrones negados (precedidos por !) devuelven un resultado cuando la expresión no coincide, las sustituciones no están disponibles para patrones negados.

ESPECIFICACIÓN EN LÍNEA

El contenido de una tabla se puede especificar en el nombre de la tabla (Postfix 3.7 y posteriores). La sintaxis básica es:

main.cf:
    parámetro = .. pcre:{ { regla-1 }, { regla-2 } .. } ..
master.cf:
    .. -o { parámetro = .. pcre:{ { regla-1 }, { regla-2 } .. } .. } ..

Postfix expande recursivamente cualquier instancia de $nombre_parámetro en

.

el valor del parámetro anterior, ignora los espacios en blanco después de '{' y antes de '}', y escribe cada regla como una línea de texto en un archivo en memoria:

archivo en memoria:
    regla-1
    regla-2
    ..

Postfix analiza el resultado como si fuera un archivo en /etc/postfix.

CAVEATS DE ESPECIFICACIÓN EN LÍNEA

  • Al usar $nombre_parametro dentro de un patrón en línea, use \Q$nombre_parametro\E para deshabilitar metacaracteres como '.' en la expansión de $nombre_parametro. De lo contrario, el patrón puede tener coincidencias inesperadas.
  • Cuando una regla en línea deba contener $, especifique $$ para evitar que Postfix intente realizar la expansión $nombre mientras evalúa el valor del parámetro. Para verificar una configuración en línea, use la opción "postconf -x" como se muestra a continuación:
  • Cuando una configuración de main.cf "nombre_parametro = valor" contiene una tabla pcre: en línea, use el comando "postconf -x nombre_parametro". Verifique que no haya advertencias de "parámetro indefinido" y que la salida tenga la sintaxis que se usaría en un archivo pcre: de Postfix no en línea.
  • Cuando una anulación de master.cf "-o { nombre_parametro = valor }" contiene una tabla pcre: en línea, use el comando "postconf -Px '*/*/nombre_parametro' ". Verifique que no haya advertencias de "parámetro indefinido" y que la salida tenga la sintaxis que se usaría en un archivo pcre: de Postfix no en línea.

EJEMPLO DE MAPA DE ACCESO SMTPD

# Protege tus exploders de majordomo salientes
/^(?!owner-)(.*)-outgoing@(.*)/ 550 Usa ${1}@${2} en su lugar
# Rebota friend@whatever, excepto cuando whatever es nuestro dominio (sería
# mejor simplemente rebotar todo el correo de friend@ - esto es solo un ejemplo).
/^(friend@(?!my\.domain$).*)$/  550 Pégalo en tu tubería $1
# Una entrada multilínea. El texto se envía como una sola línea.
#
/^noddy@my\.domain$/
 550 Este usuario es peculiar. Realmente no quieres enviarle correos electrónicos,
 ya que solo hace que su cabeza dé vueltas.

EJEMPLO DE MAPA DE FILTRO DE ENCABEZADO

/^Subject: make money fast/     RECHAZAR
/^To: friend@public\.com/       RECHAZAR

EJEMPLO DE MAPA DE FILTRO DE CUERPO

# Primero omite el texto codificado en base64 para ahorrar ciclos de CPU.
# Requiere la versión 3 de PCRE.
~^[[:alnum:]+/]{60,}$~          OK
# Pon tus propios patrones de cuerpo aquí.
