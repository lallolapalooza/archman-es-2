NOMBRE

SINOPSIS

#include <libtecla.h>
PathCache *new_PathCache(void);
PathCache *del_PathCache(PathCache *pc);
int pca_scan_path(PathCache *pc, const char *path);
void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                      void *data);
char *pca_lookup_file(PathCache *pc, const char *name,
                      int name_len, int literal);
const char *pca_last_error(PathCache *pc);
CPL_MATCH_FN(pca_path_completions);

DESCRIPCIÓN

El objeto PathCache forma parte de la biblioteca tecla (ver la página del manual libtecla(3)).

Los objetos PathCache permiten a una aplicación buscar archivos en cualquier lista de directorios separada por dos puntos, como la variable de entorno PATH de ejecución de Unix. Los archivos en directorios absolutos se almacenan en caché en un objeto PathCache, mientras que los directorios relativos se exploran según sea necesario. Usando un objeto PathCache, puedes buscar la ruta completa de un nombre de archivo simple, o puedes obtener una lista de las posibles completaciones de un prefijo de nombre de archivo dado. Por defecto, todos los archivos en la lista de directorios son objetivos para la búsqueda y completación, pero se proporciona un mecanismo versátil para seleccionar solo tipos específicos de archivos. La aplicación obvia de esta facilidad es proporcionar completación con Tab y búsqueda de comandos ejecutables en el PATH de Unix, por lo que se proporciona una devolución de llamada opcional que rechaza todos los archivos excepto los ejecutables.

UN EJEMPLO

En UNIX, el siguiente programa de ejemplo busca y muestra las rutas completas de cada uno de los nombres de comando en la línea de comandos.

  #include <stdio.h>
  #include <stdlib.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    int i;
  /*
   * Crea una caché para archivos ejecutables.
   */
    PathCache *pc = new_PathCache();
    if(!pc)
      exit(1);
  /*
   * Escanea el PATH del usuario en busca de ejecutables.
   */
    if(pca_scan_path(pc, getenv("PATH"))) {
      fprintf(stderr, "%s\n", pca_last_error(pc));
      exit(1);
    }
  /*
   * Configura para informar solo de archivos ejecutables.
   */
   pca_set_check_fn(pc, cpl_check_exe, NULL);
  /*
   * Busca y muestra la ruta completa de cada uno de los
   * comandos listados en la línea de comandos.
   */
    for(i=1; i<argc; i++) {
      char *cmd = pca_lookup_file(pc, argv[i], -1, 0);
      printf("La ruta completa de '%s' es %s\n", argv[i],
             cmd ? cmd : "desconocido");
    }
    pc = del_PathCache(pc);  /* Limpieza */
    return 0;
  }

El siguiente es un ejemplo de lo que esto hace en mi portátil bajo Linux:

  $ ./ejemplo less more blob
  La ruta completa de 'less' es /usr/bin/less
  La ruta completa de 'more' es /bin/more
  La ruta completa de 'blob' es desconocido
  $

DESCRIPCIONES DE FUNCIONES

Para usar las facilidades de este módulo, primero debes asignar un objeto PathCache llamando a la función constructora new_PathCache().

  PathCache *new_PathCache(void)

Esta función crea los recursos necesarios para almacenar en caché y buscar archivos en una lista de directorios. Devuelve NULL en caso de error.

POBLANDO LA CACHÉ

Una vez que hayas creado una caché, necesita ser poblada con archivos. Para hacer esto, llama a la función pca_scan_path().

  int pca_scan_path(PathCache *pc, const char *path);

Cada vez que se llama a esta función, descarta el contenido actual de la caché, luego escanea la lista de directorios especificada en su argumento path en busca de archivos. El argumento path debe ser una cadena que contenga una lista de directorios separada por dos puntos, como "/usr/bin:/home/mcs/bin:.". Esto puede incluir directorios especificados por rutas absolutas como "/usr/bin", así como subdirectorios especificados por rutas relativas como "." o "bin". Los archivos en los directorios absolutos se almacenan inmediatamente en caché en el objeto PathCache especificado, mientras que los subdirectorios, cuyas identidades obviamente cambian cada vez que se cambia el directorio de trabajo actual, se marcan para ser escaneados sobre la marcha cada vez que se busca un archivo.

En caso de éxito, esta función devuelve 0. En caso de error, devuelve 1, y una descripción del error puede obtenerse llamando a pca_last_error(pc).

BUSCANDO ARCHIVOS

Una vez que la caché ha sido poblada con archivos, puedes buscar la ruta completa de un archivo, simplemente especificando su nombre de archivo a pca_lookup_file().

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal);

Para poder pasar a esta función un nombre de archivo que es en realidad parte de una cadena más larga, se puede usar el argumento name_len para especificar la longitud del nombre de archivo al principio del argumento name[]. Si pasas -1 para esta longitud, la longitud de la cadena se determinará con strlen(). Si la cadena name[] puede contener barras invertidas que escapan los significados especiales de los espacios y tabulaciones dentro del nombre de archivo, dale al argumento literal el valor 0. De lo contrario, si las barras invertidas deben tratarse como caracteres normales, pasa 1 para el valor del argumento literal.

COMPLETADO DE NOMBRES DE ARCHIVO

Buscar las posibles completaciones de un prefijo de nombre de archivo en la caché de nombres de archivo, se logra pasando la función de devolución de llamada proporcionada pca_path_completions() a la función cpl_complete_word() (ver la página del manual cpl_complete_word(3)).

  CPL_MATCH_FN(pca_path_completions);

Esta devolución de llamada requiere que su argumento data sea un puntero a un objeto PcaPathConf. Los objetos de configuración de este tipo se asignan llamando a new_PcaPathConf().

  PcaPathConf *new_PcaPathConf(PathCache *pc);

Esta función devuelve un objeto inicializado con parámetros de configuración predeterminados, que determinan cómo se comporta la función de devolución de llamada cpl_path_completions(). Las funciones que le permiten cambiar individualmente estos parámetros se discuten a continuación.

Por defecto, la función de devolución de llamada pca_path_completions() busca hacia atrás el inicio del nombre de archivo que se está completando, buscando el primer espacio sin escapar o el inicio de la línea de entrada. Si desea especificar una ubicación diferente, llame a ppc_file_start() con el índice en el que comienza el nombre del archivo en la línea de entrada. Pasar start_index=-1 vuelve a habilitar el comportamiento predeterminado.

  void ppc_file_start(PcaPathConf *ppc, int start_index);

Por defecto, cuando pca_path_completions() examina un nombre de archivo en la línea de entrada, cada barra invertida solitaria en la línea de entrada se interpreta como un carácter especial que elimina cualquier significado especial del carácter que le sigue, como un espacio que debe tomarse como parte del nombre del archivo en lugar de delimitar el inicio del nombre del archivo. Estas barras invertidas se ignoran mientras se buscan completaciones y, posteriormente, se añaden antes de espacios, tabulaciones y barras invertidas literales en la lista de completaciones. Para que las barras invertidas sin escapar se traten como caracteres normales, llame a ppc_literal_escapes() con un valor distinto de cero en su argumento literal.

  void ppc_literal_escapes(PcaPathConf *ppc, int literal);

Cuando haya terminado con una variable PcaPathConf, puede pasarla a la función destructora del_PcaPathConf() para recuperar su memoria.

  PcaPathConf *del_PcaPathConf(PcaPathConf *ppc);

SIENDO SELECTIVO

Si solo está interesado en ciertos tipos de archivos, como, por ejemplo, archivos ejecutables, o archivos cuyos nombres terminan en un sufijo particular, puede hacer que las funciones de completado y búsqueda de nombres de archivo sean selectivas con los nombres de archivo que devuelven. pca_lookup_file(3)

NAME

pca_lookup_file, pca_scan_path, pca_set_check_fn, pca_last_error, new_PathCache, del_PathCache - Path searching cache

SYNOPSIS

#include <tecla.h>

PathCache *new_PathCache(void);
void pca_scan_path(PathCache *pc, const char *path);
int pca_lookup_file(PathCache *pc, const char *name);
void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn, void *data);
const char *pca_last_error(PathCache *pc);
PathCache *del_PathCache(PathCache *pc);

DESCRIPTION

The PathCache object implements a cache of files found in directories specified by the PATH environment variable. This cache can be populated using the pca_scan_path() function, and files can be looked up using the pca_lookup_file() function. The cache can be destroyed using the del_PathCache() function.

The cache may be selectively populated using a callback function. This is achieved by calling the pca_set_check_fn() function. This callback is given the pathname of every file in the cache, and may return true or false to indicate whether the file should be included in the cache.

If an error occurs during scanning of the path, a description of the error may be obtained by calling pca_last_error().

AN EXAMPLE

  PathCache *pc;
  pc = new_PathCache();
  pca_scan_path(pc, getenv("PATH"));
  if (pca_lookup_file(pc, "ls"))
    printf("ls is in the PATH\n");
  else
    printf("ls is not in the PATH\n");
  del_PathCache(pc);

FUNCTION DESCRIPTIONS

PathCache *new_PathCache(void);
Allocates and initialises a new PathCache object, returning a pointer to it. Returns NULL on failure.
void pca_scan_path(PathCache *pc, const char *path);
Scans the directories specified by the path argument, and adds any files found to the cache referenced by pc. The path argument should be a colon-separated list of directories, in the same format as the PATH environment variable. If path is NULL, then the contents of the PATH environment variable are scanned. Any previously cached files are discarded.
int pca_lookup_file(PathCache *pc, const char *name);
Looks for the file named name in the cache referenced by pc. Returns 1 if the file is found, and 0 otherwise.
void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn, void *data);
Sets a callback function to be used to check files found during pca_scan_path(). The check_fn argument is a pointer to the callback function, and data is a pointer to application-specific data that will be passed to the callback function when it is called. If check_fn is NULL, then all files found are accepted.
const char *pca_last_error(PathCache *pc);
Returns a string describing the last error that occurred when scanning the path. Returns NULL if no error occurred.
PathCache *del_PathCache(PathCache *pc);
Destroys the PathCache object referenced by pc, freeing all associated memory. Returns NULL.

POPULATING THE CACHE

The cache is populated by calling pca_scan_path(). This function takes a PathCache object, and a colon-separated list of directories to search. If the list is NULL, then the value of the PATH environment variable is used. Any previously cached files are discarded.

The function scans each directory in the list, and for each file found, it may call a callback function supplied via pca_set_check_fn(). If no callback function is supplied, then all files found are added to the cache.

LOOKING UP FILES

Once the cache has been populated, files may be looked up using pca_lookup_file(). This function takes the PathCache object and the name of the file to look up. It returns 1 if the file is found in the cache, and 0 otherwise.

FILENAME COMPLETION

The PathCache object is primarily intended for use in filename completion. In this context, the callback function supplied to pca_set_check_fn() is used to filter the files found in the cache. For example, it may be used to filter out files that are not executable, or files that are not accessible by the current user.

BEING SELECTIVE

The callback function supplied to pca_set_check_fn() will be called with the full pathname of the file, plus any application-specific data that you provide, and if the callback returns 1 the filename will be reported as a match, and if it returns 0, it will be ignored. Suitable callback functions and their prototypes should be declared with the following macro. The CplCheckFn typedef is also provided in case you wish to declare pointers to such functions.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);

Registering one of these functions involves calling the pca_set_check_fn() function. In addition to the callback function, passed via the check_fn argument, you can pass a pointer to anything via the data argument. This pointer will be passed on to your callback function, via its own data argument, whenever it is called, so this provides a way to pass appplication specific data to your callback.

  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

Note that these callbacks are passed the full pathname of each matching file, so the decision about whether a file is of interest can be based on any property of the file, not just its filename. As an example, the provided cpl_check_exe() callback function looks at the executable permissions of the file and the permissions of its parent directories, and only returns 1 if the user has execute permission to the file. This callback function can thus be used to lookup or complete command names found in the directories listed in the user's PATH environment variable. The example program given earlier in this man page provides a demonstration of this.

Beware that if somebody tries to complete an empty string, your callback will get called once for every file in the cache, which could number in the thousands. If your callback does anything time consuming, this could result in an unacceptable delay for the user, so callbacks should be kept short.

To improve performance, whenever one of these callbacks is called, the choice that it makes is cached, and the next time the corresponding file is looked up, instead of calling the callback again, the cached record of whether it was accepted or rejected is used. Thus if somebody tries to complete an empty string, and hits tab a second time when nothing appears to happen, there will only be one long delay, since the second pass will operate entirely from the cached dispositions of the files. These cached dipositions are discarded whenever pca_scan_path() is called, and whenever pca_set_check_fn() is called with changed callback function or data arguments.

ERROR HANDLING

If pca_scan_path() reports that an error occurred by returning 1, you can obtain a terse description of the error by calling pca_last_error(pc). This returns an internal string containing an error message.

  const char *pca_last_error(PathCache *pc);

CLEANING UP

Once you have finished using a PathCache object, you can reclaim its resources by passing it to the del_PathCache() destructor function. This takes a pointer to one of these objects, and always returns NULL.

  PathCache *del_PathCache(PathCache *pc);

THREAD SAFETY

In multi-threaded programs, you should use the libtecla_r.a version of the library. This uses POSIX reentrant functions where available (hence the _r suffix), and disables features that rely on non-reentrant system functions. In the case of this module, the only disabled feature is username completion in ~username/ expressions, in cpl_path_completions().

Using the libtecla_r.a version of the library, it is safe to use the facilities of this module in multiple threads, provided that each thread uses a separately allocated PathCache object. In other words, if two threads want to do path searching, they should each call new_PathCache() to allocate their own caches.
