NOMBRE

PCRE - expresiones regulares compatibles con Perl

ALGORITMOS DE COINCIDENCIA PCRE

Este documento describe los dos algoritmos diferentes que están disponibles en PCRE para hacer coincidir una expresión regular compilada con una cadena de asunto dada. El algoritmo "estándar" es el proporcionado por las funciones pcre_exec(), pcre16_exec() y pcre32_exec(). Estas funcionan de la misma manera que la función de coincidencia de Perl y proporcionan una operación de coincidencia compatible con Perl. La optimización justo a tiempo (JIT) que se describe en la documentación de pcrejit es compatible con estas funciones.

Un algoritmo alternativo es proporcionado por las funciones pcre_dfa_exec(), pcre16_dfa_exec() y pcre32_dfa_exec(); operan de una manera diferente y no son compatibles con Perl. Esta alternativa tiene ventajas y desventajas en comparación con el algoritmo estándar, y estas se describen a continuación.

Cuando solo hay una forma posible en la que una cadena de asunto dada pueda coincidir con un patrón, los dos algoritmos dan la misma respuesta. Sin embargo, surge una diferencia cuando hay múltiples posibilidades. Por ejemplo, si el patrón


^<.*>

coincide con la cadena


<algo> <otra cosa> <algo más>

hay tres respuestas posibles. El algoritmo estándar solo encuentra una de ellas, mientras que el algoritmo alternativo encuentra las tres.

EXPRESIONES REGULARES COMO ÁRBOLES

El conjunto de cadenas que coinciden con una expresión regular se puede representar como una estructura de árbol. Una repetición ilimitada en el patrón hace que el árbol sea de tamaño infinito, pero sigue siendo un árbol. Hacer coincidir el patrón con una cadena de asunto dada (desde un punto de partida dado) se puede pensar como una búsqueda en el árbol. Hay dos formas de buscar en un árbol: en profundidad y en amplitud, y estas corresponden a los dos algoritmos de coincidencia proporcionados por PCRE.

EL ALGORITMO DE COINCIDENCIA ESTÁNDAR

En la terminología del libro de Jeffrey Friedl "Mastering Regular Expressions", el algoritmo estándar es un "algoritmo NFA". Realiza una búsqueda en profundidad del árbol del patrón. Es decir, procede por un solo camino a través del árbol, comprobando que el asunto coincide con lo que se requiere. Cuando hay una falta de coincidencia, el algoritmo intenta las alternativas en el punto actual y, si todas fallan, retrocede al punto de ramificación anterior en el árbol e intenta la siguiente rama alternativa en ese nivel. Esto a menudo implica retroceder (moverse hacia la izquierda) en la cadena del asunto también. El orden en que se prueban las ramas de repetición está controlado por la naturaleza codiciosa o no codiciosa del cuantificador.

Si se llega a un nodo hoja, se ha encontrado una cadena coincidente, y en ese punto el algoritmo se detiene. Por lo tanto, si hay más de una coincidencia posible, este algoritmo devuelve la primera que encuentra. Si es la más corta, la más larga o alguna longitud intermedia depende de la forma en que se especifican los cuantificadores de repetición codiciosos y no codiciosos en el patrón.

Debido a que termina con un solo camino a través del árbol, es relativamente sencillo para este algoritmo hacer un seguimiento de las subcadenas que coinciden con partes del patrón entre paréntesis. Esto proporciona soporte para paréntesis de captura y referencias inversas.

EL ALGORITMO DE COINCIDENCIA ALTERNATIVO

Este algoritmo realiza una búsqueda en amplitud del árbol. Comenzando desde el primer punto de coincidencia en el asunto, escanea la cadena del asunto de izquierda a derecha, una vez, carácter por carácter, y a medida que lo hace, recuerda todos los caminos a través del árbol que representan coincidencias válidas. En la terminología de Friedl, este es un tipo de "algoritmo DFA", aunque no se implementa como una máquina de estados finitos tradicional (mantiene múltiples estados activos simultáneamente).

Aunque el principio general de este algoritmo de coincidencia es que escanea la cadena del asunto solo una vez, sin retroceder, hay una excepción: cuando se encuentra una aserción lookaround, los caracteres que siguen o preceden al punto actual deben ser inspeccionados independientemente.

El escaneo continúa hasta que se llega al final del asunto o no quedan más caminos no terminados. En ese punto, los caminos terminados representan las diferentes posibilidades de coincidencia (si no hay ninguna, la coincidencia ha fallado). Por lo tanto, si hay más de una coincidencia posible, este algoritmo las encuentra todas y, en particular, encuentra la más larga. Las coincidencias se devuelven en orden decreciente de longitud. Existe una opción para detener el algoritmo después de encontrar la primera coincidencia (que es necesariamente la más corta).

Tenga en cuenta que todas las coincidencias que se encuentran comienzan en el mismo punto del asunto. Si el patrón


gato(miau(gatito)?)?

coincide con la cadena "el gatomaullador atrapado", el resultado serán las tres cadenas "gatomaullador", "gato", y "gato" que comienzan en el quinto carácter del asunto. El algoritmo no avanza automáticamente para encontrar coincidencias que comiencen en posiciones posteriores.

La optimización "auto-posesivación" de PCRE generalmente se aplica a repeticiones de caracteres al final de un patrón (así como internamente). Por ejemplo, el patrón "a\d+" se compila como si fuera "a\d++" porque no hay ningún punto en el que considerar la posibilidad de retroceder en los dígitos repetidos. Para la coincidencia DFA, esto significa que solo se encuentra una coincidencia posible. Si realmente desea múltiples coincidencias en tales casos, use una repetición no codiciosa ("a\d+?") o establezca la opción PCRE_NO_AUTO_POSSESS al compilar.

Hay una serie de características de las expresiones regulares PCRE que no son compatibles con el algoritmo de coincidencia alternativo. Estas son las siguientes:

1. Dado que el algoritmo encuentra todas las coincidencias posibles, la naturaleza codiciosa o no codiciosa de los cuantificadores de repetición no es relevante. Los cuantificadores codiciosos y no codiciosos se tratan exactamente de la misma manera. Sin embargo, los cuantificadores posesivos pueden marcar la diferencia cuando lo que sigue también podría coincidir con lo que se cuantifica, por ejemplo, en un patrón como este:


^a++\w!

Este patrón coincide con "aaab!" pero no con "aaa!", que sería coincidido por un cuantificador no posesivo. De manera similar, si hay un grupo atómico, se hace coincidir como si fuera un patrón independiente en el punto actual, y la coincidencia más larga se "bloquea" para el resto del patrón general.

2. Al tratar con múltiples caminos a través del árbol simultáneamente, no es sencillo hacer un seguimiento de las subcadenas capturadas para las diferentes posibilidades de coincidencia, y la implementación de PCRE de este algoritmo no intenta hacerlo. Esto significa que no hay subcadenas capturadas disponibles.

3. Dado que no se capturan subcadenas, las referencias inversas dentro del patrón no son compatibles y causan errores si se encuentran.

4. Por la misma razón, las expresiones condicionales que utilizan una referencia inversa como condición o prueba para la recursión de un grupo específico no son compatibles.

5. Dado que pueden estar activos muchos caminos a través del árbol, la secuencia de escape \K, que restablece el inicio de la coincidencia cuando se encuentra (pero puede estar en algunos caminos y no en otros), no es compatible. Causa un error si se encuentra.

6. Las llamadas (callouts) son compatibles, pero el valor del campo capture_top es siempre 1, y el valor del campo capture_last es siempre -1.

7. La secuencia de escape \C, que (en el algoritmo estándar) siempre coincide con una sola unidad de datos, incluso en modos UTF-8, UTF-16 o UTF-32, no es compatible en estos modos, porque el algoritmo alternativo se mueve a través de la cadena del asunto un carácter (no una unidad de datos) a la vez, para todos los caminos activos a través del árbol.

8. Excepto por (*FAIL), los verbos de control de retroceso como (*PRUNE) no son compatibles. (*FAIL) es compatible y se comporta como una aserción negativa fallida.

PCRE MATCHING ALGORITHMS

This document describes the two matching algorithms that are supported by PCRE.

REGULAR EXPRESSIONS AS TREES

When a regular expression is compiled by PCRE, it is converted into an internal representation which is essentially a tree. The matching process then involves traversing this tree while scanning the subject string. The details of the traversal define the matching algorithm.

THE STANDARD MATCHING ALGORITHM

This is the algorithm that was originally implemented in PCRE, and which is still used by default. It is a variant of the algorithm used in the Perl programming language. It works by trying to match the pattern from left to right, backtracking when necessary. For example, if the pattern is a(b|c)d and the subject string is abd, the algorithm first tries to match b in the second component of the pattern. When it reaches the d, it succeeds. If the subject string were acd, it would match c and then d. If the subject string were aed, it would try to match b, fail, then try to match c, fail, and then give up.

A key feature of this algorithm is that it finds only the first match. If you want to find all matches, you need to call the matching function repeatedly, starting the next search after the end of the previous match. This is often done using the PCRE_FIND_ALL or PCRE_FIND_ALL_NOTEMPTY options.

The standard algorithm supports all PCRE features, including capturing parentheses, back references, and lookarounds.

THE ALTERNATIVE MATCHING ALGORITHM

This algorithm was introduced in PCRE version 4.0. It works by executing the regular expression's internal tree in a depth-first manner, following all possible paths through the tree for each position in the subject string. This means that it finds all possible matches of the regular expression within the subject string. It is also possible to obtain partial matches.

The alternative algorithm does not support capturing parentheses or back references. It also does not support lookarounds, except for lookbehinds. Atomic groups are supported, but they do not provide the same performance benefit as they do with the standard algorithm.

The alternative algorithm is primarily intended for use when you need to find all possible matches of a pattern, or when you need to perform partial matching.

ADVANTAGES OF THE ALTERNATIVE ALGORITHM

The alternative algorithm has the following advantages:

1. It finds all possible matches of a pattern in the subject string. The standard algorithm finds only the first match. To find more than one match using the standard algorithm, you have to do kludgy things with callouts.

2. Because the alternative algorithm scans the subject string just once, and never needs to backtrack (except for lookbehinds), it is possible to pass very long subject strings to the matching function in several pieces, checking for partial matching each time. Although it is possible to do multi-segment matching using the standard algorithm by retaining partially matched substrings, it is more complicated. The pcrepartial documentation gives details of partial matching and discusses multi-segment matching.

DISADVANTAGES OF THE ALTERNATIVE ALGORITHM

The alternative algorithm suffers from a number of disadvantages:

1. It is substantially slower than the standard algorithm. This is partly because it has to search for all possible matches, but is also because it is less susceptible to optimization.

2. Capturing parentheses and back references are not supported.

3. Although atomic groups are supported, their use does not provide the performance advantage that it does for the standard algorithm.
