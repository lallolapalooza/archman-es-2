NOMBRE

PCRE - expresiones regulares compatibles con Perl

RESUMEN DE LA SINTAXIS DE EXPRESIONES REGULARES DE PCRE

La sintaxis y semántica completas de las expresiones regulares que son compatibles con PCRE se describen en la documentación de pcrepattern. Este documento contiene un resumen de referencia rápida de la sintaxis.

CITAS


\x donde x no es alfanumérico es un literal x
\Q...\E tratar los caracteres incluidos como literales

CARACTERES


\a alarma, es decir, el carácter BEL (hex 07)
\cx "control-x", donde x es cualquier carácter ASCII
\e escape (hex 1B)
\f avance de página (hex 0C)
\n nueva línea (hex 0A)
\r retorno de carro (hex 0D)
\t tabulación (hex 09)
\0dd carácter con código octal 0dd
\ddd carácter con código octal ddd, o retroreferencia
\o{ddd..} carácter con código octal ddd..
\xhh carácter con código hexadecimal hh
\x{hhh..} carácter con código hexadecimal hhh..

Tenga en cuenta que \0dd es siempre un código octal y que \8 y \9 son los caracteres literales "8" y "9".

TIPOS DE CARACTERES


. cualquier carácter excepto nueva línea;
en modo dotall, cualquier carácter whatsoever
\C una unidad de datos, incluso en modo UTF (es mejor evitarlo)
\d un dígito decimal
\D un carácter que no es un dígito decimal
\h un carácter de espacio en blanco horizontal
\H un carácter que no es un espacio en blanco horizontal
\N un carácter que no es una nueva línea
\p{xx} un carácter con la propiedad xx
\P{xx} un carácter sin la propiedad xx
\R una secuencia de nueva línea
\s un carácter de espacio en blanco
\S un carácter que no es un espacio en blanco
\v un carácter de espacio en blanco vertical
\V un carácter que no es un espacio en blanco vertical
\w un carácter de "palabra"
\W un carácter "no palabra"
\X un cluster de grafemas extendido de Unicode

Por defecto, \d, \s y \w solo coinciden con caracteres ASCII, incluso en modo UTF-8 o en las bibliotecas de 16 y 32 bits. Sin embargo, si se está realizando una coincidencia específica de localización, \s y \w pueden también coincidir con caracteres con puntos de código en el rango 128-255. Si se establece la opción PCRE_UCP, el comportamiento de estas secuencias de escape cambia para usar propiedades de Unicode y coinciden con muchos más caracteres.

El espacio Perl y POSIX son ahora los mismos. Perl añadió VT a su conjunto de caracteres de espacio en la versión 5.18 y PCRE cambió en la versión 8.34.

CLASES DE CARACTERES


[...] clase de caracteres positiva
[^...] clase de caracteres negativa
[x-y] rango (se puede usar para caracteres hexadecimales)
[[:xxx:]] conjunto con nombre POSIX positivo
[[:^xxx:]] conjunto con nombre POSIX negativo

En PCRE, los nombres de conjuntos de caracteres POSIX solo reconocen caracteres ASCII por defecto, pero algunos de ellos usan propiedades de Unicode si se establece PCRE_UCP. Puede usar \Q...\E dentro de una clase de caracteres.

CUANTIFICADORES


? 0 o 1, codicioso (greedy)
?+ 0 o 1, posesivo
?? 0 o 1, perezoso (lazy)
* 0 o más, codicioso
*+ 0 o más, posesivo
*? 0 o más, perezoso
+ 1 o más, codicioso
++ 1 o más, posesivo
+? 1 o más, perezoso
{n} exactamente n
{n,m} al menos n, no más de m, codicioso
{n,m}+ al menos n, no más de m, posesivo
{n,m}? al menos n, no más de m, perezoso
{n,} n o más, codicioso
{n,}+ n o más, posesivo
{n,}? n o más, perezoso

ANCLAS Y AFIRMACIONES SIMPLES


\b límite de palabra
\B no es un límite de palabra
^ inicio del sujeto
también después de una nueva línea interna en modo multilínea
\A inicio del sujeto
$ fin del sujeto
también antes de una nueva línea al final del sujeto
también antes de una nueva línea interna en modo multilínea
\Z fin del sujeto
también antes de una nueva línea al final del sujeto
\z fin del sujeto
\G primera posición de coincidencia en el sujeto

REINICIO DEL PUNTO DE COINCIDENCIA


\K reinicia el inicio de la coincidencia

\K se respeta en afirmaciones positivas, pero se ignora en las negativas.

ALTERNANCIA


| o

Nota: Un carácter | entre corchetes no es un operador de alternancia.

GRUPOS Y LOOKAROUNDS


(...) grupo de captura
(?...) grupo de captura con el primer dígito de captura como 1
(...):... grupo con retroreferencia especificada por dígito
(...):(?P<nombre>...) grupo con retroreferencia especificada por nombre
(?imsx) establecimiento de bandera(s)
(?i) ? (imsx) eliminación de bandera(s)
(?:...) grupo sin captura
(?>...) grupo posesivo (no retrocede)
(?=...) afirmación positiva de lookahead
(?!...) afirmación negativa de lookahead
(?<=...) afirmación positiva de lookbehind
(?<!...) afirmación negativa de lookbehind
(?#...) comentario

Los lookbehinds solo pueden tener una longitud fija.

RETROREFERENCIAS


\1, \2, etc. retroreferencia de captura de grupo

\g1, \g2, etc. retroreferencia de captura de grupo

\g{1}, \g{2}, etc. retroreferencia de captura de grupo

\k<name>, \k"name" retroreferencia con nombre

\G ... retroreferencia de captura con nombre

PATRONES CONDICIONALES


(?(condition)pattern) patrón si la condición es verdadera
(?(condition)pattern|pattern) patrón si la condición es verdadera, otro si es falso

La condición puede ser una retroreferencia o una afirmación de lookahead/lookbehind.

SECUENCIAS ESPECIALES Y MODIFICADORES


\ escapar un carácter especial
(?imsx) establecimiento de bandera(s)
(?i) ? (imsx) eliminación de bandera(s)

Bandera i: ignora mayúsculas/minúsculas
Bandera m: modo multilínea
Bandera s: modo dotall (el punto coincide con todo)
Bandera x: modo de espacios en blanco (ignora espacios en blanco y permite comentarios)

COMENTARIOS


(?#...) comentario

Los comentarios se ignoran, y también se ignora cualquier espacio en blanco circundante, excepto cuando se utiliza el modo de espacios en blanco.

(?0) recursión completa
(?1) llamada a subrutina de grupo 1
(?<name>...) llamada a subrutina con nombre

COMPORTAMIENTO DE PCRE VS PERL

En general, PCRE intenta imitar el comportamiento de Perl. Sin embargo, hay algunas diferencias sutiles, especialmente en el manejo de fallos en expresiones regulares recursivas y en las afirmaciones de lookbehind.

The following are recognized only at the very start of a pattern or after one of the newline or \R options with similar syntax. More than one of them may appear.


(*LIMIT_MATCH=d) set the match limit to d (decimal number)
(*LIMIT_RECURSION=d) set the recursion limit to d (decimal number)
(*NO_AUTO_POSSESS) no auto-possessification (PCRE_NO_AUTO_POSSESS)
(*NO_START_OPT) no start-match optimization (PCRE_NO_START_OPTIMIZE)
(*UTF8) set UTF-8 mode: 8-bit library (PCRE_UTF8)
(*UTF16) set UTF-16 mode: 16-bit library (PCRE_UTF16)
(*UTF32) set UTF-32 mode: 32-bit library (PCRE_UTF32)
(*UTF) set appropriate UTF mode for the library in use
(*UCP) set PCRE_UCP (use Unicode properties for \d etc)

Note that LIMIT_MATCH and LIMIT_RECURSION can only reduce the value of the limits set by the caller of pcre_exec(), not increase them.

NEWLINE CONVENTION

These are recognized only at the very start of the pattern or after option settings with a similar syntax.


(*CR) carriage return only
(*LF) linefeed only
(*CRLF) carriage return followed by linefeed
(*ANYCRLF) all three of the above
(*ANY) any Unicode newline sequence

WHAT \R MATCHES

These are recognized only at the very start of the pattern or after option setting with a similar syntax.


(*BSR_ANYCRLF) CR, LF, or CRLF
(*BSR_UNICODE) any Unicode newline sequence

BACKTRACKING CONTROL

The following act immediately they are reached:


(*ACCEPT) force successful match
(*FAIL) force backtrack; synonym (*F)
(*MARK:NAME) set name to be passed back; synonym (*:NAME)

The following act only when a subsequent match failure causes a backtrack to reach them. They all force a match failure, but they differ in what happens afterwards. Those that advance the start-of-match point do so only if the pattern is not anchored.


(*COMMIT) overall failure, no advance of starting point
(*PRUNE) advance to next starting character
(*PRUNE:NAME) equivalent to (*MARK:NAME)(*PRUNE)
(*SKIP) advance to current matching position
(*SKIP:NAME) advance to position corresponding to an earlier
(*MARK:NAME); if not found, the (*SKIP) is ignored
(*THEN) local failure, backtrack to next alternation
(*THEN:NAME) equivalent to (*MARK:NAME)(*THEN)
