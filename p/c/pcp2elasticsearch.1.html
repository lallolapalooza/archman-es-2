PCP2ELASTICSEARCH(1) Manual de comandos generales PCP2ELASTICSEARCH(1)

NOMBRE

pcp2elasticsearch - exportador de métricas pcp-a-elasticsearch

SINOPSIS

pcp2elasticsearch [-5CGHIjLmnrRvV?] [-4 accion] [-8|-9 limite] [-a archivo] [-A alineacion] [--archive-folio folio] [-b|-B escala-espacio] [-c config] [--container contenedor] [-D debug] [--daemonize] [-e derivado] [-g URL] [-h host] [-i instancias] [-J rango] [-K espec] [-N predicado] [-O origen] [-p tipo] [-P|-0 precision] [-q|-Q escala-conteo] [-s muestras] [-S tiempos-inicio] [-t intervalo] [-T tiempos-fin] [-x indice] [-X id-host] [-y|-Y escala-tiempo] metricas-espec [...]

DESCRIPCIÓN

pcp2elasticsearch es una herramienta personalizable de exportación de métricas de rendimiento de PCP a Elasticsearch. Cualquier métrica de rendimiento disponible, en vivo o archivada, del sistema y/o de la aplicación, puede ser seleccionada para exportar usando argumentos de línea de comandos o un archivo de configuración.

pcp2elasticsearch es un pariente cercano de pmrep(1). Consulte pmrep(1) para la descripción de metricspec aceptada en la línea de comandos de pcp2elasticsearch. Vea pmrep.conf(5) para la descripción de la sintaxis del archivo de configuración pcp2elasticsearch.conf. Esta página describe las opciones específicas de pcp2elasticsearch y las diferencias del archivo de configuración con pmrep.conf(5). pmrep(1) también lista algunos ejemplos de uso de los cuales la mayoría son aplicables también con pcp2elasticsearch.

Solo las opciones de línea de comandos listadas en esta página son soportadas; otras opciones disponibles para pmrep(1) no son soportadas.

Las opciones a través de valores de entorno (ver pmGetOptions(3)) anulan los valores predeterminados incorporados correspondientes (si los hay). Las opciones del archivo de configuración anulan las variables de entorno correspondientes (si las hay). Las opciones de la línea de comandos anulan las opciones del archivo de configuración correspondientes (si las hay).

ARCHIVO DE CONFIGURACIÓN

pcp2elasticsearch utiliza un archivo de configuración con una sintaxis descrita en pmrep.conf(5). Las siguientes opciones son comunes con pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. El resto de las opciones de pmrep.conf son reconocidas pero ignoradas por compatibilidad.

opciones específicas de pcp2elasticsearch

es_server (cadena)

Especifica la URL de la métrica del servidor Elasticsearch de destino. La opción de línea de comandos correspondiente es -g. Por defecto es http://localhost:9200/.

es_auth (cadena)

Especifica el nombre de usuario a utilizar con las solicitudes de Elasticsearch. Por defecto es ninguno.

es_password (cadena)

Especifica la contraseña a utilizar con las solicitudes de Elasticsearch. Por defecto es ninguna.

es_index (cadena)

Especifica el índice de Elasticsearch para los nombres de las métricas. La opción de línea de comandos correspondiente es -x. Por defecto es pcp.

es_hostid (cadena)

Especifica el id-host de Elasticsearch para las mediciones. La opción de línea de comandos correspondiente es -X. Por defecto es el host de origen de las métricas.

es_search_type (cadena)

Especifica el tipo de búsqueda de Elasticsearch para las mediciones. La opción de línea de comandos correspondiente es -p. Por defecto es pcp-metric.

OPCIONES

Las opciones disponibles de línea de comandos son:

-0 precision, --precision-force=precision
Como -P pero esta opción *anulará* las especificaciones por métrica.
-4 accion, --names-change=accion
Especifica qué accion tomar al recibir un evento de cambio de nombre de métrica durante el muestreo. Estos eventos ocurren cuando un PMDA descubre nuevas métricas después de haber iniciado y lo informa a las herramientas cliente en ejecución como pcp2elasticsearch. Los valores válidos para accion son update (actualizar las métricas que se están muestreando), ignore (no hacer nada - el comportamiento predeterminado) y abort (salir del programa si ocurre dicho evento).
-5, --ignore-unknown
Ignora silenciosamente cualquier nombre de métrica que no se pueda resolver. Se debe encontrar al menos una métrica para que la herramienta pueda iniciarse.
-8 limite, --limit-filter=limite
Limita los resultados a instancias con valores por encima/debajo de limite. Un entero positivo incluirá instancias con valores en o por encima del límite en el informe. Un entero negativo incluirá instancias con valores en o por debajo del límite en el informe. Un valor de cero no realiza ningún filtrado de límite. Esta opción *no* anulará posibles especificaciones por métrica. Ver también -J y -N.
-9 limite, --limit-filter-force=limite
Como -8 pero esta opción *anulará* las especificaciones por métrica.
-a archivo, --archive=archivo
Los valores de métricas de rendimiento se obtienen del conjunto de archivos de archivo de Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista de nombres separada por comas, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos.
-A alineacion, --align=alineacion
Fuerza que la muestra inicial esté alineada en el límite de una unidad de tiempo natural alineacion. Consulte PCPIntro(1) para una descripción completa de la sintaxis de alineacion.
--archive-folio=folio
Lee los archivos de origen de métricas del folio de archivos de PCP creado por herramientas como pmchart(1) o, con menos frecuencia, manualmente con mkaf(1).
-b escala, --space-scale=escala
Unidad/escala para métricas de espacio (bytes), los valores posibles incluyen bytes, Kbytes, KB, Mbytes, MB, y así sucesivamente. Esta opción *no* anulará posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-B escala, --space-scale-force=escala
Como -b pero esta opción *anulará* las especificaciones por métrica.
-c config, --config=config
Especifica el archivo o directorio config a utilizar. En caso de que config sea un directorio, todos los archivos que terminen en .conf serán incluidos. El valor predeterminado es el primero que se encuentre de: ./pcp2elasticsearch.conf, $HOME/.pcp2elasticsearch.conf, $HOME/pcp/pcp2elasticsearch.conf, y $PCP_SYSCONF_DIR/pcp2elasticsearch.conf. Para más detalles, vea la sección anterior y pmrep.conf(5).
--container=contenedor
Obtiene métricas de rendimiento del contenedor especificado, ya sea local o remoto (ver -h).
-C, --check
Sale antes de informar cualquier valor, pero después de analizar la configuración y las métricas e imprimir

--daemonize
Daemonizar al inicio.
-e derivado, --derived=derivado
Especificar métricas de rendimiento derivadas. Si derivado comienza con una barra inclinada ('/') o un punto ('.') se interpretará como un archivo de configuración de métricas derivadas de PCP, de lo contrario se interpretará como expresiones de métricas derivadas separadas por comas o puntos y comas. Para una descripción completa de las métricas derivadas y los archivos de configuración de métricas derivadas de PCP, consulte pmLoadDerivedConfig(3) y pmRegisterDerived(3). Alternativamente, el uso de la sintaxis de configuración de pmrep.conf(5) permite definir métricas derivadas como parte de conjuntos de métricas.

En caso de problemas con métricas derivadas, revise detalladamente las páginas del manual antes mencionadas y asegúrese de que todas las métricas requeridas estén disponibles, especialmente al usar archivos. Use -Dderive para ver información de depuración adicional sobre el análisis de métricas derivadas.

-g URL, --es-host=URL
URL del servidor Elasticsearch de destino para métricas URL.
-G, --no-globals
No incluir métricas globales en el informe (consulte pmrep.conf(5)).
-h host, --host=host
Obtener métricas de rendimiento de pmcd(1) en el host, en lugar de del host local predeterminado.
-H, --no-header
No imprimir ninguna cabecera.
-i instancias, --instances=instancias
Recuperar e informar solo de las instancias de métrica especificadas. Por defecto, se informan todas las instancias, presentes y futuras.

Consulte pmrep(1) para una descripción completa de esta opción.

-I, --ignore-incompat
Ignorar métricas incompatibles. Por defecto, las métricas incompatibles (es decir, cuyo tipo no es compatible o no se pueden escalar según lo solicitado) harán que pcp2elasticsearch termine con un mensaje de error. Con esta opción, todas las métricas incompatibles se omiten silenciosamente del informe. Esto puede ser especialmente útil al solicitar nodos no terminales del árbol PMNS para el informe.
-j, --live-filter
Realizar filtrado en vivo de instancias. Esto permite capturar todas las instancias nombradas incluso si los procesos se reinician en algún momento (a diferencia de sin filtrado en vivo). Realizar filtrado en vivo sobre un gran número de instancias añadirá cierta sobrecarga interna, por lo que se aconseja precaución por parte del usuario. Consulte también -n.
-J rango, --rank=rango
Limitar los resultados a las rango instancias más altas/bajas de métricas con valor de conjunto. Un entero positivo incluirá las instancias de mayor valor en el informe. Un entero negativo incluirá las instancias de menor valor en el informe. Un valor cero no realiza ningún ranking. El ranking no implica ordenación, consulte -6. Consulte también -8.
-K espec, --spec-local=espec
Al obtener métricas de un contexto local (consulte -L), la opción -K puede usarse para controlar los PMDA DSO que deben ser accesibles. El argumento espec se ajusta a la sintaxis descrita en pmSpecLocalPMDA(3). Se pueden usar múltiples opciones -K.
-L, --local-PMDA
Usar un contexto local para recopilar métricas de PMDA DSO en el host local sin PMCD. Consulte también -K.
-m, --include-labels
Incluir etiquetas de métricas PCP en la salida.
-n, --invert-filter
Realizar el ranking antes del filtrado en vivo. Por defecto, el filtrado en vivo de instancias (cuando se solicita, consulte -j) ocurre antes del ranking de instancias (cuando se solicita, consulte -J). Con esta opción, la lógica se invierte y el ranking ocurre antes del filtrado en vivo.
-N predicado, --predicate=predicado
Especificar una lista separada por comas de métricas de referencia de filtro de predicado. Por defecto, el ranking (consulte -J) se realiza individualmente para cada métrica. Con predicados, el ranking se realiza solo para las métricas de predicado especificadas. Al informar, el resto de las métricas que comparten el mismo dominio de instancia (consulte PCPIntro(1)) que el predicado incluirán solo las instancias de mayor/menor rango del predicado correspondiente. El ranking no implica ordenación, consulte -6.

Por ejemplo, usando proc.memory.rss (tamaño de memoria residente del proceso) como métrica de predicado junto con proc.io.total_bytes y mem.util.used como métricas a informar, solo los procesos que usan más/menos memoria (según -J) se incluirán al informar los bytes totales escritos por los procesos. Dado que mem.util.used es una métrica de valor único (por lo tanto, no comparte el mismo dominio de instancia que las métricas relacionadas con procesos), se informará como de costumbre.

-O origen, --origin=origen
Al informar métricas archivadas, comience a informar en el origen dentro de la ventana de tiempo (consulte -S y -T). Consulte PCPIntro(1) para una descripción completa de la sintaxis de origen.
-p tipo, --es-search-type=tipo
Tipo de búsqueda de Elasticsearch tipo para mediciones.
-P precision, --precision=precision
Use precision para valores numéricos de salida no enteros. El predeterminado es usar 3 decimales (cuando sea aplicable). Esta opción no anulará posibles especificaciones por métrica.
-q escala, --count-scale=escala
Unidad/escala para métricas de recuento, los valores posibles incluyen count x 10^-1, count, count x 10, count x 10^2, y así sucesivamente de 10^-8 a 10^7. (Estos valores son sensibles a los espacios actualmente). Esta opción no anulará posibles especificaciones por métrica. Consulte también pmParseUnitsStr(3).
-Q escala, --count-scale-force=escala
Similar a -q pero esta opción sí anulará las especificaciones por métrica.
-r, --raw
Emitir valores de métricas sin procesar, no convertir contadores acumulativos a tasas. Esta opción sí anulará posibles especificaciones por métrica.
-R, --raw-prefer
Similar a -r pero esta opción no anulará las especificaciones por métrica.
-s muestras, --samples=muestras
El argumento muestras define el número de muestras a recuperar y reportar. Si muestras es 0 o -s no se especifica, pcp2elasticsearch muestreará e informará continuamente (en modo de tiempo real) o hasta el final del conjunto de archivos PCP (en modo de archivo). Consulte también -T.
-S tiempodeinicio, --start=tiempodeinicio
Al informar métricas archivadas, el informe se restringirá a aquellos registros registrados a partir de tiempodeinicio. Consulte PCPIntro(1) para una descripción completa de la sintaxis de tiempodeinicio.
-t intervalo, --interval=intervalo
Establecer el intervalo de informe a algo distinto del segundo predeterminado. El argumento intervalo sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos). Consulte también la opción -T.
-T tiempofinal, --finish=tiempofinal
Al informar métricas archivadas, el informe se restringirá a aquellos registros registrados antes o en tiempofinal. Consulte PCPIntro(1) para una descripción completa de la sintaxis de tiempofinal.

Cuando se usa para definir el tiempo de ejecución antes de que pcp2elasticsearch salga, si no se proporciona ninguna muestra (consulte -s), el número de muestras informadas dependerá del intervalo (consulte -t). Si se proporciona muestra, el intervalo se ajustará para permitir el informe de muestra durante el tiempo de ejecución. En caso de que se den -T, -s y -t, tiempofinal determinará el tiempo real que se ejecutará pcp2elasticsearch.

-v, --omit-flat
Informar solo métricas de conjunto con instancias (por ejemplo, disk.dev.read) y omitir métricas "planas" de valor único sin instancias (por ejemplo, kernel.all.sysfork). Consulte -i y -I.
-V, --version
Mostrar número de versión y salir.
-x índice, --es-index=índice
Índice de Elasticsearch índice para nombres de métricas.
-X idhost, --es-hostid=idhost
ID de host de Elasticsearch idhost para mediciones.
-y escala, --time-scale=escala
Unidad/escala para métricas de tiempo, los valores posibles incluyen nanosec, ns, microsec, us, millisec, ms, y así sucesivamente hasta hour, hr. Esta opción no anulará posibles especificaciones por métrica. Consulte también pmParseUnitsStr(3).
-Y escala, --time-scale-force=escala
Similar a -y pero esta opción sí anulará las especificaciones por métrica.
-?, --help

FORMATO DE SALIDA

Primero, pcp2elasticsearch envía esta definición de tipo a Elasticsearch:


{
"mappings": {
"properties": {
"@timestamp": {
"type": "long"
},
"host-id": {
"type": "text"
}
}
}
}

El documento de datos de métricas real es similar a este ejemplo:


{
"@host-id": "bozo",
"@timestamp": 1507637520,
"mem": {
"util": {
"used": 4525820,
"free": 3344000
}
},
"disk": {
"partitions": {
"@instances": [
{
"read": 1121,
"@id": "sda1"
},
{
"read": 77306,
"@id": "sda2"
},
{
"read": 131,
"@id": "sda3"
}
]
}
}
}

Archivos de configuración de pmrep proporcionados por el sistema

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para las variables de entorno que afectan a las herramientas de PCP, consulte pmGetOptions(3).

De particular interés, se puede establecer PCP_DISCRETE_ONCE para asegurar que los valores de métricas discretas se informen solo una vez, a menos que cambien en algún momento.

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información a veces es críptica y está destinada principalmente a guiar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
