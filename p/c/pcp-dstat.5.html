PCP-DSTAT(5) Manual de formatos de archivo PCP-DSTAT(5)

NOMBRE

pcp-dstat - archivo de configuración de pcp-dstat

DESCRIPCIÓN

pcp-dstat es una herramienta personalizable de informes de métricas de rendimiento. Tiene una arquitectura de "plugins", donde un conjunto de plugins predefinidos ofrecen pequeños conjuntos de informes métricos colonnes, y las opciones de línea de comandos de pcp-dstat seleccionan cuáles de estos plugins se utilizan en el informe generado.

Cada plugin se define en una sección de un archivo de configuración. Una instalación típica proporcionará muchos archivos de configuración y, a menudo, múltiples secciones (plugins) dentro de cada archivo.

Los archivos de configuración se leen tanto de un directorio del sistema como del directorio de inicio del usuario ($PCP_SYSCONF_DIR/dstat y $HOME/.pcp/dstat).

FORMATO DE ARCHIVO

Los archivos de configuración tienen una sintaxis de estilo ini que consiste en secciones (plugins) y opciones dentro de las secciones. Una sección comienza con el nombre del plugin entre corchetes y continúa hasta que comience la siguiente sección. Un ejemplo de sección con dos opciones es el siguiente:

[plugin]
opción = valor
métrica.opción = valor2

Un comentario de línea comienza con un signo de almohadilla (``#'') o un punto y coma (``;''). No se admiten comentarios en línea.

Hay algunas opciones que se aplican al plugin en su conjunto, y cualquier otra cosa se considera una definición de columna. Las definiciones de columna se mapean directamente a métricas individuales de PCP.

Las opciones [plugin]

etiqueta (cadena)

El título general que se utilizará para este plugin. En el caso especial de métricas con instancias que se informan como un grupo (ver grouptype a continuación), esta cadena puede contener el patrón %I, que será sustituido por el nombre de la instancia - consulte los plugins cpu, disk, net e int(errupts) para ver ejemplos de esta sintaxis especial. Indefinido por defecto, se establece automáticamente al nombre de la sección (plugin).

ancho (entero)

El ancho de columna utilizado para las métricas en este plugin. El valor predeterminado es 5.

precisión (entero)

La precisión máxima que se utilizará al informar columnas en punto flotante para este plugin. Indefinido por defecto, se establece automáticamente en función del ancho.

tipoprint (carácter)

Indica el estilo de informe para los valores de métricas en este plugin. Las configuraciones posibles son d(ecimal), f(lotante), p(orcentaje), s(tring), b(its), t(iempo). Por defecto, se utilizará una configuración basada en el tipo y el significado de la métrica - consulte PMAPI(3) para obtener más detalles sobre los metadatos de métricas de PCP.

pasoclor (entero)

Indica un "paso" al que se transicionará el siguiente color, al informar valores de métricas. A medida que los valores de las métricas cambian en cada muestra, el pasoclor se utiliza para determinar los incrementos más allá de los cuales se debe seleccionar un nuevo color. El valor predeterminado es 1000.

tipogrupo (entero)

Para plugins con métricas que comparten el mismo dominio de instancia, es posible solicitar un comportamiento de agrupación más complejo. El comportamiento predeterminado es no utilizar la agrupación de instancias e informar cada instancia de la métrica en una columna separada (el plugin load es un ejemplo de esto, utilizando la métrica kernel.all.load).

La agrupación se puede establecer en tres niveles distintos: 1, 2, 3 o 4. El nivel 1 muestra solo instancias de métricas (sin totales), esto es equivalente a usar el plugin --cpu en la línea de comandos de pcp-dstat con la visualización de procesadores específicos, por ejemplo, mostrar los números de CPU 4, 5 y 12 (-C 4,5,12). El nivel 2 muestra la columna total, la suma de todas las instancias para la(s) métrica(s) especificada(s) en este plugin. El nivel 3 es una combinación de ambos modos, por ejemplo, usando el plugin --cpu de pcp-dstat con las opciones -C 4,5,12,total. El nivel 4 es un modo similar a top, donde se utiliza una expresión especial "top" para clasificar todas las instancias, se mostrará el valor superior (más grande).

instancias (cadena de valor separado por comas)

Define las instancias que se informarán para la métrica. El valor predeterminado es informar todas las instancias para métricas de valor establecido.

excluirinsts (patrón regex)

Una expresión regular opcional que se puede utilizar para excluir instancias de métricas de la agregación ('total') en los informes generados. Por ejemplo, es común excluir dispositivos de loopback de los informes de interfaces de red, esto se logra utilizando esta opción. El valor predeterminado es informar sobre todas las instancias (sin exclusión).

tipofiltro (cadena)

Se utiliza para métricas de plugin que permiten opciones de filtrado de instancias en línea de comandos. El valor de la entrada tipofiltro debe ser apropiado para la opción de selección de instancia que se utiliza, como se indica en la siguiente tabla.
tipofiltro opción de selección de instancia
cpu -C
disk -D
dm -L
md -M
part -P
int -I
net -N
net-packets -N
swap -S

Las métricas [plugin]

Cada plugin debe tener al menos una métrica asociada. Cualquier clave que no sea una de las opciones globales de plugin anteriores se considera una especificación de métrica o una opción de métrica. Estas claves definen las métricas y su formato de informe.

En primer lugar, cada columna se representa típicamente por una métrica individual (si la métrica tiene valor de conjunto, es decir, tiene instancias, esto resultará en múltiples columnas). Esto se especifica estableciendo una nueva clave (columna) con una especificación de métrica. El nombre de la columna (clave) es una palabra arbitraria que utiliza caracteres alfabéticos. La especificación de métrica es cualquier nombre de métrica de PCP o especificación de métrica derivada, lo que permite que cálculos aritméticos básicos se utilicen para formar esta columna individual. La sintaxis de métrica derivada se describe en la página del manual pmRegisterDerived(3).

Algunos ejemplos de ambas formas de especificación de métrica se dan a continuación en la sección "EJEMPLOS". Una vez que una columna se ha asociado con una métrica, otras opciones específicas para esa columna se pueden establecer utilizando una sintaxis separada por puntos.

Opciones de métrica

métrica.etiqueta

El subtítulo que se utilizará para los valores informados de esta métrica. La etiqueta predeterminada es el nombre de la columna del archivo de configuración.

Cuando se utilizan métricas de PCP con valor de conjunto (es decir, con instancias), a menudo es conveniente especificar el número de instancia o el nombre de la instancia en el encabezado. Esto se logra utilizando especificadores de formato: ``%d'' o ``%i'' para números de instancia (por ejemplo, reemplazado por ``6'' para el sexto procesador), y ``%s'' o ``%I'' para nombres de instancia (por ejemplo, reemplazado por ``eth0'' para la interfaz de ethernet). Los nombres de instancia disponibles para cualquier métrica se pueden descubrir a través de los comandos pminfo(1) o pmprobe(1).

métrica.ancho

El ancho de columna que se utilizará al informar valores para esta métrica.

métrica.unidad (cadena)

Define la unidad/conversión de escala para la métrica. Debe ser compatible dimensionalmente y se utiliza con métricas no alfanuméricas. Para valores permitidos, consulte pmrep(1).

métrica.tipo (cadena)

Si se establece en raw, la conversión de tasa para la métrica se deshabilitará.

métrica.precisión (entero)

Define la precisión para valores de punto flotante.

métrica.límite (cadena)

Define el filtro de límite de valor para valores de métrica numéricos.

EJEMPLOS

El siguiente ejemplo define un plugin de sistema de archivos virtual, con dos columnas, definidas utilizando tres métricas de PCP: vfs.files.count, vfs.inodes.count y vfs.inodes.free. Las métricas de inodes se combinan utilizando la notación de métricas derivadas.

[vfs]
ancho = 6
etiqueta = sistema de archivos
archivos = vfs.files.count
inodo = vfs.inodes.count - vfs.inodes.free
inodo.etiqueta = inodos

Los archivos pcp-dstat predeterminados del sistema contienen muchos más ejemplos.

archivos de configuración privados por usuario

archivos de configuración a nivel de sistema

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para variables de entorno que afectan a las herramientas de PCP, vea pmGetOptions(3).
