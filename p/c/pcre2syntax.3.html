NOMBRE

PCRE2 - expresiones regulares compatibles con Perl (API revisada)

RESUMEN DE LA SINTAXIS DE EXPRESIONES REGULARES PCRE2

La sintaxis y semántica completas de los patrones de expresiones regulares que son compatibles con PCRE2 se describen en la documentación de pcre2pattern. Este documento contiene un resumen de referencia rápida de la sintaxis de patrones seguida de la sintaxis de las cadenas de reemplazo en la función de sustitución. La descripción completa de esta última se encuentra en la documentación de pcre2api.

COMILLADO


\x donde x no es alfanumérico es una literal x
\Q...\E trata los caracteres encerrados como literales

Tenga en cuenta que los espacios en blanco dentro de \Q...\E siempre se tratan como literales, incluso si se establece PCRE2_EXTENDED, lo que hace que la mayoría de los demás espacios en blanco se ignoren. Tenga en cuenta también que el manejo de \Q...\E por parte de PCRE2 tiene algunas diferencias con el de Perl. Consulte la documentación de pcre2pattern para obtener detalles.

ELEMENTOS ENTRE LLAVES

Con una excepción, dondequiera que los caracteres de llave { y } se requieran para encerrar datos para construcciones como \g{2} o \k{nombre}, los caracteres de espacio y/o tabulación horizontal que siguen a { o preceden a } están permitidos y se ignoran. En el caso de los cuantificadores, también pueden aparecer antes o después de la coma. La excepción es \u{...} que no es compatible con Perl y solo se reconoce cuando se establece PCRE2_EXTRA_ALT_BSUX. Esta es una característica de compatibilidad con ECMAScript y sigue el comportamiento de ECMAScript.

CARACTERES ESCAPADOS

Esta tabla se aplica a entornos ASCII y Unicode. Una secuencia de escape no reconocida provoca un error.


\a alarma, es decir, el carácter BEL (hex 07)
\cx "control-x", donde x es un carácter ASCII no de control
\e escape (hex 1B)
\f avance de página (hex 0C)
\n nueva línea (hex 0A)
\r retorno de carro (hex 0D)
\t tabulación (hex 09)
\0dd carácter con código octal 0dd
\ddd carácter con código octal ddd, o retroceso
\o{ddd..} carácter con código octal ddd..
\N{U+hh..} carácter con punto de código Unicode hh.. (solo en modo Unicode)
\xhh carácter con código hexadecimal hh
\x{hh..} carácter con código hexadecimal hh..

\N{U+hh..} es sinónimo de \x{hh..} pero no se admite en entornos que utilizan código EBCDIC (principalmente mainframes IBM). Tenga en cuenta que \N no seguido de una llave de apertura tiene un significado diferente (ver más abajo).

Si se establece PCRE2_ALT_BSUX o PCRE2_EXTRA_ALT_BSUX ("modo ALT_BSUX"), también se reconocen los siguientes:


\U el carácter "U"
\uhhhh carácter con código hexadecimal hhhh
\u{hh..} carácter con código hexadecimal hh.. pero solo para EXTRA_ALT_BSUX

Cuando \x no va seguido de {, se leen uno o dos dígitos hexadecimales, pero en modo ALT_BSUX, \x debe ir seguido de dos dígitos hexadecimales para ser reconocido como un escape hexadecimal; de lo contrario, coincide con una literal "x". Del mismo modo, si \u (en modo ALT_BSUX) no va seguido de cuatro dígitos hexadecimales o (en modo EXTRA_ALT_BSUX) una secuencia de dígitos hexadecimales entre llaves, coincide con una literal "u".

Tenga en cuenta que \0dd es siempre un código octal. El tratamiento de la barra invertida seguida de un dígito distinto de cero es complicado; para más detalles, consulte la sección "Caracteres no imprimibles" en la documentación de pcre2pattern, donde también se proporcionan detalles sobre el procesamiento de escapes en entornos EBCDIC.

TIPOS DE CARACTERES


. cualquier carácter excepto nueva línea;
en modo dotall, cualquier carácter
\C una unidad de código, incluso en modo UTF (es mejor evitarlo)
\d un dígito decimal
\D un carácter que no es un dígito decimal
\h un carácter de espacio horizontal
\H un carácter que no es un espacio horizontal
\N un carácter que no es una nueva línea
\p{xx} un carácter con la propiedad xx
\P{xx} un carácter sin la propiedad xx
\R una secuencia de nueva línea
\s un carácter de espacio en blanco
\S un carácter que no es un espacio en blanco
\v un carácter de espacio vertical
\V un carácter que no es un espacio vertical
\w un carácter de "palabra"
\W un carácter de "no palabra"
\X un clúster de grafemas extendido de Unicode

\C es peligroso porque puede dejar el punto de coincidencia actual en medio de un carácter UTF-8 o UTF-16. La aplicación puede bloquear el uso de \C estableciendo la opción PCRE2_NEVER_BACKSLASH_C. También es posible compilar PCRE2 con el uso de \C permanentemente deshabilitado.

Por defecto, \d, \s y \w solo coinciden con caracteres ASCII, incluso en modo UTF-8 o en las bibliotecas de 16 y 32 bits. Sin embargo, si se está realizando una coincidencia específica de la configuración regional, \s y \w también pueden coincidir con caracteres con puntos de código en el rango 128-255. Si se establece la opción PCRE2_UCP, el comportamiento de estas secuencias de escape cambia para usar propiedades Unicode y coinciden con muchos más caracteres, pero hay algunas configuraciones de opciones que pueden restringir secuencias individuales a coincidir solo con caracteres ASCII.

Las descripciones de propiedades en \p y \P no distinguen entre mayúsculas y minúsculas; los guiones, guiones bajos y los espacios en blanco ASCII se ignoran, de acuerdo con las reglas de "coincidencia flexible" de Unicode. Por ejemplo, \p{Bidi_Class=al} es lo mismo que \p{ bidi class = AL }.

PROPIEDADES BINARIAS PARA \p Y \P

Unicode define una serie de propiedades binarias, es decir, propiedades cuyos únicos valores son verdadero o falso. Puede obtener una lista de las que son reconocidas por \p y \P, junto con sus abreviaturas, ejecutando este comando:


pcre2test -LP

COINCIDENCIA DE ESCRITURAS CON \p Y \P

Muchos nombres de escrituras y sus abreviaturas de 4 letras se reconocen en elementos \p{sc:...} o \p{scx:...}, o por sí solos con \p (y también \P, por supuesto). Puede obtener una lista de estas escrituras ejecutando este comando:


pcre2test -LS

En PCRE2, los nombres de conjuntos de caracteres POSIX solo reconocen caracteres ASCII de forma predeterminada, pero algunos de ellos utilizan propiedades Unicode si se establece PCRE2_UCP. Puede usar \Q...\E dentro de una clase de caracteres.

Cuando se establece PCRE2_ALT_EXTENDED_CLASS, se pueden usar clases de caracteres extendidas UTS#18, lo que permite clases de caracteres anidadas, combinadas mediante operadores de conjuntos.

x~~y diferencia simétrica de conjuntos (XOR)

CLASES DE CARACTERES EXTENDIDAS DE PERL


(?[...]) clase de carácter extendida de Perl
(?[\p{Thai} & \p{Nd}]) operadores; espacio en blanco ignorado
(?[(x - y) & z]) paréntesis para agrupar


(?[ [^3] & \p{Nd} ]) [...] es una clase ordinaria anidada
(?[ [:alpha:] - [z] ]) conjunto POSIX permitido fuera de [...]
(?[ \d - [3] ]) conjunto escapado con barra invertida permitido fuera de [...]
(?[ !\n & [:ascii:] ]) carácter escapado con barra invertida permitido fuera de [...]
todos los demás caracteres o rangos deben estar entre corchetes [...]


x|y, x+y unión de conjuntos (O)
x&y intersección de conjuntos (Y)
x-y diferencia de conjuntos (Y NO)
x^y diferencia simétrica de conjuntos (XOR)
!x complemento de conjunto (NO)

Dentro de una clase de caracteres extendida de Perl, [...] cambia el modo para que se interprete como una clase de caracteres ordinaria. Fuera de un [...] anidado, los únicos elementos permitidos son escapes de barra invertida, conjuntos POSIX, operadores y paréntesis. Dentro de una clase ordinaria anidada, ^ tiene su significado habitual (invierte la clase cuando se usa como primer carácter); fuera de una clase anidada, ^ es el operador XOR.

CONFIGURACIÓN DE OPCIONES

Los cambios de estas opciones dentro de un grupo se cancelan automáticamente al final del grupo.


(?a) todas las opciones ASCII
(?aD) restringe \d a ASCII en modo UCP
(?aS) restringe \s a ASCII en modo UCP
(?aW) restringe \w a ASCII en modo UCP
(?aP) restringe todas las clases POSIX a ASCII en modo UCP
(?aT) restringe las clases de dígitos POSIX a ASCII en modo UCP
(?i) sin distinción entre mayúsculas y minúsculas
(?J) permite grupos con nombre duplicados
(?m) multilínea
(?n) sin captura automática
(?r) restringe la distinción entre mayúsculas y minúsculas a ASCII o no ASCII
(?s) línea única (dotall)
(?U) perezoso por defecto (lazy)
(?x) ignora el espacio en blanco excepto en clases o \Q...\E
(?xx) como (?x) pero también ignora el espacio y la tabulación en las clases
(?-...) anula la(s) opción(es) dada(s)
(?^) anula las opciones imnrsx

(?aP) implica (?aT) también, aunque esto no tiene un efecto adicional. Sin embargo, significa que (?-aP) también implica (?-aT) y deshabilita todas las restricciones ASCII para las clases POSIX.

Anular x o xx anula ambas. Se pueden establecer varias opciones a la vez, y se permite una mezcla de establecimiento y anulación como (?i-x), pero solo puede haber un guion. El establecimiento (pero no la anulación) está permitido después de (?^ por ejemplo (?^in). Una configuración de opción puede aparecer al principio de un grupo sin captura, por ejemplo (?i:...).

Los siguientes solo se reconocen al principio de un patrón o después de una de las secuencias de nueva línea o \R u opciones con sintaxis similar. Pueden aparecer más de uno. Para los tres primeros, d es un número decimal.


(*LIMIT_DEPTH=d) establece el límite de backtracking a d
(*LIMIT_HEAP=d) establece el límite de tamaño del heap a d * 1024 bytes
(*LIMIT_MATCH=d) establece el límite de coincidencia a d
(*CASELESS_RESTRICT) establece PCRE2_EXTRA_CASELESS_RESTRICT al hacer coincidir
(*NOTEMPTY) establece PCRE2_NOTEMPTY al hacer coincidir
(*NOTEMPTY_ATSTART) establece PCRE2_NOTEMPTY_ATSTART al hacer coincidir
(*NO_AUTO_POSSESS) sin posesión automática (PCRE2_NO_AUTO_POSSESS)
(*NO_DOTSTAR_ANCHOR) sin anclaje de .* (PCRE2_NO_DOTSTAR_ANCHOR)
(*NO_JIT) desactiva la optimización JIT
(*NO_START_OPT) sin optimización de inicio de coincidencia (PCRE2_NO_START_OPTIMIZE)
(*TURKISH_CASING) establece PCRE2_EXTRA_TURKISH_CASING al hacer coincidir
(*UTF) establece el modo UTF apropiado para la biblioteca en uso
(*UCP) establece PCRE2_UCP (usa propiedades Unicode para \d, etc.)

Tenga en cuenta que LIMIT_DEPTH, LIMIT_HEAP y LIMIT_MATCH solo pueden reducir el valor de los límites establecidos por el llamador de pcre2_match() o pcre2_dfa_match(), no aumentarlos. LIMIT_RECURSION es un sinónimo obsoleto de LIMIT_DEPTH. La aplicación puede bloquear el uso de (*UTF) y (*UCP) estableciendo las opciones PCRE2_NEVER_UTF o PCRE2_NEVER_UCP, respectivamente, en tiempo de compilación.

Cada rama de nivel superior de una afirmación de retroceso debe tener un límite para la cantidad de caracteres que coincide. CONTROL DE RETROCESO

Todos los verbos de control de retroceso pueden estar en el formato (*VERB:NOMBRE). Para (*MARK), el nombre es obligatorio, para los demás es opcional. (*SKIP) cambia su comportamiento si está presente :NOMBRE. Los otros actúan inmediatamente al ser alcanzados:


(*ACCEPT) forzar coincidencia exitosa
(*FAIL) forzar retroceso; sinónimo (*F)
(*MARK:NOMBRE) establecer el nombre a devolver; sinónimo (*:NOMBRE)

Los siguientes actúan solo cuando un fallo de coincidencia posterior provoca un retroceso hasta ellos. Todos fuerzan un fallo de coincidencia, pero difieren en lo que sucede después. Aquellos que avanzan el punto de inicio de la coincidencia lo hacen solo si el patrón no está anclado.


(*COMMIT) fallo general, sin avance del punto de inicio
(*PRUNE) avanzar al siguiente carácter de inicio
(*SKIP) avanzar a la posición de coincidencia actual
(*SKIP:NOMBRE) avanzar a la posición correspondiente a un anterior
(*MARK:NOMBRE); si no se encuentra, se ignora (*SKIP)
(*THEN) fallo local, retroceder a la siguiente alternancia

El efecto de uno de estos verbos en un grupo llamado como subrutina se limita a la llamada a la subrutina.

LLAMADAS EXTERNAS


(?C) llamada externa (número asumido 0)
(?Cn) llamada externa con datos numéricos n
(?C"texto") llamada externa con datos de cadena

Los delimitadores de cadena permitidos son ` ' " ^ % # $ (que son los mismos para el inicio y el final), y el delimitador de inicio { emparejado con el delimitador de final }. Para codificar el delimitador final dentro de la cadena, duplíquelo.

CADENAS DE REEMPLAZO

Si se establece la opción PCRE2_SUBSTITUTE_LITERAL, una cadena de reemplazo para pcre2_substitute() no se interpreta. De lo contrario, por defecto, el único carácter especial es el signo de dólar en una de las siguientes formas:


$$ insertar un signo de dólar
$n o ${n} insertar el contenido del grupo n
$<nombre> insertar el contenido del grupo nombrado
$0 o $& insertar la subcadena completa coincidente
$` insertar la subcadena que precede a la coincidencia
$' insertar la subcadena que sigue a la coincidencia
$_ insertar la cadena de entrada completa
$+ insertar el grupo de captura con el número más alto que coincidió
$*MARK o ${*MARK} insertar un nombre de verbo de control

Para ${n}, n puede ser un nombre o un número. Si se establece PCRE2_SUBSTITUTE_EXTENDED, hay una interpretación adicional:

1. La barra invertida es un carácter de escape, y se reconocen las formas descritas en "CARACTERES ESCAPADOS" arriba. También:


\Q...\E se puede usar para suprimir la interpretación
\l forzar que el siguiente carácter sea minúscula
\u forzar que el siguiente carácter sea mayúscula
\L forzar que los caracteres subsiguientes sean minúsculas
\U forzar que los caracteres subsiguientes sean mayúsculas
\u\L forzar que el siguiente carácter sea mayúscula, luego todas minúsculas
\l\U forzar que el siguiente carácter sea minúscula, luego todas mayúsculas
\E finalizar el forzado de mayúsculas/minúsculas \L o \U
\b carácter de tabulación vertical (nota: igual que en la clase de caracteres en el patrón)
\v carácter de tabulación vertical (nota: no es lo mismo que en un patrón)

2. La forma de Python \g<n>, donde los corchetes angulares son parte de la sintaxis y n es un nombre de grupo o un número, se reconoce como una forma alternativa de insertar el contenido de un grupo, por ejemplo \g<3>.

3. La sustitución de captura admite las siguientes formas adicionales:


${n:-cadena} valor predeterminado para grupo no establecido
${n:+cadena1:cadena2} valores para grupo establecido/no establecido

Las propias cadenas de sustitución se expanden. La barra invertida se puede usar para escapar dos puntos y llaves de cierre.

PCRE2 regular expression syntax summary

NAME

pcre2syntax - PCRE2 regular expression syntax summary

PCRE2 REGULAR EXPRESSION SYNTAX SUMMARY

This document is a summary of the syntax for PCRE2 regular expressions. It is not intended to be exhaustive. For full details, see the pcre2syntax(3) man page.

QUOTING

Metacharacters can be escaped by preceding them with a backslash (\), or by enclosing them in a character class. For example, to match a literal asterisk, you can use \*, or [*].

BRACED ITEMS

Items in braces { } are used for quantifiers, for example {n}, {n,}, {n,m}. They can also be used for named capture groups, like (?P<name>...).

ESCAPED CHARACTERS

A backslash followed by a letter is an escaped character. Some of these have special meanings:

  • \a: Alert (bell)
  • \b: Word boundary
  • \B: Non-word boundary
  • \d: Digit
  • \D: Non-digit
  • \e: Escape character
  • \f: Form feed
  • \h: Horizontal whitespace
  • \H: Non-horizontal whitespace
  • \n: Newline
  • \r: Carriage return
  • \s: Whitespace character
  • \S: Non-whitespace character
  • \t: Tab
  • \v: Vertical tab
  • \w: Word character
  • \W: Non-word character
  • \Z: End of string (or before final newline)
  • \z: End of string

Other characters preceded by a backslash are treated literally. For example, \\ matches a literal backslash.

CHARACTER TYPES

PCRE2 supports several character types:

  • \d: Digit [0-9]
  • \D: Non-digit
  • \s: Whitespace [\t\n\r\f\v]
  • \S: Non-whitespace
  • \w: Word character [a-zA-Z0-9_]
  • \W: Non-word character

These can be modified by the POSIX character class syntax. For example, [[:digit:]] is equivalent to \d.

GENERAL CATEGORY PROPERTIES FOR \p and \P

Unicode general category properties can be matched using \p{...} and \P{...}. For example:

  • \p{Lu}: Uppercase letter
  • \p{Ll}: Lowercase letter
  • \p{Lt}: Titlecase letter
  • \p{Lo}: Other letter
  • \p{Nd}: Decimal digit
  • \p{Zs}: Space separator
  • \p{So}: Other symbol

And so on. \P negates the property. For example, \P{Lu} matches any character that is not an uppercase letter.

PCRE2 SPECIAL CATEGORY PROPERTIES FOR \p and \P

PCRE2 also defines some special properties:

  • \p{Common}: Characters used in many scripts
  • \p{Extender}: Extender characters (e.g., accents)
  • \p{Hex_Digit}: Hexadecimal digits
  • \p{Join_Ctxt}: Join context
  • \p{Letter}: Any letter
  • \p{Nonchar}: Non-characters
  • \p{Other}: Any other character
  • \p{Pattern_Syntax}: Characters used in pattern syntax
  • \p{Pattern_White_Space}: Whitespace characters used in patterns
  • \p{Posix_Alnum}: Alphanumeric characters
  • \p{Posix_Alpha}: Alphabetic characters
  • \p{Posix_Blank}: Blank characters
  • \p{Posix_Cntrl}: Control characters
  • \p{Posix_Digit}: Digits
  • \p{Posix_Graph}: Graphic characters
  • \p{Posix_Lower}: Lowercase letters
  • \p{Posix_Print}: Printable characters
  • \p{Posix_Punct}: Punctuation characters
  • \p{Posix_Space}: Whitespace characters
  • \p{Posix_Upper}: Uppercase letters
  • \p{Posix_Xdigit}: Hexadecimal digits
  • \p{Unassigned}: Unassigned code points
  • \p{Uniq_Rem}: Unique characters that may be removed
  • \p{White_Space}: Whitespace characters

BINARY PROPERTIES FOR \p AND \P

PCRE2 also supports binary properties:

  • \p{ASCII}: Matches ASCII characters
  • \p{Binary_Property}: Any binary property
  • \p{Block=...}: Unicode block
  • \p{Canonical_Combining_Class=...}: Canonical combining class
  • \p{Derived_Core_Property}: Derived core property
  • \p{General_Category=...}: General category
  • \p{Grapheme_Cluster_Break=...}: Grapheme cluster break property
  • \p{ID_Continue}: Identifier continue characters
  • \p{ID_Start}: Identifier start characters
  • \p{InMiddleDot}: Characters in the Middle Dot block
  • \p{Is_...}: Binary property (e.g., Is_Alphabetic)
  • \p{Join_Control}: Join control characters
  • \p{Lowercase}: Lowercase letters
  • \p{Mirrored}: Mirrored characters
  • \p{Name_Assignment}: Name assignment characters
  • \p{NFKC_Casefold}: NFKC casefold characters
  • \p{Other_Grapheme_Cluster_Break}: Other grapheme cluster break property
  • \p{Other_ID_Continue}: Other identifier continue characters
  • \p{Other_ID_Start}: Other identifier start characters
  • \p{Other_Lowercase}: Other lowercase letters
  • \p{Other_Mirrored}: Other mirrored characters
  • \p{Other_Uppercase}: Other uppercase letters
  • \p{Prepended_Concatenation_Mark}: Prepended concatenation mark characters
  • \p{Sentence_Terminal}: Sentence terminal characters
  • \p{Terminal_Punctuation}: Terminal punctuation characters
  • \p{Uppercase}: Uppercase letters
  • \p{Variation_Selector}: Variation selector characters
  • \p{Word_Break}: Word break characters

SCRIPT MATCHING WITH \p AND \P

You can match characters belonging to a specific script:

  • \p{Greek}: Matches Greek characters
  • \p{Cyrillic}: Matches Cyrillic characters
  • \p{Hebrew}: Matches Hebrew characters
  • \p{Arabic}: Matches Arabic characters

And so on for all Unicode scripts. \P negates the script.

THE BIDI_CLASS PROPERTY FOR \p AND \P

The bidi class property can be used to match characters based on their bidirectional text properties:

  • \p{L}: Letter
  • \p{R}: Right-to-left character
  • \p{AL}: Arabic letter
  • \p{AN}: Arabic number
  • \p{EN}: European number
  • \p{ES}: European separator
  • \p{ET}: European terminator
  • \p{CS}: Common separator
  • \p{NSM}: Nonspacing mark
  • \p{BN}: Boundary neutral
  • \p{B}: Paragraph separator
  • \p{S}: Symbol
  • \p{ON}: Other neutrals

CHARACTER CLASSES

Square brackets [ ] define a character class. Any character within the brackets will be matched.

  • [abc]: Matches 'a', 'b', or 'c'
  • [^abc]: Matches any character except 'a', 'b', or 'c'
  • [a-z]: Matches any lowercase letter
  • [0-9]: Matches any digit
  • [a-zA-Z0-9]: Matches any alphanumeric character

Within a character class, most metacharacters lose their special meaning. For example, [.*] matches a literal dot or asterisk.

PERL EXTENDED CHARACTER CLASSES

PCRE2 supports Perl-compatible character classes:

  • \d: Digit
  • \D: Non-digit
  • \s: Whitespace
  • \S: Non-whitespace
  • \w: Word character
  • \W: Non-word character

These are equivalent to POSIX classes like [[:digit:]].

QUANTIFIERS

Quantifiers specify how many times the preceding item can occur:

  • *: Zero or more times
  • +: One or more times
  • ?: Zero or one time
  • {n}: Exactly n times
  • {n,}: n or more times
  • {n,m}: Between n and m times (inclusive)

Quantifiers are greedy by default. To make them non-greedy (lazy), append a question mark: *?, +?, ??, {n,m}?

ANCHORS AND SIMPLE ASSERTIONS

Anchors match positions, not characters:

  • ^: Start of string (or line, with the m option)
  • $: End of string (or line, with the m option)
  • \A: Start of string
  • \Z: End of string (or before final newline)
  • \z: End of string
  • \b: Word boundary
  • \B: Non-word boundary

REPORTED MATCH POINT SETTING

These assertions match specific positions within the string:

  • \K: Resets the starting point of the reported match.

ALTERNATION

The pipe symbol | separates alternative patterns.

  • cat|dog: Matches either "cat" or "dog"

CAPTURING

Parentheses ( ) create capturing groups. These groups can be referred to later in the pattern (backreferences) or can be used to extract matched substrings.

  • (abc): Captures "abc"
  • (abc)(def): Captures "abc" in group 1 and "def" in group 2
  • (?:abc): Non-capturing group. Matches "abc" but does not capture it.

ATOMIC GROUPS

An atomic group (?>...) is a capturing group that, once matched, cannot be undone by backtracking. If the pattern fails after an atomic group, the engine does not backtrack into the atomic group.

COMMENT

PCRE2 supports comments within regular expressions using the x option:

  • (?#...) : Inline comment
  • # ... : Comment until end of line (with x option)

OPTION SETTING

Options can be set inline using (?options) or (?options:-options).

  • i: Case-insensitive matching
  • m: Multiline mode (^ and $ match start/end of lines)
  • s: Single-line mode (. matches newline)
  • x: Extended mode (ignore whitespace, allow comments)
  • u: UTF-8 mode (treat string as UTF-8)

NEWLINE CONVENTION

PCRE2 can handle different newline conventions:

  • \n: Line feed (LF)
  • \r: Carriage return (CR)
  • \r\n: Carriage return + line feed (CRLF)
  • \R: Any Unicode newline sequence

WHAT \R MATCHES

\R matches any Unicode newline sequence, which includes LF, CR, CRLF, and various other Unicode characters that represent newlines.

LOOKAHEAD AND LOOKBEHIND ASSERTIONS

These assertions check for patterns ahead or behind the current position without consuming characters.

  • (?=...): Positive lookahead
  • (?!...): Negative lookahead
  • (?<=...): Positive lookbehind
  • (?<!...): Negative lookbehind

Lookbehind assertions must be fixed-width.

NON-ATOMIC LOOKAROUND ASSERTIONS

By default, lookarounds are atomic. To make them non-atomic (allowing backtracking), use the following syntax:

  • (?>=...): Non-atomic positive lookahead
  • (?!>...): Non-atomic negative lookahead
  • (?<=>...): Non-atomic positive lookbehind
  • (?<!>...): Non-atomic negative lookbehind

SUBSTRING SCAN ASSERTION

This assertion checks for the presence of a substring within the string:

  • (?!abc): Negative lookahead for "abc"
  • (?=abc): Positive lookahead for "abc"

Note that these are standard lookaheads and not a special "substring scan assertion" in PCRE2.

SCRIPT RUNS

PCRE2 can match runs of characters belonging to the same script.

  • \p{Script=...}: Matches characters of a specific script.
  • \p{Is_...}: Binary property match.

BACKREFERENCES

Backreferences allow you to refer to previously captured groups.

  • \1: Refers to the first captured group
  • \2: Refers to the second captured group
  • \g{n}: Refers to the nth captured group (more general)
  • \k<name>: Refers to a named captured group

SUBROUTINE REFERENCES (POSSIBLY RECURSIVE)

Subroutine references allow you to reuse a previously defined group.

  • (?1): Re-runs the first group
  • (?<name>): Re-runs the named group "name"
  • (?R): Recursively restarts the entire pattern

CONDITIONAL PATTERNS

Conditional patterns allow you to match based on whether a condition is met.

  • (?(condition)yes-pattern): If condition is true, match yes-pattern
  • (?(condition)yes-pattern|no-pattern): If condition is true, match yes-pattern, otherwise match no-pattern

Conditions can be backreferences, lookarounds, or recursion depth checks.

BACKTRACKING CONTROL

PCRE2 provides control over backtracking behavior:

  • (?>...): Atomic group. Prevents backtracking into the group.
  • (*SKIP): Skips the rest of the current match attempt.
  • (*FAIL): Forces backtracking.

CALLOUTS

Callouts allow C code to be executed during the matching process.

  • (?C): Triggers a callout

REPLACEMENT STRINGS

Replacement strings can use backreferences to insert matched substrings.

  • $1: Inserts the content of the first captured group
  • ${name}: Inserts the content of the named captured group "name"
  • $$: Inserts a literal dollar sign
