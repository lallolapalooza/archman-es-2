PCP2GRAPHITE(1) Manual de Comandos Generales PCP2GRAPHITE(1)

NOMBRE

pcp2graphite - exportador de métricas pcp-a-graphite

SINOPSIS

pcp2graphite [-5CGHIjLnrRvV?] [-4 acción] [-8|-9 límite] [-a archivo] [-A alineación] [--archivo-folio folio] [-b|-B escala-espacio] [-c config] [--contenedor contenedor] [-D debug] [--daemonize] [-e derivado] [-E puerto-texto] [-g servidor] [-h host] [-i instancias] [-J rango] [-K espec] [-N predicado] [-O origen] [-p puerto-pickle] [-P|-0 precisión] [-q|-Q escala-conteo] [-s muestras] [-S horainicio] [-t intervalo] [-T horafin] [-x prefijo] [-X protocolo-pickle] [-y|-Y escala-tiempo] especmetricas [...]

DESCRIPCIÓN

pcp2graphite es una herramienta personalizable de exportación de métricas de rendimiento de PCP a Graphite. Cualquier métrica de rendimiento disponible, en vivo o archivada, del sistema y/o de aplicaciones, puede ser seleccionada para exportar utilizando argumentos de línea de comandos o un archivo de configuración.

pcp2graphite es un pariente cercano de pmrep(1). Consulte pmrep(1) para la descripción de especmetricas aceptada en la línea de comandos de pcp2graphite. Consulte pmrep.conf(5) para la descripción de la sintaxis del archivo de configuración pcp2graphite.conf. Esta página describe las opciones específicas de pcp2graphite y las diferencias del archivo de configuración con pmrep.conf(5). pmrep(1) también enumera algunos ejemplos de uso de los cuales la mayoría son aplicables también con pcp2graphite.

Solo se admiten las opciones de línea de comandos que se enumeran en esta página; no se admiten otras opciones disponibles para pmrep(1).

Las opciones a través de valores de entorno (ver pmGetOptions(3)) anulan los valores predeterminados integrados correspondientes (si los hay). Las opciones del archivo de configuración anulan las variables de entorno correspondientes (si las hay). Las opciones de la línea de comandos anulan las opciones del archivo de configuración correspondientes (si las hay).

ARCHIVO DE CONFIGURACIÓN

pcp2graphite utiliza un archivo de configuración con sintaxis descrita en pmrep.conf(5). Las siguientes opciones son comunes con pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. El resto de las opciones de pmrep.conf se reconocen pero se ignoran por compatibilidad.

opciones específicas de pcp2graphite

graphite_host (cadena)

Especifica el nombre de host o la dirección IP del servidor Graphite de destino. La opción de línea de comandos correspondiente es -g. Por defecto es localhost.

graphite_port (entero)

Especifica el número de puerto del servidor Graphite (texto plano o pickle). Las opciones de línea de comandos correspondientes son -p y -E. Por defecto es 2004.

pickle (booleano)

Especifica si se debe usar el protocolo pickle. Las opciones de línea de comandos correspondientes son -p y -E. Por defecto es sí.

pickle_protocol (entero)

Especifica la versión del protocolo pickle. La opción de línea de comandos correspondiente es -X. Por defecto es 0.

prefix (cadena)

Especifica el prefijo para las métricas enviadas al servidor. La opción de línea de comandos correspondiente es -x. Por defecto es pcp..

OPCIONES

Las opciones de línea de comandos disponibles son:

-0 precisión, --precision-force=precisión
Similar a -P pero esta opción anulará las especificaciones por métrica.
-4 acción, --names-change=acción
Especifica qué acción tomar al recibir un evento de cambio de nombres de métricas durante el muestreo. Estos eventos ocurren cuando un PMDA descubre nuevas métricas algún tiempo después de iniciarse, e informa a las herramientas cliente en ejecución como pcp2graphite. Los valores válidos para acción son update (actualizar métricas que se están muestreando), ignore (no hacer nada - el comportamiento por defecto) y abort (salir del programa si ocurre dicho evento).
-5, --ignore-unknown
Ignorar silenciosamente cualquier nombre de métrica que no se pueda resolver. Se debe encontrar al menos una métrica para que la herramienta comience.
-8 límite, --limit-filter=límite
Limitar los resultados a instancias con valores por encima/por debajo del límite. Un entero positivo incluirá instancias con valores iguales o superiores al límite en el informe. Un entero negativo incluirá instancias con valores iguales o inferiores al límite en el informe. Un valor de cero no realiza ningún filtrado por límite. Esta opción no anulará las posibles especificaciones por métrica. Ver también -J y -N.
-9 límite, --limit-filter-force=límite
Similar a -8 pero esta opción anulará las especificaciones por métrica.
-a archivo, --archive=archivo
Los valores de métricas de rendimiento se obtienen del conjunto de archivos de archivo de Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo de arranque o el nombre de un directorio que contiene uno o más archivos.
-A alineación, --align=alineación
Forzar que la muestra inicial se alinee en el límite de una unidad de tiempo natural alineación. Consulte PCPIntro(1) para una descripción completa de la sintaxis para alineación.
--archive-folio=folio
Leer archivos de origen de métricas del folio de archivos de PCP creado por herramientas como pmchart(1) o, con menos frecuencia, manualmente con mkaf(1).
-b escala, --space-scale=escala
Unidad/escala para métricas de espacio (bytes), los valores posibles incluyen bytes, Kbytes, KB, Mbytes, MB, etc. Esta opción no anulará las posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-B escala, --space-scale-force=escala
Similar a -b pero esta opción anulará las especificaciones por métrica.
-c config, --config=config
Especifica el archivo o directorio de config a usar. En caso de que config sea un directorio, se incluirán todos los archivos que terminen en .conf. El valor por defecto es el primero encontrado de: ./pcp2graphite.conf, $HOME/.pcp2graphite.conf, $HOME/pcp/pcp2graphite.conf, y $PCP_SYSCONF_DIR/pcp2graphite.conf. Para detalles, consulte la sección anterior y pmrep.conf(5).
--container=contenedor
Obtener métricas de rendimiento del contenedor especificado, ya sea local o remoto (ver -h).
-C, --check
Salir antes de informar cualquier valor, pero después de analizar la configuración y las métricas, e imprimir posibles cabeceras.
--daemonize
Daemonizar al inicio.
-e derivado,
--derived=derived
Especificar métricas de rendimiento *derivadas*. Si *derived* comienza con una barra (``/'') o con un punto (``.''), se interpretará como un archivo de configuración de métricas derivadas de PCP; de lo contrario, se interpretará como expresiones de métricas derivadas separadas por comas o punto y coma. Para una descripción completa de las métricas derivadas y los archivos de configuración de métricas derivadas de PCP, consulte pmLoadDerivedConfig(3) y pmRegisterDerived(3). Alternativamente, el uso de la sintaxis de configuración de pmrep.conf(5) permite definir métricas derivadas como parte de conjuntos de métricas.

En caso de problemas con métricas derivadas, revise las páginas del manual mencionadas en detalle y asegúrese de que todas las métricas requeridas estén disponibles, especialmente cuando se utilizan archivos. Use -Dderive para ver información de depuración adicional sobre el análisis de métricas derivadas.

-E puerto, --text-port=puerto
Puerto de texto plano del servidor Graphite *puerto*. El uso de esta opción deshabilita el protocolo pickle.
-g servidor, --graphite-host=servidor
Nombre de host o dirección IP del servidor Graphite de destino *servidor*.
-G, --no-globals
No incluir métricas globales en el informe (ver pmrep.conf(5)).
-h host, --host=host
Obtener métricas de rendimiento de pmcd(1) en *host*, en lugar de del host local predeterminado.
-H, --no-header
No imprimir ningún encabezado.
-i instancias, --instances=instancias
Recuperar e informar solo de las *instancias* de métricas especificadas. Por defecto, se informan todas las instancias, presentes y futuras.

Consulte pmrep(1) para obtener una descripción completa de esta opción.

-I, --ignore-incompat
Ignorar métricas incompatibles. Por defecto, las métricas incompatibles (es decir, su tipo no es compatible o no se pueden escalar según lo solicitado) harán que pcp2graphite termine con un mensaje de error. Con esta opción, todas las métricas incompatibles se omiten silenciosamente del informe. Esto puede ser especialmente útil cuando se solicitan nodos no terminales del árbol PMNS para informar.
-j, --live-filter
Realizar filtrado en vivo de instancias. Esto permite capturar todas las instancias nombradas incluso si los procesos se reinician en algún momento (a diferencia de sin filtrado en vivo). Realizar filtrado en vivo sobre un gran número de instancias agregará cierta sobrecarga interna, por lo que se recomienda precaución por parte del usuario. Ver también -n.
-J rango, --rank=rango
Limitar los resultados a las instancias de mayor/menor *rango* de métricas de valor conjunto. Un entero positivo incluirá las instancias de mayor valor en el informe. Un entero negativo incluirá las instancias de menor valor en el informe. Un valor de cero no realiza ningún ranking. El ranking no implica ordenación, ver -6. Ver también -8.
-K spec, --spec-local=spec
Al obtener métricas de un contexto local (ver -L), la opción -K puede usarse para controlar las PMDA de DSO que deben hacerse accesibles. El argumento *spec* se ajusta a la sintaxis descrita en pmSpecLocalPMDA(3). Se puede usar más de una opción -K.
-L, --local-PMDA
Usar un contexto local para recopilar métricas de PMDA de DSO en el host local sin PMCD. Ver también -K.
-n, --invert-filter
Realizar ranking antes del filtrado en vivo. Por defecto, el filtrado en vivo de instancias (cuando se solicita, ver -j) ocurre antes del ranking de instancias (cuando se solicita, ver -J). Con esta opción, la lógica se invierte y el ranking ocurre antes del filtrado en vivo.
-N predicado, --predicate=predicado
Especificar una lista separada por comas de métricas de referencia de filtro de *predicado*. Por defecto, el ranking (ver -J) se realiza para cada métrica individualmente. Con predicados, el ranking se realiza solo para las métricas de predicado especificadas. Al informar, el resto de las métricas que comparten el mismo *dominio de instancia* (ver PCPIntro(1)) que el predicado incluirán solo las instancias de mayor/menor rango del predicado correspondiente. El ranking no implica ordenación, ver -6.

Por ejemplo, usando proc.memory.rss (tamaño de memoria residente del proceso) como la métrica de *predicado* junto con proc.io.total_bytes y mem.util.used como métricas a informar, solo se incluirán los procesos que usan más/menos memoria (según -J) al informar bytes totales escritos por los procesos. Dado que mem.util.used es una métrica de valor único (por lo tanto, no comparte el mismo dominio de instancia que las métricas relacionadas con el proceso), se informará como de costumbre.

-O origen, --origin=origen
Al informar métricas archivadas, comience a informar en *origen* dentro de la ventana de tiempo (ver -S y -T). Consulte PCPIntro(1) para una descripción completa de la sintaxis para *origen*.
-p puerto, --pickle-port=puerto
Puerto de pickle del servidor Graphite *puerto*. El uso de esta opción habilita el protocolo pickle.
-P precisión, --precision=precisión
Use *precisión* para valores de salida numéricos no enteros. El valor predeterminado es usar 3 lugares decimales (cuando sea aplicable). Esta opción *no* anulará las especificaciones posibles por métrica.
-q escala, --count-scale=escala
*Unidad/escala* para métricas de recuento, los valores posibles incluyen count x 10^-1, count, count x 10, count x 10^2, y así sucesivamente de 10^-8 a 10^7. (Estos valores son actualmente sensibles al espacio.) Esta opción *no* anulará las especificaciones posibles por métrica. Ver también pmParseUnitsStr(3).
-Q escala, --count-scale-force=escala
Similar a -q, pero esta opción *anulará* las especificaciones por métrica.
-r, --raw
Salida de valores de métricas crudas, no convertir contadores acumulativos a tasas. Esta opción *anulará* las especificaciones posibles por métrica.
-R, --raw-prefer
Similar a -r, pero esta opción *no* anulará las especificaciones por métrica.
-s muestras, --samples=muestras
El argumento *muestras* define el número de muestras a recuperar e informar. Si *muestras* es 0 o no se especifica -s, pcp2graphite tomará muestras e informará continuamente (en modo de tiempo real) o hasta el final del conjunto de archivos PCP (en modo de archivo). Ver también -T.
-S horainicio, --start=horainicio
Al informar métricas archivadas, el informe se restringirá a aquellos registros registrados en o después de *horainicio*. Consulte PCPIntro(1) para una descripción completa de la sintaxis para *horainicio*.
-t intervalo, --interval=intervalo
Establecer el *intervalo* de informe a algo diferente al segundo predeterminado. El argumento *intervalo* sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos). Ver también la opción -T.
-T hora-fin, --finish=hora-fin
Al informar métricas archivadas, el informe se restringirá a aquellos registros registrados antes o en *hora-fin*. Consulte PCPIntro(1) para una descripción completa de la sintaxis para *hora-fin*.

Cuando se utiliza para definir el tiempo de ejecución antes de que pcp2graphite salga, si no se proporciona ninguna *muestra* (ver -s), el número de muestras informadas dependerá del *intervalo* (ver -t). Si se proporciona *muestra*, el *intervalo* se ajustará para permitir el informe de *muestras* durante el tiempo de ejecución. En caso de que se proporcionen -T, -s y -t, *hora-fin* determinará la hora real a la que se ejecutará pcp2graphite.

-v, --omit-flat
Informar solo métricas de valor conjunto con instancias (por ejemplo, disk.dev.read) y omitir métricas "planas" de valor único sin instancias (por ejemplo, kernel.all.sysfork). Ver -i y -I.
-V, --version
Mostrar número de versión y salir.
-x prefijo, --prefix=prefijo
*Prefijo* de métricas para las mediciones enviadas al servidor.
-X protocolo, --pickle-protocol=protocolo
Número de versión del *protocolo* pickle.
-y escala, --time-scale=escala
*Unidad/escala* para métricas de tiempo, los valores posibles incluyen nanosec, ns, microsec, us, millisec, ms, y así sucesivamente hasta hour, hr. Esta opción *no* anulará las especificaciones posibles por métrica. Ver también pmParseUnitsStr(3).
-Y escala, --time-scale-force=escala
Similar a -y, pero esta opción *anulará* las especificaciones por métrica.
-?, --help
Mostrar mensaje de uso y salir.
pcp2graphite.1.en - PCP Performance Co-Pilot

NAME

pcp2graphite - Export performance metrics from PCP archives to Graphite format

SYNOPSIS

pcp2graphite [options] [files]

DESCRIPTION

pcp2graphite fetches performance metrics from one or more PCP archives (or live PcP Performance Co-Pilot data), transforms them into Graphite format (timestamp, metric path, value), and prints them to standard output.

The Graphite target can be a live TCP socket connection or standard output. If a hostname and port are specified with the -h option, pcp2graphite will attempt to connect to that Graphite instance and send data.

If no archives are specified, then pcp2graphite will try to read from the standard input.

The -s option can be used to specify a pmrep(1) configuration file to control which metrics are exported and how they are transformed.

OPTIONS

The available command line options are:

-c, --config=file
Specify a configuration file to use. See FILES.
-D, --debug=debug_options
Enable debug output on stderr. See DEBUGGING OPTIONS.
-h, --host=host:port
Connect to a Graphite daemon at the specified host and port. If this option is not specified, data is sent to standard output.
-H, --help
Print a help message and exit.
-L, --list-metrics
List available metrics and exit.
-s, --spec=file
Specify a pmrep.conf(5) style configuration file to control which metrics are exported and how they are transformed. If this option is used, the -c option is ignored.
-V, --version
Print version number and exit.

FILES

pcp2graphite.conf
pcp2graphite configuration file (see -c)
$PCP_SYSCONF_DIR/pmrep/*.conf
system provided default pmrep configuration files

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

Of particular note, PCP_DISCRETE_ONCE can be set to ensure that discrete metric values are reported only once, unless they change at some point.

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.
