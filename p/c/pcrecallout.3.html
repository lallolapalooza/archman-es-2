PCRECALLOUT(3) Manual de Funciones de Biblioteca PCRECALLOUT(3)

NOMBRE

PCRE - expresiones regulares compatibles con Perl

SINOPSIS

#include <pcre.h>

int (*pcre_callout)(pcre_callout_block *);

int (*pcre16_callout)(pcre16_callout_block *);

int (*pcre32_callout)(pcre32_callout_block *);

DESCRIPCIÓN

PCRE proporciona una característica llamada "callout", que es un medio para pasar temporalmente el control al llamador de PCRE en medio de la coincidencia de patrones. El llamador de PCRE proporciona una función externa poniendo su punto de entrada en la variable global pcre_callout (pcre16_callout para la biblioteca de 16 bits, pcre32_callout para la biblioteca de 32 bits). Por defecto, esta variable contiene NULL, lo que deshabilita todos los callouts.

Dentro de una expresión regular, (?C) indica los puntos en los que se debe llamar a la función externa. Se pueden identificar diferentes puntos de callout poniendo un número menor que 256 después de la letra C. El valor por defecto es cero. Por ejemplo, este patrón tiene dos puntos de callout:


(?C1)abc(?C2)def

Si el bit de opción PCRE_AUTO_CALLOUT se establece cuando se compila un patrón, PCRE inserta automáticamente callouts, todos con el número 255, antes de cada elemento del patrón. Por ejemplo, si se usa PCRE_AUTO_CALLOUT con el patrón


A(\d{2}|--)

se procesa como si fuera

(?C255)A(?C255)(\d{2}(?C255)|(?C255)-(?C255)-(?C255))(?C255)

Observe que hay un callout antes y después de cada paréntesis y barra de alternancia. Si el patrón contiene un grupo condicional cuya condición es una aserción, se inserta un callout automático inmediatamente antes de la condición. Dicho callout también puede insertarse explícitamente, por ejemplo:


(?(?C9)(?=a)ab|de)

Esto se aplica solo a las condiciones de aserción (porque son en sí mismas grupos independientes).

Los callouts automáticos se pueden usar para rastrear el progreso de la coincidencia de patrones. El programa pcretest tiene un calificador de patrón (/C) que establece callouts automáticos; cuando se usa, la salida indica cómo se está coincidiendo el patrón. Esta es información útil cuando está intentando optimizar el rendimiento de un patrón particular.

CALLOUTS FALTANTES

Debe tener en cuenta que, debido a las optimizaciones en la forma en que PCRE compila y coincide con los patrones, los callouts a veces no ocurren exactamente como podría esperar.

En tiempo de compilación, PCRE "auto-posesiona" los elementos repetidos cuando sabe que lo que sigue no puede ser parte de la repetición. Por ejemplo, a+ [bc] se compila como si fuera a++ [bc]. La salida de pcretest cuando este patrón se ancla y luego se aplica con callouts automáticos a la cadena "aaaa" es:


--->aaaa
+0 ^ ^
+1 ^ a+
+3 ^ ^ [bc]
No match

Esto indica que cuando [bc] falla en la coincidencia, no hay retroceso en a+ y, por lo tanto, los callouts que se tomarían para los retrocesos no ocurren. Puede deshabilitar la característica de auto-posesión pasando PCRE_NO_AUTO_POSSESS a pcre_compile(), o comenzando el patrón con (*NO_AUTO_POSSESS). Si esto se hace en pcretest (usando el calificador /O), la salida cambia a esto:


--->aaaa
+0 ^ ^
+1 ^ a+
+3 ^ ^ [bc]
+3 ^ ^ [bc]
+3 ^ ^ [bc]
+3 ^^ [bc]
No match

Esta vez, cuando [bc] falla en la coincidencia, el coincidente retrocede en a+ y lo intenta de nuevo, repetidamente, hasta que la propia a+ falla.

Otras optimizaciones que proporcionan resultados rápidos de "sin coincidencia" también afectan a los callouts. Por ejemplo, si el patrón es


ab(?C4)cd

PCRE sabe que cualquier cadena coincidente debe contener la letra "d". Si la cadena sujeto es "abyz", la falta de "d" significa que la coincidencia nunca comienza y el callout nunca se alcanza. Sin embargo, con "abyd", aunque el resultado sigue siendo sin coincidencia, se respeta el callout.

Si el patrón se estudia, PCRE conoce la longitud mínima de una cadena coincidente, e inmediatamente dará un retorno de "sin coincidencia" sin ejecutar realmente una coincidencia si el sujeto no es lo suficientemente largo, o, para patrones no anclados, si se ha escaneado lo suficiente.

Puede deshabilitar estas optimizaciones pasando la opción PCRE_NO_START_OPTIMIZE a la función de coincidencia, o comenzando el patrón con (*NO_START_OPT). Esto ralentiza el proceso de coincidencia, pero asegura que se respeten los callouts como el ejemplo anterior.

LA INTERFAZ DE CALLOUT

Durante la coincidencia, cuando PCRE llega a un punto de callout, se llama a la función externa definida por pcre_callout o pcre[16|32]_callout (si está configurada). Esto se aplica tanto a la coincidencia normal como a la DFA. El único argumento para la función de callout es un puntero a un bloque pcre_callout o pcre[16|32]_callout. Estas estructuras contienen los siguientes campos:


int version;
int callout_number;
int *offset_vector;
const char *subject; (versión de 8 bits)
PCRE_SPTR16 subject; (versión de 16 bits)
PCRE_SPTR32 subject; (versión de 32 bits)
int subject_length;
int start_match;
int current_position;
int capture_top;
int capture_last;
void *callout_data;
int pattern_position;
int next_item_length;
const unsigned char *mark; (versión de 8 bits)
const PCRE_UCHAR16 *mark; (versión de 16 bits)
const PCRE_UCHAR32 *mark; (versión de 32 bits)

El campo version es un entero que contiene el número de versión del formato del bloque. La versión inicial fue 0; la versión actual es 2. El número de versión cambiará nuevamente en el futuro si se agregan campos adicionales, pero la intención es nunca eliminar ninguno de los campos existentes.

El campo callout_number contiene el número del callout, tal como se compiló en el patrón (es decir, el número después de ?C para callouts manuales y 255 para callouts generados automáticamente).

El campo offset_vector es un puntero al vector de offsets que el llamador pasó a la función de coincidencia. Cuando se usa pcre_exec() o pcre[16|32]_exec(), el contenido se puede inspeccionar, para extraer subcadenas que se han coincido hasta el momento, de la misma manera que para extraer subcadenas después de que una coincidencia se ha completado. Para las funciones de coincidencia DFA, este campo no es útil.

Los campos subject y subject_length contienen copias de los valores que se pasaron a la función de coincidencia.

El campo start_match normalmente contiene el desplazamiento dentro del sujeto en el que comenzó el intento de coincidencia actual. Sin embargo, si se ha encontrado la secuencia de escape \K, este valor se cambia para reflejar el punto de inicio modificado. Si el patrón no está anclado, la función de callout puede ser llamada varias veces desde el mismo punto del patrón para diferentes puntos de inicio en el sujeto.

El campo current_position contiene el desplazamiento dentro del sujeto del puntero de coincidencia actual.

Cuando se usa pcre_exec() o pcre[16|32]_exec(), el campo capture_top contiene uno más que el número de la subcadena capturada más alta hasta el momento. Si no se han capturado subcadenas, el valor de capture_top es uno. Este es siempre el caso cuando se usan las funciones DFA, ya que no admiten subcadenas capturadas.

El campo capture_last contiene el número de la subcadena capturada más recientemente. Sin embargo, cuando una recursión sale, el valor vuelve a ser el que era fuera de la recursión, al igual que los valores de todas las subcadenas capturadas. Si no se han capturado subcadenas, el valor de capture_last es -1. Este es siempre el caso para las funciones de coincidencia DFA.

El campo callout_data contiene un valor que se pasa a una función de coincidencia específicamente para que pueda pasarse de vuelta en los callouts. Se pasa en el campo callout_data de una estructura de datos pcre_extra o pcre[16|32]_extra. Si no se pasaron dichos datos, el valor de callout_data en un bloque de callout es NULL. Hay una descripción de la estructura pcre_extra en la documentación de pcreapi.

NAME

pcrecallout — PCRE callout mechanism

SYNOPSIS

#include <pcre.h>

int callout_function(int called_via, void *data);

DESCRIPTION

PCRE supports a callout mechanism that allows user code to be executed during the matching process. This is primarily intended for debugging and testing, but it might also be useful for more advanced applications. When a callout is executed, the PCRE matching function (e.g., pcre_exec()) is temporarily suspended and the function specified in the callout field of the pcre_study() call is invoked.

The callout function is invoked when the regex processor encounters a callout item, which is written as (?{...}) or (*...):

  (?{text})
  (*MARK:name)
  (*PRUNE)
  (*PRUNE:name)
  (*THEN)
  (*THEN:name)

The text inside (?{...}) is treated as a C string, and is compiled into the pattern. It can be executed by using the pcre_config() function with the PCRE_CONFIG_JIT option to check if JIT compilation is enabled. Callouts are only supported by the standard matching functions; they are not supported by the DFA matching functions.

The callout function is called just before the match is attempted at the current position. If the callout function returns a non-zero value, the match is abandoned. If it returns zero, the match proceeds.

The data pointer is passed from the call to pcre_exec() (or its variants). It is not used by PCRE itself, but can be used by the callout function to access application-specific data.

The called_via argument tells the callout function which type of callout it is. It can be one of the following:

PCRE_CALLOUT_MATCH
The callout occurred during a matching operation.
PCRE_CALLOUT_INFO
The callout occurred during a call to pcre_study() (which is needed for certain optimizations, including JIT). In this case, the callout function receives a pointer to a pcre_callout_block structure containing information about the match, but the block should not be modified.

MISSING CALLOUTS

When using the pcre_study() function to compile a regex for faster matching, callouts are disabled by default, as they can interfere with optimizations. If you need callouts to be enabled when studying a regex, you must pass the PCRE_STUDY_CALLOUT flag to pcre_study().

THE CALLOUT INTERFACE

If called_via is PCRE_CALLOUT_INFO, the callout function is passed a pointer to a structure of type pcre_callout_block, which is defined as follows:

typedef struct {
  int      version;       /* Structure version number */
  int      callout_number;/* Current callout number */
  const char *pattern;      /* Pointer to the start of the pattern */
  int      pattern_length;  /* Length of the pattern string */
  int      next_item_length;/* Length of the next item to be matched */
  int      callout_data;    /* Data passed from pcre_exec() */
  void     *tables;       /* Pointer to the character table */
  int      input_offset;    /* Offset of current input character */
  int      input_length;    /* Length of the input string */
  const char *input;        /* Pointer to the start of the input */
  int      offset_and_length;/* Offset to next item and length packed */
  const char *mark;         /* Pointer to MARK name, or NULL */
} pcre_callout_block;

The fields in this structure are:

version
The version number of the structure. This is currently 2.
callout_number
The number specified in the callout item. For (?{...}) callouts, this is always 0.
pattern
A pointer to the start of the pattern string.
pattern_length
The length of the pattern string.
next_item_length
The length of the next item to be matched in the pattern string. This is zero if the callout immediately precedes an alternation bar, a closing parenthesis, or the end of the pattern. If the callout precedes an opening parenthesis, this field contains the length of the entire subpattern. This field is only present in version 1 of the callout structure.
callout_data
The data pointer passed to the pcre_exec() function.
tables
A pointer to the character table that is being used by PCRE. This is NULL if the default table is being used.
input_offset
The offset of the current character in the input string.
input_length
The length of the input string.
input
A pointer to the start of the input string.
offset_and_length
This field is present from version 1 of the callout structure. It contains the offset to the next item to be matched in the pattern string.

The next_item_length field is present from version 1 of the callout structure. It contains the length of the next item to be matched in the pattern string. When the callout immediately precedes an alternation bar, a closing parenthesis, or the end of the pattern, the length is zero. When the callout precedes an opening parenthesis, the length is that of the entire subpattern.

The pattern_position and next_item_length fields are intended to help in distinguishing between different automatic callouts, which all have the same callout number. However, they are set for all callouts.

mark
The field is present from version 2 of the callout structure. In callouts from pcre_exec() or pcre[16|32]_exec() it contains a pointer to the zero-terminated name of the most recently passed (*MARK), (*PRUNE), or (*THEN) item in the match, or NULL if no such items have been passed. Instances of (*PRUNE) or (*THEN) without a name do not obliterate a previous (*MARK). In callouts from the DFA matching functions this field always contains NULL.

RETURN VALUES

The external callout function returns an integer to PCRE. If the value is zero, matching proceeds as normal. If the value is greater than zero, matching fails at the current point, but the testing of other matching possibilities goes ahead, just as if a lookahead assertion had failed. If the value is less than zero, the match is abandoned, the matching function returns the negative value.

Negative values should normally be chosen from the set of PCRE_ERROR_xxx values. In particular, PCRE_ERROR_NOMATCH forces a standard "no match" failure. The error number PCRE_ERROR_CALLOUT is reserved for use by callout functions; it will never be used by PCRE itself.
