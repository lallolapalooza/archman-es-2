PCP(1) Manual de Comandos Generales PCP(1)

NOMBRE

pcp, pcp-summary - ejecuta un comando o resume una instalación

SINOPSIS

pcp [opciones de pcp...] comando-pcp [opciones de comando...]
pcp [-LPV?] [-a archivo] [-D depuración] [-h host] [-O origen] [-n archivo-pmns]

DESCRIPCIÓN

El comando pcp se utiliza en uno de dos modos. Por defecto, resume la instalación de Performance Co-Pilot (PCP) en el host local. Este modo también se puede usar para resumir la instalación de un host remoto, o una instalación histórica de un conjunto de archivos de PCP. Este modo invoca indirectamente el comando pcp-summary (en ausencia de cualquier otro comando solicitado).

Alternativamente, se puede pasar un comando a pcp para ejecutarlo, de nuevo posiblemente en el contexto de un host remoto o un conjunto de archivos históricos.

MODO COMANDO

Cuando se invoca pcp con un comando para ejecutar, buscará el comando con nombre en $PCP_BINADM_DIR y también en $HOME/.pcp/bin (normalmente son scripts e se instalan con un prefijo de "pcp-"). Este modo de operación permite implementar herramientas de rendimiento del sistema usando los servicios de PMAPI(3), conservando todas sus opciones de línea de comandos habituales. Estas opciones se aumentan (indirectamente) con el conjunto de opciones estándar de PCP, como se describe en PCPIntro(1).

Esto proporciona un mecanismo conveniente para obtener capacidades de monitorización retrospectiva o remota, conservando el comportamiento de las herramientas del sistema.

Por ejemplo, la utilidad pcp-free(1) se puede invocar así, para datos registrados del host munch:

$ pcp -a $PCP_LOG_DIR/pmlogger/munch/20140317 -O 11:35:50am free -m
             total       used       free     shared    buffers     cached
Mem:         23960      14554       9406          0        176       2137
-/+ buffers/cache:      12240      11720
Swap         12047          0      12047

Una lista completa de las herramientas disponibles e instaladas se proporciona junto con el mensaje de uso de pcp(1), pero algunos ejemplos incluyen: pcp-free(1), pcp-uptime(1) y pcp-numastat(1).

MODO RESUMEN

El informe de resumen incluye: la versión del SO, un resumen del inventario de hardware, la zona horaria local, la versión del software PCP, el estado del proceso pmcd(1) y los Agentes de Dominio de Métricas de Rendimiento (PMDA) asociados, así como información sobre cualquier archivo PCP local (pmlogger(1)), archivo PCP remoto (pmproxy(1)), y motores de inferencia PCP (pmie(1)) que se estén ejecutando.

Todos los valores mostrados son valores de métrica de rendimiento y se puede obtener más información para cada uno usando el comando:

$ pminfo -dtT métrica
El conjunto completo de métricas requeridas por pcp para producir su salida está contenido en $PCP_VAR_DIR/config/pmlogconf/tools/pcp-summary.

OPCIONES MODO RESUMEN

Sin argumentos, pcp informa sobre el host local, sin embargo se aceptan las siguientes opciones:

-a archivo, --archive=archivo
Informa la configuración de PCP tal como se describe en el conjunto de archivos de PCP, archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos.
-h host, --host=host
Informa la configuración de PCP en el host en lugar del host local.
-L, --local-PMDA
Usa un contexto local para recolectar métricas de PMDAs DSO en el host local sin PMCD.
-n archivo-pmns, --namespace=archivo-pmns
Carga un Espacio de Nombres de Métricas de Rendimiento (PMNS(5)) alternativo del archivo archivo-pmns.
-O origen, --origin=origen
Al informar métricas archivadas, comienza a informar en origen dentro de la ventana de tiempo.
-P, --pmie
Muestra información de rendimiento de pmie(1) - conteos de reglas que evalúan a verdadero, falso o indeterminado, así como la tasa esperada de cálculo de reglas, para cada proceso pmie en ejecución en el host por defecto. Consulte la ayuda individual de la métrica para obtener detalles completos sobre estos valores.
-V, --version
Muestra el número de versión y sale.
-?, --help
Muestra el mensaje de uso y sale.

DIAGNÓSTICO

pcp terminará con un estado de salida de 1 si pmcd en el host de destino no pudo ser alcanzado o el conjunto de archivos no pudo ser abierto, o 2 para cualquier otro error.

ARCHIVOS

$HOME/.pcp/bin
Ubicación por usuario para scripts de comando.
$PCP_BINADM_DIR
Ubicación del sistema para scripts de comando instalados.
$PCP_VAR_DIR/config/pmlogconf/tools/pcp-summary
Archivo de configuración de pmlogconf(1) para recolectar todas las métricas requeridas por pcp

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se usan para parametrizar los nombres de archivos y directorios usados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para variables de entorno que afectan las herramientas de PCP, vea pmGetOptions(3).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información a veces es críptica y está principalmente destinada a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. depuración es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
