PCP2SPARK(1) Manual de Comandos Generales PCP2SPARK(1)

NOMBRE

pcp2spark - exportador de métricas pcp-a-spark

SINOPSIS

pcp2spark [-5CGHIjLmnrRvV?] [-4 acción] [-8|-9 límite] [-a archivo] [-A alineación] [--archive-folio folio] [-b|-B escala-espacio] [-c configuración] [--container contenedor] [-D debug] [--daemonize] [-e derivado] [-g servidor] [-h host] [-i instancias] [-J rango] [-K espec] [-N predicado] [-O origen] [-p puerto] [-P|-0 precisión] [-q|-Q escala-conteo] [-s muestras] [-S hora-inicio] [-t intervalo] [-T hora-fin] [-y|-Y escala-tiempo] especificación-métrica [...]

DESCRIPCIÓN

pcp2spark es una herramienta personalizable de exportación de métricas de rendimiento de PCP a Apache Spark. Cualquier métrica de rendimiento disponible, en vivo o archivada, del sistema y/o de aplicaciones, puede ser seleccionada para exportar utilizando argumentos de línea de comandos o un archivo de configuración.

pcp2spark actúa como un puente que proporciona un flujo de socket de red en una dirección/puerto dado al que una tarea de worker de Apache Spark puede conectarse y extraer las métricas de PCP configuradas desde pcp2spark, exportándolas utilizando las extensiones de streaming de la API de Apache Spark.

pcp2spark es un pariente cercano de pmrep(1). Consulte pmrep(1) para la descripción de especificación-métrica aceptada en la línea de comandos de pcp2spark. Consulte pmrep.conf(5) para la descripción de la sintaxis del archivo de configuración pcp2spark.conf. Esta página describe las opciones específicas de pcp2spark y las diferencias del archivo de configuración con pmrep.conf(5). pmrep(1) también enumera algunos ejemplos de uso de los cuales la mayoría son aplicables también con pcp2spark.

Solo se admiten las opciones de línea de comandos listadas en esta página; otras opciones disponibles para pmrep(1) no son compatibles.

Las opciones a través de valores de entorno (ver pmGetOptions(3)) anulan los valores predeterminados integrados correspondientes (si los hay). Las opciones del archivo de configuración anulan las variables de entorno correspondientes (si las hay). Las opciones de la línea de comandos anulan las opciones del archivo de configuración correspondientes (si las hay).

USO GENERAL

Una configuración general para hacer uso de pcp2spark implicaría que el usuario configure pcp2spark para las métricas de PCP a exportar, seguido del inicio de la aplicación pcp2spark. La aplicación pcp2spark esperará y escuchará en la dirección/puerto dado para una conexión de un hilo de worker de Apache Spark. El hilo de worker se conectará a pcp2spark.

Cuando un hilo de worker de Apache Spark se haya conectado, pcp2spark comenzará a transmitir datos de métricas de PCP a Apache Spark hasta que el hilo de worker complete o la conexión se interrumpa. Si la conexión se interrumpe o el socket es cerrado por el hilo de worker de Apache Spark, pcp2spark saldrá.

Para un ejemplo de trabajo de worker de Apache Spark que se conectará a una instancia de pcp2spark en una dirección/puerto dado y extraerá datos de métricas de PCP, consulte el ejemplo proporcionado en el directorio de ejemplos de PCP para pcp2spark (a menudo proporcionado por el paquete de desarrollo de PCP) o la versión en línea en https://github.com/performancecopilot/pcp/blob/main/src/pcp2spark/.

ARCHIVO DE CONFIGURACIÓN

pcp2spark utiliza un archivo de configuración con una sintaxis descrita en pmrep.conf(5). Las siguientes opciones son comunes con pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. El resto de las opciones de pmrep.conf son reconocidas pero ignoradas por compatibilidad.

opciones específicas de pcp2spark

spark_server (cadena)

Especifica la dirección en la que pcp2spark escuchará las conexiones de un hilo de worker de Apache Spark. Opción de línea de comandos correspondiente: -g. Predeterminado: 127.0.0.1.

spark_port (entero)

Especifica el puerto en el que pcp2spark escuchará las conexiones. Opción de línea de comandos correspondiente: -p. Predeterminado: 44325.

OPCIONES

Las opciones de línea de comandos disponibles son:

-0 precisión, --precision-force=precisión
Similar a -P pero esta opción anulará las especificaciones por métrica.
-4 acción, --names-change=acción
Especifica qué acción tomar al recibir un evento de cambio de nombres de métricas durante el muestreo. Estos eventos ocurren cuando un PMDA descubre nuevas métricas algún tiempo después de iniciarse, e informa a las herramientas cliente en ejecución como pcp2spark. Los valores válidos para acción son update (actualizar métricas que se están muestreando), ignore (no hacer nada - el comportamiento predeterminado) y abort (salir del programa si ocurre dicho evento).
-5, --ignore-unknown
Ignorar silenciosamente cualquier nombre de métrica que no se pueda resolver. Debe encontrarse al menos una métrica para que la herramienta comience.
-8 límite, --limit-filter=límite
Limita los resultados a instancias con valores por encima/por debajo del límite. Un entero positivo incluirá instancias con valores iguales o superiores al límite en el informe. Un entero negativo incluirá instancias con valores iguales o inferiores al límite en el informe. Un valor de cero no realiza ningún filtrado por límite. Esta opción *no* anulará posibles especificaciones por métrica. Ver también -J y -N.
-9 límite, --limit-filter-force=límite
Similar a -8 pero esta opción anulará las especificaciones por métrica.
-a archivo, --archive=archivo
Los valores de las métricas de rendimiento se recuperan del conjunto de archivos de archivo de Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos.
-A alineación, --align=alineación
Fuerza que la muestra inicial esté alineada en el límite de una unidad de tiempo natural alineación. Consulte PCPIntro(1) para una descripción completa de la sintaxis de alineación.
--archive-folio=folio
Lee archivos de origen de métricas de los archivos de metadatos de PCP folio creados por herramientas como pmchart(1) o, con menos frecuencia, manualmente con mkaf(1).
-b escala, --space-scale=escala
Unidad/escala para métricas de espacio (bytes), los valores posibles incluyen bytes, Kbytes, KB, Mbytes, MB, etcétera. Esta opción *no* anulará posibles especificaciones por métrica. Consulte también pmParseUnitsStr(3).
-B escala, --space-scale-force=escala
Similar a -b pero esta opción anulará las especificaciones por métrica.
-c config, --config=config
Especifica el archivo o directorio de configuración a utilizar. En caso de que config sea un directorio, todos los archivos en él que terminen en .conf se incluirá. El valor predeterminado es el primero que se encuentra de: ./pcp2spark.conf, $HOME/.pcp2spark.conf, $HOME/pcp/pcp2spark.conf, y $PCP_SYSCONF_DIR/pcp2spark.conf. Para obtener más detalles, consulte la sección anterior y pmrep.conf(5).
--container=contenedor
Recupera métricas de rendimiento del contenedor especificado, ya sea local o remoto (ver -h).
-C, --check
Sale antes de informar ningún valor, pero después de analizar la configuración y las métricas, e imprimir las posibles cabeceras.
--daemonize
Se demoniza al inicio.
-e derivada, --derived=derivada
Especifica métricas de rendimiento derivadas. Si derivada comienza con una barra (``/'') o con un punto (``.'') se interpretará como un archivo de configuración de métricas derivadas de PCP, de lo contrario se interpretará como expresiones de métricas derivadas separadas por comas o punto y coma. Para una descripción completa de las métricas derivadas y los archivos de configuración de métricas derivadas de PCP, consulte pmLoadDerivedConfig(3) y pmRegisterDerived(3). Alternativamente, usar la sintaxis de configuración de pmrep.conf(5) permite definir métricas derivadas como parte de conjuntos de métricas.

En caso de problemas con las métricas derivadas, revise detalladamente las páginas del manual mencionadas anteriormente y asegúrese de que todas las métricas requeridas estén disponibles, especialmente cuando se usan archivos. Use -Dderive para ver información de depuración adicional sobre el análisis de métricas derivadas.

-g servidor, --spark-server=servidor
Dirección del servidor local de pcp2spark.
-G, --no-globals
No incluir métricas globales en el informe (ver pmrep.conf(5)).
-h host, --host=host
Recupera métricas de rendimiento de pmcd(1) en host, en lugar de del localhost predeterminado.
-H, --no-header
No imprimir ninguna cabecera.
-i instancias, --instances=instancias
Recupera e informa solo las instancias de métricas especificadas. Por defecto se informan todas las instancias, presentes y futuras.

Consulte pmrep(1) para obtener una descripción completa de esta opción.

-I, --ignore-incompat
Ignora métricas incompatibles. Por defecto, las métricas incompatibles (es decir, su tipo no es compatible o no se pueden escalar según lo solicitado) harán que pcp2spark termine con un mensaje de error. Con esta opción, todas las métricas incompatibles se omiten silenciosamente del informe. Esto puede ser especialmente útil al solicitar nodos no terminales del árbol PMNS para el informe.
-j, --live-filter
Realiza filtrado en vivo de instancias. Esto permite capturar todas las instancias nombradas incluso si los procesos se reinician en algún momento (a diferencia de sin filtrado en vivo). Realizar filtrado en vivo sobre un gran número de instancias agregará cierta sobrecarga interna, por lo que se recomienda precaución por parte del usuario. Ver también -n.
-J ranking, --rank=ranking
Limita los resultados a las instancias de métricas de valor conjunto de mayor/menor valor. Un entero positivo incluirá las instancias de mayor valor en el informe. Un entero negativo incluirá las instancias de menor valor en el informe. Un valor de cero no realiza ningún ranking. El ranking no implica ordenación, ver -6. Ver también -8.
-K espec, --spec-local=espec
Al recuperar métricas de un contexto local (ver -L), se puede usar la opción -K para controlar los PMDA DSO que deben ser accesibles. El argumento espec se ajusta a la sintaxis descrita en pmSpecLocalPMDA(3). Se pueden usar varias opciones -K.
-L, --local-PMDA
Utiliza un contexto local para recopilar métricas de PMDA DSO en el host local sin PMCD. Ver también -K.
-m, --include-labels
Incluye etiquetas de métricas de PCP en la salida.
-n, --invert-filter
Realiza el ranking antes del filtrado en vivo. Por defecto, el filtrado en vivo de instancias (cuando se solicita, ver -j) ocurre antes del ranking de instancias (cuando se solicita, ver -J). Con esta opción, la lógica se invierte y el ranking ocurre antes del filtrado en vivo.
-N predicado, --predicate=predicado
Especifica una lista separada por comas de métricas de referencia de filtro de predicado. Por defecto, el ranking (ver -J) se realiza para cada métrica individualmente. Con predicados, el ranking se realiza solo para las métricas de predicado especificadas. Al informar, el resto de las métricas que comparten el mismo dominio de instancia (ver PCPIntro(1)) que el predicado incluirán solo las instancias de mayor/menor valor del predicado correspondiente. El ranking no implica ordenación, ver -6.

Por ejemplo, usando proc.memory.rss (tamaño de memoria residente del proceso) como métrica de predicado junto con proc.io.total_bytes y mem.util.used como métricas a informar, solo los procesos que usan más/menos memoria (según -J) se incluirán al informar los bytes totales escritos por los procesos. Dado que mem.util.used es una métrica de valor único (por lo tanto, no comparte el mismo dominio de instancia que las métricas relacionadas con el proceso), se informará como de costumbre.

-O origen, --origin=origen
Al informar métricas archivadas, comienza a informar en origen dentro de la ventana de tiempo (ver -S y -T). Consulte PCPIntro(1) para una descripción completa de la sintaxis de origen.
-p puerto, --spark-port=puerto
Puerto local de pcp2spark.
-P precisión, --precision=precisión
Usa precisión para valores numéricos de salida no enteros. El valor predeterminado es usar 3 decimales (cuando sea aplicable). Esta opción no anulará las especificaciones posibles por métrica.
-q escala, --count-scale=escala
Unidad/escala para métricas de recuento, los valores posibles incluyen count x 10^-1, count, count x 10, count x 10^2, y así sucesivamente desde 10^-8 hasta 10^7. (Estos valores son actualmente sensibles al espacio.) Esta opción no anulará las especificaciones posibles por métrica. Ver también pmParseUnitsStr(3).
-Q escala, --count-scale-force=escala
Igual que -q pero esta opción anulará las especificaciones por métrica.
-r, --raw
Salida de valores de métricas sin procesar, no convierte contadores acumulativos a tasas. Esta opción anulará las especificaciones posibles por métrica.
-R, --raw-prefer
Igual que -r pero esta opción no anulará las especificaciones por métrica.
-s muestras, --samples=muestras
El argumento muestras define el número de muestras a recuperar e informar. Si muestras es 0 o no se especifica -s, pcp2spark tomará muestras e informará continuamente (en modo de tiempo real) o hasta el final del conjunto de archivos de PCP (en modo de archivo). Ver también -T.
-S tiempodeinicio, --start=tiempodeinicio
Al informar métricas archivadas, el informe se limitará a aquellos registros registrados a partir de tiempodeinicio. Consulte PCPIntro(1) para una descripción completa de la sintaxis de tiempodeinicio.
-t intervalo, --interval=intervalo
Establece el intervalo de informe a algo diferente del segundo predeterminado de 1 segundo. El argumento intervalo sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos). Ver también la opción -T.
-T tiempodefin, --finish=tiempodefin
Al informar métricas archivadas, el informe se limitará a aquellos registros registrados antes o en tiempodefin. Consulte PCPIntro(1) para una descripción completa de la sintaxis de tiempodefin.

Cuando se usa para definir el tiempo de ejecución antes de que pcp2spark salga, si no se proporciona ninguna muestra (ver -s), el número de muestras informadas dependerá del intervalo (ver -t). Si se proporciona muestra, el intervalo se ajustará para permitir el informe de muestras durante el tiempo de ejecución. En caso de que se proporcionen -T, -s y -t, tiempodefin determinará el tiempo real que se ejecutará pcp2spark.

-v, --omit-flat
Informa solo métricas de valor conjunto con instancias (por ejemplo, disk.dev.read) y omite métricas "planas" de valor único sin instancias (por ejemplo, kernel.all.sysfork). Ver -i y -I.
-V, --version
Muestra el número de versión y sale.
-y escala, --time-scale=escala
Unidad/escala para métricas de tiempo, los valores posibles incluyen nanosec, ns, microsec, us, millisec, ms, y así sucesivamente hasta hour, hr. E

OPCIONES

-Y escala, --time-scale-force=escala
Similar a -y, pero esta opción anulará las especificaciones por métrica.
-?, --help
Muestra el mensaje de uso y sale.

AMBIENTE PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parameterizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para las variables de entorno que afectan a las herramientas de PCP, consulte pmGetOptions(3).

De particular interés, PCP_DISCRETE_ONCE puede configurarse para asegurar que los valores de métricas discretas se informen solo una vez, a menos que cambien en algún momento.

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información es a veces críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
