NOMBRE

pcre2grep - grep con expresiones regulares compatibles con Perl.

SINOPSIS

pcre2grep [opciones] [opciones largas] [patrón] [ruta1 ruta2 ...]

DESCRIPCIÓN

pcre2grep busca archivos en busca de patrones de caracteres, de la misma manera que lo hacen otros comandos grep, pero utiliza la biblioteca de expresiones regulares PCRE2 para admitir patrones compatibles con las expresiones regulares de Perl 5. Consulte pcre2syntax(3) para un resumen de referencia rápida de la sintaxis de patrones, o pcre2pattern(3) para una descripción completa de la sintaxis y semántica de las expresiones regulares que admite PCRE2.

Los patrones, ya sean proporcionados en la línea de comandos o en un archivo separado, se proporcionan sin delimitadores. Por ejemplo:


pcre2grep Thursday /etc/motd

Si intenta usar delimitadores (por ejemplo, rodeando un patrón con barras inclinadas, como es común en los scripts de Perl), estos se interpretan como parte del patrón. Las comillas se pueden usar para delimitar patrones en la línea de comandos porque son interpretadas por el shell, y de hecho, las comillas son necesarias si un patrón contiene espacios en blanco o metacaracteres del shell.

El primer argumento que sigue a cualquier configuración de opción se trata como el único patrón a buscar cuando no están presentes ni -e ni -f. Por el contrario, cuando una o ambas de estas opciones se usan para especificar patrones, todos los argumentos se tratan como nombres de ruta. Se debe proporcionar al menos uno de -e, -f, o un patrón de argumento.

Si no se especifican archivos, pcre2grep lee la entrada estándar. La entrada estándar también se puede referenciar con un nombre que consiste en un guión simple. Por ejemplo:


pcre2grep some-pattern file1 - file3

Por defecto, se buscan archivos de entrada línea por línea, por lo que las aserciones de patrón sobre el principio y el final de una cadena sujeto (^, $, \A, \Z, y \z) coinciden al principio y al final de cada línea. Cuando una línea coincide con un patrón, se copia a la salida estándar, y si hay más de un archivo, el nombre del archivo se imprime al principio de cada línea, seguido de dos puntos. Sin embargo, existen opciones que pueden cambiar el comportamiento de pcre2grep. Por ejemplo, la opción -M permite buscar cadenas que abarcan los límites de línea. Lo que define un límite de línea está controlado por la opción -N (--newline). Las opciones -h y -H controlan si se muestran o no los nombres de archivo, y la opción -Z cambia el terminador del nombre de archivo a un byte nulo.

La cantidad de memoria utilizada para almacenar en caché los archivos que se están escaneando está controlada por parámetros que se pueden establecer mediante las opciones --buffer-size y --max-buffer-size. El primero de estos establece el tamaño del búfer que se obtiene al inicio del procesamiento. Si un archivo de entrada contiene líneas muy largas, puede ser necesario un búfer más grande; esto se maneja ampliando automáticamente el búfer, hasta el límite especificado por --max-buffer-size. Los valores predeterminados para estos parámetros se pueden establecer al compilar pcre2grep; si no se especifica nada, los valores predeterminados se establecen en 20KiB y 1MiB respectivamente. Se produce un error si una línea es demasiado larga y el búfer ya no se puede expandir.

El bloque de memoria que se utiliza realmente es tres veces el "tamaño del búfer", para permitir el almacenamiento en caché de líneas "anteriores" y "posteriores". Si el tamaño del búfer es demasiado pequeño, es posible que se produzcan menos líneas "anteriores" y "posteriores" de las solicitadas.

Al coincidir con un patrón multilínea, el tamaño del búfer debe ser al menos la mitad de la coincidencia máxima esperada o el patrón podría no coincidir.

Los patrones pueden tener una longitud máxima de 8KiB o BUFSIZ bytes, el que sea mayor. BUFSIZ se define en <stdio.h>. Cuando hay más de un patrón (especificado mediante el uso de -e y/o -f), cada patrón se aplica a cada línea en el orden en que se definen, excepto que todos los patrones -e se prueban antes que los patrones -f.

Por defecto, tan pronto como un patrón coincide con una línea, no se consideran más patrones. Sin embargo, si se utiliza --colour (o --color) para colorear las subcadenas coincidentes, o si se utiliza --only-matching, --file-offsets, --line-offsets o --output para mostrar solo la parte de la línea que coincidió (ya sea mostrada literalmente o como un desplazamiento), el comportamiento es diferente. En esta situación, todos los patrones se aplican a la línea. Si hay más de una coincidencia, se procesa la que comienza más cerca del principio del sujeto; si hay más de una coincidencia en esa posición, se procesa la que tiene la subcadena coincidente más larga; si las subcadenas coincidentes son iguales, se procesa la primera coincidencia encontrada.

El escaneo con todos los patrones se reanuda inmediatamente después de la coincidencia, de modo que se puedan encontrar coincidencias posteriores en la misma línea. Tenga en cuenta, sin embargo, que una coincidencia solapada que comienza en el medio de otra coincidencia no se procesará.

El comportamiento anterior se modificó en la versión 10.41 para ser más compatible con GNU grep. En versiones anteriores, pcre2grep no reconocía coincidencias de patrones posteriores que estuvieran antes en el sujeto.

Se aceptan patrones que pueden coincidir con una cadena vacía, pero nunca se reconocen las coincidencias de cadenas vacías. Un ejemplo es el patrón "(super)?(man)?", en el que todos los componentes son opcionales. Este patrón encuentra todas las ocurrencias de "super" y "man"; la salida difiere de la coincidencia con "super|man" cuando solo se muestran las subcadenas coincidentes.

Si la variable de entorno LC_ALL o LC_CTYPE está configurada, pcre2grep utiliza el valor para establecer una localización al llamar a la biblioteca PCRE2. La opción --locale puede usarse para anular esto.

SOPORTE PARA ARCHIVOS COMPRIMIDOS

Las opciones de compilación para pcre2grep pueden configurarlo para usar libz o libbz2 para leer archivos comprimidos cuyos nombres terminan en .gz o .bz2, respectivamente. Puede averiguar si su binario pcre2grep tiene soporte para uno o ambos de estos tipos de archivos ejecutándolo con la opción --help. Si no está presente el soporte apropiado, todos los archivos se tratan como texto plano. La entrada estándar siempre se trata así. Si un archivo con una extensión .gz o .bz2 no está en realidad comprimido, se lee como un archivo de texto plano. Cuando la entrada proviene de un archivo .gz o .bz2 comprimido, la opción --line-buffered se ignora.

ARCHIVOS BINARIOS

Por defecto, un archivo que contiene un byte nulo binario dentro de los primeros 1024 bytes se identifica como un archivo binario y se procesa especialmente. Sin embargo, si el tipo de salto de línea se especifica como NUL, es decir, el terminador de línea es un byte nulo, la prueba para un archivo binario no se aplica. Consulte la opción --binary-files para conocer una forma de cambiar la forma en que se manejan los archivos binarios.

CEROS BINARIOS EN PATRONES

Los patrones pasados desde la línea de comandos son cadenas que terminan con un cero binario, por lo que no pueden contener ceros internos. Sin embargo, los patrones que se leen de un archivo a través de la opción -f pueden contener ceros binarios.

OPCIONES

El orden en que aparecen algunas de las opciones puede afectar la salida. Por ejemplo, tanto las opciones -H como -l afectan a la impresión de los nombres de archivo. Cualquiera que aparezca más tarde en la línea de comandos será la que tenga efecto. De manera similar, excepto donde se indica a continuación, si se da una opción dos veces, se utiliza la última configuración. Los valores numéricos para las opciones pueden ir seguidos de K o M, para indicar la multiplicación por 1024 o 1024*1024, respectivamente.

-A número, --after-context=número
Escribe hasta número líneas de contexto después de cada línea coincidente. Se escriben menos líneas si la coincidencia anterior o el inicio del archivo están a menos de número líneas, o si el tamaño del búfer de procesamiento se ha establecido demasiado pequeño. Si se están escribiendo nombres de archivo y/o números de línea, se usa un guion separador en lugar de dos puntos para las líneas de contexto (la opción -Z se puede usar para cambiar el terminador de nombre de archivo a un byte cero). Se escribe una línea que contiene "--" entre cada grupo de líneas, a menos que en realidad sean contiguas en el archivo de entrada. Se espera que el valor de número sea relativamente pequeño. Cuando se usa -c, se ignora -A.
-a, --text
Trata los archivos binarios como texto. Esto es equivalente a --binary-files=text.
--allow-lookaround-bsk
PCRE2 ahora prohíbe el uso de \K en lookarounds por defecto, en línea con Perl. Esta opción hace que pcre2grep establezca la opción PCRE2_EXTRA_ALLOW_LOOKAROUND_BSK, que habilita este uso algo peligroso.
-B número, --before-context=número
Escribe hasta número líneas de contexto antes de cada línea coincidente. Se escriben menos líneas si la coincidencia anterior o el inicio del archivo están a menos de número líneas, o si el tamaño del búfer de procesamiento se ha establecido demasiado pequeño. Si se están escribiendo nombres de archivo y/o números de línea, se usa un guion separador en lugar de dos puntos para las líneas de contexto (la opción -Z se puede usar para cambiar el terminador de nombre de archivo a un byte cero). Se escribe una línea que contiene "--" entre cada grupo de líneas, a menos que en realidad sean contiguas en el archivo de entrada. Se espera que el valor de número sea relativamente pequeño. Cuando se usa -c, se ignora -B.
--binary-files=palabra
Especifica cómo se deben procesar los archivos binarios. Si la palabra es "binary" (el valor por defecto), se realiza una coincidencia de patrones en los archivos binarios, pero la única salida es "Binary file <name> matches" cuando una coincidencia tiene éxito. Si la palabra es "text", que es equivalente a la opción -a o --text, los archivos binarios se procesan de la misma manera que cualquier otro archivo. En este caso, cuando una coincidencia tiene éxito, la salida puede ser basura binaria, lo que puede tener efectos desagradables si se envía a una terminal. Si la palabra es "without-match", que es equivalente a la opción -I, los archivos binarios no se procesan en absoluto; se asume que no son de interés y se omiten sin generar ninguna salida ni afectar el código de retorno.
--buffer-size=número
Establece el parámetro que controla cuánta memoria se obtiene al inicio del procesamiento para el almacenamiento en búfer de los archivos que se están escaneando. Ver también --max-buffer-size a continuación.
-C número, --context=número
Escribe número líneas de contexto tanto antes como después de cada línea coincidente. Esto es equivalente a establecer tanto -A como -B con el mismo valor.
-c, --count
No escribe líneas de los archivos que se están escaneando; en su lugar, escribe el número de líneas que se habrían mostrado, ya sea porque coincidieron, o, si se establece -v, porque no coincidieron. Por defecto, este recuento es exactamente el mismo que el número de líneas que se habrían mostrado, pero si se utiliza la opción -M (multilínea) (sin -v), puede haber más líneas suprimidas que el recuento (es decir, el número de coincidencias).

Si no se seleccionan líneas, se escribe el número cero. Si se están escaneando varios archivos, se escribe un recuento para cada uno de ellos y la opción -t se puede usar para hacer que se escriba un total al final. Sin embargo, si también se utiliza la opción --files-with-matches, solo se enumeran aquellos archivos cuyos recuentos son mayores que cero. Cuando se usa -c, se ignoran las opciones -A, -B y -C.

--colour, --color
Si se proporciona esta opción sin ningún dato, es equivalente a "--colour=auto". Si se requieren datos, deben proporcionarse en el mismo elemento del shell, separados por un signo igual.
--colour=valor, --color=valor
Esta opción especifica bajo qué circunstancias las partes de una línea que coincidieron con un patrón deben colorearse en la salida. Se ignora si se establecen --file-offsets, --line-offsets o --output. Por defecto, la salida no se colorea. El valor para la opción --colour (que es opcional, ver arriba) puede ser "never", "always", o "auto". En este último caso, el coloreado solo ocurre si la salida estándar está conectada a una terminal. Se utilizan más recursos cuando el coloreado está habilitado, ya que pcre2grep tiene que buscar todas las coincidencias posibles en una línea, no solo una, para colorearlas todas.

El color que se utiliza se puede especificar estableciendo una de las variables de entorno PCRE2GREP_COLOUR, PCRE2GREP_COLOR, PCREGREP_COLOUR, o PCREGREP_COLOR, que se comprueban en ese orden. Si ninguna de estas está configurada, pcre2grep busca GREP_COLORS o GREP_COLOR (en ese orden). El valor de la variable debe ser una cadena de dos números, separados por un punto y coma, excepto en el caso de GREP_COLORS, que debe comenzar con "ms=" o "mt=" seguido de dos colores separados por punto y coma, terminados por el final de la cadena o por dos puntos. Si GREP_COLORS no comienza con "ms=" o "mt=" se ignora y se comprueba GREP_COLOR.

Si la cadena obtenida de una de las variables anteriores contiene caracteres distintos de punto y coma o dígitos, la configuración se ignora y se utiliza el color por defecto. La cadena se copia directamente en la cadena de control para establecer el color en una terminal, por lo que es su responsabilidad asegurarse de que los valores tengan sentido. Si no se establece ninguna variable de entorno relevante, el valor por defecto es "1;31", que da rojo.

-D acción, --devices=acción
Si una ruta de entrada no es un archivo regular o un directorio, "acción" especifica cómo se debe procesar. Los valores válidos son "read" (el valor por defecto) o "skip" (omitir silenciosamente la ruta).
-d acción, --directories=acción
Si una ruta de entrada es un directorio, "acción" especifica cómo se debe procesar. Los valores válidos son "read" (el valor por defecto en entornos no Windows, por compatibilidad con GNU grep), "recurse" (equivalente a la opción -r), o "skip" (omitir silenciosamente la ruta, el valor por defecto en entornos Windows). En el caso "read", los directorios se leen como si fueran archivos ordinarios. En algunos sistemas operativos, el efecto de leer un directorio de esta manera es un fin de archivo inmediato; en otros, puede provocar un error.
--depth-limit=número
Ver --match-limit a continuación.
-E, --case-restrict
Cuando se ignoran las distinciones de mayúsculas y minúsculas en modo Unicode, dos letras ASCII (K y S) coincidirán por defecto con los caracteres Unicode U+212A (signo de Kelvin) y U+017F (S larga), así como con sus contrapartes ASCII en minúsculas. Cuando se establece esta opción, las equivalencias de mayúsculas y minúsculas se restringen de modo que ningún carácter ASCII coincida con un carácter no ASCII, y viceversa.
-e patrón, --regex=patrón, --regexp=patrón
Especifica un patrón a buscar. Esta opción se puede usar varias veces para especificar varios patrones. También se puede usar como una forma de especificar un solo patrón que comienza con un guion. Cuando se usa -e, no se toman patrones de los argumentos de la línea de comandos; todos los argumentos se tratan como nombres de archivo. No hay límite en el número de patrones. Se aplican a cada línea en el orden en que se definen.

Si se usa -f con -e, los patrones de la línea de comandos se buscan primero, seguidos por los patrones de los archivos, independientemente del orden en que se especifiquen estas opciones.

--exclude=patrón
Los archivos (pero no los directorios) cuyos nombres coinciden con el patrón se omiten sin ser procesados. Esto se aplica a todos los archivos, ya sean listados en la línea de comandos, obtenidos de --file-list, o escaneando un directorio. El patrón es una expresión regular PCRE2 y se compara con el componente final del nombre del archivo, no con la ruta completa. Las opciones -F, -w y -x no se aplican a este patrón. La opción se puede dar cualquier número de veces para especificar múltiples patrones. Si un nombre de archivo coincide tanto con un patrón --include como con un patrón --exclude, se excluye. No hay forma abreviada para esta opción.
--exclude-from=nombrearchivo
Trata cada línea no vacía del archivo como datos para una opción --exclude. Lo que constituye una nueva línea al leer el archivo es el valor por defecto del sistema operativo. La opción --newline no tiene efecto en esta opción. Esta opción se puede dar más de una vez para especificar un número de archivos para leer.
--exclude-dir=patrón
Los directorios cuyos nombres coinciden con el patrón se omiten sin ser procesados, cualquiera que sea la configuración de la opción --recursive. Esto se aplica a todos los directorios, ya sean listados en la línea de comandos, obtenidos de --file-list, o escaneando un directorio padre. El patrón es una expresión regular PCRE2 y se compara con el componente final del nombre del directorio, no con la ruta completa. Las opciones -F, -w y -x no se aplican a este patrón. La opción se puede dar cualquier número de veces para especificar más de un patrón. Si un directorio coincide tanto con --include-dir como con --exclude-dir, se excluye. No hay forma abreviada para esta opción.
-F, --fixed-strings
Interpreta cada patrón de coincidencia de datos como una lista de cadenas fijas, separadas por saltos de línea, en lugar de como una expresión regular. Lo que constituye un salto de línea para este propósito está controlado por la opción --newline. Las opciones -w (buscar como palabra) y -x (buscar línea completa) se pueden usar con -F. Se aplican a cada una de las cadenas fijas. Se selecciona una línea si se encuentra alguna de las cadenas fijas en ella (sujeto a -w o -x, si están presentes). Esta opción solo se aplica a los patrones que se comparan con el contenido.

-f nombre_archivo, --file=nombre_archivo
Lee los patrones del archivo, uno por línea. Al igual que con los patrones en la línea de comandos, no se deben usar delimitadores. Lo que constituye un salto de línea al leer el archivo es la interpretación predeterminada de \n por parte del sistema operativo. La opción --newline no tiene ningún efecto en esta opción. Se eliminan los espacios en blanco finales de cada línea y se ignoran las líneas en blanco a menos que también se proporcione la opción --posix-pattern-file. Un archivo vacío contiene ningún patrón y, por lo tanto, no coincide con nada. Los patrones leídos de un archivo de esta manera pueden contener ceros binarios, que se tratan como literales de caracteres ordinarios.

Si se proporciona esta opción más de una vez, se leen todos los archivos especificados. Se emite una línea de datos si alguno de los patrones coincide con ella. El nombre de un archivo puede ser "-" para referirse a la entrada estándar. Cuando se usa -f, también pueden estar presentes los patrones especificados en la línea de comandos usando -e; estos se comparan antes que los patrones del archivo. Sin embargo, no se toma ningún patrón de la línea de comandos; todos los argumentos se tratan como los nombres de las rutas a buscar.

--file-list=nombre_archivo
Lee una lista de archivos y/o directorios que se van a escanear del archivo dado, uno por línea. Lo que constituye un salto de línea al leer el archivo es el valor predeterminado del sistema operativo. Se eliminan los espacios en blanco finales de cada línea y se ignoran las líneas en blanco. Estas rutas se procesan antes que las que figuran en la línea de comandos. El nombre del archivo puede ser "-" para referirse a la entrada estándar. Si --file y --file-list se especifican ambos como "-", los patrones se leen primero. Esto solo es útil cuando la entrada estándar es una terminal, de la que se pueden leer líneas adicionales (la lista de archivos) después de una indicación de fin de archivo. Si se proporciona esta opción más de una vez, se leen todos los archivos especificados.
--file-offsets
En lugar de mostrar líneas o partes de líneas que coinciden, muestra cada coincidencia como un desplazamiento desde el inicio del archivo y una longitud, separados por una coma. En este modo, --colour no tiene ningún efecto y no se muestra contexto. Es decir, las opciones -A, -B y -C se ignoran. Si hay más de una coincidencia en una línea, cada una de ellas se muestra por separado. Esta opción es mutuamente excluyente con --output, --line-offsets y --only-matching.
--group-separator=texto
Emite esta cadena de texto en lugar de dos guiones entre grupos de líneas cuando se utiliza -A, -B o -C. Véase también --no-group-separator.
-H, --with-filename
Fuerza la inclusión del nombre del archivo al inicio de las líneas de salida al buscar en un solo archivo. El nombre del archivo normalmente no se muestra en este caso. Por defecto, para las líneas coincidentes, el nombre del archivo va seguido de dos puntos; para las líneas de contexto, se utiliza un separador de guion. La opción -Z puede usarse para cambiar el terminador a un byte cero. Si también se está emitiendo un número de línea, este sigue al nombre del archivo. Cuando la opción -M hace que un patrón coincida con más de una línea, solo la primera va precedida por el nombre del archivo. Esta opción anula cualquier opción anterior -h, -l o -L.
-h, --no-filename
Suprime los nombres de archivo de salida al buscar en varios archivos. Los nombres de archivo normalmente se muestran al buscar en varios archivos. Por defecto, para las líneas coincidentes, el nombre del archivo va seguido de dos puntos; para las líneas de contexto, se utiliza un separador de guion. La opción -Z puede usarse para cambiar el terminador a un byte cero. Si también se está emitiendo un número de línea, este sigue al nombre del archivo. Esta opción anula cualquier opción anterior -H, -L o -l.
--heap-limit=número
Véase --match-limit más abajo.
--help
Emite un mensaje de ayuda, que detalla brevemente las opciones del comando y el soporte de tipos de archivo, y luego sale. Cualquier otra cosa en la línea de comandos se ignora.
-I
Ignora los archivos binarios. Esto es equivalente a --binary-files=without-match.
-i, --ignore-case
Ignora las distinciones entre mayúsculas y minúsculas al comparar patrones. Esto se aplica al comparar nombres de ruta para inclusión o exclusión, así como al comparar líneas en archivos.
--include=patrón
Si se especifican patrones --include, los únicos archivos que se procesan son aquellos cuyos nombres coinciden con uno de los patrones y no coinciden con un patrón --exclude. Esta opción no afecta a los directorios, pero se aplica a todos los archivos, ya sean listados en la línea de comandos, obtenidos de --file-list o escaneando un directorio. El patrón es una expresión regular PCRE2 y se compara con el componente final del nombre del archivo, no con la ruta completa. Las opciones -F, -w y -x no se aplican a este patrón. La opción puede especificarse cualquier número de veces. Si un nombre de archivo coincide tanto con un patrón --include como con un patrón --exclude, se excluye. No hay forma corta para esta opción.
--include-from=nombre_archivo
Trata cada línea no vacía del archivo como datos para una opción --include. Lo que constituye un salto de línea para este propósito es el valor predeterminado del sistema operativo. La opción --newline no tiene efecto en esta opción. Esta opción puede especificarse varias veces; se leen todos los archivos.
--include-dir=patrón
Si se especifican patrones --include-dir, los únicos directorios que se procesan son aquellos cuyos nombres coinciden con uno de los patrones y no coinciden con un patrón --exclude-dir. Esto se aplica a todos los directorios, ya sean listados en la línea de comandos, obtenidos de --file-list o escaneando un directorio padre. El patrón es una expresión regular PCRE2 y se compara con el componente final del nombre del directorio, no con la ruta completa. Las opciones -F, -w y -x no se aplican a este patrón. La opción puede especificarse cualquier número de veces. Si un directorio coincide tanto con --include-dir como con --exclude-dir, se excluye. No hay forma corta para esta opción.
-L, --files-without-match
En lugar de emitir líneas de los archivos, simplemente emite los nombres de los archivos que no contienen ninguna línea que hubiera sido emitida. Cada nombre de archivo se emite una vez, en una línea separada por defecto, pero si se establece la opción -Z, se separan por bytes cero en lugar de saltos de línea. Esta opción anula cualquier opción anterior -H, -h o -l.
-l, --files-with-matches
En lugar de emitir líneas de los archivos, simplemente emite los nombres de los archivos que contienen líneas que hubieran sido emitidas. Cada nombre de archivo se emite una vez, en una línea separada, pero si se establece la opción -Z, se separan por bytes cero en lugar de saltos de línea. La búsqueda normalmente se detiene tan pronto como se encuentra una línea coincidente en un archivo. Sin embargo, si también se utiliza la opción -c (count), la búsqueda continúa para obtener el recuento correcto, y se listan los archivos que tienen al menos una coincidencia junto con sus recuentos. Usar esta opción con -c es una forma de suprimir la lista de archivos sin coincidencias que ocurre con -c por sí sola. Esta opción anula cualquier opción anterior -H, -h o -L.
--label=nombre
Esta opción proporciona un nombre que se utilizará para la entrada estándar cuando se muestren los nombres de archivo. Si no se proporciona, se utiliza "(standard input)". No hay forma corta para esta opción.
--line-buffered
Cuando se proporciona esta opción, la entrada no comprimida se lee y procesa línea por línea, y la salida se vacía después de cada escritura. Por defecto, la entrada se lee en bloques grandes, a menos que pcre2grep determine que está leyendo desde una terminal, lo cual actualmente solo es posible en entornos tipo Unix o Windows. La salida a la terminal normalmente es vaciada automáticamente por el sistema operativo. Esta opción puede ser útil cuando la entrada o la salida están conectadas a una tubería y no desea que pcre2grep almacene grandes cantidades de datos en búfer. Sin embargo, su uso afectará al rendimiento y la opción -M (multilínea) dejará de funcionar. Cuando la entrada proviene de un archivo comprimido .gz o .bz2, --line-buffered se ignora.
--line-offsets
En lugar de mostrar líneas o partes de líneas que coinciden, muestra cada coincidencia como un número de línea, el desplazamiento desde el inicio de la línea y una longitud. El número de línea está terminado por dos puntos (como de costumbre; véase la opción -n), y el desplazamiento y la longitud están separados por una coma. En este modo, --colour no tiene ningún efecto y no se muestra contexto. Es decir, las opciones -A, -B y -C se ignoran. Si hay más de una coincidencia en una línea, cada una de ellas se muestra por separado. Esta opción es mutuamente excluyente con --output, --file-offsets y --only-matching.
--locale=nombre_localidad
Esta opción especifica una localidad que se utilizará para la comparación de patrones. Anula el valor en las variables de entorno LC_ALL o LC_CTYPE. Si no se especifica ninguna localidad, se utiliza el valor predeterminado de la biblioteca PCRE2 (normalmente la localidad "C"). No hay forma corta para esta opción.
-M, --multiline
Permite que los patrones coincidan con más de una línea. Cuando se establece esta opción, la biblioteca PCRE2 se llama en modo "multilínea", y se permite que una coincidencia continúe más allá del final de la línea inicial y hasta una o más líneas subsiguientes.

Los patrones utilizados con -M pueden contener útiles caracteres de salto de línea literales y ocurrencias internas de caracteres ^ y $, porque en modo multilínea estos pueden coincidir en saltos de línea internos. Debido a que pcre2grep está escaneando múltiples líneas, las aserciones \Z y \z coinciden solo en

y al final de la última línea del archivo. La aserción \A coincide al principio de la primera línea de una coincidencia. Esta puede ser cualquier línea del archivo; no está anclada a la primera línea.

La salida de una coincidencia exitosa puede constar de más de una línea. La primera línea es la línea en la que comenzó la coincidencia, y la última línea es la línea en la que terminó la coincidencia. Si la cadena coincidente termina con una secuencia de nueva línea, la salida termina al final de esa línea. Si se establece -v, ninguna de las líneas de una coincidencia multilínea se mostrará. Una vez que se ha gestionado una coincidencia, el escaneo se reanuda al principio de la línea posterior a la que terminó la coincidencia.

La secuencia de nueva línea que separa múltiples líneas debe coincidir como parte del patrón. Por ejemplo, para encontrar la frase "expresión regular" en un archivo donde "expresión" podría estar al final de una línea y "regular" al principio de la siguiente, podría usar este comando:


pcre2grep -M 'expresión\s+regular' <archivo>

La secuencia de escape \s coincide con cualquier carácter de espacio en blanco, incluidas las nuevas líneas, y va seguida de + para coincidir con el espacio en blanco final en la primera línea, así como posiblemente para manejar una secuencia de nueva línea de dos caracteres.

Existe un límite en la cantidad de líneas que se pueden hacer coincidir, impuesto por la forma en que pcre2grep almacena en búfer el archivo de entrada mientras lo escanea. Con un búfer de procesamiento lo suficientemente grande, esto no debería ser un problema.

La opción -M no funciona cuando la entrada se lee línea por línea (ver --line-buffered).

-m número, --max-count=número
Deje de procesar después de encontrar número líneas coincidentes, o líneas no coincidentes si también se establece -v. Cualquier línea de contexto final se mostrará después de la última coincidencia. En modo multilínea, cada coincidencia multilínea cuenta como una sola línea para este propósito. Si se alcanza este límite al leer la entrada estándar de un archivo regular, el archivo se deja posicionado justo después de la última línea coincidente. Si también se establece -c, el recuento que se muestra nunca es mayor que número. Esta opción no tiene efecto si se usa con -L, -l o -q, o cuando solo se verifica una coincidencia en un archivo binario.
--match-limit=número
Procesar algunos patrones de expresiones regulares puede llevar mucho tiempo para buscar todas las cadenas coincidentes posibles. Otros pueden requerir una gran cantidad de memoria. Hay tres opciones que establecen límites de recursos para la coincidencia.

La opción --match-limit proporciona un medio para limitar el uso de recursos de cómputo al procesar patrones que no van a coincidir, pero que tienen un gran número de posibilidades en sus árboles de búsqueda. El ejemplo clásico es un patrón que utiliza repeticiones anidadas ilimitadas. Internamente, PCRE2 tiene un contador que se incrementa cada vez que se recorre su bucle de procesamiento principal. Si se alcanza el valor establecido por --match-limit, se produce un error.

La opción --heap-limit especifica, como un número de kibibytes (unidades de 1024 bytes), la cantidad máxima de memoria del montón que se puede usar para la coincidencia.

La opción --depth-limit limita la profundidad de los puntos de retroceso anidados, lo que limita indirectamente la cantidad de memoria que se utiliza. La cantidad de memoria necesaria para cada punto de retroceso depende del número de paréntesis de captura en el patrón, por lo que la cantidad de memoria que se utiliza antes de que este límite actúe varía de un patrón a otro. Este límite es útil solo si se establece en un valor menor que --match-limit.

No hay formas cortas para estas opciones. Los límites predeterminados se pueden establecer al compilar la biblioteca PCRE2; si no se especifican, los valores predeterminados son muy grandes y, por lo tanto, efectivamente ilimitados.

--max-buffer-size=número
Esto limita la expansión del búfer de procesamiento, cuyo tamaño inicial se puede establecer mediante --buffer-size. El tamaño máximo del búfer se fuerza silenciosamente a que no sea menor que el tamaño inicial del búfer.
-N tipo-de-nueva-linea, --newline=tipo-de-nueva-linea
Se admiten seis convenciones diferentes para indicar los finales de línea en los archivos escaneados. Por ejemplo:


pcre2grep -N CRLF 'patrón_a_buscar' <archivo>

El tipo de nueva línea se puede especificar en mayúsculas, minúsculas o una combinación de ambas. Si el tipo de nueva línea es NUL, las líneas se separan por caracteres de cero binario. Los otros tipos son las secuencias de un solo carácter CR (retorno de carro) y LF (avance de línea), la secuencia de dos caracteres CRLF, un tipo "anycrlf", que reconoce cualquiera de los tipos anteriores, y un tipo "any", para el que se supone que cualquier secuencia de final de línea Unicode termina una línea. Las secuencias Unicode son las tres mencionadas anteriormente, más VT (tabulación vertical, U+000B), FF (salto de página, U+000C), NEL (nueva línea, U+0085), LS (separador de línea, U+2028) y PS (separador de párrafo, U+2029).

Cuando se compila la biblioteca PCRE2, se especifica una secuencia de fin de línea predeterminada. Esta suele ser la secuencia estándar para el sistema operativo. A menos que se especifique lo contrario con esta opción, pcre2grep utiliza la predeterminada de la biblioteca.

Esta opción hace posible utilizar pcre2grep para escanear archivos que provienen de otros entornos sin tener que modificar sus finales de línea. Si los datos que se están escaneando no concuerdan con la convención establecida por esta opción, pcre2grep puede comportarse de manera extraña. Tenga en cuenta que esta opción no se aplica a los archivos especificados por las opciones -f, --exclude-from o --include-from, que se espera que utilicen la secuencia de nueva línea estándar del sistema operativo.

-n, --line-number
Anteponer a cada línea de salida su número de línea en el archivo, seguido de dos puntos para las líneas coincidentes o un guion para las líneas de contexto. Si el nombre del archivo también se está mostrando, precede al número de línea. Cuando la opción -M hace que un patrón coincida con más de una línea, solo la primera se precede de su número de línea. Esta opción se fuerza si se utiliza --line-offsets.
--no-group-separator
No mostrar un separador entre grupos de líneas cuando se utilizan -A, -B o -C. El valor predeterminado es mostrar una línea que contiene dos guiones. Ver también --group-separator.
--no-jit
Si la biblioteca PCRE2 se compila con soporte para compilación justo a tiempo (que acelera la coincidencia), pcre2grep la utiliza automáticamente, a menos que se haya deshabilitado explícitamente en el momento de la compilación. Esta opción se puede utilizar para deshabilitar el uso de JIT en tiempo de ejecución. Se proporciona para pruebas y para solucionar problemas. Nunca debería ser necesaria en un uso normal.
-O texto, --output=texto
Cuando hay una coincidencia, en lugar de mostrar la línea que coincidió, muestra solo el texto especificado en esta opción, seguido de una nueva línea estándar del sistema operativo. En este modo, --colour no tiene efecto, y no se muestra ningún contexto. Es decir, las opciones -A, -B y -C se ignoran. La opción --newline no tiene efecto en esta opción, que es mutuamente excluyente con --only-matching, --file-offsets y --line-offsets. Sin embargo, al igual que --only-matching, si hay más de una coincidencia en una línea, cada una de ellas provoca una línea de salida.

Se pueden usar secuencias de escape que comiencen con un carácter de dólar para insertar el contenido de la parte coincidente de la línea y/o subcadenas capturadas en el texto.

$<dígitos> o ${<dígitos>} se reemplaza por la subcadena capturada del número decimal dado; $& (o el $0 heredado) sustituye la coincidencia completa. Si el número es mayor que el número de subcadenas capturadas, o si la captura no está establecida, el reemplazo está vacío.

$a se reemplaza por campana; $b por retroceso; $e por escape; $f por salto de página; $n por nueva línea; $r por retorno de carro; $t por tabulación; $v por tabulación vertical.

$o<dígitos> o $o{<dígitos>} se reemplaza por el carácter cuyo punto de código es el número octal dado. En la primera forma, se procesan hasta tres dígitos octales. Cuando se necesitan más dígitos en modo Unicode para especificar un carácter ancho, se debe usar la segunda forma.

$x<dígitos> o $x{<dígitos>} se reemplaza por el carácter representado por el número hexadecimal dado. En la primera forma, se procesan hasta dos dígitos hexadecimales. Cuando se necesitan más dígitos en modo Unicode para especificar un carácter ancho, se debe usar la segunda forma.

Cualquier otro carácter se sustituye por sí mismo. En particular, $$ se reemplaza por un solo dólar.

-o, --only-matching
Mostrar solo la parte de la línea que coincidió con un patrón en lugar de la línea completa. En este modo, no se muestra ningún contexto. Es decir, las opciones -A, -B y -C se ignoran. Si hay más de una coincidencia en una línea, cada una de ellas se muestra por separado, en una línea de salida separada. Si -o se combina con -v (invertir el sentido de la coincidencia para encontrar líneas no coincidentes), no se genera ninguna salida, pero el código de retorno se establece adecuadamente. Si la porción coincidente de la línea está vacía, no se muestra nada a menos que se estén imprimiendo el nombre del archivo o el número de línea, en cuyo caso se muestran en una línea de lo contrario vacía. Esta opción es mutuamente excluyente con --output, --file-offsets y --line-offsets.
-onúmero, --only-matching=número
Mostrar solo la parte de la línea que coincidió con los paréntesis de captura del número dado. Se admiten hasta 50 paréntesis de captura por defecto. Este límite se puede cambiar mediante la opción --om-capture. Un patrón puede contener cualquier número de paréntesis de captura, pero solo aquellos cuyo número esté dentro del límite se pueden acceder mediante -o. Se produce un error si el número especificado por -o es mayor que el límite.

-o0 es lo mismo que -o sin número. Dado que estas opciones se pueden dar sin argumento (ver arriba), si hay un argumento, debe darse en el mismo elemento del shell, por ejemplo, -o3 o --only-matching=2. Los comentarios dados para el caso sin argumento anterior también se aplican a esta opción. Si la captura especificada

-o, --only-matching
Extract and display only the part of the line that matches the pattern. If the pattern contains capturing parentheses, and if they were set in the match, the substring(s) matched by the parentheses are output. If the pattern does not contain capturing parentheses, or if they were not set in the match, nothing is output unless the file name or line number are being output.
If this option is given multiple times, multiple substrings are output for each match, in the order the options are given, and all on one line. For example, -o3 -o1 -o3 causes the substrings matched by capturing parentheses 3 and 1 and then 3 again to be output. By default, there is no separator (but see the next but one option).

--om-capture=number

Set the number of capturing parentheses that can be accessed by -o. The default is 50.

--om-separator=text

Specify a separating string for multiple occurrences of -o. The default is an empty string. Separating strings are never coloured.

-P, --no-ucp

Starting from release 10.43, when UTF/Unicode mode is specified with -u or -U, the PCRE2_UCP option is used by default. This means that the POSIX classes in patterns match more than just ASCII characters. For example, [:digit:] matches any Unicode decimal digit. The --no-ucp option suppresses PCRE2_UCP, thus restricting the POSIX classes to ASCII characters, as was the case in earlier releases. Note that there are now more fine-grained option settings within patterns that affect individual classes. For example, when in UCP mode, the sequence (?aP) restricts [:word:] to ASCII letters, while allowing \w to match Unicode letters and digits.

--posix-pattern-file

When patterns are provided with the -f option, do not trim trailing spaces or ignore empty lines in a similar way than other grep tools. To keep the behaviour consistent with older versions, if the pattern read was terminated with CRLF (as character literals) then both characters won't be included as part of it, so if you really need to have pattern ending in '\r', use a escape sequence or provide it by a different method.

-q, --quiet

Work quietly, that is, display nothing except error messages. The exit status indicates whether or not any matches were found.

-r, --recursive

If any given path is a directory, recursively scan the files it contains, taking note of any --include and --exclude settings. By default, a directory is read as a normal file; in some operating systems this gives an immediate end-of-file. This option is a shorthand for setting the -d option to "recurse".

--recursion-limit=number

This is an obsolete synonym for --depth-limit. See --match-limit above for details.

-s, --no-messages

Suppress error messages about non-existent or unreadable files. Such files are quietly skipped. However, the return code is still 2, even if matches were found in other files.

-t, --total-count

This option is useful when scanning more than one file. If used on its own, -t suppresses all output except for a grand total number of matching lines (or non-matching lines if -v is used) in all the files. If -t is used with -c, a grand total is output except when the previous output is just one line. In other words, it is not output when just one file's count is listed. If file names are being output, the grand total is preceded by "TOTAL:". Otherwise, it appears as just another number. The -t option is ignored when used with -L (list files without matches), because the grand total would always be zero.

-u, --utf

Operate in UTF/Unicode mode. This option is available only if PCRE2 has been compiled with UTF-8 support. All patterns (including those for any --exclude and --include options) and all lines that are scanned must be valid strings of UTF-8 characters. If an invalid UTF-8 string is encountered, an error occurs.

-U, --utf-allow-invalid

As --utf, but in addition subject lines may contain invalid UTF-8 code unit sequences. These can never form part of any pattern match. Patterns themselves, however, must still be valid UTF-8 strings. This facility allows valid UTF-8 strings to be sought within arbitrary byte sequences in executable or other binary files. For more details about matching in non-valid UTF-8 strings, see the pcre2unicode(3) documentation.

-V, --version

Write the version numbers of pcre2grep and the PCRE2 library to the standard output and then exit. Anything else on the command line is ignored.

-v, --invert-match

Invert the sense of the match, so that lines which do not match any of the patterns are the ones that are found. When this option is set, options such as --only-matching and --output, which specify parts of a match that are to be output, are ignored.

-w, --word-regex, --word-regexp

Force the patterns only to match "words". That is, there must be a word boundary at the start and end of each matched string. This is equivalent to having "\b(?:" at the start of each pattern, and ")\b" at the end. This option applies only to the patterns that are matched against the contents of files; it does not apply to patterns specified by any of the --include or --exclude options.

-x, --line-regex, --line-regexp

Force the patterns to start matching only at the beginnings of lines, and in addition, require them to match entire lines. In multiline mode the match may be more than one line. This is equivalent to having "^(?:" at the start of each pattern and ")$" at the end. This option applies only to the patterns that are matched against the contents of files; it does not apply to patterns specified by any of the --include or --exclude options.

-Z, --null

Terminate files names in the regular output with a zero byte (the NUL character) instead of what would normally appear. This is useful when file names contain unusual characters such as colons, hyphens, or even newlines. The option does not apply to file names in error messages.

VARIABLES DEL ENTORNO

Las variables de entorno LC_ALL y LC_CTYPE se examinan, en ese orden, para obtener una configuración regional. La primera que se establezca se utilizará. Esto puede ser anulado por la opción --locale. Si no se establece ninguna configuración regional, se utiliza la configuración regional predeterminada de la biblioteca PCRE2 (generalmente la configuración regional "C").

NUEVAS LÍNEAS

La opción -N (--newline) permite a pcre2grep escanear archivos con convenciones de nueva línea que difieren de las predeterminadas. Esta opción solo afecta a la forma en que se procesan los archivos escaneados. No afecta la interpretación de los archivos especificados por las opciones -f, --file-list, --exclude-from o --include-from.

Cualquier parte de los archivos de entrada escaneados que se escriba en la salida estándar se copiará con las secuencias de nueva línea que tengan en la entrada. Sin embargo, si la última línea de un archivo se muestra y no termina con una secuencia de nueva línea, se añadirá una secuencia de nueva línea. Si la configuración de nueva línea es CR, LF, CRLF o NUL, se mostrará ese final de línea; para las otras configuraciones (ANYCRLF o ANY) se usará un solo NL.

La configuración de nueva línea no afecta la forma en que pcre2grep escribe nuevas líneas en los mensajes informativos a los flujos de salida estándar y de error. En Windows, la salida estándar se configura como binaria, de modo que "\r\n" al final de las líneas de salida que se copian de la entrada no se convierte en "\r\r\n" por la biblioteca C I/O. Esto significa que cualquier mensaje escrito en la salida estándar debe terminar con "\r\n". Para todos los demás sistemas operativos, y para todos los mensajes al flujo de error estándar, se usa "\n".

COMPATIBILIDAD DE OPCIONES CON GNU GREP

Muchas de las formas cortas y largas de las opciones de pcre2grep son las mismas que en el programa GNU grep. Cualquier opción larga de la forma --xxx-regexp (terminología GNU) también está disponible como --xxx-regex (terminología PCRE2). Sin embargo, las opciones --case-restrict, --depth-limit, -E, --file-list, --file-offsets, --heap-limit, --include-dir, --line-offsets, --locale, --match-limit, -M, --multiline, -N, --newline, --no-ucp, --om-separator, --output, -P, -u, --utf, -U y --utf-allow-invalid son específicas de pcre2grep, al igual que el uso de la opción --only-matching con un número de paréntesis de captura.

Aunque la mayoría de las opciones comunes funcionan de la misma manera, algunas son diferentes en pcre2grep. Por ejemplo, el argumento de la opción --include es un glob para GNU grep, pero en pcre2grep es una expresión regular a la que se aplica la opción -i. Si se dan las opciones -c y -l, GNU grep lista solo los nombres de archivo, sin recuentos, pero pcre2grep proporciona también los recuentos.

OPCIONES CON DATOS

Hay cuatro formas diferentes en las que se puede especificar una opción con datos. Si se utiliza una forma corta de opción, los datos pueden seguir inmediatamente, o (con una excepción) en el siguiente elemento de la línea de comandos. Por ejemplo:


-f/algún/archivo
-f /algún/archivo

La excepción es la opción -o, que puede aparecer con o sin datos. Debido a esto, si hay datos presentes, deben seguir inmediatamente en el mismo elemento, por ejemplo -o3.

Si se utiliza una forma larga de opción, los datos pueden aparecer en el mismo elemento de la línea de comandos, separados por un signo igual, o (con dos excepciones) pueden aparecer

OPTIONS WITH DATA

Some options require data to be supplied on the command line. This data can be supplied in one of two forms:

  • An equals sign follows the option, and then the data, with no intervening whitespace.

  • An equals sign is omitted, and there is whitespace between the option and the data. The data must be the next item on the command line.

For example:


--file=/some/file
--file /some/file

Note, however, that if you want to supply a file name beginning with ~ as data in a shell command, and have the shell expand ~ to a home directory, you must separate the file name from the option, because the shell does not treat ~ specially unless it is at the start of an item.

The exceptions to the above are the --colour (or --color) and --only-matching options, for which the data is optional. If one of these options does have data, it must be given in the first form, using an equals character. Otherwise pcre2grep will assume that it has no data.

USANDO LA INSTALACIÓN DE LLAMADA DE PCRE2

pcre2grep tiene, por defecto, soporte para llamar a programas o scripts externos o para mostrar cadenas específicas durante la correspondencia, haciendo uso de la instalación de llamada de PCRE2. Sin embargo, este soporte puede ser deshabilitado completamente o parcialmente cuando se compila pcre2grep. Puede averiguar si su binario tiene soporte para llamadas ejecutándolo con la opción --help. Si el soporte de llamadas está completamente deshabilitado, las llamadas en los patrones están prohibidas por pcre2grep. Si la instalación está parcialmente deshabilitada, la llamada a programas externos no está soportada y las llamadas que la solicitan se ignoran.

Una llamada en un patrón PCRE2 tiene la forma (?C<arg>) donde el argumento es un número o una cadena entre comillas (ver la documentación de pcre2callout para más detalles). Las llamadas numeradas son ignoradas por pcre2grep; solo las llamadas con argumentos de cadena son útiles.

Mostrar una cadena específica

Iniciar la cadena de llamada con un carácter de barra vertical invoca una instalación de eco que evita llamar a un programa o script externo. Esta instalación está siempre disponible, siempre que las llamadas no hayan sido completamente deshabilitadas al compilar pcre2grep. El resto de la cadena de llamada se procesa como una cadena terminada en cero, lo que significa que no debe contener ningún cero binario interno. Se escribe en la salida, después de haber sido procesada a través del mismo procesamiento de escape que el texto de la opción --output (-O) (ver arriba). Sin embargo, $0 o $& no se pueden usar para insertar una subcadena correspondiente porque la correspondencia aún está en progreso. En su lugar, se inserta el carácter único '0'. Cualquier error de sintaxis en la cadena (por ejemplo, un dólar no seguido por otro carácter) hace que la llamada sea ignorada. No se añade ningún terminador a la cadena de salida, por lo que si desea una nueva línea, debe incluirla explícitamente usando el escape $n. Por ejemplo:


pcre2grep '(.)(..(.))(?C"|[$1] [$2] [$3]$n")' <some file>

La correspondencia continúa normalmente después de que la cadena sea mostrada. Si desea ver solo la salida de la llamada pero no la salida de una correspondencia real, debe terminar el patrón con (*FAIL).

Llamando a programas o scripts externos

Esta instalación puede ser deshabilitada de forma independiente al compilar pcre2grep. Está soportada para Windows, donde se utiliza una llamada a _spawnvp(), para VMS, donde se utiliza lib$spawn(), y para cualquier entorno similar a Unix donde fork() y execv() estén disponibles.

Si la cadena de llamada no comienza con un carácter de barra vertical (|), se analiza en una lista de subcadenas separadas por caracteres de barra vertical. La primera subcadena debe ser un nombre ejecutable, y las subcadenas siguientes especifican los argumentos:


nombre_ejecutable|arg1|arg2|...

Cualquier subcadena (incluido el nombre ejecutable) puede contener secuencias de escape que comiencen con un carácter de dólar. Estas son las mismas que para la opción --output (-O) documentada anteriormente, excepto que $0 o $& no pueden insertar la cadena correspondiente porque la correspondencia aún está en progreso. En su lugar, se inserta el carácter '0'. Si necesita un carácter de dólar o barra vertical literal en alguna subcadena, use $$ o $| respectivamente. Aquí hay un ejemplo:


echo -e "abcde\n12345" | pcre2grep \
'(?x)(.)(..(.))
(?C"/bin/echo|Arg1: [$1] [$2] [$3]|Arg2: $|${1}$| ($4)")()' -


Salida:


Arg1: [a] [bcd] [d] Arg2: |a| ()
abcde
Arg1: [1] [234] [4] Arg2: |1| ()
12345

Los parámetros para la llamada al sistema que se utiliza para ejecutar el programa o script son cadenas terminadas en cero. Esto significa que los caracteres cero binarios en el argumento de llamada causarán la terminación prematura de sus subcadenas y, por lo tanto, no deben estar presentes. Cualquier error de sintaxis en la cadena (por ejemplo, un dólar no seguido por otro carácter) hace que la llamada sea ignorada. Si la ejecución del programa falla por cualquier motivo (incluida la inexistencia del ejecutable), ocurre una falla de correspondencia local y el casador retrocede de la manera normal.

ERRORES DE CORRESPONDENCIA

Es posible proporcionar una expresión regular que tarde mucho tiempo en no coincidir con ciertas líneas. Tales patrones normalmente involucran repeticiones indefinidas anidadas, por ejemplo: (a+)*\d al coincidir con una línea de a's sin un dígito final. La función de correspondencia de PCRE2 tiene un límite de recursos que hace que aborten en estas circunstancias. Si esto sucede, pcre2grep muestra un mensaje de error y la línea que causó el problema en el flujo de error estándar. Si hay más de 20 errores de este tipo, pcre2grep se rinde.

La opción --match-limit de pcre2grep se puede usar para establecer el límite de recursos general. También hay otros límites que afectan la cantidad de memoria utilizada durante la correspondencia; ver la discusión de --heap-limit y --depth-limit arriba.

DIAGNÓSTICOS

El código de salida es 0 si se encontraron coincidencias, 1 si no se encontraron coincidencias, y 2 para errores de sintaxis, líneas demasiado largas, archivos inexistentes o inaccesibles (incluso si se encontraron coincidencias en otros archivos) o demasiados errores de coincidencia. Usar la opción -s para suprimir mensajes de error sobre archivos inaccesibles no afecta el código de retorno.

Cuando se ejecuta en VMS, el código de retorno se coloca en el símbolo PCRE2GREP_RC porque VMS no distingue entre exit(0) y exit(1).
