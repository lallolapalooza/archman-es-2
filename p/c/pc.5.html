PC(5) Manual de formatos de archivo PC(5)

NOMBRE

file.pc — formato de archivo pkg-config

DESCRIPCIÓN

.pc Los archivos proporcionan un mecanismo útil para almacenar diversa información sobre bibliotecas y paquetes en un sistema determinado. La información almacenada por .pc los archivos incluyen indicadores del compilador y enlazador necesarios para usar una biblioteca determinada, así como cualquier otro metadato relevante.

Estos .pc Los archivos son procesados por una utilidad llamada pkg-config, de la cual pkgconf es una implementación.

SINTAXIS DEL ARCHIVO

El .pc El archivo sigue un formato inspirado en RFC822. Los comentarios se prefijan con un signo de almohadilla, signo de hash u octal (#), y la asignación de variables es similar al shell POSIX. Las propiedades se definen utilizando estrofas al estilo RFC822.

VARIABLES

Las definiciones de variables comienzan con una cadena alfanumérica, seguida de un signo igual y luego el valor que la variable debe contener.

Las referencias a variables siempre se escriben como "${variable}". Es posible escapar un literal "${" como "$${".

PROPIEDADES

Las propiedades se establecen utilizando estrofas al estilo RFC822, que consisten en una palabra clave, seguida de dos puntos (:) y luego el valor al que se debe establecer la propiedad. La sustitución de variables se realiza siempre independientemente del tipo de propiedad.

Hay tres tipos de propiedad:

Literal
La propiedad se establecerá en el texto del valor.
Lista de dependencias
La propiedad se establecerá en una lista de dependencias analizadas del texto. Las listas de dependencias se definen con esta sintaxis ABNF: 
package-list = *WSP *( package-spec *( package-sep ) )
package-sep  = WSP / ","
package-spec = package-key [ ver-op package-version ]
ver-op       = "<" / "<=" / "=" / "!=" / ">=" / ">"
Lista de fragmentos
La propiedad se establecerá en una lista de fragmentos analizados del texto. El el texto de entrada debe estar en un formato adecuado para pasarlo a un shell POSIX sin expansiones de shell después de que se haya realizado la sustitución de variables.

PALABRAS CLAVE DE PROPIEDAD

Name
El nombre mostrado del paquete. (obligatorio; literal)
Version
La versión del paquete. (obligatorio; literal)
Description
Una descripción del paquete. (obligatorio; literal)
URL
Una URL a una página web para el paquete. Se utiliza para recomendar dónde se pueden adquirir versiones más nuevas del paquete. (obligatorio; literal)
Cflags
Indicadores del compilador requeridos. Estos indicadores siempre se utilizan, independientemente de si se solicita la compilación estática. (opcional; lista de fragmentos)
Cflags.private
Indicadores del compilador requeridos para la compilación estática. (opcional; lista de fragmentos; extensión de pkgconf)
Copyright
Una declaración de atestación de derechos de autor. (opcional; literal; extensión de pkgconf)
Libs
Indicadores de enlace requeridos para este paquete. Bibliotecas de las que depende este paquete para enlazar contra él, que no se describen como dependencias deben especificarse aquí. (opcional; lista de fragmentos)
Libs.private
Indicadores de enlace requeridos para este paquete que solo son necesarios al enlazar estáticamente. Las bibliotecas de las que depende este paquete para enlazar contra él estáticamente, que no se describen como dependencias deben especificarse aquí. (opcional; lista de fragmentos)
License
La etiqueta de licencia SPDX declarada que se debe aplicar al paquete dado. (opcional; literal; extensión de pkgconf)
Maintainer
El contacto preferido para el mantenedor. Esto debe tener el formato de un nombre seguido de una dirección de correo electrónico o sitio web. (opcional; literal; extensión de pkgconf)
Requires
Dependencias requeridas que deben cumplirse para que el paquete sea utilizable. Todas las dependencias deben cumplirse o la implementación de pkg-config no debe usar el paquete. (opcional; lista de dependencias)
Requires.private
Dependencias requeridas que deben cumplirse para que el paquete sea utilizable para inclusión de encabezados y enlace estático. Todas las dependencias deben cumplirse o la implementación de pkg-config no debe usar el paquete para la inclusión de encabezados y el enlace estático. (opcional; lista de dependencias)
Conflicts
Dependencias que no deben cumplirse para que el paquete sea utilizable. Si alguna el paquete en la solución de dependencia propuesta coincide con alguna dependencia en la Lista de conflictos, el paquete que se está considerando no es utilizable. (opcional; lista de dependencias)
Provides
Dependencias que pueden ser proporcionadas por un paquete alternativo. Si un paquete no se puede encontrar, toda la colección de paquetes se escanea en busca de proveedores que puedan coincidir con la dependencia solicitada. (opcional; lista de dependencias; extensión de pkgconf)

EXTENCIONES

Las características que se han marcado como una extensión de pkgconf solo están garantizadas para funcionar con la implementación de pkgconf de pkg-config. Otras implementaciones pueden o no admitir las extensiones.

En consecuencia, se sugiere que .pc los archivos que dependen absolutamente de estas extensiones declaren un requisito sobre el virtual pkgconf.

EJEMPLOS

Un archivo .pc de ejemplo:

# Este es un comentario
prefix=/home/kaniini/pkg   # esto define una variable
exec_prefix=${prefix}      # definiendo otra variable con una sustitución
libdir=${exec_prefix}/lib
includedir=${prefix}/include

Name: libfoo                                  # nombre legible por humanos
Description: una biblioteca de ejemplo llamada libfoo # descripción legible por humanos
Copyright: Copyright (c) 2022 autores del proyecto pkgconf
License: Apache-2.0
Maintainer: el proyecto pkgconf <http://www.pkgconf.org>
Version: 1.0
URL: http://www.pkgconf.org
Requires: libbar > 2.0.0
Conflicts: libbaz <= 3.0.0
Libs: -L${libdir} -lfoo
Libs.private: -lm
Cflags: -I${includedir}/libfoo
