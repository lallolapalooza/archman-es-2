PCREGREP(1) Manual de Comandos Generales PCREGREP(1)

NOMBRE

pcregrep - un grep con expresiones regulares compatibles con Perl.

SINOPSIS

pcregrep [opciones] [opciones largas] [patrón] [ruta1 ruta2 ...]

DESCRIPCIÓN

pcregrep busca patrones de caracteres en archivos, de la misma manera que lo hacen otros comandos grep, pero utiliza la biblioteca de expresiones regulares PCRE para admitir patrones compatibles con las expresiones regulares de Perl 5. Consulte pcresyntax(3) para un resumen rápido de la sintaxis de patrones, o pcrepattern(3) para una descripción completa de la sintaxis y semántica de las expresiones regulares que admite PCRE.

Los patrones, ya sean proporcionados en la línea de comandos o en un archivo separado, se dan sin delimitadores. Por ejemplo:


pcregrep Thursday /etc/motd

Si intenta utilizar delimitadores (por ejemplo, rodeando un patrón con barras diagonales, como es común en los scripts de Perl), estos se interpretan como parte del patrón. Las comillas pueden utilizarse, por supuesto, para delimitar patrones en la línea de comandos ya que son interpretadas por el shell, y de hecho se requieren comillas si un patrón contiene espacios en blanco o metacaracteres del shell.

El primer argumento que sigue a cualquier configuración de opción se trata como el único patrón a hacer coincidir cuando ni -e ni -f están presentes. Por el contrario, cuando una o ambas de estas opciones se usan para especificar patrones, todos los argumentos se tratan como nombres de ruta. Se debe proporcionar al menos una de las opciones -e, -f, o un patrón de argumento.

Si no se especifican archivos, pcregrep lee la entrada estándar. La entrada estándar también puede ser referenciada por un nombre que consiste en un solo guion. Por ejemplo:


pcregrep some-pattern /file1 - /file3

Por defecto, cada línea que coincide con un patrón se copia a la salida estándar y, si hay más de un archivo, el nombre del archivo se imprime al principio de cada línea, seguido de dos puntos. Sin embargo, hay opciones que pueden cambiar el comportamiento de pcregrep. En particular, la opción -M permite buscar patrones que abarcan los límites de las líneas. Lo que define un límite de línea se controla mediante la opción -N (--newline).

La cantidad de memoria utilizada para almacenar en búfer los archivos que se están escaneando se controla mediante un parámetro que se puede establecer con la opción --buffer-size. El valor predeterminado para este parámetro se especifica cuando se compila pcregrep, siendo el predeterminado general 20K. Se utiliza un bloque de memoria de tres veces este tamaño (para permitir el almacenamiento en búfer de líneas "anteriores" y "posteriores"). Ocurre un error si una línea desborda el búfer.

Los patrones no pueden tener más de 8K o BUFSIZ bytes, lo que sea mayor. BUFSIZ se define en <stdio.h>. Cuando hay más de un patrón (especificado mediante el uso de -e y/o -f), cada patrón se aplica a cada línea en el orden en que se definen, excepto que todos los patrones -e se intentan antes que los patrones -f.

Por defecto, tan pronto como un patrón coincide con una línea, no se consideran más patrones. Sin embargo, si se utiliza --colour (o --color) para colorear las subcadenas coincidentes, o si se utilizan --only-matching, --file-offsets, o --line-offsets para mostrar solo la parte de la línea que coincidió (ya sea literalmente o como un desplazamiento), el escaneo se reanuda inmediatamente después de la coincidencia, para que se puedan encontrar coincidencias adicionales en la misma línea. Si hay varios patrones, todos se intentan en el resto de la línea, pero los patrones que siguen al que coincidió no se intentan en la parte anterior de la línea.

Este comportamiento significa que el orden en que se especifican múltiples patrones puede afectar la salida cuando se utiliza una de las opciones anteriores. Esto ya no es lo mismo que el comportamiento de GNU grep, que ahora logra mostrar coincidencias anteriores para patrones posteriores (siempre que no haya superposición).

Se aceptan patrones que pueden coincidir con una cadena vacía, pero las coincidencias de cadenas vacías nunca se reconocen. Un ejemplo es el patrón "(super)?(man)?", en el que todos los componentes son opcionales. Este patrón encuentra todas las ocurrencias de "super" y "man"; la salida difiere de la coincidencia con "super|man" cuando solo se muestran las subcadenas coincidentes.

Si la variable de entorno LC_ALL o LC_CTYPE está establecida, pcregrep utiliza el valor para establecer una configuración regional al llamar a la biblioteca PCRE. La opción --locale se puede utilizar para anular esto.

SOPORTE PARA ARCHIVOS COMPRIMIDOS

Es posible compilar pcregrep para que utilice libz o libbz2 para leer archivos cuyos nombres terminan en .gz o .bz2, respectivamente. Puede averiguar si su binario tiene soporte para uno o ambos de estos tipos de archivo ejecutándolo con la opción --help. Si no está presente el soporte adecuado, los archivos se tratan como texto plano. La entrada estándar siempre se trata de esta manera.

ARCHIVOS BINARIOS

Por defecto, un archivo que contiene un byte cero binario dentro de los primeros 1024 bytes se identifica como un archivo binario y se procesa especialmente. (GNU grep también identifica archivos binarios de esta manera). Consulte la opción --binary-files para conocer una forma de cambiar la forma en que se manejan los archivos binarios.

OPCIONES

El orden en que aparecen algunas de las opciones puede afectar la salida. Por ejemplo, tanto las opciones -h como -l afectan la impresión de los nombres de archivo. Cualquiera que aparezca más tarde en la línea de comandos será la que tenga efecto. De manera similar, excepto donde se indica a continuación, si una opción se da dos veces, se utiliza la configuración posterior. Los valores numéricos para las opciones pueden ir seguidos de K o M, para significar multiplicación por 1024 o 1024*1024 respectivamente.

--
Esto termina la lista de opciones. Es útil si el siguiente elemento en la línea de comandos comienza con un guion pero no es una opción. Esto permite el procesamiento de patrones y nombres de archivo que comienzan con guiones.
-A número, --after-context=número
Imprime número líneas de contexto después de cada línea coincidente. Si se están imprimiendo nombres de archivo y/o números de línea, se utiliza un separador de guion en lugar de dos puntos para las líneas de contexto. Se imprime una línea que contiene "--" entre cada grupo de líneas, a menos que sean de hecho contiguas en el archivo de entrada. Se espera que el valor de número sea relativamente pequeño. Sin embargo, pcregrep garantiza tener hasta 8K de texto siguiente disponible para la salida de contexto.
-a, --text
Tratar los archivos binarios como texto. Esto es equivalente a --binary-files=text.
-B número, --before-context=número
Imprime número líneas de contexto antes de cada línea coincidente. Si se están imprimiendo nombres de archivo y/o números de línea, se utiliza un separador de guion en lugar de dos puntos para las líneas de contexto. Se imprime una línea que contiene "--" entre cada grupo de líneas, a menos que sean de hecho contiguas en el archivo de entrada. Se espera que el valor de número sea relativamente pequeño. Sin embargo, pcregrep garantiza tener hasta 8K de texto anterior disponible para la salida de contexto.
--binary-files=palabra
Especifica cómo se deben procesar los archivos binarios. Si la palabra es "binary" (el valor predeterminado), se realiza la coincidencia de patrones en archivos binarios, pero la única salida es "Archivo binario <nombre> coincide" cuando una coincidencia tiene éxito. Si la palabra es "text", que es equivalente a la opción -a o --text, los archivos binarios se procesan de la misma manera que cualquier otro archivo. En este caso, cuando una coincidencia tiene éxito, la salida puede ser basura binaria, lo que puede tener efectos desagradables si se envía a un terminal. Si la palabra es "without-match", que es equivalente a la opción -I, los archivos binarios no se procesan en absoluto; se asume que no son de interés.
--buffer-size=número
Establece el parámetro que controla cuánta memoria se utiliza para almacenar en búfer los archivos que se están escaneando.

-A number, --after-context=number
Print number lines of context after each matching line. Printing of context lines is done independently for each file. If -C is specified, it overrides the value that was set for -A. If you want to set context lines for just one file, you should use -C. If you want to set context lines for more than one file, you should use -C multiple times.
-B number, --before-context=number
Print number lines of context before each matching line. Printing of context lines is done independently for each file. If -C is specified, it overrides the value that was set for -B. If you want to set context lines for just one file, you should use -C. If you want to set context lines for more than one file, you should use -C multiple times.
-C number, --context=number
Print number lines of context both before and after each matching line. This is equivalent to setting both -A and -B to the same value.
-c, --count
Do not output individual lines from the files that are being scanned; instead output the number of lines that would otherwise have been shown. If no lines are selected, the number zero is output. If several files are are being scanned, a count is output for each of them. However, if the --files-with-matches option is also used, only those files whose counts are greater than zero are listed. When -c is used, the -A, -B, and -C options are ignored.
--colour, --color
If this option is given without any data, it is equivalent to "--colour=auto". If data is required, it must be given in the same shell item, separated by an equals sign.
--colour=valor, --color=valor
This option specifies under what circumstances the parts of a line that matched a pattern should be coloured in the output. By default, the output is not coloured. The value (which is optional, see above) may be "never", "always", or "auto". In the latter case, colouring happens only if the standard output is connected to a terminal. More resources are used when colouring is enabled, because pcregrep has to search for all possible matches in a line, not just one, in order to colour them all.

The colour that is used can be specified by setting the environment variable PCREGREP_COLOUR or PCREGREP_COLOR. The value of this variable should be a string of two numbers, separated by a semicolon. They are copied directly into the control string for setting colour on a terminal, so it is your responsibility to ensure that they make sense. If neither of the environment variables is set, the default is "1;31", which gives red.

-D acción, --devices=acción
If an input path is not a regular file or a directory, "acción" specifies how it is to be processed. Valid values are "read" (the default) or "skip" (silently skip the path).
-d acción, --directories=acción
If an input path is a directory, "acción" specifies how it is to be processed. Valid values are "read" (the default in non-Windows environments, for compatibility with GNU grep), "recurse" (equivalent to the -r option), or "skip" (silently skip the path, the default in Windows environments). In the "read" case, directories are read as if they were ordinary files. In some operating systems the effect of reading a directory like this is an immediate end-of-file; in others it may provoke an error.
-e patrón, --regex=patrón, --regexp=patrón
Specify a pattern to be matched. This option can be used multiple times in order to specify several patterns. It can also be used as a way of specifying a single pattern that starts with a hyphen. When -e is used, no argument pattern is taken from the command line; all arguments are treated as file names. There is no limit to the number of patterns. They are applied to each line in the order in which they are defined until one matches.

If -f is used with -e, the command line patterns are matched first, followed by the patterns from the file(s), independent of the order in which these options are specified. Note that multiple use of -e is not the same as a single pattern with alternatives. For example, X|Y finds the first character in a line that is X or Y, whereas if the two patterns are given separately, with X first, pcregrep finds X if it is present, even if it follows Y in the line. It finds Y only if there is no X in the line. This matters only if you are using -o or --colo(u)r to show the part(s) of the line that matched.

--exclude=patrón
Files (but not directories) whose names match the pattern are skipped without being processed. This applies to all files, whether listed on the command line, obtained from --file-list, or by scanning a directory. The pattern is a PCRE regular expression, and is matched against the final component of the file name, not the entire path. The -F, -w, and -x options do not apply to this pattern. The option may be given any number of times in order to specify multiple patterns. If a file name matches both an --include and an --exclude pattern, it is excluded. There is no short form for this option.
--exclude-from=nombrearchivo
Treat each non-empty line of the file as the data for an --exclude option. What constitutes a newline when reading the file is the operating system's default. The --newline option has no effect on this option. This option may be given more than once in order to specify a number of files to read.
--exclude-dir=patrón
Directories whose names match the pattern are skipped without being processed, whatever the setting of the --recursive option. This applies to all directories, whether listed on the command line, obtained from --file-list, or by scanning a parent directory. The pattern is a PCRE regular expression, and is matched against the final component of the directory name, not the entire path. The -F, -w, and -x options do not apply to this pattern. The option may be given any number of times in order to specify more than one pattern. If a directory matches both --include-dir and --exclude-dir, it is excluded. There is no short form for this option.
-F, --fixed-strings
Interpret each data-matching pattern as a list of fixed strings, separated by newlines, instead of as a regular expression. What constitutes a newline for this purpose is controlled by the --newline option. The -w (match as a word) and -x (match whole line) options can be used with -F. They apply to each of the fixed strings. A line is selected if any of the fixed strings are found in it (subject to -w or -x, if present). This option applies only to the patterns that are matched against the contents of files; it does not apply to patterns specified by any of the --include or --exclude options.
-f nombrearchivo, --file=nombrearchivo
Read patterns from the file, one per line, and match them against each line of input. What constitutes a newline when reading the file is the operating system's default. The --newline option has no effect on this option. Trailing white space is removed from each line, and blank lines are ignored. An empty file contains no patterns and therefore matches nothing. See also the comments about multiple patterns versus a single pattern with alternatives in the description of -e above.

If this option is given more than once, all the specified files are read. A data line is output if any of the patterns match it. A filename can be given as "-" to refer to the standard input. When -f is used, patterns specified on the command line using -e may also be present; they are tested before the file's patterns. However, no other pattern is taken from the command line; all arguments are treated as the names of paths to be searched.

--file-list=nombrearchivo
Read a list of files and/or directories that are to be scanned from the given file, one per line. Trailing white space is removed from each line, and blank lines are ignored. These paths are processed before any that are listed on the command line. The filename can be given as "-" to refer to the standard input. If --file and --file-list are both specified as "-", patterns are read first. This is useful only when the standard input is a terminal, from which further lines (the list of files) can be read after an end-of-file indication. If this option is given more than once, all the specified files are read.
--file-offsets
Instead of showing lines or parts of lines that match, show each match as an offset from the start of the file and a length, separated by a comma. In this mode, no context is shown. That is, the -A, -B, and -C options are ignored. If there is more than one match in a line, each of them is shown separately. This option is mutually exclusive with --line-offsets and --only-matching.
-H, --with-filename
Force the inclusion of the filename at the start of output lines when searching a single file. By default, the filename is not shown in this case. For matching lines, the filename is followed by a colon; for context lines, a hyphen separator is used. If a line number is also being output, it follows the file name.
-h, --no-filename
Suppress the output filenames when searching multiple files. By default, filenames are shown when multiple files are searched. For matching lines, the filename is followed by a colon; for context lines, a hyphen separator is used. If a line number is also being output, it follows the file name.
--help
Output a help message, giving brief details of the command options and file type support, and then exit. Anything else on the command line is ignored.
-I
Treat binary files as never matching. This is equivalent to --binary-files=without-match.
-i, --ignore-case
Ignore upper/lower case distinctions during comparisons.
--include=patrón
If any --include patterns are specified, the only files that are processed are those that match one of the patterns (and do not match an --exclude pattern). This option does not affect directories, but it applies to all files, whether listed on the command line
, obtenido de --file-list, o escaneando un directorio. El patrón es una expresión regular PCRE y se compara con el componente final del nombre del archivo, no con la ruta completa. Las opciones -F, -w y -x no se aplican a este patrón. La opción puede especificarse cualquier número de veces. Si un nombre de archivo coincide tanto con un patrón --include como con uno --exclude, se excluye. No hay forma corta para esta opción.
--include-from=nombrearchivo
Trata cada línea no vacía del archivo como datos para una opción --include. Lo que constituye una nueva línea para este propósito es el valor predeterminado del sistema operativo. La opción --newline no tiene efecto sobre esta opción. Esta opción puede especificarse cualquier número de veces; se leen todos los archivos.
--include-dir=patrón
Si se especifican patrones --include-dir, los únicos directorios que se procesan son aquellos que coinciden con uno de los patrones (y no coinciden con un patrón --exclude-dir). Esto se aplica a todos los directorios, ya sea que se listen en la línea de comandos, se obtengan de --file-list, o escaneando un directorio padre. El patrón es una expresión regular PCRE y se compara con el componente final del nombre del directorio, no con la ruta completa. Las opciones -F, -w y -x no se aplican a este patrón. La opción puede especificarse cualquier número de veces. Si un directorio coincide tanto con --include-dir como con --exclude-dir, se excluye. No hay forma corta para esta opción.
-L, --files-without-match
En lugar de mostrar las líneas de los archivos, solo muestra los nombres de los archivos que no contienen ninguna línea que se habría mostrado. Cada nombre de archivo se muestra una vez, en una línea separada.
-l, --files-with-matches
En lugar de mostrar las líneas de los archivos, solo muestra los nombres de los archivos que contienen líneas que se habrían mostrado. Cada nombre de archivo se muestra una vez, en una línea separada. Normalmente la búsqueda se detiene tan pronto como se encuentra una línea coincidente en un archivo. Sin embargo, si la opción -c (contar) también se usa, la búsqueda continúa para obtener el recuento correcto, y se listan aquellos archivos que tienen al menos una coincidencia junto con sus recuentos. Usar esta opción con -c es una forma de suprimir la lista de archivos sin coincidencias.
--label=nombre
Esta opción proporciona un nombre que se utilizará para la entrada estándar cuando se muestren nombres de archivos. Si no se proporciona, se usa "(entrada estándar)". No hay forma corta para esta opción.
--line-buffered
Cuando se especifica esta opción, la entrada se lee y procesa línea por línea, y la salida se vacía después de cada escritura. Por defecto, la entrada se lee en grandes fragmentos, a menos que pcregrep pueda determinar que está leyendo desde una terminal (lo cual actualmente solo es posible en entornos tipo Unix). La salida a la terminal normalmente se vacía automáticamente por el sistema operativo. Esta opción puede ser útil cuando la entrada o salida está conectada a una tubería y no desea que pcregrep almacene en búfer grandes cantidades de datos. Sin embargo, su uso afectará el rendimiento y la opción -M (multilínea) dejará de funcionar.
--line-offsets
En lugar de mostrar líneas o partes de líneas que coinciden, muestra cada coincidencia como un número de línea, el desplazamiento desde el inicio de la línea y una longitud. El número de línea se termina con dos puntos (como de costumbre; ver la opción -n), y el desplazamiento y la longitud están separados por una coma. En este modo, no se muestra ningún contexto. Es decir, las opciones -A, -B y -C se ignoran. Si hay más de una coincidencia en una línea, cada una se muestra por separado. Esta opción es mutuamente excluyente con --file-offsets y --only-matching.
--locale=nombrelocal
Esta opción especifica una configuración regional (locale) que se utilizará para la coincidencia de patrones. Anula el valor de las variables de entorno LC_ALL o LC_CTYPE. Si no se especifica ninguna configuración regional, se utiliza la predeterminada de la biblioteca PCRE (generalmente la configuración regional "C"). No hay forma corta para esta opción.
--match-limit=número
El procesamiento de algunos patrones de expresiones regulares puede requerir una gran cantidad de memoria, lo que en algunos casos lleva a que el programa falle si no hay suficiente disponible. Otros patrones pueden tardar mucho tiempo en buscar todas las cadenas coincidentes posibles. La función pcre_exec() que es llamada por pcregrep para hacer la coincidencia tiene dos parámetros que pueden limitar los recursos que utiliza.

La opción --match-limit proporciona un medio para limitar el uso de recursos al procesar patrones que no van a coincidir, pero que tienen un gran número de posibilidades en sus árboles de búsqueda. El ejemplo clásico es un patrón que usa repeticiones internas ilimitadas. Internamente, PCRE utiliza una función llamada match() que llama repetidamente (a veces recursivamente). El límite establecido por --match-limit se impone al número de veces que se llama a esta función durante una coincidencia, lo que tiene el efecto de limitar la cantidad de retroceso (backtracking) que puede tener lugar.

La opción --recursion-limit es similar a --match-limit, pero en lugar de limitar el número total de veces que se llama a match(), limita la profundidad de las llamadas recursivas, lo que a su vez limita la cantidad de memoria que se puede utilizar. La profundidad de recursión es un número menor que el número total de llamadas, ya que no todas las llamadas a match() son recursivas. Este límite solo es útil si se establece en un valor menor que --match-limit.

No hay formas cortas para estas opciones. Los valores predeterminados se especifican cuando se compila la biblioteca PCRE, siendo el valor predeterminado predeterminado 10 millones.

-M, --multiline
Permite que los patrones coincidan con más de una línea. Cuando se especifica esta opción, los patrones pueden contener caracteres de nueva línea literales y ocurrencias internas de los caracteres ^ y $. La salida de una coincidencia exitosa puede consistir en más de una línea, la última de las cuales es aquella en la que terminó la coincidencia. Si la cadena coincidente termina con una secuencia de nueva línea, la salida termina al final de esa línea.

Cuando se establece esta opción, la biblioteca PCRE se llama en modo "multilínea". Existe un límite en el número de líneas que se pueden emparejar, impuesto por la forma en que pcregrep almacena en búfer el archivo de entrada mientras lo escanea. Sin embargo, pcregrep asegura que al menos 8K caracteres o el resto del documento (lo que sea menor) estén disponibles para la coincidencia hacia adelante, y de manera similar, los 8K caracteres anteriores (o todos los caracteres anteriores, si son menos de 8K) están garantizados para estar disponibles para las aserciones de retroceso (lookbehind). Esta opción no funciona cuando la entrada se lee línea por línea (ver --line-buffered).

-N tiponuevalinea, --newline=tiponuevalinea
La biblioteca PCRE admite cinco convenciones diferentes para indicar los finales de línea. Son las secuencias de un solo carácter CR (retorno de carro) y LF (avance de línea), la secuencia de dos caracteres CRLF, una convención "anycrlf" que reconoce cualquiera de los tres tipos anteriores y una convención "any", en la que se asume que cualquier secuencia de fin de línea Unicode termina una línea. Las secuencias Unicode son las tres mencionadas anteriormente, más VT (tabulador vertical, U+000B), FF (salto de página, U+000C), NEL (nueva línea, U+0085), LS (separador de línea, U+2028) y PS (separador de párrafo, U+2029).

Cuando se compila la biblioteca PCRE, se especifica una secuencia de fin de línea predeterminada. Normalmente es la secuencia estándar del sistema operativo. A menos que se especifique lo contrario con esta opción, pcregrep utiliza la predeterminada de la biblioteca. Los valores posibles para esta opción son CR, LF, CRLF, ANYCRLF o ANY. Esto hace posible utilizar pcregrep para escanear archivos que provienen de otros entornos sin tener que modificar sus finales de línea. Si los datos que se escanean no coinciden con la convención establecida por esta opción, pcregrep puede comportarse de manera extraña. Tenga en cuenta que esta opción no se aplica a los archivos especificados por las opciones -f, --exclude-from o --include-from, que se espera que utilicen la secuencia de nueva línea estándar del sistema operativo.

-n, --line-number
Anteponer a cada línea de salida su número de línea en el archivo, seguido de dos puntos para las líneas coincidentes o un guion para las líneas de contexto. Si el nombre del archivo también se está mostrando, precede al número de línea. Esta opción se fuerza si se utiliza --line-offsets.
--no-jit
Si la biblioteca PCRE se compila con soporte para compilación just-in-time (que acelera la coincidencia), pcregrep la utiliza automáticamente, a menos que se haya deshabilitado explícitamente en el momento de la compilación. Esta opción se puede utilizar para deshabilitar el uso de JIT en tiempo de ejecución. Se proporciona para pruebas y para solucionar problemas. Nunca debería ser necesaria en un uso normal.
-o, --only-matching
Muestra solo la parte de la línea que coincidió con un patrón en lugar de la línea completa. En este modo, no se muestra ningún contexto. Es decir, las opciones -A, -B y -C se ignoran. Si hay más de una coincidencia en una línea, cada una se muestra por separado. Si -o se combina con -v (invierte el sentido de la coincidencia para encontrar líneas no coincidentes), no se genera ninguna salida, pero el código de retorno se establece adecuadamente. Si la porción coincidente de la línea está vacía, no se muestra nada a menos que el nombre del archivo o el número de línea se estén imprimiendo, en cuyo caso se muestran en una línea vacía. Esta opción es mutuamente excluyente con --file-offsets y --line-offsets.
-onúmero, --only-matching=número
Muestra solo la parte de la línea que coincidió con los paréntesis de captura del número dado. Se admiten hasta 32 paréntesis de captura, y -o0 es equivalente a -o sin número. Dado que estas opciones se pueden especificar sin argumento (ver arriba), si hay un argumento presente, debe estar en el mismo elemento de shell, por ejemplo, -o3 o --only-matching=2. Los comentarios para el caso sin argumento anterior también se aplican a este caso. Si la captura especificada p
parentesis no existen en el patrón, o no se establecieron en la coincidencia, no se genera nada a menos que el nombre del archivo o el número de línea se estén imprimiendo.

Si esta opción se proporciona varias veces, se generan varias subcadenas, en el orden en que se proporcionan las opciones. Por ejemplo, -o3 -o1 -o3 hace que se generen las subcadenas coincidentes por los paréntesis de captura 3 y 1 y luego 3 de nuevo. Por defecto, no hay separador (pero vea la siguiente opción).

--om-separator=texto
Especifica una cadena separadora para múltiples ocurrencias de -o. El valor predeterminado es una cadena vacía. Las cadenas separadoras nunca se colorean.
-q, --quiet
Trabaja en silencio, es decir, no muestra nada excepto mensajes de error. El estado de salida indica si se encontraron coincidencias o no.
-r, --recursive
Si alguna ruta dada es un directorio, escanea recursivamente los archivos que contiene, teniendo en cuenta la configuración de --include y --exclude. Por defecto, un directorio se lee como un archivo normal; en algunos sistemas operativos esto produce un fin de archivo inmediato. Esta opción es un atajo para establecer la opción -d en "recurse".
--recursion-limit=número
Ver --match-limit arriba.
-s, --no-messages
Suprime los mensajes de error sobre archivos inexistentes o ilegibles. Dichos archivos se omiten silenciosamente. Sin embargo, el código de retorno sigue siendo 2, incluso si se encontraron coincidencias en otros archivos.
-u, --utf-8
Opera en modo UTF-8. Esta opción solo está disponible si PCRE ha sido compilado con soporte UTF-8. Todos los patrones (incluidos los de las opciones --exclude y --include) y todas las líneas de asunto que se escanean deben ser cadenas válidas de caracteres UTF-8.
-V, --version
Escribe los números de versión de pcregrep y la biblioteca PCRE a la salida estándar y luego sale. Cualquier otra cosa en la línea de comandos se ignora.
-v, --invert-match
Invierte el sentido de la coincidencia, de modo que las líneas que *no* coinciden con ninguno de los patrones son las que se encuentran.
-w, --word-regex, --word-regexp
Fuerza que los patrones coincidan solo con palabras completas. Esto es equivalente a tener \b al principio y al final del patrón. Esta opción se aplica solo a los patrones que coinciden con el contenido de los archivos; no se aplica a los patrones especificados por ninguna de las opciones --include o --exclude.
-x, --line-regex, --line-regexp
Fuerza que los patrones estén anclados (cada uno debe comenzar a coincidir al principio de una línea) y, además, requiere que coincidan líneas completas. Esto es equivalente a tener caracteres ^ y $ al principio y al final de cada rama alternativa en cada patrón. Esta opción se aplica solo a los patrones que coinciden con el contenido de los archivos; no se aplica a los patrones especificados por ninguna de las opciones --include o --exclude.

VARIABLES DE ENTORNO

Se examinan las variables de entorno LC_ALL y LC_CTYPE, en ese orden, para obtener una configuración regional. Se utiliza la primera que esté establecida. Esto se puede anular con la opción --locale. Si no se establece ninguna configuración regional, se utiliza la predeterminada de la biblioteca PCRE (normalmente la configuración regional "C").

NUEVAS LÍNEAS

La opción -N (--newline) permite a pcregrep escanear archivos con convenciones de nueva línea diferentes a las predeterminadas. Cualquier parte de los archivos de entrada que se escriba en la salida estándar se copia de forma idéntica, con las secuencias de nueva línea que tengan en la entrada. Sin embargo, la configuración de esta opción no afecta la interpretación de los archivos especificados por las opciones -f, --exclude-from o --include-from, que se asume que utilizan la secuencia de nueva línea estándar del sistema operativo, ni afecta la forma en que pcregrep escribe mensajes informativos en los flujos de error estándar y de salida. Para estos, utiliza la cadena "\n" para indicar nuevas líneas, confiando en la biblioteca C de E/S para convertirla a una secuencia apropiada.

COMPATIBILIDAD DE OPCIONES

Muchas de las formas cortas y largas de las opciones de pcregrep son las mismas que en el programa GNU grep. Cualquier opción larga de la forma --xxx-regexp (terminología GNU) también está disponible como --xxx-regex (terminología PCRE). Sin embargo, las opciones --file-list, --file-offsets, --include-dir, --line-offsets, --locale, --match-limit, -M, --multiline, -N, --newline, --om-separator, --recursion-limit, -u y --utf-8 son específicas de pcregrep, al igual que el uso de la opción --only-matching con un número de paréntesis de captura.

Aunque la mayoría de las opciones comunes funcionan de la misma manera, algunas son diferentes en pcregrep. Por ejemplo, el argumento de la opción --include es un glob para GNU grep, pero una expresión regular para pcregrep. Si se dan las opciones -c y -l, GNU grep solo lista nombres de archivo, sin recuentos, pero pcregrep da los recuentos.

OPCIONES CON DATOS

Hay cuatro formas diferentes en las que se puede especificar una opción con datos. Si se utiliza una opción de forma corta, los datos pueden seguir inmediatamente, o (con una excepción) en el siguiente elemento de la línea de comandos. Por ejemplo:


-f/ruta/al/archivo
-f /ruta/al/archivo

La excepción es la opción -o, que puede aparecer con o sin datos. Debido a esto, si hay datos, deben seguir inmediatamente en el mismo elemento, por ejemplo, -o3.

Si se utiliza una opción de forma larga, los datos pueden aparecer en el mismo elemento de la línea de comandos, separados por un signo igual, o (con dos excepciones) pueden aparecer en el siguiente elemento de la línea de comandos. Por ejemplo:


--file=/ruta/al/archivo
--file /ruta/al/archivo

Tenga en cuenta, sin embargo, que si desea proporcionar un nombre de archivo que comience con ~ como datos en un comando de shell, y que el shell expanda ~ a un directorio de inicio, debe separar el nombre del archivo de la opción, ya que el shell no trata ~ de manera especial a menos que esté al principio de un elemento.

Las excepciones a lo anterior son las opciones --colour (o --color) y --only-matching, para las cuales los datos son opcionales. Si una de estas opciones tiene datos, debe proporcionarse en la primera forma, utilizando un signo igual. De lo contrario, pcregrep asumirá que no tiene datos.

ERRORES DE COINCIDENCIA

Es posible proporcionar una expresión regular que tarde mucho tiempo en no coincidir con ciertas líneas. Dichos patrones normalmente implican repeticiones indefinidas anidadas, por ejemplo: (a+)*\d al coincidir con una línea de a's sin un dígito final. La función de coincidencia de PCRE tiene un límite de recursos que hace que se aborte en estas circunstancias. Si esto sucede, pcregrep genera un mensaje de error y la línea que causó el problema en el flujo de error estándar. Si hay más de 20 de tales errores, pcregrep se rinde.

La opción --match-limit de pcregrep se puede utilizar para establecer el límite de recursos general; hay una segunda opción llamada --recursion-limit que establece un límite en la cantidad de memoria (generalmente pila) que se utiliza (consulte la discusión de estas opciones arriba).

DIAGNÓSTICO

El estado de salida es 0 si se encontraron coincidencias, 1 si no se encontraron coincidencias, y 2 para errores de sintaxis, líneas demasiado largas, archivos inexistentes o inaccesibles (incluso si se encontraron coincidencias en otros archivos) o demasiados errores de coincidencia. El uso de la opción -s para suprimir mensajes de error sobre archivos inaccesibles no afecta el código de retorno.

    pcregrep(1)

    pcregrep - buscar patrones usando expresiones regulares PCRE

    NAME

    pcregrep - buscar patrones usando expresiones regulares PCRE

    SYNOPSIS

    pcregrep [OPTIONS] PATTERN [FILE...]

    DESCRIPTION

    pcregrep es una utilidad de línea de comandos similar a grep, que busca líneas que coincidan con un patrón de expresión regular PCRE en cada uno de los archivos de entrada. Si no se especifican archivos, se lee la entrada estándar.

    OPTIONS

    Se admiten la mayoría de las opciones de grep. Las opciones que afectan la forma en que se interpretan los patrones (por ejemplo, -i, -w, -x) son ignoradas si se utiliza la opción -P (solo PCRE). Las opciones que afectan a los archivos (por ejemplo, -I) son ignoradas.

    -A NUM, --after-context=NUM Imprimir NUM líneas de contexto después de las líneas coincidentes. NUM debe ser un entero no negativo.

    -a, --text Procesar un archivo binario como si fuera texto.

    --color[=WHEN], --colour[=WHEN] Resaltar el texto coincidente. WHEN es 'always', 'never' o 'auto'.

    -C NUM, --context=NUM Imprimir NUM líneas de contexto alrededor de las líneas coincidentes. NUM debe ser un entero no negativo.

    -c, --count Suprimir la salida normal; imprimir un resumen de cuántas líneas de entrada coincidieron con cada archivo de entrada.

    -D, --devices=ACTION Cómo manejar dispositivos especiales. ACTION es 'read' o 'skip'.

    -d, --directories=ACTION Cómo manejar los directorios. ACTION es 'read' o 'skip'.

    --exclude=GLOB Saltar archivos cuyos nombres base coincidan con GLOB.

    --exclude-from=FILE Saltar archivos cuyos nombres base coincidan con cualquier patrón en FILE.

    -e PATTERN, --regexp=PATTERN Especificar el patrón a buscar. Esto puede ser útil para especificar un patrón que comience con un guión. Puede usar esta opción varias veces para buscar varios patrones; si es así, se buscarán las líneas que coincidan con cualquiera de los patrones.

    -F, --fixed-strings Interpretar PATTERN como una lista de cadenas fijas, separadas por saltos de línea, en lugar de una expresión regular.

    -f FILE, --file=FILE Obtener los patrones de buscar desde FILE, uno por línea.

    -G, --basic-regexp Interpretar el patrón como una expresión regular básica de POSIX.

    -i, --ignore-case Ignorar diferencias entre mayúsculas y minúsculas.

    -H, --with-filename Imprimir el nombre del archivo para cada coincidencia.

    -h, --no-filename Suprimir el prefijo del nombre del archivo en la salida.

    --include=GLOB Procesar solo archivos cuyos nombres base coincidan con GLOB.

    --include-from=FILE Procesar solo archivos cuyos nombres base coincidan con cualquier patrón en FILE.

    -J, --show-jars Muestra las coincidencias dentro de archivos JAR.

    -L, --files-without-match Suprimir la salida normal; imprimir el nombre de cada archivo de entrada que no contenga ninguna coincidencia.

    -l, --files-with-match Suprimir la salida normal; imprimir el nombre de cada archivo de entrada que contenga una coincidencia.

    -m, --max-count=NUM Detener la búsqueda después de encontrar NUM coincidencias.

    -N, --line-number Prefijar cada línea de salida con su número de línea en el archivo de entrada.

    -o, --only-matching Muestra solo la parte de la línea que coincide con el patrón.

    -P, --pcre-regexp Interpretar el patrón como una expresión regular PCRE.

    --label=STRING El STRING se utiliza en lugar del nombre del archivo de entrada cuando se imprime la salida o cuando se lista un archivo que no se encuentra.

    --print0 Escribe un carácter nulo después de cada nombre de archivo de salida. Esto puede ser útil si los nombres de archivo contienen espacios o caracteres especiales.

    -Q, --quiet, --silent No escribir nada en la salida estándar. Un valor de salida de 0 indica que se encontró una coincidencia.

    -R, --recursive Leer todos los archivos bajo cada directorio, recursivamente.

    -r, --recursive Leer todos los archivos bajo cada directorio, recursivamente.

    --revert-matching Buscar líneas que NO coincidan con el patrón.

    -S, --separator=STRING Imprime STRING entre la salida de archivos contiguos.

    -U, --allow-invalid-utf8 Permite que las entradas contengan secuencias UTF-8 inválidas.

    -u, --}{- Las líneas de salida se separan por un carácter de salto de línea.

    -V, --version Mostrar información de versión y salir.

    -v, --invert-match Invierte el sentido de la coincidencia, seleccionando líneas que no coinciden con el patrón.

    -w, --word-regexp Seleccionar solo aquellas líneas de entrada que contienen coincidencias que forman palabras completas.

    -x, --line-regexp Seleccionar solo aquellas líneas de entrada que coinciden completamente con el patrón.

    -Z, --null Salida de nombres de archivo terminados en nulo.

    OPTIONS WITH DATA

    Las siguientes opciones se pueden usar para especificar datos que se pasarán a la expresión regular:

    -B NUM, --before-context=NUM Imprimir NUM líneas de contexto antes de las líneas coincidentes. NUM debe ser un entero no negativo.

    MATCHING ERRORS

    Si se encuentra un error en una expresión regular PCRE, pcregrep imprimirá un mensaje de error en stderr y saldrá con un código de salida de 2.

    DIAGNOSTICS

    Los códigos de salida son los siguientes:

    0: Se encontró al menos una coincidencia.

    1: No se encontró ninguna coincidencia.

    2: Se encontró un error de sintaxis en la expresión regular, o un error de archivo.
