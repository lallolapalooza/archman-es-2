LA BIBLIOTECA PCRE DE 16 BITS

A partir de la versión 8.30, es posible compilar una biblioteca PCRE que admita cadenas de caracteres de 16 bits, incluidas las cadenas UTF-16, además de o en lugar de la biblioteca original de 8 bits. La mayor parte del trabajo para hacer esto posible fue realizado por Zoltan Herczeg. Las dos bibliotecas contienen conjuntos idénticos de funciones, utilizadas exactamente de la misma manera. Solo los nombres de las funciones y los tipos de datos de sus argumentos y resultados son diferentes. Para evitar una excesiva complicación y reducir la carga de mantenimiento de la documentación, la mayor parte de la documentación de PCRE describe la biblioteca de 8 bits, con solo referencias ocasionales a la biblioteca de 16 bits. Esta página describe lo que es diferente cuando se utiliza la biblioteca de 16 bits.

ADVERTENCIA: Una única aplicación puede enlazarse con ambas bibliotecas, pero debe tener cuidado al procesar cualquier patrón particular para utilizar funciones de solo una biblioteca. Por ejemplo, si desea estudiar un patrón que se compiló con pcre16_compile(), debe hacerlo con pcre16_study(), no con pcre_study(), y debe liberar los datos de estudio con pcre16_free_study().

EL ARCHIVO DE CABECERA

Solo hay un archivo de cabecera, pcre.h. Contiene prototipos para todas las funciones de todas las bibliotecas, así como definiciones de banderas, estructuras, códigos de error, etc.

EL NOMBRE DE LA BIBLIOTECA

En sistemas tipo Unix, la biblioteca de 16 bits se llama libpcre16, y normalmente se puede acceder añadiendo -lpcre16 al comando para enlazar una aplicación que utiliza PCRE.

TIPOS DE CADENAS

En la biblioteca de 8 bits, las cadenas se pasan a las funciones de la biblioteca PCRE como vectores de bytes con el tipo C "char *". En la biblioteca de 16 bits, las cadenas se pasan como vectores de cantidades de 16 bits sin signo. La macro PCRE_UCHAR16 especifica un tipo de dato apropiado, y PCRE_SPTR16 se define como "const PCRE_UCHAR16 *". En muchísimos entornos, "short int" es un tipo de dato de 16 bits. Cuando PCRE se compila, define PCRE_UCHAR16 como "unsigned short int", pero comprueba que realmente sea un tipo de dato de 16 bits. Si no lo es, la compilación falla con un mensaje de error indicando al mantenedor que modifique la definición apropiadamente.

TIPOS DE ESTRUCTURAS

Los tipos de las estructuras opacas que se utilizan para patrones compilados de 16 bits y pilas JIT son pcre16 y pcre16_jit_stack respectivamente. El tipo de la estructura accesible por el usuario que se devuelve por pcre16_study() es pcre16_extra, y el tipo de la estructura que se utiliza para pasar datos a una función de llamada es pcre16_callout_block. Estas estructuras contienen los mismos campos, con los mismos nombres, que sus homólogas de 8 bits. La única diferencia es que los punteros a cadenas de caracteres son de tipo de 16 bits en lugar de 8 bits.

FUNCIONES DE 16 BITS

Por cada función de la biblioteca de 8 bits existe una función correspondiente en la biblioteca de 16 bits con un nombre que empieza por pcre16_ en lugar de pcre_. Los prototipos se enumeran arriba. Además, hay una función adicional, pcre16_utf16_to_host_byte_order(). Esta es una función de utilidad que convierte una cadena de caracteres UTF-16 al orden de bytes del host si es necesario. Las otras funciones de 16 bits esperan que las cadenas que se les pasan estén en el orden de bytes del host.

Los argumentos input y output de pcre16_utf16_to_host_byte_order() pueden apuntar a la misma dirección, es decir, se admite la conversión in situ. El búfer de salida debe ser al menos tan largo como el de entrada.

El argumento length especifica el número de unidades de datos de 16 bits en la cadena de entrada; un valor negativo especifica una cadena terminada en nulo.

THE PCRE 16-BIT LIBRARY

Esta página describe las funciones que se encuentran en la biblioteca PCRE de 16 bits. Estas funciones realizan las mismas operaciones que sus contrapartes de 8 bits (descritas en la página de manual pcreapi), pero operan en cadenas de 16 bits que contienen caracteres de ancho fijo. La biblioteca puede manejar cadenas codificadas en UTF-16 si se solicita.

THE HEADER FILE

El archivo de cabecera que debe incluirse es <pcre16.h>.

THE LIBRARY NAME

La biblioteca se llama libpcre16.a o libpcre16.so.

STRING TYPES

Las cadenas de entrada y salida para la biblioteca de 16 bits son punteros a PCRE_UCHAR16, que es un tipo de carácter sin signo de 16 bits. Las cadenas deben terminar con un valor nulo.

STRUCTURE TYPES

Las estructuras de datos de compilación y coincidencia son las mismas que para la biblioteca de 8 bits.

16-BIT FUNCTIONS

Las funciones de la biblioteca de 16 bits tienen nombres que comienzan con pcre16_ en lugar de pcre_. El resto de los nombres de las funciones son idénticos a los de la biblioteca de 8 bits.

La función pcre16_utf16_to_host_byte_order() se utiliza para convertir una cadena de 16 bits codificada en UTF-16 a la orden de bytes del host. Devuelve la cadena convertida. El argumento byte_order apunta a un entero. Si tiene un valor distinto de cero, la cadena de entrada está en el orden de bytes del host; de lo contrario, se asume el orden de bytes opuesto. Las marcas de orden de bytes (BOM) en la cadena pueden cambiar esto. El orden de bytes final se pasa de vuelta al final del procesamiento.

Si keep_boms no es cero, se copian caracteres de marca de orden de bytes (0xfeff) en la cadena de salida. De lo contrario, se descartan.

El resultado de la función es el número de unidades de 16 bits colocadas en el búfer de salida, incluido el terminador cero si la cadena estaba terminada en cero.

SUBJECT STRING OFFSETS

Las longitudes y los desplazamientos de inicio de las cadenas de asunto deben especificarse en unidades de datos de 16 bits, y los desplazamientos dentro de las cadenas de asunto que devuelven las funciones de coincidencia también están en unidades de 16 bits en lugar de bytes.

NAMED SUBPATTERNS

La tabla de traducción de nombres a números que se mantiene para subpatrones con nombre utiliza caracteres de 16 bits. La función pcre16_get_stringtable_entries() devuelve la longitud de cada entrada en la tabla como el número de unidades de datos de 16 bits.

OPTION NAMES

Hay dos nuevos nombres de opciones generales, PCRE_UTF16 y PCRE_NO_UTF16_CHECK, que corresponden a PCRE_UTF8 y PCRE_NO_UTF8_CHECK en la biblioteca de 8 bits. De hecho, estas nuevas opciones definen los mismos bits en la palabra de opciones. Hay una discusión sobre la validez de las cadenas UTF-16 en la página pcreunicode.

Para la función pcre16_config(), hay una opción PCRE_CONFIG_UTF16 que devuelve 1 si el soporte UTF-16 está configurado, de lo contrario 0. Si esta opción se da a pcre_config() o pcre32_config(), o si la opción PCRE_CONFIG_UTF8 o PCRE_CONFIG_UTF32 se da a pcre16_config(), el resultado es el error PCRE_ERROR_BADOPTION.

CHARACTER CODES

En el modo de 16 bits, cuando PCRE_UTF16 no está configurado, los valores de caracteres se tratan de la misma manera que en el modo de 8 bits sin UTF-8, excepto, por supuesto, que pueden variar de 0 a 0xffff en lugar de 0 a 0xff. Por lo tanto, los tipos de caracteres para caracteres menores de 0xff pueden verse influenciados por la configuración regional de la misma manera que antes. Los caracteres mayores que 0xff tienen un solo caso y ningún "tipo" (como letra o dígito).

En el modo UTF-16, el código del carácter es Unicode, en el rango de 0 a 0x10ffff, con la excepción de los valores en el rango de 0xd800 a 0xdfff porque esos son valores "sustitutos" que se utilizan en pares para codificar valores mayores que 0xffff.

Una cadena UTF-16 puede indicar su endianidad mediante un código especial conocido como marca de orden de bytes (BOM). Las funciones PCRE no manejan esto, esperando que las cadenas estén en el orden de bytes del host. Se proporciona una función de utilidad llamada pcre16_utf16_to_host_byte_order() para ayudar con esto (ver arriba).

ERROR NAMES

Los errores PCRE_ERROR_BADUTF16_OFFSET y PCRE_ERROR_SHORTUTF16 corresponden a sus contrapartes de 8 bits. El error PCRE_ERROR_BADMODE se produce cuando un patrón compilado se pasa a una función que procesa patrones en el otro modo, por ejemplo, si un patrón compilado con pcre_compile() se pasa a pcre16_exec().

Hay nuevos códigos de error cuyos nombres comienzan con PCRE_UTF16_ERR para cadenas UTF-16 inválidas, correspondientes a los códigos PCRE_UTF8_ERR para cadenas UTF-8 que se describen en la sección titulada "Códigos de razón para cadenas UTF-8 inválidas" en la página principal de pcreapi. Los errores UTF-16 son:


PCRE_UTF16_ERR1 Sustituto bajo faltante al final de la cadena
PCRE_UTF16_ERR2 Sustituto bajo inválido sigue a un sustituto alto
PCRE_UTF16_ERR3 Sustituto bajo aislado
PCRE_UTF16_ERR4 No es un carácter

ERROR TEXTS

Si hay un error al compilar un patrón, el texto del error que se devuelve con pcre16_compile() o pcre16_compile2() sigue siendo una cadena de caracteres de 8 bits, terminada en nulo.

CALLOUTS

Los campos *subject* y *mark* en el bloque de llamada que se pasa a una función de llamada apuntan a vectores de 16 bits.

TESTING

El programa pcretest continúa operando con archivos de entrada y salida de 8 bits, pero puede usarse para probar la biblioteca de 16 bits. Si se ejecuta con la opción de línea de comandos -16, los patrones y las cadenas de asunto se convierten de 8 bits a 16 bits antes de pasarse a PCRE, y se utilizan las funciones de la biblioteca de 16 bits en lugar de las de 8 bits. Las cadenas de 16 bits devueltas se convierten a 8 bits para su salida. Si las bibliotecas de 8 bits y 32 bits no se compilaron, pcretest usa 16 bits por defecto y la opción -16 se ignora.

Cuando se está creando PCRE, el script RunTest que es llamado por "make check" utiliza la opción -C de pcretest para descubrir cuál de las bibliotecas de 8, 16 y 32 bits se ha creado, y ejecuta las pruebas apropiadamente.

NOT SUPPORTED IN 16-BIT MODE

No todas las características de la biblioteca de 8 bits están disponibles con la biblioteca de 16 bits. Las funciones de envoltura C++ y POSIX solo admiten la biblioteca de 8 bits, y el programa pcregrep es actualmente solo de 8 bits.
