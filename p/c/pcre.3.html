PCRE(3) Manual de Funciones de Biblioteca PCRE(3)

NOMBRE

PCRE - expresiones regulares compatibles con Perl (API original)

POR FAVOR TENGA EN CUENTA

Este documento se relaciona con las versiones de PCRE que utilizan la API original, con nombres de biblioteca libpcre, libpcre16 y libpcre32. En enero de 2015 se lanzó la primera versión de una nueva API, conocida como PCRE2, con números de versión a partir de 10.00 y nombres de biblioteca libpcre2-8, libpcre2-16 y libpcre2-32. Las bibliotecas antiguas (ahora llamadas PCRE1) han llegado al final de su vida útil, y la versión 8.45 es la última. Se recomienda a los nuevos proyectos que utilicen las nuevas bibliotecas PCRE2.

INTRODUCCIÓN

La biblioteca PCRE es un conjunto de funciones que implementan la coincidencia de patrones de expresiones regulares utilizando la misma sintaxis y semántica que Perl, con solo algunas diferencias. También hay disponibles algunas características que aparecieron en Python y PCRE antes de aparecer en Perl, utilizando la sintaxis de Python; existe cierto soporte para uno o dos elementos de sintaxis de .NET y Oniguruma, y hay una opción para solicitar algunos cambios menores que proporcionan una mejor compatibilidad con JavaScript.

A partir de la versión 8.30, es posible compilar dos bibliotecas PCRE separadas: la original, que admite cadenas de caracteres de 8 bits (incluidas cadenas UTF-8), y una segunda biblioteca que admite cadenas de caracteres de 16 bits (incluidas cadenas UTF-16). El proceso de compilación permite compilar una o ambas. La mayor parte del trabajo para hacer esto posible fue realizado por Zoltan Herczeg.

A partir de la versión 8.32, es posible compilar una tercera biblioteca PCRE separada que admita cadenas de caracteres de 32 bits (incluidas cadenas UTF-32). El proceso de compilación permite cualquier combinación de las bibliotecas de 8, 16 y 32 bits. El trabajo para hacer esto posible fue realizado por Christian Persch.

Las tres bibliotecas contienen conjuntos idénticos de funciones, excepto que los nombres en la biblioteca de 16 bits comienzan con pcre16_ en lugar de pcre_, y los nombres en la biblioteca de 32 bits comienzan con pcre32_ en lugar de pcre_. Para evitar la excesiva complicación y reducir la carga de mantenimiento de la documentación, la mayor parte de la documentación describe la biblioteca de 8 bits, con las diferencias para las bibliotecas de 16 y 32 bits descritas por separado en las páginas pcre16 y pcre32. Las referencias a funciones o estructuras de la forma pcre[16|32]_xxx deben leerse como que significan "pcre_xxx al usar la biblioteca de 8 bits, pcre16_xxx al usar la biblioteca de 16 bits o pcre32_xxx al usar la biblioteca de 32 bits".

La implementación actual de PCRE corresponde aproximadamente con Perl 5.12, incluido el soporte para cadenas codificadas en UTF-8/16/32 y propiedades de categoría general de Unicode. Sin embargo, el soporte de UTF-8/16/32 y Unicode debe habilitarse explícitamente; no es el valor predeterminado. Las tablas de Unicode corresponden a la versión 6.3.0 de Unicode.

Además de la función de coincidencia compatible con Perl, PCRE contiene una función alternativa que coincide con los mismos patrones compilados de manera diferente. En ciertas circunstancias, la función alternativa tiene algunas ventajas. Para una discusión de los dos algoritmos de coincidencia, consulte la página pcrematching.

PCRE está escrito en C y se distribuye como una biblioteca C. Varias personas han escrito envoltorios e interfaces de diversos tipos. En particular, Google Inc. ha proporcionado un envoltorio C++ completo para la biblioteca de 8 bits. Este ahora se incluye como parte de la distribución PCRE. La página pcrecpp contiene detalles de esta interfaz. Las contribuciones de otras personas se pueden encontrar en el directorio Contrib del sitio FTP principal, que es:

ftp://ftp.csx.cam.ac.uk/pub/software/programming/pcre

Los detalles sobre qué características de expresiones regulares de Perl son compatibles y cuáles no se detallan en documentos separados. Consulte las páginas pcrepattern y pcrecompat. Hay un resumen de sintaxis en la página pcresyntax.

Algunas características de PCRE pueden incluirse, excluirse o modificarse al compilar la biblioteca. La función pcre_config() permite a un cliente descubrir qué características están disponibles. Las características en sí se describen en la página pcrebuild. La documentación sobre la compilación de PCRE para varios sistemas operativos se puede encontrar en los archivos README y NON-AUTOTOOLS_BUILD en la distribución fuente.

Las bibliotecas contienen una serie de funciones y tablas de datos internas no documentadas que son utilizadas por más de una de las funciones externas exportadas, pero que no están destinadas al uso por parte de llamadores externos. Sus nombres comienzan todos con "_pcre_" o "_pcre16_" o "_pcre32_", lo que, con suerte, no provocará conflictos de nombres. En algunos entornos, es posible controlar qué símbolos externos se exportan al compilar una biblioteca compartida, y en estos casos, los símbolos no documentados no se exportan.

CONSIDERACIONES DE SEGURIDAD

Si está utilizando PCRE en una aplicación que no es UTF y que permite a los usuarios proporcionar patrones arbitrarios para compilar, debe ser consciente de una característica que permite a los usuarios habilitar el soporte UTF desde dentro de un patrón, siempre que PCRE se haya compilado con soporte UTF. Por ejemplo, un patrón de 8 bits que comienza con "(*UTF8)" o "(*UTF)" habilita el modo UTF, que interpreta los patrones y los sujetos como cadenas de caracteres UTF-8 en lugar de caracteres individuales de 8 bits. Esto hace que tanto el patrón como los datos contra los que se compara se verifiquen para la validez UTF-8. Si la cadena de datos es muy larga, dicha verificación podría consumir suficientes recursos como para que su aplicación pierda rendimiento.

Una forma de protegerse contra esta posibilidad es utilizar la función pcre_fullinfo() para verificar las opciones del patrón compilado para UTF. Alternativamente, a partir de la versión 8.33, puede establecer la opción PCRE_NEVER_UTF al compilar. Esto provoca un error de compilación si un patrón contiene una secuencia de configuración UTF.

Si su aplicación es una que admite UTF, tenga en cuenta que la verificación de validez puede llevar tiempo. Si la misma cadena de datos se va a comparar muchas veces, puede utilizar la opción PCRE_NO_UTF[8|16|32]_CHECK para la segunda y siguientes comparaciones para evitar verificaciones redundantes.

Otra forma en que el rendimiento puede verse afectado es ejecutando un patrón que tiene un árbol de búsqueda muy grande contra una cadena que nunca coincidirá. Los repeticiones ilimitadas anidadas en un patrón son un ejemplo común. PCRE proporciona cierta protección contra esto: consulte la característica PCRE_EXTRA_MATCH_LIMIT en la página pcreapi.

DOCUMENTACIÓN DEL USUARIO

La documentación del usuario para PCRE consta de varias secciones diferentes. En el formato "man", cada una de estas es una "página man" separada. En formato HTML, cada una es una página separada, enlazada desde la página de índice. En formato de texto plano, las descripciones de los programas pcregrep y pcretest se encuentran en los archivos llamados pcregrep.txt y pcretest.txt, respectivamente. Las secciones restantes, excepto la sección pcredemo (que es una lista de programas), se concatenan en pcre.txt, para facilitar la búsqueda. Las secciones son las siguientes:


pcre este documento
pcre-config mostrar información de configuración de instalación de PCRE
pcre16 detalles de la biblioteca de 16 bits
pcre32 detalles de la biblioteca de 32 bits
pcreapi detalles de la API nativa de C de PCRE
pcrebuild compilación de PCRE
pcrecallout detalles de la función de llamada
pcrecompat discusión de la compatibilidad con Perl
pcrecpp detalles del envoltorio C++ para la biblioteca de 8 bits
pcredemo un programa C de demostración que utiliza PCRE
pcregrep descripción del comando pcregrep (solo 8 bits)
pcrejit discusión del soporte de optimización just-in-time
pcrelimits detalles de límites de tamaño y otros
pcrematching discusión de los dos algoritmos de coincidencia
pcrepartial detalles de la instalación de coincidencia parcial
pcrepattern sintaxis y semántica de las expresiones regulares compatibles
pcreperform discusión de problemas de rendimiento
pcreposix la API de C compatible con POSIX para la biblioteca de 8 bits
pcreprecompile detalles de cómo guardar y reutilizar patrones precompilados
pcresample discusión del programa pcredemo
pcrestack discusión del uso de la pila
pcresyntax referencia rápida de sintaxis
pcretest descripción del comando de prueba pcretest
pcreunicode discusión del soporte de Unicode y UTF-8/16/32

En los formatos "man" y HTML, también hay una página corta para cada función de biblioteca C, que enumera sus argumentos y resultados.
