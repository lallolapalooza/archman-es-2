PCP2OPENTELEMETRY(1) General Commands Manual PCP2OPENTELEMETRY(1)

NAME

pcp2opentelemetry - pcp-to-opentelemetry exporter

SYNOPSIS

pcp2opentelemetry [-5CEGHIjLmnrRvVxXz?] [-4 action] [-8|-9 limit] [-a archive] [-A align] [--archive-folio folio] [-b|-B space-scale] [-c config] [--container container] [-D debug] [--daemonize] [-e derived] [-f format] [-F outfile] [-h host] [-i instances] [-J rank] [-K spec] [-N predicate] [-o timeout] [-O origin] [-p password] [-P|-0 precision] [-q|-Q count-scale] [-s samples] [-S starttime] [-t interval] [-T endtime] [-u url] [-U username] [-y|-Y time-scale] [-Z timezone] metricspec [...]

DESCRIPTION

pcp2opentelemetry is a customizable performance metrics exporter tool from PCP to OpenTelemetry - https://opentelemetry.io - format. Any available performance metric, live or archived, system and/or application, can be selected for exporting using either command line arguments or a configuration file.

pcp2opentelemetry is a close relative of pmrep(1). Refer to pmrep(1) for the metricspec description accepted on pcp2opentelemetry command line. See pmrep.conf(5) for description of the pcp2opentelemetry.conf configuration file syntax. This page describes pcp2opentelemetry specific options and configuration file differences with pmrep.conf(5). pmrep(1) also lists some usage examples of which most are applicable with pcp2opentelemetry as well.

Only the command line options listed on this page are supported, other options available for pmrep(1) are not supported.

Options via environment values (see pmGetOptions(3)) override the corresponding built-in default values (if any). Configuration file options override the corresponding environment variables (if any). Command line options override the corresponding configuration file options (if any).

CONFIGURATION FILE

pcp2opentelemetry uses a configuration file with syntax described in pmrep.conf(5). The following options are common with pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. The rest of the pmrep.conf options are recognized but ignored for compatibility.

pcp2opentelemetry specific options

url (string)

Send OpenTelemetry output as a HTTP POST to the given url. Corresponding command line option is -u. Defaults to None.

http_pass (string)

Use given password for Basic Authentication when sending a HTTP POST. Corresponding command line option is -p. Defaults to None.

http_user (string)

Use given username for Basic Authentication when sending a HTTP POST. Corresponding command line option is -U. Defaults to None.

http_timeout (number)

Maximum time (in seconds) when sending a HTTP POST. Corresponding command line option is -o. Defaults to 2.5 seconds.

OPTIONS

The available command line options are:

-0 precision, --precision-force=precision
Like -P but this option will override per-metric specifications.
-4 action, --names-change=action
Specify which action to take on receiving a metric names change event during sampling. These events occur when a PMDA discovers new metrics sometime after starting up, and informs running client tools like pcp2opentelemetry. Valid values for action are update (refresh metrics being sampled), ignore (do nothing - the default behaviour) and abort (exit the program if such an event occurs).
-5, --ignore-unknown
Silently ignore any metric name that cannot be resolved. At least one metric must be found for the tool to start.
-8 limit, --limit-filter=limit
Limit results to instances with values above/below limit. A positive integer will include instances with values at or above the limit in reporting. A negative integer will include instances with values at or below the limit in reporting. A value of zero performs no limit filtering. This option will not override possible per-metric specifications. See also -J and -N.
-9 limit, --limit-filter-force=limit
Like -8 but this option will override per-metric specifications.
-a archive, --archive=archive
Performance metric values are retrieved from the set of Performance Co-Pilot (PCP) archive files identified by the archive argument, which is a comma-separated list of names, each of which may be the base name of an archive or the name of a directory containing one or more archives.
-A align, --align=align
Force the initial sample to be aligned on the boundary of a natural time unit align. Refer to PCPIntro(1) for a complete description of the syntax for align.
--archive-folio=folio
Read metric source archives from the PCP archive folio created by tools like pmchart(1) or, less often, manually with mkaf(1).
-b scale, --space-scale=scale
Unit/scale for space (byte) metrics, possible values include bytes, Kbytes, KB, Mbytes, MB, and so forth. This option will not override possible per-metric specifications. See also pmParseUnitsStr(3).
-B scale, --space-scale-force=scale
Like -b but this option will override per-metric specifications.
-c config, --config=config
Specify the config file or directory to use. In case config is a directory all files in it ending .conf will be included. The default is the first found of: ./pcp2opentelemetry.conf, $HOME/.pcp2opentelemetry.conf, $HOME/pcp/pcp2opentelemetry.conf, and $PCP_SYSCONF_DIR/pcp2opentelemetry.conf. For details, see the above section and pmrep.conf(5).
--container=container
Fetch performance metrics from the specified container, either local or remote (see -h).
-C, --check
Exit before reporting any values, but after parsing the configuration and metrics and printing possible headers.
--daemonize
Daemonize on startup.

-e derivado, --derived=derivado
Especifica métricas de rendimiento derivadas. Si derivado comienza con una barra (``/'') o con un punto (``.''), se interpretará como un archivo de configuración de métricas derivadas de PCP, de lo contrario se interpretará como expresiones de métricas derivadas separadas por comas o puntos y comas. Para una descripción completa de las métricas derivadas y los archivos de configuración de métricas derivadas de PCP, consulte pmLoadDerivedConfig(3) y pmRegisterDerived(3). Alternativamente, el uso de la sintaxis de configuración de pmrep.conf(5) permite definir métricas derivadas como parte de conjuntos de métricas.
-E, --exact-types
Escribe los números como tipos de datos numéricos, no como cadenas, perdiendo potencialmente algo de precisión.
-f formato, --timestamp-format=formato
Utiliza la cadena de formato para dar formato a la marca de tiempo. El formato se utilizará con el método datetime.strftime de Python, que es en su mayor parte el mismo que el descrito en strftime(3). El valor predeterminado es %Y-%m-%d %H:%M:%S.
-F archivo_salida, --output-file=archivo_salida
Especifica el archivo de salida archivo_salida.
-G, --no-globals
No incluir métricas globales en el informe (ver pmrep.conf(5)).
-h host, --host=host
Obtener métricas de rendimiento de pmcd(1) en host, en lugar de del host local predeterminado.
-H, --no-header
No imprimir ningún encabezado.
-i instancias, --instances=instancias
Recuperar y reportar solo las instancias de métrica especificadas. Por defecto se reportan todas las instancias, presentes y futuras.

Consulte pmrep(1) para obtener una descripción completa de esta opción.

-I, --ignore-incompat
Ignorar métricas incompatibles. Por defecto, las métricas incompatibles (es decir, su tipo no es compatible o no se pueden escalar como se solicita) harán que pcp2opentelemetry termine con un mensaje de error. Con esta opción, todas las métricas incompatibles se omiten silenciosamente del informe. Esto puede ser especialmente útil al solicitar nodos no terminales del árbol PMNS para reportar.
-j, --live-filter
Realizar filtrado en vivo de instancias. Esto permite capturar todas las instancias nombradas incluso si los procesos se reinician en algún momento (a diferencia de sin filtrado en vivo). Realizar filtrado en vivo sobre un gran número de instancias añadirá una sobrecarga interna, por lo que se aconseja precaución por parte del usuario. Ver también -n.
-J rango, --rank=rango
Limitar los resultados a las instancias de mayor/menor rango de métricas con valores de conjunto. Un entero positivo incluirá las instancias de mayor valor en el informe. Un entero negativo incluirá las instancias de menor valor en el informe. Un valor de cero no realiza ningún ranking. El ranking no implica ordenación, ver -6. Ver también -8.
-K espec, --spec-local=espec
Al obtener métricas de un contexto local (ver -L), la opción -K se puede usar para controlar los PMDA de DSO que deben hacerse accesibles. El argumento espec se ajusta a la sintaxis descrita en pmSpecLocalPMDA(3). Se pueden usar varias opciones -K.
-L, --local-PMDA
Utilizar un contexto local para recopilar métricas de los PMDA de DSO en el host local sin PMCD. Ver también -K.
-n, --invert-filter
Realizar ranking antes del filtrado en vivo. Por defecto, el filtrado en vivo de instancias (cuando se solicita, ver -j) ocurre antes del ranking de instancias (cuando se solicita, ver -J). Con esta opción, la lógica se invierte y el ranking ocurre antes del filtrado en vivo.
-m, --include-labels
Incluir etiquetas de métricas PCP en la salida.
-N predicado, --predicate=predicado
Especificar una lista separada por comas de métricas de referencia de filtro predicado. Por defecto, el ranking (ver -J) se realiza para cada métrica individualmente. Con predicados, el ranking se realiza solo para las métricas de predicado especificadas. Al reportar, el resto de las métricas que comparten el mismo dominio de instancia (ver PCPIntro(1)) que el predicado incluirán solo las instancias de mayor/menor rango del predicado correspondiente. El ranking no implica ordenación, ver -6.

Por ejemplo, utilizando proc.memory.rss (tamaño de memoria residente del proceso) como métrica de predicado junto con proc.io.total_bytes y mem.util.used como métricas a reportar, solo los procesos que utilizan la mayor/menor cantidad de memoria (según -J) se incluirán al reportar los bytes totales escritos por los procesos. Dado que mem.util.used es una métrica de valor único (por lo tanto, no comparte el mismo dominio de instancia que las métricas relacionadas con el proceso), se reportará como de costumbre.

-o, --http-timeout
Tiempo de espera (en segundos) al enviar una solicitud POST HTTP con la opción -u. El valor predeterminado es 2.5 segundos.
-O origen, --origin=origen
Al reportar métricas archivadas, el reporte comenzará en origen dentro de la ventana de tiempo (ver -S y -T). Consulte PCPIntro(1) para una descripción completa de la sintaxis para origen.
-p, --http-pass
Contraseña al usar autenticación básica HTTP con la opción -u.
-P precision, --precision=precision
Utilizar precision para valores numéricos de salida no enteros. El valor predeterminado es utilizar 3 lugares decimales (cuando sea aplicable). Esta opción *no* anulará posibles especificaciones por métrica.
-q escala, --count-scale=escala
Unidad/escala para métricas de contador, los valores posibles incluyen count x 10^-1, count, count x 10, count x 10^2, y así sucesivamente de 10^-8 a 10^7. (Estos valores son actualmente sensibles a espacios.) Esta opción *no* anulará posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-Q escala, --count-scale-force=escala
Similar a -q pero esta opción *anulará* las especificaciones por métrica.
-r, --raw
Mostrar valores de métrica sin procesar, no convertir contadores acumulativos a tasas. Esta opción *anulará* posibles especificaciones por métrica.
-R, --raw-prefer
Similar a -r pero esta opción *no* anulará las especificaciones por métrica.
-s muestras, --samples=muestras
El argumento muestras define el número de muestras a recuperar y reportar. Si muestras es 0 o -s no se especifica, pcp2opentelemetry muestreará y reportará continuamente (en modo de tiempo real ) o hasta el final del conjunto de archivos PCP (en modo de archivo). Ver también -T.
-S hora_inicio, --start=hora_inicio
Al reportar métricas archivadas, el informe se restringirá a aquellos registros registrados en o después de hora_inicio. Consulte PCPIntro(1) para una descripción completa de la sintaxis para hora_inicio.
-t intervalo, --interval=intervalo
Establecer el intervalo de reporte a algo diferente al segundo predeterminado. El argumento intervalo sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos). Ver también la opción -T.
-T hora_fin, --finish=hora_fin
Al reportar métricas archivadas, el informe se restringirá a aquellos registros registrados antes o en hora_fin. Consulte PCPIntro(1) para una descripción completa de la sintaxis para hora_fin.

Cuando se utiliza para definir el tiempo de ejecución antes de que pcp2opentelemetry salga, si no se proporciona ninguna muestra (ver -s), el número de muestras reportadas dependerá del intervalo (ver -t). Si se proporciona muestras, el intervalo se ajustará para permitir el reporte de muestras durante el tiempo de ejecución. En caso de que se proporcionen -T, -s y -t, hora_fin determinará el tiempo real en el que pcp2opentelemetry se ejecutará.

-u, --url
URL para enviar una solicitud POST HTTP (en lugar de la salida estándar predeterminada).
-U, --http-user
Nombre de usuario al usar autenticación básica HTTP con la opción -u.
-v, --omit-flat
Reportar solo métricas de conjunto con instancias (por ejemplo, disk.dev.read) y omitir métricas "planas" de valor único sin instancias (por ejemplo, kernel.all.sysfork). Ver -i y -I.
-V, --version
Mostrar el número de versión y salir.
-x, --with-extended
Escribir información extendida.
-X, --with-everything
Escribir todo lo conocido sobre las métricas, incluyendo los IDs internos de PCP. Las etiquetas se omiten por compatibilidad hacia atrás, use -m para incluirlas también.
-z, --zerofill
No dejar huecos en el informe si faltan muestras (por ejemplo, cuando se informa sobre archivos que no se registran continuamente)..

OPTIONS

-y escala, --time-scale=escala
Unidad/escala para métricas de tiempo, los valores posibles incluyen nanosec, ns, microsec, us, millisec, ms, y así sucesivamente hasta hour, hr. Esta opción *no* anulará especificaciones por métrica. Ver también pmParseUnitsStr(3).
-Y escala, --time-scale-force=escala
Similar a -y pero esta opción *anulará* especificaciones por métrica.
-z, --hostzone
Utiliza la zona horaria local del host que es la fuente de las métricas de rendimiento, según lo identificado por las opciones -h o -a. El valor predeterminado es usar la zona horaria del host local.
-Z zona_horaria, --timezone=zona_horaria
Utiliza zona_horaria para la fecha y hora. Zona_horaria está en el formato de la variable de entorno TZ como se describe en environ(7). Tenga en cuenta que al incluir una cadena de zona horaria en la salida, se utilizan compensaciones UTC estilo ISO 8601 (por lo que algo como -Z EST+5 se convertirá en UTC-5).
-?, --help
Muestra el mensaje de uso y sale.

ARCHIVOS

pcp2opentelemetry.conf
Archivo de configuración de pcp2opentelemetry (ver -c)
$PCP_SYSCONF_DIR/pmrep/*.conf
Archivos de configuración de pmrep predeterminados proporcionados por el sistema

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para ver las variables de entorno que afectan a las herramientas PCP, consulte pmGetOptions(3).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información a veces es críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
