NOMBRE

pcap_get_required_select_timeout - obtener un tiempo de espera para usar al hacer select() para una captura en vivo

SINOPSIS

#include <pcap/pcap.h>
const struct timeval *pcap_get_required_select_timeout(pcap_t *p);

DESCRIPCIÓN

pcap_get_required_select_timeout() devuelve, en UNIX, un puntero a un struct timeval que contiene un valor que debe usarse como tiempo de espera mínimo en llamadas a select(2), poll(2), epoll_wait(2) y kevent(2), o NULL si no hay dicho tiempo de espera. Si se devuelve un valor distinto de NULL, debe utilizarse independientemente de si pcap_get_selectable_fd(3PCAP) devuelve -1 para cualquier descriptor en el que se realicen estas llamadas. pcap_get_required_select_timeout() debe llamarse para todos los pcap_t antes de una llamada a select(), poll(), epoll_wait() o kevent(), y los tiempos de espera utilizados para esas llamadas deben actualizarse según corresponda, dado el nuevo valor del tiempo de espera.

Para kevent(), se puede usar un filtro EVFILT_TIMER por cada descriptor seleccionable, en lugar de usar el argumento de tiempo de espera de kevent(); si el evento EVFILT_TIMER para un descriptor seleccionable particular señala un evento, se debe llamar a pcap_dispatch(3PCAP) para el pcap_t correspondiente.

En sistemas Linux con timerfd_create(2), se puede usar un objeto de temporizador creado por timerfd_create() por cada descriptor seleccionable, en lugar de usar el argumento de tiempo de espera de epoll_wait(); si el objeto de temporizador para un descriptor seleccionable particular señala un evento, se debe llamar a pcap_dispatch(3PCAP) para el pcap_t correspondiente.

De lo contrario, se debe usar un valor de tiempo de espera no mayor que el más pequeño de todos los tiempos de espera devueltos por pcap_get_required_select_timeout() para los dispositivos de los que se capturarán paquetes y cualquier otro tiempo de espera que se vaya a utilizar en la llamada, y, cuando la llamada devuelva, se debe llamar a pcap_dispatch(3PCAP) para todos los pcap_t para los que se devolvió un tiempo de espera distinto de NULL, independientemente de si se indica que tienen algo que leer de ellos o no.

Todos los dispositivos con un tiempo de espera distinto de NULL deben ponerse en modo no bloqueante con pcap_setnonblock(3PCAP).

Tenga en cuenta que un dispositivo en el que se puede realizar una lectura sin bloquear puede, en algunas plataformas, no tener paquetes para leer si ha expirado el tiempo de espera del búfer de paquetes. Una llamada a pcap_dispatch() o pcap_next_ex(3PCAP) devolverá 0 en este caso, pero no se bloqueará.

pcap_get_required_select_timeout() no está disponible en Windows.

VALOR DEVUELTO

Se devuelve un puntero a un struct timeval si se requiere el tiempo de espera; de lo contrario, se devuelve NULL.

COMPATIBILIDAD HACIA ATRÁS

Esta función se incluyó en la versión 1.9.0 de libpcap. En versiones anteriores, select(), poll(), epoll_wait() y kevent() no podían usarse para dispositivos que no proporcionaban un descriptor de archivo seleccionable (es decir, en cualquier fuente de captura para la que pcap_get_selectable_fd() devolviera -1).

En la versión 1.10.0 y posteriores de libpcap, el valor del tiempo de espera puede cambiar de una llamada a otra, por lo que se debe llamar a pcap_get_required_select_timeout() antes de cada llamada a select(), poll(), epoll_wait() o kevent(), y el nuevo valor debe usarse para calcular los tiempos de espera para la llamada. El código que hace eso también funcionará con las versiones 1.9.x de libpcap, por lo que el código que utiliza pcap_get_required_select_timeout() debe modificarse para llamarlo para cada llamada a select(), poll(), epoll_wait() o kevent(), incluso si el código también debe funcionar con libpcap 1.9.x.
