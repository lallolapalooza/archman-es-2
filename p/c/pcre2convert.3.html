NOMBRE

PCRE2 - expresiones regulares compatibles con Perl (API revisada)

FUNCIONES DE CONVERSIÓN DE PATRONES EXPERIMENTAL

Este documento describe un conjunto de funciones que se pueden utilizar para convertir patrones "ajenos" en expresiones regulares PCRE2. Esta funcionalidad es actualmente experimental y puede ser modificada en futuras versiones. Se admiten dos tipos de patrones: globbing y POSIX.

EL CONTEXTO DE CONVERSIÓN

pcre2_convert_context *pcre2_convert_context_create(
  pcre2_general_context *gcontext);

pcre2_convert_context *pcre2_convert_context_copy(
  pcre2_convert_context *cvcontext);

void pcre2_convert_context_free(pcre2_convert_context *cvcontext);

int pcre2_set_glob_escape(pcre2_convert_context *cvcontext,
  uint32_t escape_char);

int pcre2_set_glob_separator(pcre2_convert_context *cvcontext,
  uint32_t separator_char);

Un contexto de conversión se utiliza para mantener los parámetros que afectan a cómo funciona la conversión de patrones. Como con todos los contextos de PCRE2, solo necesita usar un contexto si desea anular los valores predeterminados. Existen las funciones habituales de creación, copia y liberación. Si las funciones personalizadas de gestión de memoria se establecen en un contexto general que se pasa a pcre2_convert_context_create(), se utilizan para toda la gestión de memoria dentro de las funciones de conversión.

Actualmente, solo hay dos parámetros en el contexto de conversión. Ambos se aplican solo a las conversiones de globbing. El carácter de escape predeterminado es la tilde (` `) en Windows, de lo contrario, la barra invertida (`\`). Se puede establecer a cero, lo que significa que no hay carácter de escape, o a cualquier carácter de puntuación con un punto de código inferior a 256. El carácter separador predeterminado es la barra invertida (`\`) en Windows, de lo contrario, la barra inclinada (`/`). Se puede establecer a barra inclinada (`/`), barra invertida (`\`) o punto (`.`).

Las dos funciones de establecimiento devuelven cero en caso de éxito, o PCRE2_ERROR_BADDATA si su segundo argumento no es válido.

LA FUNCIÓN DE CONVERSIÓN

int pcre2_pattern_convert(PCRE2_SPTR pattern, PCRE2_SIZE length,
  uint32_t options, PCRE2_UCHAR **buffer,
  PCRE2_SIZE *blength, pcre2_convert_context *cvcontext);

void pcre2_converted_pattern_free(PCRE2_UCHAR *converted_pattern);

Los dos primeros argumentos de pcre2_pattern_convert() definen el patrón ajeno que se va a convertir. La longitud puede especificarse como PCRE2_ZERO_TERMINATED. El argumento options define cómo se va a procesar el patrón. Si la entrada es UTF, se debe establecer la opción PCRE2_CONVERT_UTF. También se puede establecer PCRE2_CONVERT_NO_UTF_CHECK si está seguro de que la entrada es válida. Se debe establecer una o más de las opciones de globbing, o una de las siguientes opciones POSIX para definir el tipo de conversión requerida:


PCRE2_CONVERT_GLOB
PCRE2_CONVERT_GLOB_NO_WILD_SEPARATOR
PCRE2_CONVERT_GLOB_NO_STARSTAR
PCRE2_CONVERT_POSIX_BASIC
PCRE2_CONVERT_POSIX_EXTENDED

Los detalles de las conversiones se describen a continuación. Los argumentos buffer y blength definen cómo se maneja la salida:

Si buffer es NULL, la función simplemente devuelve la longitud del patrón convertido a través de blength. Esto es uno menos que la longitud del búfer necesario, ya que siempre se añade un cero terminador a la salida.

Si buffer apunta a un puntero NULL, se obtiene un búfer de salida utilizando el asignador del contexto o malloc() si no se proporciona ningún contexto. Se coloca un puntero a este búfer en la variable a la que apunta buffer. Cuando ya no se necesite, el búfer de salida debe liberarse llamando a pcre2_converted_pattern_free(). Si se llama a esta función con un argumento NULL, retorna inmediatamente sin hacer nada.

Si buffer apunta a un puntero no NULL, blength debe establecerse a la longitud real del búfer proporcionado (en unidades de código).

En todos los casos, después de una conversión exitosa, la variable apuntada por blength se actualiza a la longitud realmente utilizada (en unidades de código), excluyendo el cero terminador que siempre se añade.

Si ocurre un error, la longitud (a través de blength) se establece en el desplazamiento dentro del patrón de entrada donde se detectó el error. Solo se detectan errores graves de sintaxis; hay muchos errores que se pasarán para que pcre2_compile() los descubra.

El valor de retorno de pcre2_pattern_convert() es cero en caso de éxito o un código de error PCRE2 distinto de cero. Tenga en cuenta que los códigos de error PCRE2 pueden ser positivos o negativos: pcre2_compile() utiliza principalmente códigos positivos y pcre2_match() utiliza códigos negativos; pcre2_convert() utiliza códigos existentes de ambos tipos. Se puede obtener un mensaje de error textual llamando a pcre2_get_error_message().

CONVERSIÓN DE GLOBS

Los globs se utilizan para coincidir con nombres de archivo y, en consecuencia, tienen el concepto de un "separador de ruta", que por defecto es la barra invertida (`\`) en Windows y la barra inclinada (`/`) en otros sistemas. Si se establece PCRE2_CONVERT_GLOB, los comodines * y ? no pueden coincidir con los separadores de ruta, pero la característica de doble-asterisco (**) (que sí coincide con los separadores) está admitida.

PCRE2_CONVERT_GLOB_NO_WILD_SEPARATOR coincide con globs permitiendo que los comodines coincidan con los separadores de ruta. PCRE2_CONVERT_GLOB_NO_STARSTAR coincide con globs con la característica de doble-asterisco desactivada. Estas opciones se pueden usar juntas.

CONVERSIÓN DE PATRONES POSIX

POSIX define dos tipos de patrones de expresiones regulares: básicos y extendidos. Estos pueden ser procesados estableciendo PCRE2_CONVERT_POSIX_BASIC o PCRE2_CONVERT_POSIX_EXTENDED, respectivamente.

En los patrones POSIX, la barra invertida no es especial dentro de una clase de caracteres. Los paréntesis de cierre sin coincidir se tratan como literales.

En los patrones básicos, ? + | {} y () deben ser escapados para ser reconocidos como metacaracteres fuera de una clase de caracteres. Si el primer carácter del patrón es *, se trata como un literal. ^ es un metacaracter solo al principio de una rama.

En los patrones extendidos, una barra invertida que no esté en una clase de caracteres siempre hace que el siguiente carácter sea literal, sea cual sea. No hay retroreferencias.

Nota: POSIX exige que se encuentre la coincidencia más larga posible en la primera posición coincidente. Esto no es lo que hace pcre2_match(); produce la primera coincidencia que se encuentra. Una aplicación puede usar pcre2_dfa_match() para encontrar la coincidencia más larga, pero eso tampoco admite retroreferencias (al igual que los patrones extendidos POSIX).
