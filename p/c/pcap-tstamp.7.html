NOMBRE

pcap-tstamp - marcas de tiempo de paquetes en libpcap

DESCRIPCIÓN

Al capturar tráfico, a cada paquete se le asigna una marca de tiempo que representa, para los paquetes entrantes, la hora de llegada del paquete y, para los paquetes salientes, la hora de transmisión del paquete. Esta hora es una aproximación de la hora de llegada o transmisión. Si es proporcionada por el sistema operativo que se ejecuta en el host donde se realiza la captura, existen varias razones por las que podría no representar con precisión la hora de llegada o transmisión:

si la marca de tiempo se aplica al paquete cuando la pila de red recibe el paquete, la pila de red podría no ver el paquete hasta que se entregue una interrupción para el paquete o un evento de temporizador haga que el controlador del dispositivo de red sondee los paquetes, y la marca de tiempo podría no aplicarse hasta que el paquete haya tenido algo de procesamiento realizado por otro código en la pila de red, por lo que podría haber un retraso significativo entre el momento en que el último bit del paquete es recibido por el dispositivo de captura y el momento en que la pila de red marca el paquete;
el temporizador utilizado para generar las marcas de tiempo puede tener baja resolución, por ejemplo, puede ser un temporizador actualizado una vez por cada tick del temporizador del sistema operativo del host, con el temporizador del sistema operativo del host haciendo tick una vez cada pocos milisegundos;
un temporizador de alta resolución podría usar un contador que se ejecuta a una velocidad dependiente de la velocidad del reloj del procesador, y esa velocidad del reloj podría ajustarse hacia arriba o hacia abajo con el tiempo y el temporizador podría no ser capaz de compensar todos esos ajustes;
el reloj del sistema operativo del host podría ajustarse con el tiempo para coincidir con un estándar de hora al que el host está siendo sincronizado, lo que podría hacerse reduciendo temporalmente la velocidad o acelerando el reloj o haciendo un único ajuste;
diferentes núcleos de CPU en un sistema multinúcleo o multiprocesador podrían estar ejecutándose a diferentes velocidades, o podrían no tener contadores de tiempo completamente sincronizados, por lo que los paquetes marcados por diferentes núcleos podrían no tener marcas de tiempo consistentes;
algunas fuentes de tiempo, como las que proporcionan el tiempo en segundos desde la Época (EPOCH) según POSIX, no cuentan los segundos intercalares, lo que significa que la parte de segundos (tv_sec) de la marca de tiempo podría no incrementarse durante un segundo intercalar, de modo que la parte de fracción de segundo de la marca de tiempo podría pasar de cero pero la parte de segundos no cambiaría, o el reloj podría funcionar un poco más lento durante un período antes del segundo intercalar.

Por estas razones, las diferencias de tiempo entre las marcas de tiempo de los paquetes no reflejarán necesariamente las diferencias de tiempo entre las horas de recepción o transmisión de los paquetes.

Además, los paquetes marcados por diferentes núcleos podrían ser marcados en un orden y agregados a la cola de paquetes para que libpcap los lea en otro orden, por lo que las marcas de tiempo podrían no ser monótonamente crecientes.

Algunos dispositivos de captura en algunas plataformas pueden proporcionar marcas de tiempo para los paquetes; esas marcas de tiempo suelen ser de alta resolución y generalmente se aplican al paquete cuando llega el primer o último bit del paquete, y por lo tanto son más precisas que las marcas de tiempo proporcionadas por el sistema operativo del host. Sin embargo, esas marcas de tiempo podrían no estar sincronizadas con el reloj del sistema operativo del host, de modo que, por ejemplo, la marca de tiempo de un paquete podría no corresponder a la marca de tiempo de un evento en el host desencadenado por la llegada de ese paquete. Si están sincronizadas con el reloj del sistema operativo del host, algunos de los problemas mencionados anteriormente con las marcas de tiempo proporcionadas por el sistema operativo del host también pueden aplicarse a las marcas de tiempo proporcionadas por el dispositivo de captura.

Dependiendo del dispositivo de captura y del software en el host, libpcap podría permitir el uso de diferentes tipos de marca de tiempo. La rutina pcap_list_tstamp_types(3PCAP) proporciona, para un manejador de captura de paquetes creado por pcap_create(3PCAP) pero no activado aún por pcap_activate(3PCAP), una lista de tipos de marca de tiempo soportados por el dispositivo de captura para ese manejador. La lista podría estar vacía, en cuyo caso no se ofrece ninguna opción de tipo de marca de tiempo para ese dispositivo de captura. Si la lista no está vacía, la rutina pcap_set_tstamp_type(3PCAP) puede usarse después de una llamada a pcap_create() y antes de una llamada a pcap_activate() para especificar el tipo de marca de tiempo a utilizar en el dispositivo. Los tipos de marca de tiempo se enumeran aquí; el primer valor es la definición #define a usar en el código, el segundo valor es el valor devuelto por pcap_tstamp_type_val_to_name(3PCAP) y aceptado por pcap_tstamp_type_name_to_val(3PCAP).

PCAP_TSTAMP_HOST - host
Marca de tiempo proporcionada por el host en el que se realiza la captura. La precisión de esta marca de tiempo no está especificada; podría o no estar sincronizada con el reloj del sistema operativo del host.
PCAP_TSTAMP_HOST_LOWPREC - host_lowprec
Marca de tiempo proporcionada por el host en el que se realiza la captura. Esta es una marca de tiempo de baja precisión, sincronizada con el reloj del sistema operativo del host.
PCAP_TSTAMP_HOST_HIPREC - host_hiprec
Marca de tiempo proporcionada por el host en el que se realiza la captura. Esta es una marca de tiempo de alta precisión, sincronizada con el reloj del sistema operativo del host. Podría ser más costoso de obtener que PCAP_TSTAMP_HOST_LOWPREC.
PCAP_TSTAMP_HOST_HIPREC_UNSYNCED - host_hiprec_unsynced
Marca de tiempo proporcionada por el host en el que se realiza la captura. Esta es una marca de tiempo de alta precisión, no sincronizada con el reloj del sistema operativo del host. Podría ser más costoso de obtener que PCAP_TSTAMP_HOST_LOWPREC.
PCAP_TSTAMP_ADAPTER - adapter
Marca de tiempo proporcionada por el adaptador de red en el que se realiza la captura. Esta es una marca de tiempo de alta precisión, sincronizada con el reloj del sistema operativo del host.
PCAP_TSTAMP_ADAPTER_UNSYNCED - adapter_unsynced
Marca de tiempo proporcionada por el adaptador de red en el que se realiza la captura. Esta es una marca de tiempo de alta precisión; no está sincronizada con el reloj del sistema operativo del host.

Las marcas de tiempo sincronizadas con el reloj del sistema pueden ir hacia atrás, ya que el reloj del sistema puede ir hacia atrás. Si un reloj no está sincronizado con el reloj del sistema, podría deberse a que el reloj del sistema no está manteniendo la hora correcta, a que el otro reloj no está manteniendo la hora correcta, o a ambos.

Las marcas de tiempo proporcionadas por el host generalmente corresponden al momento en que el código de marcado de tiempo ve el paquete; esto podría ser una cantidad desconocida de tiempo después de que el primer o último bit del paquete sea recibido por el adaptador de red, debido a la agrupación de interrupciones para la llegada de paquetes, retrasos en la cola, etc.

Por defecto, al realizar una captura en vivo o leer desde un archivo de guardado, las marcas de tiempo se proporcionan como segundos desde el 1 de enero de 1970, 00:00:00 UTC, y microsegundos desde ese valor de segundos, incluso si hay marcas de tiempo de mayor resolución disponibles desde el dispositivo de captura o en el archivo de guardado. Si, al leer un archivo de guardado, las marcas de tiempo en el archivo tienen una resolución mayor que un microsegundo, se descartan los dígitos adicionales de resolución.

La rutina pcap_set_tstamp_precision(3PCAP) puede usarse después de una llamada a pcap_create() y después de una llamada a pcap_activate() para especificar la resolución de las marcas de tiempo a obtener para el dispositivo. Si el hardware o el software no pueden proporcionar una marca de tiempo de mayor resolución, la llamada a pcap_set_tstamp_precision() fallará, y las marcas de tiempo proporcionadas después de la llamada a pcap_activate() tendrán resolución de microsegundos.

Al abrir un archivo de guardado, las rutinas pcap_open_offline_with_tstamp_precision(3PCAP) y pcap_fopen_offline_with_tstamp_precision(3PCAP) pueden usarse para especificar la resolución de las marcas de tiempo a leer del archivo; si las marcas de tiempo en el archivo tienen una resolución menor, la parte de fracción de segundo de las marcas de tiempo se escalará a la resolución especificada.

La rutina pcap_get_tstamp_precision(3PCAP) devuelve la resolución de las marcas de tiempo que se proporcionarán; al capturar paquetes, esto no refleja la precisión real de la marca de tiempo proporcionada por el hardware o el sistema operativo.

y, al leer un archivo de guardado, esto no indica la precisión real de las marcas de tiempo en el archivo.
