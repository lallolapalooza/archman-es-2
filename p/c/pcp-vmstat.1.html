PMSTAT(1) Manual de Comandos Generales PMSTAT(1)

NOMBRE

pcp-vmstat, pmstat - resumen de rendimiento del sistema de alto nivel

SINOPSIS

pcp [opciones-pcp] vmstat [intervalo [muestras]]

pmstat [-gLlPVxz?] [-a archivo] [-A alineación] [-D depuración] [-h host] [-H archivo] [-n archivopmns] [-O desfase] [-p puerto] [-s muestras] [-S horainicio] [-t intervalo] [-T horafin] [-Z zona horaria]

pcp-vmstat ...

DESCRIPCIÓN

pmstat proporciona un resumen de una línea del rendimiento del sistema cada intervalo unidad de tiempo (el valor predeterminado es 5 segundos). pmstat está diseñado para monitorizar el rendimiento del sistema al más alto nivel, después de lo cual se pueden utilizar otras herramientas para examinar subsistemas en los que se puedan observar problemas de rendimiento con mayor detalle.

pcp-vmstat es un simple envoltorio para usar con el comando pcp(1), proporcionando un formato de línea de comandos más familiar para algunos usuarios. También habilita la opción de informes extendidos de forma predeterminada, consulte la opción -x a continuación.

Se pueden monitorizar varios hosts proporcionando más de un host con múltiples flags -h (para monitorización en vivo) o proporcionando un nombre de archivo de lista de hosts, donde cada línea contiene un nombre de host, con -H, o múltiples flags -a (para monitorización retrospectiva de conjuntos de archivos).

De forma predeterminada, pmstat obtiene métricas conectándose al Demonio del Colector de Métricas de Rendimiento (PMCD) en el host local. Si se especifica la opción -L, entonces se omite pmcd(1), y las métricas se obtienen de los PMDA en el host local utilizando la variante autónoma PM_CONTEXT_LOCAL de pmNewContext(3). Cuando se utiliza la opción -h, pmstat se conecta al pmcd(1) en host y obtiene métricas de allí. Como se mencionó anteriormente, se pueden monitorizar varios hosts proporcionando múltiples flags -h.

Alternativamente, si se utiliza la opción -a, las métricas se recuperan de los archivos de archivo de Performance Co-Pilot identificados por archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos. Se pueden reproducir múltiples conjuntos de archivos proporcionando múltiples flags -a. Cuando se utiliza el flag -a, el flag -P también puede usarse para pausar la salida después de cada intervalo.

El modo autónomo solo puede conectarse al host local, el uso de un conjunto de archivos implica un nombre de host, y la nominación de un host impide el uso de un archivo, por lo que las opciones -L, -a y -h son mutuamente excluyentes.

pmstat puede ceder su propio control de tiempo y operar bajo el control de un proceso pmtime(1) que utiliza un diálogo GUI para proporcionar control de tiempo. En este caso, se debe usar la opción -g para iniciar pmstat como el único cliente de una nueva instancia de pmtime(1), o se debe usar -p para adjuntar pmstat a una instancia existente de pmtime(1) a través del canal IPC identificado por el argumento puerto.

Las opciones -S, -T, -O y -A se pueden usar para definir una ventana de tiempo para restringir las muestras recuperadas, establecer un origen inicial dentro de la ventana de tiempo o especificar una alineación "natural" de los tiempos de muestra; consulte PCPIntro(1) para una descripción completa de estas opciones.

OPCIONES

Las opciones de línea de comandos disponibles son:

-a archivo, --archivo=archivo
Los valores de las métricas de rendimiento se recuperan del conjunto de archivos de archivo de Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos.
-A alineación, --alineación=alineación
Forzar que la muestra inicial se alinee en el límite de una unidad de tiempo natural alineación. Consulte PCPIntro(1) para una descripción completa de la sintaxis de alineación.
-g, --modogui
Iniciar pmstat como cliente de un nuevo proceso servidor pmtime(1) para la reproducción de datos de rendimiento archivados utilizando la interfaz gráfica de usuario de pmtime(1).
-h host, --host=host
Obtener métricas de rendimiento de pmcd(1) en host, en lugar de localhost (predeterminado).
-H ruta, --archivohosts=ruta
Especificar la ruta a un archivo que contiene un conjunto de nombres de host donde se está ejecutando pmcd(1), en lugar de usar localhost (predeterminado).
-K espec, --espec-local=espec
Al obtener métricas de un contexto local (ver -L), la opción -K se puede usar para controlar los PMDA DSO que deben ser accesibles. El argumento espec se ajusta a la sintaxis descrita en pmSpecLocalPMDA(3). Se puede usar más de una opción -K.
-l, --sufijo
Imprime los últimos 7 caracteres de un nombre de host en resúmenes que involucran más de un host (cuando se ha especificado más de una opción -h en la línea de comandos).
-L, --PMDA-local
Usar un contexto local para recopilar métricas de PMDA DSO en el host local sin PMCD. Ver también -K.
-n archivopmns, --espacio-nombres=archivopmns
Cargar un Espacio de Nombres de Métricas de Rendimiento (PMNS(5)) alternativo del archivo archivopmns.
-O origen, --origen=origen
Al informar métricas archivadas, comenzar a informar en origen dentro de la ventana de tiempo (ver -S y -T). Consulte PCPIntro(1) para una descripción completa de la sintaxis de origen.
-p puerto, --puertogui=puerto
Adjuntar pmstat a una instancia de proceso de control de tiempo pmtime(1) existente a través del canal IPC identificado por el argumento puerto. Esta opción normalmente solo es utilizada por otras herramientas, p.ej. pmchart(1), cuando lanzan pmstat con control de tiempo sincronizado.
-P, --pausar
Pausar entre actualizaciones para la reproducción de archivos.
-s muestras, --muestras=muestras
La opción muestras define el número de muestras a recuperar y reportar. Si muestras es 0 o -s no se especifica, pmstat muestreará y reportará continuamente; este es el comportamiento predeterminado.
-S horainicio, --inicio=horainicio
Al informar métricas archivadas, el informe se restringirá a aquellos registros registrados en o después de horainicio. Consulte PCPIntro(1) para una descripción completa de la sintaxis de horainicio.
-t intervalo, --intervalo=intervalo
Establecer el intervalo de reporte a algo distinto de los 5 segundos predeterminados. El argumento intervalo sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos).
-T horafin, --fin=horafin
Al informar métricas archivadas, el informe se restringirá a aquellos registros registrados antes o en horafin.
-V, --version
Mostrar el número de versión y salir.

OPTIONS

-x, --xcpu
La opción de métricas extendidas de CPU, hace que se informen tres métricas adicionales de CPU, a saber, espera de E/S ("wa"), tiempo de robo de virtualización ("st") y tiempo de invitado virtual ("gu").
-z, --hostzone
Cambia la zona horaria de reporte a la zona horaria local en el host que es la fuente de las métricas de rendimiento, según se identifique a través de las opciones -h o -a.
-Z timezone, --timezone=timezone
Por defecto, pmtime reporta la hora del día según la zona horaria local en el sistema donde se ejecuta pmstat. La opción -Z cambia la zona horaria a timezone en el formato de la variable de entorno TZ, como se describe en environ(7).
-?, --help
Muestra el mensaje de uso y sale.

SALIDA

La salida de pmstat se dirige a la salida estándar, y las columnas en el reporte se interpretan de la siguiente manera:

loadavg
El promedio de carga de 1 minuto.
memory
La columna swpd indica el espacio de intercambio promedio utilizado durante el intervalo, en Kbytes. La columna free indica la memoria libre promedio durante el intervalo, en Kbytes. La columna buff indica la memoria de búfer promedio en uso durante el intervalo, en Kbytes. La columna cache indica la memoria caché promedio en uso durante el intervalo, en Kbytes.

Si los valores se vuelven grandes, se reportan como Mbytes (sufijo m) o Gbytes (sufijo g).

swap
Las métricas en esta área de la instrumentación del kernel son de valor variable. Intentamos reportar el número promedio de páginas que se intercambian hacia adentro (pi) y hacia afuera (po) por segundo durante el intervalo. Si las métricas de intercambio de páginas correspondientes no están disponibles, reportamos la tasa promedio por segundo de operaciones de intercambio hacia adentro (si) y hacia afuera (so) durante el intervalo. Es normal que los valores "hacia adentro" no sean cero, pero el sistema está sufriendo estrés de memoria si los valores "hacia afuera" no son cero durante un período extendido.

Si los valores se vuelven grandes, se reportan como miles de operaciones por segundo (sufijo K) o millones de operaciones por segundo (sufijo M).

io
Las columnas bi y bo indican la tasa promedio por segundo de operaciones de entrada de bloques y salida de bloques (respectivamente) durante el intervalo. A menos que todos los sistemas de archivos tengan un tamaño de bloque de 1 Kbyte, estas tasas no indican directamente Kbytes transferidos.

Si los valores se vuelven grandes, se reportan como miles de operaciones por segundo (sufijo K) o millones de operaciones por segundo (sufijo M).

system
Tasa de interrupciones (in) y tasa de cambios de contexto (cs). Las tasas se expresan como operaciones promedio por segundo durante el intervalo. Tenga en cuenta que la tasa de interrupciones es normalmente al menos HZ (la tasa de interrupciones del reloj, generalmente 100) interrupciones por segundo.

Si los valores se vuelven grandes, se reportan como miles de operaciones por segundo (sufijo K) o millones de operaciones por segundo (sufijo M).

cpu
Porcentaje de tiempo de CPU dedicado a ejecutar código de usuario y "usuario agradable" (us), código de procesamiento del sistema e interrupciones (sy), bucle inactivo (id).

Si algún valor para las métricas de rendimiento asociadas no está disponible, el valor aparece como "``?''" en la salida.

ARCHIVOS

$PCP_VAR_DIR/pmns/*
archivos de especificación de PMNS por defecto

pmlogger(1) configuración para crear un archivo adecuado para reproducción con pmstat

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para ver las variables de entorno que afectan a las herramientas de PCP, consulte pmGetOptions(3).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a solucionar problemas, aunque la información a veces es críptica y está destinada principalmente a orientar a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.
