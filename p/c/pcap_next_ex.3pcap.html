NOMBRE

pcap_next_ex, pcap_next - leer el siguiente paquete de un pcap_t

SINOPSIS

#include <pcap/pcap.h>
int pcap_next_ex(pcap_t *p, struct pcap_pkthdr **pkt_header,
    const u_char **pkt_data);
const u_char *pcap_next(pcap_t *p, struct pcap_pkthdr *h);

DESCRIPCIÓN

pcap_next_ex() lee el siguiente paquete y devuelve una indicación de éxito/fallo. Si el paquete se leyó sin problemas, el puntero apuntado por el argumento pkt_header se establece para apuntar a la estructura pcap_pkthdr del paquete, y el puntero apuntado por el argumento pkt_data se establece para apuntar a los datos del paquete. El llamador no debe liberar la struct pcap_pkthdr ni los datos del paquete, y no se garantiza que sean válidos después de la próxima llamada a pcap_next_ex(), pcap_next(), pcap_loop(3PCAP) o pcap_dispatch(3PCAP); si el código necesita que permanezcan válidos, debe hacer una copia de ellos.

pcap_next() lee el siguiente paquete (llamando a pcap_dispatch() con un cnt de 1) y devuelve un puntero u_char a los datos de ese paquete. El llamador no debe liberar los datos del paquete, y no se garantiza que sean válidos después de la próxima llamada a pcap_next_ex(), pcap_next(), pcap_loop() o pcap_dispatch(); si el código necesita que permanezcan válidos, debe hacer una copia de ellos. La estructura pcap_pkthdr apuntada por h se rellena con los valores apropiados para el paquete.

Los bytes de datos del paquete comienzan con una cabecera de capa de enlace. El formato de la cabecera de capa de enlace se indica mediante el valor de retorno de la rutina pcap_datalink(3PCAP) cuando se le pasa el valor pcap_t también pasado a pcap_loop() o pcap_dispatch(). https://www.tcpdump.org/linktypes.html enumera los valores que puede devolver pcap_datalink() y describe los formatos de paquete que corresponden a esos valores. El valor que devuelve será válido para todos los paquetes recibidos a menos que y hasta que se llame a pcap_set_datalink(3PCAP); después de una llamada exitosa a pcap_set_datalink(), todos los paquetes subsiguientes tendrán una cabecera de capa de enlace del tipo especificado por el valor del tipo de cabecera de capa de enlace pasado a pcap_set_datalink().

NO suponga que los paquetes para una captura o archivo de guardado dado tendrán algún tipo de cabecera de capa de enlace, como DLT_EN10MB para Ethernet. Por ejemplo, el dispositivo "any" en Linux tendrá un tipo de cabecera de capa de enlace de DLT_LINUX_SLL o DLT_LINUX_SLL2, incluso si todos los dispositivos del sistema en el momento en que se abre el dispositivo "any" tienen algún otro tipo de capa de datos, como DLT_EN10MB para Ethernet.

VALOR DE RETORNO

pcap_next_ex() devuelve 1 si el paquete se leyó sin problemas, 0 si se están leyendo paquetes de una captura en vivo y el tiempo de espera del búfer del paquete expiró, PCAP_ERROR_BREAK si se están leyendo paquetes de un archivo de guardado y no hay más paquetes para leer del archivo de guardado, PCAP_ERROR_NOT_ACTIVATED si se llama en un manejador de captura que ha sido creado pero no activado, o PCAP_ERROR si ocurrió un error al leer el paquete. Si se devuelve PCAP_ERROR, se puede llamar a pcap_geterr(3PCAP) o pcap_perror(3PCAP) con p como argumento para obtener o mostrar el texto del error.

pcap_next() devuelve un puntero a los datos del paquete en caso de éxito, y devuelve NULL si ocurrió un error, o si no se leyeron paquetes de una captura en vivo (si, por ejemplo, se descartaron porque no pasaron el filtro de paquetes, o si, en plataformas que admiten un tiempo de espera del búfer de paquetes que comienza antes de que lleguen los paquetes, el tiempo de espera expira antes de que lleguen los paquetes, o si el descriptor de archivo del dispositivo de captura está en modo no bloqueante y no había paquetes disponibles para leer), o si no hay más paquetes disponibles en un archivo de guardado. Desafortunadamente, no hay forma de determinar si ocurrió un error o no.
