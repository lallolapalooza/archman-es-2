PCP2XLSX(1) Manual de Comandos Generales PCP2XLSX(1)

NOMBRE

pcp2xlsx - exportador de métricas de pcp a xlsx

SINOPSIS

pcp2xlsx [-5CGHILmrRvVz?] [-4 acción] [-a archivo] [-A alineación] [--archive-folio folio] [-b|-B escala-espacio] [-c config] [--container contenedor] [--daemonize] [-e derivado] [-f formato] [-F archivo_salida] [-h host] [-i instancias] [-K espec] [-O origen] [-P|-0 precisión] [-q|-Q escala-conteo] [-s muestras] [-S hora_inicio] [-t intervalo] [-T hora_fin] [-y|-Y escala-tiempo] [-Z zona_horaria] espec_metrica [...]

DESCRIPCIÓN

pcp2xlsx es una herramienta personalizable de exportación de métricas de rendimiento de PCP a XLSX. Cualquier métrica de rendimiento disponible, en vivo o archivada, del sistema y/o aplicación, puede ser seleccionada para exportar usando argumentos de línea de comandos o un archivo de configuración.

pcp2xlsx es un pariente cercano de pmrep(1). Consulte pmrep(1) para la descripción de espec_metrica aceptada en la línea de comandos de pcp2xlsx. Consulte pmrep.conf(5) para la descripción de la sintaxis del archivo de configuración pcp2xlsx.conf. Esta página describe las opciones específicas de pcp2xlsx y las diferencias del archivo de configuración con pmrep.conf(5). pmrep(1) también enumera algunos ejemplos de uso de los cuales la mayoría son aplicables a pcp2xlsx también.

Solo se admiten las opciones de línea de comandos enumeradas en esta página; otras opciones disponibles para pmrep(1) no son soportadas.

Las opciones a través de variables de entorno (ver pmGetOptions(3)) anulan los valores predeterminados incorporados correspondientes (si los hay). Las opciones del archivo de configuración anulan las variables de entorno correspondientes (si las hay). Las opciones de línea de comandos anulan las opciones del archivo de configuración correspondientes (si las hay).

ARCHIVO DE CONFIGURACIÓN

pcp2xlsx utiliza un archivo de configuración con sintaxis descrita en pmrep.conf(5). Las siguientes opciones son comunes con pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. El resto de las opciones de pmrep.conf se reconocen pero se ignoran por compatibilidad.

Opciones específicas de pcp2xlsx

Ninguna.

OPCIONES

Las opciones de línea de comandos disponibles son:

-0 precisión, --precision-force=precisión
Similar a -P pero esta opción anulará las especificaciones por métrica.
-4 acción, --names-change=acción
Especifica qué acción tomar al recibir un evento de cambio de nombres de métricas durante el muestreo. Estos eventos ocurren cuando un PMDA descubre nuevas métricas poco después de iniciarse, e informa a las herramientas cliente en ejecución como pcp2xlsx. Los valores válidos para acción son update (actualizar métricas que se están muestreando), ignore (no hacer nada - el comportamiento predeterminado) y abort (salir del programa si ocurre dicho evento).
-5, --ignore-unknown
Ignorar silenciosamente cualquier nombre de métrica que no pueda ser resuelto. Al menos una métrica debe ser encontrada para que la herramienta pueda iniciarse.
-a archivo, --archive=archivo
Los valores de las métricas de rendimiento se obtienen del conjunto de archivos de archivo de Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos.
-A alineación, --align=alineación
Forzar que la muestra inicial esté alineada en el límite de una unidad de tiempo natural alineación. Consulte PCPIntro(1) para una descripción completa de la sintaxis para alineación.
--archive-folio=folio
Leer archivos de origen de métricas de PCP del folio de archivos de PCP creado por herramientas como pmchart(1) o, con menos frecuencia, manualmente con mkaf(1).
-b escala, --space-scale=escala
Unidad/escala para métricas de espacio (bytes), los valores posibles incluyen bytes, Kbytes, KB, Mbytes, MB, etcétera. Esta opción no anulará las posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-B escala, --space-scale-force=escala
Similar a -b, pero esta opción anulará las especificaciones por métrica.
-c config, --config=config
Especificar el archivo o directorio de config a usar. En caso de que config sea un directorio, se incluirán todos los archivos que terminen en .conf. El valor predeterminado es el primero que se encuentre de: ./pcp2xlsx.conf, $HOME/.pcp2xlsx.conf, $HOME/pcp/pcp2xlsx.conf, y $PCP_SYSCONF_DIR/pcp2xlsx.conf. Para más detalles, consulte la sección anterior y pmrep.conf(5).
--container=contenedor
Obtener métricas de rendimiento del contenedor especificado, ya sea local o remoto (ver -h).
-C, --check
Salir antes de reportar cualquier valor, pero después de parsear la configuración y las métricas, e imprimir posibles encabezados.
--daemonize
Daemonizar al inicio.
-e derivado, --derived=derivado
Especificar métricas de rendimiento derivadas. Si derivado comienza con una barra (``/'') o con un punto (``.'') se interpretará como un archivo de configuración de métricas derivadas de PCP, de lo contrario se interpretará como expresiones de métricas derivadas separadas por comas o punto y coma. Para una descripción completa de las métricas derivadas y los archivos de configuración de métricas derivadas de PCP, consulte pmLoadDerivedConfig(3) y pmRegisterDerived(3). Alternativamente, usar la sintaxis de configuración de pmrep.conf(5) permite definir métricas derivadas como parte de los conjuntos de métricas.

En caso de problemas con las métricas derivadas, revise detalladamente las páginas de manual mencionadas anteriormente y asegúrese de que todas las métricas requeridas estén disponibles, especialmente al usar archivos. Use -Dderive para ver información de depuración adicional sobre el parseo de métricas derivadas.

-G, --no-globals
No incluir métricas globales en el reporte (ver pmrep.conf(5)).
-f formato, --timestamp-format=formato
Usar la cadena de formato para formatear la marca de tiempo. El formato se usará con el método strftime de datetime de Python, que es mayormente el mismo que el descrito en strftime(3). El valor predeterminado es %Y-%m-%d %H:%M:%S.
-F archivo_salida, --output-file=archivo_salida
Especificar el archivo de salida archivo_salida.
-h host, --host=host
Obtener métricas de rendimiento de pmcd(1) en el host especificado.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

>host, en lugar del localhost predeterminado.
-H, --no-header
No imprima ningún encabezado.
-i instancias, --instances=instancias
Recuperar e informar solo de las instancias de métricas especificadas de las instancias de métricas presentes actualmente. Por defecto, se informan todas las instancias actuales.

Consulte pmrep(1) para una descripción completa de esta opción.

-I, --ignore-incompat
Ignorar métricas incompatibles. Por defecto, las métricas incompatibles (es decir, cuyo tipo no es compatible o no se pueden escalar según lo solicitado) harán que pcp2xlsx termine con un mensaje de error. Con esta opción, todas las métricas incompatibles se omiten silenciosamente de la generación de informes. Esto puede ser especialmente útil al solicitar nodos no finales del árbol PMNS para la generación de informes.
-K spec, --spec-local=spec
Al obtener métricas de un contexto local (ver -L), la opción -K puede usarse para controlar las PMDA DSO que deben hacerse accesibles. El argumento spec se ajusta a la sintaxis descrita en pmSpecLocalPMDA(3). Se pueden usar varias opciones -K.
-L, --local-PMDA
Usar un contexto local para recopilar métricas de PMDA DSO en el host local sin PMCD. Ver también -K.
-m, --include-labels
Incluir etiquetas de métricas PCP en la salida.
-O origin, --origin=origin
Al informar métricas archivadas, comience a informar en origin dentro de la ventana de tiempo (ver -S y -T). Consulte PCPIntro(1) para una descripción completa de la sintaxis de origin.
-P precision, --precision=precision
Use precision para valores de salida numéricos no enteros. El valor predeterminado es usar 3 lugares decimales (cuando sea aplicable). Esta opción no anulará las especificaciones posibles por métrica.
-q scale, --count-scale=scale
Unidad/escala para métricas de recuento, los valores posibles incluyen count x 10^-1, count, count x 10, count x 10^2, y así sucesivamente de 10^-8 a 10^7. (Estos valores son actualmente sensibles a los espacios.) Esta opción no anulará las especificaciones posibles por métrica. Ver también pmParseUnitsStr(3).
-Q scale, --count-scale-force=scale
Similar a -q pero esta opción sí anulará las especificaciones por métrica.
-r, --raw
Emitir valores de métricas en bruto, no convertir contadores acumulativos en tasas. Esta opción sí anulará las especificaciones posibles por métrica.
-R, --raw-prefer
Similar a -r pero esta opción no anulará las especificaciones por métrica.
-s samples, --samples=samples
El argumento samples define el número de muestras a recuperar e informar. Si samples es 0 o -s no se especifica, pcp2xlsx tomará muestras e informará continuamente (en modo de tiempo real) o hasta el final del conjunto de archivos PCP (en modo de archivo). Ver también -T.
-S starttime, --start=starttime
Al informar métricas archivadas, el informe se limitará a aquellos registros registrados en o después de starttime. Consulte PCPIntro(1) para una descripción completa de la sintaxis de starttime.
-t interval, --interval=interval
Establezca el intervalo de generación de informes a algo distinto del valor predeterminado de 1 segundo. El argumento interval sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos). Ver también la opción -T.
-T endtime, --finish=endtime
Al informar métricas archivadas, el informe se limitará a aquellos registros registrados antes o en endtime. Consulte PCPIntro(1) para una descripción completa de la sintaxis de endtime.

Cuando se usa para definir el tiempo de ejecución antes de que pcp2xlsx salga, si no se proporciona samples (ver -s), entonces el número de muestras informadas depende de interval (ver -t). Si se proporciona samples, entonces interval se ajustará para permitir la generación de informes de samples durante el tiempo de ejecución. En caso de que se proporcionen -T, -s y -t, endtime determinará el tiempo real que se ejecutará pcp2xlsx.

-v, --omit-flat
Informar solo métricas de conjunto con instancias (por ejemplo, disk.dev.read) y omitir métricas "planas" de un solo valor sin instancias (por ejemplo, kernel.all.sysfork). Ver -i e -I.
-V, --version
Mostrar el número de versión y salir.
-y scale, --time-scale=scale
Unidad/escala para métricas de tiempo, los valores posibles incluyen nanosec, ns, microsec, us, millisec, ms, y así sucesivamente hasta hour, hr. Esta opción no anulará las especificaciones posibles por métrica. Ver también pmParseUnitsStr(3).
-Y scale, --time-scale-force=scale
Similar a -y pero esta opción sí anulará las especificaciones por métrica.
-z, --hostzone
Usar la zona horaria local del host que es la fuente de las métricas de rendimiento, según lo identificado por las opciones -h o -a. El valor predeterminado es usar la zona horaria del host local.
-Z timezone, --timezone=timezone
Usar timezone para la fecha y hora. Timezone está en el formato de la variable de entorno TZ como se describe en environ(7). Tenga en cuenta que al incluir una cadena de zona horaria en la salida, se utilizan los desplazamientos UTC al estilo ISO 8601 (por lo que algo como -Z EST+5 se convertirá en UTC-5).
-?, --help
Mostrar mensaje de uso y salir.

PCP ENVIRONMENT

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF se puede usar para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para las variables de entorno que afectan a las herramientas de PCP, consulte pmGetOptions(3).
