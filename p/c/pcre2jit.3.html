NOMBRE

PCRE2 - Expresiones regulares compatibles con Perl (API revisada)

SOPORTE DE COMPILADOR JUST-IN-TIME DE PCRE2

La compilación just-in-time (JIT) es una optimización de gran impacto que puede acelerar enormemente la coincidencia de patrones. Sin embargo, tiene el costo de un procesamiento adicional antes de realizar la coincidencia, por lo que es de mayor beneficio cuando el mismo patrón se va a hacer coincidir muchas veces. Esto no significa necesariamente muchas llamadas a una función de coincidencia; si el patrón no está anclado, los intentos de coincidencia pueden ocurrir muchas veces en varias posiciones del sujeto, incluso para una sola llamada. Por lo tanto, si la cadena sujeto es muy larga, aún puede valer la pena usar JIT incluso para coincidencias únicas. El soporte JIT está disponible para todas las bibliotecas PCRE2 de 8, 16 y 32 bits.

El soporte JIT se aplica solo a la función de coincidencia tradicional compatible con Perl. No se aplica cuando se utiliza la función de coincidencia DFA. El código para el soporte JIT fue escrito por Zoltan Herczeg.

DISPONIBILIDAD DE SOPORTE JIT

El soporte JIT es una característica opcional de PCRE2. La opción "configure" --enable-jit (o una opción CMake equivalente) debe establecerse cuando se compila PCRE2 si desea utilizar JIT. El soporte está limitado a las siguientes plataformas de hardware:


ARM de 32 bits (v7 y Thumb2)
ARM de 64 bits
IBM s390x de 64 bits
Intel x86 de 32 y 64 bits
LoongArch de 64 bits
MIPS de 32 y 64 bits
Power PC de 32 y 64 bits
RISC-V de 32 y 64 bits

Si se establece --enable-jit en una plataforma no compatible, la compilación falla.

Un programa cliente puede saber si se ha compilado el soporte JIT llamando a pcre2_config() con la opción PCRE2_CONFIG_JIT. El resultado es uno si PCRE2 se compiló con soporte JIT y cero en caso contrario. Sin embargo, tener el código JIT disponible no garantiza que se utilizará para ninguna coincidencia particular. Una razón para esto es que hay una serie de opciones y elementos de patrón que no son compatibles con JIT (ver abajo). Otra razón es que en algunos entornos JIT no puede obtener memoria ejecutable en la que construir su código compilado. La única garantía de pcre2_config() es que si devuelve cero, JIT definitivamente *no* se utilizará.

A partir de la versión 10.45, existe una forma más informativa de probar el soporte JIT. Si se llama a pcre2_compile_jit() con la única opción PCRE2_JIT_TEST_ALLOC, devuelve cero si JIT está disponible y tiene un asignador que funciona. De lo contrario, devuelve PCRE2_ERROR_NOMEMORY si JIT está disponible pero no puede asignar memoria ejecutable, o PCRE2_ERROR_JIT_UNSUPPORTED si el soporte JIT no se compiló. El argumento del código se ignora, por lo que puede ser un valor NULL.

Un programa simple no necesita verificar la disponibilidad para usar JIT cuando sea posible. La API está implementada de manera que recurre al código interpretativo si JIT no está disponible o no se puede usar para una coincidencia dada. Para programas que necesitan el mejor rendimiento posible, existe una API de "vía rápida" específica de JIT.

USO SIMPLE DE JIT

Para utilizar el soporte JIT de la manera más sencilla, todo lo que tiene que hacer es llamar a pcre2_jit_compile() después de compilar con éxito un patrón con pcre2_compile(). Esta función tiene dos argumentos: el primero es el puntero al patrón compilado que fue devuelto por pcre2_compile(), y el segundo son cero o más de los siguientes bits de opción: PCRE2_JIT_COMPLETE, PCRE2_JIT_PARTIAL_HARD o PCRE2_JIT_PARTIAL_SOFT.

Si el soporte JIT no está disponible, una llamada a pcre2_jit_compile() no hace nada y devuelve PCRE2_ERROR_JIT_BADOPTION. De lo contrario, el patrón compilado se pasa al compilador JIT, que lo convierte en código máquina que se ejecuta mucho más rápido que el código interpretativo normal, pero produce exactamente los mismos resultados. El valor devuelto por pcre2_jit_compile() es cero en caso de éxito o un código de error negativo.

Existe un límite al tamaño del patrón que JIT soporta, impuesto por el tamaño de la pila de máquina que utiliza. Las reglas exactas no están documentadas porque pueden cambiar en cualquier momento, en particular, cuando se introducen nuevas optimizaciones. Si un patrón es demasiado grande, una llamada a pcre2_jit_compile() devuelve PCRE2_ERROR_NOMEMORY.

PCRE2_JIT_COMPLETE solicita al compilador JIT que genere código para coincidencias completas. Si desea ejecutar coincidencias parciales utilizando las opciones PCRE2_PARTIAL_HARD o PCRE2_PARTIAL_SOFT de pcre2_match(), debe establecer una o ambas de las otras opciones, además de, o en lugar de, PCRE2_JIT_COMPLETE. El compilador JIT genera diferente código optimizado para cada uno de los tres modos (normal, parcial suave, parcial duro). Cuando se llama a pcre2_match(), se ejecuta el código apropiado si está disponible. De lo contrario, el patrón se compara utilizando código interpretativo.

Puede llamar a pcre2_jit_compile() varias veces para el mismo patrón compilado. No hace nada si previamente ha compilado código para alguno de los bits de opción. Por ejemplo, puede llamarla una vez con PCRE2_JIT_COMPLETE y (quizás más tarde, cuando descubra que necesita coincidencia parcial) de nuevo con PCRE2_JIT_COMPLETE y PCRE2_JIT_PARTIAL_HARD. Esta vez ignorará PCRE2_JIT_COMPLETE y solo compilará código para la coincidencia parcial. Si se llama a pcre2_jit_compile() sin ningún bit de opción establecido, devuelve cero inmediatamente. Esta es una forma alternativa de probar si el soporte JIT se ha compilado.

Actualmente, no es posible liberar código compilado por JIT, excepto cuando todo el patrón compilado se libera llamando a pcre2_code_free().

En algunas circunstancias, es posible que necesite llamar a funciones adicionales. Estas se describen en la sección titulada "Control de la pila JIT" más abajo.

Existen algunas opciones de pcre2_match() que no son compatibles con JIT, y también hay algunos elementos de patrón que JIT no puede manejar. Los detalles se proporcionan a continuación. En ambos casos, la coincidencia recurre automáticamente al código interpretativo. Si desea saber si JIT se utilizó realmente para una coincidencia particular, debe organizar que se configure una función de retrollamada JIT como se describe en la sección titulada "Control de la pila JIT" más abajo, incluso si no necesita proporcionar una pila JIT no predeterminada. Dicha función de retrollamada se llama cada vez que el código JIT está a punto de ejecutarse. Si las opciones en tiempo de coincidencia no son adecuadas para la ejecución JIT, la función de retrollamada no se obedece.

Si el compilador JIT encuentra un elemento no compatible, no se genera ningún dato JIT. Puede averiguar si la compilación JIT fue exitosa para un patrón compilado llamando a pcre2_pattern_info() con la opción PCRE2_INFO_JITSIZE. Un resultado distinto de cero significa que la compilación JIT fue exitosa. Un resultado de 0 significa que el soporte JIT no está disponible, o el patrón no fue procesado por pcre2_jit_compile(), o el compilador JIT no pudo manejar el patrón. Sin embargo, una compilación JIT exitosa no garantiza el uso de JIT en tiempo de coincidencia, ya que hay algunas opciones en tiempo de coincidencia que no son compatibles con JIT.

COINCIDENCIA DE SUJETOS QUE CONTIENEN UTF INVÁLIDO

Cuando un patrón se compila con la opción PCRE2_UTF, normalmente se espera que las cadenas sujeto sean una secuencia válida de unidades de código UTF. Por defecto, esto se verifica al inicio de la coincidencia y se genera un error si se detecta UTF inválido. La opción PCRE2_NO_UTF_CHECK se puede pasar a pcre2_match() para omitir la verificación (para mejorar el rendimiento) si está seguro de que una cadena sujeto es válida. Si se utiliza esta opción con una cadena inválida, el resultado no está definido. El programa que llama puede fallar, entrar en bucle o comportarse de otra manera inadecuada.

Sin embargo, hay disponible una forma de ejecutar coincidencias en cadenas que pueden contener secuencias UTF inválidas. Llamar a pcre2_compile() con la opción PCRE2_MATCH_INVALID_UTF tiene dos efectos: le dice al intérprete en pcre2_match() que admita UTF inválido y, si posteriormente se llama a pcre2_jit_compile(), el código JIT compilado también admite UTF inválido. Los detalles sobre cómo funciona este soporte, tanto en el caso JIT como en el interpretativo, se proporcionan en la documentación de pcre2unicode.

También existe una opción obsoleta para pcre2_jit_compile() llamada PCRE2_JIT_INVALID_UTF, que actualmente solo existe por compatibilidad hacia atrás. Está suplantada por la opción PCRE2_MATCH_INVALID_UTF de pcre2_compile() y ya no debe usarse. Puede eliminarse en el futuro.

OPCIONES Y ELEMENTOS DE PATRÓN NO SOPORTADOS

La siguiente lista describe las características que no son compatibles con JIT. Si se encuentra alguna de ellas, la coincidencia recursiva al código interpretativo.

Opciones depcre2_compile() que no son compatibles con JIT:


PCRE2_EXTENDED
PCRE2_ALT_BSUX
PCRE2_ANCHORED
PCRE2_CASELESS
PCRE2_DOLLAR_ENDONLY
PCRE2_DOTALL
PCRE2_DUPEND
PCRE2_FIRSTLINE
PCRE2_FUNC_CALLOUT
PCRE2_IGNORECASE
PCRE2_IMPLICIT_GV
PCRE2_JIT_INVALID_UTF (obsoleto, ver arriba)
PCRE2_NEWLINE_ANYCRLF
PC2_NEWLINE_CR
PCRE2_NEWLINE_LF
PCRE2_NO_AUTO_CAPTURE
PCRE2_NO_DOTSTAR_IS_NEWLINE
PCRE2_NO_START_OPT
PCRE2_OFFSET_LIMIT
PCRE2_PARTIAL (esto es ignorado; ver abajo)
PCRE2_PCRE10_COMPAT
PCRE2_SINGLELINE
PCRE2_STRICT
PCRE2_UTF
PCRE2_USE_OFFSET_LIMIT

Opciones depcre2_match() que no son compatibles con JIT:


PCRE2_ANCHORED
PCRE2_COPY_MATCH_RECURSION_LEVEL
PCRE2_NO_BACKTRACK
PCRE2_PARTIAL_HARD
PCRE2_PARTIAL_SOFT
PCRE2_SUBSTITUTE_GLOBAL
PCRE2_SUBSTITUTE_OVERWRITE
PCRE2_SUBSTITUTE_UNFINDABLE

Los programas que utilizan JIT deben tener cuidado al usar el anclaje porque las dos formas de anclaje (implícito y explícito) que se utilizan para permitir que los patrones que no comienzan con un ancla coincidan desde el principio de la cadena sujeto son ignoradas por el código JIT.

Cuando se especifica PCRE2_PARTIAL para pcre2_compile(), la coincidencia podría fallar porque el patrón no comienza al principio de la cadena sujeto. Para poder anclar el patrón, JIT realiza una verificación oculta si el patrón no comienza con un ancla, añadiendo internamente el comportamiento de PCRE2_ANCHORED. Esto significa que si el patrón no es una coincidencia completa desde el principio de la cadena, no se realizará ninguna coincidencia. El comportamiento de JIT se elimina si el patrón comienza con un ancla explícita como `^`.

Para permitir que los patrones que no comienzan con un ancla coincidan desde el principio de la cadena, JIT intenta añadir implícitamente el comportamiento de PCRE2_ANCHORED. Sin embargo, esto puede fallar si el patrón comienza con `\K` o si el patrón es un patrón que es imposible que coincida al principio de la cadena, como `(?

Elementos de patrón no compatibles con JIT:


Recursión (p. ej., `(?R)`)
Referencia a grupo de subexpresiones nombres (p. ej., `(?P<nombre>)`).
Subexpresiones con nombre que se refieren a otras subexpresiones (p. ej., `(?<name1>(?<name2>a))`).
Subexpresiones que contienen llamadas recursivas (p. ej., `(?R)`) o referencias a sí mismas.
Subexpresiones que solo hacen coincidir en una posición, como `(a*)`.

Los elementos de patrón que son compatibles con JIT son la mayoría de las características de Perl-compatible regular expressions. La implementación de JIT se centra en las optimizaciones de velocidad más comunes y beneficiosas.

CONTROL DE LA PILAS JIT

El compilador JIT puede necesitar una pila más grande que el código interpretativo. Por defecto, se asigna un tamaño de pila de 100.000 bytes. Este tamaño se puede ajustar llamando a pcre2_jit_stack_assign() en la fase de configuración (antes de llamar a pcre2_compile()), o llamando a pcre2_match() con la opción PCRE2_MATCH_USING_JIT_STACK. Para hacer esto, el programa cliente debe configurar un puntero a un tipo pcre2_jit_stack. El tamaño de pila se puede especificar en bytes.

La función pcre2_jit_stack_assign() devuelve un puntero a la nueva pila JIT. El llamador es responsable de liberarla llamando a pcre2_jit_stack_free() cuando ya no sea necesaria.

Una función de retrollamada opcional se puede registrar para ser llamada justo antes de que el código JIT sea ejecutado. Esto se hace configurando el campo callout de la estructura pcre2_jit_callback_array. El puntero a esta estructura se pasa en el argumento callback_array a pcre2_jit_stack_assign().

La función de retrollamada recibe tres argumentos: un puntero al patrón compilado, un puntero a la pila JIT y un puntero a una estructura de información de retrollamada. Esta estructura está definida por el tipo pcre2_jit_match_data y contiene información sobre el estado actual de la coincidencia, incluido el número de llamadas a la retrollamada, el número de llamadas a la función JIT y la posición actual en la cadena sujeto. La función de retrollamada puede devolver un valor para indicar si se debe continuar la coincidencia. Si devuelve 0, la coincidencia continúa. Si devuelve un valor distinto de cero, la coincidencia se detiene y se devuelve un error.

Este mecanismo de retrollamada se puede utilizar para rastrear la ejecución del código JIT, por ejemplo, para verificar si JIT se utilizó realmente para una coincidencia particular.

Existe una tercera forma de configurar la pila JIT. Si no se llama a pcre2_jit_stack_assign(), pero el programa cliente pasa un puntero a una pila JIT (creada y liberada por el programa cliente) en el campo user_jit_stack de la estructura pcre2_match_context, esta pila se utilizará. El uso de una pila JIT definida por el usuario de esta manera puede ser más eficiente ya que evita la asignación de memoria adicional.

DIRECTIVA IMPORTANTE SOBRE LA SEGURIDAD

El uso de JIT permite que el código se genere y ejecute en tiempo de ejecución. Aunque PCRE2 realiza comprobaciones exhaustivas para garantizar que el código generado sea seguro y no pueda dañar el sistema, los usuarios deben ser conscientes de que este tipo de funcionalidad puede tener implicaciones de seguridad. Si la entrada del usuario se utiliza para construir un patrón que se compila con JIT, es posible que un atacante pueda inyectar código malicioso. Por lo tanto, se recomienda encarecidamente que el código que utiliza JIT siempre valide cuidadosamente la entrada del usuario para prevenir tales ataques.

EJEMPLO

A continuación se muestra un ejemplo de cómo utilizar la función JIT para compilar un patrón y luego ejecutar una coincidencia:

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <pcre2.h>

int main() {
    pcre2_code *re;
    PCRE2_SPANCHARED_SIZE_T erroroffset;
    int errorcode;
    PCRE2_SPANCHARED_SIZE_Tjit_size;
    int jit_options = 0;
    const char *pattern = "([0-9]+)-([0-9]+)";
    const char *subject = "Product ID: 123-456";
    pcre2_match_data *match_data;
    PCRE2_SPANCHARED_SIZE_T subject_length = strlen(subject);
    PCRE2_SPANCHARED_SIZE_T length;
    PCRE2_SPANCHARED_SIZE_T *ovec;
    int rc;
    uint32_t options = PCRE2_UTF | PCRE2_ALT_BSUX;

    /* Compile the pattern */
    re = pcre2_compile(pattern, PCRE2_ZERO_TERMINATED, options,
        &errorcode, &erroroffset, NULL);

    if (re == NULL) {
        fprintf(stderr, "pcre2_compile failed at offset %d: errorcode %d\n",
            (int)erroroffset, errorcode);
        return 1;
    }

    /* Try to compile the pattern with JIT support */
    rc = pcre2_jit_compile(re, jit_options);

    if (rc == PCRE2_ERROR_JIT_BADOPTION) {
        printf("JIT compilation is not enabled or not supported.\n");
    } else if (rc < 0) {
        fprintf(stderr, "pcre2_jit_compile failed: %d\n", rc);
        pcre2_code_free(re);
        return 1;
    } else {
        printf("JIT compilation succeeded.\n");
    }

    /* Get JIT size to check if JIT compilation was successful */
    if (pcre2_pattern_info(re, PCRE2_INFO_JITSIZE, &jit_size, sizeof(jit_size)) == 0) {
        if (jit_size == 0) {
            printf("JIT compilation did not produce any code (pattern might be unsupported).\n");
        } else {
            printf("JIT code size: %zu bytes\n", (size_t)jit_size);
        }
    }

    /* Allocate match data */
    match_data = pcre2_match_data_create(1, NULL);
    if (match_data == NULL) {
        fprintf(stderr, "pcre2_match_data_create failed\n");
        pcre2_code_free(re);
        return 1;
    }

    /* Perform the match */
    rc = pcre2_match(re, subject, subject_length, 0, 0, match_data, NULL);

    if (rc < 0) {
        fprintf(stderr, "pcre2_match failed: %d\n", rc);
        pcre2_match_data_free(match_data);
        pcre2_code_free(re);
        return 1;
    }

    /* Get the offsets of the captured substrings */
    ovec = pcre2_get_ovector_pointer(match_data);
    length = ovec[1] - ovec[0];
    printf("Match found: starting at %zu, length %zu\n", (size_t)ovec[0], (size_t)length);

    /* Free match data and compiled pattern */
    pcre2_match_data_free(match_data);
    pcre2_code_free(re);

    return 0;
}

OPCIONES Y ELEMENTOS DE PATRÓN NO SOPORTADOS

Las opciones de pcre2_match() que se soportan para la coincidencia JIT son PCRE2_COPY_MATCHED_SUBJECT, PCRE2_NOTBOL, PCRE2_NOTEOL, PCRE2_NOTEMPTY, PCRE2_NOTEMPTY_ATSTART, PCRE2_NO_UTF_CHECK, PCRE2_PARTIAL_HARD y PCRE2_PARTIAL_SOFT. Las opciones PCRE2_ANCHORED y PCRE2_ENDANCHORED no se soportan en el momento de la coincidencia.

Si la opción PCRE2_NO_JIT se pasa a pcre2_match(), deshabilita el uso de JIT, forzando la coincidencia por el código del intérprete.

Los únicos elementos de patrón no soportados son \C (coincidir una sola unidad de datos) cuando se ejecuta en un modo UTF, y una llamada de extracción inmediatamente antes de una condición de aserción en un grupo condicional.

VALORES DE RETORNO DE COINCIDENCIAS JIT

Cuando un patrón coincide utilizando JIT, los valores de retorno son los mismos que los proporcionados por el código interpretativo de pcre2_match(), con la adición de un nuevo código de error: PCRE2_ERROR_JIT_STACKLIMIT. Esto significa que la memoria utilizada para la pila JIT fue insuficiente. Consulte "Control de la pila JIT" a continuación para una discusión sobre el uso de la pila JIT.

El código de error PCRE2_ERROR_MATCHLIMIT es devuelto por el código JIT si la búsqueda de un árbol de patrones muy grande se prolonga demasiado, al igual que ocurre en la misma circunstancia cuando no se usa JIT, pero los detalles de lo que se cuenta exactamente no son los mismos. El código de error PCRE2_ERROR_DEPTHLIMIT nunca se devuelve cuando se utiliza la coincidencia JIT.

CONTROL DE LA PILA JIT

Cuando el código JIT compilado se ejecuta, necesita un bloque de memoria para usarlo como pila. Por defecto, utiliza 32KiB en la pila de la máquina. Sin embargo, algunos patrones grandes o complicados necesitan más que esto. El error PCRE2_ERROR_JIT_STACKLIMIT se da cuando no hay suficiente pila. Se proporcionan tres funciones para administrar bloques de memoria para usarlos como pilas JIT. Hay una discusión adicional sobre el uso de pilas JIT en la sección titulada "Preguntas frecuentes sobre pilas JIT" a continuación.

La función pcre2_jit_stack_create() crea una pila JIT. Sus argumentos son un tamaño inicial, un tamaño máximo y un contexto general (para funciones de asignación de memoria, o NULL para asignación de memoria estándar). Devuelve un puntero a una estructura opaca de tipo pcre2_jit_stack, o NULL si hay un error. La función pcre2_jit_stack_free() se utiliza para liberar una pila que ya no es necesaria. Si su argumento es NULL, esta función retorna inmediatamente, sin hacer nada. (Para los técnicamente inclinados: el espacio de direcciones se asigna mediante mmap o VirtualAlloc.) Un tamaño máximo de pila de 512KiB a 1MiB debería ser más que suficiente para cualquier patrón.

La función pcre2_jit_stack_assign() especifica qué pila debe usar el código JIT. Sus argumentos son los siguientes:


pcre2_match_context *mcontext
pcre2_jit_callback callback
void *data

El primer argumento es un puntero a un contexto de coincidencia. Cuando este se pasa posteriormente a una función de coincidencia, su información determina qué pila JIT se utiliza. Si este argumento es NULL, la función retorna inmediatamente, sin hacer nada. Hay tres casos para los valores de las otras dos opciones:


(1) Si callback es NULL y data es NULL, se utiliza un bloque interno de 32KiB
en la pila de la máquina. Este es el valor predeterminado cuando se crea un contexto de coincidencia.


(2) Si callback es NULL y data no es NULL, data debe ser
un puntero a una pila JIT válida, el resultado de llamar a
pcre2_jit_stack_create().


(3) Si callback no es NULL, debe apuntar a una función que se llama
con data como argumento al inicio de la coincidencia, para configurar
una pila JIT. Si el retorno de la función de devolución de llamada es NULL,
se utiliza la pila interna de 32KiB; de lo contrario, el valor de retorno
debe ser una pila JIT válida, el resultado de llamar a
pcre2_jit_stack_create().

Una función de devolución de llamada se obedece cada vez que el código JIT está a punto de ejecutarse; no se obedece cuando pcre2_match() se llama con opciones incompatibles para la coincidencia JIT. Por lo tanto, una función de devolución de llamada se puede utilizar para determinar si una operación de coincidencia fue ejecutada por JIT o por el intérprete.

Puede usar de forma segura la misma pila JIT para más de un patrón (ya sea asignándola directamente o mediante una devolución de llamada), siempre que los patrones coincidan secuencialmente en el mismo hilo. Actualmente, la única forma de configurar coincidencias no secuenciales en un hilo es usar llamadas de extracción: si una función de extracción inicia otra coincidencia, esa coincidencia debe usar una pila JIT diferente a la utilizada para la coincidencia (o coincidencias) actualmente suspendida.

En una aplicación multihilo, si no especifica una pila JIT, o si asigna o devuelve NULL de una devolución de llamada, eso es seguro para hilos, ya que cada hilo tiene su propia pila de máquina. Sin embargo, si asigna o devuelve una pila JIT no nula, esta debe ser una pila diferente para cada hilo para que la aplicación sea segura para hilos.

Estrictamente hablando, se permite aún más. Puede asignar la misma pila no nula a un contexto de coincidencia que es utilizado por cualquier número de patrones, siempre que no se utilicen para coincidencias por múltiples hilos al mismo tiempo. Por ejemplo, podría usar la misma pila en todos los patrones compilados, con un mutex global en la devolución de llamada para esperar hasta que la pila esté disponible para su uso. Sin embargo, esta es una solución ineficiente y no se recomienda.

Esta es una sugerencia sobre cómo podría operar un programa multihilo que necesita configurar pilas JIT no predeterminadas:


Durante la inicialización del hilo
thread_local_var = pcre2_jit_stack_create(...)


Durante la salida del hilo
pcre2_jit_stack_free(thread_local_var)


Use una función de devolución de llamada de una línea
return thread_local_var

Todas las funciones descritas en esta sección no hacen nada si JIT no está disponible.

PREGUNTAS FRECUENTES SOBRE PILAS JIT

(1) ¿Por qué necesitamos pilas JIT?

PCRE2 (y JIT) es un motor recursivo de búsqueda en profundidad, por lo que necesita una pila donde se apilen los datos locales del nodo actual antes de comprobar sus nodos hijos. Asignar una pila de máquina real en algunas plataformas es difícil. Por ejemplo, la cadena de pilas necesita actualizarse cada vez si extendemos la pila en PowerPC. Aunque es posible, el tiempo de sobrecarga de su actualización disminuye el rendimiento. Por lo tanto, realizamos la recursión en memoria.

(2) ¿Por qué no asignamos simplemente bloques de memoria con malloc()?

Los sistemas operativos modernos tienen una buena característica: pueden reservar un espacio de direcciones en lugar de asignar memoria. Podemos asignar de forma segura páginas de memoria dentro de este espacio de direcciones, por lo que la pila podría crecer sin mover los datos de memoria (esto es importante debido a los punteros). Por lo tanto, podemos asignar un espacio de direcciones de 1MiB y usar solo una página de memoria (generalmente 4KiB) si eso es suficiente. Sin embargo, aún podemos crecer hasta 1MiB en cualquier momento si es necesario.

(3) ¿Quién "posee" una pila JIT?

El propietario de la pila es el programa de usuario, no el patrón estudiado JIT ni nada más. El programa de usuario debe asegurarse de que si una pila está siendo utilizada por pcre2_match() (es decir, está asignada a un contexto de coincidencia que se pasa al patrón en ejecución), esa pila no debe ser utilizada por ningún otro hilo (para evitar sobrescribir la misma área de memoria). La mejor práctica para programas multihilo es asignar una pila para cada hilo y devolver esta pila a través de la función de devolución de llamada JIT.

(4) ¿Cuándo se debe liberar una pila JIT?

Puede liberar una pila JIT en cualquier momento, siempre que no sea utilizada nuevamente por pcre2_match(). Al asignar la pila a un contexto de coincidencia, solo se establece un puntero. No hay conteo de referencias ni ninguna otra magia. Puede liberar patrones compilados, contextos y pilas en cualquier orden, en cualquier momento. Simplemente *no* llame a pcre2_match() con un contexto de coincidencia que apunte a una pila ya liberada, ya que eso causará un SEGFAULT. (Tampoco libere una pila utilizada actualmente por pcre2_match() en otro hilo). También puede reemplazar la pila en un contexto en cualquier momento cuando no esté en uso. Debe liberar la pila anterior antes de asignar un reemplazo.

(5) ¿Debo asignar/liberar una pila cada vez antes/después de llamar a pcre2_match()?

No, porque esto es demasiado costoso en términos de recursos. Sin embargo, podría implementar alguna idea inteligente que libere la pila si no se usa durante, digamos, dos minutos. La devolución de llamada JIT puede ayudar a lograr esto sin mantener una lista de patrones.

(6) De acuerdo, la pila es para la asignación de memoria a largo plazo. ¿Pero qué sucede si un patrón causa un desbordamiento de pila con una pila de 1MiB? ¿Se mantiene ese 1MiB hasta que se libere la pila?

Especialmente en sistemas integrados, puede ser una buena idea liberar memoria a veces sin liberar la pila. Actualmente no hay una API para esto. Probablemente una llamada a una función que devuelva la memoria actualmente asignada para cualquier pila y otra que permita liberar memoria (encoger la pila) sería una buena idea si alguien necesita esto.

(7) Esto es demasiado complicado. ¿No hay una mejor solución para el manejo de pilas JIT?

No, gracias a Windows. Si se usaran hilos POSIX en todas partes, podríamos eliminar esta complicada API.

LIBERACION DE MEMORIA ESPECULATIVA JIT

void pcre2_jit_free_unused_memory(pcre2_general_context *gcontext);

El asignador ejecutable JIT no libera toda la memoria cuando es posible. Espera nuevas asignaciones y mantiene algo de memoria libre para mejorar la velocidad de asignación. Sin embargo, en condiciones de poca memoria, podría ser mejor liberar toda la memoria posible. Puede hacer que esto suceda llamando a pcre2_jit_free_unused_memory(). Su argumento es un contexto general, para administración de memoria personalizada, o NULL para administración de memoria estándar.

API DE RUTA RÁPIDA JIT

Debido a que la API descrita anteriormente recurre a la coincidencia interpretada cuando JIT no está disponible, es conveniente para programas que están escritos para uso general en muchos entornos. Sin embargo, llamar a JIT a través de pcre2_match() tiene un impacto en el rendimiento. Los programas que están escritos para ser utilizados donde se sabe que JIT está disponible, y que necesitan el mejor rendimiento posible, pueden usar en su lugar una API de "ruta rápida" para llamar a la coincidencia JIT directamente en lugar de llamar a pcre2_match() (obviamente solo para patrones que han sido procesados con éxito por pcre2_jit_compile()).

La función de ruta rápida se llama pcre2_jit_match() y toma exactamente los mismos argumentos que pcre2_match(). Sin embargo, la cadena del sujeto debe especificarse con una longitud; PCRE2_ZERO_TERMINATED no es compatible. Los bits de opción no admitidos (por ejemplo, PCRE2_ANCHORED y PCRE2_ENDANCHORED) se ignoran, al igual que la opción PCRE2_NO_JIT. Los valores de retorno también son los mismos que para pcre2_match(), más PCRE2_ERROR_JIT_BADOPTION si se solicita un modo de coincidencia (parcial o completo) que no se compiló.

Cuando llama a pcre2_match(), además de verificar las opciones inválidas, se realizan una serie de otras comprobaciones de cordura en los argumentos. Por ejemplo, si el puntero del sujeto es NULL pero la longitud es distinta de cero, se produce un error inmediato. Además, a menos que se establezca PCRE2_NO_UTF_CHECK, se prueba la validez de una cadena de sujeto UTF. En aras de la velocidad, estas comprobaciones no ocurren en la ruta rápida JIT. Si se pasan datos UTF inválidos cuando no se estableció PCRE2_MATCH_INVALID_UTF para pcre2_compile(), el resultado no está definido. El programa puede fallar, entrar en un bucle o dar resultados incorrectos. En ausencia de PCRE2_MATCH_INVALID_UTF, debe llamar a pcre2_jit_match() en modo UTF solo si está seguro de que el sujeto es válido.

Omitir las comprobaciones de cordura y el envoltorio de pcre2_match() puede proporcionar mejoras de velocidad de más del 10%.
