PCRE2 - Expresiones regulares compatibles con Perl (API revisada)

GUARDAR Y REUTILIZAR PATRONES PRECOMPILADOS DE PCRE2

int32_t pcre2_serialize_decode(pcre2_code **codes,
  int32_t number_of_codes, const uint8_t *bytes,
  pcre2_general_context *gcontext);

int32_t pcre2_serialize_encode(const pcre2_code **codes,
  int32_t number_of_codes, uint8_t **serialized_bytes,
  PCRE2_SIZE *serialized_size, pcre2_general_context *gcontext);

void pcre2_serialize_free(uint8_t *bytes);

int32_t pcre2_serialize_get_number_of_codes(const uint8_t *bytes);

Si está ejecutando una aplicación que utiliza un gran número de patrones de expresiones regulares, puede ser útil almacenarlos en un formato precompilado en lugar de tener que compilarlos cada vez que se ejecuta la aplicación. Sin embargo, si está utilizando la función de optimización just-in-time, no es posible guardar y recargar los datos JIT, ya que dependen de la posición. El host en el que se recargan los patrones debe estar ejecutando la misma versión de PCRE2, con la misma anchura de unidad de código, y también debe tener la misma endianidad, anchura de puntero y tipo PCRE2_SIZE. Por ejemplo, los patrones compilados en un sistema de 32 bits utilizando la biblioteca de 16 bits de PCRE2 no se pueden recargar en un sistema de 64 bits, ni se pueden recargar utilizando la biblioteca de 8 bits.

Tenga en cuenta que la "serialización" en PCRE2 no convierte los patrones compilados a un formato abstracto como la serialización de Java o .NET. La salida serializada es realmente solo una descarga de bytecode, por lo que solo se puede recargar en el mismo entorno que el que la creó. Por lo tanto, las restricciones mencionadas anteriormente. Las aplicaciones que no están enlazadas estáticamente con una versión fija de PCRE2 deben estar preparadas para recompilar patrones de sus fuentes, para ser inmunes a las actualizaciones de PCRE2.

PREOCUPACIONES DE SEGURIDAD

La instalación para guardar y restaurar patrones compilados está destinada a su uso dentro de aplicaciones individuales. Como tal, se espera que los datos suministrados a pcre2_serialize_decode() sean datos de confianza, no datos de fuentes externas arbitrarias. Solo hay comprobaciones básicas de consistencia, no una validación completa de lo que se está recargando. Datos corruptos pueden causar resultados indefinidos. Por ejemplo, si el campo de longitud de un patrón en los datos serializados está corrupto, el código de deserialización puede leer más allá del final del flujo de bytes que se le pasa.

GUARDAR PATRONES COMPILADOS

Antes de que los patrones compilados puedan ser guardados, deben ser serializados, lo que en PCRE2 significa convertir el patrón a un flujo de bytes. Un único flujo de bytes puede contener cualquier número de patrones compilados, pero todos deben usar las mismas tablas de caracteres. Una sola copia de las tablas se incluye en el flujo de bytes (su tamaño es de 1088 bytes). Para más detalles sobre las tablas de caracteres, véase la sección sobre soporte de localización en la documentación de pcre2api.

La función pcre2_serialize_encode() crea un flujo de bytes serializado a partir de una lista de patrones compilados. Sus dos primeros argumentos especifican la lista, siendo un puntero a un vector de punteros a patrones compilados, y la longitud del vector. Los argumentos tercero y cuarto apuntan a variables que se establecen para apuntar al flujo de bytes creado y su longitud, respectivamente. El argumento final es un puntero a un contexto general, que se puede utilizar para especificar funciones de gestión de memoria personalizadas. Si este argumento es NULL, se utiliza malloc() para obtener memoria para el flujo de bytes. El resultado de la función es el número de patrones serializados, o uno de los siguientes códigos de error negativos:


PCRE2_ERROR_BADDATA el número de patrones es cero o menos
PCRE2_ERROR_BADMAGIC desajuste de bytes de identificación en uno de los patrones
PCRE2_ERROR_NOMEMORY fallo en la asignación de memoria
PCRE2_ERROR_MIXEDTABLES los patrones no usan todas las mismas tablas
PCRE2_ERROR_NULL el 1er, 3er o 4to argumento es NULL

PCRE2_ERROR_BADMAGIC significa que el código de un patrón ha sido corrupto, o que una ranura en el vector no apunta a un patrón compilado.

Una vez que un conjunto de patrones ha sido serializado, puede guardar los datos de la manera apropiada. Aquí hay un código de ejemplo que compila dos patrones y los escribe en un archivo. Asume que la variable fd se refiere a un archivo abierto para salida. La comprobación de errores que debería estar presente en una aplicación real se ha omitido por simplicidad.


int errorcode;
uint8_t *bytes;
PCRE2_SIZE erroroffset;
PCRE2_SIZE bytescount;
pcre2_code *list_of_codes[2];
list_of_codes[0] = pcre2_compile("primer patrón",
PCRE2_ZERO_TERMINATED, 0, &errorcode, &erroroffset, NULL);
list_of_codes[1] = pcre2_compile("segundo patrón",
PCRE2_ZERO_TERMINATED, 0, &errorcode, &erroroffset, NULL);
errorcode = pcre2_serialize_encode(list_of_codes, 2, &bytes,
&bytescount, NULL);
errorcode = fwrite(bytes, 1, bytescount, fd);

Tenga en cuenta que los datos serializados son datos binarios que pueden contener cualquiera de los 256 valores de bytes posibles. En sistemas que hacen una distinción entre datos binarios y no binarios, asegúrese de que el archivo se abre para salida binaria.

Serializar un conjunto de patrones deja los datos originales sin tocar, por lo que todavía se pueden usar para coincidencias. Su memoria debe ser liberada eventualmente de la manera habitual llamando a pcre2_code_free(). Cuando haya terminado con el flujo de bytes, también debe ser liberado llamando a pcre2_serialize_free(). Si esta función se llama con un argumento NULL, retorna inmediatamente sin hacer nada.

REUTILIZAR PATRONES PRECOMPILADOS

Para reutilizar un conjunto de patrones guardados, primero debe hacer que el flujo de bytes serializado esté disponible en la memoria principal (por ejemplo, leyendo desde un archivo). La gestión de este bloque de memoria corresponde a la aplicación. Puede utilizar la función pcre2_serialize_get_number_of_codes() para saber cuántos patrones compilados hay en los datos serializados sin decodificar realmente los patrones:


uint8_t *bytes = <datos serializados>;
int32_t number_of_codes = pcre2_serialize_get_number_of_codes(bytes);

La función pcre2_serialize_decode() lee un flujo de bytes y recrea los patrones compilados en nuevos bloques de memoria, estableciendo punteros a ellos en un vector. Los dos primeros argumentos son un puntero a un vector adecuado y su longitud, y el tercer argumento apunta a un flujo de bytes. El argumento final es un puntero a un contexto general, que se puede utilizar para especificar funciones de gestión de memoria personalizadas para los patrones decodificados. Si este argumento es NULL, se utilizan malloc() y free(). Después de la deserialización, el flujo de bytes ya no es necesario y puede ser descartado.


pcre2_code *list_of_codes[2];
uint8_t *bytes = <datos serializados>;
int32_t number_of_codes =
pcre2_serialize_decode(list_of_codes, 2, bytes, NULL);

Si el vector no es lo suficientemente grande para todos los patrones en el flujo de bytes, se llena con aquellos que caben, y el resto se ignora. El resultado de la función es el número de patrones decodificados, o uno de los siguientes códigos de error negativos:


PCRE2_ERROR_BADDATA el segundo argumento es cero o menos
PCRE2_ERROR_BADMAGIC desajuste de bytes de identificación en los datos
PCRE2_ERROR_BADMODE desajuste de la anchura de la unidad de código o de la versión de PCRE2
PCRE2_ERROR_BADSERIALIZEDDATA otra falla de comprobación de cordura
PCRE2_ERROR_MEMORY fallo de asignación de memoria
PCRE2_ERROR_NULL primer o tercer argumento es NULL

PCRE2_ERROR_BADMAGIC puede significar que los datos están corruptos, o que fueron compilados en un sistema con diferente endianidad.

Los patrones decodificados se pueden usar para coincidencias de la manera habitual, y deben ser liberados llamando a pcre2_code_free(). Sin embargo, tenga en cuenta que existe un problema potencial de concurrencia si está utilizando varios patrones que fueron decodificados de un solo flujo de bytes en una aplicación multihilo. Una sola copia de las tablas de caracteres es utilizada por todos los patrones decodificados y un contador de referencias se utiliza para organizar que su memoria sea liberada automáticamente cuando se libera el último patrón, pero no hay bloqueo en este contador de referencias.
