PCP-SS(1) Manual de Comandos Generales PCP-SS(1)

NOMBRE

pcp-ss - informa sobre estadísticas de sockets

SINOPSIS

pcp [opciones de pcp] ss [opciones de ss]

DESCRIPCIÓN

pcp-ss informa sobre estadísticas de sockets recopiladas por el agente PMDA pmdasockets(1). El comando está diseñado para ser razonablemente compatible con muchas de las opciones de línea de comandos y formatos de informe de ss(8), pero también para ofrecer las ventajas del monitoreo local o remoto (en modo en vivo) y también la reproducción histórica desde un archivo PCP previamente grabado. Tenga en cuenta que dado que ss(1) tiene muchas opciones de línea de comandos, muchas de las cuales son las mismas que las opciones estándar de línea de comandos de PCP, como se describe en PCPIntro(1), la herramienta pcp-ss siempre debe ser invocada por los usuarios utilizando el front-end pcp. Esto permite que las opciones estándar de línea de comandos de PCP, como -h, -a, -S, -T, -O, -z, etc., se pasen sin conflicto con las opciones de ss(1). Consulte las secciones de EJEMPLOS a continuación para ver el uso típico y las líneas de comandos.

El modo en vivo utiliza la opción pcp -h host y requiere que el PMDA pmdasockets(1) esté instalado y habilitado en el host de destino (local o remoto), consulte pmdasockets(1) para obtener detalles sobre cómo habilitar el PMDA sockets en un host particular. La fuente predeterminada son las métricas en vivo recopiladas en localhost, si no se proporcionan las opciones -h o -a.

La reproducción histórica/de archivo utiliza la opción pcp -a archivo, donde archivo es el nombre base de un archivo PCP grabado previamente. La función de reproducción de archivo es particularmente útil porque las estadísticas de sockets se pueden informar para un tiempo designado utilizando la opción pcp --origin (que por defecto es la hora de inicio del archivo).

EJEMPLOS

pcp ss
Muestra información básica de sockets predeterminada para el host local. Esto incluye Netid (tcp, udp, etc.), State (ESTAB, TIME_WAIT, etc.), colas Recv-Q y Send-Q y la dirección y puerto local y remoto para cada socket.
pcp -h algúnhost ss -noemitauO
Muestra la misma información básica de sockets que la anterior para el host algúnhost, que puede ser el localhost predeterminado. Los argumentos adicionales de línea de comandos (-noemitauO) muestran una línea por socket (-O), nombres de servicio numéricos (-n) (predeterminado), información del temporizador (-o), detalles extendidos del socket (-e), uso de memoria del socket (-m), información interna de TCP (-i), sockets udp (-u) y tcp (-t) y sockets tanto de escucha como no de escucha (-a).
pcp -a algúnarchivo -S '@Wed 16 Jun 2021 12:57:21' ss -noemitauO
Muestra la misma información que el ejemplo anterior, pero para el archivo algúnarchivo a partir de la hora dada Wed 16 Jun 2021 12:57:21. Tenga en cuenta que se requiere el prefijo literal @ para una hora absoluta, consulte PCPIntro(1) para obtener detalles. Por supuesto, el archivo debe contener datos para la hora solicitada. Puede usar pmlogdump -l algúnarchivo para examinar los límites de tiempo de algúnarchivo.
pcp -a algúnarchivo -O-0 ss -noemitauO
Como el anterior, pero con un desplazamiento de cero segundos (-O-0) antes del final actual de algúnarchivo, es decir, los datos registrados más recientemente. Tenga en cuenta que algúnarchivo puede estar creciendo actualmente (es decir, se está registrando con pmlogger(1)).

OPCIONES

Debido a la gran cantidad de opciones compatibles con pcp-ss, el comando pcp(1) siempre debe usarse para invocar a pcp-ss para especificar opciones como la fuente de métricas (host o archivo) y también (en modo archivo), la hora de inicio o el desplazamiento solicitado, y la zona horaria utilizando las siguientes opciones:

-h, --host
El nombre del host remoto al que conectarse en modo en vivo.
-a, --archive
El archivo de archivo a utilizar para muestreo histórico.
-O, --origin
El desplazamiento de tiempo a utilizar dentro de un archivo (implica -a).
-S, --start
La hora de inicio (por ejemplo, en formato ctime(3)) a utilizar al reproducir un archivo.
-Z, --timezone
Usar una zona horaria específica. Dado que pcp-ss no informa marcas de tiempo, esto solo afecta la interpretación de una hora de inicio absoluta (-S) o un desplazamiento (-O).
-z, --hostzone
En modo archivo, use la zona horaria del archivo en lugar de la zona horaria de la máquina local que ejecuta pcp-ss. La zona horaria, la hora de inicio y fin del archivo se pueden examinar usando pmlogdump(1) con la opción -L.

Las opciones anteriores de pcp se vuelven indirectamente disponibles para el comando pcp-ss a través de variables de entorno; consulte PCPIntro(1) para una descripción completa de estas opciones.

Las opciones adicionales de línea de comandos disponibles para el propio pcp-ss son:

-h, --help
mostrar mensaje de ayuda y salir
-V, --version
información de la versión de salida
-n, --numeric
no resolver nombres de servicio (actualmente siempre establecido)
-a, --all
mostrar todos los sockets
-l, --listening
mostrar sockets de escucha
-o, --options
mostrar información del temporizador
-e, --extended
mostrar información detallada del socket
-m, --memory
mostrar uso de memoria del socket
-i, --info
mostrar información interna de TCP
-4, --ipv4
mostrar solo sockets IP versión 4
-6, --ipv6
mostrar solo sockets IP versión 6
-t, --tcp
mostrar solo sockets TCP
-u, --udp
mostrar solo sockets UDP
-H, --noheader
suprimir línea de encabezado
-O, --oneline
datos del socket impresos en una sola línea

INFORME

Las columnas en el informe pcp-ss varían según las opciones de línea de comandos y tienen la misma interpretación que se describe en ss(8).

Una diferencia con pcp-ss es que la primera línea del informe comienza con '# Timestamp' seguido de la marca de tiempo (en la zona horaria solicitada, consulte -z y -Z arriba) de la muestra de datos del host o fuente de archivo. Después de la marca de tiempo se encuentra la cadena de filtro actualmente activa para la fuente de métricas. En modo archivo, el filtro activo se puede cambiar dinámicamente, incluso mientras el archivo se está registrando. Esto es diferente de ss(8) donde el filtro se especifica opcionalmente en la línea de comandos de la herramienta y siempre es 'en vivo', es decir, ss(8) no admite la reproducción retrospectiva. Con pcp-ss, el filtro se almacena en el PMDA back-end, consulte pmdasockets(1), en la métrica network.persocket.filter. El filtro predeterminado es state connected, que se puede cambiar

ESTABLECIENDO FILTROS

Este filtro se puede modificar dinámicamente almacenando un nuevo valor de cadena en la métrica network.persocket.filter usando pmstore(1), p. ej., pmstore network.persocket.filter "state established". Esto anulará el filtro predeterminado persistente, que se almacena en un archivo de configuración PMDA y se carga cada vez que se inicia el PMDA de sockets. Ver pmdasockets(1) para más detalles y ver ss(8) para detalles de la sintaxis del filtro y ejemplos.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para variables de entorno que afectan a las herramientas de PCP, ver pmGetOptions(3).

VER TAMBIÉN

PCPIntro(1), pcp(1), pmdasockets(1), pmlogger(1), pcp.conf(5) y ss(8).
