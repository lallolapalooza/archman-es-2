Paquete: libpcap

Licencias: BSD-3-Clause

PCAP_LOOP(3PCAP) PCAP_LOOP(3PCAP)

NOMBRE

pcap_loop, pcap_dispatch - procesar paquetes de una captura en vivo o archivo de guardado

SINOPSIS

#include <pcap/pcap.h>
typedef void (*pcap_handler)(u_char *user, const struct pcap_pkthdr *h,
    const u_char *bytes);
int pcap_loop(pcap_t *p, int cnt,
    pcap_handler callback, u_char *user);
int pcap_dispatch(pcap_t *p, int cnt,
    pcap_handler callback, u_char *user);

DESCRIPCIÓN

pcap_loop() procesa paquetes de una captura en vivo o un ``archivo de guardado'' hasta que se procesen cnt paquetes, se alcance el final del ``archivo de guardado'' al leer de uno, se llame a pcap_breakloop(3PCAP), o ocurra un error. No regresa cuando ocurren tiempos de espera del búfer de paquetes en vivo. Un valor de -1 o 0 para cnt es equivalente a infinito, de modo que los paquetes se procesan hasta que ocurra otra condición de finalización.

pcap_dispatch() procesa paquetes de una captura en vivo o un ``archivo de guardado'' hasta que se procesen cnt paquetes, se alcance el final del búfer actual de paquetes al realizar una captura en vivo, se alcance el final del ``archivo de guardado'' al leer de uno, se llame a pcap_breakloop(), o ocurra un error. Por lo tanto, al realizar una captura en vivo, cnt es el número máximo de paquetes a procesar antes de regresar, pero no es un número mínimo; al leer una captura en vivo, solo se lee un búfer de paquetes a la vez, por lo que pueden procesarse menos de cnt paquetes. Un valor de -1 o 0 para cnt hace que todos los paquetes recibidos en un búfer se procesen al leer una captura en vivo, y hace que todos los paquetes del archivo se procesen al leer un ``archivo de guardado''.

Tenga en cuenta que, al realizar una captura en vivo en algunas plataformas, si el tiempo de espera de lectura expira cuando no hay paquetes disponibles, pcap_dispatch() regresará 0, incluso si no está en modo no bloqueante, ya que no hay paquetes para procesar. Las aplicaciones deben estar preparadas para esto, pero no deben depender de que ocurra.

callback especifica una rutina pcap_handler que se llamará con tres argumentos: un puntero u_char que se pasa en el argumento user a pcap_loop() o pcap_dispatch(), un puntero const struct pcap_pkthdr apuntando a la marca de tiempo y longitudes del paquete, y un puntero const u_char a los primeros caplen (tal como se proporciona en el struct pcap_pkthdr, un puntero al cual se pasa a la rutina de callback) bytes de datos del paquete. La rutina de callback no debe liberar el struct pcap_pkthdr y los datos del paquete, y no se garantiza que sean válidos después de que la rutina de callback regrese; si el código necesita que sean válidos después del callback, debe hacer una copia de ellos.

Los bytes de datos del paquete comienzan con una cabecera de capa de enlace. El formato de la cabecera de capa de enlace se indica mediante el valor de retorno de la rutina pcap_datalink(3PCAP) cuando se le entrega el valor pcap_t también pasado a pcap_loop() o pcap_dispatch(). https://www.tcpdump.org/linktypes.html enumera los valores que pcap_datalink() puede devolver y describe los formatos de paquete que corresponden a esos valores. El valor que devuelve será válido para todos los paquetes recibidos a menos y hasta que se llame a pcap_set_datalink(3PCAP); después de una llamada exitosa a pcap_set_datalink(), todos los paquetes subsiguientes tendrán una cabecera de capa de enlace del tipo especificado por el valor del tipo de cabecera de capa de enlace pasado a pcap_set_datalink().

NO asuma que los paquetes para una captura o ``archivo de guardado'' dado tendrán algún tipo de cabecera de capa de enlace, como DLT_EN10MB para Ethernet. Por ejemplo, el dispositivo "any" en Linux tendrá un tipo de cabecera de capa de enlace de DLT_LINUX_SLL o DLT_LINUX_SLL2 incluso si todos los dispositivos del sistema en el momento en que se abre el dispositivo "any" tienen algún otro tipo de capa de datos, como DLT_EN10MB para Ethernet.

VALOR DE RETORNO

pcap_loop() regresa 0 si se agota cnt o si, al leer de un ``archivo de guardado'', no hay más paquetes disponibles. Regresa PCAP_ERROR_BREAK si el bucle terminó debido a una llamada a pcap_breakloop() antes de procesar cualquier paquete, PCAP_ERROR_NOT_ACTIVATED si se llama en un manejador de captura que se ha creado pero no activado, o PCAP_ERROR si ocurre otro error. No regresa cuando ocurren tiempos de espera del búfer de paquetes en vivo; en su lugar, intenta leer más paquetes.

pcap_dispatch() regresa el número de paquetes procesados con éxito; esto puede ser 0 si no se leyeron paquetes de una captura en vivo (si, por ejemplo, fueron descartados porque no pasaron el filtro de paquetes, o si, en plataformas que admiten un tiempo de espera del búfer de paquetes que comienza antes de que lleguen los paquetes, el tiempo de espera expira antes de que lleguen los paquetes, o si el descriptor de archivo para el dispositivo de captura está en modo no bloqueante y no había paquetes disponibles para leer) o si no hay más paquetes disponibles en un ``archivo de guardado''. Regresa PCAP_ERROR_BREAK si el bucle terminó debido a una llamada a pcap_breakloop() antes de procesar cualquier paquete, PCAP_ERROR_NOT_ACTIVATED si se llama en un manejador de captura que se ha creado pero no activado, o PCAP_ERROR si ocurre otro error. Si su aplicación utiliza pcap_breakloop(), asegúrese de verificar explícitamente PCAP_ERROR y PCAP_ERROR_BREAK, en lugar de solo verificar si el valor de retorno es < 0.

Si se devuelve PCAP_ERROR, se puede llamar a pcap_geterr(3PCAP) o pcap_perror(3PCAP) con p como argumento para obtener o mostrar el texto del error.

COMPATIBILIDAD RETROACTIVA

En versiones de libpcap anteriores a la 1.5.0, el comportamiento cuando cnt era 0 no estaba definido; diferentes plataformas y dispositivos se comportaban de manera diferente, por lo que el código que debe funcionar con estas versiones de libpcap debe usar -1, no 0, como valor de cnt.
