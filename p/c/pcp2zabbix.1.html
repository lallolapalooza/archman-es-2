NOMBRE

pcp2zabbix - exportador de métricas pcp-a-zabbix

SINOPSIS

pcp2zabbix [-5CGHIjlLnrRvV?] [-4 acción] [-8|-9 límite] [-a archivo] [-A alineación] [--archive-folio folio] [-b|-B escala-espacio] [-c config] [--container contenedor] [-D depuración] [--daemonize] [-e derivado] [-E intervalo-envío] [-g servidor] [-h host] [-i instancias] [-J rango] [-K espec] [-N predicado] [-O origen] [-p puerto] [-P|-0 precisión] [-q|-Q escala-conteo] [-s muestras] [-S inicio] [-t intervalo] [-T fin] [-x prefijo] [-X hostname] [-y|-Y escala-tiempo] metricspec [...]

DESCRIPCIÓN

pcp2zabbix es una herramienta personalizable de exportación de métricas de rendimiento de PCP a Zabbix. Cualquier métrica de rendimiento disponible, en vivo o archivada, del sistema y/o aplicación, puede ser seleccionada para exportar usando argumentos de línea de comandos o un archivo de configuración.

pcp2zabbix es un pariente cercano de pmrep(1). Consulte pmrep(1) para la descripción de metricspec aceptada en la línea de comandos de pcp2zabbix. Vea pmrep.conf(5) para la descripción de la sintaxis del archivo de configuración pcp2zabbix.conf. Esta página describe las opciones específicas de pcp2zabbix y las diferencias del archivo de configuración con pmrep.conf(5). pmrep(1) también lista algunos ejemplos de uso de los cuales la mayoría son aplicables también con pcp2zabbix.

Solo se admiten las opciones de línea de comandos listadas en esta página; otras opciones disponibles para pmrep(1) no son compatibles.

Las opciones a través de variables de entorno (ver pmGetOptions(3)) tienen prioridad sobre los valores predeterminados incorporados correspondientes (si los hay). Las opciones del archivo de configuración tienen prioridad sobre las variables de entorno correspondientes (si las hay). Las opciones de la línea de comandos tienen prioridad sobre las opciones del archivo de configuración correspondientes (si las hay).

ARCHIVO DE CONFIGURACIÓN

pcp2zabbix usa un archivo de configuración con sintaxis descrita en pmrep.conf(5). Las siguientes opciones son comunes con pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. El resto de las opciones de pmrep.conf son reconocidas pero ignoradas por compatibilidad.

Opciones específicas de pcp2zabbix

zabbix_server (string)

Especifica el nombre de host o la dirección IP del servidor Zabbix de destino. Si un host es monitoreado por un proxy, se debe usar el nombre de host o la dirección IP del proxy en su lugar. La opción de línea de comandos correspondiente es -g. Por defecto es localhost.

zabbix_port (integer)

Especifica el número de puerto del trapper del servidor que se ejecuta en el servidor. La opción de línea de comandos correspondiente es -p. Por defecto es 10051.

zabbix_host (string)

Especifica el nombre de host del agente tal como está registrado en la interfaz de Zabbix. La dirección IP del host y el nombre DNS no funcionarán. La opción de línea de comandos correspondiente es -X. Por defecto es el host de origen de las métricas.

zabbix_interval (string)

Indica el intervalo para enviar métricas al servidor Zabbix. Esto puede ser más largo que el intervalo de reporte para minimizar la sobrecarga al comunicarse con el servidor (ya que cada envío crea una nueva conexión). Sigue la sintaxis de tiempo descrita en PCPIntro(1). La opción de línea de comandos correspondiente es -E. Por defecto es el intervalo de reporte. Las herramientas de Zabbix envían como máximo 250 métricas a la vez. Ignorado al leer métricas de archivos PCP, en cuyo caso las métricas se enviarán en lotes de aproximadamente 250 métricas.

zabbix_prefix (string)

Especifica el prefijo para las métricas enviadas al servidor Zabbix. La opción de línea de comandos correspondiente es -x. Por defecto es pcp..

zabbix_lld (boolean)

Especifica si se debe habilitar el descubrimiento de bajo nivel de Zabbix. La opción de línea de comandos correspondiente es -l. Por defecto es no.

OPCIONES

Las opciones de línea de comandos disponibles son:

-0 precisión, --precision-force=precisión
Igual que -P pero esta opción anulará las especificaciones por métrica.
-4 acción, --names-change=acción
Especifica qué acción tomar al recibir un evento de cambio de nombre de métrica durante el muestreo. Estos eventos ocurren cuando un PMDA descubre nuevas métricas algún tiempo después de iniciarse, e informa a las herramientas cliente en ejecución como pcp2zabbix. Los valores válidos para acción son update (actualizar métricas que se están muestreando), ignore (no hacer nada - el comportamiento predeterminado) y abort (salir del programa si ocurre dicho evento).
-5, --ignore-unknown
Ignorar silenciosamente cualquier nombre de métrica que no se pueda resolver. Se debe encontrar al menos una métrica para que la herramienta comience.
-8 límite, --limit-filter=límite
Limitar los resultados a instancias con valores por encima/debajo del límite. Un entero positivo incluirá instancias con valores en o por encima del límite en el reporte. Un entero negativo incluirá instancias con valores en o por debajo del límite en el reporte. Un valor de cero no realiza ningún filtrado por límite. Esta opción no anulará las posibles especificaciones por métrica. Ver también -J y -N.
-9 límite, --limit-filter-force=límite
Igual que -8 pero esta opción anulará las especificaciones por métrica.
-a archivo, --archive=archivo
Los valores de las métricas de rendimiento se obtienen del conjunto de archivos de archivo Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos.
-A alineación, --align=alineación
Forzar que la muestra inicial esté alineada en el límite de una unidad de tiempo natural alineación. Consulte PCPIntro(1) para una descripción completa de la sintaxis de alineación.
--archive-folio=folio
Leer los archivos de origen de métricas de la folio de archivos PCP creada por herramientas como pmchart(1) o, con menos frecuencia, manualmente con mkaf(1).
-b escala, --space-scale=escala
Unidad/escala para métricas de espacio (bytes), los valores posibles incluyen bytes, Kbytes, KB, Mbytes, MB, y así sucesivamente. Esta opción no anulará las posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-B escala, --space-scale-force=escala
Igual que -b pero esta opción anulará las especificaciones por métrica.
-c config, --config=config
Especifica el archivo o directorio config a utilizar. En caso de que config sea un directorio, se incluirán todos los archivos que terminen en .conf. El valor predeterminado es el primero que se encuentre de: ./pcp2zabbix.conf, $HOME/.pcp2zabbix.conf, $HOME/pcp/pcp2zabbix.conf, y $PCP_SYSCONF_DIR/pcp2zabbi
-c file, --config=file
Use configuration file instead of the default $HOME/.pcp/pmrep.conf or /etc/pcp/pmrep.conf. For details, see the above section and pmrep.conf(5).
--container=container
Recuperar métricas de rendimiento del contenedor especificado, ya sea local o remoto (ver -h).
-C, --check
Salir antes de informar cualquier valor, pero después de analizar la configuración y las métricas, e imprimir las posibles cabeceras.
--daemonize
Convertirse en un demonio al inicio.
-e derived, --derived=derived
Especificar métricas de rendimiento derivadas. Si derived comienza con una barra ("/") o con un punto ("."), se interpretará como un archivo de configuración de métricas derivadas de PCP, de lo contrario, se interpretará como expresiones de métricas derivadas separadas por comas o punto y coma. Para una descripción completa de las métricas derivadas y los archivos de configuración de métricas derivadas de PCP, consulte pmLoadDerivedConfig(3) y pmRegisterDerived(3). Alternativamente, el uso de la sintaxis de configuración de pmrep.conf(5) permite definir métricas derivadas como parte de los conjuntos de métricas (metricsets).

En caso de problemas con las métricas derivadas, revise las páginas del manual mencionadas en detalle y asegúrese de que todas las métricas requeridas estén disponibles, especialmente al usar archivos (archives). Use -Dderive para ver información de depuración adicional sobre el análisis de métricas derivadas.

-E interval, --zabbix-interval=interval
Especificar el intervalo para enviar métricas al servidor. Ver la descripción de zabbix_interval arriba para más detalles.
-g server, --zabbix-server=server
Servidor Zabbix de destino server.
-G, --no-globals
No incluir métricas globales en el informe (ver pmrep.conf(5)).
-h host, --host=host
Recuperar métricas de rendimiento de pmcd(1) en el host, en lugar del host local predeterminado.
-H, --no-header
No imprimir ninguna cabecera.
-i instances, --instances=instances
Recuperar e informar solo las instancias de métricas especificadas. Por defecto, se informan todas las instancias, presentes y futuras.

Consulte pmrep(1) para una descripción completa de esta opción.

-I, --ignore-incompat
Ignorar métricas incompatibles. Por defecto, las métricas incompatibles (es decir, su tipo no es compatible o no se pueden escalar como se solicita) harán que pcp2zabbix termine con un mensaje de error. Con esta opción, todas las métricas incompatibles se omiten silenciosamente del informe. Esto puede ser especialmente útil al solicitar nodos no terminales del árbol PMNS para el informe.
-l, --zabbix-lld
Añadir métricas de descubrimiento de bajo nivel (LLD). Esto permite que los dominios de instancias de métricas PCP se envíen a Zabbix, de modo que los elementos/disparadores/gráficos prototipo puedan ser construidos automáticamente por Zabbix. Para cada métrica PCP con un dominio de instancia, la clave pcp.discovery[pcp.met.ric] se envía periódicamente. Este símbolo debe añadirse a una regla de descubrimiento y definirá la macro LLD {#PCP.MET.RIC}. Esta macro a su vez puede usarse para definir elementos/disparadores/gráficos prototipo. Los nombres se ajustan si se utilizó -x para anular el prefijo pcp..
-j, --live-filter
Realizar filtrado en vivo de instancias. Esto permite capturar todas las instancias nombradas incluso si los procesos se reinician en algún momento (a diferencia de sin filtrado en vivo). Realizar filtrado en vivo sobre un gran número de instancias añadirá cierta sobrecarga interna, por lo que se aconseja un poco de precaución por parte del usuario. Ver también -n.
-J rank, --rank=rank
Limitar los resultados a las instancias de mayor/menor valor (rank) de métricas de conjunto (set-valued). Un entero positivo incluirá las instancias de mayor valor en el informe. Un entero negativo incluirá las instancias de menor valor en el informe. Un valor de cero no realiza clasificación (ranking). La clasificación no implica ordenación, ver -6. Ver también -8.
-K spec, --spec-local=spec
Al recuperar métricas de un contexto local (ver -L), la opción -K puede usarse para controlar los PMDA DSO que deben hacerse accesibles. El argumento spec se ajusta a la sintaxis descrita en pmSpecLocalPMDA(3). Se pueden usar múltiples opciones -K.
-L, --local-PMDA
Usar un contexto local para recopilar métricas de PMDA DSO en el host local sin PMCD. Ver también -K.
-n, --invert-filter
Realizar clasificación (ranking) antes del filtrado en vivo. Por defecto, el filtrado en vivo de instancias (cuando se solicita, ver -j) ocurre antes que la clasificación de instancias (cuando se solicita, ver -J). Con esta opción, la lógica se invierte y la clasificación ocurre antes del filtrado en vivo.
-N predicate, --predicate=predicate
Especificar una lista separada por comas de métricas de referencia de filtro predicate. Por defecto, la clasificación (ver -J) ocurre para cada métrica individualmente. Con predicados, la clasificación se realiza solo para las métricas de predicado especificadas. Al informar, el resto de las métricas que comparten el mismo dominio de instancia (ver PCPIntro(1)) que el predicado incluirán solo las instancias de mayor/menor clasificación del predicado correspondiente. La clasificación no implica ordenación, ver -6.

Por ejemplo, usando proc.memory.rss (tamaño de memoria residente del proceso) como métrica predicate junto con proc.io.total_bytes y mem.util.used como métricas a informar, solo los procesos que usan más/menos memoria (según -J) se incluirán al informar los bytes totales escritos por los procesos. Dado que mem.util.used es una métrica de valor único (por lo tanto, no comparte el mismo dominio de instancia que las métricas relacionadas con el proceso), se informará como de costumbre.

-O origin, --origin=origin
Al informar métricas archivadas, comenzar el informe en origin dentro de la ventana de tiempo (ver -S y -T). Consulte PCPIntro(1) para una descripción completa de la sintaxis para origin.
-p port, --zabbix-port=port
Puerto del servidor Zabbix port.
-P precision, --precision=precision
Usar precision para valores de salida numéricos no enteros. El valor predeterminado es usar 3 decimales (cuando sea aplicable). Esta opción *no* anulará las especificaciones posibles por métrica.
-q scale, --count-scale=scale
Unidad/escala para métricas de recuento (count metrics), los valores posibles incluyen count x 10^-1, count, count x 10, count x 10^2, y así sucesivamente de 10^-8 a 10^7. (Estos valores son actualmente sensibles a los espacios). Esta opción *no* anulará las especificaciones posibles por métrica. Ver también pmParseUnitsStr(3).
-Q scale, --count-scale-force=scale
Similar a -q pero esta opción *anulará* las especificaciones por métrica.
-r, --raw
Emitir valores de métricas en bruto, no convertir contadores acumulativos a tasas (rates). Esta opción *anulará* las especificaciones posibles por métrica.
-R, --raw-prefer
Similar a -r pero esta opción *no* anulará las especificaciones por métrica.
-s samples, --samples=samples
El argumento samples define el número de muestras a recuperar y reportar. Si samples es 0 o no se especifica -s, pcp2zabbix tomará muestras e informará continuamente (en modo de tiempo real) o hasta el final del conjunto de archivos PCP (en modo de archivo). Ver también -T.
-S starttime, --start=starttime
Al informar métricas archivadas, el informe se limitará a aquellos registros anotados a partir de starttime. Consulte PCPIntro(1) para una descripción completa de la sintaxis para starttime.
-t interval, --interval=interval
Establecer el intervalo de informe a algo diferente al segundo predeterminado de 1. El argumento interval sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos). Ver también la opción -T.
-T endtime, --finish=endtime
Al informar métricas archivadas, el informe se limitará a aquellos registros anotados antes o en endtime. Consulte PCPIntro(1) para una descripción completa de la sintaxis para endtime.

Cuando se usa para definir el tiempo de ejecución antes de que pcp2zabbix salga, si no se proporciona samples (ver -s), entonces el número de muestras informadas depende del intervalo (ver -t). Si se proporciona samples, entonces el intervalo se ajustará para permitir el informe de samples durante el tiempo de ejecución. En caso de que se proporcionen -T, -s y -t, endtime determinará la hora real en que se ejecutará pcp2zabbix.

-v, --omit-flat
Informar solo métricas de conjunto (set-valued) con instancias (por ejemplo, disk.dev.read) y omitir métricas "planas" (flat) de valor único sin instancias.
pcp2zabbix(1) — pcp

NAME

pcp2zabbix — Performance Co-Pilot Zabbix Exporter

SYNOPSIS

pcp2zabbix [-c config |--config config] [-D debuglist] [-h] [-i domain ] [-I domain ] [-l logfile] [-p pidfile] [-q quiet] [-s interval] [-t timeout] [-V] [-x prefix] [-X hostname] [-y scale] [-Y scale]

pcp2zabbix [-?]

DESCRIPTION

The pcp2zabbix utility collects performance metrics from the Performance Co-Pilot (PCP) pmcd(1) daemon and exports them to a Zabbix server. It is intended to be run as a long-lived daemon, periodically querying PCP for metric values and sending them to the Zabbix server. It uses the Zabbix Sender protocol internally.

The metrics to be exported, their source PCP metrics, the Zabbix host and item keys, and other Zabbix-specific parameters are defined in a configuration file, specified by the -c option.

By default, pcp2zabbix runs in the foreground, sending data to the Zabbix server at the interval specified by the -s option. Use the -l option to redirect diagnostic output to a log file and to run in the background as a daemon.

The pcp2zabbix utility must be configured with the metrics to be exported, and the corresponding Zabbix host and item keys to which they should be sent. A detailed description of the configuration file syntax can be found in pcp2zabbix.conf(5).

CONFIGURATION FILE

The configuration file for pcp2zabbix specifies the PCP metrics to be collected and how they map to Zabbix items. The default location for this file is /etc/pcp2zabbix.conf, but it can be overridden using the -c option.

A sample configuration file is provided with the PCP distribution.

OPTIONS

-c config, --config=config
Specify the location of the configuration file. Default is /etc/pcp2zabbix.conf.
-D debuglist, --debug=debuglist
Enable additional debugging output to stderr. debuglist is a comma-separated list of debugging options. Use pmdbg(1) for a list of available options.
-h, --help
Display a help message and exit.
-i domain, --indirect=domain
Connect to PMCD via the specified indirect host domain. This is typically a comma-separated list of host:port specifications.
-I domain, --indirect-force=domain
Similar to -i, but forces the use of the specified indirect host. This option overrides any other specification for indirect hosts.
-l logfile, --logfile=logfile
Log diagnostic messages to the specified logfile. If this option is used, pcp2zabbix will run as a daemon in the background. A common practice is to log to /var/log/pcp/pcp2zabbix.log.
-p pidfile, --pidfile=pidfile
Write the process ID to the specified pidfile when running as a daemon. Default is /var/run/pcp2zabbix.pid.
-q quiet, --quiet=quiet
Suppress status messages. quiet=1 to suppress all messages except errors. quiet=2 to suppress all messages including errors. See also kernel.all.sysfork. See -i and -I.
-s interval, --sample-interval=interval
Set the sampling interval to interval seconds. Default is 10 seconds.
-t timeout, --timeout=timeout
Set the timeout for PCP metric queries to timeout seconds. Default is 5 seconds.
-V, --version
Display version number and exit.
-x prefix, --zabbix-prefix=prefix
Metrics prefix for measurements sent to the server.
-X hostname, --zabbix-host=hostname
Agent hostname as registered in Zabbix frontend.
-y scale, --time-scale=scale
Unit/scale for time metrics, possible values include nanosec, ns, microsec, us, millisec, ms, and so forth up to hour, hr. This option will not override possible per-metric specifications. See also pmParseUnitsStr(3).
-Y scale, --time-scale-force=scale
Like -y but this option will override per-metric specifications.
-?, --help
Display usage message and exit.

FILES

pcp2zabbix.conf
pcp2zabbix configuration file (see -c)
$PCP_SYSCONF_DIR/pmrep/*.conf
system provided default pmrep configuration files

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

Of particular note, PCP_DISCRETE_ONCE can be set to ensure that discrete metric values are reported only once, unless they change at some point.

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.
