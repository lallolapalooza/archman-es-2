PCRECPP(3) Manual de Funciones de Biblioteca PCRECPP(3)

NOMBRE

PCRE - Expresiones regulares compatibles con Perl.

SINOPSIS DE ENVOLTORIO C++

#include <pcrecpp.h>

DESCRIPCIÓN

El envoltorio C++ para PCRE fue proporcionado por Google Inc. Se añadió funcionalidad adicional por Giuseppe Maxia. Esta breve página del manual se construyó a partir de las notas del archivo pcrecpp.h, que debe ser consultado para obtener más detalles. Tenga en cuenta que el envoltorio C++ solo soporta la biblioteca PCRE original de 8 bits. Actualmente no hay soporte para 16 o 32 bits.

INTERFAZ DE COINCIDENCIA

La operación "FullMatch" verifica que el texto suministrado coincida exactamente con un patrón suministrado. Si se proporcionan argumentos de puntero, copia las subcadenas coincidentes que coinciden con subpatrones en ellos.


Ejemplo: coincidencia exitosa
pcrecpp::RE re("h.*o");
re.FullMatch("hola");


Ejemplo: coincidencia no exitosa (requiere coincidencia completa):
pcrecpp::RE re("e");
!re.FullMatch("hola");


Ejemplo: creación de un objeto RE temporal:
pcrecpp::RE("h.*o").FullMatch("hola");

Puede pasar un "const char*" o un "string" para "text". Los ejemplos a continuación tienden a usar un char* constante. Puede, como en los diferentes ejemplos anteriores, almacenar explícitamente el objeto RE en una variable o usar un objeto RE temporal. Los ejemplos a continuación usan un modo u otro arbitrariamente. Cualquiera podría usarse correctamente para cualquiera de estos ejemplos.

Debe proporcionar argumentos de puntero adicionales para extraer subpiezas coincidentes.


Ejemplo: extrae "ruby" en "s" y 1234 en "i"
int i;
string s;
pcrecpp::RE re("(\\w+):(\\d+)");
re.FullMatch("ruby:1234", &s, &i);


Ejemplo: no intenta extraer ningún subpatrón adicional
re.FullMatch("ruby:1234", &s);


Ejemplo: no intenta extraer en NULL
re.FullMatch("ruby:1234", NULL, &i);


Ejemplo: el desbordamiento de enteros causa fallo
!re.FullMatch("ruby:1234567891234", NULL, &i);


Ejemplo: falla porque no hay suficientes subpatrones:
!pcrecpp::RE("\\w+:\\d+").FullMatch("ruby:1234", &s);


Ejemplo: falla porque la cadena no se puede almacenar en un entero
!pcrecpp::RE("(.*)").FullMatch("ruby", &i);

Los argumentos de puntero proporcionados pueden ser punteros a cualquier tipo numérico escalar, o uno de:


string (la pieza coincidente se copia a la cadena)
StringPiece (StringPiece se modifica para apuntar a la pieza coincidente)
T (donde existe "bool T::ParseFrom(const char*, int)")
NULL (el subpatrón coincidente correspondiente no se copia)

La función devuelve verdadero si y solo si se cumplen todas las siguientes condiciones:


a. "text" coincide exactamente con "pattern";


b. El número de subpatrones coincidentes es >= al número de punteros suministrados;
c. El argumento "i" tiene un tipo adecuado para contener la cadena capturada como el subpatrón "i". Si pasa void * NULL para el argumento "i", o un NULL no-void * del tipo correcto, o pasa menos argumentos que el número de subpatrones, el subpatrón capturado "i" se ignora.

ADVERTENCIA: Un subpatrón opcional que no existe en la cadena coincidente se asigna a una cadena vacía. Por lo tanto, lo siguiente devolverá falso (porque la cadena vacía no es un número válido):


int number;
pcrecpp::RE::FullMatch("abc", "[a-z]+(\\d+)?", &number);

La interfaz de coincidencia admite como máximo 16 argumentos por llamada. Si necesita más, considere usar la interfaz más general pcrecpp::RE::DoMatch. Consulte pcrecpp.h para ver la firma de DoMatch.

NOTA: No use no_arg, que se usa internamente para marcar el final de una lista de argumentos opcionales, como marcador de posición para argumentos faltantes, ya que esto puede provocar fallos de segmentación.

CITANDO METACARACTERES

Puede usar la operación "QuoteMeta" para insertar barras invertidas antes de todos los caracteres potencialmente significativos en una cadena. La cadena devuelta, utilizada como expresión regular, coincidirá exactamente con la cadena original.


Ejemplo:
string quoted = RE::QuoteMeta(unquoted);

Tenga en cuenta que es legal escapar un carácter incluso si no tiene un significado especial en una expresión regular; así que esta función hace eso. (Esto también la hace idéntica a la función perl del mismo nombre; consulte "perldoc -f quotemeta".) Por ejemplo, "1.5-2.0?" se convierte en "1\.5\-2\.0\?".

COINCIDENCIAS PARCIALES

Puede usar la operación "PartialMatch" cuando desee que el patrón coincida con cualquier subcadena del texto.


Ejemplo: búsqueda simple de una cadena:
pcrecpp::RE("ell").PartialMatch("hola");


Ejemplo: encontrar el primer número en una cadena:
int number;
pcrecpp::RE re("(\\d+)");
re.PartialMatch("x*100 + 20", &number);
assert(number == 100);

UTF-8 Y LA INTERFAZ DE COINCIDENCIA

Por defecto, el patrón y el texto son texto plano, un byte por carácter. La bandera UTF8, pasada al constructor, hace que tanto el patrón como la cadena se traten como texto UTF-8, todavía un flujo de bytes pero potencialmente múltiples bytes por carácter. En la práctica, es más probable que el texto sea UTF-8 que el patrón, pero la coincidencia devuelta puede depender de la bandera UTF8, así que siempre úsela al coincidir texto UTF8. Por ejemplo, "." coincidirá con un byte normalmente, pero con UTF8 establecido puede coincidir con hasta tres bytes de un carácter multibyte.


Ejemplo:
pcrecpp::RE_Options options;
options.set_utf8();
pcrecpp::RE re(utf8_pattern, options);
re.FullMatch(utf8_string);


Ejemplo: usando la función de conveniencia UTF8():
pcrecpp::RE re(utf8_pattern, pcrecpp::UTF8());
re.FullMatch(utf8_string);

NOTA: La bandera UTF8 se ignora si pcre no se configuró con la bandera
--enable-utf8.

PASO DE MODIFICADORES AL MOTOR DE EXPRESIÓN REGULAR

PCRE define algunos modificadores para cambiar el comportamiento del motor de expresión regular. El envoltorio C++ define una clase auxiliar, RE_Options, como vehículo para pasar dichos modificadores a una clase RE. Actualmente, se admiten los siguientes modificadores:


modificador descripción Perl correspondiente


PCRE_CASELESS coincidencia insensible a mayúsculas y minúsculas /i
PCRE_MULTILINE coincidencia de varias líneas /m
PCRE_DOTALL el punto coincide con saltos de línea /s
PCRE_DOLLAR_ENDONLY $ coincide solo al final N/A
PCRE_EXTRA análisis estricto de escape N/A
PCRE_EXTENDED ignora espacios en blanco /x
PCRE_UTF8 maneja caracteres UTF8 incorporado
PCRE_UNGREEDY invierte * y *? N/A
PCRE_NO_AUTO_CAPTURE deshabilita paréntesis de captura N/A (*)

(*) Tanto Perl como PCRE permiten paréntesis que no capturan mediante el modificador "?:" dentro del propio patrón. Por ejemplo, (?:ab|cd) no captura, mientras que (ab|cd) sí lo hace.

Para una descripción completa de cómo funciona cada modificador, consulte la página de referencia de la API de PCRE.

Para cada modificador, hay dos funciones miembro cuyo nombre se forma a partir del modificador en minúsculas, sin el prefijo "PCRE_". Por ejemplo, PCRE_CASELESS se maneja con


bool caseless()

que devuelve verdadero si el modificador está establecido, y


RE_Options & set_caseless(bool)

que establece o anula el modificador. Además, PCRE_EXTRA_MATCH_LIMIT se puede acceder a través de la [continúa en la página siguiente]

pcrecpp(3)

SINOPISIS DE LA ENVOLTURA DE C++

La biblioteca PCRE tiene una envoltorio C++ en el espacio de nombres pcrecpp.

    #include <pcrecpp.h>
    using namespace pcrecpp;
    ...
    RE re(pattern, options);
    re.Execute(text, ...);
    ...

DESCRIPCIÓN

Esta biblioteca proporciona una interfaz C++ de alto nivel para la biblioteca PCRE. Es más fácil de usar que la API C, aunque menos flexible.

INTERFAZ DE COINCIDENCIA

La clase RE tiene varios métodos para coincidir con expresiones regulares. Aquí hay un par de ejemplos:

FullMatch()
Comprueba si toda la cadena coincide con el patrón.

    RE re("(\\w+) (\\w+)");
    string s1, s2;
    if (re.FullMatch("hello world", &s1, &s2)) {
        // s1 == "hello", s2 == "world"
    }

PartialMatch()
Comprueba si la cadena coincide con el patrón en algún lugar.

    RE re("b+");
    if (re.PartialMatch("abcde")) {
        // Coincide
    }

Extract()
Busca coincidencias y extrae subcadenas coincidentes en variables.

    RE re("(\\w+) = (\\d+)");
    string var;
    int val;
    if (re.Extract("var = 123", &var, &val)) {
        // var == "var", val == 123
    }

CITANDO METACARACTERES

A veces es necesario coincidir con un carácter literal que tiene un significado especial en expresiones regulares (por ejemplo, un punto, un asterisco). La clase RE tiene un método estático QuoteMeta() para escapar de tales caracteres.

    string s = RE::QuoteMeta("a.b*c");
    // s == "a\\.b\\*c"

COINCIDENCIAS PARCIALES

Los métodos Match() y Find() son similares a PartialMatch() pero devuelven un resultado diferente. Si se produce una coincidencia, devuelven el número de subgrupos que coinciden; de lo contrario, devuelven -1. Si se proporcionan argumentos para capturar subgrupos, se rellenan con las subcadenas coincidentes.

    RE re("(\\w+) (\\w+)");
    string s1, s2;
    int matches = re.Match("hello cruel world", &s1, &s2);
    // matches == 2, s1 == "hello", s2 == "cruel"

Find() hace lo mismo, pero no requiere que la coincidencia comience en el principio de la cadena.

UTF-8 Y LA INTERFAZ DE COINCIDENCIA

Si su expresión regular o su texto de entrada contienen caracteres multibyte UTF-8, debe compilar la expresión regular con la opción UTF8(). Esto se puede hacer creando un objeto RE_Options y pasándolo al constructor RE.

    RE_Options options;
    options.set_utf8(true);
    RE re("[\\w-]", options);

Alternativamente, puede usar el modificador UTF8() para crear un objeto RE_Options preconfigurado.

    RE re("[\\w-]", RE_Options().set_utf8(true));

PASAR MODIFICADORES AL MOTOR DE EXPRESIÓN REGULAR

La mayoría de los modificadores estándar de PCRE están disponibles. Se pueden pasar al constructor RE mediante un objeto RE_Options.

Los modificadores disponibles incluyen:

  • CASELESS() (o icase()): ignora mayúsculas y minúsculas.
  • MULTILINE(): hace que ^ y $ coincidan con el principio y el final de cada línea dentro de la cadena.
  • DOTALL() (o dotsall()): hace que el carácter '.' coincida con todos los caracteres, incluidas las nuevas líneas.
  • EXTENDED() (o extended()): permite el espacio en blanco y los comentarios dentro de la expresión regular.
  • UTF8() (o utf8()): activa el modo UTF-8.

También puede establecer límites en la cantidad de trabajo que PCRE puede realizar estableciendo match_limit() y match_limit_recursion().

Por ejemplo, para limitar el número de coincidencias a 5000:

    RE_Options options;
    options.set_match_limit(5000);
    RE re(pattern, options);

Establecer match_limit() en un valor distinto de cero limitará la ejecución de pcre para evitar que haga cosas malas, como desbordar la pila o tardar una eternidad en devolver un resultado. Un valor de 5000 es suficiente para detener el desbordamiento de pila en una pila de hilos de 2 MB. Establecer match_limit() en cero deshabilita el límite de coincidencias. Alternativamente, puede llamar a match_limit_recursion(), que utiliza PCRE_EXTRA_MATCH_LIMIT_RECURSION para limitar la recursividad de PCRE. match_limit() limita el número de coincidencias que realiza PCRE; match_limit_recursion() limita la profundidad de la recursividad interna y, por lo tanto, la cantidad de pila utilizada.

Normalmente, para pasar uno o más modificadores a una clase RE, declara un objeto RE_Options, establece las opciones apropiadas y pasa este objeto a un constructor RE. Ejemplo:


RE_Options opt;
opt.set_caseless(true);
if (RE("HELLO", opt).PartialMatch("hello world")) ...

RE_options tiene dos constructores. El constructor predeterminado no toma argumentos y crea un conjunto de indicadores que están desactivados por defecto. El parámetro opcional option_flags es para facilitar la transferencia de código heredado de programas C. Esto le permite hacer


RE(pattern,
RE_Options(PCRE_CASELESS|PCRE_MULTILINE)).PartialMatch(str);

Sin embargo, el código nuevo es mejor hacerlo


RE(pattern,
RE_Options().set_caseless(true).set_multiline(true))
.PartialMatch(str);

Si va a pasar uno de los modificadores más utilizados, existen algunas funciones de conveniencia que devuelven una clase RE_Options con el modificador apropiado ya establecido: CASELESS(), UTF8(), MULTILINE(), DOTALL(), y EXTENDED().

Si necesita establecer varias opciones a la vez y no quiere pasar por las molestias de declarar un objeto RE_Options y establecer varias opciones, existe un método paralelo que le da esa capacidad sobre la marcha. Puede concatenar varias funciones miembro set_xxxxx(), ya que cada una de ellas devuelve una referencia a su objeto de clase. Por ejemplo, para pasar PCRE_CASELESS, PCRE_EXTENDED y PCRE_MULTILINE a una RE con una sola sentencia, puede escribir:


RE(" ^ xyz \\s+ .* blah$",
RE_Options()
.set_caseless(true)
.set_extended(true)
.set_multiline(true)).PartialMatch(sometext);

ESCANEANDO TEXTO INCREMENTALMENTE

La operación "Consume" puede ser útil si desea hacer coincidir repetidamente expresiones regulares al principio de una cadena y omitirlas a medida que coinciden. Esto requiere el uso del tipo "StringPiece", que representa un subrango de una cadena real. Al igual que RE, StringPiece se define en el espacio de nombres pcrecpp.


Ejemplo: leer líneas del formato "var = valor" de una cadena.
string contents = ...; // Llenar cadena de alguna manera
pcrecpp::StringPiece input(contents); // Envolver en un StringPiece


string var;
int value;
pcrecpp::RE re("(\\w+) = (\\d+)\n");
while (re.Consume(&input, &var, &value)) {
...;
}

Cada llamada exitosa a "Consume" establecerá "var/value" y también avanzará "input" para que apunte más allá del texto coincidente.

La operación "FindAndConsume" es similar a "Consume" pero no ancla su coincidencia al principio de la cadena. Por ejemplo, podría extraer todas las palabras de una cadena llamando repetidamente


pcrecpp::RE("(\\w+)").FindAndConsume(&input, &word)

ANALIZANDO NÚMEROS HEX/OCTAL/C-RADIX

Por defecto, si pasa un puntero a un valor numérico, el texto correspondiente se interpreta como un número base 10. En su lugar, puede envolver el puntero con una llamada a uno de los operadores Hex(), Octal() o CRadix() para interpretar el texto en otra base. El operador CRadix interpreta los prefijos de estilo C "0" (base 8) y "0x" (base 16), pero por defecto es base 10.


Ejemplo:
int a, b, c, d;
pcrecpp::RE re("(.*) (.*) (.*) (.*)");
re.FullMatch("100 40 0100 0x40",
pcrecpp::Octal(&a), pcrecpp::Hex(&b),
pcrecpp::CRadix(&c), pcrecpp::CRadix(&d));

dejará 64 en a, b, c y d.

REEMPLAZANDO PARTES DE CADENAS

Puede reemplazar la primera coincidencia de "patrón" en "str" con "reescritura". Dentro de "reescritura", los dígitos escapados con barra invertida (\1 a \9) se pueden usar para insertar texto coincidente con el grupo entre paréntesis correspondiente del patrón. \0 en "reescritura" se refiere a todo el texto coincidente. Por ejemplo:


string s = "yabba dabba doo";
pcrecpp::RE("b+").Replace("d", &s);

dejará "s" conteniendo "yada dabba doo". El resultado es verdadero si el patrón coincide y ocurre un reemplazo, falso en caso contrario.

GlobalReplace es como Replace excepto que reemplaza todas las ocurrencias del patrón en la cadena con la reescritura. Los reemplazos no están sujetos a re-coincidencia. Por ejemplo:


string s = "yabba dabba doo";
pcrecpp::RE("b+").GlobalReplace("d", &s);

dejará "s" conteniendo "yada dada doo". Devuelve el número de reemplazos realizados.

Extract es como Replace, excepto que si el patrón coincide, "reescritura" se copia en "out" (un argumento adicional) con sustituciones. Las porciones no coincidentes de "texto" se ignoran. Devuelve verdadero si y solo si ocurrió una coincidencia y la extracción se realizó correctamente; si no hay coincidencia, la cadena no se ve afectada.
