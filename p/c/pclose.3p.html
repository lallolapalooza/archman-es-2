PCLOSE(3P) Manual del programador POSIX PCLOSE(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pclose — cerrar un flujo de tubería hacia o desde un proceso

SINAPSIS

#include <stdio.h>
int pclose(FILE *stream);

DESCRIPCIÓN

La función pclose() cerrará un flujo que fue abierto por popen(), esperará a que el comando termine y devolverá el estado de terminación del proceso que estaba ejecutando el intérprete del lenguaje de comandos. Sin embargo, si una llamada hizo que el estado de terminación no estuviera disponible para pclose(), entonces pclose() devolverá -1 con errno establecido en [ECHILD] para informar de esta situación. Esto puede ocurrir si la aplicación llama a una de las siguientes funciones:

*
wait()
*
waitpid() con un argumento pid menor o igual a 0 o igual al ID del proceso del intérprete del lenguaje de comandos
*
Cualquier otra función no definida en este volumen de POSIX.1-2017 que pudiera hacer una de las anteriores

En cualquier caso, pclose() no devolverá antes de que el proceso hijo creado por popen() haya terminado.

Si el intérprete del lenguaje de comandos no se puede ejecutar, el estado de terminación del hijo devuelto por pclose() será como si el intérprete del lenguaje de comandos hubiera terminado usando exit(127) o _exit(127).

La función pclose() no afectará el estado de terminación de ningún hijo del proceso llamante, aparte del creado por popen() para el flujo asociado.

Si el argumento stream a pclose() no es un puntero a un flujo creado por popen(), el resultado de pclose() no está definido.

Si un hilo es cancelado durante la ejecución de pclose(), el comportamiento no está definido.

VALOR DE RETORNO

Tras una devolución exitosa, pclose() devolverá el estado de terminación del intérprete del lenguaje de comandos. De lo contrario, pclose() devolverá -1 y establecerá errno para indicar el error.

ERRORES

La función pclose() fallará si:

ECHILD
El estado del proceso hijo no pudo ser obtenido, como se describe anteriormente.

FUNDAMENTO

Existe el requisito de que pclose() no devuelva antes de que el proceso hijo termine. Esto tiene la intención de prohibir implementaciones que devuelvan [EINTR] si se recibe una señal mientras se espera. Si pclose() devolviera antes de que el hijo terminara, no habría forma para que la aplicación descubriera qué hijo estaba anteriormente asociado con el flujo, y no podría realizar la limpieza por sí misma.

Si el flujo apuntado por stream no fue creado por popen(), las implementaciones históricas de pclose() devuelven -1 sin establecer errno. Para evitar requerir que pclose() establezca errno en este caso, POSIX.1-2008 hace que el comportamiento no esté especificado. Una aplicación no debe usar pclose() para cerrar ningún flujo que no haya sido creado por popen().

Algunas implementaciones históricas de pclose() bloquean o ignoran las señales SIGINT, SIGQUIT y SIGHUP mientras esperan que el proceso hijo termine. Dado que este comportamiento no se describe para la función pclose() en POSIX.1-2008, tales implementaciones no son conformes. Además, algunas implementaciones históricas devuelven [EINTR] si se recibe una señal, aunque el proceso hijo no haya terminado. Tales implementaciones también se consideran no conformes.

Considere, por ejemplo, una aplicación que usa:

popen("command", "r")

para iniciar command, que es parte de la misma aplicación. El padre escribe un prompt en su salida estándar (presumiblemente el terminal) y luego lee del flujo abierto por popen(). El hijo lee la respuesta del usuario, realiza alguna transformación en la respuesta (expansión de ruta, quizás) y escribe el resultado en su salida estándar. El proceso padre lee el resultado de la tubería, hace algo con él y muestra otro prompt. El ciclo se repite. Suponiendo que ambos procesos realicen un vaciado de búfer apropiado, se esperaría que esto funcione.

Para cumplir con POSIX.1-2008, pclose() debe usar waitpid(), o alguna función similar, en lugar de wait().

El siguiente ejemplo de código ilustra cómo la función pclose() podría implementarse en un sistema que cumple con POSIX.1-2008.

int pclose(FILE *stream)
{
    int stat;
    pid_t pid;
    pid = <pid del proceso creado para stream por popen()>
    (void) fclose(stream);
    while (waitpid(pid, &stat, 0) == -1) {
        if (errno != EINTR){
            stat = -1;
            break;
        }
    }
    return(stat);
}
