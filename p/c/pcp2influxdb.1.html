PCP2INFLUXDB(1) Manual de comandos generales PCP2INFLUXDB(1)

NOMBRE

pcp2influxdb - exportador de métricas pcp a influxdb

SINOPSIS

pcp2influxdb [-CGHIjLnrRvV?] [-4 acción] [-8|-9 límite] [-a archivo] [-A alineación] [--archive-folio folio] [-b|-B escala-espacio] [-c config] [--container contenedor] [-D debug] [--daemonize] [-e derivado] [-E contraseña] [-g servidor] [-h host] [-i instancias] [-J rango] [-K espec] [-N predicado] [-O origen] [-P|-0 precisión] [-q|-Q escala-conteo] [-s muestras] [-S tiempocomienzo] [-t intervalo] [-T tiempofin] [-U usuario] [-x base de datos] [-X etiquetas] [-y|-Y escala-tiempo] especificación-métrica [...]

DESCRIPCIÓN

pcp2influxdb es una herramienta exportadora de métricas de rendimiento personalizable de PCP a InfluxDB. Cualquier métrica de rendimiento disponible, en vivo o archivada, del sistema y/o de la aplicación, puede ser seleccionada para exportar usando argumentos de línea de comandos o un archivo de configuración.

pcp2influxdb es un pariente cercano de pmrep(1). Consulte pmrep(1) para la descripción de especificación-métrica aceptada en la línea de comandos de pcp2influxdb. Vea pmrep.conf(5) para la descripción de la sintaxis del archivo de configuración pcp2influxdb.conf. Esta página describe las opciones específicas de pcp2influxdb y las diferencias del archivo de configuración con pmrep.conf(5). pmrep(1) también enumera algunos ejemplos de uso de los cuales la mayoría son aplicables también con pcp2influxdb.

Solo se admiten las opciones de línea de comandos listadas en esta página; otras opciones disponibles para pmrep(1) no son soportadas.

Las opciones a través de valores de entorno (ver pmGetOptions(3)) anulan los valores predeterminados integrados correspondientes (si los hay). Las opciones del archivo de configuración anulan las variables de entorno correspondientes (si las hay). Las opciones de línea de comandos anulan las opciones del archivo de configuración correspondientes (si las hay).

ARCHIVO DE CONFIGURACIÓN

pcp2influxdb utiliza un archivo de configuración con sintaxis descrita en pmrep.conf(5). Las siguientes opciones son comunes con pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. El resto de las opciones de pmrep.conf son reconocidas pero ignoradas por compatibilidad.

Opciones específicas de pcp2influxdb

influx_server (string)

Especifica el servidor InfluxDB de destino. La opción correspondiente de línea de comandos es -g. Predeterminado a http://127.0.0.1:8086.

influx_db (string)

Especifica la base de datos de métricas. La opción correspondiente de línea de comandos es -x. Predeterminado a pcp.

influx_user (string)

Especifica el nombre de usuario para la base de datos. La opción correspondiente de línea de comandos es -U. No definido por defecto (no se intenta autenticación).

influx_pass (string)

Especifica la contraseña para la base de datos. La opción correspondiente de línea de comandos es -E. No definido por defecto (no se intenta autenticación).

influx_tags (string)

Especifica una cadena de etiquetas para añadir a las métricas. La opción correspondiente de línea de comandos es -X. No definido por defecto.

OPCIONES

Las opciones de línea de comandos disponibles son:

-0 precisión, --precision-force=precisión
Similar a -P pero esta opción anulará las especificaciones por métrica.
-4 acción, --names-change=acción
Especifica qué acción tomar al recibir un evento de cambio de nombres de métricas durante el muestreo. Estos eventos ocurren cuando un PMDA descubre nuevas métricas después de un tiempo de haber iniciado, e informa a las herramientas cliente en ejecución como pcp2influxdb. Los valores válidos para acción son update (actualizar métricas que se están muestreando), ignore (no hacer nada - el comportamiento predeterminado) y abort (salir del programa si ocurre dicho evento).
-5, --ignore-unknown
Ignora silenciosamente cualquier nombre de métrica que no se pueda resolver. Se debe encontrar al menos una métrica para que la herramienta comience.
-8 límite, --limit-filter=límite
Limita los resultados a instancias con valores por encima/por debajo del límite. Un entero positivo incluirá instancias con valores iguales o superiores al límite en el informe. Un entero negativo incluirá instancias con valores iguales o inferiores al límite en el informe. Un valor de cero no realiza ningún filtrado por límite. Esta opción no anulará las posibles especificaciones por métrica. Ver también -J y -N.
-9 límite, --limit-filter-force=límite
Similar a -8 pero esta opción anulará las especificaciones por métrica.
-a archivo, --archive=archivo
Los valores de las métricas de rendimiento se obtienen del conjunto de archivos de archivo Performance Co-Pilot (PCP) identificados por el argumento archivo, que es una lista separada por comas de nombres, cada uno de los cuales puede ser el nombre base de un archivo o el nombre de un directorio que contiene uno o más archivos.
-A alineación, --align=alineación
Fuerza que la muestra inicial esté alineada en el límite de una unidad de tiempo natural alineación. Consulte PCPIntro(1) para una descripción completa de la sintaxis de alineación.
--archive-folio=folio
Lee los archivos de métricas de origen del folio de archivos PCP creado por herramientas como pmchart(1) o, con menos frecuencia, manualmente con mkaf(1).
-b escala, --space-scale=escala
Unidad/escala para métricas de espacio (bytes), los valores posibles incluyen bytes, Kbytes, KB, Mbytes, MB, etc. Esta opción no anulará las posibles especificaciones por métrica. Ver también pmParseUnitsStr(3).
-B escala, --space-scale-force=escala
Similar a -b pero esta opción anulará las especificaciones por métrica.
-c config, --config=config
Especifica el archivo o directorio de config a usar. En caso de que config sea un directorio, se incluirán todos los archivos que terminen en .conf. El valor predeterminado es el primero que se encuentre de: ./pcp2influxdb.conf, $HOME/.pcp2influxdb.conf, $HOME/pcp/pcp2influxdb.conf, y $PCP_SYSCONF_DIR/pcp2influxdb.conf. Para detalles, consulte la sección anterior y pmrep.conf(5).
--container=contenedor
Obtiene métricas de rendimiento del contenedor especificado, ya sea local o remoto (ver -h).
-C, --check
Sale antes de reportar cualquier valor, pero después de analizar la configuración y las métricas, e imprimir posibles encabezados.
--daemonize
Se ejecuta como demonio al inicio.
-e derivado, --derived= i>métricas derivadas
Especificar métricas de rendimiento derivadas. Si derivadas comienza con una barra (``/'') o con un punto (``.'') se interpretará como un archivo de configuración de métricas derivadas de PCP (PCP), de lo contrario se interpretará como expresiones de métricas derivadas separadas por comas o punto y coma. Para una descripción completa de las métricas derivadas y los archivos de configuración de métricas derivadas de PCP, consulte pmLoadDerivedConfig(3) y pmRegisterDerived(3). Alternativamente, el uso de la sintaxis de configuración pmrep.conf(5) permite definir métricas derivadas como parte de conjuntos de métricas (metricsets).

En caso de problemas con métricas derivadas, revise detalladamente las páginas del manual antes mencionadas y asegúrese de que todas las métricas requeridas estén disponibles, especialmente al usar archivos (archives). Use -Dderive para ver información de depuración adicional sobre el análisis de métricas derivadas.

-E contraseña, --db-pass=contraseña
Especificar la contraseña de la base de datos.
-g servidor, --db-server=servidor
Servidor InfluxDB de destino servidor.
-G, --no-globals
No incluir métricas globales en el informe (ver pmrep.conf(5)).
-h host, --host=host
Obtener métricas de rendimiento de pmcd(1) en el host, en lugar de en localhost (predeterminado).
-H, --no-header
No imprimir ningún encabezado.
-i instancias, --instances=instancias
Recuperar e informar solo las instancias de métricas especificadas. Por defecto se informan todas las instancias, presentes y futuras.

Consulte pmrep(1) para obtener una descripción completa de esta opción.

-I, --ignore-incompat
Ignorar métricas incompatibles. Por defecto, las métricas incompatibles (es decir, cuyo tipo no es compatible o no se pueden escalar como se solicita) harán que pcp2influxdb termine con un mensaje de error. Con esta opción, todas las métricas incompatibles se omiten silenciosamente del informe. Esto puede ser especialmente útil al solicitar nodos no terminales del árbol PMNS para el informe.
-j, --live-filter
Realizar filtrado en vivo de instancias. Esto permite capturar todas las instancias nombradas incluso si los procesos se reinician en algún momento (a diferencia de sin filtrado en vivo). Realizar filtrado en vivo sobre una gran cantidad de instancias agregará cierta sobrecarga interna, por lo que se recomienda precaución por parte del usuario. Ver también -n.
-J rango, --rank=rango
Limitar los resultados a las instancias de métricas con valores de conjunto de mayor/menor rango. Un entero positivo incluirá las instancias de mayor valor en el informe. Un entero negativo incluirá las instancias de menor valor en el informe. Un valor de cero no realiza ningún ranking. El ranking no implica ordenación, ver -6. Ver también -8.
-K espec, --spec-local=espec
Al obtener métricas de un contexto local (ver -L), la opción -K se puede usar para controlar los PMDA de DSO que deben hacerse accesibles. El argumento espec se ajusta a la sintaxis descrita en pmSpecLocalPMDA(3). Se puede usar más de una opción -K.
-L, --local-PMDA
Usar un contexto local para recopilar métricas de los PMDA de DSO en el host local sin PMCD. Ver también -K.
-n, --invert-filter
Realizar el ranking antes del filtrado en vivo. Por defecto, el filtrado en vivo de instancias (cuando se solicita, ver -j) ocurre antes del ranking de instancias (cuando se solicita, ver -J). Con esta opción, la lógica se invierte y el ranking ocurre antes del filtrado en vivo.
-N predicado, --predicate=predicado
Especificar una lista separada por comas de métricas de referencia de filtro predicado. Por defecto, el ranking (ver -J) se realiza para cada métrica individualmente. Con predicados, el ranking se realiza solo para las métricas de predicado especificadas. Al informar, el resto de las métricas que comparten el mismo dominio de instancia (ver PCPIntro(1)) que el predicado incluirán solo las instancias de mayor/menor rango del predicado correspondiente. El ranking no implica ordenación, ver -6.

Por ejemplo, utilizando proc.memory.rss (tamaño de memoria residente del proceso) como métrica de predicado junto con proc.io.total_bytes y mem.util.used como métricas a informar, solo se incluirán los procesos que usan la mayor/menor cantidad de memoria (según -J) al informar los bytes totales escritos por los procesos. Dado que mem.util.used es una métrica de valor único (por lo tanto, no comparte el mismo dominio de instancia que las métricas relacionadas con el proceso), se informará como de costumbre.

-O origen, --origin=origen
Al informar métricas de archivo, comience el informe en el origen dentro de la ventana de tiempo (ver -S y -T). Consulte PCPIntro(1) para obtener una descripción completa de la sintaxis para origen.
-P precisión, --precision=precisión
Usar precisión para valores de salida numéricos no enteros. El valor predeterminado es usar 3 decimales (cuando sea aplicable). Esta opción no anulará las especificaciones posibles por métrica.
-q escala, --count-scale=escala
Unidad/escala para métricas de recuento, los valores posibles incluyen count x 10^-1, count, count x 10, count x 10^2, y así sucesivamente desde 10^-8 hasta 10^7. (Estos valores son actualmente sensibles al espacio). Esta opción no anulará las especificaciones posibles por métrica. Ver también pmParseUnitsStr(3).
-Q escala, --count-scale-force=escala
Similar a -q, pero esta opción anulará las especificaciones por métrica.
-r, --raw
Mostrar valores brutos de métricas, no convertir contadores acumulativos a tasas. Esta opción anulará las especificaciones posibles por métrica.
-R, --raw-prefer
Similar a -r, pero esta opción no anulará las especificaciones por métrica.
-s muestras, --samples=muestras
El argumento muestras define el número de muestras a recuperar y reportar. Si muestras es 0 o no se especifica -s, pcp2influxdb tomará muestras e informará continuamente (en modo de tiempo real) o hasta el final del conjunto de archivos PCP (en modo de archivo). Ver también -T.
-S horainicio, --start=horainicio
Al informar métricas de archivo, el informe se limitará a aquellos registros registrados en o después de la horainicio. Consulte PCPIntro(1) para obtener una descripción completa de la sintaxis para horainicio.
-t intervalo, --interval=intervalo
Establecer el intervalo de informe a algo diferente del segundo predeterminado (1). El argumento intervalo sigue la sintaxis descrita en PCPIntro(1), y en su forma más simple puede ser un entero sin signo (las unidades implícitas en este caso son segundos). Ver también la opción -T.
-T horafin, --finish=horafin
Al informar métricas de archivo, el informe se limitará a aquellos registros registrados antes o en la horafin. Consulte PCPIntro(1) para obtener una descripción completa de la sintaxis para horafin.

Cuando se usa para definir el tiempo de ejecución antes de que pcp2influxdb salga, si no se proporciona ninguna muestra (ver -s), entonces el número de muestras reportadas depende del intervalo (ver -t). Si se proporcionan muestras, el intervalo se ajustará para permitir la notificación de muestras durante el tiempo de ejecución. En caso de que se proporcionen -T, -s y -t, la horafin determinará el tiempo real que se ejecutará pcp2influxdb.

-U usuario, --db-user=usuario
Especificar el usuario de la base de datos.
-v, --omit-flat
Informar solo métricas de conjunto con instancias (por ejemplo, disk.dev.read) y omitir métricas "planas" de valor único sin instancias (por ejemplo, kernel.all.sysfork). Ver -i y -I.
-V, --version
Mostrar número de versión y salir.
-x base de datos, --db-name=base de datos
Especificar el nombre de la base de datos de métricas.
-X etiquetas, --db-tags=etiquetas
Especificar cadenas de etiquetas para agregar a las métricas.
-y escala, --time-scale=escala
Unidad/escala para métricas de tiempo, los valores posibles incluyen nanosec, ns, microsec, us, millisec, ms, y así sucesivamente hasta hour, hr. Esta opción no anulará las especificaciones posibles por métrica. Ver también pmParseUnitsStr(3).
-Y escala, --time-scale-force=escala
Similar a -y, pero esta opción anulará las especificaciones por métrica.
-?, --help
Mostrar mensaje de uso y salir.

pcp2influxdb(1) — PCP Performance Co-Pilot

NAME

pcp2influxdb

extract Performance Co-Pilot (PCP) metrics and export them to InfluxDB

SYNOPSIS

pcp2influxdb [-c config] [-D debug] [-h] [-H host] [-i instance] [-l logfile] [-p] [-S port] [-t time] [-u] [-v] [-w width] [--help] [--version]

DESCRIPTION

The pcp2influxdb utility is a specialized Performance Co-Pilot (PCP) pmrep(1) client that extracts performance metrics from the PCP collector(s) and exports them to an InfluxDB time-series database.

It relies on a configuration file to define which metrics to collect, how to transform them, and how to map them to InfluxDB measurements and tags.

See pmrep(1) for a general description of the pmrep client interface, metric selection syntax, and command line options.

CONFIGURATION FILE

The primary configuration file for pcp2influxdb is specified using the -c option. If not specified, the default configuration file is $PCP_SYSCONF_DIR/pcp2influxdb.conf.

The configuration file uses a format similar to pmrep.conf(5), but with additional sections for InfluxDB specific settings.

Key sections include:

  • influxdb: Defines connection details for the InfluxDB server (host, port, database, user, password, retention policy, etc.).
  • metrics: Defines the PCP metrics to be collected, their aliases, and how they map to InfluxDB measurements and tags. This section can include filtering and transformation rules.

Refer to the example configuration file for detailed syntax and options.

OPTIONS

In addition to the options described in pmrep(1), pcp2influxdb supports the following:

-c config
Specify the configuration file to use. If not provided, the default configuration file $PCP_SYSCONF_DIR/pcp2influxdb.conf will be used.
-D debug
Enable debugging output. See the DEBUGGING OPTIONS section below.
-h
Print a short help message and exit.
-H host
Connect to the InfluxDB server at the specified host. This overrides the host specified in the configuration file.
-i instance
Specify an instance qualifier to filter metrics. This is useful when dealing with metrics that have multiple instances (e.g., network interfaces).
-l logfile
Write log messages to the specified logfile. By default, log messages are written to stderr.
-p
Pretty-print the output (useful for debugging).
-S port
Connect to the InfluxDB server on the specified port. This overrides the port specified in the configuration file.
-t time
Fetch metrics for the specified time. The format is the same as for pmrep(1). This option is generally not used when running as a daemon.
-u
Run as a daemon, continuously exporting metrics at the specified interval.
-v
Print version information and exit.
-w width
Set the output width for metric names. Defaults to 80 characters.
--help
Print a detailed help message and exit.
--version
Print version information and exit.

FILES

$PCP_SYSCONF_DIR/pcp2influxdb.conf
The default configuration file for pcp2influxdb. This file can be overridden using the -c option.
$PCP_SYSCONF_DIR/pmrep/*.conf
System-provided default configuration files for pmrep.

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

Of particular note, PCP_DISCRETE_ONCE can be set to ensure that discrete metric values are reported only once, unless they change at some point.

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.
