NOMBRE

pcilmr - Margen de enlaces PCIe

SINOPSIS

pcilmr [--margin] [<opciones comunes>] <puerto de enlace> [<opciones de enlace>] [<puerto de enlace> [<opciones de enlace>] ...]
pcilmr --full [<opciones comunes>]
pcilmr --scan

CONFIGURACIÓN

Lista de los requisitos para los enlaces y la configuración del sistema para ejecutar la prueba de márgenes.

Configuración de la BIOS (depende del sistema, relevante para placas base de servidor con CPU Xeon):

•
Desactivar la función de cubo de fugas de PCIe, la re-ecualización y la degradación del enlace;
•
Establecer los umbrales de error en 0;
•
Intel VMD para SSD NVMe: en caso de comportamiento extraño de pcilmr, intente ejecutarlo con VMD desactivado.

Requisitos del dispositivo (enlace):

Configurado por el usuario antes de ejecutar la utilidad, la utilidad no los cambia:
•
La velocidad de datos del enlace actual debe ser de 16.0 GT/s o superior (actualmente la utilidad soporta enlaces de 16 GT/s y 32 GT/s);
•
El componente de enlace descendente debe estar en el estado de gestión de energía D0.
Configurado por la utilidad durante la operación, la utilidad los devuelve a su estado original después de recibir los resultados:
•
ASPM debe estar deshabilitado tanto en el Puerto Descendente como en el Puerto Ascendente;
•
El bit de deshabilitación de velocidad autónoma de hardware del registro de control de enlace 2 debe estar establecido tanto en el Puerto Descendente como en el Puerto Ascendente;
•
El bit de deshabilitación autónoma de ancho de hardware del registro de control de enlace debe estar establecido tanto en el Puerto Descendente como en el Puerto Ascendente.

DESCRIPCIÓN

La utilidad pcilmr permite aprovechar la capacidad de Margen de Línea PCIe en el Receptor, que es obligatoria para todos los Puertos que soportan una velocidad de datos de 16.0 GT/s o superior, incluyendo los Pseudo Puertos (Retimers). Margen de Línea en el Receptor permite al software del sistema obtener información de margen de un Receptor dado mientras el Enlace está en el estado L0. La información de margen incluye voltaje y tiempo, en cualquier dirección desde la posición actual del Receptor. El soporte de margen para el tiempo es obligatorio, mientras que el soporte para el voltaje es opcional a 16.0 GT/s y obligatorio a 32.0 GT/s y velocidades de datos superiores. Además, el margen de tiempo independiente y el margen de voltaje independiente son opcionales.

La utilidad permite obtener una aproximación del diagrama de ojo de margen en forma de rombo (mediante cuatro puntos). La capacidad de Margen de Línea en el Receptor permite a los usuarios evaluar los enlaces PCIe sin un depurador de hardware y sin necesidad de detener el sistema objetivo. La utilidad puede ser útil para depurar problemas de enlace debido a márgenes del receptor.

pcilmr requiere privilegios de root (para acceder al Espacio de Configuración Extendida), pero durante nuestras pruebas no hubo problemas con los dispositivos y estos volvieron exitosamente a su estado inicial normal después de finalizar las pruebas.

CALIFICACIÓN DE RESULTADOS

La especificación PCIe proporciona valores de referencia para el diagrama de ojo, que también son utilizados por pcilmr para evaluar los resultados, pero parece que tiene sentido contactar al fabricante de un dispositivo en particular para obtener referencias.

La utilidad utiliza los valores establecidos en la Sección 8.4.2 de la Especificación Base PCIe Rev. 5.0 como referencias mínimas por defecto de ancho y altura del ojo. Los valores recomendados se tomaron de la Especificación de Pruebas de Cumplimiento Eléctrico del Transmisor de la Arquitectura PCIe Rev 5.0.

Los valores de calificación de referencia utilizados actualmente por la utilidad se presentan en la siguiente tabla:

16 GT/s (Gen 4) 32 GT/s (Gen 5)
EW EH EW EH
Min 18.75 ps 30% UI 15 mV 9.375 ps 30% UI 15 mV
Rec 23.75 ps 38% UI 21 mV 10.157 ps 33% UI 19.75 mV

pcilmr utiliza valores completos de ancho y altura del ojo para calificar los carriles. Sin embargo, es posible que el dispositivo solo admita el margen de un lado. En tales casos, por defecto, la utilidad calculará EW o EH como el doble del resultado de un lado.

Si hay información disponible para un dispositivo específico, puede configurar los criterios de calificación y ajustar el comportamiento de la utilidad en casos de un solo lado para su dispositivo utilizando la opción específica del enlace -g (ver más abajo).

SOPORTE DE OBSERVACIONES DE HARDWARE

Gracias a las pruebas o directamente a la documentación del fabricante, sabemos que algunos dispositivos requieren un tratamiento especial durante el marging. La utilidad detecta tales dispositivos basándose en su par ID de Vendedor - ID de Dispositivo. Actualmente, la lista de dispositivos especiales está codificada en el archivo margin_hw. Para tales dispositivos, la utilidad puede ajustar automáticamente los parámetros de margen del puerto o las opciones de calificación.

Por ejemplo, para los puertos RC de CPU Ice Lake, pcilmr cambiará el valor MaxVoltageOffset del dispositivo y forzará el uso del modo de calificación 'un lado es el todo'.

OPCIONES

Especificador de dispositivo

Puede especificar el Puerto Descendente o Ascendente del Enlace.

<dispositivo/componente>
[<dominio>:]<bus>:<dev>.<func> (ver lspci(8))

Modos de utilidad

--margin <componente descendente> ...
Evalúa los enlaces seleccionados.
--full
Evalúa todos los enlaces del sistema listos para probar (en un sentido similar a la opción --scan) (uno por uno).
--scan
Busca enlaces con una velocidad negociada de 16 GT/s o superior. Marca como "Listo" aquellos en los que al menos uno de los lados del enlace tiene el bit Margining Ready configurado, lo que significa que estos enlaces están listos para la prueba y puede ejecutar la utilidad en ellos.

Opciones Comunes de Margen (para todos los enlaces especificados)

-c Muestra solo las Capacidades de Margen de Línea del Dispositivo. No realiza el margen.

-e <errores>
Especifica el Límite de Recuento de Errores para el margen.
Por defecto: 4.
-o <directorio>
Guarda los resultados del margen en formato CSV en el directorio especificado. La utilidad generará un archivo con el nombre en forma de "lmr_<puerto>_Rx#_<marca de tiempo>.csv" para cada receptor probado con éxito.
-d <tiempo>

NAME

pcilmr — PCI Express Lane Margining at Receiver utility

SYNOPSIS

pcilmr [options] [device]

CONFIGURATION

The device is specified by the PCI bus address (e.g. 0000:0a:00.0) or by PCI class name (e.g. PCI bridge controller). If no device is specified, the utility tries to find a suitable device automatically.

DESCRIPTION

This utility performs PCIe Lane Margining at Receiver test. It is intended to determine the maximum possible timing and voltage margins of PCIe links. The test is defined in the PCI Express Base Specification, chapter 7.3.9.

A PCIe link is defined by a specific device and a lane number. The utility automates the process of setting margining parameters and gathering results.

RESULTS GRADING

The utility can apply grading criteria to the results of lane margining test. This allows automatic determination whether the tested link is capable of operating at given parameters.

The grading criteria can be specified using the -g option.

-g <recvn>t=<criteria>{%|ps}[,f]
Specify pass/fail grading criteria for eye width (timing - t).
<recvn> is the receiver number.
<criteria> is the minimum eye width in percent of UI (% UI) or picoseconds (ps).
The optional flag f indicates that the measurement is for one side only (see description of the -p option).
-g <recvn>t=f[,<criteria>{%|ps}]
Same as above, but the f flag is specified first.
-g <recvn>v=<criteria>[,f]
Specify pass/fail grading criteria for eye height (voltage - v).
<recvn> is the receiver number.
<criteria> is the minimum eye height in millivolts (mV).
The optional flag f indicates that the measurement is for one side only (see description of the -p option).
-g <recvn>v=f[,<criteria>]
Same as above, but the f flag is specified first.

The grading criteria are used to determine whether the link passes or fails the margining test. If no criteria are specified, the utility will simply report the maximum possible margins.

HARDWARE QUIRKS SUPPORT

Some hardware components may require specific adjustments to perform lane margining correctly. The utility supports several hardware quirks that can be enabled using the -Q option.

-Q <quirk>[,<quirk>...]
Enable one or more hardware quirks. Supported quirks include:

  • retimer: Enables margining for retimers. This is required for some devices that use retimers to extend PCIe links.

  • nvlink: Enables margining for NVLink connections. This is specific to NVIDIA GPUs and allows margining of NVLink interconnects.

  • pvhub: Enables margining for PCIe Virtual Hubs. This quirk is necessary for devices that act as PCIe Virtual Hubs.

Example: -Q retimer,nvlink

OPTIONS

The following options are available:

-o <format>
Specify output format. Supported formats are:

  • csv: Comma-separated values.

  • json: JSON format.

  • txt: Plain text format (default).

-d <seconds>
Specify dwell time in seconds for the margining step.
Default: 1 s

Margining Link specific options

-l <lane>[,<lane>...]
Specify lanes for margining.
Remember that Device may use Lane Reversal for Lane numbering. However, utility uses logical lane numbers in arguments and for logging. Utility will automatically determine Lane Reversal and tune its calls.
Default: all link lanes.
-r <recvn>[,<recvn>...]
Specify Receivers to select margining targets.
Default: all available Receivers (including Retimers).
-p <parallel_lanes>
Specify number of lanes to margin simultaneously.
According to spec it's possible for Receiver to margin up to MaxLanes + 1 lanes simultaneously, but during testing, performing margining on several lanes simultaneously led to results that were different from sequential margining, so this feature requires additional verification and -p option right now is for experiments mostly.
Default: 1.

Use only one of -T/-t options at the same time (same for -V/-v).
Without these options utility will use MaxSteps from Device capabilities as test limit.

-T
Time Margining will continue until the Error Count is no more than an Error Count Limit. Use this option to find Link limit.
-t <steps>
Specify maximum number of steps for Time Margining.
-V
Same as -T option, but for Voltage.
-v <steps>
Specify maximum number of steps for Voltage Margining.
-g <recvn>t=<criteria>{%|ps}[,f]
<recvn>t=f[,<criteria>{%|ps}]
<recvn>v=<criteria>[,f]
<recvn>v=f[,<criteria>]
Specify pass/fail grading criteria for eye width (timing - t) or height (voltage - v) for one of the link receivers. For EW you must choose one of the units (% UI or ps), for EH mV is used.
Additional flag f is for situations when port doesn't support two side independent margining. In such cases by default utility will calculate EW or EH as a double one side result. You can add f flag for -g option to tell the utility that the result in one direction is actually the measurement of the full eye and it does not need to be multiplied. This is so called 'one side is the whole' grading mode.

EXAMPLES

Utility syntax example:

pcilmr -o csv ab:0.0 -r 1,6 -g 1t=20% -g 1v=f,30 52:0.0 -l 0,1,2 -TV

Examples of collected results on different systems.
