PCAP_GET_SELECTABLE_FD(3PCAP) PCAP_GET_SELECTABLE_FD(3PCAP)

NOMBRE

pcap_get_selectable_fd - obtener un descriptor de archivo en el que se pueda realizar un select() para una captura en vivo

SINOPSIS

#include <pcap/pcap.h>
int pcap_get_selectable_fd(pcap_t *p);

DESCRIPCIÓN

pcap_get_selectable_fd() devuelve, en UNIX, un número de descriptor de archivo para un descriptor de archivo en el que se puede realizar una llamada select(2), poll(2), epoll_wait(2), kevent(2), o similar para esperar a que sea posible leer paquetes sin bloquear, si existe dicho descriptor, o -1, si no existe ningún descriptor de este tipo.

Algunos dispositivos de red abiertos con pcap_create(3PCAP) y pcap_activate(3PCAP), o con pcap_open_live(3PCAP), no admiten esas llamadas (por ejemplo, dispositivos de red normales en FreeBSD 4.3 y 4.4, y dispositivos Endace DAG), por lo que se devuelve -1 para esos dispositivos. En ese caso, a esas llamadas se les debe dar un tiempo de espera menor o igual al tiempo de espera devuelto por pcap_get_required_select_timeout(3PCAP) para el dispositivo para el que pcap_get_selectable_fd() devolvió -1, el dispositivo se debe poner en modo no bloqueante con una llamada a pcap_setnonblock(3PCAP), y siempre se debe intentar leer paquetes del dispositivo cuando la llamada regrese. Si pcap_get_required_select_timeout() devuelve NULL, no es posible esperar a que lleguen paquetes al dispositivo en un bucle de eventos.

Tenga en cuenta que un dispositivo en el que se puede realizar una lectura sin bloquear puede, en algunas plataformas, no tener ningún paquete para leer si el tiempo de espera del búfer de paquetes ha expirado. Una llamada a pcap_dispatch(3PCAP) o pcap_next_ex(3PCAP) devolverá 0 en este caso, pero no se bloqueará.

Tenga en cuenta que en:

FreeBSD anterior a FreeBSD 4.6;
NetBSD anterior a NetBSD 3.0;
OpenBSD anterior a OpenBSD 2.4;
Mac OS X anterior a Mac OS X 10.7;

select(), poll(), y kevent() no funcionan correctamente en dispositivos BPF; pcap_get_selectable_fd() devolverá un descriptor de archivo en la mayoría de esas versiones (las excepciones son FreeBSD 4.3 y 4.4), pero una simple llamada a select(), poll(), o kevent() no indicará que el descriptor es legible hasta que se reciba un paquete completo, incluso si el tiempo de espera del paquete expira antes. Para solucionar esto, el código que utiliza estas llamadas para esperar a que lleguen paquetes debe poner el pcap_t en modo no bloqueante, y debe organizarse para que la llamada tenga un tiempo de espera menor o igual al tiempo de espera del búfer de paquetes, y debe intentar leer paquetes después de que expire ese tiempo de espera, independientemente de si la llamada indicó que el descriptor de archivo para el pcap_t está listo para ser leído o no. (Esa solución alternativa no funcionará en FreeBSD 4.3 y posteriores; sin embargo, en FreeBSD 4.6 y posteriores, esas llamadas funcionan correctamente en dispositivos BPF, por lo que la solución alternativa no es necesaria, aunque no causa daño.)

Tenga en cuenta también que poll() y kevent() no funcionan en archivos especiales de caracteres, incluidos los dispositivos BPF, en Mac OS X 10.4 y 10.5, por lo que, si bien select() se puede usar en el descriptor devuelto por pcap_get_selectable_fd(), poll() y kevent() no se pueden usar en él en esas versiones de Mac OS X. poll(), pero no kevent(), funciona en ese descriptor en las versiones de Mac OS X anteriores a la 10.4; poll() y kevent() funcionan en ese descriptor en Mac OS X 10.6 y posteriores.

pcap_get_selectable_fd() no está disponible en Windows.

VALOR DE RETORNO

Se devuelve un descriptor de archivo seleccionable si existe uno; de lo contrario, se devuelve -1.

VER TAMBIÉN
