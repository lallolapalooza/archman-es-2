NOMBRE

PCRE - expresiones regulares compatibles con Perl

GUARDAR Y REUTILIZAR PATRONES PCRE PRECOMPILADOS

Si está ejecutando una aplicación que utiliza un gran número de patrones de expresiones regulares, puede ser útil almacenarlos en un formato precompilado en lugar de tener que compilarlos cada vez que se ejecuta la aplicación. Si no utiliza tablas de caracteres privadas (consulte la documentación de pcre_maketables()), esto es relativamente sencillo. Si utiliza tablas privadas, es un poco más complicado. Sin embargo, si está utilizando la función de optimización just-in-time, no es posible guardar y recargar los datos JIT.

Si guarda patrones compilados en un archivo, puede copiarlos a un host diferente y ejecutarlos allí. Si los dos hosts tienen una ordenación de bytes diferente (endianness), debería ejecutar la función pcre[16|32]_pattern_to_host_byte_order() en el nuevo host antes de intentar hacer coincidir el patrón. Las funciones de coincidencia devuelven PCRE_ERROR_BADENDIANNESS si detectan un patrón con la ordenación de bytes incorrecta.

Compilar expresiones regulares con una versión de PCRE para usarla con una versión diferente no garantiza que funcione y puede provocar bloqueos, y guardar y restaurar un patrón compilado pierde los datos de optimización JIT.

GUARDAR UN PATRÓN COMPILADO

El valor devuelto por pcre[16|32]_compile() apunta a un único bloque de memoria que contiene el patrón compilado y los datos asociados. Puede encontrar la longitud de este bloque en bytes llamando a pcre[16|32]_fullinfo() con un argumento de PCRE_INFO_SIZE. A continuación, puede guardar los datos de la manera que considere oportuna. Aquí hay un código de ejemplo para la biblioteca de 8 bits que compila un patrón y lo escribe en un archivo. Asume que la variable fd hace referencia a un archivo abierto para salida:


int erroroffset, rc, size;
char *error;
pcre *re;


re = pcre_compile("mi patrón", 0, &error, &erroroffset, NULL);
if (re == NULL) { ... manejar errores ... }
rc = pcre_fullinfo(re, NULL, PCRE_INFO_SIZE, &size);
if (rc < 0) { ... manejar errores ... }
rc = fwrite(re, 1, size, fd);
if (rc != size) { ... manejar errores ... }

En este ejemplo, los bytes que componen el patrón compilado se copian exactamente. Tenga en cuenta que se trata de datos binarios que pueden contener cualquiera de los 256 valores de byte posibles. En sistemas que distinguen entre datos binarios y no binarios, asegúrese de que el archivo se abre para salida binaria.

Si desea escribir más de un patrón en un archivo, tendrá que idear una forma de separarlos. Para datos binarios, preceder cada patrón con su longitud es probablemente el enfoque más sencillo. Otra posibilidad es escribir los datos en hexadecimal en lugar de binario, un patrón por línea.

Guardar patrones compilados en un archivo es solo una forma posible de almacenarlos para su uso posterior. Podrían almacenarse igualmente en una base de datos o en la memoria de algún proceso demonio que los pase a través de sockets a los procesos que los necesiten.

Si el patrón ha sido estudiado, también es posible guardar los datos normales de estudio de manera similar al patrón compilado. Sin embargo, si se utilizó PCRE_STUDY_JIT_COMPILE, los datos just-in-time que se crean no se pueden guardar porque dependen demasiado del entorno actual. Cuando el estudio genera información adicional, pcre[16|32]_study() devuelve un puntero a un bloque de datos pcre[16|32]_extra. Su formato se define en la sección sobre cómo hacer coincidir un patrón en la documentación de pcreapi. El campo study_data apunta a los datos de estudio binarios, y esto es lo que debe guardar (no el bloque pcre[16|32]_extra en sí). La longitud de los datos de estudio se puede obtener llamando a pcre[16|32]_fullinfo() con un argumento de PCRE_INFO_STUDYSIZE. Recuerde comprobar que pcre[16|32]_study() devolvió un valor distinto de NULL antes de intentar guardar los datos de estudio.

REUTILIZAR UN PATRÓN PRECOMPILADO

Reutilizar un patrón precompilado es sencillo. Después de haberlo recargado en la memoria principal, haber llamado a pcre[16|32]_pattern_to_host_byte_order() si es necesario, pasa su puntero a pcre[16|32]_exec() o pcre[16|32]_dfa_exec() de la forma habitual.

Sin embargo, si pasó un puntero a tablas de caracteres personalizadas cuando se compiló el patrón (el argumento tableptr de pcre[16|32]_compile()), ahora debe pasar un puntero similar a pcre[16|32]_exec() o pcre[16|32]_dfa_exec(), porque el valor guardado con el patrón compilado obviamente no tendrá sentido. Un campo en un bloque pcre[16|32]_extra() se utiliza para pasar estos datos, como se describe en la sección sobre cómo hacer coincidir un patrón en la documentación de pcreapi.

Advertencia: Las tablas que utilizan pcre_exec() y pcre_dfa_exec() deben ser las mismas que se utilizaron cuando se compiló el patrón. Si no es así, el comportamiento es indefinido.

Si no proporcionó tablas de caracteres personalizadas cuando se compiló el patrón, el puntero en el patrón compilado es NULL, lo que hace que las funciones de coincidencia utilicen las tablas internas de PCRE. Por lo tanto, no necesita tomar ninguna medida especial en tiempo de ejecución en este caso.

Si guardó datos de estudio con el patrón compilado, necesita crear su propio bloque de datos pcre[16|32]_extra y establecer el campo study_data para que apunte a los datos de estudio recargados. También debe establecer el bit PCRE_EXTRA_STUDY_DATA en el campo flags para indicar que hay datos de estudio presentes. Luego, pase el bloque pcre[16|32]_extra a la función de coincidencia de la forma habitual. Si el patrón se estudió para optimización just-in-time, esos datos no se pueden guardar, y por lo tanto se pierden en un ciclo de guardado/restauración.

COMPATIBILIDAD CON DIFERENTES VERSIONES DE PCRE

En general, lo más seguro es recompilar todos los patrones guardados al actualizar a una nueva versión de PCRE, aunque no todas las actualizaciones lo requieren realmente.
