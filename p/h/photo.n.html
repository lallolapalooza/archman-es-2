photo(n) Comandos integrados de Tk photo(n)

NOMBRE

photo - Imágenes a todo color

SINOPSIS

image create photo ?nombre? ?opciones?
nombreImagen blank
nombreImagen cget opción
nombreImagen configure ?opción? ?valor opción valor ...?
nombreImagen copy imagenOrigen ?opción valor(es) ...?
nombreImagen data ?opción valor(es) ...?
nombreImagen get x y
nombreImagen put datos ?opción valor(es) ...?
nombreImagen read archivo ?opción valor(es) ...?
nombreImagen redither
nombreImagen transparency subcomando ?arg arg ...?
nombreImagen write archivo ?opción valor(es) ...?

DESCRIPCIÓN

Una foto es una imagen cuyos píxeles pueden mostrar cualquier color o ser transparentes. Una imagen de tipo foto se almacena internamente a todo color (32 bits por píxel) y se muestra utilizando difuminado (dithering) si es necesario. Los datos de la imagen para una imagen de tipo foto se pueden obtener de un archivo o una cadena, o se pueden suministrar desde código C a través de una interfaz procedural. Actualmente, solo se soportan los formatos PNG, GIF y PPM/PGM, pero existe una interfaz para permitir la fácil adición de formatos de archivo de imagen adicionales. Una imagen de tipo foto es transparente en regiones donde no se han proporcionado datos de imagen o donde se ha establecido como transparente mediante el subcomando transparency set.

CREACIÓN DE FOTOS

Al igual que todas las imágenes, las fotos se crean utilizando el comando image create. Las fotos soportan las siguientes opciones:

-data cadena
Especifica el contenido de la imagen como una cadena. La cadena debe contener datos binarios o, para algunos formatos, datos codificados en base64 (esto se garantiza actualmente para los formatos PNG y GIF). El formato de la cadena debe ser uno de aquellos para los que existe un manejador de formato de archivo de imagen que acepte datos en cadena. Si se especifican tanto la opción -data como la -file, la opción -file tiene precedencia.
-format nombre-formato
Especifica el nombre del formato de archivo para los datos especificados con la opción -data o -file.
-file nombre
nombre proporciona el nombre de un archivo que se leerá para obtener datos para la imagen de tipo foto. El formato del archivo debe ser uno de aquellos para los que existe un manejador de formato de archivo de imagen que pueda leer datos.
-gamma valor
Especifica que los colores asignados para mostrar esta imagen en una ventana deben corregirse para una pantalla no lineal con el valor de exponente gamma especificado. (La intensidad producida por la mayoría de las pantallas CRT es una función de potencia del valor de entrada, con buena aproximación; gamma es el exponente y suele ser alrededor de 2). El valor especificado debe ser mayor que cero. El valor predeterminado es uno (sin corrección). En general, los valores mayores que uno harán la imagen más clara y los valores menores que uno la harán más oscura.
-height número
Especifica la altura de la imagen, en píxeles. Esta opción es útil principalmente en situaciones donde el usuario desea construir el contenido de la imagen pieza por pieza. Un valor de cero (el predeterminado) permite que la imagen se expanda o contraiga verticalmente para ajustarse a los datos almacenados en ella.
-palette especificación-paleta
Especifica la resolución del cubo de colores a asignar para mostrar esta imagen, y por lo tanto, el número de colores utilizados de los mapas de colores de las ventanas donde se muestra. La cadena especificación-paleta puede ser un solo número decimal, especificando el número de tonos de gris a usar, o tres números decimales separados por barras (/), especificando el número de tonos de rojo, verde y azul a usar, respectivamente. Si se usa la primera forma (un solo número), la imagen se mostrará en monocromo (es decir, en escala de grises).
-width número
Especifica el ancho de la imagen, en píxeles. Esta opción es útil principalmente en situaciones donde el usuario desea construir el contenido de la imagen pieza por pieza. Un valor de cero (el predeterminado) permite que la imagen se expanda o contraiga horizontalmente para ajustarse a los datos almacenados en ella.

COMANDO IMAGEN

Cuando se crea una imagen de tipo foto, Tk también crea un nuevo comando cuyo nombre es el mismo que el de la imagen. Este comando se puede utilizar para invocar varias operaciones en la imagen. Tiene la siguiente forma general:

nombreImagen opción ?arg arg ...?
Opción y los arg determinan el comportamiento exacto del comando.

Aquellas opciones que escriben datos en la imagen generalmente expanden el tamaño de la imagen, si es necesario, para acomodar los datos escritos en ella, a menos que el usuario haya especificado valores distintos de cero para las opciones de configuración -width y/o -height, en cuyo caso el ancho y/o la altura, respectivamente, de la imagen no se modificarán.

Los siguientes comandos son posibles para las imágenes de tipo foto:

nombreImagen blank
Borra la imagen; es decir, establece toda la imagen para que no tenga datos, de modo que se mostrará como transparente, y el fondo de cualquier ventana en la que se muestre se verá a través.
nombreImagen cget opción
Devuelve el valor actual de la opción de configuración dada por opción. Opción puede tener cualquiera de los valores aceptados por el comando image create photo.
nombreImagen configure ?opción? ?valor opción valor ...?
Consulta o modifica las opciones de configuración para la imagen. Si no se especifica ninguna opción, devuelve una lista que describe todas las opciones disponibles para nombreImagen (consulte Tk_ConfigureInfo para obtener información sobre el formato de esta lista). Si se especifica opción sin valor, el comando devuelve una lista que describe la opción nombrada (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica opción). Si se especifican uno o más pares opción-valor, el comando modifica la(s) opción(es) dada(s) para que tengan el(los) valor(es) dado(s); en este caso, el comando devuelve una cadena vacía. Opción puede tener cualquiera de los valores aceptados por el comando image create photo.
nombreImagen copy imagenOrigen ?opción valor(es) ...?
Copia una región de la imagen llamada imagenOrigen (que debe ser una imagen de tipo foto) a la imagen llamada nombreImagen, posiblemente con escalado y/o submuestreo de píxeles. Si no se especifican opciones, este comando copia la totalidad de imagenOrigen en nombreImagen, comenzando en las coordenadas (0,0) en nombreImagen. Las siguientes opciones pueden especificarse:
-from x1 y1 x2 y2
Especifica una subregión rectangular de la imagen de origen a copiar. (x1,y1) y (x2,y2) especifican esquinas opuestas del rectángulo. Si x2 e y2 no se especifican, el valor predeterminado es la esquina inferior derecha de la imagen de origen. Los píxeles copiados incluirán los bordes izquierdo y superior del rectángulo especificado, pero no los bordes inferior o derecho. Si no se proporciona la opción -from, el predeterminado es toda la imagen de origen.
-to x1 y1 x2 y2
Especifica una subregión rectangular de la imagen de destino a afectar. (x1,y1) y (x2,y2) especifican esquinas opuestas del rectángulo. Si x2 e y2 no se especifican, el valor predeterminado es (x1,y1) más el tamaño de la región de origen (después del submuestreo y escalado, si se especifican). Si se especifican x2 e y2, la región de origen se repetirá si es necesario para llenar la región de destino de forma en mosaico.
-shrink
Especifica que el tamaño de la imagen de destino

nombreImagen data ?opción valor(es) ...?
Devuelve datos de imagen en forma de cadena. Se pueden especificar las siguientes opciones:
-background color
Si se especifica el color, los datos no contendrán información de transparencia. Todos los píxeles transparentes se reemplazarán por el color especificado.
-format nombre-formato
Especifica el nombre del manejador de formato de archivo de imagen que se utilizará. Específicamente, este subcomando busca el primer manejador cuyo nombre coincida con una subcadena inicial de nombre-formato y que tenga la capacidad de escribir una cadena que contenga estos datos de imagen. Si no se proporciona esta opción, este subcomando utiliza un formato que consiste en una lista (un elemento por fila) de listas (un elemento por píxel/columna) de colores en formato “#rrggbb” (donde rr es un par de dígitos hexadecimales para el canal rojo, gg para el verde y bb para el azul).
-from x1 y1 x2 y2
Especifica una región rectangular de nombreImagen a devolver. Si solo se especifican x1 e y1, la región se extiende desde (x1,y1) hasta la esquina inferior derecha de nombreImagen. Si se proporcionan las cuatro coordenadas, especifican esquinas opuestas en diagonal de la región rectangular, incluyendo x1,y1 y excluyendo x2,y2. El valor predeterminado, si no se proporciona esta opción, es toda la imagen.
-grayscale
Si se especifica esta opción, los datos no contendrán información de color. Todos los datos de píxeles se transformarán a escala de grises.
nombreImagen get x y
Devuelve el color del píxel en las coordenadas (x,y) de la imagen como una lista de tres enteros entre 0 y 255, que representan los componentes rojo, verde y azul, respectivamente.
nombreImagen put datos ?opción valor(es) ...?
Establece los píxeles en nombreImagen con los datos especificados en datos. Este comando primero busca en la lista de manejadores de formato de archivo de imagen un manejador que pueda interpretar los datos en datos, y luego lee la imagen codificada en nombreImagen (la imagen de destino). Si datos no coincide con ningún formato conocido, se intenta interpretarlo como una lista (de arriba a abajo) de líneas de escaneo, siendo cada línea de escaneo una lista (de izquierda a derecha) de colores de píxeles (consulte Tk_GetColor para obtener una descripción de los colores válidos). Cada línea de escaneo debe tener la misma longitud. Tenga en cuenta que cuando datos es un solo nombre de color, está indicando a Tk que rellene una región rectangular con ese color. Se pueden especificar las siguientes opciones:
-format nombre-formato
Especifica el formato de los datos de imagen en datos. Específicamente, solo se utilizarán los manejadores de formato de archivo de imagen cuyos nombres comiencen con nombre-formato al buscar un manejador de formato de datos de imagen para leer los datos.
-to x1 y1 ?x2 y2?
Especifica las coordenadas de la esquina superior izquierda (x1,y1) de la región de nombreImagen en la que se copiarán los datos de imagen. La posición predeterminada es (0,0). Si se proporcionan x2,y2 y datos no es lo suficientemente grande como para cubrir el rectángulo especificado por esta opción, los datos de imagen extraídos se embaldosarán para cubrir todo el rectángulo de destino. Tenga en cuenta que si datos especifica un único valor de color, se rellenará una región que se extienda hasta la esquina inferior derecha representada por (x2,y2) con ese color.
nombreImagen read nombreArchivo ?opción valor(es) ...?
Lee datos de imagen del archivo llamado nombreArchivo en la imagen. Este comando primero busca en la lista de manejadores de formato de archivo de imagen un manejador que pueda interpretar los datos en nombreArchivo, y luego lee la imagen en nombreArchivo en nombreImagen (la imagen de destino). Se pueden especificar las siguientes opciones:
-format nombre-formato
Especifica el formato de los datos de imagen en nombreArchivo. Específicamente, solo se utilizarán los manejadores de formato de archivo de imagen cuyos nombres comiencen con nombre-formato al buscar un manejador de formato de datos de imagen para leer los datos.
-from x1 y1 x2 y2
Especifica una subregión rectangular de los datos del archivo de imagen a copiar en la imagen de destino. Si solo se especifican x1 e y1, la región se extiende desde (x1,y1) hasta la esquina inferior derecha de la imagen en el archivo de imagen. Si se especifican las cuatro coordenadas, especifican esquinas opuestas en diagonal de la región. El valor predeterminado, si no se especifica esta opción, es toda la imagen en el archivo de imagen.
-shrink
Si esta opción, el tamaño de nombreImagen se reducirá, si es necesario, para que la región en la que se leen los datos del archivo de imagen quede en la esquina inferior derecha de nombreImagen. Esta opción no afectará al ancho o alto de la imagen si el usuario ha especificado un valor distinto de cero para la opción de configuración -width o -height, respectivamente.
-to x y
Especifica las coordenadas de la esquina superior izquierda de la región de nombreImagen en la que se leerán los datos de nombreArchivo. El valor predeterminado es (0,0).
nombreImagen redither
El algoritmo de dithering utilizado en la visualización de imágenes fotográficas propaga los errores de cuantización de un píxel a sus vecinos. Si los datos de imagen para nombreImagen se suministran en fragmentos, la imagen dithered puede no ser exactamente correcta. Normalmente la diferencia no es notable, pero si es un problema, este comando se puede utilizar para recuperar la imagen dithered en cada ventana donde se muestre la imagen.
nombreImagen transparency subcomando ?arg arg ...?
Permite examinar y manipular la información de transparencia en la imagen fotográfica. Hay varios subcomandos disponibles:
nombreImagen transparency get x y
Devuelve un booleano que indica si el píxel en (x,y) es transparente.
nombreImagen transparency set x y booleano
Hace que el píxel en (x,y) sea transparente si booleano es verdadero, y hace que ese píxel sea opaco de lo contrario.
nombreImagen write nombreArchivo ?opción valor(es) ...?
Escribe datos de imagen desde nombreImagen a un archivo llamado nombreArchivo. Se pueden especificar las siguientes opciones:
-background color
Si se especifica el color, los datos no contendrán información de transparencia. Todos los píxeles transparentes se reemplazarán por el color especificado.
-format nombre-formato
Especifica el nombre del manejador de formato de archivo de imagen que se utilizará para escribir los datos en el archivo. Específicamente, este subcomando busca el primer manejador cuyo nombre coincida con una subcadena inicial de nombre-formato y que tenga la capacidad de escribir un archivo de imagen. Si no se proporciona esta opción, el formato se adivina a partir de la extensión del archivo. Si eso no se puede determinar, este subcomando utiliza el primer manejador que tenga la capacidad de escribir un archivo de imagen.
-from x1 y1 x2 y2
Especifica una región rectangular de nombreImagen a escribir en el archivo de imagen. Si solo se especifican x1 e y1, la región se extiende desde (x1,y1) hasta la esquina inferior derecha de nombreImagen. Si se proporcionan las cuatro coordenadas, especifican esquinas opuestas en diagonal de la región rectangular. El valor predeterminado, si no se proporciona esta opción, es toda la imagen.

NAME

photo - Tk photo image type

SYNOPSIS

image create photo ?name? ?options?
image delete ?name ...?
image put photoImage ?index? data
image height image
image width image
image type image

DESCRIPTION

The photo image type is used to manage image data that is not stored in a standard GIF or PPM file. It supports loading image data from files or from strings, and can then be used with Tk widgets that display images, such as the -image option of buttons, labels, and canvases. It also supports writing image data to files.

The photo image type is implemented as a Tk image type, similar to the bitmap and bitmap image types.

CREATING PHOTOS

A photo image is created using the image create photo command. The command takes an optional name for the image, and a list of configuration options. The most common options are:

-file fileName
Specifies the name of the file from which to load the image data. The file is expected to be in one of the formats supported by the photo image type (e.g., PPM, GIF, PNG). If this option is specified, the -data option is ignored.
-data string
Specifies image data in string format. The string should contain the raw image data, in one of the formats supported by the photo image type. This is often used for image data embedded within a script or generated dynamically.
-format formatName
Specifies the format of the image data given by the -file or -data options. If this option is omitted, the photo image code attempts to automatically determine the format. The format name comparison is case-insensitive. See the IMAGE FORMATS section for details.
-gamma gammaValue
Adjusts the gamma correction of the image. The gammaValue must be a floating-point number. A value of 1.0 means no correction. Values less than 1.0 brighten the image, while values greater than 1.0 darken it.
-palette paletteSpec
Controls the color allocation for the image. The paletteSpec can be a single integer specifying the maximum number of shades for each primary color (e.g., -palette 8), or three integers separated by slashes specifying the number of shades for red, green, and blue respectively (e.g., -palette 8/8/4). If a single number is given, it forces the image to be displayed in grayscale on color displays. See the COLOR ALLOCATION section for details.

IMAGE COMMAND

The image command can be used to manipulate photo images after they have been created. The following commands are relevant:

photoImage copy sourceImage ?-to x y? ?-shrink?
Copies the contents of sourceImage into photoImage. sourceImage can be another photo image or a bitmap image. The coordinates x and y specify the top-left corner of the destination in photoImage. If -to is omitted, the origin (0,0) is used. The -shrink option causes the destination image to be shrunk to fit within the specified area if it is larger. This is useful for tiling background images.
-grayscale
If this option is specified, the data will not contain color information. All pixel data will be transformed into grayscale.

IMAGE FORMATS

The photo image code is structured to allow handlers for additional image file formats to be added easily. The photo image code maintains a list of these handlers. Handlers are added to the list by registering them with a call to Tk_CreatePhotoImageFormat. The standard Tk distribution comes with handlers for PPM/PGM, PNG and GIF formats, which are automatically registered on initialization.

When reading an image file or processing string data specified with the -data configuration option, the photo image code invokes each handler in turn until one is found that claims to be able to read the data in the file or string. Usually this will find the correct handler, but if it does not, the user may give a format name with the -format option to specify which handler to use. In fact the photo image code will try those handlers whose names begin with the string specified for the -format option (the comparison is case-insensitive). For example, if the user specifies -format gif, then a handler named GIF87 or GIF89 may be invoked, but a handler named JPEG may not (assuming that such handlers had been registered).

When writing image data to a file, the processing of the -format option is slightly different: the string value given for the -format option must begin with the complete name of the requested handler, and may contain additional information following that, which the handler can use, for example, to specify which variant to use of the formats supported by the handler. Note that not all image handlers may support writing transparency data to a file, even where the target image format does.

FORMAT SUBOPTIONS

Some image formats support sub-options, which are specified at the time that the image is loaded using additional words in the -format option. At the time of writing, the following are supported:

gif -index indexValue
When parsing a multi-part GIF image, Tk normally only accesses the first image. By giving the -index sub-option, the indexValue'th value may be used instead. The indexValue must be an integer from 0 up to the number of image parts in the GIF data.
png -alpha alphaValue
An additional alpha filtering for the overall image, which allows the background on which the image is displayed to show through. This usually also has the effect of desaturating the image. The alphaValue must be between 0.0 and 1.0.

COLOR ALLOCATION

When a photo image is displayed in a window, the photo image code allocates colors to use to display the image and dithers the image, if necessary, to display a reasonable approximation to the image using the colors that are available. The colors are allocated as a color cube, that is, the number of colors allocated is the product of the number of shades of red, green and blue.

Normally, the number of colors allocated is chosen based on the depth of the window. For example, in an 8-bit PseudoColor window, the photo image code will attempt to allocate seven shades of red, seven shades of green and four shades of blue, for a total of 198 colors. In a 1-bit StaticGray (monochrome) window, it will allocate two colors, black and white. In a 24-bit DirectColor or TrueColor window, it will allocate 256 shades each of red, green and blue. Fortunately, because of the way that pixel values can be combined in DirectColor and TrueColor windows, this only requires 256 colors to be allocated. If not all of the colors can be allocated, the photo image code reduces the number of shades of each primary color and tries again.

The user can exercise some control over the number of colors that a photo image uses with the -palette configuration option. If this option is used, it specifies the maximum number of shades of each primary color to try to allocate. It can also be used to force the image to be displayed in shades of gray, even on a color display, by giving a single number rather than three numbers separated by slashes.

CREDITS

The photo image type was designed and implemented by Paul Mackerras, based on his earlier photo widget and some suggestions from John Ousterhout.

EXAMPLE

Load an image from a file and tile it to the size of a window, which is useful for producing a tiled background:

# These lines should be called once
image create photo untiled -file "theFile.ppm"
image create photo tiled
# These lines should be called whenever .someWidget changes
# size; a <Configure> binding is useful here
set width  [winfo width .someWidget]
set height [winfo height .someWidget]
tiled copy untiled -to 0 0 $width $height -shrink

The PNG image loader allows the application of an additional alpha factor during loading, which is useful for generating images suitable for disabled buttons:

image create photo icon -file "icon.png"
image create photo iconDisabled -file "icon.png" \
        -format "png -alpha 0.5"
button .b -image icon -disabledimage iconDisabled
