NOMBRE

pg_receivewal - transmitir registros de escritura anticipada (WAL) desde un servidor PostgreSQL

SINOPSIS

pg_receivewal [opción...]

DESCRIPCIÓN

pg_receivewal se utiliza para transmitir el registro de escritura anticipada (WAL) desde un clúster de PostgreSQL en ejecución. El WAL se transmite utilizando el protocolo de replicación de transmisión y se escribe en un directorio local de archivos. Este directorio se puede usar como ubicación de archivo para realizar una restauración utilizando la recuperación puntual (ver Sección 25.3).

pg_receivewal transmite el WAL en tiempo real a medida que se genera en el servidor y no espera a que se completen los segmentos como lo hacen archive_command y archive_library. Por esta razón, no es necesario configurar archive_timeout cuando se utiliza pg_receivewal.

A diferencia del receptor WAL de un servidor standby de PostgreSQL, pg_receivewal, por defecto, vacía los datos WAL solo cuando se cierra un archivo WAL. Se debe especificar la opción --synchronous para vaciar los datos WAL en tiempo real. Dado que pg_receivewal no aplica WAL, no debes permitir que se convierta en un standby síncrono cuando synchronous_commit es igual a remote_apply. Si lo hace, parecerá un standby que nunca se pone al día y provocará que los confirmaciones de transacciones se bloqueen. Para evitar esto, debes configurar un valor apropiado para synchronous_standby_names, o especificar application_name para pg_receivewal que no coincida con él, o cambiar el valor de synchronous_commit a algo distinto de remote_apply.

El WAL se transmite a través de una conexión PostgreSQL normal y utiliza el protocolo de replicación. La conexión debe realizarse con un usuario que tenga permisos de REPLICATION (ver Sección 21.2) o un superusuario, y pg_hba.conf debe permitir la conexión de replicación. El servidor también debe configurarse con max_wal_senders establecido lo suficientemente alto como para dejar al menos una sesión disponible para la transmisión.

El punto de inicio de la transmisión del WAL se calcula cuando se inicia pg_receivewal:

1. Primero, escanea el directorio donde se escriben los archivos de segmento WAL y encuentra el archivo de segmento completado más reciente, utilizando como punto de partida el inicio del siguiente archivo de segmento WAL.
2. Si no se puede calcular un punto de inicio con el método anterior, y si se utiliza una ranura de replicación, se emite un comando adicional READ_REPLICATION_SLOT para recuperar el restart_lsn de la ranura para usarlo como punto de inicio. Esta opción solo está disponible cuando se transmiten WAL desde PostgreSQL 15 y superior.
3. Si no se puede calcular un punto de inicio con el método anterior, se utiliza la última ubicación de vaciado de WAL informada por el servidor en un comando IDENTIFY_SYSTEM.

Si la conexión se pierde, o si no se puede establecer inicialmente, con un error no fatal, pg_receivewal intentará reconectar indefinidamente y restablecerá la transmisión tan pronto como sea posible. Para evitar este comportamiento, use el parámetro -n.

En ausencia de errores fatales, pg_receivewal se ejecutará hasta que sea terminado por la señal SIGINT (Control+C) o SIGTERM.

OPCIONES

-D directorio
--directory=directorio

Directorio donde escribir la salida.

Este parámetro es obligatorio.

-E lsn
--endpos=lsn

Detener automáticamente la replicación y salir con el estado de salida normal 0 cuando la recepción alcance el LSN especificado.

Si hay un registro con LSN exactamente igual a lsn, el registro se procesará.

--if-not-exists

No generar un error cuando se especifica --create-slot y ya existe una ranura con el nombre especificado.

-n
--no-loop

No repetir en caso de errores de conexión. En su lugar, salir inmediatamente con un error.

--no-sync

Esta opción hace que pg_receivewal no fuerce el vaciado de los datos WAL al disco. Esto es más rápido, pero significa que un fallo posterior del sistema operativo puede dejar los segmentos WAL corruptos. En general, esta opción es útil para pruebas, pero no debe utilizarse al archivar WAL en una implementación de producción.

Esta opción es incompatible con --synchronous.

-s intervalo
--status-interval=intervalo

Especifica el número de segundos entre paquetes de estado enviados de vuelta al servidor. Esto permite una monitorización más fácil del progreso desde el servidor. Un valor de cero deshabilita completamente las actualizaciones de estado periódicas, aunque se enviará una actualización cuando la solicite el servidor, para evitar desconexiones por tiempo de espera. El valor predeterminado es 10 segundos.

-S slotname
--slot=slotname

Requerir que pg_receivewal utilice una ranura de replicación existente (ver Sección 26.2.6). Cuando se utiliza esta opción, pg_receivewal informará una posición de vaciado al servidor, indicando cuándo se han sincronizado cada segmento en el disco para que el servidor pueda eliminar ese segmento si no se necesita de otra manera.

Cuando el cliente de replicación de pg_receivewal está configurado en el servidor como un standby síncrono, el uso de una ranura de replicación informará la posición de vaciado al servidor, pero solo cuando se cierre un archivo WAL. Por lo tanto, esa configuración hará que las transacciones en el primario esperen durante mucho tiempo y, efectivamente, no funcionen de manera satisfactoria. La opción --synchronous (ver abajo) debe especificarse además para que esto funcione correctamente.

--synchronous

Vaciar los datos WAL al disco inmediatamente después de recibirlos. También enviar un paquete de estado de vuelta al servidor inmediatamente después del vaciado, independientemente de --status-interval.

Esta opción debe especificarse si el cliente de replicación de pg_receivewal está configurado en el servidor como un standby síncrono, para asegurar que se envíe retroalimentación oportuna al servidor.

-v
--verbose

Habilita el modo detallado.

-Z nivel
-Z método[:detalle]
--compress=nivel
--compress=método[:detalle]

Habilita la compresión de los registros de escritura anticipada.

El método de compresión se puede establecer en gzip, lz4 (si PostgreSQL fue compilado con --with-lz4) o none para no comprimir. Opcionalmente, se puede especificar una cadena de detalle de compresión. Si la cadena de detalle es un entero, especifica el nivel de compresión. De lo contrario, debe ser una lista separada por comas de elementos, cada uno de la forma palabra clave o palabra clave=valor. Actualmente, la única palabra clave admitida es level.

Si no se especifica ningún nivel de compresión, se utilizará el nivel de compresión predeterminado. Si solo se especifica un nivel sin mencionar un algoritmo, se utilizará la compresión gzip si el nivel es mayor que 0, y no se utilizará compresión si el nivel es 0.

El sufijo .gz se agregará automáticamente a todos los nombres de archivo cuando se use gzip, y el sufijo .lz4 se agregará cuando se use lz4.

-d cadena_conexión
--dbname=cadena_conexión

Especifica los parámetros utilizados para conectarse al servidor, como una cadena de conexión; estos anularán cualquier opción de línea de comandos conflictiva.

Esta opción se llama --dbname por coherencia con otras aplicaciones cliente, pero dado que pg_receivewal no se conecta a ninguna base de datos en particular del clúster, cualquier nombre de base de datos incluido en la cadena de conexión será ignorado por el servidor. Sin embargo, un nombre de base de datos proporcionado de esa manera anula el nombre de base de datos predeterminado (replication) a efectos de buscar la contraseña de la conexión de replicación en ~/.pgpass. Del mismo modo, middleware o proxies utilizados para conectarse a PostgreSQL pueden utilizar el nombre para fines como el enrutamiento de conexiones.

--host=host

El valor predeterminado se toma de la variable de entorno PGHOST, si está configurada, de lo contrario se intenta una conexión por socket de dominio Unix.

NOMBRE

pg_receivewal – recibe archivos WAL de una base de datos PostgreSQL física

SINOPSIS

pg_receivewal [connection-option...] [option...]

DESCRIPCIÓN

pg_receivewal es una utilidad para recibir archivos de WAL (Write-Ahead Log) de un servidor PostgreSQL. Está diseñado para ser utilizado como un método de backup de WAL, ya sea directamente por el usuario o como una alternativa a archive_command. Los archivos WAL se guardan en el directorio especificado por la opción -D. pg_receivewal se ejecutará continuamente, recibiendo y guardando los archivos WAL a medida que se generan en el servidor.

pg_receivewal soporta el uso de slots de replicación física para asegurar que los archivos WAL no sean reciclados por el servidor antes de que puedan ser recibidos. Se recomienda encarecidamente el uso de slots de replicación.

OPCIONES

pg_receivewal acepta las siguientes opciones de línea de comandos:

-D directorio
--directory=directorio
Especifica el directorio donde se guardarán los archivos WAL recibidos. pg_receivewal creará el directorio si no existe. Esta opción es obligatoria.
-f archivo
--file=archivo
Envía los archivos WAL recibidos a archivo en lugar de a un directorio. Esta opción solo se puede usar con --create-slot y --drop-slot.
-p puerto
--port=puerto
Especifica el puerto TCP en el que el servidor está escuchando las conexiones. Por defecto, se usa la variable de entorno PGPORT, si está definida, o un valor predeterminado compilado.
-h host
--host=host
Especifica el nombre de host o la dirección IP de la máquina en la que está ejecutándose el servidor. El valor predeterminado es el obtenido de la variable de entorno PGHOST, si está definida, o una conexión local por socket Unix si no se especifica ni host ni puerto.
-U usuario
--username=usuario
Nombre de usuario para conectarse.
-w
--no-password
Nunca solicitar una contraseña. Si el servidor requiere autenticación por contraseña y no hay una contraseña disponible por otros medios, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para introducir una contraseña.
-W
--password
Fuerza a pg_receivewal a solicitar una contraseña antes de conectarse a una base de datos.

Esta opción nunca es esencial, ya que pg_receivewal solicitará automáticamente una contraseña si el servidor la exige. Sin embargo, pg_receivewal desperdiciará un intento de conexión al averiguar que el servidor quiere una contraseña. En algunos casos, vale la pena escribir -W para evitar el intento de conexión adicional.

pg_receivewal puede realizar una de las siguientes dos acciones para controlar los slots de replicación física:

--create-slot

Crea un nuevo slot de replicación física con el nombre especificado en --slot, y luego sale.

--drop-slot

Elimina el slot de replicación con el nombre especificado en --slot, y luego sale.

También están disponibles otras opciones:

-V

--version
Imprime la versión de pg_receivewal y sale.

-?

--help
Muestra la ayuda sobre los argumentos de la línea de comandos de pg_receivewal y sale.

ESTADO DE SALIDA

pg_receivewal saldrá con el estado 0 cuando sea terminado por la señal SIGINT o SIGTERM. (Esa es la forma normal de terminarlo. Por lo tanto, no es un error). Para errores fatales u otras señales, el estado de salida será distinto de cero.

AMBIENTE

Esta utilidad, como la mayoría de las otras utilidades de PostgreSQL, utiliza las variables de entorno compatibles con libpq (ver Sección 32.15).

La variable de entorno PG_COLOR especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son always, auto y never.

NOTAS

Al utilizar pg_receivewal en lugar de archive_command o archive_library como método principal de backup de WAL, se recomienda encarecidamente el uso de slots de replicación. De lo contrario, el servidor es libre de reciclar o eliminar archivos de write-ahead log antes de que sean respaldados, ya que no tiene información, ya sea de archive_command o archive_library o de los slots de replicación, sobre hasta dónde se ha archivado el stream de WAL. Tenga en cuenta, sin embargo, que un slot de replicación llenará el espacio en disco del servidor si el receptor no se mantiene al día con la obtención de los datos de WAL.

pg_receivewal preservará los permisos de grupo en los archivos WAL recibidos si los permisos de grupo están habilitados en el clúster de origen.

EJEMPLOS

Para transmitir el write-ahead log desde el servidor en mydbserver y almacenarlo en el directorio local /usr/local/pgsql/archive:

$ pg_receivewal -h mydbserver -D /usr/local/pgsql/archive
