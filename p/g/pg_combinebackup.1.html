PG_COMBINEBACKUP(1) Documentación de PostgreSQL 18.1 PG_COMBINEBACKUP(1)

NOMBRE

pg_combinebackup - reconstruye una copia de seguridad completa a partir de una copia de seguridad incremental y copias de seguridad dependientes

SINOPSIS

pg_combinebackup [opción...] [directorio_copia_seguridad...]

DESCRIPCIÓN

pg_combinebackup se utiliza para reconstruir una copia de seguridad completa sintética a partir de una copia de seguridad incremental y las copias de seguridad anteriores de las que depende.

Especifique todas las copias de seguridad requeridas en la línea de comandos de la más antigua a la más nueva. Es decir, el primer directorio de copia de seguridad debe ser la ruta a la copia de seguridad completa, y el último debe ser la ruta a la copia de seguridad incremental final que desea restaurar. La copia de seguridad reconstruida se escribirá en el directorio de salida especificado por la opción -o.

pg_combinebackup intentará verificar que las copias de seguridad especificadas forman una cadena de copias de seguridad legal de la cual se puede reconstruir una copia de seguridad completa correcta. Sin embargo, no está diseñado para ayudarle a rastrear qué copias de seguridad dependen de qué otras copias de seguridad. Si elimina una o más de las copias de seguridad anteriores de las que depende su copia de seguridad incremental, no podrá restaurarla. Además, pg_combinebackup solo intenta verificar que las copias de seguridad tienen la relación correcta entre sí, no que cada copia de seguridad individual está intacta; para eso, use pg_verifybackup(1).

Dado que la salida de pg_combinebackup es una copia de seguridad completa sintética, puede utilizarse como entrada para una invocación futura de pg_combinebackup. La copia de seguridad completa sintética se especificaría en la línea de comandos en lugar de la cadena de copias de seguridad de las que se reconstruyó.

OPCIONES

-d
--debug

Imprime mucha salida de registro de depuración en stderr.

-k
--link

Utiliza enlaces duros en lugar de copiar archivos a la copia de seguridad sintética. La reconstrucción de la copia de seguridad sintética puede ser más rápida (sin copiar archivos) y utilizar menos espacio en disco, pero se debe tener cuidado al usar el directorio de salida, ya que cualquier modificación en ese directorio (por ejemplo, iniciar el servidor) también puede afectar a los directorios de entrada. De manera similar, los cambios en los directorios de entrada (por ejemplo, iniciar el servidor en la copia de seguridad completa) podrían afectar al directorio de salida. Por lo tanto, esta opción se utiliza mejor cuando los directorios de entrada son solo copias que se eliminarán después de que pg_combinebackup haya completado.

Requiere que las copias de seguridad de entrada y el directorio de salida estén en el mismo sistema de archivos.

Si no hay un manifiesto de copia de seguridad disponible o no contiene una suma de verificación del tipo correcto, de todos modos se crearán enlaces duros, pero el archivo también se leerá bloque por bloque para el cálculo de la suma de verificación.

-n
--dry-run

La opción -n/--dry-run indica a pg_combinebackup que determine qué se haría sin crear realmente el directorio de destino ni ningún archivo de salida. Es especialmente útil en combinación con --debug.

-N
--no-sync

Por defecto, pg_combinebackup esperará a que todos los archivos se escriban de forma segura en disco. Esta opción hace que pg_combinebackup regrese sin esperar, lo cual es más rápido, pero significa que un fallo posterior del sistema operativo puede dejar la copia de seguridad de salida corrupta. En general, esta opción es útil para pruebas, pero no debe usarse al crear una instalación de producción.

-o directorio_salida
--output=directorio_salida

Especifica el directorio de salida al que se debe escribir la copia de seguridad completa sintética. Actualmente, este argumento es obligatorio.

-T dir_antiguo=dir_nuevo
--tablespace-mapping=dir_antiguo=dir_nuevo

Reubica el tablespace en el directorio dir_antiguo a dir_nuevo durante la copia de seguridad. dir_antiguo es la ruta absoluta del tablespace tal como existe en la copia de seguridad final especificada en la línea de comandos, y dir_nuevo es la ruta absoluta a utilizar para el tablespace en la copia de seguridad reconstruida. Si alguna ruta necesita contener un signo igual (=), preceda ese signo con una barra invertida. Esta opción se puede especificar varias veces para varios tablespaces.

--clone

Utiliza clonación de archivos eficiente (también conocida como "reflinks" en algunos sistemas) en lugar de copiar archivos al nuevo directorio de datos, lo que puede resultar en una copia casi instantánea de los archivos de datos.

Si no hay un manifiesto de copia de seguridad disponible o no contiene una suma de verificación del tipo correcto, se utilizará la clonación de archivos para copiar el archivo, pero el archivo también se leerá bloque por bloque para el cálculo de la suma de verificación.

La clonación de archivos solo es compatible con algunos sistemas operativos y sistemas de archivos. Si se selecciona pero no se admite, la ejecución de pg_combinebackup fallará. Actualmente, es compatible con Linux (kernel 4.5 o posterior) con Btrfs y XFS (en sistemas de archivos creados con soporte para reflink), y en macOS con APFS.

--copy

Realiza una copia de archivo normal. Este es el valor predeterminado. (Ver también --copy-file-range, --clone, y -k/--link).

--copy-file-range

Utiliza la llamada al sistema copy_file_range para una copia eficiente. En algunos sistemas de archivos, esto produce resultados similares a --clone, compartiendo bloques de disco físicos, mientras que en otros todavía puede copiar bloques, pero lo hace a través de una ruta optimizada. Actualmente, es compatible con Linux y FreeBSD.

Si no hay un manifiesto de copia de seguridad disponible o no contiene una suma de verificación del tipo correcto, se utilizará copy_file_range para copiar el archivo, pero el archivo también se leerá bloque por bloque para el cálculo de la suma de verificación.

--manifest-checksums=algoritmo

Al igual que pg_basebackup(1), pg_combinebackup escribe un manifiesto de copia de seguridad en el directorio de salida. Esta opción especifica el algoritmo de suma de verificación que se debe aplicar a cada archivo incluido en el manifiesto de copia de seguridad. Actualmente, los algoritmos disponibles son NONE, CRC32C, SHA224, SHA256, SHA384 y SHA512. El valor predeterminado es CRC32C.

--no-manifest

Deshabilita la generación de un manifiesto de copia de seguridad. Si esta opción no se especifica, se escribirá un manifiesto de copia de seguridad para la copia de seguridad reconstruida en el directorio de salida.

--sync-method=método

Cuando se establece en fsync, que es el valor predeterminado, pg_combinebackup abrirá y sincronizará recursivamente todos los archivos del directorio de copia de seguridad. Cuando se utiliza el formato plano, la búsqueda de archivos seguirá los enlaces simbólicos para el directorio WAL y cada tablespace configurado.

En Linux, syncfs puede usarse en su lugar para solicitar al sistema operativo que sincronice todo el sistema de archivos que contiene el directorio de copia de seguridad. Cuando se utiliza el formato plano, pg_combinebackup también sincronizará los sistemas de archivos que contienen los archivos WAL y cada tablespace. Consulte recovery_init_sync_method para obtener información sobre las advertencias a tener en cuenta al usar syncfs.

Esta opción no tiene ningún efecto cuando se utiliza --no-sync.

-V
--version

Imprime la versión de pg_combinebackup y sale.

-?
--help

Muestra ayuda sobre los argumentos de la línea de comandos de pg_combinebackup y sale.

LIMITACIONES

pg_combinebackup no recalcula las sumas de verificación de páginas al escribir el directorio de salida. Por lo tanto, si alguna de las copias de seguridad utilizadas para la reconstrucción se tomó con las sumas de verificación deshabilitadas, pero la copia de seguridad final se tomó con las sumas de verificación habilitadas, el directorio resultante puede contener páginas con sumas de verificación no válidas.

Para evitar este problema, se recomienda realizar una nueva copia de seguridad completa después de cambiar el estado de suma de verificación del clúster utilizando pg_checksums(1). De lo contrario, puede deshabilitar y luego, opcionalmente, volver a habilitar las sumas de verificación en el directorio producido por pg_combinebackup para corregir el problema.

ENTORNO

Esta utilidad, al igual que la mayoría de las otras utilidades de PostgreSQL, utiliza las variables de entorno compatibles con libpq (ver Sección 32.15).

La variable de entorno PG_COLOR especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son always, auto y never.

pg_basebackup(1)

NAME

pg_basebackup — take a base backup of a PostgreSQL cluster

SYNOPSIS

pg_basebackup [-B | --with-timing] [-D datadir] [-F format] [-j jobs] [-X method] [-P | --progress] [-R | --revmap] [-v | --verbose] [-z | --gzip] [-Z level] [-d connstr] [-S slotname] [-U username] [-w | --no-password] [-W | --password] [-h hostname] [-p port] [-c command] [-o | --o-options] [-l label]

DESCRIPTION

pg_basebackup is a utility to create a base backup of a running PostgreSQL server. A base backup is a physical copy of the server's data directory, including all data files, configuration files and Write-Ahead Log (WAL) files.

It can be used to create a new standby server or to restore a server to a previous state. The backup is taken without stopping the server, so the server remains available for clients during the backup.

The backup is transferred over a regular PostgreSQL connection using the replication protocol. This means that the server must be configured to accept replication connections, and the user performing the backup must have the REPLICATION privilege.

OPTIONS

-D datadir
Specifies the directory where the base backup will be stored. This directory must exist and be empty. If not specified, the backup will be stored in the current directory.
-F format
Specifies the format of the backup. The available formats are:
  • t (tar): The backup will be stored as a tar archive.
  • p (plain): The backup will be stored as a plain copy of the data directory.
The default format is p.
-j jobs
Specifies the number of parallel jobs to use when transferring files. This can speed up the backup process on networks with high latency.
-X method
Specifies how to include WAL files in the backup. The available methods are:
  • n (none): WAL files are not included.
  • s (stream): WAL files are streamed to the backup client.
  • f (fetch): WAL files are fetched from the server after the backup is complete.
The default method is n.
-P | --progress
Shows progress information during the backup.
-R | --revmap
Creates a recovery.conf file in the backup directory that contains the necessary information to start a standby server.
-v | --verbose
Enables verbose output.
-z | --gzip
Compresses the backup using gzip. This option is only effective when the format is t.
-Z level
Specifies the compression level for gzip compression. The level must be an integer between 0 and 9.
-d connstr
Specifies the connection string to use when connecting to the server.
-S slotname
Specifies the name of the replication slot to use. If not specified, a temporary slot will be created.
-U username
Specifies the username to use when connecting to the server.
-w | --no-password
Never prompt for a password.
-W | --password
Always prompt for a password.
-h hostname
Specifies the hostname or IP address of the server to connect to.
-p port
Specifies the port number to use when connecting to the server.
-c command
Specifies the command to execute on the server to obtain the base backup. The default command is pg_basebackup.
-o | --o-options
Passes the specified options to the pg_basebackup command.
-l label
Specifies a label for the base backup. This label will be written to the backup file and can be used to identify the backup.

LIMITATIONS

pg_basebackup requires that the server is running with WAL archiving enabled (wal_level set to replica or higher) and that the user performing the backup has the REPLICATION privilege.

ENVIRONMENT

PGHOST, PGPORT, PGUSER, PGDATABASE, PGPASSWORD

The environment variables PGHOST, PGPORT, PGUSER, and PGDATABASE can be used to specify the connection parameters. PGPASSWORD can be used to specify the password. If PGPASSWORD is set, pg_basebackup will not prompt for a password.
