NOMBRE

pg_recvlogical — controla los flujos de decodificación lógica de PostgreSQL

SINOPSIS

pg_recvlogical [opción...]

DESCRIPCIÓN

pg_recvlogical controla las ranuras de replicación de decodificación lógica y transmite datos desde dichas ranuras de replicación.

Crea una conexión de modo de replicación, por lo que está sujeto a las mismas restricciones que pg_receivewal(1), además de las de la replicación lógica (ver Capítulo 47).

pg_recvlogical no tiene un equivalente a los modos peek y get de la interfaz SQL de decodificación lógica. Envía confirmaciones de reproducción para los datos de forma diferida a medida que los recibe y al salir limpiamente. Para examinar los datos pendientes en una ranura sin consumirlos, use pg_logical_slot_peek_changes.

En ausencia de errores fatales, pg_recvlogical se ejecutará hasta que sea terminado por la señal SIGINT (Control+C) o SIGTERM.

Cuando pg_recvlogical recibe una señal SIGHUP, cierra el archivo de salida actual y abre uno nuevo usando el nombre de archivo especificado por la opción --file. Esto nos permite rotar el archivo de salida renombrando primero el archivo actual y luego enviando una señal SIGHUP a pg_recvlogical.

OPCIONES

Se debe especificar al menos una de las siguientes opciones para seleccionar una acción:

--create-slot

Crea una nueva ranura de replicación lógica con el nombre especificado por --slot, utilizando el plugin de salida especificado por --plugin, para la base de datos especificada por --dbname.

Se requieren --slot y --dbname para esta acción.

Las opciones --enable-two-phase y --enable-failover se pueden especificar con --create-slot.

--drop-slot

Elimina la ranura de replicación con el nombre especificado por --slot, y luego sale.

Se requiere --slot para esta acción.

--start

Comienza a transmitir cambios desde la ranura de replicación lógica especificada por --slot, continuando hasta que sea terminada por una señal. Si el flujo de cambios del lado del servidor termina con un apagado o desconexión del servidor, reintente en un bucle a menos que se especifique --no-loop.

Se requieren --slot, --dbname y --file para esta acción.

El formato del flujo está determinado por el plugin de salida especificado cuando se creó la ranura.

La conexión debe ser a la misma base de datos utilizada para crear la ranura.

Se pueden especificar juntas --create-slot y --start. --drop-slot no se puede combinar con otra acción.

Las siguientes opciones de línea de comandos controlan la ubicación y el formato de la salida y otros comportamientos de replicación:

-E lsn
--endpos=lsn

En modo --start, detiene automáticamente la replicación y sale con estado de salida normal 0 cuando la recepción alcanza el LSN especificado. Si se especifica cuando no está en modo --start, se produce un error.

Si hay un registro con un LSN exactamente igual a lsn, se generará el registro.

La opción --endpos no tiene en cuenta los límites de transacción y puede truncar la salida a mitad de una transacción. Cualquier transacción parcialmente generada no se consumirá y se reproducirá nuevamente la próxima vez que se lea la ranura. Los mensajes individuales nunca se truncan.

--enable-failover

Habilita la sincronización de la ranura a los standbys. Esta opción solo se puede especificar con --create-slot.

-f nombre_archivo
--file=nombre_archivo

Escribe los datos de transacción recibidos y decodificados en este archivo. Use - para stdout.

Este parámetro es obligatorio para --start.

-F intervalo_segundos
--fsync-interval=intervalo_segundos

Especifica con qué frecuencia pg_recvlogical debe emitir llamadas fsync() para garantizar que el archivo de salida se haya volcado de forma segura en el disco.

El servidor solicitará ocasionalmente al cliente que realice un volcado y que informe la posición del volcado al servidor. Esta configuración se suma a eso, para realizar volcados con mayor frecuencia.

Especificar un intervalo de 0 deshabilita por completo la emisión de llamadas fsync(), mientras se informa el progreso al servidor. En este caso, los datos podrían perderse en caso de un fallo.

-I lsn
--startpos=lsn

En modo --start, inicia la replicación desde el LSN dado. Para obtener detalles sobre el efecto de esto, consulte la documentación en el Capítulo 47 y la Sección 54.4. Se ignora en otros modos.

--if-not-exists

No genere un error cuando se especifica --create-slot y ya existe una ranura con el nombre especificado.

-n
--no-loop

Cuando se pierde la conexión con el servidor, no intente repetidamente en un bucle, simplemente salga.

-o nombre[=valor]
--option=nombre[=valor]

Pasa la opción nombre al plugin de salida con, si se especifica, el valor de opción valor. Qué opciones existen y sus efectos dependen del plugin de salida utilizado.

-P plugin
--plugin=plugin

Al crear una ranura, utilice el plugin de salida de decodificación lógica especificado. Ver Capítulo 47. Esta opción no tiene ningún efecto si la ranura ya existe.

-s intervalo_segundos
--status-interval=intervalo_segundos

Esta opción tiene el mismo efecto que la opción del mismo nombre en pg_receivewal(1). Ver la descripción allí.

-S nombre_ranura
--slot=nombre_ranura

En modo --start, use la ranura de replicación lógica existente llamada nombre_ranura. En modo --create-slot, cree la ranura con este nombre. En modo --drop-slot, elimine la ranura con este nombre.

Este parámetro es obligatorio para cualquiera de las acciones.

-t
--enable-two-phase
--two-phase (obsoleto)

Habilita la decodificación de transacciones preparadas. Esta opción solo se puede especificar con --create-slot.

-v
--verbose

Habilita el modo detallado.

Las siguientes opciones de línea de comandos controlan los parámetros de conexión a la base de datos.

-d basedatos
--dbname=basedatos

La base de datos a la que conectarse. Ver la descripción de las acciones para lo que esto significa en detalle. El basedatos puede ser una cadena de conexión. Si es así, los parámetros de la cadena de conexión anularán cualquier opción de línea de comandos conflictiva.

Este parámetro es obligatorio para --create-slot y --start.

-h nombre_host_o_ip
--host=nombre_host_o_ip

Especifica el nombre del host de la máquina en la que se está ejecutando el servidor. Si el valor comienza con una barra, se utiliza como directorio para el socket de dominio Unix. El valor predeterminado se toma de la variable de entorno PGHOST, si está configurada, de lo contrario se intenta una conexión mediante socket de dominio Unix.

-p puerto
--port=puerto

Especifica el puerto TCP o la extensión del archivo de socket de dominio local Unix en el que el servidor está escuchando las conexiones. El valor predeterminado es la variable de entorno PGPORT, si está configurada, o un valor predeterminado compilado.

-U usuario
--username=usuario

Nombre de usuario con el que conectarse. El valor predeterminado es el nombre de usuario del sistema operativo actual.

-w
--no-password

Nunca solicite una contraseña. Si el servidor requiere autenticación de contraseña y una contraseña no está disponible por otros medios, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para ingresar una contraseña.

-W
--password

Fuerza a pg_recvlogical a solicitar una contraseña antes de conectarse a una base de datos.

Esta opción nunca es esencial, ya que pg_recvlogical solicitará automáticamente una contraseña pg_recvlogical(1) — PostgreSQL 18.1 documentation

NAME

pg_recvlogical ― receive and show logical decoding stream from a PostgreSQL server

SYNOPSIS

pg_recvlogical [connection-option...] [option...]

DESCRIPTION

pg_recvlogical retrieves the logical decoding stream from a PostgreSQL server, starting from a specified LSN, and writes it to standard output. This can be used to feed replication clients that can process the output format.

The tool needs to connect to a PostgreSQL server. The connection parameters can be specified using connection options or environment variables.

The following options are mandatory:

-n
--dbname=dbname

Specifies the database name to connect to.

-P
--plugin=plugin

Specifies the output plugin to use for logical decoding. Commonly used plugins include test_decoding, pgoutput, and bdr.

-S
--slot=slotname

Specifies the name of the logical replication slot to use. The slot must already exist on the server.

Optional connection options are:

-h
--host=hostname

Specifies the host name of the machine on which the server is running. If omitted, the value is taken from the PGHOST environment variable or defaults to localhost or the path to the local socket.

-p
--port=port

Specifies the TCP port or local Unix domain socket file extension on which the server is listening for connections. If omitted, the value is taken from the PGPORT environment variable or defaults to the PostgreSQL built-in default port (typically 5432).

-U
--username=username

User name to connect as.

-w
--no-password

Never prompt for a password. If the server requires password authentication and a password is not available from other variables, connection fails.

-W
--password

Force pg_recvlogical to prompt for a password before connecting. This can be useful if the server requires password authentication but the client doesn’t have a password stored in other variables.

The following additional options are available:

-V
--version

Print the pg_recvlogical version and exit.

-?
--help

Show help about pg_recvlogical command line arguments, and exit.

EXIT STATUS

pg_recvlogical will exit with status 0 when terminated by the SIGINT or SIGTERM signal. (That is the normal way to end it. Hence it is not an error.) For fatal errors or other signals, the exit status will be nonzero.

ENVIRONMENT

This utility, like most other PostgreSQL utilities, uses the environment variables supported by libpq (see Section 32.15).

The environment variable PG_COLOR specifies whether to use color in diagnostic messages. Possible values are always, auto and never.

NOTES

pg_recvlogical will preserve group permissions on the received WAL files if group permissions are enabled on the source cluster.

EXAMPLES

See Section 47.1 for an example.
