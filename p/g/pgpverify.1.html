NOMBRE

pgpverify - Verifica criptográficamente los mensajes de control de Usenet

SINOPSIS

pgpverify [--findid=cadena] [--test] < mensaje

DESCRIPCIÓN

El programa pgpverify lee (en la entrada estándar) un mensaje de control de Usenet que ha sido firmado criptográficamente usando el programa signcontrol (o algún otro programa que produzca un formato compatible). pgpverify luego usa una implementación de PGP para determinar quién firmó el mensaje de control. Si el mensaje de control tiene una firma válida, pgpverify imprime (en la salida estándar) el ID de usuario de la clave que firmó el mensaje. De lo contrario, sale con un estado de salida distinto de cero.

Si pgpverify está instalado como parte de INN, usa la configuración de INN para determinar qué programa de verificación de firmas usar, cómo registrar errores, qué directorio temporal usar y qué anillo de claves usar. De lo contrario, todos esos parámetros se pueden establecer editando el principio de este script.

Por defecto, cuando se ejecuta como parte de INN, pgpverify espera que el anillo de claves PGP se encuentre en pathetc/pgp (ya sea como pubring.pgp o pubring.gpg dependiendo de si se usa PGP o GnuPG para verificar las firmas). Si ese directorio no existe, recurrirá a usar el anillo de claves por defecto, que se encuentra en un subdirectorio .pgp o .gnupg del directorio de inicio del usuario que se está ejecutando.

INN, al usar GnuPG, configura pgpverify para usar gpg o gpgv, que por defecto espera que las claves estén en un anillo de claves llamado trustedkeys.gpg, ya que no implementa la verificación de confianza directamente. pgpverify usa ese archivo si está presente, pero recurre a pubring.gpg si no se encuentra. Esto evita el modelo de confianza para verificar claves, pero es compatible con la forma en que pgpverify se comportaba anteriormente. Por supuesto, si se encuentra un anillo de claves en pathetc/pgp o configurado en la parte superior del script, eso anula todo este comportamiento.

Tenga en cuenta que algunas jerarquías de Usenet todavía envían artículos de control firmados con claves PGP antiguas usando un algoritmo de hash débil (MD5). Las versiones modernas de GnuPG (2.1.0+) ya no validan dichas firmas, por lo que debería usar GnuPG 1.x o 2.0.x si necesita verificar dichos artículos de control.

OPCIONES

--findid=cadena
La opción --findid hace que pgpverify busque explícitamente cadena en la salida del análisis del mensaje por parte de PGP. Esta opción es útil cuando se definen varios UIDs en una única clave PGP, y el llamador de pgpverify necesita verificar si una dada está definida en esta clave. En caso de que la firma sea válida pero no contenga cadena, pgpverify sale con el estado de salida 4.
--test
La opción --test hace que pgpverify imprima la entrada que está pasando a PGP (que es una versión reconstruida de la entrada que supuestamente creó el mensaje de control) así como la salida del análisis del mensaje por parte de PGP.

ESTADO DE SALIDA

pgpverify puede salir con los siguientes estados:

0
El mensaje de control tenía una buena firma PGP.
1
El mensaje de control no tenía firma PGP.
2
El mensaje de control tenía una firma PGP desconocida.
3
El mensaje de control tenía una mala firma PGP.
4
El mensaje de control tenía una buena firma PGP, pero el argumento dado a la opción --findid no se encontró en la salida del análisis del mensaje por parte de PGP.
255
Ocurrió un problema no directamente relacionado con el análisis de la firma por parte de PGP.

AMBIENTE

pgpverify no modifica ni altera de ninguna otra manera el entorno antes de invocar el programa pgp, gpgv o gpg. Es responsabilidad de la persona que instala pgpverify asegurarse de que cuando pgp, gpgv o gpg se ejecuten, tengan la capacidad de localizar y leer un archivo de claves PGP que contenga las claves públicas PGP para los administradores apropiados de la jerarquía de Usenet. pgpverify puede ser apuntado a un anillo de claves apropiado editando variables al principio de este script.

NOTAS

Históricamente, los administradores de servidores de noticias de Usenet han configurado sus servidores para honrar automáticamente los mensajes de control de Usenet basándose en el originador de los mensajes de control y las jerarquías a las que aplicaban los mensajes de control. Por ejemplo, en el pasado, David Lawrence siempre emitía mensajes de control para las jerarquías "Big 8" (comp, humanities, misc, news, rec, sci, soc, talk). Los administradores de noticias de Usenet configuraban su software de servidor de noticias para honrar automáticamente los mensajes de control newgroup y rmgroup que se originaban en David Lawrence y se aplicaban a cualquiera de las jerarquías Big 8.

Desafortunadamente, los artículos de noticias de Usenet (incluidos los mensajes de control) son notoriamente fáciles de falsificar. Pronto, los usuarios maliciosos se dieron cuenta de que podían crear o eliminar (al menos temporalmente) cualquier grupo de noticias de Big 8 que quisieran simplemente falsificando un mensaje de control apropiado en nombre de David Lawrence. A medida que Usenet se usaba más ampliamente, las falsificaciones se volvieron más comunes.

El programa pgpverify fue diseñado para permitir a los administradores de noticias de Usenet configurar sus servidores para verificar criptográficamente los mensajes de control antes de actuar sobre ellos automáticamente. Bajo el sistema pgpverify, un mantenedor de jerarquía de Usenet crea un par de claves pública/privada PGP y difunde la clave pública. Cada vez que el mantenedor de la jerarquía emite un mensaje de control, utiliza el programa signcontrol para firmar el mensaje de control con la clave privada PGP. Los administradores de noticias de Usenet configuran sus servidores de noticias para ejecutar el programa pgpverify en los mensajes de control apropiados, y toman medidas basándose en el ID de usuario de la clave PGP que firmó el mensaje de control, no en el nombre y la dirección que aparecen en las cabeceras From: o Sender: del mensaje de control.

Por lo tanto, el uso apropiado de los programas signcontrol y pgpverify esencialmente elimina la posibilidad de que los usuarios maliciosos falsifiquen mensajes de control de Usenet sobre los que los sitios actuarán, ya que tales usuarios tendrían que obtener la clave privada PGP para falsificar un mensaje de control que pasara la verificación criptográfica. Si los administradores de jerarquía protegen adecuadamente sus claves privadas PGP, la única forma en que un usuario malicioso podría falsificar un mensaje de control firmado válidamente sería rompiendo el algoritmo de cifrado de clave pública, lo cual (al menos en este momento) se cree que es prohibitivamente difícil para claves PGP de una longitud de bits suficiente.
