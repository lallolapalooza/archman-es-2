NOMBRE

pg_verifybackup - verifica la integridad de una copia de seguridad base de un clúster de PostgreSQL

SINOPSIS

pg_verifybackup [opción...]

DESCRIPCIÓN

pg_verifybackup se utiliza para comprobar la integridad de una copia de seguridad de un clúster de bases de datos realizada con pg_basebackup contra un archivo backup_manifest generado por el servidor en el momento de la copia de seguridad. La copia de seguridad puede almacenarse en formato "plain" (normal) o "tar"; esto incluye copias de seguridad en formato tar comprimidas con cualquier algoritmo soportado por pg_basebackup. Sin embargo, en la actualidad, la verificación de WAL solo se admite para copias de seguridad en formato normal. Por lo tanto, si la copia de seguridad se almacena en formato tar, se debe usar la opción -n, --no-parse-wal.

Es importante tener en cuenta que la validación que realiza pg_verifybackup no incluye ni puede incluir todas las comprobaciones que realizará un servidor en ejecución al intentar utilizar la copia de seguridad. Incluso si utiliza esta herramienta, aún debe realizar restauraciones de prueba y verificar que las bases de datos resultantes funcionen como se espera y que parezcan contener los datos correctos. Sin embargo, pg_verifybackup puede detectar muchos problemas que ocurren comúnmente debido a problemas de almacenamiento o errores del usuario.

La verificación de la copia de seguridad procede en cuatro etapas. Primero, pg_verifybackup lee el archivo backup_manifest. Si ese archivo no existe, no se puede leer, está mal formado, no coincide con el identificador del sistema con pg_control del directorio de copia de seguridad o falla la verificación contra su propia suma de verificación interna, pg_verifybackup terminará con un error fatal.

En segundo lugar, pg_verifybackup intentará verificar que los archivos de datos almacenados actualmente en disco son exactamente los mismos que los archivos de datos que el servidor pretendía enviar, con algunas excepciones que se describen a continuación. Se detectarán archivos adicionales y faltantes, con algunas excepciones. Este paso ignorará la presencia o ausencia, o cualquier modificación, de postgresql.auto.conf, standby.signal y recovery.signal, ya que se espera que estos archivos se hayan creado o modificado como parte del proceso de realización de la copia de seguridad. Tampoco se quejará de un archivo backup_manifest en el directorio de destino ni de nada dentro de pg_wal, aunque estos archivos no se enumerarán en el manifiesto de copia de seguridad. Solo se verifican los archivos; la presencia o ausencia de directorios no se verifica, excepto indirectamente: si falta un directorio, los archivos que debería haber contenido necesariamente también faltarán.

A continuación, pg_verifybackup calculará la suma de verificación de todos los archivos, comparará las sumas de verificación con los valores del manifiesto y emitirá errores para cualquier archivo cuya suma de verificación calculada no coincida con la suma de verificación almacenada en el manifiesto. Este paso no se realiza para ningún archivo que produjera errores en el paso anterior, ya que ya se sabe que tienen problemas. Los archivos que se ignoraron en el paso anterior también se ignoran en este paso.

Finalmente, pg_verifybackup utilizará el manifiesto para verificar que los registros de escritura anticipada (WAL) que serán necesarios para recuperar la copia de seguridad están presentes y que se pueden leer y analizar. El backup_manifest contiene información sobre qué registros WAL serán necesarios, y pg_verifybackup utilizará esa información para invocar pg_waldump y analizar esos registros WAL. Se utilizará la bandera --quiet, de modo que pg_waldump solo informará errores, sin producir ninguna otra salida. Si bien este nivel de verificación es suficiente para detectar problemas obvios como un archivo faltante o uno cuyas sumas de verificación internas no coinciden, no son lo suficientemente extensos como para detectar todos los posibles problemas que podrían ocurrir al intentar la recuperación. Por ejemplo, un error del servidor que produce registros WAL con sumas de verificación correctas pero que especifican acciones sin sentido no puede ser detectado por este método.

Tenga en cuenta que si hay archivos WAL adicionales que no son necesarios para recuperar la copia de seguridad, no serán verificados por esta herramienta, aunque se podría usar una invocación separada de pg_waldump para ese propósito. Tenga en cuenta también que la verificación de WAL es específica de la versión: debe usar la versión de pg_verifybackup, y por lo tanto de pg_waldump, que corresponde a la copia de seguridad que se está comprobando. En contraste, las comprobaciones de integridad de los archivos de datos deberían funcionar con cualquier versión del servidor que genere un archivo backup_manifest.

OPCIONES

pg_verifybackup acepta los siguientes argumentos de línea de comandos:

-e
--exit-on-error

Salga tan pronto como se detecte un problema con la copia de seguridad. Si esta opción no se especifica, pg_verifybackup continuará verificando la copia de seguridad incluso después de que se haya detectado un problema, e informará todos los problemas detectados como errores.

-F formato
--format=formato

Especifica el formato de la copia de seguridad. formato puede ser uno de los siguientes:

p
plain

La copia de seguridad consiste en archivos normales con la misma estructura que el directorio de datos y las tablaspaces del servidor de origen.

t
tar

La copia de seguridad consiste en archivos tar, que pueden estar comprimidos. Una copia de seguridad válida incluye el directorio de datos principal en un archivo llamado base.tar, los archivos WAL en pg_wal.tar, y archivos tar separados para cada tablespace, nombrados según el OID del tablespace. Si la copia de seguridad está comprimida, la extensión de compresión válida se agrega al final de cada nombre de archivo.

-i ruta
--ignore=ruta

Ignora el archivo o directorio especificado, que debe expresarse como un nombre de ruta relativo, al comparar la lista de archivos de datos realmente presentes en la copia de seguridad con los que figuran en el archivo backup_manifest. Si se especifica un directorio, esta opción afecta a todo el subárbol enraizado en esa ubicación. Las quejas sobre archivos adicionales, archivos faltantes, diferencias en el tamaño de los archivos o discrepancias en las sumas de verificación se suprimirán si el nombre de la ruta relativa coincide con el nombre de ruta especificado. Esta opción se puede especificar varias veces.

-m ruta
--manifest-path=ruta

Utiliza el archivo de manifiesto en la ruta especificada, en lugar de uno ubicado en la raíz del directorio de copia de seguridad.

-n
--no-parse-wal

No intente analizar los datos del registro de escritura anticipada (WAL) que serán necesarios para recuperarse de esta copia de seguridad.

-P
--progress

Habilita la notificación de progreso. Habilitar esto proporcionará un informe de progreso mientras se verifican las sumas de verificación.

Esta opción no se puede usar junto con la opción --quiet.

-q
--quiet

No imprima nada cuando una copia de seguridad se verifica correctamente.

-s
--skip-checksums

No verifique las sumas de verificación de los archivos de datos. La presencia o ausencia de archivos y los tamaños de esos archivos aún se verificarán. Esto es mucho más rápido, ya que no es necesario leer los archivos.

-w ruta
--wal-directory=ruta

Intenta analizar los archivos WAL almacenados en el directorio especificado, en lugar de en pg_wal. Esto puede ser útil si la copia de seguridad se almacena en una ubicación separada del archivo WAL.

También hay otras opciones disponibles:

-V
--version

Imprime la versión de pg_verifybackup y sale.

-?
--help

Muestra ayuda sobre los argumentos de la línea de comandos de pg_verifybackup y sale.

EJEMPLOS

Para crear una copia de seguridad base del servidor en mydbserver y verificar la integridad de la copia de seguridad:

$ pg_basebackup -h mydbserver -D /usr/local/pgsql/data
$ pg_verifybackup /usr/local/pgsql/data

Para crear una copia de seguridad base del servidor en mydbserver, mover el manifiesto a algún lugar fuera del directorio de copia de seguridad y verificar la copia de seguridad:

$ pg_basebackup -h mydbserver -D /usr/local/pgsql/backup1234
$ mv /usr/local/pgsql/backup1234/backup_manifest /my/secure/location/backup_manifest.1234
$ pg_verifybackup -m /my/secure/location/backup_manifest.1234 /usr/local/pgsql/backup1234

Para verificar una copia de seguridad ignorando un archivo que se agregó manualmente al directorio de copia de seguridad, y también omitiendo la verificación de sumas de verificación:

$ pg_basebackup -h mydbserver -D /usr/local/pgsql/data
$ edit /usr/local/pgsql/data/note.to.self
$ pg_verifybackup --ignore=note.to.self --skip-checksums /u

pg_verifybackup 1

NAME

pg_verifybackup – verify a PostgreSQL backup

SYNOPSIS

pg_verifybackup [ OPTION... ] [ ARGUMENT... ]

DESCRIPTION

pg_verifybackup verifies a PostgreSQL backup previously created with pg_basebackup(1).

It checks the integrity of the backup by comparing the checksums of all files in the backup with the checksums stored in the control file. If the checksums match, the backup is considered valid.

pg_verifybackup can also verify a backup that was compressed using gzip or zstd.

The backup must be placed in a directory. The control file must be named backup_control and must be located in the root of the backup directory.

OPTIONS

pg_verifybackup accepts the following command-line options:

-?, --help
Show help, and exit.
-V, --version
Print version information, and exit.
-d, --dir=DIRECTORY
Specifies the directory containing the backup to be verified. This option is mandatory.
-c, --check-control
Check the control file for consistency. This is the default behavior.
-C, --compress=COMPRESS_TYPE
Specifies the compression type used for the backup. Possible values are gzip and zstd. If this option is specified, pg_verifybackup will decompress the backup on the fly before verifying it.
-v, --verbose
Enable verbose output. This will show the progress of the verification.
-q, --quiet
Enable quiet output. Only errors will be reported.
-p, --progress
Enable progress reporting. This will show the percentage of the backup that has been verified.

EXAMPLES

Verify a backup located in /path/to/backup:

pg_verifybackup -d /path/to/backup

Verify a compressed backup (gzip) located in /path/to/backup with verbose output:

pg_verifybackup -d /path/to/backup -c gzip -v

Verify a backup located in the default data directory /sr/local/pgsql/data:

pg_verifybackup -d /sr/local/pgsql/data
