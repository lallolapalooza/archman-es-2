PGSQL_TABLE(5) Manual de formatos de archivo PGSQL_TABLE(5)

NOMBRE

pgsql_table - Configuración del cliente PostgreSQL de Postfix

SINOPSIS

postmap -q "cadena" pgsql:/etc/postfix/nombre_archivo
postmap -q - pgsql:/etc/postfix/nombre_archivo <archivo_entrada

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas opcionales para la reescritura de direcciones o el enrutamiento de correo. Estas tablas suelen estar en formato dbm o db.

Alternativamente, las tablas de búsqueda se pueden especificar como bases de datos PostgreSQL. Para usar búsquedas de PostgreSQL, defina una fuente de PostgreSQL como una tabla de búsqueda en main.cf, por ejemplo:

    alias_maps = pgsql:/etc/postfix/pgsql-aliases.cf

El archivo /etc/postfix/pgsql-aliases.cf tiene el mismo formato que el archivo main.cf de Postfix, y puede especificar los parámetros que se describen a continuación.

MEMBRESÍA DE LISTAS

Al usar SQL para almacenar listas como $mynetworks, $mydestination, $relay_domains, $local_recipient_maps, etc., es importante entender que la tabla debe almacenar cada miembro de la lista como una clave separada. La búsqueda en la tabla verifica la *existencia* de la clave. Consulte "Listas de Postfix frente a tablas" en el documento README_DATABASE para obtener una discusión.

NO cree tablas que devuelvan la lista completa de dominios en $mydestination o $relay_domains, etc., o direcciones IP en $mynetworks.

SÍ cree tablas con cada elemento coincidente como clave y con un valor arbitrario. Con bases de datos SQL, no es raro devolver la propia clave o un valor constante.

PARÁMETROS PGSQL

hosts
Los hosts a los que Postfix intentará conectarse y consultar. Además de una URI de conexión de PostgreSQL, esta configuración admite las formas históricas unix:/ruta_de_acceso para sockets de dominio UNIX y inet:host:puerto para conexiones TCP, donde los prefijos unix: e inet: se aceptan y se ignoran por compatibilidad retroactiva. Ejemplos: 
    hosts = postgresql://usuario@ejemplo.com/nombre_base_datos?sslmode=require
    hosts = postgres://usuario:secreto@localhost
    hosts = inet:host1.dominio.com inet:host2.dominio.com:puerto
    hosts = host1.dominio.com host2.dominio.com:puerto
    hosts = unix:/ruta/al/archivo

Consulte https://www.postgresql.org/docs/current/libpq-connect.html para ver la sintaxis de URI de conexión admitida.

Los hosts se prueban en orden aleatorio. Las conexiones se cierran automáticamente después de estar inactivas durante aproximadamente 1 minuto y se reabren según sea necesario. Consulte idle_interval para obtener más detalles.

NOTA: si la configuración hosts especifica una URI de conexión de PostgreSQL, el cliente PostgreSQL de Postfix ignorará la configuración dbname, user y password para esa conexión.

NOTA: si la configuración hosts especifica un solo servidor, este cliente asume que el destino es un balanceador de carga y se reconectará inmediatamente después de un único error, en lugar de fallar todas las solicitudes temporalmente. Con versiones anteriores de este cliente, especifique el mismo servidor dos veces.

user
password
El nombre de usuario y la contraseña para iniciar sesión en el servidor pgsql. Ejemplo: 
    user = alguien
    password = alguna_contraseña

La configuración user y password se ignora para las conexiones hosts que se especifican como una URI.

dbname
El nombre de la base de datos en los servidores. Ejemplo: 
    dbname = base_datos_cliente

La configuración dbname se ignora para las conexiones hosts que se especifican como una URI.

La configuración dbname es obligatoria con Postfix 3.10 y posteriores, cuando hosts especifica cualquier conexión que no sea URI; siempre es obligatoria con versiones anteriores de Postfix.

encoding
La codificación utilizada por el cliente de la base de datos. La configuración predeterminada es: 
    encoding = UTF8

Históricamente, el cliente de la base de datos estaba codificado para usar LATIN1 en un intento de deshabilitar el soporte de caracteres multibyte.

Esta función está disponible en Postfix 3.8 y posteriores.

idle_interval (predeterminado: 60)
El número de segundos después de los cuales se cerrará una conexión de base de datos inactiva.

Esta función está disponible en Postfix 3.9 y posteriores.

retry_interval (predeterminado: 60)
El número de segundos que se omitirá una conexión de base de datos después de un error.

NOTA: si la configuración hosts especifica un solo servidor, este cliente asume que el destino es un balanceador de carga y se reconectará inmediatamente después de un único error, en lugar de fallar todas las solicitudes temporalmente. Con versiones anteriores de este cliente, especifique el mismo servidor dos veces.

Esta función está disponible en Postfix 3.9 y posteriores.

query
La plantilla de consulta SQL utilizada para buscar en la base de datos, donde %s es un sustituto de la dirección que Postfix intenta resolver, por ejemplo: 
    query = SELECT replacement FROM aliases WHERE mailbox = '%s'

Este parámetro admite las siguientes expansiones %:

%%
Esto se reemplaza por un carácter '%' literal. (Postfix 2.2 y posteriores)
%s
Esto se reemplaza por la clave de entrada. Se utiliza el escapado SQL para asegurarse de que la clave de entrada no agregue metacaracteres inesperados.
%u
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección escapada en SQL. De lo contrario, %u se reemplaza por toda la cadena de búsqueda. Si la parte local está vacía, la consulta se suprime y no devuelve resultados.
%d
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio escapada en SQL de la dirección. De lo contrario, la consulta se suprime y no devuelve resultados.
%[SUD]
Los equivalentes en mayúsculas de las expansiones anteriores se comportan en el parámetro query de manera idéntica a sus contrapartes en minúsculas. Con el parámetro result_format (ver más abajo), expanden la clave de entrada en lugar del valor del resultado.
Las expansiones %S, %U y %D anteriores están disponibles en Postfix 2.2 y posteriores
%[1-9]
Los patrones %1, %2, ... %9 se reemplazan por el componente más significativo correspondiente del dominio de la clave de entrada. Si la clave de entrada es usuario@correo.ejemplo.com, entonces %1 es com, %2 es ejemplo y %3 es correo. Si la clave de entrada no está calificada o no tiene suficientes componentes de dominio para satisfacer todos los patrones especificados, la consulta se suprime y no devuelve resultados.
Las expansiones %1, ... %9 anteriores están disponibles en Postfix 2.2 y posteriores
El parámetro domain descrito a continuación limita las claves de entrada a direcciones en dominios coincidentes. Cuando el parámetro domain no está vacío, las consultas SQL para direcciones no calificadas o direcciones en dominios no coincidentes se suprimen y no devuelven resultados.

La precedencia de este parámetro ha cambiado con Postfix 2.2; en versiones anteriores, la precedencia era, de mayor a menor, select_function, query, select_field, ...

Con Postfix 2.2, el parámetro query tiene la mayor precedencia; consulte INTERFACES DE CONSULTA OBSOLETAS a continuación.

NOTA: NO ponga comillas alrededor del parámetro query.

pgsql_table(5)

NAME

pgsql_table - Postfix PostgreSQL lookup tables

SYNOPSIS

pgsql:map-name
pgsql:database table [select_field where_field]
pgsql:database table [select_field where_field] [additional_conditions]
pgsql:database table [select_field where_field] [additional_conditions] [order_field]
pgsql:database table [select_field where_field] [additional_conditions] [order_field] [group_field]
pgsql:[parameter=value ...] map-name

DESCRIPTION

The Postfix PostgreSQL client interface supports lookup tables that are stored in a PostgreSQL database. It is available only when Postfix has been built with PostgreSQL support.

The lookup table is specified as a string in the format pgsql:map-name. The default PostgreSQL connection parameters are specified in a file named by the pgsql_name parameter in main.cf or master.cf. If this parameter is not specified, the default name is "default". The actual connection parameters are read from the file named by the pgsql_service_name parameter in main.cf or master.cf. If this parameter is not specified, the default name is "default".

The lookup table can also be specified as pgsql:database table. In this case, the database name and table name are specified directly. This form is useful for simple cases where only one map is needed, or where connection parameters are specified using the name=value syntax (see below).

The format of the lookup string is:

  pgsql:[parameter=value ...] map-name

or

  pgsql:[parameter=value ...] database table [select_field where_field] [additional_conditions] [order_field] [group_field]

The parameters can be any of the following:

hosts
The PostgreSQL server hostname(s). Multiple hosts can be separated by commas. For example: hosts = host1, host2. If not specified, the default is localhost.
port
The PostgreSQL server port. If not specified, the default is 5432.
database
The PostgreSQL database name. If not specified, the default is localhost.
user
The PostgreSQL username. If not specified, the default is the current system username.
password
The PostgreSQL password. If not specified, the default is an empty password.
query_filter
A filter to apply to the query. This is useful for avoiding sensitive information from being exposed. The filter is applied after the query has been executed, and can be used to modify the result. The filter is applied to each result value individually. For example, to remove trailing whitespace from a result: 
      query_filter = "%s = """ % { rstrip }

The filter string is processed by the Postfix internal string processing functions. The %s is replaced by the value of the result, and then the rest of the string is interpreted as the filter itself. The special sequence %{} can be used to enclose a Postfix internal function call. Example: 

      query_filter = "%s = %{lower}"

This parameter is available with Postfix 2.3 and later.

result_format
A format string that specifies how to format the result of the query. The default is %s, which means the result is used as is. The following special characters can be used in the format string:
%s
Is replaced by the entire result string.
%u
When the result attribute value is an address of the form user@domain, %u is replaced by the local part of the address. When the result has an empty localpart it is skipped.
%d
When a result attribute value is an address of the form user@domain, %d is replaced by the domain part of the attribute value. When the result is unqualified it is skipped.
%[SUD1-9]
The upper-case and decimal digit expansions interpolate the parts of the input key rather than the result. Their behavior is identical to that described with query, and in fact because the input key is known in advance, queries whose key does not contain all the information specified in the result template are suppressed and return no results.
For example, using "result_format = smtp:[%s]" allows one to use a mailHost attribute as the basis of a transport(5) table. After applying the result format, multiple values are concatenated as comma separated strings. The expansion_limit and parameter explained below allows one to restrict the number of values in the result, which is especially useful for maps that must return at most one value.

The default value %s specifies that each result value should be used as is.

This parameter is available with Postfix 2.2 and later.

NOTE: DO NOT put quotes around the result format!

domain (default: no domain list)
This is a list of domain names, paths to files, or "type:table" databases. When specified, only fully qualified search keys with a *non-empty* localpart and a matching domain are eligible for lookup: 'user' lookups, bare domain lookups and "@domain" lookups are not performed. This can significantly reduce the query load on the PostgreSQL server. 
    domain = postfix.org, hash:/etc/postfix/searchdomains

It is best not to use SQL to store the domains eligible for SQL lookups.

This parameter is available with Postfix 2.2 and later.

NOTE: DO NOT define this parameter for local(8) aliases, because the input keys are always unqualified.

expansion_limit (default: 0)
A limit on the total number of result elements returned (as a comma separated list) by a lookup against the map. A setting of zero disables the limit. Lookups fail with a temporary error if the limit is exceeded. Setting the limit to 1 ensures that lookups do not return multiple values.

OBSOLETE MAIN.CF PARAMETERS

For compatibility with other Postfix lookup tables, PostgreSQL parameters can also be defined in main.cf. In order to do that, specify as PostgreSQL source a name that doesn't begin with a slash or a dot. The PostgreSQL parameters will then be accessible as the name you've given the source in its definition, an underscore, and the name of the parameter. For example, if the map is specified as "pgsql:pgsqlname", the parameter "hosts" would be defined in main.cf as "pgsqlname_hosts".

Note: with this form, the passwords for the PostgreSQL sources are written in main.cf, which is normally world-readable. Support for this form will be removed in a future Postfix version.

OBSOLETE QUERY INTERFACES

This section describes query interfaces that are deprecated as of Postfix 2.2. Please migrate to the new query interface as the old interfaces are slated to be phased out.

select_function
This parameter specifies a database function name. Example: 
    select_function = my_lookup_user_alias

This is equivalent to:

    query = SELECT my_lookup_user_alias('%s')

This parameter overrides the legacy table-related fields (described below). With Postfix versions prior to 2.2, it also overrides the query parameter. Starting with Postfix 2.2, the query parameter has highest precedence, and the select_function parameter is deprecated.

The following parameters (with lower precedence than the select_function interface described above) can be used to build the SQL select statement as follows:

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

The specifier %s is replaced with each lookup by the lookup key and is escaped so if it contains single quotes or other odd characters, it will not cause a parse error, or worse, a security problem.

Starting with Postfix 2.2, this interface is obsoleted by the more general query interface described above. If higher precedence the query or select_function parameters described above are defined, the parameters described here are ignored.

select_field
The SQL "select" parameter. Example: 
    select_field = forw_addr
table
The SQL "select .. from" table name. Example: 
    table = mxaliases
where_field
The SQL "select .. where" parameter. Example: 
    where_field = alias
additional_conditions
Additional conditions to the SQL query. Example: 
    additional_conditions = AND status = 'paid'
