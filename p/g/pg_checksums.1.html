PG_CHECKSUMS(1) Documentación de PostgreSQL 18.1 PG_CHECKSUMS(1)

NOMBRE

pg_checksums - habilita, deshabilita o verifica sumas de verificación de datos en un clúster de base de datos PostgreSQL

SINOPSIS

pg_checksums [opción...] [[-D | --pgdata]directorio_datos]

DESCRIPCIÓN

pg_checksums verifica, habilita o deshabilita las sumas de verificación de datos en un clúster de PostgreSQL. El servidor debe estar apagado limpiamente antes de ejecutar pg_checksums. Al verificar las sumas de verificación, el estado de salida es cero si no hay errores de suma de verificación, y distinto de cero si se detecta al menos un error de suma de verificación. Al habilitar o deshabilitar las sumas de verificación, el estado de salida es distinto de cero si la operación falló.

Al verificar las sumas de verificación, se escanea cada archivo en el clúster. Al habilitar las sumas de verificación, cada bloque de archivo de relación con una suma de verificación modificada se reescribe en el lugar. Deshabilitar las sumas de verificación solo actualiza el archivo pg_control.

OPCIONES

Las siguientes opciones de línea de comandos están disponibles:

-D directorio
--pgdata=directorio

Especifica el directorio donde se almacena el clúster de base de datos.

-c
--check

Verifica las sumas de verificación. Este es el modo predeterminado si no se especifica nada más.

-d
--disable

Deshabilita las sumas de verificación.

-e
--enable

Habilita las sumas de verificación.

-f nódefichero
--filenode=nódefichero

Valida las sumas de verificación solo en la relación con nódefichero nódefichero.

-N
--no-sync

Por defecto, pg_checksums esperará a que todos los archivos se escriban de forma segura en el disco. Esta opción hace que pg_checksums retorne sin esperar, lo cual es más rápido, pero significa que un fallo posterior del sistema operativo puede dejar el directorio de datos actualizado corrupto. En general, esta opción es útil para pruebas, pero no debe usarse en una instalación de producción. Esta opción no tiene efecto cuando se usa --check.

-P
--progress

Habilita la notificación de progreso. Habilitar esto proporcionará un informe de progreso mientras se verifican o habilitan las sumas de verificación.

--sync-method=método

Cuando se establece en fsync, que es el valor predeterminado, pg_checksums abrirá y sincronizará recursivamente todos los archivos del directorio de datos. La búsqueda de archivos seguirá enlaces simbólicos para el directorio WAL y cada espacio de tabla configurado.

En Linux, syncfs puede usarse en su lugar para solicitar al sistema operativo que sincronice todos los sistemas de archivos que contienen el directorio de datos, los archivos WAL y cada espacio de tabla. Consulte recovery_init_sync_method para obtener información sobre las advertencias a tener en cuenta al usar syncfs.

Esta opción no tiene efecto cuando se usa --no-sync.

-v
--verbose

Habilita la salida detallada. Lista todos los archivos verificados.

-V
--version

Imprime la versión de pg_checksums y sale.

-?
--help

Muestra la ayuda sobre los argumentos de la línea de comandos de pg_checksums y sale.

AMBIENTE

PGDATA

Especifica el directorio donde se almacena el clúster de base de datos; puede ser anulado usando la opción -D.

PG_COLOR

Especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son always, auto y never.

NOTAS

Habilitar las sumas de verificación en un clúster grande puede llevar potencialmente mucho tiempo. Durante esta operación, el clúster u otros programas que escriben en el directorio de datos no deben iniciarse o de lo contrario puede ocurrir una pérdida de datos.

Al usar una configuración de replicación con herramientas que realizan copias directas de bloques de archivos de relación (por ejemplo, pg_rewind(1)), habilitar o deshabilitar las sumas de verificación puede provocar corrupciones de página en forma de sumas de verificación incorrectas si la operación no se realiza de manera consistente en todos los nodos. Por lo tanto, al habilitar o deshabilitar las sumas de verificación en una configuración de replicación, se recomienda detener todos los clústeres antes de cambiarlos de manera consistente. Destruir todos los standby, realizar la operación en el primario y finalmente recrear los standby desde cero también es seguro.

Si pg_checksums se interrumpe o se mata mientras habilita o deshabilita las sumas de verificación, la configuración de sumas de verificación de datos del clúster permanece sin cambios, y pg_checksums se puede volver a ejecutar para realizar la misma operación.
