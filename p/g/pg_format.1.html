Paquete: pgformatter

Licencias: PostgreSQL

PG_FORMAT(1) Documentación Perl contribuida por el usuario PG_FORMAT(1)

NOMBRE

pg_format - Formateador de sintaxis SQL de PostgreSQL

DESCRIPCIÓN

Este formateador/embellecedor de SQL soporta palabras clave de SQL-92, SQL-99, SQL-2003, SQL-2008, SQL-2011 y palabras clave específicas de PostgreSQL. Funciona también con cualquier otra base de datos.

pgFormatter puede funcionar como un programa de consola o como CGI. Detectará automáticamente su entorno y formateará la salida como texto o como HTML siguiendo el contexto. También puede devolver una respuesta formateada en JSON si se usa como CGI con 'Accept: application/json'.

El resaltado de palabras clave solo estará disponible en el contexto CGI.

Ejecución en terminal/consola

Uso: pg_format [opciones] archivo.sql

Formateador de consultas SQL de PostgreSQL y código PL/PGSQL.

Argumentos:

archivo.sql puede ser un archivo, múltiples archivos o usar - para leer la consulta desde stdin.
Devuelve el SQL formateado a stdout o a un archivo especificado con
la opción -o | --output.

Opciones:

-a | --anonymize      : oculta todos los literales en las consultas, útil para ocultar
                        datos confidenciales antes de formatear.
-b | --comma-start    : en una lista de parámetros, empezar con la coma (ver -e)
-B | --comma-break    : en sentencias INSERT, añadir un salto de línea después de cada coma.
-c | --config ARCHIVO    : usar un archivo de configuración. Por defecto no se usa
                        archivo de configuración a menos que existan los archivos ./.pg_format o
                        $HOME/.pg_format o el archivo XDG Base Directory
                        $XDG_CONFIG_HOME/pg_format/pg_format.conf.
-C | --wrap-comment   : con --wrap-limit, aplicar reformateo a comentarios.
-d | --debug          : habilitar modo de depuración. Deshabilitado por defecto.
-e | --comma-end      : en una lista de parámetros, terminar con la coma (por defecto)
-f | --function-case N: Cambia la capitalización de las funciones de PostgreSQL. Por defecto
                        sin cambios: 0. Valores: 0=>sin cambios, 1=>minúsculas,
                        2=>mayúsculas, 3=>capitalizadas.
-F | --format STR     : formato de salida: text o html. Por defecto: text.
-g | --nogrouping     : añadir un salto de línea entre sentencias en el agrupamiento
                        de transacciones. Por defecto se agrupan sentencias.
-h | --help           : mostrar este mensaje y salir.
-i | --inplace        : sobrescribir los archivos de entrada con el contenido formateado.
-k | --keep-newline   : conservar líneas vacías en código plpgsql.
-L | --no-extra-line  : no añadir una línea vacía extra al final de la salida.
-m | --maxlength SIZE : longitud máxima de una consulta, se truncará por encima
                        del tamaño dado. Por defecto: sin truncar.
-M | --multiline      : habilitar búsqueda multilínea para -p o --placeholder.
-n | --nocomment      : eliminar cualquier comentario del código SQL.
-N | --numbering      : numeración de sentencias como comentario antes de cada consulta.
-o | --output archivo    : definir el nombre del archivo para la salida. Por defecto: stdout.
-p | --placeholder RE : establecer expresión regular para encontrar código que no debe ser modificado.
-r | --redshift       : añadir palabras clave de RedShift a la lista de palabras clave SQL.
                        Obsoleto ahora, usar --extra-keyword 'redshift' en su lugar.
-s | --spaces size    : cambiar la indentación de espacios, por defecto 4 espacios.
-S | --separator STR  : separador de código dinámico, por defecto comilla simple.
-t | --format-type    : probar otro tipo de formato para algunas sentencias.
-T | --tabs           : usar tabulaciones en lugar de caracteres de espacio, cuando se usa
                        spaces se establece en 1 sea cual sea el valor dado a -s.
-u | --keyword-case N : Cambia la capitalización de la palabra clave reservada. Por defecto
                        mayúsculas: 2. Valores: 0=>sin cambios, 1=>minúsculas,
                        2=>mayúsculas, 3=>capitalizadas.
-U | --type-case N    : Cambia la capitalización del nombre del tipo de dato. Por defecto
                        minúsculas: 1. Valores: 0=>sin cambios, 1=>minúsculas,
                        2=>mayúsculas, 3=>capitalizadas.
-v | --version        : mostrar la versión de pg_format y salir.
-w | --wrap-limit N   : envolver consultas en una cierta longitud.
-W | --wrap-after N   : número de columnas después de las cuales las listas deben ser envueltas.
                        Por defecto: pone cada elemento en su propia línea.
-X | --no-rcfile      : no leer archivos rc automáticamente (./.pg_format o
                        $HOME/.pg_format o $XDG_CONFIG_HOME/pg_format).
                        La opción --config / -c lo anula.
--extra-function ARCHIVO  : archivo que contiene una lista de funciones para usar el mismo
                        formato que la función interna de PostgreSQL.
--extra-keyword ARCHIVO  : archivo que contiene una lista de palabras clave para usar el mismo
                        formato que la palabra clave interna de PostgreSQL. Usar
                        valor especial 'redshift' para soporte de palabras clave de Redshift
                        definidas internamente en pgFormatter.
--no-space-function : eliminar el espacio entre el nombre de la función y el paréntesis de apertura.
--redundant-parenthesis: no eliminar paréntesis redundantes en DML.

Ejemplos:

cat samples/ex1.sql | pg_format -
pg_format -n samples/ex1.sql
pg_format -f 2 -n -o result.sql samples/ex1.sql

Contexto CGI

Instala pg_format en tu carpeta cgi-bin, otórgale ejecución como un script CGI (quizás deberías añadir la extensión .cgi) y accede a él desde tu navegador favorito. Copia los archivos logo_pgformatter.png e icon_pgformatter.ico en el directorio CGI, pg_format.cgi los busca en el mismo repositorio.

Tienes un ejemplo en vivo sin más limitación que diez mil caracteres en tu consulta SQL aquí:

http://sqlformat.darold.net/

pg_format detectará automáticamente que se está ejecutando en un entorno CGI y generará todo el código HTML necesario para ejecutar un sitio formateador de código en línea. No hay nada más que hacer.

Necesitas instalar los módulos Perl CGI y JSON primero. Si aún no lo has hecho, haz:

        yum install perl-cgi
        yum install perl-json
o
        apt install libcgi-pm-perl
        apt install libjson-perl

según tu distribución.

INSTALACIÓN

Según tu distribución de Linux, es posible que necesites instalar el módulo Perl autodie:

sudo yum -y install perl-autodie

Descarga el archivo tar de GitHub y descomprime el archivo como sigue:

version=5.3 #por favor, usa la última versión de release de github
wget https://github.com/darold/pgFormatter/archive/refs/tags/v${version}.tar.gz
tar xzf v${version}.tar.gz
cd pgFormatter-${version}/
perl Makefile.PL
make && sudo make install
cd ../ && rm -rf v${version}.tar.gz && rm -rf pgFormatter-${version} #limpieza

Esto copiará el script Perl pg_format en el directorio /usr/local/bin/pg_format por defecto y la página del manual en /usr/local/share/man/man1/pg_format.1. Esos son los directorios de instalación por defecto para la instalación de 'site'.

Si deseas instalar todo bajo la ubicación /usr/, usa INSTALLDIRS='perl' como argumento de Makefile.PL. El script se instalará en /usr/bin/pg_format y la página del manual en /usr/share/man/man1/pg_format.1.

Por ejemplo, para instalar todo tal como lo hace Debian, procede como sigue:

perl Makefile.PL INSTALLDIRS=vendor

Por defecto, INSTALLDIRS se establece en site.

Las pruebas de regresión se pueden ejecutar con el siguiente comando:

make test

Si tienes docker instalado, puedes construir una imagen de pgFormatter usando:

docker build -t darold.net/pgformatter .

luego simplemente úsala como:

cat file.sql | docker run --rm -a stdin -a stdout -i darold.net/pgformatter -

FORMATO ESPECIAL

Opción -W, --wrap-after

Esta opción se puede utilizar para establecer el número de columnas después de las cuales las listas deben ser envueltas. Por defecto, pgFormatter coloca cada elemento en su propia línea. Este formato se aplica a las listas SELECT y FROM. Por ejemplo, la siguiente consulta:

SELECT a, b, c, d FROM t_1, t_2, t3 WHERE a = 10 AND b = 10;

se formateará como con -W 4:

SELECT a, b, c, d
FROM t_1, t_2, t3
WHERE a = 10
    AND b = 10;

Tenga en cuenta que este formato no encaja bien con subconsultas en listas.

Opción -w, --wrap-limit

Esta opción envuelve las consultas en una cierta longitud, sin importar la parte de la consulta que alcance el límite, a menos que sea un comentario. Por ejemplo, si se alcanza el límite en una constante de texto, el texto se envolverá. La indentación no se incluye en el recuento de caracteres. Esta opción se aplica en todos los casos, incluso si se utilizan otras opciones.

Opción -C, --wrap-comment

Esta opción envuelve los comentarios en la longitud definida por -w, --wrap-limit, sin importar la parte del comentario. La indentación no se incluye en el recuento de caracteres.

OPCIONES

Opción -t, --format-type

Esta opción activa un formato alternativo que añade:

* nueva línea en la lista de parámetros de procedimientos/funciones
* nueva línea en DDL de PUBLICACIÓN y POLÍTICA
* mantiene la enumeración en la cláusula GROUP BY en una sola línea

Se espera que esta lista crezca siguiendo pensamientos alternativos.

Opción -g, --nogrouping

Por defecto, pgFormatter agrupa todas las sentencias cuando están en una transacción:

BEGIN;
INSERT INTO foo VALUES (1, 'texto 1');
INSERT INTO foo VALUES (2, 'texto 2');
...
COMMIT;

Al deshabilitar la agrupación de sentencias, pgFormatter siempre añadirá caracteres de nueva línea adicionales entre sentencias, al igual que fuera de una transacción:

BEGIN;
INSERT INTO foo VALUES (1, 'texto 1');
INSERT INTO foo VALUES (2, 'texto 2');
...
COMMIT;

Esto puede mejorar la legibilidad de transacciones que no son DML.

Opción -L, --no-extra-line

Por defecto, pgFormatter siempre añade una línea vacía después del final de una sentencia cuando esta termina con un `;` excepto en un bloque de código plpgsql. Si la línea vacía adicional al final de la salida no es útil, puedes eliminarla añadiendo esta opción a la línea de comandos.

Opción --extra-function

pgFormatter aplica cierto formato a las llamadas de funciones internas de PostgreSQL pero no puede detectar funciones definidas por el usuario. Es posible definir una lista de funciones en un archivo (un nombre de función por línea) y proporcionársela a pgFormatter a través de la opción --extra-function, que serán formateadas como las funciones internas de PostgreSQL.

Opción --extra-keyword

pgFormatter aplica cierto formato a las palabras clave internas de PostgreSQL pero no puede detectar palabras clave de otras bases de datos. Es posible definir una lista de palabras clave en un archivo (una palabra clave por línea) y proporcionársela a pgFormatter a través de la opción --extra-keyword, que serán formateadas como las funciones internas de PostgreSQL.

También puedes pasar un valor especial 'redshift' que cargará las palabras clave definidas internamente en pgFormatter para esa base de datos. Esto era históricamente posible a través de la opción -r | --redshift, que ahora está obsoleta y será eliminada en el futuro.

Opción --no-space-function

Utiliza esta opción para eliminar el carácter de espacio entre una llamada a función y el paréntesis abierto que le sigue. Por defecto, pgFormatter añade un carácter de espacio, por ejemplo:

DROP FUNCTION IF EXISTS app_public.hello (a text);

Cuando se utiliza esta opción, la consulta resultante se formatea de la siguiente manera:

DROP FUNCTION IF EXISTS app_public.hello(a text);

Opción --redundant-parenthesis

Por defecto, pgFormatter intenta eliminar los paréntesis redundantes en DML, pero en algunos casos deben conservarse. Usar esta opción mantendrá los paréntesis redundantes sin cambios.

CONSEJOS

Configuración

Si la configuración predeterminada de pg_format no se ajusta a todas tus necesidades, puedes personalizar el comportamiento de pg_format utilizando un archivo de configuración en lugar de repetir las opciones de la línea de comandos. Por defecto, pgFormatter busca los archivos ./.pg_format o $HOME/.pg_format o $XDG_CONFIG_HOME/pg_format/pg_format.conf si existen, pero puedes elegir un archivo de configuración alternativo usando la opción de línea de comandos -c | --config

Para personalizar pg_format.cgi, busca un archivo de configuración llamado pg_format.conf en el mismo directorio que el script CGI.

Para ver un archivo de configuración de ejemplo, consulta doc/pg_format.conf.sample

Para evitar que pg_format busque en los archivos $XDG_CONFIG_HOME/pg_format o $HOME/.pg_format, puedes usar la opción de línea de comandos -X | --no-rcfile

Formateo desde stdin

Puedes ejecutar pg_format sin ningún argumento o con - para pasar el código SQL a formatear a través de stdin.

Si utilizas el modo interactivo, deberás escribir `ctrl+d` después de escribir tu sentencia SQL a formatear para finalizar la entrada.

$ pg_format
select * from customers;
< ctrl+d >

Puedes usar stdin en una sola línea de la siguiente manera:

echo "select * from customers;" | pg_format

Formateo desde VI

Con pgFormatter, puedes simplemente añadir la siguiente línea a tu archivo ~/.vimrc:

au FileType sql setl formatprg=/usr/local/bin/pg_format\ -

Esto permite que tus comandos gq utilicen pgFormatter automáticamente. Por ejemplo, si estás en la primera línea, al escribir:

ESC+gq+G

formateará todo el archivo.

ESC+gq+2j

formateará las siguientes dos líneas.

Gracias a David Fetter por el consejo.

También existe el plugin para (Neo)vim para formatear código de muchos tipos de archivos que soporta pg_format para formatear el tipo de archivo SQL. Gracias a Anders Riutta por el parche para (Neo)vim.

Formateo desde Atom

Si usas Atom como tu editor favorito, puedes instalar el paquete pg-formatter, que es un wrapper de Node.js de pgFormatter.

Características:

* Formatea texto seleccionado o un archivo completo mediante atajo de teclado o comando.
* Formatea archivos SQL al guardarlos.

Instalación:

Busca pg-formatter en la interfaz de Atom o obténlo a través de la línea de comandos:

apm install pg-formatter

Uso:

Presiona Ctrl-Alt-F para formatear texto seleccionado (o un archivo completo) o define tu propio atajo:

'ctrl-alt-p': 'pg-formatter:format'

Además, puedes formatear automáticamente los archivos SQL al guardarlos (deshabilitado por defecto).

Puedes descargar el paquete desde la URL:

https://atom.io/packages/pg-formatter

las fuentes están disponibles en https://github.com/gajus/pg-formatter

Gracias a Alex Fedoseev por el paquete de Atom.

Formateo desde Visual Studio

Gracias a Brady Holt, hay disponible una extensión para Visual Studio Code que formatea SQL de PostgreSQL utilizando pgFormatter.

https://marketplace.visualstudio.com/items?itemName=bradymholt.pgformatter

Para instalación y uso, consulta la URL anterior.

Evitar el reemplazo de fragmentos de código

Usando la opción de línea de comandos -p o --placeholder, es posible mantener el código sin ser alterado por pgFormatter en tus consultas SQL. Por ejemplo, en una consulta como:

SELECT * FROM projects WHERE projectnumber
        IN <<internalprojects>> AND username = <<loginname>>;

es posible que desees que pgFormatter no interprete << y >> como palabras clave de desplazamiento de bits y modifique tus fragmentos de código. Puedes usar una expresión regular de Perl para instruir a pgFormatter a mantener algunas partes de la consulta sin cambios. Por ejemplo:

pg_format samples/ex9.sql -p '<<(?:.*)?>>'

no formateará los operadores similares a desplazamiento de bits.

Si deseas envolver las consultas después de 60 caracteres (-w 60) y aplicar ese límite también a los comentarios (-C), las URLs en los comentarios podrían ser envueltas. Si prefieres no envolver las URLs, puedes usar una expresión regular para evitarlo. Por ejemplo:

pg_format samples/ex62.sql -C -w 60 -p 'https?:\/\/(www\.)?[-a-zA-Z0-9@:%._\+~#=]{1,256}\.[a-zA-Z0-9()]{1,6}\b([-a-zA-Z0-9()@:%_\+.~#?&//=]*)'

envolverá las consultas y los comentarios, pero no las URLs.

Evitar el formateo de código dinámico

Por defecto, pgFormatter toma todo el código entre comillas simples como constante de cadena y no realiza ningún formateo sobre ese código. Es común usar una cadena como separador de código para evitar duplicar comillas simples en la generación de código dinámico, en cuyo caso pgFormatter puede fallar al detectar automáticamente el separador de código. Por defecto, buscará cualquier cadena después de la palabra clave EXECUTE que comience con un signo de dólar. Si no puede detectar automáticamente tu separador de código, puedes usar la opción de línea de comandos -S o --separator para establecer el separador de código que debe usarse.

Wrapper ligero de Node.js

Gajus Kuizinas ha escrito un wrapper para Node.js para ejecutar pgFormatter. Puedes encontrarlo en https://github.com/gajus/pg-formatter

Personalizar CSS para la salida CGI

Puedes cambiar el estilo HTML renderizado a través del estilo CSS predeterminado creando un archivo llamado custom_css_file.css en el directorio del script CGI de pgFormatter. El CSS predeterminado será completamente sobrescrito por el contenido de este archivo personalizado. Debes mirar la salida HTML generada para obtener el código CSS predeterminado utilizado.

Usar pgFormatter como una API

Puedes usar pgFormatter como una API estableciendo la cabecera HTTP 'Accept' con el valor 'application/json' al llamarlo como una aplicación CGI. En caso de que no quieras habilitar esta función, establece "$self->{'enable_api'} = 0" en la subrutina "set_config" de lib/pgFormatter/CGI.pm.
