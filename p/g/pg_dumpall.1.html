PG_DUMPALL(1) Documentación de PostgreSQL 18.1 PG_DUMPALL(1)

NOMBRE

pg_dumpall - extraer un clúster de bases de datos PostgreSQL en un archivo de script

SINOPSIS

pg_dumpall [opción-conexión...] [opción...]

DESCRIPCIÓN

pg_dumpall es una utilidad para escribir ( "volcar" ) todas las bases de datos PostgreSQL de un clúster en un solo archivo de script. El archivo de script contiene comandos SQL que pueden ser usados como entrada para psql(1) para restaurar las bases de datos. Lo hace llamando a pg_dump(1) para cada base de datos del clúster. pg_dumpall también vuelca objetos globales que son comunes a todas las bases de datos, a saber, roles de base de datos, tablespaces y concesiones de privilegios para parámetros de configuración. (pg_dump no guarda estos objetos).

Dado que pg_dumpall lee tablas de todas las bases de datos, lo más probable es que tenga que conectarse como un superusuario de base de datos para producir un volcado completo. También necesitará privilegios de superusuario para ejecutar el script guardado para poder añadir roles y crear bases de datos.

El script SQL se escribirá en la salida estándar. Utilice la opción -f / --file o los operadores del shell para redirigirlo a un archivo.

pg_dumpall necesita conectarse varias veces al servidor PostgreSQL (una por base de datos). Si utiliza la autenticación por contraseña, le pedirá una contraseña cada vez. Es conveniente tener un archivo ~/.pgpass en tales casos. Consulte la Sección 32.16 para más información.


Advertencia

La restauración de un volcado provoca la ejecución de código arbitrario elegido por los superusuarios de origen. Los volcados parciales y las restauraciones parciales no limitan eso. Si los superusuarios de origen no son de confianza, los comandos SQL volcados deben ser inspeccionados antes de ser restaurados. Tenga en cuenta que el cliente que ejecuta el volcado y la restauración no necesita confiar en los superusuarios de origen o destino.

OPCIONES

Las siguientes opciones de línea de comandos controlan el contenido y el formato de la salida.

-a
--solo-datos

Vuelca solo los datos, no el esquema (definiciones de datos) ni las estadísticas.

-c
--limpiar

Emite comandos SQL para DROP (eliminar) todas las bases de datos, roles y tablespaces volcados antes de recrearlos. Esta opción es útil cuando la restauración va a sobrescribir un clúster existente. Si alguno de los objetos no existe en el clúster de destino, se informarán mensajes de error ignorables durante la restauración, a menos que también se especifique --if-exists.

-E codificación
--codificación=codificación

Crea el volcado en el conjunto de caracteres de codificación especificado. Por defecto, el volcado se crea en la codificación de la base de datos. (Otra forma de obtener el mismo resultado es establecer la variable de entorno PGCLIENTENCODING a la codificación de volcado deseada).

-f nombre-archivo
--archivo=nombre-archivo

Envía la salida al archivo especificado. Si se omite, se utiliza la salida estándar.

-g
--solo-globales

Vuelca solo objetos globales (roles y tablespaces), sin bases de datos.

-O
--sin-propietario

No emite comandos para establecer la propiedad de los objetos para que coincidan con la base de datos original. Por defecto, pg_dumpall emite sentencias ALTER OWNER o SET SESSION AUTHORIZATION para establecer la propiedad de los elementos del esquema creados. Estas sentencias fallarán cuando se ejecute el script a menos que lo inicie un superusuario (o el mismo usuario que posee todos los objetos del script). Para crear un script que pueda ser restaurado por cualquier usuario, pero que le otorgue la propiedad de todos los objetos, especifique -O.

-r
--solo-roles

Vuelca solo roles, sin bases de datos ni tablespaces.

-s
--solo-esquema

Vuelca solo las definiciones de objetos (esquema), no los datos.

-S nombre-usuario
--superusuario=nombre-usuario

Especifica el nombre de superusuario a utilizar al deshabilitar los triggers. Esto solo es relevante si se usa --disable-triggers. (Generalmente, es mejor omitirlo y, en su lugar, iniciar el script resultante como superusuario).

-t
--solo-tablespaces

Vuelca solo tablespaces, sin bases de datos ni roles.

-v
--verbose

Especifica el modo detallado. Esto hará que pg_dumpall emita tiempos de inicio/parada en el archivo de volcado y mensajes de progreso en el error estándar. Repetir la opción hará que aparezcan mensajes adicionales de nivel de depuración en el error estándar. La opción también se pasa a pg_dump.

-V
--version

Imprime la versión de pg_dumpall y sale.

-x
--sin-privilegios
--sin-acl

Evita el volcado de privilegios de acceso (comandos grant/revoke).

--actualización-en-sitio

Esta opción es para ser utilizada por utilidades de actualización en sitio. No se recomienda ni se admite su uso para otros propósitos. El comportamiento de la opción puede cambiar en futuras versiones sin previo aviso.

--inserciones-columna
--inserciones-atributo

Vuelca los datos como comandos INSERT con nombres de columna explícitos (INSERT INTO tabla (columna, ...) VALUES ...). Esto hará que la restauración sea muy lenta; es principalmente útil para crear volcados que se puedan cargar en bases de datos no PostgreSQL.

--sin-dollar-quoting

Esta opción deshabilita el uso de dollar quoting para los cuerpos de función y los fuerza a ser citados usando la sintaxis estándar de cadenas SQL.

--deshabilitar-triggers

Esta opción solo es relevante al crear un volcado con datos y sin esquema. Instruye a pg_dumpall a incluir comandos para deshabilitar temporalmente los triggers en las tablas de destino mientras se restauran los datos. Úselo si tiene verificaciones de integridad referencial u otros triggers en las tablas que no desea invocar durante la restauración de datos.

Actualmente, los comandos emitidos para --deshabilitar-triggers deben ser ejecutados como superusuario. Por lo tanto, también debe especificar un nombre de superusuario con -S, o preferiblemente tener cuidado al iniciar el script resultante como superusuario.

--excluir-base-de-datos=patrón

No volcar bases de datos cuyo nombre coincida con patrón. Se pueden excluir varios patrones escribiendo múltiples intercambios --excluir-base-de-datos. El parámetro patrón se interpreta como un patrón según las mismas reglas que utilizan los comandos \d de psql (ver Patrones), por lo que también se pueden excluir varias bases de datos escribiendo caracteres comodín en el patrón. Al usar comodines, tenga cuidado de citar el patrón si es necesario para evitar la expansión de comodines del shell.

--digitos-extra-flotantes=ndigitos

Utiliza el valor especificado de extra_float_digits al volcar datos de punto flotante, en lugar de la máxima precisión disponible. Los volcados rutinarios realizados con fines de copia de seguridad no deben utilizar esta opción.

--filtro=nombre-archivo

Especifica un nombre de archivo desde el cual leer los patrones de las bases de datos excluidas del volcado. Los patrones se interpretan según las mismas reglas que --excluir-base-de-datos. Para leer desde STDIN, use - como nombre de archivo. La opción --filtro se puede especificar junto con --excluir-base-de-datos para excluir bases de datos, y también se puede especificar más de una vez para múltiples archivos de filtro.

El archivo lista un patrón de base de datos por línea, con el siguiente formato:

excluir base de datos PATRÓN

Las líneas que comienzan con # se consideran comentarios y se ignoran. Los comentarios también se pueden colocar después de una fila de patrón de objeto. Las líneas en blanco también se ignoran. Ver Patrones para saber cómo realizar el citamiento en los patrones.

--si-existe

Utiliza comandos DROP ... IF EXISTS para eliminar objetos en modo --limpiar. Esto suprime los errores de "no existe" que de lo contrario podrían ser informados. Esta opción no es válida a menos que --limpiar también se especifique.

--inserciones

--load-via-partition-root

Al volcar datos para una partición de tabla, haga que las sentencias COPY o INSERT apunten a la raíz de la jerarquía de partición que la contiene, en lugar de a la partición misma. Esto hace que la partición apropiada se re-determine para cada fila al cargar los datos. Esto puede ser útil al restaurar datos en un servidor donde las filas no siempre caen en las mismas particiones que en el servidor original. Esto podría suceder, por ejemplo, si la columna de partición es de tipo texto y los dos sistemas tienen definiciones diferentes de la intercalación utilizada para ordenar la columna de partición.

--lock-wait-timeout=timeout

No espere eternamente para adquirir bloqueos de tabla compartidos al principio de la copia de seguridad. En su lugar, falle si no puede bloquear una tabla dentro del timeout especificado. El timeout puede especificarse en cualquiera de los formatos aceptados por SET statement_timeout.

--no-comments

No volcar comandos COMMENT.

--no-data

No volcar datos.

--no-policies

No volcar políticas de seguridad de filas.

--no-publications

No volcar publicaciones.

--no-role-passwords

No volcar contraseñas de roles. Al restaurarse, los roles tendrán una contraseña nula, y la autenticación de contraseña siempre fallará hasta que se establezca la contraseña. Dado que los valores de contraseña no son necesarios cuando se especifica esta opción, la información del rol se lee de la vista de catálogo pg_roles en lugar de pg_authid. Por lo tanto, esta opción también ayuda si el acceso a pg_authid está restringido por alguna política de seguridad.

--no-schema

No volcar el esquema (definiciones de datos).

--no-security-labels

No volcar etiquetas de seguridad.

--no-statistics

No volcar estadísticas. Este es el comportamiento predeterminado.

--no-subscriptions

No volcar suscripciones.

--no-sync

Por defecto, pg_dumpall esperará a que todos los archivos se escriban de forma segura en el disco. Esta opción hace que pg_dumpall regrese sin esperar, lo que es más rápido, pero significa que una falla posterior del sistema operativo puede dejar la copia de seguridad corrupta. En general, esta opción es útil para pruebas, pero no debe usarse al volcar datos de una instalación de producción.

--no-table-access-method

No emitir comandos para seleccionar métodos de acceso a tablas. Con esta opción, todos los objetos se crearán con el método de acceso a tablas que sea el predeterminado durante la restauración.

--no-tablespaces

No emitir comandos para crear tablespaces ni seleccionar tablespaces para objetos. Con esta opción, todos los objetos se crearán en el tablespace que sea el predeterminado durante la restauración.

--no-toast-compression

No emitir comandos para establecer métodos de compresión TOAST. Con esta opción, todas las columnas se restaurarán con la configuración de compresión predeterminada.

--no-unlogged-table-data

No volcar el contenido de tablas no registradas (unlogged tables). Esta opción no tiene ningún efecto sobre si se vuelcan o no las definiciones de tabla (esquema); solo suprime el volcado de los datos de la tabla.

--on-conflict-do-nothing

Añade ON CONFLICT DO NOTHING a los comandos INSERT. Esta opción no es válida a menos que también se especifique --inserts o --column-inserts.

--quote-all-identifiers

Forzar el entrecomillado de todos los identificadores. Esta opción se recomienda al volcar una base de datos de un servidor cuya versión principal de PostgreSQL sea diferente a la de pg_dumpall, o cuando la salida esté destinada a cargarse en un servidor de una versión principal diferente. Por defecto, pg_dumpall solo entrecomilla identificadores que son palabras reservadas en su propia versión principal. Esto a veces resulta en problemas de compatibilidad al tratar con servidores de otras versiones que pueden tener conjuntos de palabras reservadas ligeramente diferentes. Usar --quote-all-identifiers evita tales problemas, a costa de un script de volcado más difícil de leer.

--restrict-key=restrict_key

Utilice la cadena proporcionada como clave \restrict de psql en la salida del volcado. Si no se especifica ninguna clave de restricción, pg_dumpall generará una aleatoria según sea necesario. Las claves solo pueden contener caracteres alfanuméricos.

Esta opción está destinada principalmente a fines de prueba y otros escenarios que requieren una salida repetible (por ejemplo, comparar archivos de volcado). No se recomienda para uso general, ya que un servidor malicioso con conocimiento previo de la clave podría inyectar código arbitrario que se ejecutará en la máquina que ejecuta psql con la salida del volcado.

--rows-per-insert=nrows

Volcar datos como comandos INSERT (en lugar de COPY). Controla el número máximo de filas por comando INSERT. El valor especificado debe ser un número mayor que cero. Cualquier error durante la restauración hará que solo se pierdan las filas que forman parte del INSERT problemático, en lugar de todo el contenido de la tabla.

--statistics

Volcar estadísticas.

--statistics-only

Volcar solo las estadísticas, no el esquema (definiciones de datos) ni los datos. Se vuelcan estadísticas para tablas, vistas materializadas, tablas remotas e índices.

--sequence-data

Incluir datos de secuencias en el volcado. Este es el comportamiento predeterminado, excepto cuando se especifican --no-data, --schema-only o --statistics-only.

--use-set-session-authorization

Emitir comandos SET SESSION AUTHORIZATION del estándar SQL en lugar de comandos ALTER OWNER para determinar la propiedad de los objetos. Esto hace que el volcado sea más compatible con los estándares, pero dependiendo del historial de los objetos en el volcado, podría no restaurarse correctamente.

-?
--help

Mostrar ayuda sobre los argumentos de la línea de comandos de pg_dumpall y salir.

Las siguientes opciones de línea de comandos controlan los parámetros de conexión a la base de datos.

-d connstr
--dbname=connstr

Especifica los parámetros utilizados para conectarse al servidor, como una cadena de conexión; estos anularán cualquier opción de línea de comandos conflictiva.

La opción se llama --dbname por coherencia con otras aplicaciones cliente, pero debido a que pg_dumpall necesita conectarse a muchas bases de datos, el nombre de la base de datos en la cadena de conexión será ignorado. Utilice la opción -l para especificar el nombre de la base de datos utilizada para la conexión inicial, que volcará objetos globales y descubrirá qué otras bases de datos deben ser volcada.

-h host
--host=host

Especifica el nombre del host de la máquina en la que se está ejecutando el servidor de base de datos. Si el valor comienza con una barra, se utiliza como directorio para el socket de dominio Unix. El valor predeterminado se toma de la variable de entorno PGHOST, si está establecida; de lo contrario, se intenta una conexión de socket de dominio Unix.

-l dbname
--database=dbname

Especifica el nombre de la base de datos a la que conectarse para volcar objetos globales y descubrir qué otras bases de datos deben ser volcada. Si no se especifica, se utilizará la base de datos postgres, y si esta no existe, se utilizará template1.

-p port
--port=port

Especifica el puerto TCP o la extensión del archivo de socket de dominio Unix local en el que el servidor está escuchando conexiones. El valor predeterminado es la variable de entorno PGPORT, si está establecida, o un valor predeterminado compilado en el programa.

-U username
--username=username

Nombre de usuario con el que conectarse.

-w
--no-password

Nunca solicite una contraseña. Si el servidor requiere autenticación por contraseña y esta no está disponible por otros medios, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para introducir una contraseña.

-W
--password

Obliga a pg_dumpall a solicitar una contraseña antes de conectarse a una base de datos.

Esta opción nunca es esencial, ya que pg_dumpall solicitará automáticamente una contraseña si el servidor la exige. Sin embargo, pg_dumpall desperdiciará un intento de conexión al descubrir que el servidor quiere una contraseña. En algunos casos, vale la pena escribir -W para evitar el intento de conexión adicional.

Tenga en cuenta que la solicitud de contraseña se repetirá para cada base de datos a volcar. Normalmente, es mejor configurar un archivo ~/.pgpass que depender de la introducción manual de contraseñas.

--role=rolename

Especifica un nombre de rol que se utilizará para crear el volcado. Esta opción hace que pg_dumpall emita un comando SET ROLE rolename después de conectarse a la base de datos. Es útil cuando el usuario autenticado (especificado por -U) carece de los privilegios necesarios para pg_dumpall, pero puede cambiar a un rol con los derechos requeridos. Algunas instalaciones tienen una política contra el inicio de sesión directo como superusuario, y el uso de esta opción permite realizar volcados sin violar la política.

NOTAS

Dado que pg_dumpall llama internamente a pg_dump, algunos mensajes de diagnóstico se referirán a pg_dump.

La opción --clean puede ser útil incluso cuando su intención es restaurar el script de volcado en un clúster nuevo. El uso de --clean autoriza al script a eliminar y recrear las bases de datos integradas postgres y template1, asegurando que esas bases de datos conserven las mismas propiedades (por ejemplo, localidad y codificación) que tenían en el clúster de origen. NOTAS

Si se especifica --statistics, pg_dumpall incluirá la mayoría de las estadísticas del optimizador en el archivo de volcado resultante. Sin embargo, es posible que algunas estadísticas no se incluyan, como las creadas explícitamente con CREATE STATISTICS (CREATE_STATISTICS(7)) o estadísticas personalizadas añadidas por una extensión. Por lo tanto, puede ser útil ejecutar ANALYZE en cada base de datos después de restaurar desde un archivo de volcado para garantizar un rendimiento óptimo. También puede ejecutar vacuumdb -a -z para analizar todas las bases de datos.

No se debe esperar que el script de volcado se ejecute completamente sin errores. En particular, dado que el script emitirá CREATE ROLE para cada rol existente en el clúster de origen, es seguro que obtendrá un error de "role already exists" para el superusuario de arranque, a menos que el clúster de destino se haya inicializado con un nombre de superusuario de arranque diferente. Este error es inofensivo y debe ignorarse. El uso de la opción --clean probablemente producirá mensajes de error adicionales e inofensivos sobre objetos inexistentes, aunque puede minimizarlos añadiendo --if-exists.

pg_dumpall requiere que todos los directorios de tablespaces necesarios existan antes de la restauración; de lo contrario, la creación de bases de datos fallará para las bases de datos en ubicaciones no predeterminadas.

Generalmente se recomienda usar la opción -X (--no-psqlrc) al restaurar una base de datos desde un script pg_dumpall para garantizar un proceso de restauración limpio y prevenir posibles conflictos con configuraciones de psql no predeterminadas. Además, dado que el script pg_dumpall puede incluir meta-comandos de psql, puede ser incompatible con clientes distintos de psql.

EJEMPLOS

Para volcar todas las bases de datos:

$ pg_dumpall > db.out

Para restaurar bases de datos desde este archivo, puede usar:

$ psql -X -f db.out -d postgres

No es importante a qué base de datos se conecte aquí, ya que el archivo de script creado por pg_dumpall contendrá los comandos apropiados para crear y conectarse a las bases de datos guardadas. Una excepción es que si especificó --clean, debe conectarse inicialmente a la base de datos postgres; el script intentará eliminar otras bases de datos de inmediato, y eso fallará para la base de datos a la que está conectado.

VER TAMBIÉN

Consulte pg_dump(1) para obtener detalles sobre posibles condiciones de error.
