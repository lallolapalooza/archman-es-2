Paquete: postgresql

Licencias: PostgreSQL

PG_ARCHIVECLEANUP(1) Documentación de PostgreSQL 18.1 PG_ARCHIVECLEANUP(1)

NOMBRE

pg_archivecleanup - limpia archivos de archivo WAL de PostgreSQL

SINOPSIS

pg_archivecleanup [opción...] ubicacion_archivo archivo_wal_mas_antiguo_a_conservar

DESCRIPCIÓN

pg_archivecleanup está diseñado para ser utilizado como un comando archive_cleanup_command para limpiar los archivos WAL cuando se ejecuta como un servidor en espera (véase la Sección 26.2). pg_archivecleanup también puede ser utilizado como un programa independiente para limpiar archivos WAL.

Para configurar un servidor en espera para que utilice pg_archivecleanup, coloque lo siguiente en su archivo de configuración postgresql.conf:

archive_cleanup_command = 'pg_archivecleanup ubicacion_archivo %r'

donde ubicacion_archivo es el directorio desde el cual se deben eliminar los archivos de segmento WAL.

Cuando se utiliza dentro de archive_cleanup_command, todos los archivos WAL lógicamente anteriores al valor del argumento %r se eliminarán de ubicacion_archivo. Esto minimiza el número de archivos que deben conservarse, al tiempo que se preserva la capacidad de reinicio tras fallo. El uso de este parámetro es apropiado si la ubicacion_archivo es un área de preparación transitoria para este servidor en espera en particular, pero no cuando la ubicacion_archivo está destinada a ser un área de archivo WAL a largo plazo, o cuando varios servidores en espera se están recuperando de la misma ubicación de archivo.

Cuando se utiliza como un programa independiente, todos los archivos WAL lógicamente anteriores a archivo_wal_mas_antiguo_a_conservar se eliminarán de ubicacion_archivo. En este modo, si especifica un nombre de archivo .partial o .backup, solo se utilizará el prefijo del archivo como archivo_wal_mas_antiguo_a_conservar. Este tratamiento del nombre de archivo .backup le permite eliminar todos los archivos WAL archivados antes de una copia de seguridad base específica sin errores. Por ejemplo, el siguiente ejemplo eliminará todos los archivos anteriores al nombre de archivo WAL 000000010000003700000010:

pg_archivecleanup -d archive 000000010000003700000010.00000020.backup
pg_archivecleanup:  mantener el archivo WAL "archive/000000010000003700000010" y posteriores
pg_archivecleanup:  eliminando el archivo "archive/00000001000000370000000F"
pg_archivecleanup:  eliminando el archivo "archive/00000001000000370000000E"

pg_archivecleanup asume que ubicacion_archivo es un directorio legible y escribible por el usuario propietario del servidor.

OPCIONES

pg_archivecleanup acepta los siguientes argumentos de línea de comandos:

-b
--clean-backup-history

Elimina también los archivos de historial de copia de seguridad. Consulte la Sección 25.3.2 para obtener detalles sobre los archivos de historial de copia de seguridad.

-d
--debug

Imprime mucha salida de registro de depuración en stderr.

-n
--dry-run

Imprime los nombres de los archivos que habrían sido eliminados en stdout (realiza una ejecución de prueba).

-V
--version

Imprime la versión de pg_archivecleanup y sale.

-x extensión
--strip-extension=extensión

Proporciona una extensión que se eliminará de todos los nombres de archivo antes de decidir si deben ser eliminados. Esto es típicamente útil para limpiar archivos que han sido comprimidos durante el almacenamiento, y por lo tanto han tenido una extensión añadida por el programa de compresión. Por ejemplo: -x .gz.

-?
--help

Muestra ayuda sobre los argumentos de línea de comandos de pg_archivecleanup y sale.

AMBIENTE

La variable de entorno PG_COLOR especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son always, auto y never.

NOTAS

pg_archivecleanup está diseñado para funcionar con PostgreSQL 8.0 y posteriores cuando se utiliza como una utilidad independiente, o con PostgreSQL 9.0 y posteriores cuando se utiliza como un comando de limpieza de archivo.

pg_archivecleanup está escrito en C y tiene un código fuente fácilmente modificable, con secciones específicamente designadas para ser modificadas según sus necesidades.

EJEMPLOS

En sistemas Linux o Unix, podría usar:

archive_cleanup_command = 'pg_archivecleanup -d /mnt/standby/archive %r 2>>cleanup.log'

donde el directorio de archivo está físicamente ubicado en el servidor en espera, de modo que el archive_command lo está accediendo a través de NFS, pero los archivos son locales al servidor en espera. Esto:

•producirá salida de depuración en cleanup.log
•eliminará archivos que ya no son necesarios del directorio de archivo
