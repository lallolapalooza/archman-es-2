NOMBRE

pg_ctl - inicializa, inicia, detiene o controla un servidor PostgreSQL

SINOPSIS

pg_ctl init[db] [-D datadir] [-s] [-o initdb-options]

pg_ctl start [-D datadir] [-l filename] [-W] [-t segundos] [-s] [-o opciones] [-p ruta] [-c]

pg_ctl stop [-D datadir] [-m s[mart] | f[ast] | i[mmediate]] [-W] [-t segundos] [-s]

pg_ctl restart [-D datadir] [-m s[mart] | f[ast] | i[mmediate]] [-W] [-t segundos] [-s] [-o opciones] [-c]

pg_ctl reload [-D datadir] [-s]

pg_ctl status [-D datadir]

pg_ctl promote [-D datadir] [-W] [-t segundos] [-s]

pg_ctl logrotate [-D datadir] [-s]

pg_ctl kill nombre_señal id_proceso

En Microsoft Windows, también:

pg_ctl register [-D datadir] [-N nombreservicio] [-U nombreusuario] [-P contraseña] [-S a[uto] | d[emand]] [-e fuente] [-W] [-t segundos] [-s] [-o opciones]

pg_ctl unregister [-N nombreservicio]

DESCRIPCIÓN

pg_ctl es una utilidad para inicializar un clúster de bases de datos PostgreSQL, iniciar, detener o reiniciar el servidor de bases de datos PostgreSQL (postgres(1)), o mostrar el estado de un servidor en ejecución. Aunque el servidor puede iniciarse manualmente, pg_ctl encapsula tareas como redirigir la salida de registro y desvincularse correctamente del terminal y del grupo de procesos. También proporciona opciones convenientes para un apagado controlado.

El modo init o initdb crea un nuevo clúster de bases de datos PostgreSQL, es decir, una colección de bases de datos que serán gestionadas por una única instancia de servidor. Este modo invoca el comando initdb. Consulte initdb(1) para obtener detalles.

El modo start lanza un nuevo servidor. El servidor se inicia en segundo plano y su entrada estándar se adjunta a /dev/null (o nul en Windows). En sistemas tipo Unix, por defecto, la salida estándar y el error estándar del servidor se envían a la salida estándar de pg_ctl (no al error estándar). La salida estándar de pg_ctl debe redirigirse a un archivo o canalizarse a otro proceso como un programa de rotación de registros como rotatelogs; de lo contrario, postgres escribirá su salida en el terminal de control (desde segundo plano) y no abandonará el grupo de procesos del shell. En Windows, por defecto, la salida estándar y el error estándar del servidor se envían al terminal. Estos comportamientos por defecto se pueden cambiar usando -l para añadir la salida del servidor a un archivo de registro. Se recomienda el uso de -l o la redirección de salida.

El modo stop apaga el servidor que se está ejecutando en el directorio de datos especificado. Se pueden seleccionar tres métodos de apagado diferentes con la opción -m. El modo "Smart" (inteligente) no permite nuevas conexiones y luego espera a que todos los clientes existentes se desconecten. Si el servidor está en modo hot standby, la recuperación y la replicación en streaming se terminarán una vez que todos los clientes se hayan desconectado. El modo "Fast" (rápido) (el predeterminado) no espera a que los clientes se desconecten. Todas las transacciones activas se revierten y los clientes se desconectan forzosamente, luego se apaga el servidor. El modo "Immediate" (inmediato) abortará todos los procesos del servidor de inmediato, sin un apagado limpio. Esta elección conducirá a un ciclo de recuperación de fallos durante el próximo inicio del servidor.

El modo restart efectivamente ejecuta un stop seguido de un start. Esto permite cambiar las opciones de línea de comandos del comando postgres, o cambiar las opciones del archivo de configuración que no se pueden cambiar sin reiniciar el servidor. Si se usaron rutas relativas en la línea de comandos durante el inicio del servidor, restart podría fallar a menos que pg_ctl se ejecute en el mismo directorio actual en el que se ejecutó durante el inicio del servidor.

El modo reload simplemente envía una señal SIGHUP al proceso del servidor postgres, lo que hace que relea sus archivos de configuración (postgresql.conf, pg_hba.conf, etc.). Esto permite cambiar las opciones del archivo de configuración que no requieren un reinicio completo del servidor para que surtan efecto.

El modo status comprueba si un servidor se está ejecutando en el directorio de datos especificado. Si lo está, se muestran el PID del servidor y las opciones de línea de comandos que se utilizaron para invocarlo. Si el servidor no está en ejecución, pg_ctl devuelve un estado de salida de 3. Si no se especifica un directorio de datos accesible, pg_ctl devuelve un estado de salida de 4.

El modo promote ordena al servidor standby que se está ejecutando en el directorio de datos especificado que finalice el modo standby y comience las operaciones de lectura/escritura.

El modo logrotate rota el archivo de registro del servidor. Para obtener detalles sobre cómo usar este modo con herramientas externas de rotación de registros, consulte la Sección 24.3.

El modo kill envía una señal a un proceso especificado. Esto es principalmente valioso en Microsoft Windows, que no tiene un comando kill integrado. Use --help para ver una lista de nombres de señales admitidas.

El modo register registra el servidor PostgreSQL como un servicio del sistema en Microsoft Windows. La opción -S permite seleccionar el tipo de inicio del servicio, ya sea "auto" (iniciar el servicio automáticamente al iniciar el sistema) o "demand" (iniciar el servicio bajo demanda).

El modo unregister anula el registro de un servicio del sistema en Microsoft Windows. Esto deshace los efectos del comando register.

OPCIONES

-c
--core-files

Intenta permitir que los bloqueos del servidor produzcan archivos core, en plataformas donde esto sea posible, levantando cualquier límite de recursos blando impuesto a los archivos core. Esto es útil para depurar o diagnosticar problemas al permitir obtener un volcado de pila de un proceso de servidor fallido.

-D datadir
--pgdata=datadir

Especifica la ubicación en el sistema de archivos de los archivos de configuración de la base de datos. Si se omite esta opción, se utiliza la variable de entorno PGDATA.

-l nombrearchivo
--log=nombrearchivo

Añade la salida de registro del servidor al archivo nombrearchivo. Si el archivo no existe, se crea. El umask se establece en 077, por lo que el acceso al archivo de registro está prohibido a otros usuarios por defecto.

-m modo
--mode=modo

Especifica el modo de apagado. modo puede ser smart, fast, o immediate, o la primera letra de uno de estos tres. Si se omite esta opción, el predeterminado es fast.

-o opciones
--options=opciones

Especifica las opciones que se pasarán directamente al comando postgres. -o se puede especificar varias veces, y todas las opciones dadas se pasarán.

Las opciones normalmente deben estar rodeadas por comillas simples o dobles para asegurar que se pasen como un grupo.

-o initdb-options
--options=initdb-options

Especifica las opciones que se pasarán directamente al comando initdb. -o se puede especificar varias veces, y todas las opciones dadas se pasarán.

Las initdb-options normalmente deben estar rodeadas por comillas simples o dobles para asegurar que se pasen como un grupo.

-p ruta

Especifica la ubicación del ejecutable de postgres. Por defecto, el ejecutable de postgres se toma del mismo directorio que pg_ctl, o si no, del directorio de instalación codificado. No es necesario usar esta opción a menos que esté haciendo algo inusual y obtenga err
pg_ctl(1) — PostgreSQL 18.1

NAME

pg_ctl — initialize, start, stop, or control a PostgreSQL server

SYNOPSIS

pg_ctl [option...] command [value]...

pg_ctl [option...] init [value]...

pg_ctl [option...] initdb [value]...

pg_ctl [option...] start [value]...

pg_ctl [option...] stop [value]...

pg_ctl [option...] restart [value]...

pg_ctl [option...] reload [value]...

pg_ctl [option...] status [value]...

pg_ctl [option...] promote [value]...

pg_ctl [option...] register [value]...

pg_ctl [option...] unregister [value]...

DESCRIPTION

pg_ctl is a utility to initialize, start, stop, restart, reload, or check the status of a PostgreSQL server. It also supports registering and unregistering the server as a Windows service.

To control the server, you must know the location of the data directory. Typically, the data directory is specified using the -D option. If -D is omitted, pg_ctl will use the value of the PGDATA environment variable, if set. Otherwise, it will default to the current directory.

The initdb command initializes a new PostgreSQL database cluster. It is typically run only once when setting up a new database cluster.

The start command starts a PostgreSQL server. It requires the data directory to be initialized.

The stop command stops the PostgreSQL server. It supports several modes of shutdown (see the -m option).

The restart command stops and then starts the server. It has the ability to reuse the command line options passed to the previously running server instance.

The reload command tells the server to reload its configuration files. This happens without interrupting any active client connections.

The status command checks whether the PostgreSQL server is running. If it is, it prints the process ID (PID) and the command line used to start it.

The promote command tells a standby server to start accepting read/write connections. This essentially turns the standby into a primary server.

The register and unregister commands are used to install or remove the PostgreSQL server as a Windows service.

OPTIONS

-D directory

Specifies the location of the data directory.

-m mode

Specifies the mode for shutting down the server. Possible modes are:

smart

Allow only new connections to be made; wait until all existing connections are closed before shutting down. This is the default shutdown mode.

fast

Shut down immediately, aborting all active connections and transactions.

immediate

Shut down immediately and forcefully. This mode is only appropriate if the server cannot be shut down cleanly.

s, f, i

Short forms for the above modes.

-o options

Specifies command-line options to be passed to the postgres executable when starting or restarting the server. These options are passed directly to the postgres program.

For example, to start the server with a specific port and memory setting:

$ pg_ctl start -o "-p 5433 -B 128"

This option is also used to pass options to initdb in initdb mode.

$ pg_ctl initdb -o "-E UTF8"

-O options

Specifies command-line options to be passed to the initdb executable when initializing the data directory. This option is only relevant when using the initdb command.

-p path

Specifies the path to the postgres executable. In init mode, this specifies the path to the initdb executable.

-s
--silent

Print only errors, no informational messages.

-t seconds
--timeout=seconds

Specifies the maximum number of seconds to wait when waiting for an operation to complete (see option -w). Defaults to the value of the PGCTLTIMEOUT environment variable or, if not set, to 60 seconds.

-V
--version

Print the pg_ctl version and exit.

-w
--wait

Wait for the operation to complete. This is supported for the modes start, stop, restart, promote, and register, and is the default for those modes.

When waiting, pg_ctl repeatedly checks the server's PID file, sleeping for a short amount of time between checks. Startup is considered complete when the PID file indicates that the server is ready to accept connections. Shutdown is considered complete when the server removes the PID file. pg_ctl returns an exit code based on the success of the startup or shutdown.

If the operation does not complete within the timeout (see option -t), then pg_ctl exits with a nonzero exit status. But note that the operation might continue in the background and eventually succeed.

-W
--no-wait

Do not wait for the operation to complete. This is the opposite of the option -w.

If waiting is disabled, the requested action is triggered, but there is no feedback about its success. In that case, the server log file or an external monitoring system would have to be used to check the progress and success of the operation.

In prior releases of PostgreSQL, this was the default except for the stop mode.

-?
--help

Show help about pg_ctl command line arguments, and exit.

If an option is specified that is valid, but not relevant to the selected operating mode, pg_ctl ignores it.

Options for Windows

-e source

Name of the event source for pg_ctl to use for logging to the event log when running as a Windows service. The default is PostgreSQL. Note that this only controls messages sent from pg_ctl itself; once started, the server will use the event source specified by its event_source parameter. Should the server fail very early in startup, before that parameter has been set, it might also log using the default event source name PostgreSQL.

-N servicename

Name of the system service to register. This name will be used as both the service name and the display name. The default is PostgreSQL.

-P password

Password for the user to run the service as.

-S start-type

Start type of the system service. start-type can be auto, or demand, or the first letter of one of these two. If this option is omitted, auto is the default.

-U username

User name for the user to run the service as. For domain users, use the format DOMAIN\username.

ENVIRONMENT

PGCTLTIMEOUT

Default limit on the number of seconds to wait when waiting for startup or shutdown to complete. If not set, the default is 60 seconds.

PGDATA

Default data directory location.

Most pg_ctl modes require knowing the data directory location; therefore, the -D option is required unless PGDATA is set.

For additional variables that affect the server, see postgres(1).

FILES

postmaster.pid

pg_ctl examines this file in the data directory to determine whether the server is currently running.

postmaster.opts

If this file exists in the data directory, pg_ctl (in restart mode) will pass the contents of the file as options to postgres, unless overridden by the -o option. The contents of this file are also displayed in status mode.

EXAMPLES

Starting the Server

To start the server, waiting until the server is accepting connections:

$ pg_ctl start

To start the server using port 5433, and running without fsync, use:

$ pg_ctl -o "-F -p 5433" start

Stopping the Server

To stop the server, use:

$ pg_ctl stop

The -m option allows control over how the server shuts down:

$ pg_ctl stop -m smart

Restarting the Server

Restarting the server is almost equivalent to stopping the server and starting it again, except that by default, pg_ctl saves and reuses the command line options that were passed to the previously-running instance. To restart the server using the same options as before, use:

$ pg_ctl restart

But if -o is specified, that replaces any previous options. To restart using port 5433, disabling fsync upon restart:

$ pg_ctl -o "-F -p 5433" restart

Showing the Server Status

Here is sample status output from pg_ctl:

$ pg_ctl status
pg_ctl: server is running (PID: 13718)
/usr/local/pgsql/bin/postgres "-D" "/usr/local/pgsql/data" "-p" "5433" "-B" "128"

The second line is the command that would be invoked in restart mode.
