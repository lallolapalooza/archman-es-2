NOMBRE

pg_dump - exportar una base de datos PostgreSQL como un script SQL o a otros formatos

SINOPSIS

pg_dump [opción-conexión...] [opción...] [nombre-bd]

DESCRIPCIÓN

pg_dump es una utilidad para exportar una base de datos PostgreSQL. Realiza exportaciones consistentes incluso si la base de datos está siendo utilizada concurrentemente. pg_dump no bloquea a otros usuarios que acceden a la base de datos (lectores o escritores). Tenga en cuenta, sin embargo, que excepto en casos simples, pg_dump generalmente no es la opción correcta para realizar copias de seguridad regulares de bases de datos de producción. Consulte el Capítulo 25 para una mayor discusión.

pg_dump solo exporta una única base de datos. Para exportar un clúster completo, o para exportar objetos globales que son comunes a todas las bases de datos en un clúster (como roles y tablaspaces), use pg_dumpall(1).

Las exportaciones pueden ser de salida en formato de script o de archivo. Las exportaciones en formato de script son archivos de texto plano que contienen los comandos SQL necesarios para reconstruir la base de datos al estado en que se encontraba en el momento de guardarla. Para restaurar desde un script de este tipo, introdúzcalo a psql(1). Los archivos de script se pueden usar para reconstruir la base de datos incluso en otras máquinas y otras arquitecturas; con algunas modificaciones, incluso en otros productos de bases de datos SQL.

Los formatos alternativos de archivo de copia de seguridad deben usarse con pg_restore(1) para reconstruir la base de datos. Permiten que pg_restore sea selectivo sobre lo que se restaura, o incluso para reordenar los elementos antes de ser restaurados. Los formatos de archivo de copia de seguridad están diseñados para ser portátiles entre arquitecturas.

Cuando se usa con uno de los formatos de archivo de copia de seguridad y combinado con pg_restore, pg_dump proporciona un mecanismo flexible de archivo y transferencia. pg_dump se puede usar para exportar una base de datos completa, luego pg_restore se puede usar para examinar el archivo y/o seleccionar qué partes de la base de datos se restaurarán. Los formatos de archivo de salida más flexibles son el formato "personalizado" (-Fc) y el formato "directorio" (-Fd). Permiten la selección y reordenación de todos los elementos archivados, admiten la restauración paralela y se comprimen por defecto. El formato "directorio" es el único formato que admite exportaciones paralelas.

Al ejecutar pg_dump, se deben examinar las advertencias (impresas en la salida de error estándar), especialmente a la luz de las limitaciones que se enumeran a continuación.


Advertencia

Restaurar una exportación provoca la ejecución de código arbitrario que los superusuarios de origen elijan. Las exportaciones parciales y las restauraciones parciales no limitan eso. Si los superusuarios de origen no son de confianza, los comandos SQL exportados deben inspeccionarse antes de restaurarlos. Las exportaciones que no son de texto plano se pueden inspeccionar usando la opción --file de pg_restore. Tenga en cuenta que el cliente que ejecuta la exportación y la restauración no necesita confiar en los superusuarios de origen o destino.

OPCIONES

Las siguientes opciones de línea de comandos controlan el contenido y el formato de la salida.

nombre-bd

Especifica el nombre de la base de datos que se va a exportar. Si no se especifica, se utiliza la variable de entorno PGDATABASE. Si esta no está configurada, se utiliza el nombre de usuario especificado para la conexión.

-a
--data-only

Exportar solo los datos, no el esquema (definiciones de datos) ni las estadísticas. Se exportan los datos de las tablas, objetos grandes y valores de secuencias.

Esta opción es similar a, pero por razones históricas no idéntica a, especificar --section=data.

-b
--large-objects
--blobs (obsoleto)

Incluir objetos grandes en la exportación. Este es el comportamiento predeterminado, excepto cuando se especifican --schema, --table, --schema-only, --statistics-only o --no-data. El interruptor -b, por lo tanto, solo es útil para agregar objetos grandes a las exportaciones donde se ha solicitado un esquema o tabla específicos. Tenga en cuenta que los objetos grandes se consideran datos y, por lo tanto, se incluirán cuando se utilice --data-only, pero no cuando se utilice --schema-only o --statistics-only.

-B
--no-large-objects
--no-blobs (obsoleto)

Excluir objetos grandes de la exportación.

Cuando se proporcionan tanto -b como -B, el comportamiento es emitir objetos grandes, cuando se están exportando datos, consulte la documentación de -b.

-c
--clean

Emitir comandos para DROP (eliminar) todos los objetos de la base de datos exportados antes de emitir los comandos para crearlos. Esta opción es útil cuando la restauración va a sobrescribir una base de datos existente. Si alguno de los objetos no existe en la base de datos de destino, se informarán mensajes de error ignorables durante la restauración, a menos que también se especifique --if-exists.

Esta opción se ignora al emitir un archivo de salida de tipo archive (no de texto). Para los formatos de archive, puede especificar la opción al llamar a pg_restore.

-C
--create

Comenzar la salida con un comando para crear la base de datos en sí y volver a conectarse a la base de datos creada. (Con un script de esta forma, no importa a qué base de datos en la instalación de destino se conecte antes de ejecutar el script). Si también se especifica --clean, el script elimina y recrea la base de datos de destino antes de volver a conectarse a ella.

Con --create, la salida también incluye el comentario de la base de datos, si lo hay, y cualquier configuración de variable de configuración que sea específica de esta base de datos, es decir, cualquier comando ALTER DATABASE ... SET ... y ALTER ROLE ... IN DATABASE ... SET ... que mencionen esta base de datos. Los privilegios de acceso a la base de datos misma también se exportan, a menos que se especifique --no-acl.

Esta opción se ignora al emitir un archivo de salida de tipo archive (no de texto). Para los formatos de archive, puede especificar la opción al llamar a pg_restore.

-e patrón
--extension=patrón

Exportar solo las extensiones que coincidan con patrón. Cuando esta opción no se especifica, se exportarán todas las extensiones no del sistema en la base de datos de destino. Se pueden seleccionar varias extensiones escribiendo varios interruptores -e. El parámetro patrón se interpreta como un patrón según las mismas reglas utilizadas por los comandos \d de psql (consulte Patrones), por lo que también se pueden seleccionar varias extensiones escribiendo caracteres comodín en el patrón. Al usar comodines, tenga cuidado de citar el patrón si es necesario para evitar que el shell expanda los comodines.

Cualquier relación de configuración registrada por pg_extension_config_dump se incluye en la exportación si su extensión es especificada por --extension.


Nota
Cuando se especifica -e, pg_dump no intenta exportar ningún otro objeto de base de datos del que dependan las extensiones seleccionadas. Por lo tanto, no hay garantía de que los resultados de una exportación de extensión específica se puedan restaurar con éxito por sí solos en una base de datos limpia.

-E codificación
--encoding=codificación

Crear la exportación en el conjunto de caracteres de codificación especificado. Por defecto, la exportación se crea en la codificación de la base de datos. (Otra forma de obtener el mismo resultado es establecer la variable de entorno PGCLIENTENCODING a la codificación de exportación deseada). Las codificaciones admitidas se describen en la Sección 23.3.1.

-f archivo
--file=archivo

Enviar la salida al archivo especificado. Este parámetro se puede omitir para los formatos de salida basados en archivos, en cuyo caso se utiliza la salida estándar. Sin embargo, debe proporcionarse para el formato de salida de directorio, donde especifica el directorio de destino en lugar de un archivo. En este caso, el directorio es creado por pg_dump y no debe existir previamente.

-F formato
--format=formato

Selecciona el formato de la salida. formato puede ser uno de los siguientes:

p
plain

Emitir un archivo de script SQL de texto plano (el valor predeterminado).

c
custom

Emitir un archivo de copia de seguridad de formato personalizado adecuado para la entrada en pg_restore. Junto con el formato de salida de directorio, este es el formato de salida más flexible, ya que permite la selección manual y la reordenación de los elementos archivados.
pg_dump(1) PostgreSQL tools pg_dump(1) NAME pg_dump - PostgreSQL database backup utility SYNOPSIS pg_dump [connection-option...] [option...] [name] DESCRIPTION pg_dump is a utility for creating backups of a PostgreSQL database. pg_dump produces a dump of a single PostgreSQL database. The dump is a text file containing SQL commands that, when run, will recreate the database objects in their current state. If you append shell commands to compress the output, you can create a compressed archive of the database. pg_dump never dumps out any data that is not on the same PostgreSQL server as the database being dumped. When dumping to a file, pg_dump will write the output to the specified file or to standard output if no file is specified. When dumping to an archive file, pg_dump will write the output to a file named `archive-name`. The archive formats are: i plain Output a plain-text SQL script file. This is the default format. This format is also compressed by default. d directory Output an archive in directory format suitable for input into pg_restore. This will create a directory with one file for each table and large object being dumped, plus a so-called Table of Contents file describing the dumped objects in a machine-readable format that pg_restore can read. A directory format archive can be manipulated with standard Unix tools; for example, files in an uncompressed archive can be compressed with the gzip, lz4, or zstd tools. This format is compressed by default using gzip and also supports parallel dumps. t tar Output a tar-format archive suitable for input into pg_restore. The tar format is compatible with the directory format: extracting a tar-format archive produces a valid directory-format archive. However, the tar format does not support compression. Also, when using tar format the relative order of table data items cannot be changed during restore. The reason is that the pg_dump leader process requests shared locks (ACCESS SHARE) on the objects that the worker processes are going to dump later in order to make sure that nobody deletes them and makes them go away while the dump is running. { include | exclude } { extension | foreign_data | table | table_and_children | table_data | table_data_and_children | schema } PATTERN

La primera palabra clave especifica si los objetos que coinciden con el patrón deben incluirse o excluirse. La segunda palabra clave especifica el tipo de objeto que se filtrará usando el patrón:

•extension: extensiones. Esto funciona como la opción -e/--extension o --exclude-extension.
•foreign_data: datos en servidores externos. Esto funciona como la opción --include-foreign-data. Esta palabra clave solo se puede usar con la palabra clave include.
•table: tablas. Esto funciona como la opción -t/--table o -T/--exclude-table.
•table_and_children: tablas, incluidas las particiones o tablas hijas de herencia. Esto funciona como la opción --table-and-children o --exclude-table-and-children.
•table_data: datos de tablas de cualquier tabla que coincida con patrón. Esto funciona como la opción --exclude-table-data. Esta palabra clave solo se puede usar con la palabra clave exclude.
•table_data_and_children: datos de tablas de cualquier tabla que coincida con patrón, así como cualquier partición o tabla hija de herencia de la tabla (s). Esto funciona como la opción --exclude-table-data-and-children. Esta palabra clave solo se puede usar con la palabra clave exclude.
•schema: esquemas. Esto funciona como la opción -n/--schema o -N/--exclude-schema.

Las líneas que comienzan con # se consideran comentarios y se ignoran. Los comentarios también se pueden colocar después de una línea de patrón de objeto. Las líneas en blanco también se ignoran. Consulte Patrones para ver cómo realizar el entrecomillado en patrones.

DESCRIPTION

pg_dump es una utilidad de copia de seguridad de PostgreSQL. Copia una base de datos PostgreSQL en un script SQL o en archivos de archivo. El script puede ser ejecutado con psql para recrear la base de datos. Los archivos de archivo pueden ser utilizados por pg_restore para reconstruir la base de datos. pg_dump crea copias de seguridad de una sola base de datos. Para copiar un clúster de bases de datos completo (todos los bancos de datos, globales, pg_wal, y pg_toast), usa pg_dumpall.

pg_dump solo puede copiar objetos que el usuario que ejecuta la utilidad tenga permiso para ver. Por ejemplo, no puede volcar tablas que no están en el search_path.

pg_dump está diseñado para permitir que una base de datos sea operativa mientras se hace una copia de seguridad completa. pg_dump no bloquea los objetos de la base de datos; en su lugar, utiliza una transacción normal y repite solo los datos que estaban en vigor al inicio de la transacción.

El volcado de una base de datos a un archivo de texto plano puede requerir una gran cantidad de espacio en disco, pero es fácil de examinar y puede ser restaurado en versiones de PostgreSQL muy diferentes. Para volcar una base de datos a un archivo de formato personalizado o directorios, pg_restore debe ser usado para restaurar la base de datos. Estos formatos soportan la restauración paralela y la selección de objetos para restaurar. El formato de archivo personalizado es generalmente más compacto y rápido para restaurar que el formato de texto plano.

pg_dump realiza una copia de seguridad de una sola base de datos. Para hacer una copia de seguridad de un clúster de bases de datos completo, usa pg_dumpall.
