pg_restore(1)

Paquete: postgresql-libs

Licencias: PostgreSQL

PG_RESTORE(1) Documentación de PostgreSQL 18.1 PG_RESTORE(1)

NOMBRE

pg_restore - restaura una base de datos PostgreSQL desde un archivo de archivo creado por pg_dump

SINOPSIS

pg_restore [opción-conexión...] [opción...] [nombre-archivo]

DESCRIPCIÓN

pg_restore es una utilidad para restaurar una base de datos PostgreSQL desde un archivo creado por pg_dump(1) en uno de los formatos que no son de texto plano. Emitirá los comandos necesarios para reconstruir la base de datos al estado en que se encontraba en el momento en que se guardó. Los archivos de archivo también permiten a pg_restore ser selectivo sobre lo que se restaura, o incluso reordenar los elementos antes de ser restaurados. Los archivos de archivo están diseñados para ser portátiles entre arquitecturas.

pg_restore puede operar en dos modos. Si se especifica un nombre de base de datos, pg_restore se conecta a esa base de datos y restaura el contenido del archivo directamente en la base de datos. De lo contrario, se crea un script que contiene los comandos SQL necesarios para reconstruir la base de datos y se escribe en un archivo o en la salida estándar. Esta salida de script es equivalente al formato de salida de texto plano de pg_dump. Algunas de las opciones que controlan la salida son, por lo tanto, análogas a las opciones de pg_dump.

Obviamente, pg_restore no puede restaurar información que no esté presente en el archivo. Por ejemplo, si el archivo se creó utilizando la opción "volcar datos como comandos INSERT", pg_restore no podrá cargar los datos utilizando sentencias COPY.


Advertencia

Restaurar un volcado hace que el destino ejecute código arbitrario elegido por los superusuarios de origen. Los volcados parciales y las restauraciones parciales no limitan eso. Si los superusuarios de origen no son de confianza, las sentencias SQL volcadas deben ser inspeccionadas antes de restaurarlas. Los volcados no de texto plano se pueden inspeccionar utilizando la opción --file de pg_restore. Tenga en cuenta que el cliente que ejecuta el volcado y la restauración no necesita confiar en los superusuarios de origen o destino.

OPCIONES

pg_restore acepta los siguientes argumentos de línea de comandos.

nombre-archivo

Especifica la ubicación del archivo de archivo (o directorio, para un archivo de formato de directorio) que se va a restaurar. Si no se especifica, se utiliza la entrada estándar.

-a
--data-only

Restaura solo los datos, no el esquema (definiciones de datos) ni las estadísticas. Se restauran los datos de tablas, objetos grandes y valores de secuencias, si están presentes en el archivo.

Esta opción es similar a, pero por razones históricas no idéntica a, especificar --section=data.

-c
--clean

Antes de restaurar objetos de la base de datos, emita comandos para DROP todos los objetos que se van a restaurar. Esta opción es útil para sobrescribir una base de datos existente. Si alguno de los objetos no existe en la base de datos de destino, se informarán mensajes de error ignorables, a menos que también se especifique --if-exists.

-C
--create

Crea la base de datos antes de restaurar en ella. Si también se especifica --clean, elimina y recrea la base de datos de destino antes de conectarse a ella.

Con --create, pg_restore también restaura el comentario de la base de datos, si lo hay, y cualquier configuración de variable de configuración que sea específica de esta base de datos, es decir, cualquier comando ALTER DATABASE ... SET ... y ALTER ROLE ... IN DATABASE ... SET ... que hagan referencia a esta base de datos. Los privilegios de acceso para la base de datos en sí también se restauran, a menos que se especifique --no-acl.

Cuando se utiliza esta opción, la base de datos nombrada con -d se utiliza solo para emitir los comandos iniciales DROP DATABASE y CREATE DATABASE. Todos los datos se restauran en el nombre de la base de datos que aparece en el archivo.

-d dbname
--dbname=dbname

Conéctese a la base de datos dbname y restaure directamente en la base de datos. El dbname puede ser una cadena de conexión. Si es así, los parámetros de la cadena de conexión anularán cualquier opción de línea de comandos conflictiva.

-e
--exit-on-error

Salga si se encuentra un error al enviar comandos SQL a la base de datos. El valor predeterminado es continuar y mostrar un recuento de errores al final de la restauración.

-f nombre-archivo
--file=nombre-archivo

Especifique el archivo de salida para el script generado, o para la lista cuando se usa con -l. Use - para stdout.

-F formato
--format=formato

Especifique el formato del archivo. No es necesario especificar el formato, ya que pg_restore determinará el formato automáticamente. Si se especifica, puede ser uno de los siguientes:

c
custom

El archivo está en el formato personalizado de pg_dump.

d
directory

El archivo es un archivo de directorio.

t
tar

El archivo es un archivo tar.

-I índice
--index=índice

Restaura solo la definición del índice nombrado. Se pueden especificar varios índices con varios interruptores -I.

-j número-de-trabajos
--jobs=número-de-trabajos

Ejecuta los pasos que consumen más tiempo de pg_restore — aquellos que cargan datos, crean índices o crean restricciones — concurrentemente, utilizando hasta número-de-trabajos sesiones concurrentes. Esta opción puede reducir drásticamente el tiempo para restaurar una base de datos grande en un servidor que se ejecuta en una máquina multiprocesador. Esta opción se ignora al emitir un script en lugar de conectarse directamente a un servidor de base de datos.

Cada trabajo es un proceso o un hilo, dependiendo del sistema operativo, y utiliza una conexión separada al servidor.

El valor óptimo para esta opción depende de la configuración de hardware del servidor, del cliente y de la red. Los factores incluyen el número de núcleos de CPU y la configuración del disco. Un buen punto de partida es el número de núcleos de CPU del servidor, pero los valores mayores que eso también pueden conducir a tiempos de restauración más rápidos en muchos casos. Por supuesto, los valores demasiado altos provocarán una disminución del rendimiento debido al intercambio.

Solo los formatos de archivo personalizados y de directorio son compatibles con esta opción. La entrada debe ser un archivo o directorio regular (no, por ejemplo, una tubería o entrada estándar). Además, no se pueden usar trabajos múltiples junto con la opción --single-transaction.

-l
--list

Lista la tabla de contenido del archivo. La salida de esta operación se puede utilizar como entrada para la opción -L. Tenga en cuenta que si se utilizan interruptores de filtrado como -n o -t con -l, restringirán los elementos listados.

-L archivo-lista
--use-list=archivo-lista

Restaura solo aquellos elementos del archivo que están listados en archivo-lista, y los restaura en el orden en que aparecen en el archivo. Tenga en cuenta que si se utilizan interruptores de filtrado como -n o -t con -L, restringirán aún más los elementos restaurados.

archivo-lista normalmente se crea editando la salida de una operación -l anterior. Las líneas se pueden mover o eliminar, y también se pueden comentar colocando un punto y coma (; ) al principio de la línea. Consulte más abajo para ver ejemplos.

-n esquema
--schema=esquema

Restaura solo los objetos que están en el esquema nombrado. Se pueden especificar varios esquemas con varios interruptores -n. Esto se puede combinar con la opción -t para restaurar solo una tabla específica.

-N esquema
--exclude-schema=esquema

No restaure objetos que estén en el esquema nombrado. Se pueden especificar varios esquemas a excluir con varios interruptores -N.

Cuando se dan tanto -n como -N para el mismo nombre de esquema, el interruptor -N tiene prioridad y el esquema se excluye.

-O
--no-owner

No emita comandos para establecer la propiedad de los objetos para que coincidan con la base de datos original. Por defecto, pg_restore emite sentencias ALTER OWNER o SET SESSION AUTHORIZATION para establecer el propietario
ship of created schema elements. These statements will fail unless the initial connection to the database is made by a superuser (or the same user that owns all of the objects in the script). With -O, any user name can be used for the initial connection, and this user will own all the created objects.

-P function-name(argtype [, ...])
--function=function-name(argtype [, ...])

Restaura solo la función nombrada. Ten cuidado de escribir el nombre de la función y los argumentos exactamente como aparecen en el archivo de volcado. Se pueden especificar varias funciones con varios modificadores -P.

-R
--no-reconnect

Esta opción es obsoleta pero se sigue aceptando por compatibilidad con versiones anteriores.

-s
--schema-only

Restaura solo el esquema (definiciones de datos), no los datos, en la medida en que las entradas del esquema estén presentes en el archivo.

Esta opción no se puede usar con --data-only o --statistics-only. Es similar, pero por razones históricas no idéntica, a especificar --section=pre-data --section=post-data --no-statistics.

(No confundir con la opción --schema, que usa la palabra "esquema" en un significado diferente).

-S username
--superuser=username

Especifica el nombre de usuario superusuario a utilizar al deshabilitar triggers. Esto solo es relevante si se usa --disable-triggers.

-t table
--table=table

Restaura la definición y/o datos solo de la tabla nombrada. Para este propósito, "tabla" incluye vistas, vistas materializadas, secuencias y tablas externas. Se pueden seleccionar varias tablas escribiendo varios modificadores -t. Esta opción se puede combinar con la opción -n para especificar tabla(s) en un esquema particular.

Nota
Cuando se especifica -t, pg_restore no intenta restaurar ningún otro objeto de base de datos del que dependan las tabla(s) seleccionada(s). Por lo tanto, no hay garantía de que una restauración de tabla específica en una base de datos limpia tenga éxito.

Nota
Esta bandera no se comporta de manera idéntica a la bandera -t de pg_dump. Actualmente no hay provisión para coincidencias de comodines en pg_restore, ni se puede incluir un nombre de esquema dentro de su -t. Y, mientras que la bandera -t de pg_dump también volcará objetos subsidiarios (como índices) de las tabla(s) seleccionada(s), la bandera -t de pg_restore no incluye dichos objetos subsidiarios.

Nota
En versiones anteriores a PostgreSQL 9.6, esta bandera solo coincidía con tablas, no con ningún otro tipo de relación.

-T trigger
--trigger=trigger

Restaura solo el trigger nombrado. Se pueden especificar varios triggers con varios modificadores -T.

-v
--verbose

Especifica el modo detallado. Esto hará que pg_restore genere comentarios detallados de objetos y tiempos de inicio/fin en el archivo de salida, y mensajes de progreso en la salida estándar de error. Repetir la opción hará que aparezcan mensajes adicionales de nivel de depuración en la salida estándar de error.

-V
--version

Imprime la versión de pg_restore y sale.

-x
--no-privileges
--no-acl

Evita la restauración de privilegios de acceso (comandos grant/revoke).

-1
--single-transaction

Ejecuta la restauración como una única transacción (es decir, envuelve los comandos emitidos en BEGIN/COMMIT). Esto asegura que todos los comandos se completen con éxito, o que no se apliquen cambios. Esta opción implica --exit-on-error.

--disable-triggers

Esta opción solo es relevante al realizar una restauración sin esquema. Indica a pg_restore que ejecute comandos para deshabilitar temporalmente los triggers en las tablas de destino mientras se restauran los datos. Úsala si tienes comprobaciones de integridad referencial u otros triggers en las tablas que no deseas invocar durante la restauración de datos.

Actualmente, los comandos emitidos para --disable-triggers deben ser ejecutados como superusuario. Por lo tanto, también deberías especificar un nombre de superusuario con -S o, preferiblemente, ejecutar pg_restore como un superusuario de PostgreSQL.

--enable-row-security

Esta opción solo es relevante al restaurar el contenido de una tabla que tiene seguridad a nivel de fila. Por defecto, pg_restore establecerá row_security en "off", para asegurar que todos los datos se restauren en la tabla. Si el usuario no tiene privilegios suficientes para omitir la seguridad a nivel de fila, se lanzará un error. Este parámetro indica a pg_restore que establezca row_security en "on" en su lugar, permitiendo al usuario intentar restaurar el contenido de la tabla con la seguridad a nivel de fila habilitada. Esto aún podría fallar si el usuario no tiene derecho a insertar las filas del volcado en la tabla.

Ten en cuenta que esta opción actualmente también requiere que el volcado esté en formato INSERT, ya que COPY FROM no admite la seguridad a nivel de fila.

--filter=filename

Especifica un nombre de archivo del que leer patrones para los objetos excluidos o incluidos de la restauración. Los patrones se interpretan de acuerdo con las mismas reglas que -n/--schema para incluir objetos en esquemas, -N/--exclude-schema para excluir objetos en esquemas, -P/--function para restaurar funciones nombradas, -I/--index para restaurar índices nombrados, -t/--table para restaurar tablas nombradas o -T/--trigger para restaurar triggers. Para leer desde STDIN, usa - como nombre de archivo. La opción --filter se puede especificar junto con las opciones enumeradas anteriormente para incluir o excluir objetos, y también se puede especificar más de una vez para varios archivos de filtro.

El archivo lista un patrón de base de datos por línea, con el siguiente formato:

{ include | exclude } { function | index | schema | table | trigger } PATTERN

La primera palabra clave especifica si los objetos que coinciden con el patrón deben incluirse o excluirse. La segunda palabra clave especifica el tipo de objeto a filtrar usando el patrón:

•function: funciones, funciona como la opción -P/--function. Esta palabra clave solo se puede usar con la palabra clave include.
•index: índices, funciona como la opción -I/--indexes. Esta palabra clave solo se puede usar con la palabra clave include.
•schema: esquemas, funciona como las opciones -n/--schema y -N/--exclude-schema.
•table: tablas, funciona como la opción -t/--table. Esta palabra clave solo se puede usar con la palabra clave include.
•trigger: triggers, funciona como la opción -T/--trigger. Esta palabra clave solo se puede usar con la palabra clave include.

Las líneas que comienzan con # se consideran comentarios y se ignoran. Los comentarios también se pueden colocar después de una línea de patrón de objeto. Las líneas en blanco también se ignoran. Consulte Patrones para ver cómo realizar el entrecomillado en los patrones.

--if-exists

Usa comandos DROP ... IF EXISTS para eliminar objetos en modo --clean. Esto suprime los errores de "no existe" que de otro modo podrían reportarse. Esta opción no es válida a menos que también se especifique --clean.

--no-comments

No emite comandos para restaurar comentarios, incluso si el archivo los contiene.

--no-data

No emite comandos para restaurar datos, incluso si el archivo los contiene.

--no-data-for-failed-tables

Por defecto, los datos de la tabla se restauran incluso si el comando de creación de la tabla falló (por ejemplo, porque ya existe). Con esta opción, los datos de dicha tabla se omiten. Este comportamiento es útil si la base de datos de destino ya contiene el contenido deseado de la tabla. Por ejemplo, las tablas auxiliares para extensiones de PostgreSQL como PostGIS podrían ya estar cargadas en la base de datos de destino; especificar esta opción evita que se carguen datos duplicados u obsoletos en ellas.

Esta opción solo es efectiva al restaurar directamente en una base de datos, no al producir salida de script SQL.

--no-policies

No emite comandos para restaurar políticas de seguridad a nivel de fila, incluso si el archivo las contiene.

--no-publications

No emite comandos para restaurar publicaciones, incluso si el archivo las contiene.

--no-schema

No emite comandos para restaurar el esquema (definiciones de datos), incluso si el archivo los contiene.

--no-security-labels

No emite comandos para restaurar etiquetas de seguridad, incluso si el archivo las contiene.

--no-statistics

No emite comandos para restaurar estadísticas, incluso si el archivo las contiene.

--no-subscriptions

No emite comandos para restaurar suscripciones, incluso si el archivo las contiene.

--no-table-access-method

No emite comandos para seleccionar métodos de acceso a tablas. Con esta opción, todos los objetos se crearán con el método de acceso a tablas que sea el predeterminado durante la restauración.

--no-tablespaces

No emite comandos para seleccionar tablespaces. Con esta opción, todos los objetos se crearán en el tablespace que sea el predeterminado durante la restauración.

--restrict-key=restrict_key

Usa la cadena proporcionada como clave \restrict de psql en la salida del volcado. Esto solo se puede especificar para la salida de script SQL, es decir, cuando se usa la opción --file. Si no se especifica ninguna clave restrictiva, pg_restore generará una aleatoria según sea necesario. Las claves solo pueden contener caracteres alfanuméricos.

Esta opción está destinada principalmente a fines de prueba y otros escenarios que requieren una salida repetible (por ejemplo, para comparar archivos de volcado). No se recomienda para uso general, ya que un servidor malicioso con conocimiento previo de la clave podría inyectar código arbitrario que se ejecutará en la máquina que ejecuta psql con la salida del volcado.

--section=sectionname

Restaura solo la sección nombrada. El nombre de la sección puede ser pre-data, data o post-data. Esta opción se puede especificar más de una vez para seleccionar varias secciones. El valor predeterminado es restaurar todas las secciones.

La sección de datos contiene los datos reales de las tablas, así como las definiciones de objetos grandes. Los elementos post-data consisten en definiciones de índices

s, disparadores, reglas y restricciones distintos de las restricciones de verificación validadas. Los elementos pre-datos consisten en todos los demás elementos de definición de datos.

--statistics

Emite comandos para restaurar las estadísticas, si el archivo las contiene. Este es el comportamiento predeterminado.

--statistics-only

Restaura solo las estadísticas, no el esquema (definiciones de datos) ni los datos.

--strict-names

Exige que cada calificador de esquema (-n/--schema) y tabla (-t/--table) coincida al menos con un esquema/tabla en el archivo que se va a restaurar.

--transaction-size=N

Ejecuta la restauración como una serie de transacciones, cada una procesando hasta N objetos de base de datos. Esta opción implica --exit-on-error.

--transaction-size ofrece una opción intermedia entre el comportamiento predeterminado (una transacción por comando SQL) y -1/--single-transaction (una transacción para todos los objetos restaurados). Mientras que --single-transaction tiene la menor sobrecarga, puede no ser práctico para bases de datos grandes porque la transacción bloqueará cada objeto restaurado, posiblemente agotando el espacio de la tabla de bloqueos del servidor. Usar --transaction-size con un tamaño de unos pocos miles de objetos ofrece casi los mismos beneficios de rendimiento al tiempo que limita la cantidad de espacio de tabla de bloqueos necesario.

--use-set-session-authorization

Emite comandos SQL estándar SET SESSION AUTHORIZATION en lugar de comandos ALTER OWNER para determinar la propiedad de los objetos. Esto hace que la copia de seguridad sea más compatible con los estándares, pero dependiendo del historial de los objetos en la copia de seguridad, puede que no se restaure correctamente.

-?
--help

Muestra la ayuda sobre los argumentos de la línea de comandos de pg_restore y sale.

pg_restore también acepta los siguientes argumentos de línea de comandos para parámetros de conexión:

-h host
--host=host

Especifica el nombre del host de la máquina en la que se está ejecutando el servidor. Si el valor comienza con una barra, se utiliza como directorio para el socket de dominio Unix. El valor predeterminado se toma de la variable de entorno PGHOST, si está configurada, de lo contrario se intenta una conexión de socket de dominio Unix.

-p port
--port=port

Especifica el puerto TCP o la extensión del archivo de socket de dominio Unix local en el que el servidor está escuchando las conexiones. El valor predeterminado es la variable de entorno PGPORT, si está configurada, o un valor predeterminado compilado.

-U username
--username=username

Nombre de usuario para conectarse.

-w
--no-password

Nunca solicita una contraseña. Si el servidor requiere autenticación por contraseña y esta no está disponible por otros medios, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para introducir una contraseña.

-W
--password

Obliga a pg_restore a solicitar una contraseña antes de conectarse a una base de datos.

Esta opción nunca es esencial, ya que pg_restore solicitará automáticamente una contraseña si el servidor exige autenticación por contraseña. Sin embargo, pg_restore malgastará un intento de conexión al descubrir que el servidor quiere una contraseña. En algunos casos, vale la pena escribir -W para evitar el intento de conexión adicional.

--role=rolename

Especifica un nombre de rol que se utilizará para realizar la restauración. Esta opción hace que pg_restore emita un comando SET ROLE rolename después de conectarse a la base de datos. Es útil cuando el usuario autenticado (especificado por -U) carece de los privilegios necesarios por pg_restore, pero puede cambiar a un rol con los derechos requeridos. Algunas instalaciones tienen una política en contra de iniciar sesión directamente como superusuario, y el uso de esta opción permite que las restauraciones se realicen sin violar la política.

PGHOST

PG_COLOR

Especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son siempre, automático y nunca.

Esta utilidad, al igual que la mayoría de las otras utilidades de PostgreSQL, también utiliza las variables de entorno compatibles con libpq (ver Sección 32.15). Sin embargo, no lee PGDATABASE cuando no se proporciona un nombre de base de datos.

DIAGNÓSTICO

Cuando se especifica una conexión directa a la base de datos usando la opción -d, pg_restore ejecuta internamente sentencias SQL. Si tiene problemas al ejecutar pg_restore, asegúrese de que puede seleccionar información de la base de datos usando, por ejemplo, psql(1). Además, se aplicarán todos los ajustes de conexión predeterminados y las variables de entorno utilizadas por la biblioteca front-end libpq.

NOTAS

Si su instalación tiene alguna adición local a la base de datos template1, tenga cuidado de cargar la salida de pg_restore en una base de datos verdaderamente vacía; de lo contrario, es probable que obtenga errores debido a definiciones duplicadas de los objetos agregados. Para crear una base de datos vacía sin adiciones locales, copie desde template0 y no desde template1, por ejemplo:

CREATE DATABASE foo WITH TEMPLATE template0;

Las limitaciones de pg_restore se detallan a continuación.

•Al restaurar datos en una tabla preexistente y se utiliza la opción --disable-triggers, pg_restore emite comandos para deshabilitar los disparadores en las tablas de usuario antes de insertar los datos, y luego emite comandos para volver a habilitarlos después de que los datos se hayan insertado. Si la restauración se detiene en medio, los catálogos del sistema podrían quedar en un estado incorrecto.
•pg_restore no puede restaurar objetos grandes de forma selectiva; por ejemplo, solo aquellos para una tabla específica. Si un archivo contiene objetos grandes, entonces todos los objetos grandes se restaurarán, o ninguno de ellos si se excluyen mediante -L, -t u otras opciones.

Vea también la documentación de pg_dump(1) para obtener detalles sobre las limitaciones de pg_dump.

Por defecto, pg_restore restaurará las estadísticas del optimizador si están incluidas en el archivo de volcado. Si no se restauraron todas las estadísticas, puede ser útil ejecutar ANALYZE en cada tabla restaurada para que el optimizador tenga estadísticas útiles; vea la Sección 24.1.3 y la Sección 24.1.6 para más información.

EJEMPLOS

Supongamos que hemos volcado una base de datos llamada mydb en un archivo de volcado de formato personalizado:

$ pg_dump -Fc mydb > db.dump

Para eliminar la base de datos y recrearla a partir del volcado:

$ dropdb mydb
$ pg_restore -C -d postgres db.dump

La base de datos nombrada en el modificador -d puede ser cualquier base de datos existente en el clúster; pg_restore solo la utiliza para emitir el comando CREATE DATABASE para mydb. Con -C, los datos siempre se restauran en la base de datos nombrada que aparece en el archivo de volcado.

Para restaurar el volcado en una nueva base de datos llamada newdb:

$ createdb -T template0 newdb
$ pg_restore -d newdb db.dump

Observe que no usamos -C, y en su lugar nos conectamos directamente a la base de datos a la que se va a restaurar. También observe que clonamos la nueva base de datos desde template0 y no desde template1, para asegurarnos de que esté inicialmente vacía.

Para reordenar los elementos de la base de datos, primero es necesario volcar la tabla de contenidos del archivo:

$ pg_restore -l db.dump > db.list

El archivo de listado consta de una cabecera y una línea para cada elemento, por ejemplo:

;
; Archivo creado el Lun Sep 14 13:55:39 2009
;     dbname: DBDEMOS
