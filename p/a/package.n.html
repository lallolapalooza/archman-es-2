package(n) Comandos integrados de Tcl package(n)

NOMBRE

package - Instalaciones para la carga de paquetes y control de versiones

SINOPSIS

package forget ?paquete paquete ...?
package ifneeded paquete versión ?script?
package names
package present paquete ?requisito...?
package present -exact paquete versión
package provide paquete ?versión?
package require paquete ?requisito...?
package require -exact paquete versión
package unknown ?comando?
package vcompare versión1 versión2
package versions paquete
package vsatisfies versión requisito...
package prefer ?latest|stable?

DESCRIPCIÓN

Este comando mantiene una base de datos simple de los paquetes disponibles para su uso por el intérprete actual y cómo cargarlos en el intérprete. Soporta múltiples versiones de cada paquete y organiza la carga de la versión correcta de un paquete según lo que necesite la aplicación. Este comando también detecta y reporta conflictos de versiones. Típicamente, solo los comandos package require y package provide se invocan en scripts Tcl normales; los otros comandos se usan principalmente en scripts del sistema que mantienen la base de datos de paquetes.

El comportamiento del comando package está determinado por su primer argumento. Las siguientes formas están permitidas:

package forget ?paquete paquete ...?
Elimina toda la información sobre cada paquete especificado de este intérprete, incluida la información proporcionada tanto por package ifneeded como por package provide.
package ifneeded paquete versión ?script?
Este comando aparece típicamente solo en scripts de configuración del sistema para configurar la base de datos de paquetes. Indica que una versión particular de un paquete particular está disponible si es necesaria, y que el paquete puede ser añadido al intérprete ejecutando script. El script se guarda en una base de datos para su uso por comandos package require posteriores; típicamente, script configura la carga automática de los comandos en el paquete (o llama directamente a load y/o source), luego invoca package provide para indicar que el paquete está presente. Puede haber información en la base de datos para varias versiones diferentes de un solo paquete. Si la base de datos ya contiene información para paquete y versión, el nuevo script reemplaza el existente. Si el argumento script se omite, se devuelve el script actual para la versión versión del paquete paquete, o una cadena vacía si no se ha invocado ningún comando package ifneeded para este paquete y versión.
package names
Devuelve una lista de los nombres de todos los paquetes en el intérprete para los cuales se ha proporcionado una versión (a través de package provide) o para los cuales hay un script package ifneeded disponible. El orden de los elementos en la lista es arbitrario.
package present ?-exact? paquete ?requisito...?
Este comando es equivalente a package require excepto que no intenta cargar el paquete si no está ya cargado.
package provide paquete ?versión?
Este comando se invoca para indicar que la versión versión del paquete paquete está ahora presente en el intérprete. Típicamente se invoca una vez como parte de un script ifneeded, y de nuevo por el propio paquete cuando finalmente se carga. Ocurre un error si una versión diferente de paquete ha sido proporcionada por un comando package provide anterior. Si se omite el argumento versión, entonces el comando devuelve el número de versión que se proporciona actualmente, o una cadena vacía si no se ha invocado ningún comando package provide para paquete en este intérprete.
package require paquete ?requisito...?
Este comando lo invocan típicamente el código Tcl que desea utilizar una versión particular de un paquete particular. Los argumentos indican qué paquete se desea, y el comando asegura que una versión adecuada del paquete se cargue en el intérprete. Si el comando tiene éxito, devuelve el número de versión que se carga; de lo contrario, genera un error.

Una versión adecuada del paquete es cualquier versión que cumpla al menos uno de los requisitos, según las reglas de package vsatisfies. Si múltiples versiones son adecuadas, se elige la implementación con la versión más alta. Esta última parte está además influenciada por el modo de selección establecido con package prefer.

En el modo de selección “stable” (estable), el comando seleccionará la versión estable más alta que cumpla los requisitos, si la hay. Si ninguna versión estable cumple los requisitos, se seleccionará la versión inestable más alta que cumpla los requisitos. En el modo de selección “latest” (última), el comando aceptará la versión más alta que cumpla todos los requisitos, independientemente de su estabilidad.

Si una versión de paquete ya ha sido proporcionada (invocando el comando package provide), entonces su número de versión debe cumplir los requisitos y el comando devuelve inmediatamente. De lo contrario, el comando busca en la base de datos de información proporcionada por comandos package ifneeded anteriores para ver si hay disponible una versión aceptable del paquete. Si es así, el script de la versión más alta aceptable se evalúa en el espacio de nombres global; debe hacer lo que sea necesario para cargar el paquete, incluida la llamada a package provide para el paquete. Si la base de datos package ifneeded no contiene una versión aceptable del paquete y se ha especificado un comando package unknown para el intérprete, entonces ese comando se evalúa en el espacio de nombres global; cuando se completa, Tcl vuelve a comprobar si el paquete ya está proporcionado o si hay un script package ifneeded para él. Si todos estos pasos fallan en proporcionar una versión aceptable del paquete, entonces el comando devuelve un error.

package require -exact paquete versión
Esta forma del comando se utiliza cuando solo la versión dada de paquete es aceptable para el llamador. Este comando es equivalente a package require paquete versión-versión.
package unknown ?comando?
Este comando proporciona un comando de "último recurso" para invocar durante package require si no se puede encontrar una versión adecuada de un paquete en la base de datos package ifneeded. Si se proporciona el argumento comando, contiene la primera parte de un comando; cuando se invoca el comando durante un comando package require, Tcl añade uno o más argumentos adicionales que dan el nombre del paquete deseado y los requisitos. Por ejemplo, si comando es foo bar y más tarde se invoca el comando package require test 2.4, Tcl ejecutará el comando foo bar test 2.4 para cargar el paquete. Si no se proporcionan requisitos al comando package require, entonces solo se añadirá el nombre al comando invocado. Si se invoca el comando package unknown sin el argumento comando, entonces se devuelve el script package unknown actual, o una cadena vacía si no hay ninguno. Si comando se especifica como una cadena vacía, entonces se elimina el script package unknown actual, si existe.
package vcompare versión1 versión2
Compara los dos números de versión dados por versión1 y versión2. Devuelve -1 si versión1 es una versión anterior a versión2, 0 si son iguales, y 1 si versión1 es posterior a versión2.
package versions paquete
Devuelve una lista de todos los números de versión de paquete para los cuales se ha proporcionado información mediante comandos package ifneeded.
package vsatisfies versión requisito...
Devuelve 1 si la versión cumple al menos uno de los requisitos dados, y 0 ot

package(n)

NOMBRE

package - Mecanismo para el control de versiones y carga de paquetes de Tcl

SINOPSIS

package present ?pattern?
package require ?-exact? ?packageName? ?version?
package provide packageName version
package versions ?packageName?
package available ?packageName?
package ifneeded packageName ?version? script
package prefer ?latest|stable?

DESCRIPCIÓN

El subsistema de paquetes de Tcl es un mecanismo para la gestión de bibliotecas de código Tcl. Permite a los desarrolladores de paquetes declarar qué versiones de sus paquetes proporcionan y qué otros paquetes y versiones requieren. Permite a los scripts de Tcl solicitar versiones específicas de paquetes y se encarga de la carga automática de los paquetes requeridos.

Los comandos siguientes están disponibles:

package present ?pattern?
Si no se proporciona ningún argumento, devuelve una lista de todos los nombres de paquetes que han sido proporcionados al intérprete Tcl en algún momento. Si se proporciona un patrón, devuelve una lista de los nombres de paquetes que coinciden con el patrón. El patrón es un patrón de estilo glob que se compara con los nombres de los paquetes.
package require ?-exact? ?packageName? ?version?
Este es el comando principal para solicitar un paquete. Si el paquete ya está cargado, el comando simplemente devuelve la cadena de versión proporcionada (o la versión más alta proporcionada si no se solicita una versión específica). Si el paquete no está cargado, Tcl buscará un script de carga para el paquete, lo cargará y luego devolverá la cadena de versión proporcionada. Si se proporciona la opción -exact, se requerirá una coincidencia exacta de la versión; de lo contrario, se permite la coincidencia de versiones posteriores. Si el paquete no se puede encontrar, o si no se puede encontrar una versión adecuada, se genera un error. Si se solicitan un nombre de paquete y una versión, Tcl buscará el paquete con ese nombre y la versión especificada o una versión posterior. Si solo se solicita un nombre de paquete, se puede solicitar cualquier versión. El comportamiento predeterminado es el de una coincidencia de versiones no exacta, lo que significa que se puede cargar una versión posterior si la versión solicitada no está disponible.
package provide packageName version
Este comando se utiliza dentro de un script de paquete para declarar que el script proporciona un paquete específico con un número de versión específico. El intérprete Tcl almacena esta información para su uso posterior por parte del comando package require.
package versions ?packageName?
Si no se proporciona ningún argumento, devuelve una lista de todas las versiones de todos los paquetes que han sido proporcionados al intérprete Tcl. Si se proporciona un nombre de paquete, devuelve una lista de todas las versiones de ese paquete específico que han sido proporcionadas.
package available ?packageName?
Si no se proporciona ningún argumento, devuelve una lista de todos los paquetes que Tcl sabe que están disponibles (ya sea cargados o con un script de carga disponible). Si se proporciona un nombre de paquete, devuelve una lista de todas las versiones disponibles de ese paquete específico. La información sobre los paquetes disponibles se obtiene de los directorios especificados en la variable de Tcl auto_path.
package ifneeded packageName ?version? script
Este comando registra un script que se ejecutará cuando se requiera un paquete específico (y una versión opcional). El script se ejecutará solo una vez, la primera vez que se cumpla el requisito. El script debe contener un comando package provide para declarar el paquete y su versión. Esto es útil para cargar paquetes que no se distribuyen como archivos de código fuente individuales.

Las versiones de los paquetes se pueden especificar de varias maneras. La sintaxis antigua y la nueva sintaxis extendida son compatibles. Las versiones se comparan numéricamente. Por ejemplo, la versión 1.2.3 es posterior a la versión 1.2.2, y la versión 1.3 es posterior a la versión 1.2.99.

Cada requisito puede tener una de las siguientes formas:

min
Esta forma se llama "bounded-min".
min-
Esta forma se llama "unbounded-min".
min-max
Esta forma se llama "bounded".

donde "min" y "max" son números de versión válidos. La sintaxis antigua es un caso especial de la sintaxis extendida, manteniendo la compatibilidad hacia atrás. En cuanto a la satisfacción, las reglas son:

[1]
La versión tiene que pasar al menos uno de los requisitos listados para ser satisfactoria.
[2]
Una versión satisface un requisito "bounded" cuando
[a]
Para min igual a max si, y solo si la versión es igual a min.
[b]
De lo contrario si, y solo si la versión es mayor o igual a min, y menor que max, donde tanto min como max han sido rellenados internamente con "a0". Tenga en cuenta que mientras la comparación con min es inclusiva, la comparación con max es exclusiva.
[3]
Un requisito "bounded-min" es un requisito "bounded" disfrazado, con la parte max especificada implícitamente como el siguiente número de versión principal más alto de la parte min. Una versión lo satisface según las reglas anteriores.
[4]
Una versión satisface un requisito "unbounded-min" si, y solo si es mayor o igual a min, donde min ha sido rellenado internamente con "a0". No hay restricción a un máximo.
package prefer ?latest|stable?
Sin argumentos, los comandos devuelven "latest" o "stable", el que describe el modo actual de lógica de selección utilizado por package require.

Cuando se le pasa el argumento "latest", establece el modo de lógica de selección a "latest".

Cuando se le pasa el argumento "stable", si el modo ya es "stable", se mantiene ese valor. Si el modo ya es "latest", entonces el intento de volver a establecerlo en "stable" es ineficaz y el valor del modo permanece "latest".

Cuando se le pasa cualquier otro valor como argumento, genera un error de argumento inválido.

Cuando se crea un intérprete, su valor inicial de modo de selección se establece en "stable", a menos que la variable de entorno TCL_PKG_PREFER_LATEST esté configurada. Si esa variable de entorno está definida (con cualquier valor), entonces el valor inicial (y permanente) del modo de selección se establece en "latest".

NÚMEROS DE VERSIÓN

Los números de versión consisten en uno o más números decimales separados por puntos, como 2 o 1.162 o 3.1.13.1. El primer número se llama número de versión principal. Los números más grandes corresponden a versiones posteriores de un paquete, siendo los números de la izquierda los de mayor importancia. Por ejemplo, la versión 2.1 es posterior a la 1.3 y la versión 3.4.6 es posterior a la 3.3.5. Los campos que faltan equivalen a ceros: la versión 1.3 es lo mismo que la versión 1.3.0 y 1.3.0.0, por lo que es anterior a 1.3.1 o 1.3.0.2. Además, las letras "a" (alfa) y/o "b" (beta) pueden aparecer exactamente una vez para reemplazar un punto de separación. Estas letras añaden semánticamente un especificador negativo a la versión, donde "a" es -2 y "b" es -1. Cada una puede especificarse solo una vez, y "a" o "b" son mutuamente excluyentes en un especificador. Así, 1.3a1 se convierte (semánticamente) en 1.3.-2.1, 1.3b1 es 1.3.-1.1. No se permiten números negativos directamente en los especificadores de versión. Un número de versión que no contiene las letras "a" o "b" según lo especificado anteriormente se llama versión estable, mientras que la presencia de las letras hace que la versión se llame inestable. Se asume que un número de versión posterior es compatible hacia atrás con un número de versión anterior siempre que ambas versiones tengan el mismo número de versión principal. Por ejemplo, los scripts de Tcl escritos para la versión 2.3 de un paquete deberían funcionar sin cambios en las versiones 2.3.2, 2.4 y 2.5.1. Los cambios en el número de versión principal significan cambios incompatibles: si el código está escrito para usar la versión 2.1 de un paquete, no se garantiza que funcione sin modificaciones con la versión 1.7.3 o la versión 3.1.

ÍNDICES DE PAQUETES

La forma recomendada de usar paquetes en Tcl es invocar los comandos package require y package provide en los scripts, y usar el procedimiento pkg_mkIndex para crear archivos de índice de paquetes. Una vez que haya hecho esto, los paquetes se cargarán automáticamente en respuesta a los comandos package require. Consulte la documentación de pkg_mkIndex para obtener más detalles.

EJEMPLOS

Para indicar que un script de Tcl requiere los paquetes Tk y http, ponga esto al principio del script:

package require Tk
package require http

Para comprobar si el paquete Snack está disponible y cargarlo si lo está (a menudo útil para mejoras opcionales de programas donde la pérdida de la funcionalidad no es crítica), haga esto:

if {[catch {package require Snack}]} {
    # Se genera un error - paquete no encontrado.
    # Configurar una interfaz ficticia para solucionar la ausencia
} else {
    # Tenemos el paquete, configurar la aplicación para usarlo
}
