PACMAN(8) Manual de Pacman PACMAN(8)

NOMBRE

pacman - utilidad de gestión de paquetes

SINOPSIS

pacman <operación> [opciones] [objetivos]

DESCRIPCIÓN

Pacman es una utilidad de gestión de paquetes que rastrea los paquetes instalados en un sistema Linux. Cuenta con soporte para dependencias, grupos de paquetes, scripts de instalación y desinstalación, y la capacidad de sincronizar tu máquina local con un repositorio remoto para actualizar automáticamente los paquetes. Los paquetes de Pacman tienen un formato de tar comprimido.

Desde la versión 3.0.0, pacman ha sido el front-end de libalpm(3), la biblioteca de “Gestión de Paquetes de Arch Linux”. Esta biblioteca permite escribir front-ends alternativos (por ejemplo, un front-end gráfico).

Invocar pacman implica especificar una operación con cualquier opción y objetivo potencial para operar. Un objetivo es generalmente un nombre de paquete, un nombre de archivo, una URL o una cadena de búsqueda. Los objetivos se pueden proporcionar como argumentos de línea de comandos. Además, si stdin no proviene de una terminal y se pasa un guion simple (-) como argumento, los objetivos se leerán desde stdin.

OPERACIONES

-D, --database

Operar en la base de datos de paquetes. Esta operación permite modificar ciertos atributos de los paquetes instalados en la base de datos de pacman. También permite comprobar la consistencia interna de las bases de datos. Ver Opciones de Base de Datos más abajo.

-Q, --query

Consultar la base de datos de paquetes. Esta operación permite ver los paquetes instalados y sus archivos, así como metadatos sobre paquetes individuales (dependencias, conflictos, fecha de instalación, fecha de compilación, tamaño). Esto se puede ejecutar contra la base de datos de paquetes local o se puede usar en archivos de paquetes individuales. En el primer caso, si no se proporcionan nombres de paquetes en la línea de comandos, se consultarán todos los paquetes instalados. Además, se pueden aplicar varios filtros a la lista de paquetes. Ver Opciones de Consulta más abajo.

-R, --remove

Eliminar paquetes del sistema. También se pueden especificar grupos para ser eliminados, en cuyo caso se eliminará cada paquete de ese grupo. Se eliminarán los archivos pertenecientes al paquete especificado y se actualizará la base de datos. La mayoría de los archivos de configuración se guardarán con la extensión .pacsave a menos que se use la opción --nosave. Ver Opciones de Eliminación más abajo.

-S, --sync

Sincronizar paquetes. Los paquetes se instalan directamente desde los repositorios remotos, incluidas todas las dependencias necesarias para ejecutar los paquetes. Por ejemplo, pacman -S qt descargará e instalará qt y todos los paquetes de los que dependa. Si un nombre de paquete existe en más de un repositorio, el repositorio puede especificarse explícitamente para aclarar el paquete a instalar: pacman -S testing/qt. También puedes especificar requisitos de versión: pacman -S “bash>=3.2”. Se necesitan comillas, de lo contrario, el shell interpreta ">" como redirección a un archivo.

Además de los paquetes, se pueden especificar grupos. Por ejemplo, si gnome es un grupo de paquetes definido, entonces pacman -S gnome proporcionará una solicitud que te permitirá seleccionar qué paquetes instalar de una lista numerada. La selección de paquetes se especifica usando una lista de números de paquetes separados por espacios y/o comas. Se pueden seleccionar paquetes secuenciales especificando el primer y último número de paquete separados por un guion (-). Se excluyen paquetes prefijando un número o un rango de números con un circunflejo (^).

También se manejan los paquetes que proporcionan otros paquetes. Por ejemplo, pacman -S foo primero buscará un paquete foo. Si no se encuentra foo, se buscarán paquetes que proporcionen la misma funcionalidad que foo. Si se encuentra algún paquete, se instalará. Se proporciona una solicitud de selección si se encuentran varios paquetes que proporcionan foo.

También puedes usar pacman -Su para actualizar todos los paquetes que están desactualizados. Ver Opciones de Sincronización más abajo. Al actualizar, pacman realiza comparaciones de versiones para determinar qué paquetes necesitan actualizarse. Este comportamiento opera de la siguiente manera:

Alfanumérico:
  1.0a < 1.0b < 1.0beta < 1.0p < 1.0pre < 1.0rc < 1.0 < 1.0.a < 1.0.1
Numérico:
  1 < 1.0 < 1.1 < 1.1.1 < 1.2 < 2.0 < 3.0.0

Además, las cadenas de versión pueden tener un valor de epoch definido que anulará cualquier comparación de versión, a menos que los valores de epoch sean iguales. Esto se especifica en un formato epoch:version-rel. Por ejemplo, 2:1.0-1 es siempre mayor que 1:3.6-1.

-T, --deptest

Comprobar dependencias; esto es útil en scripts como makepkg para comprobar los paquetes instalados. Esta operación comprobará cada dependencia especificada y devolverá una lista de dependencias que no están actualmente satisfechas en el sistema. Esta operación no acepta otras opciones. Ejemplo de uso: pacman -T qt “bash>=3.2”.

-U, --upgrade

Actualizar o añadir paquete(s) al sistema e instalar las dependencias requeridas desde los repositorios de sincronización. Se puede especificar una URL o una ruta de archivo. Este es un proceso de “eliminar y añadir”. Ver Opciones de Actualización más abajo; también ver Manejo de Archivos de Configuración para una explicación sobre cómo pacman se ocupa de los archivos de configuración.

-F, --files

Consultar la base de datos de archivos. Esta operación permite buscar paquetes que poseen ciertos archivos o mostrar archivos que poseen ciertos paquetes. Solo se buscan los paquetes que forman parte de tus bases de datos de sincronización. Ver Opciones de Archivos más abajo.

-V, --version

Mostrar la versión y salir.

-h, --help

Mostrar la sintaxis de la operación dada. Si no se proporcionó ninguna operación, se muestra la sintaxis general.

OPCIONES

-b, --dbpath <ruta>

Especificar una ubicación alternativa de la base de datos (el valor predeterminado es /var/lib/pacman). Esto no debe usarse a menos que sepas lo que estás haciendo. NOTA: Si se especifica, es una ruta absoluta, y la ruta raíz no se antepone automáticamente.

-r, --root <ruta>

Especificar una raíz de instalación alternativa (el valor predeterminado es /). Esto no debe usarse como una forma de instalar software en /usr/local en lugar de /usr. NOTA: Si la ruta de la base de datos o el archivo de registro no se especifican en la línea de comandos o en pacman.conf(5), su ubicación predeterminada estará dentro de esta ruta raíz. NOTA: Esta opción no es adecuada para realizar operaciones en un sistema invitado montado. Usa --sysroot en su lugar.

-v, --verbose

Mostrar rutas como la Raíz, Archivo de Configuración, Ruta de Base de Datos, Directorios de Caché, etc.

--arch <arch>

Especificar una arquitectura alternativa.

--cachedir <directorio>

Especificar una ubicación alternativa para la caché de paquetes (el valor predeterminado es /var/cache/pacman/pkg). Se pueden especificar varios directorios de caché, y se prueban en el orden en que se pasan a pacman. NOTA: Esta es una ruta absoluta, y la ruta raíz no se antepone automáticamente.

--color <cuándo>

Especificar cuándo habilitar los colores. Las opciones válidas son always (siempre), never (nunca), o auto (automático). always fuerza la activación de colores; never fuerza la desactivación de colores; y auto solo habilita automáticamente los colores cuando se genera salida en una tty.

--config <archivo>

Especificar un archivo de configuración alternativo.

--debug

Mostrar mensajes de depuración. Al informar de errores, se recomienda usar esta opción.

--gpgdir <directorio>

Especificar un directorio de archivos utilizados por GnuPG para verificar las firmas de los paquetes (el valor predeterminado es /etc/pacman.d/gnupg). Este directorio debe contener dos archivos: pubring.gpg y trustdb.gpg. pubring.gpg contiene las claves públicas de todos los empaquetadores. trustdb.gpg contiene una base de datos de confianza, que especifica que las claves son auténticas y confiables. NOTA: Esta es una ruta absoluta, y la ruta raíz no se antepone automáticamente.

--hookdir <directorio>

Especificar un directorio alternativo que contiene archivos hook (el valor predeterminado es /etc/pacman.d/hooks). Se pueden especificar varios directorios de hooks, y los hooks en directorios posteriores tienen precedencia sobre los hooks

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

en directorios anteriores. NOTA: esta es una ruta absoluta, y la ruta raíz no se antepone automáticamente.

--logfile <archivo>

Especifica un archivo de registro alternativo. Esta es una ruta absoluta, independientemente de la configuración de la raíz de instalación.

--noconfirm

Omite todos los mensajes de “¿Está seguro?”. No es buena idea hacerlo a menos que quiera ejecutar pacman desde un script.

--confirm

Cancela los efectos de un --noconfirm anterior.

--disable-download-timeout

Deshabilita los valores predeterminados para el límite de baja velocidad y el tiempo de espera en las descargas. Úselo si tiene problemas para descargar archivos con un proxy y/o una puerta de enlace de seguridad.

--sysroot <dir>

Especifica una raíz de sistema alternativa. Esta ruta se antepondrá a todos los demás directorios de configuración y a cualquier servidor de repositorio que comience con file://. Las rutas o URL que se pasen como destino no se modificarán. Esto permite operar correctamente en sistemas invitados montados.

--disable-sandbox

Deshabilita el sandbox predeterminado aplicado al proceso de descarga de archivos en sistemas Linux. Útil si experimenta fallos relacionados con landlock al descargar archivos cuando ejecuta un kernel de Linux que no admite esta función.

OPCIONES DE TRANSACCIÓN (APLICAR A -S, -R Y -U)

-d, --nodeps

Omite las comprobaciones de versión de dependencias. Los nombres de los paquetes todavía se verifican. Normalmente, pacman siempre comprobará los campos de dependencias de un paquete para asegurarse de que todas las dependencias están instaladas y de que no hay conflictos de paquetes en el sistema. Especifique esta opción dos veces para omitir todas las comprobaciones de dependencias.

--assume-installed <paquete=versión>

Agrega un paquete virtual "paquete" con la versión "versión" a la transacción para satisfacer las dependencias. Esto permite deshabilitar las comprobaciones de dependencias específicas sin afectar a todas las comprobaciones de dependencias. Para deshabilitar todas las comprobaciones de dependencias, consulte la opción --nodeps.

--dbonly

Agrega/elimina solo la entrada de la base de datos, dejando todos los archivos en su lugar.

--noprogressbar

No muestre una barra de progreso al descargar archivos. Esto puede ser útil para scripts que llaman a pacman y capturan la salida.

--noscriptlet

Si existe un scriptlet de instalación, no lo ejecute. No lo use a menos que sepa lo que está haciendo.

-p, --print

Solo imprime los objetivos en lugar de realizar la operación real (sincronizar, eliminar o actualizar). Use --print-format para especificar cómo se muestran los objetivos. La cadena de formato predeterminada es "%l", que muestra las URL con -S, los nombres de archivo con -U y el nombre_paquete-versión_paquete con -R.

--print-format <formato>

Especifica un formato similar a printf para controlar la salida de la operación --print. Los atributos posibles son: "%a" para arch, "%b" para fecha de compilación, "%d" para descripción, "%e" para base del paquete, "%f" para nombre de archivo, "%g" para firma PGP codificada en base64, "%h" para sha256sum, "%m" para md5sum, "%n" para nombre_paquete, "%p" para empacador, "%v" para versión_paquete, "%l" para ubicación, "%r" para repositorio, "%s" para tamaño, "%C" para dependencias de comprobación, "%D" para dependencias, "%G" para grupos, "%H" para conflictos, "%L" para licencias, "%M" para dependencias de compilación, "%O" para dependencias opcionales, "%P" para proporciona y "%R" para reemplaza. Implica --print.

OPCIONES DE ACTUALIZACIÓN (APLICAR A -S Y -U)

-w, --downloadonly

Recupera todos los paquetes del servidor, pero no instala/actualiza nada.

--asdeps

Instala paquetes no explícitamente; en otras palabras, simula su razón de instalación como si se hubieran instalado como dependencia. Esto es útil para makepkg y otras herramientas de compilación a partir de fuentes que necesitan instalar dependencias antes de compilar el paquete.

--asexplicit

Instala paquetes explícitamente; en otras palabras, simula su razón de instalación como si se hubieran instalado explícitamente. Esto es útil si desea marcar una dependencia como instalada explícitamente para que no sea eliminada por la operación de eliminación --recursive.

--ignore <paquete>

Indica a pacman que ignore las actualizaciones de un paquete incluso si hay una disponible. Se pueden especificar varios paquetes separándolos con una coma.

--ignoregroup <grupo>

Indica a pacman que ignore las actualizaciones de todos los paquetes del grupo, incluso si hay una disponible. Se pueden especificar varios grupos separándolos con una coma.

--needed

No reinstale los objetivos que ya están actualizados.

--overwrite <glob>

Omite las comprobaciones de conflictos de archivos y sobrescribe los archivos en conflicto. Si el paquete que se va a instalar contiene archivos que ya están instalados y coinciden con glob, esta opción hará que todos esos archivos se sobrescriban. El uso de --overwrite no permitirá sobrescribir un directorio con un archivo ni instalar paquetes con archivos y directorios en conflicto. Se pueden especificar varios patrones separándolos con una coma. Se puede especificar varias veces. Los patrones se pueden negar, de modo que los archivos que coincidan con ellos no se sobrescriban, anteponiéndoles un signo de exclamación. Las coincidencias posteriores anularán las anteriores. Se debe escapar un signo de exclamación literal o una barra invertida inicial.

OPCIONES DE CONSULTA (APLICAR A -Q)

-c, --changelog

Ver el ChangeLog de un paquete si existe.

-d, --deps

Restringe o filtra la salida a los paquetes instalados como dependencias. Esta opción se puede combinar con -t para listar los huérfanos reales: paquetes que se instalaron como dependencias pero que ya no son requeridos por ningún paquete instalado.

-e, --explicit

Restringe o filtra la salida a los paquetes instalados explícitamente. Esta opción se puede combinar con -t para listar los paquetes instalados explícitamente que no son requeridos por ningún otro paquete.

-g, --groups

Muestra todos los paquetes que son miembros de un grupo con nombre. Si no se especifica un nombre, lista todos los paquetes agrupados.

-i, --info

Muestra información sobre un paquete determinado. La opción -p se puede utilizar si se consulta un archivo de paquete en lugar de la base de datos local. Pasar dos indicadores --info o -i también mostrará la lista de archivos de copia de seguridad y sus estados de modificación.

-k, --check

Verifica que todos los archivos propiedad de los paquetes dados estén presentes en el sistema. Si no se especifican paquetes o no se proporcionan indicadores de filtro, verifica todos los paquetes instalados. Especificar esta opción dos veces realizará una verificación de archivos más detallada (incluyendo permisos, tamaños de archivo y tiempos de modificación) para los paquetes que contengan el archivo mtree necesario.

-l, --list

Lista todos los archivos propiedad de un paquete determinado. Se pueden especificar varios paquetes en la línea de comandos.

-m, --foreign

Restringe o filtra la salida a los paquetes que no se encontraron en las bases de datos de sincronización. Normalmente, estos son paquetes que se descargaron manualmente y se instalaron con --upgrade.

-n, --native

Restringe o filtra la salida a los paquetes que se encuentran en las bases de datos de sincronización. Este es el filtro inverso de --foreign.

-o, --owns <archivo>

Busca paquetes que posean el/los archivo(s) especificado(s). La ruta puede ser relativa o absoluta, y se puede especificar uno o más archivos.

-p, --file

Indica que el paquete proporcionado en la línea de comandos es un archivo y no una entrada en la base de datos. El archivo se descomprimirá y se consultará. Esto es útil en combinación con --info y --list.

-q, --quiet

Muestra menos información para ciertas operaciones de consulta. Esto es útil cuando la salida de pacman se procesa en un script. La búsqueda solo mostrará nombres de paquetes y no información de versión, grupo y descripción; owns solo mostrará nombres de paquetes en lugar de mensajes de "el archivo es propiedad de pkg"; group solo mostrará nombres de paquetes y omitirá nombres de grupo; list solo mostrará archivos y omitirá nombres de paquetes; check solo mostrará pares de nombres de paquetes y archivos faltantes; una consulta simple solo mostrará nombres de paquetes en lugar de nombres y versiones.

-s, --search <expresion_regular>

Busca en cada paquete instalado localmente nombres o descripciones que coincidan con la expresión regular. Al incluir varios términos de búsqueda, solo se devuelven los paquetes cuyas descripciones coincidan con TODOS esos términos.

-t, --unrequired

Restringe o filtra la salida para mostrar solo los paquetes que no son requeridos ni opcionalmente requeridos por ningún paquete instalado actualmente. Especifique esta opción dos veces para incluir paquetes que son requeridos opcionalmente, pero no directamente, por otro paquete.

-u, --upgrades

Restringe o filtra la salida a los paquetes que están desactualizados en el sistema local. Solo se utilizan las versiones de los paquetes para encontrar paquetes desactualizados; los reemplazos no se verifican aquí. Esta opción funciona mejor si la base de datos de sincronización se actualiza usando -Sy.

OPCIONES DE ELIMINACIÓN (APLICAR A -R)

-c, --cascade

Elimina todos los paquetes objetivo, así como todos los paquetes que dependen de uno o más paquetes objetivo. Esta operación es recursiva y debe usarse con cuidado, ya que puede eliminar muchos paquetes potencialmente necesarios.

-n, --nosave

Indica a pacman que ignore las designaciones de copia de seguridad de archivos. Normalmente, cuando se elimina un archivo del sistema, se consulta la base de datos para ver si el archivo debe renombrarse con la extensión .pacsave.

-s, --recursive

Elimina cada objetivo especificado, incluidas todas sus dependencias, siempre que (A) no sean requeridas por otros paquetes; y (B) no hayan sido instaladas explícitamente por el usuario.

OPCIONES DE INSTALACIÓN

-c, --cascade

Esta operación es recursiva y análoga a una operación --sync inversa, y ayuda a mantener un sistema limpio sin huérfanos. Si deseas omitir la condición (B), pasa esta opción dos veces.

-u, --unneeded

Elimina los objetivos que no son requeridos por ningún otro paquete. Esto es principalmente útil al eliminar un grupo sin usar la opción -c, para evitar romper dependencias.

OPCIONES DE SYNC (APLICAN A -S)

-c, --clean

Elimina paquetes que ya no están instalados de la caché, así como las bases de datos de sincronización no utilizadas actualmente para liberar espacio en disco. Cuando pacman descarga paquetes, los guarda en un directorio de caché. Además, se guardan bases de datos por cada DB de sincronización que descargas y no se eliminan incluso si se eliminan del archivo de configuración pacman.conf(5). Usa un interruptor --clean para eliminar solo los paquetes que ya no están instalados; usa dos para eliminar todos los archivos de la caché. En ambos casos, tendrás una opción de sí o no para eliminar paquetes y/o bases de datos descargadas no utilizadas.

Si usas una caché compartida en red, consulta la opción CleanMethod en pacman.conf(5).

-g, --groups

Muestra todos los miembros de cada grupo de paquetes especificado. Si no se proporcionan nombres de grupo, se enumerarán todos los grupos; pasa la bandera dos veces para ver todos los grupos y sus miembros.

-i, --info

Muestra información sobre un paquete de base de datos de sincronización dado. Pasar dos banderas --info o -i también mostrará aquellos paquetes en todos los repositorios que dependen de este paquete.

-l, --list

Enumera todos los paquetes en los repositorios especificados. Se pueden especificar múltiples repositorios en la línea de comandos.

-q, --quiet

Muestra menos información para ciertas operaciones de sincronización. Esto es útil cuando la salida de pacman se procesa en un script. La búsqueda solo mostrará nombres de paquetes y no información de repositorio, versión, grupo y descripción; la lista solo mostrará nombres de paquetes y omitirá bases de datos y versiones; el grupo solo mostrará nombres de paquetes y omitirá nombres de grupos.

-s, --search <expresión regular>

Esto buscará en cada paquete en las bases de datos de sincronización nombres o descripciones que coincidan con la expresión regular. Cuando incluyas múltiples términos de búsqueda, solo se devolverán los paquetes con descripciones que coincidan con TODOS esos términos.

-u, --sysupgrade

Actualiza todos los paquetes que están desactualizados. Cada paquete instalado actualmente será examinado y actualizado si existe un paquete más nuevo. Se presentará un informe de todos los paquetes a actualizar, y la operación no procederá sin confirmación del usuario. Las dependencias se resuelven automáticamente a este nivel y se instalarán/actualizarán si es necesario.

Pasa esta opción dos veces para habilitar la degradación de paquetes; en este caso, pacman seleccionará paquetes de sincronización cuyas versiones no coincidan con las versiones locales. Esto puede ser útil cuando el usuario cambia de un repositorio de pruebas a uno estable.

También se pueden especificar objetivos adicionales manualmente, de modo que -Su foo realice una actualización del sistema e instale/actualice el paquete "foo" en la misma operación.

-y, --refresh

Descarga una copia fresca de las bases de datos maestras de paquetes (repo.db) de los servidores definidos en pacman.conf(5). Esto se debe usar típicamente cada vez que uses --sysupgrade o -u. Pasar dos banderas --refresh o -y forzará una actualización de todas las bases de datos de paquetes, incluso si parecen estar actualizadas.

OPCIONES DE BASE DE DATOS (APLICAN A -D)

--asdeps <paquete>

Marca un paquete como no instalado explícitamente; en otras palabras, establece su razón de instalación como instalado como dependencia.

--asexplicit <paquete>

Marca un paquete como instalado explícitamente; en otras palabras, establece su razón de instalación como instalado explícitamente. Esto es útil si deseas mantener un paquete instalado incluso cuando fue instalado inicialmente como dependencia de otro paquete.

-k, --check

Comprueba que la base de datos local de paquetes sea internamente consistente. Esto verificará que todos los archivos requeridos estén presentes y que los paquetes instalados tengan las dependencias requeridas, no entren en conflicto y que múltiples paquetes no posean el mismo archivo. Especificar esta opción dos veces realizará una comprobación en las bases de datos de sincronización para asegurar que todas las dependencias especificadas estén disponibles.

-q, --quiet

Suprime mensajes al completar con éxito las operaciones de base de datos.

OPCIONES DE ARCHIVO (APLICAN A -F)

-y, --refresh

Descarga bases de datos de archivos de paquetes frescos (repo.files) del servidor. Usa dos veces para forzar una actualización incluso si las bases de datos están actualizadas.

-l, --list

Enumera los archivos propiedad del paquete consultado.

-x, --regex

Interpreta cada consulta como una expresión regular.

-q, --quiet

Muestra menos información para ciertas operaciones de archivo. Esto es útil cuando la salida de pacman se procesa en un script, sin embargo, podrías querer usar --machinereadable en su lugar.

--machinereadable

Imprime cada coincidencia en un formato de salida legible por máquina. El formato es repositorio\0nombre_paquete\0version_paquete\0ruta\n, donde \0 es el carácter nulo y \n es un salto de línea.

MANEJO DE ARCHIVOS DE CONFIGURACIÓN

Pacman utiliza la misma lógica que rpm para determinar la acción contra los archivos que están designados para ser respaldados. Durante una actualización, se utilizan tres hashes MD5 para cada archivo de respaldo para determinar la acción requerida: uno para el archivo original instalado, uno para el nuevo archivo que está a punto de ser instalado y uno para el archivo real existente en el sistema de archivos. Después de comparar estos tres hashes, se pueden obtener los siguientes escenarios:

original=X, current=X, new=X

Los tres archivos son iguales, por lo que las sobrescrituras no son un problema. Instala el nuevo archivo.

original=X, current=X, new=Y

El archivo actual es el mismo que el original, pero el nuevo es diferente. Dado que el usuario nunca modificó el archivo, y el nuevo puede contener mejoras o correcciones de errores, instala el nuevo archivo.

original=X, current=Y, new=X

Ambas versiones del paquete contienen el mismo archivo, pero el que está en el sistema de archivos ha sido modificado. Deja el archivo actual en su lugar.

original=X, current=Y, new=Y

El nuevo archivo es idéntico al archivo actual. Instala el nuevo archivo.

original=X, current=Y, new=Z

Los tres archivos son diferentes, así que instala el nuevo archivo con la extensión .pacnew y advierte al usuario. El usuario deberá entonces fusionar manualmente cualquier cambio necesario en el archivo original.

original=NULL, current=Y, new=Z

El paquete no se había instalado previamente y el archivo ya existe en el sistema de archivos. Instala el nuevo archivo con la extensión .pacnew y advierte al usuario. El usuario deberá entonces fusionar manualmente cualquier cambio necesario en el archivo original.

EJEMPLOS

pacman -Ss ne.hack

Busca la expresión regular "ne.hack" en la base de datos de paquetes.

pacman -S gpm

Descarga e instala gpm, incluyendo las dependencias.

pacman -U /home/user/ceofhack-0.6-1-x86_64.pkg.tar.gz

Instala el paquete ceofhack-0.6-1 desde un archivo local.

pacman -Syu

Actualiza la lista de paquetes y luego actualiza todos los paquetes.

pacman -Syu gpm

Actualiza la lista de paquetes, actualiza todos los paquetes y luego instala gpm si aún no estaba instalado.
