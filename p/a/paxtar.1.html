PAXTAR(1) Manual de Comandos Generales PAXTAR(1)

NOMBRE

paxtar — archivador de cintas

SINOPSIS

paxtar {crtux}[014578abefHhJjLmOoPpqsvwXZz] [factor-de-bloqueo | archivo | cadena-reemplazo] [-C directorio] [-I archivo] [archivo ...]

paxtar {-crtux} [-014578aeHhJjLmOoPpqvwXZz] [-b factor-de-bloqueo] [-C directorio] [-D opciones-de-formato] [-f archivo] [-I archivo] [-M bandera] [-s cadena-reemplazo] [archivo ...]

DESCRIPCIÓN

El comando paxtar crea, añade archivos a, o extrae archivos de un archivo en formato “tar” (estrictamente hablando, ustar). Un archivo tar a menudo se almacena en una cinta magnética, pero puede almacenarse igualmente bien en un disquete, CD-ROM, o en un archivo de disco normal.

En la primera forma (legada), todas las banderas de opción excepto -C y -I deben estar contenidas en el primer argumento de paxtar y no deben ir precedidas por un guion (‘-’). Los argumentos de opción, si existen, se procesan como argumentos subsiguientes a paxtar y se procesan en el orden en que sus banderas de opción correspondientes se hayan presentado en la línea de comandos.

En la segunda forma y preferida, las banderas de opción pueden darse en cualquier orden e inmediatamente seguidas por sus valores de argumento de opción correspondientes.

Una de las siguientes banderas debe estar presente:

-c
Crea un archivo nuevo, o sobrescribe un archivo existente, añadiendo los archivos especificados al mismo.
-r
Añade los nuevos archivos nombrados a un archivo existente. Tenga en cuenta que esto solo funcionará en medios en los que se pueda sobrescribir una marca de fin de archivo.
-t
Lista el contenido del archivo. Si se nombran archivos en la línea de comandos, solo se listarán esos archivos. Los argumentos de archivo pueden especificarse como patrones glob (ver glob(7) para más información), en cuyo caso paxtar listará todos los miembros del archivo que coincidan con cada patrón.
-u
Alias para -r.
-x
Extrae archivos del archivo. Si se nombran archivos en la línea de comandos, solo se extraerán esos archivos del archivo. Los argumentos de archivo pueden especificarse como patrones glob (ver glob(7) para más información), en cuyo caso paxtar extraerá todos los miembros del archivo que coincidan con cada patrón.

Si más de una copia de un archivo existe en el archivo, copias posteriores sobrescribirán las anteriores durante la extracción. El modo de archivo y la hora de modificación se conservan si es posible. El modo de archivo está sujeto a modificación por umask(2).

Además de las banderas mencionadas anteriormente, se pueden usar cualquiera de las siguientes banderas:

-a
Adivina la utilidad de compresión basándose en el nombre del archivo. La incapacidad de adivinar resultará en no usar ninguna compresión silenciosamente. Esta opción solo existe para compatibilidad parcial con GNU tar; se recomienda encarecidamente archivar a stdout y canalizar a una utilidad de compresión externa con los argumentos apropiados en su lugar:
tar -cf - foo | xz -2e >foo.txz
-b factor-de-bloqueo
Establece el factor de bloqueo a utilizar para el archivo. paxtar utiliza bloques de 512 bytes. El valor por defecto es 20, el máximo es 126. Los archivos con un factor de bloqueo mayor que 63 violan el estándar POSIX y no serán portátiles a todos los sistemas.
-C directorio
Este es un argumento posicional que establece el directorio de trabajo para los siguientes archivos. Al extraer, los archivos se extraerán en el directorio especificado; al crear, los archivos especificados se buscarán desde el directorio.
-D opciones-de-formato
Especifica el formato del archivo y las opciones de formato, separadas por coma. paxtar actualmente soporta los siguientes formatos y opciones:
ar
El formato de biblioteca del Archivador Unix. Este formato coincide con los repositorios APT y la especificación de ar(1) de BSD, no con GNU binutils (que sin embargo pueden leerlos) ni con sistemas SYSV. Ver ar(5) en algunos sistemas operativos para más información.
bcpio
El formato cpio binario antiguo. El tamaño de bloque por defecto para este formato es de 5120 bytes. Este formato no es muy portable y no debería usarse cuando hay otros formatos disponibles. La información de inodo y dispositivo de un archivo (utilizada para detectar enlaces duros de archivo por este formato), que puede ser truncada por este formato, es detectada por paxtar y reparada.
cpio
El formato de intercambio cpio extendido especificado en el estándar IEEE Std 1003.2 (“POSIX.2”). El tamaño de bloque por defecto para este formato es de 5120 bytes. La información de inodo y dispositivo de un archivo (utilizada para detectar enlaces duros de archivo por este formato), que puede ser truncada por este formato, es detectada por paxtar y reparada.
sv4cpio
El cpio de System V release 4. El tamaño de bloque por defecto para este formato es de 5120 bytes. La información de inodo y dispositivo de un archivo (utilizada para detectar enlaces duros de archivo por este formato), que puede ser truncada por este formato, es detectada por paxtar y reparada.
sv4crc
El cpio de System V release 4 con sumas de verificación CRC de archivo. El tamaño de bloque por defecto para este formato es de 5120 bytes. La información de inodo y dispositivo de un archivo (utilizada para detectar enlaces duros de archivo por este formato), que puede ser truncada por este formato, es detectada por paxtar y reparada.
tar
El formato tar antiguo de BSD como se encuentra en 4.3BSD. El tamaño de bloque por defecto para este formato es de 10240 bytes. Los nombres de ruta almacenados por este formato deben tener 100 caracteres o menos de longitud. Solo se archivarán archivos regulares, enlaces duros, enlaces simbólicos y directorios (otros tipos de sistema de archivos no son compatibles).

Para compatibilidad con versiones anteriores incluso de formatos tar más antiguos, la opción write_opt=nodir puede usarse al escribir un archivo para omitir el almacenamiento de directorios.

ustar
El formato de intercambio tar extendido especificado en el estándar IEEE Std 1003.2 (“POSIX.2”). El tamaño de bloque por defecto para este formato es de 10240 bytes. Los nombres de archivo almacenados con este formato deben tener 100 caracteres o menos; la ruta completa no debe exceder los 256 caracteres.

paxtar detectará e informará cualquier archivo que no pueda almacenar o extraer debido a las restricciones de un formato de archivo específico. Los formatos de archivo individuales pueden imponer restricciones adicionales a su uso. Las restricciones típicas de los formatos de archivo incluyen (entre otras): longitud del nombre de archivo, tamaño del archivo, longitud del nombre de enlace y el tipo de archivo.

-e
Detenerse después del primer error.
-f archivo
Nombre del archivo donde se almacena el archivo. Por defecto es /dev/rst0. Si se establece a guion (‘-’) se utiliza la salida estándar. Véase también la variable de entorno TAPE.
-H
Seguir solo los enlaces simbólicos dados en la línea de comandos.
-h
Seguir los enlaces simbólicos como si fueran archivos o directorios normales. En modo de extracción, esto significa que una entrada de directorio en el archivo no sobrescribirá un enlace simbólico existente, sino lo que el enlace apunta finalmente.
-I archivo
Este es un argumento posicional que lee los nombres de los archivos a archivar o extraer del archivo dado, uno por línea.
-J
Utilizar la utilidad xz para comprimir el archivo.
-j
Utilizar la utilidad bzip2 para comprimir el archivo.
-L
Sinónimo de la opción -h.
-M flag
Configurar el normalizador de archivos. flag es un valor numérico compatible con strtonum(3) que se almacena directamente en la palabra de flags, o uno de los siguientes valores, opcionalmente prefijado con “no-” para desactivarlos:
inodes
0x0001: Serializar inodos, información de dispositivo cero.
(cpio, sv4cpio, sv4crc)
links
0x0002: Almacenar el contenido de los enlaces duros solo una vez.
(cpio, sv4cpio, sv4crc)
mtime
0x0004: Poner a cero la hora de modificación del archivo.
(ar, cpio, sv4cpio, sv4crc, ustar)
uidgid
0x0008: Establecer propietario a 0:0 (root:wheel).
(ar, cpio, sv4cpio, sv4crc, ustar)
verb
0x0010: Depurar esta opción.
debug
0x0020: Depurar el almacenamiento de la cabecera del archivo.
lncp
0x0040: Extraer enlaces duros por copia si el enlace falla.
numid
0x0080: Usar solo valores numéricos de uid y gid.
(ustar)
gslash
0x0100: Añadir una barra después de los nombres de directorio.
(ustar)
set
0x0003: Mantener intacta la propiedad y la hora de modificación.
dist
0x008B: Limpiar todo excepto la hora de modificación.
norm
0x008F: Limpiar todo.
root
0x0089: Limpiar información de propietario y dispositivo.

Al crear un archivo y listar la salida de forma detallada, estas operaciones de normalización no se reflejan en la salida, ya que se realizan solo después de que la salida se haya mostrado.

Esta opción solo está implementada para las rutinas de escritura de los formatos de archivo ar, cpio, sv4cpio, sv4crc y ustar.

-m
No preservar la hora de modificación.
-O
Si se lee, extraer archivos a la salida estándar.
Si se escribe, escribir archivos de estilo antiguo (no POSIX).
-o
Si se escribe, escribir archivos de estilo antiguo (no POSIX).
No escribir información de directorio que el estilo anterior (V7) de tar no puede decodificar. Igual que -D tar,write_opt=nodir.
-P
Por razones de seguridad, paxtar omite los nombres de ruta que contienen componentes punto-punto (“..”) y elimina las barras iniciales (‘/’) de los nombres de ruta por defecto; esta opción deshabilita ese comportamiento.
-p
Preservar el ID de usuario y grupo, así como el modo de archivo, independientemente de la umask(2) actual. Los bits setuid y setgid solo se preservan si el ID de usuario y grupo pudieron preservarse. Solo tiene sentido junto con la bandera -x.
-q
Seleccionar el primer miembro del archivo que coincida con cada operando archivo. No se coincide con más de un miembro de archivo por cada archivo. Cuando se coinciden miembros de tipo directorio, también se coincide con la jerarquía de archivos enraizada en ese directorio.
-s replstr
Modificar los nombres de los miembros del archivo de acuerdo con la expresión de sustitución replstr, utilizando la sintaxis de las expresiones regulares de la utilidad ed(1). Se pueden proporcionar argumentos archivo para restringir la lista de miembros del archivo a los especificados.

El formato de estas expresiones regulares es

/viejo/nuevo/[gp]

Como en ed(1), viejo es una expresión regular básica (ver re_format(7)) y nuevo puede contener una ampersand (‘&’), referencias inversas ‘\n’ (donde n es un dígito) o coincidencias de subexpresión. La cadena viejo también puede contener caracteres de nueva línea. Cualquier carácter no nulo puede usarse como delimitador (‘/’ se muestra aquí). Se pueden especificar múltiples expresiones -s. Las expresiones se aplican en el orden en que se especifican en la línea de comandos, terminando con la primera sustitución exitosa.

La g opcional al final continúa aplicando la expresión de sustitución a la subcadena del nombre de ruta, que comienza con el primer carácter después del final de la última sustitución exitosa. La primera sustitución fallida detiene la operación de la opción g. La p opcional al final provocará que el resultado final de una sustitución exitosa se escriba en la salida estándar de error en el siguiente formato:

nombre-ruta-original >> nombre-ruta-nuevo

Los nombres de archivo o miembros del archivo que se sustituyen por la cadena vacía no se seleccionan y se omiten.

-v
Modo de operación detallado. Si se especifica -v múltiples veces o si también se especifica la opción -t, paxtar utilizará un formato largo para listar archivos, similar al -l de ls(1).
-w
Renombrar archivos interactivamente. Esta opción hace que paxtar pregunte al usuario el nombre de archivo a utilizar al almacenar o extraer archivos en un archivo.
-X
No cruzar puntos de montaje en el sistema de archivos.
-Z
Utilizar la utilidad compress(1) para comprimir el archivo.
-z
Utilizar la utilidad gzip(1) para comprimir el archivo.

Las opciones [-014578] se pueden usar para seleccionar uno de los dispositivos de copia de seguridad compilados, /dev/rstN.

ENTORNO

TMPDIR
Ruta donde almacenar archivos temporales.
TAPE
Dispositivo de cinta por defecto a utilizar en lugar de /dev/rst0. Si se establece a guion (‘-’) se utiliza la salida estándar.

ARCHIVOS

/dev/rst0
nombre de archivo por defecto

ESTADO DE SALIDA

La utilidad paxtar sale con uno de los siguientes valores:

0
Todos los archivos se procesaron correctamente.
1
Ocurrió un error.

EJEMPLOS

Crear un archivo en la unidad de cinta por defecto, que contenga los archivos llamados bonvole y sekve:

$ paxtar c bonvole sekve

paxtar(1) - Arch Linux man pages

NAME

paxtar ― create and extract tar archives

SYNOPSIS

paxtar -c[bdfimnqrSvwW] [-k files] [-K files] [-O owner] [-G group] [-p[a|o]] [-C directory] tarfile [file…]

paxtar -r[bdfimnqrSvwW] [-k files] [-K files] [-O owner] [-G group] [-p[a|o]] [-C directory] tarfile file…

paxtar -t[bcdeW]`filetarfile [file…]

paxtar -u[bdfimnqrSvwW] [-k files] [-K files] [-O owner] [-G group] [-p[a|o]] [-C directory] tarfile [file…]

paxtar -x[bdfimnqrSvwW] [-k files] [-K files] [-O owner] [-G group] [-p[a|o]] [-C directory] tarfile [file…]

paxtar -Z[bdfimnqrSvwW] [-k files] [-K files] [-O owner] [-G group] [-p[a|o]] [-C directory] tarfile [file…]

DESCRIPTION

paxtar is a fully documented and compliant implementation of the tar format as described in POSIX 1003.1-2017.

The paxtar utility is used to create, list, and extract files from tar archives. tar archives are tape archives, a common format for storing and distributing groups of files. The original use of tar was for storing files on magnetic tape, but it is now commonly used to store files on disk as well.

The primary functions of paxtar are:

  • Create: create a new archive.
  • List: list the contents of an archive.
  • Extract: extract files from an archive.

The options to paxtar are grouped into functional areas:

Operation:

-c

Create an archive.

-r

Append to an archive. This is only possible for tar archives on disk files.

-t

List the contents of an archive. If -x is specified, extract files from the archive.

-u

Update an archive. This is only possible for tar archives on disk files.

-x

Extract files from an archive.

-Z

Extract files compressed with compress(1) from an archive.

Archive:

-f

Specify the archive file name.

-W

Write to the archive file.

Output control:

-v

Verbosely list files processed.

Miscellaneous:

-b

Use block size n (512 bytes).

-d

Delete files after adding them to the archive.

-i

Ignore directory checksum errors.

-m

Do not extract file modification times.

-n

Extract only the first encountered file. This option is only useful when extracting archives created using the pax format.

-p

Preserve file attributes. When extracting, preserve owner, group, and permissions. When creating, attempt to preserve owner, group, and permissions.

-q

Quiet mode. Do not print error messages.

-S

Process archives in a stream-oriented way.

-w

Prompt for confirmation before each operation.

-W

Check archive checksums.

-k

Extract only files whose names are listed in files.

-K

Extract files whose names are listed in the archive specified by files.

-O

Extract only files owned by user owner.

-G

Extract only files owned by group group.

-C

Change to directory directory before performing any operations.

The operations can be combined. For example, -cvf creates an archive verbosely and specifies the archive file name.

ENVIRONMENT

The following environment variables affect paxtar:

TMPDIR
Location for temporary files.

FILES

paxtar may create temporary files in /tmp or in the directory specified by TMPDIR.

EXIT STATUS

paxtar exits with one of the following values:

0
Successful completion.
1
An error occurred during processing.
2
An error occurred during archive creation or extraction.
3
A signal terminated processing.

EXAMPLES

Create an archive, called foriru.tar.gz, containing the file bonvole:

$ paxtar zcf foriru.tar.gz bonvole sekve

Verbosely create an archive, called backup.tar.gz, of all files matching the shell glob(7) function *.c:

$ paxtar zcvf backup.tar.gz *.c

Verbosely list, but do not extract, all files ending in .jpeg from a compressed archive named backup.tar.gz. Note that the glob pattern has been quoted to avoid expansion by the shell:

$ paxtar tvzf backup.tar.gz '*.jpeg'

For more detailed examples, see pax(1).

DIAGNOSTICS

Whenever paxtar cannot create a file or a link when extracting an archive or cannot find a file while writing an archive, or cannot preserve the user ID, group ID, file mode, or access and modification times when the -p option is specified, a diagnostic message is written to standard error and a non-zero exit value will be returned, but processing will continue. In the case where paxtar cannot create a link to a file, unless -M lncp is given, paxtar will not create a second copy of the file.

If the extraction of a file from an archive is prematurely terminated by a signal or error, paxtar may have only partially extracted the file the user wanted. Additionally, the file modes of extracted files and directories may have incorrect file bits, and the modification and access times may be wrong.

If the creation of an archive is prematurely terminated by a signal or error, paxtar may have only partially created the archive, which may violate the specific archive format specification.

CAVEATS

The flags -aDJjLMo are not portable to other implementations of tar where they may have a different meaning or not exist at all.

This implementation may have support for other non-standard options that are undocumented because removal-inducing deprecation was issued.

BUGS

The pax file format is not yet supported.
