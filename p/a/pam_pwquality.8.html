NOMBRE

pam_pwquality - Módulo PAM para realizar comprobaciones de calidad de contraseñas

SINOPSIS

pam_pwquality.so [...]

DESCRIPCIÓN

Este módulo puede ser enchufado en la pila de contraseñas de un servicio dado para proporcionar algunas comprobaciones de fortaleza de enchufables para contraseñas. El código se basó originalmente en el módulo pam_cracklib y el módulo es retrocompatible con sus opciones.

La acción de este módulo es solicitar al usuario una contraseña y comprobar su fortaleza contra un diccionario del sistema y un conjunto de reglas para identificar elecciones débiles.

La primera acción es solicitar una única contraseña, comprobar su fortaleza y luego, si se considera fuerte, solicitar la contraseña por segunda vez (para verificar que se escribió correctamente la primera vez). Con todo en orden, la contraseña se pasa a los siguientes módulos para ser instalada como el nuevo token de autenticación.

Las comprobaciones de fortaleza son:

Palíndromo
¿Es la nueva contraseña un palíndromo?
Solo cambio de mayúsculas/minúsculas
¿Es la nueva contraseña la misma que la anterior solo con un cambio de mayúsculas/minúsculas?
Similar
¿Es la nueva contraseña demasiado parecida a la antigua? Esto está controlado principalmente por un argumento, difok, que es el número de cambios de caracteres (inserciones, eliminaciones o reemplazos) entre la contraseña antigua y la nueva que son suficientes para aceptar la nueva contraseña.
Simple
¿Es la nueva contraseña demasiado corta? Esto está controlado por 6 argumentos: minlen, maxclassrepeat, dcredit, ucredit, lcredit y ocredit. Consulte la sección sobre los argumentos para obtener detalles sobre cómo funcionan y sus valores predeterminados.
Rotada
¿Es la nueva contraseña una versión rotada de la contraseña antigua?
Mismos caracteres consecutivos
Comprobación opcional de los mismos caracteres consecutivos.
Secuencia de caracteres monótona demasiado larga
Comprobación opcional de secuencias de caracteres monótonas demasiado largas.
Contiene nombre de usuario
Comprueba si la contraseña contiene el nombre de usuario de alguna forma.
Comprobación de diccionario
Se llama a la rutina Cracklib para comprobar si la contraseña forma parte de un diccionario.

Estas comprobaciones son configurables ya sea mediante el uso de los argumentos del módulo o modificando el archivo de configuración /etc/security/pwquality.conf. Los argumentos del módulo anulan la configuración del archivo.

OPCIONES

debug
Esta opción hace que el módulo escriba información en syslog(3) indicando el comportamiento del módulo (esta opción no escribe información de contraseña en el archivo de registro).
tipo_authtok=XXX
La acción predeterminada es que el módulo utilice las siguientes indicaciones al solicitar contraseñas: "Nueva contraseña UNIX: " y "Vuelva a escribir la contraseña UNIX: ". La palabra de ejemplo UNIX puede ser reemplazada con esta opción, por defecto está vacía.
reintentar=N
Solicitar al usuario como máximo N veces antes de devolver un error. El valor predeterminado es 1.
difok=N
Este argumento cambiará el valor predeterminado de 1 para el número de cambios en la nueva contraseña con respecto a la antigua.

El valor especial 0 deshabilita todas las comprobaciones de similitud de la nueva contraseña con la antigua, excepto que la nueva contraseña sea exactamente la misma que la antigua.

minlen=N
El tamaño mínimo aceptable para la nueva contraseña (más uno si los créditos no están deshabilitados, que es el valor predeterminado). Además del número de caracteres de la nueva contraseña, se otorga crédito (de +1 en longitud) por cada tipo diferente de carácter (otro, mayúsculas, minúsculas y dígito). El valor predeterminado para este parámetro es 8. Tenga en cuenta que también hay un par de límites de longitud en Cracklib, que se utiliza para la comprobación de diccionario, un límite de "demasiado corto" de 4 que está codificado y un límite definido en tiempo de compilación (6) que se comprobará sin referencia a minlen.
dcredit=N
(N >= 0) Este es el crédito máximo por tener dígitos en la nueva contraseña. Si tiene menos de N dígitos o N dígitos, cada dígito contará +1 para cumplir el valor actual de minlen. El valor predeterminado para dcredit es 0, lo que significa que no hay bonificación por dígitos en la contraseña.

(N < 0) Este es el número mínimo de dígitos que deben cumplirse para una nueva contraseña.

ucredit=N
(N >= 0) Este es el crédito máximo por tener letras mayúsculas en la nueva contraseña. Si tiene menos de N letras mayúsculas o N letras mayúsculas, cada letra mayúscula contará +1 para cumplir el valor actual de minlen. El valor predeterminado para ucredit es 0, lo que significa que no hay bonificación por letras mayúsculas en la contraseña.

(N < 0) Este es el número mínimo de letras mayúsculas que deben cumplirse para una nueva contraseña.

lcredit=N
(N >= 0) Este es el crédito máximo por tener letras minúsculas en la nueva contraseña. Si tiene menos de N letras minúsculas o N letras minúsculas, cada letra minúscula contará +1 para cumplir el valor actual de minlen. El valor predeterminado para lcredit es 0, lo que significa que no hay bonificación por letras minúsculas en la contraseña.

(N < 0) Este es el número mínimo de letras minúsculas que deben cumplirse para una nueva contraseña.

ocredit=N
(N >= 0) Este es el crédito máximo por tener otros caracteres en la nueva contraseña. Si tiene menos de N otros caracteres o N otros caracteres, cada carácter adicional contará +1 para cumplir el valor actual de minlen. El valor predeterminado para ocredit es 0, lo que significa que no hay bonificación por caracteres adicionales en la contraseña.

(N < 0) Este es el número mínimo de caracteres adicionales que deben cumplirse para una nueva contraseña.

minclass=N
El número mínimo de clases de caracteres requeridas para la nueva contraseña. Las cuatro clases son dígitos, letras mayúsculas y minúsculas, y otros caracteres. La diferencia con la comprobación de crédito es que no se requiere una clase específica de caracteres. En su lugar, se requieren N de las cuatro clases. Por defecto, la comprobación está deshabilitada.
maxrepeat=N
Rechaza contraseñas que contengan más de N caracteres idénticos consecutivos. El valor predeterminado es 0, lo que significa que esta comprobación está deshabilitada.
maxsequence=N
Rechaza contraseñas que contengan secuencias de caracteres monótonas más largas que N. El valor predeterminado es 0, lo que significa que esta comprobación está deshabilitada. Ejemplos de tales secuencias son '12345' o 'fedcb'. Tenga en cuenta que la mayoría de estas contraseñas no pasarán la comprobación de simplicidad a menos que la secuencia sea solo una parte menor de la contraseña.
maxclassrepeat=N
Rechaza contraseñas que contengan más de N caracteres consecutivos de la misma clase. El valor predeterminado es 0, lo que significa que esta comprobación está deshabilitada.
gecoscheck=N
Si es distinto de cero, comprueba si las palabras individuales de más de 3 caracteres del campo GECOS de passwd(5) del usuario están contenidas en la nueva contraseña. El valor predeterminado es 0, lo que significa que esta comprobación está deshabilitada.
pam_pwquality(8) — Arch Linux

NAME

pam_pwquality - The libpwquality PAM module

SYNOPSIS

pam_pwquality.

DESCRIPTION

The pam_pwquality module is used to check the quality of the new password. It provides a password strength checking mechanism using the libpwquality library.

This module can be used in the `password' stack of PAM applications.

OPTIONS

dictcheck=N
Si es distinto de cero, comprueba si la contraseña (con posibles modificaciones) coincide con una palabra de un diccionario. Actualmente, la comprobación del diccionario se realiza utilizando la biblioteca cracklib. El valor predeterminado es 1, lo que significa que esta comprobación está habilitada.
usercheck=N
Si es distinto de cero, comprueba si la contraseña (con posibles modificaciones) contiene el nombre de usuario de alguna forma. El valor predeterminado es 1, lo que significa que esta comprobación está habilitada. No se realiza para nombres de usuario de menos de 3 caracteres.
usersubstr=N
Si es mayor que 3 (debido a la longitud mínima en usercheck), comprueba si la contraseña contiene una subcadena del nombre de usuario de al menos longitud N de alguna forma. El valor predeterminado es 0, lo que significa que esta comprobación está deshabilitada.
enforcing=N
Si es distinto de cero, rechaza la contraseña si falla las comprobaciones, de lo contrario, solo imprime la advertencia. El valor predeterminado es 1, lo que significa que la contraseña débil es rechazada (para usuarios que no son root).
badwords=<lista de palabras>
Las palabras de más de 3 caracteres de esta lista separada por espacios se buscan individualmente y se prohíben en la nueva contraseña. Por predeterminado, la lista está vacía, lo que significa que esta comprobación está deshabilitada.
dictpath=/ruta/al/diccionario
Esta opción permite especificar una ruta no predeterminada a los diccionarios de cracklib.
enforce_for_root
El módulo devolverá un error en caso de fallo de la comprobación, incluso si el usuario que cambia la contraseña es root. Esta opción está desactivada por defecto, lo que significa que solo se imprime el mensaje sobre el fallo de la comprobación, pero root puede cambiar la contraseña de todos modos. Tenga en cuenta que a root no se le pide la contraseña antigua, por lo que las comprobaciones que comparan la contraseña antigua y la nueva no se realizan.
local_users_only
El módulo no probará la calidad de la contraseña para los usuarios que no estén presentes en el archivo /etc/passwd. El módulo todavía pide la contraseña para que los módulos siguientes en la pila puedan usar la opción use_authtok. Esta opción está desactivada por defecto.
use_authtok
Este argumento se utiliza para *forzar* que el módulo no solicite al usuario una nueva contraseña, sino que utilice la proporcionada por el módulo password apilado previamente.

TIPOS DE MÓDULOS PROPORCIONADOS

Solo se proporciona el tipo de módulo password.

VALORES DE RETORNO

PAM_SUCCESS
La nueva contraseña pasa todas las comprobaciones.
PAM_AUTHTOK_ERR
No se introdujo ninguna contraseña nueva, no se pudo determinar el nombre de usuario o la nueva contraseña falla las comprobaciones de fortaleza.
PAM_AUTHTOK_RECOVERY_ERR
La contraseña antigua no fue suministrada por un módulo apilado anterior o no se solicitó al usuario. El primer error puede ocurrir si se especifica use_authtok.
PAM_SERVICE_ERR
Ocurrió un error interno.

EJEMPLOS

Como ejemplo del uso de este módulo, mostramos cómo puede ser apilado con el componente de contraseña de pam_unix(8).

#
# Estas líneas apilan dos módulos de tipo contraseña. En este ejemplo,
# al usuario se le dan 3 oportunidades para introducir una contraseña
# segura. El argumento "use_authtok" asegura que el módulo pam_unix no
# solicite una contraseña, sino que utilice la proporcionada por
# pam_pwquality.
#
password required pam_pwquality.so retry=3
password required pam_unix.so use_authtok

Otro ejemplo es para el caso en que desee utilizar el cifrado de contraseñas sha256:

#
# Estas líneas permiten a los sistemas modernos soportar contraseñas de
# al menos 14 bytes con crédito adicional de 2 por dígitos y 2 por otros.
# La nueva contraseña debe tener al menos tres bytes que no estén presentes
# en la contraseña antigua.
#
password required pam_pwquality.so \
              difok=3 minlen=15 dcredit=2 ocredit=2
password required pam_unix.so use_authtok nullok sha256

Y aquí hay otro ejemplo en caso de que no desee utilizar créditos:

#
# Estas líneas requieren que el usuario seleccione una contraseña con una
# longitud mínima de 8 y con al menos 1 número de dígito, 1 letra
# mayúscula y 1 carácter especial.
#
password required pam_pwquality.so \
              dcredit=-1 ucredit=-1 ocredit=-1 lcredit=0 minlen=8
password required pam_unix.so use_authtok nullok sha256
