NOMBRE

pam_namespace - módulo PAM para configurar el espacio de nombres para una sesión

SINOPSIS

pam_namespace.so [debug] [unmnt_remnt] [unmnt_only] [require_selinux] [gen_hash] [ignore_config_error] [ignore_instance_parent_mode] [unmount_on_close] [use_current_context] [use_default_context] [mount_private]

DESCRIPCIÓN

El módulo PAM pam_namespace configura un espacio de nombres privado para una sesión con directorios poliintanciados. Un directorio poliintanciado proporciona una instancia diferente de sí mismo según el nombre de usuario, o cuando se utiliza SELinux, el nombre de usuario, el contexto de seguridad o ambos. Si existe un script ejecutable /etc/security/namespace.init, se utiliza para inicializar el directorio de instancia después de que se configura y se monta en el directorio poliintanciado. El script recibe la ruta del directorio poliintanciado, la ruta del directorio de instancia, un indicador de si el directorio de instancia se creó nuevo (0 para no, 1 para sí) y el nombre de usuario como sus argumentos. El script se invoca con privilegios de root completos y el acceso al directorio de instancia en este contexto debe hacerse con precaución, ya que está controlado por el usuario no privilegiado para el que se ha creado.

El módulo pam_namespace disocia el espacio de nombres de la sesión del espacio de nombres padre. Cualquier montaje/desmontaje realizado en el espacio de nombres padre, como el montaje de dispositivos, no se reflejará en el espacio de nombres de la sesión. Para propagar eventos de montaje/desmontaje seleccionados del espacio de nombres padre al espacio de nombres de sesión disociado, un administrador puede usar la característica especial de subárbol compartido. Para obtener información adicional sobre la característica de subárbol compartido, consulte la página del manual de mount(8) y la descripción de subárbol compartido en http://lwn.net/Articles/159077 y http://lwn.net/Articles/159092.

OPCIONES

debug

Se registra mucha información de depuración utilizando syslog

unmnt_remnt

Para programas como su y newrole, la sesión de inicio de sesión ya ha configurado un espacio de nombres poliintanciado. Para estos programas, la poliintanciación se realiza basándose en el nuevo ID de usuario o contexto de seguridad, sin embargo, el comando primero necesita deshacer la poliintanciación realizada por el inicio de sesión. Este argumento le indica al comando que deshaga primero la poliintanciación anterior antes de proceder con la nueva poliintanciación basada en el nuevo ID/contexto.

unmnt_only

Para programas de confianza que desean deshacer cualquier montaje bind existente y procesar directorios de instancia por sí mismos, este argumento les permite desmontar los directorios de instancia montados actualmente.

require_selinux

Si SELinux no está habilitado, devuelve un error

gen_hash

En lugar de usar el contexto de seguridad de cadena para el nombre de la instancia, genera y usa su hash md5.

ignore_config_error

Si una línea en el archivo de configuración correspondiente a un directorio poliintanciado contiene un error de formato, omite esa línea y procesa la siguiente. Sin esta opción, pam devolverá un error al programa que llama, lo que resultará en la terminación de la sesión.

ignore_instance_parent_mode

Por defecto, se espera que los directorios padre de instancia tengan el modo restrictivo de 000. Usando esta opción, un administrador puede optar por ignorar el modo del padre de instancia. Esta opción debe usarse con precaución, ya que reducirá los objetivos de seguridad y aislamiento del mecanismo de poliintanciación.

unmount_on_close

Desmonta explícitamente los directorios poliintanciados en lugar de depender de la destrucción automática del espacio de nombres después de que salga el último proceso en un espacio de nombres. Esta opción solo debe usarse en caso de que se garantice por otros medios que no puede haber ningún proceso ejecutándose en el espacio de nombres privado después del cierre de la sesión. También es útil solo en caso de que haya varias llamadas de sesión de pam en secuencia desde el mismo proceso.

use_current_context

Útil para servicios que no cambian el contexto SELinux con la llamada setexeccon. El módulo usará el contexto SELinux actual del proceso que llama para la poliintanciación de nivel y contexto.

use_default_context

Útil para servicios que no usan pam_selinux para cambiar el contexto SELinux con la llamada setexeccon. El módulo usará el contexto SELinux predeterminado del usuario para la poliintanciación de nivel y contexto.

mount_private

Esta opción se puede usar en sistemas donde el punto de montaje / o sus submontajes se hacen compartidos (por ejemplo, con un comando mount --make-rshared /). El módulo marcará todo el árbol de directorios para que cualquier operación de montaje y desmontaje en el espacio de nombres de poliintanciación sea privada. Normalmente, pam_namespace intentará detectar el punto de montaje / compartido y hará que los directorios poliintanciados sean privados automáticamente. Esta opción solo debe usarse cuando solo se comparte un subárbol y / no.

Tenga en cuenta que los montajes y desmontajes realizados en el espacio de nombres privado no afectarán al espacio de nombres padre si se usa esta opción o cuando el punto de montaje / compartido se detecta automáticamente.

TIPOS DE MÓDULO PROPORCIONADOS

Solo se proporciona el tipo de módulo session. El módulo no debe llamarse desde procesos multihilo.

VALORES DE RETORNO

PAM_SUCCESS

La configuración del espacio de nombres fue exitosa.

PAM_SERVICE_ERR

Ocurrió un error inesperado del sistema al configurar el espacio de nombres.

PAM_SESSION_ERR

Ocurrió un error inesperado en la configuración del espacio de nombres.

ARCHIVOS

/etc/security/namespace.conf

Archivo de configuración principal

/etc/security/namespace.d

Directorio para archivos de configuración adicionales

/etc/security/namespace.init

Script de inicialización para directorios de instancia

EJEMPLOS

Para los <servicio>s que necesiten poliintanciación (login, por ejemplo), coloque la siguiente línea en /etc/pam.d/<servicio> como la última línea para el grupo de sesión:

session required pam_namespace.so [argumentos]

Para usar la poliintanciación con el gestor de pantalla gráfico gdm, consulte la documentación de gdm.

pam_namespace(8)

pam_namespace is a PAM module that allows the creation of private namespaces for processes. Namespaces provide a way to isolate certain system resources, such as mount points, network interfaces, and the process tree, from the rest of the system.

NAME

pam_namespace - Pluggable Authentication Module for managing user-specific namespaces

SYNOPSIS

/etc/pam.d/system-auth 

auth      optional      pam_namespace.so [options]
session   required      pam_namespace.so [options]

DESCRIPTION

The pam_namespace module manipulates namespaces for user sessions. It can be used to create private mount point hierarchies, isolate network devices, and restrict visibility into the process tree. This is particularly useful for containerization technologies and for providing users with isolated environments.

The module is typically configured in the PAM stack for authentication and session management. When used in the auth section, it can prepare namespaces before a user logs in. In the session section, it is responsible for setting up and tearing down the namespaces for the duration of the user's session.

OPTIONS

[allow_other]
Allows other users to access the namespace. By default, only the user who created the namespace can access it.
[mount=/path/to/mountpoint]
Specifies a directory to be mounted privately within the namespace. This mount point will be isolated from the host system.
[unmount=/path/to/mountpoint]
Specifies a directory to be unmounted from the namespace.
[scope=<system|user>]
Defines the scope of the namespace. system namespaces are shared among all users, while user namespaces are private to each user.
[pid=/path/to/pidfile]
Specifies a PID file to be created for the namespace. This can be useful for managing processes within the namespace.

MODULE TYPES PROVIDED

The following PAM module types are provided:

  • auth
  • session

RETURN VALUES

0
Success.
1
Generic error.
2
Invalid option.
3
Cannot allocate memory.
4
Namespace creation failed.
5
Mount operation failed.
6
Unmount operation failed.

FILES

/etc/pam.d/system-auth
Default PAM configuration file.
/etc/security/namespace.conf
Configuration file for pam_namespace options.

EXAMPLES

To create a private mount namespace for users, add the following lines to your PAM configuration file (e.g., /etc/pam.d/system-auth): 

session  required     pam_namespace.so unmount=/home/user/tmp

This example will ensure that any mounts made within the user's session are unmounted automatically when the session ends. The unmount=/home/user/tmp option specifies a directory that should be unmounted.

pam(8), pam.conf(5), namespaces(7)
