PASS-OTP(1) Manual de comandos generales PASS-OTP(1)

NOMBRE

pass-otp - Una extensión de pass(1) para gestionar tokens de contraseña de un solo uso (OTP).

SINOPSIS

pass otp [ COMANDO ] [ OPCIONES ]... [ ARGUMENTOS ]...

DESCRIPCIÓN

pass-otp extiende la utilidad pass(1) con el comando otp para añadir secretos OTP, generar códigos OTP y mostrar URIs de claves secretas usando el esquema estándar otpauth://.

Si no se especifica ningún COMANDO, el COMANDO por defecto es code.

COMANDOS

otp code [ --clip, -c ] nombre-pass

Genera e imprime un código OTP de la clave secreta almacenada en nombre-pass usando oathtool(1). Si se especifica --clip o -c, no imprime el código sino que lo copia al portapapeles usando xclip(1) y luego restaura el portapapeles después de 45 (o PASSWORD_STORE_CLIP_TIME) segundos. Este comando tiene el nombre alternativo show.

otp insert [ --force, -f ] [ --echo, -e ] [ [ --secret, -s ] [ --issuer, -i emisor ] [ --account, -a cuenta ] ] [ nombre-pass ]

Solicita e inserta un nuevo secreto OTP en el almacén de contraseñas en nombre-pass.

Si se especifica --secret, solicita el valor del secreto, asumiendo el algoritmo SHA1, un período de 30 segundos y 6 dígitos OTP. También se deben especificar uno o ambos de emisor y cuenta.

Si no se especifica --secret, solicita una URI de clave; consulta la documentación en https://github.com/google/google-authenticator/wiki/Key-Uri-Format para la especificación de la URI de clave.

El secreto se consume de la entrada estándar; especifica --echo o -e para mostrar la entrada al ejecutar este comando interactivamente. Si no se especifica nombre-pass, convierte la etiqueta de URI emisor:nombredecuenta a una ruta en la forma de emisor/nombredecuenta. Solicita antes de sobrescribir un secreto existente, a menos que se especifique --force o -f. Este comando tiene el nombre alternativo add.

otp append [ --force, -f ] [ --echo, -e ] [ [ --secret, -s ] [ --issuer, -i emisor ] [ --account, -a cuenta ] ] nombre-pass

Añade un secreto OTP a la contraseña almacenada en nombre-pass, preservando cualquier línea existente.

Si se especifica --secret, solicita el valor del secreto, asumiendo el algoritmo SHA1, un período de 30 segundos y 6 dígitos OTP. También se deben especificar uno o ambos de emisor y cuenta.

Si no se especifica --secret, solicita una URI de clave; consulta la documentación en https://github.com/google/google-authenticator/wiki/Key-Uri-Format para la especificación de la URI de clave.

La URI se consume de la entrada estándar; especifica --echo o -e para mostrar la entrada al ejecutar este comando interactivamente. Solicita antes de sobrescribir un secreto existente, a menos que se especifique --force o -f.

otp uri [ --clip, -c | --qrcode, -q ] nombre-pass

Imprime la URI de clave almacenada en nombre-pass a la salida estándar. Si se especifica --clip o -c, no imprime la URI sino que la copia al portapapeles usando xclip(1) y luego restaura el portapapeles después de 45 (o PASSWORD_STORE_CLIP_TIME) segundos. Si se especifica --qrcode o -q, no imprime la URI sino que muestra un código QR usando qrencode(1) ya sea en la terminal o gráficamente si es compatible.

otp validate uri

Prueba la validez de una cadena URI según el Formato de URI de Clave. Para más información sobre este formato, consulta la documentación en https://github.com/google/google-authenticator/wiki/Key-Uri-Format.
