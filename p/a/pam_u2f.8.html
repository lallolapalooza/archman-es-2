PAM_U2F(8) Manual del módulo PAM U2F PAM_U2F(8)

NOMBRE

pam_u2f - Módulo para autenticación U2F

SINOPSIS

pam_u2f [...]

DESCRIPCIÓN

El módulo proporciona autenticación U2F contra Yubikeys y otros autenticadores compatibles.

OPCIONES

debug

Habilita la salida de depuración

debug_file

Nombre del archivo al que escribir los mensajes de depuración. Si este archivo falta, no se registrará nada. Este archivo regular debe ser creado por el usuario o debe existir y ser un archivo regular para que se registre algo en él. No se crea por pam-u2f a propósito (por consideraciones de seguridad). Este nombre de archivo puede ser alternativamente "stderr" (por defecto), "stdout", o "syslog".

origin=origen

Establece el ID de la parte confiable para el procedimiento de autenticación FIDO. Si no se especifica ningún valor, se utiliza el identificador "pam://$HOSTNAME".

appid=appid

Establece el ID de la aplicación para el procedimiento de autenticación FIDO. Si no se especifica ningún valor, se toma el mismo valor que se utiliza para origin ("pam://$HOSTNAME" si origin tampoco se especifica). Esta configuración solo es aplicable a credenciales FIDO creadas con pamu2fcfg versiones v1.0.8 o anteriores. Tenga en cuenta que en las versiones v1.1.0 y v1.1.1 de pam-u2f, el manejo de esta configuración estuvo temporalmente roto si el valor no era el mismo que el valor de origin.

authfile=archivo

Establece la ubicación del archivo que contiene las mapeos de nombres de usuario a keyHandles y claves de usuario. Se puede configurar un archivo individual (por usuario) relativo a los directorios personales del usuario, por ejemplo, ".ssh/u2f_keys". Si no se especifica, la ubicación por defecto es $XDG_CONFIG_HOME/Yubico/u2f_keys. Si $XDG_CONFIG_HOME no está configurado, se utiliza $HOME/.config/Yubico/u2f_keys. El formato del archivo de autenticación es <nombredeusuario>:<KeyHandle1>,<UserKey1>,<CoseType1>,<Options1>:<KeyHandle2>,<UserKey2>,<CoseType2>,<Options2>:...

expand

Habilita la expansión de variables dentro de la ruta del archivo de autenticación: %u se expande al nombre de usuario local (PAM_USER) y %% se expande a %. Las secuencias de expansión desconocidas resultan en un error de autenticación. Ver también openasuser.

authpending_file=archivo

Establece la ubicación del archivo que se utiliza para notificaciones de solicitud de toque. Este archivo se abrirá cuando pam-u2f comience a esperar a que un usuario toque el autenticador FIDO, y se cerrará cuando ya no espere un toque. Úselo con inotify para escuchar estos eventos, o una herramienta de nivel más alto como yubikey-touch-detector. Valor por defecto: /var/run/user/$UID/pam-u2f-authpending. Establezca un valor vacío para deshabilitar esta funcionalidad, así: "authpending_file=".

nouserok

Establecer para permitir que los intentos de autenticación tengan éxito incluso si el usuario que intenta autenticarse no se encuentra en authfile o si authfile falta o está mal formado.

openasuser

Cambia a setuid al usuario que se autentica al abrir el archivo de autenticación. Útil cuando el directorio personal del usuario se almacena en un volumen NFS montado con la opción root_squash (que mapea root a nobody, que no podrá leer el archivo). Tenga en cuenta que después del lanzamiento 1.0.8, esto se hace por defecto cuando no se ha establecido ningún archivo de autenticación global (la ruta es absoluta) o la variable de entorno XDG_CONFIG_HOME.

alwaysok

Establecer para permitir que todos los intentos de autenticación tengan éxito (también conocido como modo de presentación).

max_devices=n_dispositivos

Número máximo de autenticadores FIDO permitidos por usuario (por defecto es 24). Los autenticadores FIDO especificados en el archivo de mapeo de autorización que excedan este valor serán ignorados.

interactive

Establecer para mostrar un mensaje y esperar antes de probar la presencia de un autenticador FIDO. Recomendado si su autenticador no tiene un disparador táctil.

[prompt=su mensaje aquí]

Establece un mensaje de aviso individual para el modo interactivo. Observe los corchetes alrededor de este parámetro para que los espacios sean reconocidos correctamente por PAM.

manual

Establecer para pasar a una consola manual donde los desafíos se imprimen en pantalla y la respuesta se lee de la entrada estándar. Útil para depuración y sesiones SSH sin soporte FIDO del cliente/servidor SSH. Si está habilitado, el modo interactivo se vuelve redundante y no tiene efecto.

cue

Establecer para mostrar un mensaje que recuerde tocar el autenticador FIDO.

[cue_prompt=su mensaje aquí]

Establece un mensaje de aviso individual para la opción cue. Observe los corchetes alrededor de este parámetro para que los espacios sean reconocidos correctamente por PAM.

nodetect

Omite la detección de si un autenticador FIDO adecuado está insertado antes de realizar una autenticación completa. Ver NOTAS abajo.

userpresence=int

Si es 1, requiere presencia del usuario durante la autenticación. Si es 0, no solicita presencia del usuario durante la autenticación. Si se omite, se recurre al comportamiento por defecto del autenticador.

userverification=int

Si es 1, requiere verificación del usuario durante la autenticación (por ejemplo, biométrica). Si es 0, no solicita verificación del usuario durante la autenticación. Si se omite, se recurre al comportamiento por defecto del autenticador. Si está habilitado, se requiere un autenticador con soporte para verificación de usuario FIDO2.

pinverification=int

Si es 1, requiere verificación de PIN durante la autenticación. Si es 0, no solicita verificación de PIN durante la autenticación. Si se omite, se recurre al comportamiento por defecto del autenticador. Si está habilitado, se requiere un autenticador con soporte para un PIN FIDO2.

sshformat

Utiliza credenciales producidas por versiones de OpenSSH que tienen soporte para autenticador FIDO. No es posible mezclar credenciales nativas y credenciales SSH. Una vez habilitada esta opción, todas las credenciales se analizarán como SSH.

conf=ruta/a/pam_u2f.conf

Establece una ubicación alternativa para el archivo de configuración. La ruta proporcionada debe ser absoluta y corresponder a un archivo regular existente. Ver ARCHIVO DE CONFIGURACIÓN.

EJEMPLOS

Autenticación de segundo factor que difiere la verificación del usuario a el archivo de mapeo de autorización.

auth required pam_u2f.so authfile=/etc/u2f_mappings cue

Autenticación sin contraseña que impone la verificación de PIN.

auth sufficient pam_u2f.so authfile=/etc/u2f_mappings cue pinverification=1 userverification=0

Autenticación sin contraseña que utiliza UV incorporada (por ejemplo, biométrica) con un fallback a PIN.

auth sufficient pam_u2f.so authfile=/etc/u2f_mappings cue pinverification=0 userverification=1
auth sufficient pam_u2f.so authfile=/etc/u2f_mappings cue pinverification=1 userverification=0

SALVEDADES

Por defecto, las rutas relativas al archivo de autenticación se abrirán como el usuario de destino, mientras que las rutas absolutas se abrirán como "root". Si la variable "XDG_CONFIG_HOME" está configurada, los privilegios no se reducirán a menos que esté configurado el ajuste de configuración "openasuser".

Usar pam-u2f para asegurar el inicio de sesión en una computadora mientras se almacena el archivo de mapeo en un directorio personal cifrado, resultará en la imposibilidad de iniciar sesión en el sistema. La partición se descifra después del inicio de sesión y el archivo de mapeo no puede ser accedido.

ARCHIVO DE CONFIGURACIÓN

Se puede utilizar un archivo de configuración para establecer los argumentos por defecto del módulo.

•El archivo tiene un formato nombre = valor, con comentarios que comienzan con el carácter #.
•Los espacios en blanco al principio de la línea, al final de la línea y alrededor del signo = se ignoran.
•Cualquier argumento conf en el archivo de configuración se ignora.
•El tamaño máximo para el archivo de configuración es 4 KiB.
•La ruta por defecto para el archivo de configuración es /etc/security/pam_u2f.conf. Se permite que el archivo por defecto no exista. Se puede establecer una ruta alternativa en la línea de comandos del módulo o

OPCIONES

•Las opciones especificadas en la línea de comandos del módulo anulan los valores del archivo de configuración.

NOTAS

Nodetect

La opción "nodetect" debe usarse con precaución. pam_u2f comprueba que una clave configurada para el usuario esté insertada antes de realizar la autenticación táctil completa. Esta detección se realiza enviando una solicitud de autenticación "solo comprobación" a todos los tokens insertados para ver si al menos uno de ellos responde afirmativamente a uno o más de los manejadores de claves configurados para el usuario. Al hacer esto, pam_u2f puede evitar emitir el mensaje "cue" (si está configurado), lo que puede causar algunos problemas confusos en la interfaz de usuario si el mensaje se emite seguido de un fallo inmediato de la autenticación táctil por parte de la biblioteca subyacente. Esta opción también es útil para evitar un retraso involuntario de 1 segundo antes de la autenticación táctil causado por versiones de libu2f-host <= 1.1.5.

Si pam_u2f está configurado para "cue" y "nodetect", un atacante puede determinar que pam_u2f forma parte de la pila de autenticación insertando cualquier token U2F aleatorio y realizando un intento de autenticación. En este escenario, el atacante vería el mensaje de indicación seguido de un fallo inmediato, mientras que con la detección habilitada, la autenticación fallaría silenciosamente. Entienda que un atacante podría elegir un autenticador que le alerte de alguna manera del intento de autenticación "solo comprobación", por lo que esta precaución solo retrasa el problema un paso.

En resumen, la función de detección se añadió para evitar problemas confusos en la interfaz de usuario y para evitar la filtración de información sobre la pila de autenticación en un escenario muy específico cuando se configura "cue". La opción "nodetect" se añadió para evitar un comportamiento de suspensión erróneo en versiones anteriores de libu2f-host y para tokens hipotéticos que no toleran la doble autenticación. La detección se realiza, y de igual modo se respeta "nodetect", independientemente de si "cue" también está especificado.

SELinux

Debido a un problema con Fedora Linux, y posiblemente con otras distribuciones que usan SELinux, un sistema configurado con pam-u2f puede terminar en una situación en la que se deniega el acceso al archivo de credenciales. Si la opción nouserok también está configurada, esto resultará en una autenticación exitosa dentro del módulo, sin usar el autenticador FIDO.

Para actualizar correctamente el contexto de seguridad, se debe usar el comando fixfiles onboot en instalaciones existentes.

Además, para permitir el acceso de lectura a un archivo de autenticación o directorio ubicado en una ubicación no estándar, se debe usar el comando

# chcon -R -t auth_home_t /ruta/al/archivo_autenticacion

debe ser utilizado.

Para más información consulte https://access.redhat.com/security/cve/CVE-2020-24612.
