NOMBRE

pam_cap - Módulo PAM de capacidades

SINOPSIS

[nombre-del-servicio] auth control-flag pam_cap [opciones]

DESCRIPCIÓN

El módulo pam_so puede usarse para especificar capacidades Heredables para los árboles de procesos raíz en la aplicación PAM. El módulo también soporta el bloqueo de capacidades del vector Límite y la adición de capacidades del vector Ambiental.

Para que las aplicaciones PAM generales funcionen correctamente, la aplicación debe ejecutarse con al menos CAP_SETPCAP activado en su vector de capacidades Permitido. Muchas aplicaciones PAM se ejecutan como root, lo que tiene todos los bits del conjunto Límite activados, por lo que este requisito se cumple típicamente. Para conceder una capacidad del vector Ambiental, el bit Permitido correspondiente también debe estar disponible para la aplicación.

El módulo pam_so es un módulo auth de Linux-PAM. Proporciona funcionalidad para respaldar pam_sm_authenticate() y pam_sm_setcred(). Es este último el que modifica realmente la tupla 3 IAB de vectores de capacidad: el IAB configurado. En una configuración de aplicación típica, podría tener una línea como esta:

auth    optional    pam_cap.so

Los argumentos del módulo son:

○
debug: Aunque soportado, actualmente no hace nada.
○
config=/ruta/al/archivo: Anula la configuración predeterminada para el módulo. El valor predeterminado no especificado para este archivo es /etc/security/capability.conf. Tenga en cuenta que config=/dev/null es un valor válido. Consulte default= a continuación para ver situaciones en las que esto podría ser apropiado.
○
keepcaps: Esto es lo máximo que el módulo pam_cap.so puede hacer para ayudar a una aplicación a soportar el uso del vector de capacidades Ambiental. El soporte de la aplicación para el conjunto Ambiental es pobre en la actualidad.
○
autoauth: Este argumento hace que el módulo pam_cap.so devuelva PAM_SUCCESS si el PAM_USER que se está autenticando existe. La ausencia de este argumento hará que pam_cap.so solo devuelva PAM_SUCCESS si el PAM_USER está cubierto por una regla específica en el archivo de configuración prevaleciente.
○
default=IAB: Este argumento se ignora si el archivo de configuración prevaleciente contiene una regla "*". Si no existe tal regla, la tupla 3 IAB se inserta al final del archivo de configuración y se aplica a todos los PAM_USERs no cubiertos por una regla anterior. Tenga en cuenta que si desea que todos los PAM_USERs estén cubiertos por esta regla predeterminada, puede suministrar el argumento del módulo config=/dev/null.
○
defer: Este argumento organiza que las capacidades IAB concedidas a un usuario se añadan lo suficientemente tarde en la pila de autenticación de Linux-PAM como para que se mantengan. Es decir, *después* de que la aplicación realice su llamada setuid(UID). Como tal, en conjunción con el argumento del módulo keepcaps, las aplicaciones compatibles de este tipo pueden soportar la concesión de capacidades del vector Ambiental con pam_cap.so.

VER TAMBIÉN

pam.conf(5), capability.conf(5), cap_text_formats(7), pam(8).
