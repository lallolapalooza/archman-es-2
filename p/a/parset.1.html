NOMBRE

parset - establece variables de shell en paralelo

SINOPSIS

parset nombredevariable [opciones para GNU Parallel]

env_parset nombredevariable [opciones para GNU Parallel]

DESCRIPCIÓN

parset es una función de shell que introduce la salida de GNU parallel en variables de shell.

env_parset es una función de shell que introduce la salida de env_parallel en variables de shell.

Las funciones parset y env_parset se definen como parte de env_parallel.

Si nombredevariable es un único nombre de variable, se tratará como la variable de destino. Si la variable se define como un array asociativo (usando typeset -A mi_asociativo), se utilizará. De lo contrario, la variable se convertirá en un array normal.

Si nombredevariable contiene varios nombres separados por ',' o espacio, los nombres serán las variables de destino. El número de nombres debe ser al menos igual al número de trabajos.

OPCIONES

Igual que GNU parallel, pero se colocan después de la variable de destino.

SHELLS COMPATIBLES

Bash/Zsh/Ksh/Mksh

Ejemplos

Introduce la salida en miarray:

parset miarray seq 3 ::: 4 5 6
echo "${miarray[1]}"

Introduce la salida en las variables $seq, $pwd, $ls:

parset "seq pwd ls" ::: "seq 10" pwd ls
echo "$ls"

Introduce la salida en las variables $seq, $pwd, $ls:

into_vars=(seq pwd ls)
parset "${into_vars[*]}" ::: "seq 10" pwd ls
echo "$ls"

Introduce la salida en el array asociativo miasociativo (no compatible con mksh):

typeset -A miasociativo
parset miasociativo seq ::: 4 5 ::: 6 7
echo "${miasociativo[4 7]}"

Los comandos a ejecutar pueden ser un array:

cmd=("echo first" "echo '<>'" "pwd")
parset data ::: "${cmd[@]}"
echo "${data[1]}"
echo "${data[2]}"

parset puede leer desde stdin (entrada estándar) si es un archivo:

parset res echo < archivo_entrada_paralelo

pero parset no puede formar parte de una tubería. En particular, esto significa que no puede leer de una tubería ni escribir en una tubería:

seq 10 | parset res echo No funciona

sino que debe usar un archivo temporal:

seq 10 > archivo_entrada
parset res echo :::: archivo_entrada
echo "${res[1]}"
echo "${res[9]}"

o una FIFO:

mkfifo entrada_fifo
seq 30 > entrada_fifo &
parset res echo :::: entrada_fifo
echo "${res[1]}"
echo "${res[29]}"

o la sustitución de procesos de Bash/Zsh/Ksh:

parset res echo :::: <(seq 100)
echo "${res[1]}"
echo "${res[99]}"

Instalación

Coloca esto en el $HOME/.bashrc o $HOME/.zshenv o $HOME/.kshrc correspondiente:

. env_parallel.bash
. env_parallel.zsh
source `which env_parallel.ksh`

Por ejemplo, haciendo:

echo '. env_parallel.bash' >> $HOME/.bashrc
echo '. env_parallel.zsh' >> $HOME/.zshenv
echo 'source `which env_parallel.ksh`' >> $HOME/.kshrc

o haciendo:

env_parallel --install

ash/dash (el /bin/sh de FreeBSD)

Ejemplos

ash no soporta arrays.

Introduce la salida en las variables $seq, $pwd, $ls:

parset "seq pwd ls" ::: "seq 10" pwd ls
echo "$ls"

parset puede leer desde stdin (entrada estándar) si es un archivo:

parset res1,res2,res3 echo < archivo_entrada_paralelo

pero parset no puede formar parte de una tubería. En particular, esto significa que no puede leer de una tubería ni escribir en una tubería:

seq 3 | parset res1,res2,res3 echo No funciona

sino que debe usar un archivo temporal:

seq 3 > archivo_entrada
parset res1,res2,res3 echo :::: archivo_entrada
echo "$res1"
echo "$res2"
echo "$res3"

o una FIFO:

mkfifo entrada_fifo
seq 3 > entrada_fifo &
parset res1,res2,res3 echo :::: entrada_fifo
echo "$res1"
echo "$res2"
echo "$res3"

Instalación

Coloca el archivo correspondiente de estos en $HOME/.profile:

. env_parallel.sh
. env_parallel.ash
. env_parallel.dash

Por ejemplo, haciendo:

echo '. env_parallel.ash' >> $HOME/.bashrc

o haciendo:

env_parallel --install
