NOMBRE

pack200 - Empaqueta un archivo JAR en un archivo pack200 comprimido para el despliegue web.

SINOPSIS

pack200 [opciones] archivo-salida archivo-JAR

Las opciones pueden estar en cualquier orden. La última opción en la línea de comandos o en un archivo de propiedades anula todas las opciones especificadas previamente.

opciones
Las opciones de la línea de comandos. Ver Opciones.
archivo-salida
Nombre del archivo de salida.
archivo-JAR
Nombre del archivo de entrada.

DESCRIPCIÓN

El comando pack200 es una aplicación Java que transforma un archivo JAR en un archivo pack200 comprimido con el compresor gzip de Java. Los archivos pack200 son archivos altamente comprimidos que pueden ser desplegados directamente para ahorrar ancho de banda y reducir el tiempo de descarga.

El comando pack200 tiene varias opciones para ajustar y configurar el motor de compresión. El uso típico se muestra en el siguiente ejemplo, donde myarchive.pack.gz se produce con la configuración por defecto del comando pack200:

pack200 myarchive.pack.gz myarchive.jar

OPCIONES

-r, --repack

Produce un archivo JAR empaquetando y desempaquetando un archivo JAR. El archivo resultante puede ser utilizado como entrada para la herramienta jarsigner(1). El siguiente ejemplo empaqueta y desempaqueta el archivo myarchive.jar: 
pack200 --repack myarchive-packer.jar myarchive.jar
pack200 --repack myarchive.jar

El siguiente ejemplo preserva el orden de los archivos en el archivo de entrada.

-g, --no-gzip

Produce un archivo pack200. Con esta opción, se debe usar un compresor adecuado, y el sistema de destino debe usar un descompresor correspondiente. 
pack200 --no-gzip myarchive.pack myarchive.jar
-G, --strip-debug

Elimina los atributos de depuración de la salida. Estos incluyen SourceFile, LineNumberTable, LocalVariableTable y LocalVariableTypeTable. Eliminar estos atributos reduce el tamaño tanto de las descargas como de las instalaciones, pero reduce la utilidad de los depuradores.
--keep-file-order

Preserva el orden de los archivos en el archivo de entrada. Este es el comportamiento por defecto.
-O, --no-keep-file-order

El empaquetador reordena y transmite todos los elementos. El empaquetador también puede eliminar los nombres de directorios JAR para reducir el tamaño de la descarga. Sin embargo, ciertas optimizaciones de archivos JAR, como la indexación, pueden no funcionar correctamente.
-Svalor , --segment-limit=valor

El valor es el tamaño objetivo estimado N (en bytes) de cada segmento de archivo. Si un solo archivo de entrada requiere más de N bytes, entonces se proporciona su propio segmento de archivo. Como caso especial, un valor de -1 produce un único segmento grande con todos los archivos de entrada, mientras que un valor de 0 produce un segmento por cada clase. Los segmentos de archivo más grandes resultan en menos fragmentación y mejor compresión, pero su procesamiento requiere más memoria.

El tamaño de cada segmento se estima contando el tamaño de cada archivo de entrada a transmitir en el segmento con el tamaño de su nombre y otras propiedades transmitidas.

El valor por defecto es -1, lo que significa que el empaquetador crea un único archivo de salida segmentado. En casos donde se generan archivos de salida extremadamente grandes, se anima encarecidamente a los usuarios a usar segmentación o a dividir el archivo de entrada en JARs más pequeños.

Un JAR de 10 MB empaquetado sin este límite típicamente se comprime aproximadamente un 10 por ciento más pequeño, pero el empaquetador puede requerir un heap de Java más grande (aproximadamente 10 veces el límite del segmento).

-Evalor , --effort=valor

Si el valor se establece en un solo dígito decimal, entonces el empaquetador utiliza la cantidad indicada de esfuerzo en comprimir el archivo. El nivel 1 puede producir un tamaño algo mayor y una velocidad de compresión más rápida, mientras que el nivel 9 lleva mucho más tiempo, pero puede producir una mejor compresión. El valor especial 0 instruye al comando pack200 a copiar directamente el archivo JAR original sin compresión. El estándar JSR 200 requiere que cualquier desempaquetador entienda este caso especial como una transferencia directa de todo el archivo.

El valor por defecto es 5, para invertir una cantidad modesta de tiempo en producir una compresión razonable.

-Hvalor , --deflate-hint=valor

Anula el valor por defecto, que preserva la información de entrada, pero puede hacer que el archivo transmitido sea más grande. Los valores posibles son: true, false o keep.

Si el valor es true o false, entonces el comando packer200 establece la pista de desinflado correspondientemente en el archivo de salida y no transmite las pistas de desinflado individuales de los elementos del archivo.

El valor keep preserva las pistas de desinflado observadas en el JAR de entrada. Este es el valor por defecto.

-mvalor , --modification-time=valor

Los valores posibles son latest y keep.

Si el valor es latest, entonces el empaquetador intenta determinar la última hora de modificación, entre todas las entradas disponibles en el archivo original, o la última hora de modificación de todas las entradas disponibles en ese segmento. Este valor único se transmite como parte del segmento y se aplica a todas las entradas de cada segmento. Esto puede disminuir marginalmente el tamaño transmitido del archivo a expensas de establecer todos los archivos instalados en una única fecha.

Si el valor es keep, entonces se preservan las horas de modificación observadas en el JAR de entrada. Este es el valor por defecto.

-Parchivo , --pass-file=archivo

Indica que un archivo debe ser transferido byte a byte sin compresión. Al repetir la opción, se pueden especificar varios archivos. No hay transformación de ruta de acceso, excepto que el separador de archivos del sistema se reemplaza por el separador de archivos JAR (`/`). Los nombres de archivo resultantes deben coincidir exactamente como cadenas con sus ocurrencias en el archivo JAR. Si archivo es un nombre de directorio, entonces todos los archivos bajo ese directorio son transferidos.
-Uacción , --unknown-attribute=acción

Anula el comportamiento por defecto, lo que significa que el archivo de clase que contiene el atributo desconocido se transfiere con la acción especificada. Los valores posibles para las acciones son error, strip o pass.

Si el valor es error, entonces toda la operación del comando pack200 falla con una explicación adecuada.

Si el valor es strip, entonces el atributo se elimina. Eliminar los atributos requeridos de la Máquina Virtual Java (JVM) puede causar fallos en el cargador de clases.

Si el valor es pass, entonces toda la clase se transmite como si fuera un recurso.

OPTIONS




--class-attribute=some-layout-string





Determines how to handle class file attributes that are not recognized by the
    packer. The possible values for some-layout-string are
    error, strip, pass.
    
some-layout-string: El lenguaje de diseño se define en
        la especificación JSR 200, por ejemplo:
        --class-attribute=SourceFile=RUH.

    
Si el valor es error, la operación pack200
        falla con una explicación.

    
Si el valor es strip, el atributo se elimina
        de la salida. La eliminación de atributos requeridos por la JVM puede causar
        fallos en el cargador de clases. Por ejemplo,
        --class-attribute=CompilationID=pass hace que el archivo de
        clase que contiene este atributo se transmita sin más acción por parte del
        empaquetador.

    
Si el valor es pass, la clase completa se
        transmite como si fuera un recurso.

  

  
-f pack.properties ,
    --config-file=pack.properties

  

    

    Se puede especificar un archivo de configuración, que contiene propiedades
      de Java para inicializar el empaquetador, en la línea de comandos.
        
pack200 -f pack.properties myarchive.pack.gz myarchive.jar

    
more pack.properties

    
# Propiedades genéricas para el empaquetador.

    
modification.time=latest

    
deflate.hint=false

    
keep.file.order=false

    
# Esta opción hará que los archivos que contengan nuevos atributos sean

    
# reportados como un error en lugar de pasarlos sin comprimir.

    
unknown.attribute=error

    
# Cambiar el límite del segmento a ilimitado.

    
segment.limit=-1

    Imprime información de versión sobre este comando.

  
-Joption

  

    

    Pasa la opción especificada a la Máquina Virtual Java. Para más
      información, consulta la página de referencia del comando java(1). Por ejemplo,
      -J-Xms48m establece la memoria de inicio en 48 MB.








ESTADO DE SALIDA


Los siguientes valores de salida se devuelven: 0 para una
    finalización exitosa y un número mayor que 0 cuando ocurre un error.






NOTAS


Este comando no debe confundirse con pack(1).
    Los comandos pack y pack200 son productos separados.


La Especificación de la API de Java SE proporcionada con el JDK es la
    autoridad que prevalece, en caso de discrepancias.
