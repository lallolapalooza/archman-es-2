par2(1) Utilidades de archivo de paridad par2(1)

NOMBRE

par2 - Herramienta de verificación y reparación de archivos compatible con PAR 2.0.

SINOPSIS

par2 c|v|r [opciones] <archivo PAR2> [archivos]

par2 c(rear) [opciones] <archivo PAR2> [archivos]
par2 v(erify) [opciones] <archivo PAR2> [archivos]
par2 r(epair) [opciones] <archivo PAR2> [archivos]

También:


par2create [opciones] <archivo PAR2> [archivos]
par2verify [opciones] <archivo PAR2> [archivos]
par2repair [opciones] <archivo PAR2> [archivos]

DESCRIPCIÓN

par2cmdline es un programa para crear y usar archivos PAR2 para detectar daños en archivos de datos y repararlos si es necesario. Se puede utilizar con cualquier tipo de archivo.

OPCIONES

-h
Mostrar esta ayuda
-V
Mostrar versión
-VV
Mostrar versión y derechos de autor
-a <archivo>
Establecer el nombre del archivo principal de PAR2; requerido en la creación, opcional para verificar y reparar
-b<n>
Establecer el número de bloques
-s<n>
Establecer el tamaño del bloque (no usar ambos -b y -s)
-r<n>
Nivel de redundancia (porcentaje)
-r<c><n>
Tamaño objetivo de redundancia, <c>=g(iga),m(ega),k(ilo) bytes
-c<n>
Número de bloques de recuperación (no usar ambos -r y -c)
-f<n>
Número del primer bloque de recuperación
-u
Tamaños de archivo de recuperación uniformes
-l
Limitar el tamaño de los archivos de recuperación (no usar ambos -u y -l)
-n<n>
Número de archivos de recuperación (máx. 31) (no usar ambos -n y -l)
-m<n>
Memoria (en MB) a usar
-t<n>
Número de hilos utilizados para el procesamiento principal (auto-detectado)
-T<n>
Número de archivos procesados en paralelo (durante las etapas de verificación y creación de archivos, 2 por defecto)
-v [-v]
Ser más verboso
-q [-q]
Ser más silencioso (-qq silencia completamente)
-p
Eliminar archivos de respaldo y archivos par en caso de recuperación exitosa o cuando no se necesita recuperación
-R
Recorrer subdirectorios (solo útil al crear)
-N
Omisión de datos (encontrar bloques de datos mal posicionados)
-S<n>
Margen de omisión (distancia +/- desde la posición esperada del bloque)
-B<ruta>
Establecer la ruta base a utilizar como referencia para los archivos de datos
--
Tratar todos los argumentos siguientes como nombres de archivo

CÓDIGOS DE SALIDA

0
El proceso se completó con éxito
1
La reparación es posible, hay suficientes bloques de recuperación
2
La reparación *NO* es posible, hay insuficientes bloques de recuperación
3
La combinación de flags de línea de comandos dada es inválida
4
Datos críticos insuficientes, probablemente sus archivos par están corruptos
5
La reparación se completó, pero los archivos de datos siguen estando corruptos
6
Algún error de E/S de archivo al acceder a él
7
Ocurrió un error de lógica interna
8
Falta de memoria u otro error de memoria

EJEMPLOS

Con PAR 2.0 puede crear archivos de recuperación PAR2 para tan solo 1 o hasta 32768 archivos. Si quisiera crear archivos de recuperación PAR1 para un solo archivo, se vería obligado a dividir el archivo en varias partes y RAR se usa frecuentemente para este propósito. Usted NO necesita dividir archivos con PAR 2.0.

Para crear archivos de recuperación PAR 2 para un solo archivo de datos (por ejemplo, uno llamado test.mpg), puede usar el siguiente comando:


par2 create test.mpg

Si test.mpg es un archivo de 800 MB, esto creará un total de 8 archivos PAR2 con los siguientes nombres de archivo (tomando aproximadamente 6 minutos en una PC con una CPU de 1500MHz):


test.mpg.par2 - Este es un archivo de índice solo para verificación
test.mpg.vol00+01.par2 - Archivo de recuperación con 1 bloque de recuperación
test.mpg.vol01+02.par2 - Archivo de recuperación con 2 bloques de recuperación
test.mpg.vol03+04.par2 - Archivo de recuperación con 4 bloques de recuperación
test.mpg.vol07+08.par2 - Archivo de recuperación con 8 bloques de recuperación
test.mpg.vol15+16.par2 - Archivo de recuperación con 16 bloques de recuperación
test.mpg.vol31+32.par2 - Archivo de recuperación con 32 bloques de recuperación
test.mpg.vol63+37.par2 - Archivo de recuperación con 37 bloques de recuperación

El archivo test.mpg.par2 tiene un tamaño de 39 KB y los otros archivos varían en tamaño desde 443 KB hasta 15 MB. Estos archivos par2 permitirán la recuperación de hasta 100 errores que suman 40 MB de datos perdidos o dañados del archivo test.mpg original cuando este y los archivos par2 se publiquen en UseNet. Al publicar en UseNet se recomienda usar la opción "-s" para establecer un tamaño de bloque igual al tamaño del artículo que utilizará para publicar el archivo de datos. Si quisiera publicar el archivo test.mpg usando un tamaño de artículo de 300 KB, el comando que escribiría es:


par2 create -s307200 test.mpg

Esto creará 9 archivos PAR2 en lugar de 8, y serán capaces de corregir hasta 134 errores que suman 40 MB. Tomará aproximadamente 8 minutos crear los archivos de recuperación esta vez. En ambos ejemplos, la cantidad total de datos de recuperación creados fue de 40 MB (que es el 5% de 800 MB). Si desea crear una mayor o menor cantidad de datos de recuperación, puede usar la opción "-r". Para crear un 10% de datos de recuperación en lugar del 5% predeterminado y también para usar un tamaño de bloque de 300 KB, usaría el siguiente comando:


par2 create -s307200 -r10 test.mpg

Esto crearía 9 archivos PAR2, pero podrían corregir hasta 269 errores que suman 80 MB. Como se crea el doble de datos de recuperación, tardará unos 16 minutos en hacerlo con una CPU de 1500 MHz. Las opciones "-u" y "-n" se pueden usar para controlar exactamente cuántos archivos de recuperación se crean y cómo se distribuyen los bloques de recuperación entre ellos. No afectan la cantidad total de datos de recuperación creados. La opción "-f" se usa cuando crea datos de recuperación adicionales. Por ejemplo, si ya ha creado el 10% y desea otro 5%, podría usar el siguiente comando:


par2 create -s307200 -r5 -f300 test.mpg

Esto especifica el mismo tamaño de bloque (que es un requisito para archivos de recuperación adicionales), 5% de datos de recuperación y un número de primer bloque de 300.

La opción "-m" controla cuánta memoria utiliza par2. Por defecto es 16 MB a menos que la anule.

CREACIÓN DE ARCHIVOS PAR2 PARA MÚLTIPLES ARCHIVOS DE DATOS

Al crear archivos de recuperación PAR2 para múltiples archivos de datos, debe especificar el nombre base del archivo a usar para los archivos par2 y los nombres de todos los archivos de datos. Si test.mpg se hubiera dividido en múltiples archivos RAR, podría usar:


par2 create test.mpg.rar.par2 test.mpg.part*.rar

El nombre de archivo "test.mpg.rar.par2" indica cómo quiere que se llamen los archivos par2 y "test.mpg.part*.rar" debería seleccionar todos los archivos RAR.

Con "-R" también puede crear archivos de recuperación para una estructura de árbol de múltiples capas.


.
├── aaaa-test.data
├── subdir1
│   └── test-0.data
├── subdir2
│   ├── test-1.data
│   ├── test-2.data
│   ├── test-3.data
│   ├── test-4.data
│   ├── test-5.data
│   ├── test-6.data
│   ├── test-7.data
│   ├── test-8.data
│   └── test-9.data
└── test-a.data


par2 create -R recovery.par2 *

Resultará en:


.
├── aaaa-test.data
├── recovery.par2
├── recovery.vol000+01.par2
├── recovery.vol001+02.par2
├── recovery.vol003+04.par2
├── recovery.vol007+08.par2
├── recovery.vol015+16.par2
├── recovery.vol031+32.par2
├── recovery.vol063+37.par2
├── subdir1
│   └── test-0.data
├── subdir2
│   ├── test-1.data
│   ├── test-2.data
│   ├── test-3.data
│   ├── test-4.data
│   ├── test-5.data
│   ├── test-6.data
│   ├── test-7.data
│   ├── test-8.data
│   └── test-9.data
└── test-a.data

ADVERTENCIA: Tenga cuidado con la expansión de comodines del shell. Una vez que pase más de un argumento sin nombre, el primero se utilizará como nombre de los archivos par2 y no estará cubierto por ellos.

VERIFICACIÓN Y REPARACIÓN

Al usar los archivos de recuperación par2 para verificar o reparar los archivos de datos de los que fueron creados, solo necesita especificar el nombre de archivo de uno de los archivos par2 para par2. Por ejemplo:


par2 verify test.mpg.par2

Esto le dice a par2 que use la información en test.mpg.par2 para verificar los archivos de datos. Par2 buscará automáticamente los otros archivos par2 que se crearon y usará la información que contienen para determinar los nombres de archivo de los archivos de datos originales y luego para verificarlos. Si todos los archivos de datos están bien, par2 informará que la reparación no será necesaria. Si faltan o están dañados algunos de los archivos de datos, par2 informará los detalles de lo que ha encontrado. Si los archivos de recuperación contienen suficientes bloques de recuperación para reparar el daño, se le informará que la reparación es posible. De lo contrario, se le informará exactamente cuántos bloques de recuperación se requerirán para reparar. Para realizar una reparación, use el siguiente comando:


par2 repair test.mpg.par2

Esto le dice a par2 que verifique y, si es posible, repare cualquier archivo dañado o faltante. Si se realiza una reparación, cada archivo que se repare se volverá a verificar para confirmar que la reparación fue exitosa.

ARCHIVOS DE DATOS CON NOMBRE INCORRECTO O INCOMPLETOS

Si alguno de los archivos de recuperación o de datos tiene el nombre de archivo incorrecto, par2 no los encontrará y escaneará automáticamente. Para que par2 escanee dichos archivos, debe incluirlos en la línea de comandos al intentar verificar o reparar; por ejemplo:


par2 r test.mpg.par2 other.mpg

Esto le dice a par2 que escanee el archivo llamado other.mpg para ver si contiene algún dato perteneciente a los archivos de datos originales. Si uno de los archivos adicionales especificados de esta manera es una coincidencia exacta para un archivo de datos, el proceso de reparación renombrará el archivo para que tenga el nombre de archivo correcto. Debido a que par2 está diseñado para poder encontrar datos buenos dentro de un archivo dañado, puede hacer lo mismo con archivos incompletos descargados de UseNet. Si faltan algunos de los artículos de un archivo, aún debe descargar el archivo y guardarlo en el disco para que par2 lo escanee. Si hace esto, es posible que pueda realizar una reparación en una situación en la que de otro modo no tendría suficientes datos de recuperación. Puede hacer que par2 escanee todos los archivos que se encuentran en el directorio actual utilizando un comando como:


par2 r test.mpg.par2 *

QUÉ HACER CUANDO SE LE INFORMA QUE NECESITA MÁS BLOQUES DE RECUPERACIÓN

Si par2 determina que alguno de los archivos de datos está dañado o faltante y descubre que hay datos de recuperación insuficientes para efectuar una reparación, se le informará que necesita un cierto número de bloques de recuperación. Puede obtenerlos descargando archivos de recuperación adicionales. Para facilitar las cosas, los archivos par2 tienen nombres de archivo que le indican exactamente cuántos bloques de recuperación contiene cada uno. Suponiendo que se utilizó el siguiente comando para crear datos de recuperación:


par2 c -b1000 -r5 test.mpg

Entonces los archivos de recuperación que se crearán se llamarán:


test.mpg.par2
test.mpg.vol00+01.par2
test.mpg.vol01+02.par2
test.mpg.vol03+04.par2
test.mpg.vol07+08.par2
test.mpg.vol15+16.par2
test.mpg.vol31+19.par2

El primer archivo de esta lista no contiene ningún dato de recuperación, solo contiene información suficiente para verificar los archivos de datos. Cada uno de los otros archivos contiene un número diferente de bloques de recuperación. El número después del signo '+' es el número de bloques de recuperación y el número que precede al signo '+' es el número de bloque del primer bloque de recuperación en ese archivo. Si par2 le informó que necesitaba 10 bloques de recuperación, entonces necesitaría "test.mpg.vol01+02.par2" y "test.mpg.vol07+08.par". Por supuesto, podría optar por obtener "test.mpg.vol15+16.par2" en su lugar (en cuyo caso tendría 6 bloques de recuperación adicionales que no se utilizarían para la reparación).

HASHING

La parte de hashing (etapas de verificación y creación de archivos) del código no se puede paralelizar sin procesar varios archivos simultáneamente. El valor predeterminado de 2 archivos/hilo es una buena opción para los HDD, usar más hilos puede resultar en un peor rendimiento. Se pueden usar cuatro o más hilos para un mejor rendimiento con SSD.
