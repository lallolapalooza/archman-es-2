PAXCPIO(1) Manual de comandos generales PAXCPIO(1)

NOMBRE

paxcpio — copiar archivos de y hacia archivos

SINOPSIS

paxcpio -o [-0AaBcJjLVvZz] [-C bytes] [-F archivo] [-H formato] [-M indicador] [-O archivo] < lista-nombres [> archivo]

paxcpio -i [-06BbcdfJjmrSstuVvZz] [-C bytes] [-E archivo] [-F archivo] [-H formato] [-I archivo] [-M indicador] [patrón ...] [< archivo]

paxcpio -p [-0adLlmuVv] directorio-destino < lista-nombres

DESCRIPCIÓN

paxcpio es un comando que copia archivos hacia y desde un archivo cpio.

Las opciones son las siguientes:

-0
Usa el carácter NULO (‘\0’) como terminador de nombre de ruta, en lugar de un salto de línea (‘\n’). Esto se aplica solo a los nombres de ruta leídos desde la entrada estándar en los modos de escritura y copia, y a los nombres de ruta escritos en la salida estándar en modo de listado. Se espera que esta opción se use junto con la función -print0 de find(1), la opción -d '' para la utilidad interna read de mksh(1) o la bandera -0 en xargs(1).
-o
Crea un archivo. Lee la lista de archivos a almacenar en el archivo desde la entrada estándar, y escribe el archivo en la salida estándar.
-A
Añade al archivo especificado.
-a
Restablece los tiempos de acceso de los archivos que han sido copiados al archivo.
-B
Establece el tamaño de bloque de salida a 5120 bytes.
-C bytes
Establece el tamaño de bloque de salida a bytes.
-c
Usa formato ASCII para la cabecera cpio para portabilidad.
-F archivo
Usa el archivo especificado como entrada para el archivo.
-H formato
Escribe el archivo en el formato especificado. Los formatos reconocidos son:
ar
Archiver de Unix.
bcpio
Formato binario antiguo de cpio. Seleccionado por -6.
cpio
Formato de carácter octal antiguo de cpio. Seleccionado por -c.
sv4cpio
Formato cpio hexadecimal SVR4.
sv4crc
Formato cpio hexadecimal SVR4 con sumas de verificación. Este es el formato predeterminado para crear archivos nuevos.
tar
Formato tar antiguo.
ustar
Formato POSIX ustar.

-J
Usa la utilidad xz para comprimir el archivo.
-j
Usa la utilidad bzip2 para comprimir el archivo.
-L
Sigue los enlaces simbólicos.
-M indicador
Configura el normalizador de archivos. indicador es un valor numérico compatible con strtonum(3) que se almacena directamente en la palabra de indicadores, o uno de los siguientes valores, opcionalmente prefijado con “no-” para desactivarlos:
inodes
0x0001: Serializa los inodos, información del dispositivo cero.
(cpio, sv4cpio, sv4crc)
links
0x0002: Almacena el contenido de los enlaces duros solo una vez.
(cpio, sv4cpio, sv4crc)
mtime
0x0004: Pone a cero la hora de modificación del archivo.
(ar, cpio, sv4cpio, sv4crc, ustar)
uidgid
0x0008: Establece el propietario a 0:0 (root:wheel).
(ar, cpio, sv4cpio, sv4crc, ustar)
verb
0x0010: Depura esta opción.
(ar, cpio, sv4cpio, sv4crc, ustar)
debug
0x0020: Depura el almacenamiento de la cabecera del archivo.
(ar, cpio, sv4cpio, sv4crc, ustar)
lncp
0x0040: Extrae enlaces duros por copia si falla el enlace.
(ar, cpio, sv4cpio, sv4crc, ustar)
numid
0x0080: Usa solo valores numéricos de uid y gid.
(ustar)
gslash
0x0100: Añade una barra después de los nombres de directorio.
(ustar)
set
0x0003: Mantiene la propiedad y el mtime intactos.
dist
0x008B: Limpia todo excepto mtime.
norm
0x008F: Limpia todo.
root
0x0089: Limpia la información del propietario y del dispositivo.

Al crear un archivo y listar la salida detalladamente, estas operaciones de normalización no se reflejan en la salida, ya que se realizan solo después de que la salida ha sido mostrada.

Esta opción solo está implementada para las rutinas de escritura de los formatos de archivo ar, cpio, sv4cpio, sv4crc y ustar.

-O archivo
Usa el nombre de archivo especificado como el archivo al que escribir.
-V
Imprime un punto (‘.’) por cada archivo escrito en el archivo.
-v
Sé detallado sobre las operaciones. Lista los nombres de archivo a medida que se escriben en el archivo.
-Z

-z

-i

-6

-b

-d

-E archivo

-e

-H formato
Lee el archivo en el formato especificado. Consulte la opción -H en el modo de escritura.
-I archivo
Usa el nombre de archivo especificado como el archivo a leer.
-J
Usa la utilidad xz para descomprimir el archivo.
-j
Usa la utilidad bzip2 para descomprimir el archivo.
-m
No restaura los permisos de archivo.
-r
Extrae recursivamente los archivos en los directorios especificados.
-S

-s
Ignora los archivos que no se pueden leer.
-t

-u
No restaura la propiedad de los archivos.
-V
Imprime un punto (‘.’) por cada archivo extraído del archivo.
-v

-Z
Usa la utilidad compress(1) para descomprimir el archivo.
-z
Usa la utilidad gzip para descomprimir el archivo.
-p
Copia archivos de un archivo a un directorio. Lee la lista de archivos a copiar desde la entrada estándar y los copia al directorio de destino.
-a
Preserva todos los atributos de archivo, incluyendo permisos, propiedad y tiempos de modificación.
-d
Crea los directorios que sean necesarios.
-l
Copia los enlaces simbólicos como archivos regulares.
-m
Preserva solo los tiempos de modificación de archivo.
-u
Copia archivos solo si son más recientes que los archivos de destino.
-V
Imprime un punto (‘.’) por cada archivo copiado al directorio de destino.
-v
Sé detallado sobre las operaciones. Lista los nombres de archivo a medida que se copian al directorio de destino.
-z
Usa la utilidad gzip(1) para comprimir el archivo.
-i

-6

-B

-b

-c

-d

ENTORNO

TMPDIR
Ruta en la que almacenar archivos temporales.

ESTADO DE SALIDA

La utilidad paxcpio sale con uno de los siguientes valores:

0
Todos los archivos se procesaron correctamente.
1
Ocurrió un error.

DIAGNÓSTICOS

Siempre que paxcpio no pueda crear un archivo o un enlace al extraer un archivo o no pueda encontrar un archivo al escribir un archivo, o no pueda preservar el ID de usuario, ID de grupo, modo de archivo o tiempos de acceso y modificación cuando se especifica la opción -p, se escribirá un mensaje de diagnóstico en el error estándar y se devolverá un valor de salida distinto de cero, pero el procesamiento continuará. En el caso en que paxcpio no pueda crear un enlace a un archivo, a menos que se proporcione -M lncp, paxcpio no creará una segunda copia del archivo.

Si la extracción de un archivo desde un archivo se interrumpe prematuramente por una señal o un error, paxcpio puede haber extraído solo parcialmente el archivo que el usuario deseaba. Además, los modos de archivo de los archivos y directorios extraídos pueden tener bits de archivo incorrectos, y los tiempos de modificación y acceso pueden estar mal.

Si la creación de un archivo se interrumpe prematuramente por una señal o un error, paxcpio puede haber creado solo parcialmente el archivo, lo que puede violar la especificación del formato de archivo específico.

ADVERTENCIAS

Los diferentes formatos de archivo tienen diferentes tamaños máximos de archivo. Se recomienda utilizar un formato como cpio o ustar para archivos más grandes.

Formato de archivo Tamaño máximo de archivo
ar 10 Gigabytes - 1 Byte
bcpio 4 Gibibytes
sv4cpio 4 Gibibytes
sv4crc 4 Gibibytes
cpio 8 Gibibytes
tar 8 Gibibytes
ustar 8 Gibibytes

Las opciones de formato compatibles hacia atrás no están disponibles en el frontend pax(1).

La opción -M es una extensión de MirBSD, disponible a partir de Los archivos escritos usando estas opciones son, sin embargo, compatibles con el estándar y deberían ser legibles en cualquier otro sistema. La única opción cuyo comportamiento no está explícitamente permitido por el estándar es la unificación de enlaces duros (escribir el contenido del archivo solo una vez) seleccionada por -M 0x0002.

La opción -V es una extensión de GNU, disponible a partir de

CAVEATS

El formato de archivo ar coincide con los repositorios APT y la especificación ar(1) de BSD, no con GNU binutils (que sin embargo pueden leerlos) ni con sistemas SYSV.

BUGS

Las opciones -s y -S no están implementadas actualmente.

El formato de archivo pax aún no es compatible.
