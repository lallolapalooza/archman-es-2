NOMBRE

pam_listfile - deniega o permite servicios basándose en un archivo arbitrario

SINOPSIS

pam_listfile.so item=[tty|user|rhost|ruser|group|shell] sense=[allow|deny] file=/ruta/nombre_archivo onerr=[succeed|fail] [apply=[user|@group]] [quiet]

DESCRIPCIÓN

pam_listfile es un módulo PAM que proporciona una forma de denegar o permitir servicios basándose en un archivo arbitrario.

El módulo obtiene el item del tipo especificado -- user especifica el nombre de usuario, PAM_USER; tty especifica el nombre del terminal (si lo hay) a través del cual se ha realizado la solicitud, PAM_TTY; rhost especifica el nombre del host remoto (si lo hay) desde el que se realizó la solicitud, PAM_RHOST; y ruser especifica el nombre del usuario remoto (si está disponible) que realizó la solicitud, PAM_RUSER -- y busca una instancia de ese ítem en el file=nombre_archivo. nombre_archivo contiene una línea por ítem listado. Si se encuentra el ítem, y si sense=allow, se devuelve PAM_SUCCESS, lo que hace que la solicitud de autorización sea exitosa; de lo contrario, si sense=deny, se devuelve PAM_AUTH_ERR, lo que hace que la solicitud de autorización falle.

Si se encuentra un error (por ejemplo, si nombre_archivo no existe, o se encuentra un argumento mal construido), entonces si onerr=succeed, se devuelve PAM_SUCCESS, de lo contrario, si onerr=fail, se devolverá PAM_AUTH_ERR o PAM_SERVICE_ERR (según corresponda).

Se puede usar un argumento adicional, apply=, para restringir la aplicación de lo anterior a un usuario específico (apply=nombre_usuario) o a un grupo dado (apply=@nombre_grupo). Esta restricción adicional solo tiene sentido cuando se usa con los ítems tty, rhost y shell.

Aparte de este último, todos los argumentos deben especificarse; no cuente con ningún comportamiento predeterminado.

Este módulo no otorga credenciales.

OPCIONES

item=[tty|user|rhost|ruser|group|shell]

Lo que está listado en el archivo y se debe verificar.

sense=[allow|deny]

Acción a tomar si el ítem se encuentra en el archivo. Si el ítem NO se encuentra en el archivo, entonces se solicita la acción opuesta.

file=/ruta/nombre_archivo

Archivo que contiene un ítem por línea. El archivo debe ser un archivo plano y no escribible por todos.

onerr=[succeed|fail]

Qué hacer si ocurre algo extraño, como no poder abrir el archivo.

apply=[user|@group]

Restringe la clase de usuario para la que aplica la restricción. Tenga en cuenta que con item=[user|ruser|group] esto no tiene sentido, pero para item=[tty|rhost|shell] tiene un significado.

quiet

No trate las denegaciones de servicio o los archivos de lista faltantes como errores que necesiten ser registrados.

TIPOS DE MÓDULO PROPORCIONADOS

Se proporcionan todos los tipos de módulo (auth, account, password y session).

VALORES DE RETORNO

PAM_AUTH_ERR

Error de autenticación.

PAM_BUF_ERR

Error de búfer de memoria.

PAM_IGNORE

La regla no se aplica a la opción apply.

PAM_SERVICE_ERR

Error en el módulo de servicio.

PAM_SUCCESS

Éxito.

EJEMPLOS

La autenticación clásica de 'ftpusers' se puede implementar con esta entrada en /etc/pam.d/ftpd:

#
# deniega el acceso ftp a los usuarios listados en el archivo /etc/ftpusers
#
auth    required       pam_listfile.so \
        onerr=succeed item=user sense=deny file=/etc/ftpusers

Tenga en cuenta que los usuarios listados en el archivo /etc/ftpusers (contraintuitivamente) *no* tienen permitido el acceso al servicio ftp.

Para permitir el acceso de inicio de sesión solo a ciertos usuarios, puede usar una entrada /etc/pam.d/login como esta:

#
# permite el inicio de sesión a los usuarios listados en /etc/loginusers
#
auth    required       pam_listfile.so \
        onerr=fail item=user sense=allow file=/etc/loginusers

Para que este ejemplo funcione, todos los usuarios a los que se les permita usar el servicio de inicio de sesión deben estar listados en el archivo /etc/loginusers. A menos que esté intentando explícitamente bloquear a root, asegúrese de que cuando haga esto, deje una forma para que root inicie sesión, ya sea listando root en /etc/loginusers, o listando un usuario que pueda hacer su a la cuenta root.
