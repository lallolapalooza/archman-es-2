PACUTILS-SYSROOT(7) pacutils-sysroot PACUTILS-SYSROOT(7)

NOMBRE

pacutils-sysroot - gestión de un sistema invitado montado

DESCRIPCIÓN

Gestión de invitados con --root

Cuando una instalación basada en libalpm se rompe hasta el punto en que el propio gestor de paquetes ya no se puede utilizar, debe arreglarse cargando un entorno de trabajo y montando la instalación que necesita reparación como invitado. Normalmente esto se hace estableciendo la raíz de la instalación al invitado con la opción --root. Libalpm solo usa la raíz de la instalación para determinar dónde instalar y eliminar archivos durante las transacciones de paquetes. Es completamente independiente de todas las demás opciones de configuración. ¡Esto hace que usar --root no sea fiable para gestionar un invitado montado!

El primer problema es que al cambiar la raíz de la instalación, todavía se utiliza la configuración del sistema anfitrión. Dado que la raíz de la instalación es una opción de configuración ("RootDir") no se puede usar para cargar un archivo de configuración alternativo. Incluso si se añade --config para cargar la configuración del invitado, cualquier ruta "Include"'d todavía se resolverá en relación con la raíz del anfitrión. La única forma de utilizar realmente la configuración del invitado sin usar "chroot" es usar --config y añadir manualmente la ruta de montaje a todas las rutas "Include".

Ahora se utilizan los archivos de configuración del invitado, pero todas las rutas configuradas seguirán refiriéndose a rutas bajo la raíz del anfitrión, no a las del invitado. Si se proporciona explícitamente una raíz de instalación, pacman y pacutils establecerán valores predeterminados para algunas, pero no todas, las rutas de configuración para que estén debajo de ella. Esto generalmente funciona, porque esas rutas rara vez se establecen explícitamente, por lo que los valores predeterminados generalmente hacen lo correcto. Sin embargo, si se han establecido, se utilizarán los valores configurados sin modificaciones. Para operar de manera fiable en el invitado, todas las rutas de configuración deben establecerse en relación con la raíz de la instalación (excepto las rutas de la base de datos y el archivo de registro que, si no están definidas, se establecerán por defecto en rutas dentro de la raíz de la instalación).

Introducción del Sysroot

Esto es una gran cantidad de trabajo solo para poder operar en un sistema montado. Para permitir la operación fiable en un invitado montado, pacman y pacutils han añadido el concepto de un "sysroot". El sysroot es lo que comúnmente se pretende al usar la opción --root; el programa operará como si el sysroot fuera realmente la raíz del sistema de archivos. Esto es similar a usar "chroot" para entrar en el sistema montado antes de ejecutar el programa, pero aún ejecuta la copia del anfitrión. Hay dos maneras de hacer esto: chroot al sysroot poco después de iniciar la lectura de cualquier configuración o anteponer el sysroot a todas las rutas.

Usar "chroot" directamente puede causar problemas con bibliotecas que usan carga retardada de archivos de configuración u objetos compartidos. Notablemente, glibc retrasa la carga de ciertos objetos hasta que su funcionalidad se utiliza realmente. Esto puede causar una discrepancia entre los componentes cargados antes del "chroot" y los cargados después. Para evitar este problema, libalpm generalmente debe configurarse para usar rutas bajo el sysroot sin llamar realmente a "chroot".

Pacutils proporciona versiones conscientes del sysroot de sus funciones de análisis de configuración para simplificar el proceso. Tenga en cuenta que el sysroot se antepone a todas las rutas durante la resolución de la configuración. Los programas que utilizan las rutinas de análisis de configuración del sysroot NO deben anteponer el sysroot a las rutas de configuración proporcionadas en la línea de comandos.

EJEMPLOS

#include <alpm.h>
#include <getopt.h>
#include <pacutils.h>
enum {
       FLAG_CONFIG = 1,
       FLAG_SYSROOT,
};
int main(int argc, char *argv[]) {
 const char *config_file = "/etc/pacman.conf";
 const char *sysroot = NULL;
       alpm_handle_t *handle = NULL;
       pu_config_t *config = NULL;
       struct option long_opts[] = {
               { "config"        , required_argument , NULL    , FLAG_CONFIG        } ,
               { "sysroot"       , required_argument , NULL    , FLAG_SYSROOT       } ,
               { 0, 0, 0, 0 },
       };
       while((c = getopt_long(argc, argv, short_opts, long_opts, NULL)) != -1) {
               switch(c) {
                       case FLAG_CONFIG: config_file = optarg; break;
                       case FLAG_SYSROOT: sysroot = optarg; break;
                       case '?': return 1; /* getopt_long ya imprimió un mensaje de error */
               }
       }
       if((config = pu_ui_config_load_sysroot(NULL, config_file, sysroot)) == NULL)
               { return 1; } /* load_sysroot ya imprimió un mensaje de error */
       if(!(handle = pu_initialize_handle_from_config(config))) {
               fprintf(stderr, "error: fallo al inicializar alpm.\n");
               return 1;
       }
       puts(alpm_option_get_root(handle));
       pu_config_free(config);
       alpm_release(handle);
       return 0;
}
