Nombre

pam_mount.conf - Descripción del archivo de configuración de pam_mount

Vista general

El archivo de configuración de pam_mount define valores predeterminados suaves para los comandos que pam_mount ejecutará, los mensajes que mostrará y los volúmenes que montará al iniciar sesión. Desde pam_mount 0.18, el archivo de configuración está escrito en XML para simplificar la base de código de pam_mount, al tiempo que se otorga libertad de formato al usuario final. Los caracteres especiales como <, > y & que son utilizados por el propio XML deben codificarse como &lt;, &gt; y &amp;, respectivamente; además, " debe codificarse como &quot; dentro de un área de "", pero es poco probable que estos tres/cuatro símbolos se vean con frecuencia.

No utilice comentarios dentro de elementos que tomen texto literal, como <fusermount></fusermount> - esto no es manejado por el analizador de árboles XML de pam_mount.

Definiciones de volumen

Los volúmenes se definen con el elemento <volume>, que principalmente toma los parámetros como atributos, como:

<volume user="joe" fstype="nfs" server="fsbox" path="/home/%(USER)" mountpoint="/bigdisk/%(USER)" />

y definen qué montar, para quién y cómo. Hay muchos parámetros ajustables, que se describen en esta sección.

Control simple de usuario

Los siguientes atributos controlan si el volumen se montará una vez que el usuario inicie sesión. Por defecto, los volúmenes se aplican a todos los usuarios, y la especificación de atributos los limita a las condiciones dadas, es decir, se combinan lógicamente. Existe un mecanismo más potente y detallado para especificar condiciones complejas, descrito más adelante en la sección "Control extendido de usuario".

user="nombredeusuario"
Limita el volumen al usuario especificado, identificado por nombre.
uid="número" o uid="número-número"
Limita el volumen a los usuarios especificados, identificados por UID o rango de UID.
pgrp="nombredegrupo"
Limita el volumen a los usuarios que tienen el grupo identificado por nombre como su grupo principal.
gid="número" o gid="número-número"
Limita el volumen a los usuarios que tienen el(los) grupo(s) dados por GID o rango de GID como grupo principal.
sgrp="nombredegrupo"
Limita el volumen a los usuarios que son miembros del grupo identificado por nombre (ya sea como grupo principal o secundario).

Configuración del volumen

Los siguientes atributos seleccionan la fuente, el destino, las opciones, etc., del volumen.

fstype="tipo"
El tipo de sistema de archivos, que puede ser cualquier cosa que su kernel, espacio de usuario y pam_mount entiendan. Si fstype especifica un tipo especial de pam_mount, pam_mount lo manejará. De lo contrario, fstype se pasa a mount(8), que luego busca un ayudante en el espacio de usuario /sbin/mount.fstype y lo ejecuta si existe, y en cualquier otro caso, mount(8) llamaría a mount(2) para que el kernel lo monte directamente. mount(8) conoce un tipo de sistema de archivos auto, que puede ser útil en algunos casos. No especificar el atributo fstype implica fstype="auto". Tenga en cuenta que el montaje con auto puede fallar si el módulo del kernel del sistema de archivos aún no está cargado, ya que mount(8) verificará /proc/partitions.
Los tipos de sistema de archivos cifs, smbfs, ncpfs, fuse, nfs y nfs4 son anulados por pam_mount y ejecutamos los programas auxiliares correspondientes directamente en lugar de invocar mount(8) con el conjunto básico de argumentos predeterminados que a menudo son insuficientes para los sistemas de archivos en red. Consulte la sección "Ejemplos" de esta página del manual a continuación para obtener más detalles.
noroot="1"
Llama al programa de montaje sin privilegios de root. Por defecto es sí para el tipo de sistema de archivos fuse, porque los volúmenes FUSE deben montarse como el usuario que inicia sesión para obtener acceso a los archivos por defecto.
server="nombre"
Define el servidor al que conectarse en caso de los tipos de sistema de archivos cifs, smbfs y ncpfs y nfs. Para todos los demás tipos de sistemas de archivos, este atributo se ignora. También puede especificar el servidor en el atributo path en su lugar, pero debe cumplir con la sintaxis específica que requiere un tipo de sistema de archivos particular. (Por ejemplo, CIFS usa "//servidor/ruta", mientras que NFS usa "servidor:ruta", etc.)
path="ruta"
Este atributo obligatorio especifica la ubicación del volumen, relativa al servidor (si se especifica).
mountpoint="directorio"
Esto especifica el directorio de destino en el que se monta el volumen. "~" se expande al directorio de inicio del usuario tal como está presente en la base de datos de contraseñas, de acuerdo con la semántica de sh. "~nombre" no es compatible. Si se omite este atributo, la ubicación se lee de /etc/fstab, lo que también requiere que path sea un dispositivo o un directorio de origen de una entrada de fstab.
header="ruta"
Esto especifica un archivo de metadatos separado (desconectado) donde se almacena la cabecera LUKS. Esto se correlaciona con la opción `cryptsetup --header`. Si se omite este atributo, no se utiliza la característica de cabecera LUKS desconectada.
options="..."
Especifica las opciones de montaje. Si se omite y se utiliza /etc/fstab (ver mountpoint), las opciones también se obtendrán de fstab.
ssh="0" o ssh="1"
La opción ssh habilita un envoltorio de hackeo de entrada (zerossh, ver fd0ssh(1)) para este volumen para pasar la contraseña a ssh a través de un mecanismo específico de ssh. Habilite esta opción para cualquier montaje que involucre el binario SSH, por ejemplo, ccgfs o sshfs. No la habilite para nada más o es muy probable que el inicio de sesión se bloquee.
empty_pass="0" o empty_pass="1"
La opción empty_pass controla el comportamiento cuando se proporciona una contraseña vacía o cuando no se dispone de una contraseña. El valor predeterminado de true intentará desbloquear un volumen con una clave de cadena vacía si no hay contraseña disponible. Cuando empty_pass es false, pam_mount no intentará montar el volumen a menos que haya una contraseña no vacía disponible.
cipher="cifrado"
Nombre del cifrado de cryptsetup para el volumen. Para ser utilizado con el tipo de sistema de archivos crypt.
fskeycipher="tipodecifrado"
Nombre del cifrado de OpenSSL para la clave del sistema de archivos (fskey). Úselo con el tipo de sistema de archivos crypt (dm-crypt y LUKS). El nombre especial de cifrado "none" puede usarse para pasar directamente el contenido del archivo a cryptsetup sin descifrado por OpenSSL.
fskeyhash="hash"
Nombre del hash de OpenSSL para la clave del sistema de archivos (fskey).
fskeypath="ruta"
Ruta a la clave del sistema de archivos (fskey). ignoresource="1" Ignora la ruta de origen al verificar si el volumen ya estaba montado. Esto es útil en caso de que la ruta de origen especificada en path sea diferente a la ruta almacenada en el kernel. Esto podría

Variables

Within attributes and commands (see later section), specific placeholders or variables, identified by %(name) may be used. These are substituted at command invocation time.

%(USER)
Expands to the username of the user logging in.
%(DOMAIN_NAME), %(DOMAIN_USER)
Winbind has special UNIX usernames in the form of "domain\username", and %(DOMAIN_NAME) and %(DOMAIN_USER) provide the split parts of it. This is useful when a sharename on an MSAD server is the same as the username, e.g. <volume fstype="cifs" server="fsbox" path="%(DOMAIN_USER)" />.
%(USERUID), %(USERGID)
The numeric UID and GID of the primary group of the user logging in. This is obtained via getpw*(), not getuid(). It is useful in conjunction with the uid= or gid= mount options, e.g. <volume options="uid=%(USERUID)" />. Note that you do not need to specify uid=%(USERUID) for smbfs or cifs mounts because this is already done automatically by pam_mount.
%(GROUP)
The name of the group for %(USERGID).

All other variables you might find in the source code are internal to pam_mount, and are likely not to be expanded when you would expect it.

pam_mount parameters

Besides volumes, there are other elements allowed in pam_mount.conf.xml that control pam_mount's own behavior.

General tunables

<debug enable="1" />
Enables verbose output during login to stderr and syslog. Some programs do not cope with output sent on stderr, see doc/bugs.txt for a list. 0 disables debugging, 1 enables pam_mount tracing, and 2 additionally enables tracing in mount.crypt. The default is 0. As the config file is parsed linearly, the <debug> directive takes effect once it is seen - it it thus advised to put it near the start of the file, before any <volume> definitions.
<logout wait="microseconds" hup="yes/no" term="yes/no" kill="yes/no" />
Programs exist that do not terminate when the session is closed. (This applies to the "final" close, i.e. when the last user session ends.) Examples are processes still running in the background; or a broken X session manager that did not clean up its children, or other X programs that did not react to the X server termination notification. pam_mount can be configured to kill these processes and optionally wait before sending signals.
<luserconf name=".pam_mount.conf.xml" />
Individual users may define additional volumes in a file by the specified name relative to their home directory. The presence of <luserconf> in the master config file enables this feature. If turned on, users may mount and unmount any volumes they specify and that they have ownership of (in case of local mounts). The mount process is executed as superuser. This may have security implications, so this feature is disabled by default. Luserconfigs are parsed after any volumes from the global configuration file have been mounted, so that first mounting home directories with a global config and then mounting further volumes from luserconfigs is possible.
<mntoptions allow="options,..." />
The <mntoptions> elements determine which options may be specified in <volumes> in per-user configuration files (see <luserconf>). It does not apply to the master file. Specifying <mntoptions> is forbidden and ignored in per-user configs. The default allowed list consists of "nosuid,nodev", and this default is cleared when the first allow="..." attribute is seen by the config parser. All further allow="..." are additive, though.
<mntoptions deny="options,..." />
Any options listed in deny may not appear in the option list of per-user mounts. The default deny list is empty.
<mntoptions require="options,..." />
All options listed in require must appear in the option list of per-user mounts. The default require list consists of "nosuid,nodev", and like allow="", is cleared when first encountered by the parser, and is otherwise additive.
<path>directories...</path>
The default for the PATH environmental variable is not consistent across distributions, and so, pam_mount provides its own set of sane defaults which you may change at will.

Volume-related

<mkmountpoint enable="1" remove="true" />
Controls automatic creation and removal of mountpoints. If a mountpoint does not exist when the volume is about to be mounted, pam_mount can be instructed to create one using the enable attribute. Normally, directories created this way are retained after logout, but remove may be set to true to remove the mountpoint again, but only if it was automatically created by pam_mount in the same session before.

Auxiliary programs

Some mount programs need special default parameters to properly function. It is good practice to specify uid= for CIFS for example, because it is mounted as root and would otherwise show files belonging to root instead of the user logging in.

<fd0ssh>program...</fd0ssh>
fd0ssh is a hack around OpenSSH that essentially makes it read passwords from stdin even though OpenSSH normally does not do that.
<fsck>fsck -p %(FSCKTARGET)</fsck>
Local volumes will be checked before mounting if this program is set.
<ofl>ofl -k%(SIGNAL) %(MNTPT)</ofl>
The Open File Lister is used to identify processes using files within the given subdirectory, and optionally send a signal to those processes.
<pmvarrun>pmvarrun ...</pmvarrun>
pmvarrun(8) is a separate program to manage the reference count tracking user sessions.

Mount programs

Commands to mount/unmount volumes. They can take parameters, as shown. You can specify either absolute paths, or relative ones, in which case $PATH will be searched. Since login programs have differing default PATHs, pam_mount has its own path definition (see above).

<lclmount>mount -t %(FSTYPE) ...</lclmount>
The regular mount program.
<umount>umount %(MNTPT)</umount>
Unless there is a dedicated umount program for a given filesystem type, the regular umount program will be used.
Linux supports lazy unmounting using `/sbin/umount -l`. This may be dangerous for encrypted volumes because the underlying device is not unmapped. Loopback devices are also affected by this (not being unmapped when files are still open). Also, unmount on SMB volumes needs to be called on %(MNTPT) and not %(VOLUME).

Commands for various mount programs. Not all have a dedicated umount helper because some do not need one.

<cifsmount>mount.cifs ...</cifsmount>
<cryptmount>mount.crypt ...</cryptmount>
<cryptumount>umount.crypt %(MNTPT)</cryptumount>
Mount helpers for dm-crypt and LUKS volumes.
<fusemount>mount.fuse ...</fusemount>
<fuseumount>fuserumount ...</fuseumount>
<ncpmount>ncpmount ...</ncpmount>
<ncpumount>ncpumount ...</ncpumount>
<nfsmount>mount %(SERVER):%(VOLUME) ...</nfsmount>
<smbmount>smbmount ...</smbmount>
<smbumount>smbumount ...</smbumount>

Messages

<msg-authpw>pam_mount password:</msg-authpw>
When pam_mount cannot obtain a password through PAM, or is configured to not do so in the first place, and is configured to ask for a password interactively as a replacement, this prompt will be shown.
<msg-sessionpw>reenter...:</msg-sessionpw>
In case the 'session' PAM block does not have the password (e.g. on su from root to user), it will ask again. This prompt can also be customized.

Extended user control

Sometimes, the simple user control attributes for the <volume> element are not sufficient where one may want to build more complex expressions as to whom a volume applies. Instead of attributes, extended user control is set up using additional elements within <volume>, for example

<volume path="/dev/shm" mountpoint="~"> <and> <sgrp>students</sgrp> <not> <sgrp>profs</sgrp> </not> </and> </volume>

Which translates to (students && !profs).

Logical operators

<and><elements>*</and>
All elements within this one are logically ANDed. Any number of elements may appear.
<or><elements>*</or>
All elements within this one are logically ORed. Any number of elements may appear.
<not><element></not>
The expression within this one is negated.

User identity tests

<user>username</user>
True if the user logging in is username.
<uid>uid</uid>
True if the user's UID is uid.
<group>groupname</group>
True if the user logging in is a member of groupname.
<sgrp>groupname</sgrp>
True if the user logging in is a member of the specified group. This test is done using the setgid bit, which means it will work correctly only if the user also has the group id set. Usually this means that the group must be the primary group of the user. Note that this check is done before any group memberships are added via the PAM stack.
<custom>program</custom>
Runs program. If it exits with code 0, the expression is true. The program is run with the user's UID and GID.

Device identity tests

<device>device name</device>
True if the device is device name. This is typically the name of the block device, e.g. /dev/sda1.
<fstype>filesystem type</fstype>
True if the filesystem type is filesystem type. This is the type passed to the mount command, e.g. "ext3".

DESCRIPTION

This file is the configuration file for pam_mount. It allows you to specify mount points for users logging in, possibly based on user attributes, user login name, etc. The configuration file is parsed in XML format.

Volume definitions

The basic element is the volume definition, using the <volume> tag. A volume definition specifies a device or a remote resource to be mounted, and where it should be mounted. The attributes specify the characteristics of the volume and the mount process.

fstype=type
Specifies the filesystem type. This is passed directly to the mount(8) command. For FUSE filesystems, this should be set to "fuse" and the actual filesystem type is specified in the path attribute.
path=path
Specifies the path to the device or remote resource. For local filesystems, this is the device node, e.g. /dev/sda1. For FUSE filesystems, this specifies the FUSE filesystem module to load and any parameters it requires. The format is generally <module>#<module_options>. See the FUSE documentation for details.
mountpoint=path
Specifies the directory where the volume should be mounted. This directory must exist. If the path starts with a tilde (~), it is expanded to the user's home directory. The special token %(USER) is expanded to the username of the user logging in.
server=hostname
Specifies the server hostname for network filesystems like NFS or CIFS. This is used in conjunction with path to form the full remote path.
cipher=cipher
Specifies the cipher and mode to use for dm-crypt/LUKS volumes. Examples include "aes-cbc-essiv:sha256", "aes-xts-plain64", "blowfish-cbc-essiv:sha256". The available ciphers depend on your kernel configuration.
fskeycipher=cipher
Specifies the cipher and mode to use for encrypting the filesystem key when using dm-crypt. Defaults to the value of cipher.
fskeyhash=hash
Specifies the hash algorithm to use for deriving the filesystem key when using dm-crypt. Defaults to "sha1".
fskeypath=path
Specifies the path to the file containing the filesystem key for dm-crypt. If not specified, the key is requested from the user.
header=path
Specifies the path to the LUKS header file. If not specified, the header is assumed to be at the beginning of the device specified in path.
options=options
Specifies mount options, separated by commas. These are passed directly to the mount(8) command. For FUSE filesystems, these options are passed to the FUSE module.
ssh=0 | 1
If set to 1, the path attribute is interpreted as an SSH connection string. This is typically used for SSHFS. The format is "sshfs#[user@]host:path". If the user is omitted, the current user is used.
noroot=0 | 1
If set to 1, the volume will not be mounted if the user is root. This is useful for user-specific mounts.
user=username
Specifies that this volume should only be mounted for the given username. This can be used multiple times.
debug=0 | 1
If set to 1, enables debugging for this volume.
timeout=seconds
Specifies the timeout in seconds for operations like password prompts or key requests. Defaults to 10 seconds.
locale=locale
Specifies the locale to use for mounting this volume. Defaults to the user's current locale.
token=token
Specifies a token to use for authentication. This is typically used for smartcards or hardware tokens.
tokenprompt=prompt
Specifies the prompt to use when requesting a token. Defaults to "Please insert token: ".
tokenpromptfile=path
Specifies a file containing the token prompt. This allows for more complex prompts, including images.
unlockpath=path
Specifies the path to the file or device that contains the unlock key or password. This is typically used for encrypted volumes.
unlockprompt=prompt
Specifies the prompt to use when requesting the unlock key. Defaults to "Enter unlock key: ".
unlockpromptfile=path
Specifies a file containing the unlock prompt.
unlock=unlock_method
Specifies the method to use for unlocking the volume. Can be "askpass", "stdin", or a custom script path.
open=command
Specifies a command to execute before mounting the volume. This can be used to prepare the volume, e.g., by starting a service.
close=command
Specifies a command to execute after unmounting the volume. This can be used to clean up resources.
open_before=command
Specifies a command to execute before any volume is mounted. This is useful for global setup tasks.
close_after=command
Specifies a command to execute after all volumes have been unmounted. This is useful for global cleanup tasks.
mountoptions=options
Specifies additional mount options that are applied only during the mount operation.
umountoptions=options
Specifies additional unmount options that are applied only during the unmount operation.
noclose=0 | 1
If set to 1, the volume will not be closed automatically when the user logs out. This is useful for persistent mounts.
nofsck=0 | 1
If set to 1, filesystem check is skipped for this volume. Use with caution.
nonempty=0 | 1
If set to 1, allows mounting a non-empty directory. Useful for FUSE filesystems.
automedia=0 | 1
If set to 1, pam_mount will try to detect the presence of the media (e.g., USB drive) before attempting to mount.
rw=0 | 1
If set to 1, the volume is mounted read-write. This is the default.
readonly=0 | 1
If set to 1, the volume is mounted read-only. Overrides rw.
uid=number or uid=number-number
Specifies the UID or UID range for which this volume should be mounted. Used in conjunction with user, gid, etc.
gid=number or gid=number-number
Specifies the GID or GID range for which this volume should be mounted. Used in conjunction with user, uid, etc.
mode=octal_mode
Specifies the mode for the mount point directory. For example, "0700".
owner=username
Specifies the owner of the mount point directory.
group=groupname
Specifies the group of the mount point directory.
all=0 | 1
If set to 1, this volume is mounted for all users, unless overridden by other user-specific rules.
directory=0 | 1
If set to 1, the mount point is treated as a directory. This is useful for FUSE filesystems.
subdir=path
Specifies a subdirectory within the mount point to be used as the actual mount point. This is useful when the mount point itself should not be created.
filename=filename
Specifies the filename to use for the mount point. This is typically used in conjunction with directory=1.
mask=mask
Specifies a mask to be applied to the permissions of the mount point directory. For example, "077".
create=0 | 1
If set to 1, the mount point directory will be created if it doesn't exist. Defaults to 0.
destroy=0 | 1
If set to 1, the mount point directory will be destroyed after unmounting. Use with caution.
noauto=0 | 1
If set to 1, the volume will not be mounted automatically. It must be mounted manually using the pam_mount utility.
removable=0 | 1
If set to 1, the volume is considered removable media. This can affect how pam_mount handles unmounting.
nocrypt=0 | 1
If set to 1, encryption is disabled for this volume. This is typically used for unencrypted volumes that are otherwise configured like encrypted ones.
nocryptpass=0 | 1
If set to 1, the encryption password will not be requested. This is useful when the password is provided by other means.
nocryptkey=0 | 1
If set to 1, the encryption key will not be requested. This is useful when the key is provided by other means, e.g., a key file.
nomount=0 | 1
If set to 1, the volume will not be mounted. This is useful for defining volumes that are only used for unmounting.
recursive=0 | 1
If set to 1, mount the volume recursively. This is typically used for directory mounts.
noecho=0 | 1
If set to 1, input prompts will not echo characters to the terminal. This is useful for password entry.

The tag <volume> can be empty if it contains other tags, like <policy>.

Default volume settings

Extended user control

The <policy> tag allows for more fine-grained control over which volumes are mounted based on user attributes. The policy is evaluated using logical operators.

Policy operators

<and><elements></and>
All elements within the <and> tag must be true for the policy to evaluate to true. Any number of elements may appear.
<or><elements></or>
All elements within this one are logically ORed. Any number of elements may appear.
<xor><elements>{2}</xor>
The two elements within the <xor> are logically XORed.
<not><element></not>
The single element within the <not> is logically negated.

User selection

<user>username</user>
Match against the given username.
<uid>number</uid> or <uid>number-number</uid>
Match the UID of the user logging in against a UID or UID range.
<gid>number</gid> or <gid>number-number</gid>
Match the primary group of the user logging in against a GID or GID range.
<pgrp>groupname</pgrp>
Check if the user logging in has groupname as the primary group.
<sgrp>groupname</sgrp>
Check if the user logging in is a member of the group given by name (i.e. it is either a primary or secondary group).

Attributes

icase="yes" or icase="no"
The icase attribute may be used on <user>, <pgrp> and <sgrp> to enable case-insensitive matching (or not). It defaults to "no".
regex="yes" (or no)
The regex attribute may be used on <user>, <pgrp> and <sgrp> to enable interpreting the text content of the tag as a Perl-compatible regular expression pattern. This attribute may be combined with "icase" (see above). Example: <user regex="yes">joe</user> matches any user who has the letter sequence "joe" anywhere in their username. Therefore, use the regex feature cautiously and consider adding ^ and $ anchors to limit security surprises. Example: <user regex="yes">^.*joe.*$</user> if you really wanted to match the sequence at any position.

Examples

Remember that ~ can be used in the mountpoint attribute to denote the home directory as retrievable through getpwent(3).

sshfs and ccgfs

Not specifying any path after the colon (:) uses the path wherever ssh will put you in, usually the home directory. With fd0ssh (package hxtools) installed:

<volume fstype="fuse" path="sshfs#%(USER)@fileserver:" mountpoint="~" ssh="1" />

Without fd0ssh:

<volume fstype="fuse" path="sshfs#%(USER)@fileserver:" mountpoint="~" options="nosuid,nodev,noatime,reconnect,nonempty,allow_other,default_permissions,password_stdin" ssh="0" noroot="0" />

<volume fstype="fuse" path="ccgfs-ssh-pull#%(USER)@host:directory" mountpoint="~" />

Note that sshfs's "password_stdin" option tries to locate a string "assword" on ssh's output, while fd0ssh is rather using the "askpass" API, which might also work with passphrase-protected SSH keys whose prompt is quite different.

encfs 1.4.x and up

<volume fstype="fuse" path="encfs#/crypto/%(USER)" mountpoint="~" options="nonempty" />

(encfs 1.3 is no longer supported.)

NFS mounts

<volume fstype="nfs" server="fileserver" path="/home/%(USER)" mountpoint="~" />

CIFS mounts

<volume user="user" fstype="cifs" server="krueger" path="public" mountpoint="/home/user/krueger" />

Bind mounts

This may come useful in conjunction with pam_chroot:

<volume path="/bin" mountpoint="~/bin" options="bind" />

tmpfs mounts

Volatile tmpfs mount with restricted size (thanks to Mike Hommey for this example):

<volume user="test" fstype="tmpfs" mountpoint="/home/test" options="size=10M,uid=%(USER),mode=0700" />

dm-crypt volumes

Crypt mounts require a kernel with CONFIG_BLK_DEV_DM and CONFIG_DM_CRYPT enabled, as well as all the ciphers that are going to be used, e.g. CONFIG_CRYPTO_AES, CONFIG_CRYPTO_BLOWFISH, CONFIG_CRYPTO_TWOFISH.

<volume path="/home/%(USER).img" mountpoint="~" cipher="aes-cbc-essiv:sha256" fskeycipher="aes-256-cbc" fskeyhash="sha1" fskeypath="/home/%(USER).key" />

LUKS volumes

<volume path="/home/%(USER).img" mountpoint="~" cipher="aes-cbc-essiv:sha256" />

volume path="/home/%(USER).img" mountpoint="~" header="/home/%(USER)-header.img" />

cryptoloop volumes

cryptoloop is not explicitly supported by pam_mount. Citing the Linux kernel config help text: "WARNING: This device [cryptoloop] is not safe for journal[l]ed filesystems[...]. Please use the Device Mapper [dm-crypt] module instead."

OpenBSD encrypted home

OpenBSD encrypted home directory example:

<volume path="/home/user.img" mountpoint="/home/user" options="svnd0" />
