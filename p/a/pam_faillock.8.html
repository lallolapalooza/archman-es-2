NOMBRE

pam_faillock - Módulo que cuenta los fallos de autenticación durante un intervalo de tiempo especificado

SINOPSIS

auth ... pam_faillock.so {preauth|authfail|authsucc} [conf=/ruta/al/archivo-de-configuracion] [dir=/ruta/al/directorio-de-conteo] [even_deny_root] [deny=n] [fail_interval=n] [unlock_time=n] [root_unlock_time=n] [admin_group=nombre] [audit] [silent] [no_log_info]

account ... pam_faillock.so [dir=/ruta/al/directorio-de-conteo] [no_log_info]

DESCRIPCIÓN

Este módulo mantiene una lista de intentos fallidos de autenticación por usuario durante un intervalo especificado y bloquea la cuenta en caso de que haya habido más de deny intentos fallidos consecutivos de autenticación.

Normalmente, los intentos fallidos de autenticar a root no provocarán que la cuenta de root se bloquee, para prevenir la denegación de servicio: si a sus usuarios no se les otorgan cuentas de shell y root solo puede iniciar sesión mediante su o en la consola de la máquina (no telnet/rsh, etc), esto es seguro.

OPCIONES

{preauth|authfail|authsucc}

Este argumento debe establecerse de acuerdo con la posición de esta instancia del módulo en la pila PAM.

El argumento preauth debe usarse cuando el módulo se llama antes que los módulos que solicitan las credenciales del usuario, como la contraseña. El módulo simplemente examina si el usuario debe ser bloqueado para acceder al servicio en caso de que haya habido un número anómalo de intentos fallidos consecutivos de autenticación recientemente. Esta llamada es opcional si se utiliza authsucc.

El argumento authfail debe usarse cuando el módulo se llama después de los módulos que determinan el resultado de la autenticación, fallido. A menos que el usuario ya esté bloqueado debido a fallos de autenticación previos, el módulo registrará el fallo en el archivo de conteo de usuario apropiado.

El argumento authsucc debe usarse cuando el módulo se llama después de los módulos que determinan el resultado de la autenticación, exitoso. A menos que el usuario ya esté bloqueado debido a fallos de autenticación previos, el módulo borrará el registro de los fallos en el archivo de conteo de usuario respectivo. De lo contrario, devolverá un error de autenticación. Si esta llamada no se realiza, pam_faillock no distinguirá entre intentos fallidos de autenticación consecutivos y no consecutivos. En tal caso, se debe usar la llamada preauth. Debido a las complicaciones en la forma en que se puede configurar la pila PAM, también es posible llamar a pam_faillock como un módulo de cuenta. En tal configuración, el módulo también debe ser llamado en la etapa preauth.

conf=/ruta/al/archivo-de-configuracion

Utiliza otro archivo de configuración en lugar del predeterminado /etc/security/faillock.conf.

Las opciones para configurar el comportamiento del módulo se describen en la página del manual faillock.conf(5). Las opciones especificadas en la línea de comandos del módulo anulan los valores del archivo de configuración.

TIPOS DE MÓDULO PROPORCIONADOS

Se proporcionan los tipos de módulo auth y account.

VALORES DE RETORNO

PAM_AUTH_ERR

Se proporcionó una opción no válida, el módulo no pudo recuperar el nombre de usuario, no se encontró ningún archivo de contador válido o se produjeron demasiados inicios de sesión fallidos.

PAM_BUF_ERR

Error de búfer de memoria.

PAM_CONV_ERR

El método de conversación proporcionado por la aplicación falló al obtener el nombre de usuario.

PAM_INCOMPLETE

El método de conversación proporcionado por la aplicación devolvió PAM_CONV_AGAIN.

PAM_SUCCESS

Todo fue exitoso.

PAM_IGNORE

El usuario no está presente en la base de datos de contraseñas.

NOTAS

No se recomienda configurar opciones en la línea de comandos del módulo. Se debe utilizar /etc/security/faillock.conf en su lugar.

La configuración de pam_faillock en la pila PAM es diferente de la configuración del módulo pam_tally2.

Los archivos individuales con los registros de fallos se crean como propiedad del usuario. Esto permite que el módulo pam_faillock.so funcione correctamente cuando se llama desde un salvapantallas.

Tenga en cuenta que usar el módulo en preauth sin la opción silent especificada en /etc/security/faillock.conf o con el campo de control requisite filtra información sobre la existencia o inexistencia de una cuenta de usuario en el sistema porque los fallos no se registran para los usuarios desconocidos. El mensaje sobre el bloqueo de la cuenta de usuario nunca se muestra para las cuentas de usuario inexistentes, lo que permite al adversario inferir que una cuenta en particular no existe en un sistema.

EJEMPLOS

Aquí hay dos ejemplos de configuración posibles para /etc/pam.d/login. Hacen que pam_faillock bloquee la cuenta después de 4 inicios de sesión fallidos consecutivos durante el intervalo predeterminado de 15 minutos. La cuenta de root también se bloqueará. Las cuentas se desbloquearán automáticamente después de 20 minutos.

En el primer ejemplo, el módulo solo se llama en la fase auth y el módulo no imprime ninguna información sobre el bloqueo de la cuenta por parte de pam_faillock. Se puede agregar la llamada preauth para informar a los usuarios que sus inicios de sesión están bloqueados por el módulo y también para abortar la autenticación sin siquiera solicitar la contraseña en tales casos.

Ejemplo de archivo /etc/security/faillock.conf:

deny=4
unlock_time=1200
silent

Ejemplo de archivo /etc/pam.d/config:

auth     required       pam_securetty.so
auth     required       pam_env.so
auth     required       pam_nologin.so
# opcionalmente llamar: auth requisite pam_faillock.so preauth
# para mostrar el mensaje sobre la cuenta bloqueada
auth     [success=1 default=bad] pam_unix.so
auth     [default=die]  pam_faillock.so authfail
auth     sufficient     pam_faillock.so authsucc
auth     required       pam_deny.so
account  required       pam_unix.so
password required       pam_unix.so shadow
session  required       pam_selinux.so close
session  required       pam_loginuid.so
session  required       pam_unix.so
session  required       pam_selinux.so open

En el segundo ejemplo, el módulo se llama tanto en las fases auth como account y el módulo informa al usuario que se está autenticando cuando la cuenta está bloqueada si la opción silent no está especificada en faillock.conf.

auth     required       pam_securetty.so
auth     required       pam_env.so
auth     required       pam_nologin.so
auth     required       pam_faillock.so preauth
# opcionalmente usar requisite arriba si no desea solicitar la contraseña
# en cuentas bloqueadas
auth     sufficient     pam_unix.so
auth     [default=die]  pam_faillock.so authfail
auth     required       pam_deny.so
account  required       pam_faillock.so
# si elimina la llamada anterior a pam_faillock.so, el bloqueo se realizará también
# en fallos de autenticación no consecutivos
account  required       pam_unix.so
password required       pam_unix.so shadow
session  required       pam_selinux.so close
session  required       pam_loginuid.so
session  required       pam_unix.so
session  required       pam_selinux.so open

ARCHIVOS

/var/run/faillock/*

los archivos que registran los fallos de autenticación para los usuarios

Nota: Estos archivos desaparecerán después de reiniciar en sistemas configurados con el directorio /var/run/faillock montado en memoria virtual. Para almacenamiento persistente, utilice la opción dir= en el archivo /etc/security/faillock.conf.

/etc/security/faillock.conf

el archivo de configuración para las opciones de pam_faillock
