NOMBRE

pam_xauth - Módulo PAM para reenviar claves xauth entre usuarios

SINOPSIS

pam_xauth.so [debug] [xauthpath=/ruta/a/xauth] [systemuser=UID] [targetuser=UID]

DESCRIPCIÓN

El módulo PAM pam_xauth está diseñado para reenviar claves xauth (a veces llamadas "cookies") entre usuarios.

Sin pam_xauth, cuando xauth está habilitado y un usuario utiliza el comando su(1) para asumir los privilegios de otro usuario, ese usuario ya no puede acceder a la pantalla X del usuario original porque el nuevo usuario no tiene la clave necesaria para acceder a la pantalla. pam_xauth resuelve el problema reenviando la clave del usuario que ejecuta su (el usuario de origen) al usuario cuya identidad el usuario de origen está asumiendo (el usuario de destino) cuando se crea la sesión, y destruyendo la clave cuando se cierra la sesión.

Esto significa, por ejemplo, que cuando ejecutas su(1) desde una sesión de xterm, podrás ejecutar programas X sin tener que lidiar explícitamente con el comando xauth(1) o los archivos ~/.Xauthority.

pam_xauth solo reenviará claves si xauth puede listar una clave conectada a la variable de entorno $DISPLAY.

El control de acceso primitivo se proporciona a través de ~/.xauth/export en el directorio principal del usuario que invoca y ~/.xauth/import en el directorio principal del usuario de destino.

Si un usuario tiene un archivo ~/.xauth/import, el usuario solo recibirá cookies de los usuarios listados en el archivo. Si no hay un archivo ~/.xauth/import, el usuario aceptará cookies de cualquier otro usuario.

Si un usuario tiene un archivo .xauth/export, el usuario solo reenviará cookies a los usuarios listados en el archivo. Si no hay un archivo ~/.xauth/export, y el usuario que invoca no es root, el usuario reenviará cookies a cualquier otro usuario. Si no hay un archivo ~/.xauth/export, y el usuario que invoca es root, el usuario *no* reenviará cookies a otros usuarios.

Tanto los archivos import como export admiten comodines (como *). Tanto los archivos import como export pueden estar vacíos, lo que significa que no se permiten usuarios.

OPCIONES

debug

Imprime información de depuración.

xauthpath=/ruta/a/xauth

Especifica la ruta del programa xauth (se espera en /usr/X11R6/bin/xauth, /usr/bin/xauth o /usr/bin/X11/xauth por defecto).

systemuser=UID

Especifica el UID más alto que se asumirá que pertenece a un usuario "del sistema". pam_xauth se negará a reenviar credenciales a usuarios con un UID menor o igual a este número, excepto a root y al "targetuser", si se especifica.

targetuser=UID

Especifica un único UID de destino que está exento de la verificación de systemuser.

TIPOS DE MÓDULO PROPORCIONADOS

Solo se proporciona el tipo session.

VALORES DE RETORNO

PAM_BUF_ERR

Error de búfer de memoria.

PAM_PERM_DENIED

Permiso denegado por archivo de importación/exportación.

PAM_SESSION_ERR

No se puede determinar el nombre de usuario, UID o acceder al directorio principal del usuario.

PAM_SUCCESS

Éxito.

PAM_USER_UNKNOWN

Usuario desconocido.

EJEMPLOS

Añade la siguiente línea a /etc/pam.d/su para reenviar claves xauth entre usuarios al llamar a su:

session  optional  pam_xauth.so

DETALLES DE IMPLEMENTACIÓN

pam_xauth funcionará *solo* si se utiliza desde una aplicación setuid en la que la llamada getuid() devuelve el id del usuario que ejecuta la aplicación, y para la cual PAM puede proporcionar el nombre de la cuenta que el usuario está intentando asumir. La aplicación típica de este tipo es su(1). La aplicación debe llamar tanto a pam_open_session() como a pam_close_session() con el ruid establecido al uid del usuario que llama y el euid establecido a root, y debe haber proporcionado como elemento PAM_USER el nombre del usuario de destino.

pam_xauth llama a xauth(1) como el usuario de origen para extraer la clave de $DISPLAY, luego llama a xauth como el usuario de destino para fusionar la clave en una base de datos temporal y luego eliminar la base de datos.

No se puede indicar a pam_xauth que no elimine las claves cuando se cierra la sesión.
