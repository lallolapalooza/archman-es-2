NOMBRE

parallel - construye y ejecuta líneas de comandos de shell en paralelo desde la entrada estándar

SINOPSIS

parallel [opciones] [comando [argumentos]] < lista_de_argumentos

parallel [opciones] [comando [argumentos]] ( ::: argumentos | :::+ argumentos | :::: archivo_de_argumentos(s) | ::::+ archivo_de_argumentos(s) ) ...

parallel --semaphore [opciones] comando

#!/usr/bin/parallel --shebang [opciones] [comando [argumentos]]

#!/usr/bin/parallel --shebang-wrap [opciones] [comando [argumentos]]

DESCRIPCIÓN

¡DETENTE!

Lee la Guía del lector a continuación si eres nuevo en GNU parallel.

GNU parallel es una herramienta de shell para ejecutar trabajos en paralelo usando una o más computadoras. Un trabajo puede ser un solo comando o un pequeño script que debe ejecutarse para cada una de las líneas de entrada. La entrada típica es una lista de archivos, una lista de hosts, una lista de usuarios, una lista de URLs o una lista de tablas. Un trabajo también puede ser un comando que lee de una tubería. GNU parallel puede dividir la entrada en bloques y pasar un bloque a cada comando en paralelo.

Si hoy usas xargs y tee, encontrarás que GNU parallel es muy fácil de usar, ya que está diseñado para tener las mismas opciones que xargs. Si escribes bucles en shell, encontrarás que GNU parallel puede reemplazar la mayoría de los bucles y hacer que se ejecuten más rápido ejecutando varios trabajos en paralelo.

GNU parallel se asegura de que la salida de los comandos sea la misma que obtendrías si ejecutaras los comandos secuencialmente. Esto hace posible usar la salida de GNU parallel como entrada para otros programas.

Para cada línea de entrada, GNU parallel ejecutará comando con la línea como argumentos. Si no se proporciona comando, se ejecutará la línea de entrada. Varias líneas se ejecutarán en paralelo. GNU parallel a menudo puede usarse como un sustituto de xargs o cat | bash.

OPCIONES

comando
Comando a ejecutar.

Si comando o los argumentos siguientes contienen cadenas de reemplazo (como {}), cada instancia será sustituida por la entrada.

Si se proporciona comando, GNU parallel resuelve las mismas tareas que xargs. Si no se proporciona comando, GNU parallel se comportará de manera similar a cat | sh.

El comando debe ser un ejecutable, un script, un comando compuesto, un alias o una función.

Funciones de Bash: Exporta la función primero con export -f o usa env_parallel.

Alias de Bash, Csh o Tcsh: Usa env_parallel.

Funciones y alias de Zsh, Fish, Ksh y Pdksh: Usa env_parallel.

{}
Línea de entrada.

Esta cadena de reemplazo será reemplazada por una línea completa leída de la fuente de entrada. La fuente de entrada es normalmente la stdin (entrada estándar), pero también puede proporcionarse con --arg-file, ::: o ::::.

La cadena de reemplazo {} puede cambiarse con -I.

Si la línea de comandos no contiene cadenas de reemplazo, {} se añadirá al final de la línea de comandos.

Las cadenas de reemplazo normalmente se citan, por lo que los caracteres especiales no son analizados por el shell. La excepción es si el comando comienza con una cadena de reemplazo; en ese caso, la cadena no se cita.

Ver también: --plus {.} {/} {//} {/.} {#} {%} {n} {=expresión perl=}

{.}
Línea de entrada sin extensión.

Esta cadena de reemplazo será reemplazada por la entrada sin la extensión eliminada. Si la línea de entrada contiene . después de la última /, se eliminará el último . hasta el final de la cadena y {.} se reemplazará con lo restante. Por ejemplo, foo.jpg se convierte en foo, subdir/foo.jpg se convierte en subdir/foo, sub.dir/foo.jpg se convierte en sub.dir/foo, sub.dir/bar permanece sub.dir/bar. Si la línea de entrada no contiene ., permanecerá sin cambios.

La cadena de reemplazo {.} puede cambiarse con --extensionreplace

Ver también: {} --extensionreplace

{/}
Nombre base de la línea de entrada.

Esta cadena de reemplazo será reemplazada por la entrada con la parte del directorio eliminada.

Ver también: {} --basenamereplace

{//}
Nombre del directorio de la línea de entrada.

Esta cadena de reemplazo será reemplazada por el directorio de la línea de entrada. Ver dirname(1).

Ver también: {} --dirnamereplace

{/.}
Nombre base de la línea de entrada sin extensión.

Esta cadena de reemplazo será reemplazada por la entrada con la parte del directorio y la extensión eliminadas. {/.} es una combinación de {/} y {.}.

Ver también: {} --basenameextensionreplace

{#}
Número de secuencia del trabajo a ejecutar.

Esta cadena de reemplazo será reemplazada por el número de secuencia del trabajo que se está ejecutando. Contiene el mismo número que $PARALLEL_SEQ.

Ver también: {} --seqreplace

{%}
Número de ranura del trabajo.

Esta cadena de reemplazo será reemplazada por el número de ranura del trabajo, entre 1 y el número de trabajos a ejecutar en paralelo. Nunca habrá 2 trabajos ejecutándose al mismo tiempo con el mismo número de ranura de trabajo.

Si el trabajo necesita ser reintentado (por ejemplo, usando --retries o --retry-failed), la ranura del trabajo no se actualiza automáticamente. Deberías usar en su lugar $PARALLEL_JOBSLOT:

$ do_test() {
    id="$3 {%}=$1 PARALLEL_JOBSLOT=$2"
    echo run "$id";
    sleep 1
    # fallar si {%} es impar
    return `echo $1%2 | bc`
  }
$ export -f do_test
$ parallel -j3 --jl mylog do_test {%} \$PARALLEL_JOBSLOT {} ::: A B C D
run A {%}=1 PARALLEL_JOBSLOT=1
run B {%}=2 PARALLEL_JOBSL

Ver también: {} --jobs --slotreplace

{n}
Argumento de la fuente de entrada n o el argumento n-ésimo.

Esta cadena de reemplazo posicional se reemplazará con la entrada de la fuente de entrada n (cuando se usa con --arg-file o ::::) o con el argumento n-ésimo (cuando se usa con -N o --colsep).

Si n es negativo, se refiere al último argumento n-ésimo.

Ver también: {} {n.} {n/} {n//} {n/.} --colsep

{n.}
Argumento de la fuente de entrada n o el argumento n-ésimo sin extensión.

{n.} es una combinación de {n} y {.}.

Esta cadena de reemplazo posicional se reemplazará con la entrada de la fuente de entrada n (cuando se usa con --arg-file o ::::) o con el argumento n-ésimo (cuando se usa con -N). La entrada tendrá la extensión eliminada.

Ver también: {n} {.}

{n/}
Nombre base del argumento de la fuente de entrada n o el argumento n-ésimo.

{n/} es una combinación de {n} y {/}.

Esta cadena de reemplazo posicional se reemplazará con la entrada de la fuente de entrada n (cuando se usa con --arg-file o ::::) o con el argumento n-ésimo (cuando se usa con -N). La entrada tendrá el directorio (si lo hay) eliminado.

Ver también: {n} {/}

{n//}
Nombre de directorio del argumento de la fuente de entrada n o el argumento n-ésimo.

{n//} es una combinación de {n} y {//}.

Esta cadena de reemplazo posicional se reemplazará con el directorio de la entrada de la fuente de entrada n (cuando se usa con --arg-file o ::::) o con el argumento n-ésimo (cuando se usa con -N). Ver dirname(1).

Ver también: {n} {//}

{n/.}
Nombre base del argumento de la fuente de entrada n o el argumento n-ésimo sin extensión.

{n/.} es una combinación de {n}, {/}, y {.}.

Esta cadena de reemplazo posicional se reemplazará con la entrada de la fuente de entrada n (cuando se usa con --arg-file o ::::) o con el argumento n-ésimo (cuando se usa con -N). La entrada tendrá el directorio (si lo hay) y la extensión eliminados.

Ver también: {n} {/.}

{=expresión perl=}
Reemplazar con la expresión perl calculada.

$_ contendrá lo mismo que {}. Después de evaluar la expresión perl $_ se usará como valor. Se recomienda solo cambiar $_, pero tienes acceso completo a todas las funciones y estructuras de datos internas de GNU parallel.

La expresión debe dar el mismo resultado si se evalúa dos veces; de lo contrario, el comportamiento no está definido. Por ejemplo, en algunas versiones de GNU parallel esto no funcionará como se espera:

parallel echo '{= $_= ++$wrong_counter =}' ::: a b c

Se han creado algunas funciones y estructuras de datos de conveniencia:

Q(cadena)
Comillar una cadena para el shell. Ejemplo: 
parallel echo {} está entre comillas como '{= $_=Q($_) =}' ::: \$PWD
pQ(cadena)
Comillar una cadena para Perl. Ejemplo: 
parallel echo {} está entre comillas como '{= $_=pQ($_) =}' ::: \$PWD
uq() (o uq)
No comillar la cadena de reemplazo actual. Ejemplo: 
parallel echo {} tiene el valor '{= uq =}' ::: \$PWD
hash(val)
Calcular B::hash(val). Ejemplo: 
parallel echo El hash de {} es '{= $_=hash($_) =}' ::: a b c
total_jobs()
Número total de trabajos. Ejemplo: 
parallel echo Número de trabajos: '{= $_=total_jobs() =}' ::: a b c
slot()
Número de ranura del trabajo. Ejemplo: 
parallel echo La ranura del trabajo {} es '{= $_=slot() =}' ::: a b c
seq()
Número de secuencia del trabajo. Ejemplo: 
parallel echo El número de secuencia de {} es '{= $_=seq() =}' ::: a b c
@arg
Los argumentos contando desde 1 ($arg[1] = {1} = primer argumento). Ejemplo: 
parallel echo {1}+{2}='{=1 $_=$arg[1]+$arg[2] =}' \
  ::: 1 2 3 ::: 2 3 4

('{=1' fuerza que esta sea una cadena de reemplazo posicional, y por lo tanto no repetirá el valor para cada argumento.)

skip()
Saltar este trabajo (ver también --filter). Ejemplo: 
parallel echo '{= $arg[1] >= $arg[2] and skip =}' \
  ::: 1 2 3 ::: 2 3 4

hh_mm(sec)

yyyymmdd(sec)
hhmmss(sec)
hhmm(sec)
Funciones de tiempo. sec es el número de segundos desde la época. Si se omite, utilizará la hora local actual. Ejemplo: 
parallel echo 'Ahora: {= $_=yyyy_mm_dd_hh_mm_ss() =}' ::: Dummy

{=n expresión perl=}
Equivalente posicional a {=expresión perl=}.

Para entender las cadenas de reemplazo posicionales, ver {n}.

{rpl:formato}
Cadena de reemplazo de formato.

Usa formato para formatear rpl. formato es una cadena de formato usada en printf. rpl es una cadena de reemplazo.

Ejemplos:

{#:%04d} - Número de trabajo ({#}) con 4 dígitos precedidos por 0
{%:%02d} - Ranura de trabajo ({%}) con 2 dígitos precedidos por 0
{:%6s} - Línea de entrada ({}) alineada a la derecha, 6 caracteres de ancho
{/:%12s} - Nombre base ({/}) alineado a la derecha, 12 caracteres de ancho
{2:%8.2f} - Segunda fuente de entrada ({2}) 8 caracteres de ancho, 2 decimales

Las cadenas de formato también funcionan en cadenas de reemplazo definidas a través de --rpl que comienzan con '{'.

Ver también: {} {n} --rpl

::: argumentos
Usar argumentos en la línea de comandos como fuente de entrada.

A diferencia de otras opciones para GNU parallel, ::: se coloca después del comando y antes de los argumentos.

Los siguientes son equivalentes:

(echo file1; echo file2) | parallel gzip
parallel gzip ::: file1 file2
parallel gzip {} ::: file1 file2
parallel --arg-sep ,, gzip {} ,, file1 file2
parallel --arg-sep ,, gzip ,, file1 file2
parallel ::: "gzip file1" "gzip file2"

Para evitar tratar ::: como especial, usa --arg-sep para establecer el separador de argumentos a algo diferente.

Si se dan múltiples :::, cada grupo se tratará como una fuente de entrada, y se generarán todas las combinaciones de fuentes de entrada. Por ejemplo, ::: 1 2 ::: a b c dará como resultado las combinaciones (1,a) (1,b) (1,c) (2,a) (2,b) (2,c). Esto es útil para reemplazar bucles for anidados.

:::, ::::, y --arg-file se pueden mezclar. Por lo tanto, estos son equivalentes:

parallel echo {1} {2} {3} ::: 6 7 ::: 4 5 ::: 1 2 3
parallel echo {1} {2} {3} :::: <(seq 6 7) <(seq 4 5) \
  :::: <(seq 1 3)
parallel -a <(seq 6 7) echo {1} {2} {3} :::: <(seq 4 5) \
  :::: <(seq 1 3)
parallel -a <(seq 6 7) -a <(seq 4 5) echo {1} {2} {3} \
  ::: 1 2 3
seq 6 7 | parallel -a - -a <(seq 4 5) echo {1} {2} {3} \
  ::: 1 2 3
seq 4 5 | parallel echo {1} {2} {3} :::: <(seq 6 7) - \
  ::: 1 2 3

Ver también: --arg-sep --arg-file :::: :::+ ::::+ --link

:::+ argumentos
Similar a ::: pero enlazado como --link a la fuente de entrada anterior.

A diferencia de --link, los valores no se envuelven: la fuente de entrada más corta determina la longitud.

Ejemplo:

parallel echo ::: a b c :::+ 1 2 3 ::: X Y :::+ 11 22

Ver también: ::::+ --link

:::: archivos de argumentos
Otra forma de write --arg-file archivo_argumentos1 --arg-file archivo_argumentos2 ...

::: y :::: pueden mezclarse.

Ver también: --arg-file ::: ::::+ --link

::::+ archivos_argumentos
Similar a :::: pero enlazados como --link a la fuente de entrada anterior.

Contrario a --link, los valores no se repiten: La fuente de entrada más corta determina la longitud.

Ver también: --arg-file :::+ --link

--null
-0
Usa NUL como delimitador.

Normalmente las líneas de entrada terminarán en \n (nueva línea). Si terminan en \0 (NUL), usa esta opción. Es útil para procesar argumentos que pueden contener \n (nueva línea).

Atajo para --delimiter '\0'.

Ver también: --delimiter

--arg-file archivo_entrada
-a archivo_entrada
Usa archivo_entrada como fuente de entrada.

Si se proporcionan múltiples --arg-file, cada archivo_entrada será tratado como una fuente de entrada, y todas las combinaciones de fuentes de entrada serán generadas. Ej: El archivo foo contiene 1 2, el archivo bar contiene a b c. -a foo -a bar resultará en las combinaciones (1,a) (1,b) (1,c) (2,a) (2,b) (2,c). Esto es útil para reemplazar bucles for anidados.

Si archivo_entrada empieza con + el archivo será enlazado al --arg-file anterior. Ej: El archivo foo contiene 1 2, el archivo bar contiene a b. -a foo -a +bar resultará en las combinaciones (1,a) (2,b) como --link en lugar de generar todas las combinaciones.

Ver también: --link {n} :::: ::::+ :::

--bin expr_binning
Usa expr_binning como clave de binning y agrupa la entrada en los trabajos.

expr_binning es [número de columna|nombre de columna] [expresión perl] ej:

3
Address
3 $_%=100
Address s/\D//g

Cada línea de entrada se divide usando --colsep. El valor de la columna se pone en $_, se ejecuta la expresión perl, el valor resultante es la ranura de trabajo que recibirá la línea. Si el valor es mayor que el número de ranuras de trabajo, el valor será el módulo del número de ranuras de trabajo.

Esto es similar a --shard pero el algoritmo de hash es un simple módulo, lo que hace predecible qué ranura de trabajo recibirá qué valor.

El rendimiento es del orden de 100K filas por segundo. Más rápido si el columna_binning es pequeño (<10), más lento si es grande (>100).

--bin requiere --pipe y un valor numérico fijo para --jobs.

Ver también: REPARTO DE BLOQUES DE DATOS --group-by --round-robin --shard

--bg
Ejecuta el comando en segundo plano.

GNU parallel normalmente esperará a que un trabajo se complete. Con --bg GNU parallel no esperará a que el comando se complete antes de salir.

Este es el comportamiento predeterminado si --semaphore está configurado.

Implica --semaphore.

Ver también: --fg man sem

--bibtex
--citation
Imprime el aviso de cita y la entrada BibTeX para GNU parallel, silencia el aviso de cita para todas las ejecuciones futuras y sale. No ejecutará ningún comando.

Si te es imposible ejecutar --citation puedes usar en su lugar --will-cite, que ejecutará comandos, pero que solo silenciará el aviso de cita para esa única ejecución.

Si usas --will-cite en scripts que serán ejecutados por otros, dificultas que otros vean el aviso de cita. El desarrollo de GNU parallel se financia indirectamente a través de citas, por lo que si tus usuarios no saben que deben citar, dificultas la financiación del desarrollo. Sin embargo, si pagas 10000 EUR, has hecho tu parte para financiar el desarrollo futuro y deberías sentirte libre de usar --will-cite en scripts.

Si no quieres ayudar a financiar el desarrollo futuro permitiendo que otros usuarios vean el aviso de cita o pagando, por favor considera usar otra herramienta en lugar de GNU parallel. Puedes encontrar algunas de las alternativas en man parallel_alternatives.

--block tamaño
--block-size tamaño
Tamaño del bloque en bytes a leer a la vez.

El tamaño puede ir seguido de K, M, G, T, P, k, m, g, t, o p.

GNU parallel intenta cumplir con el tamaño del bloque pero puede desviarse en la longitud de un registro. Por razones de rendimiento, el tamaño debe ser mayor que dos registros. GNU parallel te advertirá y aumentará automáticamente el tamaño si eliges un tamaño demasiado pequeño.

El tamaño por defecto es 1M.

Un tamaño de bloque negativo no se interpreta como un tamaño de bloque sino como el número de bloques que cada ranura de trabajo debe tener. Así, --block -3 creará 3 trabajos para cada ranura de trabajo. En otras palabras: esto ejecutará 3*5 = 15 trabajos en total:

parallel --pipe-part -a miarchivo --block -3 -j5 wc
cat miarchivo | parallel --pipe --block -3 -j5 wc

--pipe-part --block es una alternativa eficiente a --round-robin porque GNU parallel nunca lee los datos, pero aún así puedes tener muy pocas ranuras de trabajo procesando grandes cantidades de datos.

Por otro lado, --pipe --block es bastante ineficiente: Lee el archivo completo en memoria antes de dividirlo. Por lo tanto, la entrada debe poder caber en memoria.

Si usas --block -tamaño, la entrada debe ser mayor que tamaño+1 registros.

Ver también: PREFIJOS DE UNIDAD -N --pipe --pipe-part --round-robin --block-timeout

--cat
Crea un archivo temporal con contenido.

Normalmente --pipe/--pipe-part enviarán datos al programa en stdin (entrada estándar). Con --cat GNU parallel creará un archivo temporal con el nombre en {}, así que puedes hacer: parallel --pipe --cat wc {}.

Implica --pipe a menos que se use --pipe-part.

Ver también: --pipe --pipe-part --fifo

--cleanup
Elimina los archivos transferidos.

--cleanup eliminará los archivos transferidos en el equipo remoto después de que el procesamiento haya terminado.

find log -name '*gz' | parallel \
  --sshlogin server.example.com --transferfile {} \
  --return {.}.bz2 --cleanup "zcat {} | bzip -9 >{.}.bz2"

Con --transferfile {} el archivo transferido al equipo remoto será eliminado en el equipo remoto. Los directorios en el equipo remoto que contienen el archivo w

¿Cuándo debe terminar GNU parallel?

En algunas situaciones, no tiene sentido ejecutar todos los trabajos. GNU parallel simplemente debería detenerse tan pronto como se cumpla una condición.

val tiene como valor predeterminado never, que ejecuta todos los trabajos sin importar lo que suceda.

val también puede tener la forma de cuándo,porqué.

cuándo puede ser 'now' (ahora), lo que significa matar todos los trabajos en ejecución y detenerse inmediatamente, o puede ser 'soon' (pronto), lo que significa esperar a que todos los trabajos en ejecución se completen, pero sin iniciar nuevos trabajos.

porqué puede ser 'fail=X', 'fail=Y%', 'success=X', 'success=Y%', 'done=X', o 'done=Y%' donde X es el número de trabajos que deben fallar, tener éxito o completarse antes de detenerse, y Y es el porcentaje de trabajos que deben fallar, tener éxito o completarse antes de detenerse.

--halt soon,fail=3

--halt soon,fail=3%
sale cuando el 3% de los trabajos han fallado, pero espera a que los trabajos en ejecución se completen.
--halt now,success=1
sale cuando un trabajo ha tenido éxito. Mata los trabajos en ejecución.
--halt soon,success=3
sale cuando 3 trabajos han tenido éxito, pero espera a que los trabajos en ejecución se completen.
--halt now,success=3%
sale cuando el 3% de los trabajos han tenido éxito. Mata los trabajos en ejecución.
--halt now,done=1
sale cuando un trabajo ha finalizado. Mata los trabajos en ejecución.
--halt soon,done=3
sale cuando 3 trabajos han finalizado, pero espera a que los trabajos en ejecución se completen.
--halt now,done=3%
sale cuando el 3% de los trabajos han finalizado. Mata los trabajos en ejecución.

Multiplica el número de hilos de CPU por num por ciento. Por ejemplo, 100% significa un trabajo por hilo de CPU en cada máquina.

Suma num al número de hilos de CPU.

Resta num del número de hilos de CPU.

numauto
Si num termina en auto, GNU parallel usará el valor como máximo. Si un trabajo falla, GNU parallel ajustará el número de trabajos hacia abajo con un factor. Si un trabajo tiene éxito, GNU parallel ajustará el número de trabajos hacia arriba con un factor pequeño.

Así que si el número de trabajos es un poco alto, GNU parallel lo reducirá dinámicamente.

Ejemplo:

# Esto falla si hay más de n sleeps en ejecución
n_sleeps() {
  nsleeps=$(ps aux | grep sleep | grep 12345 | wc -l)
  echo $nsleeps sleeps running now
  [ $nsleeps -lt $1 ]
}
export -f n_sleeps
parallel --jobs 20auto 'sleep 2.${RANDOM}{}12345; n_sleeps 5' ::: {1..100}

Esto iniciará 20 trabajos en paralelo. Estos fallarán porque hay más de 5 sleeps en ejecución. GNU parallel ajustará el número de trabajos hasta que haya alrededor de 5 ejecutándose en paralelo.

Si el número evaluado es menor que 1, se usará 1.

Si se establece --semaphore, el valor predeterminado es 1, lo que crea un mutex.

--line-buffer
--lb
Buffea la salida línea por línea.

--group mantendrá la salida junta para un trabajo completo. --ungroup permite que la salida se mezcle con la mitad de una línea proveniente de un trabajo y la mitad de una línea proveniente de otro trabajo. --line-buffer se sitúa entre estos dos: GNU parallel imprimirá una línea completa, pero permitirá la mezcla de líneas de diferentes trabajos.

--line-buffer consume más potencia de CPU que tanto --group como --ungroup, pero puede ser mucho más rápido que --group si la CPU no es el factor limitante.

Normalmente --line-buffer no buffea en disco, y por lo tanto puede procesar una cantidad infinita de datos, pero buffeará en disco cuando se combine con: --keep-order, --results, --compress, y --files. Esto lo hará tan lento como --group y limitará la salida al espacio de disco disponible.

Con --keep-order --line-buffer imprimirá líneas del primer trabajo de forma continua mientras se ejecuta, luego líneas del segundo trabajo mientras este se ejecuta. Buffeará líneas completas, pero los trabajos no se mezclarán. Compare:

parallel -j0 'echo [{};sleep {};echo {}]' ::: 1 3 2 4
parallel -j0 --lb 'echo [{};sleep {};echo {}]' ::: 1 3 2 4
parallel -j0 -k --lb 'echo [{};sleep {};echo {}]' ::: 1 3 2 4

--memfree size
Memoria libre mínima al iniciar otro trabajo.

El size puede ir seguido de los sufijos K, M, G, T, P, k, m, g, t, o p.

Si los trabajos consumen cantidades de RAM muy diferentes, GNU parallel solo iniciará tantos como haya memoria disponible. Si hay menos de size bytes libres, no se iniciarán más trabajos. --memsuspend size
Suspende trabajos cuando hay menos memoria disponible.

Si la memoria disponible cae por debajo de 2 * size, GNU parallel suspenderá algunos de los trabajos en ejecución. Si la memoria disponible cae por debajo de size, solo se ejecutará un trabajo.

Si un solo trabajo cabe en el tamaño dado, todos los trabajos completarán sin quedarse sin memoria. Si tienes espacio de intercambio disponible, generalmente puedes reducir size a aproximadamente la mitad del tamaño de un solo trabajo, con el ligero riesgo de un poco de intercambio.

Los trabajos se reanudarán cuando haya más RAM disponible, típicamente cuando el trabajo más antiguo finalice.

--memsuspend solo funciona en trabajos locales porque no hay una forma obvia de suspender trabajos remotos.

size puede ir seguido de los sufijos K, M, G, T, P, k, m, g, t, o p.

--pipe
--spreadstdin
Distribuir entrada a trabajos en stdin (entrada estándar).

Leer un bloque de datos de stdin (entrada estándar) y dar un bloque de datos como entrada a un trabajo.

El tamaño del bloque se determina por --block (predeterminado: 1M).

Excepto para el primer y último registro, GNU parallel solo pasa registros completos al trabajo. Las cadenas --recstart y --recend determinan dónde comienza y termina un registro: El borde entre dos registros se define como --recend seguido inmediatamente por --recstart. Si no se proporcionan ni --inicio-rec ni --fin-rec, entonces --fin-rec tendrá como valor predeterminado '\n'. Para no tener separador de registro (por ejemplo, para archivos binarios) usa --fin-rec "".

--inicio-rec y --fin-rec se utilizan con --tubería.

Usa --expresion-regular para interpretar --inicio-rec y --fin-rec como expresiones regulares. Sin embargo, esto es lento.

--retry-failed
Reintenta todos los trabajos fallidos del joblog.

Al leer --joblog, GNU parallel identificará los trabajos fallidos y los ejecutará de nuevo.

--retry-failed ignora el comando y los argumentos en la línea de comandos: solo busca en el joblog.

Diferencias entre --resume, --resume-failed, --retry-failed

En este ejemplo, exit {= $_%=2 =} hará que cada otro trabajo falle.

timeout -k 1 4 parallel --joblog log -j10 \
  'sleep {}; exit {= $_%=2 =}' ::: {10..1}

4 trabajos completados. 2 fallaron:

Seq   [...]   Exitval Signal  Command
10    [...]   1       0       sleep 1; exit 1
9     [...]   0       0       sleep 2; exit 0
8     [...]   1       0       sleep 3; exit 1
7     [...]   0       0       sleep 4; exit 0

--resume no tiene en cuenta el Exitval, sino que solo mira Seq. Si Seq ya se ejecutó, no se ejecutará de nuevo. Por lo tanto, si es necesario, puede cambiar el comando para los seqs que aún no se han ejecutado:

parallel --resume --joblog log -j10 \
  'sleep .{}; exit {= $_%=2 =}' ::: {10..1}
Seq   [...]   Exitval Signal  Command
[... como arriba ...]
1     [...]   0       0       sleep .10; exit 0
6     [...]   1       0       sleep .5; exit 1
5     [...]   0       0       sleep .6; exit 0
4     [...]   1       0       sleep .7; exit 1
3     [...]   0       0       sleep .8; exit 0
2     [...]   1       0       sleep .9; exit 1

--resume-failed tiene en cuenta el Exitval, pero solo mira Seq para identificar qué comandos ejecutar. Nuevamente, esto significa que puede cambiar el comando, pero no los argumentos. Ejecutará los seqs fallidos y los seqs que aún no se han ejecutado:

parallel --resume-failed --joblog log -j10 \
  'echo {};sleep .{}; exit {= $_%=3 =}' ::: {10..1}
Seq   [...]   Exitval Signal  Command
[... como arriba ...]
10    [...]   1       0       echo 1;sleep .1; exit 1
8     [...]   0       0       echo 3;sleep .3; exit 0
6     [...]   2       0       echo 5;sleep .5; exit 2
4     [...]   1       0       echo 7;sleep .7; exit 1
2     [...]   0       0       echo 9;sleep .9; exit 0

--retry-failed tiene en cuenta el Exitval, pero toma el comando del joblog. Ignora cualquier argumento o comando dado en la línea de comandos:

parallel --retry-failed --joblog log -j10 this part is ignored
Seq   [...]   Exitval Signal  Command
[... como arriba ...]
10    [...]   1       0       echo 1;sleep .1; exit 1
6     [...]   2       0       echo 5;sleep .5; exit 2
4     [...]   1       0       echo 7;sleep .7; exit 1

--return archivo
Transfiere archivos desde computadoras remotas.

--return se usa con --sshlogin cuando los argumentos son archivos en las computadoras remotas. Cuando se completa el procesamiento, el archivo archivo se transferirá desde la computadora remota usando rsync y se colocará en relación con el directorio de inicio de sesión predeterminado. Por ejemplo:

echo foo/bar.txt | parallel --return {.}.out \
  --sshlogin server.example.com touch {.}.out

Esto transferirá el archivo $HOME/foo/bar.out desde la computadora server.example.com al archivo foo/bar.out después de ejecutar touch foo/bar.out en server.example.com.

parallel -S server --trc out/./{}.out touch {}.out ::: in/file

Esto transferirá el archivo in/file.out desde la computadora server.example.com a los archivos out/in/file.out después de ejecutar touch in/file.out en server.

echo /tmp/foo/bar.txt | parallel --return {.}.out \
  --sshlogin server.example.com touch {.}.out

Esto transferirá el archivo /tmp/foo/bar.out desde la computadora server.example.com al archivo /tmp/foo/bar.out después de ejecutar touch /tmp/foo/bar.out en server.example.com.

Se pueden transferir varios archivos repitiendo la opción varias veces:

echo /tmp/foo/bar.txt | parallel \
  --sshlogin server.example.com \

--rpl 'etiqueta expresión perl'
Define cadena de reemplazo.

Usa etiqueta como cadena de reemplazo para la expresión perl. Esto permite definir tus propias cadenas de reemplazo. Las 7 cadenas de reemplazo de GNU parallel se implementan como:

--rpl '{} '
--rpl '{#} 1 $_=$job->seq()'
--rpl '{%} 1 $_=$job->slot()'
--rpl '{/} s:.*/::'
--rpl '{//} $Global::use{"File::Basename"} ||=
            eval "use File::Basename; 1;"; $_ = dirname($_);'
--rpl '{/.} s:.*/::; s:\.[^/.]+$::;'
--rpl '{.} s:\.[^/.]+$::'

Las cadenas de reemplazo --plus se implementan como:

--rpl '{+/} s:/[^/]*$:: || s:.*$::'
--rpl '{+.} s:.*\.:: || s:.*$::'
--rpl '{+..} s:.*\.([^/.]+\.[^/.]+)$:$1: || s:.*$::'
--rpl '{+...} s:.*\.([^/.]+\.[^/.]+\.[^/.]+)$:$1: || s:.*$::'
--rpl '{..} s:\.[^/.]+\.[^/.]+$::'
--rpl '{...} s:\.[^/.]+\.[^/.]+\.[^/.]+$::'
--rpl '{/..} s:.*/::; s:\.[^/.]+\.[^/.]+$::'
--rpl '{/...} s:.*/::; s:\.[^/.]+\.[^/.]+\.[^/.]+$::'
--rpl '{choose_k}
       for $t (2..$#arg){ if($arg[$t-1] ge $arg[$t]) { skip() } }'
--rpl '{##} 1 $_=total_jobs()'
--rpl '{0%} 1 $f=1+int((log($Global::max_jobs_running||1)/
                        log(10))); $_=sprintf("%0${f}d",slot())'
--rpl '{0#} 1 $f=1+int((log(total_jobs())/log(10)));
            $_=sprintf("%0${f}d",seq())'
--rpl '{seq(.*?)} $_=eval q{$job->seq()}.qq{$$1}'
--rpl '{slot(.*?)} $_=eval q{$job->slot()}.qq{$$1}'
--rpl '{:-([^}]+?)} $_ ||= $$1'
--rpl '{:(\d+?)} substr($_,0,$$1) = ""'
--rpl '{:(\d+?):(\d+?)} $_ = substr($_,$$1,$$2);'
--rpl '{#([^#}][^}]*?)} $nongreedy=::make_regexp_ungreedy($$1);
                        s/^$nongreedy(.*)/$1/;'
--rpl '{##([^#}][^}]*?)} s/^$$1//;'
--rpl '{%([^}]+?)} $nongreedy=::make_regexp_ungreedy($$1);
                   s/(.*)$nongreedy$/$1/;'
--rpl '{%%([^}]+?)} s/$$1$//;'
--rpl '{/([^}]+?)/([^}]*?)} s/$$1/$$2/;'
--rpl '{^([^}]+?)} s/^($$1)/uc($1)/e;'
--rpl '{^^([^}]+?)} s/($$1)/uc($1)/eg;'
--rpl '{,([^}]+?)} s/^($$1)/lc($1)/e;'
--rpl '{,,([^}]+?)} s/($$1)/lc($1)/eg;'
--rpl '{slot} 1 $_="\${PARALLEL_JOBSLOT}";uq()'
--rpl '{host} 1 $_="\${PARALLEL_SSHHOST}";uq()'
--rpl '{sshlogin} 1 $_="\${PARALLEL_SSHLOGIN}";uq()'
--rpl '{hgrp} 1 $_="\${PARALLEL_HOSTGROUPS}";uq()'
--rpl '{agrp} 1 $_="\${PARALLEL_ARGHOSTGROUPS}";uq()'

Si la cadena de reemplazo definida por el usuario comienza con '{', también se puede usar como una cadena de reemplazo posicional (como {2.}).

Se recomienda cambiar solo $_, pero tiene acceso completo a todas las funciones internas y estructuras de datos de GNU parallel.

Aquí tienes algunos ejemplos:

¿Es la secuencia de trabajos par o impar?
--rpl '{odd} $_ = seq() % 2 ? "odd" : "even"'
Rellena la secuencia de trabajos con ceros a la izquierda para obtener un ancho igual
--rpl '{0#} $f=1+int("".(log(total_jobs())/log(10)));
  $_=sprintf("%0${f}d",seq())'
Secuencia de trabajos contando desde 0
--rpl '{#0} $_ = seq() - 1'
Contador de ranuras de trabajo desde 2
--rpl '{%1} $_ = slot() + 1'
Eliminar todas las extensiones
--rpl '{:} s:(\.[^/]+)*$::'

Puedes tener cadenas de reemplazo dinámicas incluyendo paréntesis en la cadena de reemplazo y añadiendo una expresión regular entre los paréntesis. La cadena coincidente se insertará como $$1:

parallel --rpl '{%(.*?)} s/$$1//' echo {%.tar.gz} ::: my.tar.gz
parallel --rpl '{:+(.+?)} s:$$1(\.[^/]+)*$::' \
  echo {:+_file} ::: my_file.tar.gz
parallel -n3 --rpl '{/:+(.*?)} s:.*/(.*)$$1(\.[^/]+)*$:$1:' \
  echo job {#}: {2} {2.} {3/:+_1} ::: a/b.c c/d.e f/g_1.h.i

Incluso puedes usar múltiples coincidencias:

parallel --rpl '{/(.+?)/(.*?)} s/$$1/$$2/;'
  echo {/reemplazar_esto/con_esto} {/b/C} ::: a_reemplazar_esto_b
parallel --rpl '{(.*?)/(.*?)} $_="$$2$_$$1"' \
  echo {intercambiar/esto} ::: -medio-

DISTRIBUCIÓN DE BLOQUES DE DATOS

--round-robin, --pipe-part, --shard, --bin y --group-by son versiones especializadas de --pipe.

En lo siguiente, n es el número de ranuras de trabajo dadas por --jobs. Un registro comienza con --recstart y termina con --recend. Típicamente es una línea completa. Un fragmento es un número de registros completos que tiene aproximadamente el tamaño de un bloque. Un bloque puede contener medios registros, un fragmento no.

--pipe inicia un trabajo por fragmento. Lee bloques de stdin (entrada estándar). Encuentra un final de registro cerca del borde de un bloque y pasa un fragmento al programa.

--pipe-part inicia un trabajo por fragmento, igual que --pipe normal. Primero encuentra los finales de registro cerca de todos los bordes de bloque en el archivo y luego inicia los trabajos. Al usar --block -1, establecerá el tamaño del bloque a tamaño-del-archivo/n. Utilizado de esta manera, iniciará n trabajos en total.

--round-robin inicia n trabajos en total. Lee un bloque y pasa un fragmento al trabajo que esté listo para leer. No analiza el contenido excepto para identificar dónde termina un registro y asegurarse de que solo pasa registros completos.

--shard inicia n trabajos en total. Analiza cada línea para leer la cadena en la columna dada. Basándose en esta cadena, la línea se pasa a uno de los n trabajos. Todas las líneas que tengan esta cadena se entregarán al mismo slot de trabajo.

--bin funciona como --shard pero el valor de la columna debe ser numérico y es el número del slot de trabajo al que se pasará. Si el valor es mayor que n, entonces se restará n del valor hasta que el valor sea menor o igual a n.

--group-by inicia un trabajo por fragmento. Los bordes de registro no se dan por --recend/--recstart. En su lugar, un registro se define por un grupo de líneas que tienen la misma cadena en una columna dada. Por lo tanto, la cadena de una columna dada cambia en el borde de un fragmento. Con --pipe se analiza cada línea, con --pipe-part solo se analizan unas pocas líneas para encontrar el borde del fragmento.

--group-by se puede combinar con --round-robin o --pipe-part.

POSTFIJOS DE TIEMPO

Los argumentos que dan una duración se expresan en segundos, pero se pueden expresar como números de punto flotante seguidos de s, m, h o d, que multiplicarían el número de punto flotante por 1, 60, 60*60 o 60*60*24. Por lo tanto, estos son equivalentes: 100000 y 1d3.5h16.6m4s.

PREFIJO DE UNIDAD

Muchos argumentos numéricos en GNU parallel pueden ir seguidos de K, M, G, T, P, k, m, g, t o p, que multiplicarían el número por 1024, 1048576, 1073741824, 1099511627776, 1125899906842624, 1000, 1000000, 1000000000, 1000000000000 o 1000000000000000, respectivamente.

Incluso puede escribirlo como una expresión matemática. Por ejemplo, 1000000 se puede escribir como 1M-12*2.024*2k.

COMILLADO

GNU parallel es muy liberal con las comillas. Solo necesita poner comillas a los caracteres que tienen un significado especial en el shell:

( ) $ ` ' " < > ; | \

y dependiendo del contexto, estos también necesitan ser comillados:

~ & ! ? espacio * { #

Por lo tanto, la mayoría de las personas nunca necesitarán más comillado que poner una barra invertida (\) delante de los caracteres especiales.

A menudo, simplemente puede poner comillas simples (') alrededor de cada uno:

perl -ne '/^\S+\s+\S+$/ and print $ARGV,"\n"' file

puede ser citado:

parallel perl -ne \''/^\S+\s+\S+$/ and print $ARGV,"\n"'\' ::: file

Sin embargo, cuando desee utilizar una variable de shell, deberá citar el signo $. Aquí tiene un ejemplo que utiliza $PARALLEL_SEQ. Esta variable es establecida por GNU parallel, por lo que la evaluación del $ debe ser realizada por el subshell iniciado por GNU parallel:

seq 10 | parallel -N2 echo seq:\$PARALLEL_SEQ arg1:{1} arg2:{2}

Si la variable se estableció antes de que GNU parallel comenzara, puede hacer esto:

VAR=esto_se_establece_antes_de_iniciar
echo test | parallel echo {} $VAR

Imprime: test esto_se_establece_antes_de_iniciar

Es un poco más complicado si la variable contiene más de un espacio seguido:

VAR="dos  espacios  entre  cada  palabra"
echo test | parallel echo {} \'"$VAR"\'

Imprime: test dos espacios entre cada palabra

Si la variable no debe ser evaluada por el shell que inicia GNU parallel, sino por el subshell iniciado por GNU parallel, entonces necesita citarla:

echo test | parallel VAR=esto_se_establece_despues_de_iniciar \; echo {} \$VAR

Imprime: test esto_se_establece_despues_de_iniciar

Es un poco más complicado si la variable contiene espacios:

echo test |
  parallel VAR='"dos  espacios  entre  cada  palabra"' echo {} \'"$VAR"\'

Imprime: test dos espacios entre cada palabra

$$ es la variable de shell que contiene el ID de proceso del shell. Esto imprimirá el ID de proceso del shell que ejecuta GNU parallel:

seq 10 | parallel echo $$

Y esto imprimirá los IDs de proceso de los subshells iniciados por GNU parallel.

seq 10 | parallel echo \$\$

Si los caracteres especiales no deben ser evaluados por el subshell, entonces debe protegerlos contra la evaluación tanto del shell que inicia GNU parallel como del subshell:

echo test | parallel echo {} \\\$VAR

Imprime: test $VAR

GNU parallel puede proteger contra la evaluación por el subshell utilizando -q:

echo test | parallel -q echo {} \$VAR

Imprime: test $VAR

Esto es particularmente útil si tiene muchas citas. Si desea ejecutar un script de Perl como este:

perl -ne '/^\S+\s+\S+$/ and print $ARGV,"\n"' file

Debe ser citado como uno de estos:

ls | parallel perl -ne '/^\\S+\\s+\\S+\$/\ and\ print\ \$ARGV,\"\\n\"'
ls | parallel perl -ne \''/^\S+\s+\S+$/ and print $ARGV,"\n"'\'

Observe cómo los espacios, las comillas simples, las comillas dobles y los signos de dólar deben ser citados. GNU parallel puede realizar las citas utilizando la opción -q:

ls | parallel -q  perl -ne '/^\S+\s+\S+$/ and print $ARGV,"\n"'

Sin embargo, esto significa que no puede hacer que el subshell interprete caracteres especiales. Por ejemplo, debido a -q, esto NO FUNCIONARÁ:

ls *.gz | parallel -q "zcat {} >{.}"
ls *.gz | parallel -q "zcat {} | bzip2 >{.}.bz2"

porque > y | deben ser interpretados por el subshell.

Si obtiene errores como:

sh: -c: line 0: syntax error near unexpected token
sh: Syntax error: Unterminated quoted string
sh: -c: line 0: unexpected EOF while looking for matching `''
sh: -c: line 1: syntax error: unexpected end of file
zsh:1: no matches found:

entonces puede intentar usar -q.

Si está utilizando la sustitución de procesos de bash como <(cat foo), puede intentar -q y anteponer *command* con bash -c:

ls | parallel -q bash -c 'wc -c <(echo {})'

O para sustituir salida:

ls | parallel -q bash -c \
  'tar c {} | tee >(gzip >{}.tar.gz) | bzip2 >{}.tar.bz2'

Conclusión: Si esto es confuso, considere evitar tener que lidiar con citas escribiendo un pequeño script o una función (recuerde exportar la función con export -f) y haga que GNU parallel la llame.

LISTAR TRABAJOS EN EJECUCIÓN

Si desea una lista de los trabajos que se están ejecutando actualmente, puede ejecutar:

killall -USR1 parallel

GNU parallel imprimirá entonces los trabajos en ejecución en stderr (salida de error estándar).

COMPLETAR TRABAJOS EN EJECUCIÓN PERO NO INICIAR NUEVOS TRABAJOS

Si se arrepiente de haber iniciado muchos trabajos, puede simplemente interrumpir GNU parallel, pero si desea asegurarse de no tener trabajos a medio completar, debe enviar la señal SIGHUP a GNU parallel:

killall -HUP parallel

Esto le indicará a GNU parallel que no inicie nuevos trabajos, sino que espere hasta que los trabajos en ejecución finalicen antes de salir.

VARIABLES DE ENTORNO

$PARALLEL_HOME
Directorio donde GNU parallel almacena archivos de configuración, semáforos y caché de información entre invocaciones. Si se establece en un directorio inexistente, se creará el directorio.

Por defecto: $HOME/.parallel.

$PARALLEL_ARGHOSTGROUPS
Al usar --hostgroups, GNU parallel establece esto en los grupos de host del trabajo.

Recuerde citar el $, para que sea evaluado por el shell correcto. O use --plus y {agrp}.

$PARALLEL_HOSTGROUPS
Al usar --hostgroups, GNU parallel establece esto en los grupos de host del inicio de sesión ssh en el que se ejecuta el trabajo.

Recuerde citar el $, para que sea evaluado por el shell correcto. O use --plus y {hgrp}.

$PARALLEL_JOBSLOT
Establecida por GNU parallel y puede ser utilizada en trabajos ejecutados por GNU parallel. Recuerde citar el $, para que sea evaluado por el shell correcto. O use --plus y {slot}.

$PARALLEL_JOBSLOT es la ranura de trabajo del trabajo. Es igual a {%} a menos que el trabajo se esté reintentando. Ver {%} para más detalles.

$PARALLEL_PID
Establecida por GNU parallel y puede ser utilizada en trabajos ejecutados por GNU parallel. Recuerde citar el $, para que sea evaluado por el shell correcto.

Esto hace posible que los trabajos se comuniquen directamente con GNU parallel.

Ejemplo: Si cada uno de los trabajos prueba una solución y uno de los trabajos encuentra la solución, el trabajo puede indicar a GNU parallel que no inicie más trabajos enviando: kill -HUP $PARALLEL_PID. Esto solo funciona en la computadora local.

$PARALLEL_RSYNC_OPTS
Opciones para pasar a rsync. Por defecto: -rlDzR.
$PARALLEL_SHELL
Use este shell para los comandos ejecutados por GNU parallel:
  • $PARALLEL_SHELL. Si no está definido, use:
  • El shell que inició GNU parallel. Si no se puede determinar:
  • $SHELL. Si no está definido, use:
  • /bin/sh
$PARALLEL_SSH
GNU parallel utiliza por defecto el comando ssh para el acceso remoto. Esto puede ser anulado con $PARALLEL_SSH, que a su vez puede ser anulado con --ssh. También se puede establecer por servidor (ver --sshlogin).
$PARALLEL_SSHHOST
Establecida por GNU parallel y puede ser utilizada en trabajos ejecutados por GNU parallel. Recuerde citar el $, para que sea evaluado por el shell correcto. O use --plus y {host}.

$PARALLEL_SSHHOST es la parte del host de una línea de inicio de sesión ssh. Por ejemplo:

4//usr/bin/specialssh user@host

se convierte en:

host
$PARALLEL_SSHLOGIN
Establecida por GNU parallel y puede ser utilizada en trabajos ejecutados por GNU parallel. Recuerde citar el $, para que sea evaluado por el shell correcto. O use --plus y {sshlogin}.

El valor es la línea de inicio de sesión ssh con el número de hilos eliminado. Por ejemplo:

4//usr/bin/specialssh user@host

se convierte en:

/usr/bin/specialssh user@host
$PARALLEL_SEQ
Establecida por GNU parallel y puede ser utilizada en trabajos ejecutados por GNU parallel. Recuerde citar el $, para que sea evaluado por el shell correcto.

$PARALLEL_SEQ es el número de secuencia del trabajo que se está ejecutando.

Ejemplo:

seq 10 | parallel -N2 \
  echo seq:'$'PARALLEL_SEQ arg1:{1} arg2:{2}

{#} es una abreviatura de $PARALLEL_SEQ.

$PARALLEL_TMUX
Ruta a tmux. Si no está establecida, se usa el tmux en $PATH.
$TMPDIR
Directorio para archivos temporales.

Ver también: --tmpdir

$PARALLEL_REMOTE_TMPDIR
Directorio para archivos temporales en servidores remotos.

Ver también: --tmpdir

$PARALLEL
La variable de entorno $PARALLEL se utilizará como opciones por defecto para GNU parallel. Si la variable contiene caracteres especiales de shell (por ejemplo, $, * o espacio), estos deben ser escapados con \.

Ejemplo:

cat list | parallel -j1 -k -v ls
cat list | parallel -j1 -k -v -S"myssh user@server" ls

se puede escribir como:

cat list | PARALLEL="-kvj1" parallel ls
cat list | PARALLEL='-kvj1 -S myssh\ user@server' \
  parallel echo

Observe la \ después de 'myssh' ya que 'myssh' y 'user@server' deben ser un solo argumento.

Ver también: --profile
