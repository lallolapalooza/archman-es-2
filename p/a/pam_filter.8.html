NOMBRE

pam_filter - Módulo de filtro PAM

SINOPSIS

pam_filter.so [debug] [new_term] [non_term] run1|run2 filtro [...]

DESCRIPCIÓN

Este módulo tiene la intención de ser una plataforma para proporcionar acceso a toda la entrada/salida que pasa entre el usuario y la aplicación. Solo es adecuado para aplicaciones basadas en tty y (stdin/stdout).

Para funcionar, este módulo requiere que se instalen filtros en el sistema. El único filtro proporcionado con el módulo simplemente intercambia letras mayúsculas y minúsculas en los flujos de entrada y salida. (Esto puede ser muy molesto y no es amable con los editores basados en termcap).

Cada componente del módulo tiene el potencial de invocar el filtro deseado. El filtro siempre se ejecuta con execv(2) con el privilegio de la aplicación que llama y *no* el del usuario. Por esta razón, generalmente no puede ser eliminado por el usuario sin cerrar su sesión.

OPCIONES

debug

Imprime información de depuración.

new_term

La acción predeterminada del filtro es establecer el elemento PAM_TTY para indicar el terminal que el usuario está utilizando para conectarse a la aplicación. Este argumento indica que el filtro establecerá PAM_TTY al pseudo-terminal filtrado.

non_term

no intentes establecer el elemento PAM_TTY.

runX

Para que el módulo pueda invocar un filtro, debe saber cuándo invocarlo. Este argumento es necesario para indicarle al filtro cuándo hacerlo.

Los valores permitidos para X son 1 y 2. Estos indican el momento exacto en que se ejecutará el filtro. Para comprender este concepto, será útil haber leído la página del manual de pam(3). Básicamente, para cada grupo de gestión hay hasta dos formas de llamar a las funciones del módulo. En el caso de los componentes de autenticación y sesión, hay en realidad dos funciones separadas. Para el caso de la autenticación, estas funciones son pam_authenticate(3) y pam_setcred(3), aquí run1 significa ejecutar el filtro desde la función pam_authenticate y run2 significa ejecutar el filtro desde pam_setcred. En el caso de los módulos de sesión, run1 implica que el filtro se invoca en la etapa de pam_open_session(3), y run2 para pam_close_session(3).

Para el caso del componente de cuenta. Se puede usar tanto run1 como run2.

Para el caso del componente de contraseña, run1 se usa para indicar que el filtro se ejecuta en la primera ocasión de pam_chauthtok(3) (la fase PAM_PRELIM_CHECK) y run2 se usa para indicar que el filtro se ejecuta en la segunda ocasión (la fase PAM_UPDATE_AUTHTOK).

filtro

La ruta completa del filtro que se va a ejecutar y los argumentos de la línea de comandos que el filtro pueda esperar.

TIPOS DE MÓDULO PROPORCIONADOS

Se proporcionan todos los tipos de módulo (auth, account, password y session).

VALORES DE RETORNO

PAM_SUCCESS

El nuevo filtro se configuró correctamente.

PAM_ABORT

Error crítico, abortar inmediatamente.

EJEMPLOS

Añada la siguiente línea a /etc/pam.d/login para ver cómo configurar el inicio de sesión para intercambiar mayúsculas y minúsculas una vez que el usuario haya iniciado sesión:

        session required pam_filter.so run1 /lib/security/pam_filter/upperLOWER

VER TAMBIÉN

pam.conf(5), pam.d(5), pam(8)
