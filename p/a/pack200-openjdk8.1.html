pack200(1) Herramientas de despliegue Java pack200(1)

NOMBRE

pack200 - Empaqueta un archivo JAR en un archivo pack200 comprimido para el despliegue web.

SINOPSIS

pack200 [opciones] archivo-salida archivo-JAR

Las opciones pueden estar en cualquier orden. La última opción en la línea de comandos o en un archivo de propiedades reemplaza a todas las opciones especificadas previamente.

opciones
Las opciones de la línea de comandos. Ver Opciones.
archivo-salida
Nombre del archivo de salida.
archivo-JAR
Nombre del archivo de entrada.

DESCRIPCIÓN

El comando pack200 es una aplicación Java que transforma un archivo JAR en un archivo pack200 comprimido con el compresor gzip de Java. Los archivos pack200 son archivos altamente comprimidos que pueden desplegarse directamente para ahorrar ancho de banda y reducir el tiempo de descarga.

El comando pack200 tiene varias opciones para ajustar y configurar el motor de compresión. El uso típico se muestra en el siguiente ejemplo, donde myarchive.pack.gz se produce con la configuración por defecto del comando pack200:

pack200 myarchive.pack.gz myarchive.jar

OPCIONES

-r, --repack

Produce un archivo JAR empaquetando y desempaquetando un archivo JAR. El archivo resultante puede usarse como entrada para la herramienta jarsigner(1). El siguiente ejemplo empaqueta y desempaqueta el archivo myarchive.jar: 
pack200 --repack myarchive-packer.jar myarchive.jar
pack200 --repack myarchive.jar

El siguiente ejemplo conserva el orden de los archivos en el archivo de entrada.

-g, --no-gzip

Produce un archivo pack200. Con esta opción, debe usarse un compresor adecuado, y el sistema de destino debe usar un descompresor correspondiente. 
pack200 --no-gzip myarchive.pack myarchive.jar
-G, --strip-debug

Elimina los atributos de depuración de la salida. Estos incluyen SourceFile, LineNumberTable, LocalVariableTable y LocalVariableTypeTable. Eliminar estos atributos reduce el tamaño tanto de las descargas como de las instalaciones, pero disminuye la utilidad de los depuradores.
--conservar-orden-archivos

Conserva el orden de los archivos en el archivo de entrada. Este es el comportamiento por defecto.
-O, --no-conservar-orden-archivos

El empaquetador reordena y transmite todos los elementos. El empaquetador también puede eliminar nombres de directorios JAR para reducir el tamaño de la descarga. Sin embargo, ciertas optimizaciones de archivos JAR, como la indexación, podrían no funcionar correctamente.
-Svalor , --limite-segmento=valor

El valor es el tamaño objetivo estimado N (en bytes) de cada segmento de archivo. Si un solo archivo de entrada requiere más de N bytes, entonces se proporciona su propio segmento de archivo. Como caso especial, un valor de -1 produce un único segmento grande con todos los archivos de entrada, mientras que un valor de 0 produce un segmento por cada clase. Segmentos de archivo más grandes resultan en menos fragmentación y mejor compresión, pero procesarlos requiere más memoria.

El tamaño de cada segmento se estima contando el tamaño de cada archivo de entrada a transmitir en el segmento con el tamaño de su nombre y otras propiedades transmitidas.

El valor por defecto es -1, lo que significa que el empaquetador crea un archivo de salida de un solo segmento. En casos donde se generan archivos de salida extremadamente grandes, se recomienda encarecidamente a los usuarios usar la segmentación o dividir el archivo de entrada en JARs más pequeños.

Un JAR de 10 MB empaquetado sin este límite típicamente se empaqueta aproximadamente un 10% más pequeño, pero el empaquetador podría requerir un montón de Java más grande (aproximadamente 10 veces el límite del segmento).

-Evalor , --esfuerzo=valor

Si el valor se establece en un solo dígito decimal, el empaquetador utiliza la cantidad de esfuerzo indicado en la compresión del archivo. El nivel 1 podría producir un tamaño algo mayor y una velocidad de compresión más rápida, mientras que el nivel 9 tarda mucho más, pero puede producir una mejor compresión. El valor especial 0 indica al comando pack200 que copie el archivo JAR original directamente sin compresión. El estándar JSR 200 requiere que cualquier descompresor entienda este caso especial como una copia directa de todo el archivo.

El valor por defecto es 5, para invertir una cantidad modesta de tiempo y producir una compresión razonable.

-Hvalor , --indicador-desinflado=valor

Anula el valor por defecto, que conserva la información de entrada, pero puede hacer que el archivo transmitido sea más grande. Los valores posibles son: verdadero, falso, o conservar.

Si el valor es verdadero o falso, entonces el comando packer200 establece el indicador de desinflado en consecuencia en el archivo de salida y no transmite los indicadores de desinflado individuales de los elementos del archivo.

El valor conservar mantiene los indicadores de desinflado observados en el JAR de entrada. Este es el valor por defecto.

-mvalor , --tiempo-modificacion=valor

Los valores posibles son más-reciente y conservar.

Si el valor es más-reciente, entonces el empaquetador intenta determinar la hora de modificación más reciente, entre todas las entradas disponibles en el archivo original, o la hora de modificación más reciente de todas las entradas disponibles en ese segmento. Este valor único se transmite como parte del segmento y se aplica a todas las entradas de cada segmento. Esto puede disminuir marginalmente el tamaño transmitido del archivo a costa de establecer todos los archivos instalados en una única fecha.

Si el valor es conservar, entonces se conservan las horas de modificación observadas en el JAR de entrada. Este es el valor por defecto.

-Parchivo , --pasar-archivo=archivo

Indica que un archivo debe pasarse byte a byte sin compresión. Repitiendo la opción, se pueden especificar varios archivos. No hay transformación de ruta, excepto que el separador de archivos del sistema se reemplaza por el separador de archivos JAR barra inclinada (/). Los nombres de archivo resultantes deben coincidir exactamente como cadenas con sus ocurrencias en el archivo JAR. Si archivo es un nombre de directorio, entonces todos los archivos debajo de ese directorio se pasan.
-Uacción , --atributo-desconocido=acción

Anula el comportamiento por defecto, lo que significa que el archivo de clase que contiene el atributo desconocido se pasa con la acción especificada. Los valores posibles para las acciones son error, eliminar, o pasar.

Si el valor es error, entonces la operación completa del comando pack200 falla con una explicación adecuada.

Si el valor es eliminar, entonces el atributo se elimina. Eliminar los atributos requeridos por la Máquina Virtual Java (JVM) puede causar fallos en el cargador de clases.

Si el valor es pasar, entonces la clase completa se transmite como si fuera un recurso.

-Cnombre-atributo=layout , --atributo-clase=nombre-atributo=acción

    Ver siguiente opción.

-Mnombre-atributo=layout ,

                        NAME
                    

                    
pack200-openjdk8 - empaqueta un archivo JAR en formato de archivo JAR empaquetado

                

                

                    

                        SYNOPSIS
                    

                    
pack200 [OPTIONS] [JAR-file] [PACK-file]

                    
pack200 [OPTIONS] [PACK-file]

                    
pack200 -m pack.properties [JAR-file] [PACK-file]

                    
pack200 -H[some-layout-string] [JAR-file] [PACK-file]

                

                

                    

                        DESCRIPTION
                    

                    
La utilidad pack200 empaqueta un archivo
                        JAR en formato de archivo JAR empaquetado. El archivo JAR
                        empaquetado resultante es más pequeño que el archivo JAR
                        original y puede ser descomprimido posteriormente por
                        la utilidad unpack200 para restaurar el archivo JAR
                        original.

                    
La utilidad pack200 se utiliza para
                        reducir el tamaño de las aplicaciones Java que se distribuyen
                        como archivos JAR. La reducción se consigue mediante la
                        aplicación de técnicas de empaquetado que son específicas
                        para el formato de archivo de clase de Java.

                    
El archivo JAR de entrada puede ser un archivo
                        JAR regular, un archivo tar, o un archivo tar comprimido
                        con gzip o un archivo comprimido con Bzip2. El archivo
                        de salida es un archivo JAR empaquetado que está comprimido
                        con gzip.
