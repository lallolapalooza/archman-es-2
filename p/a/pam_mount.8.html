Nombre

pam_mount - Un módulo PAM que puede montar volúmenes para la sesión de un usuario

Descripción_general

Este módulo está dirigido a entornos con servidores de archivos centrales que un usuario desea montar al iniciar sesión y desmontar al cerrar sesión, como estaciones (semi)diskless donde muchos usuarios pueden iniciar sesión y donde montar estáticamente todo /home desde un servidor es un riesgo de seguridad, o listar todos los volúmenes posibles en /etc/fstab no es factible.

  • Los usuarios pueden definir su propia lista de volúmenes sin tener que modificar archivos de configuración globales (posiblemente no escribibles).
  • Función de inicio de sesión único: el usuario solo necesita escribir la contraseña una vez (al iniciar sesión)
  • Proceso de montaje transparente
  • Sin contraseñas almacenadas
  • Los volúmenes se desmontan al cerrar sesión, liberando recursos del sistema y sin dejar datos expuestos.

El módulo también admite el montaje de sistemas de archivos locales de cualquier tipo que admita la utilidad mount normal, con código adicional para asegurarse de que ciertos volúmenes se configuren correctamente, ya que a menudo necesitan más que una simple llamada de montaje, como volúmenes cifrados. Esto incluye SMB/CIFS, FUSE, dm-crypt y LUKS.

Si tiene la intención de utilizar pam_mount para proteger volúmenes en su computadora utilizando un sistema de archivos cifrado, sepa que hay muchos otros problemas que debe considerar para proteger sus datos. Por ejemplo, probablemente querrá deshabilitar o cifrar su partición de intercambio (cryptoswap puede ayudarlo a hacerlo). No asuma que un sistema es seguro sin considerar cuidadosamente las posibles amenazas.

Configuración

El archivo de configuración principal para el módulo pam_mount es pam_mount.conf.xml. En la mayoría de las plataformas, este archivo se lee desde /etc/security/pam_mount.conf.xml. En OpenBSD, pam_mount lee su archivo de configuración desde /etc/pam_mount.conf.xml. Consulte pam_mount.conf(5) para documentar su uso.

Los usuarios individuales pueden definir volúmenes adicionales para montar si pam_mount.conf.xml lo permite (generalmente ~/.pam_mount.conf.xml). La palabra clave volume es la única palabra clave válida en estos archivos de configuración por usuario. Si el parámetro luserconf está establecido en pam_mount.conf.xml, permitiendo volúmenes definidos por el usuario, entonces los usuarios pueden montar y desmontar cualquier volumen que posean en cualquier punto de montaje que posean. En algunas configuraciones de sistemas de archivos, esto puede ser una falla de seguridad, por lo que los volúmenes definidos por el usuario no están permitidos por el ejemplo pam_mount.conf.xml distribuido con pam_mount.

Configuración_PAM

Además, debe incluir dos entradas en los archivos de configuración aplicables /etc/pam.d/servicio del sistema, como muestra el siguiente ejemplo:

    auth     required  pam_securetty.so
    auth     required  pam_pwdb.so shadow nullok
    auth     required  pam_nologin.so
+++ auth     optional  pam_mount.so
    account  required  pam_pwdb.so
    password required  pam_cracklib.so
    password required  pam_pwdb.so shadow nullok use_authtok
    session  required  pam_pwdb.so
    session  optional  pam_console.so
+++ session  optional  pam_mount.so

Cuando se usa "sufficient" en la segunda columna, debe asegurarse de que pam_mount se agregue antes de esta entrada. De lo contrario, pam_mount no se ejecutará si un módulo PAM anterior tiene éxito. Tenga también en cuenta las declaraciones "include". Estas hacen que PAM busque en el archivo especificado. Si hay una declaración "sufficient", la entrada pam_mount debe estar en el archivo incluido antes de la declaración "sufficient" o antes de la declaración "include".

Si utiliza pam_ldap, pam_winbind o cualquier otro servicio de autenticación que utilice la palabra clave sufficient de PAM, modele su configuración en el siguiente orden:

•••
account sufficient  pam_ldap.so
auth    required    pam_mount.so
auth    sufficient  pam_ldap.so use_first_pass
auth    required    pam_unix.so use_first_pass
session optional    pam_mount.so
•••

Esto permite:

1.
pam_mount, como primer módulo "auth", solicitará una contraseña y la exportará al sistema PAM.
2.
pam_ldap utilizará la contraseña del sistema PAM para intentar autenticar al usuario. Si esto tiene éxito, el usuario será autenticado. Si falla, pam_unix intentará autenticar.
3.
pam_unix intentará autenticar al usuario si pam_ldap falló. Si pam_unix falla, entonces se denegará la autenticación (debido a "required").

Alternativamente, lo siguiente es posible (¡gracias a Andrew Morgan por la sugerencia!):

auth [success=2 default=ignore] pam_unix2.so
auth [success=1 default=ignore] pam_ldap.so use_first_pass
auth requisite pam_deny.so
auth optional pam_mount.so

Puede parecer extraño, pero las tres primeras líneas harán que al menos uno de pam_unix2 o pam_ldap tenga éxito. Como puede ver, pam_mount se ejecutará después de la autenticación exitosa con estos subsistemas.

Discos_cifrados

pam_mount admite algunos tipos de criptografía. Los más comunes son encfs, dm-crypt y dm-crypt+LUKS.

El primero utiliza la capa FUSE; los archivos dentro del contenedor encfs se almacenan como archivos cifrados únicos en el host en un directorio preexistente. Si almacena muchos archivos, se recomienda tener un sistema de archivos inferior que sea sólido en esta área, como xfs, pero algún software y/o sus decisiones de partición pueden obligarlo a usar un sistema de archivos diferente. El mapeo 1:1 de archivos también permite que los archivos cifrados se sincronicen de manera razonablemente eficiente, por ejemplo, sin tener que abrir el contenedor cifrado. La creación se realiza a través de la herramienta encfs(1).

dm-crypt proporciona cifrado de sistema de archivos completo/partición completa. También puede crear un archivo contenedor, pero la idea es que se represente como un dispositivo de bloques en el que aún debe crear un sistema de archivos. De hecho, de esta manera puede seleccionar un sistema de archivos de su elección. La desventaja es que el encogimiento a menudo no es posible (no existe tal problema en encfs porque utiliza el sistema de archivos inferior). Los contenedores dm-crypt adecuados (y archivos auxiliares), utilizando dispositivos de bloques o archivos planos, se pueden crear utilizando la herramienta pmt-ehd(8).

pmt-ehd crea material de clave del sistema de archivos que es un montón de bytes aleatorios que se utilizarán para cifrar/descifrar el volumen. Este material en sí está cifrado con su propia contraseña; esto se hace para que pueda cambiar la contraseña sin tener que volver a cifrar todos sus datos.

LUKS es una extensión para dm-crypt para admitir contenedores de varias contraseñas. A menos que lo necesite específicamente, se recomiendan las dos soluciones anteriores.

NOTA: El archivo de clave que creará pmt-ehd(8) representa el material de clave del sistema de archivos cifrado con su contraseña. Por lo tanto, es seguro almacenarlo en un sistema de archivos no seguro.

Solución_de_problemas

Para asegurarse de que su sistema y, posiblemente, el servidor remoto estén correctamente configurados, debería intentar montar todos o algunos de los volúmenes manualmente, utilizando los mismos comandos y puntos de montaje proporcionados en pam_mount.conf.xml. Esto le ahorrará muchos dolores de cabeza, ya que es más difícil depurar el proceso de montaje a través de pam_mount.

Si puede montar los volúmenes manualmente pero no sucede a través de pam_mount, es posible que desee habilitar la opción "debug" en pam_mount.conf.xml para ver qué está sucediendo.

Verifique si el usuario es propietario del punto de montaje y tiene suficientes permisos sobre él. pam_mount verificará esto y se negará a montar el volumen remoto si el usuario no posee ese directorio.

Si pam_mount tiene problemas para desmontar volúmenes al cerrar sesión, habilite la variable debug. Esto hace que pam_mount se ejecute en el cierre de sesión y escriba su salida en el registro del sistema.

pam_mount(8)

pam_mount - PAM module for mounting filesystems (e.g. home directories, encrypted disks) when a user logs in.

Name

pam_mount - PAM module for mounting filesystems (e.g. home directories, encrypted disks) when a user logs in.

Overview

pam_mount is a PAM (Pluggable Authentication Modules) module that can be used to automatically mount user-specific filesystems upon login. This can include home directories, encrypted disks, or other network shares. It works by reading configuration from pam-mount.conf(5).

Configuration

The primary configuration file for pam_mount is /etc/pam-mount.conf. This file defines the mount points, the devices to be mounted, and the options to be used. The configuration is divided into sections, each specifying a particular mount operation. For detailed information on the configuration syntax and options, refer to the pam-mount.conf(5) man page.

PAM configuration

To enable pam_mount, you need to add it to your PAM configuration files. This typically involves editing files in /etc/pam.d/. The exact configuration depends on your system and the services you want to integrate with pam_mount. Common examples include:

  • Login shells: Add a line like session optional pam_mount.so to /etc/pam.d/login.
  • SSH: Add a line like session optional pam_mount.so to /etc/pam.d/sshd.
  • Graphical logins (e.g., GDM, LightDM): Add a line like session optional pam_mount.so to the relevant PAM configuration file (e.g., /etc/pam.d/gdm-password or /etc/pam.d/lightdm).

The optional keyword means that the module will not prevent login if it fails. You might consider using required if you want to enforce mounting as part of the authentication process, but this can lead to login failures if mounting fails for any reason.

Encrypted disks

pam_mount can be used to automatically unlock and mount encrypted home directories or other encrypted volumes upon login. This typically involves configuring LUKS (Linux Unified Key Setup) and then telling pam_mount to unlock and mount the encrypted device using the user's login credentials or a stored key.

A common scenario is encrypting the home directory. You would configure a LUKS-encrypted partition and then use pam_mount to unlock it. The /etc/pam-mount.conf would specify the encrypted device and the mount point (e.g., /home).

For detailed instructions on setting up encrypted home directories with pam_mount, please refer to the ArchWiki page on Dm-crypt.

Troubleshooting

If you encounter issues with pam_mount, consider the following:

  • Check logs: System logs (e.g., via journalctl -f or /var/log/syslog) can provide valuable information about errors encountered by pam_mount.
  • Verify configuration: Double-check your /etc/pam-mount.conf and PAM service configurations for syntax errors or incorrect paths.
  • Test manually: Try mounting the filesystem manually using the same options specified in pam_mount.conf to isolate whether the issue is with pam_mount itself or the underlying mounting process.
  • Permissions: Ensure that the user has the necessary permissions to access the devices and mount points.

Authors

  • The pam_mount module was originally written by Doug Ledford <dledford@redhat.com>.
  • It has been maintained and extended by many contributors since then.

Community Support

For further assistance and discussions, you can visit the official pam-mount website and its associated mailing lists or forums.
