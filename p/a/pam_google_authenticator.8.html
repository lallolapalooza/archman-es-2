NOMBRE

pam_google_authenticator - Módulo PAM para la autenticación de dos factores de Google

SINOPSIS

pam_google_authenticator.so [secret=archivo] [authtok_prompt=mensaje] [user=nombredeusuario] [no_strict_owner] [allowed_perm=0nnn] [debug] [try_first_pass|use_first_pass|forward_pass] [noskewadj] [no_increment_hotp] [nullok] [echo_verification_code]

DESCRIPCIÓN

El módulo pam_google_authenticator está diseñado para proteger la autenticación del usuario con un segundo factor, ya sea basado en tiempo (TOTP) o basado en contador (HOTP). Antes de iniciar sesión, se le pedirá al usuario tanto su contraseña como un código de un solo uso. Dichos códigos de un solo uso pueden generarse con la aplicación Google Authenticator, instalada en el dispositivo Android del usuario. Para generar y verificar respectivamente estos códigos de un solo uso, una clave secreta (generada aleatoriamente) debe compartirse entre el dispositivo en el que se generan los códigos de un solo uso y el sistema en el que está habilitado este módulo PAM. "A su vez,"

Dependiendo de su configuración (ver sección de opciones), este módulo requiere que un archivo secreto se configure manualmente para cada cuenta en el sistema. Este archivo secreto contiene la clave secreta y opciones específicas del usuario (ver google-authenticator(1)). A menos que se utilice la opción nullok, los intentos de autenticación serán rechazados si dicho archivo secreto no existe. Alternativamente, un administrador del sistema puede crear estos archivos secretos en nombre de los usuarios y luego comunicarles las claves secretas.

OPCIONES

secret=archivo
Especifica una ubicación no estándar para el archivo secreto.

Por defecto, el módulo PAM busca el archivo secreto en el archivo .google_authenticator dentro del directorio personal del usuario que inicia sesión. Esta opción anula esta ubicación.

La ubicación proporcionada puede incluir los siguientes atajos:

•
${USER} que se interpretará como el nombre de usuario.
•
${HOME} y ~ que se interpretarán como el directorio personal del usuario.
authtok_prompt=mensaje
Anula el mensaje predeterminado del token.

Tenga en cuenta que si hay espacios en el mensaje proporcionado, todo el argumento debe encerrarse entre corchetes.

user=nombredeusuario
Cambia a un usuario codificado previamente antes de realizar cualquier operación de archivo.
no_strict_owner
Deshabilita la verificación del propietario del archivo secreto.

Por defecto, el archivo secreto debe ser propiedad del usuario que inicia sesión. Esta opción deshabilita esta verificación.

allowed_perm=0nnn
Anula los permisos verificados del archivo secreto.

Por defecto, el archivo secreto solo debe ser legible por su propietario (es decir, modo 0600). Esta opción permite especificar un modo diferente para este archivo.

debug
Habilita mensajes de registro más detallados en syslog.
try_first_pass|use_first_pass|forward_pass
Opciones de apilamiento para este módulo PAM.

Dado que algunos clientes PAM no pueden solicitar al usuario más que la contraseña, se pueden utilizar las siguientes opciones de apilamiento:

•
try_first_pass: antes de solicitar al usuario el código de un solo uso, este módulo primero intenta usar la contraseña del módulo apilado anterior en caso de que también satisfaga a este módulo.
•
use_first_pass: fuerza a este módulo a usar la contraseña de un módulo apilado anterior. Con esta opción, este módulo nunca solicitará al usuario el código de un solo uso. Por lo tanto, si no hay un código de un solo uso válido disponible, se le negará el acceso al usuario.
•
forward_pass: consulta al usuario tanto la contraseña del sistema como el código de verificación en una sola solicitud. La contraseña del sistema se reenvía luego al siguiente módulo PAM, que deberá configurarse con la opción use_first_pass, o la opción try_first_pass.
noskewadj
No ajusta la desviación horaria automáticamente.

Por defecto, el módulo PAM intenta compensar la desviación horaria entre el servidor y el dispositivo en el que se generan los códigos de un solo uso. Esta opción deshabilita este comportamiento.

Tenga en cuenta que esta opción solo es relevante para el modo basado en tiempo (TOTP).

no_increment_hotp
No incrementa el contador para intentos fallidos.

En algunas circunstancias, las contraseñas fallidas todavía obtienen una solicitud de OTP. Esta opción deshabilita la incrementación del contador en tales situaciones.

Tenga en cuenta que esta opción solo es relevante para el modo basado en contador (HOTP).

nullok
Permite a los usuarios iniciar sesión sin OTP si aún no han configurado la OTP.

Durante el proceso inicial de implementación, es posible que todos los usuarios aún no hayan creado una clave secreta. Esta opción les permite iniciar sesión, incluso si el archivo secreto no existe.

echo_verification_code
Muestra el código de verificación cuando el usuario lo ingresa.

TIPO DE MÓDULO PROPORCIONADO

Solo se proporciona el tipo de módulo auth.

VALORES DE RETORNO

PAM_SUCCESS
El código de un solo uso proporcionado es correcto o es un código de emergencia válido.
PAM_IGNORE
Este módulo se ignora.
PAM_AUTH_ERR
El código de un solo uso proporcionado no es correcto y no es un código de emergencia válido, o se encontró un error.

EJEMPLOS

Las siguientes líneas pueden usarse para habilitar este módulo PAM:

•
auth required pam_google_authenticator.so no_increment_hotp # Asegúrate de que el contador (para el modo HOTP) no se incremente para intentos fallidos.
•
auth required pam_google_authenticator.so nullok # Permite a los usuarios iniciar sesión si sus archivos secretos no existen
•
auth required pam_google_authenticator.so secret=/var/unencrypted-home/${USER}/.google_authenticator # Almacena los archivos secretos en una ubicación específica
•
auth required pam_google_authenticator.so [authtok_prompt=Tu token secreto: ] # Usa un mensaje específico
•
auth required pam_google_authenticator.so noskewadj # No compensa la desviación horaria automáticamente

NOTAS DE SEGURIDAD

Para una máxima seguridad, asegúrese de que se soliciten tanto la contraseña como el código de un solo uso, incluso si la contraseña y/o el código de un solo uso son incorrectos. Esto significa que al menos el primero de pam_unix.so (o cualquier otro módulo utilizado para verificar contraseñas) y pam_google_authenticator.so debe configurarse como required, no como requisite.
