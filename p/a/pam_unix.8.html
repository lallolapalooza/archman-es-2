PAM_UNIX(8) Manual de Linux-PAM PAM_UNIX(8)

NOMBRE

pam_unix - Módulo para autenticación de contraseñas tradicional

SINOPSIS

pam_unix.so [...]

DESCRIPCIÓN

Este es el módulo de autenticación estándar de Unix. Utiliza llamadas estándar de las bibliotecas del sistema para recuperar y establecer información de cuenta, así como para la autenticación. Normalmente, esto se obtiene del archivo /etc/passwd y del archivo /etc/shadow, si shadow está habilitado.

El componente de cuenta realiza la tarea de establecer el estado de la cuenta y la contraseña del usuario basándose en los siguientes elementos de shadow: expire, last_change, max_change, min_change, warn_change. En el caso de este último, puede ofrecer consejos al usuario sobre cómo cambiar su contraseña o, a través de PAM_AUTHTOKEN_REQD, retrasar la concesión de servicio al usuario hasta que haya establecido una nueva contraseña. Las entradas listadas anteriormente se documentan en la página del manual de shadow(5). Si el registro del usuario no contuviera una o más de estas entradas, la comprobación de shadow correspondiente no se realizaría.

El componente de autenticación realiza la tarea de comprobar las credenciales (contraseña) del usuario. La acción predeterminada de este módulo es no permitir al usuario el acceso a un servicio si su contraseña oficial está en blanco.

Se proporciona un binario auxiliar, unix_chkpwd(8), para comprobar la contraseña del usuario cuando está almacenada en una base de datos protegida contra lectura. Este binario es muy simple y solo comprobará la contraseña del usuario que lo invoca. Es llamado de forma transparente en nombre del usuario por el componente de autenticación de este módulo. De esta manera, es posible que aplicaciones como xlock(1) funcionen sin necesidad de ser setuid-root. El módulo, por defecto, desactivará temporalmente el manejo de SIGCHLD durante la ejecución del binario auxiliar. Esto es generalmente lo correcto, ya que muchas aplicaciones no están preparadas para manejar esta señal de un hijo que no sabían que había sido fork()ed. El argumento del módulo noreap puede utilizarse para suprimir este blindaje temporal y puede ser necesario para su uso con ciertas aplicaciones.

La longitud máxima de una contraseña soportada por el módulo pam_unix a través del binario auxiliar es PAM_MAX_RESP_SIZE, actualmente 512 bytes. El resto de la contraseña proporcionada por la función de conversación al módulo será ignorado.

El componente de contraseña de este módulo realiza la tarea de actualizar la contraseña del usuario. El hash de cifrado predeterminado se toma de la variable ENCRYPT_METHOD de /etc/login.defs

El componente de sesión de este módulo registra cuándo un usuario inicia o abandona el sistema.

Los argumentos restantes, soportados por otras funciones de este módulo, se ignoran silenciosamente. Otros argumentos se registran como errores a través de syslog(3).

OPCIONES

debug

Activa la depuración a través de syslog(3).

audit

Un poco más extremo que debug.

quiet

Desactiva los mensajes informativos, en concreto los mensajes sobre la apertura y cierre de sesión a través de syslog(3).

nullok

La acción predeterminada de este módulo es no permitir al usuario el acceso a un servicio si su contraseña oficial está en blanco. El argumento nullok anula este valor predeterminado.

nullresetok

Permite a los usuarios autenticarse con una contraseña en blanco si se fuerza el restablecimiento de la contraseña, incluso si nullok no está establecido. Si no se requiere el restablecimiento de la contraseña y nullok no está establecido, se denegará la autenticación con contraseña en blanco.

try_first_pass

Antes de solicitar al usuario su contraseña, el módulo intenta primero la contraseña del módulo apilado anterior, en caso de que esta también satisfaga a este módulo.

use_first_pass

El argumento use_first_pass fuerza al módulo a usar la contraseña de un módulo apilado anterior y nunca solicitará al usuario; si no hay contraseña disponible o la contraseña no es apropiada, se denegará el acceso al usuario.

nodelay

Este argumento se puede utilizar para disuadir al componente de autenticación de solicitar un retraso en caso de que la autenticación en su conjunto falle. La acción predeterminada es que el módulo solicite un retraso-en-caso-de-fallo del orden de dos segundos.

use_authtok

Al cambiar contraseñas, obliga al módulo a establecer la nueva contraseña a la proporcionada por un módulo de password apilado anteriormente (esto se utiliza en el ejemplo de apilamiento del módulo pam_passwdqc documentado a continuación).

authtok_type=type

Este argumento se puede utilizar para modificar la solicitud de contraseña al cambiar contraseñas para incluir el tipo de contraseña. Vacío por defecto.

nis

Se utiliza RPC de NIS para establecer nuevas contraseñas.

remember=n

Las últimas n contraseñas de cada usuario se guardan en /etc/security/opasswd para forzar el historial de cambios de contraseña y evitar que el usuario alterne entre la misma contraseña con demasiada frecuencia. El algoritmo de hash de contraseñas MD5 se utiliza para almacenar las contraseñas antiguas. En lugar de esta opción, se debe utilizar el módulo pam_pwhistory.

shadow

Intenta mantener un sistema basado en shadow.

md5

Cuando un usuario cambie su contraseña la próxima vez, la cifrará con el algoritmo MD5.

bigcrypt

Cuando un usuario cambie su contraseña la próxima vez, la cifrará con el algoritmo DEC C2.

sha256

Cuando un usuario cambie su contraseña la próxima vez, la cifrará con el algoritmo SHA256. El algoritmo SHA256 debe ser soportado por la función crypt(3).

sha512

Cuando un usuario cambie su contraseña la próxima vez, la cifrará con el algoritmo SHA512. El algoritmo SHA512 debe ser soportado por la función crypt(3).

blowfish

Cuando un usuario cambie su contraseña la próxima vez, la cifrará con el algoritmo blowfish. El algoritmo blowfish debe ser soportado por la función crypt(3).

gost_yescrypt

Cuando un usuario cambie su contraseña la próxima vez, la cifrará con el algoritmo gost-yescrypt. El algoritmo gost-yescrypt debe ser soportado por la función crypt(3).

yescrypt

Cuando un usuario cambie su contraseña la próxima vez, la cifrará con el algoritmo yescrypt. El algoritmo yescrypt debe ser soportado por la función crypt(3).

rounds=n

Establece el número opcional de rondas de los algoritmos de hash de contraseñas SHA256, SHA512, blowfish, gost-yescrypt y yescrypt a n.

broken_shadow

Ignora errores al leer información de shadow para usuarios en el módulo de gestión de cuentas.

minlen=n

Establece una longitud mínima de contraseña de n caracteres. El máximo para contraseñas basadas en DES crypt es de 8 caracteres.

no_pass_expiry

Cuando se establece, ignora la expiración de la contraseña definida por la entrada shadow del usuario. La opción tiene efecto solo en caso de que pam_unix no se haya utilizado para la autenticación o haya devuelto un fallo de autenticación, lo que significa que otra fuente o método de autenticación tuvo éxito. El ejemplo puede ser la autenticación de clave pública en sshd. El módulo devolverá PAM_SUCCESS en lugar del eventual PAM_NEW_AUTHTOK_REQD o PAM_AUTHTOK_EXPIRED.

Los argumentos inválidos se registran con syslog(3).

TIPOS DE MÓDULOS PROPORCIONADOS

Todos los tipos de módulos (account, auth, password y session) son proporcionados.

VALORES DE RETORNO

PAM_IGNORE

Ignorar este módulo.

EJEMPLOS

Un ejemplo de uso para /etc/pam.d/login sería:

# Autenticar al usuario
auth       required   pam_unix.so
# Asegurarse de que la cuenta y la contraseña del usuario siguen activas
account    required   pam_unix.so
# Cambiar la contraseña del usuario, pero primero comprobar su fuerza
# con pam_passwdqc(8)
password   required   pam_passwdqc.so config=/etc/pass

continuando con:

password   optional   pam_unix.so remember=5 minlen=8 sha512

Finalmente, la entrada de sesión:

session    required   pam_unix.so

En este ejemplo, el módulo pam_unix se utiliza para la autenticación, gestión de cuentas, cambio de contraseñas y registro de sesiones. Se aplica un módulo de política de contraseñas (pam_passwdqc) antes de que el módulo pam_unix cambie la contraseña.

El uso de remember=5 hace que se mantenga un historial de las últimas 5 contraseñas. El uso de minlen=8 impone una longitud mínima de 8 caracteres. Y la opción sha512 especifica que la nueva contraseña debe ser cifrada utilizando el algoritmo SHA512.

VER TAMBIÉN

pam_unix(8) — Linux-PAM manual

NAME

pam_unix — traditional UNIX authentication management module

SYNOPSIS

pam_unix.so [option ...]

DESCRIPTION

The pam_unix module is a module that handles authentication, account management, session management, and password management tasks using the traditional UNIX authentication files: /etc/passwd, /etc/shadow, and /etc/group.

It is the default module for many service providers, and is typically used to provide backward compatibility with older UNIX systems.

The pam_unix module can be configured to handle several PAM management groups: auth, account, session, and password.

OPTIONS

use_first_pass
This option can be used with the auth and password management groups. If the PAM stack has already obtained a password for the user (e.g., from a previous module in the stack), this option will cause pam_unix to use that password instead of prompting the user for it. This can be useful for services that require multiple authentication steps.
use_authtok
This option is similar to use_first_pass, but it is intended for the password management group. It instructs pam_unix to use the authentication token (password) obtained by a previous module in the stack as the new password. This is typically used when changing a user's password.
nullok
If this option is present, authentication will succeed even if the user does not have a password set in /etc/shadow. This is often used for services that do not require password authentication, or for system accounts that are not meant to be logged into directly.
yescrypt
This option forces the use of the yescrypt password hashing algorithm when storing new passwords. By default, pam_unix uses SHA-512 when supported, otherwise MD5. Using this option ensures that yescrypt is used, which is considered more secure than SHA-512 and MD5.
sha512
This option forces the use of the SHA-512 password hashing algorithm when storing new passwords. This is a strong hashing algorithm and is widely supported.
md5
This option forces the use of the MD5 password hashing algorithm when storing new passwords. MD5 is considered weak and should generally be avoided if possible.
obscure
If this option is present, the module will check the complexity of the new password being set. It will reject passwords that are too simple or too similar to the username. This option is only relevant for the password management group.
rounds=N
This option allows you to specify the number of hashing rounds for password encryption. A higher number of rounds increases security but also increases the time it takes to encrypt and verify passwords. The default value is usually determined by the system configuration or the hashing algorithm used.
remember=N
This option, when used with the password management group, enforces a password history policy. It prevents users from reusing the last N passwords. The history is typically stored in /etc/security/opasswd.
discard_expired_creds
This option is used with the session management group. If a user's credentials have expired, this option causes the module to discard them and return an error, preventing the user from logging in. This is useful for enforcing password expiration policies.

MODULE TYPES PROVIDED

Each module can be used to satisfy the requirements of a PAM application in any of the following module types:

auth, account, session, password.

RETURN VALUES

In addition to the standard PAM return values, the following may also be returned:

PAM_USER_UNKNOWN

The username is unknown to the system.

PAM_AUTH_ERR

Authentication failure. This could be due to an incorrect password, an expired account, or other authentication-related issues.

PAM_ACCT_EXPIRED

The user's account has expired.

PAM_NEW_AUTHTOK_REQUIR'D

A new authentication token (password) is required from the user.

PAM_OLDAUTHTOK_ERR

The user's old authentication token (password) was incorrect.

PAM_SUFFICIENT

If the module is configured as sufficient and it succeeds, PAM will not process any further modules in the current stack for this management group.

PAM_IGNORE

If the module is configured as optional and it fails, PAM will ignore the failure and continue processing other modules.

EXAMPLES

The following is an example of how to configure the pam_unix module in a PAM configuration file (e.g., /etc/pam.d/login):

auth       required   pam_unix.so nullok
account    required   pam_unix.so
password   required   pam_unix.so use_authtok nullok yescrypt
session    required   pam_unix.so

In this example:

  • The auth line indicates that pam_unix is required for authentication. nullok allows users without passwords to authenticate.
  • The account line indicates that pam_unix is required for account management (e.g., checking for expired accounts).
  • The password line indicates that pam_unix is required for password management. use_authtok allows the module to use an already obtained token, nullok permits users without passwords, and yescrypt forces the use of the yescrypt hashing algorithm for new passwords.
  • The session line indicates that pam_unix is required for session management (e.g., logging user access).

Another example, for a service that might use cached credentials:

password   requisite  pam_unix.so use_first_pass

This configuration would attempt to use a previously supplied password to change the user's password, without prompting if successful.
