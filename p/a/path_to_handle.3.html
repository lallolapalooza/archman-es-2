DESCRIPCIÓN

Estas funciones proporcionan una forma de realizar ciertas operaciones del sistema de archivos sin usar un descriptor de archivo para acceder a los objetos del sistema de archivos. Están destinadas a ser utilizadas por un conjunto limitado de utilidades del sistema, como programas de copia de seguridad. Solo son compatibles con el sistema de archivos XFS. Enlace con la biblioteca libhandle para acceder a estas funciones.

Un identificador, hanp, identifica de forma única un objeto del sistema de archivos o un sistema de archivos completo. Hay uno y solo un identificador por sistema de archivos u objeto del sistema de archivos. Los identificadores constan de un número de bytes. El tamaño de un identificador (es decir, el número de bytes que lo componen) varía según el tipo de identificador y puede variar para diferentes objetos del mismo tipo. El contenido de un identificador es opaco para las aplicaciones. Dado que los tamaños de los identificadores varían y sus contenidos son opacos, los identificadores se describen mediante dos cantidades, un puntero (hanp) y un tamaño (hlen). El tamaño, hlen, indica el número de bytes en el identificador a los que apunta el puntero.

La función path_to_handle() devuelve el identificador del objeto dado por el argumento path. Si el último componente del nombre de ruta es un enlace simbólico, el identificador devuelto es el del propio enlace.

La función path_to_fshandle() devuelve el identificador del sistema de archivos en el que reside el objeto dado por el argumento path.

La función fd_to_handle() devuelve el identificador del objeto al que hace referencia el argumento fd, que debe ser un descriptor de archivo válido.

La función handle_to_fshandle() devuelve el identificador del sistema de archivos en el que reside el objeto al que hace referencia el identificador dado por los argumentos hanp y hlen.

La función open_by_handle() abre un descriptor de archivo para el objeto al que hace referencia un identificador. Es análoga e idéntica a open(2) con la excepción de aceptar identificadores en lugar de nombres de ruta.

La función readlink_by_handle() devuelve el contenido de un enlace simbólico al que hace referencia un identificador.

La función attr_multi_by_handle() manipula múltiples atributos de usuario en un objeto del sistema de archivos. Es análoga e idéntica a attr_multif(3) excepto que se especifica un identificador en lugar de un descriptor de archivo.

La función attr_list_by_handle() devuelve los nombres de los atributos de usuario de un objeto del sistema de archivos. Es análoga e idéntica a attr_listf(3) excepto que se especifica un identificador en lugar de un descriptor de archivo.

La función fssetdm_by_handle() establece los campos di_dmevmask y di_dmstate en un inodo en disco XFS. Es análoga al comando XFS_IOC_FSSETDM xfsctl(3), excepto que se especifica un identificador en lugar de un archivo. Esta función no es compatible con Linux.

La función free_handle() libera el almacenamiento asignado para los identificadores devueltos por las siguientes funciones: path_to_handle(), path_to_fshandle(), fd_to_handle(), y handle_to_fshandle().

La función getparents_by_handle() devuelve una matriz de estructuras parent_t para cada enlace duro al inodo representado por el identificador dado. La estructura padre codifica el número de inodo padre, el número de generación y el nombre base del enlace. Esta función no es operativa en Linux.

La función getparentpaths_by_handle() es idéntica a la función getparents_by_handle() excepto que en lugar de devolver el nombre base, devuelve la ruta del enlace hasta el punto de montaje. Esta función tampoco es operativa en Linux.

VALOR DE RETORNO

La función free_handle() no tiene indicación de fallo. Las otras funciones devuelven el valor 0 al proceso que llama si tienen éxito; de lo contrario, devuelven el valor -1 y establecen errno para indicar el error.

ERRORES

EACCES
Se denegó el permiso de búsqueda para un componente de path.
EBADF
fd no es un descriptor de archivo válido y abierto.
EFAULT
Un argumento apuntaba a una dirección inválida.
EINVAL
path está en un sistema de archivos que no admite estas funciones.
ELOOP
Se encontraron demasiados enlaces simbólicos al traducir el nombre de ruta.
ENAMETOOLONG
Un componente de path o la longitud total de path superan los límites del sistema de archivos.
ENOENT
Un componente de path no existe.
EPERM
El llamante no tiene privilegios suficientes.

VER TAMBIÉN

open(2), readlink(2), attr_multi(3), attr_list(3), xfsctl(3), xfs(5).

path_to_handle

path_to_handle(3) - obtener un manejador de ruta de un nombre de archivo

NOMBRE

path_to_handle - obtener un manejador de ruta de un nombre de archivo

SINOPSIS C

#include <fcntl.h>

int path_to_handle(const char *pathname, size_t struct_size,
                   int flags, struct file_handle *handle);
int name_to_handle_at(int dirfd, const char *pathname,
                      struct file_handle *handle, size_t *cookie, int flags);

DESCRIPCIÓN

Estas dos funciones de interfaz de sistema pueden ser utilizadas para obtener un manejador de archivo (file handle) para un nombre de archivo determinado.

Un manejador de archivo es una representación de un archivo que puede ser pasado entre diferentes sistemas de archivos y que se puede utilizar para abrir un archivo sin necesidad de conocer su nombre de ruta.

La función path_to_handle toma un nombre de ruta pathname y un tamaño de estructura struct_size. El parámetro flags puede ser 0 o PATH_TO_HANDLE_NO_MODIFY. El manejador de archivo resultante se devuelve en la estructura handle. El campo handle_bytes de la estructura handle debe estar configurado al tamaño total del búfer handle_buf. Si el tamaño especificado en struct_size es menor que el tamaño del manejador de archivo devuelto, se devolverá -1 y EOVERFLOW.

La función name_to_handle_at es una variante de path_to_handle que opera en un directorio especificado por dirfd, de forma similar a openat(2). El parámetro pathname puede ser relativo o absoluto. El parámetro cookie es un puntero a un puntero a void. Si el sistema de archivos soporta la reubicación de archivos en el tiempo de ejecución, se puede pasar un puntero a un puntero a void para el parámetro cookie. En este caso, name_to_handle_at almacenará un puntero a un búfer de cookie en *cookie, que contendrá información sobre la posición del archivo dentro del sistema de archivos. El parámetro flags puede ser 0 o HANDLE_TO_NAME_NO_REMOTE.

VALOR DE RETORNO

En caso de éxito, path_to_handle y name_to_handle_at devuelven 0. En caso de error, devuelven -1 y establecen errno adecuadamente.

ERRORES

Los siguientes valores de errno pueden ser establecidos por estas llamadas:

EBADF
El descriptor de archivo dirfd no es válido.
EACCES
Permisos de acceso denegados.
EFAULT
pathname o handle apuntan fuera del espacio de direcciones del usuario.
EINVAL
El tamaño de la estructura handle es inválido, o el sistema de archivos no soporta manejadores de archivo.
EISDIR
pathname apunta a un directorio.
EMLINK
El sistema de archivos tiene demasiados enlaces.
ENAMETOOLONG
El nombre de ruta pathname es demasiado largo.
ENOENT
No se encontró el archivo o directorio.
ENOMEM
Memoria insuficiente para asignar el manejador de archivo.
ENOTDIR
Un componente de pathname no es un directorio, o dirfd no se refiere a un directorio.
ENXIO
El archivo no existe y no se puede crear.
EOVERFLOW
El tamaño especificado para el manejador de archivo es menor que el tamaño real requerido.
EROFS
El sistema de archivos está montado como solo lectura.
ETXTBSY
El archivo está en uso y no se puede acceder.
ELOOP
Se encontraron demasiados enlaces simbólicos durante la resolución de pathname.

VER TAMBIÉN

openat(2), open(2), file-handle(7)
