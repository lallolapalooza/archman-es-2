passt(1) Manual de Comandos Generales passt(1)

NOMBRE

passt - Conectividad de red en modo usuario sin privilegios para máquinas virtuales
pasta - Conectividad de red en modo usuario sin privilegios para espacios de nombres de red

SINOPSIS

passt [OPCIÓN]...
pasta [OPCIÓN]... [COMANDO [ARG]...]
pasta [OPCIÓN]... PID
pasta [OPCIÓN]... --netns [RUTA|NOMBRE]

DESCRIPCIÓN

passt

passt (Plug A Simple Socket Transport) proporciona conectividad de red completa y cuasi-nativa a máquinas virtuales en modo usuario sin requerir ninguna capacidad o privilegio.

El plano de datos implementa una capa de traducción entre una interfaz de red virtual de Capa 2 y sockets nativos de Capa 4 (TCP, UDP, ping) en el host, dando la ilusión de que los procesos de aplicación que residen en el guest se ejecutan en el host local, desde una perspectiva de red.

Las implementaciones integradas de ARP, DHCP, NDP y DHCPv6 están diseñadas para proporcionar al guest una configuración de red que se asemeja estrechamente a la configuración nativa del host. Con las opciones predeterminadas, el guest y el host comparten direcciones IP, rutas y enlaces de puertos.

El reenvío y la traducción de puertos permiten que los servicios de red que se ejecutan en el guest sean accesibles tanto desde hosts locales como remotos.

A diferencia de slirp4netns(1), passt no implementa una pila TCP completa: la capa de traducción TCP no tiene almacenamiento en búfer de datos con estado y opera reflejando los parámetros observados de un par (tamaño de la ventana de congestión, datos reconocidos, etc.) al par correspondiente.

Actualmente, el único hipervisor compatible es qemu(1), que se conecta a passt mediante un socket de dominio UNIX. Esto es compatible a partir de qemu 7.2. Para versiones anteriores de qemu, consulte el script de qrap(1).

pasta

pasta (Pack A Subtle Tap Abstraction) proporciona una funcionalidad equivalente a los espacios de nombres de red, como la que ofrece passt para máquinas virtuales.

Si se proporcionan PID o --netns, pasta se asocia a un espacio de nombres de usuario y de red existente. De lo contrario, pasta crea un nuevo espacio de nombres de usuario y de red, y lanza el comando dado o un shell predeterminado dentro de este contexto. Se crea un dispositivo tap dentro del espacio de nombres de red para proporcionar conectividad de red.

Solo para tráfico TCP y UDP local, pasta también implementa una ruta de omisión que mapea directamente los sockets de Capa 4 entre los espacios de nombres init y destino, por razones de rendimiento.

OPCIONES

A menos que se indique lo contrario a continuación, si se proporcionan opciones conflictivas o múltiples, la última prevalece.

-d, --debug
Sé verboso, no registres en el registrador del sistema.
--trace
Sé extra verboso, muestra paquetes individuales. Implica --debug.
--stats RETRASO
Muestra estadísticas de eventos con un mínimo de RETRASO segundos entre actualizaciones. Si no hay eventos, las estadísticas no se muestran.
-q, --quiet
No imprimas mensajes informativos.
-f, --foreground
No se ejecute en segundo plano. Esto implica que el proceso no se mueve a un espacio de nombres PID separado después de iniciarse, ya que el PID en sí no puede cambiar. El valor predeterminado es bifurcarse en segundo plano.
-e, --stderr (OBSOLETO)
Esta opción no tiene ningún efecto y se mantiene solo por motivos de compatibilidad.

Tenga en cuenta que esta opción de configuración está obsoleta y se eliminará en una versión futura.

-l, --log-file RUTA
Registrar en el archivo RUTA, y no en el registrador del sistema.

Especificar esta opción varias veces no genera múltiples archivos de registro: la última opción especificada tiene efecto.

--log-size TAMAÑO
Limita el tamaño del archivo de registro a TAMAÑO bytes. Cuando el archivo de registro está lleno, se hace espacio para nuevas entradas eliminando las antiguas del principio. Este límite es obligatorio. El valor predeterminado es 1048576 (1 MiB).
--runas UID|UID:GID|LOGIN|LOGIN:GROUP
Intenta cambiar al UID y grupo correspondiente dados si se proporciona UID, o al UID y GID dados si se proporcionan ambos. Alternativamente, se puede pasar el nombre de inicio de sesión o el nombre de inicio de sesión y el nombre de grupo. Esto requiere privilegios (ya sea UID efectivo inicial 0 o capacidad CAP_SETUID) para funcionar. El valor predeterminado es cambiar al usuario nobody si se inicia como root.
-h, --help
Muestra un mensaje de ayuda y sale.
--version
Muestra la versión y sale.
-p, --pcap archivo
Captura paquetes de red que miran al tap (es decir, del lado del guest o del lado del espacio de nombres) a archivo en formato pcap.

Especificar esta opción varias veces no genera múltiples archivos de captura: la última opción especificada tiene efecto.

-P, --pid archivo
Escribe el propio PID en archivo una vez que se completa la inicialización, antes de bifurcarse en segundo plano (si está configurado para hacerlo).
-m, --mtu mtu
Asigna mtu a través de DHCP (opción 26) y NDP (tipo de opción 5). Un valor cero deshabilita la asignación. Por defecto, el MTU anunciado es de 65520 bytes, es decir, el MTU máximo de 802.3 menos la longitud de una cabecera 802.3, redondeado a 32 bits (palabras IPv4).
-a, --address dir
Asigna la dirección IPv4 dir a través de DHCP (yiaddr), o dir a través de DHCPv6 (opción 5) y un prefijo basado en dir a través de anuncios de router NDP (tipo de opción 3) para una dir IPv6. Esta opción se puede especificar cero (para valores predeterminados) a dos veces (una vez para IPv4, una vez para IPv6). Por defecto, las direcciones IPv4 e IPv6 asignadas se toman de las interfaces del host con la primera ruta predeterminada, si la hay, para la versión IP correspondiente. Si no hay rutas predeterminadas disponibles y hay alguna interfaz con alguna ruta para una versión IP dada, se elegirá la primera de estas interfaces en su lugar. Si no existe dicha interfaz, se asignará la dirección de enlace local 169.254.2.1 para IPv4, y no se asignará ninguna dirección adicional para IPv6.
-n, --netmask mascara
Asigna la máscara de red IPv4 mascara, expresada en notación decimal o número de bits, a través de DHCP (opción 1). Por defecto, se utiliza la máscara de red asociada a la dirección del host que coincide con la asignada. Si no hay ninguna dirección coincidente en el host, la máscara de red se determina de acuerdo con el bloque CIDR de la dirección asignada (RFC 4632).
-M, --mac-addr dir
Utiliza la dirección MAC de origen dir al comunicarse con el guest o con el espacio de nombres de destino. El valor predeterminado son las direcciones MAC administradas localmente 9a:55:9a:55:9a:55.
-g, --gateway dir
Asigna la dirección IPv4 dir como puerta de enlace predeterminada a través de DHCP (opción 3), o la dirección IPv6 dir como origen para los mensajes de Anuncio de Router NDP y DHCPv6. Esta opción se puede especificar cero (para valores predeterminados) a dos veces (una vez para IPv4, una vez para IPv6). Por defecto, las puertas de enlace IPv4 e IPv6 se toman de la interfaz del host con la primera ruta predeterminada, si la hay, para la versión IP correspondiente. Si la ruta predeterminada es multipath, la puerta de enlace es el primer enrutador de salto siguiente devuelto por el kernel que tiene el peso más alto en el conjunto de rutas. -i, --interface nombre
Utiliza la interfaz del host nombre para derivar direcciones y rutas. Por defecto se utilizan las interfaces especificadas por --outbound-if4 y --outbound-if6, para direcciones y rutas IPv4 e IPv6 respectivamente.

Si no se especifican interfaces, se selecciona la interfaz con las primeras rutas por defecto para cada versión de IP. Si no hay rutas por defecto disponibles y solo hay una interfaz con alguna ruta, se elegirá esa interfaz en su lugar. Si no existe tal interfaz, las interfaces del host serán ignoradas a efectos de asignación de direcciones y rutas, y se usarán direcciones de enlace local en su lugar.

-o, --outbound dir
Utiliza una dirección dir IPv4 como dirección de origen para conexiones TCP salientes IPv4, flujos UDP, solicitudes ICMP, o una dirección dir IPv6 para las correspondientes IPv6, vinculando los sockets salientes a ella. Esta opción se puede especificar de cero (para valores predeterminados) a dos veces (una para IPv4, una para IPv6). Por defecto, la dirección de origen es seleccionada por las tablas de enrutamiento.
--outbound-if4 nombre
Vincula los sockets salientes IPv4 a la interfaz del host nombre y, a menos que se especifique otra interfaz mediante -i, --interface, utiliza esta interfaz para derivar direcciones y rutas IPv4.

Por defecto, se selecciona la interfaz proporcionada por la ruta por defecto. Si no hay rutas por defecto disponibles y solo hay una interfaz con alguna ruta, se elegirá esa interfaz en su lugar. Si no existe tal interfaz, los sockets salientes no se vincularán a ninguna interfaz específica.

--outbound-if6 nombre
Vincula los sockets salientes IPv6 a la interfaz del host nombre y, a menos que se especifique otra interfaz mediante -i, --interface, utiliza esta interfaz para derivar direcciones y rutas IPv6.

Por defecto, se selecciona la interfaz proporcionada por la ruta por defecto. Si no hay rutas por defecto disponibles y solo hay una interfaz con alguna ruta, se elegirá esa interfaz en su lugar. Si no existe tal interfaz, los sockets salientes no se vincularán a ninguna interfaz específica.

-D, --dns dir
Instruye al invitado (a través de DHCP, DHVPv6 o NDP) para que utilice dir (IPv4 o IPv6) como servidor de nombres, según lo configurado (ver opciones --no-dhcp-dns, --dhcp-dns) en lugar de leer las direcciones de /etc/resolv.conf. Esta opción se puede especificar varias veces. Especificar -D none deshabilita el uso de direcciones DNS por completo. A diferencia de las direcciones de /etc/resolv.conf, dir se proporciona al invitado sin remapeo. Por ejemplo, --dns 127.0.0.1 instruirá al invitado a usarse a sí mismo como servidor de nombres, no al host.
--dns-forward dir
Mapea dir (IPv4 o IPv6) visto desde el invitado o el espacio de nombres al servidor de nombres (con la versión IP correspondiente) especificado por la opción --dns-host. Solo mapea tráfico UDP y TCP al puerto 53 o al puerto 853. Las respuestas se traducen de vuelta con un mapeo inverso. Esta opción se puede especificar de cero a dos veces (una para IPv4, una para IPv6).
--dns-host dir
Configura el servidor de nombres del host al que se redirigirán las consultas del invitado o del espacio de nombres a la dirección --dns-forward. Esta opción se puede especificar de cero a dos veces (una para IPv4, una para IPv6). Por defecto, el primer servidor de nombres de /etc/resolv.conf del host.
-S, --search lista
Utiliza la lista separada por espacios para fines de DHCP, DHCPv6 y NDP, en lugar de leer las entradas de /etc/resolv.conf. Consulte las opciones --no-dhcp-search y --dhcp-search. --search none deshabilita la lista de búsqueda de dominios DNS por completo (si necesita buscar un dominio llamado "none", puede usar --search none.).
--no-dhcp-dns
En modo passt, no asigna direcciones IPv4 a través de DHCP (opción 23) ni direcciones IPv6 a través de Anuncios de Router NDP (tipo de opción 25) y DHCPv6 (opción 23) como resolutores DNS. Por defecto, se pasan todas las direcciones configuradas.
--dhcp-dns
En modo pasta, asigna direcciones IPv4 a través de DHCP (opción 23) o direcciones IPv6 a través de Anuncios de Router NDP (tipo de opción 25) y DHCPv6 (opción 23) como resolutores DNS. Por defecto, las direcciones configuradas, si las hay, no se pasan.
--no-dhcp-search
En modo passt, no envía las direcciones de la lista de búsqueda de dominios DNS a través de DHCP (opción 119), a través de Anuncios de Router NDP (tipo de opción 31) y DHCPv6 (opción 24). Por defecto, se pasa la lista de búsqueda de dominios DNS resultante de la configuración.
--dhcp-search
En modo pasta, envía las direcciones de la lista de búsqueda de dominios DNS a través de DHCP (opción 119), a través de Anuncios de Router NDP (tipo de opción 31) y DHCPv6 (opción 24). Por defecto, la lista de búsqueda de dominios DNS resultante de la configuración no se pasa.
--no-tcp
Deshabilita el manejador del protocolo TCP. No se aceptarán conexiones TCP del lado del host, y los paquetes TCP provenientes del invitado o del espacio de nombres de destino se descartarán silenciosamente.
--no-udp
Deshabilita el manejador del protocolo UDP. No se reenviará tráfico UDP procedente del host, y los paquetes UDP provenientes del invitado o del espacio de nombres de destino se descartarán silenciosamente.
--no-icmp
Deshabilita el manejador de protocolos ICMP/ICMPv6. Las solicitudes ICMP e ICMPv6 provenientes del invitado o del espacio de nombres de destino se descartarán silenciosamente. Implica --no-ndp.
--no-dhcp
Deshabilita el servidor DHCP. Las solicitudes de cliente DHCP provenientes del invitado o del espacio de nombres de destino se descartarán silenciosamente. Se implica si no hay puerta de enlace en la ruta por defecto IPv4 seleccionada.
--no-ndp
Deshabilita el Descubrimiento de Vecinos. Los mensajes NDP provenientes del invitado o del espacio de nombres de destino se ignorarán. No se enviará ningún mensaje NDP inicial.
--no-dhcpv6
Deshabilita el servidor DHCPv6. Las solicitudes de cliente DHCPv6 provenientes del invitado o del espacio de nombres de destino se descartarán silenciosamente.
--no-ra
Deshabilita los Anuncios de Router. Las Solicitudes de Router provenientes del invitado o del espacio de nombres de destino se ignorarán.
--freebind
Permite especificar cualquier dirección de enlace para las opciones -t y -u. Normalmente, las direcciones de enlace deben ser direcciones actualmente configuradas en el host. Con --freebind, la opción de socket IP_FREEBIND o IPV6_FREEBIND se habilita permitiendo usar cualquier dirección. Esto se usa típicamente para enlazar direcciones que podrían ser configuradas en el host en el futuro, momento en el cual el reenvío comenzará a operar inmediatamente.
--map-host-loopback dir
Traduce dir para que se refiera al host. Los paquetes del invitado a dir se redirigirán al host. En el host, dichos paquetes aparecerán con origen y destino 127.0.0.1 o ::1.

Si dir es 'none', no se mapea ninguna dirección (esto implica --no-map-gw). Solo se puede traducir una dirección IPv4 y una IPv6; si la opción se especifica varias veces, la última prevalece.

Por defecto, se traduce la dirección de la puerta de enlace por defecto del invitado, a menos que se especifique --no-map-gw, en cuyo caso no se mapea ninguna dirección.

--no-map-gw
No remapear conexiones TCP y tráfico UDP no rastreado, con la dirección de la puerta de enlace como destino, al host. Se implica si no hay puerta de enlace en la ruta por defecto seleccionada, o si no hay ruta por defecto, para cualquiera de las familias de direcciones habilitadas.
--map-guest-addr dir
Traduce dir en el invitado para que sea igual a la dirección asignada al invitado en el host. Es decir, los paquetes del invitado a dir se redirigirán a la dirección asignada al invitado con -a, o por defecto a la dirección global del host. Esto permite al invitado acceder a servicios disponibles en la dirección global del host, aunque su propia dirección opaque la del host.

Si dir es 'none', no se mapea ninguna dirección. Solo se puede traducir una dirección IPv4 y una IPv6, y si la opción se especifica varias veces, la última para cada tipo de dirección prevalece.

Por defecto, el mapeo ocurre como se describe para la opción --map-host-loopback.

-4, --ipv4-only
Habilita operación solo IPv4. El tráfico IPv6 será ignorado. Por defecto, la operación IPv6 está habilitada siempre que haya al menos una ruta IPv6 y una dirección de interfaz configuradas en una interfaz de host dada.
-6, --ipv6-only
Habilita operación solo IPv6. El tráfico IPv4 será ignorado. Por defecto, la operación IPv4 está habilitada siempre que haya al menos una ruta IPv4 y una dirección de interfaz configuradas en una interfaz de host dada.
-H, --hostname nombre
Nombre de host con el que configurar el cliente. Envía nombre como opción DHCP 12 (hostname).
--fqdn nombre
FQDN con el que configurar el cliente. Envía nombreComo FQDN del cliente: DHCP opción 81 y opción DHCPv6 39.

Opciones solo para passt

-s, --socket-path, --socket ruta
Ruta para el socket de dominio UNIX utilizado por qemu(1) o qrap(1) para conectarse a passt. Por defecto, se intenta con un socket libre, sin aceptar conexiones, empezando desde /tmp/passt_1.socket hasta /tmp/passt_64.socket.
--vhost-user
Habilitar vhost-user. El socket de comandos vhost-user es proporcionado por --socket.
--print-capabilities
Imprimir las capacidades del backend en formato JSON, solo tiene sentido en modo vhost-user.
--repair-path ruta
Ruta para el socket de dominio UNIX utilizado por la utilidad passt-repair(1) para conectarse a passt con el fin de establecer o borrar la opción TCP_REPAIR en sockets, durante la migración. --repair-path none deshabilita esta interfaz (si necesitas especificar una ruta de socket llamada "none", puedes prefijar la ruta con ./).

Por defecto, solo para el modo --vhost-user, se añade .repair a la ruta elegida para el socket UNIX del hipervisor. No se crea ningún socket si no se está en modo --vhost-user.

--migrate-exit(OBSOLETO)
Salir después de una migración completada como origen. Por defecto, passt sigue ejecutándose y el invitado migrado puede seguir usando su conexión, o puede conectarse un nuevo invitado.

Tenga en cuenta que esta opción de configuración está **obsoleta** y se eliminará en una futura versión. No se espera que tenga ningún uso y simplemente refleja un comportamiento heredado. Si tiene algún uso para esto, consulte la sección **REPORTAR ERRORES** más abajo.

--migrate-no-linger(OBSOLETO)
Cerrar sockets TCP en la instancia de origen una vez que la migración se complete.

Por defecto, los sockets se mantienen abiertos y los eventos en los sockets de datos se ignoran, de modo que cualquier mensaje adicional que llegue a los sockets después de la migración del origen se ignora silenciosamente, para evitar reinicios de conexión en caso de que se reciban datos después de la migración.

Tenga en cuenta que esta opción de configuración está **obsoleta** y se eliminará en una futura versión. No se espera que tenga ningún uso y simplemente refleja un comportamiento heredado. Si tiene algún uso para esto, consulte la sección **REPORTAR ERRORES** más abajo.

-F, --fd FD
Pasar un socket pre-abierto y conectado a passt. Normalmente el socket se abre en el proceso padre y passt lo hereda cuando se ejecuta como hijo. Esto permite al proceso padre abrir sockets utilizando otra familia de direcciones o requiriendo privilegios especiales.

Esta opción implica el comportamiento descrito para --one-off, una vez que este socket se cierre.

-1, --one-off
Salir después de manejar una única conexión de cliente, es decir, una vez que el cliente cierre el socket, o una vez que obtengamos un error de socket.

**Nota**: esta opción no tiene efecto después de que passt complete una migración como origen, porque, en ese caso, salir cerraría los sockets de las conexiones activas, lo que a su vez causaría reinicios de conexión si se recibieran datos adicionales. Consulte también la descripción de --migrate-no-linger.

-t, --tcp-ports especificación
Configurar el reenvío de puertos TCP al invitado. especificación puede ser una de las siguientes:
none
No reenviar ningún puerto.
all
Reenviar todos los puertos no enlazados y no efímeros, según lo permitido por las capacidades actuales. Para puertos bajos (< 1024), consulte **NOTAS**. No se informan errores para puertos no disponibles, a menos que no se haya podido reenviar ningún puerto.
ports
Una lista de puertos separada por comas, opcionalmente en rango con -, y, opcionalmente, con puertos de destino después de :, si son diferentes. También se pueden enlazar direcciones específicas, separadas por /, y también, desde Linux 5.7, limitadas a interfaces específicas, prefijadas por %. Dentro de los rangos dados, los puertos y rangos seleccionados pueden ser excluidos mediante una especificación adicional prefijada por ~.

Especificar solo rangos excluidos implica que todos los demás puertos se reenvían. En este caso, no se informan errores para puertos no disponibles, a menos que no se haya podido reenviar ningún puerto.

Ejemplos:

-t 22
Reenviar el puerto local 22 al puerto 22 del invitado.
-t 22:23
Reenviar el puerto local 22 al puerto 23 del invitado.
-t 22,25
Reenviar los puertos locales 22 y 25 a los puertos 22 y 25 del invitado.
-t 22-80
Reenviar los puertos locales entre 22 y 80 a los puertos correspondientes del invitado.
-t 22-80:32-90
Reenviar los puertos locales entre 22 y 80 a los puertos entre 32 y 90 del invitado.
-t 192.0.2.1/22
Reenviar el puerto local 22, enlazado a 192.0.2.1, al puerto 22 del invitado.
-t 192.0.2.1%eth0/22
Reenviar el puerto local 22, enlazado a 192.0.2.1 y a la interfaz eth0, al puerto 22.
-t %eth0/22
Reenviar el puerto local 22, enlazado a cualquier dirección en la interfaz eth0, al puerto 22.
-t 2000-5000,~3000-3010
Reenviar los puertos locales entre 2000 y 5000, excepto los comprendidos entre 3000 y 3010.
-t 192.0.2.1/20-30,~25
Para la dirección local 192.0.2.1, reenviar los puertos entre 20 y 24 y entre 26 y 30.
-t ~20000-20010
Reenviar todos los puertos al invitado, excepto el rango de 20000 a 20010.

Por defecto es none.

-u, --udp-ports especificación
Configurar el reenvío de puertos UDP al invitado. especificación es como se describe para TCP arriba.

Nota: a menos que se anule, los puertos UDP con números correspondientes a los números de puerto TCP reenviados también se reenvían, sin embargo, sin ninguna traducción de puerto. Los puertos enlazados IPv6 también se reenvían para IPv4.

Por defecto es none.

Opciones solo para pasta

-I, --ns-ifname nombre
Nombre de la interfaz tap que se creará en el namespace de destino. Por defecto, se utiliza el mismo nombre de interfaz que la interfaz externa y enrutable. Si no existe tal interfaz, se utilizará el nombre tap0.
-t, --tcp-ports especificación
Configurar el reenvío de puertos TCP al namespace. especificación puede ser una de las siguientes:
none
No reenviar ningún puerto.
auto
Reenviar dinámicamente los puertos enlazados en el namespace. La lista de puertos se deriva periódicamente (cada segundo) de los sockets de escucha informados por /proc/net/tcp y /proc/net/tcp6, consulte proc(5).
ports
Una lista de puertos separada por comas, opcionalmente en rango con -, y, opcionalmente, con puertos de destino después de :, si son diferentes. También se pueden enlazar direcciones específicas, separadas por /, y también, desde Linux 5.7, limitadas a interfaces específicas, prefijadas por %. Dentro de los rangos dados, los puertos y rangos seleccionados pueden ser excluidos mediante una especificación adicional prefijada por ~.

Especificar solo rangos excluidos implica que todos los demás puertos se reenvían. En este caso, no se informan errores para puertos no disponibles, a menos que no se haya podido reenviar ningún puerto.

Ejemplos:

-t 22
Reenviar el puerto local 22 al puerto 22 en el namespace de destino.
-t 22:23
Reenviar el puerto local 22 al puerto 23 en el namespace de destino.
-t 22,25
