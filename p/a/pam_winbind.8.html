NOMBRE

pam_winbind - Módulo PAM para Winbind

DESCRIPCIÓN

Esta herramienta es parte de la suite samba(7).

pam_winbind es un módulo PAM que puede autenticar usuarios contra el dominio local hablando con el demonio Winbind.

SINOPSIS

Edite la configuración del sistema PAM /etc/pam.d/service y modifíquela como se muestra en el siguiente ejemplo:

    ...
    auth      required        pam_env.so
    auth      sufficient      pam_unix2.so
+++ auth      required        pam_winbind.so  use_first_pass
    account   requisite       pam_unix2.so
+++ account   required        pam_winbind.so  use_first_pass
+++ password  sufficient      pam_winbind.so
    password  requisite       pam_pwcheck.so  cracklib
    password  required        pam_unix2.so    use_authtok
    session   required        pam_unix2.so
+++ session   required        pam_winbind.so
    ...

Asegúrese de que pam_winbind sea uno de los primeros módulos en la parte de sesión. Puede recuperar tickets Kerberos que son necesarios para otros módulos.

OPCIONES

pam_winbind soporta varias opciones que pueden configurarse en los archivos de configuración de PAM o en el archivo de configuración pam_winbind.conf ubicado en /etc/security/pam_winbind.conf. Las opciones del archivo de configuración de PAM tienen prioridad sobre las del archivo de configuración. Consulte pam_winbind.conf(5) para más detalles.

debug

Proporciona salida de depuración a syslog.

debug_state

Proporciona una salida detallada de depuración del estado PAM a syslog.

require_membership_of=[SID o NOMBRE]

Si esta opción está configurada, pam_winbind solo tendrá éxito si el usuario es miembro del SID o NOMBRE proporcionado. Un SID puede ser un SID de grupo, un SID de alias o incluso un SID de usuario. También es posible proporcionar un NOMBRE en lugar del SID. Ese nombre debe tener el formato: MIDOMINIO\mi_grupo o MIDOMINIO\mi_usuario (donde el carácter '\' corresponde al valor del parámetro winbind separator). También es posible usar un UPN en el formato usuario@REINO o grupo@REINO. pam_winbind, en ese caso, buscará el SID internamente. Tenga en cuenta que NOMBRE no puede contener espacios. Por lo tanto, se recomienda usar solo SIDs. Puede verificar la lista de SIDs de los que un usuario es miembro con wbinfo --user-sids=SID.

Esta opción solo debe especificarse en una declaración de módulo de autenticación, ya que solo opera junto con la autenticación de contraseñas.

use_first_pass

Por defecto, pam_winbind intenta obtener el token de autenticación de un módulo anterior. Si no hay ningún token disponible, pide al usuario la contraseña anterior. Con esta opción, pam_winbind aborta con un error si no hay un token de autenticación de un módulo anterior disponible.

try_first_pass

Igual que la opción use_first_pass (elemento anterior), excepto que si la contraseña principal no es válida, PAM solicitará una contraseña.

use_authtok

Establece la nueva contraseña a la proporcionada por el módulo de contraseña apilado anteriormente. Si esta opción no está configurada, pam_winbind pedirá al usuario la nueva contraseña.

try_authtok

Igual que la opción use_authtok (elemento anterior), excepto que si la nueva contraseña no es válida, PAM solicitará una contraseña.

krb5_auth

pam_winbind puede autenticar usando Kerberos cuando winbindd se comunica con un controlador de dominio de Active Directory. La autenticación Kerberos debe habilitarse con este parámetro. Cuando la autenticación Kerberos no puede tener éxito (por ejemplo, debido a desincronización horaria), winbindd recurrirá a la autenticación samlogon sobre MSRPC. Cuando este parámetro se usa junto con winbind refresh tickets, winbind mantendrá su Ticket Granting Ticket (TGT) actualizado actualizándolo siempre que sea necesario.

krb5_ccache_type=[tipo]

Cuando pam_winbind está configurado para intentar la autenticación Kerberos habilitando la opción krb5_auth, puede almacenar el Ticket Granting Ticket (TGT) recuperado en una caché de credenciales. El tipo de caché de credenciales se puede controlar con esta opción. Los valores soportados son: KCM o KEYRING (cuando es soportado por la biblioteca Kerberos del sistema y el sistema operativo), FILE y DIR (cuando el tipo DIR es soportado por la biblioteca Kerberos del sistema). En caso de FILE se creará una caché de credenciales en el formato /tmp/krb5cc_UID - en caso de DIR DEBE proporcionar un directorio que debe existir, el directorio UID se creará en el directorio especificado. En todos los casos, UID se reemplaza con el ID de usuario numérico. Verifique los detalles de la implementación Kerberos.

Al usar el tipo KEYRING, el mecanismo soportado es “KEYRING:persistent:UID”, que utiliza el keyring del kernel de Linux para almacenar credenciales por UID. KEYRING tiene limitaciones. Por ejemplo, es memoria segura del kernel, por lo que no es posible el almacenamiento masivo de credenciales.

Al usar el tipo KCM, el mecanismo soportado es “KCM:UID”, que utiliza un gestor de credenciales Kerberos para almacenar credenciales por UID de forma similar a KEYRING. Esta es la opción recomendada en las últimas distribuciones de Linux que ofrecen un Gestor de Credenciales Kerberos. Si no, sugerimos usar KEYRING, ya que son los métodos más seguros y predecibles.

También es posible definir rutas de archivo personalizadas y usar el patrón "%u" para sustituir el ID de usuario numérico. Ejemplos:

krb5_ccache_type = DIR:/run/user/%u/krb5cc

Esto creará un archivo de caché de credenciales en el directorio especificado.

krb5_ccache_type = FILE:/tmp/krb5cc_%u

Esto creará un archivo de caché de credenciales.

Dejar vacío para solo realizar la autenticación Kerberos sin tener una caché de tickets después de que el inicio de sesión haya tenido éxito. Esta configuración está vacía por defecto.

cached_login

Winbind permite iniciar sesión usando credenciales en caché cuando winbind offline logon está habilitado. Para usar esta función desde el módulo PAM, esta opción debe estar configurada.

silent

No emitir ningún mensaje.

mkhomedir

Crear el directorio personal para un usuario sobre la marcha, la opción es válida en el bloque de sesión PAM.

warn_pwd_expire

Define el número de días antes de que pam_winbind comience a advertir sobre contraseñas que están a punto de expirar. El valor predeterminado es 14 días.

EXPORTACIONES DE DATOS PAM

Esta sección describe los datos exportados en la pila PAM que podrían ser utilizados en otros módulos PAM.

PAM_WINBIND_HOMEDIR

Este es el Directorio Personal de Windows configurado en la pestaña de perfil en la configuración del usuario en el Servidor Active Directory. Podría ser una ruta local o un directorio en un recurso compartido mapeado a una unidad.

PAM_WINBIND_LOGONSCRIPT

La ruta al script de inicio de sesión que debería ejecutarse si un usuario inicia sesión. Normalmente es una ruta relativa al script almacenado en el servidor.

PAM_WINBIND_LOGONSERVER

Esto exporta el servidor Active Directory contra el que nos estamos autenticando. Esto puede usarse como una variable más adelante.

PAM_WINBIND_PROFILEPATH

Este es la ruta del perfil configurada en la pestaña de perfil en la configuración del usuario. Normalmente el directorio personal se sincroniza con este directorio en un recurso compartido.

pam_winbind(8)

NAME

pam_winbind - Módulo PAM para autenticación y autorización de Winbind

DESCRIPTION

El módulo pam_winbind proporciona una interfaz PAM (Pluggable Authentication Modules) para el demonio Winbind de Samba. Permite que los usuarios de un dominio NT (como un dominio Active Directory o Windows NT) inicien sesión en un sistema Linux que está unido a ese dominio.

Este módulo puede ser configurado para realizar varias funciones, incluyendo:

  • Autenticación de usuarios: Verifica las credenciales del usuario contra el controlador de dominio.
  • Autorización de usuarios: Determina si un usuario tiene permiso para iniciar sesión.
  • Gestión de cuentas: Verifica la validez de las cuentas de usuario (por ejemplo, si la cuenta ha expirado).
  • Gestión de sesiones: Configura el entorno del usuario, como montar directorios de inicio de sesión y establecer variables de entorno.

SYNOPSIS

pam_winbind.so [opciones]

OPTIONS

debug
Habilita la depuración. La salida se escribirá en el registro del sistema (syslog).
kdebug=<mask>
Habilita la depuración de Winbind con la máscara especificada.
use_first_pass
Utiliza la contraseña proporcionada anteriormente para esta solicitud sin solicitarla explícitamente al usuario. Esto puede ser útil para la autenticación no interactiva.
try_first_pass
Intenta utilizar la contraseña proporcionada anteriormente. Si falla, se le pedirá al usuario que introduzca una contraseña.
password_stdin
Lee la contraseña desde la entrada estándar en lugar de solicitarla al usuario.
nodisplay
Evita que el módulo muestre mensajes al usuario. Esto es útil en entornos no interactivos.
no_message
Similar a nodisplay, suprime los mensajes.
global_groups
Incluye los grupos globales del dominio en la lista de grupos del usuario.
local_groups
Utiliza los grupos locales definidos en el archivo /etc/group para determinar los grupos a los que pertenece un usuario.
restricted
Restringe el acceso de los usuarios. Si se establece esta opción, los usuarios solo podrán iniciar sesión si están explícitamente incluidos en el archivo /etc/security/winbind_groups.
usersdn
Especifica el DN base para buscar usuarios en el directorio LDAP. Esto anula la configuración del archivo smb.conf.
groupsdn
Especifica el DN base para buscar grupos en el directorio LDAP. Esto anula la configuración del archivo smb.conf.
search_base
Especifica el DN base para buscar usuarios y grupos.
cache_credentials
Almacena en caché las credenciales del usuario. Esto puede mejorar el rendimiento pero puede tener implicaciones de seguridad.
force_local_logins
Permite que los usuarios locales inicien sesión incluso si el dominio no está disponible.
require_membership_of
Requiere que el usuario sea miembro de uno o más grupos especificados para poder iniciar sesión.
annoy_write_enable
Evita que los usuarios sin privilegios escriban en directorios que no les pertenecen. Esto puede ser útil para evitar que los usuarios que no son administradores realicen ciertas operaciones.

PAM DATA EXPORTS

Este módulo puede exportar varios datos a otras aplicaciones PAM, como el nombre de usuario, el nombre de dominio y la información de los grupos. Consulte la documentación de PAM para obtener más detalles sobre cómo acceder a estos datos.
