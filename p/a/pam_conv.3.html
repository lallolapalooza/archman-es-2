NOMBRE

pam_conv - Función de conversación de PAM

SINOPSIS

#include <security/pam_appl.h>
struct pam_message {
    int msg_style;
    const char *msg;
};
struct pam_response {
    char *resp;
    int resp_retcode;
};
struct pam_conv {
    int (*conv)(int num_msg, const struct pam_message **msg,
                struct pam_response **resp, void *appdata_ptr);
    void *appdata_ptr;
};

DESCRIPCIÓN

La biblioteca PAM utiliza una llamada de retorno definida por la aplicación para permitir la comunicación directa entre un módulo cargado y la aplicación. Esta llamada de retorno se especifica mediante la estructura struct pam_conv pasada a pam_start(3) al inicio de la transacción.

Cuando un módulo llama a la función de conversación referenciada, el argumento appdata_ptr se establece en el segundo elemento de esta estructura.

Los otros argumentos de una llamada a conv() se refieren a la información intercambiada entre el módulo y la aplicación. Es decir, num_msg contiene la longitud del array de punteros, msg. Tras un retorno exitoso, el puntero resp apunta a un array de estructuras pam_response, que contiene el texto proporcionado por la aplicación. El miembro resp_retcode de esta estructura no se utiliza y debe establecerse en cero. Es responsabilidad del llamante liberar tanto este array como las respuestas mismas, utilizando free(3). Tenga en cuenta que *resp es un array de struct pam_response y no un array de punteros.

El número de respuestas es siempre igual al argumento de la función de conversación num_msg. Esto requiere que el array de respuestas se libere con free(3) después de cada llamada a la función de conversación. El índice de las respuestas corresponde directamente al índice de la pregunta en el array pam_message.

En caso de fallo, la función de conversación debe liberar cualquier recurso que haya asignado y devolver uno de los códigos de error predefinidos de PAM.

Cada mensaje puede tener uno de los cuatro tipos, especificados por el miembro msg_style de struct pam_message:

PAM_PROMPT_ECHO_OFF

Obtener una cadena sin mostrar ningún texto.

PAM_PROMPT_ECHO_ON

Obtener una cadena mientras se muestra texto.

PAM_ERROR_MSG

Mostrar un mensaje de error.

PAM_TEXT_INFO

Mostrar algún texto.

El propósito de tener un array de mensajes es que sea posible pasar una serie de cosas a la aplicación en una sola llamada desde el módulo. También puede ser conveniente para la aplicación que las cosas relacionadas lleguen a la vez: una aplicación basada en ventanas puede presentar un solo formulario con muchos mensajes/solicitudes a la vez.

De paso, vale la pena señalar que existe una discrepancia entre la forma en que Linux-PAM maneja el argumento de la función de conversación const struct pam_message **msg y la forma en que lo hace Solaris PAM (y derivados, se sabe que incluyen HP/UX, ¿hay otros?). Linux-PAM interpreta el argumento msg como totalmente equivalente al siguiente prototipo const struct pam_message *msg[] (que, en espíritu, es consistente con los prototipos comúnmente utilizados para el argumento argv de la familiar función main(): char **argv; y char *argv[]). Dicho de otra manera, Linux-PAM interpreta el argumento msg como un puntero a un array de num_msg punteros 'struct pam_message' de solo lectura. La implementación de PAM de Solaris interpreta este argumento como un puntero a un puntero a un array de num_msg estructuras pam_message. Afortunadamente, quizás, para la mayoría de los desarrolladores de módulos/aplicaciones, cuando num_msg tiene un valor de uno, estas dos definiciones son totalmente equivalentes. Desafortunadamente, elevar casualmente este número a dos ha provocado problemas de compatibilidad imprevistos.

Para lo que valga, las dos soluciones conocidas para los escritores de módulos para intentar mantener la compatibilidad a nivel de código fuente con ambas implementaciones de PAM son:

•nunca llamar a la función de conversación con num_msg mayor que uno.
•configurar msg como doblemente referenciado para que ambos tipos de función de conversación puedan encontrar los mensajes. Es decir, hacer 
       msg[n] = & (( *msg )[n])

VALORES DE RETORNO

PAM_BUF_ERR

Error de búfer de memoria.

PAM_CONV_ERR

Fallo de conversación. La aplicación no debe establecer *resp.

PAM_SUCCESS

Éxito.
