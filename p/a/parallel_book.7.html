¿Por qué deberías leer este libro?

Si escribes scripts de shell para hacer el mismo procesamiento para diferentes entradas, entonces GNU parallel te hará la vida más fácil y hará que tus scripts se ejecuten más rápido.

El libro está escrito para que obtengas las partes jugosas primero: El objetivo es que leas lo suficiente para empezar. GNU parallel tiene una abrumadora cantidad de características especiales para ayudar en diferentes situaciones, y para no sobrecargarte de información, se presentan primero las características más utilizadas.

Todos los ejemplos se prueban en Bash, y la mayoría funcionarán en otros shells, pero hay algunas excepciones. Por lo tanto, se recomienda usar Bash al probar los ejemplos.

Aprende GNU Parallel en 5 minutos

Solo necesitas ejecutar comandos en paralelo. No te importa el ajuste fino.

Para empezar, ejecuta esto para crear algunos archivos de ejemplo:

# Si tu sistema no tiene 'seq', reemplaza 'seq' con 'jot'
seq 5 | parallel seq {} '>' example.{}

Fuentes de entrada

GNU parallel lee valores de fuentes de entrada. Una fuente de entrada es la línea de comandos. Los valores se colocan después de ::::

parallel echo ::: 1 2 3 4 5

Esto facilita la ejecución del mismo programa en algunos archivos:

parallel wc ::: example.*

Si proporcionas múltiples :::, GNU parallel generará todas las combinaciones:

parallel wc ::: -l -c ::: example.*

GNU parallel también puede leer los valores de stdin (entrada estándar):

seq 5 | parallel echo

Construcción de la línea de comandos

La línea de comandos se coloca antes de :::. Puede contener un comando y opciones para el comando:

parallel wc -l ::: example.*

El comando puede contener múltiples programas. Solo recuerda citar los caracteres que son interpretados por el shell (como ;):

parallel echo counting lines';' wc -l ::: example.*

El valor normalmente se agregará al comando, pero se puede colocar en cualquier lugar utilizando la cadena de reemplazo {}:

parallel echo counting {}';' wc -l {} ::: example.*

Al usar múltiples fuentes de entrada, se utilizan las cadenas de reemplazo posicionales {1} y {2}:

parallel echo count {1} in {2}';' wc {1} {2} ::: -l -c ::: example.*

Puedes verificar qué se ejecutará con --dry-run:

parallel --dry-run echo count {1} in {2}';' wc {1} {2} ::: -l -c ::: example.*

Es una buena idea hacer esto para cada comando hasta que te sientas cómodo con GNU parallel.

Control de la salida

La salida se imprimirá tan pronto como el comando se complete. Esto significa que la salida puede venir en un orden diferente al de la entrada:

parallel sleep {}';' echo {} done ::: 5 4 3 2 1

Puedes forzar a GNU parallel a imprimir en el orden de los valores con --keep-order/-k. Esto seguirá ejecutando los comandos en paralelo. La salida de los trabajos posteriores se retrasará hasta que se impriman los trabajos anteriores:

parallel -k sleep {}';' echo {} done ::: 5 4 3 2 1

Control de la ejecución

Si tus trabajos son intensivos en cómputo, lo más probable es que ejecutes un trabajo por cada núcleo del sistema. Este es el valor predeterminado para GNU parallel.

Pero a veces quieres que se ejecuten más trabajos. Controlas el número de ranuras de trabajo con -j. Dale a -j el número de trabajos a ejecutar en paralelo:

parallel -j50 \
  wget https://ftpmirror.gnu.org/parallel/parallel-{1}{2}22.tar.bz2 \
  ::: 2012 2013 2014 2015 2016 \
  ::: 01 02 03 04 05 06 07 08 09 10 11 12

Modo tubería

GNU parallel también puede pasar bloques de datos a comandos en stdin (entrada estándar):

seq 1000000 | parallel --pipe wc

Esto se puede utilizar para procesar archivos de texto grandes. Por defecto, GNU parallel divide por \n (nueva línea) y pasa un bloque de aproximadamente 1 MB a cada trabajo.

Eso es todo

Ahora has aprendido el uso básico de GNU parallel. Esto probablemente cubrirá la mayoría de los casos de tu uso de GNU parallel.

El resto de este documento profundizará en cada una de las secciones y cubrirá casos de uso especiales.

Aprende GNU Parallel en una hora

En esta parte profundizaremos en lo que aprendiste en los primeros 5 minutos.

Para empezar, ejecuta esto para crear algunos archivos de ejemplo:

seq 6 > seq6
seq 6 -1 1 > seq-6

Fuentes de entrada

Además de la línea de comandos, las fuentes de entrada también pueden ser stdin (entrada estándar o '-'), archivos y fifos, y se pueden mezclar. Los archivos se proporcionan después de -a o ::::. Por lo tanto, todos estos hacen lo mismo:

parallel echo Dice1={1} Dice2={2} ::: 1 2 3 4 5 6 ::: 6 5 4 3 2 1
parallel echo Dice1={1} Dice2={2} :::: <(seq 6) :::: <(seq 6 -1 1)
parallel echo Dice1={1} Dice2={2} :::: seq6 seq-6
parallel echo Dice1={1} Dice2={2} :::: seq6 :::: seq-6
parallel -a seq6 -a seq-6 echo Dice1={1} Dice2={2}
parallel -a seq6 echo Dice1={1} Dice2={2} :::: seq-6
parallel echo Dice1={1} Dice2={2} ::: 1 2 3 4 5 6 :::: seq-6
cat seq-6 | parallel echo Dice1={1} Dice2={2} :::: seq6 -

Si stdin (entrada estándar) es la única fuente de entrada, no necesitas el '-':

cat seq6 | parallel echo Dice1={1}

Vinculación de fuentes de entrada

Puedes vincular múltiples fuentes de entrada con :::+ y ::::+:

parallel echo {1}={2} ::: I II III IV V VI :::+ 1 2 3 4 5 6
parallel echo {1}={2} ::: I II III IV V VI ::::+ seq6

El :::+ (y ::::+) vinculará cada valor al valor correspondiente en la fuente de entrada anterior, por lo que el valor número 3 de la primera fuente de entrada se vinculará al valor número 3 de la segunda fuente de entrada.

Puedes combinar :::+ y :::, de modo que vincules 2 fuentes de entrada, pero generes todas las combinaciones con otras fuentes de entrada:

parallel echo Dice1={1}={2} Dice2={3}={4} ::: I II III IV V VI ::::+ seq6 \
  ::: VI V IV III II I ::::+ seq-6

Construcción de la línea de comandos

El comando

El comando puede ser un script, un binario o una función de Bash si la función se exporta usando export -f:

# Solo funciona en Bash
my_func() {
  echo in my_func "$1"
}
export -f my_func
parallel my_func ::: 1 2 3

Si el comando es complejo, a menudo mejora la legibilidad convertirlo en una función.

Las cadenas de reemplazo

GNU parallel tiene algunas cadenas de reemplazo para facilitar la referencia a la entrada leída de las fuentes de entrada.

Si la entrada es mydir/mysubdir/myfile.myext entonces:

{} = mydir/mysubdir/myfile.myext
{.} = mydir/mysubdir/myfile
{/} = myfile.myext
{//} = mydir/mysubdir
{/.} = myfile
{#} = el número de secuencia del trabajo
{%} = el número de ranura del trabajo

Cuando se inicia un trabajo, recibe un número de secuencia que comienza en 1 y aumenta en 1 por cada nuevo trabajo. Al trabajo también se le asigna un número de ranura. Este número va de 1 al número de trabajos que se ejecutan en paralelo. Es único entre los trabajos en ejecución, pero se reutiliza tan pronto como un trabajo finaliza.

Las cadenas de reemplazo posicionales

Las cadenas de reemplazo tienen cadenas de reemplazo posicionales correspondientes. Si el valor de la tercera fuente de entrada es mydir/mysubdir/myfile.myext:

{3} = mydir/mysubdir/myfile.myext
{3.} = mydir/mysubdir/myfile
{3/} = myfile.myext
{3//} = mydir/mysubdir
{3/.} = myfile

Por lo tanto, el número de la fuente de entrada simplemente se antepone dentro de las {}.

parset

parset

parset is a shell function to get the output from GNU parallel into shell variables.

parset is fully supported for Bash/Zsh/Ksh and partially supported for ash/dash. I will assume you run Bash.

To activate parset you have to run:

. `which env_parallel.bash`

(replace bash with your shell's name).

Then you can run:

parset a,b,c seq ::: 4 5 6
echo "$c"

or:

parset 'a b c' seq ::: 4 5 6
echo "$c"

If you give a single variable, this will become an array:

parset arr seq ::: 4 5 6
echo "${arr[1]}"

parset has one limitation: If it reads from a pipe, the output will be lost.

echo This will not work | parset myarr echo
echo Nothing: "${myarr[*]}"

Instead you can do this:

echo This will work > tempfile
parset myarr echo < tempfile
echo ${myarr[*]}

Remote execution

For this section you must have ssh access with no password to 2 servers: $server1 and $server2.

server1=server.example.com
server2=server2.example.net

So you must be able to do this:

ssh $server1 echo works
ssh $server2 echo works

It can be setup by running 'ssh-keygen -t dsa; ssh-copy-id $server1' and using an empty passphrase. Or you can use ssh-agent.

Workers

--transferfile

--transferfile filename will transfer filename to the worker. filename can contain a replacement string:

parallel -S $server1,$server2 --transferfile {} wc ::: example.*
parallel -S $server1,$server2 --transferfile {2} \
   echo count {1} in {2}';' wc {1} {2} ::: -l -c ::: example.*

A shorthand for --transferfile {} is --transfer.

--return

--cleanup

A shorthand for --transfer --return {} --cleanup is --trc {}.
