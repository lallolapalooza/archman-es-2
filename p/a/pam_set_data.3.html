pam_set_data(3)

Paquete: pam

Licencias: GPL-2.0-only

PAM_SET_DATA(3) Manual de Linux-PAM PAM_SET_DATA(3)

NOMBRE

pam_set_data - establece datos internos del módulo

SINOPSIS

#include <security/pam_modules.h>

int pam_set_data(pam_handle_t *pamh, const char *module_data_name, void *data, void (*cleanup)(pam_handle_t *pamh, void *data, int error_status));

DESCRIPCIÓN

La función pam_set_data asocia un puntero a un objeto con el nombre único (con suerte) module_data_name en el contexto PAM especificado por el argumento pamh.

Los módulos PAM pueden ser objetos cargables dinámicamente. En general, dichos archivos no deberían contener variables static. Esta función y su contraparte pam_get_data(3), proporcionan un mecanismo para que un módulo asocie algunos datos con el manejador pamh. Típicamente, un módulo llamará a la función pam_set_data para registrar algún dato bajo un module_data_name (con suerte) único. Los datos están disponibles para su uso por otros módulos, pero no por una aplicación. Dado que esta función solo almacena un puntero a los data, el módulo no debe modificar ni liberar el contenido de los mismos.

La función cleanup() se asocia con los data y, si no es NULL, se llama cuando estos datos se sobrescriben o después de una llamada a pam_end(3).

El argumento error_status se utiliza para indicar al módulo el tipo de acción que debe tomar al limpiar este elemento de datos. Como ejemplo, Kerberos crea un archivo de ticket durante la fase de autenticación, este archivo podría asociarse con un elemento de datos. Cuando el módulo llama a pam_end(3), el error_status contiene el valor de retorno de pam_authenticate(3) u otra función de libpam según corresponda. Basándose en este valor, el módulo Kerberos puede optar por eliminar el archivo de ticket (fallo de autenticación) o dejarlo en su lugar.

El error_status puede haber sido combinado lógicamente (OR) con cualquiera de los siguientes dos valores:

PAM_DATA_REPLACE

Cuando se está reemplazando un elemento de datos (mediante una segunda llamada a pam_set_data) se utiliza esta máscara. De lo contrario, se asume que la llamada proviene de pam_end(3).

PAM_DATA_SILENT

Lo que indica que el proceso prefiere realizar la operación cleanup() de forma silenciosa. Es decir, desalienta el registro o los mensajes al usuario. Generalmente se utiliza para indicar que el cierre actual de la biblioteca se produce en un proceso fork(2)ed, y que el proceso padre se encargará de limpiar las cosas que existen fuera del espacio del proceso actual (archivos, etc.).

VALORES DE RETORNO

PAM_BUF_ERR

Error de búfer de memoria.

PAM_SUCCESS

Los datos se almacenaron correctamente.

PAM_SYSTEM_ERR

Se envió un puntero NULL como manejador PAM o la función fue llamada por una aplicación.

VER TAMBIÉN

pam_end(3), pam_get_data(3), pam_strerror(3)
