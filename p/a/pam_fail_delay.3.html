pam_fail_delay(3)

Paquete: pam

Licencias: GPL-2.0-only

PAM_FAIL_DELAY(3) Manual de Linux-PAM PAM_FAIL_DELAY(3)

NOMBRE

pam_fail_delay - solicitar un retraso al fallar

SINOPSIS

#include <security/pam_appl.h>

int pam_fail_delay(pam_handle_t *pamh, unsigned int usec);

DESCRIPCIÓN

La función pam_fail_delay proporciona un mecanismo mediante el cual una aplicación o módulo puede sugerir un retraso mínimo de usec microsegundos. La función mantiene un registro del tiempo más largo solicitado con esta función. Si pam_authenticate(3) falla, el retorno fallido a la aplicación se retrasa una cantidad de tiempo distribuida aleatoriamente (hasta un 50%) alrededor de este valor más largo.

Independientemente del éxito, el tiempo de retraso se restablece a su valor predeterminado cero cuando el módulo de servicio PAM devuelve el control a la aplicación. El retraso ocurre *después* de que se han llamado todos los módulos de autenticación, pero *antes* de que se devuelva el control a la aplicación de servicio.

Al utilizar esta función, el programador debe verificar si está disponible con:

#ifdef HAVE_PAM_FAIL_DELAY
    ....
#endif /* HAVE_PAM_FAIL_DELAY */

Para aplicaciones escritas con un solo hilo que son de naturaleza dirigida por eventos, generar este retraso puede ser indeseable. En su lugar, la aplicación puede querer registrar el retraso de alguna otra manera. Por ejemplo, en un servidor de un solo hilo que atiende múltiples solicitudes de autenticación desde un solo bucle de eventos, la aplicación podría querer simplemente marcar una conexión dada como bloqueada hasta que expire un temporizador de aplicación. Por esta razón, la función de retraso puede cambiarse con el elemento PAM_FAIL_DELAY. Se puede consultar y establecer con pam_get_item(3) y pam_set_item(3) respectivamente. El valor utilizado para establecerlo debe ser un puntero de función del siguiente prototipo:

void (*delay_fn)(int retval, unsigned usec_delay, void *appdata_ptr);

Los argumentos son el código de retorno retval de la pila de módulos, el retraso en microsegundos usec_delay que libpam está solicitando y el appdata_ptr que la aplicación ha asociado con el pamh actual. Este último valor fue establecido por la aplicación cuando llamó a pam_start(3) o explícitamente con pam_set_item(3).

Tenga en cuenta que el elemento PAM_FAIL_DELAY se establece en NULL por defecto. Esto indica que PAM debe realizar un retraso aleatorio como se describe anteriormente cuando falla la autenticación y se ha sugerido un retraso. Si una aplicación no desea que la biblioteca PAM realice ningún retraso en caso de fallo de autenticación, entonces la aplicación debe definir una función de retraso personalizada que no ejecute ninguna instrucción y establecer el elemento PAM_FAIL_DELAY para que apunte a esta función.

FUNDAMENTO

A menudo es posible atacar un esquema de autenticación explotando el tiempo que tarda el esquema en denegar el acceso a un usuario solicitante. En casos de tiempos de espera *cortos*, puede ser posible intentar un ataque de diccionario de *fuerza bruta*: con un proceso automatizado, el atacante prueba todas las contraseñas posibles para obtener acceso al sistema. En otros casos, donde los fallos individuales pueden tomar cantidades medibles de tiempo (indicando la naturaleza del fallo), un atacante puede obtener información útil sobre el proceso de autenticación. Estos últimos ataques utilizan retrasos procedimentales que constituyen un *canal encubierto* de información útil.

Para minimizar la efectividad de tales ataques, es deseable introducir un retraso aleatorio en un proceso de autenticación fallido. Preferiblemente, este valor debe ser establecido por la aplicación o un módulo PAM especial. Los módulos PAM estándar no deben modificar el retraso incondicionalmente.

EJEMPLO

Por ejemplo, una aplicación de inicio de sesión puede requerir un retraso de fallo de aproximadamente 3 segundos. Contendrá el siguiente código:

    pam_fail_delay (pamh, 3000000 /* microsegundos */ );
    pam_authenticate (pamh, 0);

si los módulos no solicitan un retraso, el retraso de fallo estará entre 1.5 y 4.5 segundos.

Sin embargo, los módulos, invocados en el proceso de autenticación, también pueden solicitar retrasos:

módulo #1:    pam_fail_delay (pamh, 2000000);
módulo #2:    pam_fail_delay (pamh, 4000000);

en este caso, es el valor más grande solicitado el que se utiliza para calcular el retraso real de fallo: aquí entre 2 y 6 segundos.

VALORES DE RETORNO

PAM_SUCCESS

El retraso se ajustó correctamente.

PAM_SYSTEM_ERR

Se envió un puntero nulo como manejador de PAM.
