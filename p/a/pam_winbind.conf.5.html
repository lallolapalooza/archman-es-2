NOMBRE

pam_winbind.conf - Archivo de configuración del módulo PAM para Winbind

DESCRIPCIÓN

Este archivo de configuración es parte de la suite de samba(7).

pam_winbind.conf es el archivo de configuración para el módulo PAM pam_winbind. Véase pam_winbind(8) para más detalles.

SINOPSIS

El archivo de configuración pam_winbind.conf es un archivo de configuración clásico estilo ini. Solo hay una sección (global) donde se definen varias opciones.

OPCIONES

pam_winbind soporta varias opciones que pueden ser configuradas en los archivos de configuración de PAM o en el archivo de configuración pam_winbind ubicado en /etc/security/pam_winbind.conf. Las opciones del archivo de configuración de PAM tienen prioridad sobre las del archivo de configuración pam_winbind.conf.

debug = sí|no

Proporciona salida de depuración a syslog. Por defecto es "no".

debug_state = sí|no

Proporciona salida detallada de depuración del estado de PAM a syslog. Por defecto es "no".

require_membership_of = [SID o NOMBRE]

Si esta opción está configurada, pam_winbind solo tendrá éxito si el usuario es miembro del SID o NOMBRE dado. Un SID puede ser un SID de grupo, un SID de alias o incluso un SID de usuario. También es posible dar un NOMBRE en lugar del SID. Ese nombre debe tener el formato: MIdominio\migrupo o MIdominio\miusuario (donde el carácter '\' corresponde al valor del parámetro winbind separator). También es posible usar un UPN en el formato usuario@REINO o grupo@REINO. pam_winbind, en ese caso, buscará el SID internamente. Tenga en cuenta que NOMBRE no puede contener espacios. Por lo tanto, se recomienda usar solo SIDs. Puede verificar la lista de SIDs de los que un usuario es miembro con wbinfo --user-sids=SID. Esta configuración está vacía por defecto.

Esta opción solo opera durante la autenticación de contraseña, y no restringirá el acceso si una contraseña no es requerida por alguna razón (como el inicio de sesión basado en clave SSH).

try_first_pass = sí|no

Por defecto, pam_winbind intenta obtener el token de autenticación de un módulo anterior. Si no hay ningún token disponible, pide al usuario la contraseña antigua. Con esta opción, pam_winbind aborta con un error si no hay ningún token de autenticación de un módulo anterior disponible. Si una contraseña principal no es válida, PAM solicitará una contraseña. Por defecto es "no".

krb5_auth = sí|no

pam_winbind puede autenticarse usando Kerberos cuando winbindd está comunicándose con un controlador de dominio de Active Directory. La autenticación Kerberos debe estar habilitada con este parámetro. Cuando la autenticación Kerberos no puede tener éxito (por ejemplo, debido a desfase horario), winbindd recurrirá a la autenticación samlogon a través de MSRPC. Cuando este parámetro se usa junto con winbind refresh tickets, winbind mantendrá su Ticket Granting Ticket (TGT) actualizado refrescándolo cuando sea necesario. Por defecto es "no".

krb5_ccache_type = [tipo]

Cuando pam_winbind está configurado para intentar la autenticación kerberos habilitando la opción krb5_auth, puede almacenar el Ticket Granting Ticket (TGT) recuperado en una caché de credenciales. El tipo de caché de credenciales se puede controlar con esta opción. Los valores soportados son: KCM o KEYRING (cuando son soportados por la biblioteca Kerberos del sistema y el sistema operativo), FILE y DIR (cuando el tipo DIR es soportado por la biblioteca Kerberos del sistema). En el caso de FILE se creará una caché de credenciales en el formato /tmp/krb5cc_UID - en el caso de DIR DEBE especificar un directorio. UID se reemplaza con el ID numérico del usuario. El directorio UID se crea. La ruta hasta el directorio debe existir. Consulte los detalles de la implementación de Kerberos.

Al usar el tipo KEYRING, el mecanismo soportado es "KEYRING:persistent:UID", que utiliza la keyring del kernel de Linux para almacenar credenciales por UID. La KEYRING tiene sus limitaciones. Al ser memoria segura del kernel, por ejemplo, el almacenamiento masivo de credenciales no es posible.

Al usar el tipo KCM, el mecanismo soportado es "KCM:UID", que utiliza un gestor de credenciales Kerberos para almacenar credenciales por UID de forma similar a KEYRING. Esta es la opción recomendada en las últimas distribuciones de Linux, que ofrecen un Gestor de Credenciales Kerberos. Si no es así, sugerimos usar KEYRING ya que es el método más seguro y predecible.

También es posible definir rutas de archivo personalizadas y usar el patrón "%u" para sustituir el ID numérico del usuario. Ejemplos:

krb5_ccache_type = DIR:/run/user/%u/krb5cc

Esto creará un archivo de caché de credenciales en el directorio especificado.

krb5_ccache_type = FILE:/tmp/krb5cc_%u

Esto creará un archivo de caché de credenciales.

Dejar vacío para solo realizar la autenticación kerberos sin tener una caché de tickets después de que el inicio de sesión haya tenido éxito. Esta configuración está vacía por defecto.

cached_login = sí|no

Winbind permite iniciar sesión usando credenciales cacheadas cuando winbind offline logon está habilitado. Para usar esta función desde el módulo PAM, esta opción debe estar configurada. Por defecto es "no".

silent = sí|no

No emitir ningún mensaje. Por defecto es "no".

mkhomedir = sí|no

Crea el directorio personal de un usuario sobre la marcha, la opción es válida en el bloque de sesión de PAM. Por defecto es "no".

warn_pwd_expire = días

Define el número de días antes de que pam_winbind comience a advertir sobre contraseñas que están a punto de expirar. Por defecto son 14 días.

pwd_change_prompt = sí|no

Genera un aviso para cambiar una contraseña caducada. Por defecto es "no".
