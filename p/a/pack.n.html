pack(n)

Paquete: tk

Licencias: TCL

pack(n) Comandos integrados de Tk pack(n)

NOMBRE

pack - Gestor de geometría que empaqueta alrededor de los bordes de la cavidad

SINOPSIS

pack opción arg ?arg ...?

DESCRIPCIÓN

El comando pack se utiliza para comunicarse con el empaquetador, un gestor de geometría que organiza los hijos de un padre empaquetándolos en orden alrededor de los bordes del padre. El comando pack puede tener varias formas, dependiendo del argumento opción:

pack ventana ?ventana ...? ?opciones?
Si el primer argumento de pack es un nombre de ventana (cualquier valor que comience con “.”), entonces el comando se procesa de la misma manera que pack configure.
pack configure ventana ?ventana ...? ?opciones?
Los argumentos consisten en los nombres de una o más ventanas de contenido seguidos de pares de argumentos que especifican cómo gestionar el contenido. Consulte EL ALGORITMO DEL EMPAQUETADOR a continuación para obtener detalles sobre cómo el empaquetador utiliza las opciones. Se admiten las siguientes opciones:
-después otro
Otro debe ser el nombre de otra ventana. Utilice su contenedor como contenedor para el contenido, e inserte el contenido justo después de otro en el orden de empaquetado.
-ancla ancla
Ancla debe ser una posición de ancla válida como n o sw; especifica dónde posicionar cada contenido en su parcela. El valor predeterminado es center.
-antes otro
Otro debe ser el nombre de otra ventana. Utilice su contenedor como contenedor para el contenido, e inserte el contenido justo antes de otro en el orden de empaquetado.
-expandir booleano
Especifica si el contenido debe expandirse para consumir espacio adicional en su contenedor. Booleano puede tener cualquier valor booleano válido, como 1 o no. El valor predeterminado es 0.
-rellenar estilo
Si la parcela de un contenido es más grande que sus dimensiones solicitadas, esta opción se puede utilizar para estirar el contenido. Estilo debe tener uno de los siguientes valores:
ninguno
Dale al contenido sus dimensiones solicitadas más cualquier relleno interno solicitado con -ipadx o -ipady. Este es el valor predeterminado.
x
Estire el contenido horizontalmente para llenar todo el ancho de su parcela (excepto dejar relleno externo según lo especificado por -padx).
y
Estire el contenido verticalmente para llenar toda la altura de su parcela (excepto dejar relleno externo según lo especificado por -pady).
ambos
Estire el contenido tanto horizontal como verticalmente.
-en contenedor
Inserte la ventana al final del orden de empaquetado para el contenedor dado por contenedor.
-ipadx cantidad
Cantidad especifica cuánto relleno interno horizontal dejar en cada lado del contenido. Cantidad debe ser una distancia de pantalla válida, como 2 o .5c. El valor predeterminado es 0.
-ipady cantidad
Cantidad especifica cuánto relleno interno vertical dejar en cada lado del contenido. Cantidad tiene un valor predeterminado de 0.
-padx cantidad
Cantidad especifica cuánto relleno externo horizontal dejar en cada lado del contenido. Cantidad puede ser una lista de dos valores para especificar el relleno para la izquierda y la derecha por separado. Cantidad tiene un valor predeterminado de 0.
-pady cantidad
Cantidad especifica cuánto relleno externo vertical dejar en cada lado del contenido. Cantidad puede ser una lista de dos valores para especificar el relleno para la parte superior e inferior por separado. Cantidad tiene un valor predeterminado de 0.
-lado lado
Especifica contra qué lado del contenedor se empaquetará el contenido. Debe ser left, right, top, o bottom. El valor predeterminado es top.

Si no se especifica ninguna opción -en, -después o -antes, cada contenido se insertará al final de la lista de empaquetado para su padre, a menos que ya esté gestionado por el empaquetador (en cuyo caso permanecerá donde está). Si se especifica una de estas opciones, todos los contenidos se insertarán en el punto especificado. Si alguno de los contenidos ya está gestionado por el gestor de geometría, las opciones no especificadas para ellos conservarán sus valores anteriores en lugar de recibir valores predeterminados.

pack olvidar ventana ?ventana ...?
Elimina cada una de las ventanas del orden de empaquetado para su contenedor y desmapea sus ventanas. El contenido ya no será gestionado por el empaquetador.
pack info ventana
Devuelve una lista cuyos elementos son el estado de configuración actual de la ventana dada por ventana en el mismo formato de opción-valor que podría especificarse a pack configure. Los dos primeros elementos de la lista son “-en contenedor”, donde contenedor es el contenedor de la ventana.
pack propagar contenedor ?booleano?
Si booleano tiene un valor booleano verdadero como 1 o on, la propagación está habilitada para contenedor, que debe ser un nombre de ventana (ver PROPAGACIÓN DE GEOMETRÍA a continuación). Si booleano tiene un valor booleano falso, la propagación está deshabilitada para contenedor. En cualquiera de estos casos, se devuelve una cadena vacía. Si se omite booleano, el comando devuelve 0 o 1 para indicar si la propagación está actualmente habilitada para contenedor. La propagación está habilitada por defecto.
pack hijos ventana
Devuelve una lista de todas las ventanas de contenido en el orden de empaquetado para ventana. El orden de las ventanas de contenido en la lista es el mismo que su orden en el orden de empaquetado. Si ventana no tiene contenido, se devuelve una cadena vacía.
pack contenido ventana
Sinónimo de pack hijos ventana.

EL ALGORITMO DEL EMPAQUETADOR

Para cada contenedor, el empaquetador mantiene una lista ordenada de ventanas de contenido llamada la lista de empaquetado. Las opciones de configuración -en, -después y -antes se utilizan para especificar el contenedor para cada contenido y la posición del contenido en la lista de empaquetado. Si no se proporciona ninguna de estas opciones para un contenido, este se añade al final de la lista de empaquetado de su padre.

El empaquetador organiza las ventanas de contenido para un contenedor escaneando la lista de empaquetado en orden. En el momento en que procesa cada contenido, un área rectangular dentro del contenedor aún no está asignada. Esta área se llama la cavidad; para el primer contenido es toda el área del contenedor.

Para cada contenido, el empaquetador realiza los siguientes pasos:

[1]
El empaquetador asigna una parcela rectangular para el contenido a lo largo del lado de la cavidad dado por la opción -lado del contenido. Si el lado es superior o inferior, el ancho de la parcela es el ancho de la cavidad y su altura es la altura solicitada del contenido más las opciones -ipady y -pady. Para el lado izquierdo o derecho, la altura de la parcela es la altura de la cavidad y el ancho es el ancho solicitado del contenido más las opciones -ipadx y -padx. La parcela puede ampliarse aún más debido a la opción -expandir (ver EXPANSIÓN a continuación).

pack(n)

Tk geometry manager

NAME

pack - geometry manager for Tk windows

SYNOPSIS

pack w ?options?
pack forget w
pack forget ?w ...?
pack propagate w ?boolean?
pack slaves w
pack reset
pack configure w ?options?
pack info w
pack w ?options?

DESCRIPTION

The pack command is used to manage (position and size) the children of a Tk window. It is a geometry manager, like grid and place, and it is used to arrange widgets within their parent widget.

The pack command takes one or more window names (or path names) as arguments, each of which must be a child of the same parent window. The pack command will then arrange these children within the parent window according to the geometry management rules described below. Each child widget is called a content and the window it is managed by is called the container. If a content's container is not its parent, the container must be a descendant of the content's parent.

The first argument is the window to be packed. Subsequent arguments are options that control how the window is packed.

The pack forget command removes a window from the packer's management. The window will be unmapped and will not be managed by the packer anymore. This is the opposite of packing a window.

The pack propagate command controls whether geometry information is propagated from the container window to its parent. If boolean is true (or omitted), then the container's requested width and height will be adjusted to exactly contain its packed children. If boolean is false, the container's requested size is not affected by the packed children, and the packer will use whatever space is available.

The pack slaves command returns a list of the packed children of w.

The pack reset command removes all packed geometry information from the container window w and its children.

The pack configure command reconfigures an already packed window using the specified options.

The pack info command returns a dictionary containing information about the packed window w.

The pack command can also be used to reconfigure an already packed window. In this case, the first argument is the window name and the remaining arguments are options. If the window is not already packed, it will be packed using these options. If it is already packed, its packing options will be updated.

The following options are available:

-side side
Specifies which side of the container the content should be packed against: top, bottom, left, or right. The default is top. As the packer processes its list of contents, it will reserve space for each content along the specified side of the remaining cavity. Contents packed on the top or bottom sides will expand horizontally to fill the width of the cavity. Contents packed on the left or right sides will expand vertically to fill the height of the cavity.
-fill fill
Specifies whether the content should expand to fill the space allocated to it by the packer. The fill option can be none (the default), x (fill horizontally), y (fill vertically), or both (fill horizontally and vertically). If the content is smaller than its allocated parcel, it will be expanded to fill the parcel as specified.
-expand ?boolean?
Specifies whether the content should expand to fill any extra space in the container. If boolean is true (or omitted), the content will expand if there is extra space. If boolean is false, the content will not expand.
-padx ?amount?
Specifies the amount of external padding to leave around the content in the horizontal direction. The amount is specified in screen units (e.g., pixels). The default is 0.
-pady ?amount?
Specifies the amount of external padding to leave around the content in the vertical direction. The amount is specified in screen units. The default is 0.
-ipadx ?amount?
Specifies the amount of internal padding to leave around the content within its own borders, in the horizontal direction. This increases the size of the content's parcel. The default is 0.
-ipady ?amount?
Specifies the amount of internal padding to leave around the content within its own borders, in the vertical direction. This increases the size of the content's parcel. The default is 0.
-anchor anchor
Specifies where the content should be placed within its parcel if the content is smaller than the parcel. anchor is a list of directions (e.g., n, s, e, w, center). The default is center.
-in window
Specifies the container window in which to pack the content. If omitted, the content's parent is used as the container.
-before beforeWindow
Specifies that the content should be packed just before the specified beforeWindow in the packing order. This option is only valid if the content is being packed into the same container as beforeWindow.
-after afterWindow
Specifies that the content should be packed just after the specified afterWindow in the packing order. This option is only valid if the content is being packed into the same container as afterWindow.
-expand ?boolean?
Specifies whether the content should expand to fill any extra space in the container. If boolean is true (or omitted), the content will expand if there is extra space. If boolean is false, the content will not expand.
-fill fill
Specifies whether the content should expand to fill the space allocated to it by the packer. The fill option can be none (the default), x (fill horizontally), y (fill vertically), or both (fill horizontally and vertically). If the content is smaller than its allocated parcel, it will be expanded to fill the parcel as specified.
-ipadx ?amount?
Specifies the amount of internal padding to leave around the content within its own borders, in the horizontal direction. This increases the size of the content's parcel. The default is 0.
-ipady ?amount?
Specifies the amount of internal padding to leave around the content within its own borders, in the vertical direction. This increases the size of the content's parcel. The default is 0.
-padx ?amount?
Specifies the amount of external padding to leave around the content in the horizontal direction. The amount is specified in screen units (e.g., pixels). The default is 0.
-pady ?amount?
Specifies the amount of external padding to leave around the content in the vertical direction. The amount is specified in screen units. The default is 0.

THE PACKER ALGORITHM

The packer algorithm works in three main stages:

[1]
The packer determines the requested width and height of the container window. This is done by first determining the requested width and height of each of the container's children. The packer then walks the list of packed children, allocating space for each child within the container. The packer maintains a rectangular region called the cavity, which is initially the entire area of the container window. For each child, the packer allocates a rectangular region called a parcel from the cavity. The size of the parcel is determined by the child's requested geometry, plus any internal padding (-ipadx and -ipady).
[2]
The packer chooses the dimensions of the content. The width will normally be the content's requested width plus twice its -ipadx option and the height will normally be the content's requested height plus twice its -ipady option. However, if the -fill option is x or both then the width of the content is expanded to fill the width of the parcel, minus twice the -padx option. If the -fill option is y or both then the height of the content is expanded to fill the width of the parcel, minus twice the -pady option.
[3]
The packer positions the content over its parcel. If the content is smaller than the parcel then the -anchor option determines where in the parcel the content will be placed. If -padx or -pady is non-zero, then the given amount of external padding will always be left between the content and the edges of the parcel.

Once a given content has been packed, the area of its parcel is subtracted from the cavity, leaving a smaller rectangular cavity for the next content. If a content does not use all of its parcel, the unused space in the parcel will not be used by subsequent content. If the cavity should become too small to meet the needs of a content then the content will be given whatever space is left in the cavity. If the cavity shrinks to zero size, then all remaining content on the packing list will be unmapped from the screen until the container window becomes large enough to hold them again.

EXPANSION

If a container window is so large that there will be extra space left over after all of its content have been packed, then the extra space is distributed uniformly among all of the content for which the -expand option is set. Extra horizontal space is distributed among the expandable content whose -side is left or right, and extra vertical space is distributed among the expandable content whose -side is top or bottom.

GEOMETRY PROPAGATION

The packer normally computes how large a container must be to just exactly meet the needs of its content, and it sets the requested width and height of the container to these dimensions. This causes geometry information to propagate up through a window hierarchy to a top-level window so that the entire sub-tree sizes itself to fit the needs of the leaf windows. However, the pack propagate command may be used to turn off propagation for one or more containers. If propagation is disabled then the packer will not set the requested width and height of the packer. This may be useful if, for example, you wish for a container window to have a fixed size that you specify.

RESTRICTIONS ON CONTAINER WINDOWS

The container for each content must either be the content's parent (the default) or a descendant of the content's parent. This restriction is necessary to guarantee that the content can be placed over any part of its container that is visible without danger of the content being clipped by its parent.

PACKING ORDER

If the container for a content is not its parent then you must make sure that the content is higher in the stacking order than the container. Otherwise the container will obscure the content and it will appear as if the content has not been packed correctly. The easiest way to make sure the content is higher than the container is to create the container window first: the most recently created window will be highest in the stacking order. Or, you can use the raise and lower commands to change the stacking order of either the container or the content.

EXAMPLE

# Make the widgets
label .t -text "This widget is at the top"    -bg red
label .b -text "This widget is at the bottom" -bg green
label .l -text "Left\nHand\nSide"
label .r -text "Right\nHand\nSide"
text .mid
.mid insert end "This layout is like Java's BorderLayout"
# Lay them out
pack .t   -side top    -fill x
pack .b   -side bottom -fill x
pack .l   -side left   -fill y
pack .r   -side right  -fill y
pack .mid -expand 1    -fill both
