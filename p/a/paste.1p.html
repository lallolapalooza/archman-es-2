PASTE(1P) Manual del Programador de POSIX PASTE(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

paste — fusionar líneas correspondientes o subsiguientes de archivos

SINOPSIS

paste [-s] [-d lista] archivo...

DESCRIPCIÓN

La utilidad paste concatenará las líneas correspondientes de los archivos de entrada dados y escribirá las líneas resultantes en la salida estándar.

La operación predeterminada de paste concatenará las líneas correspondientes de los archivos de entrada. El <nueva línea> de cada línea, excepto la línea del último archivo de entrada, se reemplazará con una <tabulación>.

Si se detecta una condición de fin de archivo en uno o más archivos de entrada, pero no en todos, paste se comportará como si se hubieran leído líneas vacías de los archivos en los que se detectó el fin de archivo, a menos que se especifique la opción -s.

OPCIONES

La utilidad paste se ajustará a las Definiciones Base del volumen de POSIX.1‐2017, Sección 12.2, Guías de Sintaxis de Utilidades.

Se admitirán las siguientes opciones:

-d lista
A menos que aparezca un carácter <barra invertida> en lista, cada carácter de lista es un elemento que especifica un carácter delimitador. Si aparece un carácter <barra invertida> en lista, el carácter <barra invertida> y uno o más caracteres que le siguen son un elemento que especifica un carácter delimitador según se describe a continuación. Estos elementos especifican uno o más delimitadores para usar, en lugar de la <tabulación> predeterminada, para reemplazar el <nueva línea> de las líneas de entrada. Los elementos en lista se usarán de forma circular; es decir, cuando la lista se agota, se reutiliza el primer elemento de la lista. Cuando se especifica la opción -s:
*
La última <nueva línea> de un archivo no se modificará.
*
El delimitador se restablecerá al primer elemento de lista después de procesar cada operando archivo.

Cuando la opción -s no está especificada:

*
Los caracteres <nueva línea> en el archivo especificado por el último operando archivo no se modificarán.
*
El delimitador se restablecerá al primer elemento de lista cada vez que se procese una línea de cada archivo.

Si un carácter <barra invertida> aparece en lista, este y el carácter que le sigue se usarán para representar los siguientes caracteres delimitadores:

\n
<nueva línea>.
\t
<tabulación>.
\\
Carácter <barra invertida>.
\0
Cadena vacía (no un carácter nulo). Si '\0' va seguido inmediatamente por el carácter 'x', el carácter 'X', o cualquier carácter definido por la palabra clave LC_CTYPE digit (ver el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 7, Localización), los resultados no están especificados.

Si otros caracteres siguen a la <barra invertida>, los resultados no están especificados.

-s
Concatenará todas las líneas de cada archivo de entrada en una línea de salida por archivo, en el orden de la línea de comandos. El <nueva línea> de cada línea, excepto la última línea de cada archivo de entrada, se reemplazará con una <tabulación>, a menos que se especifique lo contrario con la opción -d. Si un archivo de entrada está vacío, la línea de salida correspondiente a ese archivo consistirá únicamente en un carácter de <nueva línea>.

OPERANDOS

Se admitirá el siguiente operando:

archivo
Una ruta de un archivo de entrada. Si se especifica '-' para uno o más de los archivos, se utilizará la entrada estándar; la entrada estándar se leerá línea por línea, de forma circular, para cada instancia de '-'. Las implementaciones admitirán la fusión de al menos 12 operandos archivo.

ENTRADA ESTÁNDAR

La entrada estándar se utilizará solo si uno o más operandos archivo son '-'. Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Los archivos de entrada serán archivos de texto, excepto que las longitudes de línea no estarán limitadas.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de paste:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización sobre la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en contraposición a caracteres multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

Las líneas de entrada concatenadas se separarán con <tabulación> (u otros caracteres bajo el control de la opción -d) y terminarán con una <nueva línea>.

ERROR ESTÁNDAR

El error estándar se utilizará solo para mensajes de diagnóstico.

SALIDA ARCHIVOS

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Si uno o más archivos de entrada no se pueden abrir cuando la opción -s no está especificada, se escribirá un mensaje de diagnóstico en la salida de error estándar, pero no se escribirá ninguna salida en la salida estándar. Si se especifica la opción -s, la utilidad paste proporcionará el comportamiento predeterminado descrito en la Sección 1.4, Valores Predeterminados de Descripción de Utilidades.

This section describes conventions used throughout this volume of POSIX.1-2017.

NAME

paste - merge lines of files

SYNOPSIS

paste [-dlist] [-s] [file...]

DESCRIPTION

The paste utility shall replace the contents of the first file operand with data formed by concatenating the corresponding lines of the file operands. The corresponding lines are determined by their position relative to the beginning of the files. The first line of each input file is concatenated to form the first line of the output; the second line of each input file is concatenated to form the second line of the output, and so on. If an input file has fewer lines than the maximum number of lines in any other input file, the missing lines shall be treated as empty lines for the purpose of concatenation.

The default delimiter between concatenated lines is a <TAB> character.

The -s option shall replace the default behavior of concatenating corresponding lines with the behavior of concatenating all of the lines within each file. The lines from the first file operand are concatenated together, followed by the lines from the second file operand, and so on. The default delimiter between concatenated lines is a <TAB> character.

The -d option shall specify a list of delimiters to be used instead of the default <TAB>. The list is a list of one or more characters. The first delimiter in the list is used between concatenated lines from different files (corresponding lines). When the -s option is specified, the first delimiter is used between concatenated lines from the same file. If the list contains more than one delimiter, the delimiters are reused cyclically. If the list is empty, the default <TAB> is used.

The number of bytes in the output lines is not limited by {LINE_MAX}. If any of the concatenated lines exceed {LINE_MAX} bytes, including the delimiter and the trailing <newline> character, the behavior is undefined.

OPTIONS

The following options shall be supported:

-dlist
Specify a list of delimiters to use instead of the default <TAB> character. The list is a list of one or more characters. The first delimiter in the list is used between concatenated lines from different files (corresponding lines). When the -s option is specified, the first delimiter is used between concatenated lines from the same file. If the list contains more than one delimiter, the delimiters are reused cyclically. If the list is empty, the default <TAB> character is used.
-s
Concatenate all lines within each file, instead of concatenating corresponding lines from different files.

OPERANDS

The following operands shall be supported:

file
A path name of a file to be merged. If no file operands are specified, standard input shall be used.

STDIN

See the OPERANDS section.

INPUT FILES

The input files can be text files or binary files. Text files containing <newline> characters are read. Binary files are read until end-of-file. Lines are delimited by <newline> characters.

When reading text files, the <newline> character is treated as a line separator. When reading binary files, the <newline> character is also treated as a line separator. If a line in a text file does not end with a <newline> character, the utility appends one. If a line in a binary file does not end with a <newline> character, the utility appends one.

ENVIRONMENT VARIABLES

The following environment variables shall be supported:

LANG
Provide default values for the internationalization variables that are undefined or null. (See the Base Definitions volume of POSIX.1-2017, Section 8.2, Internationalization Variables for the significance of these variables.)
LC_ALL
Determine the locale category for any of the following variables that are undefined or null: LC_CTYPE, LC_MESSAGES, LC_NUMERIC, and LC_TIME.
LC_CTYPE
Determine the locale for the interpretation of sequences of bytes of text data as characters.
LC_MESSAGES
Determine the locale that should be used to format messages sent to standard error.
LC_NUMERIC
Determine the locale category for the formatting of numeric quantities (for example, the decimal point symbol and the grouping unit symbol).
LC_TIME
Determine the locale category for any of the following: radix search character, string conversion.

ASYNCHRONOUS EVENTS

Undefined.

STDOUT

The concatenated lines shall be written to standard output.

STDERR

The standard error shall be used only for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

Diagnostics are produced for invalid options or operands. In the case of a valid command line, the exit status shall be zero; otherwise, it shall be greater than zero.

CONSEQUENCES OF ERRORS

None.

APPLICATION USAGE

None.

EXAMPLES

1.
Write out a directory in four columns:
ls | paste - - - -
2.
Combine pairs of lines from a file into single lines:
paste -s -d "\t\n" file

RATIONALE

The POSIX.1-2017 standard requires that the POSIX utilities only use a subset of the escape sequences that are permitted by the C language. The printf utility, in its POSIX.1-2017 specification, is permitted to recognize a larger set of escape sequences. The specific sequences that are permitted by POSIX.1-2017 for backslash-escaped delimiters are listed in this volume of POSIX.1-2017. Historical implementations treat \x, where x is not in this list, as x, but future implementations are free to expand this list to recognize other common escapes similar to those accepted by printf and other standard utilities.

Most of the standard utilities work on text files. The cut utility can be used to turn files with arbitrary line lengths into a set of text files containing the same data. The paste utility can be used to create (or recreate) files with arbitrary line lengths. For example, if file contains long lines:

cut -b 1-500 -n file > file1
cut -b 501- -n file > file2

creates file1 (a text file) with lines no longer than 500 bytes (plus the <newline>) and file2 that contains the remainder of the data from file. Note that file2 is not a text file if there are lines in file that are longer than 500 + {LINE_MAX} bytes. The original file can be recreated from file1 and file2 using the command:

paste -d "\0" file1 file2 > file

The commands:

paste -d "\0" ...
paste -d "" ...

are not necessarily equivalent; the latter is not specified by this volume of POSIX.1-2017 and may result in an error. The construct \0 is used to mean ``no separator'' because historical versions of paste did not follow the syntax guidelines, and the command:

paste -d"" ...

could not be handled properly by getopt().
