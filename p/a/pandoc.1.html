NOMBRE

pandoc - convertidor general de marcado

SINOPSIS

pandoc [opciones] [archivo-entrada]...

DESCRIPCIÓN

Pandoc es una biblioteca de Haskell para convertir de un formato de marcado a otro, y una herramienta de línea de comandos que utiliza esta biblioteca.

Pandoc puede convertir entre numerosos formatos de marcado y procesamiento de textos, incluyendo, entre otros, varios sabores de Markdown, HTML, LaTeX y documentos de Word (.docx). Para obtener listas completas de formatos de entrada y salida, consulte las opciones --from y --to a continuación. Pandoc también puede producir salida en PDF: consulte la creación de un PDF, a continuación.

La versión mejorada de Markdown de Pandoc incluye sintaxis para tablas, listas de definición, bloques de metadatos, notas al pie, citas, matemáticas y mucho más. Consulte a continuación bajo Markdown de Pandoc.

Pandoc tiene un diseño modular: consta de un conjunto de lectores, que analizan texto en un formato dado y producen una representación nativa del documento (un árbol de sintaxis abstracta o AST), y un conjunto de escritores, que convierten esta representación nativa en un formato de destino. Por lo tanto, añadir un formato de entrada o salida solo requiere añadir un lector o un escritor. Los usuarios también pueden ejecutar filtros personalizados de pandoc para modificar el AST intermedio.

Dado que la representación intermedia de un documento en pandoc es menos expresiva que muchos de los formatos entre los que convierte, no se deben esperar conversiones perfectas entre todos los formatos y todos los demás. Pandoc intenta preservar los elementos estructurales de un documento, pero no los detalles de formato como el tamaño de los márgenes. Y algunos elementos del documento, como tablas complejas, pueden no encajar en el modelo de documento simple de pandoc. Si bien las conversiones del Markdown de pandoc a todos los formatos aspiran a ser perfectas, las conversiones de formatos más expresivos que el Markdown de pandoc pueden ser previsiblemente con pérdida de información.

Uso de pandoc

Si no se especifican archivos-entrada, la entrada se lee de stdin. La salida va a stdout por defecto. Para la salida a un archivo, use la opción -o:

pandoc -o salida.html entrada.txt

Por defecto, pandoc produce un fragmento de documento. Para producir un documento independiente (por ejemplo, un archivo HTML válido que incluya <head> y <body>), use el indicador -s o --standalone:

pandoc -s -o salida.html entrada.txt

Para obtener más información sobre cómo se producen los documentos independientes, consulte Plantillas a continuación.

Si se proporcionan varios archivos de entrada, pandoc los concatenará (con líneas en blanco entre ellos) antes de analizarlos. (Use --file-scope para analizar archivos individualmente.)

Especificación de formatos

El formato de entrada y salida se puede especificar explícitamente usando opciones de línea de comandos. El formato de entrada se puede especificar usando la opción -f/--from, el formato de salida usando la opción -t/--to. Por lo tanto, para convertir hola.txt de Markdown a LaTeX, puede escribir:

pandoc -f markdown -t latex hola.txt

Para convertir hola.html de HTML a Markdown:

pandoc -f html -t markdown hola.html

Los formatos de entrada y salida compatibles se enumeran a continuación en Opciones (consulte -f para formatos de entrada y -t para formatos de salida). También puede usar pandoc --list-input-formats y pandoc --list-output-formats para imprimir listas de formatos compatibles.

Si el formato de entrada o salida no se especifica explícitamente, pandoc intentará adivinarlo a partir de las extensiones de los nombres de archivo. Por lo tanto, por ejemplo,

pandoc -o hola.tex hola.txt

convertirá hola.txt de Markdown a LaTeX. Si no se especifica ningún archivo de salida (por lo que la salida va a stdout), o si la extensión del archivo de salida es desconocida, el formato de salida será HTML por defecto. Si no se especifica ningún archivo de entrada (por lo que la entrada proviene de stdin), o si las extensiones de los archivos de entrada son desconocidas, se asumirá que el formato de entrada es Markdown.

Codificación de caracteres

Pandoc utiliza la codificación de caracteres UTF-8 tanto para la entrada como para la salida. Si su codificación de caracteres local no es UTF-8, debería canalizar la entrada y la salida a través de iconv:

iconv -t utf-8 entrada.txt | pandoc | iconv -f utf-8

Tenga en cuenta que en algunos formatos de salida (como HTML, LaTeX, ConTeXt, RTF, OPML, DocBook y Texinfo), la información sobre la codificación de caracteres se incluye en la cabecera del documento, la cual solo se incluirá si usa la opción -s/--standalone.

Creación de un PDF

Para producir un PDF, especifique un archivo de salida con una extensión .pdf:

pandoc prueba.txt -o prueba.pdf

Por defecto, pandoc utilizará LaTeX para crear el PDF, lo que requiere que esté instalado un motor LaTeX (consulte --pdf-engine a continuación). Alternativamente, pandoc puede usar ConTeXt, roff ms o HTML como formato intermedio. Para hacer esto, especifique un archivo de salida con una extensión .pdf, como antes, pero añada la opción --pdf-engine o -t context, -t html, o -t ms a la línea de comandos. La herramienta utilizada para generar el PDF a partir del formato intermedio se puede especificar usando --pdf-engine.

Puede controlar el estilo del PDF usando variables, dependiendo del formato intermedio utilizado: consulte variables para LaTeX, variables para ConTeXt, variables para wkhtmltopdf, variables para ms. Cuando se usa HTML como formato intermedio, la salida se puede estilizar usando --css.

Para depurar la creación del PDF, puede ser útil examinar la representación intermedia: en lugar de -o prueba.pdf, use por ejemplo -s -o prueba.tex para generar la salida LaTeX. Luego puede probarla con pdflatex prueba.tex.

Al usar LaTeX, los siguientes paquetes deben estar disponibles (incluidos en todas las versiones recientes de TeX Live): amsfonts, amsmath, lm, unicode-math, iftex, listings (si se usa la opción --listings), fancyvrb, longtable, booktabs, graphicx (si el documento contiene imágenes), hyperref, xcolor, soul, geometry (con la variable geometry establecida), setspace (con linestretch), y babel (con lang). Si se establece CJKmainfont, se necesita xeCJK. El uso de xelatex o lualatex como motor PDF requiere fontspec. lualatex usa selnolig. xelatex usa bidi (con la variable dir establecida). Si se establece la variable mathspec, xelatex usará mathspec en lugar de unicode-math. Los paquetes upquote y microtype se usan si están disponibles, y se usará csquotes para tipografía si la variable o campo de metadatos csquotes se establece a un valor verdadero. SOPORTE DE BIBLIOGRAFÍA Y OTROS

Los paquetes natbib, bibtex y biber se pueden usar opcionalmente para la representación de citas. Los siguientes paquetes se usarán para mejorar la calidad de la salida si están presentes, pero pandoc no requiere su presencia:

upquote (para comillas rectas en entornos verbatim), microtype (para mejores ajustes de espaciado), parskip (para mejores espacios entre párrafos), xurl (para mejores saltos de línea en URLs), bookmark (para mejores marcadores de PDF) y footnotehyper o footnote (para permitir notas al pie en tablas).

Lectura desde la Web

En lugar de un archivo de entrada, se puede proporcionar una URI absoluta. En este caso, pandoc obtendrá el contenido usando HTTP:

pandoc -f html -t markdown https://www.fsf.org

Es posible proporcionar una cadena de Agente de Usuario personalizada u otra cabecera al solicitar un documento desde una URL:

pandoc -f html -t markdown --request-header User-Agent:"Mozilla/5.0" \
  https://www.fsf.org

Reader options

--shift-heading-level-by=NUMBER
Shift heading levels by a positive or negative integer. For example, with --shift-heading-level-by=-1, level 2 headings become level 1 headings, and level 3 headings become level 2 headings. Headings cannot have a level less than 1, so a heading that would be shifted below level 1 becomes a regular paragraph. Exception: with a shift of -N, a level-N heading at the beginning of the document replaces the metadata title. --shift-heading-level-by=-1 is a good choice when converting HTML or Markdown documents that use an initial level-1 heading for the document title and level-2+ headings for sections. --shift-heading-level-by=1 may be a good choice for converting Markdown documents that use level-1 headings for sections to HTML, since pandoc uses a level-1 heading to render the document title.
--base-header-level=NUMBER
Deprecated. Use --shift-heading-level-by=X instead, where X = NUMBER - 1. Specify the base level for headings (defaults to 1).
--indented-code-classes=CLASSES
Specify classes to use for indented code blocks–for example, perl,numberLines or haskell. Multiple classes may be separated by spaces or commas.
--default-image-extension=EXTENSION
Specify a default extension to use when image paths/URLs have no extension. This allows you to use the same source for formats that require different kinds of images. Currently this option only affects the Markdown and LaTeX readers.
--file-scope[=true|false]
Parse each file individually before combining for multifile documents. This will allow footnotes in different files with the same identifiers to work as expected. If this option is set, footnotes and links will not work across files. Reading binary files (docx, odt, epub) implies --file-scope.

If two or more files are processed using --file-scope, prefixes based on the filenames will be added to identifiers in order to disambiguate them, and internal links will be adjusted accordingly. For example, a header with identifier foo in subdir/file1.txt will have its identifier changed to subdir__file1.txt__foo.

In addition, a Div with an identifier based on the filename will be added around the file’s content, so that internal links to the filename will point to this Div’s identifier.

-F PROGRAM, --filter=PROGRAM
Specify an executable to be used as a filter transforming the pandoc AST after the input is parsed and before the output is written. The executable should read JSON from stdin and write JSON to stdout. The JSON must be formatted like pandoc’s own JSON input and output. The name of the output format will be passed to the filter as the first argument. Hence,

is equivalent to

The latter form may be useful for debugging filters.

Opciones generales del escritor

-s, --standalone
Produce una salida con una cabecera y pie de página apropiados (por ejemplo, un archivo HTML, LaTeX, TEI o RTF independiente, no un fragmento). Esta opción se establece automáticamente para las salidas pdf, epub, epub3, fb2, docx y odt. Para la salida native, esta opción hace que se incluya metadatos; de lo contrario, los metadatos se suprimen.
--template=FILE|URL
Utiliza el archivo especificado como plantilla personalizada para el documento generado. Implica --standalone. Vea Plantillas, más adelante, para obtener una descripción de la sintaxis de las plantillas. Si no se especifica una extensión, se añadirá una extensión correspondiente al escritor, de modo que --template=special busque special.html para la salida HTML. Si la plantilla no se encuentra, pandoc la buscará en el subdirectorio templates del directorio de datos del usuario (vea --data-dir). Si esta opción no se utiliza, se usará una plantilla predeterminada apropiada para el formato de salida (vea -D/--print-default-template).
-V KEY[=VAL], --variable=KEY[:VAL]
Establece la variable de plantilla KEY al valor VAL al renderizar el documento en modo independiente. Si no se especifica VAL, la clave recibirá el valor true.
--sandbox[=true|false]
Ejecuta pandoc en un entorno aislado (sandbox), limitando las operaciones de entrada/salida en lectores y escritores a la lectura de los archivos especificados en la línea de comandos. Tenga en cuenta que esta opción no limita las operaciones de E/S de los filtros ni la producción de documentos PDF. Pero ofrece seguridad contra, por ejemplo, la divulgación de archivos mediante el uso de directivas include. Cualquiera que utilice pandoc con entradas de usuario no confiables debería usar esta opción.

Nota: algunos lectores y escritores (por ejemplo, docx) necesitan acceso a archivos de datos. Si estos están almacenados en el sistema de archivos, pandoc no podrá encontrarlos cuando se ejecute en modo --sandbox y generará un error. Para estas aplicaciones, recomendamos usar una binaria de pandoc compilada con la opción embed_data_files, que hace que los archivos de datos se incorporen a la binaria en lugar de almacenarse en el sistema de archivos.

-D FORMAT, --print-default-template=FORMAT
Imprime la plantilla predeterminada del sistema para un FORMATO de salida. (Vea -t para una lista de FORMATOs posibles). Las plantillas en el directorio de datos del usuario se ignoran. Esta opción se puede usar con -o/--output para redirigir la salida a un archivo, pero -o/--output debe aparecer antes de --print-default-template en la línea de comandos.

--data-dir=DIRECTORY
Specify the path to the pandoc data directory. This option is generally not needed, as pandoc will automatically search for the data directory in the standard locations. However, it can be useful if you have a non-standard installation or want to use a custom set of templates or filters. This option may be used with -o/--output to redirect output to a file, but -o/--output must come before --data-dir on the command line.
--print-default-data-file=FILE
Prints the contents of a default data file (e.g., a default template) to standard output. This is useful for seeing the default settings or for modifying them. For a list of available data files, see Data files below. This option may be used with -o/--output to redirect output to a file, but -o/--output must come before --print-default-data-file on the command line.
--eol=crlf|lf|native
Especifica manualmente los finales de línea: crlf (Windows), lf (macOS/Linux/UNIX), o native (finales de línea apropiados para el SO en el que se está ejecutando pandoc). El valor predeterminado es native.
--dpi=NÚMERO
Especifica el valor dpi (puntos por pulgada) predeterminado para la conversión de píxeles a pulgadas/centímetros y viceversa. (Técnicamente, el término correcto sería ppi: píxeles por pulgada). El valor predeterminado es 96dpi. Cuando las imágenes contienen información sobre dpi internamente, el valor codificado se utiliza en lugar del valor predeterminado especificado por esta opción.
--wrap=auto|none|preserve
Determina cómo se ajusta el texto en la salida (el código fuente, no la versión renderizada). Con auto (el valor predeterminado), pandoc intentará ajustar las líneas al ancho de columna especificado por --columns (predeterminado 72). Con none, pandoc no ajustará las líneas en absoluto. Con preserve, pandoc intentará preservar el ajuste del documento fuente (es decir, donde hay saltos de línea no semánticos en el fuente, habrá saltos de línea no semánticos en la salida también). En la salida ipynb, esta opción afecta al ajuste del contenido de las celdas de markdown.
--columns=NÚMERO
Especifica la longitud de las líneas en caracteres. Esto afecta al ajuste de texto en el código fuente generado (ver --wrap). También afecta al cálculo de los anchos de columna para las tablas de texto plano (ver Tablas más abajo).
--toc[=true|false], --table-of-contents[=true|false]
Incluye una tabla de contenidos generada automáticamente (o, en el caso de latex, context, docx, odt, opendocument, rst, o ms, una instrucción para crear una) en el documento de salida. Esta opción no tiene efecto a menos que se use -s/--standalone, y no tiene efecto en la salida man, docbook4, docbook5, o jats.

Tenga en cuenta que si está produciendo un PDF a través de ms, la tabla de contenidos aparecerá al principio del documento, antes del título. Si prefiere que esté al final del documento, use la opción --pdf-engine-opt=--no-toc-relocation.

--toc-depth=NÚMERO
Especifica el número de niveles de sección a incluir en la tabla de contenidos. El valor predeterminado es 3 (lo que significa que los encabezados de nivel 1, 2 y 3 se enumerarán en el contenido).
--strip-comments[=true|false]

Renderizado de citas

-C, --citeproc
Procesa las citas en el archivo, reemplazándolas por citas renderizadas y añadiendo una bibliografía. El procesamiento de citas no se llevará a cabo a menos que se proporcionen datos bibliográficos, ya sea a través de un archivo externo especificado usando la opción --bibliography o el campo bibliography en los metadatos, o a través de una sección references en los metadatos que contenga una lista de citas en formato YAML CSL con formato Markdown. El estilo se controla mediante una hoja de estilos CSL especificada usando la opción --csl o el campo csl en los metadatos. (Si no se especifica ninguna hoja de estilos, se utilizará el estilo chicago-author-date por defecto). La transformación de procesamiento de citas se puede aplicar antes o después de los filtros o filtros Lua (ver --filter, --lua-filter): estas transformaciones se aplican en el orden en que aparecen en la línea de comandos. Para más información, consulta la sección sobre Citas.
--bibliography=ARCHIVO
Establece el campo bibliography en los metadatos del documento a ARCHIVO, anulando cualquier valor establecido en los metadatos. Si proporcionas este argumento varias veces, cada ARCHIVO se añadirá a la bibliografía. Si ARCHIVO es una URL, se obtendrá a través de HTTP. Si ARCHIVO no se encuentra relativo al directorio de trabajo, se buscará en la ruta de recursos (ver --resource-path).
--csl=ARCHIVO
Establece el campo csl en los metadatos del documento a ARCHIVO, anulando cualquier valor establecido en los metadatos. (Esto es equivalente a --metadata csl=ARCHIVO.) Si ARCHIVO es una URL, se obtendrá a través de HTTP. Si ARCHIVO no se encuentra relativo al directorio de trabajo, se buscará en la ruta de recursos (ver --resource-path) y finalmente en el subdirectorio csl del directorio de datos de usuario de pandoc.
--citation-abbreviations=ARCHIVO
Establece el campo citation-abbreviations en los metadatos del documento a ARCHIVO, anulando cualquier valor establecido en los metadatos. (Esto es equivalente a --metadata citation-abbreviations=ARCHIVO.) Si ARCHIVO es una URL, se obtendrá a través de HTTP. Si ARCHIVO no se encuentra relativo al directorio de trabajo, se buscará en la ruta de recursos (ver --resource-path) y finalmente en el subdirectorio csl del directorio de datos de usuario de pandoc.
--natbib
Utiliza natbib para las citas en la salida LaTeX. Esta opción no es para usar con la opción --citeproc ni con salida PDF. Está pensada para producir un archivo LaTeX que pueda ser procesado con bibtex.
--biblatex
Utiliza biblatex para las citas en la salida LaTeX. Esta opción no es para usar con la opción --citeproc ni con salida PDF. Está pensada para producir un archivo LaTeX que pueda ser procesado con bibtex o biber.

Renderizado de matemáticas en HTML

El valor predeterminado es renderizar las matemáticas TeX tanto como sea posible utilizando caracteres Unicode. Las fórmulas se colocan dentro de una span con class="math", para que puedan ser estilizadas de manera diferente del texto circundante si es necesario. Sin embargo, esto solo da resultados aceptables para matemáticas básicas, por lo que normalmente querrás usar --mathjax u alguna de las siguientes opciones.

--mathjax[=URL]
Utiliza MathJax para mostrar matemáticas TeX incrustadas en la salida HTML. Las matemáticas TeX se colocarán entre \(...\) (para matemáticas en línea) o \[...\] (para matemáticas en pantalla) y se envolverán en etiquetas <span> con la clase math. Luego, el JavaScript de MathJax las renderizará. La URL debe apuntar al script de carga MathJax.js. Si no se proporciona una URL, se insertará un enlace al CDN de Cloudflare.
--mathml
Convierte matemáticas TeX a MathML (en epub3, docbook4, docbook5, jats, html4 y html5). Este es el valor predeterminado en la salida odt. MathML es soportado nativamente por los principales navegadores web y lectores de libros electrónicos seleccionados.
--webtex[=URL]
Convierte fórmulas TeX a etiquetas <img> que enlazan a un script externo que convierte fórmulas a imágenes. La fórmula se codificará en formato URL y se concatenará con la URL proporcionada. Para imágenes SVG, por ejemplo, puedes usar --webtex https://latex.codecogs.com/svg.latex?. Si no se especifica una URL, se utilizará la URL de CodeCogs que genera PNGs (https://latex.codecogs.com/png.latex?). Nota: la opción --webtex afectará también a la salida de Markdown, lo cual es útil si tu objetivo es una versión de Markdown sin soporte nativo para matemáticas.
--katex[=URL]
Utiliza KaTeX para mostrar matemáticas TeX incrustadas en la salida HTML. La URL es la URL base de la biblioteca KaTeX. Ese directorio debe contener un archivo katex.min.js y un archivo katex.min.css. Si no se proporciona una URL, se insertará un enlace al CDN de KaTeX.
--gladtex
Encierra las matemáticas TeX en etiquetas <eq> en la salida HTML. El HTML resultante puede ser procesado por GladTeX para producir imágenes SVG de las fórmulas compuestas y un archivo HTML con estas imágenes incrustadas.
pandoc -s --gladtex input.md -o myfile.htex
gladtex -d image_dir myfile.htex
# produce myfile.html e imágenes en image_dir

ARCHIVOS DE VALORES PREDETERMINADOS

La opción --defaults se puede usar para especificar un paquete de opciones, en forma de un archivo YAML.

Los campos que se omitan simplemente tendrán sus valores predeterminados normales. Por lo tanto, un archivo de valores predeterminados puede ser tan simple como una línea:

verbosity: INFO

En los campos que esperan una ruta de archivo (o una lista de rutas de archivo), se puede usar la siguiente sintaxis para interpolar variables de entorno:

csl:  ${HOME}/mycsldir/special.csl

${USERDATA} también se puede usar; esto siempre se resolverá en el directorio de datos de usuario que esté activo cuando se analice el archivo de valores predeterminados, independientemente de la configuración de la variable de entorno USERDATA.

${.} se resolverá en el directorio que contiene el archivo de valores predeterminados en sí. Esto le permite referirse a recursos contenidos en ese directorio:

epub-cover-image: ${.}/cover.jpg
epub-metadata: ${.}/meta.xml
resource-path:
- .             # el directorio de trabajo desde el cual se ejecuta pandoc
- ${.}/images   # el subdirectorio de imágenes del directorio
                # que contiene este archivo de valores predeterminados

Esta sintaxis de interpolación de variables de entorno *solo* funciona en campos que esperan rutas de archivo.

Los archivos de valores predeterminados se pueden colocar en el subdirectorio defaults del directorio de datos de usuario y usarse desde cualquier directorio. Por ejemplo, se podría crear un archivo que especifique los valores predeterminados para escribir cartas, guardarlo como letter.yaml en el subdirectorio defaults del directorio de datos de usuario, y luego invocar estos valores predeterminados desde cualquier directorio usando pandoc --defaults letter o pandoc -dletter.

Cuando se usan múltiples valores predeterminados, sus contenidos se combinarán.

Tenga en cuenta que, donde los argumentos de línea de comandos se pueden repetir (--metadata-file, --css, --include-in-header, --include-before-body, --include-after-body, --variable, --metadata, --syntax-definition), los valores especificados en la línea de comandos se combinarán con los valores especificados en el archivo de valores predeterminados, en lugar de reemplazarlos.

TEMPLATES

When the -s/--standalone option is used, pandoc uses a template to add header and footer material that is needed for a self-standing document. To see the default template that is used, just type

pandoc -D *FORMAT*

where FORMAT is the name of the output format. A custom template can be specified using the --template option. You can also override the system default templates for a given output format FORMAT by putting a file templates/default.*FORMAT* in the user data directory (see --data-dir, above). Exceptions:

•
For odt output, customize the default.opendocument template.
•
For pdf output, customize the default.latex template (or the default.context template, if you use -t context, or the default.ms template, if you use -t ms, or the default.html template, if you use -t html).
•
docx and pptx have no template (however, you can use --reference-doc to customize the output).

Templates contain variables, which allow for the inclusion of arbitrary information at any point in the file. They may be set at the command line using the -V/--variable option. If a variable is not set, pandoc will look for the key in the document’s metadata, which can be set using either YAML metadata blocks or with the -M/--metadata option. In addition, some variables are given default values by pandoc. See Variables below for a list of variables used in pandoc’s default templates.

If you use custom templates, you may need to revise them as pandoc changes. We recommend tracking the changes in the default templates, and modifying your custom templates accordingly. An easy way to do this is to fork the pandoc-templates repository and merge in changes after each pandoc release.

Template syntax

Comments

Anything between the sequence $-- and the end of the line will be treated as a comment and omitted from the output.

Delimiters

To mark variables and control structures in the template, either $...$ or ${...} may be used as delimiters. The styles may also be mixed in the same template, but the opening and closing delimiter must match in each case. The opening delimiter may be followed by one or more spaces or tabs, which will be ignored. The closing delimiter may be preceded by one or more spaces or tabs, which will be ignored.

To include a literal $ in the document, use $$.

Interpolated variables

A slot for an interpolated variable is a variable name surrounded by matched delimiters. Variable names must begin with a letter and can contain letters, numbers, _, -, and .. The keywords it, if, else, endif, for, sep, and endfor may not be used as variable names. Examples:

$foo$
$foo.bar.baz$
$foo_bar.baz-bim$
$ foo $
${foo}
${foo.bar.baz}
${foo_bar.baz-bim}
${ foo }

Variable names with periods are used to get at structured variable values. So, for example, employee.salary will return the value of the salary field of the object that is the value of the employee field.

•
If the value of the variable is a simple value, it will be rendered verbatim. (Note that no escaping is done; the assumption is that the calling program will escape the strings appropriately for the output format.)
•
If the value is a list, the values will be concatenated.
•
If the value is a map, the string true will be rendered.
•
Every other value will be rendered as the empty string.

Conditionals

A conditional begins with if(variable) (enclosed in matched delimiters) and ends with endif (enclosed in matched delimiters). It may optionally contain an else (enclosed in matched delimiters). The if section is used if variable has a non-empty value, otherwise the else section is used (if present). Examples:

$if(foo)$bar$endif$
$if(foo)$
  $foo$
$endif$
$if(foo)$
part one
$else$
part two
$endif$
${if(foo)}bar${endif}
${if(foo)}
  ${foo}
${endif}
${if(foo)}
${ foo.bar }
${else}
no foo!
${endif}

The keyword elseif may be used to simplify complex nested conditionals:

$if(foo)$
XXX
$elseif(bar)$
YYY
$else$
ZZZ
$endif$

For loops

A for loop begins with for(variable) (enclosed in matched delimiters) and ends with endfor (enclosed in matched delimiters).

•
If variable is an array, the material inside the loop will be evaluated repeatedly, with variable being set to each value of the array in turn, and concatenated.
•
If variable is a map, the material inside will be set to the map.
•
If the value of the associated variable is not an array or a map, a single iteration will be performed on its value.

Examples:

$for(items)$
  $it$
$sep$,$endfor$

$for(items)$
  $it.name$: $it.price$
$sep$

$endfor$

${for(items)}
  ${it}
${sep},${endfor}

${for(items)}
  ${it.name}: ${it.price}
${sep}

${endfor}

If the variable is a map, you can iterate over its keys using for_keys. For example, if `myMap` is a map `{a: 1, b: 2}`, then $for(myMap)$ ... $endfor$ will render the string "true", but $for_keys(myMap)$ ... $endfor$ will iterate over "a" and "b".

$for_keys(myMap)$
  $it$
$sep$,$endfor$

The sep keyword (used inside a loop) prints its contents between iterations. It is empty on the first iteration and prints its contents before subsequent iterations. It is often used for separating list items with commas or newlines.

If the variable is a map, the special variable key will be set to the current key, and value will be set to the current value.

$for(myMap)$
  Key: $key$, Value: $value$
$sep$

$endfor$

If the variable is an array of maps, then the key key is not used. Instead, the fields of the map are available directly as variables.

$for(items)$
  $name$: $price$
$sep$

$endfor$

The it variable within a loop refers to the current item being iterated over. This is identical to the value of variable itself, unless the variable is a map and you are iterating over its keys (in which case it is the same as key).

Macro definitions

You can define reusable macros in your template:

$def(macro_name, arg1, arg2)$
  ... macro body ...
$enddef$

Macros are invoked like variables:

$macro_name(value1, value2)$

The macro body is evaluated with the arguments bound to the specified names. The result is substituted into the document.

Macros defined with def can only be used within the template they are defined in. Use the --template option to specify a template file containing macro definitions.

Include files

You can include the contents of other files in your template:

$include(filename)$

Pandoc will look for `filename` in the same directory as the template file, or in the user data directory.

The code-overflow variable controls how code blocks that are too long to fit on a slide are handled. If set to wrap, the code will be wrapped. If set to scroll, a scrollbar will be added.

The table-of-contents variable is an alias for toc.

The pandoc-title-output variable, when set to true, will cause the document title to be output as an h1 element at the beginning of the document.

The id-prefix variable allows you to add a prefix to all generated IDs, which can be useful for avoiding ID collisions when embedding HTML documents within other HTML documents.

Variables for specific formats

Some variables are specific to certain output formats:

•
LaTeX: documentclass, classoption, fontsize, documentclassoption, papersize, geometry, header-includes, include-before, include-after.
•
ConTeXt: main, header-includes, include-before, include-after.
•
EPUB: epub-cover-image, epub-title-page, epub-metadata, epub-fonts.
•
HTML: include-before, include-after, katex-css, katex-js, mathjax-script, highlight-css, code-overflow.

The documentclass, classoption, and fontsize variables are used to specify the LaTeX document class, its options, and the base font size. The documentclassoption variable can be used to specify additional document class options. The papersize variable sets the paper size. The geometry variable allows you to set page margins using the geometry package.

For ConTeXt, the main variable can be used to specify the main ConTeXt module to load.

The include-before and include-after variables can be used to include arbitrary content before or after the main document body. This is useful for adding custom headers, footers, or other elements.

The highlight-css variable specifies the path to a CSS file for syntax highlighting. The katex-css and katex-js variables specify the paths to the KaTeX CSS and JavaScript files, respectively. The mathjax-script variable specifies the MathJax script to include.

The code-overflow variable controls how code blocks that are too long to fit on a slide are handled. If set to wrap, the code will be wrapped. If set to scroll, a scrollbar will be added.

Partiales

Los parciales (subplantillas almacenadas en archivos diferentes) se pueden incluir utilizando el nombre del parcial, seguido de (), por ejemplo:

${ styles() }

Los parciales se buscarán en el directorio que contiene la plantilla principal. Se asumirá que el nombre del archivo tiene la misma extensión que la plantilla principal si carece de extensión. Al llamar al parcial, también se puede utilizar el nombre completo, incluida la extensión del archivo:

${ styles.html() }

(Si no se encuentra un parcial en el directorio de la plantilla y la ruta de la plantilla se proporciona como una ruta relativa, también se buscará en el subdirectorio templates del directorio de datos del usuario.)

Los parciales opcionalmente se pueden aplicar a variables usando dos puntos:

${ date:fancy() }
${ articles:bibentry() }

Si articles es una matriz, esto iterará sobre sus valores, aplicando el parcial bibentry() a cada uno. Por lo tanto, el segundo ejemplo anterior es equivalente a

${ for(articles) }
${ it:bibentry() }
${ endfor }

Tenga en cuenta que la palabra clave anafórica it debe usarse al iterar sobre parciales. En los ejemplos anteriores, el parcial bibentry debería contener it.title (y así sucesivamente) en lugar de articles.title.

Las nuevas líneas finales se omiten de los parciales incluidos.

Los parciales pueden incluir otros parciales.

Se puede especificar un separador entre los valores de una matriz entre corchetes, inmediatamente después del nombre de la variable o parcial:

${months[, ]}$
${articles:bibentry()[; ]$

El separador en este caso es literal y (a diferencia de sep en un bucle for explícito) no puede contener variables interpoladas ni otras directivas de plantilla.

Anidación

Para asegurar que el contenido esté "anidado", es decir, las líneas subsiguientes indentadas, use la directiva ^:

$item.number$  $^$$item.description$ ($item.price$)

En este ejemplo, si item.description tiene varias líneas, todas se indentarán para alinearse con la primera línea:

00123  Una buena botella de whisky Oban de 18 años
       ($148)

Para anidar varias líneas al mismo nivel, alinéelas con la directiva ^ en la plantilla. Por ejemplo:

$item.number$  $^$$item.description$ ($item.price$)
               (Disponible hasta $item.sellby$.)

producirá

00123  Una buena botella de whisky Oban de 18 años
       ($148)
       (Disponible hasta el 30 de marzo de 2020.)

Si una variable aparece sola en una línea, precedida de espacios en blanco y sin texto o directivas adicionales en la misma línea, y el valor de la variable contiene varias líneas, se anidará automáticamente.

Espacios rompibles

Normalmente, los espacios en la plantilla misma (a diferencia de los valores de las variables interpoladas) no son rompibles, pero se pueden hacer rompibles en parte de la plantilla usando la palabra clave ~ (terminada con otra ~).

$~$Esta línea larga puede romperse si el documento se renderiza
con una longitud de línea corta.$~$

Pipes

Un pipe transforma el valor de una variable o parcial. Los pipes se especifican usando una barra (/) entre el nombre de la variable (o parcial) y el nombre del pipe. Ejemplo:

$for(name)$
$name/uppercase$
$endfor$
$for(metadata/pairs)$
- $it.key$: $it.value$
$endfor$
$employee:name()/uppercase$

Los pipes se pueden encadenar:

$for(employees/pairs)$
$it.key/alpha/uppercase$. $it.name$
$endfor$

Algunos pipes toman parámetros:

|----------------------|------------|
$for(employee)$
$it.name.first/uppercase/left 20 "| "$$it.name.salary/right 10 " | " " |"$
$endfor$
|----------------------|------------|

Actualmente los siguientes pipes están predefinidos:

•
pairs: Convierte un mapa o una matriz en una matriz de mapas, cada uno con campos key y value. Si el valor original era una matriz, la key será el índice de la matriz, comenzando en 1.
•
uppercase: Convierte texto a mayúsculas.
•
lowercase: Convierte texto a minúsculas.
•
length: Devuelve la longitud del valor: número de caracteres para un valor textual, número de elementos para un mapa o una matriz.
•
reverse: Invierte un valor textual o una matriz, y no tiene efecto en otros valores.
•
first: Devuelve el primer valor de una matriz, si se aplica a una matriz no vacía; de lo contrario, devuelve el valor original.
•
last: Devuelve el último valor de una matriz, si se aplica a una matriz no vacía; de lo contrario, devuelve el valor original.
•
rest: Devuelve todos los elementos excepto el primero de una matriz, si se aplica a una matriz no vacía; de lo contrario, devuelve el valor original.
•
allbutlast: Devuelve todos los elementos excepto el último de una matriz, si se aplica a una matriz no vacía; de lo contrario, devuelve el valor original.
•
chomp: Elimina las nuevas líneas finales (y los espacios rompibles).
•
nowrap: Deshabilita el ajuste de línea en espacios rompibles.
•
alpha: Convierte valores textuales que se pueden leer como un entero en caracteres alfabéticos minúsculos a..z (módulo 26). Esto se puede usar para obtener enumeraciones con letras a partir de índices de matriz. Para obtener letras mayúsculas, encadene con uppercase.
•
roman: Convierte valores textuales que se pueden leer como un entero en números romanos minúsculos. Esto se puede usar para obtener enumeraciones con letras a partir de índices de matriz. Para obtener números romanos mayúsculos, encadene con uppercase.
•
left n "leftborder" "rightborder": Renderiza un valor textual en un bloque de ancho n, alineado a la izquierda, con un borde izquierdo y derecho opcional. No tiene efecto en otros valores. Esto se puede usar para alinear material en tablas. Los anchos son enteros positivos que indican el número de caracteres. Los bordes son cadenas entre comillas dobles; los caracteres literales " y \ deben escaparse con barra invertida.
•
right n "leftborder" "rightborder": Renderiza un valor textual en un bloque de ancho n, alineado a la derecha, y no tiene efecto en otros valores.
•
center n "leftborder" "rightborder": Renderiza un valor textual en un bloque de ancho n, alineado al centro, y no tiene efecto en otros valores.

EXTENSIONES

El comportamiento de algunos de los lectores y escritores puede ajustarse habilitando o deshabilitando varias extensiones.

Una extensión puede habilitarse añadiendo +EXTENSION al nombre del formato y deshabilitarse añadiendo -EXTENSION. Por ejemplo, --from markdown_strict+footnotes es Markdown estricto con notas a pie de página habilitadas, mientras que --from markdown-footnotes-pipe_tables es Markdown de pandoc sin notas a pie de página o tablas de tubería.

El lector y escritor de Markdown son los que más utilizan extensiones. Las extensiones que solo se utilizan en ellos se cubren, por lo tanto, en la sección Markdown de Pandoc a continuación (véase las variantes de Markdown para commonmark y gfm). En lo siguiente, se cubren las extensiones que también funcionan para otros formatos.

Tenga en cuenta que las extensiones de Markdown añadidas al formato ipynb afectan a las celdas de Markdown en los cuadernos Jupyter (al igual que las opciones de línea de comandos como --markdown-headings).

Tipografía

Extensión: smart

Interpreta las comillas rectas como comillas curvas, --- como guiones largos, -- como guiones medios, y ... como elipses. Se insertan espacios de no separación después de ciertas abreviaturas, como "Sr.".

Esta extensión se puede habilitar/deshabilitar para los siguientes formatos:

formatos de entrada
markdown, commonmark, latex, mediawiki, org, rst, twiki, html
formatos de salida
markdown, latex, context, rst
habilitada por defecto en
markdown, latex, context (entrada y salida)

Nota: Si estás *escribiendo* Markdown, la extensión smart tiene el efecto inverso: lo que serían comillas curvas se muestra como rectas.

En LaTeX, smart significa usar las ligaduras estándar de TeX para las comillas (`` y '' para comillas dobles, ` y ' para comillas simples) y los guiones (-- para guion medio y --- para guion largo). Si smart está deshabilitada, entonces al leer LaTeX, pandoc analizará estos caracteres literalmente. Al escribir LaTeX, habilitar smart le dice a pandoc que use las ligaduras cuando sea posible; si smart está deshabilitada, pandoc usará caracteres de comillas y guiones unicode.

Títulos y secciones

Extensión: auto_identifiers

Un encabezado sin un identificador especificado explícitamente recibirá automáticamente un identificador único basado en el texto del encabezado.

Esta extensión se puede habilitar/deshabilitar para los siguientes formatos:

formatos de entrada
markdown, latex, rst, mediawiki, textile
formatos de salida
markdown, muse
habilitada por defecto en
markdown, muse

El algoritmo por defecto utilizado para derivar el identificador del texto del encabezado es:

•
Eliminar todo formato, enlaces, etc.
•
Eliminar todas las notas a pie de página.
•
Eliminar todos los caracteres no alfanuméricos, excepto guiones bajos, guiones y puntos.
•
Reemplazar todos los espacios y saltos de línea con guiones.
•
Convertir todos los caracteres alfabéticos a minúsculas.
•
Eliminar todo hasta la primera letra (los identificadores no pueden empezar por un número o signo de puntuación).
•
Si no queda nada después de esto, usa el identificador section.

Por lo tanto, por ejemplo,

  Encabezado                       Identificador
  ----------------------------- -----------------------------
  Encabezados en HTML           heading-identifiers-in-html
  Maître d'hôtel                maître-dhôtel
  *Perros*?--en *mi* casa?       dogs--in-my-house
  [HTML], [S5], o [RTF]?       html-s5-or-rtf
  3. Aplicaciones               applications
  33                            section

Estas reglas, en la mayoría de los casos, deberían permitir determinar el identificador a partir del texto del encabezado. La excepción es cuando varios encabezados tienen el mismo texto; en este caso, el primero recibirá un identificador como se describe anteriormente; el segundo recibirá el mismo identificador con -1 añadido; el tercero con -2; y así sucesivamente.

(Sin embargo, se utiliza un algoritmo diferente si gfm_auto_identifiers está habilitado; véase más abajo.)

Enlaces

En Markdown, los enlaces se pueden crear de dos maneras:

Enlaces de referencia

Los enlaces de referencia constan de dos partes: la parte de la etiqueta (el texto del enlace) y la parte de la definición del enlace. La etiqueta está encerrada entre corchetes. El texto y la definición de la etiqueta están separados por dos puntos y luego, opcionalmente, un espacio o varios espacios o una nueva línea. La definición del enlace consta de un identificador de enlace entre corchetes, seguido de dos puntos y luego la URL. La URL puede ir encerrada opcionalmente entre corchetes o paréntesis. Si los corchetes o paréntesis se utilizan, pueden contener espacios en blanco que se ignoran.

[texto del enlace][identificador]

[identificador]: url "título opcional"
[identificador]:  "título opcional"
[identificador]: url "título opcional"

El identificador de enlace puede contener letras, números, espacios y puntuación. Los identificadores de enlace no distinguen entre mayúsculas y minúsculas. El título, si se proporciona, se mostrará como información sobre la herramienta cuando el usuario pase el cursor sobre el enlace. Los identificadores de enlace son opcionales; si se omiten, se utiliza el texto del enlace.

[Google]

[Google]: http://www.google.com/

Los enlaces de referencia se pueden definir en cualquier lugar del documento. A menudo se agrupan al final del documento o cerca de donde se usan.

Si necesitas hacer referencia a un fragmento de encabezado en un documento HTML, puedes usar los identificadores de encabezado de Markdown. Por ejemplo, si tu documento HTML tiene:

<h1 id="heading-identifiers-in-html">Heading Identifiers in HTML</h1>

Puedes enlazar a él así:

[Heading identifiers in HTML](#heading-identifiers-in-html)

en lugar de dar explícitamente el identificador:

[Heading identifiers in HTML](#heading-identifiers-in-html)

Si hay varios encabezados con texto idéntico, la referencia correspondiente enlazará solo al primero, y necesitarás usar enlaces explícitos para enlazar a los demás, como se describe anteriormente.

Al igual que los enlaces de referencia normales, estas referencias no distinguen entre mayúsculas y minúsculas.

Las definiciones de referencia de enlaces explícitos siempre tienen prioridad sobre las referencias de encabezado implícitas. Por lo tanto, en el siguiente ejemplo, el enlace apuntará a bar, no a #foo:

# Foo
[foo]: bar
See [foo]

Citas en bloque

Markdown utiliza convenciones de correo electrónico para citar bloques de texto. Una cita en bloque es uno o más párrafos u otros elementos de bloque (como listas o encabezados), con cada línea precedida por un carácter > y un espacio opcional. (El > no necesita empezar en el margen izquierdo, pero no debe estar indentado más de tres espacios).

> Esto es una cita en bloque. Este
> párrafo tiene dos líneas.
>
> 1. Esta es una lista dentro de una cita en bloque.
> 2. Segundo elemento.

También se permite una forma "perezosa", que requiere el carácter > solo en la primera línea de cada bloque:

> Esto es una cita en bloque. Este
párrafo tiene dos líneas.
> 1. Esta es una lista dentro de una cita en bloque.
2. Segundo elemento.

Entre los elementos de bloque que pueden contenerse en una cita en bloque se encuentran otras citas en bloque. Es decir, las citas en bloque pueden anidarse:

> Esto es una cita en bloque.
>
> > Una cita en bloque dentro de una cita en bloque.

Si el carácter > va seguido de un espacio opcional, ese espacio se considerará parte del marcador de cita en bloque y no parte de la indentación del contenido. Por lo tanto, para colocar un bloque de código indentado en una cita en bloque, necesitas cinco espacios después del >:

>     código

Extensión: blank_before_blockquote

La sintaxis original de Markdown no requiere una línea en blanco antes de una cita en bloque. Pandoc sí requiere esto (excepto, por supuesto, al principio del documento). La razón del requisito es que es demasiado fácil que un > termine al principio de una línea por accidente (quizás por ajuste de línea). Por lo tanto, a menos que se utilice el formato markdown_strict, lo siguiente no produce una cita en bloque anidada en pandoc:

> This is a block quote.
>> Not nested, since `blank_before_blockquote` is enabled by default

Bloques de verbatim (código)

Bloques de código indentados

Un bloque de texto indentado cuatro espacios (o una tabulación) se trata como texto verbatim: es decir, los caracteres especiales no activan un formato especial, y todos los espacios y saltos de línea se conservan. Por ejemplo,

    if (a > 3) {
      moveShip(5 * gravity, DOWN);
    }

La indentación inicial (cuatro espacios o una tabulación) no se considera parte del texto verbatim y se elimina en la salida.

Nota: las líneas en blanco en el texto verbatim no necesitan empezar con cuatro espacios.

Bloques de código cercados

Extensión: fenced_code_blocks

Además de los bloques de código indentados estándar, pandoc admite bloques de código cercados. Estos comienzan con una fila de tres o más tildes (~) y terminan con una fila de tildes que debe ser al menos tan larga como la fila de inicio. Todo lo que quede entre estas líneas se trata como código. No se necesita indentación:

~~~~~~~
if (a > 3) {
  moveShip(5 * gravity, DOWN);
}
~~~~~~~

Al igual que los bloques de código normales, los bloques de código cercados deben separarse del texto circundante mediante líneas en blanco.

Si el código en sí contiene una fila de tildes o comillas invertidas, simplemente use una fila más larga de tildes o comillas invertidas al principio y al final:

~~~~~~~~~~~~~~~~
~~~~~~~~~~
código que incluye tildes
~~~~~~~~~~
~~~~~~~~~~~~~~~~

Extensión: backtick_code_blocks

Igual que fenced_code_blocks, pero usa comillas invertidas (`) en lugar de tildes (~).

Extensión: fenced_code_attributes

Opcionalmente, puedes adjuntar atributos a los bloques de código cercados o de comillas invertidas usando esta sintaxis:

~~~~ {#mycode .haskell .numberLines startFrom="100"}
qsort []     = []
qsort (x:xs) = qsort (filter (< x) xs) ++ [x] ++
               qsort (filter (>= x) xs)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Aquí mycode es un identificador, haskell y numberLines son clases, y startFrom es un atributo con valor 100. Algunos formatos de salida pueden usar esta información para realizar resaltado de sintaxis. Actualmente, los únicos formatos de salida que utilizan esta información son HTML, LaTeX, Docx, Ms y PowerPoint. Si el resaltado es compatible con tu formato de salida e idioma, entonces el bloque de código anterior aparecerá resaltado, con líneas numeradas. (Para ver qué idiomas son compatibles, escribe pandoc --list-highlight-languages.) De lo contrario, el bloque de código anterior aparecerá como sigue:

<pre id="mycode" class="haskell numberLines" startFrom="100">
  <code>
  ...
  </code>
</pre>

La clase numberLines (o number-lines) hará que las líneas del bloque de código se numeren, comenzando con 1 o el valor del atributo startFrom. La clase lineAnchors (o line-anchors) hará que las líneas sean anclajes hacibles clicables en la salida HTML.

También se puede utilizar una forma abreviada para especificar el idioma del bloque de código:

```haskell
qsort [] = []
```

Esto es equivalente a:

``` {.haskell}
qsort [] = []
```

Esta forma abreviada se puede combinar con atributos:

```haskell {.numberLines}
qsort [] = []
```

Que es equivalente a:

``` {.haskell .numberLines}
qsort [] = []
```

Si la extensión fenced_code_attributes está deshabilitada, pero la entrada contiene atributos de clase para el bloque de código, el primer atributo de clase se imprimirá después de la cerca de apertura como una palabra desnuda.

Para evitar todo el resaltado, utiliza la opción --no-highlight. Para establecer el estilo de resaltado, utiliza --highlight-style. Para más información sobre el resaltado, véase Resaltado de sintaxis, más abajo.

Bloques de líneas

Extensión: line_blocks

Un bloque de líneas es una secuencia de líneas que comienzan con una barra vertical (|) seguida de un espacio. La división en líneas se conservará en la salida, al igual que cualquier espacio inicial; de lo contrario, las líneas se formatearán como Markdown. Esto es útil para versos y direcciones:

| The limerick packs laughs anatomical
| In space that is quite economical.
|    But the good ones I've seen
|    So seldom are clean
| And the clean ones so seldom are comical
| 200 Main St.
| Berkeley, CA 94718

Las líneas pueden ajustarse si es necesario, pero la línea de continuación debe comenzar con un espacio.

| The Right Honorable Most Venerable and Righteous Samuel L.
  Constable, Jr.
| 200 Main St.
| Berkeley, CA 94718

Se permiten formatos en línea (como énfasis) en el contenido (aunque no pueden cruzar los límites de las líneas). No se reconocen formatos a nivel de bloque (como citas en bloque o listas).

Listas

Listas de viñetas

Una lista de viñetas es una lista de elementos de lista con viñetas. Un elemento de lista de viñetas comienza con una viñeta (*, + o -). Aquí hay un ejemplo simple:

* uno
* dos
* tres

Esto producirá una lista "compacta". Si deseas una lista "suelta", en la que cada elemento se formatee como un párrafo, deja espacios entre los elementos:

* uno
* dos
* tres

Las viñetas no necesitan estar alineadas con el margen izquierdo; pueden estar indentadas uno, dos o tres espacios. La viñeta debe ir seguida de un espacio en blanco.

Los elementos de lista quedan mejor si las líneas subsiguientes están alineadas con la primera línea (después de la viñeta):

* aquí está mi primer
  elemento de lista.
* y mi segundo.

Pero Markdown también permite un formato "perezoso":

* aquí está mi primer
elemento de lista.
* y mi segundo.

Contenido de bloque en elementos de lista

Extensión: lists_without_trailing_blank_line

En la sintaxis de Markdown original, se requiere una línea en blanco al final de un bloque de código o cita para que se considere parte del elemento de lista anterior. La extensión lists_without_trailing_blank_line elimina este requisito.

Listas ordenadas

Una lista ordenada es una lista de elementos de lista numerados. Un elemento de lista numerado comienza con un número seguido de un punto y un espacio. Aquí hay un ejemplo simple:

1. uno
2. dos
3. tres

Esto producirá una lista numerada. Los números de los elementos no tienen que estar en orden correcto; Markdown los reordenará por ti.

1. uno
3. dos
2. tres

Esto producirá:

1. uno
2. dos
3. tres

Al igual que con las listas de viñetas, las listas ordenadas pueden ser compactas o sueltas, y los elementos pueden indentarse.

1. uno
2. dos

3. tres

Producirá una lista suelta:

1. uno
2. dos

3. tres

Y la indentación y el formato "perezoso" funcionan igual que con las listas de viñetas.

  1. uno
      2. dos

Para una lista ordenada que comienza en un número distinto de 1, simplemente comienza el primer elemento con ese número:

3. tres
4. cuatro

Esto producirá:

3. tres
4. cuatro

Listas de definiciones

Extensión: definition_lists

Una lista de definiciones consta de términos de definición y cuerpos de definición. Un término de definición va seguido de dos puntos y un espacio, y luego el cuerpo de la definición. El término y el cuerpo de la definición pueden abarcar varias líneas, siempre que las líneas subsiguientes estén indentadas con respecto a la primera. Se pueden definir varios términos para la misma definición, y se pueden definir varios cuerpos para el mismo término. Por ejemplo:

Markdown
:   A lightweight markup language with plain-text formatting syntax.

term
:   This is a definition.
    This is the second line of the definition.

another term
:   This is another definition.

Los términos pueden indentarse hasta tres espacios. El cuerpo de la definición debe comenzar en la línea siguiente o en la misma línea, y debe estar indentado cuatro espacios o una tabulación. Si el cuerpo de la definición abarca varias líneas, las líneas subsiguientes deben estar indentadas al menos cuatro espacios.

Un término puede ser indentado más que el cuerpo de la definición:

   Term 1
      : Definition A
   Term 2
      : Definition B

Se permite un formato perezoso:

Markdown
:   A lightweight markup language with plain-text formatting syntax.

    This is the second paragraph of the definition.

Los elementos de lista de definiciones pueden contener bloques de otros elementos (incluidas otras listas de definiciones), siempre que estén indentados adecuadamente.

Term
:   This is a definition.

    Here is a list in the definition:
    * Item 1
    * Item 2

Tablas

Extensión: table

Pandoc admite tablas en el estilo de GitHub Flavored Markdown. Una tabla se define mediante líneas verticales y guiones. La primera línea define la cabecera de la tabla. Las líneas siguientes definen las filas. Las columnas se separan mediante líneas verticales.

| Header 1 | Header 2 |
|----------|----------|
| Row 1, Col 1 | Row 1, Col 2 |
| Row 2, Col 1 | Row 2, Col 2 |

La línea que separa la cabecera del cuerpo de la tabla debe contener al menos tres guiones por columna. Las líneas verticales alrededor de la tabla son opcionales.

La alineación de las columnas se puede especificar añadiendo dos puntos a la línea de separación. Dos puntos a la izquierda de los guiones alinean a la izquierda, dos puntos a la derecha alinean a la derecha, y dos puntos en ambos lados centran el texto.

| Left-aligned | Center-aligned | Right-aligned |
|:-------------|:--------------:|--------------:|
| ten          | ten            |          ten |
| eleven       | eleven         |        eleven |
| twelve       | twelve         |        twelve |

Las celdas de la tabla pueden contener formato Markdown (énfasis, etc.), pero no elementos de bloque como citas o listas.

Si la extensión fenced_code_attributes está habilitada, se pueden usar atributos de tabla para añadir un ID y clases a la tabla:

{#my-table .table}

Por ejemplo:

{#my-table .table}
| Header 1 | Header 2 |
|----------|----------|
| Row 1, Col 1 | Row 1, Col 2 |

Esto generará el siguiente HTML:

<table id="my-table" class="table">
  <thead>
    <tr>
      <th>Header 1</th>
      <th>Header 2</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Row 1, Col 1</td>
      <td>Row 1, Col 2</td>
    </tr>
  </tbody>
</table>

Cursiva y negrita

Para crear texto en cursiva, envuélvelo con un asterisco o un guion bajo. Para crear texto en negrita, envuélvelo con dos asteriscos o dos guiones bajos.

*cursiva*
_cursiva_
**negrita**
__negrita__

El texto en cursiva y negrita puede combinarse:

**_negrita y cursiva_**

Los asteriscos o guiones bajos usados para el formato de énfasis o fuerte deben ser los mismos (es decir, todos asteriscos o todos guiones bajos).

Si necesitas un asterisco o guion bajo literal, colócalo precedido por una barra invertida.

\*esto no es cursiva\*
\_esto no es cursiva\_
\*\*esto no es negrita\*\*
\_\_esto no es negrita\_\_

Los caracteres de énfasis o fuerte no deben ir precedidos ni seguidos de un espacio. Si lo hacen, se tratarán como literales.

* no cursiva *
** no negrita **

Markdown también admite la negrita y la cursiva intercaladas, usando la sintaxis de Markdown dentro de otra sintaxis de Markdown:

***negrita y cursiva***
**_negrita y cursiva_**

Para usar un asterisco o guion bajo literal que sea parte de una palabra (por ejemplo, en un nombre de archivo o variable), puedes usar la sintaxis de código, o simplemente precederlo con una barra invertida.

Matemáticas

Extensión: tex_math_dollars

El soporte para expresiones matemáticas en línea y de bloque se proporciona mediante la extensión tex_math_dollars.

Las expresiones matemáticas en línea se delimitan con signos de dólar ($). Las expresiones matemáticas de bloque se delimitan con dobles signos de dólar ($$).

La fórmula $ax^2 + bx + c = 0$ es una ecuación cuadrática.

$$
\int_0^\infty e^{-x^2} dx = \frac{\sqrt{\pi}}{2}
$$

Si necesitas un signo de dólar literal, puedes precederlo con una barra invertida.

Nota: Si el signo de dólar aparece al principio de una línea o va seguido de un espacio, se asumirá que es un literal, a menos que el signo de dólar esté precedido por otro signo de dólar (para expresiones de bloque). Por ejemplo, $ no se interpretará como un signo de dólar matemático. Para evitar la delimitación de los signos de dólar que deberían interpretarse como matemáticas, colócalos inmediatamente después de una palabra o un signo de puntuación.

Es posible que necesites usar la extensión dollar_math en lugar de tex_math_dollars si tu texto contiene muchos signos de dólar literales. Ver la documentación de Pandoc para más detalles.

Etiquetas HTML

Markdown permite insertar bloques de HTML intercalado directamente en el documento. Esto es útil para usar elementos HTML que no están cubiertos por la sintaxis de Markdown.

<p>Este es un párrafo.</p>
<div class="example">
  <p>Este es un div.</p>
</div>

Las etiquetas HTML deben estar separadas del texto circundante por líneas en blanco. Las etiquetas HTML no se escapan. Por ejemplo, si incluyes una etiqueta <script>, el navegador la ejecutará.

Las etiquetas HTML no se procesan si el formato de salida es LaTeX, excepto por las etiquetas span y div con atributos class o id.

Para obtener una lista completa de las etiquetas HTML que se admiten en los documentos de Markdown, consulta la especificación de Markdown.

HTML crudo en bloques de código

Extension: raw_html

Si la extensión raw_html está habilitada (lo que es por defecto), el contenido de los bloques de código cercados se puede marcar para que se procese como HTML crudo en la salida de HTML. Se utiliza la siguiente sintaxis:

```html

Este es un párrafo.

```

Esto es equivalente a escribir directamente el HTML:

<p>Este es un párrafo.</p>

La extensión raw_html también permite especificar la salida de HTML crudo para otros formatos de salida:

```{=html}
<p>Este es un párrafo.</p>
```

```{=latex}
\textit{Este es un párrafo.}
```

Esto permite incrustar código específico del formato de salida dentro de un documento Markdown.

Enlaces automáticos a URLs

Cualquier URL que aparezca en el texto que no esté dentro de un enlace de referencia o un enlace explícito se convertirá automáticamente en un enlace.

Visita http://www.google.com/.

Esto producirá:

<a href="http://www.google.com/">http://www.google.com/</a>

Los enlaces de correo electrónico también se crearán automáticamente.

envíame un correo a user@example.com

Esto producirá:

<a href="mailto:user@example.com">user@example.com</a>

Escapar caracteres de Markdown

Si necesitas usar caracteres que tienen un significado especial en Markdown (por ejemplo, *, `_`, `[`, `]`, `(`, `)`, etc.) como literales, puedes precederlos con una barra invertida (\).

Aquí hay un asterisco literal: \*

La barra invertida también se puede usar para escapar de otros caracteres que normalmente no tendrían un significado especial en Markdown, pero que aún así quieres asegurarte de que se traten como literales.

Saltos de línea forzados

En Markdown, un salto de línea en el texto fuente se ignora a menos que esté precedido por dos o más espacios o esté dentro de un bloque de código o cita. Para forzar un salto de línea, puedes añadir dos o más espacios al final de la línea.

Esta es la primera línea.  
Esta es la segunda línea.

Esto producirá un salto de línea en la salida:

Esta es la primera línea.<br />
Esta es la segunda línea.

Espacios finales

Los espacios al final de una línea se eliminan por defecto. Para conservarlos, debes usar la extensión space_headers (para encabezados) o la extensión hard_line_breaks (para todos los saltos de línea).

Espacios de no separación

Para insertar un espacio de no separación, usa la entidad HTML &nbsp;.

Puntuación final

A veces, la puntuación al final de un enlace puede ser problemática. Por ejemplo, si quieres enlazar a la página de Wikipedia sobre el término "markdown", escribirías:

[Wikipedia](http://en.wikipedia.org/wiki/Markdown).

El punto al final se incluirá en la URL, lo que la romperá.

Una solución es usar la sintaxis de enlace de referencia:

[Wikipedia][wiki].
[wiki]: http://en.wikipedia.org/wiki/Markdown

Otra solución es usar la sintaxis de corchetes para la URL:

[Wikipedia](http://en.wikipedia.org/wiki/Markdown).

O simplemente eliminar el punto al final del enlace en el Markdown.

Caracteres especiales

Algunos caracteres tienen un significado especial en Markdown y deben escaparse con una barra invertida si se quieren usar literalmente. Estos caracteres son:

\` * _ { } [ ] ( ) # + - . !

Por ejemplo, para obtener un asterisco literal, usa \*.

Extensión: smart

La extensión smart convierte las comillas rectas (", ') en comillas curvas tipográficamente correctas (comillas inteligentes), y convierte los guiones rectos (--, ---) en guiones em y en (–, —) respectivamente.

"A la derecha," dijo él, "vamos -- por el camino largo."

Cursiva y negrita

Para crear texto en cursiva, envuélvelo con un asterisco o un guion bajo. Para crear texto en negrita, envuélvelo con dos asteriscos o dos guiones bajos.

*cursiva*
_cursiva_
**negrita**
__negrita__

El texto en cursiva y negrita puede combinarse:

**_negrita y cursiva_**

Los asteriscos o guiones bajos usados para el formato de énfasis o fuerte deben ser los mismos (es decir, todos asteriscos o todos guiones bajos).

Si necesitas un asterisco o guion bajo literal, colócalo precedido por una barra invertida.

\*esto no es cursiva\*
\_esto no es cursiva\_
\*\*esto no es negrita\*\*
\_\_esto no es negrita\_\_

Los caracteres de énfasis o fuerte no deben ir precedidos ni seguidos de un espacio. Si lo hacen, se tratarán como literales.

* no cursiva *
** no negrita **

Markdown también admite la negrita y la cursiva intercaladas, usando la sintaxis de Markdown dentro de otra sintaxis de Markdown:

***negrita y cursiva***
**_negrita y cursiva_**

Para usar un asterisco o guion bajo literal que sea parte de una palabra (por ejemplo, en un nombre de archivo o variable), puedes usar la sintaxis de código, o simplemente precederlo con una barra invertida.

Matemáticas

Extensión: tex_math_dollars

El soporte para expresiones matemáticas en línea y de bloque se proporciona mediante la extensión tex_math_dollars.

Las expresiones matemáticas en línea se delimitan con signos de dólar ($). Las expresiones matemáticas de bloque se delimitan con dobles signos de dólar ($$).

La fórmula $ax^2 + bx + c = 0$ es una ecuación cuadrática.

$$
\int_0^\infty e^{-x^2} dx = \frac{\sqrt{\pi}}{2}
$$

Si necesitas un signo de dólar literal, puedes precederlo con una barra invertida.

Nota: Si el signo de dólar aparece al principio de una línea o va seguido de un espacio, se asumirá que es un literal, a menos que el signo de dólar esté precedido por otro signo de dólar (para expresiones de bloque). Por ejemplo, $ no se interpretará como un signo de dólar matemático. Para evitar la delimitación de los signos de dólar que deberían interpretarse como matemáticas, colócalos inmediatamente después de una palabra o un signo de puntuación.

Es posible que necesites usar la extensión dollar_math en lugar de tex_math_dollars si tu texto contiene muchos signos de dólar literales. Ver la documentación de Pandoc para más detalles.

Etiquetas HTML

Markdown permite insertar bloques de HTML intercalado directamente en el documento. Esto es útil para usar elementos HTML que no están cubiertos por la sintaxis de Markdown.

<p>Este es un párrafo.</p>
<div class="example">
  <p>Este es un div.</p>
</div>

Las etiquetas HTML deben estar separadas del texto circundante por líneas en blanco. Las etiquetas HTML no se escapan. Por ejemplo, si incluyes una etiqueta <script>, el navegador la ejecutará.

Las etiquetas HTML no se procesan si el formato de salida es LaTeX, excepto por las etiquetas span y div con atributos class o id.

Para obtener una lista completa de las etiquetas HTML que se admiten en los documentos de Markdown, consulta la especificación de Markdown.

HTML crudo en bloques de código

Extensión: raw_html

Si la extensión raw_html está habilitada (lo que es por defecto), el contenido de los bloques de código cercados se puede marcar para que se procese como HTML crudo en la salida de HTML. Se utiliza la siguiente sintaxis:

```html
<p>Este es un párrafo.</p>
```

Esto es equivalente a escribir directamente el HTML:

<p>Este es un párrafo.</p>

La extensión raw_html también permite especificar la salida de HTML crudo para otros formatos de salida:

```{=html}
<p>Este es un párrafo.</p>
```

```{=latex}
\textit{Este es un párrafo.}
```

Esto permite incrustar código específico del formato de salida dentro de un documento Markdown.

Enlaces automáticos a URLs

Cualquier URL que aparezca en el texto que no esté dentro de un enlace de referencia o un enlace explícito se convertirá automáticamente en un enlace.

Visita http://www.google.com/.

Esto producirá:

<a href="http://www.google.com/">http://www.google.com/</a>

Los enlaces de correo electrónico también se crearán automáticamente.

envíame un correo a user@example.com

Esto producirá:

<a href="mailto:user@example.com">user@example.com</a>

Escapar caracteres de Markdown

Si necesitas usar caracteres que tienen un significado especial en Markdown (por ejemplo, *, `_`, `[`, `]`, `(`, `)`, etc.) como literales, puedes precederlos con una barra invertida (\).

Aquí hay un asterisco literal: \*

La barra invertida también se puede usar para escapar de otros caracteres que normalmente no tendrían un significado especial en Markdown, pero que aún así quieres asegurarte de que se traten como literales.

Saltos de línea forzados

En Markdown, un salto de línea en el texto fuente se ignora a menos que esté precedido por dos o más espacios o esté dentro de un bloque de código o cita. Para forzar un salto de línea, puedes añadir dos o más espacios al final de la línea.

Esta es la primera línea.  
Esta es la segunda línea.

Esto producirá un salto de línea en la salida:

Esta es la primera línea.<br />
Esta es la segunda línea.

Espacios finales

Los espacios al final de una línea se eliminan por defecto. Para conservarlos, debes usar la extensión space_headers (para encabezados) o la extensión hard_line_breaks (para todos los saltos de línea).

Espacios de no separación

Para insertar un espacio de no separación, usa la entidad HTML &nbsp;.

Puntuación final

A veces, la puntuación al final de un enlace puede ser problemática. Por ejemplo, si quieres enlazar a la página de Wikipedia sobre el término "markdown", escribirías:

[Wikipedia](http://en.wikipedia.org/wiki/Markdown).

El punto al final se incluirá en la URL, lo que la romperá.

Una solución es usar la sintaxis de enlace de referencia:

[Wikipedia][wiki].
[wiki]: http://en.wikipedia.org/wiki/Markdown

Otra solución es usar la sintaxis de corchetes para la URL:

[Wikipedia](http://en.wikipedia.org/wiki/Markdown).

O simplemente eliminar el punto al final del enlace en el Markdown.

Caracteres especiales

Algunos caracteres tienen un significado especial en Markdown y deben escaparse con una barra invertida si se quieren usar literalmente. Estos caracteres son:

\` * _ { } [ ] ( ) # + - . !

Por ejemplo, para obtener un asterisco literal, usa \*.

Emoji

Extensión: emoji

Pandoc admite el uso de abreviaturas de emoji de GitHub estilo `::`. Por ejemplo, `:smile:` se renderiza como una cara sonriente.

:smile: :laughing: :smiley:

Una lista de nombres de emoji válidos se puede encontrar en la documentación de Pandoc.

Comillas inteligentes

Extensión: smart

La extensión smart convierte las comillas rectas (", ') en comillas curvas tipográficamente correctas (comillas inteligentes), y convierte los guiones rectos (--, ---) en guiones em y en (–, —) respectivamente.

"A la derecha," dijo él, "vamos -- por el camino largo."

Producirá:

“A la derecha,” dijo él, “vamos – por el camino largo.”

Ten en cuenta que la extensión smart solo se aplica a las comillas y los guiones; otros caracteres tipográficos (como los puntos suspensivos) se manejan mediante el formato de salida.

Notas al pie

Extensión: footnotes

Las notas al pie se indican mediante un marcador de nota al pie, que consiste en un signo de intercalación (^) seguido de un identificador de nota al pie entre corchetes. El identificador puede ser un número o una cadena de texto.

Aquí hay algo de texto con una nota al pie.[^1]

[^1]: Y aquí está el contenido de la nota al pie.

También se pueden usar identificadores de texto:

Aquí hay algo de texto con una nota al pie.[^note]

[^note]: Y aquí está el contenido de la nota al pie.

Los marcadores de notas al pie se pueden colocar en cualquier lugar del documento, pero las definiciones de notas al pie deben colocarse al final del documento o, si se usa el formato Markdown, al final del párrafo al que se refieren.

Las notas al pie pueden contener elementos de bloque, como listas y citas.

Aquí hay algo de texto con una nota al pie.[^2]

[^2]: Aquí hay una nota al pie.
    Con dos párrafos.

    *   Un elemento de lista.
    *   Otro elemento de lista.

Si hay varias notas al pie con el mismo identificador, se fusionarán en una sola nota al pie.

Los marcadores de notas al pie en línea se pueden usar para notas al pie cortas, que se colocan inmediatamente después del texto de referencia.

Aquí hay algo de texto con una nota al pie.[^3]

[^3]: Y aquí está el contenido de la nota al pie.

Las notas al pie se renderizarán como un enlace desde el texto al contenido de la nota al pie, y un enlace de retorno desde el contenido de la nota al pie al texto de referencia.
