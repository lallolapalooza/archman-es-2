NOMBRE

pam_sss - módulo PAM para SSSD

SINOPSIS

pam_sss.so [quiet] [forward_pass] [use_first_pass] [use_authtok] [retry=N] [ignore_unknown_user] [ignore_authinfo_unavail] [domains=X] [allow_missing_name] [prompt_always] [try_cert_auth] [require_cert_auth] [allow_chauthtok_by_root]

DESCRIPCIÓN

pam_sss.so es la interfaz PAM para el demonio System Security Services (SSSD). Los errores y resultados se registran a través de syslog(3) con la instalación LOG_AUTHPRIV.

OPCIONES

quiet

Suprime los mensajes de registro para usuarios desconocidos.

forward_pass

Si se establece forward_pass, la contraseña introducida se pone en la pila para que otros módulos PAM la utilicen.

use_first_pass

El argumento use_first_pass obliga al módulo a usar la contraseña de un módulo apilado anterior y nunca solicitará al usuario. Si no hay contraseña disponible o la contraseña no es apropiada, se denegará el acceso al usuario.

use_authtok

Al cambiar la contraseña, obliga al módulo a establecer la nueva contraseña a la proporcionada por un módulo de contraseña apilado anterior.

retry=N

Si se especifica, se le pide al usuario otras N veces una contraseña si la autenticación falla. El valor predeterminado es 0.

Tenga en cuenta que esta opción podría no funcionar como se espera si la aplicación que llama a PAM maneja el diálogo del usuario por sí misma. Un ejemplo típico es sshd con PasswordAuthentication.

ignore_unknown_user

Si se especifica esta opción y el usuario no existe, el módulo PAM devolverá PAM_IGNORE. Esto hace que el framework PAM ignore este módulo.

ignore_authinfo_unavail

Especifica que el módulo PAM debe devolver PAM_IGNORE si no puede contactar con el demonio SSSD. Esto hace que el framework PAM ignore este módulo.

domains

Permite al administrador restringir los dominios contra los que un servicio PAM particular puede autenticarse. El formato es una lista separada por comas de nombres de dominio de SSSD, tal como se especifica en el archivo sssd.conf.

NOTA: Si se utiliza para un servicio que no se ejecuta como usuario root, por ejemplo, un servidor web, debe usarse junto con las opciones “pam_trusted_users” y “pam_public_domains”. Consulte la página del manual de sssd.conf(5) para obtener más información sobre estas dos opciones de respondedor PAM.

allow_missing_name

El propósito principal de esta opción es permitir que SSSD determine el nombre de usuario basándose en información adicional, por ejemplo, el certificado de una tarjeta inteligente.

El caso de uso actual son los gestores de inicio de sesión que pueden monitorizar un lector de tarjetas inteligentes para detectar eventos de tarjeta. En caso de que se inserte una tarjeta inteligente, el gestor de inicio de sesión llamará a una pila PAM que incluye una línea como

auth sufficient pam_sss.so allow_missing_name

En este caso, SSSD intentará determinar el nombre de usuario basándose en el contenido de la tarjeta inteligente, lo devolverá a pam_sss, que finalmente lo pondrá en la pila PAM.

prompt_always

Solicita siempre credenciales al usuario. Con esta opción, las credenciales solicitadas por otros módulos PAM, típicamente una contraseña, se ignoran y pam_sss volverá a solicitar credenciales. Basándose en la respuesta pre-autenticación de SSSD, pam_sss puede solicitar una contraseña, un PIN de tarjeta inteligente u otras credenciales.

try_cert_auth

Intenta utilizar la autenticación basada en certificados, es decir, la autenticación con una tarjeta inteligente o dispositivos similares. Si una tarjeta inteligente está disponible y el servicio está permitido para la autenticación con tarjeta inteligente, se le pedirá al usuario un PIN y continuará la autenticación basada en certificados.

Si no hay una tarjeta inteligente disponible o la autenticación basada en certificados no está permitida para el servicio actual, se devuelve PAM_AUTHINFO_UNAVAIL.

require_cert_auth

Realiza la autenticación basada en certificados, es decir, la autenticación con una tarjeta inteligente o dispositivos similares. Si no hay una tarjeta inteligente disponible, se pedirá al usuario que inserte una. SSSD esperará una tarjeta inteligente hasta que expire el tiempo de espera definido por p11_wait_for_card_timeout; consulte sssd.conf(5) para más detalles.

Si no hay una tarjeta inteligente disponible después del tiempo de espera o la autenticación basada en certificados no está permitida para el servicio actual, se devuelve PAM_AUTHINFO_UNAVAIL.

allow_chauthtok_by_root

Por defecto, la acción chauthtok de PAM se cortocircuita para devolver PAM_SUCCESS cuando pam_sss.so es invocado por el usuario root.

Esta opción deshabilita este comportamiento, permitiendo cambiar los tokens de autenticación cuando se ejecuta como root.

TIPOS DE MÓDULOS PROPORCIONADOS

Todos los tipos de módulos (account, auth, password y session) se proporcionan.

Si el respondedor PAM de SSSD no se está ejecutando, por ejemplo, si el socket del respondedor PAM no está disponible, pam_sss devolverá PAM_USER_UNKNOWN cuando se llame como módulo account para evitar problemas con usuarios de otras fuentes durante el control de acceso.

VALORES DE RETORNO

PAM_SUCCESS

La operación PAM se completó con éxito.

PAM_USER_UNKNOWN

El usuario no es conocido por el servicio de autenticación o el respondedor PAM de SSSD no se está ejecutando.

PAM_AUTH_ERR

Fallo de autenticación. También puede devolverse cuando hay un problema al obtener el certificado.

PAM_PERM_DENIED

Permiso denegado. Los archivos de registro de SSSD pueden contener información adicional sobre el error.

PAM_IGNORE

Consulte las opciones ignore_unknown_user y ignore_authinfo_unavail.

PAM_AUTHTOK_ERR

No se pudo obtener el nuevo token de autenticación. También puede devolverse cuando se utilizaron las opciones use_first_pass o use_authtok, pero no se encontró ninguna contraseña del módulo PAM apilado anterior.

PAM_AUTHINFO_UNAVAIL

No se pudo acceder a la información de autenticación. Esto podría deberse a un fallo de red o de hardware.

PAM_BUF_ERR

Se produjo un error de memoria. También puede devolverse cuando las opciones use_first_pass o use_authtok estaban establecidas, pero no se encontró ninguna contraseña del módulo PAM apilado anterior.

PAM_SYSTEM_ERR

Se produjo un error del sistema. Los archivos de registro de SSSD pueden contener información adicional sobre el error.

PAM_CRED_ERR

No se pudieron establecer las credenciales del usuario.

PAM_CRED_INSUFFICIENT

La aplicación no tiene credenciales suficientes para autenticar al usuario. Por ejemplo, falta el PIN durante la autenticación con tarjeta inteligente o falta un factor durante la autenticación de dos factores.

PAM_SERVICE_ERR

Error en el módulo de servicio.

PAM_NEW_AUTHTOK_REQD

El token de autenticación del usuario ha caducado.

PAM_ACCT_EXPIRED

La cuenta de usuario ha caducado.

PAM_SESSION_ERR

No se pudieron obtener las reglas del perfil de escritorio IPA o la información del usuario.

PAM_CRED_UNAVAIL

No se pudieron recuperar las credenciales de usuario de Kerberos.

PAM_NO_MODULE_DATA

Kerberos no encontró ningún método de autenticación. Esto podría ocurrir si el usuario tiene una tarjeta inteligente asignada pero el plugin pkint no está disponible en el cliente.

PAM_CONV_ERR

Fallo de conversación.

PAM_AUTHTOK_LOCK_BUSY

No hay ningún KDC adecuado para el cambio de contraseña disponible.

PAM_ABORT

Llamada PAM desconocida.

PAM_MODULE_UNKNOWN

Tarea o comando PAM no soportado.

PAM_BAD_ITEM

El módulo de autenticación no puede manejar credenciales de tarjeta inteligente.

ARCHIVOS

Si un restablecimiento de contraseña por parte de root falla, debido a que el proveedor SSSD correspondiente no admite restablecimientos de contraseña, se puede mostrar un mensaje individual. Este mensaje puede, por ejemplo, contener instrucciones sobre cómo restablecer una contraseña.

El mensaje se lee del archivo pam_sss_pw_reset_message.LOC donde LOC representa una cadena de localización devuelta por setlocale(3). Si no hay un archivo coincidente, se muestra el contenido de pam_sss_pw_reset_message.txt. Root debe ser el propietario de los archivos y solo root puede tener permisos de lectura y escritura, mientras que todos los demás usuarios solo deben tener permisos de lectura.

Estos archivos se buscan en el directorio /etc/sssd/customize/DOMAIN_NAME/. Si no hay un archivo coincidente, se muestra un mensaje genérico.
