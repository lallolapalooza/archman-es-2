PATHCHK(1P) Manual de Programador POSIX PATHCHK(1P)

PROLOG

Esta página del manual forma parte del Manual de Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pathchk — comprobar nombres de ruta

SINOPSIS

pathchk [-p] [-P] nombre_ruta...

DESCRIPCIÓN

La utilidad pathchk comprobará que uno o más nombres de ruta son válidos (es decir, que podrían usarse para acceder o crear un archivo sin causar errores de sintaxis) y portátiles (es decir, que no se produce ninguna truncación de nombre de archivo). Los -p y -P proporcionan comprobaciones de portabilidad más exhaustivas.

Por defecto, la utilidad pathchk comprobará cada componente de cada operando nombre_ruta basándose en el sistema de archivos subyacente. Se escribirá un diagnóstico por cada operando nombre_ruta que:

*
Supere en longitud a {PATH_MAX} bytes (consulte Valores de Variables de Nombres de Ruta en el volumen de Definiciones Base de POSIX.1‐2017, <limits.h>)
*
Contenga cualquier componente con una longitud superior a {NAME_MAX} bytes en su directorio contenedor
*
Contenga cualquier componente en un directorio que no sea accesible
*
Contenga cualquier secuencia de bytes que no sea válida en su directorio contenedor

El formato del mensaje de diagnóstico no está especificado, pero deberá indicar el error detectado y el operando nombre_ruta correspondiente.

No se considerará un error si uno o más componentes de un operando nombre_ruta no existen, siempre y cuando un archivo que coincida con el nombre de ruta especificado por los componentes faltantes pudiera crearse sin violar ninguna de las comprobaciones especificadas anteriormente.

OPCIONES

La utilidad pathchk cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidad.

Se admitirá la siguiente opción:

-p
En lugar de realizar comprobaciones basadas en el sistema de archivos subyacente, escribirá un diagnóstico por cada operando nombre_ruta que:
*
Supere en longitud a {_POSIX_PATH_MAX} bytes (consulte Valores Mínimos en el volumen de Definiciones Base de POSIX.1‐2017, <limits.h>)
*
Contenga cualquier componente con una longitud superior a {_POSIX_NAME_MAX} bytes
*
Contenga cualquier carácter en cualquier componente que no esté en el conjunto de caracteres de nombres de archivo portátiles
-P
Escribirá un diagnóstico por cada operando nombre_ruta que:
*
Contenga un componente cuyo primer carácter sea el carácter <guion-menos>
*
Esté vacío

OPERANDOS

Se admitirá el siguiente operando:

nombre_ruta
Un nombre de ruta a comprobar.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán a la ejecución de pathchk:

LANG
Proporcionará un valor predeterminado para las variables de internacionalización que no estén definidas o estén vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en una cadena de valor no vacía, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinará la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en los argumentos).
LC_MESSAGES

Determinará la localización que debería utilizarse para afectar al formato y contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determinará la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASINCRÓNICOS

Predeterminado.

SALIDA ESTÁNDAR

No se utiliza.

ERROR ESTÁNDAR

El error estándar se utilizará únicamente para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Todos los operandos nombre_ruta pasaron todas las comprobaciones.
>0
Ocurrió un error.

CONSECUENCIAS DE LOS ERRORES

Predeterminado.

USO DE APLICACIONES

La utilidad test se puede utilizar para determinar si un nombre de ruta dado nombra un archivo existente; sin embargo, no da ninguna indicación de si algún componente del nombre de ruta fue truncado en un directorio donde la característica _POSIX_NO_TRUNC no está en vigor. La utilidad pathchk no comprueba la existencia de archivos; realiza comprobaciones para determinar si un nombre de ruta existe o podría crearse sin ninguna truncación de componente del nombre de ruta.

La opción noclobber en el shell (consulte la instrucción especial set) se puede utilizar para crear un archivo de forma atómica. Al igual que con todas las semánticas de creación de archivos en el volumen de Interfaces del Sistema de POSIX.1‐2017, garantiza la creación atómica, pero aún depende de que las aplicaciones acuerden convenciones y cooperen en el uso de los archivos después de haber sido creados.

Para verificar que un nombre de ruta cumple los requisitos de portabilidad de nombres de archivo, las aplicaciones deben usar las opciones -p y -P juntas.

EJEMPLOS

Para verificar que todos los nombres de ruta en un archivo de intercambio de datos importado son legítimos y no ambiguos en el sistema actual:

# Este ejemplo asume que ningún nombre de ruta en el archivo
# contiene caracteres de <nueva línea>.
pax -f archivo | sed -e 's/[^[:alnum:]]/\\&/g' | xargs pathchk --
if [ $? -eq 0 ]
then
    pax -r -f archivo
else
    echo Investigue los problemas antes de importar archivos.
    exit 1
fi

Para verificar que todos los archivos en la jerarquía de directorios actual podrían moverse a cualquier sistema que cumpla con el volumen de Interfaces del Sistema de POSIX.1‐2017 y que también admita la utilidad pax:

find . -exec pathchk -p -P {} +
if [ $? -eq 0 ]
then
    pax -w -f ../archivo .
else
    echo No se puede crear el archivo portable.
    exit 1
fi

The pathchk utility was new for the\n ISO POSIX‐2:1993 standard. It, along with the set\n -C(noclobber) option added to the shell, replaces the\n mktemp, validfnam, and create utilities that appeared\n in early proposals. All of these utilities were attempts to solve several\n common problems:

\n
\n
*
\n
Verify the validity (for several different definitions of ``valid'') of a\n pathname supplied by a user, generated by an application, or imported from\n an external source.
\n
*
\n
Atomically create a file.
\n
*
\n
Perform various string handling functions to generate a temporary\n filename.
\n
\n

The create utility, included in an early proposal, provided\n checking and atomic creation in a single invocation of the utility; these\n are orthogonal issues and need not be grouped into a single utility. Note\n that the noclobber option also provides a way of creating a lock for\n process synchronization; since it provides an atomic create, there is\n no race between a test for existence and the following creation if it did\n not exist.

\n

Having a function like tmpnam() in the ISO C\n standard is important in many high-level languages. The shell programming\n language, however, has built-in string manipulation facilities, making it\n very easy to construct temporary filenames. The names needed obviously\n depend on the application, but are frequently of a form similar to:

\n
\n
$TMPDIR/application_abbreviation$$.suffix
\n
\n

In cases where there is likely to be contention for a given\n suffix, a simple shell for or while loop can be used with the\n shell noclobber option to create a file without risk of collisions, as\n long as applications trying to use the same filename name space are\n cooperating on the use of files after they have been created.

\n

For historical purposes, -p does not check for the use of\n the <hyphen-minus> character as the first character in a component of\n the pathname, or for an empty pathname operand.
