NOMBRE

pageant - Agente de autenticación SSH de PuTTY

SINOPSIS

pageant (-X | -T | --permanent | --debug | --foreground ) [ [ --encrypted ] archivo-clave... ]
pageant [ [ --encrypted ] archivo-clave... ] --exec comando [ args... ]
pageant -a [ --encrypted ] archivo-clave...
pageant (-d | -r | --public | --public-openssh ) identificador-clave...
pageant (-D | -R )
pageant -l [ --fptype formato ]
pageant --askpass prompt

DESCRIPCIÓN

pageant es tanto un agente de autenticación SSH como una herramienta para comunicarse con un agente ya en ejecución.

Al ejecutarse como un agente SSH, escucha en un socket de dominio Unix las conexiones de los procesos cliente que se ejecutan bajo tu ID de usuario. Los clientes pueden cargar claves privadas SSH en el agente o solicitar firmas sobre un mensaje dado de una clave ya en el agente. Esto permite la autenticación de un solo toque por parte de los programas cliente SSH, si Pageant contiene una clave que el servidor al que se conectan aceptará.

pageant también puede actuar como un programa cliente en sí mismo, comunicándose con un agente ya en ejecución para añadir o eliminar claves, listar las claves o extraer su mitad pública.

El protocolo de agente utilizado por pageant es compatible con las herramientas de PuTTY y también con otras implementaciones como el cliente SSH de OpenSSH y ssh-agent(1). Algunas funciones de pageant se implementan con extensiones del protocolo, por lo que solo funcionarán si pageant está en ambos extremos.

Para ejecutar pageant como agente, debes proporcionar una opción que le indique cuál debe ser su *duración*. Típicamente, probablemente querrás que Pageant dure durante la sesión de inicio de sesión, en cuyo caso debes usar -X o -T, dependiendo de si tu sesión de inicio de sesión es gráfica o puramente basada en terminal, respectivamente. Por ejemplo, en tu script de inicio de sesión de X podrías escribir:

eval $(pageant -X)

lo que hará que Pageant comience a ejecutarse, monitoree el servidor X para notar cuándo termina tu sesión (y entonces él también terminará), e imprima en la salida estándar algunos comandos de configuración de shell que los procesos cliente necesitarán para encontrar el agente en ejecución.

En un inicio de sesión basado en terminal, podrías hacer casi lo mismo pero con -T:

eval $(pageant -T)

Esto hará que Pageant vincule su duración a la de tu terminal de control, al notar cuándo deja de tener una terminal de control (lo que sucederá automáticamente como un efecto secundario de la terminación del proceso líder de la sesión). Al igual que con -X, Pageant imprimirá comandos de configuración de variables de entorno en la salida estándar.

En cualquiera de estos modos, también puedes añadir una o más claves privadas como argumentos adicionales de línea de comandos, por ejemplo:

eval $(pageant -T ~/.ssh/key.ppk)

en cuyo caso Pageant pedirá inmediatamente las contraseñas de las claves (si las hay) y comenzará el agente con esas claves ya cargadas en forma de texto plano. Las solicitudes de contraseña utilizarán la terminal de control si está disponible, o la GUI si esta última está disponible. (El método de solicitud se puede anular con las opciones --gui-prompt o --tty-prompt). Si ninguna de las dos está disponible, no se podrán realizar solicitudes de contraseña.

Alternativamente, puedes iniciar un agente con claves almacenadas en forma cifrada:

eval $(pageant -T --encrypted ~/.ssh/key.ppk)

En este caso, Pageant no pedirá una contraseña al inicio; en su lugar, la pedirá la primera vez que un cliente intente usar la clave. (Pageant necesitará acceso a una GUI para poder mostrar una solicitud de contraseña cuando sea necesario, a menos que se esté ejecutando en modo --debug).

Para usar Pageant para interactuar con un agente existente, puedes añadir nuevas claves usando -a, listar las huellas digitales y comentarios del conjunto actual de claves con -l, extraer la mitad pública completa de cualquier clave usando --public o --public-openssh, eliminar una clave específica o todas las claves usando -d o -D respectivamente, o solicitar el cifrado de una clave específica o de todas las claves usando -r o -R respectivamente.

DURACIÓN

Las siguientes opciones se denominan *modos de duración*. Todas solicitan a Pageant que opere en modo agente; cada una especifica un método diferente para que Pageant se inicie y sepa cuándo apagarse.

-X
Pageant abrirá una conexión a tu pantalla X, y cuando esa conexión se pierda, terminará. Esto le da la misma duración que tu sesión de inicio de sesión gráfica, por lo que en este modo es adecuado para ejecutarse desde un script de inicio como .xsession. El agente real será un subproceso; el proceso principal de Pageant terminará inmediatamente, después de imprimir comandos de configuración de variables de entorno en la salida estándar que deberían ser instalados en cualquier proceso que desee comunicarse con el agente.

El enfoque habitual sería ejecutar

eval $(pageant -X)

en un script de inicio de sesión X. Sin embargo, existen otras posibilidades, como redirigir la salida estándar de `pageant -X' a un archivo que luego es "sourced" por cualquier shell nuevo.

-T
Pageant vinculará su duración a la de la sesión de inicio de sesión que se ejecuta en su terminal de control, al notar cuándo deja de tener una terminal de control (lo que sucederá automáticamente como un efecto secundario de la terminación del proceso líder de la sesión). Al igual que -X, Pageant imprimirá comandos de configuración de variables de entorno en la salida estándar.
--exec comando
Pageant ejecutará el comando proporcionado como un subproceso, precargado con las variables de entorno apropiadas para acceder al agente que inicia. Cuando el subproceso termine, Pageant también terminará.

Todos los argumentos en la línea de comandos de Pageant después de --exec se tratarán como parte del comando a ejecutar, incluso si parecen otras opciones válidas de Pageant o archivos de claves.

--permanent
Pageant creará un subproceso para que sea el agente, e imprimirá comandos de configuración de variables de entorno en la salida estándar, como -X y -T. Sin embargo, en este caso, no hará ningún esfuerzo por limitar su duración de ninguna manera; simplemente se ejecutará permanentemente, a menos que se mate manualmente. La variable de entorno SSH_AGENT_PID, establecida por los comandos impresos por Pageant, permite que el proceso agente sea encontrado para este propósito.

Esta opción no se recomienda, ya que cualquier método para matar manualmente el agente conlleva el riesgo de que la sesión termine inesperadamente antes de que se logre.

--debug
Pageant se ejecutará en primer plano, sin crear un fork. Imprimirá sus comandos de configuración de variables de entorno en la salida estándar, y luego registrará toda la actividad del agente en la salida estándar también; las solicitudes de contraseña deberán responderse en la entrada estándar. Esto es útil para depurar lo que está haciendo el propio Pageant, o lo que le está haciendo otro proceso.
--foreground
Al igual que --debug, Pageant se ejecutará en primer plano, sin crear un fork. Imprimirá sus comandos de configuración de variables de entorno en la salida estándar. A diferencia de --debug, Pageant no registrará automáticamente la actividad del agente en la salida estándar, ni forzará las solicitudes de contraseña a la entrada estándar. Esto es útil si Pageant es generado por un proceso padre que controla o interactúa programáticamente con Pageant.

Después de que Pageant imprima sus comandos de configuración de entorno, cierra su salida estándar. Por lo tanto, si el proceso padre lo ha ejecutado en una tubería para recuperar los comandos de configuración de entorno, puede simplemente leer hasta recibir EOF, en lugar de tener que saber cuántas líneas de salida esperar.

OPCIONES DE CLIENTE

Las siguientes opciones indican a Pageant que opere en modo cliente, contactando a un agente existente a través de variables de entorno que ya debería tener configuradas.

-a archivos-clave
Carga el archivo(s) de clave privada especificado(s) y los añade al agente ya en ejecución. A menos que también se especifique --encrypted, pageant los descifrará si es necesario solicitando sus frases de contraseña (con la misma elección de interfaces de usuario que en modo agente).

Los archivos de clave privada deben estar en el formato de archivo .ppk de PuTTY.

-l
Lista las claves actualmente en el agente en ejecución. Se mostrará la huella digital y la cadena de comentario de cada clave. (Utiliza la opción -E para cambiar el formato de la huella digital).

Las claves que requerirán una frase de contraseña en su próximo uso se listan como `encrypted'. Las claves que pueden ser devueltas a este estado con -r se listan como `re-encryptable'.

--public identificadores-clave
Imprime la mitad pública de cada clave especificada, en el formato estándar RFC 4716 (múltiples líneas, comenzando con `---- BEGIN SSH2 PUBLIC KEY ----').

Cada identificador-clave puede ser cualquiera de los siguientes:

•
El nombre de un archivo que contiene la clave, ya sea la clave completa (nuevamente en formato .ppk) o solo su mitad pública.
•
La cadena de comentario de la clave, como se muestra con pageant -l.
•
Suficiente parte de uno de los formatos de huella digital de la clave para que sea único entre las claves cargadas actualmente en el agente.

Si Pageant puede identificar de forma única una clave interpretando el identificador-clave de alguna de estas maneras, asumirá que esa es la clave que pretendías. Si no puede, tendrás que especificar más detalles.

Si descubres que tu cadena identificador-clave deseada puede ser interpretada válidamente como más de uno de los tipos de identificación anteriores, puedes desambiguar prefijándola de la siguiente manera:

`file:'
para indicar que es un nombre de archivo
`comment:'
para indicar que es una cadena de comentario
`fp:'
para indicar que es una huella digital; cualquier formato de huella digital será coincidente
`sha256:' o `md5:'
para indicar que es una huella digital de un formato específico
`sha256-cert:' o `md5-cert:'
para indicar que es una huella digital de un formato específico, y que coincide específicamente con la huella digital de la clave pública incluyendo un certificado si lo hay
--public-openssh identificadores-clave, -L identificadores-clave
Imprime la mitad pública de cada clave especificada, en el formato de una sola línea utilizado por OpenSSH, adecuado para colocar en archivos .ssh/authorized_keys.
-d identificadores-clave
Elimina cada clave especificada de la memoria del agente, de modo que el agente ya no la servirá a los clientes a menos que se cargue de nuevo utilizando pageant -a.
-D
Elimina todas las claves de la memoria del agente, dejándolo completamente vacío.
-r identificadores-clave
``Vuelve a cifrar'' cada clave especificada en la memoria del agente; es decir, olvida cualquier versión en texto plano, de modo que se le pida al usuario una frase de contraseña la próxima vez que se utilice la clave. (Para que esto sea posible, la clave debe haber sido añadida previamente con la opción --encrypted).

(Almacenar claves cifradas es una extensión de Pageant, por lo que es poco probable que esta opción y -R funcionen con otros agentes).

-R
``Vuelve a cifrar'' todas las claves posibles en la memoria del agente. (Esto puede dejar algunas claves en texto plano, si no fueron añadidas previamente con la opción --encrypted).
--test-sign identificador-clave
--test-sign-with-flags=flags identificador-clave
Firma datos arbitrarios con la clave dada. Este modo solo es útil cuando se prueba pageant en sí mismo.

Los datos a firmar se toman de la entrada estándar, se firman por el agente con la clave identificada por identificador-clave, y la firma resultante se emite en la salida estándar (como un blob binario en el formato definido por las especificaciones SSH).

flags es un número que representa una combinación de bits de bandera definidos por el protocolo del agente SSH.

REEMPLAZO DE SSH-ASKPASS

--askpass prompt
Con esta opción, pageant actúa como un reemplazo de ssh-askpass(1), en lugar de realizar cualquier funcionalidad de agente SSH. Esto puede ser útil si prefieres el estilo de aviso de la GUI de Pageant, que minimiza la fuga de información sobre la longitud de tu frase de contraseña en su retroalimentación visual, en comparación con otras implementaciones de ssh-askpass(1).

pageant --askpass implementa la interfaz estándar ssh-askpass(1): se le puede pasar un aviso para mostrar (como un único argumento) y, si tiene éxito, imprime la frase de contraseña en la salida estándar y devuelve un estado de salida cero. Normalmente, utilizarías la variable de entorno SSH_ASKPASS para indicar a otros programas que utilicen pageant de esta manera.

OPCIONES

-v
Modo detallado. Cuando Pageant se ejecuta en modo agente, esta opción hace que registre toda la actividad del agente en su error estándar. Por ejemplo, podrías ejecutar
eval $(pageant -X -v 2>~/.pageant.log)

y esperar que se acumule en ese archivo de registro una lista de todas las firmas solicitadas por los clientes del agente.

La información del registro es la misma que la producida por la opción de ciclo de vida --debug, pero --debug la envía a la salida estándar (ya que ese es el objetivo principal del modo de depuración), mientras que -v en todos los demás modos de ciclo de vida envía los mismos datos de registro al error estándar (siendo un subproducto del propósito principal del programa). Usar -v en modo --debug no tiene efecto: el registro todavía va a la salida estándar.

-s, -c
Fuerza a Pageant a generar sus comandos de configuración de entorno en el estilo de los shells POSIX / Bourne (-s) o C shells (-c) respectivamente. Si no se da ninguna de las opciones, Pageant adivinará basándose en si la variable de entorno SHELL tiene un valor que termina en `csh'.
--symlink ruta-fija
Al operar en modo agente, además de crear un socket de escucha con nombre único, pageant también creará (o actualizará) un enlace simbólico en ruta-fija apuntando a ese socket.

Esto permite el acceso a una instancia de agente configurando la variable de entorno SSH_AUTH_SOCK a ruta-fija, en lugar de tener que usar el valor inventado por pageant cuando se inicia. Se espera que sea útil principalmente para la depuración.

--encrypted, --no-decrypt
Al añadir claves al agente (al inicio o más tarde), mantenlas en forma cifrada hasta el primer intento de usarlas; se le pedirá al usuario una frase de contraseña entonces. Una vez descifrada, una clave que se añadió de esta manera puede ser `cifrada de nuevo' con las opciones de cliente -r o -R.

La opción --encrypted no tiene ningún efecto para los archivos de clave que no tienen una frase de contraseña.

(Almacenar claves en forma cifrada es una extensión de Pageant; es poco probable que otras implementaciones de agentes la soporten).

-E tipo-huella, --fptype tipo-huella
Especifica el formato de huella digital a imprimir. Solo aplicable al listar huellas digitales con -l. Los formatos disponibles son sha256 (el predeterminado) y md5.
--gui-prompt, --tty-prompt
Fuerza a Pageant a solicitar las frases de contraseña de las claves con un método particular (GUI o terminal) en lugar de intentar adivinar el método más apropiado como se describe anteriormente. (Estas opciones son relevantes cada vez que se especifica un archivo de clave a pageant que necesita descifrado inmediato, y en modo --askpass).
--help
Imprime un resumen breve de las opciones de la línea de comandos y termina.
--version, -V
Imprime la versión de Pageant.
--
Hace que todos los argumentos subsiguientes sean tratados como nombres de archivo de clave, incluso si parecen opciones.
