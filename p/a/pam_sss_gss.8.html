NOMBRE

pam_sss_gss - módulo PAM para autenticación GSSAPI de SSSD

SINOPSIS

pam_sss_gss.so [debug]

DESCRIPCIÓN

pam_sss_gss.so autentica al usuario a través de GSSAPI en cooperación con SSSD.

Este módulo intentará autenticar al usuario utilizando el nombre de servicio GSSAPI basado en host, host@hostname, que se traduce al principal Kerberos host/hostname@REALM. La parte REALM del nombre del principal Kerberos se deriva mediante mecanismos internos de Kerberos y se puede establecer explícitamente en la configuración de la sección [domain_realm] en /etc/krb5.conf.

SSSD se utiliza para proporcionar el nombre de servicio deseado y para validar las credenciales del usuario mediante llamadas GSSAPI. Si el ticket de servicio ya está presente en la caché de credenciales de Kerberos o si el ticket de concesión de tickets del usuario se puede utilizar para obtener el ticket de servicio correcto, el usuario será autenticado.

Si pam_gssapi_check_upn es True (predeterminado), SSSD requiere que las credenciales utilizadas para obtener los tickets de servicio puedan asociarse con el usuario. Esto significa que el principal al que pertenecen las credenciales de Kerberos debe coincidir con el nombre del principal del usuario tal como se define en LDAP.

Para habilitar la autenticación GSSAPI en SSSD, establezca la opción pam_gssapi_services en la sección [pam] o de dominio de sssd.conf. Las credenciales del servicio deben almacenarse en la keytab de SSSD (ya está presente si se utiliza el proveedor ipa o ad). La ubicación de la keytab se puede establecer con la opción krb5_keytab. Consulte sssd.conf(5) y sssd-krb5(5) para obtener más detalles sobre estas opciones.

Algunas implementaciones de Kerberos permiten asociar indicadores de autenticación con un método de preautenticación particular utilizado para obtener el ticket de concesión de tickets por parte del usuario. pam_sss_gss.so permite forzar la presencia de indicadores de autenticación en los tickets de servicio antes de que se pueda acceder a un servicio PAM en particular.

Si pam_gssapi_indicators_map está configurado en la sección [pam] o de dominio de sssd.conf, SSSD realizará una comprobación de la presencia de los indicadores configurados en el ticket de servicio.

OPCIONES

debug

Imprime información de depuración.

TIPOS DE MÓDULO PROPORCIONADOS

Solo se proporciona el tipo de módulo auth.

VALORES DE RETORNO

PAM_SUCCESS

La operación PAM finalizó correctamente.

PAM_USER_UNKNOWN

El usuario es desconocido para el servicio de autenticación o la autenticación GSSAPI no es compatible.

PAM_AUTH_ERR

Error de autenticación.

PAM_AUTHINFO_UNAVAIL

No se pudo acceder a la información de autenticación. Esto podría deberse a un error de red o de hardware.

PAM_SYSTEM_ERR

Ocurrió un error del sistema. Los archivos de registro de SSSD pueden contener información adicional sobre el error.

EJEMPLOS

El caso de uso principal es proporcionar autenticación sin contraseña en sudo, pero sin la necesidad de deshabilitar completamente la autenticación. Para lograr esto, primero habilite la autenticación GSSAPI para sudo en sssd.conf:

[domain/MYDOMAIN]
pam_gssapi_services = sudo, sudo-i

Y luego habilite el módulo en la pila PAM deseada (por ejemplo, /etc/pam.d/sudo y /etc/pam.d/sudo-i).

...
auth sufficient pam_sss_gss.so
...

SOLUCIÓN DE PROBLEMAS

Los registros de SSSD, la salida de depuración de pam_sss_gss y syslog pueden contener información útil sobre el error. Aquí hay algunos problemas comunes:

1. Tengo la variable de entorno KRB5CCNAME establecida y la autenticación no funciona: Dependiendo de su versión de sudo, es posible que sudo no pase esta variable al entorno PAM. Intente agregar KRB5CCNAME a env_keep en /etc/sudoers o en sus reglas de sudo de LDAP, opciones predeterminadas.

2. La autenticación no funciona y syslog contiene "Server not found in Kerberos database": Es probable que Kerberos no pueda resolver el reino correcto para el ticket de servicio basándose en el nombre del host. Intente agregar el nombre del host directamente a [domain_realm] en /etc/krb5.conf de la siguiente manera:

3. La autenticación no funciona y syslog contiene "No Kerberos credentials available": No tiene credenciales que se puedan utilizar para obtener el ticket de servicio requerido. Use kinit o autentíquese a través de SSSD para adquirir esas credenciales.

4. La autenticación no funciona y el registro sssd-pam de SSSD contiene "User with UPN [$UPN] was not found." o "UPN [$UPN] does not match target user [$username].": Está utilizando credenciales que no se pueden mapear al usuario que se está autenticando. Intente usar kswitch para seleccionar un principal diferente, asegúrese de haberse autenticado con SSSD o considere deshabilitar pam_gssapi_check_upn.

[domain_realm]
.myhostname = MYREALM

    pam_sss_gss(8)

    NOMBRE

    pam_sss_gss - Módulo PAM para autenticación GSSAPI a través de SSSD

    SINOPSIS

    pam_sss_gss.so

    DESCRIPCIÓN

    El módulo pam_sss_gss es un módulo PAM (Pluggable Authentication Modules) que permite la autenticación de usuarios utilizando GSSAPI (Generic Security Services Application Program Interface) a través del servicio SSSD (System Security Services Daemon).

    Este módulo interactúa con SSSD para obtener credenciales GSSAPI y autenticar a los usuarios en sistemas que utilizan Kerberos u otros mecanismos de seguridad compatibles con GSSAPI gestionados por SSSD.

    OPCIONES

    • disable_replay_protection: Deshabilita la protección contra repetición de tickets. (No recomendado para la mayoría de los casos de uso).
    • use_first_pass: Intenta usar la contraseña proporcionada anteriormente en la pila PAM, si está disponible.
    • use_hashed_pass: Se espera que la contraseña proporcionada en la pila PAM esté en formato hash.
    • principal=NOMBRE_PRINCIPAL: Especifica un nombre principal GSSAPI alternativo.

    EJEMPLOS

    Para usar pam_sss_gss en una configuración PAM:

    auth        sufficient    pam_sss_gss.so principal=mi-servicio@MI.DOMINIO

    VER TAMBIÉN

    pam.d(5), sssd.conf(5), gssapi(8)
