pldd(1) Manual de Comandos Generales pldd(1)

NOMBRE

pldd - mostrar objetos compartidos dinámicos enlazados en un proceso

SINOPSIS

pldd pid
pldd opción

DESCRIPCIÓN

El comando pldd muestra una lista de los objetos compartidos dinámicos (DSOs) que están enlazados en el proceso con el ID de proceso (PID) especificado. La lista incluye las bibliotecas que se han cargado dinámicamente utilizando dlopen(3).

OPCIONES

--help
-?
Muestra un mensaje de ayuda y sale.
--usage
Muestra un mensaje de uso corto y sale.
--version
-V
Muestra la información de la versión del programa y sale.

ESTADO DE SALIDA

En caso de éxito, pldd sale con el estado 0. Si el proceso especificado no existe, el usuario no tiene permiso para acceder a su lista de objetos compartidos dinámicos, o no se proporcionan argumentos de línea de comandos, pldd sale con el estado 1. Si se le da una opción inválida, sale con el estado 64.

VERSIONES

Otros sistemas tienen un comando similar.

ESTANDARES

Ninguno.

HISTORIA

glibc 2.15.

NOTAS

El comando


lsof -p PID

también muestra una salida que incluye los objetos compartidos dinámicos que están enlazados en un proceso.

El comando de gdb(1) info shared también muestra las bibliotecas compartidas que está utilizando un proceso, de modo que se puede obtener una salida similar a pldd utilizando un comando como el siguiente (para monitorizar el proceso con el pid especificado):


$ gdb -ex "set confirm off" \
      -ex "set height 0" \
      -ex "info shared" \
      -ex "quit" \
      -p $pid \
| grep '^0x.*0x';

ERRORES

Desde glibc 2.19 hasta glibc 2.29, pldd estaba roto: simplemente se colgaba al ejecutarse. Este problema se solucionó en glibc 2.30, y la solución se ha retroportado a versiones anteriores de glibc en algunas distribuciones.

EJEMPLOS

$ echo $$;               # Mostrar PID del shell
1143
$ pldd $$;               # Mostrar DSOs enlazados en el shell
1143:   /usr/bin/bash
linux-vdso.so.1
/lib64/libtinfo.so.5
/lib64/libdl.so.2
/lib64/libc.so.6
/lib64/ld-linux-x86-64.so.2
/lib64/libnss_files.so.2

VER TAMBIÉN

ldd(1), lsof(1), dlopen(3), ld.so(8)
