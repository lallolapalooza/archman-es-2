place(n)

place(n) Comandos integrados de Tk place(n)

NOMBRE

place - Gestor de geometría para colocación fija o elástica

SINOPSIS

place opción argumento ?argumento ...?

DESCRIPCIÓN

El gestor de colocación (placer) es un gestor de geometría para Tk. Proporciona una colocación fija sencilla de ventanas, donde se especifica el tamaño y la ubicación exactos de una ventana, llamada el *contenido*, dentro de otra ventana, llamada el *contenedor*. El gestor de colocación también proporciona colocación elástica, donde se especifica el tamaño y la ubicación del contenido en términos de las dimensiones del contenedor, de modo que el contenido cambia de tamaño y ubicación en respuesta a los cambios en el tamaño del contenedor. Por último, el gestor de colocación permite mezclar estos estilos de colocación de manera que, por ejemplo, el contenido tenga un ancho y alto fijos pero esté centrado dentro del contenedor.

place ventana opción valor ?opción valor ...?
Organiza la gestión de la geometría de una ventana de contenido cuya ruta de acceso es ventana. Los argumentos restantes consisten en uno o más pares de *opción-valor* que especifican la forma en que se gestiona la geometría de ventana. Opción puede tener cualquiera de los valores aceptados por el comando place configure.
place configure ventana ?opción? ?valor opción valor ...?
Consulta o modifica las opciones de geometría del contenido dado por ventana. Si no se especifica ninguna opción, este comando devuelve una lista que describe las opciones disponibles (consulte Tk_ConfigureInfo para obtener información sobre el formato de esta lista). Si se especifica opción sin ningún valor, el comando devuelve una lista que describe la opción nombrada (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica ninguna opción). Si se especifican uno o más pares de *opción-valor*, el comando modifica la(s) opción(es) dada(s) para que tengan el(los) valor(es) dado(s); en este caso, el comando devuelve una cadena vacía.

Los siguientes pares de *opción-valor* son compatibles:

-anchor dónde
Dónde especifica qué punto de ventana se posicionará en la ubicación (x,y) seleccionada por las opciones -x, -y, -relx y -rely. El punto de anclaje se especifica en términos del área exterior de ventana, incluido su borde, si lo tiene. Por lo tanto, si dónde es se, la esquina inferior derecha del borde de ventana aparecerá en la ubicación (x,y) dada en el contenedor. El punto de anclaje por defecto es nw.
-bordermode modo
Modo determina el grado en que los bordes dentro del contenedor se utilizan para determinar la colocación del contenido. El valor por defecto y más común es inside. En este caso, el gestor de colocación considera que el área del contenedor es el área más interna del contenedor, dentro de cualquier borde: una opción de -x 0 corresponde a una coordenada x justo dentro del borde y una opción de -relwidth 1.0 significa que ventana llenará el área dentro del borde del contenedor.

Si modo es outside, el gestor de colocación considera que el área del contenedor incluye su borde; este modo se utiliza normalmente al colocar ventana fuera de su contenedor, como con las opciones -x 0 -y 0 -anchor ne. Por último, modo puede especificarse como ignore, en cuyo caso los bordes se ignoran: el área del contenedor se considera su área X oficial, que incluye cualquier borde interno pero ningún borde externo. Un modo de borde de ignore probablemente no sea muy útil.

-height tamaño
Tamaño especifica la altura de ventana en unidades de pantalla (es decir, cualquiera de las formas aceptadas por Tk_GetPixels). La altura será la dimensión exterior de ventana, incluido su borde, si lo tiene. Si tamaño es una cadena vacía, o si no se especifica ninguna opción -height o -relheight, se utilizará la altura solicitada internamente por la ventana.
-in contenedor
Contenedor especifica el nombre de ruta de la ventana en relación con la cual se colocará ventana. Contenedor debe ser el padre de ventana o un descendiente del padre de ventana. Además, contenedor y ventana deben ser descendientes de la misma ventana de nivel superior. Estas restricciones son necesarias para garantizar que ventana sea visible siempre que contenedor sea visible. Si no se especifica esta opción, el valor por defecto de la otra ventana es el padre de ventana.
-relheight tamaño
Tamaño especifica la altura de ventana. En este caso, la altura se especifica como un número de punto flotante relativo a la altura del contenedor: 0.5 significa que ventana tendrá la mitad de altura que el contenedor, 1.0 significa que ventana tendrá la misma altura que el contenedor, y así sucesivamente. Si se especifican tanto -height como -relheight para un contenido, sus valores se suman. Por ejemplo, -relheight 1.0 -height -2 hace que el contenido sea 2 píxeles más bajo que el contenedor.
-relwidth tamaño
Tamaño especifica el ancho de ventana. En este caso, el ancho se especifica como un número de punto flotante relativo al ancho del contenedor: 0.5 significa que ventana tendrá la mitad de ancho que el contenedor, 1.0 significa que ventana tendrá el mismo ancho que el contenedor, y así sucesivamente. Si se especifican tanto -width como -relwidth para un contenido, sus valores se suman. Por ejemplo, -relwidth 1.0 -width 5 hace que el contenido sea 5 píxeles más ancho que el contenedor.
-relx ubicación
Ubicación especifica la coordenada x dentro de la ventana del contenedor del punto de anclaje de ventana. En este caso, la ubicación se especifica de forma relativa como un número de punto flotante: 0.0 corresponde al borde izquierdo del contenedor y 1.0 corresponde al borde derecho del contenedor. Ubicación no tiene por qué estar en el rango 0.0-1.0. Si se especifican tanto -x como -relx para un contenido, sus valores se suman. Por ejemplo, -relx 0.5 -x -2 posiciona el borde izquierdo del contenido 2 píxeles a la izquierda del centro de su contenedor.
-rely ubicación
Ubicación especifica la coordenada y dentro de la ventana del contenedor del punto de anclaje de ventana. En este caso, el valor se especifica de forma relativa como un número de punto flotante: 0.0 corresponde al borde superior del contenedor y 1.0 corresponde al borde inferior del contenedor. Ubicación no tiene por qué estar en el rango 0.0-1.0. Si se especifican tanto -y como -rely para un contenido, sus valores se suman. Por ejemplo, -rely 0.5 -x 3 posiciona el borde superior del contenido 3 píxeles por debajo del centro de su contenedor.
-width tamaño
Tamaño especifica el ancho de ventana en unidades de pantalla (es decir, cualquiera de las formas aceptadas por Tk_GetPixels). El ancho será la dimensión exterior de ventana, incluido su borde, si lo tiene. Si tamaño es una cadena vacía, o si no se especifica ninguna opción -width o -relwidth, se utilizará el ancho solicitado internamente por la ventana.
-x ubicación
Ubicación especifica la coordenada x dentro de la ventana del contenedor del punto de anclaje de ventana. La ubicación se especifica en unidades de pantalla (es decir, cualquiera de las formas aceptadas por Tk_GetPixels) y no tiene por qué estar dentro de los límites de la ventana del contenedor.
-y ubicación
Ubicación especifica la coordenada y dentro de la ventana del contenedor del punto de anclaje de ventana. La ubicación se especifica en unidades de pantalla (es decir, cualquiera de las formas aceptadas por Tk_GetPixels) y no tiene por qué estar dentro de los límites de la ventana del contenedor.

Si se especifica el mismo valor por separado con dos opciones diferentes, como -x y -relx, se utiliza la opción más reciente y se ignora la anterior.

NAME

place - geometry manager for Tk windows

SYNOPSIS

place window ?option value ...?

DESCRIPTION

The place command provides a geometry manager for Tk windows. It allows you to specify the position and size of a window (the content window) relative to another window (the container window).

The window argument is the path name of the content window whose geometry is to be managed. The container window is specified implicitly by the -in option, or defaults to the content window's parent if -in is not specified. The geometry of the content window is specified by a combination of the following options:

place configure window ?option value ...?
Configures the geometry of window using the specified option value pairs. The options are:
-anchor anchor
Specifies how the window should be anchored within its container. anchor must be one of the standard Tk anchors like n, ne, e, se, s, sw, w, nw, or center. Default is nw.
-bordermode borderMode
Specifies whether window geometry should be relative to the outside or inside of the container's border. borderMode must be either inside or outside. Default is inside.
-height height
Specifies the height of the window in screen units. If the value is followed by c, the height is in screen units (e.g. "100c"). If the value is followed by w, the height is a screen percentage (e.g. "50w").
-in master
Specifies the container window. If this option is omitted, the content window's parent is used as the container.
-relheight relHeight
Specifies the height of the window as a fraction of the container's height. relHeight is a screen percentage (e.g. "50w").
-relwidth relWidth
Specifies the width of the window as a fraction of the container's width. relWidth is a screen percentage (e.g. "50w").
-relx relX
Specifies the x-coordinate of the -anchor point of the window within the container, as a fraction of the container's width. relX is a screen percentage.
-rely relY
Specifies the y-coordinate of the -anchor point of the window within the container, as a fraction of the container's height. relY is a screen percentage.
-width width
Specifies the width of the window in screen units. If the value is followed by c, the width is in screen units (e.g. "100c"). If the value is followed by w, the width is a screen percentage (e.g. "50w").
-x x
Specifies the x-coordinate of the -anchor point of the window within the container, in screen units. If the value is followed by c, the x is in screen units (e.g. "100c"). If the value is followed by w, the x is a screen percentage (e.g. "50w").
-y y
Specifies the y-coordinate of the -anchor point of the window within the container, in screen units. If the value is followed by c, the y is in screen units (e.g. "100c"). If the value is followed by w, the y is a screen percentage (e.g. "50w").
The options -relx, -rely, -relwidth, and -relheight specify geometry relative to the container. The options -x, -y, -width, and -height specify geometry in absolute screen units. All options default to 0, except for -anchor which defaults to nw and -bordermode which defaults to inside. If an option is specified with a value ending in w, it's treated as a percentage of the container's size. Otherwise, it's treated as screen units.
place forget window
Causes the placer to stop managing the geometry of window. As a side effect of this command window will be unmapped so that it does not appear on the screen. If window is not currently managed by the placer then the command has no effect. This command returns an empty string.
place info window
Returns a list giving the current configuration of window. The list consists of option-value pairs in exactly the same form as might be specified to the place configure command.
place slaves window
Returns a list of all the content windows for which window is the container. If there is no content for window then an empty string is returned.
place content window
Synonym for place slaves window.

If the configuration of a window has been retrieved with place info, that configuration can be restored later by first using place forget to erase any existing information for the window and then invoking place configure with the saved information.

FINE POINTS

It is not necessary for the container window to be the parent of the content window. This feature is useful in at least two situations. First, for complex window layouts it means you can create a hierarchy of subwindows whose only purpose is to assist in the layout of the parent. The “real children” of the parent (i.e. the windows that are significant for the application's user interface) can be children of the parent yet be placed inside the windows of the geometry-management hierarchy. This means that the path names of the “real children” do not reflect the geometry-management hierarchy and users can specify options for the real children without being aware of the structure of the geometry-management hierarchy.

A second reason for having a container different than the content's parent is to tie two siblings together. For example, the placer can be used to force a window always to be positioned centered just below one of its siblings by specifying the configuration

-in sibling -relx 0.5 -rely 1.0 -anchor n -bordermode outside
Whenever the sibling is repositioned in the future, the content will be repositioned as well.

Unlike many other geometry managers (such as the packer) the placer does not make any attempt to manipulate the geometry of the container windows or the parents of content windows (i.e. it does not set their requested sizes). To control the sizes of these windows, make them windows like frames and canvases that provide configuration options for this purpose.

EXAMPLE

Make the label occupy the middle bit of the toplevel, no matter how it is resized:

label .l -text "In the\nMiddle!" -bg black -fg white
place .l -relwidth .3 -relx .35 -relheight .3 -rely .35
