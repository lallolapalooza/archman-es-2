plink(1) Suite de herramientas PuTTY plink(1)

NOMBRE

plink - PuTTY link, herramienta de conexión de red por línea de comandos

SINOPSIS

plink [opciones] [usuario@]host [comando]

DESCRIPCIÓN

plink es una herramienta de conexión de red que soporta varios protocolos.

OPCIONES

Las opciones de línea de comandos soportadas por plink son:

-V
Muestra información de versión y sale.
-pgpfp
Muestra las huellas digitales de las Claves Maestras PGP de PuTTY y sale, para ayudar a verificar nuevos archivos publicados por el equipo de PuTTY.
-v
Muestra mensajes detallados.
-load sesión
Carga la configuración desde una sesión guardada.
-ssh
Fuerza el uso del protocolo SSH (por defecto).
-telnet
Fuerza el uso del protocolo Telnet.
-rlogin
Fuerza el uso del protocolo rlogin.
-raw
Fuerza el modo raw.
-serial
Fuerza el modo serie.
-ssh-connection
Fuerza el uso del protocolo `bare ssh-connection'. Esto sólo es probable que sea útil al conectarse a un servidor psusan(1), muy probablemente con una ruta absoluta a un socket de dominio Unix en lugar de host.
-proxycmd comando
En lugar de establecer una conexión TCP, usa comando como proxy; el tráfico de red se redirigirá a la entrada y salida estándar de comando. comando debe ser una sola palabra, por lo que es probable que necesite ser entrecomillado por el shell.

Las cadenas especiales %host y %port en comando se reemplazarán por el nombre de host y el número de puerto al que deseas conectarte; para obtener un signo % literal, introduce %%.

También se admiten escapes de barra invertida, como secuencias como \n que se reemplazan por un salto de línea literal; para obtener una barra invertida literal, introduce \\. (Es posible que se requieran escapes adicionales según el shell.)

(Consulte el manual principal de PuTTY para obtener detalles completos de los tokens soportados delimitados por % y barra invertida, aunque la mayoría de ellos probablemente no sean muy útiles en este contexto.)

-P puerto
Conéctate al puerto puerto.
-l usuario
Establece el nombre de usuario remoto a usuario.
-m ruta
Lee comandos remotos desde el archivo local ruta.
-batch
Deshabilita las indicaciones interactivas.
-sanitise-stderr
-sanitise-stdout
-no-sanitise-stderr
-no-sanitise-stdout
Por defecto, Plink puede optar por filtrar caracteres de control si parece apropiado, para evitar que procesos remotos envíen secuencias de escape confusas. Estas opciones anulan el comportamiento por defecto de Plink para habilitar o deshabilitar dicho filtrado en los canales de error estándar y salida estándar.
-pwfile nombrearchivo
Abre el archivo especificado y utiliza la primera línea de texto leída de él como contraseña remota.
-pw contraseña
Establece la contraseña remota a contraseña. PRECAUCIÓN: esto probablemente hará que la contraseña sea visible para otros usuarios de la máquina local (a través de comandos como `ps' o `w'). Usa -pwfile en su lugar.
-L [dir_origen:]puerto_origen:host_destino:puerto_destino
Configura un reenvío de puerto local: escucha en puerto_origen (o dir_origen:puerto_origen si se especifica), y reenvía cualquier conexión a través de la conexión SSH a la dirección de destino host_destino:puerto_destino. Sólo funciona en SSH.
-R [dir_origen:]puerto_origen:host_destino:puerto_destino
Configura un reenvío de puerto remoto: pide al servidor SSH que escuche en puerto_origen (o dir_origen:puerto_origen si se especifica), y que reenvíe cualquier conexión de vuelta a través de la conexión SSH donde el cliente la pasará a la dirección de destino host_destino:puerto_destino. Sólo funciona en SSH.
-D [dir_origen:]puerto_origen
Configura un reenvío de puerto dinámico. El cliente escucha en puerto_origen (o dir_origen:puerto_origen si se especifica), e implementa un servidor SOCKS. Así puedes apuntar aplicaciones compatibles con SOCKS a este puerto y usarán automáticamente la conexión SSH para tunelizar todas sus conexiones. Sólo funciona en SSH.
-X
Habilita el reenvío X11.
-x
Deshabilita el reenvío X11 (por defecto).
-A
Habilita el reenvío del agente.
-a
Deshabilita el reenvío del agente (por defecto).
-t
Habilita la asignación de pty (por defecto si NO se especifica un comando).
-T
Deshabilita la asignación de pty (por defecto si se especifica un comando).
-1
Fuerza el uso de la versión 1 del protocolo SSH.
-2
Fuerza el uso de la versión 2 del protocolo SSH.
-4, -6
Fuerza el uso de IPv4 o IPv6 para las conexiones de red.
-C
Habilita la compresión SSH.
-i archivo_clave
Archivo de clave privada para la autenticación de usuario. Para claves SSH-2, este archivo de clave debe estar en formato PPK de PuTTY, no en formato OpenSSH ni en ningún otro.

Si estás utilizando un agente de autenticación, también puedes especificar una clave pública aquí (en formato RFC 4716 o OpenSSH), para identificar cuál de las claves del agente utilizar.

-noagent
No intentes usar un agente de autenticación para la autenticación local. (Esto no afecta al reenvío del agente.)
-agent
Permite el uso de un agente de autenticación. (Esta opción sólo es necesaria para anular una configuración en una sesión guardada.)
-no-trivial-auth
Desconéctate de cualquier servidor SSH que acepte autenticación sin haber solicitado nunca ninguna contraseña, firma o token. (Puede que quieras habilitar esto para un servidor que siempre esperas que te desafíe, por ejemplo, para asegurarte de no escribir accidentalmente la contraseña de tu archivo de clave en un servidor comprometido que suplanta el aviso de contraseña de Plink.)
-noshare
No pruebes ni intentes compartir una conexión existente, siempre haz una nueva conexión.
-share
Prueba e intenta compartir una conexión existente.
-hostkey clave
Especifica una clave pública de host aceptable. Esta opción puede especificarse varias veces; cada clave puede ser una huella digital (SHA256:AbCdE..., 99:aa:bb:..., etc.) o un blob codificado en base64 en el formato de una sola línea de OpenSSH.

Especificar esta opción anula la gestión automática de claves de host; sólo se aceptarán las claves especificadas en la línea de comandos (a menos que una sesión guardada también anule las claves de host, en cuyo caso se añadirán.

NAME

plink ― PuTTY Link

SYNOPSIS

plink [Options] [user@]host [command]

DESCRIPTION

Plink is a command-line connection tool for the PuTTY backends. It can be used to connect to SSH, Telnet, Rlogin or serial ports.

It supports all the same command-line options as the other PuTTY tools, described in the PuTTY manual page.

In this man page, we will only describe the options that are specific to Plink, or options that behave differently when used with Plink.

The following options are specific to Plink:

OPTIONS

-a
Request pseudo-terminal allocation. This is the default when running arbitrary commands.
-A
Enable X11 forwarding. This allows you to run X11 applications on the remote server and have their display appear on your local X server.
-batch
Run in batch mode. This disables all interactive prompts. If any prompt would normally appear, Plink will instead exit with an error.
-bc
Make Plink behave like the PuTTY connection type. This is mainly useful for debugging.
-c command
Specify the command to be run on the remote server.
-C
Enable compression of data. This can speed up connections on slow networks, at the expense of increased CPU usage.
-pw password
Specify the password to use for authentication. This is not recommended, as it is insecure. It is better to use SSH keys.
-P port
Specify the port number to connect to on the server.
-i identity file
Specify the private key file to use for authentication. This is only relevant for SSH connections.
-loadsession session name
Load saved session parameters from the specified session name.
-noagent
Do not try to use an SSH authentication agent.
-proxyauth username:password
Provide authentication details for the proxy server.
-proxycmd command
Use the specified command to set up a connection to the server. This is useful for connecting through proxies that Plink does not natively support.
-proxyip ip address
Specify the IP address of the proxy server. This is only relevant when using a SOCKS proxy.
-proxysubsystem
Use the proxy as an SSH subsystem. This is only relevant for SSH connections.
-proxyuser username
Specify the username to use when connecting to the proxy server. This is only relevant when using a SOCKS proxy.
-quiet
Do not display any warning or informational messages.
-serial port
Connect to the specified serial port instead of using SSH or Telnet.
-share
Share an existing connection if possible. This can save resources by avoiding the need to establish a new connection.
-sshlog logfile
Log protocol details to the specified log file. This is useful for debugging SSH connections. The log file will not be written if the host key cache is not written.
-sshrawlog logfile
Log raw encrypted packet data to the specified log file. This is even more detailed than -sshlog and can be useful for debugging complex issues.
-s
Remote command is SSH subsystem (SSH-2 only).
-N
Don't start a remote command or shell at all (SSH-2 only).
-nc host:port
Make a remote network connection from the server instead of starting a shell or command.
-sercfg configuration-string
Specify the configuration parameters for the serial port, in -serial mode. configuration-string should be a comma-separated list of configuration parameters as follows:
•
Any single digit from 5 to 9 sets the number of data bits.
•
`1', `1.5' or `2' sets the number of stop bits.
•
Any other numeric string is interpreted as a baud rate.
•
A single lower-case letter specifies the parity: `n' for none, `o' for odd, `e' for even, `m' for mark and `s' for space.
•
A single upper-case letter specifies the flow control: `N' for none, `X' for XON/XOFF, `R' for RTS/CTS and `D' for DSR/DTR.
-sshlog logfile
-sshrawlog logfile
For SSH connections, these options make plink log protocol details to a file. (Some of these may be sensitive, although by default an effort is made to suppress obvious passwords.)

-sshlog logs decoded SSH packets and other events (those that -v would print). -sshrawlog additionally logs the raw encrypted packet data.

-logoverwrite
If Plink is configured to write to a log file that already exists, discard the existing file.
-logappend
If Plink is configured to write to a log file that already exists, append new log data to the existing file.
-shareexists
Instead of making a new connection, test for the presence of an existing connection that can be shared. The desired session can be specified in any of the usual ways.

Returns immediately with a zero exit status if a suitable `upstream' exists, nonzero otherwise.
