POSTFIX-LOGWATCH(1) Manual de comandos generales POSTFIX-LOGWATCH(1)

NOMBRE

postfix-logwatch - Utilidad de análisis y análisis de registros de Postfix

SINOPSIS

postfix-logwatch [opciones] [archivo_log ...]

DESCRIPCIÓN


La utilidad postfix-logwatch(1) es un analizador de registros de Postfix MTA que produce resúmenes, detalles y estadísticas sobre el funcionamiento de Postfix.

Esta utilidad puede usarse como un programa independiente o como un módulo de filtro de Logwatch para producir informes resumidos y detallados de Postfix dentro de Logwatch.

Postfix-logwatch es capaz de producir una amplia gama de informes con datos agrupados y ordenados tanto como sea posible para reducir el ruido y destacar patrones. Los informes resumidos breves proporcionan una visión general rápida de las operaciones generales de Postfix y la entrega de mensajes, señalando advertencias que pueden requerir atención. Los informes detallados proporcionan información fácil de escanear, organizada jerárquicamente y con tanto o tan poco detalle como se desee.

Postfix-logwatch genera dos secciones principales: una sección de Resumen y una sección Detallada. Para facilitar la lectura y el escaneo rápido, los recuentos de eventos o aciertos aparecen en la columna izquierda, seguidos de una breve descripción del tipo de evento, y finalmente pueden aparecer estadísticas adicionales o representaciones de recuentos en la columna más a la derecha.

El siguiente segmento de un informe de Resumen de ejemplo ilustra:

****** Resumen ********************************************
      81   *Advertencia: Límite de tasa de conexión alcanzado (anvil)
     146   Advertido
  68.310M  Bytes aceptados                       71,628,177
  97.645M  Bytes entregados                     102,388,245
========   ================================================
    3464   Aceptados                                 41.44%
    4895   Rechazados                                58.56%
--------   ------------------------------------------------
    8359   Total                                    100.00%
========   ================================================
El informe advierte que se alcanzó el límite de tasa de conexión de anvil 81 veces, se registró una acción WARN de verificación de acceso de Postfix 146 veces, y un total de 68.310 megabytes (71,628,177 bytes) fueron aceptados en el sistema Postfix, entregando 97.645 megabytes de datos (debido a múltiples destinatarios). Las líneas Aceptados y Rechazados muestran que Postfix aceptó 3464 (41.44% del total de mensajes) y rechazó 4895 (el 58.56% restante) de los 8359 mensajes totales (los rechazos temporales aparecen en otro lugar).

Hay docenas de subsecciones disponibles en el informe Detallado, cuya salida puede controlarse de diversas maneras. Cada subsección intenta agrupar y presentar los datos más significativos en los niveles superiores, mientras que los datos menos útiles o *ruidosos* se empujan a los niveles inferiores. El objetivo es proporcionar el máximo beneficio posible de la agrupación inteligente de datos, para permitir un escaneo de informes más rápido, la identificación de patrones y la resolución de problemas. Los datos siempre se ordenan en orden descendente por recuento y luego numéricamente por dirección IP o alfabéticamente según corresponda.

El siguiente segmento de errores MX de un informe Detallado de ejemplo ilustra la estructura básica de nivel jerárquico de postfix-logwatch:

****** Detallado *******************************************
     261   Errores MX --------------------------------------
     261      Imposible buscar host MX
     222         Host no encontrado
      73            foolishspammer.local
      60            completely.bogus.domain.example
      11            friend.example.com
      39         No hay dirección asociada con el nombre del host
      23            dummymx.sample.net
      16            pushn.spam.sample.com

La utilidad postfix-logwatch lee desde STDIN o desde el archivo de registro de Postfix llamado archivo_log. Se pueden especificar varios argumentos de archivo_log, cada uno procesado en orden. El usuario que ejecuta postfix-logwatch debe tener permiso de lectura sobre cada archivo de registro especificado.

Opciones

Las opciones que se enumeran a continuación afectan el funcionamiento de postfix-logwatch. Las opciones especificadas más tarde en la línea de comandos anulan las anteriores. Cualquier opción puede abreviarse a una longitud inequívoca.

-f archivo_config
--archivo_config archivo_config
Utiliza un archivo de configuración alternativo archivo_config en lugar del predeterminado. Esta opción se puede usar más de una vez. Múltiples archivos de configuración se procesarán en el orden presentado en la línea de comandos. Consulte ARCHIVO DE CONFIGURACIÓN a continuación.
--debug palabras_clave
Muestra información de depuración durante la operación de postfix-logwatch. El parámetro palabras_clave son una o más palabras clave separadas por comas o espacios. Para obtener la lista de palabras clave válidas, use --debug xxx donde xxx es cualquier palabra clave no válida.
--[no]retrasos
Habilita (deshabilita) la salida del informe de percentiles de retrasos de mensajes. El informe de percentiles de retrasos muestra los percentiles para cada uno de los 4 tiempos de latencia de entrega informados por Postfix (disponible en la versión 2.3 y posteriores) en el formato retrasos=a/b/c/d, donde a es el tiempo antes de la cola activa (incluye el tiempo para intentos de entrega anteriores y el tiempo en la cola diferida), b es el tiempo en la cola activa hasta la transferencia al agente de entrega, c es el tiempo dedicado a establecer conexiones (incluyendo DNS, HELO y TLS) y d es el tiempo dedicado a entregar el mensaje. El retraso total mostrado proviene del campo retraso= en una línea de registro de entrega de mensajes.

Nota: Este informe puede consumir una gran cantidad de memoria; si no le es útil, deshabilite el informe de retrasos.

--percentiles_retrasos p1 [p2 ...]
Especifica los percentiles que se utilizarán en el informe de percentiles de retrasos de mensajes. Los percentiles p1, p2, ... varían de 0 a 100, inclusive. El orden de la lista no se ordena; el informe mostrará las columnas de percentiles en el orden que usted especifique.
--detalle nivel
Establece el nivel de detalle máximo para postfix-logwatch en nivel. Esta opción es global y anula cualquier otro limitador de salida descrito a continuación.

La utilidad postfix-logwatch produce una sección de Resumen, una sección Detallada y secciones de informe adicionales. Con nivel menor que 5, postfix-logwatch producirá solo la sección de Resumen. En nivel 5 o superior, la sección Detallada y cualquier sección de informe adicional son candidatas para su salida. Cada aumento incremental en nivel genera un subnivel adicional de salida en la sección Detallada del informe. En nivel 10, se emiten todos los niveles. Las líneas que exceden el ancho máximo del informe (especificado con ancho_max_informe) se cortarán. Establecer nivel en 11 evitará que se corten las líneas del informe (ver también --estilo_linea).

--ayuda
Imprime la información de uso y una breve descripción de las opciones de la línea de comandos.
--ignorar_servicio patron
Ignora las líneas de registro que contienen el nombre del servicio de Postfix postfix/servicio. El parámetro servicio es una expresión regular.

Nota: si utiliza paréntesis en su expresión regular, asegúrese de que estén agrupando y no capturando: use (?:patron) en lugar de (patron).

--ancho_direccion_ip ancho
Especifica que las direcciones IP en pares de direcciones/nombres de host se impriman con un ancho de campo de ancho caracteres. Aumentar el valor predeterminado puede ser útil para sistemas que utilizan direcciones IPv6 largas.
-l limitador=nivel
--limitar limitador=nivel
Establece el limitador limitador con la especificación nivel.
--estilo_linea estilo
Especifica cómo manejar las líneas de informe largas. Hay tres estilos disponibles: completo, truncar y

OPTIONS

--max_report_width width
Set the maximum width of each line in the report to width. The default value is 80. This value may be overridden for specific sections by the wrap, full, and truncate options below.
--[no]wrap
This option controls line wrapping behavior. Setting style to full will prevent cutting lines to max_report_width; this is what occurs when detail is 11 or higher. When style is truncate (the default), long lines will be truncated according to max_report_width. Setting style to wrap will wrap lines longer than max_report_width such that left column hit counts are not obscured. This option takes precedence over the line style implied by the detail level. The options --full, --truncate, and --wrap are synonyms.
--[no]long_queue_ids
Habilita (deshabilita) la interpretación de IDs de cola largos en los registros de Postfix (>= 2.9).
--nodetail
Deshabilita la sección Detailed del informe y todos los informes suplementarios. Esta opción proporciona un mecanismo conveniente para deshabilitar rápidamente todas las secciones bajo el informe Detailed, donde las opciones de línea de comando subsiguientes pueden volver a habilitar una o más secciones para crear informes específicos.
--[no]summary
--show_summary
Habilita (deshabilita) la visualización de la sección Summary del informe. La variable postfix_Show_Summary se utiliza en un archivo de configuración.
--recipient_delimiter delimiter
Divide las direcciones de entrega de correo electrónico utilizando el carácter delimitador de destinatarios delimiter. Esto generalmente debería coincidir con el recipient_delimiter especificado en el archivo de parámetros de Postfix main.cf, o con el valor predeterminado indicado en postconf -d recipient_delimiter. Esto es muy útil para obtener estadísticas por alias cuando se utiliza un delimitador de destinatarios para la entrega de correo.
--reject_reply_patterns r1 [r2 ...]
Especifica la lista de patrones de respuesta de rechazo utilizados para crear grupos de rechazo. Cada entrada en la lista r1 [r2 ...] debe ser un código de respuesta de expresión regular de tres caracteres de la forma [45][0-9.][0-9.], o la palabra "Warn". El "." en la expresión regular es un punto literal que coincide con cualquier subcódigo de respuesta de rechazo; este comodín permite la creación de amplios grupos de rechazo. El orden de la lista se conserva, en el sentido de que los informes de rechazo se generarán en el mismo orden que las entradas de la lista. Los códigos de respuesta de rechazo específicos tendrán prioridad sobre los patrones comodín, independientemente del orden de la lista.

La lista predeterminada es "5.. 4.. Warn", que crea tres grupos de rechazos: rechazos permanentes, fallos de rechazo temporales y advertencias de rechazo (como en warn_if_reject).

Esta característica permite, por ejemplo, distinguir los cierres de canal de transmisión 421 de los errores 45x (por ejemplo, 450 buzón no disponible, 451 errores de procesamiento local, 452 almacenamiento insuficiente). Dicha agrupación se configuraría con la lista: "421 4.. 5.. Warn". Consulte RFC 2821 para obtener más información sobre los códigos de respuesta.

Consulte también CONFIGURATION FILE con respecto al uso de reject_reply_patterns dentro de un archivo de configuración.

--[no]sect_vars
--show_sect_vars boolean
Habilita (deshabilita) la adición del nombre del limitador de nivel de cada sección al título de cada sección Detailed. El nombre que se muestra es la opción de línea de comandos (o la variable del archivo de configuración) utilizada para limitar la salida de esa sección. Con la gran cantidad de limitadores de nivel disponibles en postfix-logwatch, este es un mecanismo conveniente para determinar exactamente qué limitador de nivel afecta a una sección.
--syslog_name namepat
Especifica el nombre del servicio syslog que postfix-logwatch utiliza para hacer coincidir las líneas de syslog. Solo las líneas de registro cuyo nombre de servicio coincida con la expresión regular de Perl namepat serán utilizadas por postfix-logwatch; todas las líneas que no coincidan se ignorarán silenciosamente. Esto es útil cuando un paquete Postfix preinstalado utiliza un nombre diferente al predeterminado (postfix), o cuando hay varias instancias de Postfix en uso y se desea un informe por instancia.

El patrón namepat debe coincidir con el parámetro de configuración syslog_name especificado en el archivo de parámetros de Postfix main.cf, el archivo de control maestro master.cf, o el valor predeterminado como lo indica la salida de postconf -d syslog_name.

Nota: si utiliza paréntesis en su expresión regular, asegúrese de que sean delimitadores y no de captura: use (?:patrón) en lugar de (patrón).

--[no]unknown
--show_unknown boolean
Habilita (deshabilita) la visualización del nombre generado por postfix de 'unknown' en pares de IP/nombre de host formateados en informes Detailed. Predeterminado: habilitado.
--version
Imprime información de la versión de postfix-logwatch.

Limitadores de Nivel

La salida de cada sección en el informe Detailed está controlada por un limitador de nivel. El nombre de la variable limitadora de nivel se mostrará cuando se establezca la opción sect_vars. Los limitadores de nivel se establecen ya sea a través de la línea de comandos en modo independiente con la opción --limit limiter=levelspec, o a través de la variable del archivo de configuración $postfix_limiter=levelspec. Cada limitador requiere un argumento levelspec, que se describe a continuación en CONTROL DE NIVEL.

La lista de limitadores de nivel se muestra a continuación.

Existen varios limitadores de nivel que controlan las subsecciones de rechazo (por ejemplo, rejectbody, rejectsender, etc.). Dado que la lista de variantes de rechazo no se conoce hasta el tiempo de ejecución, después de ver reject_reply_patterns, estos limitadores de rechazo se muestran a continuación de forma genérica, con el prefijo ###. Para utilizar uno de estos limitadores de rechazo, sustituya ### con uno de los códigos de respuesta de rechazo en vigor, reemplazando cada punto con un carácter x. Por ejemplo, utilizando la lista predeterminada de reject_reply_patterns de "5.. 4.. Warn", son válidas tres variantes de rejectbody: --limit 5xxrejectbody, --limit 4xxrejectbody y --limit warnrejectbody. Como conveniencia, puede eliminar completamente el prefijo ### y, en su lugar, utilizar la opción desnuda rejectXXX, y todas las variaciones del limitador de nivel de rechazo se generarán automáticamente basándose en la lista de reject_reply_patterns. Por ejemplo, el segmento de línea de comandos:

    ... --reject_reply_patterns "421 5.." \
            --limit rejectrbl="1:10:"
se convertiría automáticamente en: 
    ... --reject_reply_patterns "421 5.." \
            --limit 421rejectrbl="1:10:" --limit 5xxrejectrbl="1:10:"
Consulte reject_reply_patterns arriba, y los comentarios en el archivo de configuración postfix-logwatch.conf.

CONTROL DE NIVEL


La sección Detailed del informe consta de un número de subsecciones, cada una de las cuales se controla tanto globalmente como independientemente. Dos configuraciones influyen en la salida proporcionada en el informe Detailed: un nivel de detalle global (especificado con --detail) que tiene control final (martillo grande) para limitar la salida de la sección Detailed, y configuraciones de detalle específicas de la subsección (martillo pequeño), que permiten limitar aún más la salida para una subsección. Cada subsección puede limitarse a un nivel de profundidad específico, y cada subnivel puede limitarse con límites de los primeros N elementos o umbrales. El argumento levelspec para cada uno de los limitadores de nivel listados anteriormente se utiliza para lograr esto.

Probablemente sea mejor continuar la explicación de la limitación de subniveles con la siguiente jerarquía de estilo de esquema bien conocida y algunos ejemplos básicos:

    nivel 0
       nivel 1
          nivel 2
             nivel 3
                nivel 4
                nivel 4
          nivel 2
             nivel 3
                nivel 4
                nivel 4
                nivel 4
             nivel 3
                nivel 4
       nivel 1
          nivel 2
             nivel 3
                nivel 4

La forma más simple de limitar la salida suprime toda la salida por debajo de un nivel especificado. Por ejemplo, un levelspec establecido en "2" muestra solo los datos en los niveles 0 a 2. Piense en esto como colapsar cada elemento del subnivel 2, ocultando así todos los niveles inferiores (3, 4, ...), para obtener:

    nivel 0
       nivel 1
          nivel 2
          nivel 2
       nivel 1
          nivel 2

A veces, el volumen de salida en una sección es demasiado grande y es útil suprimir cualquier dato que no supere un valor umbral determinado. Considere un ataque de diccionario de spam, que produce listas muy largas de direcciones de correo electrónico o IP que han golpeado una vez. DESCRIPTION

postfix-logwatch analyzes Postfix log files and generates reports based on their content. It can function as a standalone utility or as a module within the Logwatch(8) utility.

The utility categorizes log entries into various sections such as Summary, Detailed, Sent, Received, Rejected, etc. It aggregates counts and provides detailed breakdowns for each category.

Key features include:

  • Configurable detail levels for reports.
  • Filtering and limiting of specific log entries or categories.
  • Support for various output formats and destinations (STDOUT, file, email, syslog).
  • Integration with Logwatch for centralized log analysis.
  • Advanced filtering for reject messages, including RBL checks.

postfix-logwatch identifies log entries based on patterns and timestamps within the log files. The interpretation of log entries is influenced by the configured detail level.

For a detailed breakdown of options and their behavior, refer to the Synopsis and subsequent sections.

LEVEL LIMITERS

Level limiters are used to control the verbosity of Postfix log data that is output. They function by specifying a maximum level of detail to report, and optionally, a top-N list and/or a minimum hit count threshold. This allows for concise reports by filtering out less important information.

A levelspec is used to define these limits. For example, setting the detail level to "2::" will produce output for level 2 data, but no deeper levels. Using "2:5:" will limit level 2 data to only those entries exceeding a hit count of 5. A levelspec of "2::5" will suppress any data at level 2 that does not exceed a hit count of 5.

Perhaps producing a top N list, such as top 10 senders, is desired. A levelspec of "3:10:" limits level 3 data to only the top 10 hits.

With those simple examples out of the way, a levelspec is defined as a whitespace- or comma-separated list of one or more of the following:

l
Specifies the maximum level to be output for this sub-section, with a range from 0 to 10. if l is 0, no levels will be output, effectively disabling the sub-section (level 0 data is already provided in the Summary report, so level 1 is considered the first useful level in the Detailed report). Higher values will produce output up to and including the specified level.
l.n
Same as above, with the addition that n limits this section's level 1 output to the top n items. The value for n can be any integer greater than 1. (This form of limiting has less utility than the syntax shown below. It is provided for backwards compatibility; users are encouraged to use the syntax below).
l:n:t
This triplet specifies level l, top n, and minimum threshold t. Each of the values are integers, with l being the level limiter as described above, n being a top n limiter for the level l, and t being the threshold limiter for level l. When both n and t are specified, n has priority, allowing top n lists (regardless of threshold value). If the value of l is omitted, the specified values for n and/or t are used for all levels available in the sub-section. This permits a simple form of wildcarding (eg. place minimum threshold limits on all levels). However, specific limiters always override wildcard limiters. The first form of level limiter may be included in levelspec to restrict output, regardless of how many triplets are present.

All three forms of limiters are effective only when postfix-logwatch's detail level is 5 or greater (the Detailed section is not activated until detail is at least 5).

See the EXAMPLES section for usage scenarios.

CONFIGURATION FILE

Postfix-logwatch can read configuration settings from a configuration file. Essentially, any command line option can be placed into a configuration file, and these settings are read upon startup.

Because postfix-logwatch can run either standalone or within Logwatch, to minimize confusion, postfix-logwatch inherits Logwatch's configuration file syntax requirements and conventions. These are:

  • White space lines are ignored.
  • Lines beginning with # are ignored
  • Settings are of the form: 
            option = value
  • Spaces or tabs on either side of the = character are ignored.
  • Any value protected in double quotes will be case-preserved.
  • All other content is reduced to lowercase (non-preserving, case insensitive).
  • All postfix-logwatch configuration settings must be prefixed with "$postfix_" or postfix-logwatch will ignore them.
  • When running under Logwatch, any values not prefixed with "$postfix_" are consumed by Logwatch; it only passes to postfix-logwatch (via environment variable) settings it considers valid.
  • The values True and Yes are converted to 1, and False and No are converted to 0.
  • Order of settings is not preserved within a configuration file (since settings are passed by Logwatch via environment variables, which have no defined order).

To include a command line option in a configuration file, prefix the command line option name with the word "$postfix_". The following configuration file setting and command line option are equivalent:

        $postfix_Line_Style = Truncate
        --line_style Truncate

Level limiters are also prefixed with $postfix_, but on the command line are specified with the --limit option:

        $postfix_Sent = 2
        --limit Sent=2

The order of command line options and configuration file processing occurs as follows: 1) The default configuration file is read if it exists and no --config_file was specified on a command line. 2) Configuration files are read and processed in the order found on the command line. 3) Command line options override any options already set either via command line or from any configuration file.

Command line options are interpreted when they are seen on the command line, and later options will override previously set options. The notable exception is with limiter variables, which are interpreted in the order found, but only after all other options have been processed. This allows --reject_reply_patterns to determine the dynamic list of the various reject limiters.

See also --reject_reply_patterns.

EXIT STATUS

The postfix-logwatch utility exits with a status code of 0, unless an error occurred, in which case a non-zero exit status is returned.

EXAMPLES

Running Standalone

Note: postfix-logwatch reads its log data from one or more named Postfix log files, or from STDIN. For brevity, where required, the examples below use the word file as the command line argument meaning /path/to/postfix.log. Obviously you will need to substitute file with the appropriate path.

To run postfix-logwatch in standalone mode, simply run:

postfix-logwatch file

A complete list of options and basic usage is available via:

postfix-logwatch --help

To print a summary only report of Postfix log data:

postfix-logwatch --detail 1 file

To produce a summary report and a one-level detail report for May 25th:

grep 'May 25' file | postfix-logwatch --detail 5

To produce only a top 10 list of Sent email domains, the summary report and detailed reports are first disabled. Since commands line options are read and enabled left-to-right, the Sent section is re-enabled to level 1 with a level 1 top 10 limiter:

postfix-logwatch --nosummary --nodetail --limit sent='1 1:10:' file

Running within Logwatch

Note: Logwatch versions prior to 7.3.6, unless configured otherwise, required the --print option to print to STDOUT instead of sending reports via email. Since version 7.3.6, STDOUT is the default output destination, and the --print option has been replaced by --output stdout. Check your configuration to determine where report output will be directed, and add the appropriate option to the commands below.

To print a summary report for today's Postfix log data:

logwatch --service postfix --range today --detail 1

To print a report for today's Postfix log data, with one level
of detail in the Detailed section:

logwatch --service postfix --range today --detail 5

To print a report for yesterday, with two levels of detail in the Detailed section:

logwatch --service postfix --range yesterday --detail 6

To print a report from Dec 12th through Dec 14th, with four levels of detail in the Detailed section:

logwatch --service postfix --range \
        'between 12/12 and 12/14' --detail 8
To print a
report for today, with all levels of detail: 
logwatch --service postfix --range today --detail 10
Same as above, but leaves long lines uncut:

logwatch --service postfix --range today --detail 11

ENTORNO

El programa postfix-logwatch utiliza las siguientes variables de entorno (configuradas automáticamente) cuando se ejecuta bajo Logwatch:

LOGWATCH_DETAIL_LEVEL
Este es el nivel de detalle especificado con el argumento de línea de comandos de Logwatch --detail o la configuración Detail en el archivo de configuración ...conf/services/postfix.conf.
LOGWATCH_DEBUG
Este es el nivel de depuración especificado con el argumento de línea de comandos de Logwatch --debug.
postfix_xxx
El programa Logwatch pasa todas las configuraciones postfix_xxx en el archivo de configuración ...conf/services/postfix.conf al filtro postfix (que en realidad se llama .../scripts/services/postfix) a través de una variable de entorno.
