NOMBRE

podman-push - Envía una imagen, lista de manifiestos o índice de imágenes desde el almacenamiento local a otro lugar

SINOPSIS

podman push [opciones] imagen [destino]

podman image push [opciones] imagen [destino]

DESCRIPCIÓN

Envía una imagen, lista de manifiestos o índice de imágenes desde el almacenamiento local a un destino especificado.

Almacenamiento de imágenes

Las imágenes se envían desde las almacenadas en el almacenamiento de imágenes local.

DESTINO

DESTINO es la ubicación a la que se envía la imagen del contenedor. Admite todos los transportes de containers-transports(5). Si no se especifica ningún transporte, se utiliza el transporte docker (es decir, registro de contenedores). Para clientes remotos, incluidas las máquinas Mac y Windows (excluyendo WSL2), docker es el único transporte admitido.

# Enviar a un registro de contenedores
$ podman push quay.io/podman/stable
# Enviar a un registro de contenedores a través del transporte docker
$ podman push docker://quay.io/podman/stable
# Enviar a un registro de contenedores con otra etiqueta
$ podman push myimage quay.io/username/myimage
# Enviar a un directorio local
$ podman push myimage dir:/tmp/myimage
# Enviar a un archivo tar en formato docker-archive
$ podman push myimage docker-archive:/tmp/myimage
# Enviar a un demonio docker local
$ sudo podman push myimage docker-daemon:docker.io/library/myimage:33
# Enviar a un archivo tar en formato OCI
$ podman push myimage oci-archive:/tmp/myimage

OPCIONES

--authfile=ruta

Ruta del archivo de autenticación. Por defecto es ${XDG_RUNTIME_DIR}/containers/auth.json en Linux y $HOME/.config/containers/auth.json en Windows/macOS. El archivo se crea con podman login. Si la sesión de autorización no se encuentra allí, se comprueba $HOME/.docker/config.json, que se establece usando docker login.

Nota: También existe la opción de anular la ruta predeterminada del archivo de autenticación estableciendo la variable de entorno REGISTRY_AUTH_FILE. Esto se puede hacer con export REGISTRY_AUTH_FILE=ruta.

--cert-dir=ruta

Utiliza los certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro. (Por defecto: /etc/containers/certs.d) Para más detalles, ver containers-certs.d(5). (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--compress

Comprime las capas de la imagen en archivos tar al enviarlas a un directorio utilizando el transporte 'dir'. (El valor predeterminado es el mismo tipo de compresión, comprimido o sin comprimir, que la fuente)

Nota: Esta bandera solo se puede establecer cuando se utiliza el transporte dir

--compression-format=gzip | zstd | zstd:chunked

Especifica el formato de compresión a utilizar. Los valores admitidos son: gzip, zstd y zstd:chunked. El valor predeterminado es gzip a menos que se anule en el archivo containers.conf. zstd:chunked es incompatible con el cifrado de imágenes y se tratará como zstd con una advertencia en ese caso.

--compression-level=nivel

Especifica el nivel de compresión a utilizar. El valor es específico del algoritmo de compresión utilizado, por ejemplo, para zstd los valores aceptados están en el rango 1-20 (inclusive) con un valor predeterminado de 3, mientras que para gzip es 1-9 (inclusive) y tiene un valor predeterminado de 5.

--creds=[usuario[:contraseña]]

El [usuario[:contraseña]] a utilizar para autenticarse con el registro, si es necesario. Si no se proporcionan uno o ambos valores, aparece un mensaje en la línea de comandos y se puede introducir el valor. La contraseña se introduce sin efecto visual.

Tenga en cuenta que las credenciales especificadas solo se utilizan para autenticarse en los registros de destino. No se utilizan para espejos ni cuando el registro se reescribe (ver containers-registries.conf(5)); para autenticarse en ellos, considere usar un archivo containers-auth.json(5).

--digestfile=ArchivoDigest

Después de copiar la imagen, escribe el digest de la imagen resultante en el archivo.

--disable-content-trust

Esta es una opción específica de Docker para deshabilitar la verificación de imágenes en un registro de contenedores y no es compatible con Podman. Esta opción es un NOOP (no operation) y se proporciona únicamente para compatibilidad de scripts.

--encrypt-layer=capa(s)

Capa(s) a cifrar: índices de capas basados en 0 con soporte para indexación negativa (por ejemplo, 0 es la primera capa, -1 es la última capa). Si no se define, cifra todas las capas si se especifica la bandera encryption-key.

--encryption-key=clave

El [protocolo:archivo_clave] especifica el protocolo de cifrado, que puede ser JWE (RFC7516), PGP (RFC4880) y PKCS7 (RFC2315) y el material clave necesario para el cifrado de imágenes. Por ejemplo, jwe:/ruta/a/clave.pem o pgp:admin@example.com o pkcs7:/ruta/a/archivo/x509.

--force-compression

Si se establece, el envío utiliza el algoritmo de compresión especificado incluso si el destino contiene una variante con compresión diferente ya. Por defecto es true si se especifica explícitamente --compression-format en la línea de comandos, false en caso contrario.

--format, -f=formato

Tipo de manifiesto (oci, v2s2 o v2s1) a utilizar al enviar una imagen.

--quiet, -q

Al escribir la imagen de salida, suprimir la salida de progreso

--remove-signatures

Descarta cualquier firma preexistente en la imagen.

--retry=intentos

Número de veces que se intentará volver a descargar o enviar imágenes entre el registro y el almacenamiento local en caso de fallo. Por defecto es 3.

--retry-delay=duración

Duración del retraso entre intentos de reintento al descargar o enviar imágenes entre el registro y el almacenamiento local en caso de fallo. El valor predeterminado es empezar con dos segundos y luego retroceder exponencialmente. El retraso se utiliza cuando se establece este valor y no se produce ninguna retroceso exponencial.

--sign-by=clave

Añade una firma de "firma simple" en el destino utilizando la clave especificada. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sign-by-sigstore=archivo_param

Añade una firma sigstore basada en opciones adicionales especificadas en un archivo de parámetros de firma sigstore de contenedor archivo_param. Ver containers-sigstore-signing-params.yaml(5) para detalles sobre el formato del archivo.

--sign-by-sigstore-private-key=ruta

Añade una firma sigstore en el destino utilizando una clave privada en la ruta especificada. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sign-by-sq-fingerprint=huella_digital

Añade una firma de "firma simple" utilizando una clave Sequoia-PGP con la huella digital especificada. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sign-passphrase-file=ruta

Si firma la imagen (usando --sign-by, sign-by-sq-fingerprint o --sign-by-sigstore-private-key), lee la frase de contraseña a utilizar desde la ruta especificada.

--tls-verify

Requiere HTTPS y verifica certificados al contactar con los registros (por defecto: true). Si se establece explícitamente en true, se utiliza la verificación TLS. Si se establece en fal

se, no se utiliza la verificación TLS. Si no se especifica, se utiliza la verificación TLS a menos que el registro de destino esté listado como un registro inseguro en containers-registries.conf(5)

EJEMPLOS

Empuja la imagen especificada a un directorio local:

# podman push imageID dir:/path/to/image

Empuja la imagen especificada a un directorio local en formato OCI:

# podman push imageID oci-archive:/path/to/layout:image:tag

Empuja la imagen especificada a un registro de contenedores:

# podman push imageID docker://registry.example.com/repository:tag

Empuja la imagen especificada a un registro de contenedores y guarda el digest en el archivo especificado:

# podman push --digestfile=/tmp/mydigest imageID docker://registry.example.com/repository:tag

Empuja la imagen especificada al almacén de contenedores del daemon Docker local:

# podman push imageID docker-daemon:image:tag

Empuja la imagen especificada con un nombre de imagen diferente utilizando credenciales de una ruta de archivo de autenticación alternativa:

# podman push --authfile temp-auths/myauths.json alpine docker://docker.io/umohnani/alpine
