POSIX_TRACE_CREATE(3P) Manual del programador POSIX POSIX_TRACE_CREATE(3P)

PRÓLOGO

Esta página del manual es parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

posix_trace_create, posix_trace_create_withlog, posix_trace_flush, posix_trace_shutdown — inicialización, vaciado y cierre de secuencias de rastreo desde un proceso (Rastreo)

SINOPSIS

#include <sys/types.h>
#include <trace.h>
int posix_trace_create(pid_t pid,
    const trace_attr_t *restrict attr,
    trace_id_t *restrict trid);
int posix_trace_create_withlog(pid_t pid,
    const trace_attr_t *restrict attr, int file_desc,
    trace_id_t *restrict trid);
int posix_trace_flush(trace_id_t trid);
int posix_trace_shutdown(trace_id_t trid);

DESCRIPCIÓN

La función posix_trace_create() creará una secuencia de rastreo activa. Asigna todos los recursos necesarios para la secuencia de rastreo que se está creando para rastrear el proceso especificado por pid de acuerdo con el argumento attr. El argumento attr representa los atributos iniciales de la secuencia de rastreo y debe haber sido inicializado por la función posix_trace_attr_init() antes de la llamada a posix_trace_create(). Si el argumento attr es NULL, se utilizarán los atributos predeterminados. El objeto de atributos attr se manipulará a través de un conjunto de funciones descritas en la familia de funciones posix_trace_attr. Si los atributos del objeto apuntado por attr se modifican posteriormente, los atributos de la secuencia de rastreo no se verán afectados. El atributo creation-time de la secuencia de rastreo recién creada se establecerá en el valor del reloj del sistema, si la opción Timers no es compatible, o en el valor del reloj CLOCK_REALTIME, si la opción Timers es compatible.

El argumento pid representa el proceso objetivo a rastrear. Si el proceso que ejecuta esta función no tiene los privilegios adecuados para rastrear el proceso identificado por pid, se devolverá un error. Si el argumento pid es cero, se rastreará el proceso que llama.

La función posix_trace_create() almacenará el identificador de la secuencia de rastreo de la nueva secuencia en el objeto apuntado por el argumento trid. Este identificador de secuencia de rastreo se utilizará en llamadas posteriores para controlar el rastreo. El argumento trid solo puede ser utilizado por las siguientes funciones:

posix_trace_clear() posix_trace_eventid_equal() posix_trace_eventid_get_name() posix_trace_eventtypelist_getnext_id() posix_trace_eventtypelist_rewind() posix_trace_get_attr() posix_trace_get_status() posix_trace_getnext_event() posix_trace_shutdown() posix_trace_start() posix_trace_stop() posix_trace_timedgetnext_event() posix_trace_trid_eventid_open() posix_trace_trygetnext_event()

Si la opción de Filtro de Eventos de Rastreo es compatible, las siguientes funciones adicionales pueden usar el argumento trid:

posix_trace_get_filter() posix_trace_set_filter()

En particular, nótese que las operaciones normalmente utilizadas por un proceso analizador de rastreo, como posix_trace_rewind() o posix_trace_close(), no pueden invocarse utilizando el identificador de la secuencia de rastreo devuelto por la función posix_trace_create().

Se creará una secuencia de rastreo en estado suspendido. Si la opción Filtro de Eventos de Rastreo es compatible, su filtro de tipos de eventos de rastreo estará vacío.

La función posix_trace_create() puede ser llamada múltiples veces desde el mismo o diferente proceso, con el límite del sistema indicado por el valor invariante en tiempo de ejecución {TRACE_SYS_MAX}, que tiene el valor mínimo {_POSIX_TRACE_SYS_MAX}.

El identificador de la secuencia de rastreo devuelto por la función posix_trace_create() en el argumento apuntado por trid es válido solo en el proceso que realizó la llamada a la función. Si se utiliza desde otro proceso, que sea un proceso hijo, en las funciones definidas en POSIX.1‐2008, estas funciones devolverán con el error [EINVAL].

La función posix_trace_create_withlog() será equivalente a posix_trace_create(), excepto que asocia un registro de rastreo con esta secuencia. El argumento file_desc será el descriptor de archivo que designa el destino del registro de rastreo. La función fallará si este descriptor de archivo se refiere a un archivo con un tipo de archivo que no es compatible con la política de registro asociada con el registro de rastreo. La lista de los tipos de archivo apropiados que son compatibles con cada política de registro es específica de la implementación.

La función posix_trace_create_withlog() devolverá en el parámetro apuntado por trid el identificador de la secuencia de rastreo, que identifica de forma única la secuencia de rastreo recién creada, y se utilizará en llamadas posteriores para controlar el rastreo. El argumento trid solo puede ser utilizado por las siguientes funciones:

posix_trace_clear() posix_trace_eventid_equal() posix_trace_eventid_get_name() posix_trace_eventtypelist_getnext_id() posix_trace_eventtypelist_rewind() posix_trace_flush() posix_trace_get_attr() posix_trace_get_status() posix_trace_getnext_event() posix_trace_shutdown() posix_trace_start() posix_trace_stop() posix_trace_timedgetnext_event() posix_trace_trid_eventid_open()

Si la opción de Filtro de Eventos de Rastreo es compatible, las siguientes funciones adicionales pueden usar el argumento trid:

posix_trace_get_filter() posix_trace_set_filter()

En particular, nótese que las operaciones normalmente utilizadas por un proceso analizador de rastreo, como posix_trace_rewind() o posix_trace_close(), no pueden invocarse utilizando el identificador de la secuencia de rastreo devuelto por la función posix_trace_create_withlog().

La función posix_trace_flush() iniciará una operación de vaciado que copiará el contenido de la secuencia de rastreo identificada por el argumento trid en el registro de rastreo asociado con la secuencia de rastreo en el momento de la creación. Si no se ha asociado ningún registro de rastreo con la secuencia de rastreo apuntada por trid, esta función devolverá un error. La finalización de la operación de vaciado puede ser consultada mediante la función posix_trace_get_status(). Durante la operación de vaciado, se podrán rastrear nuevos eventos de rastreo hasta el punto en que la secuencia de rastreo se llene. Después de que se complete el vaciado, el espacio utilizado por los eventos de rastreo vaciados estará disponible para rastrear nuevos eventos.

Si el vaciado de la secuencia de rastreo provoca que el registro de rastreo resultante se llene, se aplicará la política de registro lleno:

POSIX_TRACE_UNTIL_FULL

Los eventos de rastreo que aún no se han vaciado se descartarán.
POSIX_TRACE_LOOP

Los eventos de rastreo que aún no se han vaciado se escribirán al principio del registro de rastreo, sobrescribiendo los eventos de rastreo anteriores almacenados allí.
POSIX_TRACE_APPEND

Los eventos de rastreo que aún no se han vaciado se añadirán al registro de rastreo.

La función posix_trace_shutdown() detendrá el rastreo de eventos de rastreo en la secuencia de rastreo identificada por trid, como si se hubiera invocado posix_trace_stop(). La función posix_trace_shutdown() liberará todos los recursos asociados con la secuencia de rastreo.

La función posix_trace_shutdown() no devolverá hasta que se hayan liberado todos los recursos asociados con la secuencia de rastreo. Cuando la función posix_trace_shutdown() devuelve, el argumento trid se convierte en un identificador de secuencia de rastreo inválido. Una llamada a esta función desasignará incondicionalmente los recursos independientemente de si el proceso analizador ha recuperado todos los eventos de rastreo. PROLOG

This page is a manual page for the POSIX trace functions.

NAME

posix_trace_create, posix_trace_create_withlog, posix_trace_flush, posix_trace_shutdown - trace control functions

SYNOPSIS

#include <trace.h>

int posix_trace_create(pid_t pid, const struct posix_trace_attr_t *attr, trace_id_t *trid);

int posix_trace_create_withlog(pid_t pid, const struct posix_trace_attr_t *attr, int file_desc, trace_id_t *trid);

int posix_trace_flush(trace_id_t trid);

int posix_trace_shutdown(trace_id_t trid);

DESCRIPTION

The POSIX trace facility provides a means to record trace events generated by a traced process. The trace events are stored in a trace log, which can be retrieved later.

The posix_trace_create() function shall create a trace stream for the process specified by pid. The attributes of the trace stream shall be initialized according to the attr parameter. If attr is NULL, the default trace stream attributes shall be used. The trace stream identifier shall be returned in the object pointed to by trid.

The posix_trace_create_withlog() function shall be equivalent to posix_trace_create(), except that the trace events shall be logged to the file descriptor specified by file_desc. The file descriptor shall be associated with a file that is open for writing.

The posix_trace_flush() function shall cause all trace events that have not yet been flushed to the trace log to be written to the trace log. The trace stream shall remain active after this call.

The posix_trace_shutdown() function shall cause all trace events that have not yet been flushed to the trace log to be written to the trace log, as in the posix_trace_flush() function, and the trace stream shall be closed. After this call, the trace stream identifier is no longer valid.

If the process exits, invokes a member of the exec family of functions, or is terminated, the trace streams that the process had created and that have not yet been shut down, shall be automatically shut down as if an explicit call were made to the posix_trace_shutdown() function.

For an active trace stream with log, when the posix_trace_shutdown() function is called, all trace events that have not yet been flushed to the trace log shall be flushed, as in the posix_trace_flush() function, and the trace log shall be closed.

When a trace log is closed, all the information that may be retrieved later from the trace log through the trace interface shall have been written to the trace log. This information includes the trace attributes, the list of trace event types (with the mapping between trace event names and trace event type identifiers), and the trace status.

In addition, unspecified information shall be written to the trace log to allow detection of a valid trace log during the posix_trace_open() operation.

The posix_trace_shutdown() function shall not return until all trace events have been flushed.

RETURN VALUE

Upon successful completion, these functions shall return a value of zero. Otherwise, they shall return the corresponding error number.

The posix_trace_create() and posix_trace_create_withlog() functions store the trace stream identifier value in the object pointed to by trid, if successful.

ERRORS

The posix_trace_create() and posix_trace_create_withlog() functions shall fail if:

EAGAIN
No more trace streams can be started now. {TRACE_SYS_MAX} has been exceeded.
EINTR
The operation was interrupted by a signal. No trace stream was created.
EINVAL
One or more of the trace parameters specified by the attr parameter is invalid.
ENOMEM
The implementation does not currently have sufficient memory to create the trace stream with the specified parameters.
EPERM
The caller does not have appropriate privileges to trace the process specified by pid.
ESRCH
The pid argument does not refer to an existing process.

The posix_trace_create_withlog() function shall fail if:

EBADF
The file_desc argument is not a valid file descriptor open for writing.
EINVAL
The file_desc argument refers to a file with a file type that does not support the log policy associated with the trace log.
ENOSPC
No space left on device. The device corresponding to the argument file_desc does not contain the space required to create this trace log.

The posix_trace_flush() and posix_trace_shutdown() functions shall fail if:

EINVAL
The value of the trid argument does not correspond to an active trace stream with log.
EFBIG
The trace log file has attempted to exceed an implementation-defined maximum file size.
ENOSPC
No space left on device.
