NOMBRE

podman-push - Empuja una imagen, lista de manifiestos o índice de imágenes desde el almacenamiento local a otro lugar

SINOPSIS

podman push [opciones] imagen [destino]

podman image push [opciones] imagen [destino]

DESCRIPCIÓN

Empuja una imagen, lista de manifiestos o índice de imágenes desde el almacenamiento local a un destino especificado.

Almacenamiento de imágenes

Las imágenes se empujan desde las almacenadas en el almacenamiento de imágenes local.

DESTINO

DESTINO es la ubicación a la que se empuja la imagen del contenedor. Soporta todos los transportes de containers-transports(5). Si no se especifica transporte, se utiliza el transporte docker (es decir, registro de contenedores). Para clientes remotos, incluidas las máquinas Mac y Windows (excluyendo WSL2), docker es el único transporte soportado.

# Empujar a un registro de contenedores
$ podman push quay.io/podman/stable
# Empujar a un registro de contenedores a través del transporte docker
$ podman push docker://quay.io/podman/stable
# Empujar a un registro de contenedores con otra etiqueta
$ podman push myimage quay.io/username/myimage
# Empujar a un directorio local
$ podman push myimage dir:/tmp/myimage
# Empujar a un archivo tar en formato docker-archive
$ podman push myimage docker-archive:/tmp/myimage
# Empujar a un demonio docker local
$ sudo podman push myimage docker-daemon:docker.io/library/myimage:33
# Empujar a un archivo tar en formato OCI
$ podman push myimage oci-archive:/tmp/myimage

OPCIONES

--authfile=ruta

Ruta del archivo de autenticación. Por defecto es ${XDG_RUNTIME_DIR}/containers/auth.json en Linux, y $HOME/.config/containers/auth.json en Windows/macOS. El archivo es creado por podman login. Si el estado de autorización no se encuentra allí, se busca en $HOME/.docker/config.json, que se establece usando docker login.

Nota: También existe la opción de anular la ruta predeterminada del archivo de autenticación estableciendo la variable de entorno REGISTRY_AUTH_FILE. Esto se puede hacer con export REGISTRY_AUTH_FILE=ruta.

--cert-dir=ruta

Utiliza certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro. (Predeterminado: /etc/containers/certs.d) Para más detalles, ver containers-certs.d(5). (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--compress

Comprime las capas de imágenes en archivos tar al empujar a un directorio usando el transporte 'dir'. (El valor predeterminado es el mismo tipo de compresión, comprimido o sin comprimir, que la fuente)

Nota: Esta bandera solo se puede establecer al usar el transporte dir

--compression-format=gzip | zstd | zstd:chunked

Especifica el formato de compresión a utilizar. Los valores soportados son: gzip, zstd y zstd:chunked. El valor predeterminado es gzip a menos que se anule en el archivo containers.conf. zstd:chunked es incompatible con el cifrado de imágenes, y se tratará como zstd con una advertencia en ese caso.

--compression-level=nivel

Especifica el nivel de compresión a utilizar. El valor es específico para el algoritmo de compresión utilizado, por ejemplo, para zstd los valores aceptados están en el rango 1-20 (inclusive) con un valor predeterminado de 3, mientras que para gzip es 1-9 (inclusive) y tiene un valor predeterminado de 5.

--creds=[usuario[:contraseña]]

El [usuario[:contraseña]] a utilizar para autenticarse con el registro, si es necesario. Si no se proporcionan uno o ambos valores, aparece un aviso en la línea de comandos y se puede introducir el valor. La contraseña se introduce sin eco.

Tenga en cuenta que las credenciales especificadas solo se utilizan para autenticarse contra los registros de destino. No se utilizan para espejos ni cuando el registro se reescribe (ver containers-registries.conf(5)); para autenticarse contra ellos considere usar un archivo containers-auth.json(5) .

--digestfile=ArchivoDigest

Después de copiar la imagen, escribe el digest de la imagen resultante en el archivo.

--disable-content-trust

Esta es una opción específica de Docker para deshabilitar la verificación de imágenes a un registro de contenedores y no está soportada por Podman. Esta opción es un NOOP y se proporciona únicamente para compatibilidad de scripts.

--encrypt-layer=capa(s)

Capa(s) a cifrar: índices de capas 0-basados con soporte para indexación negativa (por ejemplo, 0 es la primera capa, -1 es la última capa). Si no se define, cifra todas las capas si se especifica la bandera encryption-key.

--encryption-key=clave

El [protocolo:archivo_clave] especifica el protocolo de cifrado, que puede ser JWE (RFC7516), PGP (RFC4880) y PKCS7 (RFC2315) y el material clave requerido para el cifrado de imágenes. Por ejemplo, jwe:/ruta/a/key.pem o pgp:admin@example.com o pkcs7:/ruta/a/archivo-x509.

--force-compression

Si se establece, el push utiliza el algoritmo de compresión especificado aunque el destino ya contenga una variante comprimida de forma diferente. Por defecto es true si --compression-format se especifica explícitamente en la línea de comandos, false en caso contrario.

--format, -f=formato

Tipo de manifiesto (oci, v2s2, o v2s1) a utilizar al empujar una imagen.

--quiet, -q

Al escribir la imagen de salida, suprime la salida del progreso

--remove-signatures

Descarta cualquier firma preexistente en la imagen.

--retry=intentos

Número de veces que se intentará descargar o empujar imágenes entre el registro y el almacenamiento local en caso de fallo. El valor predeterminado es 3.

--retry-delay=duración

Duración del retraso entre intentos de reintento al descargar o empujar imágenes entre el registro y el almacenamiento local en caso de fallo. El valor predeterminado es empezar a los dos segundos y luego retroceder exponencialmente. El retraso se utiliza cuando este valor está establecido, y no se produce retroceso exponencial.

--sign-by=clave

Añade una firma de "firma simple" en el destino usando la clave especificada. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sign-by-sigstore=archivo-param

Añade una firma sigstore basada en opciones adicionales especificadas en un archivo de parámetros de firma sigstore de un contenedor archivo-param. Ver containers-sigstore-signing-params.yaml(5) para detalles sobre el formato del archivo.

--sign-by-sigstore-private-key=ruta

Añade una firma sigstore en el destino utilizando una clave privada en la ruta especificada. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sign-by-sq-fingerprint=huella_digital

Añade una firma de "firma simple" utilizando una clave Sequoia-PGP con la huella digital especificada. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sign-passphrase-file=ruta

Si se firma la imagen (usando --sign-by, sign-by-sq-fingerprint o --sign-by-sigstore-private-key), lee la contraseña a utilizar desde la ruta especificada.

EJEMPLOS

Empujar la imagen especificada a un directorio local:

# podman push imageID dir:/ruta/a/imagen

Empujar la imagen especificada a un directorio local en formato OCI:

# podman push imageID oci-archive:/ruta/al/layout:imagen:etiqueta

Empujar la imagen especificada a un registro de contenedores:

# podman push imageID docker://registro.ejemplo.com/repositorio:etiqueta

Empujar la imagen especificada a un registro de contenedores y guardar el digest en el archivo especificado:

# podman push --digestfile=/tmp/midigest imageID docker://registro.ejemplo.com/repositorio:etiqueta

Empujar la imagen especificada al almacén de contenedores del demonio Docker local:

# podman push imageID docker-daemon:imagen:etiqueta

Empujar la imagen especificada con un nombre de imagen diferente utilizando credenciales de una ruta de archivo de autenticación alternativa:

# podman push --authfile temp-auths/myauths.json alpine docker://docker.io/umohnani/alpine
