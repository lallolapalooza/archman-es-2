POSTMULTI(1) Manual de Comandos Generales POSTMULTI(1)

NOMBRE

postmulti - gestor de instancias múltiples de Postfix

SINOPSIS

Habilitar la gestión de instancias múltiples:

postmulti -e init [-v]

Modo iterador:

postmulti -l [-aRv] [-g grupo] [-i nombre]

postmulti -p [-av] [-g grupo] [-i nombre] comando-postfix...

postmulti -x [-aRv] [-g grupo] [-i nombre] comando-unix...

Gestión del ciclo de vida:

postmulti -e create [-av] [-g grupo] [-i nombre] [-G grupo] [-I nombre] [param=valor ...]

postmulti -e import [-av] [-g grupo] [-i nombre] [-G grupo] [-I nombre] [directorio_configuracion=/ruta]

postmulti -e destroy [-v] -i nombre

postmulti -e deport [-v] -i nombre

postmulti -e enable [-v] -i nombre

postmulti -e disable [-v] -i nombre

postmulti -e assign [-v] -i nombre [-I nombre] [-G grupo]

DESCRIPCIÓN


El comando postmulti(1) permite a un administrador de Postfix gestionar múltiples instancias de Postfix en un mismo host.

postmulti(1) implementa dos modos fundamentales de operación. En modo iterador, ejecuta el mismo comando para múltiples instancias de Postfix. En modo de gestión del ciclo de vida, añade o elimina una instancia, o cambia el estado de instancia múltiple de una instancia.

Cada modo de operación tiene su propia sintaxis de comando. Por esta razón, cada modo se documenta en secciones separadas a continuación.

ANTECEDENTES

Una configuración de instancias múltiples consiste en una instancia primaria de Postfix y una o más instancias secundarias cuyas rutas de directorios de configuración se registran en el archivo main.cf de la instancia primaria. Las instancias de Postfix comparten archivos de programas y documentación, pero tienen sus propios directorios de configuración, colas y datos.

Actualmente, solo la instancia primaria de Postfix puede ser utilizada como instancia primaria en una configuración de instancias múltiples. El comando postmulti(1) no soporta actualmente la opción -c para seleccionar una instancia primaria alternativa y sale con un error fatal si la variable de entorno MAIL_CONFIG está establecida a un directorio de configuración no predeterminado.

Consulta el tutorial MULTI_INSTANCE_README para una discusión más detallada sobre la gestión de instancias múltiples con postmulti(1).

MODO ITERADOR

En modo iterador, postmulti realiza la misma operación en todas las instancias de Postfix por turno.

Si el soporte de instancias múltiples no está habilitado, el comando solicitado se realiza solo para la instancia primaria.

El modo iterador implementa las siguientes opciones de comando:

Selección de instancia

-a
Realiza la operación en todas las instancias. Este es el valor predeterminado.
-g grupo
Realiza la operación solo para los miembros del grupo con nombre.
-i nombre
Realiza la operación solo para la instancia con el nombre especificado. Puedes especificar tanto el nombre de la instancia como la ruta absoluta del directorio de configuración de la instancia. Especifica "-" para seleccionar la instancia primaria de Postfix.
-R
Invierte el orden de iteración. Esto puede ser apropiado al actualizar un sistema de instancias múltiples, donde las instancias de "sumidero" se inician antes que las instancias de "fuente".

Esta opción no se puede usar con -p.

Modo lista

-l
Lista las instancias de Postfix con su nombre de instancia, nombre de grupo de instancia, estado de habilitación/deshabilitación y directorio de configuración.

Modo envoltorio de Postfix

-p comando-postfix
Invoca postfix(1) para ejecutar comando-postfix. Esta opción implementa la interfaz de postfix-wrapper(5).
  • Con comandos tipo "start", se ejecuta "postfix check" para las instancias que no están habilitadas. La lista completa de comandos se especifica con el parámetro postmulti_start_commands.
  • Con comandos tipo "stop", se invierte el orden de iteración y se omiten las instancias deshabilitadas. La lista completa de comandos se especifica con el parámetro postmulti_stop_commands.
  • Con "reload" y otros comandos que requieren una instancia iniciada, se omiten las instancias deshabilitadas. La lista completa de comandos se especifica con el parámetro postmulti_control_commands.
  • Con "status" y otros comandos que no requieren una instancia iniciada, el comando se ejecuta para todas las instancias.
La opción -p también se puede usar interactivamente para iniciar/detener/etc. una instancia o grupo de instancias con nombre. Por ejemplo, para iniciar solo las instancias del grupo "msa", invoca postmulti(1) de la siguiente manera:
# postmulti -g msa -p start

Modo comando

-x comando-unix
Ejecuta el comando-unix especificado para todas las instancias de Postfix. El comando se ejecuta con la configuración de entorno apropiada para MAIL_CONFIG, command_directory, daemon_directory, config_directory, queue_directory, data_directory, multi_instance_name, multi_instance_group y multi_instance_enable.

Otras opciones

-v
Habilita el registro detallado con fines de depuración. Múltiples opciones -v hacen que el software sea cada vez más detallado.

MODO GESTIÓN DEL CICLO DE VIDA

Con la opción -e, postmulti(1) se puede utilizar para añadir o eliminar una instancia de Postfix, y para gestionar el estado de instancia múltiple de una instancia existente.

Se implementan las siguientes opciones:

Selección de instancia existente

-a
Al crear o importar una instancia, coloca la nueva instancia al principio de la lista de instancias secundarias.
-g grupo
Al crear o importar una instancia, coloca la nueva instancia antes de la primera instancia secundaria que sea miembro del grupo especificado.
-i nombre
Al crear o importar una instancia, coloca la nueva instancia antes de la instancia secundaria coincidente.

Con otras operaciones del ciclo de vida, aplica la operación a la instancia existente con nombre. Especifica "-" para seleccionar la instancia primaria de Postfix.

Asignación de nombre de instancia nueva o existente

-I nombre
Asigna el nombre especificado a la instancia que se está creando o importando. Con la opción -e assign, se asigna el nombre especificado a la instancia existente.

Creación o importación de instancia

-e create
Crea una nueva instancia de Postfix. La instancia se crea en la ubicación especificada por el parámetro `data_directory` o se genera una ruta predeterminada. La nueva instancia se añade al final de la lista de instancias secundarias. Por defecto, la nueva instancia se coloca al principio de la lista.
-e import
Importa una instancia de Postfix existente para su gestión por parte de postmulti(1). La instancia debe existir en la ubicación especificada por el parámetro `config_directory`. Si no se proporciona `config_directory`, se utiliza el valor predeterminado de la variable de entorno MAIL_CONFIG.

Destrucción o deportación de instancia

-e destroy
Destruye la instancia de Postfix especificada con -i. Esto elimina el directorio de configuración de la instancia, el directorio de colas y el directorio de datos. No se puede utilizar para destruir la instancia primaria.
-e deport
Saca la instancia de Postfix especificada con -i de la gestión de instancias múltiples. El directorio de configuración de la instancia se deja intacto.

Habilitación o deshabilitación de instancia

-e enable
Habilita la instancia especificada con -i para su uso en una configuración de instancias múltiples.
-e disable
Deshabilita la instancia especificada con -i para su uso en una configuración de instancias múltiples.

Asignación de instancia a grupo

-e assign
Asigna la instancia especificada con -i al grupo especificado con -G. Si se especifica -I, la instancia con ese nombre pasa a formar parte del grupo.

Parámetros de instancia adicionales

Las siguientes opciones se utilizan al crear o importar una instancia:

-G group
Asigna la nueva instancia al group especificado. Los grupos se utilizan para agrupar instancias para operaciones específicas, como el inicio o la detención.
-I name
Asigna el name especificado a la nueva instancia. Este nombre se utiliza para identificar la instancia en operaciones posteriores.
param=value
Establece el parámetro de configuración de Postfix param al valor value para la instancia que se está creando o importando. Esto se puede especificar varias veces para establecer múltiples parámetros de configuración.

EJEMPLOS

Crear una nueva instancia llamada "backup" en el directorio /var/spool/postfix/backup:

# postmulti -I backup -i backup -G backup \ -e create config_directory=/var/spool/postfix/backup,
daemon_directory=/usr/lib/postfix,
data_directory=/var/lib/postfix/backup,
mail_owner=_postfix,
mail_group=_postdrop,
setgid_group=_postdrop

Listar todas las instancias de Postfix:

# postmulti -l

Iniciar todas las instancias de Postfix:

# postmulti -p start

Detener todas las instancias de Postfix:

# postmulti -p stop

Recargar la configuración de todas las instancias de Postfix:

# postmulti -p reload

Mostrar el estado de todas las instancias de Postfix:

# postmulti -p status

Verificar la configuración de todas las instancias de Postfix:

# postmulti -p check

Destruir la instancia "backup":

# postmulti -i backup -e destroy

Importar una instancia existente en /etc/postfix-test:

# postmulti -i test -e import config_directory=/etc/postfix-test

Habilitar la instancia "test":

# postmulti -i test -e enable

Deshabilitar la instancia "test":

# postmulti -i test -e disable

Asignar la instancia "test" al grupo "qa" y nombrar la instancia como "test01":

# postmulti -i test -e assign -G qa -I test01

OPTIONS

-I nombre
Asigna el nombre de instancia especificado a una instancia existente, recién creada o importada. Los nombres de instancia distintos de "-" (que hace que la instancia sea "sin nombre") deben comenzar con "postfix-". Esta restricción reduce la probabilidad de colisiones de nombres con archivos del sistema.
-G grupo
Asigna el nombre de grupo especificado a una instancia existente o a una instancia recién creada o importada.

Creación/eliminación/cambio de estado de instancias

-e acción
Edita instancias gestionadas. Las siguientes acciones son compatibles:
init
Este comando es necesario antes de que postmulti(1) pueda usarse para gestionar instancias de Postfix. El comando "postmulti -e init" actualiza el archivo main.cf de la instancia principal estableciendo:
multi_instance_wrapper =
        ${command_directory}/postmulti -p --
multi_instance_enable = yes
Puedes configurar esto por otros medios si lo prefieres.
create
Crea una nueva instancia de Postfix y la añade al parámetro multi_instance_directories de la instancia principal. Se recomienda la opción "-I nombre" para dar a la instancia un nombre corto que se utiliza para construir valores predeterminados para los directorios privados de la nueva instancia. La opción "-G grupo" puede especificarse para asignar la instancia a un grupo; de lo contrario, la nueva instancia no pertenece a ningún grupo.

El archivo main.cf de la nueva instancia es el archivo main.cf base con los parámetros que especifican las ubicaciones de los archivos compartidos clonados de la instancia principal. Para las instancias "sin nombre", debes ajustar manualmente "syslog_name" para obtener un "logtag" único que comience con "postfix-" que identificará de forma única la instancia en los registros de correo. Es más sencillo asignar a la instancia un nombre corto con la opción "-I nombre".

Los argumentos opcionales "nombre=valor" especifican el directorio de configuración (`config_directory`), el directorio de cola (`queue_directory`) y el directorio de datos (`data_directory`) de la instancia. Por ejemplo:

# postmulti -I postfix-mumble \
        -G mygroup -e create \
        config_directory=/my/config/dir \
        queue_directory=/my/queue/dir \
        data_directory=/my/data/dir
Si alguna de estas rutas no se proporciona, el programa intenta generar las rutas faltantes tomando la ruta correspondiente de la instancia principal y reemplazando el último componente de la ruta por el valor de la opción -I.

Si el directorio de configuración de la instancia ya existe y contiene archivos `main.cf` y `master.cf`, create "importará" la instancia tal cual. Para instancias existentes, create e import son idénticos.

import
Importa una instancia existente a la lista de instancias gestionadas por el gestor de instancias múltiples postmulti(1). Esto añade la instancia a la lista `multi_instance_directories` de la instancia principal. Si se proporciona la opción "-I nombre", especifica el nuevo nombre de la instancia y se utiliza para definir una ubicación predeterminada para el directorio de configuración de la instancia (como con create anteriormente). La opción "-G grupo" puede usarse para asignar la instancia a un grupo. Añade un argumento "config_directory=/ruta" para anular una ruta predeterminada basada en "-I nombre".
destroy
Destruye una instancia secundaria de Postfix. Para ser candidata a la destrucción, una instancia debe estar deshabilitada, detenida y su cola no debe contener ningún mensaje. Los intentos de destruir la instancia principal de Postfix generan un error fatal, sin destruir la instancia.

La instancia se elimina del parámetro `alternate_config_directories` del archivo `main.cf` de la instancia principal y sus directorios de datos, cola y configuración se limpian de archivos y directorios creados por el sistema Postfix. Los archivos `main.cf` y `master.cf` se eliminan del directorio de configuración, incluso si se han modificado desde su creación inicial. Finalmente, la instancia es "deportada" de la lista de instancias gestionadas.

Si hay otros archivos presentes en los directorios privados de la instancia, es posible que los directorios no se eliminen por completo; se registrará una advertencia para alertar al administrador. Se espera que una instancia creada con directorios "frescos" a través de la acción create sea eliminada por completo por la acción destroy (si primero se deshabilita). Si los directorios de configuración y cola de la instancia se pueblan con archivos adicionales (tablas de acceso y reescritura, contenido de la cárcel chroot, etc.), los directorios de la instancia no se eliminarán por completo.

La acción destroy activa operaciones de eliminación de archivos potencialmente peligrosas. Asegúrate de que los directorios de datos, cola y configuración de la instancia estén configurados correctamente y no contengan ningún archivo valioso.

deport
Exporta una instancia secundaria de la lista de instancias gestionadas. Esto elimina el directorio de configuración de la instancia de la lista `multi_instance_directories` de la instancia principal, pero no elimina ningún archivo o directorio.
assign
Asigna un nuevo nombre de instancia o un nuevo nombre de grupo a la instancia seleccionada. Utiliza "-G -" para especificar "sin grupo" y "-I -" para especificar "sin nombre". Si decides hacer una instancia "sin nombre", configura un `syslog_name` adecuado en el archivo `main.cf` correspondiente.
enable
Marca la instancia seleccionada como habilitada. Esto simplemente establece el parámetro `multi_instance_enable` a "yes" en el archivo `main.cf` de la instancia.
disable
Marca la instancia seleccionada como deshabilitada. Esto significa que la instancia no se iniciará con "postfix start", "postmulti -p start" y similares. La instancia aún se puede iniciar con "postfix -c config-directory start".

Otras opciones

-v
Habilita el registro detallado con fines de depuración. Múltiples opciones -v hacen que el software sea cada vez más detallado.

ENTORNO

El comando postmulti(1) exporta las siguientes variables de entorno antes de ejecutar el comando solicitado para una instancia dada:

MAIL_VERBOSE
Se establece cuando está presente la opción de línea de comandos -v.
MAIL_CONFIG
La ubicación del directorio de configuración de la instancia.

PARÁMETROS DE CONFIGURACIÓN

config_directory (ver la salida de 'postconf -d')
La ubicación predeterminada de los archivos de configuración main.cf y master.cf de Postfix.
daemon_directory (ver la salida de 'postconf -d')
El directorio con los programas de soporte y demonios de Postfix.
import_environment (ver la salida de 'postconf -d')
La lista de variables de entorno que un proceso privilegiado de Postfix importará de un proceso padre que no sea de Postfix, o anulaciones de entorno nombre=valor.
multi_instance_directories (vacío)
Una lista opcional de directorios de configuración de Postfix no predeterminados; estos directorios pertenecen a instancias adicionales de Postfix que comparten los archivos ejecutables y la documentación de Postfix con la instancia predeterminada de Postfix, y que se inician, detienen, etc., junto con la instancia predeterminada de Postfix.
multi_instance_group (vacío)
El nombre opcional del grupo de instancias de esta instancia de Postfix.
multi_instance_name (vacío)
El nombre opcional de la instancia de esta instancia de Postfix.
multi_instance_enable (no)
Permite que esta instancia de Postfix sea iniciada, detenida, etc., por un gestor de instancias múltiples.
postmulti_start_commands (start)
Los comandos de postfix(1) que el gestor de instancias postmulti(1) trata como comandos de "inicio".
postmulti_stop_commands (ver la salida de 'postconf -d')
Los comandos de postfix(1) que el gestor de instancias postmulti(1) trata como comandos de "parada".
postmulti_control_commands (reload flush)
Los comandos de postfix(1) que el gestor de instancias postmulti(1) trata como comandos de "control", que operan sobre instancias en ejecución.
syslog_facility (mail)
La instalación de syslog para el registro de Postfix.

PARÁMETROS DE CONFIGURACIÓN

meta_directory (ver salida de 'postconf -d')
La ubicación de los archivos no ejecutables que se comparten entre múltiples instancias de Postfix, como postfix-files, dynamicmaps.cf y los archivos plantilla de instancia múltiple main.cf.proto y master.cf.proto.
shlib_directory (ver salida de 'postconf -d')
La ubicación de las bibliotecas enlazadas dinámicamente de Postfix (libpostfix-*.so), y la ubicación por defecto de los plugins de base de datos de Postfix (postfix-*.so) que tienen una ruta relativa en el archivo dynamicmaps.cf.

ARCHIVOS

$meta_directory/main.cf.proto, archivo de configuración base
$meta_directory/master.cf.proto, archivo de configuración base
$daemon_directory/postmulti-script, programa auxiliar de ciclo de vida
