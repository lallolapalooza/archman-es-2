NOMBRE

podman-image-sign - Crear una firma para una imagen

SINOPSIS

podman image sign [opciones] imagen [imagen ...]

DESCRIPCIÓN

podman image sign crea una firma local para una o más imágenes locales que han sido descargadas de un registro. La firma se escribe en un directorio derivado de los archivos de configuración del registro en $HOME/.config/containers/registries.d si existe, de lo contrario /etc/containers/registries.d (a menos que se anule en tiempo de compilación), vea containers-registries.d(5) para más información. Por defecto, la firma se escribe en /var/lib/containers/sigstore para root y $HOME/.local/share/containers/sigstore para usuarios no root.

OPCIONES

--all, -a

Firma todos los manifiestos de la imagen multiarquitectura (por defecto false).

--authfile=ruta

Ruta del archivo de autenticación. El valor predeterminado es ${XDG_RUNTIME_DIR}/containers/auth.json en Linux y $HOME/.config/containers/auth.json en Windows/macOS. El archivo es creado por podman login. Si el estado de autorización no se encuentra allí, se comprueba $HOME/.docker/config.json, que se establece usando docker login.

Nota: También existe la opción de anular la ruta predeterminada del archivo de autenticación estableciendo la variable de entorno REGISTRY_AUTH_FILE. Esto se puede hacer con export REGISTRY_AUTH_FILE=ruta.

--cert-dir=ruta

Utiliza los certificados en ruta (*.crt, *.cert, *.key) para conectarte al registro. (Predeterminado: /etc/containers/certs.d) Para más detalles, vea containers-certs.d(5). (Esta opción no está disponible con el cliente remoto de Podman, incluidas las máquinas Mac y Windows (excluyendo WSL2)).

--directory, -d=directorio

Almacena las firmas en el directorio especificado. Predeterminado: /var/lib/containers/sigstore

--help, -h

Imprime el mensaje de uso.

--sign-by=identidad

Anula la identidad predeterminada de la firma.

EJEMPLOS

Firma la imagen busybox con la identidad de foo@bar.com usando el almacén de claves del usuario y guarda la firma en /tmp/signatures/.

   $ sudo podman image sign --sign-by foo@bar.com --directory /tmp/signatures docker://privateregistry.example.com/foobar
   $ sudo podman image sign --authfile=/tmp/foobar.json --sign-by foo@bar.com --directory /tmp/signatures docker://privateregistry.example.com/foobar

CONFIGURACIÓN RELACIONADA

La ubicación de escritura (y lectura) para las firmas se define en archivos de configuración basados en YAML en /etc/containers/registries.d/ para root, o $HOME/.config/containers/registries.d para usuarios no root. Al firmar una imagen, Podman utiliza esos archivos de configuración para determinar dónde escribir la firma basándose en el nombre del registro de origen o un valor de almacenamiento predeterminado, a menos que se anule con la opción --directory. Por ejemplo, considere el siguiente archivo de configuración.

docker:
  privateregistry.example.com:
    sigstore: file:///var/lib/containers/sigstore

Al firmar una imagen precedida por el nombre del registro 'privateregistry.example.com', la firma se escribe en subdirectorios de /var/lib/containers/sigstore/privateregistry.example.com. El uso de 'sigstore' también significa que la firma se 'lee' de la misma ubicación en una función relacionada con la extracción.

VER TAMBIÉN

containers-certs.d(5), containers-registries.d(5)
