NOMBRE

podman-container-runlabel - Ejecuta un comando según lo descrito por una etiqueta de imagen de contenedor

SINOPSIS

podman container runlabel [opciones] etiqueta imagen [arg...]

DESCRIPCIÓN

podman container runlabel lee la etiqueta especificada de la imagen y la ejecuta como un comando en el host. Si la etiqueta no existe, Podman sale con un error. Los argumentos adicionales se anexan al comando.

Históricamente, las imágenes de contenedor describen el contenido (por ejemplo, capas) y cómo un tiempo de ejecución de contenedor (por ejemplo, crun(1) o runc(1)) ejecuta el contenedor. Por ejemplo, una imagen puede establecer el entorno y el comando en su configuración. Sin embargo, una imagen de contenedor no puede especificar directamente cómo un motor de contenedor como Podman la ejecuta. Por ejemplo, una configuración de imagen no incluye información sobre controladores de registro, espacios de nombres o qué capacidades necesita para ejecutarse correctamente.

podman container runlabel aborda la limitación de las imágenes de contenedor de una manera simple pero eficiente. Podman lee el contenido de la etiqueta y lo interpreta como un comando que se ejecuta en el host. De esta manera, una imagen puede describir exactamente cómo es ejecutada por Podman. Por ejemplo, una etiqueta con el contenido /usr/bin/podman run -d --pid=host --privileged \${IMAGE} instruye a la imagen a ser ejecutada en un contenedor desconectado y privilegiado que utiliza el espacio de nombres PID del host. Esto eleva la autodescripción de una imagen de contenedor de "qué" a "cómo".

Tenga en cuenta que el comando runlabel está destinado a ser ejecutado exclusivamente en entornos de confianza. No se recomienda el uso del comando en imágenes no confiables.

VARIABLES

El contenido de una etiqueta puede referirse a las siguientes variables que se sustituyen al procesar la etiqueta.

IMAGE El nombre de la imagen. Al ejecutar podman container runlabel etiqueta fedora, la variable IMAGE se reemplaza con fedora. Los formatos válidos son IMAGE, $IMAGE, ${IMAGE} y =IMAGE.

NAME Tal como se especifica en la opción --name. El formato es idéntico al del atributo IMAGE.

PWD Se reemplazará con el directorio de trabajo actual.

OPCIONES

--authfile=ruta

Ruta del archivo de autenticación. Por defecto es ${XDG_RUNTIME_DIR}/containers/auth.json en Linux y $HOME/.config/containers/auth.json en Windows/macOS. El archivo es creado por podman login. Si el estado de autorización no se encuentra allí, se comprueba $HOME/.docker/config.json, que se establece usando docker login.

Nota: También existe la opción de anular la ruta por defecto del archivo de autenticación estableciendo la variable de entorno REGISTRY_AUTH_FILE. Esto se puede hacer con export REGISTRY_AUTH_FILE=ruta.

--cert-dir=ruta

Utiliza certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro. (Por defecto: /etc/containers/certs.d) Para obtener detalles, consulte containers-certs.d(5). (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--creds=[usuario[:contraseña]]

El [usuario[:contraseña]] a utilizar para autenticarse con el registro, si es necesario. Si no se proporcionan uno o ambos valores, aparecerá un aviso en la línea de comandos y se podrá introducir el valor. La contraseña se introduce sin eco.

Tenga en cuenta que las credenciales especificadas solo se utilizan para autenticarse en los registros de destino. No se utilizan para espejos o cuando el registro se reescribe (ver containers-registries.conf(5)); para autenticarse en esos, considere usar un archivo containers-auth.json(5).

--display

Muestra el valor de la etiqueta de la imagen con sus variables de entorno pobladas. El comando runlabel no se ejecuta si se especifica --display.

--help, -h

Imprime la declaración de uso

--name, -n=nombre

Utiliza este nombre para crear contenido para el contenedor. Si no se especifica, el nombre por defecto es el nombre de la imagen.

--quiet, -q

Suprime la información de salida al descargar imágenes

--replace

Si existe un contenedor con el nombre actual, se detiene, se elimina y se crea un nuevo contenedor a partir de esta imagen.

--tls-verify

Requiere HTTPS y verifica los certificados al contactar con los registros (por defecto: true). Si se establece explícitamente en true, se utiliza la verificación TLS. Si se establece en false, no se utiliza la verificación TLS. Si no se especifica, se utiliza la verificación TLS a menos que el registro de destino figure como un registro inseguro en containers-registries.conf(5)

EJEMPLOS

Ejecuta la etiqueta run de una imagen llamada foobar.

$ podman container runlabel run foobar

Ejecuta la etiqueta install de una imagen llamada foobar con argumentos adicionales.

$ podman container runlabel install foobar apples oranges

Muestra el contenido de la etiqueta run de la imagen foobar.

$ podman container runlabel --display run foobar

Vuelve a ejecutar un contenedor utilizando una etiqueta que establece un nombre de contenedor fijo. La opción --replace asegura que cualquier contenedor existente se elimine primero.

$ podman ps -a
CONTAINER ID  IMAGE                             COMMAND               CREATED         STATUS                     PORTS       NAMES
1254c038d892  docker.io/library/busybox:latest  echo Hello from r...  26 seconds ago  Exited (0) 26 seconds ago              test-runlabel
$ podman container runlabel --replace RUN runlabel-test
Hello from runlabel
$ podman ps -a
CONTAINER ID  IMAGE                             COMMAND               CREATED        STATUS                    PORTS       NAMES
28efd9600d0c  docker.io/library/busybox:latest  echo Hello from r...  4 seconds ago  Exited (0) 4 seconds ago              test-runlabel

Este comando es útil cuando la etiqueta utiliza un nombre fijo (por ejemplo, --name mi-contenedor) y desea ejecutarlo repetidamente sin eliminar manualmente el contenedor anterior.
