DSPOSV calcula la solución al sistema de ecuaciones lineales A * X = B para matrices PO

Propósito:

!>
!> DSPOSV calcula la solución a un sistema de ecuaciones lineales real
!>    A * X = B,
!> donde A es una matriz simétrica definida positiva de N por N y X y B
!> son matrices de N por NRHS.
!>
!> DSPOSV primero intenta factorizar la matriz en PRECISION SIMPLE
!> y utiliza esta factorización dentro de un procedimiento de refinamiento iterativo
!> para producir una solución con una calidad de error residual normwise en PRECISION DOBLE
!> (ver abajo). Si el enfoque falla, el método cambia a una
!> factorización y solución en PRECISION DOBLE.
!>
!> El refinamiento iterativo no será una estrategia ganadora si
!> la relación rendimiento en PRECISION SIMPLE sobre rendimiento en PRECISION DOBLE
!> es demasiado pequeña. Una estrategia razonable debería tener en cuenta
!> el número de lados derechos y el tamaño de la matriz.
!> Esto podría hacerse con una llamada a ILAENV en el futuro. Hasta ahora,
!> siempre intentamos el refinamiento iterativo.
!>
!> El proceso de refinamiento iterativo se detiene si
!>     ITER > ITERMAX
!> o para todos los RHS tenemos:
!>     RNRM < SQRT(N)*XNRM*ANRM*EPS*BWDMAX
!> donde
!>     o ITER es el número de la iteración actual en el proceso
!>       de refinamiento iterativo
!>     o RNRM es la norma infinito del residuo
!>     o XNRM es la norma infinito de la solución
!>     o ANRM es la norma operador infinito de la matriz A
!>     o EPS es el epsilon de la máquina devuelto por DLAMCH('Epsilon')
!> Los valores ITERMAX y BWDMAX se fijan en 30 y 1.0D+00
!> respectivamente.
!>

Parámetros

UPLO 
!>          UPLO es CHARACTER*1
!>          = 'U':  El triángulo superior de A está almacenado;
!>          = 'L':  El triángulo inferior de A está almacenado.
!>

N

!>          N es INTEGER
!>          El número de ecuaciones lineales, es decir, el orden de
!>          la matriz A.  N >= 0.
!>

NRHS

!>          NRHS es INTEGER
!>          El número de lados derechos, es decir, el número de columnas
!>          de la matriz B.  NRHS >= 0.
!>

A

!>          A es un array DOUBLE PRECISION,
!>          dimensión (LDA,N)
!>          En la entrada, la matriz simétrica A.  Si UPLO = 'U', la parte
!>          superior triangular de N por N de A contiene la parte
!>          superior triangular de la matriz A, y la parte estrictamente
!>          inferior triangular de A no se referencia. Si UPLO = 'L', la parte
!>          inferior triangular de N por N de A contiene la parte
!>          inferior triangular de la matriz A, y la parte estrictamente
!>          superior triangular de A no se referencia.
!>          En la salida, si el refinamiento iterativo se ha utilizado
!>          con éxito (INFO = 0 e ITER >= 0, ver descripción abajo), entonces A
!>          no se modifica; si se ha utilizado la factorización en precisión
!>          doble (INFO = 0 e ITER < 0, ver descripción abajo), entonces el
!>          array A contiene el factor U o L de la factorización de
!>          Cholesky A = U**T*U o A = L*L**T.
!>

LDA

!>          LDA es INTEGER
!>          La dimensión principal del array A.  LDA >= max(1,N).
!>

B

!>          B es un array DOUBLE PRECISION, dimensión (LDB,NRHS)
!>          La matriz B del lado derecho de N por NRHS.
!>

LDB

!>          LDB es INTEGER
!>          La dimensión principal del array B.  LDB >= max(1,N).
!>

X

!>          X es un array DOUBLE PRECISION, dimensión (LDX,NRHS)
!>          Si INFO = 0, la matriz solución X de N por NRHS.
!>

LDX

!>          LDX es INTEGER
!>          La dimensión principal del array X.  LDX >= max(1,N).
!>

WORK

!>          WORK es un array DOUBLE PRECISION, dimensión (N,NRHS)
!>          Este array se utiliza para almacenar los vectores residuales.
!>

SWORK

!>          SWORK es un array REAL, dimensión (N*(N+NRHS))
!>          Este array se utiliza para utilizar la matriz en precisión simple y los
!>          lados derechos o soluciones en precisión simple.
!>

ITER

!>          ITER es INTEGER
!>          < 0: el refinamiento iterativo ha fallado, se ha realizado
!>               una factorización en precisión doble
!>               -1 : la rutina recurrió a precisión completa por
!>                    razones específicas de implementación o máquina
!>               -2 : al estrechar la precisión se produjo un desbordamiento,
!>                    la rutina recurrió a precisión completa
!>               -3 : fallo de SPOTRF
!>               -31: se detuvo el refinamiento iterativo después de la 30ª
!>                    iteración
!>          > 0: se ha utilizado con éxito el refinamiento iterativo.
!>               Devuelve el número de iteraciones
!>

INFO

!>          INFO es INTEGER
!>          = 0:  salida exitosa
!>          < 0:  si INFO = -i, el i-ésimo argumento tenía un valor ilegal
!>          > 0:  si INFO = i, el menor principal líder de orden i
!>                de (DOUBLE PRECISION) A no es positivo, por lo que la
!>                factorización no pudo completarse y la solución
!>                no se calculó.
!>

SYNOPSIS

SUBROUTINE ZCPOSV_MIXED( UPLO, N, NRHS, A, LDA, B, LDB, X, LDX, WORK, SWORK, RWORK, ITER, INFO )
  CHARACTER UPLO
  INTEGER N
  INTEGER NRHS
  COMPLEX*16 A( LDA, * )
  INTEGER LDA
  COMPLEX*16 B( LDB, * )
  INTEGER LDB
  COMPLEX*16 X( LDX, * )
  INTEGER LDX
  COMPLEX*16 WORK( N, * )
  COMPLEX SWORK( * )
  DOUBLE PRECISION RWORK( * )
  INTEGER ITER
  INTEGER INFO

Detailed Description

This routine is called by ZPOSV.

It uses the complex split iterative refinement strategy to compute the solution X of a system of linear equations A*X = B, where A is a Hermitian positive definite matrix.

The strategy consists of the following steps:

  1. Compute the double precision solution X1.
  2. Compute the residual R = B - A*X1.
  3. Compute the single precision solution X2 from A*X = R.
  4. Compute the final solution X = X1 + X2.

    5. The routine uses factorization within an iterative refinement procedure to produce a solution with COMPLEX*16 normwise backward error quality (see below). If the approach fails the method switches to a COMPLEX*16 factorization and solve.

    The iterative refinement is not going to be a winning strategy if the ratio COMPLEX performance over COMPLEX*16 performance is too small. A reasonable strategy should take the number of right-hand sides and the size of the matrix into account. This might be done with a call to ILAENV in the future. Up to now, we always try iterative refinement.

    The iterative refinement process is stopped if

        ITER > ITERMAX

    or for all the RHS we have:

        RNRM < SQRT(N)*XNRM*ANRM*EPS*BWDMAX

    where

    • ITER is the number of the current iteration in the iterative refinement process
    • RNRM is the infinity-norm of the residual
    • XNRM is the infinity-norm of the solution
    • ANRM is the infinity-operator-norm of the matrix A
    • EPS is the machine epsilon returned by DLAMCH('Epsilon')

    The value ITERMAX and BWDMAX are fixed to 30 and 1.0D+00 respectively.

Parameters

UPLO
UPLO is CHARACTER*1
                        = 'U':  Upper triangle of A is stored;
                        = 'L':  Lower triangle of A is stored.
N
N is INTEGER
                        The number of linear equations, i.e., the order of the
                        matrix A.  N >= 0.
NRHS
NRHS is INTEGER
                        The number of right hand sides, i.e., the number of columns
                        of the matrix B.  NRHS >= 0.
A
A is COMPLEX*16 array,
                        dimension (LDA,N)
                        On entry, the Hermitian matrix A. If UPLO = 'U', the leading
                        N-by-N upper triangular part of A contains the upper
                        triangular part of the matrix A, and the strictly lower
                        triangular part of A is not referenced.  If UPLO = 'L', the
                        leading N-by-N lower triangular part of A contains the lower
                        triangular part of the matrix A, and the strictly upper
                        triangular part of A is not referenced.

                        Note that the imaginary parts of the diagonal
                        elements need not be set and are assumed to be zero.

                        On exit, if iterative refinement has been successfully used
                        (INFO = 0 and ITER >= 0, see description below), then A is
                        unchanged, if double precision factorization has been used
                        (INFO = 0 and ITER < 0, see description below), then the
                        array A contains the factor U or L from the Cholesky
                        factorization A = U**H*U or A = L*L**H.
LDA
LDA is INTEGER
                        The leading dimension of the array A.  LDA >= max(1,N).
B
B is COMPLEX*16 array, dimension (LDB,NRHS)
                        The N-by-NRHS right hand side matrix B.
LDB
LDB is INTEGER
                        The leading dimension of the array B.  LDB >= max(1,N).
X
X is COMPLEX*16 array, dimension (LDX,NRHS)
                        If INFO = 0, the N-by-NRHS solution matrix X.
LDX
LDX is INTEGER
                        The leading dimension of the array X.  LDX >= max(1,N).
WORK
WORK is COMPLEX*16 array, dimension (N,NRHS)
                        This array is used to hold the residual vectors.
SWORK
SWORK is COMPLEX array, dimension (N*(N+NRHS))
                        This array is used to use the single precision matrix and the
                        right-hand sides or solutions in single precision.
RWORK
RWORK is DOUBLE PRECISION array, dimension (N)
ITER
ITER is INTEGER
                        < 0: iterative refinement has failed, COMPLEX*16
                             factorization has been performed
                             -1 : the routine fell back to full precision for
                                  implementation- or machine-specific reasons
                             -2 : narrowing the precision induced an overflow,
                                  the routine fell back to full precision
                             -3 : failure of CPOTRF
                             -31: stop the iterative refinement after the 30th
                                  iterations
                        > 0: iterative refinement has been successfully used.
                             Returns the number of iterations
INFO
INFO is INTEGER
                        = 0:  successful exit
                        < 0:  if INFO = -i, the i-th argument had an illegal value
                        > 0:  if INFO = i, the leading principal minor of order i
                              of (COMPLEX*16) A is not positive, so the factorization
                              could not be completed, and the solution has not been
                              computed.
