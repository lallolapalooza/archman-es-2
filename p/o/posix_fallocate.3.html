posix_fallocate(3) Manual de Funciones de Biblioteca posix_fallocate(3)

NOMBRE

posix_fallocate - asignar espacio en un archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <fcntl.h>
int posix_fallocate(int fd, off_t offset, off_t size);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

posix_fallocate():

    _POSIX_C_SOURCE >= 200112L

DESCRIPCIÓN

La función posix_fallocate() asegura que se asigna espacio en disco para el archivo al que se refiere el descriptor de archivo fd para los bytes en el rango que comienza en offset y continúa durante size bytes. Después de una llamada exitosa a posix_fallocate(), las escrituras posteriores a bytes en el rango especificado garantizan no fallar debido a la falta de espacio en disco.

Si el tamaño del archivo es menor que offset+size, entonces el archivo se incrementa a este tamaño; de lo contrario, el tamaño del archivo permanece sin cambios.

VALOR DE RETORNO

posix_fallocate() devuelve cero en caso de éxito, o un número de error en caso de fallo. Tenga en cuenta que errno no se establece.

ERRORES

EBADF
fd no es un descriptor de archivo válido, o no está abierto para escritura.
EFBIG
offset+size excede el tamaño máximo de archivo.
EINTR
Se capturó una señal durante la ejecución.
EINVAL
offset era menor que 0, o size era menor o igual a 0, o el sistema de archivos subyacente no admite la operación.
ENODEV
fd no se refiere a un archivo regular.
ENOSPC
No queda suficiente espacio en el dispositivo que contiene el archivo al que se refiere fd.
EOPNOTSUPP
El sistema de archivos que contiene el archivo al que se refiere fd no admite esta operación. Este código de error puede ser devuelto por bibliotecas C que no realizan la emulación que se muestra en CAVEATS, como musl libc.
ESPIPE
fd se refiere a una tubería.

Interfaz Atributo Valor

ESTÁNDARES

POSIX.1-2008.

HISTORIA

glibc 2.1.94. POSIX.1-2001

POSIX.1-2008 dice que una implementación debe dar el error EINVAL si size era 0, o offset era menor que 0. POSIX.1-2001 dice que una implementación debe dar el error EINVAL si size es menor que 0, o offset era menor que 0, y puede dar el error si size es cero.

CAVEATS

En la implementación de glibc, posix_fallocate() se implementa utilizando la llamada al sistema fallocate(2), que es MT-safe. Si el sistema de archivos subyacente no admite fallocate(2), la operación se emula con las siguientes advertencias:

•
La emulación es ineficiente.
•
Existe una condición de carrera en la que escrituras concurrentes desde otro hilo o proceso podrían ser sobrescritas con bytes nulos.
•
Existe una condición de carrera en la que los aumentos de tamaño de archivo concurrentes por otro hilo o proceso podrían resultar en un archivo cuyo tamaño es menor de lo esperado.
•
Si fd se ha abierto con las banderas O_APPEND o O_WRONLY, la función falla con el error EBADF.

En general, la emulación no es MT-safe. En Linux, las aplicaciones pueden usar fallocate(2) si no pueden tolerar las advertencias de emulación. En general, esto solo se recomienda si la aplicación planea terminar la operación si se devuelve EOPNOTSUPP, de lo contrario, la aplicación misma deberá implementar una solución alternativa con todos los mismos problemas que la emulación proporcionada por glibc.
