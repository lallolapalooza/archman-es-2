PO4A.1P(1) Documentación de Perl contribuida por el usuario PO4A.1P(1)

NOMBRE

po4a - actualiza tanto los archivos PO como los documentos traducidos en una sola pasada

SINOPSIS

po4a [opciones] archivo_configuración

DESCRIPCIÓN

po4a (PO para cualquier cosa) facilita el mantenimiento de la traducción de documentación utilizando las herramientas clásicas de gettext. La característica principal de po4a es que desacopla la traducción del contenido de su estructura de documento. Por favor, consulte la página po4a(7) para una introducción sencilla a este proyecto.

Al ejecutarse, po4a analiza todos los archivos de documentación especificados en su archivo de configuración. Actualiza los archivos PO (que contienen la traducción) para reflejar cualquier cambio en la documentación, y produce una documentación traducida inyectando la traducción del contenido (encontrada en los archivos PO) en la estructura del documento maestro original.

Al principio, los archivos PO solo contienen las cadenas a traducir de la documentación original. Este formato de archivo permite a los traductores proporcionar manualmente una traducción para cada párrafo extraído por po4a. Si la documentación se modifica después de la traducción, po4a marca las traducciones correspondientes como "fuzzy" en el archivo PO para solicitar una revisión manual por parte de los traductores. Los traductores también pueden proporcionar los llamados "addendum", que son contenido adicional que indica, por ejemplo, quién realizó la traducción y cómo informar de errores.

documentos maestros ---+---->-------->---------+
 (autoría de doc)    |                       |
                    V   (ejecuciones de po4a)   >-----+--> documentos
                    |                       |     |     traducidos
archivos PO existentes -->--> archivos PO actualizados >-+     |
     ^                            |               |
     |                            V               |
     +----------<---------<-------+               ^
      (proceso de traducción manual)              |
                                                  |
addendum -->--------------------------------------+

El flujo de trabajo de po4a es asíncrono, como conviene a los proyectos de código abierto. Los redactores de documentación crean los documentos maestros a su propio ritmo. Los traductores revisan y actualizan las traducciones en los archivos PO. Los mantenedores vuelven a ejecutar po4a según sea necesario, para reflejar cualquier cambio en la documentación original en los archivos PO, y para producir traducciones de documentación actualizadas, inyectando la última traducción en la última estructura de documento.

Por defecto, se produce un documento traducido dado cuando se traduce al menos el 80% de su contenido. El texto no traducido se mantiene en el idioma original. La documentación producida, por lo tanto, mezcla idiomas si la traducción no está completa. Puede cambiar el umbral del 80% con la opción --keep descrita a continuación. Tenga en cuenta, sin embargo, que descartar traducciones tan pronto como no sean del 100% puede ser desalentador para los traductores cuyo trabajo casi nunca será mostrado a los usuarios, mientras que mostrar "traducciones" que son demasiado incompletas puede ser problemático para los usuarios finales.

Almacenar los archivos de documentación traducidos en el sistema de control de versiones es probablemente una mala idea, ya que se generan automáticamente. Los archivos valiosos son los archivos PO, que contienen el arduo trabajo de sus compañeros traductores. Además, a algunas personas les resulta más fácil interactuar con los traductores a través de una plataforma en línea como weblate, pero esto es naturalmente totalmente opcional.

Tutorial de inicio rápido

Supongamos que mantiene un programa llamado foo que tiene una página de manual man/foo.1 escrita en inglés (el idioma puente en la mayoría de los proyectos de código abierto, pero po4a se puede usar desde o hacia cualquier idioma). Hace algún tiempo, alguien proporcionó una traducción al alemán llamada man/foo.de.1 y desapareció. Este es un problema porque acaba de recibir un informe de error que dice que su documentación contiene información gravemente engañosa que debe corregirse en todos los idiomas, pero no habla alemán, por lo que solo puede modificar el original, no la traducción. Ahora, otro contribuidor quiere contribuir con una traducción al japonés, un idioma que tampoco domina.

Es hora de convertir su documentación a po4a para resolver sus pesadillas de mantenimiento de documentación. Quiere actualizar el documento cuando sea necesario, quiere facilitar el trabajo de sus compañeros traductores y quiere asegurarse de que sus usuarios nunca vean documentación desactualizada y, por lo tanto, engañosa.

La conversión incluye dos pasos: configurar la infraestructura de po4a y convertir la traducción anterior al alemán para recuperar el trabajo anterior. Esta última parte se realiza utilizando po4a-gettextize, de la siguiente manera. Como se detalla en la documentación de po4a-gettextize(1), este proceso rara vez es completamente automático, pero una vez hecho, el archivo de.po que contiene la traducción al alemán puede integrarse en su flujo de trabajo de po4a.

po4a-gettextize --format man --master foo.1 --localized foo.de.1 --po de.po

Ahora, configuremos po4a. Con la disposición de archivos apropiada, su archivo de configuración podría ser tan simple como esto:

[po_directory] man/po4a/
[type: man] man/foo.1 $lang:man/translated/foo.$lang.1

Especifica que todos los archivos PO (que contienen el trabajo de los traductores) están en el directorio man/po4a/, y que solo tiene un archivo maestro, man/foo.1. Si tuviera varios archivos maestros, tendría varias líneas similares a la segunda. Cada línea de este tipo también especifica dónde escribir los archivos de traducción correspondientes. Aquí, la traducción al alemán de man/foo.1 está en man/translated/foo.de.1.

Lo último que necesitamos para completar la configuración de po4a es un archivo POT que contenga el material de plantilla que se utilizará para iniciar una nueva traducción. Simplemente cree un archivo vacío con la extensión .pot en el directorio po especificado (por ejemplo, man/po4a/foo.pot), y po4a lo llenará con el contenido esperado.

Aquí hay un resumen de los archivos en esta configuración:

├── man/
│   ├── foo.1        <- La página de manual original, en inglés
│   ├── po4a/
│   │   ├── de.po    <- La traducción PO al alemán, de la obtención de textos
│   │   └── foo.pot  <- La plantilla POT para futuras traducciones (vacía al principio)
│   └── translated/  <- Directorio donde se crearán las traducciones
└── po4a.cfg         <- El archivo de configuración

Una vez configurado, ejecutar po4a analizará su documentación, actualizará el archivo de plantilla POT, lo usará para actualizar los archivos de traducción PO y los usará para actualizar los archivos de traducción de documentación. Todo en un solo comando:

po4a --verbose po4a.cfg

Eso es todo. po4a está ahora completamente configurado. Una vez que haya corregido su error en man/foo.1, el párrafo ofensivo en la traducción alemana será reemplazado por el texto corregido en inglés. Mezclar idiomas no es óptimo, pero es la única manera de eliminar errores en traducciones que ni siquiera comprende, y garantizar que el contenido presentado a los usuarios nunca sea engañoso. Actualizar la traducción alemana también es mucho más fácil en el archivo PO correspondiente, por lo que la mezcla de idiomas puede no durar mucho. Finalmente, cuando un traductor japonés quiera contribuir con una nueva traducción, debería renombrar foo.pot a ja.po y completar la traducción. Una vez que tenga este archivo, simplemente colóquelo en man/po4a/po/. Una página traducida aparecerá como man/translated/foo.ja.1 (siempre que se traduzca suficiente contenido) cuando ejecute po4a de nuevo.

OPCIONES

un comando entre corchetes cuadrados, seguido de sus parámetros. Los comentarios comienzan con el carácter '#' y continúan hasta el final de la línea. Puede escapar el final de línea para extender un comando en varias líneas.

Se presentan algunos ejemplos completos en esta página, mientras que otros ejemplos se pueden encontrar en el directorio "t/cfg" de la distribución fuente.

Encontrando los archivos PO y POT

La solución más simple es dar explícitamente la ruta a los archivos POT y PO, como sigue:

[po4a_paths] man/po/project.pot de:man/po/de.po fr:man/po/fr.po

Esto especifica la ruta al archivo POT primero, y luego las rutas a los archivos PO alemán y francés.

La misma información se puede escribir de la siguiente manera para reducir el riesgo de errores de copiar/pegar:

[po4a_langs] fr de
[po4a_paths] man/po/project.pot $lang:man/po/$lang.po

El componente $lang se expande automáticamente utilizando la lista de idiomas proporcionada, reduciendo el riesgo de errores de copiar/pegar cuando se agrega un nuevo idioma.

Puede compactar aún más la misma información proporcionando solo la ruta al directorio que contiene su proyecto de traducción, como sigue.

[po_directory] man/po/

El directorio proporcionado debe contener un conjunto de archivos PO, cada uno llamado XX.po con "XX" el ISO 639-1 del idioma utilizado en este archivo. El directorio también debe contener un único archivo POT, con la extensión de archivo ".pot". Para la primera ejecución, este archivo puede estar vacío pero debe existir (po4a no puede adivinar el nombre a usar antes de la extensión).

Tenga en cuenta que debe elegir solo una opción entre "po_directory" y "po4a_paths". La primera ("po_directory") es más compacta, reduce aún más el riesgo de errores de copiar/pegar, pero lo obliga a usar la estructura del proyecto y los nombres de archivo esperados. La segunda ("po4a_paths"), es más explícita, probablemente más legible, y se aconseja al configurar su primer proyecto con po4a.

¿Archivos PO centralizados o divididos?

Por defecto, po4a produce un único archivo PO por idioma de destino, que contiene todo el contenido de su proyecto de traducción. A medida que su proyecto crece, el tamaño de estos archivos puede volverse problemático. Al usar weblate, es posible especificar prioridades para cada segmento de traducción (es decir, msgid) para que los importantes se traduzcan primero. Aún así, algunos equipos de traducción prefieren dividir el contenido en varios archivos.

Para tener un archivo PO por archivo maestro, simplemente tiene que usar la cadena $master en el nombre de sus archivos PO en la línea "[po4a_paths]", como sigue.

[po4a_paths] doc/$master/$master.pot $lang:doc/$master/$lang.po

Con esta línea, po4a producirá archivos POT y PO separados para cada documento a traducir. Por ejemplo, si tiene 3 documentos y 5 idiomas, esto resultará en 3 archivos POT y 15 archivos PO. Estos archivos se nombran como se especifica en la plantilla "po4a_paths", con $master sustituido por el nombre base de cada documento a traducir. En caso de conflicto de nombres, puede especificar el archivo POT a usar como sigue, con el parámetro "pot=".

Esta característica también se puede usar para agrupar varios archivos traducidos en el mismo archivo POT. El siguiente ejemplo solo produce 2 archivos POT: l10n/po/foo.pot (que contiene el material de foo/gui.xml) y l10n/po/bar.pot (que contiene el material tanto de bar/gui.xml como de bar/cli.xml).

[po4a_langs] de fr ja
[po4a_paths] l10n/po/$master.pot $lang:l10n/po/$master.$lang.po
[type: xml] foo/gui.xml $lang:foo/gui.$lang.xml pot=foo
[type: xml] bar/gui.xml $lang:bar/gui.$lang.xml pot=bar
[type: xml] bar/cli.xml $lang:bar/cli.$lang.xml pot=bar

En modo dividido, po4a construye un compendio temporal durante la actualización del PO, para compartir las traducciones entre todos los archivos PO. Si dos archivos PO tienen traducciones diferentes para la misma cadena, po4a marcará esta cadena como "fuzzy" y enviará ambas traducciones en todos los archivos PO que contengan esta cadena. Cuando el traductor la desactive (unfuzzied), la traducción se usará automáticamente en todos los archivos PO.

Especificando los documentos a traducir

También debe enumerar los documentos que deben traducirse. Para cada archivo maestro, debe especificar el analizador de formato a usar, la ubicación del documento traducido a producir y, opcionalmente, alguna configuración. Los nombres de archivo deben entrecomillarse o escaparse si contienen espacios. Aquí hay un ejemplo:

[type: sgml] "doc/my stuff.sgml"  "fr:doc/fr/mon truc.sgml"  de:doc/de/mein\ kram.sgml
[type: man] script fr:doc/fr/script.1 de:doc/de/script.1
[type: docbook] doc/script.xml fr:doc/fr/script.xml \
            de:doc/de/script.xml

Pero de nuevo, estas líneas complejas son difíciles de leer y modificar, por ejemplo, al agregar un nuevo idioma. Es mucho más simple reorganizar las cosas usando la plantilla $lang como sigue:

[type: sgml]    doc/my_stuff.sgml $lang:doc/$lang/my_stuff.sgml
[type: man]     script.1          $lang:po/$lang/script.1
[type: docbook] doc/script.xml    $lang:doc/$lang/script.xml

Especificando opciones

Hay dos tipos de opciones: las *opciones po4a* son valores predeterminados para las opciones de línea de comandos de po4a, mientras que las *opciones de formato* se utilizan para cambiar el comportamiento de los analizadores de formato. Como *opción po4a*, podría, por ejemplo, especificar en su archivo de configuración que el valor predeterminado del parámetro de línea de comandos --keep sea 50% en lugar del 80%. Las *opciones de formato* se documentan en la página específica de cada módulo de análisis, por ejemplo, Locale::Po4a::Xml(3pm). Podría, por ejemplo, pasar nostrip al analizador XML para no eliminar los espacios alrededor de las cadenas extraídas.

Puede pasar estas opciones para un archivo maestro específico, o incluso para una traducción específica de ese archivo, usando "opt:" y "opt_XX:" para el idioma "XX". En el siguiente ejemplo, la opción nostrip se pasa al analizador XML (para todos los idiomas), mientras que el umbral se reducirá al 0% para la traducción francesa (que por lo tanto siempre se mantiene).

[type:xml] toto.xml $lang:toto.$lang.xml opt:"-o nostrip" opt_fr:"--keep 0"

En cualquier caso, estos fragmentos de configuración deben ubicarse al final de la línea. La declaración de archivos debe ir primero, luego el añadido si lo hay (ver más abajo), y solo después las opciones. La agrupación de fragmentos de configuración no es muy importante, ya que los elementos se concatenan internamente como cadenas. Los siguientes ejemplos son todos equivalentes:

[type:xml] toto.xml $lang:toto.$lang.xml opt:"--keep 20" opt:"-o nostrip" opt_fr:"--keep 0"
[type:xml] toto.xml $lang:toto.$lang.xml opt:"--keep 20 -o nostrip" opt_fr:"--keep 0"
[type:xml] toto.xml $lang:toto.$lang.xml opt:--keep opt:20 opt:-o opt:nostrip opt_fr:--keep opt_fr:0

Tenga en cuenta que las opciones específicas del idioma no se utilizan al generar el archivo POT. Por ejemplo, es imposible pasar nostrip al analizador solo al generar la traducción francesa, porque el mismo archivo POT se utiliza para actualizar todos los idiomas. Por lo tanto, las únicas opciones que pueden ser específicas del idioma son aquellas que se utilizan al producir la traducción, como la opción "--keep".

Alias de configuración

Para pasar las mismas opciones a varios archivos, lo mejor es definir un alias de tipo como sigue. En el siguiente ejemplo, se pasa "--keep 0" a todas las traducciones italianas que utilizan este tipo "test", que es una extensión del tipo "man".

[po4a_alias:test] man opt_it:"--keep 0"
[type: test] man/page.1 $lang:man/$lang/page.1

También puede extender un tipo existente reutilizando el mismo nombre para el alias como sigue. Esto no se interpreta como una definición recursiva errónea.

[po4a_alias:man] man opt_it:"--keep 0"
[type: man] man/page.1 $lang:man/$lang/page.1

Opciones predeterminadas globales

También puede usar líneas "[options]" para definir opciones que deben usarse para todos los archivos, independientemente de su tipo.

[options] --keep 20 --option nostrip

Al igual que con las opciones de línea de comandos, puede abreviar los parámetros pasados en el archivo de configuración:

[options] -k 20 -o nostrip

Prioridad de opciones

Las opciones de cada fuente se concatenan, asegurando que los valores predeterminados se puedan sobrescribir fácilmente con opciones más específicas. El orden es el siguiente:

  • Las líneas "[options]" proporcionan valores predeterminados que pueden ser sobrescritos por cualquier otra fuente.
  • Luego se utilizan los alias de tipo. La configuración específica del idioma sobrescribe las que son aplicables a todos los idiomas.
  • La configuración que es específica para un archivo maestro dado sobrescribe tanto los valores predeterminados como los provenientes del alias de tipo. En este caso también, la configuración específica del idioma sobrescribe la global.
  • Finalmente, los parámetros proporcionados en la línea de comandos de po4a sobrescriben cualquier configuración del archivo de configuración.

Ejemplo

Aquí hay un ejemplo que muestra cómo entrecomillar los espacios y las comillas:

[po_directory] man/po/

[options] --master-charset UTF-8

[po4a_alias:man] man opt:"-o \"mdoc=NAME,SEE ALSO\""
[type:man] t-05-config/test02_man.1 $lang:tmp/test02_man.$lang.1 \
           opt:"-k 75" opt_it:"-L UTF-8" opt_fr:--verbose

Añadido: Añadir contenido extra en la traducción

Si desea agregar una sección adicional a la traducción, por ejemplo, para dar crédito al traductor, necesita definir un añadido a la línea que define su archivo maestro. Consulte la página po4a(7) para obtener más detalles sobre la sintaxis de los archivos de añadido.

[type: pod] script fr:doc/fr/script.1 \
            add_fr:doc/l10n/script.fr.add

También puede usar plantillas de idioma como sigue:

[type: pod] script $lang:doc/$lang/script.1 \
            add_$lang:doc/l10n/script.$lang.add

NAME

po4a - convert documentation to PO files, translate them and convert them back

SYNOPSIS

po4a [options] master_file [input_file]...

po4a [options] --update-po po_file [input_file]...

po4a [options] --add-header po_file [input_file]...

po4a [options] --remove-header po_file [input_file]...

po4a [options] --import-header po_file [input_file]...

po4a [options] --export-header po_file [input_file]...

po4a [options] --split-file po_file [input_file]...

po4a [options] --merge-file po_file [input_file]...

po4a [options] --check po_file [input_file]...

po4a [options] --clean

DESCRIPTION

The po4a project provides tools to help translators translate documentation. It works by converting documentation in various formats into PO files (Portable Object files, a standard format for translatable strings), which can then be edited using standard gettext tools like poedit, gtranslator, or vim.

Once the PO files are translated, po4a can convert them back into the original documentation format, with the translated strings embedded.

The main goal is to ease the translation of documentation into multiple languages. The conversion process is language-aware, and handles language-specific files (like addenda or appendices).

po4a supports the following document formats:

  • POD (Plain Old Documentation)
  • DocBook
  • TeX/LaTeX
  • Getttextize comments in C source code
  • INI files
  • XHTML
  • Man pages

po4a uses a configuration file (or command-line options) to define how to process the input files and how to generate the output files.

OPTIONS

The following options are available:

-f, --format format
Specify the input document format. If not specified, it is auto-detected from the file extension.
-o, --output output_dir
Specify the directory where the output files (PO files or translated documents) will be placed. Defaults to the current directory.
-L, --language lang
Specify the language for which the PO files are generated or translated documents are created. This is mandatory when generating PO files for a specific language or when translating. Defaults to the system's default language if not specified.
-p, --po-dir po_dir
Specify the directory where the PO files are located. Defaults to the current directory.
-m, --master master_file
Specify the master input file. This is the main document that will be used to generate the PO file or the translated document. This option is usually not needed as the master file is often the first argument.
-M, --msgid-mode mode
Controls how msgids are generated. Possible values are:
file
The filename is part of the msgid (default).
line
The line number is part of the msgid.
ref
A reference to the location is part of the msgid.
normal
No location information is part of the msgid.
-w, --wrap-width width
Set the width for line wrapping in the generated PO files. Defaults to 70.
-k, --keyword keyword
Add a keyword to search for in the document. This is useful for formats that don't have a standard way of marking translatable strings.
-v, --verbose
Enable verbose output.
-d, --debug
Enable debug output.
-h, --help
Display help message and exit.
--version
Display version information and exit.
--check
Check if the translation is up-to-date with the master document.
--clean
Remove temporary files generated by po4a.
--update-po
Update an existing PO file with new strings from the master document.
--add-header
Add header information to a PO file.
--remove-header
Remove header information from a PO file.
--import-header
Import header information from a file.
--export-header
Export header information to a file.
--split-file
Split a PO file into multiple smaller files.
--merge-file
Merge multiple PO files into a single file.

CONFIGURATION FILE

po4a can be configured using a configuration file, typically named po4a.cfg. This file allows for more complex configurations than command-line options alone.

The configuration file consists of several entries, each defining how to process a specific type of document or a set of files.

File entries

A file entry starts with an opening bracket `[` and ends with a closing bracket `]`. Inside, you specify the type of the file and the file itself.

[type: format] filename

For example:

[type: pod] mydoc.pod

This indicates that mydoc.pod is a POD document.

You can also specify a list of files separated by spaces:

[type: pod] file1.pod file2.pod

Or use wildcards:

[type: pod] *.pod

Parameters for file entries

Parameters are specified after the filename, separated by whitespace. Each parameter is of the form key:value.

$lang
This special parameter indicates that the following value should be language-specific. The language code is inserted here. For example, $lang:doc/$lang/file.po becomes doc/en/file.po for English and doc/fr/file.po for French.
[type:]format
Specify the document format. If omitted, it is inferred from the file extension.
pot:path
Specifies the path to the POT file to generate.
po:path
Specifies the path to the PO file to use for translation.
output:path
Specifies the path to the output file (translated document).
lang:language
Specifies the language for the current entry.
depend:file
Specifies a file that this entry depends on. If the dependency is older than the output file, the output file will be regenerated.
msgid:mode
Specifies the msgid generation mode (see --msgid-mode option).
wrap:width
Specifies the line wrap width for PO files (see --wrap-width option).
key:keyword
Adds a keyword for string extraction (see -k option).

Addenda

Addenda are supplementary files that are appended to the main document during translation. They can be used for language-specific information, glossaries, or other supplementary material.

Addenda are specified using the add_ prefix followed by the language code. For example:

[type: pod] mydoc.pod add_en:en.add add_fr:fr.add

This means that for English, en.add will be appended, and for French, fr.add will be appended.

You can use the special variable $lang to specify language-specific addendum paths:

[type: pod] mydoc.pod add_$lang:doc/addenda/$lang.add

The following addendum modifiers can be used before the file name:

?
Include addendum_path if this file exists, otherwise do nothing. This is useful for optional addenda.
@
addendum_path is not a regular addendum but a file containing a list of addenda, one per line. Each addendum may be preceded by modifiers.
!
addendum_path is discarded; it is not loaded and will not be loaded by any further addendum specification.

The following includes an addendum in any language, but only if it exists. No error is reported if the addendum does not exist.

[type: pod] script $lang:doc/$lang/script.1  add_$lang:?doc/l10n/script.$lang.add

The following includes a list of addenda for every language:

[type: pod] script $lang:doc/$lang/script.1  add_$lang:@doc/l10n/script.$lang.add

Filtering the translated strings

Sometimes, you want to hide some strings from the translation process. To that end, you can give a "pot_in" parameter to your master file to specify the name of the file to use instead of the real master when building the POT file. Here is an example:

[type:docbook] book.xml          \
        pot_in:book-filtered.xml \
        $lang:book.$lang.xml

With this setting, the strings to translate will be extracted from book-filtered.xml (which must be produced before calling po4a), while the translated files will be built from book.xml. As a result, any string that is part of book.xml but not in book-filtered.xml will not be included in the PO files, preventing the translators from providing a translation for them. These strings will remain unmodified when producing the translated documents. This naturally decreases the level of translation, so you might need the "--keep" option to ensure that the document is produced anyway.
