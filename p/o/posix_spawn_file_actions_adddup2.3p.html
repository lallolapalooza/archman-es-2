Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

posix_spawn_file_actions_adddup2 — añadir acción dup2 al objeto de acciones de archivo de spawn (REALTIME AVANZADO)

SINOPSIS

#include <spawn.h>
int posix_spawn_file_actions_adddup2(posix_spawn_file_actions_t
    *file_actions, int fildes, int newfildes);

DESCRIPCIÓN

La función posix_spawn_file_actions_adddup2() añadirá una acción dup2() al objeto referenciado por file_actions que causará que el descriptor de archivo fildes se duplique como newfildes (como si se hubiera llamado a dup2(fildes, newfildes)) cuando se genere un nuevo proceso utilizando este objeto de acciones de archivo.

Un objeto de acciones de archivo de spawn se define como en posix_spawn_file_actions_addclose().

VALOR DE RETORNO

Si se completa con éxito, la función posix_spawn_file_actions_adddup2() devolverá cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función posix_spawn_file_actions_adddup2() fallará si:

EBADF
El valor especificado por fildes o newfildes es negativo o mayor o igual que {OPEN_MAX}.
ENOMEM
No existe memoria suficiente para añadir al objeto de acciones de archivo de spawn.

La función posix_spawn_file_actions_adddup2() puede fallar si:

EINVAL
El valor especificado por file_actions es inválido.

No se considerará un error que el argumento fildes pasado a la función posix_spawn_file_actions_adddup2() especifique un descriptor de archivo para el cual la operación especificada no pudo ser realizada en el momento de la llamada. Cualquier error de este tipo se detectará cuando el objeto de acciones de archivo asociado se utilice posteriormente durante una operación posix_spawn() o posix_spawnp().

USO DE LA APLICACIÓN

La función posix_spawn_file_actions_adddup2() forma parte de la opción Spawn y no tiene por qué proporcionarse en todas las implementaciones.

Las implementaciones pueden utilizar descriptores de archivo que deben heredarse en los procesos hijos para que el proceso hijo siga siendo conforme, como para fines de catálogo de mensajes o rastreo. Por lo tanto, una aplicación que llama a posix_spawn_file_actions_adddup2() con un entero arbitrario para newfildes corre el riesgo de un comportamiento no conforme, y esta función solo puede usarse de forma portable para sobrescribir valores de descriptores de archivo que la aplicación ha obtenido a través de acciones explícitas, o para los tres descriptores de archivo correspondientes a los flujos de archivo estándar. Para evitar una condición de carrera de fugas de un descriptor de archivo no deseado en un proceso hijo, una aplicación debe considerar abrir todos los descriptores de archivo con el bit FD_CLOEXEC establecido, a menos que el descriptor de archivo esté destinado a ser heredado a través de exec.
