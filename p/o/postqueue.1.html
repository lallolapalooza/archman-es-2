NOMBRE

postqueue - control de cola de correo de Postfix

SINOPSIS

Para vaciar la cola de correo:
postqueue [-v] [-c directorio_config] -f
postqueue [-v] [-c directorio_config] -i id_cola
postqueue [-v] [-c directorio_config] -s sitio
Para listar la cola de correo:
postqueue [-v] [-c directorio_config] -j
postqueue [-v] [-c directorio_config] -p

DESCRIPCIÓN


El comando postqueue(1) implementa la interfaz de usuario de Postfix para la gestión de colas. Implementa operaciones que tradicionalmente están disponibles a través del comando sendmail(1). Consulte el comando postsuper(1) para operaciones de cola que requieren privilegios de superusuario, como eliminar un mensaje de la cola o cambiar su estado.

Se reconocen las siguientes opciones:

-c directorio_config
El archivo de configuración main.cf se encuentra en el directorio especificado en lugar del directorio de configuración predeterminado. Consulte también la configuración del entorno MAIL_CONFIG a continuación.
-f
Vaciar la cola: intenta entregar todo el correo en cola.

Esta opción implementa el comando tradicional "sendmail -q", contactando al demonio qmgr(8) de Postfix.

Advertencia: vaciar el correo no entregable con frecuencia provocará un rendimiento de entrega deficiente de todo el demás correo.

-i id_cola
Programar la entrega inmediata de correo diferido con el ID de cola especificado.

Esta opción implementa el comando tradicional sendmail -qI, contactando al servidor de flush(8).

Esta característica está disponible a partir de Postfix versión 2.4.

-j
Produce un listado de cola en formato JSON LINES, basado en la salida del demonio showq(8). Consulte "FORMATO DE OBJETO JSON" a continuación para obtener detalles.

Esta característica está disponible en Postfix 3.1 y posterior.

-p
Produce un listado de cola tradicional al estilo sendmail. Esta opción implementa el comando tradicional mailq, contactando al demonio showq(8) de Postfix.

Cada entrada de cola muestra el ID del archivo de cola, el tamaño del mensaje, la hora de llegada, el remitente y los destinatarios que aún deben entregarse. Si el correo no se pudo entregar en el último intento, se muestra el motivo de la falla. Al ID de cola le sigue un carácter de estado opcional:

*
El mensaje está en la cola activa, es decir, el mensaje se selecciona para su entrega.
!
El mensaje está en la cola de retención, es decir, no se realizará ningún intento de entrega adicional hasta que el correo se retire de la retención.
#
Se fuerza la expiración del mensaje. Consulte las opciones -e o -f del comando postsuper(1).

Esta característica está disponible en Postfix 3.5 y posterior.

-s sitio
Programar la entrega inmediata de todo el correo que está en cola para el sitio especificado. Se debe especificar un sitio numérico como una dirección literal válida de RFC 5321 entre corchetes, al igual que en las direcciones de correo electrónico. El sitio debe ser elegible para el servicio de "vaciado rápido". Consulte flush(8) para obtener más información sobre el servicio de "vaciado rápido".

Esta opción implementa el comando tradicional "sendmail -qRsitio", contactando al demonio flush(8) de Postfix.

-v
Habilitar el registro detallado con fines de depuración. Múltiples opciones -v hacen que el software sea cada vez más detallado. A partir de Postfix 2.3, esta opción solo está disponible para el superusuario.

FORMATO DE OBJETO JSON

Cada objeto JSON representa un archivo de cola; se emite como una sola línea de texto seguida de un carácter de nueva línea.

Los miembros del objeto tienen valores de cadena, a menos que se indique lo contrario. Los programas deben ignorar los miembros del objeto que no figuran aquí; se espera que la lista de miembros crezca con el tiempo.

nombre_cola
El nombre de la cola donde se encontró el mensaje. Tenga en cuenta que el contenido de la cola de correo puede cambiar mientras se lista; algunos mensajes pueden aparecer más de una vez, y algunos mensajes pueden omitirse.
id_cola
El nombre del archivo de cola. El id_cola puede reutilizarse dentro de una instancia de Postfix a menos que "enable_long_queue_ids = true" y el tiempo sea monótono. Incluso entonces, no se espera que el id_cola sea único entre diferentes instancias de Postfix. Las herramientas de gestión que requieren un nombre único deben combinar el id_cola con la configuración myhostname de la instancia de Postfix.
tiempo_llegada
El número de segundos desde el inicio de la época UNIX.
tamano_mensaje
El número de bytes en el encabezado y el cuerpo del mensaje. Este número no incluye la información del sobre del mensaje. Es aproximadamente igual al número de bytes que se transmitirían a través de SMTP, incluidas las terminaciones de línea <CR><LF>.
expiracion_forzada
Se fuerza la expiración del mensaje (true o false). Consulte las opciones -e o -f del comando postsuper(1).

Esta característica está disponible en Postfix 3.5 y posterior.

remitente
La dirección del remitente del sobre.
destinatarios
Una matriz que contiene cero o más objetos con los miembros:
direccion
Una dirección de destinatario.
motivo_retraso
Si está presente, el motivo del retraso en la entrega. Los destinatarios retrasados pueden no tener un motivo de retraso, por ejemplo, mientras la entrega está en curso, o después de que el sistema se detuvo antes de que pudiera registrar el motivo.

SEGURIDAD

Este programa está diseñado para ejecutarse con privilegios de grupo establecidos, de modo que pueda conectarse a los procesos demonio de Postfix.

ESTANDARES

DIAGNOSTICO


Los problemas se registran en syslogd(8) o postlogd(8), y en el flujo de error estándar.

ENTORNO

MAIL_CONFIG
Directorio con el archivo main.cf. Para evitar la explotación de privilegios de grupo establecidos, solo se permite un directorio no estándar si:
  • El nombre está listado en el archivo main.cf estándar con el parámetro de configuración alternate_config_directories.
  • El comando es invocado por el superusuario.

NAME

postqueue - Postfix mail queue management

SYNOPSIS

postqueue [-p] [-f] [-i] [-s domain] [-u user]
postqueue -c config_dir [-p] [-f] [-i] [-s domain] [-u user]
postqueue -j job_id [-c config_dir] [-v]

DESCRIPTION

The postqueue command is a front-end to Postfix mail queue management commands. It can be used to send mail to the queue, or to flush, delete, or hold mail from the queue.

When invoked without options, it lists the current mail queue contents, similar to the Unix mailq command.

OPTIONS

-c config_dir
Use the specified config_dir for the Postfix configuration.
-f
Force delivery of all mail currently in the queue. This is equivalent to running sendmail(1) with the -fflush:all argument.
-i
Delete all mail with the specified recipient(s) from the queue. This is equivalent to running sendmail(1) with the -i argument.
-j job_id
Hold the specified mail job. This is equivalent to running sendmail(1) with the -j argument.
-p
List the mail queue. This is the default action when no other options are specified. This is equivalent to running mailq(1).
-s domain
Process only mail for the specified domain. This option can be specified multiple times.
-u user
Process only mail for the specified user. This option can be specified multiple times.
-v
Report verbose results. This option is only valid with the -j option.

JSON OBJECT FORMAT

The -p, -s and -u options produce JSON output when run with the -j option. The JSON output is a list of objects, each describing a message in the queue.

Each JSON object has the following members:

id
The queue message ID (e.g. 78D1F64A67).
sender
The sender address (e.g. john@example.com).
recipients
A list of recipient addresses.
arrival_time
The time the message arrived in the queue, in Unix epoch format.
size
The message size in bytes.
trace
A list of trace entries, each describing a hop the message has taken.

SECURITY

The postqueue command is typically run by root or by users with special privileges. When invoked with options that modify the queue (e.g., -f, -i, -j), it requires appropriate privileges to operate on files owned by the Postfix queue user.

The postqueue command invokes the underlying Postfix queue management commands (e.g., sendmail(1), flush(8), postsuper(1)) which perform the actual queue operations. These commands implement their own access controls and security checks.

STANDARDS

The postqueue command is largely compatible with the sendmail(1) command-line interface for queue management operations.

DIAGNOSTICS

The exit status is 0 on success, or 1 if an error occurred.

ENVIRONMENT

MAIL_CONFIG
The list of non-default Postfix configuration directories. For more information, see the description of the e_config_directories parameter.

CONFIGURATION PARAMETERS

e_config_directories (empty)
A list of non-default Postfix configuration directories that may be specified with "-c config_directory" on the command line (in the case of sendmail(1), with the "-C" option), or via the MAIL_CONFIG environment parameter.
config_directory (see 'postconf -d' output)
The default location of the Postfix main.cf and master.cf configuration files.
command_directory (see 'postconf -d' output)
The location of all postfix administrative commands.
fast_flush_domains ($relay_domains)
Optional list of destinations that are eligible for per-destination logfiles with mail that is queued to those destinations.
import_environment (see 'postconf -d' output)
The list of environment variables that a privileged Postfix process will import from a non-Postfix parent process, or name=value environment overrides.
queue_directory (see 'postconf -d' output)
The location of the Postfix top-level queue directory.
syslog_facility (mail)
The syslog facility of Postfix logging.
syslog_name (see 'postconf -d' output)
A prefix that is prepended to the process name in syslog records, so that, for example, "smtpd" becomes "prefix/smtpd".
trigger_timeout (10s)
The time limit for sending a trigger to a Postfix daemon (for example, the pickup(8) or qmgr(8) daemon).

Available in Postfix version 2.2 and later:

authorized_flush_users (static:anyone)
List of users who are authorized to flush the queue.
authorized_mailq_users (static:anyone)
List of users who are authorized to view the queue.
