POSTFIX(1) Manual de comandos generales POSTFIX(1)

NOMBRE

postfix - Programa de control de Postfix

SINOPSIS

postfix [-Dv] [-c dir_config] comando

DESCRIPCIÓN


Este comando está reservado para el superusuario. Para enviar correo, use el comando sendmail(1) de Postfix.

El comando postfix(1) controla la operación del sistema de correo Postfix: iniciar o detener el demonio master(8), realizar una verificación de estado y otro mantenimiento.

Por defecto, el comando postfix(1) configura un entorno estandarizado y ejecuta el script shell postfix-script para realizar el trabajo real.

Sin embargo, cuando se configura el soporte para múltiples instancias de Postfix, postfix(1) ejecuta el comando especificado con el parámetro de configuración multi_instance_wrapper. Este comando ejecutará el comando para cada instancia de Postfix aplicable.

Los siguientes comandos están implementados:

check
Advierte sobre la propiedad o permisos incorrectos de directorios/archivos, y crea directorios faltantes.
start
Inicia el sistema de correo Postfix. Esto también ejecuta la verificación de configuración descrita anteriormente.
start-fg
Similar a start, pero mantiene el demonio master(8) ejecutándose en primer plano y habilita el modo "init" de master(8) cuando se ejecuta como PID 1. Este comando requiere que el soporte multi-instancia esté deshabilitado (es decir, el valor del parámetro multi_instance_directories debe estar vacío).

Al ejecutar Postfix dentro de un contenedor, consulte MAILLOG_README para registrar en stdout. Postfix registra en syslog por defecto, lo que requiere a) ejecutar un proceso syslogd dentro del contenedor, o b) montar el socket /dev/log del host del contenedor dentro del contenedor (ejemplo: "docker run -v /dev/log:/dev/log ..."), y c) un prefijo distinto de "syslog_name" de Postfix que identifique el registro de la instancia de Postfix.

stop
Detiene el sistema de correo Postfix de forma ordenada. Si es posible, se permite que los procesos en ejecución terminen a su conveniencia más temprana.

Nota: para actualizar el sistema de correo Postfix después de un cambio de configuración, no utilice los comandos start y stop en sucesión. Utilice el comando reload en su lugar.

abort
Detiene el sistema de correo Postfix abruptamente. Se señala a los procesos en ejecución que se detengan inmediatamente.
flush
Forzar entrega: intenta entregar cada mensaje en la cola de correo diferido. Normalmente, los intentos de entregar correo retrasado ocurren a intervalos regulares, y el intervalo se duplica después de cada intento fallido.

Advertencia: vaciar el correo no entregable con frecuencia provocará un bajo rendimiento de entrega de todo el demás correo.

reload
Relee los archivos de configuración. Los procesos en ejecución terminan a su conveniencia más temprana.
status
Indica si el sistema de correo Postfix se está ejecutando actualmente (código de salida cero) o está detenido (código de salida distinto de cero).
set-permissions [nombre=valor ...]
Establece la propiedad y los permisos de los archivos y directorios relacionados con Postfix, como se especifica en el archivo postfix-files.

Especifique nombre=valor para anular y actualizar parámetros de configuración específicos de main.cf. Úselo, por ejemplo, para cambiar la configuración mail_owner o setgid_group para un sistema Postfix ya instalado.

Esta función está disponible en Postfix 2.1 y posteriores. Con Postfix 2.0 y anteriores, use "$config_directory/post-install set-permissions".

logrotate
Rota el archivo de registro especificado con $maillog_file, agregando un sufijo de marca de tiempo con formato según $maillog_file_rotate_suffix, y comprimiendo el archivo con el comando especificado con $maillog_file_compressor. Esto no rotará archivos /dev/*.

Esta función está disponible en Postfix 3.4 y posteriores.

tls subcomando
Habilita TLS opcional en el cliente o servidor SMTP de Postfix y administra las claves privadas y los certificados TLS del servidor SMTP de Postfix. Consulte postfix-tls(1) para obtener documentación.

Esta función está disponible en Postfix 3.1 y posteriores.

upgrade-configuration [nombre=valor ...]
Actualiza los archivos main.cf y master.cf con la información que Postfix necesita para ejecutarse: agrega o actualiza servicios, y agrega o actualiza la configuración de parámetros.

Especifique nombre=valor para anular y actualizar parámetros de configuración específicos de main.cf.

Esta función está disponible en Postfix 2.1 y posteriores. Con Postfix 2.0 y anteriores, use "$config_directory/post-install upgrade-configuration".

Las siguientes opciones están implementadas:

-c dir_config
Lee los archivos de configuración main.cf y master.cf en el directorio especificado en lugar del directorio de configuración predeterminado. Úselo para distinguir entre múltiples instancias de Postfix en el mismo host.

Con Postfix 2.6 y posteriores, esta opción fuerza al comando postfix(1) a operar solo en la instancia de Postfix especificada. Este comportamiento es heredado por los comandos de postfix(1) que se ejecutan como descendientes del proceso actual.

-D (solo con postfix start)
Ejecuta cada demonio de Postfix bajo el control de un depurador según lo especificado a través del parámetro de configuración debugger_command.
-v
Habilita el registro detallado para fines de depuración. Múltiples opciones -v hacen que el software sea cada vez más detallado.

ENTORNO

El comando postfix(1) exporta las siguientes variables de entorno antes de ejecutar el archivo postfix-script:

MAIL_CONFIG
Se establece cuando está presente la opción de línea de comandos -c.

Con Postfix 2.6 y posteriores, esta variable de entorno fuerza al comando postfix(1) a operar solo en la instancia de Postfix especificada. Este comportamiento es heredado por los comandos de postfix(1) que se ejecutan como descendientes del proceso actual.

MAIL_VERBOSE
Se establece cuando está presente la opción de línea de comandos -v.
MAIL_DEBUG
Se establece cuando está presente la opción de línea de comandos -D.

Cuando el servicio de registro interno está habilitado (al establecer un valor de parámetro maillog_file no vacío), el comando postfix(1) exporta configuraciones que son utilizadas por los procesos hijos antes de que hayan procesado main.cf o las configuraciones de línea de comandos.

POSTLOG_SERVICE
El nombre del punto final del servicio público postlog.
POSTLOG_HOSTNAME
El nombre de host que se antepone al registro interno.

PARÁMETROS DE CONFIGURACIÓN

Los siguientes parámetros de configuración de main.cf se exportan como variables de entorno con los mismos nombres:

config_directory (ver la salida de 'postconf -d')
La ubicación predeterminada de los archivos de configuración main.cf y master.cf de Postfix.
command_d

PARÁMETROS DE CONFIGURACIÓN

Estos son los parámetros de configuración que controlan la instalación y el comportamiento de Postfix.

config_directory (see 'postconf -d' output)
El directorio con los archivos de configuración de Postfix, como main.cf y master.cf.
command_directory (see 'postconf -d' output)
La ubicación de todos los comandos administrativos de Postfix.
daemon_directory (see 'postconf -d' output)
El directorio con los programas de soporte y los programas demonio de Postfix.
html_directory (see 'postconf -d' output)
La ubicación de los archivos HTML de Postfix que describen cómo construir, configurar u operar un subsistema o característica específica de Postfix.
mail_owner (postfix)
La cuenta del sistema UNIX que es propietaria de la cola de Postfix y de la mayoría de los procesos demonio de Postfix.
mailq_path (see 'postconf -d' output)
Característica de compatibilidad con Sendmail que especifica dónde está instalado el comando Postfix mailq(1).
manpage_directory (see 'postconf -d' output)
Dónde están instaladas las páginas del manual de Postfix.
newaliases_path (see 'postconf -d' output)
Característica de compatibilidad con Sendmail que especifica la ubicación del comando newaliases(1) de Postfix.
queue_directory (see 'postconf -d' output)
La ubicación del directorio de cola principal de Postfix.
readme_directory (see 'postconf -d' output)
La ubicación de los archivos README de Postfix que describen cómo construir, configurar u operar un subsistema o característica específica de Postfix.
sendmail_path (see 'postconf -d' output)
Una característica de compatibilidad con Sendmail que especifica la ubicación del comando sendmail(1) de Postfix.
setgid_group (postdrop)
La propiedad de grupo de los comandos Postfix con el bit set-gid y de los directorios de Postfix escribibles por grupo.

Disponible en la versión 2.5 de Postfix y posteriores:

data_directory (see 'postconf -d' output)
El directorio con archivos de datos escribibles por Postfix (por ejemplo: cachés, números pseudoaleatorios).

Disponible en la versión 3.0 de Postfix y posteriores:

compatibility_level (0)
Una red de seguridad que hace que Postfix se ejecute con configuraciones predeterminadas compatibles hacia atrás después de una actualización a una versión más nueva de Postfix.
meta_directory (see 'postconf -d' output)
La ubicación de los archivos no ejecutables que se comparten entre múltiples instancias de Postfix, como postfix-files, dynamicmaps.cf y los archivos de plantilla multi-instancia main.cf.proto y master.cf.proto.
shlib_directory (see 'postconf -d' output)
La ubicación de las bibliotecas enlazadas dinámicamente de Postfix (libpostfix-*.so) y la ubicación predeterminada de los plugins de base de datos de Postfix (postfix-*.so) que tienen una ruta relativa en el archivo dynamicmaps.cf.

Disponible en la versión 3.1 de Postfix y posteriores:

openssl_path (openssl)
La ubicación del programa de línea de comandos de OpenSSL openssl(1).

Otros parámetros de configuración:

import_environment (see 'postconf -d' output)
La lista de variables de entorno que un proceso privilegiado de Postfix importará de un proceso padre que no sea de Postfix, o anulaciones de entorno nombre=valor.
syslog_facility (mail)
La facilidad de syslog para el registro de Postfix.
syslog_name (see 'postconf -d' output)
Un prefijo que se antepone al nombre del proceso en los registros de syslog, de modo que, por ejemplo, "smtpd" se convierta en "prefix/smtpd".

Disponible en la versión 2.6 de Postfix y posteriores:

multi_instance_directories (empty)
Una lista opcional de directorios de configuración de Postfix no predeterminados; estos directorios pertenecen a instancias adicionales de Postfix que comparten los archivos ejecutables y la documentación de Postfix con la instancia predeterminada de Postfix, y que se inician, detienen, etc., junto con la instancia predeterminada de Postfix.
multi_instance_wrapper (empty)
La ruta del comando administrador de múltiples instancias que invoca el comando postfix(1) cuando el valor del parámetro multi_instance_directories no está vacío.
multi_instance_group (empty)
El nombre opcional del grupo de instancias de esta instancia de Postfix.
multi_instance_name (empty)
El nombre opcional de la instancia de esta instancia de Postfix.
multi_instance_enable (no)
Permitir que esta instancia de Postfix sea iniciada, detenida, etc., por un administrador de múltiples instancias.

Disponible en la versión 3.4 de Postfix y posteriores:

maillog_file (empty)
El nombre de un archivo de registro opcional en el que escribe el servicio postlogd(8) de Postfix.
maillog_file_compressor (gzip)
El programa a ejecutar después de rotar $maillog_file con "postfix logrotate".
maillog_file_prefixes (/var, /dev/stdout)
Una lista de prefijos permitidos para un valor de maillog_file.
maillog_file_rotate_suffix (%Y%m%d-%H%M%S)
El formato del sufijo a añadir a $maillog_file al rotar el archivo con "postfix logrotate".
postlog_service_name (postlog)
El nombre de la entrada del servicio postlogd(8) en master.cf.

ARCHIVOS

Antes de la versión 2.6 de Postfix, todos los siguientes archivos estaban en $config_directory. Algunos archivos se encuentran ahora en $daemon_directory o $meta_directory para que puedan ser compartidos entre múltiples instancias que ejecutan la misma versión de Postfix.

Utilice el comando "postconf config_directory" o "postconf daemon_directory" para expandir los nombres a sus valores reales.

postfix(1) - Arch Linux man pages

NAME

postfix - Postfix multi-platform mail system

SYNOPSIS

/usr/sbin/postfix [-c config_dir] [-e command] [-i] [-m] [-N] [-P] [-q queue_name] [-t] [-v]

DESCRIPTION

The postfix command is the Postfix mail system controller. It starts, stops, and reconfigures Postfix daemons, and controls the mail queue.

The Postfix mail system is a suite of daemons that together provide a general-purpose mail-transport and delivery agent.

The default configuration directory is /etc/postfix. Use the -c option to override this.

The postfix command is typically invoked by administrator scripts, not directly by users.

ENVIRONMENT

MAIL_CONFIG
The default configuration directory is /etc/postfix. This can be overridden by the MAIL_CONFIG environment variable.

CONFIGURATION PARAMETERS

The primary Postfix configuration file is main.cf. Some parameters are documented in the online help or in the README_FILES. Others are documented in the inline comments of the Postfix distribution's main.cf.default file.

Use the command "postconf parameter-name" to view the value of a parameter.
