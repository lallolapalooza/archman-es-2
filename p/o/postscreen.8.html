POSTSCREEN(8) Manual del Administrador del Sistema POSTSCREEN(8)

NOMBRE

postscreen - Bloqueador de zombies de Postfix

SINOPSIS

postscreen [opciones genéricas de demonio de Postfix]

DESCRIPCIÓN


El servidor postscreen(8) de Postfix proporciona protección adicional contra la sobrecarga del servidor de correo. Un proceso postscreen(8) maneja múltiples conexiones SMTP entrantes y decide qué clientes pueden hablar con un proceso de servidor SMTP de Postfix. Al mantener alejados a los spambots, postscreen(8) deja más procesos de servidor SMTP disponibles para clientes legítimos y retrasa la aparición de condiciones de sobrecarga del servidor.

Este programa no debe usarse en puertos SMTP que reciban correo de clientes de usuario final (MUA). En una implementación típica, postscreen(8) maneja el servicio MX en el puerto TCP 25, y smtpd(8) recibe correo de MUA en el servicio submission (puerto TCP 587) que requiere autenticación del cliente. Alternativamente, un sitio podría configurar un servidor dedicado, no postscreen, en el "puerto 25" que proporcione el servicio submission y autenticación del cliente, pero ningún servicio MX.

postscreen(8) mantiene una lista temporal de permitidos para clientes que han pasado una serie de pruebas. Cuando una dirección IP de cliente SMTP está en la lista de permitidos, postscreen(8) transfiere la conexión inmediatamente a un proceso de servidor SMTP de Postfix. Esto minimiza la sobrecarga para el correo legítimo.

Por defecto, postscreen(8) registra estadísticas y transfiere cada conexión a un proceso de servidor SMTP de Postfix, mientras excluye a los clientes en mynetworks de todas las pruebas (principalmente, para evitar problemas con implementaciones SMTP no estándar en dispositivos de red). Este modo predeterminado no bloquea ningún cliente y es útil para pruebas no destructivas.

En un entorno de producción típico, postscreen(8) está configurado para rechazar correo de clientes que fallan una o más pruebas. postscreen(8) registra el correo rechazado con la dirección del cliente, helo, remitente y información del destinatario.

postscreen(8) no es un proxy SMTP; esto es intencional. El propósito es mantener a los spambots alejados de los procesos del servidor SMTP de Postfix, minimizando la sobrecarga para el tráfico legítimo.

SEGURIDAD

El servidor postscreen(8) es moderadamente sensible a la seguridad. Habla con clientes no confiables en la red. El proceso puede ejecutarse en un entorno chrooted con privilegios bajos y fijos.

DIAGNÓSTICOS


Los problemas y transacciones se registran en syslogd(8) o postlogd(8).

ERRORES CONOCIDOS


El motor de protocolo SMTP incorporado de postscreen(8) actualmente no anuncia soporte para AUTH, XCLIENT o XFORWARD. Si necesita hacer que estos servicios estén disponibles en el puerto 25, entonces no habilite las pruebas opcionales "después del saludo del servidor 220".

Las pruebas opcionales "después del saludo del servidor 220" pueden resultar en retrasos inesperados en la entrega por parte de remitentes que reintentan la entrega de correo desde una dirección IP diferente. Razón: después de pasar estas pruebas, un nuevo cliente debe desconectarse y volver a conectarse desde la misma dirección IP antes de que pueda entregar el correo. Consulte POSTSCREEN_README, sección "Pruebas después del saludo del servidor SMTP 220", para una discusión.

PARÁMETROS DE CONFIGURACIÓN

Los cambios en main.cf no se detectan automáticamente, ya que los procesos postscreen(8) pueden ejecutarse durante varias horas. Use el comando "postfix reload" después de un cambio de configuración.

El texto a continuación proporciona solo un resumen de los parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

NOTA: Algunos parámetros de postscreen(8) implementan comportamiento dependiente del estrés. Esto solo se admite cuando el valor del parámetro predeterminado depende del estrés (es decir, parece ${stress?{X}:{Y}}, o es el $nombre de un parámetro smtpd con un valor predeterminado dependiente del estrés). Otros parámetros siempre se evalúan como si el valor del parámetro stress fuera una cadena vacía.

ORDEN DE LAS PRUEBAS

Las pruebas se ejecutan en el siguiente orden:

  1. PERMANENT ALLOW/DENYLIST TEST
  2. MAIL EXCHANGER POLICY TESTS
  3. BEFORE 220 GREETING TESTS
  4. AFTER 220 GREETING TESTS

Las pruebas se detienen tan pronto como una prueba tiene un resultado que requiere una acción por parte de postscreen(8).

EJEMPLOS

Habilitar el filtrado de spam basado en DNSBL y la espera de saludo:

# main.cf
postscreen_dnsbl_sites = zen.spamhaus.org
postscreen_dnsbl_threshold = 1
postscreen_greet_delay = 5s

Permitir que los clientes de confianza pasen las comprobaciones de DNSBL y saludo:

# main.cf
postscreen_access_list = permit_mynetworks, cidr:/etc/postfix/postscreen_access
postscreen_dnsbl_sites = zen.spamhaus.org
postscreen_dnsbl_threshold = 2
postscreen_greet_barrier = 1s

Para usar el archivo /etc/postfix/postscreen_access:

# /etc/postfix/postscreen_access
192.168.0.0/24 permit
10.0.0.1 permit

También se recomienda encarecidamente el uso del archivo de registro de DNSBL en el sistema de registro de Postfix.

# main.cf
postscreen_dnsbl_action = log: postscreen_dnsbl

Para ver los resultados del registro, ejecute:

$ tail -f /var/log/mail.log

Para ver el registro de las listas blancas temporales y permanentes, ejecute:

$ postcat -q -PH postscreen-cache

ERRORES

La comprobación postscreen_bare_newline_enable puede causar falsos positivos en el caso de que el cliente SMTP no envíe un retorno de carro antes de una nueva línea. Esto se debe a que el resultado de la comprobación de los caracteres de nueva línea sin formato no se almacena en caché.

NAME

postscreen - Postfix SMTP proxy daemon

SYNOPSIS

postscreen [-a] [-e] [-h] [-l] [-p] [-v]

DESCRIPTION

The postscreen daemon is a network server that sits in front of the Postfix SMTP server (smtpd(8)). It rejects mail from unwanted clients based on a variety of criteria, before the mail reaches the Postfix SMTP server.

The primary purpose of postscreen is to reduce the load on the Postfix SMTP server (smtpd(8)) by rejecting obviously spamming clients as early as possible.

postscreen implements a set of tests that can be applied to incoming SMTP connections. These tests are executed in order, and if a client fails any test, the connection is immediately closed, and the client is blocked from reconnecting for a while.

The tests are:

pre-connect tests
These tests are performed before the SMTP protocol handshake begins. They include DNS-based tests (like DNSBL lookups), and tests based on the client's IP address history.
SMTP protocol tests
These tests are performed during the SMTP protocol handshake. They include checks for bare newlines, unknown commands, incorrect command order, and protocol violations.
access control tests
These tests use Postfix's standard access control tables to permit or reject clients based on their IP address, hostname, or other criteria.
rate limiting tests
These tests limit the number of connections or commands allowed from a client within a given time period.

A successful client passes all the tests and is then forwarded to the Postfix SMTP server (smtpd(8)) for normal SMTP processing.

The postscreen daemon runs as a separate process, listening on the SMTP port (25) or a dedicated port specified in master.cf. When a client connects, postscreen performs its tests. If the client passes, postscreen forwards the connection to a Postf ix SMTP server process. All tests and their results are logged to the system log.

SECURITY

The postscreen daemon handles network connections and executes external commands (e.g., DNS lookups). It should be run with minimal privileges. The default configuration runs it as the postscreen user.

STANDARDS

RFC 5965 (Postscreen is inspired by this RFC, but not compliant)

DIAGNOSTICS

The postscreen daemon logs its actions to the system log using the facility specified by syslog_facility and the name specified by syslog_name. Diagnostic information includes connection attempts, test results, and any errors encountered.

BUGS

The history of Postfix support for bare newline filtering dates back to RFC 1854, and has been problematic. The postscreen bare newline filter is not intended as a replacement for the SMTP server's bare newline filter.

NAME

postscreen - Postfix 3.6.4 advanced spam blocking

SYNOPSIS

postscreen

DESCRIPTION

El demonio postscreen se ejecuta en el puerto 25 (o en el puerto configurado) y realiza la mayor parte del trabajo de filtrado de spam, dejando que el demonio smtpd de Postfix maneje solo la última fase de la entrega de correo. El objetivo es mantener la carga de la CPU lo más baja posible, haciendo que los spambots desperdicien sus recursos al tratar con postscreen en lugar de con smtpd.

postscreen requiere un entorno de ejecución específico para funcionar correctamente. Este entorno es proporcionado por el script master.cf de Postfix. Consulta el ejemplo master.cf en la sección de ejemplos de esta página de manual.

HOW IT WORKS

postscreen actúa como un proxy inverso para el demonio smtpd de Postfix. Espera las conexiones SMTP entrantes y las somete a una serie de pruebas automatizadas. Solo si un cliente pasa estas pruebas, se le permite conectarse al demonio smtpd de Postfix para completar la entrega del correo.

Las pruebas se dividen en dos categorías:

  • Pruebas permanentes: Estas pruebas verifican el comportamiento del cliente y se aplican de forma permanente. Si un cliente falla una prueba permanente, se bloquea indefinidamente.
  • Pruebas temporales: Estas pruebas verifican el comportamiento del cliente y se aplican solo temporalmente. Si un cliente falla una prueba temporal, se le impide conectarse por un período de tiempo limitado.

postscreen utiliza una base de datos en memoria (con volcados a disco) para realizar un seguimiento de los resultados de las pruebas y la información de los clientes. Esto permite un seguimiento rápido y eficiente del comportamiento de los clientes.

SECURITY

postscreen no se comunica directamente con la red externa. En su lugar, se comunica con el demonio smtpd de Postfix a través de un socket de dominio Unix. Esto evita la posibilidad de que un atacante intente eludir las protecciones de postscreen conectándose directamente a smtpd.
