PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

posix_openpt — abre un dispositivo de pseudo-terminal

SINOPSIS

#include <stdlib.h>
#include <fcntl.h>
int posix_openpt(int oflag);

DESCRIPCIÓN

La función posix_openpt() establecerá una conexión entre un dispositivo maestro para una pseudo-terminal y un descriptor de archivo. El descriptor de archivo se asignará como se describe en la Sección 2.14, Asignación de Descriptores de Archivo y podrá ser utilizado por otras funciones de E/S que hagan referencia a esa pseudo-terminal.

Las banderas de estado del archivo y los modos de acceso al archivo de la descripción del archivo abierto se establecerán de acuerdo con el valor de oflag.

Los valores de oflag se construyen mediante una OR inclusiva a nivel de bits de las banderas de la siguiente lista, definidas en <fcntl.h>:

O_RDWR
Abrir para lectura y escritura.
O_NOCTTY
Si se establece, posix_openpt() no hará que el dispositivo terminal se convierta en la terminal de control del proceso.

El comportamiento de otros valores para el argumento oflag no está especificado.

VALOR DE RETORNO

Al completarse con éxito, la función posix_openpt() abrirá un descriptor de archivo para un dispositivo maestro de pseudo-terminal y devolverá un entero no negativo que representa el descriptor de archivo. De lo contrario, se devolverá -1 y se establecerá errno para indicar el error.

ERRORES

La función posix_openpt() fallará si:

EMFILE
Todos los descriptores de archivo disponibles para el proceso están actualmente abiertos.
ENFILE
El número máximo de archivos permitido está actualmente abierto en el sistema.

La función posix_openpt() puede fallar si:

EINVAL
El valor de oflag no es válido.
EAGAIN
Sin recursos de pseudo-terminal.
ENOSR
Sin recursos STREAMS.

Las siguientes secciones son informativas.

EJEMPLOS

Abrir una Pseudo-Terminal y Devolver el Nombre del Dispositivo Esclavo y un Descriptor de Archivo

#include <fcntl.h>
#include <stdio.h>
int masterfd, slavefd;
char *slavedevice;
masterfd = posix_openpt(O_RDWR|O_NOCTTY);
if (masterfd == -1
    || grantpt (masterfd) == -1
    || unlockpt (masterfd) == -1
    || (slavedevice = ptsname (masterfd)) == NULL)
    return -1;
printf("el dispositivo esclavo es: %s\n", slavedevice);
slavefd = open(slavedevice, O_RDWR|O_NOCTTY);
if (slavefd < 0)
    return -1;

USO DE LA APLICACIÓN

Esta función es un método para obtener de forma portable un descriptor de archivo de un dispositivo maestro de terminal para una pseudo-terminal. Las funciones grantpt() y ptsname() se pueden usar para manipular los permisos de modo y propiedad, y para obtener el nombre del dispositivo esclavo, respectivamente.

FUNDAMENTO

Los desarrolladores del estándar consideraron la cuestión de añadir un dispositivo especial para clonar pseudo-terminales maestras: el dispositivo /dev/ptmx. Sin embargo, no se alcanzó un consenso y se consideró que añadir una nueva función permitiría otras implementaciones. La función posix_openpt() está diseñada para complementar las funciones grantpt(), ptsname() y unlockpt().

En implementaciones que soportan el dispositivo de clonación /dev/ptmx, abrir el dispositivo maestro de una pseudo-terminal es simplemente:

mfdp = open("/dev/ptmx", oflag );
if (mfdp < 0)
    return -1;

posix_openpt(3p)

NOMBRE

posix_openpt - abrir un pseudoterminal maestro

SINOPSIS

#include <stdlib.h>

int posix_openpt(int oflag);

DESCRIPCIÓN

La función posix_openpt() abre un pseudoterminal (PTY) maestro y devuelve un descriptor de archivo para el PTY maestro abierto.

El argumento oflag es una combinación de banderas que controlan el modo de apertura del PTY maestro. Las banderas permitidas son las mismas que las que se pueden pasar a la llamada al sistema open(2). Sin embargo, se debe especificar exactamente una de las banderas de acceso O_RDONLY, O_RDWR u O_WRONLY.

Si la llamada tiene éxito, el descriptor de archivo devuelto se puede usar para controlar el PTY maestro. El PTY esclavo asociado se puede encontrar usando el nombre de ruta devuelto por la llamada a la función ptsname(3).

VALOR DE RETORNO

En caso de éxito, posix_openpt() devuelve un descriptor de archivo para el PTY maestro abierto. En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORES

EACCES
El Oflag especificado no está permitido.
EMFILE
El proceso ha alcanzado el límite de descriptores de archivo abiertos.
EINVAL
El valor especificado en oflag no es válido.
ENFILE
Se ha alcanzado el límite máximo de descriptores de archivo en el sistema.
ENOENT
No se pudo crear el PTY maestro.
ENOSPC
No hay espacio suficiente en el sistema para crear el PTY maestro.
ENOMEM
No hay memoria suficiente en el sistema para crear el PTY maestro.

EJEMPLO

El siguiente ejemplo abre un PTY maestro y luego obtiene el nombre del PTY esclavo asociado:

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>

int main(void) {
    int master_fd;
    char *slave_name;

    master_fd = posix_openpt(O_RDWR | O_NOCTTY | O_NONBLOCK);
    if (master_fd == -1) {
        perror("posix_openpt");
        exit(EXIT_FAILURE);
    }

    slave_name = ptsname(master_fd);
    if (slave_name == NULL) {
        perror("ptsname");
        close(master_fd);
        exit(EXIT_FAILURE);
    }

    printf("PTY maestro abierto, descriptor de archivo: %d\n", master_fd);
    printf("PTY esclavo: %s\n", slave_name);

    // ... hacer algo con el PTY maestro y esclavo ...

    close(master_fd);
    exit(EXIT_SUCCESS);
}

NORMATIVA

La función posix_openpt() está definida por el estándar POSIX.1-2017.
