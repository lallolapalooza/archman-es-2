NOMBRE

podman-image-trust - Gestiona la política de confianza de imágenes de registros de contenedores

SINOPSIS

podman image trust set|show [opciones] registro[/repositorio]

DESCRIPCIÓN

Gestiona qué registros son de confianza como fuente de imágenes de contenedores basándose en su ubicación. (Esta opción no está disponible con el cliente remoto de Podman, incluidas las máquinas Mac y Windows (excepto WSL2)).

La ubicación se determina por el transporte y el host del registro de la imagen. Usando la imagen de contenedor docker://docker.io/library/busybox como ejemplo, docker es el transporte y docker.io es el host del registro.

La confianza se define en /etc/containers/policy.json y se aplica cuando un usuario intenta descargar una imagen remota de un registro. La política de confianza en policy.json describe un ámbito de registro (registro y/o repositorio) para la confianza. Esta confianza puede usar claves públicas para imágenes firmadas.

El ámbito de la confianza se evalúa de lo más específico a lo menos específico. En otras palabras, una política puede ser:

  • Definida para un registro completo.
  • Definida para un repositorio particular en ese registro.
  • Definida para una imagen firmada específica dentro del registro.

La siguiente lista son ejemplos de valores de ámbito válidos utilizados en policy.json de lo más específico a lo menos específico:

docker.io/library/busybox:notlatest

docker.io/library/busybox

docker.io/library

docker.io

Si no se encuentra ninguna configuración para ninguno de estos ámbitos, se utiliza el valor predeterminado (especificado usando "default" en lugar de REGISTRY[/REPOSITORY]).

El tipo de confianza proporciona una forma de:

Lista blanca ("accept") o lista negra ("reject") de registros o requerir una firma simple (“signedBy”), requerir una firma sigstore ("sigstoreSigned").

La confianza puede actualizarse usando el comando podman image trust set para un ámbito de confianza existente.

OPCIONES

--help, -h

Imprime la declaración de uso.

set OPCIONES

--pubkeysfile, -f=CLAVE1

Una ruta a una clave pública exportada en el sistema local. Las rutas de clave
se referencian en policy.json. Se puede usar cualquier ruta de archivo, pero se recomienda ubicar el archivo en /etc/pki/containers. Las opciones se pueden usar varias veces para
requerir que una imagen esté firmada por varias claves. La opción --pubkeysfile es obligatoria para los tipos signedBy y sigstoreSigned.

--type, -t=valor

El tipo de confianza para esta entrada de política.
Valores aceptados:
signedBy (predeterminado): Requiere firmas simples con la lista correspondiente de
claves públicas
sigstoreSigned: Requiere firmas sigstore con la lista correspondiente de
claves públicas
accept: no requiere ninguna firma para este
ámbito de registro
reject: no acepta imágenes para este ámbito de registro

show OPCIONES

--json, -j

Muestra la confianza como JSON para el análisis por máquinas

--noheading, -n

Omite los encabezados de la tabla del listado.

--raw

Muestra el archivo de política de confianza como JSON sin procesar

EJEMPLOS

Aceptar todas las imágenes sin firmar de un registro:

sudo podman image trust set --type accept docker.io

Modificar la política de confianza predeterminada:

sudo podman image trust set -t reject default

NAME

podman-image-trust - Manage trust for container images

SYNOPSIS

podman image trust [options] IMAGE...

podman image trust --add [options] IMAGE...

podman image trust --remove [options] IMAGE...

podman image trust --list [options]

DESCRIPTION

Manage trust for container images. This command allows you to add, remove, and list images that are trusted by Podman. Trust is established by signing images with a GPG key and storing the public key of the signer in a trusted certificate store.

OPTIONS

--add, -a

Add the specified images to the trusted list. This implies signing the images with a GPG key.

--remove, -r

Remove the specified images from the trusted list.

--list, -l

List all trusted images.

--sign-by keyid

Specify the GPG key ID to use for signing images when adding them to the trusted list.

--cert-dir dir

Specify the directory where trusted GPG keys are stored. Defaults to $HOME/.config/containers/})^{#trusted-ca-dir}.

--policy policy

Specify a policy file to use for image trust verification. See containers-policy.json(5) for more information.

--help, -h

Print usage information.

EXAMPLES

Add an image to the trusted list:

$ podman image trust --add myregistry.com/myimage:latest

Add an image signed by a specific key:

$ podman image trust --add --sign-by 0xDEADBEEF myregistry.com/myimage:latest

Remove an image from the trusted list:

$ podman image trust --remove myregistry.com/myimage:latest

List all trusted images:

$ podman image trust --list
