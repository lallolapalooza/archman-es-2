NOMBRE

podman-container-clone - Crear una copia de un contenedor existente

SINOPSIS

podman container clone [opciones] contenedor nombre imagen

DESCRIPCIÓN

podman container clone crea una copia de un contenedor, recreando el original con una configuración idéntica. Este comando toma tres argumentos: el primero es el ID o nombre del contenedor a clonar, el segundo argumento en este comando puede cambiar el nombre del clon desde el predeterminado de $NOMBRE_ORIGINAL-clone, y el tercero es una nueva imagen a utilizar en el contenedor clonado.

OPCIONES

--blkio-weight=peso

Peso relativo de Block IO. El peso es un valor entre 10 y 1000.

Esta opción no es compatible con sistemas sin root cgroups V1.

--blkio-weight-device=dispositivo:peso

Peso relativo del dispositivo de Block IO.

--cpu-period=límite

Establece el período de CPU para el Completely Fair Scheduler (CFS), que es una duración en microsegundos. Una vez que la cuota de CPU del contenedor se agota, no se programará para ejecutarse hasta que finalice el período actual. El valor predeterminado es 100000 microsegundos.

En algunos sistemas, cambiar los límites de recursos puede no estar permitido para usuarios no root. Para más detalles, ver https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Esta opción no es compatible con sistemas sin root cgroups V1.

Si no se especifica ninguno, se utiliza el período de CPU del contenedor original.

--cpu-quota=límite

Límite de la cuota Completely Fair Scheduler (CFS) de la CPU.

Limita el uso de CPU del contenedor. Por defecto, los contenedores se ejecutan con todos los recursos de CPU. El límite es un número en microsegundos. Si se proporciona un número, al contenedor se le permite usar esa cantidad de tiempo de CPU hasta que finalice el período de CPU (controlable mediante --cpu-period).

En algunos sistemas, cambiar los límites de recursos puede no estar permitido para usuarios no root. Para más detalles, ver https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Esta opción no es compatible con sistemas sin root cgroups V1.

Si no se especifica ninguno, se utiliza la cuota de CPU del contenedor original.

--cpu-rt-period=microsegundos

Límite del período de tiempo real de la CPU en microsegundos.

Limita el uso de la CPU en tiempo real del contenedor. Esta opción indica al kernel que restrinja el uso de la CPU en tiempo real del contenedor al período especificado.

Esta opción solo es compatible con sistemas con root cgroups V1.

Si no se especifica ninguno, se utiliza el período de tiempo de ejecución de la CPU del contenedor original.

--cpu-rt-runtime=microsegundos

Límite del tiempo de ejecución en tiempo real de la CPU en microsegundos.

Limita el uso del tiempo de ejecución de la CPU en tiempo real del contenedor. Esta opción indica al kernel que limite la cantidad de tiempo que las tareas de tiempo real pueden consumir en un período de CPU dado. Por ejemplo: un período de 1.000.000 µs y un tiempo de ejecución de 950.000 µs significa que este contenedor puede consumir el 95% de la CPU disponible y dejar el 5% restante para tareas de prioridad normal.

La suma de todos los tiempos de ejecución entre contenedores no puede exceder la cantidad asignada al cgroup padre.

Esta opción solo es compatible con sistemas con root cgroups V1.

--cpu-shares, -c=acciones

Acciones de CPU (peso relativo).

Por defecto, todos los contenedores obtienen la misma proporción de ciclos de CPU. Esta proporción se puede modificar cambiando el peso de las acciones de CPU del contenedor en relación con el peso combinado de todos los contenedores en ejecución. El peso predeterminado es 1024.

La proporción solo se aplica cuando se ejecutan procesos que consumen mucha CPU. Cuando las tareas de un contenedor están inactivas, otros contenedores pueden usar el tiempo de CPU sobrante. La cantidad real de tiempo de CPU varía según el número de contenedores en ejecución en el sistema.

Por ejemplo, considere tres contenedores, uno tiene una acción de CPU de 1024 y otros dos tienen una configuración de acción de CPU de 512. Cuando los procesos en los tres contenedores intentan usar el 100% de la CPU, el primer contenedor recibe el 50% del tiempo total de CPU. Si se agrega un cuarto contenedor con una acción de CPU de 1024, el primer contenedor solo obtiene el 33% de la CPU. Los contenedores restantes reciben el 16.5%, 16.5% y 33% de la CPU.

En un sistema multinúcleo, las acciones de tiempo de CPU se distribuyen en todos los núcleos de CPU. Incluso si un contenedor está limitado a menos del 100% del tiempo de CPU, puede usar el 100% de cada núcleo de CPU individual.

Por ejemplo, considere un sistema con más de tres núcleos. Si el contenedor C0 se inicia con --cpu-shares=512 ejecutando un proceso, y otro contenedor C1 con --cpu-shares=1024 ejecutando dos procesos, esto puede resultar en la siguiente división de acciones de CPU:

PID contenedor CPU Acción de CPU
100 C0 0 100% de CPU0
101 C1 1 100% de CPU1
102 C1 2 100% de CPU2

En algunos sistemas, cambiar los límites de recursos puede no estar permitido para usuarios no root. Para más detalles, ver https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Esta opción no es compatible con sistemas sin root cgroups V1.

Si no se especifican, se utilizan las acciones de CPU del contenedor original.

--cpus

Establece un número de CPUs para el contenedor que reemplaza los límites de CPU del contenedor original. Si no se especifica ninguno, se utilizan los Nano CPUs del contenedor original.

Esto es un atajo para --cpu-period y --cpu-quota, por lo que solo se puede establecer --cpus o ambos --cpu-period y --cpu-quota.

Esta opción no es compatible con sistemas sin root cgroups V1.

--cpuset-cpus=número

CPUs en las que permitir la ejecución. Se puede especificar como una lista separada por comas (por ejemplo, 0,1), como un rango (por ejemplo, 0-3), o cualquier combinación de ellos (por ejemplo, 0-3,7,11-15).

En algunos sistemas, cambiar los límites de recursos puede no estar permitido para usuarios no root. Para más detalles, ver https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Esta opción no es compatible con sistemas sin root cgroups V1.

Si no se especifica ninguno, se utiliza el cpuset de CPU del contenedor original.

--cpuset-mems=nodos

Nodos de memoria (MEMs) en los que permitir la ejecución (0-3, 0,1). Solo efectivo en sistemas NUMA.

Si hay cuatro nodos de memoria en el sistema (0-3), usa --cpuset-mems=0,1 y los procesos en el contenedor solo usarán memoria de los dos primeros nodos de memoria.

En algunos sistemas, cambiar los límites de recursos puede no estar permitido para usuarios no root. Para más detalles, ver https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Esta opción no es compatible con sistemas sin root cgroups V1.

Si no se especifica ninguno, se utilizan los nodos de memoria de CPU del contenedor original.

--destroy

Elimina el contenedor original que estamos clonando una vez utilizado para imitar la configuración.

--device-read-bps=ruta:tasa

Limita la tasa de lectura (en bytes por segundo) de un dispositivo (ej. --device-read-bps=/dev/sda:1mb).

En algunos sistemas, el cambio de los límites de recursos puede no estar permitido para usuarios no root. Para más detalles, ver https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Esta opción no es compatible con sistemas sin root de cgroups V1.

--device-write-bps=ruta:tasa

Limita la tasa de escritura (en bytes por segundo) a un dispositivo (ej. --device-write-bps=/dev/sda:1mb).

En algunos sistemas, el cambio de los límites de recursos puede no estar permitido para usuarios no root. Para más detalles, ver https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Esta opción no es compatible con sistemas sin root de cgroups V1.

--force, -f

Fuerza la eliminación del contenedor original que estamos clonando. Solo puede usarse junto con --destroy.

--memory, -m=número[unidad]

Límite de memoria. Una unidad puede ser b (bytes), k (kibibytes), m (mebibytes) o g (gibibytes).

Permite restringir la memoria disponible para un contenedor. Si el host soporta memoria swap, entonces la configuración de memoria de -m puede ser mayor que la RAM física. Si se especifica un límite de 0 (sin usar -m), la memoria del contenedor no está limitada. El límite real puede redondearse al múltiplo del tamaño de página del sistema operativo (el valor es muy grande, son millones de billones).

Esta opción no es compatible con sistemas sin root de cgroups V1.

Si no se especifican límites de memoria, se utilizan los límites de memoria del contenedor original.

--memory-reservation=número[unidad]

Límite blando de memoria. Una unidad puede ser b (bytes), k (kibibytes), m (mebibytes) o g (gibibytes).

Después de establecer la reserva de memoria, cuando el sistema detecta contención de memoria o poca memoria, los contenedores se ven obligados a restringir su consumo a su reserva. Así que siempre establece el valor por debajo de --memory, de lo contrario, el límite duro tiene prioridad. Por defecto, la reserva de memoria es igual al límite de memoria.

Esta opción no es compatible con sistemas sin root de cgroups V1.

Si no se especifica, la reserva de memoria es igual al límite de memoria del contenedor que se está clonando.

--memory-swap=número[unidad]

Un valor límite igual a memoria más swap. Una unidad puede ser b (bytes), k (kibibytes), m (mebibytes) o g (gibibytes).

Debe usarse con la opción -m (--memory). El valor del argumento debe ser mayor que el de
-m (--memory). Por defecto, se establece al doble del valor de --memory.

Establece número a -1 para habilitar swap ilimitado.

Esta opción no es compatible con sistemas sin root de cgroups V1.

Si no se especifica, se utiliza el contenedor que se está clonando para derivar el valor de swap.

--memory-swappiness=número

Ajusta el comportamiento de intercambio de memoria de un contenedor. Acepta un entero entre 0 y 100.

Esta opción solo es compatible con sistemas rootful de cgroups V1.

--name

Establece un nombre personalizado para el contenedor clonado. El valor por defecto si no se especifica es de la sintaxis: <NOMBRE_ORIGINAL>-clone

--pod=nombre

Clona el contenedor en un pod existente. Es útil para mover un contenedor a un pod existente. El contenedor se une a los namespaces compartidos del pod, perdiendo su configuración que entra en conflicto con los namespaces compartidos.

--run

Cuando se establece en true, esta opción ejecuta el contenedor recién creado después de que el proceso de clonación haya finalizado. Especifica un modo de ejecución desvinculado.

EJEMPLOS

Clonar un contenedor especificado en un nuevo contenedor:

# podman container clone d0cf1f782e2ed67e8c0050ff92df865a039186237a4df24d7acba5b1fa8cc6e7
6b2c73ff8a1982828c9ae2092954bcd59836a131960f7e05221af9df5939c584

Clonar un contenedor especificado en un contenedor con nombre nuevo:

# podman container clone --name=clon d0cf1f782e2ed67e8c0050ff92df865a039186237a4df24d7acba5b1fa8cc6e7
6b2c73ff8a1982828c9ae2092954bcd59836a131960f7e05221af9df5939c584

Reemplazar un contenedor especificado con restricciones de recursos seleccionadas en un nuevo contenedor, eliminando el contenedor original:

# podman container clone --destroy --cpus=5 d0cf1f782e2ed67e8c0050ff92df865a039186237a4df24d7acba5b1fa8cc6e7
6b2c73ff8a1982828c9ae2092954bcd59836a131960f7e05221af9df5939c584
