NOMBRE

podman-network-create - Crea una red Podman

SINOPSIS

podman network create [opciones] [nombre]

DESCRIPCIÓN

Crea una configuración de red para usar con Podman. Por defecto, Podman crea una conexión de puente (bridge). Se puede crear una conexión Macvlan con la opción -d macvlan. Se puede designar un dispositivo padre para macvlan o ipvlan con la opción -o parent=<dispositivo> o --network-interface=<dispositivo>.

Si no se proporcionan opciones, Podman asigna una subred y un nombre libres para la red.

Al finalizar la creación de la red, Podman muestra el nombre de la red recién agregada.

OPCIONES

--disable-dns

Deshabilita el plugin DNS para esta red que, si está habilitado, puede realizar la resolución de nombres de contenedor a contenedor. Solo se soporta con el controlador bridge; para otros controladores, siempre está deshabilitado.

--dns=ip

Establece el servidor/nombre de resolución DNS con ámbito de red para los contenedores en esta red. Si no se establece, se utilizan los servidores del host de /etc/resolv.conf. Puede ser sobrescrito a nivel de contenedor con la opción podman run/create --dns. Esta opción se puede especificar varias veces para establecer más de una IP.

--driver, -d=driver

Controlador para gestionar la red. Actualmente se soportan bridge, macvlan e ipvlan. El valor por defecto es bridge. Como usuario sin privilegios (rootless), los controladores macvlan e ipvlan no tienen acceso a las interfaces de red del host porque el networking rootless requiere un espacio de nombres de red separado.

El backend netavark permite el uso de los llamados plugins de netavark, ver la documentación plugin-API.md en netavark. El binario debe colocarse en un directorio especificado para que podman pueda descubrirlo; esta lista se establece en netavark_plugin_dirs en containers.conf(5) bajo la sección [network].

El nombre del plugin puede usarse entonces como controlador para crear una red para tu plugin. La lista de todos los controladores y plugins soportados se puede ver con podman info --format {{.Plugins.Network}}.

Tenga en cuenta que los controladores macvlan e ipvlan no soportan el reenvío de puertos. El soporte para el reenvío de puertos con un plugin depende de la implementación del plugin.

--gateway=ip

Define una pasarela (gateway) para la subred. Para proporcionar una dirección de pasarela, se requiere una opción subnet. Se puede especificar varias veces. El orden de los argumentos de las opciones --subnet, --gateway y --ip-range debe coincidir.

--ignore

Ignora la solicitud de creación si una red con el mismo nombre ya existe, en lugar de fallar. Tenga en cuenta que intentar crear una red con un nombre existente y parámetros diferentes no cambia la configuración de la existente.

--interface-name=nombre

Esta opción mapea la opción network_interface en la configuración de red, ver podman network inspect. Dependiendo del controlador, esto puede tener diferentes efectos; para bridge, usa el nombre de la interfaz de puente. Para macvlan e ipvlan, es el dispositivo padre en el host. Es lo mismo que --opt parent=....

--internal

Restringe el acceso externo de esta red cuando se utiliza una red bridge. Tenga en cuenta que al usar el backend CNI, el DNS se deshabilitará automáticamente, ver --disable-dns.

Al usar los controladores macvlan o ipvlan con esta opción, no se añadirá una ruta por defecto al contenedor. Como evita la pila de red del host, podman no puede establecer restricciones adicionales y si se ejecuta un contenedor privilegiado, este puede establecer su propia ruta por defecto. Si esto es una preocupación, las conexiones del contenedor deben ser bloqueadas en su pasarela de red real.

El uso del controlador bridge con esta opción tiene los siguientes efectos:
- Los sysctls globales de reenvío IP no se modificarán en el espacio de nombres de red del host.
- El reenvío IP se deshabilita en la interfaz de puente en lugar de configurar un firewall.
- No se añadirá una ruta por defecto al contenedor.

En todos los casos, aardvark-dns solo resolverá nombres de contenedores con esta opción habilitada. Otras consultas responderán con NXDOMAIN.

--ip-range=rango

Asigna una IP de contenedor de un rango. El rango debe ser una subred completa en notación CIDR o estar en la sintaxis <IPInicio>-<IPFin>, que permite un rango más flexible que la subred CIDR. La opción ip-range debe usarse con una opción subnet. Se puede especificar varias veces. El orden de los argumentos de las opciones --subnet, --gateway y --ip-range debe coincidir.

--ipam-driver=driver

Establece el controlador ipam (Controlador de Gestión de Direcciones IP) para la red. Si no se establece, podman elige automáticamente un controlador ipam basándose en el controlador de red.

Los valores válidos son:

  • dhcp: Las direcciones IP se asignan desde un servidor dhcp en la red. Al usar el backend netavark, el netavark-dhcp-proxy.socket debe estar habilitado para iniciar el dhcp-proxy cuando se inicia un contenedor; para CNI, use la unidad cni-dhcp.socket en su lugar.
  • host-local: Las direcciones IP se asignan localmente.
  • none: No se asignan direcciones IP a las interfaces.

Vea el controlador en la salida de podman network inspect bajo el campo ipam_options.

--ipv6

Habilita el networking IPv6 (Dual Stack). Si no se dan subredes, asigna una subred ipv4 y una ipv6.

--label=etiqueta

Establece metadatos para una red (por ejemplo, --label miclave=valor).

--opt, -o=opción

Establece opciones específicas del controlador.

Todos los controladores aceptan las opciones mtu, metric, no_default_route y.

  • mtu: Establece la Unidad Máxima de Transmisión (MTU) y toma un valor entero.
  • metric: Establece la Métrica de Ruta para la ruta por defecto creada en cada contenedor que se une a esta red. Acepta un valor entero positivo. Solo se puede usar con el backend de red Netavark.
  • no_default_route: Si se establece en 1, Podman no añadirá automáticamente una ruta por defecto a las subredes. Las rutas aún se pueden añadir manualmente creando una ruta personalizada usando --route.

Adicionalmente, el controlador bridge soporta las siguientes opciones:

  • vlan: Esta opción asigna una etiqueta VLAN y habilita el filtrado vlan. Por defecto es none.
  • isolate: Esta opción aísla las redes bloqueando el tráfico entre aquellas que tienen esta opción habilitada.
  • com.docker.network.bridge.name: Esta opción asigna el nombre dado al Puente Linux creado.
  • com.docker.network.driver.mtu: Establece la Unidad Máxima de Transmisión (MTU) y toma un valor entero.
  • vrf: Esta opción asigna una VRF a la interfaz de puente. Acepta el nombre de la VRF y por defecto es none. Solo se puede usar con el backend de red Netavark.
  • mode: Esta opción establece el modo de puente especificado en la interfaz. Por defecto es managed. Valores soportados:
  • managed: Podman crea y elimina el puente y modifica sus sysctls. Añade reglas de firewall para enmascarar el tráfico saliente, así como configura el reenvío de puertos para el tráfico entrante usando DNAT.
  • unmanaged: Podman utiliza un puente existente. Debe existir en el momento en que desee iniciar un contenedor que utilice la red. No habrá NAT ni reenvío de puertos, incluso si se pasaron tales opciones al crear el contenedor.

Los controladores macvlan e ipvlan soportan las siguientes opciones:

  • parent: El dispositivo host que se utiliza para la interfaz macvlan. Por defecto es la interfaz de ruta por defecto.
  • mode: Este opt

EJEMPLOS

Crear una red de puente llamada 'mi-red' con una subred y pasarela especificadas:

podman network create --subnet=10.89.0.0/24 --gateway=10.89.0.1 mi-red

Crear una red macvlan con el dispositivo padre 'eth0' y la red 'mi-macvlan':

podman network create --driver=macvlan --opt parent=eth0 mi-macvlan

Crear una red interna aislada llamada 'red-interna':

podman network create --internal red-interna

Crear una red con un rango de IP específico:

podman network create --subnet=10.89.0.0/24 --ip-range=10.89.0.100-10.89.0.200 mi-rango

Crear una red bridge con MTU de 9000:

podman network create -o mtu=9000 red-grande

Crear una red bridge con VLAN 100 y filtrado VLAN habilitado:

podman network create -o vlan=100 red-vlan

Crear una red bridge que utiliza un puente Linux existente llamado 'br1':

podman network create -o com.docker.network.bridge.name=br1 --driver=bridge --opt mode=unmanaged red-externa

Crear una red ipvlan con el dispositivo padre 'eth0' y el modo 'l2':

podman network create --driver=ipvlan --opt parent=eth0 --opt mode=l2 red-ipvlan

Crear una red sin DNS:

podman network create --disable-dns mi-red-sin-dns
