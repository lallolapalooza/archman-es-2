NOMBRE

podman-events - Monitorizar eventos de Podman

SINOPSIS

podman events [opciones]

podman system events [opciones]

DESCRIPCION

Monitoriza e imprime eventos que ocurren en Podman. Cada evento incluye una marca de tiempo, un tipo, un estado, nombre (si aplica) e imagen (si aplica). El mecanismo de registro por defecto es journald. Esto se puede cambiar en containers.conf modificando el valor de events_logger a file. Solo se aceptan file y journald. También está disponible un logger none, pero este mecanismo de registro deshabilita completamente los eventos; podman events no informa nada.

Por defecto, se utiliza el modo de transmisión (streaming), imprimiendo los nuevos eventos a medida que ocurren. Los eventos anteriores se pueden listar mediante --since y --until.

El tipo de evento container informa los siguientes estados:
* attach
* checkpoint
* cleanup
* commit
* connect
* create
* died
* disconnect
* exec
* exec_died
* exited
* export
* import
* init
* kill
* mount
* pause
* prune
* remove
* rename
* restart
* restore
* start
* stop
* sync
* unmount
* unpause
* update

El tipo de evento pod informa los siguientes estados:
* create
* kill
* pause
* remove
* start
* stop
* unpause

El tipo de evento image informa los siguientes estados:
* loadFromArchive,
* mount
* pull
* pull-error
* push
* remove
* save
* tag
* unmount
* untag

El tipo system informa los siguientes estados:
* refresh
* renumber

El tipo volume informa los siguientes estados:
* create
* prune
* remove

El tipo secret informa los siguientes estados:
* create
* remove

Eventos de Creación Detallados

Establecer events_container_create_inspect_data=true en containers.conf(5) indica a Podman que cree eventos de creación de contenedor más detallados que incluyen una carga útil JSON con información detallada sobre los contenedores. La carga útil JSON es idéntica a la de podman-container-inspect(1). El campo asociado en journald se llama PODMAN_CONTAINER_INSPECT_DATA.

OPCIONES

--filter, -f=filtro

Filtra los eventos que se muestran. Deben estar en el formato "filtro=valor". Los siguientes filtros son compatibles:

Filtro Descripción
container [Nombre o ID] Nombre o ID del contenedor
event estado_evento (descrito arriba)
image [Nombre o ID] Nombre o ID de la imagen
label etiqueta [clave] o [clave=valor]
pod [Nombre o ID] Nombre o ID del pod
volume [Nombre o ID] Nombre o ID del volumen
type tipo_evento (descrito arriba)

En caso de que se utilice un ID, el ID puede estar en su forma completa o acortada. El evento "die" se mapea a "died" para compatibilidad con Docker.

--format

Formatea la salida a Líneas JSON o utilizando la plantilla Go dada.

Marcador Descripción
.Attributes ... created_at, _by, labels, y más (map[])
.ContainerExitCode Código de salida (int)
.ContainerInspectData Carga útil de la inspección del contenedor
.Error Mensaje de error en caso de que el estado del evento sea un error (por ejemplo, pull-error)
.HealthStatus Estado de salud (string)
.ID ID del contenedor (SHA completo de 64 bits)
.Image Nombre de la imagen que se está ejecutando (string)
.Name Nombre del contenedor (string)
.Network Nombre de la red que se está utilizando (string)
.PodID ID del pod asociado con el contenedor, si lo hay
.Status Estado del evento (por ejemplo, create, start, died, ...)
.Time Marca de tiempo del evento (string)
.TimeNano Marca de tiempo del evento con precisión de nanosegundos (int64)
.Type Tipo de evento (por ejemplo, image, container, pod, ...)

--help

Imprime el enunciado de uso.

--no-trunc

No truncar la salida (por defecto true).

--since=marca_de_tiempo

Mostrar todos los eventos creados desde la marca de tiempo dada.

--stream

Transmitir eventos y no salir después de leer el último evento conocido (por defecto true).

--until=marca_de_tiempo

Mostrar todos los eventos creados hasta la marca de tiempo dada.

Los valores since y until pueden ser marcas de tiempo RFC3339Nano o una cadena de duración Go como 10m, 5h. Si no se proporcionan valores since o until, solo se muestran los eventos nuevos.

IDENTIFICADORES DE JOURNALD

El backend de eventos journald de Podman utiliza los siguientes identificadores de journald. Puede usar los identificadores para filtrar directamente los eventos de Podman con journalctl.

Identificador Descripción
SYSLOG_IDENTIFIER Siempre establecido en "podman"
PODMAN_EVENT El estado del evento como se describe arriba
PODMAN_TYPE El tipo de evento como se describe arriba
PODMAN_TIME La marca de tiempo cuando se escribió el evento
PODMAN_NAME Nombre del objeto del evento (por ejemplo, contenedor, imagen)
PODMAN_ID ID del objeto del evento (por ejemplo, contenedor, imagen)
PODMAN_EXIT_CODE Código de salida del contenedor
PODMAN_POD_ID ID del pod del contenedor
PODMAN_LABELS Etiquetas del contenedor
PODMAN_HEALTH_STATUS Estado de salud del contenedor
PODMAN_CONTAINER_INSPECT_DATA La carga útil JSON de podman-inspect como se describe arriba
PODMAN_NETWORK_NAME El nombre de la red

NAME

podman-events

display podman events

SYNOPSIS

podman events [ OPTIONS ]

DESCRIPTION

The podman events command displays events that occur within the Podman container runtime. Events can include container creation, deletion, starting, stopping, and other state changes.

The default output format includes the timestamp, event type, ID, image name, and container name.

OPTIONS

--all, -a
Show all events, including events related to containers, pods, and volumes.
--cert-dir=path
Path to a directory containing certificates for TLS bootstrapper. Default:
--containers
Show only container events.
--daemon-socket=path
Path to the daemon socket. Default:
--filter=condition, -f condition
Filter output based on specified conditions. Conditions can include:
event=value
Filter by event type (e.g., create, destroy, start, stop).
type=value
Filter by object type (e.g., container, pod, volume).
name=value
Filter by object name.
id=value
Filter by object ID.
--format=template
Format output using Go's template syntax. Default: human-readable.
--latest, -l
Show the latest event.
--pod
Show only pod events.
--since=timestamp
Show events created since a specific timestamp. Timestamps can be relative (e.g., 5m for 5 minutes ago) or absolute (e.g., 2019-03-02T10:00:00Z).
--stream, -s
Stream events in real-time.
--until=timestamp
Show events created until a specific timestamp.
--version
Print version information and exit.
--volumes
Show only volume events.

JOURNALD IDENTIFIERS

If Podman is configured to log to the systemd journal, the events command can be used to filter journald entries. The following identifiers are used:

CONTAINER_ID
The ID of the container.
CONTAINER_NAME
The name of the container.
POD_ID
The ID of the pod.
POD_NAME
The name of the pod.
TYPE
The type of object (e.g., container, pod).

For example, to show all container events from the journal:

$ journalctl -f _TRANSPORT=podman -g CONTAINER_ID -o cat
