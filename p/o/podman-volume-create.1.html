NOMBRE

podman-volume-create - Crear un nuevo volumen

SINOPSIS

podman volume create [opciones] [nombre]

DESCRIPCIÓN

Crea un volumen vacío y lo prepara para ser utilizado por los contenedores. El volumen puede ser creado con un nombre específico, si no se proporciona un nombre se generará uno aleatorio. Puede añadir metadatos al volumen utilizando la opción --label y las opciones del driver se pueden establecer usando la opción --opt.

OPCIONES

--driver, -d=driver

Especifica el nombre del driver de volumen (por defecto local). Hay dos drivers soportados por el propio Podman: local e image.

El driver local utiliza un directorio en disco como backend por defecto, pero también puede usar el comando mount(8) para montar un sistema de archivos como volumen si se especifica --opt.

El driver image utiliza una imagen como almacenamiento de respaldo para el volumen. Se crea un sistema de archivos overlay, que permite que los cambios en el volumen se guarden como una nueva capa sobre la imagen.

Utilizando un valor distinto de local o image, Podman intenta crear el volumen usando un plugin de volumen con el nombre dado. Dichos plugins deben definirse en la sección volume_plugins del archivo de configuración containers.conf(5).

--gid=gid

Establece el GID con el que se creará el volumen. A diferencia de --opt o=gid=*gid*, el valor especificado no se pasa a la operación de montaje. El GID especificado será el propietario del directorio de punto de montaje del volumen y afecta a la operación chown del volumen.

--help

Imprimir la declaración de uso

--ignore

No fallar si el volumen nombrado ya existe, en su lugar simplemente imprimir el nombre. Nota: las nuevas opciones no se aplican al volumen existente.

--label, -l=label

Establecer metadatos para un volumen (por ejemplo, --label mykey=value).

--opt, -o=option

Establecer opciones específicas del driver. Para el driver por defecto, local, esto permite configurar un volumen para montar un sistema de archivos en el host.

Para el driver local, las siguientes opciones son compatibles: type, device, o, y [no]copy.

  • La opción type establece el tipo de sistema de archivos a montar, y es equivalente a la bandera -t de mount(8).
  • La opción device establece el dispositivo a montar, y es equivalente al argumento device de mount(8).
  • La opción copy habilita la copia de archivos desde la ruta de la imagen del contenedor donde se crea el montaje al nuevo volumen en la primera ejecución. copy es el valor por defecto.

La opción o establece opciones para el montaje, y es equivalente a las opciones del sistema de archivos (también -o) pasadas a mount(8) con las siguientes excepciones:

  • La opción o soporta las opciones uid y gid para establecer el UID y GID del volumen creado, que normalmente no son soportadas por mount(8).
  • La opción o soporta la opción size para establecer el tamaño máximo del volumen creado, la opción inodes para establecer el número máximo de inodos para el volumen, y noquota para deshabilitar completamente el soporte de cuotas incluso para el seguimiento del uso del disco. La opción size es compatible con los sistemas de archivos "tmpfs" y "xfs[nota]". La opción inodes es compatible con los sistemas de archivos "xfs[nota]". Nota: Los sistemas de archivos xfs deben montarse con la bandera prjquota descrita en la página del manual de xfs_quota(8). Podman generará un error si no es así.
  • La opción o soporta el uso de opciones de volumen distintas de las opciones UID/GID con el driver local y requiere privilegios de root.
  • La opción o soporta la opción timeout que permite a los usuarios establecer un tiempo de espera específico del driver en segundos antes de que falle la creación del volumen. Por ejemplo, --opt=o=timeout=10 establece un tiempo de espera del driver de 10 segundos.

Nota No confundir la opción de creación --opt,-o con la opción de montaje -o. Por ejemplo, con podman volume create, usar -o=o=uid=1000 no -o=uid=1000.

Para el driver image, la única opción compatible es image, que especifica la imagen en la que se basa el volumen. Esta opción es obligatoria cuando se utiliza el driver image.

Cuando no se utilizan los drivers local e image, las opciones dadas se pasan directamente al plugin de volumen. En este caso, las opciones compatibles son dictadas por el plugin en cuestión, no por Podman.

--uid=uid

Establece el UID con el que se creará el volumen. A diferencia de --opt o=uid=*uid*, el valor especificado no se pasa a la operación de montaje. El UID especificado será el propietario del directorio de punto de montaje del volumen y afecta a la operación chown del volumen.

CUOTAS

podman volume create utiliza los controles de cuota de proyecto de XFS para controlar el tamaño y el número de inodos de los volúmenes incorporados. El directorio utilizado para almacenar los volúmenes debe ser un sistema de archivos XFS y estar montado con la opción pquota.

Ejemplo de entrada en /etc/fstab:

/dev/podman/podman-var /var xfs defaults,x-systemd.device-timeout=0,pquota 1 2

Podman genera IDs de proyecto para cada volumen incorporado, pero estos IDs de proyecto deben ser únicos para el sistema de archivos XFS. Estos IDs de proyecto se generan aleatoriamente por defecto, con una posibilidad de superposición con otras cuotas en el mismo sistema de archivos.

La herramienta xfs_quota se puede utilizar para asignar un ID de proyecto al directorio del driver de almacenamiento, por ejemplo:

echo 100000:/var/lib/containers/storage/overlay >> /etc/projects
echo 200000:/var/lib/containers/storage/volumes >> /etc/projects
echo storage:100000 >> /etc/projid
echo volumes:200000 >> /etc/projid
xfs_quota -x -c 'project -s storage volumes' /<punto de montaje xfs>

En el ejemplo anterior, estamos configurando el driver de almacenamiento overlay para los contenedores recién creados, así como los volúmenes, para usar IDs de proyecto con un desplazamiento de inicio. A todos los contenedores se les asignan IDs de proyecto más grandes (por ejemplo, >= 100000). A todos los volúmenes se les asignan IDs de proyecto más grandes que comienzan con 200000. Esto evita conflictos de gestión de xfs_quota con contenedores/almacenamiento.

EJEMPLOS

Crear un volumen vacío.

$ podman volume create

Crear un volumen vacío con nombre.

$ podman volume create myvol

Crear un volumen vacío con nombre y una etiqueta especificada.

$ podman volume create --label foo=bar myvol

Crear un volumen tmpfs con nombre, tamaño y opciones de montaje especificados.

# podman volume create --opt device=tmpfs --opt type=tmpfs --opt o=size=2M,nodev,noexec myvol

Crear un volumen tmpfs llamado testvol con las opciones especificadas.

# podman volume create --opt device=tmpfs --opt type=tmpfs --opt o=uid=1000,gid=1000 testvol

Crear un volumen anulando el UID y GID del propietario.

# podman volume create --uid 1000 --gid 1000 myvol

Crear un volumen con nombre de imagen utilizando la imagen local especificada en containers/storage.

# podman volume create --driver image --opt image=fedora:latest fedoraVol

EJEMPLOS DE MONTAJE

podman volume create permite pasar las opciones type, device y o a mount(8) al usar el driver local.

s3fs-fuse

s3fs-fuse o simplemente s3fs, es un sistema de archivos fuse que permite montar prefijos s3 como montajes de sistemas de archivos.

Instalación:

$ doas dnf install s3fs-fuse

Uso simple:

$ s3fs --help
$ s3fs -o use_xattr,endpoint=aq-cen
tral-1 bucket:/prefijo /mnt

Equivalente a través de mount(8)

$ mount -t fuse.s3fs -o use_xattr,endpoint=aq-central-1 bucket:/prefijo /mnt

Equivalente a través de podman volume create

$ podman volume create s3fs-fuse-volume -o type=fuse.s3fs -o device=bucket:/prefijo -o o=use_xattr,endpoint=aq-central-1

El volumen se puede montar en un contenedor con

$ podman run -v s3fs-fuse-volume:/s3:z --rm -it fedora:latest

Por favor, consulte las opciones disponibles en su wiki.

Usando con otros usuarios del contenedor

El ejemplo anterior funciona porque el volumen se monta como el usuario del host y dentro del contenedor root se mapea al usuario en el host.

Si el montaje es accedido por un usuario diferente dentro del contenedor, se generará un error de "Permiso denegado".

$ podman run --user bin:bin -v s3fs-fuse-volume:/s3:z,U --rm -it fedora:latest
$ ls /s3
# ls: /s3: Permiso denegado

En el mundo FUSE, los montajes están protegidos para el usuario que los montó; especifique la opción de montaje allow_other si otros usuarios necesitan acceso. > Nota: Esto eliminará las medidas de seguridad normales de fuse en el punto de montaje, después de lo cual los permisos normales del sistema de archivos tendrán que protegerlo

$ podman volume create s3fs-fuse-other-volume -o type=fuse.s3fs -o device=bucket:/prefijo -o o=allow_other,use_xattr,endpoint=aq-central-1
$ podman run --user bin:bin -v s3fs-fuse-volume:/s3:z,U --rm -it fedora:latest
$ ls /s3

El prefijo debe existir

s3fs fallará al montar si el prefijo no existe en el bucket.

Cree un directorio s3 colocando un objeto vacío en la clave deseada prefijo/

$ aws s3api put-object --bucket bucket --key prefix/

Si el rendimiento es la prioridad, consulte goofys, que es más eficiente.

Existen sistemas de archivos FUSE para Google Cloud Storage y Azure Blob Storage
