POSIX_SPAWNATTR_DESTROY(3P) Manual del Programador de POSIX POSIX_SPAWNATTR_DESTROY(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

posix_spawnattr_destroy, posix_spawnattr_init — destruir e inicializar el objeto de atributos de spawn (TIEMPO REAL AVANZADO)

SINOPSIS

#include <spawn.h>
int posix_spawnattr_destroy(posix_spawnattr_t *attr);
int posix_spawnattr_init(posix_spawnattr_t *attr);

DESCRIPCIÓN

La función posix_spawnattr_destroy() destruirá un objeto de atributos de spawn. Un objeto de atributos attr destruido puede ser reinicializado usando posix_spawnattr_init(); los resultados de referenciar el objeto de otra manera después de que haya sido destruido son indefinidos. Una implementación puede hacer que posix_spawnattr_destroy() establezca el objeto referenciado por attr a un valor inválido.

La función posix_spawnattr_init() inicializará un objeto de atributos de spawn attr con el valor predeterminado para todos los atributos individuales utilizados por la implementación. Los resultados son indefinidos si posix_spawnattr_init() se llama especificando un objeto de atributos attr ya inicializado.

Un objeto de atributos de spawn es de tipo posix_spawnattr_t (definido en <spawn.h>) y se utiliza para especificar la herencia de atributos de proceso a través de una operación de spawn. POSIX.1‐2008 no define operadores de comparación o asignación para el tipo posix_spawnattr_t.

Cada implementación documentará los atributos individuales que utiliza y sus valores predeterminados, a menos que estos valores estén definidos por POSIX.1‐2008. Los atributos no definidos por POSIX.1‐2008, sus valores predeterminados y los nombres de las funciones asociadas para obtener y establecer esos valores de atributos son definidos por la implementación.

El objeto de atributos de spawn resultante (posiblemente modificado al establecer valores de atributos individuales), se utiliza para modificar el comportamiento de posix_spawn() o posix_spawnp(). Después de que un objeto de atributos de spawn se ha utilizado para crear un proceso mediante una llamada a posix_spawn() o posix_spawnp(), cualquier función que afecte al objeto de atributos (incluida su destrucción) no afectará a ningún proceso que se haya creado de esta manera.

VALOR DE RETORNO

Al completarse con éxito, posix_spawnattr_destroy() y posix_spawnattr_init() devolverán cero; de lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función posix_spawnattr_init() fallará si:

ENOMEM
No hay suficiente memoria para inicializar el objeto de atributos de spawn.

La función posix_spawnattr_destroy() puede fallar si:

EINVAL
El valor especificado por attr es inválido.

USO DE APLICACIONES

Estas funciones forman parte de la opción Spawn y no es necesario que se proporcionen en todas las implementaciones.

RACIÓN

La interfaz de spawn original propuesta en POSIX.1‐2008 definía los atributos que especifican la herencia de atributos de proceso a través de una operación de spawn como una estructura. Para poder separar los atributos individuales opcionales bajo sus opciones apropiadas (es decir, los atributos spawn-schedparam y spawn-schedpolicy dependiendo de la opción de Planificación de Procesos), y también para extensibilidad y consistencia con las interfaces POSIX más nuevas, la interfaz de atributos se ha cambiado a un tipo de datos opaco. Esta interfaz ahora consta del tipo posix_spawnattr_t, que representa un objeto de atributos de spawn, junto con funciones asociadas para inicializar o destruir el objeto de atributos, y para establecer o obtener cada atributo individual. Aunque la nueva interfaz orientada a objetos es más verbosa que la estructura original, es fácil de usar, más extensible y fácil de implementar.
