DESCRIPCIÓN

La biblioteca popt existe esencialmente para analizar opciones de línea de comandos. Se encuentra superior en muchos aspectos en comparación con el análisis manual del array argv o con el uso de las funciones getopt getopt() y getopt_long() [ver getopt(3)]. Algunas ventajas específicas de popt son: no utiliza variables globales, permitiendo así múltiples pasadas en el análisis de argv; puede analizar un array arbitrario de elementos estilo argv, permitiendo el análisis de cadenas de línea de comandos desde cualquier fuente; proporciona un método estándar de alias de opciones (que se discutirá en detalle a continuación); puede ejecutar filtros de opciones externos; y, finalmente, puede generar automáticamente mensajes de ayuda y uso para la aplicación.

Al igual que getopt_long(), la biblioteca popt soporta opciones cortas y largas. Recuerde que una opción corta consiste en un carácter - seguido de un carácter alfanumérico único. Una opción larga, común en las utilidades GNU, consiste en dos caracteres - seguidos de una cadena compuesta por letras, números y guiones. Las opciones largas opcionalmente pueden comenzar con un solo -, principalmente para permitir la compatibilidad de línea de comandos entre aplicaciones popt y aplicaciones de la caja de herramientas X. Cualquiera de los dos tipos de opción puede ir seguido de un argumento. Un espacio separa una opción corta de sus argumentos; un espacio o un = separa una opción larga de un argumento.

La biblioteca popt es altamente portable y debería funcionar en cualquier plataforma POSIX. La última versión se distribuye con rpm y siempre está disponible en: ftp://ftp.rpm.org/pub/rpm/dist.

Puede ser redistribuida bajo la licencia de la consorcio X, ver el archivo COPYING en la distribución fuente de popt para detalles.

USO BÁSICO DE POPT

1. LA TABLA DE OPCIONES

Las aplicaciones proporcionan a popt información sobre sus opciones de línea de comandos mediante una "tabla de opciones", es decir, un array de estructuras struct poptOption:

#include <popt.h>

struct poptOption {
    const char * longName;   /* puede ser NULL */
    char shortName;          /* puede ser '\0' */
    unsigned int argInfo;    /* tipo de argumento esperado después de la opción */
    void * arg;              /* depende de argInfo */
    int val;                 /* 0 significa no devolver, solo actualizar arg */
    const char * descrip;    /* descripción para autoayuda -- puede ser NULL */
    const char * argDescrip; /* descripción del argumento para autoayuda -- puede ser NULL*/
};

Cada miembro de la tabla define una única opción que puede pasarse al programa. Las opciones largas y cortas se consideran una única opción que puede aparecer en dos formas diferentes. Los dos primeros miembros, longName y shortName, definen los nombres de la opción; el primero es un nombre largo, mientras que el segundo es un solo carácter.

El miembro argInfo indica a popt qué tipo de argumento se espera después de la opción. Si no se espera ningún argumento, se debe usar POPT_ARG_NONE. Los valores válidos de argInfo se muestran en la siguiente tabla:

Valor Descripción Tipo de arg
POPT_ARG_NONE No se espera argumento int
POPT_ARG_STRING No se realizará ninguna comprobación de tipo char *
POPT_ARG_ARGV No se realizará ninguna comprobación de tipo char **
POPT_ARG_SHORT Se espera un argumento corto short
POPT_ARG_INT Se espera un argumento entero int
POPT_ARG_LONG Se espera un entero largo long
POPT_ARG_LONGLONG Se espera un entero largo largo long long
POPT_ARG_VAL Valor entero tomado de val int
POPT_ARG_FLOAT Se espera un argumento flotante float
POPT_ARG_DOUBLE Se espera un argumento doble double

Para valores numéricos, si el valor argInfo se combina bitwise con uno de POPT_ARGFLAG_OR, POPT_ARGFLAG_AND, o POPT_ARGFLAG_XOR, el valor se guarda realizando un OR, AND, o XOR. Si el valor argInfo se combina bitwise con POPT_ARGFLAG_NOT, el valor se negará antes de guardarlo. Para las operaciones comunes de establecer y/o borrar bits, POPT_BIT_SET y POPT_BIT_CLR tienen las banderas apropiadas establecidas para realizar operaciones de bits.

Si el valor argInfo se combina bitwise con POPT_ARGFLAG_ONEDASH, el argumento largo puede darse con un solo - en lugar de dos. Por ejemplo, si --longopt es una opción con POPT_ARGFLAG_ONEDASH, se especifica, -longopt también se acepta.

El siguiente elemento, arg, permite a popt actualizar automáticamente variables del programa cuando se utiliza la opción. Si arg es NULL, se ignora y popt no toma ninguna acción especial. De lo contrario, debe apuntar a una variable del tipo indicado en la columna más a la derecha de la tabla anterior. Un argumento POPT_ARG_ARGV (re)asignará un array de punteros de cadenas char *, añadirá el argumento de cadena y agregará un terminador NULL al final del array según sea necesario. La dirección char ** objetivo de un argumento POPT_ARG_ARGV debe inicializarse a NULL.

Si la opción no toma argumento (argInfo es POPT_ARG_NONE), la variable apuntada por arg se establece en 1 cuando se usa la opción. (Incidentalmente, quizás no escape a la atención de los mecanógrafos que el valor de POPT_ARG_NONE es 0). Si la opción toma un argumento, la variable a la que apunta arg se actualiza para reflejar el valor del argumento. Cualquier cadena es aceptable para los argumentos POPT_ARG_STRING y POPT_ARG_ARGV, pero POPT_ARG_INT, POPT_ARG_SHORT, POPT_ARG_LONG, POPT_ARG_LONGLONG, POPT_ARG_FLOAT y POPT_ARG_DOUBLE se convierten al tipo apropiado, y se devuelve un error si la conversión falla.

POPT_ARG_VAL hace que arg se establezca en el valor (entero) de val cuando se encuentra el argumento. Esto es más a menudo útil para argumentos mutuamente excluyentes en casos donde no es un error que ocurran múltiples argumentos y donde se desea que gane el último argumento especificado; por ejemplo, "rm -i -f". POPT_ARG_VAL hace que la función de análisis no devuelva un valor, ya que el valor de val ya se ha utilizado.

Si el valor argInfo se combina bitwise con POPT_ARGFLAG_OPTIONAL, el argumento de la opción larga puede omitirse. Si se usa la opción larga sin argumento, se guardará un valor predeterminado de cero o NULL (si el puntero arg está presente), de lo contrario, se comportará...

1. OPTION TABLES

All information about command-line arguments is stored in an array of struct poptOption structures. The last entry in this array must be an empty structure marking the end of the table, and the macro POPT_TABLEEND is provided for this purpose.

Each entry in the table defines a command-line option and contains the following fields:

  • The argInfo field is a bitmask which specifies how the option behaves. If the mask is 0, then the option is a simple flag which is not associated with an argument. If the mask is non-zero, the option takes an argument which may be a string or a number. The low byte of the mask is the argument type. If this is POPT_ARG_NONE, then the option does not take an argument. If it is POPT_ARG_STRING, then the option expects a string argument. If it is POPT_ARG_INT, then the option expects an integer argument. If it is POPT_ARG_FLOAT, then the option expects a floating point argument. If the mask is POPT_ARG_ALL, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_NONSPECIAL, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_SPECIFIC, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_REQUIRES_STATE, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_IMPLICATION, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_FORWARDED, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_HELP, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_CASE_INSENSITIVE, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_SHOW_DEFAULT, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_INTERNAL, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_IS_ENUM, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option. If the mask is POPT_ARG_VALIDATE, then the option is treated as a long option with an argument, and the argument is parsed using the argument type specified for that option.

    The remaining bits of the mask are flags that modify the option's behavior. POPT_ARGFLAG_ONEDASH specifies that the option can be specified with a single dash. POPT_ARGFLAG_VALUE specifies that the option's value should be treated as a string, even if it looks like a number. POPT_ARGFLAG_OPTIONAL_ARG specifies that the option's argument is optional. POPT_ARGFLAG_DONT_EXEC_EXPANSION specifies that any escape sequences in the argument should not be expanded. POPT_ARGFLAG_EXEC_EXPANSION specifies that any escape sequences in the argument should be expanded. POPT_ARGFLAG_APPEND specifies that the option's argument should be appended to the existing value. POPT_ARGFLAG_PREPEND specifies that the option's argument should be prepended to the existing value. POPT_ARGFLAG_NEGATABLE specifies that the option can be negated by prefixing it with "no-". POPT_ARGFLAG_TOGGLE specifies that the option can be toggled by prefixing it with "no-". POPT_ARGFLAG_ALIAS specifies that the option is an alias for another option. POPT_ARGFLAG_DEPRECATED specifies that the option is deprecated and should not be used. POPT_ARGFLAG_RESTRICTED specifies that the option is restricted to certain users or groups. POPT_ARGFLAG_HIDDEN specifies that the option should not be shown in help messages. POPT_ARGFLAG_SHOW_DEFAULT specifies that the option's default value should be shown in help messages.

  • The shortName field specifies the single character option that represents this argument. For example, if this field is set to 'h', then the option can be specified on the command line as -h.

  • The popt_val field is the value that is returned when this option is encountered. If the option takes an argument, this value is also used as the value for the argument. If the option does not take an argument, this value is used as the return value of poptGetNextOpt(). If the value is 0, then the next command-line argument is treated as the argument for this option. The value must be greater than 0.

  • The longName field specifies the long option name for this argument. For example, if this field is set to "help", then the option can be specified on the command line as "--help". If this field is NULL, then the option can only be specified using its short name.

  • The descrip field is a descriptive string that is used when generating help messages. It should be a concise explanation of what the option does. If automatic help generation is being used, this field is required.

  • The argDescrip field is a short string that describes the type of argument the option expects. This is also used when generating help messages. If the option does not take an argument, this field should be NULL.

For example, the following table defines a simple program with three options: -h or --help for help, -v or --verbose for verbose output, and -f or --file which takes a filename as an argument.

struct poptOption my_options[] = {
    { NULL, '\0', POPT_ARG_NONE,    0,      0,      NULL, NULL },
    { "help",   'h', POPT_ARG_NONE,    0,      0,      "Show help message", NULL },
    { "verbose", 'v', POPT_ARG_NONE,    0,      0,      "Enable verbose output", NULL },
    { "file",   'f', POPT_ARG_STRING,  0,      0,      "Specify input file", "" },
    POPT_TABLEEND
};

The first entry in the table is a placeholder for options that do not have a short name or a long name. The descrip and argDescrip fields are only required if automatic help messages are desired. descrip is a text description of the argument and argDescrip is a short summary of the type of arguments the option expects, or NULL if the option doesn't require any arguments.

If popt should automatically provide --usage and --help (-?) options, one line in the table should be the macro POPT_AUTOHELP. This macro includes another option table (via POPT_ARG_INCLUDE_TABLE ; see below) in the main one which provides the table entries for these arguments. When --usage or --help are passed to programs which use popt's automatic help, popt displays the appropriate message on stderr as soon as it finds the option, and exits the program with a return code of 0. If you want to use popt's automatic help generation in a different way, you need to explicitly add the option entries to your programs option table instead of using POPT_AUTOHELP.

If the argInfo value is bitwise or'd with POPT_ARGFLAG_DOC_HIDDEN, the argument will not be shown in help output.

If the argInfo value is bitwise or'd with POPT_ARGFLAG_SHOW_DEFAULT, the initial value of the arg will be shown in help output.

The final structure in the table should have all the pointer values set to NULL and all the arithmetic values set to 0, marking the end of the table. The macro POPT_TABLEEND is provided to do that.

There are two types of option table entries which do not specify command line options. When either of these types of entries are used, the longName element must be NULL and the shortName element must be '\0'.

The first of these special entry types allows the application to nest another option table in the current one; such nesting may extend quite deeply (the actual depth is limited by the program's stack). Including other option tables allows a library to provide a standard set of command-line options to every program which uses it (this is often done in graphical programming toolkits, for example). To do this, set the argInfo field to POPT_ARG_INCLUDE_TABLE and the arg field to point to the table which is being included. If automatic help generation is being used, the descrip field should contain an overall description of the option table being included.

The other special option table entry type tells popt to call a function (a callback) when any option in that table is found. This is especially useful when included option tables are being used, as the program which provides the top-level option table doesn't need to be aware of the other options which are provided by the included table. When a callback is set for a table, the parsing function never returns information on an option in the table. Instead, options information must be retained via the callback or by having popt set a variable through the option's arg field. Option callbacks should match the following prototype:

void poptCallbackType(poptContext con,
                      const struct poptOption * opt,
                      const char * arg, void * data);

The first parameter is the context which is being parsed (see the next section for information on contexts), opt points to the option which triggered this callback, and arg is the option's argument. If the option does not take an argument, arg is NULL. The final parameter, data is taken from the descrip field of the option table entry which defined the callback. As descrip is a pointer, this allows callback functions to be passed an arbitrary set of data (though a typecast will have to be used).

The option table entry which defines a callback has an argInfo of POPT_ARG_CALLBACK, an arg which points to the callback function, and a descrip field which specifies an arbitrary pointer to be passed to the callback.

2. CREATING A CONTEXT

popt can interleave the parsing of multiple command-line sets. It allows this by keeping all the state information for a particular set of command-line arguments in a poptContext data structure, an opaque type that should not be modified outside the popt library.

New popt contexts are created by poptGetContext():

poptContext poptGetContext(const char * name, int argc,
                           const char ** argv,
                           const struct poptOption * options,
                           unsigned int flags);

The first parameter, name, is used only for alias handling (discussed later). It should be the name of the application whose options are being parsed, or should be NULL if no option aliasing is desired. The next two arguments specify the command-line arguments to parse. These are generally passed to poptGetContext() exactly as they were passed to the program's main() function. The options parameter points to the table of command-line options, which was described in the previous section. The final parameter, flags, can be any bitwise or combination of the following four values:

Value Description
POPT_CONTEXT_NO_EXEC Ignore exec expansions
POPT_CONTEXT_KEEP_FIRST Do not ignore argv[0]
POPT_CONTEXT_POSIXMEHARDER Options cannot follow arguments
POPT_CONTEXT_ARG_OPTS Return the arguments as options of value 0

A poptContext keeps track of which options have already been parsed and which remain, among other things. If a program wishes to restart option processing of a set of arguments, it can reset the poptContext by passing the context as the sole argument to poptResetContext().

When argument processing is complete, the process should free the poptContext as it contains dynamically allocated components. The poptFreeContext() function takes a poptContext as its sole argument and frees the resources the context is using.

Here are the prototypes of both poptResetContext() and poptFreeContext():

3. PARSING THE COMMAND LINE

After an application has created a poptContext, it may begin parsing arguments. poptGetNextOpt() performs the actual argument parsing.

#include <popt.h>
int poptGetNextOpt(poptContext con);

Taking the context as its sole argument, this function parses the next command-line argument found. After finding the next argument in the option table, the function fills in the object pointed to by the option table entry's arg pointer if it is not NULL. If the val entry for the option is non-0, the function then returns that value. Otherwise, poptGetNextOpt() continues on to the next argument.

poptGetNextOpt() returns -1 when the final argument has been parsed, and other negative values when errors occur. This makes it a good idea to keep the val elements in the options table greater than 0.

If all of the command-line options are handled through arg pointers, command-line parsing is reduced to the following line of code:

rc = poptGetNextOpt(poptcon);

Many applications require more complex command-line parsing than this, however, and use the following structure:

while ((rc = poptGetNextOpt(poptcon)) > 0) {
     switch (rc) {
          /* specific arguments are handled here */
     }
}

When returned options are handled, the application needs to know the value of any arguments that were specified after the option. There are two ways to discover them. One is to ask popt to fill in a variable with the value of the option through the option table's arg elements. The other is to use poptGetOptArg():

#include <popt.h>
char * poptGetOptArg(poptContext con);

This function returns the argument given for the final option returned by poptGetNextOpt(), or it returns NULL if no argument was specified. The calling function is responsible for deallocating this string.

4. LEFTOVER ARGUMENTS

Many applications take an arbitrary number of command-line arguments, such as a list of file names. When popt encounters an argument that does not begin with a -, it assumes it is such an argument and adds it to a list of leftover arguments. Three functions allow applications to access such arguments:

const char * poptGetArg(poptContext con);
This function returns the next leftover argument and marks it as processed. 
const char * poptPeekArg(poptContext con);
The next leftover argument is returned but not marked as processed. This allows an application to look ahead into the argument list, without modifying the list. 
const char ** poptGetArgs(poptContext con);
All the leftover arguments are returned in a manner identical to argv. The final element in the returned array points to NULL, indicating the end of the arguments.

5. AUTOMATIC HELP MESSAGES

The popt library can automatically generate help messages which describe the options a program accepts. There are two types of help messages which can be generated. Usage messages are a short messages which lists valid options, but does not describe them. Help messages describe each option on one (or more) lines, resulting in a longer, but more useful, message. Whenever automatic help messages are used, the descrip and argDescrip fields struct poptOption members should be filled in for each option.

MENSAJES DE AYUDA Y USO

Si sus mensajes de ayuda son sencillos, estos se generarán automáticamente a partir de la tabla de opciones y se imprimirán cuando se especifique la opción de ayuda (generalmente -h o --help). Si el programa no define explícitamente una opción de ayuda, se añadirá una automáticamente. Si no está satisfecho con la ayuda predeterminada, o si sus argumentos de línea de comandos son más complejos, puede definir las siguientes funciones para obtener más control sobre sus mensajes de ayuda:

#include <popt.h>
void poptPrintHelp(poptContext con, FILE * f, int flags);
void poptPrintUsage(poptContext con, FILE * f, int flags);

poptPrintHelp() imprime el mensaje de ayuda estándar en el descriptor de archivo f, mientras que poptPrintUsage() imprime el mensaje de uso más corto. Ambas funciones ignoran actualmente el argumento flags; está ahí para permitir cambios futuros.

MANEJO DE ERRORES

Todas las funciones de popt que pueden devolver errores devuelven enteros. Cuando ocurre un error, se devuelve un código de error negativo. La siguiente tabla resume los códigos de error que ocurren:

Error Descripción
POPT_ERROR_NOARG Falta el argumento para una opción.
POPT_ERROR_BADOPT No se pudo analizar el argumento de la opción.
POPT_ERROR_UNWANTEDARG La opción no acepta un argumento.
POPT_ERROR_OPTSTOODEEP El alias de la opción está anidado demasiado profundamente.
POPT_ERROR_BADQUOTE Las comillas no coinciden.
POPT_ERROR_ERRNO errno establecido, use strerror(errno).
POPT_ERROR_BADNUMBER No se pudo convertir la opción a un número.
POPT_ERROR_OVERFLOW Un número dado era demasiado grande o demasiado pequeño.
POPT_ERROR_BADOPERATION Se solicitaron operaciones lógicas mutuamente excluyentes.
POPT_ERROR_NULLARG opt->arg no debe ser NULL.
POPT_ERROR_MALLOC Fallo de asignación de memoria.
POPT_ERROR_BADCONFIG El archivo de configuración falló la prueba de sanidad.

Aquí hay una discusión más detallada de cada error:

POPT_ERROR_NOARG
Se especificó en la línea de comandos una opción que requiere un argumento, pero no se proporcionó ningún argumento. Esto solo puede ser devuelto por poptGetNextOpt().
POPT_ERROR_BADOPT
Se especificó una opción en argv pero no está en la tabla de opciones. Este error solo puede ser devuelto por poptGetNextOpt().
POPT_ERROR_OPTSTOODEEP
Un conjunto de alias de opciones está anidado demasiado profundamente. Actualmente, popt sigue las opciones solo 10 niveles (POPT_OPTION_DEPTH) para evitar la recursión infinita. Solo poptGetNextOpt() puede devolver este error.
POPT_ERROR_BADQUOTE
Una cadena analizada tiene una discrepancia de comillas (como una comilla simple). poptParseArgvString(), poptReadConfigFile() o poptReadDefaultConfig() pueden devolver este error.
POPT_ERROR_ERRNO
Una llamada al sistema devolvió un error y errno todavía contiene el error de la llamada al sistema. Tanto poptReadConfigFile() como poptReadDefaultConfig() pueden devolver este error.
POPT_ERROR_BADNUMBER
La conversión de una cadena a un número (int o long) falló debido a que la cadena contenía caracteres no numéricos. Esto ocurre cuando poptGetNextOpt() está procesando un argumento de tipo POPT_ARG_INT, POPT_ARG_SHORT, POPT_ARG_LONG, POPT_ARG_LONGLONG, POPT_ARG_FLOAT o POPT_ARG_DOUBLE.
POPT_ERROR_OVERFLOW
La conversión de cadena a número falló porque el número era demasiado grande o demasiado pequeño. Al igual que POPT_ERROR_BADNUMBER, este error puede ocurrir solo cuando poptGetNextOpt() está procesando un argumento de tipo POPT_ARG_INT, POPT_ARG_SHORT, POPT_ARG_LONG, POPT_ARG_LONGLONG, POPT_ARG_FLOAT o POPT_ARG_DOUBLE.
POPT_ERROR_BADOPERATION
Se especificó más de una operación lógica (AND, OR, XOR) para una opción, o se especificó POPT_ARGFLAG_RANDOM pero la plataforma no admite la función random(). Esto solo puede ser devuelto por poptSaveLongLong(), poptSaveLong(), poptSaveInt(), poptSaveShort() y poptGetNextOpt().
POPT_ERROR_NULLARG
Se invocó una operación en un arg objetivo nulo (incluidos argumentos de cadena de longitud cero). En el caso de poptBitsArgs(), esto incluye un array argv sobrante vacío. Esto solo puede ser devuelto por las funciones poptBits*() y poptSave*(), poptConfigFileToString() y poptGetNextOpt().
POPT_ERROR_MALLOC
Fallo de asignación de memoria. Esto solo puede ser devuelto por poptReadFile(), poptDupArgv(), poptParseArgvString(), poptConfigFileToString() y poptGetNextOpt().
POPT_ERROR_BADCONFIG
Los archivos de configuración de popt están corruptos. Esto solo puede ser devuelto por poptReadConfigFile() y poptReadConfigFiles().

Hay dos funciones disponibles para facilitar que las aplicaciones proporcionen buenos mensajes de error.

const char *const poptStrerror(const int error);
Esta función toma un código de error de popt y devuelve una cadena que describe el error, al igual que la función estándar strerror(). 
const char * poptBadOption(poptContext con, int flags);
Si ocurrió un error durante poptGetNextOpt(), esta función devuelve la opción que causó el error. Si el argumento flags se establece en POPT_BADOPTION_NOALIAS, se devuelve la opción más externa. De lo contrario, flags debe ser 0, y la opción que se devuelve puede haber sido especificada a través de un alias.

Estas dos funciones hacen que el manejo de errores de popt sea trivial para la mayoría de las aplicaciones. Cuando se detecta un error en la mayoría de las funciones, se imprime un mensaje de error junto con la cadena de error de poptStrerror(). Cuando ocurre un error durante el análisis de argumentos, un código similar al siguiente muestra un mensaje de error útil:

fprintf(stderr, "%s: %s\n",
        poptBadOption(optCon, POPT_BADOPTION_NOALIAS),
        poptStrerror(rc));

ALIAS DE OPCIONES

Uno de los principales beneficios de usar popt sobre getopt() es la capacidad de usar alias de opciones. Esto permite al usuario especificar opciones que popt expande en otras opciones cuando se especifican. Si el programa grep estándar hiciera uso de popt, los usuarios podrían agregar una opción --text que se expandiría a -i -n -E -2 para permitirles encontrar información más fácilmente en archivos de texto.

1. ESPECIFICACIÓN DE ALIAS

Los alias normalmente se especifican en dos lugares: /etc/popt y el archivo .popt en el directorio principal del usuario (encontrado a través de la variable de entorno HOME). Ambos archivos tienen el mismo formato, un número arbitrario de líneas formateadas de esta manera:

nombreapp alias nuevaopcion expansión

El nombreapp es el nombre de la aplicación, que debe ser el mismo que el parámetro name pasado a poptGetContext(). Esto permite que cada archivo especifique alias para múltiples programas. La palabra clave alias especifica que se está definiendo un alias; actualmente, los archivos de configuración de popt solo admiten alias, pero es posible que se agreguen otras capacidades en el futuro. La siguiente opción es la opción que debe ser aliasada, y puede ser una opción corta o larga. El resto de la línea especifica la expansión para el alias. Se analiza de manera similar a un comando de shell, lo que permite usar \, ", y ' para las comillas. Si una barra invertida es el último carácter de una línea, se asume que la siguiente línea del archivo es una continuación lógica de la línea que contiene la barra invertida, al igual que en el shell.

La siguiente entrada agregaría una opción --text al comando grep, como se sugirió al principio de esta sección.

grep alias --text -i -n -E -2

2. HABILITACIÓN DE ALIAS

Una aplicación debe habilitar la expansión de alias para un poptContext antes de llamar a poptGetNextArg() por primera vez. Hay tres funciones que definen alias para un contexto:

int poptReadDefaultConfig(poptContext con, int flags);
Esta función lee alias de /etc/popt y del archivo .popt en el directorio principal del usuario. Actualmente, flags debe ser NULL, ya que solo se proporciona para expansión futura. 
int poptReadConfigFile(poptContext con, char * fn);
Se abre y se analiza el archivo especificado por fn como un archivo de configuración de popt. Esto permite a los programas usar archivos de configuración específicos del programa. 
int poptAddAlias(poptContext con, struct poptAlias alias,
                 int flags);
Ocasionalmente, los procesos quieren especificar alias sin tener que leerlos de un archivo de configuración. Esta función agrega un nuevo alias a un contexto. El argumento flags debe ser 0, ya que actualmente está reservado para expansión futura. El nuevo alias se especifica como un struct poptAlias, que se define como: 
struct poptAlias {
     const char * longName; /* puede ser NULL */
     char shortName; /* puede ser '\0' */
     int argc;
     const char ** argv; /* debe ser liberable con free() */
};

Los dos primeros elementos, longName y shortName, especifican la opción que es aliasada. Los dos últimos, argc y argv, definen la expansión que se utilizará cuando se encuentre la opción de alias.

popt(3) — Arch Linux Manual Pages

NAME

popt — library to parse argv style arguments

SYNOPSIS

#include <popt.h>

poptContext poptGetContext(const char *name, int argc, const char **argv, const struct poptOption *options, int flags);

int poptGetNextOpt(poptContext con);

char * poptGetArg(poptContext con);

const char * poptPeekArg(poptContext con);

void poptFreeContext(poptContext con);

void poptSetOtherOptionHelp(poptContext con, const char *otherHelp);

void poptPrintUsage(poptContext con, FILE *fp, int flags);

const char * poptBadOption(poptContext con, int flags);

int poptStrerror(int error);

int poptDupArgv(int argc, const char ** argv, int * argcPtr, const char *** argvPtr);

int poptParseArgvString(char * s, int * argcPtr, char *** argvPtr);

int poptStuffArgs(poptContext con, const char ** argv);

DESCRIPTION

The popt library is a library designed to help applications parse command line arguments. It supports options in the traditional Unix style (e.g. -a, -b, --long-option) and also allows for aliasing options, so that a single invocation can trigger multiple options.

The popt library may be used in a variety of ways. It can be used to process options for the current program, or it can be used to process options for other programs. It can also be used to parse argument strings that are formatted identically to command lines.

BASIC POPT USAGE

The basic usage model is to initialize a poptContext, then repeatedly call poptGetNextOpt() until it returns -1. The application can then process any remaining arguments using poptGetArg().

First, an array of struct poptOption is defined. This structure defines the valid options the program accepts, and what action should be taken when each option is encountered. The structure is defined as follows:

struct poptOption {
    const char *optDescribe;     /* description of option */
    char         shortOpt;        /* short option letter */
    int          argInfo;         /* flag indicating if option takes argument */
    void         *arg;            /* location to store arg value */
    int          val;             /* value returned when option is processed */
    const char   *argLabel;       /* argument label for usage message */
    const char   *docString;      /* documentation string */
};

When poptGetNextOpt() is called, it returns the value specified in the val field of the matching struct poptOption. If the option takes an argument, it is stored in the location pointed to by the arg field. If the option doesn't take an argument, the arg field is ignored.

Options can be specified as arguments to programs by passing them to poptGetContext(). If the first argument to poptGetContext() is NULL, then the arguments are taken from the standard argc and argv passed to main().

The following constants may be used for argInfo:

POPT_ARG_NONE
The option takes no argument.
POPT_ARG_INT
The option takes an integer argument.
POPT_ARG_STRING
The option takes a string argument.
POPT_ARG_FLOAT
The option takes a floating-point argument.
POPT_ARG_DOUBLE
The option takes a double-precision floating-point argument.
POPT_ARG_LONG
The option takes a long integer argument.
POPT_ARG_ANY
The option takes an argument, which is stored as a string. This is the default if no argument is specified.

The following constants may be used for val:

POPT_AUTOOPTION
This signifies that the next option in the table should be used as the argument for the current option. This is useful for options that take arguments.
POPT_AUTOHELP
This signifies that a help option should be automatically generated. The value returned is `?`.
POPT_ getopt
This signifies that the option should be processed by the underlying getopt library. This is useful for compatibility with older programs.

A special entry in the options table, consisting of all NULL pointers and zero values, signifies the end of the table.

Once all options have been processed, any remaining arguments on the command line are considered non-option arguments. These can be retrieved using poptGetArg(). If poptGetArg() returns NULL, then all arguments have been processed.

The function poptFreeContext() should be called when finished with the popt context to free any allocated memory.

ERROR HANDLING

If poptGetNextOpt() encounters an error, it returns a negative value indicating the type of error. The function poptStrerror() can be used to translate these error codes into human-readable strings. The function poptBadOption() can be used to retrieve the specific option that caused the error.

OPTION ALIASING

The popt library supports option aliasing, which allows a single option to trigger multiple other options. This is done by setting the argInfo field of a struct poptOption to POPT_ARG_ALIAS. The arg field should then point to a NULL-terminated array of strings, where each string is a command-line option that should be executed.

For example:

struct poptOption aliases[] = {
    { "verbose", 'v', POPT_ARG_NONE, 0, 'v', NULL, NULL },
    { "quiet", 'q', POPT_ARG_NONE, 0, 'q', NULL, NULL },
    { "force", 'f', POPT_ARG_NONE, 0, 'f', NULL, NULL },
    { "help", 0, POPT_ARG_HELP, 0, 'h', NULL, NULL },
    { "version", 0, POPT_ARG_VERSION, 0, 'V', NULL, NULL },
    { "all", 0, POPT_ARG_ALIAS, (void*) "\v\v\f", 0, NULL, "enable verbose, quiet, and force" },
    { NULL, 0, 0, NULL, 0 }
};

In this example, the alias "--all" is defined to trigger the options "-v", "-q", and "-f". Note that the NULL terminator for the alias string list is represented by a NULL character ('\0') in the string itself. The actual NULL terminator for the array is a NULL pointer.

PARSING ARGUMENT STRINGS

Although popt is usually used for parsing arguments already divided into an argv-style array, some programs need to parse strings that are formatted identically to command lines. To facilitate this, popt provides a function that parses a string into an array of strings, using rules similar to normal shell parsing.

#include <popt.h>
int poptParseArgvString(char * s, int * argcPtr,
                        char *** argvPtr);
int poptDupArgv(int argc, const char ** argv, int * argcPtr,
                        const char *** argvPtr);

The string s is parsed into an argv-style array. The integer pointed to by the argcPtr parameter contains the number of elements parsed, and the final argvPtr parameter contains the address of the newly created array. The routine poptDupArgv() can be used to make a copy of an existing argument array.

The argvPtr created by poptParseArgvString() or poptDupArgv() is suitable to pass directly to poptGetContext(). Both routines return a single dynamically allocated contiguous block of storage and should be free()ed when the application is finished with the storage.

HANDLING EXTRA ARGUMENTS

Some applications implement the equivalent of option aliasing but need to do so through special logic. The poptStuffArgs() function allows an application to insert new arguments into the current poptContext.

#include <popt.h>
int poptStuffArgs(poptContext con, const char ** argv);

The passed argv must have a NULL pointer as its final element. When poptGetNextOpt() is next called, the "stuffed" arguments are the first to be parsed. popt returns to the normal arguments once all the stuffed arguments have been exhausted.

EXAMPLE

The following example is a simplified version of the program "robin" which appears in Chapter 15 of the text cited below. Robin has been stripped of everything but its argument-parsing logic, slightly reworked, and renamed "parse." It may prove useful in illustrating at least some of the features of the extremely rich popt library.

#include <popt.h>
#include <stdio.h>
#include <stdlib.h>
void usage(poptContext optCon, int exitcode, char *error, char *addl) {
    poptPrintUsage(optCon, stderr, 0);
    if (error) fprintf(stderr, "%s: %s\n", error, addl);
    exit(exitcode);
}
int main(int argc, char *argv[]) {
   int     c;            /* used for argument parsing */
   int     i = 0;        /* used for tracking options */
   int     speed = 0;    /* used in argument parsing to set speed */
   int     raw = 0;      /* raw mode? */
   int     j;
   char    buf[BUFSIZ+1];
   const char *portname;
   poptContext optCon;   /* context for parsing command-line options */
   struct poptOption optionsTable[] = {
      { "bps", 'b', POPT_ARG_INT, &speed, 0,
	"signaling rate in bits-per-second", "BPS" },
      { "crnl", 'c', 0, 0, 'c',
	"expand cr characters to cr/lf sequences", NULL },
      { "hwflow", 'h', 0, 0, 'h',
	"use hardware (RTS/CTS) flow control", NULL },
      { "noflow", 'n', 0, 0, 'n',
	"use no flow control", NULL },
      { "raw", 'r', 0, &raw, 0,
	"don't perform any character conversions", NULL },
      { "swflow", 's', 0, 0, 's',
	"use software (XON/XOF) flow control", NULL } ,
      POPT_AUTOHELP
      { NULL, 0, 0, NULL, 0 }
    };
   optCon = poptGetContext(NULL, argc, argv, optionsTable, 0);
   poptSetOtherOptionHelp(optCon, "[OPTIONS]* <port>");
   if (argc < 2) {
	poptPrintUsage(optCon, stderr, 0);
	exit(1);
   }
   /* Now do options processing, get portname */
   while ((c = poptGetNextOpt(optCon)) >= 0) {
      switch (c) {
       case 'c':
          buf[i++] = 'c';
          break;
       case 'h':
          buf[i++] = 'h';
          break;
       case 's':
          buf[i++] = 's';
          break;
       case 'n':
          buf[i++] = 'n';
          break;
      }
   }
   portname = poptGetArg(optCon);
   if((portname == NULL) || !(poptPeekArg(optCon) == NULL))
      usage(optCon, 1, "Specify a single port", ".e.g., /dev/cua0");
   if (c < -1) {
      /* an error occurred during option processing */
      fprintf(stderr, "%s: %s\n",
              poptBadOption(optCon, POPT_BADOPTION_NOALIAS),
              poptStrerror(c));
      return 1;
   }
   /* Print out options, portname chosen */
   printf("Options  chosen: ");
   for(j = 0; j < i ; j++)
      printf("-%c ", buf[j]);
   if(raw) printf("-r ");
   if(speed) printf("-b %d ", speed);
   printf("\nPortname chosen: %s\n", portname);
   poptFreeContext(optCon);
   exit(0);
}

RPM, a popular Linux package management program, makes heavy use of popt's features. Many of its command-line arguments are implemented through popt aliases, which makes RPM an excellent example of how to take advantage of the popt library. For more information on RPM, see http://www.rpm.org. The popt source code distribution includes test program(s) which use all of the features of the popt libraries in various ways. If a feature isn't working for you, the popt test code is the first place to look.
