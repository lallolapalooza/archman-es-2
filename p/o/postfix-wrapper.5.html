NOMBRE

postfix-wrapper - API de Postfix multi-instancia

DESCRIPCIÓN


El soporte para la gestión de múltiples instancias de Postfix está disponible a partir de la versión 2.6. Las instancias comparten archivos ejecutables y documentación, pero tienen sus propios directorios para archivos de configuración, cola y datos.

Este documento describe cómo la familiar interfaz de usuario "postfix start" etc. puede ser utilizada para gestionar una o múltiples instancias de Postfix, y proporciona detalles de una API para coordinar actividades entre el comando postfix(1) y un programa gestor multi-instancia.

Con el soporte multi-instancia, la instancia por defecto de Postfix siempre es requerida. Esta instancia se identifica por el valor por defecto del parámetro config_directory.

OPERACIÓN GENERAL

El soporte multi-instancia es compatible con versiones anteriores: cuando se ejecuta solo una instancia de Postfix, comandos como "postfix start" no cambiarán su comportamiento en absoluto.

Incluso con múltiples instancias de Postfix, puedes seguir usando los mismos comandos de postfix en scripts de arranque, procedimientos de actualización y otros lugares. Los comandos hacen más trabajo, pero los humanos no se ven obligados a aprender trucos nuevos.

Por ejemplo, para iniciar todas las instancias de Postfix, usa:

# postfix start

Otros comandos de postfix(1) también funcionan como se espera. Por ejemplo, para averiguar qué instancias de Postfix existen en una configuración multi-instancia, usa:

# postfix status

Esto enumera el estado de todas las instancias de Postfix dentro de una configuración multi-instancia.

GESTIÓN DE UNA INSTANCIA INDIVIDUAL DE POSTFIX

Para gestionar una instancia específica de Postfix, especifica su directorio de configuración en la línea de comandos de postfix(1):

# postfix -c /ruta/al/directorio_de_configuración comando

Alternativamente, el comando postfix(1) acepta el directorio de configuración de la instancia a través de la variable de entorno MAIL_CONFIG (la opción de línea de comandos -c tiene mayor precedencia).

De lo contrario, el comando postfix(1) operará en todas las instancias de Postfix.

HABILITACIÓN DEL MODO MULTI-INSTANCIA DE POSTFIX(1)

Por defecto, el comando postfix(1) opera en modo de instancia única. En este modo, el comando invoca directamente el archivo postfix-script (actualmente instalado en el directorio del demonio). Este archivo contiene los comandos que inician o detienen una instancia de Postfix, actualizan la configuración de una instancia de Postfix, etc.

Cuando el comando postfix(1) opera en modo multi-instancia como se discute a continuación, el comando necesita ejecutar comandos de inicio, detención, etc. para cada instancia de Postfix. Esta multiplicación de comandos es manejada por un programa gestor multi-instancia.

La habilitación del modo multi-instancia de postfix(1) se realiza de la siguiente manera: en el archivo main.cf de la instancia por defecto de Postfix, 1) especifica la ruta del programa gestor multi-instancia con el parámetro multi_instance_wrapper; 2) pobla el parámetro multi_instance_directories con las rutas de los directorios de configuración de instancias adicionales de Postfix. Por ejemplo:

/etc/postfix/main.cf:
    multi_instance_wrapper = $daemon_directory/postfix-wrapper
    multi_instance_directories = /etc/postfix-test

El archivo $daemon_directory/postfix-wrapper implementa un gestor simple y contiene instrucciones para crear instancias de Postfix manualmente. El comando postmulti(1) proporciona una implementación más extensa que incluye soporte para la gestión del ciclo de vida.

Los parámetros multi_instance_directories y otros parámetros de main.cf se enumeran a continuación en la sección PARÁMETROS DE CONFIGURACIÓN.

En modo multi-instancia, el comando postfix(1) invoca el comando $multi_instance_wrapper en lugar del archivo postfix-script. Este gestor multi-instancia a su vez ejecuta el comando postfix(1) en modo de instancia única para cada instancia de Postfix.

Para ilustrar las ideas principales detrás de la operación multi-instancia, a continuación se presenta un ejemplo de una implementación simple pero útil de un gestor multi-instancia:

#!/bin/sh
: ${command_directory?"no invoques este comando directamente"}
POSTCONF=$command_directory/postconf
POSTFIX=$command_directory/postfix
instance_dirs=`$POSTCONF -h multi_instance_directories |
                sed 'y/,/ /'` || exit 1
err=0
for dir in $config_directory $instance_dirs
do
    case "$1" in
    stop|abort|flush|reload|drain)
        test "`$POSTCONF -c $dir -h multi_instance_enable`" \
            = yes || continue;;
    start)
        test "`$POSTCONF -c $dir -h multi_instance_enable`" \
            = yes || {
            $POSTFIX -c $dir check || err=$?
            continue
        };;
    esac
    $POSTFIX -c $dir "$@" || err=$?
done
exit $err

CONTROLES MULTI-INSTANCIA POR INSTANCIA

Cada instancia de Postfix tiene su propio archivo main.cf con parámetros que controlan cómo el gestor multi-instancia opera en esa instancia. Esta sección discute las configuraciones más importantes.

La configuración "multi_instance_enable = yes" permite al gestor multi-instancia iniciar (detener, etc.) la instancia de Postfix correspondiente. Por razones de seguridad, esta configuración no es la predeterminada.

La configuración por defecto "multi_instance_enable = no" es útil para pruebas manuales con "postfix -c /ruta/nombre start" etc. El gestor multi-instancia no iniciará dicha instancia y omitirá comandos como "stop" o "flush" que requieren una instancia de Postfix en ejecución. El gestor multi-instancia ejecutará comandos como "check", "set-permissions" o "upgrade-configuration", y reemplazará "start" por "check" para que los problemas se informen incluso cuando la instancia esté deshabilitada.

MANTENIMIENTO DE ARCHIVOS COMPARTIDOS Y NO COMPARTIDOS

Algunos archivos se comparten entre instancias de Postfix, como los ejecutables y las páginas de manual, y algunos archivos son por instancia, como los archivos de configuración, los archivos de cola de correo y los archivos de datos. Consulte la sección ARCHIVOS NO COMPARTIDOS a continuación para obtener una lista de archivos por instancia.

Antes de que se implementara el soporte multi-instancia de Postfix, los ejecutables, las páginas de manual, etc., siempre se han mantenido como parte de la instancia por defecto de Postfix.

Con el soporte multi-instancia, simplemente continuamos haciendo esto. Específicamente, una instancia de Postfix no comprobará ni actualizará los archivos compartidos cuando el valor config_directory de esa instancia esté listado en el parámetro multi_instance_directories del archivo main.cf por defecto.

La consecuencia de este enfoque es que la instancia por defecto de Postfix debe ser revisada y actualizada antes que cualquier otra instancia.

RESUMEN DE LA API MULTI-INSTANCIA

Solo el gestor multi-instancia implementa soporte para el parámetro de configuración multi_instance_enable. El gestor multi-instancia iniciará solo las instancias de Postfix cuyos archivos main.cf tengan "multi_instance_enable = yes". Una configuración de "no" permite probar una instancia de Postfix manualmente.

El comando postfix(1) opera en una sola instancia de Postfix cuando se especifica la opción -c, o cuando MAIL_CONFIG está presente en el entorno del proceso. Esto es necesario para terminar la recursión.

De lo contrario, cuando el valor del parámetro multi_instance_directories no esté vacío, el comando postfix(1) ejecutará el comando especificado con el parámetro multi_instance_wrapper, en lugar de ejecutar los comandos en postfix-script.

El gestor multi-instancia omite comandos como "stop" o "reload" que requieren una instancia de Postfix en ejecución, cuando una instancia no tiene "multi_instance_enable = yes". Esto evita mensajes de error falsos.

El gestor multi-instancia reemplaza un comando "start" por "check" cuando el archivo main.cf de una instancia de Postfix no tiene "multi_instance_enable = yes". Esta sustitución asegura que los problemas se informarán incluso cuando la instancia esté deshabilitada.

postfix-wrapper(8) — Arch manual pages

NAME

postfix-wrapper — Postfix multi-instance manager

SYNOPSIS

postfix-wrapper [command]

DESCRIPTION

The postfix-wrapper program is used to manage multiple Postfix instances on a single host. It is typically invoked by the postfix(1) command, but can also be invoked directly to manage Postfix instances.

GENERAL OPERATION

When multiple Postfix instances are run on a single host, they typically share Postfix executable files and documentation. Each instance has its own configuration, mail queue, and mail data directories.

The postfix-wrapper program determines which Postfix instance to operate on based on the following:

  1. If the MAIL_CONFIG environment variable is set, it specifies the configuration directory of the instance to operate on.
  2. If the postfix(1) command is invoked with the -c option, it specifies the configuration directory of the instance to operate on.
  3. If neither of the above is specified, it operates on the default Postfix instance.

MANAGING AN INDIVIDUAL POSTFIX INSTANCE

The postfix-wrapper program can be used to start, stop, restart, and check the status of individual Postfix instances. The available commands are:

start
Start the Postfix instance.
stop
Stop the Postfix instance.
restart
Restart the Postfix instance.
status
Check the status of the Postfix instance.

These commands are typically invoked via the postfix(1) command, which then invokes postfix-wrapper.

ENABLING POSTFIX(1) MULTI-INSTANCE MODE

To enable multi-instance mode, you need to configure the multi_instance_directories parameter in the main Postfix configuration file (main.cf). This parameter is a space-separated list of Postfix configuration directories for non-default instances.

For example:

main.cf: multi_instance_directories = /etc/postfix-test, /etc/postfix-backup

When this parameter is set, the multi_instance_wrapper parameter specifies the command to be used to manage the non-default instances. This is typically $daemon_directory/postfix-wrapper.

PER-INSTANCE MULTI-INSTANCE MANAGER CONTROLS

The following parameters control the behavior of postfix-wrapper for individual instances:

multi_instance_name
The name of this Postfix instance. This is used to identify the instance when it is managed by postfix-wrapper.
multi_instance_group
The group name for this Postfix instance. This is used for grouping instances together for management purposes.
multi_instance_enable
Specifies whether this Postfix instance should be managed by postfix-wrapper. Set to "yes" to enable management, or "no" to disable.

MAINTAINING SHARED AND NON-SHARED FILES

When using multiple Postfix instances, it's important to understand which files are shared and which are not. Shared files include Postfix executables and documentation, which are typically located in /usr/lib/postfix.

Non-shared files are specific to each instance and include:

  • Configuration files (main.cf, master.cf)
  • Mail queue files
  • Mail data files

The config_directory parameter specifies the location of the instance's configuration files. The data_directory parameter specifies the location of instance-specific data files, and queue_directory specifies the top-level queue directory for the instance.

The multi_instance_directories parameter in the default main.cf lists the configuration directories of non-default instances. This ensures that commands like postdrop(1) and postqueue(1) can correctly identify the relevant instance configuration.

The legacy alternate_config_directories parameter is still necessary for non-default instances that run different versions of Postfix or that are not managed together with the default instance.

No Postfix command or script will update or check shared files when its config_directory value is listed in the default main.cf's multi_instance_directories parameter value. Therefore, the default instance should be checked and updated before any Postfix instances that depend on it.

Set-gid commands such as postdrop(1) and postqueue(1) effectively append the multi_instance_directories parameter value to the legacy alternate_config_directories parameter value. The commands use this information to determine whether a -c option or MAIL_CONFIG environment setting specifies a legitimate value.

The legacy alternate_config_directories parameter remains necessary for non-default Postfix instances that are running different versions of Postfix, or that are not managed together with the default Postfix instance.

ENVIRONMENT VARIABLES

MAIL_CONFIG
When present, this forces the postfix(1) command to operate only on the specified Postfix instance. This environment variable is exported by the postfix(1) -c option, so that postfix(1) commands in descendant processes will work correctly.

CONFIGURATION PARAMETERS

The text below provides only a parameter summary. See postconf(5) for more details.

multi_instance_directories (empty)
An optional list of non-default Postfix configuration directories; these directories belong to additional Postfix instances that share the Postfix executable files and documentation with the default Postfix instance, and that are started, stopped, etc., together with the default Postfix instance.
multi_instance_wrapper (empty)
The pathname of a multi-instance manager command that the postfix(1) command invokes when the multi_instance_directories parameter value is non-empty.
multi_instance_name (empty)
The optional instance name of this Postfix instance.
multi_instance_group (empty)
The optional instance group name of this Postfix instance.
multi_instance_enable (no)
Allow this Postfix instance to be started, stopped, etc., by a multi-instance manager.

NON-SHARED FILES

config_directory (see 'postconf -d' output)
The default location of the Postfix main.cf and master.cf configuration files.
data_directory (see 'postconf -d' output)
The directory with Postfix-writable data files (for example: caches, pseudo-random numbers).
queue_directory (see 'postconf -d' output)
The location of the Postfix top-level queue directory.
