NOMBRE

podman-network - Gestionar redes de Podman

SINOPSIS

podman network subcomando

DESCRIPCIÓN

El comando network gestiona las redes para Podman.

Podman soporta dos backends de red: Netavark y CNI. Netavark es el backend de red por defecto y se añadió en la versión 4.0 de Podman. CNI está obsoleto y será eliminado en la próxima versión mayor de Podman 5.0, en preferencia de Netavark. Para configurar el backend de red, utiliza la clave network_backend bajo la sección [Network] en containers.conf(5). Los nuevos sistemas usan netavark por defecto, para comprobar qué backend se está utilizando, ejecuta podman info --format {{.Host.NetworkBackend}}.

Todos los comandos de red funcionan para ambos backends, pero CNI y Netavark usan archivos de configuración diferentes, por lo que las redes deben ser creadas de nuevo después de un cambio de backend.

NOTAS SOBRE SUBREDES

Podman requiere IPs por defecto específicas y, por lo tanto, subredes de red. Los valores por defecto utilizados por Podman se pueden modificar en el archivo containers.conf(5).

Red Podman

La red puente por defecto (llamada podman) utiliza 10.88.0.0/16 como subred. Cuando Podman se ejecuta como root, la red podman se utiliza por defecto. Es lo mismo que añadir la opción --network bridge o --network podman. Esta subred se puede cambiar en containers.conf(5) bajo la sección [network]. Establece default_subnet a cualquier subred que esté libre en el entorno. El nombre de la red por defecto también se puede cambiar de podman a otro nombre usando la clave de red por defecto. Ten en cuenta que esto solo se hace cuando no hay contenedores en ejecución.

Pasta

Pasta por defecto no realiza Network Address Translation (NAT) y copia las IPs de tu interfaz principal al espacio de nombres del contenedor. Si pasta no puede encontrar una interfaz con la ruta por defecto, seleccionará una interfaz si solo hay una interfaz con una ruta válida. Si no tienes una ruta por defecto y varias interfaces tienen rutas definidas, pasta no podrá determinar la interfaz correcta y fallará al iniciarse. Para especificar la interfaz, utiliza la opción -i para pasta. Un conjunto por defecto de opciones de pasta se puede configurar en containers.conf(5) bajo la sección [network] con la clave pasta_options.

La herramienta de red rootless por defecto se puede seleccionar en containers.conf(5) bajo la sección [network] con default_rootless_network_cmd, que se puede establecer a pasta (por defecto) o slirp4netns.

Slirp4netns

Slirp4netns utiliza 10.0.2.0/24 para su red por defecto. Esto también se puede cambiar en containers.conf(5) pero bajo la sección [engine]. Utiliza la clave network_cmd_options y añade ["cidr=X.X.X.X/24"] como valor. Ten en cuenta que slirp4netns necesita un tamaño de prefijo de red entre 1 y 25. Esta opción acepta un array, por lo que se pueden añadir más opciones en una cadena separada por comas, como se describe en la página del manual de podman-network-create(1). Para cambiar el CIDR de un solo contenedor, especifícalo en la línea de comandos utilizando la opción --network de esta manera: --network slirp4netns:cidr=192.168.1.0/24.

Podman network create

Cuando se crea una nueva red con el comando podman network create, y no se proporciona una subred con la opción --subnet, Podman comienza a seleccionar una subred libre de 10.89.0.0/24 a 10.255.255.0/24. Utiliza la opción default_subnet_pools bajo la sección [network] en containers.conf(5) para cambiar el rango y/o tamaño que se asigna por defecto.
