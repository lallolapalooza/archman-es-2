NOMBRE

postgres - servidor de base de datos PostgreSQL

SINOPSIS

postgres [opción...]

DESCRIPCIÓN

postgres es el servidor de base de datos PostgreSQL. Para que una aplicación cliente pueda acceder a una base de datos, se conecta (a través de la red o localmente) a una instancia de postgres en ejecución. La instancia de postgres inicia entonces un proceso de servidor separado para manejar la conexión.

Una instancia de postgres siempre gestiona los datos de exactamente un clúster de bases de datos. Un clúster de bases de datos es una colección de bases de datos que se almacena en una ubicación común del sistema de archivos (el "área de datos"). Pueden ejecutarse varias instancias de postgres en un sistema a la vez, siempre que utilicen áreas de datos diferentes y puertos de comunicación distintos (ver más abajo). Cuando postgres se inicia, necesita saber la ubicación del área de datos. La ubicación debe especificarse con la opción -D o la variable de entorno PGDATA; no hay un valor predeterminado. Típicamente, -D o PGDATA apunta directamente al directorio del área de datos creado por initdb(1). Otros posibles diseños de archivos se discuten en la Sección 19.2.

Por defecto, postgres se inicia en primer plano e imprime los mensajes de registro en el flujo de error estándar. En aplicaciones prácticas, postgres debería iniciarse como un proceso en segundo plano, quizás al arrancar el sistema.

El comando postgres también puede ser invocado en modo de usuario único. El uso principal de este modo es durante el arranque por parte de initdb(1). A veces se utiliza para depuración o recuperación ante desastres; ten en cuenta que ejecutar un servidor de usuario único no es realmente adecuado para depurar el servidor, ya que no ocurrirán comunicaciones interprocesos ni bloqueos realistas. Cuando se invoca en modo de usuario único desde la línea de comandos, el usuario de la sesión se establecerá en el usuario con ID 1, y se otorgarán poderes implícitos de superusuario a este usuario. Este usuario no tiene por qué existir, por lo que el modo de usuario único puede utilizarse para recuperar manualmente ciertos tipos de daños accidentales en los catálogos del sistema.

OPCIONES

postgres acepta los siguientes argumentos de línea de comandos. Para una discusión detallada de las opciones, consulta el Capítulo 19. Puedes ahorrarte escribir la mayoría de estas opciones configurando un archivo de configuración. Algunas opciones (seguras) también se pueden establecer desde el cliente que se conecta de forma dependiente de la aplicación para que se apliquen solo a esa sesión. Por ejemplo, si la variable de entorno PGOPTIONS está establecida, los clientes basados en libpq pasarán esa cadena al servidor, que la interpretará como opciones de línea de comandos de postgres.

Propósito General

-B nbuffers

Establece el número de búferes compartidos para uso de los procesos del servidor. El valor predeterminado de este parámetro se elige automáticamente por initdb. Especificar esta opción es equivalente a establecer el parámetro de configuración shared_buffers.

-c nombre=valor

Establece un parámetro de ejecución con nombre. Los parámetros de configuración compatibles con PostgreSQL se describen en el Capítulo 19. La mayoría de las otras opciones de línea de comandos son de hecho formas cortas de dicha asignación de parámetros. -c puede aparecer varias veces para establecer varios parámetros.

-C nombre

Imprime el valor del parámetro de ejecución con nombre y sale. (Ver la opción -c arriba para más detalles.) Esto devuelve los valores de postgresql.conf, modificados por cualquier parámetro proporcionado en esta invocación. No refleja los parámetros proporcionados cuando se inició el clúster.

Esto se puede usar en un servidor en ejecución para la mayoría de los parámetros. Sin embargo, el servidor debe ser apagado para algunos parámetros calculados en tiempo de ejecución (por ejemplo, shared_memory_size, shared_memory_size_in_huge_pages y wal_segment_size).

Esta opción está pensada para que otros programas que interactúan con una instancia de servidor, como pg_ctl(1), consulten los valores de los parámetros de configuración. Las aplicaciones dirigidas al usuario deberían usar en su lugar SHOW o la vista pg_settings.

-d nivel-depuración

Establece el nivel de depuración. Cuanto mayor sea este valor, más salida de depuración se escribirá en el registro del servidor. Los valores van de 1 a 5. También es posible pasar -d 0 para una sesión específica, lo que evitará que el nivel de registro del servidor del proceso postgres padre se propague a esta sesión.

-D datadir

Especifica la ubicación en el sistema de archivos de los archivos de configuración de la base de datos. Ver Sección 19.2 para más detalles.

-e

Establece el estilo de fecha predeterminado en "Europeo", es decir, orden DMY de los campos de fecha de entrada. Esto también hace que el día se imprima antes que el mes en ciertos formatos de salida de fecha. Ver Sección 8.5 para más información.

-F

Deshabilita las llamadas fsync para mejorar el rendimiento, a riesgo de corrupción de datos en caso de un fallo del sistema. Especificar esta opción es equivalente a deshabilitar el parámetro de configuración fsync. ¡Lee la documentación detallada antes de usar esto!

-h hostname

Especifica el nombre o la dirección IP del host en el que postgres debe escuchar las conexiones TCP/IP de las aplicaciones cliente. El valor también puede ser una lista separada por comas de direcciones, o * para especificar la escucha en todas las interfaces disponibles. Un valor vacío especifica no escuchar en ninguna dirección IP, en cuyo caso solo se pueden usar sockets de dominio Unix para conectarse al servidor. El valor predeterminado es escuchar solo en localhost. Especificar esta opción es equivalente a establecer el parámetro de configuración listen_addresses.

-i

Permite a los clientes remotos conectarse a través de conexiones TCP/IP (dominio de Internet). Sin esta opción, solo se aceptan conexiones locales. Esta opción es equivalente a establecer listen_addresses a * en postgresql.conf o a través de -h.

Esta opción está obsoleta ya que no permite el acceso a toda la funcionalidad de listen_addresses. Por lo general, es mejor establecer listen_addresses directamente.

-k directorio

Especifica el directorio del socket de dominio Unix en el que postgres debe escuchar las conexiones de las aplicaciones cliente. El valor también puede ser una lista separada por comas de directorios. Un valor vacío especifica no escuchar en ningún socket de dominio Unix, en cuyo caso solo se pueden usar sockets TCP/IP para conectarse al servidor. El valor predeterminado suele ser /tmp, pero eso puede cambiarse en tiempo de compilación. Especificar esta opción es equivalente a establecer el parámetro de configuración unix_socket_directories.

-l

Habilita conexiones seguras usando SSL. PostgreSQL debe haber sido compilado con soporte para SSL para que esta opción esté disponible. Para más información sobre el uso de SSL, consulta la Sección 18.9.

-N max-conexiones

Establece el número máximo de conexiones de clientes que este servidor aceptará. El valor predeterminado de este parámetro se elige automáticamente por initdb. Especificar esta opción es equivalente a establecer el parámetro de configuración max_connections.

-p puerto

Especifica el puerto TCP/IP o la extensión del archivo del socket de dominio Unix local en el que postgres debe escuchar las conexiones de las aplicaciones cliente. Por defecto, toma el valor de la variable de entorno PGPORT o, si PGPORT no está establecida, entonces el valor establecido durante la compilación (normalmente 5432). Si especificas un puerto diferente al predeterminado, entonces todas las aplicaciones cliente deberán especificar el mismo puerto usando opciones de línea de comandos o PGPORT.

-s

Imprime información de tiempo y otras estadísticas al final de cada comando. Esto es útil para la evaluación comparativa o para usar en la optimización del número de búferes.

-S memoria-trabajo

Especifica la cantidad base de memoria que se utilizará para ordenaciones y tablas hash antes de recurrir a archivos temporales en disco. Ver la descripción del parámetro de configuración work_mem en la Sección 19.4.1.

-V

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

--version

Muestra la versión de postgres y sale.

--nombre=valor

Establece un parámetro de tiempo de ejecución con nombre; una forma más corta de -c.

--describe-config

Esta opción volca las variables de configuración internas del servidor, descripciones y valores predeterminados en formato de tabulación delimitada COPY. Está diseñada principalmente para su uso por herramientas de administración.

-?
--help

Muestra ayuda sobre los argumentos de línea de comandos de postgres y sale.

Opciones Semi-Internas

Las opciones descritas aquí se utilizan principalmente para fines de depuración y, en algunos casos, para ayudar a la recuperación de bases de datos gravemente dañadas. No debería haber ninguna razón para usarlas en una configuración de base de datos de producción. Se enumeran aquí solo para que las utilicen los desarrolladores del sistema PostgreSQL. Además, estas opciones pueden cambiar o eliminarse en una futura versión sin previo aviso.

-f { s | i | o | b | t | n | m | h }

Prohíbe el uso de métodos específicos de escaneo y unión: s e i deshabilitan los escaneos secuenciales e de índice respectivamente, o, b y t deshabilitan los escaneos solo de índice, los escaneos de índice de mapa de bits y los escaneos TID respectivamente, mientras que n, m y h deshabilitan las uniones de bucle anidado, de fusión y de hash respectivamente.

Ni los escaneos secuenciales ni las uniones de bucle anidado se pueden deshabilitar por completo; las opciones -fs y -fn simplemente disuaden al optimizador de usar esos tipos de planes si tiene alguna otra alternativa.

-O

Permite modificar la estructura de las tablas del sistema. Esto es utilizado por initdb.

-P

Ignora los índices del sistema al leer las tablas del sistema, pero aún actualiza los índices al modificar las tablas. Esto es útil al recuperarse de índices del sistema dañados.

-t pa[rser] | pl[anner] | e[xecutor]

Muestra estadísticas de tiempo para cada consulta relacionadas con cada uno de los módulos principales del sistema. Esta opción no se puede usar junto con la opción -s.

-T

Esta opción es para depurar problemas que causan que un proceso servidor muera de forma anormal. La estrategia habitual en esta situación es notificar a todos los demás procesos servidores que deben terminar, enviándoles señales SIGQUIT. Con esta opción, se enviará SIGABRT en su lugar, lo que resultará en la producción de archivos core dump.

-v protocolo

Especifica el número de versión del protocolo frontend/backend a utilizar para una sesión particular. Esta opción es solo para uso interno.

-W segundos

Se produce un retraso de esta cantidad de segundos cuando se inicia un nuevo proceso servidor, después de que este realiza el procedimiento de autenticación. Esto tiene la intención de dar la oportunidad de adjuntar un depurador al proceso servidor.

Opciones para Modo de Usuario Único

Las siguientes opciones solo se aplican al modo de usuario único (ver Modo de Usuario Único a continuación).

--single

Selecciona el modo de usuario único. Este debe ser el primer argumento en la línea de comandos.

base_de_datos

Especifica el nombre de la base de datos a la que se accederá. Este debe ser el último argumento en la línea de comandos. Si se omite, por defecto será el nombre de usuario.

-E

Eco de todos los comandos en la salida estándar antes de ejecutarlos.

-j

Utiliza punto y coma seguido de dos saltos de línea, en lugar de solo un salto de línea, como terminador de entrada de comando.

-r nombre_archivo

Envía toda la salida de registro del servidor a nombre_archivo. Esta opción solo se tiene en cuenta cuando se proporciona como opción de línea de comandos.

ENTORNO

PGCLIENTENCODING

Codificación de caracteres predeterminada utilizada por los clientes. (Los clientes pueden anular esto individualmente). Este valor también se puede establecer en el archivo de configuración.

PGDATA

Ubicación predeterminada del directorio de datos

PGDATESTYLE

Valor predeterminado del parámetro de tiempo de ejecución DateStyle. (El uso de esta variable de entorno está obsoleto).

PGPORT

Número de puerto predeterminado (preferiblemente establecido en el archivo de configuración)

DIAGNÓSTICO

Un mensaje de error que menciona semget o shmget probablemente indica que necesita configurar su kernel para proporcionar memoria compartida y semáforos adecuados. Para más discusión, consulte la Sección 18.4. Es posible que pueda posponer la reconfiguración de su kernel disminuyendo shared_buffers para reducir el consumo de memoria compartida de PostgreSQL, y/o reduciendo max_connections para reducir el consumo de semáforos.

Un mensaje de error que sugiere que ya se está ejecutando otro servidor debe verificarse cuidadosamente, por ejemplo, usando el comando

$ ps ax | grep postgres

o

$ ps -ef | grep postgres

dependiendo de su sistema. Si está seguro de que no se está ejecutando ningún servidor conflictivo, puede eliminar el archivo de bloqueo mencionado en el mensaje e intentarlo de nuevo.

Un mensaje de error que indica la incapacidad de vincularse a un puerto podría indicar que ese puerto ya está en uso por algún proceso que no sea PostgreSQL. También puede recibir este error si termina postgres y lo reinicia inmediatamente usando el mismo puerto; en este caso, simplemente debe esperar unos segundos hasta que el sistema operativo cierre el puerto antes de intentarlo de nuevo. Finalmente, podría recibir este error si especifica un número de puerto que su sistema operativo considera reservado. Por ejemplo, muchas versiones de Unix consideran que los números de puerto inferiores a 1024 son "confiables" y solo permiten que el superusuario de Unix acceda a ellos.

NOTAS

La utilidad pg_ctl(1) se puede usar para iniciar y apagar el servidor postgres de manera segura y cómoda.

Si es posible, no use SIGKILL para matar el servidor principal de postgres. Hacerlo impedirá que postgres libere los recursos del sistema (por ejemplo, memoria compartida y semáforos) que mantiene antes de terminar. Esto podría causar problemas al iniciar una nueva ejecución de postgres.

Para terminar el servidor postgres normalmente, se pueden usar las señales SIGTERM, SIGINT o SIGQUIT. La primera esperará a que todos los clientes terminen antes de salir, la segunda desconectará forzosamente a todos los clientes y la tercera saldrá inmediatamente sin una finalización normal, lo que resultará en una ejecución de recuperación durante el reinicio.

La señal SIGHUP recargará los archivos de configuración del servidor. También es posible enviar SIGHUP a un proceso servidor individual, pero eso generalmente no es sensato.

Para cancelar una consulta en ejecución, envíe la señal SIGINT al proceso que ejecuta ese comando. Para terminar un proceso backend de forma limpia, envíe SIGTERM a ese proceso. Consulte también pg_cancel_backend y pg_terminate_backend en la Sección 9.28.2 para obtener equivalentes llamables en SQL de estas dos acciones.

El servidor postgres utiliza SIGQUIT para indicar a los procesos servidores subordinados que terminen sin una limpieza normal. Los usuarios no deben usar esta señal. Tampoco es aconsejable enviar SIGKILL a un proceso servidor: el proceso principal de postgres interpretará esto como un fallo y forzará a todos los procesos hermanos a salir como parte de su procedimiento estándar de recuperación de fallos.

ERRORES

Las opciones -- no funcionarán en FreeBSD u OpenBSD. Use -c en su lugar. Este es un error en los sistemas operativos afectados; una futura versión de PostgreSQL proporcionará una solución si esto no se corrige.

MODO DE USUARIO ÚNICO

Para iniciar un servidor en modo de usuario único, use un comando como

postgres --single -D /usr/local/pgsql/data otras-opciones mi_base_de_datos

Proporcione la ruta correcta al directorio de la base de datos con -D, o asegúrese de que la variable de entorno PGDATA esté establecida. Especifique también el nombre de la base de datos particular en la que desea trabajar.

Normalmente, el servidor en modo de usuario único trata el salto de línea como el terminador de entrada de comando; no hay inteligencia sobre los puntos y comas, como la hay en psql. Para continuar un comando a través de varias líneas, debe escribir una barra invertida justo antes de cada salto de línea, excepto el último. La barra invertida y el salto de línea adyacente se eliminan del comando de entrada. Tenga en cuenta que esto sucederá incluso cuando esté dentro de un literal de cadena o un comentario.

Pero si usa el modificador de línea -j, un solo salto de línea no termina la entrada del comando; en su lugar, la secuencia punto y coma-salto de línea-salto de línea lo hace. Es decir, escriba un punto y coma seguido inmediatamente de una línea completamente vacía. La barra invertida-salto de línea no se trata de forma especial en este modo. Nuevamente, no hay inteligencia sobre la aparición de tal secuencia dentro de un literal de cadena o un comentario.

En cualquier modo de entrada, si escribe un punto y coma que no está justo antes o como parte de un terminador de entrada de comando, se considera un separador de comandos. Cuando escribe un terminador de entrada de comando, las múltiples sentencias que ha introducido se ejecutarán como una sola transacción.

Para salir de la sesión, escriba EOF (Control+D, generalmente). Si ha introducido algún texto desde el último terminador de entrada de comando, entonces EOF se tomará como un terminador de entrada de comando, y se necesitará otro EOF para salir.

Tenga en cuenta que el servidor en modo de usuario único no proporciona funciones de edición de línea sofisticadas (sin historial de comandos, por ejemplo). El modo de usuario único tampoco realiza ningún procesamiento en segundo plano, como puntos de control automáticos o replicación.

EJEMPLOS

Para iniciar postgres en segundo plano utilizando los valores predeterminados, escriba:

$ nohup postgres >logfile 2>&1 </dev/null &

Para iniciar postgres con un puerto específico, por ejemplo, 1234:

$ postgres -p 1234

Para conectarse a este servidor usando psql, especifique este puerto con la opción -p:

$ psql -p 1234

o establecer la variable de entorno PGPORT:

$ export PGPORT=1234
$ psql

Los parámetros de tiempo de ejecución con nombre se pueden establecer en cualquiera de estos estilos:

$ postgres -c work_mem=1234
$ postgres --work-mem=1234

Cualquiera de las formas anula cualquier configuración que pueda existir para work_mem en postgresql.conf. Tenga en cuenta que los guiones bajos en los nombres de los parámetros se pueden escribir como guion bajo o guion en la línea de comandos. Excepto para experimentos a corto plazo, probablemente sea una mejor práctica editar la configuración en postgresql.conf que depender de un interruptor de línea de comandos para establecer un parámetro.
