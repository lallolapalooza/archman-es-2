POLL(3P) Manual del programador POSIX POLL(3P)

PROLOGO

Esta página del manual es parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

poll — multiplexación de entrada/salida

SINOPSIS

#include <poll.h>
int poll(struct pollfd fds[], nfds_t nfds, int timeout);

DESCRIPCIÓN

La función poll() proporciona a las aplicaciones un mecanismo para multiplexar la entrada/salida a través de un conjunto de descriptores de archivo. Para cada miembro del array al que apunta fds, poll() examinará el descriptor de archivo dado para los eventos especificados en events. El número de estructuras pollfd en el array fds se especifica mediante nfds. La función poll() identificará aquellos descriptores de archivo en los que una aplicación puede leer o escribir datos, o en los que han ocurrido ciertos eventos.

El argumento fds especifica los descriptores de archivo a examinar y los eventos de interés para cada descriptor de archivo. Es un puntero a un array con un miembro por cada descriptor de archivo abierto de interés. Los miembros del array son estructuras pollfd dentro de las cuales fd especifica un descriptor de archivo abierto y events y revents son máscaras de bits construidas mediante la OR de una combinación de las siguientes banderas de eventos:

POLLIN
Se pueden leer datos distintos de datos de alta prioridad sin bloquear.

Para STREAMS, esta bandera se establece en revents incluso si el mensaje es de longitud cero. Esta bandera será equivalente a POLLRDNORM | POLLRDBAND.

POLLRDNORM
Se pueden leer datos normales sin bloquear.

Para STREAMS, los datos en la banda de prioridad 0 se pueden leer sin bloquear. Esta bandera se establece en revents incluso si el mensaje es de longitud cero.

POLLRDBAND
Se pueden leer datos de prioridad sin bloquear.

Para STREAMS, los datos en bandas de prioridad mayores que 0 se pueden leer sin bloquear. Esta bandera se establece en revents incluso si el mensaje es de longitud cero.

POLLPRI
Se pueden leer datos de alta prioridad sin bloquear.

Para STREAMS, esta bandera se establece en revents incluso si el mensaje es de longitud cero.

POLLOUT
Se pueden escribir datos normales sin bloquear.

Para STREAMS, los datos en la banda de prioridad 0 se pueden escribir sin bloquear.

POLLWRNORM
Equivalente a POLLOUT.
POLLWRBAND
Se pueden escribir datos de prioridad.

Para STREAMS, los datos en bandas de prioridad mayores que 0 se pueden escribir sin bloquear. Si se ha escrito en alguna banda de prioridad en este STREAM, este evento solo examina las bandas en las que se ha escrito al menos una vez.

POLLERR
Ha ocurrido un error en el dispositivo o stream. Esta bandera solo es válida en la máscara de bits revents; se ignorará en el miembro events.
POLLHUP
Se ha desconectado un dispositivo, o un pipe o FIFO ha sido cerrado por el último proceso que lo tenía abierto para escribir. Una vez establecida, el estado de desconexión de un FIFO persistirá hasta que algún proceso abra el FIFO para escribir o hasta que se cierren todos los descriptores de archivo de solo lectura para el FIFO. Este evento y POLLOUT son mutuamente excluyentes; un stream nunca puede ser escribible si ha ocurrido una desconexión. Sin embargo, este evento y POLLIN, POLLRDNORM, POLLRDBAND o POLLPRI no son mutuamente excluyentes. Esta bandera solo es válida en la máscara de bits revents; se ignorará en el miembro events.
POLLNVAL
El valor fd especificado no es válido. Esta bandera solo es válida en el miembro revents; se ignorará en el miembro events.

La significancia y semántica de los datos normales, de prioridad y de alta prioridad son específicas del archivo y del dispositivo.

Si el valor de fd es menor que 0, events será ignorado, y revents se establecerá en 0 en esa entrada al regresar de poll().

En cada estructura pollfd, poll() borrará el miembro revents, excepto que donde la aplicación solicitó un informe sobre una condición estableciendo uno de los bits de events listados arriba, poll() establecerá el bit correspondiente en revents si la condición solicitada es verdadera. Además, poll() establecerá las banderas POLLHUP, POLLERR y POLLNVAL en revents si la condición es verdadera, incluso si la aplicación no estableció el bit correspondiente en events.

Si ninguno de los eventos definidos ha ocurrido en ningún descriptor de archivo seleccionado, poll() esperará al menos timeout milisegundos a que ocurra un evento en cualquiera de los descriptores de archivo seleccionados. Si el valor de timeout es 0, poll() regresará inmediatamente. Si el valor de timeout es -1, poll() se bloqueará hasta que ocurra un evento solicitado o hasta que la llamada sea interrumpida.

Las implementaciones pueden imponer limitaciones a la granularidad de los intervalos de tiempo de espera. Si el intervalo de tiempo de espera solicitado requiere una granularidad más fina de la que admite la implementación, el intervalo de tiempo de espera real se redondeará al siguiente valor admitido.

La función poll() no se verá afectada por la bandera O_NONBLOCK.

La función poll() admitirá archivos regulares, dispositivos de terminal y pseudo-terminal, FIFOs, pipes, sockets y archivos basados en STREAMS. El comportamiento de poll() en los elementos de fds que se refieren a otros tipos de archivos no está especificado.

Los archivos regulares siempre se consultarán como TRUE para leer y escribir.

Un descriptor de archivo para un socket que está escuchando conexiones indicará que está listo para leer, una vez que haya conexiones disponibles. Un descriptor de archivo para un socket que se está conectando asincrónicamente indicará que está listo para escribir, una vez que se haya establecido una conexión.

Siempre que la aplicación no realice ninguna acción que resulte en un comportamiento no especificado o indefinido, el valor de los miembros fd y events de cada elemento de fds no será modificado por poll().

VALOR DE RETORNO

Al completarse con éxito, poll() devolverá un valor no negativo. Un valor positivo indica el número total de estructuras pollfd que han seleccionado eventos (es decir, aquellos para los que el miembro revents no es cero). Un valor de 0 indica que la llamada excedió el tiempo de espera y no se seleccionaron descriptores de archivo. En caso de fallo, poll() devolverá -1 y establecerá errno para indicar el error.

ERRORES

La función poll() fallará si:

EAGAIN
La asignación de estructuras de datos internas falló pero una solicitud posterior puede tener éxito.
EINTR
Se capturó una señal durante poll().
EINVAL
El argumento nfds es mayor que {OPEN_MAX}, o uno de los miembros fd se refiere a un STREAM o multiplexor que está enlazado (directa o indirectamente) aguas abajo de un multiplexor.

PROLOG

This section describes the behavior of the poll() function, which is part of the POSIX.1‐2008 standard. This description is based on the IEEE Std 1003.1‐2017.

NAME

poll

allow any of the designated I/O descriptorto become ready

SYNOPSIS

#include <poll.h>
int
poll(struct pollfd *fds, nfds_t nfd, int timeout);

DESCRIPTION

The poll() function shall examine the I/O descriptor members of the structures pointed to by the fds argument to see if any of the events specified in the events members have occurred. The nfd argument specifies the number of structures in the array pointed to by fds. The timeout argument specifies the number of milliseconds that the function shall block waiting for an event to occur. If timeout is zero, poll() shall return immediately. If timeout is “ -1 ” (INT_MAX), it shall block indefinitely until an event occurs. Otherwise, it shall block until an event occurs or until timeout milliseconds elapse.

The pollfd structure shall be defined as follows:

typedef struct pollfd {
    int fd;            /* file descriptor */
    short events;      /* events of interest */
    short revents;     /* events that occurred */
} pollfd_t;

The events and revents members shall be bitmasks formed by logically ORing any of the following flags:

POLLIN
There is data to read.
POLLPRI
There is urgent data to read.
POLLOUT
There is a non-should-block write possible.
POLLERR
An error occurred on the device.
POLLHUP
A hangup occurred on the device.
POLLNVAL
The specified fd value is invalid.

Applications can set the following events bits in the events member:

POLLIN
Request an optional notification for reading.
POLLPRI
Request an optional notification for urgent data.
POLLOUT
Request an optional notification for writing.
POLLRDNORM
Request an optional notification for normal data available for reading.
POLLRDBAND
Request an optional notification for data available for reading in ordi- nary or priority band.
POLLWRBAND
Request an optional notification for writing data in a priority band.

When poll() returns, the revents member of each structure will contain the events that actually occurred. The revents member can include any of the events bits set in the input, plus any of the following additional bits:

POLLERR
An error has occurred when reading or writing the file descriptor. The POLLIN, POLLPRI, POLLOUT, POLLRDNORM, POLLRDBAND, and POLLWRBAND bits should not be set.
POLLHUP
A hang up of the associated device has occurred. The POLLIN, POLLPRI, POLLOUT, POLLRDNORM, POLLRDBAND, and POLLWRBAND bits should not be set.
POLLNVAL
The specified fd is not open for the requested events, or the file descriptor is invalid. The POLLIN, POLLPRI, POLLOUT, POLLRDNORM, POLLRDBAND, and POLLWRBAND bits should not be set.

If the timeout argument is zero, poll() shall return immediately without blocking. If the timeout argument is -1, poll() shall block indefinitely. Otherwise, poll() shall block for at most the number of milliseconds specified by timeout.

The poll() function may be used to test if STREAMS devices can be written to. This is done by setting the events field of the pollfd structure to POLLOUT or POLLWRBAND. If the return value of poll() is positive, then one of the devices can be written to. The following example shows how this may be done:

#include <stropts.h>
#include <poll.h>
...
struct pollfd fds[2];
int timeout_msecs = 500;
int ret;
    int i;
/* Open STREAMS device. */
fds[0].fd = open("/dev/dev0", ...);
fds[1].fd = open("/dev/dev1", ...);
fds[0].events = POLLOUT | POLLWRBAND;
fds[1].events = POLLOUT | POLLWRBAND;
ret = poll(fds, 2, timeout_msecs);
if (ret > 0) {
    /* An event on one of the fds has occurred. */
    for (i=0; i<2; i++) {
        if (fds[i].revents & POLLWRBAND) {
        /* Priority data may be written on device number i. */
...
        }
        if (fds[i].revents & POLLOUT) {
        /* Data may be written on device number i. */
...
        }
        if (fds[i].revents & POLLHUP) {
        /* A hangup has occurred on device number i. */
...
        }
    }
}

The process proceeds as follows:

1.
Sets the timeout parameter to 500 milliseconds.
2.
Opens the STREAMS devices /dev/dev0 and /dev/dev1, and then polls them, specifying POLLOUT and POLLWRBAND as the events of interest.

The STREAMS device names /dev/dev0 and /dev/dev1 are only examples of how STREAMS devices can be named; STREAMS naming conventions may vary among systems conforming to the POSIX.1‐2008.

3.
Uses the ret variable to determine whether an event has occurred on either of the two STREAMS. The poll() function is given 500 milliseconds to wait for an event to occur (if it has not occurred prior to the poll() call).
4.
Checks the returned value of ret. If a positive value is returned, one of the following can be done:
a.
Priority data can be written to the open STREAM on priority bands greater than 0, because the POLLWRBAND event occurred on the open STREAM (fds[0] or fds[1]).
b.
Data can be written to the open STREAM on priority-band 0, because the POLLOUT event occurred on the open STREAM (fds[0] or fds[1]).
5.
If the returned value is not a positive value, permission to write data to the open STREAM (on any priority band) is denied.
6.
If the POLLHUP event occurs on the open STREAM (fds[0] or fds[1]), the device on the open STREAM has disconnected.

RETURN VALUE

Upon successful completion, poll() shall return the number of pollfd structures in the array that have a positive value in their revents member, indicating that a requested event has occurred or an error has been detected. If the timeout interval times out without any requested events occurring, poll() shall return 0.

If an error occurs, poll() shall return -1 and set errno to indicate the error.

ERRORS

The poll() function shall fail if:

EAGAIN
The timeout interval was not infinite, but some resource shortage other than memory occurred during the call.
EBADF
An argument fd is not a valid open file descriptor.
EINTR
A signal was caught during the polling process.
EINVAL
The nfds argument is less than or equal to zero or greater than {{ POLLFD_MAX }}.
ENOMEM
There was insufficient memory available to allocate internal data structures required by poll().

EXAMPLES

None.

APPLICATION USAGE

None.

RATIONALE

The POLLHUP event does not occur for FIFOs just because the FIFO is not open for writing. It only occurs when the FIFO is closed by the last writer and persists until some process opens the FIFO for writing or until all read-only file descriptors for the FIFO are closed.
