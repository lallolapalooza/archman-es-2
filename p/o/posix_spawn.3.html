posix_spawn(3) Manual de funciones de biblioteca posix_spawn(3)

NOMBRE

posix_spawn, posix_spawnp - crear un proceso

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <spawn.h>
int posix_spawn(pid_t *restrict pid, const char *restrict path,
                const posix_spawn_file_actions_t *restrict file_actions,
                const posix_spawnattr_t *restrict attrp,
                char *const argv[restrict],
                char *const envp[restrict]);
int posix_spawnp(pid_t *restrict pid, const char *restrict file,
                const posix_spawn_file_actions_t *restrict file_actions,
                const posix_spawnattr_t *restrict attrp,
                char *const argv[restrict],
                char *const envp[restrict]);

DESCRIPCIÓN

Las funciones posix_spawn() y posix_spawnp() se utilizan para crear un nuevo proceso hijo que ejecute un archivo especificado. Estas funciones fueron especificadas por POSIX para proporcionar un método estandarizado de creación de nuevos procesos en máquinas que carecen de la capacidad de admitir la llamada al sistema fork(2). Estas máquinas son generalmente sistemas pequeños y embebidos que carecen de soporte de MMU.

Las funciones posix_spawn() y posix_spawnp() proporcionan la funcionalidad de una combinación de fork(2) y exec(3), con algunos pasos opcionales de mantenimiento en el proceso hijo antes de la ejecución de exec(3). Estas funciones no están destinadas a reemplazar las llamadas al sistema fork(2) y execve(2). De hecho, proporcionan solo un subconjunto de la funcionalidad que se puede lograr utilizando las llamadas al sistema.

La única diferencia entre posix_spawn() y posix_spawnp() es la forma en que especifican el archivo a ejecutar por el proceso hijo. Con posix_spawn(), el archivo ejecutable se especifica como una ruta de archivo (que puede ser absoluta o relativa). Con posix_spawnp(), el archivo ejecutable se especifica como un nombre de archivo simple; el sistema busca este archivo en la lista de directorios especificada por PATH (de la misma manera que para execvp(3)). Para el resto de esta página, la discusión se formula en términos de posix_spawn(), con el entendimiento de que posix_spawnp() difiere solo en el punto descrito.

Los argumentos restantes para estas dos funciones son los siguientes:

pid
apunta a un búfer que se utiliza para devolver el ID del proceso del nuevo proceso hijo.
file_actions
apunta a un objeto de acciones de archivo de spawn que especifica acciones relacionadas con archivos que se realizarán en el hijo entre los pasos de fork(2) y exec(3). Este objeto se inicializa y se rellena antes de la llamada a posix_spawn() usando posix_spawn_file_actions_init(3) y las funciones posix_spawn_file_actions_*().
attrp
apunta a un objeto de atributos que especifica varios atributos del proceso hijo creado. Este objeto se inicializa y se rellena antes de la llamada a posix_spawn() usando posix_spawnattr_init(3) y las funciones posix_spawnattr_*().
argv
envp
especifican la lista de argumentos y el entorno para el programa que se ejecuta en el proceso hijo, como para execve(2).

A continuación, las funciones se describen en términos de un proceso de tres pasos: el paso fork(), el paso pre-exec() (ejecutado en el hijo) y el paso exec() (ejecutado en el hijo).

paso fork()

Desde glibc 2.24, la función posix_spawn() comienza llamando a clone(2) con las banderas CLONE_VM y CLONE_VFORK. Las implementaciones más antiguas usan fork(2), o posiblemente vfork(2) (ver abajo).

El PID del nuevo proceso hijo se coloca en *pid. La función posix_spawn() devuelve el control al proceso padre.

Posteriormente, el padre puede usar una de las llamadas al sistema descritas en wait(2) para verificar el estado del proceso hijo. Si el hijo falla en alguno de los pasos de mantenimiento descritos a continuación, o falla en ejecutar el archivo deseado, sale con un estado de 127.

Antes de glibc 2.24, el proceso hijo se crea usando vfork(2) en lugar de fork(2) cuando se cumple alguna de las siguientes condiciones:

•
el elemento spawn-flags del objeto de atributos apuntado por attrp contiene la bandera específica de GNU POSIX_SPAWN_USEVFORK; o
•
file_actions es NULL y el elemento spawn-flags del objeto de atributos apuntado por attrp no contiene POSIX_SPAWN_SETSIGMASK, POSIX_SPAWN_SETSIGDEF, POSIX_SPAWN_SETSCHEDPARAM, POSIX_SPAWN_SETSCHEDULER, POSIX_SPAWN_SETPGROUP, o POSIX_SPAWN_RESETIDS.

En otras palabras, se usa vfork(2) si el llamante lo solicita, o si no hay limpieza esperada en el hijo antes de que ejecute el archivo solicitado con exec(3).

paso pre-exec(): mantenimiento

Entre los pasos fork() y exec(), un proceso hijo puede necesitar realizar un conjunto de acciones de mantenimiento. Las funciones posix_spawn() y posix_spawnp() admiten un conjunto pequeño y bien definido de tareas del sistema que el proceso hijo puede realizar antes de ejecutar el archivo ejecutable. Estas operaciones son controladas por el objeto de atributos apuntado por attrp y el objeto de acciones de archivo apuntado por file_actions. En el hijo, el procesamiento se realiza en la siguiente secuencia:

(1)
Las acciones de atributos del proceso: máscara de señales, manejadores predeterminados de señales, algoritmo y parámetros de planificación, grupo de procesos y IDs de usuario y grupo efectivos se cambian según lo especificado por el objeto de atributos apuntado por attrp.
(2)
Las acciones de archivo, según se especifica en el argumento file_actions, se realizan en el orden en que se especificaron mediante llamadas a las funciones posix_spawn_file_actions_add*().
(3)
Se cierran los descriptores de archivo con la bandera FD_CLOEXEC establecida.

Todos los atributos del proceso en el hijo, aparte de aquellos afectados por los atributos especificados en el objeto apuntado por attrp y las acciones de archivo en el objeto apuntado por file_actions, se verán afectados como si el hijo se hubiera creado con fork(2) y hubiera ejecutado el programa con execve(2).

Las acciones de atributos del proceso se definen mediante el objeto de atributos apuntado por attrp. El atributo spawn-flags (establecido usando posix_spawnattr_setflags(3)) controla las acciones generales que ocurren, y otros atributos en el objeto especifican los valores que se usarán durante esas acciones.

Los efectos de las banderas que se pueden especificar en spawn-flags son los siguientes:

POSIX_SPAWN_SETSIGMASK
Establece la máscara de señales al conjunto de señales especificado en el atributo spawn-sigmask del objeto apuntado por attrp. Si la bandera POSIX_SPAWN_SETSIGMASK no está establecida, el hijo hereda la máscara de señales del padre.
POSIX_SPAWN_SETSIGDEF
Restablece la disposición de todas las señales en el conjunto especificado en el atributo spawn-sigdefault del objeto

Código fuente del programa

#include <err.h>
#include <errno.h>
#include <spawn.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <wait.h>
char **environ;
int
main(int argc, char *argv[])
{
    pid_t child_pid;
    int s, opt, status;
    sigset_t mask;
    posix_spawnattr_t attr;
    posix_spawnattr_t *attrp;
    posix_spawn_file_actions_t file_actions;
    posix_spawn_file_actions_t *file_actionsp;
    /* Analiza las opciones de la línea de comandos, que se pueden usar para especificar un
       objeto de atributos y un objeto de acciones de archivo para el hijo.  */
    attrp = NULL;
    file_actionsp = NULL;
    while ((opt = getopt(argc, argv, "sc")) != -1) {
        switch (opt) {
        case 'c':       /* -c: cerrar salida estándar en el hijo */
            /* Crea un objeto de acciones de archivo y agrega una acción de "cierre"
               a él.  */
            s = posix_spawn_file_actions_init(&file_actions);
            if (s != 0)
                errc(EXIT_FAILURE, s, "posix_spawn_file_actions_init");
            s = posix_spawn_file_actions_addclose(&file_actions,
                                                  STDOUT_FILENO);
            if (s != 0)
                errc(EXIT_FAILURE, s, "posix_spawn_file_actions_addclose");
            file_actionsp = &file_actions;
            break;
        case 's':       /* -s: bloquear todas las señales en el hijo */
            /* Crea un objeto de atributos y agrega una acción de "establecer máscara de señal"
               a él.  */
            s = posix_spawnattr_init(&attr);
            if (s != 0)
                errc(EXIT_FAILURE, s, "posix_spawnattr_init");
            s = posix_spawnattr_setflags(&attr, POSIX_SPAWN_SETSIGMASK);
            if (s != 0)
                errc(EXIT_FAILURE, s, "posix_spawnattr_setflags");
            sigfillset(&mask);
            s = posix_spawnattr_setsigmask(&attr, &mask);
            if (s != 0)
                errc(EXIT_FAILURE, s, "posix_spawnattr_setsigmask");
            attrp = &attr;
            break;
        }
    }
    if (argv[optind] == NULL) {
        fprintf(stderr, "Uso: %s [-cs] ejecutable [argumentos]\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    /* Crea el hijo. El nombre del programa a ejecutar y los argumentos
       de la línea de comandos se toman de los argumentos de la línea de comandos
       de este programa. El entorno del programa ejecutado en el hijo
       se hace igual que el entorno del padre.  */
    s = posix_spawnp(&child_pid, argv[optind], file_actionsp, attrp,
                     &argv[optind], environ);
    if (s != 0)
        errc(EXIT_FAILURE, s, "posix_spawn");
    /* Destruye cualquier objeto que hayamos creado anteriormente.  */
    if (attrp != NULL) {
        s = posix_spawnattr_destroy(attrp);
        if (s != 0)
            errc(EXIT_FAILURE, s, "posix_spawnattr_destroy");
    }
    if (file_actionsp != NULL) {
        s = posix_spawn_file_actions_destroy(file_actionsp);
        if (s != 0)
            errc(EXIT_FAILURE, s, "posix_spawn_file_actions_destroy");
    }
    printf("PID del hijo: %jd\n", (intmax_t) child_pid);
    /* Supervisa el estado del hijo hasta que termine.  */
    do {
        s = waitpid(child_pid, &status, WUNTRACED | WCONTINUED);
        if (s == -1)
            err(EXIT_FAILURE, "waitpid");
        printf("Estado del hijo: ");
        if (WIFEXITED(status)) {
            printf("terminado, estado=%d\n", WEXITSTATUS(status));
        } else if (WIFSIGNALED(status)) {
            printf("eliminado por señal %d\n", WTERMSIG(status));
        } else if (WIFSTOPPED(status)) {
            printf("detenido por señal %d\n", WSTOPSIG(status));
        } else if (WIFCONTINUED(status)) {
            printf("continuado\n");
        }
    } while (!WIFEXITED(status) && !WIFSIGNALED(status));
    exit(EXIT_SUCCESS);
}
