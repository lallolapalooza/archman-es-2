NOMBRE

podman-events - Monitorizar eventos de Podman

SINOPSIS

podman events [opciones]

podman system events [opciones]

DESCRIPCIÓN

Monitoriza e imprime eventos que ocurren en Podman. Cada evento incluye una marca de tiempo, un tipo, un estado, nombre (si aplica) e imagen (si aplica). El mecanismo de registro predeterminado es journald. Esto se puede cambiar en containers.conf modificando el valor de events_logger a file. Solo se aceptan file y journald. También hay disponible un registrador none, pero este mecanismo de registro deshabilita completamente los eventos; podman events no informa nada.

Por defecto, se utiliza el modo de transmisión, imprimiendo nuevos eventos a medida que ocurren. Los eventos anteriores se pueden listar usando --since y --until.

El tipo de evento container informa los siguientes estados:
* attach
* checkpoint
* cleanup
* commit
* connect
* create
* died
* disconnect
* exec
* exec_died
* exited
* export
* import
* init
* kill
* mount
* pause
* prune
* remove
* rename
* restart
* restore
* start
* stop
* sync
* unmount
* unpause
* update

El tipo de evento pod informa los siguientes estados:
* create
* kill
* pause
* remove
* start
* stop
* unpause

El tipo de evento image informa los siguientes estados:
* loadFromArchive,
* mount
* pull
* pull-error
* push
* remove
* save
* tag
* unmount
* untag

El tipo system informa los siguientes estados:
* refresh
* renumber

El tipo volume informa los siguientes estados:
* create
* prune
* remove

El tipo secret informa los siguientes estados:
* create
* remove

Eventos de Creación Detallados

Establecer events_container_create_inspect_data=true en containers.conf(5) instruye a Podman a crear eventos de creación de contenedores más detallados que incluyen una carga útil JSON con información detallada sobre los contenedores. La carga útil JSON es idéntica a la de podman-container-inspect(1). El campo asociado en journald se llama PODMAN_CONTAINER_INSPECT_DATA.

OPCIONES

--filter, -f=filtro

Filtra los eventos que se muestran. Deben estar en el formato de "filtro=valor". Los siguientes filtros son compatibles:

Filtro Descripción
container [Nombre o ID] Nombre o ID del contenedor
event estado_evento (descrito arriba)
image [Nombre o ID] Nombre o ID de la imagen
label [clave] o [clave=valor] etiqueta
pod [Nombre o ID] Nombre o ID del pod
volume [Nombre o ID] Nombre o ID del volumen
type tipo_evento (descrito arriba)

En el caso de que se utilice un ID, el ID puede estar en su forma completa o acortada. El evento "die" se mapea a "died" para compatibilidad con Docker.

--format

Formatea la salida a Líneas JSON o utilizando la plantilla Go dada.

Marcador de posición Descripción
.Attributes ... created_at, _by, labels, y más (mapa[])
.ContainerExitCode Código de salida (int)
.ContainerInspectData Carga útil de la inspección del contenedor
.Error Mensaje de error en caso de que el estado del evento sea un error (por ejemplo, pull-error)
.HealthStatus Estado de salud (cadena)
.ID ID del contenedor (SHA completo de 64 bits)
.Image Nombre de la imagen que se está ejecutando (cadena)
.Name Nombre del contenedor (cadena)
.Network Nombre de la red que se está utilizando (cadena)
.PodID ID del pod asociado con el contenedor, si existe
.Status Estado del evento (por ejemplo, create, start, died, ...)
.Time Marca de tiempo del evento (cadena)
.TimeNano Marca de tiempo del evento con precisión de nanosegundos (int64)
.Type Tipo de evento (por ejemplo, image, container, pod, ...)

--help

Imprime el enunciado de uso.

--no-trunc

No truncar la salida (predeterminado true).

--since=timestamp

Mostrar todos los eventos creados desde la marca de tiempo dada

--stream

Transmitir eventos y no salir después de leer el último evento conocido (predeterminado true).

--until=timestamp

Mostrar todos los eventos creados hasta la marca de tiempo dada

Los valores since y until pueden ser marcas de tiempo RFC3339Nano o una cadena de duración Go como 10m, 5h. Si no se proporcionan valores since o until, solo se muestran los eventos nuevos.

IDENTIFICADORES DE JOURNALD

El backend de eventos journald de Podman utiliza los siguientes identificadores de journald. Puedes usar los identificadores para filtrar eventos de Podman directamente con journalctl.

Identificador Descripción
SYSLOG_IDENTIFIER Siempre establecido en "podman"
PODMAN_EVENT El estado del evento como se describe arriba
PODMAN_TYPE El tipo de evento como se describe arriba
PODMAN_TIME La marca de tiempo cuando se escribió el evento
PODMAN_NAME Nombre del objeto del evento (por ejemplo, contenedor, imagen)
PODMAN_ID ID del objeto del evento (por ejemplo, contenedor, imagen)
PODMAN_EXIT_CODE Código de salida del contenedor
PODMAN_POD_ID ID del pod del contenedor
PODMAN_LABELS Etiquetas del contenedor
PODMAN_HEALTH_STATUS Estado de salud del contenedor
PODMAN_CONTAINER_INSPECT_DATA La carga útil JSON de podman-inspect como se describe arriba
PODMAN_NETWORK_NAME El nombre de la red

NAME

podman-events - display events emitted by the containers-daemon

SYNOPSIS

podman system events [options]

DESCRIPTION

The podman system events command displays events emitted by the containers-daemon. The events can be filtered by containers, pods, volumes, networks, and more. The output can be streamed in real time.

OPTIONS

       --all, -a
              Show all events, not just recent ones.

       --cert-dir directory
              Use a directory of TLS certificates for the remote daemon.

       --containers-only
              Show only container events.

       --daemon-socket path
              Use alternate path for Podman socket.

       --filter, -f
              Filter output based on conditions provided. Supported filters:
              * event (container, image, volume, network, pod, etc.)
              * id
              * label
              * name
              * type (container, image, volume, network, pod, etc.)

       --format Go-template
              Format output using Go-template. Defaults to:
              "{{.ID}}\t{{.Image}}\t{{.Name}}\t{{.Type}}\t{{.Status}}\t{{.Time}}\n"

       --help, -h
              Usage information.

       --latest, -l
              Show only the latest events.

       --no-stream
              Do not block and wait for events.

       --pod-running-container-only
              Show only events for containers that are running in pods.

       --quiet, -q
              Only display event IDs.

       --since timestamp
              Show only events created since a given timestamp. The timestamp format
              is RFC3339Nano. e.g. 2006-01-02T15:04:05.999999999Z.

       --stream
              Stream events in real time. This is the default behavior.

       --until timestamp
              Show only events created before a given timestamp. The timestamp format
              is RFC3339Nano. e.g. 2006-01-02T15:04:05.999999999Z.

JOURNALD IDENTIFIERS

When configured to use journald for logging, the podman command records events with the following identifiers:

  • container
  • image
  • volume
  • network
  • pod

For example, to view all container create events logged to journald:

$ journalctl -f /usr/bin/podman --since "1 hour ago" | grep -oP "container create \K\w+"
