poll(2) Manual de Llamadas al Sistema poll(2)

NOMBRE

poll, ppoll - esperar a que ocurra algún evento en un descriptor de archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <poll.h>
int poll(struct pollfd *fds, nfds_t nfds, int timeout);
#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <poll.h>
int ppoll(struct pollfd *fds, nfds_t nfds,
          const struct timespec *_Nullable tmo_p,
          const sigset_t *_Nullable sigmask);

DESCRIPCIÓN

poll() realiza una tarea similar a select(2): espera a que un conjunto de descriptores de archivo esté listo para realizar E/S. La API específica de Linux epoll(7) realiza una tarea similar, pero ofrece características que van más allá de las encontradas en poll().

El conjunto de descriptores de archivo a monitorear se especifica en el argumento fds, que es un array de estructuras de la siguiente forma:


struct pollfd {
    int   fd;         /* descriptor de archivo */
    short events;     /* eventos solicitados */
    short revents;    /* eventos devueltos */
};

El llamador debe especificar el número de elementos en el array fds en nfds.

El campo fd contiene un descriptor de archivo para un archivo abierto. Si este campo es negativo, entonces el campo events correspondiente se ignora y el campo revents devuelve cero. (Esto proporciona una forma fácil de ignorar un descriptor de archivo para una sola llamada a poll(): simplemente establezca el campo fd en su complemento a nivel de bits.)

El campo events es un parámetro de entrada, una máscara de bits que especifica los eventos que interesan a la aplicación para el descriptor de archivo fd. Este campo puede especificarse como cero, en cuyo caso los únicos eventos que pueden devolverse en revents son POLLHUP, POLLERR y POLLNVAL (ver más abajo).

El campo revents es un parámetro de salida, completado por el kernel con los eventos que ocurrieron realmente. Los bits devueltos en revents pueden incluir cualquiera de los especificados en events, o uno de los valores POLLERR, POLLHUP o POLLNVAL. (Estos tres bits no tienen significado en el campo events, y se establecerán en el campo revents siempre que la condición correspondiente sea verdadera.)

Si ninguno de los eventos solicitados (y ningún error) ha ocurrido para ninguno de los descriptores de archivo, entonces poll() se bloquea hasta que ocurra uno de los eventos.

Estar "listo" significa que la operación solicitada no se bloqueará; por lo tanto, hacer poll() a archivos regulares, dispositivos de bloque y otros archivos sin un semántico de sondeo razonable *siempre* devuelve inmediatamente como listos para leer y escribir.

Tenga en cuenta que el intervalo de timeout se redondeará hacia arriba a la granularidad del reloj del sistema, y los retrasos de planificación del kernel significan que el intervalo de bloqueo puede excederse en una pequeña cantidad. Especificar un valor negativo en timeout significa un tiempo de espera infinito. Especificar un timeout de cero hace que poll() devuelva inmediatamente, incluso si ningún descriptor de archivo está listo.

Los bits que pueden establecerse/devolverse en events y revents se definen en <poll.h>:

POLLIN
Hay datos para leer.
POLLPRI
Hay alguna condición excepcional en el descriptor de archivo. Las posibilidades incluyen:
•
Hay datos fuera de banda en un socket TCP (ver tcp(7)).
•
Un maestro de pseudoterminal en modo paquete ha visto un cambio de estado en el esclavo (ver ioctl_tty(2)).
•
Un archivo cgroup.events ha sido modificado (ver cgroups(7)).
POLLOUT
La escritura ahora es posible, aunque una escritura mayor que el espacio disponible en un socket o tubería aún se bloqueará (a menos que O_NONBLOCK esté configurado).
POLLRDHUP (desde Linux 2.6.17)
El par del socket de flujo cerró la conexión, o cerró la mitad de escritura de la conexión. El macro de prueba de características _GNU_SOURCE debe definirse (antes de incluir cualquier archivo de cabecera) para obtener esta definición.
POLLERR
Condición de error (solo devuelto en revents; ignorado en events). Este bit también se establece para un descriptor de archivo que se refiere al extremo de escritura de una tubería cuando el extremo de lectura se ha cerrado.
POLLHUP
Cuelgue (hang up) (solo devuelto en revents; ignorado en events). Tenga en cuenta que al leer de un canal como una tubería o un socket de flujo, este evento simplemente indica que el par cerró su extremo del canal. Las lecturas posteriores del canal devolverán 0 (fin de archivo) solo después de que se hayan consumido todos los datos pendientes en el canal.
POLLNVAL
Solicitud inválida: fd no abierto (solo devuelto en revents; ignorado en events).

Al compilar con _XOPEN_SOURCE definido, también se tiene lo siguiente, que no transmiten más información que los bits enumerados anteriormente:

POLLRDNORM
Equivalente a POLLIN.
POLLRDBAND
Se pueden leer datos de banda de prioridad (generalmente no utilizados en Linux).
POLLWRNORM
Equivalente a POLLOUT.
POLLWRBAND
Se pueden escribir datos de banda de prioridad.

Linux también conoce, pero no utiliza, POLLMSG.

ppoll()

La relación entre poll() y ppoll() es análoga a la relación entre select(2) y pselect(2): al igual que pselect(2), ppoll() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo esté listo o hasta que se capture una señal.

Aparte de la diferencia en la precisión del argumento timeout, la siguiente llamada a ppoll():


ready = ppoll(&fds, nfds, tmo_p, &sigmask);

es casi equivalente a ejecutar *atmicamente* las siguientes llamadas:


sigset_t origmask;
int timeout;
timeout = (tmo_p == NULL) ? -1 :
          (tmo_p->tv_sec * 1000 + tmo_p->tv_nsec / 1000000);
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = poll(&fds, nfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

El segmento de código anterior se describe como *casi* equivalente porque, mientras que un valor negativo de timeout para poll() se interpreta como un tiempo de espera infinito, un valor negativo expresado en *tmo_p da como resultado un error de ppoll().

Ver la descripción de pselect(2) para una explicación de por qué ppoll() es necesario.

Si el argumento sigmask se especifica como NULL, entonces no se realiza ninguna manipulación de la máscara de señales (y, por lo tanto, ppoll() difiere de poll() solo en la precisión del argumento timeout).

El argumento tmo_p especifica un límite superior en la cantidad de tiempo que ppoll() se bloqueará. Este argumento es un puntero a una estructura timespec(3).

Si tmo_p se especifica como NULL, entonces ppoll() puede bloquearse indefinidamente.

VALOR DE RETORNO

En caso de éxito, poll() devuelve un valor no negativo que es el número de elementos en pollfds cuyos campos revents han sido establecidos a un valor distinto de cero (indicando un evento o un error). Un valor de retorno de cero indica que la llamada al sistema superó el tiempo de espera antes de que algún descriptor de archivo estuviera listo.

En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EFAULT
fds apunta fuera del espacio de direcciones accesible del proceso. El array proporcionado como argumento no estaba contenido en el espacio de direcciones del programa que realiza la llamada.
EINTR
Ocurrió una señal antes de que se produjera algún evento solicitado; consulte signal(7).
EINVAL
El valor nfds excede el valor RLIMIT_NOFILE.
EINVAL
(ppoll()) El valor de tiempo de espera expresado en *tmo_p es inválido (negativo).
ENOMEM
No se pudo asignar memoria para las estructuras de datos del kernel.

VERSIONES

En otros sistemas UNIX, poll() puede fallar con el error EAGAIN si el sistema no puede asignar recursos internos del kernel, en lugar de ENOMEM como lo hace Linux. POSIX permite este comportamiento. Los programas portátiles pueden desear verificar EAGAIN y volver a intentarlo, al igual que con EINTR.

Algunas implementaciones definen la constante no estándar INFTIM con el valor -1 para usarla como timeout para poll(). Esta constante no se proporciona en glibc.

Diferencias biblioteca C/kernel

La llamada al sistema ppoll() de Linux modifica su argumento tmo_p. Sin embargo, la función envoltorio de glibc oculta este comportamiento utilizando una variable local para el argumento de tiempo de espera que se pasa a la llamada al sistema. Por lo tanto, la función ppoll() de glibc no modifica su argumento tmo_p.

La llamada al sistema ppoll() en bruto tiene un quinto argumento, size_t sigsetsize, que especifica el tamaño en bytes del argumento sigmask. La función envoltorio ppoll() de glibc especifica este argumento como un valor fijo (igual a sizeof(kernel_sigset_t)). Consulte sigprocmask(2) para una discusión sobre las diferencias entre la noción de sigset del kernel y la de libc.

ESTANDARES

NOTAS

La operación de poll() y ppoll() no se ve afectada por la bandera O_NONBLOCK.

Para una discusión sobre lo que puede suceder si un descriptor de archivo que está siendo monitoreado por poll() se cierra en otro hilo, consulte select(2).

ERRORES CONOCIDOS

Consulte la discusión sobre notificaciones de preparación espurias bajo la sección ERRORES CONOCIDOS de select(2).

EJEMPLOS

El programa a continuación abre cada uno de los archivos cuyos nombres se encuentran en los argumentos de la línea de comandos y monitorea los descriptores de archivo resultantes para ver si están listos para leer (POLLIN). El programa se repite, usando poll() repetidamente para monitorear los descriptores de archivo, imprimiendo el número de descriptores de archivo listos al regresar. Para cada descriptor de archivo listo, el programa:

•
muestra el campo revents devuelto en un formato legible por humanos;
•
si el descriptor de archivo es legible, lee algunos datos de él y muestra esos datos en la salida estándar; y
•
si el descriptor de archivo no era legible, pero ocurrió algún otro evento (presumiblemente POLLHUP), cierra el descriptor de archivo.

Supongamos que ejecutamos el programa en una terminal, pidiéndole que abra una FIFO:


$ mkfifo myfifo;
$ ./poll_input myfifo;

En una segunda ventana de terminal, abrimos la FIFO para escribir, escribimos algunos datos en ella y cerramos la FIFO:


$ echo aaaaabbbbbccccc > myfifo;

En la terminal donde estamos ejecutando el programa, veríamos entonces:


Opened "myfifo" on fd 3
About to poll()
Ready: 1
  fd=3; events: POLLIN POLLHUP
    read 10 bytes: aaaaabbbbb
About to poll()
Ready: 1
  fd=3; events: POLLIN POLLHUP
    read 6 bytes: ccccc
About to poll()
Ready: 1
  fd=3; events: POLLHUP
    closing fd 3
All file descriptors closed.  Bye.

En la salida anterior, vemos que poll() regresó tres veces:

•
En el primer regreso, los bits devueltos en el campo revents fueron POLLIN, indicando que el descriptor de archivo es legible, y POLLHUP, indicando que el otro extremo de la FIFO ha sido cerrado. El programa consumió entonces parte de la entrada disponible.
•
El segundo regreso de poll() también indicó POLLIN y POLLHUP; el programa consumió entonces el resto de la entrada disponible.
•
En el regreso final, poll() solo indicó POLLHUP en la FIFO, momento en el cual se cerró el descriptor de archivo y el programa terminó.

Fuente del programa

/* poll_input.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <fcntl.h>
#include <poll.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int            ready;
    char           buf[10];
    nfds_t         num_open_fds, nfds;
    ssize_t        s;
    struct pollfd  *pfds;
    if (argc < 2) {
       fprintf(stderr, "Usage: %s file...\n", argv[0]);
       exit(EXIT_FAILURE);
    }
    num_open_fds = nfds = argc - 1;
    pfds = calloc(nfds, sizeof(struct pollfd));
    if (pfds == NULL)
        err(EXIT_FAILURE, "malloc");
    /* Open each file on command line, and add it to 'pfds' array.  */
    for (nfds_t j = 0; j < nfds; j++) {
        pfds[j].fd = open(argv[j + 1], O_RDONLY);
        if (pfds[j].fd == -1)
            err(EXIT_FAILURE, "open");
        printf("Opened \"%s\" on fd %d\n", argv[j + 1], pfds[j].fd);
        pfds[j].events = POLLIN;
    }
    /* Keep calling poll() as long as at least one file descriptor is
       open.  */
    while (num_open_fds > 0) {
        printf("About to poll()\n");
        ready = poll(pfds, nfds, -1);
        if (ready == -1)
            err(EXIT_FAILURE, "poll");
        printf("Ready: %d\n", ready);
        /* Deal with array returned by poll().  */
        for (nfds_t j = 0; j < nfds; j++) {
            if (pfds[j].revents != 0) {
                printf("  fd=%d; events: %s%s%s\n", pfds[j].fd,
                       (pfds[j].revents & POLLIN)  ? "POLLIN "  : "",
                       (pfds[j].revents & POLLHUP) ? "POLLHUP " : "",
                       (pfds[j].revents & POLLERR) ? "POLLERR " : "");
                if (pfds[j].revents & POLLIN) {
                    s = read(pfds[j].fd, buf, sizeof(buf));
                    if (s == -1)
                        err(EXIT_FAILURE, "read");
                    printf("    read %zd bytes: %.*s\n",
                           s, (int) s, buf);
                } else {                /* POLLERR | POLLHUP */
                    printf("    closing fd %d\n", pfds[j].fd);
                    if (close(pfds[j].fd) == -1)
                        err(EXIT_FAILURE, "close");
                    num_open_fds--;
                }
            }
        }
    }
    printf("All file descriptors closed.  Bye.\n");
    exit(EXIT_SUCCESS);
}

poll(2)

poll - esperar a un evento en un descriptor de archivo

SINOPSIS

#include <poll.h>

int poll(struct pollfd fds[], nfds_t nfds, int timeout);

DESCRIPCIÓN

La función poll() examina un conjunto de descriptores de archivo para ver si alguna de ellas está lista para la E/S, o si alguna ha ocurrido una condición de error. El conjunto de descriptores de archivo a examinar se especifica en el array fds, que es un array de estructuras pollfd.

typedef struct pollfd {
    int   fd;         /* descriptor de archivo */
    short events;     /* eventos de interés */
    short revents;    /* eventos ocurridos */
} pollfd_t;

El argumento nfds especifica el número de elementos en el array fds.

El argumento timeout especifica el tiempo en milisegundos que se esperará a que ocurra un evento. Si timeout es positivo, representa el número máximo de milisegundos que poll() esperará. Si timeout es cero, poll() volverá inmediatamente. Si timeout es -1, poll() esperará indefinidamente.

El campo events de cada estructura pollfd especifica los eventos que el usuario desea detectar en el descriptor de archivo correspondiente. Los eventos posibles son:

  • POLLIN: Hay datos para leer.
  • POLLPRI: Hay datos urgentes para leer.
  • POLLOUT: Se puede escribir datos.
  • POLLERR: Ha ocurrido un error en el descriptor de archivo.
  • POLLHUP: Se ha colgado el descriptor de archivo.
  • POLLNVAL: El descriptor de archivo es inválido.

Al regresar, el campo revents de cada estructura pollfd contendrá los eventos que realmente ocurrieron en el descriptor de archivo correspondiente.

VALOR DE RETORNO

Al éxito, poll() devuelve el número de estructuras pollfd en las que se ha detectado un evento (es decir, donde revents no es cero). Si se alcanza el tiempo de espera sin que ocurra ningún evento, poll() devuelve 0.

ERRORES

Los siguientes valores pueden ser establecidos en errno:

  • EBADF: Un descriptor de archivo en fds no es válido.
  • EINTR: Se recibió una señal mientras se esperaba a que ocurriera un evento.
  • EINVAL: El argumento nfds es negativo o mayor que FD_SETSIZE.
  • ENOMEM: No hay memoria disponible.

VERSIONES

La función poll() está disponible en Linux desde la versión 2.1.54. En sistemas anteriores, se utilizaba la función select().

ESTÁNDARES

POSIX.1-2001, POSIX.1-2008.

HISTORIAL

Linux 2.1.54.

NOTAS

La función poll() es una alternativa más eficiente a la función select() para un gran número de descriptores de archivo.

BUGS

Ninguno conocido.

EJEMPLOS

#include <stdio.h>
#include <poll.h>
#include <unistd.h>

int main() {
    struct pollfd fds[1];
    int ret;

    fds[0].fd = STDIN_FILENO;
    fds[0].events = POLLIN;

    ret = poll(fds, 1, -1); /* Espera indefinidamente */

    if (ret > 0) {
        if (fds[0].revents & POLLIN) {
            printf("Datos disponibles para leer en stdin.\n");
            /* Aquí puedes leer los datos */
        }
    } else if (ret == 0) {
        printf("Tiempo de espera agotado.\n");
    } else {
        perror("poll");
    }

    return 0;
}
