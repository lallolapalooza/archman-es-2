NOMBRE

podman-container-restore - Restaura uno o más contenedores desde un punto de control

SINOPSIS

podman container restore [opciones] nombre [...]

DESCRIPCIÓN

podman container restore restaura un contenedor desde un punto de control de contenedor o una imagen de punto de control. Los IDs de contenedor, IDs de imagen o nombres se utilizan como entrada.

OPCIONES

--all, -a

Restaura todos los contenedores en punto de control.
El valor predeterminado es false.
IMPORTANTE: Esta OPCIÓN no necesita un nombre o ID de contenedor como argumento de entrada.

--file-locks

Restaura un contenedor con bloqueos de archivo. Esta opción es necesaria para restaurar bloqueos de archivo desde una imagen de punto de control. Si la imagen de punto de control no contiene bloqueos de archivo, esta opción se ignora. Por defecto, no se restauran los bloqueos de archivo.
El valor predeterminado es false.

--ignore-rootfs

Si un contenedor se restaura desde un archivo tar.gz de punto de control, es posible que también contenga todos los cambios del sistema de archivos raíz. Con --ignore-rootfs es posible deshabilitar explícitamente la aplicación de estos cambios del sistema de archivos raíz al contenedor restaurado.
El valor predeterminado es false.
IMPORTANTE: Esta OPCIÓN solo está disponible en combinación con --import, -i.

--ignore-static-ip

Si el contenedor se inició con --ip, el contenedor restaurado también intenta usar esa dirección IP y la restauración falla si esa dirección IP ya está en uso. Esto puede ocurrir si un contenedor se restaura varias veces desde un punto de control exportado con --name, -n.

El uso de --ignore-static-ip indica a Podman que ignore la dirección IP si se configuró con --ip durante la creación del contenedor.

El valor predeterminado es false.

--ignore-static-mac

Si el contenedor se inició con --mac-address, el contenedor restaurado también intenta usar esa dirección MAC y la restauración falla si esa dirección MAC ya está en uso. Esto puede ocurrir si un contenedor se restaura varias veces desde un punto de control exportado con --name, -n.

El uso de --ignore-static-mac indica a Podman que ignore la dirección MAC si se configuró con --mac-address durante la creación del contenedor.

El valor predeterminado es false.

--ignore-volumes

Esta opción debe usarse en combinación con la opción --import, -i. Al restaurar contenedores desde un archivo tar.gz de punto de control con esta opción, el contenido de los volúmenes asociados no se restaura.
El valor predeterminado es false.

--import, -i=archivo

Importa un archivo tar.gz de punto de control, que fue exportado por Podman. Esto se puede usar para importar un contenedor en punto de control desde otro host.
IMPORTANTE: Esta OPCIÓN no necesita un nombre o ID de contenedor como argumento de entrada.

Durante la importación de un archivo de punto de control, Podman selecciona el mismo tiempo de ejecución de contenedor que se utilizó durante el punto de control. Esto es especialmente importante si se especificó un tiempo de ejecución de contenedor específico (no predeterminado) durante la creación del contenedor. Podman también aborta la restauración si el tiempo de ejecución del contenedor especificado durante la restauración no coincide con el tiempo de ejecución del contenedor utilizado para la creación del contenedor.

--import-previous=archivo

Importa un archivo tar.gz pre-punto de control que fue exportado por Podman. Esta opción debe usarse con -i o --import. Solo funciona en runc 1.0-rc3 o superior. IMPORTANTE: Esta OPCIÓN no es compatible con el cliente remoto, incluidas las máquinas Mac y Windows (excepto WSL2).

--keep, -k

Conserva todos los archivos temporales de registro y estadísticas creados por CRIU durante la creación del punto de control, así como durante la restauración. Estos archivos no se eliminan si la restauración falla, para depuración adicional. Si la restauración tiene éxito, estos archivos teóricamente no son necesarios, pero si se necesitan, Podman puede conservar los archivos para análisis adicionales. Esto incluye el directorio del punto de control con todos los archivos creados durante la creación del punto de control. El tamaño requerido por el directorio del punto de control es aproximadamente la misma cantidad de memoria requerida por los procesos en el contenedor en punto de control.
Sin la opción --keep, -k, el punto de control se consume y no se puede volver a utilizar.
El valor predeterminado es false.

--latest, -l

En lugar de proporcionar el ID de contenedor o el nombre, usa el último contenedor creado. El valor predeterminado es false. IMPORTANTE: Esta OPCIÓN no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excepto WSL2). Esta OPCIÓN no necesita un nombre o ID de contenedor como argumento de entrada.

--name, -n=nombre

Si un contenedor se restaura desde un archivo tar.gz de punto de control, es posible renombrarlo con --name, -n. De esta manera, es posible restaurar un contenedor desde un punto de control varias veces con nombres diferentes.

Si se utiliza la opción --name, -n, Podman no intenta asignar la misma dirección IP al contenedor que estaba usando antes del punto de control, ya que cada dirección IP solo puede usarse una vez, y el contenedor restaurado tiene una dirección IP diferente. Esto también significa que --name, -n no se puede usar en combinación con --tcp-established.
IMPORTANTE: Esta OPCIÓN solo está disponible para una imagen de punto de control o en combinación con --import, -i.

--pod=nombre

Restaura un contenedor en el pod nombre. El pod de destino para esta restauración debe compartir los mismos espacios de nombres que el pod del cual se hizo el punto de control de este contenedor (ver **podman pod create --share).
IMPORTANTE: Esta OPCIÓN solo está disponible para una imagen de punto de control o en combinación con --import, -i.

Esta opción requiere al menos CRIU 3.16.

--print-stats

Imprime estadísticas sobre la restauración de los contenedores. La salida se presenta en una matriz JSON y contiene información sobre cuánto tiempo requirieron las diferentes operaciones de restauración. Muchas de las estadísticas de restauración son creadas por CRIU y simplemente se pasan a Podman. La siguiente información se proporciona en la matriz JSON:

  • podman_restore_duration: Tiempo total (en microsegundos) necesario para restaurar todos los puntos de control.
  • runtime_restore_duration: Tiempo (en microsegundos) que el tiempo de ejecución del contenedor necesitó para restaurar el punto de control.
  • forking_time: Tiempo (en microsegundos) que CRIU necesitó para crear (bifurcar) todos los procesos en el contenedor restaurado (medido por CRIU).
  • restore_time: Tiempo (en microsegundos) que CRIU necesitó para restaurar todos los procesos en el contenedor (medido por CRIU).
  • pages_restored: Número de páginas de memoria restauradas (medido por CRIU).

El valor predeterminado es false.

--publish, -p=puerto

Reemplaza los puertos que el contenedor publica, según lo configurado durante el inicio inicial del contenedor, con un nuevo conjunto de reglas de reenvío de puertos.

Para más detalles, consulta podman run --publish.

--tcp-close

Restaura un contenedor y cierra todas las conexiones TCP. Esta opción es útil cuando las conexiones TCP no son necesarias después de la restauración o cuando la aplicación las restablecerá. Si la imagen de punto de control se creó con --tcp-close, esta opción debe usarse durante la restauración.
El valor predeterminado es false.

--tcp-established

Restaura un contenedor con conexiones TCP establecidas. Si la imagen de punto de control contiene conexiones TCP establecidas, esta opción es necesaria durante la restauración. Si la imagen de punto de control no contiene conexiones TCP establecidas, esta opción se ignora. Por defecto, no se restauran contenedores con conexiones TCP

NAME

podman-container-restore

restore containers from a checkpoint

SYNOPSIS

podman container restore [OPTIONS] [CONTAINER]

DESCRIPTION

Restores a container from a checkpoint. The container can be restored from a file created by podman-container-checkpoint(1) or from a checkpoint image created with the podman-container-checkpoint(1) command.

You can restore a container to its previous state by using the --import-previous option.

OPTIONS

--container-external-ip
Set the container's external IP address. This option is valid only when restoring a container from a checkpoint file and not from a checkpoint image. If the container was created with an external IP address, this option can be used to set it to a different value. The IP address must be a valid IPv4 or IPv6 address.
--export
Export the checkpoint to a file. The file can then be used to restore the container on another machine or in a different namespace. This option is only valid when restoring a container from a checkpoint file and not from a checkpoint image.
--file
Path to the checkpoint file. If this option is not specified, the container will be restored from a checkpoint image. The checkpoint file must be created by podman-container-checkpoint(1).
--import
Path to the checkpoint file. This option can be used to restore a container from a checkpoint file that was created by podman-container-checkpoint(1). This option is mutually exclusive with the --name option.
--import-previous
Path to the pre-checkpoint file. This option can be used to restore a container from a checkpoint file that was created by podman-container-checkpoint(1). This option is mutually exclusive with the --name option.
--latest
Restore container from the latest checkpoint. This option is only valid when restoring from a checkpoint image.
--name
Assign a name to the restored container. If this option is not specified, the container will be restored with the original name. This option is mutually exclusive with the --import and --import-previous options.
--publish
Publish container's ports. The format is [HOST_IP:]HOST_PORT[:CONTAINER_PORT][/PROTOCOL]. This option can be specified multiple times to publish multiple ports. This option is valid only when restoring a container from a checkpoint file and not from a checkpoint image.
--tcp-established
Restore existing TCP connections. The default is false.

EXAMPLES

Restore the container "mywebserver".

# podman container restore mywebserver

Import a checkpoint file and a pre-checkpoint file.

# podman container restore --import-previous pre-checkpoint.tar.gz --import checkpoint.tar.gz

Start the container "mywebserver". Make a checkpoint of the container and export it. Restore the container with other port ranges from the exported file.

$ podman run --rm -p 2345:80 -d webserver
# podman container checkpoint -l --export=dump.tar
# podman container restore -p 5432:8080 --import=dump.tar

Start a container with the name "foobar-1". Create a checkpoint image "foobar-checkpoint". Restore the container from the checkpoint image with a different name.

# podman run --name foobar-1 -d webserver
# podman container checkpoint --create-image foobar-checkpoint foobar-1
# podman inspect foobar-checkpoint
# podman container restore --name foobar-2 foobar-checkpoint
# podman container restore --name foobar-3 foobar-checkpoint
