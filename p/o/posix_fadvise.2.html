posix_fadvise(2) Manual de Llamadas al Sistema posix_fadvise(2)

NOMBRE

posix_fadvise - predeclarar un patrón de acceso para datos de archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <fcntl.h>
int posix_fadvise(int fd, off_t offset, off_t size, int advice);
Requisitos de macros de prueba de características para glibc (ver feature_test_macros(7)):

posix_fadvise():

    _POSIX_C_SOURCE >= 200112L

DESCRIPCIÓN

Los programas pueden usar posix_fadvise() para anunciar la intención de acceder a datos de archivo en un patrón específico en el futuro, permitiendo así al kernel realizar optimizaciones apropiadas.

El advice se aplica a una región (no necesariamente existente) que comienza en offset y se extiende por size bytes (o hasta el final del archivo si size es 0) dentro del archivo al que se refiere fd. El advice no es vinculante; simplemente constituye una expectativa por parte de la aplicación.

Los valores permitidos para advice incluyen:

POSIX_FADV_NORMAL
Indica que la aplicación no tiene consejos que dar sobre su patrón de acceso para los datos especificados. Si no se dan consejos para un archivo abierto, esta es la suposición por defecto.
POSIX_FADV_SEQUENTIAL
La aplicación espera acceder a los datos especificados secuencialmente (con desplazamientos más bajos leídos antes que los más altos).
POSIX_FADV_RANDOM
Los datos especificados se accederán en orden aleatorio.
POSIX_FADV_NOREUSE
Los datos especificados se accederán solo una vez.
Antes de Linux 2.6.18, POSIX_FADV_NOREUSE tenía la misma semántica que POSIX_FADV_WILLNEED. Esto probablemente fue un error; desde Linux 2.6.18 hasta Linux 6.2, este flag no hacía nada. Desde Linux 6.3, POSIX_FADV_NOREUSE señala que el algoritmo de reemplazo de páginas del kernel puede ignorar el acceso a la caché de páginas marcada con este flag. Esto es útil, por ejemplo, mientras se transmiten archivos grandes.
POSIX_FADV_WILLNEED
Los datos especificados se accederán en un futuro cercano.
POSIX_FADV_WILLNEED inicia una lectura no bloqueante de la región especificada en la caché de páginas. La cantidad de datos leídos puede ser reducida por el kernel dependiendo de la carga de memoria virtual. (Unos pocos megabytes generalmente se satisfarán completamente, y más raramente es útil).
POSIX_FADV_DONTNEED
Los datos especificados no se accederán en un futuro cercano.
POSIX_FADV_DONTNEED intenta liberar páginas cacheadas asociadas con la región especificada. Esto es útil, por ejemplo, mientras se transmiten archivos grandes. Un programa puede solicitar periódicamente al kernel que libere datos cacheados que ya se han utilizado, para que páginas cacheadas más útiles no se descarten en su lugar.
Las solicitudes para descartar páginas parciales se ignoran. Es preferible conservar los datos necesarios que descartar los datos innecesarios. Si la aplicación requiere que los datos se consideren para su descarte, entonces offset y size deben estar alineados a página.
La implementación *puede* intentar escribir las páginas sucias en la región especificada, pero esto no está garantizado. Las páginas sucias no escritas no se liberarán. Si la aplicación desea asegurarse de que las páginas sucias se liberarán, primero debería llamar a fsync(2) o fdatasync(2).

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve un número de error.

ERRORES

EBADF
El argumento fd no era un descriptor de archivo válido.
EINVAL
Se especificó un valor inválido para advice.
ESPIPE
El descriptor de archivo especificado se refiere a una tubería o FIFO. (ESPIPE es el error especificado por POSIX, pero antes de Linux 2.6.16, Linux devolvía EINVAL en este caso.)

VERSIÓNES

En Linux, POSIX_FADV_NORMAL establece la ventana de relectura al tamaño por defecto para el dispositivo subyacente; POSIX_FADV_SEQUENTIAL duplica este tamaño, y POSIX_FADV_RANDOM deshabilita completamente la relectura del archivo. POSIX_FADV_NOREUSE no modifica el tamaño de la ventana de relectura. Estos cambios afectan a todo el archivo, no solo a la región especificada (pero otros manejadores de archivos abiertos al mismo archivo no se ven afectados).

Diferencias de biblioteca C/kernel

El nombre de la función envoltorio en la biblioteca C es posix_fadvise(). La llamada al sistema subyacente se llama fadvise64() (o, en algunas arquitecturas, fadvise64_64()); la diferencia entre ambas es que la primera llamada al sistema asume que el tipo del argumento size es size_t, mientras que la segunda espera loff_t allí.

Variantes específicas de arquitectura

Algunas arquitecturas requieren que los argumentos de 64 bits se alineen en un par adecuado de registros (ver syscall(2) para más detalles). En dichas arquitecturas, la firma de llamada de posix_fadvise() mostrada en el SINOPSIS forzaría que se desperdiciara un registro como relleno entre los argumentos fd y offset. Por lo tanto, estas arquitecturas definen una versión de la llamada al sistema que ordena los argumentos adecuadamente, pero es de lo contrario exactamente igual que posix_fadvise().

Por ejemplo, desde Linux 2.6.14, ARM tiene la siguiente llamada al sistema:


long arm_fadvise64_64(int fd, int advice,
                      loff_t offset, loff_t size);

Estos detalles específicos de la arquitectura generalmente son ocultados a las aplicaciones por la función envoltorio posix_fadvise() de glibc, que invoca la llamada al sistema específica de la arquitectura apropiada.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001.

El soporte del kernel apareció por primera vez en Linux 2.5.60; la llamada al sistema subyacente se llama fadvise64(). El soporte de la biblioteca se ha proporcionado desde glibc 2.2, a través de la función envoltorio posix_fadvise().

Desde Linux 3.18, el soporte para la llamada al sistema subyacente es opcional, dependiendo de la configuración de la opción de configuración CONFIG_ADVISE_SYSCALLS.

El tipo del argumento size se cambió de size_t a off_t en POSIX.1-2001 TC1.

NOTAS

El contenido de la caché de búfer del kernel se puede borrar a través de la interfaz /proc/sys/vm/drop_caches descrita en proc(5).

Se puede obtener una instantánea de qué páginas de un archivo residen en la caché de búfer abriendo un archivo, mapeándolo con mmap(2), y luego aplicando mincore(2) al mapeo.

ERRORES DE PROGRAMACIÓN

En Linux 2.6.18, se introdujo un error de regresión en la implementación de POSIX_FADV_NOREUSE que causaba que el sistema devolviera ENOSYS cuando se le pasaba este valor. Este error se corrigió en Linux 2.6.22.
