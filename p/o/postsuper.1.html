POSTSUPER(1) Manual de comandos generales POSTSUPER(1)

NOMBRE

postsuper - Superintendente de Postfix

SINOPSIS

postsuper [-psSv]
[-c directorio_config] [-d id_cola]
[-e id_cola] [-f id_cola]
[-h id_cola] [-H id_cola]
[-r id_cola] [directorio ...]

DESCRIPCIÓN


El comando postsuper(1) realiza tareas de mantenimiento en la cola de Postfix. El uso del comando está restringido al superusuario. Consulte el comando postqueue(1) para operaciones de cola no privilegiadas, como listar o vaciar la cola de correo.

Por defecto, postsuper(1) realiza las operaciones solicitadas con las opciones de línea de comandos -s y -p en todos los directorios de cola de Postfix: esto incluye los directorios incoming, active, deferred y hold con archivos de mensajes y los directorios bounce, defer, trace y flush con archivos de registro.

Opciones:

-c directorio_config
El archivo de configuración main.cf se encuentra en el directorio especificado en lugar del directorio de configuración predeterminado. Consulte también la configuración del entorno MAIL_CONFIG a continuación.
-d id_cola
Elimina un mensaje con el ID de cola especificado de las colas de correo nombradas (predeterminado: hold, incoming, active y deferred).

Para eliminar varios archivos, especifique la opción -d varias veces, o especifique un id_cola de - para leer los IDs de cola desde la entrada estándar. Por ejemplo, para eliminar todo el correo con un único destinatario usuario@ejemplo.com:

postqueue -j | jq -r '
    # Ver la sección FORMATO DE OBJETO JSON en la página del manual de postqueue(1)
    select(.recipients[0].address == "user@example.com")
    | select(.recipients[1].address == null)
    | .queue_id
 ' | postsuper -d -

(nota la opción "jq -r"), o la forma histórica:

mailq | tail -n +2 | grep -v '^ *(' | awk  'BEGIN { RS = "" }
    # $7=remitente, $8=destinatario1, $9=destinatario2
    { if ($8 == "user@example.com" && $9 == "")
          print $1 }
 ' | tr -d '*!' | postsuper -d -

Especifique "-d ALL" para eliminar todos los mensajes; por ejemplo, especifique "-d ALL deferred" para eliminar todo el correo en la cola deferred. Como medida de seguridad, la palabra ALL debe especificarse en mayúsculas.

Advertencia: Los IDs de cola de Postfix se reutilizan (siempre con Postfix <= 2.8; y con Postfix >= 2.9 cuando enable_long_queue_ids=no). Existe una posibilidad muy pequeña de que postsuper elimine el archivo de mensaje incorrecto cuando se ejecuta mientras el sistema de correo de Postfix está entregando correo.

El escenario es el siguiente:

1)
El gestor de colas de Postfix elimina el mensaje que se le pide a postsuper(1) que elimine, porque Postfix ha terminado con el mensaje (se ha entregado o se ha devuelto al remitente).
2)
Llega nuevo correo y al nuevo mensaje se le da el mismo ID de cola que al mensaje que postsuper(1) debía eliminar. La probabilidad de reutilizar un ID de cola eliminado es aproximadamente 1 de cada 2**15 (el número de valores de microsegundos diferentes que el reloj del sistema puede distinguir dentro de un segundo).
3)
postsuper(1) elimina el nuevo mensaje, en lugar del mensaje antiguo que debería haber eliminado.
-e id_cola
-f id_cola
Solicita la expiración forzada de un mensaje con el ID de cola especificado en las colas de correo nombradas (predeterminado: hold, incoming, active y deferred).
  • El mensaje será devuelto al remitente cuando el gestor de colas intente entregar ese mensaje (tenga en cuenta que Postfix nunca entregará mensajes en la cola hold).
  • Las opciones -e y -f solicitan ambas la expiración forzada. La diferencia es que -f también liberará un mensaje si está en la cola hold. Con -e, dicho mensaje no sería devuelto al remitente hasta que se libere con -f o -H.
  • Cuando se expira forzosamente un mensaje diferido, el mensaje de retorno indicará el motivo del retraso. De lo contrario, el motivo será "el mensaje ha caducado administrativamente".
Para expirar varios archivos, especifique la opción -e o -f varias veces, o especifique un id_cola de - para leer los IDs de cola desde la entrada estándar (consulte la opción -d anterior para ver un ejemplo, pero asegúrese de reemplazar -d en el ejemplo).

Especifique "-e ALL" o "-f ALL" para expirar todos los mensajes; por ejemplo, especifique "-e ALL deferred" para expirar todo el correo en la cola deferred. Como medida de seguridad, la palabra ALL debe especificarse en mayúsculas.

Estas funciones están disponibles en Postfix 3.5 y posteriores.

-h id_cola
Pone el correo "en espera" para que no se intente entregarlo. Mueve un mensaje con el ID de cola especificado de las colas de correo nombradas (predeterminado: incoming, active y deferred) a la cola hold.

Para poner en espera varios archivos, especifique la opción -h varias veces, o especifique un id_cola de - para leer los IDs de cola desde la entrada estándar.

Especifique "-h ALL" para poner en espera todos los mensajes; por ejemplo, especifique "-h ALL deferred" para poner en espera todo el correo en la cola deferred. Como medida de seguridad, la palabra ALL debe especificarse en mayúsculas.

Nota: mientras el correo está "en espera", no caducará cuando su tiempo en la cola exceda la configuración maximal_queue_lifetime o bounce_queue_lifetime. Se someterá a expiración después de que se libere de la "espera".

Esta función está disponible en Postfix 2.0 y posteriores.

-H id_cola
Libera el correo que se puso "en espera". Mueve un mensaje con el ID de cola especificado de las colas de correo nombradas (predeterminado: hold) a la cola deferred.

Para liberar varios archivos, especifique la opción -H varias veces, o especifique un id_cola de - para leer los IDs de cola desde la entrada estándar.

Nota: especifique "postsuper -r" para liberar correo que se mantuvo en espera durante una fracción significativa de $maximal_queue_lifetime o $bounce_queue_lifetime, o más.

Especifique "-H ALL" para liberar todo el correo que está "en espera". Como medida de seguridad, la palabra ALL debe especificarse en mayúsculas.

Esta función está disponible en Postfix 2.0 y posteriores.

-p
Limpia archivos temporales antiguos que quedan después de bloqueos del sistema o del software. Las operaciones -p, -s y -S se realizan antes que otras operaciones.
-r id_cola
Reencola el mensaje con el ID de cola especificado de las colas de correo nombradas (predeterminado: hold, incoming, active y deferred).

Para reencolar varios archivos, especifique la opción -r varias veces, o especifique un id_cola de - para leer los IDs de cola desde la entrada estándar.

Especifique "-r ALL" para reencolar todos los mensajes. Como medida de seguridad, la palabra ALL debe especificarse en mayúsculas.

Un mensaje reencolado se mueve a la cola maildrop, desde donde es copiado por los demonios pickup(8) y cleanup(8) a un nuevo archivo de cola. En muchos aspectos, su manejo difiere del de una nueva notificación local.

  • El mensaje no se somete a la configuración smtpd_milters o non_smtpd_milters. Cuando el correo ha pasado por un filtro de contenido externo, esto produciría resultados incorrectos.

postsuper(1) — Arch Linux

NAME

postsuper — Postfix mail system administration

SYNOPSIS

postsuper [-psv] [-d queue_id] [-e queue_id] [-f queue_id] [-h queue_id] [-H queue_id] [-r queue_id]

DESCRIPTION

The postsuper command performs administrative operations on the Postfix queue. It is typically used to remove, requeue, or hold mail messages. The -p, -s, and -S operations are done before other operations.

The following operations are supported:

-d queue_id
Delete a message with the specified queue_id from the queue. Multiple -d options can be specified.
-d all
Delete all messages from the queue. This will affect all queues, except those that are part of the non-delivery backlog.
-e queue_id
Expire a message with the specified queue_id. This makes the message unusable for delivery or requeuing. Multiple -e options can be specified.
-e all
Expire all messages from the queue. This will affect all queues, except those that are part of the non-delivery backlog.
-f queue_id
Apply deferred message state for the specified queue_id. This is equivalent to running Postfix with enable_long_queue_ids=yes (default in Postfix 2.9 and later). If the message is already deferred, this operation is a no-op. Multiple -f options can be specified.
-f all
Apply deferred message state for all messages in the queue. This will affect all queues, except those that are part of the non-delivery backlog.
-h queue_id
Hold a message with the specified queue_id. The message will not be delivered until it is released with the -H option. Multiple -h options can be specified.
-h all
Hold all messages from the queue. This will affect all queues, except those that are part of the non-delivery backlog.
-H queue_id
Release a message with the specified queue_id from hold. Multiple -H options can be specified.
-H all
Release all messages from hold. This will affect all queues, except those that are part of the non-delivery backlog.
-p
Requeue a message. This will subject the message to the same delivery process as when it was first received. The -p operation is useful for recovering from transient delivery problems or for applying new configuration settings.

The message is subjected to the following operations:

  • The message is subjected to the same content_filter settings (if any) as used for new local mail submissions. This is useful when content_filter settings have changed.
  • The message is subjected again to mail address rewriting and substitution. This is useful when rewriting rules or virtual mappings have changed.

    The address rewriting context (local or remote) is the same as when the message was received.

  • The message is subjected again to Milter applications that depend on original SMTP connection state information.
-p all
Requeue all messages from the queue. This will affect all queues, except those that are part of the non-delivery backlog.

Warning: Postfix queue IDs are reused (always with Postfix <= 2.8; and with Postfix >= 2.9 when enable_long_queue_ids=no). There is a very small possibility that postsuper requeues the wrong message file when it is executed while the Postfix mail system is running, but no harm should be done.

This feature is available in Postfix 1.1 and later.

-s
Structure check and structure repair. This should be done once before Postfix startup. The -p, -s, and -S operations are done before other operations.
  • Rename files whose name does not match the message file inode number. This operation is necessary after restoring a mail queue from a different machine or from backup, when queue files were created with Postfix <= 2.8 or with "enable_long_queue_ids = no".
  • Move queue files that are in the wrong place in the file system hierarchy and remove subdirectories that are no longer needed. File position rearrangements are necessary after a change in the hash_queue_names and/or hash_queue_depth configuration parameters.
  • Rename queue files created with "enable_long_queue_ids = yes" to short names, for migration to Postfix <= 2.8. The procedure is as follows: 
    # postfix stop
# postconf enable_long_queue_ids=no
# postsuper -s

    Run postsuper repeatedly until it stops reporting file name changes.

-S
A redundant version of -s that requires that long file names also match the message file inode number. This option exists for testing purposes, and is available with Postfix 2.9 and later. The -p, -s, and -S operations are done before other operations.
-v
Enable verbose logging for debugging purposes. Multiple -v options make the software increasingly verbose.

DIAGNOSTICS


Problems are reported to the standard error stream and to syslogd(8) or postlogd(8).

postsuper reports the number of messages deleted with -d, the number of messages expired with -e, the number of messages expired or released with -f, the number of messages held or released with -h or -H, the number of messages requeued with -r, and the number of messages whose queue file name was fixed with -s. The report is written to the standard error stream and to syslogd(8) or postlogd(8).

ENVIRONMENT

MAIL_CONFIG
Directory with the main.cf file.

BUGS


Mail that is not sanitized by Postfix (i.e. mail in the maildrop queue) cannot be placed "on hold".

CONFIGURATION PARAMETERS

The following main.cf parameters are especially relevant to this program. The text below provides only a parameter summary. See postconf(5) for more details including examples.

config_directory (see 'postconf -d' output)
The default location of the Postfix main.cf and master.cf configuration files.
hash_queue_depth (1)
The number of subdirectory levels for queue directories listed with the hash_queue_names parameter.
hash_queue_names (deferred, defer)
The names of queue directories that are split across multiple subdirectory levels.
import_environment (see 'postconf -d' output)
The list of environment variables that a privileged Postfix process will import from a non-Postfix parent process, or name=value environment overrides.
queue_directory (see 'postconf -d' output)
The location of the Postfix top-level queue directory.
syslog_facility (mail)
The syslog facility of Postfix logging.
syslog_name (see 'postconf -d' output)
A prefix that is prepended to the process name in syslog records, so that, for example, "smtpd" becomes "prefix/smtpd".

Available in Postfix version 2.9 and later:

enable_long_queue_ids (no)
Enable long, non-repeating, queue IDs (queue file names).
