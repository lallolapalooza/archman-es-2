podman-pull(1) Manual de Comandos Generales podman-pull(1)

NOMBRE

podman-pull - Descargar una imagen de un registro

SINOPSIS

podman pull [opciones] fuente [fuente...]

podman image pull [opciones] fuente [fuente...]

podman pull [opciones] [transporte]nombre[:etiqueta|@digest]

podman image pull [opciones] [transporte]nombre[:etiqueta|@digest]

DESCRIPCIÓN

podman pull copia una imagen de un registro a la máquina local. El comando puede descargar una o más imágenes. Si la referencia de la imagen en el argumento de la línea de comandos no contiene un registro, se denomina referencia de nombre corto. Si la imagen es una referencia de 'nombre corto', Podman le pide al usuario el registro de contenedores específico para descargar la imagen, si no se ha especificado un alias para el nombre corto en short-name-aliases.conf. Si no se especifica una etiqueta de imagen, podman pull utiliza por defecto la imagen con la etiqueta latest (si existe) y la descarga. Después de descargar la imagen, podman imprime el ID completo de la imagen. podman pull también puede descargar imágenes usando un digest podman pull imagen@digest y también puede usarse para descargar imágenes de archivos y almacenamiento local usando diferentes transportes. IMPORTANTE: Las imágenes se almacenan en el almacenamiento de imágenes local.

FUENTE

FUENTE es la ubicación desde la cual se descarga la imagen del contenedor. Soporta todos los transportes de containers-transports(5). Si no se especifica transporte, la entrada está sujeta a la resolución de nombres cortos y se utiliza el transporte docker (es decir, registro de contenedores). Para clientes remotos, incluidas máquinas Mac y Windows (excluyendo WSL2), docker es el único transporte soportado.

# Descargar de un registro de contenedores
$ podman pull quay.io/username/myimage
# Descargar de un registro de contenedores con resolución de nombre corto
$ podman pull fedora
# Descargar de un registro de contenedores a través del transporte docker
$ podman pull docker://quay.io/username/myimage
# Descargar de un directorio local
$ podman pull dir:/tmp/myimage
# Descargar de un archivo tar en formato docker-archive
$ podman pull docker-archive:/tmp/myimage
# Descargar de un demonio docker local
$ sudo podman pull docker-daemon:docker.io/library/myimage:33
# Descargar de un archivo tar en formato OCI-archive
$ podman pull oci-archive:/tmp/myimage

OPCIONES

--all-tags, -a

Se descargan todas las imágenes etiquetadas en el repositorio.

*IMPORTANTE: Al usar la bandera all-tags, Podman no itera sobre los registros de búsqueda en containers-registries.conf(5), sino que siempre utiliza docker.io para nombres de imágenes no calificados.*

--arch=ARQUITECTURA

Anula la arquitectura, por defecto la del host, de la imagen a descargar. Por ejemplo, arm. A menos que se anule, las búsquedas posteriores de la misma imagen en el almacenamiento local coinciden con esta arquitectura, independientemente del host.

--authfile=ruta

Ruta del archivo de autenticación. El valor predeterminado es ${XDG_RUNTIME_DIR}/containers/auth.json en Linux, y $HOME/.config/containers/auth.json en Windows/macOS. El archivo es creado por podman login. Si el estado de autorización no se encuentra allí, se verifica $HOME/.docker/config.json, que se establece usando docker login.

Nota: También existe la opción de anular la ruta predeterminada del archivo de autenticación estableciendo la variable de entorno REGISTRY_AUTH_FILE. Esto se puede hacer con export REGISTRY_AUTH_FILE=ruta.

--cert-dir=ruta

Utiliza los certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro. (Predeterminado: /etc/containers/certs.d) Para más detalles, ver containers-certs.d(5). (Esta opción no está disponible con el cliente remoto de Podman, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--creds=[usuario[:contraseña]]

El [usuario[:contraseña]] a utilizar para autenticarse con el registro, si es necesario. Si uno o ambos valores no se proporcionan, aparece un aviso en la línea de comandos y se puede introducir el valor. La contraseña se introduce sin eco.

Tenga en cuenta que las credenciales especificadas solo se utilizan para autenticarse contra los registros de destino. No se utilizan para espejos ni cuando el registro se reescribe (ver containers-registries.conf(5)); para autenticarse contra ellos considere usar un archivo containers-auth.json(5).

--decryption-key=clave[:frase_contraseña]

La [clave[:frase_contraseña]] que se utilizará para el descifrado de imágenes. La clave puede apuntar a claves y/o certificados. Se intenta el descifrado con todas las claves. Si la clave está protegida por una frase de contraseña, es obligatorio pasarla en el argumento y omitirla de lo contrario.

--disable-content-trust

Esta es una opción específica de Docker para deshabilitar la verificación de imágenes en un registro de contenedores y no es compatible con Podman. Esta opción es un NOOP y se proporciona únicamente para compatibilidad de scripting.

--help, -h

Imprime la declaración de uso.

--os=SO

Anula el sistema operativo, por defecto el del host, de la imagen a descargar. Por ejemplo, windows. A menos que se anule, las búsquedas posteriores de la misma imagen en el almacenamiento local coinciden con este SO, independientemente del host.

--platform=SO/ARQUITECTURA

Especifica la plataforma para seleccionar la imagen. (Entra en conflicto con --arch y --os) La opción --platform se puede usar para anular la arquitectura y el sistema operativo actuales. A menos que se anule, las búsquedas posteriores de la misma imagen en el almacenamiento local coinciden con esta plataforma, independientemente del host.

--policy

Política de descarga de imágenes. El valor predeterminado es always.

  • always: Siempre descarga la imagen y genera un error si la descarga falla.
  • missing: Solo descarga la imagen si no se pudo encontrar en el almacenamiento de contenedores local. Genera un error si no se encontró ninguna imagen y la descarga falla.
  • never: Nunca descarga la imagen; solo utiliza la versión local. Genera un error si la imagen no está presente localmente.
  • newer: Descarga si la imagen en el registro es más reciente que la del almacenamiento de contenedores local. Una imagen se considera más reciente cuando los digests son diferentes. Comparar las marcas de tiempo es propenso a errores. Los errores de descarga se suprimen si se encontró una imagen local.

--quiet, -q

Suprime la información de salida al descargar imágenes

--retry=intentos

Número de veces que se intentará descargar o enviar imágenes entre el registro y el almacenamiento local en caso de fallo. El valor predeterminado es 3.

--retry-delay=duración

Duración del retraso entre intentos de reintento al descargar o enviar imágenes entre el registro y el almacenamiento local en caso de fallo. El valor predeterminado es comenzar en dos segundos y luego retroceder exponencialmente. El retraso se utiliza cuando se establece este valor y no se produce una retroalimentación exponencial.

--tls-verify

Requiere HTTPS y verifica los certificados al contactar los registros (predeterminado: true). Si se establece explícitamente en true, se utiliza la verificación TLS. Si se establece en false, no se utiliza la verificación TLS. Si no se especifica, se utiliza la verificación TLS a menos que el registro de destino figure como un registro inseguro en containers-registries.conf(5)

--variant=VARIANTE

Utiliza VARIANTE en lugar de la variante de arquitectura predeterminada de la imagen del contenedor. Algunas imágenes pueden usar múltiples variantes de las arquitecturas arm, como arm/v5 y arm/v7.

ARCHIVOS

short-name-aliases.con

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

"f" (/var/cache/containers/short-name-aliases.conf, $HOME/.cache/containers/short-name-aliases.conf)

Cuando los usuarios especifican imágenes que no incluyen el registro de contenedores donde se almacena la imagen, esto se llama un nombre corto. El uso de registros de búsqueda no calificados implica una ambigüedad, ya que no está claro de qué registro se puede extraer una imagen dada, referenciada por un nombre corto.

El uso de nombres cortos está sujeto al riesgo de encontrar espacios de nombres de registro secuestrados. Si los registros de búsqueda no calificados se establecen en ["public-registry.com", "my-private-registry.com"], un atacante puede apoderarse de un espacio de nombres de public-registry.com de tal manera que una imagen pueda extraerse de public-registry.com en lugar de la fuente prevista my-private-registry.com.

Si bien se recomienda encarecidamente utilizar siempre referencias de imágenes completamente calificadas, las implementaciones existentes que utilizan nombres cortos pueden no cambiarse fácilmente. Para sortear la ambigüedad mencionada, se pueden configurar las llamadas alias de nombre corto que apuntan a una referencia de imagen completamente calificada. Las distribuciones a menudo distribuyen un archivo de expansión predeterminado de shortnames.conf en el directorio /etc/containers/registries.conf.d/. Los administradores pueden usar este directorio para agregar sus propios archivos de expansión de nombres cortos locales.

Al extraer una imagen, si el usuario no especifica el registro completo, los motores de contenedores intentan expandir el nombre corto a un nombre completo. Si el comando se ejecuta con una tty, se le pide al usuario que seleccione un registro de la lista predeterminada de registros no calificados definidos en registries.conf. La selección del usuario se almacena luego en un archivo de caché para ser utilizado en todas las expansiones de nombres cortos futuras. Los nombres cortos de rootful se almacenan en /var/cache/containers/short-name-aliases.conf. Los nombres cortos sin root se almacenan en el archivo $HOME/.cache/containers/short-name-aliases.conf.

Para obtener más información sobre nombres cortos, consulte containers-registries.conf(5)

registries.conf (/etc/containers/registries.conf)

registries.conf es el archivo de configuración que especifica qué registros de contenedores se consultan al completar nombres de imágenes que no incluyen un registro o una porción de dominio.

NOTA: Utilice la variable de entorno TMPDIR para cambiar la ubicación de almacenamiento temporal de las imágenes de contenedor descargadas. Podman utiliza por defecto /var/tmp.
