POSTMAP(1) Manual de comandos generales POSTMAP(1)

NOMBRE

postmap - gestión de tablas de búsqueda de Postfix

SINOPSIS

postmap [-bfFhimnNoprsuUvw] [-c directorio_configuración] [-d clave] [-q clave]
[tipo_archivo:]nombre_archivo ...

DESCRIPCIÓN


El comando postmap(1) crea o consulta una o más tablas de búsqueda de Postfix, o actualiza una existente.

Si los archivos resultantes no existen, se crearán con los mismos permisos de lectura de grupo y otros que su archivo fuente.

Mientras se está actualizando la tabla, se pospone la entrega de señales y se coloca un bloqueo exclusivo y consultivo en toda la tabla, con el fin de evitar sorpresas en los procesos espectadores.

FORMATO DEL ARCHIVO DE ENTRADA

El formato de un archivo de entrada de tabla de búsqueda es el siguiente:

  • Una entrada de tabla tiene la forma 
         clave espacios en blanco valor
  • Se ignoran las líneas vacías y las líneas que solo contienen espacios en blanco, al igual que las líneas cuyo primer carácter que no es un espacio en blanco es un `#'.
  • Una línea lógica comienza con texto que no son espacios en blanco. Una línea que comienza con espacios en blanco continúa una línea lógica.

La clave y el valor se procesan tal cual, excepto que los espacios en blanco circundantes se eliminan. Los espacios en blanco en las claves de búsqueda son compatibles en Postfix 3.2 y posteriores, rodeando la clave con comillas dobles `"'. Dentro de las comillas dobles, los caracteres de comillas dobles `"' y de barra invertida `\' se pueden incluir anteponiéndoles una barra invertida.

Cuando se proporciona la opción -F, el valor debe especificar uno o más nombres de archivo separados por comas y/o espacios en blanco; postmap(1) concatenará el contenido del archivo (insertando un carácter de nueva línea entre archivos) y almacenará el resultado codificado en base64 en lugar del valor.

Cuando la clave especifica información de dirección de correo electrónico, la parte local debe encerrarse entre comillas dobles si es requerido por RFC 5322. Por ejemplo, una parte local de dirección que contiene ";", o una parte local que comienza o termina con ".".

Por defecto, la clave de búsqueda se mapea a minúsculas para que las búsquedas no distingan entre mayúsculas y minúsculas; a partir de Postfix 2.3, este plegado de mayúsculas y minúsculas solo ocurre con tablas cuyas claves de búsqueda son cadenas de mayúsculas y minúsculas fijas como btree:, dbm: o hash:. Con versiones anteriores, la clave de búsqueda se plegaba incluso con tablas donde un campo de búsqueda podía coincidir con texto en mayúsculas y minúsculas, como regexp: y pcre:. Esto resultó en pérdida de información con sustituciones de $número.

ARGUMENTOS DE LA LÍNEA DE COMANDOS

-b
Habilita el modo de consulta del cuerpo del mensaje. Al leer claves de búsqueda de la entrada estándar con "-q -", procesa la entrada como si fuera un mensaje de correo electrónico en formato RFC 5322. Cada línea de contenido del cuerpo se convierte en una clave de búsqueda.

Por defecto, la opción -b comienza a generar claves de búsqueda en la primera línea que no es una cabecera, y se detiene cuando se alcanza el final del mensaje. Para simular el procesamiento de body_checks(5), habilita el análisis MIME con -m. Con esto, la opción -b no genera claves de búsqueda de estilo de cuerpo para cabeceras MIME de archivos adjuntos y para cabeceras de mensaje/* adjuntas.

NOTA: con "smtputf8_enable = yes", la opción -b deshabilita las comprobaciones de sintaxis UTF-8 en las claves de consulta y los resultados de búsqueda. Especifica la opción -U para forzar las comprobaciones de sintaxis UTF-8 de todos modos.

Esta característica está disponible en Postfix versión 2.6 y posteriores.

-c directorio_configuración
Lee el archivo de configuración main.cf en el directorio especificado en lugar del directorio de configuración predeterminado.
-d clave
Busca en los mapas especificados la clave y elimina una entrada por mapa. El estado de salida es cero cuando se encontró la información solicitada.

Si se especifica un valor de clave de -, el programa lee los valores de clave del flujo de entrada estándar. El estado de salida es cero cuando se encontró al menos una de las claves solicitadas.

-f
No pliega la clave de búsqueda a minúsculas al crear o consultar una tabla.

Con Postfix versión 2.3 y posteriores, esta opción no tiene efecto para tablas de expresiones regulares. Allí, el plegado de mayúsculas y minúsculas se controla añadiendo un indicador a un patrón.

-F
Al consultar un mapa o listar un mapa, decodifica cada valor de base64. Al crear un mapa a partir de un archivo fuente, procesa cada valor como una lista de nombres de archivo, concatena el contenido de esos archivos y almacena el resultado codificado en base64 en lugar del valor (ver FORMATO DEL ARCHIVO DE ENTRADA para detalles).

Esta característica está disponible en Postfix versión 3.4 y posteriores.

-h
Habilita el modo de consulta de cabeceras de mensaje. Al leer claves de búsqueda de la entrada estándar con "-q -", procesa la entrada como si fuera un mensaje de correo electrónico en formato RFC 5322. Cada línea de cabecera lógica se convierte en una clave de búsqueda. Una cabecera de varias líneas se convierte en una clave de búsqueda con uno o más caracteres de nueva línea incrustados.

Por defecto, la opción -h genera claves de búsqueda hasta que se alcanza la primera línea que no es una cabecera. Para simular el procesamiento de header_checks(5), habilita el análisis MIME con -m. Con esto, la opción -h también genera claves de búsqueda de estilo de cabecera para cabeceras MIME de archivos adjuntos y para cabeceras de mensaje/* adjuntas.

NOTA: con "smtputf8_enable = yes", la opción -b deshabilita las comprobaciones de sintaxis UTF-8 en las claves de consulta y los resultados de búsqueda. Especifica la opción -U para forzar las comprobaciones de sintaxis UTF-8 de todos modos.

Esta característica está disponible en Postfix versión 2.6 y posteriores.

-i
Modo incremental. Lee entradas de la entrada estándar y no trunca una base de datos existente. Por defecto, postmap(1) crea una nueva base de datos a partir de las entradas en nombre_archivo.
-m
Habilita el análisis MIME con "-b" y "-h".

Esta característica está disponible en Postfix versión 2.6 y posteriores.

-N
Incluye el carácter nulo de terminación que finaliza las claves y valores de búsqueda. Por defecto, postmap(1) hace lo que sea el valor predeterminado para el sistema operativo anfitrión.
-n
No incluye el carácter nulo de terminación que finaliza las claves y valores de búsqueda. Por defecto, postmap(1) hace lo que sea el valor predeterminado para el sistema operativo anfitrión.
-o
No libera privilegios de root al procesar un archivo de entrada que no sea de root. Por defecto, postmap(1) deja caer los privilegios de root y se ejecuta como propietario del archivo fuente en su lugar.
-p
No hereda los permisos de acceso a archivos del archivo de entrada al crear un archivo nuevo. En su lugar, crea un archivo nuevo con permisos de acceso predeterminados (modo 0644).
-q clave
Busca en los mapas especificados la clave y escribe el primer valor encontrado en el flujo de salida estándar. El estado de salida es cero cuando se encontró la información solicitada.

Nota: esto realiza una única consulta con la clave tal como se especifica, y no realiza consultas iterativas con subcadenas de la clave como se describe para access(5), canonical(5), transport(5), virtual(5) y otras características de Postfix basadas en tablas.

Si se especifica un valor de clave de -, el programa lee los valores de clave del flujo de entrada estándar y escribe una línea de salida clave valor por cada clave que se encontró. El estado de salida es cero cuando se encontró al menos una de las claves solicitadas.

-r
Al actualizar una tabla, no se queja de los intentos de actualizar entradas existentes y realiza esas actualizaciones de todos modos.
-s
Recuperar

NAME

postmap — create/update/query Postfix lookup tables

SYNOPSIS

postmap [-d | -q key] [-b | -h] [-f] [-i] [-u] [-U] [-v] [-w] [file_type:]file_name ...

DESCRIPTION

The postmap command is used to create or update Postfix lookup tables. It reads a list of key-value pairs from standard input, or from one or more specified source files, and writes the result to one or more database files.

When postmap is invoked without the -d or -q options, it builds the lookup table(s) from the specified source file(s).

When postmap is invoked with the -q option, it queries the lookup table for a specific key.

When postmap is invoked with the -d option, it dumps all database elements, and writes one line of key value output for each element. The elements are printed in database order, which is not necessarily the same as the original input order.

This feature is available in Postfix version 2.2 and later, and is not available for all database types.

INPUT FILE FORMAT

The input file format is:

keyvalue

Blank lines and lines starting with the default comment character (usually '#') are ignored. White space surrounding the key and value is removed.

The lookup table type determines how the key and value are stored. For hash, btree, cdb, dbm, and sdbm tables, the key and value are treated as byte strings. For other table types, the key and value are treated as character strings and may be subject to additional validation.

For details, see postmap(1).

COMMAND-LINE ARGUMENTS

-d
Dump all database elements, and write one line of key value output for each element. The elements are printed in database order, which is not necessarily the same as the original input order.

This feature is available in Postfix version 2.2 and later, and is not available for all database types.

-f
Process the input file and write the output to standard output, instead of updating the database file. This is useful for testing changes or for converting between database types.
-h
When querying (-q), also query subdomains. This is available only for hash and btree databases.
-i
When querying (-q), ignore case sensitivity. This is available only for hash and btree databases.
-q key
Query the lookup table for the specified key. If found, the corresponding value is printed to standard output, followed by a newline. If not found, a message is printed to standard error and postmap exits with a non-zero status.
-u
Disable UTF-8 support. UTF-8 support is enabled by default when "smtputf8_enable = yes". It requires that keys and values are valid UTF-8 strings.
-U
With "smtputf8_enable = yes", force UTF-8 syntax checks with the -b and -h options.
-v
Enable verbose logging for debugging purposes. Multiple -v options make the software increasingly verbose.
-w
When updating a table, do not complain about attempts to update existing entries, and ignore those attempts.

Arguments:

file_type
The database type. To find out what types are supported, use the "postconf -m" command.

The postmap(1) command can query any supported file type, but it can create only the following file types:

btree
The output file is a btree file, named file_name.db. This is available on systems with support for db databases.
cdb
The output consists of one file, named file_name.cdb. This is available on systems with support for cdb databases.
dbm
The output consists of two files, named file_name.pag and file_name.dir. This is available on systems with support for dbm databases.
fail
A table that reliably fails all requests. The lookup table name is used for logging only. This table exists to simplify Postfix error tests.
hash
The output file is a hashed file, named file_name.db. This is available on systems with support for db databases.
lmdb
The output is a btree-based file, named file_name.lmdb. lmdb supports concurrent writes and reads from different processes, unlike other supported file-based tables. This is available on systems with support for lmdb databases.
sdbm
The output consists of two files, named file_name.pag and file_name.dir. This is available on systems with support for sdbm databases.

When no file_type is specified, the software uses the database type specified via the default_database_type configuration parameter.

file_name
The name of the lookup table source file when rebuilding a database.

DIAGNOSTICS


Problems are logged to the standard error stream and to syslogd(8) or postlogd(8). No output means that no problems were detected. Duplicate entries are skipped and are flagged with a warning.

postmap(1) terminates with zero exit status in case of success (including successful "postmap -q" lookup) and terminates with non-zero exit status in case of failure.

ENVIRONMENT

MAIL_CONFIG
Directory with Postfix configuration files.
MAIL_VERBOSE
Enable verbose logging for debugging purposes.

CONFIGURATION PARAMETERS

The following main.cf parameters are especially relevant to this program. The text below provides only a parameter summary. See postconf(5) for more details including examples.

berkeley_db_create_buffer_size (16777216)
The per-table I/O buffer size for programs that create Berkeley DB hash or btree tables.
berkeley_db_read_buffer_size (131072)
The per-table I/O buffer size for programs that read Berkeley DB hash or btree tables.
config_directory (see 'postconf -d' output)
The default location of the Postfix main.cf and master.cf configuration files.
default_database_type (see 'postconf -d' output)
The default database type for use in newaliases(1), postalias(1) and postmap(1) commands.
import_environment (see 'postconf -d' output)
The list of environment variables that a privileged Postfix process will import from a non-Postfix parent process, or name=value environment overrides.
smtputf8_enable (yes)
Enable preliminary SMTPUTF8 support for the protocols described in RFC 6531, RFC 6532, and RFC 6533.
syslog_facility (mail)
The syslog facility of Postfix logging.
syslog_name (see 'postconf -d' output)
A prefix that is prepended to the process name in syslog records, so that, for example, "smtpd" becomes "prefix/smtpd".

Available in Postfix 2.11 and later:

lmdb_map_size (16777216)
The initial OpenLDAP LMDB database size limit in bytes.
