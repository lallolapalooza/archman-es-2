DESCRIPCIÓN

INTRODUCCIÓN

postfwd3 está escrito para combinar restricciones complejas de postfix en un conjunto de reglas similar a las de la mayoría de los firewalls. El programa utiliza el protocolo de delegación de políticas de postfix para controlar el acceso al sistema de correo antes de que se acepte un mensaje (visite http://www.postfix.org/SMTPD_POLICY_README.html para más información).

postfwd3 le permite elegir una acción (por ejemplo, rechazar, dunno) para una combinación de varios parámetros smtp (como la dirección del remitente y el destinatario, el tamaño o la huella digital TLS del cliente). También ofrece macros/acls simples que deberían permitir configuraciones sencillas y fáciles de leer.

Características:

* Combinaciones complejas de parámetros smtp

* Búsquedas combinadas RBL/RHSBL con acciones arbitrarias dependiendo de los resultados

* Sistema de puntuación

* Reglas basadas en fecha/hora

* Macros/ACLs, grupos dinámicos, negación

* Comparar atributos de solicitud (por ejemplo, client_name y helo_name)

* Caché interna para solicitudes y búsquedas DNS

* Estadísticas integradas para el análisis de la eficiencia de las reglas

CONFIGURACIÓN

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Una línea de configuración consiste en pares opcionales de ítem=valor, separados por punto y coma (`;`) y la acción deseada apropiada:

[ <ítem1>=<valor>; <ítem2>=<valor>; ... ] acción=<resultado>

Ejemplo:

dirección_cliente=192.168.1.1 ; remitente==no@mala.local ; acción=RECHAZAR

Esto denegará todo el correo de 192.168.1.1 con remitente de sobre no@mala.local. El orden de los elementos no es importante. Así que lo siguiente conduciría al mismo resultado que el ejemplo anterior:

acción=RECHAZAR ; dirección_cliente=192.168.1.1 ; remitente==no@mala.local

La forma en que los ítems de la solicitud se comparan con el conjunto de reglas se puede influenciar de la siguiente manera:

====================================================================
 ÍTEM == VALOR                verdadero si ÍTEM es igual a VALOR
 ÍTEM => VALOR                verdadero si ÍTEM >= VALOR
 ÍTEM =< VALOR                verdadero si ÍTEM <= VALOR
 ÍTEM >  VALOR                verdadero si ÍTEM >  VALOR
 ÍTEM <  VALOR                verdadero si ÍTEM <  VALOR
 ÍTEM =~ VALOR                verdadero si ÍTEM ~= /^VALOR$/i
 ÍTEM != VALOR                falso si ÍTEM es igual a VALOR
 ÍTEM !> VALOR                falso si ÍTEM >= VALOR
 ÍTEM !< VALOR                falso si ÍTEM <= VALOR
 ÍTEM !~ VALOR                falso si ÍTEM ~= /^VALOR$/i
 ÍTEM =  VALOR                comportamiento por defecto (ver sección ÍTEMS)
====================================================================

Para identificar reglas individuales en sus archivos de registro, puede agregar un identificador único para cada una:

id=R_001 ; acción=RECHAZAR ; dirección_cliente=192.168.1.1 ; remitente==no@mala.local

Puede usar estos identificadores como destino para el comando `jump()` (ver sección ACCIONES a continuación). Los caracteres de espacio en blanco iniciales o finales serán ignorados. Use '#' para comentar su configuración. Otros lo apreciarán.

Un conjunto de reglas consta de una o varias reglas, que pueden cargarse desde archivos o pasarse como argumentos de línea de comandos. Consulte la sección LÍNEA DE COMANDOS a continuación para obtener más información sobre este tema.

Desde la versión 1.30 de postfwd, las reglas que abarcan múltiples líneas se pueden definir prefijando las siguientes líneas con uno o más caracteres de espacio en blanco (o '}' para macros):

id=REGLA001
        dirección_cliente=192.168.1.0/24
        remitente==no@mala.local
        acción=RECHAZAR no hay acceso

Las versiones de postfwd anteriores a la 1.30 requieren caracteres ';' y '\' al final:

id=REGLA001; \
        dirección_cliente=192.168.1.0/24; \
        remitente==no@mala.local; \
        acción=RECHAZAR no hay acceso

ÍTEMS

id                      - un id de regla único, que se puede usar para análisis de registro
                          los ids también sirven como destinos para el comando "jump".
fecha, hora              - un rango de tiempo o fecha dentro del cual la regla especificada debe coincidir
                          # FORMATO:
                          # Feb, 29th
                          fecha=29.02.2008
                          # Dec, 24th - 26th
                          fecha=24.12.2008-26.12.2008
                          # desde hoy hasta Nov, 23rd
                          fecha=-23.09.2008
                          # desde April, 1st hasta hoy
                          fecha=01.04.2008-
días, meses            - un rango de días de la semana (Dom-Sáb) o meses (Ene-Dic)
                          dentro del cual la regla especificada debe coincidir
puntuación                   - cuando se alcanza la puntuación especificada (ver sección ACCIONES)
                          la acción especificada se devolverá a postfix
                          las puntuaciones se establecen globalmente hasta que se redefinan.
puntuación_solicitud       - este valor permite acceder a la puntuación de una solicitud.
                          puede usarse como variable ($$puntuación_solicitud).
rbl, rhsbl,             - consulta las RBLs/RHSBLs especificadas, los valores posibles son:
rhsbl_cliente,            <nombre>[/<respuesta>/<caché_máx>, <nombre>/<respuesta>/<caché_máx>]
rhsbl_remitente,          (por defecto: respuesta=^127\.0\.0\.\d+$ caché_máx=3600)
rhsbl_remitente_inverso     los resultados de todas las consultas rhsbl_* se combinarán
                          en rhsbl_conteo (ver abajo).
rblconteo, rhsblconteo    - recuentos mínimos de aciertos de RBL/RHSBL para coincidir. si no se especifica
                          un único acierto de RBL/RHSBL coincidirá con los ítems rbl/rhsbl.
                          puede especificar 'all' para evaluar todos los ítems, y usarlo
                          como variable en una acción (ver sección ACCIONES)
                          (por defecto: 1)
parte_local_remitente,       - la parte local/dominio de la dirección del remitente
dominio_remitente
parte_local_destinatario,    - la parte local/dominio de la dirección del destinatario
dominio_destinatario
dirección_helo            - postfwd3 intenta buscar el helo_name. use
                          dirección_helo=!!(0.0.0.0/0) para comprobar si no se conoce.
                          Por favor, no use esto para control de acceso positivo
                          (listas blancas), ya que podría ser falsificado.
nombres_ns_remitente,       - postfwd3 intenta buscar los nombres/direcciones IP
direcciones_ns_remitente      de los servidores DNS para la parte del dominio del remitente.
                          Por favor, no use esto para control de acceso positivo
                          (listas blancas), ya que podría ser falsificado.
nombres_mx_remitente,       - postfwd3 intenta buscar los nombres/direcciones IP
direcciones_mx_remitente      de los registros MX para la parte del dominio del remitente.
                          Por favor, no use esto para control de acceso positivo
                          (listas blancas), ya que podría ser falsificado.
versión                 - versión de postfwd3, contiene "postfwd3 n.nn"
                          esto habilita verificaciones basadas en la versión en sus conjuntos de reglas
                          (por ejemplo, para migración). funciona también con versiones antiguas,
                          porque un ítem inexistente siempre devuelve falso:
                          # versión >= 1.10
                          id=R01; versión~=1\.[1-9][0-9]; dominio_remitente==algún.org \
                                ; acción=RECHAZAR lo siento, no hay acceso
puerto_postfwd            - puerto del servidor postfwd, permite usar el mismo conjunto de reglas en diferentes
                          instancias:
                          # la regla solo coincide para la instancia en el puerto 10045
                          id=PUERTO10045; puerto_postfwd==10045; acción=DUNNO
interfaz_postfwd       - interfaz de inicialización del servidor postfwd, ver puerto_postfwd
conteo_tasa              - solo disponible para las acciones rate(), size() y rcpt().
                          contiene el contador de límites real:
                                id=R01; acción=rate(remitente/200/600/RECHAZAR se excedió el límite de 200 [$$conteo_tasa aciertos])
                                id=R02; acción=rate(remitente/100/600/ADVERTIR se excedió el límite de 100 [$$conteo_tasa aciertos])

Además de estos, puede especificar cualquier atributo del protocolo de delegación de políticas de postfix. Siéntase libre de combinarlos como necesite (eche un vistazo a la sección EJEMPLOS a continuación).

la lista actual se puede encontrar en http://www.postfix.org/SMTPD_POLICY_README.html. Lea cuidadosamente sobre qué atributo se puede usar en qué nivel de la transacción smtp (por ejemplo, el tamaño solo funcionará de manera confiable en el nivel FINAL DEL MENSAJE). La coincidencia de patrones se realiza sin distinguir entre mayúsculas y minúsculas.

El uso múltiple del mismo ítem está permitido y se comparará como OR lógico, lo que significa que esto funcionará como se espera:

id=CONFIA001; acción=OK; tamaño_clave=64
        ccert_fingerprint=11:22:33:44:55:66:77:88:99
        ccert_fingerprint=22:33:44:55:66:77:88:99:00
        ccert_fingerprint=33:44:55:66:77:88:99:00:11
        remitente=@dominio\.local$

Los ítems dirección_cliente, rbl y rhsbl también se pueden especificar como valores separados por espacios en blanco o comas:

id=SALTA01; acción=dunno
        dirección_cliente=192.168.1.0/24, 172.16.254.23
id=SALTA02; acción=dunno
        dirección_cliente= 10.10.3.32 10.216.222.0/27

Los siguientes ítems deben ser únicos:

id, valores mínimos y máximos, rblconteo y rhsblconteo

Cualquier ítem puede ser negado anteponiendo '!!' a él, por ejemplo:

id=HOST001 ;  nombre_host == !!seguro.confia.local ;  acción=RECHAZAR solo seguro.confia.local por favor

o usando el operador de comparación correcto:

id=HOST001 ;  nombre_host != seguro.confia.local ;  acción=RECHAZAR solo seguro.confia.local por favor

Para evitar confusiones con expresiones regulares o simplemente para una mejor visibilidad, puede usar '!!(...)':

id=USUARIO01 ;  nombre_usuario_sasl =~ !!( /^(bob|alice)$/ )  ;  acción=RECHAZAR ¿quién es?

Los atributos de la solicitud se pueden comparar anteponiendo '$$' caracteres, por ejemplo:

id=R-003 ;  nombre_cliente = !! $$nombre_helo      ;  acción=ADVERTIR el helo no coincide con DNS
# o
id=R-003 ;  nombre_cliente = !!($$(nombre_helo))   ;  acción=ADVERTIR el helo no coincide con DNS

Esto solo es válido para valores PCRE (ver lista anterior). La comparación se realizará como una coincidencia exacta sin distinguir mayúsculas y minúsculas. Use la opción '-vv' para depurar.

Estos ítems especiales se restablecerán para cada nueva regla:

rblcount - contiene el número de respuestas de RBL rhsblcount - contiene el número de respuestas de RHSBL matches - contiene el número de elementos coincidentes dnsbltext - contiene la parte TXT del DNS de todas las respuestas de RBL y RHSBL en el formato rbltype:rblname:<txt>; rbltype:rblname:<txt>; ...

Estos elementos especiales se modificarán para cualquier regla coincidente:

request_hits    - contiene los ids de todas las reglas coincidentes

Esto significa que puede ser necesario guardarlos si planea usar estos valores en reglas posteriores:

# establecer valores
id=RBL01 ; rhsblcount=all; rblcount=all
        action=set(HIT_rhls=$$rhsblcount,HIT_rbls=$$rblcount,HIT_txt=$$dnsbltext)
        rbl=list.dsbl.org, bl.spamcop.net, dnsbl.sorbs.net, zen.spamhaus.org
        rhsbl_client=rddn.dnsbl.net.au, rhsbl.ahbl.org, rhsbl.sorbs.net
        rhsbl_sender=rddn.dnsbl.net.au, rhsbl.ahbl.org, rhsbl.sorbs.net
# comparar
id=RBL02 ; HIT_rhls>=1 ; HIT_rbls>=1 ; action=554 5.7.1 bloqueado usando $$HIT_rhls RHSBLs y $$HIT_rbls RBLs [INFO: $$HIT_txt]
id=RBL03 ; HIT_rhls>=2               ; action=554 5.7.1 bloqueado usando $$HIT_rhls RHSBLs [INFO: $$HIT_txt]
id=RBL04 ; HIT_rbls>=2               ; action=554 5.7.1 bloqueado usando $$HIT_rbls RBLs [INFO: $$HIT_txt]

ARCHIVOS

Desde postfwd1 v1.15 y postfwd3 v0.18, las listas de elementos largos se pueden almacenar en archivos separados:

id=R001 ;  ccert_fingerprint==file:/etc/postfwd/wl_ccerts ;  action=DUNNO

postfwd3 leerá una lista de elementos (un elemento por línea) de /etc/postfwd/wl_ccerts. Se permiten comentarios:

# cliente1
11:22:33:44:55:66:77:88:99
# cliente2
22:33:44:55:66:77:88:99:00
# cliente3
33:44:55:66:77:88:99:00:11

Para usar tablas existentes en formato clave=valor, puede usar:

id=R001 ;  ccert_fingerprint==table:/etc/postfwd/wl_ccerts ;  action=DUNNO

Esto ignorará el valor de la mano derecha. Los elementos se pueden mezclar:

id=R002 ;  action=REJECT
        client_name==unknown
        client_name==file:/etc/postfwd/blacklisted

y para elementos que no son pcre (separados por comas):

id=R003 ;  action=REJECT
        client_address==10.1.1.1, file:/etc/postfwd/blacklisted
id=R004 ;  action=REJECT
        rbl=myrbl.home.local, zen.spamhaus.org, file:/etc/postfwd/rbls_changing

Puede verificar su configuración con la opción --show_config en la línea de comandos:

# postfwd3 --showconfig --rule='action=DUNNO; client_address=10.1.0.0/16, file:/etc/postfwd/wl_clients, 192.168.2.1'

debería dar algo como:

Rule   0: id->"R-0"; action->"DUNNO"; client_address->"=;10.1.0.0/16, =;194.123.86.10, =;186.4.6.12, =;192.168.2.1"

Si no se puede leer un archivo, se ignorará:

# postfwd3 --showconfig --rule='action=DUNNO; client_address=10.1.0.0/16, file:/etc/postfwd/wl_clients, 192.168.2.1'
[LOG warning]: error: file /etc/postfwd/wl_clients not found - file will be ignored ?
Rule   0: id->"R-0"; action->"DUNNO"; client_address->"=;10.1.0.0/16, =;192.168.2.1"

Los elementos de archivo se evalúan en la etapa de configuración. Por lo tanto, postfwd3 necesita ser recargado si un archivo ha cambiado.

Si desea especificar un archivo que se recargará por cada solicitud, puede usar lfile: y ltable:

id=R001; client_address=lfile:/etc/postfwd/client_whitelist; action=dunno

Esto verificará la hora de modificación de /etc/postfwd/client_whitelist cada vez que se evalúe la regla y la recargará según sea necesario. Por supuesto, esto podría aumentar la carga del sistema, así que úselo con precaución.

La opción --showconfig ilustra la diferencia:

## evaluado en la etapa de configuración
# postfwd3 --nodaemon -L --rule='client_address=table:/etc/postfwd/clients; action=dunno' -C
Rule   0: id->"R-0"; action->"dunno"; client_address->"=;1.1.1.1, =;1.1.1.2, =;1.1.1.3"
## evaluado para cualquier coincidencia de regla
# postfwd3 --nodaemon -L --rule='client_address=ltable:/etc/postfwd/clients; action=dunno' -C
Rule   0: id->"R-0"; action->"dunno"; client_address->"=;ltable:/etc/postfwd/clients"

Los archivos pueden referirse a otros archivos. Lo siguiente es válido.

-- ARCHIVO /etc/postfwd/rules.cf --
id=R01; client_address=file:/etc/postfwd/clients_master.cf; action=DUNNO
-- ARCHIVO /etc/postfwd/clients_master.cf --
192.168.1.0/24
file:/etc/postfwd/clients_east.cf
file:/etc/postfwd/clients_west.cf
-- ARCHIVO /etc/postfwd/clients_east.cf --
192.168.2.0/24
-- ARCHIVO /etc/postfwd/clients_west.cf --
192.168.3.0/24

Tenga en cuenta que actualmente no hay detección de bucles (/a/file llama a /a/file) y que esta función solo está disponible con postfwd1 v1.15 y postfwd3 v0.18 y superior.

ACCIONES

General

Las acciones se ejecutarán cuando todos los elementos de la regla hayan coincidido con una solicitud (o al menos uno de cualquier lista de elementos). Puede hacer referencia a los atributos de la solicitud anteponiendo $$ caracteres, como:

id=R-003; client_name = !!$$helo_name; action=WARN helo '$$helo_name' does not match DNS '$$client_name'
# o
id=R-003; client_name = !!$$helo_name; action=WARN helo '$$(helo_name)' does not match DNS '$$(client_name)'

acciones de postfix

Las acciones se responderán a postfix como resultado de las solicitudes de delegación de políticas. Cualquier acción que postfix entienda está permitida: consulte "man 5 access" o http://www.postfix.org/access.5.html para obtener una descripción. Si no se especifica ninguna acción, se utilizará la acción postfix WARN, que simplemente registra el evento, para la regla correspondiente.

postfwd3 devolverá dunno si ha llegado al final del conjunto de reglas y ninguna regla ha coincidido. Esto se puede cambiar colocando una última regla que contenga solo una declaración de acción:

...
action=dunno ; sender=@domain.local     # el remitente está bien
action=reject                           # denegar por defecto

acciones de postfwd3

Las acciones de postfwd3 controlan el comportamiento del programa. Actualmente, puede especificar lo siguiente:

jump (<id>)
salta a la regla con id <id>, úselo para omitir ciertas reglas.
puede saltar hacia atrás, ¡pero recuerde que actualmente no hay detección de bucles!
los saltos a ids inexistentes se omitirán.
score (<puntuación>)
la puntuación de la solicitud se modificará por la <puntuación> especificada,
que debe ser un valor de punto flotante. el modificador puede ser:
        +n.nn   suma n.nn a la puntuación actual
        -n.nn   resta n.nn de la puntuación actual
        *n.nn   multiplica la puntuación actual por n.nn
        /n.nn   divide la puntuación actual por n.nn
        =n.nn   establece la puntuación actual en n.nn
si la puntuación excede el máximo establecido por la opción --scores (ver LÍNEA
DE COMANDOS) o el elemento de puntuación (ver ELEMENTOS), se devolverá la acción
definida para este caso (por defecto: 5.0=>"REJECT postfwd3 score exceeded").
set (<elemento>=<valor>,<elemento>=<valor>,...)
este comando le permite insertar o anular atributos de solicitud, que luego pueden
compararse con su conjunto de reglas posterior. úselo para acelerar comparaciones
repetidas con grandes listas de elementos.
consulte la sección EJEMPLOS para obtener más información. puede separar varios
pares clave=valor con caracteres ",".
rate (<elemento>/<max>/<tiempo>/<acción>)
este comando crea un contador para el <elemento> dado, que se incrementará cada vez que
llegue una solicitud que lo contenga. si excede <max> dentro de <tiempo> segundos,
devolverá <acción> a postfix.
los contadores de tasa son muy rápidos ya que se ejecutan antes de que se analice el conjunto de reglas.
tenga en cuenta que <acción> se limitó a acciones de postfix (sin acciones de postfwd) para las
versiones de postfwd <1.33.
    # no más de 3 solicitudes por 5 minutos
    # del mismo cliente "desconocido"
    id=RATE01 ;  client_name==unknown
       action=rate(client_address/3/300/450 4.7.1 lo siento, máximo 3 solicitudes por 5 minutos)
size (<elemento>/<max>/<tiempo>/<acción>)
este comando funciona de manera similar al comando rate(), con la diferencia de que el contador
de tasa se incrementa por el atributo de tamaño de la solicitud. para hacerlo de manera confiable,
debe llamar a postfwd3 desde smtpd_end_of_data_restrictions. si desea estar seguro, podría
verificarlo dentro del conjunto de reglas:
   # límite de tamaño de 1.5 MB por hora por cliente
   id=SIZE01 ;  protocol_state==END-OF-MESSAGE ;  client_address==!!(10.1.1.1)
      action=size(client_address/1572864/3600/450 4.7.1 lo siento, máximo 1.5 MB por hora)
rcpt (<elemento>/<max>/<tiempo>/<acción>)
este comando funciona de manera similar al comando rate(), con la diferencia de que el contador
de tasa se incrementa por el atributo recipient_count de la solicitud. para hacerlo de manera
confiable, debe llamar a postfwd desde smtpd_data_restrictions o smtpd_end_of_data_restrictions.
si desea estar seguro, podría verificarlo dentro del conjunto de reglas:
   # límite de número de destinatarios de 3 por hora por cliente
   id=RCPT01 ;  protocol_state==END-OF-MESSAGE ;  client_address==!!(1.1.1.1)
      action=rcpt(client_address/3/3600/450 4.7.1 lo siento, máximo 3 destinatarios por hora)
rate5321,size5321,rcpt5321 (<elemento>/<max>/<tiempo>/<acción>)
igual que las funciones no-5321 correspondientes, con la diferencia de que la parte local de
las direcciones del remitente o destinatario se evalúan teniendo en cuenta las mayúsculas y
minúsculas según rfc5321. Esto significa que las solicitudes de bob@example.local y BoB@example.local
se tratarán de manera diferente.
groupadd(<nombre_grupo>/<elemento>[/<ttl>])
guarda <elemento> en el grupo dinámico <grupo> para su uso posterior. el objeto se eliminará de ese
grupo después de ttl segundos. si no se establece, postfwd3 utilizará el valor predeterminado
--default_group_ttl [3600s]. ¡Lea el capítulo sobre grupos dinámicos antes de usarlo!
   # agregar client_address al grupo %%blacklisted_hosts
   id=ADDGROUP
        rbl=zen.spamhaus.org,bl.spamcop.net,ix.dnsbl.manitu.net
        action=groupadd(%%blacklisted_hosts/client_address/86400)
groupdel(<nombre_grupo>/<elemento>)
elimina <elemento> del grupo dinámico <grupo>. ¡Lea el capítulo sobre grupos dinámicos antes de usarlo!
   # eliminar un client_address del grupo %%blacklisted_hosts
   id=DELGROUP
        rbl=lists.dnswl.org
        action=groupdel(%%blacklisted_hosts/client_address)
ask (<dirección>:<puerto>[:<ignorar>])
permite delegar la decisión de política a otro servicio de políticas (por ejemplo, postgrey).
el primer y segundo argumento (dirección y puerto) son obligatorios. se puede especificar un
tercer argumento opcional para indicar a postfwd3 que ignore ciertas respuestas y continúe
analizando el conjunto de reglas:
   # ejemplo1: consultar postgrey y devolver su respuesta a postfix
   id=GREY; client_address==10.1.1.1; action=ask(127.0.0.1:10031)
   # ejemplo2: consultar postgrey pero ignorar su respuesta, si coincide con 'DUNNO'
   # y continuar analizando el conjunto de reglas de postfwd
   id=GREY; client_address==10.1.1.1; action=ask(127.0.0.1:10031:^dunno$)
mail(servidor/helo/de/a/asunto/cuerpo)
Este comando está obsoleto. Debería intentar usar la acción sendmail() en su lugar.
Comando de correo muy básico, que envía un mensaje con los argumentos dados. LIMITACIONES:
Básicamente realiza un telnet. No hay autenticación ni TLS disponibles. Además, no rastrea el
estado de notificación y le notificará cada vez que se active la regla correspondiente.
sendmail(ruta_sendmail::de::a::asunto::cuerpo)
Comando de correo, que utiliza una instancia binaria de sendmail existente y envía un mensaje
con los argumentos dados. LIMITACIONES: El comando no rastrea el estado de notificación y le
notificará cada vez que se active la regla correspondiente (lo que podría significar 100 correos
para un m
ail con 100 destinatarios en la etapa RCPT).
wait ()
pausa la ejecución del programa durante  segundos. Úselo para
retrasar o estrangular conexiones.
note ()
simplemente registra la cadena dada y continúa analizando el conjunto de reglas.
si la cadena está vacía, no se registrará nada (noop).
quit ()
termina el programa con el código de salida dado. postfix no
aprecia eso demasiado, así que úselo con cuidado.


Puede hacer referencia a los atributos de la solicitud, como


id=R-HELO ;  helo_name=^[^\.]+$ ;  action=REJECT heló inválido '$$helo_name'

MACROS/ACLS

El uso múltiple de elementos largos o combinaciones de ellos puede ser abreviado mediante macros. Estas deben ir precedidas por '&&' (dos caracteres '&'). Primero, las macros deben definirse de la siguiente manera:

&&RBLS { rbl=zen.spamhaus.org,list.dsbl.org,bl.spamcop.net,dnsbl.sorbs.net,ix.dnsbl.manitu.net; };

Luego, estas pueden usarse en sus reglas, como:

&&RBLS ;  client_name=^unknown$                         ; action=REJECT
&&RBLS ;  client_name=(\d+[\.-_]){4}                    ; action=REJECT
&&RBLS ;  client_name=[\.-_](adsl|dynamic|ppp|)[\.-_]   ; action=REJECT

Las macros también pueden contener acciones:

# definición
&&GONOW { action=REJECT su solicitud provocó que nuestra política de detección de spam rechazara este mensaje. Más información en http://www.domain.local; };
# reglas
&&GONOW ;  &&RBLS ;  client_name=^unknown$
&&GONOW ;  &&RBLS ;  client_name=(\d+[\.-_]){4}
&&GONOW ;  &&RBLS ;  client_name=[\.-_](adsl|dynamic|ppp|)[\.-_]

Las macros también pueden contener otras macros:

# definición
&&RBLS{
        rbl=zen.spamhaus.org
        rbl=list.dsbl.org
        rbl=bl.spamcop.net
        rbl=dnsbl.sorbs.net
        rbl=ix.dnsbl.manitu.net
};
&&DYNAMIC{
        client_name=^unknown$
        client_name=(\d+[\.-_]){4}
        client_name=[\.-_](adsl|dynamic|ppp|)[\.-_]
};
&&GOAWAY { &&RBLS; &&DYNAMIC; };
# reglas
&&GOAWAY ; action=REJECT cliente dinámico y listado en RBL

Básicamente, las macros son sustituciones de texto simples - consulte la sección "PARSER" para más información.

GRUPOS DINÁMICOS

Los grupos dinámicos son objetos de lista. Puede agregar o eliminar elementos y comparar elementos de solicitud con su contenido dentro de su conjunto de reglas. Los grupos se guardan de forma persistente para futuras solicitudes. De esta manera, puede guardar información para su uso posterior. Cada elemento de un grupo tiene un valor de tiempo de vida (time-to-live).

Los nombres de grupo deben ir precedidos por caracteres dobles '%', como %%GROUPNAME:

# añadir client_address al grupo %%BLACKLISTED, si se envía a spamtrap
id=SPAMTRAP; recipient==spamtrap@domain.local; action=groupadd(%%BLACKLISTED/client_address)
# rechazar cualquier solicitud de client_address en el grupo %%BLACKLISTED
id=BLACKLISTED; client_address=%%BLACKLISTED; action=REJECT

La función groupadd() recibe los siguientes argumentos. El valor <ttl> es opcional. Si no se especifica, postfwd3 usará el valor predeterminado --default_group_ttl [300s]:

groupadd ( <NombreGrupo> / <elemento> [ / <ttl> ] )

postfwd guardará estos datos en la siguiente estructura:

%Group_Cache -> %<NombreGrupo> -> $<elemento> = <ttl>

La función groupdel() elimina un elemento de un grupo:

groupdel ( <NombreGrupo> / <elemento> )

Los miembros caducados se eliminarán en la etapa de limpieza después de --cleanup_groups <i> segundos.

Para comparar solicitudes con grupos dinámicos, estos deben ser referenciados por caracteres '%%' precedentes:

<elemento> = %%<NombreGrupo>

Los grupos vacíos siempre comparan como falso. El siguiente conjunto de reglas es posible:

# permitir cualquier solicitud de client_address en el grupo %%WHITELISTED
id=WHITEGROUP; client_address=%%WHITELISTED; action=DUNNO
# rechazar cualquier solicitud de client_address en el grupo %%BLACKLISTED
id=BLACKGROUP; client_address=%%BLACKLISTED; action=REJECT
# ... otras reglas ...
# ... archivo de lista blanca ...
id=W_TRUST; action=set(WHITE=1)
    client_address=file:/etc/postfwd/whitelist_networks
# ... dns de lista blanca ...
id=W_DNSWL; action=set(WHITE=1)
    rbl=list.dnswl.org
# ... -> añadirla a la lista blanca por un día y permitir la solicitud
id=W_GROUP; WHITE==1
    action=groupadd(%%WHITELISTED/client_address/86400)
    action=DUNNO
# ... o poner en lista negra enviando a spamtrap ...
id=B_SPAMTRAP; action=set(BLACK=1)
    recipient==spamtrap@domain.local
# ... o poner en lista negra por dns ...
id=B_DNSBL; action=set(BLACK=1)
    rbl=zen.spamhaus.org
# ... -> añadirla al grupo BLACKLISTED por 1 hora y rechazar
id=B_GROUP; BLACK==1
    action=groupadd(%%BLACKLISTED/client_address/3600)
    action=REJECT

Limitaciones

Actualmente, los grupos dinámicos se mantienen en memoria. Por defecto, postfwd3 solo aceptará un máximo de 999999 miembros en un grupo. Para desactivar este límite, establezca --group_maxitems en '-1'.

Con la personalidad PreFork, debe tener en cuenta que esta información debe compartirse a través del demonio de caché.

En resumen: no permita que estas listas se vuelvan excesivamente grandes a menos que tenga suficiente capacidad del sistema para hacerlo. Si es necesario, ajuste su configuración estableciendo el <ttl> y --group_maxitems.

PLUGINS

Descripción

La interfaz de plugins le permite definir sus propias verificaciones y mejorar la funcionalidad de postfwd. ¡No dude en compartir cosas útiles!

Advertencia

Tenga en cuenta que la interfaz de plugins todavía está en fase de desarrollo. ¡Pruebe sus plugins cuidadosamente, ya que los errores pueden hacer que postfwd falle! También se permite anular atributos o funciones integradas, pero asegúrese de que sabe lo que hace, ya que algunos de ellos se utilizan internamente.

Tenga en cuenta la seguridad al acceder a recursos sensibles y ¡nunca, nunca ejecute postfwd como usuario privilegiado! Tampoco confíe nunca en su entrada (¡especialmente nombres de host y direcciones de correo electrónico!).

ITEMS

Los plugins de elementos son subrutinas de Perl que integran atributos adicionales a las solicitudes antes de que se evalúen contra el conjunto de reglas de postfwd, como cualquier otro elemento del protocolo de delegación de políticas. Esto le permite crear sus propias verificaciones.

Los plugin-items no se pueden usar de forma selectiva. Estas funciones se ejecutarán para cada solicitud que reciba postfwd, así que tenga en cuenta el rendimiento.

SYNOPSIS: postfwd_items_plugin{<nombre>}($solicitud)

significa que su subrutina, llamada <nombre>, tiene acceso a una referencia de hash llamada $solicitud, que contiene todos los atributos de la solicitud, como $solicitud->{client_name} y guarda valores de la siguiente forma:

guardar: $resultado->{<item>} = <valor>

esto crea el nuevo elemento <item> que contiene <valor>, el cual se integrará en la solicitud de delegación de políticas y, por lo tanto, podrá ser utilizado en el conjunto de reglas de postfwd.

# NO eliminar la siguiente línea
%postfwd_items_plugin = (
        # EJEMPLOS - integrados en postfwd. no es necesario activarlos aquí.

                # permite verificar la versión de postfwd en el conjunto de reglas
                "version" => sub {
                        my($solicitud) = shift;
                        $solicitud->{version} => $NAME." ".$VERSION,
                },

                # dominio del remitente y dominio del destinatario
                "address_parts" => sub {
                        my($solicitud) = shift;
                        $solicitud->{sender} =~ /@([^@]*)$/;
                        $solicitud->{sender_domain} = ($1 || '');
                        $solicitud->{recipient} =~ /@([^@]*)$/;
                        $solicitud->{recipient_domain} = ($1 || '');
                },
# NO eliminar la siguiente línea
);

COMPARAR

Los plugins de comparación le permiten definir cómo se deben comparar sus nuevos elementos con el conjunto de reglas. Estos son opcionales. Si no especifica uno, se utilizará el predeterminado (== para coincidencia exacta, =~ para PCRE, ...).

SYNOPSIS:  <item> => sub { return &{$postfwd_compare{<tipo>}}(@_); },
# NO eliminar la siguiente línea
%postfwd_compare_plugin = (
        EJEMPLOS - integrados en postfwd. no es necesario activarlos aquí.

                # Ejemplo simple
                # SYNOPSIS:  <resultado> = <item> (return &{$postfwd_compare{<tipo>}}(@_))
                "client_address"  => sub { return &{$postfwd_compare{cidr}}(@_); },
                "size"            => sub { return &{$postfwd_compare{numeric}}(@_); },
                "recipient_count" => sub { return &{$postfwd_compare{numeric}}(@_); },

                # Ejemplo complejo
                # SYNOPSIS:  <resultado> = <item>(<operador>, <valor de regla>, <valor de solicitud>, <solicitud>)
                "numeric" => sub {
                        my($cmp,$val,$myitem,$request) = @_;
                        my($myresult) = undef;  $myitem ||= "0"; $val ||= "0";
                        if ($cmp eq '==') {
                                $myresult = ($myitem == $val);
                        } elsif ($cmp eq '=<') {
                                $myresult = ($myitem <= $val);
                        } elsif ($cmp eq '=>') {
                                $myresult = ($myitem >= $val);
                        } elsif ($cmp eq '<') {
                                $myresult = ($myitem < $val);
                        } elsif ($cmp eq '>') {
                                $myresult = ($myitem > $val);
                        } elsif ($cmp eq '!=') {
                                $myresult = not($myitem == $val);
                        } elsif ($cmp eq '!<') {
                                $myresult = not($myitem <= $val);
                        } elsif ($cmp eq '!>') {
                                $myresult = not($myitem >= $val);
                        } else {
                                $myresult = ($myitem >= $val);
                        };
                        return $myresult;
                },
# NO eliminar la siguiente línea
);

LINEA DE COMANDOS

Conjunto de reglas

Los siguientes argumentos se utilizan para especificar la fuente del conjunto de reglas de postfwd3. Esto significa que al menos uno de los siguientes es requerido para que postfwd3 funcione.

-f, --file <archivo>
Lee las reglas de <archivo>. Consulte la sección CONFIGURACIÓN para obtener
más información.
-r, --rule <regla>
Añade <regla> al conjunto de reglas. Recuerde que es posible que tenga que
poner entre comillas las cadenas que contengan espacios en blanco o
caracteres de shell.

Configuración

-F, --loadsettings <archivo>
Carga la configuración del programa desde <archivo>. los datos deben estar en
formato Data::Dumper. Lea la sección CONFIGURACIÓN para obtener más
información.
--savesettings <archivo>
Guarda la configuración del programa en <archivo> en formato Data::Dumper.
Lea la sección CONFIGURACIÓN para obtener más información.
--showsettings
Exporta la configuración del programa en formato Data::Dumper a la salida
estándar. Esta salida se puede guardar en un archivo y utilizar más tarde con
la opción --loadsettings.

Puntuación

-s, --scores <val>=<accion>
Devuelve <accion> a postfix, cuando la puntuación de la solicitud excede
<val>

Se permite el uso múltiple. Simplemente encadene sus argumentos, como:

postfwd3 -r "<elemento>=<valor>;accion=<resultado>" -f <archivo> -f <archivo> ...
  o
postfwd3 --scores 4.5="ADVERTIR puntuación alta" --scores 5.0="RECHAZAR puntuación demasiado alta de postfwd3" ...

En caso de múltiples puntuaciones, se aplicará la coincidencia más alta. El orden de los argumentos se reflejará en el conjunto de reglas de postfwd3.

Red

postfwd3 puede ejecutarse como un demonio para que escuche en la red solicitudes entrantes. Los siguientes argumentos controlarán su comportamiento en este caso.

-d, --daemon, --nodaemon
postfwd3 se ejecutará como un demonio y escuchará en la red consultas
entrantes (por defecto 127.0.0.1:10045). Utilice --nodaemon para mantener
postfwd3 ejecutándose en primer plano.
-i, --interface <disp>
Vincula postfwd3 a la interfaz especificada (por defecto 127.0.0.1).
-p, --port <puerto>
postfwd3 escucha en el puerto especificado (por defecto tcp/10045).
--proto <tipo>
El tipo de protocolo para el socket de postfwd. Actualmente puede usar 'tcp'
o 'unix' aquí.
Para usar postfwd3 con un socket de dominio Unix, ejecútelo de la siguiente
manera:
    postfwd3 --proto=unix --port=/algún/lugar/postfwd.socket
-u, --user <nombre>
Cambia el usuario real y efectivo a <nombre>.
-g, --group <nombre>
Cambia el grupo real y efectivo a <nombre>.
--personality <tipo>
Tipo de servidor de políticas, permite 'PreFork' o 'Multiplex'.
Esta opción anula --autopersonality.
--v1
establece la personalidad en 'Multiplex'
Esta opción anula --autopersonality.
--v2
establece la personalidad en 'PreFork'
Esta opción anula --autopersonality.
--autopersonality
postfwd3 determina la personalidad por el nombre del programa:
   * 'Multiplex' para 'postfwd' o 'postfwd1'
   * 'PreFork' para 'postfwd2'
puede deshabilitar esto usando --noautopersonality o
explicitamente usando --personality, --v1 o --v2
--umask <máscara>
Cambia la máscara de permisos de archivo del proceso maestro (archivo pid).
Atención: Esto es umask, no chmod - debe especificar los bits que
no deben aplicarse. Por ejemplo: umask 077 equivale a chmod 700.
--cache_umask <máscara>
Cambia la máscara de permisos de archivo del proceso de caché (socket de
dominio Unix).
--server_umask <máscara>
Cambia la máscara de permisos de archivo del proceso del servidor (socket de
dominio Unix).
-R, --chroot <ruta>
Realiza un chroot del proceso a la ruta especificada.
¡Por favor, consulte http://postfwd.org/postfwd3-chroot.html antes de
usarlo!
--pidfile <ruta>
El ID del proceso se guardará en el archivo especificado.
--facility <f>
establece la instalación de syslog, por defecto es 'mail'
--socktype <s>
establece el tipo de socket de Sys::Syslog a 'native', 'inet' o 'unix'.
Por defecto es la detección automática según la versión del módulo y el SO.
-l, --logname <etiqueta>
Etiqueta los mensajes de syslog. Útil cuando se ejecutan
múltiples instancias de postfwd.
--loglen <int>
Trunca cualquier mensaje de syslog después de <int> caracteres.

Plugins

--plugins <archivo>
Carga los plugins de postfwd desde el archivo. Consulte http://postfwd.org/postfwd.plugins
o el archivo plugins.postfwd.sample que está disponible en el tarball para
más información.

Argumentos opcionales

Estos parámetros influyen en la forma en que funciona postfwd3. Cualquiera de ellos se puede combinar.

 -v, --verbose
 El registro detallado muestra mucha información útil, pero puede hacer que
 sus archivos de registro crezcan notablemente. Úselo con precaución.
 Establezca la opción dos veces (-vv) para obtener más información (registra
 todos los atributos de la solicitud).
 -c, --cache <int>    (por defecto=600)
 Tiempo de espera para la caché de solicitudes, los resultados para
 solicitudes idénticas se almacenarán en caché hasta que la configuración se
 recargue o expire este tiempo (en segundos).
 Un valor de 0 deshabilita esta función.
 --cache-no-size
 Ignora el atributo de tamaño para las comparaciones de caché, lo que
 conducirá a mejores tasas de aciertos de caché. Debería establecer esta
 opción si no utiliza el elemento de tamaño en su conjunto de reglas.
 --cache-no-sender
 Ignora la dirección del remitente para las comparaciones de caché, lo que
 conducirá a mejores tasas de aciertos de caché. Debería establecer esta
 opción si no utiliza el elemento del remitente en su conjunto de reglas.
 --cache-rdomain-only 
 Esto eliminará la parte local de la dirección del destinatario antes de
 rellenar la caché. Esto puede aumentar considerablemente las tasas de
 aciertos de caché.
 --cache-rbl-timeout <timeout>     (por defecto=3600)
 Este valor predeterminado se utilizará como tiempo de espera en segundos para
 los elementos de caché rbl, si no se especifican en el conjunto de reglas.
 --cache-rbl-default <patrón>    (por defecto=^127\.0\.0\.\d+$)
 Coincide con <patrón> con las respuestas rbl/rhsbl (expresión regular) si no
 se especifican en el conjunto de reglas.
 --cacheid <elemento>, <elemento>, ...
 Esta lista de atributos de solicitud separados por comas se utilizará para
 construir el identificador de caché de la solicitud. Úselo solo si sabe
 exactamente lo que está haciendo. Si, por ejemplo, solo usa postfwd3 para
 el control de RBL/RHSBL, puede configurarlo en
         postfwd3 --cache=3600 --cacheid=nombre_cliente,direccion_cliente
 Esto aumenta la eficiencia del almacenamiento en caché y mejora el rendimiento
 de postfwd.
 Advertencia: ¡Debería listar todos los elementos aquí que se utilizan en su
 conjunto de reglas!
 --cacheid_md5, --nocacheid_md5    (por defecto=1)
 El cacheid se creará con una suma md5 de los elementos de la solicitud.
 --cleanup-requests <intervalo>    (por defecto=600)
 La caché de solicitudes se buscará para ver los elementos caducados después de
 este <intervalo> en segundos. Es un valor mínimo. El proceso de limpieza solo
 tendrá lugar cuando llegue una nueva solicitud.
 --cleanup-rbls <intervalo>    (por defecto=600)
 La caché de rbl se buscará para ver los elementos caducados después de
 este <intervalo> en segundos. Es un valor mínimo. El proceso de limpieza solo
 tendrá lugar cuando llegue una nueva solicitud.
 --cleanup-rates <intervalo>    (por defecto=600)
 La caché de tasas se buscará para ver los elementos caducados después de
 este <intervalo> en segundos. Es un valor mínimo. El proceso de limpieza solo
 tendrá lugar cuando llegue una nueva solicitud.

 Deshabilita todas las comprobaciones basadas en DNS, como las comprobaciones

REFRESH

En modo demonio, postfwd3 recarga su conjunto de reglas después de recibir una señal HUP. Consulte la descripción del interruptor '-I' para tener su configuración actualizada para cada solicitud que postfwd3 recibe.

EJEMPLOS

## listas blancas
# 1. redes 192.168.1.0/24, 192.168.2.4
# 2. nombres de cliente *.gmx.net y *.gmx.de
# 3. remitente *@someshop.tld desde 11.22.33.44
id=WL001; action=dunno ; client_address=192.168.1.0/24, 192.168.2.4
id=WL002; action=dunno ; client_name=\.gmx\.(net|de)$
id=WL003; action=dunno ; sender=@someshop\.tld$ ; client_address=11.22.33.44
## control TLS
# 1. *@authority.tld solo con huella digital TLS correcta
# 2. *@secret.tld solo con tamaños de clave >=64
id=TL001; action=dunno ; sender=@authority\.tld$ ; ccert_fingerprint=AA:BB:CC..
id=TL002; action=REJECT huella digital TLS incorrecta ; sender=@authority\.tld$
id=TL003; action=REJECT clave TLS < 64 ; sender=@secret\.tld$ ; encryption_keysize=64
## Comprobaciones combinadas de RBL
# Esto rechazará el correo si
# 1. listado en ix.dnsbl.manitu.net
# 2. listado en zen.spamhaus.org (sbl y xbl, tiempo de espera de caché DNS 1200s en lugar de 3600s)
# 3. listado en min 2 de bl.spamcop.net, list.dsbl.org, dnsbl.sorbs.net
# 4. listado en bl.spamcop.net y uno de rhsbl.ahbl.org, rhsbl.sorbs.net
id=RBL01 ; action=REJECT listado en ix.dnsbl.manitu.net ; rbl=ix.dnsbl.manitu.net
id=RBL02 ; action=REJECT listado en zen.spamhaus.org ; rbl=zen.spamhaus.org/127.0.0.[2-8]/1200
id=RBL03 ; action=REJECT listado en demasiadas RBLs ; rblcount=2 ; rbl=bl.spamcop.net, list.dsbl.org, dnsbl.sorbs.net
id=RBL04 ; action=REJECT comprobación combinada RBL+RHSBL ; rbl=bl.spamcop.net ; rhsbl=rhsbl.ahbl.org, rhsbl.sorbs.net
## Tamaño del mensaje (requiere que message_size_limit se establezca en 30000000)
# 1. 30MB para sistemas en *.customer1.tld
# 2. 20MB para el usuario SASL joejob
# 3. 10MB predeterminado
id=SZ001; protocol_state==END-OF-MESSAGE; action=DUNNO; size<=30000000 ; client_name=\.customer1.tld$
id=SZ002; protocol_state==END-OF-MESSAGE; action=DUNNO; size<=20000000 ; sasl_username==joejob
id=SZ002; protocol_state==END-OF-MESSAGE; action=DUNNO; size<=10000000
id=SZ100; protocol_state==END-OF-MESSAGE; action=REJECT mensaje demasiado grande

##
## Tenga en cuenta que postfwd no incluye greylisting. Esta configuración requiere un
## servicio postgrey en ejecución en el puerto 10031 y la siguiente clase
## de restricción de postfix en su main.cf:
##
##      smtpd_restriction_classes = check_postgrey, ...
##      check_postgrey = check_policy_service inet:127.0.0.1:10031

# 3. El cliente proviene de varios dominios de acceso telefónico

id=GR002; action=check_postgrey ; client_name=^unknown$

 time=03:00:00 - 04:00:00
};
# reglas
id=COMBINED ; &&RBLS ; &&DYNAMIC ; action=REJECT cliente dinámico y listado en RBL
id=MAINTENANCE ; &&MAINTENANCE ; action=DEFER tiempo de mantenimiento - por favor, vuelva a intentarlo más tarde

# ahora con el comando set(), tenga en cuenta que las listas de
# elementos largas no tienen que compararse dos veces
id=RBL01 ; &&RBLS ; action=set(HIT_rbls=1)
id=HELO01 ; &&BAD_HELO ; action=set(HIT_helo=1)
id=DYNA01 ; &&DYNAMIC ; action=set(HIT_dyna=1)
id=REJECT01 ; HIT_rbls==1 ; HIT_helo==1 ; action=REJECT por favor vea http://some.org/info?reject=01 para más información
id=REJECT02 ; HIT_rbls==1 ; HIT_dyna==1 ; action=REJECT por favor vea http://some.org/info?reject=02 para más información

ANALIZADOR

Configuración

El conjunto de reglas de postfwd3 se puede especificar en la línea de comandos (opción -r) o leer desde archivos (-f). Se conservará el orden de sus argumentos. Debe verificar el analizador con el interruptor -C | --showconfig en la línea de comandos antes de aplicar una nueva configuración. La siguiente llamada:

postfwd3 --showconfig \
 -r "id=TEST; recipient_count=100; action=WARN correo con 100+ destinatarios" \
 -f /etc/postfwd.cf \
 -r "id=DEFAULT; action=dunno";

producirá la siguiente salida:

Regla   0: id->"TEST" action->"WARN correo con 100+ destinatarios"; recipient_count->"100"
...
... <contenido de /etc/postfwd.cf> ...
...
Regla <n>: id->"DEFAULT" action->"dunno"

Múltiples elementos del mismo tipo se añadirán a listas (ver la sección "ELEMENTOS" para más información):

postfwd3 --showconfig \
 -r "client_address=192.168.1.0/24; client_address=172.16.26.32; action=dunno"

resultará en:

Regla   0: id-&quo
t;R-0"; acción->"no sé"; dirección_cliente->"192.168.1.0/24, 172.16.26.32"

Las macros se evalúan en la etapa de configuración, lo que significa que

postfwd3 --showconfig \
        -r "&&RBLS { rbl=bl.spamcop.net; client_name=^unknown$; };" \
        -r "id=RBL001; &&RBLS; action=REJECT listed on spamcop and bad rdns";

resultará en:

Regla   0: id->"RBL001"; acción->"REJECT listed on spamcop and bad rdns"; rbl->"bl.spamcop.net"; client_name->"^unknown$"

Procesamiento de solicitudes

Cuando llega una solicitud de delegación de política, se comparará con el conjunto de reglas de postfwd. Para inspeccionar el procesamiento en detalle, debe aumentar la verbosidad utilizando el interruptor "-v" o "-vv". "-L" redirige los mensajes de registro a stdout.

Manteniendo el orden general del conjunto de reglas, los elementos se compararán en orden aleatorio, lo que básicamente significa que

id=R001; acción=no sé; dirección_cliente=192.168.1.1; remitente=bob@alice.local

es igual a

id=R001; remitente=bob@alice.local; dirección_cliente=192.168.1.1; acción=no sé

Las listas se evaluarán en el orden especificado. Esto permite colocar expresiones más rápidas primero:

postfwd3 -vv --cmd -r "id=RBL001; rbl=localrbl.local zen.spamhaus.org; action=REJECT" /some/where/request.sample

produce lo siguiente

[LOGS info]: compare rbl: "remotehost.remote.net[68.10.1.7]"  ->  "localrbl.local"
[LOGS info]: count1 rbl:  "2"  ->  "0"
[LOGS info]: query rbl:   localrbl.local 7.1.10.68 (7.1.10.68.localrbl.local)
[LOGS info]: count2 rbl:  "2"  ->  "0"
[LOGS info]: match rbl:   FALSE
[LOGS info]: compare rbl: "remotehost.remote.net[68.10.1.7]"  ->  "zen.spamhaus.org"
[LOGS info]: count1 rbl:  "2"  ->  "0"
[LOGS info]: query rbl:   zen.spamhaus.org 7.1.10.68 (7.1.10.68.zen.spamhaus.org)
[LOGS info]: count2 rbl:  "2"  ->  "0"
[LOGS info]: match rbl:   FALSE
[LOGS info]: Acción: no sé

El operador de negación !!(<valor>) tiene la mayor prioridad y, por lo tanto, se evaluará primero. Luego se realizan las sustituciones de variables:

postfwd3 -vv --cmd -r "id=TEST; action=REJECT; client_name=!!($$heloname)" /some/where/request.sample

dará

[LOGS info]: compare client_name:     "unknown"  ->  "!!($$helo_name)"
[LOGS info]: negate client_name:      "unknown"  ->  "$$helo_name"
[LOGS info]: substitute client_name:  "unknown"  ->  "english-breakfast.cloud8.net"
[LOGS info]: match client_name:  TRUE
[LOGS info]: Acción: REJECT

Evaluación del conjunto de reglas

Una regla coincide cuando todos los elementos (o al menos un elemento de una lista para cada elemento) han coincidido. Tan pronto como un elemento (o todos los elementos de una lista) no se compara con el atributo de la solicitud, el analizador saltará a la siguiente regla en el conjunto de reglas de postfwd3.

Si una regla coincide, hay dos opciones:

* La regla devuelve la acción de postfix (no sé, rechazar, ...) El analizador detiene el procesamiento de reglas y devuelve la acción a postfix. Otras reglas no se evaluarán.

* La regla devuelve la acción de postfwd3 (jump(), note(), ...) El analizador evalúa la acción dada y continúa con la siguiente regla (excepto para las acciones jump() o quit() - consulte la sección "ACCIONES" para obtener más información). No se enviará nada a postfix.

Si ninguna regla coincidió y se alcanza el final del conjunto de reglas, postfwd3 devolverá "no sé" sin registrar nada, a menos que esté en modo detallado. Puede colocar una última regla de captura para cambiar ese comportamiento:

... <tus reglas> ...
id=DEFAULT ;  action=no sé

registrará cualquier solicitud que pase por el conjunto de reglas sin haber activado una regla anterior.

CONFIGURACIÓN

Desde la versión postfwd3 2.00-pre6, la configuración del programa se puede obtener de un archivo. La información debe ser analizable por la función eval() de perl. Se permiten comentarios:

# configuración de ejemplo para postfwd3
{
   # habilitar registro detallado
   verbose => 1,
   # usuario y grupo para postfwd
   base => {
       group => 'postfw',
       user => 'postfw'
   },
   # configuración del servidor
   server => {
       proto => 'tcp',
       host => '127.0.0.1',
       port => '10099'
   }
}

postfwd3 también puede exportar la configuración del programa en ese formato utilizando Data::Dumper.

# mostrar configuración
postfwd3 --showsettings
# guardar configuración en archivo
postfwd3 --savesettings=/path/to/file
# leer configuración de archivo
postfwd3 --loadsettings=/path/to/file

Se permite el uso múltiple de --loadsettings o la forma corta -F. Se mantendrá el orden. Los argumentos de la línea de comandos anulan la configuración obtenida de un archivo.

# cargar configuración base, anular con configuración de nodo y establecer puerto y registro detallado
postfwd3 -v -p 10050 -F /path/to/basefile -F /path/to/nodefile

Se distribuyen ejemplos de archivos de configuración en la carpeta etc/- del tarball de postfwd3.

DEPURACIÓN

Para depurar pasos especiales del analizador, el interruptor '--debug' toma una lista de clases de depuración. Desde postfwd3 2.00, la lista de clases de depuración disponibles se puede obtener ejecutando:

postfwd3 --debugclasses

INTEGRACIÓN

Integración a través del modo demonio

La forma común de usar postfwd3 es iniciarlo como un demonio, escuchando en un puerto tcp especificado. postfwd3 generará múltiples procesos hijos que se comunicarán con una caché principal. Esta es la forma preferida de usar postfwd3 en entornos de alto volumen. Inicie postfwd3 con los siguientes parámetros:

postfwd3 -d -f /etc/postfwd.cf -i 127.0.0.1 -p 10045 -u nobody -g nobody -S

Para una caché eficiente, debe verificar si puede usar las opciones --cacheid, --cache-rdomain-only, --cache-no-sender y --cache-no-size.

Ahora verifique sus registros del sistema (instalación predeterminada "mail") para una línea como:

Aug  9 23:00:24 mail postfwd[5158]: postfwd3 n.nn ready for input

y use `netstat -an|grep 10045` para verificar algo como

tcp  0  0  127.0.0.1:10045  0.0.0.0:*  LISTEN

Si todo funciona, abra su main.cf de postfix e inserte lo siguiente

127.0.0.1:10045_time_limit      = 3600                                          <--- integración
smtpd_recipient_restrictions    = permit_mynetworks                             <--- recomendado
                                  reject_unauth_destination                     <--- recomendado
                                  check_policy_service inet:127.0.0.1:10045     <--- integración

Recargue su configuración con `postfix reload` y observe sus registros. Si funciona, debería ver líneas como las siguientes en su registro de correo:

Aug  9 23:01:24 mail postfwd[5158]: rule=22, id=ML_POSTFIX, client=english-breakfast.cloud9.net[168.100.1.7], sender=owner-postfix-users@postfix.tld, recipient=someone@domain.local, helo=english-breakfast.cloud9.net, proto=ESMTP, state=RCPT, action=dunno

Si desea verificar elementos de tamaño o número de destinatarios, debe integrar postfwd3 en smtp_data_restrictions o smtpd_end_of_data_restrictions. Por supuesto, también puede especificar una clase de restricción y usarla en sus tablas de acceso. Primero cree un archivo /etc/postfix/policy que contenga:

domain1.local           postfwdcheck
domain2.local           postfwdcheck
...

Luego haga postmap de ese archivo (`postmap hash:/etc/postfix/policy`), abra su main.cf y escriba

# Clases de restricción
smtpd_restriction_classes       = postfwdcheck, <más>...                          <--- integración
postfwdcheck                    = check_policy_service inet:127.0.0.1:10045             <--- integración
127.0.0.1:10045_time_limit      = 3600                                                  <--- integración
smtpd_recipient_restrictions    = permit_mynetworks,                                    <--- recomendado
                                  reject_unauth_destination,                            <--- recomendado
                                  ...                                                   <--- opcional
                                  check_recipient_access hash:/etc/postfix/policy,      <--- integración
                                  ...                                                   <--- opcional

Recargue postfix y observe sus registros.

postfwd se puede ejecutar en un contenedor de docker. Las opciones relevantes son --nodaemon y --stdout. Puede encontrar más información en doc/docker.html incluido o en http://postfwd.org/docker.

PRUEBAS

Primero debe crear un conjunto de reglas (ver sección Configuración). Verifíquelo con

postfwd3 -f /etc/postfwd.cf -C

Hay una solicitud de política de ejemplo distribuida con postfwd, llamada 'request.sample'. Simplemente cámbiela para que cumpla con sus requisitos y use

postfwd3 --cmd -f /etc/postfwd.cf request.sample

Debería obtener una respuesta como

action=<loqueseahaconfigurado>

Para pruebas de red, uso netcat:

nc 127.0.0.1 10045 <request.sample

para enviar una solicitud a postfwd. Si no recibe nada, asegúrese de que postfwd3 se esté ejecutando y escuchando en la configuración de red especificada.

RENDIMIENTO

Algunas de estas propuestas podrían no coincidir con su entorno. ¡Por favor, verifique sus requisitos y pruebe las nuevas opciones cuidadosamente!

- use las opciones de caché
- use el operador de coincidencia correcto ==, <=, >=
- use ^ y/o $ en expresiones regulares
- use listas de elementos (más rápidas que reglas individuales)
- use la acción set() en listas de elementos repetidas
- use saltos y límites de velocidad
- use una regla de pre-búsqueda para rbl/rhsbls con acción note() vacía

NAME

postfwd3

connection-based mail proxy firewall

SYNOPSIS

postfwd3 [-hv] [-c config_file]

DESCRIPTION

This manual page describes the postfwd3 command.

postfwd is a connection-based mail proxy firewall. It is designed to run in front of one or more mail servers to provide filtering and protection against spam and other unwanted mail. It inspects the SMTP traffic between the client and the server, and can decide to reject or accept the connection based on various criteria.

The primary advantage of postfwd is its speed. It is written in C and heavily optimized to handle a large number of connections with minimal resource usage. It can be used to implement complex filtering policies without significantly impacting mail server performance.

postfwd listens on a network port (usually port 25) and accepts incoming SMTP connections. For each connection, it checks a set of rules defined in its configuration file. These rules can include checks on the client's IP address, hostname, the sender and recipient addresses, and other SMTP protocol elements.

If a connection matches a rule that dictates rejection, postfwd sends a rejection message back to the client and closes the connection. If the connection is allowed, postfwd forwards it to a configured backend mail server.

The configuration file allows for a flexible definition of rules, including regular expressions, IP address ranges, and lookups in external databases (like DNS RBLs). It also supports various actions, such as logging connections, marking connections with specific headers, or performing content filtering.

postfwd can be configured to work with various mail transfer agents (MTAs) like Postfix, Sendmail, Exim, etc., by setting the MTA to deliver mail to postfwd, which then relays it to the actual mail server. This setup is often referred to as an "in-bound relay" or "smarthost" configuration.

Key features include:

  • High performance and low resource usage.
  • Flexible rule-based filtering.
  • Support for IP address and hostname lookups.
  • Integration with DNS Realtime Blackhole Lists (RBLs).
  • Customizable logging and reporting.
  • Easy integration with existing mail server infrastructures.
