podman-pull(1) Manual de Comandos Generales podman-pull(1)

NOMBRE

podman-pull - Descargar una imagen de un registro

SINOPSIS

podman pull [opciones] fuente [fuente...]

podman image pull [opciones] fuente [fuente...]

podman pull [opciones] [transporte]nombre[:etiqueta|@digest]

podman image pull [opciones] [transporte]nombre[:etiqueta|@digest]

DESCRIPCIÓN

podman pull copia una imagen de un registro a la máquina local. El comando puede descargar una o más imágenes. Si la referencia de imagen en el argumento de línea de comandos no contiene un registro, se denomina referencia de nombre corto. Si la imagen es una referencia de 'nombre corto', Podman le pedirá al usuario el registro de contenedor específico del cual descargar la imagen, si no se ha especificado un alias para el nombre corto en short-name-aliases.conf. Si no se especifica una etiqueta de imagen, podman pull utiliza por defecto la imagen con la etiqueta latest (si existe) y la descarga. Después de descargar la imagen, podman imprime el ID completo de la imagen. podman pull también puede descargar imágenes usando un digest podman pull imagen@digest y también puede ser utilizado para descargar imágenes desde archivos y almacenamiento local usando diferentes transportes. IMPORTANTE: Las imágenes se almacenan en el almacenamiento de imágenes local.

FUENTE

FUENTE es la ubicación desde la cual se descarga la imagen del contenedor. Soporta todos los transportes de containers-transports(5). Si no se especifica ningún transporte, la entrada está sujeta a la resolución de nombre corto y se utiliza el transporte docker (es decir, registro de contenedor). Para clientes remotos, incluyendo máquinas Mac y Windows (excluyendo WSL2), docker es el único transporte soportado.

# Descargar desde un registro de contenedor
$ podman pull quay.io/username/myimage
# Descargar desde un registro de contenedor con resolución de nombre corto
$ podman pull fedora
# Descargar desde un registro de contenedor a través del transporte docker
$ podman pull docker://quay.io/username/myimage
# Descargar desde un directorio local
$ podman pull dir:/tmp/myimage
# Descargar desde un archivo tar en formato docker-archive
$ podman pull docker-archive:/tmp/myimage
# Descargar desde un demonio docker local
$ sudo podman pull docker-daemon:docker.io/library/myimage:33
# Descargar desde un archivo tar en formato oci-archive
$ podman pull oci-archive:/tmp/myimage

OPCIONES

--all-tags, -a

Se descargan todas las imágenes etiquetadas del repositorio.

*IMPORTANTE: Al usar la opción all-tags, Podman no itera sobre los registros de búsqueda en el containers-registries.conf(5) sino que siempre utiliza docker.io para nombres de imágenes no calificados.*

--arch=ARQUITECTURA

Sobrescribe la arquitectura, por defecto la del host, de la imagen a descargar. Por ejemplo, arm. A menos que se sobrescriba, las búsquedas posteriores de la misma imagen en el almacenamiento local coincidirán con esta arquitectura, independientemente del host.

--authfile=ruta

Ruta del archivo de autenticación. Por defecto es ${XDG_RUNTIME_DIR}/containers/auth.json en Linux, y $HOME/.config/containers/auth.json en Windows/macOS. El archivo es creado por podman login. Si el estado de autorización no se encuentra allí, se verifica $HOME/.docker/config.json, que se establece usando docker login.

Nota: También existe la opción de sobrescribir la ruta por defecto del archivo de autenticación estableciendo la variable de entorno REGISTRY_AUTH_FILE. Esto se puede hacer con export REGISTRY_AUTH_FILE=ruta.

--cert-dir=ruta

Utiliza certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro. (Por defecto: /etc/containers/certs.d) Para más detalles, ver containers-certs.d(5). (Esta opción no está disponible con el cliente Podman remoto, incluyendo máquinas Mac y Windows (excluyendo WSL2))

--creds=[usuario[:contraseña]]

El [usuario[:contraseña]] a usar para autenticarse con el registro, si es necesario. Si no se suministra uno o ambos valores, aparece un mensaje en la línea de comandos y se puede introducir el valor. La contraseña se introduce sin mostrarse.

Tenga en cuenta que las credenciales especificadas solo se utilizan para autenticarse contra los registros de destino. No se utilizan para espejos ni cuando el registro se reescribe (ver containers-registries.conf(5)); para autenticarse contra ellos, considere usar un archivo containers-auth.json(5).

--decryption-key=clave[:contraseña]

La [clave[:contraseña]] a utilizar para el descifrado de imágenes. Clave puede apuntar a claves y/o certificados. Se intenta el descifrado con todas las claves. Si la clave está protegida por una contraseña, se requiere pasarla en el argumento y omitirla en caso contrario.

--disable-content-trust

Esta es una opción específica de Docker para deshabilitar la verificación de imágenes en un registro de contenedores y no está soportada por Podman. Esta opción es un NOOP y se proporciona únicamente para la compatibilidad de scripts.

--help, -h

Imprime la declaración de uso.

--os=SO

Sobrescribe el SO, por defecto el del host, de la imagen a descargar. Por ejemplo, windows. A menos que se sobrescriba, las búsquedas posteriores de la misma imagen en el almacenamiento local coincidirán con este SO, independientemente del host.

--platform=SO/ARQUITECTURA

Especifica la plataforma para seleccionar la imagen. (Conflicta con --arch y --os) La opción --platform se puede usar para sobrescribir la arquitectura y el sistema operativo actuales. A menos que se sobrescriba, las búsquedas posteriores de la misma imagen en el almacenamiento local coincidirán con esta plataforma, independientemente del host.

--policy

Política de descarga de imágenes. La predeterminada es always.

  • always: Descarga siempre la imagen y genera un error si la descarga falla.
  • missing: Solo descarga la imagen si no se encontró en el almacenamiento de contenedores local. Genera un error si no se encontró ninguna imagen y la descarga falla.
  • never: Nunca descarga la imagen; usa solo la versión local. Genera un error si la imagen no está presente localmente.
  • newer: Descarga si la imagen en el registro es más nueva que la del almacenamiento de contenedores local. Una imagen se considera más nueva cuando los digestos son diferentes. Comparar las marcas de tiempo es propenso a errores. Los errores de descarga se suprimen si se encontró una imagen local.

--quiet, -q

Suprime la información de salida al descargar imágenes

--retry=intentos

Número de veces que se intentará descargar o subir imágenes entre el registro y el almacenamiento local en caso de fallo. Por defecto es 3.

--retry-delay=duración

Duración del retraso entre intentos de reintento al descargar o subir imágenes entre el registro y el almacenamiento local en caso de fallo. Por defecto, comienza en dos segundos y luego retrocede exponencialmente. El retraso se utiliza cuando se establece este valor y no ocurre ningún retroceso exponencial.

--tls-verify

Requiere HTTPS y verifica los certificados al contactar con los registros (por defecto: true). Si se establece explícitamente en true, se utiliza la verificación TLS. Si se establece en false, no se utiliza la verificación TLS. Si no se especifica, se utiliza la verificación TLS a menos que el registro de destino esté listado como un registro inseguro en containers-registries.conf(5)

--variant=VARIANT

Utiliza VARIANT en lugar de la variante de arquitectura por defecto de la imagen del contenedor. Algunas imágenes pueden usar múltiples variantes de las arquitecturas arm, como arm/v5 y arm/v7.

podman-pull(1) — Arch Linux

NAME

podman-pull — Pull an image or a repository from a registry

SYNOPSIS

podman pull [options] [image]

podman pull [options] [transport:][address/image[:tag|@digest]

DESCRIPTION

Pulls an image or a repository from a specified registry. If you do not specify a registry, Podman defaults to using the registry listed in registries.conf. If you do not specify a tag, Podman defaults to using latest.

Short names are supported for image names. For example, if you specify alpine as the image name, Podman assumes you mean docker.io/library/alpine. For more details on short name resolution, see the SHORT NAME RESOLUTION section.

When pulling an image, if the user does not specify the complete registry, container engines attempt to expand the short-name into a full name. If the command is executed with a tty, the user is prompted to select a registry from the default list unqualified registries defined in registries.conf. The user’s selection is then stored in a cache file to be used in all future short-name expansions. Rootful short-names are stored in /var/cache/containers/short-name-aliases.conf. Rootless short-names are stored in the $HOME/.cache/containers/short-name-aliases.conf file.

For more information on short-names, see containers-registries.conf(5)

SOURCE

The source of the image is determined by the registries.conf(5) file. This file determines which registries are consulted when completing image names which do not include a registry or domain portion.

NOTE: Use the environment variable TMPDIR to change the temporary storage location of downloaded container images. Podman defaults to use /var/tmp.

OPTIONS

--add-host, --add-host=[host-mapping] Add a host entry to the container's /etc/hosts file. Default format is [name:IP]

--all, -a Download all tagged images in the repository.

--authfile=[path] Path to the authentication file. Default is ${XDG_RUNTIME_DIR/containers/auth.json}.

--cert-dir=[path] Use TLS certs from this directory to connect to the registry. The default is 

@/etc/containers/certs.d/
. This option overrides the default directory.

--creds=[username:password] Use username:password for the registry, overriding the --authfile.

--daemon-host=[path] Use the specified Podman daemon.

--digest=[digest] Pull the image with the specified digest.

--format=[format] Pretty-print images based on the Go template format. Supported values: " table ", " raw ", " json " and Go template formats. Default is "table".

--get-content Get the contents of the image, not just the metadata.

--help, -h Help for podman pull

--history Show the history of the image.

--identity=[identity] The identity to use for pull, in case of multiple identities.

--jobs=[num] The number of concurrent jobs to run. Default is 10.

--latest, -l Saves the image as latest, regardless of the tag specified.

--login Use the registry's default username and password.

--os=[os] The OS for the image to be pulled. Default is linux.

--platform=[platform] The platform for which the image is to be pulled. Format: OS[/Variant] where Variant is optional. Examples: linux, linux/amd64, linux/amd64/v7, linux/arm64, etc.

--policy=[policy] Image pull policy. Possible values:

missing: Pull the image only if it is not present locally.

never: Never pull the image, only use local version.

always: Always pull the image even if present locally.

--proto=[proto] Use the specified proto when pulling images. Possible values: http, https. Default is https.

--quiet, -q Suppress the output.

--retry=[num] Number of retries upon failure. Default is 3.

--retry-delay=[time] Delay between retries. Example: 5s, 3m, 2h. Default is 10s.

--security-opt=[key=value] Security option.

--signature-policy=[path] Path to the signature policy file. Default is /etc/containers/policy.json.

--storage-driver=[driver] Specify the storage driver to use.

--storage-opt=[key=value] Specify storage driver options.

--syslog Log to syslog instead of stdout.

--tls-verify=[bool] Require TLS verification of the registry. Default is true.

--variant=[variant] The variant of the OS for the image to be pulled.

--usage-tag-only Only use the tag for the image, not the digest.

--username=[username] Username for registry authentication.

--version, -v Print the version

SHORT NAME RESOLUTION

When users specify images that do not include the container registry where the image is stored, this is called a short name. The use of unqualified-search registries entails an ambiguity as it is unclear from which registry a given image, referenced by a short name, may be pulled from.

Using short names is subject to the risk of hitting squatted registry namespaces. If the unqualified-search registries are set to ["public-registry.com", "my-private-registry.com"] an attacker may take over a namespace of public-registry.com such that an image may be pulled from public-registry.com instead of the intended source my-private-registry.com.

While it is highly recommended to always use fully-qualified image references, existing deployments using short names may not be easily changed. To circumvent the aforementioned ambiguity, so called short-name aliases can be configured that point to a fully-qualified image reference. Distributions often ship a default shortnames.conf expansion file in /etc/containers/registries.conf.d/ directory. Administrators can use this directory to add their own local short-name expansion files.

When pulling an image, if the user does not specify the complete registry, container engines attempt to expand the short-name into a full name. If the command is executed with a tty, the user is prompted to select a registry from the default list unqualified registries defined in registries.conf. The user's selection is then stored in a cache file to be used in all future short-name expansions. Rootful short-names are stored in /var/cache/containers/short-name-aliases.conf. Rootless short-names are stored in the $HOME/.cache/containers/short-name-aliases.conf file.

For more information on short-names, see containers-registries.conf(5)

registries.conf (/etc/containers/registries.conf)

registries.conf is the configuration file which specifies which container registries is consulted when completing image names which do not include a registry or domain portion.

NOTE: Use the environment variable TMPDIR to change the temporary storage location of downloaded container images. Podman defaults to use /var/tmp.
