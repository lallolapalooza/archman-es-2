pow(3) Manual de funciones de biblioteca pow(3)

NOMBRE

pow, powf, powl - funciones de potencia

BIBLIOTECA

Biblioteca matemática (libm, -lm)

SINOPSIS

#include <math.h>
double pow(double x, double y);
float powf(float x, float y);
long double powl(long double x, long double y);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

powf(), powl():

    _ISOC99_SOURCE || _POSIX_C_SOURCE >= 200112L
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

Estas funciones devuelven el valor de x elevado a la potencia de y.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven el valor de x elevado a la potencia de y.

Si el resultado excede los límites, ocurre un error de rango y las funciones devuelven HUGE_VAL, HUGE_VALF o HUGE_VALL, respectivamente, con el signo matemáticamente correcto.

Si el resultado está por debajo de los límites y no es representable, ocurre un error de rango y se devuelve 0.0 con el signo apropiado.

Si x es +0 o -0, y y es un entero impar menor que 0, ocurre un error de polo y se devuelve HUGE_VAL, HUGE_VALF o HUGE_VALL, con el mismo signo que x.

Si x es +0 o -0, y y es menor que 0 y no es un entero impar, ocurre un error de polo y se devuelve +HUGE_VAL, +HUGE_VALF o +HUGE_VALL.

Si x es +0 (-0), y y es un entero impar mayor que 0, el resultado es +0 (-0).

Si x es 0, y y es mayor que 0 y no es un entero impar, el resultado es +0.

Si x es -1, y y es infinito positivo o infinito negativo, el resultado es 1.0.

Si x es +1, el resultado es 1.0 (incluso si y es NaN).

Si y es 0, el resultado es 1.0 (incluso si x es NaN).

Si x es un valor finito menor que 0, y y es un número finito no entero, ocurre un error de dominio y se devuelve un NaN.

Si el valor absoluto de x es menor que 1, y y es infinito negativo, el resultado es infinito positivo.

Si el valor absoluto de x es mayor que 1, y y es infinito negativo, el resultado es +0.

Si el valor absoluto de x es menor que 1, y y es infinito positivo, el resultado es +0.

Si el valor absoluto de x es mayor que 1, y y es infinito positivo, el resultado es infinito positivo.

Si x es infinito negativo, y y es un entero impar menor que 0, el resultado es -0.

Si x es infinito negativo, y y es menor que 0 y no es un entero impar, el resultado es +0.

Si x es infinito negativo, y y es un entero impar mayor que 0, el resultado es infinito negativo.

Si x es infinito negativo, y y es mayor que 0 y no es un entero impar, el resultado es infinito positivo.

Si x es infinito positivo, y y es menor que 0, el resultado es +0.

Si x es infinito positivo, y y es mayor que 0, el resultado es infinito positivo.

Excepto como se especifica anteriormente, si x o y es un NaN, el resultado es un NaN.

ERRORES

Consulte math_error(7) para obtener información sobre cómo determinar si ha ocurrido un error al llamar a estas funciones.

Los siguientes errores pueden ocurrir:

Error de dominio: x es negativo, y y es un número finito no entero
errno se establece en EDOM. Se genera una excepción de punto flotante inválida (FE_INVALID).
Error de polo: x es cero, y y es negativo
errno se establece en ERANGE (pero consulte ERRORES).
Error de rango: el resultado excede los límites
errno se establece en ERANGE. Se genera una excepción de punto flotante de desbordamiento (FE_OVERFLOW).
Error de rango: el resultado está por debajo de los límites
errno se establece en ERANGE. Se genera una excepción de punto flotante de subdesbordamiento (FE_UNDERFLOW).

ESTÁNDARES

C11, POSIX.1-2008.

HISTORIA

C99, POSIX.1-2001.

La variante que devuelve double también cumple con SVr4, 4.3BSD, C89.

ERRORES DE SOFTWARE

Errores históricos (ahora corregidos)

Antes de glibc 2.28, en algunas arquitecturas (por ejemplo, x86-64), pow() podía ser más de 10.000 veces más lento para algunas entradas que para otras entradas cercanas. Esto solo afectaba a pow() y no a powf() ni a powl(). Este problema se corrigió en glibc 2.28.

Se corrigieron varios errores en la implementación de pow() de glibc en glibc 2.16.

En glibc 2.9 y versiones anteriores, cuando ocurre un error de polo, errno se establece en EDOM en lugar del ERANGE exigido por POSIX. Desde glibc 2.10, glibc hace lo correcto.

En glibc 2.3.2 y versiones anteriores, cuando ocurre un error de desbordamiento o subdesbordamiento, pow() de glibc genera una excepción inválida de punto flotante (FE_INVALID) además de la excepción de desbordamiento o subdesbordamiento.

powf - float power function

#include <math.h>

float powf(float base, float exponent);

The powf function computes the value of base raised to the power of exponent, without loss of precision for the given single-precision floating-point format.

The behavior of powf is similar to pow, but it operates on float types instead of double types.

On success, powf returns the computed value of baseexponent.

Special cases:

  • If base is a NaN, a NaN is returned.
  • If exponent is a NaN, a NaN is returned.
  • If base is 0 and exponent is negative, a pole error may occur, and HUGE_VALF is returned.
  • If base is 0 and exponent is 0, 1 is returned.
  • If base is negative and exponent is not an integer, a domain error may occur, and NaN is returned.
  • If base is 1, 1 is returned.
  • If exponent is 0, 1 is returned.
  • If exponent is 1, base is returned.

The following conditions are considered errors and may set errno to the indicated value:

  • DOMÁIN ERROR: base is negative and exponent is not an integer.
  • POLE ERROR: base is 0 and exponent is negative.

For an explanation of the terms used in this section, see attributes(7).

The powf function conforms to the C99 standard and later. It is also specified by POSIX.1-2001 and POSIX.1-2008.

The powf function first appeared in POSIX.1-1990.

No known bugs.
