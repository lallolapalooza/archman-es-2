NOMBRE

podman-container-checkpoint - Realiza un punto de control de uno o más contenedores en ejecución

SINOPSIS

podman container checkpoint [opciones] contenedor [contenedor ...]

DESCRIPCIÓN

podman container checkpoint realiza un punto de control de todos los procesos en uno o más contenedores. Un contenedor puede ser restaurado desde un punto de control con podman-container-restore. Se utilizan los IDs o nombres de contenedor como entrada.

IMPORTANTE: Si el contenedor está utilizando systemd como entrypoint, la realización de un punto de control del contenedor podría no ser posible.

OPCIONES

--all, -a

Realiza un punto de control de todos los contenedores en ejecución.
Por defecto es false.
IMPORTANTE: Esta OPCIÓN no necesita un nombre o ID de contenedor como argumento de entrada.

--compress, -c=zstd | none | gzip

Especifica el algoritmo de compresión utilizado para el archivo de punto de control creado con la OPCIÓN --export, -e. Los algoritmos posibles son zstd, none y gzip.
Una razón posible para usar none es permitir una creación más rápida de los archivos de punto de control. No comprimir el archivo de punto de control puede resultar en una creación más rápida del mismo.
Por defecto es zstd.

--create-image=imagen

Crea una imagen de punto de control a partir de un contenedor en ejecución. Esta es una imagen OCI estándar creada en el almacén local de imágenes. Consiste en una sola capa que contiene todos los archivos del punto de control. El contenido de esta capa de imagen tiene el mismo formato que un punto de control creado con --export. Una imagen de punto de control se puede enviar a un registro de contenedores estándar y descargar en un sistema diferente para permitir la migración de contenedores. Además, la imagen se puede exportar con podman image save e inspeccionar con podman inspect. La inspección de una imagen de punto de control muestra información adicional, almacenada como anotaciones, sobre el entorno del host utilizado para realizar el punto de control:

  • io.podman.annotations.checkpoint.name: Nombre legible por humanos del contenedor original.
  • io.podman.annotations.checkpoint.rawImageName: Nombre no procesado de la imagen utilizada para crear el contenedor original (según lo especificado por el usuario).
  • io.podman.annotations.checkpoint.rootfsImageID: ID de la imagen utilizada para crear el contenedor original.
  • io.podman.annotations.checkpoint.rootfsImageName: Nombre de la imagen utilizada para crear el contenedor original.
  • io.podman.annotations.checkpoint.podman.version: Versión de Podman utilizada para crear el punto de control.
  • io.podman.annotations.checkpoint.criu.version: Versión de CRIU utilizada para crear el punto de control.
  • io.podman.annotations.checkpoint.runtime.name: Runtime del contenedor (por ejemplo, runc, crun) utilizado para crear el punto de control.
  • io.podman.annotations.checkpoint.runtime.version: Versión del runtime del contenedor utilizada para crear el punto de control.
  • io.podman.annotations.checkpoint.conmon.version: Versión de conmon utilizada con el contenedor original.
  • io.podman.annotations.checkpoint.host.arch: Arquitectura de CPU del host en el que se creó el punto de control.
  • io.podman.annotations.checkpoint.host.kernel: Versión del kernel de Linux del host donde se creó el punto de control.
  • io.podman.annotations.checkpoint.cgroups.version: Versión de cgroup utilizada por el host donde se creó el punto de control.
  • io.podman.annotations.checkpoint.distribution.version: Versión de la distribución del host en la que se creó el punto de control.
  • io.podman.annotations.checkpoint.distribution.name: Nombre de la distribución del host en la que se creó el punto de control.

--export, -e=archivo

Exporta el punto de control a un archivo. El tipo de archivo se especifica con --compress. El punto de control exportado puede ser utilizado para importar el contenedor en otro sistema y así permitir la migración en vivo del contenedor. Este archivo de punto de control también incluye todos los cambios en el sistema de archivos raíz del contenedor, si no se desactiva explícitamente con --ignore-rootfs.

--file-locks

Realiza un punto de control de un contenedor con bloqueos de archivos. Si una aplicación que se ejecuta en el contenedor está utilizando bloqueos de archivos, esta OPCIÓN es necesaria durante el punto de control y la restauración. De lo contrario, se espera que la realización de un punto de control de contenedores con bloqueos de archivos falle. Si no se utilizan bloqueos de archivos, esta opción se ignora.
Por defecto es false.

--ignore-rootfs

Si un punto de control se exporta a un archivo, es posible con la ayuda de --ignore-rootfs deshabilitar explícitamente la inclusión de cambios en el sistema de archivos raíz en el archivo de punto de control.
Por defecto es false.
IMPORTANTE: Esta OPCIÓN solo funciona en combinación con --export, -e.

--ignore-volumes

Esta OPCIÓN debe usarse en combinación con la OPCIÓN --export, -e. Cuando se especifica esta OPCIÓN, el contenido de los volúmenes asociados con el contenedor no se incluye en el archivo de punto de control.
Por defecto es false.

--keep, -k

Conserva todos los archivos temporales de registro y estadísticas creados por CRIU durante la realización del punto de control. Estos archivos no se eliminan si la realización del punto de control falla, para su posterior depuración. Si la realización del punto de control tiene éxito, estos archivos teóricamente no son necesarios, pero si se necesitan, Podman puede conservar los archivos para un análisis posterior.
Por defecto es false.

--latest, -l

En lugar de proporcionar el ID o nombre del contenedor, utiliza el último contenedor creado. Por defecto es false. IMPORTANTE: Esta OPCIÓN no está disponible con el cliente remoto de Podman, incluyendo máquinas Mac y Windows (excluyendo WSL2). Esta OPCIÓN no necesita un nombre o ID de contenedor como argumento de entrada.

--leave-running, -R

Deja el contenedor en ejecución después de realizar el punto de control en lugar de detenerlo.
Por defecto es false.

--pre-checkpoint, -P

Vuelca solo la información de memoria del contenedor, dejando el contenedor en ejecución. Las operaciones posteriores anulan las volcadas anteriores.
Por defecto es false.

La funcionalidad de solo realizar un punto de control de la memoria del contenedor y en un segundo punto de control solo volcar las páginas de memoria que han cambiado desde el primer punto de control se basa en el bit de "soft-dirty" del kernel de Linux, que no está disponible en todos los sistemas, ya que depende de la arquitectura del sistema y la configuración del kernel de Linux. Podman verifica si el sistema actual admite esta funcionalidad y devuelve un error si el sistema actual no la admite.

--print-stats

Imprime estadísticas sobre la realización del punto de control de los contenedores. La salida se renderiza en una matriz JSON y contiene información sobre cuánto tiempo requirieron las diferentes operaciones de punto de control. Muchas de las estadísticas de punto de control son creadas por CRIU y simplemente se pasan a Podman. La siguiente información se proporciona en la matriz JSON:

  • podman_checkpoint_duration: Tiempo total (en microsegundos) necesario para crear todos los puntos de control.
  • runtime_checkpoint_duration: Tiempo (en microsegundos) que el runtime del contenedor necesitó para crear el punto de control.
  • freezing_time: Tiempo (en microsegundos) que CRIU necesitó para pausar (congelar) todos los procesos en el contenedor (medido por CRIU).
  • frozen_time: Tiempo (en microsegundos) que todos los procesos en el contenedor estuvieron pausados (medido por CRIU).
  • memdump_time: Tiempo (en microsegundos) necesario para extraer todas las páginas de memoria requeridas de todos los procesos del contenedor (medido por CRIU).
  • memwrite_time: Tiempo (en microsegundos) necesario para escribir todas las páginas de memoria requeridas en los archivos de imagen de punto de control correspondientes (medido por CRIU).
  • pages_scanned: Número de páginas de memoria escaneadas para determinar si necesitan ser checkpointed (medido por CRIU).
  • pages_written: Número de páginas de memoria realmente escritas en los archivos de imagen de punto de control (medido por CRIU).

--quiet, -q

No imprima los IDs de los contenedores recién creados. Por defecto es false.

EJEMPLO

Realizar un punto de control de un contenedor llamado webserver y dejarlo en ejecución:

$ podman container checkpoint --leave-running webserver

Realizar un punto de control de todos los contenedores, exportarlo a un archivo llamado myarchive.tar.gz y comprimirlo con gzip:

$ podman container checkpoint --all --export myarchive.tar.gz --compress gzip

Realizar un punto de control de un contenedor y crear una imagen llamada my-checkpoint-image:

$ podman container checkpoint --create-image my-checkpoint-image mycontainer

NAME

podman-container-checkpoint, podman-container-restore - Checkpoint a container into a directory or a tar archive.

SYNOPSIS

podman container checkpoint [--compress=none|gzip|bzip2|xz|zstd] [--create-image] [--export=archive] [--leave-running] [--podman-args] [--pre-checkpoint] [--tcp-established] [--with-previous] [-P|--pretty] [-e|--export=archive] [-l|--latest] [container...]

podman container restore [--default-log-driver] [--podman-args] [--tcp-established] [-i|--import=archive] [-l|--latest] [container...]

DESCRIPTION

The podman container checkpoint command checkpoints one or more containers into a directory or a tar archive. CRIU (Checkpoint/Restore In Userspace) is used to dump the state of processes and other objects into frozen images. The frozen images can then be used to restore the processes back into execution.

The podman container restore command restores one or more containers from a directory or a tar archive.

To checkpoint a container, use the podman container checkpoint command. To restore a container, use the podman container restore command.

The default location for checkpoint images is /var/lib/containers/storage/libpod/checkpoint/container.

Podman supports checkpointing of containers created with the `docker-compatible` volume driver. Checkpointing of containers created with the `overlay` volume driver is not supported.

By default, the container is paused during the checkpoint operation and resumed after the operation completes. Use the --leave-running option to keep the container paused after checkpointing.

OPTIONS

podman container checkpoint

--compress=none|gzip|bzip2|xz|zstd
Compression algorithm to use for checkpoint image archives. Defaults to zstd if available, otherwise gzip.
--create-image
Create a container image from the checkpointed container. The image will be created with the name specified by the first argument. This option is useful for creating reproducible containers.
-e, --export=archive
Path to a tar archive file where the checkpoint image will be stored. This option overrides the default checkpoint directory.
-l, --latest
Instead of specifying a container name or ID, use the container resulting from the last (most recent) operation.
-P, --pretty
This is a shorthand for --export=/var/lib/containers/storage/libpod/checkpoint/ container. This will dump the memory usage of the latest container into a checkpoint image.
--leave-running
Do not resume the container after checkpointing. The container will remain in the paused state.
--podman-args
Pass the provided arguments to the podman command. This is useful for passing options that are not directly supported by the checkpoint command.
--pre-checkpoint
Perform a pre-checkpoint dump. This is the first step in a two-step checkpointing process. The second step is performed using the --with-previous option.
--tcp-established
Checkpoint a container with established TCP connections. If the checkpoint image contains established TCP connections, this option is required during restore. Defaults to not checkpointing containers with established TCP connections.
--with-previous
Check out the container with previous criu image files in pre-dump. It only works on runc 1.0-rc3 or higher.
The default is false.
IMPORTANT: This option is not available with --pre-checkpoint.

This option requires that the option --pre-checkpoint has been used before on the same container. Without an existing pre-checkpoint, this option fails.

Also see --pre-checkpoint for additional information about --pre-checkpoint availability on different systems.

podman container restore

--default-log-driver
Set the default log driver for the restored container. This option is useful when restoring a container that was created with a specific log driver that may not be available in the current environment.
-i, --import=archive
Path to a tar archive file from which the checkpoint image will be restored. This option overrides the default checkpoint directory.
-l, --latest
Instead of specifying a container name or ID, use the container resulting from the last (most recent) operation.
--podman-args
Pass the provided arguments to the podman command. This is useful for passing options that are not directly supported by the restore command.
--tcp-established
Checkpoint a container with established TCP connections. If the checkpoint image contains established TCP connections, this OPTION is required during restore. Defaults to not checkpointing containers with established TCP connections.
The default is false.

EXAMPLES

Make a checkpoint for the container "mywebserver".

# podman container checkpoint mywebserver

Create a checkpoint image for the container "mywebserver".

# podman container checkpoint --create-image mywebserver-checkpoint-1 mywebserver

Dumps the container's memory information of the latest container into an archive.

# podman container checkpoint -P -e pre-checkpoint.tar.zst -l

Keep the container's memory information from an older dump and add the new container's memory information.

# podman container checkpoint --with-previous -e checkpoint.tar.zst -l

Dump the container's memory information of the latest container into an archive with the specified compress method.

# podman container checkpoint -l --compress=none --export=dump.tar
# podman container checkpoint -l --compress=gzip --export=dump.tar.gz
