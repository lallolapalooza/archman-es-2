POWERVAR_CX_USB(8) Manual de NUT POWERVAR_CX_USB(8)

NOMBRE

powervar_cx_usb - Controlador para equipos de SAI Powervar series GTS y UPM con conexión USB

SINOPSIS

powervar_cx_usb -h

powervar_cx_usb -a NOMBRE_SAI [OPCIONES]


Nota

Esta página del manual solo documenta las características específicas del hardware del controlador Powervar. Para obtener información sobre el controlador principal, consulte nutupsdrv(8).

HARDWARE SOPORTADO

Este controlador soporta dos familias de SAI Powervar con conexiones USB:

•UPM (USB o Serie)
•GTS (solo USB)

Para dispositivos de la serie UPM conectados por serie, consulte también powervar_cx_ser(8).

ARGUMENTOS ADICIONALES

Este controlador soporta las siguientes configuraciones opcionales en el archivo ups.conf(5):

port = cadena

Opción requerida para todos los controladores NUT. Se debe establecer algún valor, típicamente auto para los controladores que manejan conexiones USB.

Nota
Podría ser una ruta de sistema de archivos de dispositivos como /dev/usb/hiddev0, pero el uso actual de la API libusb impide conocer y coincidir con dichos identificadores. También pueden ser intrínsecamente poco fiables (dependientes de la reconexión y el orden de enumeración). En este momento, el valor real se ignora, pero sintácticamente todavía debe haber alguna configuración de port.

Es posible controlar múltiples unidades de SAI simultáneamente ejecutando varias instancias de este controlador, siempre que se puedan distinguir de forma única estableciendo alguna combinación de las opciones vendor, product, vendorid, productid, serial, bus y/o device detalladas a continuación. Para dispositivos o sistemas operativos que no proporcionan información suficiente, la opción allow_duplicates puede ser útil (¡limitada y arriesgada!).

vendorid = regex, productid = regex, vendor = regex, product = regex, serial = regex

Selecciona un SAI específico, en caso de que haya más de uno conectado vía USB. Cada opción especifica una expresión regular extendida (consulte regex(7) para más información sobre expresiones regulares), que debe coincidir con los valores completos de las cadenas de proveedor/producto/serie del SAI (sin espacios en blanco alrededor), o con el código hexadecimal completo de 4 dígitos para vendorid y productid.

Intente lsusb(8) o ejecute este controlador NUT con el argumento de línea de comandos -DD para averiguar las cadenas con las que coincidir.

Ejemplos:

•-x vendor="Foo.Corporation.*"
•-x vendorid="051d*" (APC)
•-x product=".*(Smart|Back)-?UPS.*"

bus = regex

OPCIONAL, NO RECOMENDADO.

Selecciona un SAI en un bus USB específico o grupo de buses. El argumento es una expresión regular que debe coincidir con el nombre del bus donde está conectado el SAI (por ejemplo, bus="002" o bus="00[2-3]") como se ve en Linux en /sys/bus/usb/devices o lsusb(8); incluyendo ceros iniciales.


Nota
Los números de bus no están garantizados por el SO para ser estables entre reinicios, recargas de controladores del kernel o reconexiones de dispositivos (por ejemplo, cambios en la población visible de concentradores USB).

device = regex

OPCIONAL, NO RECOMENDADO.

Selecciona un SAI en un dispositivo USB específico o grupo de dispositivos. El argumento es una expresión regular que debe coincidir con el nombre del dispositivo donde está conectado el SAI (por ejemplo, device="001" o device="00[1-2]") como se ve en Linux en /sys/bus/usb/devices o lsusb(8); incluyendo ceros iniciales.


Nota
Los números de dispositivo no están garantizados por el SO para ser estables entre reinicios o reconexiones de dispositivos.

busport = regex

OPCIONAL, NO RECOMENDADO.

Si es compatible con el hardware, el SO y libusb en la implementación particular, esta opción debería permitir especificar números de puerto físicos en un concentrador USB, en lugar de valores de enumeración lógicos y, a su vez, esto debería ser menos volátil entre reinicios o reconexiones. El valor puede verse en la salida de topología USB de lsusb -tv en sistemas con esa herramienta, por ejemplo.


Nota
Esta opción no es prácticamente compatible con algunas compilaciones de NUT (debería ignorarse con una advertencia entonces), y no con todos los sistemas en los que NUT puede ejecutarse.

allow_duplicates

OPCIONAL, NO RECOMENDADO.

Si tiene varios dispositivos SAI que no se pueden identificar de forma única mediante las opciones anteriores (por ejemplo, solo se pueden descubrir VID:PID), esta bandera permite que cada instancia del controlador donde se establezca tome la primera coincidencia si está disponible, o continúe intentando con otra.

Normalmente, la inicialización del controlador abortaría en este punto reclamando "Recurso ocupado" o un error similar, asumiendo que el dispositivo, que de otra manera estaría bien emparejado, es único, y que otro proceso ya lo está manejando.


Advertencia
¡Esta característica es inherentemente no determinista! ¡La asociación del nombre de la instancia del controlador con el dispositivo real puede variar entre ejecuciones!

Si solo le importa saber que al menos uno de sus SAI sin nombre está en línea, esta opción puede ayudar.

¡Si realmente necesita saber cuál, no le servirá!

usb_set_altinterface = bAlternateSetting

Fuerza una llamada redundante a usb_set_altinterface(), especialmente si es necesario para dispositivos que sirven múltiples roles USB donde el SAI no está representado por la interfaz número 0 (predeterminado).

usb_config_index, usb_hid_rep_index, usb_hid_desc_index, usb_hid_ep_in, usb_hid_ep_out

Fuerza el uso de números específicos de interfaz, punto final, índice de descriptor, etc., en lugar de usar el valor predeterminado de 0 (raramente otros valores en ciertos controladores para algunos dispositivos conocidos por usar números distintos de cero). Especificado como un número hexadecimal.

Como regla general para el descubrimiento de usb_hid_desc_index, puede ver valores más grandes de wDescriptorLength (aproximadamente 600+ bytes) en los informes de lsusb o herramientas similares.

LIBUSB_DEBUG = ENTERO

La resolución de problemas en tiempo de ejecución de los controladores NUT compatibles con USB puede implicar no solo aumentar la verbosidad de depuración común de NUT (por ejemplo, usando la configuración DEBUG_MIN en ups.conf(5) o comandos de protocolo para cambiar el valor de driver.debug), sino que también puede beneficiarse de la depuración específica de LibUSB.

Para esto último, puede establecer la opción del controlador LIBUSB_DEBUG; alternativamente, puede exportar clásicamente la variable de entorno LIBUSB_DEBUG antes de iniciar un programa controlador NUT (puede ser configurada y "exportada" en el script de inicialización del controlador o método de servicio, quizás a través de nut.conf(5)), a un valor numérico como 4 ("Se emiten todos los mensajes").

Para más detalles, incluyendo los valores actualmente soportados para su versión de la biblioteca, consulte por ejemplo:

•https://libusb.sourceforge.io/api-1.0/
•https://libusb.sourceforge.io/api-1.0/group__libusb__lib.html

startdelay=num

Cambia el tiempo de espera de inicio del valor predeterminado de 1 segundo.

offdelay=num

Cambia el tiempo de espera de apagado del valor predeterminado de 0 segundos.

disptesttime=num

Cambia el tiempo de prueba de pantalla del valor predeterminado de 10 segundos (solo UPM).

COMANDOS INSTANTANEOS

Estos son los comandos que puede enviar a las UPS soportadas:

Unidades APC UPS

ups.disable

Deshabilita la UPS.

ups.enable

Habilita la UPS.

ups.debug

Activa la depuración (debug) para la UPS.

ups.feature.mute

Silencia el pitido de la UPS.

shutdown.return

Apaga la carga posiblemente después de un retraso y regresa cuando la energía se restablece.

shutdown.stop

Detiene un apagado en progreso.

shutdown.reboot

Apaga la carga brevemente mientras reinicia la UPS.

shutdown.stayoff

Apaga la carga y permanece apagada.

test.battery.start.deep

Inicia una prueba de batería "profunda". Esta prueba ejecuta la UPS hasta el punto de batería baja y luego regresa a la línea de CA.

test.battery.start.quick

Inicia una prueba de batería "rápida". El tiempo predeterminado es de 2 minutos. Este tiempo se puede configurar en el archivo ups.conf. Ver testime arriba.

test.battery.stop

Detiene una prueba de batería en progreso.

test.failure.start

Inicia una simulación de fallo de energía de entrada.

test.failure.stop

Detiene una simulación de fallo de energía de entrada.

Todas las unidades UPM UPS

test.panel.start

Inicia la prueba del panel de la UPS.

reset.input.minmax

Restablece el estado mínimo y máximo del voltaje de entrada.
