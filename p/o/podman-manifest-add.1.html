NOMBRE

podman-manifest-add - Añadir una imagen o artefacto a una lista de manifiestos o índice de imágenes

SINOPSIS

podman manifest add [opciones] nombre_lista_o_indice [transporte]:nombre_imagen nombre_imagen_o_artefacto [...]

DESCRIPCIÓN

Añade la imagen especificada a la lista de manifiestos o índice de imágenes especificado, o crea un manifiesto de artefacto y lo añade al índice de imágenes especificado.

VALOR DE RETORNO

El ID de la imagen de la lista.

OPCIONES

--all

Si la imagen que se añade a la lista o índice es en sí misma una lista o índice, añade todos los contenidos a la lista local. Por defecto, solo se añade una imagen de dicha lista o índice a la lista o índice. NO se recomienda combinar --all con ninguna de las otras opciones descritas a continuación.

--annotation=anotación=valor

Establece una anotación en la entrada para la imagen o artefacto especificado.

--arch=arquitectura

Sobrescribe la arquitectura que la lista o índice registra como requisito para la imagen. Si nombre_imagen se refiere a una lista de manifiestos o índice de imágenes, la información de la arquitectura se recupera de ella. De lo contrario, se recupera de la información de configuración de la imagen.

--artifact

Crea un manifiesto de artefacto y lo añade al índice de imágenes. Los argumentos después del nombre del índice se interpretarán como nombres de archivo en lugar de referencias de imagen. En la mayoría de los escenarios, la opción --artifact-type también debe especificarse.

--artifact-config=ruta

Al crear un manifiesto de artefacto y añadirlo al índice de imágenes, utiliza el contenido del archivo especificado como blob de configuración en el manifiesto de artefacto. En la mayoría de los escenarios, dejar el valor predeterminado, que indica una configuración vacía, sin cambios, es la opción preferida.

--artifact-config-type=tipo

Al crear un manifiesto de artefacto y añadirlo al índice de imágenes, utiliza el tipo MIME especificado como mediaType asociado al blob de configuración en el manifiesto de artefacto. En la mayoría de los escenarios, dejar el valor predeterminado, que indica una configuración vacía o el tipo de configuración estándar de OCI, sin cambios, es la opción preferida.

--artifact-exclude-titles

Al crear un manifiesto de artefacto y añadirlo al índice de imágenes, no establezca anotaciones "org.opencontainers.image.title" iguales al nombre base del archivo para cada archivo añadido al manifiesto de artefacto. Las herramientas que recuperan artefactos de un registro pueden usar estos valores para elegir nombres de archivo al guardar artefactos en disco, por lo que esta opción no se recomienda a menos que sea necesaria para la interoperabilidad con un registro particular.

--artifact-layer-type=tipo

Al crear un manifiesto de artefacto y añadirlo al índice de imágenes, utiliza el tipo MIME especificado como mediaType asociado al contenido de los archivos. Si no se especifica, se intentarán adivinar basándose en los nombres de archivo o su contenido, pero la opción debe especificarse si se necesita certeza.

--artifact-subject=nombre_imagen

Al crear un manifiesto de artefacto y añadirlo al índice de imágenes, establece el campo subject en el manifiesto de artefacto para marcar el manifiesto de artefacto como asociado con la imagen especificada de alguna manera. Un manifiesto de artefacto solo puede asociarse con, como máximo, un sujeto.

--artifact-type=tipo

Al crear un manifiesto de artefacto, utiliza el tipo MIME especificado como valor artifactType del manifiesto en lugar del valor predeterminado menos informativo.

--authfile=ruta

Ruta del archivo de autenticación. El valor predeterminado es ${XDG_RUNTIME_DIR}/containers/auth.json en Linux y $HOME/.config/containers/auth.json en Windows/macOS. El archivo es creado por podman login. Si el estado de autorización no se encuentra ahí, se comprueba $HOME/.docker/config.json, que se establece usando docker login.

Nota: También existe la opción de sobrescribir la ruta predeterminada del archivo de autenticación estableciendo la variable de entorno REGISTRY_AUTH_FILE. Esto se puede hacer con export REGISTRY_AUTH_FILE=ruta.

--cert-dir=ruta

Utiliza los certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro. (Por defecto: /etc/containers/certs.d) Para más detalles, véase containers-certs.d(5). (Esta opción no está disponible con el cliente remoto de Podman, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--creds=[nombre_usuario[:contraseña]]

El [nombre_usuario[:contraseña]] a utilizar para autenticarse con el registro, si es necesario. Si no se proporcionan uno o ambos valores, aparecerá un aviso en la línea de comandos y se podrá introducir el valor. La contraseña se introduce sin mostrarse.

Tenga en cuenta que las credenciales especificadas solo se utilizan para autenticarse en los registros de destino. No se utilizan para espejos ni cuando el registro se reescribe (véase containers-registries.conf(5)); para autenticarse en esos casos, considere usar un archivo containers-auth.json(5).

--features=característica

Especifica la lista de características que la lista o índice registra como requisitos para la imagen. Esta opción rara vez se utiliza.

--os=SO

Sobrescribe el SO que la lista o índice registra como requisito para la imagen. Si nombre_imagen se refiere a una lista de manifiestos o índice de imágenes, la información del SO se recupera de ella. De lo contrario, se recupera de la información de configuración de la imagen.

--os-version=versión

Especifica la versión del SO que la lista o índice registra como requisito para la imagen. Esta opción rara vez se utiliza.

--tls-verify

Requiere HTTPS y verifica certificados al contactar con los registros (por defecto: true). Si se establece explícitamente en true, se utiliza la verificación TLS. Si se establece en false, no se utiliza la verificación TLS. Si no se especifica, se utiliza la verificación TLS a menos que el registro de destino esté listado como un registro inseguro en containers-registries.conf(5)

--variant

Especifica la variante que la lista o índice registra para la imagen. Esta opción se utiliza típicamente para distinguir entre múltiples entradas que comparten el mismo valor de arquitectura, pero que esperan diferentes versiones de su conjunto de instrucciones.

Transporte

Se admiten múltiples transportes:

docker://referencia_docker (por defecto)
Una imagen en un registro que implementa la "API HTTP V2 del Registro Docker". Por defecto, utiliza el estado de autorización en $XDG_RUNTIME_DIR/containers/auth.json, que se establece usando (podman login). Si el estado de autorización no se encuentra ahí, se comprueba $HOME/.docker/config.json, que se establece usando (docker login).

$ podman manifest add mylist:v1.11 docker://quay.io/username/myimage

containers-storage:referencia_oci
Una imagen en formato referencia_oci almacenada en el almacenamiento local de contenedores. referencia_oci debe contener una etiqueta.

$ podman manifest add mylist:v1.11 containers-storage:quay.io/username/myimage

dir:ruta
Un directorio local existente ruta que almacena el manifiesto, los archivos tar de capas y las firmas como archivos individuales. Este
es un formato no estandarizado, principalmente útil para depuración o inspección no invasiva de contenedores.

$ podman manifest add dir:/tmp/myimage
