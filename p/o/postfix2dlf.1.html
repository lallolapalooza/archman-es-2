POSTFIX2DLF.IN(1) Documentación de Lire de LogReport POSTFIX2DLF.IN(1)

NOMBRE

postfix2dlf - convierte archivos de registro de postfix al formato dlf

SINOPSIS

postfix2dlf

DESCRIPCIÓN

postfix2dlf convierte un archivo de registro de postfix a un archivo de formato de registro destilado (DLF) de Lire. Llama a postfix2dlf_pre(1) y postfix2dlf_main(1) para hacer el trabajo real. Espera el archivo de registro en la entrada estándar (stdin) e imprime el DLF en la salida estándar (stdout). Los diagnósticos se imprimen en la salida de error (stderr). Este script es llamado por lr_log2xml(1).

FUNDAMENTO

La arquitectura de postfix2dlf es bastante diferente de otros convertidores de dlf de correo electrónico. Esto se debe a que al analizar un archivo de registro de postfix, no hay ninguna indicación de si un mensaje ha sido entregado a todos los destinatarios. (En un registro de sendmail, hay un campo rcpts=, que se puede usar para este propósito).

Existen varias soluciones alternativas para tratar con un registro así. 1: hacer un seguimiento de todos los id de cola junto con su información de origen durante todo el procesamiento del archivo de registro. Esto consume demasiada memoria. 2: hacer una heurística de 10 segundos: asumir que un mensaje nunca permanecerá en la cola más de, por ejemplo, 10 segundos. O, alternativamente, asumir que no más de $LR_POSTFIX_MAX_QUEUE_SIZE mensajes estarán en la cola simultáneamente. Esto es demasiado propenso a errores. 3: usar sort(1) para ordenar las líneas de registro por id de cola. Esto es lo que solíamos hacer. Sin embargo, no sabemos de antemano qué campo almacenará el id de cola (los archivos de registro procesados por el syslog de Sun Solaris tendrán su id de cola en otra posición, por ejemplo). Calcular esta posición implicaría analizar el registro dos veces.

Hemos elegido una variación de la tercera alternativa: almacenamos la información que habríamos obtenido con sort(1) en un archivo db. Mientras construimos este archivo db, que contiene un mapa de ids de cola al número de líneas con ese id, realizamos el máximo preprocesamiento posible. El registro preprocesado se imprime en un archivo temporal. La estructura del registro preprocesado es la misma que la del registro sin procesar: una línea de registro sin procesar produce una línea preprocesada. El registro preprocesado se convierte a dlf mediante lr_postfix2dlf_main(1), utilizando la información del archivo db.

Un buen efecto secundario de esta forma de procesar es que el registro se procesa en el orden cronológico original.

postfix2dlf rara vez se usará por sí solo, sino que es más probable que sea llamado por lr_log2report:

$ lr_log2report postfix < /var/log/mail.log > report

. Si realmente desea ejecutar este script de forma independiente (por ejemplo, para depuración), ejecútelo como:

$ LR_SERVICE=email LR_ID=`date +%s` /ruta/a/lire/convertors/postfix2dlf < /var/log/mail.log > mail.dlf

. Asegúrese de tener /ruta/a/libexec/lire y /ruta/a/lire/convertors en su PATH, y asegúrese de tener configurados TMPDIR, LR_DBFILE y LR_DBDIR. Podría ejecutar manualmente /ruta/a/etc/lire/profile_lean y /ruta/a/etc/lire/defaults para lograr esto.

LOGFORMAT

The input log lines are Postfix log lines. The conversion process is two-staged, because Postfix log lines are of a different format before and after the main logging daemon has done its work. We first convert the raw log file, then convert the main log file.

postfix2dlf_pre info read 195257 lines; output 177027 DLF lines; 3 errors
postfix2dlf_pre info memory stats: vsize=5900K rss=4508K majflt=430
postfix2dlf_pre info elapsed time in seconds real=626 user=449.16 system=8.7
postfix2dlf_main info read 177027 lines; output 61671 DLF lines; 0 errors
postfix2dlf_main info memory stats: vsize=5976K rss=4656K majflt=427
postfix2dlf_main info elapsed time in seconds real=245 user=152.05 system=4.15

.

EJEMPLOS

postfix2dlf se usará raramente por sí solo, pero es más probable que sea llamado por lr_log2report:

$ lr_run lr_log2report postfix < /var/log/maillog

ERRORES

Este script necesita mucho espacio en TMPDIR: crea un archivo temporal que es aproximadamente del mismo tamaño que el log sin procesar que se le está alimentando.

Ocasionalmente, postfix reutiliza sus queueids muy rápido. No podemos manejar esto.
