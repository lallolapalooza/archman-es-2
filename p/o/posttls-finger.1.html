POSTTLS-FINGER(1) Manual de comandos generales POSTTLS-FINGER(1)

NOMBRE

posttls-finger - Sondea las propiedades TLS de un servidor ESMTP o LMTP.

SINOPSIS

posttls-finger [opciones] [inet:]dominio[:puerto] [coincidencia ...]
posttls-finger -S [opciones] unix:ruta_acceso [coincidencia ...]

DESCRIPCIÓN


posttls-finger(1) se conecta al destino especificado e informa sobre información relacionada con TLS del servidor. Con SMTP, el destino es un nombre de dominio; con LMTP, es un nombre de dominio prefijado con inet: o una ruta de acceso prefijada con unix:. Si Postfix está compilado sin soporte TLS, el programa resultante posttls-finger(1) tiene una funcionalidad muy limitada y solo las opciones -a, -c, -h, -o, -S, -t, -T y -v están disponibles.

Nota: este es un programa de prueba no soportado. No se hace ningún intento de mantener la compatibilidad entre versiones sucesivas.

Para servidores SMTP que no soportan ESMTP, solo se informa el banner de saludo y la respuesta negativa EHLO. De lo contrario, la respuesta EHLO informada detalla más capacidades del servidor.

Si el soporte TLS está habilitado cuando se compila posttls-finger(1), y el servidor soporta STARTTLS, se intenta una negociación TLS.

Si el soporte DNSSEC está disponible, el nivel de seguridad TLS de la conexión (opción -l) por defecto es dane; consulte TLS_README para más detalles. De lo contrario, por defecto es secure. Esta configuración determina la política de coincidencia de certificados.

Si la negociación TLS tiene éxito, se informan los detalles del protocolo y cifrado TLS. Luego, el certificado del servidor se verifica de acuerdo con la política en el nivel de seguridad elegido (o por defecto). Con confianza basada en CA pública, cuando la opción -L incluye certmatch (verdadero por defecto), se realiza la coincidencia de nombres incluso si la cadena de certificados no es confiable. Esto registra los nombres encontrados en el certificado del servidor SMTP remoto y cuáles, si los hubiere, coincidirían si la cadena de certificados fuera confiable.

Nota: posttls-finger(1) no realiza ninguna consulta de tablas, por lo que no se consultan la tabla de políticas TLS ni las tablas obsoletas por sitio. No se comunica con el demonio tlsmgr(8) (ni con ningún otro demonio de Postfix); su caché de sesiones TLS se mantiene en memoria privada y desaparece cuando el proceso termina.

Con la opción -r retraso, si el servidor asigna un identificador de sesión TLS, la sesión TLS se almacena en caché. Luego, la conexión se cierra y se reabre después del retraso especificado, y posttls-finger(1) informa si la sesión TLS en caché se reutilizó.

Cuando el destino es un balanceador de carga, puede estar distribuyendo la carga entre múltiples cachés de servidores. Típicamente, cada servidor devuelve su nombre único en su respuesta EHLO. Si, al reconectar con -r, se detecta un nuevo nombre de servidor, se almacena en caché otra sesión para el nuevo servidor y la reconexión se repite hasta un número máximo de veces (por defecto 5) que se puede especificar a través de la opción -m.

La elección de SMTP o LMTP (opción -S) determina la sintaxis del argumento de destino. Con SMTP, se puede especificar un servicio en un puerto no predeterminado como host:servicio, y deshabilitar las búsquedas DNS MX (intercambiador de correo) con [host] o [host]:puerto. La forma [] es necesaria cuando se especifica una dirección IP en lugar de un nombre de host. Una dirección IPv6 tiene el formato [ipv6:dirección]. El puerto por defecto para SMTP se toma de la entrada smtp/tcp en /etc/services, por defecto 25 si la entrada no se encuentra.

Con LMTP, especifique unix:ruta_acceso para conectarse a un servidor local que escucha en un socket de dominio Unix enlazado a la ruta de acceso especificada; de lo contrario, especifique un prefijo opcional inet: seguido de un dominio y un puerto opcional, con la misma sintaxis que para SMTP. El puerto TCP por defecto para LMTP es 24.

Argumentos:

-a familia (por defecto: any)
Preferencia de familia de direcciones: ipv4, ipv6 o any. Al usar any, posttls-finger(1) seleccionará aleatoriamente una de las dos como la más preferida, y agotará todas las preferencias MX para la primera familia de direcciones antes de intentar cualquier dirección de la otra.
-A raíz_confianza.pem (por defecto: ninguna)
Una lista de archivos de raíz de confianza PEM que anulan la verificación de la cadena de confianza de CAfile y CApath. Especifique la opción varias veces para especificar varios archivos. Consulte la documentación de main.cf para smtp_tls_trust_anchor_file para obtener detalles.
-c
Deshabilita el registro de chat SMTP; solo se registra información relacionada con TLS.
-C
Imprime la cadena de confianza del certificado del servidor SMTP remoto en formato PEM. El DN del emisor, el DN del sujeto, las huellas dactilares del certificado y la clave pública (ver la opción -d mdalg más abajo) se imprimen encima de cada bloque de certificado PEM. Si especifica -F CAfile o -P CApath, la biblioteca OpenSSL puede aumentar la cadena con certificados de emisor faltantes. Para ver la cadena real enviada por el servidor SMTP remoto, deje CAfile y CApath sin configurar.
-d mdalg (por defecto: $smtp_tls_fingerprint_digest)
El algoritmo de resumen de mensajes a utilizar para informar las huellas dactilares del servidor SMTP remoto y compararlas con las huellas dactilares de certificado proporcionadas por el usuario (con los registros DANE TLSA, el algoritmo se especifica en el DNS). En versiones de Postfix anteriores a la 3.6, el valor por defecto era "md5".
-f
Busca el conjunto de registros DANE TLSA asociado incluso cuando un nombre de host no es un alias y sus registros de direcciones se encuentran en una zona sin firmar. Consulte smtp_tls_force_insecure_host_tlsa_lookup para obtener detalles.
-F CAfile.pem (por defecto: ninguna)
El CAfile en formato PEM para la verificación del certificado del servidor SMTP remoto. Por defecto, no se utiliza ningún CAfile y no se confían en CAs públicas.
-g grado (por defecto: medium)
El grado mínimo de cifrado TLS utilizado por posttls-finger(1). Consulte smtp_tls_mandatory_ciphers para obtener detalles.
-h búsqueda_host (por defecto: dns)
Los métodos de búsqueda de nombres de host utilizados para la conexión. Consulte la documentación de smtp_host_lookup para sintaxis y semántica.
-H archivos_cadena (por defecto: ninguno)
Lista de archivos con una secuencia de cadenas de certificados de cliente TLS codificadas en PEM. La lista se puede construir incrementalmente, especificando la opción varias veces, o todas a la vez a través de una lista de nombres de archivo separados por comas o espacios en blanco. Cada cadena comienza con una clave privada, seguida inmediatamente por el certificado correspondiente y, opcionalmente, por certificados de emisor adicionales. Cada nueva clave comienza una nueva cadena para el algoritmo correspondiente. Esta opción es mutuamente exclusiva con las opciones -k y -K a continuación.
-k archivo_certificado (por defecto: archivo_clave)
Archivo con la cadena de certificado de cliente TLS codificada en PEM. Esto es por defecto archivo_clave si se especifica uno.
-K archivo_clave (por defecto: archivo_certificado)
Archivo con la clave privada TLS del cliente codificada en PEM. Esto es por defecto archivo_certificado si se especifica uno.
-l nivel (por defecto: dane o secure)
El nivel de seguridad para la conexión, por defecto dane o secure dependiendo de si DNSSEC está disponible. Para sintaxis y semántica, consulte la documentación de smtp_tls_security_level. Cuando se soporta y selecciona dane o dane-only, si no se encuentran registros TLSA, o todos los registros encontrados no son utilizables, se utilizará el nivel secure en su lugar. El nivel de seguridad fingerprint le permite probar coincidencias de huellas dactilares de certificados o claves públicas antes de implementarlas en la tabla de políticas.
Nota, dado que posttls-finger(1) no entrega ningún correo, los niveles de seguridad none, may y encrypt no son muy útiles. Dado que may y encrypt no requieren certificados de par, o
s, por lo que no aprenderá mucho sobre los certificados del servidor SMTP remoto en estos niveles si también admite TLS anónimo (aunque puede aprender que el servidor admite TLS anónimo).
-L opciones_registro (por defecto: rutina,certmatch)
Opciones de registro TLS de grano fino. Para ajustar las características TLS registradas durante el apretón de manos TLS, especifique una o más de las siguientes:
0, ninguna
Estos no generan registro TLS; generalmente querrá más, pero esto es útil si solo desea la cadena de confianza:
$ posttls-finger -cC -L ninguna destino
1, rutina, resumen
Estos valores sinónimos generan un resumen normal de una línea de la conexión TLS.
2, depurar
Estos valores sinónimos combinan rutina, ssl-debug, cache y verbose.
3, ssl-expert
Estos valores sinónimos combinan debug con ssl-handshake-packet-dump. Para expertos solamente.
4, ssl-developer
Estos valores sinónimos combinan ssl-expert con ssl-session-packet-dump. Solo para expertos y, en la mayoría de los casos, use wireshark en su lugar.
ssl-debug
Activa el registro de OpenSSL del progreso del apretón de manos SSL.
ssl-handshake-packet-dump
Registra volcados de paquetes hexadecimales del apretón de manos SSL; solo para expertos.
ssl-session-packet-dump
Registra volcados de paquetes hexadecimales de toda la sesión SSL; solo útil para aquellos que pueden depurar problemas del protocolo SSL a partir de volcados hexadecimales.
untrusted
Registra problemas de verificación de la cadena de confianza. Esto se activa automáticamente en niveles de seguridad que utilizan nombres de pares firmados por Autoridades Certificadoras para validar certificados. Por lo tanto, aunque esta configuración se reconoce, usted debería nunca necesitar configurarla explícitamente.
peercert
Esto registra un resumen de una línea del asunto del certificado del servidor SMTP remoto, el emisor y las huellas digitales.
certmatch
Esto registra la coincidencia del certificado del servidor SMTP remoto, mostrando el CN y cada subjectAltName y qué nombre coincidió. Con DANE, registra la coincidencia del anclaje de confianza del registro TLSA y los certificados de entidad final.
cache
Esto registra las operaciones de caché de sesión, mostrando si la caché de sesión es efectiva con el servidor SMTP remoto. Se utiliza automáticamente al reconectar con la opción -r; rara vez es necesario configurarlo explícitamente.
verbose
Habilita el registro detallado en el controlador TLS de Postfix; incluye todo de peercert..cache y más.
El valor por defecto es rutina,certmatch. Después de una reconexión, peercert, certmatch y verbose se deshabilitan automáticamente mientras que cache y summary se habilitan.
-m contador (por defecto: 5)
Cuando se especifica la opción -r retraso, la opción -m determina el número máximo de intentos de reconexión a utilizar con un servidor detrás de un balanceador de carga, para ver si la caché de conexión es probable que sea efectiva para este destino. Algunos MTA no exponen la identidad del servidor subyacente en su respuesta EHLO; con estos servidores nunca habrá más de 1 intento de reconexión.
-M politica_mx_insegura (por defecto: dane)
La política TLS para hosts MX con registros TLSA "seguros" cuando el nivel de seguridad del destino siguiente es dane, pero el registro MX se encontró a través de una búsqueda MX "insegura". Consulte la documentación de main.cf para smtp_tls_dane_insecure_mx_policy para obtener detalles.
-o nombre=valor
Especificar cero o más veces para anular el valor del parámetro main.cf nombre con valor. Los casos de uso posibles incluyen la anulación de los valores de los parámetros de la biblioteca TLS, o "myhostname" para configurar el nombre EHLO SMTP enviado al servidor remoto.
-p protocolos (por defecto: >=TLSv1)
Protocolos TLS que posttls-finger(1) excluirá o incluirá. Consulte smtp_tls_mandatory_protocols para obtener detalles.
-P CApath/ (por defecto: ninguno)
El directorio CApath/ de OpenSSL (indexado a través de c_rehash(1)) para la verificación del certificado del servidor SMTP remoto. Por defecto, no se utiliza CApath y no se confían en CAs públicas.
-r retraso
Con una sesión TLS almacenable en caché, desconectar y volver a conectar después de retraso segundos. Informar si la sesión se reutiliza. Reintentar si se encuentra un nuevo servidor, hasta 5 veces o según lo especificado con la opción -m. Por defecto, la reconexión está deshabilitada; especifique un retraso positivo para habilitar este comportamiento.
-R
Usar búsqueda SRV en lugar de MX.
-s nombre_servidor
El nombre del servidor a enviar con la extensión Server Name Indication (SNI) TLS. Cuando el servidor tiene registros TLSA de DANE, este parámetro se ignora y se utiliza el dominio base TLSA en su lugar. De lo contrario, SNI no se utiliza por defecto, pero se puede habilitar especificando el valor deseado con esta opción.
-S
Deshabilitar SMTP; es decir, conectarse a un servidor LMTP. El puerto por defecto para LMTP sobre TCP es 24. Se pueden especificar puertos alternativos añadiendo ":nombre_servicio" o ":numeropuerto" al argumento de destino.
-t tiempo_espera (por defecto: 30)
El tiempo de espera de conexión TCP a utilizar. Este es también el tiempo de espera para leer el banner 220 del servidor remoto.
-T tiempo_espera (por defecto: 30)
El tiempo de espera del comando SMTP/LMTP para EHLO/LHLO, STARTTLS y QUIT.
-v
Habilita el registro detallado de Postfix. Especifique varias veces para aumentar el nivel de registro detallado.
-w
Habilita el modo envoltorio TLS de salida, o soporte SUBMISSIONS/SMTPS. Esto es típicamente proporcionado en el puerto 465 por servidores compatibles con el protocolo SMTP-in-SSL, en lugar del protocolo STARTTLS. El dominio/puerto de destino debe, por supuesto, proporcionar dicho servicio.
-x
Prefiere credenciales de servidor de clave pública sin formato (RPK) RFC7250 no X.509. Por defecto, solo se aceptan certificados X.509. Esto es análogo a establecer smtp_tls_enable_rpk = sí en el cliente smtp(8). En el nivel de seguridad de huella digital, cuando las claves públicas sin formato están habilitadas, solo se compararán las huellas digitales de clave pública (y no de certificado) con la lista especificada de argumentos de coincidencia. Las huellas digitales de certificado son frágiles cuando se solicitan claves públicas sin formato; el servidor puede, en algún momento, devolver solo la clave pública.
-X
Habilita el modo tlsproxy(8). Este es un modo no soportado, solo para desarrollo de programas.
[inet:]dominio[:puerto]
Conéctese a través de TCP al dominio dominio, puerto puerto. El puerto por defecto es smtp (o 24 con LMTP). Con SMTP, se realiza una búsqueda MX para resolver el dominio a un host, a menos que el dominio esté entre corchetes []. Si desea conectarse a un host MX específico, por ejemplo mx1.example.com, especifique [mx1.example.com] como destino y example.com como argumento de coincidencia. Al usar DNS, se asume que el dominio de destino está completamente cualificado y no se aplican dominios por defecto ni sufijos de búsqueda; debe usar nombres completamente cualificados o habilitar también las búsquedas de host nativas (estas no admiten dane o dane-only ya que no hay información de validación DNSSEC disponible a través de búsquedas nativas).
unix:ruta_acceso
Conéctese al socket de dominio UNIX en ruta_acceso. Solo LMTP.
coincidencia ...
Sin argumentos de coincidencia especificados, la coincidencia de nombre de par de certificado utiliza las estrategias por defecto compiladas para cada nivel de seguridad. Si especifica uno o más argumentos, estos se utilizarán como la lista de resúmenes de certificado o clave pública a coincidir para el nivel fingerprint, o como la lista de nombres DNS a coincidir en el certificado en los niveles verify y secure. Si el nivel de seguridad es dane, o dane-only, los nombres de coincidencia se ignoran y se utilizan las estrategias hostname, nexthop.
