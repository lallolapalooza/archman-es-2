POPEN(3P) Manual del programador POSIX POPEN(3P)

PROLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

popen — iniciar flujos de tubería hacia o desde un proceso

SINOPSIS

#include <stdio.h>
FILE *popen(const char *command, const char *mode);

DESCRIPCIÓN

La función popen() ejecutará el comando especificado por la cadena command. Creará una tubería entre el programa que llama y el comando ejecutado, y devolverá un puntero a un flujo que se puede usar para leer o escribir en la tubería.

El entorno del comando ejecutado será como si un proceso hijo se hubiera creado dentro de la llamada a popen() utilizando la función fork(), y el hijo invocara la utilidad sh utilizando la llamada:

execl(ruta_shell, "sh", "-c", command, (char *)0);

donde ruta_shell es una ruta de acceso no especificada para la utilidad sh.

La función popen() se asegurará de que todos los flujos de llamadas anteriores a popen() que permanezcan abiertos en el proceso padre se cierren en el nuevo proceso hijo.

El argumento mode para popen() es una cadena que especifica el modo de E/S:

1.
Si mode es r, cuando se inicia el proceso hijo, su descriptor de archivo STDOUT_FILENO será el extremo escribible de la tubería, y el descriptor de archivo fileno(stream) en el proceso que llama, donde stream es el puntero de flujo devuelto por popen(), será el extremo legible de la tubería.
2.
Si mode es w, cuando se inicia el proceso hijo, su descriptor de archivo STDIN_FILENO será el extremo legible de la tubería, y el descriptor de archivo fileno(stream) en el proceso que llama, donde stream es el puntero de flujo devuelto por popen(), será el extremo escribible de la tubería.
3.
Si mode es cualquier otro valor, el resultado no está especificado.

Después de popen(), tanto el proceso padre como el hijo serán capaces de ejecutarse de forma independiente antes de que cualquiera de ellos termine.

Los flujos de tubería son orientados a bytes.

VALOR DE RETORNO

Al completarse con éxito, popen() devolverá un puntero a un flujo abierto que se puede usar para leer o escribir en la tubería. De lo contrario, devolverá un puntero nulo y puede establecer errno para indicar el error.

ERRORES

La función popen() fallará si:

EMFILE
{STREAM_MAX} flujos están actualmente abiertos en el proceso que llama.

La función popen() puede fallar si:

EMFILE
{FOPEN_MAX} flujos están actualmente abiertos en el proceso que llama.
EINVAL
El argumento mode es inválido.

La función popen() también puede establecer valores de errno como se describe en fork() o pipe().

EJEMPLOS

Usar popen() para Obtener una Lista de Archivos de la Utilidad ls

El siguiente ejemplo demuestra el uso de popen() y pclose() para ejecutar el comando ls* con el fin de obtener una lista de archivos en el directorio actual:

#include <stdio.h>
...
FILE *fp;
int status;
char path[PATH_MAX];
fp = popen("ls *", "r");
if (fp == NULL)
    /* Manejar error */;
while (fgets(path, PATH_MAX, fp) != NULL)
    printf("%s", path);
status = pclose(fp);
if (status == -1) {
    /* Error reportado por pclose() */
    ...
} else {
    /* Usar macros descritas en wait() para inspeccionar `status' para
       determinar el éxito/fracaso del comando ejecutado por popen() */
    ...
}

USO DE APLICACION

Dado que los archivos abiertos se comparten, un comando de modo r puede usarse como un filtro de entrada y un comando de modo w como un filtro de salida.

La lectura con búfer antes de abrir un filtro de entrada puede dejar la entrada estándar de ese filtro mal posicionada. Problemas similares con un filtro de salida pueden prevenirse mediante una cuidadosa limpieza del búfer; por ejemplo, con fflush().

Un flujo abierto por popen() debe cerrarse con pclose().

El comportamiento de popen() se especifica para valores de mode de r y w. Modos como rb y wb pueden ser soportados por implementaciones específicas, pero estas no serían características portátiles. Tenga en cuenta que las implementaciones históricas de popen() solo verifican si el primer carácter de mode es r. Por lo tanto, un mode de robert the robot se trataría como mode r, y un mode de cualquier otra cosa se trataría como mode w.

Si la aplicación llama a waitpid() o waitid() con un argumento pid mayor que 0, y todavía tiene un flujo que fue llamado con popen() abierto, debe asegurarse de que pid no se refiera al proceso iniciado por popen().

Para determinar si el entorno especificado en el Volumen de Shell y Utilidades de POSIX.1‐2017 está presente, use la llamada a función:

sysconf(_SC_2_VERSION)

(Consulte sysconf()).

RACIONALE

No se debe utilizar la función popen() por programas que tengan privilegios de ID de usuario (o grupo) establecidos. En su lugar, se deben utilizar las funciones de la familia fork() y exec (excepto execlp() y execvp()). Esto evita cualquier manipulación imprevista del entorno del usuario que pudiera causar la ejecución de comandos no anticipados por el programa que llama.

Si los procesos original y el llamado con popen() pretenden leer o escribir, o leer y escribir, un archivo común, y cualquiera de ellos utilizará funciones de tipo FILE de C (fread(), fwrite(), etc.), se deben observar las reglas para compartir manejadores de archivos (consulte la Sección 2.5.1, Interacción de Descriptores de Archivos y Flujos de E/S Estándar).
