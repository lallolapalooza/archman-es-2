NOMBRE

podman-start - Inicia uno o más contenedores

SINOPSIS

podman start [opciones] contenedor ...

podman container start [opciones] contenedor ...

DESCRIPCIÓN

Inicia uno o más contenedores utilizando IDs de contenedor o nombres como entrada. Las opciones attach e interactive no se pueden utilizar para anular las opciones --tty e --interactive de cuando se creó el contenedor. Al iniciar un contenedor que ya está en ejecución con la opción --attach, Podman simplemente se adjunta al contenedor.

OPCIONES

--all

Inicia todos los contenedores; por defecto, solo los contenedores en ejecución.

--attach, -a

Adjunta STDOUT y STDERR del contenedor. El valor predeterminado es falso. Esta opción no se puede usar al iniciar varios contenedores.

--detach-keys=secuencia

Especifica la secuencia de teclas para desconectar un contenedor. El formato es un solo carácter [a-Z] o uno o más caracteres ctrl-<valor> donde <valor> es uno de: a-z, @, ^, [, , o _. Especificar "" deshabilita esta característica. El valor predeterminado es ctrl-p,ctrl-q.

Esta opción también se puede configurar en el archivo containers.conf(5).

--filter, -f

Filtra qué contenedores se iniciarán a partir de los argumentos dados. Se pueden dar varios filtros usando la opción --filter varias veces. Los filtros con la misma clave funcionan de forma inclusiva, con la única excepción de label, que es exclusiva. Los filtros con claves diferentes siempre funcionan de forma exclusiva.

Los filtros válidos se enumeran a continuación:

Filtro Descripción
id [ID] ID del contenedor (coincidencia de prefijo CID por defecto; acepta expresiones regulares)
name [Nombre] Nombre del contenedor (acepta expresiones regulares)
label [Clave] o [Clave=Valor] Etiqueta asignada a un contenedor
exited [Int] Código de salida del contenedor
status [Estado] Estado del contenedor: 'created', 'initialized', 'exited', 'paused', 'running', 'unknown'
ancestor [NombreImagen] Imagen o descendiente utilizada para crear el contenedor
before [ID] o [Nombre] Contenedores creados antes de este contenedor
since [ID] o [Nombre] Contenedores creados desde este contenedor
volume [NombreVolumen] o [PuntoMontajeDestino] Volumen montado en el contenedor
health [Estado] healthy o unhealthy
pod [Pod] Nombre o ID completo o parcial del pod
network [Red] Nombre o ID completo de la red
until [FechaHora] Contenedores creados antes de la duración o hora dadas.
command [Comando] el comando que está ejecutando el contenedor, solo se toma argv[0]

--interactive, -i

Cuando se establece en true, hace que stdin esté disponible para el proceso contenido. Si es false, el stdin del proceso contenido está vacío y se cierra inmediatamente.

Si está adjunto, stdin se canaliza al proceso contenido. Si está desconectado, la lectura de stdin se bloqueará hasta que se adjunte más tarde.

Advertencia: Podman consumirá la entrada de stdin tan pronto como esté disponible, incluso si el proceso contenido no la solicita.

--latest, -l

En lugar de proporcionar el nombre o ID del contenedor, utiliza el último contenedor creado. Nota: el último contenedor iniciado puede ser de otros usuarios de Podman en la máquina host. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sig-proxy

Reenvía las señales recibidas al proceso contenedor. SIGCHLD, SIGURG, SIGSTOP y SIGKILL no se reenvían.

El valor predeterminado es true cuando se adjunta, false en caso contrario.

EJEMPLO

Inicia un contenedor especificado:

podman start mi_servidor_web

Inicia varios contenedores:

podman start 860a4b231279 5421ab43b45

Inicia el contenedor especificado en modo interactivo con la terminal adjunta:

podman start --interactive --attach 860a4b231279

Inicia el último contenedor creado en modo interactivo (esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2)):

podman start -i -l

Inicia contenedores por etiqueta:

$ podman start --filter label=app=frontend
9351ccb3ef4272532bc0c188bd4f0ddfc2b0de217732cd108259ea126b014647

Inicia un contenedor por nombre:

$ podman start --filter name=backend-app1
93308911bd4769cda03b75eb7f56588e862e0ea3568f25e1e3defa4138b9b973

Inicia contenedores por estado:

$ podman start --filter status=exited
f8e85f84a749b205fb602895afa6ec8a866045ff27b82f843033712c8b93a2c9
34f997d354017a0076402c3a79245a5b8bd11b597c84385bec25ae8941fd5238
47972eb04aa7c77705b597a929957d1e8a392e00b44c0a2a7f88a01f9f860d11

Inicia un contenedor por nombre:

$ podman start --filter name=backend-app1
93308911bd4769cda03b75eb7f56588e862e0ea3568f25e1e3defa4138b9b973

Inicia contenedores por volumen:

$ podman start --filter volume=web-vol
4a3332649ed8bec1e0d82e113074b9a13d45582007aeac969c005992cc480a73

Inicia un contenedor por red:

$ podman start --filter network=web-net
4a3332649ed8bec1e0d82e113074b9a13d45582007aeac969c005992cc480a73
f8e85f84a749b205fb602895afa6ec8a866045ff27b82f843033712c8b93a2c9

$ podman start --filter ancestor=nginx
