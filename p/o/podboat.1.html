NOMBRE

podboat - un gestor de descargas de podcasts para terminales de texto

SINOPSIS

podboat [-C archivo-config] [-q archivo-cola] [-a] [-h]

DESCRIPCIÓN

Podboat es un gestor de podcasts para terminales de texto. Es un programa auxiliar para Newsboat que pone en cola las descargas de podcasts en un archivo. Estas descargas en cola pueden ser descargadas posteriormente con Podboat.

OPCIONES

-h, --help

Muestra la ayuda

-C archivo-config, --config-file=archivo-config

Usa un archivo de configuración alternativo

-q archivo-cola, --queue-file=archivo-cola

Usa un archivo de cola alternativo

--lock-file=archivo-bloqueo

Usa un archivo de bloqueo alternativo

-a, --autodownload

Inicia la descarga automática de todos los archivos en cola al iniciar

-l nivel-log, --log-level=nivel-log

Genera un archivo de log con un cierto nivel-log (valores válidos: del 1 al 6, para error de usuario, crítico, error, advertencia, información y depuración respectivamente). El nombre del archivo se puede especificar usando la opción --log-file. Si no se especifica, se genera un nombre de archivo con el formato podboat_<fecha-hora>.log

-d archivo-log, --log-file=archivo-log

Usa este archivo-log como salida al registrar mensajes de depuración. Ten en cuenta que esto solo funciona cuando se proporciona un nivel de log.

SOPORTE PARA PODCAST

Un podcast es un archivo multimedia distribuido a través de Internet utilizando feeds de sindicación como RSS, para su posterior reproducción en reproductores portátiles u ordenadores. Newsboat soporta la descarga, guardado y streaming de podcasts, aunque se necesita un reproductor multimedia externo para la reproducción. Este soporte difiere un poco de otros agregadores de podcasts o "podcatchers" en cómo se realiza.

El contenido de los podcasts se transporta en feeds RSS a través de etiquetas especiales llamadas "enclosures". Newsboat reconoce estas enclosures y almacena la información relevante para cada elemento de podcast que encuentra en un feed RSS. Desde la versión 2.0, también reconoce y maneja las extensiones Yahoo Media RSS.

Las APIs remotas no siempre listan estas "enclosures", por lo que los podcasts pueden faltar en Newsboat. Dichas APIs están marcadas en la sección relevante de nuestra documentación. Si falta una nota pero aún así no ves enclosures en Newsboat, por favor, crea un problema y lo resolveremos.

GESTIÓN DE ARCHIVOS DE AUDIO CON PODBOAT

Lo que el usuario puede hacer es añadir la URL de descarga del podcast a una cola de descargas. Alternativamente, Newsboat puede configurarse para hacerlo automáticamente. Esta cola se almacena en el archivo queue junto al archivo cache.db.

El usuario puede entonces usar el gestor de descargas podboat para descargar estos archivos a un directorio en el sistema de archivos local. Podboat viene con el paquete Newsboat, y tiene una apariencia muy similar a la de Newsboat. También comparte el mismo archivo de configuración.

Los podcasts que han sido descargados pero aún no se han reproducido permanecen en la cola pero se marcan como descargados. Puedes eliminarlos purgándolos de la cola con la tecla Shift + P. Después de haber reproducido un archivo y cerrar Podboat, se eliminará de la cola. El archivo descargado permanece en el sistema de archivos a menos que se active "delete-played-files".

Un "caso de uso" común es configurar Newsboat para poner automáticamente en cola las URLs de descarga de podcasts recién encontradas. Luego, el usuario recarga los feeds RSS de podcasts en Newsboat y, después de eso, usa Podboat para ver la cola actual y descargar selectivamente ciertos archivos o descargarlos todos juntos presionando A dentro de Podboat.

COMANDOS DE CONFIGURACIÓN

delete-played-files (parámetros: [sí/no]; valor por defecto: no)

Si se establece en sí, Podboat eliminará los archivos cuando se elimine su entrada de cola correspondiente (esto incluye las entradas "finalizadas" y "eliminadas"). (ejemplo: delete-played-files sí)

download-path (parámetros: <ruta>; valor por defecto: ~/)

Especifica el directorio donde Podboat descargará los archivos. Opcionalmente, se pueden usar marcadores de posición para colocar las descargas en una estructura de directorios. Consulta la sección "Strings de formato" del manual de Newsboat para obtener detalles sobre los formatos disponibles. Esta configuración se aplica en el momento de poner en cola; cambiarla no afectará las rutas de descarga de los podcasts que ya se hayan añadido a la cola. (ejemplo: download-path "~/Descargas/%h/%n")

download-filename-format (parámetros: <cadena>; valor por defecto: "%?u?%u&%Y-%b-%d-%H%M%S.desconocido?")

Especifica cómo nombrará Podboat los archivos que descarga (ver también download-path). Consulta la sección "Strings de formato" del manual de Newsboat para obtener detalles sobre los formatos disponibles. (ejemplo: download-filename-format "%F-%t.%e")

max-downloads (parámetros: <número>; valor por defecto: 1)

Especifica el número máximo de descargas paralelas cuando la descarga automática está habilitada. (ejemplo: max-downloads 3)

player (parámetros: <comando-reproductor>; valor por defecto: "")

Especifica el reproductor que se utilizará para la reproducción de archivos descargados. (ejemplo: player "mp3blaster")

podlist-format (parámetros: <formato>; valor por defecto: "%4i [%6dMB/%6tMB] [%5p %%] [%12K] %-20S %u → %F")

Esta variable define el formato de las entradas en la lista de descargas de Podboat. Consulta la sección correspondiente de la documentación para obtener más información sobre las strings de formato. (ejemplo: podlist-format "%i %u %-20S %F")

ARCHIVOS

Por defecto, Newsboat almacena todos los archivos en un formato Unix tradicional, es decir, en un "dotdir" ubicado en ~/.newsboat. Sin embargo, también soporta una forma moderna, la Especificación de Directorios Base de XDG, que divide los archivos entre las siguientes ubicaciones:

1.$XDG_CONFIG_HOME/newsboat/ (XDG_CONFIG_HOME por defecto es ~/.config)
2.$XDG_DATA_HOME/newsboat/ (XDG_DATA_HOME por defecto es ~/.local/share)

Si el directorio newsboat existe bajo XDG_CONFIG_HOME, entonces Newsboat usará los directorios XDG (creando el directorio de datos si es necesario). De lo contrario, Newsboat utilizará por defecto ~/.newsboat.

Si actualmente usas ~/.newsboat/ pero deseas migrar a directorios XDG, deberías mover los archivos de la siguiente manera:

config, urls

a $XDG_CONFIG_HOME/newsboat/

cache.db, history.search, history.cmdline, queue

a $XDG_DATA_HOME/newsboat/

Newsboat y Podboat también crean "archivos de bloqueo". Estos evitan que inicies dos instancias del mismo programa y, por lo tanto, que corrompas tus datos. Newsboat y Podboat eliminan estos archivos cuando sales del programa, por lo que no es necesario copiarlos a ningún sitio — solo ten en cuenta su existencia en caso de que escribas scripts que trabajen con cache.db o queue. Por defecto, los archivos de bloqueo se encuentran en las siguientes ubicaciones:

dotdir XDG
Newsboat ~/.newsboat/cache.db.lock $XDG_DATA_HOME/newsboat/cache.db.lock
Podboat

ARCHIVOS

~/.newsboat/pb-lock.pid

$XDG_DATA_HOME/newsboat/.lock

Newsboat coloca el archivo de bloqueo junto al archivo de caché, por lo que si especificas la configuración cache-file o pasas el argumento de línea de comandos —cache-file, la ruta al archivo de bloqueo también cambiará. El bloqueo de Podboat se puede colocar en otro lugar usando el argumento de línea de comandos —lock-file.

archivos de configuración (dotfiles)

~/.newsboat/config

~/.newsboat/queue

XDG

$XDG_CONFIG_HOME/newsboat/config

$XDG_DATA_HOME/newsboat/queue

Nota: si la variable de entorno XDG_CONFIG_HOME no está configurada, Podboat se comporta como si estuviera configurada a ~/.config. De manera similar, XDG_DATA_HOME tiene como valor predeterminado ~/.local/share.

ENTORNO

BROWSER

Indica a Newsboat qué navegador usar si no hay una configuración de browser en el archivo de configuración. Si esta variable no existe, se usará lynx(1) por defecto.

CURL_CA_BUNDLE

Indica a Newsboat que use el archivo de certificado especificado para verificar al par. El archivo puede contener múltiples certificados. Los certificados deben estar en formato PEM.

Esta opción es útil si tu libcurl está compilada sin información útil de certificados y no puedes recompilar la biblioteca tú mismo.

EDITOR

Indica a Newsboat qué editor de respaldo usar al editar el archivo urls a través de la operación edit-urls y si la variable de entorno VISUAL no está configurada. Si esta variable tampoco existe, se usará vi(1) por defecto.

NO_PROXY

Indica a Newsboat que ignore la configuración de proxy para ciertos sitios.

Esta variable contiene una lista separada por comas de nombres de host, dominios y direcciones IP.

Los nombres de dominio coinciden con subdominios, es decir, "example.com" también coincide con "foo.example.com". Los nombres de dominio que comienzan con un punto solo coinciden con subdominios, por ejemplo, ".example.com" coincide con "bar.example.com" pero no con el propio "example.com".

Las direcciones IPv6 se escriben sin corchetes y se *comparan como* *cadenas*. Por lo tanto, "::1" no coincide con "::0:1" aunque sea la misma dirección.

PAGER

Indica a Newsboat qué paginador usar si la configuración pager en el archivo de configuración se establece explícitamente como una cadena vacía.

TMPDIR

Indica a Newsboat que use el directorio especificado para almacenar archivos temporales. Si esta variable no existe, se usará /tmp por defecto.

VISUAL

Indica a Newsboat qué editor usar al editar el archivo urls a través de la operación edit-urls. Si esta variable no existe, se usará la variable de entorno EDITOR.

XDG_CONFIG_HOME

Indica a Newsboat qué directorio base usar para los archivos de configuración. Ver también la sección sobre archivos para más información.

XDG_DATA_HOME

Indica a Newsboat qué directorio base usar para los archivos de datos. Ver también la sección sobre archivos para más información.
