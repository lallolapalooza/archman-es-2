NOMBRE

podman-manifest-push - Envía una lista de manifiestos o un índice de imágenes a un registro

SINOPSIS

podman manifest push [opciones] nombre_lista_o_indice [destino]

DESCRIPCIÓN

Envía una lista de manifiestos o un índice de imágenes a un registro.

VALOR DE RETORNO

El ID de la imagen de la lista y el digest de la imagen del manifiesto.

OPCIONES

--add-compression=compresión

Asegura que la variante de compresión solicitada para cada plataforma se agregue a la lista de manifiestos, manteniendo intacta la instancia original en la misma lista de manifiestos. Los valores admitidos son (gzip, zstd y zstd:chunked). La siguiente bandera se puede usar varias veces.

Tenga en cuenta que --compression-format controla el formato de compresión de cada instancia en la lista de manifiestos. --add-compression agregará otra variante para cada instancia en la lista con las compresiones especificadas. --compression-format gzip --add-compression zstd enviará una lista de manifiestos donde cada instancia se comprime con gzip más una variante adicional de cada instancia comprimida con zstd.

--all

Envía las imágenes mencionadas en la lista de manifiestos o el índice de imágenes, además de la propia lista o índice. (Predeterminado: verdadero)

--authfile=ruta

Ruta del archivo de autenticación. El valor predeterminado es ${XDG_RUNTIME_DIR}/containers/auth.json en Linux y $HOME/.config/containers/auth.json en Windows/macOS. El archivo es creado por podman login. Si el estado de autorización no se encuentra allí, se revisa $HOME/.docker/config.json, que se establece usando docker login.

Nota: También existe la opción de anular la ruta predeterminada del archivo de autenticación estableciendo la variable de entorno REGISTRY_AUTH_FILE. Esto se puede hacer con export REGISTRY_AUTH_FILE=ruta.

--cert-dir=ruta

Usa certificados en ruta (*.crt, *.cert, *.key) para conectarte al registro. (Predeterminado: /etc/containers/certs.d) Para obtener detalles, consulta containers-certs.d(5). (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--compression-format=gzip | zstd | zstd:chunked

Especifica el formato de compresión a utilizar. Los valores admitidos son: gzip, zstd y zstd:chunked. El valor predeterminado es gzip a menos que se anule en el archivo containers.conf. zstd:chunked es incompatible con el cifrado de imágenes y se tratará como zstd con una advertencia en ese caso.

--compression-level=nivel

Especifica el nivel de compresión a utilizar. El valor es específico del algoritmo de compresión utilizado, por ejemplo, para zstd los valores aceptados están en el rango 1-20 (inclusive) con un predeterminado de 3, mientras que para gzip es 1-9 (inclusive) y tiene un predeterminado de 5.

--creds=[usuario[:contraseña]]

El [usuario[:contraseña]] a utilizar para autenticarse con el registro, si es necesario. Si uno o ambos valores no se proporcionan, aparece un aviso en la línea de comandos y se puede introducir el valor. La contraseña se introduce sin eco.

Tenga en cuenta que las credenciales especificadas solo se utilizan para autenticarse en los registros de destino. No se utilizan para espejos ni cuando el registro se reescribe (ver containers-registries.conf(5)); para autenticarse en ellos, considere usar un archivo containers-auth.json(5) .

--digestfile=ArchivoDigest

Después de copiar la imagen, escribe el digest de la imagen resultante en el archivo.

--force-compression

Si está establecido, el envío utiliza el algoritmo de compresión especificado incluso si el destino ya contiene una variante comprimida de manera diferente. Predeterminado: verdadero si --compression-format se especifica explícitamente en la línea de comandos, falso en caso contrario.

--format, -f=formato

Tipo de lista de manifiestos (oci o v2s2) a utilizar al enviar la lista (predeterminado es oci).

--quiet, -q

Al escribir el manifiesto, suprimir la salida de progreso

--remove-signatures

No copiar firmas al enviar imágenes.

--rm

Eliminar la lista de manifiestos o el índice de imágenes del almacenamiento local si el envío tiene éxito.

--sign-by=huella_digital

Firma las imágenes enviadas con una firma de “firma simple” utilizando la clave especificada. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sign-by-sigstore=archivo_param

Agrega una firma sigstore basada en opciones adicionales especificadas en un archivo de parámetros de firma sigstore de un contenedor archivo_param. Consulta containers-sigstore-signing-params.yaml(5) para obtener detalles sobre el formato del archivo.

--sign-by-sigstore-private-key=ruta

Firma las imágenes enviadas con una firma sigstore utilizando una clave privada en la ruta especificada. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sign-by-sq-fingerprint=huella_digital

Agrega una firma de “firma simple” utilizando una clave Sequoia-PGP con la huella digital especificada. (Esta opción no está disponible con el cliente Podman remoto, incluidas las máquinas Mac y Windows (excluyendo WSL2))

--sign-passphrase-file=ruta

Si firma la imagen (usando --sign-by, sign-by-sq-fingerprint o --sign-by-sigstore-private-key), lee la contraseña a utilizar desde la ruta especificada.

--tls-verify

Requiere HTTPS y verifica los certificados al contactar los registros (predeterminado: verdadero). Si se establece explícitamente en verdadero, se utiliza la verificación TLS. Si se establece en falso, no se utiliza la verificación TLS. Si no se especifica, se utiliza la verificación TLS a menos que el registro de destino esté listado como un registro inseguro en containers-registries.conf(5)

DESTINO

DESTINO es la ubicación a la que se envía la imagen del contenedor. Admite todos los transportes de containers-transports(5). Si no se especifica ningún transporte, se utiliza el transporte docker (es decir, registro de contenedores). Para clientes remotos, incluidas las máquinas Mac y Windows (excluyendo WSL2), docker es el único transporte admitido.

EJEMPLOS

Enviar lista de manifiestos a un registro de contenedores:

podman manifest push mylist:v1.11 docker://registry.example.org/mylist:v1.11

VER TAMBIÉN

podman(1), podman-manifest(1), containers-transports(5)

NAME

podman-manifest-push - Push a manifest list to a container registry

SYNOPSIS

podman manifest push [options] manifest-list destination

DESCRIPTION

Push a manifest list to a container registry. The manifest list may be local or remote.

The manifest-list argument is the name of the manifest list to push. This can be a name that was previously created with podman manifest create, or it can be the name of an image that contains a manifest list. The manifest-list can also be a URL to a manifest list.

The destination argument is the name of the destination registry and repository to push the manifest list to. The format is [registry/][namespace/]repository[:tag].

If the manifest list is local, it is pushed to the specified destination. If the manifest list is remote, it is pulled and then pushed to the specified destination.

By default, podman manifest push pushes the manifest list and all images referenced in the manifest list. If you want to push only the manifest list, use the --all=false option.

When pushing a manifest list to a registry, Podman will automatically create the necessary tags for the manifest list and the images referenced in the manifest list.

RETURN VALUE

Returns 0 if the command is successful, or a non-zero value otherwise.

The command will exit with 1 if the manifest list does not exist or if the destination is not accessible.

OPTIONS

Option Description
--all=true|false If true, push all images referenced in the manifest list. If false, push only the manifest list. The default is true.
--authfile path Path to the authentication file. The default is ${XDG_RUNTIME_DIR}/containers/auth.json.
--cert-dir path Use directories with certificates for connecting to the registry.
--creds string Use authentication headers in the form of user:password.
--force Force push the manifest list, overwriting any existing manifest list at the destination.
--tls-verify=true|false Require TLS server certificate verification. The default is true.

DESTINATION

The destination can be specified in the following formats:

  • [registry/][namespace/]repository[:tag]

EXAMPLES

Push a local manifest list to a remote registry:

$ podman manifest push my-manifest-list docker.io/myuser/myimage:latest

Push a remote manifest list to a remote registry:

$ podman manifest push docker.io/myuser/myimage:latest docker.io/myuser/myimage:v1.0

Push only the manifest list, not the images:

$ podman manifest push --all=false my-manifest-list docker.io/myuser/myimage:latest
