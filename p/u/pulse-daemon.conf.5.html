NOMBRE

pulse-daemon.conf - Archivo de configuración del demonio PulseAudio

SINOPSIS

~/.config/pulse/daemon.conf

~/.config/pulse/daemon.conf.d/*.conf

/etc/pulse/daemon.conf

/etc/pulse/daemon.conf.d/*.conf

DESCRIPCIÓN

El servidor de sonido PulseAudio lee directivas de configuración de un archivo de configuración al inicio. Si existe el archivo por usuario ~/.config/pulse/daemon.conf, se utiliza; de lo contrario, se usa el archivo de configuración del sistema /etc/pulse/daemon.conf. Además de esos archivos principales, las directivas de configuración también se pueden colocar en archivos bajo los directorios ~/.config/pulse/daemon.conf.d/ y /etc/pulse/daemon.conf.d/. Estos archivos deben tener la extensión de nombre de archivo .conf, pero por lo demás, los nombres de archivo se pueden elegir libremente. Los archivos bajo daemon.conf.d se procesan en orden alfabético. En caso de que la misma opción se establezca en varios archivos, el último archivo en establecer una opción anula las anteriores. El archivo principal daemon.conf se procesa primero, por lo que las opciones establecidas en los archivos bajo daemon.conf.d anulan el archivo principal.

Tenga en cuenta que el servidor también lee un script de configuración al inicio. Consulte default.pa(5).

El archivo de configuración es una simple colección de declaraciones de variables. Si el analizador del archivo de configuración encuentra ; o #, ignora el resto de la línea hasta su final.

Para las configuraciones que toman un argumento booleano, los valores true, yes, on y 1 son equivalentes, respectivamente; false, no, off, 0.

DIRECTIVAS GENERALES

daemonize= Se ejecuta como demonio después del inicio. Toma un valor booleano, por defecto es no. La opción de línea de comandos --daemonize tiene precedencia.
fail= Falla al iniciar si alguna de las directivas en el script de configuración default.pa falla. Toma un argumento booleano, por defecto es yes. La opción de línea de comandos --fail tiene precedencia.
allow-module-loading= Permite/desactiva la carga de módulos después del inicio. Esta es una medida de seguridad que, si se deshabilita, asegura que no se puedan cargar más módulos en el servidor PulseAudio después de que se haya completado el inicio. Se recomienda deshabilitar esto cuando system-instance esté habilitado. Tenga en cuenta que ciertas características como el soporte automático de conexión en caliente no funcionarán si esta opción está habilitada. Toma un argumento booleano, por defecto es yes. La opción de línea de comandos --disallow-module-loading tiene precedencia.
allow-exit= Permite/desactiva la salida a petición del usuario. Por defecto es yes.
resample-method= El algoritmo de remuestreo a utilizar. Use uno de src-sinc-best-quality, src-sinc-medium-quality, src-sinc-fastest, src-zero-order-hold, src-linear, trivial, speex-float-N, speex-fixed-N, ffmpeg, soxr-mq, soxr-hq, soxr-vhq. Consulte la documentación de libsamplerate y speex para obtener explicaciones de los diferentes métodos src- y speex-, respectivamente. El método trivial es el algoritmo más básico implementado. Si tiene limitaciones de CPU, considere usarlo. Por otro lado, tiene la peor calidad de todos. Los remuestreadores Speex toman una configuración de calidad entera en el rango 0..10 (malo...bueno). Existen en dos sabores: fixed y float. El primero usa números de punto fijo, el segundo depende de números de punto flotante. En la mayoría de las CPU de escritorio, el remuestreador de punto flotante es mucho más rápido y también ofrece una calidad ligeramente mejor. Las familias de métodos soxr se basan en libsoxr, una biblioteca de remuestreo de la utilidad de procesamiento de sonido SoX. La variante mq tiene el mejor rendimiento de las tres. La hq es más costosa y, según los desarrolladores de SoX, se considera la mejor opción para audio de hasta 16 bits por muestra. La variante vhq tiene más precisión que hq y es más adecuada para muestras más grandes. Los remuestreadores Soxr generalmente ofrecen una mejor calidad con menos CPU en comparación con otros remuestreadores, como speex. La desventaja es que pueden agregar un retraso significativo a la salida (generalmente hasta alrededor de 20 ms, en casos raros más). Consulte la salida de dump-resample-methods para obtener una lista completa de todos los remuestreadores disponibles. Por defecto es speex-float-1. La opción de línea de comandos --resample-method tiene precedencia. Tenga en cuenta que algunos módulos sobrescriben o permiten sobrescribir el remuestreador a usar.
avoid-resampling= Si se establece, intente configurar el dispositivo para evitar el remuestreo. Esto solo funciona en dispositivos que admiten la reconfiguración de su tasa, y cuando no se están reproduciendo o capturando otros flujos de audio. El dispositivo tampoco se configurará a una tasa inferior a las tasas de muestreo predeterminada y alternativas.
enable-remixing= Si está deshabilitado, nunca remezcle hacia arriba o hacia abajo los canales a diferentes mapas de canales. En su lugar, realice solo una coincidencia basada en nombres. Por defecto es yes. No se conoce ningún caso de uso válido para establecer esta opción en no, por lo tanto, esta opción está obsoleta y puede eliminarse en una versión futura de PulseAudio.
remixing-use-all-sink-channels= Si está habilitado, use todos los canales del sumidero al remezclar. De lo contrario, remezcle al conjunto mínimo de canales del sumidero necesario para reproducir todos los canales de la fuente. (Esto no tiene efecto en la remezcla LFE). Por defecto es yes.
enable-lfe-remixing= Esta es una forma de establecer remixing-produce-lfe y remixing-consume-lfe al mismo valor a la vez. Esta opción solo existe por compatibilidad hacia atrás y puede eliminarse en una versión futura de PulseAudio.
remixing-produce-lfe= Si está habilitado, y la entrada del sumidero no tiene el canal LFE, sintetiza el canal LFE de salida como un promedio (filtrado de paso bajo, si lfe-crossover-freq no es 0) de todos los canales de entrada. Además, cuando lfe-crossover-freq no es 0, filtra las frecuencias bajas de otros canales mientras produce una salida LFE sintética. Si está deshabilitado, el canal LFE de salida solo obtendrá una señal cuando también esté disponible un canal LFE de entrada. Por defecto es no.
remixing-consume-lfe= Si está habilitado, y el sumidero no tiene un canal LFE, redirige el canal LFE de entrada (si lo hay) a otros canales. Si está deshabilitado, el canal LFE de entrada permanecerá sin usar a menos que el sumidero también tenga el canal LFE. Por defecto es no.
lfe-crossover-freq= La frecuencia de cruce (en Hz) para el filtro LFE. Establézcala en 0 para deshabilitar el filtro LFE. Por defecto es 0.
use-pid-file= Crea un archivo PID en el directorio de ejecución ($XDG_RUNTIME_DIR/pulse/pid). Si esto está habilitado, puede usar comandos como --kill o --check. Si planea iniciar más de un proceso PulseAudio por usuario, es mejor deshabilitar esta opción ya que efectivamente deshabilita instancias múltiples. Toma un argumento booleano, por defecto es yes. La opción de línea de comandos --use-pid-file tiene precedencia.
cpu-limit= Si está deshabilitado, no instale el limitador de carga de CPU, incluso en plataformas donde sea compatible. Esta opción es útil al depurar/perfilar PulseAudio para deshabilitar señales SIGXCPU molestas. Toma un argumento booleano, por defecto es no. El argumento de línea de comandos --no-cpu-limit tiene precedencia.
system-instance= Ejecuta el demonio como una instancia del sistema, requiere privilegios de root. Toma un argumento booleano, por defecto es no. El argumento de línea de comandos --system tiene precedencia.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

MISCELANEOUS

daemonize= Daemonize into the background after startup. Takes a boolean argument, defaults to no. The --daemonize command line argument takes precedence.
fail-if-not-running= Exit with an error code if PulseAudio daemon is not running. Takes a boolean argument, defaults to no. This is useful for scripts that need to ensure that PulseAudio is running before they proceed.
allow-simultaneous-clients= Allow multiple clients to run simultaneously. Takes a boolean argument, defaults to yes. Setting this to no is useful for special applications that do not want other applications to access the sound device. If set to no, PulseAudio will exit if another client is already running.
use-pid-file= Create a PID file when daemonizing. Takes a boolean argument, defaults to yes. The PID file is located at /run/pulseaudio.pid. If this is disabled, it's not possible to detect if PulseAudio is already running, and it's not possible to stop PulseAudio gracefully using pulseaudio -k.
system-instance= Run a system-wide instance of PulseAudio. Takes a boolean argument, defaults to no. If set to yes, PulseAudio will run as the root user and will serve all users on the system. This is typically used on systems that do not have a dedicated sound server per user. Note that this option is often considered less secure and less flexible than running per-user instances. The local-server-type option takes precedence over this option.
local-server-type= Por favor, no uses esta opción si no es necesario. Esta opción es útil actualmente solo cuando deseas que los clientes D-Bus utilicen un servidor remoto. Esta opción puede ser eliminada en futuras versiones. Si solo deseas ejecutar PulseAudio en modo de sistema, usa la opción system-instance. Esta opción toma como argumento user, system o none. Es esencialmente un duplicado de la opción system-instance. La diferencia es la opción none, que es útil cuando deseas usar un servidor remoto con clientes D-Bus. Si tanto esta como system-instance están definidas, esta opción tiene precedencia. Por defecto, el valor es el que tenga establecido system-instance.
enable-shm= Habilita la transferencia de datos a través de memoria compartida POSIX o memfd. Toma un argumento booleano, por defecto es yes. El argumento de línea de comandos --disable-shm tiene precedencia.
enable-memfd=. Habilita la memoria compartida memfd. Toma un argumento booleano, por defecto es yes.
shm-size-bytes= Establece el tamaño del segmento de memoria compartida para el demonio, en bytes. Si se deja sin especificar o se establece en 0, utilizará un valor predeterminado específico del sistema, generalmente 64 MiB. Ten en cuenta que normalmente no es necesario cambiar este valor, a menos que estés ejecutando un kernel de SO que no realiza sobre-asignación de memoria.
lock-memory= Bloquea todo el proceso de PulseAudio en la memoria. Si bien esto puede aumentar la seguridad contra interrupciones cuando se usa junto con la planificación en tiempo real, esto quita mucha memoria a otros procesos y por lo tanto podría ralentizar considerablemente tu sistema. Por defecto es no.
flat-volumes= Habilita volúmenes 'planos', es decir, cuando sea posible, permite que el volumen de la salida sea igual al máximo de los volúmenes de las entradas conectadas a ella. Toma un argumento booleano, por defecto es no.
rescue-streams= Habilita el rescate de flujos si la salida o fuente utilizada deja de estar disponible. Toma un argumento booleano. Si se establece en yes, pulseaudio intentará mover los flujos de una salida o fuente que deja de estar disponible a la salida o fuente predeterminada. Si se establece en no, los flujos serán eliminados si la salida o fuente correspondiente desaparece. Por defecto es yes.

PLANIFICACIÓN

high-priority= Renombra el demonio después de iniciarse para que sea un proceso de alta prioridad. Esto es una buena idea si experimentas interrupciones durante la reproducción. Sin embargo, esto es un problema de seguridad, ya que funciona solo cuando se llama SUID root, o se utiliza RLIMIT_NICE. La raíz se elimina inmediatamente después de obtener el nivel de nice al inicio, por lo que es presumiblemente seguro. Consulta pulseaudio(1) para más información. Toma un argumento booleano, por defecto es yes. La opción de línea de comandos --high-priority tiene precedencia.
realtime-scheduling= Intenta adquirir la planificación SCHED_FIFO para los hilos de IO. Las mismas preocupaciones de seguridad que se mencionan anteriormente aplican. Sin embargo, si PA entra en un bucle infinito, la planificación en tiempo real causa un bloqueo del sistema. Por lo tanto, la planificación en tiempo real solo debe habilitarse en máquinas de confianza por ahora. Ten en cuenta que solo los hilos de IO de PulseAudio se configuran en tiempo real. El hilo de control se deja como un hilo planificado normalmente. Por lo tanto, habilitar la opción high-priority es ortogonal. Consulta pulseaudio(1) para más información. Toma un argumento booleano, por defecto es yes. La opción de línea de comandos --realtime tiene precedencia.
realtime-priority= La prioridad en tiempo real a adquirir, si realtime-scheduling está habilitado. Nota: JACK usa 10 por defecto, 9 para clientes. Por lo tanto, se recomienda elegir las prioridades en tiempo real de PulseAudio más bajas. Algunos hilos de PulseAudio podrían elegir una prioridad un poco más baja o más alta que el valor especificado. Por defecto es 5.
nice-level= El nivel de nice a adquirir para el demonio, si high-priority está habilitado. Nota: en algunas distribuciones X11 usa -10 por defecto. Por defecto es -11.

TIEMPOS INACTIVOS

exit-idle-time= Termina el demonio después de que el último cliente se cierra y pasa este tiempo en segundos. Usa un valor negativo para deshabilitar esta función. Por defecto es 20. La opción de línea de comandos --exit-idle-time tiene precedencia.

Cuando PulseAudio se ejecuta en modo por usuario y detecta una sesión de inicio de sesión, cualquier valor positivo se restablecerá a 0 para que PulseAudio termine inmediatamente al cerrar la sesión. Un valor positivo, por lo tanto, solo tiene efecto en entornos donde no hay soporte para el seguimiento de sesiones de inicio de sesión (o si el usuario inicia sesión sin una sesión iniciada, también conocido como "lingering"). Un valor negativo aún puede usarse para deshabilitar la salida automática.

Cuando PulseAudio se ejecuta en modo de sistema, la salida automática siempre está deshabilitada, por lo que esta opción no hace nada.

scache-idle-time= Descarga las entradas de caché de muestras cargadas automáticamente después de estar inactivas durante este tiempo en segundos. Por defecto es 20. La opción de línea de comandos --scache-idle-time tiene precedencia.

RUTAS

dl-search-path= La ruta donde buscar objetos compartidos dinámicos (DSOs/plugins). Puedes especificar más de una ruta separada por dos puntos. La ruta predeterminada depende de la configuración en tiempo de compilación. La opción de línea de comandos --dl-search-path tiene precedencia.
default-script-file= El archivo de script de configuración predeterminado a cargar. Especifica una cadena vacía para no cargar un archivo de script predeterminado. El comportamiento predeterminado es cargar ~/.config/pulse/default.pa, y si ese archivo no existe, recurre a la versión instalada en todo el sistema /etc/pulse/default.pa. Si se ejecuta en modo de sistema, se utiliza el archivo /etc/pulse/system.pa en su lugar. Si se pasa -n en la línea de comandos o se deshabilita default-script-file=, se ignora el archivo de script de configuración predeterminado.
load-default-script-file= Carga el archivo de script de configuración predeterminado según lo especificado en default-script-file=. Por defecto es yes.

REGISTRO

log-target= El destino de registro predeterminado. Usa stderr, syslog, journal (opcional), auto, file:PATH o newfile:PATH. En sistemas tradicionales auto es equivalente a syslog. En sistemas habilitados para systemd, auto es equivalente a journal, en caso de que daemonize esté habilitado, y a stderr de lo contrario. Si se establece en file:PATH, el registro se dirige al archivo indicado por PATH. newfile:PATH es igual a file:PATH en otros aspectos, pero los archivos existentes nunca se sobrescriben. Si el archivo especificado ya existe, se agrega un sufijo al nombre del archivo para evitar sobrescribirlo. Por defecto es auto. La opción de línea de comandos --log-target tiene precedencia.
log-level= Nivel de registro, uno de debug, info, notice, warning, error. Los mensajes de registro con un nivel de registro inferior al especificado aquí no se registrarán. Por defecto es notice. La opción de línea de comandos --log-level tiene precedencia. La opción -v de línea de comandos puede alterar esta configuración.
log-meta= Con cada mensaje registrado, registra la ubicación del código desde donde se generó el mensaje. Por defecto es no.
log-time= Con cada mensaje registrado, registra el tiempo relativo desde el inicio. Por defecto es no.
log-backtrace= Cuando es mayor que 0, con cada mensaje registrado, registra un rastreo de pila de código hasta el número especificado de marcos de pila. Por defecto es 0.

LÍMITES DE RECURSOS

Consulta getrlimit(2) para más información. Establecido en -1 si PulseAudio no debe tocar el límite de recursos. No todos los límites de recursos están disponibles en todos los sistemas operativos.

NAME

pulse-daemon.conf

PulseAudio daemon configuration file

SYNOPSIS

~/.config/pulse/daemon.conf, /etc/pulse/daemon.conf

DESCRIPTION

This file is used to configure the PulseAudio sound server daemon. It is read by the daemon on startup. Settings can be overridden by command line arguments or by client configuration files.

The configuration file is a simple key-value pair file. Blank lines and lines starting with semicolons are ignored.

Comments may be introduced with a semicolon, and are effective until the end of the line.

The settings are grouped into sections, indicated by square brackets.

GENERAL DIRECTIVES

daemonize=
If set to yes, the daemon will fork into the background. Default: yes.
fail-if-running=
If set to yes, the daemon will exit if another instance is already running. Default: yes.
allow-simulation=
If set to yes, the daemon will allow multiple instances to run, each simulating a sound server. Default: no.
flat-volumes=
If set to yes, all sinks and sources will have their volume adjusted separately. Default: yes.
artificial-masters=
If set to yes, artificial master sink/source volumes are created. Default: yes.
realtime-volumes=
If set to yes, realtime volumes are used. Default: yes.
log-target=
Where to send log messages. Possible values are: auto, syslog, stderr, stdout, null. Default: auto.
log-level=
Set the verbosity of the logging. Possible values are: quiet, error, warning, notice, info, debug. Default: notice.
log-time=
If set to yes, timestamps are printed in log messages. Default: yes.
log-rate=
If set to yes, sample rates are printed in log messages. Default: no.
exit-on-idle=
If set to yes, the daemon will exit when there are no active clients. Default: no.
idle-timeout=
If exit-on-idle is enabled, this option sets the time in seconds after which the daemon will exit if there are no clients. Default: 0 (never exit).
cleanup-shm-on-exit=
If set to yes, shared memory segments are cleaned up on exit. Default: yes.
use-pidfile=
If set to yes, a PID file is created. Default: yes.
pid-file=
The path to the PID file. Default: /run/pulseaudio.pid.
xtalk-prevent=
If set to yes, cross-talk prevention is enabled for sinks that support it. Default: no.

SCHEDULING

high-priority=
If set to yes, the daemon will try to acquire and maintain a high scheduling priority. Default: yes.
nice-level=
Sets the nice level of the daemon when high-priority is enabled. Default: -11.
realtime-scheduling=
If set to yes, the daemon will try to acquire and maintain real-time scheduling priority. Default: yes.
realtime-priority=
Sets the real-time priority of the daemon when realtime-scheduling is enabled. Default: 5.
realtime-relax-semaphore=
If set to yes, the daemon will try to relax the semaphore for realtime scheduling. Default: no.

IDLE TIMES

timeout-stream=
The time in seconds after which an unused stream is considered stale and will be destroyed. Default: 10.
timeout-client=
The time in seconds after which an unused client is considered stale and will be disconnected. Default: 5.
timeout-sink=
The time in seconds after which an unused sink is considered stale and will be suspended. Default: 10.
timeout-source=
The time in seconds after which an unused source is considered stale and will be suspended. Default: 10.

PATHS

default-sample-channels=
The default number of sample channels for sinks and sources. Default: 2.
default-sample-rate=
The default sample frequency for sinks and sources. Default: 44100.
default-sample-format=
The default sample format for sinks and sources. Default: s16le.
default-channel-map=
The default channel map for sinks and sources. Default: front-left,front-right.
default-fragments=
The default number of fragments for sinks and sources. Default: 4.
default-fragment-size-msec=
The default fragment size in milliseconds for sinks and sources. Default: 25.
shm-size-bytes=
Size in bytes of the shared memory segment used for transferring samples. Default: 0 (auto).

LOGGING

log-target=
Where to send log messages. Possible values are: auto, syslog, stderr, stdout, null. Default: auto.
log-level=
Set the verbosity of the logging. Possible values are: quiet, error, warning, notice, info, debug. Default: notice.
log-time=
If set to yes, timestamps are printed in log messages. Default: yes.
log-rate=
If set to yes, sample rates are printed in log messages. Default: no.

RESOURCE LIMITS

These settings control the resource limits for the daemon. They are only effective if the system supports setting resource limits.

rlimit-memlock Defaults to 16 KiB. Please note that the JACK client libraries may require more locked memory.
rlimit-nice Defaults to 31. Please make sure that the default nice level as configured with nice-level fits in this resource limit, if high-priority is enabled.
rlimit-rtprio Defaults to 9. Please make sure that the default real-time priority level as configured with realtime-priority= fits in this resource limit, if realtime-scheduling is enabled. The JACK client libraries require a real-time priority of 9 by default.
rlimit-rttime Defaults to 1000000.

DEFAULT DEVICE SETTINGS

Most drivers try to open the audio device with these settings and then fall back to lower settings. The default settings are CD quality: 16bit native endian, 2 channels, 44100 Hz sampling.

default-sample-format= The default sampling format. See https://www.freedesktop.org/wiki/Software/PulseAudio/Documentation/User/SupportedAudioFormats/ for possible values.
default-sample-rate= The default sample frequency.
default-sample-channels The default number of channels.
default-channel-map The default channel map.
alternate-sample-rate The alternate sample frequency. Sinks and sources will use either the default-sample-rate value or this alternate value, typically 44.1 or 48kHz. Switching between default and alternate values is enabled only when the sinks/sources are suspended. This option is ignored in passthrough mode where the stream rate will be used. If set to the same value as the default sample rate, this feature is disabled.

DEFAULT FRAGMENT SETTINGS

Some hardware drivers require the hardware playback buffer to be subdivided into several fragments. It is possible to change these buffer metrics for machines with high scheduling latencies. Not all possible values that may be configured here are available in all hardware. The driver will find the nearest setting supported. Modern drivers that support timer-based scheduling ignore these options.

default-fragments= The default number of fragments. Defaults to 4.
default-fragment-size-msec=The duration of a single fragment. Defaults to 25ms (i.e. the total buffer is thus 100ms long).

DEFAULT DEFERRED VOLUME SETTINGS

With the flat volume feature enabled, the sink HW volume is set to the same level as the highest volume input stream. Any other streams (with lower volumes) have the appropriate adjustment applied in SW to bring them to the correct overall level. Sadly hardware mixer changes cannot be timed accurately and thus this change of volumes can sometimes cause the resulting output sound to be momentarily too loud or too soft. So to ensure SW and HW volumes are applied concurrently without any glitches, their application needs to be synchronized. The sink implementation needs to support deferred volumes. The following parameters can be used to refine the process.

enable-deferred-volume= Enable deferred volume for the sinks that support it. This feature is enabled by default.
deferred-volume-safety-margin-usec= The amount of time (in usec) by which the HW volume increases are delayed and HW volume decreases are advanced. Defaults to 8000 usec.
deferred-volume-extra-delay-usec= The amount of time (in usec) by which HW volume changes are delayed. Negative values are also allowed. Defaults to 0.
