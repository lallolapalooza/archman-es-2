PUTENV(3P) Manual de Programador POSIX PUTENV(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

putenv — cambiar o añadir un valor a un entorno

SINOPSIS

#include <stdlib.h>
int putenv(char *string);

DESCRIPCIÓN

La función putenv() utiliza el argumento string para establecer valores de variables de entorno. El argumento string debe apuntar a una cadena de la forma "nombre=valor". La función putenv() establecerá el valor de la variable de entorno nombre en valor, modificando una variable existente o creando una nueva. En cualquier caso, la cadena apuntada por string pasará a formar parte del entorno, por lo que modificar la cadena modificará el entorno.

La función putenv() no necesita ser segura para hilos.

VALOR DE RETORNO

Al completarse con éxito, putenv() devolverá 0; de lo contrario, devolverá un valor distinto de cero y establecerá errno para indicar el error.

ERRORES

La función putenv() puede fallar si:

ENOMEM
No había memoria suficiente disponible.

Las siguientes secciones son informativas.

EJEMPLOS

Cambio del Valor de una Variable de Entorno

El siguiente ejemplo cambia el valor de la variable de entorno HOME al valor /usr/home.

#include <stdlib.h>
...
static char *var = "HOME=/usr/home";
int ret;
ret = putenv(var);

USO POR PARTE DE LA APLICACIÓN

La función putenv() manipula el entorno apuntado por environ, y puede utilizarse junto con getenv().

Consulte exec() para ver las restricciones sobre el cambio del entorno en aplicaciones multihilo.

Esta rutina puede utilizar malloc() para ampliar el entorno.

Un error potencial es llamar a putenv() con una variable automática como argumento, y luego retornar de la función llamante mientras string todavía forma parte del entorno.

Aunque el espacio utilizado por string ya no se usa una vez que se pasa una nueva cadena que define name a putenv(), si algún hilo de la aplicación ha utilizado getenv() para recuperar un puntero a esta variable, no debe liberarse llamando a free(). Si la variable de entorno modificada es una conocida por el sistema (como las variables de entorno de configuración regional), la aplicación nunca debe liberar el búfer utilizado por llamadas anteriores a putenv() para la misma variable.

La función setenv() es preferible a esta función. Una razón es que putenv() es opcional y, por lo tanto, menos portable. Otra es que el uso de putenv() puede ralentizar las búsquedas en el entorno, como se explica en la sección RATIONALE de getenv().
