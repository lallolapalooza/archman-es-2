NOMBRE

puppet-facts - Recuperar y almacenar hechos (facts).

SINOPSIS

puppet facts acción [--terminus TERMINUS]

DESCRIPCIÓN

Este subcomando administra hechos (facts), que son colecciones de información normalizada del sistema utilizada por Puppet. Puede leer hechos directamente del sistema local (con el terminus facter por defecto).

OPCIONES

Tenga en cuenta que cualquier configuración válida en el archivo de configuración también es un argumento largo válido, aunque puede o no ser relevante para la acción actual. Por ejemplo, server y run_mode son configuraciones válidas, por lo que puede especificar --server <nombre_servidor>, o --run_mode <modo_ejecución> como argumento.

Consulte la documentación del archivo de configuración en https://puppet.com/docs/puppet/latest/configuration.html para obtener la lista completa de parámetros aceptables. Una lista comentada de todas las opciones de configuración también se puede generar ejecutando puppet con --genconfig.

--render-as FORMATO
El formato en el que se renderizará la salida. Los formatos más comunes son json, s (string/cadena), yaml y console, pero otras opciones como dot a veces están disponibles.
--verbose
Si se debe registrar información detallada.
--debug
Si se debe registrar información de depuración.
--terminus TERMINUS
Las caras indirectas exponen subsistemas indirectos de Puppet. Estos subsistemas son capaces de recuperar y alterar un tipo específico de datos (con las acciones familiares de find, search, save y destroy) de un número arbitrario de backends enchufables. En la jerga de Puppet, estos backends se denominan termini.
Casi todos los subsistemas indirectos tienen un terminus rest que interactúa con los datos del maestro de puppet. La mayoría de ellos tienen termini adicionales para varios modelos de datos locales, que a su vez son utilizados por el subsistema indirecto en el maestro de puppet siempre que recibe una solicitud remota.
El terminus para una acción a menudo se determina por el contexto, pero ocasionalmente debe establecerse explícitamente. Consulte la sección "Notas" de la página del manual de esta cara para obtener más detalles.

ACCIONES

find - Recuperar los hechos de un nodo.
SINOPSIS
puppet facts find [--terminus TERMINUS] [nombre_certificado_nodo]
DESCRIPCIÓN
Recuperar los hechos de un nodo.
RETORNA
Un hash que contiene metadatos y (bajo la clave "values") el conjunto de hechos para el nodo solicitado. Cuando se usa desde la API de Ruby: un objeto Puppet::Node::Facts.
PROBLEMAS DE RENDERIZADO: Los hechos actualmente no se pueden renderizar como una cadena; use yaml o json.
NOTAS
Cuando se usa el terminus facter, el argumento del host se ignora.
info - Imprimir la clase de terminus predeterminada para esta cara.
SINOPSIS
puppet facts info [--terminus TERMINUS]
DESCRIPCIÓN
Imprime la clase de terminus predeterminada para este subcomando. Tenga en cuenta que los diferentes modos de ejecución pueden tener diferentes termini predeterminados; en caso de duda, especifique el modo de ejecución con la opción '--run_mode'.
save - Solo API: crear o sobrescribir un objeto.
SINOPSIS
puppet facts save [--terminus TERMINUS] clave
DESCRIPCIÓN
Solo API: crear o sobrescribir un objeto. Como el framework Faces no acepta actualmente datos de STDIN, las acciones de guardado no se pueden invocar desde la línea de comandos.
show - Recuperar los hechos del nodo actual.
SINOPSIS
puppet facts [--terminus TERMINUS] [--config-file ruta] [--custom-dir ruta] [--external-dir ruta] [--no-block] [--no-cache] [--show-legacy] [--value-only] [--timing] [hechos]
DESCRIPCIÓN
Lee hechos del sistema local usando el terminus facter. Se puede proporcionar una consulta para recuperar solo un hecho específico o un conjunto de hechos.
OPCIONES --config-file <ruta> - La ubicación del archivo de configuración de Facter.
--custom-dir <ruta> - La ruta a un directorio que contiene hechos personalizados.
--external-dir <ruta> - La ruta a un directorio que contiene hechos externos.
--no-block - Desactiva el mecanismo de bloqueo de hechos.
--no-cache - Desactiva el mecanismo de caché de hechos.
--show-legacy - Muestra hechos heredados al consultar todos los hechos.
--timing - Muestra cuánto tiempo tomó resolver cada hecho.
--value-only - Muestra solo el valor cuando la acción se llama con una sola consulta
RETORNA
La salida de facter con hechos específicos de puppet añadidos.
NOTAS
upload - Cargar hechos locales al maestro de puppet.
SINOPSIS
puppet facts upload [--terminus TERMINUS]
DESCRIPCIÓN
Lee hechos del sistema local usando el terminus facter, y luego guarda los hechos devueltos usando el terminus rest.
RETORNA
Nada.
NOTAS
Esta acción requiere que el archivo auth.conf del Servidor Puppet permita el acceso PUT o save al endpoint de la API /puppet/v3/facts.
Para obtener detalles sobre la configuración de auth.conf del Servidor Puppet, consulte:
https://puppet.com/docs/puppetserver/latest/config_file_auth.html

EJEMPLOS

find

Obtener hechos del sistema local:

$ puppet facts find

show

recuperar hechos:

$ puppet facts show os

upload

Cargar hechos:

$ puppet facts upload

NOTAS

Este subcomando es una cara de indirector, que expone las acciones find, search, save y destroy para un subsistema indirecto de Puppet. Los termini válidos para esta cara incluyen:

  • facter
  • json
  • memory
  • network_device
  • rest
  • store_configs
  • yaml
