PULLNEWS(1) Documentación de InterNetNews PULLNEWS(1)

NOMBRE

pullnews - Obtener noticias de múltiples servidores de noticias y alimentarlas a otro

SINOPSIS

pullnews [-BhnOqRx] [-a hashfeed] [-b fracción] [-c config] [-C ancho] [-d nivel] [-f fracción] [-F saltotmp] [-g grupos] [-G gruposdenoticias] [-H cabeceras] [-k punto de control] [-l archivo de registro] [-L tamaño] [-m patrones de cabecera] [-M num] [-N tiempo de espera] [-p puerto] [-P límite de saltos] [-Q nivel] [-r archivo] [-s servidor-destino[:puerto][_modotls]] [-S max-ejecución] [-t reintentos] [-T pausa-conexión] [-w num] [-z pausa-artículo] [-Z pausa-grupo] [servidor-origen ...]

REQUISITOS

El módulo "Net::NNTP" debe estar instalado. Este módulo está disponible como parte de la distribución libnet y viene con versiones recientes de Perl. Para versiones antiguas de Perl, puedes descargarlo de http://www.cpan.org/.

DESCRIPCIÓN

pullnews lee un archivo de configuración llamado pullnews.marks, y se conecta a los servidores de origen listados allí como un cliente lector. Este archivo se busca en pathdb cuando pullnews se ejecuta como el usuario configurado en runasuser en inn.conf (que por defecto es el usuario "news"); de lo contrario, este archivo se busca en el directorio principal del usuario que lo ejecuta.

Por defecto, pullnews se conecta a todos los servidores listados en el archivo de configuración, pero puedes limitar pullnews a servidores específicos listándolos en la línea de comandos: se puede especificar una lista separada por espacios de nombres de servidores, como servidor-origen para uno de ellos. Para cada servidor al que se conecta, obtiene artículos y los alimenta al servidor de destino a través de los comandos IHAVE o POST. Esto significa que el sistema donde se ejecuta pullnews debe tener acceso de alimentación al servidor de noticias de destino.

pullnews está diseñado para sitios muy pequeños que no quieren molestarse en configurar peering tradicional y no está destinado a manejar grandes feeds.

En caso de que tengas peers activos y no quieras propagarles los artículos que estás obteniendo de los servidores de origen, deberías añadir un salto falso con la opción -F a todos los artículos obtenidos, y añadir ese mismo salto falso en el subcampo de exclusión de todos los sitios configurados en tu archivo newsfeeds que no deberían recibir estos artículos. Por ejemplo, usando "pullnews -F miservidorimportado", cambia "nombredelsitio:*:Tm:innfeed!" a "nombredelsitio/miservidorimportado:*:Tm:innfeed!" para cada nombredelsitio en newsfeeds al que no quieras enviar los artículos obtenidos (como tus peers salientes y una posible entrada "inpaths!"). Entradas como "ME", "controlchan!", "innfeed!" o "nocem!" no necesitan esa exclusión.

OPCIONES

-a hashfeed
Esta opción es una forma determinista de controlar el flujo de artículos y dividir un feed. El parámetro hashfeed debe tener el formato "valor/mod" o "inicio-fin/mod". El Message-ID de cada artículo se hashea usando MD5, lo que resulta en un hash de 128 bits. Los 32 bits más bajos se toman por defecto como el valor hashfeed (que es un entero). Si el valor hashfeed módulo "mod" más uno es igual a "valor" o está entre "inicio" y "fin", pullnews alimentará el artículo. Todos estos números deben ser enteros.

Por ejemplo:

pullnews -a 1/2      Alimenta aproximadamente el 50% de todos los artículos.
pullnews -a 2/2      Alimenta el otro 50% de todos los artículos.

Otro ejemplo:

pullnews -a 1-3/10   Alimenta aproximadamente el 30% de todos los artículos.
pullnews -a 4-5/10   Alimenta aproximadamente el 20% de todos los artículos.
pullnews -a 6-10/10  Alimenta aproximadamente el 50% de todos los artículos.

Puedes usar una sintaxis extendida del tipo "valor/mod:offset" o "inicio-fin/mod:offset" (también se reconoce el uso de un guion bajo "_" en lugar de dos puntos ":"). Dado que MD5 genera un valor de retorno de 128 bits, es posible especificar desde qué offset de byte comienza el entero de 32 bits utilizado por hashfeed. El valor por defecto para "offset" es ":0" y se pueden usar hasta trece valores superpuestos desde ":0" hasta ":12". Solo existen hasta cuatro valores totalmente independientes: ":0", ":4", ":8" y ":12".

Por lo tanto, permite generar un segundo nivel de distribución determinista. De hecho, si pullnews alimenta "1/2", puede seguir dividiendo gracias a "1-3/9:4", por ejemplo. Se pueden usar hasta cuatro niveles de distribución determinista.

El algoritmo es compatible con el utilizado por Diablo 5.1 y superior.

-b fracción
Retroceder en el reinicio de la numeración del servidor. Especifica la proporción (0.0 a 1.0) de artículos de un grupo a obtener cuando el número de artículo del servidor es menor que nuestro máximo para ese grupo. Cuando fracción es 1.0, obtiene todos los artículos de un servidor renumerado. Por defecto no hace nada.
-B
El feed es solo de cabeceras, es decir, pullnews solo alimenta las cabeceras de los artículos, más una línea en blanco. Añade el campo de cabecera Bytes si el artículo no lo tiene ya, y mantiene el cuerpo solo si el artículo es un artículo de control.
-c config
Normalmente, el archivo de configuración se almacena en pullnews.marks en pathdb cuando pullnews se ejecuta como el usuario news, o de lo contrario en el directorio principal del usuario que lo ejecuta. Si se proporciona -c, se usará config como archivo de configuración. Esto es útil si estás ejecutando pullnews como un usuario del sistema de forma automatizada fuera de cron o como un usuario individual, en lugar del usuario news.

Ver "ARCHIVO DE CONFIGURACIÓN" más abajo para el formato de este archivo.

-C ancho
Usa ancho caracteres por línea para la tabla de progreso. El valor por defecto es 50.
-d nivel
Establece el nivel de depuración al entero nivel (hasta 4); se registrará más salida de depuración a medida que este valor aumente. El valor por defecto es 0.
-f fracción
Esto cambia la proporción de artículos a obtener de cada grupo a fracción y debe estar en el rango de 0.0 a 1.0 (1.0 es el valor por defecto).
-F saltotmp
Antepone saltotmp como un host al cuerpo del campo Path de los artículos alimentados.
-g grupos
Especifica una colección de grupos a obtener. grupos es una lista de grupos de noticias separados por comas (solo comas, sin espacios). Cada grupo debe estar definido en el archivo de configuración, y solo se contactará a los hosts remotos que contengan esos grupos. Ten en cuenta que esta es una lista simple de grupos, no una expresión wildmat, y no se admiten comodines.
-G gruposdenoticias
Añade la lista de grupos separada por comas gruposdenoticias

OPCIONES

-a wsgroups
Añade las wsgroups a cada servidor en el archivo de configuración (ver también -g y -w).
-h
Imprime un mensaje de uso y sale.
-H cabeceras
Elimina estos campos de cabecera con nombre (lista separada por dos puntos) de los artículos fed.
-k checkpt
Punto de control (guarda) el archivo de configuración cada checkpt artículos (el valor por defecto es 0, es decir, al final de la sesión).
-l logfile
Registra el progreso/estadísticas en logfile (el valor por defecto es "stdout").
-L size
Especifica el tamaño máximo deseado de artículo en bytes. El valor por defecto es descargar todos los artículos, independientemente de su tamaño. Cuando se utiliza esta opción, pullnews recuperará primero los datos de resumen (si están disponibles) de cada grupo de noticias a procesar para obtener los tamaños de los artículos, antes de decidir qué artículos descargar realmente.
-m header_pats
Alimenta un artículo basándose en la coincidencia del cuerpo del campo de cabecera. El argumento es un número de tuplas separadas por espacios en blanco (cada tupla es un nombre de campo de cabecera separado por dos puntos y una expresión regular). Por ejemplo: 
-m "Hdr1:regexp1 !Hdr2:regexp2 #Hdr3:regexp3 !#Hdr4:regexp4"

especifica que el artículo solo se pasará si el cuerpo del campo de cabecera "Hdr1" coincide con "regexp1" y el cuerpo del campo de cabecera "Hdr2" no coincide con "regexp2". Además, si el cuerpo del campo de cabecera "Hdr3" coincide con "regexp3", esa cabecera se elimina; y si el cuerpo del campo de cabecera "Hdr4" no coincide con "regexp4", esa cabecera se elimina.

-M num
Especifica el número máximo de artículos (por grupo) a procesar. El valor por defecto es procesar todos los artículos nuevos. Ver también -f.
-n
No hacer nada más que leer artículos -- no alimenta artículos aguas abajo, no escribe ningún archivo rnews, no actualiza el archivo de configuración.
-N timeout
Especifica la duración del tiempo de espera, como timeout segundos, al establecer una conexión NNTP.
-O
Utiliza un modo optimizado: pullnews comprueba si el artículo existe ya en el servidor aguas abajo, antes de descargarlo. Esto puede ayudar con artículos muy grandes o con un enlace lento a los hosts ascendentes.
-p port
Conéctate al servidor de noticias de destino en un puerto diferente al predeterminado de 119. Esta opción no cambia el puerto utilizado para conectarse a los servidores de noticias de origen.
-P hop_limit
Restringe la alimentación de un artículo basándose en el número de saltos que ya ha realizado. Cuenta los saltos en el cuerpo del campo de cabecera Path (hop_count), alimentando el artículo solo cuando hop_limit es "+num" y hop_count es mayor que num; o hop_limit es "-num" y hop_count es menor que num.
-q
Imprime menos información de estado mientras se ejecuta.
-Q level
Establece el nivel de silencio ("-Q 2" es equivalente a "-q"). Cuanto mayor sea este valor, menos se registrará. El valor por defecto es 0.
-r file
En lugar de alimentar los artículos descargados a un servidor de destino, crea un archivo por lotes que luego puede ser alimentado a un servidor usando rnews. Ver rnews(1) para más información sobre el formato del archivo por lotes.
-R
Actúa como un lector (usa los comandos MODE READER y POST) para el servidor aguas abajo. Algunas publicaciones serán entonces rechazadas debido a campos de cabecera de inyección inesperados, campos de cabecera obsoletos o incorrectamente formateados, o con una fecha demasiado antigua. Es posible que entonces desees establecer artcutoff a 0 en inn.conf, y usar la bandera -H para eliminar los campos de cabecera no deseados. Incluso con eso, algunos artículos todavía pueden ser rechazados.

El valor por defecto es actuar como un alimentador y usar el comando IHAVE. (Tendrás que permitir en incoming.conf las conexiones de pullnews para que sea reconocido como un alimentador).

-s to-server[:port][_tlsmode]
Normalmente, pullnews alimentará los artículos que recupera al servidor de noticias que se ejecuta en localhost. Para conectarte a un host diferente, especifica un servidor con la bandera -s. También puedes especificar el puerto con esta misma bandera o usar -p. El puerto por defecto es 119.

La conexión es por defecto no cifrada. Para negociar una capa de cifrado TLS, puedes establecer tlsmode a "TLS" para TLS implícito (negociado inmediatamente al conectar en un puerto dedicado) o "STARTTLS" para TLS explícito (el comando apropiado se enviará antes de autenticarse o alimentar mensajes). Ejemplos de uso son:

pullnews -s news.server.com
pullnews -s news.server.com_STARTTLS
pullnews -s news.server.com:433_TLS

Ten en cuenta que no todos los servidores NNTP implementan TLS para alimentar artículos.

-S max-run
Especifica el tiempo máximo max-run en segundos para que pullnews se ejecute.
-t retries
El número máximo (retries) de intentos para conectarse a un servidor o reconectarse a un servidor si el socket se cierra inesperadamente (ver también -T). El valor por defecto es 0.
-T connect-pause
Pausa connect-pause segundos entre reintentos de conexión (ver también -t). El valor por defecto es 1.
-w num
Establece la marca de agua alta (último número de artículo recibido) de cada grupo a num. Si num es negativo, calcula Current+num en su lugar (es decir, obtén los últimos num artículos). Por lo tanto, un num de 0 volverá a obtener todos los artículos del servidor; mientras que un num de "-0" no obtendrá ningún artículo antiguo, estableciendo la marca de agua a Current (el artículo más reciente en el servidor).
-x
Si se utiliza la bandera -x, se añade un campo de cabecera Xref a cualquier artículo que carezca de él. Puede ser útil, por ejemplo, si los artículos se alimentan a un servidor de noticias que tiene xrefslave establecido en inn.conf.
-z article-pause
Duerme article-pause segundos entre artículos. El valor por defecto es 0.
-Z group-pause
Duerme group-pause segundos entre grupos. El valor por defecto es 0.

ARCHIVO DE CONFIGURACIÓN

El archivo de configuración para pullnews se divide en bloques, un bloque para cada servidor remoto al que conectarse. Un bloque comienza con la línea del host (que no debe tener espacios en blanco al principio) y contiene solo el nombre de host del servidor remoto con puerto y modo TLS opcionales (con la misma semántica que la bandera -s), seguido opcionalmente por detalles de autenticación (nombre de usuario y contraseña para ese servidor). Ten en cuenta que los detalles de autenticación también se pueden proporcionar para el servidor aguas abajo (una línea de host para "localhost" o el nombre de host especificado con la bandera -s podría agregarse para él en el archivo de configuración, sin grupo de noticias que obtener).

Después de la línea del host deben seguir una o más líneas de grupo de noticias que comienzan con un espacio en blanco seguido del nombre de un grupo de noticias a recuperar. Solo se debe listar un grupo de noticias en cada línea.

pullnews actualizará el archivo de configuración para incluir la hora en que se revisó por última vez el grupo y el número más alto de artículo recuperado y transferido con éxito al servidor de destino. Utiliza estos datos para evitar realizar trabajo duplicado la próxima vez que se ejecute.

La sintaxis completa es:

<host>[:<port>][_<tlsmode>] [<username> <password>]
    <group> [<time> <high>]
    <group> [<time> <high>]

donde la línea <host> no debe tener espacios en blanco al principio y las líneas <group> sí.

Un archivo de configuración típico sería:

# Format: group date high
data.pa.vix.com
    rec.bicycles.racing 908086612 783
    rec.humor.funny 908086613 18
    comp.programming.threads
nnrp.vix.com pull sekret
    comp.std.lisp
news.server.com:563_TLS joe password
    news.software.nntp

Ten en cuenta que una ejecución anterior de pullnews ha rellenado detalles sobre las últimas descargas de artículos de los dos grupos rec.*. Los dos grupos comp.* y el grupo news.* fueron añadidos por el usuario y aún no han sido revisados.

El servidor nnrp.vix.com requiere autenticación, y pullnews utilizará el nombre de usuario "pull" y la contraseña "sekret" (sin ninguna capa de cifrado).

La conexión a news.server.com se cifrará con TLS implícito en el puerto 563. La contraseña de Joe no se enviará en texto plano.

ARCHIVOS

pathbin/pullnews
El script Perl en sí utilizado para extraer noticias de servidores ascendentes y alimentarlas a otro servidor de noticias.
pathdb/pullnews.marks o ~/pullnews.marks
El archivo de configuración por defecto. Se almacena en pullnews.marks en pathdb cuando pullnews se ejecuta como usuario de noticias, o de lo contrario en el directorio de inicio del usuario en ejecución.
