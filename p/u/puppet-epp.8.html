NOMBRE

puppet-epp - Interactuar directamente con el analizador/renderizador de plantillas EPP.

SINOPSIS

puppet epp acción

OPCIONES

Tenga en cuenta que cualquier configuración que sea válida en el archivo de configuración también es un argumento largo válido, aunque puede ser o no relevante para la acción presente. Por ejemplo, server y run_mode son configuraciones válidas, por lo que puede especificar --server <nombre_servidor>, o --run_mode <modo_ejecucion> como argumento.

Consulte la documentación del archivo de configuración en https://puppet.com/docs/puppet/latest/configuration.html para obtener la lista completa de parámetros aceptables. También se puede generar una lista comentada de todas las opciones de configuración ejecutando puppet con --genconfig.

--render-as FORMATO
El formato en el que se renderizará la salida. Los formatos más comunes son json, s (string), yaml y console, pero otras opciones como dot a veces están disponibles.
--verbose
Si se debe registrar de forma detallada.
--debug
Si se deben registrar información de depuración.

ACCIONES

•
dump - Muestra un volcado del árbol de análisis interno de la plantilla para depuración: SINOPSIS
puppet epp dump [--e fuente] [--[no-]validate] [--format old, pn, o json] [--pretty] [--[no-]header] [--format old|pn|json] [--pretty] { -e fuente | [plantillas ...] }
DESCRIPCIÓN
La acción dump analiza y valida la sintaxis EPP y muestra el modelo AST resultante en un formato legible por humanos (pero no necesariamente fácil de entender).
El formato de salida se puede controlar usando --format old|pn|json donde:
  • ´old´ es el formato predeterminado, pero ahora obsoleto, que no es API.
  • ´pn´ es la Notación de Expresión S Extendida de Puppet.
  • ´json´ muestra el mismo grafo que ´pn´ pero con sintaxis JSON.
La salida se imprimirá de forma "bonita" cuando la opción --pretty se proporcione junto con --format ´pn´ o ´json´. Esta opción no tiene ningún efecto en el formato ´old´.
El comando acepta uno o más archivos de plantilla (.epp), o -e seguido del texto de origen de la plantilla. Las plantillas dadas pueden ser rutas a archivos de plantilla, o referencias a plantillas en módulos cuando se dan en el formato nombremodulo/nombreplantilla.epp. Si no se proporcionan argumentos, se lee la entrada estándar (a menos que esté conectada a una terminal)
Si se proporcionan varias plantillas, se separan con una cabecera que indica el nombre de la plantilla. Esto se puede suprimir con la opción --no-header. La opción --[no-]header no tiene efecto cuando se muestra una sola plantilla.
Al depurar el analizador epp en sí, puede ser útil suprimir el paso de validación con la opción --no-validate para observar lo que el analizador produjo a partir de la fuente dada.
Este comando ignora la configuración/opción --render-as.
OPCIONES --e <fuente> - Muestra una expresión fuente epp dada en la línea de comandos.
--format <old, pn, o json> - Obtiene el resultado en ´old´ (formato obsoleto), ´pn´ (formato nuevo), o ´json´ (formato nuevo en JSON).
--[no-]header - Si se debe mostrar o no una cabecera con el nombre del archivo entre archivos.
--pretty - Imprime la salida de forma bonita. Solo aplicable junto con --format pn o json
--[no-]validate - Si se debe validar o no el resultado analizado, si no se valida, solo se informan los errores de sintaxis.
RETORNA
Un volcado del modelo AST resultante a menos que haya errores de sintaxis o validación.
•
render - Renderiza una plantilla epp como texto: SINOPSIS
puppet epp render [--node nombre_nodo] [--e fuente] [--values hash_valores] [--values_file archivo_pp_o_yaml] [--facts archivo_facts] [--[no-]header] -e fuente | [plantillas ...]
DESCRIPCIÓN
Esta acción renderiza una o más plantillas EPP.
El comando acepta una o más plantillas (archivos .epp), dadas de la misma manera que las plantillas se dan a la función epp de puppet (una ruta completa, o una referencia relativa en el formato ´nombremodulo/nombreplantilla.epp´), o como una ruta relativa. En caso de que la ruta dada coincida tanto con un nombre de módulo/plantilla como con un archivo, se utiliza la plantilla del módulo.
También se puede realizar un equivalente a inline_epp proporcionando la plantilla después de -e, o canalizando el texto de origen EPP al comando.
Los valores para la plantilla se pueden definir usando el Lenguaje Puppet en la línea de comandos con --values o en un archivo .pp o .yaml referenciado con --values_file. Si se especifican ambos, el resultado se fusiona teniendo --values mayor precedencia.
La opción --values permite definir una secuencia de expresiones del Lenguaje Puppet en la línea de comandos de la misma manera que se puede dar en un archivo .pp referenciado con --values_file. Puede establecer valores de variables (que estarán disponibles en la plantilla) y debe producir undef o un Hash de valores (el hash puede estar vacío). Producir undef simula que la plantilla se llama sin un hash de argumentos y, por lo tanto, solo hace referencia a variables en su ámbito externo. Cuando se proporciona un hash, una plantilla se limita a ver solo el ámbito global. Por lo tanto, es posible simular los diferentes tipos de llamadas a las funciones epp e inline_epp, con o sin un hash dado. Tenga en cuenta que si se proporcionan variables, siempre están disponibles en esta simulación; para probar que la plantilla solo hace referencia a variables dadas como argumentos, produzca un hash en --values o en el --values_file, no especifique ninguna variable que no sea global y active la configuración --strict_variables.
Si se proporcionan varias plantillas, se les da el mismo conjunto de valores a cada una. Si se utilizan tanto --values como --value_file, los --values se fusionan encima de los dados en el archivo.
Cuando se renderizan varias plantillas, se muestra una cabecera separadora entre las plantillas que muestra el nombre de la plantilla antes de la salida. La salida de la cabecera se puede desactivar con --no-header. Esto también concatena los resultados de la plantilla sin ningún separador de nueva línea añadido.
Por defecto, se utilizan los hechos del nodo donde se ejecuta el comando. Los hechos se pueden obtener para otros nodos si han llamado y reportado sus hechos usando la opción --node <nombre_nodo>.
Los hechos del nodo que se están ejecutando se utilizan por defecto. Los hechos se pueden obtener para otros nodos si han llamado y reportado sus hechos usando la opción --node <nombre_nodo>.
Anular los hechos del nodo, así como hechos adicionales, se pueden proporcionar en un archivo .yaml o .json y referenciarlos con la opción --facts. (Los valores se pueden obtener en formato yaml directamente de facter, o de puppet para un nodo dado). Tenga en cuenta que no es posible simular el nombre de variable reservado $facts de ninguna otra manera.
Tenga en cuenta que no es posible establecer variables usando el Lenguaje Puppet que tengan los mismos nombres que los hechos, ya que esto resulta en un error; "intento de redefinir una variable", ya que los hechos se establecen primero.
Sale con 0 si no hubo errores de validación. En caso de errores, no se produce ninguna salida renderizada para ese archivo de plantilla.
Al diseñar plantillas EPP, se recomienda encarecidamente definir todos los argumentos de la plantilla en la plantilla, y proporcionarlos en un hash al llamar a epp o inline_epp y utilizar la menor cantidad posible de variables globales, preferiblemente solo el hash $facts. Esto hace que las plantillas sean más independientes y fáciles de reutilizar y probar.

--facts <archivo_facts> - Un archivo .yaml o .json que contiene un hash de hechos puestos a disposición en $facts y $trusted

NAME

puppet-epp - EPP template rendering and validation

SYNOPSIS

puppet epp render [options] template
puppet epp validate [options] [template] [template ...]

OPTIONS

This command accepts common Puppet options and the following specific ones:

--debug
Enable debug output.
--detailed-exitcodes
Enable detailed exit codes.
--evaluate-all
Evaluate all templates, even if they are not needed.
--face <face>
Use the specified face.
--help, -h
Print help for this command.
--host <host>
Specifiy the host.
--logdest <logdest>
Set the log destination.
--mode <mode>
Set the log mode.
--render-as <format>
The rendering format.
--verbose
Enable verbose output.

ACTIONS

•
render - Render one or more EPP templates.: SYNOPSIS
puppet epp render [--[no-]strict_variables] [--values <values_hash>] [--values_file <pp_or_yaml_file>] [--facts <facts_hash_or_file>] [--node <node_name>] template
DESCRIPTION
This action renders an EPP template and outputs the result.
The template can be given as a reference to a template in a module (modulename/template.epp) or as a path to a file. If the reference to a file can be resolved against a template in a module, the module version wins - in this case use an absolute path to reference the template file if the module version is not wanted.
Can also render from STDIN if STDIN is not a TTY.
OPTIONS
--[no-]strict_variables - Whether or not to issue an error when an undefined variable is used.
--facts <facts_hash_or_file> - A hash of facts in Puppet DSL form or a path to a YAML file containing facts.
--node <node_name> - The name of the node for which facts are obtained. Defaults to facts for the local node.
--values <values_hash> - A Hash in Puppet DSL form given as arguments to the template being rendered.
--values_file <pp_or_yaml_file> - A .pp or .yaml file that is processed to produce a hash of values for the template.
RETURNS
A rendered result of one or more given templates.
•
validate - Validate the syntax of one or more EPP templates.: SYNOPSIS
puppet epp validate [--[no-]continue_on_error] [template] [template ...]
DESCRIPTION
This action validates EPP syntax without producing any output.
When validating, multiple issues per file are reported up to the settings of max_error, and max_warnings. The processing stops after having reported issues for the first encountered file with errors unless the option --continue_on_error is given.
Files can be given using the modulename/template.epp style to lookup the template from a module, or be given as a reference to a file. If the reference to a file can be resolved against a template in a module, the module version wins - in this case use an absolute path to reference the template file if the module version is not wanted.
Exits with 0 if there were no validation errors.
OPTIONS --[no-]continue_on_error - Whether or not to continue after errors are reported for a template.
RETURNS
Nothing, or encountered syntax errors.

EXAMPLES

render

Render the template in module ´mymodule´ called ´mytemplate.epp´, and give it two arguments a and b:

$ puppet epp render mymodule/mytemplate.epp --values ´{a => 10, b => 20}´

Render a template using an absolute path:

$ puppet epp render /tmp/testing/mytemplate.epp --values ´{a => 10, b => 20}´

Render a template with data from a .pp file:

$ puppet epp render /tmp/testing/mytemplate.epp --values_file mydata.pp

Render a template with data from a .pp file and override one value on the command line:

$ puppet epp render /tmp/testing/mytemplate.epp --values_file mydata.pp --values ´{a=>10}´

Render from STDIN:

$ cat template.epp | puppet epp render --values ´{a => 10, b => 20}´

Set variables in a .pp file and render a template that uses variable references:

# data.pp file
$greeted = ´a global var´
undef
$ puppet epp render -e ´hello <%= $greeted %>´ --values_file data.pp

Render a template that outputs a fact:

$ facter --yaml > data.yaml
$ puppet epp render -e ´<% $facts[osfamily] %>´ --facts data.yaml

validate

Validate the template ´template.epp´ in module ´mymodule´:

$ puppet epp validate mymodule/template.epp

Validate two arbitrary template files:

$ puppet epp validate mymodule/template1.epp yourmodule/something.epp

Validate a template somewhere in the file system:

  $ puppet epp validate /tmp/testing/template1.epp

Validate a template against a file relative to the current directory:

 $ puppet epp validate template1.epp
 $ puppet epp validate ./template1.epp

Validate from STDIN:

$ cat template.epp | puppet epp validate

Continue on error to see errors for all templates:

$ puppet epp validate mymodule/template1.epp mymodule/template2.epp --continue_on_error
