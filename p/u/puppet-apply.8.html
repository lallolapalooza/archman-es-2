NOMBRE

puppet-apply - Aplica manifiestos de Puppet localmente

SINOPSIS

Aplica un manifiesto de Puppet independiente al sistema local.

USO

puppet apply [-h|--help] [-V|--version] [-d|--debug] [-v|--verbose] [-e|--execute] [--detailed-exitcodes] [-L|--loadclasses] [-l|--logdest syslog|eventlog|RUTA_ARCHIVO_ABS|console] [--noop] [--catalog catálogo] [--write-catalog-summary] archivo

DESCRIPCIÓN

Esta es la herramienta de ejecución independiente de Puppet; úsela para aplicar manifiestos individuales.

Cuando se proporciona un `modulepath` (ruta de módulos), a través de la línea de comandos o del archivo de configuración, `puppet apply` puede imitar efectivamente el catálogo que serviría un `puppet master` con acceso a los mismos módulos, aunque existen algunas diferencias sutiles. Cuando se combina con la programación y un sistema automatizado para distribuir manifiestos, esto puede usarse para implementar un sitio Puppet sin servidor.

La mayoría de los usuarios deberían usar `puppet agent` y `puppet master` para los manifiestos de todo el sitio.

OPCIONES

Cualquier configuración válida en el archivo de configuración es un argumento largo válido para `puppet apply`. Por ejemplo, `tags` es una configuración válida, por lo que puede especificar `--tags clase,etiqueta` como argumento.

Consulte la documentación del archivo de configuración en https://puppet.com/docs/puppet/latest/configuration.html para obtener la lista completa de parámetros aceptables. Puede generar una lista comentada de todas las opciones de configuración ejecutando puppet con `--genconfig`.

  • --debug: Habilita la depuración completa.
  • --detailed-exitcodes: Proporciona información adicional sobre la ejecución a través de códigos de salida. Si está habilitado, `puppet apply` usará los siguientes códigos de salida:
0: La ejecución se completó sin cambios ni fallos; el sistema ya estaba en el estado deseado.
1: La ejecución falló.
2: La ejecución se completó con éxito y algunos recursos fueron modificados.
4: La ejecución se completó con éxito y algunos recursos fallaron.
6: La ejecución se completó con éxito e incluyó tanto cambios como fallos.
  • --help: Imprime este mensaje de ayuda
  • --loadclasses: Carga las clases almacenadas. `puppet agent` almacena en caché las clases configuradas (generalmente en `/etc/puppetlabs/puppet/classes.txt`), y establecer esta opción hace que todas esas clases se configuren en su manifiesto de puppet.
  • --logdest: Dónde enviar los mensajes de registro. Elija entre `syslog` (el servicio syslog POSIX), `eventlog` (el registro de eventos de Windows), `console`, o la ruta a un archivo de registro. El valor predeterminado es `console`. Se pueden establecer varios destinos utilizando una lista separada por comas (ej: /ruta/archivo1,consola,/ruta/archivo2)"
Una ruta que termina en `.json` recibirá una salida estructurada en formato JSON. El archivo de registro no tendrá un cierre `]` añadido automáticamente debido a la naturaleza acumulativa del registro. Debe agregarse manualmente para que el contenido sea JSON válido.
Una ruta que termina en `.jsonl` recibirá una salida estructurada en formato JSON Lines.
  • --noop: Utiliza el modo `noop` (sin operación) donde Puppet se ejecuta en un modo de simulación o prueba. Esto es útil para ver qué cambios hará Puppet sin ejecutarlos realmente.
  • --execute: Ejecuta una pieza específica de código Puppet
  • --test: Habilita las opciones más comunes utilizadas para pruebas. Estas son `verbose`, `detailed-exitcodes` y `show_diff`.
  • --verbose: Imprime información adicional.
  • --catalog: Aplica un catálogo JSON (como uno generado con `puppet master --compile`). Puede especificar un archivo JSON o canalizar JSON desde la entrada estándar.
  • --write-catalog-summary Después de compilar el catálogo, guarda la lista de recursos y la lista de clases en el nodo en el directorio de estado llamado classes.txt y resources.txt

EJEMPLO

$ puppet apply -e ´notify { "hola mundo": }´
$ puppet apply -l /tmp/manifest.log manifest.pp
$ puppet apply --modulepath=/root/dev/modules -e "include ntpd::server"
$ puppet apply --catalog catalog.json
