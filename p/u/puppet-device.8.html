NOMBRE

puppet-device - Gestionar dispositivos de red remotos

SINOPSIS

Recupera catálogos del maestro de Puppet y los aplica a dispositivos remotos.

Este subcomando se puede ejecutar manualmente; o periódicamente usando cron, una tarea programada o una herramienta similar.

USO

puppet device [-h|--help] [-v|--verbose] [-d|--debug] [-l|--logdest syslog|archivo|consola] [--detailed-exitcodes] [--deviceconfig archivo] [-w|--waitforcert segundos] [--libdir directorio] [-a|--apply archivo] [-f|--facts] [-r|--resource tipo [nombre]] [-t|--target dispositivo] [--user=usuario] [-V|--version]

DESCRIPCIÓN

Los dispositivos requieren un agente proxy de Puppet para solicitar certificados, recopilar facts, recuperar y aplicar catálogos, y almacenar informes.

NOTAS DE USO

Los dispositivos administrados por el subcomando puppet-device en un agente de Puppet se configuran en device.conf, que se encuentra en $confdir/device.conf por defecto, y se puede configurar con la opción $deviceconfig.

El archivo device.conf es un archivo similar a INI, con una sección por dispositivo:

[NOMBRE_CERTIFICADO_DISPOSITIVO] tipo TIPO url URL debug

El nombre de la sección especifica el nombre del certificado del dispositivo.

Los valores para las propiedades tipo y url son específicos para cada tipo de dispositivo.

La propiedad debug opcional especifica la depuración a nivel de transporte, y se limita a los transportes telnet y ssh.

Consulta https://puppet.com/docs/puppet/latest/config_file_device.html para obtener detalles.

OPCIONES

Ten en cuenta que cualquier opción válida en el archivo de configuración también es un argumento largo válido. Por ejemplo, «server» es un parámetro de configuración válido, por lo que puedes especificar «--server nombre_servidor» como argumento.

--help, -h
Imprime este mensaje de ayuda
--verbose, -v
Activa la generación de informes detallada.
--debug, -d
Habilita la depuración completa.
--logdest, -l
A dónde enviar los mensajes de registro. Elige entre «syslog» (el servicio syslog de POSIX), «consola», o la ruta a un archivo de registro. Si la depuración o la verbosidad están habilitadas, el valor predeterminado es «consola». De lo contrario, el valor predeterminado es «syslog». Se pueden establecer varios destinos usando una lista separada por comas (ej: /ruta/archivo1,consola,/ruta/archivo2)"
Una ruta que termina en «.json» recibirá salida estructurada en formato JSON. El archivo de registro no tendrá un «]» final escrito automáticamente debido a la naturaleza de adición del registro. Debe agregarse manualmente para que el contenido sea JSON válido.
--detailed-exitcodes
Proporciona información de la transacción a través de códigos de salida. Si esto está habilitado, un código de salida de «1» significa que al menos un dispositivo tuvo un error de compilación, un código de salida de «2» significa que al menos un dispositivo tuvo cambios en los recursos, y un código de salida de «4» significa que al menos un dispositivo tuvo fallos en los recursos. Códigos de salida de «3», «5», «6» o «7» significan que ocurrió una combinación bit a bit de los códigos de salida anteriores.
--deviceconfig
Ruta al archivo de configuración del dispositivo para puppet device. Por defecto: $confdir/device.conf
--waitforcert, -w
Esta opción solo importa para objetivos que aún no tienen certificados y está habilitada por defecto, con un valor de 120 (segundos). Esto hace que +puppet device+ consulte al servidor cada 2 minutos y le pida que firme una solicitud de certificado. Esto es útil para la configuración inicial de un objetivo. Puedes desactivar la espera de certificados especificando un tiempo de 0.
--libdir
Anula el libdir por dispositivo con un directorio local. Especificar un libdir también deshabilita pluginsync. Esto es útil para pruebas.
Una ruta que termina en «.jsonl» recibirá salida estructurada en formato JSON Lines.
--apply
Aplica un manifiesto contra un objetivo remoto. El objetivo debe ser especificado.
--facts
Muestra los facts de un objetivo remoto. El objetivo debe ser especificado.
--resource
Muestra el estado de un recurso como código Puppet, aproximadamente equivalente a puppet resource. Se puede filtrar por título. Requiere que se especifique --target.
--target
Dirígete a un dispositivo/certificado específico en device.conf. Al hacerlo, se realizará una ejecución de dispositivo solo contra ese dispositivo/certificado.
--to_yaml
Muestra los recursos encontrados en formato yaml, adecuado para usar con Hiera y create_resources.
--user
El usuario con el que ejecutar.

EJEMPLO

  $ puppet device --target remotehost --verbose
