NOMBRE

puppet-node - Ver y gestionar definiciones de nodos.

SINOPSIS

puppet node acción [--terminus _TERMINUS]

DESCRIPCIÓN

Este subcomando interactúa con objetos de nodo, que son utilizados por Puppet para construir un catálogo. Un objeto de nodo consiste en los datos (facts) del nodo, el entorno, los parámetros del nodo (expuestos en el analizador como variables de alcance superior) y las clases.

OPCIONES

Tenga en cuenta que cualquier configuración válida en el archivo de configuración también es un argumento largo válido, aunque puede ser o no relevante para la acción presente. Por ejemplo, server y run_mode son configuraciones válidas, por lo que puede especificar --server <nombre_servidor>, o --run_mode <modo_ejecucion> como argumento.

Consulte la documentación del archivo de configuración en https://puppet.com/docs/puppet/latest/configuration.html para obtener la lista completa de parámetros aceptables. También se puede generar una lista comentada de todas las opciones de configuración ejecutando puppet con --genconfig.

--render-as FORMATO
El formato en el que se debe renderizar la salida. Los formatos más comunes son json, s (string/cadena), yaml y console, pero a veces también están disponibles otras opciones como dot.
--verbose
Si se debe registrar información detallada.
--debug
Si se debe registrar información de depuración.
--terminus _TERMINUS
Las caras de indirector exponen subsistemas indirectos de Puppet. Estos subsistemas pueden recuperar y alterar datos específicos (con las acciones familiares de find, search, save y destroy) de un número arbitrario de backends conectables. En la jerga de Puppet, estos backends se llaman terminuses.
Casi todos los subsistemas indirectados tienen un terminus rest que interactúa con los datos del puppet master. La mayoría de ellos tienen terminuses adicionales para varios modelos de datos locales, que a su vez son utilizados por el subsistema indirectado en el puppet master siempre que recibe una solicitud remota.
El terminus para una acción a menudo se determina por el contexto, pero ocasionalmente es necesario establecerlo explícitamente. Consulte la sección "Notas" de la página del manual de esta cara para obtener más detalles.

ACCIONES

clean - Limpia certificados firmados, datos (facts) cacheados, objetos de nodo e informes almacenados por el puppetmaster
SINOPSIS
puppet node clean [--terminus _TERMINUS] host1 [host2 ...]
DESCRIPCIÓN
Limpia la siguiente información que un puppet master conoce sobre un nodo:
Certificados firmados - ($vardir/ssl/ca/signed/nodo.dominio.pem)
Datos (facts) cacheados - ($vardir/yaml/facts/nodo.dominio.yaml)
Objetos de nodo cacheados - ($vardir/yaml/node/nodo.dominio.yaml)
Informes - ($vardir/reports/nodo.dominio)
NOTA: esta acción ahora limpia certificados a través de la API CA de Puppet Server. Se requiere un servidor en ejecución para que los certificados se limpien.
find - Recupera un objeto de nodo.
SINOPSIS
puppet node find [--terminus _TERMINUS] host
DESCRIPCIÓN
Recupera un objeto de nodo.
RETORNA
Un hash que contiene las clases del nodo, el entorno, la expiración, el nombre, los parámetros (sus datos, combinados con cualquier parámetro impuesto por ENC) y el tiempo. Cuando se utiliza desde la API de Ruby: un objeto Puppet::Node.
PROBLEMAS DE RENDERIZADO: Renderizar como cadena y json están actualmente rotos; los objetos de nodo solo se pueden renderizar como yaml.
info - Imprime la clase de terminus predeterminada para esta cara.
SINOPSIS
puppet node info [--terminus _TERMINUS]
DESCRIPCIÓN
Imprime la clase de terminus predeterminada para este subcomando. Tenga en cuenta que los diferentes modos de ejecución pueden tener diferentes terminuses predeterminados; en caso de duda, especifique el modo de ejecución con la opción ´--run_mode´.

EJEMPLOS

find

Recupera un nodo "vacío" (sin clases, sin parámetros impuestos por ENC y con un entorno de "production"):

$ puppet node find somenode.puppetlabs.lan --terminus plain --render-as yaml

Recupera un nodo utilizando el ENC configurado del Puppet Server:

$ puppet node find somenode.puppetlabs.lan --terminus exec --run_mode server --render-as yaml

Recupera el mismo nodo del Puppet Server:

$ puppet node find somenode.puppetlabs.lan --terminus rest --render-as yaml

NOTAS

Este subcomando es una cara de indirector, que expone las acciones find, search, save y destroy para un subsistema indirectado de Puppet. Los terminuses válidos para esta cara incluyen:

  • exec
  • json
  • memory
  • msgpack
  • plain
  • rest
  • store_configs
  • yaml
