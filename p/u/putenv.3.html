putenv(3) Manual de Funciones de Biblioteca putenv(3)

NOMBRE

putenv - cambiar o añadir una variable de entorno

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdlib.h>
int putenv(char *string);
Requisitos de Macro de Prueba de Características para glibc (ver feature_test_macros(7)):

putenv():

    _XOPEN_SOURCE
        || /* glibc >= 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE

DESCRIPCIÓN

La función putenv() añade o cambia el valor de las variables de entorno. El argumento string tiene el formato nombre=valor. Si nombre no existe ya en el entorno, entonces string se añade al entorno. Si nombre ya existe, entonces el valor de nombre en el entorno se cambia a valor. La cadena apuntada por string pasa a formar parte del entorno, por lo que modificar la cadena cambia el entorno.

VALOR DE RETORNO

La función putenv() devuelve cero si tiene éxito. En caso de fallo, devuelve un valor distinto de cero y errno se establece para indicar el error.

ERRORES

ENOMEM
Espacio insuficiente para asignar nuevo entorno.

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, ver attributes(7).

Interfaz Atributo Valor
putenv () Seguridad de hilos MT-Unsafe const:env

ESTÁNDARES

POSIX.1-2008.

HISTORIA

POSIX.1-2001, SVr2, 4.3BSD-Reno.

No se requiere que la función putenv() sea reentrante, y la de glibc 2.0 no lo es, pero la versión 2.1 de glibc sí.

Desde glibc 2.1.2, la implementación de glibc cumple con SUSv2: se utiliza el puntero string proporcionado a putenv(). En particular, esta cadena pasa a formar parte del entorno; modificarla más tarde cambiará el entorno. (Por lo tanto, es un error llamar a putenv() con una variable automática como argumento y luego salir de la función que llama mientras string sigue siendo parte del entorno). Sin embargo, de glibc 2.0 a glibc 2.1.1, difiere: se utiliza una copia de la cadena. Por un lado, esto causa una fuga de memoria y, por otro, viola SUSv2.

La versión 4.3BSD-Reno, al igual que glibc 2.0, utiliza una copia; esto se corrigió en todas las BSD modernas.

SUSv2 elimina el const del prototipo, al igual que glibc 2.1.3.

La implementación de la biblioteca GNU C proporciona una extensión no estándar. Si string no incluye un signo de igual:


putenv("NOMBRE");

entonces la variable nombrada se elimina del entorno del llamador.

VER TAMBIÉN

clearenv(3), getenv(3), setenv(3), unsetenv(3), environ(7)
