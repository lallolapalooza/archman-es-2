NOMBRE

puppet-agent - El demonio del agente de puppet

SINOPSIS

Recupera la configuración del cliente del maestro de Puppet y la aplica al host local.

Este servicio puede ejecutarse como un demonio, ejecutarse periódicamente usando cron (o algo similar), o ejecutarse interactivamente con fines de prueba.

USO

puppet agent [--certname NOMBRE] [-D|--daemonize|--no-daemonize] [-d|--debug] [--detailed-exitcodes] [--digest DIGEST] [--disable [MENSAJE]] [--enable] [--fingerprint] [-h|--help] [-l|--logdest syslog|eventlog|RUTA_ARCHIVO_ABS|console] [--serverport PUERTO] [--noop] [-o|--onetime] [--sourceaddress DIRECCION_IP] [-t|--test] [-v|--verbose] [-V|--version] [-w|--waitforcert SEGUNDOS]

DESCRIPCIÓN

Este es el cliente principal de puppet. Su trabajo es recuperar la configuración de la máquina local de un servidor remoto y aplicarla. Para comunicarse exitosamente con el servidor remoto, el cliente debe tener un certificado firmado por una autoridad de certificación en la que el servidor confíe; el método recomendado para esto, por el momento, es ejecutar una autoridad de certificación como parte del servidor puppet (que es el valor predeterminado). El cliente se conectará y solicitará un certificado firmado, y continuará conectándose hasta que reciba uno.

Una vez que el cliente tenga un certificado firmado, recuperará su configuración y la aplicará.

NOTAS DE USO

´puppet agent´ hace todo lo posible por encontrar un compromiso entre el uso interactivo y el uso de demonio. Si lo ejecuta sin argumentos ni configuración, pasa a segundo plano, intenta obtener un certificado firmado, y recupera y aplica su configuración cada 30 minutos.

Algunas banderas están diseñadas específicamente para uso interactivo --- en particular, ´test´, ´tags´ y ´fingerprint´ son útiles.

´--test´ se ejecuta una vez en primer plano con registro detallado, y luego sale. También sale si no puede obtener un catálogo válido. --test incluye la opción ´--detailed-exitcodes´ por defecto y sale con uno de los siguientes códigos de salida:

  • 0: La ejecución se completó sin cambios ni fallos; el sistema ya estaba en el estado deseado.
  • 1: La ejecución falló, o no se intentó debido a que otra ejecución ya estaba en curso.
  • 2: La ejecución se completó y algunos recursos fueron modificados.
  • 4: La ejecución se completó y algunos recursos fallaron.
  • 6: La ejecución se completó e incluyó tanto cambios como fallos.

´--tags´ te permite especificar qué porciones de una configuración deseas aplicar. Los elementos de Puppet se etiquetan con todos los nombres de clase o definición que los contienen, y puedes usar la bandera ´tags´ para especificar uno de estos nombres, lo que hace que solo se apliquen los elementos de configuración contenidos dentro de esa clase o definición. Esto es muy útil cuando estás probando nuevas configuraciones --- por ejemplo, si recién estás comenzando a administrar ´ntpd´, pondrías todos los nuevos elementos en una clase ´ntpd´, y llamarías a puppet con ´--tags ntpd´, lo que solo aplicaría esa pequeña porción de la configuración durante tus pruebas, en lugar de aplicar todo.

´--fingerprint´ es una bandera de una sola vez. En este modo, ´puppet agent´ se ejecuta una vez y muestra en la consola (y en el registro) la huella digital del certificado actual (o solicitud de firma de certificado). Proporcionar la opción ´--digest´ te permite usar un algoritmo de hash diferente para generar la huella digital. El uso principal es verificar que antes de firmar una solicitud de certificado en el maestro, la solicitud de certificado que el maestro recibió es la misma que envió el cliente (para evitar ataques de intermediario al firmar certificados).

´--skip_tags´ es una bandera utilizada para filtrar recursos. Si se establece, entonces solo se aplicarán los recursos que no estén etiquetados con las etiquetas especificadas. Los valores deben estar separados por comas.

OPCIONES

Ten en cuenta que cualquier configuración de Puppet que sea válida en el archivo de configuración también es un argumento largo válido. Por ejemplo, ´server´ es una configuración válida, por lo que puedes especificar ´--server nombre_servidor´ como argumento. Las configuraciones booleanas aceptan un prefijo ´--no-´ para desactivar un comportamiento, traduciéndose en pares ´--setting´ y ´--no-setting´, como --daemonize y --no-daemonize.

Consulta la documentación del archivo de configuración en https://puppet.com/docs/puppet/latest/configuration.html para obtener la lista completa de configuraciones aceptables. Una lista comentada de todas las configuraciones también se puede generar ejecutando puppet agent con ´--genconfig´.

  • --certname: Establece el nombre de certificado (ID único) del cliente. El maestro lee esta cadena de identificación única, que generalmente se establece en el nombre de dominio completo del nodo, para determinar qué configuraciones recibirá el nodo. Utiliza esta opción para depurar problemas de configuración o implementar esquemas de identificación de nodos inusuales. (Esta es una configuración de Puppet y puede ir en puppet.conf).
  • --daemonize: Envía el proceso al segundo plano. Este es el valor predeterminado. (Esta es una configuración de Puppet y puede ir en puppet.conf. Ten en cuenta el prefijo especial ´no-´ para las configuraciones booleanas en la línea de comandos).
  • --no-daemonize: No envía el proceso al segundo plano. (Esta es una configuración de Puppet y puede ir en puppet.conf. Ten en cuenta el prefijo especial ´no-´ para las configuraciones booleanas en la línea de comandos).
  • --debug: Habilita la depuración completa.
  • --detailed-exitcodes: Proporciona información adicional sobre la ejecución a través de códigos de salida; solo funciona si ´--test´ o ´--onetime´ también se especifican. Si está habilitado, ´puppet agent´ utiliza los siguientes códigos de salida:
0: La ejecución se completó sin cambios ni fallos; el sistema ya estaba en el estado deseado.
1: La ejecución falló, o no se intentó debido a que otra ejecución ya estaba en curso.
2: La ejecución se completó y algunos recursos fueron modificados.
4: La ejecución se completó y algunos recursos fallaron.
6: La ejecución se completó e incluyó tanto cambios como fallos.
  • --digest: Cambia el algoritmo de hash utilizado para la huella digital del certificado. El valor predeterminado es SHA256. Los valores válidos dependen de la versión de OpenSSL instalada, pero probablemente incluirán MD5, MD2, SHA1 y SHA256.
  • --disable: Deshabilita el trabajo en el sistema local. Esto coloca un archivo de bloqueo en su lugar, lo que hace que ´puppet agent´ no funcione en el sistema hasta que se elimine el archivo de bloqueo. Esto es útil si estás probando una configuración y no quieres que la configuración central anule el estado local hasta que todo esté probado y confirmado.
Disable también puede tomar un mensaje opcional que será reportado por ´puppet agent´ en la próxima ejecución deshabilitada.
´puppet agent´ utiliza el mismo archivo de bloqueo mientras se está ejecutando, por lo que no más de un proceso ´puppet agent´ está funcionando a la vez.
´puppet agent´ sale después de ejecutar esto.
•
--enable: Habilita el trabajo en el sistema local. Esto elimina cualquier archivo de bloqueo, lo que hace que ´puppet agent´ comience a administrar el sistema local nuevamente. Sin embargo, continúa utilizando su programación normal, por lo que podría no iniciarse durante otra media hora.
´puppet agent´ sale después de ejecutar esto.
  • --evaltrace: Registra cada recurso a medida que se evalúa. Esto te permite ver interactivamente exactamente lo que se está haciendo. (Esta es una configuración de Puppet y puede ir en puppet.conf. Ten en cuenta el prefijo especial ´no-´ para las configuraciones booleanas en la línea de comandos).
  • --fingerprint: Muestra la huella digital actual del certificado o de la solicitud de firma de certificado y luego sale. Utiliza la opción ´--digest´ para cambiar el algoritmo de hash utilizado.
  • --help: Imprime este mensaje de ayuda
  • --job-id: Adjunta el ID de trabajo especificado a la solicitud de catálogo y al informe utilizados para esta ejecución del agente. Esta opción solo funciona cuando ´--onetime´

NAME

puppet-agent - run a Puppet client or apply a Puppet manifest

SYNOPSIS

puppet agent --server puppet.domain.com [--options]

USAGE

puppet agent [-t | --test] [--color color] [--debug] [--disable STRING]
    [--disable_only_when STRING] [--diff] [--diff-storage-on-patch] [--disable_per_environment_modulepath]
    [--environment STRING] [--environmentpath STRING] [--evaltrace] [--exclude STRING]
    [--graph] [--graphdir STRING] [--help] [--ignoreschedules] [--immutable_load]
    [--libdir STRING] [--logdest STRING] [--log_level LEVEL] [--modulepath STRING]
    [--no_app_defaults_run] [--no_enable] [--no-daemonize] [--no-ignorecache] [--no-lastrunreport]
    [--no_report] [--no_use_cache_on_failure] [--noop] [--onetime] [--pluginsync] [--proxy STRING]
    [--puppetdir STRING] [--rundir STRING] [--splay] [--splaylimit INTEGER]
    [--statehook STRING] [--test] [--trace] [--trap STRING] [--tree STRING]
    [--url STRING] [--validate_immutable_loaddir] [--verbose] [--version] [--waitforcert INTEGER]
    [--write_catalog_summary]

DESCRIPTION

The puppet agent command runs as a client daemon that applies catalogs received from the puppet master. It can also be run as a standalone command to apply a local manifest, or to apply a catalog for testing or debugging purposes.

When run as a daemon (the default behavior), puppet agent periodically checks in with the puppet master, retrieves its most recent catalog, and applies it. It also submits reports to the puppet master.

Puppet agent can also be run in a standalone mode. This is useful for applying a single manifest file (often for initial setup or configuration testing), or when debugging catalogs.

USAGE NOTES

Puppet agent settings can be configured via the puppet.conf file. Command-line options will override settings in puppet.conf.

When running puppet agent as a daemon, it must be started using the puppet agent --daemonize command (which is the default behavior) or through an init system like systemd or upstart.

In addition to the options listed below, puppet agent accepts any valid Puppet setting as a command-line argument. For example, you can set the environment directly on the command line:

$ puppet agent --environment production

OPTIONS

--allow_puppetfile_errors
Allows puppet agent to continue applying a catalog even if Puppetfile errors occur during module installation.
--certdir STRING
The directory to find certificates. (Puppet setting)
--clientbucketdir STRING
The directory where the client stores files. (Puppet setting)
--config STRING
The configuration file to use.
--config_file STRING
The configuration file to use. (Deprecated, use --config)
--debug
Enable debug logging.
--detailed-exitcodes
Exit with a status code that indicates whether a configuration change was made. An exit code of 0 means no changes were made, 1 means changes were made, and 2 means there was an error.
--deviceconfig STRING
A file containing device credentials. (Puppet setting)
--device_libdir STRING
Device library directory. (Puppet setting)
--diff
Show differences between files that are managed by Puppet. Only works when Puppet is managing files, and when the file content is retrieved from the Puppet master. (Puppet setting)
--diff-storage-on-patch
When enabled, the diff file will be stored on the node for subsequent patches. (Puppet setting)
--disable STRING
Disable Puppet agent operation. You can specify a file to disable by using the --disable option. Puppet agent will not run if any disabled files are present. (Puppet setting)
--disable_only_when STRING
Disable Puppet agent operation only when the specified file exists. (Puppet setting)
--disable_per_environment_modulepath
Do not append the environment-specific modulepath when searching for modules.
--disabledir STRING
The directory containing disabled files. (Puppet setting)
--environment STRING
Set the Puppet environment. Defaults to production.
--environmentpath STRING
Set the directory for finding environments. Defaults to /etc/puppetlabs/code/environments.
--evaltrace
Show a trace of events that occur during the evaluation of resources.
--exclude STRING
A file containing a list of files and directories to exclude from Puppet operations.
--graph
Enable graph generation. (Puppet setting)
--graphdir STRING
The directory in which to store generated graphs. (Puppet setting)
--help
Print this help message.
--ignorecache
Do not use the cache when evaluating file metadata. (Puppet setting)
--ignoreschedules
Do not run scheduled tasks.
--immutable_load
Load plugins and facts in an immutable way. (Puppet setting)
--libdir STRING
The directory containing Puppet libraries. (Puppet setting)
--logdest
Where to send log messages. Choose between syslog (the POSIX syslog service), eventlog (the Windows Event Log), console, or the path to a log file. If debugging or verbosity is enabled, this defaults to console. Otherwise, it defaults to syslog on POSIX systems and eventlog on Windows. Multiple destinations can be set using a comma separated list (eg: /path/file1,console,/path/file2).
A path ending with .json will receive structured output in JSON format. The log file will not have an ending ] automatically written to it due to the appending nature of logging. It must be appended manually to make the content valid JSON.
A path ending with .jsonl will receive structured output in JSON Lines format.
--log_level LEVEL
Set the log level. Possible values are: debug, info, notice, warning, error, fatal. Defaults to notice.
--masterport INTEGER
The port on which to contact the Puppet Server. (This is a Puppet setting, and can go in puppet.conf. Deprecated in favor of the serverport setting.)
--modulepath STRING
Set the module path. Multiple directories can be separated by colons (POSIX) or semicolons (Windows). Defaults to /etc/puppetlabs/code/environments/$environment/modules:/etc/puppetlabs/code/modules.
--no-daemonize
Run Puppet in the foreground instead of daemonizing.
--no-ignorecache
Use the cache when evaluating file metadata.
--no-lastrunreport
Do not store the last run report.
--no_enable
Do not enable Puppet after it has been disabled.
--no_report
Do not send reports to the Puppet master.
--no_use_cache_on_failure
Do not cache a failed run.
--no_splay
Disable splay. When enabled, Puppet agent will randomly delay the start of a Puppet run by up to the configured splaylimit.
--noop
Use noop mode where the daemon runs in a no-op or dry-run mode. This is useful for seeing what changes Puppet would make without actually executing the changes. (This is a Puppet setting, and can go in puppet.conf. Note the special no- prefix for boolean settings on the command line.)
--onetime
Run the configuration once. Runs a single (normally daemonized) Puppet run. Useful for interactively running puppet agent when used in conjunction with the --no-daemonize option. (This is a Puppet setting, and can go in puppet.conf. Note the special no- prefix for boolean settings on the command line.)
--pluginsync
Whether to sync plugins. Defaults to true.
--pluginsync_timeout
The amount of time, in seconds, to wait for pluginsync to complete. Defaults to 120 seconds.
--proxy STRING
Specify a proxy server for Puppet to use for all network connections.
--puppetdir STRING
The directory containing Puppet’s configuration files. Defaults to /etc/puppetlabs.
--rundir STRING
The directory in which to store PID files. Defaults to /var/run/puppetlabs/puppet.
--serverport INTEGER
The port on which to contact the Puppet Server. (This is a Puppet setting, and can go in puppet.conf.)
--show_diff
Show differences between files that are managed by Puppet. (Puppet setting)
--splay
Enable splay. When enabled, Puppet agent will randomly delay the start of a Puppet run by up to the configured splaylimit. Defaults to true.
--splaylimit INTEGER
The maximum amount of time, in seconds, to delay the start of a Puppet run.
--statehook STRING
A hook script to run when the state of a resource changes. (Puppet setting)
--test
Enable the most common options used for testing. These are onetime, verbose, no-daemonize, no-usecacheonfailure, detailed-exitcodes, no-splay, and show_diff.
--trace
Print stack traces on some errors. (This is a Puppet setting, and can go in puppet.conf. Note the special no- prefix for boolean settings on the command line.)
--trap STRING
Specify a signal to trap. (Puppet setting)
--tree STRING
Write the catalog to disk as a directory of files. (Puppet setting)
--url STRING
Run Puppet with a catalog from the specified URL.
--validate_immutable_loaddir
Validate the immutable load directory. (Puppet setting)
--verbose
Turn on verbose reporting.
--version
Print the puppet version number and exit.
--waitforcert INTEGER
This option only matters for daemons that do not yet have certificates and it is enabled by default, with a value of 120 (seconds). This causes puppet agent to connect to the server every 2 minutes and ask it to sign a certificate request. This is useful for the initial setup of a puppet client. You can turn off waiting for certificates by specifying a time of 0. (This is a Puppet setting, and can go in puppet.conf.)
--write_catalog_summary
After compiling the catalog saves the resource list and classes list to the node in the state directory named classes.txt and resources.txt (This is a Puppet setting, and can go in puppet.conf.)

EXAMPLE

$ puppet agent --server puppet.domain.com

DIAGNOSTICS

Puppet agent accepts the following signals:

SIGHUP
Restart the puppet agent daemon.
SIGINT and SIGTERM
Shut down the puppet agent daemon.
SIGUSR1
Immediately retrieve and apply configurations from the puppet master.
SIGUSR2
Close file descriptors for log files and reopen them. Used with logrotate.
