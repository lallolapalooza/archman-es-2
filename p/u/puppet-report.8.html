NOMBRE

puppet-report - Crear, mostrar y enviar informes.

SINOPSIS

puppet report acción [--terminus _TERMINUS]

OPCIONES

Tenga en cuenta que cualquier configuración válida en el archivo de configuración también es un argumento largo válido, aunque puede o no ser relevante para la acción actual. Por ejemplo, server y run_mode son configuraciones válidas, por lo que puede especificar --server <nombre_servidor>, o --run_mode <modo_ejecucion> como argumento.

Consulte la documentación del archivo de configuración en https://puppet.com/docs/puppet/latest/configuration.html para obtener la lista completa de parámetros aceptables. También puede generar una lista comentada de todas las opciones de configuración ejecutando puppet con --genconfig.

--render-as FORMATO
El formato en el que se renderizará la salida. Los formatos más comunes son json, s (string), yaml y console, pero otras opciones como dot a veces están disponibles.
--verbose
Si se debe registrar de forma detallada.
--debug
Si se deben registrar información de depuración.
--terminus _TERMINUS
Las caras indirectas exponen subsistemas indirectos de Puppet. Estos subsistemas pueden recuperar y alterar un tipo específico de datos (con las acciones familiares de find, search, save y destroy) desde un número arbitrario de backends conectables. En la jerga de Puppet, estos backends se llaman terminuses.
Casi todos los subsistemas indirectos tienen un terminus rest que interactúa con los datos del puppet master. La mayoría tienen terminuses adicionales para varios modelos de datos locales, que a su vez son utilizados por el subsistema indirecto en el puppet master siempre que recibe una solicitud remota.
El terminus para una acción a menudo se determina por el contexto, pero ocasionalmente necesita establecerse explícitamente. Consulte la sección "Notas" de la página man de esta cara para obtener más detalles.

ACCIONES

info - Imprimir la clase de terminus predeterminada para esta cara.
SINOPSIS
puppet report info [--terminus _TERMINUS]
DESCRIPCIÓN
Imprime la clase de terminus predeterminada para este subcomando. Tenga en cuenta que los diferentes modos de ejecución pueden tener diferentes terminuses predeterminados; en caso de duda, especifique el modo de ejecución con la opción ´--run_mode´.
save - Solo API: enviar un informe.
SINOPSIS
puppet report save [--terminus _TERMINUS] informe
DESCRIPCIÓN
Solo API: crear o sobrescribir un objeto. Como el framework Faces actualmente no acepta datos de STDIN, las acciones de guardado no se pueden invocar desde la línea de comandos en este momento.
DEVUELVE
Nada.
submit - Solo API: enviar un informe con manejo de errores.
SINOPSIS
puppet report submit [--terminus _TERMINUS] informe
DESCRIPCIÓN
Solo API: Envía un informe al puppet master. Esta acción es esencialmente un atajo y un envoltorio para la acción save con el terminus rest, y proporciona detalles adicionales en caso de fallo.

EJEMPLOS

save

Desde la implementación de puppet report submit (ejemplo de API):

begin Puppet::Transaction::Report.indirection.terminus_class = :rest Puppet::Face[:report, "0.0.1"].save(report) Puppet.notice "Informe cargado para #{report.name}" rescue => detalle Puppet.log_exception(detalle, "No se pudo enviar el informe: #{detalle}") end

submit

Ejemplo de API: report = Puppet::Face[:catalog, ´0.0.1´].apply Puppet::Face[:report, ´0.0.1´].submit(report) return report

NOTAS

Este subcomando es una cara indirecta, que expone las acciones find, search, save y destroy para un subsistema indirecto de Puppet. Los terminuses válidos para esta cara incluyen:

  • json
  • msgpack
  • processor
  • rest
  • yaml
