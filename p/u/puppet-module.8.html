NOMBRE

puppet-module - Crea, instala y busca módulos en Puppet Forge.

SINOPSIS

puppet module acción [--environment production ] [--modulepath ]

DESCRIPCIÓN

Este subcomando puede encontrar, instalar y gestionar módulos de Puppet Forge, un repositorio de código Puppet contribuido por usuarios. También puede generar módulos vacíos y preparar módulos desarrollados localmente para su publicación en Forge.

OPCIONES

Tenga en cuenta que cualquier configuración válida en el archivo de configuración también es un argumento largo válido, aunque puede o no ser relevante para la acción actual. Por ejemplo, server y run_mode son configuraciones válidas, por lo que puede especificar --server <nombre_servidor>, o --run_mode <modo_ejecución> como argumento.

Consulte la documentación del archivo de configuración en https://puppet.com/docs/puppet/latest/configuration.html para obtener la lista completa de parámetros aceptables. También se puede generar una lista comentada de todas las opciones de configuración ejecutando puppet con --genconfig.

--render-as FORMATO
El formato en el que se renderizará la salida. Los formatos más comunes son json, s (string), yaml y console, pero otras opciones como dot a veces están disponibles.
--verbose
Si se registrarán mensajes detallados.
--debug
Si se registrará información de depuración.
--environment producción
El entorno en el que se está ejecutando Puppet. Para los clientes, como puppet agent, esto determina el entorno en sí, que Puppet utiliza para encontrar módulos y mucho más. Para los servidores, como puppet server, esto proporciona el entorno predeterminado para los nodos de los que Puppet no sabe nada.
Al definir un entorno en la sección [agent], esto se refiere al entorno que el agente solicita al servidor principal. El entorno no tiene que existir en el sistema de archivos local porque el agente lo recupera del servidor principal. Esta definición se utiliza al ejecutar puppet agent.
Cuando se define en la sección [user], el entorno se refiere a la ruta que Puppet utiliza para buscar código y módulos relacionados con su ejecución. Esto requiere que el entorno exista localmente en el sistema de archivos donde se está ejecutando puppet. Los subcomandos de Puppet, incluyendo puppet module y puppet apply, utilizan esta definición.
Dado que el contexto y los efectos varían según la sección de configuración https://puppet.com/docs/puppet/latest/config_file_main.html#config-sections en la que se define la configuración environment, no la establezca globalmente.
--modulepath
La ruta de búsqueda de módulos, como una lista de directorios separados por el carácter separador de ruta del sistema. (El separador de ruta POSIX es ´:´, y el separador de ruta de Windows es ´;´.)
No está permitido establecer un valor global para modulepath en puppet.conf (pero se puede anular desde la línea de comandos). Por favor, utilice entornos de directorio en su lugar. Si necesita usar algo más que el modulepath predeterminado de <DIRECTORIO DE MÓDULOS DEL ENTORNO ACTIVO>:$basemodulepath, puede establecer modulepath en environment.conf. Para más información, consulte https://puppet.com/docs/puppet/latest/environments_about.html

ACCIONES

changes - Muestra archivos modificados de un módulo instalado.
SINOPSIS
puppet module changes ruta
DESCRIPCIÓN
Muestra cualquier archivo en un módulo que haya sido modificado desde que se instaló. Esta acción compara los archivos en disco con las sumas de verificación MD5 incluidas en el archivo checksums.json del módulo o, si este falta, en metadata.json.
RETORNA
Matriz de cadenas que representan las rutas de los archivos modificados.
install - Instala un módulo desde Puppet Forge o un archivo de distribución.
SINOPSIS
puppet module install [--force | -f] [--target-dir DIR | -i DIR] [--ignore-dependencies] [--version VER | -v VER] nombre
DESCRIPCIÓN
Instala un módulo desde Puppet Forge o desde un archivo de distribución. Nota: La instalación de módulos utiliza sumas de verificación MD5, que están prohibidas en sistemas con FIPS habilitado.
El módulo especificado se instalará en el directorio especificado con la opción --target-dir, que por defecto es el primer directorio en el modulepath.
OPCIONES --force | -f - Fuerza la sobrescritura del módulo existente, si lo hay. Implica --ignore-dependencies.
--ignore-dependencies - No intentes instalar dependencias. Implicado por --force.
--target-dir DIR | -i DIR - El directorio en el que se instalan los módulos; por defecto es el primer directorio en el modulepath.
Especificar esta opción cambiará el directorio de instalación y utilizará el modulepath existente al comprobar dependencias. Si desea comprobar un conjunto diferente de directorios para dependencias, también debe usar las opciones --environment o --modulepath.
--version VER | -v VER - Versión del módulo a instalar; puede ser una versión exacta o una cadena de requisitos, por ejemplo ´>= 1.0.3´. Por defecto, la última versión.
RETORNA
Objeto pathname que representa la ruta al módulo instalado.
list - Lista los módulos instalados
SINOPSIS
puppet module list [--tree]
DESCRIPCIÓN
Lista los módulos puppet instalados. Por defecto, esta acción escanea el modulepath del bloque [main] de puppet.conf; usa la opción --modulepath para cambiar los directorios que se escanean.
La salida de esta acción incluye información de los metadatos del módulo, incluyendo números de versión y dependencias de módulos no cumplidas.
OPCIONES --tree - Si se muestran las dependencias como vista de árbol
RETORNA
Hash de rutas a objetos de módulo
uninstall - Desinstala un módulo puppet.
SINOPSIS
puppet module uninstall [--force | -f] [--ignore-changes | -c] [--version=] nombre
DESCRIPCIÓN
Desinstala un módulo puppet del modulepath (o de un directorio de destino específico). Nota: La desinstalación de módulos utiliza sumas de verificación MD5, que están prohibidas en sistemas con FIPS habilitado.
OPCIONES --force | -f - Fuerza la desinstalación de un módulo instalado incluso si hay cambios locales o la posibilidad de causar dependencias rotas.
--ignore-changes | -c - Desinstala un módulo instalado incluso si hay cambios locales en él. (Implicado por --force.)
--version= - La versión del módulo a desinstalar. Al usar esta opción, un módulo que coincida con la versión especificada debe estar instalado o se generará un error.
RETORNA
Hash de objetos de módulo que representan módulos desinstalados y errores relacionados.

NAME

puppet-module

manage puppet modules

SYNOPSIS

puppet module action [options]

DESCRIPTION

The puppet module tool is used to install, list, and uninstall modules from the Puppet Forge, or to list locally installed modules.

For information about Puppet modules, see Puppet modules.

The module tool can also be used to upgrade installed modules to the latest version or a specific version.

OPTIONS

--modulepath

A comma-separated list of directories to search for modules. Defaults to Puppet's configured modulepath.

--environment

The environment to operate in. Defaults to the current environment.

--target-dir

The directory in which to install or manage modules. Defaults to the first directory in the Puppet modulepath.

--force, -f

Force the action, such as installation or upgrade, even if it might cause broken dependencies.

--version

Specify a version number to install or upgrade to.

--ignore-dependencies

Do not attempt to install dependencies.

--ignore-changes, -c

Ignore local changes when checking or upgrading modules.

--tree

Display installed modules in a tree view.

ACTIONS

changes

Show modified files of an installed module.

puppet module changes modulepath
List changes for modules in the specified path.

install

Install a module from the Puppet Forge or a release archive.

puppet module install [name|archive]
Install a module by name or from a local archive file.
puppet module install name --version=version
Install a specific version of a module.
puppet module install name --target-dirdirectory
Install a module into a specific target directory.
puppet module install name --environmentenvironment
Install a module into a specific environment.

list

List installed modules.

puppet module list [modulepath]
List modules installed in the specified path or the default modulepath.
puppet module list --tree
Display installed modules in a tree view.
puppet module list --environmentenvironment
List modules installed in the specified environment.

uninstall

Uninstall a module.

puppet module uninstall name
Uninstall a module by name.
puppet module uninstall name --version=version
Uninstall a specific version of a module.
puppet module uninstall name --modulepathdirectory
Uninstall a module from a specific directory.
puppet module uninstall name --environmentenvironment
Uninstall a module from a specific environment.

upgrade

Upgrade an installed module.

puppet module upgrade name
Upgrade an installed module to the latest version.
puppet module upgrade name --version=version
Upgrade an installed module to a specific version.
puppet module upgrade name --environmentenvironment
Upgrade an installed module in a specific environment.

OPTIONS upgrade

--force | -f
Force the upgrade of an installed module even if there are local changes or the possibility of causing broken dependencies. Implies --ignore-dependencies.
--ignore-changes | -c
Upgrade an installed module even if there are local changes to it. (Implied by --force.)
--ignore-dependencies
Do not attempt to install dependencies. Implied by --force.
--version= name
The version of the module to upgrade to.

RETURNS

Hash

EXAMPLES

changes

Show modified files of an installed module:

$ puppet module changes /etc/puppetlabs/code/modules/vcsrepo/

warning: 1 files modified lib/puppet/provider/vcsrepo.rb

install

Install a module:

$ puppet module install puppetlabs-vcsrepo

Preparing to install into /etc/puppetlabs/code/modules ... Downloading from https://forgeapi.puppet.com ... Installing -- do not interrupt ... /etc/puppetlabs/code/modules └── puppetlabs-vcsrepo (v0.0.4)

Install a module to a specific environment:

$ puppet module install puppetlabs-vcsrepo --environment development

Preparing to install into /etc/puppetlabs/code/environments/development/modules ... Downloading from https://forgeapi.puppet.com ... Installing -- do not interrupt ... /etc/puppetlabs/code/environments/development/modules └── puppetlabs-vcsrepo (v0.0.4)

Install a specific module version:

$ puppet module install puppetlabs-vcsrepo -v 0.0.4

Preparing to install into /etc/puppetlabs/modules ... Downloading from https://forgeapi.puppet.com ... Installing -- do not interrupt ... /etc/puppetlabs/code/modules └── puppetlabs-vcsrepo (v0.0.4)

Install a module into a specific directory:

$ puppet module install puppetlabs-vcsrepo --target-dir=/opt/puppetlabs/puppet/modules

Preparing to install into /opt/puppetlabs/puppet/modules ... Downloading from https://forgeapi.puppet.com ... Installing -- do not interrupt ... /opt/puppetlabs/puppet/modules └── puppetlabs-vcsrepo (v0.0.4)

Install a module into a specific directory and check for dependencies in other directories:

$ puppet module install puppetlabs-vcsrepo --target-dir=/opt/puppetlabs/puppet/modules --modulepath /etc/puppetlabs/code/modules

Preparing to install into /opt/puppetlabs/puppet/modules ... Downloading from https://forgeapi.puppet.com ... Installing -- do not interrupt ... /opt/puppetlabs/puppet/modules └── puppetlabs-vcsrepo (v0.0.4)

Install a module from a release archive:

$ puppet module install puppetlabs-vcsrepo-0.0.4.tar.gz

Preparing to install into /etc/puppetlabs/code/modules ... Downloading from https://forgeapi.puppet.com ... Installing -- do not interrupt ... /etc/puppetlabs/code/modules └── puppetlabs-vcsrepo (v0.0.4)

Install a module from a release archive and ignore dependencies:

$ puppet module install puppetlabs-vcsrepo-0.0.4.tar.gz --ignore-dependencies

Preparing to install into /etc/puppetlabs/code/modules ... Installing -- do not interrupt ... /etc/puppetlabs/code/modules └── puppetlabs-vcsrepo (v0.0.4)

list

List installed modules:

$ puppet module list

/etc/puppetlabs/code/modules ├── bodepd-create_resources (v0.0.1) ├── puppetlabs-bacula (v0.0.2) ├── puppetlabs-mysql (v0.0.1) ├── puppetlabs-sqlite (v0.0.1) └── puppetlabs-stdlib (v2.2.1) /opt/puppetlabs/puppet/modules (no modules installed)

List installed modules in a tree view:

$ puppet module list --tree

/etc/puppetlabs/code/modules └─┬ puppetlabs-bacula (v0.0.2) ├── puppetlabs-stdlib (v2.2.1) ├─┬ puppetlabs-mysql (v0.0.1) │ └── bodepd-create_resources (v0.0.1) └── puppetlabs-sqlite (v0.0.1) /opt/puppetlabs/puppet/modules (no modules installed)

List installed modules from a specified environment:

$ puppet module list --environment production

/etc/puppetlabs/code/modules ├── bodepd-create_resources (v0.0.1) ├── puppetlabs-bacula (v0.0.2) ├── puppetlabs-mysql (v0.0.1) ├── puppetlabs-sqlite (v0.0.1) └── puppetlabs-stdlib (v2.2.1) /opt/puppetlabs/puppet/modules (no modules installed)

List installed modules from a specified modulepath:

$ puppet module list --modulepath /opt/puppetlabs/puppet/modules

/opt/puppetlabs/puppet/modules (no modules installed)

uninstall

Uninstall a module:

$ puppet module uninstall puppetlabs-ssh

Removed /etc/puppetlabs/code/modules/ssh (v1.0.0)

Uninstall a module from a specific directory:

$ puppet module uninstall puppetlabs-ssh --modulepath /opt/puppetlabs/puppet/modules

Removed /opt/puppetlabs/puppet/modules/ssh (v1.0.0)

Uninstall a module from a specific environment:

$ puppet module uninstall puppetlabs-ssh --environment development

Removed /etc/puppetlabs/code/environments/development/modules/ssh (v1.0.0)

Uninstall a specific version of a module:

$ puppet module uninstall puppetlabs-ssh --version 2.0.0

Removed /etc/puppetlabs/code/modules/ssh (v2.0.0)

upgrade

upgrade an installed module to the latest version

$ puppet module upgrade puppetlabs-apache

/etc/puppetlabs/puppet/modules └── puppetlabs-apache (v1.0.0 -> v2.4.0)

upgrade an installed module to a specific version

$ puppet module upgrade puppetlabs-apache --version 2.1.0

/etc/puppetlabs/puppet/modules └── puppetlabs-apache (v1.0.0 -> v2.1.0)

upgrade an installed module for a specific environment

$ puppet module upgrade puppetlabs-apache --environment test

/etc/puppetlabs/code/environments/test/modules └── puppetlabs-apache (v1.0.0 -> v2.4.0)
