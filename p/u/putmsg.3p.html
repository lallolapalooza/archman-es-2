PUTMSG(3P) Manual del Programador POSIX PUTMSG(3P)

PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación en Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

putmsg, putpmsg — enviar un mensaje en un STREAM (STREAMS)

SINOPSIS

#include <stropts.h>
int putmsg(int fildes, const struct strbuf *ctlptr,
    const struct strbuf *dataptr, int flags);
int putpmsg(int fildes, const struct strbuf *ctlptr,
    const struct strbuf *dataptr, int band, int flags);

DESCRIPCIÓN

La función putmsg() creará un mensaje a partir de los búferes del proceso y enviará el mensaje a un archivo STREAMS. El mensaje puede contener una parte de datos, una parte de control, o ambas. Las partes de datos y control se distinguen por su colocación en búferes separados, como se describe a continuación. La semántica de cada parte está definida por el módulo STREAMS que recibe el mensaje.

La función putpmsg() es equivalente a putmsg(), excepto que el proceso puede enviar mensajes en diferentes bandas de prioridad. Excepto donde se indique lo contrario, todos los requisitos de putmsg() también se aplican a putpmsg().

El argumento fildes especifica un descriptor de archivo que referencia a un STREAM abierto. Los argumentos ctlptr y dataptr apuntan cada uno a una estructura strbuf.

El argumento ctlptr apunta a la estructura que describe la parte de control, si la hay, que se incluirá en el mensaje. El miembro buf en la estructura strbuf apunta al búfer donde reside la información de control, y el miembro len indica el número de bytes que se enviarán. El miembro maxlen no es utilizado por putmsg(). De manera similar, el argumento dataptr especifica los datos, si los hay, que se incluirán en el mensaje. El argumento flags indica qué tipo de mensaje se debe enviar y se describe más adelante.

Para enviar la parte de datos de un mensaje, la aplicación deberá asegurarse de que dataptr no sea un puntero nulo y que el miembro len de dataptr sea 0 o mayor. Para enviar la parte de control de un mensaje, la aplicación deberá asegurarse de que se establezcan los valores correspondientes para ctlptr. No se enviará ninguna parte de datos (control) si dataptr(ctlptr) es un puntero nulo o si el miembro len de dataptr(ctlptr) se establece en -1.

Para putmsg(), si se especifica una parte de control y flags se establece en RS_HIPRI, se enviará un mensaje de alta prioridad. Si no se especifica ninguna parte de control y flags se establece en RS_HIPRI, putmsg() fallará y establecerá errno en [EINVAL]. Si flags se establece en 0, se enviará un mensaje normal (banda de prioridad igual a 0). Si no se especifican partes de control y de datos y flags se establece en 0, no se enviará ningún mensaje y se devolverá 0.

Para putpmsg(), las flags son diferentes. El argumento flags es una máscara de bits con las siguientes flags mutuamente excluyentes definidas: MSG_HIPRI y MSG_BAND. Si flags se establece en 0, putpmsg() fallará y establecerá errno en [EINVAL]. Si se especifica una parte de control y flags se establece en MSG_HIPRI y band se establece en 0, se enviará un mensaje de alta prioridad. Si flags se establece en MSG_HIPRI y no se especifica ninguna parte de control o band se establece en un valor distinto de cero, putpmsg() fallará y establecerá errno en [EINVAL]. Si flags se establece en MSG_BAND, se enviará un mensaje en la banda de prioridad especificada por band. Si no se especifican partes de control y de datos y flags se establece en MSG_BAND, no se enviará ningún mensaje y se devolverá 0.

La función putmsg() se bloqueará si la cola de escritura del STREAM está llena debido a condiciones internas de control de flujo, con las siguientes excepciones:

*
Para mensajes de alta prioridad, putmsg() no se bloqueará en esta condición y continuará procesando el mensaje.
*
Para otros mensajes, putmsg() no se bloqueará pero fallará cuando la cola de escritura esté llena y O_NONBLOCK esté establecido.

La función putmsg() también se bloqueará, a menos que se vea impedida por falta de recursos internos, mientras espera la disponibilidad de bloques de mensajes en el STREAM, independientemente de la prioridad o de si O_NONBLOCK ha sido especificado. No se enviará ningún mensaje parcial.

VALOR DE RETORNO

Al completarse con éxito, putmsg() y putpmsg() devolverán 0; de lo contrario, devolverán -1 y establecerán errno para indicar el error.

ERRORES

Las funciones putmsg() y putpmsg() fallarán si:

EAGAIN
Se especificó un mensaje no prioritario, la flag O_NONBLOCK está establecida, y la cola de escritura del STREAM está llena debido a condiciones internas de control de flujo; o no se pudieron asignar búferes para el mensaje que se iba a crear.
EBADF
fildes no es un descriptor de archivo válido abierto para escritura.
EINTR
Se capturó una señal durante putmsg().
EINVAL
Se especificó un valor indefinido en flags, o flags se estableció en RS_HIPRI o MSG_HIPRI y no se proporcionó ninguna parte de control, o el STREAM o multiplexor referenciado por fildes está enlazado (directa o indirectamente) aguas abajo de un multiplexor, o flags se estableció en MSG_HIPRI y band es distinto de cero (solo para putpmsg()).
ENOSR
No se pudieron asignar búferes para el mensaje que se iba a crear debido a insuficientes recursos de memoria de STREAMS.
ENOSTR
No hay ningún STREAM asociado a fildes.
ENXIO
Se generó una condición de desconexión aguas abajo para el STREAM especificado.
EPIPE o EIO
El argumento fildes se refiere a una tubería basada en STREAMS y el otro extremo de la tubería está cerrado. Se genera una señal SIGPIPE para el hilo que llama.
ERANGE
El tamaño de la parte de datos del mensaje no se encuentra dentro del rango especificado por los tamaños máximo y mínimo de paquete del módulo STREAM superior. Este valor también se devuelve si la parte de control del mensaje es mayor que el tamaño máximo configurado de la parte de control de un mensaje, o si la parte de datos de un mensaje es mayor que el tamaño máximo configurado de la parte de datos de un mensaje.

Además, putmsg() y putpmsg() fallarán si el cabezal STREAM había procesado un error asíncrono antes de la llamada. En este caso, el valor de errno no refleja el resultado de putmsg() o putpmsg(), sino que refleja el error previo.

Las siguientes secciones son informativas.

EJEMPLOS

Envío de un mensaje de alta prioridad

Se asume que el valor de fd se refiere a un archivo STREAMS abierto. Esta llamada a putmsg() hace lo siguiente:

1.
Crea un mensaje de alta prioridad con una parte de control y una parte de datos, utilizando los búferes apuntados por ctrlbuf y databuf, respectivamente.
2.
Envía el mensaje al archivo STREAMS identificado por fd.
#include <stropts.h>
#include <string.h>
...
int fd;
char *ctrlbuf = "Esta es la parte de control";
char *databuf = "Esta es la parte de datos";
struct strbuf ctrl;
struct strbuf data;
int ret;
ctrl.buf = ctrlbuf;
ctrl.len = strlen(ctrlbuf);
data.buf = databuf;
data.len = strlen(databuf);
ret = putmsg(fd, &ctrl, &data, MSG_HIPRI);

Uso de putpmsg()

EJEMPLOS

Este ejemplo tiene el mismo efecto que el ejemplo anterior. Sin embargo, en este ejemplo, la función putpmsg() crea y envía el mensaje al archivo STREAMS.

#include <stropts.h>
#include <string.h>
...
int fd;
char *ctrlbuf = "Esta es la parte de control";
char *databuf = "Esta es la parte de datos";
struct strbuf ctrl;
struct strbuf data;
int ret;
ctrl.buf = ctrlbuf;
ctrl.len = strlen(ctrlbuf);
data.buf = databuf;
data.len = strlen(databuf);
ret = putpmsg(fd, &ctrl, &data, 0, MSG_HIPRI);

USO DE LA APLICACIÓN

Ninguno.

RAZONAMIENTO

Ninguno.

DIRECCIONES FUTURAS

Las funciones putmsg() y putpmsg() pueden ser eliminadas en una versión futura.
