NOMBRE

puts - Escribir en un canal

SINOPSIS

puts ?-nonewline? ?channelId? string

DESCRIPCIÓN

Escribe los caracteres proporcionados por string en el canal proporcionado por channelId.

ChannelId debe ser un identificador de un canal abierto, como un canal estándar de Tcl (stdout o stderr), el valor de retorno de una invocación de open o socket, o el resultado de un comando de creación de canal proporcionado por una extensión de Tcl. El canal debe haber sido abierto para escritura.

Si no se especifica ningún channelId, se utilizará stdout por defecto. Puts normalmente emite un carácter de nueva línea después de string, pero esta característica se puede suprimir especificando la opción -nonewline.

Los caracteres de nueva línea en la salida son traducidos por puts a secuencias de fin de línea específicas de la plataforma, de acuerdo con el valor actual de la opción -translation para el canal (por ejemplo, en PCs, las nuevas líneas se reemplazan normalmente por secuencias de retorno de carro-nueva línea. Consulte la entrada del manual de fconfigure para una discusión sobre las formas en que fconfigure alterará la salida.

Tcl almacena en búfer la salida internamente, por lo que los caracteres escritos con puts pueden no aparecer inmediatamente en el archivo o dispositivo de salida; Tcl normalmente retrasará la salida hasta que el búfer esté lleno o el canal se cierre. Puede forzar que la salida aparezca inmediatamente con el comando flush.

Cuando el búfer de salida se llena, el comando puts normalmente se bloqueará hasta que todos los datos almacenados en el búfer hayan sido aceptados para su salida por el sistema operativo. Si channelId está en modo no bloqueante, el comando puts no se bloqueará, incluso si el sistema operativo no puede aceptar los datos. En su lugar, Tcl continúa almacenando los datos en búfer y los escribe en segundo plano tan rápido como el archivo o dispositivo subyacente pueda aceptarlos. La aplicación debe utilizar el bucle de eventos de Tcl para que la salida no bloqueante funcione; de lo contrario, Tcl nunca se enterará de que el archivo o dispositivo está listo para más datos de salida. Es posible que se almacene una cantidad arbitrariamente grande de datos para un canal en modo no bloqueante, lo que podría consumir una gran cantidad de memoria. Para evitar desperdiciar memoria, la E/S no bloqueante debe usarse normalmente de forma orientada a eventos con el comando fileevent (no invoque puts a menos que haya sido notificado recientemente a través de un evento de archivo de que el canal está listo para más datos de salida).

EJEMPLOS

Escribir un mensaje corto en la consola (o dondequiera que se redireccione stdout):

puts "Hola, Mundo!"

Imprimir un mensaje en varias partes:

puts -nonewline "Hola, "
puts "Mundo!"

Imprimir un mensaje en el canal de error estándar:

puts stderr "Hola, Mundo!"

Añadir un mensaje de registro a un archivo:

set chan [open my.log a]
set timestamp [clock format [clock seconds]]
puts $chan "$timestamp - Hola, Mundo!"
close $chan

VER TAMBIÉN

file(n), fileevent(n), Tcl_StandardChannels(3)
