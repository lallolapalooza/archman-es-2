NOMBRE

puppet-catalog - Compila, guarda, visualiza y convierte catálogos.

SINOPSIS

puppet catalog acción [--terminus _TERMINUS]

DESCRIPCIÓN

Este subcomando trata con catálogos, que son artefactos compilados por nodo generados a partir de un conjunto de manifiestos de Puppet. Por defecto, interactúa con el subsistema de compilación y compila un catálogo utilizando el manifiesto y certname por defecto, pero puedes cambiar la fuente del catálogo con la opción --terminus. También puedes optar por imprimir cualquier catálogo en formato ´dot´ (para una fácil visualización de gráficos con OmniGraffle o Graphviz) con ´--render-as dot´.

OPCIONES

Ten en cuenta que cualquier configuración válida en el archivo de configuración también es un argumento largo válido, aunque puede ser o no relevante para la acción presente. Por ejemplo, server y run_mode son configuraciones válidas, por lo que puedes especificar --server <nombre_servidor>, o --run_mode <modo_ejecución> como argumento.

Consulta la documentación del archivo de configuración en https://puppet.com/docs/puppet/latest/configuration.html para obtener la lista completa de parámetros aceptables. También se puede generar una lista comentada de todas las opciones de configuración ejecutando puppet con --genconfig.

--render-as FORMATO
El formato en el que se renderizará la salida. Los formatos más comunes son json, s (cadena), yaml y console, pero otras opciones como dot a veces están disponibles.
--verbose
Si se debe registrar de forma detallada.
--debug
Si se debe registrar información de depuración.
--terminus _TERMINUS
Las caras indirectas exponen subsistemas indirectos de Puppet. Estos subsistemas son capaces de recuperar y alterar un tipo específico de datos (con las acciones familiares de find, search, save y destroy) de un número arbitrario de backends enchufables. En la jerga de Puppet, estos backends se llaman terminus.
Casi todos los subsistemas indirectos tienen un terminus rest que interactúa con los datos del maestro de puppet. La mayoría de ellos tienen terminus adicionales para varios modelos de datos locales, que a su vez son utilizados por el subsistema indirecto en el maestro de puppet siempre que recibe una solicitud remota.
El terminus para una acción a menudo se determina por el contexto, pero ocasionalmente necesita ser establecido explícitamente. Consulta la sección de "Notas" de la página man de esta cara para obtener más detalles.

ACCIONES

apply - Encontrar y aplicar un catálogo.
SINOPSIS
puppet catalog apply [--terminus _TERMINUS]
DESCRIPCIÓN
Encuentra y aplica un catálogo. Esta acción no toma argumentos, pero la fuente del catálogo se puede gestionar con la opción --terminus.
RETORNA
Nada. Cuando se usa desde la API de Ruby, devuelve un objeto Puppet::Transaction::Report.
compile - Compilar un catálogo.
SINOPSIS
puppet catalog compile [--terminus _TERMINUS]
DESCRIPCIÓN
Compila un catálogo localmente para un nodo, requiriendo acceso a módulos, clasificador de nodos, etc.
RETORNA
Un catálogo serializado.
download - Descargar el catálogo de este nodo del servidor maestro de puppet.
SINOPSIS
puppet catalog download [--terminus _TERMINUS]
DESCRIPCIÓN
Recupera un catálogo del maestro de puppet y lo guarda en la caché yaml local. Esta acción siempre contacta al maestro de puppet e ignorará los terminus alternativos.
El catálogo guardado se puede usar en cualquier acción de catálogo posterior especificando ´--terminus yaml´ para esa acción.
RETORNA
Nada.
NOTAS
Cuando se usa desde la API de Ruby, esta acción tiene el efecto secundario de dejar Puppet::Resource::Catalog.indirection.terminus_class establecido en yaml. El terminus debe ser reestablecido explícitamente para acciones de catálogo posteriores.
find - Recuperar el catálogo del nodo desde el que se ejecuta el comando.
SINOPSIS
puppet catalog find [--terminus _TERMINUS] [--facts_for_catalog] certname, facts
DESCRIPCIÓN
Recupera el catálogo del nodo desde el que se ejecuta el comando.
OPCIONES --facts_for_catalog - No implementado para la CLI; los hechos se recopilan internamente.
RETORNA
Un catálogo serializado. Cuando se usa desde la API de Ruby, devuelve un objeto Puppet::Resource::Catalog.
info - Imprimir la clase de terminus por defecto para esta cara.
SINOPSIS
puppet catalog info [--terminus _TERMINUS]
DESCRIPCIÓN
Imprime la clase de terminus por defecto para este subcomando. Ten en cuenta que diferentes modos de ejecución pueden tener diferentes termini por defecto; en caso de duda, especifica el modo de ejecución con la opción ´--run_mode´.
save - Solo API: crear o sobrescribir un objeto.
SINOPSIS
puppet catalog save [--terminus _TERMINUS] clave
DESCRIPCIÓN
Solo API: crear o sobrescribir un objeto. Como el framework de Faces no acepta datos de STDIN actualmente, las acciones de guardar no se pueden invocar desde la línea de comandos.
select - Recuperar un catálogo y filtrarlo por recursos de un tipo dado.
SINOPSIS
puppet catalog select [--terminus _TERMINUS] host tipo_recurso
DESCRIPCIÓN
Recupera un catálogo para el host especificado, luego lo busca para encontrar todos los recursos del tipo solicitado.
RETORNA
Una lista de referencias de recursos ("Tipo[título]"). Cuando se usa desde la API, devuelve un array de objetos Puppet::Resource extraídos de un catálogo.
NOTAS
Por defecto, esta acción recuperará un catálogo del subsistema compilador de Puppet; debes llamar a la acción con --terminus rest si deseas recuperar un catálogo del maestro de Puppet.
PROBLEMAS DE FORMATO: Esta acción no puede renderizar actualmente yaml útil; en su lugar, devuelve un catálogo completo. Usa json en su lugar.

EJEMPLOS

apply

Aplicar el catálogo almacenado localmente:

$ puppet catalog apply --terminus yaml

Recuperar un catálogo del maestro y aplicarlo, en un solo paso:

$ puppet catalog apply --terminus rest

Ejemplo de API:

# ...
Puppet::Face[:catalog, ´0.0.1´].download
# (Los termini son singleton; catalog.download tiene el efecto secundario de
# establecer el terminus del catálogo en yaml)
report  = Puppet::Face[:catalog, ´0.0.1´].apply
# ...

compile

Compilar catálogo para el nodo ´mynode´:

$ puppet catalog compile mynode --codedir ...

download

Recuperar y almacenar un catálogo:

$ puppet catalog download

NOMBRE

puppet-catalog - Interact with the Puppet catalog

SINOPSIS

puppet catalog find [--terminus TERMINUS] [--extra ARGS] [--mode MODE] [--trusted_facts TRUSTED_FACTS] [--environment ENV] NODE [TYPE]

puppet catalog deserialize [--terminus TERMINUS] [--extra ARGS] [--mode MODE] [--trusted_facts TRUSTED_FACTS] [--environment ENV] [--reality_file REALITY_FILE] [--rubydesc RUBYDESC] [--local_file LOCAL_FILE]

puppet catalog serialize [--terminus TERMINUS] [--extra ARGS] [--mode MODE] [--trusted_facts TRUSTED_FACTS] [--environment ENV] [--reality_file REALITY_FILE] [--rubydesc RUBYDESC] [--local_file LOCAL_FILE]

puppet catalog save [--terminus TERMINUS] [--extra ARGS] [--mode MODE] [--trusted_facts TRUSTED_FACTS] [--environment ENV] [--reality_file REALITY_FILE] [--rubydesc RUBYDESC] [--local_file LOCAL_FILE] NODE TYPE

puppet catalog delete [--terminus TERMINUS] [--extra ARGS] [--mode MODE] [--trusted_facts TRUSTED_FACTS] [--environment ENV] [--reality_file REALITY_FILE] NODE TYPE

puppet catalog select [--terminus TERMINUS] [--extra ARGS] [--mode MODE] [--trusted_facts TRUSTED_FACTS] [--environment ENV] NODE TYPE

DESCRIPCIÓN

This command is the public face for discovering and manipulating Puppet catalogs. It allows for the retrieval, serialization, and saving of catalogs for specific nodes.

OPCIONES

--terminus TERMINUS
Specifies the backend to use for the request (e.g., rest, yaml, json, compiler). Defaults to the value configured in Puppet's configuration, typically rest.
--extra ARGS
An array of extra arguments to pass to the backend.
--mode MODE
The environment mode for the request.
--trusted_facts TRUSTED_FACTS
A string containing trusted facts for the request.
--environment ENV
The Puppet environment to query.
--reality_file REALITY_FILE
Path to a file containing reality data for serialization/deserialization.
--rubydesc RUBYDESC
A Ruby descriptor for serialization/deserialization.
--local_file LOCAL_FILE
Path to a local file for serialization/deserialization.

ACCIONES

find
Finds the catalog for a given node and type.
deserialize
Deserializes a catalog from a file or string.
serialize
Serializes a catalog to a file or string.
save
Saves a catalog for a given node and type.
delete
Deletes a catalog for a given node and type.
select
Selects file resources from a node's catalog.

EJEMPLOS

Retrieve the catalog for a node named somenode.magpie.lan:

$ puppet catalog find --terminus rest somenode.magpie.lan

Deserialize a catalog from a YAML file:

$ puppet catalog deserialize --terminus yaml --local_file /tmp/catalog.yaml

Serialize a catalog to a JSON file:

$ puppet catalog serialize --terminus json --local_file /tmp/catalog.json somenode.magpie.lan

Save a catalog for a node:

$ puppet catalog save --terminus rest somenode.magpie.lan my_type

Delete a catalog for a node:

$ puppet catalog delete --terminus rest somenode.magpie.lan my_type

Puppet::Face[:plugin, '0.0.1'].download
Puppet::Face[:facts, '0.0.1'].upload
Puppet::Face[:catalog, '0.0.1'].download
# ...

select

Ask the puppet master for a list of managed file resources for a node:

$ puppet catalog select --terminus rest somenode.magpie.lan file

NOTAS

This subcommand is an indirector face, which exposes find, search, save, and destroy actions for an indirected subsystem of Puppet. Valid termini for this face include:

  • compiler
  • json
  • msgpack
  • rest
  • store_configs
  • yaml
