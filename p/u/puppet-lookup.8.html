NOMBRE

puppet-lookup - Búsqueda interactiva de Hiera

SINOPSIS

Realiza búsquedas de Hiera desde la línea de comandos.

Dado que este comando necesita acceso a tus datos de Hiera, asegúrate de ejecutarlo en un nodo que tenga una copia de esos datos. Esto generalmente implica iniciar sesión en un nodo de Servidor Puppet y ejecutar ´puppet lookup´ con sudo.

La versión más común de este comando es:

´puppet lookup CLAVE --node NOMBRE --environment ENTORNO --explain´

USO

puppet lookup [--help] [--type TIPOSTRING] [--merge first|unique|hash|deep] [--knock-out-prefix STRING-DE-PREFIJO] [--sort-merged-arrays] [--merge-hash-arrays] [--explain] [--environment ENTORNO] [--default VALOR] [--node NOMBRE-NODO] [--facts ARCHIVO] [--compile] [--render-as s|json|yaml|binary|msgpack] claves

DESCRIPCIÓN

El comando lookup es una CLI para la función ´lookup()´ de Puppet. Busca en tus datos de Hiera y devuelve un valor para la clave de búsqueda solicitada, lo que te permite probar y explorar tus datos. Es un reemplazo moderno del comando ´hiera´. Lookup utiliza la configuración para el hiera.yaml global desde la configuración de puppet, y el entorno para encontrar el hiera.yaml a nivel de entorno, así como el modulepath resultante para el entorno (para archivos hiera.yaml en módulos). Hiera normalmente se basa en los hechos de un nodo para localizar las fuentes de datos relevantes. Por defecto, ´puppet lookup´ utiliza los hechos del nodo en el que ejecutas el comando, pero puedes obtener datos para cualquier otro nodo con la opción ´--node NOMBRE´. Si es posible, el comando lookup utilizará los hechos reales almacenados del nodo solicitado de PuppetDB; si PuppetDB no está configurado o si quieres proporcionar valores de hechos arbitrarios, puedes pasar hechos alternativos como un archivo JSON o YAML con ´--facts ARCHIVO´.

Si estás depurando tus datos de Hiera y quieres ver de dónde provienen los valores, utiliza la opción ´--explain´.

Si no se especifica ´--explain´, lookup sale con 0 si se encontró un valor y con 1 en caso contrario. Con ´--explain´, lookup siempre sale con 0 a menos que haya un error importante.

Puedes proporcionar múltiples claves de búsqueda a este comando, pero solo devuelve un valor para la primera clave encontrada, omitiendo las demás.

Para más detalles sobre cómo funciona Hiera, consulta la documentación de Hiera: https://puppet.com/docs/puppet/latest/hiera_intro.html

OPCIONES

  • --help: Imprime este mensaje de ayuda.
  • --explain Explica los detalles de cómo se realizó la búsqueda y de dónde proviene el valor final (o la razón por la que no se encontró ningún valor).
  • --node NOMBRE-NODO Especifica para qué nodo buscar datos; por defecto, es el nodo donde se ejecuta el comando. Dado que el propósito de Hiera es proporcionar diferentes valores para diferentes nodos (generalmente basado en sus hechos), normalmente querrás usar los hechos de un nodo específico para explorar tus datos. Si el nodo donde ejecutas este comando está configurado para comunicarse con PuppetDB, el comando utilizará los hechos más recientes del nodo solicitado. De lo contrario, puedes anular los hechos con la opción ´--facts´.
  • --facts ARCHIVO Especifica un archivo .json o .yaml de mapeos clave => valor para anular los hechos para esta búsqueda. Cualquier hecho no especificado en este archivo mantiene su valor original.
  • --environment ENTORNO Al igual que con la mayoría de los comandos de Puppet, puedes especificar un entorno en la línea de comandos. Esto es importante para la búsqueda porque diferentes entornos pueden tener diferentes datos de Hiera. Este entorno siempre será el que se utilice independientemente de cualquier otro factor.
  • --merge first|unique|hash|deep: Especifica el comportamiento de fusión, anulando cualquier comportamiento de fusión de las lookup_options de los datos. ´first´ devuelve el primer valor encontrado. ´unique´ agrega todo a una matriz fusionada y deduplicada. ´hash´ realiza una fusión simple de hash sobrescribiendo las claves de menor prioridad de búsqueda. ´deep´ realiza una fusión profunda en valores de tipo Array y Hash. Hay opciones adicionales que se pueden usar con ´deep´.
  • --knock-out-prefix STRING-DE-PREFIJO Se puede usar con la estrategia de fusión ´deep´. Especifica un prefijo para indicar que un valor debe eliminarse del resultado final.
  • --sort-merged-arrays Se puede usar con la estrategia de fusión ´deep´. Cuando se utiliza esta bandera, todas las matrices fusionadas se ordenan.
  • --merge-hash-arrays Se puede usar con la estrategia de fusión ´deep´. Cuando se utiliza esta bandera, los hashes DENTRO de las matrices se fusionan profundamente con sus contrapartes por posición.
  • --explain-options Explica si una tabla hash lookup_options afecta a esta búsqueda y cómo se ensambló esa tabla hash. (lookup_options es cómo Hiera configura el comportamiento de fusión en los datos).
  • --default VALOR Un valor que se devolverá si Hiera no puede encontrar un valor en los datos. Para emular llamadas a la función ´lookup()´ que incluyen un valor predeterminado.
  • --type TIPOSTRING: Afirma que el valor tiene el tipo especificado. Para emular llamadas a la función ´lookup()´ que incluyen un tipo de datos.
  • --compile Realiza una compilación completa del catálogo antes de la búsqueda. Si tu jerarquía y datos solo usan las variables $facts, $trusted y $server_facts, no necesitas esta opción; sin embargo, si tu configuración de Hiera usa variables arbitrarias establecidas por un manifiesto de Puppet, podrías necesitar esta opción para obtener datos precisos. No se realiza ninguna compilación del catálogo a menos que se proporcione esta bandera.
  • --render-as s|json|yaml|binary|msgpack Especifica el formato de salida de los resultados; "s" significa texto plano. El valor por defecto al producir un valor es yaml y el valor por defecto al producir una explicación es s.

EJEMPLO

Para buscar ´key_name´ utilizando los hechos del nodo Servidor Puppet: $ puppet lookup key_name

Para buscar ´key_name´ utilizando las variables arbitrarias del nodo Servidor Puppet de un manifiesto, y clasificar el nodo si es aplicable: $ puppet lookup key_name --compile

Para buscar ´key_name´ utilizando los hechos del nodo Servidor Puppet, anulados por los hechos proporcionados en un archivo: $ puppet lookup key_name --facts fact_file.yaml

Para buscar ´key_name´ con los hechos de agent.local: $ puppet lookup --node agent.local key_name

Para obtener el primer valor encontrado para ´key_name_one´ y ´key_name_two´ con los hechos de agent.local, mientras se fusionan valores y se elimina el prefijo ´foo´ al fusionar: $ puppet lookup --node agent.local --merge deep --knock-out-prefix foo key_name_one key_name_two

Para buscar ´key_name´ con los hechos de agent.local, y devolver un valor por defecto de ´bar´ si no se encontró nada: $ puppet lookup --node agent.local --default bar key_name

Para ver una explicación de cómo se encontraría el valor para ´key_name´, usando los hechos de agent.local: $ puppet lookup --node agent.local --explain key_name

puppet-lookup(8)

NAME

puppet-lookup - Lookup puppet values from Puppet's configuration.

SYNOPSIS

puppet lookup [KEY] [--type TYPE] [--merge STRATEGY] [--node NODE] [--environment ENVIRONMENT] [--compile] [--help] [--version]

USAGE

puppet lookup is a command-line tool for looking up configuration data (facts, variables, Hiera data) from Puppet's configuration. It's useful for debugging and interactive data retrieval.

DESCRIPTION

The puppet lookup command allows you to query for specific configuration values that Puppet would use when compiling a catalog for a given node. This includes:

  • Variables: Puppet variables defined in manifests or environments.
  • Facts: Facts about the node, typically collected by Facter.
  • Hiera data: Data configured in Hiera, which is Puppet's primary mechanism for separating data from code.

The command resolves the given KEY using Puppet's data lookup mechanism, which considers multiple data sources (like Hiera, environment variables, and node facts) in a specific order.

OPTIONS

KEY
The name of the variable, fact, or Hiera key to look up.
--type TYPE
Specifies the expected data type for the looked-up value. Puppet will attempt to coerce the data to this type. If coercion fails, it will raise an error.
--merge STRATEGY
Specifies the merge strategy to use when looking up structured data. Possible strategies include deep, deep_hash, first, hash, list, none.
--node NODE
Specifies the node name for which to perform the lookup. Defaults to the current system's hostname.
--environment ENVIRONMENT
Specifies the environment to use for the lookup. Defaults to the production environment.
--compile
Forces Puppet to compile the catalog before performing the lookup. This ensures that all data sources are considered, including those that depend on compilation state.
--help
Display help information for the command.
--version
Display the Puppet version.

EXAMPLE

To look up the value of the ntp::server class parameter in the 'production' environment for a node named 'webserver.example.com':

puppet lookup ntp::server --node webserver.example.com --environment production

To look up a Hiera key with a specific type and merge strategy:

puppet lookup my_app::config::settings --type Hash --merge deep
