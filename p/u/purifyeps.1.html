PURIFYEPS(1) PURIFYEPS(1)

NOMBRE

purifyeps - hacer que un archivo PostScript Encapsulado funcione tanto con dvips como con pdflatex

SINOPSIS

purifyeps --help

purifyeps --version

purifyeps [--fontmap=archivo .fmp] [archivo .eps de entrada [archivo .eps de salida]]

purifyeps --make-man[=nombre de archivo] [--section=sección]

purifyeps --make-ps-man[=nombre de archivo] [--section=sección]

DESCRIPCIÓN

Si bien pdflatex tiene una serie de características útiles, su principal defecto en comparación con el estándar latex+dvips es que no puede leer archivos PostScript Encapsulado (EPS) normales, el formato gráfico más común en el mundo LaTeX. pdflatex solo puede leer los siguientes tipos de archivos gráficos:

PDF
La mayoría de las personas que usan pdflatex convierten sus documentos a PDF utilizando una utilidad como epstopdf. Esto funciona bien y preserva la naturaleza vectorial del EPS original. Desafortunadamente, dvips no lee PDF, por lo que se deben mantener dos versiones del gráfico si el documento se va a procesar tanto con latex+dvips como con pdflatex.
PNG
PNG es un formato de mapa de bits y, por lo tanto, escala mal. Además, dvips no lee PNG, por lo que se deben mantener dos versiones del gráfico si el documento se va a procesar tanto con latex+dvips como con pdflatex.
JPEG
JPEG es un formato de mapa de bits y, por lo tanto, escala mal. Además, dvips no lee JPEG, por lo que se deben mantener dos versiones del gráfico si el documento se va a procesar tanto con latex+dvips como con pdflatex.
MPS
Este es probablemente el formato gráfico compatible con pdflatex menos utilizado. MPS es en realidad una versión estilizada de EPS que produce MetaPost. Al igual que PDF, MPS es un formato vectorial y permanece como tal cuando se importa en un documento pdflatex. También al igual que PDF, dvips no lee MPS, por lo que se deben mantener dos versiones del gráfico si el documento se va a procesar tanto con latex+dvips como con pdflatex.

La idea detrás de purifyeps es que solo hay unas pocas diferencias pequeñas entre MPS y EPS y que un archivo puede convertirse a un formato que cumpla con las especificaciones MPS y EPS simultáneamente. purifyeps toma un archivo EPS de entrada, utiliza el filtro "mpost" de pstoedit para convertir el archivo a MetaPost (.mp), ejecuta mpost sobre el archivo para convertirlo a MPS y, finalmente, realiza algunas modificaciones en el resultado para convertir el archivo de nuevo a EPS, preservando al mismo tiempo su capacidad de ser analizado por pdflatex.

OPCIONES

--help
Muestra el "Uso" y las "Opciones" de la documentación de purifyeps.
-V, --version
Muestra el número de versión de purifyeps, los derechos de autor y la licencia.
--fontmap=archivo .fmp
Especifica el nombre de un archivo que indica a purifyeps cómo mapear nombres de fuentes TeX a nombres de fuentes PostScript. [Por defecto: mpost.fmp]
--make-man [=nombre de archivo]] [--section=sección]
Crea automáticamente una página de manual de Unix para purifyeps. sección especifica la sección [por defecto: 1 (Comandos de Usuario)]. nombre de archivo toma por defecto el nombre purifyeps.1 o un nombre de archivo análogo si se especifica sección.
--make-ps-man [=nombre de archivo]] [--section=sección]
Crea automáticamente una versión PostScript de la documentación de purifyeps. La documentación tiene el formato de una página de manual de Unix. sección especifica la sección [por defecto: 1 (Comandos de Usuario)]. nombre de archivo toma por defecto el nombre purifyeps.ps.

En operación normal (es decir, cuando no se ejecuta con "--help", "--make-man" o "--make-ps-man"), purifyeps toma el nombre de un archivo de entrada y un archivo de salida. Se puede usar el mismo nombre de archivo para ambos archivos. Si se omite el nombre del archivo de salida, la salida se enviará al dispositivo de salida estándar. Si se omite el nombre del archivo de entrada, purifyeps leerá desde el dispositivo de entrada estándar.

EJEMPLOS

Crear una versión PostScript de la documentación de purifyeps, pero llamarla happydoc.ps en lugar del valor por defecto, purifyeps.ps:

purifyeps --make-ps-man=happydoc.ps

Crear una página de manual de Unix para purifyeps (en el formato roff habitual), pero indicar que pertenece a la sección "LOCAL" en lugar de la sección 1 por defecto:

purifyeps --make-man --section=LOCAL

Purificar sample.eps (mpost.fmp está en el directorio actual):

purifyeps sample.eps sample.eps

Purificar sample.eps (mpost.fmp está en una ubicación diferente):

purifyeps --fontmap=/usr/share/pstoedit/mpost.fmp sample.eps sample.eps

Renombrar la versión purificada mientras se purifica:

purifyeps sample.eps sample-pure.eps

Hacer lo mismo, pero en un pipeline de Unix:

cat sample.eps | purifyeps > sample-pure.eps

Cuando ejecute purifyeps, debería ver la salida tanto de pstoedit como de mpost, seguida de un mensaje de éxito de purifyeps:

ARCHIVOS

mpost.fmp
Archivo que contiene mapeos entre nombres de fuentes TeX y PostScript. Vea "NOTAS" para una descripción del contenido de este archivo.

ERRORES

La notificación de errores podría definitivamente mejorarse. Los mensajes de error producidos por pstoedit y mpost a veces se ignoran silenciosamente. Además, los errores a veces hacen que purifyeps deje archivos temporales (purifyeps-#####) por ahí.

purifyeps está sujeto a todas las limitaciones que afectan a pstoedit y especialmente al backend "mpost" de pstoedit. Como resultado, purifyeps ignora ciertas construcciones de PostScript, como texto escalado de forma no uniforme.

NOTAS

purifyeps necesita un archivo que le indique cómo mapear nombres de fuentes TeX a nombres de fuentes PostScript. Este archivo debe contener dos columnas separadas por espacios. La primera enumera un nombre de fuente PostScript y la segunda enumera el equivalente TeX. Se ignoran las líneas en blanco y las líneas que comienzan con "%". El siguiente es un archivo de ejemplo .fmp:

% This is a sample font map for purifyeps.
Times-Bold                           ptmb
Times-Italic                         ptmri
Times-Roman                          ptmr
Helvetica                            phvr
Helvetica-Bold                       phvb
Helvetica-Oblique                    phvro
Courier                              pcrr
Courier-Bold                         pcrb
Courier-Oblique                      pcrro

Tenga en cuenta que este es exactamente el mismo formato que usa pstoedit. Por defecto, purifyeps busca en el directorio actual un mapa de fuentes llamado mpost.fmp. La opción de línea de comandos "--fontmap" le dice a purifyeps que use un mapa de fuentes diferente, que normalmente será el archivo mpost.fmp que viene con pstoedit.

purifyeps(1) — Arch Linux

NAME

purifyeps — remove superfluous parts of an EPS file

SYNOPSIS

purifyeps [-defer] [-list] [-out<file>] [-verbose] [<epsfile> ...]

DESCRIPTION

The purifyeps utility removes various kinds of superfluous information from PostScript files that are in Encapsulated PostScript (EPS) format, with the goal of making them more suitable for inclusion in a LaTeX document processed by pdfLaTeX.

The following types of information are removed:

  • %%BoundingBox comments that are incorrect or do not match the actual bounding box of the image.
  • %%HiResBoundingBox comments.
  • Any comments that are not PostScript comments (i.e., lines not starting with %).
  • ASCII 85 encoded streams.
  • Color stack manipulation operators.
  • The Page setup operators.
  • The pdfmark operators.
  • The PS operators that are specific to PostScript Level 3.
  • The trailer comment and the dictionary that follows it.
  • Unused procedures in the PostScript dictionary.

Additionally, purifyeps will try to fix any %%BoundingBox comments that are incorrect (e.g., where the lower-left corner is not at (0,0)).

By default, purifyeps overwrites the original files. Use the -out option to specify a different output file.

OPTIONS

-defer
When processing EPS files that were generated by MetaPost, this option defers the processing of the actual PostScript code until it is needed. This is primarily of use when processing EPS files generated by older versions of MetaPost, which sometimes contain PostScript code that is incompatible with pdfLaTeX.
-list
Lists the files that purifyeps will process, but does not actually modify them.
-out<file>
Writes the purified output to the specified <file> instead of overwriting the input file.
-verbose
Prints a running commentary on what purifyeps is doing.

EXAMPLES

To purify an EPS file named image.eps and save the result in the same file:

purifyeps image.eps

To purify image.eps and save the result in newimage.eps:

purifyeps -out newimage.eps image.eps

To list the files that would be processed without modifying them:

purifyeps -list *.eps

To process a MetaPost-generated EPS file with deferred processing:

purifyeps -defer metapost_image.eps

FILES

The purifyeps utility is a Perl script. It uses a number of Perl modules to parse and manipulate PostScript files.

BUGS

There are undoubtedly bugs in purifyeps. If you find any, please report them to the author.

NOTES

When using pdfLaTeX with EPS files, it's often necessary to instruct pdfLaTeX to treat EPS files as if they were MetaPost (MPS) files. The following LaTeX code, placed in your document's preamble, tells pdfLaTeX to use them.

% Tell pdfLaTeX that all .eps files were produced by MetaPost.
\usepackage{graphicx} % or graphics
\usepackage{ifpdf}
\ifpdf
  \DeclareGraphicsRule{.eps}{mps}{*}{}
  \makeatletter
    \g@addto@macro\Gin@extensions{,.eps}
  \makeatother
\fi

This code tells pdfLaTeX that all .eps files are in MPS format. This is necessary because the default pdfLaTeX configuration for the "graphics" and "graphicx" packages (pdftex.def) normally ignores .eps files. By putting the above LaTeX code in your document's preamble, you instruct pdfLaTeX to use them.
