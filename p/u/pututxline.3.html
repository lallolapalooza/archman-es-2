pututxline(3) Library Functions Manual pututxline(3)

NAME

getutent, getutid, getutline, pututline, setutent, endutent, utmpname, getutxent, getutxid, getutxline, pututxline, setutxent, endutxent, utmpxname - access utmp file entries

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <utmp.h>
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *ut);
struct utmp *getutline(const struct utmp *ut);
struct utmp *pututline(const struct utmp *ut);
void setutent(void);
void endutent(void);
int utmpname(const char *path);
#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *ut);
struct utmpx *getutxline(const struct utmpx *ut);
struct utmpx *pututxline(const struct utmpx *ut);
void setutxent(void);
void endutxent(void);
int utmpxname(const char *path);

DESCRIPTION

New applications should use the POSIX.1-specified "utmpx" versions of these functions; see STANDARDS.

utmpname() and utmpxname() set the pathname of the utmp-format file for the other utmp functions to access. If utmpname() or utmpxname() is not used to set the pathname before the other functions are used, they assume _PATH_UTMP or _PATH_UTMPX, respectively, as defined in <paths.h>.

setutent() and setutxent() rewind the file pointer to the beginning of the utmp file. They are generally a good idea to call before any of the other functions.

endutent() and endutxent() close the utmp file. They should be called when the user code is done accessing the file with the other functions.

getutent() and getutxent() read a line from the current file position in the utmp file. They return a pointer to a structure containing the fields of the line. The definition of these structures is shown in utmp(5).

getutid() and getutxid() search forward from the current file position in the utmp file based upon ut. If ut->ut_type is one of RUN_LVL, BOOT_TIME, NEW_TIME, or OLD_TIME, getutid() will find the first entry whose ut_type field matches ut->ut_type. If ut->ut_type is one of INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS, or DEAD_PROCESS, getutid() will find the first entry whose ut_id field matches ut->ut_id.

getutline() and getutxline() search forward from the current file position in the utmp file. They scan entries whose ut_type is USER_PROCESS or LOGIN_PROCESS and return the first one whose ut_line field matches ut->ut_line.

pututline() and pututxline() write the utmp or utmpx structure ut into the utmp file. They use getutid()/getutxid() to search for the proper place in the file to insert the new entry. If they cannot find an appropriate slot for ut, pututline()/pututxline() will append the new entry to the end of the file.

RETURN VALUE

getutent(), getutid(), getutline(), getutxent(), getutxid(), and getutxline() return a pointer to a struct utmp or struct utmpx on success, and NULL on failure (which includes the "record not found" case). These structures are allocated in static storage, and may be overwritten by subsequent calls.

On success pututline() and pututxline() return ut; on failure, they return NULL.

utmpname() and utmpxname() return 0 if the new name was successfully stored, or -1 on failure.

On failure, these functions errno set to indicate the error.

ERRORS

ENOMEM
Out of memory.
ESRCH
Record not found.

setutent(), pututline(), and the getut*() functions can also fail for the reasons described in open(2).

FILES

STANDARDS

These functions are specified by the POSIX.1-2008 standard, with the exception of the non-x versions which are obsolete.

HISTORY

XPG2, SVr4.

In XPG2 and SVID 2 the function pututline() is documented to return void, and that is what it does on many systems (AIX, HP-UX). HP-UX introduces a new function _pututline() with the prototype given above for pututline().

All these functions are obsolete now on non-Linux systems. POSIX.1-2001 and POSIX.1-2008, following SUSv1, does not have any of these functions, but instead uses

#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void endutxent(void);

These functions are provided by glibc, and perform the same task as their equivalents without the "x", but use struct utmpx, defined on Linux to be the same as struct utmp. For completeness, glibc also provides utmpxname(), although this function is not specified by POSIX.1.

On some other systems, the utmpx structure is a superset of the utmp structure, with additional fields, and larger versions of the existing fields, and parallel files are maintained, often /var/*/utmpx and /var/*/wtmpx.

Linux glibc on the other hand does not use a parallel utmpx file since its utmp structure is already large enough. The "x" functions listed above are just aliases for their counterparts without the "x" (e.g., getutxent() is an alias for getutent()).

NOTES

glibc notes

The above functions are not thread-safe. glibc adds reentrant versions

#include <utmp.h>
int getutent_r(struct utmp *ubuf, struct utmp **ubufp);
int getutid_r(struct utmp *ut,
              struct utmp *ubuf, struct utmp **ubufp);
int getutline_r(struct utmp *ut,
                struct utmp *ubuf, struct utmp **ubufp);
#include <utmpx.h>
int getutxent_r(struct utmpx *ubuf, struct utmpx **ubufp);
int getutxid_r(const struct utmpx *ut,
               struct utmpx *ubuf, struct utmpx **ubufp);
int getutxline_r(const struct utmpx *ut,
                 struct utmpx *ubuf, struct utmpx **ubufp);

Feature Test Macro Requirements for glibc (see feature_test_macros(7)):

getutent_r(), getutid_r(), getutline_r(), getutxent_r(), getutxid_r(), getutxline_r():

    _GNU_SOURCE
        || /* Since glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */    _SVID_SOURCE || _BSD_SOURCE

These functions are GNU extensions, analogs of the functions of the same name without the _r suffix. The ubuf argument gives these functions a place to store their result. On success, they return 0, and a pointer to the result is written in *ubufp. On error, these functions return -1.

EXAMPLES

Write a new utmp entry

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <utmp.h>
int
main(void)
{
    struct utmp ut;
    time_t now;
    memset(&ut, 0, sizeof(struct utmp));
    ut.ut_type = USER_PROCESS;
    strncpy(ut.ut_user, "testuser", sizeof(ut.ut_user) - 1);
    strncpy(ut.ut_line, "tty1", sizeof(ut.ut_line) - 1);
    ut.ut_pid = getpid();
    now = time(NULL);
    ut.ut_tv.tv_sec = now;
    ut.ut_tv.tv_usec = 0;
    if (pututline(&ut) == NULL) {
        perror("pututline");
        exit(EXIT_FAILURE);
    }
    endutent();
    printf("Successfully wrote utmp entry.\n");
    exit(EXIT_SUCCESS);
}

EJEMPLO

El siguiente ejemplo agrega y elimina un registro utmp, asumiendo que se ejecuta desde dentro de una pseudo terminal. Para su uso en una aplicación real, debería comprobar los valores de retorno de getpwuid(3) y ttyname(3).

#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmp entry;
    if (system("echo antes de agregar entrada:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* solo correcto para ptys nombrados /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo despues de agregar entrada:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo despues de eliminar entrada:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutent();
    exit(EXIT_SUCCESS);
}
