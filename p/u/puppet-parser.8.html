NOMBRE

puppet-parser - Interactuar directamente con el analizador.

SINOPSIS

puppet parser acción

OPCIONES

Tenga en cuenta que cualquier configuración válida en el archivo de configuración también es un argumento largo válido, aunque puede ser o no relevante para la acción actual. Por ejemplo, server y run_mode son configuraciones válidas, por lo que puede especificar --server <nombre_servidor>, o --run_mode <modo_ejecución> como argumento.

Consulte la documentación del archivo de configuración en https://puppet.com/docs/puppet/latest/configuration.html para obtener la lista completa de parámetros aceptables. También puede generar una lista comentada de todas las opciones de configuración ejecutando puppet con --genconfig.

--render-as FORMATO
El formato en el que se renderizará la salida. Los formatos más comunes son json, s (cadena), yaml y console, pero otras opciones como dot a veces están disponibles.
--verbose
Si se debe registrar de forma detallada.
--debug
Si se deben registrar información de depuración.

ACCIONES

•
dump - Muestra un volcado del árbol de análisis interno para depuración: SINOPSIS
puppet parser dump [--e fuente] [--[no-]validate] [--format old, pn, o json] [--pretty] [--format old|pn|json] [--pretty] { -e fuente | [plantillas ...] }
DESCRIPCIÓN
Esta acción analiza y valida la sintaxis de Puppet DSL sin compilar un catálogo ni sincronizar ningún recurso.
El formato de salida se puede controlar usando --format old|pn|json donde:
  • ´old´ es el formato predeterminado, pero ahora obsoleto, que no es API.
  • ´pn´ es la Notación de S-Expresión Extendido de Puppet.
  • ´json´ muestra el mismo gráfico que ´pn´ pero con sintaxis JSON.
La salida se imprimirá de forma "pretty" (bonita) cuando se proporcione la opción --pretty junto con --format ´pn´ o ´json´. Esta opción no tiene efecto en el formato ´old´.
El comando acepta uno o más archivos de manifiesto (.pp), o un -e seguido del texto de la fuente de puppet. Si no se proporcionan argumentos, se lee la entrada estándar (a menos que esté conectada a una terminal)
El formato de salida del árbol volcado está destinado a fines de depuración y no es una API, puede cambiar de vez en cuando.
OPCIONES --e <fuente> - volcar una expresión fuente proporcionada en la línea de comandos.
--format <old, pn, o json> - Obtener el resultado en formato ´old´ (obsoleto), ´pn´ (nuevo formato), o ´json´ (nuevo formato en JSON).
--pretty - Imprime la salida de forma bonita. Solo aplicable junto con --format pn o json
--[no-]validate - Si se valida o no el resultado analizado, si es no-validate solo se informan errores de sintaxis
RETORNA
Un volcado del modelo AST resultante a menos que haya errores de sintaxis o de validación.
•
validate - Valida la sintaxis de uno o más manifiestos de Puppet.: SINOPSIS
puppet parser validate [manifiesto] [manifiesto ...]
DESCRIPCIÓN
Esta acción valida la sintaxis de Puppet DSL sin compilar un catálogo ni sincronizar ningún recurso. Si no se proporcionan archivos de manifiesto, validará el manifiesto del sitio predeterminado.
Al validar, se informan múltiples problemas por archivo hasta la configuración de max_error y max_warnings. El procesamiento se detiene después de informar problemas para el primer archivo encontrado con errores.
RETORNA
Nada, o el primer error de sintaxis encontrado.

EJEMPLOS

validate

Validar el manifiesto del sitio predeterminado en /etc/puppetlabs/puppet/manifests/site.pp:

$ puppet parser validate

Validar dos archivos de manifiesto arbitrarios:

$ puppet parser validate init.pp vhost.pp

Validar desde STDIN:

$ cat init.pp | puppet parser validate
