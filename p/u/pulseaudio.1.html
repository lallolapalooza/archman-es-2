pulseaudio(1) Manual de Comandos Generales pulseaudio(1)

NOMBRE

pulseaudio - El Sistema de Sonido PulseAudio

SINOPSIS

pulseaudio [opciones]

pulseaudio --help

pulseaudio --version

pulseaudio --dump-conf

pulseaudio --dump-modules

pulseaudio --dump-resample-methods

pulseaudio --cleanup-shm

pulseaudio --start

pulseaudio --kill

pulseaudio --check

DESCRIPCIÓN

PulseAudio es un servidor de sonido de baja latencia en red para Linux, sistemas POSIX y Windows.

OPCIONES

-h | --help
Mostrar ayuda.
--version
Mostrar información de la versión.
--dump-conf
Cargar el archivo de configuración del demonio daemon.conf (ver abajo), analizar las opciones de configuración restantes en la línea de comandos y volcar la configuración resultante del demonio, en un formato que sea compatible con daemon.conf.
--dump-modules
Listar módulos cargables disponibles. Combinar con -v para una lista más detallada.
--dump-resample-methods
Listar remuestreadores de audio disponibles.
--cleanup-shm
Identificar segmentos de memoria compartida POSIX de PulseAudio obsoletos en /dev/shm y eliminarlos si es posible. Esto se hace implícitamente cada vez que un nuevo demonio se inicia o un cliente intenta conectarse a un demonio. Normalmente no debería ser necesario ejecutar este comando manualmente. Solo disponible en sistemas con segmentos de memoria compartida POSIX implementados a través de un sistema de archivos virtual montado en /dev/shm (por ejemplo, Linux).
--start
Iniciar PulseAudio si aún no se está ejecutando. Esto es diferente de iniciar PulseAudio sin --start, lo que fallaría si PA ya está en ejecución. Se garantiza que PulseAudio esté completamente inicializado cuando esta llamada regrese. Implica --daemonize.
-k | --kill
Matar un demonio de PulseAudio en ejecución del usuario que llama (Equivalente a enviar una SIGTERM).
--check
Devolver 0 como código de retorno cuando el demonio de PulseAudio ya esté en ejecución para el usuario que llama, o un valor distinto de cero en caso contrario. No produce ninguna salida en la consola excepto errores a stderr.

Tenga en cuenta que un valor de retorno distinto de cero no significa necesariamente que PulseAudio no sea utilizable. Incluso si el servidor no está en ejecución, puede iniciarse automáticamente a través del mecanismo de autoinicio de PulseAudio o la activación de socket de systemd, o el entorno puede ser tal que la verificación de procesos no funcione (por ejemplo, el servidor en ejecución puede no aparecer en un contenedor, incluso si el servidor es accesible a través de un socket). Deshabilitar archivos PID con --use-pid-file=no también impide que --check detecte servidores en ejecución.

Una verificación más robusta en la mayoría de las situaciones sería intentar establecer una conexión de cliente con el servidor. Desafortunadamente, actualmente no hay una opción --check-connection para reemplazar --check, pero ejecutar "pactl info" podría ser un sustituto bastante bueno.

--system[=BOOL]
Ejecutar como instancia de todo el sistema en lugar de por usuario. Tenga en cuenta que esto deshabilita ciertas características de PulseAudio y, en general, no se recomienda a menos que el sistema no conozca usuarios locales (por ejemplo, sea un cliente ligero). Esta característica requiere una configuración especial y un usuario de UNIX dedicado configurado. Se recomienda encarecidamente combinar esto con --disallow-module-loading (ver abajo).
-D | --daemonize[=BOOL]
Convertirse en demonio después de iniciar, es decir, desvincularse de la terminal. Tenga en cuenta que al ejecutarse como un servicio systemd, debe usar --daemonize=no para que la notificación de systemd funcione.
--fail[=BOOL]
Fallar el inicio cuando cualquiera de los comandos especificados en el script de inicio default.pa (ver abajo) falle.
--high-priority[=BOOL]
Intentar obtener un nivel de prioridad alto en Unix. Esto solo tendrá éxito si el usuario que llama tiene un límite de recursos RLIMIT_NICE distinto de cero establecido (en sistemas que admiten esto), o si estamos configurados para ejecutarnos como un demonio del sistema (ver --system arriba). Se recomienda habilitar esto, ya que es solo un riesgo de seguridad insignificante (ver abajo).
--realtime[=BOOL]
Intentar obtener una programación en tiempo real para los hilos de E/S de PulseAudio. Esto solo tendrá éxito si el usuario que llama tiene un límite de recursos RLIMIT_RTPRIO distinto de cero establecido (en sistemas que admiten esto), o si rtkit está disponible y permite que PulseAudio habilite la programación en tiempo real, o si estamos configurados para ejecutarnos como un demonio del sistema (ver --system arriba).
--disallow-module-loading[=BOOL]
Deshabilitar la carga de módulos después del inicio. Esta es una característica de seguridad, ya que deshabilita la carga de módulos adicionales durante la ejecución y a petición del usuario. Se recomienda encarecidamente cuando se usa --system (ver arriba). Tenga en cuenta, sin embargo, que esto rompe ciertas características como la carga automática de módulos en conexiones en caliente.
--disallow-exit[=BOOL]
Deshabilitar la salida solicitada por el usuario
--exit-idle-time=SECS
Terminar el demonio después de que el último cliente se desconecte y haya pasado este tiempo en segundos. Use un valor negativo para deshabilitar esta característica. Por defecto es 20.

Cuando PulseAudio se ejecuta en modo por usuario y detecta una sesión de inicio de sesión, cualquier valor positivo se restablecerá a 0, por lo que PulseAudio terminará inmediatamente al cerrar la sesión. Un valor positivo, por lo tanto, solo tiene efecto en entornos donde no hay soporte para el seguimiento de sesiones de inicio de sesión (o si el usuario ha iniciado sesión sin una sesión iniciada, también conocido como persistente). Un valor negativo aún se puede usar para deshabilitar la salida automática.

Cuando PulseAudio se ejecuta en modo de sistema, la salida automática siempre está deshabilitada, por lo que esta opción no hace nada.

--scache-idle-time=SECS
Descargar muestras cargadas automáticamente de la caché cuando no se han utilizado durante el número especificado de segundos.
--log-level[=NIVEL]
Si se pasa un argumento, establezca el nivel de registro al valor especificado, de lo contrario, aumente el nivel de verbosidad configurado en uno. Los niveles de registro son numéricos de 0 a 4, correspondientes a error, warn, notice, info, debug. El nivel de registro predeterminado es notice, es decir, se imprimen todos los mensajes de registro con niveles de registro inferiores: error, warn, notice.
-v | --verbose
Aumentar el nivel de verbosidad configurado en uno (ver --log-level arriba). Especifique varias veces para aumentar el nivel de registro varias veces.
--log-target={auto,syslog,journal,stderr,file:RUTA,newfile:RUTA}
Especificar el destino del registro. Si se establece en auto (que es el valor predeterminado), el registro se dirige a syslog cuando se pasa --daemonize, de lo contrario a STDERR. Si se establece en journal, el registro se dirige al journal de systemd. Si se establece en file:RUTA, el registro se dirige al archivo indicado por RUTA. newfile:RUTA es lo mismo que file:RUTA, pero los archivos existentes nunca se sobrescriben. Si el archivo especificado ya existe, se agrega un sufijo al nombre del archivo para evitar sobrescribir.
--log-meta[=BOOL]
Mostrar la ubicación del código fuente en los mensajes de registro.
--log-time[=BOOL]
Mostrar marcas de tiempo en los mensajes de registro.
