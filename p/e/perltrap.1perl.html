PERLTRAP(1perl) Guía de referencia para programadores de Perl PERLTRAP(1perl)

NOMBRE

perltrap - Trampas de Perl para los incautos

DESCRIPCIÓN

La mayor trampa de todas es olvidar "use warnings" o usar el modificador -w; véase warnings y "-w" en perlrun. La segunda mayor trampa es no hacer que todo tu programa sea ejecutable bajo "use strict". La tercera mayor trampa es no leer la lista de cambios en esta versión de Perl; véase perldelta.

Trampas de Awk

Los usuarios acostumbrados a awk deben prestar especial atención a lo siguiente:

  • Un programa Perl se ejecuta solo una vez, no una vez por cada línea de entrada. Puedes hacer un bucle implícito con "-n" o "-p".
  • El módulo English, cargado mediante 
    use English;

    permite referirse a variables especiales (como $/) con nombres (como $RS), como si estuvieran en awk; véase perlvar para más detalles.

  • Los puntos y comas son obligatorios después de todas las sentencias simples en Perl (excepto al final de un bloque). El salto de línea no es un delimitador de sentencia.
  • Las llaves son obligatorias en "if" y "while".
  • Las variables comienzan con "$", "@" o "%" en Perl.
  • Los arrays se indexan a partir de 0. Igualmente las posiciones de cadena en substr() y index().
  • Tienes que decidir si tu array tiene índices numéricos o de cadena.
  • Los valores de los hashes no surgen por el simple hecho de ser referenciados.
  • Tienes que decidir si quieres usar comparaciones de cadena o numéricas.
  • Leer una línea de entrada no la divide por ti. Tienes que dividirla tú mismo en un array. Y el operador split() tiene argumentos diferentes que el de awk.
  • La línea de entrada actual está normalmente en $_, no en $0. Generalmente no tiene el salto de línea eliminado. ($0 es el nombre del programa ejecutado.) Véase perlvar.
  • $<dígito> no se refiere a campos, sino a subcadenas coincidentes con el último patrón de coincidencia.
  • La sentencia print() no añade separadores de campo y registro a menos que establezcas $, y "$\". Puedes establecer $OFS y $ORS si estás usando el módulo English.
  • Debes abrir tus archivos antes de imprimir en ellos.
  • El operador de rango es "..", no una coma. El operador coma funciona como en C.
  • El operador de coincidencia es "=~", no "~". ("~" es el operador de complemento a uno, como en C.)
  • El operador de exponenciación es "**", no "^". "^" es el operador XOR, como en C. (Sabes, uno podría tener la sensación de que awk es básicamente incompatible con C.)
  • El operador de concatenación es ".", no la cadena vacía. (Usar la cadena vacía haría que "/pat/ /pat/" no se pudiera analizar, ya que la tercera barra se interpretaría como un operador de división - el tokenizador es de hecho ligeramente sensible al contexto para operadores como "/", "?" y ">". Y de hecho, "." en sí mismo puede ser el comienzo de un número.)
  • Las palabras clave "next", "exit" y "continue" funcionan diferentemente.
  • Las siguientes variables funcionan diferentemente: 
    Awk       Perl
ARGC      scalar @ARGV (comparar con $#ARGV)
ARGV[0]   $0
FILENAME  $ARGV
FNR       $. - algo
FS        (lo que quieras)
NF        $#Fld, o algo así
NR        $.
OFMT      $#
OFS       $,
ORS       $\
RLENGTH   length($&)
RS        $/
RSTART    length($`)
SUBSEP    $;
  • No puedes establecer $RS a un patrón, solo a una cadena.
  • En caso de duda, ejecuta la construcción de awk a través de a2p y mira lo que te da.

Trampas de C/C++

Los programadores cerebrales de C y C++ deben prestar atención a lo siguiente:

  • Las llaves son obligatorias en "if" y "while".
  • Debes usar "elsif" en lugar de "else if".
  • Las palabras clave "break" y "continue" de C se convierten en Perl en "last" y "next", respectivamente. A diferencia de en C, estos *no* funcionan dentro de una construcción de "do { } while". Véase "Loop Control" en perlsyn.
  • La sentencia switch se llama "given"/"when" y solo está disponible en perl 5.10 o posterior. Véase "Switch Statements" en perlsyn.
  • Las variables comienzan con "$", "@" o "%" en Perl.
  • Los comentarios comienzan con "#", no con "/*" o "//". Perl puede interpretar comentarios de C/C++ como operadores de división, expresiones regulares no terminadas o el operador "definido-o".
  • No puedes tomar la dirección de nada, aunque un operador similar en Perl es la barra invertida, que crea una referencia.
  • "ARGV" debe estar en mayúsculas. $ARGV[0] es el "argv[1]" de C, y "argv[0]" termina en $0.
  • Las llamadas al sistema como link(), unlink(), rename(), etc. devuelven un valor distinto de cero para el éxito, no 0. (Sin embargo, system() devuelve cero para el éxito.)
  • Los manejadores de señales tratan con nombres de señales, no con números. Usa "kill -l" para encontrar sus nombres en tu sistema.

Trampas de JavaScript

Los programadores juiciosos de JavaScript deben prestar atención a lo siguiente:

  • En Perl, el binario "+" es siempre suma. "$string1 + $string2" convierte ambas cadenas a números y luego las suma. Para concatenar dos cadenas, usa el operador ".".
  • El operador unario "+" no hace nada en Perl. Existe para evitar ambigüedades sintácticas.
  • A diferencia de "for...in", el "for" de Perl (también escrito "foreach") no permite que el lado izquierdo sea una expresión arbitraria. Debe ser una variable: 
    for my $variable (keys %hash) {
     ...
}

    Además, no olvides "keys" ahí, ya que "foreach my $kv (%hash) {}" itera sobre las claves y los valores, y generalmente no es útil ($kv sería una clave, luego un valor, etc.).

  • Para iterar sobre los índices de un array, usa "foreach my $i (0 .. $#array) {}". "foreach my $v (@array) {}" itera sobre los valores.
  • Perl requiere llaves después de "if", "while", "foreach", etc.
  • En Perl, "else if" se escribe "elsif".
  • "? :" tiene mayor precedencia que la asignación. En JavaScript, puedes escribir: 
    condition ? do_something() : variable = 3

    y la variable solo se asigna si la condición es falsa. En Perl, necesitas paréntesis:

    $condition ? do_something() : ($variable = 3);

    O simplemente usa "if".

  • Perl requiere puntos y comas para separar sentencias.
  • Las variables declaradas con "my" solo afectan al código *después* de la declaración. No puedes escribir "$x = 1; my $x;" y esperar que la primera asignación afecte a la misma variable. En su lugar, asignará a un $x declarado previamente en un ámbito exterior, o a una variable global.

perltrap - traps for the unwary in Perl

NAME

perltrap - traps for the unwary in Perl

DESCRIPTION

This document describes some of the more common traps that may catch unwary programmers. It is intended for people who are already somewhat familiar with Perl.

Autovivification Traps

Autovivification is Perl's ability to create nested data structures on demand. While convenient, it can also lead to surprising results:

  • In scalar context, assignment to an undefined hash key or array element causes autovivification, but it only creates a scalar value, not a new hash or array.

    • Example:

          $foo->{bar} = 1;  # $foo is autovivified to an empty hash
    $foo->[0] = 1;  # $foo is autovivified to an empty array
    $foo->{bar}[0] = 1; # $foo->{bar} is autovivified to undef, then assigned 1
                        # $foo->{bar}[0] is invalid!

  • Autovivification only creates what is necessary. You can't assign to a nested element unless the intermediate elements already exist as hash or array references.

    • Example:

          $foo->{bar}{baz} = 1; # $foo->{bar} autovivifies to undef,
                                  # attempt to hash into undef fails.

Special Variable Traps

  • Don't use $_ if it might be modified by a function you are using. Many functions default to using $_ if no argument is given, but they may modify it.

    • Example:

          $_ = "hello";
    chop;      # chops the 'o'
    print;     # prints "hell"

    $_ = "hello";
    print;     # prints "hello"

  • The special variables $!, $&, $`, $', and $+ are not automatically cleared between logical lines. If you are not careful, you might use old values.

    • Example:

          # Incorrect: prints "hello"
    print $&;
    /hello/;
    print $&;

    # Correct: prints "", "hello"
    print $&;
    /hello/;
    print $&;

Context Traps

Perl's operators and functions often behave differently depending on whether they are executed in a scalar or a list context. This is perhaps the most common source of bugs for novice Perl programmers.

  • List functions used in scalar context return only the last element. This is often not what you want.

    • Example:

          @a = (1, 2, 3);
    $x = @a;    # $x is 3 (the number of elements)
    $x = @a[0]; # $x is 1 (the first element)
    $x = @a[0,1];# $x is 1 (the first element)
    $x = @a[0,1,2];# $x is 3 (the number of elements)

  • Functions that return lists might return an empty list in scalar context. This often means you'll get undef or 0.

    • Example:

          sub get_list { return (1, 2, 3); }
    my $scalar = get_list(); # $scalar is 3
    my @list = get_list();   # @list is (1, 2, 3)

Assignment Traps

  • In Perl, assignment is an expression, and it returns the value assigned. This means you can chain assignments together.

    • Example:

          $a = $b = 1; # $b is assigned 1, then $a is assigned the value of $b (1)

    • This can be dangerous if you meant to use == for comparison:

          # Incorrect:
    if ($x = 0) { print "x was zero\n"; } # Assigns 0 to $x, condition is false

    # Correct:
    if ($x == 0) { print "x was zero\n"; }

  • Assignments to array or hash elements are not allowed in certain contexts.

    • Example:

          # Incorrect:
    @a[0] = 1; # Can't assign to a subarray element

Scope Traps

  • The my keyword declares a lexical variable, which is only visible within the block in which it is declared. This means that in "my $x = 1 + $x" the second $x refers to one declared previously.

  • my variables are scoped to the current block, not to the current function. If you write "{my $x;} $x;", the second $x does not refer to the one declared inside the block.

  • An object's members cannot be made accessible as variables. The closest Perl equivalent to "with(object) { method() }" is "for", which can alias $_ to the object:

    for ($object) {
    $_->method;
}

  • The object or class on which a method is called is passed as one of the method's arguments, not as a separate "this" value.

Sed Traps

Seasoned sed programmers should take note of the following:

  • A Perl program executes only once, not once for each input line. You can do an implicit loop with "-n" or "-p".

  • Backreferences in substitutions use "$" rather than "\".

  • The pattern matching metacharacters "(", ")", and "|" do not have backslashes in front.

  • The range operator is "...", rather than comma.

Shell Traps

Sharp shell programmers should take note of the following:

  • The backtick operator does variable interpolation without regard to the presence of single quotes in the command.

  • The backtick operator does no translation of the return value, unlike csh.

  • Shells (especially csh) do several levels of substitution on each command line. Perl does substitution in only certain constructs such as double quotes, backticks, angle brackets, and search patterns.

  • Shells interpret scripts a little bit at a time. Perl compiles the entire program before executing it (except for "BEGIN" blocks, which execute at compile time).

  • The arguments are available via @ARGV, not $1, $2, etc.

  • The environment is not automatically made available as separate scalar variables.

  • The shell's "test" uses "=", "!=", "<" etc for string comparisons and "-eq", "-ne", "-lt" etc for numeric comparisons. This is the reverse of Perl, which uses "eq", "ne", "lt" for string comparisons, and "==", "!=" "<" etc for numeric comparisons.

Perl Traps

Practicing Perl Programmers should take note of the following:

  • Remember that many operations behave differently in a list context than they do in a scalar one. See perldata for details.

  • Avoid barewords if you can, especially all lowercase ones. You can't tell by just looking at it whether a bareword is a function or a string. By using quotes on strings and parentheses on function calls, you won't ever get them confused.

  • You cannot discern from mere inspection which builtins are unary operators (like chop() and chdir()) and which are list operators (like print() and unlink()). (Unless prototyped, user-defined subroutines can only be list operators, never unary ones.) See perlop and perlsub.

  • People have a hard time remembering that some functions default to $_, or @ARGV, or whatever, but that others which you might expect to do not.

  • The <FH> construct is not the name of the filehandle, it is a readline operation on that handle. The data read is assigned to $_ only if the file read is the sole condition in a while loop:

    while (<FH>)      { }
while (defined($_ = <FH>)) { }..
<FH>;  # data discarded!

  • Remember not to use "=" when you need "=~"; these two constructs are quite different:

    $x =  /foo/;
$x =~ /foo/;

  • The "do {}" construct isn't a real loop that you can use loop control on.

  • Use my() for local variables whenever you can get away with it (but see perlform for where you can't). Using local() actually gives a local value to a global variable, which leaves you open to unforeseen side-effects of dynamic scoping.

  • If you localize an exported variable in a module, its exported value will not change. The local name becomes an alias to a new value but the external name is still an alias for the original.

As always, if any of these are ever officially declared as bugs, they'll be fixed and removed.
