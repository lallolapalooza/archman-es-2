PERLOS390(1perl) Guía de Referencia del Programador de Perl PERLOS390(1perl)

NOMBRE

perlos390 - compilación e instalación de Perl para z/OS (anteriormente llamado OS/390)

SINOPSIS

Este documento te ayudará a Configurar, compilar, probar e instalar Perl en z/OS Unix System Services.

DESCRIPCIÓN

Esta es una versión de Perl portada para z/OS. Ha sido probada en z/OS 2.4 y debería funcionar bien con z/OS 2.5. Puede que funcione en otras versiones o lanzamientos, pero esos son en los que ha sido probada.

El juego de caracteres nativo para z/OS es EBCDIC, pero también puede ejecutarse en modo ASCII. Perl puede soportar ambos, pero tienes que compilarlo explícitamente para uno u otro. Podrías tener tanto un perl ASCII como un perl EBCDIC en la misma máquina. Si usas el modo ASCII y un perl ASCII, el módulo Encode enviado con perl se puede usar para traducir archivos de varias páginas de códigos EBCDIC para su manejo por perl, y luego de vuelta en la salida.

Este documento describe cómo compilar un Perl Dinámico de 64 bits, ya sea ASCII o EBCDIC. Puedes elegir interactivamente otras configuraciones, así como muchas otras opciones en el script Configure que se ejecuta como parte del proceso de compilación. Puede que necesites llevar a cabo algunas tareas de configuración del sistema antes de ejecutar Configure, como se detalla a continuación.

Herramientas

Querrás obtener GNU make 4.1 o posterior. GNU make se puede descargar de un puerto que Rocket Software proporciona. Necesitarás el compilador c99 de z/OS de IBM (aunque xlc en modo c99 sin optimización activada funciona en EBCDIC).

Si quieres la última versión de desarrollo de Perl, necesitarás git. Puedes usar git en otra plataforma y transferir el resultado vía sftp o ftp a z/OS. Pero hay un puerto nativo de cliente git para z/OS disponible a través de Rocket Software.

También podrías necesitar el puerto de cliente gunzip que Rocket Software proporciona para descomprimir cualquier archivo tar comprimido que subas a z/OS.

Compilación de un Perl ASCII Dinámico de 64 bits

Para compilar desde una versión estable oficial de Perl, ve a https://www.perl.org/get.html y elige cualquiera de los botones "Download latest stable source". Esto te dará un archivo tar. El nombre de ese archivo será algo como 'perl-V.R.M,tar,gz', donde V.R.M es la versión/release/modificación del perl que estás descargando. Haz

gunzip perl-V.R.M.tar.gz

Luego, una de estas opciones:

tar -xvf perl-V.R.M.tar
pax -r -f perl-V.R.M.tar

Cualquiera de estas creará el directorio fuente. Puedes renombrarlo como quieras; para estas instrucciones, se asume que 'perl' es el nombre.

Si en su lugar quieres la última versión de desarrollo inestable, usando el git nativo en z/OS, clona Perl:

git clone https://github.com/Perl/perl5.git perl

De cualquier manera, una vez que tengas un directorio 'perl' conteniendo el código fuente, entra en él y etiqueta todo el código como ASCII:

cd perl
chtag -R -h -t -cISO8859-1 *

Configura el entorno de compilación como de 64 bits, Dinámico, ASCII, de desarrollo, desplegándolo en /usr/local/perl/ascii:

export PATH=$PWD:$PATH
export LIBPATH=$PWD:$PATH
./Configure -Dprefix=/usr/local/perl/ascii -des -Dusedevel \
      -Duse64bitall -Dusedl

Si estás compilando desde una fuente estable, no necesitas "-Dusedevel". (Si ejecutas Configure sin opciones, te preguntará interactivamente sobre cada posible opción basándose en su sondeo de lo que está disponible en tu máquina particular, así puedes elegir sobre la marcha.)

Ejecuta GNU make para compilar Perl

make

Ejecuta las pruebas para asegurarte de que Perl funciona correctamente. Actualmente, hay alrededor de una docena de pruebas fallidas de casi 2500

make test_harness

Instala Perl en /usr/local/perl/ascii:

make install

Compilación de un Perl EBCDIC Dinámico de 64 bits

Necesitarás un perl funcional en alguna máquina con conectividad a la máquina de destino. En z/OS, podría ser un perl ASCII, o uno EBCDIC anterior. Muchas máquinas ya tendrán un perl precompilado en ejecución, o se puede descargar fácilmente desde https://www.perl.org/get.html.

Sigue las instrucciones de arriba en "Compilación de un Perl ASCII Dinámico de 64 bits" hasta obtener un directorio 'perl' poblado. Luego vuelve aquí para continuar.

El perl descargado necesitará ser convertido a EBCDIC 1047. Para hacer esto:

cd perl
Porting/makerel -e

Si el paso Porting/makerel falla con un error de que no puede ejecutar el comando tar, procede a ejecutar el comando interactivamente, donde V.R.M es la versión/release/modificación de Perl que estás subiendo:

cd ../
tar cf -  --format=ustar perl-V.R.M | gzip --best > perl-V.R.M.tar.gz

Usa sftp para subir el archivo tar comprimido a z/OS:

sftp <tu sistema>
cd /tmp
put perl-V.R.M.tar.gz

Descomprime y extrae el archivo tar comprimido en z/OS:

cd /tmp
gunzip perl-V.R.M.tar.gz

Luego, una de estas opciones:

tar -xvf perl-V.R.M.tar
pax -r -f perl-V.R.M.tar

Ahora tienes el código fuente para el Perl EBCDIC en z/OS y puedes proceder a compilarlo. Esto es análogo a cómo compilarías el código para ASCII, pero ten en cuenta: no debes etiquetar el código, sino dejarlo sin etiquetar.

Configura el entorno de compilación como de 64 bits, Dinámico, nativo, de desarrollo, desplegándolo en /usr/local/perl/ebcdic:

export PATH=$PWD:$PATH
export LIBPATH=$PWD:$PATH
./Configure -Dprefix=/usr/local/perl/ebcdic -des -Dusedevel \
      -Duse64bitall -Dusedl

Si estás compilando desde una fuente estable, no necesitas "-Dusedevel". (Si ejecutas Configure sin opciones, te preguntará interactivamente sobre cada posible opción basándose en su sondeo de lo que está disponible en tu máquina particular, así puedes elegir sobre la marcha.)

Ejecuta GNU make para compilar Perl

make

Ejecuta las pruebas para asegurarte de que Perl funciona correctamente.

make test_harness

También podrías querer tener GNU groff para OS/390 instalado antes de ejecutar el paso "make install" para Perl.

Instala Perl en /usr/local/perl/ebcdic:

make install

El Perl EBCDIC todavía está en desarrollo. Todo el código central funciona, hasta donde sabemos, pero varios módulos que podrías querer descargar de CPAN no lo hacen. Los fallos van desde muy menores a catastróficos. Muchos de ellos son simplemente errores en las pruebas, con el módulo funcionando correctamente. Esto ocurre porque, por ejemplo, la prueba está codificada para esperar un punto de código ASCII de un carácter determinado; cuando recibe el valor EBCDIC en su lugar, se queja. Pero el código realmente funcionó. Otros fallos potenciales que no son realmente fallos provienen de sumas de verificación que resultan diferentes, ya que "A", por ejemplo, tiene una representación binaria diferente entre los conjuntos de caracteres. Una prueba que espera el valor ASCII mostrará un fallo, incluso si el módulo está funcionando perfectamente. También en la ordenación, las letras mayúsculas vienen antes que las minúsculas en sistemas ASCII; lo contrario en EBCDIC.

Algunos módulos de CPAN vienen incluidos con el perl descargado. Y unos pocos de ellos aún no han sido corregidos para pasar en plataformas EBCDIC. Como resultado, se omiten cuando ejecutas 'make test'. La lista actual es:

Config::Perl::V
CPAN::Meta
CPAN::Meta::YAML
Digest::MD5
Digest::SHA
Encode
ExtUtils::MakeMaker
ExtUtils::Manifest
HTTP::Tiny
IO::Compress
IPC::Cmd
JSON::PP
libnet
MIME::Base64
Module::Metadata
PerlIO::via-QuotedPrint
Pod::Checker
podlators
Pod::Simple

Ver también hints/os390.sh para otras posibles dificultades.

Configuración y utilidades para Perl en OS/390

Este también puede ser un buen momento para asegurarse de que sus archivos /etc/protocol y ya sea su /etc/resolv.conf o /etc/hosts estén en su lugar. El documento de IBM que describe tales problemas de configuración del sistema USS es "z/OS UNIX System Services Planning"

Para pruebas exitosas, puede que necesites activar el sticky bit para tu directorio /tmp legible por todos si aún no lo has hecho (ver man chmod).

NAME

perlos390 - Perl build and installation notes for OS/390 and z/OS

SYNOPSIS

        # You may need to set the following environment variables
        # in your .profile or login script:
        export CC=cob2
        export FC=cob2
        export LDFLAGS="-L/lib"
        export PERL_CORE=1
        export OPT="-W c -Wl,"
        export MAKEFLAGS="-e"

DESCRIPTION

This document contains information specific to building and installing Perl on OS/390 (now z/OS).

It is important that you read the general installation manual, perl, before you attempt to build Perl.

Shell Requirements

Ensure that you are using the Bourne shell (sh) for the Configure run.

        ksh is not recommended for Configure. Some ksh's blow up on Configure,
        mainly on older exotic systems. If yours does, try the Bourne shell
        instead.

is nothing to worry about at all.

Dynamic loading

Dynamic loading is required if you want to use XS modules from CPAN (like DBI (and DBD's), JSON::XS, and Text::CSV_XS) or update CORE modules from CPAN with newer versions (like Encode) without rebuilding all of the perl binary.

The instructions above will create a dynamic Perl. If you do not want to use dynamic loading, remove the -Dusedl option. See the comments in hints/os390.sh for more information on dynamic loading.

Optimizing

Optimization has not been turned on yet. There may be issues if Perl is optimized.

Build Anomalies with Perl on OS/390

"Out of memory!" messages during the build of Perl are most often fixed by re building the GNU make utility for OS/390 from a source code kit.

Within USS your /etc/profile or $HOME/.profile may limit your ulimit settings. Check that the following command returns reasonable values:

ulimit -a

To conserve memory you should have your compiler modules loaded into the Link Pack Area (LPA/ELPA) rather than in a link list or step lib.

If the compiler complains of syntax errors during the build of the Socket extension then be sure to fix the syntax error in the system header /usr/include/sys/socket.h.

Testing Anomalies with Perl on OS/390

The "make test" step runs a Perl Verification Procedure, usually before installation. You might encounter STDERR messages even during a successful run of "make test". Here is a guide to some of the more commonly seen anomalies:

Out of Memory (31-bit only)

Out of memory problems should not be an issue, unless you are attempting to build a 31-bit Perl.

If you _are_ building a 31-bit Perl, the constrained environment may mean you need to change memory options for Perl. In addition to the comments above on memory limitations it is also worth checking for _CEE_RUNOPTS in your environment. Perl now has (in miniperlmain.c) a C #pragma for 31-bit only to set CEE run options, but the environment variable wins.

The 31-bit C code asks for:

#pragma runopts(HEAP(2M,500K,ANYWHERE,KEEP,8K,4K) STACK(,,ANY,) ALL31(ON))

The important parts of that are the second argument (the increment) to HEAP, and allowing the stack to be "Above the (16M) line". If the heap increment is too small then when perl (for example loading unicode/Name.pl) tries to create a "big" (400K+) string it cannot fit in a single segment and you get "Out of Memory!" - even if there is still plenty of memory available.

A related issue is use with perl's malloc. Perl's malloc uses sbrk() to get memory, and sbrk() is limited to the first allocation so in this case something like:

HEAP(8M,500K,ANYWHERE,KEEP,8K,4K)

is needed to get through the test suite.

Usage Hints for Perl on z/OS

When using Perl on z/OS please keep in mind that the EBCDIC and ASCII character sets are different. See perlebcdic for more on such character set issues. Perl builtin functions that may behave differently under EBCDIC are also mentioned in the perlport.pod document.

If you are having trouble with square brackets then consider switching your rlogin or telnet client. Try to avoid older 3270 emulators and ISHELL for working with Perl on USS.

Modules and Extensions for Perl on z/OS (Static Only)

Pure Perl (that is non XS) modules may be installed via the usual:

perl Makefile.PL
make
make test
make install

If you built perl with dynamic loading capability then that would also be the way to build XS based extensions. However, if you built perl with static linking you can still build XS based extensions for z/OS but you will need to follow the instructions in ExtUtils::MakeMaker for building statically linked perl binaries. In the simplest configurations building a static perl + XS extension boils down to:

perl Makefile.PL
make
make perl
make test
make install
make -f Makefile.aperl inst_perl MAP_TARGET=perl

Running Perl on z/OS

To run the 64-bit Dynamic Perl environment, update your PATH and LIBPATH to include the location you installed Perl into, and then run the perl you installed as perlV.R.M where V/R/M is the Version/Release/Modification level of the current development level. If you are running the ASCII/EBCDIC Bi-Modal Perl environment, you also need to set up your ASCII/EBCDIC Bi-Modal environment variables, and ensure any Perl source code you run is tagged appropriately as ASCII or EBCDIC using "chtag -t -c<CCSID>":

For ASCII Only:
export _BPXK_AUTOCVT=ON
export _CEE_RUNOPTS="FILETAG(AUTOCVT,AUTOTAG),POSIX(ON)"
export _TAG_REDIR_ERR="txt"
export _TAG_REDIR_IN="txt"
export _TAG_REDIR_OUT="txt"
For ASCII or EBCDIC:
export PATH=/usr/local/perl/ascii:$PATH
export LIBPATH=/usr/local/perl/ascii/lib:$LIBPATH
perlV.R.M args

If tcsh is your login shell then use the setenv command.
