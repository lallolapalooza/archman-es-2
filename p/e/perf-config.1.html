PERF-CONFIG(1) Perf Manual PERF-CONFIG(1)

NOMBRE

perf-config - Obtiene y establece variables en un archivo de configuración.

SINOPSIS

perf config [<opción-archivo>] [sección.nombre[=valor] ...]
o
perf config [<opción-archivo>] -l | --list

DESCRIPCIÓN

Puedes administrar variables en un archivo de configuración con este comando.

OPCIONES

-l, --list

Muestra las variables de configuración actuales, nombre y valor, para todas las secciones.

--user

Para escribir y leer opciones: escribe en el archivo de usuario $HOME/.perfconfig o léelo.

--system

Para escribir y leer opciones: escribe en el archivo $(sysconfdir)/perfconfig a nivel de sistema o léelo.

ARCHIVO DE CONFIGURACIÓN

El archivo de configuración de perf contiene muchas variables para cambiar varios aspectos de cada una de sus herramientas, incluida la salida, el uso del disco, etc. El archivo $HOME/.perfconfig se utiliza para almacenar una configuración por usuario. El archivo $(sysconfdir)/perfconfig puede utilizarse para almacenar una configuración predeterminada a nivel de sistema.

Se puede deshabilitar la lectura de archivos de configuración estableciendo la variable de entorno PERF_CONFIG a /dev/null, o proporcionar un archivo de configuración alternativo estableciendo esa variable.

Al leer o escribir, los valores se leen de los archivos de configuración del sistema y del usuario por defecto, y las opciones --system y --user se pueden utilizar para indicar al comando que lea o escriba únicamente en esa ubicación.

Sintaxis

El archivo consta de secciones. Una sección comienza con su nombre entre corchetes y continúa hasta que comienza la siguiente sección. Cada variable debe estar en una sección y tener la forma nombre = valor, por ejemplo:

[sección]
        nombre1 = valor1
        nombre2 = valor2

Los nombres de sección distinguen entre mayúsculas y minúsculas y pueden contener cualquier carácter excepto salto de línea (las comillas dobles " y la barra invertida tienen que escaparse como \" y \\, respectivamente). Los encabezados de sección no pueden abarcar varias líneas.

Ejemplo

Dado un $HOME/.perfconfig como este:

# # Este es el archivo de configuración, y # un carácter # y ; indica un comentario #

[colores]
        # Variables de color
        top = rojo, por defecto
        medio = verde, por defecto
        normal = grisclaro, por defecto
        seleccionado = blanco, grisclaro
        flechas_salto = azul, por defecto
        dir = magenta, por defecto
        raíz = blanco, azul
[tui]
        # Valores predeterminados si se enlaza con libslang
        report = activado
        annotate = activado
        top = activado
[buildid]
        # Predeterminado, deshabilitar usando /dev/null
        dir = ~/.debug
[annotate]
        # Valores predeterminados
        hide_src_code = falso
        use_offset = verdadero
        jump_arrows = verdadero
        show_nr_jumps = falso
[help]
        # El formato puede ser man, info, web o html
        format = man
        autocorrect = 0
[ui]
        show-headers = verdadero
[call-graph]
        # fp (framepointer), dwarf
        record-mode = fp
        print-type = graph
        order = caller
        sort-key = function
[report]
        # Valores predeterminados
        sort_order = comm,dso,symbol
        percent-limit = 0
        queue-size = 0
        children = verdadero
        group = verdadero
        skip-empty = verdadero

Puedes ocultar el código fuente de la función de anotación estableciendo la configuración a falso con

% perf config annotate.hide_src_code=verdadero

Si deseas agregar o modificar varios elementos de configuración, puedes hacerlo así:

% perf config ui.show-headers=falso kmem.default=slab

Para modificar el orden de clasificación de la funcionalidad de informe en el archivo de configuración del usuario (es decir, ~/.perfconfig), haz lo siguiente:

% perf config --user report.sort-order=srcline

Para cambiar los colores de la línea seleccionada a otros colores de primer plano y fondo en el archivo de configuración del sistema (es decir, $(sysconf)/perfconfig), haz lo siguiente:

% perf config --system colors.selected=amarillo,verde

Para consultar el modo de registro del grafo de llamadas, haz lo siguiente:

% perf config call-graph.record-mode

Si deseas conocer varios pares de clave/valor de configuración, puedes hacerlo así:

% perf config report.queue-size call-graph.order report.children

Para consultar el valor de configuración del orden de clasificación del grafo de llamadas en el archivo de configuración del usuario (es decir, ~/.perfconfig), haz lo siguiente:

% perf config --user call-graph.sort-order

Para consultar el valor de configuración del directorio buildid en el archivo de configuración del sistema (es decir, $(sysconf)/perfconfig), haz lo siguiente:

% perf config --system buildid.dir

Variables

colors.*

Las variables para personalizar los colores utilizados en la salida de report, top y annotate en la TUI. Deben especificar los colores de primer plano y de fondo, separados por una coma, por ejemplo: 
medio = verde, grisclaro
Si deseas utilizar el color configurado para tu terminal, simplemente déjalo
como 'por defecto', por ejemplo:
medio = por defecto, grisclaro
Colores disponibles:
rojo, amarillo, verde, cian, gris, negro, azul,
blanco, por defecto, magenta, grisclaro

colors.top

top significa un porcentaje de sobrecarga que es mayor al 5%. Los valores de esta variable especifican los colores del porcentaje. Los valores clave básicos son color de primer plano rojo y color de fondo por defecto.

colors.medium

medio significa un porcentaje de sobrecarga que tiene más del 0.5%. Los valores predeterminados son verde y por defecto.

colors.normal

normal significa el resto de los porcentajes de sobrecarga excepto top, medio, seleccionado. Los valores predeterminados son grisclaro y por defecto.

colors.selected

Esto selecciona los colores para la entrada actual en una lista de entradas de subcomandos (top, report, annotate). Los valores predeterminados son negro y grisclaro.

colors.jump_arrows

Colores para las flechas de salto en los listados de código ensamblador como jns, jmp, jane, etc. Los valores predeterminados son azul, por defecto.

colors.addr

Esto selecciona los colores para las direcciones de annotate. Los valores predeterminados son magenta, por defecto.

colors.root

Colores para los encabezados en la salida de subcomandos (top, report). Los valores predeterminados son blanco, azul.

core.*, core.proc-map-timeout

Establece un tiempo de espera (en milisegundos) para analizar los archivos /proc/<pid>/maps. Puede ser anulado por la opción --proc-map-timeout en subcomandos compatibles. El tiempo de espera predeterminado es 500ms.

tui., gtk.

Los subcomandos que se pueden configurar aquí son top, report y annotate. Estos valores son booleanos, por ejemplo: 
[tui]
        top = verdadero
hará que la TUI sea la predeterminada para el subcomando 'top'. Estos estarán
disponibles si las bibliotecas necesarias se detectaron en el momento de la
compilación de la herramienta.

buildid.*, buildid.dir

Cada ejecutable y biblioteca compartida en las distribuciones modernas viene con un identificador basado en contenido que, si está disponible, se insertará en un encabezado de archivo perf.data para, en el momento del análisis, encontrar lo necesario para realizar la resolución de símbolos, anotación de código, etc. 
Las herramientas de grabación también almacenan un enlace duro o una copia en
un directorio por usuario, $HOME/.debug/, de binarios, bibliotecas compartidas,
archivos /proc/kallsyms y /proc/kcore para ser utilizados en el momento del
análisis.
La variable buildid.dir se puede utilizar para cambiar la ubicación de esta
caché de directorio, o para deshabilitarla por completo. Si deseas deshabilitarla,
establece buildid.dir a /dev/null. El valor predeterminado es $HOME/.debug.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

re>

buildid-cache.*

buildid-cache.debuginfod=URLs Especifica las URLs de debuginfod que se utilizarán al recuperar binarios de perf.data, sigue la misma sintaxis que la variable DEBUGINFOD_URLS, como por ejemplo: 
buildid-cache.debuginfod=http://192.168.122.174:8002

annotate.*

Estos controlan las direcciones, la función de salto, el código fuente en líneas de código ensamblador de un programa específico.

annotate.disassemblers

Elige el desensamblador a usar: "objdump", "llvm", "capstone", si no se especifica intentará primero, si está disponible, el de "llvm", luego, si falla, el de "capstone", y finalmente el original basado en "objdump". 
Elegir uno diferente es útil al tratar con alguna característica que
se sabe que está mejor soportada en algún momento por una de las opciones,
para comparar la salida cuando hay dudas sobre algún error, etc.
Esta puede ser una lista, en orden de preferencia, la primera que funcione
termina el proceso.

annotate.addr2line

Binario addr2line a usar para nombres de archivo y números de línea.

annotate.objdump

Binario objdump a usar para desensamblado y anotaciones, incluido en el comando perf test.

annotate.disassembler_style

Usa esto para cambiar el estilo predeterminado del desensamblador a otro valor compatible con binutils, como "intel", consulta la ayuda de la opción -M en la página man de objdump.

annotate.hide_src_code

Si un programa que se está analizando tiene código fuente, esta opción permite que annotate imprima una lista de código ensamblador con el código fuente. Por ejemplo, veamos una parte de un programa. Hay cuatro líneas. Si esta opción es true, se pueden imprimir sin el código fuente del programa como a continuación. 
│        push   %rbp
│        mov    %rsp,%rbp
│        sub    $0x10,%rsp
│        mov    (%rdi),%rdx
Pero si esta opción es 'false', también se puede imprimir el código fuente de la parte como a continuación. El valor predeterminado es 'false'.
│      struct rb_node *rb_next(const struct rb_node *node)
│      {
│        push   %rbp
│        mov    %rsp,%rbp
│        sub    $0x10,%rsp
│              struct rb_node *parent;
│
│              if (RB_EMPTY_NODE(node))
│        mov    (%rdi),%rdx
│              return n;
Esta opción funciona con los navegadores tui y stdio2.

annotate.use_offset

Basándose en la primera dirección de una función cargada, se puede usar un desplazamiento. En lugar de usar las direcciones originales del código ensamblador, se pueden imprimir las direcciones restadas de una dirección base. Ilustremos un ejemplo. Si una dirección base es 0XFFFFFFFF81624d50 como a continuación, 
ffffffff81624d50 <load0>
una dirección en el código ensamblador tiene una dirección absoluta específica como la siguiente:
ffffffff816250b8:│  mov    0x8(%r14),%rdi
pero si use_offset es 'true', se imprime la dirección restada de una dirección base. El valor predeterminado es true. Esta opción solo se aplica a TUI.
368:│  mov    0x8(%r14),%rdi
Esta opción funciona con los navegadores tui y stdio2.

annotate.jump_arrows

Puede haber instrucciones de salto entre el código ensamblador. Dependiendo del valor booleano de jump_arrows, se pueden imprimir flechas o no, que representan a dónde salta la instrucción, como a continuación. 
│     ┌──jmp    1333
│     │  xchg   %ax,%ax
│1330:│  mov    %r15,%r10
│1333:└─→cmp    %r15,%r14
Si jump_arrow es 'false', las flechas no se imprimen como a continuación. El valor predeterminado es 'false'.
│      ↓ jmp    1333
│        xchg   %ax,%ax
│1330:   mov    %r15,%r10
│1333:   cmp    %r15,%r14
Esta opción funciona con el navegador tui.

annotate.show_linenr

Al mostrar el código fuente, si esta opción es true, se imprimen los números de línea como a continuación. 
│1628         if (type & PERF_SAMPLE_IDENTIFIER) {
│     ↓ jne    508
│1628                 data->id = *array;
│1629                 array++;
│1630         }
Sin embargo, si esta opción es 'false', no se imprimen como a continuación. El valor predeterminado es 'false'.
│             if (type & PERF_SAMPLE_IDENTIFIER) {
│     ↓ jne    508
│                     data->id = *array;
│                     array++;
│             }
Esta opción funciona con los navegadores tui y stdio2.

annotate.show_nr_jumps

Veamos una parte del código ensamblador. 
│1382:   movb   $0x1,-0x270(%rbp)
Si se usa esto, se puede imprimir el número de saltos que van a esa dirección como a continuación. El valor predeterminado es 'false'.
│1 1382:   movb   $0x1,-0x270(%rbp)
Esta opción funciona con los navegadores tui y stdio2.

annotate.show_total_period

Para comparar dos registros sobre una base de instrucciones, con esta opción activada, se muestra el número total de muestras que pertenecen a una línea en el código ensamblador. Si esta opción es true, se imprimen los períodos totales en lugar de los porcentajes como a continuación. 
302 │      mov    %eax,%eax
Pero si esta opción es 'false', se imprimen los valores porcentuales de sobrecarga, es decir, el valor predeterminado es 'false'.
99.93 │      mov    %eax,%eax
Esta opción funciona con los navegadores tui, stdio2 y stdio.

annotate.show_nr_samples

Por defecto, perf annotate muestra el porcentaje de muestras. Esta opción se puede usar para imprimir el número absoluto de muestras. Por ejemplo, cuando se establece en false: 
Percent│
 74.03 │      mov    %fs:0x28,%rax
Cuando se establece en true:
Samples│
     6 │      mov    %fs:0x28,%rax
Esta opción funciona con los navegadores tui, stdio2 y stdio.

annotate.offset_level

El valor predeterminado es 1, lo que significa que solo los destinos de salto mostrarán los desplazamientos junto a la instrucción. Cuando se establece en 2, las instrucciones call también mostrarán sus desplazamientos, 3 o superior mostrará los desplazamientos para todas las instrucciones. 
Esta opción funciona con los navegadores tui y stdio2.

annotate.demangle

Descodifica los nombres de símbolos a un formato legible por humanos. El valor predeterminado es true.

annotate.demangle_kernel

Descodifica los nombres de símbolos del kernel a un formato legible por humanos. El valor predeterminado es true.

hist.*, hist.percentage

Esta opción controla la forma de calcular la sobrecarga de las entradas filtradas, lo que significa que el valor de esta opción solo es efectivo si hay un filtro (por nombre de comm, dso o símbolo). Supongamos el siguiente ejemplo: 
Overhead  Symbols
........  .......
 33.33%     foo
 33.33%     bar
 33.33%     baz
Esta es la sobrecarga original y filtraremos la primera entrada 'foo'. El valor de 'relative' aumentaría la sobrecarga de 'bar' y 'baz' al 50.00% cada una, mientras que 'absolute' mostraría su sobrecarga actual (33.33%).

ui.*, ui.show-headers

Esta opción controla la visualización de los encabezados de columna (como Overhead y Symbol) en report y top. Si esta opción es false, se ocultan. Esta opción solo se aplica a TUI.

call-graph.*

Lo siguiente controla el manejo de los grafos de llamadas (obtenidos a través de las opciones -g/--call-graph).

call-graph.record-mode

El modo para el espacio de usuario puede ser fp (puntero de marco), dwarf y lbr. El valor dwarf solo es efectivo si libunwind (o una versión reciente de libdw) está presente en el sistema; el valor lbr solo funciona para ciertas cpus. El método para el espacio del kernel se controla no por esta opción sino por la configuración del kernel (CONFIG_UNWINDER_*).

call-graph.dump-size

El tamaño de la pila a volcar para realizar la descompresión posterior. El valor predeterminado es 8192 (bytes). Al usar dwarf en modo record, se usará el tamaño predeterminado si se omite.

call-graph.print-type

Los tipos de impresión pueden ser graph (gráfico absoluto), fractal (gráfico relativo), flat y folded. Esta opción controla la forma de mostrar la sobrecarga para cada entrada de cadena de llamadas. Supongamos el siguiente ejemplo. 
Overhead  Symbols
........  .......
  40.00%  foo
          |
          ---foo
             |
             |--50.00%--bar
             |          main
             |
              --50.00%--baz
                        main
Esta salida es un formato 'fractal'. El 'foo' proviene de 'bar' y 'baz' exactamente
a partes iguales, por lo que 'fractal' muestra 50.00% para cada uno
(lo que significa que asume un 100% de sobrecarga total de 'foo').
El 'graph' usa el valor de sobrecarga absoluto de 'foo' como total, por lo que cada cadena de llamadas de 'bar' y 'baz' tendrá un 20.00% de sobrecarga.
Si se usa 'flat', se expone una sola columna y lineal de las cadenas de llamadas.
'folded' significa que las cadenas de llamadas se muestran en una línea, separadas por punto y coma.

call-graph.order

Esta opción controla el orden de impresión de las cadenas de llamadas. El valor predeterminado es callee, lo que significa que la callee se imprime en la parte superior y luego le sigue su llamador, y así sucesivamente. caller la imprime en orden inverso. 
Si esta opción no está configurada y report.children o top.children está
configurado como true (o se proporciona la opción de línea de comandos equivalente),
el valor predeterminado de esta opción se cambia a 'caller' para la ejecución de
'perf report' o 'perf top'. Otros comandos seguirán usando 'callee' por defecto.

call-graph.sort-key

Las cadenas de llamadas se fusionan si contienen la misma información. La opción sort-key determina una forma de comparar las cadenas de llamadas. Un valor de sort-key puede ser function o address. El valor predeterminado es function.

call-graph.threshold

Cuando hay muchas cadenas de llamadas, se imprimiría un montón de perf-report(1)

NAME

perf-report - análisis de perfiles de rendimiento

SYNOPSIS

perf report [options]

DESCRIPTION

El comando perf report lee los datos de rendimiento recopilados por perf record y los muestra en un formato legible. Presenta los eventos de rendimiento (muestras) de manera jerárquica, lo que permite identificar las partes del código que consumen más recursos.

OPTIONS

perf report soporta una gran cantidad de opciones para personalizar la visualización y el análisis de los datos. Muchas de estas opciones pueden ser configuradas a través del archivo de configuración de perf.

call-graph.print-overhead

Si es true, entonces el overhead total de cada elemento de la pila de llamadas se imprimirá. El valor por defecto es true.

call-graph.record-mode

El modo de grabación de la pila de llamadas. Las opciones son:
  • callstack: (Predeterminado) Graba la pila de llamadas usando el mecanismo de `callstack` de perf.
  • fp: Graba la pila de llamadas usando el puntero de marco (frame pointer).
  • dwarf: Graba la pila de llamadas usando información DWARF.
  • none: No graba la pila de llamadas.

call-graph.depth

Profundidad máxima de la pila de llamadas a imprimir. El valor por defecto es 0, lo que significa sin límite.

call-graph.precision

Número de dígitos después del punto decimal para la columna de porcentaje. El valor por defecto es 2.

call-graph.tree-type

El tipo de árbol a imprimir. Las opciones son:
  • flat: Muestra las llamadas de función de forma plana.
  • graph: Muestra las llamadas de función como un grafo.
  • fractal: Muestra las llamadas de función de forma fractal (similar a un árbol).
El valor por defecto es graph.

call-graph.overhead-only

Si es true, solo se imprimirán las llamadas de función que tengan un overhead superior al umbral. El valor por defecto es false.

call-graph.fields

Lista de campos a imprimir en la salida. Los campos disponibles son: overhead, symbol, dso, comm. El valor por defecto es overhead,symbol,dso,comm.

call-graph.filter

Filtra las llamadas de función basándose en un patrón. Por ejemplo, call-graph.filter=main solo mostrará las llamadas relacionadas con la función `main`.

call-graph.sort-order

Ordena la salida según los campos especificados. Por ejemplo, call-graph.sort-order=overhead ordenará por overhead de forma descendente.

call-graph.threshold

Umbral de overhead para omitir llamadas de función pequeñas. perf omite las llamadas de función pequeñas por debajo de un cierto overhead (umbral) y esta opción controla dicho umbral. El valor por defecto es 0.5 (%). El overhead se calcula según el tipo de grafo de llamadas call-graph.print-type.

call-graph.print-limit

Número máximo de líneas de la pila de llamadas a imprimir por cada entrada del histograma. El valor por defecto es 0, lo que significa sin limitación.

report.*, report.sort_order

Permite cambiar el orden de clasificación predeterminado de "comm,dso,symbol" a otro predeterminado, por ejemplo, "sym,dso" podría ser más adecuado para los desarrolladores del kernel.

report.percent-limit

Esta opción es muy similar a call-graph.threshold pero funciona para las entradas del histograma. Las entradas que tengan un overhead inferior a este porcentaje no se imprimirán. El valor por defecto es 0. Si percent-limit es 10, solo se imprimirán las entradas que tengan más del 10% de overhead.

report.queue-size

Esta opción configura el tamaño máximo de asignación de la cola de eventos interna para ordenar los eventos. El valor por defecto es 0, lo que significa sin límite.

report.children

Children significa funciones llamadas desde otra función. Si esta opción es true, perf report acumula las pilas de llamadas de los hijos y muestra el overhead total (acumulado) así como el overhead Self. Consulte el manual de perf report. El valor por defecto es true.

report.group

Esta opción sirve para mostrar información de grupos de eventos juntos. Ejemplo de salida con esta opción activada, nótese que hay una columna por evento en el grupo, ref-cycles y cycles: 
# group: {ref-cycles,cycles}
# ========
#
# Samples: 7K of event 'anon group { ref-cycles, cycles }'
# Event count (approx.): 6876107743
#
#         Overhead  Command      Shared Object               Symbol
# ................  .......  .................  ...................
#
    99.84%  99.76%  noploop  noploop            [.] main
     0.07%   0.00%  noploop  ld-2.15.so         [.] strcmp
     0.03%   0.00%  noploop  [kernel.kallsyms]  [k] timerqueue_del

report.skip-empty

Esta opción puede cambiar el comportamiento predeterminado de `stat` con resultados vacíos. Si se establece en true, perf report --stat no mostrará estadísticas de 0.

top.*, top.children

Igual que report.children. Por lo tanto, si está habilitado, la salida del comando top tendrá una columna de overhead Children además de la columna de overhead Self por defecto. El valor por defecto es true.

top.call-graph

Esto es idéntico a call-graph.record-mode, excepto que solo se aplica al subcomando top. Esta opción ÚNICAMENTE configura el método de desempaquetado (unwind). Para que perf top lo use realmente, se debe especificar la opción de línea de comandos -g.

man.*, man.viewer

Esta opción puede asignar una herramienta para ver las páginas del manual cuando se invoca el subcomando help. Las herramientas compatibles son man, woman (con el cliente emacs) y konqueror. El valor por defecto es man. 
Una nueva herramienta para el visor de manuales también puede añadirse usando 'man.<tool>.cmd'
o usar una ruta diferente usando la opción de configuración 'man.<tool>.path'.

pager.*, pager.<subcommand>

Cuando el subcomando se ejecuta en stdio, determina si usa paginador o no basándose en este valor. El valor por defecto es sin especificar.

kmem.*, kmem.default

Esta opción decide qué asignador se analizará si no se utilizan las opciones --slab o --page. El valor por defecto es slab.

record.*, record.build-id

Esta opción puede ser cache, no-cache, skip o mmap. cache es para post-procesar datos y guardar/actualizar los binarios en la caché de build-id (en ~/.debug). Este es el valor por defecto. Pero si esta opción es no-cache, no actualizará la caché de build-id. skip omite el post-procesamiento y no actualiza la caché. mmap omite el post-procesamiento y lee los build-ids de los eventos MMAP.

record.call-graph

Esto es idéntico a call-graph.record-mode, excepto que solo se aplica al subcomando record. Esta opción ÚNICAMENTE configura el método de desempaquetado (unwind). Para que perf record lo use realmente, se debe especificar la opción de línea de comandos -g.

record.aio

Usa n bloques de control en el modo de escritura de traza asíncrono (Posix AIO) (n por defecto: 1, máximo: 4).

record.debuginfod

Especifica la URL de debuginfod que se utilizará al almacenar en caché los binarios de perf.data, sigue la misma sintaxis que la variable DEBUGINFOD_URLS, como:
http://192.168.122.174:8002 
Si la URL es 'system', se utiliza el valor de la variable de entorno del sistema DEBUGINFOD_URLS.

diff.*, diff.order

Esta opción establece el número de columnas para ordenar el resultado. El valor por defecto es 0, lo que significa ordenar por línea base. Establecerlo en 1 ordenará el resultado por delta (u otro método de cálculo seleccionado).

diff.compute

Estas opciones establecen el método para calcular el resultado de la diferencia. Los valores posibles son delta, delta-abs, ratio y wdiff. El valor por defecto es delta.

trace.*, trace.add_events

Permite añadir un conjunto de eventos a los especificados por el usuario, o usarlos como predeterminados si no se especificó ninguno. El caso de uso inicial es añadir augmented_raw_syscalls.o para activar la lógica de perf trace que busca el contenido del puntero de la llamada al sistema después de la carga normal del tracepoint.

trace.args_alignment

Número de columnas para alinear la lista de argumentos, el valor por defecto es 70, usar 40 para el valor predeterminado de strace, cero para no alinear.

trace.no_inherit

No seguir hilos hijos.

trace.show_arg_names

¿Se deben imprimir los nombres de los argumentos de las llamadas al sistema? Si no, se establecerá trace.show_zeros.

trace.show_duration

Mostrar la duración de las llamadas al sistema.

trace.show_prefix

Si se establece en yes, se mostrarán prefijos de cadena comunes en las tablas. El valor predeterminado es eliminar el prefijo común en cosas como "MAP_SHARED", mostrando solo "SHARED".

trace.show_timestamp

Mostrar la marca de tiempo de inicio de la llamada al sistema.

trace.show_zeros

No suprimir los argumentos de las llamadas al sistema que sean iguales a cero.

trace.tracepoint_beautifiers

Usar "libtraceevent" para usar esa biblioteca para aumentar los argumentos del tracepoint, "libbeauty", el valor predeterminado, para usar los mismos embellecedores de argumentos utilizados en las líneas de sys_enter+sys_exit similares a strace.

ftrace.*, ftrace.tracer

Se puede usar para seleccionar el tracer predeterminado cuando no se especifica ni la opción -G ni la -F. Los valores posibles son function y function_graph.

samples.*, samples.context

Define cuántos ns de tiempo mostrar alrededor de las muestras en el navegador de contexto de muestras de perf report.

scripts.*

Cualquier opción define un script que se añade al menú de scripts en el navegador interactivo de perf y cuya salida se muestra. El nombre de la opción es el nombre, el valor es la línea de comandos del script. El script recibe las mismas opciones que un script completo de perf, en particular -i archivo perfdata, --cpu, --tid

convert.*, convert.queue-size

Limita el tamaño de la cola de eventos ordenados, para poder controlar el tamaño de asignación de los archivos de datos de perf sin eventos de ronda completos adecuados.

stat.*, stat.big-num

(booleano) Cambia el valor predeterminado de "--big-num". Para que "--no-big-num" sea el valor predeterminado, establezca "stat.big-num=false".

intel-pt.*, intel-pt.cache-divisor, intel-pt.mispred-all

Si se establece, el decodificador Intel PT establecerá el indicador mispred en todas las ramas.

intel-pt.max-loops

Si se establece y no es cero, el número máximo de ramas incondicionales decodificadas sin consumir ningún paquete de traza. Si se supera el máximo, se producirá un error de "Bucle infinito". El valor por defecto es 100000.

intel-pt.all-switch-events

Si el usuario tiene permiso para hacerlo, siempre graba todos los eventos de cambio de contexto en todas las CPUs.

auxtrace.*, auxtrace.dumpdir

Solo s390. El directorio para guardar el búfer de traza auxiliar se puede cambiar usando esta opción. Por ejemplo, auxtrace.dumpdir=/tmp. Si el directorio no existe o tiene el tipo de archivo incorrecto, se utilizará el directorio actual.

itrace.*, debug-log-buffer-size

Tamaño del registro en bytes a generar al usar la opción --itrace=d+e. Consulte la opción itrace de perf-script(1) o perf-report(1). El valor por defecto es 16384.

daemon.*, daemon.base

Ruta base para los datos del demonio. Todos los datos de las sesiones se almacenan bajo esta ruta.

session-<NAME>.*, session-<NAME>.run

Define una nueva sesión de grabación para el demonio. El valor es la línea de comandos de grabación sin la palabra clave record.

CONFIGURATION FILE

Las opciones de configuración se pueden establecer en el archivo ~/.perfconfig o /etc/perf.conf. Las opciones en el archivo de configuración tienen el formato <sección>.<opción> = <valor>. Por ejemplo:

[call-graph]
    print-overhead = true
    threshold = 0.1
[report]
    percent-limit = 5

perf-config(1)

Arch Linux man pages

perf-config es una herramienta para configurar el registro de eventos de rendimiento. Permite definir qué eventos se registrarán, cuándo se registrarán y cómo se almacenarán los datos.

SINOPSIS

perf-config [opciones]

DESCRIPCIÓN

La utilidad perf-config proporciona una interfaz para gestionar la configuración del registro de eventos de rendimiento del sistema. Permite a los usuarios especificar qué eventos de rendimiento deben ser monitorizados, establecer umbrales para la generación de alertas y definir el formato y la ubicación del almacenamiento de los datos de rendimiento.

Esta herramienta es útil para administradores de sistemas y desarrolladores que necesitan un control detallado sobre la recopilación de datos de rendimiento para propósitos de depuración, optimización o monitorización.

OPCIONES

perf-config soporta varias opciones para personalizar la configuración. Algunas de las opciones comunes incluyen:

  • --event <nombre_evento>: Especifica el nombre del evento de rendimiento a registrar.
  • --enable <nombre_evento>: Habilita el registro para un evento específico.
  • --disable <nombre_evento>: Deshabilita el registro para un evento específico.
  • --threshold <evento>:<valor>: Establece un umbral para un evento.
  • --output <archivo>: Define el archivo de salida para los datos de rendimiento.
  • --format <formato>: Especifica el formato de los datos de salida (ej. CSV, JSON).
  • --list: Muestra una lista de todos los eventos de rendimiento configurables.
  • -h, --help: Muestra un mensaje de ayuda.

EJEMPLOS

Para habilitar el registro del evento 'cpu-cycles' y guardarlo en 'perf_data.csv' en formato CSV: 

perf-config --enable cpu-cycles --output perf_data.csv --format csv

Para listar todos los eventos de rendimiento disponibles: 

perf-config --list
