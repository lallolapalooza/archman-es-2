PERLSYNOLOGY(1perl) Guía de referencia del programador de Perl PERLSYNOLOGY(1perl)

NOMBRE

perlsynology - Perl 5 en sistemas Synology DSM

DESCRIPCIÓN

Synology fabrica una gran cantidad de dispositivos de almacenamiento conectado en red (NAS) que son muy populares en grandes organizaciones, así como en pequeñas empresas y hogares.

Los sistemas NAS están equipados con Synology Disk Storage Manager (DSM), que es un sistema Linux reducido mejorado con varias herramientas para gestionar el NAS. Existen varios tipos de hardware: Marvell Armada (ARMv5tel, ARMv7l), Intel Atom (i686, x86_64), Freescale QorIQ (PPC) y más. Para una lista completa, consulte la FAQ de Synology https://kb.synology.com/en-global/DSM/tutorial/What_kind_of_CPU_does_my_NAS_have.

Dado que se basa en Linux, el NAS puede ejecutar muchos paquetes de software populares de Linux, incluido Perl. De hecho, Synology proporciona un paquete listo para instalar para Perl, y según la versión de DSM, la versión de Perl instalada varía desde 5.8.6 en DSM-4.3 hasta 5.28.1 en DSM-7.1.

Existe una comunidad de usuarios activa que proporciona muchos paquetes de software para los sistemas Synology DSM; en el momento de escribir este documento, proporcionan la versión de Perl 5.28.1.

Este documento describe varias características del sistema operativo Synology DSM que afectarán cómo se configura, compila y/o ejecuta Perl 5 (en adelante, simplemente Perl). Ha sido compilado y verificado por Johan Vromans para el Synology DS413 (QorIQ), con comentarios de H.Merijn Brand (DS213: ARMv5tel, RS815: Intel Atom x64, y DS218+: Celeron J3355).

Configuración del entorno de compilación

DSM 7

Para un entorno de desarrollo cómodo, Entware es actualmente la única solución viable. Simplemente siga las instrucciones detalladas en Instalar Entware en Synology NAS https://github.com/Entware/Entware/wiki/Install-on-Synology-NAS. Las arquitecturas compatibles son armv5, armv7, mipsel, wl500g, x86_32 y x86_64. Consulte aquí https://pkg.entware.net/binaries/ para plataformas compatibles.

Ese enlace de github también muestra qué entornos deberían ser compatibles.

Fue probado en DSM-7.1 por H.Merijn Brand en un DS218+ y un DS220+ (ambos Intel x64).

Entware viene con una versión precompilada 5.26.1 (enero de 2018) que permite compilar código XS compartido. Tenga en cuenta que esta instalación no utiliza una carpeta site_perl. El "cpan" disponible funciona. Si todos los paquetes de desarrollo necesarios también están instalados, también para XS.

Instalación de perl desde el centro de paquetes de la comunidad:

  • Usando su navegador favorito, abra la página de administración de DSM e inicie el Centro de paquetes.
  • En Configuración, agregue las siguientes Fuentes de paquetes: 
    Nombre:     Comunidad
Ubicación: https://synopackage.com/repository/spk/All
  • Aún en Configuración, en Actualización de canal, seleccione Canal Beta.

Para completar el entorno de desarrollo, instale make y gcc

ds220# opkg install make gcc

Luego, opcionalmente, asegúrese de utilizar las versiones más recientes de bash y gawk.

ds220# opkg install bash gawk
ds220# cd /usr/bin
ds220# mv bash bash.syno
ds220# ln -s /opt/bin/bash .

Para que Configure encuentre las bibliotecas necesarias

ds220# cd /opt/lib
ds220# ln -s libcrypt.so.?       libcrypt.so
ds220# ln -s libdl.so.?          libdl.so
ds220# ln -s libgdbm.so.?        libgdbm.so
ds220# ln -s libgdbm_compat.so.? libgdbm_compat.so
ds220# ln -s libm.so.?           libm.so
ds220# ln -s libpthread.so.?     libpthread.so
ds220# ln -s libutil.so.?        libutil.so

DSM 6

El uso de iPkg ha sido obsoleto en DSM 6, pero hay una alternativa disponible para DSM 6: entware/opkg. Para obtener instrucciones sobre cómo usarlo, lea Instalar Entware-ng en Synology NAS https://github.com/Entware-ng/Entware-ng/wiki/Install-on-Synology-NAS

Lamentablemente, eso no funciona (aún) en QorIQ. En el momento de escribir esto, las arquitecturas compatibles son armv5, armv7, mipsel, wl500g, x86_32 y x86_64. Consulte aquí https://pkg.entware.net/binaries/ para plataformas compatibles.

Entware-ng viene con una versión precompilada 5.24.1 (junio de 2017) que permite compilar código XS compartido. Tenga en cuenta que esta instalación no utiliza una carpeta site_perl. El "cpan" disponible funciona. Si todos los paquetes de desarrollo necesarios también están instalados, también para XS.

DSM 5

Dado que DSM es un sistema Linux reducido, carece de muchas de las herramientas y bibliotecas que se encuentran comúnmente en Linux. Las herramientas básicas como sh, cp, rm, etc. se implementan utilizando BusyBox https://en.wikipedia.org/wiki/BusyBox.

  • Usando su navegador favorito, abra la página de administración de DSM e inicie el Centro de paquetes.
  • Si desea probar Perl, instale "Perl".
  • En Configuración, agregue las siguientes Fuentes de paquetes: 
    https://www.cphub.net
http://packages.quadrat4.de

    Dado que estos dos están descontinuados, es poco probable que pueda configurar un entorno de compilación en DSM 5.

  • Aún en Configuración, en Canal Update, seleccione Canal Beta.
  • Presione Actualizar. En el panel izquierdo aparecerá el elemento "Comunidad". Haga clic en él. Seleccione "Bootstrap Installer Beta" e instálelo.
  • Igualmente, instale "iPKGui Beta".

    La ventana de la aplicación debería mostrar ahora un icono para iPKGui.

  • Inicie iPKGui. Instale los paquetes "make", "gcc" y "coreutils".

    Si desea probar Perl, instale "patch".

El siguiente paso es agregar algunos enlaces simbólicos a las bibliotecas del sistema. Por ejemplo, el software de desarrollo espera una biblioteca "libm.so" que normalmente es un enlace simbólico a "libm.so.6". Synology solo proporciona este último y no el enlace simbólico.

Aquí importa la arquitectura real del sistema Synology. Debe averiguar dónde se han instalado las bibliotecas de gcc. Busque en /opt un directorio similar a arm-none-linux-gnueab o powerpc-linux-gnuspe. En las siguientes instrucciones, usaré powerpc-linux-gnuspe como ejemplo.

  • En la página de administración de DSM, inicie el Panel de control.
  • Haga clic en Terminal y habilite el servicio SSH.
  • Cierre Terminal y el Panel de control.
  • Abra un shell en el Synology usando ssh y conviértase en root.
  • Ejecute los siguientes comandos: 
    cd /lib
ln -s libm.so.6 libm.so
ln -s libcrypt.so.1 libcrypt.so
ln -s libdl.so.2 libdl.so
cd /opt/powerpc-linux-gnuspe/lib  (o
                                  /opt/arm-none-linux-gnueabi/lib)
ln -s /lib/libdl.so.2 libdl.so

ADVERTENCIA: Cuando realice una actualización de software del sistema, estos enlaces desaparecerán y deberán restablecerse.

Compilar Perl 5

Una vez configurado el entorno de compilación, compilar y probar Perl es sencillo. Lo único que necesita hacer es descargar las fuentes como de costumbre y agregar un archivo Policy.sh de la siguiente manera:

# Administrivia.
perladmin="your.email@goes.here"
# Instalar Perl en un árbol en /opt/perl en lugar de /opt/bin.
prefix=/opt/perl
# Seleccionar el compilador. Tenga en cuenta que no hay un alias o enlace 'cc'
# en versiones anteriores de DSM
cc=gcc
awk=/opt/bin/gawk
# Banderas de compilación. Opcional
ccflags="-DDEBUGGING"
# Rutas de bibliotecas y encabezados.
locincpth="/opt/include"
loclibpth="/opt/lib /usr/local/lib /usr/lib"
libpth="/opt/lib /usr/local/lib /usr/lib"

Es posible que desee crear el directorio de destino y darle los permisos correctos antes de instalar, eliminando así la necesidad de compilar Perl como superusuario.

En el directorio donde desempaquetó las fuentes, emita los comandos habituales:

$ bash ./Configure -Dusedevel -Duseshrplib -Duse64bitall -des
$ make -j2
$ env TEST_JOBS=2 make test_harness
$ make install

Pruebas fallidas

ext/DynaLoader/t/DynaLoader.t
Una subprueba falla debido a la estructura poco común del sistema de archivos de Synology. Falta el archivo /lib/glibc.so.

ADVERTENCIA: No cree un enlace simbólico de /lib/glibc.so.6 a /lib/glibc.so o algunos componentes del sistema comenzarán a fallar.

Pruebas de humo de Perl

Si la compilación se completa con éxito, puede configurar pruebas de humo como se describe en la documentación de Test::Smoke.

Para las pruebas de humo, necesita una Perl en funcionamiento. Puede instalar el paquete proporcionado por Synology para Perl 5.8.6, o compilar e instalar su propia versión, mucho más reciente.

Tenga en cuenta que no pude ejecutar pruebas de humo exitosas cuando fueron iniciadas por el Programador de Tareas de Synology. Recurrí a iniciar las pruebas de humo a través de un trabajo cron ejecutado en otro sistema, usando ssh:

ssh nas1 wrk/Test-Smoke/smoke/smokecurrent.sh

Parches locales

Cuando se aplican parches locales con pruebas de humo, el controlador de pruebas solicitará automáticamente la regeneración de ciertas tablas después de que se apliquen los parches. La Perl 5.8.6 proporcionada por Synology (al menos en el DS413) **NO es capaz** de generar estas tablas. Generará opcodes con valores falsos, lo que provocará que la compilación falle.

Puede evitar la regeneración agregando la configuración

'flags' => 0,

a la configuración de humo, o agregando otro parche que inserte

exit 0 if $] == 5.008006;

al principio del programa "regen.pl".

Agregar librerías

El procedimiento anterior describe un entorno básico y, por lo tanto, resulta en una Perl básica. Si desea agregar librerías adicionales a Perl, puede necesitar configuraciones adicionales.

Por ejemplo, la Perl básica no tiene ninguna de las librerías DB (db, dbm, ndbm, gdsm). Puede agregarlas usando iPKGui, sin embargo, necesita establecer la variable de entorno LD_LIBRARY_PATH al valor apropiado:

LD_LIBRARY_PATH=/lib:/opt/lib
export LD_LIBRARY_PATH

Esta configuración debe estar activa mientras se compila Perl, pero también cuando se ejecutan los programas.
