NOMBRE

perl5120delta - Novedades de perl v5.12.0

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.10.0 y la versión 5.12.0.

Muchas de las correcciones de errores en 5.12.0 ya están incluidas en la versión de mantenimiento 5.10.1.

Puede ver la lista de esos cambios en las notas de la versión 5.10.1 (perl5101delta).

Mejoras del núcleo

Nueva sintaxis "package NOMBRE VERSIÓN"

Esta nueva sintaxis permite al autor de un módulo establecer la $VERSION de un espacio de nombres al declarar el espacio de nombres con 'package'. Elimina la necesidad de "our $VERSION = ..." y construcciones similares. Por ejemplo:

package Foo::Bar 1.23;
# $Foo::Bar::VERSION == 1.23

Esto tiene varias ventajas:

  • $VERSION se analiza de la misma manera que "use NOMBRE VERSIÓN"
  • $VERSION se establece en tiempo de compilación
  • $VERSION es un objeto de versión que proporciona una sobrecarga adecuada de los operadores de comparación, por lo que comparar $VERSION con números de versión decimales (1.23) o de decimales punteados (v1.2.3) funciona correctamente.
  • Elimina el desorden de "$VERSION = ..." y "eval $VERSION"
  • Dado que requiere que VERSION sea una cadena literal numérica o una cadena literal v, puede ser analizada estáticamente por módulos de la cadena de herramientas sin "eval", de la forma en que MM->parse_version lo hace para "$VERSION = ..."

No rompe el código antiguo que solo tiene "package NOMBRE", pero el código que usa "package NOMBRE VERSIÓN" deberá estar restringido a perl 5.12.0 o superior. Esto es análogo al cambio de "open" de dos argumentos a tres argumentos. Los usuarios que requieran la última versión de Perl se beneficiarán, y quizás después de varios años, se convertirá en una práctica estándar.

Sin embargo, "package NOMBRE VERSIÓN" requiere un formato de número de versión nuevo y 'estricto'. Consulte "Formatos de número de versión" para obtener detalles.

El operador "..."

Se ha añadido un nuevo operador, "...", apodado el operador Yada Yada, que está pensado para marcar código de marcador de posición que aún no está implementado. Consulte "Operador Yada Yada" en perlop.

Estricturas implícitas

Usar la sintaxis "use VERSIÓN" con un número de versión mayor o igual a 5.11.0 habilitará léxicamente las estricturas como lo haría "use strict" (además de habilitar características). Lo siguiente:

use 5.12.0;

significa:

use strict;
use feature ':5.12';

Mejoras de Unicode

Perl 5.12 viene con Unicode 5.2, la última versión disponible para nosotros en el momento del lanzamiento. Esta versión de Unicode se publicó en octubre de 2009. Consulte http://www.unicode.org/versions/Unicode5.2.0 para obtener más detalles sobre los cambios en esta versión del estándar. Consulte perlunicode para obtener instrucciones sobre cómo instalar y usar otras versiones de Unicode.

Además, los desarrolladores de Perl han mejorado significativamente la implementación de Unicode de Perl. Para obtener todos los detalles, consulte "Revisión de Unicode" a continuación.

Cumplimiento Y2038

Las funciones principales relacionadas con el tiempo de Perl ahora cumplen con Y2038. (¡Puede que no signifique mucho para usted, pero a sus hijos les encantará!)

Sobrecarga qr

Ahora es posible sobrecargar el operador "qr//", es decir, la conversión a regexp, como ya era posible sobrecargar la conversión a booleano, cadena o número de objetos. Se invoca cuando un objeto aparece en el lado derecho del operador "=~" o cuando se interpola en un regexp. Consulte overload.

Palabras clave enchufables

Los módulos de extensión ahora pueden conectarse limpiamente al analizador de Perl para definir nuevos tipos de expresiones encabezadas por palabras clave y sentencias compuestas. La sintaxis que sigue a la palabra clave está definida completamente por la extensión. Esto permite que un sublenguaje completamente no-Perl se analice en línea, con las operaciones correctas generadas limpiamente.

Consulte "PL_keyword_plugin" en perlapi para conocer el mecanismo. La distribución fuente de Perl también incluye un nuevo módulo XS::APItest::KeywordRPN, que implementa la aritmética de notación polaca inversa a través de palabras clave enchufables. Este módulo se utiliza principalmente para fines de prueba y normalmente no se instala, pero también sirve como ejemplo de cómo usar el nuevo mecanismo.

Los desarrolladores de Perl consideran que esta característica es experimental. Es posible que la eliminemos o la cambiemos de forma incompatible con versiones anteriores en Perl 5.14.

APIs para más internos

Las capas más bajas del analizador léxico y partes del sistema de almohadillas ahora tienen APIs de C disponibles para extensiones XS. Estas son necesarias para admitir el uso adecuado de palabras clave enchufables, pero tienen otros usos también. Las nuevas APIs son experimentales y solo cubren una pequeña proporción de lo que sería necesario para aprovechar al máximo las instalaciones del núcleo en estas áreas. Se pretende que el ciclo de desarrollo de Perl 5.13 vea la adición de una gama completa de interfaces limpias y compatibles.

Los desarrolladores de Perl consideran que esta característica es experimental. Es posible que la eliminemos o la cambiemos de forma incompatible con versiones anteriores en Perl 5.14.

Búsqueda de funciones sobreescribible

Donde un módulo de extensión engancha la creación de ops rv2cv para modificar el proceso de búsqueda de subrutinas, esto ahora funciona correctamente para las llamadas a subrutinas bareword. Esto significa que los prototipos en las subrutinas referenciadas de esta manera se procesarán correctamente. (Anteriormente, los nombres de subrutinas bareword eran inicialmente buscados, para fines de análisis, por un mecanismo no enganchable, por lo que las extensiones solo podían influir correctamente en los nombres de subrutinas que aparecían con un sigilo de "&").

La orden de resolución de métodos C3 añadida en 5.10.0 se ha reimplementado como un plugin, sin cambiar su interfaz en el espacio de Perl. Consulte perlmroapi para obtener más información.

Escape de regex experimental "\N"

Perl ahora admite "\N", un nuevo escape de regex que puede considerar como la inversa de "\n". Coincidirá con cualquier carácter que no sea un salto de línea, independientemente de la presencia o ausencia del modificador de coincidencia de línea única "/s". No es utilizable dentro de una clase de caracteres. "\N{3}" significa coincidir con 3 no saltos de línea; "\N{5,}" significa coincidir con al menos 5. "\N{NOMBRE}" sigue significando el carácter o secuencia llamado "NOMBRE", pero "NOMBRE" ya no puede ser cosas como 3 o "5,".

Formatos de números de versión

Los formatos aceptables de números de versión se han formalizado en reglas "estrictas" y "laxas". toma un número de versión estricto. y los constructores de objetos de versión toman números de versión laxos. Proporcionar una versión inválida resultará en un error fatal. El argumento de versión en se analiza primero como un literal numérico o una cadena v y luego se pasa a (y luego debe pasar la prueba de formato "laxo").

Estos formatos se documentan completamente en el módulo version. A primera aproximación, un número de versión "estricto" es un número decimal positivo (entero o fraccionario decimal) sin exponentiación o bien una cadena v de punto decimal con un carácter 'v' inicial y al menos tres componentes. Un número de versión "laxo" permite cadenas v con menos de tres componentes o sin una 'v' inicial. Bajo las reglas "laxas", tanto las versiones decimales como las de punto decimal pueden tener un componente "alfa" final separado por un guión bajo después de un componente fraccionario o de punto decimal.

El módulo version agrega las funciones y para verificar un escalar contra estas reglas.

Módulos deprecados

Varios módulos que se incluían con Perl ahora están obsoletos. Estos módulos siguen estando disponibles para la compatibilidad hacia atrás, pero se desaconseja su uso y en el futuro se eliminarán. El objetivo de esta medida es reducir el tamaño de la distribución central de Perl, promoviendo el uso de módulos de CPAN que sean más fáciles de mantener y actualizar de forma independiente.

Si te encuentras con advertencias de deprecación relacionadas con estos módulos, tienes varias opciones:

  • Puedes ignorarlas si no vas a modificar el código que las utiliza.
  • Puedes silenciar las advertencias instalando los módulos obsoletos utilizando los paquetes proporcionados por tu sistema operativo, si existen.
  • Puedes instalar los módulos obsoletos con paquetes para algunos o todos los módulos obsoletos que se instalan en los directorios de bibliotecas Perl "vendor" o "site". Esto inhibirá las advertencias de deprecación.

Alternativamente, puedes considerar parchear lib/deprecate.pm para proporcionar advertencias de deprecación específicas para tu sistema de empaquetado o distribución de Perl, de forma consistente con cómo tu sistema de empaquetado o distribución gestiona una transición escalonada desde una versión donde la instalación de un solo paquete proporciona la funcionalidad dada, a una versión posterior donde el administrador del sistema necesita saber instalar múltiples paquetes para obtener la misma funcionalidad.

Puedes silenciar estas advertencias de deprecación instalando los módulos en cuestión desde CPAN. Para instalar la última versión de todos ellos, simplemente instala "Task::Deprecations::5_12".

Revisión de Unicode

Los desarrolladores de Perl han hecho un esfuerzo concertado para actualizar Perl y sincronizarlo con el último estándar Unicode. Los cambios para esto incluyen:

Perl ahora puede manejar todas las propiedades de caracteres Unicode. La nueva documentación, perluniprops, enumera todas las propiedades de caracteres no Unihan disponibles. Por defecto, perl no expone las propiedades Unihan, obsoletas o internas de Unicode. Vea más abajo para más detalles sobre estas; también hay una sección en el pod que las enumera y explica por qué no se exponen.

Perl ahora soporta completamente el estilo compuesto de Unicode del uso de "=" y ":" al escribir expresiones regulares: "\p{property=value}" y "\p{property:value}" (ambos significan lo mismo).

Perl ahora soporta completamente las reglas de coincidencia flexible de Unicode para el texto entre llaves en construcciones de "\p{...}". Además, Perl permite guiones bajos entre dígitos de números.

Perl ahora acepta todos los sinónimos definidos por Unicode para propiedades y valores de propiedades.

"qr/\X/", que coincide con un carácter lógico Unicode, se ha ampliado para funcionar mejor con varios idiomas asiáticos. Ahora se define como un *clúster de grafemas extendido*. (Ver http://www.unicode.org/reports/tr29/). Cualquier cosa que coincidiera anteriormente y que tuviera sentido seguirá siendo aceptada. Además:

  • "\X" no separará una secuencia "CR LF".
  • "\X" ahora coincidirá con una secuencia que incluye los caracteres "ZWJ" y "ZWNJ".
  • "\X" ahora coincidirá siempre al menos con un carácter, incluyendo una marca inicial. Las marcas generalmente vienen después de un carácter base, pero es posible en Unicode tenerlas aisladas, y "\X" ahora manejará ese caso, por ejemplo al principio de una línea, o después de un "ZWSP". Y aquí es donde "\X" no coincide con lo que solía coincidir y que no tiene sentido. Anteriormente, por ejemplo, podías tener el caso sin sentido de un LF acentuado.
  • "\X" ahora coincidirá con una secuencia de sílaba Hangul (coreana) y los casos de excepción tailandesa y laosiana.

Por lo demás, este cambio debería ser transparente para los idiomas no afectados.

Las coincidencias de "\p{...}" usando la propiedad Canonical_Combining_Class estaban completamente rotas en versiones anteriores de Perl. Ahora deberían funcionar correctamente.

Antes de Perl 5.12, la propiedad Unicode "Decomposition_Type=Compat" y una extensión de Perl tenían el mismo nombre, lo que llevó a que ninguna de las dos coincidiera con todos los valores correctos (con más de 100 errores en una y varios miles en la otra). La extensión de Perl ha sido renombrada a "Decomposition_Type=Noncanonical" (abreviado: "dt=noncanon"). Tiene el mismo significado que se pretendía anteriormente, a saber, la unión de todos los tipos de descomposición no canónica, siendo Unicode "Compat" solo uno de ellos.

"\p{Decomposition_Type=Canonical}" ahora incluye las sílabas Hangul.

"\p{Uppercase}" y "\p{Lowercase}" ahora funcionan como dice el estándar Unicode. Esto significa que cada una coincide con algunos caracteres más de los que solía.

"\p{Cntrl}" ahora coincide con los mismos caracteres que "\p{Control}". Esto significa que ya no coincidirá con puntos de código de Uso Privado (gc=co), Sustitutos (gc=cs), ni de Formato (gc=cf). Los puntos de código de Formato representan el mayor problema posible. Todos menos 36 de ellos están oficialmente obsoletos o fuertemente desaconsejados de su uso. De esos 36, probablemente los más utilizados son el guion suave (U+00AD), y BOM, ZWSP, ZWNJ, WJ y caracteres similares, además de controles bidireccionales.

"\p{Alpha}" ahora coincide con los mismos caracteres que "\p{Alphabetic}". Antes de la 5.12, la definición de Perl incluía una serie de cosas que no son realmente alfabéticas (todas las marcas) mientras omitía muchas que sí lo eran. Las definiciones de "\p{Alnum}" y "\p{Word}" dependen de la definición de Alpha y han cambiado en consecuencia.

"\p{Word}" ya no coincide incorrectamente con caracteres no de palabra como las fracciones.

"\p{Print}" ya no coincide con los caracteres de control de línea: Tab, LF, CR, FF, VT y NEL. Esto lo alinea con los estándares y la documentación.

"\p{XDigit}" ahora coincide con los mismos caracteres que "\p{Hex_Digit}". Esto significa que además de los caracteres que actualmente coincide, "[A-Fa-f0-9]", también coincidirá con los 22 equivalentes de ancho completo, por ejemplo U+FF10: CERO DE ANCHO COMPLETO.

La propiedad de tipo Numérico se ha ampliado para incluir los caracteres Unihan.

Hay una nueva extensión de Perl, la propiedad 'Present_In', o simplemente 'In'. Esta es una extensión de la propiedad Age de Unicode, pero "\p{In=5.0}" coincide con cualquier punto de código cuyo uso se haya determinado *a partir* de la versión 5.0 de Unicode. El "\p{Age=5.0}" solo coincide con los puntos de código añadidos *precisamente* en la versión 5.0.

Un número de propiedades ahora tienen los valores correctos para puntos de código no asignados. Las propiedades afectadas son Bidi_Class, East_Asian_Width, Joining_Type, Decomposition_Type, Hangul_Syllable_Type, Numeric_Type y Line_Break.

Las propiedades Default_Ignorable_Code_Point, ID_Continue e ID_Start están ahora actualizadas con las definiciones actuales de Unicode.

Versiones anteriores de Perl exponían erróneamente ciertas propiedades que se supone que son solo internas de Unicode. Su uso en expresiones regulares generará ahora, si está habilitado, un mensaje de advertencia de deprecación. Las propiedades son: Other_Alphabetic, Other_Default_Ignorable_Code_Point, Other_Grapheme_Extend, Other_ID_Continue, Other_ID_Start, Other_Lowercase, Other_Math y Other_Uppercase.

Ahora es posible cambiar qué propiedades Unicode entiende Perl en una base por instalación. Como se mencionó anteriormente, ciertas propiedades están desactivadas por defecto. Estas incluyen todas las propiedades Unihan (que deberían ser accesibles a través del módulo CPAN Unicode::Unihan) y cualquier propiedad obsoleta o interna de Unicode que Perl nunca haya expuesto.

Los archivos generados en el directorio "lib/unicore/To" ahora están marcados más claramente como estables, directamente utilizables por las aplicaciones. Nuevas entradas de hash

se encuentran en el formato de las entradas normales, lo que permite un análisis más fácil por parte de las máquinas. Perl puede generar archivos en este directorio para cualquier propiedad, aunque la mayoría están suprimidas. Puede encontrar instrucciones para cambiar cuáles se escriben en perluniprops.

  • Perl_sv_utf8_upgrade() ahora es más rápido.
  • "keys" en un hash vacío ahora es más rápido.
  • "if (%foo)" se ha optimizado para ser más rápido que "if (keys %foo)".
  • El operador de repetición de cadenas ("$str x $num") ahora es varias veces más rápido cuando $str tiene longitud uno o $num es grande.
  • Invertir un array sobre sí mismo (como en "@a = reverse @a") en contexto void ahora se realiza in situ y es varios órdenes de magnitud más rápido de lo que solía ser.     Core Changes

    • Se han encontrado y corregido varios problemas de fugas de memoria en diversas partes del intérprete.
    • Las operaciones a nivel de bits en referencias podían bloquear el intérprete, por ejemplo, "$x=\$y; $x |= "foo"" [RT #54956].
    • Los patrones que incluían alternancia podían ser sensibles a la representación interna de UTF-8, por ejemplo: 
      my $byte = chr(192);
my $utf8 = chr(192); utf8::upgrade($utf8);
$utf8 =~ /$byte|X}/i;       # falló en 5.10.0
    • Dentro de archivos fuente de Perl codificados en UTF8 (es decir, donde está en vigor "use utf8"), las cadenas literales entre comillas dobles podían corromperse donde un "\xNN", "\0NNN" o "\N{}" era seguido por un carácter literal con valor ordinal mayor que 255 [RT #59908].
    • "B::Deparse" no logró depurar correctamente varias construcciones: "readpipe STRING" [RT #62428], CORE::require(STRING) [RT #62488], "sub foo(_)" [RT #62484].
    • El uso de "setpgrp" sin argumentos podía corromper la pila de perl.
    • El bloque de "eval" ahora es específicamente detectable por "Safe" y "ops". Anteriormente se trataba erróneamente como "eval" de cadena.
    • En 5.10.0, los dos caracteres "[~" a veces se analizaban como el operador de coincidencia inteligente ("~~") [RT #63854].
    • En 5.10.0, el cuantificador "*" en patrones a veces se trataba como "{0,32767}" [RT #60034, #60464]. Por ejemplo, esta coincidencia fallaría: 
      ("ab" x 32768) =~ /^(ab)*$/
    • "shmget" estaba limitado a un tamaño de segmento de 32 bits en un sistema operativo de 64 bits [RT #63924].
    • Usar "next" o "last" para salir de un bloque "given" ya no produce una advertencia espuria como la siguiente: 
      Exiting given via last at foo.pl line 123
    • Asignar un formato a un glob podía corromper el formato; por ejemplo: 
      *bar=*foo{FORMAT}; # foo format now bad
    • Intentar forzar un typeglob a una cadena o número podía causar un fallo de aserción. Ahora se genera el mensaje de error correcto, "Can't coerce GLOB to $type".
    • Bajo "use filetest 'access'", "-x" usaba el modo de acceso incorrecto. Esto se ha corregido [RT #49003].
    • "length" en un escalar enlazado que devolvía un valor Unicode no era correcto la primera vez. Esto se ha corregido.
    • Usar un "tie" de array dentro de un "tie" de array podía causar un SEGV. Esto se ha corregido. [RT #51636]
    • Se ha identificado y corregido una condición de carrera dentro de PerlIOStdio_close(). Esto solía causar varios problemas de subprocesos, incluidos SEGVs.
    • En "unpack", el uso de grupos "()" en contexto escalar colocaba internamente una lista en la pila del intérprete, lo que se manifestaba de diversas formas, incluidos SEGVs. Esto ahora está corregido [RT #50256].
    • La magia se llamó dos veces en "substr", "\&$x", "tie $x, $m" y "chop". Todo esto se ha corregido.
    • Se ha revertido una optimización de 5.10.0 para limpiar la pila temporal dentro del bucle implícito de "s///ge", ya que resultó ser la causa de errores oscuros en partes aparentemente no relacionadas del intérprete [commit ef0d4e17921ee3de].
    • Los números de línea para las advertencias dentro de "elsif" son ahora correctos.
    • El operador ".." ahora funciona correctamente con rangos cuyos extremos están en o cerca de los valores de los enteros más pequeños y más grandes.
    • "binmode STDIN, ':raw'" podía provocar fallos de segmentación en algunas plataformas. Esto se ha corregido [RT #54828].
    • Un error de un dígito significó que "index $str, ..." se ejecutaba efectivamente como "index "$str\0", ...". Esto se ha corregido [RT #53746].
    • Se han corregido varias fugas asociadas con capturas nombradas en expresiones regulares [RT #57024].
    • Una referencia débil a un hash causaba fugas. Esto afectaba a "DBI" [RT #56908].
    • El uso de (?|) en una expresión regular podía causar un segfault [RT #59734].
    • El uso de un "tr//" UTF-8 dentro de un clausura podía causar un segfault [RT #61520].
    • La llamada a Perl_sv_chop() o la actualización de un SV de otra manera podía resultar en un acceso de 64 bits no alineado en la arquitectura SPARC [RT #60574].
    • En la versión 5.10.0, "inc_version_list" listaba incorrectamente "5.10.*" después de "5.8.*"; esto afectaba al orden de búsqueda de @INC [RT #67628].
    • En 5.10.0, "pack "a*", $tainted_value" devolvía un valor no contaminado [RT #52552].
    • En 5.10.0, "printf" y "sprintf" podían producir el error fatal "panic: utf8_mg_pos_cache_update" al imprimir cadenas UTF-8 [RT #62666].
    • En la versión 5.10.0, un método "AUTOLOAD" creado dinámicamente podría no ser encontrado (problema de caché de métodos) [RT #60220,60232].
    • En la versión 5.10.0, una combinación de "use feature" y "//ee" podía causar una fuga de memoria [RT #63110].
    • Se permite nuevamente "-C" en la línea shebang ("#!") si también se especifica en la línea de comandos. "-C" en la línea shebang solía ser un no-op silencioso *si* no estaba también en la línea de comandos, por lo que perl 5.10.0 lo prohibió, lo que rompió algunos scripts. Ahora perl comprueba si también está en la línea de comandos y solo falla si no lo está [RT #67880].
    • En 5.10.0, ciertos tipos de expresiones regulares reentrantes podían bloquear o causar el siguiente fallo de aserción [RT #60508]: 
      Assertion rx->sublen >= (s - rx->subbeg) + i failed
    • Perl ahora incluye archivos previamente faltantes de la Base de Datos de Caracteres Unicode.
    • Perl ahora respeta "TMPDIR" al abrir un archivo temporal anónimo.

    If you find what you think is a bug, you might check the articles recently posted to the comp.lang.perl.misc newsgroup and the perl bug database at http://rt.perl.org/perlbug/. There may also be information at http://www.perl.org/, the Perl Home Page.

    If you believe you have an unreported bug, please run the perlbug program included with your release. Be sure to trim your bug down to a tiny but sufficient test case. Your bug report, along with the output of "perl -V", will be sent off to perlbug@perl.org to be analyzed by the Perl porting team.

    If the bug you are reporting has security implications, which make it inappropriate to send to a publicly archived mailing list, then please send it to perl5-security-report@perl.org. This points to a closed subscription unarchived mailing list, which includes all the core committers, who will be able to help assess the impact of issues, figure out a resolution, and help co-ordinate the release of patches to mitigate or fix the problem across all platforms on which Perl is supported. Please only use this address for security issues in the Perl core, not for modules independently distributed on CPAN.
