NOMBRE

perlretut - Tutorial de expresiones regulares de Perl

DESCRIPCIÓN

Esta página proporciona un tutorial básico sobre cómo entender, crear y usar expresiones regulares en Perl. Sirve como complemento de la página de referencia sobre expresiones regulares perlre. Las expresiones regulares son una parte integral de los operadores "m//", "s///", "qr//" y "split" y, por lo tanto, este tutorial también se solapa con "Regexp Quote-Like Operators" en perlop y "split" en perlfunc.

Perl es ampliamente reconocido por su excelencia en el procesamiento de texto, y las expresiones regulares son uno de los grandes factores detrás de esta fama. Las expresiones regulares de Perl muestran una eficiencia y flexibilidad desconocidas en la mayoría de los otros lenguajes de computadora. Dominar incluso los conceptos básicos de las expresiones regulares te permitirá manipular texto con sorprendente facilidad.

¿Qué es una expresión regular? En su nivel más básico, una expresión regular es una plantilla que se utiliza para determinar si una cadena tiene ciertas características. La cadena es muy a menudo algún texto, como una línea, una oración, una página web, o incluso un libro completo, pero no tiene por qué serlo. Podría ser datos binarios, por ejemplo. Los biólogos a menudo usan Perl para buscar patrones en largas secuencias de ADN.

Supongamos que queremos determinar si el texto en la variable $var contiene la secuencia de caracteres "champiñón" (espacios añadidos para legibilidad). Podemos escribir en Perl:

$var =~ m/champiñon/

El valor de esta expresión será VERDADERO si $var contiene esa secuencia de caracteres en cualquier lugar, y FALSO en caso contrario. La porción encerrada entre caracteres '/' denota la característica que estamos buscando. Usamos el término patrón para ello. El proceso de buscar para ver si el patrón ocurre en la cadena se llama coincidencia, y el operador "=~" junto con "m//" le dicen a Perl que intente hacer coincidir el patrón con la cadena. Tenga en cuenta que el patrón también es una cadena, pero de un tipo muy especial, como veremos. Los patrones están en uso común hoy en día; los ejemplos son los patrones escritos en un motor de búsqueda para encontrar páginas web y los patrones utilizados para listar archivos en un directorio, es decir, ""ls *.txt"" o ""dir *.*"". En Perl, los patrones descritos por expresiones regulares se utilizan no solo para buscar cadenas, sino también para extraer partes deseadas de las cadenas y para realizar operaciones de búsqueda y reemplazo.

Las expresiones regulares tienen la reputación inmerecida de ser abstractas y difíciles de entender. Esto realmente se debe simplemente a que la notación utilizada para expresarlas tiende a ser concisa y densa, y no a una complejidad inherente. Recomendamos usar el modificador de expresión regular "/x" (descrito a continuación) junto con mucho espacio en blanco para hacerlas menos densas y más fáciles de leer. Las expresiones regulares se construyen utilizando conceptos simples como condicionales y bucles y no son más difíciles de entender que los condicionales "if" y los bucles "while" correspondientes en el propio lenguaje Perl.

Este tutorial achata la curva de aprendizaje discutiendo los conceptos de expresiones regulares, junto con su notación, uno a la vez y con muchos ejemplos. La primera parte del tutorial progresará desde las búsquedas de palabras más simples hasta los conceptos básicos de expresiones regulares. Si domina la primera parte, tendrá todas las herramientas necesarias para resolver aproximadamente el 98% de sus necesidades. La segunda parte del tutorial es para aquellos cómodos con los conceptos básicos y con ganas de herramientas más potentes. Discute los operadores de expresiones regulares más avanzados e introduce las últimas innovaciones de vanguardia.

Una nota: para ahorrar tiempo, "expresión regular" a menudo se abrevia como regexp o regex. Regexp es una abreviatura más natural que regex, pero es más difícil de pronunciar. La documentación pod de Perl está equilibrada entre regexp y regex; en Perl, hay más de una forma de abreviarlo. Usaremos regexp en este tutorial.

Novedad en la v5.22, "use re 'strict'" aplica reglas más estrictas de lo contrario al compilar patrones de expresiones regulares. Puede encontrar cosas que, aunque legales, pueden no ser lo que usted pretendía.

Parte 1: Los conceptos básicos

Coincidencia simple de palabras

El regexp más simple es simplemente una palabra, o más generalmente, una cadena de caracteres. Un regexp que consiste solo en una palabra coincide con cualquier cadena que contenga esa palabra:

"Hola Mundo" =~ /Mundo/;  # coincide

¿De qué trata esta sentencia de Perl? "Hola Mundo" es una simple cadena entre comillas dobles. "Mundo" es la expresión regular y los "//" que encierran "/Mundo/" le dicen a Perl que busque una coincidencia en una cadena. El operador "=~" asocia la cadena con la coincidencia del regexp y produce un valor verdadero si el regexp coincidió, o falso si el regexp no coincidió. En nuestro caso, "Mundo" coincide con la segunda palabra en "Hola Mundo", por lo que la expresión es verdadera. Expresiones como esta son útiles en condicionales:

if ("Hola Mundo" =~ /Mundo/) {
    print "Coincide\n";
}
else {
    print "No coincide\n";
}

Hay variaciones útiles sobre este tema. El sentido de la coincidencia se puede invertir usando el operador "!~":

if ("Hola Mundo" !~ /Mundo/) {
    print "No coincide\n";
}
else {
    print "Coincide\n";
}

La cadena literal en el regexp puede ser reemplazada por una variable:

my $saludo = "Mundo";
if ("Hola Mundo" =~ /$saludo/) {
    print "Coincide\n";
}
else {
    print "No coincide\n";
}

Si estás haciendo coincidir la variable especial predeterminada $_, la parte "$_ =~" se puede omitir:

$_ = "Hola Mundo";
if (/Mundo/) {
    print "Coincide\n";
}
else {
    print "No coincide\n";
}

Y finalmente, los delimitadores predeterminados "//" para una coincidencia se pueden cambiar a delimitadores arbitrarios anteponiendo una 'm':

"Hola Mundo" =~ m!Mundo!;   # coincide, delimitado por '!'
"Hola Mundo" =~ m{Mundo};   # coincide, nota los pares '{}'
"/usr/bin/perl" =~ m"/perl"; # coincide después de '/usr/bin',
                             # '/' se convierte en un carácter ordinario

"/Mundo/", "m!Mundo!", y "m{Mundo}" todos representan lo mismo. Cuando, por ejemplo, la comilla ('"') se usa como delimitador, la barra inclinada '/' se convierte en un carácter ordinario y se puede usar en este regexp sin problemas.

Consideremos cómo diferentes regexps coincidirían con "Hola Mundo":

"Hola Mundo" =~ /mundo/;  # no coincide
"Hola Mundo" =~ /o M/;    # coincide
"Hola Mundo" =~ /oM/;     # no coincide
"Hola Mundo" =~ /Mundo /; # no coincide

El primer regexp "mundo" no coincide porque los regexps son sensibles a mayúsculas y minúsculas por defecto. El segundo regexp coincide porque la subcadena 'o M' ocurre en la cadena "Hola Mundo". El carácter de espacio ' ' se trata como cualquier otro carácter en un regexp y es necesario para que coincida en este caso. La ausencia del carácter de espacio es la razón por la que el tercer regexp 'oM' no coincide. El cuarto regexp ""Mundo "" no coincide porque hay un espacio al final del regexp, pero no al final de la cadena. La lección aquí es que los regexps deben coincidir exactamente con una parte de la cadena para que la sentencia sea verdadera.

Si un regexp coincide en más de un lugar en la cadena, Perl siempre coincidirá en el punto más temprano posible en la cadena:

"Hola Mundo" =~ /o/;       # coincide

Ahora sabemos cómo crear opciones entre clases de caracteres en una expresión regular. ¿Qué pasa con las opciones entre palabras o cadenas de caracteres? Estas opciones se describen en la siguiente sección.

Coincidencia de esto o aquello

A veces nos gustaría que nuestra expresión regular pudiera coincidir con diferentes palabras o cadenas de caracteres posibles. Esto se logra usando el metacaracter de *alternancia* '|'. Para hacer coincidir "perro" o "gato", formamos la expresión regular "perro|gato". Como antes, Perl intentará hacer coincidir la expresión regular en el punto más temprano posible de la cadena. En cada posición de carácter, Perl primero intentará hacer coincidir la primera alternativa, "perro". Si "perro" no coincide, Perl intentará la siguiente alternativa, "gato". Si "gato" tampoco coincide, entonces la coincidencia falla y Perl pasa a la siguiente posición en la cadena. Algunos ejemplos:

"gatos y perros" =~ /gato|perro|pájaro/;  # coincide con "gato"
"gatos y perros" =~ /perro|gato|pájaro/;  # coincide con "gato"

Incluso aunque "perro" es la primera alternativa en la segunda expresión regular, "gato" puede coincidir antes en la cadena.

"gatos"          =~ /g|ga|gato|gatos/; # coincide con "g"
"gatos"          =~ /gatos|gato|ga|g/; # coincide con "gatos"

Aquí, todas las alternativas coinciden en la primera posición de la cadena, por lo que la primera alternativa es la que coincide. Si algunas de las alternativas son truncamientos de otras, ponga las más largas primero para darles una oportunidad de coincidir.

"cab" =~ /a|b|c/ # coincide con "c"
                 # /a|b|c/ == /[abc]/

El último ejemplo señala que las clases de caracteres son como alternancias de caracteres. En una posición de carácter dada, la primera alternativa que permite que la expresión regular coincida será la que coincida.

Agrupando cosas y coincidencia jerárquica

La alternancia permite que una expresión regular elija entre alternativas, pero por sí sola es insatisfactoria. La razón es que cada alternativa es una expresión regular completa, pero a veces queremos alternativas solo para una parte de una expresión regular. Por ejemplo, supongamos que queremos buscar gatos domésticos o amas de llaves. La expresión regular "gato_domestico|ama_de_llaves" cumple el propósito, pero es ineficiente porque tuvimos que escribir "casa" dos veces. Sería bueno tener partes de la expresión regular constantes, como "casa", y algunas partes con alternativas, como "gato|ama_de_llaves".

Los metacaracteres de *agrupación* "()" resuelven este problema. La agrupación permite que partes de una expresión regular se traten como una sola unidad. Las partes de una expresión regular se agrupan encerrándolas entre paréntesis. Así podríamos resolver "gato_domestico|ama_de_llaves" formando la expresión regular como casa(gato|ama_de_llaves). La expresión regular casa(gato|ama_de_llaves) significa coincidir con "casa" seguido de "gato" o "ama_de_llaves". Algunos ejemplos más son

/(a|b)b/;    # coincide con 'ab' o 'bb'
/(ac|b)b/;   # coincide con 'acb' o 'bb'
/(^a|b)c/;   # coincide con 'ac' al principio de la cadena o 'bc' en cualquier lugar
/(a|[bc])d/; # coincide con 'ad', 'bd', o 'cd'
/casa(gato|)/;  # coincide con 'casagato' o 'casa'
/casa(gato(s|)|)/;  # coincide con 'casagatos' o 'casagato' o
                    # 'casa'. Nótese que los grupos pueden anidarse.
/(19|20|)\d\d/;  # coincide con años 19xx, 20xx, o el problema Y2K, xx
"20" =~ /(19|20|)\d\d/;  # coincide con la alternativa nula '()\d\d',
                         # porque '20\d\d' no puede coincidir

Las alternancias se comportan de la misma manera dentro de los grupos que fuera de ellos: en una posición de cadena dada, se toma la alternativa más a la izquierda que permite que la expresión regular coincida. Así que en el último ejemplo, en la primera posición de la cadena, "20" coincide con la segunda alternativa, pero no queda nada para coincidir con los dos dígitos siguientes "\d\d". Por lo tanto, Perl pasa a la siguiente alternativa, que es la alternativa nula y eso funciona, ya que "20" son dos dígitos.

El proceso de probar una alternativa, ver si coincide y pasar a la siguiente alternativa, retrocediendo en la cadena desde donde se intentó la alternativa anterior, si no lo hace, se llama *backtracking* (retrospección). El término "backtracking" proviene de la idea de que hacer coincidir una expresión regular es como un paseo por el bosque. Hacer coincidir exitosamente una expresión regular es como llegar a un destino. Hay muchos puntos de partida posibles, uno para cada posición de la cadena, y cada uno se prueba en orden, de izquierda a derecha. Desde cada punto de partida puede haber muchos caminos, algunos de los cuales te llevan allí, y otros que son callejones sin salida. Cuando caminas por un sendero y llegas a un callejón sin salida, tienes que retroceder por el sendero hasta un punto anterior para intentar otro sendero. Si llegas a tu destino, te detienes inmediatamente y te olvidas de intentar todos los demás senderos. Eres persistente, y solo si has intentado todos los senderos desde todos los puntos de partida y no has llegado a tu destino, declaras el fracaso. Para ser concreto, aquí hay un análisis paso a paso de lo que hace Perl cuando intenta hacer coincidir la expresión regular

"abcde" =~ /(abd|abc)(df|d|de)/;
1.
Comienza con la primera letra de la cadena 'a'.
2.
Intenta la primera alternativa en el primer grupo 'abd'.
3.
Coincide 'a' seguido de 'b'. Hasta ahora todo bien.
4.
'd' en la expresión regular no coincide con 'c' en la cadena: un callejón sin salida. Así que retrocede dos caracteres y elige la segunda alternativa en el primer grupo 'abc'.
5.
Coincide 'a' seguido de 'b' seguido de 'c'. Vamos bien y hemos satisfecho el primer grupo. Establece $1 a 'abc'.
6.
Pasa al segundo grupo y elige la primera alternativa 'df'.
7.
Coincide con la 'd'.
8.
'f' en la expresión regular no coincide con 'e' en la cadena, por lo que es un callejón sin salida. Retrocede un carácter y elige la segunda alternativa en el segundo grupo 'd'.
9.
'd' coincide. El segundo grupo está satisfecho, así que establece $2 a 'd'.
10.
Estamos al final de la expresión regular, ¡así que hemos terminado! Hemos hecho coincidir 'abcd' de la cadena "abcde".

Hay un par de cosas a tener en cuenta sobre este análisis. Primero, la tercera alternativa en el segundo grupo 'de' también permite una coincidencia, pero nos detuvimos antes de llegar a ella: en una posición de carácter dada, la más a la izquierda gana. Segundo, pudimos obtener una coincidencia en la primera posición de carácter de la cadena 'a'. Si no hubiera coincidencias en la primera posición, Perl pasaría a la segunda posición de carácter 'b' e intentaría la coincidencia de nuevo. Solo cuando todos los caminos posibles en todas las posiciones de carácter posibles se hayan agotado, Perl se rendirá y declarará que "$cadena =~ /(abd|abc)(df|d|de)/;" es falso.

Incluso con todo este trabajo, la coincidencia de expresiones regulares ocurre notablemente rápido. Para acelerar las cosas, Perl compila la expresión regular en una secuencia compacta de opcodes que a menudo pueden caber dentro de la caché de un procesador. Cuando el código se ejecuta, estos opcodes pueden funcionar a máxima velocidad y buscar muy rápidamente.

Extrayendo coincidencias

Los metacaracteres de agrupación "()" también sirven para otra función completamente diferente: permiten la extracción de las partes de una cadena que coincidieron. Esto es muy útil para averiguar qué coincidió y para el procesamiento de texto en general. Por cada agrupación, la parte que coincidió dentro va a las variables especiales $1, $2, *etc.* Se pueden usar como variables ordinarias:

# extraer horas, minutos, segundos
if ($tiempo =~ /(\d\d):(\d\d):(\d\d)/) {    # coincide con formato hh:mm:ss
    $horas = $1;
    $minutos = $2;
    $segundos = $3;
}

Ahora, sabemos que en contexto escalar, "$tiempo =~ /(\d\d):(\d\d):(\d\d)/" devuelve un valor verdadero o falso. Sin embargo, en contexto de lista, devuelve la lista de valores coincidentes "($1,$2,$3)". Por lo tanto, podríamos escribir el código de forma más compacta como

# extraer horas, minutos, segundos
($horas, $minutos, $segundo) = ($tiempo =~ /(\d\d):(\d\d):(\d\d)/);

Si las agrupaciones en una expresión regular están anidadas, $1 recibe el grupo con el paréntesis de apertura más a la izquierda, $2 el siguiente paréntesis de apertura, *etc.* Aquí hay una expresión regular con grupos anidados:

/(ab(cd|ef)((gi)|j))/;
 1  2      34

Si esta expresión regular coincide, $1 contiene una cadena que comienza con 'ab', $2 se establece en 'cd' o 'ef', $3 es igual a 'gi' o 'j', y $4 se establece en 'gi', al igual que $3, o permanece indefinido.

Referencias cruzadas

Estrechamente asociadas con las variables coincidentes $1, $2, ... están las referencias cruzadas "\g1", "\g2",... Las referencias cruzadas son simplemente variables coincidentes que se pueden usar dentro de una expresión regular. Esta es una característica realmente buena; lo que coincide más tarde en una expresión regular depende de lo que coincidió antes en la expresión regular. Supongamos que queríamos buscar palabras duplicadas en un texto, como "la la". La siguiente expresión regular encuentra todos los duplicados de 3 letras con un espacio en medio:

/\b(\w\w\w)\s\g1\b/;

La agrupación asigna un valor a "\g1", de modo que se usa la misma secuencia de 3 letras para ambas partes.

Una tarea similar es encontrar palabras que consisten en dos partes idénticas:

% simple_grep '^(\w\w\w\w|\w\w\w|\w\w|\w)\g1$' /usr/dict/words
beriberi
booboo
coco
mama
murmur
papa

La expresión regular tiene una única agrupación que considera combinaciones de 4 letras, luego combinaciones de 3 letras, etc., y usa "\g1" para buscar una repetición. Aunque $1 y "\g1" representan lo mismo, se debe tener cuidado de usar las variables coincidentes $1, $2,... solo fuera de una expresión regular y las referencias cruzadas "\g1", "\g2",... solo dentro de una expresión regular; no hacerlo puede llevar a resultados sorprendentes e insatisfactorios.

Referencias cruzadas relativas

Contar los paréntesis de apertura para obtener el número correcto para una referencia cruzada es propenso a errores tan pronto como hay más de un grupo de captura. Una técnica más conveniente estuvo disponible con Perl 5.10: las referencias cruzadas relativas. Para referirse al grupo de captura inmediatamente anterior, ahora se puede escribir "\g-1" o "\g{-1}", el penúltimo está disponible a través de "\g-2" o "\g{-2}", y así sucesivamente.

Otra buena razón, además de la legibilidad y el mantenimiento, para usar referencias cruzadas relativas se ilustra con el siguiente ejemplo, donde se utiliza un patrón simple para hacer coincidir cadenas peculiares:

$a99a = '([a-z])(\d)\g2\g1';   # coincide con a11a, g22g, x33x, etc.

Ahora que tenemos este patrón almacenado como una cadena útil, podríamos sentirnos tentados a usarlo como parte de algún otro patrón:

$line = "code=e99e";
if ($line =~ /^(\w+)=$a99a$/){   # ¡comportamiento inesperado!
    print "$1 es válido\n";
} else {
    print "línea incorrecta: '$line'\n";
}

Pero esto no coincide, al menos no de la manera que uno podría esperar. Solo después de insertar el $a99a interpolado y observar el texto completo resultante de la expresión regular es obvio que las referencias cruzadas han fallado. La subexpresión "(\w+)" ha capturado el número 1 y ha degradado los grupos en $a99a en un rango. Esto se puede evitar utilizando referencias cruzadas relativas:

$a99a = '([a-z])(\d)\g{-1}\g{-2}';  # seguro para ser interpolado

Referencias cruzadas con nombre

Perl 5.10 también introdujo grupos de captura con nombre y referencias cruzadas con nombre. Para adjuntar un nombre a un grupo de captura, se escribe "(?<nombre>...)" o "(?'nombre'...)". La referencia cruzada se puede escribir como "\g{nombre}". Es permisible adjuntar el mismo nombre a más de un grupo, pero entonces solo se puede hacer referencia al más a la izquierda del conjunto epónimo. Fuera del patrón, se puede acceder a un grupo de captura con nombre a través del hash "%+".

Suponiendo que debemos hacer coincidir fechas de calendario que pueden proporcionarse en uno de los tres formatos aaaa-mm-dd, mm/dd/aaaa o dd.mm.aaaa, podemos escribir tres patrones adecuados donde usamos 'd', 'm' y 'y' respectivamente como los nombres de los grupos que capturan los componentes pertinentes de una fecha. La operación de coincidencia combina los tres patrones como alternativas:

$fmt1 = '(?<y>\d\d\d\d)-(?<m>\d\d)-(?<d>\d\d)';
$fmt2 = '(?<m>\d\d)/(?<d>\d\d)/(?<y>\d\d\d\d)';
$fmt3 = '(?<d>\d\d)\.(?<m>\d\d)\.(?<y>\d\d\d\d)';
for my $d (qw(2006-10-21 15.01.2007 10/31/2005)) {
    if ( $d =~ m{$fmt1|$fmt2|$fmt3} ){
        print "día=$+{d} mes=$+{m} año=$+{y}\n";
    }
}

Si alguna de las alternativas coincide, el hash "%+" contendrá los tres pares clave-valor.

Numeración alternativa de grupos de captura

Una técnica más de numeración de grupos de captura (también a partir de Perl 5.10) aborda el problema de referirse a grupos dentro de un conjunto de alternativas. Considere un patrón para hacer coincidir una hora del día, estilo civil o militar:

if ( $time =~ /(\d\d|\d):(\d\d)|(\d\d)(\d\d)/ ){
    # procesar hora y minuto
}

El procesamiento de los resultados requiere una instrucción if adicional para determinar si $1 y $2 o $3 y $4 contienen los elementos deseados. Sería más fácil si pudiéramos usar los números de grupo 1 y 2 también en la segunda alternativa, y esto es exactamente lo que logra la construcción entre paréntesis "(?|...)", colocada alrededor de una alternativa. Aquí hay una versión extendida del patrón anterior:

if($time =~ /(?|(\d\d|\d):(\d\d)|(\d\d)(\d\d))\s+([A-Z][A-Z][A-Z])/){
    print "hora=$1 minuto=$2 zona=$3\n";
}

Dentro del grupo de numeración de alternativas, los números de grupo comienzan en la misma posición para cada alternativa. Después del grupo, la numeración continúa con un número mayor que el máximo alcanzado en todas las alternativas.

Información de posición

Además de lo que coincidió, Perl también proporciona las posiciones de lo que coincidió como contenido de los arreglos "@-" y "@+". "$-[0]" es la posición de inicio de la coincidencia completa y $+[0] es la posición final. De manera similar, "$-[n]" es la posición de inicio de la coincidencia de $n y $+[n] es la posición final. Si $n no está definido, tampoco lo están "$-[n]" y $+[n]. Entonces este código

$x = "Mmm...donut, pensó Homer";
$x =~ /^(Mmm|Yech)\.\.\.(donut|peas)/; # coincide
foreach $exp (1..$#-) {
    no strict 'refs';
    print "Coincidencia $exp: '$$exp' en posición ($-[$exp],$+[$exp])\n";
}

Incluso si no hay agrupaciones en una expresión regular, todavía es posible averiguar qué coincidió exactamente en una cadena. Si los usa, Perl establecerá "$`" en la parte de la cadena antes de la coincidencia, establecerá $& en la parte de la cadena que coincidió, y establecerá "$'" en la parte de la cadena después de la coincidencia. Un ejemplo:

$x = "el gato atrapó el ratón";
$x =~ /gato/;  # $` = 'el ', $& = 'gato', $' = ' atrapó el ratón'
$x =~ /el/;  # $` = '', $& = 'el', $' = ' gato atrapó el ratón'

En la segunda coincidencia, "$`" es igual a '' porque la expresión regular coincidió en la primera posición de carácter de la cadena y se detuvo; nunca vio el segundo "el".

Si su código se ejecutará en versiones de Perl anteriores a 5.20, vale la pena señalar que el uso de "$`" y "$'" ralentiza la coincidencia de expresiones regulares bastante, mientras que $& la ralentiza en menor medida, porque si se usan en una expresión regular en un programa, se generan para *todas* las expresiones regulares del programa. Por lo tanto, si el rendimiento bruto es un objetivo de su aplicación, deben evitarse. Si necesita extraer las subcadenas correspondientes, use "@-" y "@+" en su lugar:

$` es lo mismo que substr( $x, 0, $-[0] )
$& es lo mismo que substr( $x, $-[0], $+[0]-$-[0] )
$' es lo mismo que substr( $x, $+[0] )

A partir de Perl 5.10, se pueden usar las variables "${^PREMATCH}", "${^MATCH}" y "${^POSTMATCH}". Estas solo se establecen si está presente el modificador "/p". En consecuencia, no penalizan el resto del programa. En Perl 5.20, "${^PREMATCH}", "${^MATCH}" y "${^POSTMATCH}" están disponibles independientemente de si se ha utilizado o no "/p" (el modificador se ignora), y "$`", "$'" y $& no causan ninguna diferencia de velocidad.

Agrupaciones sin captura

Un grupo que se requiere para agrupar un conjunto de alternativas puede ser útil o no como grupo de captura. Si no lo es, simplemente crea una adición superflua al conjunto de valores de grupo de captura, tanto dentro como fuera de la expresión regular. Las agrupaciones sin captura, denotadas por "(?:regexp)", aún permiten que la expresión regular se trate como una unidad única, pero no establecen un grupo de captura al mismo tiempo. Tanto las agrupaciones de captura como las sin captura están permitidas para coexistir en la misma expresión regular. Debido a que no hay extracción, las agrupaciones sin captura son más rápidas que las agrupaciones de captura. Las agrupaciones sin captura también son útiles para elegir exactamente qué partes de una expresión regular se extraerán a variables coincidentes:

Minimal quantifiers

The default behavior of quantifiers is to be as greedy as possible. That is, they match as many characters as they can while still allowing the overall regexp to match. In this section we will see how to make quantifiers non-greedy, or minimal. If a quantifier is followed by a "?", it becomes minimal.

$x = "The programming republic of Perl";
$x =~ /^(.+?)(e|r)(.*)$/; # matches,
                          # $1 = 'Th'
                          # $2 = 'e'
                          # $3 = ' programming republic of Perl'

The minimal string that will allow both the start of the string '^' and the alternation to match is "Th", with the alternation "e|r" matching 'e'. The second quantifier ".*" is free to gobble up the rest of the string.

$x =~ /(m{1,2}?)(.*?)$/;  # matches,
                          # $1 = 'm'
                          # $2 = 'ming republic of Perl'

The first string position that this regexp can match is at the first 'm' in "programming". At this position, the minimal "m{1,2}?" matches just one 'm'. Although the second quantifier ".*?" would prefer to match no characters, it is constrained by the end-of-string anchor '$' to match the rest of the string.

$x =~ /(.*?)(m{1,2}?)(.*)$/;  # matches,
                              # $1 = 'The progra'
                              # $2 = 'm'
                              # $3 = 'ming republic of Perl'

In this regexp, you might expect the first minimal quantifier ".*?" to match the empty string, because it is not constrained by a '^' anchor to match the beginning of the word. Principle 0 applies here, however. Because it is possible for the whole regexp to match at the start of the string, it will match at the start of the string. Thus the first quantifier has to match everything up to the first 'm'. The second minimal quantifier matches just one 'm' and the third quantifier matches the rest of the string.

$x =~ /(.??)(m{1,2})(.*)$/;  # matches,
                             # $1 = 'a'
                             # $2 = 'mm'
                             # $3 = 'ing republic of Perl'

Just as in the previous regexp, the first quantifier ".??" can match earliest at position 'a', so it does. The second quantifier is greedy, so it matches "mm", and the third matches the rest of the string.

We can modify principle 3 above to take into account non-greedy quantifiers:

•
Principle 3: If there are two or more elements in a regexp, the leftmost greedy (non-greedy) quantifier, if any, will match as much (little) of the string as possible while still allowing the whole regexp to match. The next leftmost greedy (non-greedy) quantifier, if any, will try to match as much (little) of the string remaining available to it as possible, while still allowing the whole regexp to match. And so on, until all the regexp elements are satisfied.

Just like alternation, quantifiers are also susceptible to backtracking. Here is a step-by-step analysis of the example

$x = "the cat in the hat";
$x =~ /^(.*)(at)(.*)$/; # matches,
                        # $1 = 'the cat in the h'
                        # $2 = 'at'
                        # $3 = ''   (0 matches)
1.
Start with the first letter in the string 't'.
2.
The first quantifier '.*' starts out by matching the whole string "the cat in the hat".
3.
'a' in the regexp element 'at' doesn't match the end of the string. Backtrack one character.
4.
'a' in the regexp element 'at' still doesn't match the last letter of the string 't', so backtrack one more character.
5.
Now we can match the 'a' and the 't'.
6.
Move on to the third element '.*'. Since we are at the end of the string and '.*' can match 0 times, assign it the empty string.
7.
We are done!

Most of the time, all this moving forward and backtracking happens quickly and searching is fast. There are some pathological regexps, however, whose execution time exponentially grows with the size of the string. A typical structure that blows up in your face is of the form

/(a|b+)*/;

The problem is the nested indeterminate quantifiers. There are many different ways of partitioning a string of length n between the '+' and '*': one repetition with "b+" of length n, two repetitions with the first "b+" length k and the second with length n-k, m repetitions whose bits add up to length n, etc. In fact there are an exponential number of ways to partition a string as a function of its length. A regexp may get lucky and match early in the process, but if there is no match, Perl will try every possibility before giving up. So be careful with nested '*''s, "{n,m}"'s, and '+''s. The book Mastering Regular Expressions by Jeffrey Friedl gives a wonderful discussion of this and other efficiency issues.

Possessive quantifiers

Backtracking during the relentless search for a match may be a waste of time, particularly when the match is bound to fail. Consider the simple pattern

/^\w+\s+\w+$/; # a word, spaces, a word

Whenever this is applied to a string which doesn't quite meet the pattern's expectations such as "abc  " or "abc  def ", the regexp engine will backtrack, approximately once for each character in the string. But we know that there is no way around taking all of the initial word characters to match the first repetition, that all spaces must be eaten by the middle part, and the same goes for the second word.

With the introduction of the possessive quantifiers in Perl 5.10, we have a way of instructing the regexp engine not to backtrack, with the usual quantifiers with a '+' appended to them. This makes them greedy as well as stingy; once they succeed they won't give anything back to permit another solution. They have the following meanings:

  • "a{n,m}+" means: match at least "n" times, not more than "m" times, as many times as possible, and don't give anything up. "a?+" is short for "a{0,1}+"
  • "a{n,}+" means: match at least "n" times, but as many times as possible, and don't give anything up. "a++" is short for "a{1,}+".
  • "a{,n}+" means: match as many times as possible up to at most "n" times, and don't give anything up. "a*+" is short for "a{0,}+".
  • "a{n}+" means: match exactly "n" times. It is just there for notational consistency.

These possessive quantifiers represent a special case of a more general concept, the independent subexpression, see below.

As an example where a possessive quantifier is suitable we consider matching a quoted string, as it appears in several programming languages. The backslash is used as an escape character that indicates that the next character is to be taken literally, as another character for the string. Therefore, after the opening quote, we expect a (possibly empty) sequence of alternatives: either some character except an unescaped quote or backslash or an escaped character.

/"(?:[^"\\]++|\\.)*+"/;

Building a regexp

At this point, we have all the basic regexp concepts covered, so let's give a more involved example of a regular expression. We will build a regexp that matches numbers.

The first task in building a regexp is to decide what we want to match and what we want to exclude. In our case, we want to match both integers and floating point numbers and we want to reject any string that isn't a number.

The next task is to break the problem down into smaller problems that are easily converted into a regexp.

The simplest case is integers. These consist of a sequence of digits, with an optional sign in front. The digits we can represent with "\d+" and the sign can be matched with "[+-]". Thus the integer regexp is

/[+-]?\d+/;  # matches integers

A floating point number potentially has a sign, an integral part, a decimal point, a fractional part, and an exponent. One or more of these parts is optional, so we need to check out the different possibilities. Floating point numbers which are in proper form include 123., 0.345, .34, -1e6, and 25.4E-72. As with integers, the sign out front is completely optional and can be matched by "[+-]?". We can see that if there is no exponent, floating point numbers must have a decimal point, otherwise they are integers. We might be tempted to model these with "\d*\.\d*", but this would also match just a single decimal point, which is not a number. So the three cases of floating point number without exponent are

/[+-]?\d+\./;  # 1., 321., etc.
/[+-]?\.\d+/;  # .1, .234, etc.
/[+-]?\d+\.\d+/;  # 1.0, 30.56, etc.

These can be combined into a single regexp with a three-way alternation:

/[+-]?(\d+\.\d+|\d+\.|\.\d+)/;  # floating point, no exponent

In this alternation, it is important to put '\d+\.\d+' before '\d+\.'. If '\d+\.' were first, the regexp would happily match that and ignore the fractional part of the number.

Building a regexp

Se debe colocar un signo de interrogación delante de un exponente. Luego, los exponentes, al igual que el signo general, son independientes de si estamos comparando números con o sin puntos decimales, y se pueden "desacoplar" de la mantisa. La forma general de la expresión regular ahora se vuelve clara:

/^(signo opcional)(entero | mantisa de punto flotante)(exponente opcional)$/;

El exponente es una 'e' o 'E', seguida de un entero. Por lo tanto, la expresión regular del exponente es

/[eE][+-]?\d+/;  # exponente

Juntando todas las partes, obtenemos una expresión regular que coincide con números:

/^[+-]?(\d+\.\d+|\d+\.|\.\d+|\d+)([eE][+-]?\d+)?$/;  # ¡Tachán!

Las expresiones regulares largas como esta pueden impresionar a tus amigos, pero pueden ser difíciles de descifrar. En situaciones complejas como esta, el modificador "/x" para una coincidencia es invaluable. Permite insertar espacios en blanco y comentarios casi arbitrarios en una expresión regular sin afectar su significado. Usándolo, podemos reescribir nuestra expresión regular "extendida" en la forma más agradable

/^
   [+-]?         # primero, coincide con un signo opcional
   (             # luego coincide con enteros o mantisas de punto flotante:
       \d+\.\d+  # mantisa de la forma a.b
      |\d+\.     # mantisa de la forma a.
      |\.\d+     # mantisa de la forma .b
      |\d+       # entero de la forma a
   )
   ( [eE] [+-]? \d+ )?  # finalmente, coincide opcionalmente con un exponente
$/x;

Si los espacios en blanco son en su mayoría irrelevantes, ¿cómo se incluyen los caracteres de espacio en una expresión regular extendida? La respuesta es anteponerles una barra invertida '\ ' o colocarlos en una clase de caracteres "[ ]". Lo mismo ocurre con los signos de almohadilla: use "\#" o "[#]". Por ejemplo, Perl permite un espacio entre el signo y la mantisa o el entero, y podríamos agregar esto a nuestra expresión regular de la siguiente manera:

/^
   [+-]?\ *      # primero, coincide con un signo opcional *y espacio*
   (             # luego coincide con enteros o mantisas de punto flotante:
       \d+\.\d+  # mantisa de la forma a.b
      |\d+\.     # mantisa de la forma a.
      |\.\d+     # mantisa de la forma .b
      |\d+       # entero de la forma a
   )
   ( [eE] [+-]? \d+ )?  # finalmente, coincide opcionalmente con un exponente
$/x;

En esta forma, es más fácil ver una manera de simplificar la alternancia. Las alternativas 1, 2 y 4 comienzan todas con "\d+", por lo que se podría factorizar:

/^
   [+-]?\ *      # primero, coincide con un signo opcional
   (             # luego coincide con enteros o mantisas de punto flotante:
       \d+       # comienza con un ...
       (
           \.\d* # mantisa de la forma a.b o a.
       )?        # ? se encarga de los enteros de la forma a
      |\.\d+     # mantisa de la forma .b
   )
   ( [eE] [+-]? \d+ )?  # finalmente, coincide opcionalmente con un exponente
$/x;

A partir de Perl v5.26, especificar "/xx" cambia las porciones de un patrón entre corchetes para ignorar los caracteres de tabulación y espacio, a menos que se escapen precediéndolos con una barra invertida. Por lo tanto, podríamos escribir

/^
   [ + - ]?\ *   # primero, coincide con un signo opcional
   (             # luego coincide con enteros o mantisas de punto flotante:
       \d+       # comienza con un ...
       (
           \.\d* # mantisa de la forma a.b o a.
       )?        # ? se encarga de los enteros de la forma a
      |\.\d+     # mantisa de la forma .b
   )
   ( [ e E ] [ + - ]? \d+ )?  # finalmente, coincide opcionalmente con un exponente
$/xx;

Esto no mejora realmente la legibilidad de este ejemplo, pero está disponible en caso de que lo desee. Al reducir el patrón a la forma compacta, tenemos

/^[+-]?\ *(\d+(\.\d*)?|\.\d+)([eE][+-]?\d+)?$/;

Esta es nuestra expresión regular final. Para recapitular, construimos una expresión regular

  • especificando la tarea en detalle,
  • desglosando el problema en partes más pequeñas,
  • traduciendo las partes pequeñas a expresiones regulares,
  • combinando las expresiones regulares,
  • y optimizando la expresión regular combinada final.

Estos son también los pasos típicos involucrados en la escritura de un programa de computadora. Esto tiene perfecto sentido, porque las expresiones regulares son esencialmente programas escritos en un pequeño lenguaje de computadora que especifica patrones.

Uso de expresiones regulares en Perl

El último tema de la Parte 1 cubre brevemente cómo se utilizan las expresiones regulares en los programas de Perl. ¿Dónde encajan en la sintaxis de Perl?

Ya hemos introducido el operador de coincidencia en su forma predeterminada "/regexp/" y en su forma de delimitador arbitrario "m!regexp!". Hemos utilizado el operador de enlace "=~" y su negación "!~" para probar coincidencias de cadenas. Asociados con el operador de coincidencia, hemos discutido los modificadores de una sola línea "/s", multilínea "/m", insensible a mayúsculas y minúsculas "/i" y extendido "/x". Hay algunas cosas más que quizás desee saber sobre los operadores de coincidencia.

Prohibir la sustitución

Si cambia $pattern después de que ocurra la primera sustitución, Perl la ignorará. Si no desea ninguna sustitución en absoluto, utilice el delimitador especial "m''":

@pattern = ('Seuss');
while (<>) {
    print if m'@pattern';  # coincide con el literal '@pattern', no con 'Seuss'
}

De manera similar a las cadenas, "m''" actúa como apóstrofes en una expresión regular; todos los demás delimitadores 'm' actúan como comillas. Si la expresión regular se evalúa como una cadena vacía, se utiliza en su lugar la expresión regular de la *última coincidencia exitosa*. Así tenemos

"dog" =~ /d/;  # 'd' coincide
"dogbert" =~ //;  # esto coincide con la expresión regular 'd' utilizada anteriormente

Coincidencia global

Los dos últimos modificadores que discutiremos aquí, "/g" y "/c", se refieren a múltiples coincidencias. El modificador "/g" significa coincidencia global y permite que el operador de coincidencia coincida dentro de una cadena tantas veces como sea posible. En contexto escalar, las invocaciones sucesivas contra una cadena harán que "/g" salte de coincidencia en coincidencia, manteniendo un registro de la posición en la cadena a medida que avanza. Puede obtener o establecer la posición con la función pos().

El uso de "/g" se muestra en el siguiente ejemplo. Supongamos que tenemos una cadena que consta de palabras separadas por espacios. Si sabemos de antemano cuántas palabras hay, podríamos extraer las palabras usando agrupaciones:

$x = "cat dog house"; # 3 palabras
$x =~ /^\s*(\w+)\s+(\w+)\s+(\w+)\s*$/; # coincide,
                                       # $1 = 'cat'
                                       # $2 = 'dog'
                                       # $3 = 'house'

¿Pero qué pasa si tuviéramos un número indeterminado de palabras? Esta es el tipo de tarea para la que se hizo "/g". Para extraer todas las palabras, forme la expresión regular simple "(\w+)" y recorra todas las coincidencias con "/(\w+)/g":

while ($x =~ /(\w+)/g) {
    print "Palabra es $1, termina en la posición ", pos $x, "\n";
}

imprime

Palabra es cat, termina en la posición 3
Palabra es dog, termina en la posición 7
Palabra es house, termina en la posición 13

Una coincidencia fallida o un cambio en la cadena objetivo reinician la posición. Si no desea que la posición se reinicie después de una coincidencia fallida, agregue "/c", como en "/regexp/gc". La posición actual en la cadena está asociada con la cadena, no con la expresión regular. Esto significa que diferentes cadenas tienen diferentes posiciones y sus respectivas posiciones se pueden establecer o leer de forma independiente.

En contexto de lista, "/g" devuelve una lista de agrupaciones coincidentes, o si no hay agrupaciones, una lista de coincidencias para toda la expresión regular. Entonces, si solo quisiéramos las palabras, podríamos usar

@words = ($x =~ /(\w+)/g);  # coincide,
                            # $words[0] = 'cat'
                            # $words[1] = 'dog'
                            # $words[2] = 'house'

Estrechamente asociado con el modificador "/g" está el ancla "\G". El ancla "\G" coincide en el punto donde la coincidencia "/g" anterior se detuvo. "\G" nos permite hacer fácilmente coincidencias sensibles al contexto:

$metric = 1;  # usar unidades métricas
...
$x = <FILE>;  # leer medida
$x =~ /^([+-]?\d+)\s*/g;  # obtener magnitud
$weight = $1;
if ($metric) { # comprobación de errores
    print "¡Error de unidades!" unless $x =~ /\Gkg\./g;
}
else {
    print "¡Error de unidades!" unless $x =~ /\Glbs\./g;
}
$x =~ /\G\s+(widget|sprocket)/g;  # continuar procesando

La combinación de "/g" y "\G" nos permite procesar la cadena un poco a la vez y usar lógica arbitraria de Perl para decidir qué hacer a continuación.

"\G" también es invaluable para procesar registros de longitud fija con expresiones regulares. Supongamos que tenemos un fragmento de región codificante de ADN, codificado como letras de pares de bases "ATCGTTGAAT..." y queremos encontrar todos los codones de parada "TGA". En una región codificante, los codones son secuencias de 3 letras, por lo que podemos pensar en el fragmento de ADN como una secuencia de registros de 3 letras. La expresión regular ingenua

# expandido, esto es "ATC GTT GAA TGC AAA TGA CAT GAC"
$dna = "ATCGTTGAATGCAAATGACATGAC";
$dna =~ /TGA/;

no funciona; puede coincidir con una "TGA", pero no hay garantía de que la coincidencia esté alineada con los límites de los codones, *por ejemplo*, la subcadena "GTT GAA" da una coincidencia. Una solución mejor es

while ($dna =~ /(\w\w\w)*?TGA/g) {  # nota el *? mínimo
    print "Encontré un codón de parada TGA en la posición ", pos $dna, "\n";
}

que imprime

Encontré un codón de parada TGA en la posición 23

La posición 18 está bien, pero la posición 23 es falsa. ¿Qué pasó?

La respuesta es que nuestra expresión regular funciona bien hasta que pasamos la última coincidencia real. Luego, la expresión regular fallará en coincidir con una "TGA" sincronizada y comenzará a avanzar un carácter a la vez, ¡lo cual no es lo que queremos! La solución es usar "\G" para anclar la coincidencia a la alineación del codón:

while ($dna =~ /\G(\w\w\w)*?TGA/g) {
    print "Encontré un codón de parada TGA en la posición ", pos $dna, "\n";
}

que es la respuesta correcta.

Búsqueda y reemplazo

Las expresiones regulares también juegan un papel importante en las operaciones de búsqueda y reemplazo en Perl. La búsqueda y reemplazo se logra con el operador "s///". La forma general es "s/expresion_regular/reemplazo/modificadores", donde todo lo que sabemos sobre expresiones regulares y modificadores se aplica también en este caso. El reemplazo es una cadena entre comillas dobles de Perl que reemplaza en la cadena todo lo que coincide con la "expresion_regular". El operador "=~" también se utiliza aquí para asociar una cadena con "s///". Si se busca coincidencias contra $_, se puede omitir "$_ =~". Si hay una coincidencia, "s///" devuelve el número de sustituciones realizadas; de lo contrario, devuelve falso. Aquí hay algunos ejemplos:

$x = "¡Es hora de alimentar al gato!";
$x =~ s/gato/hacker/;   # $x contiene "¡Es hora de alimentar al hacker!"
if ($x =~ s/^(Hora.*hacker)!$/$1 ahora!/) {
    $mas_insistente = 1;
}
$y = "'palabras entre comillas'";
$y =~ s/^'(.*)'$/$1/;  # eliminar comillas simples,
                       # $y contiene "palabras entre comillas"

En el último ejemplo, toda la cadena coincidió, pero solo la parte dentro de las comillas simples fue agrupada. Con el operador "s///", las variables coincidentes $1, $2, etc. están inmediatamente disponibles para su uso en la expresión de reemplazo, así que usamos $1 para reemplazar la cadena entre comillas con solo lo que estaba entre comillas. Con el modificador global, "s///g" buscará y reemplazará todas las ocurrencias de la expresión regular en la cadena:

$x = "Bateé 4 de 4";
$x =~ s/4/cuatro/;   # no lo hace todo:
                   # $x contiene "Bateé cuatro de 4"
$x = "Bateé 4 de 4";
$x =~ s/4/cuatro/g;  # lo hace todo:
                   # $x contiene "Bateé cuatro de cuatro"

Si prefiere "regex" en lugar de "regexp" en este tutorial, puede utilizar el siguiente programa para reemplazarlo:

% cat > reemplazo_simple
#!/usr/bin/perl
$expresion_regular = shift;
$reemplazo = shift;
while (<>) {
    s/$expresion_regular/$reemplazo/g;
    print;
}
^D
% reemplazo_simple expresion_regular regex perlretut.pod

En "reemplazo_simple" usamos el modificador "s///g" para reemplazar todas las ocurrencias de la expresión regular en cada línea. (Incluso si la expresión regular aparece en un bucle, Perl es lo suficientemente inteligente como para compilarla solo una vez). Al igual que con "simple_grep", tanto "print" como "s/$expresion_regular/$reemplazo/g" utilizan $_ implícitamente.

Si no desea que "s///" modifique su variable original, puede usar el modificador de sustitución no destructiva, "s///r". Esto cambia el comportamiento de manera que "s///r" devuelve la cadena sustituida final (en lugar del número de sustituciones):

$x = "Me gustan los perros.";
$y = $x =~ s/perros/gatos/r;
print "$x $y\n";

Ese ejemplo imprimirá "Me gustan los perros. Me gustan los gatos". Observe que la variable original $x no ha sido afectada. El resultado general de la sustitución se almacena en $y. Si la sustitución no afecta nada, se devuelve la cadena original:

$x = "Me gustan los perros.";
$y = $x =~ s/elefantes/pumas/r;
print "$x $y\n"; # imprime "Me gustan los perros. Me gustan los perros."

Otra cosa interesante que permite la bandera "s///r" es encadenar sustituciones:

$x = "Los gatos son geniales.";
print $x =~ s/Gatos/Perros/r =~ s/Perros/Ranas/r =~
    s/Ranas/Erizos/r, "\n";
# imprime "Los erizos son geniales."

"s///e" trata el texto de reemplazo como código de Perl, en lugar de una cadena entre comillas dobles. El valor que devuelve el código se sustituye por la subcadena que coincide. la frecuencia de 'i' es 1
la frecuencia de 'a' es 1

Al igual que con el operador de coincidencia "m//", "s///" puede usar otros delimitadores, como "s!!!" y "s{}{}", e incluso "s{}//". Si se usan comillas simples "s'''", entonces la expresión regular y el reemplazo se tratan como cadenas entre comillas simples y no hay sustituciones de variables. "s///" en contexto de lista devuelve lo mismo que en contexto escalar, es decir, el número de coincidencias.

La función split

La función split() es otro lugar donde se usa una expresión regular. "split /expresion_regular/, cadena, limite" separa el operando "cadena" en una lista de subcadenas y devuelve esa lista. La expresión regular debe estar diseñada para coincidir con lo que constituye los separadores para las subcadenas deseadas. El "limite", si está presente, restringe la división a no más de "limite" números de cadenas. Por ejemplo, para dividir una cadena en palabras, use

$x = "Calvin y Hobbes";
@palabras = split /\s+/, $x;  # $palabra[0] = 'Calvin'
                           # $palabra[1] = 'y'
                           # $palabra[2] = 'Hobbes'

Si se usa la expresión regular vacía "//", la expresión regular siempre coincide y la cadena se divide en caracteres individuales. Si la expresión regular tiene agrupaciones, la lista resultante también contendrá las subcadenas coincidentes de las agrupaciones. Por ejemplo,

$x = "/usr/bin/perl";
@directorios = split m!/!, $x;  # $directorios[0] = ''
                         # $directorios[1] = 'usr'
                         # $directorios[2] = 'bin'
                         # $directorios[3] = 'perl'
@partes = split m!(/)!, $x;  # $partes[0] = ''
                            # $partes[1] = '/'
                            # $partes[2] = 'usr'
                            # $partes[3] = '/'
                            # $partes[4] = 'bin'
                            # $partes[5] = '/'
                            # $partes[6] = 'perl'

Dado que el primer carácter de $x coincidió con la expresión regular, "split" antepuso un elemento inicial vacío a la lista.

Más sobre caracteres, cadenas y clases de caracteres

Hay una serie de secuencias de escape y clases de caracteres que aún no hemos cubierto.

Hay varias secuencias de escape que convierten caracteres o cadenas entre mayúsculas y minúsculas, y también están disponibles dentro de los patrones. "\l" y "\u" convierten el siguiente carácter a minúscula o mayúscula, respectivamente:

$x = "perl";
$cadena =~ /\u$x/;  # coincide con 'Perl' en $cadena
$x = "M(rs?|s)\\."; # nota la doble barra invertida
$cadena =~ /\l$x/;  # coincide con 'mr.', 'mrs.', y 'ms.',

Un "\L" o "\U" indica una conversión de mayúsculas/minúsculas duradera, hasta que se termina con "\E" o se interrumpe por otro "\U" o "\L":

$x = "Esta palabra está en minúsculas:\L GRITAR\E";
$x =~ /gritar/;       # coincide
$x = "TODAVÍA TECLO TARJETAS PARA MI 360";
$x =~ /\Uteclado/;  # coincide con la cadena de tarjeta perforada

Si no hay "\E", las mayúsculas/minúsculas se convierten hasta el final de la cadena. Las expresiones regulares "\L\u$palabra" o "\u\L$palabra" convierten el primer carácter de $palabra a mayúscula y el resto de los caracteres a minúscula. (Más allá de los caracteres ASCII, las cosas se complican un poco; "\u" en realidad realiza un mapeo de primera letra mayúscula, que para la mayoría de los caracteres es lo mismo que mayúscula, pero no para todos; ver https://unicode.org/faq/casemap_charprop.html#4.)

Los caracteres de control se pueden escapar con "\c", de modo que un carácter de control-Z coincidiría con "\cZ". La secuencia de escape "\Q"..."\E" comilla, o protege la mayoría de los caracteres no alfabéticos. Por ejemplo,

$x= "\QThat !^*&%~& cat!";
$x =~ /\Q!^*&%~&\E/;  # comprueba lenguaje soez

No protege a '$' ni a '@', de modo que las variables todavía pueden ser sustituidas.

"\Q", "\L", "\l", "\U", "\u" y "\E" son en realidad parte de la sintaxis de comillas dobles, y no de la sintaxis de expresiones regulares propiamente dicha. Funcionarán si aparecen en una expresión regular incrustada directamente en un programa, pero no cuando están contenidas en una cadena que se interpola en un patrón.

Las expresiones regulares de Perl pueden manejar más que solo el conjunto de caracteres ASCII estándar. Perl soporta _Unicode_, un estándar para representar los alfabetos de prácticamente todos los idiomas escritos del mundo, y una gran cantidad de símbolos. Las cadenas de texto de Perl son cadenas Unicode, por lo que pueden contener caracteres con un valor (punto de código o número de carácter) superior a 255.

¿Qué significa esto para las expresiones regulares? Bueno, los usuarios de expresiones regulares no necesitan saber mucho sobre la representación interna de cadenas de Perl. Pero sí necesitan saber 1) cómo representar caracteres Unicode en una expresión regular y 2) que una operación de coincidencia tratará la cadena a buscar como una secuencia de caracteres, no de bytes. La respuesta a 1) es que los caracteres Unicode mayores que chr(255) se representan utilizando la notación "\x{hex}", porque "\x"XY (especificado con dos dígitos hexadecimales sin llaves) no va más allá de 255. (A partir de Perl 5.14, si eres fanático de los octales, también puedes usar "\o{oct}".)

/\x{263a}/;   # coincide con una cara sonriente Unicode :)
/\x{ 263a }/; # Lo mismo

NOTA: En Perl 5.6.0 solía ser necesario decir "use utf8" para usar cualquier característica Unicode. Este ya no es el caso: para casi todo el procesamiento Unicode, el pragmático explícito "utf8" no es necesario. (El único caso en el que importa es si tu script de Perl está en Unicode y codificado en UTF-8, entonces se necesita un explícito "use utf8".)

Descubrir la secuencia hexadecimal de un carácter Unicode que deseas o descifrar la expresión regular Unicode hexadecimal de otra persona es tan divertido como programar en código máquina. Así que otra forma de especificar caracteres Unicode es usar la secuencia de escape de _nombre de carácter_ "\N{nombre}". nombre es un nombre para el carácter Unicode, según lo especificado en el estándar Unicode. Por ejemplo, si quisiéramos representar o hacer coincidir el signo astrológico del planeta Mercurio, podríamos usar

$x = "abc\N{MERCURY}def";
$x =~ /\N{MERCURY}/;   # coincide
$x =~ /\N{ MERCURY }/; # También coincide

También se pueden usar nombres "cortos":

print "\N{GREEK SMALL LETTER SIGMA} se llama sigma.\n";
print "\N{greek:Sigma} es una sigma mayúscula.\n";

También puedes restringir los nombres a un cierto alfabeto especificando el pragmático charnames:

use charnames qw(greek);
print "\N{sigma} es sigma griega\n";

Un índice de nombres de caracteres está disponible en línea del Consorcio Unicode, https://www.unicode.org/charts/charindex.html; material explicativo con enlaces a otros recursos en https://www.unicode.org/standard/where.

A partir de Perl v5.32, hay disponible una alternativa a "\N{...}" para nombres completos, y es decir

/\p{Name=greek small letter sigma}/

La capitalización del nombre del carácter es irrelevante cuando se usa en "\p{}", al igual que la mayoría de los espacios, guiones bajos y guiones. (Algunos caracteres atípicos causan problemas al ignorar todos ellos siempre. Los detalles (que puedes consultar cuando seas más competente, y si alguna vez los necesitas) se encuentran en https://www.unicode.org/reports/tr44/tr44-24.html#UAX44-LM2).

La respuesta al requisito 2) es que una expresión regular (en su mayor parte) utiliza caracteres Unicode. El "en su mayor parte" se debe a razones de compatibilidad con versiones anteriores, pero a partir de Perl 5.14, cualquier expresión regular compilada en el ámbito de un "use feature 'unicode_strings'" (que se activa automáticamente dentro del ámbito de un "use v5.12" o superior) convertirá ese "en su mayor parte" en "siempre". Si deseas manejar Unicode correctamente, debes asegurarte de que 'unicode_strings' esté activado. Internamente, esto se codifica a bytes utilizando UTF-8 o una codificación nativa de 8 bits, dependiendo del historial de la cadena, pero conceptualmente es una secuencia de caracteres, no de bytes. Consulta perlunitut para un tutorial sobre eso.

Discutamos ahora las clases de caracteres Unicode, más comúnmente llamadas "propiedades de caracteres". Estas se representan mediante la secuencia de escape "\p{nombre}". La negación de esto es "\P{nombre}". Por ejemplo, para hacer coincidir caracteres minúsculas y mayúsculas,

$x = "BOB";
$x =~ /^\p{IsUpper}/;   # coincide, clase de caracteres mayúsculos
$x =~ /^\P{IsUpper}/;   # no coincide, clase de caracteres sin mayúsculas
$x =~ /^\p{IsLower}/;   # no coincide, clase de caracteres minúsculos
$x =~ /^\P{IsLower}/;   # coincide, clase de caracteres sin minúsculas

(El "Is" es opcional.)

Existen muchísimas propiedades de caracteres Unicode. Para la lista completa, consulta perluniprops. La mayoría de ellas tienen sinónimos con nombres más cortos, también listados allí. Algunos sinónimos son un solo carácter. Para estos, puedes omitir las llaves. Por ejemplo, "\pM" es lo mismo que "\p{Mark}", lo que significa cosas como acentos.

Las propiedades Unicode "\p{Script}" y "\p{Script_Extensions}" se utilizan para categorizar cada carácter Unicode en el script de idioma en el que está escrito. Por ejemplo, el inglés, el francés y un montón de otros idiomas europeos se escriben en el script latino. Pero también está el script griego, el script tailandés, el script katakana, _etc_. ("Script" es una forma más antigua y menos avanzada de "Script_Extensions", conservada solo por compatibilidad con versiones anteriores). Puedes probar si un carácter está en un script particular con, por ejemplo "\p{Latin}", "\p{Greek}", o "\p{Katakana}". Para probar si no está en el script balinés, usarías "\P{Balinese}". (Todas estas utilizan "Script_Extensions" internamente, ya que proporciona mejores resultados.)

Lo que hemos descrito hasta ahora es la forma simple de las clases de caracteres "\p{...}". También existe una forma compuesta que puedes encontrar. Se ven como "\p{nombre=valor}" o "\p{nombre:valor}" (el signo igual y los dos puntos se pueden usar indistintamente). Estas son más generales que la forma simple, y de hecho la mayoría de las formas simples son solo atajos definidos por Perl para formas compuestas comunes. Por ejemplo, los ejemplos de script del párrafo anterior podrían escribirse equivalente como "\p{Script_Extensions=Latin}", "\p{Script_Extensions:Greek}", "\p{script_extensions=katakana}", y "\P{script_extensions=balinese}" (la capitalización es irrelevante entre las llaves "{}"). Es posible que nunca tengas que usar las formas compuestas, pero a veces es necesario, y su uso puede hacer que tu código sea más fácil de entender.

"\X" es una abreviatura de una clase de caracteres que comprende un _cluster gráfico extendido_ de Unicode. Esto representa un "carácter lógico": lo que parece ser un solo carácter, pero que puede estar representado internamente por más de uno. Como ejemplo, usando los nombres completos de Unicode, p. ej., "A + RING COMBINATORIO" es un cluster gráfico con el carácter base "A" y el carácter combinatorio "RING COMBINATORIO", que se traduce al danés como "A" con el círculo encima, como en la palabra Ångstrom.

Para obtener la información completa y más reciente sobre Unicode, consulta el último estándar Unicode, o el sitio web del Consorcio Unicode https://www.unicode.org

Compilación y guardado de expresiones regulares

En la Parte 1 mencionamos que Perl compila una expresión regular en una secuencia compacta de opcodes. Por lo tanto, una expresión regular compilada es una estructura de datos que se puede almacenar una vez y usar una y otra vez. La comilla de expresión regular "qr//" hace exactamente eso: "qr/cadena/" compila la "cadena" como una expresión regular y transforma el resultado en un formato que se puede asignar a una variable:

$reg = qr/foo+bar?/;  # reg contiene una expresión regular compilada

Luego, $reg se puede usar como una expresión regular:

$x = "fooooba";
$x =~ $reg;     # coincide, igual que /foo+bar?/
$x =~ /$reg/;   # lo mismo, forma alternativa

$reg también se puede interpolar en una expresión regular más grande:

$x =~ /(abc)?$reg/;  # aún coincide

Al igual que con el operador de coincidencia, la comilla de expresión regular puede usar diferentes delimitadores, por ejemplo, "qr!!", "qr{}" o "qr~~". Las comillas como delimitadores ("qr''") inhiben cualquier interpolación.

Las expresiones regulares precompiladas son útiles para crear coincidencias dinámicas que no necesitan recompilarse cada vez que se encuentran. Usando expresiones regulares precompiladas, escribimos un programa "grep_step" que busca una secuencia de patrones, avanzando al siguiente patrón tan pronto como se satisface uno.

% cat > grep_step
#!/usr/bin/perl
# grep_step - coincide con <número> expresiones regulares, una tras otra
# uso: multi_grep <número> regexp1 regexp2 ... archivo1 archivo2 ...
$number = shift;
$regexp[$_] = shift foreach (0..$number-1);
@compiled = map qr/$_/, @regexp;
while ($line = <>) {
    if ($line =~ /$compiled[0]/) {
        print $line;
        shift @compiled;
        last unless @compiled;
    }
}
^D
% grep_step 3 shift print last grep_step
$number = shift;
        print $line;
        last unless @compiled;

Almacenar expresiones regulares precompiladas en un array @compiled nos permite simplemente iterar a través de las expresiones regulares sin ninguna recompilación, ganando así flexibilidad sin sacrificar velocidad.

Composición de expresiones regulares en tiempo de ejecución

El backtracking es más eficiente que los intentos repetidos con diferentes expresiones regulares. Si hay varias expresiones regulares y una coincidencia con cualquiera de ellas es aceptable, entonces es posible combinarlas en un conjunto de alternativas. Si las expresiones individuales son datos de entrada, esto se puede hacer programando una operación de unión. Explotaremos esta idea en una versión mejorada del programa "simple_grep": un programa que coincide con múltiples patrones:

% cat > multi_grep
#!/usr/bin/perl
# multi_grep - coincide con cualquiera de las <número> expresiones regulares
# uso: multi_grep <número> regexp1 regexp2 ... archivo1 archivo2 ...
$number = shift;
$regexp[$_] = shift foreach (0..$number-1);
$pattern = join '|', @regexp;
while ($line = <>) {
    print $line if $line =~ /$pattern/;
}
^D
% multi_grep 2 shift for multi_grep
$number = shift;
$regexp[$_] = shift foreach (0..$number-1);

A veces es ventajoso construir un patrón a partir de la entrada que se va a analizar y usar los valores permitidos en el lado izquierdo de las operaciones de coincidencia. Como ejemplo de esta situación algo paradójica, supongamos que nuestra entrada contiene un verbo de comando que debe coincidir con uno de un conjunto de verbos de comando disponibles, con el giro adicional de que los comandos pueden abreviarse siempre que la cadena dada sea única. El programa a continuación demuestra el algoritmo básico.

% cat > keymatch
#!/usr/bin/perl
$kwds = 'copy compare list print';
while( $cmd = <> ){
    $cmd =~ s/^\s+|\s+$//g;  # recorta espacios iniciales y finales
    if( ( @matches = $kwds =~ /\b$cmd\w*/g ) == 1 ){
        print "command: '@matches'\n";
    } elsif( @matches == 0 ){
        print "no such command: '$cmd'\n";
    } else {
        print "not unique: '$cmd' (could be one of: @matches)\n";
    }
}
^D
% keymatch
li
command: 'list'
co
not unique: 'co' (could be one of: copy compare)
printer
no such command: 'printer'

En lugar de intentar que la entrada coincida con las palabras clave, hacemos que el conjunto combinado de palabras clave coincida con la entrada. La operación de coincidencia de patrones "$kwds =~ /\b($cmd\w*)/g" hace varias cosas al mismo tiempo. Asegura que el comando dado comience donde comienza una palabra clave ("\b"). Tolera abreviaturas debido al "\w*" agregado. Nos dice el número de coincidencias ("scalar @matches") y todas las palabras clave que realmente coincidieron. Difícilmente se podría pedir más.

Incrustación de comentarios y modificadores en una expresión regular

A partir de esta sección, discutiremos el conjunto de patrones extendidos de Perl. Estas son extensiones a la sintaxis tradicional de expresiones regulares que proporcionan herramientas nuevas y potentes para la coincidencia de patrones. Ya hemos visto extensiones en forma de construcciones de coincidencia mínima "??", "*?", "+?", "{n,m}?", "{n,}?" y "{,n}?". La mayoría de las extensiones a continuación tienen la forma "(?char...)", donde "char" es un carácter que determina el tipo de extensión.

La primera extensión es un comentario incrustado "(?#texto)". Esto incrusta un comentario en la expresión regular sin afectar su significado. El comentario no debe tener ningún paréntesis de cierre en el texto. Un ejemplo es

/(?# Coincide con un entero:)[+-]?\d+/;

Este estilo de comentarios ha sido en gran medida reemplazado por los comentarios sin formato y de formato libre que se permiten con el modificador "/x".

La mayoría de los modificadores, como "/i", "/m", "/s" y "/x" (o cualquier combinación de ellos) también se pueden incrustar en una expresión regular usando "(?i)", "(?m)", "(?s)" y "(?x)". Por ejemplo,

/(?i)yes/;  # coincide con 'yes' sin distinguir entre mayúsculas y minúsculas
/yes/i;     # lo mismo
/(?x)(          # versión de formato libre de una expresión regular de enteros
         [+-]?  # coincide con un signo opcional
         \d+    # coincide con una secuencia de dígitos
     )
/x;

Los modificadores incrustados pueden tener dos ventajas importantes sobre los modificadores habituales. Los modificadores incrustados permiten un conjunto personalizado de modificadores para *cada* patrón de expresión regular. Esto es ideal para hacer coincidir un array de expresiones regulares que deben tener modificadores diferentes:

$pattern[0] = '(?i)doctor';
$pattern[1] = 'Johnson';
...
while (<>) {
    foreach $patt (@pattern) {
        print if /$patt/;
    }
}

La segunda ventaja es que los modificadores incrustados (excepto "/p", que modifica toda la expresión regular) solo afectan a la expresión regular dentro del grupo en el que se encuentra el modificador incrustado. Por lo tanto, la agrupación se puede utilizar para localizar los efectos del modificador:

/Answer: ((?i)yes)/;  # coincide con 'Answer: yes', 'Answer: YES', etc.

Los modificadores incrustados también pueden desactivar cualquier modificador presente utilizando, por ejemplo, "(?-i)". Los modificadores también se pueden combinar en una sola expresión, por ejemplo, "(?s-i)" activa el modo de línea única y desactiva la insensibilidad a mayúsculas y minúsculas.

Los modificadores incrustados también se pueden agregar a una agrupación que no captura. "(?i-m:regexp)" es una agrupación que no captura y que coincide con "regexp" sin distinguir entre mayúsculas y minúsculas y desactiva el modo multilínea.

Mirando hacia adelante y hacia atrás

Esta sección trata sobre las aserciones de mirada hacia adelante y hacia atrás. Primero, un poco de contexto.

En las expresiones regulares de Perl, la mayoría de los elementos de la expresión regular "consumen" una cierta cantidad de cadena cuando coinciden. Por ejemplo, el elemento de expresión regular "[abc]" consume un carácter de la cadena cuando coincide, en el sentido de que Perl pasa a la siguiente posición de carácter en la cadena después de la coincidencia. Sin embargo, hay algunos elementos que no consumen caracteres (avanzan la posición del carácter) si coinciden. Los ejemplos que hemos visto hasta ahora son los anclajes. El anclaje '^' coincide con el principio de la línea, pero no consume ningún carácter. Del mismo modo, el anclaje de límite de palabra "\b" coincide donde un carácter que coincide con "\w" está al lado de un carácter que no lo hace, pero no consume ningún carácter por sí mismo. Los anclajes son ejemplos de aserciones de ancho cero: ancho cero, porque no consumen caracteres, y aserciones, porque prueban alguna propiedad de la cadena. En el contexto de nuestro paseo por el bosque análogo a la coincidencia de expresiones regulares, la mayoría de los elementos de expresión regular nos mueven por un sendero, pero los anclajes nos hacen detenernos un momento y observar nuestro entorno. Si el entorno local nos satisface, podemos seguir adelante. Pero si el entorno local no nos satisface, debemos retroceder.

Examinar el entorno implica mirar hacia adelante en el sendero, mirar hacia atrás o ambas cosas. '^' mira hacia atrás, para ver que no hay caracteres delante. '$' mira hacia adelante, para ver que no hay ch

Usando lookahead y lookbehind

Las aserciones de lookahead y lookbehind son generalizaciones del concepto de ancla. El lookahead y el lookbehind son aserciones de ancho cero que nos permiten especificar qué caracteres queremos probar. La aserción de lookahead se denota mediante "(?=regexp)" o (a partir de 5.32, experimentalmente en 5.28) "(*pla:regexp)" o "(*positive_lookahead:regexp)"; y la aserción de lookbehind se denota mediante "(?<=fixed-regexp)" o (a partir de 5.32, experimentalmente en 5.28) "(*plb:fixed-regexp)" o "(*positive_lookbehind:fixed-regexp)". Algunos ejemplos son

$x = "I catch the housecat 'Tom-cat' with catnip";
$x =~ /cat(*pla:\s)/;   # coincide 'cat' en 'housecat'
@catwords = ($x =~ /(?<=\s)cat\w+/g);  # coincide,
                                       # $catwords[0] = 'catch'
                                       # $catwords[1] = 'catnip'
$x =~ /\bcat\b/;  # coincide 'cat' en 'Tom-cat'
$x =~ /(?<=\s)cat(?=\s)/; # no coincide; no hay 'cat' aislado en

El lookahead puede coincidir con regexps arbitrarios, pero el lookbehind anterior a 5.30 "(?<=fixed-regexp)" solo funciona para regexps de ancho fijo, *es decir*, una cantidad fija de caracteres de longitud. Las versiones negadas de las aserciones de lookahead y lookbehind se denotan mediante "(?!regexp)" y "(?<!fixed-regexp)" respectivamente. O, a partir de 5.32 (experimentalmente en 5.28), "(*nla:regexp)", "(*negative_lookahead:regexp)", "(*nlb:regexp)", o "(*negative_lookbehind:regexp)". Evalúan verdadero si los regexps *no* coinciden:

$x = "foobar";

$x =~ /foo(?!baz)/;  # coincide, 'baz' no sigue a 'foo'
$x =~ /(?<!\s)foo/;  # coincide, no hay \s antes de 'foo'

Aquí hay un ejemplo donde una cadena que contiene palabras, números y guiones simples separados por espacios se divide en sus componentes. Usar "/\s+/" solo no funcionará, porque los espacios no son requeridos entre guiones, o una palabra o un guion. $str = "one two - --6-8";

              /x, $str;          # @toks = qw(one two - - - 6 - 8)

Usando subexpresiones independientes para prevenir el backtracking

Las *subexpresiones independientes* (o subexpresiones atómicas) son expresiones regulares, en el contexto de una expresión regular más grande, que funcionan independientemente de la expresión regular más grande. Es decir, consumen tanto o tan poco de la cadena como deseen sin tener en cuenta la capacidad de la regexp más grande para coincidir. Las subexpresiones independientes se representan mediante "(?>regexp)" o (a partir de 5.32, experimentalmente en 5.28) "(*atomic:regexp)". Podemos ilustrar su comportamiento considerando primero una regexp ordinaria:

$x = "ab";
$x =~ /a*ab/;  # coincide

Esto obviamente coincide, pero en el proceso de coincidencia, la subexpresión "a*" primero agarró la 'a'. Hacerlo, sin embargo, no permitiría que la regexp completa coincidiera, por lo que después del backtracking, "a*" finalmente devolvió la 'a' y coincidió con la cadena vacía. Aquí, lo que "a*" coincidió fue *dependiente* de lo que el resto de la regexp coincidió.

Contrasta eso con una subexpresión independiente:

$x =~ /(?>a*)ab/;  # ¡no coincide!

La subexpresión independiente "(?>a*)" no se preocupa por el resto de la regexp, por lo que ve una 'a' y la agarra. Luego el resto de la regexp "ab" no puede coincidir. Debido a que "(?>a*)" es independiente, no hay backtracking y la subexpresión independiente no devuelve su 'a'. Por lo tanto, la coincidencia de la regexp en general falla. Un comportamiento similar ocurre con regexps completamente independientes:

$x = "ab";
$x =~ /a*/g;   # coincide, consume una 'a'
$x =~ /\Gab/g; # no coincide, no hay 'a' disponible

Aquí "/g" y "\G" crean un traspaso de "equipo" de la cadena de una regexp a la otra. Las regexps con una subexpresión independiente son muy parecidas a esto, con un traspaso de la cadena a la subexpresión independiente, y un traspaso de la cadena de vuelta a la regexp envolvente.

La capacidad de una subexpresión independiente para prevenir el backtracking puede ser muy útil. Supongamos que queremos hacer coincidir una cadena no vacía encerrada entre paréntesis hasta dos niveles de profundidad. Entonces la siguiente regexp coincide:

$x = "abc(de(fg)h";  # paréntesis desequilibrados
$x =~ /\( ( [ ^ () ]+ | \( [ ^ () ]* \) )+ \)/xx;

La regexp coincide con un paréntesis de apertura, una o más copias de una alternancia, y un paréntesis de cierre. La alternancia es de dos vías, con la primera alternativa "[^()]+" que coincide con una subcadena sin paréntesis y la segunda alternativa "\([^()]*\)" que coincide con una subcadena delimitada por paréntesis. El problema con esta regexp es que es patológica: tiene cuantificadores indeterminados anidados de la forma "(a+|b)+". Discutimos en la Parte 1 cómo cuantificadores anidados como este podrían llevar un tiempo exponencialmente largo para ejecutarse si no es posible una coincidencia. Para prevenir el desbordamiento exponencial, necesitamos prevenir el backtracking inútil en algún punto. Esto se puede hacer encerrando el cuantificador interno como una subexpresión independiente:

$x =~ /\( ( (?> [ ^ () ]+ ) | \([ ^ () ]* \) )+ \)/xx;

Aquí, "(?>[^()]+)" rompe la degeneración del particionamiento de la cadena al consumir tanto de la cadena como sea posible y retenerla. Entonces, los fallos de coincidencia fallan mucho más rápidamente.

Expresiones condicionales

Una *expresión condicional* es una forma de instrucción if-then-else que permite elegir qué patrones deben coincidir, basándose en alguna condición. Hay dos tipos de expresión condicional: "(?(condición)regexp-si)" y "(?(condición)regexp-si|regexp-no)". "(?(condición)regexp-si)" es como una instrucción 'if () {}' en Perl. Si la *condición* es verdadera, la *regexp-si* coincidirá. Si la *condición* es falsa, la *regexp-si* se omitirá y Perl pasará al siguiente elemento de la regexp. La segunda forma es como una instrucción 'if () {} else {}' en Perl. Si la *condición* es verdadera, la *regexp-si* coincidirá, de lo contrario, la *regexp-no* coincidirá.

La *condición* puede tener varias formas. La primera forma es simplemente un entero entre paréntesis "(entero)". Es verdadera si la referencia posterior correspondiente "\entero" coincidió anteriormente en la regexp. Lo mismo se puede hacer con un nombre asociado a un grupo de captura, escrito como "(<nombre>)" o "('nombre')". La segunda forma es una aserción de ancho cero desnuda "(?...)", ya sea un lookahead, un lookbehind o una aserción de código (discutida en la siguiente sección). El tercer conjunto de formas proporciona pruebas que devuelven verdadero si la expresión se ejecuta dentro de una recursión ("(R)") o se llama desde algún grupo de captura, referenciado por número ("(R1)", "(R2)",...) o por nombre ("(R&nombre)").

La forma de entero o nombre de la *condición* nos permite elegir, con mayor flexibilidad, qué coincidir basándonos en lo que coincidió anteriormente en la regexp. Esto busca palabras de la forma "$x$x" o "$x$y$y$x":

% simple_grep '^(\w+)(\w+)?(?(2)\g2\g1|\g1)$' /usr/dict/words
beriberi
coco
couscous
deed
...
toot
toto
tutu

La condición de lookbehind permite, junto con las referencias posteriores, que una parte anterior de la coincidencia influya en una parte posterior de la coincidencia. Por ejemplo,

/[ATGC]+(?(?<=AA)G|C)$/;

coincide con una secuencia de ADN de tal manera que termina en "AAG", o alguna otra combinación de par de bases y 'C'. Nótese que la forma es "(?(?<=AA)G|C)" y no "(?((?<=AA))G|C)"; para las aserciones de lookahead, lookbehind o de código, los paréntesis alrededor de la condicional no son necesarios.

Patrones recursivos

Esta característica (introducida en Perl 5.10) extiende significativamente la potencia de la coincidencia de patrones de Perl. Al hacer referencia a otro grupo de captura en cualquier lugar del patrón con la construcción "(?ref-grupo)", el patrón dentro del grupo referenciado se utiliza como un subpatrón independiente en lugar de la referencia al grupo en sí. Debido a que la referencia al grupo puede estar contenida dentro del grupo al que se refiere, ahora es posible aplicar la coincidencia de patrones a tareas que hasta ahora requerían un analizador recursivo.

Para ilustrar esta característica, diseñaremos un patrón que coincide si una cadena contiene un palíndromo. (Es una palabra o frase que, ignorando espacios, puntuación y mayúsculas/minúsculas, se lee igual hacia atrás que hacia adelante. Empezamos observando que la cadena vacía o una cadena que contiene solo un carácter de palabra es un palíndromo. De lo contrario, debe tener un carácter de palabra al principio y el mismo al final, con otro palíndromo en el medio.

/(?: (\w) (?...Aquí va un palíndromo...) \g{ -1 } | \w? )/x

Añadiendo "\W*" a cada extremo para eliminar lo que se ignora, ya tenemos el patrón completo:

my $pp = qr/^(\W* (?: (\w) (?1) \g{-1} | \w? ) \W*)$/ix;
for $s ( "saippuakauppias", "A man, a plan, a canal: Panama!" ){
    print "'$s' es un palíndromo\n" if $s =~ /$pp/;
}

En "(?...)" se pueden usar referencias hacia atrás absolutas y relativas. El patrón completo se puede volver a insertar con "(?R)" o "(?0)". Si prefiere nombrar sus grupos, puede usar "(?&nombre)" para recursar en ese grupo.

Un poco de magia: ejecutando código Perl en una expresión regular

Normalmente, las expresiones regulares son parte de las expresiones de Perl. Las expresiones de evaluación de código invierten eso al permitir que código Perl arbitrario sea parte de una expresión regular. Una expresión de evaluación de código se denota "(?{código})", donde código es una cadena de sentencias Perl.

Las expresiones de código son aserciones de ancho cero, y el valor que devuelven depende de su entorno. Hay dos posibilidades: o la expresión de código se utiliza como condición en una expresión condicional "(?(condición)...)", o no lo es. Si la expresión de código es una condición, se evalúa el código y el resultado (es decir, el resultado de la última sentencia) se utiliza para determinar la verdad o falsedad. Si la expresión de código no se utiliza como condición, la aserción siempre evalúa como verdadera y el resultado se coloca en la variable especial $^R. La variable $^R puede ser utilizada entonces en expresiones de código más adelante en la expresión regular. Aquí hay algunos ejemplos tontos:

$x = "abcdef";
$x =~ /abc(?{print "¡Hola Mamá!";})def/; # coincide,
                                     # imprime '¡Hola Mamá!'
$x =~ /aaa(?{print "¡Hola Mamá!";})def/; # no coincide,
                                     # no imprime '¡Hola Mamá!'

Presta mucha atención al siguiente ejemplo:

$x =~ /abc(?{print "¡Hola Mamá!";})ddd/; # no coincide,
                                     # pero _imprime_
                                     # ¿por qué no?

A primera vista, pensarías que no debería imprimir, porque obviamente el "ddd" no va a coincidir con la cadena objetivo. Pero mira este ejemplo:

$x =~ /abc(?{print "¡Hola Mamá!";})[dD]dd/; # no coincide,
                                        # pero SÍ imprime

Hmm. ¿Qué pasó aquí? Si has seguido la explicación, sabes que el patrón anterior debería ser efectivamente (casi) el mismo que el último; encerrar la 'd' en una clase de caracteres no va a cambiar lo que coincide. Entonces, ¿por qué el primero no imprime mientras que el segundo sí?

La respuesta está en las optimizaciones que realiza el motor de expresiones regulares. En el primer caso, todo lo que el motor ve son caracteres normales (aparte de la construcción "?{}"). Es lo suficientemente inteligente como para darse cuenta de que la cadena 'ddd' no aparece en nuestra cadena objetivo antes de ejecutar realmente el patrón. Pero en el segundo caso, lo hemos engañado haciéndole pensar que nuestro patrón es más complicado. Echa un vistazo, ve nuestra clase de caracteres, y decide que tendrá que ejecutar el patrón para determinar si coincide o no, y en el proceso de ejecución llega a la sentencia de impresión antes de descubrir que no tenemos una coincidencia.

Para echar un vistazo más de cerca a cómo el motor realiza las optimizaciones, consulta la sección "Pragmas y depuración" más abajo.

Más diversión con "?{}":

$x =~ /(?{print "¡Hola Mamá!";})/;         # coincide,
                                       # imprime '¡Hola Mamá!'
$x =~ /(?{$c = 1;})(?{print "$c";})/;  # coincide,
                                       # imprime '1'
$x =~ /(?{$c = 1;})(?{print "$^R";})/; # coincide,
                                       # imprime '1'

El truco mencionado en el título de la sección ocurre cuando la expresión regular retrocede en el proceso de búsqueda de una coincidencia. Si la expresión regular retrocede sobre una expresión de código y si las variables utilizadas dentro se localizan usando "local", los cambios en las variables producidos por la expresión de código se deshacen. Por lo tanto, si quisiéramos contar cuántas veces se emparejó un carácter dentro de un grupo, podríamos usar, por ejemplo,

$x = "aaaa";
$count = 0;  # inicializa el contador de 'a'
$c = "bob";  # prueba si $c es sobrescrito

       ( a                        # coincide con 'a'
         (?{local $c = $c + 1;})  # incrementa el contador
       )*                         # haz esto cualquier número de veces,
       aa                         # pero coincide con 'aa' al final
