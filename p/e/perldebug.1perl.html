NOMBRE

perldebug - Depuración de Perl

DESCRIPCIÓN

Primero que nada, ¿ha intentado usar "use strict;" y "use warnings;"?

Si es nuevo en el depurador de Perl, puede preferir leer perldebtut, que es una introducción tutorial al depurador.

Si está buscando los detalles más profundos de cómo se *implementa* el depurador, puede preferir leer perldebguts.

Para detalles técnicos de uso en profundidad, consulte perl5db.pl, la documentación del propio depurador.

El Depurador de Perl

Si invoca Perl con el modificador -d, su script se ejecutará bajo el depurador de código fuente de Perl. Esto funciona como un entorno interactivo de Perl, solicitando comandos del depurador que le permiten examinar el código fuente, establecer puntos de interrupción, obtener rastreos de pila, cambiar los valores de las variables, etc. Esto es tan conveniente que a menudo se inicia el depurador por sí solo solo para probar construcciones de Perl interactivamente y ver qué hacen. Por ejemplo:

$ perl -d -e 42

En Perl, el depurador no es un programa separado como suele ser en el entorno compilado típico. En cambio, el indicador -d le dice al compilador que inserte información de origen en los árboles de análisis que está a punto de entregar al intérprete. Eso significa que su código debe compilar correctamente para que el depurador funcione sobre él. Luego, cuando se inicia el intérprete, precarga un archivo especial de la biblioteca de Perl que contiene el depurador.

El programa se detendrá *justo antes* de la primera sentencia ejecutable en tiempo de ejecución (pero vea abajo con respecto a las sentencias en tiempo de compilación) y le pedirá que ingrese un comando del depurador. Contrariamente a las expectativas populares, cada vez que el depurador se detiene y le muestra una línea de código, siempre muestra la línea que está *a punto* de ejecutar, en lugar de la que acaba de ejecutar.

Cualquier comando que no sea reconocido por el depurador se ejecuta directamente (se hace "eval") como código Perl en el paquete actual. (El depurador utiliza el paquete DB para mantener su propia información de estado).

Tenga en cuenta que dicho "eval" está limitado por un ámbito implícito. Como resultado, cualquier variable léxica recién introducida o cualquier contenido de buffer de captura modificado se pierde después del eval. El depurador es un buen entorno para aprender Perl, pero si experimenta interactivamente con material que debería estar en el mismo ámbito, póngalo en una sola línea.

Para cualquier texto ingresado en el prompt del depurador, los espacios en blanco iniciales y finales se eliminan primero antes de su procesamiento posterior. Si un comando del depurador coincide con alguna función en su propio programa, simplemente preceda la función con algo que no parezca un comando del depurador, como un ";" inicial o quizás un "+", o envolviéndolo con paréntesis o llaves.

Llamar al Depurador

Hay varias formas de llamar al depurador:

perl -d nombre_programa
Sobre el programa dado identificado por "nombre_programa".
perl -d -e 0
Suministrar interactivamente una "expresión" arbitraria usando "-e".
perl -d:ptkdb nombre_programa
Depurar un programa dado a través de la GUI Devel::ptkdb.
perl -dt nombre_programa_con_hilos
Depurar un programa dado usando hilos (experimental).

Si Perl se llama con el modificador "-d", la variable $^P contendrá un valor verdadero. Esto es útil si necesita saber si su código se está ejecutando bajo el depurador:

if ( $^P ) {
    # ejecutándose bajo el depurador
}

Consulte "$^P" en perlvar para obtener más información sobre la variable.

Comandos del Depurador

El depurador interactivo entiende los siguientes comandos:

h
Imprime un resumen de ayuda.
h [comando]
Imprime un mensaje de ayuda para el comando del depurador dado.
h h
El argumento especial de "h h" produce la página de ayuda completa, que es bastante larga.

Si la salida del comando "h h" (o cualquier comando, de hecho) se desplaza más allá de su pantalla, preceda el comando con un símbolo de tubería inicial para que se ejecute a través de su paginador, como en

DB> |h h

Puede cambiar el paginador que se utiliza a través del comando "o pager=...".

p expr
Igual que "print {$DB::OUT} expr" en el paquete actual. En particular, dado que esta es solo la propia función "print" de Perl, esto significa que las estructuras de datos anidadas y los objetos no se vuelcan, a diferencia del comando "x".

El manejador de archivos "DB::OUT" se abre a * /dev/tty *, independientemente de dónde se redirija STDOUT.

x [maxdepth] expr
Evalúa su expresión en contexto de lista y vuelca el resultado de forma bonita. Las estructuras de datos anidadas se imprimen recursivamente, a diferencia de la función "print" real en Perl. Al volcar hashes, probablemente preferirá 'x \%h' en lugar de 'x %h'. Consulte Dumpvalue si desea hacer esto usted mismo.

El formato de salida está gobernado por múltiples opciones descritas en "Opciones Configurables".

Si se incluye "maxdepth", debe ser un número *N*; el valor se vuelca solo *N* niveles de profundidad, como si la opción "dumpDepth" se hubiera establecido temporalmente en *N*.

V [pkg [vars]]
Muestra todas (o algunas) variables en el paquete (por defecto "main") usando un formateador de datos bonito (los hashes muestran sus claves y valores para que vea qué es qué, los caracteres de control se vuelven imprimibles, etc.). Asegúrese de no poner el especificador de tipo (como "$"), solo los nombres de los símbolos, así: 
V DB nombre_archivo numero_linea

Use "~patrón" y "!patrón" para expresiones regulares positivas y negativas.

Esto es similar a llamar al comando "x" en cada var aplicable.

X [vars]
Igual que "V paquete_actual [vars]".
y [nivel [vars]]
Muestra todas (o algunas) variables léxicas (mnemónico: variables "mY") en el ámbito actual o *nivel* ámbitos superiores. Puede limitar las variables que ve con *vars*, que funciona exactamente como lo hace para los comandos "V" y "X". Requiere el módulo PadWalker versión 0.08 o superior; advertirá si no está instalado. La salida se formatea de forma bonita en el mismo estilo que para "V" y el formato está controlado por las mismas opciones.
T
Produce un rastreo de pila. Vea abajo para más detalles sobre su salida.
s [expr]
Paso a paso. Ejecuta hasta el comienzo de otra sentencia, descendiendo en llamadas a subrutinas. Si se proporciona una expresión que incluye llamadas a funciones, también se ejecutará paso a paso.
n [expr]
Siguiente. Ejecuta sobre llamadas a subrutinas, hasta el comienzo de la siguiente sentencia. Si se proporciona una expresión que incluye llamadas a funciones, esas funciones se ejecutarán con paradas antes de cada sentencia.
r
Continúa hasta el retorno de la subrutina actual. Vuelca el valor de retorno si

la opción "PrintRet" está configurada (por defecto).

<CR>
Repite el último comando "n" o "s".
c [línea|sub]
Continúa, insertando opcionalmente un punto de interrupción de un solo uso en la línea o subrutina especificada.
l
Lista la siguiente ventana de líneas.
l min+incr
Lista "incr+1" líneas comenzando en "min".
l min-max
Lista las líneas "min" a "max". "l -" es sinónimo de "-".
l línea
Lista una sola línea.
l nombre_sub
Lista la primera ventana de líneas de la subrutina. nombre_sub puede ser una variable que contenga una referencia de código.
-
Lista la ventana anterior de líneas.
v [línea]
Muestra unas pocas líneas de código alrededor de la línea actual.
.
Devuelve el puntero interno del depurador a la línea ejecutada por última vez, y la imprime.
f nombre_archivo
Cambia a la visualización de un archivo diferente o declaración "eval". Si nombre_archivo no es una ruta completa encontrada en los valores de %INC, se considera una expresión regular.

"eval"uaciones (cuando son accesibles) se consideran nombres de archivo: "f (eval 7)" y "f eval 7\b" acceden al cuerpo de la 7ª cadena "eval"uada (en orden de ejecución). Los cuerpos de la "eval"uación actualmente en ejecución y de las cadenas "eval"uadas que definen subrutinas se guardan y por lo tanto son accesibles.

/patrón/
Busca hacia adelante el patrón (una expresión regular de Perl); la / final es opcional. La búsqueda no distingue entre mayúsculas y minúsculas por defecto.
?patrón?
Busca hacia atrás el patrón; la ? final es opcional. La búsqueda no distingue entre mayúsculas y minúsculas por defecto.
L [abw]
Lista (por defecto todas) las acciones, puntos de interrupción y expresiones de vigilancia.
S [[!]expresión_regular]
Lista nombres de subrutinas [no] coincidentes con la expresión regular.
t [n]
Activa/desactiva el modo de rastreo (ver también la opción "AutoTrace"). El argumento opcional es el número máximo de niveles a rastrear por debajo del actual; cualquier cosa más profunda que eso será silenciosa.
t [n] expr
Rastrea la ejecución de "expr". El primer argumento opcional es el número máximo de niveles a rastrear por debajo del actual; cualquier cosa más profunda que eso será silenciosa. Ver "Ejemplos de Salida de Listado de Marco" en perldebguts para ver ejemplos.
b
Establece un punto de interrupción en la línea actual.
b [línea] [condición]
Establece un punto de interrupción antes de la línea dada. Si se especifica una condición, se evalúa cada vez que se alcanza la sentencia: solo se toma un punto de interrupción si la condición es verdadera. Los puntos de interrupción solo pueden establecerse en líneas que comiencen una sentencia ejecutable. Las condiciones no usan "if": 
b 237 $x > 30
b 237 ++$count237 < 11
b 33 /patrón/i

Si el número de línea es ".", establece un punto de interrupción en la línea actual:

b . $n > 100
b [archivo]:[línea] [condición]
Establece un punto de interrupción antes de la línea dada en un archivo (posiblemente diferente). Si se especifica una condición, se evalúa cada vez que se alcanza la sentencia: solo se toma un punto de interrupción si la condición es verdadera. Los puntos de interrupción solo pueden establecerse en líneas que comiencen una sentencia ejecutable. Las condiciones no usan "if": 
b lib/MiModulo.pm:237 $x > 30
b /usr/lib/perl5/site_perl/CGI.pm:100 ++$count100 < 11
b nombre_sub [condición]
Establece un punto de interrupción antes de la primera línea de la subrutina nombrada. nombre_sub puede ser una variable que contenga una referencia de código (en este caso condición no es compatible).
b postponer nombre_sub [condición]
Establece un punto de interrupción en la primera línea de la subrutina después de que sea compilada.
b cargar nombre_archivo
Establece un punto de interrupción antes de la primera línea ejecutada del nombre_archivo, que debe ser una ruta completa encontrada entre los valores de %INC.
b compilar nombre_sub
Establece un punto de interrupción antes de la primera sentencia ejecutada después de que la subrutina especificada sea compilada.
B línea
Elimina un punto de interrupción de la línea especificada.
B *
Elimina todos los puntos de interrupción instalados.
desactivar [archivo]:[línea]
Desactiva el punto de interrupción para que no detenga la ejecución del programa. Los puntos de interrupción están activados por defecto y pueden ser reactivados usando el comando "enable".
desactivar [línea]
Desactiva el punto de interrupción para que no detenga la ejecución del programa. Los puntos de interrupción están activados por defecto y pueden ser reactivados usando el comando "enable".

Esto se hace para un punto de interrupción en el archivo actual.

activar [archivo]:[línea]
Activa el punto de interrupción para que detenga la ejecución del programa.
activar [línea]
Activa el punto de interrupción para que detenga la ejecución del programa.

Esto se hace para un punto de interrupción en el archivo actual.

a [línea] comando
Establece una acción que se realizará antes de que se ejecute la línea. Si línea se omite, se establece una acción en la línea que está a punto de ejecutarse. La secuencia de pasos que sigue el depurador es 
1. comprueba si hay un punto de interrupción en esta línea
2. imprime la línea si es necesario (rastreo)
3. realiza cualquier acción asociada con esa línea
4. solicita al usuario si está en un punto de interrupción o en modo de un solo paso
5. evalúa la línea

Por ejemplo, esto imprimirá $foo cada vez que se pase por la línea 53:

a 53 print "DB FOUND $foo\n"
A línea
Elimina una acción de la línea especificada.
A *
Elimina todas las acciones instaladas.
w expr
Añade una expresión de vigilancia global. Cada vez que una variable global vigilada cambie, el depurador se detendrá y mostrará los valores antiguo y nuevo.
W expr
Elimina la expresión de vigilancia.
W *
Elimina todas las expresiones de vigilancia.
o
Muestra todas las opciones.
o booloption ...
Establece cada opción booleana listada en el valor 1.
o anyoption? ...
Imprime el valor de una o más opciones.
o option=valor ...
Establece el valor de una o más opciones. Si el valor tiene espacios internos, debe ir entre comillas. Por ejemplo, podría establecer "o pager="less -MQeicsNfr"" para llamar a less con esas opciones específicas. Puede usar comillas simples o dobles, pero si lo hace, debe escapar cualquier instancia incrustada del mismo tipo de comilla con la que comenzó, así como escapar cualquier escape que preceda inmediatamente a esa comilla pero que no pretenda escapar la comilla misma. En otras palabras, sigue las reglas de comillas simples independientemente de la comilla; por ejemplo: "o option='esto no está mal'" o "o option="Ella dijo, \"¿No es así?\""".

Por razones históricas, el "=valor" es opcional, pero por defecto es 1 solo donde es seguro hacerlo, es decir, principalmente para opciones booleanas. Siempre es mejor asignar un valor específico usando "=". La "opción" puede abreviarse, pero para mayor claridad probablemente no debería hacerlo. Se pueden establecer varias opciones juntas. Ver "Opciones Configurables" para una lista de estas.

< ?
Lista todas las acciones de comandos de Perl anteriores al prompt.
< [ comando ]
Establece una acción (comando Perl) que ocurrirá antes de cada prompt del depurador. Un comando multilínea se puede introducir haciendo una barra invertida en los saltos de línea.
< *
Elimina todas las acciones de comandos de Perl anteriores al prompt.
<< comando
Añade una acción (comando Perl) que ocurrirá antes de cada prompt del depurador. Un comando multilínea se puede introducir haciendo una barra invertida en los saltos de línea (apostamos a que no podías haberlo adivinado hasta ahora).
> ?
Lista todas las acciones de comandos de Perl posteriores al prompt.
> comando
Establece una acción (comando Perl) que ocurrirá después del prompt cuando acabas de dar un comando para reanudar la ejecución del script. Un comando multilínea se puede introducir haciendo una barra invertida en los saltos de línea (apostamos a que no podías haberlo adivinado hasta ahora).
> *
Elimina todas las acciones de comandos de Perl posteriores al prompt.
>> comando
Añade una acción (comando Perl) que ocurrirá después del prompt cuando acabas de dar un comando para reanudar la ejecución del script. Un comando multilínea se puede introducir haciendo una barra invertida en los saltos de línea.
{ ?
Lista todos los comandos del depurador anteriores al prompt.
{ [ comando ]
Establece una acción (comando del depurador) que ocurrirá antes de cada prompt del depurador. Un comando multilínea se puede introducir de la manera habitual.

Debido a que este comando es, en cierto sentido, nuevo, se emite una advertencia si parece que ha introducido accidentalmente un bloque en su lugar. Si eso es lo que pretende hacer, escríbalo como con "; { ... }" o incluso "do { ... }".

{ *
Elimina todos los comandos del depurador anteriores al prompt.
{{ comando
Añade una acción (comando del depurador) que ocurrirá antes de cada prompt del depurador. Un comando multilínea se puede introducir, si puedes adivinar cómo: ver arriba.
! número
Repite un comando anterior (por defecto, el comando anterior).
! -número
Repite el n-ésimo comando anterior.
! patrón
Repite el último comando que comenzó con el patrón. Ver "o&#

COMMANDS

recallCommand
Recall last command. Also see "o recallCommand".

In addition to the normal recall of the last command, the debugger also understands the DB::recallCommand function.

!! cmd
Run cmd in a subprocess (reads from DB::IN, writes to DB::OUT) See "o shellBang", also. Note that the user's current shell (well, their $ENV{SHELL} variable) will be used, which can interfere with proper interpretation of exit status or signal and coredump information.
source file
Read and execute debugger commands from file. file may itself contain "source" commands.
H -number
Display last n commands. Only commands longer than one character are listed. If number is omitted, list them all.
q or ^D
Quit. ("quit" doesn't work for this, unless you've made an alias) This is the only supported way to exit the debugger, though typing "exit" twice might work.

Set the "inhibit_exit" option to 0 if you want to be able to step off the end the script. You may also need to set $finished to 0 if you want to step through global destruction.

R
Restart the debugger by exec()ing a new session. We try to maintain your history across this, but internal settings and command-line options may be lost.

The following settings are currently preserved: history, breakpoints, actions, debugger options, and the Perl command-line options -w, -I, and -e.

|dbcmd
Run the debugger command, piping DB::OUT into your current pager.
||dbcmd
Same as "|dbcmd" but DB::OUT is temporarily "select"ed as well.
= [alias value]
Define a command alias, like 
= quit q

or list current aliases.

command
Execute command as a Perl statement. A trailing semicolon will be supplied. If the Perl statement would otherwise be confused for a Perl debugger, use a leading semicolon, too.
m expr
List which methods may be called on the result of the evaluated expression. The expression may be evaluated to a reference to a blessed object, or to a package name.
M
Display all loaded modules and their versions.
man [manpage]
Despite its name, this calls your system's default documentation viewer on the given page, or on the viewer itself if manpage is omitted. If that viewer is man, the current "Config" information is used to invoke man using the proper MANPATH or -M manpath option. Failed lookups of the form "XXX" that match known manpages of the form perlXXX will be retried. This lets you type "man debug" or "man op" from the debugger.

On systems traditionally bereft of a usable man command, the debugger invokes perldoc. Occasionally this determination is incorrect due to recalcitrant vendors or rather more felicitously, to enterprising users. If you fall into either category, just manually set the $DB::doccmd variable to whatever viewer to view the Perl documentation on your system. This may be set in an rc file, or through direct assignment. We're still waiting for a working example of something along the lines of:

$DB::doccmd = 'netscape -remote http://something.here/';

Configurable Options

The debugger has numerous options settable using the "o" command, either interactively or from the environment or an rc file. The file is named ./.perldb or ~/.perldb under Unix with /dev/tty, perldb.ini otherwise.

"recallCommand", "ShellBang"
The characters used to recall a command or spawn a shell. By default, both are set to "!", which is unfortunate.
"pager"
Program to use for output of pager-piped commands (those beginning with a "|" character.) By default, $ENV{PAGER} will be used. Because the debugger uses your current terminal characteristics for bold and underlining, if the chosen pager does not pass escape sequences through unchanged, the output of some debugger commands will not be readable when sent through the pager.
"tkRunning"
Run Tk while prompting (with ReadLine).
"signalLevel", "warnLevel", "dieLevel"
Level of verbosity. By default, the debugger leaves your exceptions and warnings alone, because altering them can break correctly running programs. It will attempt to print a message when uncaught INT, BUS, or SEGV signals arrive. (But see the mention of signals in "BUGS" below.)

To disable this default safe mode, set these values to something higher than 0. At a level of 1, you get backtraces upon receiving any kind of warning (this is often annoying) or exception (this is often valuable). Unfortunately, the debugger cannot discern fatal exceptions from non-fatal ones. If "dieLevel" is even 1, then your non-fatal exceptions are also traced and unceremoniously altered if they came from "eval'ed" strings or from any kind of "eval" within modules you're attempting to load. If "dieLevel" is 2, the debugger doesn't care where they came from: It usurps your exception handler and prints out a trace, then modifies all exceptions with its own embellishments. This may perhaps be useful for some tracing purposes, but tends to hopelessly destroy any program that takes its exception handling seriously.

"AutoTrace"
Trace mode (similar to "t" command, but can be put into "PERLDB_OPTS").
"LineInfo"
File or pipe to print line number info to. If it is a pipe (say, "|visual_perl_db"), then a short message is used. This is the mechanism used to interact with a client editor or visual debugger, such as the special "vi" or "emacs" hooks, or the "ddd" graphical debugger.
"inhibit_exit"
If 0, allows stepping off the end of the script.
"PrintRet"
Print return value after "r" command if set (default).
"ornaments"
Affects screen appearance of the command line (see Term::ReadLine). There is currently no way to disable these, which can render some output illegible on some displays, or with some pagers. This is considered a bug.
"frame"
Affects the printing of messages upon entry and exit from subroutines. If "frame & 2" is false, messages are printed on entry only. (Printing on exit might be useful if interspersed with other messages.)

If "frame & 4", arguments to functions are printed, plus context and caller info. If "frame & 8", overloaded "stringify" and "tie"d "FETCH" is enabled on the printed arguments. If "frame & 16", the return value from the subroutine is printed.

The length at which the argument list is truncated is governed by the next option:

"maxTraceLen"
Length to truncate the argument list when the "frame" option's bit 4 is set.
"windowSize"
Change the size of code list window (default is 10 lines).

The following options affect what happens with "V", "X", and "x" commands:

"arrayDepth", "hashDepth"
Print only first N elements ('' for all).
"dumpDepth"
Limit recursion depth to N levels when dumping structures. Negative values are interpreted as infinity. Default: infinity.
"compactDump", "veryCompact"
Change the style of array and hash output. If "compactDump", short array may be printed on one line.
"globPrint"
Whether to print contents of globs.
"DumpDBFiles"
Dump arrays holding debugged files.
"DumpPackages"
Dump symbol tables of packages.
"DumpReused"
Dump contents of "reused" addresses.
"quote", "HighBit", "undefPrint"
Change the style of string dump. The default value for "quote" is "auto"; one can enable double-quotish or single-quotish format by setting it to """ or "'", respectively. By default, characters with their high bit set are printed verbatim.
"UsageOnly"
Rudimentary per-package memory usage dump. Calculates total size of strings found in variables in the package. This does not include lexicals in a module's file scope, or lost in closures.
"HistFile"
The path of the file from which the history (assuming a usable Term::ReadLine backend) will be read on the debugger's startup, and to which it will be saved on shutdown (for persistence across sessions). Similar in concept to Bash's ".bash_history" file.
"HistSize"
The count of the saved lines in the history (assuming "HistFile" above).

After the rc file is read, the debugger reads the $ENV{PERLDB_OPTS} environme

nt variable y analiza esto como el resto de una línea "O ..." como se podría introducir en el indicador del depurador. Puede colocar las opciones de inicialización "TTY", "noTTY", "ReadLine" y "NonStop" allí.

Si su archivo rc contiene:

parse_options("NonStop=1 LineInfo=db.out AutoTrace");

entonces su script se ejecutará sin intervención humana, colocando la información de rastreo en el archivo db.out. (Si lo interrumpe, será mejor que restablezca "LineInfo" a /dev/tty si espera ver algo).

"TTY"
La TTY a usar para la E/S de depuración.
"noTTY"
Si está configurado, el depurador entra en modo "NonStop" y no se conectará a una TTY. Si se interrumpe (o si el control va al depurador a través de la configuración explícita de $DB::signal o $DB::single desde el script Perl), se conecta a una TTY especificada en la opción "TTY" al inicio, o a una tty encontrada en tiempo de ejecución usando el módulo "Term::Rendezvous" de su elección.

Este módulo debe implementar un método llamado "new" que devuelva un objeto con dos métodos: "IN" y "OUT". Estos deben devolver filehandles para usar para la entrada y salida de depuración respectivamente. El método "new" debe inspeccionar un argumento que contenga el valor de $ENV{PERLDB_NOTTY} al inicio, o "$ENV{HOME}/.perldbtty$$" de lo contrario. Este archivo no se inspecciona en busca de propiedad adecuada, por lo que teóricamente son posibles riesgos de seguridad.

"ReadLine"
Si es falso, la compatibilidad con readline en el depurador se deshabilita para depurar aplicaciones que utilizan ReadLine.
"NonStop"
Si está configurado, el depurador entra en modo no interactivo hasta que se interrumpe, o programáticamente al establecer $DB::signal o $DB::single.

Aquí hay un ejemplo de uso de la variable $ENV{PERLDB_OPTS}:

$ PERLDB_OPTS="NonStop frame=2" perl -d myprogram

Eso ejecutará el script myprogram sin intervención humana, imprimiendo el árbol de llamadas con puntos de entrada y salida. Tenga en cuenta que "NonStop=1 frame=2" es equivalente a "N f=2", y que originalmente, las opciones podían abreviarse de forma única por la primera letra (módulo las opciones "Dump*"). Sin embargo, se recomienda que siempre las escriba completamente para mayor legibilidad y compatibilidad futura.

Otros ejemplos incluyen

$ PERLDB_OPTS="NonStop LineInfo=listing frame=2" perl -d myprogram

que ejecuta el script de forma no interactiva, imprimiendo información sobre cada entrada a una subrutina y cada línea ejecutada en el archivo llamado listing. (Si lo interrumpe, ¡será mejor que restablezca "LineInfo" a algo "interactivo"!).

Otros ejemplos incluyen (usando la sintaxis estándar del shell para mostrar la configuración de variables de entorno):

$ ( PERLDB_OPTS="NonStop frame=1 AutoTrace LineInfo=tperl.out"
    perl -d myprogram )

que puede ser útil para depurar un programa que utiliza Term::ReadLine en sí mismo. No olvide desconectar su shell de la TTY en la ventana que corresponde a /dev/ttyXX, por ejemplo, emitiendo un comando como

$ sleep 1000000

Ver "Debugger Internals" en perldebguts para más detalles.

Entrada/Salida del Depurador

Prompt
El prompt del depurador es algo como 
DB<8>

o incluso

DB<<17>>

donde ese número es el número de comando, y que usaría para acceder con el mecanismo de historial incorporado similar a csh. Por ejemplo, "!17" repetiría el comando número 17. La profundidad de los corchetes angulares indica la profundidad de anidamiento del depurador. Podría obtener más de un conjunto de corchetes, por ejemplo, si ya estuviera en un punto de interrupción y luego imprimiera el resultado de una llamada a una función que a su vez tiene un punto de interrupción, o si entrara en una expresión a través del comando "s/n/t expression".

Comandos multilínea
Si desea introducir un comando multilínea, como una definición de subrutina con varias sentencias o un formato, escape el salto de línea que normalmente finalizaría el comando del depurador con una barra invertida. Aquí hay un ejemplo: 
DB<1> for (1..4) {         \
cont:     print "ok\n";   \
cont: }
ok
ok
ok
ok

Tenga en cuenta que este asunto de escapar un salto de línea es específico de los comandos interactivos escritos en el depurador.

Retroceso de la pila
Aquí hay un ejemplo de cómo podría verse un retroceso de la pila a través del comando "T": 
$ = main::infested llamado desde el archivo 'Ambulation.pm' línea 10
@ = Ambulation::legs(1, 2, 3, 4) llamado desde el archivo 'camel_flea'
                                                         línea 7
$ = main::pests('bactrian', 4) llamado desde el archivo 'camel_flea'
                                                         línea 4

El carácter de la izquierda indica el contexto en el que se llamó a la función, con "$" y "@" significando contextos escalar o de lista respectivamente, y "." significando contexto vacío (que es en realidad una especie de contexto escalar). La visualización anterior dice que estaba en la función "main::infested" cuando ejecutó el volcado de la pila, y que fue llamada en contexto escalar desde la línea 10 del archivo Ambulation.pm, pero sin ningún argumento, lo que significa que fue llamada como &infested. El siguiente marco de la pila muestra que la función "Ambulation::legs" fue llamada en contexto de lista desde el archivo camel_flea con cuatro argumentos. El último marco de la pila muestra que "main::pests" fue llamada en contexto escalar, también desde camel_flea, pero desde la línea 4.

Si ejecuta el comando "T" dentro de una instrucción "use" activa, el retroceso contendrá un marco de "require" y un marco de "eval".

Formato de listado de línea
Esto muestra los tipos de salida que puede producir el comando "l": 
  DB<<13>> l
101:        @i{@i} = ();
102:b       @isa{@i,$pack} = ()
103             if(exists $i{$prevpack} || exists $isa{$pack});
104     }
105
106     next
107==>      if(exists $isa{$pack});
108
109:a   if ($extra-- > 0) {
110:        %isa = ($pack,1);

Las líneas rompibles están marcadas con ":". Las líneas con puntos de interrupción están marcadas por "b" y aquellas con acciones por "a". La línea que está a punto de ejecutarse está marcada por "==>".

Tenga en cuenta que el código en los listados del depurador puede no verse igual que su código fuente original. Las directivas de línea y los filtros de origen externos pueden alterar el código antes de que Perl lo vea, haciendo que el código se mueva de sus posiciones originales o tome formas completamente diferentes.

Listado de marcos
Cuando la opción "frame" está configurada, el depurador imprimiría las subrutinas ingresadas (y opcionalmente salientes) en diferentes estilos. Ver perldebguts para ejemplos increíblemente largos de esto.

Depuración de sentencias en tiempo de compilación

Si tiene sentencias ejecutables en tiempo de compilación (como código dentro de bloques BEGIN, UNITCHECK y CHECK o sentencias "use"), estas *no* serán detenidas por el depurador, aunque "require"s y bloques INIT lo harán, y las sentencias en tiempo de compilación se pueden rastrear con la opción "AutoTrace" configurada en "PERLDB_OPTS"). Sin embargo, desde su propio código Perl, puede transferir el control de vuelta al depurador usando la siguiente sentencia, que es inofensiva si el depurador no se está ejecutando:

$DB::single = 1;

Si establece $DB::single a 2, es equivalente a haber escrito el comando "n", mientras que un valor de 1 significa el comando "s". La variable $DB::trace debe establecerse a 1 para simular haber escrito el comando "t".

Otra forma de depurar código en tiempo de compilación es iniciar el depurador, establecer un punto de interrupción en la carga de algún módulo:

  DB<7> b load f:/perllib/lib/Carp.pm
Will stop on load of 'f:/perllib/lib/Carp.pm'.

y luego reiniciar el depurador usando el comando "R" (si es posible). Se puede usar "b compile subname" para el mismo propósito.

Personalización del Depurador

El depurador probablemente contiene suficientes ganchos de configuración como para que nunca necesite modificarlo usted mismo. Puede cambiar el comportamiento del depurador desde dentro del depurador usando su comando "o", desde la línea de comandos a través de la variable de entorno "PERLDB_OPTS", y desde archivos de personalización.

NAME

perldebug - Perl debugger

DESCRIPTION

The Perl debugger is a tool that allows you to step through your Perl code, examine variables, and otherwise debug your programs.

The Perl Debugger

You invoke the Perl debugger by passing the "-d" switch to Perl:

$ perl -d your_script.pl

This will start the debugger, stopping at the first line of your script. You can then use commands to control execution and inspect the state of your program. Some of the most common commands include:

  • b [line|sub] - Set a breakpoint.
  • c - Continue execution until the next breakpoint.
  • n - Execute the next line.
  • s - Step into a subroutine call.
  • p expression - Print the value of an expression.
  • l - List source code around the current line.
  • q - Quit the debugger.

For a full list of commands, type "h" at the debugger prompt.

The debugger can be customized by creating a .perldb file in your home directory or the current directory. This file is a Perl script that is executed when the debugger starts.

For example, you can add aliases or set options in your .perldb file:

$DB::alias{'h'}   = 'h'; # Alias for help
$DB::alias{'ps'}   = 's/^ps\b/p scalar /';
$DB::alias{'quit'} = 's/^quit(\s*)/exit/';

You can change options from .perldb by using calls like this one;

parse_options("NonStop=1 LineInfo=db.out AutoTrace=1 frame=2");

The code is executed in the package "DB". Note that .perldb is processed before processing "PERLDB_OPTS". If .perldb defines the subroutine "afterinit", that function is called after debugger initialization ends. .perldb may be contained in the current directory, or in the home directory. Because this file is sourced in by Perl and may contain arbitrary commands, for security reasons, it must be owned by the superuser or the current user, and writable by no one but its owner.

You can mock TTY input to debugger by adding arbitrary commands to @DB::typeahead. For example, your .perldb file might contain:

sub afterinit { push @DB::typeahead, "b 4", "b 6"; }

Which would attempt to set breakpoints on lines 4 and 6 immediately after debugger initialization. Note that @DB::typeahead is not a supported interface and is subject to change in future releases.

If you want to modify the debugger, copy perl5db.pl from the Perl library to another name and hack it to your heart's content. You'll then want to set your "PERL5DB" environment variable to say something like this:

BEGIN { require "myperl5db.pl" }

As a last resort, you could also use "PERL5DB" to customize the debugger by directly setting internal variables or calling debugger functions.

Note that any variables and functions that are not documented in this document (or in perldebguts) are considered for internal use only, and as such are subject to change without notice.

Readline Support / History in the Debugger

As shipped, the only command-line history supplied is a simplistic one that checks for leading exclamation points. However, if you install the Term::ReadKey and one of the "Term::ReadLine::*" modules from CPAN (such as Term::ReadLine::Gnu, Term::ReadLine::Perl, ...) you will have full editing capabilities much like those GNU readline(3) provides. Look for these in the modules/by-module/Term directory on CPAN. These do not support normal vi command-line editing, however.

A rudimentary command-line completion is also available, including lexical variables in the current scope if the PadWalker module is installed.

Without Readline support you may see the symbols "^[[A", "^[[C", "^[[B", "^[[D"", "^H", ... when using the arrow keys and/or the backspace key.

Editor Support for Debugging

If you have the GNU's version of emacs installed on your system, it can interact with the Perl debugger to provide an integrated software development environment reminiscent of its interactions with C debuggers.

Recent versions of Emacs come with a start file for making emacs act like a syntax-directed editor that understands (some of) Perl's syntax. See perlfaq3.

Users of vi should also look into vim and gvim, the mousey and windy version, for coloring of Perl keywords.

Note that only perl can truly parse Perl, so all such CASE tools fall somewhat short of the mark, especially if you don't program your Perl as a C programmer might.

The Perl Profiler

If you wish to supply an alternative debugger for Perl to run, invoke your script with a colon and a package argument given to the -d flag. Perl's alternative debuggers include a Perl profiler, Devel::NYTProf, which is available separately as a CPAN distribution. To profile your Perl program in the file mycode.pl, just type:

$ perl -d:NYTProf mycode.pl

When the script terminates the profiler will create a database of the profile information that you can turn into reports using the profiler's tools. See <perlperf> for details.

Debugging Regular Expressions

"use re 'debug'" enables you to see the gory details of how the Perl regular expression engine works. In order to understand this typically voluminous output, one must not only have some idea about how regular expression matching works in general, but also know how Perl's regular expressions are internally compiled into an automaton. These matters are explored in some detail in "Debugging Regular Expressions" in perldebguts.

Debugging Memory Usage

Perl contains internal support for reporting its own memory usage, but this is a fairly advanced concept that requires some understanding of how memory allocation works. See "Debugging Perl Memory Usage" in perldebguts for the details.

BUGS

You cannot get stack frame information or in any fashion debug functions that were not compiled by Perl, such as those from C or C++ extensions.

If you alter your @_ arguments in a subroutine (such as with "shift" or "pop"), the stack backtrace will not show the original values.

The debugger does not currently work in conjunction with the -W command-line switch, because it itself is not free of warnings.

If you're in a slow syscall (like "wait"ing, "accept"ing, or "read"ing from your keyboard or a socket) and haven't set up your own $SIG{INT} handler, then you won't be able to CTRL-C your way back to the debugger, because the debugger's own $SIG{INT} handler doesn't understand that it needs to raise an exception to longjmp(3) out of slow syscalls.
