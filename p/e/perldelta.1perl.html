PERLDELTA(1perl) Guía de referencia para programadores de Perl PERLDELTA(1perl)

NOMBRE

perldelta - qué hay de nuevo en perl v5.42.0

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.42.0 y la versión 5.40.0.

Mejoras del núcleo

Más subrutinas CORE::

"chdir" se ha añadido como subrutina al espacio de nombres "CORE::".

Anteriormente, código como &CORE::chdir($dir) o my $ref = \&CORE::chdir; $ref->($dir) lanzaba un error diciendo "&CORE::chdir no se puede llamar directamente". Estos casos ahora están completamente soportados.

Nuevo pragma "source::encoding"

Esto permite declarar que la porción de un programa para el resto del ámbito léxico de este pragma está codificada completamente en ASCII (para "use source::encoding 'ascii'") o si también se permite UTF-8 (para "use source::encoding 'utf8'"). No se aceptan otras codificaciones. La segunda forma es completamente equivalente a "use utf8" y puede ser usada indistintamente con ella.

El propósito de este pragma es detectar casos tempranos donde olvidaste especificar "use utf8".

"use source::encoding 'ascii'" se habilita automáticamente dentro del ámbito léxico de un "use v5.41.0" o superior.

"no source::encoding" desactiva toda esta verificación para el resto de su ámbito léxico. El significado de los caracteres no ASCII se define entonces como indefinido.

Nuevo atributo ":writer" en variables de campo

Las clases definidas usando "use feature 'class'" ahora pueden crear automáticamente accesores de escritura para campos escalares, usando el atributo ":writer", de manera similar a cómo ":reader" ya crea accesores de lectura.

class Point {
    field $x :reader :writer :param;
    field $y :reader :writer :param;
}
my $p = Point->new( x => 20, y => 40 );
$p->set_x(60);

Nuevos operadores "any" y "all"

Se han añadido dos nuevas características experimentales, que introducen los operadores de procesamiento de listas "any" y "all".

use v5.42;
use feature 'keyword_all';
no warnings 'experimental::keyword_all';
my @numbers = ...
if ( all { $_ % 2 == 0 } @numbers ) {
    say "Todos los números son pares";
}

Estas palabras clave operan de manera similar a "grep", excepto que solo devuelven verdadero o falso, probando si alguno (o todos) de los elementos de la lista hacen que el bloque de prueba devuelva verdadero. Debido a esto, pueden cortocircuitar, evitando la necesidad de probar elementos adicionales si un elemento dado determina el resultado final.

Están inspirados en las funciones del mismo nombre del módulo List::Util, excepto que están implementados como operadores centrales directos y, por lo tanto, rinden más rápido y no producen un marco de pila de llamadas de subrutina adicional para invocar el bloque de código.

Las banderas de características que habilitan esas palabras clave se han denominado "keyword_any" y "keyword_all" para evitar confusiones con la capacidad del módulo "feature" de referirse a todas sus características usando la etiqueta de exportación ":all". [GH #23104 https://github.com/Perl/perl5/issues/23104]

Las banderas de advertencia experimentales relacionadas se denominan consecuentemente "experimental::keyword_any" y "experimental::keyword_all".

La apóstrofe como separador de nombres globales puede deshabilitarse

Esto fue desaprobado en Perl 5.38 y eliminado según lo programado en perl 5.41.3, pero después de algunas discusiones ha sido reinstaurado por defecto.

Esto se puede controlar con la característica "apostrophe_as_package_separator", que está habilitada por defecto, pero está deshabilitada en los paquetes de características de 5.41 en adelante.

Si deseas deshabilitar su uso en tu propio código, puedes deshabilitar explícitamente la característica:

no feature "apostrophe_as_package_separator";

Ten en cuenta que deshabilitar esta característica solo evita el uso de la apóstrofe como separador de paquetes dentro del código; las referencias simbólicas todavía tratan "'" como "::" con la característica deshabilitada:

my $symref = "My'Module'Var";
# características por defecto
my $x = $My'Module'Var; # bien
no feature "apostrophe_as_package_separator";
no strict "refs";
my $y = $$symref;       # como $My::Module::Var
my $z = $My'Module'Var; # error de sintaxis

[GH #22644 https://github.com/Perl/perl5/issues/22644]

Declaración léxica de métodos usando "my method"

Al igual que "sub" desde la versión 5.18 de Perl, "method" ahora puede ir precedido por la palabra clave "my". Esto declara una subrutina que tiene visibilidad léxica, en lugar de visibilidad de paquete. Ver perlclass para más detalles.

Operador de invocación de método léxico "->&"

Además de la capacidad de declarar métodos léxicamente, esta versión también permite invocar una subrutina léxica como si fuera un método, omitiendo la resolución de métodos habitual basada en nombres.

Combinadas con la declaración léxica de métodos, estas dos nuevas capacidades crean el efecto de tener métodos privados.

Operador Switch y Smart Match se mantienen, detrás de una característica

La característica "switch" y el operador smartmatch, "~~", se introdujeron en v5.10. Su comportamiento cambió significativamente en v5.10.1. Cuando se añadió el sistema de "experimento" en v5.18.0, switch y smartmatch se declararon experimentalmente de forma retroactiva. A lo largo de los años, han surgido propuestas para arreglar o complementar las características.

Fueron desaprobados en Perl v5.38.0 y programados para su eliminación en Perl v5.42.0. Después de una extensa discusión, su eliminación se ha pospuesto indefinidamente. Su uso ya no produce una advertencia de desaprobación.

Switch en sí todavía requiere la característica "switch", que está habilitada por defecto para paquetes de características desde v5.9.5 hasta v5.34. Switch permanece deshabilitado en paquetes de características 5.35 y posteriores, pero se puede habilitar por separado:

# sin switch aquí
use v5.10;
# con switch aquí
use v5.36;
# sin switch aquí
use feature "switch";
# con switch aquí

Smart match ahora requiere la característica "smartmatch", que está habilitada por defecto y incluida en todos los paquetes de características hasta 5.40. Está deshabilitada para el paquete de características 5.41 y posteriores, pero se puede habilitar por separado:

# con smartmatch aquí
use v5.41;
# sin smartmatch aquí
use feature "smartmatch";
# con smartmatch aquí

Perl 5.40.0 introdujo el operador exclusivo lógico de precedencia media "^^". En ese momento no se notó que la variante de asignación "^^=" también faltaba. Ahora se ha añadido.

Seguridad

[CVE-2024-56406] Vulnerabilidad de desbordamiento de búfer en el heap con tr//

Se descubrió una vulnerabilidad de desbordamiento de búfer en el heap en Perl.

Cuando hay bytes no ASCII en el lado izquierdo del operador "tr", S_do_trans_invmap() puede desbordar el puntero de destino "d".

$ perl -e '$_ = "\x{FF}" x 1000000; tr/\xFF/\x{100}/;'
Segmentation fault (core dumped)

Se cree que esta vulnerabilidad puede permitir ataques de Denegación de Servicio o Ejecución de Código Arbitrario en plataformas que carecen de defensas suficientes.

Este problema fue descubierto por Nathan Mills y asignado [CVE-2024-56406 https://lists.security.metacpan.org/cve-announce/msg/28708725/] por el Grupo de Seguridad de CPAN https://security.metacpan.org/.

El parche para solucionar este problema (87f42aa0e0096e9a346c9672aa3a0bd3bef8c1dd https://github.com/Perl/perl5/commit/87f42aa0e0096e9a346c9672aa3a0bd3bef8c1dd) es aplicable a todas las versiones de perl vulnerables, incluidas las que ya no tienen soporte.

[CVE-2025-40909] Las hilos de Perl tienen una condición de carrera en el directorio de trabajo donde las operaciones de archivo pueden apuntar a rutas no deseadas

La clonación de hilos de Perl tenía una condición de carrera en el directorio de trabajo donde las operaciones de archivo podían apuntar a rutas no deseadas. Perl 5.42 ya no cambiará el directorio (`chdir`) a cada manejador.

Este problema fue descubierto por Vincent Lefèvre a través de [GH #23010 https://github.com/Perl/perl5/issues/23010] y asignado [CVE-2025-40909 https://lists.security.metacpan.org/cve-announce/msg/30017499/] por el Grupo de Seguridad de CPAN https://security.metacpan.org/.

Se proporcionaron correcciones a través de [GH #23019 https://github.com/Perl/perl5/pull/23019] y [GH #23361 https://github.com/Perl/perl5/pull/23361].

Cambios Incompatibles

Se eliminaron las referencias a la función contenedora para funciones sin eval

Perl 5.40 reintrodujo referencias incondicionales de funciones a sus funciones contenedoras para corregir un error introducido en Perl 5.18 que rompía el comportamiento especial de "eval EXPR" en el paquete "DB", que es utilizado por el depurador.

En algunos casos, este cambio provocó cadenas de referencias circulares entre cierres y otras referencias existentes, lo que resultó en fugas de memoria.

Este cambio ha sido revertido, corrigiendo [GH #22547 https://github.com/Perl/perl5/issues/22547] pero volviendo a romper [GH #19370 https://github.com/Perl/perl5/issues/19370].

Esto significa que los bucles de referencia no ocurrirán, y que las variables léxicas y las funciones de funciones envolventes pueden no ser visibles en el depurador.

Tenga en cuenta que llamar a "eval EXPR" en una función provoca incondicionalmente que una función referencie sus funciones envolventes, como siempre lo ha hecho.

Mejoras de Rendimiento

  • Las cadenas plegadas por constantes ahora se pueden compartir a través del mecanismo de Copia en Escritura (Copy-on-Write). [GH #22163 https://github.com/Perl/perl5/pull/22163]

    El siguiente código habría asignado previamente once búferes de cadena, cada uno conteniendo un millón de "A":

    my @scalars; push @scalars, ("A" x 1_000_000) for 0..9;

    Ahora se asigna un único búfer y se comparte entre una constante OP y los diez elementos escalares de @scalars.

    Tenga en cuenta que cualquier código que utilice este tipo de constante para simular fugas de memoria (quizás en archivos de prueba) debe ahora permutar la cadena para activar una copia de la cadena y la asignación de búferes separados. Por ejemplo, "("A" x 1_000_000).time" podría ser un cambio pequeño y adecuado.

  • "tr///" ahora se ejecuta a la misma velocidad independientemente de la representación interna de su operando, siempre que los únicos caracteres que se traduzcan sean del rango ASCII, por ejemplo "tr/A-Z/a-z/". Anteriormente, si la codificación interna era UTF-8, se utilizaba una implementación más lenta y general.
  • El código que utiliza la función "indexed" del módulo incorporado para generar una lista de pares índice/valor a partir de un array o lista que luego se pasa a un "foreach" de dos variables para desempaquetarlos nuevamente, ahora está optimizado para ser más eficiente. 
    my @array = (...);
foreach my ($idx, $val) (builtin::indexed @array) {
    ...
}

    foreach my ($idx, $val) (builtin::indexed LIST...) {
    ...
}

    En particular, ya no se genera una lista temporal del doble del tamaño de la original. En su lugar, el bucle itera directamente sobre el array o lista original en su lugar, de la misma manera que lo harían "foreach (@array)" o "foreach (LIST)".

  • El optimizador "peephole" reconoce los siguientes patrones de "substr" con desplazamiento cero y los intercambia por un nuevo operador dedicado ("OP_SUBSTR_LEFT"). [GH #22785 https://github.com/Perl/perl5/issues/22785] 
    substr($x, 0, ...)
substr($x, 0, ..., '')
  • La conversión a cadena de enteros por "print" en perlfunc y "say" en perlfunc, cuando provienen de un "SVt_IV", es ahora más eficiente. [GH #22927 https://github.com/Perl/perl5/issues/22927]
  • La inversión de cadenas a partir de un solo argumento, cuando el búfer de cadena no está "barrido", ahora se realiza en un solo paso y es notablemente más rápido. El alcance de la mejora depende del compilador y del hardware. [GH #23012 https://github.com/Perl/perl5/issues/23012]

    Nuevos Diagnósticos

    Nuevos Errores

    • Uso de carácter no ASCII 0x%X ilegal cuando 'use source::encoding "ascii"' está en efecto

      (F) Esta pragmática prohíbe caracteres no ASCII dentro de su alcance.

    • Subrutina indefinida &%s llamada, cerca de la etiqueta '%s'

      (F) La subrutina indicada no ha sido definida, o si lo fue, ha sido indefinida desde entonces.

      Este error también podría indicar un separador de paquete mal escrito, cuando se escribió un solo dos puntos en lugar de dos. Por ejemplo, Foo:bar() se analizaría como la etiqueta "Foo" seguida de un nombre de función no calificado: "foo: bar()". [GH #22860 https://github.com/Perl/perl5/issues/22860]

    Nuevas Advertencias

    • __CLASS__ es experimental

      (S experimental::class) Esta advertencia se emite si usa la palabra clave "__CLASS__" de "use feature 'class'". Esta palabra clave es actualmente experimental y su comportamiento puede cambiar en futuras versiones de Perl.

    • %s() intentado en manejador %s abierto con open()

      (W io) Llamó a readdir(), telldir(), seekdir(), rewinddir() o closedir() en un manejador que fue abierto con open(). Si desea utilizar estas funciones para recorrer el contenido de un directorio, necesita abrir el manejador con opendir().

      [GH #22394 https://github.com/Perl/perl5/issues/22394]

    • Posible problema de precedencia entre ! y %s

      (W precedence) Escribió algo como

      !$x < $y               # analizado como: (!$x) < $y
!$x eq $y              # analizado como: (!$x) eq $y
!$x =~ /regex/         # analizado como: (!$x) =~ /regex/
!$obj isa Some::Class  # analizado como: (!$obj) isa Some::Class

      pero dado que "!" tiene una precedencia mayor que los operadores de comparación, "=~" e "isa", esto se interpreta como comparar/coincidir la negación lógica del primer operando, en lugar de negar el resultado de la comparación/coincidencia.

      Para desambiguar, utilice un operador de comparación/unión negado:

      $x >= $y
$x ne $y
$x !~ /regex/

      ... o paréntesis:

      !($x < $y)
!($x eq $y)
!($x =~ /regex/)
!($obj isa Some::Class)

      ... o el operador de baja precedencia "not":

      not $x < $y
not $x eq $y
not $x =~ /regex/
not $obj isa Some::Class

      (Si realmente quería comparar el resultado booleano de negar el primer operando, use paréntesis como "(!$x) < $y", "(!$x) eq $y", etc.)

      Nota: esta advertencia no se activa para código como "!!$x == $y", es decir, donde la doble negación ("!!") se utiliza como operador de convertir a booleano.

    • Se ha eliminado la macro de configuración (mayormente indocumentada) "PERL_STRICT_CR". Cuando estaba habilitada (por ejemplo, con "./Configure -A ccflags=-DPERL_STRICT_CR"), hacía que el analizador de perl lanzara un error fatal al encontrar un carácter CR (retorno de carro) en los archivos fuente.       ("PERL_STRICT_CR" se introdujo originalmente en perl 5.005 para restaurar opcionalmente la compatibilidad con perl 5.004, que había convertido el CR en archivos fuente en un error. Antes de eso, el CR se aceptaba, pero se conservaba literalmente en construcciones de varias líneas entre comillas, como los here-documents, incluso al final de una línea.)

    • De manera similar, se ha eliminado la macro de configuración (aún menos documentada) "PERL_CR_FILTER". Cuando estaba habilitada, instalaba un filtro de origen predeterminado para eliminar los retornos de carro del código fuente antes de que el analizador lo viera.

    Cambios Internos

    • Se introduce la función de la API de Perl ""sv_strftime_ints"". Esta es una versión mejorada de ""my_strftime"" en la API de Perl, que se mantiene por compatibilidad con versiones anteriores. Ambas llaman a strftime(3) cuando tienes el año, mes, hora, etc. La nueva función maneja la UTF8 por ti, y te permite especificar si deseas que se considere la posibilidad de horario de verano. "my_strftime" nunca considera el horario de verano.
    • Las funciones "bytes_to_utf8", "bytes_from_utf8" y "bytes_from_utf8_loc" ya no son experimentales.
    • Las llamadas a call_argv() con el indicador "G_DISCARD" establecido también aseguran que los SV parámetros construidos a partir del parámetro "argv" se liberen antes de que call_argv() devuelva el control. Anteriormente se liberaban en el siguiente FREETMPS. [GH #22255 https://github.com/Perl/perl5/issues/22255]
    • Cuando se compila con la opción de compilación "-DDEBUGGING", las funciones de la API de perl que toman punteros a tipos distintos de SV (AV, HV o CV) verificarán el SvTYPE() de los valores pasados para asegurar que sean válidos. Además, el código interno dentro de las funciones principales que intentan extraer AV, HV o CV de los valores de referencia pasados también realizará dichas comprobaciones.

      Si bien esto ha sido completamente probado por las pruebas normales de CI de Perl, todavía puede haber algunos casos extremos en los que estas restricciones se violen en llamadas que de otro modo serían válidas. Estos pueden requerir una mayor investigación si se encuentran, y es posible que se deba ajustar el código específico para tenerlo en cuenta.

    • La función op_dump() se ha ampliado para incluir información adicional sobre las operaciones recientes "OP_METHSTART" y "OP_INITFIELD", así como para "OP_ARGCHECK" y "OP_ARGELEM" que no se habían hecho previamente.
    • op_dump() ahora también tiene la capacidad de imprimir información de depuración adicional sobre operadores personalizados, si esos operadores registran una función auxiliar a través del nuevo elemento "xop_dump" de la estructura "XOP". Para obtener más información, consulte las adiciones relevantes a perlguts.
    • Se introducen nuevas funciones de API para convertir cadenas codificadas en UTF-8 a su equivalente de punto de código ordinal. Estas son seguras de usar por defecto y, en general, más convenientes de usar que las existentes.

      ""utf8_to_uv"" en perlapi y ""utf8_to_uv_or_die"" en perlapi reemplazan ""utf8_to_uvchr"" en perlapi (que se mantiene por compatibilidad con versiones anteriores), pero debes convertirte para usar las nuevas formas, ya que es probable que no estés utilizando la antigua de forma segura.

      Para convertir en la dirección opuesta, ahora puedes usar ""uv_to_utf8"" en perlapi. Esta no es una función nueva, sino un sinónimo nuevo para ""uvchr_to_utf8"" en perlapi. Se agrega para que no tengas que aprender dos conjuntos de nombres.

      También hay dos funciones nuevas, ""strict_utf8_to_uv"" en perlapi y ""c9strict_utf8_to_uv"" en perlapi que hacen lo mismo excepto cuando la cadena de entrada representa un punto de código que Unicode no acepta como legal para intercambio, utilizando ya sea la definición original estricta ("strict_utf8_to_uv"), o la más laxa dada por la corrección #9 de Unicode https://www.unicode.org/versions/corrigendum9.html ("c9strict_utf8_to_uv"). Cuando la cadena de entrada representa uno de los puntos de código restringidos, estas funciones devuelven el "CARÁCTER DE REEMPLAZO" de Unicode en su lugar.

      También ""extended_utf8_to_uv"" en perlapi es un sinónimo de "utf8_to_uv", para usar cuando quieras enfatizar que todo el rango de UTF-8 extendido de Perl es aceptable.

      También hay funciones de reemplazo para las tres funciones de conversión más especializadas que es poco probable que necesites usar. Nuevamente, las formas antiguas se conservan para compatibilidad con versiones anteriores, pero debes convertirte para usar las nuevas formas.

      ""utf8_to_uv_flags"" en perlapi reemplaza ""utf8n_to_uvchr"" en perlapi.

      ""utf8_to_uv_errors"" en perlapi reemplaza ""utf8n_to_uvchr_error""

      ; in perlapi.

      ""utf8_to_uv_msgs"" en perlapi reemplaza a ""utf8n_to_uvchr_msgs"" en perlapi.

      También se agregan las funciones inversas ""uv_to_utf8_flags"" en perlapi y ""uv_to_utf8_msgs"" en perlapi, que son sinónimos de las funciones existentes, ""uvchr_to_utf8_flags"" en perlapi y ""uvchr_to_utf8_flags_msgs"" en perlapi respectivamente. Estas se proporcionan solo para que no tengas que aprender dos conjuntos de nombres.

    • Se introducen tres nuevas funciones de API para convertir cadenas codificadas en UTF-8 a formato de bytes nativo (si es posible). Estas son más fáciles de usar que las existentes y evitan asignaciones de memoria innecesarias. Las funciones son ""utf8_to_bytes_overwrite"" en perlapi, que se usa cuando está bien que la cadena de entrada se sobrescriba con el resultado convertido; y ""utf8_to_bytes_new_pv"" en perlapi y ""utf8_to_bytes_temp_pv"" en perlapi cuando la cadena original debe conservarse intacta. "utf8_to_bytes_temp_pv" devuelve el resultado en un temporal usando perlapi/"SAVEFREEPV" que se destruirá automáticamente. Con "utf8_to_bytes_new_pv", eres responsable de liberar la memoria recién asignada que se devuelve si la conversión es exitosa.

      Las dos últimas funciones están diseñadas para reemplazar ""bytes_from_utf8"" en perlapi, que crea memoria innecesariamente, o innecesariamente grande.

    • Se han agregado nuevas funciones de API valid_identifier_pve(), valid_identifier_pvn() y valid_identifier_sv(), que prueban si una cadena sería considerada por Perl como un identificador válido nombre.
    • Al asignar desde un SVt_IV a un SVt_NV (o viceversa), siempre que ambos sean tipos "sin cuerpo", Perl_sv_setsv_flags ahora simplemente cambiará el tipo de destino para que coincida con el tipo de origen. Anteriormente, un SVt_IV se habría actualizado a un SVt_PVNV para almacenar un NV, y un SVt_NV se habría actualizado a un SVt_PVIV para almacenar un IV. Este cambio evita la necesidad de asignar y luego liberar la estructura de cuerpo relevante.
    • Se introducen dos nuevas funciones de API para convertir cadenas codificadas en formato de bytes nativo a UTF-8. Estas devuelven la cadena sin cambios si su representación UTF-8 es la misma que la original. De lo contrario, se asigna nueva memoria para contener la cadena convertida. Esto contrasta con la función existente ""bytes_to_utf8"" en perlapi, que siempre asigna nueva memoria. Las nuevas funciones son ""bytes_to_utf8_free_me"" en perlapi y ""bytes_to_utf8_temp_pv"" en perlapi. ""bytes_to_utf8_temp_pv"" en perlapi se encarga de que la nueva memoria se libere automáticamente. Con "bytes_to_utf8_free_me", eres responsable de liberar cualquier memoria recién asignada.
    • La forma en que el analizador gramatical analiza las firmas de subrutinas ha cambiado.

      Anteriormente, al analizar parámetros de firma individuales, el analizador acumulaba un fragmento de optree "OP_ARGELEM" por cada parámetro en la pila del analizador, recogiéndolos en una secuencia "OP_LIST", antes de construir finalmente el árbol de opciones completo de manejo de argumentos, en un bloque de acción grande definido directamente en perly.y.

      En el nuevo enfoque, toda la generación de árboles de opciones es manejada por funciones recién definidas en op.c que son llamadas por los bloques de acción en el analizador. Estos no conservan el estado en la pila del analizador, sino en una estructura de memoria dedicada referenciada por la estructura principal "PL_parser". Se pretende que sea en gran medida opaco para otro código, y se acceda solo a través de las nuevas funciones.

      Este nuevo arreglo está destinado a permitir la generación de código más flexible y el desarrollo de funciones adicionales en el futuro.

    • Se han agregado tres nuevas funciones de API para interactuar con la posición de coincidencia global de expresiones regulares almacenada en un SV. Estas son sv_regex_global_pos_get(), sv_regex_global_pos_set() y sv_regex_global_pos_clear(). Usar estas funciones de API evita que los módulos XS necesiten conocer o interactuar directamente con la forma en que se almacena actualmente esta posición, lo que implica el tipo mágico "PERL_MAGIC_regex_global".
    • Nuevo macro de API "SvVSTRING"

      Se ha agregado un nuevo macro de API, que se utiliza para obtener el segundo búfer de cadena de un SV de "vstring", de manera similar al macro "SvPV", que obtiene el búfer de cadena regular de un SV regular.

      STRLEN len;
const char *vstr_pv = SvVSTRING(sv, vstr_len);

      Ver ""SvVSTRING"" en perlapi.

    Andrew Main (ZEFRAM) falleció el 10 de marzo de 2025.

    Zefram era una persona brillante, aparentemente conocedora de todo y feliz de impartir su conocimiento y compartir sus notables ideas con una manera gentil y técnica que a menudo no transmitía el cuidado genuino con el que se comunicaba.

    Sería imposible exagerar el impacto que Zefram ha tenido tanto en el lenguaje como en la cultura de Perl a lo largo de los años. Desde sus innumerables contribuciones a la base de código, hasta sus apariciones a menudo peculiares pero siempre distintivas en conferencias y reuniones, su influencia y recuerdo perdurarán mucho en el futuro.

    Zefram deseaba que no hubiera un lugar conmemorativo designado en el mundo físico. Su lugar conmemorativo designado en el ciberespacio es http://www.fysh.org/~zefram/personal/.

    Reporting Bugs

    If you find what you think is a bug, you might check the perl bug database at https://github.com/Perl/perl5/issues. There may also be information at https://www.perl.org/, the Perl Home Page.

    If you believe you have an unreported bug, please open an issue at https://github.com/Perl/perl5/issues. Be sure to trim your bug down to a tiny but sufficient test case.

    If the bug you are reporting has security implications which make it inappropriate to send to a public issue tracker, then see "SECURITY VULNERABILITY CONTACT INFORMATION" in perlsec for details of how to report the issue.
