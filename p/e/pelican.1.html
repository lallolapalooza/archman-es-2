NOMBRE

pelican - generador de sitios estáticos

  • Escribe tu contenido directamente con tu editor preferido en formatos reStructuredText o Markdown
  • Incluye una herramienta CLI sencilla para (re)generar tu sitio
  • Fácil de interconectar con sistemas de control de versiones distribuidos y webhooks
  • Salida completamente estática, fácil de alojar en cualquier lugar

¿Listo para empezar? Consulta la guía de Inicio Rápido.

CARACTERÍSTICAS

Las características destacadas de Pelican incluyen:

  • Artículos (p. ej., publicaciones de blog) y páginas (p. ej., "Acerca de", "Proyectos", "Contacto")
  • Integración con servicios externos
  • Temas del sitio (creados usando plantillas Jinja2)
  • Publicación de artículos en varios idiomas
  • Generación de feeds Atom y RSS
  • Resaltado de sintaxis de código
  • Importación de contenido existente desde WordPress, Dotclear o feeds RSS
  • Tiempos de reconstrucción rápidos gracias al caché de contenido y a la escritura selectiva de salida
  • Extensible a través de un rico ecosistema de plugins: Plugins de Pelican

¿POR QUÉ EL NOMBRE PELICAN?

"Pelican" es un anagrama de calepin, que significa "cuaderno de notas" en francés. ;)

Inicio Rápido

Se recomienda encarecidamente leer toda la documentación, pero para los verdaderamente impacientes, a continuación se presentan algunos pasos rápidos para empezar.

Instalación

Instala Pelican (y opcionalmente Markdown si piensas usarlo) en Python >=3.9 ejecutando el siguiente comando en tu terminal preferida, prefijándolo con sudo si los permisos lo requieren:

python -m pip install "pelican[markdown]"

Crear un proyecto

Primero, elige un nombre para tu proyecto, crea un directorio con el nombre apropiado para tu sitio y cambia a ese directorio:

mkdir -p ~/proyectos/tusitio
cd ~/proyectos/tusitio

Crea un proyecto esqueleto con el comando pelican-quickstart, que comienza haciendo algunas preguntas sobre tu sitio:

pelican-quickstart

Para las preguntas que tienen valores predeterminados indicados entre corchetes, siéntete libre de usar la tecla Intro para aceptar esos valores predeterminados [1]. Cuando se te pregunte por el prefijo de tu URL, introduce tu nombre de dominio como se indica (p. ej., https://example.com).

Crear un artículo

No puedes ejecutar Pelican hasta que hayas creado algún contenido. Usa tu editor de texto preferido para crear tu primer artículo con el siguiente contenido:

Título: Mi Primera Reseña
Fecha: 2010-12-03 10:20
Categoría: Reseña
A continuación se presenta una reseña de mi teclado mecánico favorito.

Dado que este artículo de ejemplo está en formato Markdown, guárdalo como ~/proyectos/tusitio/content/keyboard-review.md.

Generar tu sitio

Desde el directorio raíz de tu proyecto, ejecuta el comando pelican para generar tu sitio:

pelican content

Tu sitio ha sido generado ahora dentro del directorio output/. (Puede que veas una advertencia relacionada con los feeds, pero eso es normal al desarrollar localmente y se puede ignorar por ahora).

Instalación de Pelican

Pelican actualmente funciona mejor en versiones >=3.9; las versiones anteriores de Python no son compatibles.

python -m pip install pelican

O, si planeas usar Markdown:

python -m pip install "pelican[markdown]"

(Ten en cuenta que algunos sistemas operativos requerirán que antepongas sudo al comando anterior para instalar Pelican a nivel de sistema.)

virtualenv ~/virtualenvs/pelican
cd ~/virtualenvs/pelican
source bin/activate

Una vez que el entorno virtual haya sido creado y activado, Pelican puede ser instalado a través de python -m pip install pelican como se mencionó anteriormente. Alternativamente, si tienes el código fuente del proyecto, puedes instalar Pelican usando el método distutils:

cd ruta-a-codigo-fuente-de-Pelican
python setup.py install

Si tienes Git instalado y prefieres instalar la última versión de vanguardia de Pelican en lugar de una versión estable, usa el siguiente comando:

python -m pip install -e "git+https://github.com/getpelican/pelican.git#egg=pelican"

Una vez instalado Pelican, puedes ejecutar pelican --help para ver las opciones básicas de uso. Para más detalles, consulta la sección Publicar.

Dependencias

Cuando se instale Pelican, los siguientes paquetes de Python dependientes deberían instalarse automáticamente sin ninguna acción de su parte:

  • feedgenerator, para generar los feeds Atom
  • jinja2, para soporte de plantillas
  • pygments, para resaltado de sintaxis
  • docutils, para soportar reStructuredText como formato de entrada
  • blinker, un sistema de señales de objeto a objeto y difusión
  • unidecode, para utilidades de texto Unicode de transliteración a ASCII
  • MarkupSafe, para una implementación de cadena segura para marcado
  • python-dateutil, para leer los metadatos de fecha

Actualizando

python -m pip install --upgrade pelican

Si instaló Pelican a través de distutils o el método de vanguardia, simplemente realice el mismo paso para instalar la versión más reciente.

Inicia tu sitio

Una vez que Pelican esté instalado, puede crear un proyecto esqueleto a través del comando pelican-quickstart, que comienza haciendo algunas preguntas sobre su sitio:

pelican-quickstart

Si se ejecuta dentro de un entorno virtual activado, pelican-quickstart buscará una ruta de proyecto asociada dentro de $VIRTUAL_ENV/.project. Si ese archivo existe y contiene una ruta de directorio válida, el nuevo proyecto Pelican se guardará en esa ubicación. De lo contrario, el valor predeterminado es el directorio de trabajo actual. Para establecer la ruta del nuevo proyecto en la invocación inicial, use: pelican-quickstart --path /tu/directorio/deseado

Una vez que termine de responder todas las preguntas, su proyecto consistirá en la siguiente jerarquía (excepto por las páginas, que se muestran entre paréntesis a continuación, que puede agregar opcionalmente usted mismo si planea crear contenido no cronológico):

tuproyecto/
├── content
│   └── (pages)
├── output
├── tasks.py
├── Makefile
├── pelicanconf.py       # Archivo de configuración principal
└── publishconf.py       # Configuración a usar cuando esté listo para publicar

El siguiente paso es comenzar a agregar contenido a la carpeta content que se ha creado para usted.

Escribiendo contenido

Artículos y páginas

Pelican considera que los "artículos" son contenido cronológico, como publicaciones de un blog, y por lo tanto asociados con una fecha.

La idea detrás de las "páginas" es que generalmente no son de naturaleza temporal y se utilizan para contenido que no cambia muy a menudo (por ejemplo, páginas de "Acerca de" o "Contacto").

Puede encontrar contenido de ejemplo en el repositorio en samples/content/.

Metadatos del archivo

Pelican intenta ser lo suficientemente inteligente como para obtener la información que necesita del sistema de archivos (por ejemplo, sobre la categoría de sus artículos), pero alguna información debe proporcionarla en forma de metadatos dentro de sus archivos.

Si está escribiendo su contenido en formato reStructuredText, puede proporcionar estos metadatos en archivos de texto utilizando la siguiente sintaxis (asigne la extensión .rst a su archivo):

Mi super título
##############
:date: 2010-10-03 10:20
:modified: 2010-10-04 18:40
:tags: eso, asombroso
:category: sí
:slug: mi-super-post
:authors: Alexis Metaireau, Conan Doyle
:summary: Versión corta para índices y feeds

Las listas de autores y etiquetas pueden estar separadas por punto y coma en su lugar, lo que le permite escribir autores y etiquetas que contengan comas:

:tags: pelican, herramienta de publicación; pelican, pájaro
:authors: Metaireau, Alexis; Doyle, Conan

Pelican implementa una extensión para reStructuredText para habilitar el soporte para la etiqueta HTML abbr. Para usarla, escriba algo como esto en su publicación:

La sintaxis de metadatos para las publicaciones de Markdown debe seguir este patrón:

Título: Mi super título
Fecha: 2010-12-03 10:20
Modificado: 2010-12-05 19:30
Categoría: Python
Etiquetas: pelican, publicación
Slug: mi-super-post
Autores: Alexis Metaireau, Conan Doyle
Resumen: Versión corta para índices y feeds
Este es el contenido de mi súper publicación de blog.

También puede tener sus propias claves de metadatos (siempre que no conflicten con las palabras clave de metadatos reservadas) para usarlas en sus plantillas. La siguiente tabla contiene una lista de palabras clave de metadatos reservadas:

Metadato Descripción
title Título del artículo o página
date Fecha de publicación (ej. YYYY-MM-DD HH:SS)
modified Fecha de modificación (ej. YYYY-MM-DD HH:SS)
tags Etiquetas del contenido, separadas por comas
keywords Palabras clave del contenido, separadas por comas (solo contenido HTML)
category Categoría del contenido (una sola - no múltiples)
slug Identificador utilizado en URLs y traducciones
author Autor del contenido, cuando solo hay uno
authors Autores del contenido, cuando hay varios
summary Breve descripción del contenido para las páginas de índice
lang ID de idioma del contenido (en, fr, etc.)
translation Si el contenido es una traducción de otro (true o false)
status Estado del contenido: draft, hidden, skip, o published

save_as Guardar el contenido en esta ruta de archivo relativa

Si desea excluir alguna página de ser enlazada o listada en el menú, agregue un atributo status: hidden a sus metadatos. Esto es útil para cosas como crear páginas de error que se ajusten al tema generado de su sitio.

Contenido estático

Los archivos estáticos son archivos distintos de artículos y páginas que se copian a la carpeta de salida tal cual, sin procesamiento. Puede controlar qué archivos estáticos se copian con la configuración STATIC_PATHS del archivo pelicanconf.py del proyecto. La configuración predeterminada de Pelican incluye el directorio images para esto, pero otros deben agregarse manualmente. Además, se incluyen los archivos estáticos a los que se enlaza explícitamente (ver más abajo).

NOTA:

En la configuración predeterminada, todos los archivos con un sufijo de archivo de contenido válido (.html, .rst, .md, ...) son procesados por los generadores de artículos y páginas *antes* del generador estático. Esto se evita modificando las configuraciones *_EXCLUDE apropiadamente.

Contenido mixto en el mismo directorio

A partir de Pelican 3.5, los archivos estáticos pueden compartir de forma segura un directorio de origen con los archivos de origen de las páginas, sin exponer las fuentes de las páginas en el sitio generado. Cualquier directorio de este tipo debe agregarse tanto a STATIC_PATHS como a PAGE_PATHS (o STATIC_PATHS y ARTICLE_PATHS). Pelican identificará y procesará los archivos de origen de las páginas normalmente, y copiará los archivos restantes como si estuvieran en un directorio separado reservado para archivos estáticos.

Nota: Colocar archivos estáticos y fuentes de contenido juntos en el mismo directorio de origen no garantiza que terminen en el mismo lugar en el sitio generado. La forma más fácil de hacerlo es usando la sintaxis de enlace {attach} (descrita a continuación). Alternativamente, las configuraciones STATIC_SAVE_AS, PAGE_SAVE_AS y ARTICLE_SAVE_AS (y las configuraciones correspondientes *_URL) se pueden configurar para colocar archivos de diferentes tipos juntos, tal como podrían hacerlo en versiones anteriores de Pelican.

Enlazar contenido interno

Desde Pelican 3.1, ahora es posible especificar enlaces dentro del sitio a archivos en la jerarquía de contenido de origen en lugar de a archivos en la jerarquía generada. Esto facilita enlazar desde la publicación actual a otro contenido que pueda estar junto a esa publicación (en lugar de tener que determinar dónde se colocará el otro contenido después de la generación del sitio).

Para enlazar a contenido interno (archivos en el directorio content), use la siguiente sintaxis para el objetivo del enlace: {filename}ruta/a/archivo. Nota: Las barras inclinadas, /, son el separador de ruta requerido en la directiva {filename} en todos los sistemas operativos, incluido Windows.

Por ejemplo, un proyecto Pelican podría estructurarse así:

website/
├── content
│   ├── category/
│   │   └── article1.rst
│   ├── article2.md
│   └── pages
│       └── about.md
└── pelican.conf.py

En este ejemplo, article1.rst podría verse así:

El primer artículo
#################
:date: 2012-12-01 10:02
Vea abajo ejemplos de enlaces intra-sitio en formato reStructuredText.
`un enlace relativo al archivo actual <{filename}../article2.md>`_
`un enlace relativo a la raíz del contenido <{filename}/article2.md>`_

y article2.md:

Title: El segundo artículo
Date: 2012-12-01 10:02
Vea abajo ejemplos de enlaces intra-sitio en formato Markdown.
[un enlace relativo al archivo actual]({filename}category/article1.rst)
[un enlace relativo a la raíz del contenido]({filename}/category/article1.rst)

Enlazar a archivos estáticos

Puede enlazar a contenido estático usando {static}ruta/a/archivo. Los archivos enlazados con esta sintaxis se copiarán automáticamente al directorio de salida, incluso si los directorios de origen que los contienen no están incluidos en la configuración STATIC_PATHS del archivo pelicanconf.py del proyecto.

Por ejemplo, el directorio de contenido de un proyecto podría estructurarse así:

content
├── images
│   └── han.jpg
├── pdfs
│   └── menu.pdf
└── pages
    └── test.md

test.md incluiría:

![Texto alternativo]({static}/images/han.jpg)
[Nuestro Menú]({static}/pdfs/menu.pdf)

La generación del sitio copiaría entonces han.jpg a output/images/han.jpg, menu.pdf a output/pdfs/menu.pdf, y escribiría los enlaces apropiados en test.md.

Si usa {static} para enlazar a un artículo o una página, esto se convertirá en un enlace a su código fuente.

Adjuntar archivos estáticos

A partir de Pelican 3.5, los archivos estáticos pueden ser "adjuntados" a una página o artículo usando esta sintaxis para el objetivo del enlace: {attach}ruta/a/archivo. Esto funciona como la sintaxis {static}, pero también reubica el archivo estático en el directorio de salida del documento enlazado. Si el archivo estático se origina en un subdirectorio debajo del documento enlazado, esa relación se conservará en la salida. De lo contrario, se convertirá en un hermano del documento enlazado.

Esto solo funciona para enlazar a archivos estáticos.

Por ejemplo, el directorio de contenido de un proyecto podría estructurarse así:

content
├── blog
│   ├── icons
│   │   └── icon.png
│   ├── photo.jpg
│   └── post.md

y post.md contendría:

Este es un post con algunos archivos adjuntos.

![Icono]({attach}/blog/icons/icon.png)
[Foto]({attach}/blog/photo.jpg)

La generación del sitio crearía:

output/blog/
├── icons/
│   └── icon.png
├── photo.jpg
└── post.md

Observe cómo post.md está en el mismo directorio que sus archivos adjuntos en el resultado.

Los enlaces en post.md se actualizarían a:

Este es un post con algunos archivos adjuntos.

![Icono](icons/icon.png)
[Foto](photo.jpg)

Y este ejemplo ilustra el uso de archivos adjuntos en un directorio de sub-origen:

content/
└── blog/
    ├── images/
    │   └── logo.png
    └── post/
        ├── images/
        │   └── attachment.png
        └── article.md

y article.md contendría:

[Adjunto]({attach}images/attachment.png)

La generación del sitio produciría:

output/blog/post/
├── images/
│   └── attachment.png
└── article.md

El enlace en article.md se actualizaría a:

[Adjunto](images/attachment.png)

Por último, también puede adjuntar un archivo de un directorio que no sea de origen del artículo:

content/
├── images/
│   └── logo.png
└── blog/
    └── post/
        └── article.md

y article.md contendría:

[Logo]({attach}/images/logo.png)

La generación del sitio produciría:

output/blog/post/
└── article.md

y el archivo output/images/logo.png se copiaría.

El enlace en article.md se actualizaría a:

[Logo](images/logo.png)

Archivos adjuntos

El marcador {attach} se puede usar para enlazar a archivos adjuntos. Pelican moverá automáticamente los archivos adjuntos a un directorio de salida correspondiente al artículo o página que los enlaza. Para que esto funcione, debe tener la siguiente estructura de contenido:

content/
├── blog/
    ├── 2014/
    │  ├── icons/
    │  │  └── icon.png
    │  ├── photo.jpg
    └── test-post.md
    └── downloads/
        └── archive.zip

pelicanconf.py incluiría:

PATH = 'content'
ARTICLE_PATHS = ['blog']
ARTICLE_SAVE_AS = '{date:%Y}/{slug}.html'
ARTICLE_URL = '{date:%Y}/{slug}.html'

testpost.md incluiría:

Title: Test Post
Category: test
Date: 2014-10-31
![Icon]({attach}icons/icon.png)
![Photo]({attach}photo.jpg)
[Downloadable File]({attach}/downloads/archive.zip)

La generación del sitio produciría entonces un directorio de salida estructurado así:

output
└── 2014
    ├── archive.zip
    ├── icons
    │   └── icon.png
    ├── photo.jpg
    └── test-post.html

Observe que todos los archivos enlazados usando {attach} terminaron en o debajo del directorio de salida del artículo.

Si un archivo estático se enlaza varias veces, la función de reubicación de {attach} solo funcionará en el primero de esos enlaces que se procese. Después del primer enlace, Pelican tratará {attach} como {static}. Esto evita romper los enlaces ya procesados.

Tenga cuidado al enlazar a un archivo desde varios documentos: Dado que el primer enlace a un archivo finaliza su ubicación y Pelican no define el orden en que se procesan los documentos, el uso de {attach} en un archivo enlazado por varios documentos puede hacer que su ubicación cambie de una compilación de sitio a la siguiente. (Si esto ocurre en la práctica dependerá del sistema operativo, sistema de archivos, versión de Pelican y documentos que se añaden, modifican o eliminan del proyecto.) Cualquier sitio externo que enlace a la ubicación anterior del archivo podría entonces tener sus enlaces rotos. Por lo tanto, es recomendable usar {attach} solo si lo usa en todos los enlaces a un archivo, y solo si los documentos enlazados comparten un único directorio. Bajo estas condiciones, la ubicación de salida del archivo no cambiará en compilaciones futuras. En casos donde estas precauciones no son posibles, considere usar enlaces {static} en lugar de {attach}, y dejar que la ubicación del archivo sea determinada por la configuración STATIC_SAVE_AS y STATIC_URL del proyecto. (Las anulaciones de save_as y url por archivo todavía se pueden establecer en EXTRA_PATH_METADATA.)

NOTA:

Al usar {attach}, cualquier directorio padre en la configuración de *_URL / *_SAVE_AS debe coincidir entre sí. Ver también: Configuración de URL

Enlazar a autores, categorías, índice y etiquetas

Puedes enlazar a autores, categorías, índice y etiquetas usando la sintaxis {author}nombre, {category}foobar, {index} y {tag}etiqueta.

Sintaxis de enlace interno obsoleta

Para mantener la compatibilidad con versiones anteriores, Pelican todavía admite barras verticales (||) además de llaves ({}) para enlaces internos. Por ejemplo: |nombrearchivo|un_articulo.rst, |tag|etiqueta, |category|foobar. La sintaxis se cambió de || a {} para evitar colisiones con extensiones de Markdown o directivas de reST. De manera similar, Pelican también todavía admite el enlace a contenido estático con {nombrearchivo}. La sintaxis se cambió a {static} para permitir el enlace tanto a artículos y páginas generadas como a sus fuentes estáticas.

El soporte para la sintaxis antigua puede eliminarse eventualmente.

Incluir otros archivos

Tanto la sintaxis de Markdown como la de reStructuredText proporcionan mecanismos para esto.

.. include:: file.rst

Incluir un fragmento de un archivo delimitado por dos identificadores, resaltado como C++ (también es posible cortar basándose en números de línea):

.. include:: main.cpp
    :code: c++
    :start-after: // begin
    :end-before: // end

Incluir un archivo HTML sin procesar (o un SVG en línea) y colocarlo directamente en la salida sin ningún procesamiento:

```html
{! template.html !}
```

Traducciones

Es posible traducir artículos. Para hacerlo, necesitas agregar un atributo meta lang a tus artículos/páginas y establecer una configuración DEFAULT_LANG (que es inglés [en] por defecto). Con estas configuraciones en su lugar, solo se listarán los artículos en el idioma predeterminado, y cada artículo vendrá acompañado de una lista de traducciones disponibles para ese artículo.

NOTA:

Esta funcionalidad principal de Pelican no crea sub-sitios (por ejemplo, ejemplo.com/de) con plantillas traducidas para cada idioma. Para tal funcionalidad avanzada se puede utilizar el plugin i18n_subsites.

Por defecto, Pelican utiliza el "slug" de la URL del artículo para determinar si uno o más artículos son traducciones entre sí. (Esto se puede cambiar con la configuración ARTICLE_TRANSLATION_ID.) El slug se puede establecer manualmente en los metadatos del archivo; si no se establece explícitamente, Pelican generará automáticamente el slug a partir del título del artículo.

Aquí hay un ejemplo de dos artículos, uno en inglés y otro en francés.

El artículo en inglés:

Foobar is not dead
##################
:slug: foobar-is-not-dead
:lang: en
That's true, foobar is still alive!

Y la versión francesa:

Foobar n'est pas mort !
#######################
:slug: foobar-is-not-dead
:lang: fr
Oui oui, foobar est toujours vivant !

Independientemente de la calidad del contenido de las publicaciones, puedes ver que el único elemento en común entre los dos artículos es el slug, que funciona aquí como un identificador. Si prefieres no definir explícitamente el slug de esta manera, debes asegurarte de que los títulos de los artículos traducidos sean idénticos, ya que el slug se generará automáticamente a partir del título del artículo.

Si no quieres que la versión original de un artículo específico sea detectada por la configuración DEFAULT_LANG, usa los metadatos translation para especificar qué publicaciones son traducciones:

Foobar is not dead
##################
:slug: foobar-is-not-dead
:lang: en
:translation: true
That's true, foobar is still alive!

Publicar borradores

Si deseas publicar un artículo o una página como borrador (para que amigos lo revisen antes de publicarlo, por ejemplo), puedes agregar un atributo Status: draft a sus metadatos. Ese artículo se generará entonces en la carpeta drafts y no se listará en la página de inicio ni en ninguna página de categoría o etiqueta.

Si tus artículos deben publicarse automáticamente como borrador (para no publicar accidentalmente un artículo antes de que esté terminado), incluye el estado en DEFAULT_METADATA:

DEFAULT_METADATA = {
    'status': 'draft',
}

Para publicar una publicación cuando el estado predeterminado es draft, actualiza los metadatos de la publicación para incluir Status: published.

Publicaciones ocultas

Al igual que las páginas, las publicaciones también se pueden marcar como hidden (ocultas) con el atributo Status: hidden. Las publicaciones ocultas se generarán en ARTICLE_SAVE_AS como se espera, pero no se incluyen por defecto en los índices de etiquetas, categorías y autores, ni en el feed principal de artículos. Esto tiene el efecto de crear una publicación "no listada".

Omitir publicaciones

Las publicaciones marcadas con el estado skip (omitir) se ignoran por completo. No se procesan ni se generan en la ruta ARTICLE_SAVE_AS. Dichas publicaciones tampoco se incluirán en los índices ni en los feeds.

Configuración

Pelican es configurable gracias a un archivo de configuración que puedes pasar a la línea de comandos:

pelican content -s path/to/your/pelicanconf.py

Si usaste el comando pelican-quickstart, tu archivo de configuración principal se llamará pelicanconf.py por defecto.

También puedes especificar configuraciones a través de las opciones de línea de comandos -e / --extra-settings. Estas anularán la configuración por defecto, así como cualquier otra definida en el archivo de configuración. Ten en cuenta que los valores deben seguir la notación JSON:

pelican content -e SITENAME='"Un sitio"' READERS='{"html": null}' CACHE_CONTENT=true

Las variables de entorno también se pueden usar aquí, pero deben escaparse apropiadamente:

pelican content -e API_KEY=''\"$API_KEY\"''

NOTA:

Al experimentar con diferentes configuraciones (especialmente las de metadatos), el caché puede interferir y los cambios podrían no ser visibles. En tales casos, deshabilita el caché con LOAD_CONTENT_CACHE = False o usa el modificador de línea de comandos --ignore-cache.

Para ver una lista de las configuraciones actuales en tu entorno, incluyendo tanto los valores por defecto como los personalizados, ejecuta el siguiente comando (añade uno o más nombres de configuración específicos como argumentos para ver solo los valores de esas configuraciones):

pelican --print-settings

Todos los identificadores de configuración deben estar en mayúsculas, de lo contrario no se procesarán. Los valores de configuración que son números (5, 20, etc.), booleanos (True, False, None, etc.), diccionarios o tuplas no deben ir entre comillas. Todos los demás valores (es decir, cadenas) deben ir entre comillas.

A menos que se especifique lo contrario, las configuraciones que se refieren a rutas pueden ser absolutas o relativas al archivo de configuración. Configuración de URL

Lo primero que hay que entender es que actualmente hay dos métodos admitidos para la formación de URL: relativa y absoluta. Las URL relativas son útiles al probar localmente, y las URL absolutas son confiables y más útiles al publicar. Un método para admitir ambas es tener un archivo de configuración de Pelican para el desarrollo local y otro para la publicación. Para ver un ejemplo de este tipo de configuración, utilice el script pelican-quickstart como se describe en la sección Instalación, que producirá dos archivos de configuración separados para el desarrollo local y la publicación, respectivamente.

Puede personalizar las URL y las ubicaciones donde se guardarán los archivos. Las variables *_URL y *_SAVE_AS utilizan las cadenas de formato de Python. Estas variables le permiten colocar sus artículos en una ubicación como {slug}/index.html y enlazarlos como {slug} para obtener URL limpias (ver ejemplo a continuación). Estas configuraciones le dan la flexibilidad de colocar sus artículos y páginas donde quiera.

NOTA:

Si una configuración *_SAVE_AS contiene un directorio padre que no coincide con el directorio padre dentro de la configuración correspondiente *_URL, esto puede hacer que Pelican genere URL inesperadas en algunos casos, como al usar la sintaxis {attach}.

Si no desea esa flexibilidad y prefiere que sus rutas de salida generadas reflejen la jerarquía de rutas del sistema de archivos de su contenido de origen, pruebe las siguientes configuraciones:

PATH_METADATA = '(?P<path_no_ext>.*)\..*'
ARTICLE_URL = ARTICLE_SAVE_AS = PAGE_URL = PAGE_SAVE_AS = '{path_no_ext}.html'

De lo contrario, puede utilizar una variedad de atributos de metadatos de archivo dentro de las configuraciones relacionadas con URL:

  • slug
  • date
  • lang
  • author
  • category

Ejemplo de uso:

ARTICLE_URL = 'posts/{date:%Y}/{date:%b}/{date:%d}/{slug}/'
ARTICLE_SAVE_AS = 'posts/{date:%Y}/{date:%b}/{date:%d}/{slug}/index.html'
PAGE_URL = 'pages/{slug}/'
PAGE_SAVE_AS = 'pages/{slug}/index.html'

Esto guardaría sus artículos en algo como /posts/2011/Aug/07/sample-post/index.html, guardaría sus páginas en /pages/about/index.html y las haría disponibles en URL como /posts/2011/Aug/07/sample-post/ y /pages/about/, respectivamente.

NOTA:

Si especifica una directiva datetime, se sustituirá utilizando el atributo de metadatos de fecha de los archivos de entrada. Si la fecha no se especifica para un archivo determinado, Pelican se basará en la marca de tiempo mtime del archivo. Consulte la documentación de Python datetime para obtener más información.

Paginación

El comportamiento predeterminado de Pelican es listar todos los títulos de los artículos junto con una breve descripción en la página principal. Si bien esto funciona bien para sitios pequeños y medianos, los sitios con una gran cantidad de artículos probablemente se beneficiarán de la paginación de esta lista.

Puede utilizar la siguiente configuración para configurar la paginación.

PAGINATION_PATTERNS = (
(1, '{name}{extension}', '{name}{extension}'),
(2, '{name}{number}{extension}', '{name}{number}{extension}'),
)
Un conjunto de patrones que se utilizan para determinar la salida avanzada de paginación.

Uso de patrones de paginación

Por defecto, las páginas posteriores a .../foo.html se crean como .../foo2.html, etc. La configuración PAGINATION_PATTERNS se puede utilizar para cambiar esto. Toma una secuencia de triples, donde cada triple consta de:

(minimum_page, page_url, page_save_as,)

Para page_url y page_save_as, puede utilizar una serie de variables. {url} y {save_as} corresponden respectivamente a los valores *_URL y *_SAVE_AS del tipo de página correspondiente (por ejemplo, ARTICLE_SAVE_AS). Si {save_as} == foo/bar.html, entonces {name} == foo/bar y {extension} == .html. {base_name} es igual a {name} excepto que elimina /index al final si está presente. {number} es igual al número de página.

Por ejemplo, si desea dejar la primera página sin cambios, pero colocar las páginas posteriores en .../page/2/, etc., puede configurar PAGINATION_PATTERNS de la siguiente manera:

PAGINATION_PATTERNS = (
    (1, '{url}', '{save_as}'),
    (2, '{base_name}/page/{number}/', '{base_name}/page/{number}/index.html'),
)

Si desea que un patrón se aplique a la última página de la lista, use -1 como el valor de minimum_page:

(-1, '{base_name}/last/', '{base_name}/last/index.html'),

Registro

A veces, puede aparecer una larga lista de advertencias durante la generación del sitio. Encontrar el mensaje de error significativo en medio de una gran cantidad de registros molestos puede ser bastante complicado. Para filtrar los mensajes de registro redundantes, Pelican viene con el ajuste LOG_FILTER.

LOG_FILTER debe ser una lista de tuplas (level, msg), cada una compuesta por el nivel de registro (hasta warning) y el mensaje a ignorar. Simplemente rellene la lista con los mensajes de registro que desee ocultar y se filtrarán.

Por ejemplo:

import logging
LOG_FILTER = [(logging.WARN, 'TAG_SAVE_AS is set to False')]

Es posible filtrar mensajes por plantilla. Consulte el código fuente para obtener una plantilla.

Por ejemplo:

import logging
LOG_FILTER = [(logging.WARN, 'Empty alt attribute for image %s in %s')]

ADVERTENCIA:

Silenciar mensajes por plantilla es una característica peligrosa. Es posible filtrar involuntariamente varios tipos de mensajes con la misma plantilla (incluidos mensajes de versiones futuras de Pelican). Proceda con precaución.

NOTA:

Esta opción no hace nada si se pasa --debug.

Lectura solo del contenido modificado

Para acelerar el proceso de construcción, Pelican puede opcionalmente leer solo los artículos y páginas con contenido modificado.

Cuando Pelican está a punto de leer un archivo fuente de contenido:

1.
La información del hash o tiempo de modificación del archivo de una compilación anterior se carga desde un archivo de caché si LOAD_CONTENT_CACHE es True. Estos archivos se almacenan en el directorio CACHE_PATH. Si el archivo no tiene registro en el archivo de caché, se lee como de costumbre.
2.
El archivo se comprueba según CHECK_MODIFIED_METHOD:
  • Si se establece en 'mtime', se comprueba la hora de modificación del archivo.
  • Si se establece en el nombre de una función proporcionada por el módulo hashlib, por ejemplo, 'md5', se comprueba el hash del archivo.
  • Si se establece en cualquier otra cosa o si la información necesaria sobre el archivo no se puede encontrar en el archivo de caché, el contenido se lee como de costumbre.
3.
Si el archivo se considera sin cambios, los datos de contenido guardados en una compilación anterior correspondientes al archivo se cargan desde la caché, y el archivo no se lee.
4.
Si el archivo se considera modificado, se lee el archivo y la nueva información de modificación y los datos de contenido se guardan en la caché si CACHE_CONTENT es True.

Si CONTENT_CACHING_LAYER se establece en 'reader' (el valor predeterminado), se almacenan en caché el contenido y los metadatos sin procesar devueltos por un lector. Si esta configuración se establece en 'generator' en su lugar, se almacena en caché el objeto de contenido procesado. Almacenar en caché el objeto de contenido procesado m ay conflicto con los complementos (ya que algunas señales relacionadas con la lectura pueden omitirse) y la funcionalidad WITH_FUTURE_DATES (ya que el estado draft de los objetos de contenido en caché no cambiaría automáticamente con el tiempo).

Verificar los tiempos de modificación es más rápido que comparar hashes de archivos, pero no es tan confiable porque la información mtime se puede perder, por ejemplo, al copiar archivos fuente de contenido utilizando los comandos cp o rsync sin el modo de preservación de mtime (que para rsync se puede invocar pasando la bandera --archive).

Los archivos de caché son "pickles" de Python, por lo que es posible que no sean legibles por diferentes versiones de Python, ya que el formato de "pickle" a menudo cambia. Si se produce un error de este tipo, se detecta y el archivo de caché se reconstruye automáticamente en el nuevo formato. Los archivos de caché también se reconstruirán después de que se haya cambiado la configuración GZIP_CACHE.

La opción de línea de comandos --ignore-cache es útil cuando se necesita regenerar toda la caché, como al realizar modificaciones en el archivo de configuración que afectarán al contenido en caché, o simplemente para fines de depuración. Cuando Pelican se ejecuta en modo de recarga automática, la modificación del archivo de configuración hará que ignore la caché automáticamente si AUTORELOAD_IGNORE_CACHE es True.

Tenga en cuenta que incluso al usar contenido en caché, toda la salida siempre se escribe, por lo que los tiempos de modificación de los archivos *.html generados siempre cambiarán. Por lo tanto, la carga basada en rsync puede beneficiarse de la opción --checksum.

Complementos

A partir de la versión 3.0, Pelican admite complementos. Los complementos son una forma de añadir funciones a Pelican sin tener que modificar directamente el núcleo de Pelican.

Cómo usar complementos

pelican-plugins

Si dejas la configuración PLUGINS por defecto (None), Pelican descubrirá automáticamente los complementos de espacio de nombres y los registrará. Si, por otro lado, especificas una configuración PLUGINS como una lista de complementos, este descubrimiento automático se deshabilitará. En ese momento, solo se registrarán los complementos que especifiques y deberás listar explícitamente cualquier complemento de espacio de nombres también.

Si estás usando la configuración PLUGINS, puedes especificar complementos de dos maneras. El primer método especifica complementos como una lista de cadenas. Los complementos de espacio de nombres se pueden especificar por sus nombres completos (pelican.plugins.myplugin) o por sus nombres cortos (myplugin):

PLUGINS = ['package.myplugin',
           'namespace_plugin1',
           'pelican.plugins.namespace_plugin2']

Alternativamente, puedes importarlos en tu archivo de configuración y pasar los módulos:

from package import myplugin
from pelican.plugins import namespace_plugin1, namespace_plugin2
PLUGINS = [myplugin, namespace_plugin1, namespace_plugin2]

NOTA:

Al experimentar con diferentes complementos (especialmente aquellos que tratan con metadatos y contenido), la caché puede interferir y los cambios pueden no ser visibles. En tales casos, deshabilita la caché con LOAD_CONTENT_CACHE = False o usa el interruptor de línea de comandos --ignore-cache.

Cómo crear complementos

Los complementos se basan en el concepto de señales. Pelican envía señales y los complementos se suscriben a esas señales. La lista de señales disponibles se documenta en una sección posterior.

La única regla a seguir para los complementos es definir una llamada register, en la que mapeas las señales a la lógica de tu complemento. Tomemos un ejemplo simple:

import logging
from pelican import signals
log = logging.getLogger(__name__)
def test(sender):
    log.debug("%s initialized !!", sender)
def register():
    signals.initialized.connect(test)

NOTA:

Los receptores de señales se referencian débilmente y, por lo tanto, no deben definirse dentro de tu llamada register o serán recolectados por el recolector de basura antes de que se emita la señal.

Si varios complementos se conectan a la misma señal, los complementos se invocarán en el orden en que se registran. Cuando se define la configuración PLUGINS, el orden de invocación de los complementos será el orden en que los complementos se enumeran en la configuración PLUGINS. Si dependes de complementos de espacio de nombres descubiertos automáticamente y no tienes definida la configuración PLUGINS, los complementos se invocarán en el mismo orden en que se descubren (el mismo orden en que se enumeran en la salida del comando pelican-plugins). Si deseas especificar el orden explícitamente, deshabilita el descubrimiento automático definiendo PLUGINS en el orden deseado.

Estructura de complementos de espacio de nombres

Los complementos de espacio de nombres deben cumplir una cierta estructura para funcionar correctamente. Deben ser instalables (es decir, contener setup.py o equivalente) y tener una estructura de carpetas como la siguiente:

myplugin
├── pelican
│   └── plugins
│       └── myplugin
│           ├── __init__.py
│           └── ...
├── ...
└── setup.py

Es crucial que la carpeta pelican o pelican/plugins no contenga un archivo __init__.py. De hecho, es mejor tener esas carpetas vacías además de las carpetas enumeradas en la estructura anterior y mantener tus archivos relacionados con el complemento únicamente en la carpeta pelican/plugins/myplugin para evitar cualquier problema.

Cómo crear un nuevo lector

Una cosa que quizás quieras es agregar soporte para tu propio formato de entrada. Si bien podría tener sentido agregar esta característica al núcleo de Pelican, sabiamente optamos por evitar esta situación y en su lugar tener los diferentes lectores definidos a través de plugins.

La razón detrás de esta elección es principalmente que los plugins son realmente fáciles de escribir y no ralentizan a Pelican cuando no están activos.

Sin más preámbulos, aquí hay un ejemplo:

from pelican import signals
from pelican.readers import BaseReader
# Crea una nueva clase lector, heredando de pelican.reader.BaseReader
class NewReader(BaseReader):
    enabled = True  # Sí, probablemente querrás eso :-)
    # La lista de extensiones de archivo que quieres que coincidan con este
    # lector. Si varios lectores usaran la misma extensión, el último ganará
    # (así que el que estás definiendo aquí, lo más probable).
    file_extensions = ['yeah']
    # Debes tener un método read, que toma un nombre de archivo y devuelve
    # algún contenido y los metadatos asociados.
    def read(self, filename):
        metadata = {'title': 'Oh yeah',
                    'category': 'Foo',
                    'date': '2012-12-01'}
        parsed = {}
        for key, value in metadata.items():
            parsed[key] = self.process_metadata(key, value)
        return "Some content", parsed
def add_reader(readers):
    readers.reader_classes['yeah'] = NewReader
# Así es como funciona pelican.
def register():
    signals.readers_init.connect(add_reader)

Listing and Linking to Period Archives

The period_archives variable can be used to generate a list of links to the set of period archives that Pelican generates. As a common variable, it is available for use in any template, so you can implement such an index in a custom direct template, or in a sidebar visible across different site pages.

period_archives is a dict that may contain year, month, and/or day keys, depending on which *_ARCHIVE_SAVE_AS settings are enabled. The corresponding value is a list of dicts, where each dict in turn represents a time period (ordered according to the NEWEST_FIRST_ARCHIVES setting) with the following keys and values:

Key Value
period The same tuple as described in period_archives.html, e.g. (2023, 'June', 18).
period_num The same tuple as described in period_archives.html, e.g. (2023, 6, 18).
url The URL to the period archive page, e.g. posts/2023/06/18/. This is controlled by the corresponding *_ARCHIVE_URL setting.
save_as The path to the save location of the period archive page file, e.g. posts/2023/06/18/index.html. This is used internally by Pelican and is usually not relevant to themes.
articles A list of Article objects that fall under the time period.
dates Same list as articles, but ordered according to the NEWEST_FIRST_ARCHIVES setting.

Here is an example of how period_archives can be used in a template:

<ul>
{% for archive in period_archives.month %}
    <li>
        <a href="{{ SITEURL }}/{{ archive.url }}">
            {{ archive.period | reverse | join(' ') }} ({{ archive.articles|count }})
        </a>
    </li>
{% endfor %}
</ul>

You can change period_archives.month in the for statement to period_archives.year or period_archives.day as appropriate, depending on the time period granularity desired.

Herencia

Desde la versión 3.0, Pelican soporta la herencia del tema simple, por lo que puedes reutilizar las plantillas del tema simple en tus propios temas.

Si falta alguno de los archivos obligatorios en el directorio templates/ de tu tema, será reemplazado por la plantilla correspondiente del tema simple. Así que si la estructura HTML de una plantilla en el tema simple es adecuada para ti, no necesitas escribir una nueva plantilla desde cero.

También puedes extender plantillas del tema simple en tus propios temas utilizando la directiva {% extends %} como en el siguiente ejemplo:

{% extends "!simple/index.html" %}   <!-- extiende la plantilla ``index.html`` del tema ``simple`` -->
{% extends "index.html" %}   <!-- extensión "regular" -->

Ejemplo

Con este sistema, es posible crear un tema con solo dos archivos.

base.html

El primer archivo es la plantilla templates/base.html:

{% extends "!simple/base.html" %}
{% block head %}
{{ super() }}
   <link rel="stylesheet" type="text/css" href="{{ SITEURL }}/theme/css/style.css" />
{% endblock %}
1.
En la primera línea, extendemos la plantilla base.html del tema simple, así no tenemos que reescribir el archivo completo.
2.
En la tercera línea, abrimos el bloque head que ya ha sido definido en el tema simple.
3.
En la cuarta línea, la función super() mantiene el contenido insertado previamente en el bloque head.
4.
En la quinta línea, añadimos una hoja de estilos a la página.
5.
En la última línea, cerramos el bloque head.

Este archivo será extendido por todas las demás plantillas, por lo que la hoja de estilos se enlazará desde todas las páginas.

Descripción

pelican-themes es una herramienta de línea de comandos para gestionar temas para Pelican. Ver Themes para la configuración relacionada con los temas.

Uso

pelican-themes [-h] [-l] [-i ruta_tema [ruta_tema ...]]
[-r nombre_tema [nombre_tema ...]]
[-s ruta_tema [ruta_tema ...]] [-v] [--version]

Argumentos opcionales:

-h, --help
Muestra la ayuda y sale
-l, --list
Muestra los temas ya instalados
-i ruta_tema, --install ruta_tema
Uno o más temas para instalar
-r nombre_tema, --remove nombre_tema
Uno o más temas para eliminar
-s ruta_tema, --symlink ruta_tema
Igual que --install, pero crea un enlace simbólico en lugar de copiar el tema. Útil para el desarrollo de temas
-v, --verbose
Salida detallada
--version
Imprime la versión de este script

Ejemplos

Listar los temas instalados

Con pelican-themes, puedes ver los temas disponibles usando la opción -l o --list:

$ pelican-themes -l
notmyidea
two-column@
simple
$ pelican-themes --list
notmyidea
two-column@
simple

En este ejemplo, podemos ver que hay tres temas disponibles: notmyidea, simple y two-column.

two-column va seguido de un @ porque este tema no se copia a la ruta de temas de Pelican, sino que simplemente se enlaza a ella (ver Creación de enlaces simbólicos para más detalles sobre la creación de enlaces simbólicos).

Ten en cuenta que puedes combinar la opción --list con la opción -v o --verbose para obtener una salida más detallada, así:

$ pelican-themes -v -l
/usr/local/lib/python2.6/dist-packages/pelican-2.6.0-py2.6.egg/pelican/themes/notmyidea
/usr/local/lib/python2.6/dist-packages/pelican-2.6.0-py2.6.egg/pelican/themes/two-column (enlace simbólico a `/home/skami/Dev/Python/pelican-themes/two-column')
/usr/local/lib/python2.6/dist-packages/pelican-2.6.0-py2.6.egg/pelican/themes/simple

Instalar temas

Puedes instalar uno o más temas usando la opción -i o --install. Esta opción toma como argumento las rutas del(los) tema(s) que deseas instalar, y puede combinarse con la opción --verbose:

# pelican-themes --install ~/Dev/Python/pelican-themes/notmyidea-cms --verbose
# pelican-themes -
-install ~/Dev/Python/pelican-themes/notmyidea-cms \ ~/Dev/Python/pelican-themes/martyalchin \ --verbose 
# pelican-themes -vi ~/Dev/Python/pelican-themes/two-column

Remover temas

El comando pelican-themes también puede eliminar temas de la ruta de temas de Pelican. La opción -r o --remove toma como argumento el nombre (o nombres) del tema (o temas) que deseas eliminar, y puede combinarse con la opción --verbose.

# pelican-themes --remove two-column
# pelican-themes -r martyachin notmyidea-cmd -v

Crear enlaces simbólicos

pelican-themes también puede instalar temas creando enlaces simbólicos en lugar de copiar temas completos a la ruta de temas de Pelican.

Para crear un enlace simbólico a un tema, puedes usar la opción -s o --symlink, que funciona exactamente igual que la opción --install:

# pelican-themes --symlink ~/Dev/Python/pelican-themes/two-column

En este ejemplo, el tema two-column ahora está enlazado simbólicamente a la ruta de temas de Pelican, por lo que podemos usarlo, pero también podemos modificarlo sin tener que reinstalarlo después de cada modificación.

Esto es útil para el desarrollo de temas:

$ sudo pelican-themes -s ~/Dev/Python/pelican-themes/two-column
$ pelican ~/Blog/content -o /tmp/out -t two-column
$ firefox /tmp/out/index.html
$ vim ~/Dev/Pelican/pelican-themes/two-column/static/css/main.css
$ pelican ~/Blog/content -o /tmp/out -t two-column
$ cp /tmp/bg.png ~/Dev/Pelican/pelican-themes/two-column/static/img/bg.png
$ pelican ~/Blog/content -o /tmp/out -t two-column
$ vim ~/Dev/Pelican/pelican-themes/two-column/templates/index.html
$ pelican ~/Blog/content -o /tmp/out -t two-column

Hacer varias cosas a la vez

Las opciones --install, --remove y --symlink no son mutuamente excluyentes, por lo que puedes combinarlas en la misma línea de comandos para realizar más de una operación a la vez, como esto:

# pelican-themes --remove notmyidea-cms two-column \
                 --install ~/Dev/Python/pelican-themes/notmyidea-cms-fr \
                 --symlink ~/Dev/Python/pelican-themes/two-column \
                 --verbose

En este ejemplo, el tema notmyidea-cms es reemplazado por el tema notmyidea-cms-fr

Importar un sitio existente

Descripción

pelican-import es una herramienta de línea de comandos para convertir artículos de otro software a reStructuredText o Markdown. Los formatos de importación admitidos son:

  • Exportación XML de Blogger
  • Exportación de Dotclear
  • Exportación de Medium
  • API de Tumblr
  • Exportación XML de WordPress
  • Feed RSS/Atom

NOTA:

A diferencia de Pelican, Wordpress admite varias categorías por artículo. Estas se importan como una cadena separada por comas. Debes resolverlas manualmente, o usar un plugin como More Categories que habilita múltiples categorías por artículo.

NOTA:

Las páginas importadas pueden contener enlaces a imágenes que todavía apuntan al sitio original. Por lo tanto, es posible que desees descargar esas imágenes en tu contenido local y volver a enlazarlas manualmente desde las páginas relevantes de tu sitio.

Dependencias

pelican-import tiene algunas dependencias no requeridas por el resto de Pelican:

  • BeautifulSoup4 y lxml, para importación de WordPress y Dotclear. Se pueden instalar como cualquier otro paquete de Python (pip install BeautifulSoup4 lxml).
  • Feedparser, para importación de feeds (pip install feedparser).
  • Pandoc, consulta el sitio de Pandoc para obtener instrucciones de instalación en tu sistema operativo.

Uso

$ pelican-import --blogger -o ~/output ~/posts.xml

Para Dotclear:

$ pelican-import --dotclear -o ~/output ~/backup.txt

Para Medium:

Para Tumblr:

$ pelican-import --tumblr -o ~/output --blogname=<nombre_blog> <api_key>

Para WordPress:

$ pelican-import --wpfile -o ~/output ~/posts.xml

$ python -m pip install feedparser $ pelican-import --feed https://medium.com/feed/@username

Preguntas Frecuentes (FAQ)

Aquí hay algunas preguntas frecuentes sobre Pelican.

¿Cuál es la mejor manera de comunicar un problema, pregunta o sugerencia?

Por favor, lee nuestras directrices de comentarios.

¿Cómo puedo ayudar?

También puedes contribuir creando temas y mejorando la documentación.

¿Es obligatorio el archivo de configuración de Pelican?

Los archivos de configuración son opcionales y solo son una forma fácil de configurar Pelican. Para operaciones básicas, es posible especificar opciones al invocar Pelican a través de la línea de comandos. Consulta pelican --help para más información.

Los cambios en el archivo de configuración no tienen efecto

Al experimentar con diferentes configuraciones (especialmente las de metadatos) la caché puede interferir y los cambios pueden no ser visibles. En tales casos, asegúrate de que la caché esté deshabilitada mediante LOAD_CONTENT_CACHE = False o usa el modificador de línea de comandos --ignore-cache.

Estoy creando mi propio tema. ¿Cómo uso Pygments para resaltar sintaxis?

Puedes usar los siguientes comandos de ejemplo para generar un archivo CSS inicial a partir de un estilo integrado de Pygments (en este caso, "monokai") y luego copiar el archivo CSS generado a tu nuevo tema:

pygmentize -S monokai -f html -a .highlight > pygment.css
cp pygment.css ruta/a/tema/static/css/

No olvides importar tu archivo pygment.css desde tu archivo CSS principal.

¿Cómo creo mi propio tema?

Por favor, consulta Temas.

¿Puedo sobrescribir plantillas individuales sin hacer un fork de todo el tema?

Sí, puedes sobrescribir plantillas existentes del tema que estés usando, o agregar nuevas plantillas, a través de la variable THEME_TEMPLATES_OVERRIDES. Por ejemplo, para sobrescribir la plantilla de página, puedes definir la ubicación de tus plantillas así:

THEME_TEMPLATES_OVERRIDES = ["plantillas"]

Luego puedes definir una plantilla personalizada en plantillas/pagina.html. Consulta Temas para más detalles.

Quiero usar Markdown, pero recibí un error.

Si intentas generar contenido en Markdown sin haber instalado primero la biblioteca Markdown, puedes ver un mensaje que dice No se encontraron archivos válidos en el contenido. Markdown no es una dependencia dura para Pelican, por lo que si tienes contenido en formato Markdown, necesitarás instalar explícitamente la biblioteca Markdown. Puedes hacerlo escribiendo el siguiente comando, anteponiendo sudo si los permisos lo requieren:

python -m pip install markdown

¿Puedo usar metadatos arbitrarios en mis plantillas?

Sí. Por ejemplo, para incluir una fecha de modificación en una publicación de Markdown, se podría incluir lo siguiente al principio del artículo:

Modificado: 2012-08-08

Para reStructuredText, estos metadatos deberían ir prefijados con dos puntos, por supuesto:

:Modificado: 2012-08-08

Estos metadatos se pueden acceder luego en plantillas como articulo.html a través de:

{% if article.modified %}
Última modificación: {{ article.modified }}
{% endif %}

Si deseas incluir metadatos en plantillas fuera del contexto del artículo (por ejemplo, base.html), la declaración if debería ser en su lugar:

{% if article and article.modified %}

¿Cómo hago que la estructura de mi carpeta de salida sea idéntica a mi jerarquía de contenido?

Prueba estas configuraciones:

USE_FOLDER_AS_CATEGORY = False
PATH_METADATA = "(?P<path_no_ext>.*)\..*"
ARTICLE_URL = ARTICLE_SAVE_AS = PAGE_URL = PAGE_SAVE_AS = "{path_no_ext}.html"

¿Cómo asigno plantillas personalizadas por página?

Es tan simple como agregar una línea adicional de metadatos a cualquier página o artículo que quieras que tenga su propia plantilla. Por ejemplo, así es como se manejaría para contenido en formato reST:

:template: nombre_plantilla

Para contenido en formato Markdown:

Plantilla: nombre_plantilla

Luego, solo asegúrate de que tu tema contenga el archivo de plantilla relevante (por ejemplo, nombre_plantilla.html). Si solo quieres agregar una nueva plantilla personalizada a un tema existente, también puedes proporcionarla en un directorio especificado por THEME_TEMPLATES_OVERRIDES (consulta Temas).

¿Cómo puedo sobrescribir la URL generada de una página o artículo específico?

:url: anular/url/

Flujo de despliegue

Este es un flujo de trabajo de GitHub Actions para desplegar tu sitio de Pelican. Se activa con eventos `push` y `pull_request` en la rama principal, o manualmente a través de `workflow_dispatch`.

if: github.event_name == 'push' || github.event_name == 'pull_request' || inputs.deploy == true

La sección on del flujo de trabajo define los eventos que lo activarán. En este ejemplo, el flujo de trabajo se ejecutará en pushes a la rama principal, pull requests a la rama principal y ejecuciones manuales del flujo de trabajo.

workflow_dispatch define el booleano de despliegue para que sea verdadero por defecto. Esto significa que si ejecutas el flujo de trabajo manualmente, desplegará el sitio.

La entrada deploy para el trabajo está utilizando un conjunto de variables estándar de flujo de trabajo de GitHub para controlar cuándo deploy será verdadero o falso (puedes personalizar esto según tus necesidades).

En este ejemplo, deploy será verdadero si el evento es un push a la rama principal (o una fusión a la principal desde un PR) o una ejecución manual del flujo de trabajo. Si el evento es un pull request, deploy será falso y solo construirá un artefacto para el sitio.

Advertencias de "contenido inseguro" de los navegadores

Si tu sitio utiliza https:// y está roto porque el navegador está bloqueando las solicitudes de red (por ejemplo, para archivos CSS) debido a "contenido inseguro", puede ser porque GitHub Pages está generando URLs http:// para tu sitio.

Para solucionarlo, ve a la configuración del repositorio de tu sitio y habilita la opción Forzar HTTPS: ve a Configuración → Páginas y marca Forzar HTTPS. Luego, vuelve a ejecutar el flujo de trabajo para volver a desplegar tu sitio. Alternativamente, puedes usar la configuración siteurl y feed_domain del flujo de trabajo.

Para actualizar automáticamente tu sitio Pelican en cada commit, puedes crear un hook post-commit. Por ejemplo, puedes agregar lo siguiente a .git/hooks/post-commit:

STATIC_PATHS = ['images', 'extra/CNAME']
EXTRA_PATH_METADATA = {'extra/CNAME': {'path': 'CNAME'},}

Consejos de registro

Intente usar el registro con los niveles apropiados.

Para mensajes de registro que no se repiten, use la forma habitual de Python:

# en la parte superior del archivo
import logging
logger = logging.getLogger(__name__)
# cuando sea necesario
logger.warning("Una advertencia con formato %s", arg_a_formatear)

No formatee los mensajes de registro usted mismo. Use el formato %s en los mensajes y pase los argumentos al registrador. Esto es importante, porque el registrador de Pelican preprocesará algunos argumentos, como las excepciones.

Limitar mensajes de registro extralíneos

Si el mensaje de registro puede ocurrir varias veces, es posible que desee limitar el registro para evitar inundaciones. Para hacerlo, use el argumento de palabra clave extra para el mensaje de registro en el siguiente formato:

logger.warning("Una advertencia con formato %s", arg_a_formatear,
    extra={'limit_msg': 'Un mensaje genérico para demasiadas advertencias'})

Opcionalmente, también puede establecer 'limit_args' como una tupla de argumentos en el diccionario extra si su mensaje genérico necesita formato.

El límite se establece en 5, es decir, las primeras cuatro entradas de registro con el mismo 'limit_msg' se muestran normalmente, pero la quinta se registrará usando 'limit_msg' (y 'limit_args' si está presente). Después de la quinta, los mensajes de registro correspondientes se ignorarán.

Por ejemplo, si desea registrar recursos que faltan, use el siguiente código:

for resource in resources:
    if resource.is_missing:
        logger.warning(
            'El recurso %s falta', resource.name,
            extra={'limit_msg': 'Otros recursos faltaban'})

Los mensajes de registro se mostrarán de la siguiente manera:

WARNING: El recurso prettiest_cat.jpg falta
WARNING: El recurso best_cat_ever.jpg falta
WARNING: El recurso cutest_cat.jpg falta
WARNING: El recurso lolcat.jpg falta
WARNING: Otros recursos faltaban

Mostrar el traceback en los registros

Si está registrando dentro de un bloque except, es posible que también desee proporcionar información de traceback. Puede hacerlo estableciendo el argumento de palabra clave exc_info en True al registrar. Sin embargo, hacer esto por defecto puede ser indeseable porque los tracebacks son largos y pueden ser confusos para los usuarios normales. Intente limitarlos al modo --debug como se muestra a continuación:

try:
    alguna_accion()
except Exception as e:
    logger.error('Ocurrió una excepción: %s', e,
        exc_info=settings.get('DEBUG', False))

Internos de Pelican

Esta sección describe cómo funciona Pelican internamente. Como verá, es bastante simple, pero un poco de documentación no hace daño. :)

También puede encontrar en la sección Alguna historia sobre Pelican un extracto de un informe que el autor original escribió con alguna información de diseño de software.

Estructura general

Lo que hace Pelican es tomar una lista de archivos y procesarlos en algún tipo de salida. Normalmente, los archivos de entrada son archivos reStructuredText y Markdown, y la salida es un blog, pero tanto la entrada como la salida pueden ser lo que quiera.

La lógica está separada en diferentes clases y conceptos:

  • Los Writers (Escritores) son responsables de escribir archivos: archivos .html, feeds RSS, etc. Dado que estas operaciones se usan comúnmente, el objeto se crea una vez y luego se pasa a los generadores.
  • Los Readers (Lectores) se utilizan para leer desde varios formatos (HTML, Markdown y reStructuredText por ahora, pero el sistema es extensible). Dado un archivo, devuelven metadatos (autor, etiquetas, categoría, etc.) y contenido (formato HTML).
  • Los Generators (Generadores) generan las diferentes salidas. Por ejemplo, Pelican viene con ArticlesGenerator y PageGenerator. Dado un archivo de configuración, pueden hacer lo que quieran. La mayoría de las veces, se trata de generar archivos a partir de entradas.
  • Pelican también utiliza plantillas, por lo que es fácil escribir su propio tema. La sintaxis es Jinja2 y es muy fácil de aprender, así que no dude en empezar y crear su propio tema.

¿Cómo implementar un nuevo lector?

¿Hay algún lenguaje de marcado impresionante que quiera añadir a Pelican? Bueno, lo único que tiene que hacer es crear una clase con un método read que devuelva contenido HTML y algunos metadatos.

Eche un vistazo al lector de Markdown:

from pelican.readers import BaseReader
from pelican.utils import pelican_open
from markdown import Markdown
class MarkdownReader(BaseReader):
    enabled = True
    def read(self, source_path):
        """Analiza el contenido y los metadatos de los archivos markdown"""
        with pelican_open(source_path) as text:
            md_extensions = {'markdown.extensions.meta': {},
                             'markdown.extensions.codehilite': {}}
            md = Markdown(extensions=md_extensions.keys(),
                          extension_configs=md_extensions)
            content = md.convert(text)
        metadata = {}
        for name, value in md.Meta.items():
            name = name.lower()
            meta = self.process_metadata(name, value[0])
            metadata[name] = meta
        return content, metadata

Simple, ¿no?

Si su nuevo lector requiere dependencias adicionales de Python, entonces debería envolver sus declaraciones import en un bloque try...except. Luego, dentro de la clase del lector, establezca el atributo de clase enabled para marcar el éxito o fracaso de la importación. Esto permite a los usuarios seguir usando su método de marcado favorito sin necesidad de instalar módulos para formatos que no usan.

Internamente, se sigue el siguiente proceso:

  • Primero, se analiza la línea de comandos y se utiliza contenido del usuario para inicializar los diferentes objetos generadores.
  • Se crea un contexto. Contiene la configuración de la línea de comandos y un archivo de configuración si se proporciona.
  • Se llama al método generate_context de cada generador, actualizando el contexto.
  • Se crea el escritor y se entrega al método generate_output de cada generador.

Hago dos llamadas porque es importante que cuando la salida sea generada por los generadores, el contexto no cambie. En otras palabras, el primer método generate_context debe modificar el contexto, mientras que el segundo método generate_output no debería.

  • Lee la carpeta "path", buscando archivos de texto reestructurado, los carga y construye un objeto de contenido (Article) con él. Para hacer esto, utiliza objetos Reader.
  • Actualiza el contexto con todos esos artículos.

Luego, el método generate_content utiliza el contexto y el escritor para generar la salida deseada.

NAME

pelican - static site generator

DESCRIPTION

Pelican is a static site generator, written in Python. It has a simple and elegant design, is extensible and fast. Pelican reads your content, applies a theme, and generates a full static website, ready to be deployed on any web server. The generated website can be plain HTML or a blog, with articles, tags, categories, archives, feeds, comments, and more.

You can write your content in Markdown, reStructuredText, or AsciiDoc. Pelican supports themes, allowing you to easily change the look and feel of your website. It can generate different types of feeds (Atom, RSS) and supports various plugins that extend its functionality.

This document describes the release history of Pelican.
