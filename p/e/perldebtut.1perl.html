NOMBRE

perldebtut - Tutorial de depuración de Perl

DESCRIPCIÓN

Una introducción (muy) ligera al uso del depurador de Perl, y un enlace a fuentes de información existentes y más profundas sobre el tema de la depuración de programas de Perl.

Hay una cantidad extraordinaria de personas que no parecen saber nada sobre el uso del depurador de Perl, aunque usen el lenguaje todos los días. Esto es para ellas.

use strict

En primer lugar, hay algunas cosas que puedes hacer para que tu vida sea mucho más sencilla en lo que respecta a la depuración de programas de Perl, sin usar el depurador en absoluto. Para demostrarlo, aquí tienes un script simple, llamado "hello", con un problema:

#!/usr/bin/perl
$var1 = 'Hello World'; # siempre quise hacer eso :-)
$var2 = "$varl\n";
print $var2; 
exit;

Si bien esto compila y se ejecuta sin problemas, probablemente no hará lo que se espera, es decir, no imprimirá "Hello World\n" en absoluto; En cambio, hará exactamente lo que se le dijo que hiciera, las computadoras tienden a ser un poco así. Es decir, imprimirá un carácter de nueva línea, y obtendrás lo que parece una línea en blanco. Parece que hay 2 variables cuando (debido al error tipográfico) en realidad hay 3:

$var1 = 'Hello World';
$varl = undef;
$var2 = "\n";

Para detectar este tipo de problemas, podemos forzar que cada variable se declare antes de su uso al importar el módulo strict, colocando 'use strict;' después de la primera línea del script.

Ahora, cuando lo ejecutes, Perl se quejará de las 3 variables no declaradas y obtendremos cuatro mensajes de error porque una variable se referencia dos veces:

Global symbol "$var1" requires explicit package name at ./t1 line 4.
Global symbol "$var2" requires explicit package name at ./t1 line 5.
Global symbol "$varl" requires explicit package name at ./t1 line 5.
Global symbol "$var2" requires explicit package name at ./t1 line 7.
Execution of ./hello aborted due to compilation errors.

¡Encantador! Y para solucionarlo, declaramos todas las variables explícitamente y ahora nuestro script se ve así:

#!/usr/bin/perl
use strict;
my $var1 = 'Hello World';
my $varl = undef;
my $var2 = "$varl\n";
print $var2; 
exit;

Luego, hacemos (siempre es una buena idea) una verificación de sintaxis antes de intentar ejecutarlo de nuevo:

> perl -c hello
hello syntax OK

Y ahora, cuando lo ejecutamos, todavía obtenemos "\n", pero al menos sabemos por qué. El simple hecho de que este script se compile ha expuesto la variable '$varl' (con la letra 'l'), y simplemente cambiar $varl a $var1 resuelve el problema.

Mirando datos y -w y v

Ok, pero ¿qué pasa cuando quieres ver realmente tus datos, qué hay en esa variable dinámica, justo antes de usarla?

#!/usr/bin/perl 
use strict;
my $key = 'welcome';
my %data = (
        'this' => qw(that), 
        'tom' => qw(and jerry),
        'welcome' => q(Hello World),
        'zip' => q(welcome),
);
my @data = keys %data;
print "$data{$key}\n";
exit;

Parece bien, después de haber pasado por la verificación de sintaxis (perl -c nombre_script), lo ejecutamos y todo lo que obtenemos es una línea en blanco de nuevo. Hmmmm.

Un enfoque de depuración común aquí sería salpicar liberalmente algunas sentencias de impresión, para agregar una verificación justo antes de imprimir nuestros datos, y otra justo después:

print "All OK\n" if grep($key, keys %data);
print "$data{$key}\n";
print "done: '$data{$key}'\n";

Y probamos de nuevo:

> perl data
All OK     
done: ''

Después de mucho mirar el mismo fragmento de código y no ver el bosque por los árboles durante un tiempo, tomamos una taza de café y probamos otro enfoque. Es decir, traemos la caballería dándole a Perl el modificador '-d' en la línea de comandos:

> perl -d data 
Default die handler restored.
Loading DB routines from perl5db.pl version 1.07
Editor support available.
Enter h or `h h' for help, or `man perldebug' for more help.
main::(./data:4):    my $key = 'welcome';

Ahora, lo que hemos hecho aquí es lanzar el depurador incorporado de Perl en nuestro script. Se ha detenido en la primera línea de código ejecutable y está esperando entrada.

Antes de ir más lejos, querrás saber cómo salir del depurador: usa solo la letra 'q', no las palabras 'quit' o 'exit':

DB<1> q
>

Eso es todo, has vuelto a tu territorio de nuevo.

¡Más opciones confusas de las que puedes agitar un palo grande! No es tan malo como parece y es muy útil saber más sobre todo ello, ¡y también es divertido!

Hay un par de opciones útiles que debes conocer de inmediato. No pensarías que estamos usando ninguna biblioteca en este momento, pero 'M' mostrará qué módulos están cargados actualmente y su número de versión, mientras que 'm' mostrará los métodos, y 'S' muestra todas las subrutinas (por patrón) como se muestra a continuación. 'V' y 'X' muestran variables en el programa por alcance de paquete y pueden ser restringidas por patrón.

DB<2>S str 
dumpvar::stringify
strict::bits
strict::import
strict::unimport

Usar 'X' y sus derivados requiere que no uses los identificadores de tipo ($@%), solo el 'nombre':

DM<3>X ~err
FileHandle(stderr) => fileno(2)

Recordemos que estamos en nuestro pequeño programa con un problema, deberíamos echar un vistazo a dónde estamos y cómo se ven nuestros datos. Primero, veamos algo de código en nuestra posición actual (la primera línea de código en este caso), a través de 'v':

DB<4> v

Un recorrido rápido

Este es un pequeño programa que imprime un montón de cosas. Puede que tenga un problema, o quizás no. Si desea ver más, puede decir 'v' para ver más código:

   1: #!/usr/bin/perl
   2: use strict;
   3: use warnings;
   4: my $key = 'welcome';
   5: my %data = (
   6:               'this' => qw(that),
   7               'tom' => qw(and jerry),
   8               'welcome' => q(Hello World),
   9               'zip' => q(welcome),
  10:     );

En la línea número 4 hay un puntero útil, que te dice dónde estás ahora. Para ver más código, escribe 'v' de nuevo:

DB<4> v
8               'welcome' => q(Hello World),
9               'zip' => q(welcome),
10      );
11:     my @data = keys %data;
12:     print "All OK\n" if grep($key, keys %data);
13:     print "$data{$key}\n";
14:     print "done: '$data{$key}'\n";
15:     exit;

Y si quisieras listar la línea 5 de nuevo, escribe 'l 5', (nota el espacio):

DB<4> l 5
5:      my %data = (

En este caso, no hay mucho que ver, pero por supuesto normalmente hay páginas de cosas para revisar, y 'l' puede ser muy útil. Para restablecer tu vista a la línea que vamos a ejecutar, escribe un punto solo '.':

DB<5> .
main::(./data_a:4):     my $key = 'welcome';

La línea que se muestra es la que está a punto de ser ejecutada a continuación, aún no ha ocurrido. Así que, aunque podemos imprimir una variable con la letra 'p', en este punto todo lo que obtendríamos sería un valor vacío (indefinido). Lo que necesitamos hacer es pasar a la siguiente instrucción ejecutable con una 's':

DB<6> s
main::(./data_a:5):     my %data = (
main::(./data_a:6):             'this' => qw(that),
main::(./data_a:7):             'tom' => qw(and jerry),
main::(./data_a:8):             'welcome' => q(Hello World),
main::(./data_a:9):             'zip' => q(welcome),
main::(./data_a:10):    );

Ahora podemos echar un vistazo a esa primera variable ($key):

DB<7> p $key
welcome

La línea 13 es donde está la acción, así que continuemos hasta allí con la letra 'c', que por cierto, inserta un punto de interrupción 'solo una vez' en la línea o subrutina dada:

DB<8> c 13
All OK
main::(./data_a:13):    print "$data{$key}\n";

Hemos pasado nuestra verificación (donde se imprimió 'All OK') y nos hemos detenido justo antes del meollo de nuestra tarea. Podríamos intentar imprimir un par de variables para ver qué está pasando:

DB<9> p $data{$key}

No hay mucho ahí, veamos nuestro hash:

DB<10> p %data
Hello Worldziptomandwelcomejerrywelcomethisthat
DB<11> p keys %data
Hello Worldtomwelcomejerrythis

Bueno, esto no es muy fácil de leer, y usando el manual útil (h h), el comando 'x' parece prometedor:

DB<12> x %data
0  'Hello World'
1  'zip'
2  'tom'
3  'and'
4  'welcome'
5  undef
6  'jerry'
7  'welcome'
8  'this'
9  'that'

Eso no ayuda mucho, un par de 'welcomes' ahí, pero sin indicación de cuáles son las claves y cuáles los valores, es solo un volcado de array listado y, en este caso, no particularmente útil. El truco aquí es usar una referencia a la estructura de datos:

DB<13> x \%data
0  HASH(0x8194bc4)
   'Hello World' => 'zip'
   'jerry' => 'welcome'
   'this' => 'that'
   'tom' => 'and'
   'welcome' => undef

La referencia se ha volcado por completo y finalmente podemos ver con qué estamos tratando. Nuestra cita fue perfectamente válida pero incorrecta para nuestros propósitos, con 'and jerry' siendo tratado como 2 palabras separadas en lugar de una frase, lo que desalinea la estructura del hash emparejada uniformemente.

El modificador '-w' nos habría informado de esto, si lo hubiéramos usado al principio, y nos habría ahorrado muchos problemas:

> perl -w data
Odd number of elements in hash assignment at ./data line 5.

Arreglamos nuestras citas: 'tom' => q(and jerry), y lo ejecutamos de nuevo, esta vez obtenemos nuestra salida esperada:

> perl -w data
Hello World

Mientras estamos aquí, echemos un vistazo más de cerca al comando 'x', es realmente útil y volcará alegremente referencias anidadas, objetos completos, objetos parciales, ¡casi cualquier cosa que le lances!

Hagamos un objeto rápido y lo explotemos, primero iniciaremos el depurador: necesita alguna forma de entrada de STDIN, así que le damos algo no comprometedor, un cero:

> perl -de 0
Default die handler restored.
Loading DB routines from perl5db.pl version 1.07
Editor support available.
Enter h or `h h' for help, or `man perldebug' for more help.
main::(-e:1):   0

Ahora construimos un objeto sobre la marcha en un par de líneas (nota la barra invertida):

DB<1> $obj = bless({'unique_id'=>'123', 'attr'=> \
cont:  {'col' => 'black', 'things' => [qw(this that etc)]}}, 'MY_class')

Y echemos un vistazo:

       DB<2> x $obj

               'attr' => HASH(0x828ad68)

Paso a paso por el código

Aquí hay un programa simple que convierte entre Celsius y Fahrenheit, también tiene un problema:

#!/usr/bin/perl
use v5.36;
my $arg = $ARGV[0] || '-c20';
if ($arg =~ /^\-(c|f)((\-|\+)*\d+(\.\d+)*)$/) {
       my ($deg, $num) = ($1, $2);
       my ($in, $out) = ($num, $num);
       if ($deg eq 'c') {
               $deg = 'f';
               $out = &c2f($num);
       } else {
               $deg = 'c';
               $out = &f2c($num);
       }
       $out = sprintf('%0.2f', $out);
       $out =~ s/^((\-|\+)*\d+)\.0+$/$1/;
       print "$out $deg\n";
} else {
       print "Usage: $0 -[c|f] num\n";
}
exit;
sub f2c {
       my $f = shift;
       my $c = 5 * $f - 32 / 9;
       return $c;
}
sub c2f {
       my $c = shift;
       my $f = 9 * $c / 5 + 32;
       return $f;
}

Por alguna razón, la conversión de Fahrenheit a Celsius no devuelve la salida esperada. Esto es lo que hace:

> temp -c0.72
33.30 f
> temp -f33.3
162.94 c

¡No muy consistente! Estableceremos un punto de interrupción en el código manualmente y lo ejecutaremos bajo el depurador para ver qué está sucediendo. Un punto de interrupción es una bandera, hasta la cual el depurador se ejecutará sin interrupción, cuando alcance el punto de interrupción, detendrá la ejecución y ofrecerá un prompt para interacción adicional. En uso normal, estos comandos del depurador son completamente ignorados, y son seguros, aunque un poco desordenados, para dejarlos en código de producción.

my ($in, $out) = ($num, $num);
$DB::single=2; # ¡insertar en la línea 9!
if ($deg eq 'c')
        ...
> perl -d temp -f33.3
Default die handler restored.
Loading DB routines from perl5db.pl version 1.07
Editor support available.
Enter h or `h h' for help, or `man perldebug' for more help.
main::(temp:4): my $arg = $ARGV[0] || '-c100';

Simplemente continuaremos hasta nuestro punto de interrupción preestablecido con una 'c':

DB<1> c
main::(temp:10):                if ($deg eq 'c') {

Seguido de un comando de vista para ver dónde estamos:

DB<1> v
7:              my ($deg, $num) = ($1, $2);
8:              my ($in, $out) = ($num, $num);
9:              $DB::single=2;
10==>           if ($deg eq 'c') {
11:                     $deg = 'f';
12:                     $out = &c2f($num);
13              } else {
14:                     $deg = 'c';
15:                     $out = &f2c($num);
16              }

Y una impresión para mostrar qué valores estamos usando actualmente:

DB<1> p $deg, $num
f33.3

Podemos poner otro punto de interrupción en cualquier línea que comience con dos puntos, usaremos la línea 17 ya que es justo al salir de la subrutina, y nos gustaría pausar allí más tarde:

DB<2> b 17

No hay retroalimentación de esto, pero puedes ver qué puntos de interrupción están establecidos usando el comando de lista 'L':

DB<3> L
temp:
        17:            print "$out $deg\n";
        break if (1)

Nota que para eliminar un punto de interrupción usas 'B'.

Ahora continuaremos hacia nuestra subrutina, esta vez en lugar de por número de línea, usaremos el nombre de la subrutina, seguido del ya familiar 'v':

DB<3> c f2c
main::f2c(temp:30):             my $f = shift;
DB<4> v
24:     exit;
25
26      sub f2c {
27==>           my $f = shift;
28:             my $c = 5 * $f - 32 / 9;
29:             return $c;
30      }
31
32      sub c2f {
33:             my $c = shift;

Nota que si hubiera una llamada a subrutina entre nosotros y la línea 29, y quisiéramos avanzar paso a paso a través de ella, podríamos usar el comando 's', y para saltarla usaríamos 'n' que ejecutaría la sub, pero no descendería en ella para inspección. En este caso, sin embargo, simplemente continuamos hasta la línea 29:

DB<4> c 29
main::f2c(temp:29):             return $c;

Y veamos el valor de retorno:

DB<5> p $c
162.944444444444

Esta no es la respuesta correcta en absoluto, pero la suma parece correcta. Me pregunto si tiene algo que ver con la precedencia de operadores? Probaremos un par de otras posibilidades con nuestra suma:

DB<6> p (5 * $f - 32 / 9)
162.944444444444
DB<7> p 5 * $f - (32 / 9)
162.944444444444
DB<8> p (5 * $f) - 32 / 9
162.944444444444
DB<9> p 5 * ($f - 32) / 9
0.722222222222221

:-) ¡eso se parece más! Ok, ahora podemos establecer nuestra variable de retorno y saldremos de la sub con una 'r':

DB<10> $c = 5 * ($f - 32) / 9
DB<11> r
scalar context return from main::f2c: 0.722222222222221

CONSEJOS DE SALIDA

Para obtener toda la salida de tu archivo de registro de errores, y no perderte ningún mensaje debido al útil almacenamiento en búfer del sistema operativo, inserta una línea como esta al principio de tu script:

$|=1;

Para ver la cola de un archivo de registro que crece dinámicamente (desde la línea de comandos):

tail -f $error_log

Encapsular todas las llamadas a `die` en una rutina de manejo puede ser útil para ver cómo y desde dónde se están llamando. perlvar tiene más información:

BEGIN { $SIG{__DIE__} = sub { require Carp; Carp::confess(@_) } }

Se explican varias técnicas útiles para la redirección de los manejadores de archivos STDOUT y STDERR en perlopentut y perlfaq8.

CGI

Solo una breve pista aquí para todos esos programadores de CGI que no pueden averiguar cómo demonios superar esa indicación de 'esperando entrada' al ejecutar su script CGI desde la línea de comandos, prueba algo como esto:

> perl -d my_cgi.pl -nodebug

Por supuesto, CGI y perlfaq9 te dirán más.

GUI

La interfaz de línea de comandos está estrechamente integrada con una extensión de emacs y también hay una interfaz de vi.

Sin embargo, no tienes que hacer todo esto en la línea de comandos; hay algunas opciones de GUI disponibles. Lo bueno de estas es que puedes pasar el ratón sobre una variable y se mostrará una instantánea de sus datos en una ventana apropiada, o en un globo emergente, ¡adiós a la tediosa escritura de 'x $nombre_variable'! :-)

En particular, busca lo siguiente:

ptkdb: envoltorio basado en perlTK para el depurador incorporado

ddd: depurador de visualización de datos

PerlDevKit y PerlBuilder son específicos de NT

RESUMEN

Hemos visto cómo fomentar buenas prácticas de codificación con use strict y -w. Podemos ejecutar el depurador de perl perl -d nombre_script para inspeccionar tus datos dentro del depurador de perl con los comandos p y x. Puedes recorrer tu código, establecer puntos de interrupción con b y avanzar por ese código con s o n, continuar con c y retornar de una subrutina con r. Cosas bastante intuitivas cuando te pones a ello.

Por supuesto, hay mucho más por descubrir; esto solo ha arañado la superficie. La mejor manera de aprender más es usar perldoc para obtener más información sobre el lenguaje, leer la ayuda en línea (perldebug es probablemente el próximo lugar al que ir) y, por supuesto, experimentar.
