NOMBRE

perl5320delta - Novedades de la versión perl v5.32.0

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.30.0 y la versión 5.32.0.

Si está actualizando desde una versión anterior como la 5.28.0, primero lea perl5300delta, que describe las diferencias entre 5.28.0 y 5.30.0.

Mejoras del núcleo

El operador isa

Se ha introducido un nuevo operador infijo experimental llamado "isa" que comprueba si un objeto dado es una instancia de una clase dada o de una clase derivada de ella:

if( $obj isa Paquete::Nombre ) { ... }

Para más detalles, consulte "Class Instance Operator" en perlop.

Unicode 13.0 es compatible

Consulte https://www.unicode.org/versions/Unicode13.0.0/ para obtener detalles.

Capacidad de comparaciones encadenadas

Algunos operadores de comparación, junto con su asociatividad, se encadenan con algunos operadores de la misma precedencia (pero nunca con operadores de diferente precedencia).

if ( $x < $y <= $z ) {...}

se comporta exactamente como:

if ( $x < $y && $y <= $z ) {...}

(suponiendo que "$y" es un escalar tan simple como parece).

Puede leer más sobre esto en perlop bajo "Operator Precedence and Associativity" en perlop.

Nuevas propiedades Unicode "Identifier_Status" y "Identifier_Type" compatibles

Unicode ha revisado sus requisitos de expresiones regulares: https://www.unicode.org/reports/tr18/tr18-21.html. Como parte de eso, quieren que se expongan más propiedades, que no forman parte de la base de datos estricta de caracteres Unicode (UCD). Estas dos se utilizan para examinar las entradas con fines de seguridad. Los detalles sobre su uso se encuentran en https://www.unicode.org/reports/tr39/.

Ahora es posible escribir "qr/\p{Name=...}/", o "qr!\p{na=/(SMILING|GRINNING)_FACE/}!"

La propiedad de Nombre Unicode ahora es accesible en patrones de expresiones regulares, como alternativa a "\N{...}". Se proporciona una comparación de ambos métodos en "Comparison of \N{...} and \p{name=...}" en perlunicode.

El segundo ejemplo anterior muestra que los subpatrones comodín también se pueden utilizar en esta propiedad. Consulte "Wildcards in Property Values" en perlunicode.

Mejora de POSIX::mblen(), "mbtowc", y "wctomb"

Las funciones POSIX::mblen(), "mbtowc" y "wctomb" ahora funcionan con locales de estado de cambio y son seguras para hilos en compiladores C99 y superiores cuando se ejecutan en una plataforma con seguridad de hilos para locales; los parámetros de longitud ahora son opcionales.

Estas funciones se ejecutan siempre bajo la configuración regional del lenguaje C actual. (Consulte perllocale). La mayoría de las configuraciones regionales no tienen estado, pero algunas, especialmente las de ISO 2022 que se encuentran muy raramente, mantienen un estado entre llamadas a estas funciones. Anteriormente, el estado se reiniciaba en cada llamada, pero ahora el estado no se restablece a menos que el parámetro apropiado sea "undef".

En Perl con hilos, las funciones C99 mbrlen(3), mbrtowc(3) y wcrtomb(3), cuando están disponibles, se sustituyen por las funciones normales. Esto hace que estas funciones sean seguras para hilos cuando se ejecutan en una plataforma segura para hilos de configuración regional.

Los parámetros de longitud de cadena en "mblen" y "mbtowc" ahora son opcionales; son útiles solo si desea restringir la longitud analizada en la cadena de origen a menos que la longitud real.

Las aserciones alfabéticas ya no son experimentales

Consulte "(*pla:pattern)" en perlre, "(*plb:pattern)" en perlre, "(*nla:pattern)" en perlre y "(*nlb:pattern)" en perlre. El uso de estas ya no genera una advertencia; el código existente que deshabilita la categoría de advertencia "experimental::alpha_assertions" continuará funcionando sin necesidad de cambios. Habilitar la categoría no tiene ningún efecto.

Las ejecuciones de scripts ya no son experimentales

Consulte "Script Runs" en perlre. El uso de estas ya no genera una advertencia; el código existente que deshabilita la categoría de advertencia "experimental::script_run" continuará funcionando sin necesidad de cambios. Habilitar la categoría no tiene ningún efecto.

Las comprobaciones de características son ahora más rápidas

Anteriormente, las comprobaciones de características en el analizador requerían una búsqueda en tabla hash cuando las características se establecían fuera de un paquete de características, esto se ha optimizado a una comprobación de máscara de bits. [GH #17229 https://github.com/Perl/perl5/issues/17229]

Perl se desarrolla ahora en GitHub

Perl ahora se desarrolla en GitHub. Puede encontrarnos en https://github.com/Perl/perl5.

Los errores que no sean de seguridad ahora deben informarse a través de GitHub. Los problemas de seguridad deben seguir informándose como se documenta en perlsec.

Los patrones compilados ahora se pueden volcar antes de la optimización

Esto es principalmente útil para rastrear errores en el compilador de expresiones regulares. Este volcado ocurre en Perl con "-DDEBUGGING", si especifica "-Drv" en la línea de comandos; o en cualquier Perl si el patrón se compila dentro del ámbito de "use re qw(Debug DUMP_PRE_OPTIMIZE)" o "use re qw(Debug COMPILE EXTRA)". (Todos menos el segundo caso muestran también otra información).

Seguridad

[CVE-2020-10543] Desbordamiento de búfer causado por una expresión regular manipulada

Un desbordamiento de entero con signo de "size_t" en los cálculos de espacio de almacenamiento para cuantificadores de expresiones regulares anidados podría causar un desbordamiento de búfer en el montón en el compilador de expresiones regulares de Perl, sobrescribiendo memoria asignada después del espacio de almacenamiento de la expresión regular con datos suministrados por el atacante.

El sistema de destino necesita una cantidad suficiente de memoria para asignar expansiones parciales de los cuantificadores anidados antes de que ocurra el desbordamiento. Es poco probable que este requisito se cumpla en sistemas de 64 bits.

Descubierto por: ManhND del Equipo Tarantula, VinCSS (miembro de Vingroup).

Security Fixes

[CVE-2020-26558] Stack overflow via malformed bytecode produced by a crafted regular expression

Integer overflows in the calculation of offsets between instructions for the regular expression engine could cause corruption of the intermediate language state of a compiled regular expression. An attacker could abuse this behaviour to insert instructions into the compiled form of a Perl regular expression.

Discovered by: Hugo van der Sanden and Slaven Rezic.

[CVE-2020-12723] Buffer overflow caused by a crafted regular expression

Recursive calls to S_study_chunk() by Perl's regular expression compiler to optimize the intermediate language representation of a regular expression could cause corruption of the intermediate language state of a compiled regular expression.

Discovered by: Sergey Aleynikov.

Nota adicional

Una aplicación escrita en Perl solo sería vulnerable a cualquiera de las fallas anteriores si evalúa expresiones regulares proporcionadas por el atacante. Evaluar expresiones regulares de esta manera se sabe que es peligroso, ya que el motor de expresiones regulares no protege contra ataques de denegación de servicio en este escenario de uso.

Cambios incompatibles

Ciertas características de coincidencia de patrones ahora están prohibidas al compilar subpatrones comodín de valor de propiedad Unicode

Estas pocas características son inapropiadas o interfieren con el algoritmo utilizado para lograr esta tarea. La lista completa se encuentra en "Wildcards in Property Values" en perlunicode.

Se eliminan las funciones no utilizadas "POSIX::mbstowcs" y "POSIX::wcstombs"

Estas funciones nunca podrían haber funcionado debido a una especificación de interfaz defectuosa. Claramente no hay demanda para ellas, dado que nadie se ha quejado en los muchos años que las funciones supuestamente estuvieron disponibles, por lo tanto, el llamado "soporte" para ellas ahora se elimina.

Una corrección de error para "(?[...])" puede haber hecho que algunos patrones ya no compilen

Ver "Selección de correcciones de errores". Las heurísticas utilizadas anteriormente pueden haber permitido compilar algunas construcciones (quizás no con el efecto previsto por el programador) que deberían haber sido errores. No se conocen, pero es posible que algunas construcciones erróneas ya no compilen.

"\p{user-defined}" properties now always override official Unicode ones

Anteriormente, si y solo si una propiedad definida por el usuario se declaraba antes de la compilación del patrón de expresión regular que la contenía, se utilizaba su definición en lugar de cualquier propiedad Unicode oficial con el mismo nombre. Ahora, siempre anula la propiedad oficial. Este cambio podría romper el código existente que dependía (probablemente sin saberlo) del comportamiento anterior. Sin esta corrección, si Unicode lanzara una nueva versión con una nueva propiedad que tuviera el mismo nombre que la que habías estado usando durante mucho tiempo, tu programa fallaría cuando actualizaras a una versión de Perl que utilizara esa nueva versión de Unicode. Ver "User-Defined Character Properties" en perlunicode. [GH #17205 https://github.com/Perl/perl5/issues/17205]

Las variables modificables ya no están permitidas en las constantes

Código como:

my $var;
$sub = sub () { $var };

donde $var se hace referencia en otro lugar en algún tipo de contexto modificable, ahora produce una excepción cuando se define el sub.

Este error se puede evitar agregando un `return` a la definición del sub:

$sub = sub () { return $var };

Esto ha sido obsoleto desde Perl 5.22. [GH #17020 https://github.com/Perl/perl5/issues/17020]

El uso de "vec" en cadenas con puntos de código superiores a 0xFF está prohibido

Dichas cadenas se representan internamente en UTF-8, y "vec" es una operación orientada a bits que probablemente arrojará resultados inesperados en esas cadenas. Esto fue obsoleto en perl 5.28.0.

Uso de puntos de código superiores a 0xFF en operadores bit a bit de cadenas

Algunos usos de estos ya eran ilegales después de un ciclo de obsolescencia anterior. Los usos restantes ahora están prohibidos, habiendo sido obsoletos en perl 5.28.0. Ver perldeprecation.

Sys::Hostname::hostname() no acepta argumentos

Este uso fue obsoleto en perl 5.28.0 y ahora es fatal.

La cadena literal "0" ahora se trata como un número para el operador de rango

Anteriormente, un rango "0" .. "-1" producía un rango de cadenas numéricas de "0" a "99"; esto ahora produce una lista vacía, al igual que "0 .. -1". Esto también significa que "0" .. "9" ahora produce una lista de enteros, mientras que anteriormente producía una lista de cadenas.

Esto se debió a un caso especial que trataba las cadenas que comenzaban con "0" como cadenas, por lo que rangos como "00" .. "03" producían "00", "01", "02", "03", pero no manejaba especialmente la cadena "0". [GH #16770 https://github.com/Perl/perl5/issues/16770]

"\K" now disallowed in look-ahead and look-behind assertions

Esto se prohibió porque causa un comportamiento inesperado, y nadie pudo definir cuál debería ser el comportamiento deseado. [GH #14638 https://github.com/Perl/perl5/issues/14638]

Mejoras de rendimiento

  • "my_strnlen" se ha acelerado para sistemas que no tienen su propia implementación de "strnlen".
  • "grok_bin_oct_hex" (y por lo tanto, "grok_bin", "grok_oct" y "grok_hex") se han acelerado.
  • "grok_number_flags" se ha acelerado.
  • "sort" es ahora notablemente más rápido en casos como "sort {$a <=> $b}" o "sort {$b <=> $a}". [GH #17608 https://github.com/Perl/perl5/pull/17608]

    Adicionalmente, se han realizado los siguientes cambios seleccionados:

    perldebguts

    • Simplificar algunas definiciones de nodos regulares

      Actualizar las definiciones de "BOUND" y "NBOUND".

    • Agregar nodo regular ANYOFHs

      Este nodo es similar a "ANYOFHb", pero se usa cuando más de un byte inicial es el mismo en todos los puntos de código coincidentes.

      "ANYOFHb" se usa para evitar tener que convertir de UTF-8 a punto de código para algo que no coincidirá. Verifica que el primer byte en el objetivo codificado en UTF-8 sea el deseado, descartando así la mayoría de los puntos de código posibles.

    PERL VERSION 5.32.0

    Perl 5.32.0 is a stable release. This version brings a number of bug fixes and improvements over Perl 5.30.0.

    Changes since Perl 5.30.0

    • The behavior of "%{^CAPTURE}" and "@{^CAPTURE}" has been clarified. "%{^CAPTURE}" now only captures into a scalar context, while "@{^CAPTURE}" captures into an array context. This means that "%{^CAPTURE}" did not work if "@{^CAPTURE}" was mentioned first. Similarly for "%{^CAPTURE_ALL}" and "@{^CAPTURE_ALL}", though "[GH #17045]|https://github.com/Perl/perl5/issues/17045"]
    • Extraordinarily large (over 2GB) floating point format widths could cause an integer overflow in the underlying call to snprintf(), resulting in an assertion. Formatted floating point widths are now limited to the range of int, the return value of snprintf(). [#16881 https://github.com/Perl/perl5/issues/16881]
    • Parsing the following constructs within a sub-parse (such as with "${code here}" or "s/.../code here/e") has changed to match how they're parsed normally:
    • "print $fh ..." no longer produces a syntax error.
    • Code like "s/.../ ${time} /e" now properly produces an "Ambiguous use of ${time} resolved to $time at ..." warning when warnings are enabled.
    • "@x {"a"}" (with the space) in a sub-parse now properly produces a "better written as" warning when warnings are enabled.
    • Attributes can now be used in a sub-parse. [GH #16847] https://github.com/Perl/perl5/issues/16847
    • Incomplete hex and binary literals like "0x" and "0b" are now treated as if the "x" or "b" is part of the next token. [#17010 https://github.com/Perl/perl5/issues/17010]
    • A spurious ")" in a subparse, such as in "s/.../code here/e" or "...${code here}", no longer confuses the parser.

      Previously a subparse was bracketed with generated "(" and ")" tokens, so a spurious ")" would close the construct without doing the normal subparse clean up, confusing the parser and possible causing an assertion failure.

      Such constructs are now surrounded by artificial tokens that can't be included in the source. [GH #15814] https://github.com/Perl/perl5/issues/15814

    • Reference assignment of a sub, such as "\&foo = \&bar;", silently did nothing in the "[GH #16987]|https://github.com/Perl/perl5/issues/16987"]
    • sv_gets() now recovers better if the target SV is modified by a signal handler. [GH #16960] https://github.com/Perl/perl5/issues/16960
    • "readline @foo" now evaluates @foo in scalar context. Previously it would be evaluated in list context, and since readline() pops only one argument from the stack, the stack could underflow, or be left with unexpected values on the stack. [GH #16929] https://github.com/Perl/perl5/issues/16929
    • Parsing incomplete hex or binary literals was changed in 5.31.1 to treat such a literal as just the 0, leaving the following "x" or "b" to be parsed as part of the next token. This could lead to some silent changes in behaviour, so now incomplete hex or binary literals produce a fatal error. [GH #17010] https://github.com/Perl/perl5/issues/17010
    • eval_pv()'s croak_on_error flag will now throw even if the exception is a false overloaded value. [GH #17036] https://github.com/Perl/perl5/issues/17036
    • "INIT" blocks and the program itself are no longer run if exit(0) is called within a "BEGIN", "UNITCHECK" or "CHECK" block. [GH #1537] https://github.com/Perl/perl5/issues/1537
    • "open my $fh, ">>+", undef" now opens the temporary file in append mode: writes will seek to the end of file before writing. [GH #17058] https://github.com/Perl/perl5/issues/17058
    • Fixed a SEGV when searching for the source of an uninitialized value warning on an op whose subtree includes an OP_MULTIDEREF. [GH #17088] https://github.com/Perl/perl5/issues/17088

    Reporting Bugs

    If you find what you think is a bug, you might check the perl bug database at https://github.com/Perl/perl5/issues. There may also be information at http://www.perl.org/, the Perl Home Page.

    If you believe you have an unreported bug, please open an issue at https://github.com/Perl/perl5/issues. Be sure to trim your bug down to a tiny but sufficient test case.

    If the bug you are reporting has security implications which make it inappropriate to send to a public issue tracker, then see "SECURITY VULNERABILITY CONTACT INFORMATION" in perlsec for details of how to report the issue.
