PERLPRAGMA(1perl) Guía de referencia para programadores de Perl PERLPRAGMA(1perl)

NOMBRE

perlpragma - cómo escribir un pragma de usuario

DESCRIPCIÓN

Un pragma es un módulo que influye en algún aspecto del comportamiento de Perl en tiempo de compilación o en tiempo de ejecución, como "strict" o "warnings". Con Perl 5.10 ya no estás limitado a los pragmas incorporados; ahora puedes crear pragmas de usuario que modifican el comportamiento de las funciones de usuario dentro de un ámbito léxico.

Un ejemplo básico

Por ejemplo, supongamos que necesitas crear una clase que implemente operadores matemáticos sobrecargados, y te gustaría proporcionar tu propio pragma que funcione de manera similar a "use integer;" Te gustaría que este código

use MyMaths;
my $l = MyMaths->new(1.2);
my $r = MyMaths->new(3.4);
print "A: ", $l + $r, "\n";
use myint;
print "B: ", $l + $r, "\n";
{
    no myint;
    print "C: ", $l + $r, "\n";
}
print "D: ", $l + $r, "\n";
no myint;
print "E: ", $l + $r, "\n";

produjera la salida

A: 4.6
B: 4
C: 4.6
D: 4
E: 4.6

es decir, donde "use myint;" está en vigor, las operaciones de suma se fuerzan a entero, mientras que por defecto no lo están, y el comportamiento por defecto se restaura mediante "no myint;"

La implementación mínima del paquete "MyMaths" sería algo así:

package MyMaths;
use v5.36;
use myint();
use overload '+' => sub {
    my ($l, $r) = @_;
    # Pasar 1 para comprobar un nivel de llamada desde aquí
    if (myint::in_effect(1)) {
        int($$l) + int($$r);
    } else {
        $$l + $$r;
    }
};
sub new {
    my ($class, $value) = @_;
    bless \$value, $class;
}
1;

Observa cómo cargamos el pragma de usuario "myint" con una lista vacía "()" para evitar que se llame a su "import".

La interacción con la compilación de Perl ocurre dentro del paquete "myint":

package myint;
use v5.36;
sub import {
    $^H{"myint/in_effect"} = 1;
}
sub unimport {
    $^H{"myint/in_effect"} = 0;
}
sub in_effect {
    my $level = shift // 0;
    my $hinthash = (caller($level))[10];
    return $hinthash->{"myint/in_effect"};
}
1;

Como los pragmas se implementan como módulos, como cualquier otro módulo, "use myint;" se convierte en

BEGIN {
    require myint;
    myint->import();
}

y "no myint;" es

BEGIN {
    require myint;
    myint->unimport();
}

Por lo tanto, las rutinas "import" y "unimport" se llaman en tiempo de compilación para el código del usuario.

Los pragmas de usuario almacenan su estado escribiendo en el hash mágico "%^H", por lo tanto, estas dos rutinas lo manipulan. La información de estado en "%^H" se almacena en el optree y se puede recuperar de solo lectura en tiempo de ejecución con caller(), en el índice 10 de la lista de resultados devueltos. En el pragma de ejemplo, la recuperación se encapsula en la rutina in_effect(), que toma como parámetro el número de niveles de llamada a subir para encontrar el valor del pragma en el script del usuario. Esto utiliza caller() para determinar el valor de $^H{"myint/in_effect"} cuando se llamó a cada línea del script del usuario, y por lo tanto, proporcionar la semántica correcta en la subrutina que implementa la suma sobrecargada.

Nombramiento de claves

Solo existe un "%^H", pero arbitrariamente muchos módulos que quieren usar su semántica de ámbito. Para evitar pisarse los unos a los otros, deben asegurarse de usar claves diferentes en el hash. Por lo tanto, es convencional que un módulo use solo claves que comiencen con el nombre del módulo (el nombre de su paquete principal) y un carácter "/". Después de este prefijo identificador del módulo, el resto de la clave depende completamente del módulo: puede incluir cualquier carácter. Por ejemplo, un módulo "Foo::Bar" debería usar claves como "Foo::Bar/baz" y "Foo::Bar/$%/_!". Los módulos que siguen esta convención interactúan amigablemente entre sí.

El núcleo de Perl utiliza un puñado de claves en "%^H" que no siguen esta convención, porque son anteriores a ella. Las claves que siguen la convención no entrarán en conflicto con las claves históricas del núcleo.

Detalles de implementación

El optree se comparte entre hilos. Esto significa que existe la posibilidad de que el optree sobreviva al hilo particular (y, por lo tanto, a la instancia del intérprete) que lo creó, por lo que los escalares de Perl verdaderos no se pueden almacenar en el optree. En su lugar, se utiliza una forma compacta, que solo puede almacenar valores que son enteros (firmados y sin firmar), cadenas o "undef"; las referencias y los valores de punto flotante se convierten a cadenas. Si necesitas almacenar varios valores o estructuras complejas, deberías serializarlos, por ejemplo con "pack". La eliminación de una clave de hash de "%^H" se registra y, como siempre, se puede distinguir de la existencia de una clave con el valor "undef" con "exists".

No intentes almacenar referencias a estructuras de datos como enteros que se recuperan a través de "caller" y se convierten de nuevo, ya que esto no será seguro para hilos. Los accesos serían a la estructura sin bloqueo (lo que no es seguro para los escalares de Perl), y la estructura tendría que tener fugas o liberarse cuando su hilo creador termine, lo que podría ser antes de que se elimine el optree que la referencia, si otros hilos la sobreviven.
