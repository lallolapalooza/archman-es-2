PERLAIX(1perl) Guía de referencia del programador de Perl PERLAIX(1perl)

NOMBRE

perlaix - Perl versión 5 en sistemas AIX (UNIX) de IBM

DESCRIPCIÓN

Este documento describe varias características del sistema operativo AIX de IBM que afectarán a cómo se compila y/o ejecuta Perl versión 5 (en adelante, Perl).

Compilar Perl 5 en AIX

Para obtener información sobre compiladores en versiones antiguas de AIX, consulte "Compiling Perl 5 on older AIX versions up to 4.3.3".

Al compilar Perl, debe utilizar un compilador C ANSI. AIX no incluye un compilador C compatible con ANSI por defecto, pero existen compilaciones binarias de gcc para AIX ampliamente disponibles. Una versión de gcc también se incluye en la Caja de herramientas de AIX que se envía con AIX.

Compiladores soportados

Actualmente, todas las versiones de los compiladores C ANSI de IBM "xlc", "xlc_r", "cc", "cc_r" o "vac" funcionarán para construir Perl si dicho compilador funciona en su sistema.

Si planea enlazar Perl a algún módulo que requiera soporte de hilos, como DBD::Oracle, es mejor usar la versión _r del compilador. Esto no construirá un Perl con hilos, sino un Perl preparado para hilos. Consulte también "Perl con hilos" más adelante.

Al momento de escribir esto (2010-09), solo el compilador *IBM XL C for AIX* o *IBM XL C/C++* *for AIX* está soportado por IBM en AIX 5L/6.1/7.1.

Las siguientes versiones de compilador son actualmente soportadas por IBM:

IBM XL C e IBM XL C/C++ V8, V9, V10, V11

XL C for AIX está integrado en el compilador XL C/C++ for AIX y, por lo tanto, también está soportado.

Si elige XL C/C++ V9, necesita tener instalado APAR IZ35785, de lo contrario, SDBM_File integrado no se compilará correctamente debido a un error de optimización. Puede evitar este problema añadiendo -qipa a las opciones de optimización (-Doptimize='-O -qipa'). El PTF para APAR IZ35785, que resuelve este problema, está disponible en IBM (PTF de abril de 2009 para XL C/C++ Enterprise Edition para AIX, V9.0).

Si elige XL C/C++ V11, necesita tener instalado el PTF de abril de 2010 (o posterior), de lo contrario, no obtendrá una versión de Perl que funcione.

Perl puede compilarse con el compilador C ANSI de IBM o con gcc. Se recomienda el primero, ya que no solo puede compilar Perl sin dificultad, sino que también puede aprovechar las características que se enumeran más adelante y que requieren el uso de indicadores de línea de comandos específicos del compilador de IBM.

Si decide usar gcc, asegúrese de que su instalación sea reciente y completa, y lea el archivo INSTALL de Perl para obtener más detalles específicos de gcc. Informe de cualquier dificultad que haya tenido al equipo de desarrollo.

Incompatibilidad con lib gdbm de AIX Toolbox

Si la versión de lib gdbm de AIX Toolbox < 1.8.3-5 está instalada en su sistema, Perl no funcionará. Esta biblioteca contiene los archivos de cabecera /opt/freeware/include/gdbm/dbm.h|ndbm.h que entran en conflicto con las versiones del sistema AIX. La lib gdbm se eliminará automáticamente de las bibliotecas deseadas si se detecta la presencia de alguno de estos dos archivos de cabecera. Si desea compilar Perl con soporte GDBM, instale al menos gdbm-devel-1.8.3-5 (o superior).

Compilación de extensiones dinámicas en AIX

A partir de Perl 5.7.2 (y consecuentemente 5.8.x / 5.10.x / 5.12.x) y AIX 4.3 o superior, Perl utiliza la interfaz de carga dinámica nativa de AIX en el modo de enlace en tiempo de ejecución en lugar de la interfaz emulada que se utilizaba en las versiones anteriores de Perl 5.6.1 o, para versiones de AIX 4.2 y anteriores. Este cambio interrumpe la compatibilidad con módulos compilados de versiones anteriores de Perl. El cambio se realizó para hacer que Perl sea más compatible con otras aplicaciones como Apache/mod_perl que utilizan la interfaz nativa de AIX. Este cambio también permite el uso de código C++ con constructores y destructores estáticos en extensiones de Perl, lo cual no era posible usando la interfaz emulada.

Se recomienda encarecidamente utilizar la nueva interfaz.

Uso de archivos grandes con Perl

No debería presentar problemas.

Perl con hilos

No debería presentar problemas con AIX 5.1 / 5.2 / 5.3 / 6.1 / 7.1.

IBM utiliza el Perl del sistema AIX (V5.6.0 en AIX 5.1 y V5.8.2 en AIX 5.2 / 5.3 y 6.1; V5.8.8 en AIX 5.3 TL11 y AIX 6.1 TL4; V5.10.1 en AIX 7.1) para algunos scripts del sistema AIX. Si cambia los enlaces en /usr/bin del Perl del sistema AIX (/usr/opt/perl5) al Perl recién construido, obtendrá las mismas características que con el Perl del sistema AIX de IBM si se utilizan las opciones de hilos.

La compilación de Perl con hilos también funciona en AIX 5.1, pero la compilación de Perl de IBM (Perl v5.6.0) no tiene hilos en AIX 5.1.

Perl 5.12 y posteriores no son compatibles con el fileset perl.libext de IBM.

Perl de 64 bits

Si su sistema AIX está instalado con soporte de 64 bits, puede esperar que las configuraciones de 64 bits funcionen. Si desea usar Perl de 64 bits en AIX 6.1, necesita un APAR para un error en libc.a que afecta a las funciones (n)dbm_XXX. El número de APAR para este problema es IZ39077.

Si necesita más memoria (segmento de datos más grande) para sus programas Perl, puede configurar:

/etc/security/limits
default:                    (o su usuario)
    data = -1               (el valor por defecto es 262144 * 512 bytes)

Con la configuración por defecto, el tamaño se limita a 128 MB. El -1 elimina este límite. Si "make test" falla, modifique su /etc/security/limits como se indica arriba.

Long doubles

IBM denomina su implementación de long doubles de 128 bits, pero no es la IEEE de 128 bits ("doble precisión") que daría 116 bits de mantisa (ni está implementada en hardware), sino una implementación especial por software llamada "double-double", que proporciona 106 bits de mantisa.

Parece haber varios problemas en esta implementación de long double. Si Configure detecta esta incorrección, deshabilitará el soporte de long double. Esto se puede anular con explícito "-Duselongdouble" (o "-Dusemorebits", que habilita tanto long doubles como enteros de 64 bits). Si decide habilitar long doubles, para la mayoría de las cosas incorrectas Perl ha implementado soluciones alternativas, pero el manejo de los valores especiales infinito y NaN sigue siendo gravemente defectuoso: por ejemplo, infinito más cero da como resultado NaN.

Opciones Recomendadas AIX 5.1/5.2/5.3/6.1 y 7.1 (con hilos/32 bits)

Con las siguientes opciones, obtendrá una versión de Perl con hilos que pasa todas las pruebas de compilación en modo de 32 bits con hilos, que es la configuración predeterminada para las compilaciones de Perl que incluye AIX.

rm config.sh
./Configure \
-d \
-Dcc=cc_r \
-Duseshrplib \
-Dusethreads \
-Dprefix=/usr/opt/perl5_32

La opción -Dprefix instalará Perl en un directorio paralelo a la instalación de Perl del sistema IBM AIX.

Compilación de Perl 5 en AIX 7.1.0

Una regresión en AIX 7 provoca un fallo en `make test` en Time::Piece durante el horario de verano. APAR IV16514 proporciona la solución para esto. Una prueba rápida para ver si es necesario, asumiendo que actualmente es horario de verano en la Hora del Este, sería ejecutar " TZ=EST5 date +%Z ". Esto devolverá "EST" normalmente, pero nada si tiene el problema.

Compilación de Perl 5 en versiones anteriores de AIX hasta 4.3.3

Debido a que AIX 4.3.3 llegó al fin de servicio el 31 de diciembre de 2003, esta información se proporciona tal cual. Las versiones de Perl anteriores a Perl 5.8.9 se podían compilar en AIX hasta 4.3.3 con la siguiente configuración (su kilometraje puede variar):

Al compilar Perl, debe usar un compilador C ANSI. AIX no incluye un compilador C compatible con ANSI por defecto, pero las compilaciones binarias de gcc para AIX están ampliamente disponibles.

En el momento de escribir esto, AIX admite dos compiladores C nativos diferentes, por los que debe pagar: xlC y vac. Si decide usar alguno de estos dos (lo que es bastante más fácil que usar gcc), asegúrese de actualizar al último nivel de parche disponible. Actualmente:

xlC.C     3.1.4.10 o 3.6.6.0 o 4.0.2.2 o 5.0.2.9 o 6.0.0.3
vac.C     4.4.0.3  o 5.0.2.6 o 6.0.0.1

Tenga en cuenta que xlC tiene la versión del sistema operativo en el nombre a partir de la versión 4.0.2.0, por lo que encontrará xlC.C para AIX-5.0 como paquete

xlC.aix50.rte   5.0.2.0 o 6.0.0.3

Las subversiones no son las mismas "últimas" en todas las versiones del sistema operativo. Por ejemplo, el último xlC-5 en aix41 es 5.0.2.9, mientras que en aix43 es 5.0.2.7.

Perl se puede compilar tanto con el compilador C ANSI de IBM como con gcc. Se recomienda el primero, ya que no solo puede compilar Perl sin dificultad, sino que también puede aprovechar las características que se enumeran más adelante y que requieren el uso de indicadores de línea de comandos específicos del compilador de IBM.

Los niveles de parche del compilador de IBM 5.0.0.0 y 5.0.1.0 tienen errores de optimización del compilador que afectan a la compilación de perl.c y regcomp.c, respectivamente. Si la configuración de Perl detecta esos niveles de parche del compilador, la optimización se desactiva para los archivos de código fuente mencionados. Se recomienda actualizar al menos a la versión 5.0.2.0.

Si decide usar gcc, asegúrese de que su instalación sea reciente y completa, y lea el archivo INSTALL de Perl para obtener más detalles específicos de gcc. Informe de cualquier obstáculo que haya tenido al equipo de desarrollo.

Nivel del Sistema Operativo

Antes de instalar los parches del compilador C de IBM, debe conocer el nivel de parche del sistema operativo. El comando `oslevel` de IBM mostrará la base, pero no siempre está completo (en este ejemplo, oslevel muestra 4.3.NULL, mientras que el sistema podría ejecutar la mayor parte de 4.3.THREE):

# oslevel
4.3.0.0
# lslpp -l | grep 'bos.rte '
bos.rte           4.3.3.75  COMMITTED  Base Operating System Runtime
bos.rte            4.3.2.0  COMMITTED  Base Operating System Runtime
#

Lo mismo podría suceder con AIX 5.1 u otros niveles del sistema operativo. Como nota adicional, Perl no se puede compilar sin `bos.adt.syscalls` y `bos.adt.libm` instalados

# lslpp -l | egrep "syscalls|libm"
bos.adt.libm      5.1.0.25  COMMITTED  Base Application Development
bos.adt.syscalls  5.1.0.36  COMMITTED  System Calls Application
#

Compilación de Extensiones Dinámicas en AIX < 5L

AIX admite objetos cargables dinámicamente, así como bibliotecas compartidas. Las bibliotecas compartidas, por convención, terminan con el sufijo .a, lo que es un poco engañoso, ya que un archivo puede contener miembros estáticos y dinámicos. Para los objetos cargables dinámicamente de Perl, usamos el sufijo .so que también se usa en muchas otras plataformas.

Tenga en cuenta que a partir de Perl 5.7.2 (y en consecuencia 5.8.0) y AIX 4.3 o más reciente, Perl utiliza la interfaz de carga dinámica nativa de AIX en el llamado modo de enlace en tiempo de ejecución en lugar de la interfaz emulada que se usaba en las versiones de Perl 5.6.1 y anteriores o, para las versiones de AIX 4.2 y anteriores. Este cambio interrumpe la compatibilidad con módulos compilados de versiones anteriores de Perl. El cambio se realizó para hacer que Perl sea más compatible con otras aplicaciones como Apache/mod_perl que utilizan la interfaz nativa de AIX. Este cambio también permite el uso de código C++ con constructores y destructores estáticos en extensiones de Perl, lo que no era posible con la interfaz emulada.

El Compilador C ANSI de IBM

Se pueden usar todas las opciones predeterminadas para Configure.

Si ha elegido usar vac 4, asegúrese de ejecutar la versión 4.4.0.3. Las versiones anteriores causarán problemas más adelante. Para vac 5, asegúrese de ejecutar al menos la versión 5.0.1.0, pero se recomienda encarecidamente la versión 5.0.2.6 o superior. Tenga en cuenta que dado que IBM ha eliminado las versiones vac 5.0.2.1 a 5.0.2.5 del repositorio de software, estas versiones deben considerarse obsoletas.

NAME

perlaix - Perl build instructions and notes for AIX

DESCRIPTION

This document contains notes on building Perl on AIX. It covers potential issues and workarounds, as well as specific configurations.

A good starting point for obtaining the necessary compiler and tools for AIX can be found at:

http://www14.software.ibm.com/webapp/download/downloadaz.jsp

Click on "C for AIX" and follow the instructions.

The usenm option

If linking miniperl results in errors similar to this:

cc -o miniperl ... miniperlmain.o opmini.o perl.o ... -lm -lc ...

with messages like:

ld: 0711-317 ERROR: Undefined symbol: .aintl
ld: 0711-317 ERROR: Undefined symbol: .copysignl
ld: 0711-317 ERROR: Undefined symbol: .syscall
ld: 0711-317 ERROR: Undefined symbol: .eaccess
ld: 0711-317 ERROR: Undefined symbol: .setresuid
ld: 0711-317 ERROR: Undefined symbol: .setresgid
ld: 0711-317 ERROR: Undefined symbol: .setproctitle
ld: 0711-345 Use the -bloadmap or -bnoquiet option to obtain more
                                                           information.

You can try recompiling with the following commands:

make realclean
rm config.sh
./Configure -Dusenm ...

This instructs Configure to use the nm tool when scanning for library symbols, which is often not the default behavior on AIX.

Related to this, you should probably avoid using the -r option with Configure on AIX, as it can affect how the nm tool is utilized.

Using GNU's gcc for building Perl

Using gcc-3.x (tested with versions 3.0.4, 3.1, and 3.2) should work without extra configuration. Recent gcc-2.9 builds, available from IBM as part of their Linux compatibility packages, should also work. These packages can be found at:

http://www.ibm.com/servers/aix/products/aixos/linux/

Using Large Files with Perl < 5L

There should be no problems using large files with Perl versions prior to 5L.

Threaded Perl < 5L

Threads appear to function correctly. However, not all tests may pass when threads are used in conjunction with 64-bit configurations in current versions.

You might encounter a warning during a threaded build, similar to this:

"pp_sys.c", line 4640.39: 1506-280 (W) Function argument assignment
between types "unsigned char*" and "const void*" is not allowed.

The exact line number might differ. If you see a warning (W) originating from a line like this:

hent = PerlSock_gethostbyaddr(addr, (Netdb_hlen_t) addrlen, addrtype);

within the pp_ghostent function, it is safe to ignore. This warning arises because the reentrant variant of gethostbyaddr() has a slightly different prototype than its non-reentrant counterpart, but the difference is not significant in this context.

64-bit Perl < 5L

If your AIX system is installed with 64-bit support enabled, you can expect 64-bit configurations to work. Be aware that some tests might still fail when using 64-bit configurations combined with threads.

AIX 4.2 and extensions using C++ with statics

On AIX 4.2, Perl extensions that utilize C++ functions employing static variables might encounter issues where these static variables are not properly initialized. Newer AIX releases have resolved this by linking Perl with the libC_r library. However, on AIX 4.2, this library contains a known bug where time-related functions (such as time() and gettimeofday()) return incorrect values. Consequently, Perl is not linked against libC_r on AIX 4.2.
