NOMBRE

perl5380delta - qué hay de nuevo en la versión perl v5.38.0

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.36.0 y la versión 5.38.0.

Mejoras del núcleo

Nueva "class" Característica

Ahora está disponible una nueva sintaxis **experimental** para definir clases de objetos, donde los datos por instancia se almacenan en variables de tipo "field" que se comportan como variables léxicas.

use feature 'class';
class Point
{
    field $x;
    field $y;
    method zero { $x = $y = 0; }
}

Esto se describe con más detalle en perlclass. Las notas sobre los internos de su implementación y otros detalles relacionados se pueden encontrar en perlclassguts.

Esta sigue siendo una característica nueva y experimental, y está todavía muy en desarrollo. Será objeto de muchas más adiciones, refinamientos y modificaciones en futuras versiones. Al ser experimental, genera advertencias en la categoría de "experimental::class". Estas se pueden silenciar con una declaración de "no warnings".

use feature 'class';
no warnings 'experimental::class';

Unicode 15.0 se soporta

Ver https://www.unicode.org/versions/Unicode15.0.0/ para más detalles.

Las advertencias de deprecación ahora tienen subcategorías específicas

Todas las advertencias de deprecación ahora tienen su propia categoría de deprecación específica que se puede deshabilitar individualmente. Puede ver una lista de todas las características deprecadas en perldeprecation y en warnings. La siguiente lista es de warnings:

Todavía es posible deshabilitar todas las advertencias de deprecación en una sola declaración con

no warnings 'deprecated';

pero ahora es posible tener un control más granular. Como ha sido históricamente el caso, estas advertencias se habilitan automáticamente con

use warnings;

API %{^HOOK} introducida

Por diversas razones, puede ser difícil crear envolturas de subrutinas para algunas de las palabras clave de perl. Cualquier palabra clave que tenga un prototipo indefinido simplemente no se puede envolver con una subrutina, y algunas palabras clave que perl permite envolver son, en la práctica, muy difíciles de envolver. Por ejemplo, "require" es difícil de envolver; es posible, pero hacerlo cambia la profundidad de la pila, y los métodos estándar de exportación asumen que exportarán a un paquete a una cierta profundidad de pila, y la envoltura así cambiará dónde se exportan las funciones a menos que se implemente con mucho cuidado. Esto puede ser muy engorroso de manejar.

Por lo tanto, hemos introducido una nueva tabla hash llamada "%{^HOOK}" que está destinada a facilitar tales casos. Cuando una palabra clave admite algún tipo de gancho especial, el gancho vivirá en esta nueva tabla hash. Los ganchos en esta tabla hash se nombrarán según la función que los llama, seguidos de dos guiones bajos y luego la fase en la que se ejecutan, actualmente antes o después de que se ejecute la palabra clave.

En esta versión inicial, admitimos dos ganchos: "require__before" y "require__after". Estos se proporcionan para facilitar la realización de tareas antes y después de una declaración require.

Ver perlvar para más detalles.

PERL_RAND_SEED

Se añadió una nueva variable de entorno "PERL_RAND_SEED" que se puede utilizar para que un programa perl que utiliza "rand" sin usar explícitamente srand() o que utiliza srand() sin argumentos sea repetible. Ver perlrun. Esta característica se puede deshabilitar en tiempo de compilación pasando

-Accflags=-DNO_PERL_RAND_SEED

a Configure durante el proceso de compilación.

Expresiones predeterminadas de asignación definida-o y lógica-o en firmas

La expresión predeterminada para un parámetro de firma de subrutina ahora se puede asignar utilizando los operadores "//=" o "||=", para aplicar los valores predeterminados cada vez que el llamador proporcionó un valor indefinido o falso (respectivamente), en lugar de simplemente cuando el parámetro falta por completo. Para más detalles, consulte la documentación en perlsub.

Mejoras de @INC Hook y $INC e INCDIR

Los internos de los ganchos de @INC se han fortalecido para manejar varios casos límite y ya no deberían fallar o lanzar excepciones de aserción cuando los ganchos modifican @INC durante una operación de require. Como parte de esto, ahora nos aseguramos de que cada gancho se ejecute como máximo una vez durante una llamada a require, y que los directorios duplicados no activen sondeos de directorio adicionales.

Para proporcionar a los desarrolladores un mayor control sobre la búsqueda dinámica de módulos, ahora se admite un nuevo método de gancho "INCDIR". Un objeto que admita este método puede inyectarse en el array de @INC, y cuando se encuentre en el proceso de búsqueda de módulos, se ejecutará, al igual que se ejecutan los ganchos INC, y su valor de retorno se utilizará como una lista de directorios para buscar el módulo. Devolver una lista vacía actúa como una operación nula. Tenga en cuenta que, dado que cualquier referencia devuelta por este gancho se convertirán a cadena y se usarán como cadenas, no puede devolver un gancho para que se ejecute más tarde a través de esta API.

Cuando se llama a un gancho de @INC (ya sea "INC" o "INCDIR") durante require, la variable $INC se localizará para que sea el valor del índice de @INC del que provino el gancho. Si el gancho desea anular cuál debería ser el "siguiente" índice en @INC, puede actualizar $INC para que sea uno menos que el índice deseado ( "undef" es equivalente a -1). Esto permite que un gancho de @INC reescriba completamente el array @INC y haga que perl reinicie sus sondeos de directorio desde el principio de @INC.

Las referencias de CÓDIGO bendecidas en @INC que no admiten los métodos "INC" o "INCDIR" ya no activarán una excepción, y en su lugar se tratarán de la misma manera que las referencias de CÓDIGO no bendecidas, y se ejecutarán como si fueran un gancho "INC".

El flujo de control prohibido fuera de "defer" o "finally" ahora se detecta en tiempo de compilación

Está prohibido intentar salir de un bloque "defer" o "finally" mediante un flujo de control como "return" o "goto". Las versiones anteriores de perl solo podían detectar esto cuando se intentaba en tiempo de ejecución.

Novedades

Detección de errores en tiempo de compilación

Esta versión de perl añade detección en tiempo de compilación para muchos casos que pueden determinarse estáticamente. Esto puede significar que el código que compiló correctamente en una versión anterior de perl ahora se reporta como un error en tiempo de compilación con esta. Esto solo ocurre en casos donde de todos modos habría sido un error ejecutar el código; el error simplemente ocurre en un momento anterior.

Evaluación optimista en patrones

El uso de "(?{ ... })" y en un patrón deshabilita varias optimizaciones globalmente en ese patrón. Esto puede o no ser deseado por el programador. Esta versión añade el equivalente . La única diferencia es que no deshabilita ni deshabilitará ninguna optimización en el motor de expresiones regulares. Esto puede hacerlo más inestable en el sentido de que puede ser llamado más o menos veces en el futuro, sin embargo, el número de veces que se ejecuta coincidirá verdaderamente con el funcionamiento del motor de expresiones regulares. Por ejemplo, ciertos tipos de optimización se deshabilitan cuando se incluye en un patrón, de modo que los patrones que son O(N) en uso normal se convierten en O(N*N) con un patrón en ellos. Cambiar a significa que el patrón permanecerá O(N).

REG_INF ha aumentado de 65,536 a 2,147,483,647

Muchos cuantificadores de expresiones regulares solían estar limitados a en el pasado, pero ahora están limitados a , por lo tanto, ahora es posible escribir , por ejemplo. Tenga en cuenta que hacerlo puede hacer que el motor de expresiones regulares tarde más y use más memoria.

Nuevas funciones API optimize_optree y finalize_optree

Hay dos nuevas funciones API para operar en fragmentos de optree, asegurando que pueda invocar las partes requeridas del proceso de generación de optree que de otro modo no se invocarían (por ejemplo, al crear un LOGOP personalizado). Para acceder a estas funciones, primero debe establecer una para optar por usar estas funciones.

#define PERL_USE_VOLATILE_API

Estas funciones están estrechamente ligadas a los internos de cómo funciona el intérprete, y podrían ser alteradas o eliminadas en cualquier momento si otros cambios internos lo hacen necesario.

Algunos "goto" ahora están permitidos en bloques "defer" y "finally"

La versión 5.36.0 de Perl añadió bloques y permitió que la palabra clave también añadiera un comportamiento similar a la sintaxis /. Estos no permitían ninguna expresión dentro del cuerpo, ya que podría haber causado que el flujo de control saltara fuera del bloque. Ahora, algunas expresiones están permitidas, si tienen una etiqueta de destino constante, y esa etiqueta se encuentra dentro del bloque.

use feature 'defer';
defer {
  goto LABEL;
  print "Esto no se ejecuta\n";
  LABEL: print "Esto sí\n";
}

Nueva expresión regular variable ${^LAST_SUCCESSFUL_PATTERN}

Esto permite acceder al último patrón exitoso que coincidió en el ámbito actual. Muchos aspectos del motor de expresiones regulares se refieren al "último patrón exitoso". El patrón vacío lo reutiliza, y todas las variables mágicas de expresiones regulares se relacionan con él. Esto permite acceder a su patrón. El siguiente código

if (m/foo/ || m/bar/) {
    s//PQR/;
}

se puede reescribir de la siguiente manera

if (m/foo/ || m/bar/) {
    s/${^LAST_SUCCESSFUL_PATTERN}/PQR/;
}

y hará exactamente lo mismo.

Categoría de localización LC_NAME ahora soportada en plataformas participantes

En plataformas que tienen la extensión GNU de la categoría , ahora puede usarla como parámetro de categoría para "setlocale" en POSIX para establecer y consultar su localización.

Cambios incompatibles

readline() ya no borra las banderas de error y fin de archivo del stream

readline(), también escrito como , borraba las banderas de error y fin de archivo del manejador después de que ocurría un error en el stream.

En casi todos los casos, este borrado ya no se realiza, por lo que las banderas de error y fin de archivo ahora reflejan correctamente el estado del stream después de readline().

Dado que la bandera de error ya no se borra, llamar a close() en el stream puede fallar y si el stream no se cerró explícitamente, el cierre implícito del stream puede generar una advertencia.

Esto ha resultado en dos tipos principales de problemas en módulos de CPAN posteriores, y estos también pueden ocurrir en su código:

  • Si su código lee hasta el final del archivo, y luego reasigna el manejador a un nuevo descriptor de archivo, anteriormente como la bandera de fin de archivo no estaba establecida, podía continuar leyendo del stream. Ahora necesita borrar la bandera de fin de archivo usted mismo con para continuar leyendo.
  • Si su código encuentra un error en el stream mientras lee con readline(), necesitará llamar a para continuar leyendo. El único caso en que esto ocurrió fue que el descriptor de archivo subyacente estaba marcado como no bloqueante, por lo que la llamada al sistema read() fallaba con , lo que resultó en que la bandera de error se estableciera en el stream.

El único caso en que las banderas de error y fin de archivo continúan borrándose en caso de error es al leer del proceso hijo para glob() en miniperl. Esto le permite informar correctamente los errores del proceso hijo en close(). Es poco probable que esto sea un problema durante el desarrollo normal de perl.

[GH #20060 https://github.com/Perl/perl5/issues/20060]

Los bloques "INIT" ya no se ejecutan después de un exit() en "BEGIN"

"INIT" bloques ya no se ejecutarán después de un exit() realizado dentro de un . Esto significa que la combinación de la opción y la opción ya no ejecuta una verificación de compilación además de mostrar la versión de perl. La opción ejecuta un exit(0) después de imprimir la información de la versión dentro de un bloque , y la verificación se implementa utilizando ganchos , lo que resulta en que la opción tenga prioridad.

[GH #1537 https://github.com/Perl/perl5/issues/1537] [GH #20181 https://github.com/Perl/perl5/issues/20181]

Los errores de sintaxis ya no producen "mensajes de error fantasma"

En general, perl continúa analizando el código fuente incluso después de encontrar un error de compilación. En muchos casos, esto es útil, por ejemplo, con nombres de variables mal escritos, es útil mostrar tantos ejemplos del error como sea posible. Pero en el caso de errores de sintaxis, continuar a menudo produce mensajes de error extraños e incluso puede causar fallos de segmentación durante el proceso de compilación. En esta versión, el compilador se detendrá en el primer error de sintaxis encontrado. Esto significa que cualquier código que espere ver los mensajes de error específicos que solíamos producir se romperá. El error que se emite será uno de los diagnósticos que solíamos producir, pero en algunos casos, algunos mensajes que solíamos producir ya no se mostrarán.

Vea "Cambios en los diagnósticos existentes" para más detalles.

Cambios en las localizaciones "thread-safe"

Perl 5.28 introdujo localizaciones "thread-safe" en sistemas que las soportaban, a saber, Windows moderno y sistemas que soportan operaciones de localización POSIX 2008. Estos sistemas logran esto teniendo localizaciones por hilo, mientras continúan soportando las operaciones de localización globales más antiguas para código que no toma las medidas necesarias para usar las nuevas por hilo.

Resulta que algunas plataformas POSIX 2008 tienen o han tenido implementaciones defectuosas, lo que obligó a perl a no usarlas. La variable escalar contiene 0 o 1 para indicar si la plataforma actual es considerada por perl como una implementación thread-safe que funciona. Seguridad local

Las operaciones AFE ya no son utilizadas por Perl, a partir de esta versión. Por lo tanto, "${^SAFE_LOCALES}" ahora es 0 para ellas. Las versiones anteriores de Perl se pueden configurar para evitar estas implementaciones defectuosas agregando la opción Configure "-DNO_POSIX_2008_LOCALE".

Y v5.38 corrige un error en todas las versiones anteriores de Perl que provocaba que las configuraciones regionales (locales) no fueran totalmente seguras para hilos. El primer hilo que finalizaba hacía que el hilo principal (llamado "thread0") volviera a la configuración regional global vigente al inicio, descartando cualquier configuración que el hilo hubiera establecido previamente. Si algún otro hilo hubiera cambiado a la configuración regional global llamando a switch_to_global_locale() en código XS, esos hilos compartirían la configuración regional global, y "thread0" no sería seguro para hilos.

Deprecaciones

El uso de "'" como separador de nombres de paquete está deprecated

El uso de "'" como separador de paquete en una variable nombrada en una cadena entre comillas dobles ha emitido advertencias desde la versión 5.28. Ahora está deprecated tanto en la interpolación de cadenas como en contextos no interpolados, y se eliminará en Perl 5.42.

Operador Switch y Smart Match

La característica "switch" y el operador smartmatch, "~~", se introdujeron en la v5.10. Su comportamiento se modificó significativamente en la v5.10.1. Cuando se agregó el sistema de "experimento" en la v5.18.0, switch y smartmatch se declararon retroactivamente experimentales. A lo largo de los años, han surgido y desaparecido propuestas para corregir o complementar las características.

En la v5.38.0, declaramos que el experimento ha fracasado. Algún sistema futuro puede ocupar el lugar conceptual de smartmatch, pero aún no ha sido diseñado ni construido.

Estas características se eliminarán por completo de Perl en la v5.42.0.

    Cambios en diagnósticos existentes

    • The compiler will now stop parsing on the first syntax error it encounters. Historically the compiler would attempt to "skip past" the error and continue parsing so that it could list multiple errors. For things like undeclared variables under strict this makes sense. For syntax errors however it has been found that continuing tends to result in a storm of unrelated or bizarre errors that mostly just obscure the true error. In extreme cases it can even lead to segfaults and other incorrect behavior.

      Therefore we have reformed the continuation logic so that the parse will stop after the first seen syntax error. Semantic errors like undeclared variables will not stop the parse, so you may still see multiple errors when compiling code. However if there is a syntax error it will be the last error message reported by perl and all of the errors that you see will be something that actually needs to be fixed.

    • Error messages that output class or package names have been modified to output double quoted strings with various characters escaped so as to make the exact value clear to a reader. The exact rules on which characters are escaped may change over time but currently are that printable ASCII codepoints, with the exception of """ and "\", and Unicode word characters whose codepoint is over 255 are output raw, and any other symbols are escaped much as Data::Dumper might escape them, using "\n" for newline and "\"" for double quotes, etc. Codepoints in the range 128-255 are always escaped as they can cause trouble on Unicode terminals when output raw.

      In older versions of perl the one liner

      $ perl -le'"thing\n"->foo()'

      would output the following error message exactly as shown here, with text spread over multiple lines because the "\n" would be emitted as a raw newline character:

      Can't locate object method "foo" via package "thing
" (perhaps you forgot to load "thing
"?) at -e line 1.

      As of this release we would output this instead (as one line):

      Can't locate object method "foo" via package "thing\n"
  (perhaps you forgot to load "thing\n"?) at -e line 1.

      Notice the newline in the package name has been quoted and escaped, and thus the error message is a single line. The text is shown here wrapped to two lines only for readability.

    • When package or class names in errors are very large the middle excess portion will be elided from the message. As of this release error messages will show only up to the first 128 characters and the last 128 characters in a package or class name in error messages. For example 
      $ perl -le'("Foo" x 1000)->new()'

      will output the following as one line:

      Can't locate object method "new" via package "FooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFo"..."oFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFoo" (perhaps you forgot to load
"FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFo"...
"oFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo"?)
at -e line 1.

      Notice the "prefix"..."suffix" form of the package name in this case. In previous versions of perl the complete string would have been shown making the error message over 6k long and there was no upper limit on the length of the error message at all. If you accidentally used a 1MB string as a class name then the error message would be over 2MB long. In this perl the upper limit should be around 2k when eliding and escaping are taken into account.

    • Removed "Complex regular subexpression recursion limit (%d) exceeded"

      The regular expression engine has not used recursion in some time. This warning no longer makes sense.

      See [GH #19636 https://github.com/Perl/perl5/pull/19636].

    (Do you need to predeclare foo?)

    • Agregar newAVav() para crear un AV a partir de un AV existente. Agregar newAVhv() para crear un AV usando claves y valores de un HV existente.
    • Corregir la definición de "Perl_atof".
    • Corregir comportamiento indefinido con desbordamiento relacionado con "OPTIMIZE_INFTY" y delta en regcomp.c.
    • Corregir el problema de alineación de punteros regnode en regcomp.h.
    • La bandera CV "CVf_METHOD" y la macro asociada "CvMETHOD" se han renombrado a "CVf_NOWARN_AMBIGUOUS" y "CvNOWARN_AMBIGUOUS". Esto refleja más de cerca su comportamiento real (suprime una advertencia que de otro modo se generaría sobre nombres ambiguos), para que sea menos confuso con "CvIsMETHOD", que indica que un CV es una subrutina de "método" relacionada con la característica de "clase".
    • La bandera "OPf_SPECIAL" ya no se establece en el op "OP_ENTERSUB" construido para llamar a los métodos "VERSION", "import" y "unimport" como parte de una declaración "use" y la aplicación de atributos, ni al asignar a una subrutina de ":lvalue".
    • Se ha agregado una nueva bandera de CV "CVf_REFCOUNTED_ANYSV", que indica que el CV es un XSUB y almacena un puntero SV en el campo de unión "CvXSUBANY.any_sv". Las operaciones principales de Perl, como clonar o destruir el CV, mantendrán el recuento de referencias del SV al que apunta, destruyéndolo cuando sea necesario.
    • Se agrega una nueva función de API ""Perl_localeconv"" en perlapi. Esto es lo mismo que "POSIX::localeconv" (que devuelve un hash de los campos de localeconv()), pero se puede llamar directamente desde código XS.
    • Se agrega una nueva función de API, ""Perl_langinfo8"" en perlapi. Esto es lo mismo que ""Perl_langinfo"" en perlapi, pero con un parámetro adicional que permite al llamador saber de manera simple y confiable si la cadena devuelta es UTF-8.
    • Hemos introducido un límite en el número de bloques anidados de "eval EXPR"/"BEGIN" y "require"/"BEGIN" (y, por lo tanto, también las declaraciones "use") para evitar desbordamientos de pila de C. Esta variable también se puede utilizar para prohibir la ejecución de bloques "BEGIN" durante la compilación de "eval EXPR". El límite es de 1000 por defecto, pero puede ser reemplazado estableciendo la variable "${^MAX_NESTED_EVAL_BEGIN_BLOCKS}". El valor predeterminado en sí se puede cambiar en tiempo de compilación con 
      -Accflags='-DPERL_MAX_NESTED_EVAL_BEGIN_BLOCKS_DEFAULT=12345'

      Tenga en cuenta que este valor se relaciona con el tamaño de su pila de C y si elige un valor inapropiadamente grande, Perl podría fallar (segfault). Sea conservador con lo que elija.

    • Se ha agregado un nuevo tipo de magia "PERL_MAGIC_extvalue". Esto está disponible para su uso como "PERL_MAGIC_ext", pero es una magia de valor: al localizar, el nuevo valor no será mágico.
    • Las API SSNEW(), SSNEWt(), SSNEWa() y SSNEWat() ahora devuelven un valor "SSize_t". Las macros SSPTR() y SSPTRt() ahora esperan un parámetro "SSize_t" y lo imponen en compilaciones de depuración. [GH #20411 https://github.com/Perl/perl5/issues/20411]
    • Los nombres de archivo en los opcodes ahora tienen recuento de referencias bajo hilos. Bajo hilos, estábamos copiando los nombres de archivo en cada opcode. Esto se debe a que, en teoría, los opcodes creados en un hilo pueden ser destruidos en otro. El cambio agrega una nueva estructura/tipo "RCPV", que es una cadena con recuento de referencias que utiliza memoria compartida. Esto se implementa de tal manera que el código que anteriormente usaba un char * puede continuar haciéndolo, ya que los datos de recuento de referencias se encuentran en un desplazamiento específico antes del propio puntero char *.
    • Se agregaron "HvNAMEf" y "HvNAMEf_QUOTEDPREFIX" formatos especiales. Toman un "HV *" como argumento y utilizan HvNAME() y macros relacionadas para determinar la cadena, su longitud y si es utf8.
    • La función subyacente "Perl_dowantarray" que implementa la macro "GIMME", obsoleta desde hace mucho tiempo, ha sido marcada como obsoleta, de modo que el uso de la macro genera una advertencia en tiempo de compilación. "GIMME" ha sido documentada como obsoleta en favor de "GIMME_V" desde Perl v5.6.0, pero anteriormente no había emitido una advertencia.
    • La función de la API "utf8_length" en perlapi es ahora más eficiente.
    • Se agregaron SAVERCPV() y SAVEFREERCPV() para un mejor soporte para trabajar con estructuras "RCPV" (cadena/puntero con recuento de referencias) que actualmente se utilizan en opcodes para compartir datos de nombres de archivo y bits de advertencia de manera eficiente en cuanto a memoria.
    • Se agregaron las macros MORTALSVFUNC_SV() y MORTALDESTRUCTOR_SV(), que permiten crear un destructor que se activa al final de la instrucción actual. Esto utiliza la magia "PERL_MAGIC_destruct" para usar magia "gratuita" para activar una acción cuando se libera una variable. La acción se puede especificar como una función C o como una referencia de código Perl.
    • Se agregó la API "%{^HOOK}" y las relacionadas "PERL_MAGIC_hook" y "PERL_MAGIC_hookelem" para proporcionar formas de enganchar funciones seleccionadas de perl que, por una razón u otra, son problemáticas de envolver con una subrutina personalizada.
    • Se agregó soporte para "${^HOOK}{require__before}" que se puede utilizar para reescribir el nombre de archivo que "require" intentará cargar, y también para bloquear que "require" cargue un módulo específico, incluso a través de un nombre de archivo completamente calificado. El hook también se puede usar para realizar acciones de "pre-require" y "post-require".
    • Se agregó soporte para "${^HOOK}{require__after}" que se puede utilizar para rastrear qué módulos se han requerido después del hecho.
    • Los opcodes de expresiones regulares (regops) ahora utilizan un diseño de estructura estandarizado que usa uniones para exponer datos en diferentes formatos. Esto significa que debería ser mucho más fácil extender o modificar regops para usar más memoria. Esto se ha utilizado para que varios regops rastreen cuántos paréntesis contienen.

      Cambios de Perl 5.36.0 a 5.38.0

      • Cuando una subrutina de Perl realiza una llamada de cola a una subrutina XS usando "goto &xs_sub", la subrutina XS ahora puede determinar correctamente su contexto de llamada. Anteriormente, siempre se informaba como escalar.

        Además, cuando la subrutina de Perl se libera al mismo tiempo:

        sub foo { *foo = sub {}; goto &xs_sub }

        esto anteriormente podía provocar bloqueos si la subrutina XS intentaba utilizar el valor de "PL_op", ya que se estaba estableciendo en NULL. Esto ahora está arreglado.

        [GH #19936 https://github.com/Perl/perl5/issues/19936]

      • setsockopt() ahora utiliza el mecanismo añadido en 5.36 para distinguir mejor entre valores numéricos y de cadena proporcionados como parámetro "OPTVAL". [GH #18761 https://github.com/Perl/perl5/issues/18761]
      • El select() de 4 argumentos ahora rechaza cadenas con puntos de código superiores a 255. Además, para los puntos de código 128-255, este operador ahora siempre proporcionará el octeto correspondiente al sistema operativo, independientemente de cómo Perl almacene dichos puntos de código en memoria. (Anteriormente, Perl filtraba su almacenamiento interno de cadenas al sistema operativo). [GH #19882 https://github.com/Perl/perl5/issues/19882]
      • Arreglado problema de pánico de "val {} dentro de /(?{...})/" [GH #19390 https://github.com/Perl/perl5/issues/19390]
      • Corregidas varias advertencias del compilador de regexp.c, locale.c [GH #19915 https://github.com/Perl/perl5/issues/19915]
      • Corregido un error con la consulta de locales en plataformas que no tienen "LC_NUMERIC" [GH #19890 https://github.com/Perl/perl5/issues/19890]
      • Se evita el comportamiento indefinido en S_maybe_multideref().
      • Se evita el desbordamiento de enteros con signo en las operaciones de "use integer".
      • Se evita añadir un desplazamiento a un puntero NULL en "hv_delete_common".
      • PerlIO::get_layers ahora aceptará también referencias a IO

        Anteriormente solo aceptaba referencias a glob o nombres de globs. Ahora también aceptará referencias a IO.

      • Correcciones en la gestión de memoria para "PL_splitstr":
      • Si se creaba un hilo, la cadena asignada se liberaba dos veces.
      • Si se proporcionaban dos opciones "-F", la memoria asignada para la primera opción no se liberaba.
      • Se manejan correctamente las operaciones "OP_ANONCODE" generadas por módulos CPAN que no incluyen la bandera OPf_REF al propagar el contexto de lvalue. [GH #20532 https://github.com/Perl/perl5/pull/20532]
      • POSIX::strxfrm ahora utiliza la categoría de local "LC_CTYPE" para especificar su ordenación, ignorando cualquier "LC_COLLATE" diferente. No tiene sentido que una cadena esté codificada en una locale (por ejemplo, ISO-8859-6, árabe) y se ordene basándose en otra (como ISO-8859-7, griego). Perl asume que la locale "LC_CTYPE" actual representa correctamente la codificación y ordena en consecuencia.

        Además, ahora se permiten caracteres "NUL" incrustados en la entrada.

        Si la ordenación por locale no está habilitada en la plataforma ("LC_COLLATE"), la entrada se devuelve sin cambios.

      • Se han corregido dobles FETCH durante la conversion a cadena de escalares enlazados que devuelven un objeto sobrecargado. El método FETCH solo debería llamarse una vez, pero antes de esta versión se llamaba en realidad dos veces. [GH #20574 https://github.com/Perl/perl5/pull/20574]
      • Escribir en variables mágicas asociadas al manejador de salida seleccionado, $^, $~, $=, "$-" y $%, ya no bloquea perl si el objeto IO ha sido borrado del manejador de salida seleccionado. [GH #20733 https://github.com/Perl/perl5/issues/20733]
      • La redefinición de una constante de lista "use constant" con "use constant" ahora advierte adecuadamente. Esto cambia el comportamiento de "use constant" pero es un cambio central, no un cambio en constant.pm. [GH #20742 https://github.com/Perl/perl5/issues/20742]
      • La redefinición de una constante de lista "use constant" con una subrutina constante de prototipo vacío resultaría en un fallo de aserción. [GH #20742 https://github.com/Perl/perl5/issues/20742]
      • Se ha corregido una regresión en la que el método "INC" para objetos en @INC no era resuelto por "AUTOLOAD", mientras que sí lo era en 5.36. El método "INCDIR" para objetos en @INC no puede ser resuelto por "AUTOLOAD" ya que "INC" habría sido resuelto primero. [GH #20665 https://github.com/Perl/perl5/issues/20665]
      • $SIG{__DIE__} ahora se llamará desde eval cuando el código muera durante la compilación, independientemente de cómo muera. Esto significa que el código que espera poder actualizar $@ a un objeto se llamará de forma consistente. En versiones anteriores de perl, $SIG{__DIE__} no se llamaba para ciertos errores de compilación, por ejemplo, variables no declaradas. Para otros errores, podría llamarse si había más de un cierto número de errores, pero no si había menos. Ahora se puede esperar que se llame en todos los casos.
      • La compilación de código con errores solía detenerse de forma inconsistente dependiendo del número y tipo de errores encontrados. La intención era que después de 10 errores la compilación se detendría, pero los errores en esta lógica significaban que ciertos tipos de error se contaban, pero no activaban el umbral para detener la compilación. Otros errores sí lo hacían. Con esta versión, después de un máximo de 10 errores, la compilación terminará, independientemente del tipo de error que fueran.

        Tenga en cuenta que puede cambiar el número máximo definiendo "PERL_STOP_PARSING_AFTER_N_ERRORS" para que sea otra cosa durante el proceso de configuración. Por ejemplo:

        ./Configure ... -Accflags='-DPERL_STOP_PARSING_AFTER_N_ERRORS=100'

        permitiría hasta 100 errores.

      • La función de la API "my_snprintf" en perlapi ahora imprime un punto decimal no punto si el código perl desde el que finalmente se llama está en el ámbito de "use locale" y la locale en efecto lo requiere.
      • Se han corregido varios errores relacionados con los grupos de captura en grupos cuantificados en expresiones regulares, especialmente en alternancias. Por ejemplo, en un patrón como: 
        "foobazfoobar" =~ /((foo)baz|foo(bar))+/

        la variable de regex $2 no será "foo" como lo fue una vez, será undef.

      • Se han corregido errores con los operadores de retroreferencia de regex que están dentro de un grupo de captura. Por ejemplo: 
        "xa=xaaa" =~ /^(xa|=?\1a){2}\z/

        ahora correctamente no coincidirá. [GH #10073 https://github.com/Perl/perl5/issues/10073]

      • SSGROW() y SSCHECK() han sido rediseñados para asegurar que el espacio solicitado se asigna realmente. SSCHECK() es ahora un alias para SSGROW().
