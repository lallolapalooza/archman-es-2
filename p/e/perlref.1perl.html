NOMBRE

perlref - Referencias de Perl y estructuras de datos anidadas

NOTA

Esta es la documentación completa sobre todos los aspectos de las referencias. Para una introducción tutorial más corta sobre solo las características esenciales, consulte perlreftut.

DESCRIPCIÓN

Antes de la versión 5 de Perl era difícil representar estructuras de datos complejas, porque todas las referencias tenían que ser simbólicas y aun así era difícil referirse a una variable en lugar de una entrada de la tabla de símbolos. Perl ahora no solo facilita el uso de referencias simbólicas a variables, sino que también permite tener referencias "duras" a cualquier pieza de datos o código. Cualquier escalar puede contener una referencia dura. Como los arrays y hashes contienen escalares, ahora puede construir fácilmente arrays de arrays, arrays de hashes, hashes de arrays, arrays de hashes de funciones, y así sucesivamente.

Las referencias duras son inteligentes: realizan un seguimiento de los recuentos de referencias por usted, liberando automáticamente la cosa referenciada cuando su recuento de referencias llega a cero. (Los recuentos de referencias de valores en estructuras de datos autorreferenciales o cíclicas pueden no llegar a cero sin un poco de ayuda; consulte "Referencias Circulares" para una explicación detallada.) Si esa cosa resulta ser un objeto, el objeto se destruye. Consulte perlobj para obtener más información sobre objetos. (En cierto sentido, todo en Perl es un objeto, pero generalmente reservamos la palabra para referencias a objetos que han sido oficialmente "bendecidos" en un paquete de clase.)

Las referencias simbólicas son nombres de variables u otros objetos, al igual que un enlace simbólico en un sistema de archivos Unix contiene meramente el nombre de un archivo. La notación *glob es algo así como una referencia simbólica. (A veces se llama a las referencias simbólicas "referencias suaves", pero por favor, no las llame así; las referencias son lo suficientemente confusas sin sinónimos inútiles.)

En contraste, las referencias duras se parecen más a los enlaces duros en un sistema de archivos Unix: se utilizan para acceder a un objeto subyacente sin preocuparse por cuál es su (otro) nombre. Cuando se utiliza la palabra "referencia" sin un adjetivo, como en el siguiente párrafo, generalmente se refiere a una referencia dura.

Las referencias son fáciles de usar en Perl. Solo hay un principio fundamental: en general, Perl no realiza referenciación ni desreferenciación implícitas. Cuando un escalar contiene una referencia, siempre se comporta como un escalar simple. No empieza mágicamente a ser un array, un hash o una subrutina; tiene que indicárselo explícitamente desreferenciándolo.

Creación de Referencias

Las referencias se pueden crear de varias maneras.

Operador de Barra Diagonal Inversa

Usando el operador de barra diagonal inversa en una variable, subrutina o valor. (Esto funciona de manera similar al operador & (dirección de) en C.) Esto típicamente crea *otra* referencia a una variable, porque ya existe una referencia a la variable en la tabla de símbolos. Pero la referencia de la tabla de símbolos podría desaparecer y usted todavía tendrá la referencia que devolvió la barra diagonal inversa. Aquí hay algunos ejemplos:

$ref_escalar = \$foo;
$ref_array  = \@ARGV;
$ref_hash   = \%ENV;
$ref_codigo = \&handler;
$ref_glob   = \*foo;

No es posible crear una referencia real a un manejador de IO (manejador de archivo o de directorio) usando el operador de barra diagonal inversa. Lo máximo que puede obtener es una referencia a un typeglob, que es en realidad una entrada completa de la tabla de símbolos. Pero consulte la explicación de la sintaxis *foo{THING} a continuación. Sin embargo, aún puede usar type globs y globrefs como si fueran manejadores de IO.

Corchetes

Se puede crear una referencia a un array anónimo usando corchetes:

$ref_array = [1, 2, ['a', 'b', 'c']];

Aquí hemos creado una referencia a un array anónimo de tres elementos cuyo último elemento es, a su vez, una referencia a otro array anónimo de tres elementos. (La sintaxis multidimensional descrita más adelante se puede usar para acceder a esto. Por ejemplo, después de lo anterior, "$ref_array->[2][1]" tendría el valor "b".)

Tomar una referencia a una lista enumerada no es lo mismo que usar corchetes: ¡en su lugar, es lo mismo que crear una lista de referencias!

@lista = (\$x, \@y, \%z);
@lista = \($x, @y, %z);      # ¡lo mismo!

Como caso especial, "\(@foo)" devuelve una lista de referencias a los contenidos de @foo, no una referencia a @foo misma. Lo mismo ocurre con %foo, excepto que las referencias de clave son a copias (ya que las claves son solo cadenas en lugar de escalares completos).

Llaves

Se puede crear una referencia a un hash anónimo usando llaves:

$ref_hash = {
    'Adam'  => 'Eve',
    'Clyde' => 'Bonnie',
};

Compositores de hashes y arrays anónimos como estos se pueden mezclar libremente para producir una estructura tan complicada como desee. La sintaxis multidimensional descrita a continuación funciona también para estos. Los valores anteriores son literales, pero las variables y expresiones funcionarían igual de bien, porque los operadores de asignación en Perl (incluso dentro de local() o my()) son sentencias ejecutables, no declaraciones en tiempo de compilación.

Debido a que las llaves se usan para varias otras cosas, incluidos los BLOQUEs, es posible que ocasionalmente deba desambiguar las llaves al comienzo de una declaración colocando un "+" o un "return" delante para que Perl se dé cuenta de que la llave de apertura no está iniciando un BLOQUE. La economía y el valor mnemotécnico de usar llaves se consideran dignos de este inconveniente ocasional.

Por ejemplo, si quisiera una función para crear un nuevo hash y devolver una referencia a él, tiene estas opciones:

sub hashem {        { @_ } }   # silenciosamente incorrecto
sub hashem {       +{ @_ } }   # ok
sub hashem { return { @_ } }   # ok

Por otro lado, si desea el otro significado, puede hacer esto:

sub showem {        { @_ } }   # ambiguo (actualmente ok,
                               # pero puede cambiar)
sub showem {       {; @_ } }   # ok
sub showem { { return @_ } }   # ok

El "+{" inicial y "{;" siempre sirven para desambiguar la expresión y que signifique la referencia al HASH o el BLOQUE.

Subrutinas Anónimas

Se puede crear una referencia a una subrutina anónima usando "sub" sin un nombre de subrutina:

$ref_codigo = sub { print "¡Boing!\n" };

Tenga en cuenta el punto y coma. Excepto que el código interno no se ejecuta inmediatamente, un "sub {}" no es tanto una declaración como un operador, como "do{}" o "eval{}". (Sin embargo, no importa cuántas veces ejecute esa línea en particular (a menos que esté en un eval("...")), $ref_codigo seguirá teniendo una referencia a la *misma* subrutina anónima.)

Las subrutinas anónimas actúan como clausuras con respecto a las variables my(), es decir, variables léxicamente visibles dentro del ámbito actual. Clausura es una noción del mundo Lisp que dice que si se define una función anónima en un contexto léxico particular, pretende ejecutarse en ese contexto incluso cuando se llama fuera del contexto. En términos humanos, es una forma peculiar de pasar argumentos a una subrutina cuando se define, así como cuando se llama. Es útil para configurar pequeños fragmentos de código para ejecutar más tarde, como devoluciones de llamada. Incluso puede hacer cosas orientadas a objetos con ella, aunque Perl ya proporciona un mecanismo diferente para hacer eso: consulte perlobj.

También podría pensar en la clausura como una forma de escribir una plantilla de subrutina sin usar eval(). Aquí hay un pequeño ejemplo de cómo funcionan las clausuras:

sub newprint {
    my $x = shift;
    return sub { my $y = shift; print "$x, $y!\n"; };
}
$h = newprint("Hola");
$g = newprint("Saludos");
# Pasa el tiempo...
&$h("mundo");
&$g("terrícolas");

Esto imprime

Hola, mundo!
Saludos, terrícolas!

Tenga en cuenta en particular que $x continúa refiriéndose al valor pasado a newprint() *a pesar* de que "my $x" ha salido del ámbito para cuando se ejecuta la subrutina anónima. De eso se trata una clausura.

Esto se aplica solo a variables léxicas, por cierto. Las variables dinámicas continúan funcionando como siempre lo han hecho. La clausura no es algo de lo que la mayoría de los programadores de Perl necesiten preocuparse para empezar

Creación de Referencias

Las referencias se pueden crear de varias maneras.

Constructores

Las referencias a menudo son devueltas por subrutinas especiales llamadas constructores. Los objetos de Perl son simplemente referencias a un tipo especial de objeto que sabe con qué paquete está asociado. Los constructores son simplemente subrutinas especiales que saben cómo crear esa asociación. Lo hacen comenzando con una referencia ordinaria, y sigue siendo una referencia ordinaria incluso mientras también es un objeto. Los constructores a menudo se llaman new(). Puede llamarlos indirectamente:

$objref = new Doggie( Tail => 'short', Ears => 'long' );

Pero eso puede producir una sintaxis ambigua en ciertos casos, por lo que a menudo es mejor usar el enfoque de invocación de métodos directos:

$objref   = Doggie->new(Tail => 'short', Ears => 'long');
use Term::Cap;
$terminal = Term::Cap->Tgetent( { OSPEED => 9600 });
use Tk;
$main    = MainWindow->new();
$menubar = $main->Frame(-relief              => "raised",
                        -borderwidth         => 2)

Esta sintaxis de objeto indirecto solo está disponible cuando "use feature "indirect"" está activo, y ese no es el caso cuando se solicita "use v5.36" (o superior), es mejor evitar la sintaxis de objeto indirecto por completo.

Autovivificación

Las referencias del tipo apropiado pueden aparecer de la nada si las desreferencia en un contexto que asume que existen. Como aún no hemos hablado de la desreferenciación, no podemos mostrarle ningún ejemplo todavía.

Ranuras de Typeglob

Se puede crear una referencia utilizando una sintaxis especial, conocida cariñosamente como la sintaxis *foo{THING}. *foo{THING} devuelve una referencia a la ranura THING en *foo (que es la entrada de la tabla de símbolos que contiene todo lo conocido como foo).

$scalarref = *foo{SCALAR};
$arrayref  = *ARGV{ARRAY};
$hashref   = *ENV{HASH};
$coderef   = *handler{CODE};
$ioref     = *STDIN{IO};
$globref   = *foo{GLOB};
$formatref = *foo{FORMAT};
$globname  = *foo{NAME};    # "foo"
$pkgname   = *foo{PACKAGE}; # "main"

La mayoría de estas son autoexplicativas, pero *foo{IO} merece especial atención. Devuelve el manejador IO, utilizado para manejadores de archivos ("open" en perlfunc), sockets ("socket" en perlfunc y "socketpair" en perlfunc), y manejadores de directorios ("opendir" en perlfunc). Para compatibilidad con versiones anteriores de Perl, *foo{FILEHANDLE} es un sinónimo de *foo{IO}, aunque se desaconseja para fomentar un uso consistente de un solo nombre: IO. En perls entre v5.8 y v5.22, emitirá una advertencia de depreciación, pero esta depreciación ha sido revocada desde entonces.

*foo{THING} devuelve undef si esa THING en particular aún no se ha utilizado, excepto en el caso de escalares. *foo{SCALAR} devuelve una referencia a un escalar anónimo si $foo aún no se ha utilizado. Esto podría cambiar en una versión futura.

*foo{NAME} y *foo{PACKAGE} son la excepción, ya que devuelven cadenas, en lugar de referencias. Estos devuelven el paquete y el nombre del typeglob en sí, en lugar de uno que se le haya asignado. Por lo tanto, después de "*foo=*Foo::bar", *foo se convertirá en "*Foo::bar" cuando se use como cadena, pero *foo{PACKAGE} y *foo{NAME} continuarán produciendo "main" y "foo", respectivamente.

*foo{IO} es una alternativa al mecanismo *HANDLE dado en "Typeglobs and Filehandles" en perldata para pasar manejadores de archivos hacia o desde subrutinas, o almacenarlos en estructuras de datos más grandes. Su desventaja es que no creará un nuevo manejador de archivos para usted. Su ventaja es que tiene menos riesgo de sobrescribir más de lo que desea con una asignación de typeglob. (Sin embargo, todavía confunde manejadores de archivos y directorios). Sin embargo, si asigna el valor entrante a un escalar en lugar de a un typeglob, como hacemos en los ejemplos a continuación, no hay riesgo de que eso suceda.

splutter(*STDOUT);          # pasar el glob completo
splutter(*STDOUT{IO});      # pasar manejadores de archivos y directorios
sub splutter {
    my $fh = shift;
    print $fh "her um well a hmmm\n";
}
$rec = get_rec(*STDIN);     # pasar el glob completo
$rec = get_rec(*STDIN{IO}); # pasar manejadores de archivos y directorios
sub get_rec {
    my $fh = shift;
    return scalar <$fh>;
}

Uso de Referencias

Eso es todo para la creación de referencias. A estas alturas, probablemente está deseando saber cómo usar referencias para recuperar sus datos perdidos hace mucho tiempo. Hay varios métodos básicos.

Escalar Simple

En cualquier lugar donde pondría un identificador (o una cadena de identificadores) como parte del nombre de una variable o subrutina, puede reemplazar el identificador con una variable escalar simple que contenga una referencia del tipo correcto:

$bar = $$scalarref;
push(@$arrayref, $filename);
$$arrayref[0] = "January";
$$hashref{"KEY"} = "VALUE";
&$coderef(1,2,3);
print $globref "output\n";

Es importante entender que específicamente *no* estamos desreferenciando $arrayref[0] o $hashref{"KEY"} allí. La desreferenciación de la variable escalar ocurre *antes* de que realice cualquier búsqueda de clave. Cualquier cosa más complicada que una variable escalar simple debe usar los métodos 2 o 3 a continuación. Sin embargo, un "escalar simple" incluye un identificador que a su vez usa el método 1 recursivamente. Por lo tanto, lo siguiente imprime "howdy".

$refrefref = \\\"howdy";
print $$$$refrefref;

Bloque

En cualquier lugar donde pondría un identificador (o una cadena de identificadores) como parte del nombre de una variable o subrutina, puede reemplazar el identificador con un BLOQUE que devuelva una referencia del tipo correcto. En otras palabras, los ejemplos anteriores podrían escribirse de esta manera:

$bar = ${$scalarref};
push(@{$arrayref}, $filename);
${$arrayref}[0] = "January";
${$hashref}{"KEY"} = "VALUE";
&{$coderef}(1,2,3);
$globref->print("output\n");  # si IO::Handle está cargado

Hay que admitir que es un poco tonto usar las llaves en este caso, pero el BLOQUE puede contener cualquier expresión arbitraria, en particular, expresiones subíndice:

&{ $dispatch{$index} }(1,2,3);      # llamar a la rutina correcta

Debido a poder omitir las llaves para el caso simple de $$x, la gente a menudo comete el error de ver los símbolos de desreferenciación como operadores correctos, y se pregunta sobre su precedencia. Si lo fueran, sin embargo, podría usar paréntesis en lugar de llaves. Ese no es el caso. Considere la diferencia a continuación; el caso 0 es una versión abreviada del caso 1, *no* del caso 2:

$$hashref{"KEY"}   = "VALUE";       # CASO 0
${$hashref}{"KEY"} = "VALUE";       # CASO 1
${$hashref{"KEY"}} = "VALUE";       # CASO 2
${$hashref->{"KEY"}} = "VALUE";     # CASO 3

El caso 2 también es engañoso en que está accediendo a una variable llamada %hashref, no desreferenciando a través de $hashref al hash al que presumiblemente se refiere. Ese sería el caso 3.

Notación de Flecha

Las llamadas a subrutinas y las búsquedas de elementos individuales de arreglos surgen con la suficiente frecuencia como para que sea engorroso usar el método 2. Como forma de azúcar sintáctico, los ejemplos para el método 2 se pueden escribir:

$arrayref->[0] = "January";   # Elemento de arreglo
$hashref->{"KEY"} = "VALUE";  # Elemento de hash
$coderef->(1,2,3);            # Llamada a subrutina

El lado izquierdo de la flecha puede ser cualquier expresión que devuelva una referencia, incluida una desreferencia previa. Tenga en cuenta que $array[$x] *no* es lo mismo que "$array->[$x]" aquí:

$array[$x]->{"foo"}->[0] = "January";

Este es uno de los casos que mencionamos anteriormente en los que las referencias podían aparecer de la nada cuando estaban en un contexto de lvalue. Antes de esta declaración, $array[$x] podría haber sido indefinido. Si es así, se define automáticamente con una referencia de hash para que podamos buscar "{"foo"}" en ella. De manera similar, "$array[$x]->{"foo"}" se definirá automáticamente con una referencia de arreglo para que podamos buscar "[0]" en ella. Este proceso se llama *autovivificación*.

Una cosa más aquí. La flecha es opcional *entre* los subíndices de corchetes, por lo que puede reducir lo anterior a

$array[$x]{"foo"}[0] = "January";

Lo que, en el caso degenerado de usar solo arreglos ordinarios, le da arreglos multidimensionales al igual que los de C:

$score[$x][$y][$z] += 42;

Bueno, está bien, no es exactamente como los arreglos de C, en realidad. C no sabe cómo expandir sus arreglos a demanda. Perl sí.

Objetos

Si una referencia resulta ser una referencia a un objeto, entonces probablemente haya métodos para acceder a las cosas a las que se hace referencia, y probablemente debería adherirse a esos métodos a menos que esté en el paquete de la clase que define los métodos del objeto. En otras palabras, sea amable y no viole el encapsulamiento del objeto sin una muy buena razón. Perl no hace cumplir el encapsulamiento. No somos totalitarios aquí. Sin embargo, esperamos cierta civilidad básica.

Uso Misceláneo

Usar una cadena o un número como referencia produce una referencia simbólica, como se explicó anteriormente. Usar una referencia como número produce un entero que representa su ubicación de almacenamiento en memoria. Lo único útil que se puede hacer con esto es comparar dos referencias numéricamente para ver si se refieren a la misma ubicación.

if ($ref1 == $ref2) {  # comparación numérica barata de referencias
    print "refs 1 and 2 refer to the same thing\n";
}

Usar una referencia como cadena produce el tipo de su referente, incluido cualquier bendición de paquete como se describe en perlobj, así como la dirección numérica expresada en hexadecimal. El operador ref() devuelve solo el tipo de cosa a la que apunta la referencia, sin la dirección. Consulte "ref" en perlfunc para obtener detalles y ejemplos de su uso.

El operador bless() puede usarse para asociar el objeto al que apunta una referencia con un paquete que funciona como una clase de objeto. Consulte perlobj.

Un typeglob puede desreferenciarse de la misma manera que una referencia, porque la sintaxis de desreferenciación siempre indica el tipo de referencia deseado. Por lo tanto, "${*foo}" y "${\$foo}" ambos indican la misma variable escalar.

Interpolación de subrutinas

Aquí tienes un truco para interpolar una llamada a subrutina en una cadena:

print "Mi subrutina devolvió @{[mysub(1,2,3)]} esa vez.\n";

La forma en que funciona es que cuando se ve el "@{...}" en la cadena entre comillas dobles, se evalúa como un bloque. El bloque crea una referencia a un array anónimo que contiene los resultados de la llamada a "mysub(1,2,3)". Por lo tanto, todo el bloque devuelve una referencia a un array, que luego es desreferenciada por "@{...}" y pegada en la cadena entre comillas dobles. Esta artimaña también es útil para expresiones arbitrarias:

print "Eso produce @{[$n + 5]} widgets\n";

De manera similar, una expresión que devuelve una referencia a un escalar puede ser desreferenciada a través de "${...}". Por lo tanto, la expresión anterior se puede escribir como:

print "Eso produce ${\($n + 5)} widgets\n";

Referencias Circulares

Es posible crear una "referencia circular" en Perl, lo que puede provocar fugas de memoria. Una referencia circular ocurre cuando dos referencias se contienen mutuamente, como esto:

my $foo = {};
my $bar = { foo => $foo };
$foo->{bar} = $bar;

También puedes crear una referencia circular con una sola variable:

my $foo;
$foo = \$foo;

En este caso, el recuento de referencias para las variables nunca llegará a 0, y las referencias nunca serán recolectadas por el recolector de basura. Esto puede provocar fugas de memoria.

Dado que los objetos en Perl se implementan como referencias, también es posible tener referencias circulares con objetos. Imagina una clase TreeNode donde cada nodo hace referencia a su padre y a sus nodos hijos. Cualquier nodo con un padre formará parte de una referencia circular.

Puedes romper referencias circulares creando una "referencia débil". Una referencia débil no incrementa el recuento de referencias para una variable, lo que significa que el objeto puede salir del ámbito y ser destruido. Puedes debilitar una referencia con la función "weaken" exportada por el módulo Scalar::Util, o disponible como "builtin::weaken" directamente en Perl versión 5.35.7 o posterior.

Aquí te mostramos cómo podemos hacer más seguro el primer ejemplo:

use Scalar::Util 'weaken';
my $foo = {};
my $bar = { foo => $foo };
$foo->{bar} = $bar;
weaken $foo->{bar};

La referencia de $foo a $bar se ha debilitado. Cuando la variable $bar salga del ámbito, será recolectada por el recolector de basura. La próxima vez que mires el valor de la clave "$foo->{bar}", será "undef".

Esta acción a distancia puede ser confusa, por lo que debes tener cuidado con el uso de `weaken`. Debes debilitar la referencia en la variable que saldrá del ámbito *primero*. De esta manera, la variable de mayor duración contendrá la referencia esperada hasta que salga del ámbito.

Referencias Simbólicas

Dijimos que las referencias surgen a la existencia según sea necesario si no están definidas, pero no dijimos qué sucede si un valor utilizado como referencia ya está definido, pero *no* es una referencia dura. Si la usas como referencia, se tratará como una referencia simbólica. Es decir, se toma el valor del escalar como el *nombre* de una variable, en lugar de un enlace directo a un valor (posiblemente) anónimo.

La gente frecuentemente espera que funcione así. Así que lo hace.

$name = "foo";
$$name = 1;                 # Establece $foo
${$name} = 2;               # Establece $foo
${$name x 2} = 3;           # Establece $foofoo
$name->[0] = 4;             # Establece $foo[0]
@$name = ();                # Borra @foo
&$name();                   # Llama a &foo()
$pack = "THAT";
${"{$pack}::$name"} = 5;    # Establece $THAT::foo sin eval

Esto es poderoso y ligeramente peligroso, ya que es posible tener la intención (con la mayor sinceridad) de usar una referencia dura y, accidentalmente, usar una referencia simbólica en su lugar. Para protegerse contra eso, puede decir:

use strict 'refs';

y luego solo se permitirán referencias duras para el resto del bloque envolvente. Un bloque interno puede revocar eso con:

no strict 'refs';

Solo las variables de paquete (globales, incluso si están localizadas) son visibles para las referencias simbólicas. Las variables léxicas (declaradas con my()) no están en una tabla de símbolos y, por lo tanto, son invisibles para este mecanismo. Por ejemplo:

local $value = 10;
$ref = "value";
{
    my $value = 20;
    print $$ref;
}

Esto todavía imprimirá 10, no 20. Recuerde que local() afecta a las variables de paquete, que son todas "globales" para el paquete.

Referencias No tan simbólicas

Los corchetes alrededor de una referencia simbólica pueden servir simplemente para aislar un identificador o nombre de variable del resto de una expresión, al igual que siempre lo han hecho dentro de una cadena. Por ejemplo,

$push = "pop on ";
print "${push}over";

siempre ha significado imprimir "pop on over", aunque `push` sea una palabra reservada. Esto se generaliza para que funcione igual sin las comillas dobles envolventes, de modo que

print ${push} . "over";

e incluso

print ${ push } . "over";

tendrán el mismo efecto. Esta construcción *no* se considera una referencia simbólica cuando se usa `strict refs`:

use strict 'refs';
${ bareword };      # Bien, significa $bareword.
${ "bareword" };    # Error, referencia simbólica.

De manera similar, debido a la cantidad de subíndices que se realizan utilizando palabras únicas, la misma regla se aplica a cualquier palabra desnuda que se utilice para subíndices de un hash. Así que ahora, en lugar de escribir

$hash{ "aaa" }{ "bbb" }{ "ccc" }

puedes escribir simplemente

$hash{ aaa }{ bbb }{ ccc }

y no preocuparte por si los subíndices son palabras reservadas. En el raro caso de que desees hacer algo como

$hash{ shift }

puedes forzar la interpretación como una palabra reservada agregando cualquier cosa que la convierta en algo más que una palabra desnuda:

$hash{ shift() }
$hash{ +shift }
$hash{ shift @_ }

La pragmática "use warnings" o el modificador -w te advertirán si interpreta una palabra reservada como una cadena. Pero ya no te advertirá sobre el uso de palabras en minúsculas, porque la cadena se cita efectivamente.

Pseudo-hashes: Usando un array como un hash

Los pseudo-hashes han sido eliminados de Perl. La pragmática `fields` sigue disponible.

Plantillas de Funciones

Como se explicó anteriormente, una función anónima con acceso a las variables léxicas visibles cuando esa función fue compilada, crea un closure. Retiene el acceso a esas variables aunque no se ejecute hasta más tarde, como en un manejador de señales o una devolución de llamada de Tk.

Usar un closure como plantilla de función nos permite generar muchas funciones que actúan de manera similar. Supongamos que quisieras funciones con nombres de colores que generaran cambios de fuente HTML para los diversos colores:

print "Sé ", red("cuidadoso"), "con esa luz ", green("verde");

Las funciones red() y green() serían similares. Para crearlas, asignaremos un closure a un `typeglob` con el nombre de la función que estamos intentando construir.

@colors = qw(red blue green yellow orange purple violet);
for my $name (@colors) {
    no strict 'refs';       # permite la manipulación de la tabla de símbolos
    *$name = *{uc $name} = sub { "@_" };
}

Ahora todas esas funciones diferentes parecen existir de forma independiente. Puedes llamar a red(), RED(), blue(), BLUE(), green(), etc. Esta técnica ahorra tanto en tiempo de compilación como en uso de memoria, y además es menos propensa a errores, ya que las comprobaciones de sintaxis ocurren en tiempo de compilación. Es crucial que cualquier variable en la subrutina anónima sea léxica para crear un closure adecuado. Esa es la razón del "my" en la variable de iteración del bucle.

Este es uno de los pocos lugares donde dar un prototipo a un closure tiene mucho sentido. Si quisieras imponer un contexto escalar en los argumentos de estas funciones (probablemente no sea una buena idea para este ejemplo en particular), podrías haberlo escrito de esta manera:

*$name = sub ($) { "$_[0]" };

Sin embargo, dado que la verificación de prototipos ocurre en tiempo de compilación, la asignación anterior ocurre demasiado tarde para ser de mucha utilidad. Podrías abordar esto poniendo todo el bucle de asignaciones dentro de un bloque BEGIN, forzando a que ocurra durante la compilación.

El acceso a léxicas que cambian con el tiempo -como las del bucle "for" anterior, básicamente alias de elementos de los ámbitos léxicos circundantes- solo funciona con subs anónimas, no con subrutinas nombradas. En general, las subrutinas nombradas no se anidan correctamente y solo deben declararse en el ámbito del paquete principal.

Esto se debe a que las subrutinas nombradas se crean en tiempo de compilación, por lo que sus variables léxicas se asignan a las léxicas principales de la primera ejecución del bloque padre. Si se ingresa a un ámbito padre una segunda vez, sus léxicas se crean de nuevo, mientras que las subs anidadas todavía hacen referencia a las antiguas.

Las subrutinas anónimas capturan cada vez que ejecutas el operador "sub", ya que se crean sobre la marcha. Si estás acostumbrado a usar subrutinas anidadas en otros lenguajes de programación con sus propias variables privadas, tendrás que esforzarte un poco en Perl. La codificación intuitiva de este tipo de cosas incurre en advertencias misteriosas sobre "no se mantendrá compartido" debido a las razones explicadas anteriormente. Por ejemplo, esto no funcionará:

sub outer {
    my $x = $_[0] + 35;
    sub inner { return $x * 19 }   # INCORRECTO
    return $x + inner();
}

Una solución es la siguiente:

sub outer {
    my $x = $_[0] + 35;
    local *inner = sub { return $x * 19 };
    return $x + inner();
}

NAME

perlref - Perl references y variables

NOTE

This document is not for the faint of heart. It is a partial documentation of some of the more advanced features of Perl.

DESCRIPTION

Una referencia es una variable que contiene la dirección de otro valor. Las referencias son esenciales para crear estructuras de datos complejas y para pasar argumentos a subrutinas de forma eficiente.

Referencias

Se crea una referencia usando el operador de referencia \. Por ejemplo:

$a = 10;
$ref_a = \$a; # $ref_a ahora contiene la dirección de $a

Se puede acceder al valor al que apunta una referencia mediante el operador de desreferencia (* o {}). Por ejemplo:

print $$ref_a; # Imprime 10
print ${$ref_a}; # Imprime 10

Las referencias se pueden crear para cualquier tipo de variable de Perl:

my @array = (1, 2, 3);
my $aref = \@array; # Referencia a un array

my %hash = (a => 1, b => 2);
my $href = \%hash; # Referencia a un hash

sub my_sub { print "Hello\n" }
my $cref = \&my_sub; # Referencia a una subrutina

Las referencias son especiales en que una referencia puede ser un valor en sí misma. Esto permite la creación de estructuras de datos recursivas y la creación de estructuras de datos complejas como listas de listas, hashes de hashes, listas de hashes, etc.

$aref = [1, 2, [3, 4]]; # Lista que contiene un número y otra lista
$href = { a => 1, b => [5, 6] }; # Hash que contiene un número y una lista

La desreferencia postfija permite escribir:

print $aref->[0]; # Imprime 1
print $href->{a}; # Imprime 1

Un uso interesante de las referencias es la creación de subrutinas locales a otras subrutinas:

sub outer {
    my $x = shift;
    my $inner = sub {
        my $y = shift;
        return $x + $y;
    };
    return $inner->($x);
}
print outer(5); # Imprime 10

Esto tiene el interesante efecto de crear una función local a otra función, algo que normalmente no se soporta en Perl.

Sintaxis de Desreferencia Postfija

A partir de la v5.20.0, está disponible una sintaxis postfija para usar referencias. Se comporta como se describe en "Usando Referencias", pero en lugar de un sigilo prefijado, se usa un sigilo y estrella postfijos.

Por ejemplo:

$r = \@a;
@b = $r->@*; # equivalente a @$r o @{ $r }
$r = [ 1, [ 2, 3 ], 4 ];
$r->[1]->@*;  # equivalente a @{ $r->[1] }
$aref->@* = (1, 2, 3);  # lo mismo que @{ $aref } = (1, 2, 3)

En Perl 5.20 y 5.22, esta sintaxis debe habilitarse con use feature 'postderef'. A partir de Perl 5.24, no se requieren declaraciones de características para que esté disponible.

La desreferencia postfija debería funcionar en todas las circunstancias en las que funcionó la desreferencia de bloque (circunfijo), y debería ser completamente equivalente. Esta sintaxis permite que la desreferencia se escriba y lea completamente de izquierda a derecha. Las siguientes equivalencias están definidas:

$sref->$*;  # lo mismo que  ${ $sref }
$aref->@*;  # lo mismo que  @{ $aref }
$aref->$#*; # lo mismo que $#{ $aref }
$href->%*;  # lo mismo que  %{ $href }
$cref->&*;  # lo mismo que  &{ $cref }
$gref->**;  # lo mismo que  *{ $gref }

Note especialmente que "$cref-&*" *no* es equivalente a $cref->(), y puede servir a propósitos diferentes.

Los elementos glob se pueden extraer a través de la característica de desreferencia postfija:

$gref->*{SCALAR}; # lo mismo que *{ $gref }{SCALAR}

La desreferencia postfija de arrays y escalares *puede* usarse en cadenas de interpolación (comillas dobles o el operador qq), pero solo si la característica "postderef_qq" está habilitada. La interpolación del acceso al índice más alto de array postfijo ("->$#*") también está soportada cuando la característica "postderef_qq" está habilitada.

Rebanado de Referencias Postfijas

Las rebanadas de valores de arrays y hashes también pueden obtenerse con la notación de desreferencia postfija, con las siguientes equivalencias:

$aref->@[ ... ];  # lo mismo que @$aref[ ... ]
$href->@{ ... };  # lo mismo que @$href{ ... }

El rebanado de pares clave/valor postfijos, añadido en 5.20.0 y documentado en la sección Key/Value Hash Slices de perldata, también se comporta como se espera:

$aref->%[ ... ];  # lo mismo que %$aref[ ... ]
$href->%{ ... };  # lo mismo que %$href{ ... }

Al igual que con el array postfijo, la desreferencia de rebanada de valor postfija *puede* usarse en cadenas de interpolación (comillas dobles o el operador qq), pero solo si la característica "postderef_qq" está habilitada.

Asignación a Referencias

A partir de la v5.22.0, el operador de referenciación puede ser asignado. Realiza una operación de alias, de modo que el nombre de variable referenciado en el lado izquierdo se convierte en un alias para la cosa referenciada en el lado derecho:

\$x = \$y; # $x y $y ahora apuntan al mismo escalar
\&foo = \&bar; # foo() ahora significa bar()

Esta sintaxis debe habilitarse con "use feature 'refaliasing'". Es experimental y advertirá por defecto a menos que no warnings 'experimental::refaliasing' esté en efecto.

Estas formas pueden ser asignadas y hacen que el lado derecho se evalúe en contexto escalar:

\$scalar
\@array
\%hash
\&sub
\my $scalar
\my @array
\my %hash
\state $scalar # o @array, etc.
\our $scalar   # etc.
\local $scalar # etc.
\local our $scalar # etc.
\$some_array[$index]
\$some_hash{$key}
\local $some_array[$index]
\local $some_hash{$key}
condition ? \$this : \$that[0] # etc.

Las operaciones de rebanado y los paréntesis hacen que el lado derecho se evalúe en contexto de lista:

\@array[5..7]
(\@array[5..7])
\(@array[5..7])
\@hash{'foo','bar'}
(\@hash{'foo','bar'})
\(@hash{'foo','bar'})
(\$scalar)
\($scalar)
\(my $scalar)
\my($scalar)
(\@array)
(\%hash)
(\&sub)
\(&sub)
\($foo, @bar, %baz)
(\$foo, \@bar, \%baz)

Cada elemento en el lado derecho debe ser una referencia a un dato del tipo correcto. Los paréntesis que rodean inmediatamente un array (y posiblemente también "my"/"state"/"our"/"local") harán que cada elemento del array sea un alias del escalar correspondiente referenciado en el lado derecho:

\(@x) = \(@y); # @x y @y ahora tienen los mismos elementos
\my(@x) = \(@y); # lo mismo
\(my @x) = \(@y); # lo mismo
push @x, 3; # pero ahora @x tiene un elemento extra que @y no tiene
\(@x) = (\$x, \$y, \$z); # @x ahora contiene $x, $y y $z

Combinar esa forma con "local" y poner paréntesis inmediatamente alrededor de un hash está prohibido (porque no está claro qué deberían hacer):

\local(@array) = foo(); # INCORRECTO
\(%hash)       = bar(); # INCORRECTO

La asignación a referencias y no referencias puede combinarse en listas y expresiones ternarias condicionales, siempre que los valores del lado derecho sean del tipo correcto para cada elemento del lado izquierdo, aunque esto puede resultar en un código ofuscado:

(my $tom, \my $dick, \my @harry) = (\1, \2, [1..3]);
# $tom ahora es \1
# $dick ahora es 2 (solo lectura)
# @harry es (1,2,3)
my $type = ref $thingy;
($type ? $type eq 'ARRAY' ? \@foo : \$bar : $baz) = $thingy;

Una asignación de referencia en contexto de lista devuelve una lista de referencias a cada valor del lado izquierdo. Así, por ejemplo

@b = ((\$l1, \$l2, \(@a)) = (\$r1, \$r2, $\r3, \$4));

es equivalente a

(\$l1, \$l2, \(@a)) = (\$r1, \$r2, $\r3, \$4);
@b = (\$l1, \$l2, \$a[0], \$a[1]);

El bucle "foreach" también puede tomar un constructor de referencia para su variable de bucle, aunque la sintaxis se limita a una de las siguientes, con un opcional "my", "state", o "our" después de la barra invertida:

\$s
\@a
\%h
\&c

No se permiten paréntesis. Esta característica es particularmente útil para arrays de arrays, o arrays de hashes:

foreach \my @a (@array_of_arrays) {
    frobnicate($a[0], $a[-1]);
}
foreach \my %h (@array_of_hashes) {
    $h{gelastic}++ if $h{type} eq 'funny';
}

ADVERTENCIA: El aliasing no funciona correctamente con clausuras. Si intenta hacer alias de variables léxicas de una subrutina interna o "eval", el aliasing solo será visible dentro de esa sub interna, y no afectará a la subrutina externa donde se declaran las variables. Este comportamiento extraño está sujeto a cambios.

Declaración de una Referencia a una Variable

A partir de la v5.26.0, el operador de referenciación puede ir después de "my", "state", "our", o "local". Esta sintaxis debe habilitarse con "use feature 'declared_refs'". Es experimental y advertirá por defecto a menos que "no warnings 'experimental::refaliasing'" esté en efecto.

Esta característica hace que:

my \$x;
our \$y;

sea equivalente a:

\my $x;
\our $x;

Está pensada principalmente para su uso en asignaciones a referencias (ver "Asignación a Referencias", arriba). También permite que la barra invertida se use solo en algunos elementos de una lista de variables declaradas:

my ($foo, \@bar, \%baz); # equivalente a:  my $foo, \my(@bar, %baz);

ADVERTENCIA: No usar referencias como claves de hash

No se puede usar (útilmente) una referencia como clave de un hash. Se convertirá en una cadena:

$x{ \$x } = $x;

Si intenta desreferenciar la clave, no realizará una desreferencia fuerte, y no logrará lo que intenta. Podría querer hacer algo más como

$r = \@a;
$x{ $r } = $r;

Y entonces al menos podrá usar los values(), que serán referencias reales, en lugar de las keys(), que no lo serán.

El módulo estándar Tie::RefHash proporciona una solución alternativa conveniente.
