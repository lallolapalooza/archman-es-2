NOMBRE

perl583delta - qué hay de nuevo para la versión perl v5.8.3

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.8.2 y la versión 5.8.3.

Si estás actualizando desde una versión anterior como la 5.6.1, lee primero perl58delta, que describe las diferencias entre 5.6.0 y 5.8.0, y perl581delta y perl582delta, que describen las diferencias entre 5.8.0, 5.8.1 y 5.8.2.

Cambios Incompatibles

No hay cambios incompatibles con la versión 5.8.2.

Mejoras del Núcleo

Ahora está disponible un método "SCALAR" para hashes atados (tied hashes). Se llama cuando un hash atado se usa en contexto escalar, como:

if (%tied_hash) {
    ...
}

El comportamiento anterior era que %tied_hash devolvía lo que se hubiera devuelto para ese hash antes de atar el hash (por lo tanto, generalmente 0). El nuevo comportamiento en ausencia de un método SCALAR es devolver TRUE si está en medio de una iteración "each", y de lo contrario llama a FIRSTKEY para verificar si el hash está vacío (asegurando que un "each" posterior también comience llamando a FIRSTKEY). Por favor, consulta "SCALAR" en perltie para obtener detalles completos y advertencias.

Cambios en Utilidades

"find2perl" ahora asume "-print" como una acción predeterminada. Anteriormente, era necesario especificarlo explícitamente.

Una nueva utilidad, "prove", facilita la ejecución de una prueba de regresión individual desde la línea de comandos. "prove" es parte de Test::Harness, que los usuarios de versiones anteriores de Perl pueden instalar desde CPAN.

Nueva Documentación

La documentación ha sido revisada en algunos lugares para producir páginas man más estándar.

La documentación de los bloques de código especiales (BEGIN, CHECK, INIT, END) ha sido mejorada.

Mejoras en Instalación y Configuración

Perl ahora se compila en OpenVMS I64.

Correcciones de Errores Seleccionadas

El uso de substr() en una cadena UTF8 podía causar que accesos posteriores a esa cadena devolvieran basura. Esto se debió a la existencia de compensaciones UTF8 incorrectas almacenadas en caché, y ahora está corregido.

join() podía devolver basura cuando la misma instrucción join() se utilizaba para procesar datos de 8 bits después de haber procesado datos UTF8, debido a que las banderas del espacio de trabajo temporal de esa instrucción no se restablecían correctamente. Esto ahora está corregido.

"$a .. $b" ahora funcionará como se esperaba cuando $a o $b es "undef".

El uso de claves Unicode con hashes atados debería funcionar correctamente ahora.

Leer $^E ahora preserva $!. Anteriormente, el código C que implementaba $^E no preservaba "errno", por lo que leer $^E podía causar que "errno" y, por lo tanto, $! cambiaran inesperadamente.

Las funciones reentrantes funcionarán (una vez más) con C++. La versión 5.8.2 introdujo una corrección de errores que accidentalmente rompió la compilación de extensiones de Perl escritas en C++.

Diagnósticos Nuevos o Cambiados

El error fatal "DESTROY created new reference to dead object" ahora está documentado en perldiag.

Internos Cambiados

El código hash ha sido refactorizado para reducir la duplicación de código fuente. La interfaz externa no ha cambiado y, aparte de las correcciones de errores descritas anteriormente, no debería haber ningún cambio en el comportamiento.

"hv_clear_placeholders" es ahora parte de la API de perl.

Se han reorganizado algunas macros C. En particular, las macros que crean variables locales temporales ahora nombran estas variables de forma más defensiva, lo que debería evitar errores donde los nombres colisionan.

<signal.h> ahora siempre se incluye.

Configuración y Compilación

"Configure" ahora invoca callbacks independientemente del valor de la variable para la que se llaman. Anteriormente, los callbacks solo se invocaban en la rama "case $variable $define)". Este cambio solo debería afectar a los mantenedores de plataformas que escriben archivos de sugerencias de configuración.

Problemas Específicos de Plataforma

La prueba de regresión ext/threads/shared/t/wait.t falla en las primeras versiones de RedHat 9 y HP-UX 10.20 debido a errores en sus implementaciones de hilos. Los usuarios de RedHat deberían consultar https://rhn.redhat.com/errata/RHBA-2003-136.html y considerar actualizar su glibc.

Problemas Conocidos

Los hilos desvinculados (detached threads) aún no son compatibles con Windows, ya que pueden provocar problemas de violación de acceso a memoria.

Existe una condición de carrera conocida al abrir scripts en "suidperl". "suidperl" no se compila ni se instala por defecto, y ha sido obsoleto desde perl 5.8.0. Se recomienda reemplazar el uso de suidperl con herramientas como sudo ( http://www.courtesan.com/sudo/ ).

Tenemos un atraso de errores sin resolver. Lidiar con errores e informes de errores es un trabajo poco glamoroso; no es algo idealmente adecuado para mano de obra voluntaria, pero eso es todo lo que tenemos.

El equipo de desarrollo de perl5 está implementando cambios para ayudar a abordar este problema, que deberían entrar en vigor a principios de 2004.

Reportando Errores

Si encuentra lo que cree que es un error, puede consultar los artículos publicados recientemente en el grupo de noticias comp.lang.perl.misc y la base de datos de errores de Perl en http://bugs.perl.org. También puede encontrar información en http://www.perl.org, la página principal de Perl.

Si cree que tiene un error no reportado, ejecute el programa perlbug incluido con su versión. Asegúrese de reducir su error a un caso de prueba pequeño pero suficiente. Su informe de error, junto con la salida de "perl -V", se enviará a perlbug@perl.org para ser analizado por el equipo de portabilidad de Perl. Puede buscar y examinar los errores de Perl 5 en http://bugs.perl.org/
