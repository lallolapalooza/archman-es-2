DESCRIPCIÓN

Esta sección del FAQ de Perl cubre preguntas relacionadas con la interacción con el sistema operativo. Los temas incluyen la comunicación entre procesos (IPC), el control de la interfaz de usuario (teclado, pantalla y dispositivos señaladores), y casi cualquier otra cosa no relacionada con la manipulación de datos.

Lea los FAQs y la documentación específica del puerto de perl a su sistema operativo (por ejemplo, perlvms, perlplan9, ...). Estos deberían contener información más detallada sobre las peculiaridades de su perl.

¿Cómo averiguo bajo qué sistema operativo estoy ejecutándome?

La variable $^O ($OSNAME si usas "English") contiene una indicación del nombre del sistema operativo (no su número de versión) para el que se compiló su binario de perl.

¿Por qué exec() no retorna?

(contribuido por brian d foy)

El trabajo de la función "exec" es convertir su proceso en otro comando y nunca retornar. Si no es eso lo que quiere hacer, no use "exec". :)

Si desea ejecutar un comando externo y mantener su proceso de Perl en ejecución, considere usar una "open" con tubería, "fork" o "system".

¿Cómo imprimo algo en color?

En general, no lo hace, porque no sabe si el destinatario tiene un dispositivo de pantalla compatible con color. Si sabe que tiene una terminal ANSI que entiende el color, puede usar el módulo Term::ANSIColor de CPAN:

use Term::ANSIColor;
print color("red"), "¡Detente!\n", color("reset");
print color("green"), "¡Adelante!\n", color("reset");

O de esta manera:

use Term::ANSIColor qw(:constants);
print RED, "¡Detente!\n", RESET;
print GREEN, "¡Adelante!\n", RESET;

¿Cómo leo una sola tecla sin esperar la tecla de retorno?

El control del búfer de entrada es un asunto notablemente dependiente del sistema. En muchos sistemas, puede simplemente usar el comando stty como se muestra en "getc" en perlfunc, pero como ve, eso ya lo está metiendo en problemas de portabilidad.

open(TTY, "+</dev/tty") or die "no tty: $!";
system "stty  cbreak </dev/tty >/dev/tty 2>&1";
$key = getc(TTY);        # quizás esto funcione
# O SI NO
sysread(TTY, $key, 1);    # probablemente esto lo haga
system "stty -cbreak </dev/tty >/dev/tty 2>&1";

El módulo Term::ReadKey de CPAN ofrece una interfaz fácil de usar que debería ser más eficiente que invocar a stty para cada tecla. Incluso incluye soporte limitado para Windows.

use Term::ReadKey;
ReadMode('cbreak');
$key = ReadKey(0);
ReadMode('normal');

Sin embargo, usar el código requiere que tenga un compilador C funcional y que pueda usarlo para construir e instalar un módulo de CPAN. Aquí hay una solución que usa el módulo POSIX estándar, que ya está en su sistema (asumiendo que su sistema soporta POSIX).

use HotKey;
$key = readkey();

Y aquí está el módulo "HotKey", que oculta las llamadas algo misteriosas para manipular las estructuras termios de POSIX.

# HotKey.pm
package HotKey;
use strict;
use warnings;
use parent 'Exporter';
our @EXPORT = qw(cbreak cooked readkey);
use POSIX qw(:termios_h);
my ($term, $oterm, $echo, $noecho, $fd_stdin);
$fd_stdin = fileno(STDIN);
$term     = POSIX::Termios->new();
$term->getattr($fd_stdin);
$oterm     = $term->getlflag();
$echo     = ECHO | ECHOK | ICANON;
$noecho   = $oterm & ~$echo;
sub cbreak {
    $term->setlflag($noecho);  # ok, tampoco quiero echo
    $term->setcc(VTIME, 1);
    $term->setattr($fd_stdin, TCSANOW);
}
sub cooked {
    $term->setlflag($oterm);
    $term->setcc(VTIME, 0);
    $term->setattr($fd_stdin, TCSANOW);
}
sub readkey {
    my $key = '';
    cbreak();
    sysread(STDIN, $key, 1);
    cooked();
    return $key;
}
END { cooked() }
1;

¿Cómo compruebo si hay entrada lista en el teclado?

La forma más fácil de hacerlo es leer una tecla en modo no bloqueante con el módulo Term::ReadKey de CPAN, pasándole un argumento de -1 para indicar que no bloquee:

use Term::ReadKey;
ReadMode('cbreak');
if (defined (my $char = ReadKey(-1)) ) {
    # había entrada esperando y era $char
} else {
    # no había entrada esperando
}
ReadMode('normal');                  # restaurar la configuración normal de la tty

¿Cómo borro la pantalla?

(contribuido por brian d foy)

Para borrar la pantalla, solo tiene que imprimir la secuencia especial que le indica a la terminal que borre la pantalla. Una vez que tenga esa secuencia, imprímala cuando quiera borrar la pantalla.

Puede usar el módulo Term::ANSIScreen para obtener la secuencia especial. Importe la función "cls" (o la etiqueta ":screen"):

use Term::ANSIScreen qw(cls);
my $clear_screen = cls();
print $clear_screen;

El módulo Term::Cap también puede obtener la secuencia especial si quiere tratar con los detalles de bajo nivel del control de terminal. El método "Tputs" devuelve la cadena para la capacidad dada:

use Term::Cap;
my $terminal = Term::Cap->Tgetent( { OSPEED => 9600 } );
my $clear_screen = $terminal->Tputs('cl');
print $clear_screen;

En Windows, puede usar el módulo Win32::Console. Después de crear un objeto para el manejador de archivo de salida que desea afectar, llame al método "Cls":

Win32::Console;
my $OUT = Win32::Console->new(STD_OUTPUT_HANDLE);
$OUT->Cls;

Si tiene un programa de línea de comandos que hace el trabajo, puede llamarlo entre comillas invertidas para capturar lo que sea que imprima y poder usarlo más tarde:

my $clear_string = `clear`;
print $clear_string;

¿Cómo obtengo el tamaño de la pantalla?

Si tiene el módulo Term::ReadKey instalado desde CPAN, puede usarlo para obtener el ancho y alto en caracteres y en píxeles:

use Term::ReadKey;
my ($wchar, $hchar, $wpixels, $hpixels) = GetTerminalSize();

Esto es más portable que el "ioctl" bruto, pero no tan ilustrativo:

require './sys/ioctl.ph';
die "no TIOCGWINSZ " unless defined &TIOCGWINSZ;
open(my $tty_fh, "+</dev/tty")
or die "No tty: $!"; unless (ioctl($tty_fh, &TIOCGWINSZ, $winsize='')) { die sprintf "$0: ioctl TIOCGWINSZ (%08x: $!)\n", &TIOCGWINSZ; } my ($row, $col, $xpixel, $ypixel) = unpack('S4', $winsize); print "(row,col) = ($row,$col)"; print " (xpixel,ypixel) = ($xpixel,$ypixel)" if $xpixel || $ypixel; print "\n"; ```

¿Cómo le pido al usuario una contraseña?

(Esta pregunta no tiene nada que ver con la web. Consulta otra FAQ para eso).

Hay un ejemplo de esto en "crypt" en perlfunc. Primero, pones la terminal en modo "sin eco", luego simplemente lees la contraseña normalmente. Puedes hacer esto con una función ioctl() de estilo antiguo, control de terminal POSIX (ver POSIX o su documentación en el Libro del Camello), o una llamada al programa stty, con diversos grados de portabilidad.

También puedes hacer esto para la mayoría de los sistemas utilizando el módulo Term::ReadKey de CPAN, que es más fácil de usar y, en teoría, más portable.

use Term::ReadKey;
ReadMode('noecho');
my $password = ReadLine(0);

¿Cómo leo y escribo en el puerto serie?

Esto depende del sistema operativo en el que se esté ejecutando tu programa. En el caso de Unix, los puertos serie serán accesibles a través de archivos en "/dev"; en otros sistemas, los nombres de los dispositivos sin duda diferirán. Varias áreas problemáticas comunes a toda interacción con dispositivos son las siguientes:

archivos de bloqueo
Tu sistema puede usar archivos de bloqueo para controlar el acceso múltiple. Asegúrate de seguir el protocolo correcto. Pueden producirse comportamientos impredecibles si varios procesos leen de un dispositivo.
modo de apertura
Si esperas usar operaciones de lectura y escritura en el dispositivo, tendrás que abrirlo para actualización (ver "open" en perlfunc para más detalles). Es posible que desees abrirlo sin el riesgo de bloqueo utilizando sysopen() y "O_RDWR|O_NDELAY|O_NOCTTY" del módulo Fcntl (parte de la distribución estándar de perl). Ver "sysopen" en perlfunc para más sobre este enfoque.
fin de línea
Algunos dispositivos esperarán un "\r" al final de cada línea en lugar de un "\n". En algunos puertos de perl, "\r" y "\n" son diferentes de sus valores ASCII habituales (Unix) de "\015" y "\012". Es posible que tengas que dar directamente los valores numéricos que deseas, usando octal ("\015"), hexadecimal ("0x0D"), o como especificación de carácter de control ("\cM"). 
print DEV "atv1\012";    # incorrecto, para algunos dispositivos
print DEV "atv1\015";    # correcto, para algunos dispositivos

Aunque con los archivos de texto normales un "\n" servirá, todavía no existe un esquema unificado para terminar una línea que sea portable entre Unix, DOS/Win y Macintosh, excepto terminar *TODOS* los finales de línea con "\015\012", y eliminar lo que no necesites de la salida. Esto se aplica especialmente a la E/S de sockets y al vaciado automático, que se discuten a continuación.

vaciado de salida
Si esperas que los caracteres lleguen a tu dispositivo cuando los imprimes con print(), querrás vaciar automáticamente ese manejador de archivo. Puedes usar select() y la variable $| para controlar el vaciado automático (ver "$|" en perlvar y "select" en perlfunc, o perlfaq5, "¿Cómo vacío/desbufferizo un manejador de archivo de salida? ¿Por qué debo hacer esto?"): 
my $old_handle = select($dev_fh);
$| = 1;
select($old_handle);

También verás código que hace esto sin una variable temporal, como en

select((select($deb_handle), $| = 1)[0]);

O si no te importa incorporar unos miles de líneas de código solo porque te asusta un poco la variable $|:

use IO::Handle;
$dev_fh->autoflush(1);

Como se mencionó en el punto anterior, esto todavía no funciona cuando se utiliza E/S de sockets entre Unix y Macintosh. En ese caso, tendrás que codificar tus terminadores de línea de forma fija.

entrada no bloqueante
Si estás realizando una lectura bloqueante con read() o sysread(), tendrás que organizar un manejador de alarma para proporcionar un tiempo de espera (ver "alarm" en perlfunc). Si tienes una apertura no bloqueante, probablemente tendrás una lectura no bloqueante, lo que significa que puede que tengas que usar un select() de 4 argumentos para determinar si la E/S está lista en ese dispositivo (ver "select" en perlfunc.

Mientras intentaba leer de su caja de identificación de llamada, el notorio Jamie Zawinski "<jwz@netscape.com>", después de mucho refunfuñar y luchar con "sysread", "sysopen", el asunto de "tcgetattr" de POSIX, y varias otras funciones que hacen ruidos por la noche, finalmente llegó a esto:

sub open_modem {
    use IPC::Open2;
    my $stty = `/bin/stty -g`;
    open2( \*MODEM_IN, \*MODEM_OUT, "cu -l$modem_device -s2400 2>&1");
    # iniciar cu estropea los ajustes de stty de /dev/tty, incluso cuando
    # se ha abierto en una tubería...
    system("/bin/stty $stty");
    $_ = ;
    chomp;
    if ( !m/^Connected/ ) {
        print STDERR "$0: cu imprimió '$_' en lugar de 'Connected'\n";
    }
}

¿Cómo decodifico archivos de contraseñas cifradas?

Gastas mucho, mucho dinero en hardware dedicado, pero esto te hará hablar.

En serio, no puedes si son archivos de contraseña de Unix; el sistema de contraseñas de Unix emplea cifrado unidireccional. Es más como hashing que cifrado. Lo mejor que puedes hacer es comprobar si otra cosa genera el mismo hash. No puedes convertir un hash de nuevo a la cadena original. Programas como Crack pueden intentar adivinar contraseñas por la fuerza (e inteligentemente), pero no garantizan un éxito rápido (ni pueden hacerlo).

Si te preocupa que los usuarios seleccionen contraseñas débiles, deberías comprobar proactivamente cuando intenten cambiar su contraseña (modificando passwd(1), por ejemplo).

¿Cómo inicio un proceso en segundo plano?

(contribuido por brian d foy)

No hay una única forma de ejecutar código en segundo plano para que no tengas que esperar a que termine antes de que tu programa pase a otras tareas. La gestión de procesos depende de tu sistema operativo particular, y muchas de las técnicas se cubren en perlipc.

Varios módulos de CPAN pueden ser de ayuda, incluyendo IPC::Open2 o IPC::Open3, IPC::Run, Parallel::Jobs, Parallel::ForkManager, POE, Proc::Background y Win32::Process. Hay muchos otros módulos que podrías usar, así que consulta esos espacios de nombres para otras opciones también.

Si estás en un sistema tipo Unix, podrías salirte con la tuya con una llamada al sistema donde pones un "&" al final del comando:

system("cmd &")

También puedes intentar usar "fork", como se describe en perlfunc (aunque esto es lo mismo que harán muchos de los módulos por ti).

STDIN, STDOUT y STDERR se comparten
Tanto el proceso principal como el del segundo plano (el proceso "hijo") comparten los mismos manejadores de archivo STDIN, STDOUT y STDERR. Si ambos intentan acceder a ellos al mismo tiempo, pueden ocurrir cosas extrañas. Es posible que desees cerrar o reabrir estos para el hijo. Puedes evitar esto abriendo una tubería ("open") (ver "open" en perlfunc) pero en algunos sistemas esto significa que el proceso hijo no puede sobrevivir al padre.
Señales
Tendrás que capturar la señal SIGCHLD, y posiblemente SIGPIPE también. SIGCHLD se envía cuando el proceso en segundo plano termina. SIGPIPE se envía cuando escribes en un manejador de archivo cuyo proceso hijo ha cerrado (un SIGPIPE no capturado puede hacer que tu programa muera silenciosamente). Esto no es un problema con system("cmd&").
Zombis
Tienes que estar preparado para "recolectar" el proceso hijo cuando termine. 
$SIG{CHLD} = sub { wait };
$SIG{CHLD} = 'IGNORE';

También puedes usar un doble fork. Inmediatamente esperas (wait()) a tu primer hijo, y el demonio init esperará a tu nieto una vez que este salga.

unless ($pid = fork) {
    unless (fork) {
        exec "lo que realmente quieres hacer";
        die "¡exec falló!";
    }
    exit 0;
}
waitpid($pid, 0);

Ver "Signals" en perlipc para otros ejemplos de código para hacer esto. Los zombis no son un problema con "system("prog &")".

¿Cómo atrapo caracteres/señales de control?

En realidad no "atrapas" un carácter de control. En cambio, ese carácter genera una señal que se envía al grupo de procesos actualmente en primer plano de tu terminal, que luego atrapas en tu proceso. Las señales se documentan en "Signals" en perlipc y en la sección sobre "Signals" en el Camello.

Puedes establecer los valores de la hash %SIG para que sean las funciones que quieres que manejen la señal. Después de que Perl capture la señal, busca en %SIG una clave con el mismo nombre que la señal, y luego llama al valor de la subrutina para esa clave.

# como una subrutina anónima
$SIG{INT} = sub { syswrite(STDERR, "ouch\n", 5 ) };
# o una referencia a una función
$SIG{INT} = \&ouch;
# o el nombre de la función como una cadena
$SIG{INT} = "ouch";

¿Cómo puedo escribir expect en Perl?

Érase una vez, existía una biblioteca llamada chat2.pl (parte de la distribución estándar de perl), que nunca se terminó realmente. Si la encuentras en algún lugar, no la uses. Hoy en día, tu mejor opción es buscar el módulo Expect disponible en CPAN, que también requiere otros dos módulos de CPAN, IO::Pty e IO::Stty.

¿Hay alguna forma de ocultar la línea de comandos de perl de programas como "ps"?

Primero que nada, ten en cuenta que si estás haciendo esto por razones de seguridad (para evitar que la gente vea contraseñas, por ejemplo) entonces deberías reescribir tu programa para que la información crítica nunca se proporcione como argumento. Ocultar los argumentos no hará que tu programa sea completamente seguro.

Para alterar realmente la línea de comandos visible, puedes asignar a la variable $0 como se documenta en perlvar. Sin embargo, esto no funcionará en todos los sistemas operativos. Los programas demonio como sendmail colocan su estado allí, como en:

$0 = "orcus [aceptando conexiones]";

Cambié de directorio, modifiqué mi entorno en un script de perl. ¿Por qué el cambio desapareció cuando salí del script? ¿Cómo hago que mis cambios sean visibles?

Unix
En el sentido más estricto, no se puede hacer; el script se ejecuta como un proceso diferente al del shell desde el que se inició. Los cambios en un proceso no se reflejan en su padre; solo en los hijos creados después del cambio. Existe magia del shell que puede permitirte simularlo mediante eval()uando la salida del script en tu shell; consulta el FAQ de comp.unix.questions para más detalles.

¿Cómo cierro el manejador de archivos de un proceso sin esperar a que se complete?

Suponiendo que tu sistema soporta tales cosas, simplemente envía una señal apropiada al proceso (ver "kill" en perlfunc). Es común primero enviar una señal TERM, esperar un poco, y luego enviar una señal KILL para finalizarlo.

¿Cómo creo un proceso demonio con fork?

Si por proceso demonio te refieres a uno que está desconectado (disociado de su tty), entonces el siguiente proceso se reporta que funciona en la mayoría de los sistemas tipo Unix. Los usuarios no Unix deberían consultar su módulo Your_OS::Process para otras soluciones.

  • Abre /dev/tty y usa el ioctl TIOCNOTTY en él. Ver tty(4) para detalles. O mejor aún, puedes simplemente usar la función POSIX::setsid(), para no tener que preocuparte por los grupos de procesos.
  • Cambia el directorio a /
  • Reabre STDIN, STDOUT y STDERR para que no estén conectados al tty anterior.
  • Ponte en segundo plano así: 
    fork && exit;

El módulo Proc::Daemon, disponible en CPAN, proporciona una función para realizar estas acciones por ti.

¿Cómo averiguo si estoy ejecutando interactivamente o no?

(contribuido por brian d foy)

Esta es una pregunta difícil de responder, y la mejor respuesta es solo una suposición.

¿Qué quieres saber realmente? Si simplemente quieres saber si uno de tus manejadores de archivos está conectado a una terminal, puedes probar la prueba de archivo "-t":

if( -t STDOUT ) {
    print "¡Estoy conectado a una terminal!\n";
}

Sin embargo, podrías tener mala suerte si esperas que eso signifique que hay una persona real del otro lado. Con el módulo Expect, otro programa puede fingir ser una persona. El programa incluso podría acercarse a pasar la prueba de Turing.

El módulo IO::Interactive hace lo mejor que puede para darte una respuesta. Su función "is_interactive" devuelve un manejador de salida; ese manejador apunta a la salida estándar si el módulo cree que la sesión es interactiva. De lo contrario, el manejador es un manejador nulo que simplemente descarta la salida:

use IO::Interactive;
print { is_interactive } "¡Quizás vaya a la salida estándar!\n";

Esto todavía no garantiza que una persona real esté respondiendo tus solicitudes o leyendo tu salida.

Si quieres saber cómo manejar las pruebas automatizadas para tu distribución, puedes verificar el entorno. CPAN Testers, por ejemplo, establece el valor de "AUTOMATED_TESTING":

unless( $ENV{AUTOMATED_TESTING} ) {
    print "¡Hola tester interactivo!\n";
}

¿Cómo establezco un tiempo de espera para un evento lento?

Usa la función alarm(), probablemente en conjunción con un manejador de señales, como se documenta en "Signals" en perlipc y la sección sobre "Signals" en el Camel. Alternativamente, puedes usar el módulo Sys::AlarmCall, más flexible, disponible en CPAN.

La función alarm() no está implementada en todas las versiones de Windows. Consulta la documentación de tu versión específica de Perl.

¿Cómo establezco límites de CPU?

(contribuido por Xho)

Usa el módulo BSD::Resource de CPAN. Como ejemplo:

use BSD::Resource;
setrlimit(RLIMIT_CPU,10,20) or die $!;

Esto establece los límites blando y duro en 10 y 20 segundos, respectivamente. Después de 10 segundos de tiempo de CPU empleado en la ejecución (no tiempo de "reloj"), al proceso se le enviará una señal (XCPU en algunos sistemas) que, si no se atrapa, hará que el proceso termine. Si esa señal se atrapa, entonces después de 10 segundos más (20 segundos en total) el proceso será terminado con una señal no atrapable.

Consulta BSD::Resource y la documentación de tu sistema para los detalles escabrosos.

¿Cómo evito los zombies en un sistema Unix?

Usa el código recolector de perlipc "Signals" para llamar a wait() cuando se recibe una SIGCHLD, o usa la técnica de doble fork descrita en "How do I start a process in the background?" en perlfaq8.

¿Cómo uso una base de datos SQL?

El módulo DBI proporciona una interfaz abstracta a la mayoría de los servidores y tipos de bases de datos, incluyendo Oracle, DB2, Sybase, mysql, Postgresql, ODBC y archivos planos. El módulo DBI accede a cada tipo de base de datos a través de un controlador de base de datos, o DBD. Puedes ver una lista completa de los controladores disponibles en CPAN: http://www.cpan.org/modules/by-module/DBD/ . Puedes leer más sobre DBI en http://dbi.perl.org/ .

Otros módulos proporcionan acceso más específico: Win32::ODBC, Alzabo, "iodbc", y otros encontrados en CPAN Search: https://metacpan.org/ .

¿Cómo hago que una llamada a system() salga al presionar control-C?

No puedes. Necesitas imitar la llamada system() (ver perlipc para código de ejemplo) y luego tener un manejador de señales para la señal INT que pase la señal al subproceso. O puedes verificarlo:

$rc = system($cmd);
if ($rc & 127) { die "muerte por señal" }

¿Cómo abro un archivo sin bloquear?

Si tienes la suerte de usar un sistema que soporta lecturas no bloqueantes (la mayoría de los sistemas tipo Unix lo hacen), solo necesitas usar el flag "O_NDELAY" o "O_NONBLOCK" del módulo "Fcntl" en conjunción con sysopen():

use Fcntl;
sysopen(my $fh, "/foo/somefile", O_WRONLY|O_NDELAY|O_CREAT, 0644)
    or die "no se puede abrir /foo/somefile: $!";

¿Cómo diferencio entre errores del shell y de perl?

(respuesta contribuida por brian d foy)

Cuando ejecutas un script de Perl, algo más está ejecutando el script por ti, y ese algo más puede generar mensajes de error. El script podría generar sus propias advertencias y mensajes de error. La mayoría de las veces no puedes decir quién dijo qué.

Probablemente no puedas arreglar lo que ejecuta perl, pero puedes cambiar cómo perl genera sus advertencias definiendo funciones personalizadas de advertencia y muerte.

Considera este script, que tiene un error que quizás no notes inmediatamente.

#!/usr/locl/bin/perl
print "Hola Mundo\n";

Recibo un error cuando ejecuto esto desde mi shell (que resulta ser bash). Eso podría parecer que perl olvidó que tiene una función print(), pero mi línea shebang no es la ruta a perl, así que el shell ejecuta el script, y obtengo el error.

$ ./test
./test: line 3: print: command not found

Una solución rápida y sucia

¿Cómo sé si un mensaje de error proviene de Perl?

La forma más fácil es ver si el mensaje de error tiene la palabra "Perl:" al principio. Este prefijo es añadido por el código:

BEGIN {
    $SIG{__WARN__} = sub{ print STDERR "Perl: ", @_; };
    $SIG{__DIE__}  = sub{ print STDERR "Perl: ", @_; exit 1};
}
use strict;
use warnings;
my $a = 1 + undef;
my $x / 0;

Aquí, el código simplemente añade "Perl:" delante de cada mensaje de advertencia o error fatal. Si ves esa palabra, es de Perl.

Aquí tienes un ejemplo de salida de ese código:

Perl: Use of uninitialized value in addition (+) at ./test line 7.
Perl: Use of uninitialized value in division (/) at ./test line 8.
Perl: Illegal division by zero at ./test line 8.

Si no ves ese prefijo "Perl:", probablemente no sea un error de Perl.

Hay una manera más fácil de depurar errores de Perl sin necesidad de añadir código: puedes usar el pragma "diagnostics" que proporciona una explicación más detallada de los mensajes de error de Perl.

use diagnostics;

Si no obtienes una explicación detallada, probablemente no sea un error de Perl.

Si aún tienes dudas, puedes consultar el manual de Perl "perldiag". Si el mensaje de error no aparece allí, es muy probable que no sea un error de Perl.

¿Cómo instalo un módulo de CPAN?

(contribuido por brian d foy)

La forma más sencilla es usar el módulo CPAN que viene con Perl. Puedes invocarlo desde la línea de comandos para instalar uno o varios módulos:

$ cpan IO::Interactive Getopt::Whatever

Si prefieres usar "CPANPLUS", el proceso es igual de sencillo:

$ cpanp i IO::Interactive Getopt::Whatever

Si quieres instalar una distribución desde el directorio actual, puedes indicarle a "CPAN.pm" que instale "." (el punto):

$ cpan .

Consulta la documentación de esos comandos para ver todas sus funcionalidades.

Si deseas instalar una distribución manualmente, resolviendo tú mismo todas las dependencias, puedes seguir uno de estos dos caminos:

Para distribuciones que usan Makefile.PL:

$ perl Makefile.PL
$ make test install

Para distribuciones que usan Build.PL:

$ perl Build.PL
$ ./Build test
$ ./Build install

Algunas distribuciones pueden requerir enlazar con bibliotecas externas u otro código de terceros, y sus secuencias de compilación e instalación pueden ser más complejas. Revisa los archivos README o INSTALL si los encuentras.

¿Cuál es la diferencia entre require y use?

(contribuido por brian d foy)

Perl ejecuta la sentencia "require" en tiempo de ejecución. Una vez que Perl carga, compila y ejecuta el archivo, no hace nada más. La sentencia "use" es como un "require" ejecutado en tiempo de compilación, pero además Perl llama al método "import" del paquete cargado. Estas dos sentencias son equivalentes:

use MODULE qw(import list);
BEGIN {
    require MODULE;
    MODULE->import(import list);
}

Sin embargo, puedes suprimir la llamada a "import" usando una lista de importación explícita y vacía. Ambas siguen ocurriendo en tiempo de compilación:

use MODULE ();
BEGIN {
    require MODULE;
}

Dado que "use" también llama al método "import", el valor real para "MODULE" debe ser un identificador (bareword). Es decir, "use" no puede cargar archivos por nombre, aunque "require" sí puede:

require "$ENV{HOME}/lib/Foo.pm"; # ¡sin búsqueda en @INC!

Consulta la entrada para "use" en perlfunc para más detalles.

¿Cómo mantengo mi propio directorio de módulos/bibliotecas?

Al compilar módulos, indica a Perl dónde instalarlos.

Si quieres instalar módulos para tu propio uso, la forma más fácil podría ser local::lib, que puedes descargar de CPAN. Configura varias opciones de instalación para ti y utiliza esas mismas opciones dentro de tus programas.

Si buscas más flexibilidad, necesitas configurar tu cliente CPAN para tu situación particular.

Para distribuciones basadas en "Makefile.PL", usa la opción INSTALL_BASE al generar los Makefiles:

perl Makefile.PL INSTALL_BASE=/mydir/perl

Puedes configurar esto en tu configuración de "CPAN.pm" para que los módulos se instalen automáticamente en tu directorio de biblioteca privado cuando uses el shell de CPAN.pm:

% cpan
cpan> o conf makepl_arg INSTALL_BASE=/mydir/perl
cpan> o conf commit

Para distribuciones basadas en "Build.PL", usa la opción --install_base:

perl Build.PL --install_base /mydir/perl

También puedes configurar "CPAN.pm" para que use automáticamente esta opción:

% cpan
cpan> o conf mbuild_arg "--install_base /mydir/perl"
cpan> o conf commit

INSTALL_BASE indica a estas herramientas que coloquen tus módulos en /mydir/perl/lib/perl5. Consulta "¿Cómo añado un directorio a mi ruta de inclusión (@INC) en tiempo de ejecución?" para obtener detalles sobre cómo ejecutar tus módulos recién instalados.

Sin embargo, hay una advertencia con INSTALL_BASE, ya que actúa de manera diferente a las opciones PREFIX y LIB que defendían versiones anteriores de ExtUtils::MakeMaker. INSTALL_BASE no admite la instalación de módulos para múltiples versiones de Perl o arquitecturas diferentes bajo el mismo directorio. Debes considerar si realmente quieres eso y, si es así, usar las opciones PREFIX y LIB antiguas. Consulta la documentación de ExtUtils::MakeMaker para más detalles.

¿Cómo añado el directorio donde vive mi programa a la ruta de búsqueda de módulos/bibliotecas?

(contribuido por brian d foy)

Si conoces el directorio de antemano, puedes añadirlo a @INC como lo harías con cualquier otro directorio. Podrías usar "use lib" si conoces el directorio en tiempo de compilación:

use lib $directory;

El truco en esta tarea es encontrar el directorio. Antes de que tu script haga nada más (como un "chdir"), puedes obtener el directorio de trabajo actual con el módulo "Cwd", que viene con Perl:

BEGIN {
    use Cwd;
    our $directory = cwd;
}
use lib $directory;

Puedes hacer algo similar con el valor de $0, que contiene el nombre del script. Este podría contener una ruta relativa, pero "rel2abs" puede convertirla en una ruta absoluta. Una vez que tengas la

BEGIN {
    use File::Spec::Functions qw(rel2abs);
    use File::Basename qw(dirname);
    my $path   = rel2abs( $0 );
    our $directory = dirname( $path );
}
use lib $directory;

El módulo FindBin, que viene con Perl, podría funcionar. Encuentra el directorio del script que se está ejecutando actualmente y lo coloca en $Bin, que luego puedes usar para construir la ruta de biblioteca correcta:

use FindBin qw($Bin);

También puedes usar local::lib para hacer gran parte de lo mismo. Instala módulos usando la configuración de local::lib y luego usa el módulo en tu programa:

use local::lib; # configura una biblioteca local en ~/perl5

Consulta la documentación de local::lib para más detalles.

¿Cómo añado un directorio a mi ruta de inclusión (@INC) en tiempo de ejecución?

Aquí tienes las formas sugeridas de modificar tu ruta de inclusión, incluyendo variables de entorno, opciones de línea de comandos y sentencias en el código:

la variable de entorno "PERLLIB"
$ export PERLLIB=/path/to/my/dir
$ perl program.pl
la variable de entorno "PERL5LIB"
$ export PERL5LIB=/path/to/my/dir
$ perl program.pl
la opción de línea de comandos "perl -Idir"
$ perl -I/path/to/my/dir program.pl
el pragma "lib":
use lib "$ENV{HOME}/myown_perllib";
el módulo local::lib:
use local::lib;
use local::lib "~/myown_perllib";

¿Dónde se instalan los módulos?

Los módulos se instalan caso por caso (según los métodos descritos en la sección anterior) y en el sistema operativo. Todas estas rutas se almacenan en @INC, que puedes mostrar con el comando:

perl -e 'print join("\n",@INC,"")'

La misma información se muestra al final de la salida del comando

perl -V

Para saber dónde se encuentra el código fuente de un módulo, usa

perldoc -l Encode

para mostrar la ruta del módulo. En algunos casos (por ejemplo, el módulo "AutoLoader"), este comando mostrará la ruta a un archivo "pod" separado; el módulo en sí debería estar en el mismo directorio, con extensión de archivo 'pm'.

¿Qué es socket.ph y dónde lo consigo?

Es un archivo de estilo Perl 4 que define valores para constantes de red del sistema. A veces, puede serse crea usando h2ph cuando se instala Perl, pero otras veces no. Los programas modernos deberían usar "use Socket;" en su lugar.
