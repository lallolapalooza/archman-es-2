¿Cómo vacío/desbufferizo un manejador de archivo de salida? ¿Por qué debo hacer esto?

(contribuido por brian d foy)

Podrías querer leer el artículo de Mark Jason Dominus "Suffering From Buffering" en http://perl.plover.com/FAQs/Buffering.html.

Perl normalmente almacena en búfer la salida para no realizar una llamada al sistema por cada bit de salida. Al acumular la salida, realiza menos llamadas al sistema costosas. Por ejemplo, en este pequeño fragmento de código, deseas imprimir un punto en la pantalla por cada línea que procesas para observar el progreso de tu programa. En lugar de ver un punto por cada línea, Perl almacena la salida en búfer y tienes que esperar mucho tiempo antes de ver una fila de 50 puntos de una vez:

# larga espera, luego una fila de puntos de una vez
while( <> ) {
    print ".";
    print "\n" unless ++$count % 50;
    #... operaciones costosas de procesamiento de línea
}

Para evitar esto, tienes que desbufferizar el manejador de archivo de salida, en este caso, "STDOUT". Puedes establecer la variable especial $| a un valor verdadero (mnecdotécnico: hacer que tus manejadores de archivo estén "calientes como una pipa"):

$|++;
# punto mostrado inmediatamente
while( <> ) {
    print ".";
    print "\n" unless ++$count % 50;
    #... operaciones costosas de procesamiento de línea
}

El $| es una de las variables especiales por manejador de archivo, así que cada manejador de archivo tiene su propia copia de su valor. Si quieres fusionar la salida estándar y el error estándar por ejemplo, tienes que desbufferizar cada uno (aunque STDERR podría estar desbufferizado por defecto):

{
    my $previous_default = select(STDOUT);  # guardar el predeterminado anterior
    $|++;                                   # vaciado automático de STDOUT
    select(STDERR);
    $|++;                                   # vaciado automático de STDERR, para estar seguro
    select($previous_default);              # restaurar el predeterminado anterior
}
# ahora debería alternar . y +
while( 1 ) {
    sleep 1;
    print STDOUT ".";
    print STDERR "+";
    print STDOUT "\n" unless ++$count % 25;
}

Además de la variable especial $|, puedes usar "binmode" para darle a tu manejador de archivo una capa ":unix", que no usa búfer:

binmode( STDOUT, ":unix" );
while( 1 ) {
    sleep 1;
    print ".";
    print "\n" unless ++$count % 50;
}

Para más información sobre capas de salida, consulta las entradas para "binmode" y open en perlfunc, y la documentación del módulo PerlIO.

Si estás usando IO::Handle o una de sus subclases, puedes llamar al método "autoflush" para cambiar la configuración del manejador de archivo:

use IO::Handle;
open my( $io_fh ), ">", "output.txt";
$io_fh->autoflush(1);

Los objetos IO::Handle también tienen un método "flush". Puedes vaciar el búfer en cualquier momento sin desbufferizado automático

$io_fh->flush;

¿Cómo cambio, elimino o inserto una línea en un archivo, o añado al principio de un archivo?

(contribuido por brian d foy)

La idea básica de insertar, cambiar o eliminar una línea de un archivo de texto implica leer e imprimir el archivo hasta el punto donde deseas hacer el cambio, realizar el cambio, y luego leer e imprimir el resto del archivo. Perl no proporciona acceso aleatorio a las líneas (especialmente porque el separador de entrada de registros, $/, es mutable), aunque módulos como Tie::File pueden simularlo.

Un programa Perl para realizar estas tareas toma la forma básica de abrir un archivo, imprimir sus líneas y luego cerrar el archivo:

open my $in,  '<',  $file      or die "No se puede leer el archivo antiguo: $!";
open my $out, '>', "$file.new" or die "No se puede escribir el nuevo archivo: $!";
while( <$in> ) {
        print $out $_;
}
close $out;

Dentro de esa forma básica, añade las partes que necesitas para insertar, cambiar o eliminar líneas.

Para anteponer líneas al principio, imprime esas líneas antes de entrar en el bucle que imprime las líneas existentes.

open my $in,  '<',  $file      or die "No se puede leer el archivo antiguo: $!";
open my $out, '>', "$file.new" or die "No se puede escribir el nuevo archivo: $!";
print $out "# Añadir esta línea al principio\n"; # <--- AQUÍ ESTÁ LA MAGIA
while( <$in> ) {
        print $out $_;
}
close $out;

Para cambiar líneas existentes, inserta el código para modificar las líneas dentro del bucle "while". En este caso, el código encuentra todas las versiones en minúsculas de "perl" y las pone en mayúsculas. Esto ocurre para cada línea, así que asegúrate de que se supone que debes hacer eso en cada línea.

open my $in,  '<',  $file      or die "No se puede leer el archivo antiguo: $!";
open my $out, '>', "$file.new" or die "No se puede escribir el nuevo archivo: $!";
print $out "# Añadir esta línea al principio\n";
while( <$in> ) {
    s/\b(perl)\b/Perl/g;
    print $out $_;
}
close $out;

Para cambiar solo una línea particular, el número de línea de entrada, $., es útil. Primero lee e imprime las líneas hasta la que quieres cambiar. Luego, lee la única línea que quieres cambiar, cámbiala y imprímela. Después de eso, lee el resto de las líneas e imprímelas:

while( <$in> ) { # imprime las líneas antes del cambio
    print $out $_;
    last if $. == 4; # número de línea antes del cambio
}
my $line = <$in>;
$line =~ s/\b(perl)\b/Perl/g;
print $out $line;
while( <$in> ) { # imprime el resto de las líneas
    print $out $_;
}

Para omitir líneas, usa los controles de bucle. El "next" en este ejemplo omite las líneas de comentarios, y el "last" detiene todo el procesamiento una vez que encuentra el marcador "__END__" o "__DATA__".

while( <$in> ) {
    next if /^\s+#/;             # omitir líneas de comentarios
    last if /^__(END|DATA)__$/;  # detener en el marcador de fin de código
    print $out $_;
}

Haz lo mismo para eliminar una línea particular usando "next" para omitir las líneas que no deseas que aparezcan en la salida. Este ejemplo omite cada quinta línea:

while( <$in> ) {
    next unless $. % 5;
    print $out $_;
}

Si, por alguna razón extraña, realmente quieres ver el archivo entero de una vez en lugar de procesarlo línea por línea, puedes cargarlo (¡siempre que quepa entero en memoria!):

open my $in,  '<',  $file      or die "No se puede leer el archivo antiguo: $!";
open my $out, '>', "$file.new" or die "No se puede escribir el nuevo archivo: $!";
my $content = do { local $/; <$in> }; # ¡cargar!
    # haz tu magia aquí
print $out $content;

Módulos como Path::Tiny y Tie::File también pueden ayudar con eso. Sin embargo, si es posible, evita leer el archivo completo a la vez. Perl no devolverá esa memoria al sistema operativo hasta que termine el proceso.

También puedes usar one-liners de Perl para modificar un archivo in-situ. Lo siguiente cambia todos los 'Fred' por 'Barney' en inFile.txt, sobrescribiendo el archivo con el nuevo contenido. Con el switch "-p", Perl envuelve un bucle "while" alrededor del código que especificas con "-e", y "-i" activa la edición in-situ. La línea actual está en $_. Con "-p", Perl imprime automáticamente el valor de $_ al final del bucle. Consulta perlrun para más detalles.

perl -pi -e 's/Fred/Barney/' inFile.txt

Para hacer una copia de seguridad de "inFile.txt", dale a "-i" una extensión de archivo para añadir:

perl -pi.bak -e 's/Fred/Barney/' inFile.txt

Para cambiar solo la quinta línea, puedes añadir una prueba que verifique $., el número de línea de entrada, y luego solo realizar la operación cuando la prueba sea verdadera:

perl -pi -e 's/

¿Cómo puedo modificar un archivo sobre la marcha?

Puede modificar archivos sobre la marcha utilizando el conmutador "-i". Esto le permite pasar un nombre de archivo o de extensión de archivo, que actúa como copia de seguridad. Si no se proporciona, Perl creará una copia de seguridad temporal.

perl -pi -e 's/viejo/nuevo/' miArchivo.txt

Esto reemplazará la primera ocurrencia de "viejo" por "nuevo" en cada línea de `miArchivo.txt`. Si quisiera hacer una copia de seguridad, puede hacer lo siguiente:

perl -pi.bak -e 's/viejo/nuevo/' miArchivo.txt

Esto creará un archivo de copia de seguridad llamado `miArchivo.txt.bak` y modificará el original. Puede agregar líneas antes de una línea determinada agregando una línea (¡o líneas!) antes de que Perl imprima $_:

perl -pi -e 'print "Poner antes de la tercera línea\n" if $. == 3' miArchivo.txt

Incluso puede agregar una línea al principio de un archivo, ya que la línea actual se imprime al final del bucle:

perl -pi -e 'print "Poner antes de la primera línea\n" if $. == 1' miArchivo.txt

Para insertar una línea después de una que ya está en el archivo, use el conmutador "-n". Es como "-p" excepto que no imprime $_ al final del bucle, por lo que debe hacerlo usted mismo. En este caso, imprima $_ primero y luego imprima la línea que desea agregar.

perl -ni -e 'print; print "Poner después de la quinta línea\n" if $. == 5' miArchivo.txt

Para eliminar líneas, solo imprima las que desee.

perl -ni -e 'print if /d/' miArchivo.txt

¿Cómo cuento el número de líneas en un archivo?

(contribuido por brian d foy)

Conceptualmente, la forma más fácil de contar las líneas en un archivo es simplemente leerlas y contarlas:

mi $contador = 0;
mientras( <$fh> ) { $contador++; }

Sin embargo, realmente no tiene que contarlas usted mismo, ya que Perl ya lo hace con la variable $., que es el número de línea actual del último manejador de archivos leído:

1 mientras( <$fh> );
mi $contador = $.;

Si desea utilizar $., puede reducirlo a una simple línea de comando, como una de estas:

% perl -lne '} print $.; {'    archivo
% perl -lne 'END { print $. }' archivo

Sin embargo, esas pueden ser bastante ineficientes. Si no son lo suficientemente rápidas para usted, podría simplemente leer fragmentos de datos y contar el número de saltos de línea:

mi $líneas = 0;
abrir mi($fh), '<:raw', $nombrearchivo o morir "No se puede abrir $nombrearchivo: $!";
mientras( sysread $fh, $buffer, 4096 ) {
    $líneas += ( $buffer =~ tr/\n// );
}
cerrar $fh;

Sin embargo, eso no funciona si el final de línea no es un salto de línea. Podría cambiar ese "tr///" por un "s///" para poder contar el número de veces que aparece el separador de registros de entrada, $/:

mi $líneas = 0;
abrir mi($fh), '<:raw', $nombrearchivo o morir "No se puede abrir $nombrearchivo: $!";
mientras( sysread $fh, $buffer, 4096 ) {
    $líneas += ( $buffer =~ s|$/||g );
}
cerrar $fh;

Si no le importa delegar a un proceso externo, el comando "wc" suele ser el más rápido, incluso con la sobrecarga adicional entre procesos. Asegúrese de tener un nombre de archivo no contaminado, sin embargo:

#!perl -T
$ENV{PATH} = undef;
mi $líneas;
si( $nombrearchivo =~ /^([0-9a-z_.]+)\z/ ) {
    $líneas = `/usr/bin/wc -l $1`;
    chomp $líneas;
}

¿Cómo elimino las últimas N líneas de un archivo?

(contribuido por brian d foy)

La solución conceptual más sencilla es contar las líneas del archivo y luego empezar desde el principio e imprimir el número de líneas (menos las últimas N) a un archivo nuevo.

La mayoría de las veces, la pregunta real es cómo eliminar las últimas N líneas sin hacer más de un paso por el archivo, o cómo hacerlo sin copiar mucho. El concepto fácil es la realidad difícil cuando puede tener millones de líneas en su archivo.

Un truco es usar File::ReadBackwards, que comienza al final del archivo. Ese módulo proporciona un objeto que envuelve el manejador de archivos real para facilitarle el movimiento por el archivo. Una vez que llegue al lugar que necesita, puede obtener el manejador de archivos real y trabajar con él como de costumbre. En este caso, obtendrá la posición del archivo al final de la última línea que desea conservar y truncará el archivo a ese punto:

usar File::ReadBackwards;
mi $nombrearchivo = 'test.txt';
mi $Líneas_a_truncar = 2;
mi $bw = File::ReadBackwards->new( $nombrearchivo )
    o morir "No se pudo leer hacia atrás en [$nombrearchivo]: $!";
mi $líneas_desde_el_final = 0;
hasta( $bw->eof o $líneas_desde_el_final == $Líneas_a_truncar ) {
    imprimir "Obtenido: ", $bw->readline;
    $líneas_desde_el_final++;
}
truncar( $nombrearchivo, $bw->tell );

El módulo File::ReadBackwards también tiene la ventaja de establecer el separador de registros de entrada en una expresión regular.

También puede usar el módulo Tie::File, que le permite acceder a las líneas a través de una matriz enlazada. Puede usar operaciones de matriz normales para modificar su archivo, incluido el establecimiento del último índice y el uso de "splice".

¿Cómo puedo usar la opción "-i" de Perl desde dentro de un programa?

"-i" establece el valor de la variable $^I de Perl, lo que a su vez afecta el comportamiento de "<>"; vea perlrun para más detalles. Al modificar las variables apropiadas directamente, puede obtener el mismo comportamiento dentro de un programa más grande. Por ejemplo:

# ...
{
    local($^I, @ARGV) = ('.orig', glob("*.c"));
    mientras (<>) {
        si ($. == 1) {
            imprimir "Esta línea debe aparecer en la parte superior de cada archivo\n";
        }
        s/\b(p)earl\b/${1}erl/i;        # Corregir erratas, conservando mayúsculas/minúsculas
        imprimir;
        cerrar ARGV si eof;              # Restablecer $.
    }
}
# $^I y @ARGV vuelven a sus viejos valores aquí

Este bloque modifica todos los archivos ".c" en el directorio actual, dejando una copia de seguridad de los datos originales de cada archivo en un nuevo archivo ".c.orig".

¿Cómo copio un archivo?

(contribuido por brian d foy)

Use el módulo File::Copy. Viene con Perl y puede hacer una copia real entre sistemas de archivos, y hace su magia de manera portátil.

usar File::Copy;
copiar( $original, $nueva_copia ) o morir "La copia falló: $!";

Si no puede usar File::Copy, tendrá que hacer el trabajo usted mismo: abrir el archivo original, abrir el archivo de destino e imprimir en el archivo de destino mientras lee el original. También debe recordar copiar los permisos, el propietario y el grupo al nuevo archivo.

¿Cómo creo un nombre de archivo temporal?

Si no necesita conocer el nombre del archivo, puede usar open() con "undef" en lugar del nombre del archivo. En Perl 5.8 o posterior, la función open() crea un archivo temporal anónimo:

abrir mi $tmp, '+>', undef o morir $!;

De lo contrario, puede usar el módulo File::Temp.

usar File::Temp qw/ tempfile tempdir /;
mi $dir = tempdir( CLEANUP => 1 );
($fh, $nombrearchivo) = tempfile( DIR => $dir );
# o si no necesitas saber el nombre del archivo
mi $fh = tempfile( DIR => $dir );

File::Temp ha sido un módulo estándar desde Perl 5.6.1. Si no tiene un Perl lo suficientemente moderno instalado, use el método de clase "new_tmpfile" del módulo IO::File para obtener un manejador de archivos abierto para lectura y escritura. Úselo si no necesita saber el nombre del archivo:

usar IO::File;
mi $fh = IO::File->new_tmpfile()
    o morir "No se pudo crear un nuevo archivo temporal: $!";

Si está decidido a crear un archivo temporal manualmente, use el ID del proceso y/o el valor de tiempo actual. Si necesita tener muchos archivos temporales en un solo proceso, use un contador:

INICIO {
    usar Fcntl;
    usar File::Spec;
    mi $temp_dir  = File::Spec->tmpdir();
    mi $file_base = sprintf "%d-%d-0000", $$, tiempo;
    mi $base_name = File::Spec->catfile($temp_dir, $file_base);
    sub temp_file {
        mi $fh;
        mi $contador = 0;
        hasta( defined(fileno($fh)) || $contador++ > 100 ) {
            $base_name =~ s/-(\d+)$/"-" . (1 + $1)/e;
            # O_EXCL es necesario por razones de seguridad.
            sysopen $fh, $base_name, O_WRONLY|O_EXCL|O_CREAT;
        }
        si( defined fileno($fh) ) {
            devolver ($fh, $base_name);
        }
        else {
            devolver ();
        }
    }
}

¿Cómo manipulo archivos de longitud de registro fija?

La forma más eficiente es usar pack() y unpack(). Esto es más rápido que usar substr() al tomar muchas, muchas cadenas. Es más lento para solo unas pocas.

Aquí hay un fragmento de código de ejemplo para dividir y volver a unir algunas líneas de entrada de formato fijo, en este caso, de la salida de un ps normal, estilo Berkeley:

# línea de entrada de ejemplo:
#   15158 p5  T      0:00 perl /home/tchrist/scripts/now-what
mi $PS_T = 'A6 A4 A7 A5 A*';
abrir mi $ps, '-|', 'ps';
imprimir escalar <$ps>;
mis @campos = qw( pid tt stat time command );
mientras (<$ps>) {
    mi %proceso;
    @proceso{@campos} = unpack($PS_T, $_);
    para mi $campo ( @campos ) {
        imprimir "$campo: <$process{$field}>\n";
    }
    imprimir 'línea=', pack($PS_T, @process{@campos} ), "\n";
}

Hemos utilizado una rebanada de hash para manejar fácilmente los campos de cada fila. Almacenar las claves en una matriz facilita operarlas como un grupo o iterar sobre ellas con "for". También evita contaminar el programa con variables globales y usar referencias simbólicas.

¿Cómo hago que un manejador de archivo sea local a una subrutina? ¿Cómo paso manejadores de archivo entre subrutinas? ¿Cómo creo una matriz de manejadores de archivo?

abrir mi    $fh, $nombre_archivo;
abrir local $fh, $nombre_archivo;
imprimir $fh "Hola Mundo!\n";
procesar_archivo( $fh );

Cuando abro un archivo para leer-escribir, ¿por qué lo borra?

Porque estás usando algo como esto, que trunca el archivo y luego te da acceso de lectura-escritura:

open my $fh, '+>', '/ruta/nombre'; # INCORRECTO (casi siempre)

Ups. En su lugar, deberías usar esto, que fallará si el archivo no existe:

open my $fh, '+<', '/ruta/nombre'; # abre para actualización

Usar ">" siempre sobrescribe o crea. Usar "<" nunca hace ninguna de las dos cosas. El "+" no cambia esto.

Aquí tienes ejemplos de muchos tipos de apertura de archivos. Los que usan "sysopen" asumen que has importado las constantes de Fcntl:

use Fcntl;

Para abrir un archivo para lectura:

open my $fh, '<', $path                               or die $!;
sysopen my $fh, $path, O_RDONLY                       or die $!;

Para abrir un archivo para escritura, crea un archivo nuevo si es necesario o trunca uno existente:

open my $fh, '>', $path                               or die $!;
sysopen my $fh, $path, O_WRONLY|O_TRUNC|O_CREAT       or die $!;
sysopen my $fh, $path, O_WRONLY|O_TRUNC|O_CREAT, 0666 or die $!;

Para abrir un archivo para escritura, crea un archivo nuevo, el archivo no debe existir:

sysopen my $fh, $path, O_WRONLY|O_EXCL|O_CREAT        or die $!;
sysopen my $fh, $path, O_WRONLY|O_EXCL|O_CREAT, 0666  or die $!;

Para abrir un archivo para añadir, crea si es necesario:

open my $fh, '>>', $path                              or die $!;
sysopen my $fh, $path, O_WRONLY|O_APPEND|O_CREAT      or die $!;
sysopen my $fh, $path, O_WRONLY|O_APPEND|O_CREAT, 0666 or die $!;

Para abrir un archivo para añadir, el archivo debe existir:

sysopen my $fh, $path, O_WRONLY|O_APPEND              or die $!;

Para abrir un archivo para actualización, el archivo debe existir:

open my $fh, '+<', $path                              or die $!;
sysopen my $fh, $path, O_RDWR                         or die $!;

Para abrir un archivo para actualización, crea el archivo si es necesario:

sysopen my $fh, $path, O_RDWR|O_CREAT                 or die $!;
sysopen my $fh, $path, O_RDWR|O_CREAT, 0666           or die $!;

Para abrir un archivo para actualización, el archivo no debe existir:

sysopen my $fh, $path, O_RDWR|O_EXCL|O_CREAT          or die $!;
sysopen my $fh, $path, O_RDWR|O_EXCL|O_CREAT, 0666    or die $!;

Para abrir un archivo sin bloqueo, creándolo si es necesario:

sysopen my $fh, '/foo/somefile', O_WRONLY|O_NDELAY|O_CREAT
    or die "no se puede abrir /foo/somefile: $!";

Ten en cuenta que ni la creación ni la eliminación de archivos están garantizadas como operaciones atómicas sobre NFS. Es decir, ¡dos procesos podrían crear o desenlazar exitosamente el mismo archivo! Por lo tanto, O_EXCL no es tan exclusivo como podrías desear.

¿Por qué a veces recibo un "Argument list too long" cuando uso <*>?

El operador "<>" realiza una operación de glob (ver arriba). En versiones de Perl anteriores a la v5.6.0, el operador interno glob() llama a csh(1) para realizar la expansión del glob, pero csh no puede manejar más de 127 elementos y, por lo tanto, muestra el mensaje de error "Argument list too long". Las personas que instalaron tcsh como csh no tendrán este problema, pero sus usuarios pueden sorprenderse por él.

Para evitar esto, actualiza a Perl v5.6.0 o posterior, haz el glob tú mismo con readdir() y patrones, o usa un módulo como File::Glob, uno que no use el shell para hacer el glob.

¿Cómo puedo abrir un archivo nombrado con un ">" inicial o espacios al final?

(contribuido por Brian McCauley)

La forma especial de dos argumentos de la función open() de Perl ignora los espacios al final de los nombres de archivo e infiere el modo de ciertos caracteres iniciales (o una "|" al final). En versiones antiguas de Perl, esta era la única forma de open() y, por lo tanto, es prevalente en código y libros antiguos.

A menos que tengas una razón particular para usar la forma de dos argumentos, deberías usar la forma de tres argumentos de open(), que no trata ningún carácter del nombre de archivo como especial.

open my $fh, "<", "  archivo  ";  # el nombre del archivo es "  archivo  "
open my $fh, ">", ">archivo";     # el nombre del archivo es ">archivo"

¿Cómo puedo renombrar un archivo de forma fiable?

Si tu sistema operativo soporta una utilidad mv(1) adecuada o su equivalente funcional, esto funciona:

rename($viejo, $nuevo) or system("mv", $viejo, $nuevo);

Puede ser más portable usar en su lugar el módulo File::Copy. Simplemente copias al nuevo archivo con el nuevo nombre (comprobando los valores de retorno), y luego eliminas el antiguo. Esto no es realmente lo mismo semánticamente que un rename(), que preserva metainformación como permisos, marcas de tiempo, información de inodo, etc.

¿Cómo puedo bloquear un archivo?

La función integrada de Perl flock() (ver perlfunc para más detalles) llamará a flock(2) si existe, a fcntl(2) si no (en la versión 5.004 de perl y posteriores), y a lockf(3) si ninguna de las dos llamadas anteriores existe. En algunos sistemas, puede incluso usar una forma diferente de bloqueo nativo. Aquí hay algunas trampas con el flock() de Perl:

1.
Produce un error fatal si ninguna de las tres llamadas al sistema (o su equivalente cercano) existe.
2.
lockf(3) no proporciona bloqueo compartido y requiere que el manejador de archivo esté abierto para escritura (o para añadir, o para lectura/escritura).
3.
Algunas versiones de flock() no pueden bloquear archivos en red (por ejemplo, en sistemas de archivos NFS), por lo que necesitarías forzar el uso de fcntl(2) al compilar Perl. Pero incluso esto es dudoso en el mejor de los casos. Ver la entrada flock de perlfunc y el archivo INSTALL en la distribución fuente para obtener información sobre cómo compilar Perl para hacer esto.

Dos semánticas de flock potencialmente no obvias pero tradicionales son que espera indefinidamente hasta que se concede el bloqueo, y que sus bloqueos son meramente consultivos. Tales bloqueos discrecionales son más flexibles, pero ofrecen menos garantías. Esto significa que los archivos bloqueados con flock() pueden ser modificados por programas que no usan también flock(). Los coches que se detienen en los semáforos se llevan bien entre sí, pero no con los coches que no se detienen en los semáforos. Ver la página del manual perlport, la documentación específica de tu puerto, o tus páginas del manual locales específicas del sistema para más detalles. Es mejor asumir el comportamiento tradicional si estás escribiendo programas portables. (Si no lo estás, como siempre, siéntete perfectamente libre de escribir para las idiosincrasias de tu propio sistema (a veces llamadas "características"). La adhesión servil a las preocupaciones de portabilidad no debería interponerse en tu camino para hacer tu trabajo.)

Para más información sobre el bloqueo de archivos, ver también "File Locking" en perlopentut si lo tienes (nuevo para 5.6).

¿Por qué no puedo simplemente abrir(FH, ">archivo.lock")?

Un fragmento de código común que **NO SE DEBE USAR** es este:

sleep(3) while -e 'archivo.lock';    # POR FAVOR NO USAR
open my $lock, '>', 'archivo.lock'; # ESTE CÓDIGO ESTÁ ROTO

Esta es una condición de carrera clásica: das dos pasos para hacer algo que debe hacerse en uno solo. Por eso el hardware de las computadoras proporciona una instrucción atómica de test-and-set. En teoría, esto "debería" funcionar:

sysopen my $fh, "archivo.lock", O_WRONLY|O_EXCL|O_CREAT
    or die "no se puede abrir  archivo.lock: $!";

excepto que, lamentablemente, la creación (y eliminación) de archivos no es atómica sobre NFS, por lo que esto no funcionará (al menos, no siempre) a través de la red. Se han sugerido varios esquemas que involucran link(), pero estos tienden a implicar busy-wait, lo cual tampoco es deseable.

Todavía no entiendo el bloqueo. Solo quiero incrementar el número en el archivo. ¿Cómo puedo hacer esto?

¿Nadie te dijo que los contadores de visitas de páginas web son inútiles? No cuentan el número de visitas, son una pérdida de tiempo y solo sirven para halagar la vanidad del escritor. Es mejor elegir un número aleatorio; son más realistas.

De todos modos, esto es lo que puedes hacer si no puedes evitarlo.

use Fcntl qw(:DEFAULT :flock);
sysopen my $fh, "numfile", O_RDWR|O_CREAT or die "no se puede abrir numfile: $!";
flock $fh, LOCK_EX                        or die "no se puede flock numfile: $!";
my $num = <$fh> || 0;
seek $fh, 0, 0                            or die "no se puede rebobinar numfile: $!";
truncate $fh, 0                           or die "no se puede truncar numfile: $!";
(print $fh $num+1, "\n")                  or die "no se puede escribir numfile: $!";
close $fh                                 or die "no se puede cerrar numfile: $!";

Aquí tienes un contador de visitas de páginas web mucho mejor:

$hits = int( (time() - 850_000_000) / rand(1_000) );

Si el recuento no impresiona a tus amigos, entonces el código podría hacerlo. :-)

Todo lo que quiero hacer es añadir un poco de texto al final de un archivo. ¿Todavía tengo que usar bloqueo?

Si estás en un sistema que implementa correctamente "flock" y usas el código de ejemplo para añadir de "perldoc -f flock" todo estará bien, incluso si el sistema operativo en el que te encuentras no implementa el modo de añadir correctamente (si es que existe tal sistema). Así que si te conformas con limitarte a sistemas operativos que implementan "flock" (y esa no es realmente una gran restricción), entonces eso es lo que deberías hacer.

Si sabes que solo vas a usar un sistema que implementa correctamente la adición (es decir, no Win32), entonces puedes omitir el "seek" del código de la respuesta anterior.

Si sabes que solo estás escribiendo código para ejecutarse en un sistema operativo y un sistema de archivos que implementan correctamente el modo de adición (por ejemplo, un sistema de archivos local en un Unix moderno), y mantienes el archivo en modo de búfer de bloque y escribes menos de un búfer entre cada vaciado manual del búfer, entonces cada carga de búfer casi está garantizada que se escribirá al final del archivo en un solo bloque sin mezclarse con la salida de nadie más. También puedes usar la función "syswrite" que es simplemente un envoltorio alrededor de la llamada al sistema write(2) de tu sistema.

Todavía existe una pequeña posibilidad teórica de que una señal interrumpa la operación write() a nivel de sistema antes de su finalización. También existe la posibilidad de que algunas implementaciones de STDIO realicen múltiples escrituras a nivel de sistema incluso si el búfer estaba vacío al principio. Puede haber algunos sistemas donde esta probabilidad se reduzca a cero, y esto no es una preocupación al usar ":perlio" en lugar del STDIO de tu sistema.

¿Cómo actualizo aleatoriamente un archivo binario?

Si solo estás intentando parchear un binario, en muchos casos algo tan simple como esto funciona:

perl -i -pe 's{window manager}{window mangler}g' /usr/bin/emacs

Sin embargo, si tienes registros de tamaño fijo, entonces podrías hacer algo más parecido a esto:

my $RECSIZE = 220; # tamaño del registro, en bytes
my $recno   = 37;  # qué registro actualizar
open my $fh, '+<', 'somewhere' or die "no se puede actualizar somewhere: $!";
seek $fh, $recno * $RECSIZE, 0;
read $fh, $record, $RECSIZE == $RECSIZE or die "no se puede leer el registro $recno: $!";
# modificar el registro
seek $fh, -$RECSIZE, 1;
print $fh $record;
close $fh;

¿Cómo obtengo la marca de tiempo de un archivo en Perl?

Si deseas recuperar el momento en que el archivo fue leído, escrito o sus metadatos (propietario, etc.) modificados por última vez, usa las operaciones de prueba de archivo -A, -M o -C como se documenta en perlfunc. Estas recuperan la antigüedad del archivo (medida contra el momento de inicio de tu programa) en días como un número de punto flotante. Algunas plataformas pueden no tener todos estos tiempos. Consulta perlport para obtener detalles. Para recuperar el tiempo "crudo" en segundos desde la época, llamarías a la función stat y luego usarías localtime(), gmtime() o POSIX::strftime() para convertirlo a un formato legible por humanos.

Aquí tienes un ejemplo:

my $write_secs = (stat($file))[9];
printf "archivo %s actualizado a las %s\n", $file,
    scalar localtime($write_secs);

Si prefieres algo más legible, usa el módulo File::stat (parte de la distribución estándar en la versión 5.004 y posteriores):

# la comprobación de errores se deja como ejercicio para el lector.
use File::stat;
use Time::localtime;
my $date_string = ctime(stat($file)->mtime);
print "archivo $file actualizado a las $date_string\n";

El enfoque de POSIX::strftime() tiene el beneficio de ser, en teoría, independiente de la configuración regional actual. Consulta perllocale para obtener detalles.

¿Cómo establezco la marca de tiempo de un archivo en Perl?

Utilizas la función utime() documentada en "utime" en perlfunc. A modo de ejemplo, aquí tienes un pequeño programa que copia los tiempos de lectura y escritura de su primer argumento a todos los demás.

if (@ARGV < 2) {
    die "uso: cptimes archivo_marca_tiempo otros_archivos ...\n";
}
my $timestamp = shift;
my($atime, $mtime) = (stat($timestamp))[8,9];
utime $atime, $mtime, @ARGV;

La comprobación de errores, como de costumbre, se deja como ejercicio para el lector.

La documentación de perldoc para utime también tiene un ejemplo que tiene el mismo efecto que touch(1) en archivos que *ya existen*.

Ciertos sistemas de archivos tienen una capacidad limitada para almacenar las marcas de tiempo en un archivo con el nivel de precisión esperado. Por ejemplo, los sistemas de archivos FAT y HPFS no pueden crear fechas en archivos con una granularidad más fina que dos segundos. Esta es una limitación de los sistemas de archivos, no de utime().

¿Cómo imprimo en más de un archivo a la vez?

Para conectar un manejador de archivo a varios manejadores de archivo de salida, puedes usar los módulos IO::Tee o Tie::FileHandle::MultiPlex.

Si solo tienes que hacerlo una vez, puedes imprimir individualmente en cada manejador de archivo.

for my $fh ($fh1, $fh2, $fh3) { print $fh "lo que sea\n" }

¿Cómo puedo leer un archivo completo de una vez?

El enfoque habitual de Perl para procesar todas las líneas de un archivo es hacerlo línea por línea:

open my $input, '<', $file or die "no se puede abrir $file: $!";
while (<$input>) {
    chomp;
    # haz algo con $_
}
close $input or die "no se puede cerrar $file: $!";

Esto es tremendamente más eficiente que leer todo el archivo en memoria como una matriz de líneas y luego procesarlo elemento por elemento, lo cual es a menudo, si no casi siempre, el enfoque incorrecto. Cada vez que veas a alguien hacer esto:

my @lines = <INPUT>;

Deberías pensar detenidamente por qué necesitas que todo se cargue a la vez. Simplemente no es una solución escalable.

Si usas "mmap" el archivo con el módulo File::Map de CPAN, puedes cargar virtualmente todo el archivo en una cadena sin almacenarlo realmente en memoria:

use File::Map qw(map_file);
map_file my $string, $filename;

Una vez mapeado, puedes tratar $string como cualquier otra cadena. Dado que no necesariamente tienes que cargar los datos, mmap-ing puede ser muy rápido y puede que no aumente tu huella de memoria.

También podrías encontrar más divertido usar el módulo estándar Tie::File, o las vinculaciones $DB_RECNO del módulo DB_File, que te permiten vincular una matriz a un archivo de modo que acceder a un elemento de la matriz accede realmente a la línea correspondiente en el archivo.

Si deseas cargar todo el archivo, puedes usar el módulo Path::Tiny para hacerlo en un paso simple y eficiente:

use Path::Tiny;
my $all_of_it = path($filename)->slurp; # todo el archivo en escalar
my @all_lines = path($filename)->lines; # una línea por elemento

O puedes leer todo el contenido del archivo en una variable escalar así:

my $var;
{
    local $/;
    open my $fh, '<', $file or die "no se puede abrir $file: $!";
    $var = <$fh>;
}

Eso desdefine temporalmente tu separador de registro y cerrará automáticamente el archivo al salir del bloque. Si el archivo ya está abierto, simplemente usa esto:

my $var = do { local $/; <$fh> };

También puedes usar un @ARGV localizado para eliminar el "open":

my $var = do { local( @ARGV, $/ ) = $file; <> };

¿Cómo puedo leer un archivo por párrafos?

Usa la variable $/ (consulta perlvar para obtener detalles). Puedes establecerla en "" para eliminar párrafos vacíos ("abc\n\n\n\ndef", por ejemplo, se trata como dos párrafos y no tres), o en "\n\n" para aceptar párrafos vacíos.

Ten en cuenta que una línea en blanco debe no tener espacios en blanco. Por lo tanto "fred\n \nstuff\n\n" es un párrafo, pero "fred\n\nstuff\n\n" son dos.

¿Cómo puedo leer un solo carácter de un archivo? ¿Del teclado?

Puedes usar la función incorporada getc() para la mayoría de los manejadores de archivo, pero no funcionará (fácilmente) en un dispositivo de terminal. Para STDIN, usa el módulo Term::ReadKey de CPAN o usa el código de ejemplo en "getc" en perlfunc.

Si tu sistema soporta la interfaz de programación de sistemas operativos portátiles (POSIX), puedes usar el siguiente código, que notarás que también desactiva el procesamiento del eco.

#!/usr/bin/perl -w
use strict;
$| = 1;
for (1..4) {
    print "dame: ";
    my $got = getone();
    print "--> $got\n";
}
exit;
BEGIN {
    use POSIX qw(:termios_h);
    my ($term, $oterm, $echo, $noecho, $fd_stdin);
    my $fd_stdin = fileno(STDIN);
    $term     = POSIX::Termios->new();
    $term->getattr($fd_stdin);
    $oterm     = $term->getlflag();
    $echo     = ECHO | ECHOK | ICANON;
    $noecho   = $oterm & ~$echo;
    sub cbreak {
        $term->setlflag($noecho);
        $term->setcc(VTIME, 1);
        $term->setattr($fd_stdin, TCSANOW);
    }
    sub cooked {
        $term->setlflag($oterm);
        $term->setcc(VTIME, 0);
        $term->setattr($fd_stdin, TCSANOW);
    }
    sub getone {
        my $key = '';
        cbreak();
        sysread(STDIN, $key, 1);
        cooked();
        return $key;
    }
}
END { cooked() }

use Term::ReadKey;
open my $tty, '<', '/dev/tty';
print "Dime un carácter: ";
ReadMode "raw";
my $key = ReadKey 0, $tty;
ReadMode "normal";
printf "\ Dijiste %s, número de carácter %03d\n",
    $key, ord $key;

¿Cómo puedo saber si hay un carácter esperando en un filehandle?

Lo primero que deberías hacer es buscar la extensión Term::ReadKey de CPAN. Como mencionamos antes, ahora incluso tiene soporte limitado para sistemas no portables (es decir: no sistemas abiertos, cerrados, propietarios, no POSIX, no Unix, etc.).

También deberías consultar la lista de Preguntas Frecuentes en comp.unix.* para cosas como esta: la respuesta es esencialmente la misma. Depende mucho del sistema. Aquí hay una solución que funciona en sistemas BSD:

sub key_ready {
    my($rin, $nfd);
    vec($rin, fileno(STDIN), 1) = 1;
    return $nfd = select($rin,undef,undef,0);
}

Si quieres saber cuántos caracteres están esperando, también está la llamada ioctl FIONREAD para considerar. La herramienta h2ph que viene con Perl intenta convertir archivos de inclusión de C a código Perl, que se puede "require". FIONREAD termina definido como una función en el archivo sys/ioctl.ph:

require './sys/ioctl.ph';
$size = pack("L", 0);
ioctl(FH, FIONREAD(), $size)    or die "No se pudo llamar a ioctl: $!\n";
$size = unpack("L", $size);

Si h2ph no estaba instalado o no te funciona, puedes buscar en los archivos de inclusión manualmente:

% grep FIONREAD /usr/include/*/*
/usr/include/asm/ioctls.h:#define FIONREAD      0x541B

O escribe un pequeño programa en C usando el editor de los campeones:

% cat > fionread.c
#include <sys/ioctl.h>
main() {
    printf("%#08x\n", FIONREAD);
}
^D
% cc -o fionread fionread.c
% ./fionread
0x4004667f

Y luego codifícalo de forma fija, dejando la portabilidad como ejercicio para tu sucesor.

$FIONREAD = 0x4004667f;         # XXX: dependiente del sistema operativo
$size = pack("L", 0);
ioctl(FH, $FIONREAD, $size)     or die "No se pudo llamar a ioctl: $!\n";
$size = unpack("L", $size);

FIONREAD requiere un filehandle conectado a un stream, lo que significa que los sockets, pipes y dispositivos tty funcionan, pero los archivos no.

¿Cómo hago un "tail -f" en perl?

Primero intenta

seek($gw_fh, 0, 1);

La declaración "seek($gw_fh, 0, 1)" no cambia la posición actual, pero sí borra la condición de fin de archivo en el handle, de modo que el siguiente "<$gw_fh>" hace que Perl intente leer algo de nuevo.

Si eso no funciona (depende de las características de tu implementación de stdio), entonces necesitas algo más parecido a esto:

for (;;) {
  for ($curpos = tell($gw_fh); <$gw_fh>; $curpos =tell($gw_fh)) {
    # busca algo y ponlo en archivos
  }
  # duerme un rato
  seek($gw_fh, $curpos, 0);  # busca a donde habíamos estado
}

Si esto todavía no funciona, investiga el método "clearerr" de IO::Handle, que reinicia los estados de error y fin de archivo en el handle.

También hay un módulo File::Tail de CPAN.

¿Cómo hago un dup() de un filehandle en Perl?

Si consultas "open" en perlfunc, verás que varias de las formas de llamar a open() deberían funcionar. Por ejemplo:

open my $log, '>>', '/foo/logfile';
open STDERR, '>&', $log;

O incluso con un descriptor numérico literal:

my $fd = $ENV{MHCONTEXTFD};
open $mhcontext, "<&=$fd";  # como fdopen(3S)

Ten en cuenta que "<&STDIN" hace una copia, pero "<&=STDIN" crea un alias. Eso significa que si cierras un handle con alias, todos los alias se vuelven inaccesibles. Esto no ocurre con uno copiado.

La comprobación de errores, como siempre, se ha dejado como un ejercicio para el lector.

¿Cómo cierro un descriptor de archivo por número?

Si, por alguna razón, tienes un descriptor de archivo en lugar de un filehandle (quizás usaste "POSIX::open"), puedes usar la función close() del módulo POSIX:

use POSIX ();
POSIX::close( $fd );

Esto rara vez debería ser necesario, ya que la función close() de Perl se usa para cosas que Perl abrió por sí mismo, incluso si fue un dup de un descriptor numérico como con "MHCONTEXT" arriba. Pero si realmente tienes que hacerlo, puedes intentar esto:

require './sys/syscall.ph';
my $rc = syscall(SYS_close(), $fd + 0);  # forzar numérico
die "no se puede sysclose $fd: $!" if $rc == -1;

O, simplemente usa la característica fdopen(3S) de open():

{
    open my $fh, "<&=$fd" or die "No se puede reabrir fd=$fd: $!";
    close $fh;
}

¿Por qué no puedo usar "C:\temp\foo" en rutas de DOS? ¿Por qué no funciona `C:\temp\foo.exe`?

¡Vaya! ¡Acabas de poner un tabulador y un salto de página en ese nombre de archivo! Recuerda que dentro de las cadenas entre comillas dobles ("como\esto"), la barra invertida es un carácter de escape. La lista completa de estos se encuentra en "Quote and Quote-like Operators" en perlop. No es sorprendente que no tengas un archivo llamado "c:(tabulador)(salto de página)oo" o "c:(tabulador)(salto de página)oo.exe" en tu sistema de archivos DOS heredado.

O usa comillas simples para tus cadenas, o (preferiblemente) usa barras inclinadas. Dado que todas las versiones de DOS y Windows desde algo como MS-DOS 2.0 o posterior han tratado "/" y "\" de la misma manera en una ruta, podrías usar la que no entra en conflicto con Perl, o con el shell POSIX, ANSI C y C++, awk, Tcl, Java o Python, solo por mencionar algunos. Las rutas POSIX también son más portables.

¿Por qué glob("*. *") no obtiene todos los archivos?

Porque incluso en puertos no Unix, la función glob de Perl sigue la semántica estándar de globbing de Unix. Necesitarás glob("*") para obtener todos los archivos (no ocultos). Esto hace que glob() sea portable incluso a sistemas heredados. Tu puerto puede incluir funciones de globbing propietarias también. Consulta su documentación para más detalles.

¿Por qué Perl me deja eliminar archivos de solo lectura? ¿Por qué "-i" sobrescribe archivos protegidos? ¿No es esto un error en Perl?

Esto se describe de forma elaborada y minuciosa en el artículo file-dir-perms de la colección "Far More Than You Ever Wanted To Know" en http://www.cpan.org/misc/olddoc/FMTEYEWTK.tgz .

El resumen ejecutivo: aprende cómo funciona tu sistema de archivos. Los permisos de un archivo dicen qué se puede hacer con los datos de ese archivo. Los permisos de un directorio dicen qué se puede hacer con la lista de archivos en ese directorio. Si eliminas un archivo, estás quitando su nombre del directorio (por lo que la operación depende de los permisos del directorio, no de los del archivo). Si intentas escribir en el archivo, los permisos del archivo rigen si se te permite hacerlo.

¿Cómo selecciono una línea aleatoria de un archivo?

Aparte de cargar el archivo en una base de datos o pre-indexar las líneas en el archivo, hay un par de cosas que puedes hacer.

Aquí hay un algoritmo de muestreo de reservorio del Camel Book:

srand;
rand($.) < 1 && ($line = $_) while <>;

Esto tiene una ventaja significativa en espacio sobre leer el archivo completo. Puedes encontrar una prueba de este método en The Art of Computer Programming, Volumen 2, Sección 3.4.2, de Donald E. Knuth.

Puedes usar el módulo File::Random, que proporciona una función para ese algoritmo:

use File::Random qw/random_line/;
my $line = random_line($filename);

Otra forma es usar el módulo Tie::File, que trata el archivo completo como un array. Simplemente accede a un elemento aleatorio del array.

¿Por qué obtengo espacios raros cuando imprimo un array de líneas?

(contribuido por brian d foy)

Si estás viendo espacios entre los elementos de tu array cuando imprimes el array, probablemente estás interpolando el array en comillas dobles:

my @animals = qw(camel llama alpaca vicuna);
print "animals are: @animals\n";

Son las comillas dobles, no el "print", lo que hace esto. Cada vez que interpolas un array en un contexto de comillas dobles, Perl une los elementos con espacios (o lo que sea que esté en $", que es un espacio por defecto):

animals are: camel llama alpaca vicuna

Esto es diferente de imprimir el array sin la interpolación:

my @animals = qw(camel llama alpaca vicuna);
print "animals are: ", @animals, "\n";

Ahora la salida no tiene los espacios entre los elementos porque los elementos de @animals simplemente se convierten en parte de la lista para "print":

animals are: camelllamaalpacavicuna

Puedes notar esto cuando cada uno de los elementos de @array termina con un salto de línea. Esperas imprimir un elemento por línea, pero notas que cada línea después de la primera está indentada:

this is a line
 this is another line
 this is the third line

Ese espacio adicional proviene de la interpolación del array. Si no quieres poner nada entre tus elementos de array

¿Cómo listo el contenido de un directorio?

(contribuido por Tom Christiansen)

Puedes usar el globbing de Perl:

@list = <*>;

Esto te da una lista de todos los archivos y directorios en el directorio actual. Para listar solo los archivos ocultos, usa:

@list = <.*>;

Si quieres listar los contenidos de un directorio específico, puedes usar:

$dir = "/path/to/directory";
@list = "$dir/*";

Sin embargo, esto también incluirá la ruta del directorio. Si prefieres tener solo los nombres de archivo, puedes usar el módulo File::Slurp (disponible en CPAN) o el módulo IO::Dir (incluido con Perl):

use IO::Dir '$dir';
my $dh = IO::Dir->new( $dir );
while ( $_ = $dh->read ) {
    next if $_ eq '.' || $_ eq '..';
    # hacer algo con $_
}

También puede ser útil usar la función glob:

@files = glob("/path/to/directory/*");

Si necesitas que se filtre el contenido de un directorio, puedes usar la misma sintaxis que con el globbing de Perl:

@lines = <pattern>;

Aquí, pattern puede ser cualquier patrón de globbing. Por ejemplo, para listar solo los archivos que terminan en .txt:

@lines = <*.txt>;

Para obtener una lista de todos los directorios que comienzan con `dir_`:

@dir_list = <dir_*>;

Es importante tener en cuenta que el globbing de Perl funciona en el sistema de archivos, por lo que el patrón se expande antes de que se use el valor. Si el patrón no coincide con nada, puede que obtengas el patrón literal como resultado (dependiendo de tu configuración y versión de Perl).

También ten en cuenta que si quieres imprimir una lista de archivos, no necesitas rodear el array con comillas dobles. Puedes enviarlo a imprimir sin ellas:

print @lines;

¿Cómo recorro el árbol de directorios?

(contribuido por brian d foy)

El módulo File::Find, que viene con Perl, hace todo el trabajo duro para recorrer una estructura de directorios. Simplemente llama a la subrutina "find" con una subrutina de devolución de llamada y los directorios que deseas recorrer:

use File::Find;
find( \&wanted, @directories );
sub wanted {
    # ruta completa en $File::Find::name
    # solo el nombre de archivo en $_
    ... haz lo que quieras hacer ...
}

Las File::Find::Closures, que puedes descargar de CPAN, proporcionan muchas subrutinas listas para usar que puedes utilizar con File::Find.

El módulo File::Finder, que puedes descargar de CPAN, puede ayudarte a crear la subrutina de devolución de llamada utilizando algo más cercano a la sintaxis de la utilidad de línea de comandos "find":

use File::Find;
use File::Finder;
my $deep_dirs = File::Finder->depth->type('d')->ls->exec('rmdir','{}');
find( $deep_dirs->as_options, @places );

El módulo File::Find::Rule, que puedes descargar de CPAN, tiene una interfaz similar, pero también hace el recorrido por ti:

use File::Find::Rule;
my @files = File::Find::Rule->file()
                         ->name( '*.pm' )
                         ->in( @INC );

¿Cómo elimino un árbol de directorios?

(contribuido por brian d foy)

Si tienes un directorio vacío, puedes usar la función incorporada de Perl "rmdir". Si el directorio no está vacío (es decir, con archivos o subdirectorios), tienes que vaciarlo tú mismo (mucho trabajo) o usar un módulo para que te ayude.

El módulo File::Path, que viene con Perl, tiene una función "remove_tree" que puede encargarse de todo el trabajo duro por ti:

use File::Path qw(remove_tree);
remove_tree( @directories );

El módulo File::Path también tiene una interfaz heredada para la subrutina más antigua "rmtree".

¿Cómo copio un directorio completo?

(contribuido por Shlomi Fish)

Para hacer el equivalente a "cp -R" (es decir, copiar un árbol de directorios completo recursivamente) en Perl portable, necesitarás escribir algo tú mismo o encontrar un buen módulo de CPAN como File::Copy::Recursive.
