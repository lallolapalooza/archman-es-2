NAME

perlqnx - Perl version 5 on QNX

DESCRIPTION

As of perl5.7.2 all tests pass under:

QNX 4.24G
Watcom 10.6 with Beta/970211.wcc.update.tar.F
socket3r.lib Nov21 1996.

As of perl5.8.1 there is at least one test still failing.

Some tests may complain under known circumstances.

See below and hints/qnx.sh for more information.

Under QNX 6.2.0 there are still a few tests which fail. See below and hints/qnx.sh for more information.

Software Requerido para Compilar Perl en QNX4

Al igual que muchos ports de Unix, este depende de algunas utilidades "estándar" de Unix que no son necesariamente estándar para QNX4.

/bin/sh
Se usa intensivamente por Configure y luego por el propio perl. La versión de QNX4 está bien, pero Configure fallará con la versión de 16 bits, así que si estás ejecutando QNX 4.22, enlaza /bin/sh a /bin32/ksh
ar
Este es el constructor de bibliotecas estándar de Unix. Usamos wlib. Con Watcom 10.6, cuando wlib se enlaza como "ar", se comporta como ar y todo está bien. Bajo la versión 9.5, se requiere una capa de abstracción. Una está incluida en ../qnx
nm
Se usa (opcionalmente) por configure para listar el contenido de las bibliotecas. Generaré una función de cobertura sobre la marcha en el directorio UU.
cpp
Configure y perl necesitan una forma de invocar un preprocesador C. He creado una simple capa de abstracción para cc que hace lo correcto. Sin esto, Configure creará su propio script de envoltura que funciona, pero no maneja algunos de los argumentos de línea de comandos que perl le enviará.
make
Realmente necesitas GNU make para compilar esto. GNU make viene por defecto con QNX 4.23, pero puedes obtenerlo de quics para versiones anteriores.

Problemas Pendientes con Perl en QNX4

No hay soporte para bibliotecas enlazadas dinámicamente en QNX4.

Si deseas compilar con la extensión Socket, necesitas tener el kit de herramientas TCP/IP, y necesitas asegurarte de que -lsocket localiza la copia correcta de socket3r.lib. Ten en cuenta que el compilador Watcom viene con una versión stub de socket3r.lib que tiene muy poca funcionalidad. Ten también cuidado con el orden en que wlink busca directorios para las bibliotecas. Puede que tengas /usr/lib/socket3r.lib apuntando a la biblioteca correcta, pero wlink puede coger /usr/watcom/10.6/usr/lib/socket3r.lib en su lugar. Asegúrate de que ambos apuntan a la biblioteca correcta, es decir, /usr/tcptk/current/usr/lib/socket3r.lib.

Las siguientes pruebas pueden reportar errores bajo QNX4:

dist/Cwd/Cwd.t se quejará si `pwd` y cwd no dan los mismos resultados. cwd llama a `fullpath -t`, así que si haces cd `fullpath -t` antes de ejecutar la prueba, pasará.

lib/File/Find/taint.t se quejará si '.' está en tu PATH. La prueba PATH se activa porque cwd llama a `fullpath -t`.

ext/IO/lib/IO/t/io_sock.t: Las subpruebas 14 y 22 se omiten debido al hecho de que la funcionalidad para leer el estado no bloqueante de un socket no está implementada en el TCP/IP de QNX. Esto ha sido reportado a QNX y puede funcionar con versiones posteriores de TCP/IP.

t/io/tell.t: La subprueba 27 está fallando. Aún estamos investigando.

Archivos auxiliares de QNX

Los archivos en el directorio "qnx" son:

qnx/ar
Un script que emula la utilidad estándar de archivo (también conocida como biblioteca) de Unix. Bajo Watcom 10.6, ar se enlaza a wlib y proporciona la interfaz esperada. Con Watcom 9.5, se requiere una capa de abstracción. Esta es bastante rudimentaria pero ha demostrado ser adecuada para compilar perl.
qnx/cpp
Un script que proporciona funcionalidad de preprocesamiento C. Configure puede generar una capa de abstracción similar, pero no maneja todas las opciones de línea de comandos que perl le lanza. Esto podría colocarse razonablemente en /usr/local/bin.

Problemas Pendientes con perl bajo QNX6

Las siguientes pruebas siguen fallando para Perl 5.8.1 bajo QNX 6.2.0:

op/sprintf.........................FAILED at test 91
lib/Benchmark......................FAILED at test 26

Esto se debe a un error en la rutina printf de la biblioteca C. printf("'%e'", 0. ) produce '0.000000e+0', pero ANSI requiere '0.000000e+00'. QNX ha reconocido el error.

Compilación Cruzada

Perl soporta la compilación cruzada a QNX NTO a través del Native Development Kit (NDK) para Blackberry 10. Esto significa que puedes hacer compilación cruzada tanto para las versiones ARM como x86 de la plataforma.

Configuración de un entorno de compilación cruzada

Puedes descargar el NDK desde http://developer.blackberry.com/native/downloads/.

Consulta http://developer.blackberry.com/native/documentation/cascades/getting_started/setting_up.html para obtener instrucciones sobre cómo configurar tu dispositivo antes de intentar cualquier otra cosa.

Una vez que hayas instalado el NDK y configurado tu dispositivo, todo lo que queda es configurar el dispositivo y el entorno de compilación cruzada. Blackberry proporciona un script, "bbndk-env.sh" (ocasionalmente llamado algo como "bbndk-env_10_1_0_4828.sh") que se puede usar para hacer esto. Sin embargo, hay un pequeño obstáculo que debemos superar: El script modifica PATH de modo que 'gcc' o 'ar' apunten a sus equivalentes de compilación cruzada, lo que estropea el proceso de compilación.

Así que en lugar de eso, querrás hacer algo como esto:

$ orig_path=$PATH
$ source $location_of_bbndk/bbndk-env*.sh
$ export PATH="$orig_path:$PATH"

Además de colocar el compilador cruzado y el resto de la cadena de herramientas en tu PATH, esto también proporcionará la variable QNX_TARGET, que pasaremos a Configure a través de -Dsysroot.

Preparación del sistema de destino

Es muy posible que el sistema de destino no tenga un /tmp fácilmente disponible, por lo que generalmente es más seguro hacer algo como esto:

$ ssh $TARGETUSER@$TARGETHOST 'rm -rf perl; mkdir perl; mkdir perl/tmp'
$ export TARGETDIR=`ssh $TARGETUSER@$TARGETHOST pwd`/perl
$ export TARGETENV="export TMPDIR=$TARGETDIR/tmp; "

Más adelante, pasaremos esto a Configure a través de -Dtargetenv

Llamando a Configure

Si estás apuntando a un dispositivo ARM — que actualmente incluye la gran mayoría de teléfonos y tabletas — querrás pasar -Dcc=arm-unknown-nto-qnx8.0.0eabi-gcc a Configure. Alternativamente, si estás apuntando a un dispositivo x86, o usando el simulador proporcionado con el NDK, deberías especificar -Dcc=ntox86-gcc en su lugar.

Una invocación de ejemplo de Configure se parece a esto:

./Configure -des -Dusecrosscompile \
    -Dsysroot=$QNX_TARGET          \
    -Dtargetdir=$TARGETDIR         \
    -Dtargetenv="$TARGETENV"       \
    -Dcc=ntox86-gcc                \
    -Dtarghost=... # Opciones habituales de compilación cruzada
