PERF-LIST(1) Manual de perf PERF-LIST(1)

NOMBRE

perf-list - Enumera todos los tipos de eventos simbólicos

SINOPSIS

perf list [<opciones>]
            [hw|sw|cache|tracepoint|pmu|sdt|metric|metricgroup|event_glob]

DESCRIPCIÓN

Este comando muestra los tipos de eventos simbólicos que se pueden seleccionar en los diversos comandos de perf con la opción -e.

OPCIONES

-d, --desc

Imprime descripciones adicionales de eventos. (predeterminado)

--no-desc

No imprime descripciones.

-v, --long-desc

Imprime descripciones de eventos más largas y todas las PMU similares con sufijos alfanuméricos.

--debug

Habilita la salida de depuración.

--details

Imprime cómo los eventos nombrados se resuelven internamente en eventos de perf, y también cualquier expresión adicional calculada por perf stat.

--deprecated

Imprime eventos obsoletos. Por defecto, los eventos obsoletos se ocultan.

--unit

Imprime eventos de PMU y métricas limitadas al nombre específico de la PMU. (por ejemplo, --unit cpu, --unit msr, --unit cpu_core, --unit cpu_atom)

-j, --json

Salida en formato JSON.

-o, --output=

Nombre del archivo de salida. Por defecto, la salida se escribe en stdout.

MODIFICADORES DE EVENTOS

Los eventos opcionalmente pueden tener un modificador al añadir dos puntos y uno o más modificadores. Los modificadores permiten al usuario restringir los eventos a contar. Los siguientes modificadores existen:

u - conteo en espacio de usuario
k - conteo en kernel
h - conteo en hypervisor
I - conteo no inactivo
G - conteo en guest (en guests KVM)
H - conteo en host (no en guests KVM)
p - nivel de precisión
P - usar el nivel de precisión máximo detectado
S - leer valor de muestra (PERF_SAMPLE_READ)
D - fijar el evento a la PMU
W - el grupo es débil y recurrirá a no-grupo si no es programable,
e - el grupo o evento son exclusivos y no comparten la PMU
b - usar agregación BPF (ver perf stat --bpf-counters)
R - valor de latencia de retiro del evento

El modificador p se puede usar para especificar cuán preciso debe ser la dirección de la instrucción. El modificador p se puede especificar varias veces:

0 - SAMPLE_IP puede tener un "skid" arbitrario
1 - SAMPLE_IP debe tener un "skid" constante
2 - SAMPLE_IP solicitado para tener "skid" 0
3 - SAMPLE_IP debe tener "skid" 0, o usa aleatorización para evitar
    efectos de sombreado de muestras.

Para sistemas Intel, el muestreo de eventos precisos se implementa con PEBS, que admite hasta el nivel de precisión 2, y el nivel de precisión 3 para algunos casos especiales.

En sistemas AMD, se implementa usando IBS OP (hasta el nivel de precisión 2). A diferencia de PEBS de Intel, que proporciona niveles de precisión, la PMU del núcleo AMD es inherentemente no precisa y IBS es inherentemente precisa. (es decir, ibs_op//, ibs_op//p, ibs_op//pp e ibs_op//ppp son todos iguales). El modificador preciso funciona con los tipos de evento 0x76 (ciclos de cpu, relojes de CPU no detenidos) y 0xC1 (micro-ops retiradas). Ambos eventos se mapean al muestreo de ejecución IBS (operación IBS) con el bit IBS Op Counter Control (IbsOpCntCtl) configurado respectivamente (ver la sección del Núcleo Complejo (CCX) -> Procesador x86 Core -> Muestreo Basado en Instrucciones (IBS) del [AMD Processor Programming Reference (PPR)] relevante para la familia, modelo y paso del procesador utilizado).

Volumen 2: Programación de Sistemas, 13.3 Muestreo Basado en Instrucciones).

Ejemplos para usar IBS:

perf record -a -e cpu-cycles:p ...    # usar conteo de ciclos op IBS
perf record -a -e r076:p ...          # igual que -e cpu-cycles:p
perf record -a -e r0C1:p ...          # usar conteo de micro-ops op IBS

DESCRIPCIÓN DE EVENTO DE HARDWARE EN BRUTO

Incluso cuando un evento no está disponible en forma simbólica dentro de perf actualmente, se puede codificar de una manera específica por procesador.

Por ejemplo, en CPUs x86, N es un valor hexadecimal que representa la codificación bruta del registro con el diseño de los MSRs IA32_PERFEVTSELx (ver [Intel® 64 and IA-32 Architectures Software Developer’s Manual Volume 3B: System Programming Guide] Figura 30-1 Diseño de los MSRs IA32_PERFEVTSELx) o los MSRs PERF_CTL de AMD (ver la sección Registros MSR del Núcleo Complejo (CCX) -> Procesador x86 Core -> en el [AMD Processor Programming Reference (PPR)] relevante para la familia, modelo y paso del procesador utilizado).

Nota: Solo los siguientes campos de bits se pueden configurar en los registros de contador x86: evento, umask, edge, inv, cmask. Especialmente las banderas de modo guest/host y OS/usuario deben configurarse usando MODIFICADORES DE EVENTOS.

Ejemplo:

Si los documentos de Intel para un Core i7 QM720 describen un evento como:

Número de  Valor  Mnemónico  Descripción              Comentario
Evento     Umask  Event Mask
A8H        01H    LSD.UOPS   Cuenta el número de micro-ops  Usar cmask=1 e
                          entregadas por el detector    invertir para contar
                          de flujo de bucle            ciclos

Se puede usar la codificación bruta de 0x1a8:

perf stat -e r1a8 -a sleep 1
perf record -e r1a8 ...

También es posible usar la sintaxis pmu:

perf record -e r1a8 -a sleep 1
perf record -e cpu/r1a8/ ...
perf record -e cpu/r0x1a8/ ...

Algunos procesadores, como los de AMD, admiten códigos de evento y máscaras de unidad más grandes que un byte. En tales casos, los bits correspondientes a los parámetros de configuración del evento se pueden ver con:

cat /sys/bus/event_source/devices/<pmu>/format/<config>

Ejemplo:

Si los documentos de AMD para un procesador EPYC 7713 describen un evento como:

Número de  Valor  Mnemónico                        Descripción
Evento     Umask  Event Mask
28FH       03H    op_cache_hit_miss.op_cache_hit  Cuenta eventos de
                                              micro-etiqueta de Op Cache
                                              que aciertan.

la codificación bruta de 0x0328F no se puede usar ya que el nibble superior de los bits EventSelect debe especificarse a través de los bits 32-35, como se puede ver con:

cat /sys/bus/event_source/devices/cpu/format/event

en su lugar, se debe usar la codificación bruta 0x20000038F:

perf stat -e r20000038f -a sleep 1
perf record -e r20000038f ...

También es posible usar la sintaxis pmu:

perf record -e r20000038f -a sleep 1
perf record -e cpu/r20000038f/ ...
perf record -e cpu/r0x20000038f/ ...

Debe consultar la documentación específica del procesador para obtener estos detalles. Algunos de ellos se referencian en la sección VE TAMBIÉN a continuación.

PMUS ARBITRARIAS

Perf también admite una sintaxis extendida para especificar parámetros brutos a las PMUs. Usar esto generalmente requiere buscar el evento específico en la documentación específica del proveedor de CPU.

Las PMUs disponibles y sus parámetros brutos se pueden enumerar con

ls /sys/bus/event_source/devices/*/format

Por ejemplo, el evento PMU de núcleo "LSD.UOPS" bruto anterior podría especificarse como

perf stat -e cpu/event=0xa8,umask=0x1,name=LSD.UOPS_CYCLES,cmask=0x1/ ...
o usando la sintaxis de nombre extendida
perf stat -e cpu/event=0xa8,umask=0x1,cmask=0x1,name=\'LSD.UOPS_CYCLES:cmask=0x1\'/ ...

PMUS POR SOCKET

Algunas PMUs no están asociadas con un núcleo, sino con un zócalo de CPU completo. Los eventos en estas PMUs generalmente no se pueden muestrear, sino solo contar globalmente con perf stat -a. Se pueden vincular a una CPU lógica, pero medirán todas las CPUs del mismo zócalo.

Este ejemplo mide el ancho de banda de memoria cada segundo en el primer controlador de memoria en el zócalo 0 de un sistema Intel Xeon

perf stat -C 0 -a uncore_imc_0/cas_count_read/,uncore_imc_0/cas_count_write/ -I 1000 ...

Cada controlador de memoria tiene su propia PMU. Medir el ancho de banda completo del sistema requeriría especificar todas las PMUs imc (ver la salida de perf list) y sumar los valores.
