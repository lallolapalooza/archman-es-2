PERLBS2000(1perl) Guía de referencia para programadores de Perl PERLBS2000(1perl)

NOMBRE

perlbs2000 - compilación e instalación de Perl para BS2000.

Este documento necesita ser actualizado, pero no sabemos qué debería decir. Por favor, envía comentarios a https://github.com/Perl/perl5/issues.

SINÓPSIS

Este documento te ayudará a configurar, compilar, probar e instalar Perl en BS2000 dentro del subsistema POSIX.

DESCRIPCIÓN

Este es un Perl portado para el subsistema POSIX en BS2000 VERSIÓN OSD V3.1A o posterior. Puede que funcione en otras versiones, pero comenzamos el porting y las pruebas con la 3.1A y actualmente usamos la Versión V4.0A.

Puede que necesites los siguientes programas GNU para instalar Perl:

gzip en BS2000

Usamos la versión 1.2.4, que pudo ser instalada directamente con un fallo durante 'make check'.

bison en BS2000

El yacc que viene con BS2000 POSIX no nos funcionó. Así que tuvimos que usar bison. Tuvimos que hacer algunos cambios en Perl para poder usar el parser puro (reentrante) de bison. Usamos la versión 1.25, pero tuvimos que añadir algunos cambios debido a EBCDIC. Ver más abajo para más detalles sobre yacc.

Desempaquetado de la Distribución Perl en BS2000

Para extraer un archivo tar ASCII en BS2000 POSIX necesitas un sistema de archivos ASCII (usamos el punto de montaje /usr/local/ascii para esto). Ahora extraes el archivo en el sistema de archivos ASCII sin conversión de I/O:

cd /usr/local/ascii export IO_CONVERSION=NO gunzip < /usr/local/src/perl.tar.gz | pax -r

Puedes ignorar el mensaje de error para el primer elemento del archivo (esto no parece un archivo tar / saltando al siguiente archivo...), es solo el directorio que se creará automáticamente de todos modos.

Después de extraer el archivo, copias todo el árbol de directorios a tu sistema de archivos EBCDIC. **Esta vez usas conversión de I/O**:

cd /usr/local/src IO_CONVERSION=YES cp -r /usr/local/ascii/perl5.005_02 ./

Compilación de Perl en BS2000

Hay un archivo de "pistas" para BS2000 llamado hints.posix-bc (porque posix-bc es el nombre del SO dado por `uname`) que especifica los valores correctos para la mayoría de las cosas. El principal problema es (por supuesto) el conjunto de caracteres EBCDIC. Tenemos la versión alemana de EBCDIC.

Debido a nuestros problemas con el yacc nativo usamos GNU bison para generar un parser puro (=reentrante) para perly.y. Así que nuestro yacc es en realidad el siguiente script:

-----8<-----/usr/local/bin/yacc-----8<----- #! /usr/bin/sh

# Bison como un yacc reentrante:

# guardar parámetros: params="" while [[ $# -gt 1 ]]; do
params="$params $1"
shift done

# añadir flag %pure_parser:

tmpfile=/tmp/bison.$$.y echo %pure_parser > $tmpfile cat $1 >> $tmpfile

# llamar a bison:

echo "/usr/local/bin/bison --yacc $params $1\t\t\t(Analizador Puro)" /usr/local/bin/bison --yacc $params $tmpfile

# limpieza:

rm -f $tmpfile -----8<----------8<-----

Todavía usamos el yacc normal para a2p.y, ¡¡¡sin embargo!!! Hicimos un enlace simbólico llamado byacc para distinguir entre las dos versiones:

ln -s /usr/bin/yacc /usr/local/bin/byacc

Compilamos Perl usando GNU make. Intentamos usar el make nativo una vez y también funcionó.

Pruebas de Perl en BS2000

Todavía obtuvimos algunos errores durante "make test". Algunos de ellos son el resultado de usar bison. Bison imprime *parser error* en lugar de *syntax error*, por lo que podemos ignorarlos. La siguiente lista muestra nuestros errores, tus resultados pueden variar:

Instalación de Perl en BS2000

No tenemos nroff en BS2000 POSIX (todavía), así que ignoramos cualquier error durante la instalación de la documentación.

Uso de Perl en el Shell Posix de BS2000

BS2000 POSIX no soporta la notación shebang ("#!/usr/local/bin/perl"), así que tienes que usar las siguientes líneas en su lugar:

: # usar perl
eval 'exec /usr/local/bin/perl -S $0 ${1+"$@"}'
if 0; # ^ Ejecutar solo bajo un shell

Uso de Perl en BS2000 "nativo"

No tenemos mucha experiencia con esto todavía, pero intenta lo siguiente:

Copia tu ejecutable de Perl a un LLM de BS2000 usando bs2cp:

"bs2cp /usr/local/bin/perl 'bs2:perl(perl,l)'"

Ahora puedes iniciarlo con el siguiente comando (SDF):

"/START-PROG FROM-FILE=*MODULE(PERL,PERL),PROG-MODE=*ANY,RUN-MODE=*ADV"

Primero obtendrás el prompt de la línea de comandos de BS2000 ('*'). Aquí puedes introducir tus parámetros, por ejemplo "-e 'print "Hello World!\\n";'" (¡¡¡nota la doble barra invertida!!!) o "-w" y el nombre de tu script Perl. Los nombres de archivo que empiezan con "/" se buscan en el sistema de archivos Posix, otros se buscan en el sistema de archivos de BS2000. Incluso puedes usar comodines si pones un "%" delante de tu nombre de archivo (por ejemplo, "-w checkfiles.pl %*.c"). Lee tu manual de C/C++ para posibilidades adicionales del prompt de la línea de comandos (busca en PARAMETER-PROMPTING).

Anomalías de punto flotante en BS2000

Parece haber un error en la implementación de punto flotante en sistemas POSIX de BS2000 de tal manera que llamar a int() sobre el producto de un número y un número de pequeña magnitud no es lo mismo que llamar a int() sobre el cociente de ese número y un número de gran magnitud. Por ejemplo, en el siguiente código Perl:

my $x = 100000.0;
my $y = int($x * 1e-5) * 1e5; # '0'
my $z = int($x / 1e+5) * 1e5;  # '100000'
print "\$y es $y y \$z es $z\n"; # $y es 0 y $z es 100000

Aunque uno esperaría que las cantidades $y y $z fueran iguales y equivalentes a 100000, diferirán y en su lugar serán 0 y 100000 respectivamente.

Uso de PerlIO y diferentes codificaciones en particiones ASCII y EBCDIC

Desde la versión 5.8, Perl usa el nuevo PerlIO en BS2000. Esto te permite usar diferentes codificaciones por canal de I/O. Por ejemplo, puedes usar

use Encode;
open($f, ">:encoding(ascii)", "test.ascii");
print $f "Hola Mundo!\n";
open($f, ">:encoding(posix-bc)", "test.ebcdic");
print $f "Hola Mundo!\n";
open($f, ">:encoding(latin1)", "test.latin1");
print $f "Hola Mundo!\n";
open($f, ">:encoding(utf8)", "test.utf8");

;); print $f "Hola Mundo!\n";

para obtener dos archivos que contengan "Hola Mundo!\n" en ASCII, EBCDIC, ISO Latin-1 (en este ejemplo idéntico a ASCII) y UTF-EBCDIC (en este ejemplo idéntico a EBCDIC normal). Consulte la documentación de Encode::PerlIO para obtener más detalles.

Como la capa PerlIO utiliza E/S crudas internamente, todo esto ignora totalmente el tipo de tu sistema de archivos (ASCII o EBCDIC) y la variable de entorno IO_CONVERSION. Si deseas obtener el comportamiento anterior, es decir, que las funciones de E/S de BS2000 determinen la conversión dependiendo del sistema de archivos, PerlIO sigue siendo tu amigo. Utilizas IO_CONVERSION como de costumbre y le dices a Perl que utilice la capa de E/S nativa:

export IO_CONVERSION=YES
export PERLIO=stdio

Ahora tu E/S sería ASCII en particiones ASCII y EBCDIC en particiones EBCDIC. Consulte la documentación de PerlIO (sin "Encode::"!) para ver más posibilidades.
