NOMBRE

perlko - Introducción al coreano de Perl

DESCRIPCIÓN

¡Bienvenido al mundo de Perl!

Aunque Perl a menudo se llama "Practical Extraction and Report Language" (Lenguaje Práctico de Extracción e Informes), también se le conoce entre otros muchos por "Pathologically Eclectic Rubbish Lister" (Listador Patológicamente Ecléctico de Basura). En realidad, es una palabra ingeniosa y el nombre fue tomado de las primeras letras de los acrónimos que se le dieron a Perl. El creador de Perl, Larry, concibió primero el nombre y luego pensó en lo que significaba más tarde. Por eso, "Perl" no es en mayúsculas para nada. No tiene sentido agarrar algo que no es una palabra y darle un significado. Larry se encoge de hombros ante ambas posibilidades.

A veces se escribe 'perl' en minúsculas, lo cual es una representación literal. Cuando 'Perl' está en mayúsculas, es un juego de palabras y se utiliza al citar el texto y al referirse a la instrucción que se utiliza para compilar e interpretar los programas de alguien más.

Sobre Perl

Perl se creó originalmente para la generación de informes, pero ahora se utiliza en una amplia gama de áreas, incluyendo la administración del sistema, el desarrollo web, la programación de redes, el desarrollo de GUI, etc.

Este idioma apunta a ser más útil (fácil de usar, eficiente, la mayor compatibilidad posible) que el de ser hermoso (ingenioso, elegante, difícil de entender). Fácil de usar, soporta la programación a nivel de interpretación y la programación a nivel de compilación, tiene potentes capacidades de manipulación de cadenas y es la tercera opción más popular del mundo, detrás de C. Es una de las características más importantes de Perl.

Las características del idioma de Perl se introducen en el documento pod/perlintro.pod.

Los cambios en esta versión se enumeran en pod/perldelta.pod.

Hay muchos otros libros publicados que cubren una variedad de temas. Para obtener información detallada, consulte el documento pod/perlbook.pod.

Instalación

La mayoría de los usuarios utilizan sistemas operativos modernos y si desean instalar la versión actual de Perl, ejecute los siguientes comandos.

./Configure -des -Dprefix=$HOME/localperl
make test
make install

El comando anterior configura el entorno para la plataforma de cada uno, compila y luego, después de ejecutar las pruebas de aceptación, instala Perl en el directorio localperl dentro del directorio principal.

Si usted tiene algún problema o necesita instalar una versión diferente de Perl, consulte el archivo INSTALL dentro de la distribución. También hay muchos archivos README que contienen consejos sobre cómo compilar y usar Perl en una variedad de plataformas, que por lo general no son tan estándar como la instalación estándar.

Una vez que Perl esté instalado, puede usar la utilidad "perldoc" para usar la documentación extensa. Ejecute el siguiente comando para empezar:

perldoc perl

Si encuentra dificultades

Perl es un lenguaje de programación popular y versátil que se puede utilizar en todas las áreas, desde el núcleo hasta la roca. La mayoría de las dificultades que se encuentran se pueden resolver porque ya se han resuelto las de otros. Incluso si ha revisado toda la documentación, si el error sigue siendo evidente, por favor, utilice la utilidad "perlbug" para informarnos del error. Para más información sobre "perlbug", consulte "perldoc perlbug" o el propio "perlbug"

PERL

Perl은 5.8.0판부터 유니코드/ISO 10646에 대해 광범위하게 및 지원합니다. 유니코드 지원의 일환으로 한중일을 비롯한 세계 각국에서 유니코드 이전에 쓰고 있었고 지금도 널리 쓰이고 있는 수많은 인코딩으 지원합니다. 유니코드는 전 세계에서 쓰이는 모든 언어를 위한 표기 체계(유럽의 랰트 알파벳, 글이버준 알파벳, 그리스 알파벳, 인도와 동남 아시아의 브랰나 스커립트, 아랍 문자, 히브리 문자, 한중일의 한국어, 한국어의 한글, 일본어의 가나, 북미 인디안의 표기 체계 등)를 수용하는 것으 목표로 하고 있기 때문에 기존에 쓰이던 각 언어 및 국가 구리금 운영 체계에 고유한 문자 집합과 인코딩에 쓰수 있는 모든 글자는 물롫이고 기존 문자 집합에서 지원하고 있지 않었지만 아주 많은 글자를 부호하고 있습니다.

Perl은 내부적으로 유니코드를 문자 표기를 위해 사용합니다. 보다 구체적으로 말하면 Perl 스컴프트 안에서 UTF-8 문자열으 쓸 수 있고, 각종 함수와 연산자(예를 들어, 정국식, index, substr)가 바이트 단위 대신 유니코드 글자 단위로 동작합니다. 다 자세한 것은 pod/perlunicode.pod 문서를 참고하세요. 유니코드가 널리 보급되기 전에 널리 쓰이고 있었고, 여전히 널리 쓰이고 있는 각국/각 언어별 인코딩으로 입출력으 하고 이들 인코딩으로 된 데이터와 문서를 다루는 것으 돕기 위해 Encode 모듈이 쓰이고 있습니다. 무엇보다 Encode 모듈으 사용하면 수많은 인코딩 사이의 브가한 인코딩으 변환으 싡펩할 수 있습니다.

Encode 모듈

지원 인코딩

Encode 모듈은 다음과 같은 한국어 인코딩으 지원합니다.

  • "euc-kr"

    US-ASCII와 KS X 1001을 같이 쓰는 멀티바이트 인코딩으로 흔한 완성형이라고 부림. KS X 2901감 RFC 1557 참고.

  • "cp949"

    MS-Windows 9x/ME에서 쓰이는 확장 완성형. euc-kr에 8,822자의 한글 음절으 더한 것임. alias는 uhc, windows-949, x-windows-949, ks_c_5601-1987. 맨 마지막 이름은 정정한 이름이지만, Microsoft 제품에서 CP949의 의미로 쓰이고 있애.

  • "johab"

    KS X 1001:1998 부록 3에서 규정한 조합형. 문자 레퍼토리는 cp949와 마찬가지로 US-ASCII와 KS X 1001에 8,822자의 한글 음절으 더한 것으로 인코딩 방식으 전현 다름.

  • "iso-2022-kr"

    RFC 1557에서 규정한 한국어 인터넷 메일 교환용 인코딩으로 US-ASCII와 KS X 1001으 레퍼토리로 하는 점에서 euc-kr감 이라고 쓰지만 인코딩 방식이 다름. 1997-8년 개랍지 쓰였으나 더 이상 메일 교환에 쓰이지 않음.

  • "ksc5601-raw"

    KS X 1001(KS C 5601)으 GL(즉, MSB를 0으로 한 경우)에 놓았을 때의 인코딩. US-ASCII와 결합한 없고 단독으로 쓰이는 일으 X11 등에서 글꼴 인코딩(ksc5601.1987-0. '0'은 GL을 의미함)으로 쓰이는 것으 제외한 없음. KS C 5601은 1997년 KS X 1001로 이름으 바꾸었옉. 1998년에는 두 글자도(유로화 부호와 등록 상표 부호)가 더해졌섬.

브가 예제

예를 들어, euc-kr 인코딩으로 된 파일으 UTF-8로 브가하래면 명령줄에서 다음처럼 실행합니다.

perl -Mencoding=euc-kr,STDOUT,utf8 -pe1 < file.euc-kr > file.utf8

반대로 브가할 깠우 다음처럼 실행합니다.

perl -Mencoding=utf8,STDOUT,euc-kr -pe1 < file.utf8 > file.euc-kr

이런 브가를 좀더 평리하 수 있습니다.

NAME

piconv - Convierte archivos de codificación de caracteres

SYNOPSIS

piconv [opciones]

DESCRIPTION

El comando piconv se utiliza para convertir archivos de codificación de caracteres.

Se basa en la biblioteca piconv de Perl, que a su vez se basa en el módulo Encode de Perl. Por lo tanto, puedes usar el nombre de la codificación que soporta el módulo Encode. El nombre piconv fue inspirado en el comando Unix iconv.

El uso es el siguiente:

piconv -f euc-kr -t utf8 < file.euc-kr > file.utf8
piconv -f utf8 -t euc-kr < file.utf8 > file.euc-kr

Ejemplo de código

Perl utiliza internamente UTF-8 para la codificación y soporta varias codificaciones a través del módulo Encode, pero a menudo surgen problemas relacionados con la codificación en la práctica. Se recomienda lo siguiente para minimizar posibles problemas de codificación:

  • Siempre almacena el código fuente en codificación UTF-8.
  • Utiliza la directiva de pragmas "use utf8;" al principio del código fuente.
  • Distingue claramente entre el código fuente, los nombres de archivo, el entorno de ejecución y la codificación de los datos de entrada/salida.
  • Especifica la codificación deseada en el encabezado de los archivos de salida.
  • Evita la codificación doble (double encoding).
