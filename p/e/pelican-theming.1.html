NOMBRE

pelican-theming - Cómo crear temas para Pelican

Tenga en cuenta que, si bien hacemos todo lo posible por revisar y fusionar las contribuciones de temas, estas son enviadas por la comunidad de Pelican y, por lo tanto, pueden tener niveles variables de soporte e interoperabilidad.

CREACIÓN DE TEMAS

Para generar su sitio utilizando un tema que haya creado (o descargado manualmente y luego modificado), puede especificar ese tema mediante la opción -t:

pelican content -s pelicanconf.py -t /proyectos/tu-sitio/temas/tu-tema

Si prefiere no especificar el tema en cada invocación, puede definir THEME en su configuración para que apunte a la ubicación de su tema preferido.

Estructura

Para crear su propio tema, debe seguir la siguiente estructura:

├── static
│   ├── css
│   └── images
└── templates
    ├── archives.html         // para mostrar archivos
    ├── article.html          // procesado para cada artículo
    ├── author.html           // procesado para cada autor
    ├── authors.html          // debe listar todos los autores
    ├── categories.html       // debe listar todas las categorías
    ├── category.html         // procesado para cada categoría
    ├── index.html            // el índice (lista todos los artículos)
    ├── page.html             // procesado para cada página
    ├── period_archives.html  // para mostrar archivos de período de tiempo
    ├── tag.html              // procesado para cada etiqueta
    └── tags.html             // debe listar todas las etiquetas. Puede ser una nube de etiquetas.
  • static contiene todos los activos estáticos, que se copiarán en la carpeta de salida theme. La estructura de archivos anterior incluye carpetas CSS e imágenes, pero esos son solo ejemplos. Coloque lo que necesite aquí.
  • templates contiene todas las plantillas que se utilizarán para generar el contenido. Los archivos de plantilla enumerados anteriormente son obligatorios; puede agregar sus propias plantillas si le ayuda a mantener las cosas organizadas al crear su tema.

Plantillas y Variables

La idea es utilizar una sintaxis sencilla que pueda incrustar en sus páginas HTML. Este documento describe qué plantillas deben existir en un tema y qué variables se pasarán a cada plantilla en el momento de la generación.

Todas las plantillas recibirán las variables definidas en su archivo de configuración, siempre que estén en mayúsculas. Puede acceder a ellas directamente.

Variables Comunes

Todos estos ajustes estarán disponibles para todas las plantillas.

Variable Descripción
output_file El nombre del archivo que se está generando actualmente. Por ejemplo, cuando Pelican esté procesando la página de inicio, output_file será "index.html".
articles La lista de artículos, ordenados de forma descendente por fecha. Todos los elementos son objetos Article, por lo que puede acceder a sus atributos (por ejemplo, título, resumen, autor, etc.). A veces, este se oculta (por ejemplo, en la página de etiquetas). Encontrará información al respecto en la variable all_articles.
dates La misma lista de artículos, pero ordenada por fecha, ascendente.
hidden_articles La lista de artículos ocultos
drafts La lista de borradores de artículos
period_archives Un diccionario que contiene elementos relacionados con archivos de período de tiempo (si está habilitado). Consulte la sección Listar y enlazar a archivos de período para obtener más detalles.
authors Una lista de tuplas (autor, artículos), que contiene todos los autores y los artículos correspondientes (valores)
categories Una lista de tuplas (categoría, artículos), que contiene todas las categorías y los artículos correspondientes (valores)
tags Una lista de tuplas (etiqueta, artículos), que contiene todas las etiquetas y los artículos correspondientes (valores)

draft_pages La lista de borradores de páginas

Verificación de Plugins Cargados

Pelican proporciona una prueba Jinja plugin_enabled para verificar si un plugin determinado está habilitado. Esta prueba acepta un nombre de plugin como cadena y devolverá un valor booleano. Los plugins de espacio de nombres se pueden especificar por nombre completo (pelican.plugins.plugin_name) o por nombre corto (plugin_name). El siguiente ejemplo utiliza el plugin webassets para minificar CSS si el plugin está habilitado y, de lo contrario, recurre a CSS normal:

{% if "webassets" is plugin_enabled %}
    {% assets filters="cssmin", output="css/style.min.css", "css/style.scss" %}
        <link rel="stylesheet" href="{{SITEURL}}/{{ASSET_URL}}">
    {% endassets %}
{% else %}
    <link rel="stylesheet" href="{{SITEURL}}/css/style.css}">
{% endif %}

article.html

Esta plantilla se procesará para cada artículo, con la salida generada según la configuración ARTICLE_SAVE_AS (Por defecto: {slug}.html). Las siguientes variables están disponibles al renderizar.

Variable Descripción
article El objeto del artículo a mostrar
category El nombre de la categoría del artículo actual

Cualquier metadato que pongas en la cabecera del archivo fuente del artículo estará disponible como campos en el objeto article. El nombre del campo será el mismo que el nombre del campo de metadatos, excepto en caracteres completamente en minúsculas.

Por ejemplo, podrías añadir un campo llamado FacebookImage a los metadatos de tu artículo, como se muestra a continuación:

Title: Amo Python más que la música
Date: 2013-11-06 10:06
Tags: personal, python
Category: Tech
Slug: python-je-l-aime-a-mourir
Author: Francis Cabrel
FacebookImage: http://franciscabrel.com/images/pythonlove.png

Estos nuevos metadatos estarán disponibles como article.facebookimage en tu plantilla article.html. Esto te permitiría, por ejemplo, especificar una imagen para las etiquetas open graph de Facebook que cambie para cada artículo:

<meta property="og:image" content="{{ article.facebookimage }}"/>

page.html

Esta plantilla se procesará para cada página, con la salida generada según la configuración PAGE_SAVE_AS (Por defecto: pages/{slug}.html). Las siguientes variables están disponibles al renderizar.

Variable Descripción
page El objeto de la página a mostrar. Puedes acceder a su título, slug y contenido.

tag.html

Esta plantilla se procesará para cada etiqueta, con la salida generada según la configuración TAG_SAVE_AS (Por defecto: tag/{slug}.html). Si la paginación está activa, las páginas subsiguientes residirán por defecto en tag/{slug}{número}.html.

period_archives.html

Este template se procesará para cada año de tus publicaciones si se define una ruta para YEAR_ARCHIVE_SAVE_AS, cada mes si se define MONTH_ARCHIVE_SAVE_AS, y cada día si se define DAY_ARCHIVE_SAVE_AS.

Variable Descripción
period Una tupla del tipo (año, mes, día) que indica el período de tiempo actual. año y día son números mientras que mes es una cadena. Esta tupla solo contiene año si el período de tiempo es un año determinado. Contiene tanto año como mes si el período de tiempo abarca años y meses, y así sucesivamente.
period_num Una tupla del tipo (year, month, day), como en period, excepto que todos los valores son números.

Puedes ver un ejemplo de cómo usar period en la plantilla period_archives.html del tema "simple".

Listado y Enlace a Archivos por Período

La variable period_archives se puede usar para generar una lista de enlaces al conjunto de archivos por período que Pelican genera. Como variable común, está disponible para su uso en cualquier plantilla, por lo que puedes implementar dicho índice en una plantilla directa personalizada, o en una barra lateral visible en diferentes páginas del sitio.

period_archives es un diccionario que puede contener claves year, month y/o day, dependiendo de qué configuraciones de *_ARCHIVE_SAVE_AS estén habilitadas. El valor correspondiente es una lista de diccionarios, donde cada diccionario representa un período de tiempo (ordenado según la configuración NEWEST_FIRST_ARCHIVES) con las siguientes claves y valores:

Clave Valor
period La misma tupla que se describe en period_archives.html, p. ej. (2023, 'June', 18).
period_num La misma tupla que se describe en period_archives.html, p. ej. (2023, 6, 18).
url La URL de la página de archivo por período, p. ej. posts/2023/06/18/. Esto está controlado por la configuración correspondiente de *_ARCHIVE_URL.
save_as La ruta de guardado del archivo de la página de archivo por período, p. ej. posts/2023/06/18/index.html. Esto es utilizado internamente por Pelican y generalmente no es relevante para los temas.
articles Una lista de objetos Article que pertenecen al período de tiempo.
dates La misma lista que articles, pero ordenada según la configuración NEWEST_FIRST_ARCHIVES.

Aquí hay un ejemplo de cómo se puede usar period_archives en una plantilla:

<ul>
{% for archive in period_archives.month %}
    <li>
        <a href="{{ SITEURL }}/{{ archive.url }}">
            {{ archive.period | reverse | join(' ') }} ({{ archive.articles|count }})
        </a>
    </li>
{% endfor %}
</ul>

Puedes cambiar period_archives.month en la declaración for a period_archives.year o period_archives.day según corresponda, dependiendo de la granularidad de período de tiempo deseada.

Herencia

Desde la versión 3.0, Pelican soporta la herencia del tema simple, por lo que puedes reutilizar las plantillas del tema simple en tus propios temas.

Si falta alguno de los archivos obligatorios en el directorio templates/ de tu tema, será reemplazado por la plantilla coincidente del tema simple. Así, si la estructura HTML de una plantilla en el tema simple te sirve, no tienes que escribir una nueva plantilla desde cero.

También puedes extender plantillas del tema simple en tus propios temas usando la directiva {% extends %} como en el siguiente ejemplo:

{% extends "!simple/index.html" %}   <!-- extiende la plantilla ``index.html`` del tema ``simple`` -->
{% extends "index.html" %}   <!-- extensión "regular" -->

Ejemplo

Con este sistema, es posible crear un tema con solo dos archivos.

base.html

El primer archivo es la plantilla templates/base.html:

{% extends "!simple/base.html" %}
{% block head %}
{{ super() }}
   <link rel="stylesheet" type="text/css" href="{{ SITEURL }}/theme/css/style.css" />
{% endblock %}
1.
En la primera línea, extendemos la plantilla base.html del tema simple, para no tener que reescribir el archivo completo.
2.
En la tercera línea, abrimos el bloque head que ya ha sido definido en el tema simple.
3.
En la cuarta línea, la función super() mantiene el contenido previamente insertado en el bloque head.
4.
En la quinta línea, añadimos una hoja de estilos a la página.
5.
En la última línea, cerramos el bloque head.

Este archivo será extendido por todas las demás plantillas, por lo que la hoja de estilos se enlazará desde todas las páginas.

style.css

El segundo archivo es la hoja de estilos CSS static/css/style.css:
