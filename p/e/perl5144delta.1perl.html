NOMBRE

perl5144delta - qué hay de nuevo para la versión perl v5.14.4

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.14.3 y la versión 5.14.4.

Si está actualizando desde una versión anterior como la 5.12.0, primero lea perl5140delta, que describe las diferencias entre 5.12.0 y 5.14.0.

Mejoras Centrales

No hay cambios desde la versión 5.14.0.

Seguridad

Esta versión contiene una corrección de seguridad importante y de gravedad media, y varias correcciones menores. Estas últimas se incluyen principalmente para permitir que la suite de pruebas pase limpiamente con la instalación de sanitización de direcciones del compilador clang.

CVE-2013-1667: Agotamiento de memoria con claves de hash arbitrarias

Con un conjunto cuidadosamente diseñado de claves de hash (por ejemplo, argumentos en una URL), es posible hacer que un hash consuma una gran cantidad de memoria y CPU, y por lo tanto, posiblemente lograr una Denegación de Servicio.

Este problema ha sido corregido.

Fuga de memoria en Encode

La implementación de codificación UTF-8 en Encode.xs tenía una fuga de memoria que ha sido corregida.

[perl #111594] Desbordamiento de búfer en la pila de Socket::unpack_sockaddr_un

Podría ocurrir un desbordamiento de búfer de lectura al copiar búferes de "sockaddr". Bastante inofensivo.

Este problema ha sido corregido.

[perl #111586] SDBM_File: Corrección de acceso con un byte de diferencia a la variable global ".dir"

Se estaba copiando un byte adicional para algunas cadenas literales. Bastante inofensivo.

Este problema ha sido corregido.

Error de dos bytes de diferencia en List::Util

Se estaba utilizando una cadena literal que incluía dos bytes más allá del final de la cadena. Bastante inofensivo.

Este problema ha sido corregido.

[perl #115994] Corrección de segfault en regcomp.c:S_join_exact()

En compilaciones de depuración, mientras se marcaban los nodos de expresiones regulares optimizados como tipo "OPTIMIZED", podría tratar bloques de texto exacto como si fueran nodos, provocando un segfault (SEGV). Bastante inofensivo.

Este problema ha sido corregido.

[perl #115992] Uso después de liberar en PL_eval_start

La declaración "local $[;", cuando estaba precedida por un "eval", y cuando no era parte de una asignación, podría causar un bloqueo.

Este problema ha sido corregido.

Desbordamiento con IO en cadenas largas

Leer o escribir cadenas de más de 2**31 bytes de tamaño podría causar un segfault debido a desbordamiento de enteros.

Este problema ha sido corregido.

Notas Específicas de Plataforma

VMS
5.14.3 no pudo compilarse en VMS debido a la aplicación incompleta de una serie de parches que permitía usar "userelocatableinc" y "usesitecustomize" simultáneamente. Otras plataformas no se vieron afectadas y el problema ha sido corregido.

Corrección de Errores Seleccionados

•
En Perl 5.14.0, "$tainted ~~ @array" dejó de funcionar correctamente. A veces fallaba erróneamente (cuando $tainted contenía una cadena que aparece en el array *después* del primer elemento) o tenía éxito erróneamente (cuando "undef" aparecía después del primer elemento) [perl #93590].

Reporting Bugs

If you find what you think is a bug, you might check the articles recently posted to the comp.lang.perl.misc newsgroup and the perl bug database at http://rt.perl.org/perlbug/ . There may also be information at http://www.perl.org/ , the Perl Home Page.

If you believe you have an unreported bug, please run the perlbug program included with your release. Be sure to trim your bug down to a tiny but sufficient test case. Your bug report, along with the output of "perl -V", will be sent off to perlbug@perl.org to be analysed by the Perl porting team.

If the bug you are reporting has security implications, which make it inappropriate to send to a publicly archived mailing list, then please send it to perl5-security-report@perl.org. This points to a closed subscription unarchived mailing list, which includes all the core committers, who be able to help assess the impact of issues, figure out a resolution, and help co-ordinate the release of patches to mitigate or fix the problem across all platforms on which Perl is supported. Please only use this address for security issues in the Perl core, not for modules independently distributed on CPAN.
