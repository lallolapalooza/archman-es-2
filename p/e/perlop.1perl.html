NOMBRE

perlop - Expresiones de Perl: operadores, precedencia, literales de cadena

DESCRIPCIÓN

En Perl, el operador determina qué operación se realiza, independientemente del tipo de los operandos. Por ejemplo, "$x + $y" siempre es una suma numérica, y si $x o $y no contienen números, se intenta convertirlos a números primero.

Esto contrasta con muchos otros lenguajes dinámicos, donde la operación se determina por el tipo del primer argumento. También significa que Perl tiene dos versiones de algunos operadores, una para comparación numérica y otra para comparación de cadenas. Por ejemplo, "$x == $y" compara dos números para igualdad, y "$x eq $y" compara dos cadenas.

Sin embargo, hay algunas excepciones: el operador "x" puede ser repetición de cadenas o repetición de listas, dependiendo del tipo del operando izquierdo, y "&quot;, "|", "^" y "~" pueden ser operaciones bit a bit de cadenas o numéricas.

Precedencia y Asociatividad del Operador

La precedencia y la asociatividad de los operadores funcionan en Perl más o menos como lo hacen en matemáticas.

Precedencia de operadores significa que algunos operadores se agrupan más fuertemente que otros. Por ejemplo, en "2 + 4 * 5", la multiplicación tiene mayor precedencia, por lo que "4 * 5" se agrupa como el operando derecho de la suma, en lugar de "2 + 4" agruparse como el operando izquierdo de la multiplicación. Es como si la expresión se hubiera escrito "2 + (4 * 5)", no "(2 + 4) * 5". Por lo tanto, la expresión produce "2 + 20 == 22", en lugar de "6 * 5 == 30".

Asociatividad de operadores define qué sucede si se usa una secuencia de los mismos operadores uno tras otro: generalmente se agruparán a la izquierda o a la derecha. Por ejemplo, en "9 - 3 - 2", la resta es asociativa a la izquierda, por lo que "9 - 3" se agrupa como el operando izquierdo de la segunda resta, en lugar de "3 - 2" agruparse como el operando derecho de la primera resta. Es como si la expresión se hubiera escrito "(9 - 3) - 2", no "9 - (3 - 2)". Por lo tanto, la expresión produce "6 - 2 == 4", en lugar de "9 - 1 == 8".

Para operadores simples que evalúan todos sus operandos y luego combinan los valores de alguna manera, la precedencia y la asociatividad (y los paréntesis) implican algunos requisitos de orden en esas operaciones de combinación. Por ejemplo, en 2 + 4 * 5, la agrupación implícita por la precedencia significa que la multiplicación de 4 y 5 debe realizarse antes que la suma de 2 y 20, simplemente porque el resultado de esa multiplicación se requiere como uno de los operandos de la suma. Pero el orden de las operaciones no se determina completamente por esto: en "2 * 2 + 4 * 5", ambas multiplicaciones deben realizarse antes de la suma, pero la agrupación no dice nada sobre el orden en que se realizan las dos multiplicaciones. De hecho, Perl tiene una regla general de que los operandos de un operador se evalúan en orden de izquierda a derecha. Pocos operadores, como "&&=", tienen reglas de evaluación especiales que pueden resultar en que un operando no se evalúe en absoluto; en general, el operador de nivel superior en una expresión tiene control sobre la evaluación de los operandos.

Algunos operadores de comparación, junto con su asociatividad, se *encadenan* con algunos operadores de la misma precedencia (pero nunca con operadores de diferente precedencia). Este encadenamiento significa que cada comparación se realiza con los dos argumentos que la rodean, y cada argumento interior participa en dos comparaciones, y los resultados de la comparación se combinan implícitamente con AND. Por lo tanto, "$x < $y <= $z" se comporta exactamente como "$x < $y && $y <= $z", suponiendo que "$y" es tan simple un escalar como parece. El ANDing se evalúa de forma perezosa (short-circuits), al igual que "&&", deteniendo la secuencia de comparaciones tan pronto como una produce falso.

En una comparación encadenada, cada expresión de argumento se evalúa como máximo una vez, incluso si participa en dos comparaciones, pero el resultado de la evaluación se obtiene para cada comparación. (No se evalúa en absoluto si la evaluación perezosa significa que no es necesaria para ninguna comparación). Esto importa si el cálculo de un argumento interior es costoso o no determinista. Por ejemplo:

if ($x < expensive_sub() <= $z) { ...

no es completamente como

if ($x < expensive_sub() && expensive_sub() <= $z) { ...

sino más bien parecido a

my $tmp = expensive_sub();
if ($x < $tmp && $tmp <= $z) { ...

en el sentido de que la subrutina solo se llama una vez. Sin embargo, tampoco es exactamente como este último código, porque la comparación encadenada no involucra ninguna variable temporal (nombrada o de otro tipo): no hay asignación. Esto no marca mucha diferencia cuando la expresión es una llamada a una subrutina ordinaria, pero importa más con una subrutina lvalue, o si la expresión del argumento produce algún tipo de escalar inusual por otros medios. Por ejemplo, si la expresión del argumento produce un escalar "tied" (vinculado), entonces la expresión se evalúa para producir ese escalar como máximo una vez, pero el valor de ese escalar puede obtenerse hasta dos veces, una por cada comparación en la que se utiliza realmente.

En este ejemplo, la expresión se evalúa solo una vez, y el escalar vinculado (el resultado de la expresión) se obtiene para cada comparación que lo usa.

if ($x < $tied_scalar < $z) { ...

En el siguiente ejemplo, la expresión se evalúa solo una vez, y el escalar vinculado se obtiene una vez como parte de la operación dentro de la expresión. El resultado de esa operación se obtiene para cada comparación, lo que normalmente no importa a menos que ese resultado de la expresión sea también mágico debido a la sobrecarga de operadores.

if ($x < $tied_scalar + 42 < $z) { ...

Algunos operadores son en cambio no asociativos, lo que significa que es un error de sintaxis usar una secuencia de esos operadores de la misma precedencia. Por ejemplo, "$x .. $y .. $z" es un error.

Términos y Operadores de Lista (Hacia la izquierda)

Un TÉRMINO tiene la mayor precedencia en Perl. Incluyen variables, operadores de cita y similares a citas, cualquier expresión entre paréntesis y cualquier función cuyos argumentos estén entre paréntesis. De hecho, realmente no hay funciones en este sentido, solo operadores de lista y opera unarios

Términos y Operadores de Lista (Hacia la Izquierda)

Los operadores de lista son tratados como términos si van seguidos de un paréntesis que inicia su lista de argumentos. Por ejemplo, "print @array" se comporta como si fuera "print(@array)", tratando "@array" como un argumento. En otras palabras, está usando la sintaxis de llamada a función. "print $scalar" se comporta como si fuera "print($scalar)", tratando "$scalar" como un argumento. En cualquier caso, "print" se considera un término simple.

En la ausencia de paréntesis, los operadores de lista tales como "print", "sort", o "chmod" son tratados como términos cuando se utilizan en el lado izquierdo de una expresión de asignación, pero se comportan como operadores de lista cuando se utilizan en el lado derecho.

Aquí hay un ejemplo de cómo esto puede ser confuso:

my @a = (1, 2, sort 3, 4); # @a contendrá (1, 2, 3, 4)
print @a;                  # imprime 1234

En el ejemplo anterior, "sort 3, 4" se evalúa como un término, y la coma que sigue a "sort" es tratada como un separador de argumentos de lista. Por lo tanto, "sort 3, 4" se evalúa como "sort(3, 4)", que devuelve "3, 4". Luego, esto se pasa a la lista de argumentos de "print", resultando en "print 1, 2, 3, 4".

Si no se usan paréntesis, los operadores de lista pueden ser difíciles de usar correctamente. Por ejemplo, en:

print @a, sort @b;

El intérprete de Perl primero evalúa "@a", luego evalúa "sort @b", y finalmente llama a "print" con los resultados de ambos.

Sin embargo, si usa paréntesis alrededor de los argumentos de un operador de lista, estos se tratarán como una llamada a función normal, con la máxima precedencia:

print (@a, sort @b);

Esto evalúa "sort @b" y luego pasa el resultado junto con "@a" a "print".

Debido a la precedencia inusual de los operadores de lista, se recomienda usar paréntesis alrededor de sus argumentos siempre que sea posible. Esto hace que el código sea más legible y menos propenso a errores.

Los operadores de lista también pueden ser tratados como términos si van seguidos de una llamada a subrutina o método, o de un constructor anónimo. Por ejemplo:

print substr($string, 0, 10);

En este caso, "print" se trata como un término, y "substr($string, 0, 10)" se evalúa primero y luego se pasa a "print".

Los siguientes construidos también se analizan como términos: "do {}", "eval {}", llamadas a subrutinas y métodos, y los constructores anónimos "[]" y "{}".

Tenga en cuenta que los operadores de lista (como print(), etc.) o cualquier operador unario (como chdir(), etc.) seguidos de un paréntesis izquierdo como siguiente token, el operador y los argumentos dentro de los paréntesis se toman con la máxima precedencia, al igual que una llamada a función normal. Todos estos están documentados en perlfunc.

En ausencia de paréntesis, la precedencia de los operadores de lista como "print", "sort" o "chmod" es muy alta o muy baja dependiendo de si se está mirando el lado izquierdo o el lado derecho del operador. Por ejemplo, en

@ary = (1, 3, sort 4, 2);
print @ary;         # imprime 1324

las comas a la derecha de "sort" se evalúan antes que el "sort", pero las comas a la izquierda se evalúan después. En otras palabras, los operadores de lista tienden a "comerse" todos los argumentos que les siguen, y luego actúan como un simple TÉRMINO con respecto a la expresión precedente. Tenga cuidado con los paréntesis:

# Estos evalúan exit antes de hacer el print:
print($foo, exit);  # Obviamente no es lo que quieres.
print $foo, exit;   # Tampoco esto.
# Estos hacen el print antes de evaluar exit:
(print $foo), exit; # Esto es lo que quieres.
print($foo), exit;  # O esto.
print ($foo), exit; # O incluso esto.

También tenga en cuenta que

print ($foo & 255) + 1, "\n";

probablemente no haga lo que espera a primera vista. Los paréntesis envuelven la lista de argumentos para "print" que se evalúa (imprimiendo el resultado de "$foo & 255"). Luego se suma uno al valor de retorno de "print" (generalmente 1). El resultado es algo como esto:

1 + 1, "\n";    # Obviamente no es lo que querías decir.

Para hacer lo que querías correctamente, debes escribir:

print(($foo & 255) + 1, "\n");

Ver "Operadores Unarios Nombrados" para más discusión sobre esto.

También se analizan como términos las construcciones "do {}" y "eval {}", así como las llamadas a subrutinas y métodos, y los constructores anónimos "[]" y "{}".

Ver también "Operadores de Comillas y Similares a Comillas" más abajo, así como "Operadores de E/S".

El Operador Flecha

""->"" es un operador de desreferencia infijo, tal como lo es en C y C++. Si el lado derecho es uno de los índices de "[...]", "{...}", o "(...)", entonces el lado izquierdo debe ser una referencia dura o simbólica a un array, un hash o una subrutina respectivamente. (O técnicamente hablando, una ubicación capaz de contener una referencia dura, si es una referencia a un array o hash que se utiliza para asignación.) Ver perlreftut y perlref.

De lo contrario, el lado derecho es un nombre de método o una variable escalar simple que contiene el nombre del método o una referencia a una subrutina, y (si es un nombre de método) el lado izquierdo debe ser un objeto (una referencia bendecida) o un nombre de clase (es decir, un nombre de paquete). Ver perlobj.

El lado derecho también puede ser el nombre de una subrutina, prefijado con el sigilo "&". Esto crea lo que parece una invocación de método léxico, donde la subrutina del método se resuelve léxicamente en lugar de por nombre mediante una búsqueda dentro de los paquetes de la clase del objeto. Esta resolución ocurre completamente en tiempo de compilación, y funciona igual que una llamada a subrutina regular en tiempo de ejecución.

Los casos de desreferencia (en contraposición a los casos de llamada a método) se extienden algo más con la característica "postderef". Para los detalles de esa característica, consulte "Sintaxis de Desreferencia Postfija" en perlref.

Auto-incremento y Auto-decremento

"++" y "--" funcionan como en C. Es decir, si se colocan antes de una variable, incrementan o decrementan la variable en uno antes de devolver el valor, y si se colocan después, incrementan o decrementan después de devolver el valor.

$i = 0;  $j = 0;
print $i++;  # imprime 0
print ++$j;  # imprime 1

Tenga en cuenta que, al igual que en C, Perl no define *cuándo* se incrementa o decrementa la variable. Simplemente sabe que se hará en algún momento antes o después de que se devuelva el valor. Esto también significa que modificar una variable dos veces en la misma sentencia dará lugar a un comportamiento indefinido. Evite sentencias como:

$i = $i ++;
print ++ $i + $i ++;

Perl no garantizará el resultado de las sentencias anteriores.

El operador de auto-incremento tiene un poco de magia adicional incorporada. Si incrementa una variable que es numérica, o que alguna vez se ha utilizado en un contexto numérico, obtiene un incremento normal. Sin embargo, si la variable solo se ha utilizado en contextos de cadena desde que se estableció, y tiene un valor que no es la cadena vacía y coincide con el patrón "/^[a-zA-Z]*[0-9]*\z/", el incremento se realiza como una cadena, conservando cada carácter dentro de su rango, con acarreo:

print ++($foo = "99");      # imprime "100"
print ++($foo = "a0");      # imprime "a1"
print ++($foo = "Az");      # imprime "Ba"
print ++($foo = "zz");      # imprime "aaa"

"undef" siempre se trata como numérico, y en particular se cambia a 0 antes de incrementar (de modo que un post-incremento de un valor undef devolverá 0 en lugar de "undef").

El operador de auto-decremento no es mágico.

Exponenciación

El operador binario "**" es el operador de exponenciación. Se une aún más fuertemente que el menos unario, por lo que "-2**4" es "-(2**4)", no "(-2)**4". (Esto se implementa utilizando la función pow(3) de C, que en realidad funciona con dobles internamente.)

Tenga en cuenta que ciertas expresiones de exponenciación no están definidas: estas incluyen "0**0", "1**Inf", e "Inf**0". No espere resultados particulares de estos casos especiales, los resultados dependen de la plataforma.

Operadores Unarios Simbólicos

El unario "!" realiza la negación lógica, es decir, "no". Ver también "not" para una versión de menor precedencia de esto.

El unario "-" realiza la negación aritmética si el operando es numérico, incluyendo cualquier cadena que parezca un número. Si el operando es un identificador, se devuelve una cadena que consiste en un signo menos concatenado con el identificador. De lo contrario, si la cadena comienza con un signo más o menos, se devuelve una cadena que comienza con el signo opuesto. Un efecto de estas reglas es que "-bareword" es equivalente a la cadena "-bareword". Si, sin embargo, la cadena comienza con un carácter no alfabético (excluyendo "+" o "-"), Perl intentará convertir la cadena a un número y se realizará la negación aritmética. Si la cadena no se puede convertir limpiamente a un número, Perl dará la advertencia Argumento "la cadena" no es numérico en negación (-) en ....

El unario "~" realiza la negación bitwise, es decir, complemento de 1's. Por ejemplo, "0666 & ~027" es 0640. (Ver también "Aritmética Entera" y "Operadores de Cadena Bitwise".) Tenga en cuenta que el ancho del resultado depende de la plataforma: "~0" tiene 32 bits de ancho en una plataforma de 32 bits, pero 64 bits en una plataforma de 64 bits, por lo que si espera un determinado ancho de bits, recuerde usar el operador "&" para enmascarar los bits excedentes.

A partir de Perl 5.28, es un error fatal intentar complementar una cadena que contiene un carácter con un valor ordinal superior a 255.

Si la característica "bitwise" está habilitada a través de "use feature 'bitwise'" o "use v5.28", entonces el unario "~" siempre trata su argumento como un número, y una forma alternativa del operador, "~.", siempre trata su argumento como una cadena. Por lo tanto, "~0" y "~"0"" ambos darán 2**32-1 en plataformas de 32 bits, mientras que "~.0" y "~."0"" ambos producirán "\xff". Hasta Perl 5.28, esta característica producía una advertencia en la categoría "experimental::bitwise".

El unario "+" no tiene ningún efecto en absoluto, ni siquiera en cadenas. Es útil sintácticamente para separar un nombre de función de una expresión entre paréntesis que de otro modo se interpretaría como la lista completa de argumentos de la función. (Ver ejemplos anteriores en "Términos y Operadores de Lista (Hacia la Izquierda)".)

El unario "\" crea referencias. Si su operando es una sola cosa con sigilo, crea una referencia a ese objeto. Si su operando es una lista entre paréntesis, entonces crea referencias a las cosas mencionadas en la lista. De lo contrario, pone su operando en contexto de lista y crea una lista de referencias a los escalares en la lista proporcionada por el operando. Ver perlreftut y perlref. No confunda este comportamiento con el comportamiento de la barra invertida dentro de una cadena, aunque ambas formas transmiten la noción de proteger lo siguiente de la interpolación.

Operadores de Enlace

El binario "=~" enlaza una expresión escalar a una coincidencia de patrón. Ciertos oper

ciones de búsqueda o modificación de la cadena $_ por defecto. Este operador hace que ese tipo de operación funcione en alguna otra cadena. El argumento derecho es un patrón de búsqueda, sustitución o transliteración. El argumento izquierdo es lo que se supone que debe ser buscado, sustituido o transliterado en lugar de $_ por defecto. Cuando se utiliza en contexto escalar, el valor de retorno generalmente indica el éxito de la operación. Las excepciones son la sustitución ("s///") y la transliteración ("y///") con la opción "/r" (no destructiva), que hacen que el valor de **r**etorno sea el resultado de la sustitución. El comportamiento en contexto de lista depende del operador particular. Ver "Operadores tipo comilla de expresiones regulares" para más detalles y perlretut para ejemplos que usan estos operadores.

Si el argumento derecho es una expresión en lugar de un patrón de búsqueda, sustitución o transliteración, se interpreta como un patrón de búsqueda en tiempo de ejecución. Tenga en cuenta que esto significa que su contenido se interpolará dos veces, por lo tanto,

'\\' =~ q'\\';

no es correcto, ya que el motor regex terminará intentando compilar el patrón "\", lo que considerará un error de sintaxis.

El operador binario "!~" es igual que "=~" excepto que el valor de retorno se niega en sentido lógico.

El operador binario "!~" con una sustitución no destructiva ("s///r") o transliteración ("y///r") es un error de sintaxis.

Operadores Multiplicativos

El operador binario "*" multiplica dos números.

El operador binario "/" divide dos números.

El operador binario "%" es el operador módulo, que calcula el resto de la división de su primer argumento con respecto a su segundo argumento. Dados los operandos enteros $m y $n: Si $n es positivo, entonces "$m % $n" es $m menos el múltiplo más grande de $n menor o igual que $m. Si $n es negativo, entonces "$m % $n" es $m menos el múltiplo más pequeño de $n que no es menor que $m (es decir, el resultado será menor o igual a cero). Si los operandos $m y $n son valores de punto flotante y el valor absoluto de $n (es decir, abs($n)) es menor que "(UV_MAX + 1)", solo se usará la porción entera de $m y $n en la operación (Nota: aquí "UV_MAX" significa el máximo del tipo entero sin signo). Si el valor absoluto del operando derecho (abs($n)) es mayor o igual que "(UV_MAX + 1)", el operador "%" calcula el resto de punto flotante $r en la ecuación "($r = $m - $i*$n)" donde $i es un entero determinado que hace que $r tenga el mismo signo que el operando derecho $n (no el mismo signo que el operando izquierdo $m como la función C fmod()) y el valor absoluto menor que el de $n. Tenga en cuenta que cuando "use integer" está activo, "%" le da acceso directo al operador módulo tal como lo implementa su compilador C. Este operador no está tan bien definido para operandos negativos, pero se ejecutará más rápido.

El operador binario "x" es el operador de repetición. En contexto escalar, o si el operando izquierdo no está encerrado entre paréntesis ni es una lista "qw//", realiza una repetición de cadena. En ese caso, suministra contexto escalar al operando izquierdo y devuelve una cadena que consiste en el operando izquierdo repetido tantas veces como especifique el operando derecho. Si el operador "x" está en contexto de lista, y el operando izquierdo está encerrado entre paréntesis o es una lista "qw//", realiza una repetición de lista. En ese caso, suministra contexto de lista al operando izquierdo y devuelve una lista que consiste en la lista del operando izquierdo repetida tantas veces como especifique el operando derecho. Si el operando derecho es cero o negativo (emitiendo una advertencia en caso de ser negativo), devuelve una cadena vacía o una lista vacía, según el contexto.

print '-' x 80;             # imprime una fila de guiones
print "\t" x ($tab/8), ' ' x ($tab%8);      # tabula
@ones = (1) x 80;           # una lista de 80 unos
@ones = (5) x @ones;        # establece todos los elementos a 5

Operadores Aditivos

El operador binario "+" devuelve la suma de dos números.

El operador binario "-" devuelve la diferencia de dos números.

El operador binario "." concatena dos cadenas.

Operadores de Desplazamiento

El operador binario "<<" devuelve el valor de su argumento izquierdo desplazado a la izquierda el número de bits especificado por el argumento derecho. Los argumentos deben ser enteros. (Ver también "Aritmética de Enteros".)

El operador binario ">>" devuelve el valor de su argumento izquierdo desplazado a la derecha el número de bits especificado por el argumento derecho. Los argumentos deben ser enteros. (Ver también "Aritmética de Enteros".)

Si "use integer" (ver "Aritmética de Enteros") está activo, se utilizan enteros C con signo (desplazamiento aritmético), de lo contrario se utilizan enteros C sin signo (desplazamiento lógico), incluso para valores desplazados negativos. En el desplazamiento aritmético a la derecha, el bit de signo se replica a la izquierda, en el desplazamiento lógico entran bits cero desde la izquierda.

En cualquier caso, la implementación no generará resultados mayores que el tamaño del tipo entero con el que se compiló Perl (32 bits o 64 bits).

Desplazar por un número negativo de bits significa el desplazamiento inverso: el desplazamiento a la izquierda se convierte en desplazamiento a la derecha, el desplazamiento a la derecha se convierte en desplazamiento a la izquierda. Esto es diferente a C, donde el desplazamiento negativo no está definido.

Desplazar por un valor mayor o igual al tamaño del entero (en bits) resulta en cero (todos los bits se desbordan), excepto que bajo "use integer" el desplazamiento a la derecha de un valor negativo por tal cantidad resulta en -1. Esto es diferente a C, donde el desplazamiento por demasiados bits no está definido.

Si se cansa de estar sujeto a los enteros nativos de su plataforma, la pragmática "use bigint" evita elegantemente el problema por completo:

print 20 << 20;  # 20971520
print 20 << 32;  # 0 con entero de 32 bits,
                 # 85899345920 con entero de 64 bits
use bigint;
print 20 << 100; # 25353012004564588029934064107520

Operadores Unarios Nombrados

Los diversos operadores unarios nombrados se tratan como funciones con un argumento, con paréntesis opcionales.

Si cualquier operador de lista (print(), etc.) o cualquier operador unario (chdir(), etc.) va seguido de un paréntesis izquierdo como el siguiente token, el operador y los argumentos dentro de los paréntesis se consideran de la más alta precedencia, al igual que una llamada a función normal. Por ejemplo, debido a que los operadores unarios nombrados tienen mayor precedencia que "||":

chdir $foo    || die;       # (chdir $foo) || die
chdir($foo)   || die;       # (chdir $foo) || die
chdir ($foo)  || die;       # (chdir $foo) || die
chdir +($foo) || die;       # (chdir $foo) || die

pero, debido a que "*" tiene mayor precedencia que los operadores nombrados:

chdir $foo * 20;    # chdir ($foo * 20)
chdir($foo) * 20;   # (chdir $foo) * 20
chdir ($foo) * 20;  # (chdir $foo) * 20
chdir +($foo) * 20; # chdir ($foo * 20)
rand 10 * 20;       # rand (10 * 20)
rand(10) * 20;      # (rand 10) * 20
rand (10) * 20;     # (rand 10) * 20
rand +(10) * 20;    # rand (10 * 20)

Con respecto a la precedencia, los operadores de prueba de archivo, como "-f", "-M", etc., se tratan como operadores unarios nombrados, pero no siguen esta regla funcional de paréntesis. Esto significa, por ejemplo, que "-f($file).".bak"" es equivalente a "-f "$file.bak"".

Ver también "Términos y Operadores de Lista (Hacia la Izquierda)".

Operador Instancia de Clase

El operador binario "isa" evalúa a verdadero cuando el argumento izquierdo es una instancia de objeto de la clase (o una subclase derivada de esa clase) dada por el argumento derecho. Si el argumento izquierdo no está definido, no es una instancia de objeto bendecida y no deriva de la clase dada por el argumento derecho, el operador evalúa a falso. El argumento derecho puede dar la clase como una palabra desnuda o una expresión escalar que produce un nombre de clase en cadena:

if ( $obj isa Some::Class ) { ... }
if ( $obj isa "Different::Class" ) { ... }
if ( $obj isa $name_of_class ) { ... }

Esta característica está disponible a partir de Perl 5.31.6 cuando se habilita mediante "use feature 'isa'". Esta característica se habilita automáticamente mediante una declaración "use v5.36" (o superior) en el ámbito actual.

Operador Condicional

El operador ternario "?: es el operador condicional, igual que en C. Funciona de manera muy similar a un if-then-else. Si el argumento antes del "?" es verdadero, se devuelve el argumento antes del ":", de lo contrario, se devuelve el argumento después del ":". Por ejemplo:

printf "I have %d dog%s.\n", $n,
        ($n == 1) ? "" : "s";

El contexto escalar o de lista se propaga hacia abajo al 2do o 3er argumento, el que sea seleccionado.

$x = $ok ? $y : $z;  # obtener un escalar
@x = $ok ? @y : @z;  # obtener un array
$x = $ok ? @y : @z;  # ¡ups, eso es solo un conteo!

El operador puede ser asignado si ambos, el 2do y 3er argumento, son lvalues legales (es decir, que se puede asignar a ellos):

($x_or_y ? $x : $y) = $z;

Debido a que este operador produce un resultado asignable, usar asignaciones sin paréntesis te causará problemas. Por ejemplo, esto:

$x % 2 ? $x += 10 : $x += 2

Realmente significa esto:

(($x % 2) ? ($x += 10) : $x) += 2

En lugar de esto:

($x % 2) ? ($x += 10) : ($x += 2)

Probablemente debería escribirse de forma más simple como:

$x += ($x % 2) ? 10 : 2;

Operador Coma

La "," binaria es el operador coma. En contexto escalar evalúa su argumento izquierdo, descarta ese valor, luego evalúa su argumento derecho y devuelve ese valor. Esto es igual que el operador coma de C.

En contexto de lista, es simplemente el separador de argumentos de lista, e inserta ambos argumentos en la lista. Estos argumentos también se evalúan de izquierda a derecha.

El operador "=>" (a veces pronunciado "coma gorda") es un sinónimo de la coma, excepto que hace que una palabra a su izquierda sea interpretada como una cadena si comienza con una letra o guion bajo y está compuesta solo de letras, dígitos y guiones bajos. Esto incluye operandos que de otro modo podrían interpretarse como operadores, constantes, v-strings de un solo número o llamadas a funciones. Si dudas sobre este comportamiento, el operando izquierdo puede ser citado explícitamente.

De lo contrario, el operador "=>" se comporta exactamente como el operador coma o separador de argumentos de lista, según el contexto.

Por ejemplo:

use constant FOO => "something";
my %h = ( FOO => 23 );

es equivalente a:

my %h = ("FOO", 23);

*No* es:

my %h = ("something", 23);

El operador "=>" es útil para documentar la correspondencia entre claves y valores en hashes, y otros elementos emparejados en listas.

%hash = ( $key => $value );
login( $username => $password );

El comportamiento especial de citación ignora la precedencia, y por lo tanto puede aplicarse a *parte* del operando izquierdo:

print time.shift => "bbb";

Ese ejemplo imprime algo como "1314363215shiftbbb", porque el "=>" cita implícitamente el "shift" inmediatamente a su izquierda, ignorando el hecho de que "time.shift" es todo el operando izquierdo.

Operadores de Lista (hacia la Derecha)

En el lado derecho de un operador de lista, la coma tiene una precedencia muy baja, de tal manera que controla todas las expresiones separadas por comas que se encuentran allí. Los únicos operadores con menor precedencia son los operadores lógicos "and", "or", y "not", que pueden usarse para evaluar llamadas a operadores de lista sin necesidad de paréntesis:

open HANDLE, "< :encoding(UTF-8)", "filename"
    or die "Can't open: $!\n";

Sin embargo, algunas personas encuentran ese código más difícil de leer que escribirlo con paréntesis:

open(HANDLE, "< :encoding(UTF-8)", "filename")
    or die "Can't open: $!\n";

en cuyo caso, podrías usar el operador más común "||":

open(HANDLE, "< :encoding(UTF-8)", "filename")
    || die "Can't open: $!\n";

Ver también la discusión de operadores de lista en "Términos y Operadores de Lista (hacia la Izquierda)".

Negación Lógica

El operador unario "not" devuelve la negación lógica de la expresión a su derecha. Es el equivalente a "!" excepto por la precedencia muy baja.

Conjunción Lógica

El operador binario "and" devuelve la conjunción lógica de las dos expresiones circundantes. Es equivalente a "&&" excepto por la precedencia muy baja. Esto significa que tiene cortocircuito: la expresión derecha solo se evalúa si la expresión izquierda es verdadera.

Lógica o y O Exclusiva

No existe un operador de baja precedencia para OR definido.

El operador binario "or" devuelve la disyunción inclusiva lógica de las dos expresiones circundantes. Es equivalente a "||" excepto por tener una precedencia muy baja. Esto lo hace útil para el control de flujo:

"qr/STRING/msixpodualn"
Este operador cita (y posiblemente compila) su STRING como una expresión regular. STRING se interpola de la misma manera que PATTERN en "m/PATTERN/". Si se usa "'" como delimitador, no se realiza interpolación de variables. Devuelve un valor de Perl que puede usarse en lugar de la expresión correspondiente "/STRING/msixpodualn\". El valor devuelto es una versión normalizada del patrón original. Difere mágicamente de una cadena que contiene los mismos caracteres: ref(qr/x/) devuelve "Regexp"; sin embargo, desreferenciarlo no está bien definido (actualmente obtienes la versión normalizada del patrón original, pero esto puede cambiar).

Por ejemplo,

$rex = qr/my.STRING/is;
print $rex;                 # imprime (?si-xm:my.STRING)

es equivalente a

s/my.STRING/foo/is;

El resultado puede usarse como subpatrón en una coincidencia:

$re = qr/$pattern/;
$string =~ /foo${re}bar/;   # se puede interpolar en otros
                            # patrones
$string =~ $re;             # o usar de forma independiente
$string =~ /$re/;           # o de esta manera

Dado que Perl puede compilar el patrón en el momento de la ejecución del operador qr(), usar qr() puede tener ventajas de velocidad en algunas situaciones, notablemente si el resultado de qr() se usa de forma independiente:

sub match {
    my $patterns = shift;
    my @compiled = map qr/$_/i, @$patterns;
    grep {
        my $success = 0;
        foreach my $pat (@compiled) {
            $success = 1, last if /$pat/;
        }
        $success;
    } @_;
}

La precompilación del patrón en una representación interna en el momento de qr() evita la necesidad de recompilar el patrón cada vez que se intenta una coincidencia "/$pat/". (Perl tiene muchas otras optimizaciones internas, pero ninguna se activaría en el ejemplo anterior si no usáramos el operador qr()).

Las opciones (especificadas por los siguientes modificadores) son:

m   Tratar la cadena como líneas múltiples.
s   Tratar la cadena como una sola línea. (Hacer que . coincida con un salto de línea)
i   Realizar coincidencias de patrón sin distinción entre mayúsculas y minúsculas.
x   Usar expresiones regulares extendidas; especificar dos
    x significa que \t y el carácter ESPACIO se ignoran dentro
    de las clases de caracteres entre corchetes
p   Al hacer coincidir, conservar una copia de la cadena coincidente para que
    ${^PREMATCH}, ${^MATCH}, ${^POSTMATCH} estén definidos (ignorado a partir de la v5.20, ya que siempre están
    definidos a partir de esa versión)
o   Compilar el patrón solo una vez.
a   Restringir ASCII: Usar ASCII para las clases de caracteres \d, \s, \w y [[:posix:]];
    especificar dos 'a' añade la restricción adicional de que ningún carácter ASCII coincidirá con uno
    no ASCII bajo /i.
l   Usar las reglas del locale de ejecución actual.
u   Usar reglas Unicode.
d   Usar Unicode o el conjunto de caracteres nativo, como en las versiones 5.12 y anteriores.
n   Modo de no captura. No permitir que () rellene $1, $2, etc...

Si "/" es el delimitador, entonces la "m" inicial es opcional. Con la "m" puedes usar cualquier par de caracteres no blancos (ASCII) como delimitadores. Esto es particularmente útil para hacer coincidir nombres de ruta que contienen "/", para evitar el síndrome del palillo inclinado (LTS). Si "?" es el delimitador, entonces se aplica una regla de coincidencia única, descrita en "m?PATRÓN?" a continuación. Si "'" (comilla simple) es el delimitador, no se realiza ninguna interpolación de variables en el PATRÓN. Al usar un carácter delimitador válido en un identificador, se requiere espacio en blanco después de la "m".

PATRÓN puede contener variables, que se interpolarán cada vez que se evalúe la búsqueda del patrón, excepto cuando el delimitador sea una comilla simple. (Ten en cuenta que $(, $) y $| no se interpolan porque parecen pruebas de fin de cadena). Perl no recompilará el patrón a menos que cambie una variable interpolada que contenga. Puedes forzar a Perl a omitir la prueba y nunca recompilar añadiendo una "/o" (que significa "una vez") después del delimitador final. En el pasado, Perl recompilaba expresiones regulares innecesariamente, y este modificador era útil para indicarle que no lo hiciera, en aras de la velocidad. Pero ahora, las únicas razones para usar "/o" son una de las siguientes:

1.
Las variables tienen miles de caracteres de longitud y sabes que no cambian, y necesitas exprimir hasta la última pizca de velocidad haciendo que Perl omita la verificación de eso. (Hay una penalización de mantenimiento por hacer esto, ya que mencionar "/o" constituye una promesa de que no cambiarás las variables en el patrón. Si las cambias, ¡Perl ni siquiera se dará cuenta!)
2.
quieres que el patrón use los valores iniciales de las variables, independientemente de si cambian o no. (Pero hay formas más sensatas de lograr esto que usar "/o".)
3.
Si el patrón contiene código incrustado, como 
use re 'eval';
$code = 'foo(?{ $x })';
/$code/

entonces Perl recompilará cada vez, aunque la cadena del patrón no haya cambiado, para asegurar que el valor actual de $x se vea cada vez. Usa "/o" si quieres evitar esto.

La conclusión es que usar "/o" casi nunca es una buena idea.

El patrón vacío "//"
Si el PATRÓN se evalúa como una cadena vacía, se utiliza en su lugar la última expresión regular *coincidente exitosa* en el ámbito dinámico actual (consulta también "Reglas de ámbito de las variables de expresiones regulares" en perlvar). En este caso, solo se respetan las banderas "g" y "c" del patrón vacío; las otras banderas se toman del patrón original. Si ninguna coincidencia ha tenido éxito previamente, esto actuará (silenciosamente) como un patrón vacío genuino (que siempre coincidirá). Usar una cadena proporcionada por el usuario como patrón tiene el riesgo de que si la cadena está vacía, active el comportamiento de "última coincidencia exitosa", lo que puede ser muy confuso. En tales casos, se recomienda reemplazar "m/$patron/" con "m/(?:$patron)/" para evitar este comportamiento.

La última coincidencia exitosa se puede acceder como una variable a través de "${^LAST_SUCCESSFUL_PATTERN}". Hacer coincidir con ella, o con el patrón vacío, debería tener el mismo efecto, con la excepción de que cuando no hay una última coincidencia exitosa, el patrón vacío coincidirá silenciosamente, mientras que usar la variable "${^LAST_SUCCESSFUL_PATTERN}" producirá advertencias indefinidas (si las advertencias están habilitadas). Puedes comprobar defined(${^LAST_SUCCESSFUL_PATTERN}) para probar si hay una "última coincidencia exitosa" en el ámbito actual.

Ten en cuenta que es posible confundir a Perl y hacerle creer que "//" (la expresión regular vacía) es en realidad "//" (el operador definido-o). Perl suele ser bastante bueno en esto, pero algunos casos patológicos podrían activarlo, como "$x///" (¿es "($x) / (//)" o "$x // /"?) y "print $fh //" ("print $fh(//" o "print($fh //"?). En todos estos ejemplos, Perl asumirá que te refieres a definido-o. Si querías la expresión regular vacía, simplemente usa paréntesis o espacios para desambiguar, o incluso prefija la expresión regular vacía con una "m" (así "//" se convierte en "m//").

Coincidencia en contexto de lista
Si la opción "/g" no se utiliza, "m//" en contexto de lista devuelve una lista que consiste en las subexpresiones coincidentes por los paréntesis en el patrón, es decir, ($1, $2, $3...) (ten en cuenta que aquí también se establecen $1, etc.). Cuando no hay paréntesis en el patrón, el valor de retorno es la lista "(1)" para el éxito. Con o sin paréntesis, se devuelve una lista vacía en caso de fallo.

Ejemplos:

open(TTY, "+</dev/tty")
   || die "no se puede acceder a /dev/tty: $!";
<TTY> =~ /^y/i && foo();       # haz foo si se desea
if (/Version: *([0-9.]*)/) { $version = $1; }
next if m#^/usr/spool/uucp#;
# grep de hombre pobre
$arg = shift;
while (<>) {
   print if /$arg/;
}
if (($F1, $F2, $Etc) = ($foo =~ /^(\S+)\s+(\S+)\s*(.*)/))

Este último ejemplo divide $foo en las primeras dos palabras y el resto de la línea, y asigna esos tres campos a $F1, $F2 y $Etc. La condición es verdadera si se asignaron variables; es decir, si el patrón coincidió.

El modificador "/g" especifica la coincidencia de patrones global, es decir, la coincidencia tantas veces como sea posible dentro de la cadena. Cómo se comporta depende del contexto. En contexto de lista, devuelve una lista de las subcadenas coincidentes por cualquier paréntesis de captura en la expresión regular. Si no hay paréntesis, devuelve una lista de todas las cadenas coincidentes, como si hubiera paréntesis alrededor de todo el patrón.

En contexto escalar, cada ejecución de "m//g" encuentra la siguiente coincidencia, devolviendo verdadero si coincide y falso si no hay más coincidencias. La posición después de la última coincidencia se puede leer o establecer usando la función pos(); consulta "pos" en perlfunc. Modificar la cadena objetivo también restablece la posición de búsqueda.

Sin el modificador "/g", la aserción "\G" todavía se ancla en pos() tal como estaba al inicio de la operación (ver "pos" en perlfunc), pero por supuesto, la coincidencia solo se intenta una vez. Usar "\G" sin "/g" en una cadena objetivo a la que no se le haya aplicado previamente una coincidencia "/g" es lo mismo que usar la aserción "\A" para coincidir con el principio de la cadena. Ten en cuenta también que, actualmente, "\G" solo se admite correctamente cuando se ancla al principio del patrón.

THE REGULAR EXPRESSION OPERATORS

Regular expression matching and substitution are extremely powerful features of Perl. You will find yourself using them constantly.

THE MATCH OPERATOR

=~ and !~

EXPR =~ m/PATTERN/ATTRIBUTES
EXPR !~ m/PATTERN/ATTRIBUTES
These operators attempt to match the regex PATTERN against the value of EXPR. If EXPR is omitted, the default is $_. The match operator returns the number of characters matched if the match is successful, and false otherwise. The ATTRIBUTES are optional modifiers to the match. The PATTERN may be delimited by any character, not just /.

The !~ operator is the negation of the match operator. It returns true if the pattern does not match, and false if it does.

The special variables $1, $2, etc., are set to the substrings that match any capturing parentheses in the PATTERN. If the match fails, these variables are reset to undefined values.

When used in a boolean context, the match operator returns true if the match is successful, and false otherwise.

The following is a typical example:

if ($name =~ /^\s*(\w+)\s*$/) {
    print "The first word was: $1\n";
}

The match operator can be used with other delimiters:

if ($name =~ m@^\s*(\w+)\s*$@) { ... }
if ($name =~ %^\s*(\w+)\s*%) { ... }

Some common modifiers:

/i
Ignore case distinctions.
/m
Treat string as multiple lines. ^ and $ match the start and end of a line, respectively, and also the start and end of each line within the string.
/s
Treat string as one line. The . matches any character, including a newline.
/x
Ignore whitespace within the pattern.
/g
Global match. When matching against a scalar context, it successively finds all matches.

When /g is used in a list context, it returns a list of all substrings matched by the parentheses. When used in a scalar context, it returns the number of matches found.

my @lines = ($line =~ /^(\S+)\s+(\S+)/g);

If the match operator is used in a context that requires a value, and /g is specified, it returns the number of matches found. Otherwise, it returns the number of characters matched (for a successful match) or false (for a failed match).

Note that the digit form is used only on the left-hand side of the =~ operator.

if (/(\d)(\d\d\d)(?!\d)/) {
    print "Matched $1 and $2\n";
}

This is unlike the behaviour in sed, where we use the digit form only in the left hand side. Anywhere else it's $<digit>.

Occasionally, you can't use just a "/g" to get all the changes to occur that you might want. Here are two common cases:

# put commas in the right places in an integer
1 while s/(\d)(\d\d\d)(?!\d)/$1,$2/g;
# expand tabs to 8-column spacing
1 while s/\t+/' ' x (length($&)*8 - length($`)%8)/e;

While "s///" accepts the "/c" flag, it has no effect beyond producing a warning if warnings are enabled.

THE TRANSLITERATE OPERATOR

"tr/SEARCHLIST/REPLACEMENTLIST/cdsr"
"y/SEARCHLIST/REPLACEMENTLIST/cdsr"
These transliterate all occurrences of the characters found (or not found if the "/c" modifier is specified) in the search list with the positionally corresponding character in the replacement list, possibly deleting some, depending on the modifiers specified. Unless the "/r" flag is specified, they return the number of characters replaced or deleted. If no string is specified via the "=~" or "!~" operator, the $_ string is transliterated.

For sed devotees, "y" is provided as a synonym for "tr".

If the "/r" (non-destructive) option is present, a new copy of the string is made and its characters transliterated, and this copy is returned, instead of a count, no matter whether it was modified or not: the original string is always left unchanged. The new copy is always a plain string, even if the input string is an object or a tied variable.

Unless the "/r" option is used, the string specified with "=~" must be a scalar variable, an array element, a hash element, or an assignment to one of those; in other words, an lvalue.

The characters delimiting SEARCHLIST and REPLACEMENTLIST can be any printable character, not just forward slashes. If they are single quotes ("tr'SEARCHLIST'REPLACEMENTLIST'"), the only interpolation is removal of "\" from pairs of "\\"; so hyphens are interpreted literally rather than specifying a character range.

Otherwise, a character range may be specified with a hyphen, so "tr/A-J/0-9/" does the same replacement as "tr/ACEGIBDFHJ/0246813579/".

If the SEARCHLIST is delimited by bracketing quotes, the REPLACEMENTLIST must have its own pair of quotes, which may or may not be bracketing quotes; for example, "tr(aeiouy)(yuoiea)" or "tr[+\-*/]"ABCD""". This final example shows a way to visually clarify what is going on for people who are more familiar with regular expression patterns than with "tr", and who may think forward slash delimiters imply that "tr" is more like a regular expression pattern than it actually is. (Another option might be to use "tr[...] [...]".)

"tr" isn't fully like bracketed character classes, just (significantly) more like them than it is to full patterns. For example, characters appearing more than once in either list behave differently here than in patterns, and "tr" lists do not allow backslashed character classes such as "\d" or , nor variable interpolation, so "$" and "@" are always treated as literals.

The allowed elements are literals plus "\'" (meaning a single quote). If the delimiters aren't single quotes, also allowed are any of the escape sequences accepted in double-quoted strings. Escape sequence details are in the table near the beginning of this section.

A hyphen at the beginning or end, or preceded by a backslash is also always considered a literal. Precede a delimiter character with a backslash to allow it.

The "tr" operator is not equivalent to the "tr(1)" utility. "tr[a-z][A-Z]" will uppercase the 26 letters "a" through "z", but for case changing not confined to ASCII, use "lc", "uc", "lcfirst", "ucfirst" (all documented in perlfunc), or the substitution operator "s/PATTERN/REPLACEMENT/" (with "\U", "\u", "\L", and "\l" string-interpolation escapes in the REPLACEMENT portion).

Most ranges are unportable between character sets, but certain ones signal Perl to do special handling to make them portable. There are two classes of portable ranges. The first are any subsets of the ranges "A-Z", "a-z", and "0-9", when expressed as literal characters.

tr/h-k/H-K/

capitalizes the letters "h", "i", "j", and "k" and nothing else, no matter what the platform's character set is. In contrast, all of

tr/\x68-\x6B/\x48-\x4B/
tr/h-\x6B/H-\x4B/
tr/\x68-k/\x48-K/

do the same capitalizations as the previous example when run on ASCII platforms, but something completely different on EBCDIC ones.

The second class of portable ranges is invoked when one or both of the range's end points are expressed as "\N{...}"

$string =~ tr/\N{U+20}-\N{U+7E}//d;

removes from $string all the platform's characters which are equivalent to any of Unicode U+0020, U+0021, ... U+007D, U+007E. This is a portable range, and has the same effect on every platform it is run on. In this example, these are the ASCII printable characters. So after this is run, $string has only controls and characters which have no ASCII equivalents.

But, even for portable ranges, it is not generally obvious what is included without having to look things up in the manual. A sound principle is to use only ranges that both begin from, and end at, either ASCII alphabetics of equal case ("b-e", "B-E"), or digits ("1-4"). Anything else is unclear (and unportable unless "\N{...}" is used). If in doubt, spell out the character sets in full.

Options:

c   Complement the SEARCHLIST.
d   Delete found but unreplaced characters.
r   Return the modified string instead of a count, and leave the
    original string untouched.
s   Squash duplicate replaced characters.

If the "/d" modifier is specified, any characters specified by SEARCHLIST not found in REPLACEMENTLIST are deleted. (Note that this is slightly more flexible than the behavior of some tr programs, which delete anything they find in the SEARCHLIST, period.)

If the "/s" modifier is specified, sequences of characters, all in a row, that were transliterated to the same character are squashed down to a single instance of that character.

my $x = "aaabbbca";
$x =~ tr/ab/dd/s;     # $x now is "dcd"

If the "/d" modifier is used, the REPLACEMENTLIST is always interpreted exactly as specified. Otherwise, if the REPLACEMENTLIST is shorter than the SEARCHLIST, the final character, if any, is replicated until it is long enough. There won't be a final character if and only if the REPLACEMENTLIST is empty, in which case REPLACEMENTLIST is copied from SEARCHLIST. An empty REPLACEMENTLIST is useful for counting characters in a class, or for squashing character sequences in a class.

tr/abcd//            tr/abcd/abcd/
tr/abcd/AB/          tr/abcd/ABBB/
tr/abcd//d           s/[abcd]//g
tr/abcd/AB/d         (tr/ab/AB/ + s/[cd]//g)  - but run together

If the "/c" modifier is specified, the characters to be transliterated are the ones NOT in SEARCHLIST, that is, it is complemented. If "/d" and/or "/s" are also specified, they apply to the complemented SEARCHLIST. Recall, that if REPLACEMENTLIST is empty (except under "/d") a copy of SEARCHLIST is used instead. That copy is made after complementing under "/c". SEARCHLIST is sorted by code point order after complementing, and any REPLACEMENTLIST is applied to that sorted result. This means that under "/c", the order of the characters specified in SEARCHLIST is irrelevant. This can lead to different results on EBCDIC systems if REPLACEMENTLIST contains more than one character, hence it is generally non-portable to use "/c" with such a REPLACEMENTLIST.

Another way of describing the operation is this

: Si se especifica "/c", la SEARCHLIST se ordena por puntos de código y luego se complementa. Si REPLACEMENTLIST está vacía y no se especifica "/d", REPLACEMENTLIST se reemplaza por una copia de SEARCHLIST (tal como se modifica bajo "/c"), y estas listas potencialmente modificadas se utilizan como base para lo que sigue. Cualquier carácter en la cadena de destino que no esté en SEARCHLIST se pasa sin cambios. Cada carácter restante en la cadena de destino se reemplaza por el carácter en REPLACEMENTLIST que corresponde posicionalmente a su par en SEARCHLIST, excepto que bajo "/s", los caracteres 2º y siguientes se eliminan en una secuencia de caracteres seguidos que se traducen al mismo carácter. Si SEARCHLIST es más larga que REPLACEMENTLIST, los caracteres en la cadena de destino que coinciden con un carácter en SEARCHLIST que no tiene correspondencia en REPLACEMENTLIST se eliminan de la cadena de destino si se especifica "/d"; o se reemplazan por el carácter final en REPLACEMENTLIST si no se especifica "/d".

tr/o/o/s;                 # libro -> libbro
tr/oe/oe/s;               # libro -> libbro
tr/oe//s;                 # libro -> libbro
tr/oe/o/s;                # libro -> libbpro
($HOST = $host) =~ tr/a-z/A-Z/;
 $HOST = $host  =~ tr/a-z/A-Z/r; # lo mismo
$HOST = $host =~ tr/a-z/A-Z/r # encadenado con s///r
              =~ s/:/ -p/r;
tr/a-zA-Z/ /cs;               # cambiar no-alfas a un solo espacio
@stripped = map tr/a-zA-Z/ /csr, @original;
                              # /r con map
tr [\200-\377]
   [\000-\177];               # borrar maliciosamente el 8º bit
$foo !~ tr/A/a/    # transcribir todas las A en $foo a 'a',
                   # devolver 0 si se encontró alguna y se cambió.
                   # De lo contrario, devolver 1

Si se dan varias transliteraciones para un carácter, solo se usa la primera:

tr/AAA/XYZ/

transcribirá cualquier A a X.

Debido a que la tabla de transliteración se construye en tiempo de compilación, ni la SEARCHLIST ni la REPLACEMENTLIST están sujetas a interpolación de comillas dobles. Eso significa que si desea usar variables, debe usar un eval():

eval "tr/$oldlist/$newlist/";
die $@ if $@;
eval "tr/$oldlist/$newlist/, 1" or die $@;

Here-docs

"<<EOT"
"<<~EOT"
Una forma de citar orientada a líneas se basa en la sintaxis de "documento aquí" del shell. Después de un "<<" se especifica una cadena para terminar el material citado, y todas las líneas posteriores a la línea actual hasta la cadena terminadora son el valor del elemento.

Un ejemplo es

my $endng = <<WHIMPER;
This is the way the text ends.
This is the way the text ends.
Not with a bang, but with a
WHIMPER

En este caso, el terminador es un identificador, la palabra "WHIMPER". La mayoría de las veces, la gente pone en mayúsculas el identificador, solo para que se destaque, pero esto es solo una convención que no es necesaria.

El terminador puede estar entre comillas, como se detalla a continuación, pero sin ellas, el texto del here-doc actúa exactamente como si estuviera entre comillas dobles.

my $person = 'John';
print uc <<EOT;
Hello, $person!
And the text goes on.
EOT

Esto produce:

HELLO, JOHN!
AND THE TEXT GOES ON.

Los paréntesis en la llamada a la función "uc" no tienen que omitirse:

print uc(<<EOT);
Hello, $person!
And the text goes on.
EOT
HELLO, JOHN!
AND THE TEXT GOES ON.

Y puedes mezclar un here-doc con otras cosas:

print <<EOT, "Followed by the next argument\n";
Hello, $person!
And the text goes on.
EOT
Hello, John!
And the text goes on.
Followed by the next argument

Y puedes tener múltiples here-docs:

print <<EOT1, <<EOT2;
Hello, $person!
And the text goes on.
EOT1
Followed by the next argument
EOT2
Hello, John!
And the text goes on.
Followed by the next argument

El terminador no tiene que ser una sola palabra; también puede ser algún texto entre comillas:

my $pagliaci = << "La Commedia e finita!";
A troupe comes to town to perform a play, a comedy.  The lead actress
and lead actor are in an unhappy marriage.  On stage, he stabs her
for real; then he stabs her lover who has rushed from the audience to
defend her.  Both die.
La Commedia e finita!

No debe haber un espacio entre "<<" y el identificador a menos que el terminador esté entre comillas, como se demuestra en el ejemplo anterior. Las reglas de citación para el terminador no están relacionadas con las reglas de citación de Perl. Solo se pueden usar "", '' y `` para citarlo, NO q(), qq() y similares. La única interpolación es para hacer escape de la comilla citadora:

print << "abc\"def";
testing...
abc"def

La cadena terminadora debe aparecer por sí sola (sin comillas y sin espacio en blanco alrededor) en la línea terminadora. Además, no puede abarcar varias líneas. La regla general es que el identificador debe ser una cadena literal. Cíñete a eso y estarás a salvo.

No olvides que tienes que poner un punto y coma al final para terminar la sentencia, ya que Perl no sabe que no vas a intentar hacer esto:

print <<ABC
10
ABC
   + 20;

que imprime 30 y ningún terminador de línea.

Si desea que su here-doc no tenga un terminador de línea en la última línea, use chomp().

chomp($string = <<'END');
This is the first line.
This second line won't end in a \n.
END

Si utiliza un here-doc dentro de una construcción delimitada, como en "s///eg", el material citado debe seguir estando en la línea posterior al marcador "<<TERMINATOR", lo que significa que puede estar dentro de la construcción delimitada:

s/this/<<E . 'that'
the other
E
 . 'more '/eg;

(Funciona de esta manera a partir de Perl 5.18. Históricamente, era inconsistente, y tendrías que escribir

s/this/<<E . 'that'
 . 'more '/eg;
the other
E

fuera de las evaluaciones de cadenas.)

Un problema con la sintaxis de Here-doc dada hasta ahora es que debe estar en el margen izquierdo de tu programa, estropeando la indentación. A partir de Perl v5.26, el modificador tilde "~" te permite indentar tus here-docs para hacer el código más legible.

if ($some_var) {
    print <<~EOF;
      This is a here-doc
      EOF
}

Esto imprimirá...

This is a here-doc

...sin espacio en blanco inicial.

La línea que contiene el delimitador que marca el final del here-doc determina la plantilla de indentación para todo. La compilación falla si alguna línea no vacía dentro del here-doc no comienza con la indentación precisa de la línea terminadora. (Una línea vacía consta del único carácter "\n".) Por ejemplo, suponga que la línea terminadora comienza con un carácter de tabulación seguido de 4 espacios. Cada línea no vacía en el here-doc debe comenzar con una tabulación seguida de 4 espacios. Se eliminan de cada línea, y cualquier espacio en blanco inicial restante en una línea sirve como la indentación para esa línea. Actualmente, solo los caracteres TAB y ESPACIO se tratan como espacio en blanco para este propósito. Las tabulaciones y los espacios se pueden mezclar, pero se emparejan exactamente; las tabulaciones permanecen tabulaciones y no se expanden.

El espacio en blanco inicial adicional (más allá de lo que precedía al delimitador) se conservará:

print <<~EOF;
  This text is not indented
    This text is indented with two spaces
               This line is indented with two tabs, though those may
               have been converted to spaces by various filters by
               the time you read this.
  EOF

Citar el delimitador

Como se mencionó anteriormente, la cadena terminadora puede ser citada. Hay tres tipos de citas posibles. El tipo utilizado determina el tratamiento del texto.

Comillas Dobles
Las comillas dobles que rodean la palabra o cadena terminadora se comportan como si no hubiera comillas, es decir, el texto se interpolará utilizando exactamente las mismas reglas que las cadenas normales entre comillas dobles, como en todos los ejemplos anteriores. Así 
my $person = 'John';
print uc << "EOT";
Hello, $person!
And the text goes on.
EOT

produce:

HELLO, JOHN!
AND THE TEXT GOES ON.

que es el mismo resultado que sin comillas.

Comillas Simples
Si, en cambio, se utilizan comillas simples, el texto se trata literalmente, sin interpolación de su contenido. 
my $person = 'John';
print uc <<'EOT';
Hello, $person!
And the text goes on.
EOT
HELLO, $PERSON!
AND THE TEXT GOES ON.

La diferencia entre un here-doc entre comillas simples y una cadena entre comillas simples es que las barras invertidas no tienen significado especial en un here-doc, tratándose "\\" como dos barras invertidas y no una, como lo harían en cualquier otra construcción de citación.

Al igual que en el shell, una palabra desnuda con barra invertida después de "<<" significa lo mismo que una cadena entre comillas simples:

$cost = <<'VISTA';  # hasta la ...
That'll be $10 please, ma'am.
VISTA
$cost = <<'VISTA'; # ¡Lo mismo! Eso será $10 por favor, señora. VISTA

Estas dos formas son las únicas maneras de citar en Perl donde no hay necesidad de preocuparse por escapar contenido, algo que los generadores de código pueden y hacen aprovechar bien.

Backticks
Finalmente, si en lugar de ello se usan backticks para citar la cadena terminadora, el contenido del here doc se trata igual que si fuera una cadena incrustada en backticks. Por lo tanto, el contenido se interpola como si estuviera entre comillas dobles y luego se ejecuta a través del shell, devolviendo los resultados de la ejecución. 
print << `EOC`; # ejecuta comando y obtiene resultados
echo hi there
EOC

Detalles escabrosos del análisis de construcciones citadas

Cuando se le presenta algo que podría tener varias interpretaciones diferentes, Perl utiliza el principio DWIM (que significa "Haz lo que quiero decir") para elegir la interpretación más probable. Esta estrategia es tan exitosa que los programadores de Perl a menudo no sospechan la ambigüedad de lo que escriben. Pero de vez en cuando, las nociones de Perl difieren sustancialmente de lo que el autor realmente quiso decir.

Esta sección espera aclarar cómo Perl maneja las construcciones citadas. Aunque la razón más común para aprender esto es desentrañar expresiones regulares laberínticas, dado que los pasos iniciales del análisis son los mismos para todos los operadores de citación, se discuten juntos.

La regla de análisis más importante de Perl es la primera que se discute a continuación: al procesar una construcción citada, Perl primero encuentra el final de esa construcción y luego interpreta su contenido. Si entiende esta regla, puede omitir el resto de esta sección en la primera lectura. Es probable que las otras reglas contradigan las expectativas del usuario con mucha menos frecuencia que esta primera.

Algunas pasadas discutidas a continuación se realizan concurrentemente, pero dado que sus resultados son los mismos, las consideramos individualmente. Para diferentes construcciones citadas, Perl realiza un número diferente de pasadas, de una a cuatro, pero estas pasadas siempre se realizan en el mismo orden.

Encontrar el final
La primera pasada es encontrar el final de la construcción citada. Esto resulta en guardar en una ubicación segura una copia del texto (entre los delimitadores de inicio y fin), normalizado según sea necesario para evitar tener que saber cuáles eran los delimitadores originales.

Si la construcción es un here-doc, el delimitador de fin es una línea que tiene una cadena terminadora como contenido. Por lo tanto, "<<EOF" se termina con "EOF" seguido inmediatamente por "\n" y comenzando desde la primera columna de la línea terminadora. Al buscar la línea terminadora de un here-doc, nada se omite. En otras palabras, las líneas después de la sintaxis del here-doc se comparan línea por línea con la cadena terminadora.

Para las construcciones excepto los here-docs, se utilizan caracteres individuales como delimitadores de inicio y fin. Si el delimitador de inicio es una puntuación de apertura (es decir, "(", "[", "{" o "<"), el delimitador de fin es la puntuación de cierre correspondiente (es decir, ")", "]", "}" o ">"). Si el delimitador de inicio es un carácter sin pareja como "/" o una puntuación de cierre, el delimitador de fin es el mismo que el delimitador de inicio. Por lo tanto, un "/" termina una construcción "qq//", mientras que un "]" termina ambas construcciones "qq[]" y "qq]]".

Al buscar delimitadores de un solo carácter, se omiten los delimitadores escapados y los "\\". Por ejemplo, al buscar el delimitador de fin "/", se omiten las combinaciones de "\\" y "\/". Si los delimitadores son de anidamiento, también se omiten los pares anidados. Por ejemplo, al buscar un "]" de cierre emparejado con el "[" de apertura, se omiten las combinaciones de "\\", "\]" y "\[", y también se omiten los "[" y "]" anidados. Sin embargo, cuando las barras invertidas se utilizan como delimitadores (como "qq\\" y "tr\\\"), nada se omite. Durante la búsqueda del final, las barras invertidas que escapan delimitadores u otras barras invertidas se eliminan (hablando exactamente, no se copian a la ubicación segura).

Para construcciones con delimitadores de tres partes ("s///", "y///" y "tr///"), la búsqueda se repite una vez más. Si el primer delimitador no es una puntuación de apertura, los tres delimitadores deben ser iguales, como "s!!!" y "tr)))", en cuyo caso el segundo delimitador termina la parte izquierda y comienza la parte derecha a la vez. Si la parte izquierda está delimitada por puntuación de anidamiento (es decir, "()", "[]", "{}" o "<>"), la parte derecha necesita otro par de delimitadores como "s(){}" y "tr[]//". En estos casos, se permiten espacios en blanco y comentarios entre las dos partes, aunque el comentario debe seguir al menos un carácter de espacio en blanco; de lo contrario, un carácter esperado como inicio del comentario puede considerarse como el delimitador de inicio de la parte derecha.

Durante esta búsqueda no se presta atención a la semántica de la construcción. Por lo tanto:

"$hash{"$foo/$bar"}"

o:

m/
  bar       # NO es un comentario, esta barra / terminó m//!
 /x

no forman expresiones citadas legales. La parte citada termina en la primera """ y "/", y el resto resulta ser un error de sintaxis. Dado que la barra que terminó "m//" fue seguida por un "ESPACIO", el ejemplo anterior no es "m//x", sino más bien "m//" sin el modificador "/x". Por lo tanto, el "#" incrustado se interpreta como un literal "#".

Tampoco se presta atención a "\c\" (sintaxis de carácter de control multicarácter) durante esta búsqueda. Por lo tanto, la segunda "\" en "qq/\c\/" se interpreta como parte de "\/", y la siguiente "/" no se reconoce como delimitador. En su lugar, use "\034" o "\x1c" al final de las construcciones citadas.

Interpolación
El siguiente paso es la interpolación en el texto obtenido, que ahora es independiente del delimitador. Hay múltiples casos.
"<<'EOF'"
No se realiza ninguna interpolación. Tenga en cuenta que la combinación "\\" se deja intacta, ya que los delimitadores escapados no están disponibles para los here-docs.
"m''", el patrón de "s'''"
No se realiza ninguna interpolación en esta etapa. Las secuencias escapadas, incluida "\\", se tratan en la etapa de "Análisis de expresiones regulares".
'', "q//", "tr'''", "y'''", el reemplazo de "s'''"
La única interpolación es la eliminación de "\" de los pares de "\\". Por lo tanto, "-" en "tr'''" y "y'''" se trata literalmente como un guion y no hay rango de caracteres disponible. "\1" en el reemplazo de "s'''" no funciona como $1.
"tr///", "y///"
No ocurre ninguna interpolación de variables. Las combinaciones de modificación de cadena para mayúsculas y minúsculas y citación como "\Q", "\U" y "\E" no se reconocen. Las otras secuencias de escape como "\200" y "\t" y los caracteres escapados como "\\" y "\-" se convierten en literales apropiados. El carácter "-" se trata especialmente y, por lo tanto, "\-" se trata como un literal "-".
"", ``, "qq//", "qx//", "<file*glob>", "<<"EOF""
"\Q", "\U", "\u", "\L", "\l", "\F" (posiblemente emparejado con "\E") se convierten en construcciones de Perl correspondientes. Por lo tanto, "$foo\Qbaz$bar" se convierte internamente en "$foo . (quotemeta("baz" . $bar))". Las otras secuencias de escape como "\200" y "\t" y los caracteres escapados como "\\" y "\-" se reemplazan con expansiones apropiadas.

Que sea

Enfatizó que todo lo que cae entre "\Q" y "\E" se interpola de la manera habitual. Algo como "\Q\\E" no tiene "\E" dentro. En su lugar, tiene "\Q", "\\" y "E", por lo que el resultado es el mismo que para "\\\\E". Como regla general, las barras invertidas entre "\Q" y "\E" pueden dar lugar a resultados contraintuitivos. Por lo tanto, "\Q\t\E" se convierte en quotemeta("\t"), que es lo mismo que "\\\t" (ya que TAB no es alfanumérico). Tenga en cuenta también que:

$str = '\t';
return "\Q$str";

puede estar más cerca de la intención conjetural del escritor de "\Q\t\E".

Los escalares y arrays interpolados se convierten internamente a las operaciones de concatenación "join" y ".". Por lo tanto, "$foo XXX '@arr'" se convierte en:

$foo . " XXX '" . (join $", @arr) . "'";

Todas las operaciones anteriores se realizan simultáneamente, de izquierda a derecha.

Dado que el resultado de "\Q CADENA \E" tiene todos los metacaracteres entrecomillados, no hay forma de insertar un "$" o "@" literal dentro de un par "\Q\E". Si se protege con "\", "$" se entrecomillará para convertirse en "\\\$"; de lo contrario, se interpretará como el inicio de un escalar interpolado.

Tenga en cuenta también que el código de interpolación necesita tomar una decisión sobre dónde termina el escalar interpolado. Por ejemplo, si "a $x -> {c}" realmente significa:

"a " . $x . " -> {c}";

o:

"a " . $x -> {c};

La mayoría de las veces, el texto más largo posible que no incluye espacios entre componentes y que contiene llaves o corchetes coincidentes. Dado que el resultado puede determinarse por votación basada en estimadores heurísticos, el resultado no es estrictamente predecible. Afortunadamente, suele ser correcto para casos ambiguos.

El reemplazo de "s///"
El procesamiento de "\Q", "\U", "\u", "\L", "\l", "\F" y la interpolación ocurren como con los constructos "qq//".

Es en este paso que "\1" se convierte a regañadientes en $1 en el texto de reemplazo de "s///", para corregir a los incorregibles hackers de sed que aún no han adoptado el modismo más sensato. Se emite una advertencia si se estableció la pragmática "use warnings" o la bandera de línea de comandos -w (es decir, la variable $^W).

"RE" en "m?RE?", "/RE/", "m/RE/", "s/RE/foo/",
El procesamiento de "\Q", "\U", "\u", "\L", "\l", "\F", "\E", y la interpolación ocurren (casi) como con los constructos "qq//".

El procesamiento de "\N{...}" también se realiza aquí y se compila en una forma intermedia para el compilador de expresiones regulares. (Esto se debe a que, como se menciona a continuación, la compilación de expresiones regulares puede realizarse en tiempo de ejecución, y "\N{...}" es un constructo en tiempo de compilación.)

Sin embargo, cualquier otra combinación de "\" seguida de un carácter no se sustituye sino que solo se omite, para poder analizarlas como expresiones regulares en el siguiente paso. Como "\c" se omite en este paso, el "@" de "\c@" en RE se trata posiblemente como un símbolo de array (por ejemplo @foo), aunque el mismo texto en "qq//" produce la interpolación de "\c@".

Los bloques de código como "(?{BLOQUE})" se manejan pasando temporalmente el control al analizador de Perl, de manera similar a como lo haría una expresión de subíndice de array interpolada como "foo$array[1+f("[xyz")]bar".

Además, dentro de "(?{BLOQUE})", "(?# comentario )" y un comentario de "#" en una expresión regular "/x", no se realiza ningún procesamiento. Este es el primer paso en el que la presencia del modificador "/x" es relevante.

La interpolación en patrones tiene varias peculiaridades: $|, $(, $), "@+" y "@-" no se interpolan, y los constructos $var[ALGO] se votan (por varios estimadores diferentes) para ser un elemento de array o $var seguido de una alternativa de RE. Aquí es donde la notación "${arr[$bar]}" resulta útil: "/${arr[0-9]}/" se interpreta como el elemento de array -9, no como una expresión regular de la variable $arr seguida de un dígito, que sería la interpretación de "/$arr[0-9]/". Dado que puede haber votaciones entre diferentes estimadores, el resultado no es predecible.

La falta de procesamiento de "\\" crea restricciones específicas en el texto post-procesado. Si el delimitador es "/", no se puede obtener la combinación "\/" en el resultado de este paso. "/" finalizará la expresión regular, "\/" se eliminará a "/" en el paso anterior, y "\\/" se dejará como está. Dado que "/" es equivalente a "\/" dentro de una expresión regular, esto no importa a menos que el delimitador sea un carácter especial para el motor de RE, como en "s*foo*bar*", "m[foo]", o "m?foo?"; o un carácter alfanumérico, como en:

m m ^ a \s* b mmx;

En la RE anterior, que está intencionalmente ofuscada para ilustración, el delimitador es "m", el modificador es "mx", y después de la eliminación del delimitador, la RE es la misma que para "m/ ^ a \s* b /mx". Hay más de una razón por la que se le anima a restringir sus delimitadores a opciones no alfanuméricas y no espacios en blanco.

Este paso es el último para todos los constructos excepto para las expresiones regulares, que se procesan further.

Análisis de expresiones regulares
Los pasos anteriores se realizaron durante la compilación del código Perl, pero este ocurre en tiempo de ejecución, aunque puede optimizarse para calcularse en tiempo de compilación si es apropiado. Después del preprocesamiento descrito anteriormente, y posiblemente después de la evaluación si se trata de concatenación, unión, traducción de mayúsculas/minúsculas o meta-entrecomillado, la cadena resultante se pasa al motor de RE para su compilación.

Lo que suceda en el motor de RE podría discutirse mejor en perlre, pero en aras de la continuidad, lo haremos aquí.

Este es otro paso en el que la presencia del modificador "/x" es relevante. El motor de RE escanea la cadena de izquierda a derecha y la convierte en un autómata finito.

Los caracteres con barra invertida se reemplazan con cadenas literales correspondientes (como con "\{"), o bien generan nodos especiales en el autómata finito (como con "\b"). Los caracteres especiales para el motor de RE (como "|") generan nodos o grupos de nodos correspondientes. Los comentarios "(?#...)" se ignoran. Todo lo demás se convierte en cadenas literales para que coincidan, o bien se ignora (como los espacios en blanco y los comentarios de estilo "#" si "/x" está presente).

El análisis del constructo de clase de caracteres entre corchetes, "[...]", es bastante diferente de la regla utilizada para el resto del patrón. El terminador de este constructo se encuentra utilizando las mismas reglas que para encontrar el terminador de un constructo delimitado por "{}", con la única excepción de que "]" inmediatamente después de "[" se trata como si estuviera precedido por una barra invertida.

El terminador de "(?{...})" en tiempo de ejecución se encuentra cambiando temporalmente el control al analizador de Perl, que debe detenerse en el punto donde se encuentra el "}" terminador lógicamente equilibrado.

Es posible inspeccionar tanto la cadena que se pasa al motor de RE como

, o glob referencia, se interpreta como un patrón de nombre de archivo para ser globbed, y se devuelve una lista de nombres de archivo o el siguiente nombre de archivo de la lista, dependiendo del contexto. Esta distinción se determina únicamente por motivos sintácticos. Eso significa que "<$x>" es siempre una readline() de un manejador indirecto, pero "<$hash{key}>" es siempre un glob(). Esto se debe a que $x es una variable escalar simple, pero $hash{key} no lo es, es un elemento de hash. Incluso "<$x >" (observe el espacio adicional) se trata como "glob("$x ")", no como readline($x).

Se realiza un nivel de interpretación de comillas dobles primero, pero no puedes decir "<$foo>" porque es un manejador de archivos indirecto como se explicó en el párrafo anterior. (En versiones anteriores de Perl, los programadores insertaban llaves para forzar la interpretación como glob de nombres de archivo: "<${foo}>". En estos días, se considera más limpio llamar a la función interna directamente como glob($foo), que es probablemente la forma correcta de haberlo hecho en primer lugar). Por ejemplo:

while (<*.c>) {
    chmod 0644, $_;
}

es aproximadamente equivalente a:

open(FOO, "echo *.c | tr -s ' \t\r\f' '\\012\\012\\012\\012'|");
while (<FOO>) {
    chomp;
    chmod 0644, $_;
}

excepto que el globbing se realiza internamente utilizando la extensión estándar "File::Glob". Por supuesto, la forma más corta de hacer lo anterior es:

chmod 0644, <*.c>;

Un glob (de archivos) evalúa su argumento (incrustado) solo cuando está iniciando una nueva lista. Deben leerse todos los valores antes de que comience de nuevo. En contexto de lista, esto no es importante porque los obtienes todos automáticamente de todos modos. Sin embargo, en contexto escalar, el operador devuelve el siguiente valor cada vez que se llama, o "undef" cuando la lista se ha agotado. Al igual que con las lecturas del manejador de archivos, un "defined" automático se genera cuando el glob ocurre en la parte de prueba de un "while", porque los retornos legales de glob (por ejemplo, un archivo llamado 0) de lo contrario terminarían el bucle. Nuevamente, "undef" se devuelve solo una vez. Por lo tanto, si esperas un solo valor de un glob, es mucho mejor decir

($file) = <blurch*>;

que

$file = <blurch*>;

porque este último alternará entre devolver un nombre de archivo y devolver falso.

Si intentas hacer interpolación de variables, es definitivamente mejor usar la función glob(), porque la notación antigua puede hacer que las personas se confundan con la notación del manejador de archivos indirecto.

@files = glob("$dir/*.[ch]");
@files = glob($files[$i]);

Si una expresión de globbing basada en corchetes angulares se utiliza como condición de un bucle "while" o "for", entonces se asignará implícitamente a $_. Si una expresión de globbing o una asignación explícita de una expresión de globbing a un escalar se utiliza como una condición de "while"/"for", entonces la condición en realidad prueba la definici_n del valor de la expresión, no su valor de verdad regular.

Plegado de Constantes

Al igual que C, Perl realiza una cierta cantidad de evaluación de expresiones en tiempo de compilación siempre que determina que todos los argumentos de un operador son estáticos y no tienen efectos secundarios. En particular, la concatenación de cadenas ocurre en tiempo de compilación entre literales que no hacen sustitución de variables. La interpolación de barras invertidas también ocurre en tiempo de compilación. Puedes decir

  'Ahora es el momento para todos'
. "\n"
.  'los buenos hombres de venir.'

y todo esto se reduce a una sola cadena internamente. De manera similar, si dices

foreach $file (@filenames) {
    if (-s $file > 5 + 100 * 2**16) {  }
}

el compilador precalcula el número que representa esa expresión para que el intérprete no tenga que hacerlo.

No-ops

Perl no tiene oficialmente un operador no-op, pero las constantes desnudas 0 y 1 se tratan de manera especial para no producir una advertencia en contexto void, por lo que puedes, por ejemplo, hacer de forma segura

1 while foo();

Operadores Bitwise de Cadenas

Se pueden manipular cadenas de bits de cualquier tamaño mediante los operadores bitwise ( "~ | & ^").

Si los operandos de un op bitwise binario son cadenas de tamaños diferentes, los operadores | y ^ actúan como si el operando más corto tuviera bits cero adicionales a la derecha, mientras que el operador & actúa como si el operando más largo fuera truncado a la longitud del más corto. La granularidad para tal extensión o truncamiento es de uno o más bytes.

# Ejemplos basados en ASCII
print "j p \n" ^ " a h";            # imprime "JAPH\n"
print "JA" | "  ph\n";              # imprime "japh\n"
print "japh\nJunk" & '_____';       # imprime "JAPH\n";
print 'p N$' ^ " E<H\n";            # imprime "Perl\n";

Si tu intención es manipular cadenas de bits, asegúrate de que estás proporcionando cadenas de bits: Si un operando es un número, eso implicará una operación bitwise numérica. Puedes mostrar explícitamente qué tipo de operación intentas utilizando "" o "0+", como en los siguientes ejemplos.

$foo =  150  |  105;        # produce 255  (0x96 | 0x69 es 0xFF)
$foo = '150' |  105;        # produce 255
$foo =  150  | '105';       # produce 255
$foo = '150' | '105';       # produce la cadena '155' (en ASCII)
$baz = 0+$foo & 0+$bar;     # ambos ops explícitamente numéricos
$biz = "$foo" ^ "$bar";     # ambos ops explícitamente de cadena

Este comportamiento algo impredecible se puede evitar con la característica "bitwise", nueva en Perl 5.22. Puedes habilitarla a través de use feature 'bitwise' o "use v5.28". Antes de Perl 5.28, emitía una advertencia en la categoría "experimental::bitwise". Bajo esta característica, los cuatro operadores bitwise estándar ( "~ | & ^") son siempre numéricos. Añadir un punto después de cada operador ( "~. |. &. ^.") lo fuerza a tratar sus operandos como cadenas:

use feature "bitwise";
$foo =  150  |  105;        # produce 255  (0x96 | 0x69 es 0xFF)
$foo = '150' |  105;        # produce 255
$foo =  150  | '105';       # produce 255
$foo = '150' | '105';       # produce 255
$foo =  150  |. 105;        # produce la cadena '155'
$foo = '150' |. 105;        # produce la cadena '155'
$foo =  150  |.'105';       # produce la cadena '155'
$foo = '150' |.'105';       # produce la cadena '155'
$baz = $foo &  $bar;        # ambos operandos numéricos
$biz = $foo ^. $bar;        # ambos operandos de cadena

Las variantes de asignación de estos operadores ( "&= |= ^= &.= |.= ^.=") se comportan de manera similar bajo la característica.

Es un error fatal si un operando contiene un carácter cuyo valor ordinal es superior a 0xFF, y por lo tanto no es expresable excepto en UTF-8. La operación se realiza sobre una copia no UTF-8 para otros operandos codificados en UTF-8. Ver "Semántica de Bytes y Caracteres" en perlunicode.

Ver "vec" en perlfunc para obtener información sobre cómo manipular bits individuales en un vector de bits.

Aritmética Entera

Por defecto, Perl asume que debe realizar la mayor parte de su aritmética en punto flotante. Pero al decir

use integer;

puedes indicarle al compilador que use operaciones enteras (ver integer para una explicación detallada) desde aquí hasta el final del BLOQUE envolvente. Un BLOQUE interno puede revocar esto diciendo

no integer;

que dura hasta el final de ese BLOQUE. Ten en cuenta que esto no significa que todo sea un entero, sino que Perl usará operaciones enteras para operadores aritméticos, de comparación y bitwise. Por ejemplo, incluso bajo "use integer", si tomas la sqrt(2), aún obtendrás 1.4142135623731 o algo similar.

Usados en números, los operadores bitwise ( "&" "|" "^" "~" "<<" ">>") siempre producen resultados enteros. (Pero ver también "Operadores Bitwise de Cadenas"). Sin embargo, "use integer" todavía tiene significado para ellos. Por defecto, sus resultados se interpretan como enteros sin signo, pero si "use integer" está en efecto, sus resultados se interpretan como enteros con signo. Por ejemplo, "~0" generalmente se evalúa como un valor entero grande. Sin embargo, "use integer; ~0" es -1 en máquinas de complemento a dos.

        NAME
    

    
perlop - Perl operators






    

        DESCRIPTION
    

    

        This document describes the operators available in the Perl
        programming language. Operators are symbols or keywords that perform
        operations on one or more operands. Perl provides a rich set of operators,
        including arithmetic, logical, bitwise, string, comparison,
        assignment, and others.
    

    

        The operators are listed below, grouped by their general functionality.
        The precedence and associativity of operators are important for understanding
        how expressions are evaluated. Lower numbers indicate higher precedence.
    


    

        

            UNARY OPERATORS
        

        

            Unary operators operate on a single operand. They typically have high
            precedence.
        

        

            
+, -

            
Unary plus and minus. Numeric context.

            
~

            
Stringifies the operand.

            
!

            
Logical NOT. Returns true if the operand is false, and false if the
            operand is true.

            
--, ++

            
Decrement and increment operators. Applicable to numbers and
            references.

            
defined

            
Tests if the operand is defined.

            
exists

            
Tests if an element exists in an array or hash.

            
delete

            
Deletes an element from a hash.

            
ref

            
Returns a string describing the type of the reference, or false if
            the operand is not a reference.

            
scalar

            
Forces scalar context.

            
chop

            
Removes the last character from a string.

            
length

            
Returns the length of a string.

            
pos

            
Returns the position of the last match of a regular expression, or
            sets the position.

            
ord

            
Returns the numeric value of the first character of a string.

            
chr

            
Returns the character corresponding to a given ASCII value.

        

    


    

        

            BINARY OPERATORS
        

        

            Binary operators operate on two operands.
        

        

            
+, -, *, /, %

            
Arithmetic operators: addition, subtraction, multiplication,
            division, modulo.

            
.

            
String concatenation.

            
==, !=, <, >, <=, >=

            
Numeric comparison operators.

            
eq, ne, lt, gt, le, ge

            
String comparison operators.

            
&&, ||

            
Logical AND and OR operators. Short-circuiting.

            
and, or, xor

            
Alternative logical operators with lower precedence.

            
x

            
String repetition.

            
<=>

            
Spaceship operator. Returns -1, 0, or 1.

            
cmp

            
String comparison operator, equivalent to lt, eq, gt.

            
.., ...

            
Range operators.

            
=~, !~

            
Binding operators for regular expression matching and negation.

            
&, |, ^, ~, <<, >>

            
Bitwise operators: AND, OR, XOR, NOT (compliment), left shift,
            right shift.

            
,

            
Comma operator. Evaluates operands left to right and returns the
            value of the rightmost operand.

            
=>

            
Pair operator, often used in hash initialization.

        

    


    

        

            ASSIGNMENT OPERATORS
        

        

            
=

            
Simple assignment.

            
+=, -=, *=, /=, %=, .=, x=, <<=, >>=, &=, |=, ^=, ~=
            
Compound assignment operators. For example, a += b is
            equivalent to a = a + b.

        

    


    

        

            CONTROL OPERATORS
        

        

            
? :

            
Conditional (ternary) operator.

            
.., ...

            
Range operators.

            
and, or, xor

            
Logical operators with low precedence.

        

    


    

        

            OTHER OPERATORS
        

        

            
()

            
Grouping operator. Controls order of evaluation.

            
[]

            
Array subscripting and hash key access.

            
{}

            
Block delimiters. Also used for hash key access with barewords.

            
sub name { ... }

            
Subroutine definition.

            
if (expr) ..., unless (expr) ...

            
Conditional statements.

            
while (expr) ..., until (expr) ...

            
Looping constructs.

            
for (...) ..., foreach (...) ...

            
Iteration constructs.

            
do ... while, do ... until

            
Do-while and do-until loops.

            
goto LABEL

            
Unconditional jump to a labeled statement.

            
return ...

            
Returns a value from a subroutine.

            
next

            
Skips the rest of the current loop iteration.

            
last

            
Exits the innermost loop.

            
redo

            
Restarts the current loop iteration without re-evaluating the
            condition.

            
continue

            
Block executed at the end of each loop iteration.

            
print ..., printf ...

            
Output functions.

            
say ...

            
Output function that automatically adds a newline.

            
chomp ...

            
Removes trailing newline characters from a string.

            
warn ...

            
Prints a warning message to STDERR.

            
die ...

            
Exits the program with an error message.

            
map BLOCK LIST

            
Applies a block to each element of a list and returns the results.

            
grep BLOCK LIST

            
Filters a list, returning only elements for which the block evaluates
            to true.

            
sort BLOCK LIST

            
Sorts a list. If a block is provided, it defines the comparison.

            
splice @ARRAY, OFFSET, LENGTH, LIST

            
Removes or replaces elements from an array.

            
push @ARRAY, LIST

            
Appends elements to the end of an array.

            
pop @ARRAY

            
Removes and returns the last element of an array.

            
shift @ARRAY

            
Removes and returns the first element of an array.

            
unshift @ARRAY, LIST

            
Prepends elements to the beginning of an array.

            
keys %HASH

            
Returns a list of all keys in a hash.

            
values %HASH

            
Returns a list of all values in a hash.

            
each %HASH

            
Returns the next key-value pair from a hash.

            
__FILE__, __LINE__, __PACKAGE__

            
Special variables containing the current file name, line number, and
            package name.

        

    


    

        

            REGULAR EXPRESSION OPERATORS
        

        

            Perl's regular expression matching and substitution operators are
            very powerful.
        

        

            
m/pattern/flags

            
Match operator.

            
s/pattern/replacement/flags

            
Substitution operator.

            
tr/set1/set2/flags

            
Transliteration operator.

            
y/set1/set2/flags

            
Synonym for tr.

            
qr/pattern/flags

            
Compiles a regular expression for later use.

        

        

            Common flags include:
        

        
    
            
  • i: Case-insensitive matching.
    • 
            
  • m: Multiline mode (^ and $ match start/end of lines).
    • 
            
  • s: Single-line mode (. matches newline).
    • 
            
  • x: Extended regular expression syntax (ignore whitespace, allow comments).
    • 
        

    


    

        

            ARROW OPERATORS
        

        

            These operators are used for accessing elements of array references,
            hash references, or objects.
        

        

            
->

            
Dereferences an array, hash, or code reference. Also used for method calls
            on objects.

            
::

            
Scope resolution operator, used to access package variables or subroutines.
