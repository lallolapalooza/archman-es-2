perlbrew(1p)

Paquete: perlbrew

Licencias: MIT

PERLBREW(1p) Documentación de Perl contribuida por el usuario PERLBREW(1p)

NOMBRE

perlbrew - Gestor de entornos Perl.

SINOPSIS

Sintaxis del comando perlbrew:

perlbrew <comando> [opciones] [argumentos]

Comandos:

init           Inicializa el entorno de perlbrew.
info           Muestra información útil sobre la instalación de perlbrew
install        Instala perl
uninstall      Desinstala la instalación dada
available      Lista las versiones de perl disponibles para instalar
lib            Gestiona directorios local::lib.
alias          Da un nuevo nombre a las instalaciones de perl
upgrade-perl   Actualiza la versión de perl actual
list           Lista las instalaciones de perl
use            Usa la versión de perl especificada en la shell actual
off            Desactiva perlbrew en la shell actual
switch         Usa permanentemente la versión de perl especificada como predeterminada
switch-off     Desactiva permanentemente perlbrew (revierte a la versión de perl del sistema)
exec           Ejecuta programas con entornos de perl especificados.
list-modules   Lista los módulos CPAN instalados para la versión de Perl actualmente en uso
clone-modules  Reinstala todos los módulos CPAN de una instalación a otra
self-install       Instala perlbrew mismo dentro de PERLBREW_ROOT/bin
self-upgrade       Actualiza perlbrew mismo.
install-patchperl  Instala patchperl
install-cpanm      Instala cpanm, un compañero amigable.
install-cpm        Instala cpm, un compañero más rápido pero aún amigable.
install-multiple   Instala múltiples versiones y sabores de perl
download       Descarga el archivo tarball de distribución de perl especificado.
clean          Limpia archivos tarball y directorios de compilación
version        Muestra la versión
help           Lee instrucciones más detalladas

Opciones genéricas de comando:

-q --quiet     Ser silencioso en mensajes de salida informativa.
-v --verbose   Dime más al respecto.

Consulta `perlbrew help` para la documentación completa de perlbrew, o

Consulta `perlbrew help <comando>` para obtener una descripción detallada del comando.

CONFIGURACIÓN

PERLBREW_ROOT
Por defecto, perlbrew compila e instala versiones de perl en el directorio "$ENV{HOME}/perl5/perlbrew". Para usar un directorio diferente, establece esta variable de entorno en tu "bashrc" al directorio en tu RC de shell antes de cargar el RC de perlbrew.

Es posible compartir una instalación de perlbrew con múltiples cuentas de usuario en la misma máquina. Por lo tanto, la gente no tiene que instalar la misma versión de perl una y otra vez. Digamos que "/opt/perl5" es el directorio que queremos compartir. Todos los usuarios deberían poder añadir este fragmento a su bashrc para hacerlo efectivo:

export PERLBREW_ROOT=/opt/perl5
source ${PERLBREW_ROOT}/etc/bashrc

Después de hacer esto, el PATH de todos debería incluir "/opt/perl5/bin" y "/opt/perl5/perls/${PERLBREW_PERL}/bin". Cada usuario puede invocar "perlbrew switch" y "perlbrew use" para cambiar independientemente a un entorno de perl diferente de su elección. Sin embargo, solo el usuario con permiso de escritura para $PERLBREW_ROOT puede instalar módulos CPAN. Esto es bueno y malo dependiendo de la convención de trabajo de tu equipo.

Si deseas instalar módulos CPAN solo para ti, deberías usar el comando "lib" para construir un entorno personal de local::lib. Los entornos de local::lib son personales y no se comparten entre diferentes usuarios. Para más detalles, lee "perlbrew help lib" y la documentación de local::lib.

Si deseas un aislamiento de módulos aún más genial y deseas instalar módulos CPAN utilizados solo para un proyecto, deberías usar carton para este propósito.

También es posible establecer esta variable antes de instalar perlbrew para que perlbrew se instale bajo el PERLBREW_ROOT dado:

export PERLBREW_ROOT=/opt/perl5
curl -L https://install.perlbrew.pl | bash

Después de hacer esto, el ejecutable de perlbrew se instala como "/opt/perl5/bin/perlbrew"

PERLBREW_HOME
Por defecto, perlbrew almacena la configuración por usuario en el directorio "$ENV{HOME}/.perlbrew". Para usar un directorio diferente, establece esta variable de entorno en tu RC de shell antes de cargar el RC de perlbrew.

En algunos casos, digamos, tu directorio de inicio está en NFS y es compartido entre múltiples máquinas, es posible que desees tener varias configuraciones de perlbrew diferentes por máquina. Para hacerlo, puedes usar la variable de entorno "PERLBREW_HOME" para indicarle a perlbrew dónde buscar el archivo de inicialización. Aquí tienes un breve fragmento de bash para la situación dada.

if [ "$(hostname)" == "machine-a" ]; then
    export PERLBREW_HOME=~/.perlbrew-a
elif [ "$(hostname)" == "machine-b" ]; then
    export PERLBREW_HOME=~/.perlbrew-b
fi
source ~/perl5/perlbrew/etc/bashrc
PERLBREW_CONFIGURE_FLAGS
Esta variable de entorno especifica la lista de banderas de tipo comando a pasar a 'sh Configure'. Por defecto es '-de'.
PERLBREW_CPAN_MIRROR
La URL del espejo CPAN de tu elección. Por defecto, se utiliza "https://cpan.metacpan.org".

COMANDO: INIT

Uso: perlbrew init

El comando "init" debe ser invocado manualmente cada vez que tú (el usuario de perlbrew) actualices o reinstales perlbrew.

Si la actualización se realiza con el comando "self-upgrade", o ejecutando manualmente el instalador de una línea, este comando se invoca automáticamente.

COMANDO: INFO

info [módulo]
Uso: perlbrew info [ <módulo> ]

Muestra información útil sobre la instalación de perlbrew.

Si se proporciona un módulo, se mostrará la versión y la ubicación del módulo.

COMANDO: INSTALL

Uso:

perlbrew install [opciones] <perl-release>
perlbrew install [opciones] /ruta/a/perl-5.14.0.tar.gz
perlbrew install [opciones] /ruta/al/directorio/de/checkout/de/perl5/git
perlbrew install [opciones] https://ejemplo.com/espejo/perl-5.12.3.tar.gz

Compila e instala la versión de perl deseada. El último argumento puede ser una cadena corta que designa una versión específica que se puede conocer a partir de la salida de "perlbrew available", una ruta a un archivo tarball precargado, una ruta a un checkout de git del repositorio perl5, o una URL a un archivo tarball.

El formato de <perl-release> se ve así:

perl-<versión>
perl-stable
perl-blead
<versión>
stable
blead

Los números de versión suelen tener el formato "5.x.xx", o "perl-5.xx.x-RCx" para las versiones candidatas.

La versión "stable" es un token especial que significa la última versión estable disponible en ese momento.

La versión "blead" es también un token especial que significa la última versión en el repositorio, que se descarga de esta URL específica independientemente de la configuración del espejo:

https://github.com/Perl/perl5/archive/blead.tar.gz

La versión especificada se descarga del sitio oficial de CPAN o del sitio espejo configurado previamente.

El número de versión solo, sin el prefijo "perl-", significa la versión oficial proporcionada por los responsables de perl5.

Opciones para el comando "install":

-f --force     Forzar la instalación
-j $n          Compilación y pruebas paralelas. ej. C<perlbrew install -j 5 perl-5.14

COMANDO: INSTALL-MULTIPLE

Uso: perlbrew install-multiple [opciones] <perl-version-1> <perl-version-2> ...

Compilar e instalar las versiones de perl dadas.

"install-multiple" acepta el mismo conjunto de opciones que el comando "install" más las siguientes:

--both $flavor       Donde $flavor es uno de C<thread>, C<multi>, C<ld>,
                     C<64int>, C<64all>, C<debug> y C<clang>.
                     Para cada versión de perl dada, instala dos
                     sabores, uno con la opción C<--$flavor> establecida
                     y el otro sin ella. C<--both> puede ser
                     pasado varias veces con diferentes valores
                     y en ese caso, se generan todas las
                     combinaciones posibles.
--common-variations  equivalente a C<--both thread --both ld --both 64int>
--all-variations     genera todas las combinaciones de sabores posibles
--append $string     Añade la cadena dada a los nombres generados

Por ejemplo:

perlbrew install-multiple 5.18.0 blead --both thread --both debug

Instala los siguientes perls:

perl-blead
perl-blead-debug
perl-blead-thread-multi
perl-blead-thread-multi-debug
perl-5.18.0
perl-5.18.0-debug
perl-5.18.0-thread-multi
perl-5.18.0-thread-multi-debug

(nota que el sabor "multi" se selecciona automáticamente porque "thread" lo requiere)

Otro ejemplo usando flags de compilación personalizados:

perlbrew install-multiple 5.18.0 --both thread -Doptimize='-O3' --append='-O3'

COMANDO: UNINSTALL

Uso:

perlbrew uninstall <nombre>

Alternativamente:

perlbrew delete <nombre>
perlbrew rm <nombre>

Desinstala la instalación de perl dada. El nombre es el nombre de la instalación como en la salida de `perlbrew list`. Esto elimina efectivamente la instalación de perl especificada y todas las bibliotecas asociadas a ella.

COMANDO: USE

Uso: perlbrew use [perl-<version> | <version> | <nombre>]

Usa la versión de perl dada en el shell actual. Esto no afectará a las shells recién abiertas.

Sin un parámetro, muestra la versión de perl actualmente en uso.

COMANDO: SWITCH

Uso: perlbrew switch [ <nombre> ]

Cambia a la versión dada y la establece como predeterminada para esta y todas las sesiones de terminal futuras.

Sin un parámetro, muestra la versión de perl actualmente seleccionada.

COMANDO: LIST

Uso: perlbrew list

Lista todas las instalaciones de perl dentro de la raíz de perlbrew especificada por la variable de entorno $PERLBREW_ROOT. Por defecto, el valor es "~/perl5/perlbrew".

Si hay bibliotecas asociadas a algunas instalaciones de perl, se incluirán como parte del nombre. Los elementos de salida en esta lista pueden ser el argumento en varios otros comandos.

COMANDO: AVAILABLE

Uso: perlbrew available [--all]

Lista las versiones de perl recientemente disponibles en CPAN.

Por defecto, se listan las últimas subversiones de cada versión estable.

Para obtener una lista de todos los perls publicados, incluidas las versiones de desarrollo y RC, ejecuta el comando con la opción "--all".

COMANDO: OFF

Uso: perlbrew off

Deshabilita temporalmente perlbrew en el shell actual. Efectivamente vuelve a habilitar el Perl del sistema predeterminado, sea cual sea.

Este comando solo funciona si agregas la declaración `source $PERLBREW_ROOT/etc/bashrc` en tu inicialización de shell (bashrc / zshrc).

COMANDO: SWITCH-OFF

Uso: perlbrew switch-off

Deshabilita permanentemente perlbrew. Usa el comando "switch" para volver a habilitarlo. Invoca el comando "use" para habilitarlo solo en el shell actual.

Vuelve a habilitar el Perl del sistema predeterminado, sea cual sea.

COMANDO: ALIAS

Uso: perlbrew alias [-f] create <nombre> <alias>

Crea un alias para la instalación llamada <nombre>.

Uso: perlbrew alias [-f] rename <old_alias> <new_alias>

Renombra el alias a un nuevo nombre.

Uso: perlbrew alias delete <alias>

Elimina el alias dado.

COMANDO: EXEC

Uso: perlbrew exec [opciones] <comando> <args...>

Opciones para el comando "exec":

--with perl-version,... - usa solo estas versiones
--min n.nnnnn           - versión mínima de perl
                            (el formato es el mismo que en 'use 5.012')
--max n.nnnnn           - versión máxima de perl
--halt-on-error         - detener en el primer estado de salida distinto de cero

Ejecuta el comando para cada instalación de perl, una por una.

Por ejemplo, ejecuta un programa Hola:

perlbrew exec perl -e 'print "Hello from $]\n"'

La salida se ve así:

perl-5.12.2
==========
Hello word from perl-5.012002
perl-5.13.10
==========
Hello word from perl-5.013010
perl-5.14.0
==========
Hello word from perl-5.014000

Observa que el comando no se ejecuta en paralelo.

Cuando se proporciona el argumento "--with", el comando solo se ejecutará con las instalaciones de perl especificadas. El siguiente comando instala el módulo Moose en perl-5.12, independientemente del perl actual:

perlbrew exec --with perl-5.12 cpanm Moose

Se pueden proporcionar múltiples nombres de instalación:

perlbrew exec --with perl-5.12,perl-5.12-debug,perl-5.14.2 cpanm Moo

Se dividen por espacios o comas. Cuando se usan espacios, se requiere citar toda la especificación como un solo argumento, pero entonces se pueden usar comas en los nombres de instalación:

perlbrew exec --with '5.12 5.12,debug 5.14.2@nobita @shizuka' cpanm Moo

Como se demostró anteriormente, el prefijo "perl-" se puede omitir, y también se pueden especificar nombres de bibliotecas. Los nombres de bibliotecas pueden aparecer sin un nombre de instalación de perl, en cuyo caso se asume que es el "perl actual".

Por el momento, cualquier nombre especificado que no se resuelva como un nombre de instalación real se ignora silenciosamente en la salida. Además, los estados de salida del comando no se propagan hacia atrás.

COMANDO: ENV

Uso: perlbrew env [ <nombre> ]

Comando de bajo nivel. Invoca este comando para ver la lista de variables de entorno que son establecidas por "perlbrew" mismo para la integración del shell.

La salida es algo similar a esto (si tu shell es bash/zsh):

export PERLBREW_ROOT=/Users/gugod/perl5/perlbrew
export PERLBREW_VERSION=0.31
export PERLBREW_PATH=/Users/gugod/perl5/perlbrew/bin:/Users/gugod/perl5/perlbrew/perls/current/bin
export PERLBREW_PERL=perl-5.14.1

Los usuarios de tcsh / csh deberían ver declaraciones 'setenv' en lugar de `export`.

COMANDO: SYMLINK-EXECUTABLES

Uso: perlbrew symlink-executables [ <nombre> ]

Comando de bajo nivel. Este comando se utiliza para crear el enlace simbólico ejecutable "perl" hacia, por ejemplo, "perl5.13.6". Esto solo es necesario para versiones de desarrollo de perls.

No necesitas hacer esto a menos que hayas estado usando una versión antigua de perlbrew para instalar perls, y te encuentres confundido porque el perl que acabas de instalar parece faltar después de invocar `use` o `switch`. perlbrew cambia su diseño de instalación desde la versión 0.11, lo que genera enlaces simbólicos a ejecutables de una mejor manera.

Si acabas de actualizar perlbrew (desde la versión 0.11 o anterior) y "perlbrew switch" no funcionó después de cambiar a una versión de desarrollo de perl, por ejemplo, perl-5.13.6, ejecuta este comando:

perlbrew symlink-executables perl-5.13.6

Esto crea esencialmente este enlace simbólico:

${PERLBREW_ROOT}/perls/perl-5.13.6/bin/perl
-> ${PERLBREW_ROOT}/perls/perl-5.13.6/bin/perl5.13.6

Los perls recién instalados, ya sean versiones de desarrollo o no, no necesitan tratamiento manual con este comando.

COMANDO: INSTALL-CPANM

COMANDO: INSTALL-CPANM

Uso: perlbrew install-cpanm

Instala el ejecutable independiente "cpanm" en "$PERLBREW_ROOT/bin".

Para más justificación sobre la existencia de este comando, lee https://perlbrew.pl/Perlbrew-and-Friends.html

Uso: perlbrew install-cpm

Instala el ejecutable independiente "cpm" en "$PERLBREW_ROOT/bin".

COMANDO: INSTALL-PATCHPERL

Uso: perlbrew install-patchperl

Instala el ejecutable independiente "patchperl" en "$PERLBREW_ROOT/bin". Esto se invoca automáticamente si tu instalación de perlbrew se realizó con el instalador, pero no con cpan.

Para más justificación sobre la existencia de este comando, lee https://perlbrew.pl/Perlbrew-and-Friends.html

COMANDO: SELF-UPGRADE

Uso: perlbrew self-upgrade

Este comando actualiza Perlbrew a su última versión.

COMANDO: SELF-INSTALL

Uso: perlbrew self-install

AVISO: No deberías necesitar ejecutar este comando en tu rutina diaria.

Este comando instala perlbrew en sí mismo en "$PERLBREW_ROOT/bin". Está destinado a ser utilizado por el instalador de perlbrew. Sin embargo, podrías hacer manualmente lo siguiente para reinstalar solo el ejecutable "perlbrew":

curl https://raw.githubusercontent.com/gugod/App-perlbrew/master/perlbrew -o perlbrew
perl ./perlbrew self-install

Es ligeramente diferente de ejecutar el instalador de perlbrew porque "patchperl" no se instala en este caso.

COMANDO: CLEAN

Uso: perlbrew clean

Elimina todas las tarballs de Perl y directorios de compilación descargados previamente.

COMANDO: VERSION

Uso: perlbrew version

Muestra la versión de perlbrew.

COMANDO: LIB

Uso: perlbrew lib <acción> <nombre-lib>

perlbrew lib list
perlbrew lib create <nombre-lib>
perlbrew lib delete <nombre-lib>

El comando `lib` se utiliza para manipular las raíces de local::lib dentro de las instalaciones de perl. Efectivamente, es similar a `perl -Mlocal::lib=/ruta/a/nombre-lib`, pero un poco más que eso.

Un nombre de lib puede ser un nombre corto, que contiene caracteres alfanuméricos, como 'awesome', o un nombre completo, prefijado por el nombre de una instalación de perl y un signo '@', por ejemplo, 'perl-5.14.2@awesome'.

Aquí hay algunos breves ejemplos para invocar el comando `lib`:

# Crear lib perl-5.12.3@shizuka
perlbrew lib create perl-5.12.3@shizuka
# Crear lib perl-5.14.2@nobita y perl-5.14.2@shizuka
perlbrew use perl-5.14.2
perlbrew lib create nobita
perlbrew lib create shizuka
# Ver la lista de objetivos de uso/cambio
perlbrew list
# Activar una lib en el shell actual
perlbrew use perl-5.12.3@shizuka
perlbrew use perl-5.14.2@nobita
perlbrew use perl-5.14.2@shizuka
# Activar una lib como predeterminada
perlbrew switch perl-5.12.3@shizuka
perlbrew switch perl-5.14.2@nobita
perlbrew switch perl-5.14.2@shizuka
# Eliminar lib perl-5.14.2@nobita y perl-5.14.2@shizuka
perlbrew use perl-5.14.2
perlbrew lib delete nobita
perlbrew lib delete shizuka
# Eliminar lib perl-5.12.3@shizuka
perlbrew lib delete perl-5.12.3@shizuka

Los nombres cortos de lib son locales al perl actual. Un nombre de lib 'nobita' puede referirse a 'perl-5.12.3@nobita' o 'perl-5.14.2@nobita', el que esté activado en el shell actual.

Al usar o cambiar a una lib, siempre proporciona el nombre largo. Una regla simple: el argumento para el comando `use` o `switch` debe aparecer en la salida del comando `perlbrew list`.

COMANDO: UPGRADE-PERL

Uso: perlbrew upgrade-perl

Ejecutar este comando actualiza el perl actualmente activado a sus hermanos de última versión liberada. Si tienes un shell con 5.32.0 activado, lo actualiza a 5.32.1.

Las versiones menores de Perl (por ejemplo, 5.x.*) son binariamente compatibles entre sí, por lo que este comando te ofrece la capacidad de actualizar entornos de perlbrew antiguos en el lugar.

COMANDO: DOWNLOAD

Uso:
perlbrew download <version-perl>

Ejemplos:
perlbrew download perl-5.14.2
perlbrew download perl-5.16.1
perlbrew download perl-5.17.3

Descarga el archivo tar de distribución de perl de la versión especificada en el directorio "$PERLBREW_ROOT/dists/".

El argumento "version-perl" debe ser uno de los elementos del comando "perlbrew available".

COMANDO: LIST-MODULES

Uso:
perlbrew list-modules

Lista todos los módulos cpan instalados para el perl actual.

Este comando se puede usar junto con `perlbrew exec` para migrar tu instalación de módulos a un perl diferente. El siguiente comando reinstala todos los módulos bajo perl-5.16.0:

perlbrew list-modules | perlbrew exec --with perl-5.16.0 cpanm

Ten en cuenta que esto instala las versiones *más recientes* de los módulos Perl en el nuevo perl, que no son necesariamente las *mismas* versiones de módulos que tenías instaladas anteriormente.

COMANDO: CLONE-MODULES

Uso:

perlbrew clone-modules [opciones] <destino>
perlbrew clone-modules [opciones] <origen> <destino>

Opciones:

--notest    Omitir todas las pruebas de módulos

Este comando reinstala todos los módulos CPAN encontrados de una instalación a otra. Por ejemplo, esto lista todos los módulos bajo '5.26.1' y los reinstala bajo '5.27.7':

perlbrew clone-modules 5.26.1 5.27.7

El argumento "origen" es opcional y por defecto es el activado actualmente. Sin embargo, si no hay ninguno activado (perlbrew está desactivado), es un error.

Ten en cuenta que esto no garantiza que las versiones de los módulos permanezcan iguales en el destino.

COMANDO: MAKE-SHIM

Uso:

perlbrew make-shim <programa>
perlbrew make-shim -o <nombre-shim> <programa>
perlbrew make-shim --output <nombre-shim> <programa>

Este comando produce un archivo ejecutable en el directorio actual llamado "programa", o "nombre-shim" si se proporciona después de "--output" (o "-o" para abreviar). La salida es un envoltorio de shell, un shim, del programa nombrado dentro del entorno perlbrew actual.

Cuando se ejecuta el shim, el "programa" original se ejecuta con todas las variables de entorno relevantes establecidas para el entorno perlbrew en el que está instalado, independientemente de qué entorno perlbrew esté actualmente activado. El shim también se puede mover a diferentes directorios y, como el convencional "~/.local/bin", por lo que siempre está disponible.

Por ejemplo, puedes encontrar "tldr" de App::tldr una herramienta útil y decidir instalarla dentro de tu entorno de trabajo diario:

perlbrew use perl-5.36.1
cpm install -g App::tldr

Pero cuando ocasionalmente tienes que cambiar a un entorno diferente, "PATH" se modificará y el comando "tldr" desaparecerá, y ese es el resultado esperado:

perlbrew use perl-5.18.4
tldr perl  #=> error: comando no encontrado

Sería bueno si "tldr" pudiera hacerse universalmente disponible. Una forma de mitigar tales necesidades es preparar la instalación del programa "tldr" fuera de "PERLBREW_ROOT", mientras aún se utiliza el entorno perlbrew para ejecutarlo.

Por ejemplo, prepara un directorio convencional "~/.local/bin" y ponlo en "PATH", luego:

perlbrew use perl-5.36.1
cd /tmp
perlbrew make-shim tldr
mv /tmp/tldr ~/.local/bin/tldr

Este "~/.local/bin/tldr" es un envoltorio de shell del programa real "tldr", y activa internamente el entorno perlbrew "perl-5.36.1". Ejecutar el shim de tldr ejecutará entonces siempre el "tldr" real, sin importar qué entorno perlbrew esté activado, o incluso si perlbrew está desactivado. Los únicos requisitos son que el entorno perlbrew "perl-5.36.1" y la instalación de "App::tldr" deben permanecer.

COMANDO: MAKE-PP

Uso:

perlbrew make-pp -i <ruta> -o <ruta>
perlbrew make-pp --input <ruta> --output <ruta>

Este comando toma la ruta de un programa perl (la entrada) y produce una versión empaquetada con PAR de ese programa en la ruta especificada (la salida). Esencialmente, es un envoltorio de `pp` de PAR::Packer, de ahí el nombre.

Esto requiere que el entorno perlbrew actual tenga instalados PAR y PAR::Packer primero. De lo contrario, `make-pp` falla. Además, si el perl actual no es un perl administrado por perlbrew

COMANDO: MAKE-PP

Este comando crea un ejecutable binario independiente que puede ser ejecutado en diferentes máquinas (con el mismo sistema operativo y arquitectura). No es una solución perfecta para determinar las dependencias de tiempo de ejecución de un programa arbitrario, ya que empaqueta más de lo estrictamente necesario.

El archivo producido es un ejecutable binario independiente que contiene:

1. El programa perl de entrada.
2. El runtime de perl.
3. Todas las bibliotecas core de perl del perl actual.
4. Toda la biblioteca del sitio (site lib).
5. Toda la biblioteca local (gestionada por el comando `perlbrew lib`), si está activa.

Se espera que el ejecutable pueda ser ejecutado en una máquina diferente con el mismo sistema operativo y arquitectura.

Cabe destacar que este enfoque es un exceso de celo para empaquetar un solo programa, ya que definitivamente empaquetará mucho más que la lista exacta de dependencias de tiempo de ejecución del programa nombrado. "make-pp" está pensado como una solución perezosa para un problema no trivial de determinar perfectamente las dependencias de tiempo de ejecución de un programa arbitrario.
