NOMBRE

perlcygwin - Perl para Cygwin

SINOPSIS

Este documento te ayudará a configurar, compilar, probar e instalar Perl en Cygwin. Este documento también describe las características de Cygwin que afectarán el comportamiento de Perl en tiempo de ejecución.

NOTA: Hay paquetes de Perl precompilados disponibles para Cygwin y una versión de Perl se proporciona en la instalación normal de Cygwin. Si no necesitas personalizar la configuración, considera usar uno de esos paquetes.

REQUISITOS PREVIOS PARA COMPILAR PERL EN CYGWIN

Cygwin = GNU+Cygnus+Windows (No te vayas de UNIX sin él)

Las herramientas de Cygwin son puertos de las populares herramientas de desarrollo GNU para plataformas Win32. Funcionan gracias a la biblioteca Cygwin que proporciona las llamadas al sistema y el entorno UNIX que estos programas esperan. Puedes encontrar más información sobre este proyecto en:

https://www.cygwin.com/

Se requiere una versión reciente de la red o comercial de Cygwin.

En el momento en que se actualizó por última vez este documento, Cygwin 3.0.7 era la versión actual.

Configuración de Cygwin

Mientras compilas Perl, pueden ser necesarios algunos cambios en tu configuración de Cygwin para que Perl compile correctamente. Estos cambios **no** son necesarios para el uso normal de Perl.

NOTA: Los binarios que se compilen se ejecutarán en todas las versiones de Win32. No dependen de tu sistema anfitrión ni de tu configuración de Cygwin (montajes binarios/de texto, cygserver). Las únicas dependencias provienen de nombres de ruta codificados como /usr/local. Sin embargo, tu sistema anfitrión y tu configuración de Cygwin afectarán el comportamiento de Perl en tiempo de ejecución (ver "PRUEBA").

  • "PATH"

    Establece la variable de entorno "PATH" para que Configure encuentre las versiones de Cygwin de los programas. Cualquier directorio de Windows no necesario debe eliminarse o moverse al final de tu "PATH".

  • nroff

    Si no tienes nroff (que forma parte del paquete groff), Configure **no** te pedirá que instales páginas man.

CONFIGURAR PERL EN CYGWIN

Las opciones por defecto recopiladas por Configure con la ayuda de hints/cygwin.sh compilarán un Perl que admita carga dinámica (lo que requiere un cygperl5_16.dll compartido).

Esto ejecutará Configure y mantendrá un registro:

./Configure 2>&1 | tee log.configure

Si estás dispuesto a aceptar todas las opciones por defecto, ejecuta Configure con -de. Sin embargo, hay varias personalizaciones útiles disponibles.

Eliminar binarios de Perl en Cygwin

Es posible eliminar los ejecutables y DLLs creados por el proceso de compilación. Los binarios resultantes serán significativamente más pequeños. Si deseas que los binarios se eliminen, puedes agregar una opción -s cuando Configure te lo pida,

¿Alguna bandera adicional de ld (NO incluyendo bibliotecas)? [ninguna] -s
¿Alguna bandera especial para pasar a g++ para crear una biblioteca cargada dinámicamente?
[ninguna] -s
¿Alguna bandera especial para pasar a gcc para usar enlace dinámico? [ninguna] -s

o puedes editar hints/cygwin.sh y descomentar las variables relevantes cerca del final del archivo.

Bibliotecas Opcionales para Perl en Cygwin

Varias funciones y módulos de Perl dependen de la existencia de algunas bibliotecas opcionales. Configure las encontrará si están instaladas en uno de los directorios listados como utilizados para búsquedas de bibliotecas. Los paquetes precompilados para la mayoría de estas están disponibles en el instalador de Cygwin.

  • "-lcrypt"

    El paquete crypt distribuido con Cygwin es un puerto crypt DES de 56 bits compatible con Linux de Corinna Vinschen.

    Alternativamente, las bibliotecas crypt en GNU libc han sido portadas a Cygwin.

    A partir de libcrypt 1.3 (marzo de 2016), necesitarás instalar el paquete libcrypt-devel para que Configure detecte crypt().

  • "-lgdbm_compat" ("use GDBM_File")

    GDBM está disponible para Cygwin.

    NOTA: La biblioteca GDBM solo funciona en particiones NTFS.

  • "-ldb" ("use DB_File")

    BerkeleyDB está disponible para Cygwin.

    NOTA: La biblioteca BerkeleyDB solo funciona completamente en particiones NTFS.

  • "cygserver" ("use IPC::SysV")

    Un puerto de SysV IPC está disponible para Cygwin.

    NOTA: Esto **no** ha sido probado exhaustivamente. En particular, "d_semctl_semun" está indefinido porque falla una prueba de Configure. También crea una dependencia en tiempo de compilación ya que perl.h incluye <sys/ipc.h> y <sys/sem.h> (que serán necesarios en el futuro al compilar módulos CPAN). ¡ACTUALMENTE NO SOPORTADO!

  • "-lutil"

    Incluido con el netrelease estándar de Cygwin está el paquete inetutils que incluye libutil.a.

Opciones en tiempo de configuración para Perl en Cygwin

El documento INSTALL describe varias opciones de tiempo de configuración. Algunas de estas funcionarán con Cygwin, otras aún no son posibles. Además, algunas de estas son experimentales. Puedes seleccionar una opción cuando Configure te la pida o puedes definir (desdefinir) símbolos en la línea de comandos.

  • "-Uusedl"

    Desdefinir este símbolo fuerza a Perl a compilarse estáticamente.

  • "-Dusemymalloc"

    Por defecto, Perl no usa el malloc() incluido con el código fuente de Perl, porque era más lento y no completamente seguro para hilos. Si quieres forzar a Perl a compilarse con el antiguo -Dusemymalloc, define esto.

  • "-Uuseperlio"

    Desdefinir este símbolo deshabilita la abstracción PerlIO. PerlIO es ahora el valor por defecto; no se recomienda deshabilitar PerlIO.

  • "-Dusemultiplicity"

    La multiplicidad es necesaria al incrustar Perl en un programa C y usar más de una instancia de intérprete. Esto solo es necesario cuando compilas un perl no multi-hilo con "-Uuseithreads".

  • "-Uuse64bitint"

    Por defecto, Perl utiliza enteros de 64 bits. Si quieres usar enteros de 32 bits más pequeños, define este símbolo.

  • "-Duselongdouble"

    gcc soporta `long double` (12 bytes). Sin embargo, se necesitan varias funciones matemáticas `long double` adicionales para usarlos dentro de Perl ({atan2, cos, exp, floor, fmod, frexp, isnan, log, modf, pow, sin, sqrt}l, strtold). Estos **no** están todavía disponibles con newlib, la libc de Cygwin.

  • "-Uuseithreads"

    Define este símbolo si quieres un perl más rápido no multi-hilo.

  • "-Duselargefiles"

    Cygwin utiliza enteros de 64 bits para cálculos internos de tamaño y posición, esto será detectado y definido correctamente por Configure.

  • "-Dmksymlinks"

    Usa esto para compilar perl fuera del árbol de fuentes. Los detalles se pueden encontrar en el documento INSTALL. Esta es la forma recomendada de compilar perl desde fuentes.

HACER EN CYGWIN

El documento INSTALL describe las opciones de compilación. Las principales opciones son "make" y "make install".

Puedes compilar todos los ejecutables y bibliotecas de Perl ejecutando simplemente "make".

Puedes instalar Perl en el directorio que le dijiste a Configure. Por defecto, este es "/usr/local".

make install

PROBAR EN CYGWIN

La mayoría de las pruebas escritas en t/op/ y t/porting/ deben funcionar bien con Cygwin.

Sin embargo, hay varias excepciones notables que se describen a continuación.

Pruebas de archivos de descriptores de archivos

Las pruebas "stdio.t" y "seek.t" deberían funcionar sin problemas en la mayoría de las versiones de Cygwin. Tienen la extraña característica de no advertir al usuario si un archivo no es buscable (como lo haría Unix).

Pruebas de enlaces simbólicos y duros

Las pruebas de enlaces simbólicos y duros pueden fallar si los nombres de archivo contienen espacios.

Pruebas de archivos con nombres de caracteres especiales

Las pruebas de archivos con nombres que contienen espacios o caracteres especiales pueden fallar si estás usando el instalador de Cygwin o si has configurado tus montajes de forma que no se puedan crear nombres de archivo como se describe en la sección "Configuración de Cygwin".

Pruebas de redes

Las pruebas de red que esperan que las llamadas al sistema se comporten como en Unix pueden fallar en Cygwin. Esto se debe a que WinSock se comporta de manera diferente a las bibliotecas de red de Unix.

Pruebas de procesos en segundo plano

Las pruebas que implican la ejecución de programas en segundo plano podrían no funcionar como se espera.

Otras pruebas que pueden fallar

Las pruebas relacionadas con la creación de archivos temporales que utilizan "tmpnam()" pueden fallar porque "tmpnam()" no está implementado en Cygwin.

Las pruebas relacionadas con la creación de archivos temporales pueden fallar si tu directorio temporal está en una unidad de red y el uso compartido de archivos está deshabilitado.

La prueba "realloc.t" fallará si usas Cygwin <= 1.3.10, porque la biblioteca C en esta versión falla de forma irregular cuando se llama a "realloc()" en un puntero nulo.

CARACTERÍSTICAS DE PERL EN CYGWIN

Comportamiento de archivos y directorios

Cygwin te permite usar nombres de archivo estilo Unix, pero algunas cosas son un poco diferentes a Unix.

  • Los nombres de archivo y directorio no distinguen entre mayúsculas y minúsculas.
  • Los nombres de archivo y directorio pueden contener espacios.
  • Cygwin convierte automáticamente las rutas de estilo Unix a rutas de estilo Windows y viceversa.
  • Cygwin puede emular enlaces simbólicos y duros.
  • El carácter de barra invertida "\" se utiliza como separador de directorios en Windows. Cygwin también puede usarlo.

Comportamiento del sistema de archivos en Cygwin

El comportamiento del sistema de archivos en Cygwin puede verse afectado por la forma en que montes tus unidades. Puedes montar unidades como binarias o de texto.

Si montas una unidad como binaria, los archivos se tratarán como secuencias de bytes. Si la montas como de texto, Cygwin realizará conversiones de fin de línea (CRLF a LF y viceversa).

Puedes ver tus montajes actuales ejecutando el comando "mount" en la línea de comandos de Cygwin. Puedes montar tus unidades ejecutando el comando "mount" con las opciones adecuadas. Por ejemplo, para montar la unidad C: como binaria, puedes usar:

mount -b c:/ /cygdrive/c

Para montar la unidad C: como texto, usarías:

mount c:/ /cygdrive/c

Entorno de ejecución

Perl se ejecutará en el entorno Cygwin, lo que significa que tendrá acceso a las herramientas y bibliotecas de Cygwin. Esto también significa que puede haber algunas diferencias en el comportamiento en comparación con Perl en Unix.

Por ejemplo, las rutas de archivo pueden necesitar ser convertidas entre el estilo Unix y el estilo Windows. El módulo "Win32::ShellQuote" puede ser útil para esto.

Utilización de servicios de Windows

Perl en Cygwin no tiene acceso directo a los servicios de Windows. Sin embargo, puedes usar el módulo "Win32::API" para llamar a funciones de la API de Windows directamente.

PRUEBA EN CYGWIN

Hay dos pasos para ejecutar el conjunto de pruebas:

make test 2>&1 | tee log.make-test
cd t; ./perl harness 2>&1 | tee ../log.harness

Las mismas pruebas se ejecutan ambas veces, pero se proporciona más información al ejecutar como "./perl harness", y puedes ejecutar las pruebas en paralelo especificando en su lugar

cd t; TEST_JOBS=n ./perl harness 2>&1 | tee ../log.harness

donde n es el número máximo de pruebas a ejecutar simultáneamente.

Los resultados de las pruebas varían dependiendo de tu sistema anfitrión y de tu configuración de Cygwin. Si una prueba puede pasar en alguna configuración de Cygwin, siempre se intenta y los fallos de prueba explicables se documentan. Es posible que Perl pase todas las pruebas, pero es más probable que algunas pruebas fallen por alguna de las razones que se enumeran a continuación.

Permisos de Archivo en Cygwin

Los permisos de archivos UNIX se basan en conjuntos de bits de modo para {lectura,escritura,ejecución} para cada {usuario,grupo,otro}. Por defecto, Cygwin solo rastrea el atributo de solo lectura de Win32 representado como el bit de escritura del usuario de archivos de UNIX (los archivos son siempre legibles, los archivos son ejecutables si tienen una extensión .{com,bat,exe} o comienzan con , los directorios son siempre legibles y ejecutables). En WinNT con la configuración de CYGWIN de ntea, los bits de modo adicionales se almacenan como atributos extendidos de archivo. En WinNT con la configuración predeterminada de CYGWIN de ntsec, los permisos usan los descriptores de seguridad y las listas de control de acceso estándar de WinNT. Sin una de estas opciones, estas pruebas fallarán (lista no actualizada aún):

No uses NDBM_File u ODBM_File en sistemas de archivos FAT. Se pueden compilar en un sistema de archivos FAT, pero muchas pruebas fallarán:

Características específicas del puerto Cygwin

Portabilidad de Scripts en Cygwin

Cygwin hace un trabajo excepcional al proporcionar semántica similar a UNIX sobre sistemas Win32. Sin embargo, además de los elementos mencionados anteriormente, hay algunas diferencias que debes conocer. Esta es una guía muy breve sobre portabilidad, puedes encontrar más información en la documentación de Cygwin.

  • Nombres de ruta

    Los nombres de ruta de Cygwin están separados por barras (/), también se soportan los Códigos de Nombres Universales (//UNC). Desde cygwin-1.7, no se deben usar nombres de ruta no POSIX. Los nombres pueden contener todos los caracteres imprimibles.

    Los nombres de archivo no distinguen entre mayúsculas y minúsculas, pero conservan la capitalización. Un nombre de ruta que contiene una barra invertida o una letra de unidad es un nombre de ruta Win32, y no está sujeto a las traducciones aplicadas a los nombres de ruta de estilo POSIX, pero cygwin te advertirá, así que es mejor convertirlos a POSIX.

    Para la conversión tenemos Cygwin::win_to_posix_path() y Cygwin::posix_to_win_path().

    Desde cygwin-1.7, los nombres de ruta están codificados en UTF-8.

  • Texto/Binario

    Desde cygwin-1.7, los montajes de texto (textmounts) están obsoletos y se desaconsejan firmemente.

    Cuando se abre un archivo, está en modo texto o binario. En modo texto, un archivo está sujeto a traducciones CR/LF/Ctrl-Z. Con Cygwin, el modo predeterminado para un open() está determinado por el modo del montaje que subyace al archivo. Ver "Cygwin::is_binmount"(). Perl proporciona una función binmode() para establecer el modo binario en archivos que de otro modo se tratarían como texto. sysopen() con el indicador "O_TEXT" establece el modo texto en archivos que de otro modo se tratarían como binarios:

    sysopen(FOO, "bar", O_WRONLY|O_CREAT|O_TEXT)

    lseek(), tell() y sysseek() solo funcionan con archivos abiertos en modo binario.

    El tema texto/binario se cubre en detalle en la documentación de Cygwin.

  • PerlIO

    PerlIO anula el comportamiento predeterminado de Texto/Binario de Cygwin. Un archivo siempre se tratará como binario, independientemente del modo del montaje en el que resida, al igual que en UNIX. Por lo tanto, la traducción CR/LF debe solicitarse en la llamada open() de esta manera:

    open(FH, ">:crlf", "out.txt");

    que realizará la conversión de LF a CR/LF en la salida, o en la configuración del entorno (añade esto a tu .bashrc):

    export PERLIO=crlf

    que cargará la capa PerlIO crlf que realiza la conversión de LF a CRLF en cada salida generada por perl.

  • .exe

    Las funciones stat(), lstat() y readlink() de Cygwin hacen que la extensión .exe sea transparente buscando foo.exe cuando se solicita foo (a menos que también exista un foo). Cygwin no requiere una extensión .exe, pero gcc la añade automáticamente al compilar un programa. Sin embargo, al acceder a un ejecutable como un archivo normal (por ejemplo, cp en un makefile) el .exe no es transparente. El programa install incluido con Cygwin añade automáticamente un .exe cuando es necesario.

  • IDs de proceso Cygwin vs. Windows

    Los procesos Cygwin tienen su propio pid, que es diferente del pid de Windows subyacente. La mayoría de las funciones Proc compatibles con POSIX esperan el pid de cygwin, pero varias funciones de Win32::Process esperan el winpid. Por ejemplo, $$ es el pid de cygwin de /usr/bin/perl, que no es el winpid. Usa Cygwin::pid_to_winpid() y Cygwin::winpid_to_pid() para traducir entre ellos.

  • Errores Cygwin vs. Windows

    En Cygwin, $^E es lo mismo que $!. Al usar funciones de la API Win32, usa Win32::GetLastError() para obtener el último error de Windows.

  • Errores de rebase en fork o system

    Usar fork() o system() hacia otro perl después de cargar múltiples dll puede resultar en un conflicto de dirección base de DLL. El error interno de cygwin se parece a lo siguiente:

    0 [main] perl 8916 child_info_fork::abort: data segment start:
parent (0xC1A000) != child(0xA6A000)

    o:

    183 [main] perl 3588 C:\cygwin\bin\perl.exe: *** fatal error -
unable to remap C:\cygwin\bin\cygsvn_subr-1-0.dll to same address
as parent(0x6FB30000) != 0x6FE60000 46 [main] perl 3488 fork: child
3588 - died waiting for dll loading, errno11

    Ver https://cygwin.com/faq/faq.html#faq.using.fixing-fork-failures. Ayuda si no se cargan demasiadas DLL en memoria, por lo que el espacio de direcciones disponible es mayor, por ejemplo, detener el MS Internet Explorer podría ayudar.

    +Usar las utilidades de rebase para resolver las direcciones de DLL en conflicto. El paquete rebase está incluido en la configuración de Cygwin. Usa setup.exe de https://cygwin.com/install.html para instalarlo.

    1. mata todos los procesos perl y ejecuta
    "</bin/find <dir" -xdev -name \*.dll | /bin/rebase -OT ->> o

    2. mata todos los procesos y servicios de cygwin, y ejecuta setup.exe.

  • Misceláneos

    El bloqueo de archivos usando el comando "F_GETLK" para fcntl() es un stub que devuelve "ENOSYS".

    La implementación de chroot() de Cygwin tiene lagunas (no puede restringir el acceso a archivos por programas Win32 nativos).

    La edición en el lugar "perl -i" de archivos no funciona sin hacer una copia de seguridad del archivo que se está editando "perl -i.bak" debido a restricciones de ventana, por lo tanto Perl añade el sufijo ".bak" automáticamente si usas "perl -i" sin especificar una extensión de copia de seguridad.

Métodos precompilados:

"Cwd::cwd"
Devuelve el directorio de trabajo actual.
"Cygwin::pid_to_winpid"
"Cygwin::pid_to_winpid"
Traduce un pid de Cygwin al pid de Windows correspondiente (que puede ser o no el mismo).
"Cygwin::winpid_to_pid"
Traduce un pid de Windows al pid de Cygwin correspondiente (si existe).
"Cygwin::win_to_posix_path"
Traduce una ruta de Windows a la ruta de Cygwin correspondiente respetando los puntos de montaje actuales. Con un segundo argumento no nulo, devuelve una ruta absoluta. Los caracteres de doble byte no se traducirán.
"Cygwin::posix_to_win_path"
Traduce una ruta de Cygwin a la ruta de Cygwin correspondiente respetando los puntos de montaje actuales. Con un segundo argumento no nulo, devuelve una ruta absoluta. Los caracteres de doble byte no se traducirán.
Cygwin::mount_table()
Devuelve una matriz de [mnt_dir, mnt_fsname, mnt_type, mnt_opts]. 
perl -e 'for $i (Cygwin::mount_table) {print join(" ",@$i),"\n";}'
/cygdrive/c c: system binmode,noumount
/cygdrive/d d: system binmode,noumount
/cygdrive/e e: system binmode,noumount
"Cygwin::mount_flags"
Devuelve el tipo de montaje y las banderas para un punto de montaje especificado. Una cadena separada por comas de mntent->mnt_type (siempre "system" o "user"), luego los mntent->mnt_opts, donde el primero es siempre "binmode" o "textmode". 
system|user,binmode|textmode,exec,cygexec,cygdrive,mixed,
notexec,managed,nosuid,devfs,proc,noumount

Si el argumento es "/cygdrive", entonces solo se devuelven la configuración del montaje del volumen y el prefijo del montaje cygdrive.

Los montajes de usuario anulan los montajes del sistema.

$ perl -e 'print Cygwin::mount_flags "/usr/bin"'
system,binmode,cygexec
$ perl -e 'print Cygwin::mount_flags "/cygdrive"'
binmode,cygdrive,/cygdrive
"Cygwin::is_binmount"
Devuelve verdadero si la ruta de Cygwin dada está montada en modo binario, falso si la ruta está montada en modo texto.
"Cygwin::sync_winenv"
Cygwin no inicializa todas las variables de entorno Win32 originales. Véase la parte inferior de esta página https://cygwin.com/cygwin-ug-net/setup-env.html para "Entorno Win32 restringido".

Ciertos programas Win32 llamados desde programas Cygwin pueden necesitar alguna variable de entorno, como por ejemplo ADODB necesita %COMMONPROGRAMFILES%. Llame a Cygwin::sync_winenv() para copiar todas las variables de entorno Win32 a su proceso y tenga en cuenta que Cygwin advertirá sobre cada encuentro de rutas no POSIX.

INSTALAR PERL EN CYGWIN

Esto instalará Perl, incluyendo las páginas de man.

make install 2>&1 | tee log.make-install

NOTA: Si "STDERR" se redirige, "make install" no le pedirá que instale perl en /usr/bin.

Puede que necesite ser Administrador para ejecutar "make install". Si no lo es, debe tener acceso de escritura a los directorios en cuestión.

La información sobre cómo instalar la documentación de Perl en formato HTML se puede encontrar en el documento INSTALL.

NAME

perlcygwin - Perl module for Cygwin specific functionality

SYNOPSIS

use Cygwin;

PREREQUISITES FOR COMPILING PERL ON CYGWIN

Before you can compile Perl on Cygwin you need the Cygwin development tools. These are the GCC compiler, make, the C library headers and static libraries. You will also need the Perl development headers/libraries and the headers/libraries for any modules you wish to compile.

The Perl module is provided with the Cygwin Perl installation. The files are:

lib/Cygwin.pm
lib/Cygwin.pod
lib/Pod/Simple/t/perlcyg.pod
lib/Pod/Simple/t/perlcygo.txt
lib/Pod/Simple/t/perlfaq.pod
lib/Pod/Simple/t/perlfaqo.txt
lib/User/grent.t
lib/User/pwent.t

CONFIGURE PERL ON CYGWIN

Run sh configure.bat. This is a DOS batch file that will configure Perl to run on Cygwin.

It will automatically determine the correct settings for your system.

MAKE ON CYGWIN

Run make. This will compile Perl and all its modules.

TEST ON CYGWIN

Run make test. This will run all the installed tests and report any failures.

Specific features of the Cygwin port

The Cygwin port of Perl includes a module called Cygwin.pm. This module provides access to Cygwin-specific functionality, such as manipulating Windows access tokens and security contexts.

The following functions are exported by default:

cygwin_get_token()
Retrieves the access token for the current process.
cygwin_set_token($token)
Sets the access token for the current process.
cygwin_get_sid()
Retrieves the security identifier (SID) for the current user.
cygwin_get_primary_group()
Retrieves the primary group SID for the current user.

The Cygwin.pm module also provides access to the following functions:

cygwin_lookup_account_name($name)
Looks up the SID for a given account name.
cygwin_lookup_account_sid($sid)
Looks up the account name for a given SID.
cygwin_lookup_primary_group($sid)
Looks up the primary group name for a given SID.
cygwin_check_token_membership($token, $sid)
Checks if a given SID is a member of the specified token.

INSTALL PERL ON CYGWIN

Run make install. This will install Perl and all its modules into your Cygwin environment.

BUGS ON CYGWIN

Support for swapping real and effective user and group IDs is incomplete. On WinNT Cygwin provides setuid(), seteuid(), setgid() and setegid(). However, additional Cygwin calls for manipulating WinNT access tokens and security contexts are required.
