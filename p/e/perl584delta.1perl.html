NOMBRE

perl584delta - qué hay de nuevo en perl v5.8.4

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.8.3 y la versión 5.8.4.

Cambios Incompatibles

Se han corregido muchos errores menores. Los scripts que dependan casualmente de un comportamiento previamente erróneo considerarán estas correcciones como cambios incompatibles :-). Se aconseja realizar pruebas de aceptación suficientes en esta versión para asegurarse de que esto no le afecta antes de poner esta versión en producción.

La salida de diagnóstico de Carp ha cambiado ligeramente, para añadir un espacio después de la coma entre argumentos. Esto hace que sea mucho más fácil para herramientas como los navegadores web envolverla, pero podría confundir a cualquier herramienta automática que realice un análisis detallado de la salida de Carp.

La salida interna de volcado (dump) ha mejorado, de modo que los caracteres no imprimibles como la nueva línea y el retroceso se muestran en notación "\x", en lugar de octal. Esto podría confundir a herramientas no robustas que analicen la salida de módulos como Devel::Peek.

Mejoras del Núcleo

Envoltura de Malloc

Perl ahora puede compilarse para detectar intentos de asignar trozos de memoria patológicamente grandes. Anteriormente, tales asignaciones sufrían un desbordamiento de enteros durante los cálculos de tamaño, causando una mala asignación, lo que bloqueaba perl y teóricamente podría usarse para ataques de "stack smashing". La envoltura está habilitada por defecto en plataformas donde sabemos que funciona (la mayoría de las configuraciones de AIX, BSDi, Darwin, DEC OSF/1, FreeBSD, HP/UX, GNU Linux, OpenBSD, Solaris, VMS y la mayoría de los compiladores de Win32) y está deshabilitada por defecto en otras plataformas.

Base de Datos de Caracteres Unicode 4.0.1

La copia de la Base de Datos de Caracteres Unicode incluida en Perl 5.8 se ha actualizado de la 4.0.0 a la 4.0.1.

suidperl menos inseguro

Paul Szabo ha analizado y parcheado "suidperl" para eliminar las inseguridades conocidas existentes. Actualmente no se conocen agujeros en "suidperl", pero la experiencia previa demuestra que no podemos estar seguros de que estos fueran los últimos. Ya no puede invocar el perl set uid directamente, por lo que para preservar la compatibilidad con scripts que invocan #!/usr/bin/suidperl, el único binario set uid es ahora "sperl5.8."n ("sperl5.8.4" para esta versión). "suidperl" se instala como un enlace físico a "perl"; tanto "suidperl" como "perl" invocarán automáticamente "sperl5.8.4", el binario set uid, por lo que este cambio debería ser completamente transparente.

Para proyectos nuevos, el equipo central de perl recomienda encarecidamente que utilice herramientas de seguridad dedicadas y de un solo propósito como "sudo" en lugar de "suidperl".

format

Además de correcciones de errores, las características de "format" han sido mejoradas. Véase perlform

Módulos y Pragmata

El (mal) uso de "/tmp" en los módulos principales y la documentación ha sido pulido. Algunos módulos disponibles tanto dentro del núcleo de perl como independientemente de CPAN ("módulos de doble vida") aún no han recibido estos cambios; los cambios se integrarán en futuras versiones estables de perl a medida que los módulos se actualicen en CPAN.

Cambios en Utilidades

El depurador de Perl (lib/perl5db.pl) ahora puede guardar todos los comandos del depurador para ejecutarlos posteriormente, y puede mostrar el árbol de herencia padre de una clase dada.

perl584delta - Changes Todistribution Perl 5.8.4

NAME

perl584delta - Changes between Perl 5.8.3 and Perl 5.8.4

DESCRIPTION

This document describes the changes between Perl 5.8.3 and Perl 5.8.4.

Perl 5.8.4 is a maintenance release that fixes bugs and makes minor improvements to Perl 5.8.3.

Incompatible Changes

The "%ENV" hash is now implemented using the same mechanism as user-defined hashes, meaning that a tied hash that behaves like "%ENV" can be used to intercept environment variable access. This should be completely transparent to existing code.

The "Carp" module's error messages are now more similar to the messages produced by the core routines, meaning that code relying on the exact format of "Carp" error messages may break.

Core Enhancements

The "sort" function now correctly handles empty lists.

Support for Unicode 3.0 has been added.

Modules and Pragmata

The "constant" pragma now correctly handles constants defined within a subroutine.

The "strict" pragma now correctly detects bareword filehandles used with "open".

Performance Enhancements

Regular expression matching has been optimized, particularly for cases involving alternations.

The performance of hash lookups has been improved.

Utility Changes

The "perlbug" script has been updated to provide more informative error messages.

The "makeplatter" script has been updated to support the creation of installation scripts for the new "Compress::Zlib" module.

Installation and Configuration Improvements

The Perl build process has been improved to better detect and handle platform-specific issues.

The "Configure" script has been updated to support new configuration options, including those related to Unicode and regular expression engines.

The documentation for the "INSTALL" file has been updated to reflect the changes in the build process.

The camel icon provided with Perl is intended for use as an executable's icon only. Its use for any other purpose, including redistribution with Perl binaries, requires explicit permission from O'Reilly Media.

Perl should now build cleanly on Stratus VOS.

Selected Bug Fixes

More UTF-8 bugs have been fixed, particularly in how "chomp", "chop", "send", and "syswrite" interact with UTF-8 data. Concatenation now works correctly when "use bytes;" is in scope.

Pragmata are now correctly propagated into (?{...}) constructions in regexps. Code such as:

my $x = qr{ ... (??{ $x }) ... };

will now (correctly) fail under use strict. (As the inner $x is and has always referred to $::x)

The "const in void context" warning has been suppressed for a constant in an optimized-away boolean expression such as "5 || print;".

"perl -i" could mistakenly fchmod(stdin). This is serious if stdin is attached to a terminal and Perl is running as root. This has now been fixed.

New or Changed Diagnostics

"Carp" and the internal diagnostic routines used by "Devel::Peek" have been made clearer, as described in "Incompatible Changes"

Changed Internals

Some bugs in the hash internals have been fixed. Restricted hashes and their placeholders are now allocated and deleted at slightly different times, but this should not be visible to user code.

Future Directions

The code freeze for the next maintenance release (5.8.5) will be on June 30, 2004, with a release by mid-July.

Platform Specific Problems

This release is known not to build on Windows 95.

Reporting Bugs

If you find what you think is a bug, you might check the articles recently posted to the comp.lang.perl.misc newsgroup and the Perl bug database at http://bugs.perl.org. There may also be information at http://www.perl.org, the Perl Home Page.

If you believe you have an unreported bug, please run the perlbug program included with your release. Be sure to trim your bug down to a tiny but sufficient test case. Your bug report, along with the output of "perl -V", will be sent to perlbug@perl.org to be analyzed by the Perl porting team. You can browse and search the Perl 5 bugs at http://bugs.perl.org/
