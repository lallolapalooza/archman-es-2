NOMBRE

perl56delta - Novedades de la versión v5.6.0 de Perl

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.005 y la versión 5.6.0.

Mejoras centrales

Clonación del intérprete, hilos y concurrencia

Perl 5.6.0 introduce los inicios del soporte para ejecutar múltiples intérpretes de forma concurrente en diferentes hilos. En conjunción con la llamada a la API perl_clone(), que puede ser utilizada para duplicar selectivamente el estado de cualquier intérprete dado, es posible compilar un fragmento de código una vez en un intérprete, clonar ese intérprete una o más veces, y ejecutar todos los intérpretes resultantes en hilos distintos.

En la plataforma Windows, esta característica se utiliza para emular fork() a nivel de intérprete. Consulte perlfork para obtener más detalles al respecto.

Esta característica todavía está en evolución. Eventualmente, se pretende utilizar para clonar selectivamente una subrutina y los datos alcanzables desde esa subrutina en un intérprete separado y ejecutar la subrutina clonada en un hilo separado. Dado que no hay datos compartidos entre los intérpretes, se necesitará poca o ninguna sincronización (a menos que partes de la tabla de símbolos se compartan explícitamente). Obviamente, se pretende que sea un reemplazo fácil de usar para el soporte de hilos existente.

El soporte para clonar intérpretes y la concurrencia de intérpretes puede habilitarse utilizando la opción de configuración -Dusethreads (consulte win32/Makefile para ver cómo habilitarlo en Windows). El ejecutable de Perl resultante será funcionalmente idéntico a uno que se hubiera compilado con -Dmultiplicity, pero la llamada a la API perl_clone() solo estará disponible en el primero.

-Dusethreads habilita la macro cpp USE_ITHREADS por defecto, lo que a su vez activa cambios en el código fuente de Perl que proporcionan una clara separación entre el árbol de operaciones (op tree) y los datos sobre los que opera. El primero es inmutable y, por lo tanto, puede ser compartido entre un intérprete y todos sus clones, mientras que el segundo se considera local a cada intérprete y, por lo tanto, se copia para cada clon.

Tenga en cuenta que compilar Perl con la opción de configuración -Dusemultiplicity es suficiente si desea ejecutar múltiples intérpretes **independientes** de forma concurrente en diferentes hilos. -Dusethreads solo proporciona la funcionalidad adicional de la llamada a la API perl_clone() y otro soporte para ejecutar intérpretes **clonados** de forma concurrente.

NOTA: Esta es una característica experimental. Los detalles de implementación
están sujetos a cambios.

Categorías de advertencia con ámbito léxico

Ahora puede controlar la granularidad de las advertencias emitidas por Perl a un nivel más fino utilizando la pragmática "use warnings". warnings y perllexwarn tienen abundante documentación sobre esta característica.

Soporte para Unicode y UTF-8

Perl ahora utiliza UTF-8 como su representación interna para las cadenas de caracteres. Las pragmáticas "utf8" y "bytes" se utilizan para controlar este soporte en el ámbito léxico actual. Consulte perlunicode, utf8 y bytes para obtener más información.

Se espera que esta característica evolucione rápidamente para soportar alguna forma de disciplinas de E/S que puedan ser utilizadas para especificar el tipo de datos de entrada y salida (bytes o caracteres). Hasta que eso suceda, se necesitarán módulos adicionales de CPAN para completar el conjunto de herramientas para tratar con Unicode.

NOTA: Esta debe considerarse una característica experimental. Los detalles de
implementación están sujetos a cambios.

Soporte para la interpolación de caracteres nombrados

La nueva secuencia de escape "\N" interpola caracteres nombrados dentro de las cadenas. Por ejemplo, "Hola! \N{CARA SONRIENTE BLANCA}" se evalúa como una cadena con una cara sonriente de Unicode al final.

Declaraciones "our"

Una declaración "our" introduce un valor que puede ser entendido mejor como un alias simbólico de ámbito léxico a una variable global en el paquete que estaba actual donde se declaró la variable. Esto es principalmente útil como una alternativa a la pragmática "vars", pero también proporciona la oportunidad de introducir tipado y otros atributos para tales variables. Consulte "our" en perlfunc.

Soporte para cadenas representadas como un vector de ordinales

Las literales de la forma "v1.2.3.4" ahora se analizan como una cadena compuesta por caracteres con los ordinales especificados. Esta es una forma alternativa y más legible de construir cadenas (posiblemente Unicode) en lugar de interpolar caracteres, como en "\x{1}\x{2}\x{3}\x{4}". La "v" inicial puede omitirse si hay más de dos ordinales, por lo que 1.2.3 se analiza igual que "v1.2.3".

Las cadenas escritas de esta forma también son útiles para representar "números" de versión. Es fácil comparar tales "números" de versión (que en realidad son solo cadenas simples) utilizando cualquiera de los operadores de comparación de cadenas habituales "eq", "ne", "lt", "gt", etc., o realizar operaciones de cadena bit a bit sobre ellas utilizando "|", "&", etc.

En conjunción con la nueva variable mágica $^V (que contiene la versión de Perl como una cadena), tales literales pueden ser utilizados como una forma legible de comprobar si se está ejecutando una versión particular de Perl:

# esto también se analizará en versiones anteriores de Perl
if ($^V and $^V gt v5.6.0) {
    # características nuevas soportadas
}

"require" y "use" también tienen algo de magia especial para soportar tales literales, pero este uso en particular debe evitarse ya que conduce a mensajes de error engañosos en versiones de Perl que no soportan cadenas vectoriales. El uso de un número de versión real garantizará un comportamiento correcto en todas las versiones de Perl:

require 5.006;    # comprobación en tiempo de ejecución para v5.6
use 5.006_001;    # comprobación en tiempo de compilación para v5.6.1

Además, "sprintf" y "printf" soportan el indicador de formato específico de Perl %v para imprimir los ordinales de los caracteres en cadenas arbitrarias:

printf "v%vd", $^V;         # imprime la versión actual, como "v5.5.650"
printf "%*vX", ":", $addr;  # formatea la dirección IPv6
printf "%*vb", " ", $bits;  # muestra la cadena de bits

Consulte "Constructores de valores escalares" en perldata para obtener información adicional.

Sistema mejorado de numeración de versiones de Perl

A partir de la versión 5.6.0 de Perl, la convención de numeración de versiones se ha cambiado a un esquema de "enteros con puntos" que se encuentra más comúnmente en proyectos de código abierto.

Las versiones de mantenimiento de v5.6.0 se publicarán como v5.6.1, v5.6.2, etc. La próxima serie de desarrollo que seguirá a v5.6.0 se numerará v5.7.x, comenzando con v5.7.0, y la próxima versión de producción principal que seguirá a v5.6.0 será v5.8.0.

El módulo English ahora establece $PERL_VERSION a $^V (un valor de cadena) en lugar de $] (un valor numérico). (Esta es una incompatibilidad potencial. Envíenos un informe a través de perlbug si se ve afectado por esto).

La sintaxis v1.2.3 ahora también es legal en Perl. Consulte "Soporte para cadenas representadas como un vector de ordinales" para saber más sobre eso.

Para adaptarse al nuevo sistema de versionado que utiliza al menos tres dígitos significativos para cada componente de versión, el método utilizado para incrementar el número de subversión también ha cambiado ligeramente.

Asumimos que las versiones anteriores a la v5.6.0 han estado incrementando el componente de subversión en múltiplos de 10. Las versiones posteriores a la v5.6.0 las incrementarán en 1. Por lo tanto, utilizando la nueva notación, 5.005_03 es lo "mismo" que la v5.5.30, y la primera versión de mantenimiento posterior a la v5.6.0 será la v5.6.1 (que debe leerse como equivalente a un valor de punto flotante de 5.006_001 en el formato antiguo, almacenado en $]).

Nueva sintaxis para declarar atributos de subrutinas

Anteriormente, si deseabas marcar una subrutina como una llamada a método o como requiriendo un lock() automático al entrar en ella, tenías que declararlo con un pragma "use attrs" en el cuerpo de la subrutina. Esto ahora se puede lograr con la sintaxis de declaración, de esta manera:

sub mi_metodo : locked method;
...
sub mi_metodo : locked method {
    ...
}
sub otro_metodo :locked :method;
...
sub otro_metodo :locked :method {
    ...
}

(Observa que solo el primer ":" es obligatorio, y el espacio en blanco que rodea los ":" es opcional).

AutoSplit.pm y SelfLoader.pm se han actualizado para conservar los atributos con los stubs que proporcionan. Ver atributos.

Los manejadores de archivos y directorios pueden ser autovivificados

De forma similar a como construcciones como "$x->[0]" autovivifican una referencia, los constructores de manejadores (open(), opendir(), pipe(), socketpair(), sysopen(), socket() y accept()) ahora autovivifican un manejador de archivo o directorio si el manejador pasado a ellos es una variable escalar no inicializada. Esto permite que construcciones como "open(my $fh, ...)" y "open(local $fh,...)" se utilicen para crear manejadores de archivo que se cerrarán automáticamente cuando finalice el ámbito, siempre que no haya otras referencias a ellos. Esto elimina en gran medida la necesidad de typeglobs al abrir manejadores de archivo que deben pasarse, como en el siguiente ejemplo:

sub mi_apertura {
    open my $fh, "@_"
         or die "No se puede abrir '@_': $!";
    return $fh;
}
{
    my $f = mi_apertura("</etc/motd");
    print <$f>;
    # $f se cierra implícitamente aquí
}

open() con más de dos argumentos

Si a open() se le pasan tres argumentos en lugar de dos, el segundo argumento se utiliza como modo y el tercer argumento se toma como el nombre del archivo. Esto es principalmente útil para proteger contra el comportamiento mágico no intencionado de la forma tradicional de dos argumentos. Ver "open" en perlfunc.

Soporte de 64 bits

Cualquier plataforma que tenga enteros de 64 bits ya sea

(1) nativamente como longs o ints
(2) a través de flags especiales del compilador
(3) usando long long o int64_t

puede utilizar "quads" (enteros de 64 bits) de la siguiente manera:

  • constantes (decimales, hexadecimales, octales, binarias) en el código
  • argumentos para oct() y hex()
  • argumentos para print(), printf() y sprintf() (prefijos de formato ll, L, q)
  • impresos como tales
  • formatos "q" y "Q" de pack() y unpack()
  • en aritmética básica: + - * / % (NOTA: operar cerca de los límites de los valores enteros puede producir resultados sorprendentes)
  • en aritmética de bits: & | ^ ~ << >> (NOTA: solían ser forzados a tener 32 bits de ancho, pero ahora operan en el ancho nativo completo).
  • vec()

Tenga en cuenta que a menos que tenga el caso (a), deberá configurar y compilar Perl usando el flag Configure -Duse64bitint.

NOTA: Los flags de Configure -Duselonglong y -Duse64bits han sido
deprecados. Utilice -Duse64bitint en su lugar.

En realidad, hay dos modos de 64 bits: el primero se logra usando Configure -Duse64bitint y el segundo usando Configure -Duse64bitall. La diferencia es que el primero es mínimo y el segundo es máximo. El primero funciona en más lugares que el segundo.

La opción "use64bitint" hace solo lo necesario para incorporar enteros de 64 bits en Perl (esto puede significar, por ejemplo, usar "long longs"), mientras que tu memoria puede seguir limitada a 2 gigabytes (porque tus punteros todavía podrían ser de 32 bits). Tenga en cuenta que el nombre "64bitint" no implica que su compilador C vaya a usar "int"s de 64 bits (podría hacerlo, pero no tiene por qué): "use64bitint" significa que podrás tener valores escalares de 64 bits de ancho.

La opción "use64bitall" va más allá intentando cambiar también los enteros (si puede), los longs (y los punteros) a 64 bits. Esto puede crear un Perl aún más incompatible a nivel binario que -Duse64bitint: el ejecutable resultante podría no funcionar en absoluto en una máquina de 32 bits, o podrías tener que reiniciar/reconfigurar/recompilar tu sistema operativo para que sea compatible con 64 bits.

Los sistemas nativamente de 64 bits como Alpha y Cray no necesitan ni -Duse64bitint ni -Duse64bitall.

Por último, pero no menos importante: tenga en cuenta que debido a la costumbre de Perl de usar siempre números de punto flotante, los quads siguen sin ser enteros verdaderos. Cuando los quads desbordan sus límites (0...18_446_744_073_709_551_615 sin signo, -9_223_372_036_854_775_808...9_223_372_036_854_775_807 con signo), se promueven silenciosamente a números de punto flotante, después de lo cual comenzarán a perder precisión (en sus dígitos inferiores).

NOTA: El soporte de 64 bits sigue siendo experimental en la mayoría de las
plataformas. El soporte existente solo cubre el modelo de datos LP64. En
particular, el modelo de datos LLP64 aún no es compatible. Las bibliotecas
de 64 bits y las API del sistema en muchas plataformas no se han
estabilizado; su experiencia puede variar.

Soporte de archivos grandes

Si tienes sistemas de archivos que soportan "archivos grandes" (archivos de más de 2 gigabytes), ahora también podrás crearlos y acceder a ellos desde Perl.

NOTA: La acción predeterminada es habilitar el soporte de archivos grandes,
si está disponible en la plataforma.

Si el soporte de archivos grandes está activado y tienes una constante Fcntl O_LARGEFILE, se añade automáticamente O_LARGEFILE a las banderas de sysopen().

Tenga en cuenta que a menos que su sistema de archivos también soporte "archivos dispersos", buscar hasta un umpteen de petabytes puede no ser aconsejable.

Tenga en cuenta que además de requerir un sistema de archivos adecuado para manejar archivos grandes, también es posible que deba ajustar los límites máximos de tamaño de archivo por proceso (o por sistema, o por grupo de procesos, o por usuario) antes de ejecutar scripts de Perl que intenten manejar archivos grandes, especialmente si tiene la intención de escribir dichos archivos.

Finalmente, además de los límites máximos de tamaño de archivo por proceso/grupo de procesos, puede haber límites de cuota en sus sistemas de archivos que le impidan (a su ID de usuario o a su ID de grupo de usuario) utilizar archivos grandes.

Ajustar sus límites de proceso/usuario/grupo/sistema de archivos/sistema operativo está fuera del alcance del lenguaje principal de Perl. Para límites de proceso, puede intentar aumentar los límites usando el comando limits/limit/ulimit de su shell antes de ejecutar Perl. La extensión BSD::Resource (no incluida con la distribución estándar de Perl) también puede ser útil, ofrece la interfaz getrlimit/setrlimit que se puede utilizar para ajustar los límites de uso de recursos del proceso, incluido el límite máximo de tamaño de archivo.

Dobles largos

En algunos sistemas, es posible que pueda utilizar dobles largos para mejorar el rango y la precisión de sus números de punto flotante de doble precisión (es decir, los números de Perl). Utilice Configure -Duselongdouble para habilitar este soporte (si está disponible).

"más bits"

Puede ejecutar "Configure -Dusemorebits" para habilitar tanto el soporte de 64 bits como el soporte de dobles largos.

Soporte mejorado para subrutinas de sort()

Las subrutinas de Perl con un prototipo de "($$)", y las XSUBs en general, ahora pueden usarse como subrutinas de ordenación. En cualquier caso, los dos elementos a comparar se pasan como parámetros normales en @_. Ver "sort" en perlfunc.

Para subrutinas de ordenación sin prototipo, el comportamiento histórico de pasar los elementos a comparar como variables globales $a y $b permanece sin cambios.

"sort $coderef @foo" permitido

sort() no aceptaba una referencia de subrutina como función de comparación en versiones anteriores. Esto ahora está permitido.

Globbing de archivos implementado internamente

Perl ahora utiliza la implementación de File::Glob del operador glob() automáticamente. Esto evita el uso de un proceso csh externo y los problemas asociados con él.

NOTA: Esta es actualmente una característica experimental. Las interfaces y
la implementación están sujetas a cambios.

Soporte para bloques CHECK

Además de "BEGIN", "INIT", "END", "DESTROY" y "AUTOLOAD", las subrutinas llamadas "CHECK" son ahora especiales. Estas se ponen en cola durante la compilación y se comportan de manera similar a los bloques END, excepto que se llaman al final de la compilación en lugar de al final de la ejecución. No se pueden llamar directamente.

Sintaxis de clase de caracteres POSIX [: :] soportada

Por ejemplo, para coincidir con caracteres alfabéticos, use /[[:alpha:]]/. Ver perlre para más detalles.

Mejor generador de números pseudoaleatorios

En las versiones 5.005_0x y anteriores, la función rand() de Perl utilizaba la función rand(3) de la biblioteca C. A partir de la versión 5.005_52, Configure prueba drand48(), random() y rand() (en ese orden) y elige la primera que encuentra.

Estos cambios deberían dar como resultado mejores números aleatorios de rand().

Operador "qw//" mejorado

El operador "qw//" ahora se evalúa en tiempo de compilación en una lista real en lugar de ser reemplazado por una llamada en tiempo de ejecución a split(). Esto elimina el comportamiento confuso e incorrecto de "qw//" en contexto escalar, que había heredado ese comportamiento de split().

Por lo tanto:

$foo = ($bar) = qw(a b c); print "$foo|$bar\n";

ahora imprime correctamente "3|a", en lugar de "2|a".

Mejor comportamiento en el peor caso de los hashes

Se han implementado pequeños cambios en el algoritmo de hash para mejorar la distribución de los bits de orden inferior en el valor hash. Se espera que esto proporcione un mejor rendimiento en claves que son secuencias repetidas.

pack() formato 'Z' soportado

El nuevo tipo de formato 'Z' es útil para empaquetar y desempaquetar cadenas terminadas en nulo. Ver "pack" en perlfunc.

pack() modificador de formato '!' soportado

El nuevo modificador de tipo de formato '!' es útil para empaquetar y desempaquetar enteros cortos, enteros y largos nativos. Ver "pack" en perlfunc.

pack() y unpack() soportan cadenas contadas

El carácter de plantilla '/' se puede utilizar para especificar un tipo de cadena contada para empaquetar o desempaquetar. Ver "pack" en perlfunc.

Comentarios en plantillas de pack()

El carácter '#' en una plantilla introduce un comentario hasta el final de la línea. Esto facilita la documentación de las plantillas de pack().

Referencias débiles

En versiones anteriores de Perl, no se podían almacenar en caché objetos para permitir que se eliminaran si se eliminaba la última referencia desde fuera de la caché. La referencia en la caché mantendría un recuento de referencias sobre el objeto y los objetos nunca se destruirían.

Otro problema familiar son las referencias circulares. Cuando un objeto se referencia a sí mismo, su recuento de referencias nunca llegaba a cero, y no se destruía hasta que el programa estaba a punto de salir.

Las referencias débiles resuelven esto al permitir "debilitar" cualquier referencia, es decir, hacer que no cuente para el recuento de referencias. Cuando la última referencia no débil a un objeto se elimina, el objeto se destruye y todas las referencias débiles al objeto se convierten automáticamente en undef.

Para utilizar esta función, necesita el paquete Devel::WeakRef de CPAN, que contiene documentación adicional.

NOTA: Esta es una característica experimental. Los detalles están sujetos a cambios.

Números binarios soportados

Ahora se soportan números binarios como literales, en formatos s?printf y oct():

$answer = 0b101010;
printf "The answer is: %b\n", oct("0b101010");

Subrutinas lvalue

Las subrutinas ahora pueden devolver lvalues modificables. Ver "Subrutinas lvalue" en perlsub.

NOTA: Esta es una característica experimental. Los detalles están sujetos a cambios.

Algunas flechas pueden omitirse en llamadas a través de referencias

Perl ahora permite omitir la flecha en muchas construcciones que involucran llamadas a subrutinas a través de referencias. Por ejemplo, "$foo[10]->('foo')" ahora puede escribirse como "$foo[10]('foo')". Esto es bastante similar a cómo se puede omitir la flecha de "$foo[10]->{'foo'}". Tenga en cuenta, sin embargo, que la flecha todavía se requiere para "foo(10)->('bar')".

Operadores de asignación booleana son lvalores legales

Ahora se permiten construcciones como "($a ||= 2) += 1".

exists() es soportado en nombres de subrutinas

La función incorporada exists() ahora funciona en nombres de subrutinas. Una subrutina se considera que existe si ha sido declarada (incluso si es implícitamente). Ver "exists" en perlfunc para ejemplos.

exists() y delete() son soportados en elementos de arrays

Las funciones incorporadas exists() y delete() ahora también funcionan en arrays simples. El comportamiento es similar al de los elementos de hash.

exists() se puede utilizar para comprobar si un elemento de array ha sido inicializado. Esto evita la autovivificación de elementos de array que no existen. Si el array está "tied", se invocará el método EXISTS() en el paquete "tied" correspondiente.

delete() puede utilizarse para eliminar un elemento del array y devolverlo. El elemento del array en esa posición vuelve a su estado no inicializado, de modo que la prueba del mismo elemento con exists() devolverá falso. Si el elemento resulta ser el último, el tamaño del array también se reduce hasta el elemento más alto que devuelve verdadero para exists(), o 0 si no se encuentra ninguno. Si el array está "tied", se invocará el método DELETE() en el paquete "tied" correspondiente.

Ver "exists" en perlfunc y "delete" en perlfunc para ejemplos.

Pseudo-hashes funcionan mejor

La desreferenciación de algunos tipos de valores de referencia en un pseudo-hash, como "$ph->{foo}[1]", estaba accidentalmente prohibida. Esto se ha corregido.

Cuando se aplica a un elemento de pseudo-hash, exists() ahora informa si el valor especificado existe, no solo si la clave es válida.

delete() ahora funciona en pseudo-hashes. Cuando se le da un elemento o una "slice" de pseudo-hash, elimina los valores correspondientes a las claves (pero no las claves mismas). Ver "Pseudo-hashes: Usando un array como un hash" en perlref.

Las "slices" de pseudo-hash con claves constantes ahora se optimizan a búsquedas en arrays en tiempo de compilación.

Ahora se soportan las asignaciones de listas a "slices" de pseudo-hash.

El pragma "fields" ahora proporciona formas de crear pseudo-hashes, a través de fields::new() y fields::phash(). Ver fields.

NOTA: El tipo de dato pseudo-hash sigue siendo experimental.
Limitarse a los elementos de interfaz proporcionados por el
pragma fields proporcionará protección contra futuros cambios.

Vaciado automático de buffers de salida

fork(), exec(), system(), qx// y las aperturas de tubería open() ahora vacían los buffers de todos los archivos abiertos para salida cuando se intentó la operación. Esto elimina en gran medida los confusos errores de buffering sufridos por usuarios que no conocían cómo Perl maneja internamente la E/S.

Esto no se soporta en algunas plataformas como Solaris donde no hay una implementación suficientemente correcta de fflush(NULL) disponible.

Mejores diagnósticos en operaciones sin sentido de filehandle

Construcciones como open(<FH>) y close(<FH>) son errores en tiempo de compilación. Intentar leer de filehandles que solo se abrieron para escritura ahora producirá advertencias (al igual que escribir en filehandles de solo lectura).

Donde sea posible, datos bufferizados descartados del filehandle de entrada duplicado

"open(NEW, "<&OLD")" ahora intenta descartar cualquier dato que se haya leído y bufferizado previamente en "OLD" antes de duplicar el handle. En plataformas donde esto está permitido, la próxima operación de lectura en "NEW" devolverá los mismos datos que la operación correspondiente en "OLD". Anteriormente, habría devuelto los datos desde el inicio del siguiente bloque de disco en su lugar.

eof() tiene la misma magia antigua que <>

eof() devolvía verdadero si aún no se había intentado leer de "<>". Se ha cambiado eof() para tener un poco de magia propia, ahora abre los archivos de "<>".

binmode() se puede usar para establecer los modos :crlf y :raw

binmode() ahora acepta un segundo argumento que especifica una disciplina para el handle en cuestión. Las dos pseudo-disciplinas ":raw" y ":crlf" están actualmente soportadas en plataformas derivadas de DOS. Ver "binmode" en perlfunc y open.

El filetest "-T" reconoce archivos codificados en UTF-8 como "texto"

El algoritmo utilizado para el filetest "-T" se ha mejorado para identificar correctamente el contenido UTF-8 como "texto".

system(), backticks y pipe ahora reflejan fallos de exec()

En Unix y plataformas similares, system(), qx() y open(FOO, "cmd |") etc., se implementan a través de fork() y exec(). Cuando el exec() subyacente fallaba, las versiones anteriores no informaban del error adecuadamente, ya que el exec() ocurría en un proceso diferente.

El proceso hijo ahora se comunica con el padre sobre el error al lanzar el comando externo, lo que permite que estas construcciones regresen con su valor de error habitual y establezcan $!.

Mejoras en los diagnósticos

Los números de línea ya no se suprimen (en las circunstancias más probables) durante la fase de destrucción global.

Los diagnósticos emitidos desde código que se ejecuta en hilos que no son el hilo principal ahora van acompañados del ID del hilo.

Los caracteres nulos incrustados en los diagnósticos ahora se muestran realmente. Solían truncar el mensaje en versiones anteriores.

$foo::a y $foo::b ahora están exentos de advertencias de "posible error tipográfico" solo si sort() se encuentra en el paquete "foo".

Las escapes alfabéticas no reconocidas encontradas al analizar construcciones de comillas ahora generan una advertencia, ya que pueden adquirir nuevos significados semánticos en versiones posteriores de Perl.

Muchos diagnósticos ahora informan la operación interna en la que se provocó la advertencia, de la siguiente manera:

Use of uninitialized value in concatenation (.) at (eval 1) line 1.
Use of uninitialized value in print at (eval 1) line 1.

Los diagnósticos que ocurren dentro de eval también pueden informar el archivo y el número de línea donde se encuentra el eval, además del número de secuencia de eval y el número de línea dentro del propio texto evaluado. Por ejemplo:

Not enough arguments for scalar at (eval 4)[newlib/perl5db.pl:1411] line 2, at EOF

Los diagnósticos siguen a STDERR

La salida de diagnóstico ahora va al archivo al que apunta el manejador "STDERR", en lugar de ir siempre al "stderr" de la biblioteca de tiempo de ejecución de C subyacente.

Comportamiento más consistente de cierre al ejecutar

En sistemas que admiten una bandera de cierre al ejecutar en manejadores de archivos, la bandera ahora se establece para cualquier manejador creado por pipe(), socketpair(), socket() y accept(), si eso está justificado por el valor de $^F que pueda estar en vigor. Las versiones anteriores omitieron establecer la bandera para los manejadores creados con estos operadores. Ver "pipe" en perlfunc, "socketpair" en perlfunc, "socket" en perlfunc, "accept" en perlfunc y "$^F" en perlvar.

Facilidad de uso de syswrite()

El argumento de longitud de syswrite() se ha vuelto opcional.

Mejores comprobaciones de sintaxis en operadores unarios parentetizados

Expresiones como:

print defined(&foo,&bar,&baz);
print uc("foo","bar","baz");
undef($foo,&bar);

solían ser permitidas accidentalmente en versiones anteriores y producían un comportamiento impredecible. Algunas producían advertencias auxiliares cuando se usaban de esta manera; otras hacían silenciosamente lo incorrecto.

Las formas parentetizadas de la mayoría de los operadores unarios que esperan un solo argumento ahora aseguran que no se llamen con más de un argumento, lo que convierte los casos mostrados anteriormente en errores de sintaxis. El comportamiento habitual de:

print defined &foo, &bar, &baz;
print uc "foo", "bar", "baz";
undef $foo, &bar;

no cambia. Ver perlop.

Los operadores de bits soportan el ancho completo del entero nativo

Los operadores de bits (& | ^ ~ << >>) ahora operan en el ancho integral nativo completo (el tamaño exacto del cual está disponible en $Config{ivsize}). Por ejemplo, si su plataforma es nativamente de 64 bits o si Perl ha sido configurado para usar enteros de 64 bits, estas operaciones se aplican a 8 bytes (en lugar de 4 bytes en plataformas de 32 bits). Para portabilidad, asegúrese de enmascarar los bits en exceso en el resultado de "~" unario, por ejemplo, "~$x & 0xffffffff".

Mejoras en las funciones de seguridad

Más operaciones potencialmente inseguras "ensucian" sus resultados para mejorar la seguridad.

Los campos "passwd" y "shell" devueltos por getpwent(), getpwnam() y getpwuid() ahora están "ensuciados", porque el usuario puede afectar su propia contraseña cifrada y su shell de inicio de sesión.

La variable modificada por shmread(), y los mensajes devueltos por msgrcv() (y su interfaz orientada a objetos IPC::SysV::Msg::rcv) también están "ensuciados", porque otros procesos no confiables pueden modificar mensajes y segmentos de memoria compartida para sus propios fines nefastos.

Protótipo de bareword más funcional (*)

Los prototipos de bareword se han racionalizado para permitir su uso para anular funciones incorporadas que aceptan barewords e interpretarlas de manera especial, como "require" o "do".

Los argumentos prototipados como "*" ahora serán visibles dentro de la subrutina como un escalar simple o como una referencia a un typeglob. Ver "Prototypes" en perlsub.

"require" y "do" pueden ser anulados

"require" y las operaciones "do 'file'" pueden ser anuladas localmente importando subrutinas del mismo nombre en el paquete actual (o globalmente importándolas en el espacio de nombres CORE::GLOBAL::). Anular "require" también afectará a "use", siempre que la anulación sea visible en tiempo de compilación. Ver "Overriding Built-in Functions" en perlsub.

$^X las variables ahora pueden tener nombres más largos que un solo carácter

Anteriormente, $^X era sinónimo de ${"\cX"}, pero $^XY era un error de sintaxis. Ahora los nombres de variables que comienzan con un carácter de control pueden ser arbitrariamente largos. Sin embargo, por razones de compatibilidad, estas variables *deben* escribirse con llaves explícitas, como "${^XY}" por ejemplo. "${^XYZ}" es sinónimo de ${"\cXYZ"}. Los nombres de variables con más de un carácter de control, como "${^XY^Z}", son ilegales.

La sintaxis antigua no ha cambiado. Como antes, `^X' puede ser un carácter literal de control-X o la secuencia de dos caracteres `caret' más `X'. Cuando se omiten las llaves, el nombre de la variable se detiene después del carácter de control. Por lo tanto, "$^XYZ" sigue siendo sinónimo de "$^X . "YZ"" como antes.

Como antes, las variables léxicas no pueden tener nombres que comiencen con caracteres de control. Como antes, las variables cuyos nombres comienzan con un carácter de control siempre se ven obligadas a estar en el paquete `main'. Todas estas variables están reservadas para extensiones futuras, excepto aquellas que comienzan con "^_", que pueden ser utilizadas por programas de usuario y están garantizadas para no adquirir un significado especial en ninguna versión futura de Perl.

Nueva variable $^C refleja el modificador "-c"

$^C tiene un valor booleano que refleja si perl se está ejecutando en modo de solo compilación (es decir, a través del modificador "-c"). Dado que los bloques BEGIN se ejecutan en tales condiciones, esta variable permite que el código de perl determine si las acciones que solo tienen sentido durante la ejecución normal están justificadas. Ver perlvar.

Nueva variable $^V contiene la versión de Perl como cadena

$^V contiene el número de versión de Perl como una cadena compuesta por caracteres cuyos ordinales coinciden con los números de versión, es decir, v5.6.0. Esto puede usarse en comparaciones de cadenas.

Ver "Support for strings represented as a vector of ordinals" para un ejemplo.

Este comportamiento debe habilitarse específicamente al ejecutar Configure. Ver INSTALL y README.Y2K.

Los arrays ahora siempre se interpolan en cadenas entre comillas dobles

En cadenas entre comillas dobles, los arrays ahora se interpolan, sin importar qué. El comportamiento en versiones anteriores de perl 5 era que los arrays se interpolaban en cadenas si el array había sido mencionado antes de que se compilara la cadena, y de lo contrario Perl generaba un error fatal en tiempo de compilación. En las versiones 5.000 a 5.003, el error era

Literal @example now requires backslash

En las versiones 5.004_01 a 5.6.0, el error era

> 
En cadenas, @ejemplo ahora debe escribirse como \@ejemplo

La idea era acostumbrar a la gente a escribir "fred\@example.com" cuando querían un signo "@" literal, así como siempre han escrito "Dame de vuelta mis \$5" cuando querían un signo de "$" literal.

A partir de la versión 5.6.1, cuando Perl ve ahora un signo "@" en una cadena entrecomillada doble, *siempre* intenta interpolar una matriz, independientemente de si la matriz se ha utilizado o declarado ya o no. El error fatal se ha degradado a una advertencia opcional:

Posible interpolación no intencionada de @ejemplo en cadena

Esto le advierte de que "fred@example.com" se convertirá en "fred.com" si no antepone una barra invertida a la "@". Consulte http://perl.plover.com/at-error.html para más detalles sobre la historia aquí.

@- y @+ proporcionan desplazamientos de inicio/fin de coincidencias de expresiones regulares

Las nuevas variables mágicas @- y @+ proporcionan los desplazamientos de inicio y fin, respectivamente, de $&, $1, $2, etc. Consulte perlvar para obtener detalles.

        key1 => value1,
        key2 => value2,
    );

This is mostly syntactic sugar, and is identical to the way hashes have been created in list context for years. However, it means that you can now interpolate hashes into double-quoted strings:

$name = "fred";
    @f = (key1 => value1, key2 => value2);
    print "The values for $name are @f\n";
    # Prints: The values for fred are key1 value1 key2 value2

This is also identical to what list context has done for years. The new syntax is the primary change here.

Symbolic regular expression references

You can now refer to capture groups in regular expressions symbolically using the :name syntax.

if (/(?<year>\d{4})/) {
        print "The year is $<year>\n";
    }

See perlre for more information.

The tie mechanism can now return undef from TIEHASH::FETCH

Previously, fetching a non-existent key from a tied hash would always return undef, even if the value stored for that key was undef. This has been fixed. See the Tie::Hash manpage for more.

The %Regexp hash is now available for inspecting regexes

The special hash %Regexp has been added. It allows you to inspect the compiled regular expressions available in the current scope. See perlvar for more.

Stack limits are now checked by default

A new variable, $], is initialized to a value that indicates the current Perl version. When Perl starts up, it checks this value against a compiled-in limit. If the limit has been exceeded, Perl will exit. This prevents infinite recursion bugs from consuming all available stack space.

See perlvar.

XSLoader has been added

XSLoader is a replacement for DynaLoader. It's designed to be simpler and more robust. See XSLoader.

DBM Filters

A new feature called "DBM Filters" has been added to all the DBM modules--DB_File, GDBM_File, NDBM_File, ODBM_File, and SDBM_File. DBM Filters add four new methods to each DBM module: 

filter_store_key
filter_store_value
filter_fetch_key
filter_fetch_value

These can be used to filter key-value pairs before the pairs are written to the database or just after they are read from the database. See perldbmfilter for further information.

Pragmata

"use attrs" is now obsolete, and is only provided for backward-compatibility. It's been replaced by the "sub : attributes" syntax. See "Subroutine Attributes" in perlsub and attributes.

Lexical warnings pragma, "use warnings;", to control optional warnings. See perllexwarn.

"use filetest" to control the behaviour of filetests ("-r" "-w" ...). Currently only one subpragma implemented, "use filetest 'access';", that uses access(2) or equivalent to check permissions instead of using stat(2) as usual. This matters in filesystems where there are ACLs (access control lists): the stat(2) might lie, but access(2) knows better.

The "open" pragma can be used to specify default disciplines for handle constructors (e.g. open()) and for qx//. The two pseudo-disciplines ":raw" and ":crlf" are currently supported on DOS-derivative platforms (i.e. where binmode is not a no-op). See also "binmode() can be used to set :crlf and :raw modes".

Performance enhancements

Simple sort() using { $a <=> $b } and the like are optimized

Minor changes in how subroutine calls are handled internally provide marginal improvements in performance.

The hash values returned by delete(), each(), values() and hashes in a list context are the actual values in the hash, instead of copies. This results in significantly better performance, because it eliminates needless copying in most situations.

Correcciones de errores importantes

<HANDLE> en archivos vacíos

Con $/ establecido en "undef", "slurping" un archivo vacío devuelve una cadena de longitud cero (en lugar de "undef", como solía hacer) la primera vez que se lee el HANDLE después de que $/ se establece en "undef". Las lecturas posteriores generan "undef".

Esto significa que lo siguiente agregará "foo" a un archivo vacío (antes no hacía nada):

perl -0777 -pi -e 's/^/foo/' empty_file

El comportamiento de:

perl -pi -e 's/^/foo/' empty_file

no cambia (continúa dejando el archivo vacío).

Mejoras en "eval '…'"

Los números de línea (reflejados por caller() y la mayoría de los diagnósticos) dentro de "eval '...'" a menudo eran incorrectos cuando había aquí documentos involucrados. Esto se ha corregido.

Las búsquedas léxicas de variables que aparecen en "eval '...'" dentro de funciones que a su vez fueron llamadas dentro de un "eval '...'"

Correcciones de errores

Se estaban buscando lexemas en el lugar equivocado. La búsqueda lexical ahora termina correctamente en el límite del bloque de la subrutina.

El uso de "return" dentro de "eval {...}" provocaba que $@ no se restableciera correctamente cuando no ocurría ninguna excepción dentro del eval. Esto se ha corregido.

El análisis de los here documents solía ser defectuoso cuando aparecían como la expresión de reemplazo en "eval 's/.../.../e'". Esto se ha corregido.

Todos los errores de compilación son errores reales

Algunos "errores" encontrados en tiempo de compilación se generaban por necesidad como advertencias, seguidas de la eventual terminación del programa. Esto permitía informar de más errores de este tipo en una sola ejecución, en lugar de detenerse bruscamente ante el primer error que se encontraba.

El mecanismo para informar de tales errores se ha reimplementado para poner en cola los errores de tiempo de compilación y reportarlos al final de la compilación como errores reales en lugar de advertencias. Esto corrige casos en los que los mensajes de error se filtraban en forma de advertencias cuando el código se compilaba en tiempo de ejecución usando "eval STRING", y también permite que dichos errores se capturen de forma fiable usando "eval "..."".

Los filehandles cerrados implícitamente son más seguros

A veces, los filehandles cerrados implícitamente (como cuando se localizan y Perl los cierra automáticamente al salir del ámbito) podían establecer inadvertidamente $? o $!. Esto se ha corregido.

El comportamiento de los slices de listas es más consistente

Al tomar un slice de una lista literal (en contraposición a un slice de un array o hash), Perl solía devolver una lista vacía si el resultado estaba compuesto por todos valores undef.

El nuevo comportamiento es producir una lista vacía si (y solo si) la lista original estaba vacía. Considere el siguiente ejemplo:

@a = (1,undef,undef,2)[2,1,2];

El comportamiento anterior habría resultado en que @a no tuviera elementos. El nuevo comportamiento asegura que tenga tres elementos indefinidos.

Tenga en cuenta en particular que el comportamiento de los slices de los siguientes casos no ha cambiado:

@a = ()[1,2];
@a = (getpwent)[7,0];
@a = (anything_returning_empty_list())[2,1,2];
@a = @b[2,1,2];
@a = @c{'a','b','c'};

Ver perldata.

El prototipo "(\$)" y $foo{a}

Un prototipo de referencia escalar ahora permite correctamente un elemento de hash o array en esa posición.

"goto &sub" y AUTOLOAD

La construcción "goto &sub" funciona correctamente cuando &sub se carga automáticamente.

"-bareword" permitido bajo "use integer"

La auto-cotización de barewords precedidas por "-" no funcionaba en versiones anteriores cuando el pragma "integer" estaba habilitado. Esto se ha corregido.

Fallos en DESTROY()

Cuando el código en un destructor lanzaba una excepción, pasaba desapercibido en versiones anteriores de Perl, a menos que alguien estuviera mirando en $@ justo después del punto en que el destructor se ejecutaba. Tales fallos son ahora visibles como advertencias cuando las advertencias están habilitadas.

Errores de localización corregidos

printf() y sprintf() restablecían previamente la localización numérica a la localización predeterminada "C". Esto se ha corregido.

Los números formateados según la localización numérica local (como el uso de una coma decimal en lugar de un punto decimal) provocaban advertencias de "no es numérico", a pesar de que las operaciones que accedían a esos números producían resultados correctos. Estas advertencias han sido discontinuadas.

Fugas de memoria

La construcción "eval 'return sub {...}'" podía filtrar memoria en ocasiones. Esto se ha corregido.

Las operaciones que no son constructores de filehandles solían filtrar memoria cuando se usaban en filehandles inválidos. Esto se ha corregido.

Las construcciones que modificaban @_ podían fallar al desasignar valores en @_ y, por lo tanto, filtrar memoria. Esto se ha corregido.

Stub de subrutina superfluos después de llamadas fallidas a subrutinas

Perl a veces podía crear stubs de subrutinas vacías cuando no se encontraba una subrutina en el paquete. Estos casos impedían que búsquedas de métodos posteriores progresaran en paquetes base. Esto se ha corregido.

Fallos de contaminación bajo "-U"

Al ejecutarse en modo inseguro, las violaciones de contaminación podían causar fallos silenciosos en ocasiones. Esto se ha corregido.

Bloques END y el conmutador "-c"

Las versiones anteriores ejecutaban bloques BEGIN y END cuando Perl se ejecutaba en modo de solo compilación. Dado que este no es típicamente el comportamiento esperado, los bloques END ya no se ejecutan cuando se usa el conmutador "-c", o si la compilación falla.

Ver "Soporte para bloques CHECK" para saber cómo ejecutar cosas cuando finaliza la fase de compilación.

Potencial de fugas de filehandles DATA

El uso del token "__DATA__" crea un filehandle implícito al archivo que contiene el token. Es responsabilidad del programa cerrarlo cuando termine de leer de él.

Esta advertencia ahora se explica mejor en la documentación. Ver perldata.

perl56delta - cambios y adiciones a Perl 5.6

DESCRIPCIÓN

Este documento describe los cambios y adiciones introducidos en Perl 5.6.0, en comparación con Perl 5.4.x.

Los cambios se dividen en varias categorías:

  • Mejoras del Núcleo
  • Módulos y Pragmata
  • Cambios en Utilidades
  • Documentación Mejorada
  • Mejoras de Rendimiento
  • Mejoras de Instalación y Configuración
  • Cambios Específicos de Plataforma
  • Correcciones de Errores Significativas
  • Diagnósticos Nuevos o Modificados
  • Nuevas Pruebas
  • Cambios Incompatibles
  • Problemas Conocidos
  • Diagnósticos Obsoletos

Core Enhancements

  • Un nuevo operador de cadenas, `tr///`, que funciona como `y///` pero es más explícito.
  • Las cadenas pueden ahora ser indexadas o cortadas usando índices negativos para contar desde el final.
  • El operador `defined` ahora funciona en escalares, arrays y hashes.
  • El operador `undef` se puede usar para asignar indefinido a variables escalares.
  • Las variables especiales `$/` y `$\` ahora pueden ser arrays de cadenas para leer o escribir usando múltiples delimitadores.
  • El operador `split` ahora tiene un tercer argumento opcional para limitar el número de divisiones.
  • El operador `pack` ahora soporta nuevas directivas para tipos de datos de punto flotante y enteros de tamaño variable.
  • El operador `unpack` ha sido mejorado con soporte para las mismas directivas que `pack`.
  • Las expresiones regulares ahora soportan clases de caracteres POSIX.
  • El uso de subrutinas como lvalues se ha mejorado.
  • El soporte para referencias débiles se ha introducido.
  • Se ha introducido un nuevo tipo de datos de pseudo-hash.
  • El conjunto de compiladores ha sido reescrito.
  • La implementación interna de globbing de archivos ha sido mejorada.
  • El módulo `DB` ha sido reescrito.
  • Se han introducido nuevas construcciones de código de expresiones regulares: "(?{ code })" y "(??{ code })".

Modules and Pragmata

  • Se ha añadido el pragma `use strict`.
  • Se ha añadido el pragma `use warnings`.
  • Se ha añadido el módulo `B::C` para compilar Perl a C.
  • Se ha añadido el módulo `B::DI` para inspeccionar el código de bytes de Perl.
  • Se ha añadido el módulo `Data::Dumper` para volcar estructuras de datos de Perl.
  • Se ha añadido el módulo `File::Find` para encontrar archivos recursivamente.
  • Se ha añadido el módulo `Getopt::Long` para análisis de argumentos de línea de comandos.
  • Se ha añadido el módulo `Module::Install` para instalar módulos.
  • Se ha añadido el módulo `Perl::Compiler` para compilar Perl a código de bytes.
  • Se ha añadido el módulo `Pod::Checker` para verificar documentación Pod.
  • Se ha añadido el módulo `Symbol::Approx` para buscar símbolos aproximados.
  • Se ha añadido el módulo `Test::Harness` para ejecutar pruebas.
  • Se ha añadido el módulo `Test::More` para escribir pruebas.
  • Se ha añadido el módulo `Thread` para soporte de hilos.
  • Se ha añadido el módulo `Unicode::String` para soporte de Unicode.

Utility Changes

  • `perl` ahora soporta la opción `-M` para cargar módulos.
  • `perlbug` ahora puede enviar informes de errores a través de HTTP.
  • `h2ph` ahora soporta la conversión de archivos de cabecera C a archivos de cabecera Perl.
  • `splain` ha sido añadido para formatear mensajes de error.

Improved Documentation

  • La documentación ha sido revisada y actualizada.
  • Se han añadido nuevos tutoriales y guías de referencia.
  • Se han corregido numerosos errores tipográficos y de formato.

Performance enhancements

  • La compilación de expresiones regulares ha sido optimizada.
  • El manejo de cadenas ha sido mejorado.
  • La asignación de memoria ha sido optimizada.
  • El recolector de basura ha sido mejorado.

Installation and Configuration Improvements

  • El script Configure ha sido mejorado para detectar más características de la plataforma.
  • El proceso de instalación ha sido simplificado.
  • Se ha añadido soporte para la instalación en sistemas sin permisos de superusuario.

Platform specific changes

Se han realizado numerosos cambios para mejorar la portabilidad y el rendimiento en diversas plataformas.

HP-UX socket test failure

En HP-UX 10.x, la prueba de sockets puede fallar debido a un problema con la implementación de sockets multihomed en la biblioteca del sistema operativo. La prueba intenta crear y conectarse a sockets "multihomed" (sockets que tienen múltiples direcciones IP).

NEXTSTEP 3.3 POSIX test failure

En NEXTSTEP 3.3p2, la implementación de strftime(3) en las bibliotecas del sistema operativo tiene un error: el formato %j numera los días de un mes comenzando desde cero, lo cual, aunque lógico para los programadores, provocará que fallen las subpruebas 19 a 27 de la prueba lib/posix.

Tru64 (aka Digital UNIX, aka DEC OSF/1) lib/sdbm test failure with gcc

Si se compila con gcc 2.95, la prueba lib/sdbm fallará (hará core dump). La solución es usar el cc del proveedor, que viene con el sistema operativo y produce buen código.

UNICOS/mk CC failures during Configure run

En UNICOS/mk, los siguientes errores pueden aparecer durante la ejecución de Configure:

Guessing which symbols your C compiler and preprocessor define...
CC-20 cc: ERROR File = try.c, Line = 3
...
  bad switch yylook 79bad switch yylook 79bad switch yylook 79bad switch yylook 79#ifdef A29K
...
4 errors detected in the compilation of "try.c".

El culpable es el awk defectuoso de UNICOS/mk. El efecto es afortunadamente bastante leve: Perl en sí mismo no se ve afectado negativamente por el error, solo la utilidad h2ph que viene con Perl, y esta se necesita muy raramente en estos días.

Arrow operator and arrays

Cuando el argumento izquierdo del operador flecha "->" es un array, o el operador "scalar" operando sobre un array, el resultado de la operación debe considerarse erróneo. Por ejemplo:

@x->[2]
scalar(@x)->[2]

Estas expresiones generarán errores en tiempo de ejecución en alguna versión futura de Perl.

Obsolete Diagnostics

La sintaxis de clase de caracteres [: :] está reservada para futuras extensiones
(W) Dentro de las clases de caracteres de expresiones regulares ([]) la sintaxis que comienza con "[:" y termina con ":]" está reservada para futuras extensiones. Si necesita representar esas secuencias de caracteres dentro de una clase de caracteres de expresión regular, simplemente quote los corchetes con la barra invertida: "\[:" y ":\]".
Nombre lógico mal formado |%s| en prime_env_iter
(W) Una advertencia peculiar de VMS. Se encontró un nombre lógico al preparar la iteración sobre %ENV que viola las reglas sintácticas que rigen los nombres lógicos. Debido a que no se puede traducir normalmente, se omite y no aparecerá en %ENV. Esto puede ser una ocurrencia benigna, ya que algunos paquetes de software podrían modificar directamente las tablas de nombres lógicos e introducir nombres no estándar, o podría indicar que una tabla de nombres lógicos se ha corrompido.
En una cadena, @%s ahora debe escribirse como \@%s
La descripción de este error solía decir: 
(Algún día simplemente asumirá que un @ sin barra invertida
 interpola un array.)

Ese día ha llegado, y este error fatal ha sido eliminado. Ha sido reemplazado por una advertencia no fatal en su lugar. Vea "Arrays ahora siempre interpolan en cadenas entre comillas dobles" para más detalles.

Problema probable de precedencia en %s
(W) El compilador encontró una palabra desnuda donde esperaba una condicional, lo que a menudo indica que un || o && fue analizado como parte del último argumento de la construcción anterior, por ejemplo: 
open FOO || die;
regexp demasiado grande
(F) La implementación actual de expresiones regulares usa 'shorts' como desplazamientos de dirección dentro de una cadena. Desafortunadamente, esto significa que si la expresión regular compila a más de 32767, explotará. Generalmente, cuando se desea una expresión regular tan grande, hay una mejor manera de hacerlo con múltiples sentencias. Ver perlre.
El uso de "$$<digit>" para significar "${$}<digit>" está obsoleto
(D) Las versiones de Perl anteriores a 5.004 malinterpretaban cualquier marcador de tipo seguido de "$" y un dígito. Por ejemplo, "$$0" se tomaba incorrectamente como "${$}0" en lugar de "${$0}". Este error está (mayormente) corregido en Perl 5.004.

Sin embargo, los desarrolladores de Perl 5.004 no pudieron corregir completamente este error, ya que al menos dos módulos ampliamente utilizados dependen del antiguo significado de "$$0" en una cadena. Por lo tanto, Perl 5.004 todavía interpreta "$$" de la forma antigua (rota) dentro de las cadenas; pero genera este mensaje como una advertencia. Y en Perl 5.005, este tratamiento especial cesará.
