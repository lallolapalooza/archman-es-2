personality(2) Manual de llamadas al sistema personality(2)

NOMBRE

personality - establecer el dominio de ejecución del proceso

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/personality.h>
int personality(unsigned long persona);

DESCRIPCIÓN

Linux admite diferentes dominios de ejecución, o personalidades, para cada proceso. Entre otras cosas, los dominios de ejecución indican a Linux cómo mapear los números de señales a las acciones de señal. El sistema de dominios de ejecución permite a Linux proporcionar soporte limitado para binarios compilados bajo otros sistemas operativos tipo UNIX.

Si persona no es 0xffffffff, entonces personality() establece el dominio de ejecución del llamante al valor especificado por persona. Especificar persona como 0xffffffff proporciona una forma de obtener la personalidad actual sin cambiarla.

Una lista de los dominios de ejecución disponibles se puede encontrar en <sys/personality.h>. El dominio de ejecución es un valor de 32 bits en el que los tres bytes superiores se reservan para banderas que hacen que el kernel modifique el comportamiento de ciertas llamadas al sistema para emular peculiaridades históricas o arquitectónicas. El byte menos significativo es un valor que define la personalidad que el kernel debe asumir. Los valores de las banderas son los siguientes:

ADDR_COMPAT_LAYOUT (desde Linux 2.6.9)
Con esta bandera establecida, proporcionar diseño de espacio de direcciones virtual heredado.
ADDR_NO_RANDOMIZE (desde Linux 2.6.12)
Con esta bandera establecida, deshabilitar la aleatorización del diseño del espacio de direcciones.
ADDR_LIMIT_32BIT (desde Linux 2.2)
Limitar el espacio de direcciones a 32 bits.
ADDR_LIMIT_3GB (desde Linux 2.4.0)
Con esta bandera establecida, usar 0xc0000000 como el desplazamiento en el que buscar un bloque de memoria virtual en mmap(2); de lo contrario, usar 0xffffe000. Se aplica solo a procesos x86 de 32 bits.
FDPIC_FUNCPTRS (desde Linux 2.6.11)
Los punteros de función en el espacio de usuario a manejadores de señales apuntan a descriptores. Se aplica solo a ARM si BINFMT_ELF_FDPIC y SuperH.
MMAP_PAGE_ZERO (desde Linux 2.4.0)
Mapear la página 0 como de solo lectura (para soportar binarios que dependen de este comportamiento SVr4).
READ_IMPLIES_EXEC (desde Linux 2.6.8)
Con esta bandera establecida, PROT_READ implica PROT_EXEC para mmap(2).
SHORT_INODE (desde Linux 2.4.0)
Sin efecto.
STICKY_TIMEOUTS (desde Linux 1.2.0)
Con esta bandera establecida, select(2), pselect(2), y ppoll(2) no modifican el argumento de tiempo de espera devuelto cuando se interrumpe por un manejador de señales.
UNAME26 (desde Linux 3.1)
Hacer que uname(2) informe un número de versión 2.6.(40+x) en lugar de un número de versión MAJOR.x. Añadido como medida provisional para soportar aplicaciones rotas que no podían manejar el cambio de numeración de versión del kernel de Linux 2.6.x a Linux 3.x.
WHOLE_SECONDS (desde Linux 1.2.0)
Sin efecto.

Los dominios de ejecución disponibles son:

PER_BSD (desde Linux 1.2.0)
BSD. (Sin efectos.)
PER_HPUX (desde Linux 2.4)
Soporte para HP/UX de 32 bits. Este soporte nunca fue completo, y se eliminó por lo que, desde Linux 4.0, este valor no tiene efecto.
PER_IRIX32 (desde Linux 2.2)
IRIX 5 de 32 bits. Nunca completamente funcional; el soporte se eliminó en Linux 2.6.27. Implica STICKY_TIMEOUTS.
PER_IRIX64 (desde Linux 2.2)
IRIX 6 de 64 bits. Implica STICKY_TIMEOUTS; de lo contrario, sin efecto.
PER_IRIXN32 (desde Linux 2.2)
IRIX 6 nuevo de 32 bits. Implica STICKY_TIMEOUTS; de lo contrario, sin efecto.
PER_ISCR4 (desde Linux 1.2.0)
Implica STICKY_TIMEOUTS; de lo contrario, sin efecto.
PER_LINUX (desde Linux 1.2.0)
Linux.
PER_LINUX32 (desde Linux 2.2)
uname(2) devuelve el nombre de la arquitectura de 32 bits en el campo machine ("i686" en lugar de "x86_64", etc.).
En ia64 (Itanium), los procesos con esta personalidad no tienen forzado el indicador O_LARGEFILE de open(2).
En ARM de 64 bits, establecer esta personalidad está prohibido si ejecutar un proceso de 32 bits con execve(2) también estaría prohibido (consulte el parámetro del kernel allow_mismatched_32bit_el0 y Documentation/arm64/asymmetric-32bit.rst).
PER_LINUX32_3GB (desde Linux 2.4)
Igual que PER_LINUX32, pero implica ADDR_LIMIT_3GB.
PER_LINUX_32BIT (desde Linux 2.0)
Igual que PER_LINUX, pero implica ADDR_LIMIT_32BIT.
PER_LINUX_FDPIC (desde Linux 2.6.11)
Igual que PER_LINUX, pero implica FDPIC_FUNCPTRS.
PER_OSF4 (desde Linux 2.4)
OSF/1 v4. Sin efecto desde Linux 6.1, que eliminó el soporte para binarios a.out. Antes, en alpha, se borraban los 32 bits superiores de iov_len en el búfer del usuario para compatibilidad con versiones antiguas de OSF/1 donde iov_len se definía como int.
PER_OSR5 (desde Linux 2.4)
SCO OpenServer 5. Implica STICKY_TIMEOUTS y WHOLE_SECONDS; de lo contrario, sin efecto.
PER_RISCOS (desde Linux 2.3.7; macro desde Linux 2.3.13)
Acorn RISC OS/Arthur (MIPS). Sin efecto. Hasta Linux v4.0, establecía la raíz alternativa de emulación en /usr/gnemul/riscos (consulte PER_SUNOS, abajo). Antes de eso, hasta Linux 2.6.3, solo emulación Arthur.
PER_SCOSVR3 (desde Linux 1.2.0)
SCO UNIX System V Release 3. Igual que PER_OSR5, pero también implica SHORT_INODE.
PER_SOLARIS (desde Linux 2.4)
Solaris. Implica STICKY_TIMEOUTS; de lo contrario, sin efecto.
PER_SUNOS (desde Linux 2.4.0)
Sun OS. Igual que PER_BSD, pero implica STICKY_TIMEOUTS. Antes de Linux 2.6.26, redirigía las búsquedas de bibliotecas y enlazadores dinámicos a /usr/gnemul. Erróneo, en gran parte sin mantenimiento y casi completamente sin usar.
PER_SVR3 (desde Linux 1.2.0)
AT&T UNIX System V Release 3. Implica STICKY_TIMEOUTS y SHORT_INODE; de lo contrario, sin efecto.
PER_SVR4 (desde Linux 1.2.0)
AT&T UNIX System V Release 4. Implica STICKY_TIMEOUTS y MMAP_PAGE_ZERO; de lo contrario, sin efecto.
PER_UW7 (desde Linux 2.4)
UnixWare 7. Implica STICKY_TIMEOUTS y MMAP_PAGE_ZERO;

personality(2) - Linux man pages

NAME

personality - establecer o obtener el conjunto de características del núcleo de un proceso

LIBRARY

Se proporciona por la biblioteca C estándar (libc, -lc).

SYNOPSIS

#include <linux/personality.h>

int personality(unsigned int persona);

DESCRIPTION

La llamada al sistema personality() establece o obtiene el conjunto de características de personalidad de un proceso. La personalidad afecta a cómo el núcleo interpreta ciertas llamadas al sistema y maneja ciertas características, como las señales. El argumento persona es una máscara de bits que especifica el conjunto deseado de características de personalidad. La personalidad actual del proceso se determina mediante la lógica de prioridad (el valor más bajo es el más importante).

Las siguientes constantes de personalidad se definen en <linux/personality.h>:

ADDR_COMPAT_LAYOUT (desde Linux 2.6.25)
Activa el diseño de memoria compatible con las arquitecturas de 32 bits en sistemas de 64 bits. Esto se hace principalmente para la compatibilidad con la pila en sistemas de 64 bits. Normalmente, el valor solo se modifica si se intenta cargar binarios de 32 bits en un sistema de 64 bits.
ADDR_LIMITED_SOCK_MEM (desde Linux 3.1)
Limita la memoria máxima que pueden utilizar las asignaciones de memoria de socket. Esto es para evitar el uso excesivo de memoria por parte de los sockets, especialmente en escenarios de alto rendimiento.
ALL_COMPAT (desde Linux 2.6.25)
Activa todas las personalidades de compatibilidad disponibles.
APLICACIONES_TIEMPO_REAL (desde Linux 2.6.12)
Habilita el manejo de señales en tiempo real y el comportamiento de los hilos para el soporte de hilos POSIX.
FREEBSD (desde Linux 1.2.0)
Comportamiento compatible con FreeBSD. Implica STICKY_TIMEOUTS y SHORT_INODE; de lo contrario, no tiene efecto.
LINUX (desde Linux 1.2.0)
Comportamiento estándar de Linux. Implica STICKY_TIMEOUTS y SHORT_INODE; de lo contrario, no tiene efecto.
LINUX_32BIT (desde Linux 2.6.16)
Ejecuta un programa de 32 bits en un sistema de 64 bits. Esto se hace automáticamente cuando se ejecuta un binario de 32 bits en un sistema de 64 bits, pero se puede establecer explícitamente.
NO_COLOR_EVENTS (desde Linux 5.12)
Desactiva los códigos de color de la salida de los eventos de terminal. Esto es útil para scripts o programas que no manejan códigos de escape de color.
NEW_STDIO (desde Linux 4.15)
Activa un nuevo modelo de E/S estándar que puede mejorar el rendimiento y reducir la sobrecarga para las aplicaciones que dependen en gran medida de las E/S estándar.
SHORT_INODE (desde Linux 1.2.0)
Habilita inodos cortos. Esto puede mejorar el rendimiento para aplicaciones que acceden a muchos inodos pequeños.
STICKY_TIMEOUTS (desde Linux 1.2.0)
Los tiempos de espera de las E/S se vuelven "pegajosos". Esto significa que los tiempos de espera de las E/S, una vez establecidos, permanecen en vigor hasta que se cambian explícitamente.
SUNOS (desde Linux 1.2.0)
Comportamiento compatible con SunOS. Implica STICKY_TIMEOUTS y SHORT_INODE; de lo contrario, no tiene efecto.
TARGET_LINUX (desde Linux 2.6.16)
Activa el comportamiento de destino de Linux para llamadas al sistema y otras operaciones. Esto se utiliza principalmente para la compatibilidad con programas de diferentes arquitecturas.
TRANSPARENT_HIGH_MEM (desde Linux 3.1)
Permite el acceso transparente a la memoria alta para los procesos. Esto puede ser útil para aplicaciones que requieren grandes cantidades de memoria que no caben en la memoria física principal.
UNAME26 (desde Linux 2.6.16)
Activa la interfaz `uname` versión 2.6. Esto se utiliza para la compatibilidad con sistemas más antiguos y permite que los programas vean una versión del núcleo que se asemeja a un núcleo Linux de 2.6.
PER_WYSEV386 (desde Linux 1.2.0)
WYSE UNIX System V/386. Implica STICKY_TIMEOUTS y SHORT_INODE; de lo contrario, no tiene efecto.
PER_XENIX (desde Linux 1.2.0)
XENIX. Implica STICKY_TIMEOUTS y SHORT_INODE; de lo contrario, no tiene efecto.

RETURN VALUE

Al tener éxito, se devuelve la persona anterior. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORS

EINVAL
El núcleo no pudo cambiar la personalidad.

STANDARDS

Linux.

HISTORY

Linux 1.1.20, glibc 2.3.
