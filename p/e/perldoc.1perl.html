PERLDOC(1perl) Guía de Referencia del Programador de Perl PERLDOC(1perl)

NOMBRE

perldoc - Buscar documentación de Perl en formato Pod.

SINOPSIS

perldoc [-h] [-D] [-t] [-u] [-m] [-l] [-U] [-F]
    [-i] [-V] [-T] [-r]
    [-d archivo_destino]
    [-o nombre_formato]
    [-M NombreClaseFormateador]
    [-w opcion:valor]
    [-n reemplazo-nroff]
    [-X]
    [-L codigo_idioma]
    NombrePagina|NombreModulo|NombrePrograma|URL

Ejemplos:

perldoc -f FuncionIncorporada
perldoc -L it -f FuncionIncorporada
perldoc -q FAQ PalabraClave
perldoc -L fr -q FAQ PalabraClave
perldoc -v VariablePerl
perldoc -a ApiPerl

Vea más abajo para una descripción de las opciones.

DESCRIPCIÓN

perldoc busca documentación en formato .pod incrustada en el árbol de instalación de perl o en un script de perl, y la muestra utilizando una variedad de formateadores. Esto se usa principalmente para la documentación de los módulos de la biblioteca de perl.

Es posible que su sistema también tenga páginas man instaladas para esos módulos, en cuyo caso probablemente pueda usar el comando man(1).

Si está buscando una tabla de contenidos para la documentación de los módulos de la biblioteca de perl, consulte la página perltoc.

OPCIONES

-h
Imprime un breve mensaje de ayuda.
-D
Describe la búsqueda del elemento en detalle.
-t
Muestra la documentación usando el convertidor de texto plano, en lugar de nroff. Esto puede ser más rápido, pero probablemente no se verá tan bien.
-u
Omite el formato real de Pod, y solo muestra el código fuente Pod sin formatear (Unformateado)
-m módulo
Muestra el módulo completo: tanto el código como la documentación Pod sin formatear. Esto puede ser útil si la documentación no explica una función con el detalle que necesita, y desea inspeccionar el código directamente; perldoc encontrará el archivo por usted y simplemente lo entregará para su visualización.
-l
Muestra sólo el nombre del archivo del módulo encontrado.
-U
Al ejecutarse como superusuario, no intente degradar privilegios por seguridad. Esta opción se implica con -F.

NOTA: Por favor, consulte el encabezado SEGURIDAD para más información.

-F
Considera los argumentos como nombres de archivo; no se realizarán búsquedas en directorios. Implica -U si se ejecuta como superusuario.
-f función_perl
La opción -f seguida del nombre de una función incorporada de perl extraerá la documentación de esta función de perlfunc.

Ejemplo:

perldoc -f sprintf
-q expresión_regular_búsqueda_faq_perl
La opción -q toma una expresión regular como argumento. Buscará en los encabezados de preguntas en perlfaq[1-9] e imprimirá las entradas que coincidan con la expresión regular.

Ejemplo:

perldoc -q shuffle
-a función_api_perl
La opción -a seguida del nombre de una función de la API de perl extraerá la documentación de esta función de perlapi.

Ejemplo:

perldoc -a newHV
-v variable_perl
La opción -v seguida del nombre de una variable predefinida de Perl extraerá la documentación de esta variable de perlvar.

Ejemplos:

perldoc -v '$"'
perldoc -v @+
perldoc -v DATA
-T
Esto especifica que la salida no debe enviarse a un paginador, sino que se enviará directamente a STDOUT.
-d nombre_archivo_destino
Esto especifica que la salida no debe enviarse ni a un paginador ni a STDOUT, sino que debe guardarse en el archivo especificado. Ejemplo: "perldoc -oLaTeX -dtextwrapdocs.tex Text::Wrap"
-o nombre_formato_salida
Esto especifica que desea que Perldoc intente usar una clase de formato Pod para el formato de salida que especifique. Por ejemplo: "-oman". Esto es en realidad solo un envoltorio alrededor del interruptor "-M"; usar "-onombre_formato" simplemente busca una clase cargable añadiendo ese nombre de formato (con diferentes capitalizaciones) al final de diferentes prefijos de nombres de clase.

Por ejemplo, "-oLaTeX" actualmente intenta todas las siguientes clases: Pod::Perldoc::ToLaTeX Pod::Perldoc::Tolatex Pod::Perldoc::ToLatex Pod::Perldoc::ToLATEX Pod::Simple::LaTeX Pod::Simple::latex Pod::Simple::Latex Pod::Simple::LATEX Pod::LaTeX Pod::latex Pod::Latex Pod::LATEX.

-M nombre_módulo
Esto especifica el módulo que desea intentar usar para formatear el pod. La clase debe proporcionar al menos un método "parse_from_file". Por ejemplo: "-MPod::Perldoc::ToChecker".

Puede especificar varias clases para intentar uniéndolas con comas o puntos y coma, como en "-MTk::SuperPod;Tk::Pod".

-w opcion:valor o -w opcion
Esto especifica una opción para llamar al formateador con. Por ejemplo, "-w textsize:15" llamará a "$formatter->textsize(15)" en el objeto formateador antes de que se utilice para formatear el objeto. Para que esto sea válido, la clase formateadora debe proporcionar dicho método, y el valor que pase debe ser válido. (Así que si "textsize" espera un entero, y hace "-w textsize:big", espere problemas.)

Puede usar "-w nombre_opcion" (sin valor) como atajo para "-w nombre_opcion:VERDADERO". Esto es presumiblemente útil en casos de características de encendido/apagado como: "-w numeración_páginas".

Puede usar un signo igual (=) en lugar de dos puntos (:), como en: "-w textsize=15". Esto puede ser más (o menos) conveniente, dependiendo del shell que utilice.

-X
Utiliza un índice si está presente. La opción -X busca una entrada cuyo nombre base coincida con el nombre dado en la línea de comandos en el archivo "$Config{archlib}/pod.idx". El archivo pod.idx debe contener nombres de archivo completamente calificados, uno por línea.
-L código_idioma
Esto permite especificar el código de idioma para la traducción deseada. Si el paquete "POD2::<código_idioma>" no está instalado en su sistema, la opción se ignora. Todos los paquetes de traducción disponibles se encuentran bajo el espacio de nombres "POD2::". Consulte POD2::IT (o POD2::FR) para ver cómo crear nuevos paquetes de documentación localizados "POD2::*" e integrarlos en Pod::Perldoc.
NombrePagina|NombreModulo|NombrePrograma|URL
El elemento que desea buscar. Los módulos anidados (como "File::Basename") se especifican como "File::Basename" o "File/Basename". También puede dar un nombre descriptivo de una página, como "perlfunc". Para URLs, HTTP y HTTPS son los únicos tipos actualmente admitidos.

Para nombres simples como 'foo', cuando la búsqueda normal no encuentra una página coincidente, también se intenta una búsqueda con el prefijo "perl". Por lo tanto, "perldoc intro" es suficiente para encontrar/renderizar

NAME

perldoc - Display text documentation for Perl modules

SYNOPSIS

perldoc [-o formatter] [-u] [-U] [-m] [-l] [-t] [-T] [-d] [-h] [-i] [-r] [-n] [-V] [-v] [-F] [-S] [-X] [module|file|section]...

DESCRIPTION

perldoc retrieves documentation from installed Perl modules and displays it.

When invoked without arguments, it displays the documentation for the perl manual page.

It will search for modules in directories listed in "PERL5LIB", "PERLLIB", and the directories in your "PATH". In directories where either "Makefile.PL" or "Build.PL" exist, it will also search ".", "lib", and "blib" (if not running as superuser).

The documentation can be displayed in several formats, controlled by the -o switch. By default, it uses the "Term::ReadKey" module to determine the terminal width and format the output accordingly.

If you try to display documentation for a section of a module, like "perldoc -n perlfunc/open", perldoc will try to find the specified section. This is useful for navigating the large "perlfunc" manual page.

OPTIONS

-o formatter
Specify the output formatter. Options include:
-t
Display the documentation as plain text, without any special formatting. Equivalent to -otext.
-T
Display the documentation as plain text, without any special formatting, and without a pager. Equivalent to -otext.
-r
Use the RTF formatter. Requires that the Pod::Perldoc::RTF module is installed.
-x
Use the XML formatter. Requires that the Pod::Perldoc::XML module is installed.
-m
Display the module's source code.
-l
Display the module's source file name.
-F
Treat the argument as a file name rather than a module name. This is useful for searching documentation for modules that are not installed in the standard Perl library directories.
-S
Search the PATH for the specified file. This is useful for finding documentation for executables that are not Perl modules.
-X
Do not attempt to drop privileges when running as the superuser. Use with caution.
-d
Enable debugging output.
-h
Display a help message and exit.
-v
Enable verbose output. This is now equivalent to the "-D" option from older versions. See the "ENVIRONMENT" section for "PERLDOCDEBUG".
-n some-formatter
Specify replacement for groff
-r
Recursive search.
-i
Ignore case.
-V
Displays the version of perldoc you're running.

SECURITY

Because perldoc does not run properly tainted, and is known to have security issues, when run as the superuser it will attempt to drop privileges by setting the effective and real IDs to nobody's or nouser's account, or -2 if unavailable. If it cannot relinquish its privileges, it will not run.

See the "-U" option if you do not want this behavior but beware that there are significant security risks if you choose to use "-U".

Since 3.26, using "-F" as the superuser also implies "-U" as opening most files and traversing directories requires privileges that are above the nobody/nogroup level.

ENVIRONMENT

Any switches in the "PERLDOC" environment variable will be used before the command line arguments.

Useful values for "PERLDOC" include "-oterm", "-otext", "-ortf", "-oxml", and so on, depending on what modules you have on hand; or the formatter class may be specified exactly with "-MPod::Perldoc::ToTerm" or the like.

"perldoc" also searches directories specified by the "PERL5LIB" (or "PERLLIB" if "PERL5LIB" is not defined) and "PATH" environment variables. (The latter is so that embedded pods for executables, such as "perldoc" itself, are available.)

In directories where either "Makefile.PL" or "Build.PL" exist, "perldoc" will add "." and "lib" first to its search path, and as long as you're not the superuser will add "blib" too. This is really helpful if you're working inside of a build directory and want to read through the docs even if you have a version of a module previously installed.

"perldoc" will use, in order of preference, the pager defined in "PERLDOC_PAGER", "MANPAGER", or "PAGER" before trying to find a pager on its own. ("MANPAGER" is not used if "perldoc" was told to display plain text or unformatted pod.)

When using perldoc in it's "-m" mode (display module source code), "perldoc" will attempt to use the pager set in "PERLDOC_SRC_PAGER". A useful setting for this command is your favorite editor as in "/usr/bin/nano". (Don't judge me.)

One useful value for "PERLDOC_PAGER" is "less -+C -E".

Having PERLDOCDEBUG set to a positive integer will make perldoc emit even more descriptive output than the "-D" switch does; the higher the number, the more it emits.

CHANGES

Up to 3.14_05, the switch -v was used to produce verbose messages of perldoc operation, which is now enabled by -D.
