NOMBRE

perl5141delta - qué hay de nuevo en la versión perl v5.14.1

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.14.0 y la versión 5.14.1.

Si está actualizando desde una versión anterior como la 5.12.0, primero lea perl5140delta, que describe las diferencias entre la 5.12.0 y la 5.14.0.

Mejoras Principales

Sin cambios desde 5.14.0.

Seguridad

Sin cambios desde 5.14.0.

Cambios Incompatibles

No hay cambios intencionalmente incompatibles con 5.14.0. Si los hubiera, serían errores y se agradecen los informes.

Deprecaciones

No ha habido deprecaciones desde 5.14.0.

Módulos y Pragmata Actualizados

  • B::Deparse se ha actualizado de la versión 1.03 a la 1.04, para corregir dos regresiones en Perl 5.14.0:

    La deconstrucción del operador "glob" y su forma de diamante ("<>") ahora funciona de nuevo. [perl #90898]

    La presencia de subrutinas llamadas "::::" o "::::::" ya no hace que B::Deparse se bloquee.

  • Pod::Perldoc se ha actualizado de la versión 3.15_03 a la 3.15_04.

    Corrige las rutas de búsqueda en VMS. [perl #90640]

Cambios en la Documentación Existente

perlfunc

  • "given", "when" y "default" ahora están listados en perlfunc.
  • La documentación para "use" ahora incluye un enlace a if.pm.

perllol

•
perllol ha sido ampliado con ejemplos que utilizan la nueva sintaxis "push $escalar" introducida en Perl 5.14.0.

perlop

  • La explicación de los operadores bit a bit se ha ampliado para explicar cómo funcionan en cadenas Unicode.
  • La sección sobre el operador de triple punto o yada-yada se ha movido arriba, ya que solía separar dos secciones relacionadas sobre el operador coma.
  • Se han añadido más ejemplos para "m//g".
  • Se ha documentado la sintaxis de aquí-documento "<<\FOO".

perlrun

•
perlrun ha sido objeto de una limpieza significativa. Notablemente, se ha clarificado la forma -0x... del flag -0, y la sección final sobre variables de entorno ha sido corregida y ampliada.

POSIX

•
La documentación de invocación para "WIFEXITED", "WEXITSTATUS", "WIFSIGNALED", "WTERMSIG", "WIFSTOPPED" y "WSTOPSIG" fue corregida.

Configuración y Compilación

•
regexp.h ha sido modificado para compatibilidad con la opción "-Werror" de GCC, tal como la utilizan algunos proyectos que incluyen archivos de encabezado de perl.

Pruebas

  • Se han corregido algunos fallos en las pruebas de dist/Locale-Maketext/t/09_compile.t que podían ocurrir dependiendo del entorno. [perl #89896]
  • Se amplió un temporizador de vigilancia para t/re/re.t para acomodar sistemas SH-4 que no podían completar las pruebas antes de que expirara el temporizador anterior.

Notas Específicas de Plataforma

Solaris

•
La documentación que enumera los paquetes de Solaris necesarios para compilar Perl en Solaris 9 y Solaris 10 ha sido corregida.

Mac OS X

  • El script de prueba lib/locale.t se ha actualizado para funcionar en la próxima versión Lion.
  • Las instrucciones de compilación específicas de Mac OS X se han aclarado.

Ubuntu Linux

•
El proceso de instalación de ODBM_File se ha actualizado con las nuevas rutas de biblioteca en Ubuntu natty.

Cambios Internos

•
La representación compilada de los formatos ahora se almacena a través del mg_ptr de su PERL_MAGIC_fm. Anteriormente se almacenaba en el búfer de cadena, más allá de SvLEN(), el final regular de la cadena. SvCOMPILED() y SvCOMPILED_{on,off}() ahora existen únicamente para compatibilidad con código XS. El primero es siempre 0, los otros dos ahora no tienen efecto.

Correcciones de Errores

  • Se ha corregido un error que causaba un error de "Uso de valor liberado en iteración" si se eliminaban los dos siguientes elementos del hash que se iban a iterar. [perl #85026]
  • Pasar la misma subrutina constante a "index" y "formline" ya no provoca que una u otra falle. [perl #89218]
  • 5.14.0 introdujo algunas fugas de memoria en clases de caracteres de expresiones regulares como "[\w\s]", que ahora se han corregido.
  • Un caso extremo en la coincidencia de expresiones regulares podría potencialmente entrar en un bucle. Esto ocurría solo bajo "/i" en clases de caracteres entre corchetes que tienen char

perl5141delta - Changes Perl 5.14.1

Bug Fixes

  • A bug was fixed where a regular expression containing an alternation of alternations, such as "/((a)|(b))|(c|d)/", could cause an infinite loop.
  • A bug was fixed in Unicode case folding where a multi-character fold could fail to match if the target string was constructed in a particular way. This occurred when the search pattern matched the first part of a multi-character fold, and the character following it started another multi-character fold that included the rest of the original fold plus more characters. 
    "s\N{LATIN SMALL LETTER SHARP S}" =~ /[\x{DF}foo]/i

    is one such case. "\xDF" folds to "ss".

  • Several bugs in Unicode case folding have been fixed.
  • The new (in 5.14.0) regular expression modifier "/a", when repeated as "/aa", forbids characters outside the ASCII range that match characters inside that range from matching under "/i". This was not working under some circumstances, all involving alternation, such as: 
    "\N{KELVIN SIGN}" =~ /k|foo/iaa;

    This succeeded inappropriately. This is now fixed.

  • A case was fixed where it was possible that a freed buffer might have been read from when parsing a here document.

Reporting Bugs

If you find what you think is a bug, you might check the articles recently posted to the comp.lang.perl.misc newsgroup and the perl bug database at http://rt.perl.org/perlbug/ . There may also be information at http://www.perl.org/ , the Perl Home Page.

If you believe you have an unreported bug, please run the perlbug program included with your release. Be sure to trim your bug down to a tiny but sufficient test case. Your bug report, along with the output of "perl -V", will be sent off to perlbug@perl.org to be analysed by the Perl porting team.

If the bug you are reporting has security implications, which make it inappropriate to send to a publicly archived mailing list, then please send it to perl5-security-report@perl.org. This points to a closed subscription unarchived mailing list, which includes all the core committers, who will be able to help assess the impact of issues, figure out a resolution, and help coordinate the release of patches to mitigate or fix the problem across all platforms on which Perl is supported. Please only use this address for security issues in the Perl core, not for modules independently distributed on CPAN.
