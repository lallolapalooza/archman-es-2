NOMBRE

perl5300delta - qué hay de nuevo para perl v5.30.0

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.28.0 y la versión 5.30.0.

Si está actualizando desde una versión anterior como la 5.26.0, primero lea perl5280delta, que describe las diferencias entre la 5.26.0 y la 5.28.0.

Aviso

sv_utf8_(downgrade|decode) ya no están marcadas como experimentales. [GH #16822] https://github.com/Perl/perl5/issues/16822.

Mejoras del Núcleo

La búsqueda hacia atrás de longitud variable limitada en la coincidencia de patrones de expresiones regulares ahora es soportada experimentalmente

Usar una aserción de búsqueda hacia atrás (como "(?<=foo?)" o "(?<!ba{1,9}r)" previamente generaba un error y se negaba a compilar. Ahora compila (si la búsqueda hacia atrás máxima es de 255 caracteres o menos), pero genera una advertencia en la nueva categoría de advertencias "experimental::vlb". Esto es para advertirle que el comportamiento preciso está sujeto a cambios basado en la retroalimentación del uso en el campo.

Ver "(?<=pattern)" en perlre y "(?<!pattern)" en perlre.

El límite superior "n" especificable en un cuantificador de expresión regular de la forma "{m,n}" ha sido duplicado a 65534

El significado de un cuantificador con límite superior ilimitado "{m,}" no cambia. Coincide 2**31 - 1 veces en la mayoría de las plataformas, y más en aquellas donde una variable corta del lenguaje C es de más de 4 bytes de longitud.

Unicode 12.1 es soportado

Debido a un cambio en los ciclos de lanzamiento de Unicode, Perl salta de Unicode 10.0 en Perl 5.28 a Unicode 12.1 en Perl 5.30.

Para detalles sobre los cambios de Unicode, ver https://www.unicode.org/versions/Unicode11.0.0/ para 11.0; https://www.unicode.org/versions/Unicode12.0.0/ para 12.0; y https://www.unicode.org/versions/Unicode12.1.0/ para 12.1. (Unicode 12.1 difiere de 12.0 solo en la adición de un solo carácter, el del nuevo nombre de era japonés.)

La propiedad Word_Break, como en versiones anteriores de Perl, se mantiene adaptada para comportarse más en línea con las expectativas de los usuarios de Perl. Esto significa que las secuencias de caracteres de espacio en blanco horizontales no se separan, sino que se mantienen como una sola secuencia. Unicode 11 cambió desde versiones anteriores para estar más en línea con Perl, pero dejó varios caracteres de espacio en blanco como causantes de rupturas: TAB, NO BREAK SPACE y FIGURE SPACE (U+2007). Hemos decidido continuar usando la adaptación anterior de Perl con respecto a estos.

Los comodines en especificaciones de valores de propiedades Unicode ahora son parcialmente soportados

Ahora puedes hacer algo como esto en un patrón de expresión regular :

qr! \p{nv= /(?x) \A [0-5] \z / }!

lo que coincide con todos los puntos de código Unicode cuyos valores numéricos están entre 0 y 5 inclusive. Por lo tanto, podría coincidir con los dígitos tailandeses o bengalíes cuyos valores numéricos son 0, 1, 2, 3, 4 o 5.

Este marca otro paso en la implementación de las características de expresiones regulares que sugiere el Consorcio Unicode.

La mayoría de las propiedades son soportadas, con el resto planeado para 5.32. Los detalles están en "Wildcards in Property Values" en perlunicode.

qr'\N{nombre}' ahora es soportado

Previamente era un error evaluar un carácter nombrado "\N{...}" dentro de un patrón de expresión regular de comillas simples (cuya evaluación se pospone desde el lugar normal). Esta restricción ahora se ha eliminado.

Los locales UTF-8 turcos ahora son soportados sin problemas

Los idiomas turcos tienen reglas de mayúsculas/minúsculas diferentes a otros idiomas para los caracteres "i" e "I". La mayúscula de "i" es LATIN CAPITAL LETTER I WITH DOT ABOVE (U+0130); y la minúscula de "I" es LATIN SMALL LETTER DOTLESS I (U+0131). Unicode proporciona reglas de mayúsculas/minúsculas alternativas para usar con idiomas turcos. Anteriormente, Perl las ignoraba, pero ahora las usa cuando detecta que está operando bajo un locale UTF-8 turco.

Ahora es posible compilar perl para usar siempre operaciones de locale seguras para hilos

Anteriormente, estas llamadas solo se usaban cuando el perl se compilaba para ser multi-hilo. Para habilitarlas siempre, agregue

-Accflags='-DUSE_THREAD_SAFE_LOCALE'

a sus flags de Configure.

Eliminación del uso de la macro opASSIGN del núcleo

Esta macro todavía está definida pero ya no se usa en el núcleo.

"-Drv" ahora significa algo en compilaciones "-DDEBUGGING"

Ahora, agregar el flag verboso ("-Dv") al flag "-Dr" activa todas las depuraciones posibles de expresiones regulares.

Cambios Incompatibles

La asignación de un valor no cero a $[ es fatal

Establecer $[ a un valor no cero ha sido deprecado desde Perl 5.12 y ahora genera un error fatal. Ver "Assigning non-zero to $[ is fatal" en perldeprecation.

Los delimitadores ahora deben ser grafemas

Ver "Use of unassigned code point or non-standalone grapheme for a delimiter." en perldeprecation

Algunos usos anteriormente deprecados de una llave izquierda sin escapar "{" en patrones de expresiones regulares ahora son ilegales

Pero para evitar romper código innecesariamente, la mayoría de las instancias que generaron una advertencia de deprecación, siguen siendo legales y ahora generan una advertencia que no es de deprecación. Ver "Unescaped left braces in regular expressions" en perldeprecation.

El uso anteriormente deprecado de sysread()/syswrite() en manejadores :utf8 es ahora fatal

El uso de sysread() o syswrite() en un manejador de archivo abierto con :utf8 se ha deprecado desde Perl 5.10. Ahora, estos intentos lanzan un error fatal.

Por favor, use las funciones de lectura/escritura normal de Perl (como print, read, syswrite, etc.) en su lugar.

La conversión a invocación de método de escalares con nombres de métodos que coinciden con caracteres especiales ahora es un error

Anteriormente, se permitía la siguiente construcción:

    my $invocant = "Foo::Bar";
    $invocant->method();

donde $invocant podría contener "Foo::Bar". Ahora, si $invocant contiene un nombre que se parece a un nombre de método de una clase invocante, se genera un error.

Esto se hizo para abordar problemas de seguridad con el método autoloader.

Las cláusulas use version y use filetest ahora son completamente evaluadas inmediatamente

Anteriormente, use version y use filetest permitían que la evaluación de sus argumentos se pospusiera hasta que se usara el módulo.

Esto era un error, que ahora se ha corregido.

El uso de variables lexicales en un contexto que no es de scalar con "=" como separador con "$" o "@" es un error

Por ejemplo, el código siguiente solía ser legal:

    use strict;
    my $a;
    ($a) = 1;

Ahora, la asignación a una variable lexical solo se permite si el número de elementos a la derecha de la asignación es uno.

En el ejemplo anterior, 1 es un solo elemento. Sin embargo, la siguiente asignación solía ser legal pero ahora es un error:

    my ($a) = @some_array;

Esto se debe a que @some_array podría expandirse a cero o más de un elemento, y la asignación solo está permitida si @some_array es un solo elemento.

Si realmente desea asignar un array a una variable lexical, deberá hacerlo explícitamente como:

    my $a = scalar @some_array;

Ver la discusión en perlsec para más detalles.

La desactivación de la compilación de expresiones regulares con pragmas como use re 'eval' => 0 ahora es un error

En versiones anteriores, permitía desactivar la compilación de expresiones regulares, con la expectativa de que esto mejoraría el rendimiento. Sin embargo, la implementación estaba rota y era inútil. Ahora, se considera un error y se elimina.

Los archivos de cabecera de Perl ya no incluyen directamente los archivos de cabecera del sistema en Windows

En versiones anteriores de Perl, los archivos de cabecera de Perl para Windows incluían directamente los archivos de cabecera del sistema de Windows (como <windows.h>). Esto podría causar problemas si estos archivos de cabecera definían macros que entraran en conflicto con las usadas por Perl.

Ahora, los archivos de cabecera de Perl para Windows solo incluyen los archivos de cabecera del sistema necesarios a través de <compat.h>. Esto debería eliminar cualquier conflicto de macros.

Si está compilando módulos de Perl para Windows y tiene problemas, es posible que necesite ajustar sus archivos de cabecera para incluir <patchlevel.h> y <win32/winnt.h> para obtener las definiciones necesarias.

    Mac OS X
    El proceso de compilación y prueba de Perl en Mac OS X para compilaciones con "-Duseshrplib" ahora es compatible con la Protección de Integridad del Sistema (SIP) de Mac OS X.

    SIP impide que los binarios en /bin (y algunos otros lugares) reciban la variable de entorno "DYLD_LIBRARY_PATH". Para nuestros propósitos, esto evita que "DYLD_LIBRARY_PATH" se pase al shell, lo que impide que esa variable se pase al proceso de prueba o compilación, por lo que ejecutar "perl" no podía encontrar libperl.dylib.

    Para solucionar esto, la compilación inicial del ejecutable perl espera encontrar libperl.dylib en el directorio de compilación, y la ruta de la biblioteca se ajusta durante la instalación para apuntar a la biblioteca instalada.

    Cambios Internos

    • La pasada de dimensionamiento se ha eliminado del compilador de expresiones regulares. En su lugar, puede ser necesaria una pasada adicional en algunos casos para contar el número de grupos de captura entre paréntesis.
    • Una nueva función ""my_strtod"" en perlapi o su sinónimo, Strtod(), ahora está disponible con la misma firma que el strtod() de libc. Proporciona un comportamiento equivalente a strotod() en todas las plataformas, utilizando la mejor precisión disponible, dependiendo de las capacidades de la plataforma y las opciones de Configure, al tiempo que maneja problemas relacionados con la configuración regional, como si el carácter separador decimal debe ser un punto o una coma.
    • Se añadió newSVsv_nomg() para copiar un SV sin procesar la magia de obtención en la fuente. [GH #16461] https://github.com/Perl/perl5/issues/16461.
    • Ahora está prohibido hacer malloc de más de "PTRDIFF_MAX" bytes. Gran parte del código (incluyendo los optimizadores C) asume que todas las estructuras de datos no serán más grandes que esto, por lo que esto captura tales intentos antes de que ocurra el desbordamiento.
    • Se han introducido dos nuevos nodos de registro: "EXACT_ONLY8" y "EXACTFU_ONLY8". Son equivalentes a "EXACT" y "EXACTFU", excepto que contienen un punto de código que requiere UTF-8 para representar/coincidir. Por lo tanto, si la cadena de destino no es UTF-8, sabemos que no puede coincidir, sin necesidad de intentarlo.
    • print_bytes_for_locale() ahora está definido si "DEBUGGING", Anteriormente, no se definía a menos que "LC_COLLATE" estuviera definido en la plataforma.

    Changes for Perl 5.30.0 ("The Diamond Release")

    This is a sorted list of changes between Perl 5.28.0 and Perl 5.30.0. For a more detailed list of changes, including bug fixes, see the Perl 5.30.0 CHANGES file.

    • Fixed a regression in the handling of Perl's internal filehandle representation. https://github.com/Perl/perl5/issues/16349.
    • Fix for "mutator not seen in (lex = ...) .= ..." [GH #16655] https://github.com/Perl/perl5/issues/16655.
    • "pack "u", "invalid uuencoding"" now properly NUL terminates the zero-length SV produced. [GH #16343] https://github.com/Perl/perl5/issues/16343.
    • Improve the debugging output for calloc() calls with . [GH #16653] https://github.com/Perl/perl5/issues/16653.
    • Regexp script runs were failing to permit ASCII digits in some cases. [GH #16704] https://github.com/Perl/perl5/issues/16704.
    • On Unix-like systems supporting a platform-specific technique for determining $^X, Perl failed to fall back to the generic technique when the platform-specific one fails (for example, a Linux system with /proc not mounted). This was a regression in Perl 5.28.0. [GH #16715] https://github.com/Perl/perl5/issues/16715.
    • SDBM_File is now more robust with corrupt database files. The improvements do not make SDBM files suitable as an interchange format. [GH #16164] https://github.com/Perl/perl5/issues/16164.
    • "binmode($fh);" or "binmode($fh, ':raw');" now properly removes the ":utf8" flag from the default ":crlf" I/O layer on Win32. [GH #16730] https://github.com/Perl/perl5/issues/16730.
    • The experimental reference aliasing feature was misinterpreting array and hash slice assignment as being localised, e.g. 
      \(@a[3,5,7]) = \(....);

      was being interpreted as:

      local \(@a[3,5,7]) = \(....);

      [GH #16701] https://github.com/Perl/perl5/issues/16701.

    • "sort SUBNAME" within an "eval EXPR" when "EXPR" was UTF-8 upgraded could panic if the "SUBNAME" was non-ASCII. [GH #16979] https://github.com/Perl/perl5/issues/16979.
    • Correctly handle realloc() modifying "errno" on success so that the modification isn't visible to the perl user, since realloc() is called implicitly by the interpreter. This modification is permitted by the C standard, but has only been observed on FreeBSD 13.0-CURRENT. [GH #16907] https://github.com/Perl/perl5/issues/16907.
    • Perl now exposes POSIX "getcwd" as Internals::getcwd() if available. This is intended for use by "Cwd.pm" during bootstrapping and may be removed or changed without notice. This fixes some bootstrapping issues while building perl in a directory where some ancestor directory isn't readable. [GH #16903] https://github.com/Perl/perl5/issues/16903.
    • pack() no longer can return malformed UTF-8. It croaks if it would otherwise return a UTF-8 string that contains malformed UTF-8. This protects against potential security threats. [GH #16035] https://github.com/Perl/perl5/issues/16035.
    • See "Any set of digits in the Common script are legal in a script run of another script".
    • Regular expression matching no longer leaves stale UTF-8 length magic when updating $^R. This could result in length($^R) returning an incorrect value.
    • Reduce recursion on ops [GH #11866] https://github.com/Perl/perl5/issues/11866.

      This can prevent stack overflow when processing extremely deep op trees.

    • Avoid leak in multiconcat with overloading. [GH #16823] https://github.com/Perl/perl5/issues/16823.
    • The handling of user-defined "\p{}" properties (see "User-Defined Character Properties" in perlunicode) has been rewritten to be in C (instead of Perl). This speeds things up, but in the process several inconsistencies and bug fixes are made.
    1.
    A few error messages have minor wording changes. This is essentially because the new way is integrated into the regex error handling mechanism that marks the position in the input at which the error occurred. That was not possible previously. The messages now also contain additional back-trace-like information in case the error occurs deep in nested calls.
    2.
    A user-defined property is implemented as a perl subroutine with certain highly constrained naming conventions. It was documented previously that the sub would be in the current package if the package was unspecified. This turned out not to be true in all cases, but now it is.
    3.
    All recursive calls are treated as infinite recursion. Previously they would cause the interpreter to panic. Now, they cause the regex pattern to fail to compile.
    4.
    Similarly, any other error likely would lead to a panic; now to just the pattern failing to compile.
    5.
    The old mechanism did not detect illegal ranges in the definition of the property. Now, the range max must not be smaller than the range min. Otherwise, the pattern fails to compile.
    6.
    The intention was to have each sub called only once during the lifetime of the program, so that a property's definition is immutable. This was relaxed so that it could be called once for all /i compilations, and potentially a second time for non-/i (the sub is passed a parameter indicating which). However, in practice there were instances when this was broken, and multiple calls were possible. Those have been fixed. Now (besides the /i,non-/i cases) the only way a sub can be called multiple times is if some component of it has not been defined yet. For example, suppose we have sub IsA() whose definition is known at compile time, and it in turn calls isB() whose definition is not yet known. isA() will be called each time a pattern it appears in is compiled. If isA() also calls isC() and that definition is known, isC() will be called just once.
    7.
    There were some races and very long hangs should one thread be compiling the same property as another simultaneously. These have now been fixed.
    • Fixed a failure to match properly.

      An EXACTFish regnode has a finite length it can hold for the string being matched. If that length is exceeded, a second node is used for the next segment of the string, for as many regnodes as are needed. Care has to be taken where to break the string, in order to deal multi-character folds in Unicode correctly. If we want to break a string at a place which could potentially be in the middle of a multi-character fold, we back off one (or more) characters, leaving a shorter EXACTFish regnode. This backing off mechanism contained an off-by-one error. [GH #16806] https://github.com/Perl/perl5/issues/16806.

    • A bare "eof" call with no previous file handle now returns true. [GH #16786] https://github.com/Perl/perl5/issues/16786
    • Failing to compile a format now aborts compilation. Like other errors in sub-parses this could leave the parser in a strange state, possibly crashing perl if compilation continued. [GH #16169] https://github.com/Perl/perl5/issues/16169
    • If an in-place edit is still in progress during global destruction and the process exit code (as stored in $?) is zero, perl will now treat the in-place edit as successful, replacing the input file with any output produced.

      This allows code like:

      perl -i -ne 'print "Foo"; last'

      to replace the input file, while code like:

      perl -i -ne 'print "Foo"; die'

      will not. Partly resolves [GH #16748] https://github.com/Perl/perl5/issues/16748.

    • A regression in 5.28 caused the following code to fail 
      close(STDIN); open(CHILD, "|wc -l")'

      because the child's stdin would be closed on exec. This has now been fixed.

    • Fixed an issue where compiling a regexp containing both compile-time and run-time code blocks could lead to trying to compile something which is invalid syntax.
    • Fixed build failures with "-DNO_LOCALE_NUMERIC" and . [GH #16771] https://github.com/Perl/perl5/issues/16771.
    • Prevent the tests in ext/B/t/strict.t from being skipped. [GH #16783] https://github.com/Perl/perl5/issues/16783.
    • nodes ending or beginning in s are now "EXACTF". We do not want two "EXACTFU" to be joined together during optimization, and to form a "ss", "sS", "Ss" or "SS" sequence; they are the only multi-character sequences which may match differently under and .
