versión 5.20250619

DESCRIPCIÓN

Esta sección del FAQ responde preguntas sobre dónde encontrar el código fuente y la documentación de Perl, soporte y asuntos relacionados.

¿Qué máquinas soportan Perl? ¿Dónde lo consigo?

La distribución estándar de Perl (la mantenida por el equipo de desarrollo de Perl) se distribuye únicamente en forma de código fuente. Puedes encontrar las últimas versiones en http://www.cpan.org/src/.

Perl compila y se ejecuta en un número asombroso de plataformas. Prácticamente todos los derivados de Unix conocidos y actuales son soportados (la plataforma nativa de perl), así como otros sistemas como VMS, DOS, OS/2, Windows, QNX, BeOS, OS X, MPE/iX y Amiga.

Las distribuciones binarias para algunas plataformas propietarias se pueden encontrar en el directorio http://www.cpan.org/ports/. Dado que estas no forman parte de la distribución estándar, pueden diferir y de hecho difieren de la versión base de Perl en una variedad de formas. Tendrás que consultar sus notas de lanzamiento respectivas para ver cuáles son las diferencias. Estas diferencias pueden ser positivas (por ejemplo, extensiones para las características de la plataforma en particular que no son soportadas en la versión fuente de perl) o negativas (por ejemplo, podrían basarse en una versión fuente de perl menos actualizada).

¿Cómo puedo obtener una versión binaria de Perl?

Ver Puertos de CPAN en http://www.cpan.org/ports/

No tengo un compilador C. ¿Cómo puedo construir mi propio intérprete de Perl?

Para Windows, utiliza una versión binaria de Perl. Strawberry Perl http://strawberryperl.com/ y ActivePerl http://www.activestate.com/activeperl vienen con un compilador C incluido.

Por lo demás, si realmente quieres construir Perl, primero necesitas obtener una versión binaria de "gcc" para tu sistema. Usa un motor de búsqueda para averiguar cómo hacer esto para tu sistema operativo.

Copí el binario de Perl de una máquina a otra, pero los scripts no funcionan.

Eso es probablemente porque olvidaste las bibliotecas, o las rutas de las bibliotecas difieren. Realmente deberías compilar toda la distribución en la máquina donde vivirá finalmente, y luego escribir "make install". La mayoría de los otros enfoques están condenados al fracaso.

Una forma sencilla de comprobar que las cosas están en el lugar correcto es imprimir la lista codificada de forma rígida @INC que perl busca para las bibliotecas:

% perl -le 'print for @INC'

Si este comando lista alguna ruta que no existe en tu sistema, entonces podrías necesitar mover las bibliotecas apropiadas a estas ubicaciones, o crear enlaces simbólicos, alias o atajos apropiados. @INC también se imprime como parte de la salida de

% perl -V

También podrías querer consultar "¿Cómo mantengo mi propio directorio de módulos/bibliotecas?" en perlfaq8.

Obtuve las fuentes e intenté compilar pero gdbm/carga dinámica/malloc/enlace/... falló. ¿Cómo hago que funcione?

Lee el archivo INSTALL, que forma parte de la distribución fuente. Describe en detalle cómo lidiar con la mayoría de las idiosincrasias que el script "Configure" no puede solucionar para un sistema o arquitectura dada.

¿Qué módulos y extensiones están disponibles para Perl? ¿Qué es CPAN?

CPAN significa Comprehensive Perl Archive Network (Red de Archivos Exhaustivos de Perl), un archivo de varios gigabytes replicado en cientos de máquinas en todo el mundo. CPAN contiene decenas de miles de módulos y extensiones, código fuente y documentación, diseñados para *todo*, desde interfaces de bases de datos comerciales hasta control de teclado/pantalla y ejecución de grandes sitios web.

Puedes buscar en CPAN en http://metacpan.org.

El sitio web principal de CPAN es http://www.cpan.org/; http://www.cpan.org/SITES.html lista todos los espejos.

Consulta el FAQ de CPAN en http://www.cpan.org/misc/cpan-faq.html para obtener respuestas a las preguntas más frecuentes sobre CPAN.

El módulo Task::Kensho tiene una lista de módulos recomendados que deberías revisar como un buen punto de partida.

¿Dónde puedo obtener información sobre Perl?

  • http://www.perl.org/
  • http://perldoc.perl.org/
  • http://learn.perl.org/

La documentación completa de Perl está disponible con la distribución de Perl. Si tienes Perl instalado localmente, probablemente también tengas la documentación instalada: escribe "perldoc perl" en una terminal o visualízala en línea en http://perldoc.perl.org/perl.html.

(Algunas distribuciones de sistemas operativos pueden incluir la documentación en un paquete diferente; por ejemplo, en Debian, necesitas instalar el paquete "perl-doc".)

Se han escrito muchos libros buenos sobre Perl; consulta la sección "Libros de Perl" para más detalles.

¿Qué es perl.com? ¿Perl Mongers? ¿pm.org? ¿perl.org? ¿cpan.org?

Perl.com http://www.perl.com/ solía ser parte de O'Reilly Network, una subsidiaria de O'Reilly Media. Aunque conserva la mayor parte del contenido original de su O'Reilly Network, ahora es alojado por The Perl Foundation http://www.perlfoundation.org/.

The Perl Foundation es una organización de defensa del lenguaje Perl que mantiene el sitio web http://www.perl.org/ como un sitio general de promoción del lenguaje Perl. Utiliza el dominio para proporcionar servicios generales de soporte a la comunidad Perl, incluyendo el alojamiento de listas de correo, sitios web y otros servicios. También hay muchos otros subdominios para temas especiales como aprender Perl y trabajos en Perl, tales como:

  • http://www.perl.org/
  • http://learn.perl.org/
  • http://jobs.perl.org/
  • http://lists.perl.org/

Perl Mongers http://www.pm.org/ utiliza el dominio pm.org para servicios relacionados con grupos locales de usuarios de Perl, incluyendo el alojamiento de listas de correo y sitios web. Consulta el sitio web de Perl Mongers http://www.pm.org/ para más información sobre cómo unirse, iniciar o solicitar servicios para un grupo de usuarios de Perl.

CPAN, o Comprehensive Perl Archive Network http://www.cpan.org/, es un repositorio replicado a nivel mundial de software Perl. Ver ¿Qué es CPAN?.

perlfaq - Answers to Frequently Asked Questions about Perl

VERSION

This document describes version 5.005_03 of Perl.

DESCRIPTION

This document is a collection of answers to frequently asked questions about Perl. It is broken down into several sections, each dealing with a specific topic.

Where can I ask questions about Perl?

The Perl community offers several avenues for asking questions and getting help. The most prominent are:

  • The Perl mailing lists, available at https://lists.perl.org for various topics, specifically the beginners list http://lists.perl.org/list/beginners.html may be of use.

  • Other places to ask questions are on the PerlMonks site http://www.perlmonks.org/ or stackoverflow http://stackoverflow.com/questions/tagged/perl.

Perl Books

There are many good books on Perl http://www.perl.org/books/library.html.

Which magazines have Perl content?

There are no current magazines that focus on Perl, although you sometimes will find Perl content in more general interest programming titles.

In the distant past, there have been a few Perl magazines. The first was The Perl Journal, published by Jon Orwant. After that, there was The Perl Review, published by brian d foy, and $foo Magazin, published by Renée Bäcker (http://www.foo-magazin.de).

The closest you might find today is Perl Weekly, (https://perlweekly.com), an online newsletter with a magazine-like format.

Which Perl blogs should I read?

Perl News http://perlnews.org/ covers some of the major events in the Perl world, Perl Weekly http://perlweekly.com/ is a weekly e-mail (and RSS feed) of hand-picked Perl articles.

http://blogs.perl.org/ hosts many Perl blogs, there are also several blog aggregators: Perlsphere http://perlsphere.net/ and IronMan http://ironman.enlightenedperl.org/ are two of them.

What mailing lists are there for Perl?

A comprehensive list of Perl-related mailing lists can be found at http://lists.perl.org/

Where can I buy a commercial version of Perl?

Perl already is commercial software: it has a license that you can grab and carefully read to your manager. It is distributed in releases and comes in well-defined packages. There is a very large and supportive user community and an extensive literature.

If you still need commercial support ActiveState http://www.activestate.com/activeperl offers this.

Where do I send bug reports?

(contributed by brian d foy)

First, ensure that you've found an actual bug. Second, ensure you've found an actual bug.

If you've found a bug with the perl interpreter or one of the modules in the standard library (those that come with Perl), submit a bug report to the GitHub issue tracker at https://github.com/Perl/perl5/issues.

To determine if a module came with your version of Perl, you can install and use Module::CoreList. It knows the modules (with their versions) included with each release of Perl:

$ corelist File::Copy
Data for 2023-07-02
File::Copy was first released with perl 5.002
$ corelist Business::ISBN
Data for 2023-07-02
Business::ISBN was not in CORE (or so I think)

If the module does not come with Perl, report its issues using the tool that the particular module author decided to use, such as a GitHub or Google Code. The quickest way may be to check the MetaCPAN page for the module (for example, https://metacpan.org/pod/Business::ISBN), which shows the denoted bugtracker in the left sidebar as the "Issues" link.

Also check the module's documentation, README, the build files (Makefile.PL or "Build.PL"), or META.{json,yml} files. Although many module authors follow the same pattern, some have their own way. Use the directions you find.

Sometimes the module author does not declare a bugtracker. For a long time, everyone assumed that the CPAN Request Tracker (https://rt.cpan.org) was the bugtracker since every distribution had an RT queue generated automatically. In some cases, the author might use CPAN RT. They also might have not declared a different bugtracker but don't use CPAN RT.

Submit bugs to RT either through its web interface, https://rt.cpan.org, or by email. Send email to bug-<distribution-name>@rt.cpan.org. For example, if you wanted to report a bug in the example module "Foo::Bar", you could send a message to bug-Foo-Bar@rt.cpan.org.
