PERL5360DELTA(1perl) Guía de Referencia del Programador de Perl PERL5360DELTA(1perl)

NOMBRE

perl5360delta - qué hay de nuevo en la versión perl v5.36.0

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.34.0 y la versión 5.36.0.

Mejoras del núcleo

"use v5.36"

Como siempre, "use v5.36" activa el conjunto de características para esa versión de Perl.

El conjunto de características 5.36 activa la característica "signatures". Introducida en la versión de Perl 5.20.0 y modificada varias veces desde entonces, la característica de firmas de subrutinas ya no se considera experimental. Ahora se considera una característica estable del lenguaje y ya no imprime una advertencia.

use v5.36;
sub add ($x, $y) {
  return $x + $y;
}

A pesar de esto, ciertos elementos de las subrutinas con firmas siguen siendo experimentales; véase más abajo.

El conjunto de características 5.36 activa la característica "isa". Introducida en la versión de Perl 5.32.0, este operador no ha cambiado desde entonces. El operador ahora se considera una característica estable del lenguaje. Para más detalles, véase "Class Instance Operator" en perlop.

El conjunto de características 5.36 también *desactiva* las características "indirect" y "multidimensional". Estas prohibirán, respectivamente: el uso de llamadas a métodos "indirectas" (como "$x = new Class;"); el uso de una expresión de lista como clave de hash para simular arrays multidimensionales dispersos. Los detalles de estos cambios se pueden encontrar en feature, pero la versión corta es: esto es un poco como tener más "use strict" activado, deshabilitando características que causan más problemas de los que valen.

Además, "use v5.36" también activará advertencias como si hubieras escrito "use warnings".

Finalmente, con esta versión, la característica experimental "switch", presente en cada conjunto de características desde que se introdujeron en v5.10, ha sido eliminada del conjunto de características v5.36. Si quieres usarla (contra nuestro consejo), tendrás que activarla explícitamente.

bandera de línea de comandos -g

Hay disponible una nueva bandera de línea de comandos, -g. Es un alias más simple para -0777.

Para más información, véase "-g" en perlrun.

Unicode 14.0 se admite

Véase https://www.unicode.org/versions/Unicode14.0.0/ para más detalles.

los conjuntos de expresiones regulares ya no se consideran experimentales

Antes de esta versión, la característica de conjuntos de expresiones regulares (denominada oficialmente "Clases de caracteres entre corchetes extendidas") se consideraba experimental. Introducida en la versión de Perl 5.18.0 y modificada varias veces desde entonces, ahora se considera una característica estable del lenguaje y su uso ya no imprime una advertencia. Véase "Extended Bracketed Character Classes" en perlrecharclass.

la búsqueda hacia atrás de longitud variable ya no se considera experimental en su mayoría

Antes de esta versión, cualquier forma de búsqueda hacia atrás de longitud variable se consideraba experimental. Con esta versión, el estado experimental se ha reducido para cubrir solo la búsqueda hacia atrás que contiene paréntesis de captura. Esto se debe a que no está claro si

"aaz"=~/(?=z)(?<=(a|aa))/

debería coincidir y dejar $1 igual a "a" o "aa". Actualmente, coincidirá con la alternativa más larga posible, "aa". Si bien estamos seguros de que la construcción general ahora coincidirá solo cuando deba hacerlo, no estamos seguros de que mantengamos el comportamiento actual de "coincidencia más larga".

SIGFPE ya no se pospone

Las excepciones de punto flotante ahora se entregan inmediatamente, de la misma manera que otras señales de "fallo" como SIGSEGV. Esto significa que uno tiene al menos una oportunidad de capturar tal señal con un manejador $SIG{FPE}, por ejemplo, para que "die" pueda informar la línea en perl que la activó.

seguimiento booleano estable

Los valores booleanos "verdadero" y "falso", a menudo accedidos por construcciones como "!!0" y "!!1", así como siendo devueltos por muchas funciones y operadores principales, ahora recuerdan su naturaleza booleana incluso a través de la asignación a variables. La nueva función is_bool() en builtin puede comprobar si un valor tiene naturaleza booleana.

Esto probablemente será útil al interoperar con otros lenguajes o serialización de tipos de datos, entre otros lugares.

iterando sobre múltiples valores a la vez (experimental)

Ahora puedes iterar sobre múltiples valores a la vez especificando una lista de léxicos entre paréntesis. Por ejemplo,

for my ($key, $value) (%hash) { ... }
for my ($left, $right, $gripping) (@moties) { ... }

Antes de perl v5.36, intentar especificar una lista después de "for my" era un error de sintaxis.

Esta característica es actualmente experimental y causará una advertencia de la categoría "experimental::for_list". Para más detalles, véase "Compound Statements" en perlsyn. Véase también "builtin::indexed" en este documento, que es un compañero útil para el foreach n-a-la-vez.

funciones builtin (experimental)

Se ha añadido un nuevo módulo principal, builtin, que proporciona documentación para nuevas funciones siempre presentes que están integradas en el intérprete.

say "Reference type of arrays is ", builtin::reftype([]);

También proporciona un mecanismo de importación léxico para proporcionar versiones de nombre corto de estas funciones.

use builtin 'reftype';
say "Reference type of arrays is ", reftype([]);

Este mecanismo de funciones builtin y las funciones que proporciona son actualmente **experimentales**. Esperamos que "builtin" en sí deje de ser experimental en un futuro próximo, pero que las funciones individuales en él puedan volverse estables de forma continua. Se añadirán otras funciones a "builtin" con el tiempo.

Para más detalles, véase builtin, pero aquí tienes un resumen de las funciones builtin en v5.36:

builtin::trim
Esta función trata su argumento como una cadena, devolviendo el resultado de eliminar todos los espacios en blanco al principio y al final.
builtin::indexed
Esta función devuelve una lista el doble de grande que la lista de argumentos, donde cada elemento va precedido por su índice dentro de esa lista. Esto es principalmente útil para usar la nueva sintaxis de "foreach" con múltiples variables iteradoras para iterar sobre un array o lista, mientras se rastrea también el índice de cada elemento: 
use builtin 'indexed';
foreach my ($index, $val) (indexed @array) {
    ...
}
builtin::true, builtin::false, builtin::is_bool
"true" y "false" devuelven valores booleanos verdaderos y falsos. Perl sigue siendo perl, y no tiene tipos estrictos de booleanos, pero estos valores serán conocidos por haber sido creados como booleanos. "is_bool" te dirá si un valor está

Builtin Functions

builtin::abs, builtin::int
These functions provide a version of the built-in Perl functions that are known to have been created as a boolean.
builtin::weaken, builtin::unweaken, builtin::is_weak
These functions will, respectively: weaken a reference; strengthen a reference; and return whether a reference is weak. (A weak reference is not counted for garbage collection purposes. See perlref.) These can take the place of some similar routines in Scalar::Util.
builtin::blessed, builtin::refaddr, builtin::reftype
These functions provide more data about references (or non-references, actually!) and can take the place of similar routines found in Scalar::Util.
builtin::ceil, builtin::floor
"ceil" returns the smallest integer greater than or equal to its argument. "floor" returns the largest integer less than or equal to its argument. These can take the place of similar routines found in POSIX.

"defer" bloques (experimental)

Este lanzamiento añade soporte para bloques "defer", que son bloques de código precedidos por el modificador "defer". Proporcionan una sección de código que se ejecuta en un momento posterior, durante la salida del ámbito.

En resumen, cuando se alcanza un bloque "defer" en tiempo de ejecución, su cuerpo se reserva para ser ejecutado cuando se sale del ámbito que lo contiene. No es similar a un UNITCHECK (entre otras razones) ya que si el bloque *que contiene* el bloque "defer" se sale antes de que se alcance el bloque, este último no se ejecutará.

"defer" bloques pueden usarse para reemplazar objetos de "guardia de ámbito" donde se pasa a un objeto un bloque de código para ser ejecutado por su destructor.

Para más información, véase "Bloques defer" en perlsyn.

try/catch ahora puede tener un bloque "finally" (experimental)

La sintaxis experimental "try"/"catch" se ha ampliado para soportar un tercer bloque opcional introducido por la palabra clave "finally".

try {
    attempt();
    print "Success\n";
}
catch ($e) {
    print "Failure\n";
}
finally {
    print "Esto sucede sin importar qué\n";
}

Esto proporciona código que se ejecuta al final de la constructo "try"/"catch", incluso si es interrumpida por una excepción o una palabra clave de flujo de control. Son similares a los bloques "defer".

Para más información, véase "Manejo de excepciones Try Catch" en perlsyn.

delimitadores no ASCII para operadores tipo comilla (experimental)

Tradicionalmente, Perl solo ha permitido cuatro pares de delimitadores de cadena/patrón: "( )" "{ }" "[ ]" y "< >", todos en el rango ASCII. Unicode tiene cientos de posibilidades más, y el uso de esta característica habilita muchas de ellas. Cuando está habilitado, puedes decir "qr« »" por ejemplo, o "use utf8; q𝄃cadena𝄂". Ver "La característica 'extra_paired_delimiters'" en feature para detalles.

@_ es ahora experimental dentro de subs con firma

Aunque las firmas de subrutinas ahora son estables, el uso del array de argumentos heredado (@_) con una subrutina que tiene una firma *sigue siendo* experimental, con su propia categoría de advertencia. Silenciar la categoría de advertencia "experimental::signatures" no es suficiente para descartar esto. La nueva advertencia se emite con el nombre de categoría "experimental::args_array_with_signatures".

Cualquier subrutina que tenga una firma e intente usar el array de argumentos por defecto o un elemento de él (@_ o $_[INDEX]), ya sea explícita o implícitamente (como "shift" o "pop" sin argumento), provocará una advertencia en tiempo de compilación:

use v5.36;
sub f ($x, $y = 123) {
  say "El primer argumento es $_[0]";
}
El uso de @_ en un elemento de array con subrutina con firma es experimental
en file.pl línea 4.

El comportamiento del código que intenta hacer esto ya no está especificado y puede estar sujeto a cambios en una versión futura.

Cambios Incompatibles

Un sort físicamente vacío es ahora un error en tiempo de compilación

@a = sort @empty; # sin afectar
@a = sort;        # ahora un error en tiempo de compilación
@a = sort ();     # también un error en tiempo de compilación

Un sort desnudo solía ser una forma extraña de crear una lista vacía; ahora falla en tiempo de compilación. Este cambio tiene la intención de liberar parte del espacio de sintaxis para posibles mejoras futuras de "sort".

Deprecaciones

"use VERSION" (donde VERSION es inferior a v5.11) después de "use v5.11" está deprecado

Cuando se está en el ámbito de "use v5.11" o posterior, una línea "use vX" donde X es inferior a v5.11 ahora emitirá una advertencia:

La declaración de uso de VERSION degradándose a versiones inferiores a v5.11 está deprecada

Por ejemplo:

use v5.14;
say "La declaración say está permitida";
use v5.8;                               # Esto imprimirá una advertencia
print "Debemos usar print\n";

Esto se debe a que el equipo de Perl planea cambiar el comportamiento en este caso. Desde Perl v5.12 (y partes de v5.11), strict está habilitado *a menos que se haya deshabilitado previamente*. En otras palabras:

no strict;
use v5.12;  # no habilitará strict, porque "no strict" lo precedió
$x = 1;     # permitido, a pesar de no haber declaración "my"

En el futuro, este comportamiento se eliminará y "use VERSION" siempre habilitará strict para las versiones v5.12 y posteriores.

El código que desee mezclar versiones de esta manera debe usar ámbitos léxicos con sintaxis de bloque para asegurar que las regiones con versiones diferentes permanezcan léxicamente aisladas.

{
    use v5.14;
    say "La declaración say está permitida";
}
{
    use v5.8;                           # No se emite ninguna advertencia
    print "Debemos usar print\n";
}

Por supuesto, ¡esto probablemente no es algo que necesites hacer! Si el primer bloque compila, significa que estás usando perl v5.14.0 o posterior.

Mejoras de Rendimiento

  • Ahora sondeamos el soporte del compilador para almacenamiento local de hilos C11, y cuando está disponible, lo usamos para el "contexto implícito" para extensiones XS que realizan llamadas a la API para una compilación de Perl multihilo. Esto requiere menos llamadas a funciones a nivel de C que el almacenamiento específico de hilos POSIX. Continuamos usando el enfoque pthreads si el enfoque C11 no está disponible.

    Configure ejecutado con los valores predeterminados compilará un Perl no multihilo (que es ligeramente más rápido), pero la mayoría de los sistemas operativos distribuyen un Perl multihilo.

  • Perl ahora puede configurarse para dejar de asignar claves para hashes grandes de la tabla de cadenas compartida.

    El mismo tipo de dato interno ("PVHV") se utiliza para todos los elementos de

  • Tablas de símbolos
  • Objetos (por defecto)
  • Arrays asociativos

La tabla de cadenas compartida se agregó originalmente para mejorar el rendimiento de los hashes bendecidos utilizados como objetos, ya que cada instancia de objeto tiene las mismas claves, por lo que es una optimización compartir memoria entre ellos. También tiene sentido para las tablas de símbolos, donde las clases derivadas tendrán las mismas claves (típicamente nombres de métodos), y los árboles OP construidos para llamadas a métodos también pueden compartir memoria. La tabla de cadenas compartida se comporta aproximadamente como una caché para claves de hash.

Pero para los hashes realmente utilizados como arrays asociativos, que mapean claves a valores, típicamente las claves no se reutilizan en otros hashes. Por ejemplo, los hashes de "vistos" se indexan por IDs de objeto (o direcciones), y lógicamente estas claves no se repetirán en otros hashes.

Almacenar estas claves "usadas solo una vez" en la tabla de cadenas compartida aumenta el uso de CPU y RAM sin ningún beneficio. Para dichas claves, la tabla de cadenas compartida se comporta como una caché con una tasa de aciertos del 0%. Almacenar todas las claves allí aumenta el tamaño total de la tabla de cadenas compartida, así como el número de veces que se redimensiona a medida que crece. *Peor aún*, en cualquier entorno que tenga memoria de "copia en escritura" para procesos hijos (como un servidor con pre-forking), las páginas de memoria utilizadas para la tabla de cadenas compartida necesitan copiarse rápidamente a medida que el proceso hijo manipula los hashes. Por lo tanto, si la mayor parte de la tabla de cadenas compartida es tal que las claves se usan solo en un lugar, no hay beneficio por la reutilización dentro del intérprete de perl, pero sí un alto costo debido a más páginas que el sistema operativo debe copiar.

El intérprete de perl ahora puede configurarse para deshabilitar las claves de hash compartidas para hashes "grandes" (que no son ni objetos ni tablas de símbolos). Para hacerlo, agregue "-Accflags='-DPERL_USE_UNSHARED_KEYS_IN_LARGE_HASHES'" al ejecutar Configure.

a sus opciones de Configurar. "Grande" es una heurística; actualmente, la heurística es que el intercambio se deshabilita cuando al agregar una clave a un hash se activa la asignación de más almacenamiento y el hash tiene más de 42 claves.

Esto podría causar un uso de memoria ligeramente mayor para programas que crean estructuras de datos (no bendecidas) que contienen varios hashes grandes que comparten las mismas claves. Pero, en general, nuestras pruebas sugieren que para los casos específicos descritos es una ventaja y otro código no se ve afectado.

•
En ciertos escenarios, la creación de nuevos escalares es ahora notablemente más rápida.

Por ejemplo, el siguiente código se está ejecutando ~30% más rápido:

$str = "A" x 64;
for (0..1_000_000) {
    @svs = split //, $str
}

(Puede leer más sobre este en [perl #19414] https://github.com/Perl/perl5/pull/19414.)

Diagnósticos

Se han realizado las siguientes adiciones o cambios en la salida de diagnóstico, incluyendo advertencias y mensajes de error fatales. Para la lista completa de mensajes de diagnóstico, consulte perldiag.

Nuevos Diagnósticos

Nuevos Errores

  • No se puede salir de un bloque "defer" con "%s"

    (F) Se intentó saltar del ámbito de un bloque defer mediante una declaración de flujo de control como "return", "goto" o un control de bucle. Esto no está permitido.

  • No se puede modificar %s en %s (para asignación escalar a "undef")

    Intentar realizar una asignación escalar a "undef", por ejemplo a través de "undef = $foo;", anteriormente activaba un error fatal en tiempo de ejecución con el mensaje "Intentando modificar un valor de solo lectura." Es más útil detectar tales intentos de asignación antes del tiempo de ejecución, por lo que ahora son errores en tiempo de compilación, resultando en el mensaje "No se puede modificar el operador undef en asignación escalar".

Nuevos diagnósticos

  • panic: newFORLOOP, %s

    El analizador falló una comprobación interna de coherencia al intentar analizar un bucle "foreach".

Nuevas advertencias

  • La función incorporada '%s' es experimental

    Se está realizando una llamada a una función en el espacio de nombres "builtin::", que actualmente es experimental.

  • defer es experimental

    El modificador de bloque "defer" es experimental. Si desea usar esta función, desactive la advertencia con "no warnings 'experimental::defer'", pero tenga en cuenta que al hacerlo corre el riesgo de que su código pueda romperse en una futura versión de Perl.

  • La degradación de una declaración use VERSION a una versión inferior a v5.11 está obsoleta

    Esta advertencia se emite en una declaración "use VERSION" que solicita una versión inferior a v5.11 (cuando los efectos de "use strict" se deshabilitarían), después de una declaración previa de una con un número mayor (que habría habilitado estos efectos).

  • for my (...) es experimental

    Esta advertencia se emite si usa "for" para iterar varios valores a la vez. Esta sintaxis es actualmente experimental y su comportamiento puede cambiar en futuras versiones de Perl.

  • El uso implícito de @_ en %s con subrutinas con firma es experimental

    Se encontró una expresión que involucra implícitamente el array de argumentos @_ en una subrutina que usa una firma.

  • El uso de @_ en %s con subrutinas con firma es experimental

    Se encontró una expresión que involucra el array de argumentos @_ en una subrutina que usa una firma.

  • Carácter ancho en $0

    Los intentos de insertar caracteres anchos en el nombre del programa ($0) ahora provocan esta advertencia.

Cambios en diagnósticos existentes

  • '/' no toma un recuento de repetición en %s

    Esta advertencia solía no incluir el "in %s".

  • La subrutina %s se redefinió

    Las redefiniciones de subrutinas localizadas ya no activan esta advertencia.

  • unexpected constant lvalue entersub entry via type/targ %d:%d" ahora tiene un prefijo de pánico

    Esto lo hace coherente con otras comprobaciones de coherencia interna al compilar una subrutina.

  • Useless use of sort in scalar context ahora está en la nueva categoría "scalar".

    Cuando "sort" se utiliza en contexto escalar, provoca una advertencia de que hacer esto no es útil. Esta advertencia solía estar en la categoría "void". Ahora se ha agregado una nueva categoría para advertencias sobre el contexto escalar, llamada "scalar".

  • Se eliminaron varios diagnósticos

    Muchos diagnósticos que se han eliminado del núcleo de perl a lo largo de muchos años ahora también se han eliminado de la documentación.

Configuración y compilación

  • El código fuente de Perl C ahora utiliza algunas características de C99, que hemos verificado que son compatibles con todos los compiladores que dirigimos. Esto significa que las cabeceras de Perl ahora contienen código que es legal en C99 pero no en C89.

    Esto puede causar problemas para algunos módulos XS que agregan incondicionalmente "-Werror=declaration-after-statement" a sus flags del compilador C si compilan con gcc o clang. Versiones anteriores de Perl admiten compiladores obsoletos que son estrictos al rechazar ciertas características de C99, particularmente declaraciones y código mezclados, y por lo tanto tiene sentido que los autores de módulos XS auditen que su código no viole esto. Sin embargo, hacer esto ahora solo es posible en estas versiones anteriores de Perl, por lo que estos módulos deben modificarse para agregar esta bandera solo para "$] < 5.035005".

  • El paso makedepend ahora se ejecuta en paralelo usando make

    Cuando se usan MAKEFLAGS=-j8, esto reduce significativamente el tiempo requerido para:

    sh ./makedepend MAKE=make cflags
  • Configure ahora prueba si se requiere "#include <xlocale.h>" para usar las funciones de localización seguras para hilos POSIX 1003 o algunas extensiones relacionadas. Esto previene problemas donde un xlocale.h no público se elimina en una actualización de biblioteca, o xlocale.h no está destinado al uso público. (github #18936 https://github.com/Perl/perl5/pull/18936)

Pruebas

Se agregaron y modificaron pruebas para reflejar las otras adiciones y cambios en esta versión.

Soporte de plataforma

Windows

  • Se eliminó el soporte para MSVC++ antiguo (anterior a VC12)

    Estos no admitían C99 y, por lo tanto, ya no se pueden usar para compilar perl.

  • Se agregó soporte para compilar perl en Windows usando Microsoft Visual Studio 2022 (que contiene Visual C++ 14.3).
  • Se eliminó la capa IO :win32. Este reemplazo experimental para la capa :unix nunca alcanzó la madurez en sus casi dos décadas de existencia.

VMS

"keys %ENV" en VMS devuelve resultados consistentes
En VMS, las entradas en el hash %ENV se cargan del entorno del sistema operativo en el primer acceso, por lo que la primera iteración de %ENV requiere que se escanee todo el entorno para encontrar todas las claves posibles. Esta inicialización siempre se había realizado correctamente para la iteración completa, pero anteriormente no se estaba realizando para %ENV en contexto escalar, lo que significa que "scalar %ENV" devolvería 0 si se llamaba antes de cualquier otro acceso a %ENV, o solo devolvería el recuento de claves accedidas si no hubiera habido iteración.

Estos errores ahora están corregidos: %ENV y "keys %ENV" en contexto escalar ahora devuelven el resultado correcto: el recuento de todas las claves en el entorno.

Plataformas descontinuadas

AT&T UWIN
UWIN es una capa de compatibilidad UNIX para Windows. Se lanzó por última vez en 2012 y ha sido reemplazado por Cygwin en la actualidad.
DOS/DJGPP
DJGPP es un puerto de la cadena de herramientas GNU a sistemas x86 de 32 bits que ejecutan DOS. El último intento conocido de compilar Perl en él fue en 5.20, que solo llegó a compilar minIPerl.
NetWare
Se ha eliminado el código de soporte para Novell NetWare. NetWare era un sistema operativo de servidor de Novell. El puerto se actualizó por última vez en julio de 2002 y la plataforma en sí en mayo de 2009.

Cambios no relacionados rompieron accidentalmente la compilación para el puerto NetWare en septiembre de 2009, y en 12 años nadie ha informado de esto.

Notas específicas de la plataforma

z/OS
Esta actualización nos permite compilar Perl estático/dinámico EBCDIC y en modo de direccionamiento de 31 bits/64 bits. El número de pruebas que pasan es coherente con la línea base anterior a estas actualizaciones.

Estos cambios también proporcionan la base de soporte para poder proporcionar Perl estático/dinámico ASCII y en modo de direccionamiento de 31 bits/64 bits.

El README de z/OS (anteriormente llamado OS/390) se actualizó para describir las compilaciones ASCII y EBCDIC.

  • Leer la forma de cadena de un valor entero ya no establece el flag "SVf_POK". La forma de cadena todavía se almacena en caché internamente y todavía se lee directamente por las macros SvPV(sv) *et al.* (en línea, sin llamar a una función C). El código XS que ya llama a las APIs para obtener valores no se verá afectado por este cambio. El código XS que accede a los flags directamente en lugar de usar llamadas a la API para expresar su intención *podría* romperse, pero dicho código probablemente ya tenga errores si se le pasan otros valores, como valores de punto flotante u objetos con sobrecarga de cadenas.

    Este pequeño cambio permite que el código (como los serializadores JSON) determine de manera fiable entre:

  • un valor que se escribió inicialmente como un entero, pero luego se leyó como una cadena 
    my $answer = 42;
print "The answer is $answer\n";
  • ese mismo valor que se escribió inicialmente como una cadena, pero luego se leyó como un entero 
    my $answer = "42";
print "That doesn't look right\n"
    unless $answer == 6 * 9;

Para el primer caso (escrito originalmente como un entero), ahora tenemos:

use Devel::Peek;
my $answer = 42;
Dump ($answer);
my $void = "$answer";
print STDERR "\n";
Dump($answer)

  FLAGS = (IOK,pIOK)
  IV = 42

  REFCNT = 1
  FLAGS = (IOK,pIOK,pPOK)
  IV = 42
  PV = 0x562538919b50 "42"\0
  CUR = 2
  LEN = 10

Para el segundo (escrito originalmente como una cadena), ahora tenemos:

use Devel::Peek;
my $answer = "42";
Dump ($answer);
my $void = $answer == 6 * 9;
print STDERR "\n";
Dump($answer)'

  COW_REFCNT = 1

  REFCNT = 1

(No se puede confiar en la presencia o ausencia del flag "SVf_IsCOW" para determinar el historial de operaciones en un escalar.)

Anteriormente, ambos casos serían indistinguibles, con los 4 flags establecidos:

SV = PVIV(0x55d4d62edaf0) at 0x55d4d62f0930
  REFCNT = 1

(y posiblemente "SVf_IsCOW", pero no siempre)

Esto ahora significa que si el código XS *realmente* necesita determinar en qué forma se escribió por primera vez un valor, debe implementar una lógica aproximadamente así:

if (flags & SVf_IOK|SVf_NOK) && !(flags & SVf_POK)
    serialize as number
else if (flags & SVf_POK)
    serialize as string
else
    the existing guesswork ...

Tenga en cuenta que esto no cubre los "dualvars": escalares que devuelven valores diferentes cuando se les pide su forma de cadena o su forma numérica (como $!). La mayoría de los formatos de serialización no pueden representar tal duplicidad.

El *adivinar existente* permanece porque además de los dualvars, los valores pueden ser "undef", referencias, referencias sobrecargadas, typeglobs y otras cosas que Perl mismo puede representar pero que no se mapean uno a uno en formatos externos, por lo que necesitan cierta aproximación o encapsulación.

•
"sv_dump" (y la función "Dump" de Devel::Peek) ahora escapan los octetos de bit alto en el PV como hexadecimal en lugar de octal. Dado que la mayoría de la gente entiende mejor el hexadecimal que el octal, esto debería hacer que estos volcados sean un poco más legibles. Esto *no* afecta a ninguna otra interfaz de diagnóstico como "pv_display".

Errores Corregidos Seleccionados

  • utime() ahora establece correctamente errno/$! cuando se llama en un manejador cerrado.
  • Los flags en el parámetro OPTVAL a setsockopt() se comprobaban previamente antes de llamar a magic, posiblemente tratando un valor numérico como un buffer empaquetado o viceversa. También ignoraba el flag UTF-8, tratando potencialmente la representación interna de un SV mejorado como los bytes a suministrar a la llamada del sistema setsockopt(). (github #18660 https://github.com/Perl/perl5/issues/18660)
  • Solo establecer IOKp, no IOK en $) y $(. Este fue el problema #18955 https://github.com/Perl/perl5/issues/18955: Esto evitará que los serializadores serialicen estas variables como números (lo que pierde los grupos adicionales). Esto restaura el comportamiento de la versión 5.16.
  • El uso de la utilidad de depuración "mktables" provocaba que perl fallara desde la v5.31.10; este problema ahora se ha corregido.
  • La lógica de "makedepend" ahora es compatible con make de BSD (corrige GH #19046 https://github.com/Perl/perl5/issues/19046).
  • Llamar a "untie" en un hash enlazado que está a mitad de la iteración ahora libera el estado de iteración inmediatamente.

    Iterar un hash enlazado hace que perl almacene una copia de la clave hash actual para rastrear el estado de iteración, con esta copia almacenada pasada como segundo parámetro a "NEXTKEY". Este estado interno se libera inmediatamente cuando la iteración del hash enlazado se completa, o si el hash se destruye, pero debido a una omisión en la implementación, no se liberaba si el hash se desenlazaba. En ese caso, la copia interna de la clave persistiría hasta la primera de las siguientes opciones:

1.
Se volvió a llamar a "tie" en el mismo hash.
2.
El hash (ahora desenlazado) se iteró (es decir, se pasó a "keys", "values" o "each").
3.
El hash fue destruido.

Esta inconsistencia ahora está corregida: el estado interno se libera inmediatamente por "untie".

Dado que el momento preciso de este comportamiento se puede observar con código Perl puro (el momento de "DESTROY" en objetos devueltos por "FIRSTKEY" y "NEXTKEY"), es posible que algún código sea sensible a ello.

  • La función Internals::getcwd() añadida para arrancar miniperl en perl 5.30.0 ahora solo está disponible en miniperl. [github #19122]
  • Establecer un punto de interrupción en una declaración BEGIN o, equivalente, en una declaración "use" podría provocar una escritura de memoria en un op de "dbstate" liberado. [GH #19198 https://github.com/Perl/perl5/issues/19198]
  • Cuando los filehandles de palabra desnuda están deshabilitados, el analizador interpretaba cualquier palabra desnuda como un filehandle, incluso cuando iba seguida inmediatamente por paréntesis.

DESCRIPTION

This document describes the changes between Perl 5.34.0 and Perl 5.36.0.

Perl 5.36.0 represents the latest stable release of Perl 5. It contains many bug fixes and improvements over previous releases.

This is a partial list of changes. For a more complete list, please see the Changes file in the Perl source distribution.

Core Enhancements

This release includes the following core enhancements:

  • Support for Unicode 14.0.

  • New experimental features, such as:

    • Method call syntax: object->method(args)

    • Class method calls: ClassName->method(args)

    • Lexical subroutines: my sub routine_name { ... }

  • Performance improvements in various areas, including regular expression matching and string operations.

  • Numerous bug fixes and stability improvements.

Incompatible Changes

There are no incompatible changes in this release.

Deprecations

The following features have been deprecated:

  • The goto EXPR construct is now deprecated.

  • The goto &sub construct is now deprecated.

Performance Enhancements

This release includes several performance enhancements:

  • Optimized regular expression matching for certain patterns.

  • Faster string concatenation and manipulation.

  • Improved memory management for large data structures.

Modules and Pragmata

This release includes updated versions of many core modules and pragmata. Notable updates include:

  • Module::CoreList updated to version 5.20220520.

  • CPANPLUS updated to version 0.608.

  • ExtUtils::MakeMaker updated to version 7.70.

  • Test::Harness updated to version 3.44.

Documentation

The documentation has been updated to reflect the changes in this release.

Diagnostics

New diagnostics have been added to improve error reporting.

Configuration and Compilation

No changes in this area.

Testing

No changes in this area.

Platform Support

No changes in this area.

Internal Changes

No changes in this area.

Selected Bug Fixes

This release includes fixes for a number of bugs, including:

  • Fix for a crash when using the \c escape sequence with non-ASCII characters.

  • Fix for a memory leak in the regular expression engine.

  • Fix for a bug in the sprintf function related to floating-point numbers.
