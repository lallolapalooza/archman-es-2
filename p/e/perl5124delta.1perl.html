NOMBRE

perl5124delta - qué hay de nuevo para la versión perl v5.12.4

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.12.3 y la versión 5.12.4.

Si está actualizando desde una versión anterior como la 5.12.2, primero lea perl5123delta, que describe las diferencias entre 5.12.2 y 5.12.3. Los principales cambios realizados en 5.12.0 se describen en perl5120delta.

Cambios incompatibles

No hay cambios intencionalmente incompatibles con 5.12.3. Si existen, son errores y se agradecen los informes.

Correcciones de errores seleccionadas

Cuando el modo estricto "refs" está desactivado, "%{...}" en contexto de rvalue devuelve "undef" si su argumento no está definido. Una optimización introducida en Perl 5.12.0 para hacer que "keys %{...}" sea más rápido cuando se utiliza como booleano no tuvo esto en cuenta, provocando que "keys %{+undef}" (y "keys $foo" cuando $foo no está definido) sea un error, como debería ser solo en modo estricto [perl #81750].

"lc", "uc", "lcfirst" y "ucfirst" ya no devuelven cadenas no contaminadas cuando el argumento está contaminado. Esto ha estado roto desde perl 5.8.9 [perl #87336].

Se corrigió un caso en el que era posible que se leyera de un búfer liberado al analizar un documento here.

Módulos y pragmata

Module::CoreList se ha actualizado de la versión 2.43 a la 2.50.

Pruebas

El script de prueba cpan/CGI/t/http.t se ha corregido para funcionar cuando el entorno tiene variables de entorno HTTPS_*, como HTTPS_PROXY.

Documentación

Se ha actualizado la documentación de rand() en perlfunc para indicar que no es criptográficamente seguro.

Notas específicas de la plataforma

Linux
Se añadió soporte para el nuevo diseño de bibliotecas multi-arquitectura de Ubuntu 11.04.

Agradecimientos

Reporte de errores

Si encuentra lo que cree que es un error, puede consultar los artículos publicados recientemente en el grupo de noticias comp.lang.perl.misc y la base de datos de errores de perl en http://rt.perl.org/perlbug/. También puede haber información en http://www.perl.org/, la página principal de Perl.

Si cree que tiene un error no reportado, ejecute el programa perlbug incluido con su versión. Asegúrese de reducir su error a un caso de prueba pequeño pero suficiente. Su informe de error, junto con la salida de "perl -V", se enviará a perlbug@perl.org para ser analizado por el equipo de portabilidad de Perl.

Si el error que reporta tiene implicaciones de seguridad, que hacen inapropiado enviarlo a una lista de correo con archivo público, entonces por favor envíelo a perl5-security-report@perl.org. Esto apunta a una lista de correo cerrada sin archivo, que incluye a todos los core committers, quienes podrán ayudar a evaluar el impacto de los problemas, encontrar una solución y ayudar a coordinar la publicación de parches para mitigar o corregir el problema en todas las plataformas en las que se soporta Perl. Por favor, use esta dirección solo para problemas de seguridad en el núcleo de Perl, no para módulos distribuidos de forma independiente en CPAN.
