NOMBRE

perlform - Formatos de Perl

DESCRIPCIÓN

Perl tiene un mecanismo para ayudar a generar informes y gráficos simples. Para facilitar esto, Perl te ayuda a codificar tu página de salida cerca de cómo se verá cuando se imprima. Puede hacer un seguimiento de cosas como cuántas líneas hay en una página, qué página estás, cuándo imprimir encabezados de página, etc. Las palabras clave se toman prestadas de FORTRAN: format() para declarar y write() para ejecutar; consulta sus entradas en perlfunc. Afortunadamente, el diseño es mucho más legible, más parecido a la sentencia PRINT USING de BASIC. Piensa en ello como un nroff(1) para pobres.

Los formatos, al igual que los paquetes y las subrutinas, se declaran en lugar de ejecutarse, por lo que pueden aparecer en cualquier punto de tu programa. (Normalmente es mejor mantenerlos todos juntos). Tienen su propio espacio de nombres separado de todos los demás "tipos" en Perl. Esto significa que si tienes una función llamada "Foo", no es lo mismo que tener un formato llamado "Foo". Sin embargo, el nombre predeterminado para el formato asociado con un manejador de archivos dado es el mismo que el nombre del manejador de archivos. Por lo tanto, el formato predeterminado para STDOUT se llama "STDOUT", y el formato predeterminado para el manejador de archivos TEMP se llama "TEMP". Simplemente se ven igual. No lo son.

Los formatos de registro de salida se declaran de la siguiente manera:

format NOMBRE =
LISTA_DE_FORMATO
.

Si se omite el nombre, se define el formato "STDOUT". Se utiliza un solo "." en la columna 1 para terminar un formato. LISTA_DE_FORMATO consta de una secuencia de líneas, cada una de las cuales puede ser de uno de los tres tipos:

1.
Un comentario, indicado al colocar un '#' en la primera columna.
2.
Una línea de "imagen" que proporciona el formato para una línea de salida.
3.
Una línea de argumento que suministra valores para insertar en la línea de imagen anterior.

Las líneas de imagen contienen definiciones de campos de salida, intercaladas con texto literal. Estas líneas no sufren ningún tipo de interpolación de variables. Las definiciones de campos se componen de un conjunto de caracteres, para iniciar y extender un campo a su ancho deseado. Este es el conjunto completo de caracteres para definiciones de campos:

@    inicio de campo regular
^    inicio de campo especial
<    carácter de relleno para justificación izquierda
|    carácter de relleno para centrado
>    carácter de relleno para justificación derecha
#    carácter de relleno para un campo numérico justificado a la derecha
0    en lugar del primer #: rellena el número con ceros a la izquierda
.    punto decimal dentro de un campo numérico
...  termina un campo de texto, muestra "..." como evidencia de truncamiento
@*   campo de ancho variable para un valor de varias líneas
^*   campo de ancho variable para la siguiente línea de un valor de varias líneas
~    suprime la línea con todos los campos vacíos
~~   repite la línea hasta que se agoten todos los campos

Cada campo en una línea de imagen comienza con "@" (arroba) o "^" (acento circunflejo), indicando lo que llamaremos, respectivamente, un campo "regular" o "especial". La elección de los caracteres de relleno determina si un campo es textual o numérico. Los operadores de tilde no forman parte de un campo. Veamos las diversas posibilidades en detalle.

Campos de Texto

La longitud del campo se suministra rellenando el campo con múltiples caracteres "<", ">" o "|" para especificar un campo no numérico con, respectivamente, justificación izquierda, justificación derecha o centrado. Para un campo regular, el valor (hasta la primera nueva línea) se toma e imprime según la justificación seleccionada, truncando los caracteres excedentes. Si termina un campo de texto con "...", se mostrarán tres puntos si el valor se trunca. Un campo de texto especial puede usarse para hacer un relleno rudimentario de bloques de texto de varias líneas; consulte "Uso del Modo de Relleno" para obtener detalles.

Ejemplo:
   format STDOUT =
   @<<<<<<   @||||||   @>>>>>>
   "izquierda",   "medio", "derecha"
   .
Salida:
   izquierda      medio    derecha

Campos Numéricos

Usar "#" como carácter de relleno especifica un campo numérico, con justificación a la derecha. Un "." opcional define la posición del punto decimal. Con un "0" (cero) en lugar del primer "#", el número formateado se rellenará con ceros a la izquierda si es necesario. Un campo numérico especial se pone en blanco si el valor no está definido. Si el valor resultante excediera el ancho especificado, el campo se rellena con "#" como evidencia de desbordamiento.

Ejemplo:
   format STDOUT =
   @###   @.###   @##.###  @###   @###   ^####
    42,   3.1415,  undef,    0, 10000,   undef
   .
Salida:
     42   3.142     0.000     0   ####

El Campo @* para Texto Multilínea de Ancho Variable

El campo "@*" se puede usar para imprimir valores multilínea no truncados; debería (pero no necesariamente) aparecer solo en una línea. Se elimina un salto de línea final, pero todos los demás caracteres se emiten literalmente.

El Campo ^* para Texto de una Línea a la vez de Ancho Variable

Al igual que "@*", este es un campo de ancho variable. El valor proporcionado debe ser una variable escalar. Perl pone la primera línea (hasta la primera "\n") del texto en el campo, y luego corta la parte delantera de la cadena para que la próxima vez que se haga referencia a la variable, se pueda imprimir más texto. La variable *no* se restaurará.

Ejemplo:
   $texto = "línea 1\nlínea 2\nlínea 3";
   format STDOUT =
   Texto: ^*
         $texto
   ~~    ^*
         $texto
   .
Salida:
   Texto: línea 1
         línea 2
         línea 3

Especificación de Valores

Los valores se especifican en la siguiente línea de formato en el mismo orden que los campos de imagen. Las expresiones que proporcionan los valores deben separarse por comas. Todas se evalúan en contexto de lista antes de procesar la línea, por lo que una única expresión de lista podría producir múltiples elementos de lista. Las expresiones pueden distribuirse a más de una línea si están encerradas entre llaves. Si es así, la llave de apertura debe ser el primer token en la primera línea. Si una expresión se evalúa como un número con parte decimal, y si la imagen correspondiente especifica que la parte decimal debe aparecer en la salida (es decir, cualquier imagen excepto múltiples caracteres "#" *sin* un "." incrustado), el carácter utilizado para el punto decimal está determinado por la configuración regional LC_NUMERIC actual si "use locale" está en efecto. Esto significa que, si, por ejemplo, el entorno de ejecución especifica una configuración regional alemana, se utilizará "," en lugar del "." predeterminado. Consulte perllocale y "ADVERTENCIAS" para obtener más información.

Uso del Modo de Relleno

En los campos de texto, el acento circunflejo activa un tipo de modo de relleno. En lugar de una expresión arbitraria, el valor proporcionado debe ser una variable escalar que contenga una cadena de texto. Perl inserta la siguiente porción de texto en el campo y luego trunca la parte inicial de la cadena para que la próxima vez que se haga referencia a la variable, se pueda imprimir más texto. (Sí, esto significa que la variable se altera durante la ejecución de la llamada a write(), y no se restaura). La siguiente porción de texto se determina mediante un algoritmo rudimentario de ruptura de línea. Puede usar el carácter de retorno de carro ("\r") para forzar una ruptura de línea. Puede cambiar qué caracteres son legales para romper modificando la variable $:

(es $FORMAT_LINE_BREAK_CHARACTERS si está usando el módulo English) a una lista de los caracteres deseados.

Normalmente usaría una secuencia de campos en una pila vertical asociada con la misma variable escalar para imprimir un bloque de texto. Es posible que desee terminar el último campo con el texto "...", que aparecerá en la salida si el texto era demasiado largo para aparecer en su totalidad.

Suprimir Líneas donde Todos los Campos están Vacíos

El uso de campos con acento circunflejo puede producir líneas donde todos los campos están en blanco. Puede suprimir tales líneas colocando un "~" (tilde)

Multi-line fields\n

A field starting with ^ allows a single value to span multiple lines. The value is repeatedly printed, each time consuming one line of the format, until the value is exhausted or the format runs out of lines. This is useful for printing long strings, like addresses or descriptions, that may need to wrap.

\n

Example:\n

format multiline =
@<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<
^<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<
.
$long_string = \"This is a very long string that needs to be printed across multiple lines.\";
write;\n
\n\nIn this example, the value of $long_string will be printed, filling the ^<<< field. If the string is longer than the available space, it will wrap to subsequent lines defined by the same field.\n

Repeating format lines\n

If you have two contiguous tilde characters (~~) anywhere in a line, that line will be repeated until all fields on the line are exhausted. This is useful for printing variable-length lists or data structures. The tilde character itself is translated to a space upon output.

\n

Example:\n

format repeating =
Item: @<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<< ~~
$item, $value
.
@items = (\n    [ 'apple', 1 ],\n    [ 'banana', 2 ],\n    [ 'cherry', 3 ],\n);\n\nfor my $item_pair (@items) {\n    my ($item, $value) = @$item_pair;\n    write;\n}\n
\n\nIn this example, each iteration of the loop will print a line with the item and value. The ~~ indicates that the line should be repeated if necessary to accommodate all items.\n

Footers

\n

While $FORMAT_TOP_NAME contains the name of the current header format, there is no corresponding mechanism to automatically do the same thing for a footer. Not knowing how big a format is going to be until you evaluate it is one of the major problems. It's on the TODO list.

\n

Here's one strategy: If you have a fixed-size footer, you can get footers by checking $FORMAT_LINES_LEFT before each write() and print the footer yourself if necessary.

\n

Here's another strategy: Open a pipe to yourself, using "open(MYSELF, "|-")" (see "open" in perlfunc) and always write() to MYSELF instead of STDOUT. Have your child process massage its STDIN to rearrange headers and footers however you like. Not very convenient, but doable.

NOTES

Variables declared with my within a format subroutine are local to that subroutine. They are not visible outside of the format subroutine.

If the program's environment specifies an LC_NUMERIC locale, and "use locale" is in effect when the format is declared, the locale is used to specify the decimal point character in formatted output. Formatted output cannot be controlled by "use locale" at the time when write() is called. See perlrun for further discussion of locale handling.

Within strings that are to be displayed in a fixed-length text field, each control character is substituted by a space. (But remember the special meaning of "\r" when using fill mode.) This is done to avoid misalignment when control characters "disappear" on some output media.
