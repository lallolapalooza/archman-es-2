NOMBRE

perf-script - Leer perf.data (creado por perf record) y mostrar salida de traza

SINOPSIS

perf script [<opciones>]
perf script [<opciones>] record <script> [<opciones-de-grabacion>] <comando>
perf script [<opciones>] report <script> [argumentos-de-script]
perf script [<opciones>] <script> <argumentos-requeridos-de-script> [<opciones-de-grabacion>] <comando>
perf script [<opciones>] <script-principal> [argumentos-de-script]

DESCRIPCIÓN

Este comando lee el archivo de entrada y muestra la traza grabada.

Hay varias variantes de perf script:

'perf script' para ver una traza detallada de la carga de trabajo que fue
grabada.
También puede ejecutar un conjunto de scripts predefinidos que agregan y
resumen los datos brutos de la traza de diversas maneras (la lista de scripts
está disponible a través de 'perf script -l'). Las siguientes variantes le
permiten grabar y ejecutar esos scripts:
'perf script record <script> <comando>' para grabar los eventos requeridos
para 'perf script report'. <script> es el nombre mostrado en la salida de
'perf script --list', es decir, el nombre real del script menos cualquier
extensión de idioma. Si no se especifica <comando>, los eventos se graban
utilizando la opción -a (sistema completo) de 'perf record'.
'perf script report <script> [argumentos]' para ejecutar y mostrar los resultados
de <script>. <script> es el nombre mostrado en la salida de 'perf
script --list', es decir, el nombre real del script menos cualquier
extensión de idioma. La salida de perf.data de una ejecución previa de 'perf
script record <script>' se utiliza y debe estar presente para que este
comando tenga éxito. [argumentos] se refiere a los argumentos (principalmente
opcionales) esperados por el script.
'perf script <script> <argumentos-requeridos-de-script> <comando>' para grabar
los eventos requeridos para <script> y ejecutar el <script> usando
'modo en vivo', es decir, sin escribir nada en disco. <script> es el nombre
mostrado en la salida de 'perf script --list', es decir, el nombre real del
script menos cualquier extensión de idioma. Si no se especifica <comando>,
los eventos se graban utilizando la opción -a (sistema completo) de 'perf
record'. Si <script> tiene argumentos requeridos, deben especificarse antes
de <comando>. Este modo no permite especificar argumentos de script opcionales;
si se desean argumentos de script opcionales, se pueden especificar usando
comandos separados 'perf script record' y 'perf script report', con la salida
estándar del paso de grabación canalizada a la entrada estándar del script de
informe, utilizando las opciones '-o -' y '-i -' de los comandos
correspondientes.
'perf script <script-principal>' para grabar los eventos requeridos para
<script-principal> y ejecutar el <script-principal> usando 'modo en vivo',
es decir, sin escribir nada en disco. <script-principal> es el nombre
mostrado en la salida de 'perf script --list', es decir, el nombre real del
script menos cualquier extensión de idioma; un <script-principal> se
define como cualquier nombre de script que termine con la cadena 'top'.
[<opciones-de-grabacion>] se pueden pasar a los pasos de grabación de
'perf script record' y variantes de 'modo en vivo'; sin embargo, esto no es
posible para el modo 'en vivo' de '<script-principal>' ni para las
variantes de 'perf script report'.
Consulte la sección 'VER TAMBIÉN' para ver enlaces a información específica
del idioma sobre cómo escribir y ejecutar sus propios scripts de traza.

OPCIONES

<comando>...

Cualquier comando que pueda especificar en un shell.

-D, --dump-raw-trace=

Muestra un volcado detallado de los datos de traza.

--dump-unsorted-raw-trace=

Igual que --dump-raw-trace pero no ordenado por orden de tiempo.

-L, --Latency=

Muestra atributos de latencia (interrupciones/deshabilitación de preemption, etc.).

-l, --list=

Muestra una lista de scripts de traza disponibles.

-s [idioma], --script=

Procesa datos de traza con el script dado ([idioma]:script[.ext]). Si se especifica la cadena idioma en lugar de un nombre de script, se mostrará una lista de idiomas compatibles en su lugar.

-g, --gen-script=

Genera el script de inicio perf-script.[ext] para el idioma dado, utilizando el perf.data actual.

--dlfilter=<archivo>

Filtra eventos de muestra usando el archivo de objeto compartido dado. Consulte perf-dlfilter(1)

--dlarg=<argumento>

Pasa argumento como argumento a dlfilter. --dlarg puede repetirse para añadir más argumentos.

--list-dlfilters

Muestra una lista de dlfilters disponibles. Úselo con la opción -v (debe ir antes de la opción --list-dlfilters) para mostrar descripciones largas.

-a

Fuerza la recolección a nivel de sistema. Los scripts que se ejecutan sin un <comando> usan -a por defecto, mientras que los scripts que se ejecutan con un <comando> normalmente no lo hacen; esta opción permite que estos últimos se ejecuten en modo de sistema completo.

-i, --input=

Nombre del archivo de entrada. (por defecto: perf.data a menos que la entrada estándar sea una fifo)

-d, --debug-mode

Realiza varias comprobaciones como el orden de las muestras y los eventos perdidos.

-F, --fields

Lista separada por comas de campos a imprimir. Las opciones son: comm, tid, pid, time, cpu, event, trace, ip, sym, dso, dsoff, addr, symoff, srcline, period, iregs, uregs, brstack, brstacksym, flags, bpf-output, brstackinsn, brstackinsnlen, brstackdisasm, brstackoff, callindent, insn, disasm, insnlen, synth, phys_addr, metric, misc, srccode, ipc, data_page_size, code_page_size, ins_lat, machine_pid, vcpu, cgroup, retire_lat, brcntr, 
La lista de campos puede ir precedida por el tipo, trace, sw o hw,
para indicar a qué tipo de evento se aplica la lista de campos.
por ejemplo: -F sw:comm,tid,time,ip,sym y -F trace:time,cpu,trace
perf script -F <campos>
es equivalente a:
perf script -F trace:<campos> -F sw:<campos> -F hw:<campos>
es decir, los campos especificados se aplican a todos los tipos de eventos si
no se proporciona la cadena de tipo.
Además de anular los campos, también es posible agregar o eliminar campos
de los predeterminados. Por ejemplo:
-F -cpu,+insn
elimina el campo cpu y agrega el campo insn. Agregar/eliminar campos
no se puede mezclar con la anulación normal.
Los argumentos se procesan en el orden en que se reciben. Una invocación
posterior puede anular una solicitud anterior. Por ejemplo:
-F trace: -F comm,tid,time,ip,sym
El primer -F suprime los eventos de traza (la lista de campos es ""),
pero luego la segunda invocación establece los campos en comm,tid,time,ip,sym.
En este caso, se muestra una advertencia al usuario:
"Anulando solicitud de campo anterior para todos los eventos."
Alternativamente, considere el orden:
-F comm,tid,time,ip,sym -F trace:
El primer -F establece los campos para todos los eventos y el segundo -F
suprime los eventos de traza. Se muestra un mensaje de advertencia al usuario
sobre la anulación, y el resultado de lo anterior es que solo los eventos S/W y
H/W se muestran con los campos dados.
Es posible agregar/eliminar campos solo para un tipo de evento específico:
-Fsw:-cpu,-period
elimina cpu y period de los eventos de software.
Para la opción de 'comodín' si un campo seleccionado por el usuario no es
válido para un tipo de evento, se muestra un mensaje al usuario de que la
opción se ignora para ese tipo. Por ejemplo:
$ perf script -F comm,tid,trace
'trace' no es válido para eventos de hardware. Ignorando.
'trace' no es válido para eventos de software. Ignorando.
Alternativamente, si se le da al tipo un campo no válido, es un error. Por
ejemplo:
perf script -v -F sw:comm,tid,trace
'trace' no es válido para eventos de software.
En este punto se muestra el uso y perf-script sale.
El campo flags se sintetiza y puede tener un valor al decodificar la traza
de instrucciones. Las flags son "bcrosyiABExghDt" que representan branch,
call, return, conditional, system

El campo callindent se sintetiza y puede tener un valor al
decodificar la traza de instrucciones. Para llamadas y retornos, mostrará el
nombre del símbolo indentado con espacios para reflejar la profundidad de la pila.
Al decodificar la traza de instrucciones, insn, disasm e insnlen proporcionan los
bytes de la instrucción, las instrucciones desensambladas (requiere soporte de libcapstone)
y la longitud de la instrucción actual respectivamente.
El campo synth se utiliza para eventos sintetizados que pueden crearse al
decodificar la traza de instrucciones.
El campo ipc (instrucciones por ciclo) se sintetiza y puede tener un valor al
decodificar la traza de instrucciones.
Los campos machine_pid y vcpu se derivan de datos resultantes del uso de
perf inject para insertar un archivo perf.data grabado dentro de una máquina virtual en
un archivo perf.data grabado en el host al mismo tiempo.
Los campos cgroup requieren que la muestra tenga el id de cgroup que se guarda
cuando se pasa la opción "--all-cgroups" a 'perf record'.
Finalmente, un usuario no puede establecer campos a ninguno para todos los tipos de eventos.
es decir, -F "" no está permitido.
La salida brstack incluye información relacionada con las ramas con direcciones crudas usando la
sintaxis FROM/TO/EVENT/INTX/ABORT/CYCLES/TYPE/SPEC en el siguiente orden:
FROM  : instrucción fuente de la rama
TO    : instrucción destino de la rama
EVENT : M=destino de la rama o dirección fue predicha incorrectamente
        P=destino de la rama o dirección fue predicha
        N=rama no tomada
        -=sin evento o no soportado
INTX  : X=rama dentro de una región transaccional
        -=rama no en región de transacción o no soportado
ABORT : A=entrada de aborto TSX
        -=región no abortada o no soportada
CYCLES: número de ciclos transcurridos desde que se registró la última rama
TYPE  : tipo de rama: COND/UNCOND/IND/CALL/IND_CALL/RET etc.
        -=no soportado
SPEC  : información de especulación de rama: SPEC_WRONG_PATH/NON_SPEC_CORRECT_PATH/SPEC_CORRECT_PATH
        -=no soportado
El campo brstacksym es idéntico a brstack, excepto que las direcciones FROM y TO se imprimen en forma simbólica si es posible.
Cuando se especifica brstackinsn, se imprimen las secuencias completas de ensamblaje de las secuencias de ramas para cada muestra
. Este es el camino de ejecución completo que lleva a la muestra. Esto solo se admite cuando la
muestra se grabó con perf record -b o -j any.
Utilice brstackinsnlen para imprimir la longitud de brstackinsn. Por ejemplo, no
puede saber la siguiente instrucción secuencial después de una rama incondicional a menos que
la calcule basándose en su longitud.
brstackdisasm actúa como brstackinsn, pero imprimirá instrucciones desensambladas si
perf se compila con la biblioteca capstone.
El campo brstackoff imprimirá un desplazamiento dentro de un dso/binario específico.
Con la opción metric, perf script puede calcular métricas para
períodos de muestreo, similar a perf stat. Esto requiere
especificar un grupo con múltiples eventos que definen métricas con la opción :S
para perf record. perf tomará muestras del primer evento e
imprimirá las métricas calculadas para todos los eventos del grupo. Tenga en cuenta
que la métrica calculada se promedia durante todo el período de muestreo
(desde la última muestra), no solo para el punto de muestreo.

Muestra información extendida sobre el archivo perf.data. Esto agrega información que puede ser muy grande y, por lo tanto, puede saturar la pantalla. Actualmente incluye: la topología de CPU y NUMA del sistema host. Solo se puede usar con el modo de informe perf script.

Intenta resolver la ruta de [kernel.kallsyms]

--show-round-events Muestra eventos de ronda finalizados, es decir, eventos de tipo PERF_RECORD_FINISHED_ROUND.

--show-bpf-events Muestra eventos bpf, es decir, eventos de tipo PERF_RECORD_KSYMBOL y PERF_RECORD_BPF_EVENT.

--show-cgroup-events Muestra eventos cgroup, es decir, eventos de tipo PERF_RECORD_CGROUP.

--show-text-poke-events Muestra eventos de poke de texto, es decir, eventos de tipo PERF_RECORD_TEXT_POKE y PERF_RECORD_KSYMBOL.

--demangle

Descodifica nombres de símbolos a una forma legible por humanos. Está habilitado por defecto, desactívelo con --no-demangle.

--demangle-kernel

Descodifica nombres de símbolos del kernel a una forma legible por humanos (para kernels C++).

--addr2line=<path>

Ruta al binario addr2line.

NOMBRE

perf-script - evento de script de perf para filtrar e interpretar datos de perf

SINOPSIS

perf script [opciones]

DESCRIPCIÓN

El comando perf script lee los datos de eventos recopilados por perf record y los presenta en un formato legible por humanos. Puede filtrar e interpretar los datos de varias maneras, lo que permite analizar eventos de rendimiento, seguimientos de llamadas y más.

Este comando es útil para generar informes, depurar cuellos de botella de rendimiento y comprender el comportamiento de ejecución de un programa.

OPCIONES

--itrace[=<fmt>]

Habilitar el seguimiento de instrucciones. El formato (formato) puede ser:

none: no mostrar nada
srcline: mostrar el archivo fuente y el número de línea
srcline_abs: mostrar el archivo fuente absoluto y el número de línea
symbol: mostrar el nombre de la función
callchain: mostrar la cadena de llamadas (si está disponible)

El formato predeterminado es srcline. Las siguientes banderas pueden habilitar o deshabilitar si los mensajes de seguimiento de instrucciones se registrarán. Cada bandera debe ir precedida por '+' o '-'. Las banderas son:

a       todos los eventos de perf
e       salida solo en errores (tamaño configurable - ver linkperf:perf-config[1])
o       salida a stdout
Si se admite, la opción 'q' se puede repetir para aumentar el efecto.
Para deshabilitar la decodificación por completo, use --no-itrace.

--full-source-path

Mostrar la ruta completa de los archivos fuente para la salida de srcline.

--max-stack

Establecer el límite de profundidad de la pila al analizar la cadena de llamadas, se ignorará todo lo que exceda la profundidad especificada. Esto es un compromiso entre la pérdida de información y un procesamiento más rápido, especialmente para cargas de trabajo que pueden tener una cadena de llamadas muy larga. Tenga en cuenta que al usar la opción --itrace, el tamaño de la cadena de llamadas sintetizada anulará este valor si el tamaño de la cadena de llamadas sintetizada es mayor. 
Por defecto: 127

--ns

Usar 9 decimales al mostrar el tiempo (es decir, mostrar los nanosegundos).

-f, --force

No realizar validación de propiedad.

--time

Analizar solo muestras dentro de la ventana de tiempo dada: <inicio>,<fin>. Los tiempos tienen el formato segundos.nanosegundos. Si no se proporciona el inicio (es decir, la cadena de tiempo es ,x.y) entonces el análisis comienza al principio del archivo. Si no se proporciona el tiempo de finalización (es decir, la cadena de tiempo es x.y,) entonces el análisis va hasta el final del archivo. Se pueden separar múltiples rangos con espacios, lo que requiere que el argumento esté entre comillas, por ejemplo, --time "1234.567,1234.789 1235," 
También admite el porcentaje de tiempo con múltiples rangos de tiempo. La
  cadena de tiempo es 'a%/n,b%/m,...' o 'a%-b%,c%-%d,...'.
Por ejemplo:
Seleccionar la segunda rebanada de tiempo del 10%:
perf script --time 10%/2
Seleccionar desde la rebanada de tiempo del 0% al 10%:
perf script --time 0%-10%
Seleccionar la primera y la segunda rebanada de tiempo del 10%:
perf script --time 10%/1,10%/2
Seleccionar las rebanadas del 0% al 10% y del 30% al 40%:
perf script --time 0%-10%,30%-40%

--max-blocks

Establecer el número máximo de bloques de programa a imprimir con brstackinsn para cada muestra.

--reltime

Imprimir marcas de tiempo relativas al inicio del seguimiento.

--deltatime

Imprimir marcas de tiempo relativas al evento anterior.

--per-event-dump

Crear archivos por evento con un nombre "perf.data.EVENT.dump" en lugar de imprimir en stdout, útil, por ejemplo, para generar flamographs.

--inline

Si una dirección de grafo de llamadas pertenece a una función incrustada, se imprimirá la pila incrustada. Cada entrada tiene el nombre de la función y el archivo/línea. Habilitado por defecto, deshabilitar con --no-inline.

--insn-trace[=<raw|disasm>]

Mostrar el flujo de instrucciones en bytes (raw) o desensamblado (disasm) para seguimientos de intel_pt. El valor predeterminado es raw. Para usar xed, combine raw con --xed para mostrar el desensamblado realizado por xed.

--xed

Ejecutar el desensamblador xed en la salida. Requiere instalar el desensamblador xed.

-S, --symbols=símbolo[,símbolo...]

Considerar solo los símbolos listados. Los símbolos suelen ser un nombre, pero también pueden ser una dirección hexadecimal. 
La dirección hexadecimal puede ser la dirección de inicio de un símbolo o
cualquier otra dirección para filtrar los registros de seguimiento
Por ejemplo, para seleccionar el símbolo noploop o la dirección 0x4007a0:
perf script --symbols=noploop,0x4007a0
Admite el filtrado de registros de seguimiento por nombre de símbolo,
dirección de inicio de símbolo, cualquier dirección hexadecimal y rango de
direcciones.
El orden de comparación es:
1.comparación de nombre de símbolo
2.comparación de dirección de inicio de símbolo.
3.comparación de cualquier dirección hexadecimal.
4.comparación de rango de direcciones (ver --addr-range).

--addr-range

Usar con -S o --symbols para listar registros rastreados dentro del rango de direcciones. 
Por ejemplo, para listar los registros rastreados dentro del rango de
direcciones [0x4007a0, 0x0x4007a9]:
perf script -S 0x4007a0 --addr-range 10

--dsos=

Considerar solo símbolos en estos DSO.

--call-trace

Mostrar el flujo de llamadas para seguimientos de intel_pt. Las CPU están entrelazadas, pero se pueden filtrar con -C.

--call-ret-trace

Mostrar el flujo de llamadas y retornos para seguimientos de intel_pt.

--graph-function

Para itrace, mostrar solo las funciones especificadas y sus llamados para itrace. Se pueden separar múltiples funciones por comas.

--switch-on EVENT_NAME

Considerar solo eventos después de que se encuentre este evento.

--switch-off EVENT_NAME

Dejar de considerar eventos después de que se encuentre este evento.

--show-on-off-events

Mostrar también los eventos --switch-on/off.

--stitch-lbr

Mostrar grafo de llamadas con LBR cosidos, lo que puede tener un grafo de llamadas más completo. El archivo perf.data debe haber sido obtenido usando perf record --call-graph lbr. Deshabilitado por defecto. En casos comunes con desbordamientos de pila de llamadas, puede recrear mejores pilas de llamadas que la salida predeterminada de pila de llamadas lbr. Pero este enfoque no es infalible. Puede haber casos en los que cree pilas de llamadas incorrectas a partir de coincidencias incorrectas. Las limitaciones conocidas incluyen el manejo de excepciones como setjmp/longjmp, que tendrán llamadas/retornos que no coinciden.

--guestmount=<ruta>

Directorio de montaje del sistema de archivos raíz del SO invitado. Los usuarios montan los directorios raíz del SO invitado bajo <ruta> mediante un método de acceso específico al sistema de archivos, típicamente, sshfs. Por ejemplo, iniciar 2 SO invitados, el pid de uno es 8888 y el del otro es 9999: 
$ mkdir ~/guestmount
$ cd ~/guestmount
$ sshfs -o allow_other,direct_io -p 5551 localhost:/ 8888/
$ sshfs -o allow_other,direct_io -p 5552 localhost:/ 9999/
$ perf script --guestmount=~/guestmount

--guestkallsyms=<ruta>

Copia del archivo /proc/kallsyms del SO invitado. perf lo lee para obtener los símbolos del kernel invitado. Los usuarios lo copian fuera del SO invitado.

--guestmodules=<ruta>

Copia del archivo /proc/modules del SO invitado. perf lo lee para obtener información del módulo del kernel invitado. Los usuarios lo copian fuera del SO invitado.

--guestvmlinux=<ruta>

Vmlinux del kernel del SO invitado.

--guest-code

Indicar que el código invitado se puede encontrar en el proceso hipervisor, que es un caso común para los programas de prueba de KVM.
