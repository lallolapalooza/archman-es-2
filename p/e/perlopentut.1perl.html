PERLOPENTUT(1perl) Guía de Referencia del Programador de Perl PERLOPENTUT(1perl)

NOMBRE

perlopentut - Recetas sencillas para abrir archivos y tuberías en Perl

DESCRIPCIÓN

Cada vez que realizas E/S en un archivo en Perl, lo haces a través de lo que en Perl se llama un manejador de archivo. Un manejador de archivo es un nombre interno para un archivo externo. Es trabajo de la función "open" hacer la asociación entre el nombre interno y el nombre externo, y es trabajo de la función "close" romper esa asociación.

Para tu conveniencia, Perl configura algunos manejadores de archivo especiales que ya están abiertos cuando ejecutas. Estos incluyen "STDIN", "STDOUT", "STDERR" y "ARGV". Dado que están pre-abiertos, puedes usarlos de inmediato sin tener que molestarte en abrirlos tú mismo:

print STDERR "Este es un mensaje de depuración.\n";
print STDOUT "Por favor, introduce algo: ";
$response = <STDIN> // die "¿cómo es que no hay entrada?";
print STDOUT "¡Gracias!\n";
while (<ARGV>) { ... }

Como ves en esos ejemplos, "STDOUT" y "STDERR" son manejadores de salida, y "STDIN" y "ARGV" son manejadores de entrada. Están en mayúsculas porque están reservados para Perl, al igual que lo están el array @ARGV y el hash %ENV. Sus asociaciones externas fueron establecidas por tu shell.

Necesitarás abrir cualquier otro manejador de archivo por tu cuenta. Aunque existen muchas variantes, la forma más común de llamar a la función open() de Perl es con tres argumentos y un valor de retorno:

" OK = open(MANEJADOR, MODO, RUTA)"

Donde:

OK
será algún valor definido si la apertura tiene éxito, pero "undef" si falla;
MANEJADOR
debe ser una variable escalar indefinida que será llenada por la función "open" si tiene éxito;
MODO
es el modo de acceso y el formato de codificación con el que abrir el archivo;
RUTA
es el nombre externo del archivo que quieres abrir.

La mayor parte de la complejidad de la función "open" reside en los muchos valores posibles que el parámetro MODO puede tomar.

Una última cosa antes de mostrarte cómo abrir archivos: abrir archivos no los bloquea (generalmente) automáticamente en Perl. Ver perlfaq5 para saber cómo bloquear.

Abrir archivos de texto

Abrir archivos de texto para leer

Si quieres leer de un archivo de texto, primero ábrelo en modo de solo lectura así:

my $nombre_archivo = "/alguna/ruta/a/un/archivo/de/texto/aqui";
my $codificacion = ":encoding(UTF-8)";
my $manejador   = undef;     # esto se llenará en caso de éxito
open($manejador, "< $codificacion", $nombre_archivo)
    || die "$0: no se puede abrir $nombre_archivo para lectura: $!";

Al igual que en el shell, en Perl se usa "<" para abrir el archivo en modo de solo lectura. Si tiene éxito, Perl te asigna un nuevo manejador de archivo y llena tu argumento $manejador previamente indefinido con una referencia a ese manejador.

Ahora puedes usar funciones como "readline", "read", "getc" y "sysread" en ese manejador. Probablemente la función de entrada más común es la que se parece a un operador:

$linea = readline($manejador);
$linea = <$manejador>;          # lo mismo

Dado que la función "readline" devuelve "undef" al final del archivo o en caso de error, a veces la verás usada de esta manera:

$linea = <$manejador>;
if (defined $linea) {
    # haz algo con $linea
}
else {
    # $linea no es válida, así que ignórala
}

También puedes simplemente salir en un valor indefinido de esta manera:

$linea = <$manejador> // die "no se encontró entrada";

Sin embargo, si llegar al final del archivo es un evento esperado y normal, no quieres salir simplemente porque te has quedado sin entrada. En su lugar, probablemente solo querrás salir de un bucle de entrada. Luego puedes comprobar si un error real ha provocado que el bucle termine y actuar en consecuencia:

while (<$manejador>) {
    # haz algo con los datos en $_
}
if ($!) {
    die "error inesperado al leer de $nombre_archivo: $!";
}

Nota sobre codificaciones: Tener que especificar la codificación de texto cada vez puede parecer un poco molesto. Para configurar una codificación predeterminada para "open" de modo que no tengas que suministrarla cada vez, puedes usar la pragmática "open":

use open qw< :encoding(UTF-8) >;

Una vez que hayas hecho eso, puedes omitir de forma segura la parte de codificación del modo de apertura:

open($manejador, "<", $nombre_archivo)
    || die "$0: no se puede abrir $nombre_archivo para lectura: $!";

Pero nunca uses el "<" desnudo sin haber configurado previamente una codificación predeterminada. De lo contrario, Perl no puede saber cuál de los muchos, muchos, muchos sabores posibles de archivo de texto tienes, y Perl no tendrá idea de cómo mapear correctamente los datos de tu archivo a caracteres reales con los que pueda trabajar. Otros formatos de codificación comunes incluyen "ASCII", "ISO-8859-1", "ISO-8859-15", "Windows-1252", "MacRoman" e incluso "UTF-16LE". Ver perlunitut para más sobre codificaciones.

Abrir archivos de texto para escribir

Cuando quieras escribir en un archivo, primero tienes que decidir qué hacer con cualquier contenido existente en ese archivo. Tienes dos opciones básicas aquí: preservar o sobrescribir.

Si quieres preservar cualquier contenido existente, entonces quieres abrir el archivo en modo de añadir. Como en el shell, en Perl usas ">>" para abrir un archivo existente en modo de añadir. ">>" crea el archivo si no existe.

my $manejador   = undef;
my $nombre_archivo = "/alguna/ruta/a/un/archivo/de/texto/aqui";
my $codificacion = ":encoding(UTF-8)";
open($manejador, ">> $codificacion", $nombre_archivo)
    || die "$0: no se puede abrir $nombre_archivo para añadir: $!";

Ahora puedes escribir en ese manejador usando cualquiera de "print", "printf", "say", "write" o "syswrite".

Como se señaló anteriormente, si el archivo no existe, el modo de añadir lo creará por ti. Pero si el archivo ya existe, su contenido estará a salvo porque agregarás tu nuevo texto después del final del texto antiguo.

Por otro lado, a veces quieres sobrescribir lo que pueda haber ahí ya. Para vaciar un archivo antes de empezar a escribir en él, puedes abrirlo en modo de solo escritura:

my $manejador   = undef;
my $nombre_archivo = "/alguna/ruta/a/un/archivo/de/texto/aqui";
my $codificacion = ":encoding(UTF-8)";
open($manejador, "> $codificacion", $nombre_archivo)
    || die "$0: no se puede abrir $nombre_archivo en modo de escritura: $!";

Aquí de nuevo Perl funciona igual que el shell, en que ">" sobrescribe un archivo existente.

Como en el modo de añadir, cuando abres un archivo en modo de solo escritura, ahora puedes escribir en ese manejador usando cualquiera de "print", "printf",

"decir", "escribir" o "syswrite".

¿Qué pasa con el modo de lectura/escritura? Probablemente deberías pretender que no existe, porque abrir archivos de texto en modo de lectura/escritura probablemente no hará lo que deseas. Consulta perlfaq5 para más detalles.

Abrir Archivos Binarios

Si el archivo a abrir contiene datos binarios en lugar de caracteres de texto, entonces el argumento "MODO" para "open" es un poco diferente. En lugar de especificar la codificación, le dices a Perl que tus datos están en bytes crudos.

my $filename = "/alguna/ruta/a/un/archivo/binario/va/aqui";
my $encoding = ":raw :bytes"
my $handle   = undef;     # esto se llenará en caso de éxito

Y luego abre como antes, eligiendo "<", ">>" o ">" según sea necesario:

open($handle, "< $encoding", $filename)
    || die "$0: no se puede abrir $filename para lectura: $!";
open($handle, ">> $encoding", $filename)
    || die "$0: no se puede abrir $filename para añadir: $!";
open($handle, "> $encoding", $filename)
    || die "$0: no se puede abrir $filename en modo escritura/apertura: $!";

Alternativamente, puedes cambiar al modo binario en un manejador existente de esta manera:

binmode($handle)    || die "no se puede hacer binmode al manejador";

Esto es especialmente útil para los manejadores que Perl ya ha abierto para ti.

binmode(STDIN)      || die "no se puede hacer binmode a STDIN";
binmode(STDOUT)     || die "no se puede hacer binmode a STDOUT";

También puedes pasarle a "binmode" una codificación explícita para cambiarla sobre la marcha. Esto no es exactamente el modo "binario", pero aún usamos "binmode" para hacerlo:

binmode(STDIN,  ":encoding(MacRoman)") || die "no se puede hacer binmode a STDIN";
binmode(STDOUT, ":encoding(UTF-8)")    || die "no se puede hacer binmode a STDOUT";

Una vez que tengas tu archivo binario abierto correctamente en el modo adecuado, puedes usar las mismas funciones de E/S de Perl que usaste en archivos de texto. Sin embargo, es posible que desees usar la "read" de tamaño fijo en lugar de la "readline" de tamaño variable para tu entrada.

Aquí tienes un ejemplo de cómo copiar un archivo binario:

my $BUFSIZ   = 64 * (2 ** 10);
my $name_in  = "/archivo/de/entrada";
my $name_out = "/archivo/de/salida";
my($in_fh, $out_fh, $buffer);
open($in_fh,  "<", $name_in)
    || die "$0: no se puede abrir $name_in para lectura: $!";
open($out_fh, ">", $name_out)
    || die "$0: no se puede abrir $name_out para escritura: $!";
for my $fh ($in_fh, $out_fh)  {
    binmode($fh)               || die "binmode fallido";
}
while (read($in_fh, $buffer, $BUFSIZ)) {
    unless (print $out_fh $buffer) {
        die "no se pudo escribir en $name_out: $!";
    }
}
close($in_fh)       || die "no se pudo cerrar $name_in: $!";
close($out_fh)      || die "no se pudo cerrar $name_out: $!";

Abrir Pipes

Perl también te permite abrir un manejador de archivo en un programa externo o comando de shell en lugar de en un archivo. Puedes hacer esto para pasar datos desde tu programa Perl a un comando externo para su posterior procesamiento, o para recibir datos de otro programa para que tu propio programa Perl los procese.

Los manejadores de archivo para comandos también se conocen como pipes, ya que funcionan con principios de comunicación entre procesos similares a los de las canalizaciones de Unix. Dicho manejador de archivo tiene un programa activo en lugar de un archivo estático en su extremo externo, pero en todos los demás aspectos funciona igual que un manejador de archivo más típico, con todas las técnicas discutidas anteriormente aplicables.

Como tal, abres un pipe usando la misma llamada "open" que usas para abrir archivos, configurando el segundo argumento ("MODO") a caracteres especiales que indican un pipe de entrada o de salida. Usa "-|" para un manejador de archivo que permitirá a tu programa Perl leer datos de un programa externo, y "|-" para un manejador de archivo que enviará datos a ese programa en su lugar.

Abrir un pipe para lectura

Supongamos que quieres que tu programa Perl procese datos almacenados en un directorio cercano llamado "unsorted", que contiene una serie de archivos de texto. También te gustaría que tu programa ordenara todo el contenido de estos archivos en una lista única y ordenada alfabéticamente antes de empezar a procesarlos.

Podrías hacer esto abriendo un manejador de archivo ordinario en cada uno de esos archivos, construyendo gradualmente en memoria una matriz de todo el contenido de los archivos que cargas de esta manera, y finalmente ordenando y filtrando esa matriz cuando te quedes sin archivos para cargar. O, podrías delegar todo ese trabajo de fusión y ordenación al propio comando "sort" de tu sistema operativo abriendo un pipe directamente a su salida, y empezar a trabajar mucho más rápido.

Así es como podría verse:

open(my $sort_fh, '-|', 'sort -u unsorted/*.txt')
    or die "No se pudo abrir un pipe a sort: $!";
# Y de inmediato, podemos empezar a leer líneas ordenadas:
while (my $line = <$sort_fh>) {
    #
    # ... Haz algo interesante con cada $line aquí ...
    #
}

El segundo argumento para "open", "-|", lo convierte en un pipe de lectura hacia un programa separado, en lugar de un manejador de archivo ordinario hacia un archivo.

Ten en cuenta que el tercer argumento para "open" es una cadena que contiene el nombre del programa ("sort") más todos sus argumentos: en este caso, "-u" para especificar ordenación única, y luego un comodín que especifica los archivos a ordenar. El manejador de archivo resultante $sort_fh funciona igual que un manejador de archivo de solo lectura ("<"), y tu programa puede posteriormente leer datos de él como si estuviera abierto en un archivo único ordinario.

Abrir un pipe para escritura

Continuando el ejemplo anterior, digamos que tu programa ha completado su procesamiento y los resultados se encuentran en una matriz llamada @processed. Quieres imprimir estas líneas en un archivo llamado "numbered.txt" con una columna bien formateada de números de línea.

Ciertamente podrías escribir tu propio código para hacer esto — o, una vez más, podrías delegar ese trabajo a otro programa. En este caso, "cat", ejecutándose con su propia opción "-n" para activar la numeración de líneas, debería hacer el trabajo:

open(my $cat_fh, '|-', 'cat -n > numbered.txt')
    or die "No se pudo abrir un pipe a cat: $!";
for my $line (@processed) {
    print $cat_fh $line;
}

Aquí, usamos un segundo argumento de "open" de "|-", que significa que el manejador de archivo asignado a $cat_fh debe ser un pipe de escritura. Luego podemos usarlo como si fuera un manejador de archivo ordinario de solo escritura, incluyendo la función básica de imprimir datos en él.

Ten en cuenta que el tercer argumento, que especifica el comando al que deseamos canalizar, configura "cat" para redirigir su salida a través de ese símbolo ">" al archivo "numbered.txt". Esto puede empezar a parecer un poco complicado, porque el mismo símbolo habría significado algo completamente diferente si hubiera aparecido en el segundo argumento de "open". Pero aquí, en el tercer argumento, es simplemente parte del comando de shell en el que Perl abrirá el pipe, y Perl en sí mismo no le da ningún significado especial.

Expresar el comando como una lista

Para abrir pipes, Perl ofrece la opción de llamar a "open" con una lista que comprende el comando deseado y todos sus argumentos como elementos separados, en lugar de combinarlos en una sola cadena como en los ejemplos anteriores. Por ejemplo, podríamos haber expresado la llamada "open" en el primer ejemplo de esta manera:

open(my $sort_fh, '-|', 'sort', '-u', glob('unsorted/*.txt'))
    or die "No se pudo abrir un pipe a sort: $!";

Cuando llamas a "open" de esta manera, Perl invoca el comando dado directamente, omitiendo el shell. Como tal, el shell no intentará interpretar caracteres especiales dentro de la lista de argumentos del comando, lo que de otro modo podría tener efectos no deseados. Esto puede hacer que las llamadas a "open" sean más seguras y menos propensas a errores, útil en casos como pasar variables como argumentos, o incluso simplemente referirse a nombres de archivo con espacios.

Sin embargo, cuando SÍ deseas pasar un metacarácter significativo al shell, como con el "*" dentro de ese último argumento "unsorted/*.txt" aquí, no puedes usar esta sintaxis alternativa. En este caso, lo hemos resuelto a través de la práctica función incorporada "glob" de Perl, que evalúa su argumento en una lista de nombres de archivo — y podemos pasar de forma segura esa lista resultante a "open", como se muestra arriba.

También ten en cuenta que representar argumentos de comandos canalizados en forma de lista de esta manera no funciona en todas las plataformas. Funcionará en cualquier sistema operativo basado en Unix que proporcione una función "fork" real (por ejemplo, macOS o Linux), así como en Windows cuando se ejecute Perl 5.22 o posterior.
