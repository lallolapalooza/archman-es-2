NOMBRE

perl5220delta - qué hay de nuevo para la versión v5.22.0 de perl

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.20.0 y la versión 5.22.0.

Si está actualizando desde una versión anterior como la 5.18.0, primero lea perl5200delta, que describe las diferencias entre la 5.18.0 y la 5.20.0.

Mejoras del núcleo

Nuevos operadores bitwise

Se ha añadido una nueva funcionalidad experimental que hace que los cuatro operadores bitwise estándar ("& | ^ ~") traten sus operandos consistentemente como números, e introduce cuatro nuevos operadores con punto ("&. |. ^. ~.") que tratan sus operandos consistentemente como cadenas. Lo mismo aplica a las variantes de asignación ("&= |= ^= &.= |.= ^.=").

Para usar esto, habilite la característica "bitwise" y deshabilite la categoría de advertencias "experimental::bitwise". Consulte "Operadores bitwise de cadenas" en perlop para más detalles. [GH #14348] https://github.com/Perl/perl5/issues/14348.

Nuevo operador doble-diamante

"<<>>" es como "<>" pero usa "open" de tres argumentos para abrir cada archivo en @ARGV. Esto significa que cada elemento de @ARGV será tratado como un nombre de archivo real, y "|foo" no será tratado como una tubería abierta.

Nuevos límites "\b" en expresiones regulares

"qr/\b{gcb}/"

"gcb" significa Límite de Cluster Grafemático. Es una propiedad Unicode que encuentra el límite entre secuencias de caracteres que se ven como un solo carácter para un hablante nativo de un idioma. Perl ha tenido durante mucho tiempo la capacidad de tratar con estos a través de la secuencia de escape regular "\X". Ahora, hay una forma alternativa de manejarlos. Consulte "\b{}, \b, \B{}, \B" en perlrebackslash para más detalles.

"qr/\b{wb}/"

"wb" significa Límite de Palabra. Es una propiedad Unicode que encuentra el límite entre palabras. Esto es similar al simple "\b" (sin llaves) pero es más adecuado para el procesamiento del lenguaje natural. Sabe, por ejemplo, que los apóstrofes pueden ocurrir en medio de las palabras. Consulte "\b{}, \b, \B{}, \B" en perlrebackslash para más detalles.

"qr/\b{sb}/"

"sb" significa Límite de Oración. Es una propiedad Unicode para ayudar a analizar oraciones de lenguaje natural. Consulte "\b{}, \b, \B{}, \B" en perlrebackslash para más detalles.

Indicador de expresión regular no capturadora

Las expresiones regulares ahora admiten un indicador "/n" que deshabilita la captura y el relleno de $1, $2, etc. dentro de los grupos:

"hola" =~ /(hi|hola)/n; # $1 no se establece

Esto es equivalente a colocar "?:" al principio de cada grupo capturador.

Consulte "n" en perlre para más información.

"use re 'strict'"

Esto aplica reglas de sintaxis más estrictas a los patrones de expresiones regulares compilados dentro de su ámbito. Esto, con suerte, le alertará sobre errores tipográficos y otros comportamientos no deseados que los problemas de compatibilidad hacia atrás nos impiden informar en las compilaciones normales de expresiones regulares. Dado que el comportamiento de esto está sujeto a cambios en futuras versiones de Perl a medida que ganamos experiencia, usar este pragmatismo generará una advertencia de la categoría "experimental::re_strict". Consulte 'strict' en re.

Unicode 7.0 (con corrección) ahora es soportado

Para detalles sobre lo que hay en esta versión, consulte http://www.unicode.org/versions/Unicode7.0.0/. La versión de Unicode 7.0 que viene con Perl incluye una corrección relacionada con la formación de glifos en árabe (consulte http://www.unicode.org/errata/#current_errata).

"use locale" puede restringir qué categorías de localidad se ven afectadas

Ahora es posible pasar un parámetro a "use locale" para especificar un subconjunto de categorías de localidad para que sean conscientes de la localidad, y las restantes no se vean afectadas. Consulte "El pragmatismo "use locale"" en perllocale para más detalles.

Perl ahora soporta adiciones de moneda de localidad POSIX 2008

En plataformas que pueden manejar POSIX.1-2008, el hash devuelto por POSIX::localeconv() incluye los campos de moneda internacional añadidos por esa versión del estándar POSIX. Estos son "int_n_cs_precedes", "int_n_sep_by_space", "int_n_sign_posn", "int_p_cs_precedes", "int_p_sep_by_space", y "int_p_sign_posn".

Mejores heurísticas en plataformas antiguas para determinar la codificación UTF-8 de la localidad

En plataformas que no implementan el estándar C99 ni el estándar POSIX 2001, determinar si la localidad actual es UTF-8 o no depende de heurísticas. Estas han sido mejoradas en esta versión.

Alias mediante referencia

Ahora las variables y subrutinas pueden ser aliadas asignando a una referencia:

\$c = \$d;
\&x = \&y;

El aliasing también se puede lograr usando una barra invertida antes de una variable iteradora de "foreach"; este es quizás el modismo más útil que proporciona esta característica:

foreach \%hash (@array_of_hash_refs) { ... }

Esta característica es experimental y debe habilitarse mediante use feature 'refaliasing'. Generará una advertencia a menos que se deshabilite la categoría de advertencias "experimental::refaliasing".

Consulte "Asignación a referencias" en perlref

"prototype" sin argumentos

prototype() sin argumentos ahora infiere $_. [GH #14376] https://github.com/Perl/perl5/issues/14376.

Nuevo atributo de subrutina ":const"

El atributo "const" se puede aplicar a una subrutina anónima. Hace que la nueva sub se ejecute inmediatamente cada vez que se crea una (es decir, cuando se evalúa la expresión "sub"). Su valor se captura y se utiliza para crear una nueva subrutina constante que se devuelve. T

Novedades

Funciones constantes (experimental)

Esta característica es experimental. Véase "Funciones constantes" en perlsub.

"fileno" ahora funciona en handles de directorio

Cuando el soporte relevante está disponible en el sistema operativo, la función integrada "fileno" ahora funciona en handles de directorio, devolviendo el descriptor de archivo subyacente de la misma manera que para los filehandles. En sistemas operativos sin dicho soporte, "fileno" en un handle de directorio continúa devolviendo el valor indefinido, como antes, pero también establece $! para indicar que la operación no es compatible.

Actualmente, esto utiliza un miembro "dd_fd" en la estructura "DIR" del SO, o una función dirfd(3) según lo especificado por POSIX.1-2008.

Implementada la forma de lista de pipe open para Win32

La forma de lista de pipe:

open my $fh, "-|", "programa", @argumentos;

ahora está implementada en Win32. Tiene las mismas limitaciones que "system LIST" en Win32, ya que la API de Win32 no acepta argumentos de programa como una lista.

Asignación a repetición de listas

"(...) x ..." ahora puede usarse dentro de una lista a la que se le asigna, siempre que el lado izquierdo sea un lvalue válido. Esto permite que "(undef,undef,$foo) = esa_funcion()" se escriba como "((undef)x2, $foo) = esa_funcion()".

Mejorado el manejo de Infinito y NaN (no es un número)

Los valores de punto flotante pueden contener los valores especiales infinito, infinito negativo y NaN (no es un número). Ahora reconocemos y propagamos el valor de manera más robusta en los cálculos, y al momento de la salida los normalizamos a las cadenas "Inf", "-Inf" y "NaN".

Véase también las mejoras de POSIX.

Mejorada la interpretación de punto flotante

La interpretación y la impresión de valores de punto flotante han sido mejoradas.

Como característica completamente nueva, ahora se admiten literales de punto flotante hexadecimales (como "0x1.23p-4"), y se pueden imprimir con "printf "%a"". Véase "Constructores de valores escalares" en perldata para más detalles.

Empaquetar infinito o no es un número en un carácter es ahora fatal

Antes, al intentar empaquetar infinito o no es un número en un carácter (con signo), Perl advertía y asumía que se intentaba empaquetar 0xFF; si se le daba como argumento a "chr", se devolvía "U+FFFD".

Pero ahora, todas estas acciones ("pack", "chr", y "print '%c'") resultan en un error fatal.

API experimental de backtrace C

Perl ahora soporta (a través de una API a nivel de C) la obtención del backtrace a nivel de C (similar a lo que hacen los depuradores simbólicos como gdb).

El backtrace devuelve el rastreo de la pila de los marcos de llamada de C, con los nombres de los símbolos (nombres de funciones), los nombres de los objetos (como "perl"), y si puede, también las ubicaciones del código fuente (archivo:línea).

Las plataformas soportadas son Linux y OS X (algunos *BSD podrían funcionar al menos parcialmente, pero aún no han sido probados).

La característica debe ser habilitada con "Configure -Dusecbacktrace".

Véase "Backtrace C" en perlhacktips para más información.

Seguridad

Perl ahora se compila con "-fstack-protector-strong" si disponible

Perl se ha compilado con la opción anti-desbordamiento de pila "-fstack-protector" desde 5.10.1. Ahora Perl utiliza la variante más nueva llamada "-fstack-protector-strong", si está disponible.

El módulo Safe podría permitir la sustitución de paquetes externos

Corrección de error crítico: los paquetes externos podían ser reemplazados. Safe ha sido parcheado a 2.38 para abordar esto.

Perl ahora se compila siempre con "-D_FORTIFY_SOURCE=2" si disponible

La opción de 'endurecimiento de código' llamada "_FORTIFY_SOURCE", disponible en gcc 4.*, ahora se usa siempre para compilar Perl, si está disponible.

Tenga en cuenta que esto no es necesariamente un gran avance, ya que en muchas plataformas el paso ya se había dado hace varios años: muchas distribuciones de Linux (como Fedora) han estado usando esta opción para Perl, y OS X la ha impuesto durante muchos años.

Cambios incompatibles

Las firmas de subrutinas se movieron antes de los atributos

La característica experimental de firmas de subrutinas, tal como se introdujo en 5.20, interpretaba las firmas después de los atributos. En esta versión, siguiendo los comentarios de los usuarios de la característica experimental, la posición se ha movido de manera que las firmas ocurran después del nombre de la subrutina (si existe) y antes de la lista de atributos (si existe).

"&" y "\&" prototipos acepta solo subs

El carácter de prototipo "&" ahora acepta solo subs anónimas ("sub {...}"), elementos que comienzan con "\&", o un explícito "undef". Anteriormente, también permitía erróneamente referencias a arrays, hashes y listas. [GH #2776] https://github.com/Perl/perl5/issues/2776. [GH #14186] https://github.com/Perl/perl5/issues/14186. [GH #14353] https://github.com/Perl/perl5/issues/14353.

Además, el prototipo "\&" permitía llamadas a subrutinas, mientras que ahora solo permite subrutinas: &foo todavía está permitido como argumento, mientras que &foo() y foo() ya no lo están. [GH #10633] https://github.com/Perl/perl5/issues/10633.

"use encoding" es ahora léxico

El efecto del pragma de codificación ahora se limita al ámbito léxico. Este pragma está obsoleto, pero mientras tanto, podría afectar negativamente a módulos no relacionados que se incluyen en el mismo programa; este cambio lo soluciona.

Las rebanadas de lista que devuelven listas vacías

Las rebanadas de lista ahora devuelven una lista vacía solo si la lista original estaba vacía (o si no hay índices). Anteriormente, una rebanada de lista devolvía una lista vacía si todos los índices caían fuera de la lista original; ahora devuelve una lista de valores "undef" en ese caso. [GH #12335] https://github.com/Perl/perl5/issues/12335.

"\\N{}" con una secuencia de múltiples espacios es ahora un error fatal

Por ejemplo, "\N{DEMASIADOS  ESPACIOS}" o "\N{ESPACIO FINAL }". Esto ha sido obsoleto desde v5.18.

"use UNIVERSAL '...'" es ahora un error fatal

La importación de funciones desde "UNIVERSAL" ha sido obsoleta desde v5.12, y ahora es un error fatal. "use UNIVERSAL" sin ningún argumento todavía está permitido.

En la comilla doble "\cX", X debe ser ahora un carácter ASCII imprimible

En versiones anteriores, no hacer esto generaba una advertencia de obsolescencia.

Deprecaciones Las siguientes características se consideran obsoletas y se eliminarán en futuras versiones. Deprecación de asignación a subrutinas y métodos La asignación a subrutinas y métodos, como la siguiente: *Sub::new = sub { ... }; sub foo () { $var }; # obsoleto } En el segundo ejemplo anterior, detectar que $var se asigna solo una vez es demasiado difícil de detectar. Que suceda en un lugar distinto a la declaración de "my" es suficiente para que Perl lo encuentre sospechoso. Esta advertencia de obsolescencia solo ocurre para una variable simple para el cuerpo de la subrutina. (Un bloque "BEGIN" o una declaración "use" dentro de la subrutina se ignoran, ya que no forman parte del cuerpo de la subrutina). Para casos más complejos, como "sub () { do_something() if 0; $var }", el comportamiento ha cambiado de modo que la inserción no ocurre si la variable se puede modificar en otro lugar. Tales casos deberían ser raros. Uso de múltiples modificadores de expresiones regulares "/x" Ahora se desaconseja decir algo como cualquiera de lo siguiente: qr/foo/xx; /(?xax:foo)/; use re qw(/amxx); Es decir, ahora "x" solo debe aparecer una vez en cualquier cadena de modificadores de patrones de expresiones regulares contiguos. No creemos que haya ninguna ocurrencia de esto en todo CPAN. Esto está en preparación para una futura versión de Perl que permitirá "/xx" para permitir espacios en blanco para mayor legibilidad en clases de caracteres entre corchetes (aquellos encerrados entre corchetes: "[...]"). El uso de un espacio NO ROTO en un alias de carácter para "\N{...}" ahora está obsoleto Este carácter no gráfico es esencialmente indistinguible de un espacio normal, por lo que no debería permitirse. Consulte "ALIAS PERSONALIZADOS" en charnames. Un "{" literal ahora debe escaparse en un patrón Si desea un corchete izquierdo literal (también llamado llave izquierda) en un patrón de expresión regular, ahora debe escaparlo precediéndolo con una barra invertida ("\{") o encerrándolo entre corchetes "[{]", o usando "\Q"; de lo contrario, se generará una advertencia de obsolescencia. Esto se anunció por primera vez como próximo en la versión v5.16; permitirá futuras extensiones del lenguaje. Hacer que todas las advertencias sean fatales es desalentador La documentación de advertencias fatales señala que "use warnings FATAL => 'all'" está desalentado, y proporciona un lenguaje más fuerte sobre los riesgos de las advertencias fatales en general. Mejoras de rendimiento Si un nombre de método o clase se conoce en tiempo de compilación, se precalcula una tabla hash para acelerar la búsqueda de métodos en tiempo de ejecución. Además, los nombres de métodos compuestos como "SUPER::new" se analizan en tiempo de compilación, para ahorrar tener que analizarlos en tiempo de ejecución. Las búsquedas en matrices y tablas hash (especialmente anidadas) que utilizan solo constantes o variables simples como claves son ahora considerablemente más rápidas. Consulte "Cambios internos" para obtener más detalles. "(...)x1", "("constante")x0" y "($escalar)x0" ahora se optimizan en contexto de lista. Si el argumento del lado derecho es una constante 1, el operador de repetición desaparece. Si el argumento del lado derecho es una constante 0, toda la expresión se optimiza a la lista vacía, siempre que el argumento del lado izquierdo sea un escalar simple o una constante. (Es decir, "(foo())x0" no está sujeto a esta optimización). La asignación de "substr" ahora se optimiza a "substr" de 4 argumentos al final de una subrutina (o como argumento de "return"). Anteriormente, esta optimización solo ocurría en contexto nulo. En "\L...", "\Q...", etc., la op adicional de "stringify" se optimiza, haciendo que estas sean tan rápidas como "lcfirst", "quotemeta", etc. La asignación a una lista vacía es ahora a veces más rápida. En particular, nunca llama a "FETCH" en argumentos ligados en el lado derecho, mientras que antes lo hacía a veces. Hay una mejora de rendimiento de hasta el 20% cuando "length" se aplica a una cadena no mágica y no ligada, y ya sea "use bytes" está en el ámbito o la cadena no utiliza UTF-8 internamente. En la mayoría de las compilaciones de perl con enteros de 64 bits, el uso de memoria para escalares no mágicos y no ligados que contienen solo un valor de punto flotante se ha reducido entre 8 y 32 bytes, según el sistema operativo. En "@array = split", la asignación se puede optimizar, de modo que "split" escribe directamente en la matriz. Esta optimización solo ocurría para matrices de paquetes distintas de "@_", y solo a veces. Ahora esta optimización ocurre casi todo el tiempo. "join" ahora está sujeto a plegado de constantes. Por lo tanto, por ejemplo, "join " - ", "a", "b"" se convierte en tiempo de compilación a "a-b". Además, "join" con un separador escalar o constante y una lista de un solo elemento para unir se simplifica a una "stringification", y el separador ni siquiera se evalúa. qq(@array) se implementa utilizando dos ops: una op de "stringify" y una op de "join". Si el "qq" no contiene nada más que una sola matriz, la "stringification" se optimiza. "our $var" y "our($s,@a,%h)" en contexto nulo ya no se evalúan en tiempo de ejecución. Incluso una secuencia completa de declaraciones "our $foo;" simplemente se omitirá. Lo mismo se aplica a las variables "state". Muchas funciones internas se han refactorizado para mejorar el rendimiento y reducir su huella de memoria.   • No se puede usar un hash como referencia

    (F) Intentaste usar un hash como referencia, como en "%foo->{"bar"}" o "%$ref->{"hello"}". Las versiones de perl <= 5.6.1 solían permitir esta sintaxis, pero no deberían haberlo hecho.

   # no está vacío
}

    Plataformas descontinuadas

    NeXTSTEP/OPENSTEP
    NeXTSTEP era un sistema operativo propietario incluido con las estaciones de trabajo de NeXT a mediados de los 90; OPENSTEP era una especificación de API que proporcionaba un entorno similar a NeXTSTEP en un sistema no NeXTSTEP. Ambos están muertos desde hace mucho tiempo, por lo que se ha eliminado el soporte para compilar Perl en ellos.

    Notas Específicas de Plataforma

    EBCDIC
    Se requiere un manejo especial del intérprete de perl en plataformas EBCDIC para que "qr/[i-j]/" coincida solo con "i" y "j", ya que hay 7 caracteres entre los puntos de código de "i" y "j". Este manejo especial solo se había invocado cuando ambos extremos del rango son literales. Ahora también se invoca si se utiliza alguna de las formas "\N{...}" para especificar un carácter por nombre o punto de código Unicode en lugar de un literal. Consulte "Rangos de caracteres" en perlrecharclass.
    HP-UX
    El nombre de la arquitectura ahora distingue use64bitint de use64bitall.
    Android
    Se ha mejorado el soporte de compilación para la compilación cruzada en general y para Android en particular.
    VMS
    • Al iniciar un subproceso sin esperar, el valor de retorno es ahora el PID correcto.
    • Se corrigió un prototipo para que el enlace no falle bajo el compilador C++ de VMS.
    • Se ha agregado la detección de "finite", "finitel" y "isfinite" a "configure.com", se han realizado algunos cambios menores en el manejo del entorno y una corrección para el estado de verificación de características heredadas.
    Win32
    • miniperl.exe ahora se compila con "-fno-strict-aliasing", lo que permite que las compilaciones de 64 bits se completen en GCC 4.8. [GH #14556] https://github.com/Perl/perl5/issues/14556
    • "nmake minitest" ahora funciona en Win32. Debido a problemas de dependencia, debe compilar "nmake test-prep" primero, y un pequeño número de pruebas fallan. [GH #14318] https://github.com/Perl/perl5/issues/14318
    • Perl ahora se puede compilar en modo C++ en Windows estableciendo la macro del makefile "USE_CPLUSPLUS" con el valor "define".
    • La forma de lista de open por tubería se ha implementado para Win32. Nota: a diferencia de "system LIST", esto no recurre al shell. [GH #13574] https://github.com/Perl/perl5/issues/13574
    • Se agregaron las nuevas opciones de configuración "DebugSymbols" y "DebugFull" a los makefiles de Windows.
    • Anteriormente, la compilación de módulos XS (incluidos los de CPAN) utilizando Visual C++ para Win64 generaba alrededor de una docena de advertencias por archivo de hv_func.h. Estas advertencias han sido silenciadas.
    • Se ha eliminado el soporte para compilar sin PerlIO de los makefiles de Windows. Las compilaciones sin PerlIO fueron casi obsoletas en Perl 5.18.0 y ya no son compatibles con Configure en sistemas POSIX.
    • Se han ahorrado entre 2 y 6 milisegundos y siete llamadas de E/S por intento de abrir un módulo de perl por cada ruta en @INC.
    • Las compilaciones de Intel C ahora siempre se compilan en modo C99.
    • Ahora se utiliza %I64d en lugar de %lld para MinGW.
    • En la capa experimental ":win32", se corrigió un bloqueo en "open". También se implementó la apertura de /dev/null (que funciona bajo la capa predeterminada ":unix" de Perl en Win32) para ":win32". [GH #13968] https://github.com/Perl/perl5/issues/13968
    • Se ha agregado una nueva opción de makefile, "USE_LONG_DOUBLE", al makefile dmake de Windows solo para compilaciones de gcc. Establezca esto en "define" si desea que perl utilice dobles largos para brindar más precisión y rango para números de punto flotante.
    OpenBSD
    En OpenBSD, Perl ahora usará por defecto el "malloc" del sistema debido a las características de seguridad que proporciona. El propio envoltorio de malloc de Perl se ha utilizado desde v5.14 por razones de rendimiento, pero el proyecto OpenBSD cree que la compensación vale la pena y preferiría que los usuarios que necesiten velocidad la soliciten específicamente.

    [GH #13888] https://github.com/Perl/perl5/issues/13888.

    Solaris
    • Ahora buscamos el compilador Sun Studio tanto en /opt/solstudio* como en /opt/solarisstudio*.
    • Las compilaciones en Solaris 10 con "-Dusedtrace" fallarían temprano ya que make no seguía las dependencias implícitas para compilar "perldtrace.h". Se agregó una dependencia explícita a "depend". [GH #13334] https://github.com/Perl/perl5/issues/13334
    • Se limpiaron las opciones C99; las pistas buscan "solstudio" así como "SUNWspro"; y se agregó soporte para el "setenv" nativo.

    Cambios Internos

    •
    Se ha agregado soporte experimental para permitir que los ops en el optree localicen su padre, si lo hay. Esto se habilita mediante la opción de compilación no predeterminada "-DPERL_OP_PARENT". Se prevé que esto eventualmente se habilite por defecto, por lo que el código XS que accede directamente al campo "op_sibling" de los ops debería actualizarse para ser a prueba de futuro.

    En las compilaciones "PERL_OP_PARENT", el campo "op_sibling" ha sido renombrado a "op_sibparent" y se ha agregado una nueva bandera, "op_moresib". En el último op de una cadena de hermanos, "op_moresib" es falso y "op_sibparent" apunta al padre (si lo hay) en lugar de ser "NULL".

    Para que el código existente funcione transparentemente, ya sea utilizando "PERL_OP_PARENT" o no, se ha agregado una serie de nuevas macros y funciones que deben usarse, en lugar de manipular directamente "op_sibling".

    Para el caso de solo leer "op_sibling" para determinar el siguiente hermano, se han agregado dos nuevas macros. Un escaneo simple a través de una cadena de hermanos como este:

    for (; kid->op_sibling; kid = kid->op_sibling) { ... }

    ahora debería escribirse como:

    for (; OpHAS_SIBLING(kid); kid = OpSIBLING(kid)) { ... }

    Para alterar los optrees, se ha agregado una función de propósito general op_sibling_splice(), que permite la manipulación de una cadena de ops hermanos. Por analogía con la función de Perl splice(), permite eliminar cero o más ops de una cadena de hermanos y reemplazarlos con cero o más ops nuevos. Maneja transparentemente todas las actualizaciones de punteros de hermanos, padres, op_last, etc.

    Si necesita manipular ops a un nivel inferior, entonces tres nuevas macros, "OpMORESIB_set", "OpLASTSIB_set" y "OpMAYBESIB_set" están destinadas a ser una forma portátil de bajo nivel para establecer "op_sibling" / "op_sibparent" al mismo tiempo que se actualiza "op_moresib". La primera establece el puntero del hermano a un nuevo hermano, la segunda hace que el op sea el último hermano, y la tercera realiza condicionalmente la primera o segunda acción. Tenga en cuenta que, a diferencia de op_sibling_splice(), estas macros no mantendrán la consistencia en el padre al mismo tiempo (por ejemplo, actualizando "op_first" y "op_last" cuando corresponda).

    Se han agregado una función Perl_op_parent() a nivel de C y un método B::OP::parent() a nivel de Perl. La función C solo existe en compilaciones "PERL_OP_PARENT" (usarla es un error en tiempo de compilación en perls genéricos). B::OP::parent() existe siempre, pero en una compilación genérica siempre devuelve "NULL". Bajo "PERL_OP_PARENT", devuelven el padre del op actual, si lo hay. La variable $B::OP::does_parent le permite determinar si "B" admite la recuperación del padre de un op.

    "PERL_OP_PARENT" se introdujo en 5.21.2, pero la interfaz se modificó considerablemente en 5.21.11. Si actualizó su código antes de los cambios de 5.21.11, puede requerir una revisión adicional. Los principales cambios después de 5.21.2 fueron:

    • Las macros "OP_SIBLING" y "OP_HAS_SIBLING" han sido renombradas a "OpSIBLING" y "OpHAS_SIBLING" para consistencia con otras macros de manipulación de ops.
    • El campo "op_lastsib" ha sido renombrado a "op_moresib", y su significado ha sido invertido.
    • La macro "OpSIBLING_set" ha sido eliminada y ha sido reemplazada por "OpMORESIB_set" et al.
    • La función op_sibling_splice() ahora acepta un argumento "parent" nulo cuando el empalme no afecta a los primeros o últimos ops en la cadena de hermanos.
    • Se han creado macros para permitir que el código XS manipule mejor la categoría de localización POSIX "LC_NUMERIC". Consulte "Funciones y macros relacionadas con la localización" en perlapi.
    • La función de reemplazo anterior "atoi" et al, "grok_atou", ha sido
    • Ha sido reemplazada por `"grok_atoUV"`. Ver perlclib para más detalles.
    • Se ha añadido una nueva función, Perl_sv_get_backrefs(), que permite recuperar las referencias débiles, si las hay, que apuntan a un SV.
    • La función screaminstr() ha sido eliminada. Aunque estaba marcada como API pública, no estaba documentada y no tenía uso en módulos de CPAN. Llamarla ha sido fatal desde la versión 5.17.0.
    • Las funciones newDEFSVOP(), block_start(), block_end() y intro_my() se han añadido a la API.
    • La función interna "convert" en op.c ha sido renombrada a "op_convert_list" y añadida a la API.
    • La función sv_magic() ya no prohíbe la magia "ext" en valores de solo lectura. Después de todo, perl no puede saber si la magia personalizada modificará el SV o no. [GH #14202] https://github.com/Perl/perl5/issues/14202.
    • El acceso a "CvPADLIST" en perlapi en un XSUB ahora está prohibido.

      El campo `"CvPADLIST"` ha sido reutilizado para un propósito interno diferente para los XSUBs. Por lo tanto, en particular, ya no puedes confiar en que sea NULL como prueba de si un CV es un XSUB. Usa CvISXSUB() en su lugar.

    • Los SVs de tipo "SVt_NV" ahora son a veces sin cuerpo cuando la configuración de compilación y la plataforma lo permiten: específicamente, cuando sizeof(NV) <= sizeof(IV). "Sin cuerpo" significa que el valor NV se almacena directamente en la cabecera de un SV, sin necesidad de asignar un cuerpo separado. Este truco ya se ha utilizado para los IVs desde la versión 5.9.2 (aunque en el caso de los IVs, siempre se usa, independientemente de la plataforma y la configuración de compilación).
    • Las variables $DB::single, $DB::signal y $DB::trace ahora tienen magia de establecimiento y obtención que almacena sus valores como IVs, y esos IVs se utilizan al probar sus valores en pp_dbstate(). Esto evita que perl entre en recursión infinita si se asigna un objeto sobrecargado a cualquiera de esas variables. [GH #14013] https://github.com/Perl/perl5/issues/14013.
    • Perl_tmps_grow(), que está marcada como API pública pero no está documentada, ha sido eliminada de la API pública. Este cambio no afecta al código XS que utiliza la macro "EXTEND_MORTAL" para pre-extender la pila mortal.
    • Los internos de Perl ya no establecen ni utilizan el indicador "SVs_PADMY". SvPADMY() ahora devuelve un valor verdadero para todo lo que no esté marcado como "PADTMP" y "SVs_PADMY" se define ahora como 0.
    • Las macros "SETsv" y "SETsvUN" han sido eliminadas. Ya no se utilizaban en el núcleo desde el commit 6f1401dc2a hace cinco años, y no se han encontrado en CPAN.
    • El bit "SvFAKE" (no utilizado en HVs) fue reservado informalmente por David Mitchell para trabajos futuros sobre vtables.
    • La función sv_catpvn_flags() acepta las banderas "SV_CATBYTES" y "SV_CATUTF8", que especifican si la cadena añadida son bytes o UTF-8, respectivamente. (Estas banderas han estado presentes de hecho desde la versión 5.16.0, pero anteriormente no se consideraban parte de la API).
    • Se ha introducido una nueva clase de opcode, "METHOP". Contiene información utilizada en tiempo de ejecución para mejorar el rendimiento de las llamadas a métodos de clase/objeto.

      "OP_METHOD" y "OP_METHOD_NAMED" han pasado de ser "UNOP/SVOP" a ser "METHOP".

    • cv_name() es una nueva función de API a la que se le puede pasar un CV o un GV. Devuelve un SV que contiene el nombre de la subrutina, para su uso en diagnósticos.

      [GH #12767] https://github.com/Perl/perl5/issues/12767 [GH #13392] https://github.com/Perl/perl5/issues/13392

    • cv_set_call_checker_flags() es una nueva función de API que funciona como cv_set_call_checker(), excepto que permite al llamador especificar si el verificador de llamadas requiere un GV completo para informar el nombre de la subrutina, o si se le puede pasar un CV en su lugar. Cualquier valor que se pase será aceptado por cv_name(). cv_set_call_checker() garantiza que habrá un GV, pero puede que tenga que crearlo sobre la marcha, lo cual es ineficiente. [GH #12767] https://github.com/Perl/perl5/issues/12767
    • "CvGV" (que no forma parte de la API) es ahora una macro más compleja, que puede llamar a una función y reificar un GV. Para aquellos casos en los que se ha utilizado como booleano, se ha añadido "CvHASGV", que devolverá verdadero para los CVs que notionally tienen GVs, pero sin reificar el GV. "CvGV" también devuelve un GV ahora para los subs léxicos. [GH #13392] https://github.com/Perl/perl5/issues/13392
    • La función "sync_locale" en perlapi se ha añadido a la API pública. Se debe evitar cambiar la configuración regional del programa por parte del código XS. Sin embargo, ciertas bibliotecas no Perl llamadas desde XS necesitan hacerlo, como "Gtk". Cuando esto sucede, Perl necesita saber que la configuración regional ha cambiado. Utiliza esta función para hacerlo, antes de volver a Perl.
    • Las definiciones y etiquetas para las banderas en el campo "op_private" de los OPs ahora se generan automáticamente a partir de datos en regen/op_private. El efecto notable de esto es que parte de la salida de banderas de "Concise" puede diferir ligeramente, y la salida de banderas de "perl -Dx" puede diferir considerablemente (ambos usan el mismo conjunto de etiquetas ahora). Además, las compilaciones de depuración ahora tienen una nueva aserción en op_free() para asegurar que el op no tenga ninguna bandera no reconocida establecida en "op_private".
    • La variable obsoleta "PL_sv_objcount" ha sido eliminada.
    • Perl ahora intenta mantener la categoría de localización "LC_NUMERIC" establecida en "C" excepto en operaciones que la requieren. Esto protege a muchos módulos XS que no pueden manejar que el carácter de radix decimal no sea un punto. Antes de esta versión, Perl inicializaba esta categoría a "C", pero una llamada a POSIX::setlocale() la cambiaba. Ahora tal llamada cambiará la localización subyacente de la categoría "LC_NUMERIC" para el programa, pero la localización expuesta al código XS seguirá siendo "C". Hay nuevas macros para manipular la localización LC_NUMERIC, incluyendo "STORE_LC_NUMERIC_SET_TO_NEEDED" y "STORE_LC_NUMERIC_FORCE_TO_UNDERLYING". Ver "Funciones y macros relacionadas con la localización" en perlapi.
    • Se ha escrito una nueva macro "isUTF8_CHAR" que determina eficientemente si la cadena dada por sus parámetros comienza con un carácter codificado en UTF-8 bien formado.
    • A las siguientes funciones de API privada se les ha eliminado el parámetro de contexto: "Perl_cast_ulong", "Perl_cast_i32", "Perl_cast_iv", "Perl_cast_uv", "Perl_cv_const_sv", "Perl_mg_find", "Perl_mg_findext", "Perl_mg_magical", "Perl_mini_mktime", "Perl_my_dirfd", "Perl_sv_backoff", "Perl_utf8_hop".

      Tenga en cuenta que las versiones sin prefijo de esas funciones que forman parte de la API pública, como cast_i32(), permanecen sin cambios.

    • Los tipos "PADNAME" y "PADNAMELIST" son ahora tipos separados, y ya no alias simples de SV y AV. [GH #14250] https://github.com/Perl/perl5/issues/14250.
    • Los nombres de pads ahora son siempre UTF-8. La macro "PadnameUTF8" siempre devuelve verdadero. Anteriormente, este era efectivamente el caso, pero se ha eliminado cualquier soporte para dos representaciones internas diferentes de nombres de pads.
    • Se ha añadido una nueva clase de op, "UNOP_AUX". Es una subclase de "UNOP" con un campo "op_aux" añadido, que apunta a un array de uniones de UV, SV*, etc. Está destinado a situaciones donde un op necesita almacenar más datos que un simple "op_sv" o similar. Actualmente, el único op de este tipo es "OP_MULTIDEREF" (ver el siguiente elemento).
    • Se ha añadido un nuevo op, "OP_MULTIDEREF", que realiza una o más búsquedas anidadas de arrays y hashes donde la clave es una constante o una variable simple. Por ejemplo, la expresión "$a[0]{$k}[$i]", que anteriormente implicaba diez ops "rv2Xv", "Xelem", "gvsv" y "const", ahora es realizada por un único op "multideref". También puede manejar "local", "exists" y "delete". Un índice de expresión no simple, como "[$i+1]", todavía se realiza utilizando "aelem"/"helem", y la búsqueda de array de un solo nivel con un índice constante pequeño todavía se realiza utilizando "aelemfast".

    Correcciones de Errores Seleccionadas

    • "close" ahora establece $!

      Cuando ocurre un error de E/S, el hecho de que ha habido un error se registra en el manejador. "close" devuelve falso para dicho manejador. Anteriormente, el valor de $! no se veía afectado por "close", por lo que la convención común de escribir "close $fh o die $! " no funcionaba de manera fiable. Ahora el manejador registra el valor de $! también, y "close" lo restaura.

    • "no re" ahora puede desactivar todo lo que "use re" habilita

      Anteriormente, ejecutar "no re" desactivaba solo algunas cosas. Ahora puede desactivar todas las cosas habilitadas. Por ejemplo, la única forma de detener la depuración, una vez habilitada, era salir del bloque envolvente; esto ahora está arreglado.

    • "pack("D", $x)" y "pack("F", $x)" ahora ponen a cero el relleno en compilaciones de long double x86. Bajo algunas opciones de compilación en GCC 4.8 y posteriores, solían sobrescribir el relleno inicializado a cero o evitar el búfer inicializado por completo. Esto causaba que op/pack.t fallara. [GH #14554] https://github.com/Perl/perl5/issues/14554
    • Extender un array clonado de un hilo padre podía resultar en errores de "Se intentó modificar un valor de solo lectura" al intentar modificar los nuevos elementos. [GH #14605] https://github.com/Perl/perl5/issues/14605

    Changes to Perl Version 5.22.0

    This document lists the changes made between Perl 5.20.1 and Perl 5.22.0.

    Core Enhancements

    • Perl now issues a warning when a regular expression is compiled containing a Unicode character property that is deprecated or has been removed from the Unicode standard. The warning indicates the property name and the version of the Unicode standard in which it was last seen.

    • The POSIX::localeconv() function is now available as a built-in function, removing the need to explicitly use POSIX.

    • POSIX::localeconv() now appropriately marks the values it returns as UTF-8 or not. Previously, they were always returned as bytes, even if they were supposed to be encoded as UTF-8.

    • On Microsoft Windows, within the scope of "use locale", the following POSIX character classes gave results for many locales that did not conform to the POSIX standard: "[[:alnum:]]", "[[:alpha:]]", "[[:blank:]]", "[[:digit:]]", "[[:graph:]]", "[[:lower:]]", "[[:print:]]", "[[:punct:]]", "[[:upper:]]", "[[:word:]]", and "[[:xdigit:]]". This was because the underlying Microsoft implementation does not follow the standard. Perl now takes special precautions to correct for this.

    • Many issues have been detected by Coverity http://www.coverity.com/ and fixed.

    • system() and friends should now work properly on more Android builds.

      Due to an oversight, the value specified through "-Dtargetsh" to Configure would end up being ignored by some of the build process. This caused perls cross-compiled for Android to end up with defective versions of system(), exec() and backticks: the commands would end up looking for "/bin/sh" instead of "/system/bin/sh", and so would fail for the vast majority of devices, leaving $! as "ENOENT".

    • "qr(...\(...\)...)", "qr[...\[...\]...]", and "qr{...\{...\}...}" now work. Previously it was impossible to escape these three left-characters with a backslash within a regular expression pattern where otherwise they would be considered metacharacters, and the pattern opening delimiter was the character, and the closing delimiter was its mirror character.

    • "s///e" on tainted UTF-8 strings corrupted pos(). This bug, introduced in 5.20, is now fixed. [GH #13948] https://github.com/Perl/perl5/issues/13948.

    • A non-word boundary in a regular expression ("\B") did not always match the end of the string; in particular "q{} =~ /\B/" did not match. This bug, introduced in perl 5.14, is now fixed. [GH #13917] https://github.com/Perl/perl5/issues/13917.

    • "" P" =~ /(?=.*P)P/" should match, but did not. This is now fixed. [GH #13954] https://github.com/Perl/perl5/issues/13954.

    • Failing to compile "use Foo" in an "eval" could leave a spurious "BEGIN" subroutine definition, which would produce a "Subroutine BEGIN redefined" warning on the next use of "use", or other "BEGIN" block. [GH #13926] https://github.com/Perl/perl5/issues/13926.

    • "method { BLOCK } ARGS" syntax now correctly parses the arguments if they begin with an opening brace. [GH #9085] https://github.com/Perl/perl5/issues/9085.

    • External libraries and Perl may have different ideas of what the locale is. This is problematic when parsing version strings if the locale's numeric separator has been changed. Version parsing has been patched to ensure it handles the locales correctly. [GH #13863] https://github.com/Perl/perl5/issues/13863.

    • A bug has been fixed where zero-length assertions and code blocks inside of a regex could cause "pos" to see an incorrect value. [GH #14016] https://github.com/Perl/perl5/issues/14016.

    • Dereferencing of constants now works correctly for typeglob constants. Previously the glob was stringified and its name looked up. Now the glob itself is used. [GH #9891] https://github.com/Perl/perl5/issues/9891

    • When parsing a sigil ("$" "@" "%" "&)" followed by braces, the parser no longer tries to guess whether it is a block or a hash constructor (causing a syntax error when it guesses the latter), since it can only be a block.

    • "undef $reference" now frees the referent immediately, instead of hanging on to it until the next statement. [GH #14032] https://github.com/Perl/perl5/issues/14032

    • Various cases where the name of a sub is used (autoload, overloading, error messages) used to crash for lexical subs, but have been fixed.

    • Bareword lookup now tries to avoid vivifying packages if it turns out the bareword is not going to be a subroutine name.

    • Compilation of anonymous constants (e.g., "sub () { 3 }") no longer deletes any subroutine named "__ANON__" in the current package. Not only was "*__ANON__{CODE}" cleared, but there was a memory leak, too. This bug goes back to Perl 5.8.0.

    • Stub declarations like "sub f;" and "sub f ();" no longer wipe out constants of the same name declared by "use constant". This bug was introduced in Perl 5.10.0.

    • "qr/[\N{named sequence}]/" now works properly in many instances.

      Some names known to "\N{...}" refer to a sequence of multiple characters, instead of the usual single character. Bracketed character classes generally only match single characters, but now special handling has been added so that they can match named sequences, but not if the class is inverted or the sequence is specified as the beginning or end of a range. In these cases, the only behavior change from before is a slight rewording of the fatal error message given when this class is part of a "?[...])" construct. When the "[...]" stands alone, the same non-fatal warning as before is raised, and only the first character in the sequence is used, again just as before.

    • Tainted constants evaluated at compile time no longer cause unrelated statements to become tainted. [GH #14059] https://github.com/Perl/perl5/issues/14059

    • "open $$fh, ...", which vivifies a handle with a name like "main::_GEN_0", was not giving the handle the right reference count, so a double free could happen.

    • When deciding that a bareword was a method name, the parser would get confused if an "our" sub with the same name existed, and look up the method in the package of the "our" sub, instead of the package of the invocant.

    • The parser no longer gets confused by "\U=" within a double-quoted string. It used to produce a syntax error, but now compiles it correctly. [GH #10882] https://github.com/Perl/perl5/issues/10882

    • It has always been the intention for the "-B" and "-T" file test operators to treat UTF-8 encoded files as text. (perlfunc has been updated to say this.) Previously, it was possible for some files to be considered UTF-8 that actually weren't valid UTF-8. This is now fixed. The operators now work on EBCDIC platforms as well.

    • Under some conditions warning messages raised during regular expression pattern compilation were being output more than once. This has now been fixed.

    • Perl 5.20.0 introduced a regression in which a UTF-8 encoded regular expression pattern that contains a single ASCII lowercase letter did not match its uppercase counterpart. That has been fixed in both 5.20.1 and 5.22.0. [GH #14051] https://github.com/Perl/perl5/issues/14051

    • Constant folding could incorrectly suppress warnings if lexical warnings ("use warnings" or "no warnings") were not in effect and $^W were false at compile time and true at run time.

    • Loading Unicode tables during a regular expression match could cause assertion failures under debugging builds if the previous match used the very same regular expression. [GH #14081] https://github.com/Perl/perl5/issues/14081

    • Thread cloning used to work incorrectly for lexical subs, possibly causing crashes or double frees on exit.

    • Since Perl 5.14.0, deleting $SomePackage::{__ANON__} and then undefining an anonymous subroutine could corrupt things internally, resulting in Devel::Peek crashing or B.pm giving nonsensical data. This has been fixed.

    • "(caller $n)[3]" now reports names of lexical subs, instead of treating them as "(unknown)".

    • "sort subname LIST" now supports using a lexical sub as the comparison routine.

    • Aliasing (e.g., via "*x = *y") could confuse list assignments that mention the two names for the same variable on either side, causing wrong values to be assigned. [GH #5788] https://github.com/Perl/perl5/issues/5788

    • Long here-doc terminators could cause a bad read on short lines of input. This has been fixed. It is doubly unfortunate because the fix had to be backported to 5.18.4 and 5.20.2 as well.

    Reportar Errores

    Si encuentra lo que cree que es un error, puede consultar los artículos publicados recientemente en el grupo de noticias comp.lang.perl.misc y la base de datos de errores de Perl en https://rt.perl.org/. También puede haber información en http://www.perl.org/, la página principal de Perl.

    Si cree que tiene un error no reportado, ejecute el programa perlbug incluido con su versión. Asegúrese de reducir su error a un caso de prueba pequeño pero suficiente. Su informe de error, junto con la salida de "perl -V", se enviará a perlbug@perl.org para ser analizado por el equipo de portabilidad de Perl.

    Si el error que está informando tiene implicaciones de seguridad, lo que hace que no sea apropiado enviarlo a una lista de correo archivada públicamente, envíelo a perl5-security-report@perl.org. Esto apunta a una lista de correo de suscripción cerrada y sin archivar, que incluye a todos los confirmadores principales, quienes podrán ayudar a evaluar el impacto de los problemas, encontrar una solución y ayudar a coordinar la publicación de parches para mitigar o solucionar el problema en todas las plataformas en las que se soporta Perl. Utilice esta dirección solo para problemas de seguridad en el núcleo de Perl, no para módulos distribuidos de forma independiente en CPAN.
