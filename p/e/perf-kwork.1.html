NOMBRE

perf-kwork - Herramienta para rastrear/medir propiedades de trabajo del kernel (latencias)

SINOPSIS

perf kwork {record|report|latency|timehist|top}

DESCRIPCIÓN

Hay varias variantes de perf kwork:

'perf kwork record <comando>' para registrar el trabajo del kernel de una carga de trabajo arbitraria.
'perf kwork report' para informar el tiempo de ejecución por kwork.
'perf kwork latency' para informar las latencias por kwork.
'perf kwork timehist' proporciona un análisis de eventos de trabajo del kernel.
'perf kwork top' para informar el uso de CPU de la tarea.
Ejemplo de uso:
    perf kwork record -- sleep 1
    perf kwork report
    perf kwork report -b
    perf kwork latency
    perf kwork latency -b
    perf kwork timehist
    perf kwork top
    perf kwork top -b
Por defecto, muestra los eventos de trabajo individuales como irq, workqueue,
incluyendo el tiempo de ejecución y el retraso (tiempo entre el disparo y la entrada real):

OPCIONES

-D, --dump-raw-trace=

Muestra un volcado detallado de los datos de planificación.

-f, --force

No te quejes, hazlo.

-k, --kwork

Lista de kwork a perfilar (irq, softirq, workqueue, sched, etc.)

-v, --verbose

Sé más detallado (muestra la dirección del símbolo, etc.)

OPCIONES para perf kwork report

.ft C
-b::
--use-bpf::
        Usa BPF para medir el tiempo de ejecución del kwork
-C::
--cpu::
        Solo muestra eventos para la(s) CPU(s) dada(s) (lista separada por comas).
-i::
--input::
        Nombre del archivo de entrada. (por defecto: perf.data a menos que stdin sea una tubería con nombre)
-n::
--name::
        Solo muestra eventos para el nombre dado.
-s::
--sort::
        Ordenar por clave(s): tiempo de ejecución, máximo, recuento
-S::
--with-summary::
        Muestra un resumen con estadísticas
--time::
        Analiza solo las muestras dentro de la ventana de tiempo dada: <inicio>,<fin>. Los tiempos
        tienen el formato segundos.microsegundos. Si no se proporciona el inicio (es decir, la cadena de tiempo es ',x.y')
        entonces el análisis comienza al principio del archivo. Si no se proporciona el tiempo de fin (es decir, la cadena de tiempo es 'x.y,')
        entonces el análisis llega hasta el final del archivo.
