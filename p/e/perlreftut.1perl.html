NOMBRE

perlreftut - El tutorial muy corto de Mark sobre referencias

DESCRIPCIÓN

Una de las nuevas características más importantes en Perl 5 fue la capacidad de gestionar estructuras de datos complicadas como arrays multidimensionales y hashes anidados. Para habilitar esto, Perl 5 introdujo una característica llamada referencias, y el uso de referencias es la clave para gestionar datos estructurados y complicados en Perl. Desafortunadamente, hay mucha sintaxis extraña que aprender, y la página principal del manual puede ser difícil de seguir. El manual es bastante completo, y a veces la gente lo encuentra un problema, porque puede ser difícil saber qué es importante y qué no.

Afortunadamente, solo necesitas saber el 10% de lo que hay en la página principal para obtener el 90% del beneficio. Esta página te mostrará ese 10%.

¿Quién necesita estructuras de datos complicadas?

Un problema que surge todo el tiempo es la necesidad de un hash cuyos valores sean listas. Perl tiene hashes, por supuesto, pero los valores tienen que ser escalares; no pueden ser listas.

¿Por qué querrías un hash de listas? Tomemos un ejemplo simple: tienes un archivo de nombres de ciudades y países, como este:

Chicago, USA
Frankfurt, Germany
Berlin, Germany
Washington, USA
Helsinki, Finland
New York, USA

y quieres producir una salida como esta, con cada país mencionado una vez, y luego una lista alfabética de las ciudades de ese país:

Finland: Helsinki.
Germany: Berlin, Frankfurt.
USA:  Chicago, New York, Washington.

La forma natural de hacerlo es tener un hash cuyas claves son nombres de países. Asociado con cada clave de nombre de país hay una lista de las ciudades de ese país. Cada vez que lees una línea de entrada, la divides en un país y una ciudad, buscas la lista de ciudades que ya se sabe que están en ese país y añades la nueva ciudad a la lista. Cuando termines de leer la entrada, iteras sobre el hash como de costumbre, ordenando cada lista de ciudades antes de imprimirla.

Si los valores del hash no pudieran ser listas, pierdes. Probablemente tendrías que combinar todas las ciudades en una sola cadena de alguna manera, y luego, cuando llegara el momento de escribir la salida, tendrías que dividir la cadena en una lista, ordenar la lista y volver a convertirla en una cadena. Esto es complicado y propenso a errores. Y es frustrante, porque Perl ya tiene listas perfectamente buenas que resolverían el problema si tan solo pudieras usarlas.

La solución

Para cuando surgió Perl 5, ya estábamos atascados con este diseño: los valores del hash solo pueden ser escalares. La solución a esto son las referencias.

Una referencia es un valor escalar que se refiere a un array completo o a un hash completo (o a casi cualquier otra cosa). Los nombres son un tipo de referencia con el que ya estás familiarizado. Cada ser humano es una colección desordenada e inconveniente de células. Pero para referirse a un ser humano en particular, por ejemplo, el primer programador de computadoras, no es necesario describir cada una de sus células; todo lo que necesitas es la cadena escalar fácil y conveniente "Ada Lovelace".

Las referencias en Perl son como nombres para arrays y hashes. Son nombres privados e internos de Perl, por lo que puedes estar seguro de que no son ambiguos. A diferencia de un nombre humano, una referencia solo se refiere a una cosa, y siempre sabes a qué se refiere. Si tienes una referencia a un array, puedes recuperar el array completo de ella. Si tienes una referencia a un hash, puedes recuperar el hash completo de ella. Pero la referencia sigue siendo un valor escalar fácil y compacto.

No puedes tener un hash cuyos valores sean arrays; los valores del hash solo pueden ser escalares. Estamos atascados con eso. Pero una sola referencia puede apuntar a un array completo, y las referencias son escalares, por lo que puedes tener un hash de referencias a arrays, y actuará de manera muy parecida a un hash de arrays, y será tan útil como un hash de arrays.

Volveremos a este problema de ciudades-países más tarde, después de haber visto algo de sintaxis para gestionar referencias.

Sintaxis

Solo hay dos formas de crear una referencia, y solo dos formas de usarla una vez que la tienes.

Creación de referencias

Regla de Creación 1

Si pones un "\" delante de una variable, obtienes una referencia a esa variable.

$aref = \@array;         # $aref ahora contiene una referencia a @array
$href = \%hash;          # $href ahora contiene una referencia a %hash

Una vez que la referencia se almacena en una variable como $aref o $href, puedes copiarla o almacenarla igual que cualquier otro valor escalar:

$xy = $aref;             # $xy ahora contiene una referencia a @array
$p[3] = $href;           # $p[3] ahora contiene una referencia a %hash
$z = $p[3];              # $z ahora contiene una referencia a %hash

Estos ejemplos muestran cómo crear referencias a variables con nombre. A veces quieres crear un array o un hash que no tenga nombre. Esto es análogo a la forma en que te gusta poder usar la cadena "\n" o el número 80 sin tener que almacenarlo primero en una variable con nombre.

Regla de Creación 2

"[ ITEMS ]" crea un nuevo array anónimo, y devuelve una referencia a ese array. "{ ITEMS }" crea un nuevo hash anónimo, y devuelve una referencia a ese hash.

$aref = [ 1, "foo", undef, 13 ];
# $aref ahora contiene una referencia a un array
$href = { APR => 4, AUG => 8 };
# $href ahora contiene una referencia a un hash

Las referencias que obtienes de la regla 2 son el mismo tipo de referencias que obtienes de la regla 1:

# Esto:
$aref = [ 1, 2, 3 ];
# Hace lo mismo que esto:
@array = (1, 2, 3);
$aref = \@array;

La primera línea es una abreviatura de las siguientes dos líneas, excepto que no crea la variable de array superflua @array.

Si escribes solo "[]", obtienes un array anónimo nuevo y vacío. Si escribes solo "{}", obtienes un hash anónimo nuevo y vacío.

Uso de referencias

¿Qué puedes hacer con una referencia una vez que la tienes? Es un valor escalar, y hemos visto que puedes almacenarla como un escalar y recuperarla igual que cualquier escalar. Solo hay dos formas más de usarla:

Regla de Uso 1

Siempre puedes usar una referencia de array, entre llaves, en lugar del nombre de un array. Por ejemplo, "@{$aref}" en lugar de @array.

Aquí tienes algunos ejemplos de eso:

Arrays:

@a              @{$aref}                Un array
reverse @a      reverse @{$aref}        Invertir el array
$a[3]           ${$aref}[3]             Un elemento del array
$a[3] = 17;     ${$aref}[3] = 17        Asignar un elemento

En cada línea hay dos expresiones que hacen lo mismo. Las versiones de la izquierda operan en el array @a. Las versiones de la derecha operan en el array al que se refiere $aref. Una vez que encuentran el array en el que están operando, ambas versiones hacen lo mismo con los arrays.

Usar una referencia de hash es exactamente lo mismo:

%h              %{$href}              Un hash
keys %h         keys %{$href}         Obtener las claves del hash
$h{'red'}       ${$href}{'red'}       Un elemento del hash
$h{'red'} = 17  ${$href}{'red'} = 17  Asignar un elemento

Lo que sea que quieras hacer con una referencia, la Regla de Uso 1 te dice cómo hacerlo. Simplemente escribes el código de Perl que habrías escrito para hacer lo mismo con un array o hash normal, y luego reemplazas el nombre del array o hash con "{$referencia}". "¿Cómo itero sobre un array cuando lo único que tengo es una referencia?" Bueno, para iterar sobre un array, escribirías

for my $element (@array) {
  ...
}

así que reemplaza el nombre del array, @array, con la referencia:

for my $element (@{$aref}) {
  ...
}

"¿Cómo imprimo el contenido de un hash cuando lo único que tengo es una referencia?" Primero escribe el código para imprimir un hash:

for my $key (keys %hash) {
  print "$key => $hash{$key}\n";
}

Y luego reemplaza el nombre del hash con la referencia:

for my $key (keys %{$href}) {
  print "$key => ${$href}{$key}\n";
}

Reglas de uso

La Regla 1 de uso es todo lo que realmente necesitas, porque te dice cómo hacer absolutamente todo lo que necesitas hacer con las referencias. Pero lo más común que se hace con un array o un hash es extraer un solo elemento, y la notación de la Regla 1 de uso es engorrosa. Así que hay una abreviatura.

"${$aref}[3]" es demasiado difícil de leer, así que puedes escribir "$aref->[3]" en su lugar.

"${$href}{red}" es demasiado difícil de leer, así que puedes escribir "$href->{red}" en su lugar.

Si $aref contiene una referencia a un array, entonces "$aref->[3]" es el cuarto elemento del array. No confundas esto con $aref[3], que es el cuarto elemento de un array totalmente diferente, uno llamado engañosamente @aref. $aref y @aref no están relacionados de la misma manera que $item y @item.

Del mismo modo, "$href->{'red'}" es parte del hash al que se refiere la variable escalar $href, quizás incluso uno sin nombre. $href{'red'} es parte del hash engañosamente llamado %href. Es fácil olvidar omitir el "->, y si lo haces, obtendrás resultados extraños cuando tu programa obtenga elementos de array y hash de hashes y arrays totalmente inesperados que no eran los que querías usar.

Un ejemplo

Veamos un ejemplo rápido de lo útil que es todo esto.

Primero, recuerda que crea un array anónimo que contiene y te da una referencia a ese array.

Ahora piensa en

@a = ( [1, 2, 3],
       [4, 5, 6],
       [7, 8, 9]
     );

@a es un array con tres elementos, y cada uno es una referencia a otro array.

$a[1] es una de estas referencias. Se refiere a un array, el array que contiene , y debido a que es una referencia a un array, la Regla 2 de uso dice que podemos escribir "$a[1]->[2]" para obtener el tercer elemento de ese array. "$a[1]->[2]" es el 6. Del mismo modo, "$a[0]->[1]" es el 2. Lo que tenemos aquí es como un array bidimensional; puedes escribir "$a[FILA]->[COLUMNA]" para obtener o establecer el elemento en cualquier fila y cualquier columna del array.

La notación todavía parece un poco engorrosa, así que hay una abreviatura más:

Regla de la flecha

Entre dos índices, la flecha es opcional.

En lugar de "$a[1]->[2]", podemos escribir "$a[1][2]"; significa lo mismo. En lugar de "$a[0]->[1] = 23", podemos escribir "$a[0][1] = 23"; significa lo mismo.

¡Ahora realmente parecen arrays bidimensionales!

Puedes ver por qué las flechas son importantes. Sin ellas, habríamos tenido que escribir "${$a[1]}[2]" en lugar de "$a[1][2]". Para arrays tridimensionales, nos permiten escribir "$x[2][3][5]" en lugar del ininteligible "${${$x[2]}[3]}[5]".

Solución

Aquí está la respuesta al problema que planteé anteriormente, de reformatear un archivo de nombres de ciudades y países.

 1   my %table;
 2   while (<>) {
 3     chomp;
 4     my ($city, $country) = split /, /;
 5     $table{$country} = [] unless exists $table{$country};
 6     push @{$table{$country}}, $city;
 7   }
 8   for my $country (sort keys %table) {
 9     print "$country: ";
10     my @cities = @{$table{$country}};
11     print join ', ', sort @cities;
12     print ".\n";
13   }

El programa tiene dos partes: Las líneas 2-7 leen la entrada y construyen una estructura de datos, y las líneas 8-13 analizan los datos e imprimen el informe. Vamos a tener un hash, %table, cuyas claves son nombres de países y cuyos valores son referencias a arrays de nombres de ciudades. La estructura de datos se verá así:

   %table
+-------+---+
|       |   |   +-----------+--------+
|Germany| *---->| Frankfurt | Berlin |
|       |   |   +-----------+--------+
+-------+---+
|       |   |   +----------+
|Finland| *---->| Helsinki |
|       |   |   +----------+
+-------+---+
|       |   |   +---------+------------+----------+
|  USA  | *---->| Chicago | Washington | New York |
|       |   |   +---------+------------+----------+
+-------+---+

Primero veremos la salida. Suponiendo que ya tenemos esta estructura, ¿cómo la imprimimos?

 8   for my $country (sort keys %table) {
 9     print "$country: ";
10     my @cities = @{$table{$country}};
11     print join ', ', sort @cities;
12     print ".\n";
13   }

%table es un hash ordinario, y obtenemos una lista de claves de él, ordenamos las claves y recorremos las claves como de costumbre. El único uso de referencias está en la línea 10. $table{$country} busca la clave $country en el hash y obtiene el valor, que es una referencia a un array de ciudades de ese país. La Regla 1 de uso dice que podemos recuperar el array diciendo "@{$table{$country}}". La línea 10 es como

@cities = @array;

excepto que el nombre "array" ha sido reemplazado por la referencia "{$table{$country}}". El "@" le dice a Perl que obtenga todo el array. Habiendo obtenido la lista de ciudades, la ordenamos, la unimos y la imprimimos como de costumbre.

Las líneas 2-7 son responsables de construir la estructura en primer lugar. Aquí están de nuevo:

2   while (<>) {
3     chomp;
4     my ($city, $country) = split /, /;
5     $table{$country} = [] unless exists $table{$country};
6     push @{$table{$country}}, $city;
7   }

Las líneas 2-4 obtienen un nombre de ciudad y país. La línea 5 comprueba si el país ya está presente como clave en el hash. Si no lo está, el programa utiliza la notación "[]" (Regla 2 de creación) para fabricar un nuevo array anónimo vacío de ciudades, y lo instala como referencia en el hash bajo la clave apropiada.

La línea 6 instala el nombre de la ciudad en el array apropiado. $table{$country} ahora contiene una referencia al array de ciudades vistas en ese país hasta ahora. La línea 6 es exactamente como

push @array, $city;

excepto que el nombre "array" ha sido reemplazado por la referencia "{$table{$country}}". El "push" añade un nombre de ciudad al final del array al que se refiere.

Hay un detalle fino que me salté. La línea 5 es innecesaria y podemos deshacernos de ella.

2   while (<>) {
3     chomp;
4     my ($city, $country) = split /, /;
5   ####  $table{$country} = [] unless exists $table{$country};
6     push @{$table{$country}}, $city;
7   }

Si ya existe una entrada en %table para el $country actual, entonces nada es diferente. La línea 6 localizará el valor en $table{$country}, que es una referencia a un array, y añadirá $city al array. Pero, ¿qué hace cuando $country contiene una clave, digamos "Greece", que aún no está en %table?

Esto es Perl, así que hace exactamente lo correcto. Ve que quieres añadir "Athens" a un array que no existe, así que amablemente crea un nuevo array anónimo y vacío para ti, lo instala en %table, y luego añade "Athens" a él. Esto se llama autovivificación - dar vida automáticamente. Perl vio que la clave no estaba en el hash, así que creó una nueva entrada de hash automáticamente. Perl vio que querías usar el valor del hash como un array, así que creó un nuevo array vacío y instaló una referencia a él en el hash automáticamente. Y como de costumbre, Perl hizo el array un elemento más largo para contener el nuevo nombre de la ciudad.

El resto

Te prometí darte el 90% del beneficio con el 10% de los detalles, y eso significa que omití el 90% de los detalles. Ahora que tienes una visión general de las partes importantes, debería ser más fácil leer la página del manual perlref, que discute el 100% de los detalles.

Algunos de los puntos destacados de perlref:

  • Puedes crear referencias a cualquier cosa, incluyendo escalares, funciones y otras referencias.
  • En la Regla 1 de uso, puedes omitir las llaves siempre que lo que esté dentro de ellas sea una variable escalar atómica como $aref. Por ejemplo, @$aref es lo mismo que "@{$aref}", y $$aref[1] es lo mismo que "${$aref}[1]". Si recién estás empezando, puede que quieras adoptar el hábito de incluir siempre las llaves.
  • Esto no copia el array subyacente: 
    $aref2 = $aref1;

    Obtienes dos referencias al mismo array. Si modificas "$aref1->[23]" y luego miras "$aref2->[23]", verás el cambio.

    Para copiar el array, usa

    $aref2 = [@{$aref1}];

    Esto usa la notación para crear un nuevo array anónimo, y se asigna una referencia al nuevo array a $aref2. El nuevo array se inicializa con el contenido del array al que se refiere $aref1.

    Del mismo modo, para copiar un hash anónimo, puedes usar

    $href2 = {%{$href1}};
  • Para ver si una variable contiene una referencia, usa la función "ref". Devuelve verdadero si su argumento es una referencia. En realidad, es un poco mejor que eso: devuelve
" para referencias a hashes y "ARRAY" para referencias a arrays.
  • Si intentas usar una referencia como una cadena, obtienes cadenas como 
    ARRAY(0x80f5dec)   o    HASH(0x826afc0)

    Si alguna vez ves una cadena que se ve así, sabrás que imprimiste una referencia por error.

    Un efecto secundario de esta representación es que puedes usar "eq" para ver si dos referencias se refieren a lo mismo. (Pero normalmente deberías usar "==" en su lugar porque es mucho más rápido.)

  • Puedes usar una cadena como si fuera una referencia. Si usas la cadena "foo" como una referencia de array, se toma como una referencia al array @foo. Esto se llama una referencia simbólica. La declaración "use strict 'refs'" deshabilita esta característica, lo que puede causar todo tipo de problemas si la usas por accidente.

    • Puede que prefieras continuar con perllol en lugar de perlref; discute listas de listas y arrays multidimensionales en detalle. Después de eso, deberías pasar a perldsc; es un Cookbook de Estructuras de Datos que muestra recetas para usar e imprimir arrays de hashes, hashes de arrays y otros tipos de datos.

    Resumen

    Todos necesitan estructuras de datos compuestas, y en Perl la forma de obtenerlas es con referencias. Hay cuatro reglas importantes para gestionar referencias: dos para crear referencias y dos para usarlas. Una vez que conozcas estas reglas, podrás hacer la mayoría de las cosas importantes que necesitas hacer con referencias.
