NOMBRE

perf_event_open - configurar la monitorización de rendimiento

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/perf_event.h>    /* Definición de constantes PERF_* */
#include <linux/hw_breakpoint.h> /* Definición de constantes HW_* */
#include <sys/syscall.h>         /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_perf_event_open, struct perf_event_attr *attr,
            pid_t pid, int cpu, int group_fd, unsigned long flags);

Nota: glibc no proporciona un envoltorio para perf_event_open(), haciendo necesario el uso de syscall(2).

DESCRIPCIÓN

Dada una lista de parámetros, perf_event_open() devuelve un descriptor de archivo, para usar en llamadas al sistema posteriores (read(2), mmap(2), prctl(2), fcntl(2), etc.).

Una llamada a perf_event_open() crea un descriptor de archivo que permite medir información de rendimiento. Cada descriptor de archivo corresponde a un evento que se mide; estos pueden agruparse para medir múltiples eventos simultáneamente.

Los eventos pueden habilitarse y deshabilitarse de dos maneras: mediante ioctl(2) y mediante prctl(2). Cuando un evento está deshabilitado, no cuenta ni genera desbordamientos, pero continúa existiendo y manteniendo su valor de cuenta.

Los eventos tienen dos sabores: de conteo y de muestreo. Un evento de conteo es uno que se utiliza para contar el número agregado de eventos que ocurren. En general, los resultados de los eventos de conteo se obtienen con una llamada a read(2). Un evento de muestreo escribe periódicamente mediciones en un búfer que luego puede ser accedido mediante mmap(2).

Argumentos

Los argumentos pid y cpu permiten especificar qué proceso y CPU monitorizar:

pid == 0 y cpu == -1
Esto mide el proceso/hilo de llamada en cualquier CPU.
pid == 0 y cpu >= 0
Esto mide el proceso/hilo de llamada solo cuando se ejecuta en la CPU especificada.
pid > 0 y cpu == -1
Esto mide el proceso/hilo especificado en cualquier CPU.
pid > 0 y cpu >= 0
Esto mide el proceso/hilo especificado solo cuando se ejecuta en la CPU especificada.
pid == -1 y cpu >= 0
Esto mide todos los procesos/hilos en la CPU especificada. Esto requiere la capacidad CAP_PERFMON (desde Linux 5.8) o CAP_SYS_ADMIN o un valor en /proc/sys/kernel/perf_event_paranoid menor que 1.
pid == -1 y cpu == -1
Esta configuración es inválida y devolverá un error.

Cuando pid es mayor que cero, el permiso para realizar esta llamada al sistema se rige por CAP_PERFMON (desde Linux 5.9) y una verificación de modo de acceso ptrace PTRACE_MODE_READ_REALCREDS en versiones anteriores de Linux; ver ptrace(2).

El argumento group_fd permite crear grupos de eventos. Un grupo de eventos tiene un evento que es el líder del grupo. El líder se crea primero, con group_fd = -1. Los demás miembros del grupo se crean con llamadas posteriores a perf_event_open() con group_fd establecido en el descriptor de archivo del líder del grupo. (Un solo evento por sí mismo se crea con group_fd = -1 y se considera un grupo con solo 1 miembro). Un grupo de eventos se programa en la CPU como una unidad: se pondrá en la CPU solo si todos los eventos del grupo pueden ser puestos en la CPU. Esto significa que los valores de los eventos miembros pueden ser comparados significativamente —sumados, divididos (para obtener ratios), y así sucesivamente— entre sí, ya que han contado eventos para el mismo conjunto de instrucciones ejecutadas.

El argumento flags se forma combinando mediante OR cero o más de los siguientes valores:

PERF_FLAG_FD_CLOEXEC (desde Linux 3.14)
Este indicador habilita el indicador close-on-exec para el descriptor de archivo de evento creado, de modo que el descriptor de archivo se cierre automáticamente en execve(2). Establecer los indicadores close-on-exec en el momento de la creación, en lugar de más tarde con fcntl(2), evita condiciones de carrera potenciales donde el hilo llamador invoca perf_event_open() y fcntl(2) al mismo tiempo que otro hilo llama a fork(2) y luego a execve(2).
PERF_FLAG_FD_NO_GROUP
Este indicador le dice al evento que ignore el parámetro group_fd, excepto para la configuración de redirección de salida utilizando el indicador PERF_FLAG_FD_OUTPUT.
PERF_FLAG_FD_OUTPUT (roto desde Linux 2.6.35)
Este indicador redirige la salida muestreada del evento para que se incluya en el búfer mmap del evento especificado por group_fd.
PERF_FLAG_PID_CGROUP (desde Linux 2.6.39)
Este indicador activa la monitorización a nivel de sistema por contenedor. Un contenedor es una abstracción que aísla un conjunto de recursos para un control más granular (CPUs, memoria, etc.). En este modo, el evento se mide solo si el hilo que se ejecuta en la CPU monitorizada pertenece al contenedor (cgroup) designado. El cgroup se identifica pasando un descriptor de archivo abierto en su directorio en el sistema de archivos cgroupfs. Por ejemplo, si el cgroup a monitorizar se llama test, entonces un descriptor de archivo abierto en /dev/cgroup/test (suponiendo que cgroupfs está montado en /dev/cgroup) debe pasarse como parámetro pid. La monitorización de cgroup solo está disponible para eventos a nivel de sistema y, por lo tanto, puede requerir permisos adicionales.

Los campos de la estructura perf_event_attr se describen con más detalle a continuación:

type
Este campo especifica el tipo general de evento. Tiene uno de los siguientes valores:
PERF_TYPE_HARDWARE
Esto indica uno de los eventos de hardware "generalizados" proporcionados por el kernel. Ver la definición del campo config para más detalles.
PERF_TYPE_SOFTWARE
Esto indica uno de los eventos definidos por software proporcionados por el kernel (incluso si no hay soporte de hardware disponible).
PERF_TYPE_TRACEPOINT
Esto indica un punto de rastreo proporcionado por la infraestructura de puntos de rastreo del kernel.
PERF_TYPE_HW_CACHE
Esto indica un evento de caché de hardware. Tiene una codificación especial, descrita en la definición del campo config.
PERF_TYPE_RAW
Esto indica un evento "crudo" específico de la implementación en el campo config.
PERF_TYPE_BREAKPOINT (desde Linux 2.6.33)
Esto indica un punto de interrupción de hardware según lo proporcionado por la CPU. Los puntos de interrupción pueden ser accesos de lectura/escritura a una dirección, así como la ejecución de una dirección de instrucción.
PMU dinámico
Desde Linux 2.6.38, perf_event_open() puede soportar múltiples PMU. Para habilitar esto, se puede usar un valor exportado por el kernel en el campo type para indicar qué PMU usar. El valor a usar se puede encontrar en el sistema de archivos sysfs: hay un subdirectorio por instancia de PMU bajo /sys/bus/event_source/devices. En cada subdirectorio, hay un archivo type cuyo contenido es un entero que se puede usar en el campo type. Por ejemplo, /sys/bus/event_source/devices/cpu/type contiene el valor para el PMU de CPU central, que generalmente es 4.
kprobe
uprobe (ambos desde Linux 4.17)
Estos dos PMU dinámicos crean un kprobe/uprobe y lo adjuntan al descriptor de archivo generado por perf_event_open. El kprobe/uprobe se destruirá al destruirse el descriptor de archivo. Ver los campos kprobe_func, uprobe_path, kprobe_addr y probe_offset para más detalles.
size
El tamaño de la estructura perf_event_attr para compatibilidad hacia adelante/atrás. Establezca esto usando sizeof(struct perf_event_attr) para permitir que el kernel vea el tamaño de la estructura en el momento de la compilación.
La definición relacionada PERF_ATTR_SIZE_VER0 se establece en 64; este era el tamaño de la primera estructura publicada. PERF_ATTR_SIZE_VER1 es 72, correspondiente a la adición de puntos de interrupción en Linux 2.6.33. PERF_ATTR_SIZE_VER2 es 80, correspondiente a la adición del muestreo de ramas en Linux 3.4. PERF_ATTR_SIZE_VER3 es 96, correspondiente a la adición de sample_regs_user y sample_stack_user en Linux 3.7. PERF_ATTR_SIZE_VER4 es 104, correspondiente a la adición de sample_regs_intr en Linux 3.19. PERF_ATTR_SIZE_VER5 es 112, correspondiente a la adición de aux_watermark en Linux 4.1.
config
Este campo especifica qué evento desea, en conjunción con el campo type. Los campos config1 y config2 también se tienen en cuenta en los casos en que 64 bits no es suficiente para especificar completamente el evento. La codificación de estos campos depende del evento.
Hay varias formas de establecer el campo config que dependen del valor del campo type descrito anteriormente. A continuación se presentan varias configuraciones posibles para config separadas por type.
Si type es PERF_TYPE_HARDWARE, estamos midiendo uno de los eventos de CPU de hardware generalizados. No todos están disponibles en todas las plataformas. Establezca config en uno de los siguientes:
PERF_COUNT_HW_CPU_CYCLES
Ciclos totales. Tenga cuidado con lo que sucede durante la escala de frecuencia de la CPU.
PERF_COUNT_HW_INSTRUCTIONS
Instrucciones retiradas. Tenga cuidado, estas pueden verse afectadas por varios problemas, en particular los recuentos de interrupciones de hardware.
PERF_COUNT_HW_CACHE_REFERENCES
Accesos a la caché. Normalmente, esto indica accesos a la caché de último nivel, pero esto puede variar según su CPU. Esto puede incluir prelecturas y mensajes de coherencia; de nuevo, esto depende del diseño de su CPU.
PERF_COUNT_HW_CACHE_MISSES
Fallos de caché. Normalmente, esto indica fallos de la caché de último nivel; está diseñado para usarse junto con el evento PERF_COUNT_HW_CACHE_REFERENCES para calcular las tasas de fallos de caché.
PERF_COUNT_HW_BRANCH_INSTRUCTIONS
Instrucciones de rama retiradas. Antes de Linux 2.6.35, esto usaba el evento incorrecto en procesadores AMD.
PERF_COUNT_HW_BRANCH_MISSES
Instrucciones de rama mal predichas.
PERF_COUNT_HW_BUS_CYCLES
Ciclos de bus, que pueden ser diferentes de los ciclos totales.
PERF_COUNT_HW_STALLED_CYCLES_FRONTEND (desde Linux 3.0)
Ciclos detenidos durante la emisión.
PERF_COUNT_HW_STALLED_CYCLES_BACKEND (desde Linux 3.0)
Ciclos detenidos durante la jubilación.
PERF_COUNT_HW_REF_CPU_CYCLES (desde Linux 3.3)
Ciclos totales; no afectado por la escala de frecuencia de la CPU.
Si type es PERF_TYPE_SOFTWARE, estamos midiendo eventos de software proporcionados por el kernel. Establezca config en uno de los siguientes:
PERF_COUNT_SW_CPU_CLOCK
Esto informa el reloj de la CPU, un temporizador por CPU de alta resolución.
PERF_COUNT_SW_TASK_CLOCK
Esto informa un recuento de reloj específico de la tarea que se está ejecutando.
PERF_COUNT_SW_PAGE_FAULTS
Esto informa el número de fallos de página.
PERF_COUNT_SW_CONTEXT_SWITCHES
Esto cuenta los cambios de contexto. Hasta Linux 2.6.34, todos se informaban como eventos del espacio de usuario, después de eso se informan como si ocurrieran en el kernel.
PERF_COUNT_SW_CPU_MIGRATIONS
Esto informa el número de veces que el proceso ha migrado a una nueva CPU.
PERF_COUNT_SW_PAGE_FAULTS_MIN
Esto cuenta el número de fallos de página menores. Estos no requirieron E/S de disco para manejarse.
PERF_COUNT_SW_PAGE_FAULTS_MAJ
Esto cuenta el número de fallos de página mayores. Estos requirieron E/S de disco para manejarse.
PERF_COUNT_SW_ALIGNMENT_FAULTS (desde Linux 2.6.33)
Esto cuenta el número de fallos de alineación. Estos ocurren cuando se producen accesos a memoria desalineados; el kernel puede manejarlos pero reduce el rendimiento. Esto solo ocurre en algunas arquitecturas (nunca en x86).
PERF_COUNT_SW_EMULATION_FAULTS (desde Linux 2.6.33)
Esto cuenta el número de fallos de emulación. El kernel a veces se interrumpe en instrucciones no implementadas y las emula para el espacio de usuario. Esto puede impactar negativamente el rendimiento.
PERF_COUNT_SW_DUMMY (desde Linux 3.12)
Este es un evento marcador de posición que no cuenta nada. Los tipos de registro de muestra informativos como mmap o comm deben asociarse con un evento activo. Este evento dummy permite recopilar dichos registros sin requerir un evento de conteo.
PERF_COUNT_SW_BPF_OUTPUT (desde Linux 4.4)
Esto se utiliza para generar datos de muestra sin procesar de BPF. Los programas BPF pueden escribir en este evento utilizando el ayudante bpf_perf_event_output.
PERF_COUNT_SW_CGROUP_SWITCHES (desde Linux 5.13)
Esto cuenta los cambios de contexto a una tarea en un cgroup diferente. En otras palabras, si la próxima tarea está en el mismo cgroup, no contará el cambio.
Si type es PERF_TYPE_TRACEPOINT, entonces estamos midiendo tracepoints del kernel. El valor a usar en config se puede obtener de debugfs tracing/events/*/*/id si ftrace está habilitado en el kernel.
Si type es PERF_TYPE_HW_CACHE, entonces estamos midiendo un evento de caché de CPU de hardware. Para calcular el valor apropiado de config, use la siguiente ecuación: 


config = (perf_hw_cache_id) |
         (perf_hw_cache_op_id << 8) |
         (perf_hw_cache_op_result_id << 16);

donde perf_hw_cache_id es uno de:

PERF_COUNT_HW_CACHE_L1D
para medir la caché de datos de Nivel 1
PERF_COUNT_HW_CACHE_L1I
para medir la caché de instrucciones de Nivel 1
PERF_COUNT_HW_CACHE_LL
para medir la caché de último nivel
PERF_COUNT_HW_CACHE_DTLB
para medir la TLB de datos
PERF_COUNT_HW_CACHE_ITLB
para medir la TLB de instrucciones
PERF_COUNT_HW_CACHE_BPU
para medir la unidad de predicción de ramas
PERF_COUNT_HW_CACHE_NODE (desde Linux 3.1)
para medir accesos locales a memoria

y perf_hw_cache_op_id es uno de:

PERF_COUNT_HW_CACHE_OP_READ
para accesos de lectura
PERF_COUNT_HW_CACHE_OP_WRITE
para accesos de escritura
PERF_COUNT_HW_CACHE_OP_PREFETCH
para accesos de prefetch

y perf_hw_cache_op_result_id es uno de:

PERF_COUNT_HW_CACHE_RESULT_ACCESS
para medir accesos
PERF_COUNT_HW_CACHE_RESULT_MISS
para medir fallos

Si type es PERF_TYPE_RAW, entonces se necesita un valor config "raw" personalizado. La mayoría de las CPUs admiten eventos que no están cubiertos por los eventos "generalizados". Estos se definen según la implementación; consulte el manual de su CPU (por ejemplo, la documentación del Volumen 3B de Intel, o la Guía para desarrolladores de BIOS y Kernel de AMD). La biblioteca libpfm4 se puede utilizar para traducir del nombre en los manuales arquitectónicos al valor hexadecimal crudo que perf_event_open() espera en este campo.

Si type es PERF_TYPE_BREAKPOINT, deje config establecido en cero. Sus parámetros se configuran en otros lugares.

Si type es kprobe o uprobe, establezca retprobe (bit 0 de config, consulte /sys/bus/event_source/devices/[k,u]probe/format/retprobe) para kretprobe/uretprobe. Consulte los campos kprobe_func, uprobe_path, kprobe_addr y probe_offset para obtener más detalles.

kprobe_func
uprobe_path
kprobe_addr
probe_offset
Estos campos describen el kprobe/uprobe para PMUs dinámicos kprobe y uprobe. Para kprobe: use kprobe_func y probe_offset, o use kprobe_addr y deje kprobe_func como NULL. Para uprobe: use uprobe_path y probe_offset.
sample_period
sample_freq
Un evento de "muestreo" es aquel que genera una notificación de desbordamiento cada N eventos, donde N viene dado por sample_period. Un evento de muestreo tiene sample_period > 0. Cuando ocurre un desbordamiento, los datos solicitados se registran en el búfer mmap. El campo sample_type controla qué datos se registran en cada desbordamiento.
sample_freq se puede usar si desea usar frecuencia en lugar de período. En este caso, establece el indicador freq. El kernel ajustará el período de muestreo para intentar lograr la tasa deseada. La tasa de ajuste es un tick del temporizador.
sample_type
Los diversos bits en este campo especifican qué valores incluir en la muestra. Se registrarán en un búfer de anillo, que está disponible para el espacio de usuario utilizando mmap(2). El orden en que se guardan los valores en la muestra se documenta en la subsección Diseño de MMAP a continuación; no es el orden de enum perf_event_sample_format.
PERF_SAMPLE_IP
Registra el puntero de instrucción.
PERF_SAMPLE_TID
Registra los identificadores de proceso e hilo.
PERF_SAMPLE_TIME
Registra una marca de tiempo.
PERF_SAMPLE_ADDR
Registra una dirección, si corresponde.
PERF_SAMPLE_READ
Registra los valores de los contadores para todos los eventos de un grupo, no solo para el líder del grupo.
PERF_SAMPLE_CALLCHAIN
Registra la cadena de llamadas (backtrace de pila).
PERF_SAMPLE_ID
Registra un ID único para el líder del grupo del evento abierto.
PERF_SAMPLE_CPU
Registra el número de CPU.
PERF_SAMPLE_PERIOD
Registra el período de muestreo actual.
PERF_SAMPLE_STREAM_ID
Registra un ID único para el evento abierto. A diferencia de PERF_SAMPLE_ID, se devuelve el ID real, no el líder del grupo. Este ID es el mismo que el devuelto por PERF_FORMAT_ID.
PERF_SAMPLE_RAW
Registra datos adicionales, si corresponde. Generalmente devuelto por eventos de tracepoint.
PERF_SAMPLE_BRANCH_STACK (desde Linux 3.4)
Esto proporciona un registro de ramas recientes, tal como lo proporciona el hardware de muestreo de ramas de la CPU (como Intel Last Branch Record). No todo el hardware admite esta característica.
Consulte el campo branch_sample_type para saber cómo filtrar qué ramas se informan.
PERF_SAMPLE_REGS_USER (desde Linux 3.7)
Registra el estado actual de los registros de la CPU a nivel de usuario (los valores en el proceso antes de que se llamara al kernel).
PERF_SAMPLE_STACK_USER (desde Linux 3.7)
Registra la pila a nivel de usuario, lo que permite el desenrollado de la pila.
PERF_SAMPLE_WEIGHT (desde Linux 3.10)
Registra un valor de peso proporcionado por el hardware que expresa cuán costoso fue el evento muestreado. Esto permite que el hardware resalte eventos costosos en un perfil.
PERF_SAMPLE_DATA_SRC (desde Linux 3.10)
Registra la fuente de datos: de dónde en la jerarquía de memoria provinieron los datos asociados con la instrucción muestreada. Esto solo está disponible si el hardware subyacente admite esta característica.
PERF_SAMPLE_IDENTIFIER (desde Linux 3.12)
Coloca el valor SAMPLE_ID en una posición fija en el registro, ya sea al principio (para eventos de muestra) o al final (si es un evento que no es de muestra).
Esto fue necesario porque un flujo de muestra puede tener registros de varios eventos diferentes.

No fue posible analizar correctamente el flujo de eventos porque se necesitaba el formato del registro para encontrar SAMPLE_ID, pero el formato no se pudo encontrar sin saber a qué evento pertenecía la muestra (lo que provocaba una dependencia circular).

Registra las razones de los eventos de aborto de memoria transaccional (por ejemplo, de soporte de memoria transaccional TSX de Intel).
La configuración precise_ip debe ser mayor que 0 y se debe medir un evento de aborto de memoria transaccional o no se registrarán valores. Tenga en cuenta también que algunas mediciones de perf_event, como el conteo de ciclos muestreados, pueden causar abortos extranágneos (al causar una interrupción durante una transacción).
PERF_SAMPLE_REGS_INTR (desde Linux 3.19)

Si la CPU admite el muestreo de hardware del estado de los registros (es decir, PEBS en x86 de Intel) y precise_ip se establece en un valor superior a cero, entonces los valores de los registros devueltos son los capturados por el hardware en el momento de la jubilación de la instrucción muestreada.

Registra la dirección física de los datos, como en PERF_SAMPLE_ADDR.

read_format
Este campo especifica el formato de los datos devueltos por read(2) en un descriptor de archivo de perf_event_open().
PERF_FORMAT_TOTAL_TIME_ENABLED
Añade el campo de 64 bits time_enabled. Esto se puede utilizar para calcular totales estimados si la PMU está sobrecargada y se está produciendo multiplexación.
PERF_FORMAT_TOTAL_TIME_RUNNING
Añade el campo de 64 bits time_running. Esto se puede utilizar para calcular totales estimados si la PMU está sobrecargada y se está produciendo multiplexación.
PERF_FORMAT_ID
Añade un valor único de 64 bits que corresponde al grupo de eventos.
PERF_FORMAT_GROUP
Permite leer todos los valores de contador de un grupo de eventos con una sola lectura.
PERF_FORMAT_LOST (desde Linux 6.0)
Añade un valor de 64 bits que es el número de muestras perdidas para este evento. Esto solo tendría sentido cuando se establecen sample_period o sample_freq.
disabled
El bit disabled especifica si el contador se inicia deshabilitado o habilitado. Si está deshabilitado, el evento se puede habilitar posteriormente mediante ioctl(2), prctl(2), o enable_on_exec.
Al crear un grupo de eventos, normalmente el líder del grupo se inicializa con disabled establecido en 1 y los eventos hijos se inicializan con disabled establecido en 0. A pesar de que disabled es 0, los eventos hijos no se iniciarán hasta que se habilite el líder del grupo.
inherit
El bit inherit especifica que este contador cuente los eventos de las tareas hijas además de la tarea especificada. Esto solo se aplica a los hijos nuevos, no a ningún hijo existente en el momento de la creación del contador (ni a ningún hijo nuevo de hijos existentes).
Heredar no funciona para algunas combinaciones de valores de read_format, como PERF_FORMAT_GROUP. Además, usarlo junto con cpu == -1 impide la creación del búfer de anillos mmap utilizado para registrar eventos asíncronos en modo muestreado.
pinned
El bit pinned especifica que el contador debe estar siempre en la CPU si es posible. Solo se aplica a los contadores de hardware y solo a los líderes de grupo. Si un contador fijado no se puede poner en la CPU (por ejemplo, porque no hay suficientes contadores de hardware o debido a un conflicto con algún otro evento), entonces el contador entra en un estado de 'error', donde las lecturas devuelven fin de archivo (es decir, read(2) devuelve 0) hasta que el contador se habilite o deshabilite posteriormente.
exclusive
El bit exclusive especifica que cuando el grupo de este contador esté en la CPU, debe ser el único grupo que utilice los contadores de la CPU. En el futuro, esto puede permitir que los programas de monitoreo admitan funciones de PMU que necesitan ejecutarse solas para no interrumpir otros contadores de hardware.
Tenga en cuenta que muchas situaciones inesperadas pueden impedir que los eventos con el bit exclusive establecido se ejecuten alguna vez. Esto incluye a cualquier usuario que ejecute una medición a nivel de sistema, así como cualquier uso del kernel de los contadores de rendimiento (incluida la interfaz NMI Watchdog Timer comúnmente habilitada).
exclude_user
Si este bit está establecido, el conteo excluye los eventos que ocurren en el espacio de usuario.
exclude_kernel
Si este bit está establecido, el conteo excluye los eventos que ocurren en el espacio del kernel.
exclude_hv
Si este bit está establecido, el conteo excluye los eventos que ocurren en el hipervisor. Esto es principalmente para PMUs que tienen soporte incorporado para manejar esto (como POWER). Se necesita soporte adicional para manejar mediciones de hipervisor en la mayoría de las máquinas.
exclude_idle
Si está establecido, no cuente cuando la CPU esté ejecutando la tarea inactiva. Aunque actualmente puede habilitar esto para cualquier tipo de evento, se ignora para todos excepto para los eventos de software.
mmap
El bit mmap habilita la generación de muestras PERF_RECORD_MMAP para cada llamada a mmap(2) que tiene PROT_EXEC establecido. Esto permite a las herramientas detectar nuevo código ejecutable que se mapea en un programa (bibliotecas compartidas dinámicas, por ejemplo) para que las direcciones se puedan mapear de nuevo al código original.
comm
El bit comm habilita el seguimiento del nombre del comando del proceso tal como lo modifican las llamadas al sistema execve(2) y prctl(PR_SET_NAME), así como la escritura en /proc/self/comm. Si el indicador comm_exec también se establece correctamente (posible desde Linux 3.16), entonces el indicador misceláneo PERF_RECORD_MISC_COMM_EXEC se puede utilizar para diferenciar el caso execve(2) de los demás.
freq
Si este bit está establecido, entonces se usa sample_frequency en lugar de sample_period al configurar el intervalo de muestreo.
inherit_stat
Este bit habilita el guardado de los recuentos de eventos en el cambio de contexto para las tareas heredadas. Esto solo tiene sentido si el campo inherit está establecido.
enable_on_exec
Si este bit está establecido, un contador se habilita automáticamente después de una llamada a execve(2).
task
Si este bit está establecido, entonces las notificaciones de fork/exit se incluyen en el búfer de anillos.
watermark
Si está establecido, una notificación de desbordamiento ocurre cuando se cruza el límite wakeup_watermark. De lo contrario, las notificaciones de desbordamiento ocurren después de wakeup_events muestras.
precise_ip (desde Linux 2.6.35)
Esto controla la cantidad de desplazamiento (skid). El desplazamiento es la cantidad de instrucciones que se ejecutan entre que ocurre un evento de interés y que el kernel puede detenerse y registrar el evento. Un desplazamiento menor es mejor y permite un informe más preciso de qué eventos corresponden a qué instrucciones, pero el hardware a menudo tiene limitaciones en cuanto a cuán pequeño puede ser esto.

Reading results

Once a perf_event_open() file descriptor has been opened, the values of the events can be read from the file descriptor. The values that are there are specified by the read_format field in the attr structure at open time.

If you attempt to read into a buffer that is not big enough to hold the data, the error ENOSPC results.

Here is the layout of the data returned by a read:

•
If PERF_FORMAT_GROUP was specified to allow reading all events in a group at once:

struct read_format {
    u64 nr;            /* The number of events */
    u64 time_enabled;  /* if PERF_FORMAT_TOTAL_TIME_ENABLED */
    u64 time_running;  /* if PERF_FORMAT_TOTAL_TIME_RUNNING */
    struct {
        u64 value;     /* The value of the event */
        u64 id;        /* if PERF_FORMAT_ID */
        u64 lost;      /* if PERF_FORMAT_LOST */
    } values[nr];
};

•
If PERF_FORMAT_GROUP was not specified:

struct read_format {
    u64 value;         /* The value of the event */
    u64 time_enabled;  /* if PERF_FORMAT_TOTAL_TIME_ENABLED */
    u64 time_running;  /* if PERF_FORMAT_TOTAL_TIME_RUNNING */
    u64 id;            /* if PERF_FORMAT_ID */
    u64 lost;          /* if PERF_FORMAT_LOST */

The number of events in this file descriptor. Available only if PERF_FORMAT_GROUP was specified.
time_enabled

Total time the event was enabled and running. Normally these values are the same. Multiplexing happens if the number of events is more than the number of available PMU counter slots. MMAP layout

When using perf_event_open() in sampled mode, asynchronous events (like counter overflow or PROT_EXEC mmap tracking) are logged into a ring-buffer. This ring-buffer is created and accessed through mmap(2).

The mmap size should be 1+2^n pages, where the first page is a metadata page (struct perf_event_mmap_page) that contains various bits of information such as where the ring-buffer head is.

Before Linux 2.6.39, there is a bug that means you must allocate an mmap ring buffer when sampling even if you do not plan to access it.

The structure of the first metadata mmap page is as follows:


struct perf_event_mmap_page {

    __u64 time_running;   /* time event on CPU */

    __u16 time_shift;

    __u64 time_offset;

Manejo de desbordamientos

Los eventos se pueden configurar para notificar cuando se cruza un umbral, indicando un desbordamiento. Las condiciones de desbordamiento se pueden capturar monitorizando el descriptor de archivo del evento con poll(2), select(2), o epoll(7). Alternativamente, los eventos de desbordamiento se pueden capturar a través de un manejador de señales, habilitando la señalización de E/S en el descriptor de archivo; consulte la discusión de las operaciones F_SETOWN y F_SETSIG en fcntl(2).

Los desbordamientos solo se generan por eventos de muestreo (sample_period debe tener un valor distinto de cero).

Hay dos formas de generar notificaciones de desbordamiento.

La primera es establecer un valor de wakeup_events o wakeup_watermark que se activará si un cierto número de muestras o bytes se han escrito en el búfer de anillo mmap. En este caso, se indica POLL_IN.

La otra forma es mediante el uso del ioctl PERF_EVENT_IOC_REFRESH. Este ioctl se suma a un contador que se decrementa cada vez que el evento se desborda. Cuando es distinto de cero, se indica POLL_IN, pero una vez que el contador alcanza 0, se indica POLL_HUP y el evento subyacente se deshabilita.

Actualizar el líder de un grupo de eventos actualiza a todos sus hermanos y actualizar con un parámetro de 0 actualmente permite actualizaciones infinitas; estos comportamientos no están soportados y no deben ser de fiar.

A partir de Linux 3.18, se indica POLL_HUP si el evento que se monitoriza está adjunto a un proceso diferente y ese proceso termina.

Instrucción rdpmc

A partir de Linux 3.4 en x86, puede usar la instrucción rdpmc para obtener lecturas de baja latencia sin tener que entrar en el kernel. Tenga en cuenta que usar rdpmc no es necesariamente más rápido que otros métodos para leer valores de eventos.

El soporte para esto se puede detectar con el campo cap_usr_rdpmc en la página mmap; la documentación sobre cómo calcular los valores de los eventos se puede encontrar en esa sección.

Originalmente, cuando el soporte de rdpmc estaba habilitado, cualquier proceso (no solo los que tenían un evento perf activo) podía usar la instrucción rdpmc para acceder a los contadores. A partir de Linux 4.0, el soporte de rdpmc solo se permite si un evento está actualmente habilitado en el contexto de un proceso. Para restaurar el comportamiento anterior, escriba el valor 2 en /sys/devices/cpu/rdpmc.

SYNOPSIS

#include <linux/perf_event.h>
#include <sys/ioctl.h>
#include <unistd.h>

int perf_event_open(struct perf_event_attr *attr, pid_t pid, int cpu, int group_fd, unsigned long flags);

DESCRIPTION

The perf_event_open() system call provides a generic interface for performance monitoring. It creates a file descriptor that represents a single performance monitoring event.

The structure attr points to a perf_event_attr structure that specifies the event to be created. This structure must be initialized to zeros before being filled in. The important fields are:

type
The type of event to monitor. This can be one of the following:
PERF_TYPE_HARDWARE
A hardware event (e.g., CPU cycles, cache misses). The specific event is specified by the config field.
PERF_TYPE_SOFTWARE
A software-defined event (e.g., context switches, page faults). The specific event is specified by the config field.
PERF_TYPE_TRACEPOINT
A kernel tracepoint. The specific tracepoint is specified by the config field.
PERF_TYPE_HW_CACHE
A hardware cache event. The specific cache and operation are specified by the config field.
PERF_TYPE_RAW
A raw hardware event. The specific event is specified by the config field.
PERF_TYPE_UNCORE (since Linux 3.17)
An uncore event. The specific event is specified by the config field.
size
The size of the perf_event_attr structure. This should be set to PERF_ATTR_SIZE_VER0 (or a larger supported size if known).
config
Specifies the event configuration. The meaning depends on the type field.
sample_period
For sampled events, this specifies the sampling period. For hardware events, it's the number of events to sample. For software events, it's the number of events to count before sampling. A value of 0 disables sampling.
sample_type
Specifies the information to include in each sample. Can be a bitmask of PERF_SAMPLE_* flags.
read_format
Specifies the format of the data read from the event file descriptor. Can be a bitmask of PERF_FORMAT_* flags.
disabled
If set to 1, the event is initially disabled. It can be enabled later using the PERF_EVENT_IOC_ENABLE ioctl.
inherit
If set to 1, the event inherits to child processes.
pinned
If set to 1, the event is pinned to the CPU. This is useful for groups of events that need to be measured simultaneously.
exclusive
If set to 1, the event must be the only event in its group. This is useful for events that require exclusive access to the PMU.
exclude_user
If set to 1, exclude user-space events.
exclude_kernel
If set to 1, exclude kernel-space events.
exclude_hv
If set to 1, exclude hypervisor events.
exclude_idle
If set to 1, exclude events that occur when the CPU is idle.
mmap
If set to 1, enable memory-mapped I/O for the event.
comm
If set to 1, include the command name in samples.
freq
If set to 1, use frequency-based sampling. Otherwise, use event-based sampling.
wakeup_events
Number of events to cause a wakeup.
wakeup_watermark
If set to 1, generate a wakeup when the watermark is reached.
precise_ip
If set to a value greater than 0, enable precise event counting. The value indicates the level of precision.
mmap_data (since Linux 4.9)
If set to 1, enable memory-mapped I/O for event data.
sample_max_stack (since Linux 4.14)
Maximum stack depth to record.
intr_freq (since Linux 5.7)
Deprecated. Use freq instead.
enable_on_exec
If set to 1, the event is enabled when a new program is executed.
task_clock (since Linux 3.14)
If set to 1, include task clock value in samples.
context_switch (since Linux 3.14)
If set to 1, include context switch information in samples.
write_backward (since Linux 4.7)
If set to 1, write samples backwards in the ring buffer.
namespaces (since Linux 4.17)
If set to 1, include namespace information in samples.
clockid (since Linux 5.1)
Clock ID to use for timestamping samples.
call_chain_flags (since Linux 5.4)
Flags for call chain sampling.
sample_regs_user (since Linux 5.6)
If set to 1, include user-space registers in samples.
sample_stack_user (since Linux 5.6)
If set to 1, include user-space stack in samples.

The pid argument specifies the process ID to monitor. If it is 0, the calling process is monitored. If it is -1, all processes on the specified CPU are monitored (requires CAP_SYS_ADMIN capability).

The cpu argument specifies the CPU to monitor. If it is -1, the event is tied to the CPU of the process specified by pid.

The group_fd argument specifies the file descriptor of a previously created event group. If it is -1, the new event is not part of any group.

The flags argument can be a bitmask of the following values:

PERF_FLAG_FD_CLOEXEC
Set the close-on-exec flag for the new file descriptor.
PERF_FLAG_FD_CLOFORK
Set the close-on-fork flag for the new file descriptor.
PERF_FLAG_PID_CGROUP (since Linux 4.4)
The pid argument is a file descriptor for a cgroup.
PERF_FLAG_KEEP_FOLLOWER (since Linux 5.1)
Keep following child processes after fork.
PERF_FLAG_MMAP_BENCHMARK (since Linux 5.5)
Enable mmap benchmark mode.

The returned file descriptor can be used with various ioctl operations to control the event and read its results.

The following ioctl calls are available:

PERF_EVENT_IOC_ENABLE
Enable the event or event group. The argument is a 32-bit integer. A non-zero value enables the event, while a zero value disables it.
PERF_EVENT_IOC_DISABLE
Disable the event or event group. The argument is a 32-bit integer. A non-zero value disables the event, while a zero value enables it.
PERF_EVENT_IOC_RESET
Reset the event's count to zero. The argument is ignored.
PERF_EVENT_IOC_SET_OUTPUT
This tells the kernel to report event notifications to the specified file descriptor rather than the default one. The file descriptors must all be on the same CPU.
The argument specifies the desired file descriptor, or -1 if output should be ignored.
PERF_EVENT_IOC_SET_FILTER (since Linux 2.6.33)
This adds an ftrace filter to this event.
The argument is a pointer to the desired ftrace filter.
PERF_EVENT_IOC_ID (since Linux 3.12)
This returns the event ID value for the given event file descriptor.
The argument is a pointer to a 64-bit unsigned integer to hold the result.
PERF_EVENT_IOC_SET_BPF (since Linux 4.1)
This allows attaching a Berkeley Packet Filter (BPF) program to an existing kprobe tracepoint event. You need CAP_PERFMON (since Linux 5.8) or CAP_SYS_ADMIN privileges to use this ioctl.
The argument is a BPF program file descriptor that was created by a previous bpf(2) system call.
PERF_EVENT_IOC_PAUSE_OUTPUT (since Linux 4.7)
This allows pausing and resuming the event's ring-buffer. A paused ring-buffer does not prevent generation of samples, but simply discards them. The discarded samples are considered lost, and cause a PERF_RECORD_LOST sample to be generated when possible. An overflow signal may still be triggered by the discarded sample even though the ring-buffer remains empty.
The argument is an unsigned 32-bit integer. A nonzero value pauses the ring-buffer, while a zero value resumes the ring-buffer.
PERF_EVENT_MODIFY_ATTRIBUTES (since Linux 4.17)
This allows modifying an existing event without the overhead of closing and reopening a new event. Currently this is supported only for breakpoint events.
The argument is a pointer to a perf_event_attr structure containing the updated event settings.
PERF_EVENT_IOC_QUERY_BPF (since Linux 4.16)
This allows querying which Berkeley Packet Filter (BPF) programs are attached to an existing kprobe tracepoint. You can only attach one BPF program per event, but you can have multiple events attached to a tracepoint. Querying this value on one tracepoint event returns the ID of all BPF programs in all events attached to the tracepoint. You need CAP_PERFMON (since Linux 5.8) or CAP_SYS_ADMIN privileges to use this ioctl.
The argument is a pointer to a structure 
struct perf_event_query_bpf {
    __u32    ids_len;
    __u32    prog_cnt;
    __u32    ids[0];
};

The ids_len field indicates the number of ids that can fit in the provided ids array. The prog_cnt value is filled in by the kernel with the number of attached BPF programs. The ids array is filled with the ID of each attached BPF program. If there are more programs than will fit in the array, then the kernel will return ENOSPC and ids_len will indicate the number of program IDs that were successfully copied.

Using prctl(2)

A process can enable or disable all currently open event groups using the prctl(2) PR_TASK_PERF_EVENTS_ENABLE and PR_TASK_PERF_EVENTS_DISABLE operations. This applies only to events created locally by the calling process. This does not apply to events created by other processes attached to the calling process or inherited events from a parent process. Only group leaders are enabled and disabled, not any other members of the groups.

perf_event related configuration files

Files in /proc/sys/kernel/

/proc/sys/kernel/perf_event_paranoid
The perf_event_paranoid file can be set to restrict access to the performance counters.
2
allow only user-space measurements (default since Linux 4.6).
1
allow both kernel and user measurements (default before Linux 4.6).
0
allow access to CPU-specific data but not raw tracepoint samples.
-1
no restrictions.
The existence of the perf_event_paranoid file is the official method for determining if a kernel supports perf_event_open().
/proc/sys/kernel/perf_event_max_sample_rate
This sets the maximum sample rate. Setting this too high can allow users to sample at a rate that impacts overall machine performance and potentially lock up the machine. The default value is 100000 (samples per second).
/proc/sys/kernel/perf_event_max_stack
This file sets the maximum depth of stack frame entries reported when generating a call trace.
/proc/sys/kernel/perf_event_mlock_kb
Maximum number of pages an unprivileged user can mlock(2). The default is 516 (kB).

Files in /sys/bus/event_source/devices/

Since Linux 2.6.34, the kernel supports having multiple PMUs available for monitoring. Information on how to program these PMUs can be found under /sys/bus/event_source/devices/. Each subdirectory corresponds to a different PMU.
/sys/bus/event_source/devices/*/type (since Linux 2.6.38)
This contains an integer that can be used in the type field of perf_event_attr to indicate that you wish to use this PMU.
/sys/bus/event_source/devices/cpu/rdpmc (since Linux 3.4)
If this file is 1, then direct user-space access to the performance counter registers is allowed via the rdpmc instruction. This can be disabled by echoing 0 to the file.
As of Linux 4.0 the behavior has changed, so that 1 now means only allow access to processes with active perf events, with 2 indicating the old allow-anyone-access behavior.
/sys/bus/event_source/devices/*/format/ (since Linux 3.4)
This subdirectory contains information on the architecture-specific subfields available for programming the various config fields in the perf_event_attr struct.
The content of each file is the name of the config field, followed by a colon, followed by a series of integer bit ranges separated by commas. For example, the file event may contain the value config1:1,6-10,44 which indicates that event is an attribute that occupies bits 1,6–10, and 44 of perf_event_attr::config1.
/sys/bus/event_source/devices/*/events/ (since Linux 3.4)
This subdirectory contains files with predefined events. The contents are strings describing the event settings expressed in terms of the fields found in the previously mentioned ./format/ directory. These are not necessarily complete lists of all events supported by a PMU, but usually a subset of events deemed useful or interesting.
The content of each file is a list of attribute names separated by commas. Each entry has an optional value (either hex or decimal). If no value is specified, then it is assumed to be a single-bit field with a value of 1. An example entry may look like this: event=0x2,inv,ldlat=3.
/sys/bus/event_source/devices/*/uevent
This file is the standard kernel device interface for injecting hotplug events.
/sys/bus/event_source/devices/*/cpumask (since Linux 3.7)
The cpumask file contains a comma-separated list of integers that indicate a representative CPU number for each socket (package) on the motherboard. This is needed when setting up uncore or northbridge events, as those PMUs present socket-wide events.

RETURN VALUE

On success, perf_event_open() returns the new file descriptor. On error, -1 is returned and errno is set to indicate the error.

Returned if the perf_event_attr size value is too small (smaller than PERF_ATTR_SIZE_VER0), too big (larger than the page size), or larger than the kernel supports and the extra bytes are not zero. Returned if the group_fd file descriptor is not valid, or, if PERF_FLAG_PID_CGROUP is set, the cgroup file descriptor in pid is not valid.
