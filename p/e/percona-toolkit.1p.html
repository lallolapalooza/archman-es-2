NOMBRE

percona-toolkit - Herramientas avanzadas de línea de comandos para MySQL

DESCRIPCIÓN

Percona Toolkit es una colección de herramientas avanzadas de línea de comandos utilizadas por el personal de soporte de Percona (http://www.percona.com/) para realizar una variedad de tareas de MySQL y del sistema que son demasiado difíciles o complejas de realizar manualmente.

Estas herramientas son alternativas ideales a scripts privados o "de un solo uso" porque están desarrolladas profesionalmente, probadas formalmente y completamente documentadas. También son completamente autocontenidas, por lo que la instalación es rápida y fácil, y no se instalan bibliotecas.

Percona Toolkit se deriva de Maatkit y Aspersa, dos de los kits de herramientas más conocidos para la administración de servidores MySQL. Es desarrollado y soportado por Percona. Para obtener más información y otro software gratuito de código abierto desarrollado por Percona, visite http://www.percona.com/software/.

TIPOS DE OPCIONES ESPECIALES

Las opciones de las herramientas utilizan tipos estándar ("int", "string", etc.) así como estos tipos especiales:

tiempo
Los valores de tiempo son segundos por defecto. Por ejemplo, "--run-time 60" significa 60 segundos. Los valores de tiempo admiten un sufijo opcional: s (segundos), m (minutos), h (horas), d (días). "--run-time 1m" significa 1 minuto (lo mismo que 60 segundos).
tamaño
Los valores de tamaño son bytes por defecto. Por ejemplo, "--disk-space-free 1024" significa 1 Kibibyte. Los valores de tamaño admiten un sufijo opcional: k (Kibibyte), M (Mebibyte), G (Gibibyte).
DSN
Ver "ESPECIFICACIONES DSN (NOMBRE DE ORIGEN DE DATOS)".
Hash, hash, Array, array
Los valores Hash, hash, Array y array son listas separadas por comas de valores. Por ejemplo, "--ignore-tables foo,bar" ignora las tablas "foo" y "bar".

ARCHIVOS DE CONFIGURACIÓN

Las herramientas de Percona Toolkit pueden leer opciones de archivos de configuración. La sintaxis del archivo de configuración es simple y directa, y tiene algunas similitudes con las herramientas de cliente de línea de comandos de MySQL. Todos los archivos de configuración siguen las mismas convenciones.

>Internamente, lo que realmente sucede es que las líneas se leen del archivo y luego se agregan como opciones de línea de comandos y argumentos a la herramienta, así que piense en los archivos de configuración como una forma de escribir sus líneas de comandos.

SINTAXIS

La sintaxis de los archivos de configuración es la siguiente:

  • Espacio en blanco seguido de un signo de almohadilla (#) significa que el resto de la línea es un comentario. Esto se elimina. Por ejemplo:
  • El espacio en blanco se elimina del principio y del final de todas las líneas.
  • Las líneas vacías se ignoran.
  • A cada línea se le permite estar en cualquiera de los siguientes formatos: 
    opcion
opcion=valor

    No prefije la opción con "--". No ponga comillas a los valores, incluso si tienen espacios; los valores son literales. El espacio en blanco alrededor del signo igual se elimina durante el procesamiento.

  • Solo se reconocen las opciones largas.
  • Una línea que contiene solo dos guiones señala el final del análisis de opciones. Cualquier línea posterior se interpreta como argumentos adicionales (no opciones) para el programa.

EJEMPLO

Este archivo de configuración para pt-stalk,

# Config para pt-stalk
variable=Threads_connected
cycles=2  # disparar si el problema se ve dos veces seguidas
--
--user daniel

es equivalente a esta línea de comandos:

pt-stalk --variable Threads_connected --cycles 2 -- --user daniel

Las opciones después de "--" se pasan literalmente a mysql y mysqladmin.

ORDEN LECTURA

Las herramientas leen varios archivos de configuración en orden:

1.
El archivo de configuración global de Percona Toolkit, /etc/percona-toolkit/percona-toolkit.conf. Todas las herramientas leen este archivo, por lo que solo debe agregarle opciones que desee aplicar a todas las herramientas.
2.
El archivo de configuración global específico de la herramienta, /etc/percona-toolkit/TOOL.conf, donde "TOOL" es un nombre de herramienta como "pt-query-digest". Este archivo se nombra según la herramienta específica que esté utilizando, por lo que puede agregar opciones que se apliquen solo a esa herramienta.
3.
El archivo de configuración de Percona Toolkit propio del usuario, $HOME/.percona-toolkit.conf. Todas las herramientas leen este archivo, por lo que solo debe agregarle opciones que desee aplicar a todas las herramientas.
4.
El archivo específico de la herramienta del usuario, $HOME/.TOOL.conf, donde "TOOL" es un nombre de herramienta como "pt-query-digest". Este archivo se nombra según la herramienta específica que esté utilizando, por lo que puede agregar opciones que se apliquen solo a esa herramienta.

ESPECIFICANDO

Hay una opción especial "--config", que le permite especificar qué archivos de configuración debe leer Percona Toolkit. Se especifica una lista de archivos separada por comas. Sin embargo, su comportamiento no es como el de otras opciones de línea de comandos. Debe darse primero en la línea de comandos, antes que cualquier otra opción. Si intenta especificarlo en cualquier otro lugar, causará un error. Además, no puede especificar "--config=/ruta/al/archivo"; debe especificar la opción y la ruta al archivo separados por espacio en blanco sin un signo de igual entre ellos, así:

--config /ruta/al/archivo

Si no desea ningún archivo de configuración, especifique "--config ''" para proporcionar una lista vacía de archivos.

DSN (NOMBRE FUENTE DATOS) ESPECIFICACIONES

Las herramientas de Percona Toolkit utilizan DSN para especificar cómo crear una conexión DBD a un servidor MySQL. Un DSN es una cadena separada por comas de partes "clave=valor", como:

h=host1,P=3306,u=bob

Las partes de clave estándar se muestran a continuación, pero algunas herramientas agregan partes de clave adicionales. Consulte la documentación de cada herramienta para obtener más detalles.

Algunas herramientas no utilizan DSN pero aún se conectan a MySQL utilizando opciones como "--host", "--user" y "--password". Dichas herramientas utilizan estas opciones para crear un DSN automáticamente, detrás de escena.

Otras herramientas utilizan tanto DSN como opciones como las anteriores. Las opciones proporcionan valores predeterminados para todas las DSN que no especifican la parte de clave correspondiente de la opción. Por ejemplo, si se especifican el DSN "h=host1" y la opción "--port=12345", la herramienta agrega automáticamente "P=12345" al DSN.

ESCRIBIR VALORES

Los DSN se especifican generalmente en la línea de comandos, por lo que se deben tener en cuenta las comillas y el escape de la shell. Los caracteres especiales, como el asterisco ("*"), deben entrecomillarse y/o escaparse correctamente para pasarse como caracteres literales en los valores DSN.

Dado que las partes del DSN están separadas por comas, las comas literales en los valores DSN deben escaparse con una barra invertida simple ("\"). Y dado que una barra invertida es el carácter de escape para la mayoría de las shells, se requieren dos barras invertidas para pasar una barra invertida literal. Por ejemplo, si el nombre de usuario es literalmente "my,name", debe especificarse como "my\\,name" en la mayoría de las shells. Esto se aplica a los DSN y a las opciones relacionadas con DSN como "--user".

PARTES CLAVE

Muchas de las herramientas agregan más partes a los DSN para fines especiales, y a veces anulan partes para hacer que hagan algo ligeramente diferente. Sin embargo, todas las herramientas admiten al menos las siguientes:

A
Juego de caracteres predeterminado para la conexión ("SET NAMES").

Habilita la configuración del juego de caracteres en Perl y MySQL. Si el valor es "utf8", establece el binmode de Perl en STDOUT como utf8, pasa la opción "mysql_enable_utf8" a DBD::mysql y ejecuta "SET NAMES 'utf8'" después de conectarse a MySQL. Otros valores establecen binmode en STDOUT sin la capa utf8 y ejecutan "SET NAMES" después de conectarse a MySQL.

Desafortunadamente, no hay forma desde dentro de Perl para especificar el juego de caracteres de la biblioteca cliente. "SET NAMES" solo afecta al servidor; si la configuración de la biblioteca cliente no coincide, podrían surgir problemas. Puede utilizar el archivo de valores predeterminados para especificar el juego de caracteres de la biblioteca cliente, sin embargo. Consulte la descripción de la parte F a continuación.

D
Base de datos predeterminada a usar al conectarse. Las herramientas pueden "USE" una base de datos diferente mientras se ejecutan.
F
Archivo de valores predeterminados para la biblioteca cliente de MySQL (la biblioteca cliente C utilizada por DBD::mysql, no Percona Toolkit en sí). Todas las herramientas leen la sección "[client]" dentro del archivo de valores predeterminados. Si omite esto, se leerán los archivos de valores predeterminados estándar en el orden habitual. "Estándar" varía de un sistema a otro, ya que los nombres de archivo a leer se compilan en la biblioteca cliente. En los sistemas Debian, por ejemplo, suele ser "/etc/mysql/my.cnf" luego "~/.my.cnf". Si coloca lo siguiente en "~/.my.cnf", no tendrá que especificar su nombre de usuario y contraseña de MySQL en la línea de comandos: 
[client]
user=su_nombre_de_usuario
pass=secreto

Omitir la parte F suele ser lo correcto. Siempre que haya configurado correctamente su "~/.my.cnf", eso dará como resultado que las herramientas se conecten automáticamente sin necesidad de un nombre de usuario o contraseña.

También puede especificar un juego de caracteres predeterminado en el archivo de valores predeterminados. A diferencia de la parte "A" descrita anteriormente, esto instruirá a la biblioteca cliente (DBD::mysql) a cambiar el juego de caracteres que utiliza internamente, lo cual no se puede lograr de ninguna otra manera.

h
Nombre de host o dirección IP de MySQL a la que conectarse.
L
Habilita explícitamente LOAD DATA LOCAL INFILE.

Por alguna razón, algunos proveedores compilan libmysql sin la opción --enable-local-infile, lo que deshabilita la declaración. Esto puede llevar a situaciones extrañas, como que el servidor permita LOCAL INFILE, pero el cliente arroje excepciones si se utiliza.

Sin embargo, siempre que el servidor permita LOAD DATA, los clientes pueden volver a habilitarlo fácilmente; consulte https://dev.mysql.com/doc/refman/en/load-data-local-security.html y http://search.cpan.org/~capttofu/DBD-mysql/lib/DBD/mysql.pm. Esta opción hace exactamente eso.

p
Contraseña de MySQL a utilizar al conectarse.
P
Número de puerto a utilizar para la conexión. Tenga en cuenta que se aplican los comportamientos especiales habituales: si especifica "localhost" como su nombre de host en sistemas Unix, la conexión utiliza en realidad un archivo de socket, no una conexión TCP/IP, y por lo tanto ignora el puerto.
S
Archivo de socket de MySQL a utilizar para la conexión (en sistemas Unix).
u
Nombre de usuario de MySQL a utilizar al conectarse, si no es el usuario del sistema actual.
s
Crear conexión SSL

PALABRA_CLAVE_SIMPLE

Muchas de las herramientas le permitirán especificar un DSN como una sola palabra, sin ninguna sintaxis de "clave=valor". Esto se llama una 'palabra clave simple'. Cómo se maneja esto depende de la herramienta, pero generalmente se interpreta como la parte "h".

percona-toolkit(1p) — Arch Linux

SPECIAL OPTION TYPES

The tool's "--help" output will tell you the behavior for that tool.

PROPAGATION

Many tools will let you propagate values from one DSN to the next, so you don't have to specify all the parts for each DSN. For example, if you want to specify a username and password for each DSN, you can connect to three hosts as follows:

h=host1,u=fred,p=wilma host2 host3

This is tool-specific.

ENVIRONMENT

The environment variable "PTDEBUG" enables verbose debugging output to STDERR. To enable debugging and capture all output to a file, run the tool like:

PTDEBUG=1 pt-table-checksum ... > FILE 2>&1

Be careful: debugging output is voluminous and can generate several megabytes of output.

REQUISITOS DEL SISTEMA

La mayoría de las herramientas requieren:

  • Perl v5.8 o más reciente
  • Bash v3 o más reciente
  • Módulos principales de Perl como Time::HiRes

Las herramientas que se conectan a MySQL requieren:

  • Módulos de Perl DBI y DBD::mysql
  • MySQL 5.0 o más reciente

Percona Toolkit soporta oficialmente y se prueba en muchas distribuciones populares de Linux y MySQL 5.0 a 5.6; ver http://goo.gl/srHm7 para la lista de plataformas y versiones soportadas.

soporte IPv6

Para soportar direcciones IPv6 para conectarse a MySQL, se requiere el controlador Perl DBD::MySQL v4.033_01. Además, como se indica en la RFC 3986 https://www.ietf.org/rfc/rfc3986.txt sección 3.2.2 se deben usar corchetes para distinguir el host y el puerto. Ejemplos: https://metacpan.org/pod/DBD::mysql#port

ERRORES

Por favor, reporta los errores en https://jira.percona.com. Incluye la siguiente información en tu reporte de error:

  • Línea de comandos completa utilizada para ejecutar la herramienta
  • Herramienta "--version"
  • Versión de MySQL, MongoDB o PostgreSQL de todos los servidores involucrados
  • Salida de la herramienta incluyendo STDERR
  • Archivos de entrada (archivos de log/dump/configuración, etc.)

Si es posible, incluye la salida de depuración ejecutando la herramienta con "PTDEBUG"; ver "ENVIRONMENT".
