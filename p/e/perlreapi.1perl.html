NOMBRE

perlreapi - Interfaz de plugin para expresiones regulares de Perl

DESCRIPCIÓN

A partir de Perl 5.9.5 existe una nueva interfaz para enchufar y utilizar motores de expresiones regulares distintos del predeterminado.

Se espera que cada motor proporcione acceso a una estructura constante del siguiente formato:

typedef struct regexp_engine {
    REGEXP* (*comp) (pTHX_
                     const SV * const pattern, const U32 flags);
    I32     (*exec) (pTHX_
                     REGEXP * const rx,
                     char* stringarg,
                     char* strend, char* strbeg,
                     SSize_t minend, SV* sv,
                     void* data, U32 flags);
    char*   (*intuit) (pTHX_
                       REGEXP * const rx, SV *sv,
                       const char * const strbeg,
                       char *strpos, char *strend, U32 flags,
                       struct re_scream_pos_data_s *data);
    SV*     (*checkstr) (pTHX_ REGEXP * const rx);
    void    (*free) (pTHX_ REGEXP * const rx);
    void    (*numbered_buff_FETCH) (pTHX_
                                    REGEXP * const rx,
                                    const I32 paren,
                                    SV * const sv);
    void    (*numbered_buff_STORE) (pTHX_
                                    REGEXP * const rx,
                                    const I32 paren,
                                    SV const * const value);
    I32     (*numbered_buff_LENGTH) (pTHX_
                                     REGEXP * const rx,
                                     const SV * const sv,
                                     const I32 paren);
    SV*     (*named_buff) (pTHX_
                           REGEXP * const rx,
                           SV * const key,
                           SV * const value,
                           U32 flags);
    SV*     (*named_buff_iter) (pTHX_
                                REGEXP * const rx,
                                const SV * const lastkey,
                                const U32 flags);
    SV*     (*qr_package)(pTHX_ REGEXP * const rx);
#ifdef USE_ITHREADS
    void*   (*dupe) (pTHX_ REGEXP * const rx, CLONE_PARAMS *param);
#endif
    REGEXP* (*op_comp) (...);}

Cuando se compila una expresión regular, su campo "engine" se establece para apuntar a la estructura apropiada, de modo que cuando necesite ser utilizada, Perl pueda encontrar las rutinas correctas para hacerlo.

Para instalar un nuevo manejador de expresiones regulares, $^H{regcomp} se establece en un entero que (cuando se castea apropiadamente) se resuelve en una de estas estructuras. Al compilar, se ejecuta el método "comp", y se espera que el campo "engine" de la estructura "regexp" resultante apunte de nuevo a la misma estructura.

El símbolo pTHX_ en la definición es una macro utilizada por Perl bajo hilos para proporcionar un argumento adicional a la rutina que contiene un puntero de vuelta al intérprete que está ejecutando la expresión regular. Por lo tanto, bajo hilos, todas las rutinas reciben un argumento adicional.

Callbacks

comp

REGEXP* comp(pTHX_ const SV * const pattern, const U32 flags);

Compila el patrón almacenado en "pattern" usando las "flags" dadas y devuelve un puntero a una estructura "REGEXP" preparada que puede realizar la coincidencia. Consulte "La estructura REGEXP" a continuación para obtener una explicación de los campos individuales de la estructura REGEXP.

El parámetro "pattern" es el escalar que se utilizó como patrón. Las versiones anteriores de Perl pasaban dos "char*" indicando el inicio y el final del patrón convertido a cadena; el siguiente fragmento se puede usar para obtener los parámetros antiguos:

STRLEN plen;
char*  exp = SvPV(pattern, plen);
char* xend = exp + plen;

Dado que cualquier escalar se puede pasar como patrón, es posible implementar un motor que haga algo con una matriz (""ook" =~ [ qw/ eek hlagh / ]") o con la forma no convertida a cadena de una expresión regular compilada (""ook" =~ qr/eek/"). El propio motor de Perl siempre convertirá todo a cadena utilizando el fragmento anterior, pero eso no significa que otros motores tengan que hacerlo.

El parámetro "flags" es un campo de bits que indica cuáles de las banderas "msixpn" se utilizaron para compilar la expresión regular. También contiene información adicional, como si "use locale" está activo.

Las banderas "eogc" se eliminan antes de pasarse a la rutina de compilación. El motor de expresiones regulares no necesita saber si alguna de estas está configurada, ya que esas banderas solo deberían afectar lo que Perl hace con el patrón y sus variables de coincidencia, no cómo se compila y ejecuta.

Para cuando se llama al callback de compilación, algunas de estas banderas ya han tenido efecto (indicado a continuación donde sea aplicable). Sin embargo, la mayor parte de su efecto ocurre después de que se ejecuta el callback de compilación, en rutinas que leen el campo "rx->extflags" que este popula.

En general, las banderas deben conservarse en "rx->extflags" después de la compilación, aunque el motor de expresiones regulares podría querer añadir o eliminar algunas de ellas para invocar o deshabilitar algún comportamiento especial en Perl. Las banderas junto con cualquier comportamiento especial que provoquen se documentan a continuación:

Conjunto de caracteres
Las reglas del conjunto de caracteres se determinan mediante un enumerado que se contiene en este campo. Esto todavía es experimental y está sujeto a cambios, pero la interfaz actual devuelve las reglas mediante la función en línea "get_regex_charset(const U32 flags)". El único valor documentado actualmente devuelto por ella es REGEX_LOCALE_CHARSET, que se establece si "use locale" está en efecto. Si está presente en "rx->extflags", "split" usará la definición de espacio en blanco dependiente de la configuración regional cuando RXf_SKIPWHITE o RXf_WHITE estén en efecto. Los espacios en blanco ASCII se definen según isSPACE, y por las macros internas "is_utf8_space" bajo UTF-8, y "isSPACE_LC" bajo "use locale".

Callbacks de captura nombradas

Se llama para obtener/establecer el valor de "%+" y "%-", así como por algunas funciones utilitarias en re.

Hay dos callbacks, "named_buff" se llama en todos los casos en que los callbacks de FETCH, STORE, DELETE, CLEAR, EXISTS y SCALAR de Tie::Hash ocurrirían ante cambios en "%+" y "%-" y "named_buff_iter" en los mismos casos que FIRSTKEY y NEXTKEY.

El parámetro "flags" se puede usar para determinar a cuáles de estas operaciones deben responder los callbacks. Las siguientes flags están definidas actualmente:

Qué operación de Tie::Hash se está realizando desde el nivel de Perl en "%+" o "%-", si la hay:

RXapif_FETCH
RXapif_STORE
RXapif_DELETE
RXapif_CLEAR
RXapif_EXISTS
RXapif_SCALAR
RXapif_FIRSTKEY
RXapif_NEXTKEY

Si "%+" o "%-" está siendo operado, si lo está.

RXapif_ONE /* %+ */
RXapif_ALL /* %- */

Si se está llamando como "re::regname", "re::regnames" o "re::regnames_count", si lo está. Los dos primeros se combinarán con "RXapif_ONE" o "RXapif_ALL".

RXapif_REGNAME
RXapif_REGNAMES
RXapif_REGNAMES_COUNT

Internamente "%+" y "%-" se implementan con una interfaz atada real a través de Tie::Hash::NamedCapture. Los métodos en ese paquete llamarán a estas funciones. Sin embargo, el uso de Tie::Hash::NamedCapture para este propósito podría cambiar en futuras versiones. Por ejemplo, esto podría implementarse mediante magia en su lugar (necesitaría una extensión para mgvtbl).

qr_package

SV* qr_package(pTHX_ REGEXP * const rx);

El paquete al que está bendito el objeto mágico qr// (como se ve en "ref qr//"). Se recomienda que los motores cambien esto a su nombre de paquete para identificación, independientemente de si implementan métodos en el objeto.

El paquete que devuelve este método también debe tener el paquete interno "Regexp" en su @ISA. "qr//->isa("Regexp")" siempre debe ser verdadero, independientemente del motor que se esté utilizando.

Una posible implementación:

SV*
Example_qr_package(pTHX_ REGEXP * const rx)
{
    PERL_UNUSED_ARG(rx);
    return newSVpvs("re::engine::Example");
}

Cualquier llamada a método en un objeto creado con "qr//" se enviará al paquete como un objeto normal.

use re::engine::Example;
my $re = qr//;
$re->meth; # enviado a re::engine::Example::meth()

Para recuperar el objeto "REGEXP" del escalar en una función XS, use la macro "SvRX", vea "REGEXP Functions" en perlapi.

void meth(SV * rv)
PPCODE:
    REGEXP * re = SvRX(sv);

dupe

void* dupe(pTHX_ REGEXP * const rx, CLONE_PARAMS *param);

En compilaciones con hilos, una expresión regular puede necesitar ser duplicada para que el patrón pueda ser utilizado por múltiples hilos. Se espera que esta rutina maneje la duplicación de cualquier dato privado al que apunte el miembro "pprivate" de la estructura "regexp". Se llamará con la estructura nueva "regexp" preconstruida como argumento, el miembro "pprivate" apuntará a la estructura privada **antigua**, y esta rutina será responsable de construir una copia y devolver un puntero a ella (que Perl utilizará para sobrescribir el campo tal como se pasó a esta rutina).

Esto permite al motor duplicar sus datos privados pero también, si es necesario, modificar la estructura final si realmente debe hacerlo.

En compilaciones sin hilos, este campo no existe.

op_comp

Esto es privado del núcleo de Perl y está sujeto a cambios. Debe dejarse nulo.

La estructura REGEXP

La estructura REGEXP está definida en regexp.h. Todos los motores de expresiones regulares deben ser capaces de construir correctamente dicha estructura en su rutina "comp".

La estructura REGEXP contiene todos los datos que Perl necesita conocer para trabajar correctamente con la expresión regular. Incluye datos sobre optimizaciones que Perl puede usar para determinar si el motor de expresiones regulares realmente debe usarse, y otra información de control variada que se necesita para ejecutar correctamente los patrones en varios contextos, como si el patrón estaba anclado de alguna manera, o qué flags se utilizaron durante la compilación, o si el programa contiene construcciones especiales que Perl necesita conocer.

Además, contiene dos campos destinados al uso privado del motor de expresiones regulares que compiló el patrón. Estos son los miembros "intflags" y "pprivate". "pprivate" es un puntero void a una estructura arbitraria, cuyo uso y gestión es responsabilidad del motor compilador. Perl nunca modificará ninguno de estos valores.

/* copiado de: regexp.h */
typedef struct regexp {
    /*----------------------------------------------------------------------
     * Campos requeridos para compatibilidad con tipos SV
     */
    _XPV_HEAD;
    /*----------------------------------------------------------------------
     * Campos operacionales
     */
    const struct regexp_engine* engine; /* ¿qué motor creó esta regexp? */
    REGEXP *mother_re; /* ¿qué re es esta copia ligera de? */
    HV *paren_names;   /* Hash opcional de nombres de paréntesis */
    /*----------------------------------------------------------------------
     * Información sobre la coincidencia que el núcleo de perl usa para gestionar cosas
     */
    /* ver comentario en regcomp_internal.h sobre la bifurcación de reinicio para entender
       la distinción entre búferes de captura físicos y lógicos */
    U32 nparens;                    /* número físico de búferes de captura */
    U32 logical_nparens;            /* número lógico de búferes de captura */
    I32 *logical_to_parno;          /* mapeo del número lógico de paréntesis al primero físico */
    I32 *parno_to_logical;          /* mapeo de cada número físico de paréntesis al lógico */
    I32 *parno_to_logical_next;     /* mapeo de cada número físico de paréntesis al siguiente
                                       físico con el mismo id lógico */
    SSize_t maxlen;    /* número máximo posible de caracteres en la cadena para coincidir */
    SSize_t minlen;    /* número mínimo posible de caracteres en la cadena para coincidir */
    SSize_t minlenret; /* número mínimo posible de caracteres en $& */
    STRLEN gofs;       /* caracteres a la izquierda de la posición desde la que buscamos */
                       /* datos de subcadena sobre cadenas que deben aparecer en
                        * la coincidencia final, se usa para optimizaciones */
    struct reg_substr_data *substrs;
    /* datos privados específicos del motor */
    void *pprivate;    /* Datos privados del motor de expresiones regulares que
                        * creó este objeto. */
    U32 extflags;      /* Flags usados tanto externa como internamente */
    U32 intflags;      /* Flags internos específicos del motor */
    /*----------------------------------------------------------------------
     * Datos sobre la última/actual coincidencia. Estos se modifican durante la coincidencia
     */
    U32 lastparen;           /* último paréntesis de cierre coincidente ($+) */
    U32 lastcloseparen;      /* último paréntesis de cierre coincidente ($^N) */
    regexp_paren_pair *offs; /* Array de offsets para (@-) y (@+) */
    char **recurse_locinput; /* usado para detectar recursión infinita, XXX: mover a interno */
    /*---------------------------------------------------------------------- */
    /* offset desde el envoltorio hasta el inicio de precomp */
    PERL_BITFIELD32 pre_prefix:4;

    PERL_BITFIELD32 compflags:9;

NAME

perlreapi - Perl regular expression internal API

DESCRIPTION

This document describes the internal API for Perl's regular expression engine.

The API is still subject to change and is not intended for use outside of the Perl core distribution.

Callbacks

When a regular expression is compiled, Perl associates a number of callback pointers with the compiled regular expression structure. These callbacks are invoked by Perl's internal code when it needs to perform certain operations on the compiled regular expression.

The following callbacks are defined:

  • comp: This callback is invoked when a regular expression is compiled. It is responsible for compiling the pattern into an internal representation that can be executed by the engine. The compiled structure is then returned.
  • free: This callback is invoked when the compiled regular expression structure is no longer needed. It is responsible for freeing any memory that was allocated by the comp callback.
  • eval: This callback is invoked when the regular expression needs to be executed against a string. It is responsible for performing the match and returning the result.
  • free_suboffset: This callback is invoked when the "suboffset" field of the "REGEXP" structure is being freed. This is only relevant when a sub-string match is performed.

The REGEXP structure

The "REGEXP" structure is used to hold information about a compiled regular expression. It is defined in "regcomp.h" and contains the following fields:

  • magic: A magic number used to identify the structure.
  • engine: A pointer to the "regexp_engine" structure for this regular expression.
  • program: A pointer to the compiled program for this regular expression.
  • flags: Flags associated with this regular expression. These can include options such as case-insensitivity, multiline matching, etc.
  • start_offset: The offset within the source string where the match started.
  • last_match: A pointer to the last match found.
  • name_map: A map of capture group names to their corresponding group numbers.
  • suboffset: The number of bytes from the logical start of the buffer to the physical start. This is used when a sub-string match is performed.
  • subbeg: The offset within the source string where the sub-string match begins.
  • subcoffset: The number of characters in the offset. This is needed to support "@-" and "@+" which work in characters, not bytes.

The engine may choose not to copy the full buffer (although it must still do so in the presence of "RXf_PMf_KEEPCOPY" or the relevant bits being set in "PL_sawampersand"). In this case, it may set "suboffset" to indicate the number of bytes from the logical start of the buffer to the physical start (i.e. "subbeg"). It should also set "subcoffset", the number of characters in the offset. The latter is needed to support "@-" and "@+" which work in characters, not bytes.

"RX_WRAPPED" "RX_WRAPLEN"

Macros which access the string the "qr//" stringifies to. The Perl engine for example stores "(?^:eek)" in the case of "qr/eek/".

When using a custom engine that doesn't support the "(?:)" construct for inline modifiers, it's probably best to have "qr//" stringify to the supplied pattern, note that this will create undesired patterns in cases such as:

my $x = qr/a|b/;  # "a|b"
my $y = qr/c/i;   # "c"
my $z = qr/$x$y/; # "a|bc"

There's no solution for this problem other than making the custom engine understand a construct like "(?:)".

RX_REFCNT()

The number of times the structure is referenced. When this falls to 0, the regexp is automatically freed by a call to "pregfree". This should be set to 1 in each engine's "comp" routine. Note that in older perls this was a member in the struct called "refcnt" but in more modern perls where the regexp structure was unified with the SV structure this is an alias to SvREFCNT().
