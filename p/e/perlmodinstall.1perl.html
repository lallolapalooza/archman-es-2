NOMBRE

perlmodinstall - Instalación de módulos CPAN

DESCRIPCIÓN

Puedes pensar en un módulo como la unidad fundamental de código Perl reutilizable; consulta perlmod para obtener más detalles. Cada vez que alguien crea un fragmento de código Perl que cree que será útil para el mundo, se registra como desarrollador de Perl en https://www.cpan.org/modules/04pause.html para poder subir su código al CPAN. CPAN es la Comprehensive Perl Archive Network y se puede acceder en https://www.cpan.org/ , y buscar en https://metacpan.org/ .

Esta documentación es para personas que desean descargar módulos CPAN e instalarlos en su propia computadora.

PREÁMBULO

Primero, ¿estás seguro de que el módulo no está ya en tu sistema? Intenta "perl -MFoo -e 1". (Reemplaza "Foo" con el nombre del módulo; por ejemplo, "perl -MCGI::Carp -e 1").

Si no ves un mensaje de error, tienes el módulo. (Si ves un mensaje de error, aún es posible que tengas el módulo, pero que no esté en tu ruta, la cual puedes mostrar con perl -e "print qq(@INC)".) Para el resto de este documento, asumiremos que realmente, honestamente, te falta un módulo instalado, pero lo has encontrado en el CPAN.

Así que ahora tienes un archivo que termina en .tar.gz (o, con menos frecuencia, .zip). Sabes que hay un módulo sabroso dentro. Hay cuatro pasos que debes seguir ahora:

DESCOMPRIMIR el archivo
DESEMPAQUETAR el archivo en un directorio
CONSTRUIR el módulo (a veces innecesario)
INSTALAR el módulo.

Aquí se explica cómo realizar cada paso para cada sistema operativo. Esto no reemplaza la lectura de los archivos README e INSTALL que podrían haber venido con tu módulo.

También ten en cuenta que estas instrucciones están adaptadas para instalar el módulo en el repositorio de módulos de Perl de tu sistema, pero puedes instalar módulos en cualquier directorio que desees. Por ejemplo, donde digo "perl Makefile.PL", puedes sustituir "perl Makefile.PL PREFIX=/mi/directorio/perl" para instalar los módulos en /mi/directorio/perl. Luego puedes usar los módulos desde tus programas Perl con "use lib "/mi/directorio/perl/lib/site_perl";" o a veces simplemente "use "/mi/directorio/perl";". Si estás en un sistema que requiere acceso de superusuario/root para instalar módulos en los directorios que ves cuando escribes "perl -e "print qq(@INC)"", querrás instalarlos en un directorio local (como tu directorio de inicio) y usar este enfoque.

  • Si estás en un sistema Unix o similar a Unix,

    Puedes usar el módulo CPAN de Andreas Koenig ( https://metacpan.org/release/CPAN ) para automatizar los siguientes pasos, desde DESCOMPRIMIR hasta INSTALAR.

    A. DESCOMPRIMIR

    Descomprime el archivo con "gzip -d yourmodule.tar.gz"

    Puedes obtener gzip desde <ftp://prep.ai.mit.edu/pub/gnu/>

    O, puedes combinar este paso con el siguiente para ahorrar espacio en disco:

    gzip -dc yourmodule.tar.gz | tar -xof -

    B. DESEMPAQUETAR

    Desempaqueta el resultado con "tar -xof yourmodule.tar"

    C. CONSTRUIR

    Entra en el directorio recién creado y escribe:

    perl Makefile.PL
make test

    o

    perl Makefile.PL PREFIX=/mi/directorio/perl

    para instalarlo localmente. (Recuerda que si haces esto, tendrás que poner "use lib "/mi/directorio/perl";" cerca del principio del programa que va a usar este módulo.

    D. INSTALAR

    Mientras sigues en ese directorio, escribe:

    make install

    Asegúrate de tener los permisos adecuados para instalar el módulo en tu directorio de módulos de Perl 5. A menudo, necesitarás ser root.

    Eso es todo lo que necesitas hacer en sistemas Unix con enlace dinámico. La mayoría de los sistemas Unix tienen enlace dinámico. Si el tuyo no lo tiene, o si por alguna otra razón tienes un perl enlazado estáticamente, y el módulo requiere compilación, necesitarás construir un nuevo binario de Perl que incluya el módulo. De nuevo, probablemente necesitarás ser root.

  • Si estás usando ActivePerl (Win95/98/2K/NT/XP, Linux, Solaris),

    Primero, escribe "ppm" desde una shell y mira si el repositorio PPM de ActiveState tiene tu módulo. Si es así, puedes instalarlo con "ppm" y no tendrás que preocuparte por ninguno de los otros pasos aquí. Es posible que también puedas usar las instrucciones de CPAN de la sección "Unix o Linux" de arriba; inténtalo. De lo contrario, tendrás que seguir los pasos a continuación.

    A. DESCOMPRIMIR

    Puedes usar el 7-zip de código abierto ( https://www.7-zip.org/ ) o el shareware Winzip ( https://www.winzip.com ) para descomprimir y desempaquetar módulos.

    B. DESEMPAQUETAR

    Si usaste WinZip, esto ya se hizo por ti.

    C. CONSTRUIR

    Necesitarás "nmake" o "gmake".

    ¿Requiere el módulo compilación (es decir, tiene archivos que terminan en .xs, .c, .h, .y, .cc, .cxx o .C)? Si es así, la vida es oficialmente dura para ti, porque tienes que compilar el módulo tú mismo (no es fácil en Windows). Necesitarás un compilador como Visual C++. Alternativamente, puedes descargar un paquete PPM precompilado de ActiveState. http://aspn.activestate.com/ASPN/Downloads/ActivePerl/PPM/

    Entra en el directorio recién creado y escribe:

       perl Makefile.PL
   nmake test
D. INSTALAR

    Mientras sigues en ese directorio, escribe:

    nmake install
  • Si estás en OS/2,

    Obtén el conjunto de desarrollo EMX y gzip/tar de Hobbes ( http://hobbes.nmsu.edu/h-browse.php?dir=/pub/os2/dev/emx/v0.9d ), y luego sigue las instrucciones para Unix.

  • Si estás en VMS,

    Al descargar desde CPAN, guarda tu archivo con una extensión ".tgz" en lugar de ".tar.gz". Todos los demás puntos en el nombre del archivo deben ser reemplazados por guiones bajos. Por ejemplo, "Your-Module-1.33.tar.gz" debería ser descargado como "Your-Module-1_33.tgz".

    A. DESCOMPRIMIR

    Escribe

    gzip -d Your-Module.tgz

    o, para módulos comprimidos, escribe

    unzip Your-Module.zip

    Ejecutables para gzip, zip y VMStar:

    http://www.hp.com/go/openvms/freeware/

    y su código fuente:

    http://www.fsf.org/order/ftp.html

    Ten en cuenta que gzip/gunzip de GNU no es lo mismo que el paquete zip/unzip de Info-ZIP. El primero es una herramienta de compresión simple; el segundo permite la creación de archivos de múltiples archivos.

    B. DESEMPAQUETAR

    Si estás usando VMStar:

    VMStar xf Your-Module.tar

    O, si te gusta la sintaxis de comandos de VMS:

    tar/extract/verbose Your_Module.tar

    C. CONSTRUIR

    Asegúrate de tener MMS (de Digital) o el MMK de software libre ( disponible en MadGoat en http://www.madgoat.com ). Luego escribe esto para crear el DESCRIP.MMS para el módulo:

    perl Makefile.PL

    Ahora estás listo para construir:

NAME

perlmodinstall - how to install modules from CPAN

DESCRIPTION

This document describes how to install modules from CPAN. For many modules, this is as simple as typing

mms install

Substitute "mmk" for "mms" above if you're using MMK.

D. INSTALL

Type

mms install

Substitute "mmk" for "mms" above if you're using MMK.

  • If you're on MVS,

    Introduce the .tar.gz file into an HFS as binary; don't translate from ASCII to EBCDIC.

    A. DECOMPRESS

    Decompress the file with "gzip -d yourmodule.tar.gz"

    You can get gzip from http://www.s390.ibm.com/products/oe/bpxqp1.html

    B. UNPACK

    Unpack the result with

    pax -o to=IBM-1047,from=ISO8859-1 -r < yourmodule.tar

    The BUILD and INSTALL steps are identical to those for Unix. Some modules generate Makefiles that work better with GNU make, which is available from http://www.mks.com/s390/gnu/

    • PORTABILITY

    Note that not all modules will work with on all platforms. See perlport for more information on portability issues. Read the documentation to see if the module will work on your system. There are basically three categories of modules that will not work "out of the box" with all platforms (with some possibility of overlap):

    • Those that should, but don't. These need to be fixed; consider contacting the author and possibly writing a patch.
    • Those that need to be compiled, where the target platform doesn't have compilers readily available. (These modules contain .xs or .c files, usually.) You might be able to find existing binaries on the CPAN or elsewhere, or you might want to try getting compilers and building it yourself, and then release the binary for other poor souls to use.
    • Those that are targeted at a specific platform. (Such as the Win32:: modules.) If the module is targeted specifically at a platform other than yours, you're out of luck, most likely.

    Check the CPAN Testers if a module should work with your platform but it doesn't behave as you'd expect, or you aren't sure whether or not a module will work under your platform. If the module you want isn't listed there, you can test it yourself and let CPAN Testers know, you can join CPAN Testers, or you can request it be tested.

    https://cpantesters.org/
