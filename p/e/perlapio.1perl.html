DESCRIPCIÓN

El código fuente de Perl, y las extensiones que desean máxima portabilidad, deberían usar las funciones anteriores en lugar de las definidas en stdio.h del ANSI C. Los encabezados de Perl (en particular "perlio.h") las definirán con el mecanismo de I/O seleccionado en tiempo de Configuración.

Las funciones están modeladas según las de stdio.h, pero el orden de los parámetros se ha "ordenado un poco".

"PerlIO *" toma el lugar de FILE *. Al igual que FILE *, debe tratarse como opaco (probablemente sea seguro asumir que es un puntero a algo).

Actualmente hay dos implementaciones:

1. USE_STDIO
Todas las anteriores son #define a funciones stdio o son funciones envoltorio triviales que llaman a stdio. En este caso, *solo* PerlIO * es un FILE *. Esta ha sido la implementación predeterminada desde que se introdujo la abstracción en perl5.003_02.
2. USE_PERLIO
Introducida poco después de perl5.7.0, esta es una reimplementación de la abstracción anterior que permite a Perl tener más control sobre cómo se realiza la E/S, ya que desacopla la E/S de la forma en que el sistema operativo y la biblioteca C eligen hacer las cosas. Para USE_PERLIO, PerlIO * tiene una capa adicional de indirección: es un puntero a un puntero. Esto permite que PerlIO * permanezca con un valor conocido mientras intercambia la implementación subyacente en tiempo de ejecución. En este caso, todas las funciones anteriores son funciones verdaderas (pero muy simples) que llaman a la implementación subyacente.

Esta es la única implementación para la que PerlIO_apply_layers() hace algo "interesante".

La implementación USE_PERLIO se describe en perliol.

Debido a que "perlio.h" es una capa delgada (para eficiencia), la semántica de estas funciones depende algo de la implementación subyacente. Donde estas variaciones se entienden, se señalan a continuación.

A menos que se indique lo contrario, las funciones devuelven 0 en caso de éxito, o un valor negativo (generalmente "EOF" que suele ser -1) y establecen "errno" en caso de error.

PerlIO_stdin(), PerlIO_stdout(), PerlIO_stderr()
Úselos en lugar de "stdin", "stdout", "stderr". Están escritos para parecer "llamadas a funciones" en lugar de variables porque esto facilita hacerlos llamadas a funciones si la plataforma no puede exportar datos a módulos cargados, o si (por ejemplo) diferentes "hilos" pueden tener valores diferentes.
PerlIO_open(ruta, modo), PerlIO_fdopen(fd,modo)
Estos corresponden a fopen() / fdopen() y los argumentos son los mismos. Devuelven "NULL" y establecen "errno" si hay un error. Puede haber un límite de implementación en el número de manejadores abiertos, que puede ser menor que el límite en el número de archivos abiertos; "errno" puede no establecerse cuando se devuelve "NULL" si se supera este límite.
PerlIO_reopen(ruta,modo,f)
Aunque actualmente existe en ambas implementaciones, el propio Perl no lo usa. *Como Perl no lo usa, no está bien probado.*

Perl prefiere hacer "dup" del nuevo descriptor de bajo nivel al descriptor utilizado por el PerlIO existente. Este puede convertirse en el comportamiento de esta función en el futuro.

PerlIO_printf(f,fmt,...), PerlIO_vprintf(f,fmt,a)
Estos son equivalentes a fprintf() / vfprintf().
PerlIO_stdoutf(fmt,...)
Este es el equivalente a printf(). printf se define como esta función, por lo que es (actualmente) legal usar "printf(fmt,...)" en fuentes de perl.
PerlIO_read(f,buf,cuenta), PerlIO_write(f,buf,cuenta)
Estos corresponden funcionalmente a fread() y fwrite(), pero los argumentos y los valores de retorno son diferentes. Las firmas de PerlIO_read() y PerlIO_write() se han modelado sobre las funciones de bajo nivel más lógicas read() y write()**: el argumento "archivo" se pasa primero, solo hay un "recuento", y el valor de retorno puede distinguir entre error y "EOF".

Devuelve un recuento de bytes si tiene éxito (que puede ser cero o positivo), devuelve un valor negativo y establece "errno" en caso de error. Dependiendo de la implementación, "errno" puede ser "EINTR" si la operación fue interrumpida por una señal.

PerlIO_fill(f)
Rellena el búfer asociado con "f" con datos de la capa inferior. "PerlIO_read" llama a esto como parte de su operación normal. Devuelve 0 en caso de éxito; -1 en caso de fallo.
PerlIO_close(f)
Dependiendo de la implementación, "errno" puede ser "EINTR" si la operación fue interrumpida por una señal.
PerlIO_puts(f,s), PerlIO_putc(f,c)
Estos corresponden a fputs() y fputc(). Tenga en cuenta que los argumentos se han revisado para tener el "archivo" primero.
PerlIO_ungetc(f,c)
Esto corresponde a ungetc(). Tenga en cuenta que los argumentos se han revisado para tener el "archivo" f

PerlIO Functions

PerlIO_pushed(f)
Returns true if the named stream has layers pushed onto it. Used to optimize certain operations on streams that are known not to have layers (e.g. calls to PerlIO_stdout()).
PerlIO_popped(f)
Returns true if the named stream has layers popped off it. Used to optimize certain operations on streams that are known not to have layers.
PerlIO_stdin(), PerlIO_stdout(), PerlIO_stderr()
Returns the PerlIO * for the standard input, standard output, and standard error streams, respectively. This is normally implemented via the :stdio layer, so that they can be used seamlessly with the standard C library functions.
PerlIO_get_layers(f)
Returns a string describing the layers currently on the stack for the specified stream. The format is Perl's usual comma-separated list of layer names, optionally prefixed by ":". For example, ":stdio,:encoding(UTF-8)".
PerlIO_push(f,layer)
Pushes a new layer onto the stack for the specified stream. The layer must be registered with the PerlIO system. Returns the new stream, or "NULL" on error.
PerlIO_pop(f,layer)
Pops a layer off the stack for the specified stream. If layer is "NULL", the top-most layer is popped. Returns the stream associated with the layer below the popped one, or "NULL" on error. If the layer being popped is the bottom-most layer, then it is replaced by the ":stdio" layer.
PerlIO_close(f)
Closes the stream. This corresponds to fclose(). It flushes any buffered output, frees any resources associated with the stream, and disassociates the stream from Perl. Returns 0 on success, or "EOF" (-1) on error.
PerlIO_open(name,mode)
Opens the specified file for the given mode, returning a PerlIO * handle. This corresponds to fopen(). The mode is a string as described in the Perl manual page for open(). Returns the PerlIO * handle on success, or "NULL" on error.
PerlIO_read(f,buf,count)
Reads up to "count" bytes from the stream into the buffer "buf". Returns the number of bytes read, 0 on end-of-file, or -1 ("EOF") on error.
PerlIO_write(f,buf,count)
Writes "count" bytes from the buffer "buf" to the stream. Returns the number of bytes written, or -1 ("EOF") on error. Note that this function does not guarantee that all bytes will be written; it is up to the caller to handle partial writes.
PerlIO_gets(f,buf,count)
Reads a line from the stream into the buffer "buf", up to "count" bytes. Stops reading at a newline character, EOF, or after "count" bytes have been read. Returns a pointer to the buffer on success, or "NULL" on EOF or error.
PerlIO_ungetc(f,c)
Arranges that next read operation will return the byte c. Despite the implied "character" in the name only values in the range 0..0xFF are defined. Returns the byte c on success or -1 ("EOF") on error. The number of bytes that can be "pushed back" may vary, only 1 character is certain, and then only if it is the last character that was read from the handle.
PerlIO_unread(f,buf,count)
This allows one to unget more than a single byte. It effectively unshifts "count" bytes onto the beginning of the buffer "buf", so that the next read operation(s) will return them before anything else that was in the buffer.

Returns the number of unread bytes.

PerlIO_getc(f)
This corresponds to getc(). Despite the c in the name only byte range 0..0xFF is supported. Returns the character read or -1 ("EOF") on error.
PerlIO_eof(f)
This corresponds to feof(). Returns a true/false indication of whether the handle is at end of file. For terminal devices this may or may not be "sticky" depending on the implementation. The flag is cleared by PerlIO_seek(), or PerlIO_rewind().
PerlIO_error(f)
This corresponds to ferror(). Returns a true/false indication of whether there has been an IO error on the handle.
PerlIO_fileno(f)
This corresponds to fileno(), note that on some platforms, the meaning of "fileno" may not match Unix. Returns -1 if the handle has no open descriptor associated with it.
PerlIO_clearerr(f)
This corresponds to clearerr(), i.e., clears 'error' and (usually) 'eof' flags for the "stream". Does not return a value.
PerlIO_flush(f)
This corresponds to fflush(). Sends any buffered write data to the underlying file. If called with "NULL" this may flush all open streams (or core dump with some USE_STDIO implementations). Calling on a handle open for read only, or on which last operation was a read of some kind may lead to undefined behaviour on some USE_STDIO implementations. The USE_PERLIO (layers) implementation tries to behave better: it flushes all open streams when passed "NULL", and attempts to retain data on read streams either in the buffer or by seeking the handle to the current logical position.
PerlIO_seek(f,offset,whence)
This corresponds to fseek(). Sends buffered write data to the underlying file, or discards any buffered read data, then positions the file descriptor as specified by offset and whence (sic). This is the correct thing to do when switching between read and write on the same handle (see issues with PerlIO_flush() above). Offset is of type "Off_t" which is a perl Configure value which may not be same as stdio's "off_t".
PerlIO_tell(f)
This corresponds to ftell(). Returns the current file position, or (Off_t) -1 on error. May just return value system "knows" without making a system call or checking the underlying file descriptor (so use on shared file descriptors is not safe without a PerlIO_seek()). Return value is of type "Off_t" which is a perl Configure value which may not be same as stdio's "off_t".
PerlIO_getpos(f,p), PerlIO_setpos(f,p)
These correspond (loosely) to fgetpos() and fsetpos(). Rather than stdio's Fpos_t they expect a "Perl Scalar Value" to be passed. What is stored there should be considered opaque. The layout of the data may vary from handle to handle. When not using stdio or if platform does not have the stdio calls then they are implemented in terms of PerlIO_tell() and PerlIO_seek().
PerlIO_rewind(f)
This corresponds to rewind(). It is usually defined as being 
PerlIO_seek(f,(Off_t)0L, SEEK_SET);
PerlIO_clearerr(f);
PerlIO_tmpfile()
This corresponds to tmpfile(), i.e., returns an anonymous PerlIO or NULL on error. The system will attempt to automatically delete the file when closed. On Unix the file is usually "unlink"-ed just after it is created so it does not matter how it gets closed. On other systems the file may only be deleted if closed via PerlIO_close() and/or the program exits via "exit". Depending on the implementation there may be "race conditions" which allow other processes access to the file, though in general it will be safer in this regard than ad. hoc. schemes.
PerlIO_setlinebuf(f)
This corresponds to setlinebuf(). Does not return a value. What constitutes a "line" is implementation dependent but usually means that writing "\n" flushes the buffer. What happens with things like "this\nthat" is uncertain. (Perl core uses it only when "dumping"; it has nothing to do with $| auto-flush.)

Co-existence with stdio

There is outline support for co-existence of PerlIO with stdio. Obviously if PerlIO is implemented in terms of stdio there is no problem. However in other cases then mechanisms must exist to create a FILE * which can be passed to library code which is going to use stdio calls.

The first step is to add this line:

#define PERLIO_NOT_STDIO 0

before including any perl header files. (This will probably become the default at some point). That prevents "perlio.h" from attempting to #define stdio functions onto PerlIO functions.

XS code is probably better using "typemap" if it expects FILE * arguments. The standard typemap will be adjusted to comprehend any changes in this area.

PerlIO_importFILE(f,mode)
Used to get a PerlIO * from a FILE *.

The mode argument should be a string as would be passed to fopen/PerlIO_open. If it is NULL then - for legacy support - the code will (depending upon the platform and the implementation) either attempt to empirically determine the mode in which f is open, or use "r+" to indicate a read/write stream.

Once called the FILE * should ONLY be closed by calling PerlIO_close() on the returned PerlIO *.

The PerlIO is set to textmode. Use PerlIO_binmode if this is not the desired mode.

This is not the reverse of PerlIO_exportFILE().

PerlIO_exportFILE(f,mode)
Given a PerlIO * create a 'native' FILE * suitable for passing to code expecting to be compiled and linked with ANSI C stdio.h. The mode argument should be a string as would be passed to fopen/PerlIO_open. If it is NULL then - for legacy support - the FILE * is opened in same mode as the PerlIO *.

The fact that such a FILE * has been 'exported' is recorded, (normally by pushing a new :stdio "layer" onto the PerlIO *), which may affect future PerlIO operations on the original PerlIO *. You should not call fclose() on the file unless you call PerlIO_releaseFILE() to disassociate it from the PerlIO *. (Do not use PerlIO_importFILE() for doing the disassociation.)

Calling this function repeatedly will create a FILE * on each call (and will push an :stdio layer each time as well).

PerlIO_releaseFILE(p,f)
Calling PerlIO_releaseFILE informs PerlIO that all use of FILE * is complete. It is removed from the list of 'exported' FILE *s, and the associated PerlIO * should revert to its original behaviour.

Use this to disassociate a file from a PerlIO * that was associated using PerlIO_exportFILE().

PerlIO_findFILE(f)
Returns a native FILE * used by a stdio layer. If there is none, it will create one with PerlIO_exportFILE. In either case the FILE * should be considered as belonging to PerlIO subsystem and should only be closed by calling PerlIO_close().

"Fast gets" Functions

In addition to standard-like API defined so far above there is an "implementation" interface which allows perl to get at internals of PerlIO. The following calls correspond to the various FILE_xxx macros determined by Configure - or their equivalent in other implementations. This section is really of interest to only those concerned with detailed perl-core behaviour, implementing a PerlIO mapping or writing code which can make use of the "read ahead" that has been done by the IO system in the same way perl does. Note that any code that uses these interfaces must be prepared to do things the traditional way if a handle does not support them.

NAME

perlapio - Perl I/O Layer interface

SYNOPSIS

    use PerlIO;
    my $stream = PerlIO::open( ... );
    PerlIO::binmode( $stream, ... );

DESCRIPTION

This is an internal Perl API. You should not use it directly.

PerlIO is the new I/O system for Perl. It is extensible and allows you to add new I/O layers easily. The old C-style FILE *'s have been replaced by opaque PerlIO handles.

The PerlIO interface is composed of several groups of functions:

PerlIO_close(f)
Closes the PerlIO handle f.
PerlIO_error(f)
Returns true if the PerlIO handle f is in error state.
PerlIO_fileno(f)
Returns the underlying file descriptor for handle f, or undef if not available.
PerlIO_flush(f)
Flushes the buffer for handle f.
PerlIO_get_layers(f)
Returns a string of layers applied to handle f.
PerlIO_open(name, mode)
Opens a file. name is the filename and mode is the mode string (like in Perl's built-in open). Returns a PerlIO handle or undef on failure. This is the main entry point for opening files.
PerlIO_printf(f,fmt,...)
Equivalent to C's fprintf.
PerlIO_puts(f,str)
Writes the string str to the PerlIO handle f followed by a newline.
PerlIO_read(f,len)
Reads up to len bytes from handle f.
PerlIO_seek(f,offset,whence)
Seeks to a position in the file. whence is one of SEEK_SET, SEEK_CUR, or SEEK_END.
PerlIO_skip(f,count)
Advances the file pointer by count bytes. Returns the actual number of bytes skipped.
PerlIO_tell(f)
Returns the current position in the file.
PerlIO_vprintf(f,fmt,ap)
Equivalent to C's vfprintf.
PerlIO_write(f,str,len)
Writes len bytes from str to the PerlIO handle f.

Buffer Control Functions

These functions allow fine-grained control over the internal buffer used by PerlIO. They are generally not needed by application programmers.

PerlIO_fast_gets(f)
Returns true if the implementation of f supports fast byte-level access to its buffer. This is checked by ensuring that the implementation supports setting the buffer pointer and count (PerlIO_has_cntptr(f) and PerlIO_canset_cnt(f)), and that these functions actually work as advertised.
PerlIO_has_cntptr(f)
The implementation can return a pointer to the current position in the "buffer" and a count of bytes available in the buffer. Do not use this directly - use PerlIO_fast_gets.
PerlIO_get_cnt(f)
Returns the count of readable bytes in the buffer. A zero or negative return means no more bytes are available.
PerlIO_get_ptr(f)
Returns a pointer to the next readable byte in the buffer. Dereferencing the pointer is only safe if PerlIO_get_cnt() has returned a positive value. Only positive offsets up to the value returned by PerlIO_get_cnt() are allowed.
PerlIO_set_ptrcnt(f,p,c)
Sets the pointer into the buffer, and a count of bytes still in the buffer. Should only be used to set the pointer within the range implied by previous calls to PerlIO_get_ptr and PerlIO_get_cnt. The two values *must* be consistent with each other (the implementation may only use one or the other, or may require both).
PerlIO_canset_cnt(f)
The implementation can adjust its idea of the number of bytes in the buffer. Do not use this directly - use PerlIO_fast_gets.
PerlIO_set_cnt(f,c)
Obscure - sets the count of bytes in the buffer. Deprecated. Only usable if PerlIO_canset_cnt() returns true. Currently used only in doio.c to force a count less than -1 to -1. Perhaps should be PerlIO_set_empty or similar. This call may actually do nothing if the "count" is deduced from the pointer and a "limit". Do not use this directly - use PerlIO_set_ptrcnt().
PerlIO_has_base(f)
Returns true if the implementation has a buffer, and can return a pointer to the whole buffer and its size. Used by Perl for the -T / -B tests. Other uses would be very obscure...
PerlIO_get_base(f)
Returns the *start* of the buffer. Access only positive offsets in the buffer up to the value returned by PerlIO_get_bufsiz().
PerlIO_get_bufsiz(f)
Returns the *total number of bytes* in the buffer. This is neither the number that can be read, nor the amount of memory allocated to the buffer. Rather, it is what the operating system and/or implementation happened to read() (or whatever) last time IO was requested.

Other Functions

PerlIO_apply_layers(aTHX_ f,mode,layers)
The new interface to the USE_PERLIO implementation. The layers ":crlf" and ":raw" are the only ones allowed for other implementations and they are silently ignored. (As of perl5.8 ":raw" is deprecated.) Use PerlIO_binmode() below for the portable case.
PerlIO_binmode(aTHX_ f,ptype,imode,layers)
The hook used by Perl's binmode operator. ptype is Perl's character for the kind of IO:
'<' read
'>' write
'+' read/write

imode is "O_BINARY" or "O_TEXT".

layers is a string of layers to apply; only ":crlf" makes sense in the non-USE_PERLIO case. (As of perl5.8 ":raw" is deprecated in favour of passing NULL.)

Portable cases are:

    PerlIO_binmode(aTHX_ f,ptype,O_BINARY,NULL);
and
    PerlIO_binmode(aTHX_ f,ptype,O_TEXT,":crlf");

On Unix these calls probably have no effect whatsoever. Elsewhere they alter "\n" to CR,LF translation and possibly cause a special text "end of file" indicator to be written or honoured on read. The effect of making the call after doing any IO to the handle depends on the implementation. (It may be ignored, affect any data which is already buffered as well, or only apply to subsequent data.)

PerlIO_debug(fmt,...)
PerlIO_debug is a printf()-like function that can be used for debugging. It has no return value. Its main use is inside PerlIO where using real printf, warn() etc. would recursively call PerlIO and be a problem.

PerlIO_debug writes to the file named by $ENV{'PERLIO_DEBUG'} or defaults to stderr if the environment variable is not defined. Typical use might be

Bourne shells (sh, ksh, bash, zsh, ash, ...):
 PERLIO_DEBUG=/tmp/perliodebug.log ./perl -Di somescript some args
Csh/Tcsh:
 setenv PERLIO_DEBUG /tmp/perliodebug.log
 ./perl -Di somescript some args
If you have the "env" utility:
 env PERLIO_DEBUG=/tmp/perliodebug.log ./perl -Di somescript args
Win32:
 set PERLIO_DEBUG=perliodebug.log
 perl -Di somescript some args

On a Perl built without "-DDEBUGGING", or when the "-Di" command-line switch is not specified, or under taint, PerlIO_debug() is a no-op.
