Compilar tu programa C

Si tienes problemas para compilar los scripts de esta documentación, no estás solo. La regla cardinal: COMPILA LOS PROGRAMAS DE LA MISMA MANERA QUE SE COMPILÓ TU PERL. (Perdón por gritar).

Además, cada programa C que utiliza Perl debe enlazar con la biblioteca perl. ¿Qué es eso, preguntas? Perl está escrito en C; la biblioteca perl es la colección de programas C compilados que se usaron para crear tu ejecutable de perl (/usr/bin/perl o equivalente). (Corolario: no puedes usar Perl desde tu programa C a menos que Perl se haya compilado en tu máquina o se haya instalado correctamente; por eso no deberías copiar ciegamente ejecutables de Perl de una máquina a otra sin copiar también el directorio lib).

Cuando usas Perl desde C, tu programa C normalmente asignará, "ejecutará" y liberará un objeto PerlInterpreter, que está definido por la biblioteca perl.

Si tu copia de Perl es lo suficientemente reciente como para contener esta documentación (versión 5.002 o posterior), entonces la biblioteca perl (y EXTERN.h y perl.h, que también necesitarás) residirán en un directorio que se ve así:

/usr/local/lib/perl5/tu_arquitectura_aqui/CORE

o quizás solo

/usr/local/lib/perl5/CORE

o tal vez algo como

/usr/opt/perl5/CORE

Ejecuta esta sentencia para obtener una pista sobre dónde encontrar CORE:

perl -MConfig -e 'print $Config{archlib}'

Aquí tienes cómo compilar el ejemplo de la siguiente sección, "Añadir un intérprete de Perl a tu programa C", en mi máquina Linux:

% gcc -O2 -Dbool=char -DHAS_BOOL -I/usr/local/include
-I/usr/local/lib/perl5/i586-linux/5.003/CORE
-L/usr/local/lib/perl5/i586-linux/5.003/CORE
-o interp interp.c -lperl -lm

(Todo eso es una sola línea). En mi DEC Alpha con la versión antigua 5.003_05, la incantación es un poco diferente:

% cc -O2 -Olimit 2900 -I/usr/local/include
-I/usr/local/lib/perl5/alpha-dec_osf/5.00305/CORE
-L/usr/local/lib/perl5/alpha-dec_osf/5.00305/CORE -L/usr/local/lib
-D__LANGUAGE_C__ -D_NO_PROTO -o interp interp.c -lperl -lm

¿Cómo puedes averiguar qué añadir? Suponiendo que tu Perl es posterior a 5.001, ejecuta un comando "perl -V" y presta especial atención a la información de "cc" y "ccflags".

Tendrás que elegir el compilador apropiado (cc, gcc, etc.) para tu máquina: "perl -MConfig -e 'print $Config{cc}'" te dirá cuál usar.

También tendrás que elegir el directorio de bibliotecas apropiado (/usr/local/lib/...) para tu máquina. Si tu compilador se queja de que ciertas funciones no están definidas, o que no puede localizar -lperl, entonces necesitas cambiar la ruta que sigue a "-L". Si se queja de que no encuentra EXTERN.h y perl.h, necesitas cambiar la ruta que sigue a "-I".

Puede que tengas que añadir bibliotecas adicionales. ¿Cuáles? Quizás las impresas por

perl -MConfig -e 'print $Config{libs}'

Añadir un intérprete de Perl a tu programa C

En cierto sentido, perl (el programa C) es un buen ejemplo de cómo incrustar Perl (el lenguaje), así que demostraré la incrustación con miniperlmain.c, incluido en la distribución fuente. Aquí tienes una versión bastarda y no portátil de miniperlmain.c que contiene lo esencial de la incrustación:

#include <EXTERN.h>               /* de la distribución de Perl     */
#include <perl.h>                 /* de la distribución de Perl     */
static PerlInterpreter *my_perl;  /***    El intérprete de Perl    ***/
int main(int argc, char **argv, char **env)
{
       PERL_SYS_INIT3(&argc,&argv,&env);
       my_perl = perl_alloc();
       perl_construct(my_perl);
       PL_exit_flags |= PERL_EXIT_DESTRUCT_END;
       perl_parse(my_perl, NULL, argc, argv, (char **)NULL);
       perl_run(my_perl);
       perl_destruct(my_perl);
       perl_free(my_perl);
       PERL_SYS_TERM();
       exit(EXIT_SUCCESS);
}

Observa que no usamos el puntero "env". Normalmente pasado a "perl_parse" como su argumento final, "env" aquí es reemplazado por "NULL", lo que significa que se usará el entorno actual.

Las macros PERL_SYS_INIT3() y PERL_SYS_TERM() proporcionan ajustes específicos del sistema para el entorno de ejecución C necesarios para ejecutar intérpretes de Perl; solo deben llamarse una vez, independientemente de cuántos intérpretes crees o destruyas. Llama a PERL_SYS_INIT3() antes de crear tu primer intérprete y a PERL_SYS_TERM() después de liberar tu último intérprete.

Dado que PERL_SYS_INIT3() puede modificar "env", puede ser más apropiado proporcionar "env" como argumento a perl_parse().

También observa que, independientemente de los argumentos que pases a perl_parse(), PERL_SYS_INIT3() debe invocarse con el argc, argv y env de main() de C y solo una vez.

Ten en cuenta que argv[argc] debe ser NULL, igual que los pasados a una función main en C.

Ahora compila este programa (lo llamaré interp.c) en un ejecutable:

% cc -o interp interp.c `perl -MExtUtils::Embed -e ccopts -e ldopts`

Después de una compilación exitosa, podrás usar interp igual que al propio perl:

% interp
print "Pretty Good Perl \n";
print "10890 - 9801 is ", 10890 - 9801;
<CTRL-D>
Pretty Good Perl
10890 - 9801 is 1089

o

% interp -e 'printf("%x", 3735928559)'
deadbeef

También puedes leer y ejecutar sentencias de Perl desde un archivo mientras estás en medio de tu programa C, colocando el nombre del archivo en argv[1] antes de llamar a perl_run.

Llamar a una subrutina de Perl desde tu programa C

En primer lugar, es necesario que un intérprete de Perl esté activo. (Ver la sección anterior.)

En segundo lugar, necesitas obtener la subrutina que deseas llamar. Eso se hace con la función call_pv():

SV *
call_pv(PerlInterpreter *perl, const char *name, I32 retlist);

donde name es el nombre de la subrutina a llamar (por ejemplo, "sqrt"), y retlist es un valor booleano que indica si la subrutina devuelve un valor. call_pv() devuelve un puntero a un SV (Perl Scalar Value) que contiene el valor devuelto (o sv_yes si retlist es falso).

Para pasar argumentos, necesitarás construir una pila de argumentos Perl, tal como se describe en la sección siguiente.

El ejemplo completo de la siguiente sección, "Evaluar una sentencia de Perl desde tu programa C", muestra cómo llamar a una subrutina simple y sin argumentos, "get_time". La llamada es:

SV *results = call_pv(my_perl, "get_time", TRUE);

Dado que "get_time" devuelve un solo valor (el tiempo actual), podemos simplemente invocar sv_2pv_nolen() para obtener una cadena C que contenga ese valor. Si la subrutina devolviera varios valores, el resultado de call_pv() sería un AV (Perl Array Value), que podrías desempacar.

La función call_sv() es similar a call_pv(), pero toma un puntero a un SV que contiene el código a ejecutar, en lugar de un nombre de subrutina.

Evaluar una sentencia de Perl desde tu programa C

Hay dos formas principales de ejecutar sentencias de Perl desde C. El método más sencillo es usar eval_pv():

SV *
eval_pv(PerlInterpreter *perl, const char *string);

donde string es la sentencia de Perl a ejecutar. eval_pv() devuelve un puntero a un SV que contiene el resultado de la sentencia. Si la sentencia provoca un error de ejecución, eval_pv() devuelve sv_undef, y puedes obtener información sobre el error examinando la variable especial $@ en Perl. Esto se hace típicamente de la siguiente manera:

SV *result = eval_pv(my_perl, "my $x = 5; $x + 2;");
if (result == sv_undef) {
    fprintf(stderr, "Error evaluating Perl code: ");
    perl_eval_pv(my_perl, "$@", TRUE); /* eval $@ */
    fprintf(stderr, "%s\n", SvPVX(perl_get_sv(my_perl, "$@", 0))); /* get $SPECIAL */
}

La segunda forma es usando eval_file():

int
eval_file(PerlInterpreter *perl, const char *filename, I32 todie);

donde filename es el nombre del archivo de Perl a ejecutar, y todie es un valor booleano que indica si el programa debe salir si ocurre un error. eval_file() devuelve un valor distinto de cero si hubo un error.

Aquí hay un programa C completo que evalúa una sentencia de Perl y luego llama a una subrutina de Perl:

#include <EXTERN.h>
#include <perl.h>

static PerlInterpreter *my_perl;

int main(int argc, char **argv, char **env)
{
    PERL_SYS_INIT3(&argc,&argv,&env);
    my_perl = perl_alloc();
    perl_construct(my_perl);
    PL_exit_flags |= PERL_EXIT_DESTRUCT_END;
    perl_parse(my_perl, NULL, argc, argv, (char **)NULL);
    perl_run(my_perl);

    /* Evaluar una sentencia de Perl */
    eval_pv(my_perl, "print qq(Hello from C, via Perl!)\n");

    /* Llamar a una subrutina de Perl */
    {
        SV *results = call_pv(my_perl, "get_time", TRUE);
        if (results != sv_undef) {
            printf("The time is: %s\n", SvPVX(results));
        }
    }

    perl_destruct(my_perl);
    perl_free(my_perl);
    PERL_SYS_TERM();
    exit(EXIT_SUCCESS);
}

Para que este ejemplo compile y ejecute, necesitas un archivo Perl llamado time.pl en el mismo directorio, que contenga:

sub get_time {
    require Time::localtime;
    return localtime();
}

O, si estás usando Perl 5.004 o posterior, puedes simplemente escribir:

use Time::localtime;
sub get_time { return localtime(); }

Compila y ejecuta este programa como se describe en la sección "Compilar tu programa C".

Realizar coincidencias y sustituciones de patrones de Perl desde tu programa C

Para realizar coincidencias y sustituciones de patrones de Perl desde C, necesitas construir un PV (Perl Value) que contenga la cadena que quieres examinar. Puedes obtener esto de un puntero a cadena C de la siguiente manera:

SV *string_sv = sv_2mortal(newPV("some string"));

Ahora puedes usar la función mg_search() (o match()) para realizar una coincidencia, o la función sv_grep() para sustituciones.

Sin embargo, es mucho más fácil hacer esto usando eval_pv(), como se describe en la sección anterior. Por ejemplo, para realizar una sustitución:

SV *new_string_sv = eval_pv(my_perl, "my $s = \"$old_string\"; $s =~ s/foo/bar/g; \$s");

Y para comprobar si hay una coincidencia:

SV *match_result = eval_pv(my_perl, "my $s = \"$old_string\"; \$s =~ /foo/i; \$&");

Si la coincidencia tiene éxito, match_result contendrá la parte de la cadena que coincidió. Si falla, será sv_undef.

Manipular la pila de Perl desde tu programa C

Cada intérprete de Perl tiene su propia pila, representada por PL_stack_sp (el puntero de pila de Perl). Puedes empujar y sacar valores de esta pila usando las funciones push() y pop().

Cuando llamas a una subrutina de Perl desde C, los argumentos se empujan a la pila de Perl. Para pasar argumentos, necesitas construir la pila de la siguiente manera:

void
setup_call_pv(PerlInterpreter *perl, const char *name)
{
    dSP; /* Declara SP y otros declaradores de pila */
    ENTER; /* Entra en el marco de ejecución */
    SAVETMPS; /* Guarda temporales */
    PUSHs(sv_2mortal(newPV(name))); /* Empuja el nombre de la subrutina */
    PUTBACK; /* Vuelve a poner SP en el intérprete */
    call_pv(perl, "call_sub_with_args", TRUE); /* Llama a la subrutina */
    SPAGAIN; /* Vuelve a obtener SP del intérprete */
    /* ... procesa resultados ... */
    FREETMPS; /* Libera temporales */
    LEAVE; /* Sale del marco de ejecución */
}

Para pasar argumentos a la subrutina, simplemente empújalos a la pila antes de llamar a call_pv():

void
setup_call_pv_with_args(PerlInterpreter *perl, const char *name, SV *arg1, SV *arg2)
{
    dSP;
    ENTER;
    SAVETMPS;
    PUSHs(sv_2mortal(newPV(name))); /* Nombre de la subrutina */
    PUSHs(sv_2mortal(arg1));       /* Primer argumento */
    PUSHs(sv_2mortal(arg2));       /* Segundo argumento */
    PUTBACK;
    call_pv(perl, "call_sub_with_args", TRUE);
    SPAGAIN;
    /* ... procesa resultados ... */
    FREETMPS;
    LEAVE;
}

Los valores devueltos se obtienen de la pila después de que la subrutina haya devuelto. Si la subrutina devuelve un solo valor, puedes obtenerlo con POPs. Si devuelve varios valores, los obtendrás uno por uno con POPs hasta que la pila esté vacía.

Hay una función auxiliar llamada call_sub_with_args() que maneja la pila por ti. Simplemente empuja los argumentos a la pila, y luego llama a call_sub_with_args(). La subrutina de Perl que realmente se llama es la que esté en la cima de la pila.

Mantener un intérprete persistente

Como se muestra en el ejemplo "Evaluar una sentencia de Perl desde tu programa C", simplemente no llamas a perl_destruct() y perl_free(). Mientras el intérprete esté activo, puedes seguir llamando a eval_pv(), call_pv(), etc.

El intérprete se destruye cuando tu programa C termina, o cuando llamas explícitamente a perl_destruct() y perl_free().

Mantener múltiples instancias de intérprete

Para mantener múltiples instancias de intérprete, simplemente llama a perl_alloc(), perl_construct() y perl_parse() para cada intérprete que quieras crear. Cada intérprete tendrá su propia pila, variables globales, etc.

Cuando termines con un intérprete, simplemente llama a perl_destruct() y perl_free() para ese intérprete en particular.

Usar módulos de Perl, que a su vez usan bibliotecas C, desde tu programa C

Esto es generalmente sencillo. Siempre que el módulo de Perl se haya compilado e instalado correctamente, puedes usarlo como lo harías normalmente desde Perl. Por ejemplo, si quieres usar el módulo Math::BigInt, puedes escribir:

eval_pv(my_perl, "use Math::BigInt; print Math::BigInt->new('12345678901234567890')->badd('1');");

El código C que llama al módulo de Perl se ejecutará como de costumbre. El módulo de Perl se encargará de llamar a la biblioteca C subyacente si es necesario.

El único inconveniente es que necesitas asegurarte de que el módulo de Perl esté instalado en un lugar donde el intérprete de Perl pueda encontrarlo. Normalmente, esto significa que debe estar en tu @INC (la lista de directorios de búsqueda de Perl).

Incrustar Perl en Win32

El proceso de incrustar Perl en Win32 es muy similar al de otros sistemas operativos. La principal diferencia es que necesitarás usar el compilador de C de Microsoft Visual C++ y enlazar con la biblioteca de importación de Perl (perl.lib).

Para obtener más información sobre la incrustación de Perl en Win32, consulta la documentación proporcionada con tu distribución de Perl o busca en línea la "Perl Win32 API".

Llamada a subrutinas de Perl desde su programa C

Para llamar a subrutinas individuales de Perl, puede usar cualquiera de las funciones call_* documentadas en perlcall. En este ejemplo usaremos "call_argv".

Eso se muestra a continuación, en un programa que llamaré showtime.c.

#include <EXTERN.h>
#include <perl.h>
static PerlInterpreter *my_perl;
int main(int argc, char **argv, char **env)
{
    char *args[] = { NULL };
    PERL_SYS_INIT3(&argc,&argv,&env);
    my_perl = perl_alloc();
    perl_construct(my_perl);
    perl_parse(my_perl, NULL, argc, argv, NULL);
    PL_exit_flags |= PERL_EXIT_DESTRUCT_END;
    /*** saltando perl_run() ***/
    call_argv("showtime", G_DISCARD | G_NOARGS, args);
    perl_destruct(my_perl);
    perl_free(my_perl);
    PERL_SYS_TERM();
    exit(EXIT_SUCCESS);
}

donde showtime es una subrutina de Perl que no toma argumentos (ese es el G_NOARGS) y cuyo valor de retorno ignoraremos (ese es el G_DISCARD). Esas banderas, y otras, se discuten en perlcall.

Definiré la subrutina showtime en un archivo llamado showtime.pl:

print "No se imprimirá.";
sub showtime {
    print time;
}

Sencillo. Ahora compile y ejecute:

% cc -o showtime showtime.c \
    `perl -MExtUtils::Embed -e ccopts -e ldopts`
% showtime showtime.pl
818284590

produciendo el número de segundos transcurridos entre el 1 de enero de 1970 (el comienzo de la época Unix) y el momento en que comencé a escribir esta oración.

En este caso particular, no tenemos que llamar a perl_run, ya que establecemos la bandera de salida PL_exit_flag PERL_EXIT_DESTRUCT_END que ejecuta los bloques END en perl_destruct.

Si desea pasar argumentos a la subrutina de Perl, puede agregar cadenas a la lista "args" terminada en "NULL" pasada a call_argv. Para otros tipos de datos, o para examinar valores de retorno, necesitará manipular la pila de Perl. Eso se demuestra en "Manipulando la pila de Perl desde su programa C".

Evaluación de una declaración de Perl desde su programa C

Perl proporciona dos funciones de API para evaluar fragmentos de código de Perl. Estas son "eval_sv" en perlapi y "eval_pv" en perlapi.

Podría decirse que estas son las únicas rutinas que necesitará para ejecutar fragmentos de código de Perl dentro de su programa C. Su código puede ser tan largo como desee; puede contener múltiples sentencias; puede emplear "use" en perlfunc, "require" en perlfunc, y "do" en perlfunc para incluir archivos externos de Perl.

eval_pv nos permite evaluar cadenas individuales de Perl y luego extraer variables para la conversión a tipos C. El siguiente programa, string.c, ejecuta tres cadenas de Perl, extrayendo un "int" del primero, un "float" del segundo y un "char *" del tercero.

#include <EXTERN.h>
#include <perl.h>
static PerlInterpreter *my_perl;
main (int argc, char **argv, char **env)
{
    char *embedding[] = { "", "-e", "0", NULL };
    PERL_SYS_INIT3(&argc,&argv,&env);
    my_perl = perl_alloc();
    perl_construct( my_perl );
    perl_parse(my_perl, NULL, 3, embedding, NULL);
    PL_exit_flags |= PERL_EXIT_DESTRUCT_END;
    perl_run(my_perl);
    /** Tratar $x como un entero **/
    eval_pv("$x = 3; $x **= 2", TRUE);
    printf("x = %d\n", SvIV(get_sv("x", 0)));
    /** Tratar $x como un flotante **/
    eval_pv("$x = 3.14; $x **= 2", TRUE);
    printf("x = %f\n", SvNV(get_sv("x", 0)));
    /** Tratar $x como una cadena **/
    eval_pv(
      "$x = 'rekcaH lreP rehtonA tsuJ'; $x = reverse($x);", TRUE);
    printf("x = %s\n", SvPV_nolen(get_sv("x", 0)));
    perl_destruct(my_perl);
    perl_free(my_perl);
    PERL_SYS_TERM();
}

Todas esas extrañas funciones con sv en sus nombres ayudan a convertir escalares de Perl a tipos C. Se describen en perlguts y perlapi.

Si compila y ejecuta string.c, verá los resultados de usar SvIV() para crear un "int", SvNV() para crear un "float" y SvPV() para crear una cadena:

a = 9
a = 9.859600
a = Just Another Perl Hacker

En el ejemplo anterior, hemos creado una variable global para almacenar temporalmente el valor calculado de nuestra expresión evaluada. También es posible y, en la mayoría de los casos, una mejor estrategia obtener el valor de retorno de eval_pv() en su lugar. Ejemplo:

...
SV *val = eval_pv("reverse 'rekcaH lreP rehtonA tsuJ'", TRUE);
printf("%s\n", SvPV_nolen(val));
...

De esta manera, evitamos la contaminación del espacio de nombres al no crear variables globales y hemos simplificado nuestro código también.

Realización de coincidencias y sustituciones de patrones de Perl desde su programa C

La función eval_sv() nos permite evaluar cadenas de código de Perl, por lo que podemos definir algunas funciones que utilizan esta para "especializarse" en coincidencias y sustituciones: match(), substitute() y matches().

I32 match(SV *string, char *pattern);

Dada una cadena y un patrón (por ejemplo, "m/clasp/" o "/\b\w*\b/", que en su programa C podría aparecer como "/\\b\\w*\\b/"), match() devuelve 1 si la cadena coincide con el patrón y 0 en caso contrario.

int substitute(SV **string, char *pattern);

Dado un puntero a un "SV" y una operación "=~" (por ejemplo, "s/bob/robert/g" o "tr[A-Z][a-z]"), substitute() modifica la cadena dentro del "SV" según la operación, devolviendo el número de sustituciones realizadas.

SSize_t matches(SV *string, char *pattern, AV **matches);

Dada una "SV", un patrón y un puntero a una "AV" vacía, matches() evalúa "$string =~ $pattern" en un contexto de lista y rellena matches con los elementos del array, devolviendo el número de coincidencias encontradas.

Aquí tienes un programa de ejemplo, match.c, que utiliza los tres (las líneas largas se han dividido aquí):

#include <EXTERN.h>
#include <perl.h>
static PerlInterpreter *my_perl;
/** my_eval_sv(code, error_check)
** similar a eval_sv(),
** pero sacamos el valor de retorno de la pila
**/
SV* my_eval_sv(SV *sv, I32 croak_on_error)
{
    dSP;
    SV*retval;
    PUSHMARK(SP);
    eval_sv(sv, G_SCALAR);
    SPAGAIN;
    retval = POPs;
    PUTBACK;
    if (croak_on_error && SvTRUE(ERRSV))
       croak_sv(ERRSV);
    return retval;
}
/** match(string, pattern)
**
** Se utiliza para coincidencias en un contexto escalar.
**
** Devuelve 1 si la coincidencia fue exitosa; 0 en caso contrario.
**/
I32 match(SV *string, char *pattern)
{
    SV *command = newSV(0), *retval;
    sv_setpvf(command, "my $string = '%s'; $string =~ %s",
             SvPV_nolen(string), pattern);
    retval = my_eval_sv(command, TRUE);
    SvREFCNT_dec(command);
    return SvIV(retval);
}
/** substitute(string, pattern)
**
** Se utiliza para operaciones =~ que
** modifican su lado izquierdo (s/// y tr///)
**
** Devuelve el número de coincidencias exitosas y

Manipulando la pila de Perl desde tu programa C

Al intentar explicar las pilas, la mayoría de los libros de texto de informática murmuran algo sobre columnas de platos de cafetería con resorte: lo último que pones en la pila es lo primero que sacas. Eso servirá para nuestros propósitos: tu programa C pondrá algunos argumentos en "la pila de Perl", cerrará los ojos mientras sucede algo mágico y luego sacará los resultados, el valor de retorno de tu subrutina de Perl, de la pila.

Primero necesitarás saber cómo convertir entre tipos C y tipos Perl, con newSViv() y sv_setnv() y newAV() y todos sus amigos. Están descritos en perlguts y perlapi.

Luego necesitarás saber cómo manipular la pila de Perl. Eso está descrito en perlcall.

Una vez que hayas entendido eso, incrustar Perl en C es fácil.

Dado que C no tiene una función integrada para la exponenciación entera, hagamos que el operador ** de Perl esté disponible para él (esto es menos útil de lo que parece, porque Perl implementa ** con la función pow() de C).

Primero crearé una función de exponenciación de stub en power.pl:

```perl sub expo { my ($x, $y) = @_; return $x ** $y; } ```

Ahora crearé un programa C, power.c, con una función PerlPower() que contiene todas las tripas de Perl necesarias para meter los dos argumentos en expo() y sacar el valor de retorno. Respira hondo...

```c #include #include static PerlInterpreter *my_perl; static void PerlPower(int a, int b) { dSP; /* inicializa el puntero de pila */ ENTER; /* todo lo creado después de aquí */ SAVETMPS; /* ...es una variable temporal. */ PUSHMARK(SP); /* recuerda el puntero de pila */ XPUSHs(sv_2mortal(newSViv(a))); /* empuja la base a la pila */ XPUSHs(sv_2mortal(newSViv(b))); /* empuja el exponente a la pila */ PUTBACK; /* hace que el puntero de pila local sea global */ call_pv("expo", G_SCALAR); /* llama a la función */ SPAGAIN; /* refresca el puntero de pila */ /* saca el valor de retorno de la pila */ printf ("%d elevado a la potencia %d es %d.\n", a, b, POPi); PUTBACK; FREETMPS; /* libera ese valor de retorno */ LEAVE; /* ...y los argumentos "mortales" XPUSHed. */ } int main (int argc, char **argv, char **env) { char *my_argv[] = { "", "power.pl", NULL }; PERL_SYS_INIT3(&argc,&argv,&env); my_perl = perl_alloc(); perl_construct( my_perl ); perl_parse(my_perl, NULL, 2, my_argv, (char **)NULL); PL_exit_flags |= PERL_EXIT_DESTRUCT_END; perl_run(my_perl); PerlPower(3, 4); /*** Calcula 3 ** 4 ***/ perl_destruct(my_perl); perl_free(my_perl); PERL_SYS_TERM(); exit(EXIT_SUCCESS); } ```

Manteniendo un intérprete persistente

Al desarrollar aplicaciones interactivas y/o potencialmente de larga duración, es una buena idea mantener un intérprete persistente en lugar de asignar y construir un nuevo intérprete varias veces. La razón principal es la velocidad: ya que Perl solo se cargará en memoria una vez.

Sin embargo, debes ser más cauteloso con el alcance de los espacios de nombres y las variables al usar un intérprete persistente. En ejemplos anteriores hemos estado usando variables globales en el paquete por defecto "main". Sabíamos exactamente qué código se ejecutaría y asumimos que podíamos evitar colisiones de variables y un crecimiento desmesurado de la tabla de símbolos.

Digamos que tu aplicación es un servidor que ocasionalmente ejecutará código Perl de algún archivo arbitrario. Tu servidor no tiene forma de saber qué código va a ejecutar. Muy peligroso.

Si el archivo es cargado por perl_parse(), compilado en un intérprete recién construido y posteriormente limpiado con perl_destruct(), estás protegido de la mayoría de los problemas de espacio de nombres.

Una forma de evitar colisiones de espacios de nombres en este escenario es traducir el nombre del archivo a un nombre de paquete garantizado único, y luego compilar el código en ese paquete usando "eval" en perlfunc. En el siguiente ejemplo, cada archivo solo se compilará una vez. O, la aplicación podría optar por limpiar la tabla de símbolos asociada con el archivo después de que ya no sea necesaria. Usando "call_argv" en perlapi, llamaremos a la subrutina "Embed::Persistent::eval_file" que vive en el archivo "persistent.pl" y pasaremos el nombre del archivo y un booleano de limpieza/caché como argumentos.

Ten en cuenta que el proceso seguirá creciendo por cada archivo que utilice. Además, puede haber subrutinas "AUTOLOAD" y otras condiciones que hagan que la tabla de símbolos de Perl crezca. Es posible que desees agregar alguna lógica que haga un seguimiento del tamaño del proceso, o que se reinicie después de un cierto número de solicitudes, para asegurar que el consumo de memoria se minimice. También querrás limitar el alcance de tus variables con "my" en perlfunc siempre que sea posible.

Ejecución de bloques END

Tradicionalmente, los bloques END se han ejecutado al final de perl_run. Esto causa problemas para las aplicaciones que nunca llaman a perl_run. Desde perl 5.7.2 puedes especificar "PL_exit_flags |= PERL_EXIT_DESTRUCT_END" para obtener el nuevo comportamiento. Esto también habilita la ejecución de bloques END si perl_parse falla y "perl_destruct" devolverá el valor de salida.

Mantenimiento de múltiples instancias de intérprete

Algunas aplicaciones raras necesitarán crear más de un intérprete durante una sesión. Dicha aplicación podría decidir esporádicamente liberar cualquier recurso asociado con el intérprete.

El programa debe tener cuidado de asegurarse de que esto suceda antes de que se construya el siguiente intérprete. Por defecto, cuando perl no se compila con ninguna opción especial, la variable global "PL_perl_destruct_level" se establece en 0, ya que la limpieza adicional no suele ser necesaria cuando un programa solo crea un intérprete en toda su vida útil.

Establecer "PL_perl_destruct_level" en 1 hace que todo esté impecable:

while(1) {
    ...
    /* reinicia las variables globales aquí con PL_perl_destruct_level = 1 */
    PL_perl_destruct_level = 1;
    perl_construct(my_perl);
    ...
    /* limpia y reinicia _todo_ durante perl_destruct */
    PL_perl_destruct_level = 1;
    perl_destruct(my_perl);
    perl_free(my_perl);
    ...
    /* ¡vamos a hacerlo de nuevo! */
}

Cuando se llama a perl_destruct(), se limpian el árbol de sintaxis de análisis y las tablas de símbolos del intérprete, y se reinician las variables globales. La segunda asignación a "PL_perl_destruct_level" es necesaria porque perl_construct la restablece a 0.

Ahora supongamos que tenemos más de una instancia de intérprete ejecutándose al mismo tiempo. Esto es factible, pero solo si utilizó la opción Configure "-Dusemultiplicity" o cualquiera de las opciones "-Dusethreads -Duseithreads" al compilar perl. Por defecto, habilitar una de estas opciones de Configure establece la variable global por intérprete "PL_perl_destruct_level" en 1, para que la limpieza completa sea automática y las variables del intérprete se inicialicen correctamente. Incluso si no pretende ejecutar dos o más intérpretes al mismo tiempo, sino ejecutarlos secuencialmente, como en el ejemplo anterior, se recomienda compilar perl con la opción "-Dusemultiplicity", de lo contrario, algunas variables del intérprete podrían no inicializarse correctamente entre ejecuciones consecutivas y su aplicación podría fallar.

(Antes había dos formas de hilos, apareciendo "ithreads" más tarde. Pero "ithreads" demostró ser superior, y el soporte para el modelo anterior se eliminó en Perl v5.10. Pero la documentación y el código nunca se purgaron de la terminología anterior; y quizás algún modelo más nuevo aparezca para suplantar a "ithreads", por lo que parece mejor conservar ambos. Si no le importa el modelo de hilos utilizado, use plain "usethreads" para proteger su código de tener que cambiar con desarrollos futuros. Si su código depende del modelo "ithreads", use "useithreads" para asegurarse de que siempre obtendrá ese. Esto también se aplica a los símbolos del lenguaje C "USE_THREADS" y "USE_ITHREADS".)

Ver también "Dealing with embedded perls and threads" en perlclib.

Usar "-Dusethreads -Duseithreads" en lugar de "-Dusemultiplicity" es más apropiado si pretende ejecutar múltiples intérpretes concurrentemente en diferentes hilos, porque habilita el soporte para enlazar las bibliotecas de hilos de su sistema con el intérprete.

Intentémoslo:

#include <EXTERN.h>
#include <perl.h>
/* vamos a incrustar dos intérpretes */
#define SAY_HELLO "-e", "print qq(Hi, I'm $^X\\n)"
int main(int argc, char **argv, char **env)
{

    char *two_args[] = { "two_perl", SAY_HELLO, NULL };
    PERL_SYS_INIT3(&argc,&argv,&env);
    one_perl = perl_alloc();
    two_perl = perl_alloc();
    PERL_SET_CONTEXT(one_perl);
    perl_construct(one_perl);
    PERL_SET_CONTEXT(two_perl);
    perl_construct(two_perl);
    PERL_SET_CONTEXT(one_perl);
    perl_parse(one_perl, NULL, 3, one_args, (char **)NULL);
    PERL_SET_CONTEXT(two_perl);
    perl_parse(two_perl, NULL, 3, two_args, (char **)NULL);
    PERL_SET_CONTEXT(one_perl);
    perl_run(one_perl);
    PERL_SET_CONTEXT(two_perl);
    perl_run(two_perl);
    PERL_SET_CONTEXT(one_perl);
    perl_destruct(one_perl);
    PERL_SET_CONTEXT(two_perl);
    perl_destruct(two_perl);
    PERL_SET_CONTEXT(one_perl);
    perl_free(one_perl);
    PERL_SET_CONTEXT(two_perl);
    perl_free(two_perl);

Observe las llamadas a PERL_SET_CONTEXT(). PERL_SET_CONTEXT(interp) también debe llamarse siempre que "interp" sea utilizado por un hilo que no lo creó (usando perl_alloc(), o el más esotérico perl_clone()).

Usando módulos de Perl, que a su vez usan bibliotecas C, desde su programa C

Si ha jugado con los ejemplos anteriores e intentó incrustar un script que use() un módulo de Perl (como Socket) que a su vez usa una biblioteca C o C++, probablemente sucedió esto:

Can't load module Socket, dynamic loading not available in this perl.
 (You may need to build a new perl executable which either supports
 dynamic loading or has the Socket module statically linked into it.)

¿Qué está mal?

Su intérprete no sabe cómo comunicarse con estas extensiones por sí solo. Un poco de pegamento ayudará. Hasta ahora ha estado llamando a perl_parse(), pasándole NULL como segundo argumento:

perl_parse(my_perl, NULL, argc, my_argv, NULL);

Ahí es donde se puede insertar el código de pegamento para crear el contacto inicial entre Perl y las rutinas C/C++ enlazadas. Echemos un vistazo a algunas partes de perlmain.c para ver cómo lo hace Perl:

static void xs_init (pTHX);
EXTERN_C void boot_DynaLoader (pTHX_ CV* cv);
EXTERN_C void boot_Socket (pTHX_ CV* cv);
EXTERN_C void
xs_init(pTHX)
{
       char *file = __FILE__;
       /* DynaLoader es un caso especial */
       newXS("DynaLoader::boot_DynaLoader", boot_DynaLoader, file);
       newXS("Socket::bootstrap", boot_Socket, file);
}

En pocas palabras: por cada extensión enlazada con su ejecutable de Perl (determinado durante su configuración inicial en su computadora o al agregar una nueva extensión), se crea una subrutina de Perl para incorporar las rutinas de la extensión. Normalmente, esa subrutina se llama Module::bootstrap() e se invoca cuando dice use Module. A su vez, esto se conecta a un XSUB, boot_Module, que crea una contraparte de Perl para cada uno de los XSUB de la extensión. No se preocupe por esta parte; déjela para xsubpp y los autores de extensiones. Si su extensión se carga dinámicamente, DynaLoader crea Module::bootstrap() sobre la marcha. De hecho, si tiene un DynaLoader funcional, rara vez es necesario enlazar estáticamente cualquier otra extensión.

Una vez que tenga este código, insértelo en el segundo argumento de perl_parse():

perl_parse(my_perl, xs_init, argc, my_argv, NULL);

Luego compile:

% cc -o interp interp.c `perl -MExtUtils::Embed -e ccopts -e ldopts`

  use SomeDynamicallyLoadedModule;

Usando Perl incrustado con locales POSIX

(Consulte perllocale para obtener información sobre estos.) Cuando un intérprete de Perl se inicia normalmente, le dice al sistema que quiere usar el locale predeterminado del sistema. Este es a menudo, pero no necesariamente, el locale "C" o "POSIX". En ausencia de "use locale" dentro del código de perl, esto en su mayoría no tiene efecto (pero vea "Not within the scope of \"use locale\"" en perllocale). Además, no hay problema si el locale que desea usar en su perl incrustado es el mismo que el predeterminado del sistema. Sin embargo, esto no funciona si ha configurado y desea usar un locale que no es el predeterminado del sistema. A partir de Perl v5.20, puede indicarle al intérprete de Perl incrustado que el locale ya está configurado correctamente y que omita su propia inicialización normal. Omite si la variable de entorno "PERL_SKIP_LOCALE_INIT" está establecida (incluso si se establece en 0 o ""). Un perl que tiene esta capacidad definirá el símbolo preprocesador C "HAS_SKIP_LOCALE_INIT". Esto permite que el código que tiene que trabajar con múltiples versiones de Perl realice algún tipo de solución alternativa cuando se enfrenta a una versión anterior de Perl.

Si su programa está utilizando la funcionalidad de locale multihilo POSIX 2008, debe cambiar al locale global y configurarlo correctamente

antes de iniciar el intérprete de Perl. Luego cambiará adecuadamente a usar las funciones seguras para hilos.

Ocultar Perl_

Si oculta completamente las formas cortas de la API pública de Perl, agregue -DPERL_NO_SHORT_NAMES a las banderas de compilación. Esto significa que, por ejemplo, en lugar de escribir

warn("%d botellas de cerveza en la pared", bottlecount);

tendrá que escribir la forma completa explícita

Perl_warn(aTHX_ "%d botellas de cerveza en la pared", bottlecount);

(Vea "Antecedentes y MULTIPLICIDAD" en perlguts para la explicación de "aTHX_".) Ocultar las formas cortas es muy útil para evitar todo tipo de conflictos desagradables (del preprocesador C o de otro tipo) con otros paquetes de software (Perl define aproximadamente 2400 APIs con estos nombres cortos, más o menos unos pocientos, por lo que ciertamente hay espacio para conflictos).

Doug MacEachern tiene un artículo sobre incrustación en el Volumen 1, Número 4 https://www.foo.be/docs/tpj/issues/vol1_4/ewtoc.html de The Perl Journal ( http://www.tpj.com/ ). Doug es también el desarrollador de la incrustación de Perl más utilizada: el sistema mod_perl (perl.apache.org), que incrusta Perl en el servidor web Apache. Oracle, Binary Evolution, ActiveState y nsapi_perl de Ben Sugars han utilizado este modelo para los plugins de Perl de Oracle, Netscape e Internet Information Server.
