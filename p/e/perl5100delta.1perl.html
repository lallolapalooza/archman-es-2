NOMBRE

perl5100delta - Novedades para perl 5.10.0

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.8.8 y la versión 5.10.0.

Muchas de las correcciones de errores en 5.10.0 ya se vieron en las versiones de mantenimiento 5.8.X; no se duplican aquí y se documentan en el conjunto de páginas de manual llamadas perl58[1-8]?delta.

Mejoras en el Núcleo

El pragma "feature"

El pragma "feature" se utiliza para habilitar nueva sintaxis que rompería la compatibilidad hacia atrás de Perl con versiones anteriores del lenguaje. Es un pragma léxico, como "strict" o "warnings".

Actualmente las siguientes nuevas características están disponibles: "switch" (agrega una sentencia switch), "say" (agrega una función incorporada "say") y "state" (agrega una palabra clave "state" para declarar variables "estáticas"). Esas características se describen en sus propias secciones de este documento.

El pragma "feature" también se carga implícitamente cuando se requiere una versión mínima de perl (con la construcción "use VERSION") mayor o igual a 5.9.5. Ver feature para detalles.

Nuevo interruptor de línea de comandos -E

-E es equivalente a -e, pero habilita implícitamente todas las características opcionales (como "use feature ":5.10"").

Operador definido-o

Se ha implementado un nuevo operador "//" (definido-o). La siguiente expresión:

$a // $b

es simplemente equivalente a

defined $a ? $a : $b

y la sentencia

$c //= $d;

ahora puede usarse en lugar de

$c = $d unless defined $c;

El operador "//" tiene la misma precedencia y asociatividad que "||". Se ha tomado especial cuidado para asegurar que este operador Haga Lo Que Usted Quiere sin romper código antiguo, pero algunos casos extremos que involucran la expresión regular vacía pueden ahora parsearse de manera diferente. Ver perlop para detalles.

Sentencia Switch y operador Smart Match

Perl 5 ahora tiene una sentencia switch. Está disponible cuando use feature 'switch' está en efecto. Esta característica introduce tres nuevas palabras clave, "given", "when" y "default":

given ($foo) {
    when (/^abc/) { $abc = 1; }
    when (/^def/) { $def = 1; }
    when (/^xyz/) { $xyz = 1; }
    default { $nothing = 1; }
}

Una descripción más completa de cómo Perl compara la variable switch con las condiciones "when" se da en "Sentencias switch" en perlsyn.

Este tipo de coincidencia se llama *smart match*, y también es posible usarlo fuera de las sentencias switch, a través del nuevo operador "~~". Ver "Coincidencia inteligente en detalle" en perlsyn.

Esta característica fue contribuida por Robin Houston.

Expresiones regulares

Patrones Recursivos
Ahora es posible escribir patrones recursivos sin usar la construcción "(??{})". Esta nueva forma es más eficiente y, en muchos casos, más fácil de leer.

Cada paréntesis de captura ahora puede tratarse como un patrón independiente al que se puede acceder usando la sintaxis "(?PARNO)" (siendo "PARNO" un sinónimo de "número de paréntesis"). Por ejemplo, el siguiente patrón coincidirá con corchetes angulares anidados y balanceados:

/
 ^                      # inicio de línea
 (                      # inicio del buffer de captura 1
    <                   #   coincidir con un corchete angular de apertura
    (?:                 #   coincidir con uno de:
        (?>             #     no retroceder sobre el interior de este grupo
            [^<>]+      #       uno o más caracteres que no sean corchetes angulares
        )               #     fin del grupo sin retroceso
    |                   #     ... o ...
        (?1)            #     volver al corchete 1 e intentarlo de nuevo
    )*                  #   0 o más veces.
    >                   #   coincidir con un corchete angular de cierre
 )                      # fin del buffer de captura uno
 $                      # fin de línea
/x

Los usuarios de PCRE deben notar que la característica de expresiones regulares recursivas de Perl permite retroceder a un patrón recursado, mientras que en PCRE la recursión es atómica o de naturaleza "posesiva". Como en el ejemplo anterior, se puede agregar (?>) para controlar esto selectivamente. (Yves Orton)

Buffers de Captura Nombrados
Ahora es posible nombrar paréntesis de captura en un patrón y referirse al contenido capturado por nombre. La sintaxis de nombres es "(?<NOMBRE>....)". Es posible referenciarse a un buffer nombrado con la sintaxis "\k<NOMBRE>". En el código, los nuevos hashes mágicos "%+" y "%-" pueden usarse para acceder al contenido de los buffers de captura.

Así, para reemplazar todos los caracteres duplicados por una sola copia, se podría escribir

s/(?<letra>.)\k<letra>/$+{letra}/g

Solo los buffers con contenido definido serán "visibles" en el hash "%+", por lo que es posible hacer algo como

foreach my $nombre (keys %+) {
    print "el contenido del buffer '$nombre' es $+{$nombre}\n";
}

El hash "%-" es un poco más completo, ya que contendrá referencias a arrays con valores de todos los buffers de captura nombrados de manera similar, si hubiera muchos de ellos.

"%+" y "%-" se implementan como hashes atados a través del nuevo módulo "Tie::Hash::NamedCapture".

Los usuarios familiarizados con el motor regex de .NET encontrarán que la implementación de perl difiere en que el ordenamiento numérico de los buffers es secuencial, y no "sin nombre primero, luego nombrado". Así en el patrón

/(A)(?<B>B)(C)(?<D>D)/

$1 será 'A', $2 será 'B', $3 será 'C' y $4 será 'D' y no $1 es 'A', $2 es 'C' y $3 es 'B' y $4 es 'D' que un programador de .NET esperaría. Esto se considera una característica. :-) (Yves Orton)

Cuantificadores Positivos
Perl ahora soporta la sintaxis de cuantificador "positivo" de patrón de "coincidencia atómica". Básicamente, un cuantificador positivo coincide tanto como puede y nunca cede nada hacia atrás. Por lo tanto, puede usarse para controlar el retroceso. La sintaxis es similar a la coincidencia no codiciosa, excepto que en lugar de usar un '?' como modificador se usa el '+'. Por lo tanto, "?+", "*+", "++", "{min,max}+" son ahora cuantificadores legales. (Yves Orton)

Perl versión 5.10.0

"Enhanced" backreferences
Previously, Perl's regular expressions supported two kinds of backreferences: those that captured into a numbered buffer (e.g., "s/(foo)bar/\1/") and those that captured into a named buffer (e.g., "s/(?<name>foo)bar/%<name>/").

These have been extended to handle names that are not valid identifiers, and also to support the use of Perl's associative arrays for capturing, e.g.

    s/(foo)bar/(my $var = $1)/e

This form is available when the "use feature 'enhanced_regexp'" is in effect.

The feature is implicitly enabled by the "use v5.10" pragma.

It is also available in the "s///" operator when it is used in the e form.

See "Backreferences" in perlre. (Yves Orton)

Retroreferencias relativas
Una nueva sintaxis "\g{N}" o "\gN" donde "N" es un entero decimal permite una forma más segura de notación de retroreferencias, así como permitir retroreferencias relativas. Esto debería facilitar la generación e incrustación de patrones que contienen retroreferencias. Ver "Capture buffers" en perlre. (Yves Orton)
"\\K" escape
La funcionalidad del módulo de Jeff Pinyan Regexp::Keep ha sido añadida al núcleo. En expresiones regulares ahora puedes usar el escape especial "\K" como una forma de hacer algo parecido a un lookbehind positivo de longitud flotante. También es útil en sustituciones como: 
s/(foo)bar/$1/g

que ahora puede ser convertida a

s/foo\Kbar//g

lo cual es mucho más eficiente. (Yves Orton)

Espacio en blanco vertical y horizontal, y salto de línea
Las expresiones regulares ahora reconocen los escapes "\v" y "\h" que coinciden con espacio en blanco vertical y horizontal, respectivamente. "\V" y "\H" coinciden lógicamente con sus complementos.

"\R" coincide con un salto de línea genérico, es decir, espacio en blanco vertical, más la secuencia de múltiples caracteres "\x0D\x0A".

Capturas opcionales de pre-coincidencia y post-coincidencia con el flag /p
Hay un nuevo flag "/p" para expresiones regulares. Usarlo hace que el motor preserve una copia de la parte de la cadena coincidente antes de la subcadena coincidente en la nueva variable especial "${^PREMATCH}", la parte después de la subcadena coincidente en "${^POSTMATCH}", y la subcadena coincidente misma en "${^MATCH}".

Perl todavía puede almacenar estas subcadenas en las variables especiales "$`", "$'", $&, pero usar estas variables en cualquier parte del programa añade una penalización a todas las coincidencias de expresiones regulares, mientras que si usas el flag "/p" y las nuevas variables especiales en su lugar, solo pagas por las expresiones regulares donde se usa el flag.

Para más detalles sobre las nuevas variables, ver perlvar; para el uso del flag de expresión regular, ver perlop y perlre.

say()

say() es una nueva función incorporada, solo disponible cuando "use feature 'say'" está en efecto, que es similar a print(), pero que implícitamente añade un salto de línea a la cadena impresa. Ver "say" en perlfunc. (Robin Houston)

$_ Léxico

La variable por defecto $_ ahora puede ser lexicalizada, declarándola como cualquier otra variable léxica, con un simple

my $_;

Las operaciones que por defecto actúan sobre $_ usarán la versión léxica de $_ cuando exista, en lugar de la global $_.

En un bloque de "map" o "grep", si $_ fue previamente my'ed, entonces el $_ dentro del bloque también es léxico (y está delimitado al bloque).

En un ámbito donde $_ ha sido lexicalizado, todavía se puede acceder a la versión global de $_ usando $::_, o, más simplemente, sobrescribiendo la declaración léxica con "our $_". (Rafael Garcia-Suarez)

El prototipo "_"

Se ha añadido un nuevo carácter de prototipo. "_" es equivalente a "$" pero por defecto es $_ si el argumento correspondiente no se suministra (tanto "$" como "_" denotan un escalar). Debido a la naturaleza opcional del argumento, solo puedes usarlo al final de un prototipo, o antes de un punto y coma.

Esto tiene una pequeña consecuencia incompatible: la función prototype() ha sido ajustada para devolver "_" para algunos incorporados en casos apropiados (por ejemplo, prototype('CORE::rmdir')). (Rafael Garcia-Suarez)

Bloques UNITCHECK

"UNITCHECK", un nuevo bloque de código especial ha sido introducido, además de "BEGIN", "CHECK", "INIT" y "END".

"CHECK" y "INIT" bloques, aunque útiles para algunos propósitos especializados, siempre se ejecutan en la transición entre la compilación y la ejecución del programa principal, y por lo tanto son inútiles cuando el código se carga en tiempo de ejecución. Por otro lado, "UNITCHECK" bloques se ejecutan justo después de que la unidad que los definió ha sido compilada. Ver perlmod para más información. (Alex Gough)

Pragma Nuevo, "mro"

Se ha añadido un nuevo pragma, "mro" (para Method Resolution Order - Orden de Resolución de Métodos). Permite cambiar, por clase, el algoritmo que perl utiliza para encontrar métodos heredados en caso de una jerarquía de herencia múltiple. El MRO por defecto no ha cambiado (DFS, por Depth First Search - Búsqueda en Profundidad). Otro MRO está disponible: el algoritmo C3. Ver mro para más información. (Brandon Black)

Tenga en cuenta que, debido a cambios en la implementación de la búsqueda de jerarquías de clases, el código que solía hacer undef a *ISA probablemente fallará. De todos modos, hacer undef a *ISA tenía el efecto secundario de eliminar la magia en el array @ISA y no debería haberse hecho en primer lugar. Además, la caché *::ISA::CACHE:: ya no existe; para forzar el reinicio de la caché de @ISA, ahora necesitas usar la API "mro", o más simplemente asignar a @ISA (por ejemplo, con "@ISA = @ISA").

readdir() puede devolver un "nombre de archivo corto" en Windows

La función readdir() puede devolver un "nombre de archivo corto" cuando el nombre de archivo largo contiene caracteres fuera de la página de códigos ANSI. De forma similar, Cwd::cwd() puede devolver un nombre de directorio corto, y glob() también puede devolver nombres cortos. En el sistema de archivos NTFS, estos nombres cortos siempre se pueden representar en la página de códigos ANSI. Esto no será cierto para todos los demás controladores de sistemas de archivos; por ejemplo, el sistema de archivos FAT almacena nombres de archivo cortos en la página de códigos OEM, por lo que algunos archivos en volúmenes FAT permanecen inaccesibles a través de las API ANSI.

Del mismo modo, $^X, @INC, y $ENV{PATH} se preprocesan al inicio para asegurar que todas las rutas sean válidas en la página de códigos ANSI (si es posible).

La función Win32::GetLongPathName() ahora devuelve el nombre de archivo largo correcto codificado en UTF-8 en lugar de usar caracteres de reemplazo para forzar el nombre en la página de códigos ANSI. La nueva función Win32::GetANSIPathName() puede usarse para convertir un nombre de ruta largo en uno corto solo si el largo no se puede representar en la página de códigos ANSI.

Muchas otras funciones en el módulo "Win32" han sido mejoradas para aceptar argumentos codificados en UTF-8. Por favor, consulta Win32 para detalles.

readpipe() ahora es sobrescribible

La función incorporada readpipe() ahora es sobrescribible. Sobrescribirla permite también sobrescribir su contraparte de operador, "qx//" (también conocido como ``). Además, ahora por defecto usa $_ si no se proporciona ningún argumento. (Rafael Garcia-Suarez)

Argumento por defecto para readline()

readline() ahora por defecto usa *ARGV si no se proporciona ningún argumento. (Rafael Garcia-Suarez)

Variables state()

Se ha introducido una nueva clase de variables. Las variables de estado son similares a las variables "my", pero se declaran con la palabra clave "state" en lugar de "my". Solo son visibles en su ámbito léxico, pero su valor es persistente: a diferencia de las variables "my", no se anulan al entrar en el ámbito, sino que conservan su valor anterior. (Rafael Garcia-Suarez, Nicholas Clark)

Para usar variables de estado, es necesario habilitarlas usando

use feature 'state';

o usando el switch de línea de comandos "-E" en one-liners. Ver "Persistent Private Variables" en perlsub.

Operadores filetest apilados

Como una nueva forma de azúcar sintáctico, ahora es posible apilar operadores filetest. Ahora puedes escribir "-f -w -x $file" en una fila para significar "-x $file && -w _ && -f _". Ver "-X" en perlfunc.

Pragma changes

"base"
The "base" pragma ahora advierte si una clase intenta heredar de sí misma. (Curtis "Ovid" Poe)
"strict" y "warnings"
"strict" y "warnings" ahora se quejarán ruidosamente si se cargan con una capitalización incorrecta (como en "use Strict;"). (Johan Vromans)
"version"
El módulo "version" proporciona soporte para objetos de versión.
"warnings"
El pragma "warnings" ya no carga "Carp". Eso significa que el código que usaba rutinas de "Carp" sin haberlas cargado en tiempo de compilación podría necesitar ser ajustado; típicamente, el siguiente código (defectuoso) ya no funcionará, y requerirá que se añadan paréntesis después del nombre de la función: 
use warnings;
require Carp;
Carp::confess 'argh';
"less"
"less" ahora hace algo útil (o al menos lo intenta). De hecho, se ha convertido en un pragma léxico. Así, en sus módulos, ahora puede probar si sus usuarios han solicitado usar menos CPU, o menos memoria, menos magia, o quizás incluso menos grasa. Vea less para más información. (Joshua ben Jore)

Nuevos módulos

  • "encoding::warnings", de Audrey Tang, es un módulo para emitir advertencias cada vez que una cadena de caracteres ASCII que contiene bytes de alto bit se convierte implícitamente a UTF-8. Es un pragma léxico desde Perl 5.9.4; en versiones anteriores de perl, su efecto es global.
  • "Module::CoreList", de Richard Clamp, es un módulo pequeño y útil que le dice qué versiones de módulos centrales se distribuyen con cualquier versión de Perl 5. Viene con un frontend de línea de comandos, "corelist".
  • "Math::BigInt::FastCalc" es una versión habilitada para XS, y por lo tanto más rápida, de "Math::BigInt::Calc".
  • "Compress::Zlib" es una interfaz a la biblioteca de compresión zlib. Viene con una versión empaquetada de zlib, por lo que tener una zlib funcional no es un requisito previo para instalarlo. Es utilizado por "Archive::Tar" (ver abajo).
  • "IO::Zlib" es una interfaz al estilo "IO::" para "Compress::Zlib".
  • "Archive::Tar" es un módulo para manipular archivos "tar".
  • "Digest::SHA" es un módulo utilizado para calcular muchos tipos de resúmenes SHA, se ha incluido para el soporte SHA en el módulo CPAN.
  • Se han añadido "ExtUtils::CBuilder" y "ExtUtils::ParseXS".
  • Se ha añadido "Hash::Util::FieldHash", de Anno Siegel. Este módulo proporciona soporte para hashes de campos: hashes que mantienen una asociación de una referencia con un valor, de forma segura para hilos y con recolección de basura. Dichos hashes son útiles para implementar objetos de adentro hacia afuera.
  • Se ha añadido "Module::Build", de Ken Williams. Es una alternativa a "ExtUtils::MakeMaker" para construir e instalar módulos de perl.
  • Se ha añadido "Module::Load", de Jos Boumans. Proporciona una interfaz única para cargar módulos de Perl y archivos .pl.
  • Se ha añadido "Module::Loaded", de Jos Boumans. Se utiliza para marcar módulos como cargados o descargados.
  • Se ha añadido "Package::Constants", de Jos Boumans. Es un simple ayudante para listar todas las constantes declaradas en un paquete dado.
  • Se ha añadido "Win32API::File", de Tye McQueen (para compilaciones de Windows). Este módulo proporciona acceso de bajo nivel a las llamadas a la API del sistema Win32 para archivos/directorios.
  • "Locale::Maketext::Simple", necesario por CPANPLUS, es un simple envoltorio alrededor de "Locale::Maketext::Lexicon". Tenga en cuenta que "Locale::Maketext::Lexicon" no está incluido en el núcleo de perl; el comportamiento de "Locale::Maketext::Simple" se degrada elegantemente cuando el último no está presente.
  • "Params::Check" implementa un mecanismo genérico de análisis/verificación de entrada. Es utilizado por CPANPLUS.
  • "Term::UI" simplifica la tarea de hacer preguntas en un prompt de terminal.
  • "Object::Accessor" proporciona una interfaz para crear accesores por objeto.
  • "Module::Pluggable" es un framework simple para crear módulos que aceptan sub-módulos enchufables.
  • "Module::Load::Conditional" proporciona formas sencillas de consultar y posiblemente cargar módulos instalados.
  • "Time::Piece" proporciona una interfaz orientada a objetos a las funciones de tiempo, anulando las incorporadas localtime() y gmtime().
  • "IPC::Cmd" ayuda a encontrar y ejecutar comandos externos, posiblemente de forma interactiva.
  • "File::Fetch" proporciona un mecanismo simple y genérico de obtención de archivos.
  • "Log::Message" y "Log::Message::Simple" son utilizados por el servicio de registro de "CPANPLUS".
  • "Archive::Extract" es un mecanismo genérico de extracción de archivos para archivos .tar (planos, comprimidos con gzip o bzip2) o .zip.
  • "CPANPLUS" proporciona una API y una herramienta de línea de comandos para acceder a los espejos de CPAN.
  • "Pod::Escapes" proporciona utilidades que son útiles para decodificar secuencias E<...> de Pod.
  • "Pod::Simple" es ahora el backend para varios de los módulos relacionados con Pod incluidos con Perl.

Nuevas características

PerlIO
PerlIO, the new I/O system introduced in Perl 5.8, has had a number of improvements and new features.

The new "PerlIO::encoding" IO layer has been introduced, allowing you to specify the encoding on a per-filehandle basis. For example:

    open my $fh, ">:encoding(UTF-8)", $filename
        or die "Can't open $filename: $!";
    print $fh "\x{20ac}"; # prints the Euro sign

The ":utf8" IO layer, which was previously available only as a pragma, is now also available as an IO layer. It differs from ":encoding(UTF-8)" in that it is more aware of the internal representation of strings in Perl, and will only decode characters that are not already in Perl's internal UTF-8 form.

The ":raw" IO layer has been introduced, which is similar to the ":bytes" pragma in that it disables all character encoding and decoding.

The "PerlIO::via" IO layer has been introduced, allowing you to chain IO layers together. For example, you could potentially implement compression and encoding like this:

    open my $fh, ">:via(Compress::Zlib),encoding(UTF-8)", $filename

The "PerlIO::null" layer has been added, to see if printf-like formats are allowed to be NULL.

Configure help
"Configure -h" has been extended with the most commonly used options.

"strict" no estaba en vigor en los bloques de evaluación de expresiones regulares ("/(?{...})/").
Llamada a CORE::require()
CORE::require() y CORE::do() siempre se analizaban como require() y do() cuando se sobrescribían. Esto ahora está corregido.
Subíndices de rebanadas
Ahora puede usar una forma sin flecha para subíndices encadenados después de una rebanada de lista, como en: 
({foo => "bar"})[0]{foo}

Esto antes era un error de sintaxis; se requería un "->".

"no warnings 'category'" funciona correctamente con -w
Anteriormente, cuando se ejecutaba con advertencias habilitadas globalmente a través de "-w", la desactivación selectiva de categorías de advertencia específicas en realidad desactivaba todas las advertencias. Esto ahora está corregido; ahora "no warnings 'io';" solo desactivará las advertencias de la clase "io". Anteriormente, desactivaba erróneamente todas las advertencias.
Mejoras en threads
Se cerraron varias fugas de memoria en ithreads. Además, los ithreads consumen menos memoria.

"threads" es ahora un módulo de doble vida, también disponible en CPAN. Se ha ampliado de muchas maneras. Un método kill() está disponible para la señalización de hilos. Se puede obtener el estado del hilo, o la lista de hilos en ejecución o unibles.

Se utiliza un nuevo método "threads->exit()" para salir de la aplicación (este es el valor predeterminado para el hilo principal) o solo del hilo actual (este es el valor predeterminado para todos los demás hilos). Por otro lado, la función incorporada exit() ahora siempre provoca la terminación de toda la aplicación. (Jerry D. Hedden)

chr() y valores negativos
chr() en un valor negativo ahora devuelve "\x{FFFD}", el carácter de reemplazo Unicode, excepto cuando el pragma "bytes" está en vigor, donde se utilizan los ocho bits inferiores del valor.
PERL5SHELL y tainting
En Windows, la variable de entorno PERL5SHELL ahora se verifica para detectar tainting. (Rafael Garcia-Suarez)
Uso de *FILE{IO}
stat() y las pruebas de archivo "-X" ahora tratan los manejadores de archivo *FILE{IO} como manejadores de archivo *FILE. (Steve Peters)
Sobrecarga y re-bautismo
La sobrecarga ahora funciona cuando las referencias se rebautizan a otra clase. Internamente, esto se ha implementado moviendo la bandera de "sobrecarga" de la referencia al referente, que lógicamente es donde siempre debería haber estado. (Nicholas Clark)
Sobrecarga y UTF-8
Se han corregido algunos errores relacionados con el manejo de UTF-8 con objetos que tienen sobrecargada la stringification. (Nicholas Clark)
Fugas de memoria de `eval` corregidas
Tradicionalmente, "eval 'syntax error'" tenía fugas importantes. Muchas (pero no todas) de estas fugas ahora se han eliminado o reducido. (Dave Mitchell)
Dispositivo aleatorio en Windows
En versiones anteriores, perl leía el archivo /dev/urandom si existía al sembrar su generador de números aleatorios. Es poco probable que ese archivo exista en Windows, y si lo hiciera, probablemente no contendría datos apropiados, por lo que perl ya no intenta leerlo en Windows. (Alex Davies)
PERLIO_DEBUG
La variable de entorno "PERLIO_DEBUG" ya no tiene ningún efecto para scripts setuid y para scripts ejecutados con -T.

Además, con un perl habilitado para hilos, el uso de "PERLIO_DEBUG" podría provocar un desbordamiento de búfer interno. Esto se ha corregido.

PerlIO::scalar y escalares de solo lectura
PerlIO::scalar ahora evitará escribir en escalares de solo lectura. Además, ahora se admite seek() con manejadores de archivo basados en PerlIO::scalar, y la cadena subyacente se rellena con ceros según sea necesario. (Rafael, Jarkko Hietaniemi)
study() y UTF-8
study() nunca funcionó para cadenas UTF-8, pero podría llevar a resultados falsos. Ahora es una operación nula (no-op) en datos UTF-8. (Yves Orton)
Señales críticas
Las señales SIGILL, SIGBUS y SIGSEGV ahora siempre se entregan de manera "insegura" (a diferencia de otras señales, que se posponen hasta que el intérprete de perl alcance un estado razonablemente estable; consulte "Deferred Signals (Safe Signals)" en perlipc). (Rafael)
Corrección de @INC-hook
Cuando un módulo o archivo se carga a través de un @INC-hook, y cuando este hook ha establecido una entrada de nombre de archivo en %INC, __FILE__ se establece ahora para este módulo de acuerdo con el contenido de esa entrada de %INC. (Rafael)
"-t" switch fix
Los switches "-w" y "-t" ahora se pueden usar juntos sin estropear qué categorías de advertencias están activadas. (Rafael)
Duplicación de manejadores de archivo UTF-8
Duplicar un manejador de archivo que tiene la capa PerlIO ":utf8" configurada ahora transferirá correctamente esa capa al manejador de archivo duplicado. (Rafael)
Localización de elementos de hash
La localización de un elemento de hash cuya clave se proporcionó como una variable no funcionó correctamente si la variable se cambió mientras local() estaba en vigor (como en "local $h{$x}; ++$x"). (Bo Lindbergh)

Diagnósticos nuevos o cambiados

Uso de valor no inicializado
Perl ahora intentará decirle el nombre de la variable (si la hay) que no estaba definida.
Uso obsoleto de my() en condicional falso
Se ha añadido una nueva advertencia de obsolescencia, Uso obsoleto de my() en condicional falso, para advertir contra el uso de la construcción dudosa y obsoleta 
my $x if 0;
>

Ver perldiag. Usar variables de "estado" en su lugar.

!=~ debe ser !~
Una nueva advertencia, "!=~ should be !~", se emite para prevenir esta errata del operador de no coincidencia.
Nueva línea en cadena justificada a la izquierda
La advertencia Newline in left-justified string ha sido eliminada.
Demasiado tarde para la opción "-T"
El error Too late for "-T" option ha sido reformulado para ser más descriptivo.
La variable "%s" %s enmascara declaración anterior
Esta advertencia ahora se emite en casos más consistentes; en resumen, cuando una de las declaraciones involucradas es una variable "my": 
my $x;   my $x;     # advierte
my $x;  our $x;     # advierte
our $x;  my $x;     # advierte

Por otro lado, lo siguiente:

our $x; our $x;

ahora genera una advertencia ""our" variable %s redeclared".

Intento de readdir()/closedir()/etc. en un manejador de directorio inválido
Estas nuevas advertencias ahora se emiten cuando se usa un manejador de directorio pero está cerrado o no es realmente un manejador de directorio.
Abriendo manejador de directorio/archivo %s también como un archivo/directorio
Se han agregado dos advertencias de desaprobación: (Rafael) 
Opening dirhandle %s also as a file
Opening filehandle %s also as a directory
El uso de -P está desaprobado
El interruptor de línea de comandos "-P" de Perl está ahora desaprobado.
cadena v en uso/requerir no es portable
Perl te advertirá contra posibles problemas de compatibilidad hacia atrás con la sintaxis "use VERSION".
perl -V
"perl -V" tiene varias mejoras, haciéndolo más utilizable desde scripts de shell para obtener el valor de las variables de configuración. Ver perlrun para detalles.

Internos Cambiados

En general, el código fuente de perl ha sido refactorizado, ordenado y optimizado en muchos lugares. Además, la gestión y asignación de memoria ha mejorado en varios puntos.

Al compilar el núcleo de perl con gcc, se activan tantas banderas de advertencia de gcc como es posible en la plataforma. (Esta búsqueda de limpieza no se extiende al código XS porque no podemos garantizar la pulcritud del código que no escribimos.) Se han agregado o endurecido banderas de estrictez similares para varios otros compiladores de C.

Reordenamiento de constantes SVt_*

El orden relativo de las constantes que definen los diversos tipos de "SV" ha cambiado; en particular, "SVt_PVGV" se ha movido antes que "SVt_PVLV", "SVt_PVAV", "SVt_PVHV" y "SVt_PVCV". Es poco probable que esto marque alguna diferencia a menos que tengas código que haga suposiciones explícitas sobre ese orden. (La jerarquía de herencia de los objetos "B::*" ha sido modificada para reflejar esto.)

Eliminación de SVt_PVBM

Relacionado con esto, el tipo interno "SVt_PVBM" ha sido eliminado. Este tipo dedicado de "SV" era utilizado por el operador "index" y partes del motor de expresiones regulares para facilitar coincidencias rápidas de Boyer-Moore. Su uso interno ha sido reemplazado por "SV" de tipo "SVt_PVGV".

Nuevo tipo SVt_BIND

Se ha agregado un nuevo tipo "SVt_BIND", en preparación para el proyecto de implementar Perl 6 en 5. Deliberadamente no hay implementación todavía, y aún no se pueden crear ni destruir.

Eliminación de símbolos CPP

Los símbolos del preprocesador C "PERL_PM_APIVERSION" y "PERL_XS_APIVERSION", que se suponía que debían dar el número de versión del binario perl más antiguo (respectivamente, compatible en origen) con el actual, no se usaron y a veces tenían valores engañosos. Han sido eliminados.

Menos espacio es usado por ops

La estructura "BASEOP" ahora usa menos espacio. El campo "op_seq" ha sido eliminado y reemplazado por un solo bit de campo de bits "op_opt". "op_type" ahora tiene 9 bits de longitud. (En consecuencia, la clase "B::OP" ya no proporciona un método "seq".)

Nuevo parser

El parser de perl ahora es generado por bison (solía ser generado por byacc.) Como resultado, parece ser un poco más robusto.

Además, Dave Mitchell mejoró la salida de depuración del lexer bajo "-DT".

Uso de "const"

Andy Lester proporcionó muchas mejoras para determinar qué parámetros de función y variables locales podían declararse realmente como "const" para el compilador C. Steve Peters proporcionó nuevas macros *_set y rehizo el núcleo para usar estas en lugar de asignar a macros en contexto LVALUE.

Mathoms

Se ha agregado un nuevo archivo, mathoms.c. Contiene funciones que ya no se utilizan en el núcleo de perl, pero que permanecen disponibles por razones de compatibilidad binaria o de origen. Sin embargo, esas funciones no se compilarán si agregas "-DNO_MATHOMS" en las opciones del compilador.

"AvFLAGS" ha sido eliminado

La macro "AvFLAGS" ha sido eliminada.

Cambios en "av_*"

Las funciones "av_*()", utilizadas para manipular arrays, ya no aceptan parámetros "AV*" nulos.

$^H y %^H

La implementación de las variables especiales $^H y %^H ha cambiado, para permitir la implementación de pragmas léxicos en perl puro.

Herencia cambiada de módulos B::

La jerarquía de herencia de los módulos "B::" ha cambiado; "B::NV" ahora hereda de "B::SV" (solía heredar de "B::IV").

Constructores de hashes y arrays anónimos

Los constructores de hashes y arrays anónimos ahora toman 1 op en el árbol de operaciones en lugar de 3, ahora que pp_anonhash y pp_anonlist devuelven una referencia a un hash/array cuando el op está marcado con OPf_SPECIAL. (Nicholas Clark)

Problemas Conocidos

Todavía hay un problema persistente en la implementación del $_ léxico: no funciona dentro de los bloques "/(?{...})/". (Ver la prueba TODO en t/op/mydef.t.)

Los operadores de prueba de archivos apilados no funcionarán cuando el pragma "filetest" esté activo, ya que dependen de que el búfer "_" de stat() esté poblado, y filetest omite stat().

Problemas de UTF-8

El manejo de Unicode sigue siendo poco limpio en varios lugares, donde depende de si una cadena está marcada internamente como UTF-8. Esto se hará más consistente en perl 5.12, pero no será posible sin una cierta cantidad de incompatibilidad hacia atrás.

Problemas Específicos de Plataforma

Cuando se compila con g++ y soporte de hilos en Linux, se informa que el $! deja de funcionar correctamente. Esto está relacionado con el hecho de que glibc proporciona dos implementaciones de strerror_r(3), y perl selecciona la incorrecta.

Reporte de Errores

Si encuentras lo que crees que es un error, puedes consultar los artículos publicados recientemente en el grupo de noticias comp.lang.perl.misc y la base de datos de errores de perl en http://rt.perl.org/rt3/ . También puede haber información en http://www.perl.org/ , la página principal de Perl.

Si crees que tienes un error no reportado, ejecuta el programa perlbug incluido con tu versión. Asegúrate de reducir tu error a un caso de prueba pequeño pero suficiente. Tu informe de error, junto con la salida de "perl -V", se enviará a perlbug@perl.org para ser analizado por el equipo de portabilidad de Perl.
