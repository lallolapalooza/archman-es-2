PERLTRU64(1perl) Guía de referencia para programadores de Perl PERLTRU64(1perl)

NOMBRE

perltru64 - Versión 5 de Perl en sistemas Tru64 (anteriormente conocido como Digital UNIX, anteriormente conocido como DEC OSF/1)

DESCRIPCIÓN

Este documento describe varias características del sistema operativo Unix de HP (anteriormente Compaq, anteriormente Digital) (Tru64) que afectarán cómo se configura, compila y/o ejecuta la versión 5 de Perl (en adelante, solo Perl).

Compilación de Perl 5 en Tru64

El compilador recomendado para usar en Tru64 es el compilador C nativo. El compilador nativo produce código mucho más rápido (la diferencia de velocidad es notable: varias docenas de porcentajes) y también más correcto: si estás considerando usar el compilador C de GNU, deberías usar al menos la versión 2.95.3, ya que se sabe que todas las versiones anteriores de gcc producen código defectuoso al compilar Perl. Una manifestación de este defecto es que la prueba lib/sdbm vuelca el núcleo; otra es que muchas de las pruebas op/regexp y op/pat, o ext/Storable vuelcan el núcleo (el patrón exacto de fallos depende de la versión de GCC y las banderas de optimización).

Tanto el cc nativo como el gcc parecen consumir mucha memoria al compilar Perl. toke.c es un punto problemático conocido al optimizar: 256 megabytes de sección de datos parecen ser suficientes. Otro punto problemático conocido es el script mktables, que construye las tablas de soporte Unicode. La configuración predeterminada de la sección de datos del proceso en Tru64 debería ser de un gigabyte, pero algunos sitios/configuraciones podrían haberla reducido. El proceso de configuración de Perl verifica límites de proceso demasiado bajos, reduce la optimización para toke.c si es necesario, y también da consejos sobre cómo aumentar los límites del proceso (por ejemplo: "ulimit -d 262144")

Además, Configure podría abortar con

Build a threading Perl? [n]
Configure[2437]: Syntax error at line 1 : 'config.sh' is not expected.

Esto indica que Configure se está ejecutando con un shell Korn defectuoso (incluso si crees que estás usando un shell Bourne al usar "sh Configure" o "./Configure"). El error del shell Korn ha sido reportado a Compaq desde febrero de 1999, pero mientras tanto, la razón por la que se usa ksh es que tienes la variable de entorno BIN_SH establecida en 'xpg4'. Esto hace que /bin/sh delegue sus funciones a /bin/posix/sh (un ksh). Desestablece la variable de entorno y vuelve a ejecutar Configure.

Uso de archivos grandes con Perl en Tru64

En Tru64, Perl puede usar automáticamente archivos grandes, es decir, archivos de más de 2 gigabytes; no es necesario usar la opción -Duselargefiles de Configure descrita en INSTALL (aunque usar la opción es inofensivo).

Perl con hilos en Tru64

Si quieres usar hilos, deberías usar principalmente el modelo de hilos de Perl 5.8.0 ejecutando Configure con -Duseithreads.

Los hilos de Perl solo funcionarán en las versiones 4.0 y posteriores de Tru64; las versiones anteriores del sistema operativo como la 3.2 probablemente no funcionarán correctamente con hilos.

En Tru64 V5 (al menos V5.1A, V5.1B) no puedes compilar Perl con hilos usando gcc porque la cabecera del sistema <pthread.h> comprueba explícitamente los compiladores C compatibles, y gcc (al menos 3.2.2) no es uno de ellos. Pero el compilador C del sistema debería funcionar perfectamente.

Long Doubles en Tru64

No puedes configurar Perl para usar long doubles a menos que tengas al menos Tru64 V5.0; el soporte de long double simplemente no era lo suficientemente funcional antes de eso. Configure de Perl anulará los intentos de usar long doubles (puedes notarlo cuando Configure descubra que la función modfl() no funciona como debería).

En el momento de escribir esto (junio de 2002), hay un error conocido en la impresión de long doubles en la libc de Tru64 cuando no se usa la notación "e". Los valores son correctos y utilizables, pero solo obtendrás un número limitado de dígitos mostrados a menos que fuerces la cuestión usando "printf "%.33e",$num" o algo similar. Para las versiones V5.0A a V5.1A de Tru64, se espera un parche poco después del lanzamiento de perl 5.8.0. Si tu libc aún no ha sido parcheada, recibirás una advertencia de Configure al seleccionar long doubles.

Fallos en las pruebas de DB_File en Tru64

Las pruebas de DB_File (db-btree.t, db-hash.t, db-recno.t) pueden fallar si has instalado una versión más reciente de Berkeley DB en el sistema y las banderas del compilador y enlazador -I y -L introducen conflictos de versión con las cabeceras y bibliotecas DB 1.85 que venían con Tru64. Por ejemplo, mezclar una biblioteca DB v2 con las cabeceras DB v1 es una mala idea. Ten cuidado con las opciones de Configure -Dlocincpth y -Dloclibpth, y revisa tus directorios /usr/local/include y /usr/local/lib ya que se incluyen por defecto.

La segunda opción es instruir explícitamente a Configure para que detecte la instalación más reciente de Berkeley DB, proporcionando los directorios correctos con "-Dlocincpth=/algún/include" y "-Dloclibpth=/alguna/lib" y antes de ejecutar "make test" estableciendo tu LD_LIBRARY_PATH a /alguna/lib.

La tercera opción es solucionar el problema deshabilitando completamente DB_File al compilar Perl especificando -Ui_db a Configure, y luego usando el módulo BerkeleyDB de CPAN en lugar de DB_File. BerkeleyDB funciona con versiones 2.* o superiores de Berkeley DB.

Se ha probado Berkeley DB 4.1.25 con Tru64 V5.1A y ha funcionado. La última versión de Berkeley DB se puede encontrar en http://www.sleepycat.com.

Perl de 64 bits en Tru64

En Tru64, los enteros de Perl son automáticamente de 64 bits de ancho; no es necesario usar la opción -Duse64bitint de Configure descrita en INSTALL. De manera similar, no es necesario usar -Duse64bitall ya que los punteros son automáticamente de 64 bits de ancho.

Advertencias sobre desbordamiento de punto flotante al compilar Perl en Tru64

Al compilar Perl en Tru64, puede que veas (dependiendo de la versión del compilador) dos advertencias como esta

cc: Warning: numeric.c, line 104: In this statement, floating-point
overflow occurs in evaluating the expression "1.8e308". (floatoverfl)
    return HUGE_VAL;
-----------^

y al compilar la extensión POSIX

cc: Warning: const-c.inc, line 2007: In this statement, floating-point
overflow occurs in evaluating the expression "1.8e308". (floatoverfl)
            return HUGE_VAL;
-------------------^

Los números de línea exactos pueden variar entre las versiones de Perl. Las advertencias son benignas y pueden ignorarse: en versiones posteriores del compilador C, las advertencias deberían desaparecer.

Cuando se compila el archivo pp_sys.c, es posible que (dependiendo de la versión del sistema operativo) veas que se utiliza una bandera de compilador adicional: "-DNO_EFF_ONLY_OK". Esto es normal y se refiere a una característica que solo es relevante si usas el pragmatismo "filetest". En versiones anteriores del sistema operativo, la característica estaba rota y NO_EFF_ONLY_OK instruye a Perl a no usar la característica.

Pruebas de Perl en Tru64

Durante "make test", se omitirá la prueba "comp"/"cpp" porque en Tru64 no se puede probar antes de que Perl haya sido instalado. La prueba se refiere al uso de la opción "-P" de Perl.

Fallo de la prueba de ext/ODBM_File/odbm con compilaciones estáticas

Se sabe que ext/ODBM_File/odbm falla con compilaciones estáticas (Configure -Uusedl) debido a un error conocido en la biblioteca libdbm estática de Tru64. La buena noticia es que muy probablemente nunca necesitarás usar la extensión ODBM_File, ya que NDBM_File, más avanzado, funciona bien, sin mencionar que DB_File, aún más avanzado, también funciona.

Perl Falla Debido a Símbolo No Resuelto sockatmark

Si obtienes un error como

No se puede cargar '.../OSF1/lib/perl5/5.8.0/alpha-dec_osf/auto/IO/IO.so' para el módulo IO: Símbolo no resuelto en .../lib/perl5/5.8.0/alpha-dec_osf/auto/IO/IO.so: sockatmark en .../lib/perl5/5.8.0/alpha-dec_osf/XSLoader.pm línea 75.

necesitas recompilar tu Perl en Tru64 4.0D o actualizar tu Tru64 4.0D a al menos 4.0F: la llamada al sistema sockatmark() se añadió en Tru64 4.0F, y la extensión IO hace referencia a ese símbolo.

read_cur_obj_info: número mágico de archivo incorrecto

Puede que estés mezclando el Tru64 cc/ar/ld con el GNU gcc/ar/ld. Eso puede funcionar, pero a veces no (tu gcc o utilidades GNU pueden haber sido compilados para una versión de SO incompatible).

Intenta con 'which ld' y 'which cc' (o intenta con 'ar --version' y 'ld --version', que solo funcionan para las herramientas GNU y se anunciarán como tales), y ajusta tu PATH para que estés usando consistentemente las herramientas nativas o las herramientas GNU. Después de arreglar tu PATH, deberías hacer 'make distclean' y empezar desde el principio ejecutando Configure, ya que podrías tener una situación bastante confusa.
