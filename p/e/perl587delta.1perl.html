PERL587DELTA(1perl) Guía de Referencia del Programador de Perl PERL587DELTA(1perl)

NOMBRE

perl587delta - novedades de la versión perl v5.8.7

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.8.6 y la versión 5.8.7.

Cambios Incompatibles

No hay cambios incompatibles con 5.8.6.

Mejoras Centrales

Base de Datos de Caracteres Unicode 4.1.0

La copia de la Base de Datos de Caracteres Unicode incluida en Perl 5.8 ha sido actualizada de la versión 4.0.1 a la 4.1.0. Ver http://www.unicode.org/versions/Unicode4.1.0/#NotableChanges para los cambios notables.

suidperl menos inseguro

Se han cerrado un par de exploits en "suidperl" que involucraban código de depuración.

Para nuevos proyectos, el equipo central de perl recomienda encarecidamente que utilicen herramientas de seguridad dedicadas y de propósito único como "sudo" en preferencia a "suidperl".

Script de personalización de sitio opcional

El intérprete de perl puede ser compilado para permitir el uso de un script de personalización de sitio. Por defecto, esto no está habilitado, para ser consistente con lanzamientos anteriores de perl. Para usar esto, añada "-Dusesitecustomize" a las opciones de la línea de comandos al ejecutar el script "Configure". Ver también "-f" en perlrun.

"Config.pm" ahora es mucho más pequeño

"Config.pm" ahora tiene unos 3 KB en lugar de 32 KB, con el código usado con poca frecuencia y los valores de %Config cargados bajo demanda. Esto es transparente para el programador, pero significa que la mayoría del código ahorrará el análisis y la carga de 29 KB de script (por ejemplo, código que usa "File::Find").

Cambios en Utilidades

mejoras de find2perl

"find2perl" tiene nuevas opciones "-iname", "-path" y "-ipath".

Mejoras de Rendimiento

El hash interno de mapeo de punteros utilizado durante la clonación de ithreads ahora utiliza una arena para la asignación de memoria. En pruebas, esto redujo el tiempo de clonación de ithreads en aproximadamente un 10%.

Mejoras en Instalación y Configuración

  • El archivo makefile.mk de Win32 "dmake" ha sido actualizado para hacerlo compatible con las últimas versiones de dmake.
  • "PERL_MALLOC", "DEBUG_MSTATS", "PERL_HASH_SEED_EXPLICIT" y "NO_HASH_SEED" ahora deberían funcionar en archivos make de Win32.

Corrección de Errores Seleccionados

  • La función socket() en Win32 ha sido corregida para poder usar proveedores de transporte que especifiquen un protocolo de 0 (lo que significa que se permite cualquier protocolo) una vez más. (Esto estaba roto en 5.8.6, y típicamente causaba que el uso de sockets ICMP fallara).
  • Otro error oscuro que involucraba "substr" y UTF-8, causado por un mal almacenamiento en caché de offsets internos, ha sido identificado y corregido.
  • Se ha corregido un error que implicaba la carga de tablas UTF-8 por el motor de expresiones regulares; el código como ""\x{100}" =~ /[[:print:]]/" ya no producirá resultados corruptos.
  • Las operaciones de conversión de mayúsculas/minúsculas como "uc" en una cadena Unicode larga podían agotar la memoria. Esto ha sido corregido.
  • "index"/"rindex" tenían errores para algunas combinaciones de datos Unicode y no Unicode. Esto ha sido corregido.
  • "read" (y presumiblemente "sysread") exponían los detalles internos de UTF-8 al leer desde un manejador de archivos orientado a bytes a un escalar UTF-8. Esto ha sido corregido.
  • Varias correcciones de errores en "pack"/"unpack":
  • Las sumas de verificación con formatos "b" o "B" estaban rotas.
  • Las sumas de verificación de "unpack" podían desbordarse con el formato "C".
  • "U0" y "C0" ahora están limitados a subplantillas de "pack" de "()".
  • Los prefijos de longitud contada ahora no cambian el modo "C0"/"U0".
  • "pack" "Z0" solía destruir el carácter precedente.
  • Los formatos de "pack" "P"/"p" solían reconocer solo "undef" literal.
  • Usar clausuras con ithreads podía causar que perl colgara. Esto se debió a un fallo al bloquear correctamente las estructuras OP internas y ha sido corregido.
  • El valor de retorno de "close" ahora refleja correctamente cualquier error de archivo que ocurra al vaciar los datos del manejador, en lugar de simplemente fallar si la operación subyacente real de cierre de archivo fallaba.
  • "not() || 1" solía causar un error de segmentación. not() ahora se comporta como not(0), que era el comportamiento anterior a 5.6.0.

perl587delta - Changes between perl 5.8.6 and 5.8.7

NAME

perl587delta - Changes between perl 5.8.6 and 5.8.7

DESCRIPTION

This document describes the changes between Perl 5.8.6 and Perl 5.8.7.

Incompatible Changes

None.

Core Enhancements

None.

Modules and Pragmata

None.

Utility Changes

None.

Performance Enhancements

None.

Installation and Configuration Improvements

None.

Selected Bug Fixes

  • "h2ph" has various enhancements to cope with constructs in header files that used to result in incorrect or invalid output.

New or Changed Diagnostics

There is a new taint error, "%ENV is aliased to %s". This error is thrown when taint checks are enabled and when *ENV has been aliased, so that %ENV has no env-magic anymore and hence the environment cannot be verified as taint-free.

The internals of "pack" and "unpack" have been updated. All legitimate templates should work as before, but there may be some changes in the error reported for complex failure cases. Any behaviour changes for non-error cases are bugs, and should be reported.

Changed Internals

There has been a fair amount of refactoring of the "C" source code, partly to make it tidier and more maintainable. The resulting object code and the "perl" binary may well be smaller than 5.8.6, and hopefully faster in some cases, but apart from this there should be no user-detectable changes.

"${^UTF8LOCALE}" has been added to give perl space access to "PL_utf8locale".

The size of the arenas used to allocate SV heads and most SV bodies can now be changed at compile time. The old size was 1008 bytes, the new default size is 4080 bytes.

Known Problems

Unicode strings returned from overloaded operators can be buggy. This is a long standing bug reported since 5.8.6 was released, but we do not yet have a suitable fix for it.

Platform Specific Problems

On UNICOS, lib/Math/BigInt/t/bigintc.t hangs burning CPU. ext/B/t/bytecode.t and ext/Socket/t/socketpair.t both fail tests. These are unlikely to be resolved, as our valiant UNICOS porter's last Cray is being decommissioned.

Reporting Bugs

If you find what you think is a bug, you might check the articles recently posted to the comp.lang.perl.misc newsgroup and the perl bug database at http://bugs.perl.org. There may also be information at http://www.perl.org, the Perl Home Page.

If you believe you have an unreported bug, please run the perlbug program included with your release. Be sure to trim your bug down to a tiny but sufficient test case. Your bug report, along with the output of "perl -V", will be sent off to perlbug@perl.org to be analysed by the Perl porting team. You can browse and search the Perl 5 bugs at http://bugs.perl.org/
