PERF-TRACE(1) Manual de perf PERF-TRACE(1)

NOMBRE

perf-trace - herramienta inspirada en strace

SINOPSIS

perf trace
perf trace record

DESCRIPCIÓN

Este comando mostrará los eventos asociados con el objetivo, inicialmente llamadas al sistema (syscalls), pero también otros eventos del sistema como pagefaults, eventos de vida de tareas, eventos de planificación, etc.

Esta es una herramienta de modo en vivo además de funcionar con archivos perf.data como las otras herramientas de perf. Los archivos se pueden generar usando el comando perf record, pero la sesión debe incluir los eventos raw_syscalls (-e raw_syscalls:*). Alternativamente, perf trace record se puede usar como un atajo para incluir automáticamente los eventos raw_syscalls al escribir eventos en un archivo.

Las siguientes opciones se aplican a perf trace; las opciones para perf trace record se encuentran en la página del manual de perf record.

OPCIONES

-a, --all-cpus

Recopilación en todo el sistema desde todas las CPU.

-e, --expr, --event

Lista de llamadas al sistema y otros eventos de perf (tracepoints, eventos de caché HW, etc.) a mostrar. Se admite el uso de comodines (globbing), por ejemplo: "epoll_*", "msg", etc. Consulte perf list para una lista completa de eventos. Prefijar con ! muestra todas las llamadas al sistema excepto las especificadas. Es posible que necesite escaparlas.

--filter=<filtro>

Filtro de eventos. Esta opción debe seguir a un selector de eventos (-e) que selecciona uno o más eventos de tracepoint.

-D msecs, --delay msecs

Después de iniciar el programa, espere msecs antes de medir. Esto es útil para filtrar la fase de inicio del programa, que a menudo es muy diferente.

-o, --output=

Nombre del archivo de salida.

-p, --pid=

Registrar eventos en un ID de proceso existente (lista separada por comas).

-t, --tid=

Registrar eventos en un ID de hilo existente (lista separada por comas).

-u, --uid=

Registrar eventos en hilos propiedad de uid. Nombre o número.

-G, --cgroup

Registrar eventos en hilos de un cgroup. 
Busque los cgroups para establecer en el directorio /sys/fs/cgroup/perf_event/, luego
elimine la parte /sys/fs/cgroup/perf_event/ e intente:
perf trace -G A -e sched:*switch
Configurará todas las raw_syscalls:sys_{enter,exit}, pgfault, vfs_getname, etc.
 _y_ sched:sched_switch al cgroup 'A', mientras que:
perf trace -e sched:*switch -G A
solo configurará el evento sched:sched_switch al cgroup 'A', todos los demás
eventos (raw_syscalls:sys_{enter,exit}, etc. se dejan "sin" un cgroup (en el
cgroup raíz, sys wide, etc.).
Múltiples cgroups:
perf trace -G A -e sched:*switch -G B
las llamadas al sistema irán al cgroup 'A', el sched:sched_switch irá
al cgroup 'B'.

--filter-pids=

Filtrar eventos para estos pids y para trace en sí mismo (lista separada por comas).

-v, --verbose

Aumentar el nivel de verbosidad.

--no-inherit

Las tareas hijas no heredan contadores.

-m, --mmap-pages=

Número de páginas de datos mmap (debe ser una potencia de dos) o especificación de tamaño en bytes con carácter de unidad appended - B/K/M/G. El tamaño se redondea al valor de página de potencia de dos más cercano.

-C, --cpu

Recopilar muestras solo en la lista de CPU proporcionadas. Se pueden proporcionar varias CPU como una lista separada por comas sin espacios: 0,1. Los rangos de CPU se especifican con -: 0-2. En modo por hilo con el modo de herencia activado (predeterminado), los eventos se capturan solo cuando el hilo se ejecuta en las CPU designadas. El valor predeterminado es monitorizar todas las CPU.

--duration

Mostrar solo eventos cuya duración sea superior a N.M ms.

--sched

Acumular el tiempo de ejecución del hilo y proporcionar un resumen al final de la sesión.

--failure

Mostrar solo las llamadas al sistema que fallaron, es decir, que devolvieron < 0.

-i, --input

Procesar eventos desde un archivo de datos perf dado.

-T, --time

Imprimir marca de tiempo completa en lugar del tiempo relativo a la primera muestra.

--comm

Mostrar COMM del proceso junto a su ID, activado por defecto, desactivar con --no-comm.

-s, --summary

Mostrar solo un resumen de las llamadas al sistema por hilo con tiempos mínimo, máximo y promedio (en msec) y desviación estándar relativa.

-S, --with-summary

Mostrar todas las llamadas al sistema seguidas de un resumen por hilo con tiempos mínimo, máximo y promedio (en msec) y desviación estándar relativa.

--errno-summary

Para ser utilizado con -s o -S, para mostrar estadísticas de los errnos experimentados por las llamadas al sistema, usar solo esta opción activará --summary.

--summary-mode=mode

Para ser utilizado con -s o -S, para seleccionar cómo mostrar el resumen. Por defecto mostrará el resumen de llamadas al sistema por hilo. Los valores posibles son: thread, total, cgroup.

--tool_stats

Mostrar estadísticas de la herramienta como el número de veces que se descubrió fd→pathname mediante la interceptación del retorno de la llamada al sistema open + vfs_getname o mediante la lectura de /proc/pid/fd, etc.

-f, --force

No te quejes, hazlo.

-F=[all|min|maj], --pf=[all|min|maj]

Rastrear pagefaults. Opcionalmente, puede especificar si desea pagefaults menores, mayores o todos. El valor predeterminado es maj.

--syscalls

Rastrear llamadas al sistema. Esta opción está activada por defecto, desactivar con --no-syscalls.

--call-graph [mode,type,min[,limit],order[,key][,branch]]

Configurar y habilitar la grabación del grafo de llamadas (cadena de pila/backtrace). Consulte la sección --call-graph en las páginas del manual de perf-record y perf-report para obtener detalles. Los más útiles en perf trace son dwarf y lbr, cuando estén disponibles, intente: perf trace --call-graph dwarf. 
Usar esto, para el usuario root, aumentará el valor de --mmap-pages a 4
veces el máximo para usuarios no root, basándose en el sysctl kernel.perf_event_mlock_kb.
Esto solo se hace si el usuario no especifica un valor para --mmap-pages.

--kernel-syscall-graph

Mostrar las cadenas de llamadas del kernel en la ruta de salida de la llamada al sistema.

--max-events=N

Detener después de procesar N eventos. Tenga en cuenta que los eventos tipo strace solo se consideran al salir o cuando una llamada al sistema se interrumpe, es decir, en esos casos, esta opción es equivalente al número de líneas impresas.

--switch-on EVENT_NAME

Considerar eventos solo después de que se encuentre este evento.

--switch-off EVENT_NAME

Dejar de considerar eventos después de que se encuentre este evento.

--show-on-off-events

Mostrar también los eventos --switch-on/off.

--max-stack

Establecer el límite de profundidad de la pila al analizar la cadena de llamadas, se ignorará todo lo que supere la profundidad especificada. Tenga en cuenta que en este punto solo se trata de la parte de presentación, es decir, el kernel aún no está limitando, la sobrecarga de las cadenas de llamadas debe establecerse a través de las configuraciones en --call-graph dwarf. 
Implica '--call-graph dwarf' cuando --call-graph no está presente en la
línea de comandos, en sistemas donde la resolución DWARF se incorporó en la compilación.
Predeterminado: /proc/sys/kernel/perf_event_max_stack cuando está presente para
         sesiones en vivo (sin --input/-i), 127 en caso contrario.

--min-stack

Establecer el límite de profundidad de la pila al analizar la cadena de llamadas, se ignorará todo lo que esté por debajo de la profundidad especificada. Deshabilitado por defecto. 
Implica '--call-graph dwarf' cuando --call-graph no está presente en la
línea de comandos, en sistemas donde la resolución DWARF se incorporó en la compilación.

--print-sample

Imprimir el PERF_RECORD_SAMPLE PERF_SAMPLE_ info para los tracepoints raw_syscalls:sys_{enter,exit}, para depuración.

--proc-map-timeout

Al procesar hilos preexistentes /proc/XXX/mmap, puede llevar mucho tiempo porque el archivo puede ser muy grande. Se necesita un tiempo de espera en tales casos. Esta opción establece el límite de tiempo de espera. El valor predeterminado es 500 ms.

--sort-events

Ordenar por lotes de eventos, usar cuando se observa lentitud
perf-trace(1) — perf Manual

NAME

perf-trace - Trace system calls and other events.

SYNOPSIS

perf trace [options] [command]

DESCRIPTION

This command is a frontend to perf_events and provides a strace-like interface for tracing system calls and other kernel events.

The basic usage is to run perf trace on a command line:

$ perf trace sleep 1

This will run the sleep command and trace all the system calls it makes. The output will look like:

1416.547 ( 0.000 ms): sleep/1416 openat(dfd: CWD, filename: /etc/ld.so.cache, flags: O_RDONLY|O_CLOEXEC) = 3

The output format is:

<timestamp> (<duration ms>): <process name>/<pid> <syscall name>(<arguments>) = <return value>

The timestamp and duration are in seconds and milliseconds, respectively. The process name and PID are also shown.

The arguments are shown in a human-readable format. For example, file paths are shown as strings, flags are shown as symbolic names (e.g. O_RDONLY), and integers are shown as decimal numbers.

The return value of the system call is also shown.

See perf-record(1) for a full list of options and event specification. The event specification part is similar to perf trace, perf record, perf stat.

OPTIONS

The following options are available:

--no-syscalls

Do not trace syscalls. Used to trace other events like pagefaults.

-F, --faults

Trace pagefault events.

-e <events>

Trace specific events. See perf_events(5) for syntax. List of available events can be seen with `perf list`. Events can be specified like `syscalls:sys_enter_*`, `sched:*`, `*fault*`. Use `perf trace -e 'breakpt*' ...` to trace breakpoint events, `perf trace -e 'hw*' ...` to trace hardware events, `perf trace -e 'syscalls:*'` to trace all syscalls.

-s, --summary

Display system call statistics instead of individual events.

--summary-only

Do not display individual events, only the final summary.

-m, --max-events <N>

Exit after processing N events.

-p, --pid <pid>

Trace events for the given PID only.

-t, --tid <tid>

Trace events for the given TID only.

-f, --foreground

Run in foreground (default).

-o, --output <file>

Write output to file instead of stderr.

-i, --input <file>

Read trace data from file.

-a, --all-cpus

Trace all CPUs.

-C, --cpu <cpu list>

Trace specified CPUs only.

--call-graph <type>

Enable call graph (stack trace) recording. Supported types are dwarf, fp, and perfecting.

--max-stack <depth>

Maximum depth of stack trace.

--no-children

Do not trace child threads/processes.

--filter <filter spec>

Filter events based on systemtap-style filter rules.

--libtraceevent_print

Use libtraceevent to print tracepoint arguments. By default perf trace uses the same beautifiers used in the strace-like enter+exit lines to augment the tracepoint arguments.

--force-btf

Use btf_dump to pretty print syscall argument data, instead of using hand-crafted pretty printers. This option is intended for testing BTF integration in perf trace. btf_dump-based pretty-printing serves as a fallback to hand-crafted pretty printers, as the latter can better pretty-print integer flags and struct pointers.

--bpf-summary

Collect system call statistics in BPF. This is only for live mode and works well with -s/--summary option where no argument information is required.

PAGEFAULTS

When tracing pagefaults, the format of the trace is as follows:

<min|maj>fault [<ip.symbol>+<ip.offset>] ⇒ <addr.dso@addr.offset[1]> (<map type><addr level>).

•min/maj indicates whether fault event is minor or major;
•ip.symbol shows symbol for instruction pointer (the code that generated the fault); if no debug symbols available, perf trace will print raw IP;
•addr.dso shows DSO for the faulted address;
•map type is either d for non-executable maps or x for executable maps;
•addr level is either k for kernel dso or . for user dso.

For symbols resolution you may need to install debugging symbols.

Please be aware that duration is currently always 0 and doesn’t reflect actual time it took for fault to be handled!

When --verbose specified, perf trace tries to print all available information for both IP and fault address in the form of dso@symbol[2]+offset.

EXAMPLES

Trace only major pagefaults:

$ perf trace --no-syscalls -F

Trace syscalls, major and minor pagefaults:

$ perf trace -F all
1416.547 ( 0.000 ms): python/20235 majfault [CRYPTO_push_info_+0x0] => /lib/x86_64-linux-gnu/libcrypto.so.1.0.0@0x61be0 (x.)
As you can see, there was major pagefault in python process, from
CRYPTO_push_info_ routine which faulted somewhere in libcrypto.so.
