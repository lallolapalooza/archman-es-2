NOMBRE

perf-inject - Filtro para aumentar el flujo de eventos con información adicional

SINOPSIS

perf inject <opciones>

DESCRIPCIÓN

perf-inject lee un flujo de eventos de perf-record y lo redirige a la salida estándar. En cualquier momento, el código de procesamiento puede inyectar otros eventos en el flujo de eventos; en este caso, se leen los ID de compilación (opción -b) y se inyectan según sea necesario en el flujo de eventos.

Los ID de compilación son solo el primer uso de perf-inject; potencialmente, cualquier cosa que necesite procesamiento en el espacio de usuario para aumentar el flujo de eventos con información adicional podría hacer uso de esta instalación.

OPCIONES

-b, --build-ids

Inyecta ID de compilación de los DSO golpeados por las muestras en el flujo de salida. Esto significa que necesita procesar todos los registros de MUESTRA para encontrar los DSO.

--buildid-all

Inyecta ID de compilación de todos los DSO en el flujo de salida independientemente de los golpes y omite el procesamiento de MUESTRA.

--known-build-ids=

Reemplaza los ID de compilación a inyectar usando estos pares de ID de compilación y ruta separados por comas. Entiende file://filename para leer estos pares de un archivo, que puede ser generado con perf buildid-list.

-v, --verbose

Sea más verboso.

-i, --input=

Nombre del archivo de entrada. (por defecto: stdin)

-o, --output=

Nombre del archivo de salida. (por defecto: stdout)

-s, --sched-stat

Fusiona sched_stat y sched_switch para obtener eventos de dónde y cuánto tiempo durmieron las tareas. sched_switch contiene una cadena de llamadas donde una tarea durmió y sched_stat contiene una serie temporal de cuánto tiempo durmió una tarea.

-k, --vmlinux=<archivo>

Ruta del archivo vmlinux

--ignore-vmlinux

Ignorar archivos vmlinux.

--kallsyms=<archivo>

Ruta del archivo kallsyms

--itrace

Decodifica los datos de rastreo de instrucciones, reemplazándolos con eventos sintetizados. Las opciones son: 
i       sintetiza eventos de instrucciones
y       sintetiza eventos de ciclos
b       sintetiza eventos de saltos
c       sintetiza eventos de saltos (solo llamadas)
r       sintetiza eventos de saltos (solo retornos)
x       sintetiza eventos de transacciones
w       sintetiza eventos ptwrite
p       sintetiza eventos de energía (incl. eventos PSB para Intel PT)
o       sintetiza otros eventos registrados debido al uso
        de aux-output (consultar perf record)
I       sintetiza eventos de interrupción o similares (asíncronos)
        (por ejemplo, Intel PT Event Trace)
e       sintetiza eventos de error
d       crea un registro de depuración
f       sintetiza eventos de caché de primer nivel
m       sintetiza eventos de caché de último nivel
M       sintetiza eventos de memoria
t       sintetiza eventos de TLB
a       sintetiza eventos de acceso remoto
g       sintetiza una cadena de llamadas (usar con i o x)
G       sintetiza una cadena de llamadas en registros de eventos existentes
l       sintetiza entradas de última rama (usar con i o x)
L       sintetiza entradas de última rama en registros de eventos existentes
s       omite un número inicial de eventos
q       decodificación más rápida (menos detallada)
A       IPC aproximado
Z       preferir ignorar marcas de tiempo (decodificación "sin tiempo"
        denominada así)
El valor por defecto es todos los eventos, es decir, lo mismo que --itrace=iybxwpe,
excepto para perf script donde es --itrace=ce
Además, el período (por defecto 100000, excepto para perf script donde es 1)
para los eventos de instrucciones se puede especificar en unidades de:
i       instrucciones
t       ticks
ms      milisegundos
us      microsegundos
ns      nanosegundos (por defecto)
También se puede especificar el tamaño de la cadena de llamadas (por defecto 16, máx. 1024) para los eventos de instrucciones o transacciones.
También se puede especificar el número de entradas de última rama (por defecto 64, máx. 1024) para los eventos de instrucciones o transacciones.
Similar a las opciones g y l, el tamaño también se puede especificar para las opciones G y L.
En x86, tenga en cuenta que G y L funcionan mal cuando los datos se han registrado con
PEBS grandes. Consulte la página del manual de linkperf:perf-intel-pt[1] para obtener detalles.
También es posible omitir los eventos generados (instrucciones, saltos, transacciones,
ptwrite, energía) al principio. Esto es útil para ignorar el código de inicialización.
--itrace=i0nss1000000
omite el primer millón de instrucciones.
La opción 'e' puede ir seguida de indicadores que afectan cuáles errores se informarán o no. Cada indicador debe ir precedido de '+' o '-'.
Los indicadores son:
        o       desbordamiento
        l       datos de rastreo perdidos
Si es compatible, la opción 'd' puede ir seguida de indicadores que afectan qué
mensajes de depuración se registrarán o no. Cada indicador debe ir precedido
por '+' o '-'. Los indicadores son:
        a       todos los eventos perf
        e       salida solo en errores (tamaño configurable - consulte linkperf:perf-config[1])
        o       salida a stdout
Si es compatible, la opción 'q' se puede repetir para aumentar el efecto.

--strip

Usar con --itrace para eliminar eventos no sintetizados.

-j, --jit

Procesa archivos jitdump inyectando los registros mmap correspondientes a funciones jitteadas. Esta opción también genera las imágenes ELF para cada función jitteada encontrada en los archivos jitdumps capturados en el archivo perf.data de entrada. Utilice esta opción si está monitorizando entornos que utilizan tiempos de ejecución JIT, como Java, DART o V8.

-f, --force

No te quejes, hazlo.

--vm-time-correlation[=OPCIONES]

Algunas arquitecturas pueden capturar datos del área AUX que contienen marcas de tiempo afectadas por la virtualización. Esta opción actualizará esas marcas de tiempo en el lugar, para correlacionarlas con las marcas de tiempo del host. La actualización en el lugar significa que no se especifica un archivo de salida, sino que se modifica el archivo de entrada. Las opciones son específicas de la arquitectura, excepto que pueden comenzar con "dry-run", lo que hará que el archivo se procese pero sin actualizarlo. Actualmente, esta opción solo es compatible con Intel PT, consulte perf-intel-pt(1)

--guest-data=<ruta>,<pid>[,<desplazamiento de tiempo [,<escala de tiempo>]]

Inserta eventos de un archivo perf.data grabado en una máquina virtual al mismo tiempo que se grabó el archivo perf.data de entrada en el host. Se debe proporcionar el ID de proceso (PID) del proceso hipervisor QEMU, y es probable que se necesiten el desplazamiento de tiempo y la escala de tiempo (multiplicador) para convertir las marcas de tiempo del invitado en marcas de tiempo del host. Por ejemplo, para x86, se pueden proporcionar el Desplazamiento y Multiplicador de TSC para una máquina virtual que utiliza la opción de línea de comandos de Linux no-kvmclock. Actualmente, solo se insertan eventos mmap, mmap2, comm, task, context_switch, ksymbol y text_poke, así como información de ID de compilación. La opción QEMU -name debug-threads=on es necesaria para que los nombres de los hilos puedan usarse para determinar qué hilo está ejecutando qué VCPU. Tenga en cuenta que libvirt parece usar esto por defecto. Al usar perf record en el invitado, se debe usar la opción --sample-identifier, y también pueden ser útiles --buildid-all y --switch-events.

--guestmount=<ruta>

Directorio de montaje del sistema de archivos raíz del sistema operativo invitado. Los usuarios montan los directorios raíz del sistema operativo invitado bajo <ruta> mediante un método de acceso específico al sistema de archivos, típicamente, sshfs. Por ejemplo, inicie 2 sistemas operativos invitados, uno cuyo PID es 8888 y el otro cuyo PID es 9999: 
$ mkdir ~/guestmount
$ cd ~/guestmount
$ sshfs -o allow_other,direct_io -p 5551 localhost:/ 8888/
$ sshfs -o allow_other,direct_io -p 5552 localhost:/ 9999/
$ perf inject --guestmount=~/guestmount
