NOMBRE

perf-kvm - Herramienta para trazar/medir el sistema operativo invitado de KVM

SINOPSIS

perf kvm [--host] [--guest] [--guestmount=<ruta>
        [--guestkallsyms=<ruta> --guestmodules=<ruta> | --guestvmlinux=<ruta>]]
        {top|record|report|diff|buildid-list} [<opciones>]
perf kvm [--host] [--guest] [--guestkallsyms=<ruta> --guestmodules=<ruta>
        | --guestvmlinux=<ruta>] {top|record|report|diff|buildid-list|stat} [<opciones>]
'perf kvm stat [record|report|live] [<opciones>]

DESCRIPCIÓN

Hay un par de variantes de perf kvm:

'perf kvm [opciones] top <comando>' para generar y mostrar
un perfil de contador de rendimiento del sistema operativo invitado en tiempo real
de una carga de trabajo arbitraria.
'perf kvm record <comando>' para grabar el perfil de contador de rendimiento
de una carga de trabajo arbitraria y guardarlo en un archivo de datos de perf. Establecemos
el comportamiento predeterminado de perf kvm como --guest, por lo que si no se introduce
ni --host ni --guest, el nombre del archivo de datos de perf es perf.data.guest. Si se introduce
--host, el nombre del archivo de datos de perf es perf.data.kvm. Si desea grabar datos en
perf.data.host, introduzca --host --no-guest. Los comportamientos se muestran como
siguen:
  Predeterminado('')         ->  perf.data.guest
  --host              ->  perf.data.kvm
  --guest             ->  perf.data.guest
  --host --guest      ->  perf.data.kvm
  --host --no-guest   ->  perf.data.host
'perf kvm report' para mostrar la información del perfil de contador de rendimiento
grabada con perf kvm record.
'perf kvm diff' para mostrar la diferencia de rendimiento entre dos archivos perf.data
capturados con perf record.
'perf kvm buildid-list' para mostrar los buildids encontrados en un archivo de datos de perf,
para que otras herramientas puedan ser utilizadas para obtener paquetes con tablas de símbolos coincidentes
para su uso por perf report. Como el buildid se lee de /sys/kernel/notes en el sistema operativo,
entonces si desea listar el buildid para el invitado, asegúrese de que su archivo de datos de perf
fue capturado con --guestmount en perf kvm record.
'perf kvm stat <comando>' para ejecutar un comando y recopilar estadísticas de contadores de rendimiento.
Especialmente, perf 'kvm stat record/report' genera un análisis estadístico
de eventos KVM. Actualmente, se admiten los eventos vmexit, mmio (solo x86) e ioport (solo x86).
'perf kvm stat record <comando>' graba eventos kvm y los eventos entre el inicio y el fin de <comando>.
Y este comando produce un archivo que contiene resultados de rastreo de eventos kvm.
'perf kvm stat report' informa datos estadísticos que incluyen eventos
manejados muestra, muestra_porcentual, tiempo, tiempo_porcentual, max_t, min_t, mean_t.
'perf kvm stat live' informa datos estadísticos en modo en vivo (similar a
record + report pero con datos estadísticos actualizados en vivo a una tasa de visualización dada).

OPCIONES

-i, --input=<ruta>

Nombre del archivo de entrada, para los subcomandos report, diff y buildid-list.

-o, --output=<ruta>

Nombre del archivo de salida, para el subcomando record. No funciona con report, simplemente redirija la salida a un archivo al usar report.

--host

Recopilar perfil de rendimiento del lado del host.

--guest

Recopilar perfil de rendimiento del lado del invitado.

--guestmount=<ruta>

Directorio de montaje del sistema de archivos raíz del sistema operativo invitado. Los usuarios montan directorios raíz del sistema operativo invitado bajo <ruta> mediante un método de acceso al sistema de archivos específico, típicamente, sshfs. Por ejemplo, inicie 2 sistemas operativos invitados, uno cuyo PID es 8888 y el otro es 9999: 
$ mkdir ~/guestmount
$ cd ~/guestmount
$ sshfs -o allow_other,direct_io -p 5551 localhost:/ 8888/
$ sshfs -o allow_other,direct_io -p 5552 localhost:/ 9999/
$ perf kvm --host --guest --guestmount=~/guestmount top

--guestkallsyms=<ruta>

Copia del archivo /proc/kallsyms del sistema operativo invitado. perf lo lee para obtener símbolos del kernel del invitado. Los usuarios lo copian desde el sistema operativo invitado.

--guestmodules=<ruta>

Copia del archivo /proc/modules del sistema operativo invitado. perf lo lee para obtener información de módulos del kernel del invitado. Los usuarios lo copian desde el sistema operativo invitado.

--guestvmlinux=<ruta>

Kernel vmlinux del sistema operativo invitado.

--guest-code

Indica que el código del invitado se puede encontrar en el proceso hipervisor, que es un caso común para los programas de prueba de KVM.

--stdio

Utilice la interfaz stdio.

-v, --verbose

Sea más detallado (muestre errores de apertura de contador, etc).

OPCIONES DE STAT REPORT

--vcpu=<valor>

analizar eventos que ocurren en este vcpu. (predeterminado: todos los vcpu)

--event=<valor>

evento a analizar. Valores posibles: vmexit, mmio (solo x86), ioport (solo x86). (predeterminado: vmexit)

-k, --key=<valor>

Clave de ordenación. Valores posibles: sample (predeterminado, ordenar por número de muestras), percent_sample (ordenar por porcentaje de muestras), time (ordenar por tiempo promedio), precent_time (ordenar por porcentaje de tiempo), max_t (ordenar por tiempo máximo), min_t (ordenar por tiempo mínimo), mean_t (ordenar por tiempo medio).

-p, --pid=

Analizar eventos solo para los ID de proceso dados (lista separada por comas).

OPCIONES DE STAT LIVE

-d, --display

Tiempo en segundos entre actualizaciones de pantalla

-m, --mmap-pages=

Número de páginas de datos mmap (debe ser una potencia de dos) o especificación de tamaño en bytes con carácter de unidad appended - B/K/M/G. El tamaño se redondea al valor de página de potencia de dos más cercano.

-a, --all-cpus

Recopilación en todo el sistema de todas las CPU.

-p, --pid=

Analizar eventos solo para los ID de proceso dados (lista separada por comas).

--vcpu=<valor>

analizar eventos que ocurren en este vcpu. (predeterminado: todos los vcpu)

--event=<valor>

evento a analizar. Valores posibles: vmexit, mmio (solo x86), ioport (solo x86). (predeterminado: vmexit)

-k, --key=<valor>

Clave de ordenación. Valores posibles: sample (predeterminado, ordenar por número de muestras), time (ordenar por tiempo promedio).

--duration=<valor>

Mostrar eventos distintos de HLT (solo x86) o estado de espera (solo s390) que toman más de duration microsegundos.

--proc-map-timeout

Al procesar hilos preexistentes /proc/XXX/mmap, puede llevar mucho tiempo, porque el archivo puede ser enorme. Se necesita un tiempo de espera en tales casos. Esta opción establece el límite de tiempo de espera. El valor predeterminado es 500 ms.

VER TAMBIÉN

perf-top(1), perf-record(1), perf-report(1), perf-diff(1), perf-buildid-list(1), perf-stat(1)

NAME

perf-kvm - performance analysis tool for KVM

SYNOPSIS

perf kvm [options]

DESCRIPTION

The perf kvm command is a specialized tool within the Linux perf framework designed to analyze and profile the performance of KVM (Kernel-based Virtual Machine) guests and hosts. It allows users to gather detailed performance metrics related to virtual machine execution, such as CPU cycles, cache misses, branch predictions, and more, both within the guest and at the host level.

OPTIONS

The perf kvm command supports various options to control the data collection and reporting. These options can be broadly categorized:

STAT REPORT OPTIONS

These options are used when generating a static report of collected performance data.

  • --include-kernel: Include kernel events in the report.
  • --include-user: Include user-space events in the report.
  • --event <event>: Specify the performance event(s) to collect. Can be a hardware event (e.g., cycles, instructions), a tracepoint (e.g., kvm:kvm_entry), or a software event (e.g., cpu-migrations).
  • --output <file>: Write the report to the specified file.
  • --vmlinux <file>: Specify the path to the vmlinux file for symbol resolution.

STAT LIVE OPTIONS

These options are used for live performance monitoring.

  • --duration <seconds>: Run the live monitoring for the specified duration.
  • --top: Display performance data in a top-like interface.
  • --call-graph dwarf: Enable call graph tracing using DWARF information.
  • --filter <filter>: Apply a filter to the collected events (e.g., pid=123, comm=my_process).
