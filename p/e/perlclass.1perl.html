PERLCLASS(1perl) Guía de Referencia para Programadores de Perl PERLCLASS(1perl)

NOMBRE

perlclass - Referencia de sintaxis de clases de Perl

SINOPSIS

use v5.38;
use feature 'class';
class My::Example 1.234 {
    field $x;
    ADJUST {
        $x = "Hola, mundo";
    }
    method print_message {
        say $x;
    }
}
My::Example->new->print_message;

DESCRIPCIÓN

Este documento describe la sintaxis de la característica "class" de Perl, que proporciona palabras clave nativas para la programación orientada a objetos.

Historia

Desde Perl 5, el soporte para objetos giraba en torno al concepto de bendecir referencias con un nombre de paquete (ver "bless REF,CLASSNAME" en perlfunc). Dicha referencia podía usarse luego para llamar subrutinas del paquete con el que fue bendecida (o cualquiera de sus padres). Este sistema, aunque básico, era lo suficientemente flexible como para permitir la creación de múltiples sistemas más avanzados y dirigidos por la comunidad para la orientación a objetos. Para más información, ver perlmod y perlobj.

La característica "class" es una implementación central de una sintaxis de clase similar a la que se encontraría en otros lenguajes de programación. No es una envoltura alrededor de "bless", sino un sistema completamente nuevo incorporado directamente en el intérprete de perl.

PALABRAS CLAVE

Habilitar la característica "class" permite el uso de las siguientes nuevas palabras clave en el ámbito léxico actual:

class

class NOMBRE BLOQUE
class NOMBRE VERSIÓN BLOQUE
class NOMBRE VERSIÓN : ATRIBUTOS... BLOQUE
class NOMBRE;
class NOMBRE VERSIÓN;
class NOMBRE VERSIÓN : ATRIBUTOS...;

La palabra clave "class" declara un nuevo paquete (ver "Packages" en perlmod) que está destinado a ser una clase. Todas las demás palabras clave de la característica "class" deben usarse dentro del ámbito de esta declaración.

class WithVersion 1.000 {
    # la definición de clase va aquí
}

Las clases pueden declararse en sintaxis de bloque o de sentencia. Si se usa un bloque, el cuerpo del bloque contiene la implementación de la clase. Si se usa la forma de sentencia, el resto del ámbito actual o del archivo se utiliza hasta la próxima declaración "class" o "package".

Una declaración de "class" opcionalmente puede tener un número de versión, similar a la palabra clave "package". También puede tener atributos opcionalmente. Si se especifican ambos, el número de versión debe ir primero, antes de los atributos.

"class" y "package" son declaraciones similares, pero las clases obtienen automáticamente un constructor llamado "new"; no tienes que (y no deberías) escribir uno. Además, en el BLOQUE de clase se te permite declarar campos y métodos.

field

field NOMBRE_VARIABLE;
field NOMBRE_VARIABLE = EXPR;
field NOMBRE_VARIABLE : ATRIBUTOS;
field NOMBRE_VARIABLE : ATRIBUTOS = EXPR;

Los campos son variables que son visibles en el ámbito de la clase, más específicamente dentro de los bloques "method" y ADJUST. Cada instancia de clase obtiene su propio almacenamiento de campos, independiente de otras instancias.

Un campo se comporta como una variable de ámbito léxico normal. Tiene un sigilo y es privado para la clase (aunque la creación de un método accesor lo hará accesible desde el exterior). La principal diferencia es que diferentes instancias acceden a diferentes valores en el mismo ámbito.

class WithFields {
    field $scalar = 42;
    field @array  = qw(esta es solo un array);
    field %hash   = (especie => 'Marciano', planeta => 'Marte');
}

Los campos opcionalmente pueden tener expresiones de inicialización. Si están presentes, la expresión se evaluará dentro del constructor de cada instancia de objeto. Durante cada evaluación, la expresión puede usar el valor de cualquier campo configurado previamente, así como cualquier otra variable en el ámbito.

class WithACounter {
    my $next_count = 1;
    field $count = $next_count++;
}

Cuando se combina con el atributo de campo ":param", la expresión de valor predeterminado puede usar cualquiera de los operadores "=", "//=" o "||=". Las expresiones que usan "=" se aplicarán siempre que el llamador no haya pasado el parámetro correspondiente al constructor en absoluto. Las expresiones que usan "//=" también se aplicarán si el llamador pasó el parámetro pero el valor era indefinido, y las expresiones que usan "||=" se aplicarán si el valor era falso.

Durante una expresión de inicialización de campo, la instancia aún no se ha construido y, por lo tanto, el léxico $self no está disponible. Sin embargo, el token especial "__CLASS__" puede usarse para obtener el nombre de la clase que se está construyendo, por ejemplo, para invocar métodos de clase sobre ella para ayudar en la construcción de valores para los campos.

class WithCustomField {
    use constant DEFAULT_X => 10;
    field $x = __CLASS__->DEFAULT_X;
}

Esto permite que las subclases anulen el método con un comportamiento diferente.

class DifferentCustomField :isa(WithCustomField) {
    sub DEFAULT_X { rand > 0.5 ? 20 : 30 }
}

Cuando se construye una instancia de "DifferentCustomField", la expresión "__CLASS__" en la base generará el nombre correcto de la clase y, por lo tanto, invocará este método anulado en su lugar.

method

method NOMBRE_METODO FIRMA BLOQUE
method NOMBRE_METODO BLOQUE
method FIRMA BLOQUE
method BLOQUE

Los métodos son subrutinas destinadas a ser llamadas en el contexto de objetos de clase.

Una variable llamada $self, poblada con la instancia del objeto actual, se creará automáticamente en el ámbito léxico de "method".

Los métodos actúan siempre como si "use feature 'signatures'" estuviera activo, pero $self no aparecerá en la lista de argumentos en lo que respecta a la firma.

class WithMethods {
    field $greetings;
    ADJUST {
        $greetings = "Hola";
    }
    method greet($name = "alguien") {
        say "$greetings, $name";
    }
}

Al igual que las subrutinas regulares, los métodos pueden ser anónimos:

class AnonMethodFactory {
    method get_anon_method {
        return method {
            return 'este es un método anónimo';
        };
    }
}

Los métodos también pueden declararse como subrutinas léxicas, usando el prefijo "my". Esto crea una subrutina que es léxicamente visible dentro del ámbito actual, pero no aparece en la tabla de símbolos. El efecto es el de un método *privado*; uno que puede ser llamado desde el código de la clase, pero no desde fuera.

Para invocar estas subrutinas léxicas como métodos, es mejor usar el operador "->&". Esto evita la búsqueda de métodos por nombre e invoca directamente una subrutina léxica como si fuera un método.

class LexicalMethod {
    my method abc ($x, $y) {
        say "Método interno abc invocado con x=$x y=$y";
    }
    method xyz {
        $self->&abc("x", "y");
    }
}
# El método `abc` no es visible desde aquí

ATRIBUTOS

Aspectos específicos de las palabras clave mencionadas anteriormente se gestionan mediante *atributos*. Todos los atributos comienzan con dos puntos y uno o más de ellos pueden añadirse después del nombre del elemento, separados por un espacio.

Atributos de clase

:isa

Las clases pueden heredar de **una** superclase, utilizando el atributo de clase ":isa".

class Example::Base { ... }
class Example::Subclass :isa(Example::Base) { ... }

ATTRIBUTES

Attributes are key/value pairs that can be attached to class definitions, fields, and methods. They are declared using the ":" prefix, followed by the attribute name. Attributes can accept arguments, which are specified in parentheses.

Class attributes

:isa

The ":isa" attribute specifies a base class for the current class. The class being defined inherits from the specified base class. This is equivalent to using "use base" in older Perl OO systems. The specified base class will be loaded automatically if it is not already loaded.

class Example::Subclass :isa(Example::Base) { ... }

You can specify multiple base classes by listing them, comma-separated, within the parentheses:

class Example::Subclass :isa(Example::Base, Other::Base) { ... }

The ":isa" attribute may request a minimum version of the base class. As with "use MODULE VERSION", if the actual version of the base class is too low, compilation will fail.

class Example::Subclass :isa(Example::Base 2.345) { ... }

The ":isa" attribute will attempt to "require" the named module if it is not already loaded.

Field attributes

:param

A scalar field with a ":param" attribute will take its value from a named parameter passed to the constructor. By default the parameter will have the same name as the field (minus its leading "$" sigil), but a different name can be specified in the attribute.

field $x :param;
field $y :param(the_y_value);

If there is no defaulting expression, then the parameter is required by the constructor; the caller must pass it or an exception is thrown. With a defaulting expression this becomes optional.

:reader

A field with a ":reader" attribute will generate a reader accessor method automatically. The generated method will have an empty (i.e. zero-argument) signature, and its body will simply return the value of the field variable.

field $s :reader;
# Equivalent to
field $s;
method s () { return $s; }

By default the accessor method will have the same name as the field (minus the leading sigil), but a different name can be specified in the attribute's value.

field $x :reader(get_x);
# Generates a method
method get_x () { return $x; }

Reader methods can be applied to non-scalar fields. When invoked in list context, they yield the contents of the field; in scalar context they yield the count of elements, as if the field variable had been placed in scalar context.

field @users :reader;
...
scalar $instance->users;

:writer

A field with a ":writer" attribute will generate a writer accessor method automatically. The generated method will have a signature that consumes exactly one argument, and its body will assign that scalar argument to the field and return the invocant object itself.

field $s :writer;
# Equivalent to
field $s;
method set_s($new) { $s = $new; return $self; }

By default the accessor method will have the name of the field minus the leading sigil with the string "set_" prefixed to it, but a different name can be specified in the attribute's value.

field $x :writer(write_x);
# Generates a method
method write_x ($new) { ... }

Currently, writer accessors can only be applied to scalar fields. Attempts to apply this attribute to a non-scalar field will result in a fatal exception at compile-time. This may be relaxed in a future version to allow writers on array or hash fields. For now, these will have to be created manually.

Method attributes

None yet.

OBJECT LIFECYCLE

Construction

Each object begins its life with a constructor call. The constructor is always named "new" and is invoked like a method call on the class name:

my $object = My::Class->new(%arguments);

During object construction, class fields are looked up in the %arguments hash and populated where possible.

Adjustment

Object adjustment is a way to run arbitrary user-defined code during object construction. This is done by placing code in "ADJUST" blocks. Every time an object is constructed, its "ADJUST" blocks are executed (in the order in which they are declared).

class WellAdjusted {
    field $x :param;
    ADJUST {
        say "Hello!";
    }
    ADJUST {
        say "x = $x";
    }
}
my $object = WellAdjusted->new(x => 42);
# Output:
#   Hello!
#   x = 42

"ADJUST" blocks are syntactically similar to "BEGIN" or "INIT" blocks, which only run once. However, "ADJUST" blocks, like methods, have access to $self (a lexical variable holding the object being constructed) as well as all object fields created up to that point.

Lifetime

After the construction phase, the object is ready to be used.

Using "blessed" ("Scalar::Util::blessed" or "builtin::blessed") on the object will return the name of the class, while "reftype" ("Scalar::Util::reftype" or "builtin::reftype") will return the string 'OBJECT'.

Destruction

An object is destroyed when the last reference to it goes away, just as with other data structures in Perl.

TODO

This feature is still experimental and very incomplete. The following list gives an overview of features still to be added or changed:

  • Roles

    Some syntax for declaring a role (likely a "role" keyword), and for consuming a role into a class (likely a :does() attribute).

  • Parameters to ADJUST blocks

    Some syntax for declaring that an "ADJUST" block can consume named parameters, which become part of the class constructor's API. This might be inspired by a similar plan to add named arguments to subroutine signatures.

    class X {
    ADJUST (:$alpha, :$beta = 123) {
       ...
    }
}
my $obj = X->new(alpha => 456);
  • ADJUST blocks as true blocks

    Currently, every ADJUST block is wrapped in its own CV (subroutine) that gets invoked with the full ENTERSUB overhead. It should be possible to use the same mechanism that makes all field initializer expressions appear within the same CV on ADJUST blocks as well, merging them all into a single CV per class. This will make it faster to invoke if a class has more than one of them.

  • More accessor generator attributes

    Attributes to request that other kinds of accessor methods be generated for fields. Likely ":writer".

    class X {
    field $name :writer;
}

    Equivalent to

    class X {
    field $name;
    method set_name ($new) { $name = $new; return $self; }
}
  • Metaprogramming

    An extension of the metaprogramming API (currently proposed by PPC0022 https://github.com/Perl/PPCs/pull/25) which adds knowledge of classes, methods, fields, ADJUST blocks, and other such class-related details.

  • Extension Customisation

    Ways in which out-of-core modules can interact with the class system, including an ability for them to provide new class or field attributes.

KNOWN BUGS

The following bugs have been found in the experimental "class" feature:

  • Since Perl v5.38, inheriting from a parent class which is declared in the same file and which hadn't already been sealed can cause a segmentation fault. [GH #20890 https://github.com/Perl/perl5/issues/20890]
  • Since Perl v5.38 and with the experimental "refaliasing" feature, trying to replace a field variable causes a segmentation fault. [GH #20947 https://github.com/Perl/perl5/issues/20947]
  • Since Perl v5.38, it's possible to craft a class with leaky encapsulation, which can cause a segmentation fault. [GH #20956 https://github.com/Perl/perl5/issues/20956]
  • In Perl v5.38, inheriting from a class would not always attempt to load the parent class (fixed in Perl v5.40). [GH #21332 https://github.com/Perl/perl5/issues/21332]
