NOMBRE

perl5125delta - qué hay de nuevo para la versión perl v5.12.5

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.12.4 y la versión 5.12.5.

Si está actualizando desde una versión anterior como la 5.12.3, primero lea perl5124delta, que describe las diferencias entre 5.12.3 y 5.12.4.

Seguridad

"Encode" decode_xs n-byte heap-overflow (CVE-2011-2939)

Un error en "Encode" podría, con ciertas entradas, causar un desbordamiento del montón. Este problema ha sido corregido. Informe de error de Robert Zacek.

File::Glob::bsd_glob() memory error with GLOB_ALTDIRFUNC (CVE-2011-2728)

Llamar a "File::Glob::bsd_glob" con la bandera no soportada GLOB_ALTDIRFUNC causaría una violación de acceso / segfault. Un programa Perl que acepte un valor de banderas de una fuente externa podría exponerse a ataques de denegación de servicio o de ejecución de código arbitrario. No se conocen exploits en la naturaleza. El problema ha sido corregido deshabilitando explícitamente todas las banderas no soportadas y estableciendo los punteros de función no utilizados a nulo. Informe de error de Clément Lecigne.

Heap buffer overrun in 'x' string repeat operator (CVE-2012-5195)

Código Perl mal escrito que permite a un atacante especificar el contador para el operador de repetición de cadenas 'x' de Perl ya puede causar un ataque de denegación de servicio por agotamiento de memoria. Un fallo en las versiones de Perl anteriores a la 5.15.5 puede escalar eso a un desbordamiento de búfer en el montón; acoplado con versiones de glibc anteriores a la 2.16, posiblemente permite la ejecución de código arbitrario.

Este problema ha sido solucionado.

Cambios incompatibles

No hay cambios intencionalmente incompatibles con la versión 5.12.4. Si existen, son errores y se agradecen los informes.

Módulos y pragmas

Módulos actualizados

B::Concise

B::Concise ya no produce salida corrupta con la opción -tree [perl #80632].

charnames

Se ha corregido una regresión introducida en Perl 5.8.8, que causaba que charnames::viacode(0) devolviera "undef" en lugar de la cadena "NULL" [perl #72624].

Encode se ha actualizado de la versión 2.39 a la versión 2.39_01

Ver "Seguridad".

File::Glob se ha actualizado de la versión 1.07 a la versión 1.07_01

Ver "Seguridad".

Unicode::UCD

La documentación de la función "upper" ahora dice realmente "upper", no "lower".

Module::CoreList

Module::CoreList se ha actualizado a la versión 2.50_02 para agregar datos para esta versión.

Cambios en la documentación existente

perlebcdic

El documento perlebcdic contiene una tabla útil para usar en "tr///" para convertir entre EBCDIC y Latin1/ASCII. Desafortunadamente, la tabla era la inversa de la que describe. Esto ha sido corregido.

perlunicode

La sección sobre Mapeos de Casos Definidos por el Usuario tenía marcas incorrectas y oraciones poco claras, lo que hacía que partes de ella no fueran legibles. Esto ha sido rectificado.

perluniprops

Este documento ha sido corregido para tener en cuenta las plataformas no ASCII.

Instalación y configuración

Cambios específicos de la plataforma

Mac OS X
Ha habido correcciones de configuración y pruebas para que Perl se compile limpiamente en Lion y Mountain Lion.
NetBSD
Se corrigió el archivo de sugerencias de NetBSD para que fuera compatible con NetBSD 6.*

Correcciones de errores seleccionadas

  • "chop" ahora maneja correctamente los caracteres por encima de "\x{7fffffff}" [perl #73246].
  • "($<,$>) = (...)" dejó de funcionar correctamente en la versión 5.12.0. Se supone que debe realizar una única llamada a setreuid(), en lugar de llamar a setruid() y seteuid() por separado. En consecuencia, no funcionaba correctamente. Esto se ha corregido [perl #75212].
  • Se corrigió una regresión de kill() cuando se utiliza una variable de coincidencia para el ID del proceso a matar [perl #75812].
  • "UNIVERSAL::VERSION" ya no filtra memoria. Comenzó a filtrar en Perl 5.10.0.
  • Las funciones C de nivel "my_strftime" ya no filtran memoria. Esto corrige una fuga de memoria en "POSIX::strftime" [perl #73520].
  • "caller" ya no filtra memoria cuando se llama desde el paquete DB si @DB::args se asignó después de la primera llamada a "caller". Carp estaba activando este error [perl #97010].
  • Pasar a "index" un desplazamiento más allá del final de la cadena cuando la cadena está codificada internamente en UTF8 ya no causa pánicos [perl #75898].
  • Los errores de sintaxis en los bloques "(?{...})" en expresiones regulares ya no causan mensajes de pánico [perl #2353].
  • Perl 5.10.0 introdujo una lógica defectuosa que hacía que "U*" en medio de una plantilla de empaquetado fuera equivalente a "U0" si la cadena de entrada estaba vacía. Esto se ha corregido [perl #90160].

Fe de erratas

split() y @_

split() ya no modifica @_ cuando se llama en contexto escalar o void. En contexto void ahora produce una advertencia de "Uso inútil de split". Este es en realidad un cambio introducido en perl 5.12.0, pero se pasó por alto en el perl5120delta de esa versión.

Reportar Errores

Si encuentra lo que cree que es un error, puede consultar los artículos publicados recientemente en el grupo de noticias comp.lang.perl.misc y la base de datos de errores de Perl en http://rt.perl.org/perlbug/ . También puede haber información en http://www.perl.org/ , la página principal de Perl.

Si cree que tiene un error no reportado, ejecute el programa perlbug incluido con su versión. Asegúrese de reducir su error a un caso de prueba pequeño pero suficiente. Su informe de error, junto con la salida de "perl -V", se enviará a perlbug@perl.org para ser analizado por el equipo de adaptación de Perl.

Si el error que informa tiene implicaciones de seguridad, que lo hacen inapropiado para enviarlo a una lista de correo archivada públicamente, entonces envíelo a perl5-security-report@perl.org. Esto apunta a una lista de correo de suscripción cerrada y no archivada, que incluye a todos los comprometidos del núcleo, quienes podrán ayudar a evaluar el impacto de los problemas, encontrar una solución y ayudar a coordinar la publicación de parches para mitigar o corregir el problema en todas las plataformas en las que se admite Perl. Utilice esta dirección solo para problemas de seguridad en el núcleo de Perl, no para módulos distribuidos de forma independiente en CPAN.
