NOMBRE

perl5005delta - Novedades de perl5.005

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.004 y esta.

Sobre el nuevo sistema de versionado

Perl se desarrolla ahora en dos vías: una vía de mantenimiento que realiza actualizaciones pequeñas y seguras a las versiones de producción lanzadas, con énfasis en la compatibilidad; y una vía de desarrollo que persigue una evolución más agresiva. Las versiones de mantenimiento (que deben considerarse de calidad de producción) tienen números de subversión que van de 1 a 49, y las versiones de desarrollo (que deben considerarse de calidad "alfa") van de 50 a 99.

Perl 5.005 es el producto combinado del nuevo esquema de desarrollo de doble vía.

Cambios incompatibles

ADVERTENCIA: Esta versión no es compatible binariamente con Perl 5.004

A partir de Perl 5.004_50 hubo muchos cambios profundos y de gran alcance en los internos del lenguaje. Si tienes extensiones cargadas dinámicamente que compilaste bajo perl 5.003 o 5.004, puedes seguir usándolas con 5.004, pero necesitarás recompilar y reinstalar esas extensiones para usarlas con 5.005. Consulta INSTALL para obtener instrucciones detalladas sobre cómo actualizar.

La estructura de instalación por defecto ha cambiado

Los nuevos valores por defecto de Configure están diseñados para permitir una actualización fluida de 5.004 a 5.005, pero deberías leer INSTALL para una discusión detallada de los cambios con el fin de adaptarlos a tu sistema.

Compatibilidad de fuentes de Perl

Cuando no se habilitan ninguna de las características experimentales, debería haber muy pocos problemas de compatibilidad de fuentes de Perl visibles para el usuario.

Si los hilos están habilitados, se aplican algunas advertencias. @_ y $_ se convierten en variables léxicas. El efecto de esto debería ser en gran medida transparente para el usuario, pero hay algunas condiciones límite en las que el usuario deberá ser consciente de los problemas. Por ejemplo, local(@_) resulta en un mensaje de "No se puede localizar la variable léxica @_ ...". Esto podría habilitarse en una versión futura.

Se han introducido algunas palabras clave nuevas. Generalmente se espera que tengan muy poco impacto en la compatibilidad. Consulta "Nueva palabra clave "INIT"", "Nueva palabra clave "lock"" y "Nuevo operador "qr//"".

Ciertos barewords ahora están reservados. Su uso provocará una advertencia si los has solicitado con el interruptor "-w". Consulta ""our" es ahora una palabra reservada".

Compatibilidad de fuentes de C

Ha habido un gran número de cambios en los internos para soportar las nuevas características de esta versión.

  • Las fuentes principales ahora requieren un compilador C ANSI

    Ahora se requiere obligatoriamente un compilador C ANSI para compilar perl. Consulta INSTALL.

  • Todas las variables globales de Perl ahora deben referenciarse con un prefijo explícito

    Todas las variables globales de Perl que son visibles para su uso por extensiones ahora tienen un prefijo "PL_". Las nuevas extensiones "no" deben referirse a las globales de perl por sus nombres sin calificar. Para preservar la cordura, proporcionamos compatibilidad limitada hacia atrás para las globales que se usan ampliamente, como "sv_undef" y "na" (que ahora deberían escribirse como "PL_sv_undef", "PL_na", etc.)

    Si encuentras que tu extensión XS ya no compila porque una global de perl no es visible, intenta añadir un prefijo "PL_" a la global y recompila.

    Se recomienda encarecidamente que todas las funciones de la API de Perl que no comiencen con "perl" se referencien con un prefijo "Perl_". Los nombres de función sin calificar sin el prefijo "Perl_" están soportados con macros, pero este soporte podría cesar en una versión futura.

    Consulta perlapi.

  • Habilitar hilos tiene problemas de compatibilidad de fuentes

    Perl compilado con hilos habilitados requiere que las extensiones utilicen la nueva macro "dTHR" para inicializar el manejador para acceder a datos por hilo. Si ves un error del compilador que habla de la variable "thr" no declarada (al compilar un módulo que tiene código XS), necesitas añadir "dTHR;" al principio del bloque que provocó el error.

    La función de la API "perl_get_sv("@",GV_ADD)" debería usarse en lugar de acceder directamente a las globales de perl como GvSV(errgv). La llamada a la API es compatible hacia atrás con perls existentes y proporciona compatibilidad de fuentes cuando los hilos están habilitados.

    Consulta "Compatibilidad de fuentes de C" para más información.

Compatibilidad binaria

Esta versión NO es binariamente compatible con versiones anteriores. Todas las extensiones necesitarán ser recompiladas. Además, los binarios compilados con hilos habilitados son incompatibles con los compilados sin ellos. Esto debería ser en gran medida transparente para el usuario, ya que todas las configuraciones binariamente incompatibles tienen su propio nombre de arquitectura único, y los binarios de extensión se instalan en ubicaciones únicas. Esto permite la coexistencia de varias configuraciones en la misma jerarquía de directorios. Consulta INSTALL.

Las correcciones de seguridad pueden afectar la compatibilidad

Se han corregido algunas fugas y omisiones de taint. Esto puede llevar al "fallo" de scripts que solían funcionar con versiones anteriores. Compilar con -DINCOMPLETE_TAINTS proporciona un perl con cantidades mínimas de cambios en el comportamiento del taint. Pero ten en cuenta que el perl resultante tendrá inseguridades conocidas.

Los one-liners con el interruptor "-e" ya no crean archivos temporales.

Advertencias obligatorias relajadas introducidas en 5.004

Muchas advertencias nuevas que se introdujeron en 5.004 se han hecho opcionales. Algunas de estas advertencias todavía están presentes, pero las nuevas características de perl hacen que sean un problema con menos frecuencia. Consulta "Nuevos diagnósticos".

Licencia

Perl tiene un nuevo Contrato Social para los colaboradores. Consulta Porting/Contract.

La licencia incluida en gran parte de la documentación de Perl ha cambiado. La mayor parte de la documentación de Perl estaba anteriormente bajo la Licencia Pública General de GNU implícita o la Licencia Artística (a elección del usuario). Ahora, gran parte de la documentación establece inequívocamente los términos bajo los cuales puede ser distribuida. Estos términos son, en general, mucho menos restrictivos que la GPL de GNU. Consulta perl y las páginas de manual de perl individuales listadas en ella.

Compiler

ADVERTENCIA: El Compilador y las herramientas relacionadas se consideran experimentales. Las características pueden cambiar sin previo aviso, y existen limitaciones y errores conocidos. Dado que el compilador es completamente externo a perl, la configuración predeterminada lo compilará e instalará.

El Compilador produce tres tipos diferentes de transformaciones de un programa perl. El backend C genera código C que captura el estado de perl justo antes de que comience la ejecución. Elimina las sobrecargas en tiempo de compilación del intérprete perl regular, pero el rendimiento en tiempo de ejecución sigue siendo comparativamente el mismo. El backend CC genera código C optimizado equivalente a la ruta de código en tiempo de ejecución. El backend CC tiene un mayor potencial para grandes optimizaciones, pero actualmente solo se implementan unas pocas optimizaciones. El backend Bytecode genera una representación de bytecode independiente de la plataforma del estado del intérprete justo antes de la ejecución. Por lo tanto, el backend Bytecode también elimina gran parte de la sobrecarga de compilación del intérprete.

El compilador viene con varias utilidades valiosas.

"B::Lint" es un módulo experimental para detectar y advertir sobre código sospechoso, especialmente los casos que el interruptor "-w" no detecta.

"B::Deparse" puede usarse para desmitificar código perl y comprender cómo perl optimiza ciertas construcciones.

"B::Xref" genera informes de referencias cruzadas de todas las definiciones y usos de variables, subrutinas y formatos en un programa.

"B::Showlex" muestra las variables léxicas utilizadas por una subrutina o archivo de un vistazo.

"perlcc" es un frontend simple para compilar perl.

Consulte "ext/B/README", B y los módulos del compilador correspondientes.

Mejorado malloc()

Consulte el banner al principio de "malloc.c" para obtener detalles.

Quicksort se implementa internamente

Perl ahora contiene su propia rutina qsort() altamente optimizada. El nuevo qsort() es resistente a funciones de comparación inconsistentes, por lo que el sort() de Perl ya no provocará volcados de núcleo cuando se le den subrutinas de ordenación mal escritas. (Algunos qsort() de la biblioteca C que se usaban antes solían tener este problema). En nuestras pruebas, el nuevo qsort() requirió el número mínimo de comparaciones por pares en promedio, entre todas las implementaciones conocidas de qsort().

Consulte "perlfunc/sort".

Señales fiables

El manejo de señales de Perl es susceptible a bloqueos aleatorios, debido a que las señales llegan de forma asíncrona y el tiempo de ejecución de Perl no es reentrante en momentos arbitrarios.

Sin embargo, una implementación experimental de señales fiables está disponible cuando los hilos están habilitados. Consulte "Thread::Signal". Consulte también INSTALL para saber cómo compilar un Perl capaz de hilos.

Punteros de pila fiables

Los internos ahora reasignan la pila de perl solo en momentos predecibles. En particular, las llamadas mágicas nunca desencadenan reasignaciones de la pila, porque toda la reentrada del tiempo de ejecución se maneja utilizando una "pila de pilas". Esto debería mejorar la fiabilidad de los punteros de pila en caché en los internos y en XSUBs.

Tratamiento más generoso de los retornos de carro

Perl solía quejarse si encontraba retornos de carro literales en los scripts. Ahora se tratan en su mayoría como espacios en blanco dentro del texto del programa. Dentro de los literales de cadena y los here documents, los retornos de carro literales se ignoran si aparecen emparejados con saltos de línea, o se interpretan como espacios en blanco si están solos. Este comportamiento significa que se deben evitar los retornos de carro literales en los archivos. Puede obtener el comportamiento anterior, más compatible (pero menos generoso), definiendo el símbolo preprocesador "PERL_STRICT_CR" al compilar perl. Por supuesto, todo esto no tiene nada que ver con cómo se manejan las secuencias de escape como "\r" dentro de las cadenas.

Tenga en cuenta que esto no permite mágicamente mantener todos los archivos de texto en formato DOS. El tratamiento generoso solo se aplica a los archivos que el propio perl analiza. Si su compilador C no permite retornos de carro en los archivos, es posible que aún no pueda compilar módulos que necesiten un compilador C.

Fugas de memoria

"substr", "pos" y "vec" ya no tienen fugas de memoria cuando se usan en contexto lvalue. Se han corregido muchas fugas pequeñas que afectaban a aplicaciones que incrustan múltiples intérpretes.

Mejor soporte para múltiples intérpretes

La opción de tiempo de compilación "-DMULTIPLICITY" ha tenido muchos detalles revisados. Algunas variables previamente globales que deberían haber sido por intérprete ahora lo son. Con cuidado, esto permite que los intérpretes se llamen entre sí. Consulte la extensión "PerlInterp" en CPAN.

El comportamiento de local() en elementos de array y hash ahora está bien definido

Consulte "Valores temporales a través de local()" en perlsub.

"%!" está transparentemente enlazado al módulo Errno

Consulte perlvar y Errno.

Se admiten pseudo-hashes

Consulte perlref.

Se admite "EXPR foreach EXPR"

Consulte perlsyn.

Las palabras clave se pueden anular globalmente

Consulte perlsub.

$^E tiene significado en Win32

Consulte perlvar.

"foreach (1..1000000)" optimizado

"foreach (1..1000000)" ahora está optimizado en un bucle de conteo. Ya no intenta asignar una lista de tamaño 1000000.

"Foo::" puede b

"Foo::" puede ser usado como nombre de paquete implícitamente entre comillas

Las palabras desnudas causaban un comportamiento poco intuitivo cuando una subrutina con el mismo nombre que un paquete estaba definida. Por lo tanto, "new Foo @args", usa el resultado de la llamada a Foo() en lugar de que "Foo" sea tratado como literal. La forma recomendada de escribir palabras desnudas en la ranura del objeto indirecto es "new Foo:: @args". Ten en cuenta que el método new() se llama con un primer argumento de "Foo", no "Foo::" cuando haces eso.

"exists $Foo::{Bar::}" prueba la existencia de un paquete

Era imposible probar la existencia de un paquete sin crearlo realmente antes. Ahora "exists $Foo::{Bar::}" puede ser usado para probar si el espacio de nombres "Foo::Bar" ha sido creado.

Mejor soporte para locales

Ver perllocale.

Soporte experimental para plataformas de 64 bits

Perl5 siempre ha tenido soporte de 64 bits en sistemas con 'long' de 64 bits. A partir de 5.005, se han añadido los inicios del soporte experimental para sistemas con enteros 'long' de 32 bits y 'long long' de 64 bits. Si añades -DUSE_LONG_LONG a tus ccflags en config.sh (o lo defines manualmente en perl.h) entonces perl se compilará con soporte para 'long long'. Habrá muchas advertencias del compilador, y el perl resultante puede no funcionar en todos los sistemas. Hay muchos otros problemas relacionados con extensiones y bibliotecas de terceros. Esta opción existe para permitir a la gente trabajar en esos problemas.

prototype() devuelve resultados útiles en funciones integradas

Ver "prototype" en perlfunc.

Soporte extendido para manejo de excepciones

die() ahora acepta un valor de referencia, y $@ se establece a ese valor en las trampas de excepción. Esto hace posible propagar objetos de excepción. Esta es una característica **experimental** no documentada.

La reasignación de clase (re-blessing) en DESTROY() es compatible para encadenar métodos DESTROY()

Ver "Destructors" en perlobj.

Todas las conversiones de formato de "printf" se manejan internamente

Ver "printf" en perlfunc.

Nueva palabra clave "INIT"

Las subs "INIT" son como "BEGIN" y "END", pero se ejecutan justo antes de que comience la ejecución del tiempo de ejecución de Perl. Por ejemplo, el compilador de Perl hace uso de los bloques "INIT" para inicializar y resolver punteros a XSUBs.

Nueva palabra clave "lock"

La palabra clave "lock" es el primitivo de sincronización fundamental en Perl con hilos. Cuando los hilos no están habilitados, actualmente no hace nada.

Para minimizar el impacto en la compatibilidad de código fuente, esta palabra clave es "débil", es decir, cualquier subrutina definida por el usuario con el mismo nombre la reemplaza, a menos que se haya visto un "use Thread".

Nuevo operador "qr//"

El operador "qr//", que es sintácticamente similar a los otros operadores de tipo comilla, se utiliza para crear expresiones regulares precompiladas. Esta forma compilada ahora se puede pasar explícitamente en variables e interpolar en otras expresiones regulares. Ver perlop.

"our" es ahora una palabra reservada

Llamar a una subrutina con el nombre "our" ahora provocará una advertencia cuando se use el interruptor "-w".

Los arrays enlazados (tied arrays) ahora son totalmente compatibles

Ver Tie::Array.

El soporte para handles enlazados (tied handles) es mejor

Se han añadido varios hooks que faltaban. También hay una nueva clase base para implementaciones TIEARRAY. Ver Tie::Array.

Cuarto argumento para substr

substr() ahora puede tanto devolver como reemplazar en una sola operación. El 4º argumento opcional es la cadena de reemplazo. Ver "substr" en perlfunc.

Argumento LENGTH negativo para splice

splice() con un argumento LENGTH negativo ahora funciona de manera similar a lo que hacía LENGTH para substr(). Anteriormente, un LENGTH negativo se trataba como 0. Ver "splice" en perlfunc.

Los lvalues mágicos ahora son más mágicos

Cuando dices algo como "substr($x, 5) = "hi"", el escalar devuelto por substr() es especial, en el sentido de que cualquier modificación a él afecta a $x. (Esto se llama 'lvalue mágico' porque un 'lvalue' es algo en el lado izquierdo de una asignación.) Normalmente, esto es exactamente lo que esperarías que sucediera, pero Perl usa la misma magia si usas substr(), pos() o vec() en un contexto donde puedan ser modificados, como tomar una referencia con "\" o como argumento para una sub que modifica @_. En versiones anteriores, esta 'magia' solo funcionaba en una dirección, pero ahora los cambios en el escalar al que se refiere la magia ( $x en el ejemplo anterior) también afectan al lvalue mágico. Por ejemplo, este código ahora actúa de manera diferente:

$x = "hello";
sub printit {
    $x = "g'bye";
    print $_[0], "\n";
}
printit(substr($x, 0, 5));

En versiones anteriores, esto imprimiría "hello", pero ahora imprime "g'bye".

<> ahora lee en registros

Si $/ es una referencia a un entero, o un escalar que contiene un entero, <> leerá en registros en lugar de líneas. Para más información, ver "$/" en perlvar.

En particular, las búsquedas que no distinguen entre mayúsculas y minúsculas necesitan el modificador "-i", y las búsquedas recursivas necesitan "-r". Puedes establecer estos modificadores en la variable de entorno "PERLDOC" para obtener el comportamiento anterior.

Nuevos diagnósticos

Llamada ambigua resuelta como CORE::%s(), califícala como tal o usa &
(W) Una subrutina que has declarado tiene el mismo nombre que una palabra clave de Perl, y has usado el nombre sin calificar para llamar a una u otra. Perl decidió llamar a la incorporada porque la subrutina no está importada.

Para forzar la interpretación como una llamada a subrutina, pon un ampersand antes del nombre de la subrutina, o califica el nombre con su paquete. Alternativamente, puedes importar la subrutina (o pretender que está importada con el pragma "use subs").

Para interpretarla silenciosamente como el operador de Perl, usa el prefijo "CORE::" en el operador (por ejemplo, CORE::log($x)) o declarando la subrutina como un método de objeto (ver "attrs").

Índice incorrecto al convertir un array en hash
(F) El índice buscado en el hash encontrado en el elemento 0 de un pseudo-hash no es legal. Los valores de índice deben ser 1 o mayores. Ver perlref.
Bareword "%s" se refiere a un paquete inexistente
(W) Usaste un bareword calificado de la forma "Foo::", pero el compilador no vio ningún otro uso de ese espacio de nombres antes de ese punto. ¿Quizás necesitas predeclarar un paquete?
No se puede llamar al método "%s" sobre un valor indefinido
(F) Usaste la sintaxis de llamada a método, pero la ranura ocupada por la referencia al objeto o el nombre del paquete contiene un valor indefinido. Algo como esto reproducirá el error: 
$BADREF = 42;
process $BADREF 1,2,3;
$BADREF->process(1,2,3);
No se puede comprobar el sistema de archivos del script "%s" para nosuid
(P) Por alguna razón no puedes comprobar el sistema de archivos del script para nosuid.
No se puede convertir un array en hash
(F) Usaste un array donde se esperaba un hash, pero el array no tiene información sobre cómo mapear de claves a índices de array. Solo puedes hacer eso con arrays que tengan una referencia de hash en el índice 0.
No se puede goto a subrutina desde una cadena eval
(F) La llamada a "goto subroutine" no se puede usar para saltar fuera de un eval "string". (Puedes usarla para saltar fuera de un eval {BLOQUE}, pero probablemente no quieras hacerlo.)
No se puede localizar un elemento de pseudo-hash
(F) Dijiste algo como "local $ar->{'key'}", donde $ar es una referencia a un pseudo-hash. Eso aún no se ha implementado, pero puedes obtener un efecto similar localizando directamente el elemento de array correspondiente: "local $ar->[$ar->[0]{'key'}]".
No se puede usar %%! porque Errno.pm no está disponible
(F) La primera vez que se usa el hash %!, perl carga automáticamente el módulo Errno.pm. Se espera que el módulo Errno enlace el hash %! para proporcionar nombres simbólicos para los valores errno de $!.
No se puede encontrar un opnumber para "%s"
(F) Se dio una cadena de la forma "CORE::palabra" a prototype(), pero no hay ningún builtin con el nombre "palabra".
La sintaxis de clase de caracteres [. .] está reservada para futuras extensiones
(W) Dentro de las clases de caracteres de expresiones regulares ([]), la sintaxis que comienza con "[." y termina con ".]" está reservada para futuras extensiones. Si necesitas representar esas secuencias de caracteres dentro de una clase de caracteres de expresión regular, simplemente escapa los corchetes con la barra invertida: "\[." y ".\]".
La sintaxis de clase de caracteres [: :] está reservada para futuras extensiones
(W) Dentro de las clases de caracteres de expresiones regulares ([]), la sintaxis que comienza con "[:" y termina con ":]" está reservada para futuras extensiones. Si necesitas representar esas secuencias de caracteres dentro de una clase de caracteres de expresión regular, simplemente escapa los corchetes con la barra invertida: "\[:" y ":\]".
La sintaxis de clase de caracteres [= =] está reservada para futuras extensiones
(W) Dentro de las clases de caracteres de expresiones regulares ([]), la sintaxis que comienza con "[=" y termina con "=]" está reservada para futuras extensiones. Si necesitas representar esas secuencias de caracteres dentro de una clase de caracteres de expresión regular, simplemente escapa los corchetes con la barra invertida: "\[=" y "=\]".
%s: Grupo eval en expresión regular insegura
(F) Perl detectó datos contaminados al intentar compilar una expresión regular que contiene la aserción de ancho cero "(?{ ... })", que es insegura. Ver "(?{ código })" en perlre, y perlsec.

NAME

perl - Practical Extraction and Report Language

DESCRIPTION

This document describes recent changes to Perl. It is not a full manual, but a summary of what has changed since the last release.

The primary purpose of this document is to highlight any changes that might affect existing Perl code, and to document new features and diagnostic messages.

Refer to the relevant individual POD documents for more details on specific changes.

About the new versioning system

Perl has adopted a new versioning system. The version number is now of the form X.YYY, where X is the major version number and YYY is the minor version number. For example, Perl 5.38.0 has version 5.038000.

This change was made to accommodate a larger number of future releases without creating version number bloat. It also makes it easier to distinguish between major and minor releases.

Incompatible Changes

This section lists changes that may break existing Perl code. It is strongly recommended that you test your code with this new version before deploying it.

Ambiguity in autovivification
(F) An attempt to autovivify a hash or array within a scalar context where it was not defined has been made ambiguous. This change is intended to prevent subtle bugs related to autovivification.

Previously, attempting to assign to a hash or array within a scalar context where it was not defined would result in the creation of an empty hash or array, respectively. This could lead to unexpected behavior if the programmer intended to check for the existence of the hash or array before assigning to it.

With this change, attempting to autovivify a hash or array in a scalar context where it is not defined will now result in a fatal error. To avoid this error, you should explicitly check for the existence of the hash or array before assigning to it, or use a list context where autovivification is well-defined.

# Old behavior (now an error)
my $scalar;
$scalar->{key} = value;

# Corrected behavior
my $scalar;
if (!defined $scalar) {
  $scalar = {}; # Explicitly create a hash reference
}
$scalar->{key} = value;
Default autovivification
(F) The default autovivification behavior has been changed to be more consistent with expectations. Specifically, when assigning to a key in an autovivified hash reference, the value is now checked for definedness.

Previously, assigning an undefined value to a key in an autovivified hash reference would result in the key being created with an undefined value. This could lead to unexpected behavior if the programmer intended to check for the existence of the key before assigning to it.

With this change, assigning an undefined value to a key in an autovivified hash reference will now result in a fatal error. To avoid this error, you should explicitly check for the definedness of the value before assigning it, or ensure that the value is defined.

# Old behavior (now an error)
my $hash_ref;
$hash_ref->{key} = undef;

# Corrected behavior
my $hash_ref;
my $value = get_value(); # Assume get_value() might return undef
if (defined $value) {
  $hash_ref->{key} = $value;
} else {
  # Handle the case where the value is undefined
}

Core Changes

Argument handling
The argument handling in Perl has been refactored to improve performance and reduce memory usage. This change may affect modules that rely on specific argument parsing behaviors.
Built-in operators
Several built-in operators have been optimized for better performance. These include:
  • String comparison operators
  • Numeric comparison operators
  • Array and hash access operators
Garbage collection
The garbage collector has been improved to reduce memory fragmentation and improve overall memory management. This change may affect the performance of applications that use a large amount of memory.
Internal data structures
Several internal data structures have been redesigned to improve efficiency and reduce memory overhead. These changes may affect the performance of modules that interact directly with Perl's internal data structures.

Supported Platforms

  • Linux (x86_64, ARM64)
  • macOS (x86_64, ARM64)
  • Windows (x86_64)

Support for other platforms may be available but has not been officially tested.

New Diagnostics

Can't locate object method "%s" via package "%s"
(F) You tried to call a method named %s on an object (or class) named %s, but that class doesn't know about that method. This is most commonly because the method was never defined in the class, or it was defined in a base class that hasn't been loaded yet. See "Calling Methods" in perlsub and perlmod.
Can't locate package %s
(F) You tried to use a package named %s, but it wasn't found. This is most commonly because the package was never defined, or it was defined in a module that hasn't been loaded yet. See perlmod.
Die (runtime): Can't find `%s'
(F) The compiler tried to find a subroutine or variable named %s, but it wasn't found.
Internal error: *** %s
(F) Perl internal error: the program crashed. You should report this as a bug, along with a minimal test case. See BUGS.
Invalid %s escape
(F) You used an invalid escape sequence in a string literal. For example, "\q" is not a valid escape sequence. See "Quote-like operators" in perlsyn.
Newline in %s, between literal and variable
(F) You have a newline in a string literal between a literal string and a variable. This is not allowed. For example:
print "hello
$world"; # WRONG

To fix this, either put the variable on the same line as the literal, or use the x operator:

print "hello $world";       # RIGHT
print "hello" . $world;     # also RIGHT
Not enough arguments for function %s
(F) You called a function or method with too few arguments.
Not enough keys in hash definition
(F) You tried to define a hash, but provided an odd number of elements. Hashes must have an even number of elements, because they consist of key/value pairs.
Odd number of elements in hash assignment
(F) You tried to assign to a hash, but provided an odd number of elements. Hashes must have an even number of elements, because they consist of key/value pairs.
Out of memory
(F) Perl ran out of memory while trying to perform some operation. This can happen if you are processing very large amounts of data, or if you have a bug in your program that causes excessive memory allocation.
Quantifier %s follows nothing
(F) You used a quantifier (e.g., *, +, ?, {n,m}) immediately after another quantifier, or at the beginning of a regular expression. Quantifiers must apply to a preceding character, character class, or group.
Range iterator outside integer range
(F) One (or both) of the numeric arguments to the range operator ".." are outside the range which can be represented by integers internally. One possible workaround is to force Perl to use magical string increment by prepending "0" to your numbers.
Scalar value is not allowed
(F) You tried to use a scalar value in a context where a list or array reference was expected. For example, you tried to assign a scalar value to a hash.
Subroutine %s redefined
(W) You have defined a subroutine named %s more than once. The most recent definition will be used.
Syntax error in %s
(F) There is a syntax error in the specified file or input stream. The error message usually indicates the location of the error.
Too many arguments for function %s
(F) You called a function or method with too many arguments.
Unexpected end of file
(F) Perl reached the end of the input unexpectedly. This usually means you have an unclosed block (e.g., parentheses, brackets, or braces).
Unknown operator "%s"
(F) You used an operator that Perl does not recognize. This is usually a typo.
Unmatched %s
(F) You have an unmatched delimiter. For example, an unclosed parenthesis or bracket.
Use of uninitialized value in %s
(W) You used a variable that has not been initialized (assigned a value). This warning can be helpful in finding potential bugs in your code. You can suppress this warning by assigning a default value to the variable, or by using the defined() function to check if the variable has been initialized.
Variable "$%s" is not available
(F) You tried to use a special variable that is not available in the current context. For example, you tried to use $T in a context where it is not defined.
Zero length assertion in regex not allowed
(F) A zero-length assertion (e.g., ^, $, \b) was used in a context where it is not allowed. This usually occurs when the assertion is not followed by a valid pattern.
Zero width assertion (?{ ... }) not allowed
(F) A zero-width assertion with embedded code ((?{ ... })) was used in a regular expression. This feature is deprecated and has been removed. Use the eval pragma instead. See "Zero-width Assertions" in perlre.
Eval-group not allowed, use re 'eval'
(F) A regular expression contained the "(?{ ... })" zero-width assertion, but that construct is only allowed when the "use re 'eval'" pragma is in effect. See "(?{ code })" in perlre.
Eval-group not allowed at run time
(F) Perl tried to compile a regular expression containing the "(?{ ... })" zero-width assertion at run time, as it would when the pattern contains interpolated values. Since that is a security risk, it is not allowed. If you insist, you may still do this by explicitly building the pattern from an interpolated string at run time and using that in an eval(). See "(?{ code })" in perlre.
Explicit blessing to '' (assuming package main)
(W) You are blessing a reference to a zero length string. This has the effect of blessing the reference into the package main. This is usually not what you want. Consider providing a default target package, e.g. bless($ref, $p || 'MyPackage');
Illegal hex digit ignored
(W) You may have tried to use a character other than 0 - 9 or A - F in a hexadecimal number. Interpretation of the hexadecimal number stopped before the illegal character.
No such array field
(F) You tried to access an array as a hash, but the field name used is not defined. The hash at index 0 should map all valid field names to array indices for that to work.
No such field "%s" in variable %s of type %s
(F) You tried to access a field of a typed variable where the type does not know about the field name. The field names are looked up in the %FIELDS hash in the type package at compile time. The %FIELDS hash is usually set up with the 'fields' pragma.
Out of memory during ridiculously large request
(F) You can't allocate more than 2^31+"small amount" bytes. This error is most likely to be caused by a typo in the Perl program. e.g., $arr[time] instead of $arr[$time].
Range iterator outside integer range
(F) One (or both) of the numeric arguments to the range operator ".." are outside the range which can be represented by integers internally. One possible workaround is to force Perl to use magical string increment by prepending "0" to your numbers.
Recursive inheritance detected while looking for method '%s' %s
(F) More than 100 levels of inheritance were encountered while invoking a method. Probably indicates an unintended loop in your inheritance hierarchy.
Reference found where even-sized list expected
(W) You gave a single reference where Perl was expecting a list with an even number of elements (for assignment to a hash). This usually means that you used the anon hash constructor when you meant to use parens. In any case, a hash requires key/value pairs. 
%hash = { one => 1, two => 2, };   # WRONG
%hash = [ qw/ an anon array / ];   # WRONG
%hash = ( one => 1, two => 2, );   # right
%hash = qw( one 1 two 2 );                 # also fine
Undefined value assigned to typeglob
(W) An undefined value was assigned to a typeglob, a la "*foo = undef". This does nothing. It's possible that you really mean "undef *foo".
Use of reserved word "%s" is deprecated
(D) The indicated bareword is a reserved word. Future versions of perl may use it as a keyword, so you're better off either explicitly quoting the word in a manner appropriate for its context of use, or using a different name altogether. The warning can be suppressed for subroutine names by either adding a "&" prefix, or using a package qualifier, e.g. &our(), or Foo::our().
perl: warning: Setting locale failed.
(S) The whole warning message will look something like: 
perl: warning: Setting locale failed.
perl: warning: Please check that your locale settings:
        LC_ALL = "En_US",
        LANG = (unset)
    are supported and installed on your system.
perl: warning: Falling back to the standard locale ("C").

Exactly what were the failed locale settings varies. In the above the settings were that the LC_ALL was "En_US" and the LANG had no value. This error means that Perl detected that you and/or your system administrator have set up the so-called variable system but Perl could not use those settings. This was not dead serious, fortunately: there is a "default locale" called "C" that Perl can and will use, the script will be run. Before you really fix the problem, however, you will get the same error message each time you run Perl. How to really fix the problem can be found in "LOCALE PROBLEMS" in perllocale.

Obsolete Diagnostics

Can't mktemp()
(F) The mktemp() routine failed for some reason while trying to process a -e switch. Maybe your /tmp partition is full, or clobbered.

Removed because -e doesn't use temporary files any more.

Can't write to temp file for -e: %s
(F) The write routine failed for some reason while trying to process a -e switch. Maybe your /tmp partition is full, or clobbered.

Removed because -e doesn't use temporary files any more.

Cannot open temporary file
(F) The create routine failed for some reason while trying to process a -e switch. Maybe your /tmp partition is full, or clobbered.

Removed because -e doesn't use temporary files any more.

regexp too big
(F) The current implementation of regular expressions uses shorts as address offsets within a string. Unfortunately this means that if the regular expression compiles to longer than 32767, it'll blow up. Usually when you want a regular expression this big, there is a better way to do it with multiple statements. See perlre.

Configuration Changes

You can use "Configure -Uinstallusrbinperl" which causes installperl to skip installing perl also as /usr/bin/perl. This is useful if you prefer not to modify /usr/bin for some reason or another but harmful because many scripts assume to find Perl in /usr/bin/perl.
