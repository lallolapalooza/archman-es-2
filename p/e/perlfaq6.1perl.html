Esta sección es sorprendentemente pequeña porque el resto del FAQ está lleno de respuestas que involucran expresiones regulares. Por ejemplo, decodificar una URL y comprobar si algo es un número pueden manejarse con expresiones regulares, pero esas respuestas se encuentran en otras partes de este documento (en perlfaq9: "¿Cómo decodifico o creo esas codificaciones %-en la web" y perlfaq4: "¿Cómo determino si un escalar es un número/entero/punto flotante", para ser precisos).

¿Cómo puedo esperar usar expresiones regulares sin crear código ilegible e inmanejable?

Tres técnicas pueden hacer que las expresiones regulares sean manejables y comprensibles.

Comentarios fuera de la expresión regular
Describe qué estás haciendo y cómo lo estás haciendo, usando comentarios normales de Perl. 
# convierte la línea en la primera palabra, dos puntos y el
# número de caracteres en el resto de la línea
s/^(\w+)(.*)/ lc($1) . ":" . length($2) /meg;
Comentarios dentro de la expresión regular
El modificador "/x" hace que los espacios en blanco se ignoren en un patrón de expresión regular (excepto en una clase de caracteres y algunos otros lugares), y también te permite usar comentarios normales allí. Como puedes imaginar, los espacios en blanco y los comentarios ayudan mucho.

"/x" te permite convertir esto:

s{<(?:[^>'"]*|".*?"|'.*?')+>}{}gs;

en esto:

s{ <                    # corchete angular de apertura
    (?:                 # Paréntesis de agrupación sin retroceso
        [^>'"] *        # 0 o más cosas que no son > ni ' ni "
            |           #    o bien
        ".*?"           # una sección entre comillas dobles (coincidencia ávara)
            |           #    o bien
        '.*?'           # una sección entre comillas simples (coincidencia ávara)
    ) +                 #   ocurriendo una o más veces
    >                   # corchete angular de cierre
}{}gsx;                 # reemplaza con nada, es decir, elimina

Todavía no es tan claro como la prosa, pero es muy útil para describir el significado de cada parte del patrón.

Delimitadores diferentes
Mientras que normalmente pensamos en los patrones como delimitados por caracteres "/", pueden ser delimitados por casi cualquier carácter. perlre describe esto. Por ejemplo, el "s///" anterior usa llaves como delimitadores. Seleccionar otro delimitador puede evitar tener que escapar el delimitador dentro del patrón: 
s/\/usr\/local/\/usr\/share/g;    # mala elección de delimitador
s#/usr/local#/usr/share#g;        # mejor

Usar delimitadores lógicamente emparejados puede ser aún más legible:

s{/usr/local/}{/usr/share}g;      # aún mejor

Tengo problemas para hacer coincidir más de una línea. ¿Qué está mal?

O bien no tienes más de una línea en la cadena que estás mirando (probablemente), o bien no estás usando el(los) modificador(es) correcto(s) en tu patrón (posiblemente).

Hay muchas maneras de obtener datos multilínea en una cadena. Si quieres que suceda automáticamente mientras lees la entrada, querrás establecer $/ (probablemente a '' para párrafos o "undef" para todo el archivo) para permitirte leer más de una línea a la vez.

Lee perlre para ayudarte a decidir cuál de "/s" y "/m" (o ambos) podrías querer usar: "/s" permite que el punto incluya saltos de línea, y "/m" permite que el acento circunflejo y el signo de dólar coincidan junto a un salto de línea, no solo al final de la cadena. Necesitas asegurarte de que realmente tienes una cadena multilínea.

Por ejemplo, este programa detecta palabras duplicadas, incluso cuando abarcan saltos de línea (pero no saltos de párrafo). Para este ejemplo, no necesitamos "/s" porque no estamos usando el punto en una expresión regular que queramos que cruce límites de línea. Tampoco necesitamos "/m" porque no queremos que el acento circunflejo o el signo de dólar coincidan en ningún punto dentro del registro junto a saltos de línea. Pero es imperativo que $/ se establezca a algo distinto del valor predeterminado, o de lo contrario, nunca tendremos un registro multilínea leído.

$/ = '';          # leer párrafo completo, no solo una línea
while ( <> ) {
    while ( /\b([\w'-]+)(\s+\g1)+\b/gi ) {     # la palabra empieza alfabéticamente
        print "Duplicado $1 en párrafo $.\n";
    }
}

Aquí tienes un código que encuentra frases que comienzan con "From " (que serían desfiguradas por muchos correos):

$/ = '';          # leer párrafo completo, no solo una línea
while ( <> ) {
    while ( /^From /gm ) { # /m hace que ^ coincida junto a \n
    print "From inicial en párrafo $.\n";
    }
}

Aquí tienes código que encuentra todo entre START y END en un párrafo:

undef $/;          # leer archivo completo, no solo una línea o párrafo
while ( <> ) {
    while ( /START(.*?)END/sgm ) { # /s hace que . cruce límites de línea
        print "$1\n";
    }
}

¿Cómo puedo extraer líneas entre dos patrones que están ellos mismos en diferentes líneas?

Puedes usar el operador algo exótico de Perl ".." (documentado en perlop):

perl -ne 'print if /START/ .. /END/' archivo1 archivo2 ...

Si quisieras texto y no líneas, usarías

perl -0777 -ne 'print "$1\n" while /START(.*?)END/gs' archivo1 archivo2 ...

Pero si quieres ocurrencias anidadas de "START" a "END", te encontrarás con el problema descrito en la pregunta de esta sección sobre la coincidencia de texto balanceado.

Aquí hay otro ejemplo de uso de "..":

while (<>) {
    my $in_header =   1  .. /^$/;
    my $in_body   = /^$/ .. eof;
# ahora elige entre ellos
} continue {
    $. = 0 if eof;    # arregla $.
}

¿Cómo coincido XML, HTML u otras cosas desagradables y feas con una expresión regular?

No uses expresiones regulares. Usa un módulo y olvídate de las expresiones regulares. Los módulos XML::LibXML, HTML::TokeParser y HTML::TreeBuilder son buenos puntos de partida, aunque cada espacio de nombres tiene otros módulos de análisis especializados para ciertas tareas y diferentes formas de hacerlo. ¡Empieza en CPAN Search ( http://metacpan.org/ ) y maravíllate de todo el trabajo que la gente ha hecho por ti! :)

Puse una expresión regular en $/ pero no funcionó. ¿Qué está mal?

$/ tiene que ser una cadena. Puedes usar estos ejemplos si realmente necesitas hacer esto.

Si tienes File::Stream, esto es fácil.

use File::Stream;
my $stream = File::Stream->new(
    $filehandle,
    separator => qr/\s*,\s*/,
    );
print "$_\n" while <$stream>;

Si no tienes File::Stream, tienes que trabajar un poco más.

Puedes usar la forma de cuatro argumentos de sysread para añadir continuamente a un búfer. Después de añadir al búfer, compruebas si tienes una línea completa (usando tu expresión regular).

local $_ = "";
while( sysread FH, $_, 8192, length ) {
    while( s/^((?s).*?)your_pattern// ) {
        my $record = $1;
        # haz cosas aquí.
    }
}

Can I use Perl regular expressions to match balanced text?

The short answer is no, not with standard regular expressions. However, Perl's regular expressions do have some limited support for matching balanced constructs, at least for simple cases. This support comes from the "(*ACCEPT" and "(*FAIL" verbs, which are not documented in the main perlre manpage.

The "(*ACCEPT" verb tells the regex engine that it has found a match and should stop. The "(*FAIL" verb tells it that it has failed and should backtrack.

Here's an example that matches nested parentheses. It requires Perl 5.005 or later.

sub match_parens {
    my ($str) = @_;
    my $depth = 0;
    my $regex = qr/
        (?(DEFINE)
            (?<balanced>
                [^()]+      ##  Match any non-paren character
            |               ##  OR
                \( (?<balanced>)* \) ##  Match nested parens
            )
        )
        ^ (?<balanced>)* $   ##  Match the whole string
    /x;
    return $str =~ $regex;
}

This example will return true for "()", "(a())", and "((a)b)", but false for "(()" and "())".

The use of recursion in regular expressions is a powerful tool, but it has its limitations. For more complex cases of nested structures, you may need to resort to a full parser. However, for simple cases like matching balanced parentheses, this technique can be quite effective.

Can I use a regular expression to process a file without loading it all into memory?

Yes. The key is to read the file in chunks and to use the "s///" operator and the "\G" anchor. The "\G" anchor matches at the position where the previous match ended, or at the beginning of the string for the first match. This allows you to match across chunks.

Here's an example that reads a file 8192 bytes at a time and looks for a specific pattern:

local $_ = "";
while( sysread FH, $_, 8192, length ) {
    foreach my $record ( m/\G((?s).*?)your_pattern/gc ) {
        # do stuff here.
    }
    substr( $_, 0, pos ) = "" if pos;
}

This code reads chunks of 8192 bytes from the filehandle FH. The "m/\G((?s).*?)your_pattern/gc" regular expression attempts to find instances of "your_pattern". The "(?s)" modifier allows the dot to match newlines, and the "g" modifier allows multiple matches within the chunk. The "c" modifier allows the match to continue from where it left off in the previous chunk.

After processing each record, substr($_, 0, pos) = "" if pos; removes the processed part from the buffer to save memory.

This approach is efficient for large files as it avoids loading the entire file into memory at once. It's particularly useful when you need to find patterns that might span across chunk boundaries.

How do I substitute case-insensitively on the LHS while preserving case on the RHS?

Here's a lovely Perlish solution by Larry Rosler. It exploits properties of bitwise xor on ASCII strings.

$_= "this is a TEsT case";
$old = 'test';
$new = 'success';
s{(\Q$old\E)}
{ uc $new | (uc $1 ^ $1) .
    (uc(substr $1, -1) ^ substr $1, -1) x
    (length($new) - length $1)
}egi;
print;

And here it is as a subroutine, modeled after the above:

sub preserve_case {
    my ($old, $new) = @_;
    my $mask = uc $old ^ $old;
    uc $new | $mask .
        substr($mask, -1) x (length($new) - length($old))
}
$string = "this is a TEsT case";
$string =~ s/(test)/preserve_case($1, "success")/egi;
print "$string\n";

This prints:

this is a SUcCESS case

As an alternative, to keep the case of the replacement word if it is longer than the original, you can use this code, by Jeff Pinyan:

sub preserve_case {
    my ($from, $to) = @_;
    my ($lf, $lt) = map length, @_;
    if ($lt < $lf) { $from = substr $from, 0, $lt }
    else { $from .= substr $to, $lf }
    return uc $to | ($from ^ uc $from);
}

This changes the sentence to "this is a SUcCess case."

Just to show that C programmers can write C in any programming language, if you prefer a more C-like solution, the following script makes the substitution have the same case, letter by letter, as the original. (It also happens to run about 240% slower than the Perlish solution runs.) If the substitution has more characters than the string being substituted, the case of the last character is used for the rest of the substitution.

# Original by Nathan Torkington, massaged by Jeffrey Friedl
#
sub preserve_case
{
    my ($old, $new) = @_;
    my $state = 0; # 0 = no change; 1 = lc; 2 = uc
    my ($i, $oldlen, $newlen, $c) = (0, length($old), length($new));
    my $len = $oldlen < $newlen ? $oldlen : $newlen;
    for ($i = 0; $i < $len; $i++) {
        if ($c = substr($old, $i, 1), $c =~ /[\W\d_]/) {
            $state = 0;
        } elsif (lc $c eq $c) {
            substr($new, $i, 1) = lc(substr($new, $i, 1));
            $state = 1;
        } else {
            substr($new, $i, 1) = uc(substr($new, $i, 1));
            $state = 2;
        }
    }
    # finish up with any remaining new (for when new is longer than old)
    if ($newlen > $oldlen) {
        if ($state == 1) {
            substr($new, $oldlen) = lc(substr($new, $oldlen));
        } elsif ($state == 2) {
            substr($new, $oldlen) = uc(substr($new, $oldlen));
        }
    }
    return $new;
}

How can I make "\w" match national character sets?

You can use the POSIX character class syntax "/[[:alpha:]]/" documented in perlre.

No matter which locale you are in, the alphabetic characters are the characters in \w without the digits and the underscore. As a regex, that looks like "/[^\W\d_]/". Its complement, the non-alphabetics, is then everything in \W along with the digits and the underscore, or "/[\W\d_]/".

How can I quote a variable to use in a regex?

The Perl parser will expand $variable and @variable references in regular expressions unless the delimiter is a single quote. Remember, too, that the right-hand side of a "s///" substitution is considered a double-quoted string (see perlop for more details). Remember also that any regex special characters will be acted on unless you precede the substitution with \Q. Here's an example:

$string = "Placido P. Octopus";
$regex  = "P.";
$string =~ s/$regex/Polyp/;
# $string is now "Polypacido P. Octopus"

$string = "Placido P. Octopus";

The use of "\Q" causes the "." in the regex to be treated as a regular character, so that "P." matches a "P" followed by a dot.

What is "/o" really for?

(contributed by brian d foy)

The "/o" option for regular expressions (documented in perlop and perlreref) tells Perl to compile the regular expression only once. This is only useful when the pattern contains a variable. Perls 5.6 and later handle this automatically if the pattern does not change.

Since the match operator "m//", the substitution operator "s///", and the regular expression quoting operator "qr//" are double-quotish constructs, you can interpolate variables into the pattern. See the answer to "How can I quote a variable to use in a regex?" for more details.

This example takes a regular expression from the argument list and prints the lines of input that match it:

my $pattern = shift @ARGV;
while( <> ) {
    print if m/$pattern/;
}

Versions of Perl prior to 5.6 would recompile the regular expression for each iteration, even if $pattern had not changed. The "/o" would prevent this by telling Perl to compile the pattern the first time, then reuse that for subsequent iterations:

my $pattern = shift @ARGV;
while( <> ) {
    print if m/$pattern/o; # useful for Perl < 5.6
}

In versions 5.6 and later, Perl won't recompile the regular expression if the variable hasn't changed, so you probably don't need the "/o" option. It doesn't hurt, but it doesn't help either. If you want any version of Perl to compile the regular expression only once even if the variable changes (thus, only using its initial value), you still need the "/o".

You can watch Perl's regular expression engine at work to verify for yourself if Perl is recompiling a regular expression. The use re 'debug' pragma (comes with Perl 5.005 and later) shows the details. With Perls before 5.6, you should see "re" reporting that it's compiling the regular expression on each iteration. With Perl 5.6 or later, you should only see "re" report that for the first iteration.

use re 'debug';
my $regex = 'Perl';
foreach ( qw(Perl Java Ruby Python) ) {
    print STDERR "-" x 73, "\n";
    print STDERR "Trying $_...\n";
    print STDERR "\t$_ is good!\n" if m/$regex/;
}

How do I use a regular expression to strip C-style comments from a file?

While this actually can be done, it's much harder than you'd think. For example, this one-liner

perl -0777 -pe 's{/\*.*?\*/}{}gs' foo.c

will work in many but not all cases. You see, it's too simple-minded for certain kinds of C programs, in particular, those with what appear to be comments in quoted strings. For that, you'd need something like this, created by Jeffrey Friedl and later modified by Fred Curtis.

$/ = undef;
$_ = <>;
s#/\*[^*]*\*+([^/*][^*]*\*+)*/|("(\\.|[^"\\])*"|'(\\.|[^'\\])*'|.[^/"'\\]*)#defined $2 ? $2 : ""#gse;
print;

This could, of course, be more legibly written with the "/x" modifier, adding whitespace and comments. Here it is expanded, courtesy of Fred Curtis.

s{
   /\*         ##  Start of /* ... */ comment
   [^*]*\*+    ##  Non-* followed by 1-or-more *'s
   (
     [^/*][^*]*\*+
   )*          ##  0-or-more things which don't start with /
               ##    but do end with '*'
   /           ##  End of /* ... */ comment
 |         ##     OR  various things which aren't comments:
   (
     "           ##  Start of " ... " string
     (
       \\.           ##  Escaped char
     |               ##    OR
       [^"\\]        ##  Non "\
     )*
     "           ##  End of " ... " string
   |         ##     OR
     '           ##  Start of ' ... ' string
     (
       \\.           ##  Escaped char
     |               ##    OR
       [^'\\]        ##  Non '\
     )*
     '           ##  End of ' ... ' string
   |         ##     OR
     .           ##  Anything other char
     [^/"'\\]*   ##  Chars which doesn't start a comment, string or escape
   )
 }{defined $2 ? $2 : ""}gxse;

A slight modification also removes C++ comments, possibly spanning multiple lines using a continuation character:

s#/\*[^*]*\*+([^/*][^*]*\*+)*/|//([^\\]|[^\n][\n]?)*?\n|("(\\.|[^"\\])*"|'(\\.|[^'\\])*'|.[^/"'\\]*)#defined $3 ? $3 : ""#gse;

Versions of Perl prior to 5.6 would recompile the regular expression for each iteration, even if $pattern had not changed. The "/o" would prevent this by telling Perl to compile the pattern the first time, then reuse that for subsequent iterations:

my $pattern = shift @ARGV;
while( <> ) {
    print if m/$pattern/o; # useful for Perl < 5.6
}

In versions 5.6 and later, Perl won't recompile the regular expression if the variable hasn't changed, so you probably don't need the "/o" option. It doesn't hurt, but it doesn't help either. If you want any version of Perl to compile the regular expression only once even if the variable changes (thus, only using its initial value), you still need the "/o".

You can watch Perl's regular expression engine at work to verify for yourself if Perl is recompiling a regular expression. The use re 'debug' pragma (comes with Perl 5.005 and later) shows the details. With Perls before 5.6, you should see "re" reporting that it's compiling the regular expression on each iteration. With Perl 5.6 or later, you should only see "re" report that for the first iteration.

use re 'debug';
my $regex = 'Perl';
foreach ( qw(Perl Java Ruby Python) ) {
    print STDERR "-" x 73, "\n";
    print STDERR "Trying $_...\n";
    print STDERR "\t$_ is good!\n" if m/$regex/;
}

How do I use a regular expression to strip C-style comments from a file?

While this actually can be done, it's much harder than you'd think. For example, this one-liner

perl -0777 -pe 's{/\*.*?\*/}{}gs' foo.c

will work in many but not all cases. You see, it's too simple-minded for certain kinds of C programs, in particular, those with what appear to be comments in quoted strings. For that, you'd need something like this, created by Jeffrey Friedl and later modified by Fred Curtis.

$/ = undef;
$_ = <>;
s#/\*[^*]*\*+([^/*][^*]*\*+)*/|("(\\.|[^"\\])*"|'(\\.|[^'\\])*'|.[^/"'\\]*)#defined $2 ? $2 : ""#gse;
print;

This could, of course, be more legibly written with the "/x" modifier, adding whitespace and comments. Here it is expanded, courtesy of Fred Curtis.

s{
   /\*         ##  Start of /* ... */ comment
   [^*]*\*+    ##  Non-* followed by 1-or-more *'s
   (
     [^/*][^*]*\*+
   )*          ##  0-or-more things which don't start with /
               ##    but do end with '*'
   /           ##  End of /* ... */ comment
 |         ##     OR  various things which aren't comments:
   (
     "           ##  Start of " ... " string
     (
       \\.           ##  Escaped char
     |               ##    OR
       [^"\\]        ##  Non "\
     )*
     "           ##  End of " ... " string
   |         ##     OR
     '           ##  Start of ' ... ' string
     (
       \\.           ##  Escaped char
     |               ##    OR
       [^'\\]        ##  Non '\
     )*
     '           ##  End of ' ... ' string
   |         ##     OR
     .           ##  Anything other char
     [^/"'\\]*   ##  Chars which doesn't start a comment, string or escape
   )
 }{defined $2 ? $2 : ""}gxse;

s#/\*[^*]*\*+([^/*][^*]*\*+)*/|//([^\\]|[^\n][\n]?)*?\n|("(\\.|[^"\\])*"|'(\\.|[^'\\])*'|.[^/"'\\]*)#defined $3 ? $3 : ""#gse;

CÓMO BUSCAR UNA EXPRESIÓN REGULAR QUE ESTÁ EN UNA VARIABLE?

(contribuido por brian d foy)

No tenemos que codificar patrones en el operador de coincidencia (o cualquier otra cosa que funcione con expresiones regulares). Podemos poner el patrón en una variable para su uso posterior.

El operador de coincidencia es un contexto de doble comilla, por lo que puede interpolar su variable al igual que una cadena de doble comilla. En este caso, lee la expresión regular como entrada del usuario y la almacena en $regex. Una vez que tiene el patrón en $regex, usa esa variable en el operador de coincidencia.

chomp( my $regex = <STDIN> );
if( $string =~ m/$regex/ ) { ... }

Cualquier carácter especial de expresión regular en $regex sigue siendo especial, y el patrón aún tiene que ser válido o Perl se quejará. Por ejemplo, en este patrón hay un paréntesis sin emparejar.

my $regex = "Unmatched ( paren";
"Two parens to bind them all" =~ m/$regex/;

Cuando Perl compila la expresión regular, trata el paréntesis como el inicio de una coincidencia de memoria. Cuando no encuentra el paréntesis de cierre, se queja:

Unmatched ( in regex; marked by <-- HERE in m/Unmatched ( <-- HERE  paren/ at script line 3.

Puede solucionar esto de varias maneras, dependiendo de su situación. Primero, si no desea que ninguno de los caracteres de la cadena sea especial, puede escaparlos con "quotemeta" antes de usar la cadena.

chomp( my $regex = <STDIN> );
$regex = quotemeta( $regex );
if( $string =~ m/$regex/ ) { ... }

También puede hacer esto directamente en el operador de coincidencia usando las secuencias "\Q" y "\E". El "\Q" indica a Perl dónde empezar a escapar los caracteres especiales, y el "\E" le indica dónde parar (ver perlop para más detalles).

chomp( my $regex = <STDIN> );
if( $string =~ m/\Q$regex\E/ ) { ... }

Alternativamente, puede usar "qr//", el operador de cita de expresión regular (ver perlop para más detalles). Cita y quizás compila el patrón, y puede aplicar indicadores de expresión regular al patrón.

chomp( my $input = <STDIN> );
my $regex = qr/$input/is;
$string =~ m/$regex/  # same as m/$input/is;

También es posible que desee capturar cualquier error envolviendo un bloque "eval" alrededor de todo.

chomp( my $input = <STDIN> );
eval {
    if( $string =~ m/\Q$input\E/ ) { ... }
};
warn $@ if $@;

O...

my $regex = eval { qr/$input/is };
if( defined $regex ) {
    $string =~ m/$regex/;
}
else {
    warn $@;
}
