PERF-MEM(1) Manual de perf PERF-MEM(1)

NOMBRE

perf-mem - Perfilado de accesos a memoria

SINOPSIS

perf mem [<opciones>] (record [<comando>] | report)

DESCRIPCIÓN

"perf mem record" ejecuta un comando y recopila datos de operaciones de memoria de él, en perf.data. Se aceptan opciones de perf record y se pasan.

"perf mem report" muestra el resultado. Invoca perf report con el conjunto correcto de opciones para mostrar un perfil de acceso a memoria. Por defecto, se muestrean cargas y almacenamientos. Usa la opción -t para limitar a cargas o almacenamientos.

Ten en cuenta que en sistemas Intel la latencia de memoria reportada es la latencia de uso, no la latencia pura de carga (o almacenamiento). La latencia de uso incluye retrasos de cola de la canalización además de la latencia del subsistema de memoria.

En Arm64 esto usa SPE para muestrear operaciones de carga y almacenamiento, por lo tanto, se requiere soporte de hardware y kernel. Consulta perf-arm-spe(1) para una guía de configuración. Debido a la naturaleza estadística del muestreo SPE, no todas las operaciones de memoria serán muestreadas.

En AMD esto usa IBS Op PMU para muestrear operaciones de carga-almacenamiento.

OPCIONES COMUNES

-f, --force

No realizar validación de propiedad

-t, --type=<tipo>

Selecciona el tipo de operación de memoria: load (carga) o store (almacenamiento) (por defecto: load,store)

-v, --verbose

Ser más verboso (mostrar errores de apertura de contador, etc.)

-p, --phys-data

Registrar/Reportar direcciones físicas de las muestras

--data-page-size

Registrar/Reportar tamaño de página de datos de la muestra

OPCIONES DE GRABACIÓN

<comando>...

Cualquier comando que puedas especificar en un shell.

-e, --event <evento>

Selector de evento. Usa perf mem record -e list para listar eventos disponibles.

-K, --all-kernel

Configurar todos los eventos utilizados para ejecutarse en el espacio del kernel.

-U, --all-user

Configurar todos los eventos utilizados para ejecutarse en el espacio del usuario.

--ldlat <n>

Especifica la latencia deseada para el evento de carga (load). Soportado en procesadores Intel, Arm64 y algunos AMD. Ignorado en otras arquitecturas. 
En procesadores AMD soportados:
- El archivo /sys/bus/event_source/devices/ibs_op/caps/ldlat contiene '1'.
- Los valores de latencia soportados son de 128 a 2048 (ambos inclusive).
- Un valor de latencia que sea múltiplo de 128 incurre en un poco menos de sobrecarga de perfilado que otros valores.
- El filtrado de latencia de carga está deshabilitado por defecto.

OPCIONES DE REPORTE

-i, --input=<archivo>

Nombre del archivo de entrada.

-C, --cpu=<cpu>

Monitorizar solo en la lista de CPUs proporcionadas. Se pueden proporcionar varias CPUs como una lista separada por comas sin espacio: 0,1. Los rangos de CPUs se especifican con - como 0-2. Por defecto se monitorizan todas las CPUs.

-D, --dump-raw-samples

Volcar las muestras decodificadas crudas en la pantalla en un formato fácil de analizar con una muestra por línea.

-s, --sort=<clave>

Agrupar el resultado por la(s) clave(s) dada(s) - se pueden especificar múltiples claves en formato CSV. Las claves son específicas de las muestras de memoria y son: symbol_daddr, symbol_iaddr, dso_daddr, locked, tlb, mem, snoop, dcacheline, phys_daddr, data_page_size, blocked.
•symbol_daddr: nombre del símbolo de datos que se está ejecutando en el momento de la muestra
•symbol_iaddr: nombre del símbolo de código que se está ejecutando en el momento de la muestra
•dso_daddr: nombre de la biblioteca o módulo que contiene los datos que se están procesando en el momento de la muestra
•locked: si el bus estaba bloqueado en el momento de la muestra
•tlb: tipo de acceso TLB para los datos en el momento de la muestra
•mem: tipo de acceso a memoria para los datos en el momento de la muestra
•snoop: tipo de snoop (si lo hay) para los datos en el momento de la muestra
•dcacheline: la línea de caché en la que se encuentra la dirección de datos en el momento de la muestra
•phys_daddr: dirección física de los datos que se están procesando en el momento de la muestra
•data_page_size: el tamaño de página de datos de los datos que se están procesando en el momento de la muestra
•blocked: motivo del acceso de carga bloqueado para los datos en el momento de la muestra 
Y las claves de ordenación por defecto se cambian a local_weight, mem, sym, dso,
symbol_daddr, dso_daddr, snoop, tlb, locked, blocked, local_ins_lat.

-F, --fields=

Especifica el campo de salida - se pueden especificar múltiples claves en formato CSV. Por favor, consulta perf-report(1) para más detalles. 
Además de los campos por defecto, 'perf mem report' proporcionará los
siguientes campos para desglosar los periodos de las muestras.
•op: operación en la instrucción de muestra (load, store, prefetch, ...)
•cache: ubicación en la caché de CPU (L1, L2, ...) donde impactó la muestra
•mem: ubicación en memoria u otros lugares donde impactó la muestra
•dtlb: ubicación en TLB de Datos (L1, L2) donde impactó la muestra
•snoop: resultado del snoop para el acceso a datos muestreado 
Por favor, echa un vistazo a la sección SELECCIÓN DE CAMPOS DE SALIDA para advertencias.

-T, --type-profile

Muestra el resultado del perfil de tipo de datos en lugar de símbolos de código. Esto requiere información de depuración y cambiará las claves de ordenación por defecto a: mem, snoop, tlb, type.

-U, --hide-unresolved

Mostrar solo entradas resueltas a un símbolo.

-x, --field-separator=<separador>

Especifica el separador de campos utilizado al volcar muestras crudas (opción -D). Por defecto, el separador es el carácter de espacio.

Además, para reportar, todas las opciones de perf report son válidas, y para record, todas las opciones de perf record.

CÁLCULO DE SOBRECARGA

A diferencia de perf-report(1), que calcula la sobrecarga a partir del periodo real de la muestra, la sobrecarga de perf-mem se calcula utilizando el peso de la muestra. Por ejemplo, hay dos muestras en el archivo perf.data, ambas con el mismo periodo de muestra, pero una muestra con peso 180 y la otra con peso 20:

$ perf script -F period,data_src,weight,ip,sym
100000    629080842 |OP LOAD|LVL L3 hit|...     20       7e69b93ca524 strcmp
100000   1a29081042 |OP LOAD|LVL RAM hit|...   180   ffffffff82429168 memcpy
$ perf report -F overhead,symbol
50%   [.] strcmp
50%   [k] memcpy
$ perf mem report -F overhead,symbol
90%   [k] memcpy
10%   [.] strcmp

SELECCIÓN DE CAMPOS DE SALIDA

"perf mem report" añade una serie de nuevos campos de salida específicos de información de la fuente de datos en la muestra. Algunos de ellos tienen el mismo nombre que las claves de ordenación existentes ("mem" y "snoop"). Por lo tanto, a diferencia de otros campos y claves de ordenación, se comportarán de manera diferente cuando se utilicen con -F/--fields o -s/--sort.

Usar estos dos como campos de salida agregará todas las muestras y mostrará un desglose.

$ perf mem report -F mem,snoop
...
# ------ Memory -------  --- Snoop ----
#     RAM Uncach  Other     HitM  Other
# .....................  ..............
#
     3.5%   0.0%  96.5%    25.1%  74.9%

Pero usar el mismo nombre para las claves de ordenación agregará muestras para cada tipo por separado.

$ perf mem report -s mem,snoop
# Overhead       Samples  Memory access                            Snoop
# ........  ............  .......................................  ............
#
    47.99%          1509  L2 hit                                   N/A
    25.08%           338  core, same node Any cache hit            HitM
    10.24%         54374  N/A                                      N/A
     6.77%         35938  L1 hit

NAME

perf-mem - analyze memory access patterns

SYNOPSIS

 perf mem record [options] [<command> [arguments...]]
 perf mem report [options]

DESCRIPTION

The perf tool can also be used to analyze memory access patterns. This man page describes the memory-related options that are available.

COMMON OPTIONS

This man page describes the memory-related options that are available.

Common options apply to both record and report subcommands.

-j, --json
Output in JSON format.
-p, --phys-addresses
Display physical addresses.
-K, --kernel-sources
Show source code for kernel functions.
-S, --symbols
Show symbols.
-m, --modules
Show memory map.
-d, --data
Show data symbols.
-t, --threads
Show threads.
-f, --functions
Show functions.
-i, --individual
Show individual memory addresses.
-a, --all-cpus
Monitor all CPUs.
-C, --cpu <cpu list>
Monitor specified CPUs.
-u, --user-sources
Show source code for user-space functions.
-l, --line-info
Show line information.
-v, --verbose
Be more verbose.
-x, --extended <option>
Extended filtering, e.g. -x dso,symbol.
-I, --include-symbol <regex>
Sample only symbols that match regex.
-X, --exclude-symbol <regex>
Do not sample symbols that match regex.
-F, --foreground
Display the output in the foreground.
-w, --weight <key>
Display samples by key. Possible keys are ip, dso, symbol, hws, imm.

RECORD OPTIONS

-e, --event <event>
Event to profile. Default is cycles.
--filter <filter>
Event filtering.
-c, --count <count>
Sample count events per event.
--period <period>
Sample period events per event.
-o, --output-file <file>
Output file name.
-r, --realtime-runtime <runtime>
Runtime in seconds for realtime profiling.
-d, --delay <delay>
Profile delay seconds after the buffer is full.

REPORT OPTIONS

-s, --sort <key>
Sort output by key. Possible keys are percent, cpu, comm, dso, symbol, size.
-w, --weight <key>
Display samples by key. Possible keys are ip, dso, symbol, hws, imm.
-i, --individual
Show individual memory accesses.
-D, --dso
Display results per DSO.
-S, --symbols
Display results per symbol.
-t, --threads
Display results per thread.
-m, --modules
Display results per module.
-f, --functions
Display results per function.
-p, --phys-addresses
Display physical addresses.
-I, --include-symbol <regex>
Include only symbols matching regex.
-X, --exclude-symbol <regex>
Exclude symbols matching regex.

OVERHEAD CALCULATION

The overhead calculation is based on the number of samples collected. The percentage is calculated as:

 percentage = (samples_for_this_entry / total_samples) * 100

The following table shows an example of overhead calculation:

 Overhead  Samples  Command  Shared Object       Symbol
 --------  --------  -------  -------------  ------------------
  6.39%       101  core     [kernel.kimg]  handle_irq_event_percpu
  3.50%        69  RAM      [kernel.kimg]  do_page_fault
  0.03%       158  LFB      [kernel.kimg]  lock_acquire
  0.00%         2  Uncached [kernel.kimg]  unmap_page

In this example:

  • Overhead is the percentage of total samples.
  • Samples is the number of samples collected for that entry.
  • Command is the command that triggered the event.
  • Shared Object is the shared object where the symbol is located.
  • Symbol is the name of the symbol.

OUTPUT FIELD SELECTION

You can select which fields to display in the output using the following options:

     6.39%           101  core, same node Any cache hit            N/A
     3.50%            69  RAM hit                                  N/A
     0.03%           158  LFB/MAB hit                              N/A
     0.00%             2  Uncached hit                             N/A
