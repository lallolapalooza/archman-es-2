NOMBRE

perl5263delta - qué hay de nuevo para perl v5.26.3

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.26.2 y la versión 5.26.3.

Si está actualizando desde una versión anterior como la 5.26.1, primero lea perl5262delta, que describe las diferencias entre 5.26.1 y 5.26.2.

Seguridad

[CVE-2018-12015] Recorrido de directorios en el módulo Archive::Tar

Por defecto, Archive::Tar no permite extraer archivos fuera del directorio de trabajo actual. Sin embargo, este modo de extracción seguro podía ser eludido al colocar un enlace simbólico y un archivo regular con el mismo nombre en el archivo tar.

[GH #16580] https://github.com/Perl/perl5/issues/16580 [cpan #125523] https://rt.cpan.org/Ticket/Display.html?id=125523

[CVE-2018-18311] Desbordamiento de enteros que conduce a desbordamiento de búfer y fallo de segmentación

La aritmética de enteros en Perl_my_setenv() podía desbordarse cuando la longitud combinada del nombre y el valor de la variable de entorno excedía aproximadamente 0x7fffffff. Esto podría llevar a escribir más allá del final de un búfer asignado con datos suministrados por el atacante.

[GH #16560] https://github.com/Perl/perl5/issues/16560

[CVE-2018-18312] Escritura de desbordamiento de búfer en el heap en S_regatom (regcomp.c)

Una expresión regular manipulada podría causar una escritura de desbordamiento de búfer en el heap durante la compilación, lo que potencialmente permitiría la ejecución de código arbitrario.

[GH #16649] https://github.com/Perl/perl5/issues/16649

[CVE-2018-18313] Lectura de desbordamiento de búfer en el heap en S_grok_bslash_N (regcomp.c)

Una expresión regular manipulada podría causar una lectura de desbordamiento de búfer en el heap durante la compilación, lo que potencialmente permitiría la filtración de información sensible.

[GH #16554] https://github.com/Perl/perl5/issues/16554

[CVE-2018-18314] Escritura de desbordamiento de búfer en el heap en S_regatom (regcomp.c)

Una expresión regular manipulada podría causar una escritura de desbordamiento de búfer en el heap durante la compilación, lo que potencialmente permitiría la ejecución de código arbitrario.

[GH #16041] https://github.com/Perl/perl5/issues/16041

Cambios Incompatibles

No hay cambios intencionadamente incompatibles con 5.26.2. Si existen, son errores y solicitamos que envíe un informe. Consulte "Reportar Errores" a continuación.

Módulos y Pragmata

Módulos y Pragmata Actualizados

  • Archive::Tar se ha actualizado de la versión 2.24 a 2.24_01.
  • Module::CoreList se ha actualizado de la versión 5.20180414_26 a 5.20181129_26.

Diagnósticos

Se han realizado las siguientes adiciones o cambios en la salida diagnóstica, incluyendo advertencias y mensajes de error fatales. Para la lista completa de mensajes diagnósticos, consulte perldiag.

Diagnósticos Nuevos

Errores Nuevos

  • '\]' inesperado sin ') ' siguiente en (?[... en regex; marcado por <-- AQUÍ en m/%s/

    (F) Al analizar una clase de caracteres extendida se encontró un carácter ']' en un punto de la definición donde el único uso legal de ']' es cerrar la definición de la clase de caracteres como parte de un '])', es posible que haya olvidado el paréntesis de cierre, o haya confundido al analizador.

  • Se espera paréntesis de cierre para clase de caracteres extendida anidada en regex; marcado por <-- AQUÍ en m/%s/

    (F) Al analizar una clase de caracteres extendida anidada como:

    (?[ ... (?flags:(?[ ... ])) ... ])
                         ^

    se esperaba ver un paréntesis de cierre ')' (marcado por ^) pero no se encontró.

  • Se espera paréntesis de cierre para envoltorio de clase de caracteres extendida anidada en regex; marcado por <-- AQUÍ en m/%s/

    (F) Al analizar una clase de caracteres extendida anidada como:

    (?[ ... (?flags:(?[ ... ])) ... ])
                          ^

    se esperaba ver un paréntesis de cierre ')' (marcado por ^) pero no se encontró.

Reportar Errores

Si encuentra lo que cree que es un error, puede consultar la base de datos de errores de perl en https://rt.perl.org/ . También puede haber información en http://www.perl.org/ , la página principal de Perl.

Si cree que tiene un error no reportado, ejecute el programa perlbug incluido con su versión. Asegúrese de reducir su error a un caso de prueba pequeño pero suficiente. Su informe de error, junto con la salida de "perl -V", se enviará a perlbug@perl.org para ser analizado por el equipo de portabilidad de Perl.

Si el error que está informando tiene implicaciones de seguridad que hacen inapropiado enviarlo a una lista de correo archivada públicamente, consulte "INFORMACIÓN DE CONTACTO DE VULNERABILIDAD DE SEGURIDAD" en perlsec para obtener detalles sobre cómo informar el problema.

Dar las Gracias

NAME

perl5263delta - differences between Perl 5.26.2 and Perl 5.26.3

DESCRIPTION

Perl 5.26.3 is a maintenance release that fixes bugs and security vulnerabilities found in Perl 5.26.2.

Security

  • CVE-2018-16660: A buffer overflow vulnerability in the `S_parse_hex` function within the `pp_ctl.c` file could lead to a denial of service or potentially arbitrary code execution.

  • CVE-2018-16661: A buffer overflow vulnerability in the `regexp_diff` function within the `regcomp.c` file could lead to a denial of service or potentially arbitrary code execution.

  • CVE-2018-16662: A buffer overflow vulnerability in the `utf8_to_bytes` function within the `utf8.c` file could lead to a denial of service or potentially arbitrary code execution.

Incompatible Changes

No incompatible changes were introduced in this release.

Modules and Pragmata

  • B::Hooks::Parser::Code: Fixed a bug where `subname` was not set correctly when using `B::Hooks::Parser::Code`.

  • JSON::PP: Fixed a bug where `JSON::PP` would not correctly decode certain Unicode characters.

  • Unicode::UCD: Updated to support Unicode 11.0.0.

Diagnostics

No new diagnostics were added in this release.

Acknowledgements

The Perl 5 Porters would like to thank the Perl community for its continued support and contributions.

Reporting Bugs

Please report any bugs you find to the Perl bug tracker at https://rt.perl.org/.

Give Thanks

If you would like to show your appreciation for Perl, please consider donating to The Perl Foundation.

SEE ALSO
