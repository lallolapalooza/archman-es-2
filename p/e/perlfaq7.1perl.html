¿Puedo obtener una BNF/yacc/RE para el lenguaje Perl?

No hay BNF, pero puedes examinar la gramática yacc en perly.y en la distribución fuente si eres particularmente valiente. La gramática depende de un código de tokenización muy inteligente, así que prepárate para adentrarte también en toke.c.

En palabras de Chaim Frenkel: "La gramática de Perl no se puede reducir a BNF. El trabajo de parsear perl se distribuye entre yacc, el lexer, humo y espejos."

¿Cuáles son todos estos signos de puntuación $@%&* y cómo sé cuándo usarlos?

Son especificadores de tipo, como se detalla en perldata:

$ para valores escalares (número, cadena o referencia)
@ para arrays
% para hashes (arrays asociativos)
& para subrutinas (también conocidas como funciones, procedimientos, métodos)
* para todos los tipos de ese nombre de símbolo. En la versión 4 se usaban como
  punteros, pero en las versiones modernas de Perl puedes usar referencias.

Hay un par de otros símbolos que es probable que encuentres y que no son realmente especificadores de tipo:

<> se usan para leer un registro de un manejador de archivo.
\  toma una referencia a algo.

Ten en cuenta que <FILE> *no* es el especificador de tipo para archivos ni el nombre del manejador. Es el operador "<>" aplicado al manejador FILE. Lee una línea (bueno, un registro; ver "$/" en perlvar) del manejador FILE en contexto escalar, o *todas* las líneas en contexto de lista. Al realizar open, close, o cualquier otra operación que no sea "<>" sobre archivos, o incluso al hablar del manejador, *no* uses los corchetes. Estos son correctos: eof(FH), "seek(FH, 0, 2)" y "copiando desde STDIN a FILE".

¿Siempre/nunca tengo que citar mis cadenas o usar puntos y comas y comas?

Normalmente, una palabra desnuda no necesita ser citada, pero en la mayoría de los casos probablemente debería serlo (y debe serlo bajo "use strict"). Pero una clave de hash que consiste en una palabra simple y el operando izquierdo del operador "=>" se consideran como si estuvieran citados:

Esto                    es como esto
------------            ---------------
$foo{line}              $foo{'line'}
bar => stuff            'bar' => stuff

El punto y coma final en un bloque es opcional, al igual que la coma final en una lista. Un buen estilo (ver perlstyle) dice que los pongas, excepto para los one-liners:

if ($whoops) { exit 1 }
my @nums = (1, 2, 3);
if ($whoops) {
    exit 1;
}
my @lines = (
    "There Beren came from mountains cold",
    "And lost he wandered under leaves",
);

¿Cómo ignoro algunos valores de retorno?

Una forma es tratar los valores de retorno como una lista e indexarla en ella:

$dir = (getpwnam($user))[7];

Otra forma es usar undef como elemento en el lado izquierdo:

($dev, $ino, undef, undef, $uid, $gid) = stat($file);

También puedes usar un slice de lista para seleccionar solo los elementos que necesitas:

($dev, $ino, $uid, $gid) = ( stat($file) )[0,1,4,5];

¿Cómo bloqueo temporalmente las advertencias?

Si estás ejecutando Perl 5.6.0 o superior, el pragma "use warnings" permite un control fino sobre qué advertencias se producen. Ver perllexwarn para más detalles.

{
    no warnings;          # desactiva temporalmente las advertencias
    $x = $y + $z;         # sé que estos pueden ser undef
}

Además, puedes habilitar y deshabilitar categorías de advertencias. Desactivas las categorías que quieres ignorar y aún puedes recibir otras categorías de advertencias. Ver perllexwarn para los detalles completos, incluyendo los nombres de las categorías y su jerarquía.

{
    no warnings 'uninitialized';
    $x = $y + $z;
}

Si tienes una versión anterior de Perl, la variable $^W (documentada en perlvar) controla las advertencias en tiempo de ejecución para un bloque:

{
    local $^W = 0;        # desactiva temporalmente las advertencias
    $x = $y + $z;         # sé que estos pueden ser undef
}

Ten en cuenta que, como todas las variables de puntuación, actualmente no puedes usar my() en $^W, solo local().

¿Qué es una extensión?

Una extensión es una forma de llamar código C compilado desde Perl. Leer perlxstut es un buen lugar para aprender más sobre extensiones.

¿Por qué los operadores de Perl tienen diferente precedencia que los operadores de C?

En realidad, no la tienen. Todos los operadores de C que Perl copia tienen la misma precedencia en Perl que en C. El problema está con los operadores que C no tiene, especialmente las funciones que dan un contexto de lista a todo lo que está a su derecha, por ejemplo, print, chmod, exec, y así sucesivamente. Dichas funciones se llaman "operadores de lista" y aparecen como tales en la tabla de precedencia de perlop.

Un error común es escribir:

unlink $file || die "snafu";

Esto se interpreta como:

unlink ($file || die "snafu");

Para evitar este problema, añade paréntesis adicionales o usa el operador "or" de precedencia súper baja:

(unlink $file) || die "snafu";
unlink $file or die "snafu";

Los operadores "ingleses" ("and", "or", "xor" y "not") tienen deliberadamente una precedencia inferior a la de los operadores de lista para situaciones como la anterior.

Otro operador con una precedencia sorprendente es la exponenciación. Se une más fuertemente que el menos unario, lo que hace que "-2**2" produzca un menos cuatro y no un positivo. También es asociativo por la derecha, lo que significa que "2**3**2" es dos elevado a la novena potencia, no ocho al cuadrado.

Aunque tiene la misma precedencia que en C, el operador "?:" de Perl produce un lvalue. Esto asigna $x a $if_true o $if_false, dependiendo de la veracidad de $maybe:

($maybe ? $if_true : $if_false) = $x;

¿Cómo declaro/creo una estructura?

En general, no se "declara" una estructura. Simplemente usa una referencia a hash (probablemente anónima). Ver perlref y perldsc para detalles. Aquí hay un ejemplo:

$person = {};                   # nuevo hash anónimo
$person->{AGE}  = 24;           # establecer campo AGE a 24
$person->{NAME} = "Nat";        # establecer campo NAME a "Nat"

Si buscas algo un poco más riguroso, prueba perlootut.

¿Cómo creo una clase?

(contribuido por brian d foy)

En Perl, una clase es solo un paquete y los métodos son solo subrutinas. Perl no va más allá de eso y le permite configurar el paquete de la manera que le guste (es decir, no configura nada por usted).

Vea también perlootut, un tutorial que cubre la creación de clases, y perlobj.

Puede utilizar la función tainted() del módulo Scalar::Util, disponible en CPAN (o incluido con Perl desde la versión 5.8.0). Vea también "Laundering and Detecting Tainted Data" en perlsec.

¿Qué es un cierre?

Los cierres se documentan en perlref.

Cierre es un término de la informática con un significado preciso pero difícil de explicar. Por lo general, los cierres se implementan en Perl como subrutinas anónimas con referencias duraderas a variables léxicas fuera de sus propios ámbitos. Estos léxicos se refieren mágicamente a las variables que estaban presentes cuando se definió la subrutina (vinculación profunda).

Los cierres se utilizan con mayor frecuencia en lenguajes de programación donde el valor de retorno de una función puede ser, a su vez, una función, como se puede hacer en Perl. Tenga en cuenta que algunos lenguajes proporcionan funciones anónimas pero no son capaces de proporcionar cierres adecuados: por ejemplo, Python 2. Para obtener más información sobre los cierres, consulte cualquier libro de texto sobre programación funcional. Scheme es un lenguaje que no solo admite sino que fomenta los cierres.

Aquí hay una función clásica que genera funciones que no son cierres:

sub add_function_generator {
    return sub { shift() + shift() };
}
my $add_sub = add_function_generator();
my $sum = $add_sub->(4,5);                # $sum es 9 ahora.

La subrutina anónima devuelta por add_function_generator() no es técnicamente un cierre porque no se refiere a ninguna variable léxica fuera de su propio ámbito. Usar un cierre le proporciona una *plantilla de función* con algunas ranuras de personalización dejadas para ser llenadas más tarde.

Compare esto con la siguiente función make_adder(), en la que la función anónima devuelta contiene una referencia a una variable léxica fuera del ámbito de esa función. Dicha referencia requiere que Perl devuelva un cierre adecuado, bloqueando así para siempre el valor que tenía la variable léxica cuando se creó la función.

sub make_adder {
    my $addpiece = shift;
    return sub { shift() + $addpiece };
}
my $f1 = make_adder(20);
my $f2 = make_adder(555);

Ahora $f1->($n) es siempre 20 más lo que sea que le pase a $n, mientras que $f2->($n) es siempre 555 más lo que sea que le pase a $n. La variable $addpiece en el cierre permanece.

Los cierres se utilizan a menudo para fines menos esotéricos. Por ejemplo, cuando desea pasar un fragmento de código a una función:

my $line;
timeout( 30, sub { $line = <STDIN> } );

Si el código a ejecutar se hubiera pasado como una cadena, '$line = <STDIN>', no habría habido forma de que la función hipotética timeout() accediera a la variable léxica $line de vuelta en el ámbito de su llamador.

Otro uso de un cierre es hacer que una variable sea *privada* para una subrutina nombrada, por ejemplo, un contador que se inicializa en el momento de creación de la subrutina y solo se puede modificar desde dentro de la subrutina. Esto a veces se usa con un bloque BEGIN en archivos de paquete para asegurarse de que una variable no sea manipulada durante la vida útil del paquete:

BEGIN {
    my $id = 0;
    sub next_id { ++$id }
}

Esto se discute con más detalle en perlsub; vea la entrada sobre *Variables Privadas Persistentes*.

¿Qué es el suicidio de variables y cómo puedo evitarlo?

Este problema se solucionó en perl 5.004_05, por lo que evitarlo significa actualizar su versión de perl. ;)

El suicidio de variables es cuando usted (temporal o permanentemente) pierde el valor de una variable. Es causado por la interacción del ámbito a través de my() y local() con cierres o variables de iterador foreach() aliadas y argumentos de subrutina. Solía ser fácil perder inadvertidamente el valor de una variable de esta manera, pero ahora es mucho más difícil. Considere este código:

my $f = 'foo';
sub T {
    while ($i++ < 3) { my $f = $f; $f .= "bar"; print $f, "\n" }
}
T;
print "Finalmente $f\n";

Si está experimentando suicidio de variables, ese "my $f" en la subrutina no toma una copia nueva del $f cuyo valor es 'foo'. La salida muestra que dentro de la subrutina, el valor de $f se filtra cuando no debería, como en esta salida:

foobar
foobarbar
foobarbarbar
Finalmente foo

El $f al que se le agrega "bar" tres veces debería ser un nuevo $f. "my $f" debería crear una nueva variable léxica cada vez que se recorre el bucle. La salida esperada es:

foobar
foobar
foobar
Finalmente foo

¿Cómo puedo pasar/devolver una {Función, Descriptor de archivo, Arreglo, Hash, Método, Expresión regular}?

Necesita pasar referencias a estos objetos. Vea "Pass by Reference" en perlsub para esta pregunta en particular, y perlref para obtener información sobre referencias.

Pasar Variables y Funciones
Las variables y funciones regulares son bastante fáciles de pasar: simplemente pase una referencia a una variable o función existente o anónima: 
func( \$some_scalar );
func( \@some_array  );
func( [ 1 .. 10 ]   );
func( \%some_hash   );
func( { this => 10, that => 20 }   );
func( \&some_func   );
func( sub { $_[0] ** $_[1] }   );
Pasar Descriptores de archivo
Desde Perl 5.6, puede representar descriptores de archivo con variables escalares que trata como cualquier otro escalar. 
open my $fh, $filename or die "Cannot open $filename! $!";
func( $fh );
sub func {
    my $passed_fh = shift;
    my $line = <$passed_fh>;
}

Antes de Perl 5.6, tenía que usar las notaciones *FH o "\*FH". Estos son "typeglobs" (globos de tipo); vea "Typeglobs and Filehandles" en perldata y especialmente "Pass by Reference" en perlsub para más información.

Pasar Expresiones regulares
Aquí hay un ejemplo de cómo pasar una cadena y una expresión regular para que coincida: Construye el patrón con el operador "qr//": 
sub compare {
    my ($val1, $regex) = @_;
    my $retval = $val1 =~ /$regex/;
    return $retval;
}
$match = compare("old McDonald", qr/d.*D/i);
Pasar Métodos
Para pasar un método de objeto a una subrutina, puede hacer esto: 
call_a_lot(10, $some_obj, "methname")
sub call_a_lot {
    my ($count, $widget, $trick) = @_;
    for (my $i = 0; $i < $count; $i++) {
        $widget->$trick();
    }
}

O, puede usar un cierre para agrupar el objeto, la llamada a su método y los argumentos:

my $whatnot = sub { $some_obj->obfuscate(@args) };
func($whatnot);
sub func {
    my $code = shift;
    &$code();
}

También podría investigar el método can() en la clase UNIVERSAL (parte de la distribución estándar de perl).

¿Cómo creo una variable estática?

(contribuido por brian d foy)

En Perl 5.10, declare la variable con "state". La declaración "state" crea la variable léxica que persiste entre llamadas a la subrutina:

sub counter { state $count = 1; $count++ }

Puede simular una variable estática usando una variable léxica que sale del ámbito. En este ejemplo, define la subrutina "counter", y esta utiliza la variable léxica $count. Dado que envuelve esto en un bloque BEGIN, $count se define en tiempo de compilación, pero también sale del ámbito al final del bloque BEGIN. El bloque BEGIN también asegura que la subrutina y el valor que utiliza se definan en tiempo de compilación, por lo que la subrutina está lista para usarla como cualquier otra subrutina, y puede colocar este código en el mismo lugar que otras subrutinas en el texto del programa (es decir, al final del código, típicamente). ¿Cuál es la diferencia entre el alcance dinámico y léxico (estático)? ¿Entre local() y my()?

local($x) guarda el valor anterior de la variable global $x y le asigna un nuevo valor durante la duración de la subrutina, *el cual es visible en otras funciones llamadas desde esa subrutina*. Esto se hace en tiempo de ejecución, por lo que se llama alcance dinámico. local() siempre afecta a las variables globales, también llamadas variables de paquete o variables dinámicas.

my($x) crea una nueva variable que solo es visible en la subrutina actual. Esto se hace en tiempo de compilación, por lo que se llama alcance léxico o estático. my() siempre afecta a las variables privadas, también llamadas variables léxicas o (impropiamente) variables de alcance estático.

Por ejemplo:

sub visible {
    print "La variable tiene el valor $var\n";
}
sub dynamic {
    local $var = 'local';    # Nuevo valor temporal para la variable
    visible();              # todavía global llamada $var
}
sub lexical {
    my $var = 'privada';    # Nueva variable privada, $var
    visible();              # (invisible fuera del alcance de la subrutina)
}

Aquí se muestra cómo se declara una variable privada de función porque solo una función recordaba su referencia. Puede definir múltiples funciones mientras la variable está en alcance, y cada función puede compartir la variable "privada". En realidad, no es "estática" porque puede acceder a ella fuera de la función mientras la variable léxica está en alcance, e incluso crear referencias a ella. En este ejemplo, "increment_count" y "return_count" comparten la variable. Una función suma al valor y la otra simplemente devuelve el valor. Ambas pueden acceder a $count, y como ha salido de alcance, no hay otra forma de acceder a ella.

BEGIN {
    my $count = 1;
    sub increment_count { $count++ }
    sub return_count    { $count }
}

Para declarar una variable privada de archivo, todavía se usa una variable léxica. Un archivo también es un alcance, por lo que una variable léxica definida en el archivo no puede ser vista desde ningún otro archivo.

Vea "Variables Privadas Persistentes" en perlsub para más información. La discusión sobre cierres en perlref puede ayudarle aunque no hayamos usado subrutinas anónimas en esta respuesta. Vea "Variables Privadas Persistentes" en perlsub para más detalles.

¿Cómo puedo acceder a una variable dinámica mientras hay una variable léxica con el mismo nombre en alcance?

Si conoce su paquete, puede mencionarlo explícitamente, como en $Some_Pack::var. Tenga en cuenta que la notación $::var *no* es la variable dinámica $var en el paquete actual, sino la del paquete "main", como si hubiera escrito $main::var.

use vars '$var';
local $var = "global";
my    $var = "lexical";
print "léxico es $var\n";
print "global  es $main::var\n";

Alternativamente, puede usar la directiva del compilador our() para traer una variable dinámica al alcance léxico actual.

require 5.006; # our() no existía antes de 5.6
use vars '$var';
local $var = "global";
my $var    = "lexical";
print "léxico es $var\n";
{
    our $var;
    print "global  es $var\n";
}

¿Cuál es la diferencia entre enlace profundo y superficial?

En el enlace profundo, las variables léxicas mencionadas en subrutinas anónimas son las mismas que estaban en alcance cuando se creó la subrutina. En el enlace superficial, son cualesquiera variables con los mismos nombres que ocurran en alcance cuando se llama a la subrutina. Perl siempre usa enlace profundo de variables léxicas (es decir, las creadas con my()). Sin embargo, las variables dinámicas (también conocidas como globales, locales o de paquete) están efectivamente enlazadas superficialmente. Considere esto solo una razón más para no usarlas. Vea la respuesta a "¿Qué es un cierre?".

¿Por qué "my($foo) = <$fh>;" no funciona bien?

my() y local() dan contexto de lista al lado derecho de "=". La operación de lectura <$fh>, como muchas de las funciones y operadores de Perl, puede detectar en qué contexto fue llamada y se comporta adecuadamente. En general, la función scalar() puede ayudar. Esta función no hace nada a los datos en sí (contrariamente al mito popular), sino que le indica a su argumento que se comporte según su forma escalar. Si esa función no tiene un comportamiento escalar definido, esto por supuesto no le ayuda (como con sort()).

Sin embargo, para forzar el contexto escalar en este caso particular, simplemente necesita omitir los paréntesis:

local($foo) = <$fh>;        # INCORRECTO
local($foo) = scalar(<$fh>);   # ok
local $foo  = <$fh>;        # correcto

Probablemente debería usar variables léxicas de todos modos, aunque el problema es el mismo aquí:

my($foo) = <$fh>;    # INCORRECTO
my $foo  = <$fh>;    # correcto

¿Cuál es la diferencia entre llamar a una función como &foo y foo()?

(contribuido por brian d foy)

Llamar a una subrutina como &foo sin paréntesis finales ignora el prototipo de "foo" y le pasa el valor actual de la lista de argumentos, @_. Aquí hay un ejemplo; la subrutina "bar" llama a &foo, que imprime su lista de argumentos:

sub foo { print "Los argumentos en foo son: @_\n"; }
sub bar { &foo; }
bar( "a", "b", "c" );

Cuando llama a "bar" con argumentos, verá que "foo" recibió el mismo @_:

Los argumentos en foo son: a b c

Llamar a la subrutina con paréntesis finales, con o sin argumentos, no usa el @_ actual. Cambiar el ejemplo para poner paréntesis después de la llamada a "foo" cambia el programa:

sub foo { print "Los argumentos en foo son: @_\n"; }
sub bar { &foo(); }
bar( "a", "b", "c" );

Ahora la salida muestra que "foo" no recibe el @_ de su llamador.

Los argumentos en foo son:

Sin embargo, usar "&" en la llamada aún anula el prototipo de "foo" si está presente:

sub foo ($$$) { print "Los argumentos en foo son: @_\n"; }
sub bar_1 { &foo; }
sub bar_2 { &foo(); }
sub bar_3 { foo( $_[0], $_[1], $_[2] ); }
# sub bar_4 { foo(); }
# bar_4 no compila: "Not enough arguments for main::foo at ..."
bar_1( "a", "b", "c" );
# Los argumentos en foo son: a b c
bar_2( "a", "b", "c" );
# Los argumentos en foo son:
bar_3( "a", "b", "c" );
# Los argumentos en foo son: a b c

El uso principal de la característica de paso de @_ es para escribir subrutinas cuyo trabajo principal es llamar a otras subrutinas por usted. Para más detalles, vea perlsub.

¿Cómo creo una sentencia switch o case?

Hay una sentencia given/when en Perl, pero es experimental y será eliminada en Perl 5.42. Vea perlsyn para más detalles.

La respuesta general es usar un módulo de CPAN como Switch::Plain:

use Switch::Plain;
sswitch($variable_que_contiene_un_string) {
    case 'primero': { }
    case 'segundo': { }
    default: { }
}

o para comparaciones más complicadas, "if-elsif-else":

for ($variable_a_probar) {
    if    (/pat1/)  { }     # hacer algo
    elsif (/pat2/)  { }     # hacer otra cosa
    elsif (/pat3/)  { }     # hacer otra cosa
    else            { }     # por defecto
}

Aquí hay un ejemplo simple de un switch basado en coincidencia de patrones, alineado de una manera para que se parezca más a una sentencia switch. Haremos un condicional de múltiples vías basado en el tipo de referencia almacenada en $whatchamacallit:

SWITCH: for (ref $whatchamacallit) {
    /^$/           && die "no es una referencia";
    /SCALAR/       && do {
                    print_scalar($$ref);
last SWITCH; }; /ARRAY/ && do { print_array(@$ref); last SWITCH; }; /HASH/ && do { print_hash(%$ref); last SWITCH; }; /CODE/ && do { warn "can't print function ref"; last SWITCH; }; # DEFAULT warn "User defined type skipped"; }

Ver perlsyn para otros ejemplos en este estilo.

A veces deberías cambiar la posición de la constante y la variable. Por ejemplo, digamos que querías probar cuál de las muchas respuestas que te dieron era correcta, pero de forma insensible a mayúsculas y minúsculas que también permitiera abreviaturas. Puedes usar la siguiente técnica si las cadenas comienzan todas con caracteres diferentes o si quieres organizar las coincidencias de forma que una tenga precedencia sobre otra, como "SEND" tiene precedencia sobre "STOP" aquí:

chomp($answer = <>);
if    ("SEND"  =~ /^\Q$answer/i) { print "Action is send\n"  }
elsif ("STOP"  =~ /^\Q$answer/i) { print "Action is stop\n"  }
elsif ("ABORT" =~ /^\Q$answer/i) { print "Action is abort\n" }
elsif ("LIST"  =~ /^\Q$answer/i) { print "Action is list\n"  }
elsif ("EDIT"  =~ /^\Q$answer/i) { print "Action is edit\n"  }

Un enfoque totalmente diferente es crear un hash de referencias a funciones.

my %commands = (
    "happy" => \&joy,
    "sad"   => \&sullen,
    "done"  => sub { die "See ya!" },
    "mad"   => \&angry,
);
print "How are you? ";
chomp($string = <STDIN>);
if ($commands{$string}) {
    $commands{$string}->();
} else {
    print "No such command: $string\n";
}

A partir de Perl 5.8, un módulo de filtro de origen, "Switch", también se puede utilizar para obtener switch y case. Su uso ahora está desaconsejado, ya que no es totalmente compatible con el switch nativo de Perl 5.10, y como está implementado como un filtro de origen, no siempre funciona como se pretende cuando intervienen sintaxis complejas.

¿Cómo puedo capturar accesos a variables, funciones o métodos indefinidos?

El método AUTOLOAD, discutido en "Autoloading" en perlsub, te permite capturar llamadas a funciones y métodos indefinidos.

Cuando se trata de variables indefinidas que activarían una advertencia bajo "use warnings", puedes promover la advertencia a un error.

use warnings FATAL => qw(uninitialized);

¿Por qué no se encuentra un método incluido en este mismo archivo?

Algunas posibles razones: tu herencia se está confundiendo, has escrito mal el nombre del método, o el objeto es del tipo incorrecto. Consulta perlootut para obtener detalles sobre cualquiera de los casos anteriores. También puedes usar "print ref($object)" para averiguar en qué clase se bendijo $object.

Otra posible razón de problemas es que hayas utilizado la sintaxis de objeto indirecto (por ejemplo, "find Guru "Samy"") en un nombre de clase antes de que Perl haya visto que dicho paquete existe. Es más sensato asegurarse de que todos los paquetes estén definidos antes de empezar a usarlos, lo que se gestionará si utilizas la declaración "use" en lugar de "require". Si no, asegúrate de usar la notación de flecha (por ejemplo, "Guru->find("Samy")") en su lugar. La notación de objetos se explica en perlobj.

Asegúrate de leer sobre la creación de módulos en perlmod y los peligros de los objetos indirectos en "Method Invocation" en perlobj.

¿Cómo puedo saber mi paquete actual o el que llama?

(contribuido por brian d foy)

Para saber el paquete en el que te encuentras actualmente, utiliza la literal especial "__PACKAGE__", tal como se documenta en perldata. Solo puedes usar las literales especiales como tokens separados, por lo que no puedes interpolarlas en cadenas como puedes hacer con las variables:

my $current_package = __PACKAGE__;
print "I am in package $current_package\n";

Si quieres saber el paquete que llama a tu código, quizás para proporcionar mejores diagnósticos como hace Carp, utiliza la función incorporada "caller":

sub foo {
    my @args = ...;
    my( $package, $filename, $line ) = caller;
    print "I was called from package $package\n";
};

Por defecto, tu programa comienza en el paquete "main", por lo que siempre estarás en algún paquete.

Esto es diferente de averiguar el paquete en el que se ha bendecido un objeto, que podría no ser el paquete actual. Para eso, utiliza "blessed" de Scalar::Util, parte de la Biblioteca Estándar desde Perl 5.8:

use Scalar::Util qw(blessed);
my $object_package = blessed( $object );

La mayoría de las veces, no deberías preocuparte por el paquete en el que se ha bendecido un objeto, sin embargo, siempre que afirme heredar de esa clase:

my $is_right_class = eval { $object->isa( $package ) }; # true or false

Y, con Perl 5.10 y posteriores, no tienes que comprobar la herencia para ver si el objeto puede manejar un rol. Para eso, puedes usar "DOES", que proviene de "UNIVERSAL":

my $class_does_it = eval { $object->DOES( $role ) }; # true or false

Puedes reemplazar de forma segura "isa" por "DOES" (aunque lo contrario no es cierto).

¿Cómo puedo comentar un gran bloque de código Perl?

(contribuido por brian d foy)

La forma rápida y sucia de comentar más de una línea de Perl es rodeando esas líneas con directivas Pod. Tienes que poner estas directivas al principio de la línea y en algún lugar donde Perl espere una nueva sentencia (así que no en medio de sentencias como los comentarios "#"). Terminas el comentario con "=cut", terminando la sección Pod:

=pod
my $object = NotGonnaHappen->new();
ignored_sub();
$wont_be_assigned = 37;
=cut

El método rápido y sucio solo funciona bien cuando no planeas dejar el código comentado en el fuente. Si un analizador Pod aparece, tu comentario multilínea se mostrará en la traducción de Pod. Una mejor manera lo oculta también de los analizadores Pod.

La directiva "=begin" puede marcar una sección para un propósito particular. Si el analizador Pod no quiere manejarla, simplemente la ignora. Etiqueta los comentarios con "comment". Termina el comentario usando "=end" con la misma etiqueta. Todavía necesitas el "=cut" para volver al código Perl desde el comentario Pod:

=begin comment
my $object = NotGonnaHappen->new();
ignored_sub();
$wont_be_assigned = 37;
=end comment
=cut

Para más información sobre Pod, consulta perlpod y perlpodspec.

¿Cómo limpio un paquete?

Usa este código, proporcionado por Mark-Jason Dominus:

sub scrub_package {
    no strict 'refs';
    my $pack = shift;
    die "Shouldn't delete main package"
        if $pack eq "" || $pack eq "main";
    my $stash = *{$pack . '::'}{HASH};
    my $name;
    foreach $name (keys %$stash) {
        my $fullname = $pack . '::' . $name;
        # Get rid of everything with that name.
        undef $$fullname;
        undef @$fullname;
        undef %$fullname;
        undef &$fullname;
        undef *$fullname;
    }
}

O, si estás usando una versión reciente de Perl, puedes simplemente usar la función Symbol::delete_package() en su lugar.

¿Cómo puedo usar una variable como nombre de variable?

Los principiantes a menudo piensan que quieren que una variable contenga el nombre de una variable.

$fred    = 23;
$varname = "fred";
++$$varname;         # $fred ahora 24

Esto funciona *a veces*, pero es una muy mala idea por dos razones.

La primera razón es que esta técnica *solo funciona en variables globales*. Eso significa que si $fred es una variable léxica creada con my() en el ejemplo anterior, el código no funcionaría en absoluto: accederías accidentalmente a la global y te saltarías por completo la léxica privada. Las variables globales son malas porque pueden colisionar accidentalmente con facilidad y, en general, hacen que el código sea no escalable y confuso.

Las referencias simbólicas están prohibidas bajo el pragmatismo "use strict". No son referencias reales y, en consecuencia, no se cuentan por referencia ni se recolectan como basura.

La otra razón por la que usar una variable para contener el nombre de otra variable es una mala idea es que la pregunta a menudo surge de una falta de comprensión de las estructuras de datos de Perl, particularmente los hashes. Al usar referencias simbólicas, solo estás usando el hash de tabla de símbolos del paquete (como %main::) en lugar de un hash definido por el usuario. La solución es usar tu propio hash o una referencia real en su lugar.

$USER_VARS{"fred"} = 23;
my $varname = "fred";
$USER_VARS{$varname}++;  # not $$varname++

Ahí estamos usando el hash %USER_VARS en lugar de referencias simbólicas. A veces, esto surge al leer cadenas del usuario con referencias a variables y querer expandirlas a los valores de las variables de tu programa perl. Esto también es una mala idea porque mezcla el espacio de nombres direccionable por el programa y el direccionable por el usuario. En lugar de leer una cadena y expandirla al contenido real de las variables de tu propio programa:

$str = 'this has a $fred and $barney in it';
$str =~ s/(\$\w+)/$1/eeg;          # need double eval

REFERENCIAS SIMBÓLICAS

Algunas personas quieren que una variable escalar contenga el nombre de una variable (ya sea un escalar, un array o un hash) y luego usan esa variable escalar para acceder a la variable original. Esto se llama una referencia simbólica.

Por ejemplo, supongamos que tienes un hash llamado %USER_VARS y quieres que las referencias a las variables realmente se refieran a entradas en ese hash:

$str =~ s/\$(\w+)/$USER_VARS{$1}/g; # sin /e aquí en absoluto

Eso es más rápido, más limpio y más seguro que el enfoque anterior. Por supuesto, no necesitas usar un signo de dólar. Podrías usar tu propio esquema para que sea menos confuso, como símbolos de porcentaje entre corchetes, etc.

$str = 'this has a %fred% and %barney% in it';
$str =~ s/%(\w+)%/$USER_VARS{$1}/g; # sin /e aquí en absoluto

Otra razón por la que la gente a veces piensa que quiere que una variable contenga el nombre de una variable es que no saben cómo construir estructuras de datos adecuadas utilizando hashes. Por ejemplo, digamos que querían dos hashes en su programa: %fred y %barney, y que querían usar otra variable escalar para referirse a ellos por nombre.

$name = "fred";
$$name{WIFE} = "wilma";     # establece %fred
$name = "barney";
$$name{WIFE} = "betty";    # establece %barney

Esto sigue siendo una referencia simbólica y todavía está cargada con los problemas enumerados anteriormente. Sería mucho mejor escribir:

$folks{"fred"}{WIFE}   = "wilma";
$folks{"barney"}{WIFE} = "betty";

Y simplemente usar un hash multinivel desde el principio.

Las únicas veces que *debes* usar referencias simbólicas es cuando realmente debes referirte a la tabla de símbolos. Esto puede ser porque es algo a lo que uno no puede tomar una referencia real, como un nombre de formato. Hacerlo también puede ser importante para las llamadas a métodos, ya que estas siempre pasan por la tabla de símbolos para su resolución.

En esos casos, desactivarías "strict 'refs'" temporalmente para poder jugar con la tabla de símbolos. Por ejemplo:

@colors = qw(red blue green yellow orange purple violet);
for my $name (@colors) {
    no strict 'refs';  # renuncia para el bloque
    *$name = sub { "<FONT COLOR='$name'>@_</FONT>" };
}

Todas esas funciones (red(), blue(), green(), etc.) parecen ser separadas, pero el código real en el cierre fue compilado solo una vez.

Por lo tanto, a veces querrás usar referencias simbólicas para manipular la tabla de símbolos directamente. Esto no importa para formatos, manejadores y subrutinas, porque siempre son globales; no puedes usar my() con ellas. Sin embargo, para escalares, arrays y hashes, y generalmente para subrutinas, probablemente solo querrás usar referencias reales.

¿Qué significa "intérprete erróneo"?

(contribuido por brian d foy)

El mensaje "intérprete erróneo" proviene del shell, no de perl. El mensaje real puede variar según su plataforma, shell y configuración de idioma.

Si ve "intérprete erróneo - no existe tal archivo o directorio", la primera línea de su script de perl (la línea "shebang") no contiene la ruta correcta a perl (o a cualquier otro programa capaz de ejecutar scripts). A veces esto sucede cuando mueve el script de una máquina a otra y cada máquina tiene una ruta diferente a perl: /usr/bin/perl versus /usr/local/bin/perl, por ejemplo. También puede indicar que la máquina de origen tiene terminadores de línea CRLF y la máquina de destino solo tiene LF: el shell intenta encontrar /usr/bin/perl, pero no puede.

Si ve "intérprete erróneo: Permiso denegado", necesita hacer que su script sea ejecutable.

En cualquier caso, aún debería poder ejecutar los scripts con perl explícitamente:

% perl script.pl

Si obtiene un mensaje como "perl: comando no encontrado", perl no está en su PATH, lo que también podría significar que la ubicación de perl no es donde espera, por lo que necesita ajustar su línea shebang.

¿Necesito recompilar los módulos XS cuando hay un cambio en la biblioteca C?

(contribuido por Alex Beamish)

Si la nueva versión de la biblioteca C es compatible con ABI (interfaz binaria de aplicación) con la versión de la que está actualizando, y si la versión de la biblioteca compartida no ha cambiado, no debería ser necesaria ninguna recompilación.
