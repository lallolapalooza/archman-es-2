¿Cómo puedo usar Perl interactivamente?

El enfoque típico utiliza el depurador de Perl, descrito en la página del manual perldebug(1), en un programa "vacío", así:

perl -de 42

Ahora solo escribe cualquier código Perl válido, y se evaluará inmediatamente. También puedes examinar la tabla de símbolos, obtener rastreos de pila, verificar valores de variables, establecer puntos de interrupción y otras operaciones que se encuentran típicamente en depuradores simbólicos.

También puedes usar Devel::REPL que es un shell interactivo para Perl, comúnmente conocido como REPL - Leer, Evaluar, Imprimir, Bucle. Proporciona varias características útiles.

¿Cómo encuentro qué módulos están instalados en mi sistema?

Desde la línea de comandos, puedes usar el modificador "-l" del comando "cpan":

$ cpan -l

También puedes usar el modificador "-a" de "cpan" para crear un archivo de autobundel que "CPAN.pm" entienda y pueda usar para reinstalar todos los módulos:

$ cpan -a

Dentro de un programa Perl, puedes usar el módulo ExtUtils::Installed para mostrar todas las distribuciones instaladas, aunque puede tardar un tiempo en hacer su magia. La biblioteca estándar que viene con Perl simplemente aparece como "Perl" (aunque puedes obtenerlas con Module::CoreList).

use ExtUtils::Installed;
my $inst    = ExtUtils::Installed->new();
my @modules = $inst->modules();

Si quieres una lista de todos los nombres de archivo de los módulos Perl, puedes usar File::Find::Rule:

use File::Find::Rule;
my @files = File::Find::Rule->
    extras({follow => 1})->
    file()->
    name( '*.pm' )->
    in( @INC )
    ;

Si no tienes ese módulo, puedes hacer lo mismo con File::Find que es parte de la biblioteca estándar:

use File::Find;
my @files;
find(
    {
    wanted => sub {
        push @files, $File::Find::fullname
        if -f $File::Find::fullname && /\.pm$/
    },
    follow => 1,
    follow_skip => 2,
    },
    @INC
);
print join "\n", @files;

Si simplemente necesitas verificar rápidamente si un módulo está disponible, puedes buscar su documentación. Si puedes leer la documentación, es muy probable que el módulo esté instalado. Si no puedes leer la documentación, es posible que el módulo no tenga ninguna (en casos raros):

$ perldoc Module::Name

También puedes intentar incluir el módulo en un one-liner para ver si Perl lo encuentra:

$ perl -MModule::Name -e1

(Si no recibes un mensaje de error "Can't locate ... in @INC", entonces Perl encontró el nombre del módulo que solicitaste.)

¿Cómo depuro mis programas Perl?

El depurador de Perl es un programa de línea de comandos muy rudimentario pero útil que viene con Perl. Para usarlo, ejecuta tu programa con el modificador "-d":

perl -d myprogram.pl

Si quieres ver el código fuente de tu programa en el depurador, escribe:

perl -d:Trace myprogram.pl

Consulta la página del manual perldebug(1) para obtener más información sobre cómo usar el depurador de Perl.

Existen varios módulos disponibles en CPAN que pueden ayudarte a depurar tu código. Algunos de los más populares incluyen:

Devel::REPL
Proporciona un entorno interactivo de tipo REPL (Read-Eval-Print-Loop) para Perl.
Devel::NYTProf
Un generador de perfiles de código Perl muy rápido y detallado.
Padre
Un IDE gráfico multiplataforma escrito en Perl, dirigido a principiantes y usuarios avanzados.
Term::Screen
Una interfaz de usuario de pantalla completa que puede usarse para crear aplicaciones interactivas y menús en la línea de comandos.

Puedes instalar estos módulos usando el comando "cpan" o "cpanm":

$ cpan Devel::REPL

Una vez instalados, puedes usarlos según sus respectivas documentaciones.

¿ms?

(contribuido por brian d foy)

Antes de hacer nada más, puedes ayudarte a ti mismo asegurándote de que Perl te informa sobre las áreas problemáticas en tu código. Al activar las advertencias y las directrices, puedes evitar muchos problemas antes de que se hagan demasiado grandes. Puedes encontrar más información sobre esto en strict y warnings.

#!/usr/bin/perl
use strict;
use warnings;

Más allá de eso, el depurador más simple es la función "print". Úsala para ver los valores mientras ejecutas tu programa:

print STDERR "El valor es [$valor]\n";

El módulo Data::Dumper puede imprimir estructuras de datos de Perl con formato:

use Data::Dumper qw( Dumper );
print STDERR "El hash es " . Dumper( \%hash ) . "\n";

Perl viene con un depurador interactivo, que puedes iniciar con el modificador "-d". Se explica completamente en perldebug.

Si deseas una interfaz gráfica de usuario y tienes Tk, puedes usar "ptkdb". Está en CPAN y disponible de forma gratuita.

Si necesitas algo mucho más sofisticado y controlable, Devel::ebug de Leon Brocard (al que puedes llamar con el modificador "-D" como "-Debug") te proporciona los ganchos programáticos para todo lo que necesitas para escribir tu propio depurador (sin demasiado dolor y sufrimiento).

También puedes usar un depurador comercial como Affrus (Mac OS X), Komodo de Activestate (Windows y Mac OS X) o EPIC (la mayoría de las plataformas).

¿Cómo puedo realizar un perfil de mis programas de Perl?

(contribuido por brian d foy, actualizado el vie 25 jul 12:22:26 PDT 2008)

El espacio de nombres "Devel" tiene varios módulos que puedes usar para realizar un perfil de tus programas de Perl.

Devel::NYTProf (New York Times Profiler) realiza perfiles tanto de sentencias como de subrutinas. Está disponible en CPAN y también se invoca con el modificador "-d":

perl -d:NYTProf some_perl.pl

Crea una base de datos con la información del perfil que puedes convertir en informes. El comando "nytprofhtml" convierte los datos en un informe HTML similar al informe de Devel::Cover:

nytprofhtml

También te puede interesar usar Benchmark para medir y comparar fragmentos de código.

Puedes leer más sobre perfiles en Programming Perl, capítulo 20, o Mastering Perl, capítulo 5.

perldebguts documenta la creación de un depurador personalizado si necesitas crear un tipo especial de generador de perfiles. brian d foy describe el proceso en The Perl Journal, "Creating a Perl Debugger", https://drdobbs.com/creating-a-perl-debugger/184404522 , y "Profiling in Perl" https://drdobbs.com/profiling-in-perl/184404580 .

Perl.com tiene dos artículos interesantes sobre perfiles: "Profiling Perl", por Simon Cozens, https://www.perl.com/pub/2004/06/25/profiling.html/ y "Debugging and Profiling mod_perl Applications", por Frank Wiles, http://www.perl.com/pub/a/2006/02/09/debug_mod_perl.html .

Randal L. Schwartz escribe sobre perfiles en "Speeding up Your Perl Programs" para Unix Review, http://www.stonehenge.com/merlyn/UnixReview/col49.html , y "Profiling in Template Toolkit via Overriding" para Linux Magazine, http://www.stonehenge.com/merlyn/LinuxMag/col75.html .

¿Existe un pretty-printer (formateador) para Perl?

Perl::Tidy viene con un script de Perl, perltidy, que indenta y reformula los scripts de Perl para hacerlos más fáciles de leer intentando seguir las reglas de perlstyle. Si escribes Perl, o pasas mucho tiempo leyendo Perl, probablemente lo encontrarás útil.

Por supuesto, si simplemente sigues las directrices de perlstyle, no deberías necesitar reformatear. El hábito de formatear tu código mientras lo escribes ayudará a prevenir errores. Tu editor puede y debe ayudarte con esto. El modo perl o el más nuevo cperl-mode para emacs pueden proporcionar una cantidad notable de ayuda con la mayoría del código (pero no todo), e incluso los editores menos programables pueden ofrecer una asistencia significativa. Tom Christiansen y muchos otros usuarios de VI juran por la siguiente configuración en vi y sus clones:

set ai sw=4
map! ^O {^M}^[O^T

Pon eso en tu archivo .exrc (reemplazando los caracteres de caret por caracteres de control) y listo. En modo de inserción, ^T es para indentar, ^D es para desindentar, y ^O es para indentar bloques, por así decirlo. Un ejemplo más completo, con comentarios, se puede encontrar en http://www.cpan.org/authors/id/T/TO/TOMC/scripts/toms.exrc.gz

¿Dónde puedo obtener perl-mode o cperl-mode para emacs?

Desde la versión 19 de Emacs, nivel de parche 22 o así, ha habido tanto perl-mode.el como soporte para el depurador de Perl incorporado. Estos deberían venir con la distribución estándar de Emacs 19.

Tenga en cuenta que el modo perl de emacs tendrá problemas con "main'foo" (comilla simple), y estropeará la indentación y el resaltado. Probablemente esté usando "main::foo" en código Perl nuevo de todos modos, así que esto no debería ser un problema.

Para CPerlMode, consulte https://www.emacswiki.org/emacs/CPerlMode

¿Cómo puedo escribir una GUI (X, Tk, Gtk, etc.) en Perl?

(Contribuido por Ben Morrow)

Hay una serie de módulos que le permiten escribir GUIs en Perl. La mayoría de los toolkits de GUI tienen una interfaz para Perl: una lista incompleta es la siguiente.

Tk
Esto funciona en Unix y Windows, y la versión actual no se ve tan mal en Windows como solía hacerlo. Algunos de los elementos de la GUI todavía no se "sienten" del todo bien, sin embargo. La interfaz es muy natural y "perlish", lo que facilita su uso en scripts pequeños que solo necesitan una GUI simple. No se ha actualizado en mucho tiempo.
Wx
Esta es una vinculación de Perl para el toolkit multiplataforma wxWidgets ( http://www.wxwidgets.org ). Funciona en Unix, Win32 y Mac OS X, utilizando widgets nativos (Gtk en Unix). La interfaz sigue de cerca la interfaz C++, pero la documentación es un poco escasa para alguien que no conoce la biblioteca, refiriéndose principalmente a la documentación de C++.
Gtk y Gtk2
Estas son vinculaciones de Perl para el toolkit Gtk ( http://www.gtk.org ). La interfaz cambió significativamente entre las versiones 1 y 2, por lo que tienen módulos de Perl separados. Se ejecuta en Unix, Win32 y Mac OS X (actualmente requiere un servidor X en Mac OS, pero un port "nativo" está en marcha), y los widgets se ven iguales en todas las plataformas: es decir, no coinciden con los widgets nativos. Al igual que con Wx, las vinculaciones de Perl siguen de cerca la API C, y la documentación requiere que lea la documentación de C para entenderla.
Win32::GUI
Esto proporciona acceso a la mayoría de los widgets GUI de Win32 desde Perl. Obviamente, solo se ejecuta en Win32 y utiliza widgets nativos. La interfaz de Perl no sigue realmente la interfaz C: se ha hecho más "perlish" y la documentación es bastante buena. Las cosas más avanzadas pueden requerir familiaridad con las API de Win32 de C, o referencia a MSDN.
CamelBones
CamelBones ( http://camelbones.sourceforge.net ) es una interfaz de Perl para el toolkit GUI Cocoa de Mac OS X y, como tal, se puede utilizar para producir GUIs nativas en Mac OS X. No está en CPAN, ya que requiere frameworks que CPAN.pm no sabe cómo instalar, pero la instalación se realiza a través del instalador de paquetes estándar de OSX. La API de Perl es, de nuevo, muy cercana a la API de ObjC que está envolviendo, y la documentación solo le dice cómo traducir de una a otra.
Qt
Existe una interfaz de Perl para el toolkit Qt de TrollTech, pero no parece estar mantenida.
Athena
Sx es una interfaz al conjunto de widgets Athena que viene con X, pero de nuevo, parece que ya no se usa mucho.

¿Cómo puedo hacer que mi programa Perl se ejecute más rápido?

La mejor manera de hacerlo es idear un algoritmo mejor. Esto a menudo puede marcar una diferencia drástica. El libro de Jon Bentley Programming Pearls (¡eso no es una errata!) también tiene algunos buenos consejos sobre optimización. Los consejos sobre benchmarking se reducen a: realizar benchmarks y perfiles para asegurarse de que está optimizando la parte correcta, buscar mejores algoritmos en lugar de microajustar su código y, cuando todo lo demás falla, considerar simplemente comprar hardware más rápido. Probablemente querrá leer la respuesta a la pregunta anterior "¿Cómo hago el perfil de mis programas Perl?" si aún no lo ha hecho.

Un enfoque diferente es cargar bajo demanda código Perl que rara vez se usa. Consulte los módulos AutoSplit y AutoLoader en la distribución estándar para eso. O podría localizar el cuello de botella y pensar en escribir solo esa parte en C, de la manera que solíamos tomar cuellos de botella en código C y escribirlos en ensamblador. Similar a reescribir en C, los módulos que tienen secciones críticas se pueden escribir en C (por ejemplo, el módulo PDL de CPAN).

Si actualmente está enlazando su ejecutable de perl a una libc.so compartida, a menudo puede obtener un beneficio de rendimiento del 10-25% recompilándolo para enlazar con una libc.a estática en su lugar. Esto hará un ejecutable de perl más grande, pero su programa Perl (y sus programadores) pueden agradecerle por ello. Consulte el archivo INSTALL en la distribución fuente para obtener más información.

El programa undump fue un antiguo intento de acelerar los programas Perl almacenando la forma ya compilada en el disco. Esta ya no es una opción viable, ya que solo funcionaba en algunas arquitecturas y, de todos modos, no era una buena solución.

¿Cómo puedo hacer que mi programa Perl consuma menos memoria?

Cuando se trata de intercambios tiempo-espacio, Perl casi siempre prefiere asignar memoria a un problema. Los escalares en Perl usan más memoria que las cadenas en C, los arrays toman más que eso, y los hashes usan aún más. Si bien todavía hay mucho por hacer, las versiones recientes han abordado estos problemas. Por ejemplo, a partir de la versión 5.004, las claves de hash duplicadas se comparten entre todos los hashes que las usan, por lo que no requieren reasignación.

¿Cómo puedo conseguir que "#!perl" funcione en [MS-DOS,NT,...]?

Para OS/2 simplemente usa

extproc perl -S -tus_switches

como la primera línea en un archivo "*.cmd" ("-S" debido a un bug en el manejo de "extproc" de cmd.exe). Para DOS, primero se debe inventar un archivo batch correspondiente y codificarlo en "ALTERNATE_SHEBANG" (ver el archivo dosish.h en la distribución fuente para más información).

La instalación de Win95/NT, al usar el puerto ActiveState de Perl, modificará el Registro para asociar la extensión ".pl" con el intérprete perl. Si instalas otro puerto, o incluso compilas tu propio Perl para Win95/NT a partir de las fuentes estándar usando un puerto de Windows de gcc (por ejemplo, con cygwin o mingw32), tendrás que modificar el Registro tú mismo. Además de asociar ".pl" con el intérprete, la gente de NT puede usar: "SET PATHEXT=%PATHEXT%;.PL" para permitirles ejecutar el programa "install-linux.pl" simplemente escribiendo "install-linux".

En el MacOS "Clásico", un programa perl tendrá el Creador y Tipo apropiados, de modo que al hacer doble clic en ellos se invocará la aplicación MacPerl. En Mac OS X, se pueden crear aplicaciones ejecutables a partir de cualquier script "#!" usando la utilidad DropScript de Wil Sanchez: http://www.wsanchez.net/software/ .

¡IMPORTANTE!: Hagas lo que hagas, POR FAVOR, no te frustres, y no tires el intérprete perl en tu directorio cgi-bin para que tus programas funcionen en un servidor web. Esto es un riesgo de seguridad EXTREMADAMENTE grande. Tómate el tiempo para averiguar cómo hacerlo correctamente.

¿Puedo escribir programas útiles de Perl en la línea de comandos?

Sí. Lee perlrun para más información. Algunos ejemplos a continuación. (Estos asumen las reglas de comillas estándar del shell Unix.)

# suma el primer y último campo
perl -lane 'print $F[0] + $F[-1]' *
# identifica archivos de texto
perl -le 'for(@ARGV) {print if -f && -T _}' *
# elimina (la mayoría) de comentarios de un programa C
perl -0777 -pe 's{/\*.*?\*/}{}gs' foo.c
# hace que un archivo sea un mes más joven que hoy, derrotando a los demonios recolectores
perl -e '$X=24*60*60; utime(time(),time() + 30 * $X,@ARGV)' *
# encuentra el primer uid no utilizado
perl -le '$i++ while getpwuid($i); print $i'
# muestra manpath razonable
echo $PATH | perl -nl -072 -e '
s![^/+]*$!man!&&-d&&!$s{$_}++&&push@m,$_;END{print"@m"}'

OK, el último fue en realidad una entrada del Concurso de Perl Ofuscada. :-)

¿Por qué los one-liners de Perl no funcionan en mi sistema DOS/Mac/VMS?

El problema suele ser que los intérpretes de comandos de esos sistemas tienen ideas bastante diferentes sobre las comillas en comparación con los shells de Unix bajo los cuales se crearon los one-liners. En algunos sistemas, es posible que tengas que cambiar las comillas simples por comillas dobles, lo cual *NO* debes hacer en sistemas Unix o Plan9. También podrías tener que cambiar un % simple por un %%.

Por ejemplo:

# Unix (incluido Mac OS X)
perl -e 'print "Hello world\n"'
# DOS, etc.
perl -e "print \"Hello world\n\""
# Mac Clásico
print "Hello world\n"
 (luego Ejecutar "Myscript" o Shift-Command-R)
# MPW
perl -e 'print "Hello world\n"'
# VMS
perl -e "print ""Hello world\n"""

El problema es que ninguno de estos ejemplos es fiable: dependen del intérprete de comandos. En Unix, los dos primeros a menudo funcionan. En DOS, es completamente posible que ninguno funcione. Si 4DOS fuera el shell de comandos, probablemente tendrías más suerte así:

perl -e "print <Ctrl-x>"Hello world\n<Ctrl-x>""

En Mac, depende del entorno que estés utilizando. El shell MacPerl, o MPW, es muy similar a los shells de Unix en su soporte para varias variantes de comillas, excepto que hace un uso libre de los caracteres no ASCII de Mac como caracteres de control.

Usar qq(), q(), y qx(), en lugar de "comillas dobles", 'comillas simples', y `backticks`, puede hacer que los one-liners sean más fáciles de escribir.

No hay una solución general para todo esto. Es un lío.

¿Dónde puedo aprender sobre CGI o programación web en Perl?

Para módulos, obtén los módulos CGI o LWP de CPAN. Para libros de texto, consulta los dos dedicados especialmente a temas web en la pregunta sobre libros. Para problemas y preguntas relacionadas con la web, como "¿Por qué obtengo errores 500" o "¿Por qué no se ejecuta desde el navegador bien cuando funciona bien en la línea de comandos", consulta las guías de solución de problemas y referencias en perlfaq9 o en el CGI MetaFAQ:

L<http://www.perl.org/CGI_MetaFAQ.html>

Se recomienda encarecidamente echar un vistazo a https://plackperl.org y a los modernos frameworks web de Perl; la programación web en Perl ha evolucionado mucho desde los viejos tiempos de los simples scripts CGI.

¿Dónde puedo aprender sobre programación orientada a objetos en Perl?

Un buen lugar para empezar es perlootut, y puedes usar perlobj como referencia.

Un buen libro sobre OO en Perl es el "Object-Oriented Perl" de Damian Conway de Manning Publications, o "Intermediate Perl" de Randal Schwartz, brian d foy y Tom Phoenix de O'Reilly Media.

¿Dónde puedo aprender sobre enlazar C con Perl?

Si quieres llamar a C desde Perl, empieza con perlxstut, pasando a perlxs, xsubpp y perlguts. Si quieres llamar a Perl desde C, lee perlembed, perlcall y perlguts. No olvides que puedes aprender mucho observando cómo los autores de módulos de extensión existentes escribieron su código y resolvieron sus problemas.

Puede que no necesites todo el poder de XS. El módulo Inline::C te permite poner código C directamente en tu fuente Perl. Se encarga de toda la magia para que funcione. Todavía tienes que aprender al menos parte de la API de perl, pero no tendrás que lidiar con la complejidad de los archivos de soporte de XS.

He leído perlembed, perlguts, etc., pero no puedo incrustar perl en mi programa C; ¿qué estoy haciendo mal?

Descarga el kit ExtUtils::Embed de CPAN y ejecuta `make test'. Si las pruebas pasan, lee los pods una y otra vez. Si fallan, envía un informe de error a https://github.com/Perl/perl5/issues con la salida de "make test TEST_VERBOSE=1" junto con "perl -V".

Cuando intenté ejecutar mi script, recibí este mensaje. ¿Qué significa?

Una lista completa de los mensajes de error y advertencias de Perl con texto explicativo se puede encontrar en perldiag. También puedes usar el programa splain (distribuido con Perl) para explicar los mensajes de error:

perl programa 2>diag.out
splain [-v] [-p] diag.out

o cambia tu programa para que explique los mensajes por sí mismo:

use diagnostics;

o

use diagnostics -verbose;

¿Qué es MakeMaker?

(contribuido por brian d foy)

El módulo ExtUtils::MakeMaker, más conocido simplemente como "MakeMaker", convierte un script de Perl, típicamente llamado "Makefile.PL", en un Makefile. La herramienta de Unix "make" usa este archivo para gestionar dependencias y acciones para procesar e instalar una distribución de Perl.
