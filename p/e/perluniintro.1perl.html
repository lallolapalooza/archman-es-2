NOMBRE

perluniintro - Introducción a Unicode en Perl

DESCRIPCIÓN

Este documento ofrece una idea general de Unicode y cómo utilizar Unicode en Perl. Consulte "Recursos Adicionales" para obtener referencias a tratamientos más profundos de Unicode.

Unicode

Unicode es un estándar de conjunto de caracteres que planea codificar todos los sistemas de escritura del mundo, además de muchos otros símbolos.

Unicode y ISO/IEC 10646 son estándares coordinados que unifican casi todos los demás estándares de conjuntos de caracteres modernos, cubriendo más de 80 sistemas de escritura y cientos de idiomas, incluyendo todos los idiomas modernos comercialmente importantes. También están codificados todos los caracteres de los diccionarios chinos, japoneses y coreanos más grandes. Los estándares cubrirán eventualmente casi todos los caracteres en más de 250 sistemas de escritura y miles de idiomas. Unicode 1.0 se lanzó en octubre de 1991, y la versión 6.0 en octubre de 2010.

Un carácter Unicode es una entidad abstracta. No está ligado a ninguna anchura de entero particular, especialmente no al "char" del lenguaje C. Unicode es independiente del idioma y de la visualización: no codifica el idioma del texto, y generalmente no define fuentes ni otros detalles de diseño gráfico. Unicode opera sobre caracteres y sobre texto construido a partir de esos caracteres.

Unicode define caracteres como "LATIN CAPITAL LETTER A" (A MAYÚSCULA LATINA) o "GREEK SMALL LETTER ALPHA" (ALFA MINÚSCULA GRIEGA) y números únicos para los caracteres, en este caso 0x0041 y 0x03B1, respectivamente. Estos números únicos se llaman puntos de código. Un punto de código es esencialmente la posición del carácter dentro del conjunto de todos los caracteres Unicode posibles, y por lo tanto, en Perl, el término ordinal se usa a menudo de forma intercambiable con él.

El estándar Unicode prefiere usar notación hexadecimal para los puntos de código. Si los números como 0x0041 no le resultan familiares, eche un vistazo a una sección posterior, "Notación hexadecimal". El estándar Unicode utiliza la notación "U+0041 LATIN CAPITAL LETTER A" para indicar el punto de código hexadecimal y el nombre normativo del carácter.

Unicode también define varias propiedades para los caracteres, como "mayúscula" o "minúscula", "dígito decimal", o "puntuación"; estas propiedades son independientes de los nombres de los caracteres. Además, se definen varias operaciones sobre los caracteres, como pasar a mayúsculas, pasar a minúsculas y la ordenación (clasificación).

Un "carácter" lógico de Unicode puede constar en realidad de más de un "carácter" o punto de código real interno. Para idiomas occidentales, esto se modela adecuadamente mediante un carácter base (como "LATIN CAPITAL LETTER A") seguido de uno o más modificadores (como "COMBINING ACUTE ACCENT" - acento agudo combinatorio). Esta secuencia de carácter base y modificadores se denomina secuencia de caracteres combinatorios. Algunos idiomas no occidentales requieren modelos más complicados, por lo que Unicode creó el concepto de clúster de grafemas, que más tarde se refinó aún más en clúster de grafemas extendido. Por ejemplo, una sílaba coreana Hangul se considera un único carácter lógico, pero la mayoría de las veces consta de tres caracteres Unicode reales: una consonante inicial seguida de una vocal interior seguida de una consonante final.

Si debemos llamar a estos clústeres de grafemas extendidos "caracteres" depende de su punto de vista. Si usted es un programador, probablemente tenderá a ver cada elemento en las secuencias como una unidad, o "carácter". Sin embargo, desde el punto de vista del usuario, toda la secuencia podría verse como un solo "carácter" ya que es probablemente como se ve en el contexto del idioma del usuario. En este documento, adoptamos el punto de vista del programador: un "carácter" es un punto de código Unicode.

Para algunas combinaciones de carácter base y modificadores, existen caracteres precompuestos. Existe un carácter único equivalente, por ejemplo, para la secuencia "LATIN CAPITAL LETTER A" seguida de "COMBINING ACUTE ACCENT". Se llama "LATIN CAPITAL LETTER A WITH ACUTE" (A MAYÚSCULA LATINA CON ACENTO AGUDO). Sin embargo, estos caracteres precompuestos solo están disponibles para algunas combinaciones y están destinados principalmente a soportar conversiones de ida y vuelta entre Unicode y estándares heredados (como ISO 8859). El uso de secuencias, como hace Unicode, permite necesitar menos bloques de construcción básicos (puntos de código) para expresar muchos más clústeres de grafemas potenciales. Para soportar la conversión entre formas equivalentes, también se definen varias formas de normalización. Por lo tanto, "LATIN CAPITAL LETTER A WITH ACUTE" está en la Forma de Normalización Compuesta (NFC), y la secuencia "LATIN CAPITAL LETTER A" seguida de "COMBINING ACUTE ACCENT" representa el mismo carácter en la Forma de Normalización Decomposta (NFD).

Debido a la compatibilidad retroactiva con codificaciones heredadas, la idea de "un número único para cada carácter" se rompe un poco: en su lugar, hay "al menos un número para cada carácter". El mismo carácter podría representarse de forma diferente en varias codificaciones heredadas. Lo contrario no es cierto: algunos puntos de código no tienen un carácter asignado. En primer lugar, hay puntos de código no asignados dentro de bloques utilizados de otra manera. En segundo lugar, existen caracteres de control Unicode especiales que no representan caracteres reales.

Cuando se concibió Unicode por primera vez, se pensó que todos los caracteres del mundo podrían representarse utilizando una palabra de 16 bits; es decir, se necesitaría un máximo de 0x10000 (o 65.536) caracteres, desde 0x0000 hasta 0xFFFF. Esto pronto resultó ser incorrecto, y desde Unicode 2.0 (julio de 1996), Unicode se ha definido hasta 21 bits (0x10FFFF), y Unicode 3.1 (marzo de 2001) definió los primeros caracteres por encima de 0xFFFF. Los primeros 0x10000 caracteres se denominan el Plano 0, o el Plano Multilingüe Básico (BMP). Con Unicode 3.1, se definieron un total de 17 (sí, diecisiete) planos, pero todavía no están ni mucho menos llenos de caracteres definidos.

Cuando se codifica un nuevo idioma, Unicode generalmente elegirá un "bloque" de puntos de código no asignados consecutivos para sus caracteres. Hasta ahora, el número de puntos de código en estos bloques siempre ha sido divisible uniformemente por 16. Los excedentes en un bloque, que no se necesitan actualmente, se dejan sin asignar, para crecimiento futuro. Pero ha habido ocasiones en las que una versión posterior necesitó más puntos de código que los excedentes disponibles, y se tuvo que asignar un nuevo bloque en otro lugar, no contiguo al inicial, para manejar el desbordamiento. Por lo tanto, pronto quedó claro que "bloque" no era un principio organizativo adecuado, y así se creó la propiedad de "Script" (script). (Más tarde también se añadió una propiedad de script mejorada, la propiedad "Script_Extensions".) Aquellos puntos de código que se encuentran en bloques de desbordamiento aún pueden tener el mismo script que los originales. El concepto de script se ajusta más a los idiomas naturales: existe el script "Latin" (Latino), el script "Greek" (Griego), y así sucesivamente; y existen varios scripts artificiales, como "Common" (Común) para caracteres que se utilizan en varios scripts, como los símbolos matemáticos. Los scripts suelen abarcar partes variadas de varios bloques. Para más información sobre los scripts, consulte "Scripts" en perlunicode. La división en bloques existe, pero es casi completamente accidental, un artefacto de cómo se han asignado y se siguen asignando los caracteres. (Tenga en cuenta que este párrafo ha simplificado demasiado las cosas para que esto sea una introducción. Unicode en realidad no codifica idiomas, sino los sistemas de escritura para ellos - sus scripts; y un script puede ser utilizado por muchos idiomas. Unicode también codifica cosas que en realidad no son sobre idiomas, como símbolos como "BAGGAGE CLAIM" (reclamación de equipaje).)

Los puntos de código Unicode son solo números abstractos. Para introducir y extraer estos números abstractos, los números deben ser codificados o serializados de alguna manera. Unicode define varias formas de codificación de caracteres, de las cuales UTF-8 es la más popular. UTF-8 es una codificación de longitud variable que codifica caracteres Unicode como 1 a 4 bytes. Otras codificaciones incluyen UTF-16 y UTF-32 y sus variantes big-endian y little-endian.

Datos heredados y Unicode

Cuando se combinan datos heredados y Unicode, los datos heredados deben actualizarse a Unicode. Normalmente, se asume que los datos heredados son ISO 8859-1 (o EBCDIC, si corresponde).

El módulo "Encode" conoce muchas codificaciones y tiene interfaces para realizar conversiones entre esas codificaciones:

use Encode 'decode';
$data = decode("iso-8859-3", $data); # convertir desde heredado

Entrada/Salida Unicode

Normalmente, al escribir datos Unicode

print FH $some_string_with_unicode, "\n";

se producen bytes sin procesar que Perl utiliza para codificar internamente la cadena Unicode. La codificación interna de Perl depende del sistema y de los caracteres que contenga la cadena en ese momento. Si alguno de los caracteres tiene puntos de código 0x100 o superiores, se mostrará una advertencia. Para asegurarse de que la salida se represente explícitamente en la codificación deseada, y para evitar la advertencia, abra el flujo con la codificación deseada. Algunos ejemplos:

open FH, ">:utf8", "archivo";
open FH, ">:encoding(ucs2)",      "archivo";
open FH, ">:encoding(UTF-8)",     "archivo";
open FH, ">:encoding(shift_jis)", "archivo";

y en flujos ya abiertos, utilice binmode():

binmode(STDOUT, ":utf8");
binmode(STDOUT, ":encoding(ucs2)");
binmode(STDOUT, ":encoding(UTF-8)");
binmode(STDOUT, ":encoding(shift_jis)");

La coincidencia de nombres de codificación es flexible: las mayúsculas y minúsculas no importan, y muchas codificaciones tienen varios alias. Tenga en cuenta que la capa ":utf8" siempre debe especificarse exactamente así; *no* está sujeta a la coincidencia flexible de nombres de codificación. Tenga en cuenta también que actualmente ":utf8" no es seguro para la entrada, ya que acepta los datos sin validar que sean realmente UTF-8 válido; en su lugar, debería utilizar :encoding(UTF-8) (con o sin guion).

Consulte PerlIO para la capa ":utf8", PerlIO::encoding y Encode::PerlIO para la capa :encoding(), y Encode::Supported para muchas codificaciones admitidas por el módulo "Encode".

Leer un archivo que sabe que está codificado en una de las codificaciones Unicode o heredadas no convierte mágicamente los datos a Unicode a ojos de Perl. Para hacerlo, especifique la capa apropiada al abrir archivos

open(my $fh,'<:encoding(UTF-8)', 'cualquiercosa');
my $linea_de_unicode = <$fh>;
open(my $fh,'<:encoding(Big5)', 'cualquiercosa');
my $linea_de_unicode = <$fh>;

Las capas de E/S también se pueden especificar de forma más flexible con el pragma "open". Consulte open o mire el siguiente ejemplo.

use open ':encoding(UTF-8)'; # la codificación predeterminada de entrada/salida será
                             # UTF-8
open X, ">archivo";
print X chr(0x100), "\n";
close X;
open Y, "<archivo";
printf "%#x\n", ord(<Y>); # esto debería imprimir 0x100
close Y;

Con el pragma "open" puede usar la capa ":locale"

BEGIN { $ENV{LC_ALL} = $ENV{LANG} = 'ru_RU.KOI8-R' }
# el :locale sondeó las variables de entorno de localización como
# LC_ALL
use open OUT => ':locale'; # ruso parusski
open(O, ">koi8");
print O chr(0x430); # LETRA MINÚSCULA CIRÍLICA RUSA A = KOI8-R 0xc1
close O;
open(I, "<koi8");
printf "%#x\n", ord(<I>), "\n"; # esto debería imprimir 0xc1
close I;

Estos métodos instalan un filtro transparente en el flujo de E/S que convierte los datos de la codificación especificada al leerlos del flujo. El resultado es siempre Unicode.

El pragma open afecta a todas las llamadas a open() posteriores al pragma, estableciendo capas predeterminadas. Si solo desea afectar a ciertos flujos, utilice capas explícitas directamente en la llamada a open().

Puede cambiar las codificaciones en un flujo ya abierto utilizando binmode(); consulte "binmode" en perlfunc.

El ":locale" no funciona actualmente con open() y binmode(), solo con el pragma "open". Los métodos ":utf8" y :encoding(...) sí funcionan con open(), binmode() y el pragma "open".

Del mismo modo, puede utilizar estas capas de E/S en flujos de salida para convertir automáticamente Unicode a la codificación especificada al escribirla en el flujo. Por ejemplo, el siguiente fragmento copia el contenido del archivo "text.jis" (codificado como ISO-2022-JP, también conocido como JIS) al archivo "text.utf8", codificado como UTF-8:

open(my $nihongo, '<:encoding(iso-2022-jp)', 'text.jis');
open(my $unicode, '>:utf8',                  'text.utf8');
while (<$nihongo>) { print $unicode $_ }

El nombre de las codificaciones, tanto por open() como por el pragma "open", permite nombres flexibles: se reconocerán tanto "koi8-r" como "KOI8R".

Se reconocen las codificaciones comunes reconocidas por ISO, MIME, IANA y varias otras organizaciones de estandarización; para una lista más detallada, consulte Encode::Supported.

read() lee caracteres y devuelve el número de caracteres. seek() y tell() operan con recuentos de bytes, al igual que sysseek().

sysread() y syswrite() no deben utilizarse en manejadores de archivos con capas de codificación de caracteres; se comportan mal y ese comportamiento ha sido obsoleto desde perl 5.24.

Observe que, debido al comportamiento predeterminado de no realizar ninguna conversión en la entrada si no hay una capa predeterminada, es fácil escribir código erróneamente que siga expandiendo un archivo codificando repetidamente los datos:

# ADVERTENCIA DE CÓDIGO INCORRECTO
open F, "archivo";
local $/; ## lee todo el archivo de caracteres de 8 bits
$t = <F>;
close F;
open F, ">:encoding(UTF-8)", "archivo";
print F $t; ## convierte a UTF-8 en la salida
close F;

Si ejecuta este código dos veces, el contenido del *archivo* se codificará dos veces en UTF-8. Un "use open ':encoding(UTF-8)'" habría evitado el error, o abrir explícitamente el *archivo* para entrada también como UTF-8.

NOTA: las características ":utf8" y ":encoding" solo funcionan si su Perl se ha compilado con PerlIO, que es el valor predeterminado en la mayoría de los sistemas.

Mostrar Unicode como texto

A veces, es posible que desee mostrar escalares de Perl que contienen Unicode como texto ASCII (o EBCDIC) simple. La siguiente subrutina convierte su argumento para que los caracteres Unicode con puntos de código superiores a 255 se muestren como "\x{...}", los caracteres de control (como "\n") se muestren como "\x..", y el resto de los caracteres como ellos mismos:

sub nice_string {
       join("",
       map { $_ > 255                    # si es un carácter ancho...
             ? sprintf("\\x{%04X}", $_)  # \x{...}
             : chr($_) =~ /[[:cntrl:]]/  # si no, si es un carácter de control...
               ? sprintf("\\x%02X", $_)  # \x..
               : quotemeta(chr($_))      # si no, entrecomillado o como ellos mismos
       } unpack("W*", $_[0]));           # desempaqueta caracteres Unicode
  }

Por ejemplo,

nice_string("foo\x{100}bar\n")

devuelve la cadena

'foo\x{0100}bar\x0A'

que está lista para ser impresa.

(Se utiliza "\\x{}" aquí en lugar de "\\N{}", ya que es muy probable que desee ver cuáles son los valores nativos.)

Casos especiales

  • A partir de Perl 5.28, es ilegal que los operadores bit a bit, como "~", operen en cadenas que contengan puntos de código superiores a 255.
  • La función vec() puede producir resultados sorprendentes si se utiliza en cadenas que contienen caracteres con valores ordinales superiores a 255. En ese caso, los resultados son coherentes con la codificación interna de los caracteres, pero no con mucho más. Así que no lo haga, y a partir de Perl 5.28, se emite un mensaje de advertencia si lo hace, convirtiéndose en ilegal en Perl 5.32.
  • Inspección de la codificación interna de Perl

    Los usuarios normales de Perl nunca deberían preocuparse de cómo Perl codifica una cadena Unicode particular (porque las formas normales de acceder al contenido de una cadena con Unicode, a través de entrada y salida, siempre deberían ser a través de capas de E/S explícitamente definidas). Pero si debe hacerlo, hay dos formas de mirar detrás de escena.

    Una forma de mirar dentro de la codificación interna de los caracteres Unicode es utilizar "unpack("C*", ...)" para obtener los bytes de la codificación de la cadena que sea, o "unpack("U0..", ...)" para obtener los bytes de la codificación UTF-8:

    # esto imprime c4 80 para los bytes UTF-8 0xc4 0x80
print join(" ", unpack("U0(H2)*", pack("U", 0x100))), "\n";

    Otra forma sería utilizar el módulo Devel::Peek:

    perl -MDevel::Peek -e 'Dump(chr(0x100))'

    Eso muestra el indicador "UTF8" en FLAGS y tanto los bytes UTF-8 como los caracteres Unicode en "PV". Consulte también más adelante en este documento la discusión sobre la función utf8::is_utf8().

Temas avanzados

  • Equivalencia de cadenas

    La cuestión de la equivalencia de cadenas se vuelve algo complicada en Unicode: ¿qué se entiende por "igual"?

    (¿Es "LETRA MAYÚSCULA LATINA A CON ACENTO AGUDO" igual a "LETRA MAYÚSCULA LATINA A"?)

    La respuesta corta es que, por defecto, Perl compara la equivalencia ("eq",

    Plegado de Mayúsculas/Minúsculas

    La forma más sencilla de comparar cadenas es simplemente comparar los puntos de código de los caracteres. Esto, sin embargo, no siempre es lo que se desea.

    • Considere esto: ¿es "a" igual a "A"?
    • ¿Es "A" igual a "\xC1" (letra mayúscula latina A con acento agudo)?

    La respuesta corta es que, por defecto, Perl compara cadenas ("eq", "ne") basándose únicamente en los puntos de código de los caracteres. En el caso anterior, la respuesta es no (porque 0x00C1 != 0x0041). Pero a veces, se deben considerar iguales todas las mayúsculas de la A, o incluso las A de cualquier mayúscula o minúscula.

    La respuesta larga es que es necesario considerar la normalización de caracteres y las cuestiones de mayúsculas/minúsculas: consulte Unicode::Normalize, Unicode Technical Report #15, Unicode Normalization Forms https://www.unicode.org/reports/tr15 y las secciones sobre mapeo de mayúsculas/minúsculas en el Unicode Standard https://www.unicode.org.

    A partir de Perl 5.8.0, se implementa el plegado de mayúsculas/minúsculas "Completo" de Case Mappings/SpecialCasing, pero persisten errores en "qr//i" con ellos, la mayoría corregidos en la versión 5.14 y esencialmente en su totalidad para la 5.18.

  • Colación de Cadenas

    A la gente le gusta ver sus cadenas ordenadas de forma agradable, o como se dice en la jerga Unicode, colacionadas. Pero de nuevo, ¿qué quiere decir con colacionar?

    (¿Viene "LETRA MAYÚSCULA LATINA A CON ACENTO AGUDO" antes o después de "LETRA MAYÚSCULA LATINA A CON ACENTO GRAVE"?)

    La respuesta corta es que, por defecto, Perl compara cadenas ("lt", "le", "cmp", "ge", "gt") basándose únicamente en los puntos de código de los caracteres. En el caso anterior, la respuesta es "después", ya que 0x00C1 > 0x00C0.

    La respuesta larga es que "depende", y no se puede dar una buena respuesta sin conocer (como mínimo) el contexto del idioma. Consulte Unicode::Collate y el Unicode Collation Algorithm https://www.unicode.org/reports/tr10/

Miscelánea

  • Rangos y Clases de Caracteres

    Los rangos de caracteres en las clases de caracteres entre corchetes de las expresiones regulares (por ejemplo, "/[a-z]/") y en el operador "tr///" (también conocido como "y///") no son mágicamente conscientes de Unicode. Lo que esto significa es que "[A-Za-z]" no significará mágicamente "todas las letras alfabéticas" (no es que signifique eso incluso para caracteres de 8 bits; para esos, si está usando locales (perllocale), use "/[[:alpha:]]/"; y si no, use la propiedad consciente de 8 bits "\p{alpha}").

    Todas las propiedades que comienzan con "\p" (y su inverso "\P") son en realidad clases de caracteres conscientes de Unicode. Hay docenas de ellas, consulte perluniprops.

    A partir de la versión 5.22, puede usar puntos de código Unicode como puntos finales de los rangos de caracteres de los patrones de expresiones regulares, y el rango incluirá todos los puntos de código Unicode que se encuentren entre esos puntos finales, inclusive.

    qr/ [ \N{U+03} - \N{U+20} ] /xx

    incluye los puntos de código "\N{U+03}", "\N{U+04}", ..., "\N{U+20}".

    Esto también funciona para rangos en "tr///" a partir de Perl v5.24.

  • Conversiones de Cadena a Número

    Unicode define varios caracteres decimales y numéricos además de los familiares 0 a 9, como los dígitos arábigos e indios. Perl no admite la conversión de cadenas a números para dígitos distintos de los ASCII 0 a 9 (y los ASCII "a" a "f" para hexadecimal). Para obtener conversiones seguras de cualquier cadena Unicode, use "num()" en Unicode::UCD.

Preguntas con Respuestas

  • ¿Se Romperán Mis Scripts Antiguos?

    Muy probablemente no. A menos que esté generando caracteres Unicode de alguna manera, el comportamiento anterior debería conservarse. El único comportamiento que ha cambiado y que podría comenzar a generar Unicode es el comportamiento anterior de chr(), donde al proporcionar un argumento mayor que 255 se producía un carácter módulo 255. chr(300), por ejemplo, era igual a chr(45) o "-" (en ASCII), ahora es LETRA MAYÚSCULA LATINA I CON BREVE.

  • ¿Cómo Hago Para Que Mis Scripts Funcionen Con Unicode?

    Se necesitará muy poco trabajo, ya que nada cambia hasta que genere datos Unicode. Lo más importante es obtener la entrada como Unicode; para eso, consulte la discusión anterior sobre E/S. Para obtener un soporte Unicode completo y sin problemas, agregue "use feature 'unicode_strings'" (o "use v5.12" o superior) a su script.

  • ¿Cómo Sé Si Mi Cadena Está en Unicode?

    No debería tener que preocuparse. Pero puede que sí si su Perl es anterior a 5.14.0 o si no ha especificado "use feature 'unicode_strings'" o use 5.012 (o superior), porque de lo contrario, las reglas para los puntos de código en el rango de 128 a 255 son diferentes dependiendo de si la cadena que los contiene está en Unicode o no. (Ver "When Unicode Does Not Happen" en perlunicode.)

    Para determinar si una cadena está en Unicode, use:

    print utf8::is_utf8($string) ? 1 : 0, "\n";

    Pero tenga en cuenta que esto no significa que alguno de los caracteres de la cadena esté necesariamente codificado en UTF-8, o que algún carácter tenga puntos de código mayores que 0xFF (255) o incluso 0x80 (128), o que la cadena tenga algún carácter. Todo lo que hace is_utf8() es devolver el valor del indicador interno de "utf8ness" adjunto a $string. Si el indicador está desactivado, los bytes del escalar se interpretan como una codificación de un solo byte. Si el indicador está activado, los bytes del escalar se interpretan como los puntos de código (de longitud variable, potencialmente de varios bytes) codificados en UTF-8 de los caracteres. Los bytes añadidos a una cadena codificada en UTF-8 se actualizan automáticamente a UTF-8. Si se fusionan escalares mixtos (no UTF-8 y UTF-8) (interpolación entrecomillada, concatenación explícita o sustitución de parámetros de printf/sprintf), el resultado se codificará en UTF-8 como si las copias de las cadenas de bytes se hubieran actualizado a UTF-8: por ejemplo,

    $x = "ab\x80c";
$y = "\x{100}";
print "$x = $y\n";

    la cadena de salida será "ab\x80c = \x{100}\n" codificada en UTF-8, pero $x permanecerá codificada en bytes.

    A veces, es posible que realmente necesite conocer la longitud en bytes de una cadena en lugar de la longitud en caracteres. Para eso, use el pragmatismo "bytes" y la función length():

    my $unicode = chr(0x100);
print length($unicode), "\n"; # imprimirá 1
use bytes;
print length($unicode), "\n"; # imprimirá 2
                              # (el 0xC4 0x80 del UTF-8)
no bytes;

    Puede probar con Encode::Guess, pero tiene una serie de limitaciones.

  • ¿Cómo Detecto Datos que No Son Válidos en una Codificación Particular?

    Utilice el paquete "Encode" para intentar convertirlos. Por ejemplo,

    use Encode 'decode';
if (eval { decode('UTF-8', $string, Encode::FB_CROAK); 1 }) {
    # $string es UTF-8 válido
} else {
    # $string no es UTF-8 válido
}

    O use "unpack" para intentar decodificarlo:

    use warnings;
@chars = unpack("C0U*", $string_of_bytes_that_I_think_is_utf8);

    Si no es válido, se producirá una advertencia de "Malformed UTF-8 character". El "C0" significa "procesar la cadena carácter por carácter". Sin él, "unpack("U*", ...)" funcionaría en modo "U0" (el predeterminado si la cadena de formato comienza con "U") y devolvería los bytes que componen la codificación UTF-8 de la cadena de destino, algo que siempre funcionará.

  • ¿Cómo Convierto Datos Binarios a una Codificación Particular, o Viceversa?

    Esto probablemente no sea tan útil como podría pensar. Normalmente, no debería necesitar hacerlo.

    En cierto sentido, lo que pregunta no tiene mucho sentido: las codificaciones son para caracteres, y los datos binarios no son "caracteres", por lo que convertir "datos" a alguna codificación no es significativo a menos que sepa en qué conjunto de caracteres y codificación se encuentran los datos binarios, en cuyo caso no son solo datos binarios, ¿verdad?

    use Encode 'from_to';

Tanto antes como después de la llamada, la cadena $data contiene solo un montón de bytes de 8 bits. En lo que respecta a Perl, la codificación de la cadena sigue siendo "bytes nativos del sistema de 8 bits".

    Puede relacionar esto con un módulo ficticio 'Translate':

my $phrase = "Yes";

perluniintro - perl unicode introduction

NAME

perluniintro - perl unicode introduction

DESCRIPTION

This document is an introduction to Unicode support in Perl. It covers the most common questions that arise when dealing with Unicode, and provides pointers to more detailed information.

What is Unicode?

Unicode is a character encoding standard, designed to represent text in most of the world's writing systems. It assigns a unique number, called a code point, to each character. For example, the Latin letter 'A' is code point U+0041, and the Greek letter $\pi$ is U+03C0. The standard is maintained by the Unicode Consortium.

Code points are typically represented in hexadecimal notation, preceded by "U+".

Because Unicode code points can range up to U+10FFFF, they can require more than 16 bits to represent. Therefore, Unicode needs several different ways to be stored in memory or on disk. The two most common ways are:

UTF-8
A variable-length encoding where code points up to U+00FF are represented by a single byte, code points U+0100 to U+FFFF by two bytes, and code points U+10000 to U+10FFFF by three or four bytes. UTF-8 is ASCII-compatible, meaning that ASCII characters are represented by their original ASCII byte values. UTF-8 is the most common encoding on the web and in Unix-like systems.
UTF-16
A variable-length encoding where code points up to U+FFFF are represented by two bytes (a "code unit"), and code points U+10000 to U+10FFFF are represented by two 16-bit code units (a "surrogate pair").

Perl strings can be either plain byte strings or Unicode strings. By default, Perl strings are plain byte strings. When you perform operations that require Unicode (like using the UTF-8 pragma, or certain functions), Perl will attempt to upgrade them to Unicode strings.

A Unicode string in Perl is represented internally by a sequence of code points, which is then encoded into bytes using UTF-8 when needed (e.g. for output, or when interacting with modules that expect UTF-8 bytes). You can control how Perl interprets and handles byte strings using the utf8 pragma and the bytes pragma.

Unicode in Perl 5.8.0 and later

Perl 5.8.0 and later have built-in support for Unicode. This means that Perl strings can contain Unicode characters directly. The primary way to enable this is by using the utf8 pragma:

    use utf8;

This pragma tells Perl that the source code itself may contain Unicode characters (e.g. in string literals or regular expression patterns).

When the utf8 pragma is in effect, Perl will correctly handle Unicode characters in your code. For example, you can write:

    use utf8;
    my $string = "你好"; # Chinese for "Hello"
    print length($string), "\n"; # prints 2

If you are reading Unicode data from a file or other external source, you need to tell Perl that the data is in UTF-8. This is done using the open pragma:

    use open ':encoding(UTF-8)';
    open my $fh, '<', 'file.txt';
    my $line = <$fh>;

Alternatively, you can use the utf8::decode() function to decode a byte string into a Unicode string:

    use utf8;
    my $bytes = "你好"; # Assume this is UTF-8 encoded
    my $unicode = $bytes;
    utf8::decode($unicode);
    print length($unicode), "\n"; # prints 2

Conversely, to encode a Unicode string into UTF-8 bytes:

    use utf8;
    my $unicode = "你好";
    my $bytes = $unicode;
    utf8::encode($bytes);
    # Now $bytes contains the UTF-8 representation of "你好"

You can also use the pack and unpack functions with the appropriate format specifiers:

$native_string = pack("U*", 0x0041, 0x03c0, 0x4f60, 0x597d); # A, pi, 你, 好
# $native_string now contains the UTF-8 encoding of "Aπ你好"
$Unicode_string = unpack("U*", $native_string);
# $Unicode_string now contains the sequence of code points for "Aπ你好"

$Unicode_string = pack("W*", 0x0041, 0x03c0, 0x4f60, 0x597d);
# $Unicode_string contains the UTF-16LE encoding of "Aπ你好"
$native_string = unpack("W*", $Unicode_string);

If you have a sequence of bytes you know is valid UTF-8, but Perl doesn't know it yet, you can make Perl a believer, too:

$Unicode = $bytes;
utf8::decode($Unicode);

or:

$Unicode = pack("U0a*", $bytes);

You can find the bytes that make up a UTF-8 sequence with

@bytes = unpack("C*", $Unicode_string)

and you can create well-formed Unicode with

$Unicode_string = pack("U*", 0xff, ...)

  • How Does Unicode Work With Traditional Locales?

    If your locale is a UTF-8 locale, starting in Perl v5.26, Perl works well for all categories; before this, starting with Perl v5.20, it works for all categories but "LC_COLLATE", which deals with sorting and the "cmp" operator. But note that the standard "Unicode::Collate" and "Unicode::Collate::Locale" modules offer much more powerful solutions to collation issues, and work on earlier releases.

    For other locales, starting in Perl 5.16, you can specify

    use locale ':not_characters';

    to get Perl to work well with them. The catch is that you have to translate from the locale character set to/from Unicode yourself. See "Unicode I/O" above for how to

    use open ':locale';

    to accomplish this, but full details are in "Unicode and UTF-8" in perllocale, including gotchas that happen if you don't specify ":not_characters".

    • Hexadecimal Notation

    The Unicode standard prefers using hexadecimal notation because that more clearly shows the division of Unicode into blocks of 256 characters. Hexadecimal is also simply shorter than decimal. You can use decimal notation, too, but learning to use hexadecimal just makes life easier with the Unicode standard. The "U+HHHH" notation uses hexadecimal, for example.

    The "0x" prefix means a hexadecimal number, the digits are 0-9 and a-f (or A-F, case doesn't matter). Each hexadecimal digit represents four bits, or half a byte. "print 0x..., "\n"" will show a hexadecimal number in decimal, and "printf "%x\n", $decimal" will show a decimal number in hexadecimal. If you have just the "hex digits" of a hexadecimal number, you can use the hex() function.

    print 0x0009, "\n";    # 9
print 0x000a, "\n";    # 10
print 0x000f, "\n";    # 15
print 0x0010, "\n";    # 16
print 0x0011, "\n";    # 17
print 0x0100, "\n";    # 256
print 0x0041, "\n";    # 65
printf "%x\n",  65;    # 41
printf "%#x\n", 65;    # 0x41
print hex("41"), "\n"; # 65

    UNICODE IN OLDER PERLS

    If you cannot upgrade your Perl to 5.8.0 or later, you can still do some Unicode processing by using the modules "Unicode::String", "Unicode::Map8", and "Unicode::Map", available from CPAN.     The following are fast conversions from ISO 8859-1 (Latin-1) bytes to UTF-8 bytes and back, the code works even with older Perl 5 versions.

    # ISO 8859-1 to UTF-8
s/([\x80-\xFF])/chr(0xC0|ord($1)>>6).chr(0x80|ord($1)&0x3F)/eg;
# UTF-8 to ISO 8859-1
s/([\xC2\xC3])([\x80-\xBF])/chr(ord($1)<<6&0xC0|ord($2)&0x3F)/eg;
