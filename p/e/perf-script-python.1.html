NOMBRE

perf-script-python - Procesa datos de traza con un script de Python

SINOPSIS

perf script [-s [Python]:script[.py] ]

DESCRIPCIÓN

Esta opción del script de perf se utiliza para procesar datos del script de perf usando el intérprete de Python incorporado de perf. Lee y procesa el archivo de entrada y muestra los resultados del análisis de traza implementado en el script de Python dado, si lo hay.

UN EJEMPLO RÁPIDO

Esta sección muestra el proceso, de principio a fin, de creación de un script de Python funcional que agrega y extrae información útil de un flujo de script de perf en bruto. Puede evitar leer el resto de este documento si un ejemplo es suficiente para usted; el resto del documento proporciona más detalles sobre cada paso y enumera las funciones de la biblioteca disponibles para los escritores de scripts.

Este ejemplo detalla los pasos que se utilizaron para crear el script syscall-counts que ve cuando enumera los scripts de script de perf disponibles a través de perf script -l. Como tal, este script también muestra cómo integrar su script en la lista de scripts de propósito general de perf script enumerados por ese comando.

El script syscall-counts es un script simple, pero demuestra todas las ideas básicas necesarias para crear un script útil. Aquí hay un ejemplo de su salida (los nombres de las llamadas al sistema aún no son compatibles, aparecerán como números):

Básicamente, nuestra tarea es mantener un recuento por llamada al sistema que se actualiza cada vez que ocurre una llamada al sistema en el sistema. Nuestro script hará eso, pero primero necesitamos registrar los datos que serán procesados por ese script. Teóricamente, hay un par de formas en que podríamos hacer eso:

•podríamos habilitar cada evento en el directorio tracing/events/syscalls, pero esto son más de 600 llamadas al sistema, mucho más allá del número permitido por perf. Estos eventos individuales de llamada al sistema serán útiles si queremos usar la guía que obtenemos de los scripts de propósito general para profundizar y obtener más detalles sobre llamadas al sistema individuales de interés.
•podemos habilitar los eventos sys_enter y/o sys_exit que se encuentran en tracing/events/raw_syscalls. Estos se llaman para todas las llamadas al sistema; el campo id se puede usar para distinguir entre números de llamada al sistema individuales.

Para este script, solo necesitamos saber que se ingresó una llamada al sistema; no nos importa cómo salió, así que usaremos perf record para registrar solo los eventos sys_enter:

.ft C
# perf record -a -e raw_syscalls:sys_enter
^C[ perf record: Despertado 1 veces para escribir datos ]
[ perf record: Capturados y escritos 56.545 MB perf.data (~2470503 muestras) ]
.ft

Las opciones básicamente dicen que recopile datos para cada evento de llamada al sistema en todo el sistema y multiplique la salida por CPU a un solo flujo. Ese flujo único se registrará en un archivo en el directorio actual llamado perf.data.

Una vez que tengamos un archivo perf.data que contenga nuestros datos, podemos usar la opción -g de perf script para generar un script de Python que contendrá un manejador de devolución de llamada para cada tipo de evento que se encuentre en el flujo de traza de perf.data (para obtener más detalles, consulte la sección SCRIPTS DE INICIO).

ESCRITURA DE UN SCRIPT DE PERF

Esta sección cubre la escritura de scripts de perf script en Python.

EL PROCESO

El proceso de escritura de un script de perf script se puede resumir en los siguientes pasos:

  • Descubra el tracepoint o los tracepoints que le interesan. Puede hacerlo listando los eventos disponibles con perf list o examinando la información detallada de eventos y campos en /sys/kernel/tracing/events/.
  • Grabe los datos de rastreo correspondientes utilizando perf record, especificando los eventos de interés.
  • Genere un script esqueleto utilizando perf script -g python.
  • Modifique el código del script esqueleto para agregar, procesar y mostrar los datos según sus necesidades específicas.

EJEMPLO: CONTADOR DE LLAMADAS AL SISTEMA

Veamos un ejemplo de cómo crear un script para contar las llamadas al sistema. Supongamos que queremos contar la frecuencia de cada llamada al sistema. Necesitamos capturar el tracepoint raw_syscalls:sys_enter.

Primero, grabamos los datos de rastreo:

# perf record -a -e raw_syscalls:sys_enter sleep 10

A continuación, generamos un script esqueleto de Python:

# perf script -g python

Esto creará un archivo llamado .py con un manejador para cada tipo de evento en el archivo de rastreo. Para nuestro propósito, nos interesará el manejador raw_syscalls__sys_enter.

El script esqueleto inicial se verá algo como esto:

import os
import sys
sys.path.append(os.environ['PERF_EXEC_PATH'] + \
        '/scripts/python/Perf-Trace-Util/lib/Perf/Trace')
from perf_trace_context import *
from Core import *
def trace_end():
        print "in trace_end"
def raw_syscalls__sys_enter(event_name, context, common_cpu,
        common_secs, common_nsecs, common_pid, common_comm,
        id, args):

En trace_end(), simplemente imprimiremos los resultados, pero primero necesitamos generar algunos resultados para imprimir. Para hacerlo, necesitamos que nuestro manejador sys_enter() realice el recuento necesario hasta que se cuenten todos los eventos. Una tabla hash indexada por el ID de la llamada al sistema es una buena manera de almacenar esa información; cada vez que se llama al manejador sys_enter(), simplemente incrementamos un contador asociado con esa entrada de tabla hash indexada por ese ID de llamada al sistema:

  syscalls = autodict()
  try:
    syscalls[id] += 1
  except TypeError:
    syscalls[id] = 1

El objeto syscalls autodict es un tipo especial de diccionario de Python (implementado en Core.py) que implementa los hashes *autovivificantes* de Perl en Python, es decir, con hashes autovivificantes, puede asignar valores de hash anidados sin tener que pasar por el problema de crear niveles intermedios si no existen, por ejemplo, syscalls[comm][pid][id] = 1 creará los niveles de hash intermedios y finalmente asignará el valor 1 a la entrada hash para id (porque el valor que se está asignando no es un hash en sí mismo, el valor inicial se asigna en la excepción TypeError. Bueno, puede que haya una mejor manera de hacer esto en Python, pero esto es lo que funciona por ahora).

Poniendo ese código en el manejador raw_syscalls__sys_enter(), terminamos efectivamente con un diccionario de un solo nivel indexado por el ID de la llamada al sistema y teniendo los recuentos que hemos totalizado como valores.

La función print_syscall_totals() itera sobre las entradas del diccionario y muestra una línea para cada entrada que contiene el nombre de la llamada al sistema (las claves del diccionario contienen los IDs de las llamadas al sistema, que se pasan a la función Util syscall_name(), que traduce los números brutos de las llamadas al sistema a las cadenas de nombres de llamadas al sistema correspondientes). La salida se muestra después de que se hayan procesado todos los eventos en el rastreo, llamando a la función print_syscall_totals() desde el manejador trace_end() llamado al final del procesamiento del script.

El script final que produce la salida anterior se muestra en su totalidad a continuación (la utilidad syscall_name() aún no está disponible, por ahora solo puede tratar con IDs):

import os
import sys
sys.path.append(os.environ['PERF_EXEC_PATH'] + \
        '/scripts/python/Perf-Trace-Util/lib/Perf/Trace')
from perf_trace_context import *
from Core import *
from Util import *
syscalls = autodict()
def trace_end():
        print_syscall_totals()
def raw_syscalls__sys_enter(event_name, context, common_cpu,
        common_secs, common_nsecs, common_pid, common_comm,
        id, args):
        try:
                syscalls[id] += 1
        except TypeError:
                syscalls[id] = 1
def print_syscall_totals():
    if for_comm is not None:
            print "\nsyscall events for %s:\n\n" % (for_comm),
    else:
            print "\nsyscall events:\n\n",
    print "%-40s  %10s\n" % ("event", "count"),
    print "%-40s  %10s\n" % ("----------------------------------------", \
                                 "-----------"),
    for id, val in sorted(syscalls.iteritems(), key = lambda(k, v): (v, k), \
                                  reverse = True):
            print "%-40s  %10d\n" % (syscall_name(id), val),

El script se puede ejecutar como antes:

# perf script -s syscall-counts.py

Esos son, por lo tanto, los pasos esenciales para escribir y ejecutar un script. El proceso se puede generalizar a cualquier tracepoint o conjunto de tracepoints que le interesen; básicamente, encuentre el/los tracepoint(s) que le interesan mirando la lista de eventos disponibles que muestra perf list y/o busque en /sys/kernel/tracing/events/ para obtener información detallada de eventos y campos, grabe los datos de rastreo correspondientes usando perf record, pasándole la lista de eventos interesantes, genere un script esqueleto usando perf script -g python y modifique el código para agregar y mostrarlo según sus necesidades particulares.

Después de hacer eso, es posible que termine con un script de propósito general que desee conservar y tener disponible para uso futuro. Al escribir un par de scripts de shell muy simples y colocarlos en el lugar correcto, puede hacer que su script aparezca junto con otros scripts listados por el comando perf script -l, por ejemplo:

# perf script -l
List of available trace scripts:
  wakeup-latency                       system-wide min/max/avg wakeup latency
  rw-by-file <comm>                    r/w activity for a program, by file
  rw-by-pid                            system-wide r/w activity

Un efecto secundario agradable de hacer esto es que también captura el comando perf record, probablemente largo, necesario para grabar los eventos para el script.

Para que el script aparezca como un script integrado, escribe dos scripts simples, uno para grabar y otro para reportar.

El script record es un script de shell con el mismo nombre base que su script, pero con -record agregado. El script de shell debe colocarse en el directorio perf/scripts/python/bin en el árbol de fuentes del kernel. En ese script, escribe el comando perf record necesario para su script:

# cat kernel-source/tools/perf/scripts/python/bin/syscall-counts-record
#!/bin/bash
perf record -a -e raw_syscalls:sys_enter

El script report también es un script de shell con el mismo nombre base que su script, pero con -report agregado. También debe ubicarse en el directorio perf/scripts/python/bin. En ese script, escribe el comando perf script -s necesario para ejecutar su script:

# cat kernel-source/tools/perf/scripts/python/bin/syscall-counts-report
#!/bin/bash
# description: system-wide syscall counts
perf script -s ~/libexec/perf-core/scripts/python/syscall-counts.py

Tenga en cuenta que la ubicación del script de Python dada en el script de shell está en el directorio libexec/perf-core/scripts/python; aquí es donde se copiará el script por make install cuando instale perf. Para que la instalación instale su script allí, su script debe ubicarse en el directorio perf/scripts/python en el árbol de fuentes del kernel:

# ls -al kernel-source/tools/perf/scripts/python

Una vez que haya hecho eso (¡no olvide hacer un nuevo make install, de lo contrario su script no aparecerá en tiempo de ejecución!), perf script -l debería mostrar una nueva entrada para su script:

  wakeup-latency                       system-wide min/max/avg wakeup latency

  syscall-counts                       system-wide syscall counts

Ahora puede realizar el paso de grabación a través de perf script record:

# perf script record syscall-counts

y mostrar la salida usando perf script report:

# perf script report syscall-counts

SCRIPTS DE INICIO

Puede comenzar rápidamente a escribir un script para un conjunto particular de datos de rastreo generando un script esqueleto usando perf script -g python en el mismo directorio que un archivo de rastreo perf.data existente. Eso generará un script de inicio que contiene un manejador para cada uno de los tipos de eventos en el archivo de rastreo; simplemente imprime cada campo disponible para cada evento en el archivo de rastreo.

También puede consultar los scripts existentes en ~/libexec/perf-core/scripts/python para ver ejemplos típicos que muestran cómo realizar tareas básicas como agregar datos de eventos, imprimir resultados, etc. Además, el script check-perf-script.py, aunque no es interesante por sus resultados, intenta ejercitar todas las características principales de scripting.

MANEJADORES DE EVENTOS

Cuando perf script se invoca utilizando un script de rastreo, se llama a una función manejadora definida por el usuario para cada evento en el rastreo. Si no hay una función manejadora definida para un tipo de evento dado, el evento se ignora (o se pasa a una función trace_unhandled, ver más abajo) y se procesa el siguiente evento.

La mayoría de los valores de campo de los eventos se pasan como argumentos a la función manejadora; algunos de los menos comunes no lo son; estos están disponibles como llamadas de retorno al ejecutable de perf (ver más abajo).

Como ejemplo, el siguiente comando perf record se puede usar para grabar todos los eventos sched_wakeup en el sistema:

# perf record -a -e sched:sched_wakeup

Los rastreos destinados a ser procesados usando un script deben grabarse con la opción anterior: -a para habilitar la recopilación en todo el sistema.

El archivo de formato para el evento sched_wakeup define los siguientes campos (consulte /sys/kernel/tracing/events/sched/sched_wakeup/format):

 format:
        field:unsigned short common_type;
        field:unsigned char common_flags;
        field:unsigned char common_preempt_count;
        field:int common_pid;
        field:char comm[TASK_COMM_LEN];
        field:pid_t pid;
        field:int prio;
        field:int success;
        field:int target_cpu;

La función manejadora para este evento se definiría como:

def sched__sched_wakeup(event_name, context, common_cpu, common_secs,
       common_nsecs, common_pid, common_comm,
       comm, pid, prio, success, target_cpu):
       pass

La función manejadora toma la forma subsystem__event_name.

Los argumentos common_* en la lista de argumentos del manejador son el conjunto de argumentos pasados a todos los manejadores de eventos; algunos de los campos corresponden a los campos common_* en el archivo de formato, pero algunos son sintetizados, y algunos de los campos common_* no son lo suficientemente comunes como para pasarse a cada evento como argumentos, pero están disponibles como funciones de biblioteca.

NOMBRE

perf-script-python - scripts de interfaz para perf en Python

SINOPSIS

perf script python script_file

DESCRIPCIÓN

Esta página de manual describe cómo escribir scripts de Python para perf script.

Los scripts de Python pueden usarse para procesar eventos capturados por perf. Proporcionan una forma flexible y potente de analizar datos de rendimiento.

UN RÁPIDO EJEMPLO

Aquí hay un script simple que imprime el nombre del evento y el nombre del proceso para cada evento capturado:

#!/usr/bin/env python
# -*- coding: utf-8 -*-

import os
import sys

sys.path.append(os.environ['PERF_EXEC_PATH'] + \
              '/scripts/python/Perf-Trace-Util/lib/Perf/Trace')
from perf_trace_context import *
from Core import *

def my_event_handler(event_name, context, event_fields_dict):
    # Imprime el nombre del evento y el nombre del proceso
    print(f"Evento: {event_name}, Proceso: {event_fields_dict['comm']}")

# Registra el manejador para un evento específico (por ejemplo, 'sched:sched_switch')
# Si no se especifica, la función trace_unhandled se llamará para todos los eventos.
# Para registrar un manejador de eventos específico, por ejemplo:
# register_event_handler("sched:sched_switch", my_event_handler)

# O para manejar todos los eventos que no tienen un manejador explícito:
def trace_unhandled(event_name, context, event_fields_dict):
    print(f"Evento no manejado: {event_name}, Proceso: {event_fields_dict.get('comm', 'N/A')}")

def trace_begin():
    print("Inicio del trazado...")

def trace_end():
    print("Fin del trazado.")

# Si quieres registrar el manejador para un evento específico, descomenta la siguiente línea
# y cámbiala por el evento que te interese:
# register_event_handler("sched:sched_switch", my_event_handler)

Para ejecutar este script:

$ perf record -e 'sched:sched_switch' -a sleep 1
$ perf script -i perf.data python your_script.py

SCRIPTS DE INICIO

Los scripts de Python para perf script tienen acceso a una variedad de datos del evento. La estructura de datos principal proporcionada a las funciones manejadoras es un diccionario que contiene campos de evento. Estos campos pueden incluir:

  • event_name: el nombre del evento (p. ej., "sched:sched_switch").

  • context: un objeto opaco que contiene información contextual. Se utiliza en llamadas de vuelta a perf.

  • common_cpu: la CPU en la que ocurrió el evento.

  • common_secs: la porción de segundos de la marca de tiempo del evento.

  • common_nsecs: la porción de nanosegundos de la marca de tiempo del evento.

  • common_pid: el PID de la tarea actual.

  • common_comm: el nombre del proceso actual.

el nombre del evento como texto
context                    una 'cookie' opaca utilizada en las llamadas de vuelta a perf
common_cpu                 la cpu en la que ocurrió el evento
common_secs                la porción de segundos de la marca de tiempo del evento
common_nsecs               la porción de nanosegundos de la marca de tiempo del evento
common_pid                 el pid de la tarea actual
common_comm                el nombre del proceso actual

Todos los campos restantes en el archivo de formato del evento tienen contrapartes como argumentos de la función manejadora con el mismo nombre, como se puede ver en el ejemplo anterior.

Lo anterior proporciona los conceptos básicos necesarios para acceder directamente a cada campo de cada evento en un trazado, lo que cubre el 90% de lo que necesita saber para escribir un script de trazado útil. Las secciones siguientes cubren el resto.

ESTRUCTURA DEL SCRIPT

Cada script de Python de perf script debe comenzar configurando una ruta de búsqueda de módulos de Python e 'importando' algunos módulos de soporte (ver descripciones de módulos a continuación):

.ft C
 import os
 import sys
 sys.path.append(os.environ['PERF_EXEC_PATH'] + \
              '/scripts/python/Perf-Trace-Util/lib/Perf/Trace')
 from perf_trace_context import *
 from Core import *
.ft

El resto del script puede contener funciones manejadoras y funciones de soporte en cualquier orden.

Aparte de las funciones manejadoras de eventos discutidas anteriormente, cada script puede implementar un conjunto de funciones opcionales:

trace_begin, si se define, se llama antes de que se procese cualquier evento y da a los scripts la oportunidad de realizar tareas de configuración:

.ft C
def trace_begin():
    pass
.ft

trace_end, si se define, se llama después de que se hayan procesado todos los eventos y da a los scripts la oportunidad de realizar tareas de fin de script, como mostrar resultados:

.ft C
def trace_end():
    pass
.ft

trace_unhandled, si se define, se llama para cualquier evento que no tenga un manejador definido explícitamente para él. El conjunto estándar de argumentos comunes se pasa a él:

.ft C
def trace_unhandled(event_name, context, event_fields_dict):
    pass
.ft

process_event, si se define, se llama para cualquier evento que no sea un tracepoint

.ft C
def process_event(param_dict):
    pass
.ft

MÓDULOS Y FUNCIONES DISPONIBLES

Las siguientes secciones describen las funciones y variables disponibles a través de los diversos módulos de Python de script de perf. Para usar las funciones y variables del módulo dado, agregue la línea correspondiente de from XXXX import a su script de script de perf.

Módulo Core.py

Estas funciones proporcionan algunas funciones esenciales para los scripts de usuario.

Las funciones flag_str y symbol_str proporcionan cadenas legibles por humanos para campos de banderas y simbólicos. Estas corresponden a las cadenas y valores analizados de los campos de formato de impresión de los archivos de formato de evento:

flag_str(event_name, field_name, field_value) - devuelve la representación de cadena correspondiente a field_value para el campo de bandera field_name del evento event_name
symbol_str(event_name, field_name, field_value) - devuelve la representación de cadena correspondiente a field_value para el campo simbólico field_name del evento event_name

La función autodict devuelve un tipo especial de diccionario de Python que implementa los hashes *autovivificantes* de Perl en Python, es decir, con hashes autovivificantes, puede asignar valores de hash anidados sin tener que pasar por el inconveniente de crear niveles intermedios si no existen.

autodict() - devuelve una instancia de diccionario autovivificante

Módulo perf_trace_context

Algunos de los campos *comunes* en el archivo de formato del evento no son tan comunes, pero deben hacerse accesibles a los scripts de usuario de todos modos.

perf_trace_context define un conjunto de funciones que se pueden utilizar para acceder a estos datos en el contexto del evento actual. Cada una de estas funciones espera una variable de contexto, que es la misma que la variable de contexto pasada a cada manejador de eventos de tracepoint como segundo argumento. Para eventos que no son tracepoint, la variable de contexto también está presente como perf_trace_context.perf_script_context .

common_pc(context) - devuelve el recuento de preempt common para el evento actual
common_flags(context) - devuelve los flags comunes para el evento actual
common_lock_depth(context) - devuelve la profundidad de bloqueo común para el evento actual
perf_sample_insn(context) - devuelve la instrucción de código máquina
perf_set_itrace_options(context, itrace_options) - establece las opciones --itrace si aún no se han establecido
perf_sample_srcline(context) - devuelve nombre_archivo_fuente, número_línea
perf_sample_srccode(context) - devuelve nombre_archivo_fuente, número_línea, línea_fuente
perf_config_get(config_name) - devuelve el valor del elemento de configuración nombrado, o None si no está establecido

Módulo Util.py

Varias funciones de utilidad para usar con perf script:

nsecs(secs, nsecs) - devuelve el total de nsecs dado un par secs/nsecs
nsecs_secs(nsecs) - devuelve la porción entera de segundos dado nsecs
nsecs_nsecs(nsecs) - devuelve el resto de nsecs dado nsecs
nsecs_str(nsecs) - devuelve una cadena imprimible en formato secs.nsecs
avg(total, n) - devuelve el promedio dado una suma y un número total de valores

CAMPOS SOPORTADOS

Campos actualmente soportados:

ev_name, comm, id, stream_id, pid, tid, cpu, ip, time, period, phys_addr, addr, symbol, symoff, dso, time_enabled, time_running, values, callchain, brstack, brstacksym, datasrc, datasrc_decode, iregs, uregs, weight, transaction, raw_buf, attr, cpumode.

Campos que también pueden estar presentes:

flags - banderas de muestra
flags_disp - visualización de banderas de muestra
insn_cnt - recuento de instrucciones para determinar instrucciones por ciclo (IPC)
cyc_cnt - recuento de ciclos para determinar IPC
addr_correlates_sym - addr puede correlacionarse con un símbolo
addr_dso - addr dso
addr_symbol - addr símbolo
addr_symoff - offset del símbolo addr

Algunos campos tienen sub-elementos:

brstack: from, to, from_dsoname, to_dsoname, mispred, predicted, in_tx, abort, cycles.

brstacksym: items: from, to, pred, in_tx, abort (cadena convertida)

Por ejemplo, podemos usar este código para imprimir brstack "from", "to", "cycles".

if brstack in dict: for entry in dict[brstack]: print "from %s, to %s, cycles %s" % (entry["from"], entry["to"], entry["cycles"])
