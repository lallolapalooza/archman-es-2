NOMBRE

perf-script-perl - Procesar datos de traza con un script Perl

SINOPSIS

perf script [-s [Perl]:script[.pl] ]

DESCRIPCIÓN

Esta opción de script de perf se utiliza para procesar datos de script de perf utilizando el intérprete Perl incorporado de perf. Lee y procesa el archivo de entrada y muestra los resultados del análisis de traza implementado en el script Perl dado, si los hay.

SCRIPTS DE INICIO

Puede evitar leer el resto de este documento ejecutando perf script -g perl en el mismo directorio que un archivo de traza perf.data existente. Eso generará un script de inicio que contiene un manejador para cada uno de los tipos de eventos en el archivo de traza; simplemente imprime todos los campos disponibles para cada evento en el archivo de traza.

También puede consultar los scripts existentes en ~/libexec/perf-core/scripts/perl para ver ejemplos típicos que muestran cómo realizar tareas básicas como agregar datos de eventos, imprimir resultados, etc. Además, el script check-perf-script.pl, aunque no es interesante por sus resultados, intenta ejercitar todas las funciones principales de scripting.

MANEJADORES DE EVENTOS

Cuando se invoca perf script usando un script de traza, se llama a una función manejadora definida por el usuario para cada evento en la traza. Si no hay una función manejadora definida para un tipo de evento dado, el evento se ignora (o se pasa a una función trace_unhandled, ver abajo) y se procesa el siguiente evento.

La mayoría de los valores de los campos del evento se pasan como argumentos a la función manejadora; algunos de los menos comunes no lo son, estos están disponibles como llamadas de vuelta al ejecutable de perf (ver abajo).

Como ejemplo, el siguiente comando perf record se puede usar para registrar todos los eventos sched_wakeup en el sistema:

# perf record -a -e sched:sched_wakeup

Las trazas destinadas a ser procesadas usando un script deben ser grabadas con la opción anterior: -a para habilitar la recopilación en todo el sistema.

El archivo de formato para el evento sched_wakeup define los siguientes campos (ver /sys/kernel/tracing/events/sched/sched_wakeup/format):

.ft C
 format:
        field:unsigned short common_type;
        field:unsigned char common_flags;
        field:unsigned char common_preempt_count;
        field:int common_pid;
        field:char comm[TASK_COMM_LEN];
        field:pid_t pid;
        field:int prio;
        field:int success;
        field:int target_cpu;
.ft

La función manejadora para este evento se definiría como:

.ft C
sub sched::sched_wakeup
{
   my ($event_name, $context, $common_cpu, $common_secs,
       $common_nsecs, $common_pid, $common_comm,
       $comm, $pid, $prio, $success, $target_cpu) = @_;
}
.ft

El manejador de funciones toma la forma subsystem::event_name.

Los argumentos $common_* en la lista de argumentos del manejador son el conjunto de argumentos pasados a todos los manejadores de eventos; algunos de los campos corresponden a los campos common_* en el archivo de formato, pero algunos son sintetizados, y algunos de los campos common_* no son lo suficientemente comunes como para pasarlos a cada evento como argumentos, pero están disponibles como funciones de biblioteca.

Aquí hay una breve descripción de cada uno de los argumentos de evento invariantes:

$event_name                el nombre del evento como texto
$context                   una 'cookie' opaca utilizada en las llamadas de vuelta a perf
$common_cpu                la cpu en la que ocurrió el evento
$common_secs               la porción de segundos de la marca de tiempo del evento
$common_nsecs              la porción de nanosegundos de la marca de tiempo del evento
$common_pid                el pid de la tarea actual
$common_comm               el nombre del proceso actual

Todos los campos restantes en el archivo de formato del evento tienen contrapartes como argumentos de la función manejadora del mismo nombre, como se puede ver en el ejemplo anterior.

Lo anterior proporciona lo básico necesario para acceder directamente a cada campo de cada evento en una traza, lo que cubre el 90% de lo que necesita saber para escribir un script de traza útil. Las secciones siguientes cubren el resto.

ESTRUCTURA DEL SCRIPT

Cada script Perl de perf script debe comenzar configurando una ruta de búsqueda de módulos Perl y 'usando' algunos módulos de soporte (ver descripciones de módulos a continuación):

.ft C
 use lib "$ENV{'PERF_EXEC_PATH'}/scripts/perl/Perf-Trace-Util/lib";
 use lib "./Perf-Trace-Util/lib";
 use Perf::Trace::Core;
 use Perf::Trace::Context;
 use Perf::Trace::Util;
.ft

El resto del script puede contener funciones manejadoras y funciones de soporte en cualquier orden.

Aparte de las funciones manejadoras de eventos discutidas anteriormente, cada script puede implementar un conjunto de funciones opcionales:

trace_begin, si se define, se llama antes de que se procese cualquier evento y da a los scripts la oportunidad de realizar tareas de configuración:

.ft C
 sub trace_begin
 {
 }
.ft

trace_end, si se define, se llama después de que todos los eventos se hayan procesado y da a los scripts la oportunidad de realizar tareas de fin de script, como mostrar resultados:

.ft C
sub trace_end
{
}
.ft

trace_unhandled, si se define, se llama después de cualquier evento que no tenga un manejador explícitamente definido para él. Se le pasan el conjunto estándar de argumentos comunes:

.ft C
sub trace_unhandled
{
    my ($event_name, $context, $common_cpu, $common_secs,
        $common_nsecs, $common_pid, $common_comm) = @_;
}
.ft

Las secciones restantes proporcionan descripciones de cada uno de los módulos Perl de script de perf incorporados disponibles y sus funciones asociadas.

MÓDULOS Y FUNCIONES DISPONIBLES

Las siguientes secciones describen las funciones y variables disponibles a través de los diversos módulos Perf::Trace::* de Perl. Para usar las funciones y variables del módulo dado, agregue la línea use Perf::Trace::XXX correspondiente a su script de script de perf.

Módulo Perf::Trace::Core

Estas funciones proporcionan algunas funciones esenciales a los scripts de usuario.

Las funciones flag_str y symbol_str proporcionan cadenas legibles por humanos para campos simbólicos y de bandera. Estos corresponden a las cadenas y valores analizados de los campos print fmt de los archivos de formato de eventos:

flag_str($event_name, $field_name, $field_value) - devuelve la representación de cadena correspondiente a $field_value para el campo de bandera $field_name del evento $event_name
symbol_str($event_name, $field_name, $field_value) - devuelve la representación de cadena correspondiente a $field_value para el campo simbólico $field_name del evento $event_name

Módulo Perf::Trace::Context

Algunos de los campos common en el archivo de formato no son tan comunes, pero aún así deben hacerse accesibles a los scripts de usuario.

Perf::Trace::Context define un conjunto de funciones que se pueden utilizar para acceder a estos datos en el contexto del evento actual. Cada una de estas funciones espera una variable $context, que es la misma que la variable $context pasada a cada manejador de eventos como segundo argumento.

common_pc($context) - devuelve el recuento common_preempt para el evento actual
common_flags($context) - devuelve los common_flags para el evento actual
common_lock_depth($context) - devuelve la common_lock_depth para el evento actual

Módulo Perf::Trace::Util

Varias funciones de utilidad para usar con perf script:

nsecs($secs, $nsecs) - devuelve el total de nsecs dado un par secs/nsecs
nsecs_secs($nsecs) - devuelve la porción entera de secs dada nsecs
nsecs_nsecs($nsecs) - devuelve el resto de nsecs dada nsecs
nsecs_str($nsecs) - devuelve una cadena imprimible en el formato secs.nsecs
avg($total, $n) - devuelve el promedio dado una suma y un número total de valores

perf-script-perl — Perl script to process perf trace

NAME

perf-script-perl - Perl script to process perf trace

SYNOPSIS

perf script -s <script_file> [options]
perf script -s <script_file> -- [script_options]

DESCRIPTION

This script allows you to process the trace output of the perf(1) tool. It’s a Perl script that uses the trace data generated by perf(1) and provides a Perl API to access the trace events.

This allows for custom, complex analysis of performance data that would be difficult or impossible to achieve with standard perf(1) scripting.

The script works by reading the trace file (usually `perf.data` in the current directory) and calling specific functions within the provided Perl script for each event encountered.

STARTER SCRIPTS

The following starter scripts are available:

  • perf-script-perl(1): This script, the one you are currently reading. Used to process trace data with a Perl script.

EVENT HANDLERS

The Perl script can define handlers for various event types. The most common ones are:

  • trace_begin(): Called when tracing begins.
  • trace_end(): Called when tracing ends.
  • trace_event(event): Called for each trace event. The `event` object provides methods to access event details.
  • process_event(event, comm, pid, tid, ip, dso, symbol): An older handler, generally superseded by trace_event.

SCRIPT LAYOUT

A typical Perl script for perf(1) processing would look like this:

#!/usr/bin/env perl

# Perl script to process perf trace data

use strict;
use warnings;

my %event_counts;

# Handler for each trace event
sub trace_event {
    my ($event) = @_;

    # Access event details
    my $name = $event->{name};
    my $comm = $event->{comm};
    my $pid  = $event->{pid};
    my $tid  = $event->{tid};

    # Increment count for this event name
    $event_counts{$name}++;

    # Print event details (example)
    # print "PID: $pid, Comm: $comm, Event: $name\n";
}

# Handler for when tracing begins
sub trace_begin {
    print "Tracing started...\n";
}

# Handler for when tracing ends
sub trace_end {
    print "Tracing ended.\n";
    print "Event counts:\n";
    foreach my $name (sort keys %event_counts) {
        print "$name: $event_counts{$name}\n";
    }
}

# You can add more handlers for specific event types if needed
# For example, handling only 'syscalls':
# sub syscall {
#     my ($event) = @_;
#     print "Syscall: ", $event->{name}, "\n";
# }

Save this script to a file (e.g., `my_trace_script.pl`) and run it with:

perf script -s my_trace_script.pl

AVAILABLE MODULES AND FUNCTIONS

The Perl API provides access to event data through a hash reference passed to the handlers. Key fields include:

  • name: The name of the event (e.g., "syscall", "sched_switch").
  • pid: The process ID.
  • tid: The thread ID.
  • comm: The command name.
  • ip: The instruction pointer.
  • cpu: The CPU number.
  • time: The event timestamp.
  • type: The event type.
  • parent: The parent event (for correlation).
  • dso: The DSO (Dynamic Shared Object) the event occurred in.
  • symbol: The symbol name associated with the event.

For more details on the specific fields available for each event type, refer to the perf(1) documentation and the source code of the Perl tracing script.
