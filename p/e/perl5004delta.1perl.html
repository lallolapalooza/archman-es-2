PERL5004DELTA(1perl) Guía de Referencia para Programadores de Perl PERL5004DELTA(1perl)

NOMBRE

perl5004delta - novedades de perl5.004

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.003 (tal como se documenta en Programming Perl, segunda edición - el libro del Camello) y esta.

Entornos soportados

Perl5.004 se compila directamente en Unix, Plan 9, LynxOS, VMS, OS/2, QNX, AmigaOS y Windows NT. Perl también funciona en Windows 95, pero no se puede compilar allí por falta de un intérprete de comandos razonable.

Cambios en el núcleo

Lo más importante es que se corrigieron muchos errores, incluyendo varios problemas de seguridad. Consulte el archivo Changes en la distribución para obtener detalles.

La asignación de listas a %ENV funciona

"%ENV = ()" y "%ENV = @list" ahora funcionan como se esperaba (excepto en VMS, donde genera un error fatal).

Cambio en el error "No se encuentra Foo.pm en @INC"

El error "No se encuentra Foo.pm en @INC" ahora muestra el contenido de @INC para facilitar la depuración.

Opción de compilación: Compatibilidad binaria con 5.003

Hay una nueva pregunta en Configure que pregunta si desea mantener la compatibilidad binaria con Perl 5.003. Si elige la compatibilidad binaria, no tendrá que recompilar sus extensiones, pero podría tener conflictos de símbolos si incrusta Perl en otra aplicación, al igual que en la versión 5.003. Por defecto, se mantiene la compatibilidad binaria a expensas de la contaminación de la tabla de símbolos.

Variable de entorno $PERL5OPT

Ahora puede colocar opciones de Perl en la variable de entorno $PERL5OPT. A menos que Perl se esté ejecutando con verificaciones de seguridad (taint checks), interpretará esta variable como si su contenido hubiera aparecido en una línea "#!perl" al principio de su script, excepto que los guiones son opcionales. PERL5OPT solo puede usarse para establecer los siguientes interruptores: -[DIMUdmw].

Limitaciones en las opciones -M, -m y -T

Las opciones "-M" y "-m" ya no están permitidas en la línea "#!" de un script. Si un script necesita un módulo, debe invocarlo con la pragmática "use".

La opción -T también está prohibida en la línea "#!" de un script, a menos que estuviera presente en la línea de comandos de Perl. Debido a cómo funciona "#!", esto generalmente significa que -T debe ser el primer argumento. Por lo tanto:

#!/usr/bin/perl -T -w

probablemente funcionará para un script ejecutable invocado como "nombre_script", mientras que:

#!/usr/bin/perl -w -T

probablemente fallará bajo las mismas condiciones. (Los sistemas no Unix probablemente no seguirán esta regla.) Pero "perl nombre_script" garantizadamente fallará, ya que entonces no hay posibilidad de que -T se encuentre en la línea de comandos antes de encontrarse en la línea "#!".

Advertencias más precisas

Si eliminó la opción -w de sus scripts Perl 5.003 porque hacía que Perl fuera demasiado verboso, le recomendamos que vuelva a ponerla cuando actualice a Perl 5.004. Cada nueva versión de perl tiende a eliminar algunas advertencias indeseables, mientras que agrega nuevas advertencias que pueden detectar errores en sus scripts.

Obsoleto: Herencia de "AUTOLOAD" para no métodos

Antes de Perl 5.004, las funciones "AUTOLOAD" se buscaban como métodos (usando la jerarquía @ISA), incluso cuando la función a ser cargada automáticamente se llamaba como una función normal (por ejemplo, Foo::bar()), no como un método (por ejemplo, "Foo->bar()" o "$obj->bar()").

Perl 5.005 usará la búsqueda de métodos solo para los "AUTOLOAD" de los métodos. Sin embargo, hay una base significativa de código existente que puede estar usando el comportamiento antiguo. Por lo tanto, como paso intermedio, Perl 5.004 emite una advertencia opcional cuando un no método utiliza un "AUTOLOAD" heredado.

La regla simple es: La herencia no funcionará al cargar automáticamente no métodos. La solución simple para el código antiguo es: En cualquier módulo que solía depender de heredar "AUTOLOAD" para no métodos de una clase base llamada "ClaseBase", ejecute "*AUTOLOAD = \&ClaseBase::AUTOLOAD" durante el inicio.

Previamente obsoleto %OVERLOAD ya no es utilizable

El uso de %OVERLOAD para definir la sobrecarga fue obsoleto en 5.003. La sobrecarga ahora se define usando la pragmática overload. %OVERLOAD todavía se usa internamente pero no debe ser usado por scripts de Perl. Consulte overload para más detalles.

Argumentos de subrutinas creados solo cuando se modifican

En Perl 5.004, los elementos inexistentes de arreglos y hashes usados como parámetros de subrutinas se crean solo si se les asigna un valor (a través de @_).

Versiones anteriores de Perl varían en su manejo de tales argumentos. Las versiones 5.002 y 5.003 de Perl siempre los creaban. Las versiones 5.000 y 5.001 de Perl solo los creaban si no eran el primer argumento (lo cual era casi seguro un error). Versiones anteriores de Perl nunca los creaban.

Por ejemplo, dado este código:

undef @a; undef %a;
sub mostrar { print $_[0] };
sub cambiar { $_[0]++ };
mostrar($a[2]);
cambiar($a{b});

Después de que este código se ejecuta en Perl 5.004, $a{b} existe pero $a[2] no. En Perl 5.002 y 5.003, tanto $a{b} como $a[2] existirían (pero el valor de $a[2] sería indefinido).

Vector de grupo modificable con $)

La variable especial $) siempre ha reflejado (bueno, al menos en Perl 5) no solo el grupo efectivo actual, sino también la lista de grupos devuelta por la función C getgroups() (si existe). Sin embargo, hasta esta versión, no había una forma de llamar a la función C setgroups() desde Perl.

En Perl 5.004, asignar a $) es exactamente simétrico con examinarlo: el primer número en su valor de cadena se usa como gid efectivo; si hay algún número después del primero, se pasa a la función C setgroups() (si existe).

Análisis corregido de $$<dígito>, &$<dígito>, etc.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

El tc.

Las versiones de Perl anteriores a 5.004 interpretaban erróneamente cualquier marcador de tipo seguido de "$" y un dígito. Por ejemplo, "$$0" se tomaba incorrectamente como "${$}0" en lugar de "${$0}". Este error está (en su mayor parte) corregido en Perl 5.004.

Sin embargo, los desarrolladores de Perl 5.004 no pudieron corregir completamente este error, ya que al menos dos módulos ampliamente utilizados dependen del antiguo significado de "$$0" en una cadena. Por lo tanto, Perl 5.004 todavía interpreta "$$<dígito>" de la forma antigua (rota) dentro de las cadenas; pero genera este mensaje como una advertencia. Y en Perl 5.005, este tratamiento especial cesará.

Localización corregida de $

Las versiones de Perl anteriores a 5.004 no siempre localizaban correctamente las variables especiales relacionadas con las expresiones regulares. Perl 5.004 las localiza, como siempre ha dicho la documentación que debería hacer. Esto puede provocar que $1, $2, etc. ya no se establezcan donde los programas existentes los usan.

Sin restablecimiento de $. en cierre implícito

La documentación de Perl 5.0 siempre ha afirmado que $. *no* se restablece cuando un manejador de archivo ya abierto se vuelve a abrir sin una llamada intermedia a "close". Debido a un error, las versiones de Perl 5.000 a 5.003 *sí* restablecían $. bajo esa circunstancia; Perl 5.004 no lo hace.

"wantarray" puede devolver undef

El operador "wantarray" devuelve verdadero si se espera que una subrutina devuelva una lista, y falso en caso contrario. En Perl 5.004, "wantarray" también puede devolver el valor indefinido si el valor de retorno de una subrutina no se utilizará en absoluto, lo que permite a las subrutinas evitar un cálculo costoso de un valor de retorno si no se va a utilizar.

"eval EXPR" determina el valor de EXPR en contexto escalar

Perl (versión 5) solía determinar el valor de EXPR de manera inconsistente, utilizando a veces incorrectamente el contexto circundante para la determinación. Ahora, el valor de EXPR (antes de ser analizado por eval) siempre se determina en un contexto escalar. Una vez analizado, se ejecuta como antes, proporcionando el contexto que el ámbito circundante del eval proporcionaba. Este cambio hace que el comportamiento sea compatible con Perl4, además de corregir errores derivados del comportamiento inconsistente. Este programa:

@a = qw(time now is time);
print eval @a;
print '|', scalar eval @a;

solía imprimir algo como "timenowis881399109|4", pero ahora (y en perl4) imprime "4|4".

Cambios en las verificaciones de tainting

Un error en versiones anteriores podría haber fallado en detectar algunas condiciones inseguras cuando las verificaciones de tainting están activadas. (Las verificaciones de tainting se utilizan en scripts setuid o setgid, o cuando se activan explícitamente con la opción de invocación "-T".) Aunque es poco probable, esto puede hacer que un script que funcionaba previamente falle ahora, lo que debe interpretarse como una bendición, ya que indica que se acaba de tapar un agujero de seguridad potencialmente grave.

Las nuevas restricciones al hacer tainting incluyen:

No glob() o <*>
Estos operadores pueden invocar el shell C (csh), que no se puede hacer seguro. Esta restricción se levantará en una versión futura de Perl cuando el globbing se implemente sin el uso de un programa externo.
No invocar si $CDPATH, $ENV, $BASH_ENV tienen tainting
Estas variables de entorno pueden alterar el comportamiento de los programas invocados (especialmente shells) de formas que socavan la seguridad. Por lo tanto, ahora se tratan como peligrosas, de manera similar a $IFS y $PATH.
No invocar si $TERM con tainting no parece un nombre de terminal
Algunas bibliotecas de termcap hacen cosas inseguras con $TERM. Sin embargo, sería innecesariamente severo tratar todos los valores de $TERM como inseguros, ya que solo los metacaracteres del shell pueden causar problemas en $TERM. Por lo tanto, un $TERM con tainting se considera seguro si contiene solo caracteres alfanuméricos, guiones bajos, guiones y dos puntos, y no seguro si contiene otros caracteres (incluidos los espacios en blanco).

Nuevo módulo Opcode y módulo Safe revisado

Un nuevo módulo Opcode soporta la creación, manipulación y aplicación de máscaras de opcode. El módulo Safe revisado tiene una nueva API y está implementado utilizando el nuevo módulo Opcode. Por favor, lea la nueva documentación de Opcode y Safe.

Mejoras en la incrustación

En versiones anteriores de Perl, no era posible crear más de una instancia del intérprete de Perl dentro de un solo proceso sin fugas como un colador y/o fallar. Los errores que causaban este comportamiento han sido corregidos. Sin embargo, todavía debe tener cuidado al incrustar Perl en un programa C. Consulte la página de manual perlembed actualizada para obtener consejos sobre cómo administrar sus intérpretes.

Cambio interno: clase FileHandle basada en clases IO::*

Los manejadores de archivo ahora se almacenan internamente como tipo IO::Handle. El módulo FileHandle todavía se admite para compatibilidad con versiones anteriores, pero ahora es simplemente un front-end para los módulos IO::*, específicamente IO::Handle, IO::Seekable e IO::File. Sugerimos, pero no exigimos, que utilice los módulos IO::* en código nuevo.

En armonía con este cambio, *GLOB{FILEHANDLE} es ahora solo un sinónimo compatible con versiones anteriores de *GLOB{IO}.

Cambio interno: interfaz de abstracción PerlIO

Ahora es posible compilar Perl con el paquete de E/S sfio de AT&T en lugar de stdio. Consulte perlapio para obtener más detalles y el archivo INSTALL sobre cómo usarlo.

Sintaxis nueva y modificada

$coderef->(PARAMS)
Una referencia a subrutina ahora puede ir seguida de una flecha y una lista de parámetros (posiblemente vacía). Esta sintaxis denota una llamada a la subrutina referenciada, con los parámetros dados (si los hay).

Esta nueva sintaxis sigue el patrón de "$hashref->{FOO}" y "$aryref->[$foo]": ahora puede escribir &$subref($foo) como $subref->($foo). Todos estos términos de flecha pueden encadenarse; por lo tanto, "&{$table->{FOO}}($bar)" ahora se puede escribir como "$table->{FOO}->($bar)".

Constantes integradas nuevas y modificadas

__PACKAGE__
El nombre del paquete actual en tiempo de compilación, o el valor indefinido si no hay un paquete actual (debido a una directiva "package;"). Al igual que "__FILE__" y "__LINE__", "__PACKAGE__" *no* se interpola en cadenas.

Variables integradas nuevas y modificadas

$^E
Mensaje de error extendido en algunas plataformas. (También conocido como $EXTENDED_OS_ERROR si usa "use English").
$^H
El conjunto actual de verificaciones de sintaxis habilitadas por "use strict". Consulte la documentación de "strict" para obtener más detalles. No es realmente nuevo, pero está documentado recientemente. Dado que está destinado al uso interno de los componentes principales de Perl, no hay un nombre largo de "use English" para esta variable.
$^M
Por defecto, quedarse sin memoria no es captable. Sin embargo, si se compila para ello, Perl puede usar el contenido de $^M como un grupo de emergencia después de fallar con este mensaje. Supongamos que su Perl se compiló con -DPERL_EMERGENCY_SBRK y usó el malloc de Perl. Entonces 
$^M = 'a' x (1<<16);

asignaría un búfer de 64K para usarlo en caso de emergencia. Consulte el archivo INSTALL para obtener información sobre cómo habilitar esta opción. Como desincentivo para el uso casual de esta característica avanzada, no hay un nombre largo de "use English" para esta variable.

Funciones integradas nuevas y modificadas

delete en slices
Esto ahora funciona. (p. ej., "delete @ENV{'PATH', 'MANPATH'}")
flock
ahora es compatible en más plataformas, prefiere fcntl a lockf al emular, y siempre vacía antes de (des)bloquear.
printf y sprintf
Perl ahora implementa estas funciones internamente; ya no utiliza la función sprintf() de la biblioteca C, excepto para números de punto flotante, e incluso entonces solo se permiten las banderas conocidas. Como resultado, ahora es posible saber qué conversiones y fl

Nuevas conversiones y banderas para sprintf()

Para obtener más detalles sobre los nuevos especificadores de conversión y banderas de formato, consulte la sección de "sprintf" en perlfunc.

Las nuevas conversiones en sprintf() de Perl son:

%i   un sinónimo de %d
%p   un puntero (la dirección del valor de Perl, en hexadecimal)
%n   especial: *almacena* el número de caracteres de salida hasta el momento
     en la siguiente variable de la lista de parámetros

Las nuevas banderas que van entre el "%" y la conversión son:

#    prefija octal con "0", hexadecimal con "0x"
h    interpreta el entero como tipo C "short" o "unsigned short"
V    interpreta el entero como el tipo entero estándar de Perl

Además, donde aparecería un número en las banderas, se puede usar un asterisco ("*") en su lugar, en cuyo caso Perl usa el siguiente elemento de la lista de parámetros como el número dado (es decir, como el ancho del campo o la precisión). Si un ancho de campo obtenido mediante "*" es negativo, tiene el mismo efecto que la bandera '-': justificación a la izquierda.

Consulte "sprintf" en perlfunc para obtener una lista completa de conversiones y banderas.

keys como lvalue

Como lvalue, "keys" le permite aumentar el número de cubetas hash asignadas para el hash dado. Esto puede proporcionarle cierta medida de eficiencia si sabe que el hash va a crecer mucho. (Esto es similar a pre-extender un array asignando un número mayor a $#array). Si dice

keys %hash = 200;

entonces a %hash se le asignarán al menos 200 cubetas. Estas cubetas se conservarán incluso si hace "%hash = ()"; use undef %hash si desea liberar el almacenamiento mientras %hash todavía está en el ámbito. No puede reducir el número de cubetas asignadas para el hash usando "keys" de esta manera (pero no necesita preocuparse por hacerlo por accidente, ya que intentarlo no tiene efecto).

my() en Estructuras de Control

Ahora puede usar my() (con o sin los paréntesis) en las expresiones de control de estructuras de control como:

while (defined(my $line = <>)) {
    $line = lc $line;
} continue {
    print $line;
}
if ((my $answer = <STDIN>) =~ /^y(es)?$/i) {
    user_agrees();
} elsif ($answer =~ /^n(o)?$/i) {
    user_disagrees();
} else {
    chomp $answer;
    die "`$answer' is neither `yes' nor `no'";
}

Además, puede declarar una variable de control de bucle foreach como léxica anteponiéndole la palabra "my". Por ejemplo, en:

foreach my $i (1, 2, 3) {
    some_function();
}

$i es una variable léxica, y el ámbito de $i se extiende hasta el final del bucle, pero no más allá.

Tenga en cuenta que todavía no puede usar my() en variables de puntuación globales como $_ y similares.

pack() y unpack()

Un nuevo formato 'w' representa un entero comprimido BER (como se define en ASN.1). Su formato es una secuencia de uno o más bytes, cada uno de los cuales proporciona siete bits del valor total, con el más significativo primero. El bit ocho de cada byte está establecido, excepto para el último byte, en el que el bit ocho está claro.

Si a 'p' o 'P' se les da undef como valores, ahora generan un puntero NULL.

Tanto pack() como unpack() ahora fallan cuando sus plantillas contienen tipos inválidos. (Los tipos inválidos solían ser ignorados).

sysseek()

El nuevo operador sysseek() es una variante de seek() que establece y obtiene la posición de lectura/escritura del archivo, utilizando la llamada al sistema lseek(2). Es la única forma fiable de buscar antes de usar sysread() o syswrite(). Su valor de retorno es la nueva posición, o el valor indefinido en caso de fallo.

use VERSION

Si el primer argumento de "use" es un número, se trata como un número de versión en lugar de un nombre de módulo. Si la versión del intérprete de Perl es menor que VERSION, se imprime un mensaje de error y Perl sale inmediatamente. Debido a que "use" ocurre en tiempo de compilación, esta comprobación se realiza inmediatamente durante el proceso de compilación, a diferencia de "require VERSION", que espera hasta el tiempo de ejecución para la comprobación. Esto es a menudo útil si necesita verificar la versión actual de Perl antes de "usar" módulos de biblioteca que han cambiado de manera incompatible con versiones anteriores de Perl. (Intentamos no hacer esto más de lo necesario).

use Module VERSION LIST

Si el argumento VERSION está presente entre Module y LIST, entonces "use" llamará al método VERSION en la clase Module con la versión dada como argumento. El método VERSION por defecto, heredado de la clase UNIVERSAL, muere si la versión dada es mayor que el valor de la variable $Module::VERSION. (¡Tenga en cuenta que no hay una coma después de VERSION!).

Este mecanismo de verificación de versiones es similar al utilizado actualmente en el módulo Exporter, pero es más rápido y puede utilizarse con módulos que no utilizan Exporter. Es el método recomendado para código nuevo.

prototype(FUNCTION)

Devuelve el prototipo de una función como una cadena (o "undef" si la función no tiene prototipo). FUNCTION es una referencia o el nombre de la función cuyo prototipo desea recuperar. (En realidad no es nuevo; simplemente nunca se documentó antes).

srand

La semilla predeterminada para "srand", que solía ser "time", ha sido cambiada. Ahora es una mezcla embriagadora de valores dependientes del sistema difíciles de predecir, que deberían ser suficientes para la mayoría de los propósitos cotidianos.

Antes de la versión 5.004, llamar a "rand" sin llamar primero a "srand" producía la misma secuencia de números aleatorios en la mayoría o en todas las máquinas. Ahora, cuando perl detecta que está llamando a "rand" y aún no ha llamado a "srand", llama a "srand" con la semilla predeterminada. Aún así debería llamar a "srand" manualmente si su código pudiera ejecutarse en un sistema anterior a la versión 5.004, por supuesto, o si desea una semilla distinta a la predeterminada.

$_ como Predeterminado

Las funciones documentadas en el "Camel" ahora, de hecho, usan $_ como predeterminado, y todas las que lo hacen están así documentadas en perlfunc.

m//gc no reinicia la posición de búsqueda en caso de fallo

El constructo de iteración de coincidencia "m//g" siempre reiniciaba la posición de búsqueda de su cadena objetivo (que es visible a través del operador "pos") cuando una coincidencia fallaba; como resultado, la siguiente coincidencia "m//g" después de un fallo comenzaba de nuevo al principio de la cadena. Con Perl 5.004, este reinicio puede ser deshabilitado agregando el modificador "c" (de "continue"), es decir, "m//gc". Esta característica, junto con la aserción de ancho cero "\G", hace posible encadenar coincidencias. Consulte perlop y perlre.

m//x ignora el espacio en blanco antes de ?*+{}

El constructo "m//x" siempre ha tenido la intención de ignorar todo el espacio en blanco sin escapar. Sin embargo, antes de Perl 5.004, el espacio en blanco tenía el efecto de escapar modificadores de repetición como "*" o "?"; por ejemplo, "/a *b/x" se interpretaba (mal) como "/a\*b/x". Este error ha sido corregido en 5.004.

los cierres anidados de "sub{}" funcionan ahora

Antes del lanzamiento 5.004, las funciones anidadas no funcionaban correctamente. Ahora sí lo hacen.

los formatos funcionan correctamente con léxicos cambiantes

Al igual que las funciones anónimas que contienen variables léxicas que cambian (como una variable de índice léxico para un bucle "foreach"), los formatos ahora funcionan correctamente. Por ejemplo, esto fallaba silenciosamente antes (solo imprimía ceros), pero ahora está bien:

my $i;
foreach $i ( 1 .. 10 ) {
    write;
}
format =
    my i is @#
    $i
.

Sin embargo, todavía falla (sin advertencia) si el foreach está dentro de una subrutina:

my $i;
sub foo {
  foreach $i ( 1 .. 10 ) {
    write;
  }
}
foo;
format =
    my i is @#
    $i
.

Nuevos métodos incorporados

El paquete "UNIVERSAL" contiene automáticamente los siguientes métodos que son heredados por todas las demás clases:

isa(CLASS)
"isa" devuelve *verdadero* si su objeto está bendecido en una subclase de "CLASS"

"isa" también es exportable y puede ser llamado como una subrutina con dos argumentos. Esto permite la capacidad de verificar a qué apunta una referencia. Ejemplo:

use UNIVERSAL qw(isa);
if(isa($ref, 'ARRAY')) {
   ...
}
can(METHOD)
"can" comprueba si su objeto tiene un método llamado "METHOD", si lo tiene entonces devuelve una referencia a la subrutina; si no, devuelve *undef*.
VERSION( [NEED] )
"VERSION" devuelve el número de versión de la clase (paquete). Si se proporciona el argumento NEED, comprobará que la versión actual (según lo definido por la variable $VERSION en el paquete dado) no sea menor que NEED; morirá si no es así. Este método normalmente se llama como un método de clase. Este método es llamado automáticamente por la forma "VERSION" de
"use". 
use A 1.2 qw(some imported subs);
# implies:
A->VERSION(1.2);

NOTE: "can" utiliza directamente el código interno de Perl para la búsqueda de métodos, y "isa" utiliza un método y una estrategia de caché muy similares. Esto puede causar efectos extraños si el código de Perl cambia dinámicamente @ISA en cualquier paquete.

Puede agregar otros métodos a la clase UNIVERSAL a través de código Perl o XS. No necesita "use UNIVERSAL" para que estos métodos estén disponibles en su programa. Esto solo es necesario si desea que "isa" esté disponible como una subrutina simple en el paquete actual.

TIEHANDLE ahora compatible

Vea perltie para otros tipos de tie()s.

TIEHANDLE classname, LIST
Este es el constructor para la clase. Eso significa que se espera que devuelva un objeto de algún tipo. La referencia se puede usar para mantener alguna información interna. 
sub TIEHANDLE {
    print "<shout>\n";
    my $i;
    return bless \$i, shift;
}
PRINT this, LIST
Este método se activará cada vez que se imprima en el manejador asociado. Más allá de su autorreferencia, también espera la lista que se pasó a la función print. 
sub PRINT {
    $r = shift;
    $$r++;
    return print join( $, => map {uc} @_), $\;
}
PRINTF this, LIST
Este método se activará cada vez que se imprima en el manejador asociado con la función printf(). Más allá de su autorreferencia, también espera el formato y la lista que se pasaron a la función printf. 
sub PRINTF {
    shift;
      my $fmt = shift;
    print sprintf($fmt, @_)."\n";
}
READ this LIST
Este método se llamará cuando el manejador se lea a través de las funciones "read" o "sysread". 
sub READ {
    $r = shift;
    my($buf,$len,$offset) = @_;
    print "READ called, \$buf=$buf, \$len=$len, \$offset=$offset";
}
READLINE this
Este método se llamará cuando se lea el manejador. El método debe devolver undef cuando no haya más datos. 
sub READLINE {
    $r = shift;
    return "PRINT called $$r times\n"
}
GETC this
Este método se llamará cuando se llame a la función "getc". 
sub GETC { print "Don't GETC, Get Perl"; return "a"; }
DESTROY this
Al igual que con otros tipos de ties, este método se llamará cuando el manejador asociado esté a punto de ser destruido. Esto es útil para depuración y posiblemente para limpieza. 
sub DESTROY {
    print "</shout>\n";
}

Mejoras de Malloc

Si perl se compila con el malloc incluido en la distribución de perl (es decir, si "perl -V:d_mymalloc" es 'define') entonces puede imprimir estadísticas de memoria en tiempo de ejecución ejecutando Perl de la siguiente manera:

env PERL_DEBUG_MSTATS=2 perl your_script_here

El valor 2 significa imprimir estadísticas después de la compilación y al salir; con un valor de 1, las estadísticas solo se imprimen al salir. (Si desea las estadísticas en un momento arbitrario, necesitará instalar el módulo opcional Devel::Peek).

Tres nuevas banderas de compilación son reconocidas por malloc.c. (No tienen efecto si perl se compila con el malloc() del sistema.)

-DPERL_EMERGENCY_SBRK
Si se define esta macro, quedarse sin memoria no tiene por qué ser un error fatal: se puede asignar un grupo de memoria a la variable especial $^M. Vea "$^M".
-DPACK_MALLOC
La asignación de memoria de Perl es por cubo con tamaños cercanos a potencias de dos. Debido a esto, la sobrecarga de malloc puede ser grande, especialmente para datos de tamaño exactamente una potencia de dos. Si se define "PACK_MALLOC", perl utiliza un algoritmo ligeramente diferente para asignaciones pequeñas (hasta 64 bytes de longitud), lo que hace posible tener una sobrecarga de hasta 1 byte para asignaciones que son potencias de dos (y aparecen con bastante frecuencia).

El ahorro de memoria esperado (con alineación de 8 bytes en "alignbytes") es de aproximadamente el 20% para el uso típico de Perl. La ralentización esperada debido a la sobrecarga adicional de malloc está en fracciones de un por ciento (difícil de medir, debido al efecto de la memoria guardada en la velocidad).

-DTWO_POT_OPTIMIZE
De manera similar a "PACK_MALLOC", esta macro mejora las asignaciones de datos con tamaños cercanos a una potencia de dos; pero esto funciona para asignaciones grandes (a partir de 16K por defecto). Tales asignaciones son típicas para hashes grandes y scripts de propósito especial, especialmente procesamiento de imágenes.

En sistemas recientes, el hecho de que perl requiera 2M del sistema para una asignación de 1M no afectará la velocidad de ejecución, ya que la cola de dicho bloque no se tocará (y, por lo tanto, no requerirá memoria real). Sin embargo, puede resultar en un error de falta de memoria prematuro. Por lo tanto, si va a manipular bloques muy grandes con tamaños cercanos a potencias de dos, sería prudente definir esta macro.

El ahorro de memoria esperado es 0-100% (100% en aplicaciones que requieren la mayor parte de la memoria en tales fragmentos 2**n); la ralentización esperada es insignificante.

Mejoras de eficiencia varias

Las funciones que tienen un prototipo vacío y que no hacen nada más que devolver un valor fijo ahora están en línea (por ejemplo, "sub PI () { 3.14159 }").

Cada clave de hash única solo se asigna una vez, sin importar cuántos hashes tengan una entrada con esa clave. Por lo tanto, incluso si tiene 100 copias del mismo hash, las claves del hash nunca necesitan ser reasignadas.

Cambios en Utilidades

Envía el HTML convertido a la salida estándar
La utilidad pod2html incluida con Perl 5.004 es completamente nueva. Por defecto, envía el HTML convertido a su salida estándar, en lugar de escribirlo en un archivo como lo hacía el pod2html de Perl 5.003. Utilice la opción --outfile=NOMBRE_ARCHIVO para escribir en un archivo.

xsubpp

Las XSUBs "void" ahora devuelven nada por defecto
Debido a un error de documentación/implementación en versiones anteriores de Perl, las XSUBs con un tipo de retorno de "void" en realidad devolvían un valor. Por lo general, ese valor era el GV para la XSUB, pero a veces era algún valor ya liberado o reutilizado, lo que a veces provocaba fallos en el programa.

En Perl 5.004, si una XSUB se declara como que devuelve "void", en realidad no devuelve ningún valor, es decir, una lista vacía (aunque hay una excepción de compatibilidad con versiones anteriores; ver abajo). Si su XSUB realmente devuelve un SV, debería darle un tipo de retorno de "SV *".

Por compatibilidad con versiones anteriores, xsubpp intenta adivinar si una XSUB "void" es realmente "void" o si quiere devolver un "SV *". Lo hace examinando el texto de la XSUB: si xsubpp encuentra lo que parece una asignación a ST(0), asume que el tipo de retorno de la XSUB es realmente "SV *".

Cambios en la API del Lenguaje C

"gv_fetchmethod" y "perl_call_sv"
La función "gv_fetchmethod" encuentra un método para un objeto, al igual que en Perl 5.003. El GV que devuelve puede ser una entrada de caché de métodos. Sin embargo, en Perl 5.004, las entradas de caché de métodos no son visibles para los usuarios; por lo tanto, ya no se pueden pasar directamente a "perl_call_sv". En su lugar, debe usar la macro "GvCV" en el GV para extraer su CV y pasar el CV a "perl_call_sv".

El síntoma más probable de pasar el resultado de "gv_fetchmethod" a "perl_call_sv" es que Perl produzca un error de "Subrutina indefinida llamada" en la segunda llamada a un método dado (ya que no hay caché en la primera llamada).

Nuevos Diagnósticos

Varias condiciones nuevas activarán advertencias que antes estaban en silencio. Algunas solo afectan a ciertas plataformas. Las siguientes nuevas advertencias y errores describen estas. Estos mensajes se clasifican de la siguiente manera (enumerados en orden creciente de desesperación):

(W) Una advertencia (opcional).
(D) Una advertencia de obsolescencia (opcional).
(S) Una advertencia severa (obligatoria).
(F) Un error fatal (atrapable).
(P) Un error interno que nunca deberías ver (atrapable).
(X) Un error muy fatal (no atrapable).
(A) Un mensaje de error externo (no generado por Perl).
"my" variable %s masks earlier declaration in same scope
(W) Una variable léxica ha sido redeclarada en el mismo ámbito, lo que elimina efectivamente todo el acceso a la instancia anterior. Esto es casi siempre un error tipográfico. Tenga en cuenta que la variable anterior seguirá existiendo hasta el final del ámbito o hasta que se destruyan todos los referentes de cierre a ella.
%s argument is not a HASH element or slice
(F) El argumento para delete() debe ser un elemento de hash, como 
$foo{$bar}
$ref->[12]->{"susie"}

o un slice de hash, como

@foo{$bar, $baz, $xyzzy}
@{$ref->[12]}{"susie", "queue"}
Allocation too large: %lx
(X) No puedes asignar más de 64K en una máquina MS-DOS.
Allocation too large
(F) No puedes asignar más de 2^31 + "una pequeña cantidad" bytes.
Applying %s to %s will act on scalar(%s)
(W) Los operadores de coincidencia de patrones (//), sustitución (s///) y transliteración (tr///) funcionan sobre valores escalares. Si aplica uno de ellos a un array o un hash, convertirá el array o hash a un valor escalar (la longitud de un array o la información de población de un hash) y luego operará sobre ese valor escalar. Probablemente no sea lo que pretendía hacer. Consulte "grep" en perlfunc y "map" en perlfunc para alternativas.
Attempt to free nonexistent shared string
(P) Perl mantiene una tabla interna de cadenas contada por referencias para optimizar el almacenamiento y el acceso a las claves de hash y otras cadenas. Esto indica que alguien intentó decrementar el contador de referencias de una cadena que ya no se encuentra en la tabla.
Attempt to use reference as lvalue in substr
(W) Proporcionó una referencia como primer argumento a substr() utilizado como lvalue, lo cual es bastante extraño. Quizás olvidó desreferenciarlo primero. Consulte "substr" en perlfunc.
Bareword "%s" refers to nonexistent package
(W) Usó un bareword calificado de la forma "Foo::", pero el compilador no vio ningún otro uso de ese espacio de nombres antes de ese punto. ¿Quizás necesita predeclarar un paquete?
Can't redefine active sort subroutine %s
(F) Perl optimiza el manejo interno de las subrutinas de ordenación y mantiene punteros a ellas. Intentó redefinir una de esas subrutinas de ordenación cuando estaba activa, lo cual no está permitido. Si realmente quiere hacer esto, debería escribir "sort { &func } @x" en lugar de "sort func @x".
Can't use bareword ("%s") as %s ref while "strict refs" in use
(F) Solo se permiten referencias duras con "strict refs". Las referencias simbólicas están prohibidas. Consulte perlref.
Cannot resolve method `%s' overloading `%s' in package `%s'
(P) Error interno al intentar resolver la sobrecarga especificada por un nombre de método (en lugar de una referencia a una subrutina).
Constant subroutine %s redefined
(S) Redefinió una subrutina que anteriormente era elegible para ser inlineada. Consulte "Constant Functions" en perlsub para ver comentarios y soluciones alternativas.
Constant subroutine %s undefined
(S) Anuló la definición de una subrutina que anteriormente era elegible para ser inlineada. Consulte "Constant Functions" en perlsub para ver comentarios y soluciones alternativas.
Copy method did not return a reference
(F) El método que sobrecarga '=' está defectuoso. Consulte "Copy Constructor" en overload.
Died
(F) Pasó a die() una cadena vacía (el equivalente a "die """) o la llamó sin argumentos y tanto $@ como $_ estaban vacíos.
Exiting pseudo-block via %s
(W) Está saliendo de una construcción de bloque bastante especial (como un bloque de ordenación o una subrutina) por medios poco convencionales, como un goto o una declaración de control de bucle. Consulte "sort" en perlfunc.
Identifier too long
(F) Perl limita los identificadores (nombres de variables, funciones, etc.) a 252 caracteres para nombres simples, un poco más para nombres compuestos (como $A::B). Ha excedido los límites de Perl. Es probable que las futuras versiones de Perl eliminen estas limitaciones arbitrarias.
Illegal character %s (carriage return)
(F) Se encontró un carácter de retorno de carro en la entrada. Esto es un error, no una advertencia, porque los caracteres de retorno de carro pueden romper cadenas multilínea, incluidos los here documents (por ejemplo, "print <<EOF;").
Illegal switch in PERL5OPT: %s
(X) La variable de entorno PERL5OPT solo puede usarse para establecer los siguientes switches: -[DIMUdmw].
Integer overflow in hex number
(S) El número literal hexadecimal que ha especificado es demasiado grande para su arquitectura. En una arquitectura de 32 bits, el literal hexadecimal más grande es 0xFFFFFFFF.
Integer overflow in octal number
(S) El número literal octal que ha especificado es demasiado grande para su arquitectura. En una arquitectura de 32 bits, el literal octal más grande es 037777777777.
internal error: glob failed
(P) Algo salió mal con los programas externos utilizados para "glob" y "<*.c>". Esto puede significar que su csh (C shell) está roto. Si es así, debe cambiar todas las variables relacionadas con csh en config.sh: Si tiene tcsh, haga que las variables se refieran a él como si fuera csh (por ejemplo, "full_csh='/usr/bin/tcsh'"); de lo contrario, hágales todas vacías (excepto que "d_csh" debe ser 'undef') para que Perl piense que csh no está presente. En cualquier caso, después de editar config.sh, ejecute "./Configure -S" y reconstruya Perl.
Invalid conversion in %s: "%s"
(W) Perl no entiende la conversión de formato dada. Consulte "sprintf" en perlfunc.
Invalid type in pack: '%s'
(F) El carácter dado no es un tipo de empaquetado válido. Consulte "pack" en perlfunc.
Invalid type in unpack: '%s'
(F) El carácter dado no es un tipo de desempaquetado válido. Consulte "unpack" en perlfunc.
Name "%s::%s" used only once: possible typo
(W) Los errores tipográficos a menudo se manifiestan como nombres de variables únicos. Si tenía una buena razón para tener un nombre único, simplemente menciónelo nuevamente de alguna manera para suprimir el mensaje (el pragmatismo "use vars" se proporciona precisamente para este propósito).
Null picture in formline
(F) El primer argumento de formline debe ser una especificación de patrón de formato válida. Se encontró vacío, lo que probablemente significa que le proporcionaste un valor no inicializado. Consulta perlform.
Offset fuera de cadena
(F) Intentaste realizar una operación de lectura/escritura/envío/recepción con un offset que apunta fuera del búfer. Esto es difícil de imaginar. La única excepción es que la lectura de sysread() más allá del búfer extenderá el búfer y rellenará con ceros el área nueva.
¡Memoria agotada!
(X|F) La función malloc() devolvió 0, lo que indica que no había suficiente memoria restante (o memoria virtual) para satisfacer la solicitud.

Se juzgó que la solicitud era pequeña, por lo que la posibilidad de atraparla depende de la forma en que se compiló Perl. Por defecto, no es atrapable. Sin embargo, si se compiló para esto, Perl puede usar el contenido de $^M como un grupo de emergencia después de realizar die() con este mensaje. En este caso, el error es atrapable *una vez*.

Memoria agotada durante la solicitud de %s
(F) La función malloc() devolvió 0, lo que indica que no había suficiente memoria restante (o memoria virtual) para satisfacer la solicitud. Sin embargo, se consideró que la solicitud era lo suficientemente grande (el valor predeterminado en tiempo de compilación es 64K), por lo que se concede la posibilidad de cerrarse atrapando este error.
pánico: frexp
(P) La función de biblioteca frexp() falló, haciendo imposible printf("%f").
Posible intento de poner comentarios en la lista qw()
(W) Las listas qw() contienen elementos separados por espacios en blanco; al igual que con las cadenas literales, los caracteres de comentario no se ignoran, sino que se tratan como datos literales. (Es posible que hayas usado delimitadores diferentes a los paréntesis que se muestran aquí; los corchetes también se usan con frecuencia).

Probablemente escribiste algo como esto:

@list = qw(
    a # un comentario
    b # otro comentario
);

cuando deberías haber escrito esto:

@list = qw(
    a
    b
);

Si realmente deseas comentarios, crea tu lista de la manera tradicional, con comillas y comas:

@list = (
    'a',    # un comentario
    'b',    # otro comentario
);
Posible intento de separar palabras con comas
(W) Las listas qw() contienen elementos separados por espacios en blanco; por lo tanto, no se necesitan comas para separar los elementos. (Es posible que hayas usado delimitadores diferentes a los paréntesis que se muestran aquí; los corchetes también se usan con frecuencia).

Probablemente escribiste algo como esto:

qw! a, b, c !;

lo que inserta comas literales en algunos de los elementos de la lista. Escríbelo sin comas si no quieres que aparezcan en tus datos:

qw! a b c !;
El valor escalar @%s{%s} se escribe mejor como $%s{%s}
(W) Has utilizado un corte de hash (indicado por @) para seleccionar un solo elemento de un hash. En general, es mejor solicitar un valor escalar (indicado por $). La diferencia es que $foo{&bar} se comporta siempre como un escalar, tanto al asignarle como al evaluar su argumento, mientras que @foo{&bar} se comporta como una lista al asignarle y proporciona un contexto de lista a su subíndice, lo que puede producir resultados extraños si esperas solo un subíndice.
Se encontró un stub al resolver el método `%s' sobrecargando `%s' en %s
(P) La resolución de sobrecarga en el árbol @ISA puede verse afectada por la importación de stubs. Los stubs nunca deben crearse implícitamente, pero las llamadas explícitas a "can" pueden afectar esto.
Demasiado tarde para la opción "-T"
(X) La línea #! (o su equivalente local) en un script de Perl contiene la opción -T, pero Perl no se invocó con -T en su lista de argumentos. Esto es un error porque, para cuando Perl descubre un -T en un script, es demasiado tarde para poner en estado de "taint" correctamente todo desde el entorno. Por lo tanto, Perl abandona.
Se intentó untie mientras todavía existen %d referencias internas
(W) Una copia del objeto devuelto por "tie" (o "tied") todavía era válida cuando se llamó a "untie".
Carácter no reconocido %s
(F) El analizador de Perl no tiene idea de qué hacer con el carácter especificado en tu script de Perl (o eval). Quizás intentaste ejecutar un script comprimido, un programa binario o un directorio como un programa de Perl.
Función no admitida fork
(F) Tu versión del ejecutable no admite "fork".

Ten en cuenta que en algunos sistemas, como OS/2, puede haber diferentes versiones de ejecutables de Perl, algunas de las cuales pueden admitir "fork", otras no. Intenta cambiar el nombre con el que llamas a Perl a "perl_", "perl__", y así sucesivamente.

El uso de "$$<dígito>" para significar "${$}<dígito>" está obsoleto
(D) Las versiones de Perl anteriores a la 5.004 malinterpretaban cualquier marcador de tipo seguido de "$" y un dígito. Por ejemplo, "$$0" se interpretaba incorrectamente como "${$}0" en lugar de "${$0}". Este error está (en su mayor parte) corregido en Perl 5.004.

Sin embargo, los desarrolladores de Perl 5.004 no pudieron corregir completamente este error, ya que al menos dos módulos ampliamente utilizados dependen del antiguo significado de "$$0" en una cadena. Por lo tanto, Perl 5.004 todavía interpreta "$$<dígito>" de la manera antigua (defectuosa) dentro de las cadenas; pero genera este mensaje como una advertencia. Y en Perl 5.005, este tratamiento especial cesará.

El valor de %s puede ser "0"; pruébalo con defined()
(W) En una expresión condicional, utilizaste , <*> (glob), each() o readdir() como valor booleano. Cada una de estas construcciones puede devolver un valor de "0"; eso haría que la expresión condicional fuera falsa, lo que probablemente no es lo que pretendías. Cuando uses estas construcciones en expresiones condicionales, prueba sus valores con el operador "defined".
La variable "%s" podría no estar disponible
(W) Una subrutina anónima interna (anidada) se encuentra dentro de una subrutina *con nombre*, y fuera de esta hay otra subrutina; y la subrutina anónima (la más interna) hace referencia a una variable léxica definida en la subrutina más externa. Por ejemplo: 
sub outermost { my $a; sub middle { sub { $a } } }

Si la subrutina anónima se llama o se hace referencia a ella (directa o indirectamente) desde la subrutina más externa, compartirá la variable como esperarías. Pero si la subrutina anónima se llama o se hace referencia a ella cuando la subrutina más externa no está activa, verá el valor de la variable compartida tal como estaba antes y durante la *primera* llamada a la subrutina más externa, lo que probablemente no es lo que deseas.

En estas circunstancias, generalmente es mejor hacer que la subrutina intermedia sea anónima, utilizando la sintaxis "sub {}". Perl tiene soporte específico para variables compartidas en subrutinas anónimas anidadas; una subrutina con nombre en medio interfiere con esta característica.

La variable "%s" no permanecerá compartida
(W) Una subrutina *con nombre* interna (anidada) hace referencia a una variable léxica definida en una subrutina externa.

Cuando se llame a la subrutina interna, probablemente verá el valor de la variable de la subrutina externa tal como estaba antes y durante la *primera* llamada a la subrutina externa; en este caso, después de que la primera llamada a la subrutina externa se complete, las subrutinas interna y externa ya no compartirán un valor común para la variable. En otras palabras, la variable ya no se compartirá.

Además, si la subrutina externa es anónima y hace referencia a una variable léxica fuera de sí misma, entonces las subrutinas externa e interna *nunca* compartirán la variable dada.

Este problema generalmente se puede resolver haciendo que la subrutina interna sea anónima, utilizando la sintaxis "sub {}". Cuando se llaman o se hace referencia a subs internas anónimas que hacen referencia a variables en subs externas, se vinculan automáticamente a los valores actuales de dichas variables.

Advertencia: algo va mal
(W) Pasaste a warn() una cadena vacía (el equivalente a "warn """) o la llamaste sin argumentos y $_ estaba vacío.
Nombre lógico mal formado |%s| en prime_env_iter
(W) Una advertencia peculiar de VMS. Se encontró un nombre lógico al prepararse para iterar sobre %ENV que viola las reglas sintácticas que rigen los nombres lógicos. Dado que no se puede traducir normalmente, se omite y no aparecerá en %ENV. Esto puede ser un suceso benigno, ya que algunos paquetes de software podrían modificar directamente las tablas de nombres lógicos e introducir nombres no estándar, o puede indicar que una tabla de nombres lógicos se ha corrompido.
Se recibió un error de DosAllocMem
(P) Un error peculiar de OS/2. Lo más probable es que estés utilizando una versión obsoleta de Perl, y esto no debería suceder de todos modos.
PERLLIB_PREFIX mal formado
(F) Un error peculiar de OS/2. PERLLIB_PREFIX debe tener el formato 
prefijo1;prefijo2

o

prefijo1 prefijo2

con prefijo1 y prefijo2 no vacíos. Si "prefijo1" es de hecho un prefijo de una ruta de búsqueda de biblioteca integrada, se sustituye prefijo2. El error puede aparecer si no se encuentran los componentes o si son demasiado largos. Consulta "PERLLIB_PREFIX" en README.os2.

PERL_SH_DIR demasiado largo
(F) Un error peculiar de OS/2. PERL_SH_DIR es el directorio donde encontrar el
"sh"-shell. Consulte "PERL_SH_DIR" en README.os2.
Proceso terminado por SIG%s
(W) Este es un mensaje estándar emitido por las aplicaciones OS/2, mientras que las aplicaciones *nix mueren en silencio. Se considera una característica del port de OS/2. Se puede deshabilitar fácilmente con sighandlers apropiados, consulte "Signals" en perlipc. Consulte también "Process terminated by SIGTERM/SIGINT" en README.os2.
