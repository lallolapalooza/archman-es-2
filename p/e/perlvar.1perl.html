NOMBRE

perlvar - Variables predefinidas de Perl

DESCRIPCIÓN

La Sintaxis de los Nombres de Variables

Los nombres de variables en Perl pueden tener varios formatos. Generalmente, deben comenzar con una letra o un guion bajo, en cuyo caso pueden tener una longitud arbitraria (hasta un límite interno de 251 caracteres) y pueden contener letras, dígitos, guiones bajos o la secuencia especial "::" o "'". En este caso, la parte anterior a la última "::" o "'" se toma como un calificador de paquete; ver perlmod. Una letra Unicode que no sea ASCII no se considera una letra a menos que "use utf8" esté en efecto, y se aplican reglas algo más complicadas; ver "Identifier parsing" en perldata para más detalles.

Los nombres de variables de Perl también pueden ser una secuencia de dígitos, un solo carácter de puntuación, o la secuencia de dos caracteres: "^" (acento circunflejo) seguido de cualquiera de los caracteres "[][A-Z^_?\]". Todos estos nombres están reservados para usos especiales por Perl; por ejemplo, los nombres compuestos únicamente por dígitos se utilizan para almacenar datos capturados por referencias posteriores después de una coincidencia de expresión regular.

Desde Perl v5.6.0, los nombres de variables de Perl también pueden ser cadenas alfanuméricas precedidas por un circunflejo. Todos estos deben escribirse utilizando la forma de variable delimitada con llaves, como "${^Foo}"; las llaves **no** son opcionales. "${^Foo}" denota la variable escalar cuyo nombre se considera un control-"F" seguido de dos "o". (Ver "Demarcated variable names using braces" en perldata para más información sobre esta forma de escribir el nombre de una variable o especificar el acceso a un elemento de un array o un hash). Estas variables están reservadas para usos especiales futuros por Perl, excepto las que comienzan con "^_" (circunflejo-guion bajo). Ningún nombre que comience con "^_" adquirirá un significado especial en ninguna versión futura de Perl; por lo tanto, dichos nombres pueden usarse de forma segura en programas. $^_, sin embargo, **está** reservado.

Tenga en cuenta que **debe** usar la forma delimitada para acceder a los subíndices de variables de este tipo al interpolar, por ejemplo, para acceder al primer elemento de la variable "@{^CAPTURE}" dentro de una cadena entre comillas dobles, escribiría "${^CAPTURE[0]}" y **NO** "${^CAPTURE}[0]", lo que significaría hacer referencia a una variable escalar llamada "${^CAPTURE}" y no al índice 0 del array mágico "@{^CAPTURE}" que es poblado por el motor de regex.

Los identificadores de Perl que comienzan con dígitos o caracteres de puntuación están exentos de los efectos de la declaración "package" y siempre se fuerzan al paquete "main"; también están exentos de errores de "strict 'vars'". Algunos otros nombres también están exentos de estas maneras:

ENV      STDIN
INC      STDOUT
ARGV     STDERR
ARGVOUT
SIG

En particular, las variables especiales "${^_XYZ}" siempre se consideran en el paquete "main", independientemente de cualquier declaración de "package" actualmente en ámbito.

VARIABLES ESPECIALES

Los siguientes nombres tienen un significado especial para Perl. La mayoría de los nombres de puntuación tienen mnemotécnicos razonables o análogos en los shells. Sin embargo, si desea utilizar nombres de variables largos, solo necesita decir:

use English;

al principio de su programa. Esto crea alias para todos los nombres cortos a los nombres largos en el paquete actual. Algunos incluso tienen nombres medianos, generalmente tomados de awk. Para más información, por favor consulte English.

Antes de continuar, tenga en cuenta el orden de clasificación de las variables. En general, primero enumeramos las variables en orden lexicográfico insensible a mayúsculas y minúsculas, casi (ignorando el "{" o "^" que precede a las palabras, como en "${^UNICODE}" o $^T), aunque $_ y @_ suben a la cima de la pila. Para variables con el mismo identificador, las listamos en orden de escalar, array, hash y bareword.

Variables Generales

$ARG
$_
El espacio predeterminado de entrada y búsqueda de patrones. Los siguientes pares son equivalentes: 
while (<>) {...}    # ¡equivalente solo en while!
while (defined($_ = <>)) {...}
/^Subject:/
$_ =~ /^Subject:/
tr/a-z/A-Z/
$_ =~ tr/a-z/A-Z/
chomp
chomp($_)

Estos son los lugares donde Perl asumirá $_ incluso si no lo usa:

  • Las siguientes funciones utilizan $_ como argumento predeterminado:

    abs, alarm, chomp, chop, chr, chroot, cos, defined, eval, evalbytes, exp, fc, glob, hex, int, lc, lcfirst, length, log, lstat, mkdir, oct, ord, pos, print, printf, quotemeta, readlink, readpipe, ref, require, reverse (solo en contexto escalar), rmdir, say, sin, split (para su segundo argumento), sqrt, stat, study, uc, ucfirst, unlink, unpack.

  • Todas las pruebas de archivo ("-f", "-d") excepto "-t", que por defecto es STDIN. Ver "-X" en perlfunc
  • Las operaciones de coincidencia de patrones "m//", "s///" y "tr///" (también conocido como "y///") cuando se usan sin un operador "=~".
  • La variable iteradora predeterminada en un bucle "foreach" si no se proporciona otra variable.
  • La variable iteradora implícita en las funciones grep() y map().
  • La variable implícita de given().
  • El lugar predeterminado para poner el siguiente valor o registro de entrada cuando el resultado de una operación "<FH>", "readline", "readdir" o "each" es probado por sí mismo como el único criterio de una prueba "while". Fuera de una prueba "while", esto no ocurrirá.

$_ es una variable global.

Sin embargo, entre perl v5.10.0 y v5.24.0, podía usarse léxicamente escribiendo "my $_". Hacer que $_ se refiera al $_ global en el mismo ámbito era entonces posible con "our $_". Esta característica experimental fue eliminada y ahora es un error fatal, pero puede encontrarla en código antiguo.

Mnemotécnico: el guion bajo se entiende en ciertas operaciones.

@ARG
@_
Dentro de una subrutina, el array @_ contiene los parámetros pasados a esa subrutina. Dentro de una subrutina, @_ es el array predeterminado para los operadores de array "pop" y "shift".

Ver perlsub.

$LIST_SEPARATOR
$"
Cuando un array o una rebanada de array se interpolan en una cadena entre comillas dobles o un contexto similar como "/.../", sus elementos se separan por este valor. El valor predeterminado es un espacio. Por ejemplo, esto: 
print "El array es: @array\n";

es equivalente a esto:

print "El array es: " . join($", @array) . "\n";

Mnemotécnico: funciona en contexto de comillas dobles.

$PROCESS_ID
$PID
$$
El número de proceso del Perl que está ejecutando esto
Aunque *puedes* configurar esta variable, generalmente no se recomienda, aunque puede ser invaluable para algunos propósitos de prueba. Se restablecerá automáticamente después de las llamadas a fork().

Nota para usuarios de Linux y Debian GNU/kFreeBSD: Antes de Perl v5.16.0, Perl emulaba la semántica POSIX en sistemas Linux utilizando LinuxThreads, una implementación parcial de POSIX Threads que desde entonces ha sido reemplazada por la Biblioteca de Hilos POSIX Nativos (NPTL).

LinuxThreads ahora es obsoleto en Linux, y el caché de getpid() de esta manera hacía que la incrustación de Perl fuera innecesariamente compleja (ya que tendrías que actualizar manualmente el valor de $$), por lo que ahora $$ y getppid() siempre devolverán los mismos valores que la biblioteca C subyacente.

Los sistemas Debian GNU/kFreeBSD también usaron LinuxThreads hasta e incluyendo la versión 6.0, pero después de eso se movieron a la semántica de hilos de FreeBSD, que son similares a POSIX.

Para ver si tu sistema se ve afectado por esta discrepancia, verifica si "getconf GNU_LIBPTHREAD_VERSION | grep -q NPTL" devuelve un valor falso. Los hilos NTPL preservan la semántica POSIX.

Mnemotécnica: igual que en los shells.

$PROGRAM_NAME
$0
Contiene el nombre del programa que se está ejecutando.

En algunos (pero no todos) sistemas operativos, asignar a $0 modifica el área de argumentos que ve el programa "ps". En algunas plataformas, es posible que debas usar opciones especiales de "ps" o un "ps" diferente para ver los cambios. Modificar $0 es más útil como una forma de indicar el estado actual del programa que para ocultar el programa que estás ejecutando.

Ten en cuenta que existen limitaciones específicas de la plataforma en la longitud máxima de $0. En el caso más extremo, puede limitarse al espacio ocupado por el $0 original.

En algunas plataformas, puede haber una cantidad arbitraria de relleno, por ejemplo, caracteres de espacio, después del nombre modificado tal como lo muestra "ps". En algunas plataformas, este relleno puede extenderse hasta la longitud original del área de argumentos, sin importar lo que hagas (este es el caso, por ejemplo, de Linux 2.2).

Nota para usuarios de BSD: configurar $0 no elimina completamente "perl" de la salida de ps(1). Por ejemplo, configurar $0 a "foobar" puede resultar en "perl: foobar (perl)" (si el prefijo "perl: " y el sufijo " (perl)" se muestran depende de tu variante y versión exacta de BSD). Esta es una característica del sistema operativo, Perl no puede hacer nada al respecto.

En scripts multihilo, Perl coordina los hilos para que cualquier hilo pueda modificar su copia de $0 y el cambio sea visible para ps(1) (asumiendo que el sistema operativo colabora). Ten en cuenta que la vista de $0 que tienen los otros hilos no cambiará, ya que tienen sus propias copias de él.

Si el programa se le ha dado a Perl a través de los modificadores "-e" o "-E", $0 contendrá la cadena "-e".

En Linux a partir de Perl v5.14.0, el nombre de proceso heredado se establecerá con prctl(2), además de alterar el nombre POSIX a través de "argv[0]" como Perl ha hecho desde la versión 4.000. Ahora las utilidades del sistema que leen el nombre de proceso heredado como ps, top y killall reconocerán el nombre que establezcas al asignar a $0. La cadena que proporciones se cortará a 16 bytes, esta es una limitación impuesta por Linux.

Los caracteres anchos son inválidos en los valores de $0. Por razones históricas, sin embargo, Perl los acepta y los codifica a UTF-8. Cuando esto sucede, se activa una advertencia de carácter ancho.

Mnemotécnica: igual que sh y ksh.

$REAL_GROUP_ID
$GID
$)
El gid real de este proceso. Si te encuentras en una máquina que admite la pertenencia a varios grupos simultáneamente, devuelve una lista de grupos separados por espacios a los que perteneces. El primer número es el que devuelve getgid(), y los siguientes los devuelve getgroups(), uno de los cuales puede ser el mismo que el primer número.

Sin embargo, un valor asignado a $() debe ser un solo número utilizado para establecer el gid real. Por lo tanto, el valor proporcionado por $() *no* debe asignarse de nuevo a $() sin ser forzado numéricamente, por ejemplo, sumando cero. Ten en cuenta que esto es diferente al gid efectivo ($)) que sí acepta una lista.

Puedes cambiar tanto el gid real como el gid efectivo al mismo tiempo utilizando POSIX::setgid(). Los cambios en $() requieren una comprobación de $! para detectar cualquier posible error después de un intento de cambio.

Mnemotécnica: los paréntesis se usan para *agrupar* cosas. El gid real es el grupo al que *te fuiste*, si estás ejecutando setgid.

$EFFECTIVE_GROUP_ID
$EGID
$)
El gid efectivo de este proceso. Si te encuentras en una máquina que admite la pertenencia a varios grupos simultáneamente, devuelve una lista de grupos separados por espacios a los que perteneces. El primer número es el que devuelve getegid(), y los siguientes los devuelve getgroups(), uno de los cuales puede ser el mismo que el primer número.

De manera similar, un valor asignado a $) también debe ser una lista de números separados por espacios. El primer número establece el gid efectivo, y el resto (si los hay) se pasan a setgroups(). Para obtener el efecto de una lista vacía para setgroups(), simplemente repite el nuevo gid efectivo; es decir, para forzar un gid efectivo de 5 y una lista efectivamente vacía de setgroups(), di " $) = "5 5" ".

Puedes cambiar tanto el gid efectivo como el gid real al mismo tiempo utilizando POSIX::setgid() (usa solo un argumento numérico). Los cambios en $) requieren una comprobación de $! para detectar cualquier posible error después de un intento de cambio.

$<, $>, $() y $) solo se pueden configurar en máquinas que admiten la rutina set[re][ug]id() correspondiente. $() y $) solo se pueden intercambiar en máquinas que admiten setregid().

Mnemotécnica: los paréntesis se usan para *agrupar* cosas. El gid efectivo es el grupo que es *correcto* para ti, si estás ejecutando setgid.

$REAL_USER_ID
$UID
$<
El uid real de este proceso. Puedes cambiar tanto el uid real como el uid efectivo al mismo tiempo utilizando POSIX::setuid(). Dado que los cambios en $< requieren una llamada al sistema, comprueba $! después de un intento de cambio para detectar cualquier posible error.

Mnemotécnica: es el uid del que *vienes*, si estás ejecutando setuid.

$EFFECTIVE_USER_ID
$EUID
$>
El uid efectivo de este proceso. Por ejemplo: 
$< = $>;            # establecer real a uid efectivo
($<,$>) = ($>,$<);  # intercambiar uids real y efectivo

Puedes cambiar tanto el uid efectivo como el uid real al mismo tiempo utilizando POSIX::setuid(). Los cambios en $> requieren una comprobación de $! para detectar cualquier posible error después de un intento de cambio.

$< y $> solo se pueden intercambiar en máquinas que admiten setreuid().

Mnemotécnica: es el uid al que *fuiste*, si estás ejecutando setuid.

$SUBSCRIPT_SEPARATOR
$SUBSEP
$;
El separador de subíndices para la emulación de matrices multidimensionales. Si haces referencia a un elemento de hash como 
$foo{$x,$y,$z}

realmente significa

$foo{join($;, $x, $y, $z)}

Pero no pongas

@foo{$x,$y,$z}     # un slice--nota el @

que significa

($foo{$x},$foo{$y},$foo{$z})

El valor predeterminado es "\034", igual que SUBSEP en awk. Si tus claves contienen datos binarios, es posible que no haya ningún valor seguro para $;.

Considera usar matrices multidimensionales "reales" como se describe en perllol.

Mnemotécnica: la coma (el separador de subíndices sintáctico) es un punto y coma.

$a
$b
Variables especiales del paquete cuando se usa sort(), ver "sort" en perlfunc. Debido a esta especialidad, $a y $b no necesitan ser declaradas (usando "use vars" o our()) incluso cuando se usa el pragmatismo "strict 'vars'". No las lexicalices con "my $a" o "my $b" si quieres poder usarlas en el bloque o función de comparación de sort().
%ENV
El hash %ENV contiene tu entorno actual. Establecer un valor en "ENV" cambia el entorno para cualquier proceso hijo que posteriormente crees con fork().

A partir de la versión 5.18.0, tanto las claves como los valores almacenados en %ENV se convierten en cadenas. 

my $foo = 1;
$ENV{'bar'} = \$foo;
if( ref $ENV{'bar'} ) {
    say "Comportamiento Pre 5.18.0";
} else {
    say "Comportamiento Post 5.18.0";
}

Anteriormente, solo los procesos hijos recibían valores convertidos a cadenas:

my $foo = 1;
$E
NV{'bar'} = \$foo; # Siempre imprime 'non ref' system($^X, '-e', q/print ( ref $ENV{'bar'} ? 'ref' : 'non ref' ) /);

Esto sucede porque realmente no se pueden compartir estructuras de datos arbitrarias con procesos externos.

$OLD_PERL_VERSION
$]
La revisión, versión y subversión del intérprete de Perl, representada como un número decimal de la forma 5.XXXYYY, donde XXX es la versión / 1e3 e YYY es la subversión / 1e6. Por ejemplo, Perl v5.10.1 sería "5.010001".

Esta variable se puede usar para determinar si el intérprete de Perl que ejecuta un script está en el rango correcto de versiones:

warn "No PerlIO!\n" if "$]" < 5.008;

Al comparar $], se deben usar operadores de comparación numéricos, pero la variable debe ser tratada como una cadena primero para evitar problemas donde su valor numérico original sea inexacto.

Ver también la documentación de "use VERSION" y "require VERSION" para una forma conveniente de fallar si el intérprete de Perl en ejecución es demasiado antiguo.

Ver "$^V" para una representación de la versión de Perl como un objeto de versión, que permite comparaciones de cadenas más flexibles.

La principal ventaja de $] sobre $^V es que funciona igual en cualquier versión de Perl. Las desventajas son que no se puede comparar fácilmente con versiones en otros formatos (por ejemplo, cadenas literales v, "v1.2.3" u objetos de versión) y las comparaciones numéricas están sujetas a la representación binaria de punto flotante; es bueno para verificaciones numéricas literales de versión y malo para comparar con una variable que no ha sido verificada.

La forma $OLD_PERL_VERSION se agregó en Perl v5.20.0 por razones históricas, pero su uso se desaconseja. (Si su razón para usar $] es ejecutar código en perls antiguos, entonces referirse a él como $OLD_PERL_VERSION sería contraproducente).

Mnemotecnia: ¿Está esta versión de perl en el corchete correcto?

$SYSTEM_FD_MAX
$^F
El descriptor de archivo del sistema máximo, normalmente 2. Los descriptores de archivo del sistema se pasan a los procesos ejecutados con exec(), mientras que los descriptores de archivo superiores no. Además, durante un open(), los descriptores de archivo del sistema se conservan incluso si el open() falla (los descriptores de archivo ordinarios se cierran antes de que se intente el open()). El estado de cierre al ejecutar de un descriptor de archivo se decidirá de acuerdo con el valor de $^F cuando se abrió el archivo, pipe o socket correspondiente, no en el momento del exec().
@F
El array @F contiene los campos de cada línea leída cuando el modo de división automática está activado. Ver perlrun para el interruptor -a. Este array es específico del paquete y debe declararse o tener un nombre de paquete completo si no está en el paquete principal cuando se ejecuta bajo "strict 'vars'".
@INC
El array @INC contiene la lista de lugares donde las construcciones "do EXPR", "require" o "use" buscan sus archivos de biblioteca. Inicialmente consta de los argumentos de cualquier interruptor de línea de comandos -I, seguidos de la biblioteca Perl predeterminada, probablemente /usr/local/lib/perl. Antes de Perl 5.26, "." -que representa el directorio actual, se incluía en @INC; ha sido eliminado. Este cambio en el comportamiento se documenta en "PERL_USE_UNSAFE_INC" y no se recomienda que "." se vuelva a agregar a @INC. Si necesita modificar @INC en tiempo de ejecución, debe usar el pragma "use lib" para cargar correctamente la biblioteca dependiente de la máquina también: 
use lib '/mypath/libdir/';
use SomeMod;

También puede insertar ganchos en el sistema de inclusión de archivos colocando código Perl directamente en @INC. Esos ganchos pueden ser referencias a subrutinas, referencias a arrays u objetos bendecidos. Ver "require" in perlfunc para más detalles.

%INC
El hash %INC contiene entradas para cada nombre de archivo incluido a través de los operadores "do", "require" o "use". La clave es el nombre del archivo que especificó (con los nombres de módulo convertidos a rutas) y el valor es la ubicación del archivo encontrado. El operador "require" utiliza este hash para determinar si un archivo en particular ya ha sido incluido.

Si el archivo se cargó a través de un gancho (por ejemplo, una referencia a subrutina, ver "require" in perlfunc para una descripción de estos ganchos), este gancho se inserta por defecto en %INC en lugar de un nombre de archivo. Tenga en cuenta, sin embargo, que el gancho puede haber establecido la entrada %INC por sí mismo para proporcionar información más específica.

$INC
A partir de la versión 5.37.7, cuando se ejecuta un gancho @INC, el índice del array @INC que contiene el gancho se localizará en la variable $INC. Cuando el gancho devuelva el sucesor entero de su valor, se utilizará para determinar el siguiente índice en @INC que se comprobará, por lo tanto, si se establece en -1 (o "undef"), el recorrido por el array @INC se reiniciará desde su principio.

Normalmente, el recorrido por el array @INC es de principio a fin ("0 .. $#INC"), y si el array @INC es modificado por el gancho, el iterador puede quedar en un estado donde las entradas recién agregadas se omitan. Cambiar este valor permite que un gancho @INC reescriba el array @INC y le diga a Perl dónde continuar después. Ver "require" in perlfunc para detalles sobre ganchos @INC.

$INPLACE_EDIT
$^I
El valor actual de la extensión de edición in situ. Use "undef" para deshabilitar la edición in situ.

Mnemotecnia: valor del interruptor -i.

@ISA
Cada paquete contiene un array especial llamado @ISA que contiene una lista de las clases padre de ese paquete, si las hay. Este array es simplemente una lista de escalares, cada uno de los cuales es una cadena que corresponde a un nombre de paquete. El array se examina cuando Perl realiza la resolución de métodos, lo que se cubre en perlobj.

Para cargar paquetes mientras se agregan a @ISA, ver el pragma parent. El pragma base desaconsejado hace esto también, pero no debe usarse excepto cuando se requiere compatibilidad con el pragma fields desaconsejado.

$^M
Por defecto, quedarse sin memoria es un error fatal e intratable. Sin embargo, si se compila adecuadamente, Perl puede usar el contenido de $^M como una reserva de memoria de emergencia después de una llamada a die(). Supongamos que su Perl se compila con "-DPERL_EMERGENCY_SBRK" y utiliza el malloc de Perl. Entonces 
$^M = 'a' x (1 << 16);

asignaría un búfer de 64K para usar en una emergencia. Ver el archivo INSTALL en la distribución de Perl para obtener información sobre cómo agregar indicadores de compilación C personalizados al compilar perl. Para desalentar el uso casual de esta característica avanzada, no hay un nombre largo en inglés para esta variable.

Esta variable se agregó en Perl 5.004.

${^MAX_NESTED_EVAL_BEGIN_BLOCKS}
Esta variable determina el número máximo de anidamientos de bloques "eval EXPR"/"BEGIN" o "require"/"BEGIN" que está permitido. Esto significa que también controla el anidamiento máximo de las declaraciones "use".

El valor predeterminado de 1000 debería ser suficientemente grande para fines de trabajo normales, y si debe aumentarlo, debe ser conservador con su elección o puede encontrar fallos de segmentación por agotamiento de la pila C. Parece poco probable que el código real tenga una profundidad de uso superior a 1000, pero lo hemos dejado configurable por si acaso.

Cuando se establece en 0, los bloques "BEGIN" dentro de "eval EXPR" o "require EXPR" están completamente prohibidos y activarán una excepción que terminará la compilación y, en el caso de "require", lanzará una excepción, o en el caso de "eval", devolverá el error en $@ como de costumbre.

Considere el código

perl -le'sub f { eval "BEGIN { f() }"; } f()'

cada invocación de f() consumirá una pila C considerable, y esta variable se utiliza para hacer que código como este falle en lugar de agotar la pila C y provocar un fallo de segmentación. Huelga decir que código como este es inusual, es poco probable que necesite aumentar la configuración. Sin embargo, puede ser útil establecerlo en 0 durante un período limitado para evitar que los bloques BEGIN{} se ejecuten durante un "eval EXPR".

Tenga en cuenta que establecer esto en 1 NO afectaría al código como este:

BEGIN { $n += 1; BEGIN { $n += 2; BEGIN { $n += 4 } } }

La razón es que los bloques BEGIN se ejecutan inmediatamente después de que se completan, por lo tanto, el más interno se ejecutará antes de que los que lo contienen hayan terminado de compilar, y la profundidad no superará 1. De hecho, el código anterior es equivalente a

BEGIN { $n+=4 }
BEGIN { $n+=2 }
BEGIN { $n+=1 }

lo que hace obvio por qué un ${^MAX_EVAL_BEGIN_DEPTH} de 1 no bloquearía este código.

Solo los "BEGIN" ejecutados dentro de un "eval" o "require" (posiblemente a través de "use") se ven afectados.

$OSNAME
$^O
El nombre del sistema operativo bajo el cual se compiló esta copia de Perl, tal como se determinóned durante el proceso de configuración. Para ver ejemplos, consulte "PLATFORMS" en perlport.

El valor es idéntico a $Config{'osname'}. Consulte también Config y el interruptor de línea de comandos -V documentado en perlrun.

En las plataformas Windows, $^O no es muy útil: dado que siempre es "MSWin32", no distingue entre 95/98/ME/NT/2000/XP/CE/.NET. Utilice Win32::GetOSName() o Win32::GetOSVersion() (consulte Win32 y perlport) para distinguir entre las variantes.

Esta variable se añadió en Perl 5.003.

%SIG
El hash %SIG contiene manejadores de señales para señales. Por ejemplo: 
sub handler {   # El primer argumento es el nombre de la señal
    my($sig) = @_;
    print "Atrapada una SIG$sig -- cerrando\n";
    close(LOG);
    exit(0);
}
$SIG{'INT'}  = \&handler;
$SIG{'QUIT'} = \&handler;
...
$SIG{'INT'}  = 'DEFAULT';   # Restaura la acción predeterminada
$SIG{'QUIT'} = 'IGNORE';    # Ignora SIGQUIT

Usar un valor de 'IGNORE' generalmente tiene el efecto de ignorar la señal, excepto para la señal "CHLD". Consulte perlipc para obtener más información sobre este caso especial. Usar una cadena vacía o "undef" como valor tiene el mismo efecto que 'DEFAULT'.

Aquí hay otros ejemplos:

$SIG{"PIPE"} = "Plumber";   # asume main::Plumber (no
                            # recomendado)
$SIG{"PIPE"} = \&Plumber;   # está bien; asume el Plumber
                            # actual
$SIG{"PIPE"} = *Plumber;    # algo esotérico
$SIG{"PIPE"} = Plumber();   # ¡ups!, ¿qué devolvió Plumber()?

Asegúrese de no usar una palabra clave desnuda como nombre de un manejador de señales, para no llamarla inadvertidamente.

Usar una cadena que no corresponde a ninguna función existente o un glob que no contiene una ranura de código es equivalente a 'IGNORE', pero se emite una advertencia cuando se llama al manejador (la advertencia no se emite para los ganchos internos descritos a continuación).

Si su sistema tiene la función sigaction(), los manejadores de señales se instalan utilizándola. Esto significa que obtiene un manejo de señales confiable.

La política de entrega predeterminada de señales cambió en Perl v5.8.0 de inmediata (también conocida como "insegura") a diferida, también conocida como "señales seguras". Consulte perlipc para obtener más información.

Ciertos ganchos internos también se pueden configurar usando el hash %SIG. La rutina indicada por $SIG{__WARN__} se llama cuando un mensaje de advertencia está a punto de imprimirse. El mensaje de advertencia se pasa como primer argumento. La presencia de un gancho "__WARN__" hace que la impresión ordinaria de advertencias en "STDERR" se suprima. Puede usar esto para guardar advertencias en una variable, o convertir advertencias en errores fatales, así:

local $SIG{__WARN__} = sub { die $_[0] };
eval $proggie;

Dado que el gancho 'IGNORE' no es compatible con "__WARN__", su efecto es el mismo que usar 'DEFAULT'. Puede deshabilitar las advertencias usando la subrutina vacía:

local $SIG{__WARN__} = sub {};

La rutina indicada por $SIG{__DIE__} se llama cuando una excepción fatal está a punto de ser lanzada. El mensaje de error se pasa como primer argumento. Cuando una rutina de gancho "__DIE__" regresa, el procesamiento de la excepción continúa como lo habría hecho en ausencia del gancho, a menos que la rutina de gancho en sí misma lance una excepción. El manejador "__DIE__" se deshabilita explícitamente durante la llamada, para que pueda morir desde un manejador "__DIE__". De manera similar para "__WARN__".

El gancho $SIG{__DIE__} se llama incluso dentro de un eval(). Nunca fue la intención que sucediera de esta manera, pero un error de implementación lo hizo posible. Esto solía estar obsoleto, ya que permitía acciones extrañas a distancia como reescribir una excepción pendiente en $@. Los planes para rectificar esto se han descartado, ya que los usuarios descubrieron que reescribir una excepción pendiente es en realidad una característica útil, y no un error.

El gancho $SIG{__DIE__} no admite 'IGNORE'; tiene el mismo efecto que 'DEFAULT'.

Los manejadores "__DIE__"/"__WARN__" son muy especiales en un aspecto: pueden ser llamados para informar errores (probables) encontrados por el analizador. En tal caso, el analizador puede estar en un estado inconsistente, por lo que cualquier intento de evaluar código Perl desde dicho manejador probablemente resultará en un error de segmentación. Esto significa que las advertencias o errores que resultan del análisis de Perl deben usarse con extrema precaución, así:

require Carp if defined $^S;
Carp::confess("Algo va mal") if defined &Carp::confess;
die "Algo va mal, pero no se pudo cargar Carp para dar "
  . "rastreo de pila...\n\t"
  . "Para ver el rastreo de pila, intente iniciar Perl con el interruptor -MCarp";

Aquí la primera línea cargará "Carp" *a menos que* sea el analizador quien llamó al manejador. La segunda línea imprimirá el rastreo de pila y morirá si "Carp" estaba disponible. La tercera línea solo se ejecutará si "Carp" no estaba disponible.

Tener que pensar siquiera en la variable $^S en sus manejadores de excepciones está simplemente mal. $SIG{__DIE__} tal como está implementado actualmente invita a errores graves y difíciles de rastrear. Evítelo y use un "END{}" o una anulación de CORE::GLOBAL::die en su lugar.

Consulte "die" en perlfunc, "warn" en perlfunc, "eval" en perlfunc y warnings para obtener información adicional.

%{^HOOK}
Este hash contiene referencias de código que se llaman cuando se invocan varias palabras clave de perl que son difíciles o imposibles de envolver. Las claves de este hash se nombran según la palabra clave que se está enganchando, seguida de dos guiones bajos y luego un término de fase; ya sea "before" o "after".

Perl generará un error si intenta modificar una clave que no esté documentada como existente, o si intenta almacenar algo que no sea una referencia de código o undef en el hash. Si desea usar un objeto para implementar un gancho, puede usar currificación para incrustar el objeto en una referencia de código anónima.

Actualmente, solo hay una palabra clave que se puede enganchar, "require", pero se espera que en futuras versiones haya palabras clave adicionales con soporte de ganchos.

require__before
La rutina indicada por "${^HOOK}{require__before}" es llamada por "require" *antes* de verificar %INC, buscar en @INC, llamar a los ganchos INC o compilar código. Se llama con un solo argumento, el nombre del archivo para el elemento que se está requiriendo (los nombres de paquete se convierten en rutas). Puede alterar este nombre de archivo para cambiar qué archivo se carga. Si el gancho muere durante la ejecución, bloqueará la ejecución del require.

Para facilitar la realización de una acción con estado compartido tanto antes como después de que se ejecute la palabra clave require, el gancho "require__before" puede devolver una referencia de código de "post-acción" que a su vez se ejecutará cuando se complete el "require". Esta referencia de código se ejecutará independientemente de si el require se completó con éxito o lanzó una excepción. Se llamará con el nombre del archivo que se requirió. Puede verificar %INC para determinar si el require fue exitoso. Cualquier otro valor devuelto por el gancho "require__before" será ignorado silenciosamente.

Los ganchos "require__before" se llaman en orden FIFO, y si el gancho devuelve una referencia de código, esas referencias de código se llamarán en orden FILO. En otras palabras, si A requiere B requiere C, entonces "require__before" se llamará primero para A, luego para B y luego para C, y la referencia de código de post-acción se ejecutará primero para C, luego para B y finalmente para A.

El código bien escrito debería asegurarse de que, al configurar un gancho "require__before", se llame a cualquier gancho instalado previamente y que su valor de retorno, si es una referencia de código, también se llame. Consulte "require" en perlfunc para ver un ejemplo de implementación.

require__after
La rutina indicada por "${^HOOK}{require__after}" es llamada por "require" *después* de que el require se complete. Se llama con un solo argumento, el nombre del archivo para el elemento que se está requiriendo (los nombres de paquete se convierten en rutas). Se ejecuta cuando el "require" se completa, ya sea a través de una excepción o de la finalización de la declaración require, y puede verificar %INC para determinar si el require fue exitoso.

El gancho "require__after" se llama para cada archivo requerido en orden FILO. En otras palabras, si A requiere B requiere C, entonces "require__after" se llamará primero para C, luego para B y luego para A.

El nombre utilizado para ejecutar la copia actual de Perl, desde el "argv[0]" de C o (donde sea compatible) /proc/self/exe.

Dependiendo del sistema operativo anfitrión, el valor de $^X puede ser una ruta relativa o absoluta del archivo del programa Perl, o puede ser la cadena utilizada para invocar Perl pero no la ruta del archivo del programa Perl. Además, la mayoría de los sistemas operativos permiten invocar programas que no están en la variable de entorno PATH, por lo que no hay garantía de que el valor de $^X esté en PATH. Para VMS, el valor puede o no incluir un número de versión.

@first_run = `$^X -le "print int rand 100 for 1..100"`;

Pero recuerde que no todos los sistemas operativos admiten la creación de procesos hijos (forking) o la captura de la salida de los comandos, por lo que esta declaración compleja puede no ser portable.

No es seguro usar el valor de $^X como nombre de ruta de un archivo, ya que algunos sistemas operativos que tienen un sufijo obligatorio en los archivos ejecutables no requieren el uso del sufijo al invocar un comando. Para convertir el valor de $^X a un nombre de ruta, use las siguientes declaraciones:

# Construir un conjunto de nombres de archivo (no nombres de comando).
use Config;
my $this_perl = $^X;
if ($^O ne 'VMS') {
    $this_perl .= $Config{_exe}
    unless $this_perl =~ m/$Config{_exe}$/i;
}

Debido a que muchos sistemas operativos permiten que cualquier persona con acceso de lectura al archivo del programa Perl haga una copia de él, parchear la copia y luego ejecutar la copia, el programador de Perl consciente de la seguridad debe tener cuidado de invocar la copia instalada de Perl, no la copia a la que se hace referencia en $^X. Las siguientes declaraciones logran este objetivo y producen un nombre de ruta que se puede invocar como comando o referenciar como archivo.

use Config;
my $secure_perl_path = $Config{perlpath};
if ($^O ne 'VMS') {
    $secure_perl_path .= $Config{_exe}
    unless $secure_perl_path =~ m/$Config{_exe}$/i;
}

Variables relacionadas con expresiones regulares

La mayoría de las variables especiales relacionadas con expresiones regulares son efectos secundarios. Perl establece estas variables cuando ha completado una coincidencia con éxito, por lo que debe verificar el resultado de la coincidencia antes de usarlas. Por ejemplo:

if( /P(A)TT(ER)N/ ) {
    print "I found $1 and $2\n";
}

Estas variables son de solo lectura y se comportan de manera similar a una variable de ámbito dinámico, con algunas excepciones que se documentan explícitamente como que se comportan de manera diferente. Consulte la siguiente sección para obtener más detalles.

Reglas de ámbito de variables de expresiones regulares

Las variables de expresiones regulares permiten al programador acceder al estado de la coincidencia de expresiones regulares *exitosa* más reciente en el ámbito dinámico actual.

Las variables en sí son globales y sin ámbito, pero los datos a los que acceden tienen un ámbito similar al de las variables de ámbito dinámico, en el sentido de que cada coincidencia exitosa se comporta como si localizara un objeto de estado global en el ámbito de bloque o archivo actual. (Consulte "Sentencias Compuestas" en perlsyn para obtener más detalles sobre el ámbito dinámico y la palabra clave "local").

Una *coincidencia exitosa* incluye cualquier coincidencia exitosa realizada por el operador de búsqueda y reemplazo "s///" así como las realizadas por el operador "m//".

Considere el siguiente código:

my @state;
sub matchit {
    push @state, $1;            # empuja "baz"
    my $str = shift;
    $str =~ /(zat)/;            # coincide "zat"
    push @state, $1;            # empuja "zat"
}
{
    $str = "foo bar baz blorp zat";
    $str =~ /(foo)/;            # coincide "foo"
    push @state, $1;            # empuja "foo"
    {
        $str =~ /(pizza)/;      # NO coincide
        push @state, $1;        # empuja "foo"
        $str =~ /(bar)/;        # coincide "bar"
        push @state, $1;        # empuja "bar"
        $str =~ /(baz)/;        # coincide "baz"
        matchit($str);          # ver arriba
        push @state, $1;        # empuja "baz"
    }
    $str =~ s/noodles/rice/;    # NO coincide
    push @state, $1;            # empuja "foo"
    $str =~ s/(blorp)/zwoop/;   # coincide "blorp"
    push @state, $1;            # empuja "blorp"
}
# lo siguiente imprime "foo, foo, bar, baz, zat, baz, foo, blorp"
print join ",", @state;

Observe que cada coincidencia exitosa en el mismo ámbito exacto anula el contexto de coincidencia de la coincidencia exitosa anterior, pero que las coincidencias fallidas no lo hacen. Tenga en cuenta también que en un ámbito anidado interno, el estado anterior de un ámbito dinámico externo persiste hasta que ha sido anulado por otra coincidencia exitosa, pero que al salir del ámbito anidado interno, el contexto de coincidencia que estaba en efecto antes de la coincidencia exitosa interna se restaura cuando concluye el ámbito.

Es un problema conocido que "goto LABEL" puede interactuar mal con el contexto de coincidencia de ámbito dinámico. Esto puede no tener solución y se considera una de las muchas buenas razones para evitar "goto LABEL".

Problemas de rendimiento

Tradicionalmente en Perl, cualquier uso de alguna de las tres variables "$`", $& o "$'" (o sus equivalentes de "use English") en cualquier parte del código, causaba que todas las coincidencias de patrones exitosas posteriores hicieran una copia de la cadena coincidente, en caso de que el código pudiera acceder posteriormente a una de esas variables. Esto imponía una penalización de rendimiento considerable en todo el programa, por lo que generalmente se ha desaconsejado el uso de estas variables.

En Perl 5.6.0 se introdujeron los arrays dinámicos "@-" y "@+" que proporcionan los índices de las coincidencias exitosas. Así, por ejemplo, podría hacer esto:

$str =~ /pattern/;
print $`, $&, $'; # malo: penalización de rendimiento
print             # bueno: sin penalización de rendimiento
substr($str, 0,     $-[0]),
substr($str, $-[0], $+[0]-$-[0]),
substr($str, $+[0]);

En Perl 5.10.0 se introdujeron el flag del operador de coincidencia "/p" y las variables "${^PREMATCH}", "${^MATCH}" y "${^POSTMATCH}", que le permitían sufrir las penalizaciones solo en patrones marcados con "/p".

A partir de Perl 5.18.0, Perl comenzó a notar la presencia de cada una de las tres variables por separado y solo copiaba la parte de la cadena requerida; así que en

$`; $&; "abcdefgh" =~ /d/

Perl solo copiaría la parte "abcd" de la cadena. Eso podría marcar una gran diferencia en algo como

$str = 'x' x 1_000_000;
$&; # ups
$str =~ /x/g # un carácter copiado un millón de veces, no un millón de caracteres

En Perl 5.20.0, un nuevo sistema de copia en escritura se habilitó por defecto, lo que finalmente soluciona la mayoría de los problemas de rendimiento con estas tres variables, y las hace seguras para usar en cualquier lugar.

Los módulos "Devel::NYTProf" y "Devel::FindAmpersand" pueden ayudarle a encontrar usos de estas variables de coincidencia problemáticas en su código.

Tenga en cuenta que hay una distinción entre un búfer de captura que coincide con la cadena vacía y un búfer de captura que es opcional. Por ejemplo, "(x?)" y "(x)?". El último puede ser undef, el primero no.

Variables de error

Las variables $@, $!, $^E y $? contienen información sobre diferentes tipos de condiciones de error que pueden aparecer durante la ejecución de un programa Perl. Las variables se muestran ordenadas por la "distancia" entre el subsistema que informó el error y el proceso Perl. Corresponden a errores detectados por el intérprete de Perl, la biblioteca C, el sistema operativo o un programa externo, respectivamente.

Para ilustrar las diferencias entre estas variables, considere la siguiente expresión de Perl, que utiliza una cadena de comillas simples. Después de la ejecución de esta instrucción, perl puede haber establecido las cuatro variables de error especiales:

eval q{
    open my $pipe, "/cdrom/install |" or die $!;
    my @res = <$pipe>;
    close $pipe or die "bad pipe: $?, $!";
};

Cuando perl ejecuta la expresión eval(), traduce las llamadas open(), "<PIPE>" y "close" a la biblioteca de tiempo de ejecución C y, a partir de ahí, al kernel del sistema operativo. perl establece $! en el "errno" de la biblioteca C si alguna de estas llamadas falla.

$@ se establece si la cadena a ser "eval"uada no compiló (esto puede suceder si "open" o "close" se importaron con prototipos incorrectos), o si el código de Perl ejecutado durante la evaluación murió (die()d). En estos casos, el valor de $@ es el error de compilación, o el argumento de "die" (que interpolará $! y $?). (Ver también Fatal, sin embargo).

En algunos sistemas operativos, $^E puede contener un indicador de error más detallado, como en este caso, "Bandeja de CD-ROM no cerrada". Los sistemas que no admiten mensajes de error extendidos dejan $^E igual que $!.

Finalmente, $? puede establecerse en un valor distinto de 0 si el programa externo /cdrom/install falla. Los ocho bits superiores reflejan condiciones de error específicas encontradas por el programa (el valor de salida del programa exit()). Los ocho bits inferiores reflejan el modo de fallo, como la muerte por señal e información de volcado central. Ver wait(2) para más detalles. A diferencia de $! y $^E, que solo se establecen si se detecta una condición de error, la variable $? se establece en cada "wait" o "close" de tubería, sobrescribiendo el valor anterior. Esto se parece más a $@, que en cada eval() siempre se establece en caso de fallo y se borra en caso de éxito.

Para más detalles, ver las descripciones individuales en $@, $!, $^E y $?.

$!
Cuando se referencia, $! recupera el valor actual de la variable entera C "errno". Si $! se le asigna un valor numérico, ese valor se almacena en "errno". Cuando se referencia como una cadena, $! produce la cadena de error del sistema correspondiente a "errno".

Muchas llamadas al sistema o a la biblioteca establecen "errno" si fallan, para indicar la causa del fallo. Por lo general, no establecen "errno" a cero si tienen éxito y pueden establecer "errno" a un valor distinto de cero en caso de éxito. Esto significa que "errno", por lo tanto $!, solo tiene sentido *inmediatamente* después de un **fallo**:

if (open my $fh, "<", $filename) {
    # Aquí $! no tiene sentido.
    ...
}
else {
    # SÓLO aquí $! tiene sentido.
    ...
    # Ya aquí $! podría no tener sentido.
}

$^E
Información de error específica del sistema operativo actual. Por el momento, esto difiere de "$!" solo bajo VMS, OS/2 y Win32 (y para MacPerl). En todas las demás plataformas, $^E es siempre igual que $!.

Bajo VMS, $^E proporciona el valor de estado de VMS del último error del sistema. Esta es información más específica sobre el último error del sistema que la proporcionada por $!. Esto es particularmente importante cuando $! se establece en EVMSERR.

Bajo OS/2, $^E se establece en el código de error de la última llamada a la API de OS/2, ya sea a través de CRT o directamente desde perl.

Bajo Win32, $^E siempre devuelve la última información de error notificada por la llamada de Win32 GetLastError() que describe el último error desde la API de Win32. La mayoría del código específico de Win32 informará errores a través de $^E. Las llamadas ANSI C y similares a Unix establecen "errno" y, por lo tanto, la mayoría del código Perl portable informará errores a través de $!.

Las advertencias mencionadas en la descripción de "$!" generalmente también se aplican a $^E.

$?
El código de salida del último proceso de shell ejecutado por el sistema mediante el operador system, o por un comando de tubería o captura. Cuando se hace referencia a $? como un entero, su valor es el valor de retorno del comando wait(). Si el proceso terminó debido a una señal, entonces los 8 bits superiores son cero y los 8 bits inferiores son el número de señal. Si el proceso terminó normalmente, entonces los 8 bits inferiores son cero y los 8 bits superiores son el valor de salida del proceso. Cuando se hace referencia a $? como una cadena, el valor es una descripción de la terminación, que puede incluir el nombre de la señal y el código de salida.

Mnemotecnia: signo de interrogación para el resultado.

$!
El último error del sistema, o el último error de conexión de red.

En muchas situaciones, solo tiene sentido consultar $! inmediatamente después de una operación que pueda fallar. El valor de $! puede ser modificado por llamadas internas de Perl, así como por las llamadas al sistema subyacentes.

Aquí, sin sentido significa que $! puede no estar relacionado con el resultado del operador open().

    my $filename = "nonexistent_file";
    open my $fh, '<', $filename
        or die "Could not open $filename: $!";
    # $! might be garbage here, or might coincidentally contain the correct error.
    # The point is: don't rely on it if you didn't just examine it.

La asignación a $! es igualmente efímera. Puede usarse inmediatamente antes de invocar el operador die(), para establecer el valor de salida, o para inspeccionar la cadena de error del sistema correspondiente al error n, o para restaurar $! a un estado significativo.

Perl en sí mismo puede establecer "errno" a un valor distinto de cero en caso de fallo, incluso si no se realiza ninguna llamada al sistema.

Cada elemento de "%!" tiene un valor verdadero solo si $! está establecido a ese valor. Por ejemplo, $!{ENOENT} es verdadero si y solo si el valor actual de $! es "ENOENT"; es decir, si el error más reciente fue "No existe tal archivo o directorio" (o su equivalente moral: no todos los sistemas operativos dan ese error exacto, y ciertamente no todos los lenguajes). El valor verdadero específico no está garantizado, pero en el pasado generalmente ha sido el valor numérico de $!. Para verificar si una clave particular es significativa en su sistema, use "exists $!{la_clave}"; para obtener una lista de claves legales, use "keys %!". Consulte Errno para obtener más información, y también vea "$!".

$?
El estado devuelto por el último cierre de tubería, comando entre comillas invertidas (``), llamada exitosa a wait() o waitpid(), o del operador system(). Esta es solo la palabra de estado de 16 bits devuelta por la llamada tradicional al sistema Unix wait() (o está hecha para parecerse a ella). Por lo tanto, el valor de salida del subproceso es realmente ($? >> 8), y "$? & 127" da la señal, si la hay, por la que murió el proceso, y "$? & 128" informa si hubo un volcado de núcleo.

Adicionalmente, si la variable "h_errno" es compatible en C, su valor se devuelve a través de $? si alguna función "gethost*()" falla.

Si ha instalado un manejador de señales para "SIGCHLD", el valor de $? generalmente será incorrecto fuera de ese manejador.

Dentro de una subrutina "END" $? contiene el valor que se le dará a exit(). Puede modificar $? en una subrutina "END" para cambiar el estado de salida de su programa. Por ejemplo:

END {
    $? = 1 if $? == 255;  # die lo haría 255
}

En VMS, el pragma "use vmsish 'status'" hace que $? refleje el estado de salida real de VMS, en lugar de la emulación predeterminada del estado POSIX; vea "$?" en perlvms para más detalles.

Regla mnemotécnica: similar a sh y ksh.

${^GLOBAL_PHASE}
La fase actual del intérprete de perl.

Los valores posibles son:

CONSTRUCT
Se está construyendo el "PerlInterpreter*" a través de "perl_construct". Este valor está principalmente ahí por completitud y para su uso a través de la variable C subyacente "PL_phase". En realidad no es posible que se ejecute código Perl a menos que la construcción del intérprete haya finalizado.
START
Este es el tiempo de compilación global. Eso incluye, básicamente, cada bloque "BEGIN" ejecutado directa o indirectamente desde el tiempo de compilación del programa principal.

Esta fase no se llama "BEGIN" para evitar confusión con los bloques "BEGIN", ya que estos se ejecutan durante el tiempo de compilación de cualquier unidad de compilación, no solo del programa principal. Un tiempo de compilación nuevo y localizado al que se accede en tiempo de ejecución, por ejemplo, a través de construcciones como "eval "use SomeModule"", no son fases globales del intérprete y, por lo tanto, no se reflejan en "${^GLOBAL_PHASE}".

CHECK
Ejecución de cualquier bloque "CHECK".
INIT
Similar a "CHECK", pero para bloques "INIT", no para bloques "CHECK".
RUN
El tiempo de ejecución principal, es decir, la ejecución de "PL_main_root".
END
Ejecución de cualquier bloque "END".
DESTRUCT
Destrucción global.

Además, tenga en cuenta que no hay valor para los bloques UNITCHECK. Eso se debe a que se ejecutan para cada unidad de compilación individualmente y, por lo tanto, no es una fase global del intérprete.

No todos los programas tienen que pasar por cada una de las fases posibles, pero la transición de una fase a otra solo puede ocurrir en el orden descrito en la lista anterior.

Un ejemplo de todas las fases que el código Perl puede ver:

BEGIN { print "tiempo de compilación: ${^GLOBAL_PHASE}\n" }
INIT  { print "tiempo de inicialización: ${^GLOBAL_PHASE}\n" }
CHECK { print "tiempo de verificación: ${^GLOBAL_PHASE}\n" }
{
    package Print::Phase;
    sub new {
        my ($class, $time) = @_;
        return bless \$time, $class;
    }
    sub DESTROY {
        my $self = shift;
        print "$$self: ${^GLOBAL_PHASE}\n";
    }
}
print "tiempo de ejecución: ${^GLOBAL_PHASE}\n";
my $runtime = Print::Phase->new(
    "las variables léxicas se recolectan antes de END"
);
END   { print "tiempo final: ${^GLOBAL_PHASE}\n" }
our $destruct = Print::Phase->new(
    "las variables de paquete se recolectan después de END"
);

Esto imprimirá:

tiempo de compilación: START
tiempo de verificación: CHECK
tiempo de inicialización: INIT
tiempo de ejecución: RUN
las variables léxicas se recolectan antes de END: RUN
tiempo final: END
las variables de paquete se recolectan después de END: DESTRUCT

$^H
ADVERTENCIA: Esta variable es estrictamente para uso interno. Su disponibilidad, comportamiento y contenido están sujetos a cambios sin previo aviso.

Esta variable contiene pistas de tiempo de compilación para el intérprete de Perl. Al finalizar la compilación de un BLOQUE, el valor de esta variable se restaura al valor que tenía cuando el intérprete comenzó a compilar el BLOQUE.

Cada vez que se completa la compilación de una sentencia, el valor actual de $^H se almacena con esa sentencia, y posteriormente puede recuperarse a través de "(caller($level))[8]". Consulte "caller EXPR" en perlfunc.

Cuando perl comienza a analizar cualquier construcción de bloque que proporciona un ámbito léxico (por ejemplo, el cuerpo de eval, un archivo requerido, el cuerpo de una subrutina, el cuerpo de un bucle o un bloque condicional), se guarda el valor existente de $^H, pero su valor no se modifica. Cuando se completa la compilación del bloque, recupera el valor guardado. Entre los puntos donde se guarda y restaura su valor, el código que se ejecuta dentro de los bloques BEGIN puede cambiar el valor de $^H.

Este comportamiento proporciona la semántica del ámbito léxico, y se utiliza en, por ejemplo, el pragma "use strict".

El contenido debe ser un entero; diferentes bits del mismo se utilizan para diferentes banderas pragmáticas. Aquí hay un ejemplo:

sub add_100 { $^H |= 0x100 }
sub foo {
    BEGIN { add_100() }
    bar->baz($boon);
}

Esta variable fue introducida en Perl 5.8.0.

Special variables

Many of Perl's special variables are prefixed with ^ or $ or % or @ or &.

$^H
This hash is used internally by Perl to store information about the current lexical scope. It's often used by modules and pragmas to implement lexical scoping for their pragmas.

Consider what happens during execution of the BEGIN block. At this point the BEGIN block has already been compiled, but the body of foo() is still being compiled. The new value of $^H will therefore be visible only while the body of foo() is being compiled.

Substitution of "BEGIN { add_100() }" block with:

BEGIN { require strict; strict->import('vars') }

demonstrates how "use strict 'vars'" is implemented. Here's a conditional version of the same lexical pragma:

BEGIN {
    require strict; strict->import('vars') if $condition
}

This variable was added in Perl 5.003.

%^H
The "%^H" hash provides the same scoping semantics as $^H. This makes it useful for implementing lexically scoped pragmas. See perlpragma. All the entries are stringified when accessed at runtime, so only simple values can be accommodated. This means no references to objects, for example.

Each time a statement completes being compiled, the current value of "%^H" is stored with that statement, and can later be retrieved via "(caller($level))[10]". See "caller EXPR" in perlfunc.

When putting items into "%^H", in order to avoid conflicting with other users of the hash there is a convention regarding which keys to use. A module should use only keys that begin with the module's name (the name of its main package) and a "/" character. For example, a module "Foo::Bar" should use keys such as "Foo::Bar/baz".

This variable was added in Perl v5.6.0.

${^OPEN}
An internal variable used by PerlIO. A string in two parts, separated by a "\0" byte, the first part describes the input layers, the second part describes the output layers.

This is the mechanism that applies the lexical effects of the open pragma, and the main program scope effects of the "io" or "D" options for the -C command-line switch and PERL_UNICODE environment variable.

The functions accept(), open(), pipe(), readpipe() (as well as the related "qx" and `STRING` operators), socket(), socketpair(), and sysopen() are affected by the lexical value of this variable. The implicit "ARGV" handle opened by readline() (or the related "<>" (diamond) and "<<>>" (double diamond) operators) on passed filenames is also affected (but not if it opens "STDIN"). If this variable is not set, these functions will set the default layers as described in "Defaults and how to override them" in PerlIO.

open() ignores this variable (and the default layers) when called with 3 arguments and explicit layers are specified. Indirect calls to these functions via modules like IO::Handle are not affected as they occur in a different lexical scope. Directory handles such as opened by opendir() are not currently affected.

This variable was added in Perl v5.8.0.

Variables deprecated and removed

Deprecating a variable announces the intent of the perl maintainers to eventually remove the variable from the language. It may still be available despite its status. Using a deprecated variable triggers a warning.

Once a variable is removed, its use triggers an error telling you the variable is unsupported.

See perldiag for details about error messages.

$#
$# was a variable that could be used to format printed numbers. After a deprecation cycle, its magic was removed in Perl v5.10.0 and using it now triggers a compilation error: "$# is no longer supported".

This is not the sigil you use in front of an array name to get the last index, like $#array. That's still how you get the last index of an array in Perl. (See "Arrays" in perlintro.) The two have nothing to do with each other.

Deprecated in Perl 5.

Removed in Perl v5.10.0.

$*
$* was a variable that you could use to enable multiline matching. After a deprecation cycle, its magic was removed in Perl v5.10.0. Using it now triggers a compilation error: "$* is no longer supported". You should use the "/s" and "/m" regexp modifiers instead.

Deprecated in Perl 5.

Removed in Perl v5.10.0.

$[
This variable stores the index of the first element in an array, and of the first character in a substring. The default is 0, but you could theoretically set it to 1 to make Perl behave more like awk (or Fortran) when subscripting and when evaluating the index() and substr() functions.

As of release 5 of Perl, assignment to $[ is treated as a compiler directive, and cannot influence the behavior of any other file. (That's why you can only assign compile-time constants to it.) Its use is highly discouraged.

Prior to Perl v5.10.0, assignment to $[ could be seen from outer lexical scopes in the same file, unlike other compile-time directives (such as strict). Using local() on it would bind its value strictly to a lexical block. Now it is always lexically scoped.

As of Perl v5.16.0, it is implemented by the arybase module.

As of Perl v5.30.0, or under "use v5.16", or "no feature "array_base"", $[ no longer has any effect, and always contains 0. Assigning 0 to it is permitted, but any other value will produce an error.

Mnemonic: [ begins subscripts.

Deprecated in Perl v5.12.0.
