PERLWIN32(1perl) Perl Programmers Reference Guide PERLWIN32(1perl)

NOMBRE

perlwin32 - Perl bajo Windows

SINOPSIS

Estas son instrucciones para compilar Perl en Windows 7 y posteriores.

DESCRIPCIÓN

Antes de comenzar, deberías echar un vistazo al archivo README encontrado en el directorio de nivel superior donde se extrajo la distribución de Perl. Asegúrate de leer y comprender los términos bajo los cuales se distribuye este software.

También asegúrate de leer "BUGS AND CAVEATS" (ERRORES Y ADVERTENCIAS) más abajo para conocer las limitaciones conocidas de este port.

El archivo INSTALL en el nivel superior de Perl tiene mucha información que solo es relevante para las personas que compilan Perl en sistemas tipo Unix. En particular, puedes ignorar de forma segura cualquier información que hable de "Configure".

También puedes querer buscar otra opción para compilar un perl que funcione en Windows: el archivo README.cygwin, que proporciona un conjunto diferente de reglas para compilar un perl para Windows. Este método probablemente te permitirá compilar un perl más compatible con Unix, pero también necesitarás descargar y usar varios otros programas de soporte en tiempo de compilación y ejecución descritos en ese archivo.

Este conjunto de instrucciones está destinado a describir un llamado port "nativo" de Perl a la plataforma Windows. Esto incluye sistemas operativos Windows de 32 y 64 bits. El Perl resultante no requiere software adicional para ejecutarse (aparte de lo que vino con tu sistema operativo). Actualmente, este port es capaz de utilizar uno de los siguientes compiladores en las arquitecturas Intel x86 y x86_64:

Microsoft Visual C++    Visual C++ 2015 (versión 14.0) o posterior
Intel C++ Compiler      (experimental)
Gcc by mingw.org        gcc versión 3.4.5-5.3.0
Gcc by mingw-w64.org    gcc versión 4.4.3 o posterior

Ten en cuenta que los dos últimos son en realidad proyectos competidores que entregan cadenas de herramientas gcc completas para MS Windows:

https://osdn.net/projects/mingw/
Entrega cadenas de herramientas gcc que compilan ejecutables de 32 bits (que se pueden usar tanto en plataformas Windows de 32 como de 64 bits)
https://mingw-w64.org
Entrega cadenas de herramientas gcc dirigidas a plataformas Windows de 64 bits y 32 bits (a pesar del nombre del proyecto "mingw-w64", no están orientados solo a 64 bits). Ofrecen compiladores gcc nativos y compiladores cruzados que también son compatibles con el makefile de perl.

Los compiladores Microsoft Visual C++ también se regalan ahora. Están disponibles como "Visual C++ 2015-2022 Community Edition" y son los mismos compiladores que se distribuyen con "Visual C++ 2015-2022 Professional".

El compilador MinGW64 está disponible en https://mingw-w64.org. Este último es en realidad un compilador cruzado dirigido a Win64. También hay un compilador simplificado (sin java, ni gfortran) adecuado para compilar perl disponible en: https://strawberryperl.com/package/kmx/64_gcctoolchain/

NOTA: Si estás usando un compilador de 32 bits para compilar perl en un sistema operativo Windows de 64 bits, entonces deberías establecer la variable de entorno WIN64 a "undef". Además, el compilador simplificado solo pasa las pruebas cuando USE_ITHREADS *= define (en lugar de undef) y cuando la línea CFG *= Debug está comentada.

Este port soporta completamente MakeMaker (el conjunto de módulos que se utiliza para compilar extensiones de perl). Por lo tanto, deberías poder compilar e instalar la mayoría de las extensiones encontradas en los sitios CPAN. Consulta "Usage Hints for Perl on Windows" (Sugerencias de uso para Perl en Windows) a continuación para obtener indicaciones generales sobre esto.

Configuración de Perl en Windows

Make
Necesitas un programa "make" para compilar las fuentes. Si estás usando Visual C++, puedes usar nmake suministrado con Visual C++. También puedes usar gmake en lugar de nmake. Las compilaciones que usan gcc necesitan gmake. nmake no es compatible con compilaciones de gcc. La compilación paralela solo es compatible con gmake, no con nmake.
Shell de comandos
Usa el shell "cmd" predeterminado que viene con Windows. Algunas versiones del popular shell 4DOS/NT tienen incompatibilidades que pueden causarte problemas. Si la compilación falla bajo ese shell, intenta compilar de nuevo con el shell cmd.

Asegúrate de que la ruta al directorio de compilación no contenga espacios. La compilación generalmente funciona en estas circunstancias, pero algunas pruebas fallarán.

Microsoft Visual C++
El nmake que viene con Visual C++ será suficiente para compilar. Visual C++ requiere que ciertas cosas se configuren en la consola antes de que Visual C++ se ejecute correctamente. Para que una ventana de consola pueda ejecutar el compilador C, deberás ejecutar previamente "vcvarsall.bat x86" para compilar para x86-32 y para x86-64 "vcvarsall.bat amd64". En una instalación típica de un producto compilador de Microsoft C++, estos archivos batch ya estarán en tu variable de entorno "PATH", por lo que puedes escribirlos sin una ruta absoluta en tu consola. Si necesitas encontrar la ruta absoluta al archivo batch, generalmente se encuentra en algún lugar como C:\Program Files (x86)\Microsoft Visual Studio 14.0\VC. Con algunos compiladores de Microsoft más nuevos (lanzados después de ~2004), el instalador pondrá un acceso directo en el menú de inicio para iniciar una nueva ventana de consola con la consola ya configurada para tu arquitectura de destino (x86-32 o x86-64 o IA64). Con los compiladores más nuevos, también puedes usar los archivos batch antiguos si así lo eliges.
Microsoft Visual C++ 2015-2022 Community Edition
Estas versiones gratuitas de Visual C++ 2015-2022 Professional contienen los mismos compiladores y enlazadores que se distribuyen con las versiones completas, y también contienen todo lo necesario para compilar Perl.

Estos paquetes se pueden descargar desde https://visualstudio.microsoft.com/.

Instala Visual C++ 2015-2022 Community, luego configura tu entorno usando, por ejemplo:

C:\Program Files\Microsoft Visual Studio 14.0\Common7\Tools\vsvars32.bat

(asumiendo que se eligió la ubicación de instalación predeterminada).

Perl debería compilarse ahora usando el archivo win32/Makefile. Deberás editar ese archivo para establecer primero "CCTYPE" a uno de "MSVC140" a "MSVC143".

Microsoft C++ Build Tools
También hay una versión independiente (sin IDE) de las herramientas de compilación mencionadas anteriormente que contiene el compilador MSVC disponible para descargar desde https://visualstudio.microsoft.com/visual-cpp-build-tools/.

Esto también se conoce como Build Tools for Visual Studio.

GCC
Perl puede compilarse con gcc de MinGW (versión 3.4.5 o posterior) o de MinGW64 (versión 4.4.3 o posterior). Se puede descargar aquí:

https://osdn.net/projects/mingw/ https://www.mingw-w64.org/

También necesitas gmake. Por lo general, viene con MinGW, pero su ejecutable puede tener un nombre diferente, como mingw32-make.exe.

Ten en cuenta que la compilación con MinGW actualmente falla con la versión 6.3.0 o posterior.

Ten en cuenta también que la compilación en modo C++ actualmente falla con MinGW 3.4.5 y 4.7.2 o posterior, y con MinGW64 de 64 bits 6.3.0 o posterior.

Intel C++ Compiler
Se ha añadido soporte experimental para usar Intel C++ Compiler. Edita win32/Makefile y elige el "CCTYPE" correcto para el Visual C en el que se instaló Intel C. También descomenta "__ICC" para habilitar Intel C en el soporte de Visual C. Para configurar el entorno de compilación, desde el menú Inicio, ejecuta el modo Visual Studio 20__ IA-32 o el modo Visual Studio 20__ Intel 64, según corresponda. Luego ejecuta "nmake" como de costumbre en esa ventana de consola.

Solo se ha probado Intel C++ Compiler v12.1. Otras versiones probablemente funcionarán. Usar Intel C++ Compiler en lugar de Visual C tiene el beneficio de C9

Construcción

  • Asegúrate de estar en el subdirectorio win32 bajo el nivel superior de perl. Este directorio contiene un Makefile que funcionará con las versiones de "nmake" que vienen con Visual C++, y un GNUmakefile de GNU make que funcionará para todos los compiladores soportados. Los valores predeterminados en el makefile de "gmake" están configurados para compilar con MinGW/gcc.
  • Edita el GNUmakefile (o Makefile, si estás usando nmake) y cambia los valores de INST_DRV y "INST_TOP". También puedes habilitar varias banderas de compilación. Estas se explican en los makefiles.

    Ten en cuenta que, en general, no es una buena idea intentar compilar un "perl" con "INST_DRV" e "INST_TOP" establecidos en una ruta que ya existe de una compilación anterior. En particular, esto puede causar problemas con la prueba lib/ExtUtils/t/Embed.t, que intenta compilar un programa de prueba y puede terminar compilando contra el directorio lib/CORE de "perl" instalado en lugar del que se está probando.

    Tendrás que asegurarte de que "CCTYPE" esté configurado correctamente y de que "CCHOME" apunte a donde sea que hayas instalado tu compilador. Para GCC, este debería ser el directorio que contiene los directorios bin, include y lib.

    Si compilas con el compilador cruzado proporcionado por mingw-w64.org, necesitarás descomentar la línea que establece "GCCCROSS" en el GNUmakefile. Haz esto solo si es el compilador cruzado, es decir, solo si la carpeta bin no contiene un gcc.exe. (El compilador cruzado no proporciona un gcc.exe, g++.exe, ar.exe, etc. En su lugar, todos estos ejecutables tienen el prefijo "x86_64-w64-mingw32-".)

    El valor predeterminado para "CCHOME" en los makefiles para Visual C++ puede no ser correcto para algunas versiones. Asegúrate de que el valor predeterminado exista y sea válido.

    Si deseas compilar algunas extensiones principales estáticamente en el DLL de "perl", especifícalas en la macro "STATIC_EXT".

    Asegúrate de leer atentamente las instrucciones cerca de la parte superior de los makefiles.

  • Escribe "gmake" (o "nmake" si estás usando esa versión de "make").

    Esto debería compilar todo. Específicamente, creará perl.exe, perl542.dll en el nivel superior de perl, y varios otros DLL de extensiones bajo el directorio lib\auto. Si la compilación falla por alguna razón, asegúrate de haber realizado los pasos anteriores correctamente.

    Para probar el modo paralelo de "gmake", escribe "gmake -j2", donde 2 es el número máximo de trabajos paralelos que deseas ejecutar. Varias cosas en el proceso de compilación se ejecutarán en paralelo, pero hay puntos de serialización donde verás solo 1 CPU al máximo. Esto es normal.

    Si tienes suficiente experiencia compilando código C, aquí tienes una sugerencia para acelerar la compilación de "perl" y la posterior "make test". Intenta mantener tu variable de entorno "PATH" con el menor número posible de carpetas (recuerda mantener las carpetas de tu compilador C allí). C:\WINDOWS\system32 o C:\WINNT\system32, dependiendo de la versión de tu sistema operativo, debería ser la primera carpeta en "PATH", ya que "cmd.exe" es el programa que se lanza con más frecuencia durante la compilación y las pruebas posteriores.

Pruebas de Perl en Windows

Escribe "gmake test" (o "nmake test"). Esto ejecutará la mayoría de las pruebas de la suite de pruebas (muchas pruebas se omitirán).

No debería haber fallos en las pruebas.

Si compilas con Visual C++ 2015 o posterior, entonces ext/XS-APItest/t/locale.t puede fallar (después de que todas sus pruebas hayan pasado). Esto se debe a una regresión en el Universal CRT introducida en la Actualización de Windows 10 de abril de 2018, y se corregirá en la Actualización de mayo de 2019, como se explica aquí: https://developercommunity.visualstudio.com/content/problem/519486/setlocalelc-numeric-iso-latin-16-fails-then-succee.html.

Si compilas con ciertas versiones (por ejemplo, 4.8.1) de gcc de mingw, entonces ext/POSIX/t/time.t puede fallar la prueba 17 debido a un error conocido en esas compilaciones de gcc: ver https://sourceforge.net/p/mingw/bugs/2152/.

Pueden ocurrir algunos fallos en las pruebas si utilizas un shell de comandos distinto del nativo "cmd.exe", o si estás compilando desde una ruta que contiene espacios. Así que no hagas eso.

Si estás ejecutando las pruebas desde una ventana de shell de emacs, puedes ver fallos en op/stat.t. Ejecuta "gmake test-notty" en ese caso.

Además, debes asegurarte de que durante "make test" no tengas ningún paquete de herramientas GNU en tu PATH: algunos toolkits como Unixutils incluyen algunas herramientas ("type" por ejemplo) que anulan las de Windows y hacen fallar las pruebas. Elimínalos de tu PATH mientras pruebas para evitar estos errores.

Para ver la salida de pruebas fallidas específicas, ejecuta el harness desde el directorio t:

# asumiendo que empiezas desde el directorio win32
cd ..\win32
.\perl harness <lista de pruebas>

Por favor, informa de cualquier otro fallo como se describe en "ERRORES Y ADVERTENCIAS".

Instalación de Perl en Windows

Escribe "gmake install" ("nmake install"). Esto colocará el perl recién compilado y las bibliotecas bajo lo que sea que apunte "INST_TOP" en el Makefile. También instalará la documentación pod bajo "$INST_TOP\$INST_VER\lib\pod" y versiones HTML de la misma bajo "$INST_TOP\$INST_VER\lib\pod\html".

Para usar el Perl que acabas de instalar, necesitarás agregar una nueva entrada a tu variable de entorno PATH: "$INST_TOP\bin", por ejemplo:

set PATH=c:\perl\bin;%PATH%

Si optaste por descomentar "INST_VER" y "INST_ARCH" en el makefile, la estructura de instalación es un poco más complicada y necesitarás agregar dos componentes de PATH más: "$INST_TOP\$INST_VER\bin" y "$INST_TOP\$INST_VER\bin\$ARCHNAME", por ejemplo:

set PATH=c:\perl\5.6.0\bin;c:\perl\5.6.0\bin\MSWin32-x86;%PATH%

Sugerencias de Uso para Perl en Windows

Variables de Entorno
Las rutas de instalación que estableciste durante la compilación se compilan en perl, por lo que no tienes que hacer nada adicional para empezar a usar ese perl (excepto agregar su ubicación a tu variable PATH).

Si colocas extensiones en lugares inusuales, puedes establecer PERL5LIB a una lista de rutas separadas por punto y coma donde deseas que perl busque bibliotecas. Busca descripciones de otras variables de entorno que puedes establecer en perlrun.

También puedes controlar el shell que perl usa para ejecutar comandos system() y de comillas invertidas a través de PERL5SHELL. Ver perlrun.

Perl no depende del registro, pero puede buscar ciertos valores predeterminados si eliges ponerlos allí, a menos que se deshabilite en el momento de la compilación con USE_NO_REGISTRY. Al iniciar el proceso de Perl, Perl verifica si existen "HKEY_CURRENT_USER\Software\Perl" y "HKEY_LOCAL_MACHINE\Software\Perl". Si las claves existen, se consultarán durante el resto de la vida del proceso de Perl para ciertas entradas. Las entradas en "HKEY_CURRENT_USER\Software\Perl" anulan las entradas en "HKEY_LOCAL_MACHINE\Software\Perl". Una o más de las siguientes entradas (de tipo REG_SZ o REG_EXPAND_SZ) pueden estar establecidas en las claves:

lib-$]        ruta de biblioteca estándar específica de la versión para agregar a @INC
lib           ruta de biblioteca estándar para agregar a @INC
sitelib-$]    ruta de biblioteca de sitio específica de la versión para agregar a @INC
sitelib       ruta de biblioteca de sitio para agregar a @INC
vendorlib-$]  ruta de biblioteca de proveedor específica de la versión para agregar a @INC
vendorlib     ruta de biblioteca de proveedor para agregar a @INC
PERL*         fallback para todas las búsquedas en %ENV que comienzan con "PERL"

Ten en cuenta que $] en lo anterior no es literal. Sustituye la versión de perl que deseas para que esa entrada sea honrada, por ejemplo, 5.6.0. Las rutas deben separarse con punto y coma, como es habitual en Windows.

Globbing de Archivos
Por defecto, perl maneja el globbing de archivos utilizando la extensión File::Glob, que proporciona globbing portable.

Si deseas que perl utilice globbing que emule las peculiaridades de las convenciones de nombres de archivo de DOS, podrías considerar usar File::DosGlob para anular la implementación interna de glob(). Ver File::DosGlob para más detalles.

Uso de perl desde la línea de comandos
Si estás acostumbrado a usar perl desde varios shells de línea de comandos que se encuentran en entornos UNIX, no te complacerá lo que Windows ofrece en cuanto a shells de comandos.

2.
Dado que las asociaciones de archivos no funcionan en todas partes, y hay informes de errores con las asociaciones de archivos donde sí funcionan, el antiguo método de envolver el script de perl para que parezca un archivo batch normal para el sistema operativo, puede ser utilizado. El proceso de instalación pone a disposición el script "pl2bat.bat" que se puede usar para envolver scripts de perl en archivos batch. Por ejemplo: 
pl2bat foo.pl

creará el archivo "FOO.BAT". Nota que "pl2bat" elimina cualquier sufijo .pl y añade un sufijo .bat al archivo generado.

Si usas el shell de comandos 4DOS/NT o similar, ten en cuenta que "pl2bat" usa la variable "%*" en el archivo batch generado para referirse a todos los argumentos de la línea de comandos, así que puede que necesites asegurarte de que esa construcción funcione en los archivos batch. En el momento de escribir esto, los usuarios de 4DOS/NT necesitarán una declaración "ParameterChar = *" en su archivo 4NT.INI o necesitarán ejecutar "setdos /p*" en el archivo de inicio de 4DOS/NT para habilitar esto.

3.
El uso de "pl2bat" tiene algunos problemas: el nombre del archivo cambia, por lo que los scripts que dependen de $0 para encontrar lo que deben hacer pueden no ejecutarse correctamente; ejecutar "pl2bat" replica el contenido del script original, y por lo tanto este proceso puede requerir mucho mantenimiento si los originales se actualizan a menudo. Un enfoque diferente que evita ambos problemas es posible.

Un script llamado "runperl.bat" está disponible y puede ser copiado a cualquier nombre de archivo (junto con el sufijo .bat). Por ejemplo, si lo llamas "foo.bat", ejecutará el archivo "foo" cuando sea ejecutado. Dado que puedes ejecutar archivos batch en plataformas Windows simplemente escribiendo el nombre (sin la extensión), esto efectivamente ejecuta el archivo "foo", cuando escribes "foo" o "foo.bat". Con este método, "foo.bat" puede incluso estar en una ubicación diferente al archivo "foo", siempre y cuando "foo" esté disponible en algún lugar del PATH. Si tus scripts están en un sistema de archivos que permite enlaces simbólicos, puedes incluso evitar copiar "runperl.bat".

Cosas misceláneas

Se instala un conjunto completo de documentación HTML, por lo que deberías poder usarla si tienes un navegador web instalado en tu sistema.

"perldoc" es también una herramienta útil para navegar por la información contenida en la documentación, especialmente en conjunción con un paginador como "less" (versiones recientes del cual tienen soporte para Windows). Puede que necesites configurar la variable de entorno PAGER para usar un paginador específico. "perldoc -f foo" imprimirá información sobre el operador de perl "foo".

Un error común al usar este puerto con una biblioteca GUI como "Tk" es asumir que el comportamiento normal de Perl de abrir una ventana de línea de comandos desaparecerá. Este no es el caso. Si quieres iniciar una copia de "perl" sin abrir una ventana de línea de comandos, usa el ejecutable "wperl" compilado durante el proceso de instalación. El uso es exactamente el mismo que el de "perl" normal en Windows, excepto que opciones como "-h" no funcionan (ya que necesitan una ventana de línea de comandos para imprimir).

Si encuentras errores en perl, puedes reportarlos en https://github.com/Perl/perl5/issues.

ERRORES Y ADVERTENCIAS

Norton AntiVirus interfiere con el proceso de compilación, particularmente si está configurado como "AutoProtect, All Files, when Opened". A diferencia de las aplicaciones grandes, el proceso de compilación de perl abre y modifica muchos archivos. Tener el antivirus escaneando cada uno de ellos ralentiza significativamente el proceso de compilación. Peor aún, con PERLIO=stdio, el proceso de compilación falla con mensajes peculiares ya que el verificador de virus interactúa mal con miniperl.exe escribiendo archivos de configuración (parece que o bien captura una parte del archivo escrita y la trata como sospechosa, o el verificador de virus puede tenerla "bloqueada" de una manera que impide que miniperl la actualice). La compilación sí se completa con

set PERLIO=perlio

pero eso puede ser solo suerte. Otro software antivirus puede tener problemas similares.

Una extensión GUI de Git para Windows como TortoiseGit hará que la compilación y más tarde "make test" se ejecuten mucho más lentamente ya que cada archivo se verifica en cuanto a su estado de git tan pronto como se crea y/o modifica. TortoiseGit no causa fallos en las pruebas ni problemas de compilación a diferencia del software antivirus descrito anteriormente, pero sí causa lentitud similar. Se sugiere usar el Administrador de Tareas para buscar procesos en segundo plano que usen cantidades altas de CPU durante el proceso de compilación.

Algunas de las funciones integradas no actúan exactamente como se documenta en perlfunc, y algunas no están implementadas en absoluto. Para evitar sorpresas, especialmente si has tenido exposición previa a Perl en otros entornos operativos o si tienes la intención de escribir código que sea portable a otros entornos, consulta perlport para obtener una lista razonablemente definitiva de estas diferencias.

No todas las extensiones disponibles en CPAN pueden compilarse o funcionar correctamente en el entorno Windows. Ver "Building Extensions".

La mayoría de las llamadas relacionadas con socket() son compatibles, pero pueden no comportarse como en las plataformas Unix. Ver perlport para la lista completa.

El manejo de señales puede no comportarse como en las plataformas Unix (donde tampoco se "comporta" exactamente :). Por ejemplo, llamar a die() o exit() desde manejadores de señales causará una excepción, ya que la mayoría de las implementaciones de signal() en Windows están severamente limitadas. Por lo tanto, las señales solo pueden funcionar para cosas simples como establecer una variable de bandera en el manejador. El uso de señales bajo este puerto debe considerarse actualmente no soportado.

Por favor, informe descripciones detalladas de cualquier problema y solución que encuentre en <https://github.com/Perl/perl5/issues>, junto con la salida producida por "perl -V".
