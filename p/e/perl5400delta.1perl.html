NOMBRE

perl5400delta - qué hay de nuevo para la versión perl v5.40.0

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.38.0 y la versión 5.40.0.

Mejoras del núcleo

Nueva palabra clave "__CLASS__"

Cuando se usa la nueva característica "class", el código dentro de un método, un bloque "ADJUST" o una expresión inicializadora de campo ahora tiene permiso para usar la nueva palabra clave "__CLASS__". Esto produce un nombre de clase, similar a "__PACKAGE__", pero mientras que este último da el paquete en tiempo de compilación en el que aparece el código, la palabra clave "__CLASS__" es consciente de la clase real en tiempo de ejecución de la que la instancia del objeto es miembro. Esto la hace útil para la distribución de métodos en esa clase, especialmente durante los constructores, donde no se permite el acceso a $self.

Para más información, consulte "__CLASS__" en perlfunc.

Atributo ":reader" para variables de campo

Cuando se usa la característica "class", las variables de campo ahora pueden tener un atributo ":reader". Esto solicita que se cree automáticamente un método de acceso que simplemente devuelve el valor de la variable de campo de la instancia dada.

field $name :reader;

Es equivalente a

field $name;
method name () { return $name; }

También se puede proporcionar un nombre alternativo:

field $name :reader(get_name);

Para más detalles, consulte ":reader" en perlclass.

Permitir un espacio en la opción de línea de comandos "-M"

Al procesar opciones de línea de comandos, perl ahora permite un espacio entre el modificador "-M" y el nombre del módulo que le sigue.

$ perl -M Data::Dumper=Dumper -E 'say Dumper [1,2,3]'

Esto coincide con el comportamiento existente de la opción "-I".

Restricciones a las declaraciones "use VERSION"

En Perl 5.36, se añadió una advertencia de deprecación al degradar una declaración "use VERSION" de una superior a la versión 5.11, a una inferior. Esto ahora se ha convertido en un error fatal.

Además, ahora es un error fatal emitir una declaración "use VERSION" posterior cuando otra ya está en alcance, cuando cualquiera de las versiones es 5.39 o superior. Esto es para evitar complicaciones relacionadas con funciones léxicas importadas de integradas. También se ha añadido una advertencia de deprecación para cualquier otra declaración "use VERSION" posterior por debajo de la versión 5.39, para advertir que ya no estará permitida en la versión Perl 5.44.

Nuevas funciones "builtin::inf" y "builtin::nan" (experimental)

Se han añadido dos nuevas funciones, "inf" y "nan", al espacio de nombres "builtin". Estas actúan como constantes que producen el infinito de punto flotante y el valor No es un Número (NaN) respectivamente.

Nuevo operador lógico xor "^^"

Perl siempre ha tenido tres operadores lógicos de baja precedencia "and", "or" y "xor", así como tres versiones bit a bit de alta precedencia "&", "^" y "|". Hasta esta versión, si bien los operadores lógicos de precedencia media de "&&" y "||" también estaban presentes, no existía un equivalente de 'o exclusivo'. Esta versión de Perl añade el operador final "^^", completando el conjunto.

$x ^^ $y and say "Una de x o y es verdadera, pero no ambas";

La característica "try"/"catch" ya no es experimental

Antes de esta versión, la característica "try"/"catch" para manejar errores se consideraba experimental. Introducida en la versión Perl 5.34.0, ahora se considera una característica estable del lenguaje y su uso ya no produce una advertencia. Todavía debe habilitarse con la característica 'try'.

Consulte "Manejo de excepciones Try Catch" en perlsyn.

La iteración en "for" sobre múltiples valores a la vez ya no es experimental

Antes de esta versión, la iteración sobre múltiples valores a la vez con "for" se consideraba experimental. Introducida en la versión Perl 5.36.0, ahora se considera una característica estable del lenguaje y su uso ya no produce una advertencia. Consulte "Sentencias compuestas" en perlsyn.

El módulo "builtin" ya no es experimental

Antes de esta versión, el módulo builtin y todas sus funciones se consideraban experimentales. Introducido en la versión Perl 5.36.0, este módulo ahora se considera estable y su uso ya no produce una advertencia. Sin embargo, varias de sus funciones todavía se consideran experimentales.

El paquete de características ":5.40" añade "try"

El paquete de características de la última versión ahora contiene la característica recientemente estabilizada "try". Dado que este paquete de características es utilizado por el modificador de línea de comandos "-E", estas están inmediatamente disponibles en los scripts de "-E".

"use v5.40;" importa funciones builtin

Además de importar un paquete de características, "use v5.40;" (o versiones posteriores) importa el paquete de versión builtin correspondiente.

Seguridad

CVE-2023-47038 - Escritura fuera de los límites del búfer a través de propiedades Unicode definidas por el usuario no válidas

Esta vulnerabilidad fue informada directamente al equipo de seguridad de Perl por Nathan Mills "the.true.nathan.mills@gmail.com".

Una expresión regular manipulada, al ser compilada por perl 5.30.0 hasta 5.38.0, puede causar un desbordamiento de búfer de un byte controlado por el atacante en un búfer asignado en el heap.

Las siguientes adiciones o cambios se han realizado en la salida diagnóstica, incluyendo advertencias y mensajes de error fatales. Para ver la lista completa de mensajes diagnósticos, consulte perldiag.

Nuevos Diagnósticos

Nuevos errores

  • No se puede usar __CLASS__ fuera de un método o una expresión de inicialización de campo

    (F) Una expresión "__CLASS__" devuelve el nombre de la clase de la instancia del objeto que ejecuta el método actual y, por lo tanto, solo puede colocarse dentro de un método real (o una expresión similar a un método, como una expresión de inicialización de campo).

  • get_layers: argumento desconocido '%s'

    (F) Llamó a PerlIO::get_layers() con un argumento desconocido. Los argumentos legales se proporcionan en pares clave/valor, siendo las claves una de "input", "output" o "detail", seguida de un booleano.

  • UNIVERSAL no exporta nada

    (F) Pidió a UNIVERSAL que exportara algo, pero UNIVERSAL es la clase base para todas las clases y no contiene símbolos exportables.

  • El paquete integrado "%s" no es compatible con Perl

    (F) Intentó "use builtin :ver" para un número de versión que es anterior a 5.39 (cuando se agregó la capacidad) o posterior a la versión actual de perl.

  • Paquete de versión no válido "%s"

    (F) Un número de versión que se utiliza para especificar un paquete de importación durante una declaración "use builtin ..." debe tener el formato ":MAJOR.MINOR" con un tercer componente opcional, que se ignora. Cada componente debe ser un número de 1 a 3 dígitos. No se permiten otros caracteres. El valor especificado no cumple estas reglas.

  • Falta coma después del primer argumento para return

    (F) Mientras que ciertos operadores le permiten especificar un manejador de archivos o un "objeto indirecto" antes de la lista de argumentos, "return" no es uno de ellos.

  • Falta de memoria durante vec en contexto lvalue

    (F) Se intentó extender una cadena más allá de la asignación de memoria más grande posible asignando a vec() llamada con un segundo argumento grande.

    (Este caso solía lanzar un error genérico "¡Falta de memoria!".)

  • No se puede crear un objeto de la clase incompleta "%s"

    (F) Se intentó crear un objeto de una clase para la que se ha visto el inicio de la definición de la clase, pero la clase no se ha completado.

    Esto puede suceder debido a un eval fallido, o si intenta crear un objeto en tiempo de compilación antes de que la clase esté completa:

    eval "class Foo {"; Foo->new; # error
class Bar { BEGIN { Bar->new } }; # error

    Anteriormente, perl afirmaba o se bloqueaba. [GH #22159 https://github.com/Perl/perl5/issues/22159]

Nuevas advertencias

  • Forked open '%s' no tiene significado en <>

    (S inplace) Tenía "|-" o "-|" en @ARGV y trató de usar "<>" para leer de él.

    Anteriormente, esto haría un fork y produciría un mensaje de error confuso. [GH #21176 https://github.com/Perl/perl5/issues/21176]

  • Intento de llamar al método indefinido %s con argumentos ("%s"%s) a través del paquete "%s" (¿Quizás olvidó cargar el paquete?)

    (D deprecated::missing_import_called_with_args) Llamó al método import() o unimport() de una clase que no tiene un método de importación definido en su gráfico de herencia, y pasó un argumento al método. Esto es muy a menudo el signo de un nombre de paquete mal escrito en una declaración use o require que ha tenido éxito silenciosamente debido a un sistema de archivos insensible a mayúsculas y minúsculas.

    Otra razón común por la que esto puede suceder es al intentar incorrectamente importar o desimportar un símbolo de una definición de clase o paquete que no usa "Exporter" o que de otra manera no define sus propios métodos "import" o "unimport".

Cambios en Diagnósticos Existentes

  • Nombre "%s::%s" usado solo una vez: posible error tipográfico

    Esta advertencia ahora respeta ser marcada como fatal. [GH #13814 https://github.com/Perl/perl5/issues/13814]

  • Falta de memoria en perl:%s

    Solía haber varios lugares en el núcleo de perl que imprimían un mensaje genérico de "¡Falta de memoria!" y abortaban cuando la asignación de memoria fallaba, sin dar ninguna indicación de qué programa se estaba quedando sin memoria. Estos se han modificado para incluir la palabra "perl" y el área general de la falla de asignación, por ejemplo, "Falta de memoria en perl:util:safesysrealloc". [GH #21672 https://github.com/Perl/perl5/issues/21672]

  • Posible problema de precedencia con el operador de flujo de control (%s)

    Esta advertencia ahora menciona el nombre del operador de flujo de control que activó el diagnóstico (por ejemplo, "return", "exit", "die", etc.).

    También cubre más casos: Anteriormente, la advertencia solo se activaba si se involucraba un operador lógico de baja precedencia (como "and", "or", "xor"). Ahora también se muestra para código engañoso como este:

    exit $x ? 0 : 1;  # en realidad se analiza como: exit($x) ? 0 : 1;
exit $x == 0;     # en realidad se analiza como: exit($x) == 0;
  • Uso de valor no inicializado%s

    Esta advertencia ahora es un poco más precisa en casos que involucran "length", "pop", "shift" o "splice":

    my $x;
length($x) == 0
# Antes:
#  Uso de valor no inicializado $x en numeric eq (==) en ...
# Ahora:
#  Uso de valor no inicializado length($x) en numeric eq (==) en ...

    Es decir, la advertencia ya no implica que $x se usó directamente como operando de "==", lo cual no fue así.

    Similarmente:

    my @xs;
shift @xs == 0
# Antes:
#  Uso de valor no inicializado dentro de @xs en numeric eq (==) en ...
# Ahora:
#  Uso de valor no inicializado shift(@xs) en numeric eq (==) en ...

    Esto es más preciso porque nunca hubo un "undef" dentro de @xs como implicaba la advertencia. (La advertencia para "pop" funciona de manera análoga).

    Finalmente:

    my @xs = (1, 2, 3);
splice(@xs, 0, 0) == 0
# Antes:
#  Uso de valor no inicializado dentro de @xs en numeric eq (==) en ...
# Ahora:
#  Uso de valor no inicializado en numeric eq (==) en ...

    Es decir, en casos donde "splice" devuelve "undef", ya no culpa incondicionalmente a su primer argumento. Esto fue engañoso porque "splice" puede devolver "undef" incluso si ninguno de sus argumentos contiene "undef".

    [GH #21930 https://github.com/Perl/perl5/issues/21930]

  • Antiguo separador de paquete "'" obsoleto

    Evita que esta advertencia aparezca de forma espuria al verificar la heurística para la advertencia "You need to quote "%s"".

    [GH #22145 https://github.com/Perl/perl5/issues/22145]

      Selected Bug Fixes

      • A bug where certain source code with certain characters could cause incorrect behaviour in the compiler has been fixed.

      • A bug where Perl's internal representation of the version string might not correctly reflect the specified version was fixed, thus emitting spurious "Downgrading a use VERSION declaration" warnings due to an inconsistency in the way the version number was stored.
