PERL5241DELTA(1perl) Guía de referencia para programadores de Perl PERL5241DELTA(1perl)

NOMBRE

perl5241delta - qué hay de nuevo para la versión perl v5.24.1

DESCRIPCIÓN

Este documento describe las diferencias entre la versión 5.24.0 y la versión 5.24.1.

Si está actualizando desde una versión anterior como la 5.22.0, primero lea perl5240delta, que describe las diferencias entre 5.22.0 y 5.24.0.

Seguridad

El modificador -Di ahora es obligatorio para la salida de depuración de PerlIO

Anteriormente, la salida de depuración de PerlIO se enviaba al archivo especificado por la variable de entorno "PERLIO_DEBUG" si perl no se estaba ejecutando con permisos setuid y los modificadores -T o -t aún no se habían analizado.

Si perl realizaba una salida en un punto en el que aún no había analizado sus modificadores, esto podía hacer que perl creara o sobrescribiera el archivo nombrado por "PERLIO_DEBUG", incluso cuando se había proporcionado el modificador -T.

Perl ahora requiere el modificador -Di para producir salida de depuración de PerlIO. Por defecto, esta se escribe en "stderr", pero opcionalmente se puede redirigir a un archivo estableciendo la variable de entorno "PERLIO_DEBUG".

Si perl se está ejecutando con permisos setuid o se proporcionó el modificador -T, se ignora "PERLIO_DEBUG" y la salida de depuración se envía a "stderr", como con cualquier otro modificador -D.

Los módulos y herramientas principales ya no buscan "." para módulos opcionales

Las herramientas y muchos módulos proporcionados en el núcleo ya no buscan la entrada del directorio actual predeterminada en @INC para módulos opcionales. Por ejemplo, Storable eliminará el último "." de @INC antes de intentar cargar Log::Agent.

Esto evita que un atacante inyecte un módulo opcional en un proceso ejecutado por otro usuario donde el directorio actual es escribible por el atacante, por ejemplo, el directorio /tmp.

En la mayoría de los casos, esta eliminación no debería causar problemas, pero se encontraron dificultades con base, que trata cada nombre de módulo proporcionado como opcional. Estas dificultades aún no se han resuelto, por lo que para esta versión no hay cambios en base. Esperamos tener una solución para base en Perl 5.24.2.

Para proteger su propio código de este ataque, elimine la entrada predeterminada "." de @INC al principio de su script, de modo que:

#!/usr/bin/perl
use strict;
...

se convierta en:

#!/usr/bin/perl
BEGIN { pop @INC if $INC[-1] eq '.' }
use strict;
...

o para módulos, elimine "." de un @INC localizado, de modo que:

my $can_foo = eval { require Foo; }

se convierta en:

my $can_foo = eval {
    local @INC = @INC;
    pop @INC if $INC[-1] eq '.';
    require Foo;
};

Cambios Incompatibles

Aparte de los cambios de seguridad anteriores, no hay cambios intencionalmente incompatibles con Perl 5.24.0. Si existen, son errores y solicitamos que envíe un informe. Consulte "Reporte de Errores" a continuación.

•
Se ha añadido un nuevo script de prueba, t/run/switchDx.t, para probar que el nuevo modificador -Di funciona correctamente.

Correcciones de Errores Seleccionadas

•
Se ha revertido el cambio en la redirección de hashbang introducido en Perl 5.24.0, por el cual perl redirigía a otro intérprete (Perl 6) si encontraba una ruta de hashbang que contenía "perl" seguido de "6", ya que fallaba en casos como "#!/opt/perl64/bin/perl".

Reporting Bugs

If you find what you think is a bug, you might check the articles recently posted to the comp.lang.perl.misc newsgroup and the Perl bug database at https://rt.perl.org/ . There may also be information at http://www.perl.org/ , the Perl Home Page.

If you believe you have an unreported bug, please run the perlbug program included with your release. Be sure to trim your bug down to a tiny but sufficient test case. Your bug report, along with the output of "perl -V", will be sent off to perlbug@perl.org to be analysed by the Perl porting team.

If the bug you are reporting has security implications which make it inappropriate to send to a publicly archived mailing list, then see "SECURITY VULNERABILITY CONTACT INFORMATION" in perlsec for details of how to report the issue.
