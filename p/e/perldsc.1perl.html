PERLDSC(1perl) Guía de Referencia del Programador de Perl PERLDSC(1perl)

NOMBRE

perldsc - Libro de cocina de estructuras de datos de Perl

DESCRIPCIÓN

Perl nos permite tener estructuras de datos complejas. ¡Puedes escribir algo como esto y de repente, tendrás un array con tres dimensiones!

for my $x (1 .. 10) {
    for my $y (1 .. 10) {
        for my $z (1 .. 10) {
            $AoA[$x][$y][$z] =
                $x ** $y + $z;
        }
    }
}

Por desgracia, aunque esto pueda parecer simple, ¡en el fondo es una construcción mucho más elaborada de lo que parece!

¿Cómo lo imprimes? ¿Por qué no puedes simplemente decir "print @AoA"? ¿Cómo lo ordenas? ¿Cómo puedes pasarlo a una función o recuperar uno de estos de una función? ¿Es un objeto? ¿Puedes guardarlo en disco para leerlo más tarde? ¿Cómo accedes a filas o columnas enteras de esa matriz? ¿Tienen que ser todos los valores numéricos?

Como ves, es fácil confundirse. Si bien una pequeña parte de la culpa de esto se puede atribuir a la implementación basada en referencias, es realmente más debido a la falta de documentación existente con ejemplos diseñados para principiantes.

Este documento pretende ser un tratamiento detallado pero comprensible de los diferentes tipos de estructuras de datos que podrías desear desarrollar. También debería servir como un libro de cocina con ejemplos. De esa manera, cuando necesites crear una de estas estructuras de datos complejas, podrás simplemente pellizcar, robar o apropiarte de un ejemplo de aquí.

Veamos cada una de estas posibles construcciones en detalle. Hay secciones separadas para cada una de las siguientes:

  • arrays de arrays
  • hashes de arrays
  • arrays de hashes
  • hashes de hashes
  • construcciones más elaboradas

Pero por ahora, veamos los problemas generales comunes a todos estos tipos de estructuras de datos.

REFERENCIAS

Lo más importante que hay que entender sobre todas las estructuras de datos en Perl, incluidos los arrays multidimensionales, es que aunque puedan parecer de otra manera, los @ARRAYs y %HASHes de Perl son internamente unidimensionales. Solo pueden contener valores escalares (es decir, una cadena, un número o una referencia). No pueden contener directamente otros arrays o hashes, sino que contienen *referencias* a otros arrays o hashes.

No puedes usar una referencia a un array o hash de la misma manera que usarías un array o hash real. Para los programadores de C o C++ no acostumbrados a distinguir entre arrays y punteros a los mismos, esto puede ser confuso. Si es así, simplemente piénsalo como la diferencia entre una estructura y un puntero a una estructura.

Puedes (y debes) leer más sobre referencias en perlref. En resumen, las referencias son muy parecidas a los punteros que saben a qué apuntan. (Los objetos también son un tipo de referencia, pero no los necesitaremos de inmediato, si es que alguna vez los necesitamos.) Esto significa que cuando tienes algo que te parece un acceso a un array y/o hash bidimensional o superior, lo que realmente está sucediendo es que el tipo base es meramente una entidad unidimensional que contiene referencias al siguiente nivel. Es solo que puedes *usarlo* como si fuera bidimensional. De hecho, así es como funcionan casi todos los arrays multidimensionales de C.

$array[7][12]                       # array de arrays
$array[7]{string}                   # array de hashes
$hash{string}[7]                    # hash de arrays
$hash{string}{'another string'}     # hash de hashes

Ahora bien, dado que el nivel superior solo contiene referencias, si intentas imprimir tu array con una simple función print(), obtendrás algo que no se ve muy bien, como esto:

  my @AoA = ( [2, 3], [4, 5, 7], [0] );
  print $AoA[1][2];
7
  print @AoA;
ARRAY(0x83c38)ARRAY(0x8b194)ARRAY(0x8b1d0)

Eso es porque Perl no (nunca) desreferencia implícitamente tus variables. Si quieres acceder a la cosa a la que se refiere una referencia, entonces tienes que hacerlo tú mismo usando indicadores de tipo prefijo, como "${$blah}", "@{$blah}", "@{$blah[$i]}", o flechas de puntero postfijo, como "$arr->[3]", "$hash->{fred}", o incluso "$obj->method()->[3]".

ERRORES COMUNES

Los dos errores más comunes al construir algo como un array de arrays son contar accidentalmente el número de elementos o tomar una referencia a la misma ubicación de memoria repetidamente. Aquí está el caso en el que simplemente obtienes el conteo en lugar de un array anidado:

for my $i (1..10) {
    my @array = somefunc($i);
    $AoA[$i] = @array;      # ¡MAL!
}

Ese es solo el caso simple de asignar un array a un escalar y obtener su recuento de elementos. Si eso es lo que realmente y verdaderamente quieres, entonces podrías considerar ser un poco más explícito al respecto, así:

for my $i (1..10) {
    my @array = somefunc($i);
    $counts[$i] = scalar @array;
}

Aquí está el caso de tomar una referencia a la misma ubicación de memoria una y otra vez:

# Ya sea sin strict o teniendo una declaración my @array; de ámbito
# exterior.
for my $i (1..10) {
    @array = somefunc($i);
    $AoA[$i] = \@array;     # ¡MAL!
}

Entonces, ¿cuál es el gran problema con eso? Parece correcto, ¿verdad? Después de todo, ¡acabo de decirte que necesitas un array de referencias, así que por Dios, me has hecho uno!

Desafortunadamente, aunque esto es cierto, todavía está roto. Todas las referencias en @AoA se refieren al *mismo* lugar, y por lo tanto todas contendrán lo último que hubo en @array. Es similar al problema demostrado en el siguiente programa en C:

#include <pwd.h>
main() {
    struct passwd *getpwnam(), *rp, *dp;
    rp = getpwnam("root");
    dp = getpwnam("daemon");
    printf("daemon name is %s\nroot name is %s\n",
            dp->pw_name, rp->pw_name);
}

Lo que imprimirá

daemon name is daemon
root name is daemon

¡El problema es que tanto "rp" como "dp" son punteros a la misma ubicación en memoria! En C, tendrías que recordar hacer malloc() tú mismo algo de memoria nueva. En Perl, querrás usar el constructor de arrays "[]" o el constructor de hashes "{}" en su lugar. Aquí está la forma correcta de hacer los fragmentos de código rotos anteriores:

# Ya sea sin strict o teniendo una declaración my @array; de ámbito
# exterior.
for my $i (1..10) {
    @array = somefunc($i);
    $AoA[$i] = [ @array ];
}

Los corchetes crean una referencia a un nuevo array con una *copia* de lo que hay en @array en el momento de la asignación. Esto es lo que quieres.

Ten en cuenta que esto producirá algo similar:

# Ya sea sin strict o teniendo una declaración my @array; de ámbito
# exterior.
for my $i (1..10) {
    @array = 0 .. $i;
    $AoA[$i]->@* = @array;
}

¿Es lo mismo? Bueno, quizás sí, y quizás no. La sutil diferencia es que cuando asignas algo entre corchetes, sabes con seguridad que siempre es una referencia nueva con una copia nueva de los datos. Algo diferente podría estar sucediendo en este nuevo caso con la desreferenciación "$AoA[$i]->@*" en el lado izquierdo de la asignación. Todo depende de si $AoA[$i] había sido indefinido para empezar, o si ya contenía una referencia. Si ya habías poblado @AoA con referencias, como en

$AoA[3] = \@another_array;

Entonces la asignación con la indirección en el lado izquierdo usaría la referencia existente que ya estaba allí:

$AoA[3]->@* = @array;

Por supuesto, esto tendría el efecto "interesante" de sobrescribir @another_array. (¿Alguna vez has notado cómo cuando un programador dice que algo es "interesante", en lugar de significar "intrigante", es inquietantemente más probable que signifique que es "molesto", "difícil", o ambos? :-)

Así que recuerda usar siempre los constructores de arrays o hashes con "[]" o "{}", y estarás bien, aunque no siempre sea óptimamente eficiente.

Sorprendentemente, la siguiente construcción de aspecto peligroso realmente funcionará bien:

for my $i (1..10) {
    my @array = somefunc($i);
    $AoA[$i] = \@array;
}

Si somefunc() devuelve algo que siempre se desborda fuera del búfer de memoria asignado, entonces las referencias que apuntan a ese lugar se desreferenciarán a sí mismas, ¡y todos apuntarán al mismo lugar!

¡Pero no siempre! Si somefunc() está programado de forma inteligente, podría devolver una referencia a un array recién asignado en cada llamada. ¡Y ese podría ser el caso de la forma en que está programado somefunc()! Entonces, ¡buena suerte!

La moral de la historia es que si quieres asegurarte de que tienes un nuevo array, obtén uno nuevo explícitamente. Es mejor ser seguro que lamentar.

Eso se debe a que my() es más una sentencia de tiempo de ejecución que una declaración en tiempo de compilación per se. Esto significa que la variable my() se recrea cada vez que se recorre el bucle. Así que, aunque parezca que almacenaste la misma referencia de variable cada vez, ¡en realidad no lo hiciste! Esta es una distinción sutil que puede producir código más eficiente a riesgo de engañar a todos menos a los programadores más experimentados. Por lo tanto, normalmente desaconsejo enseñárselo a los principiantes. De hecho, excepto para pasar argumentos a funciones, rara vez me gusta ver el operador de "dame una referencia" (barra invertida) usado mucho en el código. En cambio, aconsejo a los principiantes que ellos (y la mayoría del resto de nosotros) intenten usar los constructores mucho más fáciles de entender "[]" y "{}" en lugar de depender del alcance léxico (o dinámico) y el conteo de referencias oculto para hacer lo correcto tras bambalinas.

También tenga en cuenta que existe otra forma de escribir una desreferenciación. Estas dos líneas son equivalentes:

$AoA[$i]->@* = @array;
@{ $AoA[$i] } = @array;

La primera forma, llamada desreferenciación postfija, es generalmente más fácil de leer, porque la expresión se puede leer de izquierda a derecha, y no hay llaves de cierre que equilibrar. Por otro lado, también es más nueva. Se agregó al lenguaje en 2014, por lo que a menudo encontrará la otra forma, desreferenciación circumfija, en código más antiguo.

En resumen:

$AoA[$i] = [ @array ];     # generalmente mejor
$AoA[$i] = \@array;        # peligroso; ¿cómo es mi() ese array?
$AoA[$i]->@* = @array;     # demasiado complicado para la mayoría de los programadores
@{ $AoA[$i] } = @array;    # igual de complicado y también más difícil de leer

ADVERTENCIA SOBRE PRECEDENCIA

Hablando de cosas como "@{$AoA[$i]}", lo siguiente es en realidad lo mismo:

$aref->[2][2]       # claro
$$aref[2][2]        # confuso

Esto se debe a que las reglas de precedencia de Perl para sus cinco desreferenciadores prefijos (que parecen que alguien está maldiciendo: "$ @ * % &") los unen más fuertemente que los corchetes o llaves de subíndice postfijos. Esto sin duda será una gran sorpresa para el programador de C o C++, que está bastante acostumbrado a usar *a[i] para referirse a lo que apunta el elemento i de "a". Es decir, primero toman el subíndice y solo luego desreferencian lo que hay en ese subíndice. Eso está bien en C, pero esto no es C.

La construcción aparentemente equivalente en Perl, $$aref[$i], primero desreferencia $aref, lo que hace que tome $aref como una referencia a un array, y luego lo desreferencia, y finalmente le dice el valor i del array al que apunta $AoA. Si quisiera la noción de C, podría escribir "$AoA[$i]->$*" para desreferenciar explícitamente el elemento i, leyendo de izquierda a derecha.

POR QUÉ SIEMPRE DEBERÍA "use VERSION"

Si esto empieza a sonar más aterrador de lo que vale, relájese. Perl tiene algunas características para ayudarlo a evitar sus trampas más comunes. Una forma de evitar confundirse es comenzar cada programa con:

use strict;

De esta manera, se verá obligado a declarar todas sus variables con my() y también se prohibirá la "desreferenciación simbólica" accidental. Por lo tanto, si hubiera hecho esto:

my $aref = [
    [ "fred", "barney", "pebbles", "bambam", "dino", ],
    [ "homer", "bart", "marge", "maggie", ],
    [ "george", "jane", "elroy", "judy", ],
];
print $aref[2][2];

El compilador lo marcaría inmediatamente como un error en tiempo de compilación, porque accidentalmente estaba accediendo a @aref, una variable no declarada, y por lo tanto le recordaría que escribiera en su lugar:

print $aref->[2][2]

Desde la versión 5.12 de Perl, una declaración "use VERSION" también habilitará el pragma "strict". Además, también habilitará un paquete de características, que brindará más utilidades. Desde la versión 5.36 también habilitará el pragma "warnings". A menudo, la mejor manera de activar todas estas cosas a la vez es comenzar un archivo con:

use v5.36;

De esta manera, cada archivo comenzará con "strict", "warnings" y muchas características nombradas útiles activadas, así como varias características antiguas desactivadas (como "indirect"). Para obtener más información, consulte "use VERSION" en perlfunc.

EJEMPLOS DE CÓDIGO

Presentados con poco comentario aquí hay ejemplos de código cortos que ilustran el acceso a varios tipos de estructuras de datos.

ARRAYS DE ARRAYS

Declaración de un ARRAY DE ARRAYS

my @AoA = (
       [ "fred", "barney" ],
       [ "george", "jane", "elroy" ],
       [ "homer", "marge", "bart" ],
     );

Generación de un ARRAY DE ARRAYS

# leyendo desde archivo
while ( <> ) {
    push @AoA, [ split ];
}
# llamando a una función
for my $i ( 1 .. 10 ) {
    $AoA[$i] = [ somefunc($i) ];
}
# usando variables temporales
for my $i ( 1 .. 10 ) {
    my @tmp = somefunc($i);
    $AoA[$i] = [ @tmp ];
}
# añadir a una fila existente
push $AoA[0]->@*, "wilma", "betty";

Acceso e Impresión de un ARRAY DE ARRAYS

# un elemento
$AoA[0][0] = "Fred";
# otro elemento
$AoA[1][1] =~ s/(\w)/\u$1/;
# imprimir todo con referencias
for my $aref ( @AoA ) {
    print "\t [ @$aref ],\n";
}
# imprimir todo con índices
for my $i ( 0 .. $#AoA ) {
    print "\t [ $AoA[$i]->@* ],\n";
}
# imprimir todo uno a la vez
for my $i ( 0 .. $#AoA ) {
    for my $j ( 0 .. $AoA[$i]->$#* ) {
        print "elem en ($i, $j) es $AoA[$i][$j]\n";
    }
}

HASHES DE ARRAYS

Declaración de un HASH DE ARRAYS

my %HoA = (
       flintstones        => [ "fred", "barney" ],
       jetsons            => [ "george", "jane", "elroy" ],
       simpsons           => [ "homer", "marge", "bart" ],
     );

Generación de un HASH DE ARRAYS

# leyendo desde archivo
# flintstones: fred barney wilma dino
while ( <> ) {
    next unless s/^(.*?):\s*//;
    $HoA{$1} = [ split ];
}
# leyendo desde archivo; más temporales
# flintstones: fred barney wilma dino
while ( my $line = <> ) {
    my ($who, $rest) = split /:\s*/, $line, 2;
    my @fields = split ' ', $rest;
    $HoA{$who} = [ @fields ];
}
# llamando a una función que devuelve una lista
for my $group ( "simpsons", "jetsons", "flintstones" ) {
    $HoA{$group} = [ get_family($group) ];
}
# igualmente, pero usando temporales
for my $group ( "simpsons", "jetsons", "flintstones" ) {
    my @members = get_family($group);
    $HoA{$group} = [ @members ];
}
# añadir nuevos miembros a una familia existente
push $HoA{flintstones}->@*, "wilma", "betty";

Acceso e Impresión de un HASH DE ARRAYS

# un elemento
$HoA{flintstones}[0] = "Fred";
# otro elemento
$HoA{simpsons}[1] =~ s/(\w)/\u$1/;
# imprimir todo
foreach my $family ( keys %HoA ) {
    print "$family: $HoA{$family}->@* \n"
}
# imprimir todo con índices
foreach my $family ( keys %HoA ) {
    print "familia: ";
    foreach my $i ( 0 .. $HoA{$family}->$#* ) {
        print " $i = $HoA{$family}[$i]";
    }
    print "\n";
}
# imprimir todo ordenado por número de miembros
foreach my $family ( sort { $HoA{$b}->@* <=> $HoA{$a}->@* } keys %HoA ) {
    print "$family: $HoA{$family}->@* \n"
}
# imprimir todo ordenado por número de miembros y nombre
foreach my $family ( sort {
                           $HoA{$b}->@* <=> $HoA{$a}->@*
                                         ||
                                     $a cmp $b
           } keys %HoA )
{
    print "$family: ", join(", ", sort $HoA{$family}->@* ), "\n";
}
