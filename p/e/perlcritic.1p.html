PERLCRITIC(1p) Documentación Perl contribuida por el usuario PERLCRITIC(1p)

NOMBRE

"perlcritic" - Interfaz de línea de comandos para criticar código fuente Perl.

SINOPSIS

perlcritic [-12345 | --brutal | --cruel | --harsh | --stern | --gentle]
           [--severity number | name] [{-p | --profile} file | --noprofile]
           [--top [ number ]] [--theme expression] [--include pattern]
           [--exclude pattern] [{-s | --single-policy} pattern]
           [--only | --noonly] [--profile-strictness {warn|fatal|quiet}]
           [--force | --noforce] [--statistics] [--statistics-only]
           [--count | -C] [--verbose {number | format}] [--allow-unsafe]
           [--color | --nocolor] [--pager pager] [--quiet]
           [--color-severity-highest color_specification]
           [--color-severity-high color_specification]
           [--color-severity-medium color_specification]
           [--color-severity-low color_specification]
           [--color-severity-lowest color_specification]
           [--files-with-violations | -l]
           [--files-without-violations | -L]
           [--program-extensions file_name_extension]
           {FILE | DIRECTORY | STDIN}
perlcritic --profile-proto
perlcritic { --list | --list-enabled | --list-themes | --doc pattern [...] }
perlcritic { --help | --options | --man | --version }

DESCRIPCIÓN

"perlcritic" es un analizador de código fuente Perl. Es el frontend ejecutable del motor Perl::Critic, que intenta identificar construcciones incómodas, difíciles de leer, propensas a errores o poco convencionales en tu código. La mayoría de las reglas se basan en el libro de Damian Conway, Perl Best Practices. Sin embargo, "perlcritic" no se limita a hacer cumplir PBP, e incluso soportará reglas que contradigan a Conway. Todas las reglas pueden configurarse o deshabilitarse fácilmente a tu gusto.

Esta documentación solo cubre cómo usar esta línea de comandos. Para toda la demás información, como la referencia de la API y las interfaces alternativas, consulta la documentación de Perl::Critic en sí.

EJEMPLOS DE USO

Antes de entrar en todos los detalles escabrosos, aquí tienes algunos ejemplos de uso básicos para ayudarte a empezar.

# Reportar solo las violaciones más graves (severidad = 5)
perlcritic TuModulo.pm
# Lo mismo que lo anterior, pero leyendo la entrada desde STDIN
perlcritic
# Procesar recursivamente todos los archivos Perl en un directorio
perlcritic /alguna/directory
# Reportar violaciones ligeramente menos graves también (severidad >= 4)
perlcritic -4 TuModulo.pm
# Lo mismo que lo anterior, pero usando nivel de severidad con nombre
perlcritic --stern TuModulo.pm
# Reportar todas las violaciones, independientemente de la severidad (severidad >= 1)
perlcritic -1 TuModulo.pm
# Lo mismo que lo anterior, pero usando nivel de severidad con nombre
perlcritic --brutal TuModulo.pm
# Reportar solo violaciones de cosas de "Perl Best Practices"
perlcritic --theme pbp TuModulo.pm
# Reportar las 20 violaciones más graves (severidad >= 1)
perlcritic --top TuModulo.pm
# Reportar violaciones adicionales de Políticas que coincidan con m/variables/xms
perlcritic --include variables TuModulo.pm
# Usar valores predeterminados de algún lugar que no sea ~/.perlcriticrc
perlcritic --profile proyecto/especifico/perlcriticrc TuModulo.pm

ARGUMENTOS

Los argumentos son rutas a los archivos que deseas analizar. Puedes especificar varios archivos. Si un argumento es un directorio, "perlcritic" analizará todos los archivos Perl debajo del directorio. Si no se especifican argumentos, la entrada se lee desde STDIN.

OPCIONES

Los nombres de las opciones pueden abreviarse hasta la unicidad y pueden indicarse con guiones simples o dobles, y los valores de las opciones pueden separarse del nombre de la opción por un espacio o '=' (como con Getopt::Long). Los nombres de las opciones también distinguen entre mayúsculas y minúsculas.

"--profile FILE" o "-p FILE"
Indica a "perlcritic" que use un perfil nombrado por FILE en lugar de buscar el archivo predeterminado .perlcriticrc en el directorio actual o en tu directorio personal. Consulta "CONFIGURACIÓN" en Perl::Critic para más información.
"--noprofile"
Indica a "perlcritic" que no cargue ningún archivo de configuración, revirtiendo así a la configuración predeterminada para todas las Políticas.
"--severity N"
Indica a "perlcritic" que aplique solo Políticas con una severidad mayor que "N". Los valores de severidad son enteros que van de 1 (menos severo) a 5 (más severo). El valor predeterminado es 5. Para un "--profile" dado, disminuir la "--severity" generalmente producirá más violaciones. Puedes establecer el valor predeterminado para esta opción en tu archivo .perlcriticrc. También puedes redefinir la "severity" de cualquier Política en tu archivo .perlcriticrc. Consulta "CONFIGURACIÓN" para más información.
"-5 | -4 | -3 | -2 | -1"
Estos son atajos numéricos para establecer la opción "--severity". Por ejemplo, "-4" es equivalente a "--severity 4". Si se especifican varios atajos, el más restrictivo prevalece. Si también se proporciona una opción explícita "--severity", todos los atajos se ignoran silenciosamente. NOTA: Ten cuidado de no colocar una de las opciones atajo de severidad numérica inmediatamente después del indicador "--top" o "perlcritic" la interpretará como el número de violaciones a reportar.
"--severity NAME"
Si te resulta difícil recordar si la severidad "5" es el nivel más o menos restrictivo, entonces puedes usar uno de estos valores con nombre: 
NOMBRE DE SEVERIDAD   ...es equivalente a...   NÚMERO DE SEVERIDAD
--------------------------------------------------------
--severity gentle                           --severity 5
--severity stern                            --severity 4
--severity harsh                            --severity 3
--severity cruel                            --severity 2
--severity brutal                           --severity 1
"--gentle | --stern | --harsh | --cruel | --brutal"
Estos son atajos con nombre para establecer la opción "--severity". Por ejemplo, "--cruel" es equivalente a "--severity 2". Si se especifican varios atajos, el más restrictivo prevalece. Si también se proporciona una opción explícita "--severity", todos los atajos se ignoran silenciosamente.
"--theme RULE"
Indica a "perlcritic" que aplique solo Políticas con temas que satisfagan la "RULE". Los temas son nombres arbitrarios para grupos de políticas relacionadas. Puedes combinar nombres de temas con operadores booleanos para crear una "RULE" arbitrariamente compleja. Por ejemplo, lo siguiente aplicaría solo las Políticas que tengan un tema de 'bugs' Y 'pbp': 
$> perlcritic --theme='bugs && pbp' MiModulo.pm

A menos que la opción "--severity" se proporcione explícitamente, establecer "--theme" hace que la "--severity" se establezca silenciosamente en 1. Puedes establecer el valor predeterminado para esta opción en tu archivo .perlcriticrc. Consulta "TEMAS DE POLÍTICAS" en Perl::Critic para más información sobre temas.

"--include PATTERN"
Indica a "perlcritic" que aplique Políticas adicionales que coincidan con la expresión regular "/PATTERN/imx". Usa esta opción para anular temporalmente tu perfil y/o la configuración de severidad en la línea de comandos. Por ejemplo: 
perlcritic --include=layout mi_archivo.pl

Esto haría que "perlcritic" aplicara todas las políticas de "CodeLayout::*" incluso si tienen un nivel de severidad menor que el nivel predeterminado de 5, o han sido deshabilitadas en tu archivo .perlcriticrc. Puedes especificar múltiples opciones "--include" y puedes usarla en conjunción con la opción "--exclude". Ten en cuenta que "--exclude" tiene precedencia sobre "--include" cuando una Política coincide con ambos patrones. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc.

"--exclude PATTERN"
Indica a "perlcritic" que no aplique ninguna Política que coincida con la expresión regular "/PATTERN/imx". Utilice esta opción para anular temporalmente su perfil y/o la configuración de severidad en la línea de comandos. Por ejemplo: 
perlcritic --exclude=strict mi_archivo.pl

Esto haría que "perlcritic" no aplicara las Políticas "RequireUseStrict" y "ProhibitNoStrict" aunque tengan el nivel de severidad más alto. Puede especificar varias opciones "--exclude" y puede usarla en conjunto con la opción "--include". Tenga en cuenta que "--exclude" tiene precedencia sobre "--include" cuando una Política coincide con ambos patrones. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc.

"--single-policy PATTERN" o "-s PATTERN"
Indica a "perlcritic" que aplique solo un módulo de Política que coincida con la expresión regular "/PATTERN/ixms", y excluya todas las demás Políticas. Esta opción tiene precedencia sobre las opciones "--severity", "--theme", "--include", "--exclude" y "--only". Por ejemplo: 
perlcritic --single-policy=nowarnings mi_archivo.pl

Esto haría que "perlcritic" aplicara solo la Política "ProhibitNoWarnings", independientemente del nivel de severidad establecido. No se aplicarían otras Políticas.

Esto es equivalente a lo que uno podría pretender con...

perlcritic --exclude=. --include=nowarnings mi_archivo.pl

... pero esto no funcionará porque la opción "--exclude" anula la opción "--include".

El equivalente de esta opción se puede lograr creando un perfil personalizado que contenga solo la política deseada y luego ejecutando...

perlcritic --profile=perfilpersonalizado --only mi_archivo.pl
"--top [ N ]"
Indica a "perlcritic" que reporte solo las N principales violaciones de Política en cada archivo, clasificadas por su severidad. Si no se especifica "N", el valor predeterminado es 20. Si la opción "--severity" (o uno de sus atajos) no se especifica explícitamente, la opción "--top" implica que el nivel mínimo de severidad es "1" (es decir, "brutal"). Los usuarios pueden redefinir la severidad de cualquier Política en su archivo .perlcriticrc. Consulte "CONFIGURACIÓN" para obtener más información. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc. NOTA: Tenga cuidado de no colocar una de las opciones de atajo de severidad inmediatamente después del indicador "--top" o "perlcritic" la interpretará como el número de violaciones a reportar.
"--force"
Indica a "perlcritic" que ignore las anotaciones mágicas "## no critic" en el código fuente. Consulte "DOBLANDO LAS REGLAS" para obtener más información. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc.
"--statistics"
Provoca que se reporten varias estadísticas sobre el código que se está escaneando y las violaciones encontradas después de cualquier otra salida.
"--statistics-only"
Al igual que la opción "--statistics", pero suprime la salida normal y solo muestra las estadísticas.
"--verbose N | FORMAT"
Establece el nivel de verbosidad o el formato para reportar violaciones. Si se le da un número ("N"), "perlcritic" reporta violaciones usando uno de los formatos predefinidos descritos a continuación. Si se le da una cadena ("FORMAT"), se interpreta como una especificación de formato real. Si no se especifica la opción "--verbose", el valor predeterminado es 4 o 5, dependiendo de si se proporcionaron varios archivos como argumentos a "perlcritic". Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc. 
Verbosidad     Especificación del formato
-----------   -------------------------------------------------------
 1            "%f:%l:%c:%m\n",
 2            "%f: (%l:%c) %m\n",
 3            "%m en %f línea %l\n",
 4            "%m en línea %l, columna %c.  %e.  (Severidad: %s)\n",
 5            "%f: %m en línea %l, columna %c.  %e.  (Severidad: %s)\n",
 6            "%m en línea %l, cerca de '%r'.  (Severidad: %s)\n",
 7            "%f: %m en línea %l cerca de '%r'.  (Severidad: %s)\n",
 8            "[%p] %m en línea %l, columna %c.  (Severidad: %s)\n",
 9            "[%p] %m en línea %l, cerca de '%r'.  (Severidad: %s)\n",
10            "%m en línea %l, columna %c.\n  %p (Severidad: %s)\n%d\n",
11            "%m en línea %l, cerca de '%r'.\n  %p (Severidad: %s)\n%d\n"

Los formatos son una combinación de caracteres literales y de escape similar a la forma en que funciona "sprintf". Consulte String::Format para una explicación completa de las capacidades de formato. Los caracteres de escape válidos son:

Escape    Significado
-------   ------------------------------------------------------------
%c        Número de columna donde ocurrió la violación
%d        Discusión diagnóstica completa de la violación
%e        Explicación de la violación o números de página en PBP
%F        Solo el nombre del archivo donde ocurrió la violación.
%f        Ruta al archivo donde ocurrió la violación.
%l        Número de línea donde ocurrió la violación
%m        Breve descripción de la violación
%P        Nombre completo del módulo de Política que creó la violación
%p        Nombre de la Política sin el prefijo Perl::Critic::Policy::
%r        La cadena de código fuente que causó la violación
%C        La clase del elemento PPI::Element que causó la violación
%s        El nivel de severidad de la violación

El propósito de estos formatos es proporcionar cierta compatibilidad con editores de texto que tienen una interfaz para analizar ciertos tipos de entrada. Consulte "INTEGRACIÓN CON EDITORES" para obtener más información al respecto.

"--list"
Muestra una lista condensada de todos los módulos de Política de Perl::Critic:: que se encuentran en esta máquina. Esta opción lista *todas* las Políticas, independientemente de su .perlcriticrc o las opciones de línea de comandos. Para cada Política, se muestran el nombre, la severidad predeterminada y los temas predeterminados.
"--list-enabled"
Muestra una lista condensada de todos los módulos de Política de Perl::Critic:: que *se aplicarían*, si realmente fuera a criticar un archivo con este comando. Esto es útil cuando ha construido un comando complicado o ha modificado su archivo .perlcriticrc y desea ver exactamente qué Políticas se van a aplicar (o no aplicar, según sea el caso). Para cada Política, se muestran el nombre, la severidad predeterminada y los temas predeterminados.
"--list-themes"
Muestra una lista de todos los temas de los módulos de Política de Perl::Critic:: que se encuentran en esta máquina.
"--profile-proto"
Muestra una lista ampliada de todos los módulos de Política de Perl::Critic:: que se encuentran en esta máquina. Para cada Política, se muestran el nombre, la severidad predeterminada y los temas predeterminados, así como el nombre de cualquier parámetro adicional que la Política admita. El formato es adecuado como prototipo para su archivo .perlcriticrc.
"--only"
Indica a perlcritic que aplique solo las Políticas que se mencionan explícitamente en su archivo .perlcriticrc. Esto es útil si desea utilizar solo un pequeño subconjunto de Políticas sin tener que deshabilitar todas las demás. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc.
"--profile-strictness {warn|fatal|quiet}"
Indica a perlcritic cómo tratar ciertos problemas recuperables encontrados en un archivo .perlcriticrc o especificado a través de la opción "--profile". Los valores válidos son "warn" (el predeterminado), "fatal" y "quiet". Por ejemplo, perlcritic normalmente solo advierte sobre perfiles que hacen referencia a Políticas inexistentes, pero esta opción puede hacer que esta situación sea fatal. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc.
"--count"
"-C"
Muestra solo el número de violaciones para cada archivo. Utilice esta función para obtener una idea rápida de dónde una gran cantidad de código podría necesitar la mayor atención.
"--color"
"--colour"
Esta opción está activada cuando se genera la salida a una tty. Cuando está activada, las severidades 5 y 4 se colorean de rojo y amarillo, respectivamente. La colorización solo ocurre si Term::ANSIColor está instalado. Para entornos Windows, también debe estar instalado Win32::Console::ANSI. Niega este interruptor para deshabilitar el color. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc.
"--pager PAGER_COMMAND_STRING"
Si se establece, perlcritic canalizará su salida al PAGER_COMMAND_STRING dado. Puede establecer el valor predeterminado para esta opción en su archivo .perlcriticrc.

Establecer un paginador desactiva el color por defecto. Tendrás que activar explícitamente el color. Si quieres color, probablemente también querrás decirle a tu paginador que muestre caracteres sin procesar. Para "less" y "more", usa el interruptor -R.

"--color-severity-highest ESPECIFICACION_DE_COLOR"
Especifica el color a usar para las violaciones de mayor severidad, como una especificación de color de Term::ANSIColor. También se puede especificar como "--colour- severity-highest", "--color-severity-5" o "--colour-severity-5".
"--color-severity-high ESPECIFICACION_DE_COLOR"
Especifica el color a usar para las violaciones de alta severidad, como una especificación de color de Term::ANSIColor.

OPTIONS

"--color-severity-high COLOR_SPECIFICATION"
Especifica el color a utilizar para las violaciones de alta severidad, como una especificación de color de Term::ANSIColor. También se puede especificar como "--colour- severity-high", "--color-severity-4", o "--colour-severity-4".
"--color-severity-medium COLOR_SPECIFICATION"
Especifica el color a utilizar para las violaciones de severidad media, como una especificación de color de Term::ANSIColor. También se puede especificar como "--colour- severity-medium", "--color-severity-3", o "--colour-severity-3".
"--color-severity-low COLOR_SPECIFICATION"
Especifica el color a utilizar para las violaciones de baja severidad, como una especificación de color de Term::ANSIColor. También se puede especificar como "--colour- severity-low", "--color-severity-2", o "--colour-severity-2".
"--color-severity-lowest COLOR_SPECIFICATION"
Especifica el color a utilizar para las violaciones de menor severidad, como una especificación de color de Term::ANSIColor. También se puede especificar como "--colour- severity-lowest", "--color-severity-1", o "--colour-severity-1".
"--files-with-violations"
Muestra solo los nombres de los archivos con violaciones. Utilice esta característica con --single-policy para encontrar archivos que contengan violaciones de una política dada. También se puede especificar como "--l".
"--files-without-violations"
Muestra solo los nombres de los archivos sin violaciones. Utilice esta característica con --single-policy para encontrar archivos que no contengan violaciones de una política dada. También se puede especificar como "--L".
"--program-extensions file_name_extension"
Indica a "perlcritic" que trate los archivos cuyos nombres terminan en la extensión de nombre de archivo dada como programas, no como módulos. Si se desea un punto inicial ('.') este debe especificarse explícitamente, por ejemplo: 
--program-extensions .pl

La coincidencia distingue mayúsculas y minúsculas, y la opción puede especificarse tantas veces como se desee, por ejemplo:

--program-extensions .pl --program-extensions .cgi

Lo anterior también se puede hacer entrecomillando las extensiones de nombre de archivo:

--program-extensions '.pl .cgi'

Los archivos cuyos nombres terminan en '.PL' siempre se considerarán programas.

"--doc PATTERN"
Muestra la documentación de todos los módulos Perl::Critic::Policy que coinciden con "m/PATTERN/ixms". Dado que los módulos de Política tienden a tener nombres bastante largos, esto simplemente proporciona una forma más conveniente de escribir algo como: "perldoc Perl::Critic::Policy::ValuesAndExpressions::RequireUpperCaseHeredocTerminator" en la línea de comandos.
"--allow-unsafe"
Esta opción indica a "perlcritic" que permita el uso de Políticas que han sido marcadas como "inseguras". Las Políticas inseguras pueden resultar en operaciones arriesgadas al compilar y ejecutar el código que analizan. Todas las Políticas que se distribuyen en el núcleo de la distribución de Perl::Critic son seguras. Sin embargo, las Políticas de terceros, como las de la distribución Perl::Critic::Dynamic, pueden no serlo. Tenga en cuenta que la "seguridad" es honorífica: si un autor de Políticas marca una Política como segura, no es una garantía de que no hará cosas desagradables. Si no confía en sus Políticas y en el código que está analizando, no utilice este interruptor.
"--quiet"
Suprime el mensaje "source OK" cuando no se encuentran violaciones.
"--help"
"-?"
"-H"
Muestra un breve resumen de las opciones y sale.
"--options"
Muestra las descripciones de las opciones y sale. Si bien esta salida es larga, no se acerca en absoluto a la longitud de la salida de "--man".
"--man"
Muestra el manual completo de "perlcritic" y sale.
"--version"
Muestra el número de versión de "perlcritic" y sale.

CONFIGURACIÓN

La mayoría de la configuración de Perl::Critic y de cada uno de los módulos de Política se puede controlar mediante un archivo de configuración. El archivo de configuración predeterminado se llama .perlcriticrc. "perlcritic" buscará este archivo en el directorio actual primero, y luego en su directorio de inicio. Alternativamente, puede establecer la variable de entorno "PERLCRITIC" para apuntar explícitamente a un archivo diferente en otra ubicación. Si ninguno de estos archivos existe, y la opción "--profile" no se proporciona en la línea de comandos, entonces todas las Políticas se cargarán con su configuración predeterminada.

El formato del archivo de configuración es una serie de bloques estilo INI que contienen pares clave-valor separados por "=". Los comentarios deben comenzar con "#" y pueden colocarse en una línea separada o después de los pares nombre-valor si lo desea.

Los ajustes predeterminados para perlcritic en sí se pueden establecer antes del primer bloque con nombre. Por ejemplo, colocar cualquiera o todos los siguientes en la parte superior de su archivo .perlcriticrc establecerá el valor predeterminado para el argumento de línea de comandos correspondiente.

severity  = 3                                     # Entero o nivel nombrado
only      = 1                                     # Cero o Uno
force     = 0                                     # Cero o Uno
verbose   = 4                                     # Entero o especificador de formato
top       = 50                                    # Un entero positivo
theme     = (pbp + security) * bugs               # Una expresión temática
include   = NamingConventions ClassHierarchies    # Lista separada por espacios
exclude   = Variables  Modules::RequirePackage    # Lista separada por espacios

El resto del archivo de configuración es una serie de bloques como esta:

[Perl::Critic::Policy::Category::PolicyName]
severity = 1
set_themes = foo bar
add_themes = baz
arg1 = value1
arg2 = value2

"Perl::Critic::Policy::Category::PolicyName" es el nombre completo de un módulo que implementa la política. Los módulos de Política distribuidos con Perl::Critic se han agrupado en categorías según la tabla de contenido del libro de Damian Conway, Perl Best Practices. Para abreviar, puede omitir la parte 'Perl::Critic::Policy' del nombre del módulo.

"severity" es el nivel de importancia que desea asignar a la Política. Todos los módulos de Política se definen con un valor de severidad predeterminado que oscila entre 1 (menos severo) y 5 (más severo). Sin embargo, puede no estar de acuerdo con la severidad predeterminada y optar por asignarle una severidad mayor o menor, según su propia filosofía de codificación. Puede establecer la "severity" en un entero de 1 a 5, o usar uno de los nombres equivalentes:

NOMBRE DE SEVERIDAD ...es equivalente a... NÚMERO DE SEVERIDAD
----------------------------------------------------
gentle                                             5
stern                                              4
harsh                                              3
cruel                                              2
brutal                                             1

"set_themes" establece el tema para la Política y anula su tema predeterminado. El argumento es una cadena de una o más palabras separadas por espacios en blanco. Los temas no distinguen entre mayúsculas y minúsculas. Consulte "TEMAS DE POLÍTICA" para obtener más información.

"add_themes" agrega temas a los temas predeterminados para esta Política. El argumento es una cadena de una o más palabras separadas por espacios en blanco. Los temas no distinguen entre mayúsculas y minúsculas. Consulte "TEMAS DE POLÍTICA" para obtener más información.

Los pares clave-valor restantes son parámetros de configuración que se pasarán al constructor de esa Política. Los constructores de la mayoría de los módulos de Política no admiten argumentos, y aquellos que lo hacen deben tener valores predeterminados razonables. Consulte la documentación del módulo de Política apropiado para obtener más detalles.

En lugar de redefinir la severidad para una Política dada, puede deshabilitar completamente una Política anteponiendo un '-' al nombre del módulo en su archivo de configuración. De esta manera, la Política nunca se cargará, independientemente de la "--severity" dada en la línea de comandos.

Una configuración simple podría verse así:

#--------------------------------------------------------------
# Creo que son muy importantes, así que cárgalas siempre
[TestingAndDebugging::RequireUseStrict]
severity = 5
[TestingAndDebugging::RequireUseWarnings]
severity = 5
#--------------------------------------------------------------
# Creo que son menos importantes, así que cárgalas solo cuando se solicite
[Variables::ProhibitPackageVars]
severity = 2
[ControlStructures::ProhibitPostfixControls]
allow = if unless  # Mi configuración personalizada
severity = cruel   # Lo mismo que "severity = 2"
#--------------------------------------------------------------
# Dales a estas políticas un tema personalizado. Puedo activar solo
# estas políticas diciendo "perlcritic --theme 'larry || curly'"
[Modules::RequireFilenameMatchesPackage]
add_themes = larry
[TestingAndDebugging::RequireTestLabels]
add_themes = curly moe
#--------------------------------------------------------------
# No estoy de acuerdo con estas en absoluto, así que nunca las cargues
[-NamingConventions::Capitalization]
[-ValuesAndExpressions::ProhibitMagicNumbers]
#--------------------------------------------------------------
# Para todas las demás Políticas, acepto la severidad predeterminada,
# por lo que no se requiere configuración adicional para ellas.

Tenga en cuenta que todas las políticas incluidas con la distribución de Perl::Critic que tienen parámetros enteros aceptan guiones bajos ('_') en sus valores, como con los literales numéricos de Perl. Por ejemplo,

[ValuesAndExpressions::RequireNumberSeparators]
min_value = 1_000

Para obtener ejemplos de configuración adicionales, consulte el archivo perlcriticrc que se incluye en este directorio examples de esta distribución.

TEMAS DE POLÍTICAS

Cada política se define con uno o más "temas". Los temas se pueden utilizar para crear grupos arbitrarios de políticas. Su objetivo es proporcionar un mecanismo alternativo para seleccionar su conjunto preferido de políticas. Por ejemplo, es posible que desee deshabilitar un conjunto específico de políticas al analizar programas de prueba. Por el contrario, es posible que desee habilitar solo un subconjunto específico de políticas al analizar módulos.

Las políticas que se distribuyen con Perl::Critic se han dividido en los siguientes temas. Este es solo nuestro intento de proporcionar algunas agrupaciones lógicas básicas. Puede inventar nuevos temas que se adapten a sus necesidades.

TEMA             DESCRIPCIÓN
------------------------------------------------------------------------
core              Todas las políticas que se distribuyen con Perl::Critic
pbp               Políticas que provienen directamente de "Perl Best Practices"
bugs              Políticas que previenen o revelan errores
certrec           Políticas que CERT recomienda
certrule          Políticas que CERT considera reglas
maintenance       Políticas que afectan la salud a largo plazo del código
cosmetic          Políticas que solo tienen un efecto superficial
complexity        Políticas que se relacionan específicamente con la complejidad del código
security          Políticas que se relacionan con problemas de seguridad
tests             Políticas específicas para programas de prueba

Diga "perlcritic --list" para obtener una lista de todas las políticas disponibles y los temas asociados a cada una. También puede cambiar el tema de cualquier política en su archivo .perlcriticrc. Consulte la sección "CONFIGURACIÓN" para obtener más información al respecto.

Utilizando la opción de línea de comandos "--theme", puede crear una regla arbitrariamente compleja que determine qué políticas aplicar. La precedencia es la misma que en el código Perl normal, y también puede usar paréntesis para forzar la precedencia. Los operadores admitidos son:

Operador    Alternativa    Ejemplo
-----------------------------------------------------------------
&&          and            'pbp && core'
||          or             'pbp || (bugs && security)'
!           not            'pbp && ! (portability || complexity)'

Los nombres de los temas no distinguen entre mayúsculas y minúsculas. Si "--theme" se establece en una cadena vacía, entonces evalúa como verdadero para todas las políticas.

DOBLANDO LAS REGLAS

Perl::Critic adopta un enfoque inflexible con su código: o cumple o no cumple. En el mundo real, no siempre es práctico (o incluso posible) cumplir plenamente con los estándares de codificación. En tales casos, es prudente demostrar que viola conscientemente los estándares y que tiene una Muy Buena Razón (DGR) para hacerlo.

Para ayudar en esas situaciones, puede indicar a Perl::Critic que ignore ciertas líneas o bloques de código utilizando anotaciones:

require 'LegacyLibaray1.pl';  ## no critic
require 'LegacyLibrary2.pl';  ## no critic
for my $element (@list) {
    ## no critic
    $foo = "";               # Viola 'ProhibitEmptyQuotes'
    $barf = bar() if $foo;   # Viola 'ProhibitPostfixControls'
    # Algo más de código malvado...
    ## use critic
    # Algo de código bueno...
    do_something($_);
}

Las anotaciones "## no critic" indican a Perl::Critic que ignore el resto de las líneas de código hasta que se encuentre una anotación "## use critic". Si la anotación "## no critic" está en la misma línea que una instrucción de código, entonces solo se pasa por alto esa línea de código. Para indicar a perlcritic que ignore las anotaciones "## no critic", utilice la opción "--force".

Una anotación "## no critic" desnuda deshabilita todas las políticas activas. Si desea deshabilitar políticas específicas, agregue una lista de nombres de políticas como argumentos, tal como lo haría para la pragmática "no strict" o "no warnings". Por ejemplo, esto deshabilitaría las políticas "ProhibitEmptyQuotes" y "ProhibitPostfixControls" hasta el final del bloque o hasta la próxima anotación "## use critic" (lo que ocurra primero):

## no critic (EmptyQuotes, PostfixControls);
# Ahora exento de ValuesAndExpressions::ProhibitEmptyQuotes
$foo = "";
# Ahora exento de ControlStructures::ProhibitPostfixControls
$barf = bar() if $foo;
# Todavía sujeto a ValuesAndExpression::RequireNumberSeparators
$long_int = 10000000000;

Dado que los nombres de las políticas se comparan con los argumentos de "## no critic" como expresiones regulares, puede abreviar los nombres de las políticas o deshabilitar una familia completa de políticas de una vez, así:

## no critic (NamingConventions)
# Ahora exento de NamingConventions::Capitalization
my $camelHumpVar = 'foo';
# Ahora exento de NamingConventions::Capitalization
sub camelHumpSub {}

La lista de argumentos debe ir entre paréntesis y debe contener uno o más barewords separados por comas (es decir, no use comillas). Las anotaciones "## no critic" pueden anidarse, y las políticas nombradas por una anotación interna se deshabilitarán junto con las que ya estén deshabilitadas por una anotación externa.

Algunas políticas como "Subroutines::ProhibitExcessComplexity" se aplican a todo un bloque de código. En esos casos, "## no critic" debe aparecer en la línea donde se informa la violación. Por ejemplo:

sub complicated_function {  ## no critic (ProhibitExcessComplexity)
    # Su código aquí...
}

Algunas políticas como "Documentation::RequirePodSections" se aplican a todo el documento, en cuyo caso las violaciones se informan en la línea 1. Pero si el archivo requiere una línea shebang, es imposible colocar "## no critic" en la primera línea del archivo. Esta es una limitación conocida y se abordará en una futura versión. Como solución alternativa, puede deshabilitar las políticas afectadas en la línea de comandos o en su archivo .perlcriticrc. Pero tenga en cuenta que esto afectará el análisis de **todos** los archivos.

Utilice esta función con prudencia. "## no critic" debe usarse en el alcance más pequeño posible, o solo en líneas de código individuales. Y siempre debe ser lo más específico posible sobre qué políticas desea deshabilitar (es decir, nunca use un "## no critic" desnudo). Si Perl::Critic se queja de su código, intente encontrar una solución compatible antes de recurrir a esta función.

NOMBRE

perlcritic - Analiza código Perl para detectar violaciones de las mejores prácticas.

SINOPSIS

 perlcritic [OPCIONES] Archivo ...

DESCRIPCIÓN

El script perlcritic lee uno o más archivos de código fuente Perl, los analiza para detectar violaciones de las políticas (best practices) y reporta cualquier violación encontrada a STDERR.

Perl::Critic está diseñado para ser muy configurable. Puedes personalizar qué políticas se ejecutan, cómo se ejecutan, cómo se reportan los problemas y dónde se encuentran las políticas. Consulta la sección CONFIGURATION para más detalles.

EJEMPLOS DE USO

Analizar un único archivo:
perlcritic foo.pl
Analizar varios archivos:
perlcritic foo.pl bar.pl baz.pl
Analizar todos los archivos Perl en el directorio actual:
perlcritic **/*.pl
Analizar todos los archivos Perl en el directorio actual y subdirectorios:
perlcritic -s **/*.pl
Analizar un archivo y suprimir los informes de violaciones de políticas:
perlcritic --quiet foo.pl
Analizar un archivo y exigir que se ejecute una política específica:
perlcritic --policy Module::Implement::OnlyTested Sub::RequireArgs foo.pl
Analizar un archivo y no reportar violaciones de políticas que ya han sido reportadas:
perlcritic --no-violations-just-errors foo.pl
Analizar un archivo e instalar una política personalizada desde un archivo:
perlcritic --load-criticize=MiPolitica=./MiPolitica.pm foo.pl

ARGUMENTOS

Se espera que perlcritic sea invocado con uno o más nombres de archivo o directorios como argumentos. Si se especifica un directorio, todos los archivos Perl dentro de ese directorio serán analizados.

OPCIONES

Las siguientes opciones están disponibles:

--source
Leer el código fuente Perl desde STDIN.
-s, --search-dirs
Buscar recursivamente en subdirectorios los archivos Perl.
-p, --policy POLÍTICAS
Solo ejecutar las políticas especificadas. Puede especificar múltiples políticas separadas por comas. Por ejemplo: -p Module::Implement::OnlyTested,Sub::RequireArgs.
-P, --exclude-policy POLÍTICAS
Excluir las políticas especificadas. Por ejemplo: -P Pod::PodMinimumLineLength,Code::Indent.
-C, --custom-policy RUTAS_A_POLÍTICAS
Especificar las rutas a directorios o archivos que contienen políticas personalizadas. Puede especificar múltiples rutas separadas por comas.
-a, --all-policies
Ejecutar todas las políticas disponibles, incluidas aquellas que están excluidas por defecto.
-q, --quiet
Suprimir los informes de violaciones de políticas. Solo se informarán los errores del propio analizador.
--no-violations-just-errors
Similar a --quiet, pero se reportarán las violaciones de políticas si no hay errores en el análisis.
-e, --exclude PATRÓN
Excluir archivos que coincidan con el patrón especificado. El patrón se aplica a la ruta completa del archivo. Por ejemplo: -e "t/.*\.pl" para excluir los archivos en el directorio t/.
-l, --linting-mode
Analizar solo los archivos que han sido modificados desde la última ejecución. Esto requiere un archivo de estado, que por defecto se encuentra en .perlcriticstate.
--set-state-file ARCHIVO_ESTADO
Especificar un archivo de estado diferente para el modo de análisis (--linting-mode).
--color [ COLOR ]
Habilitar la salida con color. Si se especifica un valor, se espera que sea el nombre de un tema de color. Si no se especifica, se utilizará el tema por defecto.
--no-color
Deshabilitar la salida con color.
-t, --theme TEMA
Cargar un tema de políticas con el nombre especificado. Por ejemplo: -t strict.
-d, --dump-config
Imprimir el archivo de configuración actual y salir.
-h, --help
Mostrar el mensaje de ayuda y salir.
-v, --version
Mostrar la versión de Perl::Critic y salir.

CONFIGURACIÓN

Perl::Critic se puede configurar de varias maneras:

Archivos de Configuración

Perl::Critic busca archivos de configuración en los siguientes lugares, en orden:

  1. Un archivo especificado con la opción --config-file.
  2. Un archivo llamado .perlcriticrc en el directorio actual.
  3. Un archivo llamado .perlcriticrc en el directorio principal del usuario.
  4. Un archivo llamado perlcriticrc en el directorio principal del usuario.
  5. Un archivo llamado perlcritic.rc en el directorio principal del usuario.
  6. Un archivo llamado ~/.config/perl-critic/perlcriticrc.
  7. Un archivo llamado /etc/perlcriticrc.

Los archivos de configuración pueden contener directivas para establecer políticas, excluir políticas, cargar temas, etc. Por ejemplo:

 policy = Module::Implement::OnlyTested
 exclude_policy = Pod::PodMinimumLineLength
 theme = strict
Variables de Entorno

Se pueden establecer algunas opciones a través de variables de entorno:

PERLCRITIC_CONFIG_FILE
Especifica la ruta a un archivo de configuración.
PERLCRITIC_POLICY
Lista separada por comas de políticas a ejecutar.
PERLCRITIC_EXCLUDE_POLICY
Lista separada por comas de políticas a excluir.
PERLCRITIC_THEME
Especifica el nombre de un tema de políticas.
PERLCRITIC_COLOR
Habilita la salida con color.
Perl::Critic::Policy

Puedes crear tus propias políticas creando una clase que herede de Perl::Critic::Policy.

Perl::Critic::Theme

Puedes agrupar políticas en temas creando una clase que herede de Perl::Critic::Theme.

LAS POLÍTICAS

Perl::Critic viene con una serie de políticas predeterminadas que cubren una amplia gama de las mejores prácticas de codificación Perl. Algunas de las políticas más comunes incluyen:

  • Input::Whitespace: Verifica el espaciado inconsistente.
  • NamingConventions::ProhibitMixedCaseSubs: Prohíbe nombres de subrutinas mixtos.
  • Sub::RequireArgition: Exige argumentos para las subrutinas.
  • Sub::UnderscoreInMethodNames: Exige que los nombres de métodos no contengan guiones bajos.
  • Values::RequireDecimalSeparator: Exige un separador decimal en los números.
  • Code::Indent: Verifica la indentación del código.
  • Module::RequireExplicitPackage: Exige una declaración package explícita.
  • Module::UseStrict: Exige el uso de use strict;.
  • Module::UseWarnings: Exige el uso de use warnings;.
  • Readonly::ProhibitReadonly: Prohíbe el uso de variables readonly.
  • Security::Y2038: Advierte sobre posibles problemas con el año 2038.
  • Syntax::RequireOpeningBraceOnNextLine: Exige que la llave de apertura esté en la siguiente línea.
  • Syntax::RequireSemicolonAfterControlStructure: Exige un punto y coma después de las estructuras de control.

Puedes ver una lista completa de las políticas instaladas ejecutando perlcritic --dump-config o consultando la documentación de cada política.

TEMAS DE POLÍTICAS

Los temas son colecciones predefinidas de políticas que puedes cargar fácilmente con la opción -t o --theme. Los temas disponibles pueden variar según la instalación, pero algunos comunes incluyen:

strict
Incluye políticas que imponen el uso estricto de Perl (por ejemplo, use strict; y use warnings;).
more
Incluye un conjunto más amplio de políticas, a menudo más restrictivas que el conjunto predeterminado.
lax
Incluye políticas menos restrictivas, permitiendo un estilo de codificación más flexible.
progressive
Un tema diseñado para ayudar a los programadores de Perl a aprender mejores prácticas gradualmente.

DOBLANDO LAS REGLAS

Si necesitas anular una política para un archivo específico o para toda la sesión, puedes hacerlo en tu archivo de configuración. Por ejemplo, para anular la política Pod::PodMinimumLineLength y establecerla en false (es decir, desactivarla):

 exclude_policy = Pod::PodMinimumLineLength

También puedes establecer el nivel de severidad de una política. Por defecto, todas las políticas tienen una severidad de 5 (el valor más alto). Puedes reducirlo para que las violaciones de ciertas políticas no se consideren tan críticas.

 policy_severity = Pod::PodMinimumLineLength=2

Para obtener más información sobre cómo doblar las reglas, consulta la documentación de Perl::Critic.

ESTADO DE SALIDA

Si "perlcritic" tiene algún error por sí mismo, sale con el estado == 1. Si no hay errores, pero "perlcritic" encuentra violaciones de políticas en tu código fuente, sale con el estado == 2. Si no hubo errores y no se encontraron violaciones, sale con el estado == 0.

LA FILOSOFÍA DE Perl::Critic

Los estándares de codificación son profundamente personales y altamente subjetivos. El objetivo de Perl::Critic es ayudarte a escribir código que se ajuste a un conjunto de mejores prácticas. Nuestro objetivo principal no es dictar cuáles son esas prácticas, sino implementar las prácticas descubiertas por otros. En última instancia, tú creas las reglas; Perl::Critic es simplemente una herramienta para fomentar la consistencia. Si hay una política que crees que es importante o que hemos pasado por alto, estaríamos muy agradecidos por tus contribuciones, o simplemente puedes cargar tu propio conjunto privado de políticas en Perl::Critic.

Arch Linux package

Este es un ejemplo de un paquete de Arch Linux. Los paquetes de Arch Linux son archivos comprimidos que contienen software listo para ser instalado y ejecutado en un sistema Arch Linux.

Cada paquete incluye el ejecutable o la librería, metadatos sobre el paquete (como nombre, versión, dependencias) y, opcionalmente, archivos de configuración y documentación. El sistema de gestión de paquetes de Arch Linux, Pacman, se encarga de descargar, instalar, actualizar y eliminar estos paquetes de manera eficiente.

Los paquetes se construyen a partir de "build scripts" (scripts de compilación) que describen cómo obtener el código fuente, compilarlo y empaquetarlo. Estos scripts son la base del Arch Build System (ABS), una herramienta poderosa que permite a los usuarios compilar software directamente desde el código fuente o crear sus propios paquetes personalizados.

Este contenido es un ejemplo y no representa un paquete real de Arch Linux.
