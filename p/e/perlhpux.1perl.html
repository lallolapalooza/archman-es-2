PERLHPUX(1perl) Perl Programmers Reference Guide PERLHPUX(1perl)

NOMBRE

perlhpux - Perl versión 5 en sistemas Hewlett-Packard Unix (HP-UX)

DESCRIPCIÓN

Este documento describe varias características del sistema operativo Unix de HP (HP-UX) que afectarán cómo Perl versión 5 (en adelante Perl) se compila y/o se ejecuta.

Usando perl tal como se envía con HP-UX

La versión de aplicación de septiembre de 2001, HP-UX 11.00, es la primera en incluir Perl. En ese momento era perl-5.6.1 en /opt/perl. La primera aparición está en el CD 5012-7954 y se puede instalar usando

swinstall -s /cdrom perl

asumiendo que ha montado ese CD en /cdrom.

Esa compilación era una compilación multihilo hppa-1.1 portable que soporta archivos grandes compilados con gcc-2.9-hppa-991112.

Si realiza una nueva instalación, entonces (una versión más reciente de) Perl se instalará automáticamente. Los sistemas HP-UX preinstalados ahora tienen versiones más recientes de Perl y los módulos actualizados.

Las compilaciones oficiales (con hilos) de HP, tal como se envían en el DVD/CD de aplicaciones, están disponibles en http://www.software.hp.com/portal/swdepot/displayProductInfo.do?productNumber=PERL tanto para PA-RISC como para IPF (Itanium Processor Family). Están compiladas con el compilador HP ANSI-C. Hasta la versión 5.8.8, esto lo realizaba ActiveState.

Para ver qué versión se incluye en el DVD (asumiendo aquí que está montado en /cdrom), emita este comando:

# swlist -s /cdrom perl
# perl           D.5.8.8.B  5.8.8 Perl Programming Language
  perl.Perl5-32  D.5.8.8.B  32-bit 5.8.8 Perl Programming Language
                                         with Extensions
  perl.Perl5-64  D.5.8.8.B  64-bit 5.8.8 Perl Programming Language
                                         with Extensions

Para ver qué está instalado en su sistema:

# swlist -R perl
# perl                    E.5.8.8.J  Perl Programming Language
# perl.Perl5-32           E.5.8.8.J  32-bit Perl Programming Language
                                     with Extensions
  perl.Perl5-32.PERL-MAN  E.5.8.8.J  32-bit Perl Man Pages for IA
  perl.Perl5-32.PERL-RUN  E.5.8.8.J  32-bit Perl Binaries for IA
# perl.Perl5-64           E.5.8.8.J  64-bit Perl Programming Language
                                     with Extensions
  perl.Perl5-64.PERL-MAN  E.5.8.8.J  64-bit Perl Man Pages for IA
  perl.Perl5-64.PERL-RUN  E.5.8.8.J  64-bit Perl Binaries for IA

Usando perl desde el centro de portabilidad de HP

El centro de portabilidad de HP intenta mantenerse al día con la demanda de los clientes y lanzar actualizaciones de la comunidad de Código Abierto. Tener binarios de Perl precompilados disponibles es obvio, aunque "actualizado" es algo relativo. En el momento de escribir esto, perl-5.10.1 y 5.28.0 estaban disponibles.

Los centros de portabilidad de HP están limitados en cuanto a los sistemas para los que se les permite portar y generalmente eligen las dos versiones más recientes del sistema operativo disponibles.

HP ha pedido al centro de portabilidad que traslade los binarios de Código Abierto de /opt a /usr/local, por lo que los binarios producidos desde principios de julio de 2002 se encuentran en /usr/local.

Una de las URL de los centros de portabilidad de HP es http://hpux.connect.org.uk/ La versión actualmente disponible está compilada con GNU gcc. Como portar el gcc moderno es extremadamente difícil en HP-UX, están estancados en la versión gcc-4.2.3.

Otros binarios de perl precompilados

Para obtener más depósitos de perl para toda la gama de HP-UX, visite el sitio de H.Merijn Brand en http://mirrors.develooper.com/hpux/#Perl. Lea atentamente las notas para ver si las versiones disponibles se adaptan a sus necesidades.

Compilando Perl 5 en HP-UX

Al compilar Perl, debe utilizar un compilador ANSI C. El compilador C que se envía con todos los sistemas HP-UX es un compilador K&R que solo debe utilizarse para compilar nuevos kernels.

Perl se puede compilar con el compilador HP ANSI C o con gcc. Se recomienda el primero, ya que no solo puede compilar Perl sin dificultad, sino que también puede aprovechar las características que se enumeran más adelante y que requieren el uso de indicadores de línea de comandos específicos del compilador de HP.

Si decide usar gcc, asegúrese de que su instalación sea reciente y completa, y no olvide leer el archivo INSTALL de Perl para obtener más detalles específicos de gcc.

PA-RISC

La última y definitiva versión de PA-RISC es la 2.0. HP ya no vende ningún sistema con estas CPU.

Los sistemas Unix HP9000 de HP se ejecutan en el chip Precision Architecture (PA-RISC) propio de HP. HP-UX solía ejecutarse en la familia de chips MC68000 de Motorola, pero cualquier máquina con este chip está bastante obsoleta y este documento no intentará abordar los problemas de compilación de Perl en el chipset Motorola. Aunque el hardware PA-RISC ya no se vende, todavía se pueden encontrar muchas máquinas que se ejecutan en estas CPU.

La última fecha de pedido para los sistemas HP 9000 fue el 31 de diciembre de 2008.

Los sistemas HP PA-RISC suelen denominarse con la descripción del modelo "HP 9000". La última CPU de esta serie es la PA-8900. El soporte para las máquinas con arquitectura PA-RISC finalizó oficialmente como se muestra en la siguiente tabla:

Portabilidad Entre Versiones de PA-RISC

Un ejecutable compilado en una plataforma PA-RISC 2.0 no se ejecutará en una plataforma PA-RISC 1.1, incluso si están ejecutando la misma versión de HP-UX. Si está compilando Perl en una plataforma PA-RISC 2.0 y desea que ese Perl también funcione en una PA-RISC 1.1, se deben usar las banderas del compilador +DAportable y +DS32.

Ya no es posible compilar ejecutables PA-RISC 1.0 en las plataformas PA-RISC 1.1 o 2.0. Las banderas de línea de comandos se aceptan, pero el ejecutable resultante no se ejecutará cuando se transfiera a un sistema PA-RISC 1.0.

Familia de Procesadores Itanium (IPF) y HP-UX

HP-UX también se ejecuta en el procesador Itanium más nuevo. Esto requiere el uso de la versión 11.23 (11i v2) o 11.31 (11i v3) de HP-UX, y con la excepción de algunas diferencias detalladas a continuación y en secciones posteriores, Perl debería compilarse sin problemas.

Aunque los binarios PA-RISC pueden ejecutarse en sistemas Itanium, no debe intentar usar una versión PA-RISC de Perl en un sistema Itanium. Esto se debe a que las bibliotecas compartidas creadas en un sistema Itanium no se pueden cargar mientras se ejecuta un ejecutable PA-RISC.

Los sistemas HP Itanium 2 generalmente se denominan con la descripción del modelo "HP Integrity".

Compilación de Extensiones Dinámicas en HP-UX

HP-UX soporta bibliotecas cargables dinámicamente (bibliotecas compartidas). Las bibliotecas compartidas terminan con el sufijo .sl. En sistemas Itanium, terminan con el sufijo .so.

Las bibliotecas compartidas creadas en una plataforma que utiliza una versión particular de PA-RISC no son utilizables en plataformas que utilizan una versión anterior de PA-RISC por defecto. Sin embargo, esta compatibilidad retroactiva puede habilitarse utilizando la misma bandera del compilador +DAportable (con la misma advertencia de PA-RISC 1.0 mencionada anteriormente).

Las bibliotecas compartidas creadas en una plataforma Itanium no se pueden cargar en una plataforma PA-RISC. Las bibliotecas compartidas creadas en una plataforma PA-RISC solo se pueden cargar en una plataforma Itanium si es un ejecutable PA-RISC el que intenta cargar la biblioteca PA-RISC. Una biblioteca compartida PA-RISC no se puede cargar en un ejecutable Itanium ni viceversa.

Para crear una biblioteca compartida, se deben realizar los siguientes pasos:

1. Compile los módulos fuente con la bandera +z o +Z para crear un módulo
   .o que contenga Código Independiente de Posición (PIC). El enlazador le
   indicará en el siguiente paso si se necesitaba +Z.
   (Para gcc, la bandera apropiada es -fpic o -fPIC.)
2. Enlace la biblioteca compartida usando la bandera -b. Si el código llama
   a alguna función en otras bibliotecas del sistema (por ejemplo, libm),
   debe incluirse en esta línea.

(Tenga en cuenta que estos pasos suelen ser manejados automáticamente por el Makefile de la extensión).

Si estas bibliotecas dependientes no se listan en el momento de la creación de la biblioteca compartida, obtendrá errores fatales de "Símbolo no resuelto" en tiempo de ejecución cuando se cargue la biblioteca.

Puede crear una biblioteca compartida que haga referencia a otra biblioteca, que puede ser una biblioteca de archivo o una biblioteca compartida. Si esta segunda biblioteca es una biblioteca compartida, esto se llama una "biblioteca dependiente". El nombre de la biblioteca dependiente se registra en la biblioteca compartida principal, pero no se enlaza en la biblioteca compartida. En su lugar, se carga cuando se carga la biblioteca compartida principal. Esto puede causar problemas si compila una extensión en un sistema y la traslada a otro sistema donde las bibliotecas pueden no estar ubicadas en el mismo lugar que en el primer sistema.

Si la biblioteca referenciada es una biblioteca de archivo, se trata como una simple colección de módulos .o (todos los cuales deben contener PIC). Estos módulos se enlazan luego en la biblioteca compartida.

Tenga en cuenta que está bien crear una biblioteca que contenga una biblioteca dependiente que ya esté enlazada en perl.

Algunas extensiones, como DB_File y Compress::Zlib, usan/requieren bibliotecas precompiladas para que las extensiones/módulos de perl funcionen. Si estas bibliotecas se compilan usando la configuración predeterminada, puede suceder que se encuentre con un error como "invalid loader fixup" durante la fase de carga. HP es consciente de este problema. Busque en los foros de cxx-dev de HP-UX discusiones sobre el tema. La respuesta corta es que todo (todas las bibliotecas, todo) debe compilarse con "+z" o "+Z" para ser PIC (código independiente de posición). (Para gcc, eso sería "-fpic" o "-fPIC"). En HP-UX 11.00 o posterior, el mensaje de error del enlazador debería indicar el nombre del archivo objeto infractor.

Un enfoque más general es intervenir manualmente, como con un ejemplo para el módulo DB_File, que requiere libdb.sl de SleepyCat:

# cd .../db-3.2.9/build_unix
# vi Makefile
... agregar +Z a todos los cflags para crear objetos compartidos
CFLAGS=         -c $(CPPFLAGS) +Z -Ae +O2 +Onolimit \
                -I/usr/local/include -I/usr/include/X11R6
CXXFLAGS=       -c $(CPPFLAGS) +Z -Ae +O2 +Onolimit \
                -I/usr/local/include -I/usr/include/X11R6
# make clean
# make
# mkdir tmp
# cd tmp
# ar x ../libdb.a
# ld -b -o libdb-3.2.sl *.o
# mv libdb-3.2.sl /usr/local/lib
# rm *.o
# cd /usr/local/lib
# rm -f libdb.sl
# ln -s libdb-3.2.sl libdb.sl
# cd .../DB_File-1.76
# make distclean
# perl Makefile.PL
# make
# make test
# make install

A partir de db-4.2.x ya no es necesario hacer esto manualmente. Sleepycat ha cambiado el proceso de configuración para agregar +z en HP-UX automáticamente.

# cd .../db-4.2.25/build_unix
# env CFLAGS=+DD64 LDFLAGS=+DD64 ../dist/configure

debería funcionar para generar bibliotecas compartidas de 64 bits para HP-UX 11.00 y 11i.

Ya no es posible enlazar bibliotecas compartidas PA-RISC 1.0 (aunque las banderas de línea de comandos todavía están presentes).

Los archivos objeto PA-RISC y Itanium no son intercambiables. Aunque pueda utilizar ar para crear una biblioteca de archivo de archivos objeto PA-RISC en un sistema Itanium, no puede enlazar contra ella utilizando un enlazador Itanium.

El Compilador ANSI C de HP

Cuando utilice este compilador para compilar Perl, asegúrese de que la bandera -Aa se añada a las variables cpprun y cppstdin en el archivo config.sh (aunque consulte la sección sobre perl de 64 bits a continuación). Si está utilizando una versión reciente de la distribución de Perl, estas banderas se establecen automáticamente.

Aunque HP-UX 10.20 y 11.00 ya no son mantenidos activamente por HP, las actualizaciones para el compilador HP ANSI C todavía están disponibles de vez en cuando, y podría ser aconsejable ver si las actualizaciones son aplicables. En el momento de escribir esto, los últimos parches disponibles para 11.00 que deberían aplicarse son PHSS_35098, PHSS_35175, PHSS_35100, PHSS_33036 y PHSS_33902). Si tiene una cuenta SUM, puede usarla para buscar actualizaciones/parches. Introduzca "ANSI" como palabra clave.

El Compilador GNU C

Cuando vaya a utilizar el compilador GNU C (gcc), y aún no tiene gcc, puede compilarlo usted mismo (si se siente lo suficientemente masoquista) a partir de las fuentes (disponibles en, por ejemplo, http://gcc.gnu.org/mirrors.html) o descargar un binario precompilado del centro de portabilidad de HP en <http://hpux.connect.org.uk/hppd/cgi-bin/search?term=gcc&Search=Search> o del DSPP (necesita ser miembro) en <http://h21007.www2.hp.com/portal/site/dspp/menuitem.863c3e4cbcdc3f3515b49c108973a801?ciid=2a08725cc2f02110725cc2f02110275d6e10RCRD&jumpid=reg_r1002_usen_c-001_title_r000'>http://h21007.www2.hp.com/portal/site/dspp/menuitem.863c3e4cbcdc3f3515b49c108973a801?ciid=2a08725cc2f02110725cc2f02110275d6e10RCRD&jumpid=reg_r1002_usen_c-001_title_r000>

NAME

perlhpux - Perl on HP-UX

DESCRIPTION

This document describes the issues that are known to affect Perl on HP-UX.

nss_delete core dump from op/pwent or op/grent

The key here is the "nss_delete" call. One workaround for this bug seems to be to create add to the file /etc/nsswitch.conf (at least) the following lines

group: files
passwd: files

Whether you are using NIS does not matter. Amazingly enough, the same bug also affects Solaris.

error: pasting ")" and "l" does not give a valid preprocessing token

There seems to be a broken system header file in HP-UX 11.00 that breaks perl building in 32bit mode with GNU gcc-4.x causing this error. The same file for HP-UX 11.11 (even though the file is older) does not show this failure, and has the correct definition, so the best fix is to patch the header to match:

--- /usr/include/inttypes.h  2001-04-20 18:42:14 +0200
+++ /usr/include/inttypes.h  2000-11-14 09:00:00 +0200
@@ -72,7 +72,7 @@
 #define UINT32_C(__c)                   __CONCAT_U__(__c)
 #else /* __LP64 */
 #define INT32_C(__c)                    __CONCAT__(__c,l)
-#define UINT32_C(__c)                   __CONCAT__(__CONCAT_U__(__c),l)
+#define UINT32_C(__c)                   __CONCAT__(__c,ul)
 #endif /* __LP64 */
 #define INT64_C(__c)                    __CONCAT_L__(__c,l)

Redeclaration of "sendpath" with a different storage class specifier

The following compilation warnings may happen in HP-UX releases earlier than 11.31 but are harmless:

cc: "/usr/include/sys/socket.h", line 535: warning 562:
   Redeclaration of "sendfile" with a different storage class
   specifier: "sendfile" will have internal linkage.
cc: "/usr/include/sys/socket.h", line 536: warning 562:
   Redeclaration of "sendpath" with a different storage class
   specifier: "sendpath" will have internal linkage.

They seem to be caused by broken system header files, and also other open source projects are seeing them. The following HP-UX patches should make the warnings go away:

CR JAGae12001: PHNE_27063
Warning 562 on sys/socket.h due to redeclaration of prototypes
CR JAGae16787:
Warning 562 from socket.h sendpath/sendfile -D_FILEFFSET_BITS=64
CR JAGae73470 (11.23)
ER: Compiling socket.h with cc -D_FILEFFSET_BITS=64 warning 267/562

Miscellaneous

HP-UX 11 Y2K patch "Y2K-1100 B.11.00.B0125 HP-UX Core OS Year 2000 Patch Bundle" has been reported to break the io/fs test #18 which tests whether utime() can change timestamps. The Y2K patch seems to break utime() so that over NFS the timestamps do not get changed (on local filesystems utime() still works). This has probably been fixed on your system by now.
