PERLTIE(1perl) Perl Programmers Reference Guide PERLTIE(1perl)

NOMBRE

perltie - cómo ocultar una clase de objeto en una variable simple

SINOPSIS

tie VARIABLE, CLASE, LISTA
$objeto = tied VARIABLE
untie VARIABLE

DESCRIPCIÓN

Antes de la versión 5.0 de Perl, un programador podía usar dbmopen() para conectar una base de datos en disco en el formato estándar de Unix dbm(3x) mágicamente a un %HASH en su programa. Sin embargo, su Perl estaba construido con una biblioteca dbm particular u otra, pero no ambas, y no se podía extender este mecanismo a otros paquetes o tipos de variables.

Ahora puedes.

La función tie() enlaza una variable a una clase (paquete) que proporcionará la implementación de los métodos de acceso para esa variable. Una vez realizada esta magia, el acceso a una variable enlazada activa automáticamente las llamadas a métodos en la clase correcta. La complejidad de la clase se oculta detrás de las llamadas a métodos mágicos. Los nombres de los métodos están en MAYÚSCULAS, lo que es una convención que Perl utiliza para indicar que se llaman implícitamente en lugar de explícitamente, al igual que las funciones BEGIN() y END().

En la llamada tie(), "VARIABLE" es el nombre de la variable a enchanter. "CLASE" es el nombre de una clase que implementa objetos del tipo correcto. Cualquier argumento adicional en la "LISTA" se pasa al método constructor apropiado para esa clase, lo que significa TIESCALAR(), TIEARRAY(), TIEHASH() o TIEHANDLE(). (Típicamente, estos son argumentos como los que se pasarían a la función dbminit() de C.) El objeto devuelto por el método "new" también es devuelto por la función tie(), lo que sería útil si quisieras acceder a otros métodos en "CLASE". (En realidad, no tienes que devolver una referencia al "tipo" correcto (por ejemplo, HASH o "CLASE") siempre que sea un objeto debidamente bendecido.) También puedes recuperar una referencia al objeto subyacente utilizando la función tied().

A diferencia de dbmopen(), la función tie() no hará "use" ni "require" un módulo por ti; necesitas hacerlo explícitamente tú mismo.

Enlazando Escalares

Una clase que implementa un escalar enlazado debe definir los siguientes métodos: TIESCALAR, FETCH, STORE y, posiblemente, UNTIE y/o DESTROY.

Veámoslos uno por uno, utilizando como ejemplo una clase de enlace para escalares que permite al usuario hacer algo como:

tie $velocidad_suya, 'Nice', getppid();
tie $velocidad_mia,  'Nice', $$;

Y ahora, cada vez que se acceda a una de esas variables, se recuperará y devolverá su prioridad del sistema actual. Si esas variables se establecen, ¡entonces se cambiará la prioridad del proceso!

Usaremos la clase BSD::Resource de Jarkko Hietaniemi <jhi@iki.fi> (no incluida) para acceder a las constantes PRIO_PROCESS, PRIO_MIN y PRIO_MAX de tu sistema, así como a las llamadas al sistema getpriority() y setpriority(). Aquí está el preámbulo de la clase.

package Nice;
use Carp;
use BSD::Resource;
use strict;
$Nice::DEBUG = 0 unless defined $Nice::DEBUG;
TIESCALAR clase, LISTA
Este es el constructor de la clase. Significa que se espera que devuelva una referencia bendecida a un nuevo escalar (probablemente anónimo) que está creando. Por ejemplo: 
sub TIESCALAR {
    my $class = shift;
    my $pid = shift || $$; # 0 significa yo
    if ($pid !~ /^\d+$/) {
        carp "Nice::Tie::Scalar got non-numeric pid $pid" if $^W;
        return undef;
    }
    unless (kill 0, $pid) { # EPERM o ERSCH, sin duda
        carp "Nice::Tie::Scalar got bad pid $pid: $!" if $^W;
        return undef;
    }
    return bless \$pid, $class;
}

Esta clase de enlace ha elegido devolver un error en lugar de lanzar una excepción si su constructor falla. Si bien así es como funciona dbmopen(), otras clases pueden no querer ser tan comprensivas. Comprueba la variable global $^W para ver si emite un poco de ruido de todos modos.

FETCH this
Este método se activará cada vez que se acceda (lea) la variable enlazada. No toma argumentos además de su autorreferencia, que es el objeto que representa el escalar con el que estamos tratando. Dado que en este caso usamos solo una referencia SCALAR para el objeto escalar enlazado, un simple $$self permite al método acceder al valor real almacenado allí. En nuestro ejemplo a continuación, ese valor real es el ID del proceso al que hemos enlazado nuestra variable. 
sub FETCH {
    my $self = shift;
    confess "wrong type" unless ref $self;
    croak "usage error" if @_;
    my $nicety;
    local($!) = 0;
    $nicety = getpriority(PRIO_PROCESS, $$self);
    if ($!) { croak "getpriority failed: $!" }
    return $nicety;
}

Esta vez hemos decidido explotar (lanzar una excepción) si el renice falla; no hay ningún lugar donde podamos devolver un error de otra manera, y probablemente sea lo correcto.

STORE this, valor
Este método se activará cada vez que se establezca (asigne) la variable enlazada. Además de su autorreferencia, también espera uno (y solo uno) argumento: el nuevo valor que el usuario está intentando asignar. No te preocupes por devolver un valor de STORE; la semántica de la asignación que devuelve el valor asignado se implementa con FETCH. 
sub STORE {
    my $self = shift;
    confess "wrong type" unless ref $self;
    my $new_nicety = shift;
    croak "usage error" if @_;
    if ($new_nicety < PRIO_MIN) {
        carp sprintf
          "ADVERTENCIA: prioridad %d menor que la prioridad mínima del sistema %d",
              $new_nicety, PRIO_MIN if $^W;
        $new_nicety = PRIO_MIN;
    }
    if ($new_nicety > PRIO_MAX) {
        carp sprintf
          "ADVERTENCIA: prioridad %d mayor que la prioridad máxima del sistema %d",
              $new_nicety, PRIO_MAX if $^W;
        $new_nicety = PRIO_MAX;
    }
    unless (defined setpriority(PRIO_PROCESS,
                                $$self,
                                $new_nicety))
    {
        confess "setpriority failed: $!";
    }
}
UNTIE this
Este método se activará cuando ocurra el "untie". Esto puede ser útil si la clase necesita saber cuándo no se realizarán más llamadas. (Excepto DESTROY, por supuesto). Ver "El problema del "untie"" a continuación para más detalles.
DESTROY this
Este método se activará cuando la variable enlazada necesite ser destruida. Al igual que con otras clases de objetos, un método de este tipo rara vez es necesario, porque Perl se encarga de liberar automáticamente la memoria de su objeto moribundo, no es C++, ¿sabes? Usaremos un método DESTROY aquí solo para depuración. 
sub DESTROY {
    my $self = shift;
    confess "wrong type" unless ref $self;
    carp "[ Nice::DESTROY pid $$self ]" if $Nice::DEBUG;
}

Eso es todo. De hecho, es más que todo, porque hemos hecho algunas cosas buenas aquí por completitud, robustez y estética general. Ciertamente son posibles clases TIESCALAR más simples.

Enlazando Arreglos

Una clase que implementa un array ordinario enlazado debe definir los siguientes métodos: TIEARRAY, FETCH, STORE, FETCHSIZE, STORESIZE, CLEAR y quizás UNTIE y/o DESTROY.

FETCHSIZE y STORESIZE se utilizan para proporcionar acceso a $#array y al escalar equivalente scalar(@array).

Los métodos POP, PUSH, SHIFT, UNSHIFT, SPLICE, DELETE y EXISTS son requeridos si el operador de perl con el nombre correspondiente (pero en minúsculas) debe operar en el array enlazado. La clase Tie::Array se puede usar como clase base para implementar los cinco primeros en términos de los métodos básicos anteriores. Las implementaciones predeterminadas de DELETE y EXISTS en Tie::Array simplemente "croak".

Además, EXTEND se llamará cuando Perl hubiera pre-extendido la asignación en un array real.

Para esta discusión, implementaremos un array cuyos elementos son de un tamaño fijo a

Tying Arrays

Tying an array requires you to implement a class that provides an interface for the methods that Perl will call when it performs operations on the tied array. The required methods are TIEARRAY, FETCH, STORE, FETCHSIZE, and STORESIZE.

Optional methods include EXTEND, EXISTS, DELETE, CLEAR, PUSH, POP, SHIFT, UNSHIFT, SPLICE, UNTIE, and DESTROY.

The example below implements a tied array that limits the size of each element. If you try to create an element larger than the fixed size, you will get an exception. For example:

    use FixedElem_Array;
    tie @array, 'FixedElem_Array', 3;
    $array[0] = 'cat';  # ok.
    $array[1] = 'dogs'; # exception, length('dogs') > 3.

The preamble code for the class is as follows:

    package FixedElem_Array;
    use Carp;
    use strict;
TIEARRAY classname, LIST
This is the constructor for the class. It is expected to return a blessed reference through which the new array (probably an anonymous ARRAY ref) will be accessed.

In our example, just to show you that you don't really have to return an ARRAY reference, we'll choose a HASH reference to represent our object. A HASH works out well as a generic record type: the "{ELEMSIZE}" field will store the maximum element size allowed, and the "{ARRAY}" field will hold the true ARRAY ref. If someone outside the class tries to dereference the object returned (doubtless thinking it is an ARRAY ref), they'll blow up. This just goes to show you that you should respect an object's privacy.

        sub TIEARRAY {
          my $class    = shift;
          my $elemsize = shift;
          if ( @_ || $elemsize =~ /\D/ ) {
            croak "usage: tie ARRAY, '" . __PACKAGE__ . "', elem_size";
          }
          return bless {
            ELEMSIZE => $elemsize,
            ARRAY    => [],
          }, $class;
        }
FETCH this, index
This method will be triggered every time an individual element the tied array is accessed (read). It takes one argument beyond its self reference: the index whose value we're trying to fetch. 
        sub FETCH {
          my $self  = shift;
          my $index = shift;
          return $self->{ARRAY}->[$index];
        }

If a negative array index is used to read from an array, the index will be translated to a positive one internally by calling FETCHSIZE before being passed to FETCH. You may disable this feature by assigning a true value to the variable $NEGATIVE_INDICES in the tied array class.

As you may have noticed, the name of the FETCH method (et al.) is the same for all accesses, even though the constructors differ in names (TIESCALAR vs TIEARRAY). While in theory you could have the same class servicing several tied types, in practice this becomes cumbersome, and it's easiest to keep them at simply one tie type per class.

STORE this, index, value
This method will be triggered every time an element in the tied array is set (written). It takes two arguments beyond its self reference: the index at which we're trying to store something and the value we're trying to put there.

In our example, "undef" is really "$self->{ELEMSIZE}" number of spaces so we have a little more work to do here:

        sub STORE {
          my $self = shift;
          my( $index, $value ) = @_;
          if ( length $value > $self->{ELEMSIZE} ) {
            croak "length of $value is greater than $self->{ELEMSIZE}";
          }
          # fill in the blanks
          $self->STORESIZE( $index ) if $index > $self->FETCHSIZE();
          # right justify to keep element size for smaller elements
          $self->{ARRAY}->[$index] = sprintf "%$self->{ELEMSIZE}s", $value;
        }

Negative indexes are treated the same as with FETCH.

FETCHSIZE this
Returns the total number of items in the tied array associated with object this. (Equivalent to scalar(@array)). For example: 
        sub FETCHSIZE {
          my $self = shift;
          return scalar $self->{ARRAY}->@*;
        }
STORESIZE this, count
Sets the total number of items in the tied array associated with object this to be count. If this makes the array larger then class's mapping of "undef" should be returned for new positions. If the array becomes smaller then entries beyond count should be deleted.

In our example, 'undef' is really an element containing "$self->{ELEMSIZE}" number of spaces. Observe:

        sub STORESIZE {
          my $self  = shift;
          my $count = shift;
          if ( $count > $self->FETCHSIZE() ) {
            foreach ( $count - $self->FETCHSIZE() .. $count ) {
              $self->STORE( $_, '' );
            }
          } elsif ( $count < $self->FETCHSIZE() ) {
            foreach ( 0 .. $self->FETCHSIZE() - $count - 2 ) {
              $self->POP();
            }
          }
        }
EXTEND this, count
Informative call that array is likely to grow to have count entries. Can be used to optimize allocation. This method need do nothing.

In our example there is no reason to implement this method, so we leave it as a no-op. This method is only relevant to tied array implementations where there is the possibility of having the allocated size of the array be larger than is visible to a perl programmer inspecting the size of the array. Many tied array implementations will have no reason to implement it.

        sub EXTEND {   
          my $self  = shift;
          my $count = shift;
          # nothing to see here, move along.
        }

NOTE: It is generally an error to make this equivalent to STORESIZE. Perl may from time to time call EXTEND without wanting to actually change the array size directly. Any tied array should function correctly if this method is a no-op, even if perhaps they might not be as efficient as they would if this method was implemented.

EXISTS this, key
Verify that the element at index key exists in the tied array this.

In our example, we will determine that if an element consists of "$self->{ELEMSIZE}" spaces only, it does not exist:

        sub EXISTS {
          my $self  = shift;
          my $index = shift;
          return 0 if ! defined $self->{ARRAY}->[$index] ||
                      $self->{ARRAY}->[$index] eq ' ' x $self->{ELEMSIZE};
          return 1;
        }
DELETE this, key
Delete the element at index key from the tied array this.

In our example, a deleted item is "$self->{ELEMSIZE}" spaces:

        sub DELETE {
          my $self  = shift;
          my $index = shift;
          return $self->STORE( $index, '' );
        }
CLEAR this
Clear (remove, delete, ...) all values from the tied array associated with object this. For example: 
        sub CLEAR {
          my $self = shift;
          return $self->{ARRAY} = [];
        }
PUSH this, LIST
Append elements of LIST to the array. For example: 
        sub PUSH {  
          my $self = shift;
          my @list = @_;
          my $last = $self->FETCHSIZE();
          $self->STORE( $last + $_, $list[$_] ) foreach 0 .. $#list;
          return $self->FETCHSIZE();
        }
POP this
Remove last element of the array and return it. For example: 
        sub POP {
          my $self = shift;
          return pop $self->{ARRAY}->@*;
        }
SHIFT this
Remove the first element of the array (shifting other elements down) and return it. For example: 
        sub SHIFT {
          my $self = shift;
          return shift $self->{ARRAY}->@*;
        }
UNSHIFT this, LIST
Insert LIST elements at the beginning of the array, moving existing elements up to make room. For example: 
        sub UNSHIFT {
          my $self = shift;
          my @list = @_;
          my $size = scalar( @list );
          # make room for our list
          $self->{ARRAY}[ $size .. $self->{ARRAY}->$#* + $size ]->@*
           = $self->{ARRAY}->@*
          $self->STORE( $_, $list[$_] ) foreach 0 .. $#list;
        }
SPLICE this, offset, length, LIST
Perform the equivalent of "splice" on the array.

offset is optional and defaults to zero, negative values count back from the end of the array.

length is optional and defaults to rest of the array.

LIST may be empty.

Returns a list of the original length elements at offset.

In our example, we'll use a little shortcut if there is a LIST:

        sub SPLICE {
          my $self   = shift;
          my $offset = shift || 0;
          my $length = shift || $self->FETCHSIZE() - $offset;
          my @list   = (); 
          if ( @_ ) {
            tie @list, __PACKAGE__, $self->{ELEMSIZE};
            @list   = @_;
          }
          return splice $self->{ARRAY}->@*, $offset, $length, @list;
        }
UNTIE this
Will be called when "untie" happens. (See "The "untie" Gotcha" below.)
DESTROY this
This method will be triggered when the tied variable needs to be destructed. As with the scalar tie class, this is almost never needed in a language that does its own garbage collection, so this time we'll just leave it out.

Tying Hashes

Hashes were the first Perl data type to be tied (see dbmopen()). A class implementing a tied hash should define the following methods: TIEHASH is the constructor. FETCH and STORE access the key and value pairs. EXISTS reports whether a key is present in the hash, and DELETE deletes one. CLEAR empties the hash by deleting all the key and value pairs. FIRSTKEY and NEXTKEY implement the keys() and each() functions to iterate over all the keys. SCALAR is triggered when the tied hash is evaluated in scalar context, and in 5.28 onwards, by "keys" in boolean context. UNTIE is called when "untie" happens, and DESTROY is called when the tied variable is garbage collected.

If this seems like a lot, then feel free to inherit from merely the standard Tie::StdHash module for most of your methods, redefining only the interesting ones. See Tie::Hash for details.

UNTIE this
Se llama cuando ocurre "untie". Consulte "The "untie" Gotcha" a continuación.
DESTROY this
Este método se activa cuando un hash vinculado está a punto de salir de ámbito. Realmente no lo necesita a menos que esté tratando de agregar depuración o tenga estado auxiliar que limpiar. Aquí hay una función muy simple: 
sub DESTROY  {
    carp &whowasi if $DEBUG;
}

Tenga en cuenta que las funciones como keys() y values() pueden devolver listas enormes cuando se usan en objetos grandes, como archivos DBM. Es posible que prefiera usar la función each() para iterar sobre ellos. Ejemplo:

# Imprimir los desplazamientos del archivo de historial
use NDBM_File;
tie(%HIST, 'NDBM_File', '/usr/lib/news/history', 1, 0);
while (($key,$val) = each %HIST) {
    print $key, ' = ', unpack('L',$val), "\n";
}
untie(%HIST);

Vinculando FileHandles

Esto está parcialmente implementado ahora.

Una clase que implementa un filehandle vinculado debe definir los siguientes métodos: TIEHANDLE, al menos uno de PRINT, PRINTF, WRITE, READLINE, GETC, READ, y posiblemente CLOSE, UNTIE y DESTROY. La clase también puede proporcionar: BINMODE, OPEN, EOF, FILENO, SEEK, TELL, si los operadores de perl correspondientes se usan en el handle.

Cuando STDERR está vinculado, se llamará a su método PRINT para emitir advertencias y mensajes de error. Esta función está deshabilitada temporalmente durante la llamada, lo que significa que puede usar warn() dentro de PRINT sin iniciar un bucle recursivo. Y al igual que los manejadores "__WARN__" y "__DIE__", se puede llamar al método PRINT de STDERR para informar errores del analizador, por lo que se aplican las advertencias mencionadas en "%SIG" en perlvar.

Todo esto es especialmente útil cuando perl se incrusta en algún otro programa, donde la salida a STDOUT y STDERR puede tener que ser redirigida de alguna manera especial. Consulte nvi y el módulo Apache para ver ejemplos.

Al vincular un handle, el primer argumento de "tie" debe comenzar con un asterisco. Por lo tanto, si está vinculando STDOUT, use *STDOUT. Si lo ha asignado a una variable escalar, por ejemplo $handle, use *$handle. "tie $handle" vincula la variable escalar $handle, no el handle que contiene.

En nuestro ejemplo, vamos a crear un handle gritón.

package Shout;
TIEHANDLE classname, LIST
Este es el constructor de la clase. Eso significa que se espera que devuelva una referencia bendecida de algún tipo. La referencia se puede usar para mantener información interna. 
sub TIEHANDLE { print "<shout>\n"; my $i; bless \$i, shift }
WRITE this, LIST
Este método se llamará cuando el handle se escriba a través de la función "syswrite". 
sub WRITE {
    $r = shift;
    my($buf,$len,$offset) = @_;
    print "WRITE called, \$buf=$buf, \$len=$len, \$offset=$offset";
}
PRINT this, LIST
Este método se activará cada vez que se imprima en el handle vinculado con las funciones print() o say(). Además de su autorreferencia, también espera la lista que se pasó a la función de impresión. 
sub PRINT { $$r++; print join($,,map(uc($_),@_)),$\ }

say() actúa igual que print() excepto que $\ se localizará a "\n", por lo que no necesita hacer nada especial para manejar say() en PRINT().

PRINTF this, LIST
Este método se activará cada vez que se imprima en el handle vinculado con la función printf(). Además de su autorreferencia, también espera el formato y la lista que se pasaron a la función printf. 
sub PRINTF {
    shift;
    my $fmt = shift;
    print sprintf($fmt, @_);
}
READ this, LIST
Este método se llamará cuando el handle se lea a través de las funciones "read" o "sysread". 
sub READ {
  my $self = shift;
  my $bufref = \$_[0];
  my(undef,$len,$offset) = @_;
  print "READ called, \$buf=$bufref, \$len=$len, \$offset=$offset";
  # agregar a $$bufref, establecer $len al número de caracteres leídos
  $len;
}
READLINE this
Este método se llama cuando se lee el handle a través de "<HANDLE>" o "readline HANDLE".

Según "readline", en contexto escalar debe devolver la siguiente línea, o "undef" si no hay más datos. En contexto de lista debe devolver todas las líneas restantes, o una lista vacía si no hay más datos. Las cadenas devueltas deben incluir el separador de registros de entrada $/ (consulte perlvar), a menos que sea "undef" (lo que significa modo "slurp").

sub READLINE {
  my $r = shift;
  if (wantarray) {
    return ("all remaining\n",
            "lines up\n",
            "to eof\n");
  } else {
    return "READLINE called " . ++$$r . " times\n";
  }
}
GETC this
Este método se llamará cuando se llame a la función "getc". 
sub GETC { print "Don't GETC, Get Perl"; return "a"; }
EOF this
Este método se llamará cuando se llame a la función "eof".

A partir de Perl 5.12, se pasará un parámetro entero adicional. Será cero si "eof" se llama sin parámetro; 1 si se pasa un filehandle a "eof", por ejemplo eof(FH); y 2 en el caso muy especial de que el filehandle vinculado sea "ARGV" y se llame a "eof" con una lista de parámetros vacía, por ejemplo eof().

sub EOF { not length $stringbuf }
CLOSE this
Este método se llamará cuando el handle se cierre a través de la función "close". 
sub CLOSE { print "CLOSE called.\n" }
UNTIE this
Al igual que con los otros tipos de vinculaciones, este método se llamará cuando ocurra "untie". Puede ser apropiado "auto CLOSE" cuando esto ocurra. Consulte "The "untie" Gotcha" a continuación.
DESTROY this
Al igual que con los otros tipos de vinculaciones, este método se llamará cuando el handle vinculado esté a punto de ser destruido. Esto es útil para la depuración y posiblemente para la limpieza. 
sub DESTROY { print "</shout>\n" }

Así es como se usa nuestro pequeño ejemplo:

tie(*FOO,'Shout');
print FOO "hello\n";
$x = 4; $y = 6;
print FOO $x, " plus ", $y, " equals ", $x + $y, "\n";
print <FOO>;

UNTIE this

Puede definir para todos los tipos de vinculación un método UNTIE que se llamará en untie(). Consulte "The "untie" Gotcha" a continuación.

El "untie" Gotcha

Si tiene la intención de utilizar el objeto devuelto por tie() o tied(), y si la clase de destino del vínculo define un destructor, hay una sutil trampa de la que debe protegerse.

Como configuración, considere este ejemplo (admitidamente bastante artificial) de un vínculo; todo lo que hace es usar un archivo para mantener un registro de los valores asignados a un escalar.

package Remember;
use v5.36;
use IO::File;
sub TIESCALAR {
    my $class = shift;
    my $filename = shift;
    my $handle = IO::File->new( "> $filename" )
                     or die "Cannot open $filename: $!\n";
    print $handle "The Start\n";
    bless {FH => $handle, Value => 0}, $class;
}
sub FETCH {
    my $self = shift;
    return $self->{Value};
}
sub STORE {
    my $self = shift;
    my $value = shift;
    my $handle = $self->{FH};
    print $handle "$value\n";
    $self->{Value} = $value;
}
sub DESTROY {
    my $self = shift;
    my $handle = $self->{FH};
    print $handle "The End\n";
    close $handle;
}
1;

Aquí hay un ejemplo que utiliza este vínculo:

use strict;
use Remember;
my $fred;
tie $fred, 'Remember', 'myfile.txt';
$fred = 1;
$fred = 4;
$fred = 5;
untie $fred;

NAME

perltie - tie() constructor and methods

SYNOPSIS

tie VARIABLE, CLASSNAME, LIST...
untie VARIABLE
CLASSNAME->TIE...
CLASSNAME->UNTIE...

DESCRIPTION

Tie allows you to associate a Perl variable with an object. When you access or modify the variable, the object's methods are called instead of Perl's normal operations. The tie() function takes a variable, a class name, and optionally a list of arguments. It calls the specified class's TIESCALAR, TIEARRAY, or TIEHASH method (depending on the variable type) to create the object that will represent the variable. The variable then acts as an alias for this object.

The untie() function breaks the association between the variable and its tied object. The object's DESTROY method (if defined) will be called when there are no more references to it.

The methods that can be defined in a tied object's class are:

  • TIESCALAR ($class, LIST...): Called by tie() to create a tied scalar. Should return the blessed object.

  • TIEARRAY ($class, LIST...): Called by tie() to create a tied array. Should return the blessed object.

  • TIEHASH ($class, LIST...): Called by tie() to create a tied hash. Should return the blessed object.

  • TIEHANDLE ($class, LIST...): Called by tie() to create a tied filehandle. Should return the blessed object.

  • STORE ($obj, $value): Called when the tied scalar is assigned to.

  • FETCH ($obj): Called when the tied scalar is read.

  • FETCHSIZE ($obj): Called when scalar(@array) is used on a tied array. Should return the number of elements.

  • STORE ($obj, $index, $value): Called when an element of the tied array is assigned to.

  • FETCH ($obj, $index): Called when an element of the tied array is read.

  • STORE ($obj, $key, $value): Called when an element of the tied hash is assigned to.

  • FETCH ($obj, $key): Called when an element of the tied hash is read.

  • DELETE ($obj, $key): Called when an element of the tied hash is deleted.

  • CLEAR ($obj): Called when the tied hash is cleared.

  • EXTEND ($obj, $size): Called when the tied array needs to grow.

  • PUSH ($obj, LIST...): Called when push() is used on a tied array.

  • POP ($obj): Called when pop() is used on a tied array. Should return the popped element.

  • SHIFT ($obj): Called when shift() is used on a tied array. Should return the shifted element.

  • UNSHIFT ($obj, LIST...): Called when unshift() is used on a tied array.

  • splice (@array, $offset, $length, LIST...): Called when splice() is used on a tied array.

  • DESTROY ($obj): Called when the tied object is destroyed (no more references).

  • UNTIE ($obj, $count): Called by untie(). If defined, it overrides DESTROY for the purposes of handling the untie operation. The $count argument is the number of internal references to the object that still exist.

There is a subtle but important difference between DESTROY and UNTIE. DESTROY is called when the object is no longer referenced anywhere. UNTIE is called specifically when untie() is invoked on a tied variable. If UNTIE is defined, it is called instead of DESTROY when untie() is used. This allows the class designer to control what happens when untie() is called, even if there are still other references to the tied object.

Consider the following example using a simple logging mechanism:

use strict;
use Remember; # Assume this module provides tie support for logging
my ($fred, $x);
$x = tie $fred, 'Remember', 'myfile.txt';
$fred = 1;
$fred = 4;
comment $x "changing..."; # Assuming 'comment' is a method of Remember
$fred = 5;
untie $fred;
system "cat myfile.txt";

When this code is executed there is no output. Here's why:

When a variable is tied, it is associated with the object which is the return value of the TIESCALAR, TIEARRAY, or TIEHASH function. This object normally has only one reference, namely, the implicit reference from the tied variable. When untie() is called, that reference is destroyed. Then, as in the first example above, the object's destructor (DESTROY) is called, which is normal for objects that have no more valid references; and thus the file is closed.

In the second example, however, we have stored another reference to the tied object in $x. That means that when untie() gets called there will still be a valid reference to the object in existence, so the destructor is not called at that time, and thus the file is not closed. The reason there is no output is because the file buffers have not been flushed to disk.

Now that you know what the problem is, what can you do to avoid it? Prior to the introduction of the optional UNTIE method the only way was the good old "-w" flag. Which will spot any instances where you call untie() and there are still valid references to the tied object. If the second script above this near the top "use warnings 'untie'" or was run with the "-w" flag, Perl prints this warning message:

untie attempted while 1 inner references still exist

To get the script to work properly and silence the warning make sure there are no valid references to the tied object before untie() is called:

undef $x;
untie $fred;

Now that UNTIE exists the class designer can decide which parts of the class functionality are really associated with "untie" and which with the object being destroyed. What makes sense for a given class depends on whether the inner references are being kept so that non-tie-related methods can be called on the object. But in most cases it probably makes sense to move the functionality that would have been in DESTROY to the UNTIE method.

If the UNTIE method exists then the warning above does not occur. Instead the UNTIE method is passed the count of "extra" references and can issue its own warning if appropriate. e.g. to replicate the no UNTIE case this method can be used:

sub UNTIE
{
 my ($obj,$count) = @_;
 carp "untie attempted while $count inner references still exist"
                                                             if $count;
}

SEE ALSO

See DB_File or Config for some interesting tie() implementations. A good starting point for many tie() implementations is with one of the modules Tie::Scalar, Tie::Array, Tie::Hash, or Tie::Handle.

BUGS

The normal return provided by scalar(%hash) is not available. What this means is that using %tied_hash in boolean context doesn't work right (currently this always tests false, regardless of whether the hash is empty or hash elements). [ This paragraph needs review in light of changes in 5.25 ]

Localizing tied arrays or hashes does not work. After exiting the scope the arrays or the hashes are not restored.

Counting the number of entries in a hash via "scalar(keys(%hash))" or scalar(values(%hash)) is inefficient since it needs to iterate through all the entries with FIRSTKEY/NEXTKEY.

Tied hash/array slices cause multiple FETCH/STORE pairs, there are no tie methods for slice operations.

You cannot easily tie a multilevel data structure (such as a hash of hashes) to a dbm file. The first problem is that all but GDBM and Berkeley DB have size limitations, but beyond that, you also have problems with how references are to be represented on disk. One module that does attempt to address this need is DBM::Deep. Check your nearest CPAN site as described in perlmodlib for source code. Note that despite its name, DBM::Deep does not use dbm. Another earlier attempt at solving the problem is MLDBM, which is also available on the CPAN, but which has some fairly serious limitations.

Tied filehandles are still incomplete. sysopen(), truncate(), flock(), fcntl(), stat() and -X can't currently be trapped.
