PERLSOURCE(1perl) Guía de Referencia del Programador de Perl PERLSOURCE(1perl)

NOMBRE

perlsource - Una guía del árbol de fuentes de Perl

DESCRIPCIÓN

Este documento describe la disposición del árbol de fuentes de Perl. Si estás modificando el núcleo de Perl, esto te ayudará a encontrar lo que buscas.

CÓMO ORIENTARSE

El árbol de fuentes de Perl es grande. Aquí hay algunas de las cosas que encontrarás en él:

Código C

El código fuente y los archivos de cabecera C se encuentran principalmente en la raíz del árbol de fuentes. Hay algunos directorios específicos de plataforma que contienen código C. Además, algunos de los módulos que se distribuyen con Perl incluyen código C o XS.

Ver perlinterp para más detalles sobre los archivos que componen el intérprete de Perl, así como detalles sobre cómo funciona.

Módulos principales

Los módulos que se distribuyen como parte del núcleo de Perl viven en cuatro subdirectorios. Dos de estos directorios contienen módulos que viven en el núcleo, y dos contienen módulos que también pueden ser lanzados separadamente en CPAN. Los módulos que pueden ser lanzados en cpan se conocen como módulos de "doble vida".

  • lib/

    Este directorio contiene módulos puros de Perl que solo se distribuyen como parte del núcleo. Este directorio contiene *todos* los módulos y sus pruebas, a diferencia de otros módulos del núcleo.

  • ext/

    Al igual que lib/, este directorio contiene módulos que solo se distribuyen como parte del núcleo. Sin embargo, a diferencia de lib/, un módulo en ext/ generalmente tiene un diseño de directorios y archivos al estilo de CPAN y su propio Makefile.PL. No se espera que un módulo en ext/ funcione con versiones anteriores de Perl 5. Por lo tanto, dicho módulo puede aprovechar al máximo las mejoras sintácticas y de otro tipo en Perl 5 blead.

  • dist/

    Este directorio es para módulos de doble vida donde la fuente blead es canónica. Tenga en cuenta que algunos módulos en este directorio pueden no haber sido lanzados aún por separado en CPAN. Los módulos en dist/ deben esforzarse por funcionar con versiones anteriores de Perl 5.

  • cpan/

    Este directorio contiene módulos de doble vida donde el módulo CPAN es canónico. ¡No parchees estos módulos directamente! Los cambios en estos módulos deben enviarse al mantenedor del módulo CPAN. Una vez que esos cambios se apliquen y se lancen, la nueva versión del módulo se incorporará al núcleo.

Para algunos módulos de doble vida, aún no se ha determinado si la versión de CPAN o la fuente blead es la canónica. Hasta que eso se haga, esos módulos deben estar en cpan/.

Pruebas

El núcleo de Perl tiene una extensa suite de pruebas. Si agregas nuevas pruebas (o nuevos módulos con pruebas), puede que necesites actualizar el archivo t/TEST para que las pruebas se ejecuten.

  • Pruebas de módulos

    Las pruebas para los módulos del núcleo en el directorio lib/ están justo al lado del módulo mismo. Por ejemplo, tenemos lib/strict.pm y lib/strict.t.

    Las pruebas para los módulos en ext/ y los módulos de doble vida se encuentran en subdirectorios de t/ para cada módulo, como una distribución estándar de CPAN.

  • t/base/

    Pruebas para la funcionalidad absolutamente básica de Perl. Esto incluye "if", lecturas y escrituras básicas de archivos, regex simples, etc. Estas se ejecutan primero en la suite de pruebas y si alguna de ellas falla, algo está *realmente* roto.

  • t/cmd/

    Pruebas para estructuras de control básicas, "if"/"else", "while", subrutinas, etc.

  • t/comp/

    Pruebas para problemas básicos de cómo Perl analiza y compila en sí mismo.

  • t/io/

    Pruebas para funciones de E/S incorporadas, incluyendo argumentos de línea de comandos.

  • t/mro/

    Pruebas para las implementaciones del orden de resolución de métodos de perl (ver mro).

  • t/op/

    Pruebas para las funciones incorporadas de perl que no encajan en ninguno de los otros directorios.

  • t/opbasic/

    Pruebas para las funciones incorporadas de perl que, al igual que las de t/op/, no encajan en ninguno de los otros directorios, pero que, además, no pueden usar t/test.pl, ya que ese programa depende de la funcionalidad que el propio archivo de prueba está probando.

  • t/re/

    Pruebas para funciones o comportamientos relacionados con regex. (Estos solían vivir en t/op).

  • t/run/

    Pruebas para características de cómo se ejecuta perl, incluyendo códigos de salida y manejo de variables de entorno PERL*.

  • t/uni/

    Pruebas para el soporte del núcleo de Unicode.

  • t/win32/

    Pruebas específicas de Windows.

  • t/porting/

    Prueba el estado del árbol de fuentes para varios errores comunes. Por ejemplo, prueba que todos los que están listados en el historial de git tengan una entrada correspondiente en el archivo AUTHORS.

  • t/lib/

    El antiguo hogar de las pruebas de módulos, no deberías poner nada nuevo aquí. Todavía hay algunas partes y piezas que necesitan ser movidas. ¿Quizás podrías moverlas? ¡Gracias!

Documentación

Toda la documentación del núcleo destinada a los usuarios finales vive en pod/. Los módulos individuales en lib/, ext/, dist/ y cpan/ suelen tener su propia documentación, ya sea en el archivo Module.pm o en un archivo Module.pod acompañante.

Finalmente, la documentación destinada a los desarrolladores del núcleo de Perl vive en el directorio Porting/.

Herramientas y documentación para hacking

El directorio Porting contiene una mezcla de código y documentación destinada a ayudar a los portadores a trabajar en Perl. Algunos de los aspectos más destacados incluyen:

  • check*

    Estos son scripts que comprobarán las fuentes en busca de violaciones de C ANSI, problemas de codificación de POD, etc.

  • Maintainers, Maintainers.pl y Maintainers.pm

    Estos archivos contienen información sobre quién mantiene qué módulos. Ejecuta "perl Porting/Maintainers -M Module::Name" para obtener más información sobre un módulo de doble vida.

  • podtidy

    Limpia un archivo pod. Es una buena idea ejecutarlo en un archivo pod que hayas parcheado.

Sistema de compilación

El sistema de compilación de Perl en sistemas tipo *nix comienza con el script Configure en el directorio raíz.

Las piezas específicas de la plataforma del sistema de compilación también viven en directorios específicos de plataforma como win32/, vms/, etc. Windows y VMS tienen sus propios scripts similares a Configure, en sus directorios respectivos.

El script Configure (o un script similar específico de la plataforma) es en última instancia responsable de generar un Makefile a partir de Makefile.SH.

El sistema de compilación que usa Perl se llama metaconfig. Este sistema se mantiene por separado del núcleo de Perl, y conoce los scripts similares a Configure específicos de plataforma, así como Configure mismo.

El sistema metaconfig tiene su propio repositorio git. Por favor, consulta su archivo README en https://github.com/Perl/metaconfig para más detalles.

El directorio Cross contiene varios archivos relacionados con la compilación cruzada de Perl. Ver Cross/README para más detalles.

AUTHORS

Este archivo lista a todos los que han contribuido a Perl. Si envías un parche, deberías añadir tu nombre a este archivo como parte del parche.

MANIFEST

El archivo MANIFEST en la raíz del árbol de fuentes contiene una lista de cada archivo en el núcleo de Perl, así como una breve descripción de cada archivo.
