perldata - Tipos de datos de Perl

DESCRIPCIÓN

Nombres de variables

Perl tiene tres tipos de datos incorporados: escalares, arrays de escalares y arrays asociativos de escalares, conocidos como "hashes". Un escalar es una única cadena (de cualquier tamaño, limitado solo por la memoria disponible), un número o una referencia a algo (que se discutirá en perlref). Los arrays normales son listas ordenadas de escalares indexadas por número, comenzando con 0. Los hashes son colecciones desordenadas de valores escalares indexados por su clave de cadena asociada.

Los valores generalmente se refieren por nombre, o a través de una referencia con nombre. El primer carácter del nombre te dice a qué tipo de estructura de datos se refiere. Este carácter se llama "sigil". El resto del nombre te dice el valor particular al que se refiere. Normalmente, este nombre es un único *identificador*, es decir, una cadena que comienza con una letra o guion bajo, y que contiene letras, guiones bajos y dígitos. En algunos casos, puede ser una cadena de identificadores, separados por "::" (o por el obsoleto "'"); todos excepto el último se interpretan como nombres de paquetes, para ubicar el espacio de nombres en el que buscar el identificador final (ver "Packages" en perlmod para más detalles). Para una discusión más profunda sobre identificadores, ver "Identifier parsing". Es posible sustituir un identificador simple por una expresión que produzca una referencia al valor en tiempo de ejecución. Esto se describe con más detalle a continuación y en perlref. Es legal, pero no se recomienda, separar el sigil de una variable de su nombre con caracteres de espacio y/o tabulación.

Perl también tiene sus propias variables incorporadas cuyos nombres no siguen estas reglas. Tienen nombres extraños para que no colisionen accidentalmente con ninguna de sus variables normales. Las cadenas que coinciden con partes entre paréntesis de una expresión regular se guardan bajo nombres que contienen solo dígitos después del "$" (ver perlop y perlre). Además, varias variables especiales que proporcionan ventanas al funcionamiento interno de Perl tienen nombres que contienen caracteres de puntuación. Estos se documentan en perlvar.

Los valores escalares siempre se nombran con el sigil '$', incluso cuando se refieren a un escalar que forma parte de un array o un hash. El símbolo '$' funciona semánticamente como la palabra inglesa "el" en el sentido de que indica que se espera un único valor.

$dias               # el valor escalar simple "dias"
$dias[28]           # el elemento 29 del array @dias
$dias{'Feb'}        # el valor 'Feb' del hash %dias
$#dias              # el último índice del array @dias

Los arrays completos (y las rebanadas de arrays y hashes) se indican con el sigil '@', que funciona de manera similar a las palabras "estos" o "esas" en español, en el sentido de que indica que se esperan múltiples valores.

@dias               # ($dias[0], $dias[1],... $dias[n])
@dias[3,4,5]        # lo mismo que ($dias[3],$dias[4],$dias[5])
@dias{'a','c'}      # lo mismo que ($dias{'a'},$dias{'c'})

Los hashes completos se indican con el sigil '%':

%dias               # (clave1, valor1, clave2, valor2 ...)

Además, las subrutinas se nombran con un sigil inicial '&', aunque esto es opcional cuando no es ambiguo, al igual que la palabra "hacer" a menudo es redundante en español. Las entradas de la tabla de símbolos se pueden nombrar con un '*' inicial, pero aún no te importa mucho (si es que alguna vez te importa :-)).

Cada tipo de variable tiene su propio espacio de nombres, al igual que varios identificadores no variables. Esto significa que puede usar el mismo nombre para una variable escalar, un array o un hash, o incluso para un manejador de archivos, un manejador de directorios, un nombre de subrutina, un nombre de formato o una etiqueta, sin temor a conflictos. Esto significa que $foo y @foo son dos variables diferentes. También significa que $foo[1] es parte de @foo, no de $foo. Esto puede parecer un poco extraño, pero está bien, porque es extraño.

Dado que las referencias a variables siempre comienzan con los sigilos '$', '@' o '%', las palabras "reservadas" no son en realidad reservadas con respecto a los nombres de variables. Sin embargo, *son* reservadas con respecto a etiquetas y manejadores de archivos, que no tienen un carácter especial inicial. Por ejemplo, no puede tener un manejador de archivos llamado "log". Consejo: podría decir "open(LOG,'logfile')" en lugar de "open(log,'logfile')". Usar manejadores de archivos en mayúsculas también mejora la legibilidad y lo protege de conflictos con futuras palabras reservadas. Las mayúsculas y minúsculas *son* significativas: "FOO", "Foo" y "foo" son nombres diferentes. Los nombres que comienzan con una letra o guion bajo también pueden contener dígitos y guiones bajos.

Es posible reemplazar un nombre alfanumérico de este tipo con una expresión que devuelva una referencia al tipo apropiado. Para una descripción de esto, ver perlref.

Los nombres que comienzan con un dígito solo pueden contener más dígitos. Los nombres que no comienzan con una letra, guion bajo, dígito o un circunflejo se limitan a un carácter, por ejemplo, $% o $$. (La mayoría de estos nombres de un solo carácter tienen un significado predefinido para Perl. Por ejemplo, $$ es el ID del proceso actual. Y todos estos nombres están reservados para el posible uso de Perl.)

Análisis de identificadores

Hasta Perl 5.18, las reglas reales de lo que constituía un identificador válido eran un poco imprecisas. Sin embargo, en general, todo lo definido aquí debería funcionar en versiones anteriores de Perl, mientras que lo contrario (casos extremos que funcionan en versiones anteriores, pero no se definen aquí) probablemente no funcionará en versiones más nuevas. Como nota lateral importante, tenga en cuenta que lo siguiente solo se aplica a los identificadores de palabra desnuda tal como se encuentran en el código fuente de Perl, no a los identificadores introducidos a través de referencias simbólicas, que tienen muchas menos restricciones. Si está bajo el efecto de la pragmática "use utf8;", se aplican las siguientes reglas:

/ (?[ ( \p{Word} & \p{XID_Start} ) + [_] ])
  (?[ ( \p{Word} & \p{XID_Continue} ) ]) *    /x

Es decir, un carácter de "inicio" seguido de cualquier número de caracteres de "continuación". Perl requiere que cada carácter de un identificador también coincida con "\w" (esto evita algunos casos problemáticos); y Perl también acepta nombres de identificadores que comienzan con un guion bajo.

Si no está bajo "use utf8", la fuente se trata como ASCII + 128 caracteres genéricos adicionales, y los identificadores deben coincidir

/ (?aa) (?!\d) \w+ /x

Es decir, cualquier carácter de palabra en el rango ASCII, siempre que el primer carácter no sea un dígito.

Hay un separador de paquetes en Perl: dos puntos ("::"). Los identificadores normales pueden comenzar o terminar con dos puntos, y pueden contener varias partes delimitadas por dos puntos.

Anteriormente se podía usar "'" como separador de paquetes; esto se eliminó en Perl 5.42.

Además, si el identificador va precedido por un sigil, es decir, si el identificador es parte de un nombre de variable, opcionalmente puede encerrarse entre llaves. Por ejemplo, "${name}", "@{bigcats}", "%{pizza_toppings}".

Juntas, una gramática para hacer coincidir un identificador básico se convierte en

/
 (?(DEFINE)
     (?<variable>
         (?&sigil)
         (?:
                 (?&normal_identifier)
             |   \{ \s* (?&normal_identifier) \s* \}
         )
     )
     (?<normal_identifier>
         (?: :: )*
          (?&basic_identifier)
          (?: (?= :: ) (?&normal_identifier) )?
         (?: :: )*
     )
     (?<basic_identifier>
       # ¿ está use utf8 activado?
         (?(?{ (caller(0))[8] & $utf8::hint_bits })
             (?&Perl_XIDS) (?&Perl_XIDC)*
           | (?aa) (?!\d) \w+
         )
     )
     (?<sigil> \$\# | [&*\$\@%])
     (?<Perl_XIDS> (?[ ( \p{Word} & \p{XID_Start} ) + [_] ]) )
     (?<Perl_XIDC> (?[ \p{Word} & \p{XID_Continue} ]) )
 )
/x

Mientras tanto, los identificadores especiales no siguen las reglas anteriores; En su mayor parte, todos los identificadores de esta categoría tienen un significado especial dado por Perl. Debido a que tienen reglas de análisis especiales, estos generalmente no se pueden calificar completamente.

VARIABLES

Variables are named memory locations. Perl has three fundamental variable types, distinguished by their introductory character (the sigil):

  • $: scalar variables (holding single values like numbers or strings)
  • @: array variables (holding ordered lists of scalars)
  • %: hash variables (holding unordered key/value pairs of scalars)

Scalar variables are typically named with a letter or underscore, followed by letters, digits, or underscores. Array and hash variables are named similarly, but may also contain other characters when interpolated into strings, or when constructed in certain ways.

There are six ways to form variables in Perl, but forms 5 and 6 are rarely seen and generally discouraged.

1.
A sigil, followed solely by digits matching "\p{POSIX_Digit}", like $0, $1, or $10000.
2.
A sigil followed by a single character matching the "\p{POSIX_Punct}" property, like $! or "%+", except the character "{" doesn't work.
3.
A sigil, followed by a caret and any one of the characters "[][A-Z^_?\]", like $^V or $^].
4.
Similar to the above, a sigil, followed by bareword text in braces, where the first character is a caret. The next character is any one of the characters "[][A-Z^_?\]", followed by ASCII word characters. An example is "${^GLOBAL_PHASE}".
5.
A sigil, followed by any single character in the range "[\xA1-\xAC\xAE-\xFF]" when not under "use utf8". (Under "use utf8", the normal identifier rules given earlier in this section apply.) Use of non-graphic characters (the C1 controls, the NO-BREAK SPACE, and the SOFT HYPHEN) has been disallowed since v5.26.0. The use of the other characters is unwise, as these are all reserved to have special meaning to Perl, and none of them currently do have special meaning, though this could change without notice.

Note that an implication of this form is that there are identifiers only legal under "use utf8", and vice-versa, for example the identifier $état is legal under "use utf8", but is otherwise considered to be the single character variable $é followed by the bareword "tat", the combination of which is a syntax error.

6.
This is a combination of the previous two forms. It is valid only when not under "use utf8" (normal identifier rules apply when under "use utf8"). The form is a sigil, followed by text in braces, where the first character is any one of the characters in the range "[\x80-\xFF]" followed by ASCII word characters up to the trailing brace.

The same caveats as the previous form apply: The non-graphic characters are no longer allowed with "use utf8", it is unwise to use this form at all, and utf8ness makes a big difference.

Prior to Perl v5.24, non-graphical ASCII control characters were also allowed in some situations; this had been deprecated since v5.20.

Context

The interpretation of operations and values in Perl sometimes depends on the requirements of the context around the operation or value. There are two major contexts: list and scalar. Certain operations return list values in contexts wanting a list, and scalar values otherwise. If this is true of an operation it will be mentioned in the documentation for that operation. In other words, Perl overloads certain operations based on whether the expected return value is singular or plural. Some words in English work this way, like "fish" and "sheep".

In a reciprocal fashion, an operation provides either a scalar or a list context for each of its arguments. For example, if you say

int( <STDIN> )

the integer operation provides scalar context for the <> operator, which responds by reading one line from STDIN and passing it back to the integer operation, which will then find the integer value of that line and return that. If, on the other hand, you say

sort( <STDIN> )

then the sort operation provides list context for <>, which will proceed to read every line available up to the end of file, and pass that list of lines back to the sort routine, which will then sort those lines and return them as a list to whatever the context of the sort was.

Assignment is a little bit special in that it uses its left argument to determine the context for the right argument. Assignment to a scalar evaluates the right-hand side in scalar context, while assignment to an array or hash evaluates the righthand side in list context. Assignment to a list (or slice, which is just a list anyway) also evaluates the right-hand side in list context.

When you use the "use warnings" pragma or Perl's -w command-line option, you may see warnings about useless uses of constants or functions in "void context". Void context just means the value has been discarded, such as a statement containing only ""fred";" or "getpwuid(0);". It still counts as scalar context for functions that care whether or not they're being called in list context.

User-defined subroutines may choose to care whether they are being called in a void, scalar, or list context. Most subroutines do not need to bother, though. That's because both scalars and lists are automatically interpolated into lists. See "wantarray" in perlfunc for how you would dynamically discern your function's calling context.

Scalar values

All data in Perl is a scalar, an array of scalars, or a hash of scalars. A scalar may contain one single value in any of three different flavors: a number, a string, or a reference. In general, conversion from one form to another is transparent. Although a scalar may not directly hold multiple values, it may contain a reference to an array or hash which in turn contains multiple values.

Scalars aren't necessarily one thing or another. There's no place to declare a scalar variable to be of type "string", type "number", type "reference", or anything else. Because of the automatic conversion of scalars, operations that return scalars don't need to care (and in fact, cannot care) whether their caller is looking for a string, a number, or a reference. Perl is a contextually polymorphic language whose scalars can be strings, numbers, or references (which includes objects). Although strings and numbers are considered pretty much the same thing for nearly all purposes, references are strongly-typed, uncastable pointers with builtin reference-counting and destructor invocation.

A scalar value is interpreted as FALSE in the Boolean sense if it is undefined, the null string or the number 0 (or its string equivalent, "0"), and TRUE if it is anything else. The Boolean context is just a special kind of scalar context where no conversion to a string or a number is ever performed. Negation of a true value by "!" or "not" returns a special false value. When evaluated as a string it is treated as "", but as a number, it is treated as 0. Most Perl operators that return true or false behave this way.

There are actually two varieties of null strings (sometimes referred to as "empty" strings), a defined one and an undefined one. The defined version is just a string of length zero, such as "". The undefined version is the value that indicates that there is no real value for something, such as when there was an error, or at end of file, or when you refer to an uninitialized variable or element of an array or hash. Although in early versions of Perl, an undefined scalar could become defined when first used in a place expecting a defined value, this no longer happens except for rare cases of autovivification as explained in perlref. You can use the defined() operator to determine whether a scalar value is defined (this has no meaning on arrays or hashes), and the undef() operator to produce an undefined value.

To find out whether a given string is a valid non-zero number, it's sometimes enough to test it against both numeric 0 and also lexical "0" (although this will cause noises if warnings are on). That's because strings that aren't numbers count as 0, just as they do in awk:

if ($str == 0 && $str ne "0")  {
    warn "That doesn't look like a number";
}

That method may be best because otherwise you won't treat IEEE notations like "NaN" or "Infinity" properly. At other times, you might prefer to determine whether string data can be used numerically by calling the POSIX::strtod() function or by inspecting your string with a regular expression (as documented in perlre).

warn "has nondigits"        if     /\D/;
warn "not a natural number" unless /^\d+$/;             # rejects -3
warn "not an integer"       unless /^-?\d+$/;           # rejects +3
warn "not an integer"       unless /^[+-]?\d+$/;
warn "not a decimal number" unless /^-?\d+\.?\d*$/;     # rejects .2
warn "not a decimal number" unless /^-?(?:\d+(?:\.\d*)?|\.\d+)$/;
warn "not a C float"
    unless /^([+-]?)(?=\d|\.\d)\d*(\.\d*)?([Ee]([+-]?\d+))?$/;

The length of an array is a scalar value. You may find the length of array @days by evaluating $#days, as in csh. However, this isn't the length of the array; it's the subscript of the last element, which is a different value since there is ordinarily a 0th element. Assigning to $#days actually changes the length of the array. Shortening an array this way destroys intervening values. Lengthening an array that was previously shortened does not recover values that were in those elements.

You can also gain some minuscule measure of efficiency by pre-extending an array that is going to get big. You can also extend an array by assigning to an element that is off the end of the array. You can truncate an array down to nothing by assigning the null list () to it. The following are equivalent:

@whatever = ();
$#whatever = -1;

If you evaluate an array in scalar context, it returns the length of the array. (Note that this is not true of lists, which return the last value, like the C comma operator, nor of built-in functions, which return whatever they feel like returning.) The following is always true:

scalar(@whatever) == $#whatever + 1;

Escalares

Los escalares son el tipo de datos más simple en Perl. Pueden contener un número entero, un número de punto flotante, o una cadena de texto. Los escalares también pueden contener una referencia a otro tipo de datos (un array, un hash, u otro escalar).

Cuando un escalar se evalúa en un contexto numérico, Perl intenta convertirlo a un número. Si contiene una cadena que no se parece a un número, Perl la considera como el número 0. Si el escalar está vacío, se considera 0.

Cuando un escalar se evalúa en un contexto de cadena, Perl lo trata como una cadena. Si el escalar contiene un número, Perl lo convierte en una cadena.

Los siguientes ejemplos ilustran el comportamiento de los escalares en diferentes contextos:

$a = 10;
print $a;       # Imprime 10 (numérico)
print "$a";     # Imprime 10 (cadena)

$b = "123.45";
print $b + 0;   # Imprime 123.45 (numérico)
print $b;       # Imprime 123.45 (cadena)

$c = "";
print $c + 0;   # Imprime 0 (numérico)
print $c;       # Imprime "" (cadena vacía)

$d = "hello";
print $d + 0;   # Imprime 0 (numérico)
print $d;       # Imprime hello (cadena)

Si necesitas asegurarte de que un escalar se trata como un número, puedes usar la función scalar(). Esto es útil para evitar ambigüedades, especialmente cuando se trabaja con arrays o hashes.

$element_count = scalar(@whatever);

Si evalúas un hash en contexto escalar, devuelve un valor falso si el hash está vacío. Si hay algún par clave/valor, devuelve un valor verdadero. Una definición más precisa depende de la versión.

Antes de Perl 5.25, el valor devuelto era una cadena que consistía en el número de cubetas utilizadas y el número de cubetas asignadas, separadas por una barra. Esto es bastante útil solo para averiguar si el algoritmo de hash interno de Perl está funcionando mal en tu conjunto de datos. Por ejemplo, si pones 10,000 elementos en un hash, pero al evaluar %HASH en contexto escalar revela "1/16", lo que significa que solo una de cada dieciséis cubetas ha sido utilizada y, presumiblemente, contiene los 10,000 elementos. Esto no debería suceder.

A partir de Perl 5.25, el valor devuelto se cambió para que sea el recuento de claves en el hash. Si necesitas acceder al comportamiento anterior, puedes usar Hash::Util::bucket_ratio() en su lugar.

Si un hash enlazado se evalúa en contexto escalar, se llama al método "SCALAR" (con un fallback a "FIRSTKEY").

Puedes preasignar espacio para un hash asignando a la función keys(). Esto redondea las cubetas asignadas a la siguiente potencia de dos:

keys(%users) = 1000;                # asigna 1024 cubetas

Constructores de valores escalares

Los literales numéricos se especifican en cualquiera de los siguientes formatos de punto flotante o enteros:

12345
12345.67
.23E-10             # un número muy pequeño
3.14_15_92          # un número muy importante
4_294_967_296       # guion bajo para legibilidad
0xff                # hexadecimal
0xdead_beef         # más hexadecimal
0377                # octal (solo números, comienza con 0)
0o12_345            # octal alternativo (introducido en Perl 5.33.5)
0b011011            # binario
0x1.999ap-4         # punto flotante hexadecimal (la 'p' es obligatoria)
07.65p2             # punto flotante octal (la 'p' es obligatoria)
0o7.65p2            # punto flotante octal alternativo
0b101.01p-1         # punto flotante binario (la 'p' es obligatoria)

Se te permite usar guiones bajos en literales numéricos entre dígitos para legibilidad (pero no guiones bajos múltiples seguidos: "23__500" no es legal; "23_500" sí lo es). Podrías, por ejemplo, agrupar dígitos binarios de tres en tres (como para un argumento de modo estilo Unix como 0b110_100_100) o de cuatro en cuatro (para representar nibbles, como en 0b1010_0110) u otros grupos.

Los literales de cadena suelen estar delimitados por comillas simples o dobles. Funcionan de manera muy similar a las comillas en los shells estándar de Unix: los literales de cadena entre comillas dobles están sujetos a sustitución de barras invertidas y variables; las cadenas entre comillas simples no (excepto por "\'" y "\\"). Las reglas habituales de barras invertidas al estilo C se aplican para caracteres como nueva línea, tabulación, etc., así como algunas formas más exóticas. Consulte "Quote and Quote-like Operators" en perlop para obtener una lista.

Las representaciones hexadecimales, octales o binarias en literales de cadena (por ejemplo, '0xff') no se convierten automáticamente a su representación entera. Las funciones hex() y oct() realizan estas conversiones por ti. Consulte "hex" en perlfunc y "oct" en perlfunc para obtener más detalles.

El punto flotante hexadecimal puede comenzar de manera similar a un literal hexadecimal, y puede ir seguido de una parte fraccionaria hexadecimal opcional, pero debe ir seguido de "p", un signo opcional y una potencia de dos. El formato es útil para presentar valores de punto flotante con precisión, evitando conversiones desde o hacia punto flotante decimal y, por lo tanto, evitando posibles pérdidas de precisión. Tenga en cuenta que, si bien la mayoría de las plataformas actuales utilizan el estándar IEEE 754 de 64 bits para punto flotante, no todas lo hacen. Otra fuente potencial de diferencias (de bajo orden) son los modos de redondeo de punto flotante, que pueden diferir entre CPUs, sistemas operativos y compiladores, y que Perl no controla.

Los números de punto flotante octales y binarios utilizan el mismo formato que los números de punto flotante hexadecimales, pero limitados a dígitos binarios y octales, respectivamente.

También puedes incrustar saltos de línea directamente en tus cadenas, es decir, pueden terminar en una línea diferente a la que comenzaron. Esto es agradable, pero si olvidas tu comilla de cierre, el error no se informará hasta que Perl encuentre otra línea que contenga el carácter de comilla, que puede estar mucho más adelante en el script. La sustitución de variables dentro de cadenas se limita a variables escalares, arrays y rebanadas de arrays o hashes. (En otras palabras, nombres que comienzan con $ o @, seguidos de una expresión opcional entre corchetes como subíndice). El siguiente segmento de código imprime "The price is $100."

$Price = '$100';    # no interpolado
print "The price is $Price.\n";     # interpolado

No hay doble interpolación en Perl, por lo que $100 se deja tal cual.

Por defecto, los números de punto flotante sustituidos dentro de las cadenas utilizan el punto (".") como separador decimal. Si "use locale" está activo y se ha llamado a POSIX::setlocale(), el carácter utilizado para el separador decimal se ve afectado por la configuración regional LC_NUMERIC. Consulte perllocale y POSIX.

Nombres de variables delimitados con llaves

Al igual que en algunos shells, puedes encerrar el nombre de la variable entre llaves como un delimitador para desambiguarlo de alfanuméricos y guiones bajos subsiguientes u otro texto. También debes hacerlo al interpolar una variable en una cadena para separar el nombre de la variable de un doble dos puntos o un apóstrofo subsiguientes, ya que de lo contrario se tratarían como un separador de paquete:

$who = "Larry";
print PASSWD "${who}::0:0:Superuser:/:/bin/perl\n";
print "We use ${who}speak when ${who}'s here.\n";

Sin las llaves, Perl habría buscado una variable $whospeak, una $who::0 y una variable "$who's". Las dos últimas serían las variables $0 y $s en el paquete (presumiblemente) inexistente "who".

De hecho, un identificador simple dentro de dichas llaves se fuerza a ser una cadena, y de manera similar dentro de un subíndice de hash. Ninguno de los dos necesita comillas. Nuestro ejemplo anterior, $days{'Feb'} se puede escribir como $days{Feb} y las comillas se asumirán automáticamente. Pero cualquier cosa más compleja en el subíndice se interpretará como una expresión. Esto significa, por ejemplo, que "$version{2.0}++" es equivalente a "$version{2}++", no a "$version{'2.0'}++".

Existe un problema similar con la interpolación con texto que se parece a la notación de acceso a arrays o hashes. Colocar una variable simple como $who inmediatamente antes de texto como "[1]" o "{foo}" haría que la variable se interpolara como el acceso a un elemento de @who o un valor almacenado en %who:

$who = "Larry Wall";
print "$who[1] is the father of Perl.\n";

intentaría acceder al índice 1 de un array llamado @who. Nuevamente, usar llaves evitará que esto suceda:

$who = "Larry Wall";
print "${who}[1] is the father of Perl.\n";

será tratado de la misma manera que

$who = "Larry Wall";
print $who . "[1] is the father of Perl.\n";

Esta notación también se aplica a descripciones de variables más complejas, como el acceso a arrays o hashes con subíndices. Por ejemplo

@name = qw(Larry Curly Moe);
print "Also ${name[0]}[1] was a member\n";

Sin las llaves, el ejemplo anterior se analizaría como un subíndice de array de dos niveles en el array @name, y bajo "use strict" probablemente produciría una excepción fatal, ya que se analizaría de la siguiente manera:

print "Also " . $name[0][1] . " was a member\n";

y no como la intención:

print "Also " . $name[0] . "[1] was a member\n";

Un resultado similar puede obtenerse usando una barra invertida en el primer carácter del subíndice o la notación de paquete que no forma parte de la variable a la que deseas acceder. Por lo tanto, el ejemplo anterior también podría escribirse:

@name = qw(Larry Curly Moe);
print "Also $name[0]\[1] was a member\n";

sin embargo, para algunas variables especiales (variables de tipo caret de varios caracteres) la forma delimitada con llaves es la **única** forma en que puedes referenciar la variable en absoluto, y la única forma en que puedes acceder a un subíndice de la variable a través de la interpolación.

Considere el array mágico "@{^CAPTURE}" que es poblado por el motor de expresiones regulares con el contenido de todos los búferes de captura en un patrón (ver perlvar y perlre). La **única** forma de acceder a uno de estos miembros dentro de una cadena es a través de la forma delimitada por llaves:

"abc"=~/(.)(.)(.)/
    and print "Second buffer is ${^CAPTURE[1]}";

es equivalente a

"abc"=~/(.)(.)(.)/
    and print "Second buffer is " . ${^CAPTURE}[1];

Decir "@^CAPTURE" es un error de sintaxis, por lo que **debe** referenciarse como "@{^CAPTURE}", y para acceder a uno de sus elementos en código normal escribirías " ${^CAPTURE}[1] ". Sin embargo, al interpolar en una cadena "${^CAPTURE}[1]" sería equivalente a "${^CAPTURE} . "[1]"", lo que ni siquiera se refiere a la misma variable! Por lo tanto, los subíndices **también** deben colocarse **dentro** de las llaves: "${^CAPTURE[1]}".

La forma delimitada con llaves se puede usar con todos los diferentes tipos de acceso a variables, incluidas las rebanadas de arrays y hashes. Por ejemplo, código como el siguiente:

@name = qw(Larry Curly Moe);
local $" = " and ";
print "My favorites were @{name[1,2]}.\n";

produciría

My favorites were Curly and Moe.

Literales

A literal is a sequence of characters that represents a constant value. Perl has literals for strings, numbers, and references.

Perl doesn't have a literal for arrays or hashes, but you can get them using the list constructor (), or [] and {} when used in certain contexts.

Literales Numéricos

Perl supports both traditional decimal, hexadecimal, and octal literals, and also floating-point literals. It also has special support for floating-point infinities and NaNs.

Decimal literals are written as a sequence of digits, optionally followed by a decimal point and more digits. You may have an optional exponent part, written as e or E, followed by an optional sign and exponent digits. If the literal contains a decimal point or an exponent part, it is a floating-point literal; otherwise, it is an integer literal.

12345
0.0
-7.5
7.5e0
7.5E0
7.5e1
7.5E1
7.5e-1
7.5E-1

Hexadecimal literals start with 0x, and may contain digits and the letters a- f (case-insensitive). Octal literals start with 0, and may contain digits 0-7.

0x1f         # 31
0X1F         # 31
017          # 15 (octal)

Perl's floating-point literals are parsed in a way that permits some operations to overflow the floating point range, resulting in Inf. For example, 9**9**9 will produce Inf, because 9**9**9 is simply too large to be represented as a standard double-precision floating-point number. Inf is the result of certain math operations that overflow the floating point range, like 9**9**9. The not-a-number is the result when the result is undefined or unrepresentable. Though note that you cannot get "NaN" from some common "undefined" or "out-of-range" operations like dividing by zero, or square root of a negative number, since Perl generates fatal errors for those.

The infinity and not-a-number have their own special arithmetic rules. The general rule is that they are "contagious": "Inf" plus one is "Inf", and "NaN" plus one is "NaN". Where things get interesting is when you combine infinities and not-a-numbers: "Inf" minus "Inf" and "Inf" divided by "Inf" are "NaN" (while "Inf" plus "Inf" is "Inf" and "Inf" times "Inf" is "Inf"). "NaN" is also curious in that it does not equal any number, including itself: "NaN" != "NaN".

Perl doesn't understand "Inf" and "NaN" as numeric literals, but you can have them as strings, and Perl will convert them as needed: "Inf" + 1. (You can, however, import them from the POSIX extension; "use POSIX qw(Inf NaN);" and then use them as literals.)

Note that on input (string to number) Perl accepts "Inf" and "NaN" in many forms. Case is ignored, and the Win32-specific forms like "1.#INF" are understood, but on output the values are normalized to "Inf" and "NaN".

Version Strings

A literal of the form "v1.20.300.4000" is parsed as a string composed of characters with the specified ordinals. This form, known as v-strings, provides an alternative, more readable way to construct strings, rather than use the somewhat less readable interpolation form "\x{1}\x{14}\x{12c}\x{1fa0}". This is useful for representing Unicode strings, and for comparing version "numbers" using the string comparison operators, "cmp", "gt", "lt" etc. If there are two or more dots in the literal, the leading "v" may be omitted.

print v9786;              # prints SMILEY, "\x{263a}"
print v102.111.111;       # prints "foo"
print 102.111.111;        # same

Such literals are accepted by both "require" and "use" for doing a version check. Note that using the v-strings for IPv4 addresses is not portable unless you also use the inet_aton()/inet_ntoa() routines of the Socket package.

Note that since Perl 5.8.1 the single-number v-strings (like "v65") are not v-strings before the "=>" operator (which is usually used to separate a hash key from a hash value); instead they are interpreted as literal strings ('v65'). They were v-strings from Perl 5.6.0 to Perl 5.8.0, but that caused more confusion and breakage than good. Multi-number v-strings like "v65.66" and 65.66.67 continue to be v-strings always.

Special Literals

The special literals __FILE__, __LINE__, and __PACKAGE__ represent the current filename, line number, and package name at that point in your program. __SUB__ gives a reference to the current subroutine. They may be used only as separate tokens; they will not be interpolated into strings. If there is no current package (due to an empty "package;" directive), __PACKAGE__ is the undefined value. (But the empty "package;" is no longer supported, as of version 5.10.) Outside of a subroutine, __SUB__ is the undefined value. __SUB__ is only available in 5.16 or higher, and only with a "use v5.16" or "use feature "current_sub"" declaration.

The two control characters ^D and ^Z, and the tokens __END__ and __DATA__ may be used to indicate the logical end of the script before the actual end of file. Any following text is ignored by the interpreter unless read by the program as described below.

Text after __DATA__ may be read via the filehandle "PACKNAME::DATA", where "PACKNAME" is the package that was current when the __DATA__ token was encountered. The filehandle is left open pointing to the line after __DATA__. The program should "close DATA" when it is done reading from it. (Leaving it open leaks filehandles if the module is reloaded for any reason, so it's a safer practice to close it.) For compatibility with older scripts written before __DATA__ was introduced, __END__ behaves like __DATA__ in the top level script (but not in files loaded with "require" or "do") and leaves the remaining contents of the file accessible via "main::DATA".

while (my $line = <DATA>) { print $line; }
close DATA;
__DATA__
Hello world.

The "DATA" file handle by default has whatever PerlIO layers were in place when Perl read the file to parse the source. Normally that means that the file is being read bytewise, as if it were encoded in Latin-1, but there are two major ways for it to be otherwise. Firstly, if the "__END__"/"__DATA__" token is in the scope of a "use utf8" pragma then the "DATA" handle will be in UTF-8 mode. And secondly, if the source is being read from perl's standard input then the "DATA" file handle is actually aliased to the "STDIN" file handle, and may be in UTF-8 mode because of the "PERL_UNICODE" environment variable or perl's command-line switches.

See SelfLoader for more description of __DATA__, and an example of its use. Note that you cannot read from the DATA filehandle in a BEGIN block: the BEGIN block is executed as soon as it is seen (during compilation), at which point the corresponding __DATA__ (or __END__) token has not yet been seen.

Barewords

A word that has no other interpretation in the grammar will be treated as if it were a quoted string. These are known as "barewords". As with filehandles and labels, a bareword that consists entirely of lowercase letters risks conflict with future reserved words, and if you use the "use warnings" pragma or the -w switch, Perl will warn you about any such words. Perl limits barewords (like identifiers) to about 250 characters. Future versions of Perl are likely to eliminate these arbitrary limitations.

Some people may wish to outlaw barewords entirely. If you say

use strict 'subs';

then any bareword that would NOT be interpreted as a subroutine call produces a compile-time error instead. The restriction lasts to the end of the enclosing block. An inner block may countermand this by saying "no strict 'subs'".

Array Interpolation

Arrays and slices are interpolated into double-quoted strings by joining the elements with the delimiter specified in the $" variable ($LIST_SEPARATOR if "use English;" is specified), space by default. The following are equivalent:

$temp = join($", @ARGV);
system "echo $temp";
system "echo @ARGV";

Within search patterns (which also undergo double-quotish substitution) there is an unfortunate ambiguity: Is "/$foo[bar]/" to be interpreted as "/${foo}[bar]/" (where "[bar]" is a character class for the regular expression) or as "/${foo[bar]}/" (where "[bar]" is the subscript to array @foo)? If @foo doesn't otherwise exist, then it's obviously a character class. If @foo exists, Perl takes a good guess about "[bar]", and is almost always right. If it does guess wrong, or if you're just plain paranoid, you can force the correct interpretation with curly braces as above.

List value constructors

List values are denoted by separating individual values by commas (and enclosing the list in parentheses where precedence requires it):

(LIST)

In a context not requiring a list value, the value of what appears to be a list literal is simply the value of the final element, as with the C comma operator. For example,

@foo = ('cc', '-E', $bar);

assigns the entire list value to array @foo, but

$foo = ('cc', '-E', $bar);

assigns the value of variable $bar to the scalar variable $foo. Note that the value of an actual array in scalar context is the length of the array; the following assigns the value 3 to $foo:

@foo = ('cc', '-E', $bar);
$foo = @foo;                # $foo gets 3

You may have an optional comma before the closing parenthesis of a list literal, so that you can say:

@foo = (
    1,
    2,
    3,
);

To use a here-document to assign an array, one line per element, you might use an approach like this:

@sauces = <<End_Lines =~ m/(\S.*\S)/g;
    normal tomato
    spicy tomato
    green chile
End_Lines

Las LISTAS realizan interpolación automática de sublistas. Es decir, cuando se evalúa una LISTA, cada elemento de la lista se evalúa en contexto de lista, y el valor de lista resultante se interpola en la LISTA como si cada elemento individual fuera miembro de la LISTA. Por lo tanto, los arrays y los hashes pierden su identidad en una LISTA: la lista

(@foo,@bar,&SomeSub,%glarch)

contiene todos los elementos de @foo seguidos de todos los elementos de @bar, seguidos de todos los elementos devueltos por la subrutina llamada SomeSub en contexto de lista, seguidos de los pares clave/valor de %glarch. Para crear una referencia de lista que NO interpola, consulta perlref.

La lista nula se representa con (). Interpolarla en una lista no tiene ningún efecto. Por lo tanto, ((),(),()) es equivalente a (). De manera similar, interpolar un array sin elementos es lo mismo que si no se hubiera interpolado ningún array en ese punto.

Esta interpolación se combina con el hecho de que los paréntesis de apertura y cierre son opcionales (excepto cuando son necesarios para la precedencia) y las listas pueden terminar con una coma opcional, lo que significa que múltiples comas dentro de las listas son sintaxis legal. La lista "1,,3" es una concatenación de dos listas, "1," y 3, la primera de las cuales termina con esa coma opcional. "1,,3" es "(1,),(3)" es "1,3" (Y de manera similar para "1,,,3" es "(1,),(,),3" es "1,3" y así sucesivamente.) No es que recomendemos usar esta ofuscación.

Un valor de lista también puede ser indexado como un array normal. Debes poner la lista entre paréntesis para evitar ambigüedades. Por ejemplo:

# Stat devuelve un valor de lista.
$time = (stat($file))[8];
# ERROR DE SINTAXIS AQUÍ.
$time = stat($file)[8];  # OOPS, OLVIDÉ LOS PARÉNTESIS
# Encuentra un dígito hexadecimal.
$hexdigit = ('a','b','c','d','e','f')[$digit-10];
# Un "operador coma inverso".
return (pop(@foo),pop(@foo))[0];

Las listas solo pueden ser asignadas cuando cada elemento de la lista es legal de asignar:

($x, $y, $z) = (1, 2, 3);
($map{'red'}, $map{'blue'}, $map{'green'}) = (0x00f, 0x0f0, 0xf00);

Una excepción a esto es que puedes asignar a "undef" en una lista. Esto es útil para descartar algunos de los valores de retorno de una función:

($dev, $ino, undef, undef, $uid, $gid) = stat($file);

A partir de Perl 5.22, también puedes usar "(undef)x2" en lugar de "undef, undef". (También puedes hacer "($x) x 2", lo cual es menos útil, ya que asigna a la misma variable dos veces, sobrescribiendo el primer valor asignado).

Cuando asignas una lista de escalares a un array, todos los valores anteriores en ese array se borran y el número de elementos en el array será igual al número de elementos en la lista de la derecha, la lista de la cual se hizo la asignación. El array se redimensionará automáticamente para acomodar precisamente cada elemento en la lista de la derecha.

use warnings;
my (@xyz, $x, $y, $z);
@xyz = (1, 2, 3);
print "@xyz\n";                             # 1 2 3
@xyz = ('al', 'be', 'ga', 'de');
print "@xyz\n";                             # al be ga de
@xyz = (101, 102);
print "@xyz\n";                             # 101 102

Sin embargo, cuando asignas una lista de escalares a otra lista de escalares, los resultados difieren según si la lista de la izquierda, a la que se asigna, tiene el mismo número, más o menos elementos que la lista de la derecha.

($x, $y, $z) = (1, 2, 3);
print "$x $y $z\n";                         # 1 2 3
($x, $y, $z) = ('al', 'be', 'ga', 'de');
print "$x $y $z\n";                         # al be ga
($x, $y, $z) = (101, 102);
print "$x $y $z\n";                         # 101 102
# Uso de valor no inicializado $z en concatenación (.)
# o cadena en [programa] línea [número de línea].

Si el número de escalares en la lista de la izquierda es menor que el de la lista de la derecha, los escalares "extra" de la lista de la derecha simplemente no se asignarán.

Si el número de escalares en la lista de la izquierda es mayor que el de la lista de la izquierda, los escalares "faltantes" se volverán indefinidos.

($x, $y, $z) = (101, 102);
for my $el ($x, $y, $z) {
    (defined $el) ? print "$el " : print "<undef>";
}
print "\n";
                                            # 101 102 <undef>

La asignación de lista en contexto escalar devuelve el número de elementos producidos por la expresión en el lado derecho de la asignación:

$x = (($foo,$bar) = (3,2,1));       # establece $x en 3, no en 2
$x = (($foo,$bar) = f());           # establece $x en el conteo de retorno de f()

Esto es útil cuando quieres hacer una asignación de lista en un contexto booleano, porque la mayoría de las funciones de lista devuelven una lista nula cuando terminan, lo que al ser asignado produce un 0, que se interpreta como FALSO.

También es la fuente de un modismo útil para ejecutar una función o realizar una operación en contexto de lista y luego contar el número de valores de retorno, asignando a una lista vacía y luego usando esa asignación en contexto escalar. Por ejemplo, este código:

$count = () = $string =~ /\d+/g;

colocará en $count el número de grupos de dígitos encontrados en $string. Esto sucede porque la coincidencia de patrón está en contexto de lista (ya que se está asignando a la lista vacía), y por lo tanto devolverá una lista de todas las partes coincidentes de la cadena. La asignación de lista en contexto escalar traducirá eso al número de elementos (aquí, el número de veces que el patrón coincidió) y lo asignará a $count. Ten en cuenta que simplemente usar

$count = $string =~ /\d+/g;

no habría funcionado, ya que una coincidencia de patrón en contexto escalar solo devolverá verdadero o falso, en lugar de un conteo de coincidencias.

El último elemento de una asignación de lista puede ser un array o un hash:

($x, $y, @rest) = split;
my($x, $y, %rest) = @_;

En realidad, puedes colocar un array o un hash en cualquier lugar de la lista, pero el primero en la lista absorberá todos los valores, y cualquier cosa después de él se volverá indefinida. Esto puede ser útil en un my() o local().

Un hash puede ser inicializado usando una lista literal que contiene pares de elementos que se interpretarán como una clave y un valor:

# igual que la asignación de mapa anterior
%map = ('red',0x00f,'blue',0x0f0,'green',0xf00);

Aunque las listas literales y los arrays nombrados son a menudo intercambiables, ese no es el caso de los hashes. El hecho de que puedas indexar un valor de lista como un array normal no significa que puedas indexar un valor de lista como un hash. De manera similar, los hashes incluidos como partes de otras listas (incluidas las listas de parámetros y las listas de retorno de funciones) siempre se aplanan en pares clave/valor. Es por eso que a veces es bueno usar referencias.

A menudo es más legible usar el operador "=>" entre pares clave/valor. El operador "=>" es principalmente solo un sinónimo más distintivo visualmente para una coma, pero también hace que su operando de la izquierda se interprete como una cadena si es una palabra desnuda que sería un identificador simple legal. "=>" no entrecomilla identificadores compuestos que contienen dobles dos puntos. Esto lo hace agradable para inicializar hashes:

 %map = (
              red   => 0x00f,
              blue  => 0x0f0,
              green => 0xf00,
);

o para inicializar referencias de hash que se usarán como registros:

$rec = {
            witch => 'Mable the Merciless',
            cat   => 'Fluffy the Ferocious',
            date  => '10/31/1776',
};

o para usar paso de parámetros por nombre a funciones complicadas:

$field = $query->radio_group(
            name      => 'group_name',
            values    => ['eenie','meenie','minie'],
            default   => 'meenie',
            linebreak => 'true',
            labels    => \%labels
);

Ten en cuenta que el hecho de que un hash se inicialice en ese orden no significa que salga en ese orden. Consulta "sort" en perlfunc para ver ejemplos de cómo organizar un orden de salida.

Si una clave aparece más de una vez en la lista inicializadora de un hash, la última ocurrencia gana:

%circle = (
              center => [5, 10],
              center => [27, 9],
              radius => 100,
              color => [0xDF, 0xFF, 0x00],
              radius => 54,
);
# igual que
%circle = (
              center => [27, 9],
              color => [0xDF, 0xFF, 0x00],
              radius => 54,
);

Esto se puede usar para proporcionar valores predeterminados de configuración que se pueden anular:

# los valores en %args tienen prioridad sobre %config_defaults
%config = (%config_defaults, %args);

Subíndices

Se puede acceder a un array un escalar a la vez especificando un signo de dólar ("$"), luego el nombre del array (sin el "@" inicial), luego el subíndice entre corchetes. Por ejemplo:

@myarray = (5, 50, 500, 5000);
print "El Tercer Elemento es", $myarray[2], "\n";

Los índices del array comienzan en 0. Un subíndice negativo recupera su valor desde el final. En nuestro ejemplo, $myarray[-1] habría sido 5000, y $myarray[-2] habría sido 500.

Los subíndices de hash son similares, solo que en lugar de corchetes se usan llaves. Por ejemplo:

%scientists = 
(
    "Newton" => "Isaac",
    "Einstein" => "Albert",
    "Darwin" => "Charles",
    "Feynman" => "Richard",
);
print "El Nombre de Pila de Darwin es ", $scientists{"Darwin"}, "\n";

También puedes indexar una lista para obtener un solo elemento de ella:

$dir = (getpwnam("daemon"))[7];

Emulación de arrays multidimensionales

Se pueden emular arrays multidimensionales indexando un hash con una lista. Los elementos de la lista se unen con el separador de subíndices (ver "$;" en perlvar).

$foo{$x,$y,$z}

es equivalente a

$foo{join($;, $x, $y, $z)}

El separador de subíndices predeterminado es "\034", el mismo que SUBSEP en awk.

Rebanadas (Slices)

Una rebanada accede a varios elementos de una lista, un array o un hash

NAME

perldata - Perl constants, variables, scalars, arrays, and hashes

DESCRIPTION

Una asignación a un subconjunto de un array o hash se llama "slice". Los slices son útiles para obtener o establecer valores de forma simultánea usando una lista de subíndices. Es más conveniente que escribir los elementos individuales como una lista de valores escalares separados.

($him, $her)   = @folks[0,-1];              # array slice
@them          = @folks[0 .. 3];            # array slice
($who, $home)  = @ENV{"USER", "HOME"};      # hash slice
($uid, $dir)   = (getpwnam("daemon"))[2,7]; # list slice

Dado que puedes asignar a una lista de variables, también puedes asignar a un slice de un array o hash.

@days[3..5]    = qw/Wed Thu Fri/;
@colors{'red','blue','green'} 
               = (0xff0000, 0x0000ff, 0x00ff00);
@folks[0, -1]  = @folks[-1, 0];

Las asignaciones anteriores son exactamente equivalentes a

($days[3], $days[4], $days[5]) = qw/Wed Thu Fri/;
($colors{'red'}, $colors{'blue'}, $colors{'green'})
               = (0xff0000, 0x0000ff, 0x00ff00);
($folks[0], $folks[-1]) = ($folks[-1], $folks[0]);

Dado que cambiar un slice cambia el array o hash original que está cortando, una construcción "foreach" alterará algunos, o incluso todos, los valores del array o hash.

foreach (@array[ 4 .. 10 ]) { s/peter/paul/ } 
foreach (@hash{qw[key1 key2]}) {
    s/^\s+//;                       # trim leading whitespace
    s/\s+$//;                       # trim trailing whitespace
    s/\b(\w)(\w*)\b/\u$1\L$2/g;     # "titlecase" words
}

Como excepción especial, cuando cortas una lista (pero no un array o un hash), si la lista resulta vacía, entonces tomar un slice de esa lista vacía siempre devolverá la lista vacía a su vez. Por lo tanto:

@a = ()[0,1];          # @a has no elements
@b = (@a)[0,1];        # @b has no elements
@c = (sub{}->())[0,1]; # @c has no elements
@d = ('a','b')[0,1];   # @d has two elements
@e = (@d)[0,1,8,9];    # @e has four elements
@f = (@d)[8,9];        # @f has two elements

Esto facilita la escritura de bucles que terminan cuando se devuelve una lista nula:

while ( ($home, $user) = (getpwent)[7,0] ) {
    printf "%-8s %s\n", $user, $home;
}

Como se señaló anteriormente en este documento, el sentido escalar de la asignación de listas es el número de elementos en el lado derecho de la asignación. La lista nula no contiene elementos, por lo que cuando se agota el archivo de contraseñas, el resultado es 0, no 2.

Los slices en contexto escalar devuelven el último elemento del slice.

@a = qw/first second third/;
%h = (first => 'A', second => 'B');
$t = @a[0, 1];                  # $t is now 'second'
$u = @h{'first', 'second'};     # $u is now 'B'

Si te confunde por qué usas un '@' ahí en un slice de hash en lugar de un '%', piénsalo de esta manera. El tipo de corchete (cuadrado o rizado) rige si es un array o un hash el que se está examinando. Por otro lado, el símbolo principal ('$' o '@') en el array o hash indica si se está obteniendo un valor singular (un escalar) o uno plural (una lista).

Slices de Hash de Clave/Valor

A partir de Perl 5.20, una operación de slice de hash con el símbolo % es una variante de la operación de slice que devuelve una lista de pares clave/valor en lugar de solo valores:

%h = (blonk => 2, foo => 3, squink => 5, bar => 8);
%subset = %h{'foo', 'bar'}; # key/value hash slice
# %subset is now (foo => 3, bar => 8)
%removed = delete %h{'foo', 'bar'};
# %removed is now (foo => 3, bar => 8)
# %h is now (blonk => 2, squink => 5)

Sin embargo, el resultado de dicho slice no se puede localizar ni asignar. Estos son, por lo demás, muy consistentes con los slices de hash que usan el símbolo @.

Slices de Array de Índice/Valor

Similar a los slices de hash de clave/valor (y también introducido en Perl 5.20), la sintaxis de slice de array % devuelve una lista de pares índice/valor:

@a = "a".."z";
@list = %a[3,4,6];
# @list is now (3, "d", 4, "e", 6, "g")
@removed = delete %a[3,4,6]
# @removed is now (3, "d", 4, "e", 6, "g")
# @list[3,4,6] are now undef

Tenga en cuenta que llamar a "delete" en valores de array está fuertemente desaconsejado.

Typeglobs y Filehandles

Perl usa un tipo interno llamado typeglob para mantener una entrada completa de la tabla de símbolos. El prefijo de tipo de un typeglob es un "*", porque representa todos los tipos. Este solía ser el método preferido para pasar arrays y hashes por referencia a una función, pero ahora que tenemos referencias reales, esto rara vez es necesario.

El uso principal de los typeglobs en Perl moderno es crear alias de tabla de símbolos. Esta asignación:

*this = *that;

hace que $this sea un alias de $that, @this un alias de @that, %this un alias de %that, &this un alias de &that, etc. Mucho más seguro es usar una referencia. Esto:

local *Here::blue = \$There::green;

convierte temporalmente a $Here::blue en un alias de $There::green, pero no convierte a @Here::blue en un alias de @There::green, o %Here::blue en un alias de %There::green, etc. Véase "Symbol Tables" en perlmod para más ejemplos de esto. Aunque esto parezca extraño, esta es la base de todo el sistema de importación/exportación de módulos.

Otro uso de los typeglobs es pasar filehandles a una función o crear nuevos filehandles. Si necesita usar un typeglob para guardar un filehandle, haga esto:

$fh = *STDOUT;

o quizás como una referencia real, así:

$fh = \*STDOUT;

Vea perlsub para ejemplos de uso como filehandles indirectos en funciones.

Los typeglobs también son una forma de crear un filehandle local usando el operador local(). Estos duran hasta que se sale de su bloque, pero pueden ser pasados de vuelta. Por ejemplo:

sub newopen {
    my $path = shift;
    local  *FH;  # not my!
    open   (FH, $path)          or  return undef;
    return *FH;
}
$fh = newopen('/etc/passwd');

Ahora que tenemos la notación *foo{THING}, los typeglobs no se usan tanto para la manipulación de filehandles, aunque aún se necesitan para pasar filehandles y directory handles completamente nuevos dentro o fuera de las funciones. Eso se debe a que *HANDLE{IO} solo funciona si HANDLE ya se ha utilizado como handle. En otras palabras, *FH debe usarse para crear nuevas entradas de tabla de símbolos; *foo{THING} no puede. En caso de duda, use *FH.

Todas las funciones que son capaces de crear filehandles (open(), opendir(), pipe(), socketpair(), sysopen(), socket(), y accept()) crean automáticamente un filehandle anónimo si el handle que se les pasa es una variable escalar no inicializada. Esto permite que construcciones como "open(my $fh, ...)" y "open(local $fh,...)" se usen para crear filehandles que se cerrarán automáticamente cuando finalice el scope, siempre que no haya otras referencias a ellos. Esto elimina en gran medida la necesidad de typeglobs al abrir filehandles que deben pasarse, como en el siguiente ejemplo:

sub myopen {
    open my $fh, "@_"
         or die "Can't open '@_': $!";
    return $fh;
}
{
    my $f = myopen("</etc/motd");
    print <$f>;
    # $f implicitly closed here
}

Tenga en cuenta que si se utiliza una variable escalar inicializada en su lugar, el resultado es diferente: "my $fh='zzz'; open($fh, ...)" es equivalente a "open( *{'zzz'}, ...)". "use strict 'refs'" prohíbe tal práctica.

Otra forma de crear filehandles anónimos es con el módulo Symbol o con el módulo IO::Handle y sus similares. Estos módulos tienen la ventaja de no ocultar diferentes tipos del mismo nombre durante el local(). Consulte la parte inferior de "open" en perlfunc para ver un ejemplo.
