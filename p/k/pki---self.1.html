NOMBRE

pki --self - Crear un certificado autofirmado

SINOPSIS

pki --self [--in archivo|--keyid hex] [--type t] --dn nombre-distinguido [--san subjectAltName] [--lifetime días] [--not-before fecha-hora] [--not-after fecha-hora] [--serial hex] [--flag bandera] [--digest digest] [--rsa-padding relleno] [--ca] [--ocsp uri] [--pathlen longitud] [--addrblock bloque] [--nc-permitted nombre] [--nc-excluded nombre] [--critical oid] [--policy-mapping mapeo] [--policy-explicit longitud] [--policy-inhibit longitud] [--policy-any longitud] [--cert-policy oid [--cps-uri uri] [--user-notice texto]] [--outform codificacion] [--debug nivel]
pki --self --options archivo
pki --self -h | --help

DESCRIPCIÓN

Este subcomando de pki(1) se utiliza para crear un certificado autofirmado.

OPCIONES

-h, --help
Imprime información de uso con un resumen de las opciones disponibles.
-v, --debug nivel
Establece el nivel de depuración, por defecto: 1.
-+, --options archivo
Lee las opciones de la línea de comandos desde el archivo.
-i, --in archivo
Archivo de entrada de clave privada. Si no se proporciona, la clave se lee de STDIN.
-x, --keyid hex
Identificador del objeto de clave privada de tarjeta inteligente o TPM en formato hexadecimal con un prefijo opcional de 0x.
-t, --type tipo
Tipo de la clave de entrada. Puede ser priv, rsa, ecdsa, ed25519 o ed448, por defecto es priv.
-d, --dn nombre-distinguido
Nombre distinguido (DN) del sujeto y del emisor. Requerido.
-a, --san subjectAltName
Extensión subjectAltName a incluir en el certificado. Se puede usar varias veces.
-l, --lifetime días
Días de validez del certificado, por defecto: 1095. Se ignora si se dan tanto una hora de inicio como de fin absolutas.
-F, --not-before fecha-hora
Hora absoluta en la que comienza la validez del certificado. El formato de fecha-hora se define mediante la opción --dateform.
-T, --not-after fecha-hora
Hora absoluta en la que termina la validez del certificado. El formato de fecha-hora se define mediante la opción --dateform.
-D, --dateform formato
Formato strptime(3) para las opciones --not-before y --not-after, por defecto: %d.%m.%y %T
-s, --serial hex
Número de serie en hexadecimal. Se asigna aleatoriamente por defecto.
-e, --flag bandera
Añade una bandera extendedKeyUsage. Una de serverAuth, clientAuth, crlSign, o ocspSigning. Se puede usar varias veces.
-g, --digest digest
Digest a utilizar para la creación de la firma. Uno de md5, sha1, sha224, sha256, sha384 o sha512. El valor por defecto se determina en función del tipo y tamaño de la clave de firma.
-R, --rsa-padding relleno
Relleno a utilizar para las firmas RSA. Puede ser pkcs1 o pss, por defecto es pkcs1.
-f, --outform codificacion
Codificación del archivo de certificado creado. Puede ser der (ASN.1 DER) o pem (Base64 PEM), por defecto es der.
-b, --ca
Incluye la extensión basicConstraint de CA en el certificado.
-o, --ocsp uri
URI de AuthorityInfoAccess de OCSP a incluir en el certificado. Se puede usar varias veces.
-p, --pathlen longitud
Establece la restricción de longitud de ruta.
-B, --addrblock bloque
Bloque de direcciones RFC 3779 a incluir en el certificado. bloque es una subred CIDR (como 10.0.0.0/8) o un rango de direcciones arbitrario (192.168.1.7-192.168.1.13). Se puede repetir para incluir múltiples bloques. Tenga en cuenta que los bloques proporcionados se incluyen tal cual en el certificado, por lo que, para cumplir con los estándares, los bloques múltiples deben proporcionarse en el orden correcto y los bloques adyacentes deben combinarse. Consulte RFC 3779 para obtener más detalles.
-n, --nc-permitted nombre
Añade una extensión NameConstraint permitida al certificado. Para restricciones DNS o de correo electrónico, el tipo de identidad no siempre es detectable por el nombre dado. Utilice el prefijo dns: o email: para forzar un tipo de restricción.
-N, --nc-excluded nombre
Añade una extensión NameConstraint excluida al certificado. Para restricciones DNS o de correo electrónico, el tipo de identidad no siempre es detectable por el nombre dado. Utilice el prefijo dns: o email: para forzar un tipo de restricción.
-X, --critical oid
Añade una extensión crítica con el OID dado.
-M, --policy-mapping oid-emisor:oid-sujeto
Añade una política de mapeo del emisor al sujeto OID.
-E, --policy-explicit longitud
Añade una restricción requireExplicitPolicy.
-H, --policy-inhibit longitud
Añade una restricción inhibitPolicyMapping.
-A, --policy-any longitud
Añade una restricción inhibitAnyPolicy.

Política de Certificado

Se pueden añadir múltiples extensiones de certificatePolicy. Cada una con la siguiente información:

-P, --cert-policy oid
OID a incluir en la extensión certificatePolicy. Requerido.
-C, --cps-uri uri
URI de la declaración de práctica de certificación para certificatePolicy.
-U, --user-notice texto
Aviso de usuario para certificatePolicy.

EJEMPLOS

Generar un certificado autofirmado utilizando la clave RSA dada:

  pki --self --in key.der --dn "C=CH, O=strongSwan, CN=moon" \
      --san moon.strongswan.org > cert.der
