NOMBRE

pki --req - Crear una solicitud de certificado PKCS#10

SINOPSIS

pki --req [--in archivo|--keyid hex] [--type tipo] --dn nombre-distinguido [--san nombreAlternativoSujeto] [--profile perfil] [--flag bandera] [--password contraseña] [--digest resumen] [--rsa-padding relleno] [--outform codificacion] [--debug nivel]
pki --req [--in archivo|--keyid hex] [--type tipo] --oldreq archivo [--password contraseña] [--digest resumen] [--rsa-padding relleno] [--outform codificacion] [--debug nivel]
pki --req --options archivo
pki --req -h | --help

DESCRIPCIÓN

Este subcomando de pki(1) se utiliza para crear una solicitud de certificado PKCS#10.

OPCIONES

-h, --help
Imprime información de uso con un resumen de las opciones disponibles.
-v, --debug nivel
Establece el nivel de depuración, por defecto: 1.
-+, --options archivo
Lee las opciones de la línea de comandos desde archivo.
-i, --in archivo
Archivo de entrada de clave privada. Si no se proporciona, la clave se lee de STDIN.
-x, --keyid hex
Identificador del objeto de clave privada de la tarjeta inteligente o TPM en formato hexadecimal con un prefijo opcional de 0x.
-t, --type tipo
Tipo de la clave de entrada. Puede ser priv, rsa o ecdsa, por defecto es priv.
-d, --dn nombre-distinguido
Nombre distinguido (DN) del sujeto. Requerido si la opción --dn no está establecida.
-a, --san nombreAlternativoSujeto
Extensión subjectAltName a incluir en la solicitud. Se puede usar varias veces.
-P, --profile perfil
Nombre del perfil del certificado a incluir en la solicitud de certificado. Puede ser cualquier cadena UTF8. Soportado, por ejemplo, por openxpki (con los perfiles pc-client, tls-server, etc.) o pki --issue (con los perfiles server, client, dual, o ocsp) que se traducen en las banderas correspondientes de Uso de Clave Extendido (EKU) en el certificado X.509 generado.
-e, --flag bandera
Añade una bandera extendedKeyUsage. Una de serverAuth, clientAuth, ocspSigning o msSmartcardLogon. Se puede usar varias veces. Añade una extensión X.509v3 EKU que contiene estas banderas a la solicitud de certificado.
-p, --password contraseña
El challengePassword a incluir en la solicitud de certificado.
-o, --oldreq archivo
Solicitud de certificado antigua a usar como plantilla. Requerido si la opción --dn no está establecida. La clave pública en la solicitud de certificado antigua se reemplaza y se genera una nueva firma usando la nueva clave privada. Opcionalmente, se puede establecer un nuevo challengePassword usando la opción --password.
-g, --digest resumen
Resumen a usar para la creación de la firma. Una de sha1, sha224, sha256, sha384, sha512, sha3_224, sha3_256, sha3_384, o sha3_512. Por defecto, se determina en función del tipo y tamaño de la clave de firma.
-R, --rsa-padding relleno
Relleno a usar para las firmas RSA. Puede ser pkcs1 o pss, por defecto es pkcs1.
-f, --outform codificacion
Codificación del archivo de certificado creado. Puede ser der (ASN.1 DER) o pem (PEM Base64), por defecto es der.

EJEMPLOS

Generar una solicitud de certificado para una clave RSA, con una extensión subjectAltName y un perfil TLS-server:

  pki --req --in key.der --dn "C=CH, O=strongSwan, CN=moon" \
      --san moon@strongswan.org --profile server > req.der

Generar una solicitud de certificado para una clave renovada basada en una plantilla existente

  pki --req --in myNewKey.der --oldreq myReq.der > myNewReq.der

Generar una solicitud de certificado para una clave ECDSA y un resumen diferente:

  pki --req --in key.der --type ecdsa --digest sha256 \
      --dn "C=CH, O=strongSwan, CN=carol"  > req.der
