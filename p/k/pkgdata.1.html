NOMBRE

pkgdata - datos de paquetes para uso por ICU

SINOPSIS

pkgdata [ -h, -?, --help ] [ -v, --verbose ] [ -c, --copyright | -C, --comment comentario ] [ -m, --mode modo ] -p, --name nombre -O, --bldopt opciones [ -e, --entrypoint nombre ] [ -r, --revision version ] [ -F, --rebuild ] [ -I, --install ] [ -s, --sourcedir origen ] [ -d, --destdir destino ] [ -T, --tempdir directorio ] [ archivo ... ]

DESCRIPCIÓN

pkgdata toma un conjunto de archivos de datos y los empaqueta para su uso por ICU o por aplicaciones que utilizan ICU. La razón típica para empaquetar archivos usando pkgdata es facilitar su distribución y hacer su carga por parte de ICU más rápida y menos consumidora de recursos del sistema limitados, como los descriptores de archivos. Los datos empaquetados también permiten que las aplicaciones se distribuyan con menos archivos de recursos, o incluso sin ninguno si se enlazan directamente contra los datos empaquetados.

pkgdata admite varios métodos de empaquetado de datos que sirven a diferentes propósitos.

El modo de empaquetado predeterminado es common o archive. En este modo, los diferentes archivos de datos se agrupan como un archivo dependiente de la arquitectura que posteriormente puede ser mapeado en memoria para su uso por ICU. Los datos empaquetados usando este modo se buscarán bajo el directorio de datos de ICU. Dicho empaquetado es fácil de usar para paquetes de recursos de aplicaciones, por ejemplo, siempre que la aplicación pueda instalar el archivo empaquetado en el directorio de datos de ICU.

Otro modo de empaquetado es el modo dll o library, donde los archivos de datos se compilan en una biblioteca compartida. ICU solía ser capaz de cargar dinámicamente estas bibliotecas compartidas, pero a partir de ICU 2.0, tal soporte se ha eliminado. Este modo sigue siendo útil para dos propósitos principales: compilar la propia ICU, ya que los datos de ICU se empaquetan como una biblioteca compartida por defecto; y compilar paquetes de recursos que se enlazan con la aplicación que los utiliza. Dichos paquetes de recursos pueden colocarse en cualquier lugar donde el enlazador dinámico del sistema esté buscando bibliotecas compartidas, en lugar de verse obligado a residir dentro del directorio de datos de ICU.

El modo de empaquetado static es similar al de la biblioteca compartida, excepto que produce una biblioteca estática.

Finalmente, pkgdata admite un modo files que simplemente copia los archivos de datos en lugar de empaquetarlos como un solo archivo o biblioteca. Este modo está destinado principalmente a proporcionar soporte para compilar ICU antes de que se empaquete en paquetes pequeños separados para su distribución con sistemas operativos como Debian GNU/Linux, por ejemplo. Consulte la documentación de empaquetado en la distribución de código fuente de ICU para obtener más información sobre el uso de este modo.

pkgdata compila, empaqueta, instala o limpia los datos apropiados según las opciones dadas, sin necesidad de llamar a GNU make.

OPCIONES

-h, -?, --help
Imprime ayuda sobre el uso y sale.
-v, --verbose
Muestra mensajes informativos adicionales durante la ejecución.
-c, --copyright
Incluye un aviso de copyright en los datos binarios.
-C, --comment comentario
Incluye el comentario especificado en los datos resultantes en lugar del aviso de copyright de ICU.
-m, --mode modo
Establece el modo de empaquetado que será utilizado por pkgdata. Los diferentes modos y su significado se explican en la sección DESCRIPCIÓN anterior. Los nombres de modo válidos son common (o archive), dll (o library) y files.
-O, --bldopt opciones
Especifica opciones para el constructor. El constructor es utilizado internamente por pkgdata para generar el archivo empaquetado correcto. Dichas opciones incluyen, entre otras, establecer variables utilizadas por make(1) durante la compilación del archivo empaquetado. Nota: Si icu-config está disponible, esta opción no es necesaria.
-p, --name nombre
Establece el nombre del archivo empaquetado a nombre. Este nombre también se usa como nombre de punto de entrada predeterminado después de haber sido convertido en un identificador C válido.
-e, --entrypoint nombre
Establece el punto de entrada de datos (utilizado para enlazar con los datos en formato de biblioteca compartida) a nombre. El nombre de punto de entrada predeterminado es el nombre establecido por la opción -n, --name.
-r, --revision version
Habilita la versionización de la biblioteca compartida producida en modo dll o library. El número de versión tiene el formato major.minor.patchlevel y todas las partes excepto major son opcionales. Si solo se proporciona major, se asume que la versión es major.0 para fines de versionización.
-F, --rebuild
Fuerza la reconstrucción de todos los datos y su reempaquetado.
-I, --install
Instala el archivo empaquetado (o todos los archivos en modo files). Si la variable DESTDIR está establecida, se usará para la instalación.
-s, --sourcedir origen
Establece el directorio de origen a origen. El directorio de origen predeterminado es el directorio actual.
-d, --destdir destino
Establece el directorio de destino a destino. El directorio de destino predeterminado es el directorio actual.
-T, --tempdir directorio
Establece el directorio utilizado para generar archivos temporales a directorio. El directorio temporal predeterminado es el mismo que el directorio de destino, según lo establecido por la opción -d, --destdir.

NAME

pkgdata - Get package-specific data

SYNOPSIS

pkgdata [options] query...

DESCRIPTION

The pkgdata utility allows you to retrieve package-specific data from installed Arch Linux packages. This can include things like file lists, dependencies, build information, and more.

OPTIONS

  • -h, --help: Show help message and exit.
  • -v, --version: Show version information and exit.
  • -p, --package <package_name>: Specify the package to query. If not specified, pkgdata will try to infer it from the context or query all installed packages.
  • -f, --field <field_name>: Specify which field of data to retrieve (e.g., 'files', 'depends', 'buildtime').
  • -a, --arch <architecture>: Specify the architecture of the package (e.g., 'x86_64').
  • -i, --info: Show general information about the package.
  • -l, --list: List all available queries for a package.

The query argument specifies the type of data you want to retrieve. Common queries include:

  • files: List all files installed by the package.
  • depends: List packages that the current package depends on.
  • makedepends: List packages that were required to build the current package.
  • checkdepends: List packages that are required for checking the current package.
  • optdepends: List optional dependencies for the current package.
  • provides: List capabilities that the current package provides.
  • conflicts: List packages that conflict with the current package.
  • replaces: List packages that the current package replaces.
  • backup: List backup files for the current package.
  • buildtime: Show the build time of the package.
  • packager: Show the packager of the package.
  • url: Show the URL of the package.
  • license: Show the license of the package.
  • size: Show the installed size of the package.

You can combine multiple queries. If no field is specified, pkgdata will attempt to display the most relevant information for the query.

EXAMPLES

pkgdata files bash

List all files installed by the 'bash' package.

pkgdata -p git depends

List the dependencies of the 'git' package.

pkgdata -p linux buildtime packager

Show the build time and packager of the 'linux' package.

pkgdata -l gcc

List all available queries for the 'gcc' package.
