NOMBRE

pkexec - Ejecutar un comando como otro usuario

SINOPSIS

pkexec [--version] [--disable-internal-agent] [--help]

pkexec [--keep-cwd] [--user nombredeusuario] PROGRAMA [ARGUMENTOS...]

DESCRIPCIÓN

pkexec permite a un usuario autorizado ejecutar PROGRAMA como otro usuario. Si no se especifica PROGRAMA, se ejecutará el shell predeterminado. Si no se especifica nombredeusuario, el programa se ejecutará como el superusuario administrativo, root.

VALOR DE RETORNO

Al completarse con éxito, el valor de retorno es el valor de retorno de PROGRAMA. Si el proceso que llama no está autorizado o no se pudo obtener una autorización a través de la autenticación o se produjo un error, pkexec saldrá con un valor de retorno de 127. Si no se pudo obtener la autorización porque el usuario descartó el diálogo de autenticación, pkexec saldrá con un valor de retorno de 126.

AGENTE DE AUTENTICACIÓN

pkexec, al igual que cualquier otra aplicación polkit, utilizará el agente de autenticación registrado para el proceso o sesión que lo llama. Sin embargo, si no hay ningún agente de autenticación disponible, pkexec registrará su propio agente de autenticación textual. Este comportamiento se puede desactivar pasando la opción --disable-internal-agent.

NOTAS DE SEGURIDAD

Ejecutar un programa como otro usuario es una operación privilegiada. Por defecto, la acción a verificar (ver la sección llamada “ACCIÓN Y AUTORIZACIONES”) requiere autenticación de administrador. Además, el diálogo de autenticación que se presenta al usuario mostrará la ruta completa del programa a ejecutar para que el usuario sea consciente de lo que sucederá.

El entorno en el que se ejecutará PROGRAMA se establecerá a un entorno mínimo conocido y seguro para evitar la inyección de código a través de LD_LIBRARY_PATH o mecanismos similares. Además, la variable de entorno PKEXEC_UID se establece al ID de usuario del proceso que invoca pkexec. Como resultado, pkexec no permitirá por defecto ejecutar aplicaciones X11 como otro usuario, ya que las variables de entorno $DISPLAY y $XAUTHORITY no están establecidas. Estas dos variables se conservarán si la anotación org.freedesktop.policykit.exec.allow_gui en una acción se establece a un valor no vacío; sin embargo, esto no se recomienda y solo debe usarse para programas heredados.

pkexec ejecutará PROGRAMA en el directorio de inicio de nombredeusuario, a menos que se use --keep-cwd para anular este comportamiento.

Tenga en cuenta que pkexec no realiza ninguna validación de los ARGUMENTOS pasados a PROGRAMA. En el caso normal (donde la autenticación de administrador se requiere cada vez que se usa pkexec), esto no es un problema, ya que si el usuario es un administrador, bien podría ejecutar pkexec bash para obtener root.

Sin embargo, si se utiliza una acción para la cual el usuario puede conservar la autorización (o si el usuario está implícitamente autorizado), esto podría ser un agujero de seguridad. Por lo tanto, como regla general, los programas para los que se cambia la autorización requerida por defecto, nunca deben confiar implícitamente en la entrada del usuario (por ejemplo, como cualquier otro programa suid bien escrito).

ACCIÓN Y AUTORIZACIONES

Por defecto, se utiliza la acción org.freedesktop.policykit.exec. Para usar otra acción, use la anotación org.freedesktop.policykit.exec.path en una acción con el valor establecido a la ruta completa del programa. Además de especificar el programa, se pueden especificar el mensaje de autenticación, la descripción, el icono y los valores predeterminados. Si está presente la anotación org.freedesktop.policykit.exec.argv1, la acción solo se elegirá si el primer argumento del programa coincide con el valor de la anotación.

Tenga en cuenta que los mensajes de autenticación pueden hacer referencia a variables (ver la sección llamada “VARIABLES”), por ejemplo, $(user) se expandirá al valor de la variable user.

USO DEL ENVOLTORIO

Para evitar modificar software existente para prefijar sus invocaciones de línea de comandos con pkexec, es posible usar pkexec en un envoltorio she-bang[1] de la siguiente manera:

#!/usr/bin/pkexec /usr/bin/python
import os
import sys
print "Hola, estoy ejecutando como uid %d" %(os.getuid())
for n in range(len(sys.argv)):
    print "arg[%d]=`%s'" %(n, sys.argv[n])

Si este script se instala en /usr/bin/mi-prueba-pk, entonces las siguientes anotaciones

  [...]
  <annotate key="org.freedesktop.policykit.exec.path">/usr/bin/python</annotate>
  <annotate key="org.freedesktop.policykit.exec.argv1">/usr/bin/mi-prueba-pk</annotate>
  [...]

se pueden usar para seleccionar la acción polkit apropiada. Tenga cuidado de que la última anotación sea correcta, de lo contrario, coincidirá con cualquier invocación de pkexec de scripts de /usr/bin/python.

VARIABLES

Las siguientes variables son establecidas por pkexec. Pueden usarse en reglas de autorización y mensajes que se muestran en los diálogos de autenticación:

programa

Ruta completamente calificada del programa a ejecutar. Ejemplo: “/bin/cat”

command_line

La línea de comandos solicitada (no use esto para ninguna verificación de seguridad, no es seguro). Ejemplo: “cat /srv/xyz/foobar”

user

El nombre de usuario del usuario que ejecutará el programa. Ejemplo: “davidz”

user.gecos

El nombre completo del usuario que ejecutará el programa. Ejemplo: “David Zeuthen”

user.display

Una representación del usuario que ejecutará el programa que sea adecuada para mostrarse en un diálogo de autenticación. Típicamente se establece a una combinación del nombre de usuario y el nombre completo. Ejemplo: “David Zeuthen (davidz)”
