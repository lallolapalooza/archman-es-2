NOMBRE

pkcs15-init - utilidad de personalización de tarjetas inteligentes

SINOPSIS

pkcs15-init [OPCIONES]

DESCRIPCIÓN

La utilidad pkcs15-init se puede usar para crear una estructura PKCS #15 en una tarjeta inteligente y agregar objetos de clave o certificado. Los detalles de la estructura que se creará se controlan a través de perfiles.

El perfil utilizado por defecto es pkcs15. Se pueden especificar perfiles alternativos mediante el interruptor -p.

USO DE PIN

pkcs15-init se puede usar para crear una estructura PKCS #15 en su tarjeta inteligente, crear PIN y instalar claves y certificados en la tarjeta. Este proceso también se llama personalización.

Una tarjeta OpenSC puede tener un PIN de oficial de seguridad y cero o más PIN de usuario. PIN significa Número de Identificación Personal, y es un código secreto que debe presentar a la tarjeta antes de que se le permita realizar ciertas operaciones, como usar una de las claves RSA almacenadas para firmar un documento, o modificar la propia tarjeta.

Por lo general, los PIN son una secuencia de dígitos decimales, pero algunas tarjetas aceptarán caracteres ASCII arbitrarios. Tenga en cuenta, sin embargo, que el uso de caracteres distintos de dígitos hará que la tarjeta no sea utilizable con lectores de teclado PIN, ya que estos suelen tener teclas solo para introducir dígitos.

El PIN del oficial de seguridad (SO) es especial; se utiliza para proteger la información de metadatos en la tarjeta, como la propia estructura PKCS #15. Establecer el PIN del SO es opcional, ya que lo peor que puede suceder normalmente es que alguien que encuentre su tarjeta la estropee. Para extraer cualquiera de sus claves secretas almacenadas en la tarjeta, un atacante aún necesitará su PIN de usuario, al menos para los perfiles OpenSC predeterminados. Sin embargo, es posible crear perfiles de tarjeta que permitan al oficial de seguridad anular los PIN de usuario.

Para cada PIN, puede especificar un PUK (también llamado PIN de desbloqueo). El PUK se puede usar para sobrescribir o desbloquear un PIN si se han introducido demasiados valores incorrectos seguidos.

Para algunas tarjetas que utilizan la emulación PKCS#15, los atributos de los objetos privados están protegidos y no se pueden analizar sin autenticación (generalmente con el PIN de usuario). Esta autenticación debe realizarse inmediatamente después de la vinculación de la tarjeta. En tales casos, se debe usar --verify-pin.

MODOS DE OPERACIÓN

Inicialización

Este es el primer paso durante la personalización de la tarjeta y creará los archivos básicos en la tarjeta. Para crear la estructura inicial PKCS #15, ejecute la utilidad como

pkcs15-init --create-pkcs15

Luego se le pedirá el PIN del oficial de seguridad y el PUK. Simplemente presionar Enter en el aviso del PIN del SO omitirá la instalación de un PIN del SO.

Si la tarjeta lo soporta, debe borrar el contenido de la tarjeta con pkcs15-init --erase-card antes de crear la estructura PKCS#15.

Instalación de PIN de usuario

Antes de instalar cualquier objeto de usuario, como claves privadas, necesita al menos un PIN para proteger estos objetos. Puede hacerlo usando

pkcs15-init --store-pin --id " nn

donde nn es un ID PKCS #15 en notación hexadecimal. Los valores comunes son 01, 02, etc.

Al introducir el comando anterior, se le pedirá el PIN y PUK del usuario. Si no desea instalar un PIN de desbloqueo, simplemente presione Enter en el aviso del PUK.

Para establecer una etiqueta para este objeto PIN (que las aplicaciones pueden usar para mostrar un aviso significativo al usuario), use la opción de línea de comandos --label.

Generación de clave

pkcs15-init le permite generar una nueva clave y almacenarla en la tarjeta. Puede hacerlo usando:

pkcs15-init --generate-key "keyspec" --auth-id "nn"

donde keyspec describe el algoritmo y los parámetros de la clave a crear. Por ejemplo, rsa:2048 genera una clave RSA con un módulo de 2048 bits. Si está generando una clave EC, se debe especificar la designación de la curva, por ejemplo, ec:prime256v1. Para claves simétricas, la longitud de la clave se especifica en bytes, por ejemplo, AES:32 o DES3:24.

nn es el ID de un PIN de usuario instalado previamente, por ejemplo, 01.

Además de almacenar la parte privada de la clave en la tarjeta, pkcs15-init también almacenará la parte pública de la clave como un objeto de clave pública PKCS #15.

Carga de clave privada

Puede usar una clave privada generada por otros medios y cargarla en la tarjeta. Por ejemplo, para cargar una clave privada contenida en un archivo llamado okir.pem, que está en formato PEM, usaría

pkcs15-init --store-private-key okir.pem --id 45 --auth-id 01

Además de almacenar la parte privada de la clave en la tarjeta, pkcs15-init también almacenará la parte pública de la clave como un objeto de clave pública PKCS #15.

Tenga en cuenta que el uso de la opción --id en los comandos pkcs15-init para generar o importar una nueva clave está obsoleto. Una práctica mejor es dejar que el middleware derive el identificador del material de la clave (SHA1(módulo) para RSA, ...). Esto permite establecer fácilmente la relación entre objetos 'relacionados' (claves privadas/públicas y certificados).

Además del formato de archivo de clave PEM, pkcs15-init también admite claves codificadas en DER y archivos PKCS #12. Este último es el formato de archivo utilizado por Netscape Navigator (entre otros) al exportar certificados a un archivo. Un archivo PKCS #12 generalmente contiene el certificado X.509 correspondiente a la clave privada. Si ese es el caso, pkcs15-init almacenará el certificado en lugar de la parte de clave pública.

Carga de clave pública

También puede cargar claves públicas individuales en la tarjeta usando la opción --store-public-key, que toma un nombre de archivo como argumento. Se supone que este archivo contiene la clave pública. Si no especifica un formato de archivo de clave usando la opción --format, pkcs15-init asumirá el formato PEM. El único otro formato de archivo de clave pública admitido es DER.

Dado que las claves públicas correspondientes siempre se cargan automáticamente al generar una nueva clave o al cargar una clave privada, es probable que utilice esta opción solo muy raramente.

Carga de certificado

Puede cargar certificados en la tarjeta usando la opción --store-certificate, que toma un nombre de archivo como argumento. Se supone que este archivo contiene el certificado X.509 codificado en PEM.

Carga de bolsas PKCS #12

La mayoría de los navegadores hoy en día utilizan archivos en formato PKCS #12 cuando les pide que exporten su clave y certificado a un archivo. pkcs15-init es capaz de analizar estos archivos y almacenar su contenido en la tarjeta en una sola operación. Esto funciona igual que almacenar una clave privada, excepto que necesita especificar el formato del archivo:

pkcs15-init --store-private-key okir.p12 --format pkcs12 --auth-id 01

Esto instalará la clave privada contenida en el archivo okir.p12 y la protegerá con el PIN referenciado por el ID de autenticación 01. También almacenará los certificados X.509 contenidos en el archivo, que suele ser el certificado de usuario que acompaña a la clave, así como el certificado de la CA.

Carga de clave secreta

Puede usar una clave secreta generada por otros medios y cargarla en la tarjeta. Por ejemplo, para cargar una clave secreta AES generada por el generador de números aleatorios del sistema, usaría

pkcs15-init --store-secret-key /dev/urandom --secret-key-algorithm aes:256 --auth-id 01

Por defecto, se genera un ID aleatorio para la clave secreta. Puede especificar un ID con --id si es necesario.

OPCIONES

--version,

Imprime la versión de lanzamiento del paquete OpenSC.

--card-profile nombre, -c nombre

Indica a pkcs15-init que cargue la opción de perfil de tarjeta especificada. Rara vez necesitará esta opción.

--create-pkcs15, -C

Esto indica a pkcs15-init que cree una estructura PKCS #15 en la tarjeta e inicialice cualquier PIN.

--serial SERIAL

Especifica el número de serie de la tarjeta.

--erase-card, -E

Esto borrará la tarjeta antes de crear la estructura PKCS #15, si la tarjeta lo admite. Si la tarjeta no admite el borrado, pkcs15-init fallará.

--erase-application AID

Esto borrará la aplicación con el identificador de aplicación AID.

--generate-key keyspec, -G keyspec

Indica a la tarjeta que genere una nueva clave y la almacene en la tarjeta. keyspec consta de un nombre de algoritmo, seguido opcionalmente por dos puntos ":", barra "/" o guión "-" y los parámetros de la clave que se va a crear. Es una buena idea especificar también el ID de la clave con este comando, usando la opción id, de lo contrario se calculará un ID intrínseco a partir del material de la clave. Consulte la descripción del atributo 'pkcs15-id-style' en 'pkcs15.profile' para obtener detalles sobre el algoritmo utilizado para calcular el ID intrínseco. Para tarjetas multiaplicación, la aplicación PKCS#15 de destino se puede especificar mediante el valor AID hexadecimal de la opción aid.

--pin pin, --puk puk, --so-pin sopin, --so-puk sopuk

Estas opciones se pueden usar para especificar los valores de PIN/PUK en la línea de comandos. Si el valor se establece en env:VARIABLE, se utiliza el valor de la variable de entorno especificada. Por defecto, se le pedirá al código en la línea de comandos si es necesario.

Tenga en cuenta que en la mayoría de los sistemas operativos, cualquier usuario puede mostrar la línea de comandos de cualquier proceso en el sistema utilizando utilidades como ps(1). Por lo tanto, debe preferir pasar los códigos a través de una variable de entorno en un sistema no seguro.

--no-so-pin,

No instale un PIN de SO ni solicite su introducción.

--profile nombre, -p nombre

Indica a pkcs15-init que cargue el perfil general especificado. Actualmente, el único perfil de aplicación definido es pkcs15, pero puede escribir sus propios perfiles y especificarlos usando esta opción.

El nombre del perfil se puede combinar con una o más opciones de perfil, que modifican ligeramente el comportamiento del perfil. Por ejemplo, el perfil OpenSC predeterminado admite la opción openpin, que instala un único PIN durante la inicialización de la tarjeta. Este PIN se utiliza tanto como PIN de SO como PIN de usuario para todas las claves almacenadas en la tarjeta.

El nombre del perfil y las opciones se separan con un carácter +, como en pkcs15+onepin.

--secret-key-algorithm keyspec,

keyspec describe el algoritmo y la longitud de la clave que se va a crear o descargar, como aes:256. Esto creará una clave AES de 256 bits.

--store-certificate nombre_archivo, -X nombre_archivo

Indica a pkcs15-init que almacene el certificado proporcionado en nombre_archivo en la tarjeta, creando un objeto de certificado con el ID especificado a través de la opción --id. Sin un ID proporcionado, se calculará un ID intrínseco a partir de la clave pública del certificado. Consulte la descripción del atributo 'pkcs15-id-style' en 'pkcs15.profile' para obtener detalles sobre el algoritmo utilizado para calcular el ID intrínseco. Se asume que el archivo contiene el certificado codificado en PEM. Para tarjetas multiaplicación, la aplicación de destino se puede especificar mediante el valor AID hexadecimal de la opción aid.

--store-pin, -P

Almacena un nuevo PIN/PUK en la tarjeta.

--store-public-key nombre_archivo

Indica a pkcs15-init que descargue la clave pública especificada en la tarjeta y cree un objeto de clave pública con el ID de clave especificado a través de --id. Por defecto, se asume que el archivo contiene la clave en formato PEM. Se pueden especificar formatos alternativos usando --format.

--store-private-key nombre_archivo, -S nombre_archivo

Indica a pkcs15-init que descargue la clave privada especificada en la tarjeta. Este comando también creará un objeto de clave pública que contendrá la parte de clave pública. Por defecto, se asume que el archivo contiene la clave en formato PEM. Se pueden especificar formatos alternativos usando --format. Es una buena idea especificar también el ID de la clave con este comando, usando la opción --id, de lo contrario se calculará un ID intrínseco a partir del material de la clave. Consulte la descripción del atributo 'pkcs15-id-style' en 'pkcs15.profile' para obtener detalles sobre el algoritmo utilizado para calcular el ID intrínseco. Para tarjetas multiaplicación, la aplicación PKCS#15 de destino se puede especificar mediante el valor AID hexadecimal de la opción aid.

--store-secret-key nombre_archivo,

Indica a pkcs15-init que descargue la clave secreta especificada en la tarjeta. Se asume que el archivo contiene la clave en bruto. El tipo de clave debe especificarse con la opción --secret-key-algorithm.

Adicionalmente, puede especificar el ID de la clave con este comando, usando la opción --id, de lo contrario se generará un ID aleatorio. Para tarjetas multiaplicación, la aplicación PKCS#15 de destino se puede especificar mediante el valor AID hexadecimal de la opción aid.

--store-data nombre_archivo, -W nombre_archivo

Almacena un objeto de datos.

--update-certificate nombre_archivo, -U nombre_archivo

Indica a pkcs15-init que actualice el objeto de certificado con el ID especificado a través de la opción --id con el certificado en nombre_archivo. Se asume que el archivo contiene un certificado codificado en PEM.

¡Preste especial atención al actualizar certificados de descifrado de correo, ya que la falta de certificados puede hacer que los mensajes de correo electrónico sean ilegibles!

--delete-objects arg, -D arg

Indica a pkcs15-init que elimine el objeto especificado. arg es una lista separada por comas que contiene cualquiera de los siguientes: privkey, pubkey, secrkey, cert, chain o data.

Cuando se especifica data, también se debe especificar ---application-id, en los otros casos se debe especificar un --id.

Cuando se especifica chain, se eliminará la cadena de certificados que comienza con el certificado con el ID especificado, hasta que haya un certificado de CA que certifique otro certificado en la tarjeta.

--change-attributes arg, -A arg

Indica a pkcs15-init que cambie el atributo especificado. arg es privkey, pubkey, secrkey, cert o data. También debe especificar el --id del objeto. Por ahora, solo puede cambiar la etiqueta --label, por ejemplo: 
pkcs15-init -A cert --id 45 -a 1 --label Jim

--use-default-transport-keys, -T

Indica a pkcs15-init que no solicite las claves de transporte y utilice claves predeterminadas, conocidas por el controlador de la tarjeta.

--sanity-check

Indica a pkcs15-init que realice una verificación de cordura específica de la tarjeta y, posiblemente, un procedimiento de actualización.

--reader arg, -r arg

Número del lector a utilizar. Por defecto, se utiliza el primer lector con una tarjeta presente. Si arg es un ATR, se elegirá el lector con una tarjeta coincidente.

--verbose, -v

Hace que pkcs15-init sea más detallado. Especifique esta bandera varias veces para habilitar la salida de depuración en la biblioteca OpenSC.

--wait, -w

Hace que pkcs15-init espere la inserción de una tarjeta.

--use-pinpad

No solicite al usuario; si no se proporcionan PIN, se utilizará el pinpad.

--auth-id nombre_archivo, -a nombre_archivo

Especifica el ID del PIN a usar/crear

--puk-id ID

Especifica el ID del PUK a usar/crear

--label ETIQUETA

Especifica la etiqueta para un PIN, clave, certificado o objeto de datos al crear nuevos objetos. Al eliminar objetos, esto se puede usar para eliminar objetos por etiqueta.

--puk-label ETIQUETA

Especifica la etiqueta del PUK

--public-key-label ETIQUETA

Especifica la etiqueta de la clave pública (usar con --generate-key)

--cert-label ETIQUETA

Especifica la etiqueta del certificado de usuario (usar con --store-private-key)

--application-name arg

Especifica el nombre de la aplicación del objeto de datos (usar con --store-data-object)

--aid AID

Especifica el AID de la aplicación PKCS#15 en la tarjeta a la que se enlazará (en formato hexadecimal)

--output-file nombre_archivo -o nombre_archivo,

Salida de la porción pública de la clave generada al archivo

--passphrase CONTRASEÑA

Especifica la contraseña para desbloquear la clave secreta

--authority

Marca el certificado como certificado de CA

--key-usage arg -u arg,

Especifica el uso de clave X.509. arg es una lista separada por comas que contiene cualquiera de los siguientes: digitalSignature, nonRepudiation, keyEncipherment, dataEncipherment, keyAgreement, keyCertSign, cRLSign. Se permiten nombres abreviados si son únicos (por ejemplo, dataEnc).

El alias sign es equivalente a digitalSignature,keyCertSign,cRLSign

El alias decrypt es equivalente a keyEncipherment,dataEncipherment

--finalize -F,

Finaliza la fase de inicialización de la tarjeta inteligente

--update-last-update

Actualiza el atributo 'lastUpdate' de tokenInfo

--ignore-ca-certificates

Almacenar PKCS#12, ignora los certificados de CA

--update-existing

Almacena o actualiza un certificado existente

--extractable

Clave privada almacenada como una clave extraíble

--user-consent arg

Especifica el consentimiento del usuario. arg es un valor entero. Si es > 0, el valor especifica cuántas veces se puede acceder al objeto antes de que se requiera una nueva autenticación. Si es cero, el objeto no requiere reautenticación.

b>--insecure

Modo inseguro: no requerir un PIN para la clave privada

--md-container-guid GUID

Para una nueva clave, especifique GUID para un contenedor MD

--help -h,

Mostrar mensaje de ayuda
