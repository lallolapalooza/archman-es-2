pkey_alloc(2) Manual de llamadas al sistema pkey_alloc(2)

NOMBRE

pkey_alloc, pkey_free - asignar o liberar una clave de protección

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE             /* Véase feature_test_macros(7) */
#include <sys/mman.h>
int pkey_alloc(unsigned int flags, unsigned int access_rights);
int pkey_free(int pkey);

DESCRIPCIÓN

pkey_alloc() asigna una clave de protección (pkey) y permite que se pase a pkey_mprotect(2).

El argumento flags de pkey_alloc() está reservado para uso futuro y actualmente siempre debe especificarse como 0.

El argumento access_rights de pkey_alloc() puede contener cero o más operaciones de deshabilitación:

PKEY_DISABLE_ACCESS
Deshabilita todo acceso a datos a la memoria cubierta por la clave de protección devuelta.
PKEY_DISABLE_WRITE
Deshabilita el acceso de escritura a la memoria cubierta por la clave de protección devuelta.

pkey_free() libera una clave de protección y la hace disponible para asignaciones posteriores. Después de que una clave de protección ha sido liberada, ya no puede usarse en ninguna operación relacionada con claves de protección.

Una aplicación no debe llamar a pkey_free() en ninguna clave de protección que haya sido asignada a un rango de direcciones por pkey_mprotect(2) y que todavía esté en uso. El comportamiento en este caso es indefinido y puede resultar en un error.

VALOR DE RETORNO

En caso de éxito, pkey_alloc() devuelve un valor de clave de protección positivo. En caso de éxito, pkey_free() devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EINVAL
pkey, flags, o access_rights son inválidos.
ENOSPC
(pkey_alloc()) Todas las claves de protección disponibles para el proceso actual han sido asignadas. El número de claves disponibles es específico de la arquitectura y de la implementación y puede ser reducido por el uso interno del kernel de ciertas claves. Actualmente hay 15 claves disponibles para programas de usuario en x86.
Este error también se devolverá si el procesador o el sistema operativo no admiten claves de protección. Las aplicaciones siempre deben estar preparadas para manejar este error, ya que factores fuera del control de la aplicación pueden reducir el número de pkeys disponibles.

ESTANDARES

Linux.

HISTORIA

Linux 4.9, glibc 2.27.

NOTAS

pkey_alloc() es siempre seguro de llamar independientemente de si el sistema operativo admite o no claves de protección. Puede usarse en lugar de cualquier otro mecanismo para detectar la compatibilidad de pkey y simplemente fallará con el error ENOSPC si el sistema operativo no tiene soporte para pkey.

El kernel garantiza que el contenido del registro de derechos de hardware (PKRU) se conservará solo para las claves de protección asignadas. Cada vez que una clave se desasigna (ya sea antes de la primera llamada que devuelve esa clave desde pkey_alloc() o después de que se libera a través de pkey_free()), el kernel puede realizar cambios arbitrarios en las partes del registro de derechos que afectan al acceso a esa clave.

EJEMPLOS

Véase pkeys(7).

VER TAMBIÉN

pkey_mprotect(2), pkeys(7)
