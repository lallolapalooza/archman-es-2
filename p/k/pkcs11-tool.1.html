NOMBRE

pkcs11-tool - utilidad para administrar y usar tokens de seguridad PKCS #11

SINOPSIS

pkcs11-tool [OPCIONES]

DESCRIPCIÓN

La utilidad pkcs11-tool se utiliza para administrar los objetos de datos en tarjetas inteligentes y tokens de seguridad PKCS #11 similares. Los usuarios pueden listar y leer PIN, claves y certificados almacenados en el token. Se realiza la autenticación con el PIN de usuario para las operaciones que lo requieren.

OPCIONES

--attr-from nombrearchivo

Extrae información de nombrearchivo (archivo de certificado codificado en DER) y crea los atributos correspondientes al escribir un objeto en el token. Ejemplo: el nombre del sujeto del certificado se utiliza para crear el atributo CKA_SUBJECT.

--change-pin, -c

Cambia el PIN de usuario en el token.

--unlock-pin

Desbloquea el PIN de usuario (sin --login desbloqueo en sesión iniciada; de lo contrario, --login-type debe ser 'context-specific').

--hash, -h

Calcula el hash de algunos datos.

--hash-algorithm mecanismo

Especifica el algoritmo de hash utilizado con la firma RSA-PKCS-PSS o el descifrado RSA-OAEP. Los valores permitidos son "SHA-1", "SHA256", "SHA384", "SHA512", y algunos tokens también pueden permitir "SHA224". El valor por defecto es "SHA-1".

Tenga en cuenta que la entrada para RSA-PKCS-PSS debe tener un tamaño igual al algoritmo de hash especificado. Por ejemplo, para SHA256, la entrada de la firma debe tener exactamente 32 bytes de longitud (para los mecanismos SHA256-RSA-PKCS-PSS no existe tal restricción). Para RSA-OAEP, el tamaño de la entrada del texto plano mLen no debe superar keyLen - 2 - 2*hashLen. Por ejemplo, para una clave RSA de 3072 bits y SHA384, el texto plano más largo para cifrar con RSA-OAEP es (con todos los tamaños en bytes): 384 - 2 - 2*48 = 286, es decir, 286 bytes.

--id id, -d id

Especifica el id del objeto sobre el que operar.

--init-pin

Inicializa el PIN de usuario. Esta opción difiere de --change-pin en que establece el PIN de usuario por primera vez. Una vez establecido, el PIN de usuario se puede cambiar usando --change-pin.

--init-token

Inicializa un token: establece la etiqueta del token y un PIN de Oficial de Seguridad (la etiqueta debe especificarse usando --label).

--input-file nombrearchivo, -i nombrearchivo

Especifica la ruta a un archivo para entrada.

--keypairgen, -k

Genera un nuevo par de claves (par público y privado).

--keygen

Genera una nueva clave.

--key-type especificación

Especifica el tipo y (no siempre obligatorio) el sabor (longitud de clave simétrica en bytes, longitud de clave asimétrica en bits, identificador de curva elíptica, etc.) de la clave a crear, por ejemplo RSA:2048, EC:prime256v1, GOSTR3410-2012-256:B, DES:8, DES3:24, AES:16, AES: o GENERIC:64. Si el tipo de clave se especificó de forma incompleta, se muestran los valores posibles.

--usage-sign

Especifica el indicador de uso de clave 'sign' (establece SIGN en privkey, establece VERIFY en pubkey).

--usage-decrypt

Especifica el indicador de uso de clave 'decrypt'.

Para claves RSA, establece DECRYPT en privkey y ENCRYPT en pubkey. Para claves secretas, establece DECRYPT y ENCRYPT.

--usage-derive

Especifica el indicador de uso de clave 'derive' (solo EC).

--usage-wrap

Especifica el indicador de uso de clave 'wrap'.

--label nombre, -a nombre

Especifica el nombre del objeto sobre el que operar (o la etiqueta del token cuando se usa --init-token).

--list-mechanisms, -M

Muestra una lista de mecanismos compatibles con el token.

--list-objects, -O

Muestra una lista de objetos.

Las opciones --keytype, --label, --id o --application-id se pueden usar para filtrar los objetos listados.

--list-slots, -L

Muestra una lista de ranuras (slots) disponibles en el token.

--list-token-slots, -T

Lista ranuras con tokens.

--list-interfaces

Lista las interfaces de la biblioteca PKCS #11 3.0.

--session-rw,

Fuerza la apertura de la sesión PKCS#11 con CKF_RW_SESSION.

--login, -l

Autentica en el token antes de realizar otras operaciones. Esta opción no es necesaria si se proporciona un PIN en la línea de comandos.

--login-type

Especifica el tipo de inicio de sesión ('so', 'user', 'context-specific'; por defecto: 'user').

--mechanism mecanismo, -m mecanismo

Utiliza el mecanismo especificado para las operaciones del token. Consulte -M para obtener una lista de los mecanismos compatibles con su token. El mecanismo también se puede especificar en formato hexadecimal, por ejemplo, 0x80001234.

--mgf función

Utiliza la Función de Generación de Mensajes (MGF) función especificada para firmas RSA-PKCS-PSS o descifrados RSA-OAEP. Los argumentos admitidos son MGF1-SHA1 a MGF1-SHA512 si son compatibles con el controlador. El valor por defecto se basa en la selección de hash.

--module mod

Especifica un módulo (o biblioteca) PKCS#11 para cargar.

--moz-cert nombrearchivo, -z nombrearchivo

Prueba la generación de pares de claves similar a Mozilla y la solicitud de certificado. Especifica el nombrearchivo del archivo de certificado.

--output-file nombrearchivo, -o nombrearchivo

Especifica la ruta a un archivo para salida.

--pin pin, -p pin

Utiliza el pin dado para las operaciones del token. Si se establece en env:VARIABLE, se utiliza el valor de la variable de entorno VARIABLE. ADVERTENCIA: Tenga cuidado al usar esta opción, ya que otros usuarios pueden leer la línea de comandos del sistema o si está incrustada en un script. Si se establece en env:VARIABLE, se utiliza el valor de la variable de entorno VARIABLE.

Esta opción también establecerá la opción --login.

--puk puk

Proporciona el PUK de usuario en la línea de comandos.

--new-pin pin

Proporciona el nuevo PIN de usuario en la línea de comandos.

--sensitive

Establece el atributo CKA_SENSITIVE (el objeto no se puede revelar en texto plano).

--extractable

Establece el atributo CKA_EXTRACTABLE (el objeto se puede extraer).

--undestroyable

Establece el atributo CKA_DESTROYABLE en falso (el objeto no se puede destruir).

--set-id id, -e id

Establece el CKA_ID del objeto.

--show-info, -I

Muestra información general del token.

--sign, -s

Firma algunos datos.

--decrypt,

Descifra algunos datos.

--encrypt,

Cifra algunos datos.

--unwrap,

Desenvuelve clave.

--wrap,

Envuelve clave.

--derive,

Deriva una clave secreta usando otra clave y algunos datos.

--derive-pass-der,

Deriva la clave pública ECDHpass codificada en DER para compatibilidad con algunas implementaciones PKCS#11.

--salt-len bytes

Especifica cuántos bytes de sal se deben usar en las firmas RSA-PSS. Acepta dos valores especiales: "-1" significa que la longitud de la sal es igual a la longitud del digest, "-2" o "-3" significa que se usa la longitud máxima permitida. Para la operación de verificación, "-2" significa que la longitud de la sal se recupera automáticamente de la firma. El valor "-2" para la operación de verificación solo es compatible con el módulo opensc pkcs#11. Por defecto es la longitud del digest (-1).

--slot id

Especifica el id de la ranura a usar (acepta formato HEX con prefijo 0x.. o número decimal).

--slot-description descrip

DESCRIPCIÓN

pkcs11-tool es una herramienta para probar y operar con dispositivos PKCS#11.

Los dispositivos PKCS#11 son, por ejemplo, tarjetas inteligentes o tokens USB que contienen un módulo PKCS#11 y ofrecen acceso a los servicios de criptografía del dispositivo.

El programa puede ser usado para:

  • Listar los objetos (certificados, claves, etc.) del dispositivo.
  • Leer los objetos del dispositivo.
  • Escribir objetos en el dispositivo.
  • Generar pares de claves en el dispositivo.
  • Generar datos aleatorios del dispositivo.
  • Firmar datos con claves privadas del dispositivo.
  • Verificar firmas con claves públicas del dispositivo.
  • Cifrar/Descifrar datos con el dispositivo.
  • Cifrar/Descifrar claves (wrap/unwrap) con el dispositivo.
  • Inicializar el dispositivo (ej. establecer PIN).
  • Realizar pruebas de funcionalidad.

OPCIONES

A continuación se detallan las opciones disponibles para pkcs11-tool:

--module device, -d device
Especifique la ruta al módulo PKCS#11. Si no se especifica, se intentará detectar un módulo adecuado.
--login, -l
Inicie sesión en el token con el PIN de usuario. Se le pedirá que introduzca el PIN si no se proporciona explícitamente.
--login-type type
Especifique el tipo de inicio de sesión. Los valores válidos son normal (para el PIN de usuario) y so (para el PIN del Oficial de Seguridad).
--pin pin, -p pin
Especifique el PIN de usuario. Si se establece en env:VARIABLE, se utiliza el valor de la variable de entorno VARIABLE. Tenga en cuenta que el PIN se mostrará en el historial de comandos.
--change-pin, -n
Cambie el PIN de usuario. Se le pedirá el PIN antiguo y el nuevo.
--so-change-pin, -P
Cambie el PIN del Oficial de Seguridad (SO). Se le pedirá el PIN de SO antiguo y el nuevo.
--input-file file, -i file
Especifique el archivo de entrada. Utilizado para operaciones como firmar, cifrar, escribir objetos o para datos de verificación.
--output-file file, -o file
Especifique el archivo de salida. Utilizado para almacenar datos firmados, cifrados, objetos leídos o claves generadas.
--list-objects, -L
Enumera todos los objetos (certificados, claves, etc.) en el dispositivo. Puede ser filtrado por tipo usando la opción --type.
--generate-key, -g
Genere una clave. Se requiere la opción --key-type para especificar el tipo de clave (ej. RSA, ECDSA, AES).
--keypairgen, -k
Genere un par de claves (clave privada y pública). Se requiere la opción --key-type.
--key-type keytype
Especifique el tipo de clave a generar. Los valores válidos incluyen RSA, RSA-FAST, RSA2048, RSA3072, RSA4096, DH, DSA, ECDSA, EC, EC:secp256r1, EC:secp384r1, EC:secp521r1, AES, DES, DES3, HMAC.
--key-bits bits
Especifique el número de bits para la clave a generar (ej. 2048 para RSA).
--ecc-curve curve
Especifique la curva elíptica para claves EC (ej. secp256r1, secp384r1, secp521r1).
--dsa-param file
Especifique un archivo que contenga los parámetros DSA (p, q, g).
--label label
Especifique una etiqueta para el objeto.
--id id
Especifique un ID para el objeto (en formato hexadecimal).
--extractable
Marque el objeto como extraíble (si el token lo soporta).
--private
Establezca el atributo CKA_PRIVATE (el objeto solo es visible después de un inicio de sesión).
--always-auth
Establezca el atributo CKA_ALWAYS_AUTHENTICATE en un objeto de clave privada. Si se establece, el usuario debe proporcionar el PIN para cada uso (firmar o descifrar) con la clave.
--allowed-mechanisms mechanisms
Establece el atributo CKA_ALLOWED_MECHANISMS en objetos de clave al importar un objeto o generar claves. El argumento acepta una lista de algoritmos separados por comas que se pueden usar con la clave dada.
--sign
Firme datos utilizando una clave privada.
--verify
Verifique la firma de algunos datos.
--encrypt
Cifre datos utilizando una clave.
--decrypt
Descifre datos utilizando una clave.
--wrap
Cifre (envuelva) una clave utilizando una clave de envoltura.
--unwrap
Descifre (desenvuelva) una clave utilizando una clave de desenvuelto.
--mechanism mechanism
Especifique el mecanismo criptográfico a utilizar (ej. RSA-SHA256, AES-CBC).
--list-mechanisms
Enumere todos los mecanismos criptográficos compatibles con el módulo PKCS#11.
--slot slot
Especifique el número de ranura (slot) a utilizar. Si no se especifica, se intenta utilizar la primera ranura disponible.
--slot-index index
Especifique el índice de la ranura a utilizar.
--object-index index
Especifique el índice del objeto a utilizar.
--use-locking
Indique al módulo pkcs11 que utilice el bloqueo de hilos del sistema operativo.
--test-threads options
Pruebe las implicaciones de hilos de un módulo pkcs11. (Ver código fuente).
--token-label label
Especifique la etiqueta del token. Se utilizará la primera ranura que tenga el token insertado con esta etiqueta.
--so-pin pin, -a pin
Utilice el pin dado como PIN del Oficial de Seguridad para algunas operaciones del token (inicialización del token, inicialización del PIN de usuario, etc.). Si se establece en env:VARIABLE, se utiliza el valor de la variable de entorno VARIABLE. La misma advertencia que para --pin también se aplica aquí.
--test, -t
Realice algunas pruebas en el token. Esta opción es más útil cuando se utiliza con --login o --pin.
--test-hotplug
Pruebe las capacidades de conexión en caliente (C_GetSlotList + C_WaitForSlotEvent).
--private
Establezca el atributo CKA_PRIVATE (el objeto solo es visible después de un inicio de sesión).
--always-auth
Establezca el atributo CKA_ALWAYS_AUTHENTICATE en un objeto de clave privada. Si se establece, el usuario deberá proporcionar el PIN para cada uso (firmar o descifrar) con la clave.
--allowed-mechanisms mechanisms
Establece el atributo CKA_ALLOWED_MECHANISMS en objetos de clave al importar un objeto o generar claves. El argumento acepta una lista de algoritmos separados por comas que se pueden usar con la clave dada.
--test-ec
Pruebe EC (mejor usar con la opción --login o --pin).
--test-fork
Pruebe la bifurcación y la llamada a C_Initialize() en el hijo.
--type type, -y type
Especifique el tipo de objeto sobre el que operar. Los valores válidos son cert, privkey, pubkey, secrkey y data.
--verbose, -v
Hace que pkcs11-tool sea más verboso.

NB! ¡Esto no afecta el nivel de depuración de OpenSC! Para activar el modo de depuración del módulo PKCS#11 de OpenSC, establezca la variable de entorno OPENSC_DEBUG a un número distinto de cero.

--verify,
Verifique la firma de algunos datos.
--read-object, -r
Obtenga el atributo CKA_VALUE del objeto (use con --type).
--delete-object, -b
Elimine un objeto.
--application-label label
Especifique la etiqueta de la aplicación del objeto de datos (use con --type data).
--application-id id
Especifique el ID de la aplicación del objeto de datos (use con --type data).
--issuer data
Especifique el emisor en formato hexadecimal (use con --type cert).
--subject data
Especifique el sujeto en formato hexadecimal (use con --type cert/privkey/pubkey).
--signature-file filename
La ruta al archivo de firma para la verificación de la firma
--signature-format format
Formato para la firma ECDSA: 'rs' (predeterminado), 'sequence', 'openssl'.
--write-object filename, -w filename
Escriba una clave o un objeto de certificado en el token. filename apunta al archivo de certificado o clave codificado en DER.
--generate-random num
Obtenga num bytes de datos aleatorios.
--allow-sw
Permitir el uso de mecanismos de software que no tengan el flag CKF_HW. Puede ser necesario al usar tokens de software y emuladores.
--iv data
Vector de inicialización para cifrados simétricos. Los data son números hexadecimales, es decir, "000013aa7bffa0".
--mac-general-param num
Establece la longitud del MAC para los mecanismos de MAC de longitud general en num bytes.
--aad data
Datos autenticados adicionales para cifrados AEAD. Los data son un número hexadecimal.
--tag-bits-len num
Establece la longitud de la etiqueta para cifrados AEAD en num bits.
--salt-file filename
Especifique el archivo que contiene la sal para HKDF (opcional)
--info-file filename
Especifique el archivo que contiene la información para HKDF (opcional)

EJEMPLOS

Realice una prueba básica de funcionalidad de la tarjeta:

pkcs11-tool --test --login

Liste todos los certificados en la tarjeta inteligente:

pkcs11-tool --list-objects --type cert

Lea el certificado con ID CERT_ID en formato DER de la tarjeta inteligente y conviértalo a PEM a través de OpenSSL:

pkcs11-tool --read-object --id $CERT_ID --type cert \
					--output-file cert.der
openssl x509 -inform DER -in cert.der -outform PEM > cert.pem

Escriba un certificado en el token:

pkcs11-tool --login --write-object certificate.der --type cert

Genere un nuevo par de claves RSA:

pkcs11-tool --login --keypairgen --key-type RSA:2048

Genere un nuevo par de claves RSA extraíble:

pkcs11-tool --login --keypairgen --key-type RSA:2048 --extractable

Genere un par de claves de curva elíptica con OpenSSL e impórtelo a la tarjeta como $ID:

openssl genpkey -out EC_private.der -outform DER \
	-algorithm EC -pkeyopt ec_paramgen_curve:P-521
pkcs11-tool --write-object EC_private.der --id "$ID" \
	--type privkey --label "EC private key" -p "$PIN"
openssl pkey -in EC_private.der -out EC_public.der \
	-pubout -inform DER -outform DER
pkcs11-tool --write-object EC_public.der --id "$ID" \
	--type pubkey  --label "EC public key" -p $PIN

Liste las claves privadas:

pkcs11-tool --login --list-objects --type privkey

Firme algunos datos almacenados en el archivo data utilizando la clave privada con ID ID y utilizando el mecanismo RSA-PKCS:

pkcs11-tool --sign --id $ID --mechanism RSA-PKCS \
	--input-file data --output-file data.sig

Lo mismo también es posible canalizando los datos desde stdin en lugar de especificar un archivo de entrada:

dd if=data bs=128 count=1 \
	| pkcs11-tool --sign --id $ID --mechanism RSA-PKCS \
	> data.sig

Verifique los datos firmados:

pkcs11-tool --id ID --verify -m RSA-PKCS \
	--input-file data --signature-file data.sig

Para cifrar un archivo usando la clave AES con ID 85 y usando el mecanismo AES-CBC con padding:

pkcs11-tool --login --encrypt --id 85 -m AES-CBC-PAD \
	--iv "00000000000000000000000000000000" \
	-i file.txt -o encrypted_file.data

Descifre el archivo cifrado:

pkcs11-tool --login --decrypt --id 85 -m AES-CBC-PAD \
	--iv "00000000000000000000000000000000" \
	--i encrypted_file.data -o decrypted.txt

Use la clave con ID 75 utilizando el mecanismo AES-CBC-PAD, con vector de inicialización "00000000000000000000000000000000" para envolver la clave con ID 76 en el archivo de salida exported_aes.key

pkcs11-tool --login --wrap --id 75 --mechanism AES-CBC-PAD \
	--iv "00000000000000000000000000000000" \
	--application-id 76 \
	--output-file exported_aes.key

Use la clave con ID 22 y el mecanismo RSA-PKCS para desenvolver la clave del archivo aes_wrapped.key. Después de una operación de desenvuelto exitosa, se crea una nueva clave AES en el token. El ID de esta clave se establece en 90 y la etiqueta de esta clave se establece en unwrapped-key. Nota: para la tarjeta MyEID, el tamaño de la clave AES debe estar presente en la especificación de la clave, es decir, AES:16

pkcs11-tool --login --unwrap --mechanism RSA-PKCS --id 22 \
	-i aes_wrapped.key --key-type AES: \
	--application-id 90 --applicatin-label unwrapped-key

Utilice el SO-PIN para inicializar o restablecer el PIN:

pkcs11-tool --login --login-type so --init-pin
