PKCS15-PROFILE(5) Formatos de archivo de OpenSC PKCS15-PROFILE(5)

NOMBRE

pkcs15-profile - formato del perfil para pkcs15-init

DESCRIPCIÓN

La utilidad pkcs15-init para la personalización de tarjetas inteligentes PKCS #15 se controla mediante perfiles. Al iniciarse, leerá dos perfiles en este momento, un perfil de aplicación genérico y un perfil específico de la tarjeta. El perfil genérico debe especificarse en la línea de comandos, mientras que el archivo específico de la tarjeta se selecciona en función del tipo de tarjeta detectada.

El perfil de aplicación genérico define información general sobre el diseño de la tarjeta, como la ruta del DF de la aplicación, varios archivos PKCS #15 dentro de ese directorio y las condiciones de acceso a esos archivos. También define información general sobre objetos PIN, clave y certificado. Actualmente, solo existe un perfil genérico de este tipo, pkcs15.profile.

El perfil específico de la tarjeta contiene información adicional requerida durante la inicialización de la tarjeta, como la ubicación de los archivos PIN, referencias de claves, etc. Los perfiles residen actualmente en /usr/share/opensc

Terminología básica de PKCS#15:

1. MF (Master File) es la raíz de la jerarquía del sistema de archivos.
2. DF(PKCS#15) es el directorio que contiene los archivos y directorios de PKCS#15.
3. EF(ODF) (Object Directory File) es un archivo elemental que contiene punteros a otros archivos elementales (PrKDFs, PuKDFs, SKDFs, CDFs, DODFs, AODFs).
4. PrKDF (Private Key Directory File) es un archivo elemental que contiene punteros a las claves privadas y información adicional sobre las claves privadas.
5. PubKDF (Public Key Directory File) es un archivo elemental que contiene punteros a las claves públicas y información adicional sobre las claves públicas.
6. CDF (Certificate Directory File) es un archivo elemental que contiene punteros a los certificados e información adicional sobre los certificados.
7. EF(TokenInfo) es un archivo elemental con información genérica sobre la tarjeta.

SINTAXIS Y SEMÁNTICA

La sintaxis de bloques de los archivos de perfil es, en general, similar a la del archivo de configuración. El archivo de perfil se compone de bloques que, en general, tienen el siguiente formato:

clave [, nombre...] {
	contenido_del_bloque
}

contenido_del_bloque son uno o más elementos_de_bloque donde un elemento_de_bloque es uno de:

•# cadena_de_comentario
•clave[, nombre...] = valor;
•bloque

En el nivel raíz, el perfil contiene varios bloques de configuración. Las claves de los bloques son las siguientes:

•cardinfo: Configuración de información general sobre la tarjeta.
•pkcs15: Control de algunos aspectos generales del PKCS#15 que se incluirán en la tarjeta.
•option: Opciones de perfil para modificar el comportamiento del perfil.
•PIN: Configuración y límites para tipos de PIN específicos.
•filesystem: Especificación del sistema de archivos que se creará en la tarjeta.
•macros

Configuración del archivo de perfil

Configuración de la información de la tarjeta

cardinfo { contenido_del_bloque }

Configuración de información general sobre la tarjeta:

label = nombre;

Etiqueta de la tarjeta (Predeterminado: Tarjeta OpenSC).

manufacturer = nombre;

Fabricante de la tarjeta (Predeterminado: Proyecto OpenSC).

min-pin-length = int;

Longitud mínima del PIN (Predeterminado: 4).

max-pin-length = int;

Longitud máxima del PIN, debe anularse en el perfil por tarjeta (Predeterminado: 8).

pin-encoding = valor;

Tipo de codificación del PIN. Parámetros conocidos:
•BCD: decimal codificado en binario
•ascii-numeric: valores numéricos ASCII
•utf8
•half-nibble-bcd
•iso9564-1

(Predeterminado: ascii-numeric).

pin-pad-char = valor;

Carácter utilizado para rellenar el PIN cuando sea necesario (Predeterminado: 0x00).

pin-domains = bool;

Algunas tarjetas necesitan mantener todos sus PIN en directorios separados. Las claves particulares de ese dominio se colocarán debajo del DF del PIN especificado. (Predeterminado: no)

Configuración de PKCS#15

pkcs15 { contenido_del_bloque }

Control de algunos aspectos generales del PKCS#15 que se incluirán en la tarjeta. Los parámetros de este bloque son:

direct-certificates = bool;

El sistema PKCS#15 debe contener al menos un CDF, que contiene los certificados directamente o referencias a ellos. Esta opción define si los certificados deben incluirse directamente en el CDF o no (Predeterminado: no).

encode-df-length = bool;

Guarda la longitud del DF en el archivo ODF. Útil si almacenamos certificados directamente en el CDF para un mejor rendimiento y robustez (Predeterminado: no).

do-last-update = valor;

Almacena información sobre la última actualización en el EF(TokenInfo) (Predeterminado: sí).

pkcs15-id-style = valor;

Método para calcular el ID de los objetos criptográficos. Parámetros conocidos:
•native: 'E' + número de objetos presentes del mismo tipo
•mozilla: SHA1(módulo) para RSA
•rfc2459 SHA1(secuencia ASN1 de los componentes de la clave pública como enteros ASN1)
(Predeterminado: native) .sp

minidriver-support-style = valor;

Estilo de soporte de minidriver de pkcs15-init. Parámetros conocidos:
•none
•gemalto

(Predeterminado: none)

pkcs15-profile(5) — opensc

NAME

pkcs15.profile — pkcs15-profile profile file format

DESCRIPTION

The pkcs15.profile file is used to specify the structure of the files on the smart card. It is used by the pkcs15-init(1) command to initialize the card.

A profile file consists of several nested blocks describing the filesystem structure. The main blocks are:

  • PIN_DEFINITION
  • Configuration of Filesystem

PIN_DEFINITION

The PIN_DEFINITION block describes the properties of a PIN. The syntax is:

PIN_DEFINITION [ name ] {
	block_contents
}

The name is optional and identifies the PIN. If not specified, the name defaults to the value specified in the Configuration of Filesystem section.

Known parameters are:

attempts = int;
Defines number of attempts for the given PIN (Default: 3).
flags = value...;
Flags define properties of the PIN. Possible flags:
  • case-sensitive
  • local
  • change-disabled
  • unblock-disabled
  • initialized
  • needs-padding
  • unblockingPin
  • soPin
  • disable-allowed
  • integrity-protected
  • confidentiality-protected
  • exchangeRefData
(Default: local,initialized,needs-padding).
auth-id = value;
Value used for auth ID (Default: 0).
min-length = int;
Minimal length of PIN (Default: value min-pin-length set in cardinfo block).
max-length = int;
Maximal length of PIN (Default: value max-pin-length set in cardinfo block).
reference = int;
Value of reference of the PIN (Default: set in particular card driver).
file = name;
File with PIN, obsolete option (Default: None).
offset = int;
Offset of PIN in PIN file, obsolete option (Default: 0).
encoding = value;
Encoding type of PIN. Possible values:
  • BCD
  • ascii-numeric
  • utf8
  • half-nibble-bcd
  • iso9564-1
(Default: value pin-encoding set in cardinfo block).
stored-length = int;
(Default: value max-pin-length set in cardinfo block).
max-unlocks = int;
(Default: 0).

Values in this block can be set by macros. That allows to specify the particular values with the usage of option.

Configuration of Filesystem

This block contains the specification for filesystem that is to be created on the card. The filesystem consists of several nested blocks representing DF and EF files. When the DFs or EFs are specified in card specific profile, this is added to the file system info specified in the main profile.

filesystem {
	block_contents
}

EF name { block_contents }

This block defines elementary file in PKCS#15 file hierarchy. The name can be one of:

PKCS15-TokenInfo
PKCS15-ODF
PKCS15-UnusedSpace
PKCS15-PRKDF
PKCS15-PUKDF
PKCS15-PUKDF-TRUSTED
PKCS15-SKDF
PKCS15-CDF
PKCS15-CDF-TRUSTED
PKCS15-CDF-USEFUL
PKCS15-DODF
PKCS15-AODF

The EF block can contain:

type = EF;
Type must match type of file.
acl = value;
Value of ACL (Access Control List) (Default: NONE)
file-id = EF;
File ID, relative path.
structure = value;
File structure is one of:
  • TRANSPARENT
  • LINEAR-FIXED
  • LINEAR-FIXED-TLV
  • LINEAR-VARIABLE
  • LINEAR-VARIABLE-TLV
  • CYCLIC
  • CYCLIC-TLV

DF name { block_contents }

This block defines directory file in PKCS#15 file hierarchy. The name can be one of:

MF
PKCS15-AppDF
Special cases for those DFs handled separately by the PKCS15 logic

The DF block can contain:

type = DF;
Type must match type of file.
path = value;
Specification of path of the directory file.
file-id = value;
File ID, relative path.
aid = value;
Value of AID, in XX:XX:XX:...:XX:XX:XX notation.
acl = value;
Type must match type of file.
size = int;
Size of the file in bytes.
EF name { block_contents }
Block specifying nested elementary file.

Typically, the root DF is MF.

It is mandatory that profile file contains DF entry for MF (Master File). Otherwise the profile file is incomplete and cannot be used.

The DF can contain other DF or MF blocks. For examples how the filesystem structure may look like, please refer to pkcs15.profile or any other present profile file.
