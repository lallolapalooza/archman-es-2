NAME

pkcs11.conf - Archivos de configuración para módulos PKCS#11

DESCRIPTION

Los archivos de configuración pkcs11.conf son una forma estándar de configurar módulos PKCS#11.

FILE FORMAT

Una configuración completa consta de varios archivos. Estos archivos son archivos de texto. Dado que p11-kit está diseñado para ser utilizado en todo tipo de entornos y en niveles muy bajos de la pila de software, no podemos utilizar API de configuración de alto nivel que pueda encontrar en un escritorio moderno.

Cada ajuste en el archivo de configuración se especifica con un nombre y un valor. El nombre es una cadena simple que consiste en caracteres y guiones. El nombre consta de caracteres alfanuméricos, puntos, guiones y guiones bajos.

El valor se especifica después del nombre en la misma línea, separado de él por dos puntos (:). El espacio en blanco entre el nombre y el valor se ignora.

Las líneas en blanco se ignoran. El espacio en blanco al principio o al final de las líneas se elimina. Las líneas que comienzan con un carácter # se ignoran como comentarios. Los comentarios no se reconocen cuando aparecen después de un valor en una línea.

Un archivo de configuración de módulo ficticio podría verse así:

module: module.so
# Aquí hay un comentario
managed: true
setting.2: Un valor largo con texto.
x-custom : text

MODULE CONFIGURATION

Cada módulo PKCS#11 configurado tiene su propio archivo de configuración. Estos archivos se pueden colocar en varias ubicaciones.

El nombre del archivo de configuración puede consistir en letras mayúsculas y minúsculas, guiones bajos, comas, guiones y puntos. Los primeros caracteres deben ser alfanuméricos, el nombre del archivo debe terminar con una extensión .module.

Lo más importante es que cada archivo de configuración especifica la ruta del módulo PKCS#11 a cargar. Un archivo de configuración de módulo tiene los siguientes campos:

module:

El nombre del archivo del módulo PKCS#11 a cargar. Esto debe incluir una extensión como .so

Si este valor está en blanco, el módulo se ignorará. Esto se puede usar en las configuraciones del usuario para anular la carga de un módulo especificado en la configuración del sistema.

Si esta es una ruta relativa, el módulo se cargará desde el directorio de módulos predeterminado.

critical:

Se establece en sí si el módulo es crítico y se requiere cargar. Si un módulo crítico no se puede cargar o inicializar, el proceso de carga de todos los módulos registrados se abortará y devolverá un código de error.

Este argumento es opcional y por defecto es no.

enable-in:

Una lista separada por comas y/o espacios de nombres de programas en los que este módulo solo debe cargarse. El módulo no se cargará para otros programas que utilicen p11-kit. Aquí se debe usar el nombre base del ejecutable del proceso, por ejemplo, seahorse, ssh.

Esta opción también se puede utilizar para controlar si el módulo será cargado por el módulo proxy. Para habilitar la carga solo desde el módulo proxy, especifique p11-kit-proxy como valor.

Esta no es una característica de seguridad. El argumento es opcional. Si no está presente, cualquier proceso cargará el módulo.

disable-in:

Una lista separada por comas y/o espacios de nombres de programas en los que este módulo no debe cargarse. El módulo se cargará para cualquier otro programa que utilice p11-kit. Aquí se debe usar el nombre base del ejecutable del proceso, por ejemplo, firefox, thunderbird-bin.

Esta opción también se puede utilizar para controlar si el módulo será cargado por el módulo proxy. Para deshabilitar la carga desde el módulo proxy, especifique p11-kit-proxy como valor.

Esta no es una característica de seguridad. El argumento es opcional. Si no está presente, cualquier proceso cargará el módulo.

managed:

Se establece en no si el módulo no debe ser administrado por p11-kit. No se recomienda hacer un módulo no administrado, y causará problemas si varios llamadores en un solo proceso comparten un módulo PKCS#11.

Este argumento es opcional y por defecto es sí.

priority:

El valor debe ser un entero. Cuando se devuelven listas de módulos a un llamador de p11-kit, los módulos con un número más alto se ordenan primero. Cuando las aplicaciones buscan módulos para certificados, claves e información de política de confianza, esta configuración afectará lo que se encuentra primero.

Este argumento es opcional y por defecto es cero. Los módulos con la misma opción priority se ordenarán alfabéticamente.

remote:

En lugar de cargar el módulo PKCS#11 localmente, ejecute el módulo de forma remota.

Especifique un comando para ejecutar, prefijado con | una tubería. El comando debe hablar el protocolo de remoting de p11-kit en su entrada estándar y salida estándar. Por ejemplo:

remote: |ssh user@remote p11-kit remote /path/to/module.so

Otras formas de remoting aparecerán en versiones posteriores de p11-kit.

trust-policy:

Se establece en sí para usar este módulo como fuente de información de política de confianza, como anclas de certificados y listas de bloqueo.

log-calls:

Se establece en sí para escribir un registro en stderr de todas las llamadas al módulo. Esto solo es compatible con módulos administrados.

Este argumento es opcional y por defecto es no.

server-address:

Una dirección de socket en la que el servidor p11-kit está escuchando. Solo aplicable al módulo p11-kit-client.

Esta opción se puede anular con la variable de entorno P11_KIT_SERVER_ADDRESS.

No especifique `enable-in` ni `disable-in` para el mismo módulo.

Otros campos pueden estar presentes, pero se recomienda que los nombres de campo que no se especifican en este documento comiencen con un prefijo x-.

GLOBAL CONFIGURATION

También puede estar presente una configuración global. Este archivo contiene configuraciones que no están relacionadas con un solo módulo PKCS#11. Las ubicaciones del archivo de configuración global se describen a continuación. El archivo de configuración global puede contener los siguientes campos:

user-config:

Será igual a uno de los siguientes valores: none, merge, only.

managed:

Se establece en sí o no para forzar que todos los módulos sean administrados o no administrados por p11-kit. Establecer esta configuración en un archivo de configuración global anulará la configuración `managed` en los archivos de configuración de módulos individuales. No se recomienda hacer módulos no administrados, y causará problemas si varios llamadores en un solo proceso comparten un módulo PKCS#11.

Este argumento es opcional.

log-calls:

Se establece en sí para escribir un registro en stderr de todas las llamadas a todos los módulos configurados. Esto solo es compatible con módulos administrados.

Este argumento es opcional.

Otros campos pueden estar presentes, pero se recomienda que los nombres de campo que no se especifican en este documento comiencen con un prefijo x-.

CONFIGURATION FILES

Cada módulo PKCS#11 configurado tiene su propio archivo de configuración. Estos archivos se colocan en un directorio. Además, existe un archivo de configuración global. Hay una configuración del sistema que consta de los diversos archivos de configuración de módulos y un archivo para la configuración global. Opcionalmente, cada usuario puede proporcionar configuración adicional o anular la configuración del sistema.

El archivo de configuración global del sistema suele estar en /etc/pkcs11/pkcs11.conf y el archivo de configuración global del usuario está en ~/.config/pkcs11/pkcs11.conf en el directorio de inicio del usuario.

Los archivos de configuración de módulos suelen ubicarse en el directorio /etc/pkcs11/modules, con un archivo de configuración por módulo. Además, el directorio ~/.config/pkcs11/modules se puede usar para módulos instalados por el usuario.

Tenga en cuenta que los archivos de configuración del usuario no se cargan desde el directorio de inicio si se ejecutan dentro de un programa setuid o setgid.

El archivo de configuración del sistema predeterminado y el directorio de módulos se pueden cambiar al compilar p11-kit. Siempre busque estas rutas usando pkg-config.
