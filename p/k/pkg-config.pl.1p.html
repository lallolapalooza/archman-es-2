pkg-config.pl(1p)

Paquete: perl-pkgconfig

Licencias: PerlArtistic

PKG-CONFIG(1p) Documentación de Perl contribuida por el usuario PKG-CONFIG(1p)

NOMBRE

PkgConfig - Reemplazo de pkg-config puro de Perl y solo del núcleo

SINOPSIS

Como reemplazo de "pkg-config"

$ ppkg-config --libs --cflags --static gio-2.0
#salida (líneas rotas artificialmente para facilitar la lectura):
# -I/usr/include/glib-2.0 -I/usr/lib/glib-2.0/include
# -pthread -lgio-2.0 -lz -lresolv -lgobject-2.0
# -lgmodule-2.0 -ldl -lgthread-2.0 -pthread -lrt -lglib-2.0

"pkg-config.pl" puede usarse como un alias para "ppkg-config" en plataformas que lo soporten. También puede instalarse como "pkg-config", aunque esto no se recomienda si su sistema tiene un "pkg-config" nativo.

Comparar con:
$ pkg-config --libs --cflags --static gio-2.0

#salida ( "" ):
# -pthread -I/usr/include/glib-2.0 -I/usr/lib/glib-2.0/include
# -pthread -lgio-2.0 -lz -lresolv -lgobject-2.0 -lgmodule-2.0
# -ldl -lgthread-2.0 -lrt -lglib-2.0

Desde otro módulo de Perl

use PkgConfig;
my $o = PkgConfig->find('gio');
if($o->errmsg) {
    #manejar error
} else {
    my $prefix = $o->get_var('prefix');
    my @cflags = $o->get_cflags;
    my @ldflags = $o->get_ldflags;
}

DESCRIPCIÓN

"PkgConfig" proporciona un reemplazo puro de Perl y solo del núcleo para la utilidad "pkg-config".

Esta no es una descripción de los usos de "pkg-config", sino una descripción de las diferencias entre la versión C y la de Perl.

Mientras que "pkg-config" es un binario compilado enlazado con glib, la versión pura de Perl no tiene tal requisito y se ejecutará donde sea que se ejecute Perl ( >= 5.6 ).

Las principales opciones soportadas son las comunes "--libs", "--cflags", "--static", "--exists" y "--modversion".

OPCIONES DEL SCRIPT

USO

<nombrepaquete1 nombrepaquete2..> [ --opciones ]

ARGUMENTOS

Por defecto, se debe proporcionar un nombre de biblioteca a menos que se especifique `--version` o `--real-version`.

La salida normalmente debería ser adecuada para pasar a su compilador favorito.

--libs

(También) imprimir flags del enlazador. Las dependencias se recorren en orden. Las dependencias de nivel superior aparecerán antes en la línea de comandos que las dependencias de nivel inferior.

--libs-only-L

Imprime la parte -L/-R de "--libs". Define la ruta de búsqueda de bibliotecas pero sin las bibliotecas con las que enlazar.

--libs-only-l

Imprime la parte -l de "--libs".

--libs-only-other

Imprime la parte de "--libs" no cubierta por "--libs-only-L" y "--libs-only-l", como "--pthread".

--list-all

Lista todos los paquetes conocidos.

--cflags

(También) imprimir flags del compilador y preprocesador C.

--cflags-only-I

Imprime la parte -I de "--cflags"

--cflags-only-other

Imprime las partes de "--cflags" no cubiertas por "--cflags-only-I".

--modversion

Imprime la versión de un paquete dado.

--static

Utiliza dependencias y bibliotecas adicionales si se enlaza contra una versión estática de la biblioteca solicitada.

--exists

Devuelve éxito (0) si el paquete existe en la ruta de búsqueda.

--with-path=PATH

Anteponer "PATH" a la lista de rutas de búsqueda que contienen archivos ".pc".

Esta opción se puede especificar varias veces con diferentes rutas, y todas se añadirán.

--env-only

Usando esta opción, **solo** se reconocen las rutas especificadas en "PKG_CONFIG_PATH" y se ignoran los valores por defecto codificados.

--guess-paths

Invoca "gcc" y "ld" para determinar las rutas predeterminadas del enlazador e inclusiones. Las rutas predeterminadas se excluirán de los flags explícitos -L e -I.

--define-variable=VARIABLE=VALOR

Define una variable, anulando cualquier definición de variable de este tipo en el archivo .pc y permitiendo que su valor se interpole con usos posteriores.

--variable=VARIABLE

Esto devuelve el valor de una variable definida en el archivo .pc de un paquete.

--print-variables

Imprime todas las variables definidas encontradas en los archivos .pc.

--version

La versión objetivo de "pkg-config" emulada por este script.

--real-version

La versión real de este script.

--debug

Imprimir información de depuración.

--silence-errors

Desactivar errores. Este es el valor por defecto para argumentos que no son --libs/--cflags/--modversion.

--print-errors

Imprimir errores en STDERR y tiene precedencia sobre "--silence-errors".

--short-errors

Ignorado, pero reconocido por compatibilidad.

--errors-to-stdout

Imprimir errores en STDOUT y tiene precedencia sobre "--print-errors".

ENTORNO

Las variables "PKG_CONFIG_PATH" y "PKG_CONFIG_LIBDIR" son respetadas y se utilizan como una lista de directorios delimitados por dos puntos (delimitados por punto y coma en Windows) que contienen archivos ".pc".

Otras variables de entorno reconocidas tanto por "pkg-config" como por PkgConfig incluyen:

PKG_CONFIG_ALLOW_SYSTEM_CFLAGS
PKG_CONFIG_ALLOW_SYSTEM_LIBS

Si Win32API::Registry está instalado, en Windows (pero no en Cygwin) PkgConfig también consultará estas claves de registro. Los nombres se ignoran, pero los valores son rutas que contienen archivos ".pc".

HKEY_CURRENT_USER\Software\pkgconfig\PKG_CONFIG_PATH
HKEY_LOCAL_MACHINE\Software\pkgconfig\PKG_CONFIG_PATH

El soporte de registro debe considerarse algo experimental, sujeto a cambios en el futuro, aunque no sin una buena razón. La justificación de esta advertencia es que esta característica está documentada en varios lugares, pero aún no he encontrado una versión funcional que implemente esta característica.

OPCIONES DEL MÓDULO

PkgConfig->find

my $result = PkgConfig->find($library, %options);

Encuentra una biblioteca y devuelve un objeto de resultado. $library puede ser el nombre de una sola biblioteca o una referencia a un array de nombres de bibliotecas.

Las opciones tienen el formato de claves y valores de hash, y se reconocen las siguientes:

"search_path"
"search_path_override"
Anteponer rutas de búsqueda además de las rutas especificadas en $ENV{PKG_CONFIG_PATH}. El valor es una referencia a un array.

la variante "_override" ignora los valores por defecto (como "PKG_CONFIG_PATH").

"file_path"
Especifica la ruta completa del archivo .pc que desea cargar. No necesita estar en la ruta de búsqueda (aunque sus dependencias sí lo necesitarán). Útil si conoce la ruta completa del archivo .pc exacto que desea.
"exclud
e_cflags"
"exclude_ldflags"
"exclude_cflags_override"
"exclude_ldflags_override"
Algunos archivos ".pc" especifican rutas de búsqueda predeterminadas del compilador y enlazador, por ejemplo "-I/usr/include -L/usr/lib". Especificarlas en la línea de comandos puede ser problemático ya que cambia drásticamente el orden de búsqueda.

Las opciones anteriores añadirán o reemplazarán las opciones que se excluyen y filtran.

Las opciones predeterminadas de enlazador y compilador excluidas se pueden obtener a través de @PkgConfig::DEFAULT_EXCLUDE_LFLAGS y @PkgConfig::DEFAULT_EXCLUDE_CFLAGS, respectivamente.

"static"
Especificar también bibliotecas estáticas.
"no_recurse"
No recurrir dependencias. Esto es útil solo para realizar comprobaciones de versión.
"VARS"
Definir un hashref de variables para reemplazar cualquier definición de variable dentro de los archivos .pc. Esto es equivalente a la opción de línea de comandos "--define-variable".

Se devuelve un objeto "PkgConfig" que puede ser consultado sobre los resultados:

$o->errmsg

Un mensaje de error, si lo hay. Es una cadena que indica un error.

$o->pkg_exists

Valor booleano, verdadero si el paquete existe.

$o->pkg_version

La versión del paquete

$o->get_cflags

$o->get_ldflags

Devuelve las banderas del compilador y del enlazador, respectivamente.

En contexto de lista, estos métodos devuelven una lista con cada argumento dividido por espacios sin escapar.

En contexto de lista devuelve una lista de banderas del compilador y del enlazador, respectivamente.

En contexto escalar devuelve una cadena de banderas del compilador y del enlazador con espacios y comillas correctamente escapados.

$o->get_var($name)

Obtiene la variable con el nombre dado.

PkgConfig->Guess

Este es un método de clase, y reemplazará las rutas predeterminadas de enlazador e inclusiones codificadas con las descubiertas invocando ld(1) y cpp(1).

Actualmente esto solo funciona con "ld" suministrado por GCC y "ld" de GNU.

INSTALACIÓN

El "Makefile.PL" que viene con "PkgConfig" puede tomar una o más opciones "--script" para cambiar el nombre del script o scripts que se instalan.

--script ppkg-config
Este es el predeterminado y funciona en todas las plataformas
--script pkg-config.pl
Este se instala por defecto en todas las plataformas excepto en Windows, donde el .pl puede confundir la shell y hacer que el script se abra en un editor de texto.
--script pkg-config
Este es el nombre predeterminado del "pkg-config" real y, por lo tanto, debe habilitarlo específicamente si lo desea.
--script none
No instalar ningún script.

Ejemplo, instalar todos los nombres de script:

% perl Makefile.PL --script ppkg-config --script pkg-config.pl --script pkg-config

Ejemplo, no instalar ningún script:

% perl Makefile.PL --script none

También puede establecer la variable de entorno PERL_PKG_CONFIG_SCRIPTS al valor --script deseado (separando cada nombre de script con una coma ",") para asegurar que las actualizaciones de PkgConfig hagan lo mismo.

ADVERTENCIAS

En Strawberry Perl, "ppkg-config" actúa como si Strawberry fuera el sistema. Esto significa que

  • Los archivos .pc que vienen con Strawberry se buscan por defecto.
  • Los directorios de inclusión y bibliotecas de Strawberry se utilizan para calcular las listas de exclusión.

A partir de Strawberry 5.20.0.1, PkgConfig viene incluido con Strawberry y "pkg-config" se instala por defecto (además de "ppkg-config", aunque el alias "ppkg-config" NO está incluido con Strawberry en sí).

Para obtener detalles sobre cómo parchear los archivos .pc incluidos en versiones anteriores de Strawberry, consulte el "README.win32" que viene con esta distribución.

ERRORES

El orden de las banderas no coincide exactamente con el de "pkg-config". Según mi propia observación, este módulo parece hacer un mejor trabajo, pero podría estar equivocado.

A diferencia de "pkg-config", la función "--exists" de los scripts devolverá un valor distinto de cero si un paquete o alguna de sus dependencias faltan. Esto difiere del comportamiento de "pkg-config", que solo comprobará la definición del paquete en sí (sin dependencias).
