NOMBRE

pkcheck - Comprobar si un proceso está autorizado

SINOPSIS

pkcheck [--version] [--help|-h]

pkcheck [--list-temp]

pkcheck [--revoke-temp]

pkcheck --action-id|-a accion {--process|-p { pid | pid-hora-inicio | pid-hora-inicio-uid } | --system-bus-name|-s nombre-bus} [--allow-user-interaction|-u] [--enable-internal-agent] [--detail|-d clave valor...]

DESCRIPCIÓN

pkcheck se utiliza para comprobar si un proceso, especificado por --process (ver más abajo) o --system-bus-name, está autorizado para la accion. La opción --detail se puede usar cero o más veces para pasar detalles sobre la accion. Si se pasa --allow-user-interaction, pkcheck se bloquea mientras espera la autenticación.

La invocación pkcheck --list-temp listará todas las autorizaciones temporales para la sesión actual y pkcheck --revoke-temp revocará todas las autorizaciones temporales para la sesión actual.

Este comando es un simple envoltorio para la interfaz D-Bus de polkit; consulte la documentación de la interfaz D-Bus para obtener más detalles.

VALOR DE RETORNO

Si el proceso especificado está autorizado, pkcheck sale con un valor de retorno de 0. Si el resultado de la autorización contiene algún detalle, estos se imprimen en la salida estándar como pares clave/valor utilizando el estilo de entorno de notificación, por ejemplo, primero la clave seguida de un signo igual, luego el valor seguido de un salto de línea.

CLAVE1=VALOR1
CLAVE2=VALOR2
CLAVE3=VALOR3
...

Los octetos que no están en [a-zA-Z0-9_] se escapan usando códigos octales precedidos por \. Por ejemplo, la cadena UTF-8 føl,你好 se imprimirá como f\303\270l\54\344\275\240\345\245\275.

Si el proceso especificado no está autorizado, pkcheck sale con un valor de retorno de 1 y se imprime un mensaje de diagnóstico en la salida de error estándar. Los detalles se imprimen en la salida estándar.

Si el proceso especificado no está autorizado porque no hay un agente de autenticación adecuado disponible o si no se pasó --allow-user-interaction, pkcheck sale con un valor de retorno de 2 y se imprime un mensaje de diagnóstico en la salida de error estándar. Los detalles se imprimen en la salida estándar.

Si el proceso especificado no está autorizado porque el usuario desestimó el diálogo / solicitud de autenticación, pkcheck sale con un valor de retorno de 3 y se imprime un mensaje de diagnóstico en la salida de error estándar. Los detalles se imprimen en la salida estándar.

Si ocurrió un error al comprobar la autorización, pkcheck sale con un valor de retorno de 127 con un mensaje de diagnóstico impreso en la salida de error estándar.

Si una o más de las opciones pasadas están mal formadas, pkcheck sale con un valor de retorno de 126. Si la entrada estándar es una tty, entonces esta página del manual también se muestra.

NOTAS

No utilice ninguna de las formas de sintaxis de solo pid o pid,hora-inicio para --process. Existen condiciones de carrera en ambas. El código nuevo siempre debe usar pid,pid-hora-inicio,uid. El valor de hora-inicio se puede determinar consultando, por ejemplo, el sistema de archivos proc(5) dependiendo del sistema operativo. Si se pasan menos de 3 argumentos, pkcheck intentará buscarlos internamente, pero tenga en cuenta que esto puede ser susceptible a condiciones de carrera.

Si su programa es un demonio con, por ejemplo, un socket Unix personalizado, debe determinar el parámetro uid a través de mecanismos del sistema operativo como PEERCRED.

AGENTE DE AUTENTICACIÓN

pkcheck, como cualquier otra aplicación de polkit, utilizará el agente de autenticación registrado para el proceso en cuestión. Sin embargo, si no hay un agente de autenticación disponible, pkcheck puede registrar su propio agente de autenticación textual si se pasa la opción --enable-internal-agent.
