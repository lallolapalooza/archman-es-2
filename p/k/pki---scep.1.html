PKI --SCEP(1) strongSwan PKI --SCEP(1)

NOMBRE

pki --scep - Inscribir un certificado X.509 con un servidor SCEP

SINOPSIS

pki --scep --url url [--in archivo] [--dn  nombre-distinguido] [--san subjectAltName] [--profile perfil] [--password contraseña] --ca-cert-enc archivo --ca-cert-sig archivo [--cacert archivo] [--cert archivo --key archivo] [--cipher cifrado] [--digest resumen] [--rsa-padding relleno] [--interval tiempo] [--maxpolltime tiempo] [--outform codificación] [--debug nivel]
pki --scep --options archivo
pki --scep -h | --help

DESCRIPCIÓN

Este subcomando de pki(1) envía una solicitud de certificado PKCS#10 en un contenedor PKCS#7 cifrado y firmado a través de HTTP a un servidor SCEP utilizando el Protocolo de Inscripción de Certificados Simple (RFC 8894). Después de una autorización exitosa, que con autenticación manual requiere sondeo periódico por parte del cliente de inscripción, el servidor SCEP devuelve un certificado X.509 firmado por la CA.

Antes de la caducidad del certificado actual, se puede solicitar un nuevo certificado de cliente basado en una nueva clave privada RSA, utilizando el certificado antiguo y la clave antigua para la autenticación automática con el servidor SCEP.

OPCIONES

-h, --help
Imprime información de uso con un resumen de las opciones disponibles.
-v, --debug nivel
Establece el nivel de depuración, por defecto: 1.
-+, --options archivo
Lee las opciones de la línea de comandos de archivo.
-u, --url url
URL del servidor SCEP.
-i, --in archivo
Clave privada RSA. Si no se proporciona, la clave se lee de STDIN.
-d, --dn nombre-distinguido
Nombre distinguido del asunto (DN). Requerido a menos que se proporcione --cert.
-a, --san subjectAltName
Extensión subjectAltName para incluir en la solicitud. Se puede usar varias veces.
-P, --profile perfil
Nombre del perfil de certificado para incluir en la solicitud de certificado. Puede ser cualquier cadena UTF8. Soportado, por ejemplo, por el servidor SCEP de openxpki con perfiles (pc-client, tls-server, etc.) que se traducen en banderas de Uso de Clave Ampliado (EKU) correspondientes en el certificado X.509 generado.
-p, --password contraseña
La challengePassword para incluir en la solicitud de certificado.
-e, --cacert-enc archivo
Certificado de CA o RA para cifrado
-s, --cacert-sig archivo
Certificado de CA para verificación de firma
-C, --cacert archivo
Certificado de CA adicional en la cadena de confianza utilizada para la verificación de firma. Se puede usar varias veces.
-c, --cert archivo
Certificado de cliente a renovar.
-k, --key archivo
Clave privada RSA de cliente a reemplazar.
-E, --cipher cifrado
Cifrado utilizado para el cifrado simétrico. Ya sea aes (por defecto) o des3.
-g, --digest resumen
Resumen a utilizar para la creación de firmas. Uno de sha256 (por defecto), sha384, sha512, o sha1.
-R, --rsa-padding relleno
Relleno a utilizar para firmas RSA. Ya sea pkcs1 (por defecto) o pss.
-t, --interval tiempo
Intervalo de sondeo en segundos, por defecto 60s.
-m, --maxpolltime tiempo
Tiempo máximo de sondeo en segundos, por defecto 0, lo que significa sondeo ilimitado.
-f, --outform codificación
Codificación del archivo de certificado creado. Ya sea der (ASN.1 DER) o pem (Base64 PEM), por defecto der.

EJEMPLOS

Para ahorrar algo de escritura, las siguientes opciones de línea de comandos se almacenan en un archivo scep.opt:

--url http://pki.strongswan.org:8080/scep
--cacert-enc myra.crt
--cacert-sig myca-1.crt
--cacert myca.crt

Con el siguiente comando, se solicita un certificado X.509 firmado por la CA intermedia a un servidor SCEP:

pki --options scep.opt --in moonKey.der --san "moon.strongswan.org" \
