PKI --EST(1) strongSwan PKI --EST(1)

NOMBRE

pki --est - Inscribir un certificado X.509 con un servidor EST

SINOPSIS

pki --est --url url [--label etiqueta] [--in archivo] --cacert archivo [--cert archivo|--certid hex --key archivo|--keyid hex] [--userpass usuario:contraseña] [--interval tiempo] [--maxpolltime tiempo] [--outform codificación] [--debug nivel]
pki --est --options archivo
pki --est -h | --help

DESCRIPCIÓN

Este subcomando de pki(1) envía una solicitud de certificado PKCS#10 a través de HTTPS a un servidor utilizando el Protocolo de Inscripción sobre Transporte Seguro (EST) (RFC 7030). Después de una autorización exitosa, que con autenticación manual requiere sondeo periódico por parte del cliente de inscripción, el servidor EST devuelve un certificado X.509 firmado por la CA.

Antes de la caducidad del certificado actual, se puede solicitar un nuevo certificado de cliente basado en una nueva clave privada, utilizando el certificado antiguo y la clave antigua para la autenticación automática del cliente TLS con el servidor EST.

OPCIONES

-h, --help
Imprime información de uso con un resumen de las opciones disponibles.
-v, --debug nivel
Establece el nivel de depuración, por defecto: 1.
-+, --options archivo
Lee las opciones de la línea de comandos del archivo.
-u, --url url
URL del servidor EST.
-l, --label etiqueta
Etiqueta en la ruta del servidor EST.
-i, --in archivo
Solicitud de certificado PKCS#10. Si no se proporciona, la solicitud de certificado se lee de STDIN.
-C, --cacert archivo
Certificado de CA en la cadena de confianza utilizada para la verificación de la firma del servidor TLS EST o en la cadena de confianza para verificar el certificado del cliente emitido por la CA. Se puede usar varias veces.
-c, --cert archivo
Certificado de cliente a renovar.
-X, --certid hex
Identificador del objeto del certificado del cliente de tarjeta inteligente o TPM 2.0.
-k, --key archivo
Clave privada del cliente a reemplazar.
-x, --keyid hex
Identificador del objeto de la clave privada del cliente de tarjeta inteligente o TPM 2.0.
-p, --userpass usuario:contraseña
Nombre de usuario:contraseña opcional que puede usarse para autenticación básica HTTP.
-t, --interval tiempo
Intervalo de sondeo en segundos, por defecto 60s. Este valor puede ser anulado por la cabecera retry-after en la respuesta HTTP 202 del servidor EST.
-m, --maxpolltime tiempo
Tiempo máximo de sondeo en segundos, por defecto 0, lo que significa sondeo ilimitado.
-f, --outform codificación
Codificación del archivo de certificado creado. Puede ser der (ASN.1 DER) o pem (Base64 PEM), por defecto es der.

EJEMPLOS

Para ahorrar escritura, las siguientes opciones de línea de comandos se guardan en un archivo est.opt:

--url https://pki.strongswan.org:8443
--cacert tlsca.crt
--cacert tlsca-1.crt
--cacert myca.crt
--cacert myca-1.crt

NOTA: Para una conexión HTTPS exitosa, se debe establecer confianza en el certificado del servidor EST. La cadena de confianza TLS, incluyendo el certificado de la CA raíz y opcionalmente los certificados de CA intermedios, deben proporcionarse utilizando múltiples opciones --cacert.

La opción --cacert también debe usarse para poder verificar el certificado del cliente recibido emitido por la CA. Esta segunda cadena de confianza podría ser idéntica a la cadena de confianza TLS (si el servidor EST utiliza un certificado de servidor TLS emitido por su propia CA) o podría ser totalmente diferente, por ejemplo, si se utiliza un certificado EST de Let's Encrypt.
