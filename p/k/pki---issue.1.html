NOMBRE

pki --issue - Emite un certificado usando un certificado y clave de CA

SINOPSIS

pki --issue [--in archivo] [--type tipo] --cakey archivo|--cakeyid hex --cacert archivo [--dn subject-dn] [--san subjectAltName] [--lifetime días] [--not-before fecha-hora] [--not-after fecha-hora] [--serial hex] [--flag flag] [--digest digest] [--rsa-padding padding] [--ca] [--crl uri [--crlissuer issuer]] [--ocsp uri] [--pathlen len] [--addrblock bloque] [--nc-permitted nombre] [--nc-excluded nombre] [--critical oid] [--policy-mapping mapping] [--policy-explicit len] [--policy-inhibit len] [--policy-any len] [--cert-policy oid [--cps-uri uri] [--user-notice texto]] [--outform codificación] [--debug nivel]
pki --issue --options archivo
pki --issue -h | --help

DESCRIPCIÓN

Este subcomando de pki(1) se utiliza para emitir un certificado usando un certificado y clave privada de CA.

OPCIONES

-h, --help
Imprime información de uso con un resumen de las opciones disponibles.
-v, --debug nivel
Establece el nivel de depuración, por defecto: 1.
-+, --options archivo
Lee las opciones de la línea de comandos desde archivo.
-i, --in archivo
Archivo de clave pública o solicitud de certificado PKCS#10 a emitir. Si no se proporciona, la clave/solicitud se lee de STDIN.
-t, --type tipo
Tipo de la entrada. Uno de pub (clave pública), priv (clave privada), rsa (clave privada RSA), ecdsa (clave privada ECDSA), ed25519 (clave privada Ed25519), ed448 (clave privada Ed448) o pkcs10 (solicitud de certificado PKCS#10), por defecto es pub.
-k, --cakey archivo
Archivo de clave privada de la CA. Se requiere este o --cakeyid.
-x, --cakeyid hex
Identificador de objeto de clave privada de la CA en tarjeta inteligente o TPM en formato hexadecimal con un prefijo 0x opcional. Se requiere este o --cakey.
-c, --cacert archivo
Archivo de certificado de la CA. Requerido.
-d, --dn subject-dn
Nombre distinguido (DN) del sujeto del certificado emitido.
-a, --san subjectAltName
Extensión subjectAltName a incluir en el certificado. Se puede usar varias veces.
-l, --lifetime días
Días de validez del certificado, por defecto: 1095. Se ignora si se dan una fecha de inicio y fin absolutas.
-F, --not-before fecha-hora
Hora absoluta en que comienza la validez del certificado. El formato de fecha-hora se define con la opción --dateform.
-T, --not-after fecha-hora
Hora absoluta en que termina la validez del certificado. El formato de fecha-hora se define con la opción --dateform.
-D, --dateform formato
Formato strptime(3) para las opciones --not-before y --not-after, por defecto: %d.%m.%y %T
-s, --serial hex
Número de serie en formato hexadecimal. Se asigna aleatoriamente por defecto.
-e, --flag flag
Añade una marca de uso extendido de clave. Una de serverAuth, clientAuth, crlSign, ocspSigning o msSmartcardLogon. Se puede usar varias veces. Sin modificadores, esto anula las marcas de las solicitudes de certificado PKCS#10. Prefijar una marca con + la añade al conjunto de marcas leídas de la solicitud, prefijarla con - la elimina de ese conjunto.
-g, --digest digest
Digest a usar para la creación de la firma. Uno de md5, sha1, sha224, sha256, sha384 o sha512. El valor por defecto se determina según el tipo y tamaño de la clave de firma.
-R, --rsa-padding padding
Padding a usar para firmas RSA. Uno de pkcs1 o pss, por defecto es pkcs1.
-f, --outform codificación
Codificación del archivo de certificado creado. Uno de der (ASN.1 DER) o pem (PEM Base64), por defecto es der.
-b, --ca
Incluye la extensión basicConstraint de CA en el certificado.
-u, --crl uri
URI del punto de distribución de CRL a incluir en el certificado. Se puede usar varias veces.
-I, --crlissuer issuer
Emisor opcional de CRL para el CRL en el punto de distribución precedente.
-o, --ocsp uri
URI de AuthorityInfoAccess OCSP a incluir en el certificado. Se puede usar varias veces.
-p, --pathlen len
Establece la restricción de longitud de ruta.
-B, --addrblock bloque
Bloque de direcciones RFC 3779 a incluir en el certificado. bloque es una subred CIDR (como 10.0.0.0/8) o un rango de direcciones arbitrario (192.168.1.7-192.168.1.13). Se puede repetir para incluir múltiples bloques. Tenga en cuenta que los bloques proporcionados se incluyen en el certificado tal cual, por lo que para cumplir con los estándares, se deben proporcionar múltiples bloques en el orden correcto y combinar bloques adyacentes. Consulte RFC 3779 para obtener detalles.
-n, --nc-permitted nombre
Añade una extensión NameConstraint permitida al certificado. Para restricciones de DNS o correo electrónico, el tipo de identidad no siempre se puede detectar por el nombre dado. Use el prefijo dns: o email: para forzar un tipo de restricción.
-N, --nc-excluded nombre
Añade una extensión NameConstraint excluida al certificado. Para restricciones de DNS o correo electrónico, el tipo de identidad no siempre se puede detectar por el nombre dado. Use el prefijo dns: o email: para forzar un tipo de restricción.
-X, --critical oid
Añade una extensión crítica con el OID dado.
-M, --policy-mapping oid-emisor:oid-sujeto
Añade policyMapping del emisor al OID del sujeto.
-E, --policy-explicit len
Añade la restricción requireExplicitPolicy.
-H, --policy-inhibit len
Añade inhibitPolicyMap

NAME

pki - PKI certificate management

SYNOPSIS

pki [options] [command]

DESCRIPTION

The pki utility supports the management of PKI certificates and keys. It can be used to generate key pairs, create certificate requests, issue certificates, manage certificate revocation lists (CRLs) and perform other certificate management tasks.

This document describes the options for the --issue command, which is used to issue certificates.

OPTIONS

General Options

-h, --help
Print help and exit.
-v, --version
Print version information and exit.

Issue Command Options

These options are specific to the --issue command:

--cacert file
CA certificate file in DER, PEM, or PKCS#12 format.
--cakey file
CA private key file in DER or PEM format.
--capass passphrase
Passphrase for CA private key.
--in file
Input file containing the certificate request (DER or PEM format).
--out file
Output file for the issued certificate (DER or PEM format).
--digest algo
Digest algorithm used for signing. Defaults to SHA-256.
--flag flag[,flag]...
Add certificate flags. Allowed flags are: serverAuth, clientAuth, codeSign, emailSign, OCSP, timeStamping.
--lifetime days
Certificate lifetime in days. Defaults to 1095 (3 years).
--type type
Type of certificate to issue. Allowed types are: pkcs10, rw.
--new
Generate a new CA key pair and certificate.
--enterprise
Add the EKU for TLS Web Server Authentication.
-S, --san name
Add Subject Alternative Name. Multiple values can be added.
-a, --allow-sha1
Allow SHA1 signature algorithm.
-A, --policy-any len
Add inhibitAnyPolicy constraint.

Certificate Policy

Multiple certificatePolicy extensions can be added. Each with the following information:

-P, --cert-policy oid
OID to include in certificatePolicy extension. Required.
-C, --cps-uri uri
Certification Practice statement URI for certificatePolicy.
-U, --user-notice text
User notice for certificatePolicy.

EXAMPLES

To save repetitive typing, command line options can be stored in files. Lets assume pki.opt contains the following contents:

  --cacert ca_cert.der --cakey ca_key.der --digest sha256
  --flag serverAuth --lifetime 1460 --type pkcs10

Then the following command can be used to issue a certificate based on a given PKCS#10 certificate request and the options above:

  pki --issue --options pki.opt --in req.der > cert.der
