PDNSD(8) Comandos de Administración del Sistema PDNSD(8)

NOMBRE

pdnsd - servidor proxy de nombres de dominio

SINOPSIS

pdnsd [-h] [-V] [-s] [-d] [-g] [-t] [-p archivo] [-vn] [-mxx] [-c archivo] [-4] [-6] [-a]

Esta página del manual es un extracto de la documentación de pdnsd. Para obtener documentación completa y actualizada, consulte la documentación HTML (o en texto plano) (que puede encontrar en el subdirectorio doc/ del código fuente o en un directorio de documentación estándar, típicamente /usr/share/doc/pdnsd/ si está utilizando un paquete binario).

DESCRIPCIÓN

pdnsd es un servidor de nombres de dominio (DNS) proxy con capacidad IPv6 que guarda el contenido de su caché DNS en disco al salir.

OPCIONES

-4
habilita el soporte IPv4. El soporte IPv6 se deshabilita automáticamente (si estuviera disponible). Activado por defecto.
-6
habilita el soporte IPv6. El soporte IPv4 se deshabilita automáticamente (si estuviera disponible). Desactivado por defecto.
-a
Con esta opción, pdnsd intentará detectar automáticamente si el sistema soporta IPv6, y recurrirá a IPv4 en caso contrario.
-V o --version
Imprime información de la versión y sale.
-c ARCHIVO o --config-file=ARCHIVO
especifica que la configuración se leerá de ARCHIVO. Por defecto es /etc/pdnsd.conf.
-d o --daemon
Inicia pdnsd en modo demonio (como un proceso en segundo plano).
-g o --debug
Imprime algunos mensajes de depuración en la consola o en el archivo pdnsd.debug en su directorio de caché (en modo demonio).
-h o --help
Imprime un resumen de opciones y sale.
-i PREFIJO o --ipv4_6_prefix=PREFIJO
especifica el prefijo que pdnsd utiliza (cuando se ejecuta en modo IPv6) para mapear direcciones IPv4 en el archivo de configuración a direcciones IPv6. Debe ser una dirección IPv6 válida. Por defecto es ::ffff:0.0.0.0
-p ARCHIVO
escribe el pid del servidor en ejecución en el nombre de archivo especificado. Solo funciona en modo demonio.
--pdnsd-user
Imprime el usuario bajo el cual se ejecutará pdnsd y sale.
-s o --status
habilita el socket de control de estado. O esta opción debe pasarse a la línea de comandos o se debe especificar status_ctl=on; en el archivo de configuración si desea utilizar pdnsd-ctl(8) para controlar pdnsd en tiempo de ejecución.
-t o --tcp
habilita el hilo del servidor TCP. pdnsd servirá entonces consultas TCP y UDP.
-vn
establece la verbosidad de pdnsd. n es un argumento numérico entre 0 (operación normal) y 3 (muchos mensajes para depuración).
-mxx
establece el método de consulta que utiliza pdnsd. Los valores posibles para xx son:
uo - pdnsd utilizará solo UDP. Este es el método más rápido y debe ser soportado por todos los servidores de nombres en Internet.
to - pdnsd utilizará solo TCP. Las consultas TCP suelen llevar más tiempo que las consultas UDP, pero son más seguras contra ciertos ataques, donde un atacante intenta adivinar su ID de consulta y enviar respuestas falsificadas. Las consultas TCP no son compatibles con algunos servidores de nombres.
tu - pdnsd intentará usar TCP y recurrirá a UDP si su conexión es rechazada o se agota el tiempo de espera.
ut - pdnsd intentará usar UDP y repetirá la consulta usando TCP si la respuesta UDP fue truncada (es decir, se establece el bit tc). Este es el comportamiento recomendado por los estándares DNS.

Además, se puede anteponer "no" a las opciones --status, --daemon, --debug y --tcp (por ejemplo, --notcp) para invertir su efecto.

USO

pdnsd generalmente se ejecuta desde un script de inicio. Para que pdnsd funcione, necesita:

1. Indicar a su sistema que utilice pdnsd como servidor DNS primario modificando /etc/resolv.conf.
2. Indicar a pdnsd que utilice una fuente autorizada para los registros DNS, incluyendo las direcciones IP de uno o más servidores DNS, generalmente los servidores DNS de su ISP, en /etc/pdnsd.conf.

Para ello, ponga la siguiente línea en su /etc/resolv.conf

nameserver 127.0.0.X

donde X puede ser cualquier número. (Yo uso el 3). Comente todas las demás entradas. Debería poner el mismo valor en la línea server_ip= en la sección global de /etc/pdnsd.conf.
Si desea utilizar pdnsd como servidor DNS para una pequeña red local, debería utilizar la dirección IP o el nombre de la interfaz conectada a esta red en lugar de 127.0.0.X.

Para indicar a pdnsd de dónde obtener la información DNS, añada las siguientes líneas en /etc/pdnsd.conf:-

server {
label= "myisp";
ip=123.456.789.001,123.456.789.002;
proxy_only=on;
timeout=10;
}

Tenga en cuenta las llaves de apertura y cierre. Añada más secciones server de este tipo para cada conjunto de servidores DNS que desee que pdnsd consulte. Por supuesto, las opciones de configuración mostradas aquí son solo ejemplos. Se pueden encontrar más ejemplos en /etc/pdnsd.conf.sample o en el archivo pdnsd.conf en el directorio de documentación. Consulte la página del manual pdnsd.conf(5) para ver todas las opciones posibles y su significado exacto.

Si utiliza una conexión de acceso telefónico (dial up), recuerde que los scripts ppp suelen reemplazar /etc/resolv.conf cuando se establece la conexión con el ISP. Necesita configurar ppp (o lo que sea que utilice para establecer una conexión) para que /etc/resolv.conf no sea reemplazado cada vez que se establece una conexión. Lea la documentación de los scripts que se ejecutan cuando su red se activa.

Si utiliza pppconfig, especifique `none' en la opción `nameservers' en la pestaña `advanced'. Si utiliza múltiples ISPs, debería hacer esto para cada conexión/cuenta.

Si utiliza múltiples ISPs, debería indicar a pdnsd qué servidores DNS se han puesto a disposición llamando a pdnsd-ctl, la utilidad de control de pdnsd, en un script (por ejemplo, /etc/ppp/ip-up cuando utiliza pppd) que se ejecuta cuando se establece la conexión. Si las direcciones de los servidores DNS se obtienen a través de algún tipo de protocolo de configuración dinámica (por ejemplo, pppd con la opción usepeerdns o un cliente DHCP), puede pasar las direcciones del servidor DNS como un argumento adicional a pdnsd-ctl para configurar pdnsd en tiempo de ejecución. Consulte la página del manual pdnsd-ctl(8) para obtener detalles.

ARCHIVOS

/etc/pdnsd.conf es el archivo de configuración de pdnsd. El formato del archivo y las opciones de configuración se describen en la página del manual pdnsd.conf(5). Puede encontrar ejemplos de casi todas las opciones en /etc/pdnsd.conf.sample.

/var/cache/pdnsd/pdnsd.cache

/var/cache/pdnsd/pdnsd.status es el socket de control de estado, que debe estar habilitado antes de poder usar pdnsd-ctl.

/etc/init.d/pdnsd (el nombre y la ubicación del script de inicio pueden diferir según su distribución.)

/etc/resolv.conf

/etc/defaults/pdnsd contiene parámetros u opciones adicionales que pueden pasarse a pdnsd al arrancar. Esto ahorra la molestia de manipular los scripts de inicio (no disponible en todas las distribuciones).

ERRORES

La opción de verbosidad -vn actualmente no parece tener mucho efecto en la cantidad de salida de depuración.
Reporte cualquier error restante a los autores.

CONFORMING TO

Se ha mejorado y ahora se cree (¿o se espera?) que pdnsd sea totalmente compatible con RFC. Sigue completamente la RFC 2181 (excepto por un pequeño problema en el port de FreeBSD, véase la documentación).

NO soporta las siguientes características, de las cuales la mayoría están marcadas como opcionales, experimentales u obsoletas en estas RFCs:

• Consultas inversas
• Consultas de estado
• Consultas de completitud
• Espacios de nombres distintos de IN (Internet)
• Consultas AXFR e IXFR (transferencias de zona completas); dado que pdnsd no mantiene zonas, eso no debería violar el estándar.

Los siguientes tipos de registros, que son extensiones al estándar DNS original, se soportan si se especifican como opciones en tiempo de compilación. (si no los necesita, no necesita compilar el soporte para ellos en pdnsd y ahorrará espacio en la caché y en el ejecutable):

• RP (persona responsable, RFC 1183)
• AFSDB (ubicación de la base de datos AFS, RFC 1183)
• X25 (dirección X25, RFC 1183)
• ISDN (número/dirección ISDN, RFC 1183)
• RT (ruta a través, RFC 1183)
• NSAP (dirección del Protocolo de Acceso al Servicio de Red, RFC 1348)
• PX (información de mapeo X.400/RFC822, RFC 1995)
• GPOS (posición geográfica, obsoleto)
• AAAA (dirección IPv6, RFC 1886)
• LOC (ubicación, RFC 1876)
• EID (Nimrod EID)
• NIMLOC (localizador Nimrod)
• SRV (registro de servicio, RFC 2782)
• ATMA (dirección ATM)
• NAPTR (mapeo de URI, RFC 2168)
• KX (intercambio de claves, RFC 2230)
