PDFTK(1) Manual de Comandos Generales PDFTK(1)

NOMBRE

pdftk - Una herramienta útil para manipular PDF

SINOPSIS

pdftk <archivos PDF de entrada | - | PROMPT>
[ input_pw <contraseñas de propietario de PDF de entrada | PROMPT> ]
[ <operación> <argumentos de operación> ]
[ output <nombre de archivo de salida | - | PROMPT> ]
[ encrypt_40bit | encrypt_128bit | encrypt_aes128 ]
[ allow <permisos> ]
[ owner_pw <contraseña de propietario | PROMPT> ]
[ user_pw <contraseña de usuario | PROMPT> ]
[ flatten ] [ need_appearances ]
[ compress | uncompress ]
[ keep_first_id | keep_final_id ] [ drop_xfa ] [ drop_xmp ]
[ replacement_font <nombre de fuente> ]
[ verbose ] [ dont_ask | do_ask ]
Donde:
<operación> puede estar vacío, o:
[ cat | shuffle | burst | rotate |
generate_fdf | fill_form |
background | multibackground |
stamp | multistamp |
dump_data | dump_data_utf8 |
dump_data_fields | dump_data_fields_utf8 |
dump_data_annots |
update_info | update_info_utf8 |
attach_files | unpack_files ]

Para Ayuda Completa: pdftk --help

DESCRIPCIÓN

Si el PDF es papel electrónico, entonces pdftk es un removedor de grapas electrónico, taladro, encuadernador, anillo de decodificación secreto y gafas de rayos X. Pdftk es una herramienta simple para hacer cosas cotidianas con documentos PDF. Úselo para:

* Fusionar Documentos PDF o Colacionar Escaneos de Páginas PDF
* Dividir Páginas PDF en un Nuevo Documento
* Rotar Documentos o Páginas PDF
* Descifrar la Entrada según sea Necesario (Contraseña Requerida)
* Cifrar la Salida según se Desee
* Rellenar Formularios PDF con Datos X/FDF y/o Aplanar Formularios
* Generar Plantillas de Datos FDF desde Formularios PDF
* Aplicar una Marca de Agua de Fondo o un Sello de Primer Plano
* Informar Métricas, Marcadores y Metadatos de PDF
* Añadir/Actualizar Métricas, Marcadores o Metadatos de PDF
* Adjuntar Archivos a Páginas PDF o al Documento PDF
* Desempaquetar Adjuntos de PDF
* Dividir un Documento PDF en Páginas Individuales
* Descomprimir y Recomprimir Flujos de Páginas
* Reparar PDF Corruptos (Donde Sea Posible)

OPCIONES

A continuación se incluye un resumen de las opciones.

--help, -h
Mostrar este resumen de opciones.
<archivos PDF de entrada | - | PROMPT>
Una lista de los archivos PDF de entrada. Si planea combinar estos PDF (sin usar manejadores) entonces liste los archivos en el orden en que desea que se combinen. Use - para pasar un solo PDF a pdftk a través de stdin. Los archivos de entrada pueden asociarse con manejadores, donde un manejador es una o más letras mayúsculas:

<manejador PDF de entrada>=<nombre de archivo PDF de entrada>

Los manejadores a menudo se omiten. Son útiles al especificar contraseñas de PDF o rangos de páginas, más adelante.

Por ejemplo: A=input1.pdf QT=input2.pdf M=input3.pdf

[input_pw <contraseñas de propietario de PDF de entrada | PROMPT>]
Las contraseñas de propietario de PDF de entrada, si es necesario, se asocian con los archivos usando sus manejadores:

<manejador PDF de entrada>=<contraseña de propietario de archivo PDF de entrada>

Si no se dan manejadores, entonces las contraseñas se asocian con los archivos de entrada por orden.

La mayoría de las características de pdftk requieren que los PDF de entrada cifrados vayan acompañados de la contraseña de ~propietario~. Si el PDF de entrada no tiene contraseña de propietario, entonces se debe dar la contraseña de usuario en su lugar. Si el PDF de entrada no tiene contraseñas, entonces no se debe dar ninguna contraseña.

Al ejecutarse en modo do_ask, pdftk le pedirá una contraseña si la contraseña proporcionada es incorrecta o si no se dio ninguna.

[<operación> <argumentos de operación>]
Las operaciones disponibles son: cat, shuffle, burst, rotate, generate_fdf, fill_form, background, multibackground, stamp, multistamp, dump_data, dump_data_utf8, dump_data_fields, dump_data_fields_utf8, dump_data_annots, update_info, update_info_utf8, attach_files, unpack_files. Algunas operaciones toman argumentos adicionales, descritos a continuación.

Si se omite este argumento opcional, entonces pdftk se ejecuta en modo 'filtro'. El modo filtro toma solo un PDF de entrada y crea un nuevo PDF después de aplicar todas las opciones de salida, como cifrado y compresión.

cat [<rangos de páginas>]
Ensambla (concatena) páginas de los PDF de entrada para crear un nuevo PDF. Use cat para fusionar páginas PDF o para dividir páginas PDF de documentos. También puede usarlo para rotar páginas PDF. El orden de las páginas en el nuevo PDF se especifica por el orden de los rangos de páginas dados. Los rangos de páginas se describen de la siguiente manera:

<manejador PDF de entrada>[<número de página de inicio>[-<número de página de fin>[<calificador>]]][<rotación de página>]

Donde el manejador identifica uno de los archivos PDF de entrada, y los números de página de inicio y fin son referencias basadas en uno a las páginas del archivo PDF. El calificador puede ser even, odd, o ~, y la rotación de página puede ser north, south, east, west, left, right, o down.

Si se da un manejador de PDF pero no se especifican páginas, entonces se usa el PDF completo. Si no se especifican páginas para ninguno de los PDF de entrada, entonces también se fusionan los marcadores de los PDF de entrada y se incluyen en la salida.

Si se omite el manejador del rango de páginas, entonces las páginas se toman del primer archivo PDF de entrada.

El calificador even hace que pdftk use solo las páginas PDF de número par, por lo que 1-6even produce las páginas 2, 4 y 6 en ese orden. 6-1even produce las páginas 6, 4 y 2 en ese orden.

El calificador odd funciona de manera similar a even.

Las páginas se pueden restar de un rango de páginas usando el calificador ~ seguido de un rango de páginas. Por ejemplo, 1-20~5-6 y 1-20~5~6 son equivalentes a 1-4 7-20, y ~5 produce todas las páginas excepto la página 5. Dependiendo de su shell, puede que necesite citar este argumento debido al ~ al principio.

La configuración de rotación de página puede hacer que pdftk rotete páginas y documentos. Cada opción establece la rotación de página de la siguiente manera (en grados): north: 0, east: 90, south: 180, west: 270, left: -90, right: +90, down: +180. left, right y down hacen ajustes relativos a la rotación de una página.

Si no se pasan argumentos a cat, entonces pdftk combina todos los PDF de entrada en el orden en que se proporcionaron para crear la salida.

NOTAS:
* <número de página de fin> puede ser menor que <número de página de inicio>.
* La palabra clave end puede usarse para referirse a la última página de un documento en lugar de un número de página.
* Referencie una sola página omitiendo el número de página de fin.
* El manejador puede usarse solo para representar el documento PDF completo, por ejemplo, B1-end es lo mismo que B.
* Puede referenciar números de página en orden inverso anteponiéndoles la letra r. Por ejemplo, la página r1 es la última página del documento, r2 es la penúltima página del documento y rend es la primera página del documento. Puede usar este prefijo también en rangos, por ejemplo, r3-r1 son las últimas tres páginas de un PDF.

Ejemplos de Rangos de Páginas sin Manejadores:
1\-endeast – rotar todo el documento 90 grados
5 11 20 – tomar páginas individuales del PDF de entrada
5-25oddwest – tomar páginas impares en el rango, rotar 90 grados
6-1 – invertir páginas en el rango del PDF de entrada

Ejemplos de Rangos de Páginas Usando Manejadores:
Digamos A=in1.pdf B=in2.pdf, entonces:
A1-21 – tomar rango de in1.pdf
Bend-1odd –

; tomar todas las páginas impares de in2.pdf en orden inverso
A72 – tomar una sola página de in1.pdf
A1-21 Beven A72 – ensamblar páginas de in1.pdf e in2.pdf
Awest – rotar todo el documento in1.pdf 90 grados
B – usar todo de in2.pdf
A2-30evenleft – tomar las páginas pares del rango, eliminar 90 grados de la rotación de cada página
A A – concatenar in1.pdf con in1.pdf
Aevenwest Aoddeast – aplicar rotaciones a páginas pares, páginas impares de in1.pdf
Awest Bwest Bdown – concatenar documentos rotados

shuffle [<rangos de páginas>]
Colaciona páginas de los PDF de entrada para crear un nuevo PDF. Funciona como la operación cat excepto que toma una página a la vez de cada rango de páginas para ensamblar el PDF de salida. Si un rango se queda sin páginas, continúa con los rangos restantes. Los rangos pueden usar todas las características descritas anteriormente para cat, como rangos de páginas inversas, múltiples rangos de un solo PDF y rotación de páginas. Esta característica fue diseñada para ayudar a colacionar páginas PDF después de escanear documentos en papel.
burst
Divide un solo documento PDF de entrada en páginas individuales. También crea un informe llamado doc_data.txt que es el mismo que la salida de dump_data. La sección output puede contener una cadena de formato estilo printf para nombrar estas páginas. Por ejemplo, si deseas páginas nombradas page_01.pdf, page_02.pdf, etc., pasa output page_%02d.pdf a pdftk. Si se omite el patrón, se añadirá un patrón predeterminado g_%04d.pdf y se producirán páginas nombradas pg_0001.pdf, pg_0002.pdf, etc. Se puede aplicar encriptación a la salida añadiendo opciones de salida como owner_pw, por ejemplo:

pdftk in.pdf burst owner_pw foopass

rotate [<rangos de páginas>]
Toma un solo PDF de entrada y rota solo las páginas especificadas. Todas las demás páginas permanecen sin cambios. El orden de las páginas permanece sin cambios. Especifica las páginas a rotar usando la misma notación que usarías con cat, excepto que omites las páginas que no estás rotando:

[<número de página de inicio>[-<número de página de fin>[<calificador>]]][<rotación de página>]

El calificador puede ser even (par) o odd (impar), y la rotación de página puede ser north (norte), south (sur), east (este), west (oeste), left (izquierda), right (derecha), o down (abajo).

Cada opción establece la rotación de página de la siguiente manera (en grados): north: 0, east: 90, south: 180, west: 270, left: -90, right: +90, down: +180. left, right y down realizan ajustes relativos a la rotación de una página.

El orden dado de las páginas no cambia el orden de las páginas en la salida.

generate_fdf
Lee un único archivo PDF de entrada y genera un archivo FDF adecuado para fill_form a partir de él, al nombre de archivo de salida dado o (si no se proporciona salida) a la salida estándar. No crea un nuevo PDF.
fill_form <nombre de archivo de datos FDF | nombre de archivo de datos XFDF | - | PROMPT>
Rellena los campos del formulario del PDF de entrada único con los datos de un archivo FDF, archivo XFDF o stdin. Ingresa el nombre del archivo de datos después de fill_form, o usa - para pasar los datos a través de stdin, de la siguiente manera:

pdftk form.pdf fill_form data.fdf output form.filled.pdf

Si el archivo FDF de entrada incluye datos con formato de Texto Enriquecido además de texto plano, los datos de Texto Enriquecido se empaquetan en los campos del formulario *además* del texto plano. Pdftk también establece una bandera que indica a Reader/Acrobat que genere nuevas apariencias de campo basadas en los datos de Texto Enriquecido. Por lo tanto, cuando el usuario abra el PDF, el visor creará la apariencia de Texto Enriquecido sobre la marcha. Si el visor PDF del usuario no admite Texto Enriquecido, el usuario verá los datos de texto plano en su lugar. Si aplanas este formulario antes de que Acrobat tenga la oportunidad de crear (y guardar) nuevas apariencias de campo, verás los datos de campo de texto plano.

También consulta las opciones flatten, need_appearances y replacement_font.

background <nombre de archivo de PDF de fondo | - | PROMPT>
Aplica una marca de agua PDF al fondo de un único PDF de entrada. Pasa el nombre del archivo PDF de fondo después de background de la siguiente manera:

pdftk in.pdf background back.pdf output out.pdf

Pdftk utiliza solo la primera página del PDF de fondo y la aplica a cada página del PDF de entrada. Esta página se escala y rota según sea necesario para ajustarse a la página de entrada. Puedes usar - para pasar un PDF de fondo a pdftk a través de stdin.

Si el PDF de entrada no tiene un fondo transparente (como un PDF creado a partir de escaneos de páginas), entonces el fondo resultante no será visible; usa la operación stamp en su lugar.

multibackground <nombre de archivo de PDF de fondo | - | PROMPT>
Igual que la operación background, pero aplica cada página del PDF de fondo a la página correspondiente del PDF de entrada. Si el PDF de entrada tiene más páginas que el PDF de marca, entonces la página de marca final se repite en estas páginas restantes del PDF de entrada.
stamp <nombre de archivo de PDF de marca | - | PROMPT>
Se comporta igual que la operación background, excepto que superpone la página PDF de marca *encima* de las páginas del documento PDF de entrada. Esto funciona mejor si la página PDF de marca tiene un fondo transparente.
multistamp <nombre de archivo de PDF de marca | - | PROMPT>
Igual que la operación stamp, pero aplica cada página del PDF de fondo a la página correspondiente del PDF de entrada. Si el PDF de entrada tiene más páginas que el PDF de marca, entonces la página de marca final se repite en estas páginas restantes del PDF de entrada.
dump_data
Lee un único archivo PDF de entrada e informa sus metadatos, marcadores (a.k.a. esquema), métricas de página (medios, rotación y etiquetas), datos incrustados por STAMPtk (ver la opción embed de STAMPtk) y otros datos al nombre de archivo de salida dado o (si no se proporciona salida) a la salida estándar. Los caracteres no ASCII se codifican como entidades numéricas XML. No crea un nuevo PDF.
dump_data_utf8
Igual que dump_data excepto que la salida está codificada como UTF-8.
dump_data_fields
Lee un único archivo PDF de entrada e informa estadísticas de campos de formulario al nombre de archivo de salida dado o (si no se proporciona salida) a la salida estándar. Los caracteres no ASCII se codifican como entidades numéricas XML. No crea un nuevo PDF.
dump_data_fields_utf8
Igual que dump_data_fields excepto que la salida está codificada como UTF-8.
dump_data_annots
Esta operación actualmente solo informa anotaciones de enlace. Lee un único archivo PDF de entrada e informa información de anotaciones al nombre de archivo de salida dado o (si no se proporciona salida) a la salida estándar. Los caracteres no ASCII se codifican como entidades numéricas XML. No crea un nuevo PDF.
update_info <nombre de archivo de datos de información | - | PROMPT>
Cambia los marcadores, etiquetas de página, tamaños de página, rotaciones de página y metadatos en el diccionario Info de un solo PDF para que coincidan con el archivo de datos de entrada. El archivo de datos de entrada usa la misma sintaxis que la salida de dump_data. Los caracteres no ASCII deben codificarse como entidades numéricas XML.

Esta operación no cambia los metadatos almacenados en el flujo XMP del PDF, si lo tiene. (Por esta razón, deberías incluir una entrada ModDate en tu información actualizada con una fecha/hora actual, formato: D:YYYYMMDDHHmmSS, ej. D:201307241346 - los datos omitidos después de YYYY vuelven a los valores predeterminados.)

Por ejemplo:

pdftk in.pdf update_info in.info output out.pdf

update_info_utf8 <nombre de archivo de datos de información | - | PROMPT>
Igual que update_info excepto que la entrada está codificada como UTF-8.
attach_files <nombres de archivo de adjunto | PROMPT> [to_page <número de página | PROMPT> | relation <relación>]
Empaqueta archivos arbitrarios en un PDF usando las características de adjunto de archivo de PDF. Se pueden enumerar varios adjuntos después de attach_files. Los adjuntos se añaden a nivel de documento a menos que se proporcione la opción opcional to_page, en cuyo caso los archivos se adjuntan a la página dada (la primera página es 1, la última página es end). Los adjuntos a nivel de documento pueden ser etiquetados con una relación entre Source, Data, Alternative, Supplement y Unspecified (predeterminado).

Por ejemplo:

pdftk in.pdf attach_files table1.html table2.html to_page 6 output out.pdf

pdftk in.pdf attach_files in.tex relation Source output out.pdf

unpack_files
Copia todos los adjuntos del PDF de entrada a la carpeta actual o a un directorio de salida indicado después de output. Por ejemplo:

pdftk report.pdf unpack_files output ~/atts/

o, interactivamente:

pdftk report.pdf unpack_files output PROMPT

[output <nombre de archivo de salida | - | PROMPT>]
El nombre del archivo PDF de salida no puede ser el mismo que el nombre de un archivo de entrada. Usa - para enviar la salida a stdout. Al usar la operación dump_data, usa output para establecer el nombre del archivo de datos de salida. Al usar la operación unpack_files, usa output para establecer el nombre de un directorio de salida. Al usar la operación burst, puedes usar output para controlar los nombres de archivo de las páginas PDF resultantes (descrito anteriormente).

OPCIONES DE DESENCRIPTADO

[encrypt_method <method>]
El método de encriptado por omisión es AES-128. Se pueden elegir los algoritmos más débiles RC4 de 40 bits y RC4 de 128 bits especificando encrypt_40bit o encrypt_128bit (no recomendado).
[allow <permissions>]
Los permisos se aplican al PDF de salida solo si se especifica una fuerza de encriptado o si se proporciona una contraseña de propietario o de usuario. Si no se especifican permisos, se aplicarán por omisión 'none', lo que significa que todas las siguientes funcionalidades estarán deshabilitadas.

La sección permissions puede incluir una o más de las siguientes funcionalidades:

Printing
Impresión de Alta Calidad
DegradedPrinting
Impresión de Baja Calidad
ModifyContents
También permite Ensamblaje
Assembly
CopyContents
También permite Lectores de Pantalla
ScreenReaders
ModifyAnnotations
También permite Rellenar
FillIn
AllFeatures
Permite al usuario realizar todas las operaciones anteriores y la impresión de alta calidad.
[owner_pw <contraseña de propietario | PROMPT>]
[user_pw <contraseña de usuario | PROMPT>]
Si se proporciona una fuerza de encriptado pero no contraseñas, las contraseñas de propietario y de usuario permanecerán vacías, lo que significa que cualquiera podrá abrir el PDF resultante y alterar sus parámetros de seguridad.
[compress | uncompress]
Estas opciones solo son útiles cuando se desea editar código PDF en un editor de texto como vim o emacs. Elimina la compresión de las secuencias de páginas PDF aplicando el filtro uncompress. Utiliza el filtro compress para restaurar la compresión.
[flatten]
Utiliza esta opción para fusionar los campos de formulario interactivos de un PDF de entrada (y sus datos) con las páginas del PDF. Solo se puede proporcionar un PDF de entrada. A veces se usa con la operación fill_form.
[need_appearances]
Establece una bandera que indica a Reader/Acrobat que genere nuevas apariencias para los campos basadas en los valores de los mismos. Úsalo al rellenar un formulario con texto no ASCII para asegurar la mejor presentación en Adobe Reader o Acrobat. No funcionará si se combina con la opción flatten.
[replacement_font <nombre de fuente>]
Utiliza la fuente especificada para mostrar texto en los campos del formulario. Esta opción es útil al rellenar un formulario con texto no ASCII que no es compatible con las fuentes incluidas en el PDF de entrada. nombre de fuente puede ser el nombre del archivo o el nombre de la familia de una fuente, pero usar un nombre de archivo es más fiable. Actualmente, solo se admiten fuentes TrueType con texto Unicode.
[keep_first_id | keep_final_id]
Al combinar páginas de múltiples PDFs, usa una de estas opciones para copiar el ID del documento del primer o último documento de entrada al nuevo PDF de salida. De lo contrario, pdftk crea un nuevo ID de documento para el PDF de salida. Cuando no se proporciona ninguna operación, pdftk siempre usa el ID del PDF de entrada (único).
[drop_xfa]
Si tu PDF de entrada es un formulario creado con Acrobat 7 o Adobe Designer, probablemente contenga datos XFA. Rellenar dicho formulario con pdftk produce un PDF con datos que no se muestran correctamente en Acrobat 7 (¿y 6?). La solución alternativa es eliminar los datos XFA del formulario, ya sea antes de rellenarlo con pdftk o en el momento de rellenarlo. El uso de esta opción hace que pdftk omita los datos XFA del formulario de salida del PDF.

Esta opción solo es útil cuando se ejecuta pdftk en un único PDF de entrada. Al ensamblar un PDF a partir de múltiples entradas usando pdftk, cualquier dato XFA en la entrada se omite automáticamente.

[drop_xmp]
Muchos PDFs almacenan metadatos del documento tanto en un diccionario de Información (estilo antiguo) como en un flujo XMP (estilo nuevo). La operación update_info de Pdftk puede actualizar el diccionario de Información, pero no el flujo XMP. El remedio adecuado para esto es incluir una entrada ModDate en tu información actualizada con una fecha/marca de tiempo actual. El formato de la fecha/marca de tiempo es: D:AAAAMMDDHHMMSS, por ejemplo, D:201307241346 – los datos omitidos después de AAAA vuelven a los valores predeterminados. Esta ModDate más reciente debería indicar a los visores de PDF que los metadatos de Información son más actuales que los datos XMP.

Alternativamente, podrías preferir eliminar por completo el flujo XMP del PDF – eso es lo que hace esta opción. Ten en cuenta que los objetos dentro del PDF pueden tener sus propios flujos de metadatos XMP separados, y que drop_xmp no los elimina. Solo elimina el flujo XMP a nivel de documento del PDF.

[verbose]
Por omisión, pdftk se ejecuta en silencio. Añade verbose al final y se activará.
[dont_ask | do_ask]
Dependiendo de la configuración de compilación (ver ASK_ABOUT_WARNINGS), pdftk podría solicitarte más información cuando encuentre un problema, como una contraseña incorrecta. Anula este comportamiento predeterminado añadiendo dont_ask (para que pdftk no te pregunte qué hacer) o do_ask (para que pdftk te pregunte qué hacer).

Cuando se ejecuta en modo dont_ask, pdftk sobrescribirá los archivos con su salida sin previo aviso.

EJEMPLOS

Colacionar páginas escaneadas
pdftk A=even.pdf B=odd.pdf shuffle A B output collated.pdf
o si odd.pdf está en orden inverso:
pdftk A=even.pdf B=odd.pdf shuffle A Bend-1 output collated.pdf

Los siguientes ejemplos utilizan contraseñas reales como parámetros de línea de comandos, lo cual no se recomienda (ver la sección CONSIDERACIONES DE SEGURIDAD).

Desencriptar un PDF
pdftk secured.pdf input_pw foopass output unsecured.pdf
Encriptar un PDF usando AES-128 (el valor por omisión), sin conceder permisos (el valor por omisión)
pdftk 1.pdf output 1.128.pdf owner_pw foopass
Igual que el anterior, excepto que la contraseña 'baz' también debe usarse para abrir el PDF de salida
pdftk 1.pdf output 1.128.pdf owner_pw foo user_pw baz
Igual que el anterior, excepto que se permite la impresión (una vez abierto el PDF)
pdftk 1.pdf output 1.128.pdf owner_pw foo user_pw baz allow printing
Aplicar encriptado RCA de 40 bits a la salida, revocando todos los permisos (el valor por omisión). Establecer la contraseña de propietario a 'foopass'.
pdftk 1.pdf 2.pdf cat output 3.pdf encrypt_40bit owner_pw foopass
Unir dos archivos, uno de los cuales requiere la contraseña 'foopass'. La salida no está encriptada.
pdftk A=secured.pdf 2.pdf input_pw A=foopass cat output 3.pdf
Unir in1.pdf e in2.pdf en un nuevo PDF, out1.pdf
pdftk in1.pdf in2.pdf cat output out1.pdf
o (usando identificadores):
pdftk A=in1.pdf B=in2.pdf cat A B output out1.pdf
o (usando comodines):
pdftk *.pdf cat output combined.pdf
Eliminar la página 13 de in1.pdf para crear out1.pdf
pdftk in.pdf cat 1-12 14-end output out1.pdf
o:
pdftk A=in1.pdf cat A1-12 A14-end output out1.pdf
Descomprimir las secuencias de páginas del PDF para editar el PDF en un editor de texto (p.ej., vim, emacs)
pdftk doc.pdf output doc.unc.pdf uncompress
Reparar la tabla XREF corrupta y las longitudes de las secuencias de un PDF, si es posible
pdftk broken.pdf output fixed.pdf
Dividir un único documento PDF en páginas y volcar sus datos a doc_data.txt
pdftk in.pdf burst
Dividir un único documento PDF en páginas encriptadas. Permitir impresión de baja calidad
pdftk in.pdf burst owner_pw foopass allow DegradedPrinting
Escribir un informe sobre los metadatos y marcadores del documento PDF en report.txt
pdftk in.pdf dump_data output report.txt
Rotar la primera página del PDF 90 grados en sentido horario
pdftk in.pdf cat 1east 2-end output out.pdf
Rotar un documento PDF completo 180 grados
pdftk in.pdf cat 1-endsouth output out.pdf

CONSIDERACIONES DE SEGURIDAD

Pasar una contraseña como parámetro de línea de comandos no es seguro porque puede guardarse en el historial del shell y ser accesible por otros usuarios a través de /proc. Utiliza la palabra clave PROMPT e introduce las contraseñas a través de la entrada estándar en su lugar.
