NOMBRE

pdnsd-ctl - controla pdnsd

SINOPSIS

pdnsd-ctl [-c directorio_caché] [-q] comando [argumentos]

DESCRIPCIÓN

pdnsd-ctl controla pdnsd, un servidor DNS proxy con caché permanente. Tenga en cuenta que el socket de control de estado debe estar habilitado (especificando una opción en la línea de comandos de pdnsd o en el archivo de configuración) antes de poder usar pdnsd-ctl.

-c directorio_caché
Establece el directorio de caché a directorio_caché (debe coincidir con la configuración de pdnsd). Esto solo es necesario si el directorio difiere del predeterminado especificado en tiempo de compilación.
-q
Será silencioso a menos que la salida sea especificada por el comando o algo salga mal.

COMANDOS

help   [sin argumentos]

Imprime un resumen de comandos.

version [sin argumentos]

Imprime información de versión y licencia.

status [sin argumentos]

Imprime una descripción del estado de la caché de pdnsd, el estado de los hilos y la configuración. También muestra qué servidores de nombres remotos se suponen que están disponibles.

server (índice|etiqueta) (up|down|retest) [dns1[,dns2[,...]]]

Establece el estado de los servidores con el índice o etiqueta dados a activo o inactivo, o fuerza una nueva prueba. El índice se asigna en el orden de definición en pdnsd.conf comenzando desde 0. Usa el comando status para ver los índices. Puedes especificar all en lugar de un índice para realizar la acción para todos los servidores registrados con pdnsd.

Se puede proporcionar un tercer argumento opcional que consiste en una lista de direcciones IP separadas por comas o espacios en blanco. Esta lista reemplazará las direcciones de los servidores de nombres utilizados por pdnsd para la sección de servidor dada. Esta característica es útil para la configuración en tiempo de ejecución de pdnsd con datos DNS dinámicos en scripts llamados por clientes ppp o DHCP. El último argumento también puede ser una cadena vacía, lo que hace que las direcciones IP existentes se eliminen y la sección de servidor correspondiente quede inactiva.
record nombre (delete|invalidate)

Elimina o invalida los registros del nombre de dominio dado si está en la caché. La invalidación significa que los registros se marcan como caducados y se recargarán si es posible. Para los registros locales (es decir, registros que se proporcionaron en el archivo de configuración usando una sección rr, registros leídos de un archivo estilo hosts y registros agregados usando pdnsd-ctl), la invalidación no tiene efecto. La eliminación sí funcionará.

source nombre_archivo propietario [ttl] [(on|off)] [noauth]

Carga un archivo estilo hosts. Funciona como usar la sección de configuración de origen de pdnsd. Propietario y ttl se utilizan como en la sección de origen. El ttl tiene un valor predeterminado de 900 (no es necesario especificarlo). El penúltimo argumento corresponde a la opción serve_aliases y está desactivado por defecto. noauth se utiliza para hacer que los dominios no sean autoritativos (esto es similar a establecer authrec=off en el archivo de configuración, por favor, consulte la página del manual de pdnsd.conf(5) para ver qué significa eso). nombre_archivo es el nombre del archivo, que debe ser legible por pdnsd.

add    a dir_ip nombre [ttl] [noauth]
add    aaaa dir_ip nombre [ttl] [noauth]
add    ptr host nombre [ttl] [noauth]
add    cname host nombre [ttl] [noauth]
add    mx host nombre pref [ttl] [noauth]

Agrega un registro del tipo dado a la caché de pdnsd, reemplazando los registros existentes para el mismo nombre y tipo. El segundo argumento corresponde al valor de la opción en la sección rr que tiene el mismo nombre que el primer argumento. El argumento dir_ip puede ser una lista de direcciones IP, separadas por comas o espacios en blanco. El ttl es opcional, el valor predeterminado es 900 segundos. noauth se utiliza para hacer que los dominios no sean autoritativos (esto es similar a establecer authrec=off en el archivo de configuración, por favor, consulte la página del manual de pdnsd.conf(5) para ver qué significa eso). Si desea que no haya ningún otro registro que el recién agregado en la caché, ejecute pdnsd-ctl record nombre delete antes de agregar registros.

neg    nombre [tipo] [ttl]

Agrega un registro en caché negativamente a la caché de pdnsd, reemplazando los registros existentes para el mismo nombre y tipo. Si no se proporciona ningún tipo, todo el dominio se almacena en caché negativamente. Para los registros almacenados en caché negativamente, los errores se devuelven inmediatamente en una consulta, sin consultar primero a otros servidores. El ttl es opcional, el valor predeterminado es 900 segundos.

config nombre_archivo

Recarga el archivo de configuración de pdnsd.
El archivo de configuración debe ser propiedad del uid que pdnsd tenía cuando se inició, y ser legible por el uid run_as de pdnsd. Si no se especifica ningún nombre de archivo, se recarga el archivo de configuración utilizado al inicio. Tenga en cuenta que algunos cambios de configuración, como el puerto o la dirección IP en la que escucha pdnsd, no se pueden realizar de esta manera y recibirá un mensaje de error. En estos casos, deberá reiniciar pdnsd.

include nombre_archivo

Analiza un archivo de inclusión.
El archivo de inclusión puede contener el mismo tipo de secciones que un archivo de configuración, excepto las secciones globales y de servidor, que no están permitidas. Este comando se puede utilizar para agregar datos a la caché sin reconfigurar pdnsd.

eval   cadena

Analiza una cadena como si fuera parte de un archivo de inclusión.
La cadena debe contener una o más secciones de configuración completas, pero no secciones globales y de servidor, que no están permitidas. Si se proporcionan varias cadenas, se unirán usando saltos de línea y se analizarán juntas.

empty-cache [[+|-]nombre ...]

Elimina todas las entradas de la caché que coincidan con las reglas de inclusión/exclusión.
Si no se proporcionan argumentos, la caché se vacía por completo, liberando todas las entradas existentes. Tenga en cuenta que esto también elimina los registros locales, según lo definido por el archivo de configuración. Para restaurar los registros locales, ejecute "pdnsd-ctl config" inmediatamente después.
Si se proporcionan uno o más argumentos, estos se interpretan como nombres de inclusión/exclusión. Si un argumento comienza con un '+', el nombre debe incluirse. Si un argumento comienza con un '-', debe excluirse. Si un argumento no comienza con '+' o '-', se asume un '+'. Si el nombre de dominio de una entrada de caché termina con uno de los nombres de la lista, la primera coincidencia determinará lo que sucede. Si el nombre coincidente debe incluirse, la entrada de caché se elimina; de lo contrario, permanece. Si no hay coincidencias, la acción predeterminada es no eliminar.

pdnsd-ctl(8) — pdnsd control tool

NAME

pdnsd-ctl — pdnsd control tool

SYNOPSIS

pdnsd-ctl [command [arguments ...]]

DESCRIPTION

The pdnsd-ctl utility is used to control the pdnsd daemon. It can be used to query the cache, to remove entries from the cache, to force a reread of the configuration file, and to restart the daemon.

The control socket is specified in the configuration file. If it is not specified, then pdnsd-ctl will look for /var/run/pdnsd.ctl.

The default settings for pdnsd-ctl are:

  • Control socket: /var/run/pdnsd.ctl
  • Timeout: 5 seconds

COMMANDS

cache-delete name
Delete name from the cache. If name is omitted, the entire cache is flushed.
dump [name]
Dump the cache contents to stdout. If name is specified, only the entry for name (without the leading dot) will be printed. If name is not specified, information about all the names in the cache will be printed.

list-rrtypes [no arguments]

List available rr types for the neg command. Note that those are only used for the neg command, not for add!

BUGS

If you pipe the output of dump command through an application that reads only part of the output and then blocks (such as more or less), pdnsd threads trying to add new entries to the cache will be suspended until the pipe is closed. It is preferable to capture the output in a file in such a case.
Report any remaining bugs to the authors.
