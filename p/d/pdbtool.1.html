NOMBRE

pdbtool --- Una aplicación para probar y convertir reglas de base de datos de patrones de {{ site.product.short_name }}

SINOPSIS

pdbtool [comando] [opciones]

DESCRIPCIÓN

Esta página del manual es solo un resumen.

La aplicación syslog-ng OSE puede hacer coincidir el contenido de los mensajes de registro con una base de datos de patrones de mensajes predefinidos (también llamados patterndb). Al comparar los mensajes con los patrones conocidos, syslog-ng OSE puede identificar el tipo exacto de los mensajes, etiquetar los mensajes y clasificarlos en clases de mensajes. Las clases de mensajes se pueden utilizar para clasificar el tipo de evento descrito en el mensaje de registro. La funcionalidad de la base de datos de patrones es similar a la del proyecto logcheck, pero el enfoque de syslog-ng OSE es más rápido, escala mejor y es mucho más fácil de mantener en comparación con las expresiones regulares de logcheck.

La aplicación pdbtool es una utilidad que se puede usar para:

  • probar mensajes o reglas específicas
  • convertir una base de datos de patrones antigua al último formato de base de datos
  • fusionar bases de datos de patrones en un solo archivo
  • crear automáticamente bases de datos de patrones a partir de una gran cantidad de mensajes de registro
  • volcar el árbol RADIX construido a partir de la base de datos de patrones (o una parte de ella) para explorar cómo funciona la coincidencia de patrones.

El comando dictionary

dictionary [opciones]

Lista cada par nombre-valor que se puede establecer mediante las reglas de la base de datos de patrones.

•
--dump-tag o -T

Lista las etiquetas en lugar de los nombres de los pares nombre-valor.

•
--pdb <ruta-al-archivo> o -p <ruta-al-archivo>

Nombre del archivo de base de datos de patrones a utilizar.

•
--program <nombre-del-programa> o -P <nombre-del-programa>

Lista solo los pares nombre-valor que se pueden establecer para los mensajes de la aplicación ${PROGRAMA} especificada.

El comando dump

dump [opciones]

Muestra el árbol RADIX construido a partir de los patrones. Esto muestra cómo se representan los patrones en syslog-ng OSE y también puede ayudar a rastrear problemas de coincidencia de patrones. La utilidad dump puede volcar el árbol utilizado para hacer coincidir las partes PROGRAM o MSG.

•
--debug o -d

Habilita mensajes de depuración/diagnóstico en stderr.

•
--pdb o -p

Nombre del archivo de base de datos de patrones a utilizar.

•
--program o -P

Muestra el árbol RADIX construido a partir de los patrones que pertenecen a la aplicación ${PROGRAMA}.

•
--program-tree o -T

Muestra el árbol ${PROGRAMA}.

•
--verbose o -v

Habilita mensajes detallados en stderr.

Ejemplo y salida de muestra

pdbtool dump -p patterndb.xml  -P 'sshd'
'p'
    'assword for'
    @QSTRING:@
        'from'
        @QSTRING:@
            'port '
            @NUMBER:@ rule_id='fc49054e-75fd-11dd-9bba-001e6806451b'
                ' ssh' rule_id='fc55cf86-75fd-11dd-9bba-001e6806451b'
                    '2' rule_id='fc4b7982-75fd-11dd-9bba-001e6806451b'
    'ublickey for'
    @QSTRING:@
        'from'
        @QSTRING:@
            'port '
            @NUMBER:@ rule_id='fc4d377c-75fd-11dd-9bba-001e6806451b'
                ' ssh' rule_id='fc5441ac-75fd-11dd-9bba-001e6806451b'
                    '2' rule_id='fc44a9fe-75fd-11dd-9bba-001e6806451b'

El comando match

match [opciones]

Utiliza el comando match para probar las reglas de una base de datos de patrones. El comando intenta hacer coincidir el mensaje especificado con los patrones de la base de datos, evalúa los analizadores del patrón y también muestra qué parte del mensaje se analizó correctamente. El comando devuelve un código de retorno de 0 (éxito) o 1 (sin coincidencia) y muestra la siguiente información:

  • la clase asignada al mensaje (es decir, sistema, violación, etc.),
  • el ID de la regla que coincidió con el mensaje y
  • los valores de los analizadores (si había analizadores en el patrón coincidente).

El comando match tiene las siguientes opciones:

•
--color-out o -c

Colorea la salida de la terminal para resaltar la parte del mensaje que se analizó correctamente.

•
--debug o -d

Habilita mensajes de depuración/diagnóstico en stderr.

•
--debug-csv o -C

Imprime la información de depuración devuelta por la opción --debug-pattern como valores separados por comas.

•
--debug-pattern o -D

Imprime información de depuración sobre la coincidencia de patrones. Ver también la opción --debug-csv.

•
--file=<nombre-de-archivo-con-ruta> o -f

Procesa los mensajes del archivo de registro especificado con la base de datos de patrones. Esta opción permite clasificar mensajes sin conexión y aplicar la base de datos de patrones a archivos de registro ya existentes. Para leer los mensajes desde la entrada estándar (stdin), especifique un guion (-) en lugar de un nombre de archivo.

•
--filter=<expresión-de-filtro> o -F

Imprime solo los mensajes que coinciden con la expresión de filtro de syslog-ng OSE especificada.

•
--message o -M

El texto del mensaje de registro a hacer coincidir (solo la parte MENSAJE sin las cabeceras de syslog).

•
--pdb o -p

Nombre del archivo de base de datos de patrones a utilizar.

•
--program o -P

Nombre del programa a utilizar, tal como aparece en la parte PROGRAMA del mensaje de syslog.

•
--template=<expresión-de-plantilla> o -T

Una expresión de plantilla de syslog-ng OSE que se utiliza para dar formato a los mensajes de salida.

•
--verbose o -v

Habilita mensajes detallados en stderr.

Ejemplo - comprobar

El siguiente comando comprueba si el archivo patterndb.xml reconoce el mensaje Accepted publickey for myuser from 127.0.0.1 port 59357 ssh6:

pdbtool match -p patterndb.xml -P sshd -M "Accepted publickey for myuser from 127.0.0.1 port 59357 ssh6"

Ejemplo - aplicar

El siguiente ejemplo aplica el archivo de base de datos de patrones sshd.pdb a los mensajes de registro almacenados en el archivo /var/log/messages, y muestra solo los mensajes que recibieron una etiqueta useracct.

pdbtool match -p sshd.pdb \
    –file /var/log/messages \
    –filter ‘tags(“usracct”);’

El comando merge

merge [opciones]

Utiliza el comando merge para combinar archivos de base de datos de patrones separados en un solo archivo (las bases de datos de patrones generalmente se almacenan en archivos separados por aplicación para simplificar el mantenimiento). Si un archivo utiliza un formato de base de datos antiguo, se actualiza automáticamente al último formato (V3). Consulte la Guía del administrador de syslog-ng OSE para obtener detalles sobre las diferentes versiones de la base de datos de patrones.

•
--debug o -d

Habilita mensajes de depuración/diagnóstico en stderr.

•
--directory o -D

El directorio que contiene los archivos XML de la base de datos de patrones que se fusionarán.

•
--glob o -G

Especifica nombres de archivo para
