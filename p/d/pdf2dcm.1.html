NOMBRE

pdf2dcm - Encapsula un archivo PDF en un archivo DICOM

SINOPSIS

pdf2dcm [opciones] archivo_pdf_entrada archivo_dicom_salida

DESCRIPCIÓN

La utilidad pdf2dcm lee un archivo PDF (archivo_pdf_entrada), lo convierte a una instancia SOP de Almacenamiento de PDF Encapsulado DICOM y almacena los datos convertidos en un archivo de salida (archivo_dicom_salida).

PARÁMETROS

archivo_pdf_entrada   Nombre del archivo PDF de entrada a encapsular
archivo_dicom_salida  Nombre del archivo DICOM de salida ("-" para la salida estándar)

OPCIONES

Opciones generales

  -h   --help
         imprime este texto de ayuda y sale
       --version
         imprime información de la versión y sale
       --arguments
         imprime argumentos de línea de comandos expandidos
  -q   --quiet
         modo silencioso, no imprime advertencias ni errores
  -v   --verbose
         modo detallado, imprime detalles del procesamiento
  -d   --debug
         modo de depuración, imprime información de depuración
  -ll  --log-level  [n]ivel: cadena constante
         (fatal, error, warn, info, debug, trace)
         usa el nivel n para el registrador
  -lc  --log-config  [a]rchivo: cadena
         usa el archivo de configuración a para el registrador

Opciones del documento DICOM

título del documento:
  +t   --title  [t]ítulo: cadena (por defecto: vacío)
         título del documento
  +cn  --concept-name  [DCE] [VC] [SM]: cadena (por defecto: vacío)
         representación codificada del título del documento definida por el
         designador de esquema de codificación DCE, valor de código VC y significado de código SM
datos del paciente:
  +pn  --patient-name  [n]ombre: cadena
         nombre del paciente en sintaxis PN de DICOM
  +pi  --patient-id  [i]d: cadena
         identificador del paciente
  +pb  --patient-birthdate  [f]echa: cadena (YYYYMMDD)
         fecha de nacimiento del paciente
  +ps  --patient-sex  [s]exo: cadena (M, F u O)
         sexo del paciente
estudio y serie:
  +sg  --generate
         genera nuevos UIDs de estudio y serie (por defecto)
  +st  --study-from  [a]rchivo: cadena
         lee datos del paciente/estudio del archivo DICOM
  +se  --series-from  [a]rchivo: cadena
         lee datos del paciente/estudio/serie del archivo DICOM
número de instancia:
  +i1  --instance-one
         usa el número de instancia 1 (por defecto, no con +se)
  +ii  --instance-inc
         incrementa el número de instancia (solo con +se)
  +is  --instance-set [i]nstancia número: entero
         usa el número de instancia i
anotación grabada:
  +an  --annotation-yes
         el documento contiene datos de identificación del paciente (por defecto)
  -an  --annotation-no
         el documento no contiene datos de identificación del paciente

Opciones de procesamiento

otras opciones de procesamiento:
  -k   --key  [c]lave: gggg,eeee="cadena", ruta o nombre de diccionario="cadena"
         añade atributo adicional

Opciones de salida

formato del archivo de salida:
  +F   --write-file
         escribe formato de archivo (por defecto)
  -F   --write-dataset
         escribe conjunto de datos sin información de metadatos del archivo
codificación de longitud de grupo:
  +g=  --group-length-recalc
         recalcula longitudes de grupo si están presentes (por defecto)
  +g   --group-length-create
         escribe siempre con elementos de longitud de grupo
  -g   --group-length-remove
         escribe siempre sin elementos de longitud de grupo
codificación de longitud en secuencias y elementos:
  +e   --length-explicit
         escribe con longitudes explícitas (por defecto)
  -e   --length-undefined
         escribe con longitudes indefinidas
relleno final del conjunto de datos (no con --write-dataset):
  -p   --padding-off
         sin relleno (implícito si --write-dataset)
  +p   --padding-create  [r]elleno archivo [r]elleno elemento: entero
         alinea el archivo en un múltiplo de r bytes
         y los elementos en un múltiplo de r bytes

NOTAS

Fuentes de atributos

La aplicación puede ser alimentada con información adicional para completar atributos obligatorios (y opcionales) en el nuevo archivo DICOM, como información del paciente, estudio y serie:

  • La opción --key puede usarse para añadir atributos adicionales al archivo DICOM de salida.
  • También es posible especificar secuencias, elementos y atributos anidados usando la opción --key. En estos casos, se debe usar una notación especial de "ruta". Los detalles sobre esta notación de ruta se encuentran en la documentación de dcmodify.
  • La opción --key puede aparecer más de una vez.
  • La parte del valor (después del '=') puede estar ausente, provocando que el atributo se establezca con longitud cero.
  • Tenga en cuenta que la opción --key se aplica al final, justo antes de guardar el archivo DICOM, por lo que no se realiza ninguna verificación de valor.

REGISTRO

El nivel de salida del registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, con fines de depuración. Otros niveles de registro se pueden seleccionar usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En eventos de error tan severos, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida del registro deba escribirse en un archivo (opcionalmente con rotación de archivo de registro), a syslog (Unix) o al registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos finales indican que se permiten múltiples valores (1-n), una combinación de ambos significa 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Generalmente, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells Unix comunes.

Además, se pueden especificar uno o más archivos de comandos usando un signo '@' como prefijo del nombre del archivo (por ejemplo, @comando.txt). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre comillas dobles) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comando no puede contener otro archivo de comando. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

CÓDIGOS DE SALIDA

La utilidad pdf2dcm utiliza los siguientes códigos de salida al terminar. Esto permite al usuario verificar la razón por la que la aplicación terminó.

General

EXITCODE_NO_ERROR                 0
EXITCODE_COMMANDLINE_SYNTAX_ERROR 1
EXITCODE_MEMORY_EXHAUSTED         4

Errores de archivo de entrada

EXITCODE_CANNOT_READ_INPUT_FILE   20
EXITCODE_NO_INPUT_FILES           21
EXITCODE_INVALID_INPUT_FILE       22

Errores de archivo de salida

EXITCODE_CANNOT_WRITE_OUTPUT_FILE 40

ENTORNO

La utilidad pdf2dcm intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH.

ENVIRONMENT

The DICOM data dictionary can be loaded from a file. By default, i.e. if the DCMDICTPATH environment variable is not set, the file <datadir>/dicom.dic will be loaded unless the dictionary is built into the application (default for Windows).

The default behavior should be preferred and the DCMDICTPATH environment variable only used when alternative data dictionaries are required. The DCMDICTPATH environment variable has the same format as the Unix shell PATH variable in that a colon (":") separates entries. On Windows systems, a semicolon (";") is used as a separator. The data dictionary code will attempt to load each file specified in the DCMDICTPATH environment variable. It is an error if no data dictionary can be loaded.
