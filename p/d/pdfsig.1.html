pdfsig(1) Manual de Comandos Generales pdfsig(1)

NOMBRE

pdfsig - Herramienta de firmas digitales de formato de documento portátil (PDF)

SINOPSIS

pdfsig [opciones] [archivo-PDF] [archivo-salida]

DESCRIPCIÓN

pdfsig verifica las firmas digitales en un documento PDF. También muestra la identidad de cada firmante (campo commonName y nombre distinguido completo del certificado del firmante), la hora y fecha de la firma, el algoritmo hash utilizado para firmar, el tipo de firma según lo indicado en el PDF y los rangos firmados con una declaración de si el documento completo está firmado. También puede firmar documentos PDF (opciones -add-signature o -sign).

pdfsig utiliza los certificados de confianza almacenados en la Base de Datos de Servicios de Red (NSS) o en el sistema S/MIME de GnuPG (gpgsm).

pdfsig también utiliza el Protocolo de Estado de Certificado en Línea (OCSP) (consulte http://en.wikipedia.org/wiki/Online_Certificate_Status_Protocol) para buscar el certificado en línea y comprobar si ha sido revocado (a menos que se haya especificado -no-ocsp).

Si se utiliza el backend NSS, la Base de Datos NSS se busca en las siguientes ubicaciones:

  • Si se especifica la opción -nssdir, el directorio especificado por esta opción.
  • La base de datos de certificados NSS en el perfil predeterminado de Firefox. es decir, $HOME/.mozilla/firefox/*.default.
  • La base de datos de certificados NSS en /etc/pki/nssdb.

Si se utiliza el backend GPG, el certificado S/MIME se lee de $GNUPGHOME, que por defecto es $HOME/.gnupg

OPCIONES

-nssdir [prefijo]directorio
Especifica el directorio de la base de datos que contiene los archivos de la base de datos de certificados y claves. Consulte la opción -d de certutil(1) para obtener detalles del prefijo. Si no se especifica, se utilizan las otras ubicaciones de búsqueda descritas en DESCRIPCIÓN.
-nss-pwd contraseña
Especifica la contraseña necesaria para acceder a la base de datos NSS (si la hay).
-nocert
No validar el certificado.
-no-ocsp
No realizar la comprobación de revocación de certificados OCSP en línea (las Listas de Revocación de Certificados (CRL) locales todavía se utilizan).
-assert-signer fpr_o_archivo
Esta opción comprueba si la firma que cubre todo el documento ha sido realizada con la clave especificada. La clave se especifica como una huella digital o un archivo que contiene huellas digitales. La huella digital debe proporcionarse o listarse en formato compacto (sin dos puntos ni espacios entre ellas). Si fpr_o_archivo especifica un archivo, se ignorarán las líneas vacías y todas las líneas que comiencen con un símbolo de almohadilla. Solo disponible para el backend GnuPG
-no-appearance
No añadir información de apariencia al firmar campos existentes (nombre del firmante y fecha).
-aia
Habilitar el uso de la extensión Authority Information Access (AIA) para obtener certificados faltantes para construir la cadena de certificados.
-dump
Volcar todas las firmas en el directorio actual en su formato nativo. Lo más probable es que sea un paquete CMS/PKCS7 acolchado o sin acolchar.
-add-signature
Añadir una nueva firma al documento.
-new-signature-field-name nombre
Especifica el nombre del campo que se utilizará al añadir una nueva firma. Se utilizará un ID aleatorio por defecto.
-sign campo
Firmar el documento en el campo de firma especificado presente en el documento (debe estar sin firmar). El campo se puede especificar por nombre de campo (cadena) o por el n-ésimo campo de firma del documento (entero).
-nick apodo
Utilizar el certificado con el apodo dado para firmar (backend NSS). Si el apodo comienza con pkcs11:, se trata como una URI PKCS#11 (backend NSS). Si se proporciona el apodo como huella digital, será el certificado utilizado (backend GPG)
-backend backend
Utilizar el backend especificado para firmas criptográficas
-kpw contraseña
Utilizar la contraseña dada para la clave de firma (esto podría faltar si la clave no está protegida por contraseña).
-digest algoritmo
Utilizar el algoritmo de digestión dado para firmar (predeterminado: SHA256).
-reason razón
Establecer la cadena de razón dada para la firma (predeterminado: sin razón establecida).
-enable-pgp
Habilitar firmas pgp en el backend GnuPG. Solo disponible para el backend GnuPG.
-etsi
Crear una firma de tipo ETSI.CAdES.detached en lugar de adbe.pkcs7.detached.
-list-nicks
Listar los apodos disponibles en la base de datos NSS.
-list-backends
Listar los backends disponibles para firmas criptográficas
-v
Mostrar información de copyright y versión.
-h
Mostrar información de uso. (-help y --help son equivalentes.)

EJEMPLOS

pdfsig archivo_firmado.pdf
Muestra la información de la firma para archivo_firmado.pdf.
pdfsig entrada.pdf salida.pdf -add-signature -nss-pwd contraseña -nick mi-certificado -reason 'por diversión!'
Crea un nuevo pdf llamado salida.pdf con el contenido de entrada.pdf firmado por el certificado 'mi-certificado'.
pdfsig entrada.pdf salida.pdf -add-signature -nss-pwd contraseña -nick 'pkcs11:token=smartcard0;object=Segundo%20certificado;type=cert'
Lo mismo, pero utiliza una URI PKCS#11 definida en IETF RFC 7512 para seleccionar el certificado a utilizar para firmar.
pdfsig entrada.pdf salida.pdf -sign 0 -nss-pwd contraseña -nick mi-certificado -reason 'por diversión!'
Crea un nuevo pdf llamado salida.pdf con el contenido de entrada.pdf firmado por el certificado 'mi-certificado'. entrada.pdf debe tener un campo de firma existente sin firmar.
