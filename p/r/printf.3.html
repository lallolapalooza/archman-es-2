DESCRIPCIÓN

Las funciones de la familia printf() producen salida de acuerdo con un formato como se describe a continuación. Las funciones printf() y vprintf() escriben la salida en stdout, el flujo de salida estándar; fprintf() y vfprintf() escriben la salida en el flujo de salida stream dado; sprintf(), snprintf(), vsprintf(), y vsnprintf() escriben en la cadena de caracteres str.

La función dprintf() es igual a fprintf() excepto que genera salida a un descriptor de archivo, fd, en lugar de a un flujo stdio(3).

Las funciones snprintf() y vsnprintf() escriben como máximo size bytes (incluyendo el byte nulo terminador ('\0')) en str.

Las funciones vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() son equivalentes a las funciones printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivamente, excepto que se llaman con un va_list en lugar de un número variable de argumentos. Estas funciones no llaman a la macro va_end. Debido a que invocan la macro va_arg, el valor de ap no está definido después de la llamada. Ver stdarg(3).

Todas estas funciones escriben la salida bajo el control de una cadena de formato que especifica cómo los argumentos subsiguientes (o los argumentos accedidos a través de las facilidades de argumentos de longitud variable de stdarg(3)) se convierten para la salida.

C99 y POSIX.1-2001 especifican que los resultados no están definidos si una llamada a sprintf(), snprintf(), vsprintf(), o vsnprintf() causaría que la copia tenga lugar entre objetos que se solapan (por ejemplo, si el array de cadena de destino y uno de los argumentos suministrados se refieren al mismo buffer). Ver PRECÁUCIONES.

Formato de la cadena de formato

La cadena de formato es una cadena de caracteres, que comienza y termina en su estado de desplazamiento inicial, si lo hay. La cadena de formato se compone de cero o más directivas: caracteres ordinarios (que no sean %), que se copian sin cambios al flujo de salida; y especificaciones de conversión, cada una de las cuales resulta en la obtención de cero o más argumentos subsiguientes. Cada especificación de conversión se introduce con el carácter % y termina con un especificador de conversión. Entre ellos puede haber (en este orden) cero o más flags, una anchura de campo mínima opcional, una precisión opcional y un modificador de longitud opcional.

La sintaxis general de una especificación de conversión es:


%[argumento$][flags][anchura][.precisión][modificador de longitud]conversión

Los argumentos deben corresponderse adecuadamente (después de la promoción de tipo) con el especificador de conversión. Por defecto, los argumentos se utilizan en el orden dado, donde cada '*' (ver Anchura de campo y Precisión más abajo) y cada especificador de conversión solicita el siguiente argumento (y es un error si se dan insuficientes argumentos). También se puede especificar explícitamente qué argumento se toma, en cada lugar donde se requiere un argumento, escribiendo "%m$" en lugar de '%' y "*m$" en lugar de '*', donde el entero decimal m denota la posición en la lista de argumentos del argumento deseado, indexado comenzando desde 1. Por lo tanto,


printf("%*d", anchura, num);

y


printf("%2$*1$d", anchura, num);

son equivalentes. El segundo estilo permite referencias repetidas al mismo argumento. El estándar C99 no incluye el estilo que usa '$', el cual proviene de la Especificación Única de UNIX. Si se usa el estilo que usa '$', debe usarse en todo momento para todas las conversiones que tomen un argumento y para todos los argumentos de anchura y precisión, pero puede mezclarse con formatos "%%", que no consumen un argumento. No puede haber huecos en los números de argumentos especificados usando '$'; por ejemplo, si se especifican los argumentos 1 y 3, el argumento 2 también debe especificarse en algún lugar de la cadena de formato.

Para algunas conversiones numéricas se utiliza un carácter de base ("punto decimal") o un carácter de agrupación de miles. El carácter real utilizado depende de la parte LC_NUMERIC de la configuración regional. (Ver setlocale(3).) La configuración regional POSIX usa '.' como carácter de base, y no tiene un carácter de agrupación. Por lo tanto,


printf("%'.2f", 1234567.89);

resulta en "1234567.89" en la configuración regional POSIX, en "1234567,89" en la configuración regional nl_NL, y en "1.234.567,89" en la configuración regional da_DK.

printf

NAME

printf - formatted output conversion

SYNOPSIS

#include <stdio.h>
int printf(const char *format, ...);
int fprintf(FILE *stream, const char *format, ...);
int sprintf(char *buf, const char *format, ...);
int snprintf(char *buf, size_t size, const char *format, ...);
#define _GNU_SOURCE
int asprintf(char **restrict strp, const char *restrict format, ...);
int vprintf(const char *format, va_list ap);
int vfprintf(FILE *stream, const char *format, va_list ap);
int vsprintf(char *buf, const char *format, va_list ap);
int vsnprintf(char *buf, size_t size, const char *format, va_list ap);
int vasprintf(char **restrict strp, const char *restrict format, va_list ap);

DESCRIPTION

The printf() family of functions produce output with the same regularity as input(2).

The first argument, for each function, is a pointer to a character array that contains one or more conversion specifications. These specifications, and text outside of them, determine the output of the function. The data to be output is described by a variable number of arguments (or by the va_list ap argument).

There may be between 0 and INT_MAX arguments, excluding the format string and function/stream pointer. If the number of arguments is less than the number of conversion specifications that require them, the behavior is undefined. If the number of arguments is greater than the number of conversion specifications, the excess arguments are evaluated but not used.

The conversion specifications are introduced by a percent sign (%). The conversions that may follow the percent sign are:

  • Optional flags, as described below.
  • Optional field width, as described below.
  • Optional . precision, as described below.
  • Optional length modifier, as described below.
  • A specifier, as described below.

The sprintf() and snprintf() functions are identical to printf(), except that they write output to a string buffer rather than to standard output. The snprintf() function writes at most size - 1 characters, plus the terminating null byte, to buf. It is the caller's responsibility to ensure that buf is large enough to hold the result.

The asprintf() function is similar to sprintf(), but it allocates memory for the returned string dynamically. The caller is responsible for freeing this memory using free(3).

The vprintf(), vfprintf(), vsprintf(), vsnprintf(), and vasprintf() functions are equivalent to their corresponding non-v functions, but use a va_list ap, which points to a list of arguments that has been initialized by the va_start(3), va_arg(3), and va_end(3) macros.

snprintf() and vsnprintf() provide a boundary check that sprintf() and vsprintf() lack. They are therefore generally preferable to sprintf() and vsprintf().

If size is 0, snprintf() and vsnprintf() will return the number of characters that would have been written, and buf may be NULL.

If the format string contains the NULL character, the behavior is undefined.

A NULL pointer argument is not gracefully handled, except for snprintf() and vsnprintf(), which handle NULL pointers when size is 0.

-
The converted value is to be left adjusted on the field boundary. (The default is right justification.) The converted value is padded on the right with blanks, rather than on the left with blanks or zeros. A - overrides a 0 if both are given.
0

For other conversions, the behavior is undefined.

For decimal integer conversion (i, d, u) the output uses the locale's alternative output digits, if any. For example, since glibc 2.2.3 this will give Arabic-Indic digits in the Persian ("fa_IR") locale.

Field width

An optional decimal digit string (with nonzero first digit) specifying a minimum field width. If the converted value has fewer characters than the field width, it will be padded with spaces on the left (or right, if the left-adjustment flag has been given). Instead of a decimal digit string one may write "*" or "*m$" (for some decimal integer m) to specify that the field width is given in the next argument, or in the m-th argument, respectively, which must be of type int. A negative field width is taken as a '-' flag followed by a positive field width. In no case does a nonexistent or small field width cause truncation of a field; if the result of a conversion is wider than the field width, the field is expanded to contain the conversion result.

Precision

An optional precision, in the form of a period ('.') followed by an optional decimal digit string. Instead of a decimal digit string one may write "*" or "*m$" (for some decimal integer m) to specify that the precision is given in the next argument, or in the m-th argument, respectively, which must be of type int. If the precision is given as just '.', the precision is taken to be zero. A negative precision is taken as if the precision were omitted. This gives the minimum number of digits to appear for d, i, o, u, x, and X conversions, the number of digits to appear after the radix character for a, A, e, E, f, and F conversions, the maximum number of significant digits for g and G conversions, or the maximum number of characters to be printed from a string for s and S conversions.

Here, "integer conversion" stands for d, i, o, u, x, or X conversion.

(ell-ell). A following integer conversion corresponds to a long long or unsigned long long argument, or a following n conversion corresponds to a pointer to a long long argument.

SUSv3 specifies all of the above, except for those modifiers explicitly noted as being nonstandard extensions. SUSv2 specified only the length modifiers h (in hd, hi, ho, hx, hX, hn) and l (in ld, li, lo, lx, lX, ln, lc, ls) and L (in Le, LE, Lf, Lg, LG).

As a nonstandard extension, the GNU implementations treats ll and L as synonyms, so that one can, for example, write llg (as a synonym for the standards-compliant Lg) and Ld (as a synonym for the standards compliant lld). Such usage is nonportable.

Conversion specifiers

A character that specifies the type of conversion to be applied. The conversion specifiers and their meanings are:

d, i
The int argument is converted to signed decimal notation. The precision, if any, gives the minimum number of digits that must appear; if the converted value requires fewer digits, it is padded on the left with zeros. The default precision is 1. When 0 is printed with an explicit precision 0, the output is empty.
o, u, x, X
The unsigned int argument is converted to unsigned octal (o), unsigned decimal (u), or unsigned hexadecimal (x and X) notation. The letters abcdef are used for x conversions; the letters ABCDEF are used for X conversions. The precision, if any, gives the minimum number of digits that must appear; if the converted value requires fewer digits, it is padded on the left with zeros. The default precision is 1. When 0 is printed with an explicit precision 0, the output is empty.
e, E
The double argument is rounded and converted in the style [-]d.ddde±dd where there is one digit (which is nonzero if the argument is nonzero) before the decimal-point character and the number of digits after it is equal to the precision; if the precision is missing, it is taken as 6; if the precision is zero, no decimal-point character appears. An E conversion uses the letter E (rather than e) to introduce the exponent. The exponent always contains at least two digits; if the value is zero, the exponent is 00.
f, F
The double argument is rounded and converted to decimal notation in the style [-]ddd.ddd, where the number of digits after the decimal-point character is equal to the precision specification. If the precision is missing, it is taken as 6; if the precision is explicitly zero, no decimal-point character appears. If a decimal point appears, at least one digit appears before it.
(SUSv2 does not know about F and says that character string representations for infinity and NaN may be made available. SUSv3 adds a specification for F. The C99 standard specifies "[-]inf" or "[-]infinity" for infinity, and a string starting with "nan" for NaN, in the case of f conversion, and "[-]INF" or "[-]INFINITY" or "NAN" in the case of F conversion.)
g, G
The double argument is converted in style f or e (or F or E for G conversions). The precision specifies the number of significant digits. If the precision is missing, 6 digits are given; if the precision is zero, it is treated as 1. Style e is used if the exponent from its conversion is less than -4 or greater than or equal to the precision. Trailing zeros are removed from the fractional part of the result; a decimal point appears only if it is followed by at least one digit.
a, A
(C99; not in SUSv2, but added in SUSv3) For a conversion, the double
i> el argumento se convierte a notación hexadecimal (utilizando las letras abcdef) en el estilo [-]0xh.hhhhp±d; para la conversión A se usa el prefijo 0X, las letras ABCDEF y el separador de exponente P. Hay un dígito hexadecimal antes del punto decimal, y el número de dígitos después de él es igual a la precisión. La precisión predeterminada es suficiente para una representación exacta del valor si existe una representación exacta en base 2 y, de lo contrario, es suficientemente grande para distinguir valores de tipo double. Si se proporciona una precisión, no es necesario que haya un byte nulo; si la precisión no se especifica, o es mayor que el tamaño del array, el array debe contener un byte nulo terminador.
Si hay un modificador l presente: el argumento const wchar_t * se espera que sea un puntero a un array de caracteres anchos. Los caracteres anchos del array se convierten a caracteres multibyte (cada uno mediante una llamada a la función wcrtomb(3), con un estado de conversión que comienza en el estado inicial antes del primer carácter ancho), hasta e incluyendo un carácter nulo ancho terminador. (Esta especificación no es compatible con la biblioteca C bionic.) El comportamiento es indefinido si la especificación de conversión incluye alguna bandera, ancho de campo o precisión.

(Extensión de glibc; compatible con uClibc y musl, y en Android a partir de API nivel 29.) Imprime la salida de strerror(errno) (o strerrorname_np(errno) en la forma alternativa). No se requiere ningún argumento.

Se escribe un '%'. No se convierte ningún argumento. La especificación de conversión completa es '%%'.

VALOR DE RETORNO

Al retornar con éxito, estas funciones devuelven el número de bytes impresos (excluyendo el byte nulo utilizado para finalizar la salida a cadenas).

Las funciones snprintf() y vsnprintf() no escriben más de size bytes (incluyendo el byte nulo terminador ('\0')). Si la salida fue truncada debido a este límite, entonces el valor de retorno es el número de caracteres (excluyendo el byte nulo terminador) que se habrían escrito en la cadena final si hubiera habido suficiente espacio disponible. Por lo tanto, un valor de retorno de size o superior significa que la salida fue truncada. (Véase también a continuación en ADVERTENCIAS.)

En caso de error, se devuelve un valor negativo y se establece errno para indicar el error.

ERRORES

Véase write(2) y putwc(3). Además, puede ocurrir el siguiente error:

EOVERFLOW
El valor a devolver es mayor que INT_MAX.

La función dprintf() puede fallar adicionalmente si:

EBADF
El argumento fd no es un descriptor de archivo válido.

ADVERTENCIAS

Algunos programas confían imprudentemente en código como el siguiente


sprintf(buf, "%s algún texto adicional", buf);

para añadir texto a buf. Sin embargo, las normas señalan explícitamente que los resultados son indefinidos si los búferes de origen y destino se superponen al llamar a sprintf(), snprintf(), vsprintf(), y vsnprintf(). Dependiendo de la versión de gcc(1) utilizada y las opciones del compilador empleadas, llamadas como la anterior **no** producirán los resultados esperados.

La implementación de glibc de las funciones snprintf() y vsnprintf() cumple con el estándar C99, es decir, se comporta como se describe anteriormente, desde glibc 2.1. Hasta glibc 2.0.6, devolvían -1 cuando la salida se truncaba.

ERRORES

Dado que sprintf() y vsprintf() asumen una cadena de longitud arbitraria, los llamadores deben tener cuidado de no desbordar el espacio real; esto a menudo es imposible de asegurar. Tenga en cuenta que la longitud de las cadenas producidas depende de la configuración regional y es difícil de predecir. Utilice snprintf() y vsnprintf() en su lugar (o asprintf(3) y vasprintf(3)).

Código como printf(foo); a menudo indica un error, ya que foo puede contener un carácter %. Si < printf(3) — Arch Linux

CAVEATS

If the format string ifoo comes from untrusted user input, it may contain %n, causing the printf() call to write to memory and creating a security hole.

EJEMPLOS

Para imprimir Pi a cinco decimales:


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Para imprimir una fecha y hora con el formato "Domingo, Julio 3, 10:02", donde weekday y month son punteros a cadenas:


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        weekday, month, day, hour, min);

Muchos países usan el orden día-mes-año. Por lo tanto, una versión internacionalizada debe ser capaz de imprimir los argumentos en un orden especificado por el formato:


#include <stdio.h>
fprintf(stdout, format,
        weekday, month, day, hour, min);

donde format depende de la configuración regional y puede permutar los argumentos. Con el valor:


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

se podría obtener "Sonntag, 3. Juli, 10:02".

Para asignar una cadena suficientemente grande e imprimir en ella (código correcto para glibc 2.0 y glibc 2.1):

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Determinar el tamaño requerido.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un byte extra para '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si se produce truncamiento en versiones de glibc anteriores a glibc 2.0.6, esto se trata como un error en lugar de manejarse de forma adecuada.
