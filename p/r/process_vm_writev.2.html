process_vm_readv(2) Manual de llamadas al sistema process_vm_readv(2)

NOMBRE

process_vm_readv, process_vm_writev - transferir datos entre espacios de direcciones de procesos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/uio.h>
ssize_t process_vm_readv(pid_t pid,
                       const struct iovec *local_iov,
                       unsigned long liovcnt,
                       const struct iovec *remote_iov,
                       unsigned long riovcnt,
                       unsigned long flags);
ssize_t process_vm_writev(pid_t pid,
                       const struct iovec *local_iov,
                       unsigned long liovcnt,
                       const struct iovec *remote_iov,
                       unsigned long riovcnt,
                       unsigned long flags);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

process_vm_readv(), process_vm_writev():

    _GNU_SOURCE

DESCRIPCIÓN

Estas llamadas al sistema transfieren datos entre el espacio de direcciones del proceso que llama ("el proceso local") y el proceso identificado por pid ("el proceso remoto"). Los datos se mueven directamente entre los espacios de direcciones de los dos procesos, sin pasar por el espacio del kernel.

La llamada al sistema process_vm_readv() transfiere datos del proceso remoto al proceso local. Los datos a transferir se identifican por remote_iov y riovcnt: remote_iov es un puntero a un arreglo que describe rangos de direcciones en el proceso pid, y riovcnt especifica el número de elementos en remote_iov. Los datos se transfieren a las ubicaciones especificadas por local_iov y liovcnt: local_iov es un puntero a un arreglo que describe rangos de direcciones en el proceso que llama, y liovcnt especifica el número de elementos en local_iov.

La llamada al sistema process_vm_writev() es la inversa de process_vm_readv() —transfiere datos del proceso local al proceso remoto. Aparte de la dirección de la transferencia, los argumentos liovcnt, local_iov, riovcnt y remote_iov tienen el mismo significado que para process_vm_readv().

Los argumentos local_iov y remote_iov apuntan a un arreglo de estructuras iovec, descritas en iovec(3type).

Los búferes se procesan en orden de arreglo. Esto significa que process_vm_readv() llena completamente local_iov[0] antes de proceder a local_iov[1], y así sucesivamente. Del mismo modo, se lee completamente remote_iov[0] antes de proceder a remote_iov[1], y así sucesivamente.

De manera similar, process_vm_writev() escribe todo el contenido de local_iov[0] antes de proceder a local_iov[1], y llena completamente remote_iov[0] antes de proceder a remote_iov[1].

Las longitudes de remote_iov[i].iov_len y local_iov[i].iov_len no tienen que ser iguales. Por lo tanto, es posible dividir un búfer local en múltiples búferes remotos, o viceversa.

El argumento flags no se utiliza actualmente y debe establecerse en 0.

Los valores especificados en los argumentos liovcnt y riovcnt deben ser menores o iguales a IOV_MAX (definido en <limits.h> o accesible mediante la llamada sysconf(_SC_IOV_MAX)).

Los recuentos de argumentos y local_iov se comprueban antes de realizar cualquier transferencia. Si los recuentos son demasiado grandes, o local_iov es inválido, o las direcciones se refieren a regiones que son inaccesibles para el proceso local, ninguno de los vectores se procesará y se devolverá un error inmediatamente.

Sin embargo, tenga en cuenta que estas llamadas al sistema no comprueban las regiones de memoria en el proceso remoto hasta justo antes de realizar la lectura/escritura. En consecuencia, puede ocurrir una lectura/escritura parcial (ver VALOR DE RETORNO) si uno de los elementos de remote_iov apunta a una región de memoria inválida en el proceso remoto. No se intentarán más lecturas/escrituras a partir de ese punto. Tenga esto en cuenta al intentar leer datos de longitud desconocida (como cadenas de C terminadas en nulo) de un proceso remoto, evitando abarcar páginas de memoria (típicamente 4 KiB) en un solo elemento de iovec remoto. (En su lugar, divida la lectura remota en dos elementos de remote_iov y haga que se fusionen de nuevo en una sola entrada de escritura local_iov. La primera entrada de lectura llega hasta el límite de la página, mientras que la segunda comienza en el siguiente límite de página).

El permiso para leer o escribir en otro proceso está regido por una comprobación de modo de acceso ptrace PTRACE_MODE_ATTACH_REALCREDS; ver ptrace(2).

VALOR DE RETORNO

En caso de éxito, process_vm_readv() devuelve el número de bytes leídos y process_vm_writev() devuelve el número de bytes escritos. Este valor de retorno puede ser menor que el número total de bytes solicitados, si ocurrió una transferencia parcial. (Las transferencias parciales se aplican a nivel de granularidad de los elementos iovec. Estas llamadas al sistema no realizarán una transferencia parcial que divida un solo elemento iovec).

En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EFAULT
La memoria descrita por local_iov está fuera del espacio de direcciones accesible del llamante.
EFAULT
La memoria descrita por remote_iov está fuera del espacio de direcciones accesible del proceso pid.
EINVAL
La suma de los valores iov_len de local_iov o remote_iov desborda un valor ssize_t.
EINVAL
flags no es 0.
EINVAL
liovcnt o riovcnt es demasiado grande.
ENOMEM
No se pudo asignar memoria para copias internas de las estructuras iovec.
EPERM
El llamante no tiene permiso para acceder al espacio de direcciones del proceso pid.
ESRCH
No existe ningún proceso con el ID pid.

ESTÁNDARES

Linux.

HISTORIA

Linux 3.2, glibc 2.15.

NOTAS

Las transferencias de datos realizadas por process_vm_readv() y process_vm_writev() no están garantizadas como atómicas de ninguna manera.

Estas llamadas al sistema se diseñaron para permitir la comunicación rápida de mensajes al permitir que los mensajes se intercambien con una sola operación de copia (en lugar de la doble copia que se requeriría al usar, por ejemplo, memoria compartida o tuberías).

EJEMPLOS

El siguiente ejemplo de código demuestra el uso de process_vm_readv(). Lee 20 bytes en la dirección 0x10000 del proceso con PID 10 y escribe los primeros 10 bytes en buf1 y los segundos 10 bytes en buf2.

#define _GNU_SOURCE
#include <stdlib.h>
#include <sys/types.h>
#include <sys/uio.h>
int
main(void)
{
    char          buf1[10];
    char          buf2[10];
    pid_t         pid = 10;    /* PID del proceso remoto */
    ssize_t       nread;
    struct iovec  local[2];
    struct iovec  remote[1];
    local[0].iov_base = buf1;
    local[0].iov_len = 10;
    local[1].iov_base = buf2;
    local[1].iov_len = 10;
    remote[0].iov_base = (void *) 0x10000;
    remote[0].iov_len = 20;
    nread = process_vm_readv(pid, local, 2, remote, 1, 0);
    if (nread != 20)
        exit(EXIT_FAILURE);
    /* Ahora buf1 y buf2 contienen los datos leídos */
    exit(EXIT_SUCCESS);
}
