NOMBRE

provider-keyexch - Funciones de biblioteca de intercambio de claves (keyexch) <-> proveedor

SINOPSIS

#include <openssl/core_dispatch.h>
#include <openssl/core_names.h>
/*
 * Ninguna de estas son funciones reales, sino que se muestran así para
 * las firmas de funciones que se ofrecen como punteros a función en
 * arreglos OSSL_DISPATCH.
 */
/* Funciones de gestión de contexto */
void *OSSL_FUNC_keyexch_newctx(void *provctx);
void OSSL_FUNC_keyexch_freectx(void *ctx);
void *OSSL_FUNC_keyexch_dupctx(void *ctx);
/* Derivación de secreto compartido */
int OSSL_FUNC_keyexch_init(void *ctx, void *provkey,
                           const OSSL_PARAM params[]);
int OSSL_FUNC_keyexch_set_peer(void *ctx, void *provkey);
int OSSL_FUNC_keyexch_derive(void *ctx, unsigned char *secret, size_t *secretlen,
                             size_t outlen);
int OSSL_FUNC_keyexch_derive_skey(void *ctx, const char *key_type, void *provctx,
                                  OSSL_FUNC_skeymgmt_import_fn *import,
                                  size_t keylen, const OSSL_PARAM params[]);
/* Parámetros de intercambio de claves */
int OSSL_FUNC_keyexch_set_ctx_params(void *ctx, const OSSL_PARAM params[]);
const OSSL_PARAM *OSSL_FUNC_keyexch_settable_ctx_params(void *ctx,
                                                        void *provctx);

const OSSL_PARAM *OSSL_FUNC_keyexch_gettable_ctx_params(void *ctx,
                                                        void *provctx);

DESCRIPCIÓN

Esta documentación está dirigida principalmente a autores de proveedores. Consulte provider(7) para obtener más información.

La operación de intercambio de claves (OSSL_OP_KEYEXCH) permite a los proveedores implementar algoritmos de intercambio de claves y ponerlos a disposición de las aplicaciones a través de EVP_PKEY_derive(3) y otras funciones relacionadas.

Todas las "funciones" mencionadas aquí se pasan como punteros a función entre libcrypto y el proveedor en arreglos OSSL_DISPATCH(3) a través de arreglos OSSL_ALGORITHM(3) que son devueltos por la función provider_query_operation() del proveedor (ver "Funciones del proveedor" en provider-base(7)).

Todas estas "funciones" tienen una definición de tipo de función correspondiente llamada OSSL_FUNC_{name}_fn, y una función auxiliar para recuperar el puntero de la función de un elemento OSSL_DISPATCH(3) llamada OSSL_FUNC_{name}. Por ejemplo, la "función" OSSL_FUNC_keyexch_newctx() tiene:

typedef void *(OSSL_FUNC_keyexch_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_keyexch_newctx_fn
    OSSL_FUNC_keyexch_newctx(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) Los arreglos se indexan mediante números que se proporcionan como macros en openssl-core_dispatch.h(7), de la siguiente manera:

OSSL_FUNC_keyexch_newctx                OSSL_FUNC_KEYEXCH_NEWCTX
OSSL_FUNC_keyexch_freectx               OSSL_FUNC_KEYEXCH_FREECTX
OSSL_FUNC_keyexch_dupctx                OSSL_FUNC_KEYEXCH_DUPCTX
OSSL_FUNC_keyexch_init                  OSSL_FUNC_KEYEXCH_INIT
OSSL_FUNC_keyexch_set_peer              OSSL_FUNC_KEYEXCH_SET_PEER
OSSL_FUNC_keyexch_derive                OSSL_FUNC_KEYEXCH_DERIVE
OSSL_FUNC_keyexch_derive_skey           OSSL_FUNC_KEYEXCH_DERIVE_SKEY
OSSL_FUNC_keyexch_set_ctx_params        OSSL_FUNC_KEYEXCH_SET_CTX_PARAMS
OSSL_FUNC_keyexch_settable_ctx_params   OSSL_FUNC_KEYEXCH_SETTABLE_CTX_PARAMS
OSSL_FUNC_keyexch_get_ctx_params        OSSL_FUNC_KEYEXCH_GET_CTX_PARAMS
OSSL_FUNC_keyexch_gettable_ctx_params   OSSL_FUNC_KEYEXCH_GETTABLE_CTX_PARAMS

Una implementación de algoritmo de intercambio de claves puede no implementar todas estas funciones. Para ser un conjunto coherente de funciones, un proveedor debe implementar OSSL_FUNC_keyexch_newctx, OSSL_FUNC_keyexch_freectx, OSSL_FUNC_keyexch_init y al menos una de OSSL_FUNC_keyexch_derive y OSSL_FUNC_keyexch_derive_skey. Todas las demás funciones son opcionales.

Un algoritmo de intercambio de claves también debe implementar algún mecanismo para generar, cargar o importar claves a través de la operación de gestión de claves (OSSL_OP_KEYMGMT). Consulte provider-keymgmt(7) para más detalles.

Funciones de gestión de contexto

OSSL_FUNC_keyexch_newctx() debe crear y devolver un puntero a una estructura del lado del proveedor para mantener información de contexto durante una operación de intercambio de claves. Se devolverá un puntero a este contexto en varias otras llamadas a funciones de operación de intercambio de claves. El parámetro provctx es el contexto del proveedor generado durante la inicialización del proveedor (ver provider(7)).

A OSSL_FUNC_keyexch_freectx() se le pasa un puntero al contexto de intercambio de claves del lado del proveedor en el parámetro ctx. Esta función debe liberar cualquier recurso asociado con ese contexto.

OSSL_FUNC_keyexch_dupctx() debe duplicar el contexto de intercambio de claves del lado del proveedor en el parámetro ctx y devolver la copia duplicada.

Funciones de derivación de secreto compartido

OSSL_FUNC_keyexch_init() inicializa una operación de intercambio de claves dado un contexto de intercambio de claves del lado del proveedor en el parámetro ctx, y un puntero a un objeto de clave del proveedor en el parámetro provkey. Los params, si no son NULL, deben establecerse en el contexto de una manera similar a usar OSSL_FUNC_keyexch_set_params(). El objeto de clave debe haber sido generado, cargado o importado previamente en el proveedor utilizando la operación de gestión de claves (OSSL_OP_KEYMGMT) (ver provider-keymgmt(7)).

OSSL_FUNC_keyexch_set_peer() se llama para suministrar la clave pública del par (en el parámetro provkey) a utilizar al derivar el secreto compartido. También se le pasa un contexto de intercambio de claves previamente inicializado en el parámetro ctx. El objeto de clave debe haber sido generado, cargado o importado previamente en el proveedor utilizando la operación de gestión de claves (OSSL_OP_KEYMGMT) (ver provider-keymgmt(7)).

OSSL_FUNC_keyexch_derive() realiza el intercambio de claves real derivando un secreto compartido. Se pasa un contexto de intercambio de claves previamente inicializado en el parámetro ctx. El secreto derivado debe escribirse en la ubicación secret, que no debe exceder los outlen bytes. La longitud del secreto compartido debe escribirse en *secretlen. Si secret es NULL, entonces la longitud máxima del secreto compartido debe escribirse en *secretlen.

OSSL_FUNC_keyexch_derive_skey() es similar a OSSL_FUNC_keyexch_derive() pero utiliza un objeto opaco para almacenar la clave derivada. Acepta el parámetro key_type para dar una pista al proveedor qué tipo de clave (por ejemplo, genérica o AES) se generaría y la función import del objeto EVP_SKEYMGMT para asociarla con la clave. El objeto EVP_SKEYMGMT proviene del mismo proveedor que el KDF.

Funciones de parámetros de intercambio de claves

OSSL_FUNC_keyexch_set_ctx_params() establece los parámetros de intercambio de claves asociados con el contexto de intercambio de claves del lado del proveedor dado ctx a params, ver "Parámetros comunes de intercambio de claves". Cualquier configuración de parámetro es adicional a las que se establecieron previamente. Pasar NULL para params debería devolver verdadero.

OSSL_FUNC_keyexch_get_ctx_params() obtiene los parámetros de intercambio de claves asociados con el contexto de intercambio de claves del lado del proveedor dado ctx en params, ver "Parámetros comunes de intercambio de claves". Pasar NULL para params debería devolver verdadero.

OSSL_FUNC_keyexch_settable_ctx_params() produce un arreglo constante de OSSL_PARAM(3) que describe los parámetros configurables, es decir, los parámetros que se pueden usar con OP_signature_set_ctx_params(). Si OSSL_FUNC_keyexch_settable_ctx_params() está presente, OSSL_FUNC_keyexch_set_ctx_params() también debe estar presente, y viceversa. Del mismo modo, OSSL_FUNC_keyexch_gettable_ctx_params() produce un arreglo constante de OSSL_PARAM(3) que describe los parámetros obtenibles, es decir, los parámetros que pueden ser manejados por OP_signature_get_ctx_params(). provider-keyexch - Interfaz de intercambio de claves del proveedor

SINOPSIS

```c 

#include <openssl/core_dispatch.h>

/*
 * Obtener un puntero a las funciones de intercambio de claves del proveedor.
 */
const OSSL_DISPATCH *OSSL_provider_get_keyexch_functions(int *no_store);

/*
 * Implementaciones de interfaz para el proveedor
 */

/*
 * Crear un nuevo contexto de intercambio de claves.
 * Si 'name' es NULL, se usa la implementación predeterminada.
 */
void *OSSL_FUNC_keyexch_newctx(OSSL_PROVIDER *prov, const char *name);

/*
 * Duplicar un contexto de intercambio de claves.
 */
void *OSSL_FUNC_keyexch_dupctx(OSSL_PROVIDER *prov, void *ctx);

/*
 * Liberar un contexto de intercambio de claves.
 */
void OSSL_FUNC_keyexch_freectx(void *ctx);

/*
 * Inicializar un contexto de intercambio de claves.
 * 'peer' es la clave pública del par remoto, si existe.
 */
int OSSL_FUNC_keyexch_init(void *ctx, const OSSL_PARAM params[]);

/*
 * Establecer el par remoto.
 */
int OSSL_FUNC_keyexch_set_peer(void *ctx, const OSSL_PARAM params[]);

/*
 * Derivar la clave compartida.
 * 'key' es un puntero a la estructura OSSL_KEY para almacenar la clave derivada.
 */
int OSSL_FUNC_keyexch_derive(void *ctx, OSSL_KEY *key);

/*
 * Derivar una clave secreta (clave privada).
 * 'skey' es un puntero a la estructura OSSL_KEY para almacenar la clave secreta derivada.
 */
int OSSL_FUNC_keyexch_derive_skey(void *ctx, OSSL_KEY *skey);

/*
 * Obtener los parámetros que se pueden establecer en el contexto.
 */
const OSSL_PARAM *OSSL_FUNC_keyexch_settable_ctx_params(void *ctx);

/*
 * Establecer los parámetros del contexto.
 */
int OSSL_FUNC_keyexch_set_ctx_params(void *ctx, const OSSL_PARAM params[]);

/*
 * Obtener los parámetros que se pueden obtener del contexto.
 */
const OSSL_PARAM *OSSL_FUNC_keyexch_gettable_ctx_params(void *ctx);

/*
 * Obtener los parámetros del contexto.
 */
int OSSL_FUNC_keyexch_get_ctx_params(void *ctx, OSSL_PARAM params[]);

DESCRIPCIÓN

La interfaz provider-keyexch proporciona un mecanismo para que los proveedores expongan la funcionalidad de intercambio de claves a la biblioteca OpenSSL.

La función principal expuesta por un proveedor es OSSL_provider_get_keyexch_functions(), que devuelve una tabla de punteros a funciones de OSSL_DISPATCH. Cada puntero de función se identifica mediante una cadena de consulta única. OpenSSL llama a estas funciones para realizar las operaciones de intercambio de claves.

El no_store devuelto por OSSL_provider_get_keyexch_functions() indica si el proveedor puede almacenar claves internas. Si no_store se establece en 1, el proveedor no puede almacenar ninguna clave (por ejemplo, claves públicas o privadas) de forma interna, y el valor de retorno de OSSL_FUNC_keyexch_newctx() debe ser NULL.

FUNCIONES

OSSL_FUNC_keyexch_newctx()
Crea y devuelve un nuevo contexto para el intercambio de claves. El parámetro name puede ser NULL para indicar que se debe usar la implementación predeterminada del proveedor, o puede especificar un algoritmo de intercambio de claves concreto por su nombre (por ejemplo, "DH", "ECDH").
OSSL_FUNC_keyexch_dupctx()
Crea un duplicado del contexto de intercambio de claves existente ctx. Esto es útil si se necesita realizar múltiples operaciones de intercambio de claves utilizando la misma configuración.
OSSL_FUNC_keyexch_freectx()
Libera y limpia el contexto de intercambio de claves ctx.
OSSL_FUNC_keyexch_init()
Inicializa el contexto de intercambio de claves ctx. Los parámetros de inicialización se pueden pasar a través de la matriz params. El parámetro peer debe ser la clave pública del par remoto.
OSSL_FUNC_keyexch_set_peer()
Establece la clave pública del par remoto en el contexto de intercambio de claves ctx.
OSSL_FUNC_keyexch_derive()
Realiza la operación de intercambio de claves y deriva la clave compartida. La clave derivada se almacena en la estructura key proporcionada.
OSSL_FUNC_keyexch_derive_skey()
Realiza la operación de intercambio de claves y deriva una clave secreta (clave privada). La clave secreta derivada se almacena en la estructura skey proporcionada.
OSSL_FUNC_keyexch_settable_ctx_params()
Devuelve una matriz de estructuras OSSL_PARAM que describe los parámetros que se pueden establecer en el contexto. Esto se usa para la función OSSL_FUNC_keyexch_set_ctx_params().
OSSL_FUNC_keyexch_set_ctx_params()
Establece los parámetros del contexto de intercambio de claves ctx. Los parámetros se pasan en la matriz params.
OSSL_FUNC_keyexch_gettable_ctx_params()
Devuelve una matriz de estructuras OSSL_PARAM que describen los parámetros que se pueden obtener del contexto. Esto se usa para la función OSSL_FUNC_keyexch_get_ctx_params().
OSSL_FUNC_keyexch_get_ctx_params()
Obtiene los parámetros del contexto de intercambio de claves ctx. Los parámetros solicitados se especifican en la matriz params.

El parámetro ctx en todas las funciones de interfaz (excepto OSSL_FUNC_keyexch_newctx(), OSSL_FUNC_keyexch_dupctx() y OSSL_FUNC_keyexch_freectx()) se refiere al puntero devuelto por OSSL_FUNC_keyexch_newctx() o OSSL_FUNC_keyexch_dupctx().

La misma matriz OSSL_PARAM debe ser devuelta por OSSL_FUNC_keyexch_settable_ctx_params() y OSSL_FUNC_keyexch_gettable_ctx_params(). Si un parámetro se puede establecer, también se puede obtener, y viceversa.

Tenga en cuenta que no todos los parámetros configurables son también obtenibles, y viceversa.

Parámetros comunes de intercambio de claves

Consulte OSSL_PARAM(3) para más detalles sobre la estructura de parámetros utilizada por las funciones OSSL_FUNC_keyexch_set_ctx_params() y OSSL_FUNC_keyexch_get_ctx_params().

Los parámetros comunes actualmente reconocidos por los algoritmos de intercambio de claves integrados son los siguientes:

"kdf-type" (OSSL_EXCHANGE_PARAM_KDF_TYPE) <cadena UTF8>
Establece u obtiene el tipo de Función de Derivación de Clave a aplicar dentro del contexto de intercambio asociado.
"kdf-digest" (OSSL_EXCHANGE_PARAM_KDF_DIGEST) <cadena UTF8>
Establece u obtiene el algoritmo de Digest que se utilizará como parte de la Función de Derivación de Clave asociada con el contexto de intercambio de claves dado.
"kdf-digest-props" (OSSL_EXCHANGE_PARAM_KDF_DIGEST_PROPS) <cadena UTF8>
Establece las propiedades que se utilizarán al buscar la implementación del algoritmo de Digest seleccionado para la Función de Derivación de Clave asociada con el contexto de intercambio de claves dado.
"kdf-outlen" (OSSL_EXCHANGE_PARAM_KDF_OUTLEN) <entero sin signo>
Establece u obtiene el tamaño deseado para la salida de la Función de Derivación de Clave elegida asociada con el contexto de intercambio de claves dado. La longitud del parámetro "kdf-outlen" no debe superar la de un size_t.
"kdf-ukm" (OSSL_EXCHANGE_PARAM_KDF_UKM) <cadena de octetos>
Establece el Material de Clave de Usuario que se utilizará como parte de la Función de Derivación de Clave seleccionada asociada con el contexto de intercambio de claves dado.
"kdf-ukm" (OSSL_EXCHANGE_PARAM_KDF_UKM) <puntero a cadena de octetos>
Obtiene un puntero al Material de Clave de Usuario que se utilizará como parte de la Función de Derivación de Clave seleccionada asociada con el contexto de intercambio de claves dado. Los proveedores generalmente no necesitan admitir este parámetro obtenible, ya que su único propósito es admitir la funcionalidad de las funciones obsoletas EVP_PKEY_CTX_get0_ecdh_kdf_ukm() y EVP_PKEY_CTX_get0_dh_kdf_ukm().

El proveedor FIPS de OpenSSL también admite los siguientes parámetros:

"fips-indicator" (OSSL_EXCHANGE_PARAM_FIPS_APPROVED_INDICATOR) <entero>
Un obtenedor que devuelve 1 si la operación está aprobada por FIPS, o 0 en caso contrario. Esto se puede usar después de llamar a OSSL_FUNC_keyexch_derive(). Puede devolver 0 si "digest-check" o "key-check" están establecidos en 0.
"key-check" (OSSL_EXCHANGE_PARAM_FIPS_KEY_CHECK) <entero>
Si se requiere, este parámetro debe establecerse utilizando OSSL_FUNC_keyexch_init(). El valor predeterminado de 1 causa un error durante la inicialización si la clave no está aprobada por FIPS (por ejemplo, la clave tiene una fortaleza de seguridad inferior a 112 bits). Establecer esto en 0 ignorará el error y establecerá el "fips-indicator" aprobado en 0. Esta opción infringe el cumplimiento de FIPS si hace que el "fips-indicator" aprobado devuelva 0.
"digest-check" (OSSL_EXCHANGE_PARAM_FIPS_DIGEST_CHECK) <entero>
Si se requiere, este parámetro debe establecerse antes de que se establezca cualquier digest opcional. El valor predeterminado de 1 causa un error cuando se establece el digest si el digest no está aprobado por FIPS. Establecer esto en 0 ignorará el error y establecerá el "fips-indicator" aprobado en 0. Esta opción infringe el cumplimiento de FIPS si hace que el "fips-indicator" aprobado devuelva 0.

VALORES DE RETORNO

OSSL_FUNC_keyexch_newctx() y OSSL_FUNC_keyexch_dupctx() deben devolver el contexto de intercambio de claves del lado del proveedor recién creado, o NULL en caso de fallo.

OSSL_FUNC_keyexch_init(), OSSL_FUNC_keyexch_set_peer(), OSSL_FUNC_keyexch_derive(), OSSL_FUNC_keyexch_derive_skey(), OSSL_FUNC_keyexch_set_params(), y OSSL_FUNC_keyexch_get_params() deben devolver 1 para éxito o 0 en caso de error.

OSSL_FUNC_keyexch_settable_ctx_params() y OSSL_FUNC_keyexch_gettable_ctx_params() siempre deben devolver una matriz constante de OSSL_PARAM(3).

HISTORIA

La interfaz KEYEXCH del proveedor se introdujo en OpenSSL 3.0.

Los parámetros de intercambio de claves "fips-indicator", "key-check" y "digest-check" se añadieron en OpenSSL 3.4.

La función OSSL_FUNC_keyexch_derive_skey() se añadió en OpenSSL 3.6.
