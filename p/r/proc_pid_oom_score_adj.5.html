NOMBRE

/proc/pid/oom_score_adj - Ajuste de la puntuación del OOM-killer

DESCRIPCIÓN

/proc/pid/oom_score_adj (desde Linux 2.6.36)
Este archivo se puede usar para ajustar la heurística de "maldad" utilizada para seleccionar qué proceso será eliminado en condiciones de falta de memoria (Out-of-Memory).
La heurística de "maldad" asigna un valor a cada tarea candidata que va de 0 (nunca eliminar) a 1000 (siempre eliminar) para determinar qué proceso se selecciona. Las unidades son aproximadamente una proporción a lo largo de ese rango de memoria permitida que el proceso puede asignar, basado en una estimación de su uso actual de memoria y swap. Por ejemplo, si una tarea está usando toda la memoria permitida, su puntuación de maldad será 1000. Si está usando la mitad de su memoria permitida, su puntuación será 500.
Hay un factor adicional incluido en la puntuación de maldad: a los procesos root se les da un 3% de memoria extra sobre otras tareas.
La cantidad de memoria "permitida" depende del contexto en el que se llamó al OOM-killer. Si se debe a que se ha agotado la memoria asignada al cpuset de la tarea que realiza la asignación, la memoria permitida representa el conjunto de mems asignados a ese cpuset (ver cpuset(7)). Si se debe a que se han agotado los nodos de un mempolicy, la memoria permitida representa el conjunto de nodos del mempolicy. Si se debe a que se ha alcanzado un límite de memoria (o límite de swap), la memoria permitida es ese límite configurado. Finalmente, si se debe a que todo el sistema se ha quedado sin memoria, la memoria permitida representa todos los recursos asignables.
El valor de oom_score_adj se suma a la puntuación de maldad antes de utilizarse para determinar qué tarea eliminar. Los valores aceptables van de -1000 (OOM_SCORE_ADJ_MIN) a +1000 (OOM_SCORE_ADJ_MAX). Esto permite que el espacio de usuario controle la preferencia para la eliminación por OOM, desde preferir siempre una tarea específica hasta deshabilitarla por completo de la eliminación por OOM. El valor más bajo posible, -1000, es equivalente a deshabilitar la eliminación por OOM por completo para esa tarea, ya que siempre reportará una puntuación de maldad de 0.
En consecuencia, es muy sencillo para el espacio de usuario definir la cantidad de memoria a considerar para cada tarea. Establecer un valor de oom_score_adj de +500, por ejemplo, es aproximadamente equivalente a permitir que el resto de las tareas que comparten el mismo sistema, cpuset, mempolicy o recursos del controlador de memoria utilicen un 50% más de memoria. Un valor de -500, por otro lado, sería aproximadamente equivalente a descontar el 50% de la memoria permitida de la tarea para que no se tenga en cuenta en la puntuación contra la tarea.
Por compatibilidad con kernels anteriores, /proc/pid/oom_adj todavía se puede usar para ajustar la puntuación de maldad. Su valor se escala linealmente con oom_score_adj.
Escribir en /proc/pid/oom_score_adj o /proc/pid/oom_adj cambiará el otro con su valor escalado.
El programa choom(1) proporciona una interfaz de línea de comandos para ajustar el valor de oom_score_adj de un proceso en ejecución o de un comando ejecutado recientemente.

HISTORIA

/proc/pid/oom_adj (desde Linux 2.6.11)
Este archivo se puede usar para ajustar la puntuación utilizada para seleccionar qué proceso debe ser eliminado en una situación de falta de memoria (OOM). El kernel utiliza este valor para una operación de desplazamiento de bits del valor oom_score del proceso: los valores válidos están en el rango de -16 a +15, más el valor especial -17, que deshabilita la eliminación por OOM por completo para este proceso. Una puntuación positiva aumenta la probabilidad de que este proceso sea eliminado por el OOM-killer; una puntuación negativa disminuye la probabilidad.
El valor predeterminado para este archivo es 0; un nuevo proceso hereda la configuración oom_adj de su padre. Un proceso debe tener privilegios (CAP_SYS_RESOURCE) para actualizar este archivo, aunque un proceso siempre puede aumentar su propia configuración de oom_adj (desde Linux 2.6.20).
Desde Linux 2.6.36, el uso de este archivo está obsoleto en favor de /proc/pid/oom_score_adj, y finalmente eliminado en Linux 3.7.
