PROVE(1perl) Guía de referencia del programador de Perl PROVE(1perl)

NOMBRE

prove - Ejecuta pruebas a través de un sistema de pruebas TAP.

USO

prove [opciones] [archivos o directorios]

OPCIONES

Opciones booleanas:

-v,  --verbose         Imprime todas las líneas de prueba. También establece TEST_VERBOSE
-l,  --lib             Añade 'lib' a la ruta para tus pruebas (-Ilib).
-b,  --blib            Añade 'blib/lib' y 'blib/arch' a la ruta para
                       tus pruebas
-s,  --shuffle         Ejecuta las pruebas en orden aleatorio.
-c,  --color           Salida de prueba con colores (por defecto).
     --nocolor         No usar colores en la salida de prueba.
     --count           Muestra el contador de pruebas X/Y cuando no está en modo verbose
                       (por defecto)
     --nocount         Desactiva el contador de pruebas X/Y.
-D   --dry             Ejecución de prueba (en seco). Muestra las pruebas que se habrían ejecutado.
-f,  --failures        Muestra las pruebas fallidas.
-o,  --comments        Muestra comentarios.
     --ignore-exit     Ignora el estado de salida de los scripts de prueba.
-m,  --merge           Fusiona el STDERR de los scripts de prueba con su STDOUT.
-r,  --recurse         Desciende recursivamente en los directorios.
     --reverse         Ejecuta las pruebas en orden inverso.
-q,  --quiet           Suprime parte de la salida de prueba mientras se ejecutan las pruebas.
-Q,  --QUIET           Solo imprime los resultados del resumen.
-p,  --parse           Muestra la lista completa de errores de análisis TAP, si los hay.
     --directives      Solo muestra resultados con directivas TODO o SKIP.
     --timer           Imprime el tiempo transcurrido después de cada prueba.
     --trap            Captura Ctrl-C e imprime el resumen al interrumpir.
     --normalize       Normaliza la salida TAP en la salida verbose
-T                     Habilita las comprobaciones de "tainting".
-t                     Habilita las advertencias de "tainting".
-W                     Habilita las advertencias fatales.
-w                     Habilita las advertencias.
-h,  --help            Muestra esta ayuda
-?,                    Muestra esta ayuda
-V,  --version         Muestra la versión
-H,  --man             Página de manual más larga para prove
     --norc            No procesa el archivo .proverc por defecto

Opciones que toman argumentos:

-I                     Rutas de bibliotecas a incluir.
-P                     Carga un plugin (busca App::Prove::Plugin::*).
-M                     Carga un módulo.
-e,  --exec            Intérprete para ejecutar las pruebas ('' para pruebas compiladas).
     --ext             Establece la extensión para las pruebas (por defecto '.t')
     --harness         Define el sistema de pruebas a utilizar. Ver TAP::Harness.
     --formatter       Formateador de resultados a utilizar. Ver FORMATTERS.
     --source          Carga y/o configura un SourceHandler. Ver SOURCE HANDLERS.
-a,  --archive out.tgz Almacena el TAP resultante en un archivo.
-j,  --jobs N          Ejecuta N trabajos de prueba en paralelo (prueba 9).
     --state=opts      Controla el estado persistente de prove.
     --statefile=file  Usa `file` en lugar de `.prove` para el estado
     --rc=rcfile       Procesa opciones desde rcfile
     --rules           Reglas para el procesamiento paralelo vs secuencial.

NOTAS

.proverc

Si existen ~/.proverc o ./.proverc, se leerán y se procesarán las opciones que contengan antes que las opciones de la línea de comandos. Las opciones en .proverc se especifican de la misma manera que las opciones de la línea de comandos:

# .proverc
--state=hot,fast,save
-j9

Se pueden especificar archivos de opciones adicionales con la opción "--rc". El procesamiento del archivo de opciones por defecto se deshabilita con la opción "--norc".

En Windows y VMS, el archivo de opciones se llama _proverc en lugar de .proverc y solo se busca en el directorio actual.

Lectura desde "STDIN"

Si tienes una lista de pruebas (o URLs, o cualquier otra cosa que quieras probar) en un archivo, puedes añadirlas a tus pruebas usando un '-':

prove - < mi_lista_de_cosas_a_probar.txt

Ver el archivo "README" en el directorio "examples" de esta distribución.

Directorio de Pruebas por Defecto

Si no se proporcionan archivos ni directorios, "prove" busca todos los archivos que coincidan con el patrón "t/*.t".

Salida de Pruebas con Colores

La salida de pruebas con colores usando TAP::Formatter::Color es la opción por defecto, pero si la salida no es a una terminal, el color se deshabilita. Puedes anular esto añadiendo el interruptor "--color".

El soporte de color requiere Term::ANSIColor y, en plataformas Windows, también Win32::Console::ANSI. Si los módulos necesarios no están instalados, la salida con colores no estará disponible.

Código de Salida

Si las pruebas fallan, "prove" saldrá con un estado distinto de cero.

Argumentos a las Pruebas

Es posible pasar argumentos a las pruebas. Para hacerlo, sepáralos de los argumentos de prove con el símbolo de arroba, '::'. Por ejemplo:

prove -v t/mytest.t :: --url http://example.com

esto ejecutará t/mytest.t con las opciones '--url http://example.com'. Cuando se ejecuten múltiples pruebas, cada una recibirá los mismos argumentos.

"--exec"

Normalmente, puedes simplemente pasar una lista de pruebas de Perl y el sistema de pruebas sabrá cómo ejecutarlas. Sin embargo, si tus pruebas no están escritas en Perl o si quieres que todas las pruebas se invoquen exactamente de la misma manera, usa el interruptor "-e" o "--exec":

prove --exec '/usr/bin/ruby -w' t/
prove --exec '/usr/bin/perl -Tw -mstrict -Ilib' t/
prove --exec '/path/to/my/customer/exec'

"--merge"

Si necesitas asegurarte de que tus diagnósticos se muestren en el orden correcto en relación con los resultados de las pruebas, puedes usar la opción "--merge" para fusionar el STDERR de los scripts de prueba en su STDOUT.

Esto garantiza que STDOUT (donde aparecen los resultados de las pruebas) y STDERR (donde aparecen los diagnósticos) se mantendrán sincronizados. El sistema de pruebas mostrará cualquier diagnóstico que tus pruebas emitan en STDERR.

Advertencia: esto es un poco un parche. En particular, ten en cuenta que si algo que aparece en STDERR parece un resultado de prueba, el sistema de pruebas se confundirá. Usa esta opción solo si entiendes las consecuencias y puedes vivir con el riesgo.

"--trap"

La opción "--trap" intentará capturar SIGINT (Ctrl-C) durante la ejecución de una prueba e imprimir el resumen de pruebas incluso si la ejecución se interrumpe.

"--state"

Puedes pedir a "prove" que recuerde el estado de ejecuciones de pruebas anteriores y que seleccione y/o ordene las pruebas a ejecutar basándose en ese estado guardado.

El interruptor "--state" requiere un argumento que debe ser una lista separada por comas de una o más de las siguientes opciones.

"last"
Ejecuta las mismas pruebas que la última vez que se guardó el estado. Esto hace posible, por ejemplo, recrear el orden de una prueba mezclada. 
# Ejecuta todas las pruebas en orden aleatorio
$ prove -b --state=save --shuffle
# Ejecútalas de nuevo en el mismo orden
$ prove -b --state=last
"failed"
Ejecuta solo las pruebas que fallaron en la última ejecución. 
# Ejecuta todas las pruebas
$ prove -b --state=save
# Ejecuta las fallidas
$ prove -b --state=failed

Si también especificas la opción "save", las pruebas que pasen de nuevo se excluirán de ejecuciones posteriores.

# Repite hasta que no haya más fallos
$ prove -b --state=failed,save
"passed"
Ejecuta solo las pruebas que pasaron la última vez. Útil para asegurarse de que no se han introducido nuevos problemas.

prove(1perl) — Arch Linux man pages

NAME

prove - run tests in a distribution

USAGE

prove [options] [files ...]

prove [options] --exec <command> [command options ...]

OPTIONS

Options are specified on the command line, and may be specified more than once. Some options are also supported by TAP::Harness directly.

--all
Run all tests. By default, prove only runs tests that have failed previously, or that are new. This option overrides that default.
--base
Do not run any tests that have failed previously, or that are new. This option is useful for running only the tests that passed last time.
--burst
Run all tests, one after another, without regard to previous results. This is equivalent to:
prove --all --state=all --state=new --state=failed
--exec
Execute the specified command and treat its standard output as TAP. This is useful for running tests written in languages other than Perl.
--help
Display help message and exit.
--jobs=N
Run at most N tests in parallel. Defaults to 4. A value of 1 means no parallelism.
--lib=DIR
Add DIR to Perl's library search path (@INC). This option can be specified multiple times.
--man
Display the man page for prove and exit.
--manpath
Display the man path for prove and exit.
--no-summary
Do not display the summary of tests run.
--only=REGEX
Only run tests whose filenames match the regular expression REGEX.
--parseable
Output in a machine-parseable format.
--recurse
Recurse into subdirectories when searching for tests.
--rule
See --rules.
--state=STATE
Specify which tests to run. STATE can be one of the following:
"all"
Run all tests. This is the default if no other state is specified.
"failed"
Run all tests that failed on the last run. By default, these are run first.
"new"
Run all tests that have not been run before.
"save"
Save the state of the tests after they have been run. This is necessary for the "failed", "hot", and "new" states to work on subsequent runs.
"hot"
Run tests in order of most recent failure. Tests that have never failed will not be selected.
"todo"
Run tests that have been marked as TODO.
"slow"
Run tests in order from slowest to fastest.
"fast"
Run tests in order from fastest to slowest.
"new"
Run tests in order of newest to oldest based on modification times.
"old"
Run tests in order of oldest to newest.
"fresh"
Run tests that have been modified since the last test run.
"save"
Save the state on exit. The state is stored in a file called .prove (_prove on Windows and VMS) in the current directory.

The "--state" switch may be used more than once.

$ prove -b --state=hot --state=all,save

--rules

The "--rules" option is used to control which tests are run sequentially and which are run in parallel, if the "--jobs" option is specified. The option may be specified multiple times, and the order matters.

The most practical use is likely to specify that some tests are not "parallel-ready". Since mentioning a file with --rules doesn't cause it to be selected to run as a test, you can "set and forget" some rules preferences in your .proverc file. Then you'll be able to take maximum advantage of the performance benefits of parallel testing, while some exceptions are still run in parallel.

--rules examples

# All tests are allowed to run in parallel, except those starting with "p"
--rules='seq=t/p*.t' --rules='par=**'
# All tests must run in sequence except those starting with "p", which should be run parallel
--rules='par=t/p*.t'

--rules resolution

  • By default, all tests are eligible to be run in parallel. Specifying any of your own rules removes this one.
  • "First match wins". The first rule that matches a test will be the one that applies.
  • Any test which does not match a rule will be run in sequence at the end of the run.
  • The existence of a rule does not imply selecting a test. You must still specify the tests to run.
  • Specifying a rule to allow tests to run in parallel does not make them run in parallel. You still need specify the number of parallel "jobs" in your Harness object.

--rules Glob-style pattern matching

We implement our own glob-style pattern matching for --rules. Here are the supported patterns:

** is any number of characters, including /, within a pathname
* is zero or more characters within a filename/directory name
? is exactly one character within a filename/directory name
{foo,bar,baz} is any of foo, bar or baz.
\ is an escape character

More advanced specifications for parallel vs sequence run rules

If you need more advanced management of what runs in parallel vs in sequence, see the associated 'rules' documentation in TAP::Harness and TAP::Parser::Scheduler. If what's possible directly through "prove" is not sufficient, you can write your own harness to access these features directly.

@INC

prove introduces a separation between "options passed to the perl which runs prove" and "options passed to the perl which runs tests"; this distinction is by design. Thus the perl which is running a test starts with the default @INC. Additional library directories can be added via the "PERL5LIB" environment variable, via -Ifoo in "PERL5OPT" or via the "-Ilib" option to prove.

Taint Mode

Normally when a Perl program is run in taint mode the contents of the "PERL5LIB" environment variable do not appear in @INC.

Because "PERL5LIB" is often used during testing to add build directories to @INC prove passes the names of any directories found in "PERL5LIB" as -I switches. The net effect of this is that "PERL5LIB" is honoured even when prove is run in taint mode.

FORMATTERS

You can load a custom TAP::Parser::Formatter:

prove --formatter MyFormatter

SOURCE HANDLERS

You can load custom TAP::Parser::SourceHandlers, to change the way the parser interprets particular sources of TAP.

prove --source MyHandler --source YetAnother t

If you want to provide config to the source you can use:

prove --source MyCustom \
      --source Perl --perl-option 'foo=bar baz' --perl-option avg=0.278 \
      --source File --file-option extensions=.txt --file-option extensions=.tmp t
      --source pgTAP --pgtap-option pset=format=html --pgtap-option pset=border=2

Each "--$source-option" option must specify a key/value pair separated by an "=". If an option can take multiple values, just specify it multiple times, as with the "extensions=" examples above. If the option should be a hash reference, specify the value as a second pair separated by a "=", as in the "pset=" examples above (escape "=" with a backslash).

All "--sources" are combined into a hash, and passed to "new" in TAP::Harness's "sources" parameter.

See TAP::Parser::IteratorFactory for more details on how configuration is passed to SourceHandlers.

PLUGINS

Plugins can be loaded using the "-Pplugin" syntax, eg:

prove -PMyPlugin

This will search for a module named "App::Prove::Plugin::MyPlugin", or failing that, "MyPlugin". If the plugin can't be found, "prove" will complain & exit.

You can pass arguments to your plugin by appending "=arg1,arg2,etc" to the plugin name:

prove -PMyPlugin=fou,du,fafa

Please check individual plugin documentation for more details.

Available Plugins

For an up-to-date list of plugins available, please check CPAN:

https://metacpan.org/search?q=App%3A%3AProve+Plugin

Writing Plugins

Please see "PLUGINS" in App::Prove.
