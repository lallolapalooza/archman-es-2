readv(2) Manual de llamadas al sistema readv(2)

NOMBRE

readv, writev, preadv, pwritev, preadv2, pwritev2 - leer o escribir datos en múltiples buffers

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/uio.h>
ssize_t readv(int fd, const struct iovec *iov, int iovcnt);
ssize_t writev(int fd, const struct iovec *iov, int iovcnt);
ssize_t preadv(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t pwritev(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t preadv2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);
ssize_t pwritev2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);

DESCRIPCIÓN

La llamada al sistema readv() lee iovcnt buffers del archivo asociado al descriptor de archivo fd en los buffers descritos por iov ("entrada dispersa").

La llamada al sistema writev() escribe iovcnt buffers de datos descritos por iov en el archivo asociado al descriptor de archivo fd ("salida agrupada").

El puntero iov apunta a un array de estructuras iovec, descritas en iovec(3type).

La llamada al sistema readv() funciona igual que read(2) excepto que se llenan múltiples buffers.

La llamada al sistema writev() funciona igual que write(2) excepto que se escriben múltiples buffers.

Los buffers se procesan en orden de array. Esto significa que readv() llena completamente iov[0] antes de proceder a iov[1], y así sucesivamente. (Si hay datos insuficientes, es posible que no se llenen todos los buffers apuntados por iov.) De manera similar, writev() escribe el contenido completo de iov[0] antes de proceder a iov[1], y así sucesivamente.

Las transferencias de datos realizadas por readv() y writev() son atómicas: los datos escritos por writev() se escriben como un único bloque que no se mezcla con la salida de escrituras en otros procesos; análogamente, se garantiza que readv() lee un bloque contiguo de datos del archivo, independientemente de las operaciones de lectura realizadas en otros hilos o procesos que tengan descriptores de archivo que se refieran a la misma descripción de archivo abierta (ver open(2)).

preadv() y pwritev()

La llamada al sistema preadv() combina la funcionalidad de readv() y pread(2). Realiza la misma tarea que readv(), pero añade un cuarto argumento, offset, que especifica el desplazamiento del archivo en el que se realizará la operación de entrada.

La llamada al sistema pwritev() combina la funcionalidad de writev() y pwrite(2). Realiza la misma tarea que writev(), pero añade un cuarto argumento, offset, que especifica el desplazamiento del archivo en el que se realizará la operación de salida.

El desplazamiento del archivo no se modifica por estas llamadas al sistema. El archivo al que se refiere fd debe ser capaz de buscar.

preadv2() y pwritev2()

Estas llamadas al sistema son similares a las llamadas preadv() y pwritev(), pero añaden un quinto argumento, flags, que modifica el comportamiento por llamada.

A diferencia de preadv() y pwritev(), si el argumento offset es -1, se utiliza y actualiza el desplazamiento de archivo actual.

El argumento flags contiene un OR a nivel de bits de cero o más de las siguientes banderas:

RWF_DSYNC (desde Linux 4.7)
Proporciona un equivalente por escritura del flag O_DSYNC de open(2). Este flag solo es significativo para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema.
RWF_HIPRI (desde Linux 4.6)
Lectura/escritura de alta prioridad. Permite a los sistemas de archivos basados en bloques utilizar sondeos del dispositivo, lo que proporciona una latencia menor, pero puede usar recursos adicionales. (Actualmente, esta característica solo es utilizable en un descriptor de archivo abierto utilizando el flag O_DIRECT).
RWF_SYNC (desde Linux 4.7)
Proporciona un equivalente por escritura del flag O_SYNC de open(2). Este flag solo es significativo para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema.
RWF_NOWAIT (desde Linux 4.14)
No esperar datos que no están disponibles inmediatamente. Si se especifica este flag, la llamada al sistema preadv2() retornará instantáneamente si tuviera que leer datos del almacenamiento subyacente o esperar un bloqueo. Si se leyeron algunos datos, retornará el número de bytes leídos. Si no se leyeron bytes, retornará -1 y establecerá errno a EAGAIN (pero ver BUGS). Actualmente, este flag solo es significativo para preadv2().
RWF_APPEND (desde Linux 4.16)
Proporciona un equivalente por escritura del flag O_APPEND de open(2). Este flag solo es significativo para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema. El argumento offset no afecta la operación de escritura; los datos siempre se añaden al final del archivo. Sin embargo, si el argumento offset es -1, se actualiza el desplazamiento actual del archivo.
RWF_NOAPPEND (desde Linux 6.9)
No honrar el flag O_APPEND de open(2). Este flag solo es significativo para pwritev2(). Históricamente, Linux honraba el flag O_APPEND si estaba establecido e ignoraba el argumento offset, lo que es un error. Para pwritev2(), se honra el argumento offset como se espera si el flag RWF_NOAPPEND está establecido, lo mismo que si el flag O_APPEND no estuviera establecido.
RWF_ATOMIC (desde Linux 6.11)
Requiere que las escrituras en archivos regulares en sistemas de archivos basados en bloques se emitan con protección contra escrituras rotas. La protección contra escrituras rotas significa que para una falla de energía o cualquier otra falla de hardware, se almacenarán todos los datos de la escritura o ninguno, pero nunca una mezcla de datos viejos y nuevos. Este flag solo es significativo para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema. La longitud total de escritura debe ser una potencia de 2 y debe tener un tamaño dentro del rango [stx_atomic_write_unit_min, stx_atomic_write_unit_max]. La escritura debe estar en un desplazamiento naturalmente alineado dentro del archivo con respecto a la longitud total de la escritura. Por ejemplo, se permite una escritura de 32KiB en un desplazamiento de archivo de 32KiB, sin embargo, una escritura de 32KiB en un desplazamiento de archivo de 48KiB no está permitida. El límite superior de iovcnt para pwritev2() se da por el valor en stx_atomic_write_segments_max. La protección contra escrituras rotas solo funciona con el flag O_DIRECT, es decir, las escrituras en búfer no son compatibles. Para garantizar la consistencia de la escritura entre el estado en memoria del archivo y el dispositivo de almacenamiento, se debe especificar O_SYNC o O_DSYNC para open(2). Las mismas garantías de E/S sincronizada descritas en open(2) se proporcionan cuando se utilizan estos flags o sus flags y llamadas al sistema equivalentes (por ejemplo, si se especifica RWF_SYNC para pwritev2()).
RWF_DONTCACHE (desde Linux 6.14)

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven el número total de bytes escritos o leídos en todos los buffers. En caso de error, devuelven -1 y establecen errno para indicar el error.

El valor de retorno puede ser menor que el número total de bytes solicitados si se alcanzó el final del archivo durante la lectura, o si se escribió menos de lo solicitado y la llamada al sistema no pudo esperar a que se pudiera escribir más.

Para readv() y preadv(), si el descriptor de archivo fd hace referencia a un archivo normal, y se leen cero bytes porque se alcanzó el final del archivo, se devuelve 0.

Para writev() y pwritev(), si fd hace referencia a un archivo normal, se garantiza que la escritura sea atómica si la longitud total de la escritura es menor o igual al valor de {PIPE_BUF} (consulte limits.h(3)). Si la longitud de la escritura excede {PIPE_BUF}, es posible que las escrituras no sean atómicas y que se mezclen con las escrituras de otros procesos.

ERRORES

Se pueden encontrar errores adicionales para las versiones posix (es decir, sin el argumento flags) en las páginas del manual de read(2) y write(2). Para los detalles, consulte las descripciones de read(2), write(2), pread(2), y pwrite(2).

Además, las llamadas de E/S dispersa/agrupada pueden fallar con los siguientes errores:

EBADF
El descriptor de archivo fd no es válido.
EFAULT
La dirección especificada por iov o uno de los buffers de la estructura iovec está fuera del espacio de direcciones accesible.
EINTR
La llamada fue interrumpida por una señal antes de que se hubieran escrito o leído datos.
EINVAL
iovcnt es menor o igual a 0, o iovcnt es mayor que {IOV_MAX}. O offset es negativo (para preadv() y pwritev() si el flag RWF_APPEND no está establecido).
ENOMEM
No hay suficiente memoria disponible en el kernel.
ENOTSUP
El descriptor de archivo fd está asociado con un tipo de archivo que no soporta E/S dispersa/agrupada.
EPIPE
fd hace referencia a una tubería o FIFO, y se intenta escribir en él, pero el otro extremo ha sido cerrado.

Para preadv2() y pwritev2(), se pueden producir errores adicionales si se utilizan flags inválidos o si el sistema no soporta las operaciones solicitadas.

En particular, si se especifica RWF_NOWAIT y la operación tendría que esperar, la llamada retorna -1 y errno se establece en EAGAIN (incluso si la llamada al sistema leyó algunos datos).

CONFORME A

readv(), writev(), preadv(), pwritev() conforman a POSIX.1-2001, POSIX.1-2008.

preadv2() y pwritev2() son específicos de Linux.

eads o escribe en un archivo regular podará el contenido de la página de caché instanciada cuando la operación se complete. Esto es diferente de la E/S normal en búfer, donde los datos generalmente permanecen en la caché hasta que se recuperan debido a la presión de la memoria. Si los rangos de la E/S de lectura o escritura ya estaban en la caché antes de esta lectura o escritura, esos rangos no se podarán en el momento de la finalización de la E/S.
Además, cualquier rango ensucianado por una operación de escritura con RWF_DONTCACHE establecido se enviará para escritura. Esto es similar a llamar a sync_file_range(2) con SYNC_FILE_RANGE_WRITE para iniciar la escritura en el rango dado. RWF_DONTCACHE es una pista, o mejor esfuerzo, donde no se dan garantías duras sobre el estado de la caché de páginas una vez que la operación se completa.
Si se utiliza en un sistema de archivos o dispositivo de bloques que no lo soporta, devolverá -1 y errno se establecerá en EOPNOTSUPP.

VALOR DE RETORNO

En caso de éxito, readv(), preadv() y preadv2() devuelven el número de bytes leídos; writev(), pwritev() y pwritev2() devuelven el número de bytes escritos.

Tenga en cuenta que no es un error que una llamada exitosa transfiera menos bytes de los solicitados (consulte read(2) y write(2)).

En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

Los errores son los dados para read(2) y write(2). Además, preadv(), preadv2(), pwritev() y pwritev2() también pueden fallar por las mismas razones que lseek(2). Además, se definen los siguientes errores:

EINVAL
La suma de los valores iov_len desborda un valor ssize_t.
EINVAL
Si se especifica RWF_ATOMIC, la combinación de la suma de los valores iov_len y el valor offset no cumple con las reglas de protección contra escrituras rotas de longitud y desplazamiento.
EINVAL
El recuento del vector, iovcnt, es menor que cero o mayor que el máximo permitido. Si se especifica RWF_ATOMIC, este máximo lo proporciona el valor stx_atomic_write_segments_max de statx.
EOPNOTSUPP
Se estableció RWF_DONTCACHE en flags y el archivo no lo soporta.
EOPNOTSUPP
Se especifica una bandera desconocida en flags.

VERSIONES

Diferencias biblioteca C/kernel

Las llamadas de sistema crudas preadv() y pwritev() tienen firmas de llamada que difieren ligeramente de las de las funciones envoltorio correspondientes de la biblioteca C de GNU que se muestran en la SINOPSIS. El argumento final, offset, se desempaqueta por las funciones envoltorio en dos argumentos en las llamadas al sistema:

unsigned long pos_l, unsigned long pos

Estos argumentos contienen, respectivamente, los 32 bits de orden bajo y de orden alto de offset.

Diferencias históricas biblioteca C/kernel

Para hacer frente al hecho de que IOV_MAX era tan bajo en las primeras versiones de Linux, las funciones envoltorio de glibc para readv() y writev() hicieron un trabajo adicional si detectaban que la llamada al sistema subyacente fallaba porque se excedía este límite. En el caso de readv(), la función envoltorio asignó un búfer temporal suficientemente grande para todos los elementos especificados por iov, pasó ese búfer en una llamada a read(2), copió datos del búfer a las ubicaciones especificadas por los campos iov_base de los elementos de iov, y luego liberó el búfer. La función envoltorio para writev() realizó la tarea análoga utilizando un búfer temporal y una llamada a write(2).

La necesidad de este esfuerzo adicional en las funciones envoltorio de glibc desapareció con Linux 2.2 y posteriores. Sin embargo, glibc continuó proporcionando este comportamiento hasta glibc 2.10. A partir de glibc 2.9, las funciones envoltorio solo proporcionan este comportamiento si la biblioteca detecta que el sistema está ejecutando un kernel de Linux anterior a Linux 2.6.18 (una versión de kernel seleccionada arbitrariamente). Y desde glibc 2.20 (que requiere un mínimo de Linux 2.6.32), las funciones envoltorio de glibc siempre invocan directamente las llamadas al sistema.

NOTAS

POSIX.1 permite a una implementación establecer un límite en el número de elementos que se pueden pasar en iov. Una implementación puede anunciar su límite definiendo IOV_MAX en <limits.h> o en tiempo de ejecución a través del valor de retorno de sysconf(_SC_IOV_MAX). En los sistemas Linux modernos, el límite es 1024. En los días de Linux 2.0, este límite era 16.

ERRORES DE PROGRAMACIÓN

Linux 5.9 y Linux 5.10 tienen un error donde preadv2() con la bandera RWF_NOWAIT puede devolver 0 incluso cuando no está al final del archivo.

EJEMPLOS

El siguiente ejemplo de código demuestra el uso de writev():


char          *str0 = "hello ";
char          *str1 = "world\n";
ssize_t       nwritten;
struct iovec  iov[2];
iov[0].iov_base = str0;
iov[0].iov_len = strlen(str0);
iov[1].iov_base = str1;
iov[1].iov_len = strlen(str1);
nwritten = writev(STDOUT_FILENO, iov, 2);
