FBB::Process(3bobcat) Ejecución de procesos hijos FBB::Process(3bobcat)

NOMBRE

FBB::Process - Ejecuta programas externos

SINOPSIS

#include <bobcat/process>
Opción de enlace: -lbobcat

DESCRIPCIÓN

La clase FBB::Process ofrece una interfaz extensa para llamar programas y/o scripts externos desde un programa C++ (los llamados procesos hijos). La clase ofrece una interfaz fácil de usar, basada en flujos, para los flujos de entrada estándar, salida estándar y error estándar de los procesos hijos.

Los objetos de la clase Process utilizan funciones estándar de ejecución de procesos, como miembros de la familia execl(2) o sh(1) para ejecutar procesos hijos. Por lo tanto, los procesos hijos pueden ser programas ejecutables o scripts de shell.

Los flujos de entrada estándar, salida y error de los procesos hijos pueden ser accedidos a través de sus objetos padre Process. La entrada esperada por los procesos hijos puede ser insertada por objetos Process, y la salida generada por los procesos hijos puede ser extraída de los objetos Process.

Al usar redirección (de salida) con la especificación de ruta USE_SHELL (ver abajo para las especificaciones de ruta y modo de E/S), normalmente se debe especificar el modo de E/S IGNORE_COUT (y posiblemente también IGNORE_CERR).

Los objetos Process pueden usarse repetidamente para ejecutar los mismos u otros procesos hijos. Antes de que se inicie el siguiente proceso hijo, el objeto Process primero termina su proceso hijo actualmente activo. Alternativamente, un proceso hijo actualmente activo se termina automáticamente si el objeto Process sale del ámbito, si se llama a su miembro stop o eoi (end-of-information), o si el manipulador eoi se inserta en el objeto Process.

Los programas llamados como procesos hijos pueden especificarse al construir un objeto Process o usando el miembro setCommand de Process. Los constructores de Process (o los miembros set de Process) nunca inician procesos hijos. Los procesos hijos se inician a través de los miembros start o el operador de asignación.

Los procesos hijos pueden recibir información en sus flujos de entrada estándar a través de la información insertada en los objetos Process. En estos casos, los objetos Process deben informar a sus procesos hijos que han recibido toda la entrada. Para esto se puede usar el miembro close o eoi, o el manipulador eoi. Después de llamar al miembro close, también se debe llamar al miembro waitForChild. Esto no es necesario si se usa el miembro eoi o el manipulador eoi.

Si no se llama a waitForChild (pero se enviaron datos al hijo que el proceso hijo no pudo procesar completamente en caso de que el proceso hijo terminara como resultado de que el objeto Process saliera del ámbito), el sistema operativo emite un mensaje de Tubería rota, indicando que se perdió información en una tubería.

Los argumentos pasados a los procesos hijos pueden estar rodeados por comillas dobles o simples. Los argumentos rodeados por comillas dobles tienen sus comillas eliminadas, mientras se interpretan las secuencias de escape que pudieran haberse utilizado dentro. Los argumentos rodeados por comillas simples tienen sus comillas eliminadas, mientras se acepta su contenido tal cual. Además, se pueden especificar secuencias de escape sin comillas: esas secuencias de escape se evalúan y se reemplazan por sus caracteres intencionados (por ejemplo, \100 se convierte en @).

Una especificación completa del comando puede estar rodeada por comillas invertidas (caracteres `). Estas comillas invertidas son eliminadas por el objeto Process cuando se inicia el comando.

A los procesos hijos se les puede permitir una cantidad limitada de tiempo (en segundos) para completarse. Por defecto, no se impone ningún límite de tiempo a los procesos hijos.

Por defecto, los flujos de entrada estándar, salida y error de los procesos hijos se acceden a través de sus procesos padre Process: la información insertada en el objeto Process se reenvía al flujo de entrada estándar del proceso hijo, la información enviada por el proceso hijo a su flujo de salida estándar puede ser extraída del objeto Process padre, y la información enviada por el proceso hijo a su flujo de error estándar puede obtenerse a través del miembro childErrStream de Process.

Si el proceso padre y el hijo han acordado algún proceso de comunicación, entonces la información puede ser enviada y recibida alternativamente del hijo a través de las facilidades de ostream e istream de Process. Alternativamente, cantidades no especificadas de información escrita por procesos hijos pueden ser procesadas por hilos separados (ver la sección EJEMPLOS de esta página del manual).

Los objetos Process utilizan objetos Pipe (ver pipe(3bobcat)) para la comunicación con sus procesos hijos. Para asegurar que estas tuberías se cierren correctamente, se deben usar los miembros waitForChild, stop o el manipulador eoi. Una vez que un objeto Process deja de existir, las tuberías a su proceso hijo también se cierran.

ENUMERACIONES

enum ProcessType:

El enum ProcessType define cómo se inicia o localiza un proceso hijo. Sus valores se especifican en el momento de la construcción o a través del miembro setProcessType. Esta enumeración define las siguientes constantes simbólicas:

o
NO_PATH:
El programa especificado como proceso hijo se inicia tal como se especifica, sin buscar en los elementos de la variable de entorno PATH.
o
USE_PATH:
Los elementos de la variable de entorno PATH se utilizan al localizar el programa especificado como proceso hijo.
o
USE_SHELL:
El programa especificado como proceso hijo se llama usando /bin/sh -c. Cuando se utiliza redirección (de salida) con el comando especificado, se debe especificar el modo de E/S IGNORE_COUT (y posiblemente también el modo de E/S IGNORE_CERR).

enum IOMode:

Los valores del enum IOMode se utilizan para definir cuáles de los flujos estándar del proceso hijo pueden ser accedidos a través del objeto Process. Sus constantes simbólicas pueden combinarse usando el operador bit_or. Por defecto se usa CIN | COUT | CERR (ver abajo).

Las siguientes constantes simbólicas están disponibles:

o
ALL:
Atajo para CIN | COUT | CERR.
o
CIN:
La información insertada en el objeto Process se reenvía a su proceso hijo. Si esto no es necesario, entonces no se debe especificar CIN.
o
CERR:
La información escrita por el proceso hijo a su flujo de error estándar es accesible a través del miembro childErrStream de Process. Si esto no es necesario, entonces no se debe especificar CERR.
o
COUT:
La información escrita por el proceso hijo a su flujo de salida estándar puede ser extraída directamente del objeto Process, o de su miembro childOutStream. Si esto no es necesario, entonces no se debe especificar COUT.
o
DIRECT:
Al iniciar un proceso hijo (ver abajo en el miembro start) el proceso actual (es decir, el programa que define el objeto Process) es reemplazado por el proceso hijo, heredando los flujos de entrada y salida estándar del proceso actual. Si este modo se especifica en

combinación con cualquier otro IOMode (excepto NONE, ver abajo) se lanza una excepción std::invalid_argument.
o
IGNORE_CERR:
La información escrita por el proceso hijo en su flujo de error estándar se envía a /dev/null. Se lanza una excepción std::invalid_argument si este modo se especifica en combinación con DIRECT, CERR y/o MERGE_COUT_CERR.
o
IGNORE_COUT:
La información escrita por el proceso hijo en su flujo de salida estándar se envía a /dev/null. Se lanza una excepción std::invalid_argument si este modo se especifica en combinación con COUT, DIRECT y/o MERGE_COUT_CERR.
o
IGNORE_COUT_CERR:
Atajo para IGNORE_CERR | IGNORE_COUT.
o
MERGE_COUT_CERR:
La información extraída del objeto Process es escrita por el proceso hijo en sus flujos de salida estándar y de error estándar. Se lanza una excepción std::invalid_argument si este modo se especifica en combinación con COUT, CERR, DIRECT, IGNORE_COUT o IGNORE_CERR.
o
NONE:
El objeto Process no extrae ni inserta información en los flujos estándar de su proceso hijo. El proceso hijo lee el mismo flujo de entrada estándar y escribe en los mismos flujos de salida estándar que el objeto Process padre. Cuando este modo se especifica en combinación con otros valores de IOMode, se ignora silenciosamente.

enum ChildOutput:
La enumeración ChildOutput define los valores devueltos por el miembro available (ver abajo) indicando a qué flujo estándar ha escrito información el proceso hijo. Esta enumeración define los siguientes valores:

o
NOTHING_AVAILABLE:
El proceso hijo no ha escrito (todavía) ninguna información en sus flujos estándar;
o
CHILD_COUT:
El proceso hijo escribió información en su flujo de salida estándar que está esperando ser extraída.
o
CHILD_CERR:
El proceso hijo escribió información en su flujo de error estándar que está esperando ser extraída. Los dos últimos valores pueden combinarse usando el operador bit_or. El operador bit_and, que devuelve un valor bool, se puede usar para verificar si hay información disponible en un flujo de salida específico.

PARÁMETROS DEL PROCESO

Se pueden especificar cuatro parámetros de proceso: los tamaños de los búferes de flujo que se utilizan al comunicarse con procesos hijos; para especificar cuáles de los flujos estándar de los procesos hijos se pueden acceder desde el objeto Process, se utilizan combinaciones de valores IOMode; para especificar cómo se encuentran los programas hijos, se utiliza un valor ProcessType; para especificar el tiempo máximo (en segundos) que se permite ejecutar al programa hijo, se utilizan valores size_t.

Por defecto, los búferes de flujo contienen 200 bytes; todos los flujos estándar del hijo (entrada estándar, salida y error) son accesibles desde el proceso Parent; la variable de entorno PATH *no* se utiliza para localizar el programa hijo; y se permitirá un tiempo ilimitado para la ejecución de los procesos hijos.

Después de construir un objeto Process, todos los parámetros predeterminados pueden modificarse. Estos parámetros pueden ser modificados para un solo proceso o se pueden modificar los valores predeterminados generales de un objeto Process. Los miembros set* (ver abajo) se pueden usar para cambiar los parámetros predeterminados del proceso. Cuando se especifican parámetros de otra manera, solo serán activos para el siguiente proceso.

CONSTRUCTORES

El comando proporcionado a los siguientes constructores puede ser la especificación (inicial) de un programa externo a ejecutar. Cuando el programa se inicie finalmente, puede empezar y terminar con una comilla simple invertida (`). Las comillas simples invertidas se eliminarán justo antes de ejecutar el programa especificado.

Los procesos hijos *no* se inician automáticamente después de la construcción de objetos Process. Se utiliza un miembro start o el operador de asignación (ver abajo) para iniciar el proceso hijo especificado.

Los constructores que esperan un argumento IOMode pueden ser provistos con múltiples valores IOMode combinándolos usando el operador bitwise OR.

Después de construir un objeto Process, sus parámetros pueden ser cambiados usando las funciones miembro set, operadores de llamada a función o miembros start.

Los constructores de copia y movimiento (y operadores de asignación) no están disponibles.

OPERADORES SOBRECARGADOS

o
Process &operator<<(Type value):
Este operador inserta value en el flujo de entrada estándar del hijo. Es decir, el proceso hijo lee value de su entrada estándar. Un valor de cualquier tipo que pueda insertarse en un ostream puede insertarse en un objeto Process. No sucede nada si se utiliza el miembro cuando el proceso hijo ha terminado. También se admiten manipuladores como std::endl. El comportamiento de este operador es indefinido a menos que se especificara IOMode CIN.
o
Process &operator>>(Type value):
Este operador extrae value del flujo de salida estándar del hijo y, opcionalmente (si se especificó IOMode MERGE_COUT_CERR), del flujo de error del hijo. Es decir, value puede extraerse de los objetos Process. Un valor de cualquier tipo que pueda extraerse de un istream puede extraerse de un objeto Process. No sucede nada si se utiliza el miembro cuando el proceso hijo ha terminado. El comportamiento de este operador es indefinido a menos que se especificara IOMode COUT o MERGE_COUT_CERR.
o
Process &operator+=(std::string const &):
Este operador agrega el objeto std::string proporcionado a la especificación de comando definida actualmente de un objeto Process. El miembro operator+= no agrega un espacio separador entre la especificación de comando almacenada actualmente y el texto a añadir. Simplemente agrega su cadena del lado derecho al comando almacenado hasta el momento. No afecta a un proceso hijo en ejecución.
o
int operator=(std::string const &cmd):
El miembro operator= define cmd como el comando almacenado en un objeto Process.
Antes de iniciar el proceso hijo, se detiene un proceso hijo posiblemente activo llamando a stop. Devuelve el valor de retorno de stop. Inmediatamente después de llamar a stop, se inicia el nuevo comando (cmd). Si detener y reiniciar otro comando deben ser acciones separadas, use stop, seguido de setCommand, seguido de la llamada a una versión sobrecargada apropiada del miembro start (start() utiliza el IOMode, ProcessType, y límite de tiempo actuales del objeto).
o
Process &operator()(IOMode mode):
Este operador cambia el parámetro IOMode del objeto Process. Se devuelve una referencia al objeto Process, permitiendo construcciones como 
    process(Process::COUT) = "/bin/cat";
para iniciar un nuevo proceso hijo con el IOMode especificado.
o
Process &operator()(IOMode mode, ProcessType type):
Este operador cambia los parámetros de proceso IOMode y ProcessType del objeto Process.

OPERATORS

o
Process &operator()(IOMode mode, ProcessType type, size_t timeLimit):
Este operador modifica los parámetros del proceso del objeto Process mencionados. El tamaño por defecto especificado actualmente de los búferes de flujo se mantiene sin cambios.
o
Process &operator()(IOMode mode, ProcessType type, size_t timeLimit, size_t bufferSize):
Este operador modifica todos los parámetros del proceso del objeto Process.
o
Process &operator|(Process &lhs, Process &rhs):
Este operador implementa la tubería (piping) de procesos: la información enviada por lhs a su salida estándar se convierte en la entrada estándar de rhs. El operador devuelve rhs.
Este operador imita al operador de tubería soportado por la mayoría de los programas de línea de comandos y no debe confundirse con el operador OR a nivel de bits. El operador inicia el proceso hijo de lhs, pero el proceso hijo de rhs (y por lo tanto el procesamiento de la tubería) debe iniciarse explícitamente.
Dado que operator| es asociativo por la izquierda y se devuelve rhs, la tubería puede ser encadenada, permitiendo construcciones como p1 | p2 | p3, donde p1, p2 y p3 son objetos Process.
El siguiente idiom puede ser utilizado para iniciar la ejecución de una cadena de procesos: (p1 | p2 | p3).start(). Alternativamente, se puede usar el siguiente procedimiento de dos pasos: 
    p1 | p2 | p3;
    p3.start();
Si p1 especifica Process::CIN, entonces este IOMode se reenvía al proceso final de la cadena de procesos. No es necesario especificar Process::CIN para p3. De hecho, la mayoría de los flags IOModes de los procesos pasados a operator| son ignorados o modificados. Los IOModes aceptables son Process::IGNORE_CERR y Process::CERR (aceptados para todos los procesos), Process::CIN (aceptado para el primer proceso de la cadena), y Process::COUT (para el último proceso de la cadena).
Nota: al conectar una serie de procesos usando operator|, toda la entrada y salida (excepto los flujos de error estándar) se maneja a través del último proceso: si se especifica Process::CIN para el primer proceso, este modo se transfiere al último proceso, de modo que la información insertada en el último proceso entra en la tubería a través de la entrada estándar del primer proceso.
El siguiente ejemplo ilustra cómo la entrada puede ser insertada en el primer proceso desde un proceso principal y enviada al flujo de salida estándar por el proceso final: 
    using namespace std;
    using namespace FBB;
    Process p1(Process::CIN, "/bin/cat");
    Process p2("/bin/cat");
    Process p3(Process::NONE, "/bin/cat");
    p1 | p2 | p3;
    p3.start();
    p3 << cin.rdbuf() << eoi;
Al unir múltiples comandos usando el operador de tubería (’|’), no se requiere el tipo de proceso USE_SHELL, a pesar de que la tubería de procesos se usa comúnmente como una característica de la shell. El operator| de Process maneja la tubería de E/S por sí mismo, y por lo tanto puede evitar el proceso adicional de la shell.

MIEMBROS

o
bool active():
Este miembro devuelve true si el proceso hijo se está ejecutando actualmente y false si no.
o
size_t available():
Este miembro devuelve inmediatamente. Su valor de retorno indica si se puede obtener alguna información del proceso hijo como valor(es) de la enum ChildOutput. Se devuelve NOTHING_AVAILABLE si no hay información lista para ser extraída. Se devuelve CHILD_COUT si hay información del flujo de salida estándar del proceso hijo; se devuelve CHILD_CERR si hay información del flujo de error estándar del proceso hijo; se devuelve CHILD_COUT | CHILD_CERR si hay información de ambos flujos (salida y error estándar). El operador bit_and, que devuelve un valor bool, puede ser utilizado para determinar qué flujo tiene información pendiente. Por ejemplo, 
    if (process.available() & Process::CHILD_COUT)
        cout << "Process has child standard output available";
o
size_t bufSize() const:
Este miembro devuelve el tamaño por defecto de los búferes de flujo que se usan para la comunicación con los procesos hijos. Si se llama mientras un proceso hijo se está ejecutando, el valor devuelto por este miembro puede diferir del valor que se utilizó realmente al iniciar el proceso hijo, ya que el valor por defecto puede ser alterado por una llamada al operador función justo antes de iniciar el proceso hijo.
o
std::istream &childErrStream():
Si se especificó Process::CERR, este miembro se interconecta con el flujo de error estándar del hijo. Al extraer la información de childErrStream, el proceso padre recupera la información enviada por su proceso hijo a su flujo de error estándar.
o
std::istream &childOutStream():
Si se especificó Process::COUT o Process::MERGE_COUT_CERR, este miembro se interconecta con el flujo de salida estándar del hijo. Al extraer la información de childOutStream, el proceso padre recupera la información enviada por su proceso hijo a su flujo de salida estándar. Alternativamente, esta información puede ser extraída directamente del objeto Process, pero este miembro no requiere el uso de un static_cast para desambiguar el búfer de flujo deseado en sentencias como 
    cout << process.childOutStream().rdbbuf()
o
void close():
Este miembro cierra el flujo de entrada del hijo. En situaciones donde el hijo lee continuamente información de su flujo de entrada estándar, este miembro puede ser utilizado para informar al proceso hijo que la entrada ha terminado. Este miembro solo debe ser utilizado cuando se especificó IOMode CIN para el proceso hijo actualmente en ejecución; de lo contrario, su comportamiento no está definido. Alternativamente, se puede utilizar el miembro eoi o el manipulador.
o
int eoi():
Este miembro cierra el flujo de entrada del hijo, y luego llama a waitForChild para esperar a que el proceso hijo termine. En situaciones donde el hijo lee continuamente información de su flujo de entrada estándar, este miembro puede ser utilizado para informar al proceso hijo que la entrada ha terminado. Este miembro solo debe ser utilizado cuando se especificó IOMode CIN para el proceso hijo actualmente en ejecución; de lo contrario, su comportamiento no está definido. Alternativamente, se puede utilizar el miembro close o el manipulador eoi. Se devuelve el estado de salida del proceso hijo llamado.
o
int exitStatus() const:
Después de llamar a eoi o insertar el manipulador eoi en el objeto Process, este miembro devuelve el estado de salida del proceso hijo. En otros casos, el valor devuelto por exitStatus no está definido, y se debe usar waitForChild.
o
IOMode ioMode() const:
Este miembro devuelve el IOMode por defecto. Si se llama mientras un proceso hijo se está ejecutando, el valor devuelto por este miembro puede diferir del valor que se utilizó realmente al iniciar el proceso hijo, ya que el valor por defecto puede ser alterado por una llamada al operador función justo antes de iniciar el proceso hijo.
o
ProcessType processType() const:
Este miembro devuelve el ProcessType por defecto de los procesos hijos. Si se llama mientras un proceso hijo se está ejecutando, el valor devuelto por este miembro puede diferir del valor que se utilizó realmente al iniciar el proceso hijo, ya que el valor por defecto puede ser alterado por una llamada al operador función justo antes de iniciar el proceso hijo.
o
size_t timeLimit() const:
Este miembro devuelve el límite de tiempo por defecto (en segundos) de los procesos hijos. Un valor de retorno de cero indica que no se aplica ningún límite de tiempo. Si se llama mientras un proceso hijo se está ejecutando, el valor devuelto por este miembro puede diferir del valor que se utilizó realmente al iniciar el proceso hijo, ya que el valor por defecto puede ser alterado por una llamada al operador función justo antes de iniciar el proceso hijo.
o
void setBufSize(size_t bufSize):
Este miembro cambia el tamaño del búfer de flujo por defecto que se utiliza para la comunicación con los procesos hijos. Un tamaño de búfer de cero bytes se cambia silenciosamente a uno. El nuevo valor por defecto se utilizará al iniciar el próximo proceso hijo.
o
void setCommand(std::string const &cmd):
El miembro setCommand redefine (o define por primera vez) la especificación del comando del proceso hijo (o su parte inicial).
Este miembro no inicia realmente el proceso hijo, y operator+= puede ser utilizado para añadir texto adicional a la especificación del comando. Además, este miembro puede ser utilizado cuando un proceso hijo está activo: su uso no afecta a un proceso hijo en ejecución.
o
void setIOMode(iomode mode):
Este miembro cambia el IOMode por defecto. El nuevo valor por defecto se utilizará al iniciar el próximo proceso hijo.
o
void setProcessType(ProcessType type):
Este miembro cambia el ProcessType por defecto. El nuevo valor por defecto se utilizará al iniciar el próximo proceso hijo.
o
void setTimeLimit(size_t timeLimit):
Este miembro cambia el límite de tiempo de ejecución por defecto (en segundos). No se impondrá ningún límite de tiempo a los procesos hijos si se especifica timeLimit 0. El nuevo valor por defecto se utilizará al iniciar el próximo proceso hijo.
o
