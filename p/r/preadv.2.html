readv(2) Manual de llamadas al sistema readv(2)

NOMBRE

readv, writev, preadv, pwritev, preadv2, pwritev2 - leer o escribir datos en múltiples búferes

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/uio.h>
ssize_t readv(int fd, const struct iovec *iov, int iovcnt);
ssize_t writev(int fd, const struct iovec *iov, int iovcnt);
ssize_t preadv(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t pwritev(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t preadv2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);
ssize_t pwritev2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);

DESCRIPCIÓN

La llamada al sistema readv() lee iovcnt búferes del archivo asociado con el descriptor de archivo fd en los búferes descritos por iov ("entrada dispersa").

La llamada al sistema writev() escribe iovcnt búferes de datos descritos por iov en el archivo asociado con el descriptor de archivo fd ("salida agrupada").

El puntero iov apunta a un array de estructuras iovec, descritas en iovec(3type).

La llamada al sistema readv() funciona igual que read(2) excepto que se llenan múltiples búferes.

La llamada al sistema writev() funciona igual que write(2) excepto que se escriben múltiples búferes.

Los búferes se procesan en orden de array. Esto significa que readv() llena completamente iov[0] antes de pasar a iov[1], y así sucesivamente. (Si no hay datos suficientes, es posible que no se llenen todos los búferes apuntados por iov.) De manera similar, writev() escribe el contenido completo de iov[0] antes de pasar a iov[1], y así sucesivamente.

Las transferencias de datos realizadas por readv() y writev() son atómicas: los datos escritos por writev() se escriben como un solo bloque que no se mezcla con la salida de escrituras en otros procesos; análogamente, se garantiza que readv() lee un bloque contiguo de datos del archivo, independientemente de las operaciones de lectura realizadas en otros hilos o procesos que tengan descriptores de archivo que se refieran a la misma descripción de archivo abierta (ver open(2)).

preadv() y pwritev()

La llamada al sistema preadv() combina la funcionalidad de readv() y pread(2). Realiza la misma tarea que readv(), pero añade un cuarto argumento, offset, que especifica el desplazamiento del archivo en el que se realizará la operación de entrada.

La llamada al sistema pwritev() combina la funcionalidad de writev() y pwrite(2). Realiza la misma tarea que writev(), pero añade un cuarto argumento, offset, que especifica el desplazamiento del archivo en el que se realizará la operación de salida.

El desplazamiento del archivo no se modifica por estas llamadas al sistema. El archivo al que se hace referencia con fd debe ser capaz de buscar.

preadv2() y pwritev2()

Estas llamadas al sistema son similares a las llamadas preadv() y pwritev(), pero añaden un quinto argumento, flags, que modifica el comportamiento por llamada.

A diferencia de preadv() y pwritev(), si el argumento offset es -1, se utiliza y actualiza el desplazamiento actual del archivo.

El argumento flags contiene una OR a nivel de bits de cero o más de las siguientes banderas:

RWF_DSYNC (desde Linux 4.7)
Proporciona un equivalente por escritura del indicador O_DSYNC de open(2). Esta bandera solo es significativa para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema.
RWF_HIPRI (desde Linux 4.6)
Lectura/escritura de alta prioridad. Permite a los sistemas de archivos basados en bloques utilizar la sondeo del dispositivo, lo que proporciona una latencia menor, pero puede utilizar recursos adicionales. (Actualmente, esta característica solo es utilizable en un descriptor de archivo abierto con el indicador O_DIRECT).
RWF_SYNC (desde Linux 4.7)
Proporciona un equivalente por escritura del indicador O_SYNC de open(2). Esta bandera solo es significativa para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema.
RWF_NOWAIT (desde Linux 4.14)
No esperar datos que no estén inmediatamente disponibles. Si se especifica esta bandera, la llamada al sistema preadv2() devolverá instantáneamente si tuviera que leer datos del almacenamiento de respaldo o esperar un bloqueo. Si se leyeron algunos datos, devolverá el número de bytes leídos. Si no se leyeron bytes, devolverá -1 y establecerá errno a EAGAIN (pero ver BUGS). Actualmente, esta bandera solo es significativa para preadv2().
RWF_APPEND (desde Linux 4.16)
Proporciona un equivalente por escritura del indicador O_APPEND de open(2). Esta bandera solo es significativa para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema. El argumento offset no afecta la operación de escritura; los datos siempre se añaden al final del archivo. Sin embargo, si el argumento offset es -1, se actualiza el desplazamiento actual del archivo.
RWF_NOAPPEND (desde Linux 6.9)
No honrar la bandera O_APPEND de open(2). Esta bandera solo es significativa para pwritev2(). Históricamente, Linux honraba la bandera O_APPEND si estaba establecida e ignoraba el argumento de desplazamiento, lo cual es un error. Para pwritev2(), el argumento offset se honra como se espera si la bandera RWF_NOAPPEND está establecida, lo mismo que si la bandera O_APPEND no estuviera establecida.
RWF_ATOMIC (desde Linux 6.11)
Requiere que las escrituras en archivos regulares en sistemas de archivos basados en bloques se emitan con protección contra escrituras de desgarro. La protección contra escrituras de desgarro significa que ante un fallo eléctrico o de otro tipo de hardware, todos los datos de la escritura se almacenarán o ninguno, pero nunca una mezcla de datos antiguos y nuevos. Esta bandera solo es significativa para pwritev2(), y su efecto se aplica solo al rango de datos escrito por la llamada al sistema. La longitud total de la escritura debe ser una potencia de 2 y estar en el rango [stx_atomic_write_unit_min, stx_atomic_write_unit_max]. La escritura debe realizarse en un desplazamiento naturalmente alineado dentro del archivo con respecto a la longitud total de la escritura. Por ejemplo, una escritura de 32KiB en un desplazamiento de archivo de 32KiB está permitida, sin embargo, una escritura de 32KiB en un desplazamiento de archivo de 48KiB no está permitida. El límite superior de iovcnt para pwritev2() se da por el valor en stx_atomic_write_segments_max. La protección contra escrituras de desgarro solo funciona con el indicador O_DIRECT, es decir, las escrituras en búfer no están soportadas. Para garantizar la coherencia de la escritura entre el estado en memoria del archivo y el dispositivo de almacenamiento, se debe especificar O_SYNC o O_DSYNC para open(2). Las mismas garantías de E/S sincronizada descritas en open(2) se proporcionan cuando se utilizan estas banderas o sus equivalentes (por ejemplo, si se especifica RWF_SYNC para pwritev2()).
RWF_DONTCACHE (desde Linux 6.14)

DESCRIPTION

The readv() and writev() system calls perform input/output scatter/gather operations. The argument iov is a pointer to an array of structures, each of which specifies a buffer for output or input.

The argument iovcnt indicates the number of elements in the array pointed to by iov.

The structure iovec is defined in <sys/uio.h> as:

    struct iovec {
        void  *iov_base; /* Pointer to start of buffer */
        size_t iov_len;  /* Size of buffer */
    };

readv() reads data from the file descriptor fd into buffers specified by the array iov. The read starts at the current file offset and proceeds sequentially through the buffers, filling each buffer before proceeding to the next. The file offset is updated by the number of bytes read.

writev() writes data from the buffers specified by the array iov to the file descriptor fd. The write starts at the current file offset and proceeds sequentially through the buffers, writing all of the data in each buffer before proceeding to the next. The file offset is updated by the number of bytes written.

The preadv() and pwritev() system calls are similar to, respectively, readv() and writev(), but they perform I/O at an offset specified by offset in the file descriptor fd, rather than using the current file offset. Thus, they do not affect the file offset. The offset is of type off_t.

The preadv2() and pwritev2() system calls are similar to, respectively, preadv() and pwritev(), but they accept an additional argument, flags, which modifies the behavior of the operation. The value of flags is the bitwise OR of zero or more of the following flags:

RWF_APPEND
Appends the write to the end of the file. The effect is the same as specifying the O_APPEND flag when opening the file, except that this flag can be specified only on a per-call basis. The file offset is ignored.
RWF_HIPRI
Specifies a "high priority" I/O operation. This is a hint to the kernel that the I/O should be processed with higher priority than normal. The kernel is free to ignore this hint.
RWF_DSYNC
Waits for both the data and the associated metadata to be written to the storage device before returning. This is equivalent to calling fdatasync(2).
RWF_SYNC
Waits for the data to be written out to the storage device before returning. This is equivalent to calling fsync(2).
RWF_NOWAIT
Causes the system call to return immediately, without waiting for the I/O to complete. The I/O is scheduled to be performed in the background. This flag is only supported for write operations. For read operations, it causes the system call to return -1 with errno set to EOPNOTSUPP. When RWF_NOWAIT is used, the system call still returns the number of bytes requested to be read or written, but it does not guarantee that the I/O has completed or even started. The caller must have a mechanism to determine the actual completion status of the I/O, such as using io_uring(7).
RWF_APPEND
The file offset is not used. For write operations, data is appended to the end of the file. For read operations, this flag has no effect.
RWF_DIRECT
Perform the I/O directly to or from user-space buffers, bypassing the page cache. This requires that the user-space buffers and the file offset are properly aligned for direct I/O. If the underlying file system or device does not support direct I/O, or if the alignment requirements are not met, the operation will fail with errno set to EIO.
RWF_GETFL
Returns the file access mode flags associated with the file descriptor. The actual flags are returned in the location pointed to by the flags argument. No I/O is performed. This flag can only be used with preadv2().
RWF_HIPRI
This flag is a hint to the kernel to prioritize this I/O operation. The kernel is free to ignore this hint.
RWF_INVALIDATE
This flag, when used with preadv2(), invalidates the specified range of the page cache after the read operation completes. This means that the data read is not kept in the page cache. Subsequent reads of the same data will be actual I/O operations.
RWF_NOWAIT
For write operations, this flag causes the system call to return immediately after scheduling the I/O to be performed. The actual write may complete later. For read operations, this flag is not supported and causes the system call to return -1 with errno set to EOPNOTSUPP.
RWF_NOWRITE
This flag, when used with preadv2(), ensures that the read operation does not dirty any pages in the page cache. If the data is not already in the page cache, it will be read directly into the user-space buffer without being placed in the page cache. This is useful for read-only files or for operations where keeping data in the cache is undesirable.
RWF_NOWRITE
This flag, when used with preadv2(), ensures that the read operation does not dirty any pages in the page cache. If the data is not already in the page cache, it will be read directly into the user-space buffer without being placed in the page cache. This is useful for read-only files or for operations where keeping data in the cache is undesirable.
RWF_PROCDIRTY
This flag is used with writev() and related functions to indicate that the write operation should proceed even if the data is already dirty in the page cache. This can be used to ensure that the writeback happens in a specific order or at a specific time.
RWF_SEEK
This flag, when used with preadv2() or pwritev2(), indicates that the offset specified is the one to be used for the I/O operation. This is the default behavior for these functions and this flag is mainly for completeness or compatibility.
RWF_SYNC
For write operations, this flag ensures that the data is written to persistent storage before the system call returns. This is equivalent to calling fsync(2) on the written data.
RWF_UNMAP
This flag, when used with preadv2(), causes the specified range of the page cache to be unmapped after the read operation completes. This frees up memory occupied by the data in the page cache. Subsequent reads of the same data will result in a page fault and a new I/O operation.
RWF_WRITEBACK
This flag, when used with pwritev2(), initiates writeback of the specified range of data from the page cache to the underlying storage device. The operation returns after initiating the writeback, but it does not necessarily wait for the writeback to complete. This is similar to calling sync_file_range(2) with SYNC_FILE_RANGE_WRITE.
RWF_DONTCACHE
Writes performed with this flag set will bypass the page cache entirely. The data is written directly to the storage device. Reads performed with this flag will also bypass the page cache, meaning the data is read directly from the storage device and not from the cache. Writes or reads to a regular file will prune instantiated page cache content when the operation completes. This is different than normal buffered I/O, where the data usually remains in cache until such time that it gets reclaimed due to memory pressure. If ranges of the read or written I/O were already in cache before this read or write, then those ranges will not be pruned at I/O completion time.
Additionally, any range dirtied by a write operation with RWF_DONTCACHE set will get kicked off for writeback. This is similar to calling sync_file_range(2) with SYNC_FILE_RANGE_WRITE to start writeback on the given range. RWF_DONTCACHE is a hint, or best effort, where no hard guarantees are given on the state of the page cache once the operation completes.
If used on a file system or block device that doesn't support it, it will return -1, and errno will be set to EOPNOTSUPP.

RETURN VALUE

On success, readv(), preadv(), and preadv2() return the number of bytes read; writev(), pwritev(), and pwritev2() return the number of bytes written.

Note that it is not an error for a successful call to transfer fewer bytes than requested (see read(2) and write(2)).

On error, -1 is returned, and errno is set to indicate the error.

ERRORS

The errors are as given for read(2) and write(2). Furthermore, preadv(), preadv2(), pwritev(), and pwritev2() can also fail for the same reasons as lseek(2). Additionally, the following errors are defined:

EINVAL
The sum of the iov_len values overflows an ssize_t value.
EINVAL
If RWF_ATOMIC is specified, the combination of the sum of the iov_len values and the offset value does not comply with the length and offset torn-write protection rules.
EINVAL
The vector count, iovcnt, is less than zero or greater than the permitted maximum. If RWF_ATOMIC is specified, this maximum is given by the stx_atomic_write_segments_max value from statx.
EOPNOTSUPP
RWF_DONTCACHE was set in flags and the file doesn't support it.
EOPNOTSUPP
An unknown flag is specified in flags.

VERSIONS

C library/kernel differences

The raw preadv() and pwritev() system calls have call signatures that differ slightly from that of the corresponding GNU C library wrapper functions shown in the SYNOPSIS. The final argument, offset, is unpacked by the wrapper functions into two arguments in the system calls:

unsigned long pos_l, unsigned long pos

These arguments contain, respectively, the low order and high order 32 bits of offset.

Historical C library/kernel differences

To deal with the fact that IOV_MAX was so low on early versions of Linux, the glibc wrapper functions for readv() and writev() did some extra work if they detected that the underlying kernel system call failed because this limit was exceeded. In the case of readv(), the wrapper function allocated a temporary buffer large enough for all of the items specified by iov, passed that buffer in a call to read(2), copied data from the buffer to the locations specified by the iov_base fields of the elements of iov, and then freed the buffer. The wrapper function for writev() performed the analogous task using a temporary buffer and a call to write(2).

The need for this extra effort in the glibc wrapper functions went away with Linux 2.2 and later. However, glibc continued to provide this behavior until glibc 2.10. Starting with glibc 2.9, the wrapper functions provide this behavior only if the library detects that the system is running a Linux kernel older than Linux 2.6.18 (an arbitrarily selected kernel version). And since glibc 2.20 (which requires a minimum of Linux 2.6.32), the glibc wrapper functions always just directly invoke the system calls.

NOTES

POSIX.1 allows an implementation to place a limit on the number of items that can be passed in iov. An implementation can advertise its limit by defining IOV_MAX in <limits.h> or at run time via the return value from sysconf(_SC_IOV_MAX). On modern Linux systems, the limit is 1024. Back in Linux 2.0 days, this limit was 16.

BUGS

Linux 5.9 and Linux 5.10 have a bug where preadv2() with the RWF_NOWAIT flag may return 0 even when not at end of file.

EXAMPLES

The following code sample demonstrates the use of writev():


char          *str0 = "hello ";
char          *str1 = "world\n";
ssize_t       nwritten;
struct iovec  iov[2];
iov[0].iov_base = str0;
iov[0].iov_len = strlen(str0);
iov[1].iov_base = str1;
iov[1].iov_len = strlen(str1);
nwritten = writev(STDOUT_FILENO, iov, 2);
