proc_sys_fs(5) Manual de Formatos de Archivo proc_sys_fs(5)

NOMBRE

/proc/sys/fs/ - variables del kernel relacionadas con sistemas de archivos

DESCRIPCIÓN

/proc/sys/fs/
Este directorio contiene los archivos y subdirectorios para las variables del kernel relacionadas con sistemas de archivos.
/proc/sys/fs/aio-max-nr
/proc/sys/fs/aio-nr (ambos desde Linux 2.6.4)
aio-nr es el total actual del número de eventos especificados por las llamadas io_setup(2) para todos los contextos AIO actualmente activos. Si aio-nr alcanza aio-max-nr, entonces io_setup(2) fallará con el error EAGAIN. Aumentar aio-max-nr no resulta en la preasignación o redimensionamiento de ninguna estructura de datos del kernel.
/proc/sys/fs/binfmt_misc
La documentación para los archivos en este directorio se encuentra en el código fuente del kernel de Linux en el archivo Documentation/admin-guide/binfmt-misc.rst (o en Documentation/binfmt_misc.txt en kernels más antiguos).
/proc/sys/fs/dentry-state (desde Linux 2.2)
Este archivo contiene información sobre el estado de la caché de directorios (dcache). El archivo contiene seis números, nr_dentry, nr_unused, age_limit (edad en segundos), want_pages (páginas solicitadas por el sistema) y dos valores dummy.
•
nr_dentry es el número de dentries asignados (entradas dcache). Este campo no se utiliza en Linux 2.2.
•
nr_unused es el número de dentries no utilizados.
•
age_limit es la edad en segundos después de la cual las entradas de dcache pueden ser recuperadas cuando hay poca memoria.
•
want_pages es distinto de cero cuando el kernel ha llamado a shrink_dcache_pages() y el dcache aún no ha sido podado.
/proc/sys/fs/dir-notify-enable
Este archivo se puede usar para deshabilitar o habilitar la interfaz dnotify descrita en fcntl(2) a nivel de sistema. Un valor de 0 en este archivo deshabilita la interfaz, y un valor de 1 la habilita.
/proc/sys/fs/dquot-max
Este archivo muestra el número máximo de entradas de cuota de disco cacheadas. En algunos sistemas (2.4), no está presente. Si el número de entradas de cuota de disco cacheadas gratuitas es muy bajo y tienes un número impresionante de usuarios simultáneos en el sistema, podrías querer aumentar el límite.
/proc/sys/fs/dquot-nr
Este archivo muestra el número de entradas de cuota de disco asignadas y el número de entradas de cuota de disco gratuitas.
/proc/sys/fs/epoll/ (desde Linux 2.6.28)
Este directorio contiene el archivo max_user_watches, que se puede usar para limitar la cantidad de memoria del kernel consumida por la interfaz epoll. Para más detalles, ver epoll(7).
/proc/sys/fs/file-max
Este archivo define un límite a nivel de sistema para el número de archivos abiertos por todos los procesos. Las llamadas al sistema que fallan al encontrar este límite fallan con el error ENFILE. (Ver también setrlimit(2), que puede ser usado por un proceso para establecer el límite por proceso, RLIMIT_NOFILE, en el número de archivos que puede abrir.) Si obtienes muchos mensajes de error en el registro del kernel sobre quedarse sin descriptores de archivo (descripciones de archivo abiertas) (busca "VFS: file-max limit <number> reached"), intenta aumentar este valor:

echo 100000 > /proc/sys/fs/file-max

Los procesos privilegiados (CAP_SYS_ADMIN) pueden anular el límite file-max.
/proc/sys/fs/file-nr
Este archivo (de solo lectura) contiene tres números: el número de descriptores de archivo asignados (es decir, el número de descripciones de archivo abiertas; ver open(2)); el número de descriptores de archivo gratuitos; y el número máximo de descriptores de archivo (es decir, el mismo valor que /proc/sys/fs/file-max). Si el número de descriptores de archivo asignados está cerca del máximo, deberías considerar aumentar el máximo. Antes de Linux 2.6, el kernel asignaba descriptores de archivo dinámicamente, pero no los liberaba de nuevo. En su lugar, los descriptores de archivo gratuitos se mantenían en una lista para su reutilización; el valor "descriptores de archivo gratuitos" indica el tamaño de esa lista. Un gran número de descriptores de archivo gratuitos indica que hubo un pico pasado en el uso de descriptores de archivo abiertos. Desde Linux 2.6, el kernel desasigna los descriptores de archivo liberados, y el valor "descriptores de archivo gratuitos" es siempre cero.
/proc/sys/fs/inode-max (solo presente hasta Linux 2.2)
Este archivo contiene el número máximo de inodos en memoria. Este valor debería ser 3-4 veces mayor que el valor en file-max, ya que stdin, stdout y los sockets de red también necesitan un inodo para manejarlos. Cuando te quedas sin inodos regularmente, necesitas aumentar este valor.
A partir de Linux 2.4, ya no hay un límite estático para el número de inodos, y este archivo se elimina.
/proc/sys/fs/inode-nr
Este archivo contiene los dos primeros valores de inode-state.
/proc/sys/fs/inode-state
Este archivo contiene siete números: nr_inodes, nr_free_inodes, preshrink, y cuatro valores dummy (siempre cero).
nr_inodes es el número de inodos que el sistema ha asignado. nr_free_inodes representa el número de inodos gratuitos.
preshrink es distinto de cero cuando nr_inodes > inode-max y el sistema necesita podar la lista de inodos en lugar de asignar más; desde Linux 2.4, este campo es un valor dummy (siempre cero).
/proc/sys/fs/inotify/ (desde Linux 2.6.13)
Este directorio contiene los archivos max_queued_events, max_user_instances, y max_user_watches, que se pueden usar para limitar la cantidad de memoria del kernel consumida por la interfaz inotify. Para más detalles, ver inotify(7).
/proc/sys/fs/lease-break-time
Este archivo especifica el período de gracia que el kernel otorga a un proceso que tiene un lease de archivo (fcntl(2)) después de haber enviado una señal a ese proceso notificándole que otro proceso está esperando abrir el archivo. Si el poseedor del lease no elimina o degrada el lease dentro de este período de gracia, el kernel rompe forzosamente el lease.
/proc/sys/fs/leases-enable
Este archivo se puede usar para habilitar o deshabilitar leases de archivo (fcntl(2)) a nivel de sistema. Si este archivo contiene el valor 0, los leases están deshabilitados. Un valor distinto de cero habilita los leases.
/proc/sys/fs/mount-max (desde Linux 4.9)
El valor en este archivo especifica el número máximo de montajes que pueden existir en un espacio de nombres de montaje. El valor predeterminado en este archivo es 100.000.
/proc/sys/fs/mqueue/ (desde Linux 2.6.6)
Este directorio contiene los archivos msg_max, msgsize_max, y queues_max, que controlan los recursos utilizados por las colas de mensajes POSIX. Ver mq_overview(7) para detalles.
/proc/sys/fs/nr_open (desde Linux 2.6.25)
Este archivo impone un límite superior al valor al que se puede elevar el límite de recursos RLIMIT_NOFILE (ver getrlimit(2)). Este límite se aplica tanto a procesos no privilegiados como privilegiados. El valor predeterminado en este archivo es 1048576. (Antes de Linux 2.6.25, el límite superior para RLIMIT_NOFILE estaba codificado de forma fija al mismo valor.)
/proc/sys/fs/overflowgid
/proc/sys/fs/overflowuid
Estos archivos te permiten cambiar el valor de la UID y GID fijas. El valor predeterminado es 65534. Algunos sistemas de archivos solo admiten UIDs y GIDs de 16 bits, aunque en Linux las UIDs y GIDs son de 32 bits. Cuando uno de estos sistemas de archivos está montado con escritura habilitada, cualquier UID o GID que exceda 65535 se traduce al valor de desbordamiento antes de ser escrito en el disco.
/proc/sys/fs/pipe-max-size (desde Linux 2.6.35)
Ver pipe(7).
/proc/sys/fs/pipe-user-pages-hard (desde Linux 4.5)
Ver pipe(7).
/proc/sys/fs/pipe-user-pages-soft (desde Linux 4.5)
Ver pipe(7).

La escritura a FIFOs no tiene restricciones.

/proc/sys/fs/protected_hardlinks (desde Linux 3.6)
Cuando el valor en este archivo es 0, no se imponen restricciones a la creación de enlaces duros (es decir, este es el comportamiento histórico anterior a Linux 3.6). Cuando el valor en este archivo es 1, se puede crear un enlace duro a un archivo de destino solo si se cumple una de las siguientes condiciones:
•
El proceso llamador tiene la capacidad CAP_FOWNER en su espacio de nombres de usuario y el UID del archivo tiene un mapeo en el espacio de nombres.
•
El UID del sistema de archivos del proceso que crea el enlace coincide con el propietario (UID) del archivo de destino (como se describe en credentials(7), el UID del sistema de archivos de un proceso es normalmente el mismo que su UID efectivo).
•
Se cumplen todas las siguientes condiciones:
•
el destino es un archivo regular;
•
el archivo de destino no tiene activado su bit de modo set-user-ID;
•
el archivo de destino no tiene activados tanto su bit de modo set-group-ID como su bit de modo ejecutable por grupo; y
•
el llamador tiene permiso para leer y escribir en el archivo de destino (ya sea a través de la máscara de permisos del archivo o porque tiene las capacidades adecuadas).
El valor predeterminado en este archivo es 0. Establecer el valor a 1 previene una clase de problemas de seguridad de larga data causados por carreras de tiempo de verificación, tiempo de uso basadas en enlaces duros, vistas con mayor frecuencia en directorios escribibles por todos, como /tmp. El método común para explotar esta falla es cruzar límites de privilegios al seguir un enlace duro dado (es decir, un proceso root sigue un enlace duro creado por otro usuario). Además, en sistemas sin particiones separadas, esto evita que usuarios no autorizados "fijen" archivos vulnerables set-user-ID y set-group-ID contra ser actualizados por el administrador, o enlacen a archivos especiales.
/proc/sys/fs/protected_regular (desde Linux 4.19)
El valor en este archivo es/puede ser establecido a uno de los siguientes:
0
La escritura a archivos regulares no tiene restricciones.
1
No permitir O_CREAT open(2) en archivos regulares que el llamador no posee en directorios pegajosos escribibles por todos, a menos que el archivo regular sea propiedad del propietario del directorio.
2
Como en el valor 1, pero la restricción también se aplica a directorios pegajosos escribibles por grupos.
La intención de las protecciones anteriores es similar a protected_fifos, pero permite a una aplicación evitar escrituras en un archivo regular controlado por un atacante, donde la aplicación esperaba crear uno.
/proc/sys/fs/protected_symlinks (desde Linux 3.6)
Cuando el valor en este archivo es 0, no se imponen restricciones a seguir enlaces simbólicos (es decir, este es el comportamiento histórico anterior a Linux 3.6). Cuando el valor en este archivo es 1, los enlaces simbólicos solo se siguen en las siguientes circunstancias:
•
el UID del sistema de archivos del proceso que sigue el enlace coincide con el propietario (UID) del enlace simbólico (como se describe en credentials(7), el UID del sistema de archivos de un proceso es normalmente el mismo que su UID efectivo);
•
el enlace no está en un directorio pegajoso escribible por todos; o
•
el enlace simbólico y su directorio padre tienen el mismo propietario (UID)
Una llamada al sistema que no sigue un enlace simbólico debido a las restricciones anteriores devuelve el error EACCES en errno.
El valor predeterminado en este archivo es 0. Establecer el valor a 1 evita una clase de problemas de seguridad de larga data basados en carreras de tiempo de verificación, tiempo de uso al acceder a enlaces simbólicos.
/proc/sys/fs/suid_dumpable (desde Linux 2.6.13)
El valor en este archivo se asigna al flag "dumpable" de un proceso en las circunstancias descritas en prctl(2). En efecto, el valor en este archivo determina si se producen archivos de volcado de núcleo para binarios set-user-ID o de otro modo protegidos/contaminados. La configuración "dumpable" también afecta la propiedad de los archivos en el directorio /proc/pid de un proceso, como se describe anteriormente.
Se pueden especificar tres valores enteros diferentes:
0 (predeterminado)
Esto proporciona el comportamiento tradicional (anterior a Linux 2.6.13). No se producirá un volcado de núcleo para un proceso que haya cambiado sus credenciales (llamando a seteuid(2), setgid(2), o similar, o ejecutando un programa set-user-ID o set-group-ID) o cuyo binario no tenga permiso de lectura activado.
1 ("debug")
Todos los procesos vuelcan el núcleo cuando es posible. (Las razones por las que un proceso podría no volcar el núcleo se describen en core(5).) El volcado de núcleo es propiedad del ID de usuario del sistema de archivos del proceso que vuelca y no se aplica seguridad. Esto está destinado solo a situaciones de depuración del sistema: este modo no es seguro porque permite a los usuarios sin privilegios examinar el contenido de la memoria de los procesos privilegiados.
2 ("suidsafe")
Cualquier binario que normalmente no se volcaría (ver "0" arriba) se volcará legible solo por root. Esto permite al usuario eliminar el archivo de volcado de núcleo pero no leerlo. Por razones de seguridad, los volcados de núcleo en este modo no se sobrescribirán entre sí ni a otros archivos. Este modo es apropiado cuando los administradores intentan depurar problemas en un entorno normal.
Además, desde Linux 3.6, /proc/sys/kernel/core_pattern debe ser una ruta absoluta o un comando de tubería, como se detalla en core(5). Se escribirán advertencias en el registro del kernel si core_pattern no sigue estas reglas, y no se producirá ningún volcado de núcleo.
Para obtener detalles sobre el efecto de la configuración "dumpable" de un proceso en la verificación del modo de acceso ptrace, consulte ptrace(2).
/proc/sys/fs/super-max
Este archivo controla el número máximo de superbloques y, por lo tanto, el número máximo de sistemas de archivos montados que el kernel puede tener. Solo necesita aumentar super-max si necesita montar más sistemas de archivos de los que el valor actual en super-max le permite.
/proc/sys/fs/super-nr
Este archivo contiene el número de sistemas de archivos montados actualmente.
