FBB::Proc(3bobcat) Ejecución de procesos hijos FBB::Proc(3bobcat)

NOMBRE

FBB::Proc - Ejecuta programas externos

SINOPSIS

#include <bobcat/proc>
Opción de enlace: -lbobcat

DESCRIPCIÓN

FBB::Proc ofrece una alternativa a la clase FBB::Process. FBB::Proc ofrece una interfaz extensa para llamar programas y/o scripts externos desde un programa de C++ (los llamados procesos hijos). La clase ofrece una interfaz fácil de usar, basada en flujos, para comunicarse con los flujos de entrada, salida y error estándar de los procesos hijos.

Los objetos de la clase Proc utilizan funciones estándar de ejecución de procesos, como miembros de la familia execl(2) o sh(1) para ejecutar procesos hijos. Por lo tanto, los procesos hijos pueden ser programas ejecutables o scripts de shell.

Los flujos de entrada, salida y error estándar de los procesos hijos pueden ser accedidos a través de sus objetos padre Proc. La entrada esperada por los procesos hijos puede ser insertada en los objetos Proc. La salida estándar y el error estándar generados por los procesos hijos se insertan y se procesan posteriormente en objetos std::ostream, por defecto std::cout y std::cerr.

Al usar redirección (de salida) al ejecutar procesos hijos utilizando la especificación de ruta USE_SHELL (ver abajo para las especificaciones de ruta y IOMode), normalmente se debe especificar el IOMode IGNORE_COUT (y posiblemente también IGNORE_CERR) (cf. sección ENUMERACIONES para una descripción de la enumeración IOMode).

Los objetos Proc pueden usarse repetidamente para ejecutar los mismos o diferentes procesos hijos. Antes de iniciar el siguiente proceso hijo, el objeto Proc se asegura de que su proceso hijo activo actualmente termine. Alternativamente, un proceso hijo activo actualmente termina si el objeto Proc sale del ámbito, si ha expirado el tiempo de ejecución asignado al proceso hijo, si se inicia un nuevo proceso usando el operador de asignación de Proc, o si se llama a su miembro stop. De lo contrario, los procesos hijos continúan hasta su finalización al llamar a finish o, si el proceso hijo lee su flujo de entrada estándar, cuando el manipulador eoi se inserta en el objeto Proc.

Los programas llamados como procesos hijos pueden especificarse al construir un objeto Proc o al usar el miembro setCommand de Proc. Los constructores de Proc (o el miembro setCommand de Proc) no inician procesos hijos. Para iniciar procesos hijos se deben usar los miembros start o el operador de asignación.

Los procesos hijos pueden recibir información en sus flujos de entrada estándar a través de información insertada en los objetos Proc. En esos casos, los objetos Proc deben informar a sus procesos hijos que han recibido toda la entrada. Para esto, el manipulador eoi puede insertarse en los objetos Proc, o se puede llamar al miembro finish de Proc.

Si la información enviada al hijo no es procesada completamente por el proceso hijo, el sistema operativo emite un mensaje de Tubería rota (Broken pipe), indicando que la información en una tubería se perdió, terminando el programa. El miembro pipeSignal de la clase Proc puede usarse para suprimir el mensaje de Tubería rota.

Los argumentos pasados a los procesos hijos pueden estar rodeados por comillas dobles o simples. Los argumentos rodeados por comillas dobles tienen sus comillas eliminadas, mientras interpretan cualquier secuencia de escape que se haya utilizado dentro. Los argumentos rodeados por comillas simples tienen sus comillas eliminadas, mientras aceptan su contenido tal cual. Además, se pueden especificar secuencias de escape sin comillas: esas secuencias de escape se evalúan y se reemplazan por sus caracteres previstos (por ejemplo, \100 se convierte en @).

Una especificación completa de comando también puede estar rodeada por comillas invertidas (caracteres `). Estas comillas invertidas son eliminadas por el objeto Proc cuando el comando se inicia.

A los procesos hijos se les puede asignar una cantidad limitada de tiempo (en segundos) para completarse. Por defecto, no se impone ningún límite de tiempo a los procesos hijos. Si se especifica un límite de tiempo, el proceso hijo, si todavía está en ejecución después del número especificado de segundos, se termina enviándole una señal SIGTERM, seguida de una señal SIGKILL (cf. signal(7)).

Por defecto, los flujos de entrada, salida y error estándar de los procesos hijos son manejados por sus procesos padre Proc: la información insertada en el objeto Proc se reenvía al flujo de entrada estándar del proceso hijo, la información enviada por el proceso hijo a sus flujos de salida y error estándar se reenvía a los flujos correspondientes del proceso padre, o pueden ser procesados por flujos, configurados por el objeto Proc.

Múltiples procesos Proc pueden combinarse usando el operador de tubería (es decir, el operador |). Cuando se usa, el flujo de salida estándar del objeto Proc del lado izquierdo (lhs) se usa como el flujo de entrada estándar del objeto Proc del lado derecho (rhs). Dado que los objetos Proc inician sus propios procesos hijos, esto efectivamente se reduce a que la salida del proceso hijo del lhs se usa como la entrada del proceso hijo del rhs. El objeto Proc más a la izquierda también puede leer su entrada (usando el operador de tubería) de un objeto istream o de un archivo cuyo nombre (ruta) se especifica como el argumento más lhs de una expresión de tubería. Del mismo modo, el objeto Proc más a la derecha puede enviar su salida estándar a un objeto ostream existente o a un archivo cuyo nombre (ruta) se especifica como el argumento más rhs de una expresión de tubería.

Los objetos Proc usan objetos Pipe (cf. pipe(3bobcat)) para la comunicación con sus procesos hijos. Para asegurar que estas tuberías se cierren correctamente, se deben usar los miembros waitForChild, stop o el manipulador eoi. Una vez que un objeto Proc deja de existir, las tuberías a su proceso hijo también se cierran.

ENUMERACIONES

Las siguientes enumeraciones son definidas por la clase Proc:

enum ProcType:

El enum ProcType define cómo se inicia o localiza un proc hijo. Sus valores se especifican en tiempo de construcción o a través del miembro setProcType. Esta enumeración define las siguientes constantes simbólicas:

o
NO_PATH:
El programa especificado como proc hijo se inicia como se especifica, sin buscar los elementos de la variable de entorno PATH.
o
USE_PATH:
Los elementos de la variable de entorno PATH se utilizan al localizar el programa especificado como proc hijo.
o
USE_SHELL:
El programa especificado como proc hijo se llama usando /bin/sh -c. Al usar redirección (de salida) con el comando especificado, se debe especificar el IOMode IGNORE_COUT (y posiblemente también el IOMode IGNORE_CERR).

enum IOMode:

Los valores de la enum IOMode se utilizan para definir cuáles de los flujos estándar del proc hijo pueden ser accedidos a través del objeto Proc. Sus constantes simbólicas pueden combinarse usando el operador bit_or. Por defecto se usa CIN | COUT | CERR (ver abajo).

Los argumentos de IOMode pueden combinarse usando operadores bit_or.

Las siguientes constantes simbólicas están disponibles:

o
ALL:
Atajo para CIN | COUT | CERR.
o
CIN:
La información insertada en el objeto Proc se reenvía a su proc hijo. Si esto no es necesario, entonces CIN no debe ser especificado.
o
CERR:
La información escrita por el proceso hijo en su flujo de error estándar se hace disponible como el flujo de error estándar de Proc.

IOMODE

The IOMode constants define how the Proc object interacts with the standard input and output streams of its child process. Multiple constants can be combined using the bitwise OR operator (|) unless otherwise specified.

o
ALL:
Shortcut for CIN | COUT | CERR.
o
CERR:
Information written by the child process to its standard error stream is made available as Proc’s standard error stream. If this is not required then COUT should not be specified.
o
CIN:
The Proc object provides information to the child process’s standard input stream. If this is not required then COUT and/or CERR should not be specified.
o
COUT:
Information written by the child process to its standard output stream is made available as Proc’s standard output stream. If this is not required then CERR should not be specified.
o
CERR:
Information written by the child process to its standard error stream is made available as Proc’s standard error stream. If this is not required then COUT should not be specified.
o
CIN:
The Proc object provides information to the child process’s standard input stream. If this is not required then COUT and/or CERR should not be specified.
o
COUT:
Information written by the child process to its standard output stream is made available as Proc’s standard output stream. If this is not required then CERR should not be specified.
o
IGNORE_CERR:
Information written by the child proc to its standard error stream is ignored (i.e., not made available). An std::invalid_argument exception is thrown if this mode is specified in combination with CERR, MERGE_COUT_CERR, and/or REPLACE.
o
IGNORE_COUT:
Information written by the child proc to its standard output stream is ignored. An std::invalid_argument exception is thrown if this mode is specified in combination with COUT, MERGE_COUT_CERR and/or REPLACE.
o
IGNORE_COUT_CERR:
Shortcut for IGNORE_CERR | IGNORE_COUT.
o
MERGE_COUT_CERR:
Information written by the child process to its standard output and standard error streams is made available at the Proc object’s standard output stream. An std::invalid_argument exception is thrown if this mode is specified in combination with COUT, CERR, IGNORE_COUT, IGNORE_CERR or REPLACE.
o
NONE:
The Proc object does not insert information into the standard input streams of its child process and information written by the child process to its standard output or error streams is not forwarded to the Proc object. Instead, the child process processes its standard streams by itself. When this mode is specified in combination with other IOMode values it is silently ignored.
o
REPLACE:
When starting a child proc (see below at the member start) the current process (i.e., the program defining the Proc object) is replaced by the child process, inheriting the current process’s standard input and output streams. If this mode is specified in combination with any other IOMode (except for NONE, see below) an std::invalid_argument exception is thrown.

CONSTRUCTOR

Note that child processes are not started automatically following the construction of t(Proc) objects. A start member or the assignment operator (see below) is used to start child processes.

Once a Proc object has been constructed its parameters can be changed using set-member functions or start members.

o
explicit Proc(std::string const &command = "", IOMode mode = ALL, ProcType type = NO_PATH, size_t bufSize = 200, size_t timeLimit = 0, bool pipeSignal = true):
The parameter bufSize defines the size of the streambuf buffers used by the Proc object. The timeLimit specifies the maximum execution time of a child process in seconds; when timeLimit == 0 no execution time limit is used. When pipeSignal == true incomplete processing of information sent to or read from the child process results in a Broken pipe exception, terminating the program. When specifying false the Broken pipe exception is suppressed, and the input and/or output streams do not have to be completely processed (see also pipeSignal’s description).

Copy and move constructors (and assignment operators) are not available.

OPERADORES SOBRECARGADOS

o
Proc &operator<<(Type value):
Este operador inserta value en el flujo de entrada estándar del hijo. Es decir, el proceso hijo lee value de su entrada estándar. Se puede insertar un valor de cualquier tipo que se pueda insertar en un ostream en un objeto Proc. No ocurre nada si se utiliza el miembro cuando el proceso hijo ha terminado. Los manipuladores como std::endl también son compatibles. El comportamiento de este operador no está definido cuando no se ha especificado el IOMode CIN.
o
Proc &operator+=(std::string const &):
Este operador añade el objeto std::string proporcionado a la especificación de comando actualmente definida de un objeto Proc. El miembro operator+= no añade un espacio en blanco separador entre la especificación de comando almacenada actualmente y el texto a añadir. Simplemente añade su cadena del lado derecho al comando almacenado hasta el momento. No afecta a un proceso hijo en ejecución.
o
int operator=(std::string const &cmd):
El miembro operator= define cmd como el comando almacenado en un objeto Proc, y a continuación inicia `cmd’ como su proceso hijo.
Antes de iniciar el proceso hijo, se detiene primero un proceso hijo posiblemente activo llamando a stop. Devuelve el valor de retorno de stop. Inmediatamente después de llamar a stop se inicia el nuevo comando (cmd). Si finalizar y reiniciar otro comando deben ser acciones separadas, utilice finish o stop seguido de setCommand, seguido de la llamada a una versión sobrecargada apropiada del miembro start.
o
Return operator|(Proc &lhs, Proc &rhs):
Este operador implementa el piping. La información enviada por lhs a su salida estándar se utiliza como entrada estándar del proceso hijo de rhs. El valor de retorno es rhs si la expresión va seguida de otro operador de tubería, o es void.
o
Return operator|(std::istream &in, Proc &proc):
Este operador implementa el piping. La información leída de in es leída por el proceso hijo de proc. El valor de retorno es proc si la expresión va seguida de otro operador de tubería, o es void.
o
Return operator|(std::string const &fname, Proc &proc):
Este operador implementa el piping. La información del archivo cuyo nombre de archivo (ruta) es fname es leída por el proceso hijo de proc. El valor de retorno es proc si la expresión va seguida de otro operador de tubería, o es void.
o
void operator|(Proc &proc, std::ostream &out):
Este operador implementa el piping. La información enviada por el proceso hijo de proc a su flujo de salida estándar se escribe en out.
o
void operator|(Proc &proc, std::string &fname):
Este operador implementa el piping. La información enviada por el proceso hijo de proc a su flujo de salida estándar se escribe en el archivo cuyo nombre de archivo (ruta) es fname.

El operador de tubería (|) imita el operador de tubería compatible con la mayoría de los programas de shell y no debe confundirse con el operador bitwise OR. El operador de tubería permite construcciones como

    p1 | p2 | p3            // canalizando 3 objetos Proc
    cin | p1 | p2 | cout    // p1 lee cin, p2 escribe cout
    inName | p1 | outName   // inName: nombre del archivo
                            // leído por p1, outName: nombre del archivo
                            // escrito por p1

Al usar el operador de tubería, los objetos Proc que leen entrada especifican automáticamente sus modos CIN, mientras que los objetos Proc que escriben su salida estándar especifican automáticamente sus modos COUT. Después de la expresión de tubería, se restauran las especificaciones de IOMode que se especificaron antes de la expresión de tubería.

MIEMBROS

o
bool active():
Si el proceso hijo se está ejecutando actualmente, se devuelve true, y false si no.
o
void cerrMode(char const *lab) const:
La etiqueta lab, seguida de una representación textual del IOMode actualmente configurado, se inserta en std::cerr.
o
void cerrPipes(char const *lab) const:
El texto Proc, seguido del id del Proc, seguido de la etiqueta lab, seguido de los descriptores de archivo de lectura y escritura actualmente activos de las tuberías actualmente utilizadas por el objeto Proc, se insertan en std::cerr.
o
std::string const &cmd() const:
Se devuelve el comando de inicio del proceso hijo actualmente especificado.
o
int exitStatus() const:
Se devuelve el último estado de salida del proceso hijo. Si un proceso hijo se está ejecutando actualmente o si aún no se ha iniciado ningún proceso hijo, se devuelve -1.
o
int finish():
Espera hasta que un proceso hijo actualmente activo haya terminado y devuelve su estado de salida. Si el proceso hijo no se está ejecutando actualmente, se devuelve -1.
o
IOMode ioMode() const:
Se devuelve el IOMode utilizado actualmente por el objeto Proc.
o
std::string mode() const:
Se devuelve el IOMode utilizado actualmente por el objeto Proc como una cadena de texto.
o
int pid() const:
Se devuelve el ID de proceso del proceso hijo. El valor devuelto no está definido si aún no se ha iniciado ningún proceso hijo. Si el proceso hijo ya ha completado, se devuelve el ID del último proceso hijo.
o
void pipeSignal(bool on):
Cuando se reenvía información de forma incompleta a un proceso hijo o se lee información de forma incompleta de un proceso hijo, puede producirse una tubería rota (*Broken pipe*), lo que finaliza el programa en ejecución. Para evitar esto, se puede llamar a pipeSignal(false). Para reactivar el reconocimiento de tuberías rotas, se puede llamar a pipeSignal(true). Después de usar pipeSignal(false), los intentos fallidos de inserción en un objeto Proc resultan en que su miembro good devuelva false, y sus miembros bad y fail devuelvan true.
o
size_t procIdx() const:
Cada objeto Proc construido recibe su propio índice de orden de construcción. El primer objeto Proc construido en un programa recibe el valor de índice 0.
o
ProcType procType() const:
Se devuelve el ProcType utilizado al iniciar procesos hijos.
o
void setBufSize(size_t bufSize):
El tamaño del búfer de flujo en bytes utilizado por los flujos que se comunican con procesos hijos se establece en bufSize. Un tamaño de búfer de cero bytes se cambia silenciosamente a uno.
o
void setCommand(std::string const &cmd):
Se establece la parte (inicial) de la especificación del comando del proceso hijo en cmd. Después de llamar a este miembro, se puede usar operator+= para añadir texto adicional a la especificación del comando.
o
void setIOMode(IOMode mode):
El IOMode utilizado al llamar a procesos hijos se establece en mode. Tenga en cuenta que las expresiones de tubería pueden modificar el mode de los objetos Proc mientras se ejecuta la expresión de tubería. Para más detalles, consulte el final de la sección OPERADORES SOBRECARGADOS.
o
void setProcType(ProcType type):
Se establece el ProcType utilizado al iniciar procesos hijos en type.
o
void setTimeLimit(size_t timeLimit):
El límite de tiempo de ejecución de los procesos hijos se establece en timeLimit (en segundos). No se utiliza ningún límite de tiempo cuando se especifica timeLimit 0. El límite de tiempo establecido por setTimeLimit se utiliza al iniciar el próximo proceso hijo. Al llamar a setTimeLimit, se llama automáticamente a pipeSignal(timeLimit == 0). Si esto no es lo deseado, llame explícitamente a pipeSignal después de llamar a setTimeLimit.
o
void start(size_t timeLimit, IOMode mode = ALL, ProcType type = NO_PATH, size_t bufSize = 200):
Se inicia el comando especificado actualmente utilizando los argumentos timeLimit, IOMode, ProcType y bufSize especificados. Los miembros start no alteran los valores predeterminados actualmente configurados de sus argumentos.
Si un proceso hijo todavía está activo cuando se llama a start, primero llama a stop para finalizar el proceso hijo en ejecución actual.
o
void start(IOMode mode, ProcType type = NO_PATH, size_t bufSize = 200):
Igual que el miembro start anterior, pero utilizando el timeLimit actualmente configurado y requiriendo la especificación del IOMode a utilizar.
o
void start():
Igual que el primer miembro start, pero utilizando los valores timeLimit, IOMode, ProcType y bufSize actualmente configurados.
o
int stop():
Se finaliza un proceso hijo actualmente activo llamando a Fork::endChild (ver también fork(3bobcat)).
o
void system(size_t timeLimit, IOMode mode = ALL, size_t bufSize = 200):
El comando actualmente almacenado se ejecuta como un comando de sh(1), utilizando los argumentos de proceso especificados.
o
void system(IOMode mode = ALL, size_t bufSize = 200):
Igual que el comando system anterior, pero utilizando la especificación predeterminada de timeLimit.
o
size_t timeLimit() const:
Se devuelve el límite de tiempo de ejecución actualmente configurado del proceso hijo de Proc. El valor de retorno cero indica que no se utiliza ningún límite de tiempo.
o
void useErr(std::ostream &out):
La salida de error estándar producida por el proceso hijo se envía a out. Si el objeto Proc había especificado IGNORE_CERR, entonces ese IOMode se anula y se establece el modo CERR.
o
void useErr(std::string const &fname):
Igual que el miembro anterior, pero la salida de error estándar del hijo se escribe en el archivo (ruta) fname.
o
void useMerge(std::ostream &out):
La salida estándar y la salida de error estándar producidas por el proceso hijo se envían a out. Si el objeto Proc había especificado CERR, COUT, IGNORE_CERR o IGNORE_COUT, entonces esos IOModes se anulan y se establece el modo MERGE_COUT_CERR.
o
void useMerge(std::string const &fname):
Igual que el miembro anterior, pero la salida estándar y la salida de error estándar del hijo se escriben en el archivo (ruta) fname.
o
void useOut(std::ostream &out):
La salida estándar producida por el proceso hijo se envía a out. Si el objeto Proc había especificado IGNORE_COUT, entonces ese IOMode se anula y se establece el modo COUT.
o
void useOut(std::string const &fname):
Igual que el miembro anterior, pero la salida estándar del hijo se escribe en el archivo (ruta) fname.
o
int waitForChild():
Este miembro llama al miembro de igual nombre de la clase FBB::Fork, esperando a que termine un proceso hijo. Al llamar a finish o al utilizar expresiones de tubería, se llama automáticamente a waitForChild.

EJEMPLOS

Todos los ejemplos deben comenzar con:

    #include <iostream>
    #include <bobcat/proc>
    using namespace std;
    using namespace FBB;

El primer ejemplo ilustra cómo se puede llamar a un programa que solo produce salida. Su proceso hijo es simplemente /bin/ls:

int main()
{
    Proc proc("/bin/ls -Fla", Proc::COUT);
    proc.start();
}

El siguiente ejemplo ilustra un programa hijo al que se le da una cantidad limitada de tiempo de ejecución: las líneas introducidas desde el teclado se muestran en la secuencia de salida estándar durante un máximo de 5 segundos:

int main()
{
    Proc proc("/bin/cat", Proc::CIN | Proc::COUT);
    proc.setTimeLimit(5);
    proc.start();
    while (true)
    {
        cout << "? ";
        string line;
        if (not getline(cin, line))
            return 0;
        proc << line << endl;           // a /bin/cat
        if (not proc.good())
        {
            cout << "el tiempo límite del hijo se excedió\n";
            break;
        }
    }
    cout << "tiempo límite de 5 segundos del /bin/cat alcanzado: proceso hijo terminado\n";
}

El siguiente ejemplo ilustra la canalización (piping): la información de la entrada estándar del programa se canaliza a un segundo objeto Proc, que escribe su salida estándar en la secuencia de salida estándar del programa:

int main()
{
    Proc proc1{ "/bin/cat" };
    Proc proc2{ "/bin/cat" };
    cin | proc1 | proc2;            // Por defecto, se canaliza a cout. Para hacerlo
                                    // explícitamente, use ’... | proc2 | cout’
}
