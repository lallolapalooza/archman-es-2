NOMBRE

procps_pids - API para acceder a la información de procesos en el sistema de archivos /proc

SINOPSIS

#include <libproc2/pids.h>
int procps_pids_new   (struct pids_info **info, enum pids_item *items, int numitems);
int procps_pids_ref   (struct pids_info  *info);
int procps_pids_unref (struct pids_info **info);
struct pids_stack *procps_pids_get (
    struct pids_info *info,
    enum pids_fetch_type which);
struct pids_fetch *procps_pids_reap (
    struct pids_info *info,
    enum pids_fetch_type which);
struct pids_fetch *procps_pids_select (
    struct pids_info *info,
    unsigned *these,
    int numthese,
    enum pids_select_type which);
struct pids_stack **procps_pids_sort (
    struct pids_info *info,
    struct pids_stack *stacks[],
    int numstacked,
    enum pids_item sortitem,
    enum pids_sort_order order);
int procps_pids_reset (
    struct pids_info *info,
    enum pids_item *newitems,
    int newnumitems);
struct pids_stack *fatal_proc_unmounted (
    struct pids_info *info,
    int return_self);

Enlazar con -lproc2.

DESCRIPCIÓN

Visión general

Central en esta interfaz hay una simple estructura de 'resultado' que refleja un 'ítem' más su valor (en una unión con tipos C estándar como miembros). Todas las estructuras de 'resultado' son asignadas automáticamente y proporcionadas por la biblioteca.

Especificando un array de 'ítems', estas estructuras pueden ser organizadas como una 'pila', produciendo potencialmente muchos resultados con una sola llamada a función. Así, una 'pila' puede ser vista como un registro de longitud variable cuyo contenido y orden está determinado únicamente por el usuario.

Como parte de esta interfaz existen dos enumeradores únicos. Los ítems 'noop' y 'extra' existen para contener valores de usuario. Nunca son establecidos por la biblioteca, pero el resultado 'extra' se pondrá a cero con cada interacción de la biblioteca.

El archivo pids.h será un documento esencial durante el desarrollo de programas de usuario. Allí encontrará los ítems disponibles, su tipo de retorno (el nombre del miembro de la struct 'result') y la fuente para dichos valores. Enumeradores y estructuras adicionales también se documentan allí.

Uso

La siguiente sería una secuencia típica de llamadas a esta interfaz.

1. fatal_proc_unmounted()
2. procps_pids_new()
3. procps_pids_get(), procps_pids_reap() o procps_pids_select()
4. procps_pids_unref()

La función get es un iterador para PIDs/TIDs sucesivos, retornando aquellos 'ítems' previamente identificados a través de new o reset.

Dos funciones soportan resultados variables impredecibles. La función reap recopila datos para todos los procesos mientras que la función select maneja PIDs o UIDs específicos. Ambas pueden devolver múltiples 'pilas', cada una conteniendo múltiples estructuras de 'resultado'. Opcionalmente, un usuario puede elegir sort dichos resultados

Para explotar cualquier 'pila' y acceder a las estructuras de 'resultado' individuales, se requiere un enum_relativo como se muestra en la macro VAL definida en el archivo de cabecera. Dichos valores podrían ser codificados de forma rígida como: 0 a numitems-1. Sin embargo, esta necesidad se satisface típicamente creando sus propios enumeradores correspondientes al orden del array de 'ítems'.

Advertencias

La API <pids> difiere de otras en que los ítems de interés deben ser proporcionados en el momento de new o reset, siendo este último único para esta API. Si el parámetro items o numitems es cero en el momento de new, entonces reset se vuelve obligatorio antes de emitir cualquier otra llamada. De lo contrario, procps_pids_reset() solo debe ser llamado cuando el orden o el número de ítems en sus pilas cambie.

Para las funciones new y unref, se debe suministrar la dirección de un puntero a la struct info. Con new debe haber sido inicializado a NULL. Con unref se restablecerá a NULL si el contador de referencias llega a cero.

Las funciones get y reap usan el parámetro which para especificar si solo se deben obtener tareas o tanto tareas como hilos.

La función select requiere un array de PIDs o UIDs como these junto con numthese para identificar qué procesos se deben obtener. Esta función opera entonces como un subconjunto de reap.

Al usar la función sort, los parámetros stacks y numstacked normalmente serían los devueltos en la estructura 'pids_fetch'.

Finalmente, se puede llamar a una función fatal_proc_unmounted antes de cualquier otra función para asegurar que el directorio /proc/ está montado. Como tal, el parámetro info sería NULL y el parámetro return_self cero. Si, sin embargo, se desean algunos ítems para el programa emisor (un return_self distinto de cero), entonces la llamada new debe precederla para identificar los items y obtener el puntero info requerido.

VALOR DE RETORNO

Funciones que devuelven un 'int'

Un error se indicará con un número negativo que es siempre el inverso de algún valor conocido de errno.h.

El éxito se indica con un valor de retorno cero. Sin embargo, las funciones ref y unref devuelven el contador de referencias de la estructura info actual.

Funciones que devuelven una 'dirección'

Un error se indicará con un puntero NULL y la razón se encontrará en el valor formal de errno.

El éxito se indica con un puntero a la estructura nombrada. Sin embargo, si se sobrevive a la llamada fatal_proc_unmounted, NULL siempre se devuelve cuando return_self es cero.

DEPURACIÓN

Para ayudar en el desarrollo de programas, hay dos provisiones de procps-ng que se pueden explotar.

La primera es un archivo suministrado llamado 'libproc.supp' que puede ser útil al desarrollar una aplicación multihilo. Cuando se usa con la opción '--suppressions=' de valgrind, se evitan las advertencias asociadas con la propia biblioteca procps.

Dichas advertencias surgen porque la biblioteca maneja asignaciones basadas en heap de forma segura para hilos. Una aplicación monohilo no recibirá esas advertencias.

La segunda provisión puede ayudar a asegurar que las referencias a miembros de 'resultado' concuerden con las expectativas de la biblioteca. Asume que una macro suministrada en el archivo de cabecera se usa para acceder al valor de 'resultado'.

Esta característica se puede activar a través de cualquiera de los siguientes métodos y cualquier discrepancia se escribirá en stderr.

1)
Añada CFLAGS='-DXTRA_PROCPS_DEBUG' a cualquier otra opción de ./configure que su proyecto pueda emplear.
2)
Añada #include <libproc2/xtra-procps-debug.h> a cualquier programa después de #include <libproc2/pids.h>.

Esta característica de verificación incurre en un sobrecoste sustancial. Por lo tanto, es importante que no se active para una compilación de producción/lanzamiento.

VARIABLE DE ENTORNO(S)

El valor establecido para lo siguiente no es importante, solo su presencia.

LIBPROC_HIDE_KERNEL
Esto ocultará los hilos del kernel que de otro modo serían devueltos con una llamada a procps_pids_get, procps_pids_select o procps_pids_reap.

procps_pids - get PIDs of processes belonging to a group

NAME

procps_pids - get PIDs of processes belonging to a group

SYNOPSIS

#include <proc/proc.h>

pid_t *procps_pids(int group, int *count);

DESCRIPTION

The procps_pids function retrieves the process IDs (PIDs) of all processes that belong to the specified group. The group argument specifies the process group ID.

The function allocates and returns an array of pid_t values. The number of PIDs found is stored in the integer pointed to by count.

If no processes are found for the given group, or if an error occurs, the function returns NULL and sets count to 0.

The caller is responsible for freeing the allocated memory for the PID array using free.

RETURN VALUE

On success, returns a pointer to an array of pid_t. On failure, returns NULL.

DEBUGGING

This function does not offer specific debugging options.

ENVIRONMENT VARIABLE(S)

No environment variables affect the behavior of this function.
