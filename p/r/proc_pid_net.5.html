proc_pid_net(5) Manual de formatos de archivo proc_pid_net(5)

NOMBRE

/proc/pid/net/, /proc/net/ - información de la capa de red

DESCRIPCIÓN

/proc/pid/net/ (desde Linux 2.6.25)
Ver la descripción de /proc/net.
/proc/net/
Este directorio contiene varios archivos y subdirectorios que contienen información sobre la capa de red. Los archivos contienen estructuras ASCII y, por lo tanto, son legibles con cat(1). Sin embargo, la suite estándar de netstat(8) proporciona un acceso mucho más limpio a estos archivos.
Con la llegada de los espacios de nombres de red, se virtualiza diversa información relacionada con la pila de red (ver network_namespaces(7)). Por lo tanto, desde Linux 2.6.25, /proc/net es un enlace simbólico al directorio /proc/self/net, que contiene los mismos archivos y directorios que se enumeran a continuación. Sin embargo, estos archivos y directorios ahora exponen información para el espacio de nombres de red del cual el proceso es miembro.
/proc/net/arp
Esto contiene un volcado legible por ASCII de la tabla ARP del kernel utilizada para las resoluciones de direcciones. Mostrará las entradas ARP aprendidas dinámicamente y las preprogramadas. El formato es:

Dirección IP   Tipo HW   Flags     Dirección HW          Máscara   Dispositivo
192.168.0.50   0x1       0x2       00:50:BF:25:68:F3   *      eth0
192.168.0.250  0x1       0xc       00:00:00:00:00:00   *      eth0

Aquí "Dirección IP" es la dirección IPv4 de la máquina y el "Tipo HW" es el tipo de hardware de la dirección de RFC 826. Las flags son las flags internas de la estructura ARP (como se define en /usr/include/linux/if_arp.h) y la "Dirección HW" es el mapeo de la capa de enlace de datos para esa dirección IP si se conoce.
/proc/net/dev
El pseudofichero dev contiene información sobre el estado de los dispositivos de red. Esto proporciona el número de paquetes recibidos y enviados, el número de errores y colisiones y otras estadísticas básicas. Estos son utilizados por el programa ifconfig(8) para informar del estado del dispositivo. El formato es:
Inter-|   Recepción                                              |  Transmisión
 faz   |bytes    paquetes errs drop fifo frame comprimido multicast|bytes    paquetes errs drop fifo colli portador comprimido
    lo: 2776770   11307    0    0    0     0          0         0  2776770   11307    0    0    0     0       0          0
  eth0: 1215645    2751    0    0    0     0          0         0  1782404    4324    0    0    0   427       0          0
  ppp0: 1622270    5552    1    0    0     0          0         0   354130    5669    0    0    0     0       0          0
  tap0:    7714      81    0    0    0     0          0         0     7714      81    0    0    0     0       0          0
/proc/net/dev_mcast
Definido en /usr/src/linux/net/core/dev_mcast.c:

indx nombre_interfaz  dmi_u dmi_g dmi_direccion
2    eth0            1     0     01005e000001
3    eth1            1     0     01005e000001
4    eth2            1     0     01005e000001

/proc/net/igmp
Protocolo de gestión de grupos de Internet. Definido en /usr/src/linux/net/core/igmp.c.
/proc/net/rarp
Este archivo utiliza el mismo formato que el archivo arp y contiene la base de datos de mapeo inverso actual utilizada para proporcionar servicios de búsqueda inversa de direcciones rarp(8). Si RARP no está configurado en el kernel, este archivo no estará presente.
/proc/net/raw
Contiene un volcado de la tabla de sockets RAW. Gran parte de la información no es útil aparte de la depuración. El valor "sl" es la ranura hash del kernel para el socket, la "local_address" es la dirección local y el par de números de protocolo. "St" es el estado interno del socket. "tx_queue" y "rx_queue" son las colas de datos salientes y entrantes en términos de uso de memoria del kernel. Los campos "tr", "tm->when" y "rexmits" no son utilizados por RAW. El campo "uid" contiene el UID efectivo del creador del socket.
/proc/net/snmp
Este archivo contiene los datos ASCII necesarios para las bases de información de gestión IP, ICMP, TCP y UDP para un agente SNMP.
/proc/net/tcp
Contiene un volcado de la tabla de sockets TCP. Gran parte de la información no es útil aparte de la depuración. El valor "sl" es la ranura hash del kernel para el socket, la "local_address" es la dirección local y el par de números de puerto. La "rem_address" es la dirección remota y el par de números de puerto (si está conectado). "St" es el estado interno del socket. "tx_queue" y "rx_queue" son las colas de datos salientes y entrantes en términos de uso de memoria del kernel. Los campos "tr", "tm->when" y "rexmits" contienen información interna del estado del socket del kernel y solo son útiles para la depuración. El campo "uid" contiene el UID efectivo del creador del socket.
/proc/net/udp
Contiene un volcado de la tabla de sockets UDP. Gran parte de la información no es útil aparte de la depuración. El valor "sl" es la ranura hash del kernel para el socket, la "local_address" es la dirección local y el par de números de puerto. La "rem_address" es la dirección remota y el par de números de puerto (si está conectado). "St" es el estado interno del socket. "tx_queue" y "rx_queue" son las colas de datos salientes y entrantes en términos de uso de memoria del kernel. Los campos "tr", "tm->when" y "rexmits" no son utilizados por UDP. El campo "uid" contiene el UID efectivo del creador del socket. El formato es:
sl  local_address rem_address   st tx_queue rx_queue tr rexmits  tm->when uid
 1: 01642C89:0201 0C642C89:03FF 01 00000000:00000001 01:000071BA 00000000 0
 1: 00000000:0801 00000000:0000 0A 00000000:00000000 00:00000000 6F000100 0
 1: 00000000:0201 00000000:0000 0A 00000000:00000000 00:00000000 00000000 0
/proc/net/unix
Enumera los sockets de dominio UNIX presentes en el sistema y su estado. El formato es:
Num RefCount Protocol Flags    Type St Inode Path
 0: 00000002 00000000 00000000 0001 03    42
 1: 00000001 00000000 00010000 0001 01  1948 /dev/printer
Los campos son los siguientes:
Num:
el número de ranura de la tabla del kernel.
RefCount:
el número de usuarios del socket.
Protocol:
actualmente siempre 0.
Flags:
las flags internas del kernel que contienen el estado del socket.
Type:
el tipo de socket. Para sockets SOCK_STREAM, es 0001; para sockets SOCK_DGRAM, es 0002; y para sockets SOCK_SEQPACKET, es 0005.
St:
el estado interno del socket.
Inode:
el número de inodo del socket.
Path:
el nombre de ruta enlazado (si lo hay) del socket. Los sockets en el espacio de nombres abstracto se incluyen en la lista y se muestran con un Path que comienza con el carácter '@'.
/proc/net/netfilter/nfnetlink_queue
Este archivo contiene información sobre la cola de usuario netfilter, si se utiliza. Cada línea representa una cola. No se muestran las colas a las que el espacio de usuario no se ha suscrito.

   1   4207     0  2 65535     0     0        0  1
  (1)   (2)    (3)(4)  (5)    (6)   (7)      (8)

Los campos en cada l
(1)
La ID de la cola. Esto coincide con lo especificado en las opciones --queue-num o --queue-balance del objetivo iptables(8) NFQUEUE. Consulte iptables-extensions(8) para más información.
(2)
La ID del puerto netlink suscrito a la cola.
(3)
El número de paquetes actualmente en cola y esperando a ser procesados por la aplicación.
(4)
El modo de copia de la cola. Es 1 (solo metadatos) o 2 (también copia los datos del payload al espacio de usuario).
(5)
Rango de copia; es decir, cuántos bytes del payload del paquete se copiarán al espacio de usuario como máximo.
(6)
Cola descartada. Número de paquetes que tuvieron que ser descartados por el kernel debido a que demasiados paquetes ya estaban esperando que el espacio de usuario enviara de vuelta los veredictos obligatorios de aceptación/descarte.
(7)
Cola descartada por el usuario. Número de paquetes que fueron descartados dentro del subsistema netlink. Estos descartes suelen ocurrir cuando el búfer de socket correspondiente está lleno; es decir, el espacio de usuario no puede leer los mensajes lo suficientemente rápido.
(8)
Número de secuencia. Cada paquete en cola se asocia con un número de secuencia monótonamente creciente (de 32 bits). Esto muestra la ID del paquete más reciente encolado.
El último número existe solo por razones de compatibilidad y es siempre 1.
