PROGRESS(1) Manual de Comandos Generales PROGRESS(1)

NOMBRE

progress - Visor de progreso de Coreutils

SINOPSIS

progress [ -qdwmM ] [ -W secs ] [ -c comando ] [ -a comando ] [ -p pid ]
progress -v | --version
progress -h | --help

DESCRIPCIÓN

Esta página del manual documenta brevemente el comando progress.

Esta herramienta se puede describir como un comando C pequeño, sucio, que busca comandos básicos de coreutils (cp, mv, dd, tar, gzip/gunzip, cat, etc.) que se están ejecutando actualmente en su sistema y muestra el porcentaje de datos copiados.

Ahora también puede estimar el rendimiento (usando la opción -w).

OPCIONES

-q (--quiet)
oculta todos los mensajes
-d (--debug)
muestra todos los mensajes de advertencia/error
-w (--wait)
estima el rendimiento de I/O y el tiempo restante estimado (visualización más lenta)
-W (--wait-delay secs)
espera 'secs' segundos para la estimación de I/O (implica -w)
-m (--monitor)
se repite mientras los procesos monitoreados sigan en ejecución
-M (--monitor-continuously)
como monitor pero nunca se detiene (similar a watch progress)
-c (--command cmd)
monitorea solo este nombre de comando (ej: firefox). Esta opción se puede usar múltiples veces en la línea de comandos.
-a (--additional-command cmd)
agrega este comando a la lista predeterminada. Esta opción se puede usar múltiples veces en la línea de comandos.
-p (--pid id)
monitorea solo este ID de proceso numérico (ej: `pidof firefox`). Esta opción se puede usar múltiples veces en la línea de comandos.
-i (--ignore-file file)
no reportar un proceso para 'file'. Si el archivo aún no existe, debes proporcionar una ruta absoluta completa y limpia. Esta opción se puede usar múltiples veces en la línea de comandos.
-o (--open-mode {r|w})
reportar solo archivos abiertos para lectura (r) o escritura (w) por el proceso. Esta opción es útil cuando deseas monitorear solo los archivos de salida (o de entrada) de un proceso.
-v (--version)
muestra la versión del programa y sale
-h (--help)
muestra el mensaje de ayuda y sale

AMBIENTE

Es posible proporcionar opciones permanentes usando la variable de entorno PROGRESS_ARGS. Ver el ejemplo a continuación. Los argumentos de la línea de comandos tienen precedencia sobre el entorno.

EJEMPLOS

Monitorear continuamente todas las instancias actuales y futuras de comandos coreutils

watch progress -q

Ver cómo progresa tu descarga

watch progress -wc firefox

Observar la actividad de tu servidor Web

progress -c httpd

Lanzar y monitorear cualquier comando pesado usando $!

cp bigfile newfile & progress -mp $!

Usar la variable de entorno para establecer argumentos permanentes (múltiples)

export PROGRESS_ARGS='-M --ignore-file ~/.xsession-errors'

ERRORES

Por favor, reporta errores en: http://github.com/Xfennec/progress/issues
