NOMBRE

property - Propiedades, un mecanismo de selección para implementaciones de algoritmos

DESCRIPCIÓN

A partir de OpenSSL 3.0, se ha introducido un nuevo método para decidir qué implementación de un algoritmo se utilizará entre varias disponibles. El método se centra en el concepto de propiedades. Cada implementación define un número de propiedades y, cuando se selecciona un algoritmo, se pueden usar filtros basados en estas propiedades para elegir la implementación más apropiada del algoritmo.

Las propiedades son como variables, se referencian por nombre y se les asigna un valor.

Nombres de Propiedad

Los nombres de propiedad se dividen en dos categorías: los reservados por el proyecto OpenSSL y los definidos por el usuario. Un nombre de propiedad reservado consiste en un único identificador estilo C (excepto que los guiones bajos iniciales no están permitidos), que comienza con una letra y puede ser seguido por cualquier número de letras, números y guiones bajos. Los nombres de propiedad no distinguen entre mayúsculas y minúsculas, pero OpenSSL solo usará letras minúsculas.

Un nombre de propiedad definido por el usuario es similar, pero debe consistir en dos o más identificadores estilo C, separados por puntos. El último identificador del nombre puede considerarse el nombre de propiedad 'verdadero', que va precedido por algún tipo de 'espacio de nombres'. Los proveedores, por ejemplo, podrían incluir su nombre en el prefijo y usar nombres de propiedad como

<nombre_proveedor>.<nombre_propiedad>
<nombre_proveedor>.<nombre_algoritmo>.<nombre_propiedad>

Propiedades

Una propiedad es un par nombre=valor. Una definición de propiedad es una secuencia de propiedades separadas por comas. Puede haber cualquier número de propiedades en una definición, sin embargo, cada nombre debe ser único. Por ejemplo: "" define una definición de propiedad vacía (es decir, sin restricciones); "mi.foo=bar" define una propiedad llamada mi.foo que tiene un valor de cadena bar y "iteracion.cuenta=3" define una propiedad llamada iteracion.cuenta que tiene un valor numérico de 3. La sintaxis completa para las definiciones de propiedad aparece a continuación.

Implementaciones

Cada implementación de un algoritmo puede definir cualquier número de propiedades. Por ejemplo, el proveedor predeterminado define la propiedad proveedor=predeterminado para todos sus algoritmos. De manera similar, el proveedor FIPS de OpenSSL define proveedor=fips y el proveedor legado define proveedor=legado para todos sus algoritmos.

Consultas

Una cláusula de consulta de propiedad es una única prueba condicional. Por ejemplo, "fips=yes", "proveedor!=predeterminado" o "?iteracion.cuenta=3". Las dos primeras representan cláusulas obligatorias; tales cláusulas deben coincidir para que cualquier algoritmo sea siquiera considerado. La tercera cláusula representa una cláusula opcional. La coincidencia de tales cláusulas no es un requisito, pero cualquier coincidencia adicional de cláusulas opcionales cuenta a favor del algoritmo. Más detalles sobre esto en la sección Búsquedas. Una consulta de propiedad es una secuencia de cláusulas de consulta de propiedad separadas por comas. Es un error si un nombre de propiedad aparece en más de una cláusula de consulta. La sintaxis completa para las consultas de propiedad aparece a continuación, pero las características sintácticas disponibles son:

  • = es un operador infijo que proporciona una prueba de igualdad.
  • != es un operador infijo que proporciona una prueba de desigualdad.
  • ? es un operador prefijo que significa que la cláusula siguiente es opcional pero preferida.
  • - es un operador prefijo que significa que cualquier cláusula de consulta global que involucre el siguiente nombre de propiedad debe ser ignorada.
  • "..." es una cadena entre comillas. Las comillas no se incluyen en el cuerpo de la cadena.
  • '...' es una cadena entre comillas. Las comillas no se incluyen en el cuerpo de la cadena.

Búsquedas

Cuando se busca un algoritmo, se utiliza una consulta de propiedad para determinar el mejor algoritmo coincidente. Todas las cláusulas de consulta obligatorias deben estar presentes y se utilizará la implementación que, además, tenga el mayor número de cláusulas de consulta opcionales coincidentes. Si hay más de un candidato óptimo de este tipo, el resultado se elegirá entre ellos de manera indeterminada. El orden de las cláusulas opcionales no es significativo.

Atajo

Para permitir una expresión más concisa de propiedades booleanas, existe un atajo: un nombre de propiedad solo (por ejemplo, "mi.propiedad") es exactamente equivalente a "mi.propiedad=sí" tanto en definiciones como en consultas.

Global y Local

Se admiten dos niveles de consulta de propiedades. Una consulta de propiedad basada en el contexto que se aplica a todas las operaciones de recuperación y una consulta de propiedad local. Cuando tanto la consulta de contexto como la local incluyen una cláusula con el mismo nombre, la cláusula local anula la cláusula de contexto.

Es posible que una consulta de propiedad local elimine una cláusula en la consulta de propiedad del contexto anteponiendo un '-' al nombre de la propiedad. Por ejemplo, una consulta de propiedad de contexto que contenga "fips=sí" normalmente resultaría en implementaciones que tengan "fips=sí".

Sin embargo, si la configuración de la propiedad "fips" es irrelevante para las operaciones que se están realizando, la consulta de propiedad local puede incluir la cláusula "-fips". Tenga en cuenta que la consulta de propiedad local no podría usar "fips=no" porque eso desautorizaría cualquier implementación con "fips=sí" en lugar de no importarle la configuración.

SINTAXIS

La sintaxis léxica en EBNF viene dada por:

Definición     ::= NombrePropiedad ( '=' Valor )?
                       ( ',' NombrePropiedad ( '=' Valor )? )*
Consulta       ::= ConsultaPropiedad ( ',' ConsultaPropiedad )*
ConsultaPropiedad ::= '-' NombrePropiedad
                 | '?'? ( NombrePropiedad (( '=' | '!=' ) Valor)?)
Valor          ::= LiteralNumero | LiteralCadena
LiteralCadena  ::= CadenaEntreComillas | CadenaSinComillas
CadenaEntreComillas ::= '"' [^"]* '"' | "'" [^']* "'"
CadenaSinComillas ::= [A-Za-z] [^{espacio},]+
LiteralNumero  ::= '0' ( [0-7]* | 'x' [0-9A-Fa-f]+ ) | '-'? [1-9] [0-9]+
NombrePropiedad   ::= [A-Za-z] [A-Za-z0-9_]* ( '.' [A-Za-z] [A-Za-z0-9_]* )*

El tipo de EBNF que se está utilizando se define en: https://www.w3.org/TR/2010/REC-xquery-20101214/#EBNFNotation.
