proc_sys_kernel(5) Manual de formatos de archivo proc_sys_kernel(5)

NOMBRE

proc_sys_kernel(5) — controlar un rango de parámetros del kernel

DESCRIPCIÓN

/proc/sys/kernel/
Este directorio contiene archivos que controlan un rango de parámetros del kernel, como se describe a continuación.
/proc/sys/kernel/acct
Este archivo contiene tres números: highwater, lowwater y frequency. Si la contabilidad de procesos estilo BSD está habilitada, estos valores controlan su comportamiento. Si el espacio libre en el sistema de archivos donde se encuentra el registro cae por debajo del lowwater por ciento, la contabilidad se suspende. Si el espacio libre supera el highwater por ciento, la contabilidad se reanuda. frequency determina con qué frecuencia el kernel verifica la cantidad de espacio libre (el valor está en segundos). Los valores predeterminados son 4, 2 y 30. Es decir, suspender la contabilidad si queda un 2% o menos de espacio libre; reanudarla si queda un 4% o más de espacio libre; considerar la información sobre la cantidad de espacio libre válida durante 30 segundos.
/proc/sys/kernel/auto_msgmni (Linux 2.6.27 a Linux 3.18)
Desde Linux 2.6.27 hasta Linux 3.18, este archivo se usaba para controlar el recálculo del valor en /proc/sys/kernel/msgmni tras la adición o eliminación de memoria o la creación/eliminación de un espacio de nombres IPC. Escribir "1" en este archivo habilitaba el recálculo automático de msgmni (y desencadenaba un recálculo de msgmni basado en la cantidad actual de memoria disponible y el número de espacios de nombres IPC). Escribir "0" deshabilitaba el recálculo automático. (El recalculo automático también se deshabilitaba si se asignaba un valor explícitamente a /proc/sys/kernel/msgmni.) El valor predeterminado en auto_msgmni era 1.
Desde Linux 3.19, el contenido de este archivo no tiene efecto (porque msgmni tiene un valor predeterminado cercano al máximo posible), y las lecturas de este archivo siempre devuelven el valor "0".
/proc/sys/kernel/cap_last_cap (desde Linux 3.2)
Ver capabilities(7).
/proc/sys/kernel/cap-bound (desde Linux 2.2 hasta Linux 2.6.24)
Este archivo contiene el valor del conjunto de capacidades limitantes del kernel (expresado como un número decimal con signo). Este conjunto se combina mediante un AND con las capacidades permitidas a un proceso durante execve(2). A partir de Linux 2.6.25, el conjunto de capacidades limitantes a nivel de sistema desapareció y fue reemplazado por un conjunto limitante por hilo; ver capabilities(7).
/proc/sys/kernel/core_pattern
Ver core(5).
/proc/sys/kernel/core_pipe_limit
Ver core(5).
/proc/sys/kernel/core_uses_pid
Ver core(5).
/proc/sys/kernel/ctrl-alt-del
Este archivo controla el manejo de Ctrl-Alt-Del desde el teclado. Cuando el valor en este archivo es 0, Ctrl-Alt-Del es interceptado y enviado al programa init(1) para manejar un reinicio ordenado. Cuando el valor es mayor que cero, la reacción de Linux a un Pinch de Nervios Vulcano (tm) será un reinicio inmediato, sin siquiera sincronizar sus búferes sucios. Nota: cuando un programa (como dosemu) tiene el teclado en modo "crudo", el Ctrl-Alt-Del es interceptado por el programa antes de que llegue a la capa tty del kernel, y depende del programa decidir qué hacer con él.
/proc/sys/kernel/dmesg_restrict (desde Linux 2.6.37)
El valor en este archivo determina quién puede ver el contenido del syslog del kernel. Un valor de 0 en este archivo no impone restricciones. Si el valor es 1, solo los usuarios privilegiados pueden leer el syslog del kernel. (Ver syslog(2) para más detalles.) Desde Linux 3.4, solo los usuarios con la capacidad CAP_SYS_ADMIN pueden cambiar el valor en este archivo.
/proc/sys/kernel/domainname
/proc/sys/kernel/hostname
se pueden usar para configurar el nombre de dominio NIS/YP y el nombre de host de tu máquina de la misma manera que los comandos domainname(1) y hostname(1), es decir:

# echo 'darkstar' > /proc/sys/kernel/hostname
# echo 'mydomain' > /proc/sys/kernel/domainname

tiene el mismo efecto que

# hostname 'darkstar'
# domainname 'mydomain'

Sin embargo, ten en cuenta que el clásico darkstar.frop.org tiene el nombre de host "darkstar" y el nombre de dominio DNS (Servidor de Nombres de Dominio de Internet) "frop.org", que no debe confundirse con el nombre de dominio NIS (Servicio de Información de Red) o YP (Páginas Amarillas). Estos dos nombres de dominio son generalmente diferentes. Para una discusión detallada, consulta la página del manual de hostname(1).
/proc/sys/kernel/hotplug
Este archivo contiene la ruta del agente de política de hotplug. El valor predeterminado en este archivo es /sbin/hotplug.
/proc/sys/kernel/htab-reclaim (antes de Linux 2.4.9.2)
(Solo PowerPC) Si este archivo se establece en un valor distinto de cero, la tabla htab de PowerPC (ver el archivo del kernel Documentation/powerpc/ppc_htab.txt) se poda cada vez que el sistema entra en el bucle inactivo.
/proc/sys/kernel/keys/
Este directorio contiene varios archivos que definen parámetros y límites para la instalación de gestión de claves. Estos archivos se describen en keyrings(7).
/proc/sys/kernel/kptr_restrict (desde Linux 2.6.38)
El valor en este archivo determina si las direcciones del kernel se exponen a través de los archivos de /proc y otras interfaces. Un valor de 0 en este archivo no impone restricciones. Si el valor es 1, los punteros del kernel impresos con el especificador de formato %pK serán reemplazados por ceros a menos que el usuario tenga la capacidad CAP_SYSLOG. Si el valor es 2, los punteros del kernel impresos con el especificador de formato %pK serán reemplazados por ceros independientemente de las capacidades del usuario. El valor predeterminado inicial para este archivo fue 1, pero el valor predeterminado se cambió a 0 en Linux 2.6.39. Desde Linux 3.4, solo los usuarios con la capacidad CAP_SYS_ADMIN pueden cambiar el valor en este archivo.
/proc/sys/kernel/l2cr
(Solo PowerPC) Este archivo contiene una bandera que controla la caché L2 de las placas procesador G3. Si es 0, la caché está deshabilitada. Habilitada si es distinto de cero.
/proc/sys/kernel/modprobe
Este archivo contiene la ruta del cargador de módulos del kernel. El valor predeterminado es /sbin/modprobe. El archivo solo está presente si el kernel está compilado con la opción CONFIG_MODULES (CONFIG_KMOD en Linux 2.6.26 y anteriores) habilitada. Está descrito por el archivo fuente del kernel de Linux Documentation/kmod.txt (presente solo en Linux 2.4 y anteriores).
/proc/sys/kernel/modules_disabled (desde Linux 2.6.31)
Un valor de alternancia que indica si se permite cargar módulos en un kernel que de otro modo sería modular. Esta alternancia por defecto está desactivada (0), pero puede establecerse en verdadera (1). Una vez activada, los módulos no pueden cargarse ni descargarse, y la alternancia no puede volver a ponerse en falsa. El archivo solo está presente si el kernel está compilado con la opción CONFIG_MODULES habilitada.
/proc/sys/kernel/msgmax (desde Linux 2.2)
Este archivo define un límite a nivel de sistema que especifica el número máximo de bytes en un único mensaje escrito en una cola de mensajes de System V.
/proc/sys/kernel/msgmni (desde Linux 2.4)
Este archivo define el límite a nivel de sistema en el número de identificadores de cola de mensajes. Ver también /proc/sys/kernel/auto_msgmni.
/proc/sys/kernel/msgmnb (desde Linux 2.2)
Este archivo define un parámetro a nivel de sistema utilizado para inicializar la configuración msg_qbytes para las colas de mensajes creadas posteriormente. La configuración msg_qbytes especifica el número máximo de bytes que se pueden escribir en la cola de mensajes.
/proc/sys/kernel/ngroups_max (desde Linux 2.6.4)
Este es un archivo de solo lectura que muestra el límite superior en el número de membresías de grupo de un proceso.
/proc/sys/kernel/ns_last_pid (desde Linux 3.3)
Ver pid_namespaces(7).
/proc/sys/kernel/ostype
/proc/sys/kernel/osrelease
Estos archivos proporcionan subcadenas de /proc/version.
/proc/sys/kernel/overflowgid

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

/proc/sys/kernel/overflowuid
Estos archivos duplican los archivos /proc/sys/fs/overflowgid y /proc/sys/fs/overflowuid.
/proc/sys/kernel/panic
Este archivo proporciona acceso de lectura/escritura a la variable del kernel panic_timeout. Si es cero, el kernel se quedará en un bucle ante un pánico; si es distinto de cero, indica que el kernel debe reiniciarse automáticamente después de este número de segundos. Cuando se utiliza el controlador de dispositivo watchdog, la configuración recomendada es 60.
/proc/sys/kernel/panic_on_oops (desde Linux 2.5.68)
Este archivo controla el comportamiento del kernel cuando se encuentra un oops o un BUG. Si este archivo contiene 0, el sistema intenta continuar la operación. Si contiene 1, el sistema se retrasa unos segundos (para dar tiempo a klogd a registrar la salida del oops) y luego entra en pánico. Si el archivo /proc/sys/kernel/panic también es distinto de cero, la máquina se reiniciará.
/proc/sys/kernel/pid_max (desde Linux 2.5.34)
Este archivo especifica el valor en el que los PID se reinician (es decir, el valor en este archivo es uno más que el PID máximo). Los PID mayores que este valor no se asignan; por lo tanto, el valor en este archivo también actúa como un límite a nivel de sistema para el número total de procesos e hilos. El valor predeterminado para este archivo, 32768, resulta en el mismo rango de PID que en kernels anteriores. En plataformas de 32 bits, 32768 es el valor máximo para pid_max. En sistemas de 64 bits, pid_max se puede establecer a cualquier valor hasta 2^22 (PID_MAX_LIMIT, aproximadamente 4 millones).
/proc/sys/kernel/powersave-nap (Solo PowerPC)
Este archivo contiene un indicador. Si está activado, Linux-PPC utilizará el modo "nap" de ahorro de energía, de lo contrario se utilizará el modo "doze".
/proc/sys/kernel/printk
Ver syslog(2).
/proc/sys/kernel/pty (desde Linux 2.6.4)
Este directorio contiene dos archivos relacionados con el número de pseudoterminales UNIX 98 (ver pts(4)) en el sistema.
/proc/sys/kernel/pty/max
Este archivo define el número máximo de pseudoterminales.
/proc/sys/kernel/pty/nr
Este archivo de solo lectura indica cuántos pseudoterminales están actualmente en uso.
/proc/sys/kernel/random/
Este directorio contiene varios parámetros que controlan el funcionamiento del archivo /dev/random. Ver random(4) para más información.
/proc/sys/kernel/random/uuid (desde Linux 2.4)
Cada lectura de este archivo de solo lectura devuelve un UUID aleatorio de 128 bits, como una cadena en el formato UUID estándar.
/proc/sys/kernel/randomize_va_space (desde Linux 2.6.12)
Selecciona la política de aleatorización del diseño del espacio de direcciones (ASLR) para el sistema (en arquitecturas que soportan ASLR). Se admiten tres valores para este archivo:
0
Desactiva ASLR. Este es el valor predeterminado para las arquitecturas que no soportan ASLR y cuando el kernel se inicia con el parámetro norandmaps.
1
Aleatoriza las direcciones de las asignaciones de mmap(2), la pila y la página VDSO. Entre otras cosas, esto significa que las bibliotecas compartidas se cargarán en direcciones aleatorias. El segmento de texto de los binarios enlazados con PIE también se cargará en una dirección aleatoria. Este valor es el predeterminado si el kernel se configuró con CONFIG_COMPAT_BRK.
2
(Desde Linux 2.6.25) También admite la aleatorización del heap. Este valor es el predeterminado si el kernel no se configuró con CONFIG_COMPAT_BRK.
/proc/sys/kernel/real-root-dev
Este archivo está documentado en el archivo fuente del kernel de Linux Documentation/admin-guide/initrd.rst (o Documentation/initrd.txt antes de Linux 4.10).
/proc/sys/kernel/reboot-cmd (Solo Sparc)
Este archivo parece ser una forma de pasar un argumento al cargador de arranque ROM/Flash de SPARC. ¿Quizás para indicarle qué hacer después de reiniciar?
/proc/sys/kernel/rtsig-max
(Hasta e incluyendo Linux 2.6.7; ver setrlimit(2)) Este archivo se puede utilizar para ajustar el número máximo de señales POSIX de tiempo real (en cola) que pueden estar pendientes en el sistema.
/proc/sys/kernel/rtsig-nr
(Hasta e incluyendo Linux 2.6.7.) Este archivo muestra el número de señales POSIX de tiempo real que están actualmente en cola.
/proc/pid/sched_autogroup_enabled (desde Linux 2.6.38)
Ver sched(7).
/proc/sys/kernel/sched_child_runs_first (desde Linux 2.6.23)
Si este archivo contiene el valor cero, entonces, después de un fork(2), el progenitor se planifica primero en la CPU. Si el archivo contiene un valor distinto de cero, entonces el hijo se planifica primero en la CPU. (Por supuesto, en un sistema multiprocesador, el progenitor y el hijo podrían ser planificados simultáneamente en una CPU).
/proc/sys/kernel/sched_rr_timeslice_ms (desde Linux 3.9)
Ver sched_rr_get_interval(2).
/proc/sys/kernel/sched_rt_period_us (desde Linux 2.6.25)
Ver sched(7).
/proc/sys/kernel/sched_rt_runtime_us (desde Linux 2.6.25)
Ver sched(7).
/proc/sys/kernel/seccomp/ (desde Linux 4.14)
Este directorio proporciona información y configuración adicional de seccomp. Ver seccomp(2) para más detalles.
/proc/sys/kernel/sem (desde Linux 2.4)
Este archivo contiene 4 números que definen los límites para los semáforos IPC de System V. Estos campos son, en orden:
SEMMSL
El número máximo de semáforos por conjunto de semáforos.
SEMMNS
Un límite a nivel de sistema para el número de semáforos en todos los conjuntos de semáforos.
SEMOPM
El número máximo de operaciones que se pueden especificar en una llamada a semop(2).
SEMMNI
Un límite a nivel de sistema para el número máximo de identificadores de semáforos.
/proc/sys/kernel/sg-big-buff
Este archivo muestra el tamaño del búfer del dispositivo genérico SCSI (sg). Aún no se puede ajustar, pero se podría cambiar en tiempo de compilación editando include/scsi/sg.h y cambiando el valor de SG_BIG_BUFF. Sin embargo, no debería haber ninguna razón para cambiar este valor.
/proc/sys/kernel/shm_rmid_forced (desde Linux 3.1)
Si este archivo se establece en 1, todos los segmentos de memoria compartida de System V se marcarán para su destrucción tan pronto como el número de procesos adjuntos caiga a cero; en otras palabras, ya no es posible crear segmentos de memoria compartida que existan independientemente de cualquier proceso adjunto.
El efecto es como si se realizara un IPC_RMID de shmctl(2) en todos los segmentos existentes, así como en todos los segmentos creados en el futuro (hasta que este archivo se restablezca a 0). Tenga en cuenta que los segmentos existentes que no están adjuntos a ningún proceso serán destruidos inmediatamente cuando este archivo se establezca en 1. Establecer esta opción también destruirá los segmentos que se crearon, pero nunca se adjuntaron, al terminar el proceso que creó el segmento con shmget(2).
Establecer este archivo en 1 proporciona una forma de asegurar que todos los segmentos de memoria compartida de System V se cuenten contra el uso de recursos y los límites de recursos (ver la descripción de RLIMIT_AS en getrlimit(2)) de al menos un proceso.
Dado que establecer este archivo en 1 produce un comportamiento no estándar y también podría romper aplicaciones existentes, el valor predeterminado en este archivo es 0. Establezca este archivo en 1 solo si comprende bien la semántica de las aplicaciones que utilizan memoria compartida de System V en su sistema.
/proc/sys/kernel/shmall (desde Linux 2.2)
Este archivo contiene el límite a nivel de sistema para el número total de páginas de memoria compartida de System V.
/proc/sys/kernel/shmmax (desde Linux 2.2)
Este archivo se puede utilizar para consultar y establecer el límite en tiempo de ejecución para el tamaño máximo de segmento de memoria compartida (IPC de System V) que se puede crear. Los segmentos de memoria compartida de hasta 1 GB ahora son compatibles en el kernel. Este valor predeterminado es SHMMAX.
/proc/sys/kernel/shmmni (desde Linux 2.4)
Este archivo especifica el número máximo a nivel de sistema de segmentos de memoria compartida de System V que se pueden crear.
/proc/sys/kernel/sysctl_writes_strict (desde Linux 3.16)
El valor en este archivo determina cómo el desplazamiento del archivo afecta el comportamiento de la actualización de entradas en archivos bajo /proc/sys. El archivo tiene tres valores posibles:
-1
Esto proporciona un manejo heredado, sin advertencias de printk. Cada write(2) debe contener completamente el valor a escribir, y escrituras múltiples en el mismo descriptor de archivo sobrescribirán el valor completo, independientemente de la posición del archivo.
0
(predeterminado) Esto proporciona el mismo comportamiento que para -1, pero se escriben advertencias de printk para los procesos que realizan escrituras cuando el desplazamiento del archivo no es 0.
1
Respeta el desplazamiento del archivo al escribir cadenas en archivos de /proc/sys. Las escrituras múltiples se añadirán al búfer de valor. Cualquier cosa escrita más allá de la longitud máxima del búfer de valor será ignorada. Las escrituras a entradas numéricas de /proc/sys siempre deben estar en el desplazamiento 0 y el valor debe estar completamente contenido en el búfer proporcionado a write(2).
/proc/sys/kernel/sysrq
Este archivo controla las funciones permitidas para ser invocadas por la tecla SysRq. Por defecto, el archivo contiene 1, lo que significa que se permiten todas las solicitudes SysRq posibles (en versiones anteriores del kernel, SysRq estaba deshabilitado por defecto y se requería habilitarlo específicamente en tiempo de ejecución, pero esto ya no es así). Los valores posibles en este archivo son:
0
Deshabilita sysrq por completo
1
Habilita todas las funciones de sysrq
> 1
Máscara de bits de las funciones sysrq permitidas, como sigue:
  2
Habilita el control del nivel de registro de la consola
  4
Habilita el control del teclado (SAK, unraw)
  8
Habilita volcados de depuración de procesos, etc.
 16
Habilita el comando sync
 32
Habilita la remonta como solo lectura
 64
Habilitar la señalización de procesos (term, kill, oom-kill)
128
Permitir reinicio/apagado
256
Permitir la priorización (nicing) de todas las tareas en tiempo real
Este archivo solo está presente si la opción de configuración del kernel CONFIG_MAGIC_SYSRQ está habilitada. Para más detalles, consulte el archivo de origen del kernel de Linux Documentation/admin-guide/sysrq.rst (o Documentation/sysrq.txt antes de Linux 4.10).
/proc/sys/kernel/version
Este archivo contiene una cadena como:

#5 Wed Feb 25 21:49:24 MET 1998

El "#5" significa que este es el quinto kernel construido a partir de esta base de código fuente y la fecha que le sigue indica la hora en que se compiló el kernel.
/proc/sys/kernel/threads-max (desde Linux 2.3.11)
Este archivo especifica el límite a nivel de sistema para el número de hilos (tareas) que se pueden crear en el sistema.
Desde Linux 4.1, el valor que se puede escribir en threads-max está limitado. El valor mínimo que se puede escribir es 20. El valor máximo que se puede escribir viene dado por la constante FUTEX_TID_MASK (0x3fffffff). Si se escribe un valor fuera de este rango en threads-max, se produce el error EINVAL.
El valor escrito se comprueba con las páginas de RAM disponibles. Si las estructuras de hilos ocuparan demasiado (más de 1/8) de las páginas de RAM disponibles, threads-max se reduciría en consecuencia.
/proc/sys/kernel/yama/ptrace_scope (desde Linux 3.5)
Véase ptrace(2).
/proc/sys/kernel/zero-paged (solo PowerPC)
Este archivo contiene una bandera. Cuando está habilitado (distinto de cero), Linux-PPC pre-pondrá páginas en el bucle inactivo, lo que podría acelerar get_free_pages.
