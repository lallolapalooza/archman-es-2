NOMBRE

provider-mac - Funciones de la biblioteca mac <-> provider

SINAPSIS

#include <openssl/core_dispatch.h>
#include <openssl/core_names.h>
/*
 * Ninguna de estas son funciones reales, sino que se muestran como
 * las firmas de función para funciones que se ofrecen como punteros de función
 * en arrays OSSL_DISPATCH.
 */
/* Gestión de contexto */
void *OSSL_FUNC_mac_newctx(void *provctx);
void OSSL_FUNC_mac_freectx(void *mctx);
void *OSSL_FUNC_mac_dupctx(void *src);
/* Cifrado/descifrado */
int OSSL_FUNC_mac_init(void *mctx, unsigned char *key, size_t keylen,
                       const OSSL_PARAM params[]);
int OSSL_FUNC_mac_init_skey(void *mctx, const void *key, const OSSL_PARAM params[]);
int OSSL_FUNC_mac_update(void *mctx, const unsigned char *in, size_t inl);
int OSSL_FUNC_mac_final(void *mctx, unsigned char *out, size_t *outl, size_t outsize);
/* Descriptores de parámetros MAC */
const OSSL_PARAM *OSSL_FUNC_mac_gettable_params(void *provctx);
const OSSL_PARAM *OSSL_FUNC_mac_gettable_ctx_params(void *mctx, void *provctx);
const OSSL_PARAM *OSSL_FUNC_mac_settable_ctx_params(void *mctx, void *provctx);
/* Parámetros MAC */
int OSSL_FUNC_mac_get_params(OSSL_PARAM params[]);
int OSSL_FUNC_mac_get_ctx_params(void *mctx, OSSL_PARAM params[]);
int OSSL_FUNC_mac_set_ctx_params(void *mctx, const OSSL_PARAM params[]);

DESCRIPCIÓN

Esta documentación está dirigida principalmente a los autores de proveedores. Consulte provider(7) para obtener más información.

La operación MAC permite a los proveedores implementar algoritmos mac y hacerlos disponibles para las aplicaciones a través de las funciones de la API EVP_MAC_init(3), EVP_MAC_update(3) y EVP_MAC_final(3).

Todas las "funciones" mencionadas aquí se pasan como punteros de función entre libcrypto y el proveedor en arrays OSSL_DISPATCH(3) a través de arrays OSSL_ALGORITHM(3) que son devueltos por la función provider_query_operation() del proveedor (véase "Funciones del Proveedor" en provider-base(7)).

Todas estas "funciones" tienen una definición de tipo de función correspondiente llamada OSSL_FUNC_{name}_fn, y una función auxiliar para recuperar el puntero de función de un elemento OSSL_DISPATCH(3) llamada OSSL_FUNC_{name}. Por ejemplo, la "función" OSSL_FUNC_mac_newctx() tiene:

typedef void *(OSSL_FUNC_mac_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_mac_newctx_fn
    OSSL_FUNC_mac_newctx(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) Los arrays se indexan mediante números que se proporcionan como macros en openssl-core_dispatch.h(7), de la siguiente manera:

OSSL_FUNC_mac_newctx               OSSL_FUNC_MAC_NEWCTX
OSSL_FUNC_mac_freectx              OSSL_FUNC_MAC_FREECTX
OSSL_FUNC_mac_dupctx               OSSL_FUNC_MAC_DUPCTX
OSSL_FUNC_mac_init                 OSSL_FUNC_MAC_INIT
OSSL_FUNC_mac_init_skey            OSSL_FUNC_MAC_INIT_SKEY
OSSL_FUNC_mac_update               OSSL_FUNC_MAC_UPDATE
OSSL_FUNC_mac_final                OSSL_FUNC_MAC_FINAL
OSSL_FUNC_mac_get_params           OSSL_FUNC_MAC_GET_PARAMS
OSSL_FUNC_mac_get_ctx_params       OSSL_FUNC_MAC_GET_CTX_PARAMS
OSSL_FUNC_mac_set_ctx_params       OSSL_FUNC_MAC_SET_CTX_PARAMS
OSSL_FUNC_mac_gettable_params      OSSL_FUNC_MAC_GETTABLE_PARAMS
OSSL_FUNC_mac_gettable_ctx_params  OSSL_FUNC_MAC_GETTABLE_CTX_PARAMS
OSSL_FUNC_mac_settable_ctx_params  OSSL_FUNC_MAC_SETTABLE_CTX_PARAMS

Una implementación de algoritmo mac puede no implementar todas estas funciones. Para ser un conjunto coherente de funciones, se deben implementar al menos las siguientes funciones: OSSL_FUNC_mac_newctx(), OSSL_FUNC_mac_freectx(), al menos una de OSSL_FUNC_mac_init() o OSSL_FUNC_mac_init_skey(), OSSL_FUNC_mac_update(), OSSL_FUNC_mac_final(). Todas las demás funciones son opcionales.

Funciones de Gestión de Contexto

OSSL_FUNC_mac_newctx() debe crear y devolver un puntero a una estructura del lado del proveedor para mantener información de contexto durante una operación mac. Un puntero a este contexto se pasará de vuelta en varias de las otras llamadas a funciones de operación mac. El parámetro provctx es el contexto del proveedor generado durante la inicialización del proveedor (véase provider(7)).

OSSL_FUNC_mac_freectx() recibe un puntero al contexto mac del lado del proveedor en el parámetro mctx. Si recibe NULL como valor mctx, no debe hacer nada más que devolver. Esta función debe liberar todos los recursos asociados con ese contexto.

OSSL_FUNC_mac_dupctx() debe duplicar el contexto mac del lado del proveedor en el parámetro mctx y devolver una copia duplicada.

Funciones de Cifrado/Descifrado

OSSL_FUNC_mac_init() inicializa una operación mac dada un contexto mac del lado del proveedor recién creado en el parámetro mctx. Los params se establecen antes de establecer la clave MAC de keylen bytes.

OSSL_FUNC_mac_init_skey() es similar pero utiliza un objeto opaco específico del proveedor para inicializar el contexto MAC.

OSSL_FUNC_mac_update() se llama para suministrar datos para la computación MAC de una operación mac previamente inicializada. El parámetro mctx contiene un puntero a un contexto del lado del proveedor previamente inicializado. OSSL_FUNC_mac_update() puede ser llamado múltiples veces para una sola operación mac.

OSSL_FUNC_mac_final() completa la computación MAC iniciada a través de llamadas anteriores a OSSL_FUNC_mac_init() y OSSL_FUNC_mac_update(). El parámetro mctx contiene un puntero al contexto del lado del proveedor. El MAC resultante debe escribirse en out y la cantidad de datos escritos en *outl, que no debe exceder outsize bytes. Las mismas expectativas se aplican a outsize como se documenta para EVP_MAC_final(3).

Parámetros Mac

Consulte OSSL_PARAM(3) para obtener más detalles sobre la estructura de parámetros utilizada por estas funciones.

OSSL_FUNC_mac_get_params() obtiene detalles de los valores de parámetros asociados con el algoritmo del proveedor y los almacena en params.

OSSL_FUNC_mac_set_ctx_params() establece parámetros mac asociados con el contexto mac del lado del proveedor dado mctx a params. Cualquier configuración de parámetro es adicional a cualquier configuración previa. Pasar NULL para params debería devolver true.

OSSL_FUNC_mac_get_ctx_params() obtiene detalles de los valores de parámetros actualmente establecidos asociados con el contexto mac del lado del proveedor dado mctx y los almacena en params. Pasar NULL para params debería devolver true.

OSSL_FUNC_mac_gettable_params(), OSSL_FUNC_mac_gettable_ctx_params(), y OSSL_FUNC_mac_settable_ctx_params() devuelven todos arrays constantes de OSSL_PARAM(3) como descriptores de los parámetros que OSSL_FUNC_mac_get_params(), OSSL_FUNC_mac_get_ctx_params(), y OSSL_FUNC_mac_set_ctx_params() pueden manejar, respectivamente. OSSL_FUNC_mac_gettable_ctx_params() y OSSL_FUNC_mac_settable_ctx_params() devolverán los parámetros asociados con el contexto del lado del proveedor mctx en su estado actual si no es NULL. De lo contrario, devuelven los parámetros asociados con el algoritmo del lado del proveedor provctx.

Se espera que todas las implementaciones de MAC manejen los siguientes parámetros:

con OSSL_FUNC_set_ctx_params():
"key" (OSSL_MAC_PARAM_KEY) <cadena de octetos>
Establece la clave en el contexto MAC asociado. Esto es idéntico a pasar un argumento key a la función OSSL_FUNC_mac_init().
con OSSL_FUNC_get_params():
"size" (OSSL_MAC_PARAM_SIZE) <entero>
Se puede usar para obtener el tamaño MAC predeterminado (que podría ser el único tamaño MAC permitido para la implementación).

NAME

provider-mac - MAC Algorithm Provider Interface

SYNOPSIS

The MAC provider interface is defined in the following header files:

 #include <openssl/core_dispatch.h>
 #include <openssl/evp.h>
 #include <openssl/params.h>

The following functions are available:

 OSSL_CORE_CTX *OSSL_FUNC_provider_get_core_ctx(const OSSL_PROVIDER *provider);
 OSSL_FUNC_mac_newctx_fn *OSSL_FUNC_mac_newctx(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_dupctx_fn *OSSL_FUNC_mac_dupctx(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_freectx_fn *OSSL_FUNC_mac_freectx(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_init_fn *OSSL_FUNC_mac_init(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_init_skey_fn *OSSL_FUNC_mac_init_skey(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_update_fn *OSSL_FUNC_mac_update(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_final_fn *OSSL_FUNC_mac_final(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_get_params_fn *OSSL_FUNC_mac_get_params(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_get_ctx_params_fn *OSSL_FUNC_mac_get_ctx_params(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_set_ctx_params_fn *OSSL_FUNC_mac_set_ctx_params(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_gettable_params_fn *OSSL_FUNC_mac_gettable_params(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_gettable_ctx_params_fn *OSSL_FUNC_mac_gettable_ctx_params(OSSL_DISPATCH *dispatch);
 OSSL_FUNC_mac_settable_ctx_params_fn *OSSL_FUNC_mac_settable_ctx_params(OSSL_DISPATCH *dispatch);

DESCRIPTION

This is an interface description for a MAC (Message Authentication Code) algorithm provider. A provider is a dynamic library that can be loaded by the OpenSSL library to provide cryptographic functionality. This document describes the MAC functions that a provider must implement if it wishes to offer MAC algorithms.

The functions are grouped by category. The core functions are:

OSSL_FUNC_mac_newctx
Creates a new MAC context. This context is provider-specific and opaque to the OpenSSL library.
OSSL_FUNC_mac_dupctx
Duplicates an existing MAC context. This is useful for parallelization.
OSSL_FUNC_mac_freectx
Frees a MAC context.
OSSL_FUNC_mac_init
Initializes a MAC context. This function is used when the MAC algorithm does not need a key, or when the key is provided via OSSL_FUNC_mac_set_ctx_params. The parameters can include algorithm-specific options.
OSSL_FUNC_mac_init_skey
Initializes a MAC context with a key. This is the preferred way to initialize a MAC context. The parameters can include algorithm-specific options.
OSSL_FUNC_mac_update
Feeds data into the MAC algorithm. This function can be called multiple times.
OSSL_FUNC_mac_final
Computes the MAC tag from the data fed so far and returns it. The MAC context is reset after this call, ready to be used again.

The following functions are used for retrieving and setting parameters:

OSSL_FUNC_mac_get_params
Retrieves generic MAC parameters. See EVP_MAC(3) for supported parameters.
OSSL_FUNC_mac_get_ctx_params
Retrieves MAC context-specific parameters.
OSSL_FUNC_mac_set_ctx_params
Sets MAC context-specific parameters. This function should typically be called before OSSL_FUNC_mac_init or OSSL_FUNC_mac_init_skey.
OSSL_FUNC_mac_gettable_params
Returns a list of generic parameters that can be retrieved using OSSL_FUNC_mac_get_params.
OSSL_FUNC_mac_gettable_ctx_params
Returns a list of context-specific parameters that can be retrieved using OSSL_FUNC_mac_get_ctx_params.
OSSL_FUNC_mac_settable_ctx_params
Returns a list of context-specific parameters that can be set using OSSL_FUNC_mac_set_ctx_params.

The following parameters are supported:

"digest" (OSSL_MAC_PARAM_DIGEST) <utf8 string>
This is a setter for digests that are used in MAC constructions, such as HMAC. It specifies the name of the digest to use. This must be set before calling init.
"custom-digest" (OSSL_MAC_PARAM_CUSTOM_DIGEST) <X509_DIGEST_INFO*>
This is a setter for digests that are used in MAC constructions, such as HMAC. It specifies the digest by reference. This must be set before calling init.
"digest-size" (OSSL_MAC_PARAM_DIGEST_SIZE) <size_t>
A getter for the size of the digest output. This is the same as the MAC output size.
"tls-operand" (OSSL_MAC_PARAM_TLS_OPERAND) <octet string>
A setter for the operand used in TLS.
"mac" (OSSL_MAC_PARAM_MAC) <octet string>
A setter for the MAC value. This is used in TLS.
"dtls-operand" (OSSL_MAC_PARAM_DTLS_OPERAND) <octet string>
A setter for the operand used in DTLS.
"dtls-mac" (OSSL_MAC_PARAM_DTLS_MAC) <octet string>
A setter for the MAC value used in DTLS.
"data" (OSSL_MAC_PARAM_DATA) <octet string>
A setter for arbitrary data.
"key-check" (OSSL_MAC_PARAM_KEY_CHECK) <boolean>
A setter that enables or disables key checking. When enabled (the default), an error is returned if the key is too small for the MAC algorithm. When disabled, no error is returned, but this may impact FIPS compliance. See the FIPS provider section below.
"no-short-mac" (OSSL_MAC_PARAM_NO_SHORT_MAC) <boolean>
A setter that enables or disables the check for short MAC output. When enabled (the default), an error is returned if the requested MAC output size is smaller than the algorithm's block size. When disabled, no error is returned, but this may impact FIPS compliance. See the FIPS provider section below.
"truncatable" (OSSL_MAC_PARAM_TRUNCATABLE) <boolean>
A getter that returns 1 if the MAC algorithm supports truncation (i.e. can produce a shorter MAC than its natural output size).
"length" (OSSL_MAC_PARAM_LENGTH) <size_t>
A setter for the desired output MAC length. This is used when truncatable is true. If this is set to a value other than 0, it overrides the default length, which is usually the algorithm's natural output size. The value must be less than or equal to the natural output size. Note that the actual MAC length will be returned via the output parameter of type size_t in the final call.
"block-size" (OSSL_MAC_PARAM_BLOCK_SIZE) <integer>
Can be used to get the MAC block size (if supported by the algorithm).
"size" (OSSL_MAC_PARAM_BLOCK_SIZE) <integer>
Can be used to get the MAC block size (if supported by the algorithm).

The OpenSSL FIPS provider may support the following parameters:

"fips-indicator" (OSSL_MAC_PARAM_FIPS_APPROVED_INDICATOR) <int>
A getter that returns 1 if the operation is FIPS approved, or 0 otherwise. This may be used after calling the final function. It may return 0 if either "no-short-mac" or "key-check" are set to 0.
"no-short-mac" (OSSL_MAC_PARAM_FIPS_NO_SHORT_MAC) <integer>
If required this parameter should be set early via an init function. The default value of 1 causes an error when too short MAC output is asked for. Setting this to 0 will ignore the error and set the approved "fips-indicator" to 0. This option breaks FIPS compliance if it causes the approved "fips-indicator" to return 0.
"key-check" (OSSL_MAC_PARAM_FIPS_KEY_CHECK) <integer>
If required this parameter should be set before OSSL_FUNC_mac_init. The default value of 1 causes an error when small key sizes are asked for. Setting this to 0 will ignore the error and set the approved "fips-indicator" to 0. This option breaks FIPS compliance if it causes the approved "fips-indicator" to return 0.

NOTES

The MAC life-cycle is described in life_cycle-rand(7). Providers should ensure that the various transitions listed there are supported. At some point the EVP layer will begin enforcing the listed transitions.

RETURN VALUES

OSSL_FUNC_mac_newctx() and OSSL_FUNC_mac_dupctx() should return the newly created provider side mac context, or NULL on failure.

OSSL_FUNC_mac_init(), OSSL_FUNC_mac_init_skey(), OSSL_FUNC_mac_update(), OSSL_FUNC_mac_final(), OSSL_FUNC_mac_get_params(), OSSL_FUNC_mac_get_ctx_params() and OSSL_FUNC_mac_set_ctx_params() should return 1 for success or 0 on error.

OSSL_FUNC_mac_gettable_params(), OSSL_FUNC_mac_gettable_ctx_params() and OSSL_FUNC_mac_settable_ctx_params() should return a constant OSSL_PARAM(3) array, or NULL if none is offered.

HISTORY

The provider MAC interface was introduced in OpenSSL 3.0. The parameters "no-short-mac" and "fips-indicator" were added in OpenSSL 3.4.

The function OSSL_FUNC_mac_init_skey() was introduced in OpenSSL 3.5.
