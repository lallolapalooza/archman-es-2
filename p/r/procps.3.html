PROCPS(3) Manual de funciones de biblioteca PROCPS(3)

NOMBRE

procps - API para acceder a información a nivel de sistema en el sistema de archivos /proc

SINOPSIS

Cinco interfaces distintas se representan en esta sinopsis y llevan el nombre de los archivos a los que acceden en el sistema de archivos pseudo /proc: diskstats, meminfo, slabinfo, stat y vmstat.

#include <libproc2/named_interface.h>
int procps_new   (struct info **info);
int procps_ref   (struct info  *info);
int procps_unref (struct info **info);
struct result *procps_get (
    struct info *info,
[   const char *name,      ]   solo API diskstats
    enum item item);
struct stack *procps_select (
    struct info *info,
[   const char *name,      ]   solo API diskstats
    enum item *items,
    int numitems);
struct reaped *procps_reap (
    struct info *info,
[   enum reap_type what,   ]   solo API stat
    enum item *items,
    int numitems);
struct stack **procps_sort (
    struct info *info,
    struct stack *stacks[],
    int numstacked,
    enum item sortitem,
    enum sort_order order);

Las funciones y estructuras anteriores son genéricas, pero la named_interface específica también formaría parte de cualquier identificador. Por ejemplo, 'procps_new' sería en realidad 'procps_meminfo_new' y 'info' sería realmente 'diskstats_info', etc.

El mismo named_interface se utiliza en el nombre de cada archivo de encabezado con el sufijo '.h' añadido.

Enlazar con -lproc2.

DESCRIPCIÓN

Resumen

Central a estas interfaces es una estructura simple de 'resultado' que refleja un 'elemento' más su valor (en una unión con tipos estándar del lenguaje C como miembros). Todas las estructuras de 'resultado' son asignadas automáticamente y proporcionadas por la biblioteca.

Especificando un array de 'elementos', estas estructuras pueden organizarse como una 'pila', produciendo potencialmente muchos resultados con una sola llamada a función. Por lo tanto, una 'pila' puede verse como un registro de longitud variable cuyo contenido y orden están determinados únicamente por el usuario.

Como parte de cada interfaz hay dos enumeradores únicos. Los elementos 'noop' y 'extra' existen para contener valores de usuario. Nunca son establecidos por la biblioteca, pero el resultado 'extra' se pondrá a cero con cada interacción de la biblioteca.

El archivo de encabezado named_interface será un documento esencial durante el desarrollo de programas de usuario. Allí encontrará los elementos disponibles, su tipo de retorno (el nombre del miembro de la estructura 'result') y la fuente de dichos valores. Enumeradores y estructuras adicionales también se documentan allí.

Uso

La siguiente sería una secuencia típica de llamadas a estas interfaces.

1. procps_new()
2. procps_get(), procps_select() o procps_reap()
3. procps_unref()

La función get se utiliza para recuperar una estructura de 'resultado' para un solo 'elemento'. Alternativamente, una macro GET está disponible cuando solo el valor de retorno es de interés.

La función select puede recuperar múltiples estructuras de 'resultado' en una sola 'pila'.

Para resultados variables impredecibles, las interfaces diskstats, slabinfo y stat exportan una función reap. Se utiliza para recuperar múltiples 'pilas', cada una conteniendo múltiples estructuras de 'resultado'. Opcionalmente, un usuario puede elegir sortear esos resultados.

Para explotar cualquier 'pila' y acceder a las estructuras de 'resultado' individuales, se requiere un relative_enum como se muestra en la macro VAL definida en el archivo de encabezado. Tales valores podrían ser codificados de forma fija como: 0 hasta numitems-1. Sin embargo, esta necesidad se satisface típicamente creando sus propios enumeradores que corresponden al orden del array de 'elementos'.

Advertencias

Las funciones new, ref, unref, get y select están disponibles en las cinco interfaces.

Para las funciones new y unref, se debe suministrar la dirección de un puntero a la estructura info. Con new debe haber sido inicializado a NULL. Con unref se restablecerá a NULL si el contador de referencias llega a cero.

En el caso de la interfaz diskstats, un parámetro name en las funciones get y select identifica el nombre de un disco o partición.

Para la interfaz stat, un parámetro what en la función reap identifica si se deben recopilar datos solo de las CPUs o tanto de las CPUs como de los nodos NUMA.

Al utilizar la función sort, los parámetros stacks y numstacked normalmente serían los devueltos en la estructura 'reaped'.

VALOR DEVUELTO

Funciones que devuelven un 'int'

Se indicará un error mediante un número negativo que es siempre la inversa de algún valor bien conocido de errno.h.

El éxito se indica mediante un valor de retorno cero. Sin embargo, las funciones ref y unref devuelven el contador de referencias de la estructura info actual.

Funciones que devuelven una 'dirección'

Se indicará un error mediante un puntero NULL de retorno con la razón encontrada en el valor formal de errno.

El éxito se indica mediante un puntero a la estructura nombrada.

DEPURACIÓN

Para ayudar en el desarrollo de programas, existe una provisión que puede ayudar a asegurar que las referencias a los miembros de 'resultado' concuerden con las expectativas de la biblioteca. Asume que se utiliza una macro proporcionada en el archivo de encabezado para acceder al valor de 'resultado'.

Esta característica se puede activar mediante cualquiera de los siguientes métodos y cualquier discrepancia se escribirá en stderr.

1)
Añada CFLAGS='-DXTRA_PROCPS_DEBUG' a cualquier otra opción de ./configure empleada.
2)
Añada #include <libproc2/xtra-procps-debug.h> a cualquier programa después de las inclusiones de la interfaz nombrada.

Esta característica de verificación incurre en una sobrecarga sustancial. Por lo tanto, es importante que no se active para una compilación de producción/lanzamiento.

VER TAMBIÉN

procps_misc(3), procps_pids(3), proc(5).

    procps — process management utilities

    NAME

    procps — process management utilities

    SYNOPSIS

    procps is a collection of programs that provide process management information.

    DESCRIPTION

    The procps package provides several command-line utilities for managing and monitoring processes on Linux systems. These tools interact with the /proc filesystem to retrieve and manipulate process information.

    COMMANDS

    The primary commands included in procps are:

    • ps: Reports a snapshot of the current processes.
    • top: Displays Linux processes.
    • free: Displays the amount of free and used memory in the system.
    • kill: Sends a signal to a process.
    • pgrep: Looks up or signals processes based on name and other attributes.
    • pkill: Signals processes based on name and other attributes.
    • pmap: Reports the memory map of a process.
    • pstree: Lists processes in a tree-like format.

    OPTIONS

    Each command in the procps suite has its own set of options. Refer to the individual man pages for detailed information:

    • man ps
    • man top
    • man free
    • man kill
    • man pgrep
    • man pkill
    • man pmap
    • man pstree

    FILES

    • /proc: The virtual filesystem that contains process and system information.

    ENVIRONMENT

    Various environment variables can affect the behavior of procps utilities, such as PAGER for output paging.

    EXIT STATUS

    Exit statuses vary depending on the command. Typically, 0 indicates success, and a non-zero value indicates an error.

    AUTHOR

    procps utilities have been developed and maintained by a number of individuals over the years. The original author is likely unknown, but key contributors include Robert Sanders, Albert Cahalan, and others.

    ps(1), top(1), free(1), kill(1), pgrep(1), pkill(1), pmap(1), pstree(1), proc(5)
