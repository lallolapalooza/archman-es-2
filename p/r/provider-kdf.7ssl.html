NOMBRE

provider-kdf - Funciones de biblioteca KDF <-> proveedor

SINOPSIS

#include <openssl/core_dispatch.h>
#include <openssl/core_names.h>
/*
 * Ninguna de estas son funciones reales, sino que se muestran como
 * las firmas de funciones para las funciones que se ofrecen como punteros
 * de función en arrays OSSL_DISPATCH.
 */
/* Gestión de contexto */
void *OSSL_FUNC_kdf_newctx(void *provctx);
void OSSL_FUNC_kdf_freectx(void *kctx);
void *OSSL_FUNC_kdf_dupctx(void *src);
/* Cifrado/descifrado */
int OSSL_FUNC_kdf_reset(void *kctx);
int OSSL_FUNC_kdf_derive(void *kctx, unsigned char *key, size_t keylen,
                         const OSSL_PARAM params[]);
void *OSSL_FUNC_kdf_derive_skey(void *ctx, const char *key_type, void *provctx,
                                OSSL_FUNC_skeymgmt_import_fn *import,
                                size_t keylen, const OSSL_PARAM params[]);
/* Descriptores de parámetros KDF */
const OSSL_PARAM *OSSL_FUNC_kdf_gettable_params(void *provctx);
const OSSL_PARAM *OSSL_FUNC_kdf_gettable_ctx_params(void *kcxt, void *provctx);
const OSSL_PARAM *OSSL_FUNC_kdf_settable_ctx_params(void *kcxt, void *provctx);
/* Parámetros KDF */
int OSSL_FUNC_kdf_get_params(OSSL_PARAM params[]);
int OSSL_FUNC_kdf_get_ctx_params(void *kctx, OSSL_PARAM params[]);
int OSSL_FUNC_kdf_set_ctx_params(void *kctx, const OSSL_PARAM params[]);
int OSSL_FUNC_kdf_set_skey(void *kctx, void *skeydata, const char *paramname);

DESCRIPCIÓN

Esta documentación está dirigida principalmente a los autores de proveedores. Consulte provider(7) para obtener más información.

La operación KDF permite a los proveedores implementar algoritmos KDF y ponerlos a disposición de las aplicaciones a través de las funciones de API EVP_KDF_CTX_reset(3) y EVP_KDF_derive(3).

Todas las "funciones" mencionadas aquí se pasan como punteros de función entre libcrypto y el proveedor en arrays OSSL_DISPATCH(3) a través de arrays OSSL_ALGORITHM(3) que son devueltos por la función provider_query_operation() del proveedor (ver "Funciones del Proveedor" en provider-base(7)).

Todas estas "funciones" tienen una definición de tipo de función correspondiente llamada OSSL_FUNC_{name}_fn y una función auxiliar para recuperar el puntero de función de un elemento de OSSL_DISPATCH(3) llamada OSSL_FUNC_{name}. Por ejemplo, la "función" OSSL_FUNC_kdf_newctx() tiene estas:

typedef void *(OSSL_FUNC_kdf_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_kdf_newctx_fn
    OSSL_FUNC_kdf_newctx(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) los elementos del array se identifican por números que se proporcionan como macros en openssl-core_dispatch.h(7), como sigue:

OSSL_FUNC_kdf_newctx               OSSL_FUNC_KDF_NEWCTX
OSSL_FUNC_kdf_freectx              OSSL_FUNC_KDF_FREECTX
OSSL_FUNC_kdf_dupctx               OSSL_FUNC_KDF_DUPCTX
OSSL_FUNC_kdf_reset                OSSL_FUNC_KDF_RESET
OSSL_FUNC_kdf_derive               OSSL_FUNC_KDF_DERIVE
OSSL_FUNC_kdf_derive_skey          OSSL_FUNC_KDF_DERIVE_SKEY
OSSL_FUNC_kdf_get_params           OSSL_FUNC_KDF_GET_PARAMS
OSSL_FUNC_kdf_get_ctx_params       OSSL_FUNC_KDF_GET_CTX_PARAMS
OSSL_FUNC_kdf_set_ctx_params       OSSL_FUNC_KDF_SET_CTX_PARAMS
OSSL_FUNC_kdf_gettable_params      OSSL_FUNC_KDF_GETTABLE_PARAMS
OSSL_FUNC_kdf_gettable_ctx_params  OSSL_FUNC_KDF_GETTABLE_CTX_PARAMS
OSSL_FUNC_kdf_settable_ctx_params  OSSL_FUNC_KDF_SETTABLE_CTX_PARAMS
OSSL_FUNC_kdf_set_skey             OSSL_FUNC_KDF_SET_SKEY

Una implementación de algoritmo KDF puede no implementar todas estas funciones. Para ser un conjunto coherente de funciones, al menos las siguientes funciones deben ser implementadas: OSSL_FUNC_kdf_newctx(), OSSL_FUNC_kdf_freectx(), OSSL_FUNC_kdf_set_ctx_params(), y al menos una de OSSL_FUNC_kdf_derive() o OSSL_FUNC_kdf_derive_skey(). Todas las demás funciones son opcionales.

Funciones de Gestión de Contexto

OSSL_FUNC_kdf_newctx() debe crear y devolver un puntero a una estructura del lado del proveedor para mantener información de contexto durante una operación KDF. Un puntero a este contexto será devuelto en varias de las otras llamadas de función de operación KDF. El parámetro provctx es el contexto del proveedor generado durante la inicialización del proveedor (ver provider(7)).

A OSSL_FUNC_kdf_freectx() se le pasa un puntero al contexto KDF del lado del proveedor en el parámetro kctx. Si recibe NULL como valor de kctx, no debe hacer nada más que retornar. Esta función debe liberar cualquier recurso asociado con ese contexto.

OSSL_FUNC_kdf_dupctx() debe duplicar el contexto KDF del lado del proveedor en el parámetro kctx y devolver la copia duplicada.

Funciones de Cifrado/Descifrado

OSSL_FUNC_kdf_reset() inicializa una operación KDF dado un contexto KDF del lado del proveedor en el parámetro kctx.

OSSL_FUNC_kdf_derive() realiza la operación KDF después de procesar los params según lo especificado en OSSL_FUNC_kdf_set_ctx_params(). El parámetro kctx contiene un puntero al contexto del lado del proveedor. La clave resultante del keylen deseado debe ser escrita en key. Si el algoritmo no soporta el keylen solicitado, la función debe devolver un error.

OSSL_FUNC_kdf_derive_skey() es similar a OSSL_FUNC_kdf_derive() pero utiliza un objeto opaco para almacenar la clave derivada. Acepta el parámetro key_type para dar una pista al proveedor sobre qué tipo de clave (por ejemplo, genérica o AES) se generará y la función import del objeto EVP_SKEYMGMT para asociar con la clave. El objeto EVP_SKEYMGMT proviene del mismo proveedor que el KDF.

Parámetros KDF

Consulte OSSL_PARAM(3) para obtener más detalles sobre la estructura de parámetros utilizada por estas funciones.

OSSL_FUNC_kdf_get_params() obtiene detalles de los valores de parámetros asociados con el algoritmo del proveedor y los almacena en params.

OSSL_FUNC_kdf_set_ctx_params() establece los parámetros KDF asociados con el contexto KDF del lado del proveedor dado kctx a params. Cualquier configuración de parámetros es adicional a las que se establecieron previamente. Pasar NULL para params debe devolver true.

OSSL_FUNC_kdf_get_ctx_params() recupera los valores de parámetros obtenibles asociados con el contexto KDF del lado del proveedor dado kctx y los almacena en params. Pasar NULL para params debe devolver true.

OSSL_FUNC_kdf_gettable_params(), OSSL_FUNC_kdf_gettable_ctx_params(), y OSSL_FUNC_kdf_settable_ctx_params() devuelven arrays constantes de OSSL_PARAM(3) como descriptores de los parámetros que OSSL_FUNC_kdf_get_params(), OSSL_FUNC_kdf_get_ctx_params(), y OSSL_FUNC_kdf_set_ctx_params() pueden manejar, respectivamente. OSSL_FUNC_kdf_gettable_ctx_params() y OSSL_FUNC_kdf_settable_ctx_params() devolverán los parámetros asociados con el contexto del lado del proveedor kctx en su estado actual si no es NULL. De lo contrario, devolverán los parámetros asociados con el algoritmo del lado del proveedor provctx.

OSSL_FUNF_kdf_set_skey() establece la clave de entrada para las funciones KDF que toman una clave como entrada.

Los parámetros actualmente reconocidos por los KDF integrados son los siguientes. No todos los parámetros son relevantes o entendidos por todos los KDF:

"size" (OSSL_KDF_PARAM_SIZE) <entero sin signo>
Obtiene el tamaño de salida del contexto KDF asociado. Si el algoritmo produce una cantidad variable de salida, se debe devolver SIZE_MAX. Si los parámetros de entrada requeridos para calcular el tamaño de salida fijo aún no se han suministrado, se debe devolver 0 indicando un error.
"key" (OSSL_KDF_PARAM_KEY) <cadena de octetos>
Establece la clave en el contexto KDF asociado.
"secret" (OSSL_KDF_PARAM_SECRET) <cadena de octetos>
Establece el secreto en el contexto KDF asociado.
"pass" (OSSL_KDF_PARAM_PASSWORD) <cadena de octetos>
Establece la contraseña en el contexto KDF asociado.

NAME

provider-kdf - Key Derivation Functions (KDF) provider context

SYNOPSIS

#include <openssl/core_numbers.h>

OSSL_FUNC_kdf_newctx(void *provctx)
OSSL_FUNC_kdf_dupctx(void *kdfctx)
OSSL_FUNC_kdf_freectx(void *kdfctx)
OSSL_FUNC_kdf_reset(void *kdfctx)
OSSL_FUNC_kdf_derive(void *kdfctx, unsigned char *key, size_t *keylen, const unsigned char *insecret, size_t insecretlen)
OSSL_FUNC_kdf_get_params(void *kdfctx, OSSL_PARAM params[])
OSSL_FUNC_kdf_set_ctx_params(void *kdfctx, const OSSL_PARAM params[])
OSSL_FUNC_kdf_get_ctx_params(void *kdfctx, OSSL_PARAM params[])
OSSL_FUNC_kdf_gettable_params(void *provctx, void **params)
OSSL_FUNC_kdf_gettable_ctx_params(void *kdfctx, void **params)
OSSL_FUNC_kdf_settable_ctx_params(void *kdfctx, void **params)
OSSL_FUNC_kdf_derive_skey(void *kdfctx, const OSSL_PARAM params[], unsigned char *key, size_t *keylen)
OSSL_FUNC_kdf_set_skey(void *kdfctx, const OSSL_PARAM params[])

DESCRIPTION

The KDF functions provide an abstract interface for key derivation. A provider implements this interface to offer KDF algorithms. The functions listed in the SYNOPSIS are accessed through the OSSL_PROVIDER(3) structure.

A KDF is typically used for deriving cryptographic keys from a shared secret or other less secure material. Examples include password-based key derivation and key derivation for key agreement protocols.

A KDF context is created using OSSL_FUNC_kdf_newctx(). This context holds the state for a KDF operation. The context can be duplicated using OSSL_FUNC_kdf_dupctx(). It should be freed using OSSL_FUNC_kdf_freectx().

The KDF context can be reset using OSSL_FUNC_kdf_reset(). This clears any internal state and parameters, allowing the context to be reused.

The core operation is key derivation, performed by OSSL_FUNC_kdf_derive(). This function takes an optional input secret material and derives a key of a specified length. The parameter keylen is a pointer to the desired key length, and on return, it contains the actual derived key length.

OSSL_FUNC_kdf_derive_skey() is an alternative to OSSL_FUNC_kdf_derive(). It takes the input secret material and other parameters in an OSSL_PARAM(3) array. This function is designed to derive a symmetric key for use with an asymmetric key, for example, in key agreement.

OSSL_FUNC_kdf_set_skey() is used to set the asymmetric key used in conjunction with OSSL_FUNC_kdf_derive_skey(). The parameter is an OSSL_PARAM(3) array.

Parameters for the KDF algorithm are set using OSSL_FUNC_kdf_set_ctx_params() and retrieved using OSSL_FUNC_kdf_get_ctx_params(). The structure of these parameters is defined in the OSSL_PARAM(3) manual page.

Information about settable and gettable parameters is available through OSSL_FUNC_kdf_gettable_params() and OSSL_FUNC_kdf_gettable_ctx_params(), and OSSL_FUNC_kdf_settable_ctx_params() respectively. These functions return an array of OSSL_PARAM(3) structures that describe the parameters.

The following parameters are generally supported, although specific KDF algorithms may support a subset or have additional parameters:

"digest" (OSSL_KDF_PARAM_DIGEST) <UTF8 string>
"mac" (OSSL_KDF_PARAM_MAC) <UTF8 string>
Sets the name of the underlying cipher, digest or MAC to be used. It must name a suitable algorithm for the KDF that's being used.
"maclen" (OSSL_KDF_PARAM_MAC_SIZE) <octet string>
Sets the length of the MAC in the associated KDF ctx.
"properties" (OSSL_KDF_PARAM_PROPERTIES) <UTF8 string>
Sets the properties to be queried when trying to fetch the underlying algorithm. This must be given together with the algorithm naming parameter to be considered valid.
"iter" (OSSL_KDF_PARAM_ITER) <unsigned integer>
Sets the number of iterations in the associated KDF ctx.
"mode" (OSSL_KDF_PARAM_MODE) <UTF8 string>
Sets the mode in the associated KDF ctx.
"pkcs5" (OSSL_KDF_PARAM_PKCS5) <integer>
Enables or disables the SP800-132 compliance checks. A mode of 0 enables the compliance checks.

The checks performed are:

- the iteration count is at least 1000.
- the salt length is at least 128 bits.
- the derived key length is at least 112 bits.
"ukm" (OSSL_KDF_PARAM_UKM) <octet string>
Sets an optional random string that is provided by the sender called "partyAInfo". In CMS this is the user keying material.
"cekalg" (OSSL_KDF_PARAM_CEK_ALG) <UTF8 string>
Sets the CEK wrapping algorithm name in the associated KDF ctx.
"n" (OSSL_KDF_PARAM_SCRYPT_N) <unsigned integer>
Sets the scrypt work factor parameter N in the associated KDF ctx.
"r" (OSSL_KDF_PARAM_SCRYPT_R) <unsigned integer>
Sets the scrypt work factor parameter r in the associated KDF ctx.
"p" (OSSL_KDF_PARAM_SCRYPT_P) <unsigned integer>
Sets the scrypt work factor parameter p in the associated KDF ctx.
"maxmem_bytes" (OSSL_KDF_PARAM_SCRYPT_MAXMEM) <unsigned integer>
Sets the scrypt work factor parameter maxmem in the associated KDF ctx.
"prefix" (OSSL_KDF_PARAM_PREFIX) <octet string>
Sets the prefix string using by the TLS 1.3 version of HKDF in the associated KDF ctx.
"label" (OSSL_KDF_PARAM_LABEL) <octet string>
Sets the label string using by the TLS 1.3 version of HKDF in the associated KDF ctx.
"data" (OSSL_KDF_PARAM_DATA) <octet string>
Sets the context string using by the TLS 1.3 version of HKDF in the associated KDF ctx.
"info" (OSSL_KDF_PARAM_INFO) <octet string>
Sets the optional shared info in the associated KDF ctx.
"seed" (OSSL_KDF_PARAM_SEED) <octet string>
Sets the IV in the associated KDF ctx.
"xcghash" (OSSL_KDF_PARAM_SSHKDF_XCGHASH) <octet string>
Sets the xcghash in the associated KDF ctx.
"session_id" (OSSL_KDF_PARAM_SSHKDF_SESSION_ID) <octet string>
Sets the session ID in the associated KDF ctx.
"type" (OSSL_KDF_PARAM_SSHKDF_TYPE) <UTF8 string>
Sets the SSH KDF type parameter in the associated KDF ctx. There are six supported types:
EVP_KDF_SSHKDF_TYPE_INITIAL_IV_CLI_TO_SRV
The Initial IV from client to server. A single char of value 65 (ASCII char 'A').
EVP_KDF_SSHKDF_TYPE_INITIAL_IV_SRV_TO_CLI
The Initial IV from server to client A single char of value 66 (ASCII char 'B').
EVP_KDF_SSHKDF_TYPE_ENCRYPTION_KEY_CLI_TO_SRV
The Encryption Key from client to server A single char of value 67 (ASCII char 'C').
EVP_KDF_SSHKDF_TYPE_ENCRYPTION_KEY_SRV_TO_CLI
The Encryption Key from server to client A single char of value 68 (ASCII char 'D').
EVP_KDF_SSHKDF_TYPE_INTEGRITY_KEY_CLI_TO_SRV
The Integrity Key from client to server A single char of value 69 (ASCII char 'E').
EVP_KDF_SSHKDF_TYPE_INTEGRITY_KEY_SRV_TO_CLI
The Integrity Key from client to server A single char of value 70 (ASCII char 'F').
"constant" (OSSL_KDF_PARAM_CONSTANT) <octet string>
Sets the constant value in the associated KDF ctx.
"id" (OSSL_KDF_PARAM_PKCS12_ID) <integer>
Sets the intended usage of the output bits in the associated KDF ctx. It is defined as per RFC 7292 section B.3.

RETURN VALUES

OSSL_FUNC_kdf_newctx() and OSSL_FUNC_kdf_dupctx() should return the newly created provider side KDF context, or NULL on failure.

OSSL_FUNC_kdf_derive(), OSSL_FUNC_kdf_derive_skey(), OSSL_FUNC_kdf_get_params(), OSSL_FUNC_kdf_get_ctx_params(), OSSL_FUNC_kdf_set_ctx_params() and OSSL_FUNC_kdf_set_skey() should return 1 for success or 0 on error.

OSSL_FUNC_kdf_gettable_params(), OSSL_FUNC_kdf_gettable_ctx_params() and OSSL_FUNC_kdf_settable_ctx_params() should return a constant OSSL_PARAM(3) array, or NULL if none is offered.

NOTES

The KDF life-cycle is described in life_cycle-kdf(7). Providers should ensure that the various transitions listed there are supported. At some point the EVP layer will begin enforcing the listed transitions.

SEE ALSO

provider(7), life_cycle-kdf(7), EVP_KDF(3).

HISTORY

The provider KDF interface was introduced in OpenSSL 3.0.

OSSL_FUNC_kdf_derive_skey() and OSSL_FUNC_kdf_set_skey() were added in OpenSSL 3.6.
