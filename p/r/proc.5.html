proc(5) Manual de formatos de archivo proc(5)

NOMBRE

proc - información de procesos, información del sistema y sistema de archivos pseudo sysctl

DESCRIPCIÓN

El sistema de archivos proc es un sistema de archivos pseudo que proporciona una interfaz a las estructuras de datos del kernel. Comúnmente se monta en /proc. Típicamente, es montado automáticamente por el sistema, pero también puede montarse manualmente usando un comando como:


mount -t proc proc /proc

La mayoría de los archivos en el sistema de archivos proc son de solo lectura, pero algunos archivos son escribibles, permitiendo cambiar variables del kernel.

Opciones de montaje

El sistema de archivos proc soporta las siguientes opciones de montaje:

hidepid=n (desde Linux 3.3)
Esta opción controla quién puede acceder a la información en los directorios /proc/pid. El argumento, n, es uno de los siguientes valores:
0
Todos pueden acceder a todos los directorios /proc/pid. Este es el comportamiento tradicional, y el predeterminado si esta opción de montaje no se especifica.
1
Los usuarios no pueden acceder a archivos y subdirectorios dentro de ningún directorio /proc/pid excepto los suyos propios (los directorios /proc/pid en sí mismos permanecen visibles). Archivos sensibles como /proc/pid/cmdline y /proc/pid/status ahora están protegidos contra otros usuarios. Esto hace imposible saber si algún usuario está ejecutando un programa específico (siempre que el programa no se revele de otra manera por su comportamiento).
2
Como en el modo 1, pero además los directorios /proc/pid que pertenecen a otros usuarios se vuelven invisibles. Esto significa que las entradas /proc/pid ya no se pueden usar para descubrir las PIDs en el sistema. Esto no oculta el hecho de que un proceso con un valor de PID específico existe (se puede descubrir por otros medios, por ejemplo, con "kill -0 $PID"), pero oculta la UID y GID del proceso, lo que de otro modo se podría aprender utilizando stat(2) en un directorio /proc/pid. Esto complica enormemente la tarea de un atacante para recopilar información sobre procesos en ejecución (por ejemplo, descubrir si algún demonio se está ejecutando con privilegios elevados, si otro usuario está ejecutando algún programa sensible, si otros usuarios están ejecutando algún programa en absoluto, etc.).
gid=gid (desde Linux 3.3)
Especifica la ID de un grupo cuyos miembros están autorizados a conocer información de procesos que de otro modo estaría prohibida por hidepid (es decir, los usuarios de este grupo se comportan como si /proc se hubiera montado con hidepid=0). Este grupo debe usarse en lugar de enfoques como incluir usuarios no root en el archivo sudoers(5).
subset=pid (desde Linux 5.8)
Mostrar solo el subconjunto especificado de procfs, ocultando todos los archivos y directorios de nivel superior en procfs que no están relacionados con tareas.

Visión general

Debajo de /proc, existen los siguientes grupos generales de archivos y subdirectorios:

Subdirectorios /proc/pid
Cada uno de estos subdirectorios contiene archivos y subdirectorios que exponen información sobre el proceso con el ID de proceso correspondiente.
Debajo de cada uno de los directorios /proc/pid, un subdirectorio task contiene subdirectorios de la forma task/tid, que contienen información correspondiente sobre cada uno de los hilos en el proceso, donde tid es el ID del hilo del kernel del hilo.
Los subdirectorios /proc/pid son visibles al iterar por /proc con getdents(2) (y por lo tanto son visibles cuando se usa ls(1) para ver el contenido de /proc).
Subdirectorios /proc/tid
Cada uno de estos subdirectorios contiene archivos y subdirectorios que exponen información sobre el hilo con el ID de hilo correspondiente. Los contenidos de estos directorios son los mismos que los de los directorios correspondientes /proc/pid/task/tid.
Los subdirectorios /proc/tid no son visibles al iterar por /proc con getdents(2) (y por lo tanto no son visibles cuando se usa ls(1) para ver el contenido de /proc).
/proc/self
Cuando un proceso accede a este enlace simbólico mágico, se resuelve en el directorio /proc/pid propio del proceso.
/proc/thread-self
Cuando un hilo accede a este enlace simbólico mágico, se resuelve en el directorio /proc/self/task/tid propio del proceso.
/proc/[a-z]*
Varios otros archivos y subdirectorios bajo /proc exponen información a nivel de sistema.

Todos los anteriores se describen con más detalle en páginas de manual separadas cuyos nombres comienzan con proc_.

NOTAS

Muchos archivos contienen cadenas (por ejemplo, el entorno y la línea de comandos) que están en formato interno, con subcampos terminados por bytes nulos ('\0'). Al inspeccionar dichos archivos, puede que encuentre que los resultados son más legibles si utiliza un comando de la siguiente forma para mostrarlos:


$ cat archivo | tr '\000' '\n'

NOMBRE

proc - sistema de archivos virtual del kernel de Linux

DESCRIPCIÓN

El sistema de archivos proc es un sistema de archivos virtual que proporciona información sobre los procesos y otros detalles del kernel. Es un sistema de archivos en memoria; no se almacena en disco. Se monta en el directorio /proc en el momento del arranque del sistema.

La mayoría de los archivos dentro de /proc son solo lectura, pero algunos archivos son grabables y pueden usarse para modificar parámetros del kernel y controlar el comportamiento de los procesos.

Los directorios y archivos dentro de /proc se crean dinámicamente según sea necesario. El contenido y la estructura de /proc pueden variar entre diferentes versiones del kernel de Linux.

A continuación se muestran algunas de las entradas más comunes dentro de /proc:

  • /proc/cpuinfo: Información detallada sobre la CPU.
  • /proc/meminfo: Información sobre el uso de memoria.
  • /proc/mounts: Puntos de montaje actuales.
  • /proc/modules: Módulos del kernel cargados actualmente.
  • /proc/net/: Información sobre redes.
  • /proc/sys/: Parámetros configurables del kernel.
  • /proc/[pid]/: Directorios que contienen información sobre procesos específicos, donde [pid] es el ID del proceso.

NOTAS

El sistema de archivos proc se puede habilitar o deshabilitar en tiempo de ejecución a través de la interfaz sysctl.

No se recomienda modificar directamente los archivos dentro de /proc/sys/ a menos que sepa lo que está haciendo, ya que puede afectar negativamente la estabilidad y el rendimiento del sistema.

VER TAMBIÉN

bash(1), ls(1), ps(1), sysctl(8)
