provider(7ssl)

Paquete: openssl

PROVIDER(7ssl) OpenSSL PROVIDER(7ssl)

NOMBRE

provider - Proveedores de implementación de operaciones OpenSSL

SINOPSIS

#include <openssl/provider.h>

DESCRIPCIÓN

General

Esta página contiene información útil para los autores de proveedores.

Un proveedor, en términos de OpenSSL, es una unidad de código que proporciona una o más implementaciones para diversas operaciones para diversos algoritmos que uno podría querer realizar.

Una operación es algo que uno quiere hacer, como cifrado y descifrado, derivación de claves, cálculo de MAC, firma y verificación, etc.

Un algoritmo es un método con nombre para realizar una operación. Muy a menudo, los algoritmos giran en torno a operaciones criptográficas, pero también pueden girar en torno a otros tipos de operaciones, como la gestión de ciertos tipos de objetos.

Vea crypto(7) para más detalles.

Proveedor

Un proveedor ofrece una función de inicialización, como un conjunto de funciones base en forma de un array OSSL_DISPATCH(3), y por extensión, un conjunto de OSSL_ALGORITHM(3)s (ver openssl-core.h(7)). Puede ser un módulo cargable dinámicamente, o puede estar incorporado, en las bibliotecas OpenSSL o en la aplicación. Si es un módulo cargable dinámicamente, la función de inicialización debe llamarse "OSSL_provider_init" y debe ser exportada. Si está incorporado, la función de inicialización puede tener cualquier nombre.

La función de inicialización debe tener la siguiente firma:

int NAME(const OSSL_CORE_HANDLE *handle,
         const OSSL_DISPATCH *in, const OSSL_DISPATCH **out,
         void **provctx);

handle es el objeto de la biblioteca OpenSSL para el proveedor, y funciona como un identificador para todo lo que las bibliotecas OpenSSL necesitan saber sobre el proveedor. Para el propio proveedor, se pasa a algunas de las funciones proporcionadas en el array de despacho in.

in es un array de despacho de funciones base ofrecidas por las bibliotecas OpenSSL, y las funciones disponibles se describen con más detalle en provider-base(7).

*out debe ser asignado a un array de despacho de funciones base que el proveedor ofrece a las bibliotecas OpenSSL. Las funciones que pueden ofrecerse se describen con más detalle en provider-base(7), y son el medio central de comunicación entre las bibliotecas OpenSSL y el proveedor.

*provctx debe ser asignado a un contexto específico del proveedor para permitir al proveedor usos simultáneos múltiples. Este puntero se pasará a varias funciones de operación ofrecidas por el proveedor.

Tenga en cuenta que el proveedor no estará disponible para que las aplicaciones lo utilicen hasta que la función de inicialización se haya completado y retornado con éxito.

Una de las funciones que el proveedor ofrece a las bibliotecas OpenSSL es el mecanismo central para que las bibliotecas OpenSSL accedan a las implementaciones de operaciones para diversos algoritmos. Se hace referencia con el número OSSL_FUNC_PROVIDER_QUERY_OPERATION y tiene la siguiente firma:

const OSSL_ALGORITHM *provider_query_operation(void *provctx,
                                               int operation_id,
                                               const int *no_store);

provctx es el contexto específico del proveedor que fue devuelto por la función de inicialización.

operation_id es una identidad de operación (ver "Operaciones" abajo).

no_store es una bandera para las bibliotecas OpenSSL que, cuando no es cero, significa que las bibliotecas OpenSSL no almacenarán una referencia a los datos devueltos en su almacén interno de implementaciones.

El OSSL_ALGORITHM(3) devuelto es la base de cualquier API de biblioteca OpenSSL que utilice proveedores para su implementación, más comúnmente en las funciones de tipo fetching (ver "FETCHING DE ALGORITMOS" en crypto(7)).

Operaciones

Las operaciones se refieren con números, a través de macros con nombres que comienzan con "OSSL_OP_".

Con cada operación viene un conjunto de tipos de función definidos que un proveedor puede ofrecer o no, dependiendo de sus necesidades.

Las operaciones disponibles actualmente son:

Resúmenes (Digests)
En las bibliotecas OpenSSL, el objeto de método correspondiente es EVP_MD. El número para esta operación es OSSL_OP_DIGEST. Las funciones que el proveedor puede ofrecer se describen en provider-digest(7).
Cifrados Simétricos
En las bibliotecas OpenSSL, el objeto de método correspondiente es EVP_CIPHER. El número para esta operación es OSSL_OP_CIPHER. Las funciones que el proveedor puede ofrecer se describen en provider-cipher(7).
Código de Autenticación de Mensajes (MAC)
En las bibliotecas OpenSSL, el objeto de método correspondiente es EVP_MAC. El número para esta operación es OSSL_OP_MAC. Las funciones que el proveedor puede ofrecer se describen en provider-mac(7).
Función de Derivación de Claves (KDF)
En las bibliotecas OpenSSL, el objeto de método correspondiente es EVP_KDF. El número para esta operación es OSSL_OP_KDF. Las funciones que el proveedor puede ofrecer se describen en provider-kdf(7).
Intercambio de Claves
En las bibliotecas OpenSSL, el objeto de método correspondiente es EVP_KEYEXCH. El número para esta operación es OSSL_OP_KEYEXCH. Las funciones que el proveedor puede ofrecer se describen en provider-keyexch(7).
Cifrados Asimétricos
En las bibliotecas OpenSSL, el objeto de método correspondiente es EVP_ASYM_CIPHER. El número para esta operación es OSSL_OP_ASYM_CIPHER. Las funciones que el proveedor puede ofrecer se describen en provider-asym_cipher(7).
Cifrado de Claves Asimétricas (KEM)
En las bibliotecas OpenSSL, el objeto de método correspondiente es EVP_KEM. El número para esta operación es OSSL_OP_KEM. Las funciones que el proveedor puede ofrecer se describen en provider-kem(7).
Codificación
En las bibliotecas OpenSSL, el objeto de método correspondiente es OSSL_ENCODER. El número para esta operación es OSSL_OP_ENCODER. Las funciones que el proveedor puede ofrecer se describen en provider-encoder(7).
Decodificación
En las bibliotecas OpenSSL, el objeto de método correspondiente es OSSL_DECODER. El número para esta operación es OSSL_OP_DECODER. Las funciones que el proveedor puede ofrecer se describen en provider-decoder(7).
Generación de Números Aleatorios
El número para esta operación es OSSL_OP_RAND. Las funciones que el proveedor puede ofrecer para la generación de números aleatorios se describen en provider-rand(7).
Gestión de Claves
El número para esta operación es OSSL_OP_KEYMGMT. Las funciones que el proveedor puede ofrecer para la gestión de claves se describen en provider-keymgmt(7).
Firma y Verificación de Firma
El número para esta operación es OSSL_OP_SIGNATURE. Las funciones que el proveedor puede ofrecer para firmas digitales se describen en provider-signature(7).
Gestión de Almacén
El número para esta operación es OSSL_OP_STORE. Las funciones que el proveedor puede ofrecer para la gestión de almacén se describen en provider-storemgmt(7).

Algorithm naming

Algorithm names are case insensitive. Any particular algorithm can have multiple aliases associated with it. The canonical OpenSSL naming scheme follows this format:

ALGNAME[VERSION?][-SUBNAME[VERSION?]?][-SIZE?][-MODE?]

VERSION is only present if there are multiple versions of an algorithm (e.g. MD2, MD4, MD5). It may be omitted if there is only one version.

SUBNAME may be present where multiple algorithms are combined together, e.g. MD5-SHA1.

SIZE is only present if multiple versions of an algorithm exist with different sizes (e.g. AES-128-CBC, AES-256-CBC)

MODE is only present where applicable.

Other aliases may exist for example where standards bodies or common practice use alternative names or names that OpenSSL has used historically.

Provider dependencies

Providers may depend for their proper operation on the availability of (functionality implemented in) other providers. As there is no mechanism to express such dependencies towards the OpenSSL core, provider authors must take care that such dependencies are either completely avoided or made visible to users, e.g., by documentation and/or defensive programming, e.g., outputting error messages if required external dependencies are not available, e.g., when no provider implementing the required functionality has been activated. In particular, provider initialization should not depend on other providers already having been initialized.

Note on naming clashes

It is possible to register the same algorithm name from within different providers. Users should note that if no property query is specified, or more than one implementation matches the property query then it is unspecified which implementation of a particular algorithm will be returned. Such naming clashes may also occur if algorithms only differ in capitalization as "Algorithm naming" is case insensitive.

OPENSSL PROVIDERS

OpenSSL provides a number of its own providers. These are the default, base, fips, legacy and null providers. See crypto(7) for an overview of these providers.
