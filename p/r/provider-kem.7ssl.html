NOMBRE

provider-kem - Las funciones de la biblioteca kem <-> proveedor

SINOPSIS

#include <openssl/core_dispatch.h>
#include <openssl/core_names.h>
/*
 * Ninguna de estas son funciones reales, pero se muestran así para
 * las firmas de funciones que se ofrecen como punteros de función en
 * arrays de OSSL_DISPATCH.
 */
/* Gestión de contexto */
void *OSSL_FUNC_kem_newctx(void *provctx);
void OSSL_FUNC_kem_freectx(void *ctx);
void *OSSL_FUNC_kem_dupctx(void *ctx);
/* Encapsulación */
int OSSL_FUNC_kem_encapsulate_init(void *ctx, void *provkey,
                                   const OSSL_PARAM params[]);
int OSSL_FUNC_kem_auth_encapsulate_init(void *ctx, void *provkey,
                                        void *provauthkey,
                                        const OSSL_PARAM params[]);
int OSSL_FUNC_kem_encapsulate(void *ctx, unsigned char *out, size_t *outlen,
                              unsigned char *secret, size_t *secretlen);
/* Desencapsulación */
int OSSL_FUNC_kem_decapsulate_init(void *ctx, void *provkey);
int OSSL_FUNC_kem_auth_decapsulate_init(void *ctx, void *provkey,
                                        void *provauthkey,
                                        const OSSL_PARAM params[]);
int OSSL_FUNC_kem_decapsulate(void *ctx, unsigned char *out, size_t *outlen,
                              const unsigned char *in, size_t inlen);
/* Parámetros KEM */
int OSSL_FUNC_kem_get_ctx_params(void *ctx, OSSL_PARAM params[]);
const OSSL_PARAM *OSSL_FUNC_kem_gettable_ctx_params(void *ctx, void *provctx);
int OSSL_FUNC_kem_set_ctx_params(void *ctx, const OSSL_PARAM params[]);
const OSSL_PARAM *OSSL_FUNC_kem_settable_ctx_params(void *ctx, void *provctx);

DESCRIPCIÓN

Esta documentación está dirigida principalmente a autores de proveedores. Consulte provider(7) para obtener más información.

La operación KEM asimétrica (OSSL_OP_KEM) permite a los proveedores implementar algoritmos KEM asimétricos y ponerlos a disposición de las aplicaciones a través de las funciones de la API EVP_PKEY_encapsulate(3), EVP_PKEY_decapsulate(3) y otras funciones relacionadas.

Todas las "funciones" mencionadas aquí se pasan como punteros de función entre libcrypto y el proveedor en arrays de OSSL_DISPATCH(3) a través de arrays de OSSL_ALGORITHM(3) que son devueltos por la función provider_query_operation() del proveedor (consulte "Funciones del proveedor" en provider-base(7)).

Todas estas "funciones" tienen un tipo de función correspondiente llamado OSSL_FUNC_{name}_fn, y una función auxiliar para recuperar el puntero de función de un elemento de OSSL_DISPATCH(3) llamado OSSL_FUNC_{name}. Por ejemplo, la "función" OSSL_FUNC_kem_newctx() tiene:

typedef void *(OSSL_FUNC_kem_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_kem_newctx_fn
    OSSL_FUNC_kem_newctx(const OSSL_DISPATCH *opf);

Los arrays de OSSL_DISPATCH(3) se indexan mediante números que se proporcionan como macros en openssl-core_dispatch.h(7), de la siguiente manera:

OSSL_FUNC_kem_newctx                OSSL_FUNC_KEM_NEWCTX
OSSL_FUNC_kem_freectx               OSSL_FUNC_KEM_FREECTX
OSSL_FUNC_kem_dupctx                OSSL_FUNC_KEM_DUPCTX
OSSL_FUNC_kem_encapsulate_init      OSSL_FUNC_KEM_ENCAPSULATE_INIT
OSSL_FUNC_kem_auth_encapsulate_init OSSL_FUNC_KEM_AUTH_ENCAPSULATE_INIT
OSSL_FUNC_kem_encapsulate           OSSL_FUNC_KEM_ENCAPSULATE
OSSL_FUNC_kem_decapsulate_init      OSSL_FUNC_KEM_DECAPSULATE_INIT
OSSL_FUNC_kem_auth_decapsulate_init OSSL_FUNC_KEM_AUTH_DECAPSULATE_INIT
OSSL_FUNC_kem_decapsulate           OSSL_FUNC_KEM_DECAPSULATE
OSSL_FUNC_kem_get_ctx_params        OSSL_FUNC_KEM_GET_CTX_PARAMS
OSSL_FUNC_kem_gettable_ctx_params   OSSL_FUNC_KEM_GETTABLE_CTX_PARAMS
OSSL_FUNC_kem_set_ctx_params        OSSL_FUNC_KEM_SET_CTX_PARAMS
OSSL_FUNC_kem_settable_ctx_params   OSSL_FUNC_KEM_SETTABLE_CTX_PARAMS

Una implementación de algoritmo KEM asimétrico puede no implementar todas estas funciones. Para ser un conjunto coherente de funciones, un proveedor debe implementar OSSL_FUNC_kem_newctx y OSSL_FUNC_kem_freectx. También debe implementar OSSL_FUNC_kem_encapsulate_init y OSSL_FUNC_kem_encapsulate, o OSSL_FUNC_kem_decapsulate_init y OSSL_FUNC_kem_decapsulate. OSSL_FUNC_kem_auth_encapsulate_init es opcional pero si está presente, OSSL_FUNC_kem_auth_decapsulate_init también debe estarlo. OSSL_FUNC_kem_get_ctx_params es opcional pero si está presente, OSSL_FUNC_kem_gettable_ctx_params también debe estarlo. De manera similar, OSSL_FUNC_kem_set_ctx_params es opcional pero si está presente, OSSL_FUNC_kem_settable_ctx_params también debe estarlo.

Un algoritmo KEM asimétrico también debe implementar algún mecanismo para generar, cargar o importar claves a través de la operación de gestión de claves (OSSL_OP_KEYMGMT). Consulte provider-keymgmt(7) para obtener más detalles.

Funciones de Gestión de Contexto

OSSL_FUNC_kem_newctx() debe crear y devolver un puntero a una estructura del lado del proveedor para mantener la información de contexto durante una operación KEM asimétrica. Se devolverá un puntero a este contexto en varias de las otras llamadas a funciones de operación KEM asimétrica. El parámetro provctx es el contexto del proveedor generado durante la inicialización del proveedor (consulte provider(7)).

A OSSL_FUNC_kem_freectx() se le pasa un puntero al contexto KEM asimétrico del lado del proveedor en el parámetro ctx. Esta función debe liberar cualquier recurso asociado con ese contexto.

OSSL_FUNC_kem_dupctx() debe duplicar el contexto KEM asimétrico del lado del proveedor en el parámetro ctx y devolver la copia duplicada.

Funciones de Encapsulación de Clave Asimétrica

OSSL_FUNC_kem_encapsulate_init() inicializa un contexto para la encapsulación asimétrica dado un contexto KEM asimétrico del lado del proveedor en el parámetro ctx, un puntero a un objeto de clave del proveedor en el parámetro provkey y el nombre del algoritmo. Los params, si no son NULL, deben establecerse en el contexto de manera similar a como se usa OSSL_FUNC_kem_set_ctx_params(). El objeto de clave debe haber sido generado, cargado o importado previamente en el proveedor utilizando la operación de gestión de claves (OSSL_OP_KEYMGMT) (consulte provider-keymgmt(7)).

OSSL_FUNC_kem_auth_encapsulate_init() es similar a OSSL_FUNC_kem_encapsulate_init(), pero también pasa una clave de autenticación adicional provauthkey que no puede ser NULL.

OSSL_FUNC_kem_encapsulate() realiza la encapsulación real. Se pasa un contexto KEM asimétrico previamente inicializado en el parámetro ctx. A menos que out sea NULL, los datos a encapsular se generan internamente y se devuelven en el búfer apuntado por el parámetro secret, y los datos encapsulados también deben escribirse en la ubicación apuntada por el parámetro out. La longitud de los datos encapsulados debe escribirse en *outlen y la longitud del secreto generado debe escribirse en *secretlen.

Si out es NULL, la longitud máxima de los datos encapsulados debe escribirse en *outlen, y la longitud máxima del secreto generado debe escribirse en *secretlen.

Funciones de Desencapsulación

OSSL_FUNC_kem_decapsulate_init() inicializa un contexto para la desencapsulación asimétrica dado un contexto KEM asimétrico del lado del proveedor en el parámetro ctx, un puntero a un objeto de clave del proveedor en el parámetro provkey, y el nombre del algoritmo. provider-kem(7ssl) — OpenSSL — The OpenSSL Project

NAME

provider-kem - Provider Key Encapsulation Mechanism (KEM) interface

SYNOPSIS

A provider can implement the KEM (Key Encapsulation Mechanism) operation. The functions for KEM are: OSSL_FUNC_kem_newctx, OSSL_FUNC_kem_init, OSSL_FUNC_kem_encrypt, OSSL_FUNC_kem_decrypt, OSSL_FUNC_kem_freectx, OSSL_FUNC_kem_dupctx, OSSL_FUNC_kem_get_ctx_params, OSSL_FUNC_kem_set_ctx_params, OSSL_FUNC_kem_gettable_ctx_params, OSSL_FUNC_kem_settable_ctx_params, OSSL_FUNC_kem_query_operation_name, OSSL_FUNC_kem_get_provider_operation.

See provider(7) for more information about provider operation dispatch.

DESCRIPTION

A provider KEM implementation is responsible for performing Key Encapsulation Mechanism (KEM) operations. A KEM is a cryptographic algorithm that allows a sender to encrypt a shared secret to a recipient using the recipient's public key. The recipient can then decrypt the encrypted shared secret using their private key.

The following functions are typically provided by a provider for KEM operations:

  • OSSL_FUNC_kem_newctx: Creates a new KEM context.
  • OSSL_FUNC_kem_init: Initializes the KEM context for encryption or decryption.
  • OSSL_FUNC_kem_encrypt: Encrypts a shared secret to generate an encapsulated key.
  • OSSL_FUNC_kem_decrypt: Decrypts an encapsulated key to retrieve the shared secret.
  • OSSL_FUNC_kem_freectx: Frees a KEM context.
  • OSSL_FUNC_kem_dupctx: Duplicates a KEM context.
  • OSSL_FUNC_kem_get_ctx_params: Retrieves KEM context parameters.
  • OSSL_FUNC_kem_set_ctx_params: Sets KEM context parameters.
  • OSSL_FUNC_kem_gettable_ctx_params: Retrieves the parameters that can be obtained from a KEM context.
  • OSSL_FUNC_kem_settable_ctx_params: Retrieves the parameters that can be set for a KEM context.
  • OSSL_FUNC_kem_query_operation_name: Queries the operation name of a KEM.
  • OSSL_FUNC_kem_get_provider_operation: Gets the provider operation for KEM.

The specific details of these functions, including their parameters and return values, are defined in the OpenSSL documentation for KEM operations.

OSSL_FUNC_kem_encrypt

The OSSL_FUNC_kem_encrypt function is used to encapsulate a shared secret. The provider should generate a shared secret, encapsulate it using the provided public key, and return the encapsulated secret and the shared secret. The length of the encapsulated secret should be written to *outlen.

OSSL_FUNC_kem_decrypt

The OSSL_FUNC_kem_decrypt function is used to decapsulate an encapsulated secret. The provider should use the provided private key to decapsulate the secret, and return the shared secret. The decapsulated data should be written to the location pointed to by the out parameter. The length of the decapsulated data should be written to *outlen. If out is NULL then the maximum length of the decapsulated data should be written to *outlen.

Asymmetric Key Encapsulation Parameters

See OSSL_PARAM(3) for further details on the parameters structure used by the OSSL_FUNC_kem_get_ctx_params() and OSSL_FUNC_kem_set_ctx_params() functions.

The OpenSSL FIPS provider also supports the following parameters:

"fips-indicator" (OSSL_KEM_PARAM_FIPS_APPROVED_INDICATOR) <integer>
A getter that returns 1 if the operation is FIPS approved, or 0 otherwise. This may be used after calling either OSSL_FUNC_kem_encapsulate() or OSSL_FUNC_kem_decapsulate(). It may return 0 if the "key-check" is set to 0.
"key-check" (OSSL_KEM_PARAM_FIPS_KEY_CHECK) <integer>
If required this parameter should be set using OSSL_FUNC_kem_encapsulate_init() or OSSL_FUNC_kem_decapsulate_init(). The default value of 1 causes an error during the init if the key is not FIPS approved (e.g. The key has a security strength of less than 112 bits). Setting this to 0 will ignore the error and set the approved "fips-indicator" to 0. This option breaks FIPS compliance if it causes the approved "fips-indicator" to return 0.

Asymmetric Key Encapsulation Parameter Functions

OSSL_FUNC_kem_get_ctx_params() gets asymmetric KEM parameters associated with the given provider side asymmetric kem context ctx and stores them in params. Passing NULL for params should return true.

OSSL_FUNC_kem_set_ctx_params() sets the asymmetric KEM parameters associated with the given provider side asymmetric kem context ctx to params. Any parameter settings are additional to any that were previously set. Passing NULL for params should return true.

No parameters are currently recognised by built-in asymmetric kem algorithms.

OSSL_FUNC_kem_gettable_ctx_params() and OSSL_FUNC_kem_settable_ctx_params() get a constant OSSL_PARAM(3) array that describes the gettable and settable parameters, i.e. parameters that can be used with OSSL_FUNC_kem_get_ctx_params() and OSSL_FUNC_kem_set_ctx_params() respectively.

RETURN VALUES

OSSL_FUNC_kem_newctx() and OSSL_FUNC_kem_dupctx() should return the newly created provider side asymmetric kem context, or NULL on failure.

All other functions should return 1 for success or 0 on error.

HISTORY

The provider KEM interface was introduced in OpenSSL 3.0.

OSSL_FUNC_kem_auth_encapsulate_init() and OSSL_FUNC_kem_auth_decapsulate_init() were added in OpenSSL 3.2.

The Asymmetric Key Encapsulation Parameters "fips-indicator" and "key-check" were added in OpenSSL 3.4.
