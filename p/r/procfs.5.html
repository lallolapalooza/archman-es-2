proc(5) Manual de formatos de archivo proc(5)

NOMBRE

proc - información de procesos, información del sistema y sistema de archivos pseudo-sysctl

DESCRIPCIÓN

El sistema de archivos proc es un sistema de archivos pseudo que proporciona una interfaz a las estructuras de datos del kernel. Comúnmente se monta en /proc. Típicamente, es montado automáticamente por el sistema, pero también puede ser montado manualmente usando un comando como:


mount -t proc proc /proc

La mayoría de los archivos en el sistema de archivos proc son de solo lectura, pero algunos archivos son escribibles, permitiendo cambiar variables del kernel.

Opciones de montaje

El sistema de archivos proc soporta las siguientes opciones de montaje:

hidepid=n (desde Linux 3.3)
Esta opción controla quién puede acceder a la información en los directorios /proc/pid. El argumento, n, es uno de los siguientes valores:
0
Todos pueden acceder a todos los directorios /proc/pid. Este es el comportamiento tradicional y el predeterminado si esta opción de montaje no se especifica.
1
Los usuarios no pueden acceder a archivos y subdirectorios dentro de ningún directorio /proc/pid excepto los suyos (los directorios /proc/pid en sí permanecen visibles). Archivos sensibles como /proc/pid/cmdline y /proc/pid/status ahora están protegidos contra otros usuarios. Esto hace imposible saber si algún usuario está ejecutando un programa específico (siempre que el programa no se revele por sí mismo a través de su comportamiento).
2
Como en el modo 1, pero además los directorios /proc/pid que pertenecen a otros usuarios se vuelven invisibles. Esto significa que las entradas /proc/pid ya no se pueden usar para descubrir los PIDs en el sistema. Esto no oculta el hecho de que un proceso con un valor PID específico existe (se puede averiguar por otros medios, por ejemplo, mediante "kill -0 $PID"), pero oculta el UID y GID de un proceso, que de otro modo se podrían averiguar empleando stat(2) en un directorio /proc/pid. Esto complica enormemente la tarea de un atacante para recopilar información sobre procesos en ejecución (por ejemplo, averiguar si algún demonio se está ejecutando con privilegios elevados, si otro usuario está ejecutando algún programa sensible, si otros usuarios están ejecutando algún programa en absoluto, etc.).
gid=gid (desde Linux 3.3)
Especifica el ID de un grupo cuyos miembros están autorizados a obtener información de procesos de otro modo prohibida por hidepid (es decir, los usuarios de este grupo se comportan como si /proc se hubiera montado con hidepid=0). Este grupo debe usarse en lugar de enfoques como poner a los usuarios no root en el archivo sudoers(5).
subset=pid (desde Linux 5.8)
Muestra solo el subconjunto especificado de procfs, ocultando todos los archivos y directorios de nivel superior en procfs que no estén relacionados con tareas.

Visión general

Debajo de /proc, existen los siguientes grupos generales de archivos y subdirectorios:

Subdirectorios /proc/pid
Cada uno de estos subdirectorios contiene archivos y subdirectorios que exponen información sobre el proceso con el ID de proceso correspondiente.
Debajo de cada uno de los directorios /proc/pid, un subdirectorio task contiene subdirectorios de la forma task/tid, que contienen información correspondiente sobre cada uno de los hilos en el proceso, donde tid es el ID de hilo del kernel del hilo.
Los subdirectorios /proc/pid son visibles al iterar a través de /proc con getdents(2) (y por lo tanto son visibles cuando se usa ls(1) para ver el contenido de /proc).
Subdirectorios /proc/tid
Cada uno de estos subdirectorios contiene archivos y subdirectorios que exponen información sobre el hilo con el ID de hilo correspondiente. Los contenidos de estos directorios son los mismos que los de los directorios /proc/pid/task/tid correspondientes.
Los subdirectorios /proc/tid *no* son visibles al iterar a través de /proc con getdents(2) (y por lo tanto *no* son visibles cuando se usa ls(1) para ver el contenido de /proc).
/proc/self
Cuando un proceso accede a este enlace simbólico mágico, se resuelve al directorio /proc/pid propio del proceso.
/proc/thread-self
Cuando un hilo accede a este enlace simbólico mágico, se resuelve al directorio /proc/self/task/tid propio del proceso.
/proc/[a-z]*
Varios otros archivos y subdirectorios bajo /proc exponen información a nivel de sistema.

Todos los anteriores se describen con más detalle en páginas de manual separadas cuyos nombres comienzan con proc_.

NOTAS

Muchos archivos contienen cadenas (por ejemplo, el entorno y la línea de comandos) que están en el formato interno, con subcampos terminados por bytes nulos ('\0'). Al inspeccionar dichos archivos, puede encontrar que los resultados son más legibles si utiliza un comando de la siguiente forma para mostrarlos:


$ cat archivo | tr '\000' '\n'

procfs - El sistema de archivos de procesos en Linux

NAME

procfs - El sistema de archivos de procesos en Linux

DESCRIPTION

El sistema de archivos procfs, comúnmente montado en /proc, es una interfaz virtual al kernel y al espacio de usuario de Linux. Proporciona información sobre los procesos del sistema, la arquitectura del hardware y los dispositivos. El contenido de /proc se genera sobre la marcha cuando se accede a él, y no es un sistema de archivos real almacenado en disco. Cada directorio dentro de /proc con un nombre numérico corresponde a un ID de proceso (PID) y contiene información sobre ese proceso específico.

Archivos y Directorios Comunes

  • /proc/cpuinfo: Información sobre la CPU.
  • /proc/meminfo: Información sobre el uso de memoria.
  • /proc/modules: Módulos del kernel cargados actualmente.
  • /proc/mounts: Sistemas de archivos montados.
  • /proc/[pid]/: Directorios que contienen información sobre procesos específicos.
  • /proc/[pid]/cmdline: Línea de comandos utilizada para iniciar el proceso.
  • /proc/[pid]/environ: Variables de entorno del proceso.
  • /proc/[pid]/status: Información de estado del proceso.
  • /proc/sys/: Parámetros del kernel que se pueden modificar en tiempo de ejecución (requiere privilegios de root).

NOTES

Aunque /proc proporciona mucha información útil, no todos los archivos y directorios son visibles o accesibles para todos los usuarios. El acceso a ciertos archivos puede estar restringido a root. La estructura y el contenido exactos de /proc pueden variar ligeramente entre diferentes versiones del kernel de Linux.
