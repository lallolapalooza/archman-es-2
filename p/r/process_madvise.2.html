process_madvise(2) Manual de llamadas al sistema process_madvise(2)

NOMBRE

process_madvise - dar consejos sobre el uso de memoria a un proceso

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/mman.h>
ssize_t process_madvise(size_t n;
                        int pidfd, const struct iovec iovec[n],
                        size_t n, int advice, unsigned int flags);

DESCRIPCIÓN

La llamada al sistema process_madvise() se utiliza para dar consejos o instrucciones al kernel sobre los rangos de direcciones de otro proceso o del propio proceso llamante. Proporciona el consejo para los rangos de direcciones descritos por iovec y n. El objetivo de dicho consejo es mejorar el rendimiento del sistema o de la aplicación.

El argumento pidfd es un descriptor de archivo PID (ver pidfd_open(2)) que especifica el proceso al que se aplicará el consejo.

El puntero iovec apunta a un array de estructuras iovec, descritas en iovec(3type).

n especifica el número de elementos en el array de estructuras iovec. Este valor debe ser menor o igual a IOV_MAX (definido en <limits.h> o accesible a través de la llamada sysconf(_SC_IOV_MAX)).

Si se manipula otro proceso, o antes de Linux 6.13, el argumento advice es uno de los siguientes valores:

MADV_COLD
Ver madvise(2).
MADV_COLLAPSE
Ver madvise(2).
MADV_PAGEOUT
Ver madvise(2).
MADV_WILLNEED
Ver madvise(2).

Desde Linux 6.13, al manipular el proceso llamante, cualquier bandera de consejo es permitida.

El argumento flags está reservado para uso futuro; actualmente, este argumento debe especificarse como 0.

Los argumentos n e iovec se comprueban antes de aplicar cualquier consejo. Si n es demasiado grande o iovec es inválido, se devolverá un error inmediatamente y no se aplicará ningún consejo.

El consejo puede aplicarse solo a una parte de iovec si uno de sus elementos apunta a una región de memoria inválida en el proceso remoto. No se procesarán elementos adicionales más allá de ese punto. (Ver la discusión sobre el consejo parcial en VALOR DE RETORNO).

Desde Linux 5.12, el permiso para aplicar consejos a otro proceso se rige por la comprobación de modo de acceso ptrace PTRACE_MODE_READ_FSCREDS (ver ptrace(2)); además, debido a las implicaciones de rendimiento de aplicar el consejo, el llamante debe tener la capacidad CAP_SYS_NICE (ver capabilities(7)).

VALOR DE RETORNO

En caso de éxito, process_madvise() devuelve el número de bytes aconsejados. Este valor de retorno puede ser menor que el número total de bytes solicitados, si ocurrió un error después de que algunos elementos de iovec ya fueran procesados. El llamante debe comprobar el valor de retorno para determinar si ocurrió un consejo parcial.

En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EBADF
pidfd no es un descriptor de archivo PID válido.
EFAULT
La memoria descrita por iovec está fuera del espacio de direcciones accesible del proceso al que se refiere pidfd.
EINVAL
flags no es 0.
EINVAL
La suma de los valores iov_len de iovec desborda un valor ssize_t.
EINVAL
n es demasiado grande.
ENOMEM
No se pudo asignar memoria para copias internas de las estructuras iovec.
EPERM
El llamante no tiene permiso para acceder al espacio de direcciones del proceso pidfd.
ESRCH
El proceso destino no existe (es decir, ha terminado y ha sido esperado).

Ver madvise(2) para errores específicos de advice.

ESTÁNDARES

Linux.

HISTORIA

Linux 5.10. glibc 2.36.

El soporte para esta llamada al sistema es opcional, dependiendo de la configuración de la opción de configuración CONFIG_ADVISE_SYSCALLS.

Cuando esta llamada al sistema apareció por primera vez en Linux 5.10, el permiso para aplicar consejos a otro proceso se regía enteramente por la comprobación de modo de acceso ptrace PTRACE_MODE_ATTACH_FSCREDS (ver ptrace(2)). Este requisito se relajó en Linux 5.12 para que el llamante no necesitara control total sobre el proceso destino.
