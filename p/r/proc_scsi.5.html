proc_scsi(5) Manual de Formatos de Archivo proc_scsi(5)

NOMBRE

/proc/scsi/ - SCSI

DESCRIPCIÓN

/proc/scsi/
Un directorio con el pseudo-archivo de nivel medio scsi y varios directorios de controladores de bajo nivel SCSI, que contienen un archivo para cada host SCSI en este sistema, todos los cuales dan el estado de alguna parte del subsistema de E/S SCSI. Estos archivos contienen estructuras ASCII y, por lo tanto, son legibles con cat(1).
También puede escribir en algunos de los archivos para reconfigurar el subsistema o activar o desactivar ciertas funciones.
/proc/scsi/scsi
Este es un listado de todos los dispositivos SCSI conocidos por el kernel. El listado es similar al que se ve durante el arranque. Actualmente, scsi solo admite el comando add-single-device que permite a root agregar un dispositivo "hotplugged" a la lista de dispositivos conocidos.
El comando

echo 'scsi add-single-device 1 0 5 0' > /proc/scsi/scsi

hará que el host scsi1 escanee en el canal SCSI 0 en la ID 5 LUN 0. Si ya hay un dispositivo conocido en esta dirección o la dirección no es válida, se devolverá un error.
/proc/scsi/nombre_controlador/
nombre_controlador actualmente puede ser NCR53c7xx, aha152x, aha1542, aha1740, aic7xxx, buslogic, eata_dma, eata_pio, fdomain, in2000, pas16, qlogic, scsi_debug, seagate, t128, u15-24f, ultrastore, o wd7000. Estos directorios aparecen para todos los controladores que registraron al menos un HBA SCSI. Cada directorio contiene un archivo por cada host registrado. Cada archivo de host se nombra según el número que se le asignó al host durante la inicialización.
Leer estos archivos generalmente mostrará la configuración del controlador y del host, estadísticas, etc.
Escribir en estos archivos permite diferentes cosas en diferentes hosts. Por ejemplo, con los comandos latency y nolatency, root puede activar y desactivar el código de medición de latencia de comandos en el controlador eata_dma. Con los comandos lockup y unlock, root puede controlar los bloqueos del bus simulados por el controlador scsi_debug.
