NOMBRE

pkcs11-provider - Un proveedor de OpenSSL que permite la interfaz directa con controladores pkcs11.

DESCRIPCIÓN

A partir de la versión 3.0, el proyecto OpenSSL introdujo un nuevo sistema modular para extender OpenSSL que reemplaza a los módulos de motores (Engines) obsoletos.

Los proveedores (Providers(1)) se cargan mediante directivas de configuración en el archivo de configuración de openssl (o se cargan directamente por las aplicaciones).

El proveedor pkcs11 permite a las aplicaciones enlazadas a openssl utilizar claves y operaciones criptográficas de un token de hardware o software a través de su controlador PKCS#11(2) y el uso de URIs pkcs11(3).

El proveedor pkcs11 se puede configurar para que se cargue automáticamente a través de openssl.cnf

CONFIGURACIÓN

Opciones de configuración reconocidas por el proveedor

ruta_del_módulo_pkcs11

Una ruta de archivo al controlador pkcs11 que se utilizará.

Por defecto: Si se compila con p11-kit, utiliza su controlador proxy, de lo contrario, ninguno.

NOTA: Consulte también PKCS11_PROVIDER_MODULE en la sección de variables de entorno.

Ejemplo:

pkcs11-module-path = /usr/lib64/opensc-pkcs11.so

argumentos_de_inicialización_del_módulo_pkcs11

Argumentos de inicialización no estándar que algunos controladores pkcs11 pueden necesitar. Generalmente no se usan, pero algunos tokens de software como el softokn de NSS requieren esto.

Por defecto: Ninguno

Ejemplo:

pkcs11-module-init-args = configDir=/etc/pki/token

pin_del_token_del_módulo_pkcs11

El PIN de usuario que se utilizará con el token. Si no se establece un PIN en la configuración, se puede solicitar interactivamente (si la aplicación utiliza indicadores), o se puede especificar junto con los identificadores de clave directamente en la URI pkcs11. Cuando se especifica un archivo, este debe ser un archivo de texto que contenga solo el PIN en la primera línea y un terminador.

Por defecto: Ninguno

Ejemplo:

pkcs11-module-token-pin = file:/etc/pki/pin.txt

cat /etc/pki/pin.txt
123456

permitir_exportación_del_módulo_pkcs11

Si el proveedor pkcs11 permitirá exportar claves públicas a través de OpenSSL. OpenSSL a menudo intenta exportar claves públicas de proveedores no predeterminados al proveedor predeterminado, y luego utiliza las propias funciones de OpenSSL para manejar cualquier operación asociada con la clave pública. Esta opción puede ser útil para forzar que las operaciones de clave pública se ejecuten en el token, por ejemplo, en caso de que el pkcs11 sea un acelerador que tenga un mejor rendimiento en la verificación de firmas o cifrado asimétrico que el código de OpenSSL.

Por defecto: 0 (Permitir exportación)

Ejemplo:

pkcs11-module-allow-export = 1 (Esto impide la exportación de claves públicas)

almacenar_en_caché_claves_del_módulo_pkcs11

Si el proveedor pkcs11 intentará almacenar en caché las claves del token en la sesión. Esto se usa en algunos tokens como optimización de rendimiento. Por ejemplo, los tokens de software que almacenan claves cifradas pueden mantener una copia de la clave en la sesión para acelerar el acceso. O los HSM conectados en red que permiten la exportación de material de clave pueden almacenar en caché la clave en la sesión en lugar de solicitarla nuevamente a través de la red.

Dos opciones están disponibles: * true * false

Por defecto: true (Nota: si el token no admite el almacenamiento en caché de sesiones, el almacenamiento en caché se deshabilitará automáticamente después del primer intento)

Ejemplo:

pkcs11-module-cache-keys = false (Desactiva cualquier intento de almacenar claves en caché en la sesión)

almacenar_en_caché_pines_del_módulo_pkcs11

Si el proveedor pkcs11 almacenará en caché un PIN introducido interactivamente. Esto es útil para permitir el inicio de un servicio y la introducción manual del PIN, pero que el servicio realice múltiples inicios de sesión según sea necesario, por ejemplo, después de bifurcar.

Actualmente solo hay una opción disponible: * cache: Almacena en caché el PIN

Por defecto: sin establecer (sin almacenamiento en caché)

Ejemplo:

pkcs11-module-cache-pins = cache (Almacenará en caché un PIN que se haya introducido manualmente)

almacenar_en_caché_sesiones_del_módulo_pkcs11

Permite ajustar cuántas sesiones pkcs11 pueden mantenerse abiertas y almacenadas en caché para un uso rápido. Este parámetro se ajusta en función del número máximo de sesiones que el token declara como compatibles. Tenga en cuenta que la sesión de inicio de sesión siempre se almacena en caché para mantener el token operativo.

Por defecto: 5

Ejemplo:

pkcs11-module-cache-sessions = 0 (Desactiva el almacenamiento en caché)

comportamiento_de_inicio_de_sesión_del_módulo_pkcs11

Si el proveedor pkcs11 intentará iniciar sesión en el token cuando se solicita una clave pública.

Hay tres opciones disponibles: * auto: Intenta sin iniciar sesión, pero recurre al comportamiento de inicio de sesión si no se encuentran claves * always: Siempre inicia sesión antes de intentar cargar claves públicas (esto es requerido por algunos HSM) * never: Nunca inicia sesión para claves públicas

Por defecto: "auto"

Ejemplo:

pkcs11-module-login-behavior = always (Siempre intenta iniciar sesión antes de cargar claves públicas)

comportamiento_de_carga_del_módulo_pkcs11

Si el proveedor pkcs11 carga e inicializa inmediatamente el módulo pkcs11 tan pronto como OpenSSL carga el proveedor (generalmente al inicio de la aplicación), o pospone la inicialización hasta la primera vez que se carga una clave pkcs11 (o se solicita alguna otra operación que requiera explícitamente el proveedor pkcs11).

Solo hay una opción disponible: * early: Carga el módulo pkcs11 inmediatamente

Por defecto: sin establecer (Carga solo en el primer uso)

Ejemplo:

pkcs11-module-load-behavior = early (Carga el módulo pkcs11 inmediatamente al inicio de la aplicación)

diversiones_del_módulo_pkcs11

Soluciones alternativas que pueden ser necesarias para tratar con algunos tokens y que aún no se pueden detectar automáticamente ni son predeterminadas apropiadas.

no-deinit

Evita la desinicialización cuando OpenSSL finaliza el proveedor. NOTA: esta opción puede provocar fugas de memoria y hacer que algunos módulos se comporten de forma incorrecta si la aplicación los descarga y vuelve a cargar intencionadamente.

no-operation-state

OpenSSL, por defecto, asume que los contextos con operaciones en curso se pueden duplicar fácilmente. Eso solo es posible si los tokens admiten la obtención y el establecimiento del estado de la operación. Si la diversión está habilitada, no se realiza la duplicación del contexto.

no-session-callbacks

Algunas implementaciones de PKCS11 no permiten establecer las funciones de devolución de llamada pApplication y Notify en C_OpenSession. Esta opción establece valores NULL para ambas devoluciones de llamada.

no-allowed-mechanisms

Algunas implementaciones de PKCS11 no admiten el atributo CKA_ALLOWED_MECHANISMS en las claves. Al establecer esta diversión, se evita que el proveedor intente establecer y leer este atributo.

Por defecto: ninguno

Ejemplo:

pkcs11-module-quirks = no-deinit no-operation-state (Desactiva la desinicialización, bloquea la duplicación de contextos)

pkcs11-module-block-operations

Permite bloquear operaciones específicas del "proveedor" incluso si el token realmente soporta los mecanismos necesarios. Esto es útil para solucionar casos en los que se desea forzar el uso del token para todas las operaciones estableciendo ?provider=pkcs11 en las propiedades predeterminadas, pero se desea una excepción para un tipo específico de operación, como los resúmenes (digests). NOTA: algunas operaciones pueden depender de otras o ser fundamentales para el correcto funcionamiento del proveedor, por lo que no todas las configuraciones de este parámetro funcionarán. Úsese con precaución.

Predeterminado: ninguna

Ejemplo: pkcs11-module-block-operations = digest (Deshabilita los mecanismos de resumen, que en su lugar se enrutarán al proveedor predeterminado de OpenSSL en la mayoría de las configuraciones)

pkcs11-module-assume-fips

Asume que el token utilizado por el módulo PKCS#11 está certificado bajo FIPS.

Debido a la especificación incompleta para la señalización de la certificación desde los módulos pkcs11, esto no se puede determinar automáticamente. Si sabe que su token está certificado bajo FIPS, debe establecer esta opción de configuración en true. De lo contrario, el proveedor pkcs11 no funcionará en Modo FIPS.

Predeterminado: False

Ejemplo:

pkcs11-module-assume-fips = true

VARIABLES DE ENTORNO

Variables de entorno reconocidas por el proveedor

PKCS11_PROVIDER_MODULE

Esta variable se puede usar para establecer un controlador pkcs11 diferente. Es útil cuando una aplicación necesita usar un controlador diferente al del resto del sistema. Esta variable de entorno **anula** la opción pkcs11-module-path establecida en openssl.cnf.

Ejemplo:

PKCS11_PROVIDER_MODULE = /usr/lib64/opensc-pkcs11.so

PKCS11_PROVIDER_DEBUG

Esta variable se puede establecer para obtener información de depuración. Se pueden especificar dos subopciones: file, level.

El nivel normal de depuración (debug_level) es 1. Si se proporciona un nivel superior, se imprimirá información adicional (como toda la información de mecanismos soportados para cada ranura) en el archivo de depuración especificado. El carácter de coma separa las opciones, y el carácter de dos puntos se utiliza para separar una opción y su valor. No hay carácter de escape, por lo tanto, los caracteres `,` y `:` no se pueden usar en los valores.

Ejemplos:

PKCS11_PROVIDER_DEBUG=file:/tmp/debug.log

PKCS11_PROVIDER_DEBUG=file:/dev/stderr,level:2

USO EN APLICACIONES ANTIGUAS (URIs en archivos PEM)

Se recomienda encarecidamente actualizar las aplicaciones para usar la nueva API OSSL_STORE proporcionada por OpenSSL 3.0, que acepta URIs para cargar claves de forma transparente desde archivos o cualquier otro mecanismo soportado, incluidas las URIs PKCS#11.

Sin embargo, para aquellas aplicaciones que aún no se pueden cambiar, existe una herramienta para generar un archivo PEM "envoltorio" (wrapper) que contiene la URI PKCS#11 necesaria para identificar una clave en un token.

Este archivo PEM se puede cargar a través de los métodos clásicos utilizados para analizar representaciones PEM/DER de claves y activará el uso de los decodificadores del proveedor pkcs11 cuando se cargue el proveedor. Se devolverá un error si el proveedor no está precargado o si se utiliza una versión antigua de OpenSSL.

En tools/uri2pem.py hay un script de ejemplo en Python que puede tomar una URI de clave y producir un archivo PEM que la referencia. Tenga en cuenta que almacenar PIN en estos archivos PEM no es seguro. Estos archivos no están cifrados.

El siguiente comando se puede usar para listar todas las claves en un token e imprimir su URI identificadora:

openssl storeutl -keys -text pkcs11:

EJEMPLOS

openssl.cnf:

HOME = .
# Úsese esto para cargar automáticamente los proveedores.
openssl_conf = openssl_init
[openssl_init]
providers = provider_sect
[provider_sect]
default = default_sect
pkcs11 = pkcs11_sect
[default_sect]
activate = 1
[pkcs11_sect]
module = /usr/lib64/ossl-modules/pkcs11.so
pkcs11-module-path = /usr/lib64/pkcs11/vendor_pkcs11.so
pkcs11-module-token-pin = /etc/ssl/pinfile.txt
activate = 1
