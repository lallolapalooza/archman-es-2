proc_sys_vm(5) Manual de Formatos de Archivo proc_sys_vm(5)

NOMBRE

/proc/sys/vm/ - sistema de subgestión de memoria virtual

DESCRIPCIÓN

/proc/sys/vm/
Este directorio contiene archivos para la afinación de la gestión de memoria, y la gestión de búferes y cachés.
/proc/sys/vm/admin_reserve_kbytes (desde Linux 3.10)
Este archivo define la cantidad de memoria libre (en KiB) en el sistema que debe reservarse para los usuarios con la capacidad CAP_SYS_ADMIN.
El valor predeterminado en este archivo es el mínimo de [3% de páginas libres, 8MiB] expresado en KiB. El valor predeterminado está destinado a proporcionar suficiente espacio para que el superusuario inicie sesión y mate un proceso, si es necesario, bajo el modo de sobreaprovisionamiento predeterminado 'adivina' (es decir, 0 en /proc/sys/vm/overcommit_memory).
Los sistemas que se ejecutan en modo de 'nunca sobreaprovisionar' (es decir, 2 en /proc/sys/vm/overcommit_memory) deberían aumentar el valor en este archivo para tener en cuenta el tamaño total de memoria virtual de los programas utilizados para recuperarse (por ejemplo, login(1), ssh(1) y top(1)). De lo contrario, el superusuario podría no poder iniciar sesión para recuperar el sistema. Por ejemplo, en x86-64 un valor adecuado es 131072 (128MiB reservados).
Cambiar el valor en este archivo surte efecto cada vez que una aplicación solicita memoria.
/proc/sys/vm/compact_memory (desde Linux 2.6.35)
Cuando se escribe 1 en este archivo, todas las zonas se compactan de modo que la memoria libre esté disponible en bloques contiguos siempre que sea posible. El efecto de esta acción se puede ver examinando /proc/buddyinfo.
Presente solo si el kernel se configuró con CONFIG_COMPACTION.
/proc/sys/vm/drop_caches (desde Linux 2.6.16)
Escribir en este archivo hace que el kernel elimine las cachés limpias, dentries e inodos de la memoria, liberando esa memoria. Esto puede ser útil para probar la gestión de memoria y realizar pruebas de rendimiento de sistemas de archivos reproducibles. Debido a que escribir en este archivo provoca la pérdida de los beneficios del almacenamiento en caché, puede degradar el rendimiento general del sistema.
Para liberar pagecache, usa:

echo 1 > /proc/sys/vm/drop_caches

Para liberar dentries e inodos, usa:

echo 2 > /proc/sys/vm/drop_caches

Para liberar pagecache, dentries e inodos, usa:

echo 3 > /proc/sys/vm/drop_caches

Dado que escribir en este archivo es una operación no destructiva y los objetos sucios no son liberables, el usuario debería ejecutar primero sync(1).
/proc/sys/vm/hugetlb_shm_group (desde Linux 2.6.7)
Este archivo escribible contiene un ID de grupo que tiene permitido asignar memoria utilizando páginas grandes. Si un proceso tiene un ID de grupo de sistema de archivos o cualquier ID de grupo suplementario que coincida con este ID de grupo, entonces puede realizar asignaciones de páginas grandes sin mantener la capacidad CAP_IPC_LOCK; consulta memfd_create(2), mmap(2) y shmget(2).
/proc/sys/vm/legacy_va_layout (desde Linux 2.6.9)
Si es distinto de cero, esto deshabilita el nuevo diseño de asignación de memoria de 32 bits; el kernel utilizará el diseño heredado (2.4) para todos los procesos.
/proc/sys/vm/memory_failure_early_kill (desde Linux 2.6.32)
Controla cómo matar procesos cuando se detecta un error de memoria no corregido (típicamente un error de 2 bits en un módulo de memoria) que el kernel no puede manejar en segundo plano por el hardware. En algunos casos (como cuando la página todavía tiene una copia válida en disco), el kernel manejará el fallo de forma transparente sin afectar a ninguna aplicación. Pero si no hay otra copia actualizada de los datos, matará procesos para evitar que las corrupciones de datos se propaguen.
El archivo tiene uno de los siguientes valores:
1
Mata todos los procesos que tienen la página corrompida y no recargable mapeada tan pronto como se detecta la corrupción. Ten en cuenta que esto no se admite para algunos tipos de páginas, como los datos asignados internamente por el kernel o la caché de intercambio, pero funciona para la mayoría de las páginas de usuario.
0
Desmapea la página corrompida de todos los procesos y mata un proceso solo si intenta acceder a la página.
La matanza se realiza utilizando una señal SIGBUS con si_code establecido en BUS_MCEERR_AO. Los procesos pueden manejar esto si lo desean; consulta sigaction(2) para más detalles.
Esta característica solo está activa en arquitecturas/plataformas con manejo avanzado de comprobación de máquina y depende de las capacidades del hardware.
Las aplicaciones pueden anular la configuración de memory_failure_early_kill individualmente con la operación prctl(2) PR_MCE_KILL.
Presente solo si el kernel se configuró con CONFIG_MEMORY_FAILURE.
/proc/sys/vm/memory_failure_recovery (desde Linux 2.6.32)
Habilita la recuperación de fallos de memoria (cuando es compatible con la plataforma).
1
Intenta la recuperación.
0
Siempre entra en pánico ante un fallo de memoria.
Presente solo si el kernel se configuró con CONFIG_MEMORY_FAILURE.
/proc/sys/vm/oom_dump_tasks (desde Linux 2.6.25)
Habilita la generación de un volcado de tareas a nivel de sistema (excluyendo hilos del kernel) cuando el kernel realiza una acción OOM (Out Of Memory). El volcado incluye la siguiente información para cada tarea (hilo, proceso): ID de hilo, ID de usuario real, ID de grupo de hilos (ID de proceso), tamaño de memoria virtual, tamaño del conjunto residente, la CPU en la que está programada la tarea, puntuación oom_adj (ver la descripción de /proc/pid/oom_adj) y nombre del comando. Esto es útil para determinar por qué se invocó al OOM-killer y para identificar la tarea rebelde que lo provocó.
Si contiene el valor cero, esta información se suprime. En sistemas muy grandes con miles de tareas, puede no ser factible volcar la información del estado de la memoria para cada una. Dichos sistemas no deben verse obligados a incurrir en una penalización de rendimiento en situaciones OOM cuando la información puede no ser deseada.
Si se establece en un valor distinto de cero, esta información se muestra siempre que el OOM-killer mata realmente una tarea que consume mucha memoria.
El valor predeterminado es 0.
/proc/sys/vm/oom_kill_allocating_task (desde Linux 2.6.24)
Habilita o deshabilita la matanza de la tarea que desencadena OOM en situaciones de falta de memoria.
Si se establece en cero, el OOM-killer escanea toda la lista de tareas y selecciona una tarea basándose en heurísticas para matar. Esto normalmente selecciona una tarea rebelde que consume mucha memoria y que libera una gran cantidad de memoria al ser matada.
Si se establece en un valor distinto de cero, el OOM-killer simplemente mata la tarea que desencadenó la condición de falta de memoria. Esto evita un escaneo potencialmente costoso de la lista de tareas.
Si /proc/sys/vm/panic_on_oom es distinto de cero, tiene prioridad sobre cualquier valor utilizado en /proc/sys/vm/oom_kill_allocating_task.
El valor predeterminado es 0.
/proc/sys/vm/overcommit_kbytes (desde Linux 3.14)
Este archivo escribible proporciona una alternativa a /proc/sys/vm/overcommit_ratio para controlar el CommitLimit cuando /proc/sys/vm/overcommit_memory tiene el valor 2. Permite especificar la cantidad de sobreaprovisionamiento de memoria como un valor absoluto (en kB), en lugar de como un porcentaje, como se hace con overcommit_ratio. Esto permite un control más granular de CommitLimit en sistemas con tamaños de memoria extremadamente grandes.
Solo uno de overcommit_kbytes o overcommit_ratio puede tener efecto: si overcommit_kbytes tiene un valor distinto de cero, entonces se utiliza para calcular CommitLim

proc_sys_vm.5.en

NOMBRE

proc_sys_vm - parámetros del kernel relacionados con la gestión de memoria virtual

DESCRIPCIÓN

El archivo /proc/sys/vm/* contiene varios parámetros del kernel que permiten modificar el comportamiento de la gestión de memoria virtual. Los valores de estos archivos se pueden leer y escribir. Escribir en ellos generalmente requiere privilegios de administrador (root).

/proc/sys/vm/admin_reserve_kbytes (desde Linux 3.10)
Este archivo especifica una cantidad de memoria (en KiB) que el administrador del sistema reserva para sí mismo. Esto está destinado a garantizar que el administrador siempre pueda iniciar procesos (por ejemplo, para matar un proceso descontrolado) incluso si un usuario ha consumido casi toda la memoria disponible. Este valor solo tiene efecto cuando /proc/sys/vm/overcommit_memory está configurado en 2 (modo "sin sobrecomprometer"). En este modo, el sistema reserva la cantidad especificada en este archivo para el administrador y limita las asignaciones de memoria de los usuarios al resto de la memoria disponible.
El valor predeterminado es el mínimo de [3% de las páginas libres, 128MiB] expresado en KiB.
Si el valor de este archivo se establece en cero, el administrador no se reserva ninguna memoria, lo que significa que un usuario podría potencialmente consumir toda la memoria disponible con un solo proceso (lo que provocaría un error de "fork: Cannot allocate memory" al intentar ejecutar cualquier otro comando).
Cambiar el valor de este archivo surte efecto cuando una aplicación solicita memoria.
/proc/sys/vm/legacy_va_layout (desde Linux 5.6)
Este archivo controla si se utilizan diseños de memoria virtuales más antiguos (0) o más nuevos (1). Los diseños más nuevos son más eficientes para asignar grandes cantidades de memoria virtual. El valor predeterminado es 1.
/proc/sys/vm/memory_failure_early_kill (desde Linux 5.4)
Controla si el kernel debe finalizar los procesos que utilizan memoria afectada por un error de hardware (Hardware Memory Error Detection and Reporting (EDAC)) antes de intentar corregirlo. El valor 0 (predeterminado) permite al kernel intentar corregir el error primero. El valor 1 finaliza los procesos que utilizan la memoria afectada.
/proc/sys/vm/min_free_kbytes
Este archivo controla la cantidad mínima de memoria libre (en KiB) que el kernel intentará mantener en cada zona de memoria. El demonio dekswapd se asegura de que la cantidad de memoria libre en cada zona nunca caiga por debajo de este umbral. El valor predeterminado es 1/125 de la RAM total, aproximadamente 128 MiB en sistemas con 16 GiB de RAM.
/proc/sys/vm/overcommit_kbytes (desde Linux 3.14)
Este archivo reemplaza el cálculo de CommitLimit basado en overcommit_ratio. Si overcommit_kbytes no es cero, entonces el CommitLimit se calcula como overcommit_kbytes + total_swap. Esto permite un control más preciso sobre el límite de compromiso de memoria.
/proc/sys/vm/overcommit_memory
Este archivo contiene el modo de contabilidad de memoria virtual del kernel. Los valores son:
0: sobrecomprometer heurístico (este es el valor predeterminado)
1: siempre sobrecomprometer, nunca comprobar
2: siempre comprobar, nunca sobrecomprometer
En el modo 0, las llamadas a mmap(2) con MAP_NORESERVE no se comprueban y la comprobación predeterminada es muy débil, lo que genera el riesgo de que un proceso sea "OOM-killed" (terminado por falta de memoria).
En el modo 1, el kernel simula que siempre hay suficiente memoria, hasta que la memoria realmente se agota. Un caso de uso para este modo son las aplicaciones de computación científica que emplean matrices dispersas grandes. Antes de Linux 2.6.0, cualquier valor distinto de cero implicaba el modo 1.
En el modo 2 (disponible desde Linux 2.6), el espacio total de direcciones virtuales que se puede asignar (CommitLimit en /proc/meminfo) se calcula como

CommitLimit = (RAM_total - huge_TLB_total) *
	      overcommit_ratio / 100 + swap_total

donde:
•
RAM_total es la cantidad total de RAM en el sistema;
•
huge_TLB_total es la cantidad de memoria reservada para páginas grandes (huge pages);
•
overcommit_ratio es el valor en /proc/sys/vm/overcommit_ratio; y
•
swap_total es la cantidad de espacio de intercambio (swap).
Por ejemplo, en un sistema con 16 GB de RAM física, 16 GB de swap, ningún espacio dedicado a páginas grandes y un overcommit_ratio de 50, esta fórmula produce un CommitLimit de 24 GB.
Desde Linux 3.14, si el valor en /proc/sys/vm/overcommit_kbytes no es cero, entonces CommitLimit se calcula de la siguiente manera:

CommitLimit = overcommit_kbytes + swap_total

Ver también la descripción de /proc/sys/vm/admin_reserve_kbytes y /proc/sys/vm/user_reserve_kbytes.
/proc/sys/vm/overcommit_ratio (desde Linux 2.6.0)
Este archivo escribible define un porcentaje por el cual la memoria puede ser sobrecomprometida. El valor predeterminado en el archivo es 50. Ver la descripción de /proc/sys/vm/overcommit_memory.
/proc/sys/vm/panic_on_oom (desde Linux 2.6.18)
Esto habilita o deshabilita un pánico del kernel en una situación de falta de memoria (out-of-memory).
Si este archivo se establece en el valor 0, el OOM-killer (asesino de procesos por falta de memoria) del kernel matará algún proceso descontrolado. Por lo general, el OOM-killer es capaz de matar un proceso descontrolado y el sistema sobrevive.
Si este archivo se establece en el valor 1, el kernel normalmente entra en pánico cuando ocurre una falta de memoria. Sin embargo, si un proceso limita las asignaciones a nodos específicos utilizando políticas de memoria (mbind(2) MPOL_BIND) o cpusets (cpuset(7)) y esos nodos alcanzan el estado de agotamiento de memoria, un proceso puede ser matado por el OOM-killer. En este caso no ocurre ningún pánico: debido a que la memoria de otros nodos puede estar libre, esto significa que el sistema en su conjunto puede no haber alcanzado todavía una situación de falta de memoria.
Si este archivo se establece en el valor 2, el kernel siempre entra en pánico cuando ocurre una condición de falta de memoria.
El valor predeterminado es 0. Los valores 1 y 2 son para la conmutación de errores (failover) de clústeres. Seleccione uno de acuerdo con su política de conmutación de errores.
/proc/sys/vm/stat_refresh (desde Linux 2.6.36)
La escritura de cualquier valor en este archivo provoca una actualización inmediata de las estadísticas de memoria en /proc/vmstat. Por defecto, estas estadísticas se actualizan de forma perezosa.
/proc/sys/vm/swappiness
El valor en este archivo controla la agresividad con la que el kernel intercambiará (swapping) páginas de memoria. Valores más altos aumentan la agresividad, valores más bajos la disminuyen. El valor predeterminado es 60.
/proc/sys/vm/user_reserve_kbytes (desde Linux 3.10)
Especifica una cantidad de memoria (en KiB) para reservar para procesos de usuario. Esto está destinado a evitar que un usuario inicie un único proceso que consuma mucha memoria, de modo que no pueda recuperarse (matar al proceso consumidor). El valor en este archivo solo tiene efecto cuando /proc/sys/vm/overcommit_memory está configurado en 2 ("nunca sobrecomprometer"). En este caso, el sistema reserva una cantidad de memoria que es el mínimo de [3% del tamaño actual del proceso, user_reserve_kbytes].
El valor predeterminado en este archivo es el mínimo de [3% de las páginas libres, 128MiB] expresado en KiB.
Si el valor en este archivo se establece en cero, entonces se permitirá a un usuario asignar toda la memoria libre con un solo proceso (menos la cantidad reservada por /proc/sys/vm/admin_reserve_kbytes). Cualquier intento posterior de ejecutar un comando dará como resultado "fork: Cannot allocate memory".
Cambiar el valor en este archivo entra en vigor cada vez que una aplicación solicita memoria.
/proc/sys/vm/unprivileged_userfaultfd (desde Linux 5.2)
Este archivo (escribible) expone un indicador que controla si se permite a los procesos no privilegiados emplear userfaultfd(2). Si este archivo tiene el valor 1, entonces los procesos no privilegiados pueden usar userfaultfd(2). Si este archivo tiene el valor 0, entonces solo los procesos que tienen la capacidad CAP_SYS_PTRACE pueden emplear userfaultfd(2). El valor predeterminado en este archivo es 1.
