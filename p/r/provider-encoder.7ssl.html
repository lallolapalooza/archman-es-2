provider-encoder(7ssl)

PROVIDER-ENCODER(7ssl) OpenSSL PROVIDER-ENCODER(7ssl)

NOMBRE

provider-encoder - Las funciones de la biblioteca OSSL_ENCODER <-> proveedor

SINOPSIS

#include <openssl/core_dispatch.h>
/*
 * Ninguna de estas son funciones reales, sino que se muestran así para
 * las firmas de funciones que se ofrecen como punteros a función en arreglos OSSL_DISPATCH.
 */
/* Accesor y descriptor de parámetros del codificador */
const OSSL_PARAM *OSSL_FUNC_encoder_gettable_params(void *provctx);
int OSSL_FUNC_encoder_get_params(OSSL_PARAM params[]);
/* Funciones para construir / destruir / manipular el contexto del codificador */
void *OSSL_FUNC_encoder_newctx(void *provctx);
void OSSL_FUNC_encoder_freectx(void *ctx);
int OSSL_FUNC_encoder_set_ctx_params(void *ctx, const OSSL_PARAM params[]);
const OSSL_PARAM *OSSL_FUNC_encoder_settable_ctx_params(void *provctx);
/* Funciones para verificar el soporte de selección */
int OSSL_FUNC_encoder_does_selection(void *provctx, int selection);
/* Funciones para codificar datos de objeto */
int OSSL_FUNC_encoder_encode(void *ctx, OSSL_CORE_BIO *out,
                             const void *obj_raw,
                             const OSSL_PARAM obj_abstract[],
                             int selection,
                             OSSL_PASSPHRASE_CALLBACK *cb,
                             void *cbarg);
/* Funciones para importar y liberar un objeto temporal para ser codificado */
void *OSSL_FUNC_encoder_import_object(void *ctx, int selection,
                                      const OSSL_PARAM params[]);
void OSSL_FUNC_encoder_free_object(void *obj);

DESCRIPCIÓN

Usamos el término amplio "codificar" en este manual. Esto incluye, pero no se limita a, la serialización.

La operación ENCODER es un método genérico para codificar un objeto nativo del proveedor (obj_raw) o una abstracción de objeto (object_abstract, ver provider-object(7)) en una forma codificada, y escribir el resultado en el OSSL_CORE_BIO dado. Si el llamador quiere obtener la corriente codificada a memoria, debe proporcionar un BIO de tipo BIO_s_mem(3).

El codificador no necesita saber más sobre el puntero OSSL_CORE_BIO que poder pasarlo a las llamadas apropiadas de BIO (ver "Core functions" en provider-base(7)).

La implementación del codificador puede ser parte de una cadena, donde los datos se pasan de uno a otro. Por ejemplo, puede haber una implementación para codificar un objeto a DER (se asume que ese objeto es nativo del proveedor y por lo tanto se pasa a través de obj_raw), y otra que codifique DER a PEM (esa recibiría la codificación DER a través de obj_abstract).

La codificación utilizando el formato de arreglo de OSSL_PARAM(3) permite que un codificador se utilice para datos que han sido exportados desde otro proveedor, y por lo tanto permitir que existan independientemente el uno del otro.

La codificación utilizando un objeto del lado del proveedor solo se puede usar de forma segura con datos del proveedor provenientes del mismo proveedor, por ejemplo, claves con el proveedor KEYMGMT.

Todas las "funciones" mencionadas aquí se pasan como punteros a función entre libcrypto y el proveedor en arreglos OSSL_DISPATCH(3) a través de arreglos OSSL_ALGORITHM(3) que son devueltos por la función provider_query_operation() del proveedor (ver "Provider Functions" en provider-base(7)).

Todas estas "funciones" tienen una definición de tipo de función correspondiente llamada OSSL_FUNC_{name}_fn, y una función auxiliar para obtener el puntero de función de un elemento OSSL_DISPATCH(3) llamada OSSL_FUNC_{name}. Por ejemplo, la "función" OSSL_FUNC_encoder_encode() tiene estos:

typedef int
    (OSSL_FUNC_encoder_encode_fn)(void *ctx, OSSL_CORE_BIO *out,
                                  const void *obj_raw,
                                  const OSSL_PARAM obj_abstract[],
                                  int selection,
                                  OSSL_PASSPHRASE_CALLBACK *cb, void *cbarg);
static ossl_inline OSSL_FUNC_encoder_encode_fn
    OSSL_FUNC_encoder_encode(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) Los arreglos se indexan por números que se proporcionan como macros en openssl-core_dispatch.h(7), de la siguiente manera:

OSSL_FUNC_encoder_get_params          OSSL_FUNC_ENCODER_GET_PARAMS
OSSL_FUNC_encoder_gettable_params     OSSL_FUNC_ENCODER_GETTABLE_PARAMS
OSSL_FUNC_encoder_newctx              OSSL_FUNC_ENCODER_NEWCTX
OSSL_FUNC_encoder_freectx             OSSL_FUNC_ENCODER_FREECTX
OSSL_FUNC_encoder_set_ctx_params      OSSL_FUNC_ENCODER_SET_CTX_PARAMS
OSSL_FUNC_encoder_settable_ctx_params OSSL_FUNC_ENCODER_SETTABLE_CTX_PARAMS
OSSL_FUNC_encoder_does_selection      OSSL_FUNC_ENCODER_DOES_SELECTION
OSSL_FUNC_encoder_encode              OSSL_FUNC_ENCODER_ENCODE
OSSL_FUNC_encoder_import_object       OSSL_FUNC_ENCODER_IMPORT_OBJECT
OSSL_FUNC_encoder_free_object         OSSL_FUNC_ENCODER_FREE_OBJECT

Nombres y propiedades

El nombre de una implementación debe coincidir con el tipo de objeto que maneja. Por ejemplo, una implementación que codifica una clave RSA debe llamarse "RSA". De manera similar, una implementación que codifica adicionalmente DER debe llamarse "DER".

Las propiedades, según se definen en el elemento de arreglo OSSL_ALGORITHM(3) de cada implementación de decodificador, se pueden utilizar para especificar más detalles sobre una implementación:

output
Esta propiedad se utiliza para especificar qué tipo de salida produce la implementación.

Esta propiedad es obligatoria.

Los proveedores de OpenSSL reconocen los siguientes tipos de salida:

text
Una implementación con ese tipo de salida produce texto legible por humanos, lo que hace que esa implementación sea adecuada para la salida "-text" en diversos comandos de openssl(1).
pem
Una implementación con ese tipo de salida produce datos en formato PEM.
der
Una implementación con ese tipo de salida produce datos en formato DER.
msblob
Una implementación con ese tipo de salida produce datos en formato MSBLOB.
pvk
Una implementación con ese tipo de salida produce datos en formato PVK.
structure
Esta propiedad se utiliza para especificar la estructura que se utiliza para el objeto codificado. Un ejemplo podría ser "pkcs8", para especificar explícitamente que un objeto (presumiblemente un par de claves asimétricas, en este caso) se envolverá en una estructura PKCS#8 como parte de la codificación.

Esta propiedad es opcional.

Los valores posibles de ambas propiedades son de final abierto. Un proveedor puede especificar tipos de salida y estructuras sobre las que libcrypto no sepa nada.

Selecciones de subconjuntos

A veces, un objeto tiene más de un subconjunto de datos que es interesante tratar por separado o en conjunto. Es posible especificar qué subconjuntos se van a codificar, con un conjunto de bits selection que se pasan en un int.

Este conjunto de bits depende completamente del tipo de objeto del lado del proveedor que se pasa. Por ejemplo, se asume que esos bits son los mismos que los utilizados con provider-keymgmt(7) (ver "Key Objects" en provider-keymgmt(7)) cuando el objeto es un par de claves asimétricas.

Las implementaciones de ENCODER son libres de considerar la selection como un conjunto de sugerencias, pero deben hacerlo con cuidado. Al final, la salida debe tener sentido, y si hay un decodificador correspondiente, el objeto decodificado resultante debe coincidir con el objeto original que se codificó.

OSSL_FUNC_encoder_does_selection() debería indicar si una implementación particular soporta alguna de las combinaciones dadas por selection.

Funciones de contexto

OSSL_FUNC_encoder_newctx() devuelve un contexto que se utilizará con el resto de las funciones.

NAME

provider-encoder - Encoder algorithm support

SYNOPSIS

 char *OSSL_FUNC_encoder_newctx(const OSSL_DISPATCH *provider_dispatch);
 void OSL_FUNC_encoder_freectx(char *ctx);
 int OSSL_FUNC_encoder_set_ctx_params(char *ctx, const OSSL_PARAM params[]);
 const OSSL_PARAM *OSSL_FUNC_encoder_settable_ctx_params(char *ctx);
 int OSSL_FUNC_encoder_does_selection(const char *ctx, unsigned int selection);
 char *OSSL_FUNC_encoder_import_object(const char *ctx, unsigned int selection,
                                      const OSSL_PARAM params[]);
 void OSSL_FUNC_encoder_free_object(char *obj);
 int OSSL_FUNC_encoder_encode(const char *ctx, OSSL_CORE_BIO *out,
                              const char *selection,
                              OSSL_PASSPHRASE_CALLBACK_CB_FUNC cb, void *cbarg,
                              const char *obj_abstract,
                              const char *obj_raw);

DESCRIPTION

This describes the encoder interface that is available from an OpenSSL provider.

Context functions

OSSL_FUNC_encoder_newctx() is used to create an encoder context, which is used by subsequent calls to other functions. The provider dispatch table OSSL_DISPATCH(3) must be passed.

OSSL_FUNC_encoder_freectx() frees the given ctx, if it was created by OSSL_FUNC_encoder_newctx().

OSSL_FUNC_encoder_set_ctx_params() sets context data according to parameters from params that it recognises. Unrecognised parameters should be ignored. Passing NULL for params should return true.

OSSL_FUNC_encoder_settable_ctx_params() returns a constant OSSL_PARAM(3) array describing the parameters that OSSL_FUNC_encoder_set_ctx_params() can handle.

See OSSL_PARAM(3) for further details on the parameters structure used by OSSL_FUNC_encoder_set_ctx_params() and OSSL_FUNC_encoder_settable_ctx_params().

Import functions

A provider-native object may be associated with a foreign provider, and may therefore be unsuitable for direct use with a given ENCODER implementation. Provided that the foreign provider's implementation to handle the object has a function to export that object in OSSL_PARAM(3) array form, the ENCODER implementation should be able to import that array and create a suitable object to be passed to OSSL_FUNC_encoder_encode()'s obj_raw.

OSSL_FUNC_encoder_import_object() should import the subset of params given with selection to create a provider-native object that can be passed as obj_raw to OSSL_FUNC_encoder_encode().

OSSL_FUNC_encoder_free_object() should free the object that was created with OSSL_FUNC_encoder_import_object().

Encoding functions

OSSL_FUNC_encoder_encode() should take a provider-native object (in obj_raw) or an object abstraction (in obj_abstract), and should output the object in encoded form to the OSSL_CORE_BIO. The selection bits, if relevant, should determine in greater detail what will be output. The encoding functions also take an OSSL_PASSPHRASE_CALLBACK(3) function pointer along with a pointer to application data cbarg, which should be used when a pass phrase prompt is needed.

Encoder operation parameters

Operation parameters currently recognised by built-in encoders are as follows:

"cipher" (OSSL_ENCODER_PARAM_CIPHER) <UTF8 string>
The name of the encryption cipher to be used when generating encrypted encoding. This is used when encoding private keys, as well as other objects that need protection.

If this name is invalid for the encoding implementation, the implementation should refuse to perform the encoding, i.e. OSSL_FUNC_encoder_encode_data() and OSSL_FUNC_encoder_encode_object() should return an error.

"properties" (OSSL_ENCODER_PARAM_PROPERTIES) <UTF8 string>
The properties to be queried when trying to fetch the algorithm given with the "cipher" parameter. This must be given together with the "cipher" parameter to be considered valid.

The encoding implementation isn't obligated to use this value. However, it is recommended that implementations that do not handle property strings return an error on receiving this parameter unless its value NULL or the empty string.

"save-parameters" (OSSL_ENCODER_PARAM_SAVE_PARAMETERS) <integer>
If set to 0 disables saving of key domain parameters. Default is 1. It currently has an effect only on DSA keys.

Parameters currently recognised by the built-in pass phrase callback:

"info" (OSSL_PASSPHRASE_PARAM_INFO) <UTF8 string>
A string of information that will become part of the pass phrase prompt. This could be used to give the user information on what kind of object it's being prompted for.

RETURN VALUES

OSSL_FUNC_encoder_newctx() returns a pointer to a context, or NULL on failure.

OSSL_FUNC_encoder_set_ctx_params() returns 1, unless a recognised parameter was invalid or caused an error, for which 0 is returned.

OSSL_FUNC_encoder_settable_ctx_params() returns a pointer to an array of constant OSSL_PARAM(3) elements.

OSSL_FUNC_encoder_does_selection() returns 1 if the encoder implementation supports any of the selection bits, otherwise 0.

OSSL_FUNC_encoder_encode() returns 1 on success, or 0 on failure.
