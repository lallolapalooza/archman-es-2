PROVIDER-STOREMGMT(7ssl) OpenSSL PROVIDER-STOREMGMT(7ssl)

NOMBRE

provider-storemgmt - Funciones de la biblioteca OSSL_STORE <-> proveedor

SINOPSIS

#include <openssl/core_dispatch.h>
/*
 * Ninguna de estas son funciones reales, sino que se muestran así para
 * las firmas de funciones que se ofrecen como punteros de función en
 * arreglos de OSSL_DISPATCH.
 */
void *OSSL_FUNC_store_open(void *provctx, const char *uri);
void *OSSL_FUNC_store_attach(void *provctx, OSSL_CORE_BIO *bio);
const OSSL_PARAM *store_settable_ctx_params(void *provctx);
int OSSL_FUNC_store_set_ctx_params(void *loaderctx, const OSSL_PARAM[]);
int OSSL_FUNC_store_load(void *loaderctx,
                         OSSL_CALLBACK *object_cb, void *object_cbarg,
                         OSSL_PASSPHRASE_CALLBACK *pw_cb, void *pw_cbarg);
int OSSL_FUNC_store_eof(void *loaderctx);
int OSSL_FUNC_store_close(void *loaderctx);
int OSSL_FUNC_store_export_object
    (void *loaderctx, const void *objref, size_t objref_sz,
     OSSL_CALLBACK *export_cb, void *export_cbarg);
void *OSSL_FUNC_store_open_ex(void *provctx, const char *uri,
                              const OSSL_PARAM params[],
                              OSSL_PASSPHRASE_CALLBACK *pw_cb,
                              void *pw_cbarg);
int OSSL_FUNC_store_delete(void *provctx, const char *uri,
                   const OSSL_PARAM params[],
                   OSSL_PASSPHRASE_CALLBACK *pw_cb, void *pw_cbarg);

DESCRIPCIÓN

La operación STORE es el lado del proveedor de la API de ossl_store(7).

La responsabilidad principal de la operación STORE es cargar todo tipo de objetos desde un contenedor indicado por URI. Estos objetos se entregan a la biblioteca OpenSSL en forma de abstracción de objeto nativa del proveedor (ver provider-object(7)). La biblioteca OpenSSL es entonces responsable de pasar esa abstracción a funciones de proveedor adecuadas.

Ejemplos de funciones a las que la biblioteca OpenSSL puede pasar la abstracción incluyen OSSL_FUNC_keymgmt_load() (provider-keymgmt(7)), OSSL_FUNC_store_export_object() (que exporta el objeto en forma parametrizada).

Todas las "funciones" mencionadas aquí se pasan como punteros de función entre libcrypto y el proveedor en arreglos de OSSL_DISPATCH(3) a través de arreglos de OSSL_ALGORITHM(3) que son devueltos por la función provider_query_operation() del proveedor (ver "Funciones del proveedor" en provider-base(7)).

Todas estas "funciones" tienen una definición de tipo de función correspondiente llamada OSSL_FUNC_{name}_fn, y una función auxiliar para recuperar el puntero de función de un elemento de OSSL_DISPATCH(3) llamada OSSL_get_{name}. Por ejemplo, la "función" OSSL_FUNC_store_attach() tiene:

typedef void *(OSSL_FUNC_store_attach_fn)(void *provctx,
                                          OSSL_CORE_BIO * bio);
static ossl_inline OSSL_FUNC_store_attach_fn
    OSSL_FUNC_store_attach(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) Los arreglos se indexan por números que se proporcionan como macros en openssl-core_dispatch.h(7), como sigue:

OSSL_FUNC_store_open                 OSSL_FUNC_STORE_OPEN
OSSL_FUNC_store_attach               OSSL_FUNC_STORE_ATTACH
OSSL_FUNC_store_settable_ctx_params  OSSL_FUNC_STORE_SETTABLE_CTX_PARAMS
OSSL_FUNC_store_set_ctx_params       OSSL_FUNC_STORE_SET_CTX_PARAMS
OSSL_FUNC_store_load                 OSSL_FUNC_STORE_LOAD
OSSL_FUNC_store_eof                  OSSL_FUNC_STORE_EOF
OSSL_FUNC_store_close                OSSL_FUNC_STORE_CLOSE
OSSL_FUNC_store_export_object        OSSL_FUNC_STORE_EXPORT_OBJECT
OSSL_FUNC_store_delete               OSSL_FUNC_STORE_DELETE
OSSL_FUNC_store_open_ex              OSSL_FUNC_STORE_OPEN_EX

Funciones

OSSL_FUNC_store_open() debe crear un contexto del lado del proveedor con datos basados en la uri de entrada. La implementación es totalmente responsable de la interpretación de la URI.

OSSL_FUNC_store_attach() debe crear un contexto del lado del proveedor con el BIO central bio adjunto. Esta es una alternativa a usar una URI para encontrar almacenamiento, compatible con OSSL_STORE_attach(3).

OSSL_FUNC_store_settable_ctx_params() debe devolver un arreglo constante de descriptores OSSL_PARAM(3), para parámetros que OSSL_FUNC_store_set_ctx_params() pueda manejar.

OSSL_FUNC_store_set_ctx_params() debe establecer parámetros adicionales, como qué tipo de datos esperar, criterios de búsqueda, etc. Más sobre eso a continuación, en "Parámetros de carga". Si los parámetros no reconocidos son un error o simplemente se ignoran, queda a discreción de la implementación. Pasar NULL para params debe devolver true.

OSSL_FUNC_store_load() carga el siguiente objeto de la URI abierta por OSSL_FUNC_store_open(), crea una abstracción de objeto para él (ver provider-object(7)), y llama a object_cb con él así como con object_cbarg. object_cb entonces interpretará la abstracción del objeto y hará lo que pueda para envolverla o decodificarla en una estructura OpenSSL. En caso de que se necesite una contraseña para desbloquear un objeto, se debe llamar a pw_cb.

OSSL_FUNC_store_eof() indica si se ha alcanzado el final del conjunto de objetos de la URI. Cuando eso sucede, no tiene sentido intentar seguir cargando.

OSSL_FUNC_store_close() libera el contexto del lado del proveedor ctx.

Cuando un administrador de tienda crea un objeto nativo del proveedor, sería inadecuado para su uso directo con un proveedor extranjero. La función de exportación permite exportar el objeto a ese proveedor extranjero si el proveedor extranjero soporta el tipo de objeto y proporciona una función de importación.

OSSL_FUNC_store_export_object() debe exportar el objeto de tamaño objref_sz referenciado por objref como un arreglo de OSSL_PARAM(3) y pasarlo a export_cb así como a export_cbarg dado.

OSSL_FUNC_store_delete() elimina el objeto identificado por la uri. La implementación es totalmente responsable de la interpretación de la URI. En caso de que se necesite una contraseña para eliminar un objeto, se debe llamar a pw_cb.

OSSL_FUNC_store_open_ex() es una variante extendida de OSSL_FUNC_store_open(). Si el proveedor no implementa esta función, el código recurre internamente al uso de la original OSSL_FUNC_store_open(). Esta variante acepta adicionalmente un objeto OSSL_PARAM(3) y una devolución de llamada pw_cb que se puede usar para solicitar una contraseña en casos en que toda la tienda necesite ser desbloqueada antes de realizar cualquier operación de carga.

Parámetros de carga

"expect" (OSSL_STORE_PARAM_EXPECT) <entero>
Es una pista de qué tipo de datos espera recibir la biblioteca OpenSSL. Esto solo es útil para optimización, ya que la biblioteca también verificará que los tipos de objetos coincidan con la expectativa.

El número que se puede dar a través de este parámetro se encuentra en <openssl/store.h>, con macros que tienen nombres que comienzan con "OSSL_STORE_INFO_". Estos se describen con más detalle en "OBJETOS SOPORTADOS" en OSSL_STORE_INFO(3).

"subject" (OSSL_STORE_PARAM_SUBJECT) <cadena de octetos>
Indica que el llamante desea buscar un objeto con el sujeto dado asociado. Esto se puede usar para seleccionar certificados específicos por sujeto.

Se espera que el contenido de la cadena de octetos esté en formato DER.

"issuer" (OSSL_STORE_PARAM_ISSUER) <cadena de octetos>
Indica que el llamante desea buscar un objeto con el emisor dado asociado. Esto se puede usar para seleccionar certificados específicos por emisor.

Se espera que el contenido de la cadena de octetos esté en formato DER.

"serial" (OSSL_STORE_PARAM_SERIAL) <entero>
Indica que el llamante desea buscar un objeto con el número de serie dado asociado.
"digest" (OSSL_STORE_PARAM_DIGEST) <cadena UTF8>
"fingerprint" (OSSL_STORE_PARAM_FINGERPRINT) <octeto cadena>

provider-storemgmt(7ssl)

NAME

provider-storemgmt – OpenSSL store manager API

SYNOPSIS

The OpenSSL STORE (storemgmt) operation provides functionality to manage collections of cryptographic objects such as certificates, CRLs, and private keys. Providers can implement this operation to offer different storage backends like files, PKCS#11 tokens, or other custom storage mechanisms.

The STORE operation is accessed through the OSSL_STORE_open() function. It takes a URI specifying the storage location and flags to control the access mode. The URI syntax typically follows the pattern:

scheme:[//authority/path]

where scheme identifies the type of storage (e.g., file, pkcs11).

The primary functions associated with the store operation are:

OSSL_STORE_open(const char *uri, const OSSL_DISPATCH *in, void *vdata, unsigned int flags, void *ctx)
Opens a connection to the specified store.
OSSL_STORE_close(OSSL_STORE_CTX *ctx)
Closes the connection to the store.
OSSL_STORE_load(OSSL_STORE_CTX *ctx, OSSL_STORE_INFO_LOADER_FN *loader_fn, void *loader_data)
Loads objects from the store using a callback function.
OSSL_STORE_get_result(OSSL_STORE_CTX *ctx)
Retrieves the result of the load operation.
OSSL_STORE_destroy(OSSL_STORE_CTX *ctx)
Destroys the store context.
OSSL_STORE_find(OSSL_STORE_CTX *ctx, OSSL_STORE_SEARCH_ITEM *search, OSSL_STORE_INFO_LOADER_FN *loader_fn, void *loader_data)
Searches for specific objects in the store.
OSSL_STORE_delete(OSSL_STORE_CTX *ctx, OSSL_STORE_SEARCH_ITEM *search, OSSL_STORE_INFO_LOADER_FN *loader_fn, void *loader_data)
Deletes objects matching the search criteria.

DESCRIPTION

The STORE operation in OpenSSL provides a unified interface for accessing cryptographic objects stored in various locations and formats. Providers can implement this operation to support different storage backends.

The core functionality revolves around opening a store, loading objects from it, and closing the store. It also supports searching for and deleting objects based on specific criteria.

When opening a store using OSSL_STORE_open(), a URI is provided to specify the location and type of the store. Flags can be used to control the access mode (e.g., read-only, read-write).

Loading objects typically involves providing a callback function that will be invoked for each object found in the store. This callback receives information about the object and can be used to process or filter them.

The STORE operation supports searching for objects using the OSSL_STORE_find() function. Search criteria are specified using OSSL_STORE_SEARCH_ITEM structures, which can include parameters like:

"issuer" (OSSL_STORE_PARAM_ISSUER) <OSSL_ estruturas>
Searches for objects issued by a specific issuer. The structure contains the issuer's name.
"serial" (OSSL_STORE_PARAM_SERIAL) <UTF8 string>
Searches for objects with a specific serial number.
"subject" (OSSL_STORE_PARAM_SUBJECT) <OSSL_ estruturas>
Searches for objects with a specific subject name.
"keyid" (OSSL_STORE_PARAM_KEYID) <UTF8 string>
Searches for objects with a specific key identifier.
"fingerprint" (OSSL_STORE_PARAM_FINGERPRINT) <UTF8 string>
Indicates that the caller wants to search for an object with the given fingerprint, computed with the given digest.
"alias" (OSSL_STORE_PARAM_ALIAS) <UTF8 string>
Indicates that the caller wants to search for an object with the given alias (some call it a "friendly name").
"properties" (OSSL_STORE_PARAM_PROPERTIES) <utf8 string>
Property string to use when querying for algorithms such as the OSSL_DECODER decoder implementations.
"input-type" (OSSL_STORE_PARAM_INPUT_TYPE) <utf8 string>
Type of the input format as a hint to use when decoding the objects in the store.

Several of these search criteria may be combined. For example, to search for a certificate by issuer+serial, both the "issuer" and the "serial" parameters will be given.
