PROXYMAP(8) Manual del Administrador del Sistema PROXYMAP(8)

NOMBRE

proxymap - Servidor proxy de tabla de búsqueda de Postfix

SINOPSIS

proxymap [opciones genéricas de demonio de Postfix]

DESCRIPCIÓN


El servidor proxymap(8) proporciona servicio de consulta de tabla de solo lectura o de lectura/escritura a los procesos de Postfix. Estos servicios se implementan con nombres de servicio distintos: proxymap y proxywrite, respectivamente. El propósito de estos servicios es:

  • Superar las restricciones de chroot. Por ejemplo, un servidor SMTP chrooted necesita acceso al archivo passwd del sistema para rechazar correo para direcciones locales inexistentes, pero no es práctico mantener una copia del archivo passwd en la cárcel chroot. La solución: 
    local_recipient_maps =
    proxy:unix:passwd.byname $alias_maps
  • Consolidar el número de tablas de búsqueda abiertas compartiendo una tabla abierta entre múltiples procesos. Por ejemplo, realizar conexiones mysql desde cada proceso demonio de Postfix da como resultado errores de "demasiadas conexiones". La solución: 
    virtual_alias_maps =
    proxy:mysql:/etc/postfix/virtual_alias.cf

    El número total de conexiones se limita al número de procesos del servidor proxymap.

  • Proporcionar funcionalidad de actualizador único para tablas de búsqueda que no admiten de manera confiable múltiples escritores (es decir, todas las tablas basadas en archivos que no se basan en lmdb).

El servidor proxymap(8) implementa las siguientes solicitudes:

abrir tipomapa:nombredemapa flags
Abrir la tabla con el tipo tipomapa y el nombre nombredemapa, según lo controlado por flags. La respuesta incluye las banderas dependientes del tipo de mapa (para distinguir una tabla de cadena fija de una tabla de expresión regular).
buscar tipomapa:nombredemapa flags clave
Buscar los datos almacenados bajo la clave solicitada. La respuesta es el código de estado de finalización de la solicitud y el valor del resultado de la búsqueda. El tipomapa:nombredemapa y flags son los mismos que con la solicitud abrir.
actualizar tipomapa:nombredemapa flags clave valor
Actualizar los datos almacenados bajo la clave solicitada. La respuesta es el código de estado de finalización de la solicitud. El tipomapa:nombredemapa y flags son los mismos que con la solicitud abrir.

Para implementar mapas de actualizador único, especifique un límite de proceso de 1 en la entrada de master.cf para el servicio proxywrite.

Esta solicitud es compatible con Postfix 2.5 y posteriores.

eliminar tipomapa:nombredemapa flags clave
Eliminar los datos almacenados bajo la clave solicitada. La respuesta es el código de estado de finalización de la solicitud. El tipomapa:nombredemapa y flags son los mismos que con la solicitud abrir.

Esta solicitud es compatible con Postfix 2.5 y posteriores.

secuencia tipomapa:nombredemapa flags funcion
Iterar sobre la base de datos especificada. La funcion es una de DICT_SEQ_FUN_FIRST o DICT_SEQ_FUN_NEXT. La respuesta es el código de estado de finalización de la solicitud y un valor de clave y resultado de la búsqueda, si se encuentran.

Esta solicitud es compatible con Postfix 2.9 y posteriores.

El estado de finalización de la solicitud es OK, RETRY, NOKEY (la búsqueda falló porque la clave no se encontró), BAD (solicitud mal formada) o DENY (la tabla no está aprobada para acceso de lectura o escritura proxy).

No hay comando cerrar, ni las tablas se cierran implícitamente cuando un cliente se desconecta. El propósito es compartir tablas entre múltiples procesos cliente.

GESTIÓN DE PROCESOS DEL SERVIDOR

proxymap(8) los servidores se ejecutan bajo el control del servidor master(8) de Postfix. Cada servidor puede manejar múltiples conexiones simultáneas. Cuando todos los servidores están ocupados mientras un cliente se conecta, el master(8) crea un nuevo proceso servidor proxymap(8), siempre que no se supere el límite de procesos. Cada servidor termina después de atender al menos $max_use clientes o después de $max_idle segundos de inactividad.

SEGURIDAD

El servidor proxymap(8) abre solo tablas que están aprobadas a través de los parámetros de configuración proxy_read_maps o proxy_write_maps, no habla con los usuarios y puede ejecutarse con privilegios bajos fijos, chrooted o no. Sin embargo, ejecutar el servidor proxymap chrooted limita severamente la usabilidad, ya que solo puede abrir tablas chrooted.

El servidor proxymap(8) no es un proceso demonio de confianza y no debe utilizarse para buscar información confidencial como IDs de usuario o grupo de UNIX, nombres de archivos/directorios de buzones de correo o comandos externos.

En Postfix versión 2.2 y posteriores, el cliente proxymap reconoce solicitudes para acceder a una tabla con fines de seguridad confidencial, y abre la tabla directamente. Esto permite que la misma configuración de main.cf sea utilizada por procesos confidenciales y no confidenciales.

Los archivos de datos escribibles por Postfix deben almacenarse en un directorio dedicado que solo sea escribible por el sistema de correo de Postfix, como el directorio data_directory propiedad de Postfix.

En particular, los archivos escribibles por Postfix nunca deben existir en directorios propiedad de root. Eso abriría un tipo particular de agujero de seguridad donde la propiedad de un archivo o directorio no coincide con el proveedor de su contenido.

DIAGNÓSTICO


Los problemas y las transacciones se registran en syslogd(8) o postlogd(8).

ERRORES


El servidor proxymap(8) proporciona servicio a múltiples clientes y, por lo tanto, no debe utilizarse para tablas que tengan búsquedas de alta latencia.

El servicio de lectura/escritura de proxymap(8) no cierra explícitamente las tablas de búsqueda (incluso si lo hiciera, no se podría confiar en ello, porque el proceso puede ser terminado entre las actualizaciones de la tabla). Por lo tanto, el servicio de lectura/escritura no debe utilizarse con tablas que dejen el almacenamiento persistente en un estado inconsistente entre actualizaciones (por ejemplo, CDB). Las tablas que admiten "sincronización en la actualización" deberían ser seguras (por ejemplo, Berkeley DB), al igual que las tablas implementadas por un DBMS real.

PARÁMETROS DE CONFIGURACIÓN

En sistemas de correo con mucho tráfico, puede pasar mucho tiempo antes de que los cambios relevantes de main.cf para proxymap(8) se apliquen. Use el comando "postfix reload" para acelerar un cambio.

El texto a continuación solo proporciona un resumen de los parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

config_directory (ver la salida de 'postconf -d')
La ubicación predeterminada de los archivos de configuración main.cf y master.cf de Postfix.
data_directory (ver la salida de 'postconf -d')
El directorio con archivos de datos escribibles por Postfix (por ejemplo: cachés, números pseudoaleatorios).
daemon_timeout (18000s)
Cuánto tiempo puede tardar un proceso demonio de Postfix en manejar una solicitud antes de que sea terminado por un temporizador de vigilancia incorporado.
ipc_timeout (3600s)
El límite de tiempo para enviar o recibir información a través de un canal de comunicación interno.
max_idle (100s)
La cantidad máxima de tiempo que un proceso demonio de Postfix inactivo espera una conexión entrante antes de terminar voluntariamente.
max_use (100)
El número máximo de conexiones entrantes que un proceso demonio de Postfix atenderá antes de terminar voluntariamente.
process_id (ver 'postconf -d')
Si el demonio Postfix debe registrar su ID de proceso en la salida estándar o en un archivo de registro especificado por el parámetro process_log_file.
proxy_read_maps (ver 'postconf -d')
Las tablas de búsqueda que un proceso Postfix puede leer a través de un servidor de mapa proxy. El valor predeterminado es el archivo de base de datos de la tabla de nombres de host del sistema, los archivos de alias y las tablas de nombres de usuario del sistema.
proxy_write_maps (ver 'postconf -d')
Las tablas de búsqueda que un proceso Postfix puede escribir a través de un servidor de mapa proxy.
syslog_facility (mail)
La facilidad de syslog para el registro de mensajes del sistema.
syslog_name (see 'postconf -d' output)
El nombre para identificar un demonio Postfix en los mensajes de registro.

El soporte para la solicitud delete se introdujo en Postfix 2.5.

El soporte para la solicitud sequence se introdujo en Postfix 2.9.
