NOMBRE

provider-rand - La biblioteca de generación de números aleatorios <-> funciones de proveedor

SINOPSIS

#include <openssl/core_dispatch.h>
#include <openssl/core_names.h>
/*
 * Ninguna de estas son funciones reales, pero se muestran así para
 * las firmas de funciones que se ofrecen como punteros de función en
 * matrices OSSL_DISPATCH.

DESCRIPCIÓN

Esta documentación está dirigida principalmente a los autores de proveedores. Ver provider(7) para más información.

La operación RAND permite a los proveedores implementar algoritmos de generación de números aleatorios y fuentes de números aleatorios y hacerlos disponibles para las aplicaciones a través de la función de API EVP_RAND(3).

Funciones de gestión de contexto

OSSL_FUNC_rand_newctx() debe crear y devolver un puntero a una estructura del lado del proveedor para mantener información de contexto durante una operación rand. Un puntero a este contexto se devolverá en una serie de otras llamadas a funciones de operación rand. El parámetro provctx es el contexto del proveedor generado durante la inicialización del proveedor (ver provider(7)). El parámetro parent especifica otra instancia rand que se utilizará para fines de semilla. Si es NULL y la instancia específica lo soporta, el sistema operativo se utilizará para la siembra. El parámetro parent_calls apunta a la tabla de despacho para parent. Por lo tanto, el padre no tiene por qué ser del mismo proveedor que la nueva instancia.

A OSSL_FUNC_rand_freectx() se le pasa un puntero al contexto rand del lado del proveedor en el parámetro mctx. Si recibe NULL como valor ctx, no debe hacer nada más que retornar. Esta función debe liberar todos los recursos asociados con ese contexto.

Funciones del generador de números aleatorios: NIST

Estas funciones corresponden a las definidas en NIST SP 800-90A y SP 800-90C.

OSSL_FUNC_rand_instantiate() se utiliza para instanciar el DRBG ctx con una strength de seguridad solicitada. Además, se puede solicitar prediction_resistance. Opcionalmente, se puede proporcionar una entrada adicional addin de longitud addin_len bytes. Los parámetros especificados en params configuran el DRBG y estos deben procesarse antes de la instanciación.

OSSL_FUNC_rand_uninstantiate() se utiliza para desinstanciar el DRBG ctx. Después de ser desinstanciado, un DRBG no puede producir salida hasta que se instancie de nuevo.

OSSL_FUNC_rand_generate() se utiliza para generar bytes aleatorios del DRBG ctx. Generará outlen bytes colocándolos en el búfer apuntado por out. Los bytes generados cumplirán la strength de seguridad especificada y, si prediction_resistance es verdadero, los bytes se producirán después de volver a sembrarlos desde una fuente de entropía en vivo. Opcionalmente, se puede proporcionar una entrada adicional addin de longitud addin_len bytes.

Funciones del generador de números aleatorios: Adicionales

OSSL_FUNC_rand_nonce() se utiliza para generar un nonce de la strength dada con una longitud de min_noncelen a max_noncelen. Si el búfer de salida out es NULL, se debe devolver la longitud del nonce.

OSSL_FUNC_rand_get_seed() es utilizada por los generadores deterministas para obtener su material de siembra de sus padres. Los bytes de la semilla cumplirán el nivel de seguridad especificado de entropy bits y habrá entre min_len y max_len bytes en total, inclusive. Si prediction_resistance es verdadero, los bytes se producirán a partir de una fuente de entropía en vivo. Opcionalmente, se puede proporcionar una entrada adicional addin de longitud addin_len bytes. Se devuelve un puntero al material de la semilla en *buffer y este debe liberarse mediante una llamada posterior a OSSL_FUNC_rand_clear_seed().

OSSL_FUNC_rand_clear_seed() libera un búfer de semilla buffer de longitud b_len bytes que fue asignado previamente por OSSL_FUNC_rand_get_seed().

OSSL_FUNC_rand_verify_zeroization() se utiliza para determinar si el estado interno del DRBG es cero. Esta capacidad es exigida por NIST como parte de las autocomprobaciones, es poco probable que sea útil en otras circunstancias.

Bloqueo de contexto

Cuando los DRBG son utilizados por múltiples hilos, debe haber un bloqueo empleado para asegurar su correcto funcionamiento. Dado que el bloqueo introduce una sobrecarga, está deshabilitado por defecto.

OSSL_FUNC_rand_enable_locking() permite activar el bloqueo para un DRBG y todos sus DRBG padres. A partir de esta llamada, el DRBG puede utilizarse de forma segura en hilos.

OSSL_FUNC_rand_lock() se utiliza para bloquear un DRBG. Una vez bloqueado, se garantiza acceso exclusivo.

OSSL_FUNC_rand_unlock() se utiliza para desbloquear un DRBG.

Parámetros Rand

Ver OSSL_PARAM(3) para más detalles sobre la estructura de parámetros utilizada por estas funciones.

OSSL_FUNC_rand_get_params() obtiene detalles de los valores de los parámetros asociados con el algoritmo del proveedor y los almacena en params.

OSSL_FUNC_rand_set_ctx_params() establece los parámetros rand asociados con el contexto rand del lado del proveedor dado ctx a params. Cualquier configuración de parámetro es adicional a la que se estableció previamente. Pasar NULL para params debería devolver true.

OSSL_FUNC_rand_get_ctx_params() obtiene detalles de los valores de los parámetros actualmente establecidos asociados con el contexto rand del lado del proveedor dado ctx y los almacena en params. Pasar NULL para params debería devolver true.

OSSL_FUNC_rand_gettable_params(), OSSL_FUNC_rand_gettable_ctx_params(), y OSSL_FUNC_rand_settable_ctx_params() devuelven matrices constantes de OSSL_PARAM(3) como descriptores de los parámetros que OSSL_FUNC_rand_get_params(), OSSL_FUNC_rand_get_ctx_params(), y OSSL_FUNC_rand_set_ctx_params() pueden manejar, respectivamente. _settable_ctx_params() devolverá los parámetros asociados con el contexto del lado del proveedor ctx en su estado actual si no es NULL. De lo contrario, devolverán los parámetros asociados con el algoritmo del lado del proveedor provctx.

Los parámetros actualmente reconocidos por los generadores de números aleatorios integrados son los siguientes. No todos los parámetros son relevantes para, o son entendidos por, todos los generadores de números aleatorios:

"state" (OSSL_RAND_PARAM_STATE) <entero>
Devuelve el estado del generador de números aleatorios.
"strength" (OSSL_RAND_PARAM_STRENGTH) <entero sin signo>
Devuelve la fuerza en bits del generador de números aleatorios.
"fips-indicator" (OSSL_RAND_PARAM_FIPS_APPROVED_INDICATOR) <entero>
Un getter que devuelve 1 si la operación está aprobada por FIPS, o 0 en caso contrario. Esta opción es utilizada por el proveedor FIPS de OpenSSL y no es compatible con todas las fuentes EVP_RAND.

Para los generadores de números aleatorios que también son generadores de bits aleatorios deterministas (DRBG), se reconocen estos parámetros adicionales. No todos los parámetros son relevantes para, o son entendidos por, todos los DRBG:

"reseed_requests" (OSSL_DRBG_PARAM_RESEED_REQUESTS) <entero sin signo>
Lee o establece el número de solicitudes de generación antes de volver a sembrar el contexto RAND asociado.
"reseed_time_interval" (OSSL_DRBG_PARAM_RESEED_TIME_INTERVAL) <entero>
Lee o establece el número de segundos transcurridos antes de volver a sembrar el contexto RAND asociado.
"max_request" (OSSL_DRBG_PARAM_RESEED_REQUESTS) <entero sin signo>
Especifica el número máximo de bytes que se pueden generar en una sola llamada a OSSL_FUNC_rand_generate.
"min_entropylen" (OSSL_DRBG_PARAM_MIN_ENTROPYLEN) <entero sin signo>
"max_entropylen" (OSSL_DRBG_PARAM_MAX_ENTROPYLEN) <entero sin signo>
Especifica el número mínimo y máximo de bytes de material aleatorio que se pueden utilizar para sembrar el DRBG.
"min_noncelen" (OSSL_DRBG_PARAM_MIN_NONCELEN) <entero sin signo>
"max_noncelen" (OSSL_DRBG_PARAM_MAX_NONCELEN) <entero sin signo>
Especifica el número mínimo y máximo de bytes de nonce que se pueden utilizar para instanciar el DRBG.
"max_perslen" (OSSL_DRBG_PARAM_MAX_PERSLEN) <entero sin signo>
"max_adinlen" (OSSL_DRBG_PARAM_MAX_ADINLEN) <entero sin signo>
Especifica el número mínimo y máximo de bytes de cadena de personalización que se pueden utilizar con el DRBG.
"reseed_counter" (OSSL_DRBG_PARAM_RESEED_COUNTER) <entero sin signo>
Especifica el número de veces que el DRBG ha sido sembrado o vuelto a sembrar.
"digest" (OSSL_DRBG_PARAM_DIGEST) <cadena UTF8>
"cipher" (OSSL_DRBG_PARAM_CIPHER) <cadena UTF8>
"mac" (OSSL_DRBG_PARAM_MAC) <cadena UTF8>
Establece el nombre del cifrado, resumen o MAC subyacente a utilizar. Debe nombrar un algoritmo adecuado para el DRBG que se está utilizando.
"properties" (OSSL_DRBG_PARAM_PROPERTIES) <cadena UTF8>
Establece las propiedades que se consultarán al intentar obtener un algoritmo subyacente. Esto debe proporcionarse junto con el parámetro de nombre del algoritmo para ser considerado válido.

El proveedor FIPS de OpenSSL también soporta los siguientes parámetros:

"fips-indicator" (OSSL_DRBG_PARAM_FIPS_APPROVED_INDICATOR) <entero>
Un getter que devuelve 1 si la operación está aprobada por FIPS, o 0 en caso contrario. Esto puede ser utilizado después de llamar a OSSL_FUNC_rand_generate(). Puede devolver 0 si "digest-check" está establecido a 0.
"digest-check" (OSSL_DRBG_PARAM_FIPS_DIGEST_CHECK) <entero>
Si es necesario, este parámetro debe establecerse antes de que se establezca el resumen. El valor predeterminado de 1 provoca un error al establecer el resumen si el resumen no está aprobado por FIPS (por ejemplo, resúmenes truncados). Establecer esto a 0 ignorará el error y establecerá el "fips-indicator" aprobado a 0. Esta opción rompe el cumplimiento de FIPS si hace que el "fips-indicator" aprobado devuelva 0.

VALORES DE RETORNO

OSSL_FUNC_rand_newctx() debería devolver el contexto aleatorio del lado del proveedor recién creado, o NULL en caso de fallo.

OSSL_FUNC_rand_gettable_params(), OSSL_FUNC_rand_gettable_ctx_params() y OSSL_FUNC_rand_settable_ctx_params() deberían devolver una matriz constante OSSL_PARAM(3), o NULL si no se ofrece ninguna.

OSSL_FUNC_rand_nonce() devuelve el tamaño del nonce generado, o 0 en caso de error.

OSSL_FUNC_rand_get_seed() devuelve el tamaño de la semilla generada, o 0 en caso de error.

Todas las funciones restantes deberían devolver 1 para éxito o 0 en caso de error.

NOTAS

El ciclo de vida de RAND se describe en life_cycle-rand(7). Los proveedores deben asegurarse de que las diversas transiciones listadas allí estén soportadas. En algún momento, la capa EVP comenzará a aplicar las transiciones listadas.
