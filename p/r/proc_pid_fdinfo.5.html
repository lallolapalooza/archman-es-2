proc_pid_fdinfo(5) Manual de formatos de archivo proc_pid_fdinfo(5)

NOMBRE

/proc/pid/fdinfo/ - información sobre descriptores de archivo

DESCRIPCIÓN

Este es un subdirectorio que contiene una entrada por cada archivo que el proceso tiene abierto, nombrado por su descriptor de archivo. Los archivos en este directorio solo son legibles por el propietario del proceso. El contenido de cada archivo puede leerse para obtener información sobre el descriptor de archivo correspondiente. El contenido depende del tipo de archivo al que se refiere el descriptor de archivo correspondiente.

Para archivos y directorios regulares, vemos algo como:


$ cat /proc/12015/fdinfo/4
pos:    1000
flags:  01002002
mnt_id: 21

Los campos son los siguientes:

pos
Este es un número decimal que muestra la posición del archivo.
flags
Este es un número octal que muestra el modo de acceso al archivo y las banderas de estado del archivo (ver open(2)). Si la bandera de descriptor de archivo de cierre al ejecutar está establecida, entonces flags también incluirá el valor O_CLOEXEC.
Antes de Linux 3.1, este campo mostraba incorrectamente la configuración de O_CLOEXEC en el momento en que se abrió el archivo, en lugar de la configuración actual de la bandera de cierre al ejecutar.
mnt_id
Este campo, presente desde Linux 3.15, es el ID del montaje que contiene este archivo. Ver la descripción de /proc/pid/mountinfo.

Para descriptores de archivo eventfd (ver eventfd(2)), vemos (desde Linux 3.8) los siguientes campos:


pos:	0
flags:	02
mnt_id:	10
eventfd-count:               40

eventfd-count es el valor actual del contador de eventfd, en hexadecimal.

Para descriptores de archivo epoll (ver epoll(7)), vemos (desde Linux 3.8) los siguientes campos:


pos:	0
flags:	02
mnt_id:	10
tfd:        9 events:       19 data: 74253d2500000009
tfd:        7 events:       19 data: 74253d2500000007

Cada una de las líneas que comienzan con tfd describe uno de los descriptores de archivo que se están monitoreando a través del descriptor de archivo epoll (ver epoll_ctl(2) para algunos detalles). El campo tfd es el número del descriptor de archivo. El campo events es una máscara hexadecimal de los eventos que se están monitoreando para este descriptor de archivo. El campo data es el valor de datos asociado con este descriptor de archivo.

Para descriptores de archivo signalfd (ver signalfd(2)), vemos (desde Linux 3.8) los siguientes campos:


pos:	0
flags:	02
mnt_id:	10
sigmask:	0000000000000006

sigmask es la máscara hexadecimal de señales que se aceptan a través de este descriptor de archivo signalfd. (En este ejemplo, los bits 2 y 3 están establecidos, correspondientes a las señales SIGINT y SIGQUIT; ver signal(7)).

Para descriptores de archivo inotify (ver inotify(7)), vemos (desde Linux 3.8) los siguientes campos:


pos:	0
flags:	00
mnt_id:	11
inotify wd:2 ino:7ef82a sdev:800001 mask:800afff ignored_mask:0 fhandle-bytes:8 fhandle-type:1 f_handle:2af87e00220ffd73
inotify wd:1 ino:192627 sdev:800001 mask:800afff ignored_mask:0 fhandle-bytes:8 fhandle-type:1 f_handle:27261900802dfd73

Cada una de las líneas que comienzan con "inotify" muestra información sobre un archivo o directorio que se está monitoreando. Los campos en esta línea son los siguientes:

wd
Un número de descriptor de vigilancia (en decimal).
ino
El número de inodo del archivo objetivo (en hexadecimal).
sdev
El ID del dispositivo donde reside el archivo objetivo (en hexadecimal).
mask
La máscara de eventos que se están monitoreando para el archivo objetivo (en hexadecimal).

Si el kernel fue compilado con soporte para exportfs, la ruta al archivo objetivo se expone como un manejador de archivo, a través de tres campos hexadecimales: fhandle-bytes, fhandle-type, y f_handle.

Para descriptores de archivo fanotify (ver fanotify(7)), vemos (desde Linux 3.8) los siguientes campos:


pos:	0
flags:	02
mnt_id:	11
fanotify flags:0 event-flags:88002
fanotify ino:19264f sdev:800001 mflags:0 mask:1 ignored_mask:0 fhandle-bytes:8 fhandle-type:1 f_handle:4f261900a82dfd73

La cuarta línea muestra información definida cuando se creó el grupo fanotify a través de fanotify_init(2):

flags
El argumento flags dado a fanotify_init(2) (expresado en hexadecimal).
event-flags
El argumento event_f_flags dado a fanotify_init(2) (expresado en hexadecimal).

Cada una de las líneas adicionales que se muestran en el archivo contiene información sobre una de las marcas en el grupo fanotify. La mayoría de estos campos son como para inotify, excepto:

mflags
Las banderas asociadas con la marca (expresadas en hexadecimal).
mask
La máscara de eventos para esta marca (expresada en hexadecimal).
ignored_mask
La máscara de eventos que se ignoran para esta marca (expresada en hexadecimal).

Para obtener detalles sobre estos campos, ver fanotify_mark(2).

Para descriptores de archivo timerfd (ver timerfd(2)), vemos (desde Linux 3.17) los siguientes campos:


pos:    0
flags:  02004002
mnt_id: 13
clockid: 0
ticks: 0
settime flags: 03
it_value: (7695568592, 640020877)
it_interval: (0, 0)
clockid
Este es el valor numérico del ID del reloj (correspondiente a una de las constantes CLOCK_* definidas en <time.h>) que se usa para marcar el progreso del temporizador (en este ejemplo, 0 es CLOCK_REALTIME).
ticks
Este es el número de expiraciones del temporizador que han ocurrido, (es decir, el valor que read(2) sobre él devolvería).
settime flags
Este campo lista las banderas con las que se armó por última vez el timerfd (ver timerfd_settime(2)), en octal (en este ejemplo, tanto TFD_TIMER_ABSTIME como TFD_TIMER_CANCEL_ON_SET están establecidas).
it_value
Este campo contiene la cantidad de tiempo hasta que el temporizador expire próximamente, expresado en segundos y nanosegundos. Siempre se expresa como un valor relativo, independientemente de si el temporizador se creó usando la bandera TFD_TIMER_ABSTIME.
it_interval
Este campo contiene el intervalo del temporizador, en segundos y nanosegundos. (Los campos it_value e it_interval contienen los valores que timerfd_gettime(2) sobre este descriptor de archivo devolvería).
