NOMBRE

/proc/pid/oom_score_adj - ajuste de la puntuación del asesino OOM

DESCRIPCIÓN

/proc/pid/oom_score_adj (desde Linux 2.6.36)
Este archivo puede usarse para ajustar la heurística de "maldad" utilizada para seleccionar qué proceso se mata en condiciones de falta de memoria (out-of-memory).
La heurística de "maldad" asigna un valor a cada tarea candidata que va de 0 (nunca matar) a 1000 (siempre matar) para determinar qué proceso es el objetivo. Las unidades son aproximadamente una proporción a lo largo del rango de memoria permitido que el proceso puede asignar, basándose en una estimación de su uso actual de memoria y swap. Por ejemplo, si una tarea está utilizando toda la memoria permitida, su puntuación de "maldad" será 1000. Si está utilizando la mitad de su memoria permitida, su puntuación será 500.
Hay un factor adicional incluido en la puntuación de "maldad": a los procesos root se les da un 3% de memoria extra sobre otras tareas.
La cantidad de memoria "permitida" depende del contexto en el que se llamó al asesino OOM. Si se debe a que se agotó la memoria asignada al cpuset de la tarea que asigna, la memoria permitida representa el conjunto de mems asignados a ese cpuset (ver cpuset(7)). Si se debe a que se agotaron los nodos de un mempolicy, la memoria permitida representa el conjunto de nodos del mempolicy. Si se debe a que se alcanzó un límite de memoria (o límite de swap), la memoria permitida es ese límite configurado. Finalmente, si se debe a que todo el sistema se quedó sin memoria, la memoria permitida representa todos los recursos asignables.
El valor de oom_score_adj se suma a la puntuación de "maldad" antes de usarla para determinar qué tarea matar. Los valores aceptables van desde -1000 (OOM_SCORE_ADJ_MIN) hasta +1000 (OOM_SCORE_ADJ_MAX). Esto permite al espacio de usuario controlar la preferencia para matar por OOM, desde preferir siempre una tarea determinada hasta deshabilitar por completo que sea eliminada por OOM. El valor más bajo posible, -1000, es equivalente a deshabilitar la eliminación por OOM por completo para esa tarea, ya que siempre reportará una puntuación de "maldad" de 0.
En consecuencia, es muy simple para el espacio de usuario definir la cantidad de memoria a considerar para cada tarea. Establecer un valor de oom_score_adj de +500, por ejemplo, es aproximadamente equivalente a permitir que el resto de las tareas que comparten el mismo sistema, cpuset, mempolicy o recursos del controlador de memoria utilicen al menos un 50% más de memoria. Un valor de -500, por otro lado, sería aproximadamente equivalente a descontar el 50% de la memoria permitida de la tarea para que no se tenga en cuenta en su puntuación.
Para compatibilidad con versiones anteriores del kernel, /proc/pid/oom_adj todavía se puede usar para ajustar la puntuación de "maldad". Su valor se escala linealmente con oom_score_adj.
Escribir en /proc/pid/oom_score_adj o /proc/pid/oom_adj cambiará el otro con su valor escalado.
El programa choom(1) proporciona una interfaz de línea de comandos para ajustar el valor de oom_score_adj de un proceso en ejecución o de un comando recién ejecutado.

HISTORIA

/proc/pid/oom_adj (desde Linux 2.6.11)
Este archivo puede usarse para ajustar la puntuación utilizada para seleccionar qué proceso debe ser eliminado en una situación de falta de memoria (OOM). El kernel usa este valor para una operación de desplazamiento de bits del valor oom_score del proceso: los valores válidos están en el rango -16 a +15, más el valor especial -17, que deshabilita la eliminación por OOM por completo para este proceso. Una puntuación positiva aumenta la probabilidad de que este proceso sea eliminado por el asesino OOM; una puntuación negativa disminuye la probabilidad.
El valor predeterminado para este archivo es 0; un nuevo proceso hereda la configuración oom_adj de su padre. Un proceso debe tener privilegios (CAP_SYS_RESOURCE) para actualizar este archivo, aunque un proceso siempre puede aumentar su propia configuración de oom_adj (desde Linux 2.6.20).
Desde Linux 2.6.36, el uso de este archivo está obsoleto en favor de /proc/pid/oom_score_adj, y finalmente se eliminó en Linux 3.7.
