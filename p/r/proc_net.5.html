proc_pid_net(5) Manual de formatos de archivo proc_pid_net(5)

NOMBRE

/proc/pid/net/, /proc/net/ - información de la capa de red

DESCRIPCIÓN

/proc/pid/net/ (desde Linux 2.6.25)
Ver la descripción de /proc/net.
/proc/net/
Este directorio contiene varios archivos y subdirectorios que contienen información sobre la capa de red. Los archivos contienen estructuras ASCII y, por lo tanto, son legibles con cat(1). Sin embargo, el conjunto estándar de utilidades netstat(8) proporciona un acceso mucho más limpio a estos archivos.
Con la llegada de los namespaces de red, la información relativa a la pila de red se virtualiza (ver network_namespaces(7)). Por lo tanto, desde Linux 2.6.25, /proc/net es un enlace simbólico al directorio /proc/self/net, que contiene los mismos archivos y directorios que se enumeran a continuación. Sin embargo, estos archivos y directorios ahora exponen información para el namespace de red del cual el proceso es miembro.
/proc/net/arp
Contiene un volcado legible en ASCII de la tabla ARP del kernel utilizada para las resoluciones de direcciones. Mostrará tanto las entradas ARP aprendidas dinámicamente como las preprogramadas. El formato es:

Dirección IP   Tipo HW     Flags     Dirección HW          Máscara   Dispositivo
192.168.0.50   0x1       0x2       00:50:BF:25:68:F3   *      eth0
192.168.0.250  0x1       0xc       00:00:00:00:00:00   *      eth0

Aquí "Dirección IP" es la dirección IPv4 de la máquina y el "Tipo HW" es el tipo de hardware de la dirección según RFC 826. Las banderas son las banderas internas de la estructura ARP (como se definen en /usr/include/linux/if_arp.h) y la "Dirección HW" es el mapeo de capa de enlace de datos para esa dirección IP si se conoce.
/proc/net/dev
El pseudo-archivo dev contiene información de estado de los dispositivos de red. Proporciona el número de paquetes recibidos y enviados, el número de errores y colisiones, y otras estadísticas básicas. Estos son utilizados por el programa ifconfig(8) para informar el estado del dispositivo. El formato es:
Interfaz-|   Recepción                                            |  Transmisión
          |bytes    paquetes err. descart. fifo trama comprimido multicast|bytes    paquetes err. descart. fifo colisiones portador comprimido
    lo: 2776770   11307    0    0    0     0          0         0  2776770   11307    0    0    0     0       0          0
  eth0: 1215645    2751    0    0    0     0          0         0  1782404    4324    0    0    0   427       0          0
  ppp0: 1622270    5552    1    0    0     0          0         0   354130    5669    0    0    0     0       0          0
  tap0:    7714      81    0    0    0     0          0         0     7714      81    0    0    0     0       0          0

/proc/net/igmp
Protocolo de Gestión de Grupos de Internet. Definido en /usr/src/linux/net/core/igmp.c.
/proc/net/rarp
Este archivo utiliza el mismo formato que el archivo arp y contiene la base de datos de mapeo inverso actual utilizada para proporcionar servicios de búsqueda inversa de direcciones rarp(8). Si RARP no está configurado en el kernel, este archivo no estará presente.
/proc/net/raw
Contiene un volcado de la tabla de sockets RAW. Gran parte de la información no es útil aparte de la depuración. El valor "sl" es la ranura hash del kernel para el socket, la "dirección_local" es la dirección local y el par de números de protocolo. "St" es el estado interno del socket. "tx_queue" y "rx_queue" son la cola de datos saliente y entrante en términos de uso de memoria del kernel. Los campos "tr", "tm->when", y "rexmits" no son utilizados por RAW. El campo "uid" contiene el UID efectivo del creador del socket.
/proc/net/snmp
Este archivo contiene los datos ASCII necesarios para las bases de información de gestión de IP, ICMP, TCP y UDP para un agente SNMP.
/proc/net/tcp
Contiene un volcado de la tabla de sockets TCP. Gran parte de la información no es útil aparte de la depuración. El valor "sl" es la ranura hash del kernel para el socket, la "dirección_local" es la dirección local y el par de puertos. La "dirección_remota" es la dirección remota y el par de puertos (si está conectado). "St" es el estado interno del socket. "tx_queue" y "rx_queue" son la cola de datos saliente y entrante en términos de uso de memoria del kernel. Los campos "tr", "tm->when", y "rexmits" contienen información interna del estado del socket del kernel y solo son útiles para depuración. El campo "uid" contiene el UID efectivo del creador del socket.
/proc/net/udp
Contiene un volcado de la tabla de sockets UDP. Gran parte de la información no es útil aparte de la depuración. El valor "sl" es la ranura hash del kernel para el socket, la "dirección_local" es la dirección local y el par de puertos. La "dirección_remota" es la dirección remota y el par de puertos (si está conectado). "St" es el estado interno del socket. "tx_queue" y "rx_queue" son la cola de datos saliente y entrante en términos de uso de memoria del kernel. Los campos "tr", "tm->when", y "rexmits" no son utilizados por UDP. El campo "uid" contiene el UID efectivo del creador del socket. El formato es:
sl  dirección_local  dirección_remota   st tx_queue rx_queue tr rexmits  tm->when uid
 1: 01642C89:0201 0C642C89:03FF 01 00000000:00000001 01:000071BA 00000000 0
 1: 00000000:0801 00000000:0000 0A 00000000:00000000 00:00000000 6F000100 0
 1: 00000000:0201 00000000:0000 0A 00000000:00000000 00:00000000 00000000 0
/proc/net/unix
Enumera los sockets de dominio UNIX presentes en el sistema y su estado. El formato es:
Num RefCount Protocol Flags    Type St Inode Path
 0: 00000002 00000000 00000000 0001 03    42
 1: 00000001 00000000 00010000 0001 01  1948 /dev/printer
Los campos son los siguientes:
Num:
el número de ranura de la tabla del kernel.
RefCount:
el número de usuarios del socket.
Protocol:
actualmente siempre 0.
Flags:
las banderas internas del kernel que contienen el estado del socket.
Type:
el tipo de socket. Para sockets SOCK_STREAM, es 0001; para sockets SOCK_DGRAM, es 0002; y para sockets SOCK_SEQPACKET, es 0005.
St:
el estado interno del socket.
Inode:
el número de inodo del socket.
Path:
el nombre de ruta enlazado (si existe) del socket. Los sockets en el espacio de nombres abstracto se incluyen en la lista y se muestran con un Path que comienza con el carácter '@'.
/proc/net/netfilter/nfnetlink_queue
Este archivo contiene información sobre la cola de espacio de usuario de netfilter, si se utiliza. Cada línea representa una cola. Las colas a las que no se ha suscrito el espacio de usuario no se muestran.

   1   4207     0  2 65535     0     0        0  1
  (1)   (2)    (3)(4)  (5)    (6)   (7)      (8)

Los campos en cada línea son:
(1)
La ID de la cola. Esto coincide con lo especificado en las opciones --queue-num o --queue-balance del objetivo NFQUEUE de iptables(8). Ver iptables-extensions(8) para más información.
(2)
Th

DESCRIPTION

The contents of the /proc/net/netfilter/nf_queue file describe the state of the packet queuing subsystem.

(1)
The queue ID. This is an arbitrary number identifying the queue. A value of 0 indicates the default queue (i.e., no specific queue has been subscribed to).
(2)
The netlink port ID subscribed to the queue.
(3)
The number of packets currently queued and waiting to be processed by the application.
(4)
The copy mode of the queue. It is either 1 (metadata only) or 2 (also copy payload data to user space).
(5)
Copy range; that is, how many bytes of packet payload should be copied to user space at most.
(6)
queue dropped. Number of packets that had to be dropped by the kernel because too many packets are already waiting for user space to send back the mandatory accept/drop verdicts.
(7)
queue user dropped. Number of packets that were dropped within the netlink subsystem. Such drops usually happen when the corresponding socket buffer is full; that is, user space is not able to read messages fast enough.
(8)
sequence number. Every queued packet is associated with a (32-bit) monotonically increasing sequence number. This shows the ID of the most recent packet queued.
The last number exists only for compatibility reasons and is always 1.
