proc_pid_maps(5) Manual de formatos de archivo proc_pid_maps(5)

NOMBRE

proc_pid_maps(5) — regiones de memoria mapeadas

DESCRIPCIÓN

/proc/pid/maps
Un archivo que contiene las regiones de memoria actualmente mapeadas y sus permisos de acceso. Consulte mmap(2) para obtener más información sobre los mapas de memoria.
El permiso para acceder a este archivo está regido por una comprobación del modo de acceso ptrace PTRACE_MODE_READ_FSCREDS; consulte ptrace(2).
El formato del archivo es:

dirección           perm offset  dev   inodo       ruta_archivo
00400000-00452000 r-xp 00000000 08:02 173521      /usr/bin/dbus-daemon
00651000-00652000 r--p 00051000 08:02 173521      /usr/bin/dbus-daemon
00652000-00655000 rw-p 00052000 08:02 173521      /usr/bin/dbus-daemon
00e03000-00e24000 rw-p 00000000 00:00 0           [heap]
00e24000-011f7000 rw-p 00000000 00:00 0           [heap]
...
35b1800000-35b1820000 r-xp 00000000 08:02 135522  /usr/lib64/ld-2.15.so
35b1a1f000-35b1a20000 r--p 0001f000 08:02 135522  /usr/lib64/ld-2.15.so
35b1a20000-35b1a21000 rw-p 00020000 08:02 135522  /usr/lib64/ld-2.15.so
35b1a21000-35b1a22000 rw-p 00000000 00:00 0
35b1c00000-35b1dac000 r-xp 00000000 08:02 135870  /usr/lib64/libc-2.15.so
35b1dac000-35b1fac000 ---p 001ac000 08:02 135870  /usr/lib64/libc-2.15.so
35b1fac000-35b1fb0000 r--p 001ac000 08:02 135870  /usr/lib64/libc-2.15.so
35b1fb0000-35b1fb2000 rw-p 001b0000 08:02 135870  /usr/lib64/libc-2.15.so
...
f2c6ff8c000-7f2c7078c000 rw-p 00000000 00:00 0    [stack:986]
...
7fffb2c0d000-7fffb2c2e000 rw-p 00000000 00:00 0   [stack]
7fffb2d48000-7fffb2d49000 r-xp 00000000 00:00 0   [vdso]

El campo dirección es el espacio de direcciones en el proceso que ocupa el mapa. El campo perm es un conjunto de permisos:

r = leer
w = escribir
x = ejecutar
s = compartido
p = privado (copia en escritura)

El campo offset es el desplazamiento dentro del archivo/lo que sea; dev es el dispositivo (mayor:menor); inodo es el inodo en ese dispositivo. 0 indica que no hay ningún inodo asociado con la región de memoria, como sería el caso de BSS (datos no inicializados).
El campo ruta_archivo suele ser el archivo que respalda el mapa. Para archivos ELF, puede coordinar fácilmente con el campo offset consultando el campo Offset en las cabeceras del programa ELF (readelf -l).
Hay pseudo-rutas adicionales útiles:
[stack]
La pila del proceso inicial (también conocida como la pila del hilo principal).
[stack:tid] (desde Linux 3.4 hasta Linux 4.4)
La pila de un hilo (donde tid es un ID de hilo). Corresponde a la ruta /proc/pid/task/tid/. Este campo se eliminó en Linux 4.5, ya que proporcionar esta información para un proceso con un gran número de hilos es costoso.
[vdso]
El objeto compartido virtual enlazado dinámicamente. Consulte vdso(7).
[heap]
La pila del proceso.
[anon:nombre] (desde Linux 5.17)
Un mapa anónimo privado con nombre. Establecido con prctl(2) PR_SET_VMA_ANON_NAME.
[anon_shmem:nombre] (desde Linux 6.2)
Un mapa anónimo compartido con nombre. Establecido con prctl(2) PR_SET_VMA_ANON_NAME.
Si el campo ruta_archivo está en blanco, es un mapa anónimo obtenido a través de mmap(2). No hay una forma fácil de coordinar esto de vuelta con el código fuente de un proceso, más allá de ejecutarlo a través de gdb(1), strace(1) o similares.
ruta_archivo se muestra sin escapar, excepto los caracteres de nueva línea, que se reemplazan con una secuencia de escape octal. Como resultado, no es posible determinar si la ruta original contenía un carácter de nueva línea o la secuencia literal de caracteres \012.
Si el mapa está respaldado por un archivo y este ha sido eliminado, se añade la cadena " (deleted)" a la ruta del archivo. Tenga en cuenta que esto también es ambiguo.
En Linux 2.0, no hay un campo que proporcione la ruta del archivo.
