DESCRIPCIÓN

Esta documentación está dirigida principalmente a los autores de proveedores. Consulte provider(7) para obtener más información.

La operación CIPHER permite a los proveedores implementar algoritmos de cifrado y hacerlos disponibles a las aplicaciones a través de las funciones de la API EVP_EncryptInit_ex(3), EVP_EncryptUpdate(3) y EVP_EncryptFinal(3) (así como sus equivalentes de descifrado y otras funciones relacionadas).

Todas las "funciones" mencionadas aquí se pasan como punteros de función entre libcrypto y el proveedor en arrays OSSL_DISPATCH(3) a través de arrays OSSL_ALGORITHM(3) que son devueltos por la función provider_query_operation() del proveedor (ver "Funciones del Proveedor" en provider-base(7)).

Todas estas "funciones" tienen una definición de tipo de función correspondiente llamada OSSL_FUNC_{name}_fn y una función auxiliar para obtener el puntero de función de un elemento de OSSL_DISPATCH(3) llamada OSSL_FUNC_{name}. Por ejemplo, la "función" OSSL_FUNC_cipher_newctx() tiene estos:

typedef void *(OSSL_FUNC_cipher_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_cipher_newctx_fn
    OSSL_FUNC_cipher_newctx(const OSSL_DISPATCH *opf);

Los arrays de OSSL_DISPATCH(3) se indexan mediante números que se proporcionan como macros en openssl-core_dispatch.h(7), como sigue:

OSSL_FUNC_cipher_decrypt_init              OSSL_FUNC_CIPHER_DECRYPT_INIT
OSSL_FUNC_cipher_encrypt_skey_init         OSSL_FUNC_CIPHER_ENCRYPT_SKEY_INIT
OSSL_FUNC_cipher_decrypt_skey_init         OSSL_FUNC_CIPHER_DECRYPT_SKEY_INIT
OSSL_FUNC_cipher_update                    OSSL_FUNC_CIPHER_UPDATE
OSSL_FUNC_cipher_final                     OSSL_FUNC_CIPHER_FINAL
OSSL_FUNC_cipher_cipher                    OSSL_FUNC_CIPHER_CIPHER
OSSL_FUNC_cipher_pipeline_encrypt_init     OSSL_FUNC_CIPHER_PIPELINE_ENCRYPT_INIT
OSSL_FUNC_cipher_pipeline_decrypt_init     OSSL_FUNC_CIPHER_PIPELINE_DECRYPT_INIT
OSSL_FUNC_cipher_pipeline_update           OSSL_FUNC_CIPHER_PIPELINE_UPDATE

Una implementación de algoritmo de cifrado puede no implementar todas estas funciones. Para ser un conjunto consistente de funciones, debe haber al menos un conjunto completo de funciones de "cifrado", o un conjunto completo de funciones de "descifrado", o una única función de "cifrado". De manera similar, puede haber un conjunto completo de funciones de "cifrado" de tubería, y/o un conjunto completo de funciones de "descifrado" de tubería. En todos los casos, las funciones OSSL_FUNC_cipher_get_params y ambas funciones OSSL_FUNC_cipher_newctx y OSSL_FUNC_cipher_freectx deben estar presentes. Todas las demás funciones son opcionales.

Funciones de Gestión de Contexto

OSSL_FUNC_cipher_newctx() debe crear y devolver un puntero a una estructura del lado del proveedor para mantener la información de contexto durante una operación de cifrado. Se devolverá un puntero a este contexto en una serie de otras llamadas a funciones de operación de cifrado. El parámetro provctx es el contexto del proveedor generado durante la inicialización del proveedor (ver provider(7)).

A OSSL_FUNC_cipher_freectx() se le pasa un puntero al contexto de cifrado del lado del proveedor en el parámetro cctx. Esta función debe liberar cualquier recurso asociado con ese contexto.

OSSL_FUNC_cipher_dupctx() debe duplicar el contexto de cifrado del lado del proveedor en el parámetro cctx y devolver la copia duplicada.

Funciones de Cifrado/Descifrado

OSSL_FUNC_cipher_encrypt_init() inicializa una operación de cifrado para cifrado dado un contexto de cifrado del lado del proveedor recién creado en el parámetro cctx. La clave que se utilizará se proporciona en key, que tiene una longitud de keylen bytes. El IV que se utilizará se proporciona en iv, que tiene una longitud de ivlen bytes. Los params, si no son NULL, deben establecerse en el contexto de manera similar a como se usa OSSL_FUNC_cipher_set_ctx_params().

OSSL_FUNC_cipher_decrypt_init() es lo mismo que OSSL_FUNC_cipher_encrypt_init(), excepto que inicializa el contexto para una operación de descifrado.

DESCRIPCIÓN

La interfaz del proveedor CIPHER es la interfaz de bajo nivel utilizada por los proveedores para implementar operaciones de cifrado y descifrado. Define las funciones que un proveedor debe exportar para que OpenSSL las utilice.

Funciones de la interfaz

OSSL_FUNC_cipher_newctx() es llamada para crear un nuevo contexto de proveedor para operaciones de cifrado. El parámetro provctx es el contexto del proveedor general.

OSSL_FUNC_cipher_freectx() libera el contexto del proveedor cctx.

OSSL_FUNC_cipher_dupctx() duplica el contexto del proveedor cctx para crear un nuevo contexto de proveedor que sea una copia del original.

OSSL_FUNC_cipher_encrypt_init() y OSSL_FUNC_cipher_decrypt_init() inicializan un contexto de proveedor para operaciones de cifrado o descifrado, respectivamente. El parámetro cctx es el contexto del proveedor y debe haber sido creado previamente por OSSL_FUNC_cipher_newctx(). El parámetro key es el puntero a la clave, keylen es la longitud de la clave en bytes. El parámetro iv es el vector de inicialización (IV) con longitud ivlen. El parámetro props contiene las propiedades a utilizar. Si OSSL_FUNC_cipher_encrypt_init() es llamado con un parámetro engine NULL, entonces se debe utilizar el cifrado sin padding. Si OSSL_FUNC_cipher_encrypt_init() se llama con un parámetro engine NULL, entonces el cifrado debe ser realizado sin padding.

OSSL_FUNC_cipher_encrypt_skey_init() y OSSL_FUNC_cipher_decrypt_skey_init() son variantes de OSSL_FUNC_cipher_encrypt_init() y OSSL_FUNC_cipher_decrypt_init() para trabajar con objetos opacos que contienen identificadores de clave específicos del proveedor en lugar de bytes brutos.

OSSL_FUNC_cipher_update() es llamada para suministrar datos a ser cifrados/descifrados como parte de una operación de cifrado previamente inicializada. El parámetro cctx contiene un puntero a un contexto del lado del proveedor previamente inicializado. OSSL_FUNC_cipher_update() debe cifrar/descifrar inl bytes de datos en la ubicación apuntada por in. Los datos cifrados deben almacenarse en out y la cantidad de datos escritos en *outl no debe exceder outsize bytes. OSSL_FUNC_cipher_update() puede ser llamada múltiples veces para una única operación de cifrado. Es responsabilidad de la implementación del cifrado manejar longitudes de entrada que no sean múltiplos de la longitud del bloque. En tales casos, una implementación de cifrado normalmente almacenará en caché bloques parciales de datos de entrada hasta que se obtenga un bloque completo. Los punteros out e in pueden apuntar a la misma ubicación, en cuyo caso el cifrado debe hacerse en el lugar. Si out e in apuntan a ubicaciones diferentes, los requisitos de EVP_EncryptUpdate(3) y EVP_DecryptUpdate(3) garantizan que los dos buffers son disjuntos. De manera similar, los requisitos de EVP_EncryptUpdate(3) y EVP_DecryptUpdate(3) aseguran que el buffer apuntado por out contiene suficiente espacio para la operación que se está realizando.

OSSL_FUNC_cipher_final() completa un cifrado o descifrado iniciado a través de llamadas previas a OSSL_FUNC_cipher_encrypt_init() o OSSL_FUNC_cipher_decrypt_init() y OSSL_FUNC_cipher_update(). El parámetro cctx contiene un puntero al contexto del lado del proveedor. Cualquier salida final de cifrado/descifrado debe escribirse en out y la cantidad de datos escritos en *outl no debe exceder outsize bytes. Las mismas expectativas se aplican a outsize según lo documentado para EVP_EncryptFinal(3) y EVP_DecryptFinal(3).

OSSL_FUNC_cipher_cipher() realiza el cifrado/descifrado utilizando el contexto de cifrado del lado del proveedor en el parámetro cctx, que debería haber sido previamente inicializado mediante una llamada a OSSL_FUNC_cipher_encrypt_init() o OSSL_FUNC_cipher_decrypt_init(). Esto debería llamar a la función subyacente de cifrado raw sin ningún padding. Esto se invocará en el proveedor como resultado de que la aplicación llame a EVP_Cipher(3). La aplicación es responsable de asegurar que la entrada sea un múltiplo de la longitud del bloque. Los datos a cifrar/descifrar estarán en in, y tendrán una longitud de inl bytes. La salida del cifrado/descifrado debe almacenarse en out y la cantidad de datos almacenados debe colocarse en *outl, que no debe ser superior a outsize bytes.

OSSL_FUNC_cipher_pipeline_encrypt_init(), OSSL_FUNC_cipher_pipeline_decrypt_init() OSSL_FUNC_cipher_pipeline_update(), y OSSL_FUNC_cipher_pipeline_final() son similares a las variantes no de pipeline, pero se utilizan cuando la aplicación está utilizando el pipeline de cifrado. El parámetro numpipes es el número de pipes en el pipeline. El parámetro iv es un array de buffers con IVs, cada uno con longitud ivlen bytes. Los parámetros in y out son arrays de punteros a buffers. Los parámetros inl y outl, outsize son arrays de size_t que representan la longitud de buffer correspondiente de forma similar a las variantes no de pipeline. Todos los arrays son de longitud numpipes. Consulte EVP_CipherPipelineEncryptInit(3) para más información.

Parámetros de cifrado

Consulte OSSL_PARAM(3) para obtener más detalles sobre la estructura de parámetros utilizada por estas funciones.

OSSL_FUNC_cipher_get_params() obtiene detalles de la implementación del algoritmo y los almacena en params.

OSSL_FUNC_cipher_set_ctx_params() establece los parámetros de operación del cifrado para el contexto de cifrado del lado del proveedor cctx a params. Cualquier configuración de parámetro es adicional a las que se establecieron previamente. Pasar NULL para params debería devolver verdadero.

OSSL_FUNC_cipher_get_ctx_params() obtiene detalles de la operación del cifrado del contexto de cifrado del lado del proveedor dado cctx y los almacena en params. Pasar NULL para params debería devolver verdadero.

OSSL_FUNC_cipher_gettable_params(), OSSL_FUNC_cipher_gettable_ctx_params(), y OSSL_FUNC_cipher_settable_ctx_params() devuelven arrays constantes de OSSL_PARAM(3) como descriptores de los parámetros que OSSL_FUNC_cipher_get_params(), OSSL_FUNC_cipher_get_ctx_params(), y OSSL_FUNC_cipher_set_ctx_params() pueden manejar, respectivamente. OSSL_FUNC_cipher_gettable_ctx_params() y OSSL_FUNC_cipher_settable_ctx_params() devolverán los parámetros asociados con el contexto del lado del proveedor cctx en su estado actual si no es NULL. De lo contrario, devolverán los parámetros asociados con el algoritmo del lado del proveedor provctx.

Los parámetros actualmente reconocidos por los cifrados incorporados se enumeran en "PARAMETERS" en EVP_EncryptInit(3). No todos los parámetros son relevantes o entendidos por todos los cifrados.

VALORES DE RETORNO

OSSL_FUNC_cipher_newctx() y OSSL_FUNC_cipher_dupctx() deben devolver el contexto de cifrado del lado del proveedor recién creado, o NULL en caso de fallo.

OSSL_FUNC_cipher_encrypt_init(), OSSL_FUNC_cipher_decrypt_init(), OSSL_FUNC_cipher_update(), OSSL_FUNC_cipher_final(), OSSL_FUNC_cipher_cipher(), OSSL_FUNC_cipher_encrypt_skey_init(), OSSL_FUNC_cipher_decrypt_skey_init(), OSSL_FUNC_cipher_pipeline_encrypt_init(), OSSL_FUNC_cipher_pipeline_decrypt_init(), OSSL_FUNC_cipher_pipeline_update(), OSSL_FUNC_cipher_pipeline_final(), OSSL_FUNC_cipher_get_params(), OSSL_FUNC_cipher_get_ctx_params() y OSSL_FUNC_cipher_set_ctx_params() deben devolver 1 en caso de éxito o 0 en caso de error.

OSSL_FUNC_cipher_gettable_params(), OSSL_FUNC_cipher_gettable_ctx_params() y OSSL_FUNC_cipher_settable_ctx_params() deben devolver un array constante de OSSL_PARAM(3), o NULL si no se ofrece ninguno.
