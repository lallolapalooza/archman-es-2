NOMBRE

proxytunnel - programa para tunelizar una conexión a través de un proxy HTTPS estándar

SINOPSIS

proxytunnel [OPCIÓN...] [host:puerto]

DESCRIPCIÓN

proxytunnel es un programa para tunelizar cualquier conexión a través de un proxy HTTPS estándar, eludiendo los mecanismos de filtrado HTTP estándar. Se utiliza principalmente como backend para ProxyCommand de OpenSSH, y como backend de proxy para Putty. También se puede utilizar para otros fines de traversión de proxy como el rebote de proxy.

OPCIONES

-i, --inetd

Ejecutar desde inetd (por defecto: desactivado).

-a, --standalone=[dirección:]puerto

Ejecutar como demonio independiente en la dirección y puerto especificados. dirección puede ser una dirección IPv4, una dirección IPv6 entre corchetes o una combinación entre corchetes de una dirección IPv6, '%' y el nombre de la interfaz. Este último formato solo es necesario con direcciones IPv6 de enlace local. El demonio escucha en cualquier dirección si dirección no se proporciona.

Ejemplos

22, 123.45.67.89:22, [2001:db8::123:4567:89ab:cdef]:22, [2001:db8::123:4567:89ab:cdef%eth0]:22

-p, --proxy=host:puerto

Utilizar host y puerto como el proxy local al que conectarse, si no se especifica, la variable de entorno HTTP_PROXY, si está establecida, se utilizará en su lugar.

-r, --remproxy=host:puerto

Utilizar host y puerto como el proxy remoto (secundario) al que conectarse.

-d, --dest=host:puerto

Utilizar host y puerto como el destino del túnel; también puedes especificarlos como argumento del comando proxytunnel.

-e, --encrypt

Encriptar SSL los datos entre el proxy local y el destino.

-E, --encrypt-proxy

Encriptar SSL los datos entre el cliente y el proxy local.

-X, --encrypt-remproxy

Encriptar SSL los datos entre el proxy local y el proxy remoto (secundario).

OPCIONES ADICIONALES

-W, --wa-bug-29744

Solución alternativa para el Bugzilla 29744 de ASF: Si se utiliza SSL (mediante las opciones -e, -E, -X), dejar de utilizarlo inmediatamente después del intercambio CONNECT para solucionar errores del servidor Apache (Esto puede no funcionar en todas las configuraciones).

-B, --buggy-encrypt-proxy

Equivalente a -E -W (Proporcionado por compatibilidad hacia atrás).

-z, --no-check-certificate

No verificar el certificado SSL del servidor al establecer una conexión SSL. Por defecto, se verifica el certificado SSL del servidor y se comprueba el nombre de host de destino con los nombres alternativos del sujeto del certificado, si los hay, o con el nombre común si no hay nombres alternativos del sujeto.

-C, --cacert=nombre_archivo/directorio

Especificar un archivo de certificado CA (o un directorio que contenga certificados CA) en el que confiar al verificar un certificado SSL de servidor. Si se proporciona un directorio, debe estar preparado con la herramienta c_rehash de OpenSSL (por defecto, a menos que se cambie en tiempo de compilación usando las opciones DEFAULT_CA_FILE o DEFAULT_CA_DIR: /etc/ssl/certs).

-4, --ipv4

Forzar el uso de IPv4 al conectarse al proxy local.

-6, --ipv6

Forzar el uso de IPv6 al conectarse al proxy local.

-F, --passfile=nombre_archivo

Utilizar nombre_archivo para leer el nombre de usuario y la contraseña para la autenticación del proxy HTTPS; el archivo utiliza el mismo formato que .wgetrc y puede compartirse con wget. Utilice esta opción, o variables de entorno, para ocultar la contraseña de otros usuarios.

-P, --proxyauth=nombre_usuario:contraseña

Utilizar nombre_usuario y contraseña como credenciales para autenticarse contra un proxy HTTPS local; el nombre de usuario y la contraseña también se pueden especificar en las variables de entorno PROXYUSER y PROXYPASS para ocultarlos de otros usuarios. Si se omite la contraseña y no se establece la variable de entorno PROXYPASS, proxytunnel solicitará la contraseña.

-R, --remproxyauth=nombre_usuario:contraseña

Utilizar nombre_usuario y contraseña como credenciales para autenticarse contra un proxy HTTPS remoto (secundario); el nombre de usuario y la contraseña también se pueden especificar en las variables de entorno REMPROXYUSER y REMPROXYPASS para ocultarlos de otros usuarios. Si se omite la contraseña y no se establece la variable de entorno REMPROXYPASS, proxytunnel solicitará la contraseña.

-c, --cert=nombre_archivo

Proporcionar el nombre del archivo que contiene el certificado de cliente SSL para autenticarse mediante certificado de cliente contra el proxy local, el proxy remoto o el destino. El archivo debe estar en formato PEM. Además, puede contener uno o más certificados intermedios que falten en el extremo del servidor, formando efectivamente una cadena de certificados. Requiere la especificación adicional de -k, --key. Se ignora si no se proporciona ni -e, --encrypt ni -E, --encrypt-proxy ni -X, --encrypt-remproxy.

-k, --key=nombre_archivo

Proporcionar el nombre del archivo que contiene la clave de cliente SSL para autenticarse mediante certificado de cliente contra el proxy local, el proxy remoto o el destino. El archivo debe estar en formato PEM. Requiere la especificación adicional de -c, --cert. Se ignora si no se proporciona ni -e, --encrypt ni -E, --encrypt-proxy ni -X, --encrypt-remproxy.

-N, --ntlm

Utilizar autenticación basada en NTLM.

-t, --domain=CADENA

Especificar el dominio NTLM (por defecto: autodetección).

-H, --header=CADENA

Añadir cabeceras HTTP adicionales para enviar al proxy.

-o, --host=host[:puerto]

Enviar una cabecera Host personalizada. Con conexiones SSL, host también se envía como SNI.

-x, --proctitle=CADENA

Utilizar un título de proceso diferente.

OPCIONES MISCELÁNEAS

-v, --verbose

Activar verbosidad.

-q, --quiet

Suprimir mensajes.

-h, --help

Mostrar ayuda y salir.

-V, --version

Mostrar versión y salir.

ARGUMENTOS

host:puerto es la combinación del nombre de host y el número de puerto de destino.


Nota

Especificar el destino como argumentos es exactamente lo mismo que especificarlos usando la opción -d o --dest.

USO

Dependiendo de tu situación, podrías querer hacer alguna de las siguientes cosas:

•Conectarse a través de un proxy local a tu sistema doméstico en el puerto 22 
$ proxytunnel -v -p proxy.empresa.com:8080 -d sistema.casa.nl:22
•Conectarse a través de un proxy local (con autenticación) a tu sistema doméstico 
$ proxytunnel -v -p proxy.empresa.com:8080 -P usuario:contraseña -d sistema.casa.nl:22
•Conectarse a través de un proxy local (con autenticación) ocultando tu contraseña 
$ export PROXYPASS=contraseña
$ proxytunnel -v -p proxy.empresa.com:8080 -P usuario -d sistema.casa.nl:22
•Conectarse a través de un proxy local a un proxy remoto y rebotar a cualquier sistema 
$ proxytunnel -v -p proxy.empresa.com:8080 -r proxy.encasa.nl:443 -d sistema.amigo.nl:22
•Conectarse usando SSL a través de un proxy local a tu sistema doméstico

DESCRIPTION

Proxytunnel is a command-line utility that allows you to tunnel TCP connections over an HTTPS proxy. It establishes a tunnel to a specified destination host and port through an HTTP(S) proxy server, effectively bypassing network restrictions that might otherwise block direct connections.

It is particularly useful when you need to access services on a remote machine that are only reachable through a corporate or restrictive network environment that enforces the use of an HTTP(S) proxy.

OPTIONS

-p, --proxy proxy:port
Specifies the address and port of the HTTPS proxy server to use for tunneling.
-P, --proxyauth user:password
Specifies the username and password for authenticating with the HTTPS proxy server.
-d, --dest host:port
Specifies the destination host and port to connect to after tunneling through the proxy.
-a, --agent agent:port
Specifies the address and port of an SSH agent for key-based authentication.
-r, --remote host:port
Specifies a remote (secondary) proxy server to use. This can be used for chaining proxies.
-R, --remproxyauth user:password
Specifies the username and password for authenticating with the remote (secondary) proxy server.
-4, --ipv4
Force the use of IPv4 addresses only.
-6, --ipv6
Force the use of IPv6 addresses only.
-v, --verbose
Increase verbosity. Can be used multiple times for more detailed output.
-h, --help
Display a help message and exit.
-V, --version
Display version information and exit.

ADDITIONAL OPTIONS

-t, --tcp-only
Forces proxytunnel to use only TCP connections.
-N, --no-dns
Do not perform DNS lookups.
-f, --fork
Fork the process into the background.
-L, --local local_port
Listen on a local port and forward connections to the destination.
-D, --dynamic local_port
Listen on a local port and act as a SOCKS proxy.

MISCELLANEOUS OPTIONS

-e, --encode
Encode the destination address in a way that some proxies might require.

ARGUMENTS

Proxytunnel accepts the destination host and port as command-line arguments if not specified with -d.

USAGE

To establish a connection to system.home.nl on port 22 through an HTTPS proxy at proxy.company.com on port 8080, you can use the following command:

$ proxytunnel -v -E -p proxy.company.com:8080 -d system.home.nl:22

OPENSSH CONFIGURATION

To use this program with OpenSSH to connect to a host somewhere, create a ~/.ssh/config file with the following content:

Host system.athome.nl
    ProxyCommand proxytunnel -p proxy.company.com:8080 -d %h:%p
    ServerAliveInterval 30

Note

The ServerAliveInterval directive makes sure that idle connections are not being dropped by intermediate firewalls that remove active sessions aggressively. If you see your connection dropping out, try to lower the value even more.

To use the dynamic (SOCKS) portforwarding capability of the SSH client, you can specify the DynamicForward directive in your ssh_config file like:

Host system.athome.nl
    DynamicForward 1080
    ProxyCommand proxytunnel -p proxy.company.com:8080 -d %h:%p
    ServerAliveInterval 30

NOTES


Important

Most HTTPS proxies do not allow access to ports other than HTTPS (tcp/443) and SNEWS (tcp/563). In this case you need to make sure the SSH daemon or remote proxy on the destination system is listening on either tcp/443 or tcp/563 to get through.

ENVIRONMENT

Proxytunnel can be influenced by setting one of the following environment variables:

HTTP_PROXY

If this environment variable is set, proxytunnel will use it as the local proxy if -p or --proxy is not provided.

PROXYUSER

If this environment variable is set, proxytunnel will use it as the username for proxy authentication, unless specified using the -P or --proxyauth option.

PROXYPASS

If this environment variable is set, proxytunnel will use it as the password for proxy authentication, unless specified using the -P or --proxyauth option.

REMPROXYUSER

If this environment variable is set, proxytunnel will use it as the username for remote (secondary) proxy authentication, unless specified using the -R or --remproxyauth option.

REMPROXYPASS

If this environment variable is set, proxytunnel will use it as the password for remote (secondary) proxy authentication, unless specified using the -R or --remproxyauth option.
