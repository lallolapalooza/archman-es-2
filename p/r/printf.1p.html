PRINTF(1P) Manual del programador POSIX PRINTF(1P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual correspondiente de Linux para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

printf — escribir salida formateada

SINOPSIS

printf formato [argumento...]

DESCRIPCIÓN

La utilidad printf escribirá los operandos formateados en la salida estándar. Los operandos argumento se formatearán bajo el control del operando formato.

OPCIONES

Ninguna.

OPERANDOS

Se admitirán los siguientes operandos:

formato
Una cadena que describe el formato a utilizar para escribir los operandos restantes. Consulte la sección DESCRIPCIÓN EXTENDIDA.
argumento
Las cadenas que se escribirán en la salida estándar, bajo el control de formato. Consulte la sección DESCRIPCIÓN EXTENDIDA.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán a la ejecución de printf:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no estén establecidas o estén vacías. (Consulte el volumen de Definiciones Base de POSIX.1−2017, Sección 8.2, Variables de internacionalización la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional).
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en contraposición a caracteres multibyte en los argumentos).
LC_MESSAGES

Determinar la configuración regional que debe utilizarse para afectar al formato y contenido de los mensajes de diagnóstico escritos en la salida estándar de error.
LC_NUMERIC

Determinar la configuración regional para el formateo numérico. Afectará al formato de los números escritos utilizando los especificadores de conversión e, E, f, g y G (si se admiten).
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

Consulte la sección DESCRIPCIÓN EXTENDIDA.

SALIDA DE ERROR

La salida de error se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

El operando formato se utilizará como cadena de formato descrita en el volumen de Notación de formato de archivo del volumen de Definiciones Base de POSIX.1−2017, Capítulo 5, con las siguientes excepciones:

1.
Un <espacio> en la cadena de formato, en cualquier contexto que no sea una bandera de una especificación de conversión, se tratará como un carácter ordinario que se copia a la salida.
2.
Un carácter '' en la cadena de formato se tratará como un carácter '', no como un <espacio>.
3.
Además de las secuencias de escape que se muestran en el volumen de Notación de formato de archivo de Definiciones Base de POSIX.1−2017, Capítulo 5 ('\\', '\a', '\b', '\f', '\n', '\r', '\t', '\v'), "\ddd", donde ddd es un número octal de uno, dos o tres dígitos, se escribirá como un byte con el valor numérico especificado por el número octal.
4.
La implementación no antepondrá ni seguirá la salida de los especificadores de conversión d o u con caracteres de <espacio> no especificados por el operando formato.
5.
La implementación no antepondrá ceros no especificados por el operando formato a la salida del especificador de conversión o.
6.
No es necesario admitir los especificadores de conversión a, A, e, E, f, F, g y G.
7.
Se admitirá un especificador de conversión adicional, b, de la siguiente manera. Se tomará el operando como una cadena que puede contener secuencias de escape de <barra invertida>. Se admitirán las siguientes secuencias de escape de <barra invertida>:
--
Las secuencias de escape enumeradas en el volumen de Notación de formato de archivo de Definiciones Base de POSIX.1−2017, Capítulo 5 ('\\', '\a', '\b', '\f', '\n', '\r', '\t', '\v'), que se convertirán a los caracteres que representan.
--
"\0ddd", donde ddd es un número octal de cero, uno, dos o tres dígitos que se convertirá a un byte con el valor numérico especificado por el número octal.
--
'\c', que no se escribirá y provocará que printf ignore todos los caracteres restantes en el operando de cadena que lo contenga, todos los operandos de cadena restantes y cualquier carácter adicional en el operando formato.

La interpretación de una <barra invertida> seguida de cualquier otra secuencia de caracteres no está especificada.

Los bytes de la cadena convertida se escribirán hasta el final de la cadena o hasta que se alcance el número de bytes indicado por la especificación de precisión. Si se omite la precisión, se tomará como infinita, por lo que se escribirán todos los bytes hasta el final de la cadena convertida.

8.
Por cada especificación de conversión que consuma un argumento, se evaluará el siguiente operando argumento y se convertirá al tipo apropiado para la conversión, como se especifica a continuación.
9.
El operando formato se reutilizará tantas veces como sea necesario para satisfacer los operandos argumento. Cualquier especificador de conversión b, c o s adicional se evaluará como si se hubiera proporcionado un operando de cadena nula; otras especificaciones de conversión adicionales se evaluarán como si se hubiera proporcionado un argumento cero. Si el operando formato no contiene especificaciones de conversión y hay operandos argumento, los resultados no están especificados.
10.
Si una secuencia de caracteres en el operando formato comienza con un carácter '%', pero no forma una especificación de conversión válida, el comportamiento no está especificado.
11.
El argumento del especificador de conversión c puede ser una cadena que contenga cero o más bytes. Si contiene uno o más bytes, se escribirá el primer byte y se ignorarán los bytes adicionales. Si el argumento es una cadena vacía, no está especificado si no se escribe nada o si se escribe un byte nulo.

Los operandos argumento se tratarán como cadenas si el especificador de conversión correspondiente es b, c o s, y se evaluarán como si fuera mediante la función strtod() si el especificador de conversión correspondiente es a, A, e, E, f, F, g o G. En caso contrario, se evaluarán

*
Se permitirá un <signo más> o <guion menos> inicial.
*
Si el carácter inicial es una comilla simple o doble, el valor será el valor numérico en el conjunto de códigos subyacente del carácter que sigue a la comilla simple o doble.

Si un operando argumento no se puede convertir completamente en un valor interno apropiado para la especificación de conversión correspondiente, se escribirá un mensaje de diagnóstico en la salida de error estándar y la utilidad no saldrá con un estado de salida cero, sino que continuará procesando los operandos restantes y escribirá el valor acumulado en el momento en que se detectó el error en la salida estándar.

No se considerará un error si un operando argumento no se utiliza por completo para una conversión b, c o s.

 0
Finalización exitosa.
>0

Por defecto.

USO DE APLICACIONES

Las especificaciones de conversión de formato de punto flotante de printf() no son necesarias porque todo el cálculo en el shell es aritmética entera. La utilidad awk realiza cálculos de punto flotante y proporciona su propia función printf. La utilidad bc puede realizar aritmética de punto flotante de precisión arbitraria, pero no proporciona capacidades de formato extensas. (Esta utilidad printf realmente no se puede utilizar para formatear la salida de bc; no admite precisión arbitraria). Se anima a las implementaciones a admitir las conversiones de punto flotante como una extensión.

Tenga en cuenta que esta utilidad printf, al igual que la función printf() definida en el volumen de Interfaces del Sistema de POSIX.1‐2017 en la que se basa, no hace ninguna provisión especial para tratar con caracteres multibyte al usar la especificación de conversión %c o cuando se especifica una precisión en una especificación de conversión %b o %s. Las aplicaciones deben tener extrema precaución al usar cualquiera de estas características cuando hay caracteres multibyte en el conjunto de caracteres.

No se hacen disposiciones en este volumen de POSIX.1‐2017 que permitan especificar anchos de campo y precisiones como '*' ya que el '*' se puede reemplazar directamente en el operando format utilizando la sustitución de variables del shell. Las implementaciones también pueden proporcionar esta función como una extensión si así lo desean.

Las constantes de caracteres hexadecimales, como se definen en el estándar ISO C, no se reconocen en el operando format porque no hay una forma consistente de detectar el final de la constante. Las constantes de caracteres octales se limitan a un máximo de tres dígitos octales, pero las constantes de caracteres hexadecimales solo se terminan con un carácter que no sea un dígito hexadecimal. En el estándar ISO C, el operador de concatenación "##" se puede utilizar para terminar una constante y seguirla con un carácter hexadecimal que se escribirá. En el shell, la concatenación ocurre antes de que la utilidad printf tenga la oportunidad de analizar el final de la constante hexadecimal.

La especificación de conversión %b no forma parte del estándar ISO C; se ha agregado aquí como una forma portátil de procesar secuencias de escape de <barra invertida> expandidas en operandos de cadena como las proporcionadas por la utilidad echo. Consulte también la sección USO DE APLICACIONES de echo para conocer las formas de utilizar printf como reemplazo de todas las versiones tradicionales de la utilidad echo.

Si un argumento no se puede analizar correctamente para la especificación de conversión correspondiente, la utilidad printf debe informar un error. Por lo tanto, el desbordamiento y los caracteres extraneos al final de un argumento que se utiliza para una conversión numérica se informarán como errores.

EJEMPLOS

Para alertar al usuario y luego imprimir y leer una serie de indicaciones:

printf "\aPor favor, complete lo siguiente: \nNombre: "
read name
printf "Número de teléfono: "
read phone

Para leer una lista de respuestas correctas e incorrectas de un archivo, calcular el porcentaje correctamente e imprimirlos. Los números se justifican a la derecha y se separan por un solo <tabulador>. El porcentaje se escribe con una precisión de un decimal:

while read right wrong ; do
    percent=$(echo "scale=1;($right*100)/($right+$wrong)" | bc)
    printf "%2d correctas\t%2d incorrectas\t(%s%%)\n" \
        $right $wrong $percent
done < database_file

El comando:

printf "%5d%4d\n" 1 21 321 4321 54321

produce:

    1  21
  3214321
54321   0

Tenga en cuenta que el operando format se utiliza tres veces para imprimir todas las cadenas dadas y que printf suministró un '0' para satisfacer la última especificación de conversión %4d.

La utilidad printf debe notificar al usuario cuando se detectan errores de conversión al producir salida numérica; por lo tanto, se esperarían los siguientes resultados en una implementación con enteros de complemento a dos de 32 bits cuando se especifica %d como operando format:

Estándar
Argumento Salida Salida de diagnóstico
5a 5 printf: "5a" no completamente convertido
9999999999 2147483647 printf: "9999999999" desbordamiento aritmético
-9999999999 -2147483648 printf: "-9999999999" desbordamiento aritmético
ABC 0 printf: "ABC" se esperaba un valor numérico

El formato del mensaje de diagnóstico no está especificado, pero estos ejemplos transmiten el tipo de información que debe informarse. Tenga en cuenta que el valor que se muestra en la salida estándar es lo que se esperaría como valor de retorno de la función strtol() según lo definido en el volumen de Interfaces del Sistema de POSIX.1‐2017. Existe una correspondencia similar entre %u y strtoul() y entre %e, %f y %g (si la implementación admite conversiones de punto flotante) y strtod().

En una configuración regional que utiliza el estándar ISO/IEC 646:1991 como conjunto de códigos subyacente, el comando:

printf "%d\n" 3 +3 -3 \'3 \"+3 "'-3"

produce:

3
Valor numérico de la constante 3
3
Valor numérico de la constante 3
-3
Valor numérico de la constante -3
51
Valor numérico del carácter '3' en el conjunto de códigos estándar ISO/IEC 646:1991
43
Valor numérico del carácter '+' en el conjunto de códigos estándar ISO/IEC 646:1991
45
Valor numérico del carácter '-' en el conjunto de códigos estándar ISO/IEC 646:1991

Tenga en cuenta que en una configuración regional con caracteres multibyte, el valor de un carácter pretende ser el valor de la representación equivalente de wchar_t del carácter, como se describe en el volumen de Interfaces del Sistema de POSIX.1‐2017.

FUNDAMENTO RACIONAL

La utilidad printf se agregó para proporcionar una funcionalidad que históricamente ha sido proporcionada por echo. Sin embargo, debido a las diferencias irreconciliables en las diversas versiones de echo existentes, la versión tiene pocas características especiales, dejando esas a esta nueva utilidad printf, que se basa en una del sistema de Novena Edición.

La sección DESCRIPCIÓN EXTENDIDA coincide casi exactamente con la función printf() en el estándar ISO C, aunque se describe en términos de la notación de formato de archivo en el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 5, Notación de formato de archivo.

Las versiones anteriores de este estándar especificaban que los argumentos para todas las conversiones, excepto b, c y s, se evaluaban de la misma manera (como constantes C, pero con las excepciones indicadas). Para las implementaciones que admiten las conversiones de punto flotante, no estaba claro si las conversiones enteras solo necesitaban aceptar constantes enteras y las conversiones de punto flotante solo necesitaban aceptar constantes de punto flotante, o si ambos tipos de conversiones debían aceptar ambos tipos de constantes. Además, al no distinguir entre ellas, el requisito relacionado con una comilla simple o doble inicial se aplicaba a las conversiones de punto flotante, aunque esto no proporcionaba ninguna funcionalidad útil a las aplicaciones que no estuviera ya disponible a través de las conversiones enteras. El estándar actual aclara la situación al especificar que los argumentos para las conversiones de punto flotante se evalúan como si fueran por strtod(), y los argumentos para las conversiones enteras se evalúan como constantes enteras C, con el tratamiento especial de la comilla simple o doble inicial aplicándose solo a las conversiones enteras.
