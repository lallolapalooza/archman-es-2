NOMBRE

projinfo - Consultas de objetos geodésicos y operaciones de coordenadas

SINOPSIS

projinfo
[-o formatos] [-k crs|operation|datum|ensemble|ellipsoid] [--summary] [-q]
[[--area nombre_o_codigo] | [--bbox long_o,lat_s,long_e,lat_n]]
[--spatial-test contains|intersects]
[--crs-extent-use none|both|intersection|smallest]
[--grid-check none|discard_missing|sort|known_available]
[--pivot-crs always|if_no_direct_transformation|never|{auth:code[,auth:code]*}]
[--show-superseded] [--hide-ballpark] [--accuracy {accuracy}]
[--allow-ellipsoidal-height-as-vertical-crs]
[--boundcrs-to-wgs84]
[--authority nombre]
[--main-db-path path] [--aux-db-path path]*
[--dump-db-structure]
[--identify] [--3d]
[--output-id AUTH:CODE]
[--c-ify] [--single-line]
--searchpaths | --remote-data |
--list-crs [filtro-lista-crs] |
--dump-db-structure [{definicion_objeto} | {referencia_objeto}] |
{definicion_objeto} | {referencia_objeto} |
(-s {def_srs} [--s_epoch {epoca}] -t {def_srs} [--t_epoch {epoca}]) |
({def_srs} {def_srs})

donde {definicion_objeto} o {def_srs} es una de las posibilidades aceptadas por proj_create()

  • una cadena de proj,
  • una cadena WKT,
  • un código de objeto (como "EPSG:4326", "urn:ogc:def:crs:EPSG::4326", "urn:ogc:def:coordinateOperation:EPSG::1671"),
  • un nombre de Objeto. Ej: "WGS 84", "WGS 84 / UTM zona 31N". En ese caso, como la unicidad no está garantizada, se aplican heurísticas para determinar la mejor coincidencia apropiada.
  • un nombre de CRS y una época de coordenadas, separados con '@'. Por ejemplo "ITRF2014@2025.0". (añadido en 9.2)
  • un URN OGC que combina referencias para sistemas de referencia de coordenadas compuestas (ej. "urn:ogc:def:crs,crs:EPSG::2393,crs:EPSG::5717" o sintaxis abreviada personalizada "EPSG:2393+5717"),
  • un URN OGC que combina referencias para referencias para CRSs proyectados o derivados ej. para CRS 3D Proyectado "UTM zona 31N / WGS 84 (3D)": "urn:ogc:def:crs,crs:EPSG::4979,cs:PROJ::ENh,coordinateOperation:EPSG::16031" (añadido en 6.2)
  • Extensión del URN OGC para CoordinateMetadata. ej. "urn:ogc:def:CoordinateMetadata:NRCAN::NAD83_CSRS_1997_MTM11_HT2_1997"
  • un URN OGC que combina referencias para operaciones concatenadas (ej. "urn:ogc:def:coordinateOperation,coordinateOperation:EPSG::3895,coordinateOperation:EPSG::1618")
  • una cadena PROJJSON. El jsonschema está en https://proj.org/schemas/v0.4/projjson.schema.json (añadido en 6.2)
  • un CRS compuesto formado por dos nombres de objeto separados por " + ". ej. "WGS 84 + EGM96 height" (añadido en 7.1)

{referencia_objeto} es un nombre de archivo precedido por el carácter '@'. El archivo referenciado por el {referencia_objeto} debe contener una {definicion_objeto} válida.

El uso de "{def_srs} {def_srs}" es equivalente a "-s {def_srs} -t {def_srs}" (añadido en 9.5).

DESCRIPCIÓN

projinfo es un programa que puede consultar información sobre un objeto geodésico, un sistema de referencia de coordenadas (CRS) o una operación de coordenadas, cuando se especifican las opciones -s y -t, y mostrarlo en diferentes formatos (cadena PROJ, cadena WKT o cadena PROJJSON).

También se puede utilizar para consultar operaciones de coordenadas disponibles entre dos CRS.

Los siguientes parámetros de control pueden aparecer en cualquier orden:

-o formatos
formatos es una combinación separada por comas de: all, default, PROJ, WKT_ALL, WKT2:2015, WKT2:2019, WKT1:GDAL, WKT1:ESRI, PROJJSON, SQL.

Excepto all y default, otros formatos pueden ir precedidos de - para deshabilitarlos.

NOTA:

WKT2_2019 se llamaba anteriormente WKT2_2018.

NOTA:

Antes de PROJ 6.3.0, WKT1:GDAL llamaba implícitamente a --boundcrs-to-wgs84. Esto ya no es así.

NOTA:

Cuando se especifica SQL, se debe especificar --output-id.
-k crs|operation|datum|ensemble|ellipsoid
Cuando se utiliza para consultar un solo objeto con un AUTHORITY:CODE, determina el (k)ind del objeto en caso de que existan CRS, operaciones de coordenadas o elipsoides con el mismo CODE. El valor predeterminado es crs.
--summary
Al listar operaciones de coordenadas disponibles entre 2 CRS, devuelve el resultado en un formato de resumen, mencionando solo el nombre de la operación de coordenadas, su precisión y su área de uso.

NOTA:

solo se utiliza para la computación de operaciones de coordenadas
-q
Activa el modo silencioso. El modo silencioso solo está disponible para consultas sobre objetos individuales, y solo se selecciona un formato de salida. En ese modo, solo se muestra la cadena PROJ, WKT o PROJJSON, sin ninguna otra introducción. La salida es entonces potencialmente compatible para ser enviada a otras utilidades.
--area nombre_o_codigo
Especifica un área de interés para restringir los resultados al investigar operaciones de coordenadas entre 2 CRS. El área de interés se puede especificar como un nombre (ej. "Denmark - onshore") o un AUTHORITY:CODE (EPSG:3237). Esta opción es exclusiva de --bbox.

NOTA:

solo se utiliza para la computación de operaciones de coordenadas
--bbox long_o,lat_s,long_e,lat_n
Especifica un área de interés para restringir los resultados al investigar operaciones de coordenadas entre 2 CRS. El área de interés se especifica como un cuadro delimitador con coordenadas geográficas, expresadas en grados en un CRS geográfico no especificado. long_o y long_e deben estar en el rango [-180,180], y lat_s y lat_n en el rango [-90,90]. long_o es generalmente menor que long_e, excepto en el caso en que el área de interés cruce el antimeridiano.

NOTA:

solo se utiliza para la computación de operaciones de coordenadas
--spatial-test contains|intersects
Especifica cómo se comparan las áreas de uso de las operaciones de coordenadas encontradas en la base de datos con el área de interés especificada explícitamente con --area o --bbox, o derivada implícitamente del área de uso del CRS de origen y destino. Por defecto, projinfo solo conservará las operaciones de coordenadas cuya área de uso esté estrictamente dentro del área de interés (estrategia contains). Si se utiliza la estrategia intersects, la prueba espacial se relaja, y se listará cualquier operación de coordenadas cuya área de uso se interseque al menos parcialmente con el área de interés.

NOTA:

solo se utiliza para la computación de operaciones de coordenadas
--crs-extent-use none|both|intersection|smallest
Especifica qué área de interés considerar cuando no se especifica una explícita con las opciones --area o --bbox. Por defecto (estrategia smallest), se buscará el área de uso del CRS de origen o destino, y la que sea menor en términos de área se utilizará como área de interés. Si se usa none, no se utiliza área de interés. Si se usa both, solo se seleccionarán las operaciones de coordenadas que se relacionen (contengan o intersequen según la estrategia --spatial-test) con el área de uso de ambos CRS. Si se usa intersection, solo se seleccionarán las operaciones de coordenadas que se relacionen con el área de intersección de las áreas de uso de los CRS de origen y destino.

NOTE:

solo se utiliza para la computación de operaciones de coordenadas
--grid-check none|discard_missing|sort|known_available
Controla cómo se consideran las cuadrículas de transformación disponibles. El valor predeterminado es sort.

none: No se realiza ninguna comprobación sobre la disponibilidad de las cuadrículas de transformación.

discard_missing: Se descartan las operaciones de transformación que requieren cuadrículas de transformación no disponibles.

sort: Las operaciones de transformación se ordenan por la disponibilidad de sus cuadrículas, y solo se seleccionan las que tienen todas las cuadrículas requeridas disponibles.

known_available: Solo se consideran las operaciones de transformación para las que se sabe que las cuadrículas requeridas están disponibles.

NOTE:

solo se utiliza para la computación de operaciones de coordenadas
--pivot-crs always|if_no_direct_transformation|never|{auth:code[,auth:code]*}
Controla el uso de CRS pivote para la transformación de CRS. Un CRS pivote es un CRS intermedio utilizado para facilitar la transformación entre dos CRS que no tienen una transformación directa definida.

always: Siempre se intentará utilizar un CRS pivote si está disponible.

if_no_direct_transformation: Solo se utilizará un CRS pivote si no existe una transformación directa entre los CRS de origen y destino.

never: Nunca se utilizará un CRS pivote. Si no hay una transformación directa, la operación fallará.

{auth:code[,auth:code]*}: Se utilizará una lista explícita de CRS pivote. Si ninguno de los CRS pivote especificados es adecuado, la operación fallará (a menos que se combinen con una de las estrategias anteriores).

El valor predeterminado es if_no_direct_transformation.

NOTE:

solo se utiliza para la computación de operaciones de coordenadas
--show-superseded
Incluye CRS y operaciones de coordenadas obsoletos en los resultados. Por defecto, solo se muestran los elementos actuales.
--hide-ballpark
Oculta las operaciones de coordenadas aproximadas (ballpark) de los resultados. Estas son operaciones que proporcionan una precisión limitada y generalmente se utilizan como último recurso.
--accuracy {accuracy}
Filtra las operaciones de coordenadas para incluir solo aquellas con una precisión igual o mejor que el valor especificado. La precisión se especifica en metros (ej. 10 para 10 metros).
--allow-ellipsoidal-height-as-vertical-crs
Permite que las alturas elipsoidales se traten como un CRS vertical. Esto es útil cuando se trabaja con datos que utilizan alturas elipsoidales en lugar de alturas ortométricas.
--boundcrs-to-wgs84
Para CRS que son transformaciones entre un CRS geodésico y un CRS proyectado, incluye el CRS geodésico subyacente en el formato WKT. Si el CRS geodésico subyacente no es WGS84, se añade una transformación a WGS84. Esto es particularmente útil para el formato WKT1:GDAL.
--authority nombre
Filtra los resultados para incluir solo aquellos objetos que pertenecen a la autoridad especificada (ej. EPSG, IGNF).
--main-db-path path
Especifica la ruta al archivo de base de datos principal de PROJ (por ejemplo, `proj.db`). Si no se especifica, se utiliza la ruta predeterminada del sistema.
--aux-db-path path
Especifica la ruta a archivos de bases de datos auxiliares de PROJ. Se pueden especificar varias opciones. Si no se especifican, se utilizan las rutas predeterminadas del sistema.
--dump-db-structure
Muestra la estructura de la base de datos de PROJ. Si se especifica una definición u objeto de referencia, muestra la definición de ese objeto en la base de datos.
--identify
Identifica el tipo de objeto geodésico (CRS, operación, datum, etc.) a partir de una definición dada.
--3d
Realiza búsquedas de operaciones de coordenadas que tengan en cuenta la tercera dimensión (altura). Por defecto, solo se consideran las operaciones 2D.
--output-id AUTH:CODE
Para la salida en formato SQL, especifica el identificador único del objeto a generar.
--c-ify
Formatea la salida como una cadena C (escapando caracteres especiales).
--single-line
Formatea la salida en una sola línea.
--searchpaths
Muestra las rutas de búsqueda de bases de datos de PROJ.
--remote-data
Asegura que los datos remotos (por ejemplo, cuadrículas de transformación descargadas de la red) estén disponibles. Si no lo están, intenta descargarlos. Si falla la descarga, la operación falla.
--list-crs [filtro-lista-crs]
Lista los CRS disponibles en la base de datos de PROJ. Se puede aplicar un filtro opcional para restringir la lista (por ejemplo, por autoridad o palabras clave).
--dump-db-structure [{definicion_objeto} | {referencia_objeto}]
Similar a --dump-db-structure, pero si se proporciona una definición u objeto de referencia, muestra la definición de ese objeto en la base de datos en formato legible por humanos.

Si no se especifica ninguna de las opciones anteriores que realizan una acción específica (como --searchpaths, --remote-data, --list-crs o --dump-db-structure), se espera que el último argumento sea una definición de objeto o una referencia a un archivo que contiene una definición de objeto. En ese caso, se mostrará información sobre ese objeto específico.

Si se especifican las opciones -s y -t, se espera que proporcionen las definiciones de los CRS de origen y destino, respectivamente. En este caso, projinfo encontrará la mejor transformación disponible entre los dos CRS y mostrará información detallada sobre ella.

La sintaxis alternativa de dos argumentos {def_srs} {def_srs} es un atajo para especificar las opciones -s y -t con los mismos argumentos.

La opción --remote-data está diseñada para ser utilizada principalmente con operaciones de transformación de coordenadas. Si se activa, projinfo intentará descargar automáticamente cualquier archivo de cuadrícula de transformación necesario que no se encuentre localmente.

EJEMPLOS

List all available coordinate operations between WGS 84 and a local CRS:

$ projinfo --list-crs EPSG:4326 EPSG:27700



Show the PROJ string definition for EPSG:4326:

$ projinfo -q -o PROJ EPSG:4326



Show the WKT2:2019 definition for the Mercator projection:

$ projinfo -o WKT2:2019 Mercator



Find the best transformation between WGS 84 (latitude/longitude) and UTM zone 32N:

$ projinfo -s EPSG:4326 -t EPSG:32632



Find the best transformation between WGS 84 (latitude/longitude) and UTM zone 32N,

showing only the summary information:

$ projinfo --summary -s EPSG:4326 -t EPSG:32632



Find the best transformation between WGS 84 (latitude/longitude) and UTM zone 32N,

within the area of Denmark:

$ projinfo --area Denmark -s EPSG:4326 -t EPSG:32632



Find the best transformation between WGS 84 (latitude/longitude) and UTM zone 32N,

within a bounding box covering Denmark:

$ projinfo --bbox 5,54,15,58 -s EPSG:4326 -t EPSG:32632



Find the best transformation between WGS 84 (latitude/longitude) and UTM zone 32N,

using the 'intersects' spatial test:

$ projinfo --spatial-test intersects -s EPSG:4326 -t EPSG:32632



Show all available CRS definitions, including superseded ones:

$ projinfo --list-crs --show-superseded



Show the structure of the PROJ database:

$ projinfo --dump-db-structure



Show the definition of the EPSG:4326 CRS in the database:

$ projinfo --dump-db-structure EPSG:4326



Check PROJ search paths:

$ projinfo --searchpaths



Ensure remote data (grids) are available:

$ projinfo --remote-data -s EPSG:4326 -t EPSG:32632



Query a CRS using its authority code and a coordinate epoch:

$ projinfo --crs-extent-use none -o WKT2:2019 "ITRF2014@2025.0"



Query a compound CRS from two object names separated with " + ":

$ projinfo -o WKT2:2019 "WGS 84 + EGM96 height"



Query a compound CRS using OGC URN abbreviated syntax:

$ projinfo -o WKT2:2019 "EPSG:2393+5717"



Query a compound CRS using OGC URN with coordinate operation reference for 3D projected CRS:

$ projinfo -o WKT2:2019 "urn:ogc:def:crs,crs:EPSG::4979,cs:PROJ::ENh,coordinateOperation:EPSG::16031"



Query a CRS using a PROJJSON string:

$ projinfo -o PROJJSON '{ "type": "GeographicCRS", "name": "My CRS", "datum": { "type": "GeodeticReferenceFrame", "name": "My Datum", "ellipsoid": { "type": "Ellipsoid", "name": "GRS 1980", "semiMajorAxis": 6378137, "inverseFlattening": 298.257222101 } }, "coordinateSystem": { "type": "EllipsoidalCST", "axis": [ { "name": "Latitude", "abbreviation": "Lat", "direction": "north", "unit": "degree" }, { "name": "Longitude", "abbreviation": "Lon", "direction": "east", "unit": "degree" } ] } }'



Query using a PROJ string:

$ projinfo "+proj=longlat +datum=WGS84 +no_defs +type=crs"



Query using a file containing a PROJ string:

$ echo "+proj=longlat +datum=WGS84 +no_defs +type=crs" > my_crs.proj

$ projinfo @my_crs.proj



Query using a file containing a WKT string:

$ echo 'GEOGCRS["WGS 84",DATUM["World Geodetic System 1984",ELLIPSOID["WGS 84",6378137,298.257223563,LENGTHUNIT["metre",1]]],PRIMEM["Greenwich",0,ANGLEUNIT["degree",0.0174532925199433]],CS[ellipsoidal,2],AXIS["Geodetic latitude (Lat)",ellipsoidal,2003.42,ORDER[1]],AXIS["Geodetic longitude (Lon)",ellipsoidal,2003.42,ORDER[2]],USAGE[SCOPE["Horizontal component of 3D system."],AREA["World."],BBOX[-90,-180,90,180]],ID["EPSG",4326]]' > my_crs.wkt

$ projinfo @my_crs.wkt

solo se usa para el cálculo de operaciones de coordenadas
--grid-check none|discard_missing|sort|known_available
Especifica cómo la presencia o ausencia de una cuadrícula de desplazamiento horizontal o vertical requerida para una operación de coordenadas afecta los resultados devueltos al investigar operaciones de coordenadas entre 2 CRS. La estrategia predeterminada es sort (si PROJ_NETWORK no está definido). En ese caso, se devuelven todas las operaciones candidatas, pero la disponibilidad real de las cuadrículas se utiliza para determinar el orden de clasificación. Es decir, si una operación de coordenadas implica el uso de una cuadrícula que no está disponible en los directorios de recursos de PROJ (determinado por la variable de entorno PROJ_DATA), se listará en la parte inferior de los resultados. La estrategia none deshabilita por completo las comprobaciones de presencia de cuadrículas y esto devuelve los resultados como si todas las cuadrículas estuvieran disponibles. La estrategia discard_missing descarta los resultados que involucran cuadrículas no presentes en los directorios de recursos de PROJ. La estrategia known_available descarta los resultados que involucran cuadrículas no presentes en los directorios de recursos de PROJ y que no son conocidas de la CDN. Esta es la estrategia predeterminada si PROJ_NETWORK está configurado en ON.

NOTA:

solo se usa para el cálculo de operaciones de coordenadas
--pivot-crs always|if_no_direct_transformation|never|{auth:code[,auth:code]*}
Determina si se pueden usar CRS intermedios (pivote) al investigar operaciones de coordenadas entre 2 CRS. Un ejemplo típico es el pivote WGS84. Por defecto, projinfo considerará cualquier pivote potencial si no hay una transformación directa (if_no_direct_transformation). Si se utiliza la estrategia never, solo se utilizarán transformaciones directas entre los CRS de origen y destino. Si se utiliza la estrategia always, se considerarán CRS intermedios incluso si hay transformaciones directas. También es posible restringir los CRS de pivote a considerar especificando uno o varios CRS por su AUTORIDAD:CÓDIGO.

NOTA:

solo se usa para el cálculo de operaciones de coordenadas
--show-superseded
Cuando está habilitado, se listarán las operaciones de coordenadas que han sido sustituidas por otras. Tenga en cuenta que la sustitución no es equivalente a la depreciación: las operaciones sustituidas todavía se consideran válidas aunque tengan un equivalente mejor, mientras que las operaciones obsoletas se han determinado que son erróneas y no se consideran en absoluto.

NOTA:

solo se usa para el cálculo de operaciones de coordenadas
--hide-ballpark
Añadido en la versión 7.1.

Oculta cualquier operación de coordenadas que sea, o contenga, una transformación de aproximación (Ballpark transformation)

NOTA:

solo se usa para el cálculo de operaciones de coordenadas
--accuracy {accuracy}
Añadido en la versión 8.0.

Establece la precisión mínima deseada para las operaciones de coordenadas devueltas.

NOTA:

solo se usa para el cálculo de operaciones de coordenadas
--allow-ellipsoidal-height-as-vertical-crs
Añadido en la versión 8.0.

Permite exportar un CRS geográfico o proyectado 3D como un CRS compuesto cuyo CRS vertical representa la altura elipsoidal.

NOTA:

solo se usa para CRS, y con el formato de salida WKT1:GDAL
--boundcrs-to-wgs84
Cuando se especifica, esta opción investiga una operación de coordenadas desde el CRS geográfico base del CRS único, de origen o destino, al CRS geográfico WGS84 y, si se encuentra, envuelve esos CRS en un objeto BoundCRS. Esto se usa principalmente para enfoques de enlace temprano (early-binding).
--authority name
Especifica el nombre de la autoridad en la que restringir las búsquedas de objetos, al especificar un objeto por nombre o cuando se calculan operaciones de coordenadas. El valor predeterminado es permitir todas las autoridades.

Cuando se usa con salida SQL, esto restringe las autoridades a las que pueden pertenecer los objetos intermedios (el valor predeterminado es EPSG y PROJ). Tenga en cuenta que la autoridad de la opción --output-id también se agregará implícitamente.

--main-db-path path
Especifica el nombre y la ruta de la base de datos que será utilizada por projinfo. El valor predeterminado es proj.db en los directorios de recursos de PROJ.
--aux-db-path path
Especifica el nombre y la ruta de las bases de datos auxiliares, que se combinarán con la base de datos principal. Estas bases de datos auxiliares deben tener una estructura de tabla idéntica a la de la base de datos principal, pero pueden estar parcialmente completas y sus entradas pueden referirse a entradas de la base de datos principal. La opción se puede repetir para especificar varias bases de datos auxiliares.
--identify
Cuando se utiliza con una definición de objeto, consulta la base de datos PROJ para encontrar objetos conocidos, típicamente CRS, que son cercanos o idénticos al objeto. Cada objeto candidato se asocia con un porcentaje de probabilidad aproximado. Esto es útil cuando se utiliza con una cadena WKT que carece de un identificador EPSG, como ESRI WKT1. Esto también podría usarse con cadenas PROJ. Por ejemplo, +proj=utm +zone=31 +datum=WGS84 +type=crs se identificará con una probabilidad del 70% a EPSG:32631
--dump-db-structure
Añadido en la versión 8.1.

Muestra la secuencia de sentencias SQL para crear una nueva base de datos auxiliar vacía y válida. Esta opción se puede especificar como el único interruptor de la utilidad. Si también se especifica un objeto CRS y la opción --output-id, se agregará la definición del objeto como sentencias SQL.

--list-crs [list-crs-filter]
Añadido en la versión 8.1.

Muestra una lista (nombre de autoridad:código y nombre del CRS) de los CRS filtrados de la base de datos. Si no se proporciona ningún filtro, se muestran todos los nombres de autoridad y tipos de CRS no obsoletos. list-crs-filter es una combinación separada por comas de: allow_deprecated,geodetic,geocentric, geographic,geographic_2d,geographic_3d,vertical,projected,compound. Afectado por las opciones --authority, --area, --bbox y --spatial-test

--3d
Añadido en la versión 6.3.

"Promueve" CRS 2D a su versión 3D, donde el eje vertical es la altura elipsoidal en metros, utilizando el elipsoide del CRS geodésico base. Dependiendo de las versiones de PROJ y de la naturaleza exacta de los CRS involucrados, especialmente antes de PROJ 9.1, una mezcla de CRS 2D y 3D podría llevar a transformaciones 2D o 3D. A partir de PROJ 9.1, ambos CRS deben ser 3D para que la transformación vertical pueda ocurrir.

--output-id=AUTH:NAME
Añadido en la versión 8.1.

Identificador a asignar al objeto (para salida SQL).

Combinado con --dump-db-structure, los usuarios pueden crear bases de datos auxiliares, en lugar de modificar directamente la base de datos principal proj.db. Consulte el ejemplo de cómo exportar a una base de datos auxiliar.

Estas bases de datos auxiliares se pueden especificar a través de proj_context_set_database_path() o la variable de entorno PROJ_AUX_DB.

--c-ify
Solo para desarrolladores. Modifica la salida de cadena de la utilidad para que sea fácil incluir esas cadenas en código C/C++
--single-line
Muestra las cadenas PROJ, WKT o PROJJSON en una sola línea, en lugar de varias líneas con sangría por defecto.
--searchpaths
Añadido en la versión 7.0.

Muestra los directorios en los que se buscarán los recursos de PROJ (si no se utiliza la API C como proj_context_set_search_paths() que los sustituirá).

--remote-data
Añadido en la versión 7.0.

Muestra información sobre si la capacidad de red está habilitada y la URL relacionada.

--s_epoch
Añadido en la versión 9.4.

Época de las coordenadas en el SRC de origen, como año decimal. Solo se aplica a un SRC dinámico.

--t_epoch
Añadido en la versión 9.4.

Época de las coordenadas en el SRC de destino, como año decimal. Solo se aplica a un SRC dinámico.

Exportar las sentencias SQL para insertar un nuevo SRC en una base de datos auxiliar.
# Obtener las sentencias SQL para un SRC personalizado
projinfo "+proj=merc +lat_ts=5 +datum=WGS84 +type=crs +title=my_crs" --output-id HOBU:MY_CRS -o SQL -q > my_crs.sql
cat my_crs.sql
# Inicializar una base de datos auxiliar con el esquema de la base de datos de referencia
echo ".schema" | sqlite3 /path/to/proj.db | sqlite3 aux.db
# Anadir el contenido de la definicion de HOBU:MY_CRS
sqlite3 aux.db < my_crs.db
# Comprobar que todo funciona correctamente
projinfo --aux-db-path aux.db HOBU:MY_CRS

# Crear una base de datos auxiliar con la definicion de un SRC personalizado.
projinfo "+proj=merc +lat_ts=5 +datum=WGS84 +type=crs +title=my_crs" --output-id HOBU:MY_CRS --dump-db-structure | sqlite3 aux.db

projinfo --aux-db-path aux.db HOBU:MY_CRS
