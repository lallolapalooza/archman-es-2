NOMBRE

dlltool - crear archivos necesarios para construir y usar DLLs

SINOPSIS

dlltool [-d|--input-def nombre-archivo-def]
[-b|--base-file nombre-archivo-base]
[-e|--output-exp nombre-archivo-exports]
[-z|--output-def nombre-archivo-def]
[-l|--output-lib nombre-archivo-libreria]
[-y|--output-delaylib nombre-archivo-libreria-retraso]
[--export-all-symbols] [--no-export-all-symbols]
[--exclude-symbols lista]
[--no-default-excludes]
[-S|--as ruta-al-ensamblador] [-f|--as-flags opciones]
[-D|--dllname nombre] [-m|--machine maquina]
[-a|--add-indirect]
[-U|--add-underscore] [--add-stdcall-underscore]
[-k|--kill-at] [-A|--add-stdcall-alias]
[-p|--ext-prefix-alias prefijo]
[-x|--no-idata4] [-c|--no-idata5]
[--use-nul-prefixed-import-tables]
[-I|--identify nombre-archivo-libreria] [--identify-strict]
[-i|--interwork]
[-n|--nodelete] [-t|--temp-prefix prefijo]
[-v|--verbose]
[-h|--help] [-V|--version]
[--no-leading-underscore] [--leading-underscore]
[--deterministic-libraries] [--non-deterministic-libraries]
[archivo-objeto ...]

DESCRIPCIÓN

dlltool lee sus entradas, que pueden provenir de las opciones -d y -b, así como de los archivos objeto especificados en la línea de comandos. Luego procesa estas entradas y, si se ha especificado la opción -e, crea un archivo de exportaciones. Si se ha especificado la opción -l, crea un archivo de librería y si se ha especificado la opción -z, crea un archivo def. Cualquiera o todas las opciones -e, -l y -z pueden estar presentes en una invocación de dlltool.

Al crear una DLL, además del código fuente de la DLL, es necesario tener otros tres archivos. dlltool puede ayudar con la creación de estos archivos.

El primer archivo es un archivo .def que especifica qué funciones se exportan desde la DLL, qué funciones importa la DLL, y así sucesivamente. Este es un archivo de texto y puede crearse manualmente, o se puede usar dlltool para crearlo usando la opción -z. En este caso, dlltool escaneará los archivos objeto especificados en su línea de comandos buscando aquellas funciones que han sido marcadas especialmente como exportadas y colocará entradas para ellas en el archivo .def que crea.

Para marcar una función como exportada desde una DLL, necesita tener una entrada -export:<nombre_de_la_función> en la sección .drectve del archivo objeto. Esto se puede hacer en C usando el operador asm():

asm (".section .drectve");
asm (".ascii \"-export:mi_func\"");

int my_func (void) { ... }

El segundo archivo necesario para la creación de DLL es un archivo de exportaciones. Este archivo se enlaza con los archivos objeto que constituyen el cuerpo de la DLL y maneja la interfaz entre la DLL y el mundo exterior. Este es un archivo binario y puede crearse proporcionando la opción -e a dlltool al crear o leer un archivo .def.

El tercer archivo necesario para la creación de DLL es el archivo de librería con el que los programas se enlazarán para acceder a las funciones de la DLL (una `librería de importación'). Este archivo puede crearse proporcionando la opción -l a dlltool al crear o leer un archivo .def.

Si se especifica la opción -y, dlltool genera una librería de importación retrasada que puede usarse en lugar de la librería de importación normal para permitir que un programa se enlace a la dll solo cuando se llama a una función importada por primera vez. El ejecutable resultante deberá enlazarse a la librería estática delayimp que contiene _, la cual a su vez importará LoadLibraryA y GetProcAddress de kernel32.

dlltool construye el archivo de librería manualmente, pero construye el archivo de exportaciones creando archivos temporales que contienen declaraciones de ensamblador y luego ensamblando estos. La opción de línea de comandos -S se puede usar para especificar la ruta al ensamblador que usará dlltool, y la opción -f se puede usar para pasar opciones específicas a ese ensamblador. La opción -n se puede usar para evitar que dlltool elimine estos archivos temporales de ensamblador cuando termine, y si se especifica -n dos veces, esto evitará que dlltool elimine los archivos objeto temporales que utilizó para construir la librería.

Aquí hay un ejemplo de cómo crear una DLL a partir de un archivo fuente dll.c y también crear un programa (a partir de un archivo objeto llamado program.o) que utiliza esa DLL:

gcc -c dll.c
dlltool -e exports.o -l dll.lib dll.o
gcc dll.o exports.o -o dll.dll
gcc program.o dll.lib -o program

dlltool también puede usarse para consultar una librería de importación existente para determinar el nombre de la DLL a la que está asociada. Consulte la descripción de la opción -I o --identify.

OPCIONES

Las opciones de línea de comandos tienen los siguientes significados:

-d nombre-archivo
--input-def nombre-archivo
Especifica el nombre de un archivo .def a leer y procesar.
-b nombre-archivo
--base-file nombre-archivo
Especifica el nombre de un archivo base a leer y procesar. El contenido de este archivo se agregará a la sección de reubicación en el archivo de exportaciones generado por dlltool.
-e nombre-archivo
--output-exp nombre-archivo
Especifica el nombre del archivo de exportaciones a ser creado por dlltool.
-z nombre-archivo
--output-def nombre-archivo
Especifica el nombre del archivo .def a ser creado por dlltool.
-l nombre-archivo
--output-lib nombre-archivo
Especifica el nombre del archivo de librería a ser creado por dlltool.
-y nombre-archivo
--output-delaylib nombre-archivo
Especifica el nombre del archivo de librería de importación retrasada a ser creado por dlltool.
--deterministic-libraries
--non-deterministic-libraries
Al crear librerías de salida en respuesta a las opciones --output-lib o --output-delaylib, usar el valor cero para cualquier marca de tiempo, ID de usuario e ID de grupo creados (--deterministic-libraries) o las marcas de tiempo, ID de usuario e ID de grupo reales (--non-deterministic-libraries).
--export-all-symbols
Tratar todos los símbolos definidos globales y débiles encontrados en los archivos objeto de entrada como símbolos a exportar. Hay una pequeña lista de símbolos que no se exportan por defecto; consulte la opción --no-default-excludes. Puede añadir a la lista de símbolos a no exportar usando la opción --exclude-symbols.
--no-export-all-symbols
Exportar solo los símbolos listados explícitamente en un archivo .def de entrada o en secciones .drectve en los archivos objeto de entrada. Este es el comportamiento por defecto. Las secciones .drectve son creadas por atributos dllexport en el código fuente.
--exclude-symbols lista
No exportar los símbolos en lista. Esta es una lista de nombres de símbolos separados por comas o dos puntos. Los nombres de los símbolos no deben contener un guion bajo inicial. Esto solo es significativo cuando se usa --export-all-symbols.
