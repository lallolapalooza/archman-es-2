NOMBRE

nm - listar símbolos de archivos objeto

[-h|--help]

[-j|--format=just-symbols]
[-l|--line-numbers] [--inlines]
[-n|-v|--numeric-sort]
[-P|--portability]
[-p|--no-sort]
[-r|--reverse-sort]

DESCRIPCIÓN

GNU nm lista los símbolos de los archivos objeto objfile.... Si no se listan archivos objeto como argumentos, nm asume el archivo a.out.

Para cada símbolo, nm muestra:

  • El valor del símbolo, en la base seleccionada por las opciones (ver más abajo), o hexadecimal por defecto.
  • El tipo del símbolo. Al menos los siguientes tipos se utilizan; otros también dependen del formato del archivo objeto. Si es minúscula, el símbolo suele ser local; si es mayúscula, el símbolo es global (externo). Sin embargo, hay algunos símbolos en minúscula que se muestran para símbolos globales especiales ("u", "v" y "w").
"A"
El valor del símbolo es absoluto y no se modificará por enlaces posteriores.
"B"
"b"
El símbolo está en la sección de datos BSS. Esta sección normalmente contiene datos inicializados a cero o no inicializados, aunque el comportamiento exacto depende del sistema.
"C"
"c"
El símbolo es común. Los símbolos comunes son datos no inicializados. Al enlazar, varios símbolos comunes pueden aparecer con el mismo nombre. Si el símbolo está definido en algún lugar, los símbolos comunes se tratan como referencias indefinidas. La minúscula c se utiliza cuando el símbolo está en una sección especial para comunes pequeños.
"D"
"d"
El símbolo está en la sección de datos inicializados.
"G"
"g"
El símbolo está en una sección de datos inicializados para objetos pequeños. Algunos formatos de archivo objeto permiten un acceso más eficiente a objetos de datos pequeños, como una variable entera global en comparación con una gran matriz global.
"i"
Para archivos con formato PE, esto indica que el símbolo está en una sección específica para la implementación de DLL.

Para archivos con formato ELF, esto indica que el símbolo es una función indirecta. Esta es una extensión de GNU al conjunto estándar de tipos de símbolos ELF. Indica un símbolo que, si se referencia mediante una relocalización, no se evalúa a su dirección, sino que debe invocarse en tiempo de ejecución. La ejecución en tiempo de ejecución devolverá el valor que se utilizará en la relocalización.

Nota: la visualización real de los símbolos para las funciones indirectas de GNU está controlada por la opción de línea de comandos --ifunc-chars. Si se ha proporcionado esta opción, el primer carácter de la cadena se utilizará para los símbolos de funciones indirectas globales. Si la cadena contiene un segundo carácter, ese se utilizará para los símbolos de funciones indirectas locales.

"I"
El símbolo es una referencia indirecta a otro símbolo.
"N"
El símbolo es un símbolo de depuración.
"n"
El símbolo está en una sección de solo lectura que no es de datos ni de código ni de depuración.
"p"
El símbolo está en una sección de "unwind" de la pila.
"R"
"r"
El símbolo está en una sección de datos de solo lectura.
"S"
"s"
El símbolo está en una sección de datos no inicializados o inicializados a cero para objetos pequeños.
"T"
"t"
El símbolo está en la sección de texto (código).
"U"
El símbolo es indefinido.
"u"
El símbolo es un símbolo global único. Esta es una extensión de GNU al conjunto estándar de enlaces de símbolos ELF. Para un símbolo de este tipo, el enlazador dinámico se asegurará de que en todo el proceso solo se utilice un símbolo con este nombre y tipo.
"V"
"v"
El símbolo es un objeto débil. Cuando un símbolo definido débil se enlaza con un símbolo definido normal, se utiliza el símbolo definido normal sin errores. Cuando un símbolo indefinido débil se enlaza y el símbolo no está definido, el valor del símbolo débil se convierte en cero sin errores. En algunos sistemas, las mayúsculas indican que se ha especificado un valor predeterminado.
"W"
"w"
El símbolo es un símbolo débil que no ha sido específicamente etiquetado como símbolo de objeto débil. Cuando un símbolo definido débil se enlaza con un símbolo definido normal, se utiliza el símbolo definido normal sin errores. Cuando un símbolo indefinido débil se enlaza y el símbolo no está definido, el valor del símbolo se determina de manera específica del sistema sin errores. En algunos sistemas, las mayúsculas indican que se ha especificado un valor predeterminado.
"-"
El símbolo es un símbolo stabs en un archivo objeto a.out. En este caso, los siguientes valores impresos son el campo 'other' de stabs, el campo 'desc' de stabs y el tipo 'stab'. Los símbolos stabs se utilizan para almacenar información de depuración.
"?"
El tipo de símbolo es desconocido o específico del formato del archivo objeto.
•
El nombre del símbolo. Si un símbolo tiene información de versión asociada, se muestra la información de versión. Si el símbolo versionado no está definido o está oculto al enlazador, la cadena de versión se muestra como un sufijo al nombre del símbolo, precedido por un carácter @. Por ejemplo, foo@VER_1. Si la versión es la versión predeterminada que se utilizará al resolver referencias no versionadas al símbolo, se muestra como un sufijo precedido por dos caracteres @. Por ejemplo, foo@@VER_2.

OPCIONES

Las formas largas y cortas de las opciones, que se muestran aquí como alternativas, son equivalentes.

-A
-o
--print-file-name
Precede cada símbolo con el nombre del archivo de entrada (o miembro del archivo) en el que se encontró, en lugar de identificar el archivo de entrada una sola vez, antes de todos sus símbolos.
-a
--debug-syms
Muestra todos los símbolos, incluso los símbolos solo para depuración; normalmente no se listan.
-B
Lo mismo que --format=bsd (para compatibilidad con el nm de MIPS).
-C
--demangle[=style]
Decodifica (demangle) los nombres de símbolos de bajo nivel en nombres de nivel de usuario. Además de eliminar cualquier guion bajo inicial agregado por el sistema, esto hace que los nombres de funciones de C++ sean legibles. Diferentes compiladores tienen diferentes estilos de mangling. El argumento opcional de estilo de demangling se puede usar para elegir un estilo de demangling apropiado para su compilador.
--no-demangle
No decodificar nombres de símbolos de bajo nivel. Este es el comportamiento predeterminado.
--recurse-li
mit
--no-recurse-li
mit
--recursion-li
mit
--no-recursion-li
mit
Habilita o deshabilita un límite en la cantidad de recursión realizada al desmangling de cadenas. Dado que los formatos de ofuscación de nombres permiten un nivel de recursión infinito, es posible crear cadenas cuya decodificación agotará la cantidad de espacio de pila disponible en la máquina anfitriona, provocando una falla de memoria. El límite intenta evitar que esto suceda al restringir la recursión a 2048 niveles de anidamiento.

El valor predeterminado es que este límite esté habilitado, pero deshabilitarlo puede ser necesario para des

mangling nombres verdaderamente complicados. Sin embargo, tenga en cuenta que si el límite de recursión está
deshabilitado, es posible que se agote la pila y cualquier informe de error sobre tal evento será rechazado.

Si --plugin no se proporciona, pero el soporte de plugins ha sido habilitado, entonces nm itera sobre los archivos en ${libdir}/bfd-plugins en orden alfabético y se usa el primer plugin que reclama el objeto en

Ordena los símbolos por tamaño. Para objetos ELF, los tamaños de los símbolos se leen del ELF, para otros tipos de objeto, los tamaños de los símbolos se calculan como la diferencia entre el valor del símbolo y el valor del símbolo con el siguiente valor más alto. Si se usa el formato de salida "bsd" se imprime el tamaño del símbolo, en lugar del valor, y -S debe usarse para que se impriman tanto el tamaño como el valor.

Tenga en cuenta: esta opción no funciona si --undefined-only ha sido habilitado, ya

que los símbolos no def
