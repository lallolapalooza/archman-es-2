NOMBRE

c++filt - desmanglea símbolos de C++ y Java

SINOPSIS

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-s formato|--format=formato]
[--help] [--version] [símbolo...]

DESCRIPCIÓN

Los lenguajes C++ y Java proporcionan la sobrecarga de funciones, lo que significa que puedes escribir muchas funciones con el mismo nombre, siempre que cada función reciba parámetros de tipos diferentes. Para poder distinguir estas funciones de nombres similares, C++ y Java las codifican en un nombre de ensamblador de bajo nivel que identifica de forma única cada versión diferente. Este proceso se conoce como mangling. El programa c++filt [1] realiza el mapeo inverso: decodifica (desmanglea) nombres de bajo nivel a nombres de nivel de usuario para que puedan ser leídos.

Cada palabra alfanumérica (consistente en letras, dígitos, guiones bajos, dólares o puntos) vista en la entrada es un nombre mangled potencial. Si el nombre se decodifica en un nombre de C++, el nombre de C++ reemplaza al nombre de bajo nivel en la salida; de lo contrario, se emite la palabra original. De esta manera, puedes pasar un archivo fuente de ensamblador completo, que contenga nombres mangled, a través de c++filt y ver el mismo archivo fuente con los nombres desmangled.

También puedes usar c++filt para descifrar símbolos individuales pasándolos en la línea de comandos:

c++filt <símbolo>

Si no se proporcionan argumentos símbolo , c++filt lee los nombres de símbolos de la entrada estándar. Todos los resultados se imprimen en la salida estándar. La diferencia entre leer nombres de la línea de comandos y leerlos de la entrada estándar es que los argumentos de la línea de comandos se espera que sean solo nombres mangled y no se realiza ninguna comprobación para separarlos del texto circundante. Así que, por ejemplo:

c++filt -n _Z1fv

funcionará y desmangleará el nombre a "f()" mientras que:

c++filt -n _Z1fv,

no funcionará. (Nótese la coma extra al final del nombre mangled que lo hace inválido). Sin embargo, este comando sí funcionará:

echo _Z1fv, | c++filt -n

y mostrará "f(),", es decir, el nombre desmangleado seguido de una coma final. Este comportamiento se debe a que cuando los nombres se leen de la entrada estándar, se espera que puedan ser parte de un archivo fuente de ensamblador donde pueda haber caracteres extra, superfluos después de un nombre mangled. Por ejemplo:

.type   _Z1fv, @function

OPCIONES

-_
--strip-underscore
En algunos sistemas, tanto los compiladores de C como los de C++ ponen un guion bajo delante de cada nombre. Por ejemplo, el nombre de C "foo" obtiene el nombre de bajo nivel "_foo". Esta opción elimina el guion bajo inicial. Si c++filt elimina el guion bajo por defecto depende del objetivo.
-n
--no-strip-underscore
No eliminar el guion bajo inicial.
-p
--no-params
Al desmanglear el nombre de una función, no mostrar los tipos de los parámetros de la función.
-t
--types
Intentar desmanglear tipos así como nombres de funciones. Esto está deshabilitado por defecto ya que los tipos mangled normalmente solo se usan internamente en el compilador, y pueden confundirse con nombres no mangled. Por ejemplo, una función llamada "a" tratada como un nombre de tipo mangled sería desmangleada a "signed char".
-i
--no-verbose
No incluir detalles de implementación (si los hay) en la salida desmangleada.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Habilita o deshabilita un límite en la cantidad de recursión realizada al desmanglear cadenas. Dado que los formatos de mangling de nombres permiten un nivel infinito de recursión, es posible crear cadenas cuya decodificación agotará la cantidad de espacio de pila disponible en la máquina anfitriona, provocando una falla de memoria. El límite intenta prevenir esto restringiendo la recursión a 2048 niveles de anidamiento.

El valor por defecto es que este límite esté habilitado, pero deshabilitarlo puede ser necesario para desmanglear nombres verdaderamente complicados. Nótese sin embargo que si el límite de recursión está deshabilitado, es posible que se agote la pila y cualquier informe de error sobre tal evento será rechazado.

La opción -r es un sinónimo de la opción --no-recurse-limit . La opción -R es un sinónimo de la opción --recurse-limit .

-s formato
--format=formato
c++filt puede decodificar varios métodos de mangling, usados por diferentes compiladores. El argumento de esta opción selecciona qué método usa:
"auto"
Selección automática basada en el ejecutable (el método por defecto)
"gnu"
el usado por el compilador de C++ de GNU (g++)
"lucid"
el usado por el compilador Lucid (lcc)
"arm"
el especificado por el Manual de Referencia Anotada de C++
"hp"
el usado por el compilador de HP (aCC)
"edg"
el usado por el compilador EDG
"gnu-v3"
el usado por el compilador de C++ de GNU (g++) con la ABI V3.
"java"
el usado por el compilador de Java de GNU (gcj)
"gnat"
el usado por el compilador de Ada de GNU (GNAT).
--help
Imprimir un resumen de las opciones de c++filt y salir.
--version
Imprimir el número de versión de c++filt y salir.
@archivo
Leer opciones de la línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción original @archivo . Si archivo no existe o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter espacio en blanco puede incluirse en una opción rodeando la opción completa con comillas simples o dobles. Cualquier carácter (incluyendo una barra invertida) puede incluirse anteponiendo una barra invertida al carácter que se desea incluir. El archivo puede él mismo contener opciones @archivo adicionales; cualquier opción de este tipo será procesada recursivamente.

NOTAS AL PIE

1.
MS-DOS no permite "+" en los nombres de archivos, así que en MS-DOS este programa se llama CXXFILT.
