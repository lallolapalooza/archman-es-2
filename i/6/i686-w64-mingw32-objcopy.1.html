DESCRIPCIÓN

La utilidad GNU objcopy copia el contenido de un archivo objeto a otro. objcopy utiliza la biblioteca GNU BFD para leer y escribir los archivos objeto. Puede escribir el archivo objeto de destino en un formato diferente al del archivo objeto de origen. El comportamiento exacto de objcopy se controla mediante opciones de línea de comandos. Tenga en cuenta que objcopy debería poder copiar un archivo completamente enlazado entre dos formatos cualesquiera. Sin embargo, copiar un archivo objeto reubicable entre dos formatos cualesquiera puede no funcionar como se espera.

objcopy crea archivos temporales para realizar sus traducciones y los elimina después. objcopy utiliza BFD para realizar todo su trabajo de traducción; tiene acceso a todos los formatos descritos en BFD y, por lo tanto, es capaz de reconocer la mayoría de los formatos sin que se le indique explícitamente.

objcopy se puede utilizar para generar S-records usando un destino de salida srec (por ejemplo, use -O srec).

objcopy se puede utilizar para generar un archivo binario crudo usando un destino de salida binary (por ejemplo, use -O binary). Cuando objcopy genera un archivo binario crudo, esencialmente producirá una volcado de memoria del contenido del archivo objeto de entrada. Todos los símbolos y la información de reubicación se descartarán. El volcado de memoria comenzará en la dirección de carga de la sección más baja copiada en el archivo de salida.

Al generar un archivo S-record o binario crudo, puede ser útil usar -S para eliminar secciones que contienen información de depuración. En algunos casos, -R será útil para eliminar secciones que contienen información que no es necesaria para el archivo binario.

Nota---objcopy no puede cambiar el orden de los bytes (endianness) de sus archivos de entrada. Si el formato de entrada tiene un orden de bytes (algunos formatos no lo tienen), objcopy solo puede copiar las entradas en formatos de archivo que tengan el mismo orden de bytes o que no tengan orden de bytes (por ejemplo, srec). (Sin embargo, consulte la opción --reverse-bytes).

OPCIONES

archivo_entrada
archivo_salida
Los archivos de entrada y salida, respectivamente. Si no especifica archivo_salida, objcopy crea un archivo temporal y renombra destructivamente el resultado con el nombre de archivo_entrada.
-I nombre_bfd
--input-target=nombre_bfd
Considere que el formato del archivo de origen es nombre_bfd, en lugar de intentar deducirlo.
-O nombre_bfd
--output-target=nombre_bfd
Escriba el archivo de salida utilizando el formato objeto nombre_bfd.
-F nombre_bfd
--target=nombre_bfd
Use nombre_bfd como el formato objeto tanto para el archivo de entrada como para el de salida; es decir, simplemente transfiera datos de origen a destino sin traducción.
-B arquitectura_bfd
--binary-architecture=arquitectura_bfd
Útil al transformar un archivo de entrada sin arquitectura en un archivo objeto. En este caso, la arquitectura de salida se puede establecer en arquitectura_bfd. Esta opción se ignorará si el archivo de entrada tiene una arquitectura_bfd conocida. Puede acceder a estos datos binarios dentro de un programa haciendo referencia a los símbolos especiales que se crean durante el proceso de conversión. Estos símbolos se llaman _binary_archivo_objeto_start, _binary_archivo_objeto_end y _binary_archivo_objeto_size. por ejemplo:
puedes transformar un archivo de imagen en un archivo objeto y luego acceder a él en tu código usando estos símbolos.
-j patronseccion
--only-section=patronseccion
Copia solo las secciones indicadas del archivo de entrada al archivo de salida. Esta opción se puede dar varias veces. Ten en cuenta que usar esta opción de forma inadecuada puede hacer que el archivo de salida no sea utilizable. Se aceptan caracteres comodín en patronseccion.

Si el primer carácter de patronseccion es un signo de exclamación (!), las secciones que coincidan no se copiarán, incluso si un uso anterior de --only-section en la misma línea de comandos las copiara de otra manera. Por ejemplo:

--only-section=.text.* --only-section=!.text.foo

copiará todas las secciones que coincidan con '.text.*', pero no la sección '.text.foo'.

-R patronseccion
--remove-section=patronseccion
Elimina cualquier sección que coincida con patronseccion del archivo de salida. Esta opción se puede dar varias veces. Ten en cuenta que usar esta opción de forma inadecuada puede hacer que el archivo de salida no sea utilizable. Se aceptan caracteres comodín en patronseccion. El uso conjunto de las opciones -j y -R produce un comportamiento indefinido.

Si el primer carácter de patronseccion es un signo de exclamación (!), las secciones que coincidan no se eliminarán, incluso si un uso anterior de --remove-section en la misma línea de comandos las eliminara de otra manera. Por ejemplo:

--remove-section=.text.* --remove-section=!.text.foo

eliminará todas las secciones que coincidan con el patrón '.text.*', pero no eliminará la sección '.text.foo'.

--keep-section=patronseccion
Al eliminar secciones del archivo de salida, conserva las secciones que coincidan con patronseccion.
--remove-relocations=patronseccion
Elimina las reubicaciones no dinámicas del archivo de salida para cualquier sección que coincida con patronseccion. Esta opción se puede dar varias veces. Ten en cuenta que usar esta opción de forma inadecuada puede hacer que el archivo de salida no sea utilizable, y el intento de eliminar una sección de reubicación dinámica como .rela.plt de un ejecutable o biblioteca compartida con --remove-relocations=.plt no funcionará. Se aceptan caracteres comodín en patronseccion. Por ejemplo: 
--remove-relocations=.text.*

eliminará las reubicaciones de todas las secciones que coincidan con el patrón '.text.*'.

Si el primer carácter de patronseccion es un signo de exclamación (!), no se eliminarán las reubicaciones de las secciones que coincidan, incluso si un uso anterior de --remove-relocations en la misma línea de comandos causara que las reubicaciones se eliminaran de otra manera. Por ejemplo:

--remove-relocations=.text.* --remove-relocations=!.text.foo

eliminará todas las reubicaciones de las secciones que coincidan con el patrón '.text.*', pero no eliminará las reubicaciones de la sección '.text.foo'.

--strip-section-headers
Elimina la cabecera de sección. Esta opción es específica para archivos ELF. Implica --strip-all y --merge-notes.

--strip-all

-g

--strip-unneeded
Elimina todos los símbolos que no son necesarios para el procesamiento de reubicación, además de los símbolos y secciones de depuración eliminados por --strip-debug.
-K nombresimbolo

--strip-unneeded-symbol=nombresimbolo

Mantiene solo el símbolo nombresimbolo como global. Convierte todos los demás símbolos en locales del archivo, de modo que no sean visibles externamente. Esta opción se puede dar varias veces. Nota: esta opción no se puede usar junto con las opciones --globalize-symbol o --globalize-symbols.
--localize-hidden
En un objeto ELF, marca todos los símbolos con visibilidad oculta o interna como locales. Esta opción se aplica además de las opciones de localización específicas de símbolos como -L.

--localize-symbol=nombresimbolo
Convierte un símbolo global o débil llamado nombresimbolo en un símbolo local, de modo que no sea visible externamente. Esta opción se puede dar varias veces. Nota: los símbolos únicos no se convierten.
-W nombresimbolo
--weaken-symbol=nombresimbolo
Convierte el símbolo nombresimbolo en débil. Esta opción se puede dar varias veces.
--globalize-symbol=nombresimbolo
Asigna al símbolo nombresimbolo un ámbito global para que sea visible fuera del archivo en el que está definido. Esta opción se puede dar varias veces. Nota: esta opción no se puede usar junto con las opciones -G o --keep-global-symbol.
-w
--wildcard
Permite expresiones regulares en los nombresimbolo utilizados en otras opciones de línea de comandos. Los operadores de signo de interrogación (?), asterisco (*), barra invertida (\) y corchetes ([]) se pueden usar en cualquier lugar del nombre del símbolo. Si el primer carácter del nombre del símbolo es un signo de exclamación (!), el sentido del modificador se invierte para ese símbolo. Por ejemplo: 
-w -W !foo -W fo*

haría que objcopy debilitara todos los símbolos que comiencen con "fo" excepto el símbolo "foo".

-x
--discard-all
No copia símbolos no globales del archivo fuente.
-X
--discard-locals
No copia símbolos locales generados por el compilador. (Estos suelen comenzar con L o .).
-b byte
--byte=byte
Si se ha habilitado la intercalación mediante la opción --interleave, comienza el rango de bytes a conservar en el byte-ésimo byte. byte puede estar en el rango de 0 a amplitud-1, donde amplitud es el valor dado por la opción --interleave.
-i [amplitud]
--interleave[=amplitud]
Copia solo un rango de cada amplitud bytes. (Los datos de cabecera no se ven afectados). Selecciona qué byte del rango inicia la copia con la opción --byte. Selecciona el ancho del rango con la opción --interleave-width.

Esta opción es útil para crear archivos para programar ROM. Típicamente se usa con un destino de salida "srec". Ten en cuenta que objcopy se quejará si no especificas también la opción --byte.

La amplitud de intercalación predeterminada es 4, por lo que con --byte establecido en 0, objcopy copiaría el primer byte de cada cuatro bytes de la entrada a la salida.

--interleave-width=ancho
Cuando se usa con la opción --interleave, copia ancho bytes a la vez. El inicio del rango de bytes a copiar se establece con la opción --byte, y la extensión del rango se establece con la opción --interleave.

El valor predeterminado para esta opción es 1. El valor de ancho más el valor de byte establecido por la opción --byte no debe exceder la amplitud de intercalación establecida por la opción --interleave.

Esta opción se puede usar para crear imágenes para dos flashes de 16 bits intercalados en un bus de 32 bits pasando -b 0 -i 4 --interleave-width=2 y -b 2 -i 4 --interleave-width=2 a dos comandos objcopy. Si la entrada fuera '12345678', las salidas serían '1256' y '3478' respectivamente.

-p
--preserve-dates
Establece las fechas de acceso y modificación del archivo de salida para que sean las mismas que las del archivo de entrada.

Esta opción también copia la fecha almacenada en la cabecera de un archivo en formato PE, a menos que la variable de entorno SOURCE_DATE_EPOCH esté definida. Si está definida, esta variable se utilizará como la fecha almacenada en la cabecera, interpretada como el número de segundos desde la época Unix.
