IRRECORD(1) Comandos de usuario IRRECORD(1)

NOMBRE

irrecord - Herramienta de grabación de códigos IR para su uso con LIRC

SINOPSIS

irrecord [-f] [-n] [-H driver] [-d device] [file]

irrecord -a <file>

irrecord -l

irrecord --help | --version

DESCRIPCIÓN

Este programa grabará las señales de su mando a distancia y creará un archivo de configuración para lircd. Aunque se ha hecho un gran esfuerzo en este programa, a menudo no es posible reconocer automáticamente todas las características de un mando a distancia. Consulte NOTAS DE USO más abajo.

Si file no se especifica, el valor predeterminado es "irrecord.lircd.conf"

Si file ya existe y contiene una configuración válida, irrecord usará la descripción del protocolo encontrada allí y solo intentará grabar los botones.

OPCIONES

-a --analyse
Analiza un archivo de configuración raw_codes, intentando convertirlo a una configuración regular.
-u --update
Añade nuevos botones a un archivo de configuración existente. No se actualiza la información del protocolo.
-f --force
Fuerza el modo raw. Use esto si la grabación falla de otra manera. Esto crea un archivo de configuración de códigos raw que puede usarse tal cual o convertirse usando la opción -a.
-n --disable-namespace
Desactiva las comprobaciones del espacio de nombres.
-l --list-namespace
Lista los nombres de botones válidos.
-H --driver=driver
Usa el driver dado. -H help lista los drivers disponibles.
-d --device=device
Lee del dispositivo dado. Use mode2(1) --list-devices para listar los dispositivos disponibles para un driver.
-U --plugindir=directory
Carga drivers desde el directorio. Consulte CARGA DE DRIVERS.
-k --keep-root
No descarta los privilegios de root después de abrir el dispositivo. Consulte EJECUTAR COMO ROOT.
-A, --driver-options key:value[|key:value...]
Establece una o más opciones para el driver. El argumento es una lista de pares clave:valor delimitados por '|'. La clave no puede contener espacios, pero se permiten en la parte del valor. Ciertos caracteres, incluyendo '#' y ';', se usan como marcadores de comentario en el archivo de configuración y no se permiten en ningún lugar.
-D --loglevel=level
Determina la cantidad de información de registro. [level] puede ser un nivel syslog simbólico: 'error', 'warning', 'info', 'notice' o 'debug'. lirc también define tres niveles adicionales 'trace', 'trace1' y 'trace2' que dan aún más mensajes ('trace2' dando la mayor cantidad). Sin embargo, en el registro estos mensajes se marcan como 'debug'. El nivel también puede ser un entero en el rango de 3 (casi ningún mensaje) a 10.
-O, --options-file <path>
Archivo que contiene los valores predeterminados para todas las opciones. Una ruta relativa se interpreta desde el directorio actual. Consulte [ARCHIVOS] más abajo.
-h --help
Muestra este mensaje.
-v --version
Muestra la versión.

NOTAS DE USO

Las opciones principales son --driver y generalmente también --device (algunos drivers no necesitan --device). Estas podrían verificarse usando mode2(1) si irrecord tiene problemas.

Cuando se conoce el driver y el dispositivo, ahorra trabajo actualizar lirc_options.conf con los nuevos valores. irrecord usa la sección [lircd] como respaldo, así que con un lirc_options.conf adecuado se podría ejecutar irrecord sin opciones de línea de comandos.

Usar un archivo existente como plantilla a veces puede ser necesario para que irrecord funcione. Si se usa una de las plantillas genéricas, también puede proporcionar mejores tiempos. Consulte PARÁMETROS DE PROTOCOLO Y PLANTILLAS.

Si el programa falla en reconocer el protocolo del mando a distancia, podría usar la opción --force para al menos crear un archivo de configuración en modo raw.

MÁSCARAS DE REPETICIÓN

Después de grabar algunos botones con irrecord, debería verificar las máscaras de repetición. Estas son necesarias para manejar las pulsaciones repetidas de botones, que son muy comunes.

Usando el archivo de configuración, inicie lircd e irw. Manteniendo un botón presionado, debería ver algo como:<

        0000000000f40bf0 00 KEY_1 ANIMAX
        0000000000f40bf0 01 KEY_1 ANIMAX
        0000000000f40bf0 02 KEY_1 ANIMAX
        0000000000f40bf0 03 KEY_1 ANIMAX
        0000000000f40bf0 04 KEY_1 ANIMAX
        0000000000f40bf0 05 KEY_1 ANIMAX

Observe cómo el segundo campo se incrementa. Esto debe funcionar para una operación correcta.

PARÁMETROS DE PROTOCOLO Y PLANTILLAS.

irrecord realmente funciona en dos fases. En la primera, intenta identificar el protocolo usado por el mando. Aunque esto a menudo funciona bastante bien, hay ventajas en usar un archivo existente como plantilla.

Una razón para usar una plantilla es cuando irrecord falla en reconocer el protocolo al principio. En tales casos, intente encontrar una configuración existente del mismo proveedor usando algo como:

        $ irdb-get find motorola
          # muchos mandos listados...
        $ irdb-get download motorola/VIP_1200.lircd.conf  # Elija cualquiera
        $ cp VIP_1200.lircd.conf my_remote.lircd.conf
        $ irrecord my_remote.lircd.conf

Invocar irrecord de esta manera reutiliza el protocolo existente, lo que generalmente funciona (los proveedores rara vez cambian los parámetros del protocolo).

Otra razón para usar un archivo existente es obtener tiempos más exactos, importante cuando se planea también transmitir (blast). En tales casos, usar una plantilla genérica encontrada usando irdb-get find generic tiene ventajas, ya que los valores de tiempo aquí están hechos a mano a partir de las especificaciones. Para usar estos, necesita saber qué protocolo usa su mando, sin embargo.

Si la decodificación de los comandos IR no funciona de manera confiable, puede intentar modificar los valores eps y aeps en el archivo de configuración de lircd para ajustar la tolerancia de las longitudes de señal. aeps es un valor absoluto mientras que eps es un valor relativo expresado en porcentaje. Consulte lircd.conf(5)

SOLUCIÓN DE PROBLEMAS

Mandos de múltiples personalidades

Algunos mandos realmente emulan dos o más mandos. irrecord tiene problemas si se mezclan botones de diferentes mandos lógicos en la misma ejecución, en particular en la identificación inicial del protocolo. Para tales dispositivos, irrecord debe invocarse una vez para cada dispositivo lógico usando solo botones de este dispositivo durante la ejecución.

Basura no imprimible al usar el driver predeterminado

Si hay varios residuos no imprimibles en la pantalla al ejecutar irrecord usando el driver predeterminado, el protocolo rc necesita establecerse. Con un solo dispositivo, el protocolo puede establecerse e inspeccionarse usando

        sudo sh -c "echo 'lirc' > /sys/class/rc/rc0/protocol"
        cat /sys/class/rc/rc0/protocol

Perturbaciones físicas

En cuanto a las perturbaciones físicas, la fuente principal es la luz fluorescente. No debería tener ninguna luz de este tipo alrededor al usar irrecord. También es importante tener una distancia adecuada entre el mando y el dispositivo de captura, que a menudo es menor que en el uso normal típico. Sin embargo, hacer la distancia demasiado pequeña podría causar otros problemas. En un primer intento use un pie o dos.

RUTA DE CARGA DEL CONTROLADOR

Los controladores se cargan dinámicamente. Esto se hace desde una ruta tradicional de *ux separada por dos puntos (`:`), donde se busca cada componente de la ruta (primero la parte inicial, la última al final).

La ruta utilizada para esto se determina por (prioridad decreciente):

  • La opción --plugindir.
  • La entrada 'plugindir' en la sección [lircd] del archivo lirc_options.conf.
  • La variable de entorno LIRC_PLUGINDIR.
  • Un valor predeterminado codificado (/usr/lib/lirc/plugins).

EJECUTANDO COMO ROOT

En muchos casos, irrecord necesita ejecutarse como root para acceder a dispositivos no disponibles para usuarios normales. Por otro lado, ejecutarse como root crea problemas como archivos de registro propiedad de root, preocupaciones de seguridad, etc.

Para hacer frente a esto, irrecord, por defecto, renuncia a los privilegios de root después de abrir el dispositivo de entrada. Esta funcionalidad se basa en que los permisos de root se adquieren usando sudo(1), por ejemplo, usando

        $ sudo irrecord --device /dev/lirc0 --driver default
Si no se usa sudo, el mismo comportamiento podría lograrse usando la variable de entorno SUDO_USER, por ejemplo, 
        # SUDO_USER=$LOGNAME irrecord --device /dev/lirc0 --driver default
La opción --keep-root hará que irrecord mantenga los privilegios de root durante toda la ejecución.

ARCHIVOS

/etc/lirc/lirc_options.conf
El archivo de opciones que contiene los valores predeterminados para las opciones de línea de comandos en la sección [irrecord]. Para algunos valores, incluyendo debug, plugindir, driver y device, irrecord recurre a la sección [lircd] si no se encuentran en [irrecord].
-
La ubicación de este archivo se puede cambiar usando la opción de línea de comandos -O/--options-file o usando la variable de entorno LIRC_OPTIONS_PATH.
~/.cache/irrecord.log
Salida de depuración. Establecer la variable de entorno XDG_CACHE_HOME reubica este archivo a $XDG_CACHE_HOME/irrecord.log
