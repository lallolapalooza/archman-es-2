DESCRIPCIÓ

N

La función rcmd() es utilizada por el superusuario para ejecutar un comando en una máquina remota usando un esquema de autenticación basado en números de puerto privilegiados. La función rresvport() devuelve un descriptor de archivo a un socket con una dirección en el espacio de puertos privilegiados. Las funciones iruserok() y ruserok() son utilizadas por servidores para autenticar a clientes que solicitan servicio con rcmd(). Las cuatro funciones son utilizadas por el servidor rshd(8) (entre otros)

.

rcmd(

)

La función rcmd() busca el host *ahost usando gethostbyname(3), devolviendo -1 si el host no existe. De lo contrario, *ahost se establece al nombre estándar del host y se establece una conexión con un servidor que reside en el puerto de Internet conocido inport

.

Si la conexión tiene éxito, se devuelve al llamante un socket en el dominio Internet de tipo SOCK_STREAM, y se le da al comando remoto como stdin y stdout. Si fd2p no es cero, entonces se establecerá un canal auxiliar a un proceso de control, y se colocará un descriptor de archivo para él en *fd2p. El proceso de control devolverá la salida de diagnóstico del comando (unidad 2) en este canal, y también aceptará bytes en este canal como números de señales UNIX, para ser reenviados al grupo de procesos del comando. Si fd2p es 0, entonces stderr (unidad 2 del comando remoto) será el mismo que stdout y no se hará ninguna provisión para enviar señales arbitrarias al proceso remoto, aunque puede ser capaz de atraer su atención usando datos fuera de

banda.

El protocolo se describe en detalle en rshd

(8
).

rresvport(

)

La función rresvport() se usa para obtener un socket con un puerto privilegiado vinculado a él. Este socket es adecuado para su uso por rcmd() y varias otras funciones. Los puertos privilegiados son aquellos en el rango de 0 a 1023. Solo un proceso privilegiado (en Linux, un proceso que tiene la capacidad CAP_NET_BIND_SERVICE en el espacio de nombres de usuario que gobierna su espacio de nombres de red) tiene permitido vincularse a un puerto privilegiado. En la implementación de glibc, esta función restringe su búsqueda a los puertos del 512 al 1023. El argumento port es valor-resultado: el valor que proporciona a la llamada se usa como punto de partida para una bú

squeda circular del rango de puertos; en la devolución
(exitosa), contiene el número de puerto al que se vinculó.

iruserok() y

ruserok()

Las funciones iruserok() y ruserok() toman la dirección IP o el nombre de un host remoto, respectivamente, dos nombres de usuario y un indicador que indica si el nombre del usuario local es el del superusuario. Luego, si el usuario es no es el superusuario, verifica el archivo /etc/hosts.equiv. Si esa búsqueda no se realiza, o no tiene éxito, se verifica el .rhosts en el directorio de inicio del usuario local para ver si se permite la solicitud de

servicio.

Si este archivo no existe, no es un archivo regular, es propiedad de alguien que no sea el usuario o el superusuario, es escribible por alguien que no sea el propietario, o está vinculado en cualquier parte, la verificación falla automáticamente. Se devuelve cero si el nombre de la máquina está listado en el archivo hosts.equiv , o si el host y el nombre de usuario remoto se encuentran en el archivo .rhosts ; de lo contrario, iruserok() y ruserok() devuelven -1. Si el dominio local (obtenido de gethostname(2)) es el mismo que el dominio remoto, solo se necesita especificar el nombre de la

máquina.

Si se conoce la dirección IP del host remoto, iruserok() debe usarse en lugar de ruserok(), ya que no requiere confiar en e

l servidor DNS para el d
ominio del host remoto.

Variantes

*_af()

Todas las funciones descritas anteriormente funcionan con sockets IPv4 (AF_INET). Las variantes "_af" toman un argumento adicional que permite especificar la familia de direcciones del socket. Para estas funciones, el argumento af se puede especificar como AF_INET o AF_INET6. Además, rcmd_af() soporta el uso de AF_U

VALOR

DEVUELTO

La función rcmd() devuelve un descriptor de socket válido en caso de éxito. Devuelve -1 en caso de error e imprime un mensaje de diagnóstico en la salida de error

estándar.

La función rresvport() devuelve un descriptor de socket válido y vinculado en caso de éxito. En caso de fallo, devuelve -1 y establece errno para indicar el error. El código de error EAGAIN se sobrecarga para significar: "Todos los puertos de red están en

uso".
