NOMBRE

irkerhook - script de gancho de repositorio que emite notificaciones de irker

SINOPSIS

irkerhook.py [-n] [-V] [[--variable=valor...]] [[id-commit...]]

DESCRIPCIÓN

irkerhook.py es un script de Python destinado a ser llamado desde el gancho post-commit de un repositorio de control de versiones. Su trabajo es recopilar información sobre el commit que activó el gancho (y posiblemente preferencias establecidas por el propietario del repositorio) y enviar esa información a una instancia de irkerd para su reenvío a varios canales de anuncio.

La invocación y el comportamiento adecuados de irkerhook.py varían dependiendo de qué VCS (sistema de control de versiones) lo esté llamando. Hay cuatro lugares diferentes desde los cuales puede extraer información:

1. Llamadas a utilidades VCS.
2. En VCS como git que admiten variables de configuración configurables por el usuario, variables con el prefijo "irker.".
3. En otros VCS, un archivo de configuración, "irker.conf", en el directorio interno del repositorio.
4. Argumentos de línea de comandos de la forma --variable=valor.

Las siguientes variables son generales para todos los VCS compatibles:

project

El nombre del proyecto. Debería ser un identificador relativamente corto; generalmente aparecerá al principio de una notificación.

repo

El nombre del directorio raíz del repositorio. Si no se especifica, por defecto es una copia en minúsculas del nombre del proyecto.

channels

Una URL de canal de IRC, o una lista separada por comas de las mismas, que identifica los canales a los que se deben enviar las notificaciones. Si no se especifica, el valor predeterminado es el canal #commits de freenode.

server

El host en el que se espera que resida el demonio irker que reenvía notificaciones. Por defecto es "localhost".

email

Si se establece, usa el correo electrónico para la comunicación en lugar de TCP o UDP. El valor se utiliza como dirección de correo electrónico de destino.

tcp

Si es "true", usa TCP para la comunicación; si es "false", usa UDP. Por defecto es "false".

urlprefix

Prefijo de URL de changeset para su repositorio. Cuando se agrega el ID del commit a esto, debería apuntar a un CGI que mostrará el commit a través de cgit, gitweb o algo similar. Los valores predeterminados probablemente funcionarán si tiene una configuración típica de gitweb/cgit.

Si el valor de esta variable es "None", se suprimirá la generación del campo URL en las notificaciones de commit. Otros valores mágicos son "cgit", "gitweb" y "viewcvs", que se expanden a plantillas de URL que normalmente funcionarán con esos sistemas.

Las galletas mágicas "%(host)s" y %(repo)s" pueden aparecer en esta URL. La primera se expande al FQDN del host en el que se está ejecutando irkerhook.py; la segunda se expande al valor de la variable "repo".

tinyifier

Plantilla de URL que apunta a un servicio para comprimir URL para que ocupen menos espacio en la línea de notificación. Si el valor de esta variable es "None", no se intentará ninguna compresión.

color

Si es "mIRC", resalta los campos de notificación con códigos de color mIRC. Si es "ANSI", resalta los campos de notificación con secuencias de escape de color ANSI. Por defecto es "none" (sin colores). Los códigos ANSI son compatibles con Chatzilla, irssi, ircle y BitchX; solo los códigos mIRC son reconocidos en mIRC, XChat, KVirc, Konversation o weechat.

Nota: si activa esto y las notificaciones dejan de aparecer en su canal, deberá desactivar el filtro de color de IRC en ese canal. Para hacer esto, necesitará privilegios de op; emita el comando "/mode <canal> -c" con <canal> reemplazado por el nombre de su canal. Es posible que primero deba emitir el comando "/msg chanserv set <canal> MLOCK +nt-slk".

maxchannels

Se interpreta como un entero. Si no es cero, limita el número de canales que el gancho interpretará de la variable "channels".

Esta variable no se puede establecer a través de variables de configuración de VCS o irker.conf; solo se puede establecer con un argumento de línea de comandos. Por lo tanto, en un sitio de forja en el que los propietarios de repositorios no tienen permitido modificar sus scripts post-commit, un administrador del sitio puede establecerlo para evitar el spam masivo por parte de propietarios de proyectos maliciosos. Sin embargo, establecerlo en un valor menor que 2 probablemente no sería prudente.

cialike

Si no está vacío y no es "None" (el valor predeterminado), esto emula el comportamiento antiguo de CIA de omitir largas listas de archivos en favor de un resumen del tipo (N archivos en M directorios). El valor debe ser numérico, dando un valor umbral para la longitud de la lista de archivos en caracteres.

template

Establece la plantilla utilizada para generar mensajes de notificación. Solo disponible en VCS con variables de configuración; actualmente esto significa git o hg. Todos los campos básicos de commit y extractor, incluidos los modificadores de color, están disponibles como sustituciones de %().

irkerhook.py se ejecutará tanto en python 2 como en python 3, pero aún no es compatible con repositorios mercurial en python 3.

git

En git, la forma normal de invocar este gancho (desde dentro del gancho de actualización) le pasa un nombre de ref seguido de una lista de commits. Dado que git rev-list normalmente lista del más reciente al más antiguo, querrá usar --reverse para que las notificaciones se omitan en orden cronológico. En un script de actualización normal, la invocación debería verse así:

refname=$1
old=$2
new=$3
irkerhook.py --refname=${refname} $(git rev-list --reverse ${old}..${new})

excepto que necesitará una ruta absoluta para irkerhook.py.

Para fines de prueba y compatibilidad con versiones anteriores, si invoca irkerhook.py sin argumentos (como en un gancho post-commit) se comportará como si hubiera sido llamado así:

irkerhook.py --refname=refs/heads/master HEAD

Sin embargo, esto no dará el resultado correcto cuando empuje a una rama que no sea la predeterminada de un repositorio bare.

Una forma típica de instalar este gancho es en realidad en el gancho post-receive ya que obtiene todos los detalles necesarios y no abortará el push en caso de error. Utilice el siguiente script:

#!/bin/sh
echo "enviando notificación IRC"
while read old new refname; do
    irkerhook --refname=${refname} $(git rev-list --reverse ${old}..${new})
done

Las preferencias se pueden establecer en el archivo de configuración del repo en una sección [irker]. Aquí hay un ejemplo de cómo puede verse:

[irker]
    project = gpsd
    color = ANSI
    channels = irc://chat.freenode.net/gpsd,irc://chat.freenode.net/commits

No debe establecer la variable "repository" (se calculará un equivalente). No se hace ningún intento de interpretar un archivo irker.conf.

El valor predeterminado de la variable "project" es el nombre base del directorio del repositorio. El valor predeterminado de la variable "urlprefix" es "cgit".

Hay una variable específica de git, "revformat", que controla el formato del identificador de commit en una notificación. Puede tener los siguientes valores:

raw

ID hexadecimal completo del commit

short

primeros 12 caracteres del ID hexadecimal

describe

describe relativamente la última etiqueta, recurriendo a short

El valor predeterminado es 'describe'.

Subversion

En Subversion, irkerhook.py acepta una opción --repository con valor (la ruta absoluta del repositorio Subversion) y un argumento de commit (el nivel de revisión numérico del commit). Los valores predeterminados son el directorio actual y HEAD, respectivamente.

Sin embargo, tenga en cuenta que no puede establecer un valor predeterminado para el argumento del repositorio dentro de un gancho post-commit de Subversion; esto se debe a una limitación de Subversion, que es que obtener el directorio actual no es confiable dentro de estos ganchos. En su lugar, los valores deben ser los dos argumentos que Subversion pasa a ese gancho como argumentos. Por lo tanto, una invocación típica en el script post-commit se verá así:

REPO=$1
REV=$2
irkerhook.py --repository=$REPO $REV

Otras configuraciones de --variable=valor también se pueden proporcionar en la línea de comandos, y anularán cualquier configuración en un archivo irker.conf.

NAME

irkerhook.py

hook script for irkerd(8)

SYNOPSIS

irkerhook.py [OPTION]...

DESCRIPTION

This script is a hook that can be used with version control systems (like Git or Mercurial) to send commit notifications to the irkerd(8) daemon.

It determines the version control system it is running under by examining the environment (specifically, the presence of certain environment variables, or the location of the repository relative to the hook script).

Git

When used with Git, this hook script should be placed in the "hooks/" directory of a Git repository. It should be named "post-commit" or "post-receive".

The script determines settings in the following order:

  1. Command-line arguments of the form variable=value.
  2. The file .irker.conf in the repository root directory.
  3. The file irker.conf in the repository root directory.
  4. The global configuration file ~/.irker.conf.
  5. Environment variables (prefixed with IRKER_).

The project variable is set to the basename of the repository by default. The default value of the urlprefix variable is "viewcvs".

If an irker.conf file exists in the repository root directory (not the checkout directory but where internals such as the "format" file live) the hook will interpret variable settings from it. Here is an example of what such a file might look like:

# irkerhook variable settings for the irker project
project = irker
channels  = irc://chat.freenode/irker,irc://chat.freenode/commits
tcp = false

Don't set the "repository" or "commit" variables in this file; that would have unhappy results.

There are no Subversion-specific variables.

Mercurial

Under Mercurial, irkerhook.py can be invoked in two ways: either as a Python hook (preferred) or as a script.

To call it as a Python hook, add the collowing to the "commit" or "incoming" hook declaration in your Mercurial repository:

[hooks]
	incoming.irker = python:/path/to/irkerhook.py:hg_hook

When called as a script, the hook accepts a --repository option with value (the absolute pathname of the Mercurial repository) and can take a commit argument (the Mercurial hash ID of the commit or a reference to it). The default for the repository argument is the current directory. The default commit argument is '-1', designating the current tip commit.

As for git, in both cases all variables may be set in the repo hgrc file in an [irker] section. Command-line variable=value arguments are accepted but not required for script invocation. No attempt is made to interpret an irker.conf file.

The default value of the "project" variable is the basename of the repository directory. The default value of the "urlprefix" variable is the value of the "web.baseurl" config value, if it exists.

Filtering

It is possible to filter commits before sending them to irkerd.

You have to specify the filtercmd option, which will be the command irkerhook.py will run. This command should accept one arguments, which is a JSON representation of commit and extractor metadata (including the channels variable). The command should emit to standard output a JSON representation of (possibly altered) metadata.

Below is an example filter:

#!/usr/bin/env python3
# This is a trivial example of a metadata filter.
# All it does is change the name of the commit's author.
# 
import sys, json
metadata = json.loads(sys.argv[1])
metadata['author'] = "The Great and Powerful Oz"
print json.dumps(metadata)
# end

Standard error is available to the hook for progress and error messages.

OPTIONS

irkerhook.py takes the following options:

-n

Suppress transmission to a daemon. Instead, dump the generated JSON request to standard output. Useful for debugging.

-V

Write the program version to stdout and terminate.
