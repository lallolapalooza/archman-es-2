DESCRIPCIÓ

N

irkerd es un cliente IRC de solo escritura especializado, destinado a ser utilizado para enviar mensajes de notificación a canales IRC. El caso de uso previsto cuando fue diseñado era la difusión de notificaciones desde ganchos de confirmación (commit hooks) en sistemas de control de

versiones.

La principal ventaja de retransmitir a través de este demonio en lugar de envíos individuales por script desde aplicaciones es que puede mantener el estado de la conexión para múltiples canales, en lugar de producir un molesto spam de entrada/salida del canal en cada

mensaje.

irkerd es un servidor de sockets que escucha paquetes UDP o TCP en el puerto 6659 para líneas de solicitud textuales que contienen objetos JSON y terminadas por un salto de línea. Cada objeto JSON debe tener dos miembros: "to" que especifica un destino o lista de destinos, y "privmsg" que especifica el texto del mensaje.

Ejemplos: 
{"to":"irc://chat.freenode.net/git-ciabot", "privmsg":"¡Hola, mundo!"}
{"to":["irc://chat.freenode.net/#git-ciabot","irc://chat.freenode.net/#gpsd"],"privmsg"
:"Prueba multicanal"} {"to":"irc://chat.hypothetical.net:6668/git-ciabot", "privmsg":"¡Hola, mundo!"} {"to":"ircs://chat.hypothetical.net/git-private?key=topse
cret", "privmsg":"Prueba de canal con clave"} {"to":"ircs://:topsecret@chat.example.net/git-private", "privmsg":"Prueba de servidor protegido por contraseña"}

Si la parte del canal de la URL no tiene uno de los caracteres de prefijo “#”, “&” o “+”, se le antepondrá un “#” antes de enviar - a menos que la parte del canal tenga el sufijo ",isnick" (el cual se elimina incondicionalmente)

.

La parte del host de la URL puede tener un sufijo de número de puerto separado por dos puntos, como se muestra en el tercer ejemplo; de lo contrario, irkerd envía mensajes de texto plano al puerto IRC predeterminado 6667 de cada servidor, y mensajes SSL/TLS al

6697.

La contraseña para servidores protegidos por contraseña se puede establecer usando la definición habitual “[{username}:{password}@]{host}:{port}” en el RFC 3986, como se muestra en el quinto ejemplo. Los nombres de usuario de URL no vacíos anulan el nombre de usuario predeterminado

“irker”.

Cuando la URL “to” usa el esquema “ircs” (como se muestra en el cuarto y quinto ejemplos), la conexión al servidor IRC se realiza mediante SSL/TLS (a diferencia de una conexión de texto plano con el esquema “irc”). Para conectarse mediante SSL/TLS con Python 2.x, necesita declarar explícitamente el archivo de autoridad de certificación utilizado para verificar los certificados del servidor. Por ejemplo, “-c /etc/ssl/certs/ca-certificates.crt”. En Python 3.2 y posteriores, aún puede establecer esta opción para declarar un archivo CA personalizado, pero irkerd; si no lo establece, irkerd usará el archivo predeterminado de OpenSSL (usando el método de Python “ssl.SSLContext.set_default_verify_paths”). En Python 3.2 y posteriores, se usa “ssl.match_hostname” para asegurar que el certificado del servidor pertenece al host previsto, así como que está firmado por una CA de

confianza.

Para unirse a canales protegidos por contraseña (modo +k), la parte del canal de la URL puede ir seguida de una cadena de consulta que indique la clave del canal, de la forma “?secret” o “?key=secret”, donde “secret” es la clave del

canal.

Un mensaje vacío es legal y hará que irkerd se una o mantenga una conexión con los canales

de destino sin emitir realmente un mensaje. Esto puede ser útil para anunciar que una inst
ancia está activa y en funcionamiento, o para unirse a un canal para registrar su tráfico.

OPCIONE

S

irkerd toma las siguientes

opciones:

-

d
Toma un valor siguiente, estableciendo el nivel de depuración a partir de él; los valores posibles son 'critical', 'error', 'warning', 'info', 'debug'. Esta opción generalmente solo será de interés para los desarrolladores, ya que los registros están diseñados para ayudar a rastrear el estado interno de irkerd. Estos registros de rastreo son independientes de los registros de tráfico controlados por “-l”.

El registro se realizará en la salida de error estándar (si irkerd se está ejecutando en primer plano) o en “/dev/syslog” con la facilidad "daemon" (si irkerd se está ejecutando en segundo plano). La condición de segundo pl

ano de irkerd se determina comparando el id de grupo de proceso con el grupo de proceso asociado al terminal adjunto a stdout (con no coincidencias para procesos en segundo plano). Asumimos que no está ejecutando irkerd en
Windows u otro sistema operativo que no soporte “os.getpgrp” o “tcgetpgrp”. Asumimos que si stdout está adjunto a un TTY asociado con el mismo grupo de proceso que irkerd, usted pretende registrar en stderr y no en syslog.

-

e
Toma un nombre de archivo siguiente en formato pem y lo usa para autenticarse en el servidor IRC. Debe estar conectándose al servidor IRC a través de SSL para que esto funcione correctamente. Esto es comúnmente conocido como “CertFP.
”

LIMITACIONE

S

Las solicitudes vía UDP optimizan para la menor latencia y carga de red evitando el tiempo de configuración de la conexión TCP; el costo es que la entrega no es fiable ante la pérdida de

paquetes.

Una instancia de irkerd con un socket de solicitud accesible públicamente podría complicar el bloqueo del spam de IRC al facilitar a los spammers enviar mientras ocultan sus direcciones IP; la mejor manera de desplegarlo, entonces, es en lugares como sitios de alojamiento de proyectos donde el socket de irkerd pueda ser visible desde el código de los ganchos de confirmación pero no expuesto al mundo exterior. Es siempre una buena idea poblar su cortafuegos con listas de bloqueo de direcciones IP conocidas por generar

spam.

La ausencia de cualquier opción para establecer el puerto del servicio es deliberada. Si cree que necesita hacer eso, tiene un problema que se resuelve mejor en su

cortafuegos.

IRC tiene un límite de longitud de mensaje de 510 bytes; genere los valores de su atributo privmsg con el cuidado

apropiado.

IRC ignora cualquier texto después de un salto de línea incrustado. Tenga en cuenta que irkerd convertirá las cadenas de carga útil con saltos de línea incrustados en múltiples envíos de IRC para evitar que se descarten datos de

mensajes.

Debido a un error en el análisis de URL de Python, las URLs de IRC con tanto una # como una parte de clave pueden fallar inesperadamente. La solución temporal es eliminar la

#. n>
