IRXEVENT(1) Comandos de usuario IRXEVENT(1)

NOMBRE

irxevent - emisor de eventos X por infrarrojos

SINOPSIS

irxevent [opción]... [archivo de configuración]

DESCRIPCIÓN

Irxevent es un programa para enviar clics de botones y pulsaciones de teclas a aplicaciones X activadas por un control remoto controlado por LIRC. Puedes controlar tu reproductor de CD/MP3 favorito, tu programa sintonizador de TV o cualquier otra aplicación X que responda a la entrada del teclado o del ratón. Si quieres, puedes enviar emacs ^X^S desde tu sillón.

Irxevent es un complemento de irexec(1) e irpty(1).

OPCIONES

-d --daemon
Se bifurca y se ejecuta en segundo plano.
-h --help
Muestra el resumen de uso.
-V --version
Muestra la versión.

ARCHIVOS

Irxevent funciona con el mismo archivo de configuración que irexec e irpty (~/.config/lircrc). Para un archivo lircrc de ejemplo completo, consulta examples/lircrc.

Parte de tu .lircrc podría verse así:

begin
        prog = irxevent
        button = VIDEO_UP
        config = Key SHIFT-KP_Add CurrentWindow
end
begin
        prog = irxevent
        button = VIDEO_DOWN
        config = Key SHIFT-KP_Subtract CurrentWindow
end
begin
        prog = irxevent
        button = STOP
        config = Key ctrl-c CurrentWindow
end
begin
        prog = irxevent
        button = 0
        config = Key f xawtv
        config = Key f xawtv
end
begin
        prog = irxevent
        button = POWER
        config = Key q xawtv
end
begin
        prog = irxevent
        button = CH_DOWN
        config = Button 1 329 92 kscd
end
begin
        prog = irxevent
        button = UP
        config = Button 1 110 80 GQmpeg
end
begin
        prog = irxevent
        button = DOWN
        config = Button 1 130 80 GQmpeg
end

Dicho de forma sencilla, las líneas de config= pueden parecerse a esto:

config = Key [shift-][ctrl-][alt-]<tecla> [Focus] <nombre de ventana>
        | WindowID <id> | CurrentWindow | RootWindow
config = Button <botón> <x> <y> [Focus] <nombre de ventana> | WindowID <id>
        | CurrentWindow | RootWindow
config = xy_Key <x> <y> [shift-][ctrl-][alt-]<tecla> [Focus]
        <nombre de ventana> | WindowID id | CurrentWindow | RootWindow

Algunos ejemplos más:

config = Key Up xawtv
config = Key Down xawtv
config = Button 1 50 110 xclickme
config = Key q xawtv
config = Key ctrl-c mpg123
config = Key shift-Page_Up rxvt

En BNF, esto se parece a:

LINE    = "config =" <KEY|BUTTON|XYKEY> <TARGET> |
          "config =" <KEY|BUTTON|XYKEY> "Focus" <TARGET>
XYKEY   = "xy_Key" <posición x> <posición y> <MOD><KEYSPEC>
KEY     = "Key" <MOD><KEYSPEC>
MOD     = ["shift-"]["numlock-"]["ctrl-"]["alt-"]["meta-"]
          ["numlock-"]["mod3-"]["mod4-"]["mod5-"]["altgr-"]["scrlock-"]
KEYSPEC = Nombre de tecla | "KeySym:"KeySym | "KeyCode:"KeyCode
BUTTON  = "Button" <1..5> <posición x> <posición y>
TARGET  = Nombre de ventana | "WindowID" id | "CurrentWindow" | "RootWindow"

Nombre de tecla:

es el símbolo de tecla que se declara en X windows. Por ejemplo, "Up" se refiere a la flecha del cursor apuntando hacia arriba. "KP_Add" es el signo más en el teclado numérico. Simplemente echa un vistazo a irxevent.keys (en el directorio de documentación) si no estás seguro del nombre de un símbolo.
KeySym:
número devuelto por XStringToKeysym(3x).
KeyCode:
número devuelto por XKeysymToKeycode(3x).
Nombre de ventana:
pueden ser los primeros caracteres del nombre de la ventana mostrados por el gestor de ventanas o el nombre que se muestra debajo del icono. Algunos programas usan el nombre mostrado por el gestor de ventanas para mostrar mucha información de estado pero no cambian el nombre del icono (como xawtv). Otros añaden información al nombre de la ventana ("GQmpeg - kill_windooz.mp3"). Si ni el nombre de la ventana ni el nombre del icono coinciden con el Nombre de ventana dado, se consultará la información de XClassHint(3x).
CurrentWindow:
se refiere a la ventana activa devuelta por XGetInputFocus(3x). La mayoría de las veces es la ventana que tiene el puntero del ratón.
RootWindow:
se refiere a la ventana *raíz* devuelta por RootWindow(3x). Puede que necesites esto para enviar eventos al gestor de ventanas.
WindowID id:
se refiere a la ventana con el identificador de ventana id. id debe ser un número decimal. Es útil cuando irxevent no puede encontrar la ventana deseada por otros medios.
Focus:
enviará el evento especificado a la ventana dada solo si actualmente tiene el foco de entrada. Esto, por supuesto, no tiene mucho sentido cuando se combina con CurrentWindow.

SOLUCIÓN DE PROBLEMAS

Si tienes problemas para encontrar las coordenadas para un clic de botón, puedes probar xev -id <id de ventana>. El id de ventana se puede encontrar usando xwininfo.

Hay programas que no aceptan ningún evento X sintético por defecto porque pueden causar problemas de seguridad. Actualmente, xterm y xemacs son conocidos por ignorar los eventos simulados por irxevent.

Sin embargo, puedes hacer que xterm acepte eventos externos activando "Allow SendEvents" en las "Opciones Principales" (mantén presionado el botón Ctrl y presiona el botón izquierdo del ratón dentro de la ventana de xterm). También puedes colocar esta línea en tu archivo .Xresources para cambiar esto permanentemente:

XTerm.vt100.allowSendEvents: true

Otra posibilidad es iniciar xterm de esta manera:

xterm -xrm "XTerm.vt100.allowSendEvents: true"

xemacs aceptará eventos si configuras una variable incorporada. Lo siguiente se tomó de la ayuda en línea:

`x-allow-sendevents' es una variable booleana incorporada.

Valor: t

Documentación:

*Non-nil significa permitir eventos sintéticos. Nil significa que se ignoran.

Precaución: permitir que emacs procese SendEvents abre un gran agujero de seguridad.

Para permitir eventos, debes evaluar este código lisp (presiona Meta-x e introduce la siguiente expresión):


(setq x-allow-sendevents t)

Colocar esta línea en tu archivo .xemacs-options debería tener el mismo resultado.

Si tienes problemas para enviar eventos, por favor envíame un correo electrónico.
