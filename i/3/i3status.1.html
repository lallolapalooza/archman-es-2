I3STATUS(1) Manual de i3 I3STATUS(1)

NOMBRE

i3status - Genera una línea de estado para i3bar, dzen2, xmobar o lemonbar

SINOPSIS

i3status [-c archivo_de_configuracion] [-h] [-v] [--run-once]

OPCIONES

-c --config

Especifica una ruta alternativa para el archivo de configuración. Por defecto, i3status busca archivos de configuración en el siguiente orden:
1.~/.config/i3status/config (o $XDG_CONFIG_HOME/i3status/config si está definido)
2./etc/xdg/i3status/config (o $XDG_CONFIG_DIRS/i3status/config si está definido)
3.~/.i3status.conf
4./etc/i3status.conf

-h --help

Imprime la versión y una sintaxis mínima.

-v --version

Imprime la versión y cualquier configuración de compilación.

--run-once

Ejecuta una sola vez en lugar de entrar en un bucle.

DESCRIPCIÓN

i3status es un pequeño programa para generar una barra de estado para i3bar, dzen2, xmobar, lemonbar u otros programas similares. Está diseñado para ser muy eficiente al emitir un número muy pequeño de llamadas al sistema, ya que generalmente se desea actualizar dicha barra de estado cada segundo. Esto asegura que incluso bajo alta carga, tu barra de estado se actualice correctamente. Además, ahorra un poco de energía al no acaparar tanto tu CPU como lo haría la ejecución de la cantidad correspondiente de comandos de shell.

CONFIGURACIÓN

La idea básica de i3status es que puedes especificar qué "módulos" se deben usar (la directiva de orden). Luego puedes configurar cada módulo con su propia sección. Para cada módulo, puedes especificar el formato de salida. Consulta a continuación una referencia completa.

Ejemplo de configuración.

general {
        output_format = "dzen2"
        colors = true
        interval = 5
}
order += "ipv6"
order += "disk /"
order += "run_watch DHCP"
order += "run_watch VPNC"
order += "path_exists VPN"
order += "wireless wlan0"
order += "ethernet eth0"
order += "battery 0"
order += "cpu_temperature 0"
order += "memory"
order += "load"
order += "tztime local"
order += "tztime berlin"
wireless wlan0 {
        format_up = "W: (%quality at %essid, %bitrate) %ip"
        format_down = "W: down"
}
ethernet eth0 {
        format_up = "E: %ip (%speed)"
        format_down = "E: down"
}
battery 0 {
        format = "%status %percentage %remaining %emptytime"
        format_down = "No battery"
        status_chr = "⚡ CHR"
        status_bat = "🔋 BAT"
        status_unk = "? UNK"
        status_full = "☻ FULL"
        status_idle = "☻ IDLE"
        path = "/sys/class/power_supply/BAT%d/uevent"
        low_threshold = 10
}
run_watch DHCP {
        pidfile = "/var/run/dhclient*.pid"
}
run_watch VPNC {
        # file containing the PID of a vpnc process
        pidfile = "/var/run/vpnc/pid"
}
path_exists VPN {
        # path exists when a VPN tunnel launched by nmcli/nm-applet is active
        path = "/proc/sys/net/ipv4/conf/tun0"
}
tztime local {
        format = "%Y-%m-%d %H:%M:%S"
        hide_if_equals_localtime = true
}
tztime berlin {
        format = "%Y-%m-%d %H:%M:%S %Z"
        timezone = "Europe/Berlin"
}
load {
        format = "%5min"
}
cpu_temperature 0 {
        format = "T: %degrees °C"
        path = "/sys/devices/platform/coretemp.0/temp1_input"
}
memory {
        format = "%used"
        threshold_degraded = "10%"
        format_degraded = "MEMORY: %free"
}
disk "/" {
        format = "%free"
}
read_file uptime {
        path = "/proc/uptime"
}

General

La directiva `colors` deshabilitará todos los colores si la estableces en `false`. También puedes especificar los colores que se usarán para mostrar valores "buenos", "degradados" o "malos" usando las directivas `color_good`, `color_degraded` o `color_bad`, respectivamente. Estas directivas solo se usan si el soporte de color no está deshabilitado por la directiva `colors`. El formato de entrada para los valores de color es el triplete hexadecimal RGB canónico (sin separadores entre los colores), prefijado por un carácter de almohadilla ("#").

Ejemplo de configuración:

color_good = "#00FF00"

De manera similar, puedes usar la directiva `color_separator` para especificar el color que se usará para pintar la barra separadora. El separador siempre se muestra en color, incluso cuando los colores están deshabilitados por la directiva `colors`. Esta opción no tiene efecto cuando `output_format` se establece en `i3bar` o `none`.

La directiva `interval` especifica el tiempo en segundos que i3status dormirá antes de imprimir la siguiente línea de estado.

Usando `output_format` puedes elegir qué cadenas de formato usará i3status en su salida. Actualmente disponibles están:

i3bar

i3bar viene con i3 y proporciona una barra de espacios de trabajo que hace lo correcto en situaciones multimonitor. También viene con soporte de bandeja y puede mostrar la salida de i3status. Este tipo de salida utiliza JSON para pasar tanta información meta como sea posible a i3bar (como colores, qué bloques se pueden acortar y de qué manera, etc.).

dzen2

Dzen es un programa de propósito general para mensajería, notificaciones y menús para X11. Fue diseñado para ser programable en cualquier idioma e integrarse bien con gestores de ventanas como dwm, wmii y xmonad, aunque funcionará con cualquier gestor de ventanas.

xmobar

xmobar es una barra de estado minimalista basada en texto. Fue diseñada para funcionar con el gestor de ventanas xmonad.

lemonbar

lemonbar es una barra ligera basada completamente en XCB. Tiene soporte completo de UTF-8 y cumple con EWMH.

term

Usa secuencias de escape ANSI para producir una salida de terminal lo más cercana posible a las salidas gráficas. Esto hace que depurar tu archivo de configuración sea un poco más fácil porque la salida de terminal de i3status se vuelve mucho más legible, pero solo debe usarse para esas vistas rápidas, ya que solo admitirá características de salida muy básicas (por ejemplo, solo obtienes 3 bits de profundidad de color).

none

No utiliza ningún código de color. Separa los valores con el símbolo de barra vertical por defecto. Esto debe usarse con i3bar y se puede usar para scripts personalizados.

También es posible usar las directivas `color_good`, `color_degraded`, `color_bad` para definir colores específicos por módulo. Si alguna de estas directivas está definida en una sección de módulo, su valor anulará el valor definido en la sección general solo para ese módulo.

Si no te gustan los separadores verticales entre los módulos que i3status/i3bar usa por defecto, puedes usar la directiva `separator` para configurar cómo se separan los módulos. También puedes deshabilitar el separador por defecto por completo estableciéndolo a una cadena vacía. Es posible que luego definas la separación como parte de la cadena de formato de un módulo. Esta es tu única opción al usar el formato de salida `i3bar`, ya que el separador es dibujado por i3bar directamente de lo contrario. Para los otros formatos de salida, la cadena no vacía proporcionada se encerrará automáticamente con los bits de color necesarios si el soporte de color está habilitado.

i3bar admite marcado Pango, lo que permite que tus cadenas de formato especifiquen fuente, color, tamaño, etc., estableciendo la directiva `markup` en "pango". Ten en cuenta que los caracteres ampersand ("&"), menor que ("<"), mayor que (">"), comilla simple ("'") y comilla doble (""") deben reemplazarse con "&amp;", "&lt;", "&gt;", "&apos;" y "&quot;" respectivamente. Esto se hace automáticamente para el contenido generado (por ejemplo, ESSID inalámbrico, hora).

Ejemplo de configuración:

general {
    output_format = "xmobar"
    separator = "  "
}
order += "load"
order += "disk /"
load {
    format = "[ load: %1min, %5min, %15min ]"
}
disk "/" {
    format = "%avail"
}

Memori

a

Obtiene el uso de la memoria del sistema en un sistema Linux desde /proc/meminfo. Otros sistemas no están soportados

actualmente.

Como marcadores de formato, están disponibles total, used, free, available y shared. Estos imprimirán valores legibles para humanos. También es posible anteponer percentage_ a los marcadores para obtener un valor en

porcentaje.

Es posible definir un threshold_degraded y un threshold_critical para colorear la salida de la barra de estado en color_degraded o color_bad, si la memoria disponible cae por debajo del umbral dado. Los valores posibles del umbral pueden ser cualquier entero, con un sufijo de símbolo IEC (T, G, M, K). Alternativamente, el entero puede llevar un sufijo de signo de porcentaje, lo que entonces se evalúa en relación con la memoria

total.

Si se proporciona el parámetro format_degraded y se aplica el umbral crítico o el degradado, se usará format_degraded como cadena de formato. Actúa de manera equivalente a

format.

También es posible definir la unidad para los distintos marcadores de formato. Como /proc/meminfo devuelve la memoria en kB, se convertirán a la unidad dada. Si no se proporciona unidad o se usa la opción auto, la conversión seleccionará la unidad máxima

posible.

Como el marcador de formato convertido será un número decimal, el número de decimales se puede configurar mediante la opción decimals. Si no se proporciona dicha opción, el marcador de formato convertido tendrá un

decimal.

Como el meminfo de Linux no expone la memoria total en uso, existen múltiples métodos para distinguir la memoria realmente

utilizada.

Ejemplo memory_used_method: memavailable ("memoria total" - "MemAvailable", coincide con el comando

free)

Ejemplo memory_used_method: classical ("memoria total" - "free" - "buffers" - "cache", coincide con gnome system

monitor)

OPCIONES UNIVERSALES DE

MÓDULOS

Al usar el formato de salida i3bar, hay algunas opciones adicionales que se pueden usar con todos los módulos para personalizar su

apariencia:

alig

n
La política de alineación a usar cuando no se alcanza el ancho mínimo (ver abajo). Ya sea center (predeterminado), right o
left.

min_widt

h
El ancho mínimo (en píxeles) que debe ocupar el módulo. Si el módulo ocupa menos espacio que el tamaño especificado, el bloque se rellenará a la izquierda y/o a la derecha, según la política de alineación definida. Esto es útil cuando quieres evitar que toda la línea de estado se desplace cuando los valores ocupan más o menos espacio entre cada iteración. La opción también puede ser una cadena. En este caso, el ancho del texto dado determina el ancho mínimo del bloque. Esto es útil cuando quieres establecer un ancho mínimo razonable sin importar qué fuente estés usando y en qué tamaño en particular. Ten en cuenta que un número entre comillas seguirá tratándose como un
número.

separato

r
Un valor booleano que especifica si se debe dibujar una línea separadora después de este bloque. El valor predeterminado es true, lo que significa que se dibujará la línea separadora. Ten en cuenta que si deshabilitas la línea separadora, aún habrá un espacio después del bloque, a menos que también uses separator_block_width
.

separator_block_widt

h
La cantidad de píxeles que se dejan en blanco después del bloque. En el centro de este espacio se dibujará un símbolo separador, a menos que separator esté deshabilitado. Por eso el ancho especificado debe dejar suficiente espacio para el símbolo
separador.

Ejemplo de config

uración: 
disk "/" {
    format = "%avail
" align = "left" min_wi
dth = 100 separator = false
separator_block_width = 1 }

¿QUÉ PASA CON LA FRECUENCIA DE LA

CPU?

Mientras hablamos de cosas específicas, por favor entiende esta sección como una explicación general de por qué tu información favorita no está incluida en

i3status.

LHablemos específicamente de la frecuencia de la CPU. Muchas personas no entienden con precisión cómo funciona el escalado de frecuencia. El gobernador de frecuencia de la CPU generalmente recomendado ("ondemand") cambia la frecuencia de la CPU con mucha más frecuencia de lo que i3status podría mostrarlo. Por lo tanto, el número mostrado a menudo es incorrecto y tampoco te dice nada

útil.

En general, i3status quiere mostrar cosas que mirarías ocasionalmente de todos modos, como la fecha/hora actual, si estás conectado a una red WiFi o no, y si tienes suficiente espacio en disco para esa descarga de 4.3

GiB.

Sin embargo, si necesitas mirar algún tipo de información más de una vez cada tanto, probablement

e sea mejor que uses un script para eso, que aparezca. Después de todo, el propósito de las comp
utadoras no es abrumarte con tareas aburridas adicionales como verificar un número repetidamente.

#!/bin/sh
