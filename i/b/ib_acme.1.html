NOMBRE

ib_acme - utilidad de prueba y configuración para el IB ACM

SINOPSIS

ib_acme [-f formato_dir] [-s dir_origen] -d dir_destino [-v] [-c] [-e] [-P] [-S dir_svc] [-C repeticiones]
ib_acme [-A [archivo_dir]] [-O [archivo_opt]] [-D dir_destino] [-V]

DESCRIPCIÓN

ib_acme proporciona asistencia para configurar y probar el servicio ibacm. El primer uso del servicio probará que ibacm se está ejecutando y operando correctamente. El segundo modelo de uso creará automáticamente archivos de dirección y configuración para el servicio ibacm.

OPCIONES

-f formato_dir
Especifica el formato de los parámetros dir_origen y dir_destino. Los formatos de dirección válidos son: 'i' dirección IP, 'n' nombre de host, 'l' LID, 'g' GID y 'u' no especificado. Si se omite la opción -f, se asume un formato de dirección no especificado. ib_acme utilizará getaddrinfo u otros mecanismos para determinar el formato que utiliza la dirección.
-s dir_origen
Especifica la dirección de origen local de la ruta a resolver. La dirección de origen puede ser una dirección IP, un nombre de red del sistema o LID, según lo indique la opción formato_dir.
-d dir_destino
Especifica la dirección de destino de la ruta a resolver. La dirección de destino puede ser una dirección IP, un nombre de red del sistema o LID, según lo indique la opción formato_dir.
-v
Indica que la información de ruta resuelta debe ser verificada con el SA de IB activo. El uso de la opción -v proporciona una comprobación de sentido común de que la información de ruta resuelta es utilizable dada la configuración actual del clúster.
-c
Instruye al servicio ACM para que devuelva solo la información que reside actualmente en su caché local.
-e [N]
Muestra un (N = 1, 2, ...) o todos los puntos finales (N = 0 o no presente).
-P [opc]
Consulta datos de rendimiento del servicio de destino. Las opciones válidas son: "col" para mostrar datos combinados en formato de columna, "N" (N = 1, 2, ...) para mostrar datos para un punto final específico N, "all" para mostrar datos para todos los puntos finales y "s" para mostrar datos para un punto final específico con la dirección dada por la opción -s.
-S dir_svc
Nombre de host, dirección IPv4 o socket de dominio Unix del servicio ACM, predeterminado: /run/ibacm.sock
-C repeticiones
número de repeticiones para realizar la resolución. Se utiliza para medir el rendimiento de las búsquedas en caché de ACM. Predeterminado a 1.
-A [archivo_dir]
Con esta opción, la utilidad ib_acme genera automáticamente el archivo de configuración de direcciones ibacm_addr.cfg. El archivo generado se construye utilizando el nombre de host del sistema.
-O [archivo_opt]
Con esta opción, la utilidad ib_acme genera automáticamente el archivo de configuración de opciones ibacm_opts.cfg. Actualmente, el archivo generado se crea utilizando información estática.
-D dir_destino
Especifica el directorio de destino para los archivos de salida.
-V
Habilita la salida detallada. Cuando se combina con las opciones -A u -O, ib_acme mostrará detalles adicionales, como la información de dirección generada guardada en el archivo ibacm_addr.cfg.

NOTAS

La utilidad ib_acme realiza dos funciones principales. Con las opciones -A y -O, genera automáticamente archivos de configuración de direcciones u opciones. Los archivos generados son de texto y pueden ser editados. Estas opciones están destinadas a proporcionar una forma sencilla de configurar información de direcciones y opciones en todos los nodos de un clúster.

La otra función de la utilidad ib_acme es probar el servicio ibacm, incluyendo ayudar a verificar que el servicio es utilizable dada la configuración actual del clúster. La utilidad ib_acme puede resolver direcciones IP, nombres de red o LIDs de IB en un registro de ruta. Luego puede comparar ese registro de ruta con uno obtenido por el SA. Cuando se utiliza para probar el servicio ibacm, la utilidad ib_acme tiene el efecto secundario de cargar las cachés de ibacm.

Se pueden especificar múltiples destinos numéricos agregando corchetes [] al final de un nombre base de destino o dirección. Los usuarios pueden especificar una lista de rangos numéricos dentro de los corchetes utilizando el siguiente ejemplo como guía: nodo[1-3,5,7-8]. Esto resultará en la prueba de nodo1, nodo2, nodo3, nodo5, nodo7 y nodo8.
