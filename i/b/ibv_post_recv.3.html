IBV_POST_RECV(3) Manual del programador de Libibverbs IBV_POST_RECV(3)

NOMBRE

ibv_post_recv - publicar una lista de solicitudes de trabajo (WRs) en una cola de recepción

SINOPSIS

#include <infiniband/verbs.h>

int ibv_post_recv(struct ibv_qp *qp, struct ibv_recv_wr *wr,
                  struct ibv_recv_wr **bad_wr);

DESCRIPCIÓN

ibv_post_recv() publica la lista enlazada de solicitudes de trabajo (WRs) que comienza con wr en la cola de recepción del par de colas qp. Deja de procesar las WRs de esta lista en el primer error (que pueda detectarse inmediatamente mientras se publican las solicitudes) y devuelve esta WR fallida a través de bad_wr.

El argumento wr es una estructura ibv_recv_wr, tal como se define en <infiniband/verbs.h>.

struct ibv_recv_wr {
uint64_t                wr_id;     /* ID de WR definido por el usuario */
struct ibv_recv_wr     *next;      /* Puntero a la siguiente WR en la lista, NULL si es la última WR */
struct ibv_sge         *sg_list;   /* Puntero al array s/g */
int                     num_sge;   /* Tamaño del array s/g */
};
struct ibv_sge {
uint64_t                addr;      /* Dirección de inicio del buffer de memoria local */
uint32_t                length;    /* Longitud del buffer */
uint32_t                lkey;      /* Clave de la Región de Memoria local */
};

VALOR DE RETORNO

ibv_post_recv() devuelve 0 si tiene éxito, o el valor de errno en caso de fallo (que indica el motivo del fallo).

NOTAS

Los buffers utilizados por una WR solo pueden reutilizarse de forma segura después de que la solicitud WR se haya ejecutado por completo y se haya recuperado una finalización de trabajo de la cola de finalización (CQ) correspondiente.

Si el QP qp está asociado a una cola de recepción compartida (SRQ), debe usar la función ibv_post_srq_recv() y no ibv_post_recv(), ya que la cola de recepción propia del QP no se utilizará.

Si se está publicando una WR en un QP UD, la Cabecera de Enrutamiento Global (GRH) del mensaje entrante se colocará en los primeros 40 bytes del buffer(s) en la lista de dispersión. Si no hay GRH en el mensaje entrante, los primeros bytes no estarán definidos. Esto significa que en todos los casos, los datos reales del mensaje entrante comenzarán con un desplazamiento de 40 bytes dentro del buffer(s) en la lista de dispersión.
