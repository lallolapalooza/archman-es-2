IBD2SDI(1) MySQL Database System IBD2SDI(1)

NOMBRE

ibd2sdi - utilidad de MySQL para extraer información del diccionario serializada (SDI) de un tablespace de InnoDB

SINOPSIS

ibd2sdi [opciones] nombre_archivo1 [nombre_archivo2 nombre_archivo3 ...]

DESCRIPCIÓN

ibd2sdi es una utilidad para extraer información del diccionario serializada (SDI) de archivos de tablespace de InnoDB. Los datos SDI están presentes en todos los archivos de tablespace persistentes de InnoDB.

ibd2sdi se puede ejecutar en archivos de tablespace por tabla (archivos *.ibd), archivos de tablespace generales (archivos *.ibd), archivos de tablespace del sistema (archivos ibdata*) y el tablespace del diccionario de datos (mysql.ibd). No es compatible con tablespaces temporales ni tablespaces de deshacer (undo).

ibd2sdi se puede usar en tiempo de ejecución o mientras el servidor está desconectado. Durante las operaciones DDL, las operaciones ROLLBACK y las operaciones de purga de registros de deshacer (undo log) relacionadas con SDI, puede haber un breve intervalo de tiempo durante el cual ibd2sdi no pueda leer los datos SDI almacenados en el tablespace.

ibd2sdi realiza una lectura no confirmada (uncommitted read) de SDI del tablespace especificado. No se accede a los registros de rehacer (redo logs) ni a los registros de deshacer (undo logs).

Invoque la utilidad ibd2sdi de la siguiente manera:

ibd2sdi [opciones] nombre_archivo1 [nombre_archivo2 nombre_archivo3 ...]

ibd2sdi admite tablespaces de múltiples archivos como el tablespace del sistema InnoDB, pero no se puede ejecutar en más de un tablespace a la vez. Para tablespaces de múltiples archivos, especifique cada archivo:

ibd2sdi ibdata1 ibdata2

Los archivos de un tablespace de múltiples archivos deben especificarse en orden de número de página ascendente. Si dos archivos sucesivos tienen el mismo ID de espacio, el archivo posterior debe comenzar con el último número de página del archivo anterior + 1.

ibd2sdi genera SDI (que contiene los campos id, type y data) en formato JSON. Opciones de ibd2sdi

ibd2sdi admite las siguientes opciones:

Formato de línea de comandos --id=#

Debido a la forma en que InnoDB maneja los metadatos de los valores predeterminados, un valor predeterminado puede estar presente y no vacío en la salida de ibd2sdi para una columna de tabla determinada incluso si no está definido usando DEFAULT. Considere las dos tablas creadas usando las siguientes sentencias en la base de datos denominada

i: 
CREATE TABLE t1 (c VARCHAR(16) NO
T NULL); CREATE TABLE t2 (c VARCHA
R(16) NOT NULL DEFAULT "Sakila");

Usando ibd2sdi, podemos ver que el default_value para la columna c no está vacío y de hecho está rellenado hasta la longitud en ambas tablas,

así: 
$> ibd2sdi ../data/i/t1.ibd  | grep -m1 '\"default_value\"' | cut -b34- | sed -e s/,//
"AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\nAAAAAAAAAAA="
$> ibd2sdi ../data/i/t2.ibd  | grep -m1 '\"default_value\"' | cut -b34- | sed -e s/,//
"BlNha2lsYQAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\nAAAAAAAAAAA
=
"

El examen de la salida de ibd2sdi puede ser más fácil usando una utilidad compatible con JSON como jq[1], como se muestra

aquí: 
$> ibd2sdi ../data/i/t1.ibd  | jq '.[1]["object"]["dd_object"]["columns"][0]["default_value"]'
"AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\nAAAAAAAAAAA="
$> ibd2sdi ../data/i/t2.ibd  | jq '.[1]["object"]["dd_object"]["columns"][0]["default_value"]'
"BlNha2lsYQAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\nAAAAAAAAAAA
=
"
