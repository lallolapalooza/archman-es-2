IBV_ALLOC_PARENT_DOMAIN(3) Manual del programador de Libibverbs IBV_ALLOC_PARENT_DOMAIN(3)

NOMBRE

ibv_alloc_parent_domain(), ibv_dealloc_pd() - asignar y liberar el objeto de dominio padre

SINOPSIS

#include <infiniband/verbs.h>

struct ibv_pd *ibv_alloc_parent_domain(struct ibv_context *context, struct ibv_parent_domain_init_attr *attr);

DESCRIPCIÓN

ibv_alloc_parent_domain() asigna un objeto de dominio padre para el contexto del dispositivo RDMA context.

El objeto de dominio padre extiende el dominio de protección normal con objetos adicionales, como un dominio de hilos.

Un dominio padre es completamente intercambiable con el struct ibv_pd utilizado para crearlo, y puede ser utilizado como argumento de entrada para cualquier función que acepte un struct ibv_pd.

El comportamiento de cada verbo puede ser diferente si al verbo se le pasa un dominio padre struct ibv_pd que contiene un puntero struct ibv_td. Por ejemplo, el verbo puede optar por compartir recursos entre objetos que utilizan el mismo dominio de hilos. El comportamiento exacto depende del proveedor.

El argumento attr especifica lo siguiente:

enum ibv_parent_domain_init_attr_mask {
IBV_PARENT_DOMAIN_INIT_ATTR_ALLOCATORS = 1 << 0,
IBV_PARENT_DOMAIN_INIT_ATTR_PD_CONTEXT = 1 << 1,
};
struct ibv_parent_domain_init_attr {
struct ibv_pd *pd; /* referencia a un dominio de protección, no puede ser NULL */
struct ibv_td *td; /* referencia a un dominio de hilos, o NULL */
uint32_t comp_mask;
void *(*alloc)(struct ibv_pd *pd, void *pd_context, size_t size,
               size_t alignment, uint64_t resource_type);
void (*free)(struct ibv_pd *pd, void *pd_context, void *ptr,
             uint64_t resource_type);
void *pd_context;
};

ibv_dealloc_pd() liberará el dominio padre tal como se expone como un pd ibv_pd. Todos los recursos creados con el dominio padre deben ser destruidos antes de liberar el dominio padre.

ARGUMENTOS

pd Referencia al dominio de protección que utiliza este dominio padre.

td Un dominio de hilos opcional que utiliza el dominio padre.

comp_mask Máscara de bits de campos opcionales en la estructura ibv_parent_domain_init_attr.

alloc Función de asignación de memoria personalizada para este dominio padre. Las asignaciones de memoria del proveedor utilizarán esta función para asignar la memoria necesaria. La función de asignación recibe el dominio padre pd y el contexto especificado por el usuario pd_context. Además, la devolución de llamada recibe el tamaño y la alineación del búfer solicitado, así como un tipo de recurso específico del proveedor, que se deriva del enum rdma_driver_id (32 bits superiores) y un código de recurso específico del proveedor. La función devuelve el puntero al búfer asignado, o NULL para indicar un error. También puede devolver IBV_ALLOCATOR_USE_DEFAULT pidiendo al llamante que asigne el búfer utilizando el asignador predeterminado.

La devolución de llamada se asegura de que el búfer asignado se inicialice con ceros. También es responsabilidad de la devolución de llamada asegurarse de que la memoria no pueda ser COWed (copiada al escribir), por ejemplo, utilizando madvise(MADV_DONTFORK) o asignando memoria compartida anónima.

free Devolución de llamada para liberar los búferes de memoria que fueron asignados utilizando una asignación() exitosa.

pd_context Un puntero para datos adicionales específicos del usuario que se asociarán con este dominio padre. El puntero se devuelve a las funciones del asignador personalizadas.

VALOR DE RETORNO

ibv_alloc_parent_domain() devuelve un puntero al objeto ibv_pd asignado, o NULL si la solicitud falla (y establece errno para indicar el motivo del fallo).

VER TAMBIÉN

ibv_alloc_parent_domain(3), ibv_dealloc_pd(3), ibv_alloc_pd(3), ibv_alloc_td(3)
