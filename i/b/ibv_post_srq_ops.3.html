IBV_POST_SRQ_OPS(3) Manual del programador de Libibverbs IBV_POST_SRQ_OPS(3)

NOMBRE

ibv_post_srq_ops - realiza manipulaciones de configuración en una cola de recepción compartida (SRQ) especial

SINOPSIS

#include <infiniband/verbs.h>

int ibv_post_srq_ops(struct ibv_srq *srq, struct ibv_ops_wr *wr,
                     struct ibv_ops_wr **bad_wr);

DESCRIPCIÓN

La función ibv_post_srq_ops() realiza una serie de manipulaciones de configuración de descarga en tipos especiales de SRQ srq. Actualmente se utiliza para configurar SRQ de coincidencia de etiquetas. La serie de operaciones de configuración se define mediante listas enlazadas de elementos de struct ibv_ops_wr que comienzan en wr.

struct ibv_ops_wr {
uint64_t                wr_id;   /* ID de WR definido por el usuario */
/* Puntero al siguiente WR en la lista, NULL si es el último WR */
struct ibv_ops_wr      *next;
enum ibv_ops_wr_opcode  opcode;  /* De enum ibv_ops_wr_opcode */
int                     flags;   /* De enum ibv_ops_flags */
struct {
/* Número de mensajes inesperados
 * manejados por SW */
uint32_t unexpected_cnt;
/* Parámetro de entrada para el opcode DEL
 * y parámetro de salida para el opcode ADD */
uint32_t handle;
struct {
uint64_t                recv_wr_id;   /* ID de WR definido por el usuario para TM_RECV */
struct ibv_sge         *sg_list; /* Puntero a la matriz s/g */
int                     num_sge; /* Tamaño de la matriz s/g */
uint64_t                tag;
uint64_t                mask;    /* El mensaje entrante se considera coincidente si
                                    TMH.tag & entry.mask == entry.tag */
} add;
} tm;
};

La primera parte de struct ibv_ops_wr conserva la noción de ibv_send_wr. Opcode define la operación a realizar. Actualmente, los valores admitidos son IBV_WR_TAG_ADD, IBV_WR_TAG_DEL e IBV_WR_TAG_SYNC. Consulte a continuación para obtener una descripción detallada.

Para permitir la entrega de datos confiable, TM SRQ mantiene un primitivo de sincronización especial de bajo nivel: la sincronización de fase. El manejo de mensajes del lado de recepción comprende dos actividades concurrentes: la publicación de búferes etiquetados por SW y la recepción de mensajes entrantes por HW. Este proceso se considera coherente solo si todos los mensajes inesperados recibidos por HW se procesan completamente en SW. Para pasar al hardware el número de mensajes inesperados procesados, se debe usar el campo unexpected_cnt y se debe establecer el flag IBV_OPS_TM_SYNC.

Para solicitar WC para operaciones de lista de etiquetas, se deben pasar los flags IBV_OPS_SIGNALED. En este caso, se generará un WC en el CQ de TM SRQ, y el wr_id proporcionado identificará el WC.

El opcode IBV_WR_TAG_ADD se utiliza para agregar una entrada de etiqueta a la lista de coincidencia de etiquetas. La entrada de etiqueta consta de una lista SGE, etiqueta y máscara (parámetros de coincidencia), un wr_id opaco especificado por el usuario (pasado a través del campo recv_wr_id) y se identifica de forma única por un handle (devuelto por el controlador). El tamaño de la lista de coincidencia de etiquetas está limitado por max_num_tags. El tamaño de la lista SGE está limitado por max_sge.

El opcode IBV_WR_TAG_DEL elimina una entrada de etiqueta agregada previamente. El campo handle debe establecerse en el valor devuelto por la operación IBV_WR_TAG_ADD realizada anteriormente. La operación puede fallar debido al consumo concurrente de etiquetas; en este caso, se devolverá el estado IBV_WC_TM_ERR en el WC.

El opcode IBV_WR_TAG_SYNC se puede utilizar si no se requieren cambios en la lista de coincidencia, solo para actualizar el contador de mensajes inesperados.

El flag IBV_WC_TM_SYNC_REQ devuelto en el WC de operación de lista indica que se requiere la sincronización del contador. Este flag también puede ser devuelto por el WC de recepción inesperada, solicitando una operación IBV_WR_TAG_SYNC para mantener la consistencia de TM.

VALOR DE RETORNO

ibv_post_srq_ops() devuelve 0 si tiene éxito, o el valor de errno en caso de error (que indica el motivo del fallo).
