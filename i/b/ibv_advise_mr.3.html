IBV_ADVISE_MR(3) Manual del Programador de Libibverbs IBV_ADVISE_MR(3)

NOMBRE

ibv_advise_mr - Proporciona consejos o indicaciones al kernel sobre un rango de direcciones que pertenece a una región de memoria (MR).

SINOPSIS

#include <infiniband/verbs.h>
int ibv_advise_mr(struct ibv_pd *pd,
          enum ibv_advise_mr_advice advice,
          uint32_t flags,
          struct ibv_sge *sg_list,
          uint32_t num_sge)

DESCRIPCIÓN

ibv_advise_mr() proporciona consejos o indicaciones al kernel sobre un rango de direcciones que pertenece a una región de memoria (MR). Las aplicaciones que conocen los patrones de acceso futuros pueden utilizar esta llamada de procedimiento para aprovechar este conocimiento y mejorar el rendimiento del sistema o de la aplicación.

Valores de consejo convencionales

IBV_ADVISE_MR_ADVICE_PREFETCH
Precarga un rango de una MR de paginación bajo demanda. Hace que las páginas estén presentes con permiso de solo lectura antes de que se realice la E/S real. Esto proporcionaría una forma de reducir la latencia al solapar la carga de páginas con el tiempo de cómputo o la E/S a otros rangos.
IBV_ADVISE_MR_ADVICE_PREFETCH_WRITE
Igual que IBV_ADVISE_MR_ADVICE_PREFETCH pero con permiso de lectura y escritura para la memoria cargada.
IBV_ADVISE_MR_ADVICE_PREFETCH_NO_FAULT
Precarga un rango de una MR de paginación bajo demanda sin generar fallos. Esto permite que las páginas presentadas en la CPU se presenten al dispositivo.

ARGUMENTOS

pd
El dominio de protección (PD) asociado con la MR.
advice
El valor de consejo solicitado (como se indica arriba).
flags
Describe las propiedades de la operación de consejo. Valores de consejo convencionales IBV_ADVISE_MR_FLAG_FLUSH : Solicita que sea una operación sincronizada. Retorna al llamador después de que la operación se haya completado.
sg_list
Puntero a la lista s/g. Al usar el valor de consejo IBV_ADVISE_OP_PREFETCH, todas las lkeys de todos los elementos de dispersión-agregación (SGE) deben estar asociadas con MRs de ODP (MRs que fueron registradas con IBV_ACCESS_ON_DEMAND).
num_sge
Número de elementos en la lista s/g.

VALOR DE RETORNO

ibv_advise_mr() retorna 0 cuando la llamada fue exitosa, o el valor de errno en caso de fallo (que indica la razón del fallo).

EOPNOTSUPP
libibverbs o el controlador del proveedor no soporta la llamada ibv_advise_mr() (ENOSYS puede ser devuelto a veces por versiones antiguas de libibverbs).
ENOTSUP
La operación de consejo no es compatible.
EFAULT
En uno de los siguientes casos: o Cuando el rango solicitado está fuera de los límites de la MR, o cuando partes de él no forman parte del espacio de direcciones del proceso. o Una de las lkeys proporcionadas en la lista de dispersión-agregación es inválida o tiene un permiso de escritura incorrecto.
EINVAL
En uno de los siguientes casos: o El PD es inválido. o Los flags son inválidos. o La dirección solicitada no pertenece a una MR, sino a una MW o algo similar.
EPERM
En uno de los siguientes casos: o Referencia a una lkey válida fuera del ámbito de seguridad del llamador. o El consejo es IBV_ADVISE_MR_ADVICE_PREFETCH_WRITE pero la MR especificada en la lista de dispersión-agregación no está registrada con acceso de escritura.
ENOENT
Las lkeys proporcionadas no son consistentes con las de la MR.
ENOMEM
No hay suficiente memoria. # NOTAS

Una aplicación puede precargar cualquier rango de direcciones dentro de una MR ODP al usar el consejo IBV_ADVISE_MR_ADVICE_PREFETCH o IBV_ADVISE_MR_ADVICE_PREFETCH_WRITE. Semánticamente, esta operación es "best-effort". Esto significa que el kernel no garantiza que las páginas subyacentes se actualicen en el HCA o que las páginas precargadas permanezcan residentes.

Al usar el consejo IBV_ADVISE_MR_ADVICE_PREFETCH o IBV_ADVISE_MR_ADVICE_PREFETCH_WRITE, la operación se realizará en las siguientes etapas: o Cargar las páginas del usuario en memoria (las páginas no se fijan). o Obtener el mapeo DMA de estas páginas de usuario. o Publicar las traducciones de página subyacentes al HCA.

Si se especifica IBV_ADVISE_MR_FLAG_FLUSH, se garantiza que las páginas subyacentes se actualicen en el HCA antes de retornar SUCCESS. De lo contrario, el controlador puede optar por posponer la publicación de las nuevas traducciones al HCA. Al realizar una operación de acceso RDMA local, se recomienda usar el flag IBV_ADVISE_MR_FLAG_FLUSH con uno de los consejos de precarga para aumentar la probabilidad de que las traducciones de página sean válidas en el HCA y evitar fallos de página futuros.
