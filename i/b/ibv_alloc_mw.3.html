IBV_ALLOC_MW(3) Manual del programador de Libibverbs IBV_ALLOC_MW(3)

NOMBRE

ibv_alloc_mw, ibv_dealloc_mw - asignar o liberar una ventana de memoria (MW)

SINOPSIS

#include <infiniband/verbs.h>

struct ibv_mw *ibv_alloc_mw(struct ibv_pd *pd,
                            enum ibv_mw_type type);

int ibv_dealloc_mw(struct ibv_mw *mw);

DESCRIPCIÓN

ibv_alloc_mw() asigna una ventana de memoria (MW) asociada al dominio de protección pd. El tipo de la MW (1 o 2A/2B) es type.

La MW se crea sin vincular. Para que sea útil, la MW debe vincularse, ya sea a través de ibv_bind_mw (tipo 1) o de un WR especial (tipo 2). Una vez vinculada, la ventana de memoria permite el acceso RDMA (remoto) a una subconjunto de la MR a la que se vinculó, hasta que sea invalidada por: el verbo ibv_bind_mw con longitud cero para el tipo 1, el opcode WR IBV_WR_LOCAL_INV/IBV_WR_SEND_WITH_INV para el tipo 2, o la desasignación.

ibv_dealloc_mw() Desvincula en caso de que se vinculara previamente y libera la MW mw.

VALOR DE RETORNO

ibv_alloc_mw() devuelve un puntero a la MW asignada, o NULL si la solicitud falla. El campo de clave remota (R_Key) rkey es utilizado por procesos remotos para realizar operaciones Atómicas y RDMA. Esta clave cambiará durante las operaciones de vinculación. El proceso remoto coloca este rkey como el campo rkey de la estructura ibv_send_wr pasada a la función ibv_post_send.

ibv_dealloc_mw() devuelve 0 si tiene éxito, o el valor de errno en caso de fallo (que indica el motivo del fallo).

NOTAS

ibv_dereg_mr() falla si alguna ventana de memoria todavía está vinculada a esta MR.
