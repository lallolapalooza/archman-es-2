IBV_ALLOC_DM(3) Manual del programador de Libibverbs IBV_ALLOC_DM(3)

NOMBRE

ibv_alloc_dm, ibv_free_dm, ibv_memcpy_to/from_dm - asignar o liberar un búfer de memoria del dispositivo (DM) y realizar una copia de memoria hacia o desde él

SINOPSIS

#include <infiniband/verbs.h>

struct ibv_dm *ibv_alloc_dm(struct ibv_context *context,
                            struct ibv_alloc_dm_attr *attr);

int ibv_free_dm(struct ibv_dm *dm);

DESCRIPCIÓN

ibv_alloc_dm() asigna un búfer de memoria del dispositivo para el contexto del dispositivo RDMA context. El argumento attr es un puntero a una estructura ibv_alloc_dm_attr, según se define en <infiniband/verbs.h>.

ibv_free_dm() libera el búfer de memoria del dispositivo dm.

struct ibv_alloc_dm_attr {
size_t length;			/* Longitud del búfer de memoria del dispositivo deseado */
uint32_t log_align_req;		/* Logaritmo en base 2 del requisito de alineación de dirección */
uint32_t comp_mask;		/* Máscara de compatibilidad que define qué de las siguientes variables son válidas */
};
Puede ser necesaria la alineación de direcciones en casos donde se realizarán operaciones atómicas de RDMA utilizando la memoria del dispositivo.
En tales casos, el usuario puede especificar la alineación de la dirección de inicio de la memoria del dispositivo utilizando el parámetro log_align_req
en la estructura de atributos de asignación.

Acceso a una memoria de dispositivo asignada

Para realizar un acceso de escritura/lectura a una memoria de dispositivo asignada, un usuario puede utilizar las llamadas ibv_memcpy_to_dm
y ibv_memcpy_from_dm respectivamente.

int ibv_memcpy_to_dm(struct ibv_dm *dm, uint64_t dm_offset,
                     void *host_addr, size_t length);

int ibv_memcpy_from_dm(void *host_addr, struct ibv_dm *dm,
			    uint64_t dm_offset, size_t length);

dm_offest
es el desplazamiento en bytes desde el inicio del búfer de memoria del dispositivo asignado para acceder.

host_addr
es la dirección del búfer de memoria del host para acceder.

length
es la longitud de la copia en bytes.

Registro de memoria de dispositivo

El usuario puede registrar la memoria del dispositivo asignada como una región de memoria y usar la lkey/rkey dentro de sge al publicar una solicitud de recepción o envío de trabajo. Este tipo de MR se define como basado en cero y, por lo tanto, cualquier referencia a él (específicamente en sge)
se realiza con un desplazamiento en bytes desde el inicio de la región.

Este tipo de registro se realiza utilizando ibv_reg_dm_mr.

struct ibv_mr* ibv_reg_dm_mr(struct ibv_pd *pd, struct ibv_dm *dm, uint64_t dm_offset,
                  size_t length, uint32_t access);

pd
el pd asociado para este registro.

dm
el dm asociado para este registro.

dm_offest
es el desplazamiento en bytes desde el inicio del búfer de memoria del dispositivo asignado para registrar.

length
la longitud de la memoria a registrar.

access
banderas de acceso de mr (Usar enum ibv_access_flags). Para este tipo de registro, el usuario debe establecer la bandera IBV_ACCESS_ZERO_BASED
.

VALOR DE RETORNO

ibv_alloc_dm() devuelve un puntero a una estructura ibv_dm o NULL si la solicitud falla. El dm de salida contiene el manejador que el usuario podría usar para importar esta memoria del dispositivo.

ibv_free_dm() devuelve 0 si tiene éxito, o el valor de errno en caso de fallo (que indica la razón del fallo).

ibv_reg_dm_mr() devuelve un puntero a una estructura ibv_mr si tiene éxito o NULL si la solicitud falla.

ibv_memcpy_to_dm()/ibv_memcpy_from_dm() devuelve 0 si tiene éxito o la razón del fallo en caso de fallo.

NOTAS

ibv_alloc_dm() puede fallar si al dispositivo no le queda más memoria de dispositivo libre, siendo la cantidad máxima de memoria asignada proporcionada por el atributo max_dm_size en la estructura ibv_device_attr_ex. ibv_free_dm() puede fallar si algún otro recurso (como una MR) todavía está asociado con el DM que se está liberando.
