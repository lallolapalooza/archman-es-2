NOMBRE

ibv_wr_abort, ibv_wr_complete, ibv_wr_start - Gestionar regiones permitidas para publicar trabajo

ibv_wr_atomic_cmp_swp, ibv_wr_atomic_fetch_add - Publicar solicitudes de trabajo de operación atómica remota

ibv_wr_bind_mw, ibv_wr_local_inv - Publicar solicitudes de trabajo para ventanas de memoria

ibv_wr_rdma_read, ibv_wr_rdma_write, ibv_wr_rdma_write_imm, ibv_wr_flush - Publicar solicitudes de trabajo RDMA

ibv_wr_send, ibv_wr_send_imm, ibv_wr_send_inv - Publicar solicitudes de trabajo de envío

ibv_wr_send_tso - Publicar solicitudes de trabajo de descarga de segmentación

ibv_wr_set_inline_data, ibv_wr_set_inline_data_list - Adjuntar datos en línea a la última solicitud de trabajo

ibv_wr_set_sge, ibv_wr_set_sge_list - Adjuntar datos a la última solicitud de trabajo

ibv_wr_set_ud_addr - Adjuntar información de direccionamiento UD a la última solicitud de trabajo

ibv_wr_set_xrc_srqn - Adjuntar un SRQN XRC a la última solicitud de trabajo

DESCRIPCIÓN

La API de solicitudes de trabajo (ibv_wr_*) permite publicar eficientemente trabajo en una cola de envío utilizando llamadas a funciones en lugar del esquema basado en struct ibv_post_send(). Este enfoque está diseñado para minimizar la ramificación y el bloqueo de la CPU durante el proceso de publicación.

Esta API está destinada a ser utilizada para acceder a funcionalidad adicional más allá de la proporcionada por ibv_post_send().

Los WR de lotes de ibv_post_send() y los WR de esta API de lotes pueden entrelazarse juntos solo si no se publican dentro de la región crítica de cada uno. (Una región crítica en esta API formada por ibv_wr_start() y ibv_wr_complete()/ibv_wr_abort())

USO

Para utilizar estas APIs, la QP debe crearse utilizando ibv_create_qp_ex() que permite establecer IBV_QP_INIT_ATTR_SEND_OPS_FLAGS en comp_mask. Los send_ops_flags deben establecerse al OR de los tipos de solicitud de trabajo que se publicarán en la QP.

Si la QP no admite todos los tipos de solicitud de trabajo solicitados, la creación de la QP fallará.

La publicación de solicitudes de trabajo a la QP se realiza dentro de la región crítica formada por ibv_wr_start() y ibv_wr_complete()/ibv_wr_abort() (ver CONCURRENCIA abajo).

Cada solicitud de trabajo se crea llamando a una función constructora de WR (ver la columna constructora de WR en la tabla) para comenzar a crear la solicitud de trabajo, seguida de funciones establecedoras permitidas/requeridas descritas a continuación.

La combinación de constructora de WR y establecedora se puede llamar múltiples veces para publicar eficientemente múltiples solicitudes de trabajo dentro de una sola región crítica.

Cada constructora de WR utilizará el miembro wr_id de struct ibv_qp_ex para establecer el valor que se devolverá en la finalización. Algunas operaciones también utilizarán el miembro wr_flags para influir en la operación (ver Banderas abajo). Estos valores deben establecerse antes de invocar la función constructora de WR.

Por ejemplo, un envío simple se podría formar de la siguiente manera:

qpx->wr_id = 1;
ibv_wr_send(qpx);
ibv_wr_set_sge(qpx, lkey, &data, sizeof(data));

La sección SOLICITUDES DE TRABAJO describe los diversos constructores y establecedores de WR en detalle.

La publicación de trabajo se completa llamando a ibv_wr_complete() o ibv_wr_abort(). Ningún trabajo se ejecuta en la cola hasta que ibv_wr_complete() devuelva éxito. ibv_wr_abort() descartará todo el trabajo preparado desde ibv_wr_start().

SOLICITUDES DE TRABAJO

Muchas de las operaciones coinciden con los opcodes disponibles para ibv_post_send(). Cada operación tiene una función constructora de WR, una lista de establecedores permitidos y un bit de bandera para solicitar la operación con send_ops_flags en struct ibv_qp_init_attr_ex (ver el EJEMPLO abajo).

Operación Constructor de WR Tipo de QP Soportado Establecedores
ATOMIC_CMP_AND_SWP ibv_wr_atomic_cmp_swp() RC, XRC_SEND DATA, QP
ATOMIC_FETCH_AND_ADD ibv_wr_atomic_fetch_add() RC, XRC_SEND DATA, QP
BIND_MW ibv_wr_bind_mw() UC, RC, XRC_SEND NONE
LOCAL_INV ibv_wr_local_inv() UC, RC, XRC_SEND NONE
RDMA_READ ibv_wr_rdma_read() RC, XRC_SEND DATA, QP
RDMA_WRITE ibv_wr_rdma_write() UC, RC, XRC_SEND DATA, QP
FLUSH ibv_wr_flush() RC, RD, XRC_SEND DATA, QP
RDMA_WRITE_WITH_IMM ibv_wr_rdma_write_imm() UC, RC, XRC_SEND DATA, QP
SEND ibv_wr_send() UD, UC, RC, XRC_SEND, RAW_PACKET DATA, QP
SEND_WITH_IMM ibv_wr_send_imm() UD, UC, RC, SRC SEND DATA, QP
SEND_WITH_INV ibv_wr_send_inv() UC, RC, XRC_SEND DATA, QP
TSO ibv_wr_send_tso() UD, RAW_PACKET DATA, QP

Operaciones Atómicas

Las operaciones atómicas solo son atómicas mientras todas las escrituras en memoria vayan únicamente a través del mismo hardware RDMA. No es atómica con las escrituras realizadas por la CPU, o por otro hardware RDMA en el sistema.

ibv_wr_atomic_cmp_swp()
Si la ubicación de memoria remota de 64 bits especificada por rkey y remote_addr es igual a compare, entonces se establece en swap.
ibv_wr_atomic_fetch_add()
Suma add a la ubicación de memoria de 64 bits especificada por rkey y remote_addr.
