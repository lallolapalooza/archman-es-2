IBV_FORK_INIT(3) Manual del programador de Libibverbs IBV_FORK_INIT(3)

NOMBRE

ibv_fork_init - inicializa libibverbs para soportar fork()

SINOPSIS

#include <infiniband/verbs.h>
int ibv_fork_init(void);

DESCRIPCIÓN

ibv_fork_init() inicializa las estructuras de datos de libibverbs para manejar correctamente las llamadas a la función fork() y evitar la corrupción de datos, ya sea que fork() se llame explícita o implícitamente (como en system()).

No es necesario usar esta función si todos los hilos del proceso padre siempre se bloquean hasta que todos los procesos hijos terminan o cambian de espacio de direcciones mediante una operación exec().

VALOR DE RETORNO

ibv_fork_init() devuelve 0 si tiene éxito, o el valor de errno en caso de fallo (que indica la razón del fallo). Un valor de error EINVAL indica que ya había un registro de memoria RDMA y, por lo tanto, ya no es seguro hacer fork.

NOTAS

ibv_fork_init() funciona en kernels de Linux que soportan la bandera MADV_DONTFORK para madvise() (2.6.17 y superior).

Establecer la variable de entorno RDMAV_FORK_SAFE o IBV_FORK_SAFE tiene el mismo efecto que llamar a ibv_fork_init().

Establecer la variable de entorno RDMAV_HUGEPAGES_SAFE indica a la biblioteca que verifique el tamaño de página subyacente utilizado por el kernel para las regiones de memoria. Esto es necesario si una aplicación utiliza páginas grandes, ya sea directa o indirectamente a través de una biblioteca como libhugetlbfs.

Llamar a ibv_fork_init() reducirá el rendimiento debido a una llamada adicional al sistema por cada registro de memoria y la memoria adicional asignada para rastrear las regiones de memoria. El impacto exacto en el rendimiento depende de la carga de trabajo y, por lo general, no será significativo.

Establecer RDMAV_HUGEPAGES_SAFE agrega una sobrecarga adicional a todos los registros de memoria.

VER TAMBIÉN

exec(3), fork(2), ibv_get_device_list(3), system(3), wait(2)
