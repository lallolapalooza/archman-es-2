NOMBRE

ibacm_prov - Interfaz del proveedor del asistente de gestión de comunicaciones InfiniBand

SINOPSIS

#include <infiniband/acm_prov.h>

DESCRIPCIÓN

La interfaz del proveedor ibacm proporciona una interfaz de plugin que permite a un proveedor implementar soluciones propietarias para soportar servicios escalables de resolución de direcciones y rutas sobre InfiniBand.

Para añadir un proveedor al servicio principal de ibacm, el proveedor debe:

1. ser implementado como una biblioteca compartida;
2. ser instalado en un directorio configurado, por ejemplo, /usr/lib/ibacm;
3. exportar una función provider_query() que devuelva un puntero a su información de proveedor
e información de versión.

El prototipo de la función provider_query se define a continuación:

int provider_query(struct acm_provider **info, uint32_t *version);

Esta función debe devolver un puntero a su estructura de proveedor:

struct acm_provider {
	size_t    size; 
	uint32_t  version;
	char      *name;
	int	(*open_device)(const struct acm_device *device, 
			void **dev_context);
	void	(*close_device)(void *dev_context);
	int	(*open_port)(const struct acm_port *port, 
			void *dev_context, void **port_context);
	void	(*close_port)(void *port_context);
	int	(*open_endpoint)(const struct acm_endpoint *endpoint, 
			void *port_context, void **ep_context);
	void	(*close_endpoint)(void *ep_context);
	int	(*add_address)(const struct acm_address *addr, void *ep_context,
			void **addr_context);
	void	(*remove_address)(void *addr_context);
	int	(*resolve)(void *addr_context, struct acm_msg *msg, uint64_t id);
	int	(*query)(void *addr_context, struct acm_msg *msg, uint64_t id);
	int	(*handle_event)(void *port_context, enum ibv_event_type type);
	void	(*query_perf)(void *ep_context, uint64_t *values, uint8_t *cnt);
};

Los campos size y version proporcionan una forma de detectar la compatibilidad de versiones. Cuando se asigna un puerto al proveedor, el núcleo de ibacm llamará a las funciones open/add_address; de manera similar, cuando un puerto se cae o se reasigna a otro proveedor, se invocarán las funciones close/remove_address para liberar recursos. El núcleo de ibacm centralizará la gestión de eventos para cada dispositivo y los eventos no gestionados por el núcleo de ibacm se reenviarán al puerto relevante a través de la función handle_event(). La función resolve() se llamará para resolver un nombre de destino en un registro de ruta. El rendimiento del proveedor para cada punto final se puede consultar llamando a perf_query().

Para compartir un archivo de configuración, la ruta del archivo de configuración de ibacm se exporta a través de la variable opts_file. Cada proveedor cargado puede abrir este archivo de configuración y analizar el contenido relacionado con su propia operación. Las secciones no relacionadas deben ignorarse.

El núcleo de ibacm también exporta algunas funciones de ayuda. Por ejemplo, la definición acm_log (o la función acm_write()) se puede utilizar para registrar mensajes en el archivo de registro de ibacm (por defecto /var/log/ibacm.log). Para más detalles, consulte el archivo acm_prov.h.

NOTAS

Un proveedor siempre debe establecer la versión en su estructura de información del proveedor como el valor de la definición ACM_PROV_VERSION en el momento en que se implementa el proveedor. Nunca establezca la versión en ACM_PROV_VERSION en sí, ya que la definición puede cambiar con el tiempo cuando se modifique la interfaz del proveedor, a menos que la implementación del proveedor se encuentre dentro del árbol de fuentes de ibacm. Esto es para evitar problemas de versión cuando la implementación antigua del proveedor se compila contra un archivo acm_prov.h nuevo. ibacm siempre verificará la versión del proveedor en el momento de la carga.
