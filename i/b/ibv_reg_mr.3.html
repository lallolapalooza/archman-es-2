IBV_REG_MR(3) Manual del Programador de Libibverbs IBV_REG_MR(3)

NOMBRE

ibv_reg_mr, ibv_reg_mr_iova, ibv_reg_dmabuf_mr, ibv_reg_mr_ex, ibv_dereg_mr - registrar o desregistrar una región de memoria (MR)

SINOPSIS

#include <infiniband/verbs.h>

struct ibv_mr *ibv_reg_mr(struct ibv_pd *pd, void *addr,
                          size_t length, int access);

struct ibv_mr *ibv_reg_mr_iova(struct ibv_pd *pd, void *addr,
                               size_t length, uint64_t hca_va,
                               int access);

struct ibv_mr *ibv_reg_dmabuf_mr(struct ibv_pd *pd, uint64_t offset,
                                 size_t length, uint64_t iova,
                                 int fd, int access);

struct ibv_mr *ibv_reg_mr_ex(struct ibv_pd *pd, struct ibv_mr_init_attr *mr_init_attr");

int ibv_dereg_mr(struct ibv_mr *mr);

DESCRIPCIÓN

ibv_reg_mr() registra una región de memoria (MR) asociada con el dominio de protección pd. La dirección de inicio de la MR es addr y su tamaño es length. El argumento access describe los atributos de protección de memoria deseados; es 0 o el OR bit a bit de uno o más de los siguientes indicadores:

IBV_ACCESS_LOCAL_WRITE
Habilita el acceso de escritura local
IBV_ACCESS_REMOTE_WRITE
Habilita el acceso de escritura remota
IBV_ACCESS_REMOTE_READ
Habilita el acceso de lectura remota
IBV_ACCESS_REMOTE_ATOMIC
Habilita el acceso a operaciones atómicas remotas (si se soporta)
IBV_ACCESS_FLUSH_GLOBAL
Habilita la operación de volcado remoto con tipo de colocación de visibilidad global (si se soporta)
IBV_ACCESS_FLUSH_PERSISTENT
Habilita la operación de volcado remoto con tipo de colocación de persistencia (si se soporta)
IBV_ACCESS_MW_BIND
Habilita el enlace de ventanas de memoria
IBV_ACCESS_ZERO_BASED
Usa el desplazamiento en bytes desde el inicio de la MR para acceder a esta MR, en lugar de una dirección de puntero
IBV_ACCESS_ON_DEMAND
Crea una MR de paginación bajo demanda
IBV_ACCESS_HUGETLB
Se garantiza que se usarán páginas grandes para esta MR, aplicable con IBV_ACCESS_ON_DEMAND solo en modo explícito
IBV_ACCESS_RELAXED_ORDERING
Esta configuración permite que la NIC relaje el orden en que se transfieren datos entre la red y la región de memoria de destino. El orden relajado permite que las escrituras iniciadas por la red (como operaciones de envío de mensajes entrantes o escrituras RDMA) lleguen a la memoria en un orden arbitrario. Esto puede mejorar el rendimiento de algunas aplicaciones. Sin embargo, el orden relajado tiene el siguiente impacto: el orden de los mensajes de escritura RDMA ya no está garantizado. (Los mensajes enviados seguirán coincidiendo con los búferes de recepción publicados en orden.) Las escrituras de red consecutivas que apuntan a la misma región de memoria dejan la región en un estado desconocido. El orden relajado no cambia la semántica de finalización, como la visibilidad de los datos. Es decir, una finalización aún asegura que todos los datos sean visibles, incluidos los datos de transferencias anteriores. Las operaciones con orden relajado tampoco omitirán operaciones atómicas.

Si IBV_ACCESS_REMOTE_WRITE o IBV_ACCESS_REMOTE_ATOMIC está establecido, entonces IBV_ACCESS_LOCAL_WRITE también debe estar establecido.

El acceso de lectura local siempre está habilitado para la MR.

Para crear una MR ODP implícita, IBV_ACCESS_ON_DEMAND debe estar establecido, addr debe ser 0 y length debe ser SIZE_MAX.

Si IBV_ACCESS_HUGETLB está establecido, entonces la aplicación sabe que para esta MR todas las páginas son grandes y debe prometer que nunca hará nada para romper las páginas grandes.

ibv_reg_mr_iova() ibv_reg_mr_iova es lo mismo que la reg_mr normal, excepto que se permite al usuario especificar la dirección virtual base de la MR cuando se accede a través de un lkey o rkey. El desplazamiento en la región de memoria se calcula como 'addr + (iova - hca_va)'. Especificar 0 para hca_va tiene el mismo efecto que IBV_ACCESS_ZERO_BASED.

ibv_reg_dmabuf_mr() registra una región de memoria basada en dma-buf (MR) asociada con el dominio de protección pd. La MR comienza en offset del dma-buf y su tamaño es length. El dma-buf es identificado por el descriptor de archivo fd. El argumento iova especifica la dirección virtual base de la MR cuando se accede a través de un lkey o rkey. Debe tener el mismo desplazamiento de página que offset. El argumento access describe los atributos de protección de memoria deseados; es similar al caso de ibv_reg_mr excepto que solo se soportan los siguientes indicadores: IBV_ACCESS_LOCAL_WRITE, IBV_ACCESS_REMOTE_WRITE, IBV_ACCESS_REMOTE_READ, IBV_ACCESS_REMOTE_ATOMIC, IBV_ACCESS_RELAXED_ORDERING.

ibv_reg_mr_ex() ibv_reg_mr_ex es una API que habilita todas las variantes de los otros ibv_reg_mr_xxx() que se describen en esa página de manual. Tiene el mr_init_attr->comp_mask campo para que la aplicación marque qué campos son aplicables. Además, incluye el mr_init_attr->dmah que se puede usar para incluir un objeto ibv_dmah que se usará para esa MR. Los otros campos del puntero de entrada tienen el mismo significado que los campos descritos en esa página de manual para los otros verbos.

ibv_dereg_mr() desregistra la MR mr.

VALOR DE RETORNO

ibv_reg_mr() / ibv_reg_mr_iova() / ibv_reg_dmabuf_mr() / ibv_reg_mr_ex() devuelve un puntero a la MR registrada, o NULL si la solicitud falla. El campo de clave local (L_Key) campo lkey se usa como el campo lkey de struct ibv_sge al publicar búferes con los verbos ibv_post_*, y el campo de clave remota (R_Key) campo rkey es usado por procesos remotos para realizar operaciones atómicas y RDMA. El proceso remoto coloca este rkey como el campo rkey de struct ibv_send_wr pasado a la función ibv_post_send.

ibv_dereg_mr() devuelve 0 en éxito, o el valor de errno en fallo (lo cual indica la razón del fallo).

NOTAS

ibv_dereg_mr() falla si alguna ventana de memoria sigue enlazada a esta MR. ibv_dereg_mr_ex() Se requiere uno entre mr_init_attr->fd y mr_init_attr->addr, no pueden venir ambos juntos.

VER TAMBIÉN
