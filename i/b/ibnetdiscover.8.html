IBNETDISCOVER(8) Diagnósticos Open IB IBNETDISCOVER(8)

Nombre

IBNETDISCOVER - descubre la topología de InfiniBand

SINOPSIS

ibnetdiscover [opciones] [<archivo-de-topología>]

DESCRIPCIÓN

ibnetdiscover realiza el descubrimiento de la subred IB y genera un archivo de topología legible para humanos. Se muestran los GUIDs, los tipos de nodo y los números de puerto, así como los LIDs de los puertos y las NodeDescriptions. Se muestran todos los nodos (y enlaces) (topología completa). Opcionalmente, esta utilidad se puede utilizar para listar los nodos conectados actualmente por tipo de nodo. La salida se imprime en la salida estándor a menos que se especifique un archivo de topología.

OPCIONES

-l, --list Lista de nodos conectados

-g, --grouping Mostrar agrupación. La agrupación correlaciona los nodos IB por diferentes esquemas específicos del proveedor. También puede mostrar la correspondencia de los puertos externos del conmutador.

-H, --Hca_list Lista de CAs conectadas

-S, --Switch_list Lista de conmutadores conectados

-R, --Router_list Lista de routers conectados

-s, --show Mostrar información de progreso durante el descubrimiento.

-f, --full Mostrar información completa (velocidad y ancho de los puertos, vlcap)

-p, --ports Obtener un informe de puertos, que es una lista de puertos conectados con información relevante (como LID, portnum, GUID, ancho, velocidad y NodeDescription).

-m, --max_hops Informar del número máximo de saltos descubiertos.

--outstanding_smps, -o <val>
Especificar el número de SMPs pendientes que deben emitirse durante el escaneo

Predeterminado: 2

Banderas de archivo de caché

--cache <filename> Cachear los datos de red de ibnetdiscover en el nombre de archivo especificado. Esta caché puede ser utilizada por otras herramientas para análisis posteriores.

--load-cache <filename> Cargar y usar los datos de ibnetdiscover almacenados en caché en el nombre de archivo especificado. Puede ser útil para generar salidas y conocer otras fabrics o un estado anterior de una fabric.

--diff <filename> Cargar los datos de ibnetdiscover en caché y realizar una comparación de diferencias con la red actual u otra caché. Se mostrará una salida de diferencias especial para la salida de ibnetdiscover mostrando las diferencias entre la fabric antigua y la actual. Por defecto, se comparan las siguientes cosas en busca de diferencias: conmutadores, adaptadores de canal, routers y conexiones de puertos.

--diffcheck <key(s)> Especificar qué comprobaciones de diferencias deben realizarse en la --diff opción anterior. Separar por comas múltiples claves de comprobación de diferencias. Las comprobaciones de diferencias disponibles son: sw = conmutadores, ca = adaptadores de canal, router = routers, port = conexiones de puertos, lid = lids, nodedesc = descripciones de nodo. Tener en cuenta que port, lidy nodedesc se comprueban solo para los tipos de nodo que se especifican (por ejemplo, sw, ca, router). Si se especifica port junto con lid o nodedesc, también se compararán los LIDs de los puertos remotos y las descripciones de nodo.

Banderas de selección de puerto

-C, --Ca <ca_name> usar el ca_name especificado.

-P, --Port <ca_port> usar el ca_port especificado.

Selección de puerto local

Soporte de múltiples puertos/múltiples CAs: cuando no se especifica ningún dispositivo o puerto IB (ver los "parámetros umad locales" más abajo), la biblioteca libibumad selecciona el puerto a usar según los siguientes criterios:

1.
el primer puerto que esté ACTIVO.
2.
si no se encuentra, el primer puerto que esté UP (enlace físico activo).

Si se especifica un puerto y/o un nombre de CA, la biblioteca libibumad intenta satisfacer la solicitud del usuario y fallará si no es posible.

Por ejemplo:

ibaddr                 # usar el primer puerto (criterio #1 anterior)
ibaddr -C mthca1       # elegir el mejor puerto solo de "mthca1".
ibaddr -P 2            # usar el segundo puerto (activo/up) del primer dispositivo IB disponible.
ibaddr -C mthca0 -P 2  # usar solo el puerto especificado.

Banderas de configuración

--config, -z <config_file> Especificar un archivo de configuración alternativo.

Predeterminado: /etc/infiniband-diags/ibdiag.conf
--outstanding_smps, -o <val>
Especificar el número de SMPs pendientes que deben emitirse durante el escaneo

Predeterminado: 2

--node-name-map <node-name-map> Especificar un mapa de nombres de nodo.

Este archivo asigna GUIDs a nombres más amigables para el usuario. Ver la sección ARCHIVOS.

-t, --timeout <timeout_ms> anular el tiempo de espera predeterminado para los mads solicitados.

-y, --m_key <key>
usar el M_key especificado para las solicitudes. Si se especifica un valor no numérico (como 'x'), se pedirá un valor.

Banderas de depuración

-d
aumentar el nivel de depuración de IB. Puede usarse varias veces (-ddd o -d -d -d).
-e
mostrar errores de envío y recepción (tiempos de espera y otros)

-h, --help mostrar el mensaje de uso

-v, --verbose
aumentar el nivel de verbosidad de la aplicación. Puede usarse varias veces (-vv o -v -v -v)

-V, --version mostrar la información de versión.

ARCHIVOS

ARCHIVO DE CONFIGURACIÓN

/etc/infiniband-diags/ibdiag.conf

Se proporciona un archivo de configuración global para establecer algunas de las opciones comunes para todas las herramientas. Ver el archivo de configuración proporcionado para más detalles.

FORMATO DEL ARCHIVO DE TOPOLOGÍA

El formato del archivo de topología es legible por humanos y en gran medida intuitivo. La mayoría de los identificadores se les dan nombres textuales como ID de proveedor (vendid), ID de dispositivo (device ID), GUID de varios tipos (sysimgguid, caguid, switchguid, etc.). Los PortGUID se muestran entre paréntesis (). Para los conmutadores, esto se muestra en la línea switchguid. Para los puertos CA y de enrutamiento, se muestra en las líneas de conectividad. El nodo IB se identifica seguido del número de puertos y un GUID de nodo entre comillas. A la derecha de esta línea hay un comentario (#) seguido de la NodeDescription entre comillas. Si el nodo es un conmutador, esta línea también contiene si el puerto 0 del conmutador es básico o mejorado, y el LID y el LMC del puerto 0. Las líneas siguientes relacionadas con este nodo muestran la conectividad. A la izquierda está el número de puerto del nodo actual. A la derecha está el nodo par (el nodo en el otro extremo del enlace). Se identifica entre comillas con el tipo de nodo seguido de - seguido de NodeGUID con el número de puerto entre corchetes. Más a la derecha hay un comentario (#). Lo que sigue al comentario depende del tipo de nodo. Si es un nodo conmutador, le sigue la NodeDescription entre comillas y el LID del nodo par. Si es un nodo CA o de enrutamiento, le sigue el LID y LMC locales y luego la NodeDescription entre comillas y el LID del nodo par. Luego se añaden al final de esta línea de salida el ancho y la velocidad activos del enlace.
