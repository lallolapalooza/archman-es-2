ibv_flow_action_esp(3) Manual de funciones de la biblioteca ibv_flow_action_esp(3)

NOMBRE

ibv_flow_action_esp - acción de flujo esp para verbs

SINOPSIS

#include <infiniband/verbs.h>
struct ibv_flow_action *
ibv_create_flow_action_esp(struct ibv_context *ctx,
               struct ibv_flow_action_esp *esp);
int
ibv_modify_flow_action_esp(struct ibv_flow_action *action,
               struct ibv_flow_action_esp *esp);
int ibv_destroy_flow_action(struct ibv_flow_action *action);

DESCRIPCIÓN

Una acción de dirección de flujo IPSEC ESP permite que una regla de dirección de flujo descifre o cifre un paquete después de coincidir. Cada acción contiene la información necesaria para esta operación en el argumento params.

Después de la operación criptográfica, el paquete continuará siendo procesado por las reglas de dirección de flujo hasta que alcance una acción final de descarte o entrega.

Después de crear la acción, debe asociarse con un struct ibv_flow_attr utilizando la especificación de flujo struct ibv_flow_spec_action_handle. Cada acción puede asociarse con múltiples flujos, y ibv_modify_flow_action_esp alterará todos los flujos asociados simultáneamente.

ARGUMENTOS

ctx
Contexto del dispositivo RDMA para crear la acción.
esp
Parámetros ESP y material de clave para la acción.
action
Acción existente para modificar parámetros ESP.

Argumento action

struct ibv_flow_action_esp {
    struct ibv_flow_action_esp_attr *esp_attr;
    /* Ver Material de Clave */
    uint16_t        keymat_proto;
    uint16_t        keymat_len;
    void           *keymat_ptr;
    /* Ver Protección contra Reproducción */
    uint16_t        replay_proto;
    uint16_t        replay_len;
    void           *replay_ptr;
    struct ibv_flow_action_esp_encap *esp_encap;
    uint32_t        comp_mask;
    uint32_t        esn;
};
comp_mask
Máscara de bits que especifica qué campos de la estructura son válidos.
esn
El valor inicial del número de secuencia extendido ESP. Válido solo si IBV_FLOW_ACTION_ESP_MASK_ESN está establecido en comp_mask.

Los 32 bits de esn se utilizarán para calcular el ESN de 64 bits completo requerido para la construcción del AAD.

Cuando está en modo IB_UVERBS_FLOW_ACTION_ESP_FLAGS_INLINE_CRYPTO, la implementación seguirá automáticamente el desbordamiento de los 32 bits inferiores del ESN. Sin embargo, se requiere una actualización de la ventana una vez cada 2^31 secuencias.

Cuando está en modo IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLOAD, este valor se incrementa automáticamente y también se utiliza para comprobaciones anti-reproducción.

esp_attr
Ver Atributos ESP. Puede ser NULL en la modificación.
keymat_proto, keymat_len, keymat_ptr
Describen el material de clave y el estándar de cifrado a utilizar. Puede ser NULL en la modificación.
replay_proto, replay_len, replay_ptr
Describen el esquema de protección contra reproducción utilizado para gestionar números de secuencia y prevenir ataques de reproducción. Este campo solo es válido en modo de descarga completa. Puede ser NULL en la modificación.
esp_encap
Describen la encapsulación de paquetes ESP, como el túnel IP y/o la encapsulación UDP. Este campo solo es válido en modo de descarga completa. Puede ser NULL en la modificación.

Atributos ESP

struct ibv_flow_action_esp_attr {
    uint32_t   spi;
    uint32_t   seq;
    uint32_t   tfc_pad;
    uint32_t   flags;
    uint64_t   hard_limit_pkts;
};
flags
Un OR a nivel de bits de las varias IB_UVERBS_FLOW_ACTION_ESP_FLAGS descritas a continuación.
IB_UVERBS_FLOW_ACTION_ESP_FLAGS_DECRYPT, IB_UVERBS_FLOW_ACTION_ESP_FLAGS_ENCRYPT
La acción descifrará o cifrará un paquete utilizando el material de clave proporcionado.

La implementación puede requerir que el cifrado solo se utilice con una regla de dirección de flujo saliente, y que el descifrado solo se utilice con una regla de dirección de flujo entrante.

Modo de Descarga Completa

Cuando la marca esp_attr IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLOAD está establecida, la cabecera y el remolque ESP se añaden y eliminan automáticamente durante la operación de cifrado. En este caso, el esn y el spi se utilizan para poblar y comprobar la cabecera ESP, y cualquier información del keymat (por ejemplo, un IV) se coloca en las cabeceras y se maneja automáticamente.

Para el descifrado, el hardware realizará la protección contra reproducción.

El fallo de descifrado provocará el descarte del paquete.

Esta acción debe combinarse con la dirección de flujo que identifica los paquetes protegidos por el SA definido en esta acción.

Los siguientes miembros de esp_attr se utilizan solo en modo de descarga completa:

spi
El valor para el Índice de Parámetros de Seguridad ESP. Solo se utiliza para IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLAOD.
seq
Los 32 bytes inferiores iniciales del número de secuencia. Este es el valor del número de secuencia ESP. Solo se utiliza para IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLAOD.
tfc_pad
La longitud del Relleno de Confidencialidad del Flujo de Tráfico según lo especificado por RFC4303. Si se establece en cero, no se añade relleno adicional. Solo se utiliza para IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLAOD.
hard_limit_pkts
El límite de vida útil duro de la SA medido en número de paquetes. Como se especifica en RFC4301. Una vez alcanzado este límite, la acción descartará los paquetes futuros para evitar romper la criptografía. Solo se utiliza para IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLAOD.

Modo de Cripto en Línea

Cuando la marca esp_attr IB_UVERBS_FLOW_ACTION_ESP_FLAGS_INLINE_CRYPTO está establecida, el usuario debe proporcionar paquetes con cabeceras adicionales.

Para cifrar, el paquete debe contener un paquete IPSEC completamente relleno excepto que la carga útil de datos queda sin cifrar y no hay remolque IPsec. Si el IV debe ser impredecible, entonces una marca debe indicar la transformación, como IB_UVERBS_FLOW_ACTION_IV_ALGO_SEQ.

IB_UVERBS_FLOW_ACTION_IV_ALGO_SEQ significa que el IV se incrementa secuencialmente. Si el algoritmo IV es compatible con HW, podría proporcionar soporte para la descarga LSO con cripto en línea ESP.

Finalmente, el IV utilizado para cifrar el paquete reemplaza el campo IV proporcionado, la carga útil se cifra y autentica, se añade un remolque con relleno y también se añade el ICV.

Para descifrar, el paquete se autentica y descifra en el lugar, lo que resulta en un paquete IPSEC descifrado sin remolque. El resultado del descifrado y la autenticación se puede recuperar de una CQ extendida a través de la función ibv_wc_read_XXX(3).

Este modo debe combinarse con la dirección de flujo que incluye IBV_FLOW_SPEC_IPV4 y IBV_FLOW_SPEC_ESP para que coincida con las cabeceras del paquete exterior y garantizar que la acción solo se aplique a paquetes IPSEC con los identificadores correctos.

Determinación del ESN para Paquetes de Entrada

Requerimos un comando “modify” una vez cada 2^31 paquetes. Este comando modify permite que la implementación en HW sea sin estado, de la siguiente manera:

           ESN 1                       ESN 2                      ESN 3
|-------------*-------------|-------------*-------------|-------------*
^             ^             ^             ^             ^             ^

^ - marca dónde se invoca el comando para actualizar la máquina de estados del ESN de la SA.

| - marca el inicio del alcance del ESN (0-2^32-1). En este punto, el bit "new_window" del ESN de la SA se pone a cero y se incrementa el ESN.

* - marca el medio del alcance del ESN (2^31). En este punto, el bit "new_window" del ESN de la SA se pone a uno.

Para el descifrado, la implementación utiliza la siguiente máquina de estados para determinar el ESN:

if (!overlap) {
    use esn // independientemente de packet.seq
} else { // new_window
    if (packet.seq >= 2^31)
        use esn
    else // packet.seq < 2^31
        use esn+1
}

Este mecanismo está controlado por el esp_attr flag:

IB_UVERBS_FLOW_ACTION_ESP_FLAGS_ESN_NEW_WINDOW
Este flag se utiliza solo para proporcionar soporte de ESN sin estado para la criptografía en línea. Se utiliza solo con IB_UVERBS_FLOW_ACTION_ESP_FLAGS_INLINE_CRYPTO y IBV_FLOW_ACTION_ESP_MASK_ESN.

Establecer este flag indica que el fondo de la ventana de reproducción está entre 2^31 - 2^32.

Material de Clave para AES GCM (IBV_ACTION_ESP_KEYMAT_AES_GCM)

El algoritmo criptográfico AES GCM tal como está definido por RFC4106. Esta struct es para ser proporcionada en keymat_ptr cuando keymat_proto está establecido a IBV_ACTION_ESP_KEYMAT_AES_GCM.

struct ibv_flow_action_esp_aes_keymat_aes_gcm {
    uint64_t   iv;
    uint32_t   iv_algo; /* Use enum ib_uverbs_flow_action_esp_aes_gcm_keymat_iv_algo */
    uint32_t   salt;
    uint32_t   icv_len;
    uint32_t   key_len;
    uint32_t   aes_key[256 / 32];
};
iv
El valor inicial del vector de inicialización, utilizado solo con IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLOAD para el cifrado, tal como se define en RFC4106. Este campo se ignora para IB_UVERBS_FLOW_ACTION_ESP_FLAGS_INLINE_CRYPTO.

Para una clave dada, el IV NO DEBE ser reutilizado.

iv_algo
El algoritmo utilizado para transformar/generar nuevos IVs con IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLOAD para el cifrado.

El único valor soportado es IB_UVERBS_FLOW_ACTION_IV_ALGO_SEQ para generar IVs secuenciales.

salt
El salt tal como está definido por RFC4106.
icv_len
La longitud del Valor de Comprobación de Integridad (ICV) en bytes, tal como está definido por RFC4106.
aes_key, key_len
Los datos de la clave de cifrado. Debe ser de 16, 24 o 32 bytes, tal como está definido por RFC4106.

Protección contra Reproducción con Mapa de Bits (IBV_FLOW_ACTION_ESP_REPLAY_BMP)

Se utiliza un mapa de bits desplazable para identificar qué paquetes ya han sido transmitidos. Cada bit en el mapa de bits representa un paquete; se establece si se ha recibido un paquete con este número de secuencia ESP y ha pasado la autenticación. Si se recibe un paquete con la misma secuencia, entonces el bit ya está establecido, lo que hace que la protección contra reproducción descarte el paquete. El mapa de bits representa una ventana de size números de secuencia. Si se recibe un número de secuencia más nuevo, entonces el mapa de bits se desplazará para representar esto, tal como en RFC6479. La ventana de reproducción no puede desplazarse más de 2^31 números de secuencia hacia adelante.

Esta struct es para ser proporcionada en replay_ptr cuando reply_proto está establecido a IBV_FLOW_ACTION_ESP_REPLAY_BMP. En este modo, reply_ptr y reply_len deberían apuntar a una struct ibv_flow_action_esp_replay_bmp que contiene: size : El tamaño del mapa de bits.

Encapsulación ESP

Una especificación esp_encap es requerida cuando eps_attr los flags IB_UVERBS_FLOW_ACTION_ESP_FLAGS_TUNNEL están establecidos. Se utiliza para proporcionar los campos para la cabecera de encapsulación que se añade/elimina de los paquetes. El modo Túnel y Transporte están definidos como en RFC4301. La encapsulación UDP de ESP puede ser especificada proporcionando la cabecera UDP correspondiente.

Esta configuración solo se utiliza en el modo IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLOAD .

struct ibv_flow_action_esp_encap {
    void        *val;        /* pointer to struct ibv_flow_xxxx_filter */
    struct ibv_flow_action_esp_encap   *next_ptr;
    uint16_t    len;            /* Len of mask and pointer (separately) */
    uint16_t    type;           /* Use flow_spec enum */
};

Cada enlace en la lista especifica una cabecera de red de la misma manera que la API de enrutamiento de flujo. La cabecera debería ser seleccionada de una cabecera soportada en `enum ibv_flow_spec_type'.

VALOR DE RETORNO

En caso de éxito ibv_create_flow_action_esp devolverá un nuevo struct ibv_flow_action objeto, en caso de error se devolverá NULL y errno será establecido.

En caso de éxito ibv_modify_action_esp devolverá 0. En caso de error se devolverá el valor de errno. Si ibv_modify_flow_action falla, está garantizado que la última acción todavía se mantiene. Si tiene éxito, hay un punto en el futuro donde la acción antigua se aplica a todos los paquetes hasta este punto y la nueva se aplica a todos los paquetes desde este punto en adelante.
