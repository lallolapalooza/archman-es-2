IBQUERYERRORS(8) Diagnósticos OpenIB IBQUERYERRORS(8)

Nombre

IBQUERYERRORS - consultar y reportar contadores de errores IB

SINOPSIS

ibqueryerrors [opciones]

DESCRIPCIÓN

El comportamiento por defecto es reportar los contadores de errores de puerto que excedan un umbral para cada puerto en el tejido. El umbral por defecto es cero (0). Los campos de error también se pueden suprimir por completo.

Además de reportar errores en cada puerto. ibqueryerrors puede reportar los datos de transmisión y recepción del puerto, así como reportar información completa del enlace al puerto remoto si está disponible.

OPCIONES

-s, --suppress <err1,err2,...> Suprime los errores listados en la lista separada por comas proporcionada.

-c, --suppress-common Suprime algunos de los contadores comunes de "efecto secundario". Estos contadores generalmente no indican una condición de error y, por lo general, se pueden ignorar con seguridad.

-r, --report-port Reporta la información del puerto. Esto incluye LID, puerto, puerto externo (si es aplicable), ajuste de velocidad del enlace, GUID remoto, puerto remoto, puerto externo remoto (si es aplicable) e información de descripción del nodo remoto.

--data Incluye los contadores opcionales de datos de transmisión y recepción.

--threshold-file <nombre_archivo> Especifica un archivo de umbral alternativo. El valor predeterminado es /etc/infiniband-diags/error_thresholds

--switch imprime datos solo para switches

--ca imprime datos solo para CAs

--skip-sl Usa el SL por defecto para las consultas. Esto no se recomienda cuando se usa un motor de enrutamiento consciente de QoS, ya que puede causar un interbloqueo de créditos.

--router imprime datos solo para routers

--clear-errors -k Borra los contadores de errores después de leerlos.

--clear-counts -K Borra los contadores de datos después de leerlos.

PRECAUCIÓN borrar los contadores de datos o errores ocurrirá independientemente de si se imprimen o no. Consulte --counters y --data para obtener detalles sobre cómo controlar qué contadores se imprimen.

--details incluye detalles de errores de recepción y descartes de transmisión

--counters imprime solo los contadores de datos

Banderas de escaneo parcial

El nodo para iniciar un escaneo parcial se puede especificar con las siguientes direcciones.

--port-guid, -G <guid_puerto> Especifica un guid_puerto

-D, --Direct <ruta_dr> La dirección especificada es una ruta dirigida

Ejemplos:
   -D "0"          # puerto propio
   -D "0,1,2,1,4"  # salida por el puerto 1, luego 2, ...
   (Nota: el segundo número en la ruta especificada debe coincidir con el puerto que
   se está utilizando. Esto se puede especificar usando la bandera de selección de
   puerto '-P' o el puerto encontrado a través del proceso de selección automática.)

Nota: Para switches, los resultados se imprimen para todos los puertos, no solo para el puerto 0 del switch.

-S <guid_puerto> igual que "-G". (solo se proporciona por compatibilidad hacia atrás)

Banderas de archivo de caché

--load-cache <nombre_archivo> Carga y utiliza los datos encontrados de ibnetdiscover cacheados almacenados en el nombre de archivo especificado. Puede ser útil para generar y aprender sobre otros tejidos o un estado anterior de un tejido.

Banderas de selección de puerto

-C, --Ca <nombre_ca> usa el nombre_ca especificado.

-P, --Port <puerto_ca> usa el puerto_ca especificado.

Selección de puerto local

Soporte para múltiples puertos/múltiples CA: cuando no se especifica ningún dispositivo o puerto IB (ver los "parámetros umad locales" a continuación), la biblioteca libibumad selecciona el puerto a utilizar según los siguientes criterios:

1.
el primer puerto que esté ACTIVO.
2.
si no se encuentra, el primer puerto que esté ARRIBA (enlace físico activo).

Si se especifica un nombre de puerto y/o CA, la biblioteca libibumad intenta satisfacer la solicitud del usuario y fallará si no es posible.

Por ejemplo:

ibaddr                 # usa el primer puerto (criterio #1 arriba)
ibaddr -C mthca1       # elige el mejor puerto solo de "mthca1".
ibaddr -P 2            # usa el segundo puerto (activo/arriba) del primer dispositivo IB disponible.
ibaddr -C mthca0 -P 2  # usa solo el puerto especificado.

Banderas de configuración

--config, -z <archivo_config> Especifica un archivo de configuración alternativo.

Predeterminado: /etc/infiniband-diags/ibdiag.conf
--outstanding_smps, -o <val>
Especifica el número de SMPs pendientes que deben emitirse durante el escaneo

Predeterminado: 2

--node-name-map <mapa_nombres_nodo> Especifica un mapa de nombres de nodo.

Este archivo mapea GUIDs a nombres más amigables para el usuario. Ver la sección ARCHIVOS.

-t, --timeout <timeout_ms> anula el tiempo de espera predeterminado para los mad solicitados.

-y, --m_key <clave>
usa la M_key especificada para las solicitudes. Si se especifica un valor no numérico (como 'x'), se solicitará un valor.

Banderas de depuración

-d
aumenta el nivel de depuración de IB. Se puede usar varias veces (-ddd o -d -d -d).
-e
muestra errores de envío y recepción (tiempos de espera y otros)

-h, --help muestra el mensaje de uso

-v, --verbose
aumenta el nivel de verbosidad de la aplicación. Se puede usar varias veces (-vv o -v -v -v)

-V, --version muestra la información de la versión.

-R (Esta opción es obsoleta y no hace nada)

ESTADO DE SALIDA

-1 si falla el escaneo.

0 si el escaneo se completa sin errores más allá de los umbrales

1 si se encuentran errores más allá de los umbrales o se encuentran inconsistencias en el modo de verificación.

ARCHIVOS

UMBRAL DE ERROR

/etc/infiniband-diags/error_thresholds

Define los valores umbral para los errores. El formato del archivo es simple "nombre=valor". Los comentarios comienzan con '#'.

Ejemplo:

# Define umbrales para contadores de errores
SymbolErrorCounter=10
LinkErrorRecoveryCounter=10
VL15Dropped=100

ARCHIVO DE CONFIGURACIÓN

/etc/infiniband-diags/ibdiag.conf

Se proporciona un archivo de configuración global para establecer algunas de las opciones comunes para todas las herramientas. Consulte el archivo de configuración proporcionado para obtener detalles.

FORMATO DEL ARCHIVO DE MAPA DE NOMBRES DE NODO

El mapa de nombres de nodo se utiliza para especificar nombres amigables para el usuario para los nodos en la salida. Los GUIDs se utilizan para realizar la búsqueda.

Esta funcionalidad es proporcionada por el paquete opensm-libs. Consulte opensm(8) para conocer la ubicación del archivo para su instalación.

Genéricamente:

# comentario
<guid> "<nombre>"
