ICONV(3P) Manual del programador POSIX ICONV(3P)

PROLOGO

Esta página del manual es parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

iconv — función de conversión de conjuntos de códigos

SINOPSIS

#include <iconv.h>
size_t iconv(iconv_t cd, char **restrict inbuf,
    size_t *restrict inbytesleft, char **restrict outbuf,
    size_t *restrict outbytesleft);

DESCRIPCIÓN

La función iconv() convertirá la secuencia de caracteres de un conjunto de códigos, en el array especificado por inbuf, en una secuencia de caracteres correspondientes en otro conjunto de códigos, en el array especificado por outbuf. Los conjuntos de códigos son los especificados en la llamada a iconv_open() que devolvió el descriptor de conversión, cd. El argumento inbuf apunta a una variable que apunta al primer carácter en el búfer de entrada y inbytesleft indica el número de bytes hasta el final del búfer que deben convertirse. El argumento outbuf apunta a una variable que apunta al primer byte disponible en el búfer de salida y outbytesleft indica el número de bytes disponibles hasta el final del búfer.

Para codificaciones dependientes del estado, el descriptor de conversión cd se coloca en su estado de cambio inicial mediante una llamada para la cual inbuf es un puntero nulo, o para la cual inbuf apunta a un puntero nulo. Cuando iconv() se llama de esta manera, y si outbuf no es un puntero nulo o un puntero a un puntero nulo, y outbytesleft apunta a un valor positivo, iconv() colocará, en el búfer de salida, la secuencia de bytes para cambiar el búfer de salida a su estado de cambio inicial. Si el búfer de salida no es lo suficientemente grande como para contener toda la secuencia de reinicio, iconv() fallará y establecerá errno en [E2BIG]. Las llamadas posteriores con inbuf distinto de un puntero nulo o un puntero a un puntero nulo hacen que la conversión tenga lugar desde el estado actual del descriptor de conversión.

Si una secuencia de bytes de entrada no forma un carácter válido en el conjunto de códigos especificado, la conversión se detendrá después del carácter convertido con éxito anterior. Si el búfer de entrada termina con un carácter incompleto o una secuencia de cambio, la conversión se detendrá después de los bytes convertidos con éxito anteriores. Si el búfer de salida no es lo suficientemente grande como para contener toda la entrada convertida, la conversión se detendrá justo antes de los bytes de entrada que provocarían el desbordamiento del búfer de salida. La variable apuntada por inbuf se actualizará para apuntar al byte siguiente al último byte utilizado con éxito en la conversión. El valor apuntado por inbytesleft se decrementará para reflejar el número de bytes aún no convertidos en el búfer de entrada. La variable apuntada por outbuf se actualizará para apuntar al byte siguiente al último byte de datos de salida convertidos. El valor apuntado por outbytesleft se decrementará para reflejar el número de bytes aún disponibles en el búfer de salida. Para codificaciones dependientes del estado, el descriptor de conversión se actualizará para reflejar el estado de cambio en vigor al final de la última secuencia de bytes convertida con éxito.

Si iconv() encuentra un carácter en el búfer de entrada que es válido, pero para el cual no existe un carácter idéntico en el conjunto de códigos de destino, iconv() realizará una conversión definida por la implementación en este carácter.

VALOR DE RETORNO

La función iconv() actualizará las variables apuntadas por los argumentos para reflejar el alcance de la conversión y devolverá el número de conversiones no idénticas realizadas. Si toda la cadena en el búfer de entrada se convierte, el valor apuntado por inbytesleft será 0. Si la conversión de entrada se detiene debido a alguna de las condiciones mencionadas anteriormente, el valor apuntado por inbytesleft será distinto de cero y errno se establecerá para indicar la condición. Si ocurre un error, iconv() devolverá (size_t)-1 y establecerá errno para indicar el error.

ERRORES

La función iconv() fallará si:

EILSEQ
La conversión de entrada se detuvo debido a un byte de entrada que no pertenece al conjunto de códigos de entrada.
E2BIG
La conversión de entrada se detuvo debido a la falta de espacio en el búfer de salida.
EINVAL
La conversión de entrada se detuvo debido a un carácter incompleto o una secuencia de cambio al final del búfer de entrada.

La función iconv() puede fallar si:

EBADF
El argumento cd no es un descriptor de conversión abierto válido.

USO APLICACION

El argumento inbuf apunta indirectamente al área de memoria que contiene los datos de entrada de la conversión. El argumento outbuf apunta indirectamente al área de memoria que contendrá el resultado de la conversión. Los objetos a los que apuntan indirectamente inbuf y outbuf no se limitan a contener datos que sean directamente representables en el tipo de datos char del estándar ISO C. El tipo de inbuf y outbuf, char **, no implica que los objetos a los que apuntan se interpreten como cadenas C terminadas en nulo o arrays de caracteres. Cualquier interpretación de una secuencia de bytes que represente un carácter en un esquema de codificación de conjunto de caracteres dado se realiza internamente dentro de los convertidores de conjuntos de códigos. Por ejemplo, el área a la que apuntan indirectamente inbuf y/o outbuf puede contener todos los octetos cero que no se interpretan como terminadores de cadena, sino como datos de caracteres codificados según el esquema de codificación del conjunto de códigos respectivo. El tipo de datos (char, short, long, etc.) leídos o almacenados en los objetos no se especifica, pero puede inferirse tanto para los datos de entrada como de salida por los convertidores determinados por los argumentos fromcode y tocode de iconv_open().

Independientemente del tipo de datos inferido por el convertidor, el tamaño del espacio restante en ambos objetos de entrada y salida (los argumentos intbytesleft y outbytesleft) siempre se mide en bytes.

Para implementaciones que soportan la conversión de codificaciones dependientes del estado, el descriptor de conversión debe ser capaz de reflejar con precisión el estado de cambio en vigor al final de la última conversión exitosa. No se requiere que el descriptor de conversión se actualice, lo que requeriría que fuera un tipo puntero. Por lo tanto, las implementaciones son libres de implementar el descriptor como un manejador (aparte de un tipo puntero) mediante el cual se puede acceder y actualizar la información de conversión.

ICONV(3P) POSIX Programmer's API ICONV(3P)

PROLOG

This page is a manual page for the POSIX Programmer's API. It is a subset of the Linux Programmer's manual.

NAME

iconv, iconv_close, iconv_open, iconv_strdetail, iconv_strerror

SYNOPSIS

#include <iconv.h>

size_t iconv(iconv_t cd, char **restrict inbuf, size_t *restrict inbytesleft, char **restrict outbuf, size_t *restrict outbytesleft);

int iconv_close(iconv_t cd);

iconv_t iconv_open(const char *tocode, const char *fromcode);

char *iconv_strdetail(const char *name);

char *iconv_strerror(int errnum);

DESCRIPTION

The iconv family of functions provide support for character set conversion.

The iconv_open function allocates and initializes a conversion descriptor for converting from the character encoding specified by fromcode to the character encoding specified by tocode. The strings tocode and fromcode are implementation-defined character set names. On success, iconv_open returns a conversion descriptor, which is a value of type iconv_t. On failure, it returns (iconv_t)(-1).

The iconv function performs the character set conversion. The cd argument is a conversion descriptor obtained from iconv_open. The inbuf and inbytesleft arguments point to the input buffer and the number of bytes remaining in it, respectively. The outbuf and outbytesleft arguments point to the output buffer and the number of bytes remaining in it, respectively. The iconv function converts as many characters as possible from the input buffer to the output buffer, updating the pointers and byte counts accordingly. It returns the number of non-convertible characters encountered in the input buffer. If a conversion error occurs, it returns (size_t)(-1) and sets errno to indicate the error.

The iconv_close function closes the conversion descriptor cd, freeing any resources associated with it. It returns 0 on success, and -1 on failure.

The iconv_strdetail function returns a string containing a detailed description of the character encoding specified by name. If name is a NULL pointer, it returns a string describing all available character encodings. On failure, it returns NULL.

The iconv_strerror function returns a string containing a description of the error code specified by errnum. If errnum is not a valid error code, it returns NULL.

RETURN VALUE

See descriptions.

ERRORS

The iconv function may fail if:

EILSEQ
An input byte sequence does not form a valid character in the source character set.
EINVAL
An input byte sequence is incomplete but otherwise valid.
EBADF
The conversion descriptor cd is invalid.
E2BIG
Not enough space remains in the output buffer.

The iconv_open function may fail if:

EINVAL
The specified character encodings are not supported.
EMFILE
Too many conversion descriptors are open.

The iconv_close function may fail if:

EBADF
The conversion descriptor cd is invalid.
