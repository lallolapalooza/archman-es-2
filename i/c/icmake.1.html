OPCIONES

Al usar icmbuild(1) para el mantenimiento de programas, icmake se llama automáticamente y el usuario no tiene que especificar ninguna opción de icmake.

o
--about (-a)
Finaliza icmake después de mostrar información sobre icmake;
o
--compile (-c) [opciones] fuente [archivo-bim]
El script icmake se preprocesa primero (ver la opción --preprocess abajo) y luego el archivo preprocesado es compilado por icm-comp, produciendo un archivo-bim. Si no se especifica el nombre del archivo-bim, se utiliza el nombre base de fuente, con la extensión .bim.
Si fuente es un archivo preprocesado previamente, se puede especificar la opción -P para suprimir su preprocesamiento. Por ejemplo: 
    icmake -c -P fuente destino.bim
Si el archivo-bim existe y es más reciente que fuente, fuente no se compila;
o
--dependencies (-d) [opciones] acción
Se llama al programa icm-dep determinando las dependencias entre clases. Todas las opciones y argumentos que siguen a esta opción se reenvían a icm-dep. Consulte la sección ICM-DEP de esta página del manual para obtener información sobre icm-dep;
o
--execute (-e) [opción] archivo-bim [argumentos]
Ejecuta el archivo-bim. Antes de especificar archivo-bim, se puede especificar la opción --no-version-check (ver abajo, o la opción corta equivalente -n) para permitir incompatibilidades entre la versión principal de icmake y la versión de icmake que se utilizó para compilar el archivo-bim.
Los argumentos de línea de comandos especificados después de archivo-bim se reenvían como argumentos a la función main del archivo-bim (consulte la página del manual icmscript(7) para obtener detalles sobre cómo escribir scripts de icmake);
o
--force (-f) [opciones] fuente [archivo-bim]
Actúa como la opción --compile, pero la compilación se realiza siempre, incluso si el archivo-bim está actualizado;
o
--help (-h)
Finaliza icmake después de proporcionar información de uso. La información de uso también se proporciona cuando icmake se inicia sin argumentos;
o
--multicomp (-m) [opciones] trabajos ’especificación-compilador’
Las opciones opcionales son las opciones que se pasan al programa icm-multicomp (consulte la sección ICM-MULTICOMP abajo).
Consulte también la directiva #define MULTICOMP en la página del manual icomonf(7): cuando se especifica, se utiliza automáticamente la compilación en hilos;
o
--no-process (-N)
Implica la opción --verbose (ver abajo). Esta opción es reconocida por las opciones --dependencies, --execute, --source y -t (ya sea como dos opciones separadas o uniendo ambas opciones, como -Ne). Cuando se especifica, el programa de soporte no se ejecuta, pero los comandos que se habrían utilizado se muestran en la salida estándar;
o
--no-version-check (-n)
Esta opción está disponible con las opciones de acción --execute, --source, --unassemble y -t. Cuando se especifica, las versiones principales almacenadas en el archivo icm-bim especificado y icmake en sí pueden diferir. Esta opción normalmente no debería ser necesaria, pero se añadió principalmente con fines de desarrollo;
o
--preprocess (-p) [opciones] fuente [archivo-pim]
El archivo especificado como primer argumento se preprocesa, produciendo un archivo `.pim`. Si se proporciona un segundo argumento de nombre de archivo, ese archivo se convierte en el archivo .pim. Si no se especifica, se utiliza el primer nombre de archivo, con la extensión .pim.
Con esta opción se pueden utilizar opciones de definición de símbolos del preprocesador: símbolos cuyos valores se pueden usar en fuente. Por ejemplo, al ejecutar el comando 
    icmake -p -d uno --define dos fuente destino.pim
icmake preprocesa fuente, define los símbolos del preprocesador uno y dos (cada uno con valor 1) y produce el archivo pim destino.pim. Tenga en cuenta que en lugar de usar las opciones largas --define, también se pueden usar las opciones cortas -d;
o
--spch (-S) ...
Se crea un SPCH. Todas las opciones y argumentos que siguen a --spch se reenvían al programa de soporte icm-spch. (consulte la sección ICM-SPCH abajo).
Consulte también la directiva #define SPCH en la página del manual icomonf(7): cuando se especifica, se construye automáticamente un SPCH;
o
--source (-s) [opciones] fuente [argumentos]
Icmake utiliza --compile para compilar el archivo fuente de icmake especificado como primer argumento (construyendo un archivo-bim temporal) y luego utiliza --execute para ejecutar el archivo-bim, reenviando cualquier argumento posterior como argumentos a la función main del archivo-bim.
Después de la opción --source, se pueden especificar opciones disponibles para el comando --compile de icmake. Después de esas opciones, se pueden especificar opciones de --execute de icmake. Estas últimas opciones deben ir precedidas de --execute o -e. Por ejemplo, al ejecutar el comando 
    icmake -s -d uno -en fuente
entonces icmake primero compila fuente después de definir el símbolo del preprocesador uno, y luego ejecuta el archivo-bim, pasando --no-version-check a icm-exec;
o
-t especificación-temporal [opciones] fuente [argumentos]
Esta opción está destinada principalmente a los scripts de icmake, aunque también se puede usar en una llamada de línea de comandos de icmake. La opción -t se puede usar de varias maneras diferentes, lo que se cubre en la siguiente sección (EJECUCIÓN DE SCRIPTS ICMAKE).
o
--tmpdir=directorio (-T)
Por defecto, los archivos temporales se crean en el subdirectorio /tmp, o en el directorio del usuario (${HOME}) si no se puede usar /tmp/. Para especificar otro directorio donde escribir archivos temporales, se puede usar la opción --tmpdir de icmake (o -T), seguida del nombre de un directorio (existente) a utilizar para los archivos temporales.
Por ejemplo, al compilar un archivo icmake main.im, la salida del preprocesador de icmake se escribe en un archivo temporal que se elimina después de la compilación. Para escribir el archivo temporal en ~/.icmake, se puede llamar a icmake como 
    icmake -T ~/.icmake -c main.im
o
--unassemble (-u)
El archivo especificado como primer argumento es un archivo bim de icmake, que se desensambla (consulte la sección ICM-UN abajo para obtener más información sobre cómo desensamblar archivos bim de icmake);
o
--verbose (-V)
Los procesos hijos de icmake y sus argumentos se escriben en el flujo de salida estándar antes de ser llamados. Esta opción puede preceder a las opciones de 'acción' (-c, -d, -e, -s y -u), ya sea como dos opciones separadas o uniendo ambas opciones, como -Ve.
o
--version (-v)
Finaliza icmake después de mostrar su versión.

EJECUCIÓN DE SCRIPTS ICMAKE

La opción -t está disponible principalmente para ser utilizada en scripts ejecutables de icmake. La primera línea de los scripts ejecutables de icmake consta de los siguientes componentes:

o
una especificación de shebang (#!) seguida de la ubicación de icmake;
o
la opción -t seguida de su argumento (ver abajo);

y opcionalmente:

o
opciones de compilación y ejecución (especificadas como se describe en la opción --source);
o
un componente que no es una opción (por ejemplo, :) que será reemplazado por la ubicación del script ejecutable de icmake;
o
los componentes restantes en la primera línea se reenvían tal cual a la función main del script de icmake;

Por ejemplo, el siguiente script ejecutable simple de icm `args' podría definirse en ~/bin:

    #!/usr/bin/icmake -t. -d uno : dos --dir tres
    void main(int argc, list argv)
    {
        #ifdef uno
            printf << "uno está definido\n";
        #endif
        printf << argc << " argumentos: " << argv << ’\n’;
    }
Cuando se llama como ~/bin/args cuatro cinco, los argumentos cuatro y cinco se añaden a los argumentos dos --dir tres ya especificados por el propio script. Al llamarlo de esta manera, el script muestra. Su primer argumento es el nombre de un archivo .bim temporal que es diferente en cada nueva llamada: 
    uno está definido
    /tmp/F04dgh dos --dir tres cuatro cinco

El argumento de la opción -t se utiliza para especificar la ubicación de los archivos utilizados por la opción -t de icmake (/dir también se puede especificar como múltiples directorios, como /dir/sub1/sub2):

o
si es un punto simple (-t.), el archivo bim compilado (temporal) se escribe en el directorio de icmake utilizado para archivos temporales (por ejemplo, /tmp o $HOME);
o
si es ~/dir o /dir, entonces icmake escribe archivos temporales en el directorio especificado, reemplazando ~ por el directorio $HOME del usuario;
~/dir/name
o
/dir/name entonces [~]/dir/name especifica la ruta del archivo .bim compilado, escribiendo todos los demás archivos temporales en el mismo directorio que el archivo .bim. El archivo .bim se conserva después de la ejecución (permitiendo que se ejecute repetidamente usando ’ icmake -e’). El script de icmake no se compila si elarchivo .bim es más reciente que el script. --all=archivo (-a)
Llama en secuencia icm -S’s opciones --list, --precompile, y --soft-links (ver más abajo), donde archivo es escrito por la opción --list y usado como argumento de opción para --precompile y --soft-link
s;
o
--classes=nombre_de_archivo (-c)
El archivo nombre_de_archivo es el nombre de un archivo que contiene una lista de directorios inspeccionados por la opción --list (por defecto CLASSES). El directorio superior del proyecto es inspeccionado automáticamente a menos que se especifique la opción --no-t
opdir;
o
--help (-h)
Icmake -S escribe un resumen de su uso en la salida estándar y termina, devolviendo 0 al sistema
operativo;
o
--internal=.ext (-i)
.ext es la extensión usada para los encabezados internos (incluyendo el punto). Por defecto se usa .ih
;
o
--list (-l)
Ignorado cuando se especifica la opción --all.
Escribe los nombres de los archivos a procesar al construir un SPCH en el archivo especificado como icmake -S’s primer argumento de línea de comandos. El nombre de archivo especificado no puede tener una extensión ni especificaciones de directorio (p. ej., spch
);
o
--no-topdir (-n)
Ignora el encabezado interno encontrado en el directorio superior del proyecto. Esta opción se usa cuando, p. ej., se construye simplemente una biblioteca en lugar de un
programa;
o
--precompile=archivo (-p)
Precompila archivo (el nombre del archivo especificado en la opción --list) al archivo SPCH especificado como icmake -S’s primer argumento de línea de comandos. Si ese argumento termina en / entonces se escribe el SPCH ’argumento’archivo.gch.
Por defecto, el SPCH se construye con el siguiente comando (todo en una sola línea): 
    g++ -c -o $2 ${ICMAKE_CPPSTD} -Wall -Werror -O2 -x c++-header $1
Aquí, $1 se reemplaza por ’archivo’, y $2 se reemplaza por el nombre del SPCH, mientras que $ICMAKE_CPPSTD se refiere al valor de la variable de entorno ICMAKE_CPPSTD (especificando el estándar C++ a usar, p. ej., ICMAKE_CPPSTD=--std=c++26).
Alternativamente, el comando que construye el SPCH puede proporcionarse como segundo argumento de línea de comandos, el cual debe estar entre comillas como 
    ’g++ -c -o $2 ’${ICMAKE_CPPSTD}’ -Wall -Werror -O2 -x c++-header $1’

    o
el segundo argumento de línea de comandos puede ser f:archivo, donde archivo es el nombre de un archivo cuya primera línea especifica el comando que construye el SPCH (el cual debe especificar $1 y $2 y opcionalmente $ICMAKE_CPPSTD).
La variable de entorno PATH se usa para localizar el compilador; también se puede usar la ruta absoluta del
compilador.
o
--soft-links=archivo (-s)
Ignorado cuando se especifica la opción --all.
Esta opción usa los mismos argumentos que se usan con la opción --precompile . Esta opción crea enlaces simbólicos .gch desde los archivos de encabezado listados en archivo al archivo SPCH
generado;
o
--unused=regex (-u)
En la práctica, esta opción probablemente no es necesaria, pero los archivos que coinciden con (POSIX extendido) regex no son inspeccionados por icmake -S. Cuando se usan especificaciones como (...)|(...) se pueden usar para especificar múltiples regex. Alternativamente f:archivo se puede usar como argumento de opción para especificar un archivo cuyas líneas no vacías contienen
regex;
o
--version (-v)
Icmake -S escribe su número de versión en la salida estándar y termina, devolviendo 0 al sistema
operativo;
o
--warn (-w)
advierte interactivamente cuando los archivos de encabezado existentes están a punto de ser modificados, aceptando o rechazando las modificaciones. Una vez rechazadas, icm-spch
te
rmina.

Icmake -S necesita uno, y opcionalmente dos argumentos, que fueron descritos en las descripciones de las opciones --list, --precompile, y soft-links

.

Los encabezados precompilados han estado disponibles por bastante tiempo, y usualmente resultan en una reducción significativa del tiempo de compilación. El uso de encabezados precompilados individuales resulta en una gran reducción del espacio en disco requerido en comparación con el uso de encabezados precompilados para directorios

separados.

Al usar SPCHs se evitan encabezados precompilados casi idénticos para directorios separados: solo se construye un encabezado precompilado que es luego usado por todos los componentes de un proyecto. Como se evitan secciones idénticas, los tamaños (y tiempos de construcción) de los SPCHs son mucho más pequeños, usualmente requiriendo solo del 5 al 10 % del espacio (y tiempo de construcción) en comparación con el uso de encabezados precompilados construidos por

separado.

Los SPCHs pueden usarse fácilmente en combinación con icmbuild(1). A menudo, una especificación en un archivo icmconf de un proyecto como #define SPCH "" es todo lo que se necesita (cf. icmcon

f(7
)).

ICM-U

N

El programa de soporte icm-un es llamado por icmake -u, esperando un argumento, un archivo bim. Desensambla el archivo binario y muestra las instrucciones del ensamblador y la estructura del archivo

bim.

Como ilustración, suponga que el siguiente script es compilado por icmake -c demo.im)

: 
    void main()
    {
        printf << "hello world\n";
} el archivo demo.bim resultante es desensamblado por icmake -u demo.bim escribiendo lo siguiente en el archivo de salida estándar: 
    icm-un by Frank B. Brokken (f.b.brokken@rug.nl)

Los desplazamientos se muestran usando el sistema de numeración hexadecimal y son desplazamientos absolutos de bytes en el archivo bim. de operación. Cada línea de código de operación termina mostrando el mnemón
