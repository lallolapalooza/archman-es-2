icmake(1) A program maintenance utility icmake(1)

NOMBRE

icmake - Una utilidad de mantenimiento de programas (make) que utiliza una gramática similar a C

SINOPSIS

icmake opción(es) [origen [destino]] [args]

DESCRIPCIÓN

Icmake(1) es una herramienta genérica para el mantenimiento de programas que puede usarse como alternativa a, por ejemplo, make(1). Es una herramienta genérica en el sentido de que los scripts de icmake, escritos en un lenguaje muy similar al lenguaje de programación C, pueden realizar tareas que tradicionalmente son dominio de los lenguajes de scripting.

Esta página de manual consta de las siguientes secciones:

o
ICMAKE V. 13.00.00 cubre los cambios desde la versión icmake 12.03.00;
o
OPCIONES cubre las opciones de icmake;
o
EJECUCIÓN DE SCRIPTS DE ICMAKE cubre cómo invocar scripts de icmake;
o
ICM-DEP describe el programa de soporte icm-dep;
o
ICM-MULTICOMP describe el programa de soporte icm-multicomp;
o
ICM-SPCH describe el programa de soporte icm-spch;
o
ICM-UN describe el programa de soporte icm-un;
o
ARCHIVOS proporciona una visión general de las ubicaciones de icmake y sus programas de soporte (tal como los usa la distribución Debian Linux);
o
EJEMPLOS contiene referencias a ubicaciones que contienen algunos ejemplos;
o
VÉASE TAMBIÉN contiene referencias a páginas de manual de los programas de soporte de icmake y páginas de manual de programas relacionados con icmake. En particular
o
icmstart(1), describe cómo inicializar un directorio para el desarrollo de programas (en C++ o C);
o
icmbuild(1), cubre cómo usar icmake para el mantenimiento de dichos programas.
o
icmscript(7) cubre la sintaxis y las facilidades del lenguaje de scripting de icmake, permitiéndole escribir sus propios scripts de icmake.

Icmake permite a los programadores usar un lenguaje de scripting (muy similar al conocido lenguaje de programación C) para definir las acciones necesarias para el mantenimiento de programas (complejos). Para esto, icmake ofrece varios operadores especiales así como un conjunto de funciones de soporte que han demostrado su utilidad en el mantenimiento de programas.

Icmake no debe confundirse con un Entorno de Desarrollo Integrado (IDE). Icmake simplemente realiza tareas para las cuales se pueden escribir scripts, y un conjunto mínimo de scripts predefinidos (icmstart e icmbuild) que han demostrado su utilidad al desarrollar y mantener programas se incluyen en la distribución de icmake.

Al usar icmbuild(1) para el mantenimiento de programas se usan los siguientes programas de soporte de icmake:

o
icm-comp compila a byte-code un script de icmake;
o
icm-dep gestiona las dependencias de clases;
o
icm-exec ejecuta un script de icmake compilado a byte-code;
o
icm-multicomp (opcionalmente) usa compilación de archivos fuente multihilo;
o
icm-pp preprocesa un script de icmake;
o
icm-spch (opcionalmente) construye un archivo de Encabezado Precompilado Único (SPCH) para todo el proyecto.

Además de los programas anteriores, el proyecto icmake proporciona

o
el programa icmodmap puede usarse al desarrollar programas C++ que usan módulos (cf. la página de manual icmodmap(1));
o
icm-un desensambla archivos de byte-code compilados de icmake (los `archivos-bim’). icm-un se usa principalmente para ilustración, educación y depuración y es invocado por icmake al especificar su opción --unassemble o -u (véase también la sección ICMUN).

Algunas utilidades de make por defecto recompilan las fuentes una vez que los archivos de encabezado se modifican. Al desarrollar programas C++ esto a menudo no es necesario, ya que agregar nuevas funciones miembro a las clases no requiere la recompilación de todos los archivos fuente de esas clases. Las dependencias de clases son inspeccionadas opcionalmente por icmbuld(1) (se inspeccionan cuando las directivas #define USE_ALL, SPCH y/o (ahora obsoleta) PRECOMP en el archivo icmconf están activadas (cf. la página de manual icmconf(7) para más detalles).

ICMAKE V. 13.00.00

En la versión 13.00.00 de icmake se implementaron las siguientes modificaciones con respecto a su versión 12.03.00:

o
se añadió la opción --all (-a) al programa icm-spch, que realiza en secuencia las acciones de sus opciones --list, --precompile, y --soft-link. Varias opciones existentes fueron modificadas. Consulte la sección ICM-SPH para más detalles.
o
las cabeceras (internas) inspeccionadas por icmake --spch (o -S) ya no se modifican.
o
para eliminar las especificaciones #ifndef SPCH_ (ahora obsoletas) de los archivos listados en archivos spch existentes escritos por versiones anteriores de icm-spch, el programa noifndef.cc, disponible en la distribución del código fuente de icmake en su subdirectorio support/, puede usarse para eliminar secciones #ifnef SPCH_ existentes de los archivos .ih de un proyecto;
o
icmake --source compila el script de icmake a un archivo .bim temporal;
o
el programa de soporte icmun fue renombrado a icm-un (invocado por icmake al especificar la opción --unassemble (-u), por lo que en la práctica el cambio de nombre se gestiona automáticamente).
o
El script icmconf(7) puede usar -o en su especificación #define SPCH. Todas las palabras (delimitadas por caracteres de espacio) que siguen a -o se pasan a icm-spch como opciones separadas `-o word’;
o
Al desarrollar programas en C++ ya no se usa la variable de entorno ICMAKE_CXXFLAGS. En su lugar se usa la variable de entorno ICMAKE_CPPSTD. Use esta última variable de entorno para definir un único punto de mantenimiento que especifique la versión del estándar C++ usada al compilar fuentes;
o
Al usar Debian (o una distribución comparable) el script ’rebuild’ puede usarse para reconstruir los binarios de icmake tras instalar ’libbobcat-dev’, lo que resulta en una reducción de sus tamaños de aproximadamente el 40%.
o
El propio programa icmake fue rediseñado.

OPCIONES

Cuando estén disponibles, las opciones de una sola letra se muestran entre paréntesis después de sus variantes de opción larga asociadas. Icmake define opciones de acción y opciones de no acción. Se utiliza la primera opción de acción que se encuentre.

Cuando se usa icmbuild(1) para el mantenimiento de programas se llama automáticamente a icmake, y el usuario no tiene que especificar ninguna opción de icmake.

o
--about (-a)
Finaliza icmake después de mostrar alguna información sobre icmake;
o
--compile (-c) [opciones] fuente [archivo-bim]
El script de icmake se preprocesa primero (véase la opción --preprocess más abajo), tras lo cual el archivo preprocesado es compilado por icm-comp produciendo un archivo-bim. Si no se especifica el nombre del archivo-bim entonces se usa el nombre base de fuente, recibiendo la extensión .bim.
Si fuente es un archivo preprocesado previamente, entonces se puede especificar la opción -P para suprimir su preprocesamiento. Por ejemplo, 
    icmake -c -P fuente destino.bim
Si el archivo bim existe y es más reciente que fuente, entonces fuente no se compila;
o
--dependencies (-d) [opciones] acción
Se llama al programa icm-dep determinando las dependencias entre clases. Todas las opciones y argumentos que siguen a esta opción se reenvían a icm-dep. Consulte la sección ICM-DEP de esta página de manual para obtener información sobre icm-dep;
o
--execute (-e) [opción] archivo-bim [argumentos]
Ejecuta el archivo-bim. Antes de especificar archivo-bim se puede especificar la opción --no-version-check (véase más abajo, o la opción corta equivalente -n) para permitir discrepancias entre la versión principal de icmake y la versión de icmake que se usó para compilar el archivo-bim.
Los argumentos de línea de comandos especificados después de archivo-bim se reenvían como argumentos a la función main del archivo-bim (cf. la página de manual icmscript(7) para detalles sobre cómo escribir scripts de icmake);
o
--force (-f) [opciones] fuente [archivo-bim]
Actúa como la opción --compile, pero la compilación siempre se realiza, incluso si el archivo-bim está actualizado;
o
--help (-h)
Finaliza icmake después de proporcionar información de uso. También se proporciona información de uso cuando se inicia icmake sin argumentos;
o
--multicomp (-m) [opciones] trabajos 'especificación-de-compilador'
Las opciones opcionales son las opciones pasadas al programa icm-multicomp (cf. la sección ICM-MULTICOMP más abajo).
Véase también la directiva #define MULTICOMP de la página de manual icomonf(7): cuando se especifica, se usa automáticamente la compilación con hilos;
o
--no-process (-N)
Implica la opción --verbose (véase más abajo). Esta opción es reconocida por las opciones --dependencies, --execute, --source y -t (ya sea como dos opciones separadas o 'pegando' ambas opciones, como -Ne). Cuando se especifica, el programa de soporte no se ejecuta, pero el/los comando(s) que se habrían usado se muestran en la salida estándar;
o
--no-version-check (-n)
Esta opción está disponible con las opciones de acción --execute, --source, --unassemble, y -t. Cuando se especifica, las versiones principales almacenadas en el archivo icm-bim especificado y en icmake mismo pueden diferir. Normalmente esta opción no debería ser necesaria, pero se añadió principalmente con fines de desarrollo;
o
--preprocess (-p) [opciones] fuente [archivo-pim]
El archivo especificado como primer argumento se preprocesa, produciendo un archivo `.pim'. Si se proporciona un segundo argumento de nombre de archivo, entonces ese archivo se convierte en el archivo .pim. Si no se especifica, entonces se usa el primer nombre de archivo, con la extensión .pim.
Con esta opción se pueden usar opciones de definición de símbolos del preprocesador: símbolos cuyos valores se pueden usar en fuente. Por ejemplo, al emitir el comando 
    icmake -p -d uno --define dos fuente destino.pim
icmake preprocesa fuente, define los símbolos del preprocesador uno y dos (cada uno con valor 1), y produce el archivo pim destino.pim. Tenga en cuenta que en lugar de usar las opciones largas --define también se pueden usar las opciones cortas -d;
o
--spch (-S) ...
Se construye un SPCH. Todas las opciones y argumentos que siguen a --spch se reenvían al programa de soporte icm-spch. (cf. la sección ICM-SPCH más abajo).
Véase también la directiva #define SPCH de la página de manual icomonf(7): cuando se especifica, se construye automáticamente un SPCH;
o
--source (-s) [opciones] fuente [argumentos]
Icmake usa --compile para compilar el archivo fuente de icmake especificado como primer argumento (construyendo un archivo-bim temporal) y luego usa --execute para ejecutar el archivo-bim, reenviando cualquier argumento posterior como argumentos a la función main del archivo-bim.
Después de la opción --source se pueden especificar opciones disponibles para el comando --compile de icmake. Después de esas opciones se pueden especificar opciones del comando --execute de icmake. Esas últimas opciones deben ir precedidas por --execute o -e. Por ejemplo, al emitir el comando 
    icmake -s -d uno -en fuente
entonces icmake primero compila fuente después de definir el símbolo del preprocesador uno, y luego ejecuta el archivo-bim, pasando --no-version-check a icm-exec
Cuando simplemente se compilan archivos fuente de icmake (usando icmake -c) el archivo compilado recibe por defecto la extensión .bim. Pero cuando se usa icmake -s se usan archivos temporales que se eliminan después de ejecutar el archivo binario construido. Cuando se encuentran errores de compilación se informa el nombre del archivo temporal. Consta de tres partes: el directorio que recibe los archivos temporales de icmake; el nombre de archivo del script de icmake que se pasa a icmake -s; y una extensión aleatoria de 6 caracteres. Por ejemplo, al llamar a icmake -s script los mensajes de error pueden referirse a /tmp/script.2JS49A;
o
-t especificación-tmp [opciones] fuente [argumentos]
Esta opción está pensada para scripts de icmake aunque también se puede usar en una llamada de icmake desde la línea de comandos. La opción -t se puede usar de bastantes formas diferentes, lo cual se cubre en la siguiente sección (EJECUTAR SCRIPTS DE ICMAKE).
o
--tmpdir=directorio (-T)
Por defecto, los archivos temporales se crean en el subdirectorio /tmp, o en el directorio home del usuario (${HOME}) si no se puede usar /tmp/. Para especificar otro directorio donde escribir archivos temporales se puede especificar la opción --tmpdir (o -T) de icmake, seguida del nombre de un directorio (existente) que se usará para archivos temporales.
Por ejemplo, al compilar un archivo de icmake main.im, la salida del preprocesador de icmake se escribe en un archivo temporal que se elimina después de la compilación. Para escribir el archivo temporal en ~/.icmake se puede llamar a icmake como 
    icmake -T ~/.icmake -c main.im
o
--unassemble (-u)
El archivo especificado como primer argumento es un archivo-bim de icmake, que se desensambla (cf. la sección ICM-UN más abajo para más información sobre el desensamblado de archivos-bim de icmake);
o
--verbose (-V)
Los procesos hijos de Icmake y sus argumentos se escriben en el flujo de salida estándar antes de que se llamen. Esta opción puede preceder a las opciones de 'acción' (-c, -d, -e, -s y -u), ya sea como dos opciones separadas o 'pegando' ambas opciones, como -Ve.
o
--version (-v)
Finaliza icmake después de mostrar su versión.

EJECUTANDO SCRIPTS DE ICMAKE

La opción -t está disponible principalmente para ser usada en scripts ejecutables de icmake. La primera línea de los scripts ejecutables de icmake consta de los siguientes componentes:

o
una especificación shebang (#!) seguida de la ubicación de icmake;
o
la opción -t seguida de su argumento (ver más abajo);

y opcionalmente:

o
opciones de compilación y ejecución (especificadas como se describe en la opción --source);
o
un componente no-opción (por ejemplo, :) que será reemplazado por la ubicación del script ejecutable de icmake;
o
los componentes restantes en la primera línea se reenvían tal cual a la función main del script de icmake;

Por ejemplo, el siguiente script ejecutable icm simple `args’ podría definirse en ~/bin:

    #!/usr/bin/icmake -t. -d one : two --dir three
    void main(int argc, list argv)
    {
        #ifdef one
            printf << "one is defined\n";
        #endif
        printf << argc << " arguments: " << argv << ’\n’;
    }
Cuando se llama como ~/bin/args four five, entonces los argumentos four y five se añaden a los argumentos two --dir three ya especificados por el propio script. Llamado de esta manera, el script genera. Su primer argumento es el nombre de un archivo .bim temporal cuya extensión final es diferente en cada nueva llamada (ver también el párrafo final de esta sección): 
    one is defined
    /tmp/args.F04dgh two --dir three four five

El argumento de la opción -t se usa para especificar la ubicación de los archivos usados por la opción -t de icmake (/dir también puede especificarse como múltiples directorios, como /dir/sub1/sub2):

o
si es un único punto (-t.) el archivo bim compilado (temporal) se escribe en el directorio de icmake usado para archivos temporales (por ejemplo, /tmp o $HOME);
o
si es ~/dir o /dir entonces icmake escribe archivos temporales en el directorio especificado, reemplazando ~ por el directorio $HOME del usuario;
o
si es ~/dir/name o /dir/name entonces [~]/dir/name especifica la ruta del archivo .bim compilado, escribiendo todos los demás archivos temporales en el mismo directorio que el archivo .bim. El archivo .bim se conserva después de la ejecución (permitiendo que se ejecute repetidamente usando ’icmake -e’). El script de icmake no se compila si el archivo .bim es más reciente que el script.

Al ejecutar scripts de icmake (ya sea usando scripts ejecutables #/bin/icmake que llaman explícitamente a icmake -t) los scripts preprocesados y normalmente el script compilado son archivos temporales que se usan y que se eliminan después de ejecutar el archivo binario construido. Cuando se encuentran errores, se informa el nombre del archivo temporal que contiene los errores. Esos archivos temporales constan de tres partes: el directorio que recibe los archivos temporales de icmake; el nombre del archivo del script de icmake que se pasa a icmake -s; y una extensión aleatoria de 6 caracteres. Por ejemplo, al ejecutar un script como showfiles (usando #!/bin/icmake -t .) y el script contiene errores, entonces los mensajes de error pueden referirse a /tmp/showfiles.2JS47P;)

ICM-DEP

Icm-dep es un programa de soporte invocado por icmake --dependencies (o su alternativa corta -d) para determinar las dependencias de archivos fuente y de encabezados precompilados.

Al usar icmbuild(1) y si un archivo icmconf contiene la directiva #define SPCH, no se usa icmake -d; en su lugar, los directorios inspeccionados al usar un SPCH son inspeccionados automáticamente (y actualizados cuando es necesario) por icmake -S.

La sinopsis de Icmake -d es

    icmake -d [opciones] argumento
Las especificaciones que siguen a -d se reenvían a icm-dep. Las siguientes opciones se pueden especificar después de -d:
o
--classes=nombredearchivo (-c)
Por defecto, icm-dep inspecciona las dependencias de los directorios mencionados en el archivo CLASSES. Si el archivo icmconf(7) especifica PARSER_DIR y/o SCANNER_DIR, entonces esos directorios también se consideran. Use esta opción para especificar el archivo que contiene los nombres de los directorios que debe inspeccionar icm-dep.
o
--gch
Si un archivo icmconf especifica la directiva (obsoleta) #define PRECOMP, entonces icmake -d comprueba si se deben actualizar los encabezados precompilados. Si un archivo icmconf no contiene una directiva #define PRECOMP, pero aun así se deben inspeccionar los encabezados precompilados, entonces se puede especificar la opción --gch;
o
--help (-h)
Se escribe un resumen del uso de icm-dep en la salida estándar y icmake termina, devolviendo 0 al sistema operativo;
o
--icmconf=nombredearchivo (-i)
Por defecto, icmake -d inspecciona el contenido de los archivos icmconf. Esta opción se usa si, en lugar de icmconf, se debe inspeccionar otro archivo;
o
--mainih=encabezadoprincipal (-m)
En el archivo icmconf se usa la directiva #define IH para especificar el sufijo de los archivos de encabezado de clase que se deben precompilar, suponiendo que sus nombres de archivo son iguales a los nombres de los directorios que se enumeran en el archivo CLASSES. Pero CLASSES no especifica el nombre del directorio de nivel superior del programa. Esta opción se usa para especificar el nombre del archivo de encabezado de nivel superior que se va a precompilar. Por defecto se usa main.ih;
o
--no-gch
Si un archivo icmconf contiene una directiva (obsoleta) #define PRECOMP pero icmake -d no debe comprobar si se deben actualizar los encabezados precompilados, entonces especifique la opción --no-gch;
o
--no-use-all
Si se especifica esta opción, entonces se ignora la directiva #define USE_ALL "nombredearchivo" en el archivo icmconf (cf. icmconf(7));
o
--use-all=nombredearchivo
Si se especifica esta opción, entonces se recompilan todos los archivos de los directorios que contienen el archivo nombredearchivo y los archivos fuente de los directorios que dependen (recursivamente) de los archivos de esos directorios;
o
--verbose (-V)
Esta opción se puede especificar varias veces. El número de veces que se especifica determina la verbosidad de la salida de icmake -d. Si no se especifica, entonces icmake -d realiza sus tareas silenciosamente. Si se especifica una vez (que es la especificación predeterminada), entonces icmake -d escribe en la salida estándar las acciones que realiza; si se especifica dos veces, también informa las opciones no predeterminadas y los directorios incluidos automáticamente; si se especifica tres veces, también informa las dependencias de clase; si se especifica más veces, informa qué archivos encontró y qué decisión tomaría cuando se especificara go;
o
--version (-v)
Icmake -d escribe el número de versión de icm-dep en la salida estándar y termina, devolviendo 0 al sistema operativo.

Después de las opciones no terminantes se debe especificar el argumento go para permitir que icmake -d realice sus acciones. Especificar otro argumento da como resultado una `ejecución en seco': analiza las dependencias, pero no eliminará ni tocará archivos.

Icmake -d se puede usar para proyectos de software que se desarrollan como se describe en las Anotaciones de C++, sección Organización de archivos de encabezado en el capítulo Clases. Para esos proyectos, las clases se desarrollan en sus propios directorios, que son subdirectorios directos del directorio del programa principal del proyecto. Sus interfaces de clase se proporcionan en archivos de encabezado de clase que llevan los nombres de los directorios de clase, y todos los encabezados requeridos por las fuentes de la clase se declaran en un archivo separado encabezado interno, que comúnmente tiene extensiones .ih.

ICM-MULTICOMP

Icmake admite la compilación de archivos fuente multihilo, lo que a menudo reduce significativamente el tiempo de compilación de los archivos fuente de los proyectos. Al usar icmbuild(1), la compilación multihilo se usa automáticamente cuando los archivos icmconf contienen la directiva #define MULTICOMP (cf. icmconf(7)). También se puede invocar de forma independiente de icmconf usando la opción --multicomp (o -m) de icmake.

La sinopsis de Icmake -m es

    icmake -m [opciones] argumentos

Icmake -m acepta las siguientes opciones:

o
--help (-h)
Icmake -m escribe un resumen de su uso en la salida estándar y termina, devolviendo 0 al sistema operativo;
o
--nr (-n)
Cuando se compilan archivos fuente y se especifica la opción --nr, entonces el número de hilo que compila un archivo fuente se escribe en el flujo de salida estándar.
o
--quiet (-q)
Cuando esta opción no se especifica, entonces las rutas de los archivos objeto y fuente compilados se escriben en el flujo de salida estándar. Cuando se especifica una vez, solo los directorios y nombres de archivo de los archivos fuente se escriben en el flujo de salida estándar, y cuando se especifica más de una vez, no se escribe información sobre los archivos compilados en el flujo de salida estándar.
o
--threads=nThreads (-t)
Por defecto, el número de núcleos del equipo determina el número de hilos que se usan al compilar los archivos fuente. Se puede solicitar un número diferente de hilos usando esta opción, p. ej., --threads 5.
o
--version (-v)
Icmake -m informa su número de versión en la salida estándar y termina, devolviendo 0 al sistema operativo.

Icmake -m necesita un argumento de línea de comandos y un segundo argumento opcional:

o
el primer argumento es el nombre del archivo que especifica qué archivos deben compilarse. Use icmbuild(1) para escribir este archivo. También se puede construir de otra manera:
El archivo especificado debe contener grupos de especificaciones de archivos donde cada grupo comienza con una línea como : support tmp/o 5 donde el 2.º elemento (aquí: support) especifica el (sub)directorio de los archivos fuente (use . para referirse al directorio de nivel superior del proyecto); el 3.er elemento (aquí: tmp/o) especifica el directorio de destino de los archivos compilados (que se crea si no existe); y el 4.º elemento (aquí: t) especifica el prefijo que se añade delante de los archivos objeto compilados.
Tras esta línea, las líneas restantes de un grupo especifican los nombres de los archivos fuente (ubicados en el (sub)directorio especificado) a compilar.
Una vez que termina la compilación (ya sea porque todos los archivos se compilaron correctamente, o porque falló una compilación), el archivo de especificación se elimina;
o
el segundo argumento es opcional. Por defecto se usa la siguiente especificación (todo en una línea) 
    g++ -c -o $2 ${ICMAKE_CPPSTD} --Wall -Werror $1
Aquí $1 se reemplaza por la ubicación del archivo fuente a compilar y $2 se reemplaza por la ubicación del archivo objeto compilado. Si la variable de entorno ICMAKE_CPPSTD está definida (especificando el estándar C++ a usar, p. ej., ICMAKE_CPPSTD=--std=c++26), entonces su valor reemplaza a ${ICMAKE_CPPSTD} en la especificación.
Si no se puede usar la especificación de compilador predeterminada, el comando para compilar archivos fuente se puede proporcionar como el segundo argumento de línea de comandos de icmake -m, que debe ir entre comillas, como 
    ’g++ -c -o $2 ’${ICMAKE_CPPSTD}’ --Wall -Werror $1’
o el segundo argumento de línea de comandos puede ser f:file, donde file es el nombre de un archivo cuya primera línea contiene la especificación del comando que compila archivos fuente (que debe especificar $1 y $2 y opcionalmente $ICMAKE_CPPSTD).
La variable de entorno PATH se usa para localizar el compilador; también se puede especificar la ruta absoluta del compilador.

ICM-SPCH

Los Encabezados Precompilados Únicos (SPCH, por sus siglas en inglés) están disponibles usando icmake --spch (o -S).

La sinopsis de Icmake -S es

    icmake -S [opciones] argumentos

Icmake -S acepta las siguientes opciones:

o
--all=archivo (-a)
Llama en secuencia a las opciones --list, --precompile y --soft-links de icm -S (ver más abajo), donde archivo es escrito por la opción --list y usado como argumento de las opciones --precompile y --soft-links. Icmake -S --all archivo puede ir opcionalmente seguido de uno o dos argumentos. Cuando se proporciona, el primer argumento define la ubicación del archivo SPCH; el segundo argumento define el (archivo que contiene el) comando del compilador usado para construir el SPCH. Ver la opción --precompile (más abajo) para detalles.
o
--classes=nombrearchivo (-c)
El archivo nombrearchivo es el nombre de un archivo que contiene una lista de directorios inspeccionados por la opción --list (por defecto CLASSES). El directorio superior del proyecto se inspecciona automáticamente a menos que se especifique la opción --no-topdir;
o
--help (-h)
Icmake -S escribe un resumen de su uso en la salida estándar y termina, devolviendo 0 al sistema operativo;
o
--internal=.ext (-i)
.ext es la extensión usada para los encabezados internos (incluyendo el punto). Por defecto se usa .ih;
o
--list (-l)
Se ignora cuando se especifica la opción --all.
Escribe los nombres de los archivos a procesar al construir un SPCH en el archivo especificado como el primer argumento de la línea de comandos de icmake -S. El nombre de archivo especificado no puede tener extensión ni especificaciones de directorio (por ejemplo, spch);
o
--no-topdir (-n)
Ignora el encabezado interno encontrado en el directorio superior del proyecto. Esta opción se usa cuando, por ejemplo, simplemente se construye una biblioteca en lugar de un programa;
o
--option=opt (-o)
opción extra añadida a las opciones del compilador cuando se solicita --precompile. La opción opt se inserta antes de la especificación de opción del compilador -x (ver la siguiente opción --precompile). Se pueden especificar múltiples opciones --option.
o
--precompile=archivo (-p)
Precompila archivo (el nombre del archivo especificado en la opción --list) al archivo SPCH especificado como el primer argumento de la línea de comandos de icmake -S. Si ese argumento termina en / entonces se escribe el SPCH ’argumento’archivo.gch.
Por defecto el SPCH se construye usando el siguiente comando (todo en una línea): 
g++ -c -o $2 ${ICMAKE_CPPSTD} -Wall -Werror -O2 -x c++-header $1
Aquí, $1 se reemplaza por ’archivo’, y $2 se reemplaza por el nombre del SPCH, mientras que $ICMAKE_CPPSTD se refiere al valor de la variable de entorno ICMAKE_CPPSTD (que especifica el estándar C++ a usar, por ejemplo, ICMAKE_CPPSTD=--std=c++26).
Alternativamente, el comando que construye el SPCH puede proporcionarse como segundo argumento de la línea de comandos, que debe ir entre comillas. Por ejemplo, (en una línea): 
’g++ -c -o $2 ’${ICMAKE_CPPSTD}’ -Wall -Werror -O2 
                                            -x c++-header $1’
o el segundo argumento de la línea de comandos puede ser f:archivo, donde archivo es el nombre de un archivo cuya primera línea especifica el comando que construye el SPCH (que debe especificar $1 y $2 y opcionalmente $ICMAKE_CPPSTD).
La variable de entorno PATH se usa para localizar el compilador; también se puede usar la ruta absoluta del compilador.
o
--quiet (-q)
Por defecto el comando (g++) que construye el archivo de encabezado precompilado único se muestra en el flujo de salida estándar. Especifique esta opción para suprimir la escritura del comando en el flujo de salida estándar.
o
--soft-links=archivo (-s)
Se ignora cuando se especifica la opción --all.
Esta opción usa los mismos argumentos que se usan con la opción --precompile. Esta opción crea enlaces simbólicos .gch desde los archivos de encabezado listados en archivo al archivo SPCH generado;
o
--unused=regex (-u)
En la práctica esta opción probablemente no sea necesaria, pero los archivos que coinciden con la regex (extendida POSIX) no son inspeccionados por icmake -S. Cuando se usa, se pueden emplear especificaciones como (...)|(...) para especificar múltiples regexes. Alternativamente se puede usar f:archivo como argumento de la opción para especificar un archivo cuyas líneas no vacías contienen regexes;
o
--version (-v)
Icmake -S escribe su número de versión en la salida estándar y termina, devolviendo 0 al sistema operativo;
o
--warn (-w)
advierte interactivamente cuando los archivos de encabezado existentes están a punto de ser modificados, aceptando o rechazando las modificaciones. Una vez rechazadas, icm-spch termina.

Icmake -S necesita uno, y opcionalmente dos argumentos, que fueron descritos en las descripciones de las opciones --list, --precompile y soft-links.

Los encabezados precompilados han estado disponibles desde hace bastante tiempo, y generalmente resultan en una reducción significativa del tiempo de compilación. Usar encabezados precompilados únicos resulta en una gran reducción del espacio en disco requerido en comparación con usar encabezados precompilados para directorios separados.

Al usar SPCHs se evitan encabezados precompilados casi idénticos para directorios separados: solo se construye un encabezado precompilado que es luego usado por todos los componentes de un proyecto. Como se evitan las secciones idénticas, los tamaños (y tiempos de construcción) de los SPCHs son mucho menores, generalmente requiriendo solo del 5 al 10 % del espacio (y tiempo de construcción) en comparación con usar encabezados precompilados construidos por separado.

Los SPCHs pueden usarse fácilmente en combinación con icmbuild(1). A menudo una especificación en el archivo icmconf de un proyecto como #define SPCH "" es todo lo que se necesita (cf. icmconf(7)).

ICM-UN

El programa de soporte icm-un es invocado por icmake -u, esperando un argumento, un archivo bim. Desensambla el archivo binario y muestra las instrucciones del ensamblador y la estructura del archivo bim.

A modo de ilustración, suponga que el siguiente script es compilado por icmake -c demo.im):

    void main()
    {
        printf << "hello world\n";
    }
el archivo resultante demo.bim es desensamblado por icmake -u demo.bim escribiendo lo siguiente en el archivo de salida estándar: 
    icm-un by Frank B. Brokken (f.b.brokken@rug.nl)
    icm-un V12.04.00
    Copyright (c) GPL 1992-2024. NO WARRANTY.
    Binary file statistics:
        strings      at offset  0x0025
        variables    at offset  0x0033
        filename     at offset  0x0033
        code         at offset  0x0014
        first opcode at offset  0x0021
    String constants dump:
        [0025 (0000)] ""
        [0026 (0001)] "hello world."
    Disassembled code:
        [0014] 06 01 00   push string "hello world."
        [0017] 05 01 00   push int 0001
        [001a] 1b 1d      callrss 1d (printf)
        [001c] 1c 02      add sp, 02
        [001e] 04         push int 0
        [001f] 24         pop reg
        [0020] 23         ret
        [0021] 21 14 00   call [0014]
        [0024] 1d         exit

Los desplazamientos se muestran usando el sistema numérico hexadecimal y son desplazamientos de bytes absolutos en el archivo bim. El volcado de constantes de cadena también muestra, entre paréntesis, los desplazamientos de las cadenas individuales relativos al comienzo de la sección de cadenas. La salida también muestra los códigos de operación de las instrucciones de los archivos fuente .im compilados. Si los códigos de operación usan argumentos, entonces esos valores de argumento se muestran después de sus códigos de operación. Cada línea de código de operación termina mostrando el mnemónico del código de operación más (si corresponde) la naturaleza de su argumento.

ARCHIVOS

Las rutas mencionadas son las que se utilizan en la distribución del código fuente y son usadas por la distribución Debian Linux. Sin embargo, son solo sugerentes y pueden haber sido configuradas de manera diferente:

Programas binarios:

o
/usr/bin/icmake: el programa principal icmake;
o
/usr/bin/icmbuild: el programa envoltorio alrededor del script icmbuild que maneja el mantenimiento estándar de programas;
o
/usr/bin/icmodmap: el mapeador de módulos que inicializa el mantenimiento de programas C++ usando módulos;
o
/usr/bin/icmstart: un script de icmake que se puede usar para crear los archivos de inicio de nuevos proyectos;

Programas de soporte:

o
/usr/libexec/icmake/icm-comp: el compilador llamado por icmake;
o
/usr/libexec/icmake/icm-dep: el programa de soporte que maneja las dependencias de clases;
o
/usr/libexec/icmake/icm-exec: el intérprete de código de bytes;
o
/usr/libexec/icmake/icm-multicomp: el compilador de archivos fuente multihilo;
o
/usr/libexec/icmake/icm-pp: el preprocesador llamado por icmake;
o
/usr/libexec/icmake/icm-spch: el programa que prepara SPCHs;
o
/usr/libexec/icmake/icm-un: el desensamblador de icmake.
