ICONV(1P) Manual del Programador POSIX ICONV(1P)

PRÓLOGO

Esta página manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página manual de Linux correspondiente para detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

iconv — conversión de juego de caracteres

SINOPSIS

iconv [-cs] -f frommap -t tomap [file...]
iconv -f fromcode [-cs] [-t tocode] [file...]
iconv -t tocode [-cs] [-f fromcode] [file...]
iconv -l

DESCRIPCIÓN

La utilidad iconv convertirá la codificación de los caracteres en file de un juego de caracteres a otro y escribirá los resultados en la salida estándar.

Cuando las opciones indican que se utilizan archivos charmap para especificar los juegos de caracteres (ver OPCIONES), la conversión del juego de caracteres se realizará mediante la realización de una unión lógica sobre los nombres simbólicos de caracteres en los dos charmaps. La implementación no necesita soportar el uso de archivos charmap para la conversión de juegos de caracteres a menos que el símbolo POSIX2_LOCALEDEF esté definido en el sistema.

OPCIONES

La utilidad iconv deberá cumplir con la Volumen de Definiciones Básicas de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades.

Se deberán soportar las siguientes opciones:

-c
Omitir del resultado cualquier carácter que sea inválido en el juego de caracteres del archivo de entrada. Cuando -c no se utiliza, los resultados de encontrar caracteres inválidos en el flujo de entrada (ya sean aquellos que no son caracteres en el juego de caracteres del archivo de entrada o que no tienen un carácter correspondiente en el juego de caracteres del archivo de salida) se especificarán en la documentación del sistema. La presencia o ausencia de -c no afectará el estado de salida de iconv.
-ffromcodeset

Identificar el juego de caracteres del archivo de entrada. La implementación reconocerá las siguientes dos formas del fromcodeset argumento de opción:
fromcode
El fromcode argumento de opción no debe contener un carácter <barra invertida>. Se interpretará como el nombre de una de las descripciones de juegos de caracteres proporcionadas por la implementación en un formato no especificado. Los valores válidos de fromcode están definidos por la implementación.
frommap
El frommap argumento de opción debe contener un carácter <barra invertida>. Se interpretará como la ruta de acceso a un archivo charmap como se define en el Volumen de Definiciones Básicas de POSIX.1‐2017, Sección 6.4, Archivo de Descripción del Juego de Caracteres. Si la ruta de acceso no representa un archivo charmap válido y legible, los resultados son indefinidos.

Si esta opción se omite, se utilizará el juego de caracteres de la configuración regional actual.

-l
Escribir todos los valores soportados de fromcode y tocode a la salida estándar en un formato no especificado.
-s
Suprimir cualquier mensaje escrito a la salida de error estándar concerniente a caracteres inválidos. Cuando -s no se utiliza, los resultados de encontrar caracteres inválidos en el flujo de entrada (ya sean aquellos que no son caracteres válidos en el juego de caracteres del archivo de entrada o que no tienen un carácter correspondiente en el juego de caracteres del archivo de salida) se especificarán en la documentación del sistema. La presencia o ausencia de -s no afectará el estado de salida de iconv.
-ttocodeset
Identificar el juego de caracteres a ser utilizado para el archivo de salida. La implementación reconocerá las siguientes dos formas del tocodeset argumento de opción:
tocode
La semántica será equivalente a la -f fromcode opción.
tomap
La semántica será equivalente a la -f frommap opción.

Si esta opción se omite, se utilizará el juego de caracteres de la configuración regional actual.

Si cualquiera de -f o -t representa un archivo charmap, pero el otro no (o se omite), o si tanto -f como -t se omiten, los resultados son indefinidos.

OPERANDOS

Se deberá soportar el siguiente operando:

file
Una ruta de acceso a un archivo de entrada. Si no se especifican operandos file , o si un operando file es '-', se utilizará la entrada estándar.

ENTRADA ESTÁNDAR

La entrada estándar se utilizará solo si no se especifican operandos file , o si un operando file es '-'.

ARCHIVOS DE ENTRADA

El archivo de entrada será un archivo de texto.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de iconv:

LANG
Proporcionar un valor por defecto para las variables de internacionalización que no están definidas o son nulas. (Ver el Volumen de Definiciones Básicas de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en oposición a múltiples bytes en argumentos). Durante la traducción del archivo, esta variable es reemplazada por el uso del fromcode argumento de opción.
LC_MESSAGES

Determinar la configuración regional que debe usarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos a la salida de error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Por defecto.

SALIDA ESTÁNDAR

Cuando se utiliza la opción -l , la salida estándar contendrá todos los valores soportados de fromcode y tocode , escritos en un formato no especificado.

Cuando no se utiliza la opción -l , la salida estándar contendrá la secuencia de caracteres leída de los archivos de entrada, traducida al juego de caracteres especificado. No se escribirá nada más en la salida estándar.

SALIDA DE ERROR ESTÁNDAR

La salida de error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

0
Finalización exitosa.
>0
Ocurrió un error.

Por defecto.

Las siguientes secciones son informativas.

APLICACIÓN DEL USO

El usuario debe asegurarse de que ambos archivos charmap usen los mismos nombres simbólicos para los caracteres que ambos juegos de caracteres tienen en común.

EJEMPLOS

El siguiente ejemplo convierte el contenido del archivo mail.x400 del juego de caracteres del estándar ISO/IEC 6937:2001 al juego de caracteres del estándar ISO/IEC 8859‐1:1998, y almacena los resultados en el archivo mail.local:

iconv -f IS6937 -t IS8859 mail.x400 > mail.local

JUSTIFICACIÓN

El iconv utilidad solo puede usarse de forma portátil cuando el usuario proporciona dos archivos charmap como argumentos de opción. Esto se debe a que un único charmap proporcionado por el usuario no puede unirse de forma fiable con los nombres de una descripción de conjunto de caracteres proporcionada por el sistema. Los valores válidos para fromcode y tocode están definidos por la implementación y no tienen que tener ninguna relación con los mecanismos de charmap. Como ayuda a los usuarios interactivos, la -l opción se adoptó del sistema operativo Plan 9. Esta escribe información concerniente a estos valores definidos por la implementación. El formato no está especificado porque hay muchos formatos útiles posibles que podrían elegirse, como una matriz de combinaciones válidas de fromcode y tocode. La -l opción no está destinada al uso en scripts de shell; las aplicaciones conformes tendrán que usar charmaps.

La iconv utilidad puede soportar la conversión entre ASCII y codificaciones basadas en EBCDIC, pero no se requiere que lo haga. En una implementación conforme a XSI, la dd utilidad es el único método garantizado para soportar la conversión entre estos dos conjuntos de caracteres.
