IFRENAME(8) Manual del programador de Linux IFRENAME(8)

NOMBRE

ifrename - renombra interfaces de red basándose en varios criterios estáticos

SINOPSIS

ifrename [-c archivo_config] [-p] [-d] [-u] [-v] [-V] [-D] [-C]
ifrename [-c archivo_config] [-i interfaz] [-n nuevo_nombre]

DESCRIPCIÓN

Ifrename es una herramienta que permite asignar un nombre consistente a cada una de tus interfaces de red.

Por defecto, los nombres de las interfaces son dinámicos y a cada interfaz de red se le asigna el primer nombre disponible (eth0, eth1...). El orden en que se crean las interfaces de red puede variar. Para las interfaces integradas, la enumeración durante el arranque del kernel puede variar. Para las interfaces extraíbles, el usuario puede conectarlas en cualquier orden.

Ifrename permite al usuario decidir qué nombre tendrá una interfaz de red. Ifrename puede usar una variedad de selectores para especificar cómo los nombres de las interfaces coinciden con las interfaces de red del sistema, siendo el selector más común la dirección MAC de la interfaz.

Ifrename debe ejecutarse antes de que se activen las interfaces, por lo que es principalmente útil en diversos scripts (init, hotplug) pero rara vez lo usa directamente el usuario. Por defecto, ifrename renombra todas las interfaces del sistema presentes usando las correspondencias definidas en /etc/iftab.

PARÁMETROS

-c archivo_config
Establece el archivo de configuración a utilizar (por defecto /etc/iftab). El archivo de configuración define la correspondencia entre los selectores y los nombres de las interfaces, y se describe en iftab(5).
Si archivo_config es "-", la configuración se lee desde la entrada estándar.
-p
Sondea (carga) los módulos del kernel antes de renombrar las interfaces. Por defecto, ifrename solo comprueba las interfaces ya cargadas y no carga automáticamente los módulos del kernel requeridos. Esta opción permite una integración fluida con sistemas que no cargan módulos antes de llamar a ifrename.
-d
Habilita varias modificaciones específicas de Debian. Combinado con -p, solo se cargan los módulos para las interfaces especificadas en /etc/network/interface.
-i interfaz
Renombra solo la interfaz especificada en lugar de todas las interfaces del sistema. Se imprime el nuevo nombre de la interfaz.
-n nuevo_nombre
Cuando se usa con -i, especifica el nuevo nombre de la interfaz. Se omite la lista de correspondencias del archivo de configuración, la interfaz especificada con -i se renombra directamente a nuevo_nombre. El nuevo nombre puede ser un comodín que contenga un solo '*'.
Cuando se usa sin -i, renombra las interfaces usando solo las correspondencias que las renombrarían a nuevo_nombre. El nuevo nombre no puede ser un comodín. Se desaconseja el uso de ifrename de esta manera, por ser ineficiente (-n sin -i). Todas las interfaces del sistema deben ser procesadas en cada invocación, por lo tanto, en la mayoría de los casos, no es más rápido que simplemente dejar que ifrename las renombre a todas (sin -n ni -i).
-t
Habilita el soporte de toma de control de nombres. Esto permite el intercambio de nombres de interfaz entre dos o más interfaces.
La toma de control permite a una interfaz 'robar' el nombre de otra interfaz. Esto solo funciona con el kernel 2.6.X y si la otra interfaz está desactivada. En consecuencia, esto no es compatible con Hotplug. A la otra interfaz se le asigna un nombre aleatorio, pero puede ser renombrada más tarde con 'ifrename'.
El número de tomas de control está limitado para evitar bucles circulares y, por lo tanto, algunas situaciones complejas de intercambio de nombres multidireccional pueden no ser procesadas completamente.
En cualquier caso, se desaconseja el intercambio de nombres y el uso de esta característica, y se le invita a elegir nombres únicos e inequívocos para sus interfaces...
-u
Habilita el modo de salida udev. Esto permite una integración adecuada de ifrename en el framework de udev, udevd(8) usará ifrename para asignar nombres de interfaz presentes en /etc/iftab. En este modo, la salida de ifrename puede ser parseada directamente por udevd(8) como una acción IMPORT. Esto requiere udev versión 107 o posterior.
-D
Modo de simulación (Dry-run). Ifrename no cambiará ninguna interfaz, solo imprimirá el nuevo nombre de la interfaz, si corresponde, y saldrá.
En modo de simulación, los comodines de nombres de interfaz no se resuelven. Se imprime el nuevo nombre de la interfaz, incluso si es el mismo que el nombre antiguo.
Tenga en cuenta también que algunos selectores solo pueden ser leídos por root, por ejemplo, aquellos basados en ethtool), y fallarán silenciosamente si los ejecuta un usuario normal. En otras palabras, el modo de simulación bajo un usuario estándar puede no dar el resultado esperado.
-V
Modo detallado (Verbose). Ifrename mostrará los resultados internos del análisis de su archivo de configuración y la consulta de los selectores de las interfaces. Combinado con la opción de simulación, esta es una buena manera de depurar configuraciones complejas o problemas triviales.
-C
Contar interfaces coincidentes. Muestra el número de interfaces que coinciden y lo devuelve como estado de salida de ifrename.
El número de interfaces que coinciden es el número de interfaces en el sistema para las que se encontró una correspondencia en el archivo de configuración (que es diferente del número de interfaces renombradas).
