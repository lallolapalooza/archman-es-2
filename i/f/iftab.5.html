DESCRIPCIÓ

N

El archivo /etc/iftab contiene información descriptiva sobre las distintas interfaces de red. iftab solo es utilizado por el programa ifrename(8) para asignar un nombre de interfaz de red consistente a cada interfaz de

red.

/etc/iftab define un conjunto de mapeos. Cada mapeo contiene un nombre de interfaz y un conjunto de selectores. Los selectores permiten a ifrename identificar cada interfaz de red en el sistema. Si una interfaz de red coincide con todos los descriptores de un mapeo, ifrename intenta cambiar el nombre de la inte

rfaz al nombre de interfa
z dado por el mapeo.

MAPEO

S

Cada mapeo se describe en una línea separada, comienza con un nombre de interfaz, y contiene un conjunto de descriptores, separados por espacios o

tabulaciones.

La relación entre los descriptores de un mapeo es una lógica y. Un mapeo coincide con una interfaz de red solo si todos los descriptores coinciden. Si una interfaz de red no soporta un descriptor específico, no coincidirá con ningún mapeo que use este

descriptor.

Si desea usar descriptores alternativos para un nombre de interfaz (lógica o), especifique dos mapeos diferentes con el mismo nombre de interfaz (uno en cada línea). Ifrename siempre usa el primer mapeo coincidente empezando desde el final de iftab, por lo tanto, el mapeo más restri

ctivo debería esp
ecificarse al final.

NOMBRE DE

INTERFAZ

La primera parte de cada mapeo es un nombre de interfaz. Si una interfaz de red coincide con todos los descriptores de un mapeo, ifrename intenta cambiar el nombre de la interfaz al nombre de interfaz dado por el

mapeo.

El nombre de interfaz de un mapeo es o bien un nombre de interfaz simple (como eth2 o wlan1) o un patrón de nombre de interfaz que contiene un único comodín (como eth* o wlan*). En caso de comodín, el kernel reemplaza el '*' con el entero disponible más bajo haciendo que este nombre de interfaz sea único. Tenga en cuenta que el comodín solo es soportado para los kernels 2.6.1 y 2.4.30 y

posteriores.

Se desaconseja intentar mapear interfaces a nombres de interfaz por defecto como eth0, wlan0 o ppp0. El kernel usa esos como nombre por defecto para cualquier interfaz nueva, por lo tanto, es muy probable que una interfaz ya esté usando este nombre e impida que ifrename lo use. Incluso si usa takeover, la interfaz puede ya estar activa en algunos casos. No usar esos nombres le permitirá identificar inmediatamente interfaces no configuradas o nuevas.
Los buenos nombres son o bien totalmente únicos y significativos, como mydsl o privatehub, o usan enteros más grandes, como eth5 o wlan5. El segundo tipo suele ser más fácil d

e integrar en diversas
utilidades de red.

DESCRIPTORE

S

Cada descriptor está compuesto por un nombre de descriptor y un valor de descriptor. Los descriptores especifican un atributo estático de una interfaz de red, el objetivo es identificar de forma única cada pieza de

hardware.

La mayoría de los usuarios solo usarán el selector mac a pesar de sus potenciales problemas, otros selectores son para configuraciones más especializadas. La mayoría de los selectores aceptan un '*' en el valor del selector para coincidencia con comodín, y la mayoría de los selectores no distinguen entre mayúsculas y

minúsculas.
mac dirección
mac
Coincide con la dirección MAC de la interfaz con la dirección MAC especificada. La dirección MAC de la interfaz puede mostrarse usando ifconfig(8) o ip(8).
Este es el selector más común, ya que la mayoría de las interfaces tienen una dirección MAC única que permite identificar interfaces de red sin ambigüedad. Sin embargo, algunas interfaces no tienen una dirección MAC válida hasta que se activan, en cuyo caso usar este selector es complicado o
imposible.
arp tipo
arp
Coincide con el tipo ARP (también llamado tipo de enlace) de la interfaz con el tipo ARP especificado como número. El tipo ARP de la interfaz puede mostrarse usando ifconfig(8) o ip(8), el tipo link/ether corresponde a 1 y el tipo link/ieee802.11 corresponde a 801.
Este selector es útil cuando un controlador crea múltiples interfaces de red para una sola tarjeta de
red.
driver nombre del
controlador
Coincide con el nombre del controlador de la interfaz con el nombre de controlador especificado. El nombre del controlador de la interfaz puede mostrarse usando ethtool -i(8)
.
businfo información del
bus
Coincide con la información del bus de la interfaz con la información de bus especificada. La información del bus de la interfaz puede mostrarse usando ethtool -i(8)
.
firmware revisión del
firmware
Coincide con la revisión del firmware de la interfaz con la información de revisión del firmware. La revisión del firmware de la interfaz puede mostrarse usando ethtool -i(8)
.
baseaddress dirección
base
Coincide con la dirección base de la interfaz con la dirección base especificada. La dirección base de la interfaz puede mostrarse usando ifconfig(8).
Debido a que la mayoría de las tarjetas usan asignación dinámica de la dirección base, este selector solo es útil para tarjetas ISA y
EISA.
irq línea
irq
Coincide con la línea IRQ (interrupción) de la interfaz con la línea IRQ especificada. La línea IRQ de la interfaz puede mostrarse usando ifconfig(8).
Debido a que las líneas IRQ pueden ser compartidas, este selector normalmente no es suficiente para identificar una interfaz de forma
única.
iwproto protocolo
inalámbrico
Coincide con el protocolo inalámbrico de la interfaz con el protocolo inalámbrico especificado. El protocolo inalámbrico de la interfaz puede mostrarse usando iwconfig(8) o iwgetid(8).
Este selector solo es soportado en interfaces inalámbricas y no es suficiente para identificar una interfaz de forma
única.
pcmciaslot ranura
pcmcia
Coincide con el número de socket Pcmcia de la interfaz con el número de ranura especificado. El número de socket Pcmcia de la interfaz puede mostrarse usando cardctl ident(8).
Este selector normalmente solo es soportado en tarjetas de 16 bits, para tarjetas de 32 bits se aconseja usar el selector businf
o.
prevname nombre de interfaz
anterior
Coincide con el nombre de la interfaz antes de renombrar con el nombre antiguo especificado.
Este selector debería evitarse, ya que el nombre de interfaz anterior puede variar dependiendo de diversas condiciones. Una actualización del sistema/kernel/controlador puede cambiar el nombre original. Luego, ifrename u otra herramienta puede renombrarlo antes de la ejecución de este
selector.
SYSFS{nombre de archivo} valo
r
Coincide con el contenido del atributo sysfs dado por nombre de archivo con el valor especificado. Para enlaces simbólicos y directorios padre, coincide con el nombre real del directorio del atributo sysfs dado por nombre de archivo con el valor especificado.

DESCRIPTORES

SYSFS

Los atributos sysfs para una interfaz específica se encuentran en la mayoría de los sistemas en el directorio con el nombre de esa interfaz en /sys/class/net/. La mayoría de los atributos sysfs son archivos, y sus valores pueden leerse usando cat(1) o more(1). También es posible hacer coincidir atributos en

subdirectorios.

Algunos atributos sysfs son enlaces simbólicos, que apuntan a otro directorio en sysfs. Si el nombre de archivo del atributo es un enlace simbólico, el atributo sysfs se resuelve al nombre del directorio al que apunta el enlace simbólico usando readlink(1). La ubicación es un directorio en el árbol sysfs es también importante. Si el nombre de archivo del atributo termina con /.., el atributo sysfs se resuelve al nombre real del directorio padre usando pwd(1

).

El sistema de archivos sysfs solo es compatible con el núcleo 2.6.X y debe estar montado (generalmente en /sys). Los selectores sysfs no son tan eficientes como otros selectores, por lo tanto, deben evitarse para un rendimiento

óptimo.

Estos son atributos sysfs comunes y sus descriptores ifrename correspondientes
