i2cset(8)

Paquete: i2c-tools

Licencias: GPL

I2CSET(8) Manual del Administrador del Sistema I2CSET(8)

NOMBRE

i2cset - establece registros I2C

SINOPSIS

i2cset [-f] [-y] [-m máscara] [-r] [-a] autobús-i2c dirección-chip dirección-datos [valor] ... [modo]
i2cset -V
i2cset -h

DESCRIPCIÓN

i2cset es un pequeño programa auxiliar para establecer registros visibles a través del bus I2C.

OPCIONES

-V
Muestra la versión y sale.
-h
Muestra la ayuda y sale.
-f
Fuerza el acceso al dispositivo incluso si ya está ocupado. Por defecto, i2cset se negará a acceder a un dispositivo que ya está bajo el control de un controlador del kernel. El uso de esta bandera es peligroso, puede confundir seriamente al controlador del kernel en cuestión. También puede hacer que i2cset escriba silenciosamente en el registro incorrecto. Úselo bajo su propio riesgo y solo si sabe lo que está haciendo.
-y
Desactiva el modo interactivo. Por defecto, i2cset esperará una confirmación del usuario antes de manipular el bus I2C. Cuando se usa esta bandera, realizará la operación directamente. Esto está diseñado principalmente para ser utilizado en scripts.
-m máscara
El parámetro máscara, si se especifica, describe qué bits de valor se escribirán realmente en dirección-datos. Los bits establecidos en 1 en la máscara se toman de valor, mientras que los bits establecidos en 0 se leerán de dirección-datos y, por lo tanto, se preservarán en la operación. Tenga en cuenta que este parámetro asume que las operaciones de lectura y escritura para el modo especificado son simétricas para el dispositivo al que se accede. Este puede ser el caso o no, ya que ni I2C ni SMBus garantizan esto.
-r
Lee el valor justo después de escribirlo y compara el resultado con el valor escrito. Este solía ser el comportamiento por defecto. Se aplican las mismas limitaciones que a la opción -m.
-a
Permite usar direcciones entre 0x00 - 0x07 y 0x78 - 0x7f. No se recomienda.

Hay tres opciones obligatorias para i2cset. autobús-i2c indica el número o nombre del bus I2C a escanear. Este número debería corresponder a uno de los buses listados por i2cdetect -l. dirección-chip especifica la dirección del chip en ese bus, y es un entero entre 0x08 y 0x77. dirección-datos especifica la dirección en ese chip a la que escribir, y es un entero entre 0x00 y 0xFF.

El parámetro valor, si se especifica, es el valor a escribir en esa ubicación en el chip. Si este parámetro se omite, se emite una escritura corta. Para la mayoría de los chips, esto simplemente establece un puntero interno a la ubicación de destino, pero en realidad no escribe en esa ubicación. Para algunos chips sin embargo, en particular los simples con un solo registro, esta escritura corta es una escritura real. Si el parámetro de modo es s o i, se pueden especificar varios valores.

El parámetro modo, si se especifica, es una de las letras b, w, s, o i, correspondientes a un tamaño de escritura de un solo byte, una palabra de 16 bits, una escritura de bloque SMBus, o una escritura de bloque I2C, respectivamente. Para escrituras de bloque SMBus e I2C, el tamaño de escritura se determina por el número de parámetros valor. Excepto para escrituras de bloque I2C, también se puede adjuntar una p al parámetro modo para habilitar PEC. Si el parámetro modo se omite, i2cset utiliza por defecto el modo de byte sin PEC. El valor proporcionado debe estar dentro del rango para el tipo de datos especificado (0x00-0xFF para escrituras de byte y bloque, 0x0000-0xFFFF para palabras). Otro modo posible es c, que no escribe ningún valor (escritura corta). Normalmente no tiene que especificar este modo, ya que es el valor predeterminado cuando no se proporciona ningún valor, a menos que también desee habilitar PEC.

ADVERTENCIA

i2cset puede ser extremadamente peligroso si se usa incorrectamente. Puede confundir su bus I2C, causar pérdida de datos o tener efectos secundarios más graves. Escribir en una EEPROM serie en un módulo de memoria DIMM (direcciones de chip entre 0x50 y 0x57) puede DESTRUIR su memoria, ¡dejando su sistema sin poder arrancar! Tenga mucho cuidado al usar este programa.

EJEMPLOS

Escribir el valor 0x42 en el registro de 8 bits 0x11 del dispositivo I2C en la dirección de 7 bits 0x2d en el bus 1 (i2c-1), después de la confirmación del usuario:

# i2cset 1 0x2d 0x11 0x42

Borrar inmediatamente los 3 bits menos significativos del registro de 8 bits 0x11 del dispositivo I2C en la dirección de 7 bits 0x2d en el bus 1 (i2c-1) (sin confirmación del usuario):

# i2cset -y -m 0x07 1 0x2d 0x11 0x00

Escribir el valor 0x5000 en el registro de 16 bits 0x02 del dispositivo I2C en la dirección de 7 bits 0x48 en el bus 1 (i2c-1), después de la confirmación del usuario:

# i2cset 1 0x48 0x02 0x5000 w

Vea también i2cget(8) para ver ejemplos de uso combinado de i2cset y i2cget.

ERRORES

Para informar de errores o enviar correcciones, escriba a la lista de correo de Linux I2C <linux-i2c@vger.kernel.org> con copia al mantenedor actual: Jean Delvare <jdelvare@suse.de>.
