NOMBR

i2ctransfer - enviar mensaje

s I2C definidos por el usuar
io en una sola transferencia

SINOPSI

S

i2ctransfer [-a] [-b] [-f] [-v] [-y] i2cbus desc [data] [desc [data]] ...
i2ctransfer -h
i2ctransfer -

V

DESCRIPCIÓ

N

i2ctransfer es un programa para crear mensajes I2C y enviarlos combinados como una sola transferencia. Para los mensajes de lectura, el contenido de los búferes recibidos se imprime en stdout, una línea por cada mensaje de lectura.
Tenga en cuenta la diferencia entre una transferencia y un mensaje aquí. Una transferencia puede consistir en múltiples mensajes y comienza con una condición de START y termina con una condición de STOP, como se describe en la especificación I2C. Los mensajes dentro de la transferencia se concatenan usando la condición de START REPETIDO, que también se describe allí. Hay algunas ventajas de tener múltiples mensajes en una transferencia. Primero, algunos dispositivos mantienen sus estados inte

rnos para el START REPETIDO pero los reinician después de un STOP. Segundo, no puede ser interrumpido durante una transferencia, pero podría suceder entre múltiples transferencias. La interrupción podría ocurrir a nivel
de hardware por otro maestro I2C en el bus, o a nivel de software por otro usuario de I2C que obtuvo su transferencia programada entre la suya. Este programa le ayuda a crear transferencias adecuadas para sus necesidades.

OPCIONE

S
-
a
Permite usar direcciones entre 0x00 - 0x07 y 0x78 - 0x7f. No
recomendado.
-
b
Imprime los datos de los mensajes de lectura como datos binarios. Desactiva -v (detallado). Útil para canalizar a una herramienta de impresión bonita como hexdump o para redirigir a un archivo para analizarlo más
tarde.
-
f
Fuerza el acceso al dispositivo incluso si ya está ocupado. Por defecto, i2ctransfer se negará a acceder a un dispositivo que ya está bajo el control de un controlador del kernel. Usar esta bandera es peligroso, puede confundir seriamente al controlador del kernel en cuestión. También puede causar que i2ctransfer escriba silenciosamente en el registro equivocado. Úsela bajo su propio riesgo y solo si sabe lo que está
haciendo.
-
h
Muestra la ayuda y
sale.
-
v
Habilita la salida detallada. Imprimirá información sobre todos los mensajes enviados, es decir, no solo para mensajes de lectura sino también para mensajes de
escritura.
-
V
Muestra la versión y
sale.
-
y
Desactiva el modo interactivo. Por defecto, i2ctransfer esperará una confirmación del usuario antes de manipular el bus I2C. Cu
ando se usa esta bandera, realizará la
operación directamente. Esto está destinado
principalmente a ser usado en scripts.

ARGUMENTO

S

El primer parámetro i2cbus indica el número o nombre del bus I2C a utilizar. Este número debería corresponder a uno de los buses listados por i2cdetect

-l.

El siguiente parámetro es uno o múltiples bloques desc. El número de bloques está limitado por el Kernel de Linux y definido por I2C_RDWR_IOCTL_MAX_MSGS (42 a partir de la v4.10). Los bloques desc se componen

así:

{r|w}<longitud_del_mensaje>

[@dirección]
{r|
w}
especifica si el mensaje es de lectura o
escritura
<longitud_del_mensa
je>
especifica el número de bytes leídos o escritos en este mensaje. Se analiza como un entero sin signo de 16 bits, pero tenga en cuenta que el Kernel de Linux aplica un límite superior adicional (8192 a partir de la v4.10). Para mensajes de lectura a objetivos que soportan transacciones de Bloque SMBus, también puede ser '?', entonces el objetivo determinará la
longitud.
[@direcci
ón]
especifica la dirección de 7 bits del chip a ser accedido para este mensaje, y es un entero. Si se omite, reutiliza la dirección anterior. Normalmente, las direcciones fuera del rango de 0x08-0x77 y las direcciones con un controlador del kernel adjunto serán bloqueadas. Esto puede ser anulado con -a (todas) o -f (forzar). ¡Tenga mucho cuidado al usar estas! Las dir
ecciones de 10 bits actualmente
no son soportadas en absoluto.

Si el mensaje I2C es de escritura, entonces un bloque de datos con los datos a escribir le sigue. Consiste en <longitud_del_mensaje> bytes que pueden ser marcados con los prefijos habituales para hexadecimal, octal, etc. Para facilitar la creación de bloques de datos más grandes fácilmente, el byte de dato puede tener un

sufijo.
=
mantener el valor constante hasta el final del mensaje (es decir, 0= significa 0, 0, 0,
...)
+
incrementar el valor en 1 hasta el final del mensaje (es decir, 0+ significa 0, 1, 2,
...)
-
decrementar el valor en 1 hasta el final del mensaje (es decir, 0xff- significa 0xff, 0xfe, 0xfd,
...)
p
usar el valor como semilla para una secuencia pseudoaleatoria de 8 bits (es decir, 0p significa 0x00, 0x50, 0xb0, .
.
.
)

EJEMPLO

S

En el bus 0, desde una EEPROM en la dirección 0x50, leer 8 bytes desde el desplazamiento 0x64 (el primer mensaje escribe un byte para establecer el puntero de memoria en 0x64, el segundo mensaje lee del mismo chip)

: 
# i2ctrans
fer 0 w1@0x
50 0x64 r8

Para la misma EEPROM, en el desplazamiento 0x42 escribir 0xff 0xfe ... 0xf0 (un mensaje de escritura; el primer byte establece el puntero de memoria en 0x42, 0xff es el primer byte de dato, todos los siguientes bytes de dato se decrementan en uno)

: 
# i2ctran
sfer 0 w1
7@0x50 0
x42 0xff-

ADVERTENCI

A

i2ctransfer puede ser extremadamente peligroso si se usa inadecuadamente. Puede confundir su bus I2C, causar pérdida de datos, o tener efectos secundarios más graves. Escribir en una E

EPROM serie en una memoria DIMM (direcciones de chip entre 0x50 y 0x57) puede ¡DESTRUIR su me
moria, dejando su sistema no arrancable! Sea extremadamente cuidadoso al usar este programa.

S
