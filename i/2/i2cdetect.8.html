I2CDETECT(8) Manual del Administrador del Sistema I2CDETECT(8)

NOMBRE

i2cdetect - detectar chips I2C

SINOPSIS

i2cdetect [-y] [-a] [-q|-r] bus_i2c [primero último]
i2cdetect -F bus_i2c
i2cdetect -V
i2cdetect -h
i2cdetect -l

DESCRIPCIÓN

i2cdetect es un programa de espacio de usuario para escanear un bus I2C en busca de dispositivos. Produce una tabla con la lista de dispositivos detectados en el bus especificado. bus_i2c indica el número o nombre del bus I2C a escanear, y debe corresponder a uno de los buses listados por i2cdetect -l. Los parámetros opcionales primero y último restringen el rango de escaneo (predeterminado: de 0x08 a 0x77).

Como no existe un comando de detección I2C estándar, i2cdetect utiliza comandos SMBus arbitrarios (a saber, escritura rápida SMBus y recepción de byte SMBus) para sondear dispositivos. Por defecto, el comando utilizado es el que se cree que es el más seguro para cada dirección. Consulte las opciones -q y -r para cambiar este comportamiento.

i2cdetect también se puede utilizar para consultar las funcionalidades de un bus I2C (ver opción -F).

ADVERTENCIA

¡Este programa puede confundir su bus I2C, causar pérdida de datos y algo peor!

INTERPRETACIÓN DE LA SALIDA

Cada celda en la tabla de salida contendrá uno de los siguientes símbolos:

  • "--". Se sondearon las direcciones pero ningún chip respondió.
  • "UU". Se omitió el sondeo, ya que esta dirección está actualmente en uso por un controlador. Esto sugiere fuertemente que hay un chip en esta dirección.
  • Un número de dirección en hexadecimal, por ejemplo, "2d" o "4e". Se encontró un chip en esta dirección.

OPCIONES

-y
Deshabilitar el modo interactivo. Por defecto, i2cdetect esperará una confirmación del usuario antes de manipular el bus I2C. Cuando se utiliza esta bandera, realizará la operación directamente. Esto está pensado principalmente para ser utilizado en scripts.
-a
Forzar el escaneo de direcciones no regulares. No recomendado.
-q
Utilizar el comando SMBus "quick write" para sondeos. No recomendado. Se sabe que corrompe la EEPROM AT24RF08 de Atmel que se encuentra en muchas computadoras portátiles IBM Thinkpad.
-r
Utilizar el comando SMBus "receive byte" para sondeos. No recomendado. Se sabe que bloquea SMBus en varios chips de solo escritura (notablemente chips de reloj en la dirección 0x69).
-F
Mostrar la lista de funcionalidades implementadas por el adaptador y salir.
-V
Mostrar la versión y salir.
-h
Mostrar la ayuda y salir.
-l
Mostrar una lista de los buses instalados.

EJEMPLOS

Listar todos los buses I2C disponibles:

# i2cdetect -l

Escanear inmediatamente las direcciones estándar en el bus I2C 9 (i2c-9), utilizando el método predeterminado para cada dirección (sin confirmación del usuario):

# i2cdetect -y 9

Consultar las funcionalidades del bus I2C 1 (i2c-1):

# i2cdetect -F 1

Escanear las direcciones de 0x10 a 0x17 en el bus I2C llamado "SMBus I801 adapter at efa0", utilizando el método "receive byte", después de la confirmación del usuario:

# i2cdetect -r "SMBus I801 adapter at efa0" 0x10 0x17

ERRORES

Para informar sobre errores o enviar correcciones, por favor escriba a la lista de correo de Linux I2C <linux-i2c@vger.kernel.org> con copia al mantenedor actual: Jean Delvare <jdelvare@suse.de>.
