DESCRIPCIÓ

N

Las funciones insque() y remque() manipulan colas construidas a partir de listas doblemente enlazadas. La cola puede ser circular o lineal. Una aplicación que utilice insque() o remque() debe asegurarse de definir una estructura en la que los dos primeros miembros de la estructura sean punteros al mismo tipo de estructura, y cualquier miembro adicional sea específico de la aplicación. El primer miembro de la estructura es un puntero hacia adelante a la siguiente entrada en la cola. El segundo miembro es un puntero hacia atrás a la entrada anterior en la cola. Si la cola es lineal, la cola se termina con punteros nulos. Los nombres de la estructura y de los miembros puntero no están sujetos a ninguna restricción

especial.

La función insque() insertará el elemento al que apunta el puntero element en una cola inmediatamente después del elemento al que apunta pred

.

La función remque() eliminará el elemento al que apunta el puntero element de una

cola.

Si la cola se va a utilizar como una lista lineal, invocar insque(&element, NULL), donde element es el elemento inicial de la cola, inicializará los punteros hacia adelante y hacia atrás de element a punteros

nulos.

Si la cola se va a utilizar como una lista circular, la aplicación debe

asegurarse de inicializar el puntero hacia adelante y el puntero hacia a
trás del elemento inicial de la cola a la dirección del propio elemento.

USO EN

APLICACIONES

Las implementaciones históricas de estas funciones describían los argumentos como siendo de tipo struct qelem * en lugar de ser de tipo void * como se define aquí. En esas implementaciones, struct qelem se definía comúnmente en <search.h>

como: 
struct qelem {
    struct qelem  *q_forw;
    struct qelem  *q_back;
}
;

Sin embargo, las aplicaciones que utilizaban estas funciones nunca pudieron usar esta estructura directamente ya que no proporcionaba espacio para los datos reales contenidos en los elementos. La mayoría de las aplicaciones definían estructuras que contenían los dos punteros como elementos iniciales y también proporcionaban espacio para, o punteros a, los datos del objeto. Las aplicaciones que usaban estas funciones para actualizar más de un tipo de tabla también tenían el problema de especificar dos o más estructuras diferentes con el mismo nombre, si utilizaban literalmente struct qelem como se

especificaba.

Como se describe aquí, las implementaciones esperaban en realidad un tipo de estructura donde los dos primeros miembros fueran punteros hacia adelante y hacia atrás a estructuras. Con compiladores de C que no proporcionaban prototipos de función, las aplicaciones usaban estructuras como se especifica en la DESCRIPCIÓN anterior y el compilador hacía lo que la aplicación

esperaba.

Si este método se hubiera mantenido con un compilador ISO C estándar y el prototipo de función histórico, la mayoría de las aplicaciones tendrían que modificarse para convertir los punteros a las estructuras realmente usadas en punteros a struct qelem para evitar advertencias de compilación. Al especificar void * como el tipo de argumento, las aplicaciones no necesitan cambiar (a menos que referenciaran específicamente struct qelem y dependieran de que estuviera definido en <search.h>

)
.
