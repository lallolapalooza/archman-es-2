N

inadyn se configura mediante un archivo de configuración simple. El carácter “#” marca el inicio de un comentario hasta el final de la línea. El carácter \ puede usarse como carácter de

escape.
verify-address = <true | fals
e>
De forma predeterminada, inadyn verifica tanto las direcciones IPv4 como IPv6, asegurándose de que la dirección sea una dirección de Internet válida. Las direcciones inválidas son, por ejemplo, las de enlace local, las de bucle (loopback), las de multidifusión (multicast) y las direcciones experimentales conocidas. Para más información, véase RFC3330.

La validación de la dirección IP puede deshabilitarse estableciendo esta opción en fal

s
e.
fake-address = <true | fals
e>
Al usar SIGUSR1 para realizar una actualización forzada, esta opción puede usarse para falsificar una actualización de dirección con una dirección “aleatoria” en el rango 203.0.113.0/24 (rango de direcciones de ejemplo de RFC5737) antes de actualizar con la dirección IP real. Esto está completamente fuera de la especificación, pero puede ser útil para personas que rara vez, si acaso, obtienen un cambio de dirección IP. Debido a que algunos proveedores de servicios DDNS no registrarán incluso una actualización forzada si la IP es la misma. Como resultado, el usuario podría ser dado de baja como usuario
inactivo.
allow-ipv6 = <true | fals
e>
Inadyn puede obtener una dirección IPv6 desde una interfaz, o con un script externo checkip. Esta opción controla si las direcciones IPv6 deben permitirse o descartarse. De forma predeterminada, esta opción es false, es decir, cualquier dirección IPv6 encontrada se
descarta.
iface =
IFNAME
Usar la interfaz de red IFNAME como fuente de cambios de dirección IP en lugar de consultar a un servidor externo. Con esta opción habilitada, la comprobación externa de IP se deshabilita y inadyn enviará actualizaciones DDNS usando la dirección IP de la interfaz de red IFNAME a todos los proveedores DDNS listados en el archivo de configuración. Esto puede ser útil para registrar direcciones IP de la LAN, o, cuando se está conectado directamente a una dirección IP pública, para acelerar la comprobación de IP si los servidores de comprobación de IP del proveedor DDNS son lentos en responder.

Esta opción también puede darse como una opción de la línea de comandos a inadyn(8), ambos cumplen un pro

pósito, use la
que le funcione.
iterations = <NUM | 0
>
Establece el número de actualizaciones DNS. El valor predeterminado es 0, lo que significa
infinito.
period =
SEC
Con qué frecuencia se comprueba la IP, en segundos. Predeterminado: aprox. 1 minuto. Máximo: 10
días.
forced-update =
SEC
Con qué frecuencia se debe actualizar la IP incluso si no ha cambiado. El tiempo debe darse en segundos. El valor predeterminado es igual a 30
días.
secure-ssl = < true | false
>
Si la validación del certificado HTTPS falla para un proveedor, inadyn aborta la actualización DDNS antes de enviar ninguna credencial. Cuando esta configuración está deshabilitada, es decir, false, entonces inadyn solo emitirá una advertencia. De forma predeterminada, esta configuración está habilitada, porque la seguridad
importa.
broken-rtc = < true | false
>
Los certificados HTTPS solo son válidos dentro de ventanas de tiempo especificadas, por lo que en sistemas sin reloj de tiempo real por hardware y con una hora de arranque predeterminada muy en el pasado, se espera una validación falsamente negativa (falso positivo de fallo). Cuando esta configuración está habilitada, es decir, true, entonces inadyn solo emitirá una advertencia de que el certificado aún no es válido. De forma predeterminada, esta configuración está deshabilitada, porque la seguridad
importa.
ca-trust-file =
FILE
De forma predeterminada, inadyn usa la ruta incorporada a los certificados CA de confianza del sistema, tanto GnuTLS como Open/LibreSSL soportan esto. Como respaldo, en caso de que las API para cargar certificados CA desde la ruta incorporada fallen, inadyn también soporta rutas predeterminadas comunes a los paquetes CA de Debian y RedHat.

Esta configuración anula las rutas incorporadas y las ubicaciones de respa

ldo y proporciona una manera de especificar la ruta a un conjunto de conf
ianza de certificados CA, en formato PEM, empaquetados en un solo archivo.
user-agent =
STRING
Especificar la cadena User-Agent a enviar al proveedor DDNS en las solicitudes de checkip y de actualización. Algunos proveedores requieren que este campo se establezca en una cadena específica, otros pueden estar bien con "Mozilla/4.0". El valor predeterminado es enviar "inadyn/VERSION SUPPORTURL", donde VERSION es la versión actual de inadyn, y SUPPORTURL es la URL de soporte upstream.

Esto también puede establecerse por p

roveedor, véase más abajo la descrip

abajo.
provider email@ddns-service.tld[:ID]
{}
Las secciones custom{} y provider{} son muy similares, excepto que la sección custom permite personalizar los detalles del servidor de actualización DDNS. Véase la lista más abajo para los proveedores DDNS soportados y sus identificadores email@ddns-service.tld.

Para soportar múltiples usuarios del mismo proveedor DDNS, añada [:ID] al nombre del proveedor. El ID puede ser cualquier cadena o número de forma libre siempre que la combinación sea
