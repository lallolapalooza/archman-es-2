INTEGRITYSETUP(8) Comandos de mantenimiento INTEGRITYSETUP(8)

NOMBRE

integritysetup - utilidad para configurar y gestionar dispositivos dm-integrity

SINOPSIS

integritysetup <acción> [<opciones>] <argumentos_de_acción>

DESCRIPCIÓN

Integritysetup es una utilidad para configurar y gestionar dispositivos dm-integrity del kernel.

El mapeador de dispositivos del kernel dm-integrity emula una etiqueta de integridad de datos adicional por sector de disco y proporciona protección de integridad de datos transparente para dispositivos de bloque.

Puedes configurar estas etiquetas de integridad adicionales directamente con integritysetup, o indirectamente (para cifrado autenticado) a través de LUKS2 y cryptsetup(8). A diferencia de dm-verity, dm-integrity los dispositivos admiten tanto operaciones de lectura como de escritura. El kernel realiza la comprobación de integridad de datos de forma transparente utilizando un algoritmo de suma de comprobación o hash criptográfico seleccionado.

Los dispositivos de integridad pueden activarse durante el arranque a través de integritytab(5), que forma parte de systemd(1).

ACCIONES BÁSICAS

Integritysetup admite estas operaciones:

FORMAT

format <dispositivo>

Formatea <dispositivo> (calcula el espacio y el superbloque dm-integrity y borra el dispositivo).

<opciones> puede ser [--data-device, --batch-mode, --no-wipe, --journal-size, --interleave-sectors, --tag-size, --integrity, --integrity-key-size, --integrity-key-file, --sector-size, --progress-frequency, --progress-json].

OPEN

open <dispositivo> <nombre>
create <nombre> <dispositivo> (sintaxis OBSOLETA)

Abre un mapeo con <nombre> respaldado por el dispositivo <dispositivo>.

Si el algoritmo de integridad del dispositivo no es el predeterminado, el algoritmo debe especificarse con la opción --integrity. Esto no se detectará desde el dispositivo.

<opciones> puede ser [--data-device, --batch-mode, --journal-watermark, --journal-commit-time, --buffer-sectors, --integrity, --integrity-key-size, --integrity-key-file, --integrity-no-journal, --integrity-recalculate, --integrity-recalculate-reset, --integrity-recovery-mode, --allow-discards].

CLOSE

close <nombre>
remove <nombre> (sintaxis OBSOLETA)

Elimina el mapeo existente <nombre>.

<opciones> puede ser [--deferred] o [--cancel-deferred].

STATUS

status <nombre>

Informa el estado del mapeo de integridad activo <nombre>.

DUMP

dump <dispositivo>

Informa los parámetros del superbloque almacenado en disco.

RESIZE

resize <nombre>

Redimensiona un mapeo activo <nombre>.

Si no se especifica --size (en sectores de 512 bytes) o --device-size, el tamaño se calcula a partir del dispositivo subyacente. Después de redimensionar, se establece el indicador recalculando . Si se establece la opción --wipe y el tamaño del dispositivo se incrementa, la sección recién añadida será borrada.

Aumentar el tamaño de los volúmenes de integridad ha sido posible desde la versión 5.7 del kernel de Linux; reducirlo debería funcionar también en kernels más antiguos.

<opciones> puede ser [--size, --device-size, --wipe].

OPCIONES

--allow-discards

Permite el uso de solicitudes de descarte (TRIM) para el dispositivo. Esta opción está disponible desde la versión 5.7 del kernel de Linux.

--batch-mode, -q

No solicita confirmación.

--bitmap-flush-time ms

Tiempo de volcado del mapa de bits en milisegundos.

ADVERTENCIA: En caso de un fallo, es posible que los datos y la etiqueta de integridad no coincidan si el diario está deshabilitado.

--bitmap-sectors-per-bit sectores

El número de sectores de 512 bytes por bit del mapa de bits debe ser una potencia de dos.

--buffer-sectors sectores

El número de sectores en un búfer.

El área de etiquetas se accede utilizando búferes; un tamaño de búfer grande significa que el tamaño de E/S será mayor, pero podría emitirse menos operaciones de E/S.

--cancel-deferred

Elimina una eliminación de dispositivo diferida previamente configurada en el comando close .

--data-device <dispositivo_de_datos>

Especifica un dispositivo de datos separado que contiene datos existentes. El <dispositivo> contendrá entonces las etiquetas de integridad calculadas y un diario para los datos en <dispositivo_de_datos>.

Para no borrar el dispositivo de datos después del formateo inicial, especifica también la opción --no-wipe y activa con --integrity-recalculate para recalcular las etiquetas de integridad automáticamente.

--debug

Ejecuta en modo depuración con registros de diagnóstico completos. Las líneas de salida de depuración siempre están precedidas por #.

--deferred

Difiere la eliminación del dispositivo en el comando close hasta que el último usuario lo cierre.

--help, -?

Muestra el texto de ayuda y los parámetros predeterminados.

--integrity, -I algoritmo

Usa el cálculo de integridad interno (modo independiente). El algoritmo de integridad puede ser CRC (crc32c/crc32), una función hash no criptográfica (xxhash64) o una función hash (sha1, sha256).

Para HMAC (hmac-sha256), debes especificar una clave de integridad y su tamaño.

--integrity-bitmap-mode, -B

Usa el modo alternativo de mapa de bits (disponible desde el kernel de Linux 5.2), donde dm-integrity usa un mapa de bits en lugar de un diario. Si un bit en el mapa de bits es 1, los datos de la región correspondiente y las etiquetas de integridad no están sincronizados; si la máquina falla, las regiones no sincronizadas serán recalculadas. El modo de mapa de bits es más rápido que el modo de diario porque no tenemos que escribir los datos dos veces. Sin embargo, también es menos fiable porque si ocurre una corrupción de datos cuando la máquina falla, puede no ser detectada.

--integrity-inline

Almacena las etiquetas de integridad en los campos de integridad de sector de hardware. El dispositivo debe admitir sectores con información de protección adicional (PI, también conocido como DIF - campo de integridad de datos) del tamaño solicitado. Otro subsistema de almacenamiento no debe usar el campo adicional (el dispositivo debe presentar un perfil "nop" en el kernel). Ten en cuenta que algunos dispositivos deben ser reformateados a nivel de bajo para admitir esta opción; para dispositivos NVMe, consulta los perfiles LBA de nvme(1) id-ns.

En este modo no se usa diario ni mapa de bits. El dispositivo debe operar con velocidad nativa (sin ninguna sobrecarga).

Esta opción está disponible desde la versión 6.11 del kernel de Linux.

--integrity-key-file archivo

El archivo con la clave de integridad.

--integrity-key-size bytes

El tamaño de la clave de integridad de datos. El máximo es 4096 bytes.

--integrity-no-journal, -D

Deshabilita el diario para el dispositivo de integridad.

--integrity-recalculate

Recalcula automáticamente las etiquetas de integridad en el kernel al activarse. El dispositivo puede usarse durante el recálculo automático de integridad, pero solo se convierte en totalmente protegido por integridad después de que la operación en segundo plano haya finalizado.

El caso de uso principal previsto es omitir la inicialización (borrado) del dispositivo de datos después del formateo inicial (ver la opción --no-wipe). Este parámetro puede usarse para la activación, y luego el kernel recalculará las etiquetas de integridad en segundo plano. El superbloque de integridad contiene un desplazamiento del dispositivo que indica el límite hasta el cual las etiquetas de integridad ya están actualizadas. Puedes verificar este desplazamiento con el comando dump.

--integrity-recalculate-reset

Reinicia el recálculo desde el principio del dispositivo. Puede ser used to change the integrity checksum function. Note, it does not change the tag length. This option is available since the Linux kernel version 5.13.

--integrity-recovery-mode, -R

Modo de recuperación (sin journal, sin comprobación de etiquetas).

--interleave-sectors sectores

El número de sectores entrelazados.

--journal-commit-time ms

Tiempo de confirmación en milisegundos. El journal se escribe cuando pasa este tiempo (y no se emitió ninguna operación de vaciado explícita).

--journal-crypt algoritmo

Algoritmo de cifrado para el área de datos del journal. Puedes usar un cifrador de bloque aquí, como cbc-aes o un cifrador de flujo, por ejemplo, chacha20 o ctr-aes.

Las opciones de cifrado de journal solo están destinadas a pruebas. El uso de cifrado de journal no tiene sentido sin el cifrado de los datos.

--journal-crypt-key-file archivo

El archivo con la clave de cifrado del journal.

--journal-crypt-key-size bytes

El tamaño de la clave de cifrado del journal. El máximo es 4096 bytes.

--journal-integrity algoritmo

Algoritmo de integridad para el área del journal. Consulta la opción --integrity para una especificación detallada.

--journal-integrity-key-file archivo

El archivo con la clave de integridad.

--journal-integrity-key-size bytes

El tamaño de la clave de integridad del journal. El máximo es 4096 bytes.

--journal-size, -j bytes

Tamaño del journal.

--journal-watermark porcentaje

Marca de agua del journal en porcentaje. Cuando el tamaño del journal supera esta marca, se iniciará el vaciado del journal.

--no-wipe

No limpiar el dispositivo después de formatearlo. Un dispositivo que no se limpia inicialmente contendrá sumas de verificación inválidas.

--progress-frequency segundos

Imprime una línea separada cada <segundos> con el progreso de la limpieza.

--progress-json

Imprime datos de progreso de limpieza en formato JSON, lo que es adecuado principalmente para el procesamiento por máquinas. Imprime una línea separada cada medio segundo (o según el valor de --progress-frequency). La salida JSON se ve así durante el progreso de la limpieza (excepto que es una línea compacta): 
{
  "device":"/dev/sda",      // dispositivo o archivo de respaldo
  "device_bytes":"8192",    // bytes limpiados hasta ahora
  "device_size":"44040192", // bytes totales a limpiar
  "speed":"126877696",      // velocidad calculada en bytes por segundo (basada en el progreso hasta ahora)
  "eta_ms":"2520012",       // tiempo estimado para finalizar la limpieza en milisegundos
  "time_ms":"5561235"       // tiempo total dedicado a limpiar el dispositivo en milisegundos
}

Nota sobre los números en la salida JSON: Debido a las limitaciones de los analizadores JSON, todos los números se representan en formato de cadena debido a la necesidad de enteros sin signo de 64 bits completos.

--sector-size, -s bytes

Tamaño del sector (potencia de dos: 512, 1024, 2048, 4096).

--tag-size, -t bytes

Tamaño de la etiqueta de integridad por sector (aquí, la función de integridad almacenará la etiqueta de autenticación).

El tamaño puede ser menor que el tamaño de salida de la función hash; en ese caso, solo se almacenará parte del hash.

--usage

Mostrar ayuda de opciones cortas.

--verbose, -v

Imprimir más información sobre la ejecución del comando.

--version, -V

Mostrar la versión del programa.

--wipe

Limpiar el área recién asignada después de redimensionarla a un tamaño mayor. Si esta bandera no está activada, se calcularán sumas de verificación para los datos almacenados previamente en el área recién asignada.

OPCIONES DE COMPATIBILIDAD LEGACY

No utilices estas opciones a menos que necesites compatibilidad con un kernel antiguo específico.

--integrity-legacy-padding

Utilizar relleno legacy ineficiente.

--integrity-legacy-hmac

Utilizar cálculo HMAC antiguo y defectuoso (tampoco protege el superbloque).

--integrity-legacy-recalculate

Permitir el recálculo inseguro de volúmenes con claves HMAC (el desplazamiento de recálculo en el superbloque no está protegido).

CÓDIGOS DE RETORNO

Integritysetup devuelve 0 si tiene éxito y un valor distinto de cero en caso de error.

Los códigos de error son: 1 parámetros incorrectos, 2 sin permisos, 3 sin memoria, 4 dispositivo especificado incorrecto, 5 el dispositivo ya existe o está ocupado.

NOTAS

El formato y la activación de un dispositivo de integridad siempre requieren privilegios de superusuario porque el superbloque se calcula y se maneja en el objetivo del kernel dm-integrity.

EJEMPLOS

Formatear el dispositivo con el modo independiente predeterminado (CRC32C):

integritysetup format <dispositivo>

Abrir el dispositivo con parámetros predeterminados:

integritysetup open <dispositivo> test

Formatear el dispositivo en modo independiente para usar con HMAC(SHA256):

integritysetup format <dispositivo> --tag-size 32 --integrity hmac-sha256 --integrity-key-file <archivo_clave> --integrity-key-size <bytes_clave>

Abrir (activar) el dispositivo con HMAC(SHA256) y clave HMAC en un archivo:

integritysetup open <dispositivo> test --integrity hmac-sha256 --integrity-key-file <archivo_clave> --integrity-key-size <bytes_clave>

Volcar información del superbloque dm-integrity:

integritysetup dump <dispositivo>
