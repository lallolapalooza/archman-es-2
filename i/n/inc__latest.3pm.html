DESCRIPCIÓ

N

ADVERTENCIA -- ESTE ES UN MÓDULO EXPERIMENTAL. Fue originalmente incluido (como experimento) con Module::Build y ha sido separado para un uso más

general.

El módulo "inc::latest" ayuda a iniciar las dependencias de tiempo de configuración para las distribuciones de CPAN. Estas dependencias se incluyen en el directorio "inc" dentro de una distribución y son usadas por Makefile.PL o Build.

PL.

Los argumentos de "inc::latest" son nombres de módulos que se comprueban tanto contra el array actual @INC como contra directorios con nombres especiales en "inc". Si la versión incluida es más nueva que la instalada (o si el módulo no está instalado), entonces el directorio incluido se añade al inicio de @INC y el módulo se carga desde

allí.

En realidad hay dos variaciones de "inc::latest" -- una para autores y otra para el directorio "inc". Para los autores de distribuciones, el "inc::latest" instalado en el sistema registrará los módulos cargados a través de "inc::latest" y puede ser usado para crear los archivos incluidos en "inc", incluyendo la escritura de la segunda variación como "inc/latest

.pm".

Este segundo "inc::latest" es el que se carga en una distribución que se está instalando (por ejemplo desde Makefile.PL o Build.PL). Este "inc::latest" incluido es el que determina qué módulo

cargar.

Notas especiales sobre la

inclusión

El módulo "inc::latest" crea directorios incluidos basados en el archivo packlist de una distribución instalada. Aunque "inc::latest" toma nombres de módulos como argumentos, es mejor pensarlo como la inclusión y puesta a disposición de distribuciones completas. Cuando un módulo se carga a través de "inc::latest", busca en todas las distribuciones incluidas en "inc/" un módulo más nuevo que el que se puede encontrar en el array @INC exist

ente.

Por lo tanto, el nombre de módulo proporcionado debe ser normalmente el nombre de módulo de "nivel superior" de una distribución, aunque esto no es estrictamente obligatorio. "inc::latest" tiene varias heurísticas para descubrir nombres de módulos, permitiendo a los usuarios hacer cosas como

esta: 
use inc::latest 'Devel::AssertOS::
Unix';

aunque Devel::AssertOS::Unix está contenido dentro de la distribución

Devel-CheckOS.

En este momento, los archivos packlist son obligatorios. Por lo tanto, incluir mód

ulos dual-core puede requerir una 'instalación forzada' sobre las versiones en la
última versión de perl para crear el archivo packlist necesario para la inclusión.

Gestión de cadenas de

dependencias

Antes de incluir una distribución, debe asegurarse de que todos los prerrequisitos también estén incluidos y se carguen en el orden

correcto.

Por ejemplo, si necesita "Wibble", pero "Wibble" depende de "Wobble", y ha incluido "Module::Build", su Build.PL podría verse

así: 
use inc::latest 'Wobble';
use inc::latest 'Wibble';
use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script
;

Se recomienda encarecidamente a los autores que li

miten la inclusión de dependencias adicionales
si es posible y que prueben cuidadosamente sus
tarballs de distribución antes de subirlos a CPAN.

Como incluido en

inc/

Usando el "Modo autor", se creará un módulo stub especial en su directorio de distribución como inc/latest.pm. En su Makefile.PL o Build.PL, puede entonces cargar "inc::latest" para cargar módulos

incluidos.

Al llamar a "use", el "inc::latest" incluido toma un nombre de módulo y argumentos opcionales para pasar al propio método import de ese

módulo. 
use inc::latest 'Foo::Bar' qw/foo bar
baz/;

La implementación es privada. Solo el método "import

" es p
úblico.

}
