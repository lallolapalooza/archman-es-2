DESCRIPCIÓ

N

intel es un controlador de Xorg para chipsets gráficos integrados de Intel. El controlador soporta profundidades de 8, 15, 16 y 24. Todos los tipos visuales se soportan en profundidad 8. Para el i810/i815, otras profundidades soportan los visuales TrueColor y DirectColor. Para el i830M y p

osteriores, solo se soporta el visual TrueColor para profundidades mayores a 8. El controlador soporta 3D acelerado por hardware a través de la I
nfraestructura de Renderizado Directo (DRI), pero solo en profundidad 16 para el i810/i815 y en profundidades 16 y 24 para el 830M y posteriores.

HARDWARE

SOPORTADO

intel soporta los chipsets i810, i810-DC100, i810e, i815, i830M, 845G, 852GM, 855GM, 865G, 915G, 915GM, 945G, 945GM, 965G, 965Q, 946GZ, 965GM, 945GME, G33, Q33, Q35, G35, GM45,

G45, Q45, G43, G41, Pineview-M en la serie Atom N400, Pineview-D en la serie Atom D400
/D500, Intel(R) HD Graphics, Intel(R) Iris(TM) Graphics, Intel(R) Iris(TM) Pro Graphics.

DETALLES DE

CONFIGURACIÓN

Por favor, consulte xorg.conf(5) para detalles de configuración generales. Esta sección solo cubre detalles de configuración específicos de este

controlador.

Las familias de chipsets gráficos integrados Intel 8xx y 9xx tienen una arquitectura de memoria unificada, lo que significa que la memoria del sistema se utiliza como memoria de vídeo. Para las familias de chipsets i810 e i815, se requiere soporte del sistema operativo para asignar memoria del sistema para poder usar este controlador. Para el 830M y posteriores, esto es necesario para que el controlador pueda usar más memoria de vídeo de la que ha sido preasignada en el arranque por el BIOS. Esto se logra generalmente con un controlador de kernel "agpgart" o "agp". Linux, FreeBSD, OpenBSD, NetBSD y Solaris tienen tales controladores de kernel

disponibles.

Por defecto, el i810/i815 usará 8 MB de memoria del sistema para gráficos si la memoria asignable por AGP es < 128 MB, 16 MB si es < 192 MB o 24 MB si es mayor. Use la opción VideoRam para cambiar el valor por

defecto.

Para el 830M y posteriores, el controlador dimensionará automáticamente su asignación de memoria de acuerdo con las características que soportará. Por lo tanto, la opción VideoRam, que en el pasado era necesaria para permitir que se asignara más de una pequeña cantidad de memoria, ahora es

ignorada.

CONFIGURACIONES DE MÚLTIPLES

CABEZAS

El número de salidas independientes lo dicta el número de CRTCs (en terminología de X) que admite un conjunto de chips determinado. La mayoría de los conjuntos de chips Intel recientes tienen dos CRTCs, lo que significa que se pueden mostrar simultáneamente dos búfers de fotogramas separados, en una configuración de escritorio extendido. Si un conjunto de chips admite más salidas de las que tiene CRTCs (digamos panel plano local, VGA y TV en el caso de muchas salidas), dos de las salidas tendrán que ser "clonadas", lo que significa que muestran el mismo contenido del búfer de fotogramas (o una muestra un subconjunto del búfer de la otra si los modos no son iguales)

.

Puede usar la herramienta "xrandr", o varias utilidades de escritorio, para cambiar su configuración de salida en tiempo de ejecución. Para configurar estáticamente sus salidas, puede usar las opciones "Monitor-<tipo>" junto con secciones de monitor adicionales en su xorg.conf para crear su topología de pantalla. XV_SYNC_TO_VBLANK se usa para controlar si el adaptador texturizado sincroniza la actualización de la pantalla con el vblank para eliminar el desgarr

o (tearing). Es un atributo booleano con valores de 0 (nunca sincronizar) o 1 (siempre sincronizar). Un valor histórico de -1 (sincronizar solo para v
entanas grandes) ahora se interpretará como 1 (ya que el enfoque actual para la sincronización no es costoso incluso con ventanas de vídeo pequeñas).
