NOMBRE

inet_aton, inet_addr, inet_network, inet_ntoa, inet_makeaddr, inet_lnaof, inet_netof - Rutinas de manipulación de direcciones de Internet

BIBLIOTECA

DESCRIPCIÓN

inet_aton() convierte la dirección de host de Internet cp de la notación de números y puntos IPv4 a formato binario (en orden de bytes de red) y la almacena en la estructura a la que apunta inp. inet_aton() devuelve un valor distinto de cero si la dirección es válida, cero si no lo es. La dirección proporcionada en cp puede tener una de las siguientes formas:

a.b.c.d
Cada una de las cuatro partes numéricas especifica un byte de la dirección; los bytes se asignan de izquierda a derecha para producir la dirección binaria.
a.b.c
Las partes a y b especifican los dos primeros bytes de la dirección binaria. La parte c se interpreta como un valor de 16 bits que define los dos bytes de la derecha de la dirección binaria. Esta notación es adecuada para especificar direcciones de red de clase B (obsoletas).
a.b
La parte a especifica el primer byte de la dirección binaria. La parte b se interpreta como un valor de 24 bits que define los tres bytes de la derecha de la dirección binaria. Esta notación es adecuada para especificar direcciones de red de clase A (obsoletas).
a
El valor a se interpreta como un valor de 32 bits que se almacena directamente en la dirección binaria sin ninguna reorganización de bytes.

En todas las formas anteriores, los componentes de la dirección punteada pueden especificarse en decimal, octal (con un 0 inicial) o hexadecimal, con un 0X inicial. Las direcciones en cualquiera de estas formas se denominan colectivamente notación de números y puntos IPv4. La forma que utiliza exactamente cuatro números decimales se denomina notación decimal punteada IPv4 (o a veces: notación de cuádruple punteado IPv4).

inet_aton() devuelve 1 si la cadena proporcionada se interpretó correctamente, o 0 si la cadena es inválida (errno no se establece en caso de error).

La función inet_addr() convierte la dirección de host de Internet cp de la notación de números y puntos IPv4 a datos binarios en orden de bytes de red. Si la entrada es inválida, se devuelve INADDR_NONE (generalmente -1). El uso de esta función es problemático porque -1 es una dirección válida (255.255.255.255). Evite su uso en favor de inet_aton(), inet_pton(3), o getaddrinfo(3), que proporcionan una forma más limpia de indicar el retorno de error.

La función inet_network() convierte cp, una cadena en notación de números y puntos IPv4, en un número en orden de bytes de host adecuado para usar como dirección de red de Internet. En caso de éxito, se devuelve la dirección convertida. Si la entrada es inválida, se devuelve -1.

La función inet_ntoa() convierte la dirección de host de Internet in, dada en orden de bytes de red, a una cadena en notación decimal punteada IPv4. La cadena se devuelve en un búfer asignado estáticamente, que las llamadas posteriores sobrescribirán.

La función inet_lnaof() devuelve la parte de la dirección de red local de la dirección de Internet in. El valor devuelto está en orden de bytes de host.

La función inet_netof() devuelve la parte del número de red de la dirección de Internet in. El valor devuelto está en orden de bytes de host.

La función inet_makeaddr() es la inversa de inet_netof() y inet_lnaof(). Devuelve una dirección de host de Internet en orden de bytes de red, creada combinando el número de red net con la dirección local host, ambas en orden de bytes de host.

La estructura in_addr, tal como se utiliza en inet_ntoa(), inet_makeaddr(), inet_lnaof() y inet_netof(), se define en <netinet/in.h> como:


typedef uint32_t in_addr_t;
struct in_addr {
    in_addr_t s_addr;
};

inet_lnaof(), inet_netof() y inet_makeaddr() son funciones heredadas que asumen que están tratando con direcciones de red clasifica. La red clasificada divide las direcciones de red IPv4 en componentes de host y red en los límites de los bytes, como sigue:

Clase A
Este tipo de dirección se indica con el valor 0 en el bit más significativo de la dirección (en orden de bytes de red). La dirección de red está contenida en el byte más significativo, y la dirección de host ocupa los tres bytes restantes.
Clase B
Este tipo de dirección se indica con el valor binario 10 en los dos bits más significativos de la dirección. La dirección de red está contenida en los dos bytes más significativos, y la dirección de host ocupa los dos bytes restantes.
Clase C
Este tipo de dirección se indica con el valor binario 110 en los tres bits más significativos de la dirección. La dirección de red está contenida en los tres bytes más significativos, y la dirección de host ocupa el byte restante.

Las direcciones de red clasifica ahora están obsoletas, habiendo sido reemplazadas por el Enrutamiento Interdominios sin Clases (CIDR), que divide las direcciones en componentes de red y host en límites de bits (en lugar de bytes) arbitrarios.

NOTAS

En arquitecturas x86, el orden de bytes del host es de byte menos significativo primero (little endian), mientras que el orden de bytes de red, como se usa en Internet, es de byte más significativo primero (big endian).

NAME

inet_ntoa, inet_ntoa_r - Internet address to IPv4 addresses strings

LIBRARY

Network functions library (libucv, -lucv)

SYNOPSIS

#include <arpa/inet.h>

char *
inet_ntoa(struct in_addr in);

char *
inet_ntoa_r(struct in_addr in, char *buf, int len);

DESCRIPTION

The inet_ntoa() function converts an IPv4 address in network byte order into a string in American dotted-decimal notation.

The argument in is the IPv4 address in network byte order.

The inet_ntoa() function returns a pointer to a static string, which might be overwritten by later calls to the same function.

inet_ntoa_r() is the reentrant version of inet_ntoa(). It converts the IPv4 address in into a string in American dotted-decimal notation and copies the result into the buffer pointed to by buf, which has length len. The length of the buffer must be sufficient to hold the resulting string. The caller is responsible for allocating the buffer. The return value is a pointer to the buffer buf on success, or NULL on error.

ATTRIBUTES

For definitions of the terms used in this section, see attributes(7). 

| Attribute | Value |
|-----------|-------|
| Interface stability | Unstable |
| Multicall   | none    |

STANDARDS

The inet_ntoa() function is specified by POSIX.1-2008.

The inet_ntoa_r() function is not specified by any standard.

STANDARDS

inet_ntoa() is part of the BSD socket API. It is specified in POSIX.1-2008.

NOTES

The inet_ntoa() function is inherently unsafe because it returns a pointer to a static buffer that might be overwritten by subsequent calls. Furthermore, it is not thread-safe. Use inet_ntop(3) or inet_ntoa_r() instead.

The inet_ntoa_r() function provides a thread-safe way to convert an IPv4 address to its string representation.

The IPv4 address is specified as a struct in_addr. The members of this structure are typically defined as a union that contains a uint8_t[4] array and a uint32_t, where the address is stored in network byte order.

The dotted-decimal format for an IPv4 address is four decimal numbers (0-255) separated by dots. For example, 127.0.0.1.

EXAMPLES

The following example demonstrates the usage of inet_ntoa():

#define _DEFAULT_SOURCE
#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>

int
main(int argc, char *argv[])
{
    struct in_addr addr;

    if (argc != 2) {
        fprintf(stderr, "%s <dotted-address>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    if (inet_aton(argv[1], &addr) == 0) {
        fprintf(stderr, "Invalid address\n");
        exit(EXIT_FAILURE);
    }

    printf("%s\n", inet_ntoa(addr));

    exit(EXIT_SUCCESS);
}

To compile:

gcc -o inet_ntoa_example inet_ntoa_example.c

Example usage:

$ ./inet_ntoa_example 127.0.0.1
127.0.0.1
