DESCRIPCIÓ

N

infocmp se puede utilizar para comparar una entrada terminfo binaria con otras entradas de terminfo, reescribir una descripción de terminfo para aprovechar el campo use= de terminfo, o imprimir una descripción de terminfo desde el archivo binario (term) en una variedad de formatos. En todos los casos, los campos booleanos se imprimirán primero, seguidos por los campos numéricos y, a continuación, por los campos de

cadena.

No todas las capacidades de terminfo se traducirán; solo se generarán normalmente en la salida aquellas variables que formaban parte de termcap. Especificar la opción -r eliminará esta restricción, permitiendo que todas las capacidades se generen en la forma de termcap. Normalmente utilizaría tanto las opciones -C como -r. El formato real utilizado incorpora algunas mejoras para los caracteres escapados del formato de terminfo. Para una traducción más estricta compatible con BSD, utilice la opción -K en lugar de -C

Opción Use=

[-u]

La opción -u produce una descripción de código fuente de terminfo del primer terminal tipo-de-terminal que es relativa a la suma de las descripciones dadas por las entradas de los otros tipos-de-terminal. Lo hace analizando las diferencias entre el primer tipo-de-terminal y los otros tipos-de-terminal y produciendo una descripción con campos use= para los otros terminales. De esta manera, es posible retrofitar entradas genéricas de terminfo en la descripción de un terminal. O, si existen dos terminales similares, pero fueron codificados en momentos diferentes o por diferentes personas de modo que cada descripción es una descripción completa, utilizando infocmp se mostrará qué se puede hacer para cambiar una descripción para que sea relativa a la

otra.

Una capacidad se imprimirá con un signo de arroba (@) si ya no existe en el primer tipo-de-terminal, pero una de las entradas de los otros tipos-de-terminal contiene un valor para ella. El valor de una capacidad se imprimirá si el valor en el primer tipo-de-terminal no se encuentra en ninguna de las entradas de los otros tipos-de-terminal, o si la primera de las entradas de los otros tipos-de-terminal que tiene esta capacidad da un valor diferente para la capacidad que en el primer tipo-de-terminal>

.

El orden de las otras entradas de tipo de terminal es significativo. Dado que el compilador de terminfo tic realiza un escaneo de izquierda a derecha de las capacidades, especificar dos entradas use= que contengan entradas diferentes para las mismas capacidades producirá resultados diferentes dependiendo del orden en que se den las entradas. infocmp marcará cualquier inconsistencia de este tipo entre las otras entradas de tipo de terminal a medida que se

encuentren.

Alternativamente, especificar una capacidad después de una entrada use= que contenga esa capacidad hará que la segunda especificación sea ignorada. Usar infocmp para recrear una descripción puede ser una verificación útil para asegurarse de que todo se especificó correctamente en la descripción de origen

original.

Otro error que no causa archivos compilados incorrectos, pero que ralentizará el tiempo de compilación, es especificar campos use= extra que son superfluos. infocmp marcará cualquier otro campo use= de tipo de terminal

que no haya s
ido necesario.

Como otras utilidades de ncurses, infocmp busca las descripciones de terminal en varios lugares. Puede usar las variables de entorno TERMINFO y TERMINFO_DIRS para anular la lista predeterminada de lugares donde buscar compilada en el programa. Véase curses(3X), así como la sección Obteniendo Descripciones Compiladas en terminfo

(5).

EXTENSIONE

S

Las opciones -0, -1, -E, -F, -G, -Q, -R, -T, -V, -a, -e, -f, -g, -i, -l, -p, -q y -t no están soportadas en curses

SVr4.

infocmp de SVr4 no distingue entre capacidades ausentes y canceladas. Además, muestra las capacidades enteras faltantes como -1 (el valor interno utilizado para representar enteros faltantes). Esta implementación las muestra como “NULL”, por consistencia con cadenas

faltantes.

La noción de capacidades “termcap” de la opción -r es la de System V Release 4. Las versiones reales de BSD curses tendrán un conjunto más restringido. Para ver solo el conjunto 4.4BSD, utilice -r -RB

HISTORI

A

Aunque System V Release 2 proporcionó una biblioteca terminfo, no tenía ninguna herramienta documentada para descompilar las descripciones de terminal. Tony Hansen (AT&T) escribió el primer infocmp a principios de 1984, para System V Release

3.

Eric Raymond usó la documentación de AT&T en 1995 para proporcionar un equivalente infocmp para ncurses. Además, añadió algunas características nuevas

como:
  • la opción -e, para soportar descripciones de terminal de respaldo
    • (compiladas)
  • la opción -i, para ayu
    • dar con e
l análisis

Más tarde, Thomas Dickey añadió la opción -x (capacidades definidas por el usuario) y la opción -E para soportar entradas de respaldo con capacidades definidas por el

usuario.

Para una lista completa, véase la sección EXTENSIONES

.

En 2010, Roy Marples proporcionó un programa infocmp para NetBSD. Es menos capaz que las versiones de SVr4 o ncurses (p. ej., carece de las opciones de ordenamiento documentadas en X/Open), pero sí incluye la opción -x adaptada de ncur
