NOMBRE

initdb - crea un nuevo clúster de bases de datos de PostgreSQL

SINOPSIS

initdb [opción...] [--pgdata | -D] directorio

DESCRIPCIÓN

initdb crea un nuevo clúster de bases de datos de PostgreSQL.

Crear un clúster de bases de datos consiste en crear los directorios en los que vivirán los datos del clúster, generar las tablas de catálogo compartidas (tablas que pertenecen al clúster completo en lugar de a una base de datos particular), y crear las bases de datos postgres, template1 y template0. La base de datos postgres es una base de datos predeterminada destinada al uso por usuarios, utilidades y aplicaciones de terceros. template1 y template0 están destinadas como bases de datos fuente para ser copiadas por posteriores CREATE DATABASE comandos. template0 nunca debería ser modificada, pero puedes añadir objetos a template1, que por defecto serán copiados a bases de datos creadas posteriormente. Ver Sección 22.3 para más detalles.

Aunque initdb intentará crear el directorio de datos especificado, es posible que no tenga permiso si el directorio padre del directorio de datos deseado es propiedad de root. Para inicializar en tal configuración, crea un directorio de datos vacío como root, luego usa chown para asignar la propiedad de ese directorio a la cuenta de usuario de la base de datos, luego su para convertirte en el usuario de la base de datos y ejecutar initdb.

initdb debe ejecutarse como el usuario que será propietario del proceso del servidor, porque el servidor necesita tener acceso a los archivos y directorios que initdb crea. Dado que el servidor no puede ejecutarse como root, no debes ejecutar initdb como root tampoco. (De hecho, se negará a hacerlo.)

Por razones de seguridad, el nuevo clúster creado por initdb solo será accesible por el propietario del clúster por defecto. La --allow-group-access opción permite a cualquier usuario en el mismo grupo que el propietario del clúster leer archivos en el clúster. Esto es útil para realizar copias de seguridad como un usuario no privilegiado.

initdb inicializa la configuración regional y la codificación de caracteres predeterminadas del clúster de bases de datos. Estas también pueden configurarse por separado para cada base de datos cuando se crea. initdb determina esas configuraciones para las bases de datos plantilla, que servirán como predeterminadas para todas las demás bases de datos.

Por defecto, initdb usa el proveedor de configuración regional libc (ver Sección 23.1.4). El proveedor de configuración regional libc toma la configuración regional del entorno, y determina la codificación a partir de la configuración regional.

Para elegir una configuración regional diferente para el clúster, usa la opción --locale. También hay opciones individuales --lc-* y --icu-locale (ver abajo) para establecer valores para las categorías individuales de configuración regional. Ten en cuenta que configuraciones inconsistentes para diferentes categorías regionales pueden dar resultados sin sentido, así que esto debe usarse con cuidado.

Alternativamente, initdb puede usar la biblioteca ICU para proporcionar servicios de configuración regional especificando --locale-provider=icu. El servidor debe compilarse con soporte ICU. Para elegir el ID de configuración regional ICU específico a aplicar, usa la opción --icu-locale. Ten en cuenta que por razones de implementación y para soportar código heredado, initdb aún seleccionará e inicializará la configuración regional libc cuando se usa el proveedor de configuración regional ICU.

Cuando initdb se ejecute, imprimirá la configuración regional que ha elegido. Si tienes requisitos complejos o especificaste múltiples opciones, es aconsejable verificar que el resultado coincida con lo que se pretendía.

Se pueden encontrar más detalles sobre la configuración regional en Sección 23.1.

Para alterar la codificación predeterminada, usa --encoding. Se pueden encontrar más detalles en la Sección 23.3.

OPCIONES

-A método_de_autenticación
--auth=método_de_autenticación

Esta opción especifica el método de autenticación predeterminado para usuarios locales usado en pg_hba.conf (líneas host y local). Ver Sección 20.1 para un resumen de los valores válidos.

initdb pre-poblará las entradas de pg_hba.conf usando el método de autenticación especificado para conexiones de no-replicación así como conexiones de replicación.

No uses trust a menos que confíes en todos los usuarios locales en tu sistema. trust es el predeterminado para facilitar la instalación.

--auth-host=método_de_autenticación

Esta opción especifica el método de autenticación para usuarios locales vía conexiones TCP/IP usado en pg_hba.conf (líneas host).

--auth-local=método_de_autenticación

Esta opción especifica el método de autenticación para usuarios locales vía conexiones de socket de dominio Unix usado en pg_hba.conf (líneas local).

-D directorio
--pgdata=directorio

Esta opción especifica el directorio donde el clúster de bases de datos debe ser almacenado. Esta es la única información requerida por initdb, pero puedes evitar escribirla configurando la variable de entorno PGDATA , lo que puede ser conveniente ya que el servidor de la base de datos (postgres) puede encontrar el directorio de datos más tarde por la misma variable.

-E codificación
--encoding=codificación

Selecciona la codificación de las bases de datos plantilla. Esta será también la codificación predeterminada de cualquier base de datos que crees más tarde, a menos que la anules entonces. Los conjuntos de caracteres soportados por el servidor PostgreSQL se describen en la Sección 23.3.1.

Por defecto, la codificación de la base de datos plantilla se deriva de la configuración regional. Si --no-locale se especifica (o equivalentemente, si la configuración regional es C o POSIX), entonces el predeterminado es UTF8 para el proveedor ICU y SQL_ASCII para el proveedor libc.

-g
--allow-group-access

Permite a usuarios en el mismo grupo que el propietario del clúster leer todos los archivos del clúster creados por initdb. Esta opción se ignora en Windows ya que no soporta permisos de grupo estilo POSIX.

--icu-locale=configuración_regional

Especifica la configuración regional ICU cuando se usa el proveedor ICU. El soporte de configuración regional se describe en la Sección 23.1.

--icu-rules=reglas

Especifica reglas de cotejamiento adicionales para personalizar el comportamiento de la cotejamiento predeterminada. Esto solo es soportado para ICU.

-k
--data-checksums

Usa sumas de verificación en páginas de datos para ayudar a detectar corrupción por el sistema de E/S que de otro modo sería silenciosa. Esto está habilitado por defecto; usa --no-data-checksums para deshabilitar las sumas de verificación.

Habilitar las sumas de verificación puede incurrir en una pequeña penalización de rendimiento. Si se configuran, las sumas de verificación se calculan para todos los objetos, en todas las bases de datos. Todos los fallos de suma de verificación se reportarán en la vista pg_stat_database. Ver Sección 28.2 para detalles.

--locale=configuración_regional

Establece la configuración regional predeterminada para el clúster de bases de datos. Si esta opción no se especifica, la configuración regional se hereda del entorno en el que initdb se ejecuta. El soporte de configuración regional se describe en la Sección 23.1.

Si --locale-provider es builtin, --locale o --builtin-locale debe especificarse y configurarse en C, C.UTF-8 o PG_UNICODE_FAST.

--lc-collate=configuración_regional
--lc-ctype=configuración_regional
--lc-messages=configuración_regional
--lc-monetary=configuración_regional
--lc-numeric=configuración_regional
--lc-time=configuración_regional

Como --locale, pero solo establece la configuración regional en la categoría especificada.

--no-locale

Equivalente a --locale=C.

--builtin-locale=configuración_regional

Especifica el nombre de la configuración regional cuando se usa el proveedor builtin. El soporte de configuración regional se describe en la Sección 23.1.

--locale-provider={builtin|libc|icu}

Esta opción establece el proveedor de configuración regional para las bases de datos creadas en el nuevo clúster. Puede ser anulado en el CREATE DATABASE comando cuando se crean nuevas bases de datos posteriormente. El predeterminado es libc (ver Sección 23.1.4).

--no-data-checksums

No habilitar sumas de verificación de datos.

--pwfile=nombre_de_archivo

Hace que initdb lea la contraseña del superusuario de arranque desde un archivo. La primera línea del archivo se toma como la contraseña.

-T

NOMBRE

initdb – inicializa un clúster de base de datos PostgreSQL

SINOPSIS

initdb [opción...] [-D directorio-datos]

DESCRIPCIÓN

initdb es la utilidad utilizada para crear un nuevo clúster de base de datos PostgreSQL. El clúster de base de datos es una colección de bases de datos gestionadas por un único servidor PostgreSQL. La creación de un clúster de base de datos también implica la creación de las bases de datos template1 y postgres, una tabla de parámetros del sistema y archivos de configuración.

Si no se especifica la opción -D, initdb creará el directorio del clúster en el directorio especificado por la variable de entorno PGDATA. Si la variable PGDATA no está definida, se creará en un subdirectorio llamado `data' en el directorio actual.

initdb es la forma principal de inicializar un clúster de base de datos. También puede ser invocado como pg_ctl initdb.

OPCIONES

Para inicializar un clúster de base de datos, initdb requiere algunos parámetros de configuración que se pueden especificar en la línea de comandos. Las siguientes opciones se pueden usar para especificar dichos parámetros:

-A { s| p| m| ident | peer | scram-sha-256 }
--auth={ s| p| m| ident | peer | scram-sha-256 }
Establece el método de autenticación por defecto para las conexiones locales. Las opciones son:

s (Trust)

p (Password)

m (Password)

ident (ident)

peer (peer)

scram-sha-256 (SCRAM-SHA-256)

Vea la Sección 21.1 para más información.

-D directorio
Especifica la ubicación del directorio donde se almacenará el clúster de base de datos. Si no se especifica, se usa la variable de entorno PGDATA o el directorio actual si PGDATA no está definido.
-E codificación
--encoding=codificación
Especifica la codificación de caracteres para la base de datos. Los valores válidos para codificación son los soportados por PostgreSQL (por ejemplo, SQL_ASCII, EUC_JP, UTF8, LATIN1, WIN1251, etc.). UTF8 es el valor por defecto.
-h anfitrión
--host=anfitrión
Especifica el nombre de anfitrión del servidor. No se utiliza directamente por initdb, pero se almacena en el archivo de configuración.
-k nombre-enlace
--locale=nombre-enlace
Establece la configuración regional (locale) para la base de datos. Esto incluye el orden de clasificación de cadenas, la clasificación de caracteres, la representación de números y la información de moneda. Por defecto, se utiliza el valor de la variable de entorno LC_ALL o LC_COLLATE y LC_CTYPE de su sistema operativo.
--locale-collate=nombre-enlace
Establece la configuración regional para el orden de clasificación de cadenas. Solo puede especificarse si no se usa --locale.
--locale-ctype=nombre-enlace
Establece la configuración regional para la clasificación de caracteres. Solo puede especificarse si no se usa --locale.
-O
--no-tablespaces
No permite la creación de tablas especiales. Tablespaces permite a los administradores de bases de datos definir ubicaciones en el sistema de archivos donde los objetos de la base de datos pueden ser almacenados. Esta opción inhibe su uso.
-s configuración
--text-search-config=config
Establece la configuración de búsqueda de texto por defecto. Vea default_text_search_config para más información.
-U nombre-usuario
--username=nombre-usuario
Establece el nombre de usuario del superusuario inicial. Por defecto, es el nombre del usuario del sistema operativo que ejecuta initdb.
-W
--pwprompt
Hace que initdb solicite una contraseña para el superusuario inicial. Si no planea usar autenticación por contraseña, esto no es importante. De lo contrario, no podrá usar autenticación por contraseña hasta que tenga una contraseña configurada.
-X directorio
--waldir=directorio
Esta opción especifica el directorio donde se debe almacenar el registro de escritura anticipada (WAL).
--wal-segsize=tamaño
Establece el tamaño del segmento WAL, en megabytes. Este es el tamaño de cada archivo individual en el registro WAL. El tamaño por defecto es de 16 megabytes. El valor debe ser una potencia de 2 entre 1 y 1024 (megabytes). Esta opción solo se puede establecer durante la inicialización y no se puede cambiar posteriormente.

Puede ser útil ajustar este tamaño para controlar la granularidad del envío o archivo de registros WAL. Además, en bases de datos con un alto volumen de WAL, el gran número de archivos WAL por directorio puede convertirse en un problema de rendimiento y gestión. Aumentar el tamaño del archivo WAL reducirá el número de archivos WAL.

Otras opciones, menos comunes, también están disponibles:

-c nombre=valor
--set nombre=valor
Establece forzosamente el parámetro del servidor nombre a valor durante initdb, y también instala esa configuración en el archivo postgresql.conf generado, de modo que se aplique durante futuras ejecuciones del servidor. Esta opción se puede dar más de una vez para establecer varios parámetros. Es principalmente útil cuando el entorno es tal que el servidor no se inicia en absoluto utilizando los parámetros por defecto.
-d
--debug
Imprime la salida de depuración del backend de arranque y algunos otros mensajes de menor interés para el público en general. El backend de arranque es el programa que initdb utiliza para crear las tablas de catálogo. Esta opción genera una cantidad tremenda de salida extremadamente aburrida.
--discard-caches
Ejecuta el backend de arranque con la opción debug_discard_caches=1. Esto lleva mucho tiempo y solo es útil para depuración profunda.
-L directorio
Especifica dónde initdb debe encontrar sus archivos de entrada para inicializar el clúster de bases de datos. Normalmente, esto no es necesario. Se le indicará si necesita especificar su ubicación explícitamente.
-n
--no-clean
Por defecto, cuando initdb determina que un error le impidió crear completamente el clúster de base de datos, elimina cualquier archivo que haya podido crear antes de descubrir que no puede terminar el trabajo. Esta opción inhibe la limpieza y, por lo tanto, es útil para la depuración.
-N
--no-sync
Por defecto, initdb esperará a que todos los archivos se escriban de forma segura en el disco. Esta opción hace que initdb regrese sin esperar, lo que es más rápido, pero significa que un fallo posterior del sistema operativo puede dejar el directorio de datos corrupto. En general, esta opción es útil para pruebas, pero no debe usarse al crear una instalación de producción.
--no-sync-data-files
Por defecto, initdb escribe de forma segura todos los archivos de la base de datos en el disco. Esta opción instruye a initdb a omitir la sincronización de todos los archivos en los directorios individuales de la base de datos, los propios directorios de la base de datos y los directorios de tablespace, es decir, todo en el subdirectorio base y cualquier otro directorio de tablespace. Otros archivos, como los de pg_wal y pg_xact, seguirán siendo sincronizados a menos que la opción --no-sync también se especifique.

Tenga en cuenta que si se utiliza --no-sync-data-files junto con --sync-method=syncfs, algunos o todos los archivos y directorios mencionados anteriormente se sincronizarán porque syncfs procesa sistemas de archivos completos.

Esta opción está destinada principalmente al uso interno por parte de herramientas que garantizan por separado que los archivos omitidos se sincronicen en el disco.

--no-instructions
Por defecto, initdb escribirá instrucciones sobre cómo iniciar el clúster al final de su salida. Esta opción hace que esas instrucciones se omitan. Esto está destinado principalmente para su uso por parte de herramientas que envuelven initdb con comportamiento específico de la plataforma, donde esas instrucciones probablemente sean incorrectas.
-s
--show
Muestra la configuración interna y sale, sin hacer nada más. Esto se puede usar para depurar la instalación de initdb.
--sync-method=método
Cuando se establece en fsync, que es el valor por defecto, initdb abrirá y sincronizará recursivamente todos los archivos del directorio de datos. La búsqueda de archivos seguirá los enlaces simbólicos para el directorio WAL y cada tablespace configurado.

En Linux, syncfs puede usarse en su lugar para solicitar al sistema operativo que sincronice todos los sistemas de archivos que contienen el directorio de datos, los archivos WAL y cada tablespace. Consulte recovery_init_sync_method para obtener información sobre las advertencias que se deben tener en cuenta al usar syncfs.

Esta opción no tiene efecto cuando se utiliza --no-sync.

-S
--sync-only
Escribe de forma segura todos los archivos de la base de datos en el disco y sale. Esto no realiza ninguna de las operaciones normales de initdb. En general, esta opción es útil para garantizar una recuperación fiable después de cambiar fsync de apagado a encendido.

Otras opciones:

-V
--version
Imprime la versión de initdb y sale.
-?
--help
Muestra la ayuda sobre los argumentos de la línea de comandos de initdb y sale.

ENTORNO

PGDATA
Especifica el directorio donde se almacenará el clúster de base de datos; puede ser anulado usando la opción -D.
PG_COLOR
Especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son always, auto y never.
TZ
Especifica la zona horaria por defecto del clúster de base de datos creado. El valor debe ser un nombre de zona horaria completo (ver Sección 8.5.3).

NOTAS

initdb también puede ser invocado a través de pg_ctl initdb.
