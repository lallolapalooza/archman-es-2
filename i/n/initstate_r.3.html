random_r(3) Manual de funciones de biblioteca random_r(3)

NOMBRE

random_r, srandom_r, initstate_r, setstate_r - generador de números aleatorios reentrante

BIBLIOTECA

Biblioteca estándar C (libc, -lc)

SINOPSIS

#include <stdlib.h>
int random_r(struct random_data *restrict buf,
             int32_t *restrict result);
int srandom_r(unsigned int seed, struct random_data *buf);
int initstate_r(unsigned int seed,
             char statebuf[restrict .statelen], size_t statelen,
             struct random_data *restrict buf);
int setstate_r(char *restrict statebuf,
             struct random_data *restrict buf);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

random_r(), srandom_r(), initstate_r(), setstate_r():

    /* glibc >= 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE || _BSD_SOURCE

DESCRIPCIÓN

Estas funciones son los equivalentes reentrantes de las funciones descritas en random(3). Son adecuadas para su uso en programas multihilo donde cada hilo necesita obtener una secuencia de números aleatorios independiente y reproducible.

La función random_r() es como random(3), excepto que en lugar de usar la información de estado mantenida en una variable global, utiliza la información de estado en el argumento apuntado por buf, que debe haber sido inicializado previamente por initstate_r(). El número aleatorio generado se devuelve en el argumento result.

La función srandom_r() es como srandom(3), excepto que inicializa la semilla para el generador de números aleatorios cuyo estado se mantiene en el objeto apuntado por buf, en lugar de la semilla asociada con la variable de estado global.

La función initstate_r() es como initstate(3), excepto que inicializa el estado en el objeto apuntado por buf, en lugar de inicializar la variable de estado global. Antes de llamar a esta función, el campo buf.state debe inicializarse a NULL. La función initstate_r() registra un puntero al argumento statebuf dentro de la estructura apuntada por buf. Por lo tanto, statebuf no debe ser liberado mientras buf todavía esté en uso. (Por lo tanto, statebuf normalmente debería asignarse como una variable estática, o asignarse en el heap usando malloc(3) o similar).

La función setstate_r() es como setstate(3), excepto que modifica el estado en el objeto apuntado por buf, en lugar de modificar la variable de estado global. state debe haber sido inicializado previamente usando initstate_r() o ser el resultado de una llamada previa de setstate_r().

VALOR DE RETORNO

Todas estas funciones devuelven 0 en caso de éxito. En caso de error, se devuelve -1, con errno establecido para indicar el error.

ERRORES

EINVAL
Se especificó un array de estado de menos de 8 bytes a initstate_r().
EINVAL
El argumento statebuf o buf a setstate_r() era NULL.
EINVAL
El argumento buf o result a random_r() era NULL.

ESTÁNDARES

GNU.

ERRORES

La interfaz initstate_r() es confusa. Parece que el tipo random_data está destinado a ser opaco, pero la implementación requiere que el usuario inicialice el campo buf.state a NULL o ponga a cero toda la estructura antes de la llamada.
