NOMBRE

Inkscape - un programa editor de gráficos vectoriales SVG (Scalable Vector Graphics).

DESCRIPCIÓN

Inkscape es un editor de gráficos vectoriales Libre y de código abierto. Ofrece un rico conjunto de características y se utiliza ampliamente tanto para ilustraciones artísticas como técnicas, como dibujos animados, clip art, logotipos, tipografía, diagramas y organigramas. Utiliza gráficos vectoriales para permitir impresiones y renderizados nítidos a una resolución ilimitada y no está limitado a un número fijo de píxeles como los gráficos rasterizados. Inkscape utiliza el formato de archivo estándar SVG como su formato principal, que es compatible con muchas otras aplicaciones, incluidos los navegadores web.

La interfaz está diseñada para ser cómoda y eficiente para usuarios expertos, al tiempo que se mantiene conforme a los estándares de GNOME, de modo que los usuarios familiarizados con otras aplicaciones de GNOME puedan aprender su interfaz rápidamente.

SVG es un formato XML estándar del W3C para dibujos vectoriales 2D. Permite definir objetos en el dibujo utilizando puntos, trazos y formas primitivas. Los colores, fuentes, grosor del trazo, etc., se especifican como atributos de `estilo' de estos objetos. La intención es que, dado que SVG es un estándar y que sus archivos son texto/xml, será posible utilizar archivos SVG en un número considerable de programas y para una amplia gama de usos.

Inkscape utiliza SVG como formato de documento nativo, y tiene como objetivo convertirse en el programa de dibujo más compatible con archivos SVG disponible en la comunidad de Código Abierto.

OPCIONES

-?, --help
Muestra un mensaje de ayuda.
--help-all
Muestra todas las opciones de ayuda.
--help-gapplication
Muestra las opciones de GApplication.
--help-gtk
Muestra las opciones de GTK+.
-V, --version
Muestra la versión de Inkscape y la fecha de compilación.
--debug-info
Imprime información técnica incluyendo la versión de Inkscape, versiones de dependencias y el sistema operativo. Esta información es útil al depurar problemas con Inkscape y debe incluirse siempre que se envíe un informe de error.
--system-data-directory
Imprime el directorio de datos del sistema donde se almacenan los archivos de datos que vienen con Inkscape. Esto incluye archivos que Inkscape requiere para ejecutarse (como definiciones de unidades, mapas de teclas integrados, archivos que describen la disposición de la interfaz de usuario, temas de iconos, etc.), extensiones principales, recursos de stock (filtros, fuentes, marcadores, paletas de colores, símbolos, plantillas) y documentación (archivos de ejemplo SVG, tutoriales).

La ubicación en la que Inkscape espera el directorio de datos del sistema puede ser anulada con la variable de entorno INKSCAPE_DATADIR.

--user-data-directory
Imprime el directorio de perfil de usuario donde se almacenan los archivos de datos y preferencias específicos del usuario. Las extensiones y recursos personalizados (filtros, fuentes, marcadores, paletas de colores, símbolos, plantillas) deben instalarse en sus subdirectorios correspondientes en este directorio. Además, colocar un archivo con un nombre idéntico a uno en el directorio de datos del sistema aquí permite anular la mayoría de los ajustes predeterminados del directorio de datos del sistema (por ejemplo, plantillas predeterminadas, archivos de interfaz de usuario, etc.).

La ubicación predeterminada del directorio de perfil puede ser anulada con la variable de entorno INKSCAPE_PROFILE_DIR.

-p, --pipe
Lee el archivo de entrada desde la entrada estándar (stdin).
--pages=PAGINA
Importa la lista de páginas separadas por comas dada de un archivo PDF o SVG multipágina.

Esto reemplaza el --pdf-page de versiones anteriores de Inkscape.

--pdf-poppler
Por defecto, Inkscape importa archivos PDF a través de una biblioteca interna (derivada de poppler). El texto se almacena como texto. Las mallas se convierten en teselas. Usa --pdf-poppler para importar a través de una biblioteca externa (poppler con backend cairo) en su lugar. El texto consiste en grupos que contienen glifos clonados donde cada glifo es un trazo. Las imágenes se almacenan internamente. Las mallas hacen que todo el documento se represente como una imagen rasterizada.
--convert-dpi-method=METODO
Elige el método utilizado para reescalar archivos antiguos (anteriores a 0.92) que se renderizan ligeramente más pequeños debido al cambio de 90 DPI a 96 DPI al interpretar longitudes expresadas en unidades de píxeles. Los valores posibles son "none" (sin cambios, el documento se renderizará al 94% de su tamaño original), "scale-viewbox" (el documento se reescalará globalmente, las longitudes individuales permanecerán sin cambios) y "scale-document" (cada longitud se reescalará individualmente).
--no-convert-text-baseline-spacing
No corregir automáticamente el espaciado de la línea base del texto en archivos antiguos (anteriores a 0.92) al abrirlos. Inkscape 0.92 adopta la definición estándar de CSS para la propiedad 'line-height', que difiere de versiones anteriores. Por defecto, los valores de altura de línea en archivos creados antes de Inkscape 0.92 se ajustarán al cargarse para preservar el diseño de texto previsto. Esta opción de línea de comandos omitirá ese ajuste.
-o, --export-filename=NOMBRE_ARCHIVO
Establece el nombre del archivo de salida. Por defecto, se reutiliza el nombre del archivo de entrada. Si también se utiliza --export-type, la extensión del archivo se ajustará (o se añadirá) según corresponda. De lo contrario, el tipo de archivo a exportar se inferirá de la extensión del nombre de archivo especificado.

El uso del nombre de archivo especial "-" hace que Inkscape escriba los datos de la imagen en la salida estándar (stdout).

--export-overwrite
Sobrescribe el archivo de entrada.
--export-type=TIPO[,TIPO]*
Especifica el tipo de archivo a exportar. Valores posibles: svg, png, ps, eps, pdf, emf, wmf y cualquier tipo de archivo para el cual exista una extensión de exportación. Es posible exportar más de un tipo de archivo a la vez.

Tenga en cuenta que PostScript no admite transparencia, por lo que cualquier objeto transparente en el SVG original se rasterizará automáticamente. Las fuentes utilizadas se subconjuntan y se incrustan. El área de exportación predeterminada es la página; puede establecerla en dibujo con --export-area-drawing.

Tenga en cuenta que el formato PDF pres

erva la transpar

encia del SVG original.
--export-extension=EXTENSION-
ID
Permite especificar una extensión de salida que se usará para exportar, lo cual es especialmente relevante si existe más de una opción de exportación para un tipo de archivo dado. Si se establece, la extensión de archivo en --export-filename y --export-type puede omitirse. Adicionalmente, si se establece, solo se puede indicar un tipo de archivo en

-C, --export-area-p
age
En SVG, PNG, PDF, PS el área exportada es la página. Esto es lo predeterminado para SVG, PNG, PDF y PS, por lo que no necesita especificarlo a menos que esté usando --export-id para exportar un objeto específico. Para EPS esta opción actualmente no está
soportada.
-D, --export-area-draw
ing
En la exportación a SVG, PNG, PDF, PS y EPS, el área exportada es el dibujo (no la página), es decir, la caja delimitadora de todos los objetos del documento (o del objeto exportado si se usa --export-id). Con esta opción, la imagen exportada mostrará todos los objetos visibles del documento sin márgenes ni recortes. Esta es el área de exportación predeterminada para EPS. Para PNG, se puede usar en combinación con --export-use-hin
ts.
-a x0:y0:x1:y1, --export-area=x0:y0:x1:
y1
En la exportación a PNG, establece el área exportada del documento, especificada en px (1/96 in). El valor predeterminado es exportar la página completa del documento. El punto (0,0) es la esquina inferior
izquierda.
--export-area-s
nap
Para la exportación a PNG, ajusta el área de exportación hacia afuera a los valores enteros de px más cercanos. Si está usando la resolución de exportación predeterminada de 96 dpi y sus gráficos están ajustados a píxeles para minimizar el suavizado de bordes, esta opción le permite preservar esta alineación incluso si está exportando la caja delimitadora de algún objeto (con --export-id o --export-area-drawing) que en sí misma no está alineada a
píxeles.
-d DPI, --export-dpi=DP
I
La resolución usada para la exportación a PNG. También se usa para la rasterización de respaldo de objetos con filtros al exportar a PS, EPS o PDF (a menos que especifique --export-ignore-filters para suprimir la rasterización). El valor predeterminado es 96 dpi, lo que corresponde a 1 unidad de usuario SVG (px, también llamada "unidad de usuario") exportando a 1 píxel de mapa de bits. Este valor anula la sugerencia de DPI si se usa con --export-use-hi
nts.
-w WIDTH, --export-width=WID
TH
El ancho del mapa de bits generado en píxeles. Este valor anula la configuración de --export-dpi (o la sugerencia de DPI si se usa con --export-use-hints)
.
-h HEIGHT, --export-height=HEIG
HT
La altura del mapa de bits generado en píxeles. Este valor anula la configuración de --export-dpi (o la sugerencia de DPI si se usa con --export-use-hints)
.
--export-margin=MARG
IN
Añade un margen alrededor del área exportada. El tamaño del margen se especifica en unidades de tamaño de página (para SVG) o milímetros (para PS/PDF). La opción actualmente no tiene efecto para otros formatos de
exportación.
-i ID, --export-page=all|n[,a-b]
*
Exporta solo las páginas seleccionadas. Si se especifica más de una página, el documento resultante puede contener múltiples páginas si el formato lo soporta.

El valor puede ser una lista separada por comas de números de página, o

rangos de página de dos números separados por un guion. La palabra cla

*
Para la exportación a PNG, PS, EPS, PDF y SVG plano, el valor del atributo id del objeto(s) que desea exportar del documento; todos los demás objetos no se exportan. Si especifica muchos valores con una lista de objetos separada por punto y coma, cada uno se exportará por separado. En este caso los archivos exportados se nombrarán de esta manera: [nombre_archivo_de_entrada]_[ID].

--export-lat
ex
(para exportación a PS, EPS y PDF) Usado para crear imágenes para documentos LaTeX, donde el texto de la imagen es compuesto por LaTeX. Al exportar a formato PDF/PS/EPS, esta opción divide la salida en un archivo PDF/PS/EPS (por ejemplo, como se especifica con --export-type) y un archivo LaTeX. El texto no se emitirá en el archivo PDF/PS/EPS, sino que aparecerá en el archivo LaTeX. Este archivo LaTeX incluye el PDF/PS/EPS. Al incluir (\input{image.tex}) el archivo LaTeX en su documento LaTeX se mostrará la imagen y todo el texto será compuesto por LaTeX. Consulte el archivo LaTeX resultante para más información. Vea también el terminal de salida 'epslatex' de
GNUPlot.
--export-ignore-filt
ers
Exporta objetos con filtros (por ejemplo, aquellos con desenfoque) como vectores, ignorando los filtros (para exportación a PS, EPS y PDF). Por defecto, todos los objetos con filtros se rasterizan a --export-dpi (predeterminado 96 dpi), preservando la
apariencia.

nts

Estas sugerencias se establecen automáticamente cuando exporta la selección desde Inkscape. Así que, por ejemplo, si exporta una forma con id="path231" como /home/me/shape.png a 300 dpi desde document.svg usando la GUI de Inkscape, y guarda el documento, luego podrá reexportar esa forma al mismo archivo con la misma resolución simplemente con 
inkscape -i path231 -t document.
svg

Si usa --export-dpi, --export-width, o --export-height con esta opción, la sugerencia de DPI se ignor

ará y se usará el valor de la línea de comandos. Si usa --export-filename con esta opción, la
sugerencia de nombre de archivo se ignorará y se usará el nombre de archivo de la línea de comandos.

NOTAS DE LA INTERFAZ

GRÁFICA

Para aprender el funcionamiento de la interfaz gráfica de Inkscape, lea el manual en Ayuda > Manual de Inkscape, y los tutoriales en Ayuda >

Tutoriales.

Además de SVG, Inkscape puede importar (Archivo > Importar) la mayoría de los formatos de mapa de bits (PNG, BMP, JPG, XPM, GIF, etc.), texto plano (requiere Perl), PS y EPS (requiere Ghostscript), y los formatos PDF y AI (AI versión 9.0 o posterior)

.

Inkscape exporta imágenes PNG de 32 bits (Archivo > Exportar imagen PNG), así como AI, PS, EPS, PDF, DXF y varios otros formatos mediante Archivo > Guardar

como.

Inkscape puede usar la presión y la inclinación de la pluma de una tableta gráfica para el ancho, el ángulo y la fuerza de acción de varias herramientas, incluyendo la Pluma

caligráfica.

Inkscape incluye una interfaz gráfica para el motor de trazado de mapas de bits Potrace (http://potrace.sf.net) que está integrado en

Inkscape.

Inkscape puede usar scripts externos (filtros de stdin a stdout) que se representan como comandos en el menú Extensiones. Un scri

pt puede tener un cuadro de diálogo de interfaz gráfica para establecer varios parámetros y puede obtener los ID de los objetos se
leccionados sobre los que actuar a través de la línea de comandos. Inkscape viene con una variedad de efectos escritos en Python.

HISTORI

A

La base de código que se convertiría en Inkscape comenzó su vida en 1999 como el programa Gill, la aplicación de ilustración para GNOME, creada por Raph Levien. El objetivo declarado de Gill era soportar eventualmente todo el estándar SVG. Raph implementó el modelo de imagen bezier de PostScript, incluyendo contorno y relleno, estilo de terminación de línea, estilo de unión de línea, texto, etc. La página de Gill de Raph está en http://www.levien.com/svg/. El trabajo en Gill parece haberse ralentizado o cesado en el año

2000.

La siguiente encarnación de la base de código se convertiría en el muy popular programa Sodipodi, liderado por Lauris Kaplinski. La base de código se transformó en un potente programa de ilustración a lo largo de varios años de trabajo, añadiendo varias características nuevas, soporte multilingüe, portando a Windows y otros sistemas operativos, y eliminando

dependencias.

Inkscape se formó en 2003 por cuatro desarrolladores activos de Sodipodi, Bryce Harrington, MenTaLguY, Nathan Hurst y Ted Gould, que querían tomar una dirección diferente con la base de código en términos de enfoque en el cumplimiento de SVG, la apariencia de la interfaz y el deseo de abrir las oportunidades de desarrollo a más participantes. El proyecto progresó rápidamente, ganando un número de colaboradores muy activos y características

.

Gran parte del trabajo en los primeros días del proyecto se centró en la estabilización del código y la internacionalización. El motor de renderizado original heredado de Sodipodi estaba plagado de varios casos límite matemáticos que conducían a fallos inesperados cuando el programa se empujaba más allá de los usos rutinarios; este motor fue reemplazado por Livarot, que, aunque tampoco era perfecto, era significativamente menos propenso a errores. El proyecto también adoptó una práctica de confirmar código frecuentemente y de animar a los usuarios a ejecutar instantáneas de desarrollo del programa; esto ayudó a identificar nuevos errores rápidamente y a asegurar que fuera fácil para los usuarios verificar las correcciones. Como resultado, las versiones de Inkscape han ganado generalmente una reputación de ser robustas y

fiables.

De manera similar, se tomaron esfuerzos para internacionalizar y localizar la interfaz, lo que ha ayudado al programa a ganar colaboradores en todo el

mundo.

Inkscape ha tenido un impacto beneficioso en el atractivo visual del Código Abierto en general, al proporcionar una herramienta para crear y

compartir iconos, pantallas de presentación, gráficos de sitios web, y así sucesivamente. De alguna manera, a pesar de ser "solo un programa d
e dibujo", Inkscape ha jugado un papel importante en hacer que el Código Abierto sea más estimulante visualmente para audiencias más amplias.
