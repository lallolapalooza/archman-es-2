NOMBRE

innoextract - herramienta para extraer instaladores creados por Inno Setup

SINOPSIS

innoextract [--extract] [--lowercase] [opciones] [--] instaladores ...

innoextract --list [opciones] [--] instaladores ...

innoextract --test [opciones] [--] instaladores ...

DESCRIPCIÓN

innoextract es una herramienta que puede extraer ejecutables de instalación creados por Inno Setup.

innoextract extraerá archivos de los instaladores especificados en la línea de comandos.

Para extraer un instalador multiparte con archivos de datos externos, solo se necesita proporcionar el archivo ejecutable (.exe) como argumento a innoextract.

OPCIONES

--
Trata todos los argumentos posteriores a este como archivos, incluso si comienzan con un guion.
--check-password
Aborta el procesamiento si la contraseña proporcionada mediante la opción --password o --password-file no coincide con la suma de comprobación almacenada en el instalador.

La suma de comprobación de la contraseña utilizada para esta verificación se puede obtener usando la opción --show-password .

--codepage PÁGINA_DE_CÓDIGOS
Las versiones no Unicode de Inno Setup almacenan las cadenas en una codificación no especificada. Por defecto, innoextract intentará adivinar la codificación a partir de la lista de idiomas del instalador, usando Windows-1252 como alternativa. Esta opción se puede usar para anular esa suposición especificando un número de página de códigos de Windows distinto de cero para usar.

En plataformas no Windows, innoextract ignorará la configuración regional del sistema y siempre usará UTF-8 como codificación del sistema de archivos y de la salida estándar; la opción --codepage solo cambia la codificación de entrada. Sin embargo, usar el número de página de códigos "65001" le indica a innoextract que asuma que todas las cadenas ya están codificadas como UTF-8 y que las salga sin convertir.

Esta opción no tiene efecto con los instaladores habilitados para Unicode, que siempre usan UTF-16LE. Los datos UTF-16 no válidos se representan usando la codificación WTF-8, que es una extensión directa de UTF-8 para representar unidades de código de sustitución UTF-16 no emparejadas.

--collisions ACCIÓN
Los instaladores de Inno Setup pueden contener archivos duplicados con el mismo nombre. Esta opción le dice a innoextract qué hacer cuando se encuentra con una de estas colisiones. Las acciones válidas son:
"overwrite"
Extrae solo uno de los archivos en colisión. La elección se hace de manera similar a como Inno Setup sobrescribe los archivos durante la instalación. Esta es la acción por defecto.
"rename"
Renombra los archivos que serían sobrescritos por la acción "overwrite" añadiendo un sufijo compuesto por el idioma del archivo, su arquitectura, el componente al que pertenece y/o un número para hacer único el nombre de archivo. El sufijo de idioma (si aplica) también se añade al archivo por defecto que habría sido extraído con la acción "overwrite".
"rename-all"
Renombra todos los archivos en colisión añadiendo un sufijo compuesto por el idioma del archivo, su arquitectura, el componente al que pertenece y/o un número para hacer único el nombre de archivo. El sufijo completo se añade tanto a los archivos que habrían sido sobrescritos con la acción "overwrite" como a aquellos que habrían sobrescrito a otros archivos.
"error"
Sale del programa cuando se detecta una colisión.
Reglas de renombrado:

1. Si el componente no es el mismo para todos los archivos en el conjunto de colisión (todos los archivos con el mismo nombre de archivo), se añade "#" (sin comillas) seguido del id del componente a todos los archivos que son específicos de un solo componente.

2. Si el idioma no es el mismo para todos los archivos en el conjunto de colisión, se añade "@" (sin comillas) seguido del id del idioma a todos los archivos que son específicos de un solo idioma, a menos que ese idioma coincida con el idioma por defecto especificado por --default-language. Aunque el sufijo se omite para el idioma por defecto, no se añade un sufijo numerado en su lugar a menos que sea necesario para hacer único el nombre de archivo.

3. Si la arquitectura no es la misma para todos los archivos en el conjunto de colisión, se añade "@32bit" o "@64bit" (sin comillas) a todos los archivos que son específicos de una sola arquitectura.

4. Si no se añadió ningún sufijo en los pasos anteriores, o si el nombre de archivo aún no es único, se añade "$" (sin comillas) seguido del entero más bajo (empezando por 0) necesario para hacer único el nombre de archivo.

Con la acción "rename", los pasos 1 y 3 se aplican solo a los archivos que habrían sido sobrescritos por la acción "overwrite", mientras que "rename-all" los aplica a todos los archivos en el conjunto de colisión.

-c, --color[=HABILITAR]
Por defecto, innoextract intentará detectar si el terminal soporta códigos de escape de shell y habilitará o deshabilitará la salida a color en consecuencia. Específicamente, los colores se habilitarán si tanto stdout como stderr apuntan a un TTY, la variable de entorno TERM no está establecida a "dumb" y la variable de entorno NO_COLOR no está definida. Pase 1 o true a --color para forzar la salida a color. Pase 0 o false para nunca generar códigos de
color.

-L, --lowercase
Convertir los nombres de archivo almacenados en el instalador a minúsculas antes de extraer.
-d, --output-dir DIR
Extraer todos los archivos en el directorio dado. Por defecto, innoextract extraerá todos los archivos al directorio actual.

Si el directorio especificado no existe, se creará. Sin embargo, el directorio principal debe existir o la extracción fallará.

-P, --password PASSWORD
Especifica la contraseña para descifrar archivos cifrados. Se asume que la contraseña está codificada como UTF-8 y se convierte a la codificación interna según la utilizada en el instalador según sea necesario.

Utilice la --password-file opción para cargar la contraseña desde un archivo o la entrada estándar en su lugar. Esta opción no puede combinarse con --password-file.

Si esta contraseña no coincide con el checksum almacenado en el instalador, los archivos cifrados se omitirán pero los archivos no cifrados se extraerán igualmente. Utilice la --check-password opción para abortar el procesamiento por completo si la contraseña es incorrecta.

--password-file FILE
Cargar una contraseña desde el archivo especificado. Solo se utiliza la primera línea, excluyendo el retorno de carro final y/o el salto de línea, como contraseña. Se asume que la contraseña está codificada como UTF-8 y se convierte a la codificación interna según la utilizada en el instalador según sea necesario.

Si se usa el nombre de archivo especial "-", la contraseña se leerá de la entrada estándar.

Utilice la --password opción para especificar la contraseña en la línea de comandos en su lugar. Esta opción no puede combinarse con --password.

Si esta contraseña no coincide con el checksum almacenado en el instalador, los archivos cifrados se omitirán pero los archivos no cifrados se extraerán igualmente. Utilice la --check-password opción para abortar el procesamiento por completo si la contraseña es incorrecta.

-p, --progress[=ENABLE]
Por defecto innoextract intentará detectar si el terminal soporta códigos de escape de shell y habilitará o deshabilitará la salida de la barra de progreso en consecuencia. Pase 1 o true a --progress para forzar la salida de la barra de progreso. Pase 0 o false para nunca mostrar una barra de progreso.
-q, --quiet
Salida menos detallada.
--show-password
Mostrar el checksum $c y la sal $s utilizados para la verificación de la contraseña $p así como la codificación de la contraseña. El checksum se calcula a partir de la sal concatenada con la contraseña:


$c = hash($s . $p)

Con la --silent opción, el nombre del checksum y el hash se imprimen en una línea separados por un espacio seguido de la sal codificada como bytes hexadecimales y la codificación de la contraseña en líneas separadas.

Los tipos de checksum pueden ser CRC32, MD5 o SHA-1 aunque CRC32 no se usa en instaladores con cifrado.

Utilice la --password o --password-file opción junto con --check-password para verificar si una contraseña coincide con este checksum.

-s, --silent
No imprimir nada excepto errores y advertencias a menos que se solicite explícitamente y usar un formato de salida legible por máquina.

Esta opción puede combinarse con --list para imprimir solo los nombres de los archivos contenidos (uno por línea) sin sintaxis adicional que dificulte el consumo por otros scripts.

-t, --test
Probar la integridad del archivo pero no escribir ningún archivo de salida.

Esta opción puede combinarse con --extract para abortar en errores de checksum de archivos.

-T, --timestamps TZ
Los instaladores de Inno Setup pueden contener marcas de tiempo tanto en UTC como en zonas horarias 'locales'.

La --timestamps opción especifica qué zona horaria debe usarse para ajustar estos tiempos de archivo 'locales'.

Los valores válidos son los aceptados por tzset en la variable de entorno TZ , excepto con la dirección del desfase horario invertida: tanto -T CET como -T GMT+1 darán (cuando el DST está en vigor) el mismo resultado.

Además de las zonas horarias, se aceptan dos valores especiales:

"none" No preservar los tiempos de archivo para los archivos extraídos, tanto para marcas de tiempo UTC como 'locales'. Los tiempos de archivo se dejarán como el sistema operativo los estableció al crear los archivos de salida.

"local" Usar la zona horaria del sistema para las marcas de tiempo 'locales'. Este es el comportamiento normal de Inno Setup, y puede usarse junto con la TZ variable de entorno.

El valor por defecto para esta opción es UTC, lo que hace que innoextract no ajuste los tiempos de archivo 'locales'. Los tiempos de archivo marcados como UTC en el archivo de Inno Setup nunca se ajustarán sin importar qué --timestamps esté configurado.

-v, --version
Imprimir el número de versión de innoextract y las versiones de Inno Setup soportadas.

Si se combina con la --silent opción, solo se imprime el número de versión . De lo contrario, la salida contendrá el nombre (innoextract) seguido del número de versión en la primera línea, y, a menos que la --quiet opción se especifique, el rango de versiones de instaladores de Inno Setup soportadas en la segunda línea.

--no-warn-unused
Por defecto, innoextract imprimirá una advertencia si encuentra .bin archivos que parecen ser parte de la configuración pero no se usan. Esta opción deshabilita esa advertencia.

CONSTANTES DE RUTA

Las rutas en los instaladores de Inno Setup pueden contener constantes (referencias a variables o código) que se expanden en el momento de la instalación. innoextract expande todas estas constantes a su nombre y reemplaza los caracteres inseguros con $. Por ejemplo {app} se expande a app mientras que {code:Example} se expande a code$Example.

Actualmente no hay forma de configurar esta expansión excepto deshabilitándola con la --dump opción.

LIMITACIONES

No hay soporte para extraer componentes individuales y soporte limitado para filtrar por nombre.

Los scripts y verificaciones incluidos no se ejecutan.

El mapeo de constantes de Inno Setup como el directorio de la aplicación a subdirectorios está codificado de forma fija.

Los nombres de los archivos de slice/disco de datos en instaladores de múltiples archivos deben seguir el esquema de nombres estándar.
