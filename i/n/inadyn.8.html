NOMBRE

inadyn — Cliente Automático de DNS Dinámico de Internet

SINOPSIS

inadyn [-1, --once] [--force] [--cache-dir RUTA] [-c, --cmd /ruta/a/cmd] [-C, --continue-on-error] [-e, --exec /ruta/a/cmd] [--exec-mode MODO] [-f, --config ARCHIVO] [-h, --help] [-i, --iface NOMBREIF] [-I, --ident NOMBRE] [-j, --json] [-l, --loglevel NIVEL] [-L, --list-providers] [-n, --foreground] [--no-pidfile] [-P, --pidfile ARCHIVO] [-p, --drop-privs USUARIO[:GRUPO]] [-s, --syslog] [-S, --show-provider -NOMBRE] [-t, --startup-delay SEG] [-v, --version]

DESCRIPCIÓN

inadyn, o In-a-Dyn, comprueba periódicamente si ha cambiado tu IP realmente accesible por Internet. Cuando cambia inadyn actualiza automáticamente tus registros de servidor de nombres.

Los proveedores de servicios DDNS comunes admitidos por inadyn se enumeran a continuación. Algunos de estos servicios son gratuitos para uso no comercial, otros cobran una pequeña tarifa, pero también proporcionan más nombres de dominio para elegir.

inadyn usa HTTPS de forma predeterminada para todos los proveedores, algunos sin embargo pueden no admitir esto, así que intente deshabilitar SSL para su proveedor en caso de problemas. OPCIONES

Versiones anteriores de inadyn admitían más opciones de línea de comandos, desde la v2.0 inadyn ha sido simplificado en gran medida. Vea inadyn.conf(5) para detalles del formato del archivo de configuración /etc/inadyn.conf .

-1, --once
Ejecutar solo una vez y salir, actualiza solo si es demasiado antiguo o desconocido. Use --force para forzar una actualización antes de salir.
--force
Forzar una actualización. Solo funciona con el indicador -1, --once , se ignora para todos los demás casos de uso.
--cache-dir RUTA
Establece el directorio para los archivos de caché persistentes, por defecto es /var/cache/inadyn

Los archivos de caché se usan para llevar un registro de qué direcciones se han enviado con éxito a su respectivo proveedor DDNS y cuándo. El 'cuándo' es importante para evitar que inadyn te prohíba por actualizaciones excesivas.

Al reiniciar inadyn o al reiniciar tu servidor, o dispositivo integrado, inadyn lee los archivos de caché para sembrar sus estructuras de datos internas con la última dirección IP enviada y cuándo se realizó la actualización. Por lo tanto, es muy importante tener un archivo de caché y que tenga la marca de tiempo correcta. La ausencia de un archivo de caché causará actualmente una actualización forzada.

En un dispositivo integrado sin RTC, o sin RTC respaldado por batería, se recomienda encarecidamente emparejar esta configuración con la opción de línea de comandos --startup-delay SEG .

-c, --cmd /ruta/a/cmd [argumentos opcionales]
Ruta completa al comando, o script, a ejecutar para comprobar cambios en la dirección IP. Esto es lo mismo que la opción del archivo de configuración checkip-command pero se aplicará a todos los proveedores. Esta opción de línea de comandos se proporciona solo por conveniencia, se recomienda usar en su lugar el archivo de configuración. Para más detalles, vea la página man inadyn.conf(5) . Necesitará entrecomillar el comando completo si se proporcionan argumentos, o una tubería.
--continue-on-er
ror
Ignora los errores del proveedor DDNS e inténtalo de nuevo más tarde. Esta opción de línea de comando le indica a inadyn que no salga ante errores de un proveedor DDNS, sino que intente de nuevo más tarde. Por favor, no use esto; normalmente indica que estamos enviando una solicitud malformada, por ejemplo, un nombre de usuario, contraseña o alias DNS incorrecto para la cuenta dada. ¡Continuar podría bloquear el acceso a su cuenta!

-i IFNAME , también se establece la variable de entorno INADYN_IFACE. Necesitará citar el comando

--exec-mode MODO Use
MODO
para establecer el modo de ejecución del script: compat, event: - compat: ejecutar el manejador de ejecución solo en una actualización DDNS exitosa, por defecto - event: ejecutar el manejador de ejecución en cualquier estado de actualización. Se establecen las siguientes variables de entorno: INADYN_EVENT, INADYN_ERROR, INADYN_ERROR_MESSAGE. INADYN_EVENT contiene el evento, uno de: nochg, update, error. El evento nochg indica que no se tuvo que enviar ninguna actualización, el evento update indica que una actualización se envió exitosamente, el evento error indica que la actualización se envió y ocurrió un error. INADYN_ERROR contiene el código de error, INADYN_ERROR_MESSAGE contiene el mensaje de error para el código de error. -f, --config ARCHIVO Use ARCH
