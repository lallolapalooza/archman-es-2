NOMBRE

innxbatch, sendxbatches - Envía artículos Usenet xbatched a un servidor NNTP remoto

SINOPSIS

innxbatch [-Dv] [-t timeout] [-T timeout] host archivo [archivo ...]

innxbatch -i [-Dv] [-t timeout] [-T timeout] host

sendxbatches sitename host archivo [archivo ...]

DESCRIPCIÓN

innxbatch se conecta al puerto 119 del servidor NNTP en el host especificado, y le envía los archivos xbatch especificados, utilizando la extensión XBATCH del protocolo NNTP. Estos archivos se especifican ya sea desde la línea de comandos o desde la entrada estándar si se usa -i.

Cada archivo se elimina después de haber sido transferido exitosamente.

Si ocurre un error de comunicación, como un fallo de write(2), o una respuesta inesperada del servidor remoto, innxbatch dejará de enviar y dejará todos los archivos restantes sin tocar para un reintento posterior.

Si hay credenciales de autenticación para el servidor remoto en el archivo passwd.nntp en pathetc, entonces innxbatch las usará para autenticarse.

innxbatch no utiliza bloqueo de archivos por sí mismo. En el peor de los casos, un lote podría transmitirse dos veces en paralelo por dos invocaciones independientes de innxbatch. Para evitar esto, debería ser invocado por un script ejecutado fuera de cron(8) que use shlock(8) para bloquear el nombre del host, seguido de un comando "ctlinnd flush" para vaciar el archivo de lotes. sendxbatches es un envoltorio así alrededor de innxbatch. Se asegurará de que solo se ejecute una instancia, vaciará sitename (tal como se usa en la entrada de newsfeeds) y enviará al host los archivos dados como argumentos.

Dado que la extensión XBATCH no es un comando NNTP estandarizado, algunos servidores de noticias no la reconocen. Además, para aceptar lotes de pares remotos a través de XBATCH, debe habilitar explícitamente la capacidad con la configuración xbatch en incoming.conf. En lugar de usar innxbatch, puede considerar innfeed, o si eso no es posible, nntpsend.

OPCIONES

-D
Imprime información de depuración en la salida estándar de error. Esto mostrará las transacciones del protocolo entre innxbatch y el servidor NNTP en el host remoto.
-i
Lee los nombres de archivo de lote de la entrada estándar. Por cada lote transferido con éxito, se imprimirá un "OK" en la salida estándar para indicar que se espera otro nombre de archivo.
-t timeout
Especifica un tiempo de espera en segundos sobre cuánto tiempo intentar establecer la conexión. De lo contrario, innxbatch normalmente se bloquea hasta que se establece la conexión.
-T timeout
Especifica el tiempo total en segundos que se debe permitir para las transferencias de artículos.

El valor predeterminado es esperar hasta que ocurra un error de E/S, o hasta que se hayan transferido todos los artículos. Si se utiliza esta opción, el tiempo se verifica justo antes de que comience cada artículo; no abortará una transferencia que esté en curso.

-v
Al salir, innxbatch informa estadísticas de transferencia y uso de CPU a través de syslog(3). Si se utiliza esta opción, también se imprimirán en la salida estándar.

EJEMPLOS

Una entrada de ejemplo para newsfeeds para producir archivos xbatch apropiados es:

nase\
    :*\
    :Tc,Wnb\
    :<pathbin>/batcher -p "(<$COMPRESS in <pathlib>/innshellvars>\
        > <pathoutgoing>/nase.\$\$)" nase.do.main

Un script de ejemplo para invocar innxbatch(8) es:

#! /bin/sh
#  Envía xbatches para un sitio, envuelto alrededor de innxbatch.
if [ $# -lt 3 ]
then
    echo "uso: $0 <nombre_sitio> <nombre_host> <nombre_archivo_xbatch> ..."
    exit 1
fi
. <pathlib>/innshellvars
site="$1"; host="$2"; shift; shift
ctlinnd flush "$site" \
&& sleep 5 \
&& exec ${NEWSBIN}/innxbatch -v -D "$host" $*

Puede usar sendxbatches, ya incluido con INN, que realiza el bloqueo. Un ejemplo de llamada es:

sendxbatches nase remote.news.server.name <pathoutgoing>/nase*
