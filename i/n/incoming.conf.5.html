NOMBRE

incoming.conf - Configuración de las fuentes de noticias entrantes

EN POCOS PALABRAS

El archivo incoming.conf configura desde qué nodos remotos innd acepta fuentes NNTP.

Una entrada común para permitir "news.server.com" como un nodo entrante es:

peer news.server.com {
    hostname: "news.server.com"
}

El puerto utilizado para las fuentes entrantes es aquel en el que innd está escuchando (normalmente el puerto 119 o 433).

Las entradas de nodo se leen en el orden en que aparecen en el archivo de configuración. La primera entrada de nodo con un valor de hostname que coincida con la conexión entrante se utilizará para otorgar acceso al nodo remoto. Las entradas subsiguientes se descartarán.

Después de cualquier cambio, ejecute "inncheck" para realizar verificaciones básicas de sintaxis y recargue este archivo de configuración con el siguiente comando:

ctlinnd reload incoming.conf 'new peer'

DESCRIPCIÓN

El archivo pathetc/incoming.conf consta de tres tipos de entradas: clave/valor, nodo y grupo. Los comentarios van desde el carácter hash "#" hasta el final de la línea. Las líneas en blanco se ignoran. Todas las entradas de clave/valor dentro de cada tipo no deben duplicarse. Las entradas de clave/valor son una palabra clave seguida inmediatamente de dos puntos, al menos un espacio y un valor. Por ejemplo:

max-connections: 10

Una clave legal no contiene espacios, dos puntos ni "#". Hay tres tipos diferentes de valores: enteros, booleanos y cadenas. Los enteros son como se espera. Un valor booleano es "true", "yes", "on", "false", "no" o "off" (la capitalización no es significativa). Un valor de cadena es cualquier otra secuencia de caracteres. Si la cadena necesita contener espacios en blanco, debe entrecomillarse con comillas dobles.

Las entradas de nodo tienen el siguiente aspecto:

peer <nombre> {
    # cuerpo
}

La palabra "peer" es obligatoria. <nombre> es una etiqueta para este nodo. Es cualquier cadena válida como clave. El cuerpo de una entrada de nodo contiene un número de entradas de clave/valor.

Las entradas de grupo tienen el siguiente aspecto:

group <nombre> {
    # cuerpo
}

La palabra "group" es obligatoria. <nombre> es cualquier cadena válida como clave. El cuerpo de una entrada de grupo contiene cualquier número de los tres tipos de entradas. Por lo tanto, los pares clave/valor se pueden definir dentro de un grupo, y los nodos se pueden anidar dentro de un grupo, y otros grupos se pueden anidar dentro de un grupo. Las entradas de clave/valor que se definen fuera de todos los nodos y grupos se denominan de ámbito global. Las entradas de clave/valor globales actúan como valores predeterminados para los nodos. Cuando innd busca un valor específico en una entrada de nodo (por ejemplo, el número máximo de conexiones permitidas), si el valor no está definido en la entrada del nodo, se examinan los grupos circundantes en busca de la entrada (comenzando por el grupo circundante más cercano). Si no hay grupos circundantes, o los grupos circundantes no definen la clave/valor, se utiliza el valor del ámbito global. Un pequeño ejemplo podría ser:

# Valor global aplicado a todos los nodos que no tienen un valor propio.
max-connections: 5
# Una definición de nodo.
peer uunet {
    hostname: usenet1.uu.net
}
peer vixie {
    hostname: gw.home.vix.com
    max-connections: 10        # Sobrescribe el valor global.
}
# Un grupo de dos nodos que pueden abrir más conexiones de lo normal.
group fast-sites {
    max-connections: 15
    # Otro nodo.  Se utiliza el valor max-connections del ámbito del
    # grupo fast-sites.
    peer data.ramona.vix.com {
        hostname: data.ramona.vix.com
    }
    peer bb.home.vix.com {
        hostname: bb.home.vix.com
        max-connections: 20    # Puede realmente cocinar.
   }
}

Dado el archivo de configuración anterior, los nodos definidos tendrían los siguientes valores para la clave max-connections.

uunet                  5
vixie                 10
data.ramona.vix.com   15
bb.home.vix.com       20

PARÁMETROS

Las siguientes claves están permitidas:

hold-time
Esta clave requiere un valor entero positivo. Define el tiempo de espera antes de cerrar, si la conexión excede max-connections. Un valor de cero especifica el cierre inmediato. El valor predeterminado es 0.
hostname
Esta clave requiere un valor de cadena. Es una lista de nombres de host separados por comas. Un nombre de host es un nombre de dominio completo que se resuelve a la dirección IPv4 o IPv6 del nodo, o la dirección IP de cuartetos separados por puntos del nodo para IPv4, o la dirección IP separada por dos puntos del nodo para IPv6. Si esta clave no está presente en un bloque de nodo, el nombre de host toma como valor predeterminado la etiqueta del nodo.
identd
Esta clave requiere un valor de cadena. Se utiliza si desea exigir que el nombre de usuario de un nodo recuperado a través de identd(8) coincida con la cadena especificada. Tenga en cuenta que actualmente innd no implementa ningún tiempo de espera en las devoluciones de llamada de identd, por lo que habilitar esta opción puede hacer que innd se cuelgue si el nodo remoto no responde a las devoluciones de llamada de ident en un plazo razonable. El valor predeterminado es una cadena vacía, es decir, ningún demonio ident.
ignore
Esta clave requiere un valor booleano. Establecer esta entrada en true hace que innd responda negativamente a las propuestas del nodo remoto de enviarle artículos. El valor predeterminado es false.

Más técnicamente, si ignore es true, innd rechazará cada Message-ID propuesto para ser enviado a través de CHECK o IHAVE por este nodo, comportándose como si ya tuviera el artículo. Un artículo completo enviado por este nodo a través de TAKETHIS (porque no consulta primero con CHECK, o no tiene en cuenta el código de respuesta de rechazo de un CHECK anterior) todavía será aceptado.

list
Esta clave requiere un valor booleano. Define si un nodo puede emitir comandos LIST. El valor predeterminado es true, es decir, puede.
max-connections
Esta clave requiere un valor entero positivo. Define el número máximo de conexiones permitidas. Un valor de cero especifica un número ilimitado de conexiones máximas (se pueden usar "unlimited" o "none" como sinónimos). El valor predeterminado es 0.
password
Esta clave requiere un valor de cadena. Se utiliza si desea exigir que un nodo proporcione una contraseña a través de AUTHINFO USER/PASS. El valor predeterminado es una cadena vacía, es decir, no se espera contraseña.

Tenga en cuenta que innd aceptará cualquier nombre de usuario proporcionado por el nodo remoto siempre que la contraseña sea correcta. (Como el nombre de usuario es obligatorio en el protocolo de autenticación, innd espera uno pero no hace nada con él).

patterns
Esta clave requiere un valor de cadena. Es una lista de grupos de noticias estilo newsfeeds(5) que se aceptarán de este host. El valor predeterminado es la cadena "*", es decir, se aceptan todos los grupos.
resendid
Esta clave requiere un valor booleano. Cuando se establece en true, innd pide al nodo remoto que reintente más tarde enviar el artículo propuesto (lo que ocurre cuando otro nodo ya se ha ofrecido a enviarlo, pero aún no lo ha hecho), utilizando los códigos 431 (respuesta a CHECK, en modo de transmisión) o 436 (respuesta a IHAVE en modo no de transmisión). Cuando se establece en false, innd no solicita ningún nuevo intento (lo que provocará la pérdida de un artículo si el otro nodo no lo envía), utilizando los códigos 438 (respuesta a CHECK) o 435 (respuesta a IHAVE). La función de aplazamiento puede ser útil para nodos que reenvían mensajes de inmediato, como hace innfeed. skip
Esta clave requiere un valor booleano. Establecer esta entrada hace que este par se omita. El valor predeterminado es false.
streaming
Esta clave requiere un valor booleano. Define si se permiten comandos de streaming (CHECK y TAKETHIS) de este par. El valor predeterminado es true.

Esta clave requiere un valor booleano. Define si se permite a un par emitir comandos XBATCH. El valor predeterminado es false, es decir, no puede hacerlo.
