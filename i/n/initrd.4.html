CONFIGURACIÓ

N

/dev/initrd es un dispositivo de bloque de solo lectura asignado con número mayor 1 y número menor 250. Típicamente /dev/initrd es propiedad de root:disk con modo 0400 (acceso de lectura solo para root). Si el sistema Linux no tiene /dev/initrd ya creado, se puede crear con los siguientes

comandos: 


mknod -m 400 /dev/initrd b 1 250
chown root:disk
/dev/initrd

Además, el soporte tanto para "disco RAM" como para "disco RAM inicial" (por ejemplo, CONFIG_BLK_DEV_RAM=y y CONFIG_BLK_DEV_INITRD=y) debe compilarse directamente en el núcleo de Linux para usar /dev/initrd. Al usar /dev/initrd, el controlador de disc

o RAM no puede carg
arse como un módulo.

DESCRIPCIÓ

N

El archivo especial /dev/initrd es un dispositivo de bloque de solo lectura. Este dispositivo es un disco RAM que es inicializado (por ejemplo, cargado) por el cargador de arranque antes de que se inicie el núcleo. El núcleo entonces puede usar el contenido de /dev/initrd para un arranque del sistema en dos

fases.

En la primera fase de arranque, el núcleo se inicia y monta un sistema de archivos raíz inicial a partir del contenido de /dev/initrd (por ejemplo, disco RAM inicializado por el cargador de arranque). En la segunda fase, se cargan controladores adicionales u otros módulos a partir del contenido del dispositivo raíz inicial. Después de cargar los módulos adicionales, se monta un nuevo sistema de archivos raíz (es decir, el sistema de archivos raíz normal) desde un dispositivo

diferente.

Operación de

arranque

Al arrancar con initrd, el sistema arranca de la siguiente

manera:
(1
)
El cargador de arranque carga el programa del núcleo y el contenido de /dev/initrd en la
memoria.
(2
)
Al iniciar el núcleo, este descomprime y copia el contenido del dispositivo /dev/initrd al dispositivo /dev/ram0 y luego libera la memoria usada por /dev/initr
d.
(3
)
El núcleo entonces monta el dispositivo /dev/ram0 como sistema de archivos raíz inicial en modo
lectura-escritura.
(4
)
Si el sistema de archivos raíz normal indicado es también el sistema de archivos raíz inicial (por ejemplo, /dev/ram0) entonces el núcleo salta al último paso para la secuencia de arranque
habitual.
(5
)
Si el archivo ejecutable /linuxrc está presente en el sistema de archivos raíz inicial, /linuxrc se ejecuta con UID 0. (El archivo /linuxrc debe tener permisos de ejecución. El archivo /linuxrc puede ser cualquier ejecutable válido, incluyendo un script de shell.
)
(6
)
Si /linuxrc no se ejecuta o cuando /linuxrc termina, se monta el sistema de archivos raíz normal. (Si /linuxrc sale con algún sistema de archivos montado en el sistema de archivos raíz inicial, entonces el comportamiento del núcleo es NO ESPECIFICADO. Vea la sección NOTAS para el comportamiento actual del núcleo.
)
(7
)
Si el sistema de archivos raíz normal tiene un directorio /initrd, el dispositivo /dev/ram0 se mueve desde / a /initrd. De lo contrario, si el directorio /initrd no existe, el dispositivo /dev/ram0 se desmonta. (Cuando se mueve desde / a /initrd, /dev/ram0 no se desmonta y por lo tanto los procesos pueden permanecer ejecutándose desde /dev/ram0. Si el directorio /initrd no existe en el sistema de archivos raíz normal y algún proceso permanece ejecutándose desde /dev/ram0 cuando /linuxrc sale, el comportamiento del núcleo es NO ESPECIFICADO. Vea la sección NOTAS para el comportamiento actual del núcleo.
)
(8
)
La secuencia de arranque habitual (por ejemplo, la invocación de /sbin/init) se realiz
a en el siste
ma de archivos
raíz normal.

Opcione

s

Las siguientes opciones del cargador de arranque, cuando se usan con initrd, afectan la operación de arranque del

núcleo:
initrd=nombre-de-ar
chivo
Especifica el archivo a cargar como el contenido de /dev/initrd. Para LOADLIN esta es una opción de línea de comandos. Para LILO tienes que usar este comando en el archivo de configuración de LILO /etc/lilo.config. El nombre de archivo especificado con esta opción será típicamente una imagen de sistema de archivos comprimida con
gzip.
noinit
rd
Esta opción de arranque desactiva la operación de arranque en dos fases. El núcleo realiza la secuencia de arranque habitual como si /dev/initrd no hubiera sido inicializado. Con esta opción, cualquier contenido de /dev/initrd cargado en la memoria por el cargador de arranque se conserva. Esta opción permite que el contenido de /dev/initrd sean datos arbitrarios y no necesita limitarse a una imagen de sistema de archivos. Sin embargo, el dispositivo /dev/initrd es de solo lectura y solo puede leerse una vez después del inicio del
sistema.
root=nombre-de-dispos
itivo
Especifica el dispositivo a usar como sistema de archivos raíz normal. Para LOADLIN esta es una opción de línea de comandos. Para LILO esta es una opción de tiempo de arranque o puede usarse como una línea de opción en el archivo de configuración de LILO /etc/lilo.config. El dispositivo especificado por esta
opción debe ser un dispo
sitivo montable con un sistem
a de archivos raíz adecuado.

Cambiar el sistema de archivos raíz

normal

Por defecto, la configuración del núcleo (por ejemplo, establecida en el archivo del núcleo con rdev(8) o compilada en el archivo del núcleo), o la configuración de la opción del cargador de arranque se usa para los sistemas de archivos raíz normales. Para un sistema de archivos raíz normal montado por NFS, se deben usar las opciones de arranque nfs_root_name y nfs_root_addrs para dar la configuración de NFS. Para más información sobre la raíz montada por NFS vea el archivo de documentación del núcleo Documentation/filesystems/nfs/nfsroot.txt (o Documentation/filesystems/nfsroot.txt antes de Linux 2.6.33). Para más información sobre la configuración del sistema de archivos raíz vea también la documentación de LILO y LOADLIN

.

También es posible que el ejecutable /linuxrc cambie el dispositivo raíz normal. Para que /linuxrc cambie el dispositivo raíz normal, /proc debe estar montado. Después de montar /proc, /linuxrc cambia el dispositivo raíz normal escribiendo en los archivos proc /proc/sys/kernel/real-root-dev, /proc/sys/kernel/nfs-root-name, y /proc/sys/kernel/nfs-root-addrs. Para un dispositivo raíz físico, el dispositivo raíz se cambia haciendo que /linuxrc escriba el número de dispositivo del nuevo sistema de archivos raíz en /proc/sys/kernel/real-root-dev. Para un sistema de archivos raíz NFS, el dispositivo raíz se cambia haciendo que /linuxrc escriba la configuración de NFS en los archivos /proc/sys/kernel/nfs-root-name y /proc/sys/kernel/nfs-root-addrs y luego escribiendo 0xff (por ejemplo, el número de dispositivo NFS pseudo) en el archivo /proc/sys/kernel/real-root-dev. Por ejemplo, la siguiente línea de comando de shell cambiaría el dispositivo raíz normal a /dev/hdb1

: 


echo 0x365 >/proc/sys/kernel/real-root-de
v

Para un ejemplo NFS, las siguientes líneas de comando de shell cambiarían el dispositivo raíz normal al directorio NFS /var/nfsroot en un servidor NFS de red local con número IP 193.8.232.7 para un sistema con número IP 193.8.232.2 y llamado

"idefix": 


echo /var/nfsroot >/proc/sys/kernel/nfs-root-name
echo 193.8.232.2:193.8.232.7::255.255.255.0:idefix \
    >/proc/sys/kernel/nfs-root-addrs
echo 255 >/proc/sys/kernel/real-root-de
v

Nota: El uso de /proc/sys/kernel/real-root-dev para cambiar el sistema de archivos raíz está obsoleto. Vea el archivo de código fuente del núcleo de Linux Documentation/admin-guide/initrd.rst (o Documentation/initrd.txt antes de Linux 4.10) así como pivot_root(2) y pivot_root(8) para información sobre el método

moderno de cambiar el s
istema de archivos raíz.

Us

o

La principal motivación para implementar initrdb> era permitir una configuración modular del kernel en la instalación del

sistema.

Un posible escenario de instalación del sistema es el

siguiente:
(1
)
El programa cargador arranca desde disquete u otro medio con un kernel mínimo (p. ej., soporte para /dev/ram, /dev/initrd, y el sistema de archivos ext2 ) y carga /dev/initrd con una versión comprimida con gzip del sistema de archivos
inicial.
(2
)
El ejecutable /linuxrc determina qué se necesita para (1) montar el sistema de archivos raíz normal (es decir, tipo de dispositivo, controladores de dispositivo, sistema de archivos) y (2) los medios de distribución (p. ej., CD-ROM, red, cinta, ...). Esto se puede hacer preguntando al usuario, mediante auto-detección, o usando un enfoque
híbrido.
(3
)
El ejecutable /linuxrc carga los módulos necesarios desde el sistema de archivos raíz
inicial.
(4
)
El ejecutable /linuxrc crea y puebla el sistema de archivos raíz. (En esta etapa, el sistema de archivos raíz normal aún no tiene que ser un sistema completo.
)
(5
)
El ejecutable /linuxrc establece /proc/sys/kernel/real-root-dev, desmonta /proc, el sistema de archivos raíz normal y cualquier otro sistema de archivos que haya montado, y luego
termina.
(6
)
El kernel entonces monta el sistema de archivos raíz
normal.
(7
)
Ahora que el sistema de archivos es accesible e intacto, se puede instalar el cargador de
arranque.
(8
)
El cargador de arranque se configura para cargar en /dev/initrd un sistema de archivos con el conjunto de módulos que se utilizó para iniciar el sistema. (p. ej., el dispositivo /dev/ram0 se puede modificar, luego desmontar, y finalmente, la imagen se escribe desde /dev/ram0 a un archivo.
)
(9
)
El sistema ahora es arrancabl
e y se pueden realizar tarea
s de instalación adicionales.

El papel clave de /dev/initrd en lo anterior es reutilizar los datos de configuración durante la operación normal del sistema sin requerir una selección inicial del kernel, un kernel genérico grande o recompilar el

kernel.

Un segundo escenario es para instalaciones donde Linux se ejecuta en sistemas con diferentes configuraciones de hardware en una sola red administrativa. En tales casos, puede ser deseable usar solo un pequeño conjunto de kernels (idealmente solo uno) y mantener la parte específica del sistema de la información de configuración lo más pequeña posible. En este caso, cree un archivo común con todos los módulos necesarios. Luego, solo el archivo /linuxrc o un archivo ejecutado por /linuxrc sería

diferente.

Un tercer escenario son discos de recuperación más convenientes. Debido a que información como la ubicación de la partición del sistema de archivos raíz no se necesita en el momento del arranque, el sistema cargado desde /dev/initrd puede usar un diálogo y/o auto-detección seguido de una posible verificación de

integridad.

Por último, pero no menos importante, las distribuciones de Linux en CD-ROM pueden usar initrd para una fácil instalación desde el CD-ROM. La distribución puede usar LOADLIN para cargar directamente /dev/initrd desde el CD-ROM sin la necesidad de ningún disquete. La distribución también podría usar un disquete de arranque LILO y luego iniciar un disco RAM más grande a través de /dev/initrd d

NOTA

S
•
Con el kernel actual, cualquier sistema de archivos que permanezca montado cuando /dev/ram0 se mueva de / a /initrd continúa siendo accesible. Sin embargo, las entradas de /proc/mounts no se
actualizan.
•
Con el kernel actual, si el directorio /initrd no existe, entonces /dev/ram0 no se desmontará completamente si /dev/ram0 es utilizado por algún proceso o tiene algún sistema de archivos montado en él. Si /dev/ram0 no se desmonta completamente, entonces /dev/ram0 permanecerá en
memoria.
•
Los usuarios de /dev/initrd no deben depender del comportamiento dado en las
notas anteriores. El comport
amiento puede cambiar en versio
nes futuras del kernel de Linux.
