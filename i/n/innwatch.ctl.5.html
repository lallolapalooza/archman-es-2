innwatch.ctl - Lista de

acciones de supervisión
realizadas por innwatch

DESCRIPCIÓ

N

El archivo pathetc/innwatch.ctl se utiliza para determinar qué acciones se llevan a cabo durante las supervisiones periódicas por innwatch

.

El archivo consta de una serie de líneas; las líneas en blanco y las líneas que comienzan con un signo de número ("#") se ignoran. Todas las demás líneas constan de siete campos, cada uno precedido por un carácter delimitador, por

ejemplo: 
!estado!cuándo!condición!prueba!límite!comando!
razón

o

: 
@estado@cuándo@condición@prueba@límite@comando@razó
n

El delimitador puede ser cualquiera de varios caracteres no alfanuméricos que no aparezcan en ningún otro lugar de la línea; no hay forma de escaparlo para incluirlo en cualquiera de los campos. Cualquiera de "!", ",", ":", "@", ";", o "?" es una buena elección. Cada línea puede tener un delimitador diferente; el primer carácter de cada línea es el delimitador para esa línea. El espacio en blanco que rodea a los delimitadores, excepto antes del primero, se ignora y no forma parte de los campos; se permite el espacio en blanco dentro de los campos. Todos los delimitadores deben estar

presentes.

El primer campo es el estado al que se entra si la condición para esta línea de control es verdadera. Se utiliza como un indicador de estado interno y en mensajes de ctlinnd para controlar el servidor. Si este campo está vacío, se utiliza el número de

línea.

El segundo campo especifica cuándo debe usarse esta línea de control. Consiste en una lista de estados e indicadores especiales, separados por espacios en blanco. Si el estado actual coincide con alguno de los estados en este campo, esta línea se usará como se describe a continuación. Los valores que pueden usarse

son:
"-
"
Esta línea coincide si el estado actual es el mismo que la etiqueta en esta línea, o si el estado actual es "run", el estado inicial. Este es también el estado predeterminado si este campo está
vacío.
"+
"
Esta línea coincide si el estado actual es "run
".
"*
"
Esta línea siempre
coincide.
"etique
ta"
Esta línea coincide si el estado actual es la etiqueta "etiqueta" espec
ificada.
"-etique
ta"
Esta línea coincide si el estado actual no es la etiqueta "etiqueta" e
specif
icada.

El tercer campo especifica un comando de shell que se invoca si esta línea coincide. No use caracteres de expansión de nombres de archivo del shell como "*", "?" o "[" (incluso entre comillas, es poco probable que funcionen como se pretende). El comando se ejecuta con su directorio actual establecido en el directorio de artículos del spool de noticias (pathartic

les).

Si el comando tiene éxito, como lo indica su estado de salida, se espera que haya impreso un único entero en la salida estándar. Esto proporciona el valor de esta línea de control, que se usará a continuación. Si el comando falla, la línea se

ignora.

El cuarto campo especifica el operador a usar para probar el valor devuelto anteriormente. Debe ser uno de los operadores de prueba numérica de dos letras definidos en test(1) como "eq", "lt" y similares. El guion inicial ("-") no debe

incluirse.

El quinto campo especifica una constante con la que comparar el valor usando el operador recién definido. Esto se hace invocando el

comando: 
test valor -operador
constante

Se dice que la línea tiene éxito si devuelve

verdadero.

El sexto campo especifica qué debe hacerse si la línea tiene éxito, y en algunos casos si falla. Se puede usar cualquiera de las siguientes

palabras:
"throttl
e"
Hace que innwatch limite (throttle) el servidor si esta línea tiene éxito. También establece el estado al valor de la etiqueta de la línea. Si la línea falla, y el estado era previamente igual a la etiqueta de esta línea (es decir, esta línea había tenido éxito previamente), entonces se enviará un comando "ctlinnd go" al servidor, y innwatch volverá al estado "run". El comando "ctlinnd throttle" solo se realiza si el estado actual es "run" o un estado diferente a la etiqueta de esta línea, independientemente de si el comando tiene
éxito.
"paus
e"
Es idéntico a "throttle" excepto que el servidor se pausa mediante el comando "ctlinnd
pause".
"shutdow
n"
Envía un comando "ctlinnd shutdown" al servidor. Es solo para uso de
emergencia.
"flus
h"
Envía un comando "ctlinnd flush" al
servidor.
"g
o"
Hace que innwatch envíe un comando "ctlinnd go" al servidor y establezca el estado en "run
".
"exi
t"
Hace que innwatch s
alga.
"ski
p"
El resto del archivo
de control se omite
para el pase actual.

El último campo especifica la razón que se usa en aquellos comandos "ctlinnd" que la requieren. Más estrictamente, es parte de la razón, ya que innwatch le añade alguna

información.

Para permitir que otros sitios reconozcan el estado del servidor innd local, este campo generalmente debe establecerse en uno de varios valores estándares. Use por ejemplo "No space" si el servidor está rechazando artículos por falta de recursos del sistema de archivos, o "loadav" si el servidor está rechazando artículos por falta de recursos de

CPU.

Una vez que innwatch ha tomado alguna acción como consecuencia de su línea de control, omite el resto del archivo de control para este pase. Si la acción fue reiniciar el servidor (es decir, emitir un comando "ctlinnd go"), entonces el siguiente pase comenzará casi inmediatamente, de modo que innwatch pueda descubrir cualquier otra condición que

pueda significar que el servid
or deba suspenderse de nuevo.

EJEMPLO

S 
!!! inndf . ! lt ! 10000 ! throttle ! No space (spool)
!!! inndf -i . ! lt ! 1000 ! throttle ! No space
(inodes)

La primera línea hace que el servidor se limite (throttle) si el espacio libre cae por debajo de 10000 unidades (usando las unidades que inndf use), y se reinicia de nuevo cuando el espacio libre aumenta por encima del

umbral.

La segunda línea hace lo mismo para los

inodos.

Las tres líneas siguientes actúan como un grupo y deben aparecer en el siguiente orden. Sin embargo, es más fácil explicarlas si se describen de abajo hacia

arriba. 
! load ! load hiload ! loadavg ! lt ! 5 ! go ! loadav
: hiload : + load : loadavg : gt : 8 : throttle : loadav
/ load / + / loadavg / gt / 6 / pause /
loadav

La última línea hace que el servidor se pause si innwatch está en el estado "run" y la carga media sube a seis o más. El estado se establece en "load" cuando esto sucede. La línea anterior hace que el servidor se limite (throttle) cuando innwatch está en el estado "run" o "load", y la carga media sube por encima de ocho. El estado se establece en "hiload" cuando esto sucede. Tenga en cuenta que innwatch puede cambiar el servidor de "pause" a "throttle" si la carga media sube de por debajo de seis a entre seis y siete, y luego a por encima de ocho. La primera línea hace que se envíe al servidor un comando "ctlinnd go" si innwatch está en el estado "load" o "hiload", y la carga media baja por debajo de

cinco.

Tenga en cuenta que las tres líneas asumen un comando ficticio "loadavg" que se supone que imprime la carga media actual como un entero. En circunstancias más prácticas, una tubería de uptime a AWK probabl

emente sea
más útil.

ERRORE

S

El "run" state is not actually identified by the label with that three letter name, and using it will not work as expected ("go" is the wanted state in that case)

.

Using an unusual character for the delimiter such as "(", "*", "&", "`", "'", and the like, is likely to lead t

o obscure and h
ard to locate bugs.
