DESCRIPCIÓ

N

inxi es una herramienta de información del sistema por línea de comandos creada para consola y IRC. También se utiliza como herramienta de depuración para soporte técnico en foros para determinar rápidamente las configuraciones del sistema y el hardware de los usuarios. inxi muestra el hardware del sistema, CPU, controladores, Xorg, Escritorio, Kernel, versión(es) del compilador, Procesos, uso de RAM, y una amplia variedad de otra información

útil.

La salida de inxi varía dependiendo de si se está utilizando en CLI o IRC, con algunos filtros predeterminados y opciones de color aplicados solo para uso en IRC. Los colores se pueden desactivar si se desea con -c 0, o cambiar usando las -c opciones de color listadas en la s

ección OPCIONES EST
ÁNDAR más abajo.

PRIVACIDAD Y

SEGURIDAD

Para mantener la privacidad y seguridad básicas, inxi utilizado en IRC filtra automáticamente la dirección MAC de tu dispositivo de red, la IP WAN y LAN, tu directorio de usuario /home en las particiones, y algunos otros

elementos.

Debido a que inxi se usa a menudo en foros para soporte, también puedes activar este filtro con la -z opción (-ez, por ejemplo). Para anular el filtro de IRC, puedes usar la -z opción. Esto puede ser útil al depurar problemas de conexión de red en línea en un chat privado, por

ejemplo.

-C , --cpu
Muestra el informe completo de la CPU (si cada elemento está disponible): topología básica de la CPU, modelo, tipo, caché L2, velocidad promedio de todos los núcleos (si hay más de 1 núcleo, de lo contrario, velocidad del núcleo), velocidades mínimas/máximas para la CPU y velocidad de reloj por CPU. Más datos disponibles con las opciones -x, -xxx y -a.

Explicación de las abreviaturas del tipo de CPU (tipo: MT MCP):

* AMCP - Procesador Multi-Núcleo Asimétrico. Más de 1 núcleo por CPU, y más de un tipo de núcleo (núcleos individuales y multihilo en la misma CPU).

* AMP - Procesamiento Multi-Asimétrico (más de 1 CPU física, pero no idénticas en términos de recuento de núcleos o velocidades min/max).

* MT - CPU Multi/Hiper Hilo (más de 1 hilo por núcleo, anteriormente HT).

* MST - CPU Multi y de un solo hilo (una CPU con núcleos tanto de un solo hilo como multihilo).

* MCM - Modelo Multi-Chip (más de 1 die por CPU).

* MCP - Procesador Multi-Núcleo (más de 1 núcleo por CPU).

* SMP - Procesamiento Multi-Simétrico (más de 1 CPU física).

* UP - Procesador Uni (un solo núcleo).

Tenga en cuenta que las velocidades min/max: no son necesariamente ciertas en casos de CPUs con overclock o CPUs en modo turbo/boost. Ver -Ca para datos alternativos de velocidad base/boost:, datos de caché más granulares y más.

Muestra datos de unidades ópticas además de los datos de unidades HDD/SSD de -D. Con -x, añade una línea de características al informe. También muestra disquetes si están presentes. -D , --disk
Muestra información de unidades HDD/SSD. Muestra el espacio total de la unidad y el porcentaje utilizado. El porcentaje de uso de la unidad incluye el espacio utilizado por las particiones de intercambio (swap), ya que estas no son utilizables para el almacenamiento de datos. Además, las particiones no montadas no se cuentan en los porcentajes de uso de la unidad, ya que inxi no tiene acceso a la cantidad utilizada.

Si el sistema tiene RAID u otro almacenamiento lógico, y si inxi puede determinar el tamaño de estos frente a sus componentes, verá los tamaños totales brutos y utilizables del almacenamiento, más el porcentaje utilizado del tamaño utilizable. La forma corta de inxi sin argumentos solo mostrará el tamaño utilizable (o total si no hay utilizable) y el porcentaje utilizado. Si no se detecta almacenamiento lógico, solo se mostrarán total: y usado:. Ejemplo (con tamaño lógico RAID calculado):

Almacenamiento Local: total: 5.49 TiB usable: 2.80 TiB usado: 1.35 TiB (48.3%)

Sin almacenamiento lógico detectado:

Almacenamiento Local: total: 2.89 TiB usado: 1.51 TiB (52.3%)

También muestra información por unidad: ID del disco, tipo (FireWire, Removible, USB si está presente), proveedor (si se detecta), modelo y tamaño. Consulte Opciones de Datos Adicionales (opciones -x) y Opciones de Datos Adicionales del Administrador (opciones --admin) para ver muchas más características.

-e , --expanded
Muestra el informe expandido de -b. Incluye todas las opciones en mayúsculas (excepto -J), más --swap, -s y -n. No muestra opciones extra verbosas como -d -f -i -J -l -m -o -p -r -t -u -x a menos que use esos argumentos en el comando, por ejemplo: inxi -ermxx

La línea básica de la CPU se expande a datos completos de la CPU (-C); la línea básica de información del disco se expande a información completa de la unidad (-D) más datos de la partición principal del sistema (-P), además de añadir, si se encuentran, elementos RAID (-R) y Lógicos (-L); la línea de Red (-N) se expande a red avanzada (-n).

Tenga en cuenta que con -e, para evitar desorden, -B, -E, -L y -R solo se muestran si se encuentran resultados, ya que a menudo no son relevantes.

Para un informe básico, vea -b/--basic.

Los anteriores -F/--full están obsoletos porque el informe expandido no ha sido completo durante mucho tiempo.

Datos de memoria (RAM). No se muestra con -b o -e a menos que uses -m explícitamente. Ordenado por los arreglos físicos de memoria del sistema en la placa base (Array-[número]), y los dispositivos de memoria individuales (Device-[número]). Los datos del arreglo de memoria física muestran la capacidad del arreglo, el número de dispositivos soportados y la información de Corrección de Errores. Los dispositivos muestran los datos del localizador (altamente variable en sintaxis), el tipo (ej: type: DDR3)tamaño, velocidad.

Nota: inxi -m usa dboot (BSDs), dmidecode, o udevadm (Linux) para recopilar los datos de la RAM. No todas las placas tienen datos de RAM DMI

disponibles.

dmidecode debe ejecutarse como root (o inicia inxi con doas/sudo), a menos que descubras cómo configurar doas/sudo para permitir que dmidecode lea /dev/mem como

usuario.

udevadm puede ejecutarse por un no superusuario, o si dmidecode no está instalado (solo Linux). Tiene un informe de la tabla dmi ligeramente menos fiable, y no parece soportar más de un arreglo de memoria de la placa, pero es bastante bueno. Sin embargo, los voltajes pueden ser

incorrectos.

Tanto dmidecode como udevadm necesitan una tabla DMI con datos de RAM para crear el informe. La mayoría de las placas SBC/SOC no tienen datos de RAM basados en dmi. Pero la mayoría de las otras máquinas

sí.

total.

ARCHIVO DE CONFIGURACIÓN

inxi leerá sus archivos de configuración/inicialización en el siguiente orden:

/etc/inxi.conf contiene las configuraciones por defecto. Estas pueden ser anuladas creando un archivo /etc/inxi.conf.d/inxi.conf (anulación global), lo que evitará que los paquetes de la distribución cambien o sobrescriban tus ediciones. Este método se recomienda si estás usando un inxi empaquetado por la distribución y quieres anular algunos elementos de configuración globales del archivo de configuración por defecto /etc/inxi.conf del paquete, pero no quieres perder tus cambios al actualizar el paquete.

En caso de que la distribución utilice /usr/etc o /usr/local/etc como ubicación predeterminada para herramientas no centrales, inxi utilizará esas rutas en su lugar, con la opción de anulación de inxi.conf.d/inxi.conf.

También puedes anular, por usuario, con un archivo de configuración de usuario que se encuentra en una de las siguientes ubicaciones (inxi almacenará su archivo de configuración utilizando la siguiente precedencia):

si $XDG_CONFIG_HOME no está vacío, irá allí, si no, si $HOME/.config/inxi.conf existe, irá allí, y como última opción predeterminada, se utiliza la ubicación heredada, es decir:

$XDG_CONFIG_HOME/inxi.conf > $HOME/.config/inxi.conf > $HOME/.inxi/inxi.conf > /usr/etc/inxi.conf > /usr/etc/inxi.conf.d/inxi.conf > /usr/local/etc/inxi.conf > /usr/local/etc/inxi.conf.d/inxi.conf > /etc/inxi.conf.d/inxi.conf > /etc/inxi.conf

Opciones Básicas
Aquí tienes una breve descripción general de las opciones básicas que probablemente querrás usar:

COLS_MAX_CONSOLE El ancho máximo de columna de pantalla en la terminal. Si el ancho de la terminal/consola o --width es menor que el ancho de envoltura, se produce el envolvimiento del iniciador de línea.

COLS_MAX_IRC El ancho máximo de columna de pantalla en clientes IRC.

COLS_MAX_NO_DISPLAY El ancho máximo de columna de pantalla fuera de X/Wayland/escritorio/gestor de ventanas.

CPU_SLEEP Valor decimal 0 o superior. El valor predeterminado suele ser alrededor de 0.35 segundos. Tiempo que inxi "dormirá" antes de obtener datos de velocidad de CPU, para que refleje el estado real del sistema.

DOWNLOADER Establece el descargador predeterminado de inxi: curl, fetch, ftp, perl, wget. Consulta la salida de --recommends para obtener más información sobre descargadores y descargadores de Perl.

FILTER_STRING Predeterminado <filtro>. Cualquier cadena que prefieras ver en lugar de los valores filtrados.

INDENT Cambia el ancho de indentación principal de la salida en modo amplio. Consulta --indent.

INDENTS Cambia las indentaciones principales de la salida en modo estrecho y las indentaciones de segundo nivel. Consulta --indents.

LIMIT Anula el valor predeterminado de 10 direcciones IP por IF. Esto solo interesa a los administradores de sistemas que ejecutan servidores con muchas direcciones IP.

LINES_MAX Valores: [-2-xxx]. Consulta -Y para la explicación y los valores. Usa -Y -3 para restaurar las líneas de salida ilimitadas por defecto. Evita usar esto en general a menos que la máquina sea un sistema "headless" y desees que la salida se controle siempre.

MAX_WRAP (o WRAP_MAX) El ancho máximo donde el iniciador de línea se envuelve en su propia línea. Si el ancho de la terminal/consola o --width es menor que el ancho de envoltura, se produce el envolvimiento del iniciador de línea. Anula el valor predeterminado. Consulta --max-wrap. Si es 80 o menos, la envoltura nunca ocurrirá.

NO_DIG Se establece en 1 o true para deshabilitar el uso de dig para la IP WAN y forzar el uso de descargadores alternativos.

NO_DOAS Se establece en 1 o true para deshabilitar el uso interno de doas.

NO_HTML_WAN Se establece en 1 o true para deshabilitar el uso de Descargadores HTML para la IP WAN y forzar el uso exclusivo de dig, o nada si dig también está deshabilitado. Lo mismo que --no-html-wan. Úsalo solo si dig falla y los descargadores HTML se quedan colgados.

NO_SUDO Se establece en 1 o true para deshabilitar el uso interno de sudo.

PARTITION_SORT Anula el orden de informe de particiones predeterminado. Consulta --partition-sort para ver las opciones.

PS_COUNT El número predeterminado de elementos que se muestran por tipo -t, m o c. El valor predeterminado es 5.

SENSORS_CPU_NO En casos de ambigüedad temp1/temp2 (inxi no puede determinar cuál es la CPU), fuerza a los sensores a usar el valor 1 o 2 como temperatura de CPU. Consulta la página de configuración anterior en smxi.org para obtener información completa.

SENSORS_EXCLUDE Excluye los arrays de sensores suministrados del informe de sensores. Anula con --sensors-default. Consulta --sensors-exclude.

SENSORS_USE Utiliza solo los arrays de sensores suministrados. Anula con --sensors-default. Consulta --sensors-use.

SEP2_CONSOLE Reemplaza el separador clave/valor predeterminado de ':'. Prueba con --separator.

USB_SYS Fuerza todos los datos USB a usar /sys en lugar de lsusb.

WAN_IP_URL Fuerza que -i utilice la URL suministrada y no utilice dig (dig es generalmente mucho más rápido). La URL debe comenzar con http o ftp. Ten en cuenta que si usas esto, las pruebas del descargador configurado se ejecutarán cada vez que inicies inxi, independientemente de si se va a utilizar alguna función de descargador o no.

La dirección IP de la URL debe ser el último elemento en la última línea (no vacía) del código fuente de la página de la URL.

Lo mismo que --wan-ip-url [URL]

WEATHER_SOURCE Valores: [0-9]. Lo mismo que --weather-source. Los valores 4-9 no están actualmente soportados, pero esto puede cambiar en cualquier momento.

WEATHER_UNIT Valores: [m|i|mi|im]. Lo mismo que --weather-unit.
