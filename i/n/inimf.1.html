MF(1) Manual de Comandos Generales MF(1)

NOMBRE

mf, inimf, mf-nowin - Metafont, un lenguaje para el diseño de fuentes y logotipos

SINOPSIS

mf [opciones] [comandos]

DESCRIPCIÓN

Metafont lee el programa en los archivos especificados y genera mapas de bits de fuentes (en formato gf) y métricas de fuentes (en formato tfm). El lenguaje Metafont se describe en The Metafontbook.

Al igual que TeX, Metafont se utiliza normalmente con un gran conjunto de macros precompiladas, y la generación de fuentes en particular requiere el soporte de varios archivos de macros. Esta versión de Metafont examina la línea de comandos para ver bajo qué nombre se llamó. Tanto inimf como virmf son enlaces simbólicos al ejecutable mf. Cuando se llama como inimf (o cuando se proporciona la opción -ini), se puede utilizar para precompilar macros en un archivo .base. Cuando se llama como virmf, utilizará la base plain. Cuando se llama con cualquier otro nombre, Metafont utilizará ese nombre como el nombre de la base a utilizar. Por ejemplo, cuando se llama como mf, se utiliza la base mf, que es idéntica a la base plain. Otras bases que no sean plain rara vez se utilizan.

Los comandos dados en la línea de comandos al programa Metafont se le pasan como la primera línea de entrada. (Pero a menudo es más fácil escribir argumentos extendidos como la primera línea de entrada, ya que los shells de UNIX tienden a comerse o malinterpretar los símbolos favoritos de Metafont, como los puntos y coma, a menos que los cites.) Como se describe en The Metafontbook, esa primera línea debe comenzar con un nombre de archivo, una secuencia de control \secuencia de control o un &nombre_base.

El uso normal es decir

mf  '\mode=<motor_impresión>; [mag=magstep(n);]' fuente de entrada

para comenzar a procesar fuente.mf. Las comillas simples son la mejor manera de evitar que el shell de Unix malinterprete los puntos y comas y elimine el carácter \, que es necesario aquí para evitar que Metafont piense que quieres producir una fuente llamada mode. (O simplemente puedes decir mf y dar el resto en la siguiente línea, sin comillas.) Otras secuencias de control, como batchmode (para funcionamiento silencioso), también pueden aparecer. El nombre fuente será el "nombre_trabajo", y se utiliza para formar los nombres de los archivos de salida. Si Metafont no recibe un nombre de archivo en la primera línea, el nombre_trabajo es mfput. La extensión predeterminada, .mf, se puede anular especificando explícitamente una extensión.

Un registro de mensajes de error va al archivo nombre_trabajo.log. Los archivos de salida son nombre_trabajo.tfm y nombre_trabajo.<número>gf, donde el <número> depende de la resolución y magnificación de la fuente. El modo en este ejemplo se muestra genéricamente como <motor_impresión>, un término simbólico para el cual se debe sustituir el nombre de un dispositivo real o, lo más comúnmente, el nombre localfont (ver más abajo). Si el modo no se especifica o no es válido para su sitio, Metafont utilizará el modo proof por defecto, que genera imágenes de caracteres grandes para su uso en el diseño y refinamiento de fuentes. El modo de prueba se puede reconocer por el sufijo .2602gf después del nombre_trabajo. Ejemplos de salida del modo de prueba se encuentran en Computer Modern Typefaces (Volumen E de Computers and Typesetting). El sistema de magsteps es idéntico al sistema utilizado por TeX, con valores generalmente en el rango de 0.5, 1.0, 2.0, 3.0, 4.0 y 5.0. A continuación se muestra una lista de números gf para fuentes de 118 ppp, 240 ppp y 300 ppp.

MAGSTEP 118 ppp 240 ppp 300 ppp
mag=magstep(0) 118 240 300
mag=magstep(0.5) 129 263 329
mag=magstep(1) 142 288 360
mag=magstep(2) 170 346 432
mag=magstep(3) 204 415 518
mag=magstep(4) 245 498 622
mag=magstep(5) 294 597 746

La magnificación también se puede especificar no como un magstep sino como un valor arbitrario, como 1.315, para crear tamaños de caracteres especiales.

Antes de que pueda comenzar la producción de fuentes, es necesario configurar los archivos base apropiados. El conjunto mínimo de componentes para la producción de fuentes para un motor de impresión dado es el archivo macro plain.mf y el archivo local mode_def. Las macros en plain.mf se pueden estudiar en un apéndice de The Metafontbook; fueron desarrolladas por Donald E. Knuth, y este archivo nunca debe alterarse, excepto cuando se actualiza oficialmente. Cada especificación de mode_def ayuda a adaptar las fuentes a un motor de impresión particular. Hay una discusión regular sobre mode_defs en TUGboat, la revista del TeX Users Group. Los locales en uso en esta computadora deben estar en modes.mf.

La respuesta e al modo de recuperación de errores de Metafont invoca el editor predeterminado del sistema en la línea errónea del archivo fuente. Hay una variable de entorno, MFEDIT, que anula el editor predeterminado. Debe contener una cadena con "%s" indicando dónde va el nombre del archivo y "%d" indicando dónde va el número de línea decimal (si lo hay). Por ejemplo, una cadena MFEDIT para el editor vi se puede configurar con el comando csh

setenv MFEDIT "vi +%d %s"

Un archivo conveniente en la biblioteca es null.mf, que no contiene nada. Cuando mf no encuentra el archivo que cree que quieres introducir, sigue pidiéndote otro nombre de archivo; responder `null' te saca del bucle si no quieres introducir nada.

SALIDA GRÁFICA EN LÍNEA

Metafont puede usar la mayoría de las pantallas modernas, por lo que puedes ver su salida sin imprimir. El capítulo 23 de The Metafontbook describe lo que puedes hacer. Esta implementación de Metafont utiliza variables de entorno para determinar qué dispositivo de visualización quieres usar. Primero busca una variable MFTERM, y luego TERM. Si no encuentra ninguna, no obtendrás salida en línea. De lo contrario, el valor de la variable determinará el dispositivo a usar: hp2627, sun (para el antiguo SunView), tek, uniterm (para un emulador de Tek 4014 para Atari ST), xterm (para X10 o X11). Es posible que algunos de estos dispositivos no sean compatibles con todos los ejecutables de Metafont; la elección se realiza en el momento de la compilación.

En algunos sistemas, hay dos binarios de Metafont, mf y mf-nowin. En esos sistemas, el binario mf soporta gráficos, mientras que el binario mf-nowin no lo hace. El binario mf-nowin es utilizado por scripts como mktexpk donde el soporte gráfico es un inconveniente en lugar de algo útil.
