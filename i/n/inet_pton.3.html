DESCRIPCIÓ

N

Esta función convierte la cadena de caracteres src en una estructura de dirección de red en la familia de direcciones af, y luego copia la estructura de dirección de red a dst. El argumento af debe ser o bien AF_INET o AF_INET6. dst se escribe en orden de bytes de

red.

Actualmente se admiten las siguientes familias de

direcciones:
AF_IN
ET
src apunta a una cadena de caracteres que contiene una dirección de red IPv4 en formato decimal con puntos, "ddd.ddd.ddd.ddd", donde ddd es un número decimal de hasta tres dígitos en el rango de 0 a 255. La dirección se convierte en una struct in_addr y se copia en dst, que debe tener sizeof(struct in_addr) (4) bytes (32 bits) de
longitud.
AF_INE
T6
src apunta a una cadena de caracteres que contiene una dirección de red IPv6. La dirección se convierte en una struct in6_addr y se copia en dst, que debe tener sizeof(struct in6_addr) (16) bytes (128 bits) de longitud. Los f
ormatos permitidos para las direccio
nes IPv6 siguen estas reglas:
•
El formato preferido es x:x:x:x:x:x:x:x. Esta forma consta de ocho números hexadecimales, cada uno de los cuales expresa un valor de 16 bits (es decir, cada x puede tener hasta 4 dígitos hexadecimales)
.
•
Una serie de valores cero contiguos en el formato preferido puede abreviarse como ::. Solo puede ocurrir una instancia de :: en una dirección. Por ejemplo, la dirección de bucle de retorno 0:0:0:0:0:0:0:1 puede abreviarse como ::1. La dirección comodín, que consta de todos ceros, puede escribirse como ::
.
•
Un formato alternativo es útil para expresar direcciones IPv6 mapeadas desde IPv4. Esta forma se escribe como x:x:x:x:x:x:d.d.d.d, donde los seis x iniciales son valores hexadecimales que definen las seis piezas de 16 bits más significativas de la dirección (es decir, 96 bits), y los d expresan un valor en notación decimal con puntos que define los 32 bits menos significativos de la dirección. Se devuelve 0 si src no contiene una cadena de caracteres que represente una dirección de red válida en la familia de direcciones especificada. VERSIONE

S

A diferencia de inet_aton(3) y inet_addr(3), inet_pton() admite direcciones IPv6. Por otro lado, inet_pton() acepta solo direcciones IPv4 en notación decimal con puntos, mientras que inet_aton(3) y inet_addr(3) permiten la notación más general de números y puntos (formatos de números hexadecimales y octales, y formatos que no requieren que se escriban explícitamente los cuatro bytes). Para una interfaz que maneje tanto direcciones IPv6 como direcciones IPv4 en notación de números y puntos, consulte getaddri

Código fuente del

programa 
#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
int
main(int argc, char *argv[])
{
    unsigned char buf[sizeof(struct in6_addr)];
    int domain, s;
    char str[INET6_ADDRSTRLEN];
    if (argc != 3) {
        fprintf(stderr, "Usage: %s {i4|i6|<num>} string\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    domain = (strcmp(argv[1], "i4") == 0) ? AF_INET :
             (strcmp(argv[1], "i6") == 0) ? AF_INET6 : atoi(argv[1]);
    s = inet_pton(domain, argv[2], buf);
    if (s <= 0) {
        if (s == 0)
            fprintf(stderr, "Not in presentation format");
        else
            perror("inet_pton");
        exit(EXIT_FAILURE);
    }
    if (inet_ntop(domain, buf, str, INET6_ADDRSTRLEN) == NULL) {
        perror("inet_ntop");
        exit(EXIT_FAILURE);
    }
    printf("%s\n", str);
    exit(EXIT_SUCCESS)
;
}
