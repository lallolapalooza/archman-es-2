NOMBRE

innxmit - Envía artículos de Usenet a un servidor NNTP remoto

SINOPSIS

innxmit [-acdHlprsv] [-P puerto] [-T segundos] [-t segundos] host archivo

DESCRIPCIÓN

innxmit se conecta al servidor NNTP en el host especificado (validándose a través de passwd.nntp si existen credenciales de autenticación para el servidor remoto en ese archivo) y le envía los artículos especificados en el archivo por lotes llamado archivo. Normalmente es invocado por un script ejecutado desde cron(8) que usa shlock para bloquear el nombre del host, seguido de un comando ctlinnd para vaciar el archivo por lotes. Si archivo no es una ruta absoluta, se toma en relación con el directorio especificado por el parámetro pathoutgoing en inn.conf. Normalmente es escrito especificando las banderas "Wnm" en el archivo newsfeeds. Cada línea en el archivo por lotes debe tener uno de los siguientes formatos:

article Mensaje-ID
article

El primer campo es el token de la API de almacenamiento de un artículo o el nombre de un archivo que contiene un artículo. Si no es una ruta absoluta o un token de la API de almacenamiento, se toma como un nombre de archivo relativo a patharticles en inn.conf. Si el segundo campo no está especificado, el Message-ID se obtendrá escaneando el artículo. Los dos campos, si están presentes, están separados por un espacio. Si ocurre un error de comunicación como un fallo de write(2), innxmit dejará de enviar y reescribirá el archivo por lotes para contener el artículo actual y cualquier otro artículo no enviado.

Una alternativa a innxmit puede ser innduct, mencionada en la página del manual de innfeed(8).

OPCIONES

-a
Si todos los artículos se enviaron con éxito, innxmit eliminará el archivo por lotes; de lo contrario, lo reescribirá para contener la lista de artículos no enviados. Si no se enviaron ni se rechazaron artículos, el archivo se deja intacto. Esto puede hacer que el archivo por lotes crezca excesivamente si muchos artículos han expirado y hay problemas de comunicación. Para reescribir siempre el archivo por lotes, use la bandera -a.
-c
En modo de transmisión, se realiza una verificación de cada Message-ID para evitar enviar artículos que ya están en el servidor remoto. Después de que un cierto número de artículos se acepten seguidos, innxmit ya no enviará estas consultas, sino que volverá a enviarlas al recibir un rechazo (que puede ser por otra razón que una duplicación, como por ejemplo un newsgroup no deseado).

La bandera -c, si el modo de transmisión es compatible, resultará en el envío constante de artículos sin verificación. Esto resulta en un rendimiento ligeramente mayor y puede ser apropiado cuando se sabe que el sitio aún no podría tener los artículos, como en el caso de un sitio "hoja".

-d
Use la bandera -d para imprimir información de depuración en el error estándar. Esto mostrará las transacciones del protocolo entre innxmit y el servidor NNTP en el host remoto.
-H
Si se proporciona la bandera -H, entonces solo se enviarán las cabeceras a host para todos los artículos excepto los mensajes de control. Y el campo de cabecera Bytes también se incluye aunque no exista en el artículo original. La bandera -H es útil para el lector Diablo.
-l
La bandera -l se utiliza para activar el registro de las razones que el remoto da para rechazar un artículo.
-P puerto
Para especificar un número de puerto distinto del predeterminado, use la bandera -P.
-p
Si se proporciona la bandera -p, no se realiza ninguna conexión y el archivo por lotes se purga de entradas que se refieren a archivos que ya no existen. Esto implica la bandera -a.
-r
Si el servidor remoto envía un código de respuesta inesperado, innxmit volverá a encolar el artículo y continuará. Use la bandera -r si el artículo no debe volver a encolarse.
-s
innxmit intentará negociar una extensión del modo de transmisión del protocolo NNTP con el servidor en el momento de la conexión. Si tiene éxito, utilizará un protocolo ligeramente diferente que mejora el rendimiento. Si el servidor no reconoce la negociación del modo de transmisión, innxmit volverá al modo de transferencia NNTP normal. Use la bandera -s para deshabilitar el intento de negociar la extensión del modo de transmisión.
-T segundos
Para especificar la cantidad total de tiempo que se debe permitir para las transferencias de artículos, use la bandera -T. El valor predeterminado es esperar hasta que ocurra un error de E/S, o hasta que se hayan transferido todos los artículos. Si se usa la bandera -T, el tiempo se verifica justo antes de que comience cada artículo; no abortará una transferencia que esté en progreso.
-t segundos
innxmit normalmente se bloquea hasta que se establece la conexión. Para especificar un tiempo de espera sobre cuánto tiempo intentar establecer la conexión, use la bandera -t.
-v
Al salir, innxmit informa las estadísticas de uso de CPU y transferencia a través de syslog. Si se usa la bandera -v, también se imprimirán en la salida estándar.
