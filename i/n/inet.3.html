NOMBRE

inet_aton, inet_addr, inet_network, inet_ntoa, inet_makeaddr, inet_lnaof, inet_netof - Rutinas de manipulación de direcciones de Internet

DESCRIPCIÓN

inet_aton() convierte la dirección de host de Internet cp de la notación de números y puntos IPv4 a forma binaria (en orden de bytes de red) y la almacena en la estructura a la que apunta inp. inet_aton() devuelve un valor distinto de cero si la dirección es válida, y cero si no lo es. La dirección proporcionada en cp puede tener una de las siguientes formas:

a.b.c.d
Cada una de las cuatro partes numéricas especifica un byte de la dirección; los bytes se asignan en orden de izquierda a derecha para producir la dirección binaria.
a.b.c
Las partes a y b especifican los dos primeros bytes de la dirección binaria. La parte c se interpreta como un valor de 16 bits que define los dos bytes más a la derecha de la dirección binaria. Esta notación es adecuada para especificar direcciones de red (obsoletas) de Clase B.
a.b
La parte a especifica el primer byte de la dirección binaria. La parte b se interpreta como un valor de 24 bits que define los tres bytes más a la derecha de la dirección binaria. Esta notación es adecuada para especificar direcciones de red (obsoletas) de Clase A.
a
El valor a se interpreta como un valor de 32 bits que se almacena directamente en la dirección binaria sin ninguna reorganización de bytes.

En todas las formas anteriores, los componentes de la dirección punteada se pueden especificar en decimal, octal (con un 0 delante) o hexadecimal, con un prefijo 0X). Las direcciones en cualquiera de estas formas se denominan colectivamente notación de números y puntos IPv4. La forma que utiliza exactamente cuatro números decimales se conoce como notación decimal punteada IPv4 (o a veces: notación de cuarteto punteado IPv4).

inet_aton() devuelve 1 si la cadena proporcionada se interpretó correctamente, o 0 si la cadena no es válida (errno no se establece en caso de error).

La función inet_addr() convierte la dirección de host de Internet cp de la notación de números y puntos IPv4 a datos binarios en orden de bytes de red. Si la entrada no es válida, se devuelve INADDR_NONE (generalmente -1). El uso de esta función es problemático porque -1 es una dirección válida (255.255.255.255). Evite su uso en favor de inet_aton(), inet_pton(3), o getaddrinfo(3), que proporcionan una forma más limpia de indicar la devolución de error.

La función inet_network() convierte cp, una cadena en notación de números y puntos IPv4, en un número en orden de bytes de host adecuado para su uso como dirección de red de Internet. En caso de éxito, se devuelve la dirección convertida. Si la entrada no es válida, se devuelve -1.

La función inet_ntoa() convierte la dirección de host de Internet in, dada en orden de bytes de red, a una cadena en notación decimal punteada IPv4. La cadena se devuelve en un búfer asignado estáticamente, que las llamadas posteriores sobrescribirán.

La función inet_lnaof() devuelve la parte de la dirección de red local de la dirección de Internet in. El valor devuelto está en orden de bytes de host.

La función inet_netof() devuelve la parte del número de red de la dirección de Internet in. El valor devuelto está en orden de bytes de host.

La función inet_makeaddr() es la inversa de inet_netof() y inet_lnaof(). Devuelve una dirección de host de Internet en orden de bytes de red, creada combinando el número de red net con la dirección de host host, ambas en orden de bytes de host.

La estructura in_addr tal como se usa en inet_ntoa(), inet_makeaddr(), inet_lnaof(), y inet_netof() se define en <netinet/in.h> como:


typedef uint32_t in_addr_t;
struct in_addr {
    in_addr_t s_addr;
};

inet_lnaof(), inet_netof(), y inet_makeaddr() son funciones heredadas que asumen que están tratando con direcciones de red clasificadas. La red clasificada divide las direcciones de red IPv4 en componentes de host y red en los límites de los bytes, como sigue:

Clase A
Este tipo de dirección se indica con el valor 0 en el bit más significativo de la dirección (en orden de bytes de red). La dirección de red está contenida en el byte más significativo, y la dirección de host ocupa los tres bytes restantes.
Clase B
Este tipo de dirección se indica con el valor binario 10 en los dos bits más significativos de la dirección. La dirección de red está contenida en los dos bytes más significativos, y la dirección de host ocupa los dos bytes restantes.
Clase C
Este tipo de dirección se indica con el valor binario 110 en los tres bits más significativos de la dirección. La dirección de red está contenida en los tres bytes más significativos, y la dirección de host ocupa el byte restante.

Las direcciones de red clasificadas están ahora obsoletas, habiendo sido reemplazadas por el Enrutamiento entre Dominios sin Clases (CIDR), que divide las direcciones en componentes de red y host en límites de bits (en lugar de bytes) arbitrarios.

NOTAS

En las arquitecturas x86, el orden de bytes del host es de Byte Menos Significativo primero (little endian), mientras que el orden de bytes de red, como se usa en Internet, es de Byte Más Significativo primero (big endian).

EJEMPLOS

A continuación se muestra un ejemplo del uso de inet_aton() y inet_ntoa(). Aquí hay algunas ejecuciones de ejemplo:


$ ./a.out 226.000.000.037      # Último byte está en octal

Programa

fuente 
#define _DEFAULT_SOURCE
#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
int
main(int argc, char *argv[])
{
    struct in_addr addr;
    if (argc != 2) {
        fprintf(stderr, "%s <dotted-address>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (inet_aton(argv[1], &addr) == 0) {
        fprintf(stderr, "Invalid address\n");
        exit(EXIT_FAILURE);
    }
    printf("%s\n", inet_ntoa(addr));
    exit(EXIT_SUCCESS)
;
}
