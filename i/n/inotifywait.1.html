inotifywait(1) Manual de Comandos Generales inotifywait(1)

NOMBRE

inotifywait, fsnotifywait - esperar a que se produzcan cambios en archivos usando inotify o fanotify

SINOPSIS

inotifywait [-hcmrPqIFS] [-e <evento> ] [-t <segundos> ] [--format <fmt> ] [--timefmt <fmt> ] <archivo> [ ... ]

fsnotifywait [-hcmrPqIFS] [-e <evento> ] [-t <segundos> ] [--format <fmt> ] [--timefmt <fmt> ] <archivo> [ ... ]

DESCRIPCIÓN

inotifywait espera eficientemente a que se produzcan cambios en archivos usando la interfaz inotify(7) de Linux por defecto. Es adecuado para esperar cambios en archivos desde scripts de shell. Puede salir una vez que ocurra un evento, o continuar ejecutándose y mostrar los eventos a medida que se producen.

fsnotifywait es similar a inotifywait pero usa la interfaz fanotify(7) de Linux por defecto. Si se especifica explícitamente, usa la interfaz inotify(7) .

SALIDA

inotifywait y fsnotifywait mostrarán información de diagnóstico en la salida de error estándar e información de eventos en la salida estándar. La salida de eventos se puede configurar, pero por defecto consiste en líneas del siguiente formato:

archivo_vigilado NOMBRES_EVENTOS archivo_evento

archivo_vigilado
es el nombre del archivo en el que ocurrió el evento. Si el archivo es un directorio, se muestra una barra diagonal final.
NOMBRES_EVENTOS
son los nombres de los eventos de inotify que ocurrieron, separados por comas.
archivo_evento
se muestra solo cuando el evento ocurrió en un directorio, y en este caso se muestra el nombre del archivo dentro del directorio que causó este evento.

Por defecto, los caracteres especiales en los nombres de archivo no se escapan de ninguna manera. Esto puede hacer que la salida de inotifywait sea difícil de analizar en scripts de awk o similares. Las opciones --csv y --format serán útiles en este caso.

OPCIONES

-h, --help
Muestra información de uso útil.
@<archivo>
Al vigilar un árbol de directorios recursivamente, excluye el archivo especificado de ser vigilado. El archivo debe especificarse con una ruta relativa o absoluta según se proporcione una ruta relativa o absoluta para los directorios vigilados. Si una ruta específica se incluye y excluye explícitamente, siempre será vigilada.

Nota: Si necesita vigilar un directorio o archivo cuyo nombre comienza con @, proporcione la ruta absoluta.

--fromfile <archivo>
Lee los nombres de archivo a vigilar o excluir de un archivo, un nombre de archivo por línea. Si los nombres de archivo comienzan con @, se excluyen como se describe arriba. Si <archivo> es `-', los nombres de archivo se leen de la entrada estándar. Use esta opción si necesita vigilar demasiados archivos para pasarlos como argumentos de la línea de comandos.
-m, --monitor
En lugar de salir después de recibir un solo evento, se ejecuta indefinidamente. El comportamiento por defecto es salir después de que ocurra el primer evento.
-d, --daemon
Igual que --monitor, excepto que se ejecuta en segundo plano registrando eventos en un archivo que debe especificarse con --outfile. Implica --syslog.
-o, --outfile <archivo>
Muestra los eventos en <archivo> en lugar de en stdout.
-s, --syslog
Muestra los errores en el módulo de registro del sistema syslog(3) en lugar de en stderr.
-P, --no-dereference
No sigue los enlaces simbólicos.
-r, --recursive
Vigila todos los subdirectorios de los directorios pasados como argumentos. Las vigilancias se establecerán recursivamente hasta una profundidad ilimitada. No se recorren los enlaces simbólicos. Los subdirectorios recién creados también serán vigilados.

Advertencia: Si usa esta opción mientras vigila el directorio raíz de un árbol grande, puede tardar bastante tiempo hasta que se establezcan todas las vigilancias de inotify, y no se recibirán eventos durante este tiempo. Además, como se establecerá una vigilancia de inotify por subdirectorio, es posible que se alcance la cantidad máxima de vigilancias de inotify por usuario. El máximo por defecto es 8192; se puede aumentar escribiendo en /proc/sys/fs/inotify/max_user_watches.

-q, --quiet
Si se especifica una vez, el programa será menos detallado. Específicamente, no indicará cuándo ha completado el establecimiento de todas las vigilancias de inotify.

Si se especifica dos veces, el programa no mostrará nada en absoluto, excepto en el caso de errores fatales.

--exclude <patrón>
No procesa ningún evento para el subconjunto de archivos cuyos nombres coinciden con la expresión POSIX especificada, distinguiendo mayúsculas y minúsculas.
--excludei <patrón>
No procesa ningún evento para el subconjunto de archivos cuyos nombres coinciden con la expresión POSIX especificada, sin distinguir mayúsculas y minúsculas.
--include <patrón>
Procesa eventos solo para el subconjunto de archivos cuyos nombres coinciden con la expresión POSIX especificada, distinguiendo mayúsculas y minúsculas. Cuando se usa con --recursive, los eventos seguirán generándose para los archivos coincidentes dentro de directorios recién creados, incluso si los nombres de los directorios no coinciden con el patrón.
--includei <patrón>
Procesa eventos solo para el subconjunto de archivos cuyos nombres coinciden con la expresión POSIX especificada, sin distinguir mayúsculas y minúsculas.
-t <segundos>, --timeout <segundos>
Sale si no se ha producido un evento apropiado dentro de <segundos> segundos. Si <segundos> es cero (el valor por defecto), espera indefinidamente un evento.
-e <evento>, --event <evento>
Escucha solo eventos específicos. Los eventos que se pueden escuchar están listados en la sección EVENTOS. Esta opción se puede especificar más de una vez. Si se omite, se escuchan todos los eventos.
-c, --csv
Muestra en formato CSV (valores separados por comas). Esto es útil cuando los nombres de archivo pueden contener espacios, ya que en este caso no es seguro simplemente dividir la salida en cada carácter de espacio.
--timefmt <fmt>
Establece una cadena de formato de tiempo aceptada por strftime(3) para usar con la conversión `%T' en la opción --format.
--no-newline
No imprime el símbolo de nueva línea después del formato especificado por el usuario en la opción --format.
--format <fmt>
Muestra en un formato especificado por el usuario, usando una sintaxis similar a printf. Las cadenas de eventos mostradas están limitadas a alrededor de 4000 caracteres y se truncarán a esta longitud. Las siguientes conversiones son soportadas:
%w
Será reemplazado por el nombre del archivo vigilado en el que ocurrió un evento. Cuando un evento ocurre dentro de un directorio vigilado o al vigilar con fanotify, será reemplazado por el nombre del directorio en el que ocurrió el evento.
%f
Cuando un evento ocurre dentro de un directorio vigilado o al vigilar con fanotify, será reemplazado por el nombre del archivo que causó el evento. De lo contrario, será reemplazado por una cadena vacía.
%e
Será reemplazado por el/los evento(s) que ocurrieron, separados por comas.
%Xe
Será reemplazado por el/los evento(s) que ocurrieron, separados por el carácter que en lugar de `X'.
%T
Se sustituye por la hora actual en el formato especificado por la opción --timefmt, que debe ser una cadena de formato adecuada para pasar a strftime(3).
%0
Se sustituye por NUL.
%n
Se sustituye por Salto de Línea.
-I, --inotify
Vigilar usando inotify (predeterminado para inotifywait).
-F, --fanotify
Vigilar usando fanotify (predeterminado para fsnotifywait). El soporte de fanotify para informar de eventos con información compatible con inotify se añadió en el kernel v5.9. Con kernels más antiguos, el comando fallará. A partir del kernel v5.12, fanotify requiere privilegios de administrador.
-S, --filesystem
Vigilar el sistema de archivos completo de cualquier directorio pasado como argumento usando fanotify.

ESTADO DE SALIDA

0
El programa se ejecutó correctamente y ocurrió un evento que se estaba escuchando.
1
Ocurrió un error en la ejecución del programa, o ocurrió un evento que no se estaba escuchando. Lo último generalmente ocurre si algo sucede que elimina forzosamente la vigilancia de inotify, como la eliminación de un archivo vigilado o el desmontaje del sistema de archivos que contiene un archivo vigilado.
2
Se usó la opción -t y no ocurrió ningún evento en el intervalo de tiempo especificado.

EVENTOS

Los siguientes eventos son válidos para usar con la opción -e :

access
Se leyó de un archivo vigilado o de un archivo dentro de un directorio vigilado.
modify
Se escribió en un archivo vigilado o en un archivo dentro de un directorio vigilado.
attrib
Se modificaron los metadatos de un archivo vigilado o de un archivo dentro de un directorio vigilado. Esto incluye marcas de tiempo, permisos de archivo, atributos extendidos, etc.
close_write
Se cerró un archivo vigilado o un archivo dentro de un directorio vigilado, después de haber sido abierto en modo de escritura. Esto no implica necesariamente que se haya escrito en el archivo.
close_nowrite
Se cerró un archivo vigilado o un archivo dentro de un directorio vigilado, después de haber sido abierto en modo de solo lectura.
close
Se cerró un archivo vigilado o un archivo dentro de un directorio vigilado, independientemente de cómo se haya abierto. Tenga en cuenta que esto se implementa en realidad simplemente escuchando tanto close_write como close_nowrite, por lo que todos los eventos close recibidos se emitirán como uno de estos, no como CLOSE.
open
Se abrió un archivo vigilado o un archivo dentro de un directorio vigilado.
moved_to
Se movió un archivo o directorio a un directorio vigilado. Este evento ocurre incluso si el archivo simplemente se mueve de y al mismo directorio.
moved_from
Se movió un archivo o directorio desde un directorio vigilado. Este evento ocurre incluso si el archivo simplemente se mueve de y al mismo directorio.
move
Se movió un archivo o directorio desde o hacia un directorio vigilado. Tenga en cuenta que esto se implementa en realidad simplemente escuchando tanto moved_to como moved_from, por lo que todos los eventos move recibidos se emitirán como uno o ambos de estos, no como MOVE.
move_self
Se movió un archivo o directorio vigilado. Después de este evento, el archivo o directorio ya no está siendo vigilado.
create
Se creó un archivo o directorio dentro de un directorio vigilado.
delete
Se eliminó un archivo o directorio dentro de un directorio vigilado.
delete_self
Se eliminó un archivo o directorio vigilado. Después de este evento, el archivo o directorio ya no está siendo vigilado. Tenga en cuenta que este evento puede ocurrir incluso si no se está escuchando explícitamente.
unmount
Se desmontó el sistema de archivos en el que reside un archivo o directorio vigilado. Después de este evento, el archivo o directorio ya no está siendo vigilado. Tenga en cuenta que este evento puede ocurrir incluso si no se está escuchando explícitamente.

EJEMPLOS

Ejemplo 1

Ejecutar inotifywait en la línea de comandos para esperar a que se acceda a cualquier archivo del directorio `test'. Después de ejecutar inotifywait, se ejecuta `cat test/foo' en una consola separada.

% inotifywait test
Configurando vigilancias.
Vigilancias establecidas.
test/ ACCESS foo

Ejemplo 2

Un breve script de shell para esperar eficientemente mensajes de registro relacionados con httpd y hacer algo apropiado.

#!/bin/sh
while ! inotifywait -e modify /var/log/messages; do
  if tail -n1 /var/log/messages | grep httpd; then
    kdialog --msgbox "¡Apache necesita cariño!"
  fi
done

Ejemplo 3

Se usa un formato de salida personalizado para vigilar `~/test'. Mientras tanto, alguien ejecuta `touch ~/test/badfile; touch ~/test/goodfile; rm ~/test/badfile' en otra consola.

% inotifywait -m -r --format '%:e %f' ~/test
Configurando vigilancias. ¡Cuidado: como se especificó -r, esto puede tardar un poco!
Vigilancias establecidas.
CREATE badfile
OPEN badfile
ATTRIB badfile
CLOSE_WRITE:CLOSE badfile
CREATE goodfile
OPEN goodfile
ATTRIB goodfile
CLOSE_WRITE:CLOSE goodfile
DELETE badfile

Ejemplo 4

Hacer cumplir los permisos de archivo en el directorio `~/test'

inotifywait -qmr -e 'moved_to,create' --format '%w%f%0' --no-newline ~/test |\
    while IFS= read -r -d '' file
    do
	  chmod -v a+rX "$file"
    done

ADVERTENCIAS

Al usar inotifywait, no se garantiza que el nombre de archivo que se emite esté actualizado después de una operación de mover, ya que lo que se está monitoreando es el inodo. Además, no se garantiza que ninguna de las operaciones observadas se haya realizado en el nombre de archivo en el que se instruyó a inotifywait que monitoreara en los casos en que el archivo es conocido por varios nombres en el sistema de archivos.

ERRORES

Existen condiciones de carrera en el código de vigilancia recursiva de directorios que pueden causar que se pierdan eventos si ocurren en un directorio inmediatamente después de que ese directorio sea creado. Probablemente no sea posible corregirlo.

Se asume que la cola de eventos de inotify nunca se desbordará.
