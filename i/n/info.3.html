Descripción detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es para usuarios avanzados y extremos. No lo necesitas a menos que realmente sepas lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se han limitado a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivo.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo que PhysicsFS no proporciona directamente: quizás algún formato propietario que solo tu aplicación necesite entender.

Internamente, todo el soporte de archivo incorporado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver son el código fuente de PhysicsFS.

Un archivador se añade al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automáticamente con PHYSFS_mount(); si un archivo dado puede ser manejado por tu archivador, se le dará el control según corresponda.

Estos métodos tratan con manejadores de directorios. Tienes una instancia de tu archivador, y esta genera un manejador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archiver (no de un archivo) es generalmente la vida útil completa del proceso, y se asume que es un singleton, no proporcionamos ningún dato de instancia para el archivador en sí; la aplicación puede usar variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para verificar los enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de retornar. PhysicsFS pasará estos errores a la aplicación sin modificar en la mayoría de los casos.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Archiver sean seguras para hilos por sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador dado dentro de la biblioteca, pero no promete que el uso del mismo PHYSFS_File desde dos hilos a la vez sea seguro para hilos; como tal, tu PHYSFS_Archiver puede asumir que el bloqueo se maneja por ti siempre y cuando el PHYSFS_Io que devuelves desde PHYSFS_open* no cambie ningún estado de tu Archiver, ya que el PHYSFS_Io no estará tan agresivamente protegido.

Documentación de campos

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruye un archivo previamente abierto. Cierra este archivo y libera cualquier memoria asociada, incluyendo el PHYSFS_Io original y (opaque) en sí, si aplica. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Lista todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, para que puedas desecharla al retornar de la devolución de llamada. (dirname) está en notación independiente de la plataforma. Si tienes un error, llama a PHYSFS_SetErrorCode() con el código que parezca apropiado y retorna PHYSFS_ENUM_ERROR. Si la devolución de llamada retorna PHYSFS_ENUM_ERROR, por favor llama a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y luego retorna también PHYSFS_ENUM_ERROR. No llames a la devolución de llamada de nuevo en ninguna circunstancia. Si la devolución de llamada retorna PHYSFS_ENUM_STOP, detén la enumeración y retorna PHYSFS_ENUM_STOP también. No llames a la devolución de llamada de nuevo en ninguna circunstancia. No establezcas un código de error en este caso. Las devoluciones de llamada solo deben retornar un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene comportamiento indefinido. Mientras la devolución de llamada haya retornado PHYSFS_ENUM_OK y no hayas experimentado ningún error propio, sigue enumerando hasta que termines y luego retorna PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate retorna cero o no cero (éxito o fracaso), ¡así que ten en cuenta que este puntero de función retorna valores diferentes!

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Esto se usa para identificar tu archivo, y se retorna en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crea un directorio en el archivo. Si la aplicación está intentando crear múltiples directorios, PhysicsFS los dividirá en múltiples llamadas antes de pasarlos a tu controlador. Si el archivo es de solo lectura, esta operación debería fallar. Retorna un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abre un archivo en este archivador para añadir. Si el archivo no existe, debe crearse. El desplazamiento de escritura debe ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de la plataforma. Retorna NULL en caso de fallo, y llama a PHYSFS_setErrorCode(). Retorna no NULL en caso de éxito. El puntero retornado se pasará como parámetro "opaque" para llamadas posteriores de archivo.
