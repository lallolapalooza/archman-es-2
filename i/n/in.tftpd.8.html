DESCRIPCIÓ

N

tftpd es un servidor para el Protocolo de Transferencia de Archivos Trivial. El protocolo TFTP se utiliza ampliamente para soportar el arranque remoto de dispositivos sin disco. El servidor normalmente es iniciado por inetd, pero también puede ejecut

arse de forma
independiente.

Conectar solo con IPv6, si fue

en
Ejecutar el servidor en modo independiente (escucha), en lugar de ejecutarlo desde inetd. En modo de escucha, la opción --timeout es ignorada, y la --address opción puede ser usada para especificar una dirección local específica o un puerto al que

Permitir la creación de nuevos archivos. Por defecto, tftpd solo permitirá la subida de archivos que ya existen. Los archivos se crean con permisos predeterminados que permiten a cualquiera leerlos o escribirlos, a menos que se especifiquen las opciones --permissive o --umask

--secure, -

Cambiar el directorio raíz al inicio. Esto significa que el host remoto no necesita pasar el directorio como parte de la transferencia, y puede añadir seguridad. Cuando --secure es especificado, exactamente un directorio debe ser especificado en la línea de comandos. El uso de esta opción es recomendado por seguridad así como por compatibilidad con algunas ROM de arranque que no pueden ser fácilmente modificadas para incluir un nombre de directorio en su
solicitud.

Especificar el nombre de usuario con el que tftpd se ejecutará; el valor predeterminado es "nobody". El ID de usuario, el ID de grupo y (si es posible en la plataforma) los IDs de grupos suplementarios se establecerán en los especificados en la base de datos de permisos del sistema para este nombre de

Establece la umask para los archivos recién creados en el valor especificado. El valor predeterminado es cero (cualquiera puede leer o escribir) si la --permissive opción no es especificada, o heredada del proceso invocador si --permissive es

Cuando se ejecuta en modo independiente, escribe el ID del proceso del servidor que escucha en archivo_pid. En la terminación normal (SIGTERM o SIGINT) el archivo pid es eliminado

Cuando se ejecuta desde inetd esto especifica cuánto tiempo, en segundos, esperar por una segunda conexión antes de terminar el servidor. inetd entonces reiniciará el servidor cuando llegue otra solicitud. El valor predeterminado es 900 (15 minutos.

Determina el tiempo de espera predeterminado, en microsegundos, antes de que el primer paquete sea retransmitido. Esto puede ser modificado por el cliente si se negocia la opción timeout o utimeout. El valor predeterminado es 1000000 (1 segundo.

Especifica el tamaño de bloque máximo permitido. El rango permitido para este parámetro es de 512 a 65464. Algunos clientes embebidos solicitan tamaños de bloque grandes y sin embargo no manejan los paquetes fragmentados correctamente; para estos clientes, se recomienda establecer este valor en el MTU más pequeño de su red menos 32 bytes (20 bytes para IP, 8 para UDP y 4 para TFTP; menos si usa opciones IP en su red.) NOMBREMAPEO DE

ME

La opción --mapfile especifica un archivo que contiene reglas de remapeo de nombres de archivo. Cada línea que no sea un comentario (los comentarios comienzan con signos de almohadilla, #) contiene una operación, especificada más abajo; una regex, una expresión regular en el estilo de egrep; y opcionalmente un patrón de reemplazo. Se realiza la operación indicada por operación si la regex coincide con todo o parte del nombre de archivo. Las reglas se procesan de arriba hacia abajo y, de forma predeterminada, se procesan todas las reglas incluso si hay una

coincidencia.

La operación puede ser cualquier combinación de las siguientes

letras:
r
Reemplazar la subcadena coincidente con la regex por el patrón de reemplazo. El patrón de reemplazo puede contener secuencias de escape; véase más
abajo.
g
Repetir esta regla hasta que deje de coincidir. Esto se usa siempre con r
.
i
Hacer coincidir la regex sin distinguir mayúsculas de minúsculas. De forma predeterminada, distingue mayúsculas de
minúsculas.
e
Si esta regla coincide, finalizar el procesamiento de reglas después de ejecutar la
regla.
s
Si esta regla coincide, reiniciar el procesamiento de reglas desde la primera regla después de ejecutar esta
regla.
a
Si esta regla coincide, rechazar la solicitud y enviar un error de acceso denegado al
cliente.
G
Esta regla se aplica solo a solicitudes GET (RRQ)
.
P
Esta regla se aplica solo a solicitudes PUT (WRQ)
.
~
Invertir el sentido de esta regla, es decir, ejecutar la operación solo si la regex no coincide. No se puede usar junto con r
.

Se reconocen las siguientes secuencias de escape como parte del patrón de ree

mplazo:
\
0
La cadena completa coincidente con la rege
x.
\1 a \
9
Las cadenas coincidentes con cada una de las primeras nueve subexpresiones entre paréntesis, \( ... \), del patrón re
gex.
\
i
La dirección IP del host solicitante, en notación de cuatro octetos separados por puntos (p. ej. 192.0.2.
169).
\
x
La dirección IP del host solicitante, en notación hexadecimal (p. ej. C00002A9)
.
\
\
Barra invertida
literal.
\espacio en
blanco
Espacio en blanco
literal.
\
#
Signo de almohadilla
literal.
\
U
Convierte todas las letras siguientes a
mayúsculas.
\
L
Convierte todas las letras siguientes a
minúsculas.
\
E
Cancela el efecto de \U o \L
.

SEGURIDA

D

El uso de los servicios TFTP no requiere una cuenta ni una contraseña en el sistema servidor. Debido a la falta de información de autenticación, tftpd permitirá el acceso solo a los archivos legibles públicamente (o+r), a menos que se especifique la opción --permissive. Solo se podrán escribir archivos si ya existen y son escribibles públicamente, a menos que se especifique la opción --create. Tenga en cuenta que esto extiende el concepto de ``público'' para incluir a todos los usuarios de todos los hosts a los que se pueda acceder a través de la red; esto puede no ser apropiado en todos los sistemas, y sus implicaciones deben considerarse antes de habilitar el servicio TFTP. Normalmente, se debe emplear algún tipo de firewall o solución de filtrado de paquetes. Si se ha compilado adecuadamente (véase la salida de in.tftpd --version) tftpd consultará la base de datos hosts_access(5) para obtener información de control de acceso. Esto puede ser lento; los sitios que requieran el máximo rendimiento podrían querer compilar sin esta opción y recurrir en su lugar al firewall o a los filtros de paquetes basados en el

kernel.

El servidor debe configurarse para que se ejecute como el usuario con el menor privilegio posible; consulte la opción --user. Probablemente sea una buena idea configurar una cuenta de usuario específica para tftpd, en lugar de dejarlo ejecutarse como "nobody", para protegerse contra fugas de privilegios entre

aplicaciones.

El acceso a los archivos puede, y debe, restringirse invocando tftpd con una lista de directorios incluyendo rutas como argumentos del programa servidor en la línea de comandos. En este caso, el acceso se restringe a los archivos cuyos nombres estén precedidos por uno de los directorios indicados. Si es posible, se recomienda que se use la opción --secure para configurar un entorno chroot() en el que se ejecute el servidor una vez que se haya establecido una

conexión.

Por último, el remapeo de nombres de archivo (opción --mapfile) puede utilizarse para proporciona

r una cantidad limitada de
control de acceso adicional.
