INTEGRITYTAB(5) integritytab INTEGRITYTAB(5)

NOMBRE

integritytab - Configuración para dispositivos de bloque protegidos por integridad

SINOPSIS

/etc/integritytab

DESCRIPCIÓN

El archivo /etc/integritytab describe los dispositivos de bloque protegidos por integridad que se configuran durante el arranque del sistema.

Las líneas vacías y las líneas que comienzan con el carácter "#" se ignoran. Cada una de las líneas restantes describe un dispositivo de bloque protegido por integridad verit. Los campos están delimitados por espacios en blanco.

Cada línea tiene la forma

nombre-volumen dispositivo-bloque
    [archivo-clave|-] [opciones|-]

Los dos primeros campos son obligatorios, los dos restantes son opcionales y solo se requieren si el usuario especificó opciones no predeterminadas durante el formato de integridad.

El primer campo contiene el nombre del volumen de integridad resultante; su dispositivo de bloque se configura debajo de /dev/mapper/.

El segundo campo contiene una ruta al dispositivo de bloque subyacente, o una especificación de un dispositivo de bloque mediante "UUID=" seguido del UUID, "PARTUUID=" seguido del UUID de la partición, "LABEL=" seguido de la etiqueta, "PARTLABEL=" seguido de la etiqueta de la partición.

El tercer campo, si está presente, contiene la ruta absoluta a un archivo de clave o un "-" para especificar ninguno. Cuando el nombre del archivo está presente, el "algoritmo-integridad" por defecto es "hmac-sha256" con la longitud de la clave derivada del número de bytes en el archivo de clave. En este momento, el único algoritmo de integridad compatible cuando se usa un archivo de clave es hmac-sha256. El tamaño máximo del archivo de clave es de 4096 bytes.

El cuarto campo, si está presente, es una lista de opciones separada por comas o un "-" para especificar ninguna. Las siguientes opciones se reconocen:

allow-discards

Permitir el uso de solicitudes de descarte (TRIM) para el dispositivo. Esta opción está disponible desde la versión 5.7 del kernel de Linux.

Añadido en la versión 250.

mode=(journal|bitmap|direct)

Habilitar el modo con diario, con mapa de bits o directo (passthrough). El modo con diario es el predeterminado cuando no se especifica esta opción. Proporciona seguridad contra fallos, pero puede ser lento porque todos los datos deben escribirse dos veces. El modo con mapa de bits es más eficiente ya que requiere una sola escritura, pero es menos fiable porque si ocurre corrupción de datos cuando la máquina se bloquea, es posible que no se detecte. El modo directo deshabilita el diario y el mapa de bits. Corresponde al modo de "escrituras directas" documentado en la documentación de dm-integrity[1]. Tenga en cuenta que sin un diario, si ocurre un bloqueo, es posible que las etiquetas de integridad y los datos no coincidan. Si se utiliza, las opciones journal-* a continuación no tendrán ningún efecto si se pasan.

Añadido en la versión 254.

journal-watermark=[0..100]%

Marca de agua del diario en porcentaje. Cuando el porcentaje del diario supera esta marca de agua, se iniciará la escritura del diario. Establecer un valor de "0%" utiliza el valor predeterminado.

Añadido en la versión 250.

journal-commit-time=[0..N]

Tiempo de confirmación en milisegundos. Cuando transcurre este tiempo (y no se emitió ninguna operación de escritura explícita), se escribe el diario. Establecer un valor de cero utiliza el valor predeterminado.

Añadido en la versión 250.

data-device=/dev/disk/by-...

Especifique un dispositivo de bloque separado que contenga datos existentes. El segundo campo especificado en integritytab para el dispositivo de bloque contendrá entonces las etiquetas de integridad y el diario calculados para data-device, pero no los datos del usuario final.

Añadido en la versión 250.

integrity-algorithm=[crc32c|crc32|xxhash64|sha1|sha256|hmac-sha256]

El algoritmo utilizado para la verificación de integridad. El valor predeterminado es crc32c. Debe coincidir con la opción utilizada durante el formato.

Añadido en la versión 250.

_netdev

Marca este dispositivo veritysetup como que requiere red. Se iniciará después de que la red esté disponible, de manera similar a las unidades de systemd.mount(5) marcadas con _netdev. La unidad de servicio para configurar este dispositivo se ordenará entre remote-fs-pre.target y remote-integritysetup.target, en lugar de integritysetup-pre.target e integritysetup.target.

Pista: si este dispositivo se utiliza para un punto de montaje que se especifica en fstab(5), la opción _netdev también debe usarse para el punto de montaje. De lo contrario, se podría crear un bucle de dependencias donde el punto de montaje será invocado por local-fs.target, mientras que el servicio para configurar la red generalmente solo se inicia *después* de que el sistema de archivos local se haya montado.

Añadido en la versión 258.

noauto

Este dispositivo no se agregará a integritysetup.target. Esto significa que no se habilitará automáticamente al arrancar, a menos que algo más lo invoque. En particular, si el dispositivo se utiliza para un punto de montaje, se habilitará automáticamente durante el arranque, a menos que el punto de montaje en sí también esté deshabilitado con noauto.

Añadido en la versión 258.

nofail

Este dispositivo no será una dependencia estricta de integritysetup.target. Aún se invocará y se iniciará, pero el sistema no esperará a que el dispositivo aparezca y se habilite, y el arranque no fallará si esto no tiene éxito. Tenga en cuenta que otras unidades que dependen del dispositivo habilitado aún pueden fallar. En particular, si el dispositivo se utiliza para un punto de montaje, el punto de montaje en sí también debe tener la opción nofail, o el arranque fallará si el dispositivo no se habilita correctamente.

Añadido en la versión 258.

Al inicio temprano y cuando la configuración del gestor del sistema se recarga, este archivo se traduce a unidades de systemd nativas mediante systemd-integritysetup-generator(8).

EJEMPLOS

Ejemplo 1. /etc/integritytab

Configurar dos dispositivos de bloque protegidos por integridad.

home PARTUUID=4973d0b8-1b15-c449-96ec-94bab7f6a7b8 - journal-commit-time=10,allow-discards,journal-watermark=55%
data PARTUUID=5d4b1808-be76-774d-88af-03c4c3a41761 - allow-discards

Ejemplo 2. /etc/integritytab

Configurar 1 dispositivo de bloque protegido por integridad usando valores predeterminados

home PARTUUID=4973d0b8-1b15-c449-96ec-94bab7f6a7b8

Ejemplo 3. /etc/integritytab

Configurar 1 dispositivo de integridad usando un dispositivo de bloque de datos existente que contiene datos de usuario

home PARTUUID=4973d0b8-1b15-c449-96ec-94bab7f6a7b8 - data-device=/dev/disk/by-uuid/9276d9c0-d4e3-4297-b4ff-3307cd0d092f

Ejemplo 4. /etc/integritytab

Configurar 1 dispositivo de integridad usando un archivo de clave HMAC usando valores predeterminados

home PARTUUID=4973d0b8-1b15-c449-96ec-94bab7f6a7b8 /etc/hmac.key
