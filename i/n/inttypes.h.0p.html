NOMBRE

inttypes.h — tipos de enteros de tamaño fijo

SINOPSIS

#include <inttypes.h>

DESCRIPCIÓN

Parte de la funcionalidad descrita en esta página de referencia amplía el estándar ISO C. Las aplicaciones definirán el macro de prueba de características apropiado (consulte el volumen de Interfaces del Sistema de POSIX.1‐2017, Sección 2.2, El Entorno de Compilación) para habilitar la visibilidad de estos símbolos en este encabezado.

El encabezado <inttypes.h> incluirá el encabezado <stdint.h>.

El encabezado <inttypes.h> definirá al menos los siguientes tipos:

imaxdiv_t
Tipo de estructura que es el tipo del valor devuelto por la función imaxdiv().
wchar_t
Como se describe en <stddef.h>.

El encabezado <inttypes.h> definirá los siguientes macros. Cada uno se expande a una cadena de caracteres literal que contiene un especificador de conversión, posiblemente modificado por un modificador de longitud, adecuado para su uso dentro del argumento format de una función de entrada/salida formateada al convertir el tipo entero correspondiente. Estos macros tienen la forma general de PRI (cadenas de caracteres literales para la familia de funciones fprintf() y fwprintf()) o SCN (cadenas de caracteres literales para la familia de funciones fscanf() y fwscanf()), seguidas del especificador de conversión, seguidas de un nombre correspondiente a un nombre de tipo similar en <stdint.h>. En estos nombres, N representa el ancho del tipo como se describe en <stdint.h>. Por ejemplo, PRIdFAST32 se puede utilizar en una cadena de formato para imprimir el valor de un entero de tipo int_fast32_t.

Los macros fprintf() para enteros con signo son:

PRIdN PRIdLEASTN PRIdFASTN PRIdMAX PRIdPTR
PRIiN PRIiLEASTN PRIiFASTN PRIiMAX PRIiPTR

Los macros fprintf() para enteros sin signo son:

PRIoN PRIoLEASTN PRIoFASTN PRIoMAX PRIoPTR
PRIuN PRIuLEASTN PRIuFASTN PRIuMAX PRIuPTR
PRIxN PRIxLEASTN PRIxFASTN PRIxMAX PRIxPTR
PRIXN PRIXLEASTN PRIXFASTN PRIXMAX PRIXPTR

Los macros fscanf() para enteros con signo son:

SCNdN SCNdLEASTN SCNdFASTN SCNdMAX SCNdPTR
SCNiN SCNiLEASTN SCNiFASTN SCNiMAX SCNiPTR

Los macros fscanf() para enteros sin signo son:

SCNoN SCNoLEASTN SCNoFASTN SCNoMAX SCNoPTR
SCNuN SCNuLEASTN SCNuFASTN SCNuMAX SCNuPTR
SCNxN SCNxLEASTN SCNxFASTN SCNxMAX SCNxPTR

Para cada tipo que la implementación proporcione en <stdint.h>, se definirán los macros correspondientes fprintf() y fwprintf() y se definirán los macros correspondientes fscanf() y fwscanf() a menos que la implementación no tenga un modificador adecuado para el tipo.

Se declararán las siguientes funciones y también pueden definirse como macros. Se proporcionarán prototipos de función.

intmax_t  imaxabs(intmax_t);
imaxdiv_t imaxdiv(intmax_t, intmax_t);
intmax_t  strtoimax(const char *restrict, char **restrict, int);
uintmax_t strtoumax(const char *restrict, char **restrict, int);
intmax_t  wcstoimax(const wchar_t *restrict, wchar_t **restrict, int);
uintmax_t wcstoumax(const wchar_t *restrict, wchar_t **restrict, int);

Las siguientes secciones son informativas.

EJEMPLOS

#include <inttypes.h>
#include <wchar.h>
int main(void)
{
    uintmax_t i = UINTMAX_MAX; // Este tipo siempre existe.
    wprintf(L"El valor entero más grande es %020"
        PRIxMAX "\n", i);
    return 0;
}

USO DE LA APLICACIÓN

El propósito de <inttypes.h> es proporcionar un conjunto de tipos de enteros cuyas definiciones sean consistentes entre máquinas e independientes de los sistemas operativos y otras peculiaridades de implementación. Define, a través de typedef, tipos de enteros de varios tamaños. Las implementaciones son libres de typedef como tipos de enteros estándar ISO C o extensiones que soporten. El uso coherente de este encabezado aumentará en gran medida la portabilidad de las aplicaciones entre plataformas.

RACIOCINIO

El estándar ISO/IEC 9899:1990 especificaba que el lenguaje debería soportar cuatro tipos de datos enteros con y sin signo—char, short, int y long—pero imponía muy pocos requisitos sobre su tamaño, aparte de que int y short fueran de al menos 16 bits y long fuera de al menos la longitud de int y no menor de 32 bits. Para sistemas de 16 bits, la mayoría de las implementaciones asignaban 8, 16, 16 y 32 bits a char, short, int y long, respectivamente. Para sistemas de 32 bits, la práctica común ha sido asignar 8, 16, 32 y 32 bits a estos tipos. Esta diferencia en el tamaño de int puede crear algunos problemas para los usuarios que migran de un sistema a otro que asigna tamaños diferentes a los tipos enteros, porque la regla de promoción de enteros del estándar ISO C puede producir cambios silenciosos inesperadamente. La necesidad de definir un tipo entero extendido aumentó con la introducción de sistemas de 64 bits.

DIRECCIONES FUTURAS

Se pueden añadir nombres de macros que comiencen con PRI o SCN seguidos de cualquier letra minúscula o 'X' a los macros definidos en el encabezado <inttypes.h>.

NOMBRE

inttypes.h - definiciones de tipos enteros de tamaño fijo

SINOPSIS

#include <inttypes.h>

DESCRIPCIÓN

El archivo de cabecera inttypes.h define varios macros para manejar tipos enteros de tamaño fijo. Estos tipos son importantes para la portabilidad, especialmente cuando se interactúa con el código C que se compila en diferentes arquitecturas. Los tipos de datos enteros en C tienen tamaños que pueden variar de una plataforma a otra. Por ejemplo, un int puede ser de 16, 32 o 64 bits dependiendo de la arquitectura y el compilador. Esto puede causar problemas cuando se intercambian datos entre sistemas con diferentes representaciones de tipos enteros.

El estándar C99 introdujo tipos enteros de tamaño fijo que garantizan un tamaño específico en todos los sistemas. Estos tipos se definen en el archivo de cabecera stdint.h y son los siguientes:

  • int8_t: Entero con signo de 8 bits
  • int16_t: Entero con signo de 16 bits
  • int32_t: Entero con signo de 32 bits
  • int64_t: Entero con signo de 64 bits
  • uint8_t: Entero sin signo de 8 bits
  • uint16_t: Entero sin signo de 16 bits
  • uint32_t: Entero sin signo de 32 bits
  • uint64_t: Entero sin signo de 64 bits
  • int_least8_t, int_least16_t, ..., uint_least64_t: Los tipos enteros con signo/sin signo más pequeños que son al menos 8, 16, ..., 64 bits de ancho.
  • int_fast8_t, int_fast16_t, ..., int_fast64_t: Los tipos enteros con signo/sin signo más rápidos que son al menos 8, 16, ..., 64 bits de ancho.

inttypes.h, por otro lado, se centra principalmente en proporcionar macros de formato para estos tipos de enteros para su uso con funciones de E/S como printf() y scanf(). Estas macros de formato garantizan que los tipos enteros de tamaño fijo se impriman y analicen correctamente en diferentes plataformas.

Aquí hay algunas de las macros de formato clave definidas en inttypes.h:

  • PRIdN: Macro de formato para intN_t (por ejemplo, PRId8 para int8_t)
  • PRIiN: Macro de formato para intN_t (entrada, base 10)
  • PRIoN: Macro de formato para uintN_t (salida, base 8)
  • PRIuN: Macro de formato para uintN_t (salida, base 10)
  • PRIxN: Macro de formato para uintN_t (salida, base 16, minúsculas)
  • PRIXN: Macro de formato para uintN_t (salida, base 16, mayúsculas)
  • SCNdN: Macro de formato para intN_t (entrada, base 10)
  • SCNiN: Macro de formato para intN_t (entrada, base 10)
  • SCNoN: Macro de formato para uintN_t (entrada, base 8)
  • SCNuN: Macro de formato para uintN_t (entrada, base 10)
  • SCNxN: Macro de formato para uintN_t (entrada, base 16)

Las 'N' en estas macros representa el número de bits (por ejemplo, 8, 16, 32, 64). También hay macros para los tipos 'least' y 'fast':

  • PRIdLEASTN, PRIuLEASTN, etc.
  • PRIdFASTN, PRIuFASTN, etc.
  • SCNdLEASTN, SCNuLEASTN, etc.
  • SCNdFASTN, SCNuFASTN, etc.

Además, hay macros para los tipos `intmax_t` (el tipo entero con signo más grande) y `uintmax_t` (el tipo entero sin signo más grande):

  • PRIdMAX, PRIuMAX, PRIxMAX, etc.
  • SCNdMAX, SCNuMAX, SCNxMAX, etc.

Y macros para los tipos `intptr_t` (tipo entero con signo que puede contener un puntero) y `uintptr_t` (tipo entero sin signo que puede contener un puntero):

  • PRIdPTR, PRIuPTR, PRIxPTR, etc.
  • SCNdPTR, SCNuPTR, SCNxPTR, etc.

Para usar estos tipos y macros, normalmente incluiría ambos stdint.h y inttypes.h en su código:

#include <stdint.h>
#include <inttypes.h>

int32_t my_var = 12345;
printf("Mi variable es: %" PRId32 "\n", my_var);

En este ejemplo, PRId32 se expandirá a una cadena de formato de especificador de tipo correcta para un int32_t en el sistema actual. Sin usar estas macros, tendría que escribir explícitamente el especificador de formato correcto (por ejemplo, "d", "ld", "lld") que depende del tamaño de int32_t en la plataforma, lo que haría que su código fuera menos portable.

EJEMPLOS

Aquí hay un ejemplo de cómo usar inttypes.h para imprimir un uint64_t en formato hexadecimal:

#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main() {
    uint64_t value = 0x123456789abcdef;
    printf("El valor hexadecimal es: 0x%" PRIx64 "\n", value);
    return 0;
}

Este código imprimirá:

El valor hexadecimal es: 0x123456789abcdef

Si desea leer un intmax_t de la entrada estándar:

#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main() {
    intmax_t number;
    printf("Introduce un número entero: ");
    if (scanf("%" SCNdMAX, &number) == 1) {
        printf("Has introducido: %" PRIdMAX "\n", number);
    } else {
        printf("Entrada inválida.\n");
    }
    return 0;
}

USO DE LA APLICACIÓN

inttypes.h se utiliza principalmente en programación C para garantizar la portabilidad del código que requiere tipos enteros de un tamaño específico. Al utilizar los tipos definidos en stdint.h y las macros de formato de inttypes.h, los desarrolladores pueden escribir código que funcione de manera predecible en diferentes sistemas y arquitecturas.

Es particularmente útil en:

  • Programación de sistemas: cuando se trabaja con estructuras de datos de bajo nivel o interactúa con hardware.
  • Transferencia de datos: al serializar o deserializar datos para su transmisión a través de redes o para su almacenamiento en disco, donde los tamaños de los tipos enteros deben ser consistentes.
  • Bibliotecas portátiles: para garantizar que las bibliotecas funcionen correctamente en una amplia gama de plataformas.

FUNDAMENTO

La necesidad de inttypes.h surge de la naturaleza variable de los tamaños de los tipos de datos enteros en el lenguaje C. Antes de C99, los programadores a menudo usaban tipos como long o long long para tratar de obtener tamaños más grandes, pero esto no era una garantía. La introducción de stdint.h resolvió el problema de tener tipos de un tamaño garantizado, pero la forma de formatearlos para la entrada/salida todavía estaba sujeta a las convenciones de la plataforma.

inttypes.h proporciona una solución estandarizada para el formateo de estos tipos de tamaño fijo, lo que permite a los programadores escribir código que es fácilmente portable entre diferentes compiladores y arquitecturas sin necesidad de realizar comprobaciones condicionales de tamaño de tipo o usar extensiones específicas del compilador.

DIRECCIONES FUTURAS

A medida que las arquitecturas informáticas continúan evolucionando, la necesidad de tipos enteros de tamaño fijo probablemente persistirá. Se espera que inttypes.h siga siendo una herramienta esencial para los programadores de C que buscan escribir código portátil y robusto. Es probable que las futuras revisiones del estándar C mantengan y potencialmente amplíen las capacidades proporcionadas por stdint.h y inttypes.h.
