La llamada al sistema init_module() no es soportada por glibc. No se proporciona ninguna declaración en los encabezados de glibc, pero, por una peculiaridad histórica, las versiones de glibc anteriores a glibc 2.23 sí exportaban una ABI para esta llamada al sistema. Por lo tanto, para emplear esta llamada al sistema, es (antes de glibc 2.23) suficiente declarar manualmente la interfaz en su código; alternativamente, puede invocar la llamada al sistema usando syscall

(2).

Linux 2.4 y

anteriores

En Linux 2.4 y anteriores, la llamada al sistema init_module() era bastante

diferente:

#include <linux/module.

h>

int init_module(const char *name, struct module *image)

;

(Las aplicaciones de espacio de usuario pueden detectar qué versión de init_module() está disponible llamando a query_module(); esta última llamada falla con el error ENOSYS en Linux 2.6 y posteriores.

)

La versión antigua de la llamada al sistema carga la imagen del módulo reubicada a la que apunta image en el espacio del kernel y ejecuta la función init del módulo. El llamador es responsable de proporcionar la imagen reubicada (desde Linux 2.6, la llamada al sistema init_module() realiza la reubicación)

.

La imagen del módulo comienza con una estructura de módulo y es seguida por código y datos según corresponda. Desde Linux 2.2, la estructura del módulo se define de la siguiente

manera: 


struct module {
    unsigned long         size_of_struct;

    unsigned int          ndeps;

    typeof(void (void))  *cleanup;
    const struct exception_table_entry *ex_table_start;

    unsigned long gp;

;
