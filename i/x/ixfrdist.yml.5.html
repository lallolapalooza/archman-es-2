IXFRDIST.YML(5) Servidor Autoritativo de PowerDNS IXFRDIST.YML(5)

NOMBRE

ixfrdist.yml - El archivo de configuración de ixfrdist

SINOPSIS

ixfrdist.yml

DESCRIPCIÓN

ixfrdist lee su configuración de un archivo YAML. Por defecto, este archivo se llama ixfrdist.yml y se lee del directorio configurado como SYSCONFDIR al compilar el software. Este directorio es normalmente uno de /etc/pdns, /etc/powerdns. Ejecute ixfrdist --help para ver el valor por defecto.

EJEMPLO

listen:
  - 192.0.2.2
  - '[2001:DB8:ABCD::2]:5300'
  - 127.0.0.1
acl:
  - 127.0.0.1
  - '192.0.2.0/24'
  - '2001:DB8:ABCD:1234::/64'
work-dir: /var/lib/ixfrdist
uid: ixfrdist
gid: ixfrdist
domains:
  - domain: example.com
    master: 192.0.2.18:5301
    max-soa-refresh: 1800
    notify:
      - 192.0.3.1
      - 192.0.3.2:5301
  - domain: example.net
    master: 2001:DB8:ABCD::2

OPCIONES

listen
La lista de direcciones en las que escuchar. ixfrdist escucha tanto en TCP como en UDP. Cuando no se especifica un puerto, se usa el 53. Al especificar puertos para IPv6, use la notación "de corchetes". Por defecto, ixfrdist escucha en 127.0.0.1:53 y [::1]:53.
acl
Una lista de máscaras de red a las que se les permite consultar ixfrdist y solicitar AXFRs e IXFRs. Las entradas sin una máscara de red se interpretarán como una única dirección. Por defecto, la ACL se establece en 127.0.0.0/8 y ::1/128.
axfr-max-records
Número máximo de registros permitidos en una transacción AXFR solicitada por ixfrdist. Esto puede evitar que fuentes no confiables utilicen toda la memoria del proceso. Por defecto, esta configuración es 0, lo que significa "ilimitado".
axfr-timeout
Tiempo de espera en segundos que puede tardar una transacción AXFR solicitada por ixfrdist . Aumente esto cuando la red hacia los servidores autoritativos es lenta o los dominios son muy grandes y experimenta tiempos de espera agotados. Por defecto es 20.
failed-soa-retry
Tiempo en segundos entre reintentos de la consulta SOA para una zona que nunca hemos transferido. Por defecto es 30.
compress
Si la compresión de registros debe estar habilitada, lo que conduce a respuestas más pequeñas a costa de un mayor uso de CPU y memoria. Por defecto es falso.
work-dir
El directorio donde se almacenan los datos del dominio. Cuando no está establecido, se usa el directorio de trabajo actual. Este directorio de trabajo tiene la siguiente estructura: work-dir/ZONE/SERIAL, por ejemplo work-dir/rpz.example./2018011902. Se recomienda encarecidamente establecer esta opción, ya que el directorio de trabajo actual puede cambiar entre invocaciones. Este directorio debe ser escribible para el usuario o grupo como el que se ejecuta ixfrdist
keep
Cantidad de copias antiguas/diferencias IXFR a conservar para cada dominio. Por defecto está establecido en 20.
tcp-in-threads
Número de hilos a generar para conexiones TCP (AXFRs) desde hosts aguas abajo. Esto limita el número de AXFRs concurrentes a clientes. Por defecto está establecido en 10.
gid
Nombre de grupo o ID numérico al que reducir privilegios después de enlazar los sockets de escucha. Por defecto, ixfrdist se ejecuta como el usuario que inició el proceso.
uid
Nombre de usuario o ID numérico al que reducir privilegios después de enlazar los sockets de escucha. Por defecto, ixfrdist se ejecuta como el usuario que inició el proceso.
domains
Una lista de dominios para redistribuir. Esta opción es obligatoria.
domain
El nombre del dominio desde el que transferir master. Obligatorio.
master
Dirección IP del servidor desde el que transferir este dominio. Obligatorio.
max-soa-refresh
Limitar el tiempo de actualización al máximo dado (en segundos). Opcional.
notify
La lista de destinos a los que enviar NOTIFY. Opcional.
webserver-address
Dirección IP en la que escuchar para el servidor web integrado. Cuando no está establecido, no se inicia ningún servidor web.
webserver-acl
Una lista de redes a las que se les permite acceder al servidor web de ixfrdist . Las entradas sin una máscara de red se interpretarán como una única dirección. Por defecto, esta lista está establecida en 127.0.0.0/8 y ::1/128.
webserver-loglevel
Cuánto debe registrar el servidor web: 'none', 'normal' o 'detailed'. Cuando se registra, cada línea de registro contiene el UUID de la solicitud, lo que permite encontrar errores causados por ciertas solicitudes. Con 'none', no se registra nada excepto errores. Con 'normal' (el valor por defecto), se registra una línea por solicitud en el estilo del formato de registro común:
[NOTICE] [webserver] 46326eef-b3ba-4455-8e76-15ec73879aa3 127.0.0.1:57566 "GET /metrics HTTP/1.1" 200 1846

con 'detailed', se registran las solicitudes y respuestas completas (incluyendo cabeceras) junto con la línea de registro regular de 'normal'.
