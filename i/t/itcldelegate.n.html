delegation(n) [incr Tcl] delegation(n)

NOMBRE

itcl::delegation - delegar métodos, procs u opciones a otros objetos

Partes de esta descripción se "toman prestadas" de la extensión Tcl [snit], ya que la funcionalidad es prácticamente idéntica.

¡ADVERTENCIA!

¡Esta es una nueva funcionalidad en [incr Tcl] donde la API aún puede cambiar!

SINOPSIS

delegate method nombreMetodo to nombreComponente ?as nombreDestino?
delegate method nombreMetodo ?to nombreComponente? using patrón
delegate method * ?to nombreComponente? ?using patrón? ?except nombreMetodo nombreMetodo ...?
delegate proc nombreProc to nombreComponente ?as nombreDestino?
delegate proc nombreProc ?to nombreComponente? using patrón
delegate proc * ?to nombreComponente? ?using patrón? ?except nombreProc nombreProc ...?
delegate option especificacionOpcion to nombreComponente
delegate option especificacionOpcion to nombreComponente as nombreDestino?
delegate option * to nombreComponente
delegate option * to nombreComponente except nombreOpcion nombreOpcion ...

DESCRIPCIÓN

El comando delegate se utiliza dentro de una definición de clase/widget/adaptador-de-widget extendida de [incr Tcl] para delegar métodos/procs/opciones a otros objetos para su manejo.

delegate method nombreMetodo to nombreComponente ?as nombreDestino?
Esta forma de delegate method delega el método nombreMetodo al componente nombreComponente. Es decir, cuando se llama al método nombreMetodo en una instancia de este tipo, el método y sus argumentos se pasarán al comando del componente nombrado en su lugar. Es decir, la siguiente declaración
delegate method wag to tail

es aproximadamente equivalente a este método definido explícitamente:

method wag {args} {
    uplevel $tail wag $args
}

La cláusula opcional as permite especificar el nombre del método delegado y posiblemente añadir algunos argumentos:

delegate method wagtail to tail as "wag briskly"

Un método no puede definirse localmente y delegarse al mismo tiempo.

delegate method nombreMetodo ?to nombreComponente? using patrón
En esta forma de la declaración delegate, la cláusula using se utiliza para especificar la forma precisa del comando al que se delega el nombre del método. La cláusula to es opcional, ya que el comando elegido podría no implicar ningún componente en particular.

El valor de la cláusula using es una lista que puede contener cualquiera o todos los siguientes códigos de sustitución; estos códigos se sustituyen con el valor descrito para construir el prefijo del comando delegado. Tenga en cuenta que las siguientes dos declaraciones son equivalentes:

delegate method wag to tail
delegate method wag to tail using "%c %m"

Cada elemento de la lista se convierte en un solo elemento del comando delegado — nunca se vuelve a analizar como una cadena.

Sustituciones:

%%
Se reemplaza con un solo "%". Por lo tanto, para pasar la cadena "%c" al comando como argumento, escribiría "%%c".
%c
Se reemplaza con el comando del componente nombrado.
%j
Se reemplaza con el nombre del método; si el nombre consta de varios tokens, se unen con guiones bajos ("_").
%m
Se reemplaza con el último token del nombre del método; si el nombre del método tiene un token, es idéntico a %M.
%M
Se reemplaza con el nombre del método; si el nombre consta de varios tokens, se unen con espacios.
%n
Se reemplaza con el nombre del espacio de nombres privado de la instancia.
%s
Se reemplaza con el nombre del comando de la instancia.
%t
Se reemplaza con el nombre completo del tipo.
%w
Se reemplaza con el nombre original del comando de la instancia; para los widgets y adaptadores de widgets de Itcl, será el nombre de la ventana de Tk. Permanece constante, incluso si se renombra el comando de la instancia.
delegate method * ?to nombreComponente? ?using patrón? ?except nombreMetodo nombreMetodo ...?
En esta forma, todos los nombres de métodos desconocidos se delegan al componente especificado. La cláusula except se puede utilizar para especificar una lista de excepciones, es decir, nombres de métodos que no se delegarán de esta manera. La cláusula using se define como se indica anteriormente. En esta forma, la declaración debe contener la cláusula to, la cláusula using, o ambas.

De hecho, el "*" puede ser una lista de dos o más tokens cuyo último elemento es "*", como en el siguiente ejemplo:

delegate method {tail *} to tail

Esto define implícitamente el método tail cuyos subcomandos se delegarán al componente tail.

Las definiciones para delegate proc ... son las mismas que para method, la única diferencia es que esto es para procs.

delegate option especificacionOpcion to comp
delegate option especificacionOpcion to comp as destino
delegate option * to comp
delegate option * to comp except excepciones
Define una opción delegada; la especificación de nombre se define como para la declaración option. Cuando se utiliza el método de instancia configure, configurelist o cget para establecer o recuperar el valor de la opción, el comando configure o cget equivalente se aplicará al componente como si la opción se hubiera definido con los siguientes -configuremethod y -cgetmethod:
method ConfigureMethod {option value} {
    $comp configure $option $value
}
method CgetMethod {option} {
    return [$comp cget $option]
}

Tenga en cuenta que las opciones delegadas nunca aparecen en el array itcl_options. Si se especifica la cláusula as, se utiliza el nombre de la opción de destino en lugar del nombre.

delegate opcion * ?except nombreOpcion nombreOpcion ...?
Esta forma delega todas las opciones desconocidas al componente especificado. La cláusula except se puede utilizar para especificar una lista de excepciones, es decir, nombres de opciones que no se delegarán.

Advertencia: las opciones solo se pueden delegar a un componente si este admite los métodos de instancia configure y cget.

Una opción no puede definirse localmente y delegarse al mismo tiempo. TBD: Continuar desde aquí.
