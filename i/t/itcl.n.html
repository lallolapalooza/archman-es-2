DESCRIPCIÓ

N

[incr Tcl] proporciona extensiones orientadas a objetos para Tcl, del mismo modo que C++ proporciona extensiones orientadas a objetos para C. El énfasis de este trabajo, sin embargo, no es crear un entorno de programación orientado a objetos de alto nivel. Más bien, se trata de apoyar prácticas de programación más estructuradas en Tcl sin cambiar el estilo del lenguaje. Más que nada, [incr Tcl] proporciona un medio para encapsular procedimientos relacionados junto con sus datos compartidos en un espacio de nombres que está oculto del mundo exteri

or. Fomenta una mejor programación al promover la mentalidad de "biblioteca" orient
ada a objetos. También permite la reutilización de código a través de la herencia.

CLASE

S

La construcción fundamental en [incr Tcl] es la definición de clase. Cada clase actúa como una plantilla para los objetos reales que pueden ser creados. Cada objeto tiene su propio conjunto único de datos, que contiene instancias de las "variables" definidas en la clase. Procedimientos especiales llamados "métodos" se utilizan para manipular objetos individuales. Los métodos son como las operaciones que se utilizan para manipular widgets de Tk. El widget "button", por ejemplo, tiene métodos como "flash" e "invoke" que hacen que un botón particular parpadee e invoque su

comando.

Dentro del cuerpo de un método, las "variables" definidas en la clase están automáticamente disponibles. No necesitan ser declaradas con nada como el comando global. Dentro de otro método de clase, un método se puede invocar como cualquier otro comando-simplemente usando su nombre. Desde cualquier otro contexto, el nombre del método debe ir precedido por un nombre de objeto, que proporciona un contexto para los datos a los que el método puede

acceder.

Cada clase tiene su propio espacio de nombres que contiene cosas que son comunes a todos los objetos que pertenecen a la clase. Por ejemplo, los miembros de datos "comunes" son compartidos por todos los objetos en la clase. Son variables globales que existen en el espacio de nombres de la clase, pero como están incluidas en la definición de la clase, no necesitan ser declaradas usando el comando global; están automáticamente disponibles para cualquier código que se ejecute en el contexto de la clase. Una clase también puede crear variables globales ordinarias, pero estas deben ser declaradas usando el comando global cada vez que se

usen.

Las clases también pueden tener procedimientos ordinarios declarados como "procs". Dentro de otro método o proc de clase, un proc se puede invocar como cualquier otro comando-simplemente usando su nombre. Desde cualquier otro contexto, el nombre del procedimiento debe calificarse con el espacio de nombres de la clase como "className::proc". Los procs de clase se ejecutan en el contexto de la clase y, por lo tanto, tienen acceso automático a todos los miembros de datos "comunes". Sin embargo, no pueden acceder a las "variables" específicas del objeto, ya que se invocan sin referencia a ningún objeto específico. Por lo general, se usan para realizar operaciones genéricas que afectan a todos los objetos que pertenecen a la

clase.

Cada uno de los elementos en una clase se puede declarar "public" (público), "protected" (protegido) o "private" (privado). Los elementos públicos pueden ser accedidos por la clase, por clases derivadas (otras clases que heredan esta clase) y por clientes externos que usan la clase. Los elementos protegidos pueden ser accedidos por la clase y por clases derivadas. Los elementos privados solo son accesibles en la clase donde están

definidos.

Los elementos "public" dentro de una clase definen su interfaz con el mundo exterior. Los métodos públicos definen las operaciones que se pueden usar para manipular un objeto. Las variables públicas son reconocidas como opciones de configuración por los métodos "configure" y "cget" que están integrados en cada clase. La interfaz pública dice qué hará un objeto pero no cómo lo hará. Los miembros protegidos y privados, junto con los cuerpos de los métodos y procs de la clase, proporcionan los detalles de implementación. Aislar al desarrollador de la aplicación de estos detalles deja al diseñador de la clase libre para cambiarlos en cualquier momento, sin previo aviso y sin afectar a los programas que dependen de la clase. Es precisamente esta encapsulación lo que hace que los programas orientados a objetos sean más fáciles de entender y

mantener.

El hecho de que los objetos [incr Tcl] se parezcan a widgets de Tk no es una coincidencia. [incr Tcl] fue diseñado de esta manera, para integrarse naturalmente en una aplicación Tcl/Tk. Pero [incr Tcl] extiende el paradigma de Tk de ser meramente basado en objetos a ser completamente orientado a objetos. Un sistema orientado a objetos soporta la herencia, permitiendo que las clases compartan comportamientos comunes al heredarlos de un ancestro o clase base. Tener una clase base como una abstracción común permite a un programador tratar clases relacionadas de manera similar. Por ejemplo, una tostadora y una licuadora realizan funciones diferentes (especializadas), pero ambas comparten la abstracción de ser electrodomésticos. Al abstraer comportamientos comunes en una clase base, el código se puede compartir en lugar de copiar. La aplicación resultante es más fácil de entender y mantener, y las clases derivadas (p. ej., electrodomésticos especializados) se pueden añadir o eliminar más

fácilmente.

Esta descripción fue solo una breve visión general de la programación orientada a objetos y de [incr Tcl]. Se presenta una introducción más tutorial en el documento incluido con esta distribución. Consulte el comando class para más detalles so

bre cómo crear
y usar clases.

ESPACIOS DE

NOMBRES

[incr Tcl] ahora incluye una instalación completa de espacios de nombres. Un espacio de nombres es una colección de comandos y variables globales que se mantiene separada del ámbito global habitual. Esto permite que las bibliotecas de código Tcl se empaqueten de una manera bien definida e impide interacciones no deseadas con otras bibliotecas. Un espacio de nombres también puede tener espacios de nombres hijos dentro de él, de modo que una biblioteca puede contener su propia copia privada de muchas otras bibliotecas. Un espacio de nombres también se puede usar para envolver un grupo de clases relacionadas. El ámbito global (llamado "::") es el espacio de nombres raíz para un intérprete; todos los demás espacios de nombres están contenidos dentro de

él.

Consulte el comando namespace para detalles sobre cómo c

rear y usar es
pacios de nombres.

MEGA-WIDGET

S

Los mega-widgets son widgets de alto nivel que se construyen usando widgets de Tk como partes componentes, generalmente sin ningún código C. Un fileselectionbox, por ejemplo, puede tener algunas listboxes, algunos widgets de entrada y algunos botones de control. Estos widgets individuales se juntan de una manera que los hace actuar como un solo widget

grande.

[incr Tk] es un marco para construir mega-widgets. Usa [incr Tcl] para soportar el paradigma de objetos y añade clases base que proporcionan comportamientos predeterminados de widgets. Consulte la página man itk para más

detalles.

[incr Widgets] es una biblioteca de mega-widgets construida usando [incr Tk]. Contiene más de 30 clases de widgets diferentes que se pueden usar directamente para construir aplic

aciones Tcl/Tk. Cada clase de widget tiene su propia
página man que describe las características disponibles.
