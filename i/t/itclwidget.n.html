widget(n) [incr Tcl] widget(n)

NOMBRE

itcl::widget - crear una clase de objetos widget

ADVERTENCIA!

Esta es una funcionalidad nueva en [incr Tcl] donde la API aún puede cambiar!!

SINOPSIS

itcl::widget nombreWidget {
    inherit widgetBase ?widgetBase...?
    constructor args ?init? cuerpo
    destructor cuerpo
    public method nombre ?args? ?cuerpo?
    protected method nombre ?args? ?cuerpo?
    private method nombre ?args? ?cuerpo?
    public proc nombre ?args? ?cuerpo?
    protected proc nombre ?args? ?cuerpo?
    private proc nombre ?args? ?cuerpo?

    protected variable nombreVar ?init? ?config?
    private variable nombreVar ?init? ?config?

DESCRIPCIÓN

Una de las construcciones fundamentales en [incr Tcl] es la definición de widget. Un widget es como una clase con algunas características adicionales. Cada widget actúa como una plantilla para objetos reales que pueden ser creados. El widget en sí es un espacio de nombres que contiene cosas comunes a todos los objetos. Cada objeto tiene su propio paquete único de datos que contiene instancias de las "variables" definidas en la definición del widget. Cada objeto también tiene una variable incorporada llamada "this", que contiene el nombre del objeto. Los widgets también pueden tener miembros de datos "comunes" que son compartidos por todos los objetos de un widget.

Se pueden incluir dos tipos de funciones en la definición del widget. Los "métodos" son funciones que operan sobre un objeto específico y, por lo tanto, tienen acceso tanto a los "variables" como a los miembros de datos "comunes". Los "procs" son procedimientos ordinarios en el espacio de nombres del widget, y solo tienen acceso a los miembros de datos "comunes".

Si el cuerpo de cualquier método o proc comienza con "@", se trata como el nombre simbólico de un procedimiento C. De lo contrario, se trata como un script de código Tcl. Ver abajo para detalles sobre el registro y uso de procedimientos C.

Un widget solo puede definirse una vez, aunque los cuerpos de los métodos y procs de widget pueden definirse una y otra vez para depuración interactiva. Ver los comandos body y configbody para más detalles.

Cada espacio de nombres puede tener su propia colección de objetos y widgets. La lista de widgets disponibles en el contexto actual se puede consultar usando el comando "itcl::find widgets", y la lista de objetos, con el comando "itcl::find objects".

Un widget puede eliminarse usando el comando "delete widget". Los objetos individuales pueden eliminarse usando el comando "delete object".

DEFINICIONES DE WIDGET

widget nombreWidget definición
Proporciona la definición de un widget llamado nombreWidget. Si el widget nombreWidget ya existe, o si existe un comando llamado nombreWidget en el contexto del espacio de nombres actual, este comando devuelve un error. Si la definición del widget se analiza correctamente, nombreWidget se convierte en un comando en el contexto actual, manejando la creación de objetos para este widget.

La definición del widget se evalúa como una serie de instrucciones Tcl que definen elementos dentro del widget. Se reconocen los siguientes comandos de definición de widget:

inherit widgetBase ?widgetBase...?
Hace que el widget actual herede características de uno o más widgets base. Los widgets deben haber sido definidos por un comando widget anterior, o deben estar disponibles para la instalación de carga automática (ver "CARGA AUTOMÁTICA" abajo). Una única definición de widget no puede contener más de un comando inherit.

El orden de los nombres de widgetBase en la lista inherit afecta la resolución de nombres para los miembros del widget. Cuando el mismo nombre de miembro aparece en dos o más widgets base, el widget base que aparece primero en la lista inherit tiene prioridad. Por ejemplo, si los widgets "Foo" y "Bar" contienen el miembro "x", y si otro widget tiene la declaración "inherit":

inherit Foo Bar

entonces el nombre "x" significa "Foo::x". Otros miembros heredados llamados "x" deben referenciarse con su nombre explícito, como "Bar::x".

constructor args ?init? cuerpo
Declara la lista de argumentos args y el cuerpo utilizados para el constructor, que se invoca automáticamente cada vez que se crea un objeto.

Antes de que se ejecute el cuerpo, la declaración opcional init se utiliza para invocar los constructores de widget base que requieren argumentos. Las variables en la especificación de args se pueden acceder en el fragmento de código init y pasarse a los constructores de widget base. Después de evaluar la declaración init, cualquier constructor de widget base que no se haya ejecutado se invoca automáticamente sin argumentos. Esto asegura que todos los widgets base se construyan completamente antes de que se ejecute el cuerpo del constructor. Por defecto, este esquema hace que los constructores se invoquen en orden de menos específico a más específico. Este es exactamente el orden opuesto al que se informan los widgets en el comando info heritage.

Si la construcción es exitosa, el constructor siempre devuelve el nombre del objeto, independientemente de cómo se defina el cuerpo, y el nombre del objeto se convierte en un comando en el contexto del espacio de nombres actual. Si la construcción falla, se devuelve un mensaje de error.

destructor cuerpo
Declara el cuerpo utilizado para el destructor, que se invoca automáticamente cuando se elimina un objeto. Si el destructor es exitoso, los datos del objeto se destruyen y el nombre del objeto se elimina como un comando del intérprete. Si la destrucción falla, se devuelve un mensaje de error y el objeto permanece.

Cuando se destruye un objeto, todos los destructores en su jerarquía de widgets se invocan en orden de más específico a menos específico. Este es el orden en que los widgets son reportados por el comando "info heritage", y es exactamente lo opuesto al orden de constructor predeterminado.

method nombre ?args? ?cuerpo?
Declara un método llamado nombre. Cuando se ejecuta el cuerpo del método, tendrá acceso automático a variables específicas del objeto y a miembros de datos comunes.

Si se especifica la lista de args, establece la información de uso para este método. El comando body se puede usar para redefinir el cuerpo del método, pero la lista de args debe coincidir con esta especificación.

Dentro del cuerpo de otro método de widget, un método se puede invocar como cualquier otro comando, simplemente usando su nombre. Fuera del contexto del widget, el nombre del método debe ir precedido por el nombre de un objeto, que proporciona el contexto para los datos que manipula. Los métodos en un widget base que son redefinidos en el widget actual, o ocultos por otro widget base, pueden calificarse usando la sintaxis "nombreWidget::método".

proc nombre ?args? ?cuerpo?
Declara un proc llamado nombre. Un proc es un procedimiento ordinario dentro del espacio de nombres del widget.

Los procs son similares a los métodos, excepto que no tienen acceso a miembros de datos específicos del objeto. Por lo tanto, los procs solo pueden acceder a miembros de datos comunes, o usar la información proporcionada en la lista de args.

Si el cuerpo de un proc está precedido por un "@", se trata como el nombre simbólico de un procedimiento C. Ver abajo para más detalles.

variable nombreVar ?init? ?config?
Declara una variable llamada nombreVar. Si se especifica init, se utiliza para inicializar la variable cuando se crea un objeto. Si se especifica config, se tratará como una opción de configuración para el objeto. El valor inicial de las variables de objeto se establece durante la construcción del objeto, o puede ser modificado después con la opción configure.

Si se especifica el argumento config, el valor de la variable se puede cambiar usando la opción configure para el objeto. Por ejemplo, si un widget tiene la declaración:

variable color blue

entonces el color del objeto se puede cambiar con:

widgetObj configure -color red

Las variables de objeto se pueden acceder desde el cuerpo de un método o proc simplemente usando su nombre. Las variables de un widget base que se ocultan en el widget actual pueden ser referenciadas con el nombre calificado de la forma "widgetName::variable".

common nombreVar ?init?
Declara un miembro de datos común llamado nombreVar. Si se especifica init, se utiliza para inicializar el miembro de datos común cuando se define el widget. Los miembros de datos comunes se comparten entre todos los objetos de un widget.

Los miembros de datos comunes se pueden acceder desde el cuerpo de un método o proc simplemente usando su nombre. Se puede hacer referencia a miembros de datos comunes en un widget base con el nombre calificado de la forma "widgetName::commonName".

public comando ?arg arg ...?
Declara un comando público en el espacio de nombres del widget. Los comandos públicos son accesibles desde cualquier contexto.
protected comando ?arg arg ...?
Declara un comando protegido en el espacio de nombres del widget. Los comandos protegidos son accesibles solo desde el cuerpo de los métodos y procs del widget actual, o desde los cuerpos de los métodos y procs de los widgets derivados.
private comando ?arg arg ...?
Declara un comando privado en el espacio de nombres del widget. Los comandos privados son accesibles solo desde el cuerpo de los métodos y procs del widget actual.
set nombreVar ?valor?
Establece el valor de la variable miembro nombreVar. Si se omite valor, devuelve el valor actual de la variable miembro.
array opción ?arg arg ...?
Administra la matriz de opciones para el widget. La opción opción puede ser uno de los siguientes:
array wName
Devuelve un registro Tcl que contiene todos los pares nombre-valor de las opciones de configuración disponibles para el widget wName. El nombre de la opción es la clave del registro, y el valor de la opción es el valor del registro.
array get wName ?pattern?
Devuelve un registro Tcl que contiene todos los pares nombre-valor de las opciones de configuración que coinciden con pattern para el widget wName. Si se omite pattern, se devuelven todas las opciones.
array set wName registro
Establece las opciones de configuración del widget wName usando los pares nombre-valor del registro proporcionado. El registro puede ser un registro Tcl o una lista de pares nombre-valor.
array configure wName ?arg ...?
Establece o recupera las opciones de configuración del widget wName. Si no se proporcionan argumentos, devuelve un registro que contiene todos los pares nombre-valor de las opciones de configuración del widget. Si se proporcionan argumentos, se establecen las opciones de configuración correspondientes. La lista de argumentos puede incluir pares nombre-valor de opciones y/o una lista de nombres de opciones que se recuperarán.

OBJETO CREACIÓN

Una vez que se ha definido un widget, se pueden crear objetos de ese widget utilizando la siguiente sintaxis:

widgetName objName ?arg arg ...?

Donde widgetName es el nombre del widget que se va a crear, y objName es el nombre del objeto que se va a crear. Los argumentos opcionales arg se pasan al constructor del widget.

Por ejemplo, para crear un objeto llamado myButton del widget Button:

Button myButton -text "Click Me"

Si la creación del objeto es exitosa, el objeto se convierte en un comando Tcl en el contexto actual, y se puede acceder a él usando su nombre objName.

INVOCACIÓN DE MÉTODOS

Los métodos de un objeto se invocan usando la siguiente sintaxis:

objName method ?arg arg ...?

Donde objName es el nombre del objeto, method es el nombre del método a invocar, y arg son los argumentos opcionales para el método.

Por ejemplo, para invocar el método get del objeto myButton:

myButton get

INVOCACIÓN DE PROCS

Los procs definidos dentro de un widget se pueden invocar usando la siguiente sintaxis:

widgetName::proc ?arg arg ...?

Donde widgetName es el nombre del widget que contiene el proc, y proc es el nombre del proc a invocar. Los argumentos arg son los argumentos opcionales para el proc.

Por ejemplo, para invocar el proc myProc definido dentro del widget MyWidget:

MyWidget::myProc arg1 arg2

EJEMPLO

El siguiente ejemplo muestra cómo definir un widget simple llamado Counter:

itcl::widget Counter {
    private variable count 0

    constructor {} {
        # Constructor vacío
    }

    public method increment {} {
        incr count
    }

    public method get {} {
        return $count
    }
}

# Crear un objeto Counter
Counter myCounter

# Incrementar el contador
myCounter increment
myCounter increment

# Obtener el valor actual del contador
myCounter get
# Salida: 2

ENCADENAMIENTO DE

MÉTODOS/PROCS

A veces un widget base tiene un método o proc que es redefinido con el mismo nombre en un widget derivado. Esta es una forma de hacer que el widget derivado maneje las mismas operaciones que el widget base, pero con su propio especializadod comportamiento. Por ejemplo, supongamos que tenemos un widget Toaster que se ve así:

itcl::widget Toaster {
    variable crumbs 0
    method toast {nslices} {
        if {$crumbs > 50} {
            error "== ¡FUEGO! ¡FUEGO! =="
        }
        set crumbs [expr {$crumbs+4*$nslices}]
    }
    method clean {} {
        set crumbs 0
    }
}

Podríamos crear otro widget como SmartToaster que redefine el método "toast". Si queremos acceder al método del widget base, podemos calificarlo con el nombre del widget base, para evitar ambigüedad:

itcl::widget SmartToaster {
    inherit Toaster
    method toast {nslices} {
        if {$crumbs > 40} {
            clean
        }
        return [Toaster::toast $nslices]
    }
}

En lugar de codificar el nombre del widget base de forma fija, podemos usar el comando "chain" así:

itcl::widget SmartToaster {
    inherit Toaster
    method toast {nslices} {
        if {$crumbs > 40} {
            clean
        }
        return [chain $nslices]
    }
}

El comando chain busca en la jerarquía de widgets una implementación de un método o proc ligeramente más genérica (del widget base), y la invoca con los argumentos especificados. Comienza en el contexto del widget actual y busca a través de los widgets base en el orden en que son reportados por el comando "info heritage". Si no se encuentra otra implementación, este comando no hace nada y devuelve la cadena nula.

CARGA AUTOMÁTICA

Las definiciones de widgets no necesitan cargarse explícitamente; pueden cargarse según sea necesario mediante la función de carga automática habitual de Tcl. Cada directorio que contenga archivos de definición de widgets debe tener un archivo "tclIndex" correspondiente. Cada línea en este archivo identifica un procedimiento Tcl o [incr Tcl] una definición de widget y el archivo donde se puede encontrar la definición.

Por ejemplo, supongamos que un directorio contiene las definiciones para los widgets "Toaster" y "SmartToaster". Entonces el archivo "tclIndex" para este directorio se vería así:

# Archivo de índice de carga automática de Tcl, versión 2.0 para [incr Tcl]
# Este archivo es generado por el comando "auto_mkindex"
# y se ejecuta para configurar la información de indexación para uno o
# más comandos. Típicamente cada línea es un comando que
# establece un elemento en el array auto_index, donde el
# nombre del elemento es el nombre de un comando y el valor es
# un script que carga el comando.
set auto_index(::Toaster) "source $dir/Toaster.itcl"
set auto_index(::SmartToaster) "source $dir/SmartToaster.itcl"

El auto_mkindex comando se usa para generar automáticamente archivos "tclIndex".

El cargador automático debe ser informado de este directorio añadiendo el nombre del directorio a la variable "auto_path". Cuando esto está en su lugar, los widgets se cargarán automáticamente según sea necesario cuando se usen en una aplicación.

C PROCEDIMIENTOS

Los procedimientos C pueden integrarse en una [incr Tcl] definición de widget para implementar métodos, procs y el código "config" para variables públicas. Cualquier cuerpo que comience con "@" es tratado como el nombre simbólico de un procedimiento C.

Los nombres simbólicos se establecen registrando procedimientos mediante Itcl_RegisterC(). Esto se hace generalmente en el Tcl_AppInit() procedimiento, que se llama automáticamente cuando el intérprete se inicia. En el siguiente ejemplo, el procedimiento My_FooCmd() se registra con el nombre simbólico "foo". Este procedimiento se puede referenciar en el cuerpo comando como "@foo".

int
Tcl_AppInit(interp)
    Tcl_Interp *interp;     /* Intérprete para la aplicación. */
{
    if (Itcl_Init(interp) == TCL_ERROR) {
        return TCL_ERROR;
    }
    if (Itcl_RegisterC(interp, "foo", My_FooCmd) != TCL_OK) {
        return TCL_ERROR;
    }
}

Los procedimientos C se implementan igual que los comandos Tcl ordinarios. Véase la página del manual CrtCommand para más detalles. Dentro del procedimiento, los miembros de datos del widget se pueden acceder como variables ordinarias usando Tcl_SetVar(), Tcl_GetVar(), Tcl_TraceVar(), etc. Los métodos y procs del widget se pueden ejecutar como comandos ordinarios usando Tcl_Eval(). Se puede construir y probar toda una aplicación. Cuando sea necesario, los cuerpos individuales se pueden implementar con código C para mejorar el rendimiento.
