option(n) [incr Tcl] option(n)

NOMBRE

itcl::option - definir opciones para extendedclass, widget o widgetadaptor

Partes de esta descripción se "tomaron prestadas" de la extensión Tcl [snit], ya que la funcionalidad es en su mayoría idéntica.

ADVERTENCIA!

¡¡Esta es una nueva funcionalidad en [incr Tcl] donde la API todavía puede cambiar!!

SINOPSIS

option optionSpec ?valorPredeterminado?
option optionSpec ?opciones?

DESCRIPCION

El comando option se usa dentro de una definición de [incr Tcl] extendedclass/widget/widgetadaptor para definir opciones.

En la primera forma, define una opción para instancias de este tipo y, opcionalmente, le asigna un valor inicial. El valor inicial por defecto es la cadena vacía si no se especifica ningún valor predeterminado.

Una opción definida de esta manera se dice que está definida localmente. optionSpec es una lista que define el nombre de la opción, el nombre del recurso y el nombre de la clase, por ejemplo:

    option {-fuente fuente Fuente}

El nombre de la opción debe comenzar con un guión y no debe contener letras mayúsculas. El nombre del recurso y el nombre de la clase son opcionales; si no se especifican, el nombre del recurso por defecto es el nombre de la opción, menos el guión, y el nombre de la clase por defecto es el nombre del recurso con la primera letra capitalizada. Por lo tanto, la siguiente instrucción es equivalente al ejemplo anterior:

    option -fuente {Courier 12}

Consulte La base de datos de opciones de Tk para obtener más información sobre los nombres de recursos y clases.

Las opciones normalmente se configuran y recuperan utilizando los métodos estándar de instancia configure y cget; dentro del código de instancia (cuerpos de métodos, etc.), los valores de las opciones están disponibles a través de la matriz options:

    set mi-fuente $itcl_options(-fuente)

En la segunda forma, puede definir manejadores de opciones (por ejemplo, -configuremethod), entonces probablemente debería usar configure y cget para acceder a sus opciones y evitar errores sutiles.

La declaración option puede incluir las siguientes opciones:

-predeterminado valorPredeterminado
Define el valor predeterminado de la opción; de lo contrario, el valor predeterminado de la opción será "".
-sololectura
La opción se maneja como solo lectura: solo se puede configurar usando configure en el momento de la creación, es decir, en el constructor del tipo.
-metodocget nombreMetodo
Cada opción definida localmente puede definir un -metodocget; se llama cuando se recupera el valor de la opción utilizando el método cget. Lo que devuelva el cuerpo del método será el valor de retorno de la llamada a cget.

El método con nombre debe tomar un argumento, el nombre de la opción. Por ejemplo, este código es equivalente a (aunque más lento que) el manejo predeterminado de cget de Itcl:

        option -fuente -metodocget ObtenerOpcion
        method ObtenerOpcion {opcion} {
            return $itcl_options($opcion)
        }

Tenga en cuenta que es posible que cualquier número de opciones comparta un -metodocget.

-variablenomredundante nombreVariable
Eso es muy similar a -metodocget, la única diferencia es que se puede definir una variable donde encontrar el metodocget en tiempo de ejecución.
-metodoconfigurar nombreMetodo
Cada opción definida localmente puede definir un -metodoconfigurar; se llama cuando el valor de la opción se establece utilizando los métodos configure o configurelist. Es responsabilidad del método con nombre guardar el valor de la opción; en otras palabras, el valor no se guardará en la matriz itcl_options() a menos que el método lo guarde allí.

El método con nombre debe tomar dos argumentos, el nombre de la opción y su nuevo valor. Por ejemplo, este código es equivalente a (aunque más lento que) el manejo predeterminado de configure de Itcl:

        option -fuente -metodoconfigurar EstablecerOpcion
        method EstablecerOpcion {opcion valor} {
            set itcl_options($opcion) $valor
        }

Tenga en cuenta que es posible que cualquier número de opciones comparta un único -metodoconfigurar.

-variablenomredundanteconfigurar nombreVariable
Eso es muy similar a -metodoconfigurar, la única diferencia es que se puede definir una variable donde encontrar el metodoconfigurar en tiempo de ejecución.
-metodovalidar nombreMetodo
Cada opción definida localmente puede definir un -metodovalidar; se llama cuando el valor de la opción se establece utilizando los métodos configure o configurelist, justo antes del -metodoconfigurar (si lo hay). Es responsabilidad del método con nombre validar el nuevo valor de la opción y lanzar un error si el valor no es válido.

El método con nombre debe tomar dos argumentos, el nombre de la opción y su nuevo valor. Por ejemplo, este código verifica que el valor de -flag sea un valor booleano válido:

        option -bandera -metodovalidar ComprobarBooleano
        method ComprobarBooleano {opcion valor} {
            if {![string is booleano -estricto $valor]} {
                error "la opción $opcion debe tener un valor booleano."
            }
        }

Tenga en cuenta que es posible que cualquier número de opciones comparta un único -metodovalidar.

-variablenomredundantevalidar nombreVariable
Eso es muy similar a -metodovalidar, la única diferencia es que se puede definir una variable donde encontrar el metodovalidar en tiempo de ejecución.
