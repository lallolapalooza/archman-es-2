NOMBRE

itclvars - variables utilizadas por [incr Tcl]

DESCRIPCIÓN

Las siguientes variables globales son creadas y gestionadas automáticamente por la biblioteca [incr Tcl]. Excepto donde se indica a continuación, estas variables normalmente deben ser tratadas como de solo lectura por el código específico de la aplicación y por los usuarios.

itcl::library
Cuando se crea un intérprete, [incr Tcl] inicializa esta variable para que contenga el nombre de un directorio que contiene la biblioteca del sistema de scripts de [incr Tcl]. El valor inicial de itcl::library se establece a partir de la variable de entorno ITCL_LIBRARY si existe, o de un valor compilado en caso contrario.
itcl::patchLevel
Cuando se crea un intérprete, [incr Tcl] inicializa esta variable para que contenga el nivel de parche actual para [incr Tcl]. Por ejemplo, el valor "2.0p1" indica la versión 2.0 de [incr Tcl] con el primer conjunto de parches aplicados.
itcl::purist
Cuando se crea un intérprete que contiene Tcl/Tk y la instalación de espacios de nombres de [incr Tcl], esta variable controla un modo de "compatibilidad hacia atrás" para el acceso a widgets.

En Tcl/Tk estándar, hay un único grupo de comandos, por lo que el comando de acceso para un widget es el mismo que el nombre de la ventana. Cuando se crea un widget dentro de un espacio de nombres, sin embargo, su comando de acceso se instala en ese espacio de nombres y debe accederse fuera del espacio de nombres utilizando un nombre cualificado. Por ejemplo:

namespace foo {
    namespace bar {
        button .b -text "Testing"
    }
}
foo::bar::.b configure -background red
pack .b

Nótese que el nombre de la ventana ".b" todavía se usa en conjunción con comandos como pack y destroy. Sin embargo, el comando de acceso para el widget (es decir, el nombre que aparece como primer argumento en una línea de comandos) debe ser más específico.

El comando "winfo command" puede usarse para consultar el comando de acceso totalmente cualificado para cualquier widget, por lo que se puede escribir:

[winfo command .b] configure -background red

y esta es una buena práctica al escribir procedimientos de biblioteca. Además, en conjunción con el comando bind, el campo "%q" puede usarse en lugar de "%W" como comando de acceso:

bind Button <Key-Return> {%q flash; %q invoke}

Si bien este comportamiento tiene sentido desde el punto de vista de la encapsulación, causa problemas con las aplicaciones Tcl/Tk existentes. Muchas aplicaciones existentes están escritas con enlaces que usan "%W". Muchos procedimientos de biblioteca asumen que el nombre de la ventana es el comando de acceso.

La variable itcl::purist controla un modo de compatibilidad hacia atrás. Por defecto, esta variable es "0", y el nombre de la ventana se puede usar como comando de acceso en cualquier contexto. Siempre que el procedimiento unknown se encuentre con un nombre de widget, simplemente usará "winfo command" para determinar el nombre de comando apropiado. Si esta variable se establece en "1", este modo de compatibilidad hacia atrás se deshabilita. Esto proporciona una mejor encapsulación, pero usar el nombre de la ventana como comando de acceso puede llevar a errores de "comando inválido".

itcl::version
Cuando se crea un intérprete, [incr Tcl] inicializa esta variable para que contenga el número de versión del formato x.y. Los cambios en x representan cambios importantes con probables incompatibilidades y los cambios en y representan pequeñas mejoras y correcciones de errores que conservan la compatibilidad hacia atrás.
