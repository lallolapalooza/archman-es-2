DESCRIPCIÓ

N

La construcción fundamental en [incr Tcl] es la definición de extendedclass. Cada extendedclass actúa como una plantilla para los objetos reales que se pueden crear. La extendedclass en sí misma es un espacio de nombres que contiene cosas comunes a todos los objetos. Cada objeto tiene su propio paquete único de datos que contiene instancias de las "variables" definidas en la definición de la extendedclass. Cada objeto también tiene una variable incorporada llamada "this", que contiene el nombre del objeto. Las extendedclasses también pueden tener miembros de datos "common" que son compartidos por todos los objetos en una

extendedclass.

Se pueden incluir dos tipos de funciones en la definición de la extendedclass. Los "methods" son funciones que operan en un objeto específico y, por lo tanto, tienen acceso tanto a las "variables" como a los miembros de datos "common". Los "procs" son procedimientos comunes en el espacio de nombres de la extendedclass y solo tienen acceso a los miembros de datos

"common".

Si el cuerpo de cualquier método o proc comienza con "@", se trata como el nombre simbólico de un procedimiento C. De lo contrario, se trata como un script de código Tcl. Vea más abajo los detalles sobre el registro y uso de procedimientos

C.

Una extendedclass solo se puede definir una vez, aunque los cuerpos de los métodos y procs de la extendedclass se pueden definir una y otra vez para la depuración interactiva. Vea los comandos body y configbody para los

detalles.

Cada espacio de nombres puede tener su propia colección de objetos y extendedclasses. La lista de extendedclasses disponibles en el contexto actual se puede consultar con el comando "itcl::find extendedclasses", y la lista de objetos, con el comando "itcl::find ob

jects".

Una extendedclass se puede eliminar con el comando "delete extendedclass". Los objetos individuales se pueden eliminar con el comando "delete o

bje
ct".

MÉTODOS/PROCEDIMIENTOS DE

ENCADENAMIENTO

A veces una extendedclass base tiene un método o procedimiento que es redefinido con el mismo nombre en una extendedclass derivada. Esta es una forma de hacer que la extendedclass derivada maneje las mismas operaciones que la extendedclass base, pero con su propio comportamiento especializado. Por ejemplo, supongamos que tenemos una extendedclass Toaster que se ve

así: 
itcl::extendedclass Toaster {
    variable crumbs 0
    method toast {nslices} {
        if {$crumbs > 50} {
            error "== ¡FUEGO! ¡FUEGO! =="
        }
        set crumbs [expr {$crumbs+4*$nslices}]
    }
    method clean {} {
        set crumbs 0
    }
}

Podríamos crear otra extendedclass como SmartToaster que redefina el método "toast". Si queremos acceder al método de la extendedclass base, podemos calificarlo con el nombre de la extendedclass base, para evitar

ambigüedad: 
itcl::extendedclass SmartToaster {
    inherit Toaster
    method toast {nslices} {
        if {$crumbs > 40} {
            clean
        }
        return [Toaster::toast $nslices]
    }
}

En lugar de codificar el nombre de la extendedclass base, podemos usar el comando "chain" de esta

manera: 
itcl::extendedclass SmartToaster {
    inherit Toaster
    method toast {nslices} {
        if {$crumbs > 40} {
            clean
        }
        return [chain $nslices]
    }
}

El comando chain busca en la jerarquía de extendedclasses una implementación ligeramente más genérica (extendedclass base) de un método o procedimi

ento, y la invoca con los argumentos especificados. Comienza en el contexto de la extendedclass actual y busca en las extendedclasses base en el orden
en que son reportadas por el comando "info heritage". Si no se encuentra otra implementación, este comando no hace nada y devuelve la cadena nula.

CARGA

AUTOMÁTICA

Las definiciones de extendedclass no necesitan ser cargadas explícitamente; pueden ser cargadas según sea necesario por la instalación habitual de carga automática de Tcl. Cada directorio que contenga archivos de definición de extendedclass debe tener un archivo "tclIndex" correspondiente. Cada línea en este archivo identifica un procedimiento Tcl o una definición de extendedclass de [incr Tcl] y el archivo donde se puede encontrar la

definición.

Por ejemplo, supongamos que un directorio contiene las definiciones para las extendedclasses "Toaster" y "SmartToaster". Entonces el archivo "tclIndex" para este directorio se vería

así: 
# Archivo de índice de carga automática de Tcl, versión 2.0 para [incr Tcl]
# Este archivo es generado por el comando "auto_mkindex"
# y se carga para configurar la información
de indexación para uno o # más comandos. Típicamente cada línea es un comando que # establece un elemento en el array auto_index, donde el # nombre del elemento es el nombre d
e un comando y el valor es # un script que carga el comando. set auto_index(::Toaster) "source $dir/Toaster.itcl" set auto_index(::SmartToaster) "source $dir/SmartToaster.itcl"

El comando auto_mkindex se usa para generar automáticamente archivos

"tclIndex".

El cargador automático debe ser informado de este directorio añadiendo el nombre del

directorio a la variable "auto_path". Cuando esto esté configurado, las extendedclas
ses se cargarán automáticamente según sea necesario cuando se usen en una aplicación.

PROCEDIMIENTOS

C

Los procedimientos C se pueden integrar en una definición de extendedclass de [incr Tcl] para implementar métodos, procedimientos y el código "config" para variables públicas. Cualquier cuerpo que comience con "@" se trata como el nombre simbólico de un procedimiento

C.

Los nombres simbólicos se establecen registrando procedimientos mediante Itcl_RegisterC(). Esto se hace normalmente en el procedimiento Tcl_AppInit(), que se llama automáticamente cuando se inicia el intérprete. En el siguiente ejemplo, el procedimiento My_FooCmd() se registra con el nombre simbólico "foo". Este procedimiento se puede referenciar en el comando body como

"@foo". 
int
Tcl_AppInit(interp)
    Tcl_Interp *interp;     /* Intérprete para la aplicación. */
{
    if (Itcl_Init(interp) == TCL_ERROR) {
        return TCL_ERROR;
    }
    if (Itcl_RegisterC(interp, "foo", My_FooCmd) != TCL_OK) {
        return TCL_ERROR;
    }
}

Los procedimientos C se implementan igual que los comandos Tcl ordinarios. Vea la página del manual CrtCommand para más detalles. Dentro del procedimiento, los miembros de datos de la extendedclass se pueden acceder como variables ordinarias usando Tcl_SetVar(), Tcl_GetVar(), Tcl_TraceVar(), etc. Los métodos y procedimientos de la extendedclass se pueden ejecutar como comandos ordinarios usando Tcl_Eval(). [incr Tcl] hace esto posible configurando automáticamente el contexto antes de ejecutar el procedimiento

C.

Este esquema proporciona una ruta de migración natural para el desarrollo de código. Las extendedclasses se pueden des

arrollar rápidamente usando código Tcl para implementar los cuerpos. Se puede construir y probar una aplicación comple
ta. Cuando sea necesario, los cuerpos individuales se pueden implementar con código C para mejorar el rendimiento.
