NOMBRE

iwpmd - servicios de mapeo de puertos para iWARP.

SINOPSIS

iwpmd

DESCRIPCIÓN

El Demonio Mapeador de Puertos de iWARP proporciona un servicio en el espacio de usuario (iwpmd) para que los controladores de iWarp reclamen puertos TCP a través de la interfaz de socket estándar.

El soporte en espacio de kernel para el mapeador de puertos forma parte del módulo iw_cm. El módulo ib_core incluye soporte netlink, que es utilizado por los clientes del mapeador de puertos para intercambiar mensajes con iwpmd. Ambos módulos, iw_cm e ib_core, deben cargarse para que el servicio libiwpm se inicie correctamente.

DETALLES DE IWARP PORT MAPPING

La implementación del Mapeador de Puertos de iWARP se basa en la especificación del mapeador de puertos en el Protocolo de Sockets Directos: http://www.rdmaconsortium.org/home/draft-pinkerton-iwarp-sdp-v1.0.pdf

Los proveedores RDMA de iWARP existentes utilizan la misma dirección IP que la pila TCP/IP nativa al crear conexiones RDMA. Necesitan un mecanismo para reclamar los puertos TCP utilizados para las conexiones RDMA para prevenir colisiones de puertos TCP cuando otras aplicaciones del host usan puertos TCP. El Mapeador de Puertos de iWARP proporciona un mecanismo estándar para lograr esto. Sin este servicio, es posible que la aplicación RDMA se vincule/escuche en el mismo puerto que ya está siendo utilizado por una aplicación host TCP nativa. Si eso sucede, los datos de la conexión TCP entrante pueden pasarse a la pila RDMA con error.

El Gestor de Conexiones de iWARP (cliente del mapeador de puertos) envía al servicio IWPM la dirección IP local y el puerto TCP que ha recibido de la aplicación RDMA, al iniciar una conexión. El servicio IWPM realiza una unión de sockets desde el espacio de usuario para obtener un puerto TCP disponible, llamado puerto mapeado, y lo comunica de vuelta al cliente. En este sentido, el servicio IWPM se utiliza para mapear el puerto TCP, que la aplicación RDMA utiliza a cualquier puerto disponible en el espacio de puertos TCP del host. Los puertos mapeados se utilizan en las conexiones RDMA de iWARP para evitar colisiones con la pila TCP nativa, que es consciente de que estos puertos están ocupados. Cuando se termina una conexión RDMA que utiliza un puerto mapeado, el cliente notifica al servicio IWPM, que luego libera el puerto TCP.

El intercambio de mensajes entre iwpmd y el Gestor de Conexiones de iWARP (entre el espacio de usuario y el espacio de kernel) se implementa utilizando sockets netlink.

OPCIONES

-s, --systemd Habilita la integración con systemd.

SEÑALES

SIGUSR1 forzará un volcado de los mapeos actuales al registro de mensajes del sistema.

SIGTERM/SIGHUP forzará a iwpmd a salir.

ARCHIVOS

/etc/iwpmd.conf
