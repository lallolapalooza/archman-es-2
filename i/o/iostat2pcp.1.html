IOSTAT2PCP(1) Manual de Comandos Generales IOSTAT2PCP(1)

NOMBRE

iostat2pcp - importar datos de iostat y crear un archivo PCP

SINOPSIS

iostat2pcp [-v] [-S inicio] [-t intervalo] [-V version] [-Z zona_horaria] archivo_entrada archivo_salida

DESCRIPCIÓN

iostat2pcp lee un archivo de texto creado con iostat(1) (archivo_entrada) y lo traduce a un archivo Performance Co-Pilot (PCP) con el nombre base archivo_salida. Si archivo_entrada es ``-'' entonces iostat2pcp lee desde la entrada estándar, permitiendo preprocesar fácilmente la salida de iostat(1) con sed(1) o similar.

El archivo PCP resultante puede ser utilizado con todas las herramientas cliente de PCP para graficar subconjuntos de datos usando pmchart(1), realizar reducción y reporte de datos, filtrar con el motor de inferencia de PCP pmie(1), etc.

Se crearán una serie de archivos físicos con el prefijo archivo_salida. Estos son archivo_salida.0 (los datos de rendimiento), archivo_salida.meta (los metadatos que describen los datos de rendimiento) y archivo_salida.index (un índice temporal para mejorar la eficiencia de las operaciones de reproducción para el archivo). Si alguno de estos archivos ya existe, entonces iostat2pcp no los sobrescribirá y saldrá con un mensaje de error.

La primera muestra de salida de iostat(1) contiene un resumen estadístico desde el arranque y es ignorada por iostat2pcp, por lo que el primer conjunto de datos real es el segundo en la salida de iostat(1).

Los mejores resultados se obtienen cuando iostat(1) se ejecutó con su propia bandera -t, de modo que cada muestra de salida tenga un timestamp prefijo. Aún mejor es -t con $S_TIME_FORMAT=ISO establecido en el entorno cuando se ejecuta iostat(1), en cuyo caso el timestamp incluye la zona horaria.

Tenga en cuenta que si $S_TIME_FORMAT=ISO no se usa con la opción -t, entonces iostat(1) puede producir un timestamp controlado por LC_TIME de la configuración regional que está en un formato que iostat2pcp no puede analizar. Los formatos para el timestamp que iostat2pcp acepta se ilustran con estos ejemplos:

2013-07-06T21:34:39+1000
(para $S_TIME_FORMAT=ISO).
2013-07-06 21:34:39
(para algunas de las configuraciones regionales europeas, p. ej., de_AT, de_BE, de_LU y en_DK.utf8).
06/07/13 21:34:39
(para todas las configuraciones de $LC_TIME para configuraciones regionales inglesas fuera de América del Norte, p. ej., en_AU, en_GB, en_IE, en_NZ, en_SG y en_ZA, y todas las configuraciones regionales españolas, p. ej., es_ES, es_MX y es_AR).

En particular, tenga en cuenta que algunas configuraciones regionales comunes de América del Norte para $LC_TIME no funcionarán con iostat2pcp (a saber, en_US, POSIX y C) porque utilizan el formato MM/DD que puede ser convertido incorrectamente con el formato DD/MM asumido. Esta es otra razón para recomendar el establecimiento de $S_TIME_FORMAT=ISO.

Si no hay timestamps en el flujo de entrada, iostat2pcp intentará deducir el intervalo de muestreo si se encuentran datos básicos del disco (opción -d para iostat(1)). Si esto falla, se puede usar la opción -t para especificar el intervalo de muestreo en segundos. Esta opción se ignora si se encuentran timestamps en el flujo de entrada.

La opción -S puede usarse para especificar la hora de inicio de la primera muestra real en archivo_entrada, donde inicio debe tener el formato HH:MM:SS. Esta opción se ignora si se encuentran timestamps en el flujo de entrada.

La opción -V especifica la versión para el archivo PCP de salida. Por defecto se utiliza la versión de archivo $PCP_ARCHIVE_VERSION (establecida en 3 en las versiones actuales de PCP), y los únicos valores actualmente soportados para version son 2 o 3.

La opción -Z puede usarse para especificar una zona horaria. Debe tener el formato +HHMM (para horas y minutos al Este de UTC) o -HHMM (para horas y minutos al Oeste de UTC). Tenga en cuenta en particular que ni el formato zoneinfo (también conocido como Olson), p. ej., Europe/Paris, ni el formato TZ de Posix, p. ej., EST+5, están permitidos para la opción -Z. Esta opción se ignora si se encuentran timestamps ISO en el flujo de entrada. Si la zona horaria no se especifica y no se puede deducir, se establece por defecto en ``UTC''.

Se genera alguna salida diagnóstica adicional con la opción -v.

iostat2pcp es un script de Perl que utiliza el envoltorio Perl PCP::LogImport sobre la biblioteca PCP libpcp_import, y como tal podría usarse como ejemplo para desarrollar nuevas herramientas para importar otros tipos de datos de rendimiento y crear archivos PCP.

OPCIONES

Las opciones de línea de comandos disponibles son:

-S inicio
Especifica la hora de inicio para la primera muestra.
-t intervalo
Especifica el intervalo de muestreo en segundos.
-v
Imprime salida detallada.
-Z zona_horaria
Especifica la zona horaria a utilizar, ver arriba.

SALVEDADES

iostat2pcp requiere que archivo_entrada haya sido creado por la versión de iostat(1) de http://freshmeat.net/projects/sysstat.

iostat2pcp maneja los formatos de reporte -c (CPU), -d (Disco), -x (Disco eXtendido) y -p (Partición) (incluyendo sus variantes -k, -m, -z y ALL), pero no admite el formato de reporte -n (Network Filesystem) de iostat(1); esto es una limitación bajo demanda más que una limitación técnica.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivo y directorio utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).
