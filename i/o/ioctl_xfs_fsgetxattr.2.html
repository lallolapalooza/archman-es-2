ioctl_xfs_fsgetxattr(2)

Paquete: xfsprogs

Licencias: GPL-2.0-only, LGPL-2.1-only

IOCTL-XFS-FSGETXATTR(2) Manual de Llamadas al Sistema IOCTL-XFS-FSGETXATTR(2)

NOMBRE

ioctl_xfs_fsgetxattr - consultar información de un archivo abierto

SINOPSIS

#include <linux/fs.h>

int ioctl(int fd, XFS_IOC_FSGETXATTR, struct fsxattr *arg);
int ioctl(int fd, XFS_IOC_FSGETXATTRA, struct fsxattr *arg);
int ioctl(int fd, XFS_IOC_FSSETXATTR, struct fsxattr *arg);

DESCRIPCIÓN

Consultar o establecer atributos adicionales asociados con archivos en varios sistemas de archivos. Los atributos se transmiten en una estructura de la forma:


struct fsxattr {
	__u32         fsx_xflags;
	__u32         fsx_extsize;
	__u32         fsx_nextents;
	__u32         fsx_projid;
	__u32         fsx_cowextsize;
	unsigned char fsx_pad[8];
};

fsx_xflags son banderas extendidas que se aplican a este archivo. Consulte la sección BANDERAS DE INODO XFS más abajo para obtener más información.

fsx_extsize es el tamaño de asignación de extensión preferido para bloques de datos asignados a este archivo, en unidades de bytes. Si este valor es cero, el sistema de archivos elegirá una opción predeterminada, que actualmente es cero. Si XFS_IOC_FSSETXATTR se llama con XFS_XFLAG_EXTSIZE establecido en fsx_xflags y este campo establecido en cero, la XFLAG también será borrada.

fsx_nextents es el número de extensiones de datos en este archivo. Si XFS_IOC_FSGETXATTRA se utilizó, entonces este es el número de extensiones de atributos extendidos en el archivo.

fsx_projid es el ID de proyecto de este archivo.

fsx_cowextsize es el tamaño de asignación de extensión preferido para operaciones de copia en escritura que tienen como destino este archivo, en unidades de bytes. Si este campo es cero, el sistema de archivos elegirá una opción predeterminada, que es actualmente 32 bloques del sistema de archivos. Si XFS_IOC_FSSETXATTR se llama con XFS_XFLAG_COWEXTSIZE establecido en fsx_xflags y este campo establecido en cero, la XFLAG también será borrada.

fsx_pad debe estar a cero.

BANDERAS DE INODO XFS

Este campo puede ser una combinación de lo siguiente:

XFS_XFLAG_REALTIME
El archivo es un archivo de tiempo real. Este bit solo puede cambiarse en un archivo cuando no tiene extensiones asignadas.
XFS_XFLAG_PREALLOC
El archivo tiene espacio preasignado.
XFS_XFLAG_IMMUTABLE
El archivo es inmutable: no puede ser modificado, eliminado o renombrado, no se puede crear ningún enlace a este archivo y no se pueden escribir datos en el archivo. Solo el superusuario o un proceso que posea la capacidad CAP_LINUX_IMMUTABLE puede establecer o borrar esta bandera. Si esta bandera está establecida antes de una XFS_IOC_FSSETXATTR llamada y no sería borrada por la llamada, entonces no se pueden cambiar otros atributos y se devolverá EPERM .
XFS_XFLAG_APPEND
El archivo es de solo agregado: solo puede abrirse en modo de agregado para escritura. Para directorios, esto significa que los archivos no pueden ser desvinculados de este directorio. Solo el superusuario o un proceso que posea la capacidad CAP_LINUX_IMMUTABLE puede establecer o borrar esta bandera.
XFS_XFLAG_SYNC
Todas las escrituras en el archivo son síncronas. Si se establece en un directorio y el /proc/sys/fs/xfs/inherit_sync parámetro ajustable está establecido a 1, los nuevos archivos y subdirectorios creados en el directorio también tendrán la bandera establecida.
XFS_XFLAG_NOATIME
Cuando se accede al archivo, su registro atime no se modifica. Si se establece en un directorio y el /proc/sys/fs/xfs/inherit_noatime parámetro ajustable está establecido a 1, los nuevos archivos y subdirectorios creados en el directorio también tendrán la bandera establecida.
XFS_XFLAG_NODUMP
El archivo debe ser omitido por las utilidades de copia de seguridad. Si se establece en un directorio y el /proc/sys/fs/xfs/inherit_nodump parámetro ajustable está establecido a 1, los nuevos archivos y subdirectorios creados en el directorio también tendrán la bandera establecida.
XFS_XFLAG_RTINHERIT
Bit de herencia de tiempo real: los nuevos archivos creados en el directorio serán creados automáticamente como archivos de tiempo real. Si se establece en un directorio, los nuevos subdirectorios creados en el directorio también tendrán la bandera de herencia establecida.
XFS_XFLAG_PROJINHERIT
Bit de herencia de proyecto: los nuevos archivos y directorios creados en este directorio heredarán el ID de proyecto de este directorio. Si se establece en un directorio, los nuevos subdirectorios creados en el directorio también tendrán la bandera de herencia establecida.
XFS_XFLAG_NOSYMLINKS
Desactiva la creación de enlaces simbólicos en el directorio. Esta bandera solo puede establecerse en un directorio. Si se establece en un directorio y el /proc/sys/fs/xfs/inherit_nosymlinks parámetro ajustable está establecido a 1, los nuevos archivos y subdirectorios creados en el directorio también tendrán la bandera establecida.
XFS_XFLAG_EXTSIZE
Bit de tamaño de extensión: si se establece un valor de tamaño de extensión básico en el archivo, entonces el asignador asignará en múltiplos del tamaño establecido para este archivo (véase fsx_extsize más abajo). El tamaño de extensión solo puede cambiarse en un archivo cuando no tiene extensiones asignadas.
XFS_XFLAG_EXTSZINHERIT
Bit de herencia de tamaño de extensión: los nuevos archivos y directorios creados en el directorio heredarán el valor de tamaño de extensión (véase fsx_extsize más abajo) del directorio principal. Los nuevos subdirectorios creados en el directorio heredarán el bit de herencia del tamaño de extensión.
XFS_XFLAG_NODEFRAG
Bit de no desfragmentar archivo: el archivo debe ser omitido durante una operación de desfragmentación. Si se establece en un directorio y el /proc/sys/fs/xfs/inherit_nodefrag parámetro ajustable está establecido a 1, los nuevos archivos y subdirectorios creados en el directorio también tendrán la bandera establecida.
XFS_XFLAG_FILESTREAM
Bit de asignador de flujo de archivos: permite a un directorio reservar un grupo de asignación para uso exclusivo por los archivos creados dentro de ese directorio. Los archivos que se escriben en otros directorios no usarán el mismo grupo de asignación y por lo tanto los archivos dentro de diferentes directorios no intercalarán extensiones en el disco. La reserva solo está activa mientras se crean y escriben archivos en el directorio. Si se establece en un directorio, los nuevos archivos y subdirectorios creados en el directorio también tendrán la bandera establecida.
XFS_XFLAG_DAX
Si el sistema de archivos reside en memoria persistente de acceso directo, las lecturas y escrituras en este archivo irán directamente a la memoria persistente, evitando la caché de páginas. Si se establece en un directorio, los nuevos archivos y subdirectorios creados en el directorio también tendrán la bandera establecida. Esta bandera no puede establecerse en sistemas de archivos que tengan la función de reflink habilitada.
XFS_XFLAG_COWEXTSIZE
Bit de tamaño de extensión de copia en escritura: si se establece un valor de tamaño de extensión de CoW en el archivo, el asignador asignará extensiones para preparar una operación de copia en escritura en múltiplos del tamaño establecido para este archivo (véase fsx_cowextsize más abajo). Si se establece en un directorio, los nuevos archivos y subdirectorios creados en el directorio tendrán tanto la bandera como el valor de tamaño de extensión de CoW establecidos.
XFS_XFLAG_HASATTR
El archivo tiene atributos extendidos asociados con él.

VALOR DE RETORNO

En caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

Los códigos de error pueden ser uno de los siguientes, aunque no se limitan a ellos:

EACCESS
El llamante no tiene acceso suficiente para cambiar los atributos.
EFAULT
El kernel no pudo copiar al buffer del espacio de usuario.
EFSBADCRC
Falló la validación de la suma de verificación de metadatos al realizar la consulta.
EFSCORRUPTED
Se encontró corrupción de metadatos al realizar la consulta.
EINVAL
Uno de los argumentos no era válido.
EIO
Se encontró un error de E/S al realizar la consulta.
ENOMEM
No había suficiente memoria para realizar la consulta.
EPERM
El llamante no tenía permiso para cambiar los atributos.

CONFORME A

Esta API está implementada por los sistemas de archivos ext4, xfs, btrfs y f2fs en el kernel de Linux. Es posible que los sistemas de archivos distintos de xfs no comprendan todos los campos.
