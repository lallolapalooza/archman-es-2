NOMBRE

io_uring_prep_recv - preparar una solicitud de recepción

SINOPSIS

#include <liburing.h>
void io_uring_prep_recv(struct io_uring_sqe *sqe,
                        int sockfd,
                        void *buf,
                        size_t len,
                        int flags);
void io_uring_prep_recv_multishot(struct io_uring_sqe *sqe,
                                  int sockfd,
                                  void *buf,
                                  size_t len,
                                  int flags);

DESCRIPCIÓN

La función io_uring_prep_recv(3) prepara una solicitud de recepción. La entrada de la cola de envío sqe se configura para usar el descriptor de archivo sockfd para comenzar a recibir los datos en el búfer de destino buf de tamaño len y con los indicadores modificadores flags.

Esta función prepara una solicitud asíncrona de recv(2). Consulte esa página del manual para obtener detalles sobre los argumentos especificados a esta utilidad de preparación.

La versión multishot permite a la aplicación emitir una única solicitud de recepción, que publica repetidamente un CQE cuando hay datos disponibles. Requiere que la longitud sea 0, que se establezca la bandera IOSQE_BUFFER_SELECT y que no se establezca la bandera MSG_WAITALL. Por lo tanto, cada CQE tomará un búfer de un grupo de búferes proporcionado para recibir. La aplicación debe verificar las banderas de cada CQE, independientemente de su resultado. Si un CQE publicado no tiene la bandera IORING_CQE_F_MORE establecida, entonces la recepción multishot ha terminado y la aplicación debe emitir una nueva solicitud si aún desea recibir datos del socket. Las variantes multishot están disponibles desde el kernel 6.0.

Después de llamar a esta función, se pueden establecer indicadores modificadores internos adicionales de io_uring en el campo ioprio del SQE. Se admiten los siguientes indicadores:

IORING_RECVSEND_POLL_FIRST
Si está establecida, io_uring asumirá que el socket está actualmente vacío e intentar recibir datos no tendrá éxito. Para este caso, io_uring activará una espera interna (poll) y activará una recepción de datos cuando el socket tenga datos para ser leídos. Este intento de recepción inicial puede ser ineficiente en el caso en que se espera que el socket esté vacío; establecer este indicador evitará el intento de recepción inicial y pasará directamente a activar la espera. Si la espera indica que los datos están listos para ser recibidos, la operación procederá.

Se puede usar con la bandera CQE IORING_CQE_F_SOCK_NONEMPTY, que io_uring establecerá en los CQE después de una operación de recv(2) o recvmsg(2). Si está establecida, el socket todavía tenía datos para leer después de que la operación se completara. Ambas banderas están disponibles desde 5.19.

IORING_RECVSEND_BUNDLE
Si está establecido y se utilizan búferes proporcionados con IOSQE_BUFFER_SELECT , la operación de recepción intentará llenar múltiples búferes en lugar de simplemente seleccionar un único búfer para llenar. Para recibir múltiples búferes en una sola recepción, el ID del grupo de búferes establecido en el SQE debe ser del tipo de anillo proporcionado. Si está establecido, el campo res del CQE indica el número total de bytes recibidos, y el ID del búfer devuelto en el campo flags del CQE indica el primer búfer en la operación de recepción. La aplicación debe procesar el búfer ID inicial indicado y hasta que se hayan visto todos los bytes res para saber cuál es el último búfer en la operación de recepción. Los búferes consumidos serán contiguos desde el búfer inicial, en el orden en que aparecen en el anillo de búferes. El struct CQE no contiene la posición del búfer en el anillo de búferes, por lo tanto, para identificar los búferes contenidos por el paquete, se recomienda mantener el índice principal (head index) en caché por anillo de búferes. Este índice uint16_t representa la posición del próximo búfer a consumir dentro del anillo. Tras la finalización de una operación de recepción, el índice principal en caché debe incrementarse en consecuencia. Recibir en paquetes puede mejorar el rendimiento cuando hay más de un fragmento de datos disponible para recibir, al eliminar viajes de ida y vuelta redundantes a través de la pila de red. Los paquetes de recepción pueden ser utilizados tanto por operaciones de recepción de un solo disparo como multishot. Tenga en cuenta que, internamente, los paquetes dependen de que la pila de red devuelva cuántos datos quedan en el socket después de la recepción inicial. Esto significa que la recepción inicial puede contener menos paquetes de los que están disponibles, y las recepciones posteriores contienen más paquetes. Disponible desde 6.10.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res del CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los valores posibles. Tenga en cuenta que donde las llamadas al sistema síncronas devolverán -1 en caso de error y establecerán errno al valor de error real, io_uring nunca usa errno. En su lugar, devuelve el errno negado directamente en el campo res del CQE.
