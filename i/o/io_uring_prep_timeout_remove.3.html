NOMBRE

io_uring_prep_timeout_update - prepara una solicitud para actualizar un timeout existente

SINOPSIS

#include <liburing.h>
void io_uring_prep_timeout_update(struct io_uring_sqe *sqe,
                                  struct __kernel_timespec *ts,
                                  __u64 user_data,
                                  unsigned flags);
void io_uring_prep_timeout_remove(struct io_uring_sqe *sqe,
                                  __u64 user_data,
                                  unsigned flags);

DESCRIPCIÓN

Estas funciones modifican o cancelan una solicitud de timeout existente. La entrada de la cola de envío sqe se configura para armar una actualización o eliminación de timeout especificada por user_data y con flags modificadores dados por flags. Adicionalmente, la solicitud de actualización incluye una estructura ts, que contiene nueva información de timeout.

Para una solicitud de actualización, el miembro flags puede contener una máscara de bits de los siguientes valores:

IORING_TIMEOUT_ABS
El valor especificado en ts es un valor absoluto en lugar de uno relativo.
IORING_TIMEOUT_BOOTTIME
Se debe usar la fuente de reloj boottime.
IORING_TIMEOUT_REALTIME
Se debe usar la fuente de reloj realtime.
IORING_TIMEOUT_ETIME_SUCCESS
Considerar un timeout caducado como un éxito en términos de la finalización publicada. Normalmente, un timeout que se dispara devolvería un res de CQE de -ETIME.

El comando de eliminación de timeout no acepta actualmente ningún flag.

VALOR DE RETORNO

Ninguno

ERRORES

Estos son los errores que se informan en el campo res del CQE. En caso de éxito, se devuelve 0.

-ENOENT
No se pudo encontrar el timeout identificado por user_data. Puede ser inválido o haber caducado antes de que se procesara la solicitud de actualización o eliminación.
-EALREADY
El timeout identificado por user_data ya está caducando y no puede ser cancelado.
-EINVAL
Uno de los campos establecidos en el SQE era inválido. Por ejemplo, se dieron dos fuentes de reloj, o los segundos y nanosegundos de timeout especificados eran < 0.
-EFAULT
io_uring no pudo acceder a los datos especificados por ts.

NOTAS

Al igual que con cualquier solicitud que pasa datos en una struct, esos datos deben permanecer válidos hasta que la solicitud se haya enviado correctamente. No es necesario que permanezcan válidos hasta la finalización. Una vez que se ha enviado una solicitud, el estado dentro del kernel es estable. Los kernels muy tempranos (5.4 y anteriores) requerían que el estado fuera estable hasta que ocurriera la finalización. Las aplicaciones pueden probar este comportamiento inspeccionando el flag IORING_FEAT_SUBMIT_STABLE devuelto por io_uring_queue_init_params(3).
