NOMBRE

io_uring_prep_renameat - preparar una solicitud de renombrado

SINOPSIS

#include <fcntl.h>
#include <stdio.h>
#include <liburing.h>
void io_uring_prep_renameat(struct io_uring_sqe *sqe,
                            int olddirfd,
                            const char *oldpath,
                            int newdirfd,
                            const char *newpath,
                            unsigned int flags);
void io_uring_prep_rename(struct io_uring_sqe *sqe,
                          const char *oldpath,
                          const char *newpath);

DESCRIPCIÓN

La función io_uring_prep_renameat(3) prepara una solicitud de renombrado en un directorio. La entrada de la cola de envío sqe se configura para usar el descriptor de archivo del directorio antiguo especificado por olddirfd y la ruta antigua especificada por oldpath, con el descriptor de archivo del directorio nuevo especificado por newdirfd y la ruta nueva especificada por newpath, y utilizando las banderas especificadas en flags.

La función io_uring_prep_rename(3) prepara una solicitud de renombrado. La entrada de la cola de envío sqe se configura para usar la ruta antigua especificada por oldpath con la ruta nueva especificada por newpath, ambas relativas al directorio de trabajo actual y utilizando las banderas especificadas en flags.

Estas funciones preparan una solicitud asíncrona renameat2(2) o rename(2). Si flags es cero, esta llamada es similar a la llamada del sistema renameat(2). Consulte esas páginas del manual para obtener detalles.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res de la CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los valores posibles. Tenga en cuenta que, mientras que las llamadas al sistema síncronas devolverán -1 en caso de error y establecerán errno al valor real del error, io_uring nunca utiliza errno. En su lugar, devuelve el errno negado directamente en el campo res de la CQE.

NOTAS

Como con cualquier solicitud que pasa datos en una estructura, esos datos deben permanecer válidos hasta que la solicitud se haya enviado con éxito. No es necesario que permanezcan válidos hasta la finalización. Una vez que se ha enviado una solicitud, el estado en el kernel es estable. Los kernels muy tempranos (5.4 y anteriores) requerían que el estado fuera estable hasta que ocurriera la finalización. Las aplicaciones pueden probar este comportamiento inspeccionando el flag IORING_FEAT_SUBMIT_STABLE devuelto por io_uring_queue_init_params(3).
