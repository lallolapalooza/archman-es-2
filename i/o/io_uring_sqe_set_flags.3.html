NOMBRE

io_uring_sqe_set_flags - establece banderas para la entrada de la cola de envío

SINOPSIS

#include <liburing.h>
void io_uring_sqe_set_flags(struct io_uring_sqe *sqe,
                            unsigned flags);

DESCRIPCIÓN

La función io_uring_sqe_set_flags(3) permite al llamador cambiar el comportamiento de la entrada de la cola de envío especificando banderas. Permite establecer las flags pertenecientes al parámetro de entrada de la cola de envío sqe.

flags es una máscara de bits de 0 o más de los siguientes valores combinados con OR:

IOSQE_FIXED_FILE
El descriptor de archivo en el SQE se refiere al índice de un archivo registrado previamente o a un descriptor de archivo directo, no a un descriptor de archivo normal.
IOSQE_ASYNC
La operación normal para io_uring es intentar emitir un sqe de forma no bloqueante primero, y si falla, ejecutarlo de forma asíncrona. Para soportar la operación superpuesta más eficiente de solicitudes que la aplicación sabe/asume que siempre (o la mayoría de las veces) bloquearán, la aplicación puede solicitar que un sqe se emita de forma asíncrona desde el principio. Tenga en cuenta que esta bandera hace que el SQE se descargue inmediatamente a un hilo auxiliar asíncrono sin ningún intento inicial no bloqueante. Esto puede ser menos eficiente y no debe usarse liberalmente ni sin comprender las compensaciones de rendimiento y eficiencia.
IOSQE_IO_LINK
Cuando se especifica esta bandera, el SQE forma un enlace con el siguiente SQE en el anillo de envío. El siguiente SQE no se iniciará antes de que se complete la solicitud anterior. Esto, en efecto, forma una cadena de SQEs, que puede ser arbitrariamente larga. La cola de la cadena está denotada por el primer SQE que no tiene esta bandera establecida. Las cadenas no son compatibles entre límites de envío. Incluso si el último SQE en un envío tiene esta bandera establecida, seguirá terminando la cadena actual. Esta bandera no tiene ningún efecto en envíos de SQE anteriores, ni impacta en SQEs que están fuera de la cola de la cadena. Esto significa que múltiples cadenas pueden ejecutarse en paralelo, o cadenas y SQEs individuales. Solo los miembros dentro de la cadena están serializados. Una cadena de SQEs se romperá si alguna solicitud en esa cadena termina en error.
IOSQE_IO_HARDLINK
Similar a IOSQE_IO_LINK, excepto que los enlaces no se rompen si ocurre un error o un resultado inesperado.
IOSQE_IO_DRAIN
Cuando se especifica esta bandera, el SQE no se iniciará antes de que se hayan completado los SQEs enviados previamente, y los nuevos SQEs no se iniciarán antes de que se complete este.
IOSQE_CQE_SKIP_SUCCESS
Solicita que no se genere ningún CQE para esta solicitud, si se completa con éxito. Esto puede ser útil en casos en los que la aplicación no necesita saber cuándo se completó una solicitud específica, si se completó con éxito.
IOSQE_BUFFER_SELECT
Si está configurada, y si los tipos de solicitud lo admiten, selecciona un búfer de IO del grupo de búferes indicado. Esto se puede usar con solicitudes que leen o reciben datos de un archivo o socket, donde la selección del búfer se pospone hasta que el kernel esté listo para transferir datos, en lugar de cuando se envía la IO originalmente. La aplicación también debe establecer el campo buf_group en el SQE, indicando de qué grupo de búferes previamente registrado seleccionar un búfer.
