ioperm(2) Manual de llamadas al sistema ioperm(2)

NOMBRE

ioperm - establece permisos de entrada/salida de puertos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/io.h>
int ioperm(unsigned long from, unsigned long num, int turn_on);

DESCRIPCIÓN

ioperm() establece los bits de permiso de acceso a puertos para el hilo que llama para num bits comenzando desde la dirección de puerto from. Si turn_on es distinto de cero, entonces se habilita el permiso para los bits especificados; de lo contrario, se deshabilita. Si turn_on es distinto de cero, el hilo que llama debe tener privilegios (CAP_SYS_RAWIO).

Antes de Linux 2.6.8, solo los primeros 0x3ff puertos de E/S podían ser especificados de esta manera. Para más puertos, se tenía que usar la llamada al sistema iopl(2) (con un argumento level de 3). Desde Linux 2.6.8, se pueden especificar 65.536 puertos de E/S.

Los permisos son heredados por el hijo creado por fork(2) (pero ver HISTORIA). Los permisos se conservan a través de execve(2); esto es útil para otorgar permisos de acceso a puertos a programas sin privilegios.

Esta llamada es principalmente para la arquitectura i386. En muchas otras arquitecturas no existe o siempre devolverá un error.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EINVAL
Valores inválidos para from o num.
EIO
(en PowerPC) Esta llamada no es compatible.
ENOMEM
Memoria agotada.
EPERM
El hilo que llama tiene privilegios insuficientes.

VERSIÓNES

glibc tiene un prototipo ioperm() tanto en <sys/io.h> como en <sys/perm.h>. Evita este último, solo está disponible en i386.

ESTÁNDARES

Linux.

HISTORIA

Antes de Linux 2.4, los permisos no eran heredados por el hijo creado por fork(2).

NOTAS

El archivo /proc/ioports muestra los puertos de E/S que están actualmente asignados en el sistema.

VER TAMBIÉN

iopl(2), outb(2), capabilities(7)
