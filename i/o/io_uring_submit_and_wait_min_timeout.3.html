NOMBRE

io_uring_submit_and_wait_min_timeout - enviar peticiones a la cola de envío y esperar por la finalización con un tiempo de espera mínimo de lote y normal

SINOPSIS

#include <liburing.h>
int io_uring_submit_and_wait_min_timeout(struct io_uring *ring,
                                         struct io_uring_cqe **cqe_ptr,
                                         unsigned wait_nr,
                                         struct __kernel_timespec *ts,
                                         unsigned int min_wait_usec,
                                         sigset_t *sigmask);

DESCRIPCIÓN

La función io_uring_submit_and_wait_min_timeout(3) envía las siguientes peticiones de la cola de envío que pertenecen al ring y espera por wait_nr eventos de finalización, o hasta que el tiempo de espera ts expire. Los eventos de finalización se almacenan en el array cqe_ptr. Si es distinto de cero, min_wait_usec denota un tiempo de espera para el lote de wait_nr.

El sigmask especifica el conjunto de señales a bloquear. Si está configurado, es equivalente a ejecutar atómicamente las siguientes llamadas:


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ret = io_uring_submit_and_wait_min_timeout(ring, cqe, wait_nr, ts, min_wait, NULL);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

Funciona como io_uring_submit_and_wait_timeout(3) con la particularidad de que aplica un tiempo de espera mínimo para el tamaño de lote solicitado de peticiones a esperar. Mientras que io_uring_submit_and_wait_timeout(3) espera tanto como ts especifica, o hasta que se hayan recibido wait_nr finalizaciones de peticiones, si min_wait_usec está configurado, este es el tiempo de espera para el número de wait_nr de peticiones. Si el número solicitado de finalizaciones se ha recibido dentro de min_wait_usec microsegundos, la función retorna exitosamente. Si no es así, una vez que ha transcurrido el tiempo de min_wait_usec, el control se devuelve si se ha publicado alguna finalización. Si no se ha publicado ninguna finalización, el kernel cambia a una espera normal de hasta la cantidad de tiempo especificada por ts, restando el tiempo ya transcurrido. Si se publican finalizaciones después de que esto ocurra, el control se devuelve inmediatamente a la aplicación.

Esto difiere de la espera con tiempo de espera normal en que la espera continúa después del tiempo de espera inicial, si y solo si no se han publicado finalizaciones. Está pensado para ser utilizado para optimizar la espera en lote de peticiones, donde la aplicación asigna un presupuesto de min_wait_usec microsegundos para recibir wait_nr finalizaciones, pero si no se recibe ninguna, la espera puede continuar sin incurrir en cambios de contexto adicionales o transiciones adicionales entre kernel/usuario.

Puede ser utilizado con cualquier anillo, siempre que el kernel lo soporte. El soporte se indica comprobando la bandera de característica IORING_FEAT_MIN_TIMEOUT después de que el anillo haya sido configurado. Idealmente se usa con un anillo configurado con IORING_SETUP_SINGLE_ISSUER|IORING_SETUP_DEFER_TASKRUN ya que esto reducirá en gran medida el número de cambios de contexto que una aplicación verá al esperar múltiples peticiones.

Disponible desde la versión 6.12.

VALOR DE RETORNO

En caso de éxito, io_uring_submit_and_wait_min_timeout(3) devuelve el número de entradas de la cola de envío enviadas. En caso de fallo, devuelve -errno. Si el kernel no soporta esta funcionalidad, se devolverá -EINVAL. Ver la nota sobre la bandera de característica. El caso de fallo más común es no recibir una finalización dentro del tiempo de espera especificado, en cuyo caso se devuelve -ETIME.
