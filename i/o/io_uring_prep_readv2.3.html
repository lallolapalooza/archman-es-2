NOMBRE

io_uring_prep_readv2 - prepara una solicitud de lectura de E/S vectorial con indicadores

SINOPSIS

#include <sys/uio.h>
#include <liburing.h>
void io_uring_prep_readv2(struct io_uring_sqe *sqe,
                          int fd,
                          const struct iovec *iovecs,
                          unsigned nr_vecs,
                          __u64 offset,
                          int flags);

DESCRIPCIÓN

La función io_uring_prep_readv2(3) prepara una solicitud de lectura de E/S vectorial. La entrada de la cola de envío sqe se configura para usar el descriptor de archivo fd para comenzar a leer nr_vecs en la matriz iovecs en la posición offset especificada. El comportamiento de la función se puede controlar con el parámetro flags.

Los valores admitidos para flags son:

RWF_HIPRI
Solicitud de alta prioridad, sondear si es posible
RWF_DSYNC
O_DSYNC por E/S
RWF_SYNC
O_SYNC por E/S
RWF_NOWAIT
por E/S, devolver -EAGAIN si la operación se bloquearía
RWF_APPEND
O_APPEND por E/S

En archivos que admiten búsqueda, si el desplazamiento se establece en -1, la operación de lectura comienza en el desplazamiento del archivo, y el desplazamiento del archivo se incrementa en el número de bytes leídos. Consulte read(2) para obtener más detalles. Tenga en cuenta que para una API asíncrona, leer y actualizar el desplazamiento actual del archivo puede generar un comportamiento impredecible, a menos que el acceso al archivo esté serializado. No se recomienda usar esta función si es posible proporcionar el desplazamiento de E/S deseado desde la aplicación o la biblioteca.

En archivos que no son capaces de búsqueda, el desplazamiento debe ser 0 o -1.

Después de preparar la lectura, se puede enviar con una de las funciones de envío.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res del CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los posibles valores. Tenga en cuenta que mientras que las llamadas al sistema síncronas devolverán -1 en caso de error y establecerán errno al valor de error real, io_uring nunca utiliza errno. En su lugar, devuelve el errno negado directamente en el campo res del CQE.

NOTAS

A menos que una aplicación necesite explícitamente pasar más de un iovec, es más eficiente usar io_uring_prep_read(3) en lugar de esta función, ya que no hay que mantener ningún estado para una solicitud de E/S no vectorial. Al igual que con cualquier solicitud que pase datos en una estructura, esos datos deben permanecer válidos hasta que la solicitud se haya enviado correctamente. No es necesario que permanezcan válidos hasta la finalización. Una vez que se ha enviado una solicitud, el estado dentro del kernel es estable. Los kernels muy antiguos (5.4 y anteriores) requerían que el estado fuera estable hasta que ocurriera la finalización. Las aplicaciones pueden probar este comportamiento inspeccionando el indicador IORING_FEAT_SUBMIT_STABLE devuelto por io_uring_queue_init_params(3).
