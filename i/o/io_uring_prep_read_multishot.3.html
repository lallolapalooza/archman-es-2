NOMBRE

io_uring_prep_read_multishot - prepara una solicitud de lectura multishot I/O

SINOPSIS

#include <liburing.h>
void io_uring_prep_read_multishot(struct io_uring_sqe *sqe,
                                  int fd,
                                  unsigned nbytes,
                                  __u64 offset,
                                  int buf_group);

DESCRIPCIÓN

El ayudante io_uring_prep_read_multishot(3) prepara una solicitud de lectura multishot IO. La entrada de la cola de envío (submission queue entry) sqe se configura para usar el descriptor de archivo fd para comenzar a leer en un búfer del grupo de búferes proporcionado con el ID buf_group en el offset especificado.

nbytes debe establecerse en cero, ya que el tamaño leído será el tamaño de los búferes en la E/S del grupo de búferes indicado.

En archivos que no son capaces de buscar (seek), el offset debe ser 0 o -1.

Si nbytes excede el tamaño de los búferes en el grupo de búferes especificado, o si nbytes es 0 , entonces se usará el tamaño del búfer en ese grupo para la transferencia.

Una solicitud de lectura multishot activará repetidamente un evento de finalización cada vez que haya datos disponibles para leer del archivo. Debido a eso, este tipo de solicitud solo se puede usar con un tipo de archivo que se pueda sondear (pollable). Ejemplos de esto incluyen tuberías (pipes), dispositivos tun, etc. Si se usa con un archivo regular, o un tipo de archivo incorrecto en general, la solicitud fallará con -EBADFD en el campo res de la CQE.

Dado que las solicitudes multishot activan repetidamente eventos de finalización a medida que llegan los datos, deben usarse con búferes proporcionados. Con búferes proporcionados, la aplicación proporciona búferes a io_uring por adelantado, y luego el kernel selecciona un búfer del grupo especificado en buf_group cuando la solicitud está lista para transferir datos.

Una solicitud multishot persistirá siempre que no se encuentren errores durante el manejo de la solicitud. Por cada CQE publicada en nombre de esta solicitud, el campo flags de la CQE tendrá IORING_CQE_F_MORE establecido si la aplicación debe esperar más finalizaciones de esta solicitud. Si esta bandera no está establecida, significará la terminación de la solicitud de lectura multishot.

Después de preparar la lectura, se puede enviar con una de las funciones de envío.

Disponible desde la versión 6.7.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res de la CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los valores posibles. Tenga en cuenta que donde las llamadas al sistema síncronas devolverán -1 en caso de error y establecerán errno al valor de error real, io_uring nunca usa errno. En su lugar, devuelve el errno negado directamente en el campo res de la CQE.
