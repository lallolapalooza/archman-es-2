Esto significa que si desea cambiar la prioridad de E/S de todos los hilos de un proceso, puede necesitar llamar a ioprio_set() en cada uno de los hilos. El ID de hilo que necesitaría para esta operación es el que devuelve gettid(2) o clone(2). Estas llamadas al sistema solo tienen efecto cuando se usan en conjunto con un planificador de E/S que admita prioridades de E/S. Completely Fair Queuing (CFQ).

El planificador de E/S Completely Fair Queuing

(CFQ)

Desde la versión 3 (también conocida como CFQ Time Sliced), CFQ implementa niveles nice de E/S similares a los de la planificación de CPU. Estos niveles nice se agrupan en tres clases de planificación, cada una conteniendo uno o más niveles de

prioridad:
IOPRIO_CLASS_RT
(1)
Esta es la clase de E/S en tiempo real. A esta clase de planificación se le da una prioridad más alta que a cualquier otra clase: los procesos de esta clase se les da primero acceso al disco cada vez. Por lo tanto, esta clase de E/S debe usarse con cierto cuidado: un proceso de E/S en tiempo real puede agotare sistema completo. Dentro de la clase de tiempo real, existen 8 niveles de datos de clase (prioridad) que determinan exactamente cuánto tiempo necesita este proceso el disco en cada servicio. El nivel de prioridad de tiempo real más alto es 0; el más bajo es 7. En el futuro, esto podría cambiar para ser mapeable más directamente al rendimiento, pasando en su lugar una tasa de datos
deseada.
IOPRIO_CLASS_BE
(2)
Esta es la clase de planificación de mejor esfuerzo (best-effort), que es la predeterminada para cualquier proceso que no haya establecido una prioridad de E/S específica. Los datos de clase (prioridad) determinan cuánto ancho de banda de E/S recibirá el proceso. Los niveles de prioridad de mejor esfuerzo son análogos a los valores nice de la CPU (véase getpriority(2)). El nivel de prioridad determina una prioridad relativa a otros procesos en la clase de planificación de mejor esfuerzo. Los niveles de prioridad van desde 0 (el más alto) hasta 7 (el más bajo)
.
IOPRIO_CLASS_IDLE
(3)
Esta es la clase de planificación de inactividad (idle). Los procesos que se ejecutan en este nivel obtienen tiempo de E/S sol
o cuando nadie más necesita el disco. La clase de inactividad no tiene datos de clase. Se requiere atención al asignar esta cla
se de prioridad a un proceso, ya que puede quedar inanicionado si procesos de mayor prioridad acceden constantemente al disco.

Consulte el archivo de código fuente del kernel Documentation/block/ioprio.txt para más información sob

re el planificador de E/S C

Permisos requeridos para establecer prioridades de

E/S

El permiso para cambiar la prioridad de un proceso se concede o deniega basándose en dos

criterios:
Propiedad del
proceso
Un proceso sin privilegios solo puede establecer la prioridad de E/S para un proceso cuyo UID real coincida con el UID real o efectivo del proceso que llama. Un proceso que tiene la capacidad CAP_SYS_NICE puede cambiar la prioridad de cualquier
proceso.
Cuál es la prioridad
deseada
Los intentos de establecer prioridades muy altas (IOPRIO_CLASS_RT) requieren la capacidad CAP_SYS_ADMIN. Hasta Linux 2.6.24 también se requería CAP_SYS_ADMIN para establecer una prioridad muy baja (IOPRIO_CLASS_IDLE), pero desde Lin
ux 2.6.25, esto y
a no se requiere.
