NOMBRE

io_uring_prep_writev - prepara una solicitud de escritura I/O vectorial

SINOPSIS

#include <sys/uio.h>
#include <liburing.h>
void io_uring_prep_writev(struct io_uring_sqe *sqe,
                          int fd,
                          const struct iovec *iovecs,
                          unsigned nr_vecs,
                          __u64 offset);

DESCRIPCIÓN

La función io_uring_prep_writev(3) prepara una solicitud de escritura IO vectorial. La entrada de la cola de envío sqe se configura para usar el descriptor de archivo fd para comenzar a escribir nr_vecs elementos del array iovecs en la posición offset especificada.

En archivos que soportan búsqueda (seeking), si el offset se establece en -1, la operación de escritura comienza en el offset del archivo, y el offset del archivo se incrementa por el número de bytes escritos. Ver write(2) para más detalles. Tener en cuenta que para una API asíncrona, leer y actualizar el offset actual del archivo puede resultar en un comportamiento impredecible, a menos que el acceso al archivo esté serializado. No se recomienda usar esta característica si es posible proporcionar el offset de IO deseado desde la aplicación o librería.

En archivos que no son capaces de buscar, el offset debe ser 0 o -1.

Después de que la escritura ha sido preparada, puede ser enviada con una de las funciones de envío.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res de la CQE contendrá el resultado de la operación. Ver la página de manual relacionada para detalles sobre posibles valores. Tener en cuenta que mientras las llamadas al sistema síncronas devolverán -1 en caso de error y establecerán errno al valor de error real, io_uring nunca usa errno. En su lugar, devuelve el errno negado directamente en el campo res de la CQE.

NOTAS

A menos que una aplicación necesite explícitamente pasar más de un iovec, es más eficiente usar io_uring_prep_write(3) en lugar de esta función, ya que no hay que mantener estado para una solicitud IO no vectorial. Al igual que con cualquier solicitud que pase datos en una estructura, esos datos deben permanecer válidos hasta que la solicitud se haya enviado con éxito. No es necesario que permanezcan válidos hasta la finalización. Una vez que una solicitud ha sido enviada, el estado dentro del kernel es estable. Los kernels muy tempranos (5.4 y anteriores) requerían que el estado fuera estable hasta que ocurriera la finalización. Las aplicaciones pueden probar este comportamiento inspeccionando el flag IORING_FEAT_SUBMIT_STABLE devuelto por io_uring_queue_init_params(3).
