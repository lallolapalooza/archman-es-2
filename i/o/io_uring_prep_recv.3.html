NOMBRE

io_uring_prep_recv - preparar una solicitud de recepción

SINOPSIS

#include <liburing.h>
void io_uring_prep_recv(struct io_uring_sqe *sqe,
                        int sockfd,
                        void *buf,
                        size_t len,
                        int flags);
void io_uring_prep_recv_multishot(struct io_uring_sqe *sqe,
                                  int sockfd,
                                  void *buf,
                                  size_t len,
                                  int flags);

DESCRIPCIÓN

La función io_uring_prep_recv(3) prepara una solicitud de recepción. El elemento de la cola de envío sqe se configura para utilizar el descriptor de archivo sockfd para empezar a recibir los datos en el buffer de destino buf de tamaño len y con las banderas modificadoras flags.

Esta función prepara una solicitud asíncrona de recv(2). Consulte esa página del manual para obtener detalles sobre los argumentos especificados a esta utilidad de preparación.

La versión multishot permite a la aplicación emitir una única solicitud de recepción, que publica repetidamente un CQE cuando hay datos disponibles. Requiere que la longitud sea 0, que la bandera IOSQE_BUFFER_SELECT esté establecida y que no se establezca la bandera MSG_WAITALL. Por lo tanto, cada CQE tomará un buffer de un pool de buffers proporcionado para la recepción. La aplicación debe comprobar las banderas de cada CQE, independientemente de su resultado. Si un CQE publicado no tiene la bandera IORING_CQE_F_MORE establecida, entonces la recepción multishot ha finalizado y la aplicación debe emitir una nueva solicitud si aún desea recibir datos del socket. Las variantes multishot están disponibles desde el kernel 6.0.

Después de llamar a esta función, se pueden establecer banderas modificadoras internas adicionales de io_uring en el campo ioprio del SQE. Las siguientes banderas son compatibles:

IORING_RECVSEND_POLL_FIRST
Si está establecida, io_uring asumirá que el socket está actualmente vacío y que intentar recibir datos será infructuoso. En este caso, io_uring activará la espera de sondeo (poll) y activará una recepción de los datos cuando el socket tenga datos para ser leídos. Este intento inicial de recepción puede ser inútil en el caso de que se espere que el socket esté vacío; establecer esta bandera omitirá el intento inicial de recepción y pasará directamente a activar la espera de sondeo. Si la espera de sondeo indica que los datos están listos para ser recibidos, la operación procederá.

Puede utilizarse con la bandera CQE IORING_CQE_F_SOCK_NONEMPTY, que io_uring establecerá en los CQE después de una operación de recv(2) o recvmsg(2). Si está establecida, el socket todavía tenía datos para leer después de que la operación se completara. Ambas banderas están disponibles desde la versión 5.19.

IORING_RECVSEND_BUNDLE
Si está establecida y se utilizan buffers proporcionados con IOSQE_BUFFER_SELECT, la operación de recepción intentará llenar varios buffers en lugar de simplemente seleccionar un único buffer para llenar. Para recibir varios buffers en una sola recepción, el ID del grupo de buffers establecido en el SQE debe ser del tipo de anillo proporcionado. Si está establecida, el campo res del CQE indica el número total de bytes recibidos, y el ID del buffer devuelto en el campo flags del CQE indica el primer buffer en la operación de recepción. La aplicación debe procesar el buffer inicial indicado y hasta que se hayan visto todos los bytes res para saber cuál es el último buffer en la operación de recepción. Los buffers consumidos serán contiguos desde el buffer inicial, en el orden en que aparecen en el anillo de buffers. La estructura CQE no contiene la posición del buffer en el anillo de buffers, por lo tanto, para identificar los buffers contenidos por el paquete, se recomienda mantener el índice de cabeza en caché por anillo de buffers. Este índice uint16_t representa la posición del siguiente buffer que se va a consumir dentro del anillo. Al completarse una operación de recepción, el índice de cabeza en caché debe incrementarse en consecuencia. La recepción en paquetes puede mejorar el rendimiento cuando hay más de un fragmento de datos disponible para recibir, eliminando viajes de ida y vuelta redundantes a través de la pila de red. Los paquetes de recepción pueden ser utilizados tanto por operaciones de recepción de un solo disparo como multishot. Tenga en cuenta que, internamente, los paquetes dependen de que la pila de red devuelva cuántos datos quedan en el socket después de la recepción inicial. Esto significa que la recepción inicial puede contener menos buffers de los que están disponibles, y las recepciones posteriores contendrán más buffers. Disponible desde la versión 6.10.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res del CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los valores posibles. Tenga en cuenta que mientras que las llamadas al sistema síncronas devolverán -1 en caso de fallo y establecerán errno al valor real del error, io_uring nunca utiliza errno. En su lugar, devuelve el errno negado directamente en el campo res del CQE.
