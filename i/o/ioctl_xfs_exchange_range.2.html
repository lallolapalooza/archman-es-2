ioctl_xfs_exchange_range(2)

Paquete: xfsprogs

Licencias: GPL-2.0-only, LGPL-2.1-only

IOCTL-XFS-EXCHANGE-RANGE(2) Manual de llamadas al sistema IOCTL-XFS-EXCHANGE-RANGE(2)

NOMBRE

ioctl_xfs_exchange_range - intercambiar el contenido de partes de dos archivos

SINOPSIS

#include <sys/ioctl.h>
#include <xfs/xfs_fs.h>

int ioctl(int file2_fd, XFS_IOC_EXCHANGE_RANGE, struct xfs_exchange_range *arg);

DESCRIPCIÓN

Dado un rango de bytes en un primer archivo file1_fd y un segundo rango de bytes en un segundo archivo file2_fd, esta ioctl(2) intercambia los contenidos de los dos rangos.

Los intercambios son atómicos con respecto a operaciones concurrentes de archivos. Las implementaciones deben garantizar que los lectores vean el contenido antiguo o el contenido nuevo en su totalidad, incluso si el sistema falla.

Los parámetros de la llamada al sistema se transmiten en estructuras de la siguiente forma:


struct xfs_exchange_range {
    __s32    file1_fd;
    __u32    pad;
    __u64    file1_offset;
    __u64    file2_offset;
    __u64    length;
    __u64    flags;
};

El campo pad debe ser cero.

Los campos file1_fd, file1_offset y length definen el primer rango de bytes a intercambiar.

Los campos file2_fd, file2_offset y length definen el segundo rango de bytes a intercambiar.

Ambos archivos deben ser del mismo montaje de sistema de archivos. Si los dos descriptores de archivo representan el mismo archivo, los rangos de bytes no deben superponerse. La mayoría de los sistemas de archivos basados en disco requieren que los inicios de ambos rangos estén alineados al tamaño de bloque del archivo. Si este es el caso, los finales de los rangos también deben estar alineados a menos que se establezca la bandera XFS_EXCHANGE_RANGE_TO_EOF.

El campo flags controla el comportamiento de la operación de intercambio.

XFS_EXCHANGE_RANGE_TO_EOF
Ignora el parámetro length. Todos los bytes en file1_fd desde file1_offset hasta EOF se mueven a file2_fd, y el tamaño de file2 se establece en (file2_offset+(file1_length-file1_offset)). Mientras tanto, todos los bytes en file2 desde file2_offset hasta EOF se mueven a file1 y el tamaño de file1 se establece en (file1_offset+(file2_length-file2_offset)).
XFS_EXCHANGE_RANGE_DSYNC
Asegura que todos los datos modificados en memoria en ambos rangos de archivos y todas las actualizaciones de metadatos relacionadas con la operación de intercambio se envíen al almacenamiento persistente antes de que la llamada retorne. Abrir cualquiera de los descriptores de archivo con O_SYNC u O_DSYNC tendrá el mismo efecto.
XFS_EXCHANGE_RANGE_FILE1_WRITTEN
Solo intercambia sub-rangos de file1_fd que se sabe que contienen datos escritos por software de aplicación. Cada sub-rango puede ser expandido (tanto hacia arriba como hacia abajo) para alinearse con la unidad de asignación del archivo. Para archivos en el dispositivo de datos, esta es un bloque del sistema de archivos. Para archivos en el dispositivo en tiempo real, este es el tamaño de la extensión en tiempo real. Esta facilidad se puede utilizar para implementar escrituras atómicas rápidas de dispersión-recopilación de cualquier complejidad para destinos de almacenamiento definidos por software si todas las escrituras están alineadas a la unidad de asignación del archivo.
XFS_EXCHANGE_RANGE_DRY_RUN
Verifica los parámetros y la viabilidad de la operación, pero no cambia nada.

VALOR DE RETORNO

En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

Los códigos de error pueden ser uno de los siguientes, entre otros:

EBADF
file1_fd no está abierto para lectura y escritura o está abierto para escrituras solo de anexión; o file2_fd no está abierto para lectura y escritura o está abierto para escrituras solo de anexión.
EINVAL
Los parámetros no son correctos para estos archivos. Este error también puede aparecer si alguno de los descriptores de archivo representa un dispositivo, FIFO o socket. Los sistemas de archivos de disco generalmente requieren que los argumentos de desplazamiento y longitud estén alineados a los tamaños de bloque fundamentales de ambos archivos.
EIO
Ocurrió un error de E/S.
EISDIR
Uno de los archivos es un directorio.
ENOMEM
El kernel no pudo asignar suficiente memoria para realizar la operación.
ENOSPC
No hay suficiente espacio libre en el sistema de archivos para intercambiar los contenidos de forma segura.
EOPNOTSUPP
El sistema de archivos no admite el intercambio de bytes entre los dos archivos.
EPERM
file1_fd o file2_fd son inmutables.
ETXTBSY
Uno de los archivos es un archivo de intercambio (swap).
EUCLEAN
El sistema de archivos está corrupto.
EXDEV
file1_fd y file2_fd no están en el mismo sistema de archivos montado.

CONFORMANDO A

Esta API es específica de XFS.

CASOS DE USO

Se contemplan varios casos de uso para esta llamada al sistema. En todos los casos, el software de aplicación debe coordinar las actualizaciones del archivo, ya que el intercambio se realiza incondicionalmente.

El primero es un programa de almacenamiento de datos que desea confirmar actualizaciones no contiguas a un archivo de forma atómica y coordina el acceso de escritura a ese archivo. Esto se puede hacer creando un archivo temporal, llamando a FICLONE(2) para compartir el contenido y preparando las actualizaciones en el archivo temporal. Se recomienda la bandera FULL_FILES para este propósito. El archivo temporal se puede eliminar o "punzar" después.

Un programa de ejemplo podría verse así:


int fd = open("/some/file", O_RDWR);
int temp_fd = open("/some", O_TMPFILE | O_RDWR);
ioctl(temp_fd, FICLONE, fd);
/* añadir 1MB de registros */
lseek(temp_fd, 0, SEEK_END);
write(temp_fd, data1, 1000000);
/* actualizar el índice de registros */
pwrite(temp_fd, data1, 600, 98765);
pwrite(temp_fd, data2, 320, 54321);
pwrite(temp_fd, data2, 15, 0);
/* confirmar toda la actualización */
struct xfs_exchange_range args = {
    .file1_fd = temp_fd,
    .flags = XFS_EXCHANGE_RANGE_TO_EOF,
};
ioctl(fd, XFS_IOC_EXCHANGE_RANGE, &args);

El segundo es un host de almacenamiento definido por software (por ejemplo, un cambiador de discos) que implementa un comando de escritura atómica de dispersión-recopilación. Siempre que el tamaño de bloque lógico del disco exportado coincida con el tamaño de unidad de asignación del archivo, esto se puede hacer creando un archivo temporal y escribiendo los datos en los desplazamientos apropiados. Se recomienda que el archivo temporal se trunque al tamaño del archivo regular antes de que se preparen escrituras en el archivo temporal para evitar problemas con el relleno de ceros durante la extensión del EOF. Utilice esta llamada con la bandera FILE1_WRITTEN para intercambiar solo las unidades de asignación de archivos involucradas en el comando de escritura del dispositivo emulado. El archivo temporal debe truncarse o eliminarse completamente antes de ser reutilizado para preparar otra escritura.

Un programa de ejemplo podría verse así:


int fd = open("/some/file", O_RDWR);
int temp_fd = open("/some", O_TMPFILE | O_RDWR);
struct stat sb;
int blksz;
fstat(fd, &sb);
blksz = sb.st_blksize;
/* escribir escrituras de dispersión-recopilación entre 100fsb y 500fsb */
pwrite(temp_fd, data1, blksz * 2, blksz * 100);
pwrite(temp_fd, data2, blksz * 20, blksz * 480);
pwrite(temp_fd, data3, blksz * 7, blksz * 257);
/* confirmar toda la actualización */
struct xfs_exchange_range args = {
    .file1_fd = temp_fd,
    .file1_offset = blksz * 100,
    .file2_offset = blksz * 100,
    .length       = blksz * 400,
    .flags        = XFS_EXCHANGE_RANGE_FILE1_WRITTEN |
                    XFS_EXCHANGE_RANG
