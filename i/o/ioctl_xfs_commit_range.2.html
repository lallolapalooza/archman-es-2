ioctl_xfs_commit_range(2)

Paquete: xfsprogs

Licencias: GPL-2.0-only, LGPL-2.1-only

IOCTL-XFS-COMMIT-RANGE(2) Manual de Llamadas al Sistema IOCTL-XFS-COMMIT-RANGE(2)

NOMBRE

ioctl_xfs_commit_range - intercambiar condicionalmente el contenido de partes de dos archivos ioctl_xfs_start_commit - preparar para intercambiar el contenido de dos archivos

SINOPSIS

#include <sys/ioctl.h>
#include <xfs/xfs_fs.h>

int ioctl(int file2_fd, XFS_IOC_START_COMMIT, struct xfs_commit_range *arg);

int ioctl(int file2_fd, XFS_IOC_COMMIT_RANGE, struct xfs_commit_range *arg);

DESCRIPCIÓN

Dado un rango de bytes en un primer archivo file1_fd y un segundo rango de bytes en un segundo archivo file2_fd, este ioctl(2) intercambia el contenido de los dos rangos si file2_fd cumple ciertos criterios de vigencia.

Antes de intercambiar el contenido, el programa debe llamar al ioctl XFS_IOC_START_COMMIT para muestrear los datos de vigencia de file2_fd. Si los metadatos muestreados no coinciden con los metadatos del archivo en el momento de la confirmación, XFS_IOC_COMMIT_RANGE devolverá EBUSY.

Los intercambios son atómicos con respecto a las operaciones concurrentes en archivos. Las implementaciones deben garantizar que los lectores vean o bien el contenido antiguo o bien el nuevo en su totalidad, incluso si el sistema falla.

Los parámetros de la llamada al sistema se transmiten en estructuras de la siguiente forma:


struct xfs_commit_range {
    __s32    file1_fd;
    __u32    pad;
    __u64    file1_offset;
    __u64    file2_offset;
    __u64    length;
    __u64    flags;
    __u64    file2_freshness[5];
};

El campo pad debe ser cero.

Los campos file1_fd, file1_offsety length definen el primer rango de bytes a intercambiar.

Los campos file2_fd, file2_offsety length definen el segundo rango de bytes a intercambiar.

El campo file2_freshness es un campo opaco cuyo contenido es determinado por el kernel. Estos atributos del archivo se utilizan para confirmar que file2_fd no ha sido modificado por otro hilo desde que el hilo actual comenzó a preparar su propia actualización.

Ambos archivos deben provenir del mismo punto de montaje del sistema de archivos. Si los dos descriptores de archivo representan el mismo archivo, los rangos de bytes no deben solaparse. La mayoría de los sistemas de archivos basados en disco requieren que el inicio de ambos rangos esté alineado al tamaño de bloque del archivo. Si este es el caso, los finales de los rangos también deben estar alineados, a menos que se establezca el indicador XFS_EXCHANGE_RANGE_TO_EOF .

El campo flags controla el comportamiento de la operación de intercambio.

XFS_EXCHANGE_RANGE_TO_EOF
Ignorar el parámetro length . Todos los bytes en file1_fd desde file1_offset hasta EOF se mueven a file2_fd, y el tamaño de file2 se establece en (file2_offset+(file1_length-file1_offset)). Mientras tanto, todos los bytes en file2 desde file2_offset hasta EOF se mueven a file1 y el tamaño de file1 se establece en (file1_offset+(file2_length-file2_offset)).
XFS_EXCHANGE_RANGE_DSYNC
Asegurar que todos los datos modificados en memoria en ambos rangos de archivo y todas las actualizaciones de metadatos relacionadas con la operación de intercambio se vuelquen al almacenamiento persistente antes de que la llamada retorne. Abrir cualquiera de los descriptores de archivo con O_SYNC o O_DSYNC tendrá el mismo efecto.
XFS_EXCHANGE_RANGE_FILE1_WRITTEN
Solo intercambiar subrangos de file1_fd que se sabe que contienen datos escritos por el software de aplicación. Cada subrango puede expandirse (tanto hacia arriba como hacia abajo) para alinearse con la unidad de asignación del archivo. Para archivos en el dispositivo de datos, esta es una bloque del sistema de archivos. Para archivos en el dispositivo de tiempo real, esta es el tamaño de la extensión de tiempo real. Esta facilidad puede usarse para implementar escrituras rápidas atómicas de tipo scatter-gather de cualquier complejidad para objetivos de almacenamiento definidos por software si todas las escrituras están alineadas a la unidad de asignación del archivo.
XFS_EXCHANGE_RANGE_DRY_RUN
Verificar los parámetros y la viabilidad de la operación, pero no cambiar nada.

VALOR DE RETORNO

En caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

Los códigos de error pueden ser uno de, pero no se limitan a, los siguientes:

EBADF
file1_fd no está abierto para lectura y escritura o está abierto para escrituras de solo agregado; o file2_fd no está abierto para lectura y escritura o está abierto para escrituras de solo agregado.
EBUSY
El número de inodo y las marcas de tiempo de file2 proporcionadas no coinciden con file2_fd.
EINVAL
Los parámetros no son correctos para estos archivos. Este error también puede aparecer si cualquiera de los descriptores de archivo representa un dispositivo, FIFO o socket. Los sistemas de archivos de disco generalmente requieren que los argumentos de desplazamiento y longitud estén alineados a los tamaños de bloque fundamentales de ambos archivos.
EIO
Ocurrió un error de E/S.
EISDIR
Uno de los archivos es un directorio.
ENOMEM
El kernel no pudo asignar suficiente memoria para realizar la operación.
ENOSPC
No hay suficiente espacio libre en el sistema de archivos para intercambiar el contenido de forma segura.
EOPNOTSUPP
El sistema de archivos no soporta el intercambio de bytes entre los dos archivos.
EPERM
file1_fd o file2_fd son inmutables.
ETXTBSY
Uno de los archivos es un archivo de intercambio (swap).
EUCLEAN
El sistema de archivos está corrupto.
EXDEV
file1_fd y file2_fd no están en el mismo sistema de archivos montado.

CONFORMIDAD

Esta API es específica de XFS.

CASOS DE USO

Se imaginan varios casos de uso para esta llamada al sistema. La coordinación entre múltiples hilos es realizada por el kernel.

El primero es un desfragmentador de sistemas de archivos, que copia el contenido de un archivo en otro archivo e intercambia los mapeos de espacio de los dos archivos, siempre que el archivo original no haya cambiado.

Un programa de ejemplo podría verse así:


int fd = open("/some/file", O_RDWR);
int temp_fd = open("/some", O_TMPFILE | O_RDWR);
struct stat sb;
struct xfs_commit_range args = {
    .flags = XFS_EXCHANGE_RANGE_TO_EOF,
};
/* recopilar la información de vigencia de file2 */
ioctl(fd, XFS_IOC_START_COMMIT, &args);
fstat(fd, &sb);
/* hacer una copia fresca del archivo con un alineamiento terrible para evitar reflink */
clone_file_range(fd, NULL, temp_fd, NULL, 1, 0);
clone_file_range(fd, NULL, temp_fd, NULL, sb.st_size - 1, 0);
/* confirmar toda la actualización */
args.file1_fd = temp_fd;
ret = ioctl(fd, XFS_IOC_COMMIT_RANGE, &args);
if (ret && errno == EBUSY)
    printf("file changed while defrag was underway\n");

El segundo es un programa de almacenamiento de datos que quiere confirmar actualizaciones no contiguas a un archivo de forma atómica. Este programa no puede coordinar las actualizaciones del archivo y por lo tanto depende del kernel para rechazar el comando COMMIT_RANGE si el archivo ha sido actualizado por otra persona. Esto puede hacerse creando un archivo temporal, llamando a FICLONE(2) para compartir el contenido, y preparando las actualizaciones en el archivo temporal. Se recomienda el indicador FULL_FILES para este propósito. El archivo temporal puede ser eliminado o vaciado después.

Un programa de ejemplo podría verse así:


int fd = open("/algún/archivo", O_RDWR);
int temp_fd = open("/algún", O_TMPFILE | O_RDWR);
struct xfs_commit_range args = {
    .flags = XFS_EXCHANGE_RANGE_TO_EOF,
};
/* recopilar información de frescura del archivo2 */
ioctl(fd, XFS_IOC_START_COMMIT, &args);
ioctl(temp_fd, FICLONE, fd);
/* adjuntar 1MB de registros */
lseek(temp_fd, 0, SEEK_END);
write(temp_fd, data1, 1000000);
/* actualizar índice de registros */
pwrite(temp_fd, data1, 600, 98765);
pwrite(temp_fd, data2, 320, 54321);
pwrite(temp_fd, data2, 15, 0);
/* confirmar toda la actualización */
args.file1_fd = temp_fd;
ret = ioctl(fd, XFS_IOC_COMMIT_RANGE, &args);
if (ret && errno == EBUSY)
    printf("el archivo cambió antes de la confirmación; se revertirá");

NOTAS

Algunos sistemas de archivos pueden limitar la cantidad de datos o el número de extents que se pueden intercambiar en una sola llamada.
