NOMBRE

io_uring_prep_writev2 - prepara una solicitud de escritura I/O vectorial con indicadores

SINOPSIS

#include <sys/uio.h>
#include <liburing.h>
void io_uring_prep_writev2(struct io_uring_sqe *sqe,
                           int fd,
                           const struct iovec *iovecs,
                           unsigned nr_vecs,
                           __u64 offset,
                           int flags);

DESCRIPCIÓN

La función io_uring_prep_writev2(3) prepara una solicitud de escritura IO vectorial. La entrada de la cola de envío sqe se configura para usar el descriptor de archivo fd para comenzar a escribir nr_vecs elementos del array iovecs en la posición offset especificada. El comportamiento de la función se puede controlar con el parámetro flags.

Los valores admitidos para flags son:

RWF_HIPRI
Solicitud de alta prioridad, sondea si es posible.
RWF_DSYNC
O_DSYNC por IO.
RWF_SYNC
O_SYNC por IO.
RWF_NOWAIT
Por IO, devuelve -EAGAIN si la operación se bloquearía.
RWF_APPEND
O_APPEND por IO.

En archivos que admiten búsqueda, si el desplazamiento se establece en -1, la operación de escritura comienza en el desplazamiento del archivo, y el desplazamiento del archivo se incrementa en el número de bytes escritos. Consulte write(2) para obtener más detalles. Tenga en cuenta que para una API asíncrona, leer y actualizar el desplazamiento del archivo actual puede generar un comportamiento impredecible, a menos que el acceso al archivo esté serializado. No se recomienda usar esta característica si es posible proporcionar el desplazamiento de IO deseado desde la aplicación o biblioteca.

En archivos que no son capaces de búsqueda, el desplazamiento debe ser 0 o -1.

Una vez preparada la escritura, se puede enviar con una de las funciones de envío.

VALOR DE RETORNO

Ninguno.

ERRORES

El campo res del CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los valores posibles. Tenga en cuenta que mientras que las llamadas al sistema síncronas devolverán -1 en caso de error y establecerán errno al valor de error real, io_uring nunca usa errno. En su lugar, devuelve el errno negado directamente en el campo res del CQE.

NOTAS

A menos que una aplicación necesite explícitamente pasar más de un iovec, es más eficiente usar io_uring_prep_write(3) en lugar de esta función, ya que no se tiene que mantener ningún estado para una solicitud de IO no vectorial. Como con cualquier solicitud que pase datos en una estructura, esos datos deben permanecer válidos hasta que la solicitud se haya enviado con éxito. No es necesario que permanezcan válidos hasta la finalización. Una vez que se ha enviado una solicitud, el estado en el kernel es estable. Los primeros kernels (5.4 y anteriores) requerían que el estado fuera estable hasta que ocurriera la finalización. Las aplicaciones pueden probar este comportamiento inspeccionando el indicador IORING_FEAT_SUBMIT_STABLE devuelto por io_uring_queue_init_params(3).
