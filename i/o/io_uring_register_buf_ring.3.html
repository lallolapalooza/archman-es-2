NOMBRE

io_uring_register_buf_ring - registrar un anillo de búferes para búferes proporcionados

SINOPSIS

#include <liburing.h>
int io_uring_register_buf_ring(struct io_uring *ring,
                               struct io_uring_buf_reg *reg,
                               unsigned int flags);

DESCRIPCIÓN

La función io_uring_register_buf_ring(3) registra un anillo de búferes compartido para ser utilizado con búferes proporcionados. Para los tipos de solicitud que lo admiten, los búferes proporcionados se entregan al anillo y uno es seleccionado por una solicitud si tiene IOSQE_BUFFER_SELECT establecido en los flags de la SQE, cuando la solicitud está lista para recibir datos. Esto permite tanto la propiedad clara de la vida útil del búfer, como una forma de tener más operaciones de recepción/lectura en vuelo que búferes disponibles.

El argumento reg debe completarse con la información apropiada. Se ve así:


struct io_uring_buf_reg {
    __u64 ring_addr;
    __u32 ring_entries;
    __u16 bgid;
    __u16 pad;
    __u64 resv[3];
};

El campo ring_addr debe contener la dirección de la memoria asignada para este anillo. La memoria debe estar alineada en páginas y, por lo tanto, asignada apropiadamente usando, por ejemplo, posix_memalign(3) o similar. El tamaño del anillo es el producto de ring_entries y el tamaño de struct io_uring_buf. ring_entries es el tamaño deseado del anillo y debe ser una potencia de 2. El tamaño máximo permitido es 2^15 (32768). bgid es el ID del grupo de búferes asociado con este anillo. Las SQE que seleccionan un búfer tienen un grupo de búferes asociado en su campo buf_group, y las CQE asociadas tendrán IORING_CQE_F_BUFFER establecido en su miembro flags, que también contendrá el ID específico del búfer seleccionado. El resto de los campos están reservados y deben limpiarse a cero.

El argumento flags puede establecerse en uno de los siguientes valores:

IOU_PBUF_RING_INC
Los búferes en este anillo se pueden consumir incrementalmente. Con el consumo parcial, cada finalización de un ID de búfer dado continuará donde la anterior lo dejó, o desde el principio si aún no se han visto finalizaciones. Cuando se esperan más finalizaciones para un ID de búfer dado, la CQE tendrá IORING_CQE_F_BUF_MORE establecido en el miembro flags. Disponible desde la versión 6.12.

Un anillo de búferes compartido se ve así:


struct io_uring_buf_ring {
    union {
        struct {
            __u64 resv1;
            __u32 resv2;
            __u16 resv3;
            __u16 tail;
        };
        struct io_uring_buf bufs[0];
    };
};

donde tail es el índice en el que la aplicación puede insertar nuevos búferes para ser consumidos por las solicitudes, y struct io_uring_buf es la definición del búfer:


struct io_uring_buf {
    __u64 addr;
    __u32 len;
    __u16 bid;
    __u16 resv;
};

donde addr es la dirección del búfer, len es la longitud del búfer en bytes, y bid es el ID del búfer que se devolverá en la CQE una vez consumido.

Los campos reservados no deben tocarse. Las aplicaciones deben usar io_uring_buf_ring_init(3) para inicializar el anillo de búferes antes de su uso. Las aplicaciones pueden usar io_uring_buf_ring_add(3) y io_uring_buf_ring_advance(3) o io_uring_buf_ring_cq_advance(3) para proporcionar búferes, lo que establecerá estos campos y actualizará la cola.

Disponible desde la versión 5.19.

VALOR DEVUELTO

En caso de éxito, io_uring_register_buf_ring(3) devuelve 0. En caso de error, devuelve -errno.

NOTAS

A menos que se necesite una configuración manual, se recomienda usar io_uring_setup_buf_ring(3) ya que proporciona una forma más sencilla de configurar un anillo de búferes proporcionado.
