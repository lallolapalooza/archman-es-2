IORING_REGISTER_RING_
FDS
Siempre que io_uring_enter(2) se llama para enviar solicitudes o esperar finalizaciones, el kernel debe tomar una referencia al descriptor de archivo. Si la aplicación que usa io_uring es multihilo, la tabla de archivos se marca como compartida, y tomar y soltar la referencia del conteo del descriptor de archivo es más costoso que para una aplicación no multihilo.

De manera similar a cómo io_uring permite el registro de archivos, esto permite el registro del descriptor de archivo del anillo en sí mismo. Esto reduce la sobrecarga de la llamada al sistema io_uring_enter(2)

.

arg debe establecerse a un puntero a una array de tipo struct io_uring_rsrc_update de nr_args número de entradas. El campo data de este struct debe contener un descriptor de archivo io_uring, y el campo offset puede ser -1 o un desplazamiento explícito deseado para el valor del descriptor de archivo registrado. Si se usa -1, entonces al retorno exitoso de esta llamada al sistema, el campo contendrá el valor del descriptor de archivo registrado a ser usado para futuras llamadas al sistema io_uring_enter(2)

.

Al completar exitosamente esta solicitud, los descriptores devueltos pueden usarse en lugar del descriptor de archivo real para io_uring_enter(2), siempre que IORING_EN**TER_REGISTERED_RING se establece en las flags para la llamada al sistema. Esta flag le indica al kernel que se utiliza un descriptor registrado en lugar de un descriptor de archivo real.

Cada hilo o proceso que utiliza un anillo debe registrar el descriptor de archivo directamente emitiendo esta solicitud.

El número máximo de descriptores de anillo registrados admitidos está actualmente limitado a **16**.

Disponible desde 5.18.

IORING_UNREGISTER_RING_FDS
Anula el registro de los descriptores previamente registrados con IORING_REGISTER_RING_FDS.

arg debe establecerse en un puntero a una matriz de tipo struct io_uring_rsrc_update con un número de entradas igual a nr_args. Solo el campo offset debe establecerse en la estructura, conteniendo el desplazamiento del descriptor de archivo registrado devuelto previamente por IORING_REGISTER_RING_FDS que la aplicación desea anular el registro.

Tenga en cuenta que esto no se hace automáticamente al salir del anillo, si el hilo o tarea que previamente registró un descriptor de archivo de anillo no está saliendo. Se recomienda anular manualmente cualquier descriptor de archivo de anillo registrado previamente si el anillo se cierra y la tarea persiste. Esto liberará una ranura de registro, poniéndola a disposición para uso futuro.

Disponible desde 5.18.

IORING_REGISTER_PBUF_RING
Registra un anillo de búfer compartido para ser utilizado con búferes proporcionados. Esta es una alternativa más nueva a IORING_OP_PROVIDE_BUFFERS que es más eficiente, para ser utilizada con tipos de solicitud que admiten la flag IOSQE_BUFFER_SELECT.

El argumento arg debe llenarse con la información apropiada. Se ve así:


struct io_uring_buf_reg {
    __u64 ring_addr;
    __u32 ring_entries;
    __u16 bgid;
    __u16 pad;
    __u64 resv[3];
};


El campo ring_addr debe contener la dirección de la memoria asignada para ajustarse a este anillo. La memoria debe estar alineada por páginas y, por lo tanto, asignada apropiadamente usando, por ejemplo, posix_memalign(3) o similar. El tamaño del anillo es el producto de ring_entries y el tamaño de struct io_uring_buf. ring_entries es el tamaño deseado del anillo y debe ser una potencia de 2. El tamaño máximo permitido es 2^15 (32768). bgid es el ID del grupo de búferes asociado con este anillo. Los SQE que seleccionan un búfer tienen un grupo de búfer asociado en su campo buf_group, y los CQE asociados tendrán IORING_CQE_F_BUFFER establecido en su miembro flags, que también contendrá el ID específico del búfer seleccionado. El resto de los campos están reservados y deben borrarse a cero.

nr_args debe establecerse en 1.

Consulte también io_uring_register_buf_ring(3) para más detalles. Disponible desde 5.19.

IORING_UNREGISTER_PBUF_RING
Anula el registro de un anillo de búfer proporcionado previamente registrado. arg debe establecerse en la dirección de una struct io_uring_buf_reg, con solo el campo bgid establecido en el ID del grupo de búferes del grupo de búferes proporcionado registrado previamente. nr_args debe establecerse en 1. Consulte también IORING_REGISTER_PBUF_RING.

Disponible desde 5.19.

IORING_REGISTER_SYNC_CANCEL
Realiza una solicitud de cancelación síncrona, que funciona de manera similar a IORING_OP_ASYNC_CANCEL excepto que se completa en línea. Esto puede ser útil para escenarios en los que las cancelaciones deben ocurrir sincrónicamente, en lugar de tener que emitir un SQE y esperar la finalización de ese CQE específico.

arg debe establecerse en un puntero a una estructura io_uring_sync_cancel_reg, con los detalles completados para qué solicitud(es) dirigir para la cancelación. Consulte io_uring_register_sync_cancel(3) para más detalles. Los valores de retorno son los mismos, excepto que se pasan de forma síncrona en lugar de a través del campo res del CQE. nr_args debe establecerse en 1.

Disponible desde 6.0.

IORING_REGISTER_FILE_ALLOC_RANGE
Establece el rango permitido para las asignaciones de índices de archivos fijos dentro del kernel. Cuando las solicitudes que pueden instanciar un nuevo archivo fijo se utilizan con IORING_FILE_INDEX_ALLOC, la aplicación está pidiendo al kernel que asigne un nuevo descriptor de archivo fijo en lugar de pasar un valor específico para uno. Por defecto, el kernel elegirá cualquier descriptor de archivo fijo disponible dentro del rango disponible. Esto permite efectivamente que la aplicación reserve un rango solo para asignaciones dinámicas, con el resto utilizado para valores específicos.

nr_args debe establecerse en 1 y arg debe establecerse en un puntero a una struct io_uring_file_index_range:


struct io_uring_file_index_range {
    __u32 off;
    __u32 len;
    __u64 resv;
};


con off establecido en el valor de inicio del rango, y len establecido en el número de descriptores. El campo resv reservado debe borrarse a cero.

La aplicación debe haber registrado una tabla de archivos primero.

Disponible desde 6.0.

IORING_REGISTER_PBUF_STATUS
Se puede utilizar para recuperar la cabeza actual de un anillo de búferes proporcionado anteriormente a través de IORING_REGISTER_PBUF_RING. arg debe apuntar a un


struct io_uring_buf_status {
	__u32	buf_group;	/* input */
	__u32	head;		/* output */
	__u32	resv[8];
};


del cual arg->buf_group debe contener el ID del grupo de búferes para el anillo de búfer en cuestión, nr_args debe establecerse en 1 y arg->resv debe borrarse a cero. La cabeza actual del anillo de búferes se devolverá en arg->head.

Disponible desde 6.8.

IORING_REGISTER_NAPI
Registra una instancia napi con la instancia io_uring de fd. arg debe apuntar a un


struct io_uring_napi {
	__u32	busy_poll_to;
	__u8	prefer_busy_poll;
	__u8	pad[3];
	__u64	resv;
};


en el que arg->busy_poll_to debe contener el tiempo de espera de busy polling en microsegundos y arg->prefer_busy_poll debe especificar si se debe usar busy polling en lugar de IRQs. nr_args debe establecerse en 1 y arg->pad y arg->resv deben borrarse a cero. Al devolver correctamente, la estructura io_uring_napi apuntada por arg contendrá la configuración utilizada previamente. Debe usarse con un anillo creado inicialmente con IORING_SETUP_IOPOLL.

Disponible desde 6.9.

IORING_UNREGISTER_NAPI
Anula el registro de una instancia napi registrada previamente a través de IORING_REGISTER_NAPI a la instancia io_uring de fd. arg debe apuntar a una struct io_uring_napi. Al devolver correctamente, la estructura io_uring_napi apuntada por arg contendrá la configuración utilizada previamente.

Disponible desde 6.9.

IORING_REGISTER_CLOCK
Especifica qué ID de reloj utilizará io_uring para los temporizadores mientras espera los eventos de finalización con IORING_ENTER_GETEVENTS. Solo es efectivo si se pasa el argumento de tiempo de espera en struct io_uring_getevents_arg, ignorado de lo contrario. Cuando se utiliza junto con IORING_ENTER_ABS_TIMER, interpreta el argumento de tiempo de espera como la hora absoluta del reloj especificado.

El reloj predeterminado es **CLOCK_MONOTONIC**.

Disponible desde 6.12 y admite CLOCK_MONOTONIC y CLOCK_BOOTTIME.

IORING_REGISTER_CLONE_BUFFERS
Admite la clonación de búferes de un anillo de origen a un anillo de destino, duplicando los búferes registrados previamente del origen al destino. arg debe establecerse en un puntero a una struct io_uring_clone_buffers y nr_args debe establecerse en **1**. struct io_uring_buf_reg se ve así:


struct io_uring_clone_buffers {
    __u32 src_fd;
    __u32 flags;
    __u32 src_off;
    __u32 dst_off;
    __u32 nr;
    __u32 pad[3];
};

donde src_fd indica el fd del anillo de origen, flags son flags modificadores para la operación, src_off indica el desplazamiento desde donde comenzar la clonación desde el anillo de origen, dst_off indica el desplazamiento desde donde comenzar la clonación hacia el anillo de destino, y nr indica el número de búferes a clonar en los desplazamientos dados. pad debe llenarse con ceros. El kernel 6.12 agregó soporte para la clonación de rango completo, donde src_off, dst_off y nr deben establecerse en 0, indicando la clonación de toda la tabla en origen a destino. El kernel 6.13 agregó soporte para especificar los desplazamientos y cuántos búferes clonar. Además, agregó soporte para clonar en una tabla previamente registrada en el destino también, 6.12 fallaría esa operación con **-EBUSY** si se intentaba. Para reemplazar nodos existentes o clonar en una tabla existente, **IORING_REGISTER_DST_REPLACE** debe establecerse en el miembro flags.

DESCRIPCIÓN

El sistema io_uring_register(2) permite registrar diferentes tipos de objetos con una instancia de io_uring. Los objetos que se pueden registrar son:

IORING_REGISTER_BUFFERS
Registra búferes de usuario para ser utilizados por las operaciones io_uring_prep_buf_ring(3). El argumento arg debe apuntar a un arreglo de structio_uring_buf_reg, donde cada elemento define un búfer que se registrará. El campo buf_id es un identificador para el búfer, y buf_ptr y buf_len definen la región de memoria del búfer en el espacio de usuario. El número de búferes a registrar se especifica en nr_args. Todos los búferes registrados pertenecen a un mismo grupo de búferes.
IORING_UNREGISTER_BUFFERS
Anula el registro de los búferes previamente registrados. Si nr_args es 0 y arg es NULL, todos los búferes registrados se anularán. De lo contrario, nr_args especifica el número de identificadores de búfer en el arreglo apuntado por arg, y solo esos búferes específicos se anularán.
IORING_REGISTER_FILES
Registra un conjunto de descriptores de archivo para ser utilizados por operaciones futuras. El argumento arg debe apuntar a un arreglo de tipos de datos de descriptor de archivo (generalmente int), y nr_args especifica el número de descriptores de archivo en el arreglo. Los descriptores de archivo registrados se utilizan para las operaciones que especifican IORING_OP_READV, IORING_OP_WRITEV, IORING_OP_READ, IORING_OP_WRITE, etc., y se utilizarán en lugar de los descriptores de archivo proporcionados en el structio_uring_sqe. Esto puede ser útil para evitar pasar descriptores de archivo repetidamente. El conjunto de archivos registrados reemplazará cualquier conjunto de archivos previamente registrado.
IORING_UNREGISTER_FILES
Anula el registro del conjunto de descriptores de archivo actual. Si nr_args es 0 y arg es NULL, se anulará el registro de todos los archivos registrados. De lo contrario, no tiene ningún efecto; el conjunto completo de archivos debe anularse y registrarse de nuevo para eliminar archivos individuales.
IORING_REGISTER_PROBE
Permite al usuario consultar las operaciones y características compatibles con la versión actual del kernel de io_uring. El argumento arg debe apuntar a un structio_uring_ kayıt_probe. El campo ops_len debe inicializarse con el tamaño del arreglo ops en la estructura devuelta. El kernel llenará el resto de la estructura con información sobre las operaciones compatibles y sus rangos de soporte.
IORING_REGISTER_PBUF_RING
Registra un anillo de búferes de usuario. El argumento arg debe apuntar a un structio_uring_bufreg. El campo ring_ptr apunta al arreglo de búferes en el espacio de usuario, y ring_size especifica el número de búferes en el anillo. Los búferes registrados se utilizan para operaciones de búfer, como IORING_OP_RECVMSG con la bandera MSG_WAITFORONE. Los búferes deben ser de tamaño fijo y se asignarán de forma contigua en la memoria.
IORING_UNREGISTER_PBUF_RING
Anula el registro de un anillo de búferes previamente registrado. El argumento arg debe apuntar a un structio_uring_bufreg. El campo ring_ptr debe coincidir con el puntero del anillo registrado.
IORING_REGISTER_PBUF_STATUS
Permite consultar el estado de un grupo de búferes registrado. El argumento arg debe apuntar a un structio_uring_buf_status. El campo buf_group especifica el grupo de búferes cuyo estado se va a consultar. El campo status se llenará con el estado del grupo de búferes.
IORING_REGISTER_MEM_RING
Registra un anillo de memoria para su uso con operaciones de mapeo de memoria de alta velocidad. El argumento arg debe apuntar a un structio_uring_mem_reg. El campo ring_ptr apunta a la región de memoria en el espacio de usuario, y ring_size especifica el tamaño de la región de memoria. Esta operación está diseñada para optimizar el acceso a regiones de memoria grandes y contiguas.
IORING_UNREGISTER_MEM_RING
Anula el registro de un anillo de memoria previamente registrado. El argumento arg debe apuntar a un structio_uring_mem_reg. El campo ring_ptr debe coincidir con el puntero del anillo de memoria registrado.
IORING_REGISTER_RING_ALLOC_PTR
Registra un puntero que el kernel utilizará para asignar memoria para los anillos de completado (CQ) y envío (SQ) de io_uring. El argumento arg debe apuntar a un structio_uring_ring_alloc_ptr. El campo ptr debe apuntar a una ubicación de memoria en el espacio de usuario donde el kernel escribirá un puntero a la memoria asignada para los anillos. Esta opción permite al usuario preasignar memoria para los anillos, lo que puede ser útil para optimizar la inicialización de io_uring. Disponible desde el kernel 6.13.
IORING_REGISTER_CLAMP
Permite ajustar el tamaño máximo de los anillos de completado y envío. El argumento arg debe apuntar a un structio_uring_params. Solo los campos IORING_SETUP_CQSIZE e IORING_SETUP_CLAMP en este struct son tenidos en cuenta. Ver io_uring_resize_rings(3) para más detalles. Ten en cuenta que mientras liburing se encarga de desmapear y mapear el anillo para una operación de redimensionamiento, los usuarios manuales de esta llamada al sistema de registro deben realizar esas operaciones, de forma similar a cuando se crea un nuevo anillo. La estructura structio_uring_params contendrá los offsets necesarios copiados al finalizar con éxito esta llamada al sistema, los cuales pueden ser utilizados para mapear el anillo en memoria de la misma forma que se habría mapeado un nuevo anillo. Disponible desde el kernel 6.13.
IORING_REGISTER_MEM_REGION
Soporta el registro de múltiples regiones de memoria para diversos propósitos, evitando copias innecesarias de structio_uring_getevents_arg para operaciones de espera que especifiquen un tiempo de espera o un tiempo de espera mínimo. Toma un puntero a una estructura structio_uring_mem_region_reg, que se ve así:


struct io_uring_mem_region_reg {
    __u64 region_uptr;
    __u64 flags;
    __u64 __resv[2];
};

donde region_uptr debe apuntar a la región que se está registrando como regiones de memoria, flags especifica las banderas modificadoras (actualmente debe ser IORING_MEM_REGION_REG_WAIT_ARG). Los campos de relleno deben borrarse a 0. Cada región de memoria se ve así:


struct io_uring_region_desc {
    __u64 user_addr;
    __u64 size;
    __u32 flags;
    __u32 id;
    __u64 mmap_offset;
    __u64 __resv[4];
};

donde user_addr apunta a mapeos de memoria en el espacio de usuario, size es el tamaño de la memoria del espacio de usuario. Las regiones de memoria de usuario actualmente soportadas son las siguientes:


struct io_uring_reg_wait {
    struct __kernel_timespec ts;
    __u32                    min_wait_usec;
    __u32                    flags;
    __u64                    sigmask;
    __u32                    sigmask_sz;
    __u32                    pad[3];
    __u64                    pad2[2];
};

donde ts contiene la información del tiempo de espera para esta región, flags contiene información sobre la región de tiempo de espera, sigmask es un puntero a una máscara de señales, si se usa, y sigmask_sz es el tamaño de esa máscara de señales. Los campos de relleno deben borrarse a 0. Actualmente, la única bandera válida es IORING_REG_WAIT_TS, que, si está establecida, indica que los valores en ts son válidos y deben usarse para una operación de tiempo de espera. El campo user_addr de structio_uring_region_desc debe ser establecido a una dirección de miembros de structio_uring_reg_wait, se puede mapear hasta una página de tamaño. Con un tamaño de 64 bytes por región, eso permite al menos 64 regiones individuales en un sistema con tamaño de página de 4k. Los offsets de estas regiones se utilizan para una llamada al sistema io_uring_enter(2), siendo la primera 0, la segunda 1, y así sucesivamente. Después del registro de las regiones de espera, io_uring_enter(2) puede usarse con la bandera de entrada de IORING_ENTER_EXT_ARG_REG y un argp establecido al offset de la región de espera, en lugar de un puntero a una estructura structio_uring_getevent_arg. Si se usa con IORING_ENTER_GETEVENTS, entonces la operación de espera usará la información de la región de espera registrada en lugar de necesitar una estructura io_uring_getevent_arg copiada para cada operación. Para esperas de alta frecuencia, esto puede ahorrar considerables ciclos de CPU. Nota: una vez que una región ha sido registrada, no puede ser anulada. Vive durante la vida del anillo. Los offsets individuales de las regiones de espera pueden ser modificados antes de cualquier llamada al sistema io_uring_enter(2). Disponible desde el kernel 6.13.

VALOR DE RETORNO

En caso de éxito, io_uring_register(2) devuelve 0 o un valor positivo, dependiendo del opcode utilizado. En caso de error, se devuelve un valor de error negativo. El llamante no debe depender de la variable errno.

ERRORES

EACCES
El campo opcode no está permitido debido a restricciones registradas.
EBADF
Uno o más fds en el arreglo fd son inválidos.
EBADFD
Se especificó IORING_REGISTER_ENABLE_RINGS o IORING_REGISTER_RESTRICTIONS, pero el anillo io_uring no está deshabilitado.
EBUSY
Se especificó IORING_REGISTER_BUFFERS o IORING_REGISTER_FILES o IORING_REGISTER_RESTRICTIONS, pero ya había búferes, archivos o restricciones registrados.
EEXIST
El hilo que realiza el registro no es válido.
EFAULT
el búfer está fuera del espacio de direcciones accesible del proceso, o iov_len es mayor que 1GiB.
EINVAL
Se especificó IORING_REGISTER_BUFFERS o IORING_REGISTER_FILES, pero nr_args es 0.
EINVAL
Se especificó IORING_REGISTER_BUFFERS, pero nr_args excede UIO_MAXIOV
EINVAL
Se especificó IORING_UNREGISTER_BUFFERS o IORING_UNREGISTER_FILES, y nr_args es distinto de cero o arg es NULL.
EINVAL
Se especificó IORING_REGISTER_RESTRICTIONS, pero nr_args excede el número máximo permitido de restricciones o el opcode de restricción no es válido.
EMFILE
Se especificó IORING_REGISTER_FILES y nr_args excede el número máximo permitido de archivos en un conjunto de archivos fijo.
EMFILE
Se especificó IORING_REGISTER_FILES y agregar nr_args referencias de archivo excedería el número máximo permitido de archivos que el usuario puede tener según el límite de recursos RLIMIT_NOFILE y el llamante no tiene la capacidad CAP_SYS_RESOURCE. Ten en cuenta que este es un límite por usuario, no por proceso.
ENOMEM
No hay suficientes recursos del kernel disponibles, o el llamante tenía un límite de recursos blando RLIMIT_MEMLOCK distinto de cero, pero intentó bloquear más memoria de la permitida por el límite. Este límite no se aplica si el proceso está privilegiado (CAP_IPC_LOCK).
ENXIO
Se especificó IORING_UNREGISTER_BUFFERS o IORING_UNREGISTER_FILES, pero no había búferes o archivos registrados.
ENXIO
Intento de registrar archivos o búferes en una instancia de io_uring que ya está en proceso de registro de archivos o búferes, o se está desmantelando.
EOPNOTSUPP
Los búferes de usuario apuntan a memoria respaldada por archivos.
EFAULT
Los búferes de usuario apuntan a memoria respaldada por archivos (kernels más recientes).
ENOENT
Se especificó IORING_REGISTER_PBUF_STATUS, pero buf_group no se refería a un grupo de búferes actualmente válido.
EINVAL
Se especificó IORING_REGISTER_PBUF_STATUS, pero el grupo de búferes válido especificado por buf_group no se refería a un grupo de búferes registrado a través de IORING_REGISTER_PBUF_RING.
EINVAL
Se especificó IORING_REGISTER_NAPI, pero el anillo asociado con fd no se creó con IORING_SETUP_IOPOLL.
