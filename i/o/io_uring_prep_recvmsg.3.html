NOMBRE

io_uring_prep_recvmsg - preparar una solicitud recvmsg

SINOPSIS

#include <sys/types.h>
#include <sys/socket.h>
#include <liburing.h>
void io_uring_prep_recvmsg(struct io_uring_sqe *sqe,
                           int fd,
                           struct msghdr *msg,
                           unsigned flags);
void io_uring_prep_recvmsg_multishot(struct io_uring_sqe *sqe,
                                     int fd,
                                     struct msghdr *msg,
                                     unsigned flags);

DESCRIPCIÓN

La función io_uring_prep_recvmsg(3) prepara una solicitud recvmsg. La entrada de la cola de envío sqe se configura para usar el descriptor de archivo fd para comenzar a recibir los datos indicados por msg con las banderas definidas en recvmsg(2) en el argumento flags.

Esta función prepara una solicitud recvmsg(2) asíncrona. Consulte esa página del manual para obtener detalles sobre los argumentos especificados a esta ayuda de preparación.

La versión multishot permite a la aplicación emitir una única solicitud de recepción, que publica repetidamente una CQE cuando hay datos disponibles. Requiere que se establezca la bandera IOSQE_BUFFER_SELECT y que no se establezca la bandera MSG_WAITALL. Por lo tanto, cada CQE tomará un búfer de un grupo de búferes proporcionado para la recepción. La aplicación debe verificar las banderas de cada CQE, independientemente de su resultado. Si una CQE publicada no tiene la bandera IORING_CQE_F_MORE establecida, entonces la recepción multishot ha finalizado y la aplicación debe emitir una nueva solicitud si todavía desea recibir datos del socket.

A diferencia de recvmsg(2), recvmsg multishot antepondrá un struct io_uring_recvmsg_out que describe la disposición del resto del búfer en combinación con el struct msghdr inicial enviado con la solicitud. Consulte io_uring_recvmsg_out(3) para obtener más información sobre cómo acceder a los datos.

Las variantes multishot están disponibles desde el kernel 6.0.

Después de llamar a esta función, se pueden establecer modificadores internos adicionales de io_uring en el campo ioprio de la SQE. Las siguientes banderas son compatibles:

IORING_RECVSEND_POLL_FIRST
Si está establecida, io_uring asumirá que el socket está actualmente vacío y que intentar recibir datos no tendrá éxito. Para este caso, io_uring activará la sondeo interno y activará una recepción de los datos cuando el socket tenga datos para ser leídos. Este intento de recepción inicial puede ser desperdiciado para el caso en que se espera que el socket esté vacío, establecer esta bandera omitirá el intento de recepción inicial y pasará directamente a activar la sondeo. Si la sondeo indica que los datos están listos para ser recibidos, la operación procederá.

Se puede usar con la bandera IORING_CQE_F_SOCK_NONEMPTY de la CQE, que io_uring establecerá en las CQE después de una operación de recv(2) o recvmsg(2). Si está establecida, el socket todavía tenía datos para ser leídos después de que la operación se completara. Ambas banderas están disponibles desde 5.19.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res de la CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los valores posibles. Tenga en cuenta que donde las llamadas al sistema síncronas devolverán -1 en caso de error y establecerán errno al valor real del error, io_uring nunca utiliza errno. En su lugar, devuelve el errno negado directamente en el campo res de la CQE.

NOTAS

Al igual que con cualquier solicitud que pasa datos en una struct, esos datos deben permanecer válidos hasta que la solicitud se haya enviado correctamente. No es necesario que permanezcan válidos hasta la finalización. Una vez que se ha enviado una solicitud, el estado interno del kernel es estable. Los kernels muy antiguos (5.4 y anteriores) requerían que el estado fuera estable hasta que ocurriera la finalización. Las aplicaciones pueden probar este comportamiento inspeccionando la bandera IORING_FEAT_SUBMIT_STABLE devuelta por io_uring_queue_init_params(3).
