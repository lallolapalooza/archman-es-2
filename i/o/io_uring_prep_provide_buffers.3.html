NOMBRE

io_uring_prep_provide_buffers - prepara una solicitud de provisión de búferes

SINOPSIS

#include <liburing.h>
void io_uring_prep_provide_buffers(struct io_uring_sqe *sqe,
                                   void *addr,
                                   int len,
                                   int nr,
                                   int bgid,
                                   int bid);

DESCRIPCIÓN

La función io_uring_prep_provide_buffers(3) prepara una solicitud para proporcionar búferes al kernel. La entrada de la cola de envío sqe se configura para consumir nr búferes de tamaño len que comienzan en addr e identificados por el ID de grupo de búfer bgid y numerados secuencialmente a partir de bid.

Esta función configura una solicitud para proporcionar búferes al contexto io_uring que pueden ser utilizados por operaciones de lectura o recepción. Esto se hace rellenando el campo buf_group de la SQE y estableciendo IOSQE_BUFFER_SELECT en el miembro flags de la SQE. Si se utiliza la selección de búfer para una solicitud, no se debe proporcionar ningún búfer en el campo de dirección. En su lugar, el ID del grupo se establece para que coincida con uno que se proporcionó previamente al kernel. El kernel seleccionará entonces un búfer de este grupo para la operación de E/S. Tras la finalización exitosa de la solicitud de E/S, el campo flags de la CQE tendrá IORING_CQE_F_BUFFER establecido y el ID del búfer seleccionado se indicará mediante los 16 bits superiores del campo flags.

Los ID de grupo de búferes diferentes pueden ser utilizados por la aplicación para tener diferentes tamaños o tipos de búferes disponibles. Una vez que un búfer ha sido consumido para una operación, ya no es conocido por io_uring. Debe ser re-proporcionado si así se desea o liberado por la aplicación si ya no es necesario.

Los ID de búfer se rastrean internamente a partir de bid y ascienden secuencialmente a partir de ese valor. Si se proporcionan 16 búferes y comienzan con un bid inicial de 0, entonces los ID de búfer variarán de 0..15. La aplicación debe ser consciente de esto para dar sentido al ID de búfer devuelto en la CQE.

Los ID de búfer siempre varían de 0 a 65535, ya que solo hay 16 bits disponibles en la CQE para pasarlos. Este rango es independiente de cómo se creó inicialmente el grupo de búferes. Intentar agregar ID de búfer mayores que ese, o ID de búfer que se desborden al ser convertidos a un valor de 16 bits, hará que la solicitud falle con -E2BIG o -EINVAL.

No todas las solicitudes admiten la selección de búfer, ya que solo tiene sentido para solicitudes que reciben datos del kernel en lugar de escribir o proporcionar datos. Actualmente, este modo de operación es compatible con cualquier solicitud de lectura de archivo o recepción de socket. Intentar usar IOSQE_BUFFER_SELECT con un comando que no lo admita resultará en un error res de la CQE de -EINVAL. La selección de búfer funcionará con operaciones que toman un struct iovec como destino de datos, pero solo si se proporciona 1 iovec.

VALOR DE RETORNO

Ninguno

ERRORES

Estos son los errores que se informan en el campo res de la CQE. En caso de éxito, res contendrá 0 o el número de búferes proporcionados con éxito.

-ENOMEM
El kernel no pudo asignar memoria para la solicitud.
-EINVAL
Uno de los campos establecidos en la SQE era inválido.
-E2BIG
El número de búferes proporcionados era demasiado grande, o el bid era demasiado grande. Se puede especificar un valor máximo de USHRT_MAX búferes.
-EFAULT
Parte de la memoria de usuario proporcionada no era válida para la aplicación.
-EOVERFLOW
El producto de len y nr excedió la cantidad válida o se desbordó, o la suma de addr y la longitud de los búferes se desbordó.
-EBUSY
Intento de actualizar una ranura que ya está en uso.
