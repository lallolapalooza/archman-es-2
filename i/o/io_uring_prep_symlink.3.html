NOMBRE

io_uring_prep_symlinkat - prepara una solicitud symlinkat

SINOPSIS

#include <fcntl.h>
#include <unistd.h>
#include <liburing.h>
void io_uring_prep_symlinkat(struct io_uring_sqe *sqe,
                             const char *target,
                             int newdirfd,
                             const char *linkpath);
void io_uring_prep_symlink(struct io_uring_sqe *sqe,
                           const char *target,
                           const char *linkpath);

DESCRIPCIÓN

La función io_uring_prep_symlinkat(3) prepara una solicitud symlinkat. La entrada de la cola de envío (submission queue entry) sqe se configura para crear un enlace simbólico del camino de destino apuntado por target a la nueva ubicación indicada por newdirfd y linkpath.

La función io_uring_prep_symlink(3) prepara una solicitud symlink. La entrada de la cola de envío sqe se configura para crear un enlace simbólico del camino de destino apuntado por target a la nueva ubicación indicada por linkpath relativa al directorio de trabajo actual. Esta función prepara una solicitud symlink(2) asíncrona. Consulte esa página del manual para más detalles.

Estas funciones preparan una solicitud asíncrona symlinkat(2) o symlink(2). Consulte esas páginas del manual para más detalles.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res de la CQE (Completion Queue Entry) contendrá el resultado de la operación. Consulte la página del manual relacionada para conocer los posibles valores. Tenga en cuenta que donde las llamadas al sistema síncronas devolverán -1 en caso de fallo y establecerán errno al valor real del error, io_uring nunca usa errno. En su lugar, devuelve el errno negado directamente en el campo res de la CQE.

NOTAS

Como con cualquier solicitud que pasa datos en una estructura, esos datos deben permanecer válidos hasta que la solicitud se haya enviado con éxito. No es necesario que permanezcan válidos hasta la finalización. Una vez que una solicitud ha sido enviada, el estado en el kernel es estable. Los kernels muy tempranos (5.4 y anteriores) requerían que el estado fuera estable hasta que ocurriera la finalización. Las aplicaciones pueden probar este comportamiento inspeccionando el flag IORING_FEAT_SUBMIT_STABLE devuelto por io_uring_queue_init_params(3).
