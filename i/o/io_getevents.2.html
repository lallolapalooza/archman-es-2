io_getevents(2) Manual de llamadas al sistema io_getevents(2)

NOMBRE

io_getevents - leer eventos de E/S asíncronos de la cola de finalización

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

Alternativamente, biblioteca de E/S asíncronas (libaio, -laio); ver VERSIONES.

SINOPSIS

#include <linux/aio_abi.h>    /* Definición de tipos *io_* */
#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_io_getevents, aio_context_t ctx_id,
            long min_nr, long nr, struct io_event *events,
            struct timespec *timeout);

Nota: glibc no proporciona un envoltorio para io_getevents(), lo que obliga a usar syscall(2).

DESCRIPCIÓN

Nota: esta página describe la interfaz de llamada al sistema Linux nativa. La función envoltorio proporcionada por libaio utiliza un tipo diferente para el argumento ctx_id. Ver VERSIONES.

La llamada al sistema io_getevents() intenta leer al menos min_nr eventos y hasta nr eventos de la cola de finalización del contexto AIO especificado por ctx_id.

El argumento timeout especifica el tiempo a esperar por los eventos, y se especifica como un tiempo de espera relativo en una estructura timespec(3).

El tiempo especificado se redondeará al alza a la granularidad del reloj del sistema y se garantiza que no expirará anticipadamente.

Especificar timeout como NULL significa bloquear indefinidamente hasta obtener al menos min_nr eventos.

VALOR DE RETORNO

En caso de éxito, io_getevents() devuelve el número de eventos leídos. Puede ser 0, o un valor menor que min_nr, si el timeout expiró. También puede ser un valor distinto de cero menor que min_nr si la llamada fue interrumpida por un manejador de señal.

Para el retorno de error, ver VERSIONES.

ERRORES

EFAULT
Ya sea events o timeout es un puntero inválido.
EINTR
Interrumpido por un manejador de señal; ver signal(7).
EINVAL
ctx_id es inválido. min_nr está fuera de rango o nr está fuera de rango.
ENOSYS
io_getevents() no está implementado en esta arquitectura.

VERSIONES

Probablemente quieras usar la función envoltorio io_getevents() proporcionada por libaio.

Ten en cuenta que la función envoltorio de libaio usa un tipo diferente (io_context_t) para el argumento ctx_id. Ten en cuenta también que el envoltorio de libaio no sigue las convenciones habituales de la biblioteca C para indicar errores: en caso de error devuelve un número de error negado (el negativo de uno de los valores listados en ERRORES). Si la llamada al sistema se invoca a través de syscall(2), entonces el valor de retorno sigue las convenciones habituales para indicar un error: -1, con errno establecido a un valor (positivo) que indica el error.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.5.

ERRORES DE PROGRAMACIÓN

Un ctx_id inválido puede causar una falla de segmentación en lugar de generar el error EINVAL.

VER TAMBIÉN

io_cancel(2), io_destroy(2), io_setup(2), io_submit(2), timespec(3), aio(7), time(7)
