NOMBRE

io_uring_prep_readv - preparar solicitud de lectura I/O vectorial

SINOPSIS

#include <sys/uio.h>
#include <liburing.h>
void io_uring_prep_readv(struct io_uring_sqe *sqe,
                         int fd,
                         const struct iovec *iovecs,
                         unsigned nr_vecs,
                         __u64 offset);

DESCRIPCIÓN

La función io_uring_prep_readv(3) prepara una solicitud de lectura de IO vectorial. La entrada de la cola de envío sqe se configura para usar el descriptor de archivo fd para comenzar a leer nr_vecs en el array iovecs en el offset especificado.

En archivos que soportan búsqueda, si el offset se establece en -1, la operación de lectura comienza en el offset del archivo y el offset del archivo se incrementa por el número de bytes leídos. Ver read(2) para más detalles. Tenga en cuenta que para una API asíncrona, leer y actualizar el offset actual del archivo puede dar lugar a un comportamiento impredecible, a menos que el acceso al archivo esté serializado. No se recomienda usar esta característica si es posible proporcionar el offset de IO deseado desde la aplicación o biblioteca.

En archivos que no son capaces de búsqueda, el offset debe ser 0 o -1.

Una vez preparada la lectura, puede ser enviada con una de las funciones de envío.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res de la CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los valores posibles. Tenga en cuenta que mientras que las llamadas al sistema síncronas devolverán -1 en caso de fallo y establecerán errno al valor de error real, io_uring nunca usa errno. En su lugar, devuelve el errno negado directamente en el campo res de la CQE.

NOTAS

A menos que una aplicación necesite explícitamente pasar más de un iovec, es más eficiente usar io_uring_prep_read(3) en lugar de esta función, ya que no es necesario mantener ningún estado para una solicitud de IO no vectorial. Como con cualquier solicitud que pase datos en una estructura, esos datos deben permanecer válidos hasta que la solicitud haya sido enviada con éxito. No es necesario que permanezcan válidos hasta la finalización. Una vez enviada una solicitud, el estado en el kernel es estable. Los kernels muy tempranos (5.4 y anteriores) requerían que el estado fuera estable hasta que ocurriera la finalización. Las aplicaciones pueden probar este comportamiento inspeccionando el flag IORING_FEAT_SUBMIT_STABLE devuelto por io_uring_queue_init_params(3).
