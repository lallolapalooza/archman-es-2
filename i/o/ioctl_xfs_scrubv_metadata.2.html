ioctl_xfs_scrubv_metadata(2)

Paquete: xfsprogs

Licencias: GPL-2.0-only, LGPL-2.1-only

IOCTL-XFS-SCRUBV-METADATA(2) Manual de llamadas al sistema IOCTL-XFS-SCRUBV-METADATA(2)

NOMBRE

ioctl_xfs_scrubv_metadata - comprueba una gran cantidad de metadatos del sistema de archivos XFS

SINOPSIS

#include <xfs/xfs_fs.h>

int ioctl(int dest_fd, XFS_IOC_SCRUBV_METADATA, struct xfs_scrub_vec_head *arg);

DESCRIPCIÓN

Este ioctl de XFS pide al controlador del kernel que examine varias piezas de metadatos del sistema de archivos en busca de errores o metadatos subóptimos. Se pueden invocar múltiples tipos de limpieza para dirigirse a un único objeto del sistema de archivos. Consulte ioctl_xfs_scrub_metadata(2) para una discusión sobre la validación de metadatos y la documentación de los diversos valores de XFS_SCRUB_TYPE y XFS_SCRUB_FLAGS referenciados a continuación.

Los tipos y la ubicación de los metadatos a limpiar se transmiten como un vector con una cabecera de la siguiente forma:


struct xfs_scrub_vec_head {
	__u64 svh_ino;
	__u32 svh_gen;
	__u32 svh_agno;
	__u32 svh_flags;
	__u16 svh_rest_us;
	__u16 svh_nr;
	__u64 svh_reserved;
	__u64 svh_vectors;
};

El campo svh_ino, svh_gen y svh_agno corresponden a los campos sm_ino, sm_gen y sm_agno del ioctl de limpieza normal. Se puede especificar exactamente un objeto del sistema de archivos en una sola llamada. El kernel procederá con cada vector en svh_vectors hasta que el progreso ya no sea posible.

El campo svh_rest_us especifica una cantidad de tiempo para pausar entre cada invocación de limpieza para dar al sistema la oportunidad de procesar otras solicitudes.

El campo svh_nr especifica el número de vectores en la matriz svh_vectors.

El campo svh_vectors es un puntero a una matriz de estructuras struct xfs_scrub_vec.

El campo svh_reserved debe ser cero.

Cada vector tiene la siguiente forma:


struct xfs_scrub_vec {
	__u32 sv_type;
	__u32 sv_flags;
	__s32 sv_ret;
	__u32 sv_reserved;
};

Los campos sv_type y sv_flags indican el tipo de metadatos a comprobar y los cambios de comportamiento que el espacio de usuario permitirá al kernel. El campo sv_flags se actualizará al completar la llamada de limpieza. Consulte la documentación de los valores XFS_SCRUB_TYPE_* y XFS_SCRUB_[IO]FLAG_* en ioctl_xfs_scrub_metadata(2) para una descripción detallada de su propósito.

Si el campo sv_type de un vector se establece en el valor XFS_SCRUB_TYPE_BARRIER, el kernel dejará de procesar los vectores y devolverá el control al espacio de usuario si un depurador marca corrupción estableciendo uno de los valores XFS_SCRUB_OFLAG_* en sv_flags o devuelve un error de operación en sv_ret. De lo contrario, el kernel no devuelve hasta después de procesar todos los vectores.

El campo sv_ret se establece en el valor de retorno de la función de limpieza. Consulte la sección VALOR DE RETORNO de la página del manual de ioctl_xfs_scrub_metadata(2) para obtener más información.

El campo sv_reserved debe ser cero.

VALOR DE RETORNO

En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

Los códigos de error pueden ser uno de los siguientes, entre otros:

EINVAL
Uno o más de los argumentos especificados son inválidos.
EINTR
La operación fue interrumpida.
ENOMEM
No había suficiente memoria para realizar la operación de limpieza o reparación.
EFAULT
Se encontró un error de memoria al leer o escribir el vector.

CONFORME A

Esta API es específica del sistema de archivos XFS en el kernel de Linux.

NOTAS

Estas operaciones pueden bloquear otras operaciones del sistema de archivos durante mucho tiempo. Un proceso que llama puede detener la operación al recibir una señal fatal, pero las señales no fatales están bloqueadas.
