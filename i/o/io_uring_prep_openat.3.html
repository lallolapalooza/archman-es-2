NOMBRE

io_uring_prep_openat - prepara una solicitud de openat

SINOPSIS

#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <liburing.h>
void io_uring_prep_open(struct io_uring_sqe *sqe,
                          const char *path,
                          int flags,
                          mode_t mode);
void io_uring_prep_open_direct(struct io_uring_sqe *sqe,
                                 const char *path,
                                 int flags,
                                 mode_t mode,
                                 unsigned file_index);
void io_uring_prep_openat(struct io_uring_sqe *sqe,
                          int dfd,
                          const char *path,
                          int flags,
                          mode_t mode);
void io_uring_prep_openat_direct(struct io_uring_sqe *sqe,
                                 int dfd,
                                 const char *path,
                                 int flags,
                                 mode_t mode,
                                 unsigned file_index);

DESCRIPCIÓN

La función io_uring_prep_openat(3) prepara una solicitud de openat. La entrada de la cola de envío (submission queue entry) sqe se configura para usar el descriptor de archivo de directorio dfd para comenzar a abrir un archivo descrito por path y utilizando las banderas de apertura en flags y los bits de modo de archivo especificados en mode. De manera similar, io_uring_prep_open(3) prepara una solicitud de open.

Si se utiliza la variante directa, la aplicación debe haber registrado previamente una tabla de archivos usando io_uring_register_files(3) del tamaño apropiado. Una vez registrada, una solicitud de accept directa puede usar cualquier entrada de esa tabla y se especifica en file_index, siempre que esté dentro del tamaño de la tabla registrada. Si una entrada especificada ya contiene un archivo, el archivo primero se eliminará de la tabla y se cerrará. Es coherente con el comportamiento de actualizar un archivo existente con io_uring_register_files_update(3).

Si se usa IORING_FILE_INDEX_ALLOC como el file_index para una apertura directa, entonces io_uring asignará un descriptor directo libre en la tabla existente. El descriptor asignado se devuelve en el campo res de la CQE, de la misma manera que lo haría para una solicitud de apertura no directa. Si no quedan más entradas disponibles en la tabla de descriptores directos, se devuelve -ENFILE en su lugar.

Los descriptores directos son descriptores de archivo privados de io_uring. Evitan parte de la sobrecarga asociada con las tablas de archivos compartidas por hilos y pueden usarse en cualquier solicitud posterior de io_uring que requiera un descriptor de archivo. Para hacerlo, se debe establecer IOSQE_FIXED_FILE en el miembro flags de la SQE, y el campo fd de la SQE debe usar el valor del descriptor directo en lugar del descriptor de archivo regular. Los descriptores directos se gestionan como archivos registrados.

El descriptor de archivo de directorio dfd es siempre un descriptor de archivo regular.

Tenga en cuenta que los kernels antiguos no comprueban el campo file_index de la SQE, lo que no es un problema para las utilidades de liburing, pero los usuarios de la interfaz io_uring sin procesar deben poner a cero las SQE para evitar un comportamiento inesperado.

Estas funciones preparan una solicitud asíncrona de openat(2) o open(2). Consulte esa página del manual para obtener detalles.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res de la CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los valores posibles. Tenga en cuenta que donde las llamadas al sistema síncronas devuelven -1 en caso de error y establecen errno al valor de error real, io_uring nunca usa errno. En su lugar, devuelve el errno negado directamente en el campo res de la CQE.

NOTAS

Al igual que con cualquier solicitud que pasa datos en una estructura, esos datos deben permanecer válidos hasta que la solicitud se haya enviado correctamente. No es necesario que permanezcan válidos hasta la finalización. Una vez que se ha enviado una solicitud, el estado en el kernel es estable. Los kernels muy tempranos (5.4 y anteriores) requerían que el estado fuera estable hasta que ocurriera la finalización. Las aplicaciones pueden probar este comportamiento inspeccionando el indicador IORING_FEAT_SUBMIT_STABLE devuelto por io_uring_queue_init_params(3).
