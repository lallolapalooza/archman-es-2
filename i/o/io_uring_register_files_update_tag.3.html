NOMBRE

io_uring_register_files - registrar descriptores de archivo

SINOPSIS

#include <liburing.h>
int io_uring_register_files(struct io_uring *ring,
                            const int *files,
                            unsigned nr_files);
int io_uring_register_files_tags(struct io_uring *ring,
                                 const int *files,
                                 const __u64 *tags,
                                 unsigned nr);
int io_uring_register_files_sparse(struct io_uring *ring,
                                   unsigned nr_files);
int io_uring_register_files_update(struct io_uring *ring,
                                   unsigned off,
                                   const int *files,
                                   unsigned nr_files);
int io_uring_register_files_update_tag(struct io_uring *ring,
                                   unsigned off,
                                   const int *files,
                                   const __u64 *tags,
                                   unsigned nr_files);

DESCRIPCIÓN

La función io_uring_register_files(3) registra nr_files número de descriptores de archivo definidos por el array files pertenecientes al ring para operaciones subsiguientes.

La función io_uring_register_files_tags(3) se comporta igual que la función io_uring_register_files(3) pero además toma el parámetro tags. Ver IORING_REGISTER_BUFFERS2 para la descripción del etiquetado de recursos.

La función io_uring_register_files_sparse(3) registra una tabla de archivos vacía de nr_files número de descriptores de archivo. Estos archivos deben ser actualizados antes de su uso, utilizando por ejemplo io_uring_register_files_update_tag(3). Tenga en cuenta que si el tamaño de la tabla dispersa excede lo que RLIMIT_NOFILE permite, entonces io_uring_register_files_sparse(3) intentará aumentar el límite usando setrlimit (2) y reintentará la operación. Si el registro falla después de hacer eso, entonces se devolverá un error. La variante dispersa está disponible en kernels 5.19 y posteriores.

Registrar una tabla de archivos es un requisito previo para usar cualquier solicitud que utilice descriptores directos.

Los archivos registrados tienen menos sobrecarga por operación que los archivos normales. Esto se debe a que el kernel toma una cuenta de referencia sobre un archivo cuando una operación comienza, y la libera cuando termina. Cuando la tabla de archivos del proceso se comparte, por ejemplo si el proceso alguna vez ha creado hilos, entonces este costo aumenta aún más. El uso de archivos registrados reduce la sobrecarga de la gestión de referencias de archivos a través de solicitudes que operan sobre un archivo.

La función io_uring_register_files_update(3) actualiza los archivos registrados existentes. El off es el desplazamiento en el que comenzar la actualización de nr_files número de archivos definidos por el array files pertenecientes al ring.

La función io_uring_register_files_update_tag(3) se comporta igual que la función io_uring_register_files_update(3) pero además toma el parámetro tags. Ver IORING_REGISTER_BUFFERS2 para la descripción del etiquetado de recursos.

VALOR DE RETORNO

En caso de éxito, io_uring_register_files(3), io_uring_register_files_tags(3) y io_uring_register_files_sparse(3) devuelven 0. io_uring_register_files_update(3) y io_uring_register_files_update_tag(3) devuelven el número de archivos actualizados. En caso de fallo, devuelven -errno.
