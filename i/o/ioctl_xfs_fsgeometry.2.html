NOMBRE

ioctl_xfs_fsgeometry - informa sobre la disposición y las características del sistema de archivos XFS

SINOPSIS

#include <xfs/xfs_fs.h>

int ioctl(int fd, XFS_IOC_FSGEOMETRY, struct xfs_fsop_geom *arg);
int ioctl(int fd, XFS_IOC_FSGEOMETRY_V4, struct xfs_fsop_geom_v4 *arg);
int ioctl(int fd, XFS_IOC_FSGEOMETRY_V1, struct xfs_fsop_geom_v1 *arg);

DESCRIPCIÓN

Informa los detalles de la disposición del sistema de archivos XFS, sus características y otros elementos descriptivos. Esta información se transmite en una estructura de la siguiente forma:


struct xfs_fsop_geom {
	__u32         blocksize;
	__u32         rtextsize;
	__u32         agblocks;
	__u32         agcount;
	__u32         logblocks;
	__u32         sectsize;
	__u32         inodesize;
	__u32         imaxpct;
	__u64         datablocks;
	__u64         rtblocks;
	__u64         rtextents;
	__u64         logstart;
	unsigned char uuid[16];
	__u32         sunit;
	__u32         swidth;
	__s32         version;
	__u32         flags;
	__u32         logsectsize;
	__u32         rtsectsize;
	__u32         dirblocksize;
	/* La struct xfs_fsop_geom_v1 termina aquí. */
	__u32         logsunit;
	/* La struct xfs_fsop_geom_v4 termina aquí. */
	__u32         sick;
	__u32         checked;
	__u64         rgextents;
	__u64	      rtstart;
	__u64         rtreserved;
	__u64         reserved[14];
};

blocksize es el tamaño de un bloque fundamental del sistema de archivos, en bytes.

rtextsize es el tamaño de una extensión en el volumen de tiempo real, en bytes.

agblocks es el tamaño de un grupo de asignación, en unidades de bloques del sistema de archivos.

agcount es el número de grupos de asignación en el sistema de archivos.

logblocks es el tamaño del registro (log), en unidades de bloques del sistema de archivos.

sectsize es la cantidad más pequeña de datos que puede escribirse en el dispositivo de datos de forma atómica, en bytes.

inodesize es el tamaño de un registro de inode, en bytes.

imaxpct es el porcentaje máximo del sistema de archivos que puede asignarse a bloques de registros de inodes.

datablocks es el tamaño del dispositivo de datos, en unidades de bloques del sistema de archivos.

rtblocks es el tamaño del dispositivo de tiempo real, en unidades de bloques del sistema de archivos.

rtextents es el número de extensiones que pueden asignarse en el dispositivo de tiempo real.

logstart es el inicio del registro (log), en unidades de bloques del sistema de archivos. Si el sistema de archivos tiene un registro externo, este valor será cero.

uuid es el identificador universal único del sistema de archivos.

sunit es lo que se le ha indicado al sistema de archivos que es el tamaño de una unidad de banda RAID en el dispositivo de datos subyacente, en bloques del sistema de archivos.

swidth es lo que se le ha indicado al sistema de archivos que es el ancho de una banda RAID en el dispositivo de datos subyacente, en unidades de bandas RAID.

version es la versión de esta estructura. Este valor será XFS_FSOP_GEOM_VERSION.

flags indican qué características están habilitadas en el sistema de archivos. Consulte la sección BANDERAS DE CARACTERÍSTICAS DEL SISTEMA DE ARCHIVOS más abajo para obtener más información sobre cada característica.

logsectsize es la cantidad más pequeña de datos que puede escribirse en el dispositivo de registro de forma atómica, en bytes.

rtsectsize es la cantidad más pequeña de datos que puede escribirse en el dispositivo de tiempo real de forma atómica, en bytes.

dirblocksize es el tamaño de los bloques de directorio, en bytes.

logsunit es lo que se le ha indicado al sistema de archivos que es el tamaño de una unidad de banda RAID en el dispositivo de registro subyacente, en bloques del sistema de archivos. Este campo solo es significativo si la bandera XFS_FSOP_GEOM_FLAGS_LOGV2 está establecida.

Los campos sick y checked indican el estado relativo de diversos metadatos de todo el sistema de archivos. Consulte la sección INFORME DE SALUD DE METADATOS DE XFS para más detalles.

rgextents Es el número de extensiones de tiempo real en cada grupo de tiempo real (rtgroup).

rtstart Inicio del dispositivo de tiempo real interno en bloques del sistema de archivos (fsblocks). 0 si se usa un dispositivo de tiempo real externo. Este campo solo es significativo si la bandera XFS_FSOP_GEOM_FLAGS_ZONED está establecida.

rtreserved La cantidad de espacio en la sección de tiempo real que está reservada para uso interno por los algoritmos de recolección de basura y reorganización en bloques del sistema de archivos (fsblocks). Este campo solo es significativo si la bandera XFS_FSOP_GEOM_FLAGS_ZONED está establecida.

reserved se establece en cero.

BANDERAS DE CARACTERÍSTICAS DEL SISTEMA DE ARCHIVOS

Las características del sistema de archivos se informan al espacio de usuario como una combinación de las siguientes banderas:

XFS_FSOP_GEOM_FLAGS_ATTR
Están presentes los atributos extendidos.
XFS_FSOP_GEOM_FLAGS_NLINK
Los archivos en este sistema de archivos admiten hasta 2^32 enlaces duros. Si esta bandera no está establecida, los archivos en este sistema de archivos admiten solo hasta 2^16 enlaces duros.
XFS_FSOP_GEOM_FLAGS_QUOTA
Las cuotas están habilitadas.
XFS_FSOP_GEOM_FLAGS_IALIGN
Los inodes están alineados para un mejor rendimiento.
XFS_FSOP_GEOM_FLAGS_DALIGN
El sistema de archivos intenta alinear las asignaciones de bloques de datos a unidades de banda RAID para un mejor rendimiento.
XFS_FSOP_GEOM_FLAGS_SHARED
No se usa.
XFS_FSOP_GEOM_FLAGS_EXTFLG
El sistema de archivos admite extensiones no escritas.
XFS_FSOP_GEOM_FLAGS_DIRV2
Los directorios están en formato versión 2 y mantienen datos de espacio libre para un mejor rendimiento. Los directorios en formato versión 1 ya no son compatibles.
XFS_FSOP_GEOM_FLAGS_LOGV2
El registro (log) usa el formato V2.
XFS_FSOP_GEOM_FLAGS_SECTOR
El dispositivo de registro tiene un tamaño de sector mayor de 512 bytes.
XFS_FSOP_GEOM_FLAGS_ATTR2
El sistema de archivos contiene atributos extendidos V2.
XFS_FSOP_GEOM_FLAGS_PROJID32
Los identificadores de proyecto (Project IDs) pueden ser tan grandes como 2^32. Si esta bandera no está establecida, el sistema de archivos admite solo 2^16 identificadores de proyecto.
XFS_FSOP_GEOM_FLAGS_DIRV2CI
Se admiten búsquedas sin distinción de mayúsculas y minúsculas en los directorios.
XFS_FSOP_GEOM_FLAGS_LAZYSB
Los contadores del superbloque en disco se actualizan solo en el momento de la desmontaje.
XFS_FSOP_GEOM_FLAGS_V5SB
Los bloques de metadatos se describen a sí mismos y contienen sumas de verificación.
XFS_FSOP_GEOM_FLAGS_FTYPE
Los directorios contienen tipos de inode en las entradas de directorio.
XFS_FSOP_GEOM_FLAGS_FINOBT
El sistema de archivos mantiene un índice de inodes libres.
XFS_FSOP_GEOM_FLAGS_SPINODES
El sistema de archivos puede asignar trozos de inodes no contiguos cuando el espacio libre está fragmentado.
XFS_FSOP_GEOM_FLAGS_RMAPBT
El sistema de archivos almacena mapeos inversos de bloques a sus propietarios.
XFS_FSOP_GEOM_FLAGS_REFLINK
El sistema de archivos admite el uso compartido de bloques entre archivos.

NAME

ioctl_xfs_fsgeometry, XFS_IOC_FSGEOMETRY - get XFS filesystem geometry

SYNOPSIS

#include <sys/ioctl.h>
#include <xfs/xfs.h>

int ioctl(int fd, XFS_IOC_FSGEOMETRY, struct xfs_fs geometría *);

DESCRIPTION

The ioctl_xfs_fsgeometry system call, invoked via the XFS_IOC_FSGEOMETRY ioctl request code, retrieves filesystem geometry information for the filesystem associated with the open file descriptor fd. The geometry information is returned in the structure pointed to by argp, which is a pointer to a struct xfs_fsgeometry.

The struct xfs_fsgeometry is defined as follows:

struct xfs_fsgeometry {
    unsigned long       uf_version;     // version of the structure
    unsigned long       uf_size;        // size of the structure
    __int64_t           uf_blocksize;   // block size
    __int64_t           uf_nblocks;     // total blocks in filesystem
    __int64_t           uf_rtextents;   // total real time extents
    __int64_t           uf_rbamxticks;  // number of blocks for realtime bitmap
    __int64_t           uf_agblklog;    // log2 of number of blocks per allocation group
    __int64_t           uf_logblks;     // number of log blocks
    unsigned int        uf_flags;       // fsgeometry flags
    unsigned int        uf_type;        // filesystem type
    __int64_t           uf_dblocks;     // data blocks
    __int64_t           uf_agecount;    // number of aging counts
    unsigned int        uf_unit;        // allocation unit
    unsigned int        uf_width;       // stripe width
    __int64_t           uf_rsumbands;   // realtime sum bands
    __int64_t           uf_agcount;     // number of allocation groups
    __int64_t           uf_maxpct;      // max percent for any inode
    __int64_t           uf_imaxpct;     // max percent for inode table
    __int64_t           uf_reserved1;   // reserved for future use
    __int64_t           uf_reserved2;   // reserved for future use
    __int64_t           uf_spincount;   // spin count for metadata
    __int64_t           uf_resuid;      // reserved user ID
    __int64_t           uf_resgid;      // reserved group ID
    __int64_t           uf_realtime_ino; //ino for realtime data
    unsigned long       uf_inoalign;    // inode alignment factor
    unsigned long       uf_irlog;       // inode ratio log
    unsigned long       uf_iclog;       // inode count log
    __int64_t           uf_resblks;     // reserved blocks
    __int64_t           uf_allocmask;   // Allocator mask
    __int64_t           uf_fslog;       // fs log
    __int64_t           uf_allocgroup;  // Allocator group

Fields that are reserved for future use are set to zero.

The uf_version field must be set to XFS_FSGEOMETRY_VERSION before calling ioctl.

The uf_size field must be set to the size of the struct xfs_fsgeometry before calling ioctl.

The fields uf_allocmask, uf_fslog, uf_allocgroup, uf_alloc_state, and uf_ftype are only valid if the filesystem was created with XFS filesystem features enabled.

The following flags can be set in uf_flags:

XFS_FSOP_GEOM_FLAGS_EXCHANGE_RANGE
Filesystem can exchange file contents atomically via XFS_IOC_EXCHANGE_RANGE.
XFS_FSOP_GEOM_FLAGS_METADIR
Filesystem contains a metadata directory tree.
XFS_FSOP_GEOM_FLAGS_ZONED
Filesystem uses the zoned allocator for the RT device.

XFS METADATA HEALTH REPORTING

The online filesystem checking utility scans metadata and records what it finds in the kernel incore state. The following scheme is used for userspace to read the incore health status of the filesystem:

•
If a given sick flag is set in sick, then that piece of metadata has been observed to be damaged. The same bit should be set in checked.
•
If a given sick flag is set in checked but is not set in sick, then that piece of metadata has been checked and is not faulty.
•
If a given sick flag is not set in checked, then no conclusion can be made.

The following flags apply to these fields:

XFS_FSOP_GEOM_SICK_COUNTERS
Inode and space summary counters.
XFS_FSOP_GEOM_SICK_UQUOTA
User quota information.
XFS_FSOP_GEOM_SICK_GQUOTA
Group quota information.
XFS_FSOP_GEOM_SICK_PQUOTA
Project quota information.
XFS_FSOP_GEOM_SICK_RT_BITMAP
Free space bitmap for the realtime device.
XFS_FSOP_GEOM_SICK_RT_SUMMARY
Free space summary for the realtime device.
XFS_FSOP_GEOM_SICK_QUOTACHECK
Quota resource usage counters.

RETURN VALUE

On error, -1 is returned, and errno is set to indicate the error.

ERRORS

Error codes can be one of, but are not limited to, the following:

EFAULT
The kernel was not able to copy into the userspace buffer.
EFSBADCRC
Metadata checksum validation failed while performing the query.
EFSCORRUPTED
Metadata corruption was encountered while performing the query.
EIO
An I/O error was encountered while performing the query.

CONFORMING TO

This API is specific to XFS filesystem on the Linux kernel.
