NOMBRE

io_uring_setup_reg_wait - Configura y registra regiones de espera fijas

SINOPSIS

#include <liburing.h>
struct io_uring_reg_wait *io_uring_setup_reg_wait(struct io_uring *ring,
                                                  unsigned nentries,
                                                  int *err);

DESCRIPCIÓN

La función io_uring_setup_reg_wait(3) asigna y registra una región de espera fija de nentries entradas. Tras una ejecución exitosa, la función devuelve un puntero no nulo. En caso de error, devuelve NULL y rellena err con el valor del error.

Una región de espera registrada es un rango contiguo de structio_uring_reg_wait, que se ve así:

struct io_uring_reg_wait {
    struct __kernel_timespec ts;
    __u32                    min_wait_usec;
    __u32                    flags;
    __u64                    sigmask;
    __u32                    sigmask_sz;
    __u32                    pad[3];
    __u64                    pad2[2];
};
donde ts es la información relacionada con la espera para esta espera, min_wait_usec es el período mínimo de espera (para una espera de dos etapas), si se establece a un valor distinto de cero, flags informa al kernel sobre la región de espera, sigmask es un puntero a una máscara de señales, si se utiliza, y sigmask_sz es el tamaño de la máscara de señales, si se utiliza.

Actualmente, la única bandera válida es IORING_REG_WAIT_TS , que, si está establecida, indica que el valor en ts es válido y debe utilizarse para la operación de espera.

Se utiliza una máscara de señales para la espera, si sigmask está configurado en un puntero válido y distinto de cero. Si se utiliza, sigmask_sz también debe estar configurado.

Cada una de las regiones de espera se indica mediante el desplazamiento de la estructura. La primera región de espera es el índice 0 , la siguiente es el índice 1 , y así sucesivamente, hasta el número registrado de regiones establecido por nentries.

Las regiones de espera pueden ser modificadas por una aplicación en cualquier momento antes de llamar a io_uring_submit_and_reg_wait(3). Si se modifican mientras el kernel está utilizando una región de espera para ese desplazamiento dado, los resultados no están definidos; el kernel puede ver el nuevo valor a tiempo para usarlo, o puede que no.

El propósito principal de las regiones de espera registradas y los asistentes de envío y espera asociados es reducir la sobrecarga de una operación de espera. Una espera normal de eventos con un tiempo de espera agotado pasará una structio_uring_getevents_arg, que deberá copiarse para cada espera. Para operaciones de espera de alta frecuencia, esto añade una sobrecarga notable para cada espera. Con regiones de espera registradas, no es necesario realizar tales copias para cada espera.

Una vez que una región de espera ha sido configurada, persiste durante toda la vida del anillo. Actualmente no es posible anular el registro o cambiar el tamaño de una región de espera. Además, una región de espera actualmente solo puede utilizar una sola página de memoria. En un sistema con tamaño de página de 4k, esto significa que una aplicación está limitada a 64 regiones de espera. Esto debería ser suficiente, ya que cada índice de espera puede modificarse según sea necesario. Con al menos 64 índices disponibles, se espera que las aplicaciones simplemente utilicen la región de espera configurada apropiadamente para cada tipo de espera específico, con índices diferentes teniendo diferentes configuraciones de espera.

Si bien una región no puede ser anulada del registro del kernel, una vez que se ha cerrado un anillo, la aplicación puede liberar la memoria asociada llamando a io_uring_free_reg_wait(3). Una aplicación también puede hacerlo antes de cerrar un anillo, pero entonces las regiones de espera ya no podrán ser modificadas por la aplicación.

Disponible desde el kernel 6.13.

VALOR DE RETORNO

En caso de éxito, io_uring_setup_reg_wait(3) devuelve un puntero al inicio de las regiones de espera. En caso de fallo, devuelve NULL y establece err al valor -errno apropiado.
