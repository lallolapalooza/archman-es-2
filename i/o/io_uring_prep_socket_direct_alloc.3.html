NOMBRE

io_uring_prep_socket - prepara una solicitud de creación de socket

SINOPSIS

#include <sys/socket.h>
#include <liburing.h>
void io_uring_prep_socket(struct io_uring_sqe *sqe,
                          int domain,
                          int type,
                          int protocol,
                          unsigned int flags);
void io_uring_prep_socket_direct(struct io_uring_sqe *sqe,
                                 int domain,
                                 int type,
                                 int protocol,
                                 unsigned int file_index,
                                 unsigned int flags);
void io_uring_prep_socket_direct_alloc(struct io_uring_sqe *sqe,
                                 int domain,
                                 int type,
                                 int protocol,
                                 unsigned int flags);

DESCRIPCIÓN

La función io_uring_prep_socket(3) prepara una solicitud de creación de socket. La entrada de la cola de envío sqe se configura para usar el dominio de comunicación definido por domain y usar el tipo de comunicación definido por type y el protocolo establecido por protocol. El argumento flags no se utiliza actualmente.

La ayuda io_uring_prep_socket_direct(3) funciona igual que io_uring_prep_socket(3), excepto que mapea el socket a un descriptor directo en lugar de devolver un descriptor de archivo normal. El argumento file_index debe establecerse en la ranura que se utilizará para este socket.

La ayuda io_uring_prep_socket_direct_alloc(3) funciona igual que io_uring_prep_socket_direct(3), excepto que asigna un nuevo descriptor directo en lugar de pasar una ranura libre. Es equivalente a usar io_uring_prep_socket_direct(3) con IORING_FILE_INDEX_ALLOC como file_index. Tras la finalización, el campo res del CQE devolverá la ranura directa que se asignó para el socket.

Si se utilizan las variantes directas, la aplicación debe haber registrado primero una tabla de archivos usando io_uring_register_files(3) del tamaño apropiado. Una vez registrada, una solicitud de socket directo puede usar cualquier entrada de esa tabla, siempre que esté dentro del tamaño de la tabla registrada. Si una entrada especificada ya contiene un archivo, el archivo se eliminará primero de la tabla y se cerrará. Es coherente con el comportamiento de actualizar un archivo existente con io_uring_register_files_update(3).

Para una solicitud de socket con descriptor directo, el argumento file_index se puede establecer en IORING_FILE_INDEX_ALLOC. En este caso, se utilizará automáticamente una entrada libre en la tabla de archivos de io_uring y el índice del archivo se devolverá como el res del CQE. De lo contrario, se devolverá -ENFILE si no hay entradas libres en la tabla de archivos de io_uring.

Estas funciones preparan una solicitud asíncrona de socket(2). Consulte esa página del manual para obtener detalles.

VALOR DE RETORNO

Ninguno

ERRORES

El campo res del CQE contendrá el resultado de la operación. Consulte la página del manual relacionada para obtener detalles sobre los valores posibles. Tenga en cuenta que mientras las llamadas al sistema síncronas devolverán -1 en caso de error y establecerán errno al valor de error real, io_uring nunca usa errno. En su lugar, devuelve el errno negado directamente en el campo res del CQE.

VER TAMBIÉN

io_uring_get_sqe(3), io_uring_submit(3), socket(2)
