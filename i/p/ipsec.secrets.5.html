Para autenticar una conexión entre dos hosts, se utiliza la entrada que coincide más específicamente con los ID del host y del par. Una entrada sin selectores coincidirá con cualquier host y par. Más específicamente, una entrada con un selector coincidirá con un host y par si el selector coincide con el ID del host (el par no se tiene en cuenta). Aún más específicamente, una entrada con múltiples selectores coincidirá con un host y par si el ID del host y el ID del par coinciden cada uno con uno de los selectores. Si la clave es para una técnica de autenticación asimétrica (es decir, un sistema de clave pública como RSA), una entrada con múltiples selectores coincidirá con un host y par incluso si solo el ID del host coincide con un selector (se presume que los selectores son todas identidades del host). Es aceptable que dos entradas sean la mejor coincidencia siempre que estén de acuerdo sobre el secreto o la clave privada. La autenticación por secreto precompartido requiere que ambos sistemas encuentren el secreto idéntico (el secreto no es realmente transmitido por el protocolo IKE). Si tanto el host como el par aparecen en la lista de selectores, la misma entrada será adecuada para ambos sistemas, por lo que se puede usar la copia literal entre sistemas. Esto se extiende naturalmente a grupos más grandes que comparten el mismo secreto. Por lo tanto, las entradas con múltiples selectores son las mejores para la autenticación PSK. La autenticación por sistemas de clave pública como RSA requiere que cada host tenga su propia clave privada. Un host podría usar razonablemente diferentes claves privadas para diferentes interfaces y para diferentes pares. Pero no sería normal compartir entradas entre sistemas. Por lo tanto, las formas de entrada sin selector y con un selector suelen tener sentido para la autenticación por clave pública.
