DESCRIPCIÓ

N

Iptables e ip6tables se utilizan para configurar, mantener e inspeccionar las tablas de reglas de filtrado de paquetes IPv4 e IPv6 en el núcleo de Linux. Pueden definirse varias tablas diferentes. Cada tabla contiene una serie de cadenas incorporadas y también puede contener cadenas definidas por el

usuario.

Cada cadena es una lista de reglas que pueden coincidir con un conjunto de paquetes.

Cada regla especifica qué hacer con un paquete que coincide. Esto se denomina un `des
tino', que puede ser un salto a una cadena definida por el usuario en la misma tabla.

DESTINO

S

Una regla de firewall especifica criterios para un paquete y un destino. Si el paquete no coincide, se examina la siguiente regla en la cadena; si coincide, la siguiente regla la determina el valor del destino, que puede ser el nombre de una cadena definida por el usuario, uno de los destinos descritos en iptables-extensions(8), o uno de los valores especiales ACCEPT, DROP o RETURN

.

ACCEPT significa dejar pasar el paquete. DROP significa descartar el paquete. RETURN significa dejar de recorrer esta cadena y reanudar en la siguiente regla de la cadena anterior (la que llamó). Si se alcanza el final de una cadena incorporada o se coincide con una regla en una cadena incorporada con destino RETURN, el destino especificado por la política d

e la cadena determina
el destino del paquete.

nat

Esta tabla se consulta cuando se encuentra un paquete que crea una nueva conexión. Consiste en cuatro incorporadas: PREROUTING (para alterar paquetes en cuanto entran), INPUT (para alterar paquetes destinados a sockets locales), OUTPUT (para alterar paquetes generados localmente antes del enrutamiento), y POSTROUTING (para alterar paquetes cuando están a punto de salir). El soporte de NAT para IPv6 está disponible desde el núcleo
3.7.
mangl
e:
Esta tabla se utiliza para la alteración especializada de paquetes. Hasta el núcleo 2.4.17 tenía dos cadenas incorporadas: PREROUTING (para alterar paquetes entrantes antes del enrutamiento) y OUTPUT (para alterar paquetes generados localmente antes del enrutamiento). Desde el núcleo 2.4.18, también se admiten otras tres cadenas incorporadas: INPUT (para paquetes que entran en el propio equipo), FORWARD (para alterar paquetes que se enrutan a través del equipo), y POSTROUTING (para alterar paquetes cuando están a punto de salir)
.
raw
:
Esta tabla se utiliza principalmente para configurar exenciones del seguimiento de conexiones en combinación con el destino NOTRACK. Se registra en los hooks de netfilter con mayor prioridad y por lo tanto se llama antes que ip_conntrack, o cualquier otra tabla IP. Proporciona las siguientes cadenas incorporadas: PREROUTING (para paquetes que llegan a través de cualquier interfaz de red) y OUTPUT (para paquetes generados por procesos locales)
.
securit
y:
Esta tabla se utiliza para reglas de red de Control de Acceso Obligatorio (MAC), como las habilitadas por los destinos SECMARK y CONNSECMARK. El Control de Acceso Obligatorio está implementado por Módulos de Seguridad de Linux como SELinux. La tabla security se llama después de la tabla filter, permitiendo que cualquier regla de Control de Acceso Discrecional (DAC) en la tabla filter surta efecto antes que las reglas MAC. Esta tabla proporciona las siguientes cadenas incorporadas: INPUT (para paquetes que entran en el propio equipo), OUTPUT (para alterar paquetes generados localmente antes del enrutamiento), y FORWARD (para alterar
paquetes que

COMPATIBILITY WITH

IPCHAINS

This iptables is very similar to ipchains by Rusty Russell. The main difference is that the chains INPUT and OUTPUT are only traversed for packets coming into the local host and originating from the local host respectively. Hence every packet only passes through one of the three chains (except loopback traffic, which involves both INPUT and OUTPUT chains); previously a forwarded packet would pass through all

three.

The other main difference is that -i refers to the input interface; -o refers to the output interface, and both are available for packets entering the FORWARD c

hain.

The various forms of NAT have been separated out; iptables is a pure packet filter when using the default `filter' table, with optional extension modules. This should avoid much of the confusion over the combination of IP masquerading and packet filtering seen previously. So the following options are handled

differently: 
 -j MASQ
 -M -S
 -M -L
There are several other changes in
iptables.
