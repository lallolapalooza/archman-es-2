DESCRIPCIÓ

N

ipmi_cmdlang es un lenguaje de comandos diseñado para proporcionar toda la potencia de OpenIPMI en una línea de comandos. Tiene un gran número de comandos y respuestas bien formadas para cada comando. Tenga en cuenta que esto asume algún conocimiento de OpenIPMI y cómo funciona; puede obtenerlo del documento IPMI que viene con

OpenIPMI.

ipmish se inicia sin conexiones ni nada de ese tipo. Debe ingresar comandos para establecer conexiones con dominios. Luego puede ingresar comandos para manipular esos dominios u objetos dentro de esos

dominios.

Tenga en cuenta que puede usar comillas, ya sea '' o para contener parám

etros con
espacios.

COMENTARIO

S

Las líneas con un carácter # en la primera co

lumna se
ignoran.

OBJETO

S

En el lenguaje de comandos, tratará con varios objetos como sensores, controles, dominios y entidades. Cada uno de estos tiene un nombre. El nombre del dominio es asignado por el usuario en el comando domain new, todos los demás nombres se basan en el nombre del dominio al que pertenecen y varios atributos sobre el objeto. Todos estos nombres están bien formados.

Son

<domain> - Un nombre de un dominio. Cada dominio registrado en un sistema tiene un nombre asignado por el

usuario.

<entity> - Los nombres de entidad tienen la

forma:
[<domain>[(<entity spec>)]] Tenga en
cuenta que el <entity spec> es opcional. Si no se lista, entonces la operación se realiza en todas las entidades del dominio. Todo el asunto es opcional también, si no se da nada entonces la operación se realiza en cada entidad en cada dominio.

El <entity spec> es o

bien
<entity id>.<entity instance>
para entidades relativas al sistema, o:
r<channel>.<IPMB>.<entity id>.<entity instance-0x60>
para entidades relativas al dispositivo. En IPMI, las instancias de entidades relativas al dispositivo siempre comienzan en 0x60; la especificación sugiere que reste el 0x60 de la instancia de entidad al mostrar estas; el lenguaje de comandos sigue esta sugerencia.

<sensor> - Estos vienen en la

forma
[<entity>[.name]]
Al igual que con las entidades, solo listar un dominio hará que la operación se realice en cada sensor del dominio, solo listar una entidad hará que se realice en cada sensor en esa entidad. Una entrada de sensor vacía hará que una operación se realice en cada sensor en cada dominio.

<control> - Estos vienen en la

forma
[<entity>[.name]]
Estos funcionan exactamente como los sensores.

<mc> - Un controlador de gestión. Estos vienen en la

forma
[<domain>[(<channel>.<IPMB>)]] Como de
costumbre, las partes dejadas vacías causarán que se usen los valores predeterminados para todas las cosas en las partes especificadas previamente.

<connection> - Un número de conexión, en la

forma
[<domain>[.<integer>]
] El número es el número de conexión del dominio.

<pet> - Un id de trampa de eventos de plataforma, en la

forma
[<domain>[.<integer>]]
El número es asignado arbitrariamente por el sistema.

<lanparm> - Un id de parámetro LAN, en la

forma
[<domain>[.<integer>]]
El número es asignado arbitrariamente por el sistema.

<pef> - Un id de PEF, en la

forma
[<domain>[.<integer>]]
El número es asignado arbitrariamente por el sistema.

<fru> - Un id de FRU, en la

forma
[<domain>[.<integer>]]
El número es asignado arbitrariamente por el sistema.

En todos los casos, los nombres de objeto tienen partes que son opcionales, y el nombre completo del objeto es opcional. Si una parte se deja vacía, entonces todos los objetos que son parte de las partes especificadas son operados. Por ejemplo, si el sistema tiene un sensor llamado d1(7.1).temp entonces especificar d1 operaría en todos los sensores en el dominio llamado d1. Especificar d1(7.1) operaría en todos los sensores en esa entidad. Especificar un nombre vacío, ya sea con o simplemente ingresando nada si el objeto es la última cosa en los parámetros del

comando.

Tenga en cuenta que esta opcionalidad da mucho poder, pero puede ser muy peligrosa. Ingresar domain close cerraría cada dominio, por

ejemplo.

En los comandos, cada objeto operado generará

una respuesta para ese objeto. Si no se opera
ningún objeto, el comando producirá un error.

OTROS

PARÁMETROS

Los comandos y pantallas usan una variedad de otros parámetros para especificar varias cosas de

IPMI.

<guid> - un ID único global de 16 bytes, todo junto en una gran cosa

hexadecimal.

<threshold> es un umbral para un sensor; el valor que debe superar/infringir para generar un evento. Siempre se muestra como uno de lower non-critical lower critical lower non-recoverable upper non-critical upper critical upper non-recoverable. Puede ingresarse como uno de los anteriores, o como ln, lc, lr, un, uc, ur como forma

corta.

<threshold enable> es la habilitación para un umbral. Es como <threshold> arriba, pero también tiene un going-high o going-low y un assertion o deassertion agregado al final del nombre. La forma corta tendrá una l o h para going-low y going high y luego una a o d agregada para assertion y deassertion. Así que por ejemplo, urld es upper non-recoverable going-low

deassertion.

<discrete enable> es la habilitación o deshabilitación para un sensor discreto y se especifica con el offset del sensor. La forma larga es <integer> assertion o <integer> deassertion y la forma corta es <integer>[ad] donde el número es el offset y [ad] significa assertion o

deassertion.

<hot-swap state> es uno de not_present, inactive activation_requested activation_in_progress active deactivation_requested deactivation_in_progress o out_of_con

.

<color> es uno de black, white, red, green blue yellow o orange

.

<bool> es uno de true, on, t, o 1 para true y uno de false, off, f, o 0 para false. La salida siempre es true o fals

e
.

COMANDO

S

El lenguaje de comandos es jerárquico, lo que significa que los comandos pueden tener subcomandos, y los subcomandos pueden tener subsubcomandos, etc. Así que, por ejemplo, el comando para crear un dominio es domain new. El comando para listar todos los sensores en un dominio llamado domain1 es sensor list

domain1.

Cada comando tiene una respuesta para cada objeto operado, que se lista después de la descripción del comando. En esas respuestas, cualquier cosa que comience con un % es opcional. Las entradas de la forma **name** se refieren a descripciones de información de objeto que se listan en la sección de información de objeto. Si una entrada tiene dos '.' indentados un espacio debajo, entonces esa entrada puede ocurrir cero o más

veces.

Cada sección a continuación define los subcomandos únicos de un comando

principal.

La ayuda para cualquier comando está disponible

con:

comando.

NOMBRE


ipmi_cmdlang - IPMI Shell Command Language






DESCRIPCIÓN


The ipmi_cmdlang command is used to interact with the IPMI Shell.






COMENTARIOS


This document describes the command language used by the IPMI Shell. It is not a standalone command but a description of the language used by the ipmish(1) command.


The language is structured as objects and their attributes. Objects can be nested within other objects. The basic syntax is:




ObjectName
  AttributeName: Value
  NestedObjectName
    AttributeName: Value
   .
   .
ObjectName
  AttributeName: Value
 .
 .




Attributes starting with a '%' sign are read-only.


String values can be enclosed in double quotes. If the string contains double quotes, they must be escaped with a backslash.


Boolean values can be 'true', 'false', 'yes', 'no', '1', or '0'.


Integer values are standard decimal integers. Some values might be represented in hexadecimal, prefixed with '0x'.


Float values are standard decimal floating-point numbers.


Enumerated values are represented by keywords. For example, sensor thresholds can be 'going high assertion', 'going low assertion', 'going high deassertion', or 'going low deassertion'.


Lists of values are represented by repeating the same entry. For example, multiple threshold sensors can be listed under a single sensor object.




Sensor
  Threshold
    Name: temp1
    Readable: true
    Settable: false
    Supports: going high assertion
   .
  Threshold
    Name: temp2
    Readable: true
    Settable: true
    Supports: going low assertion | going high assertion
   .
  .
 .




Comments start with a '#' and continue to the end of the line.
