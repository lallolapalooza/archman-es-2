NOMBRE

ip-nexthop - gestión de objetos nexthop

SINOPSIS


ip [ OPCIONES_IP ] nexthop { COMANDO | help }

ip nexthop { show | flush } SELECTOR

ip nexthop { add | replace } id ID NH

ip nexthop { get | del } id ID

ip nexthop bucket list SELECTOR_BALDE

ip nexthop bucket get id ID index INDICE

SELECTOR := [ id ID ] [ dev DEV ] [ vrf NOMBRE ] [ master DEV ] [ groups ] [ fdb ]

SELECTOR_BALDE := SELECTOR | [ nhid ID ]

NH := { blackhole | [ via DIRECCION ] [ dev DEV ] [ onlink ] [ encap ENCAP ] [ fdb ] | group GRUPO [ hw_stats { on | off } ] [ fdb ] [ type TIPO [ ARGS_TIPO ] ] }

ENCAP := [ ENCAP_MPLS ]

ENCAP_MPLS := mpls [ ETIQUETA ] [ ttl TTL ]

GRUPO := id[,weight[/...]

TIPO := { mpath | resilient }

ARGS_TIPO := [ ARGS_RESILIENT ]

ARGS_RESILIENT := [ buckets BALDES ] [ idle_timer IDLE ] [ unbalanced_timer UNBALANCED ]

DESCRIPCIÓN

ip nexthop se utiliza para manipular entradas en las tablas nexthop del kernel.

ip nexthop add id ID
agrega una nueva entrada nexthop
ip nexthop replace id ID
cambia la configuración de un nexthop o agrega uno nuevo
via [ FAMILIA ] DIRECCION
la dirección del router nexthop, en la familia de direcciones FAMILIA. La familia de direcciones debe coincidir con la familia de direcciones de la instancia nexthop.
dev NOMBRE
es el dispositivo de salida.
onlink
pretende que el nexthop está directamente conectado a este enlace, incluso si no coincide con ningún prefijo de interfaz.
encap TIPO_ENCAP CABECERA_ENCAP
adjunta atributos de encapsulación de túnel a esta ruta.

TIPO_ENCAP es una cadena que especifica el tipo de encapsulación admitido. A saber:


mpls - tipo de encapsulación MPLS


CABECERA_ENCAP es un conjunto de atributos de encapsulación específicos del TIPO_ENCAP.


mpls
ETIQUETA_MPLS - pila de etiquetas mpls con etiquetas separadas por /

ttl TTL - TTL a usar para la cabecera MPLS o 0 para heredar de la cabecera IP

group GRUPO [ type TIPO [ ARGS_TIPO ] ]
crea un grupo nexthop. La especificación del grupo es id con un peso opcional (id,peso) y una '/' como separador entre entradas.

TIPO es una cadena que especifica el tipo de grupo nexthop. A saber:


mpath - Grupo nexthop Multipath respaldado por el algoritmo hash-threshold. El valor predeterminado cuando el tipo no está especificado.

resilient - Grupo nexthop Resiliente. El grupo es resiliente a la adición y eliminación de nexthops.


ARGS_TIPO es un conjunto de atributos específicos del TIPO.


resilient
buckets BALDES - Número de baldes nexthop. No se puede cambiar para un grupo existente

idle_timer IDLE - Tiempo en segundos en el que un balde nexthop no ve tráfico y por lo tanto se considera inactivo. El valor predeterminado es 120 segundos

unbalanced_timer UNBALANCED - Tiempo en segundos en el que un grupo nexthop está desequilibrado y por lo tanto se considera desequilibrado. El kernel intentará reequilibrar los grupos desequilibrados, lo que podría resultar en el reinicio de algunos flujos. Un valor de 0 significa que no se realizará ningún reequilibrio. El valor predeterminado es 0 segundos

blackhole
crea un nexthop de tipo blackhole
fdb
nexthop y grupos nexthop para usar con entradas fdb de capa 2. Un grupo nexthop fdb solo puede tener nexthops fdb. Ejemplo: Se utiliza para representar la IP de un vtep remoto vxlan. Entrada fdb vxlan de capa 2 que apunta a un grupo nexthop ecmp que contiene múltiples IPs de vtep remoto.
ip nexthop delete id ID
elimina el nexthop con el id dado.
ip nexthop show
muestra el contenido de la tabla nexthop o los nexthops seleccionados por algún criterio.
dev DEV
muestra los nexthops que usan el dispositivo dado.
vrf NOMBRE
muestra los nexthops que usan dispositivos asociados con el nombre vrf
master DEV
muestra los nexthops que usan dispositivos esclavizados al dispositivo maestro dado
groups
muestra solo grupos nexthop
fdb
muestra solo nexthops y grupos nexthop fdb
ip nexthop flush
descarta los nexthops seleccionados por algún criterio. Las opciones de criterio son las mismas que para show.
ip nexthop get id ID
obtiene un solo nexthop por id
ip nexthop bucket show
muestra el contenido de la tabla de baldes nexthop o los baldes nexthop seleccionados por algún criterio.
id ID

muestra los baldes nexthop que pertenecen a un grupo nexthop con un id dado
nhid ID

muestra los baldes nexthop que contienen un nexthop con un id dado
dev DEV

muestra los baldes nexthop que usan el dispositivo dado
vrf NOMBRE

muestra los baldes nexthop que usan dispositivos asociados con el nombre vrf
master DEV

muestra los baldes nexthop que usan dispositivos esclavizados al dispositivo maestro dado
ip nexthop bucket get id ID index INDEX
obtiene un solo balde nexthop por id de grupo nexthop y índice de balde

EJEMPLOS

ip nexthop ls

Muestra todas las entradas nexthop en el kernel.

ip nexthop add id 1 via 192.168.1.1 dev eth0

Agrega un nexthop IPv4 con id 1 usando la puerta de enlace 192.168.1.1 a través del dispositivo eth0.

ip nexthop add id 2 encap mpls 200/300 via 10.1.1.1 dev eth0

Agrega un nexthop IPv4 con atributos de encapsulación mpls adjuntos a él.

ip nexthop add id 3 group 1/2

Agrega un nexthop con id 3. El nexthop es un grupo que usa nexthops con ids 1 y 2 con peso igual.

ip nexthop add id 4 group 1,5/2,11

Agrega un nexthop con id 4. El nexthop es un grupo que usa nexthops con ids 1 y 2, con el nexthop 1 con peso 5 y el nexthop 2 con peso 11.

ip nexthop add id 5 via 192.168.1.2 fdb

Agrega un nexthop fdb con id 5.

ip nexthop add id 7 group 5/6 fdb

Agrega un grupo nexthop fdb con id 7. Un grupo nexthop fdb solo puede tener f

ip-nexthop(8) — iproute2

NAME

ip nexthop — manipulate routing nexthop objects

SYNOPSIS

ip [ OPTIONS ] nexthop { COMMAND | help }

ip nexthop { add | del | show } { ID | GROUP } [ nexthop OBJECT ] [ OPTIONS ]

ip nexthop add ID GROUP TYPE [ OPTIONS ]

ip nexthop del ID

ip nexthop show [ ID ]

nexthop OBJECT := { [ via IP ] [ dev STRING ] }

TYPE := { basic | resilient | ecmp | mcast }

OPTIONS := { buckets NUMBER }

DESCRIPTION

Nexthop objects are used to group multiple individual nexthops into a single logical entity. This allows for more complex routing policies, such as load balancing or failover.

  • add

    Add a new nexthop object. The object can be basic, resilient, ecmp, or mcast. A unique ID must be specified.

    • ID

      The identifier for the nexthop object. This must be unique.

    • GROUP

      The group ID to which this nexthop belongs. This is used to associate multiple nexthop objects together.

    • TYPE

      The type of nexthop object. Can be one of:

      basic
      A simple nexthop.
      resilient
      A resilient nexthop, allowing for failover.
      ecmp
      Equal-cost multi-path routing nexthop.
      mcast
      Multicast routing nexthop.

    • OPTIONS

      Optional parameters depending on the type of nexthop.

      buckets NUMBER
      Specifies the number of buckets for resilient or ecmp nexthops. This determines how traffic is distributed among the nexthops.

  • del

    Delete a nexthop object by its ID.

  • show

    Display information about nexthop objects. If an ID is specified, only that object is shown.

EXAMPLES

Add a basic nexthop with ID 1:

# ip nexthop add id 1 via 192.168.1.1 dev eth0

Add a resilient nexthop group with ID 10 and 32 nexthop buckets:

# ip nexthop add id 10 group 1/2 type resilient buckets 32
