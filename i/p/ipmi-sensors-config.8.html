DESCRIPCIÓ

N

ipmi-config se utiliza para obtener y establecer parámetros de configuración en IPMI. Puede usarse para configurar nombres de usuario, contraseñas, información de red, seguridad, Serial-over-LAN (SOL), filtrado de eventos de plataforma (PEF), dispositivos de arranque, política de restauración de energía, umbrales de sensores, eventos de sensores y muchas más opciones de configuración. Generalmente se requiere alguna configuración antes de que la mayoría de las herramientas IPMI puedan usarse para acceder a una máquina de forma remota. Por defecto, ipmi-config permitirá --checkout o --commit solo los valores IPMI básicos necesarios para la configuración de IPMI. Para campos de configuración avanzados adicionales relacionados con la configuración del chasis (incluyendo opciones de arranque), el filtrado de eventos de plataforma (PEF) o los sensores, consulte la opción --category a continuación. Para más detalles sobre la configuración básica de IPMI, consulte ipmi-config.conf(5). La mayoría de las operaciones de configuración requieren privilegios ADMIN al usar ipmi-config fuera de banda. Aunque no es necesario conectarse mediante un usuario con privilegios ADMIN para el uso fuera de banda, la gran mayoría de las opciones de configuración no se recuperarán ni se

establecerán.

A continuación se enumeran las opciones IPMI generales, las opciones específicas de la herramienta, información de resolución de problemas, información de soluciones alternativas, ejemplos y problemas conocidos. Para una introducción general a FreeIPMI, consulte freeipmi(7). Consulte USO GENERAL a continuación para una descripción del uso básico de ipmi-confi

g
.

USO

GENERAL

La mayoría de los usuarios

querrán:

A) Ejecutar con --checkout para obtener una copia de la configuración actual y almacenarla en un archivo. La salida estándar se puede redirigir a un archivo o se puede especificar un archivo con la opción --fil

ename.

B) Editar el archivo de configuración con un

editor.

C) Confirmar la configuración de vuelta usando la opción --commit y especificando el archivo de configuración con la opción --filename. La configuración se puede confirmar a múltiples hosts en paralelo a través del soporte de rango de

hosts.

Aunque no es típicamente necesario, algunas placas base no almacenan los valores de configuración en memoria no volátil. Por lo tanto, después de reiniciar el sistema, algunos valores de configuración pueden haber cambiado. El usuario puede desear ejecutar herramientas de configuración en cada arranque para asegurar que los valores de configuración

permanezcan.

Los comentarios se listarán ocasionalmente en los archivos obtenidos con información sobre cómo configurar campos. La página de manual ipmi-config.conf(5) también proporciona información adicional sobre el significado de diferentes

campos.

Para usuarios con grandes clústeres o conjuntos de nodos, es posible que desee usar el mismo archivo de configuración para todos los nodos. El único problema con esto es que la dirección IP y la dirección MAC serán diferentes en cada nodo de su clúster y por lo tanto no se pueden configurar a través del mismo archivo de configuración. La dirección IP y la dirección MAC en su archivo de configuración pueden ser sobrescritas en la línea de comandos usando la opción --key-pair. El siguiente ejemplo podría usarse en un script para configurar cada nodo en un clúster con el mismo archivo de configuración BMC. El script solo necesita determinar la dirección IP y la dirección MAC correctas a

usar.

# ipmi-config --commit -k Lan_Conf:Ip_Address=$MY_IP -k Lan_Conf:Mac_Address=$MY_MAC --filename=my_bmc.

conf

INFORMACIÓN DE CONFIGURACIÓN DE CASOS ESPECIALES DEL

NÚCLEO

Los campos UserN:Password (donde N es un número) no pueden ser extraídos en algunos sistemas, por lo tanto el valor extraído siempre será

vacío.

Los campos UserN:Enable_User (donde N es un número) no pueden ser extraídos en sistemas IPMI antiguos, por lo tanto el valor extraído será a veces

vacío.

Los campos UserN:Lan_Session_Limit y UserN:Serial_Session_Limit (donde N es un número) no pueden ser extraídos en algunos sistemas, por lo tanto el valor extraído siempre será vacío. Si no se especifica en envíos posteriores de configuraciones, el campo puede ser restablecido a 0 debido a un requisito de que otros campos (configurados junto con el límite de sesión) requerirán un valor de entrada para el límite de sesión. Bajo la mayoría de las condiciones, no es necesario establecer este campo y la mayoría de los usuarios pueden optar por ignorarlo. Este campo es considerado opcional por los estándares de IPMI, y puede resultar en errores al intentar configurarlo a un valor distinto de cero. Si ocurren errores, establecer el valor de vuelta a 0 debería resolver los

problemas.

Los campos Lan_Conf:IP_Address y Lan_Conf:MAC_Address no pueden ser enviados en paralelo mediante el soporte de rangos de host. Cada máquina debe ser configurada con un único par de Dirección IP y Dirección MAC, por lo tanto deshabilitamos esta configuración en ipmi-config

.

En algunas placas base, Lan_Conf:MAC_Address puede ser de solo lectura y la dirección MAC es configurada automáticamente

.

En algunas placas base, Lan_Conf:MAC_Address puede ser de solo lectura y la dirección MAC es configurada mediante un comando OEM. Vea ipmi-oem(8) para ver si la configuración OEM para su placa base es

soportada.

En algunas placas base, varios campos de configuración de usuario no pueden ser leídos o configurados hasta después de que un nombre de usuario no nulo o una contraseña no nula sea configurada. En algunos de estos casos, una salida apropiada en el archivo de configuración indicará esta situación. Sin embargo, no todos los casos especiales de las placas base pueden ser detectados. Los usuarios pueden querer experimentar con el orden de los campos para solucionar estos

problemas.

En algunas placas base, la Autenticación OEM en Lan_Conf_Auth no puede ser habilitada. Sin embargo, la configuración predeterminada de la placa base tiene estos campos habilitados. Se aconseja a los usuarios deshabilitar toda la Autenticación OEM en esta

sección.

En algunas placas base, pueden existir múltiples canales para la comunicación IPMI por LAN o Serial. Si existen múltiples canales, la configuración de ambos canales puede ser vista y finalmente configurada ejecutando --checkout bajo modo verboso. Cada sección o nombre de clave será sufijada apropiadamente con la palabra Channel y el número de canal. Por ejemplo, podría ver un Lan_Conf_Channel_1 y Lan_Conf_Channel_3, donde puede configurar la configuración de LAN en los Canales 1 y 3 respectivamente

.

En algunas placas base, los cambios de configuración no serán "absorbidos" por el sistema hasta que la placa base sea reiniciada físicamente. Esto puede lograrse apagando y encendiendo físicamente el sistema (por ejemplo, pulsando un botón), o puede lograrse mediante un reinicio en frío. Un reinicio en frío puede ser ejecutado mediante bmc-devic

e
.

Dado que muchos campos configurables involucran números decimales, pueden ocurrir imprecisiones de

precisión/flotante al configurar nuevos umbrales. Las imprecisiones pueden no ser aparentes inmedi
atamente. Se recomienda a los usuarios verificar sus cambios después de configurar nuevos umbrales.

SOPORTE DE RANGOS DE

HOST

Múltiples hosts pueden ser ingresados ya sea como listas explícitas separadas por comas de hosts o un rango de nombres de host en la forma general: prefijo[n-m,l-k,...], donde n < m y l < k, etc. La última forma no debe confundirse con clases de caracteres de expresiones regulares (también denotadas por []). Por ejemplo, foo[19] no representa foo1 o foo9, sino que representa un rango degenerado:

foo19.

Esta sintaxis de rango está destinada solo como una conveniencia en clústeres con una convención de nombres prefijoNN y la especificación de rangos no debe considerarse necesaria -- la lista foo1,foo9 podría especificarse como tal, o por el rango foo[1,9]

.

A continuación se presentan algunos ejemplos de uso de

rangos: 
    foo[01-05] en lugar de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] en lugar de foo7,foo9,foo10
    foo[0-3] en lugar de foo0,foo1,foo2,
foo3

Como recordatorio para el lector, algunos intérpretes de comandos interpretarán corchetes ([ y ]) para coincidencia de patrones. Dependiendo de su intérprete de comandos, puede ser necesario encerrar las listas de rangos entre

comillas.

Cuando el usuario especifica múltiples hosts, se ejecutará un hilo para cada host en paralelo hasta el abanico configurado (que puede ajustarse mediante la opción -F). Esto permitirá la comunicación con un gran número de nodos mucho más rápidamente que si se hiciera en

serie.

Por defecto, la salida estándar de cada nodo especificado será emitida con el nombre de host antepuesto a cada línea. Aunque esta salida es legible en muchas situaciones, puede ser difícil de leer en otras situaciones. Por ejemplo, la salida de múltiples nodos puede mezclarse. Las opciones -B y -C pueden usarse para cambiar este comportamiento

predeterminado.

Se utilizará la comunicación IPMI en banda cuando se esp

ecifica el host "localhost". Esto permite al usuario
agregar el localhost a la salida de rangos de host.

SOLUCIÓN DE PROBLEMAS

GENERAL

La mayoría de las veces, los problemas de IPMI se deben a problemas de

configuración.

Los problemas de IPMI sobre LAN involucran una mala configuración del BMC de la máquina remota. Verifique dos veces para asegurarse de que lo siguiente esté configurado correctamente en el BMC de la máquina remota: dirección IP, dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio de LAN, habilitación de LAN y tipo(s) de autenticación permitido(s). Para conexiones IPMI 2.0, verifique dos veces para asegurarse de que el(los) privilegio(s) de suite de cifrado y la clave K_g estén configurados correctamente. La herramienta ipmi-config(8) puede usarse para verificar y/o cambiar estos ajustes de

configuración.

Los problemas de IPMI en banda típicamente son causados por controladores mal configurados o BMCs no

estándar.

Además de los consejos de solución de problemas a continuación, por favor vea SOLUCIONES ALTERNATIVAS más abajo para ver también si hay errores específicos del proveedor que hayan sido descubiertos y

solucionados.

A continuación se enumeran muchos de los problemas comunes para los mensajes de error. Para soporte adicional, por favor envíe un correo electrónico a la lista de correo <freeipmi-users@gnu.org>

.

"username invalid" (nombre de usuario inválido) - El nombre de usuario ingresado (o un nombre de usuario NULO si no se ingresó ninguno) no está disponible en la máquina remota. También es posible que la configuración del nombre de usuario del BMC remoto sea

incorrecta.

"password invalid" (contraseña inválida) - La contraseña ingresada (o una contraseña NULA si no se ingresó ninguna) no es correcta. También es posible que la contraseña del usuario no esté configurada correctamente en el BMC

remoto.

"password verification timeout" (tiempo de espera de verificación de contraseña) - La verificación de la contraseña ha expirado. Ocurrió un error "password invalid" (descrito arriba) o un "session timeout" genérico (descrito más abajo). Durante este punto del protocolo no se puede diferenciar cuál

ocurrió.

"k_g invalid" (K_g inválido) - La clave K_g ingresada (o una clave K_g NULA si no se ingresó ninguna) no es correcta. También es posible que la clave K_g no esté configurada correctamente en el BMC

remoto.

"privilege level insufficient" (nivel de privilegio insuficiente) - Un comando IPMI requiere un privilegio de usuario más alto con el que se autenticó. Por favor intente autenticarse con un privilegio más alto. Esto puede requerir autenticarse con un usuario diferente que tenga un privilegio máximo más

alto.

"privilege level cannot be obtained for this user" (no se puede obtener el nivel de privilegio para este usuario) - El nivel de privilegio con el que intenta autenticarse es más alto que el máximo permitido para este usuario. Por favor intente de nuevo con un privilegio más bajo. También es posible que el nivel de privilegio máximo permitido para un usuario no esté configurado correctamente en el BMC

remoto.

"authentication type unavailable for attempted privilege level" (tipo de autenticación no disponible para el nivel de privilegio intentado) - El tipo de autenticación con el que desea autenticarse no está disponible para este nivel de privilegio. Intente de nuevo con un tipo de autenticación alternativo o un nivel de privilegio alternativo. También es posible que los tipos de autenticación disponibles con los que puede autenticar no estén configurados correctamente en el BMC

remoto.

"cipher suite id unavailable" (ID de conjunto de cifrado no disponible) - El ID de conjunto de cifrado con el que desea autenticar no está disponible en el BMC remoto. Intente de nuevo con un ID de conjunto de cifrado alternativo. También es posible que los IDs de conjuntos de cifrado disponibles no estén configurados correctamente en el BMC

remoto.

"ipmi 2.0 unavailable" (IPMI 2.0 no disponible) - No se detectó IPMI 2.0 en la máquina remota. Intente usar IPMI 1.5 en su

lugar.

"connection timeout" (tiempo de espera de conexión agotado) - La comunicación IPMI inicial falló. Pueden existir varios errores potenciales, incluyendo un nombre de host no válido especificado, una dirección IP de IPMI que no se puede resolver, IPMI no está habilitado en el servidor remoto, la conexión de red es deficiente, etc. Verifique la configuración y la

conectividad.

"session timeout" (tiempo de espera de sesión agotado) - La sesión IPMI ha expirado. Reconéctese. Si este error ocurre con frecuencia, es posible que desee aumentar el tiempo de espera de retransmisión. Algunos BMC remotos son considerablemente más lentos que

otros.

"device not found" (dispositivo no encontrado) - No se pudo encontrar el dispositivo especificado. Verifique la configuración o las entradas e intente de

nuevo.

"driver timeout" (tiempo de espera del controlador agotado) - La comunicación con el controlador o el dispositivo ha expirado. Intente de

nuevo.

"message timeout" (tiempo de espera del mensaje agotado) - La comunicación con el controlador o el dispositivo ha expirado. Intente de

nuevo.

"BMC busy" (BMC ocupado) - El BMC está actualmente ocupado. Puede estar procesando información o tener demasiadas sesiones simultáneas para gestionar. Espere e intente de

nuevo.

"could not find inband device" (no se pudo encontrar el dispositivo de banda interna) - No se pudo encontrar un dispositivo de banda interna. Verifique la configuración o especifique un dispositivo o controlador específico en la línea de

comandos.

"driver timeout" (tiempo de espera del controlador agotado) - El controlador de banda interna ha ag

otado el tiempo de espera al comunicarse con el BMC o el procesador de servicio local. El BMC o el
procesador de servicio puede estar ocupado o (en el peor de los casos) posiblemente no funcionando.

SOLUCIONES

ALTERNATIVAS

Con tantos proveedores diferentes implementando sus propias soluciones IPMI, diferentes proveedores pueden implementar incorrectamente sus protocolos IPMI. A continuación se describen varias soluciones alternativas actualmente disponibles para manejar los problemas de cumplimiento descubiertos. Cuando sea posible, las soluciones alternativas se han implementado para que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se use una solución alternativa mediante la opción

-W.

El hardware enumerado a continuación puede indicar solo el hardware en el que se descubrió un problema. Las versiones más nuevas de hardware pueden corregir los problemas indicados a continuación. Máquinas similares de otros proveedores pueden o no exhibir los mismos problemas. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede valer la pena probar las soluciones alternativas enumeradas a continuación, incluso si su placa base no está en la

lista.

Si cree que su hardware tiene un problema de cumplimiento adicional que necesita que se implemente una solución alternativa, póngase en contacto con los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.org>

.

assumeio - Esta opción de solución alternativa asumirá que las interfaces de banda interna se comunican con las E/S del sistema en lugar de estar mapeadas en memoria. Esto solucionará los sistemas que informan direcciones base no válidas. Aquellos que encuentren este problema pueden ver errores "device not supported" (dispositivo no soportado) o "could not find inband device" (no se pudo encontrar el dispositivo de banda interna). Problema observado en HP ProLiant DL145

G1.

spinpoll - Esta opción de solución alternativa informará a algunos controladores de banda interna (el más notable es el controlador KCS) que giren (spin) mientras hacen sondeos en lugar de poner el proceso a dormir. Esto puede mejorar significativamente el tiempo de ejecución real de las herramientas porque la granularidad del planificador del sistema operativo puede ser mucho mayor que el tiempo que tarda en realizarse una única transacción de mensaje IPMI. Sin embargo, al girar, su sistema puede estar realizando un trabajo menos útil al no cambiar el contexto de la herramienta para una tarea más

útil.

authcap - Esta opción de solución alternativa omitirá las verificaciones iniciales de capacidades de nombre de usuario, capacidades de autenticación y soporte de K_g, y permitirá que la autenticación IPMI tenga éxito. Soluciona múltiples problemas en los que el sistema remoto no informa correctamente las capacidades del nombre de usuario, las capacidades de autenticación o el estado de K_g. Aquellos que encuentren este problema pueden ver errores "username invalid" (nombre de usuario no válido), "authentication type unavailable for attempted privilege level" (tipo de autenticación no disponible para el nivel de privilegio intentado) o "k_g invalid" (K_g no válido). Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML y Sun Fire 2200/4150/4450 con

ELOM.

nochecksumcheck - Esta opción de solución alternativa le indicará a FreeIPMI que no verifique las sumas de comprobación devueltas por las respuestas de los comandos IPMI. Soluciona sistemas que devuelven sumas de comprobación no válidas debido a errores de implementación, pero el paquete es válido de otro modo. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina la validación de la integridad del paquete en una serie de circunstancias. Sin embargo, es poco probable que sea un problema en la mayoría de las situaciones. Aquellos que encuentren este problema pueden ver errores "connection timeout" (tiempo de espera de conexión agotado), "session timeout" (tiempo de espera de sesión agotado) o "password verification timeout" (tiempo de espera de verificación de contraseña agotado). En las conexiones IPMI 1.5, también puede ser necesaria la solución alternativa "noauthcodecheck". Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F y Supermicro

X9DRFR.

idzero - Esta opción de solución alternativa permitirá que el cliente acepte IDs de sesión vacíos. Soluciona sesiones IPMI que informan IDs de sesión vacíos al cliente. Aquellos que encuentren este problema pueden ver errores "session timeout" (tiempo de espera de sesión agotado). Problema observado en Tyan S2882 con BMC

M3289.

unexpectedauth - Esta opción de solución alternativa permitirá que se verifiquen códigos de autenticación no nulos inesperados como si se esperaran. Soluciona un problema cuando los paquetes contienen datos de autenticación no nulos cuando deberían ser nulos debido a la autenticación por mensaje deshabilitada. Aquellos que encuentren este problema pueden ver errores "session timeout" (tiempo de espera de sesión agotado). Problema observado en Dell PowerEdge 2850, SC1425. Confirmado como corregido en firmware más

nuevo.

forcepermsg - Esta opción de solución alternativa forzará el uso de la autenticación por mensaje sin importar lo que anuncie el sistema remoto. Soluciona un problema cuando la autenticación por mensaje se anuncia como deshabilitada en el sistema remoto, pero en realidad es requerida por el protocolo. Aquellos que encuentren este problema pueden ver errores "session timeout" (tiempo de espera de sesión agotado). Problema observado en IBM eServer

325.

endianseq - Esta opción de solución alternativa invertirá el orden de bytes (endian) de los números de secuencia de sesión para permitir que la sesión continúe correctamente. Soluciona números de secuencia de sesión IPMI 1.5 que tienen el orden de bytes incorrecto. Aquellos que encuentren este problema pueden ver errores "session timeout" (tiempo de espera de sesión agotado). Problema observado en algunos Sun ILOM 1.0/2.0 (depende del orden de bytes del procesador de servicio)

.

noauthcodecheck - Esta opción de solución alternativa le indicará a FreeIPMI que no verifique los códigos de autenticación devueltos por las respuestas de los comandos IPMI 1.5. Soluciona sistemas que devuelven códigos de autenticación no válidos debido a errores de hash o de implementación. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina una verificación de autenticación que valida la integridad de un paquete. Sin embargo, en la mayoría de las organizaciones, es poco probable que sea un problema de seguridad. Aquellos que encuentren este problema pueden ver errores "connection timeout" (tiempo de espera de conexión agotado), "session timeout" (tiempo de espera de sesión agotado) o "password verification timeout" (tiempo de espera de verificación de contraseña agotado). Problema observado en Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell y Wiwynn

Windmill.

intel20 - Esta opción de solución alternativa solucionará varios problemas de autenticación IPMI 2.0 de Intel. Los problemas cubiertos incluyen el relleno (padding) de nombres de usuario y el truncamiento de la contraseña si el algoritmo de autenticación es HMAC-MD5-128. Aquellos que encuentren este problema pueden ver errores "username invalid" (nombre de usuario no válido), "password invalid" (contraseña no válida) o "k_g invalid" (K_g no válido). Problema observado en Intel SE7520AF2 con Intel Server Management Module (Professional Edition)

.

supermicro20 - Esta opción de solución alternativa solucionará varios problemas de autenticación IPMI 2.0 de Supermicro en placas base con firmware IPMI de Peppercon. Los problemas cubiertos incluyen el manejo de códigos de autenticación de longitud no válida. Aquellos que encuentren este problema pueden ver errores "password invalid" (contraseña no válida). Problema observado en Supermicro H8QME con tarjeta hija SIMSO. Confirmado como corregido en firmware más

nuevo.

sun20 - Esta opción de solución alternativa solucionará varios problemas de autenticación IPMI 2.0 de Sun. Los problemas cubiertos incluyen claves hash de longitud no válida, claves con hash incorrecto y registros de conjunto de cifrado no válidos. Aquellos que encuentren este problema pueden ver errores "password invalid" (contraseña no válida) o "bmc error" (error de BMC). Problema observado en Sun Fire 4100/4200/4500 con ILOM. Esta solución alternativa incluye automáticamente la solución alternativa

"opensesspriv".

opensesspriv - Esta opción de solución alternativa alterará ligeramente el protocolo de conexión IPMI 2.0 de FreeIPMI para solucionar un algoritmo de hash no válido utilizado por el sistema remoto. El nivel de privilegio enviado durante la etapa de Apertura de Sesión (Open Session) de una conexión IPMI 2.0 se utiliza para el hash de claves en lugar del nivel de privilegio enviado durante la etapa de conexión RAKP1. Aquellos que encuentren este problema pueden ver errores "password invalid" (contraseña no válida), "k_g invalid" (K_g no válido), "bad rmcpplus status code" (código de estado rmcpplus incorrecto) o "privilege level cannot be obtained for this user" (no se puede obtener el nivel de privilegio para este usuario). Problema observado en Sun Fire 4100/4200/4500 con ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220 y el software BMC OpenIPMI. Esta solución alternativa se activa automáticamente con la solución alternativa

"sun20".

integritycheckvalue - Esta opción de solución alternativa solucionará un valor de verificación de integridad no válido durante el establecimiento de una sesión IPMI 2.0 al usar el ID de Conjunto de Cifrado 0. El valor de verificación de integridad debería tener una longitud de 0, sin embargo, la placa base remota responde con un campo no vacío. Aquellos que encuentren este problema pueden ver errores "k_g invalid" (K_g no válido). Problema observado en Supermicro X8DTG, Supermicro X8DTU, Intel S5500WBV/Penguin Relion 700 e Intel S2600JF/Appro

512X.

Falta de soporte para IPMI 1.5 - Se ha descubierto que algunas placas base que soportan IPMI 2.0 no soportan IPMI 1.5. Aquellos que encuentren este problema pueden ver errores "ipmi 2.0 unavailable" (IPMI 2.0 no disponible) o "connection timeout" (tiempo de espera de conexión agotado). Este problema se puede solucionar usando IPMI 2.0 en lugar de IPMI 1.5 especificando --driver-type=LAN_2_0. Problema observado en varias placas base de HP y

Supermicro.

slowcommit - Esta solución alternativa ralentizará las confirmaciones (commits) al BMC durmiendo un segundo entre la confirmación de las secciones. Soluciona placas base que tienen BMCs que pueden ser abrumados por las confirmaciones. Aquellos que encuentren este problema pueden ver errores de confirmación o confirmaciones que no se escriben en el BMC. Problema observado en Supermicro

H8QME.

veryslowcommit - Esta solución alternativa ralentizará las confirmaciones (commits) al BMC durmiendo un segund entre el commit de cada clave. Funciona con placas base que tienen BMC que pueden ser abrumados por los commits. Aquellos que se encuentren con este problema pueden ver errores de commit o commits que no se escriben en el BMC. Problema observado en Quanta S99Q/Dell FS12-TY y Dell PowerEdge

T320.

solchannelassumelanchannel - Esta solución alternativa forzará ipmi-config a asumir que el canal usado por SOL es idéntico al canal usado para LAN. En algunas placas base, el canal SOL se informa incorrectamente, lo que lleva a una

configuración incorrecta. Más notablemente, este problema ha surgido al intentar co
nfigurar múltiples canales. Problema observado en Intel S5500WBV/Penguin Relion 700.

DIAGNÓSTIC

O

Tras una ejecución exitosa, el estado de salida es 0. En caso de error no fatal, el estado de salida es 1. En caso de error fatal, el estado de salida es

2.

Si se especifican múltiples hosts para la comunicación, el estado de salida es 0 si y

solo si todos los destinos se ejecutan correctamente. Si ocurre cualquier error no fatal,
el estado de salida es 1. Si ocurre cualquier error fatal, el estado de salida es 2.

PROBLEMAS

CONOCIDOS

En sistemas operativos antiguos, si ingresa su nombre de usuario, contraseña y otra información potencialmente relevante para la seguridad en la línea de comandos, esta información puede ser descubierta por otros usuarios al usar herramientas como el comando ps(1) o mirando en el sistema de archivos /proc. Generalmente es más seguro ingresar la información de contraseña con opciones como las opciones -P o -K. Configurar información relevante para la seguridad en el archivo de configuración de FreeIPMI también sería una forma apropiada de ocultar esta

información.

Para prevenir ataques de fuerza bruta, algunos BMC se "bloquearán" temporalmente desp

ués de un número de errores de autenticación remota. Puede que necesite esperar un t
iempo para que este "bloqueo" temporal pase antes de que pueda autenticarse de nuevo.
