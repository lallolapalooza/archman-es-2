NOMBRE

ip-rule - gestión de la base de datos de política de enrutamiento

SINOPSIS

ip rule [ show [ SELECTOR ]]

ip rule { add | del } SELECTOR ACCIÓN

ip rule { flush | save | restore }

SELECTOR := [ not ] [ from PREFIX ] [ to PREFIX ] [ tos TOS ] [ dscp DSCP[/MASK] ] [ fwmark FWMARK[/MASK] ] [ iif STRING ] [ oif STRING ] [ priority PREFERENCE ] [ l3mdev ] [ uidrange NUMBER-NUMBER ] [ ipproto PROTOCOL ] [ sport [ NUMBER[/MASK] | NUMBER-NUMBER ] ] [ dport [ NUMBER[/MASK] | NUMBER-NUMBER ] ] [ tun_id TUN_ID ] [ flowlabel FLOWLABEL[/MASK] ]

ACCIÓN := [ table TABLE_ID ] [ protocol PROTO ] [ nat ADDRESS ] [ realms [SRCREALM/]DSTREALM ] [ goto NUMBER ] SUPRESOR

SUPRESOR := [ suppress_prefixlength NUMBER ] [ suppress_ifgroup GROUP ]

TABLE_ID := [ local | main | default | NUMBER ]

DESCRIPCIÓN

ip rule manipula reglas en la base de datos de política de enrutamiento que controla el algoritmo de selección de rutas.

Los algoritmos de enrutamiento clásicos utilizados en Internet toman decisiones de enrutamiento basándose únicamente en la dirección de destino de los paquetes (y en teoría, pero no en la práctica, en el campo TOS).

En algunas circunstancias, queremos enrutar paquetes de manera diferente dependiendo no solo de las direcciones de destino sino también de otros campos del paquete: dirección de origen, protocolo IP, puertos del protocolo de transporte o incluso la carga útil del paquete. Esta tarea se denomina 'enrutamiento por políticas'.

Para resolver esta tarea, la tabla de enrutamiento convencional basada en el destino, ordenada según la regla de coincidencia más larga, se reemplaza con una 'base de datos de política de enrutamiento' (o RPDB), que selecciona rutas ejecutando un conjunto de reglas.

Cada regla de enrutamiento por políticas consta de un selector y un predicado de acción. La RPDB se escanea en orden de prioridad decreciente (note que un número más bajo significa mayor prioridad, vea la descripción de PREFERENCE más abajo). El selector de cada regla se aplica a {dirección de origen, dirección de destino, interfaz entrante, tos, fwmark} y, si el selector coincide con el paquete, se realiza la acción. El predicado de acción puede devolver con éxito. En este caso, dará una ruta o una indicación de fallo y la búsqueda en la RPDB termina. De lo contrario, el programa de la RPDB continúa con la siguiente regla.

Semánticamente, la acción natural es seleccionar el siguiente salto (nexthop) y el dispositivo de salida.

En el arranque, el kernel configura la RPDB por defecto que consta de tres reglas:

1.
Prioridad: 0, Selector: coincide con todo, Acción: buscar en la tabla de enrutamiento local (ID 255). La tabla local es una tabla de enrutamiento especial que contiene rutas de control de alta prioridad para direcciones locales y de difusión.
2.
Prioridad: 32766, Selector: coincide con todo, Acción: buscar en la tabla de enrutamiento main (ID 254). La tabla main es la tabla de enrutamiento normal que contiene todas las rutas no basadas en políticas. Esta regla puede ser eliminada y/o anulada con otras por el administrador.
3.
Prioridad: 32767, Selector: coincide con todo, Acción: buscar en la tabla de enrutamiento default (ID 253). La tabla default está vacía. Está reservada para algún post-procesamiento si ninguna de las reglas por defecto anteriores seleccionó el paquete. Esta regla también puede ser eliminada.

Cada entrada de la RPDB tiene atributos adicionales. Por ejemplo, cada regla tiene un puntero a alguna tabla de enrutamiento. Las reglas NAT y de enmascaramiento tienen un atributo para seleccionar la nueva dirección IP a traducir/enmascarar. Además, las reglas tienen algunos atributos opcionales que también tienen las rutas, a saber realms. Estos valores no anulan los contenidos en las tablas de enrutamiento. Solo se usan si la ruta no seleccionó ningún atributo.

La RPDB puede contener reglas de los siguientes tipos:

unicast - la regla devuelve la ruta encontrada en la tabla de enrutamiento referenciada por la regla.

blackhole - la regla provoca una eliminación silenciosa del paquete.

unreachable - la regla genera un error 'Network is unreachable' (Red inaccesible).

prohibit - la regla genera un error 'Communication is administratively prohibited' (Comunicación prohibida administrativamente).

nat - la regla traduce la dirección de origen del paquete IP en algún otro valor.

from PREFIX
seleccionar el prefijo de origen a coincidir.
to PREFIX
seleccionar el prefijo de destino a coincidir.
iif NAME
seleccionar el dispositivo entrante a coincidir. Si la interfaz es loopback, la regla solo coincide con paquetes originados en este host. Esto significa que puede crear tablas de enrutamiento separadas para paquetes reenviados y locales y, por lo tanto, separarlos completamente.
oif NAME
seleccionar el dispositivo saliente a coincidir. La interfaz de salida solo está disponible para paquetes originados en sockets locales que están vinculados a un dispositivo.
tos TOS
dsfield TOS
seleccionar el valor TOS a coincidir.
dscp DSCP[/MASK]
seleccionar el valor DSCP a coincidir con una máscara opcional. Los valores DSCP pueden escribirse directamente como valores numéricos (los valores válidos son 0-63), o usando nombres simbólicos especificados en /usr/share/iproute2/rt_dsfield o /etc/iproute2/rt_dsfield (tiene precedencia si existe). Sin embargo, note que el archivo especifica valores dsfield completos de 8 bits, mientras que ip rule solo usará los seis bits superiores. ip rule show formateará de manera similar los valores DSCP como nombres simbólicos si es posible. La opción de línea de comandos -N desactiva la traducción en show.
fwmark MARK
seleccionar el valor fwmark a coincidir.
uidrange NUMBER-NUMBER
seleccionar el valor uid a coincidir.
ipproto PROTOCOL
seleccionar el valor de protocolo ip a coincidir.
sport NUMBER[/MASK] | NUMBER-NUMBER
seleccionar el valor del puerto de origen a coincidir con una máscara opcional. Soporta rango de puertos.
dport NUMBER[/MASK] | NUMBER-NUMBER
seleccionar el valor del puerto de destino a coincidir con una máscara opcional. Soporta rango de puertos.
priority PREFERENCE
la prioridad de esta regla. PREFERENCE es un valor entero sin signo, un número más alto significa menor prioridad, y las reglas se procesan en orden de número creciente. Cada regla debe tener un valor de prioridad único establecido explícitamente. Las opciones preference y order son sinónimos de priority.
table TABLEID
el identificador de la tabla de enrutamiento a buscar si el selector de la regla coincide. También es posible usar lookup en lugar de table.
protocol PROTO
el protocolo de enrutamiento que instaló la regla en cuestión. Como ejemplo, cuando zebra instala una regla,obtendrá RTPROT_ZEBRA como el protocolo que
instala.
