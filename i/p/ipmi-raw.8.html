DESCRIPCIÓ

N

Ipmi-raw se utiliza para ejecutar comandos IPMI mediante valores hexadecimales. Los valores hexadecimales pueden introducirse en la línea de comandos, en un archivo mediante la --file opción, o a través de stdin si no se especifica ninguna de las

anteriores.

A continuación se enumeran las opciones IPMI generales, las opciones específicas de la herramienta, información de resolución de problemas, información sobre soluciones alternativas, ejemplos y problemas conocidos. Para una introducción general a FreeIPMI, consulte free

ipmi
(7).

SOPORTE DE RANGO DE

HOSTS

Se pueden introducir múltiples hosts ya sea como listas explícitas de hosts separadas por comas o como un rango de nombres de host en la forma general: prefijo[n-m,l-k,...], donde n < m y l < k, etc. La última forma no debe confundirse con las clases de caracteres de expresiones regulares (también denotadas por []). Por ejemplo, foo[19] no representa foo1 o foo9, sino que representa un rango degenerado:

foo19.

Esta sintaxis de rango está destinada solo como una comodidad en clústeres con una convención de nombres prefijoNN y la especificación de rangos no debe considerarse necesaria -- la lista foo1,foo9 podría especificarse como tal, o por el rango foo[1,9]

.

A continuación se muestran algunos ejemplos de uso de

rangos: 
    foo[01-05] en lugar de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] en lugar de foo7,foo9,foo10
    foo[0-3] en lugar de foo0,foo1,foo2,
foo3

Como recordatorio para el lector, algunos intérpretes de comandos interpretarán los corchetes ([ y ]) para la coincidencia de patrones. Dependiendo de su intérprete de comandos, puede ser necesario encerrar las listas de rangos entre

comillas.

Cuando el usuario especifica múltiples hosts, se ejecutará un hilo para cada host en paralelo hasta la distribución configurada (que puede ajustarse mediante la opción -F). Esto permitirá la comunicación con un gran número de nodos mucho más rápidamente que si se hiciera en

serie.

De forma predeterminada, la salida estándar de cada nodo especificado se emitirá con el nombre de host antepuesto a cada línea. Aunque esta salida es legible en muchas situaciones, puede ser difícil de leer en otras situaciones. Por ejemplo, la salida de múltiples nodos puede mezclarse. Las opciones -B y -C pueden usarse para cambiar este valor

predeterminado.

Se utilizará la comunicación IPMI en banda cuando se esp

ecifica el host "localhost". Esto permite al usuari
o añadir el localhost a la salida de rango de hosts.

SOLUCIÓN DE PROBLEMAS

GENERAL

La mayoría de las veces, los problemas de IPMI se deben a problemas de

configuración.

Los problemas de IPMI sobre LAN implican una configuración incorrecta del BMC de la máquina remota. Verifique dos veces para asegurarse de que lo siguiente esté configurado correctamente en el BMC de la máquina remota: dirección IP, dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio LAN, habilitación LAN y tipo(s) de autenticación permitido(s). Para conexiones IPMI 2.0, verifique dos veces para asegurarse de que el/los privilegio(s) de la suite de cifrado y la clave K_g estén configurados correctamente. La herramienta ipmi-config(8) puede usarse para verificar y/o cambiar estos ajustes de

configuración.

Los problemas de IPMI en banda típicamente son causados por controladores mal configurados o BMCs no

estándar.

Además de los consejos de solución de problemas a continuación, consulte SOLUCIONES ALTERNATIVAS más abajo para ver también si hay errores específicos del proveedor que hayan sido descubiertos y

solucionados.

A continuación se enumeran muchos de los problemas comunes para los mensajes de error. Para soporte adicional, por favor envíe un correo electrónico a la lista de correo <freeipmi-users@gnu.org>

.

"username invalid" - El nombre de usuario introducido (o un nombre de usuario NULL si no se introdujo ninguno) no está disponible en la máquina remota. También es posible que la configuración del nombre de usuario del BMC remoto sea

incorrecta.

"password invalid" - La contraseña introducida (o una contraseña NULL si no se introdujo ninguna) no es correcta. También es posible que la contraseña del usuario no esté configurada correctamente en el BMC

remoto.

"password verification timeout" - La verificación de la contraseña ha agotado el tiempo de espera. Ha ocurrido un error "password invalid" (descrito arriba) o un "session timeout" genérico (descrito más abajo). Durante este punto del protocolo no se puede diferenciar cuál ha

ocurrido.

"k_g invalid" - La clave K_g introducida (o una clave K_g NULL si no se introdujo ninguna) no es correcta. También es posible que la clave K_g no esté configurada correctamente en el BMC

remoto.

"privilege level insufficient" - Un comando IPMI requiere un privilegio de usuario más alto que el con el que se ha autenticado. Por favor, intente autenticar con un privilegio más alto. Esto puede requerir autenticar a un usuario diferente que tenga un privilegio máximo más

alto.

"privilege level cannot be obtained for this user" - El nivel de privilegio con el que intenta autenticar es más alto que el máximo permitido para este usuario. Por favor, inténtelo de nuevo con un privilegio más bajo. También es posible que el nivel de privilegio máximo permitido para un usuario no esté configurado correctamente en el BMC

remoto.

"authentication type unavailable for attempted privilege level" - El tipo de autenticación con el que desea autenticar no está disponible para este nivel de privilegio. Por favor, inténtelo de nuevo con un tipo de autenticación alternativo o un nivel de privilegio alternativo. También es posible que los tipos de autenticación disponibles con los que puede autenticar no estén configurados correctamente en el BMC

remoto.

"cipher suite id unavailable" - El id de la suite de cifrado con el que desea autenticar no está disponible en el BMC remoto. Por favor, intente de nuevo con un id de suite de cifrado alternativo. También es posible que los ids de suite de cifrado disponibles no estén configurados correctamente en el BMC

remoto.

"ipmi 2.0 unavailable" - IPMI 2.0 no se descubrió en la máquina remota. Por favor, intente usar IPMI 1.5 en su

lugar.

"connection timeout" - La comunicación IPMI inicial falló. Son posibles varios errores potenciales, incluyendo un nombre de host especificado inválido, una dirección IP de IPMI no se puede resolver, IPMI no está habilitado en el servidor remoto, la conexión de red es deficiente, etc. Por favor, verifique la configuración y la

conectividad.

"session timeout" - La sesión IPMI ha agotado el tiempo de espera. Por favor, reconéctese. Si este error ocurre con frecuencia, es posible que desee aumentar el tiempo de espera de retransmisión. Algunos BMCs remotos son considerablemente más lentos que

otros.

"device not found" - El dispositivo especificado no se pudo encontrar. Por favor, verifique la configuración o las entradas e inténtelo de

nuevo.

"driver timeout" - La comunicación con el controlador o el dispositivo ha agotado el tiempo de espera. Por favor, inténtelo de

nuevo.

"message timeout" - La comunicación con el controlador o el dispositivo ha agotado el tiempo de espera. Por favor, inténtelo de

nuevo.

"BMC busy" - El BMC está actualmente ocupado. Puede estar procesando información o tener demasiadas sesiones simultáneas que gestionar. Por favor, espere e inténtelo de

nuevo.

"could not find inband device" - No se pudo encontrar un dispositivo en banda. Por favor, verifique la configuración o especifique un dispositivo o controlador específico en la línea de

comandos.

"driver timeout" - El controlador en banda ha agotado el tiempo de espera comunicándose con el BMC o el procesador de servicio local. El BMC o el procesador de servicio puede estar ocupado o (en el peor de los casos) posiblemente no

funcionando.

"internal IPMI error" - Ha ocurrido un error IPMI que Free

IPMI no sabe cómo manejar. Por favor, envíe un correo electrón
ico a <freeipmi-users@gnu.org> para informar del problema.

SOLUCIONES

ALTERNATIVAS

Con tantos proveedores diferentes implementando sus propias soluciones IPMI, diferentes proveedores pueden implementar sus protocolos IPMI incorrectamente. Lo siguiente describe un número de soluciones alternativas actualmente disponibles para manejar problemas de cumplimiento descubiertos. Cuando sea posible, se han implementado soluciones alternativas de modo que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se use una solución alternativa mediante la opción

-W.

El hardware listado a continuación puede solo indicar el hardware en el que se descubrió un problema. Las versiones más nuevas de hardware pueden corregir los problemas indicados a continuación. Máquinas similares de proveedores pueden o no exhibir los mismos problemas. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede valer la pena probar las soluciones alternativas listadas a continuación incluso si su placa base no está

listada.

Si cree que su hardware tiene un problema de cumplimiento adicionale que necesita una solución alternativa para ser implementada, por favor contacte a los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.

org>

. assumeio - Esta bandera de solución alternativa asumirá que las interfaces inband se comunican con las E/S del sistema en lugar de estar mapeadas en memoria. Esto funcionará como solución para sistemas que reportan direcciones base inválidas. Aquellos que se encuentren con este problema pueden ver errores "device not supported" o "could not find inband device". Problema

observado

en HP ProLiant DL145 G1. spinpoll - Esta bandera de solución alternativa informará a algunos controladores inband (el más notable es el controlador KCS) que den vueltas mientras hacen sondeos en lugar de poner el proceso a dormir. Esto puede mejorar significativamente el tiempo de ejecución real de las herramientas porque la granularidad del planificador del sistema operativo puede ser mucho mayor que el tiempo que tarda en realizarse una única transacción de mensaje IPMI. Sin embargo, al dar vueltas, su sistema puede estar realizando un trabajo menos útil al no cambiar el

contexto

de la herramienta para una tarea más útil. authcap - Esta bandera de solución alternativa omitirá las verificaciones tempranas de capacidades de nombre de usuario, capacidades de autenticación y soporte de K_g y permitirá que la autenticación IPMI tenga éxito. Funciona como solución para múltiples problemas en los que el sistema remoto no reporta correctamente las capacidades de nombre de usuario, las capacidades de autenticación o el estado de K_g. Aquellos que se encuentren con este problema pueden ver errores "username invalid", "authentication type unavailable for attempted privilege level" o "k_g invalid". Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4,

Intel

SR1520ML/X38ML y Sun Fire 2200/4150/4450 con ELOM. nochecksumcheck - Esta bandera de solución alternativa le dirá a FreeIPMI que no verifique las sumas de verificación devueltas por las respuestas de comandos IPMI. Funciona como solución para sistemas que devuelven sumas de verificación inválidas debido a errores de implementación, pero el paquete es de otro modo válido. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina la validación de la integridad del paquete en una serie de circunstancias. Sin embargo, es poco probable que sea un problema en la mayoría de las situaciones. Aquellos que se encuentren con este problema pueden ver errores "connection timeout", "session timeout" o "password verification timeout". En conexiones IPMI 1.5, la solución alternativa "noauthcodecheck" también puede ser necesaria.

Problema

observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F y Supermicro X9DRFR. idzero - Esta bandera de solución alternativa permitirá que el cliente acepte identificadores de sesión vacíos. Funciona como solución para sesiones IPMI que reportan identificadores de sesión vacíos al cliente. Aquellos que se encuentren

con

este problema pueden ver errores "session timeout". Aquellos que se encuentren con este problema pueden

ver

errores "session timeout". Problema observado en Dell PowerEdge 2850, SC1425. Confirmado como corregido en firmware más reciente. forcepermsg - Esta bandera de solución alternativa forzará el uso de la autenticación por mensaje sin importar lo que anuncie el sistema remoto. Funciona como solución a un problema cuando la autenticación por mensaje se anuncia como deshabilitada en el sistema remoto, pero en realidad es requerida por el protocolo. Aquellos

que

se encuentren con este problema pueden ver errores "session timeout". Se advierte a los usuarios sobre el uso de esta opción, ya que elimina una verificación de autenticación que valida la integridad de un paquete.
