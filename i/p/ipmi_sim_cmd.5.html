ipmi_sim_cmd(5) Comandos del simulador LAN de IPMI ipmi_sim_cmd(5)

DESCRIPCIÓN

La emulación ipmi_sim se configura utilizando estos comandos. Pueden leerse desde un archivo de comandos, ejecutarse desde la línea de comandos o ejecutarse dentro del simulador después de que este se haya iniciado.

Esto puede ser un poco confuso, pero las interfaces de red se configuran mediante el archivo de configuración de ipmi_lan, y los diversos controladores de gestión, sensores, etc., se especifican utilizando este archivo. Además, esto se puede utilizar para configurar el simulador una vez que está activo, establecer valores de sensor, inyectar eventos y cosas de esa naturaleza.

COMANDOS GENERALES

Las líneas en blanco y las líneas que comienzan con '#' se ignoran. Las líneas largas pueden dividirse colocando una ' al final de la línea a continuar.

quit
Salir del simulador.
include "archivo"
Incluir el archivo dado.
define nombre "valor"

Define el nombre dado como una variable con el valor dado. Esta variable puede usarse más tarde haciendo $nombre. Esto no se puede usar entre comillas, pero las comillas pueden dividirse y la variable colocarse entre ellas. Por ejemplo, si dices:

define MCNUM "40"

puedes usarlo más tarde como en

mc_add $MCNUM 1 no-device-sdrs 00 00 00 0xc9 0x009000 0x0002

o

sensor_add $MCNUM 0 21 12 0x6f poll 1000 file "/sys/dev/sens1-"$MCNUM"-1"

sleep tiempo
Pausar la interfaz de comandos durante el número dado de segundos. Esto no afecta la ejecución del simulador.
debug opciones
Establecer la salida de depuración. Las opciones válidas son:

msg Volcar mensajes.

raw Volcar E/S en bruto

Introducir nada desactiva la depuración.

read_cmds nombre_archivo
Ejecutar los comandos del archivo dado.

COMANDOS MC

mc_add DireccionIPMB IDDispositivo TieneDispositivoSDRs RevisionDispositivo RevFWMayor RevFWMenor SoporteDispositivo IDFabricante IDProducto
Añadir un MC al simulador. Todos los valores son hexadecimales. Estos son principalmente valores para el comando ``Get Device ID'', véase la especificación para más detalles. Tenga en cuenta que el MC no se habilita después de ser añadido, debe añadirlo.

Tenga en cuenta que algunos de estos valores controlan las capacidades del MC. Por ejemplo, HasDeviceSDRs establece si los comandos del repositorio SDR del dispositivo funcionarán.

Puede usar has-device-sdrs o no-device-sdrs en el campo HasDeviceSDRs.

mc_add_fru_data direccion_mc IDDispositivo TamañoFRU (datos [byte1 [byte2 [...]]] | archivo desplazamiento nombre_archivo)
Establecer los datos FRU para un MC y un ID de dispositivo dados. Los datos pueden proporcionarse directamente aquí, o pueden darse como un archivo. El desplazamiento es el inicio desde el principio del archivo donde se guardan los datos.
mc_dump_fru_data direccion_mc IDDispositivo
Volcar los datos FRU para un MC y un ID de dispositivo dados.
mc_delete direccion_mc
Eliminar el MC del sistema.
mc_disable direccion_mc
Deshabilitar el MC, pero no eliminarlo.
mc_enable direccion_mc
Habilitar el MC dado.
mc_setbmc direccion_mc
Establecer la dirección del BMC.
mc_set_guid direccion_mc guid
Establecer el valor GUID. El GUID puede ser una cadena (entre comillas) o una cadena hexadecimal.
sel_enable direccion_mc max_entradas flags
Habilitar el Registro de Eventos del Sistema en el MC dado. El campo flags es un byte que se devuelve desde el comando ``Get SEL Info''; controla varios aspectos del SEL. Véase la especificación para más detalles.
sel_add direccion_mc TipoRegistro byte1 byte2 ... byte13
Añadir una entrada al SEL del MC.
main_sdr_add direccion_mc byte1 [byte2 [...]]
Añadir una entrada al SDR principal del MC.
device_sdr_add direccion_mc LUN byte1 [byte2 [...]]
Añadir una entrada al SDR del dispositivo del MC.

COMANDOS SENSOR

sensor_add direccion_mc LUN num_sensor tipo_sensor codigo_lectura_evento [poll tasa_poll tipo_poll opciones_tipo_poll] [solo_evento]

Añadir un sensor al MC y LUN dados. El tipo de sensor se establece mediante el código de lectura de eventos.

Si se especifica poll, el sensor será consultado para obtener datos. Actualmente solo se admite el tipo de consulta file. El valor es un número leído de un archivo. Tiene las siguientes opciones, todas opcionales:

div=val dividirá el valor leído por el número dado. Esto se hace después de la operación de multiplicación.

mult=val multiplicará el valor leído por el número dado. Esto se hace después de la resta.

sub=val restará el valor por el número dado. Esto se hace después de la máscara.

mask=val enmascarará (AND bit a bit) el valor por el número dado.

base=valor Especifica la base del valor leído del archivo. Por defecto es cero, lo que significa que se utilizan las convenciones de "C".

initstate=valor establece cuál es el estado del evento inicialmente. Esto es útil para sensores discretos con bits que normalmente deben establecerse en "1", como un bit de presencia, para evitar que el programa emita un evento cada vez que se inicia.

raw especifica que los datos del archivo son un valor bruto. Solo se leen longitud bytes de desplazamiento.

ascii especifica que los datos del archivo están en ASCII. Este es el valor predeterminado. Se utiliza el valor de desplazamiento, pero no el de longitud.

length=val especifica la longitud de los datos a leer del archivo. El valor máximo es 4, y esto solo se usa para datos brutos.

depends=<direccion_mc>,<lun>,<numero_sensor>,<bit> especifica un bit de sensor discreto que debe establecerse en 1 para que el sensor esté activo. Generalmente, se utiliza el bit de presencia de un sensor para marcar si otros sensores del dispositivo están realmente presentes. Cada uno de los otros sensores tendría uno de estos apuntando al bit de presencia.

solo_evento especifica que el sensor no será legible, solo generará eventos (especificado con un SDR de tipo 3).

sensor_set_bit direccion_mc LUN num_sensor bit_a_establecer valor_bit generar_evento
Establece el bit dado a valor_bit (0 o 1) para el sensor por número de bit, ya sea el umbral para analógico o el bit del sensor discreto. Si generar_evento no es cero y el sensor tiene eventos habilitados para ese bit, entonces genera un evento.
sensor_set_bit_clr_rest direccion_mc LUN num_sensor bit_a_establecer valor_bit generar_evento
Al igual que sensor_set_bit, pero borra automáticamente todos los demás bits.

COMANDOS DE SENSOR

sensor_set_value mc-addr LUN sensor-num valor generar-evento
Establece el valor en bytes para un sensor analógico. Si el sensor excede un umbral, tiene eventos habilitados y generar-evento no es cero, entonces genera un evento para la condición.
sensor_set_hysteresis mc-addr LUN sensor-num soporte positivo negativo
Establece las capacidades de histéresis del sensor. Debe ser un sensor analógico. El valor de soporte es la capacidad de histéresis, lo mismo que el valor de soporte de histéresis en el SDR del sensor. Los valores de histéresis positiva y negativa también se establecen con este comando.

El valor de soporte también puede ser none, readable, settable, o fixed en lugar de los números.

sensor_set_threshold mc-addr LUN sensor-num soporte-umbral umbral-habilitado [valor5 [valor4 [... [valor0]]]]

Establece el soporte de umbrales para un sensor. Debe ser un sensor analógico. El valor de soporte-umbral es el mismo que el valor de soporte de acceso a umbrales en el SDR del sensor. Los valores de umbral-habilitado son una cadena de caracteres "0" y "1" que habilitan los 6 umbrales correspondientes; el valor más a la derecha es el valor 0, el más a la izquierda es el valor 5. Opcionalmente, los valores de umbral pueden especificarse como sus valores en bytes.

El valor de soporte-umbral también puede ser none, readable, settable, o fixed para hacerlo un poco más legible. Los umbrales son:

0 - inferior no crítico

1 - inferior crítico

2 - inferior no recuperable

3 - superior no crítico

4 - superior crítico

5 - superior no recuperable

sensor_set_event_support mc-addr LUN sensor-num eventos-habilitados escaneo soporte-evento soporte-afirmacion soporte-desafirmacion afirmacion-habilitada desafirmacion-habilitada

Establece el soporte de eventos de un sensor. eventos-habilitados habilitará eventos globales en el sensor si no es cero, de lo contrario, estarán deshabilitados. Los valores de escaneo establecen el valor de escaneo para el sensor. El valor de soporte-evento establece las capacidades de eventos en el sensor, esto es lo mismo que el valor "soporte de control de mensajes de eventos del sensor" en el SDR del sensor. soporte-afirmacion, soporte-desafirmacion, afirmacion-habilitada, y desafirmacion-habilitada son todas máscaras de bits (una cadena de caracteres "0" y "1") que establecen la capacidad de sus bits de sensor correspondientes para generar eventos (soporte) y si generarán eventos ahora (habilitado).

Tenga en cuenta que todas las máscaras de bits tienen el dígito más a la derecha como el bit cero, y el dígito más a la izquierda como el bit de orden más alto. Tenga en cuenta que debe especificar 15 bits aquí, incluso si no los utiliza todos.

Tenga en cuenta que puede usar enable o disable en el campo eventos-habilitados, y puede usar scanning o no-scanning en el campo escaneo.

Para soporte-evento, puede usar per-state, entire-sensor, global o none en lugar de un número.

Para un sensor de umbral, los valores son:

0
- inferior no crítico yendo bajo

1
- inferior no crítico yendo alto

2
- inferior crítico yendo bajo

3
- inferior crítico yendo alto

4
- inferior no recuperable yendo bajo

5
- inferior no recuperable yendo alto

6
- superior no crítico yendo bajo

7
- superior no crítico yendo alto

8
- superior crítico yendo bajo

9
- superior crítico yendo alto

1
- superior no recuperable yendo bajo

1
- superior no recuperable yendo alto

Tenga en cuenta que los valores "inferior yendo alto" y "superior yendo bajo" no son compatibles, ya que son simplemente estúpidos.

COMANDOS OEM ATCA

Estos son para la emulación de capacidades especiales de ATCA.

atca_enable
El sistema es un sistema ATCA, habilita las otras capacidades ATCA.

Tenga en cuenta que debe hacer esto *antes* de crear cualquier MC (esto debería ser realmente lo primero) ya que los MC se configuran de manera un poco diferente para el modo ATCA. Esto hace que los MC puedan manejar comandos PICMG correctamente, configura 2 LEDs por defecto y habilita el manejo adecuado de hot-swap, incluido el LED azul. Por defecto, el LED azul admite control local y los otros LEDs no lo hacen y son rojos.

En modo ATCA, para controlar la máquina de estados de hot-swap, debe usar sensor_set_bit_clr_rest para establecer el estado de hot-swap.

atca_set_site direccion-hardware tipo-sitio numero-sitio
Establece los valores dados para un sistema ATCA, los valores devueltos por los comandos de obtención de dirección.
mc_set_num_leds mc-addr contador
Establece el número de LEDs ATCA que tiene el MC.
mc_set_power mc-addr potencia generar-evento
Establece la configuración de potencia ATCA para el MC como su valor numérico. Si generar-evento no es cero, genera un evento para el cambio.
