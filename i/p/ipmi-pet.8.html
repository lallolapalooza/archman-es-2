IPMI-PET(8) Comandos del sistema IPMI-PET(8)

NOMBRE

ipmi-pet - Intérprete de Trampas de Eventos de Plataforma IPMI

SINOPSIS

ipmi-pet [OPCIÓN...] [TRAP ESPECÍFICO] [ENLACE DE VARIABLE BYTES HEXADECIMALES ...]

DESCRIPCIÓN

Ipmi-pet interpreta bytes hexadecimales de una trampa de eventos de plataforma (PET) y genera una cadena que representa su contenido. Los valores hexadecimales pueden ser introducidos en la línea de comandos, en un archivo a través de la opción --file, o a través de stdin si ninguna de las anteriores se especifica. Ipmi-pet se usa comúnmente en conjunción con un demonio de trampas SNMP para interpretar los resultados de una trampa PET IPMI capturada por el demonio. Mientras que ipmi-pet podría ser llamado directamente desde dicho demonio, típicamente se llama a un script para analizar la salida del demonio SNMP y convertirla a un formato que pueda ser introducido en ipmi-pet. En algunos sistemas, también puede desear enviar un acuse de recibo de PET a un sistema remoto para informarle que la trampa fue recibida y analizada. Se puede enviar uno utilizando la opción --pet-acknowledge. Aunque no se requiere una sesión IPMI para interpretar una PET, los datos del repositorio de datos del sensor (SDR) son necesarios para interpretar correctamente los nombres de los sensores y otra información en la PET. La configuración de la sesión IPMI a continuación, como el controlador, el nombre del host, el nombre de usuario, etc., deben configurarse para cargar el SDR del host de donde se originó la trampa. Si esto es difícil de realizar, puede ser aconsejable almacenar en caché y cargar una caché de SDR específica utilizando la opción --sdr-cache-file. Si el SDR es difícil de obtener, se puede especificar la opción --ignore-sdr-cache para que no se cargue un SDR y no se requiera una sesión IPMI. La PET se interpretará lo mejor posible dada la ausencia de SDR. La opción --ignore-sdr-cache puede afectar a otras opciones como --interpret-oem-data. Algunas opciones, como --manufacturer-id y --product-id, pueden aliviar algunos de estos problemas. Si el demonio SNMP no genera una trampa específica SNMPv1 por sí mismo, típicamente se genera como el último elemento del OID en SNMPv2. Si por alguna razón no se puede determinar una trampa específica, el valor de NA puede ser introducido para la trampa específica para indicar que no está disponible. Ipmi-pet generará la mayor cantidad posible de información basándose en los enlaces de variables. Parte de la información específica de la trampa puede obtenerse a través de información SDR.

A continuación se enumeran las opciones generales de IPMI, las opciones específicas de la herramienta, la información de resolución de problemas, la información de soluciones alternativas, los ejemplos y los problemas conocidos. Para una introducción general a FreeIPMI, consulte freeipmi(7).

OPCIONES GENERALES

Las siguientes opciones son opciones generales para configurar la comunicación IPMI y ejecutar comandos generales de la herramienta.

-D IPMIDRIVER, --driver-type=IPMIDRIVER
Especifica el tipo de controlador a utilizar en lugar de realizar una selección automática. Los controladores de banda ancha (out-of-band) disponibles actualmente son LAN y LAN_2_0, que realizan IPMI 1.5 e IPMI 2.0 respectivamente. Los controladores de banda (in-band) disponibles actualmente son KCS, SSIF, OPENIPMI, SUNBMC e INTELDCMI.
--disable-auto-probe
No sondear dispositivos IPMI de banda para obtener la configuración predeterminada.
--driver-address=DIRECCION-CONTROLADOR
Especifica la dirección del controlador de banda a utilizar en lugar del valor detectado. DIRECCION-CONTROLADOR debe ir precedida de "0x" para un valor hexadecimal y '0' para un valor octal.
--driver-device=DISPOSITIVO
Especifica la ruta del dispositivo del controlador de banda a utilizar en lugar de la ruta detectada.
--register-spacing=ESPACIAMIENTO-REGISTRO
Especifica el espaciamiento de registros del controlador de banda en lugar del valor detectado. El argumento está en bytes (es decir, espaciamiento de registro de 32 bits = 4)
--target-channel-number=NUMERO-CANAL
Especifica el número de canal de destino del controlador de banda para enviar solicitudes IPMI.
--target-slave-address=DIRECCION-ESCLAVO
Especifica el número de esclavo de destino del controlador de banda para enviar solicitudes IPMI.
-h HOST-IPMI, --hostname=HOST-IPMI[:PUERTO]
Especifica el host remoto con el que comunicarse. Se puede especificar un puerto opcional, que puede ser útil en el reenvío de puertos o situaciones similares. Si especifica una dirección IPv6 y un puerto, utilice el formato [DIRECCION]:PUERTO.
-u NOMBRE-USUARIO, --username=NOMBRE-USUARIO
Especifica el nombre de usuario a utilizar al autenticarse con el host remoto. Si no se especifica, se asume un nombre de usuario nulo (es decir, anónimo). El usuario debe tener al menos privilegios de OPERADOR para que esta herramienta funcione completamente.
-p CONTRASEÑA, --password=CONTRASEÑA
Especifica la contraseña a utilizar al autenticarse con el host remoto. Si no se especifica, se asume una contraseña nula. La longitud máxima de la contraseña es 16 para IPMI 1.5 y 20 para IPMI 2.0.
-P, --password-prompt
Solicita la contraseña para evitar la posibilidad de listarla en las listas de procesos.
-k K_G, --k-g=K_G
Especifica la clave K_g BMC a utilizar al autenticarse con el host remoto para IPMI 2.0. Si no se especifica, se asume una clave nula. Para introducir la clave en formato hexadecimal, prefije la cadena con '0x'. Por ejemplo, la clave 'abc' se puede introducir con la cadena 'abc' o la cadena '0x616263'
-K, --k-g-prompt
Solicita k-g para evitar la posibilidad de listarla en las listas de procesos.
--session-timeout=MILLISEGUNDOS
Especifica el tiempo de espera de la sesión en milisegundos. Por defecto es 20000 milisegundos (20 segundos) si no se especifica.
--retransmission-timeout=MILLISEGUNDOS
Especifica el tiempo de espera de retransmisión de paquetes en milisegundos. Por defecto es 1000 milisegundos (1 segundo) si no se especifica. El tiempo de espera de retransmisión no puede ser mayor que el tiempo de espera de la sesión.
-a TIPO-AUTENTICACION, --authentication-type=TIPO-AUTENTICACION
Especifica el tipo de autenticación IPMI 1.5 a utilizar. Los tipos de autenticación disponibles actualmente son NONE, STRAIGHT_PASSWORD_KEY, MD2 y MD5. Por defecto es MD5 si no se especifica.
-I ID-SUITE-CIFRADO, --cipher-suite-id=ID-SUITE-CIFRADO
Especifica el ID de la suite de cifrado IPMI 2.0 a utilizar. El ID de la Suite de Cifrado identifica un conjunto de algoritmos de autenticación, integridad y confidencialidad a utilizar para la comunicación IPMI 2.0. El algoritmo de autenticación identifica el algoritmo a utilizar para la configuración de la sesión, el algoritmo de integridad identifica el algoritmo a utilizar para las firmas de paquetes de sesión, y el algoritmo de confidencialidad identifica el algoritmo a utilizar para el cifrado de carga útil. SDR.
--flush-cac
he
Vacía la versión en caché del repositorio de datos de sensores (SDR). El SDR se almacena típicamente en caché para un acceso posterior más rápido. Sin embargo, puede necesitar ser vaciado y regenerado si el SDR ha sido actualizado en un
sistema.
--quiet-cac
he
No muestra información sobre la creación/borrado de la caché. Puede ser útil en
scripts.

Si la caché SDR está desactualizada o es inválida, regenera automáticamente la caché del repositorio de datos de sensores (SDR). Esta opción puede ser útil para propósitos de

SOLUCIÓN DE PROBLEMAS

GENERAL

La mayoría de las veces, los problemas de IPMI se deben a problemas de

configuración.

Los problemas de IPMI sobre LAN implican una configuración incorrecta del BMC de la máquina remota. Verifique dos veces para asegurarse de que lo siguiente está configurado correctamente en el BMC de la máquina remota: dirección IP, dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio LAN, habilitación LAN y tipo(s) de autenticación permitidos. Para conexiones IPMI 2.0, verifique dos veces para asegurarse de que los privilegios del conjunto de cifrado y la clave K_g están configurados correctamente. La herramienta ipmi-config(8) puede usarse para verificar y/o cambiar estos ajustes de

configuración.

Los problemas de IPMI inband suelen ser causados por controladores mal configurados o BMCs no

estándar.

Además de los consejos de solución de problemas siguientes, consulte SOLUCIONES ALTERNATIVAS más abajo para ver también si se han descubierto y solucionado errores específicos de

proveedores.

A continuación se enumeran muchos de los problemas comunes para los mensajes de error. Para soporte adicional, por favor envíe un correo a la lista de correo <freeipmi-users@gnu.org>

.

"username invalid" - El nombre de usuario introducido (o un nombre de usuario NULL si no se introdujo ninguno) no está disponible en la máquina remota. También es posible que la configuración del nombre de usuario del BMC remoto sea

incorrecta.

"password invalid" - La contraseña introducida (o una contraseña NULL si no se introdujo ninguna) no es correcta. También es posible que la contraseña del usuario no esté configurada correctamente en elemote

BMC.

"password verification timeout" - La verificación de la contraseña ha expirado. Ha ocurrido un error de "contraseña inválida" (descrito arriba) o un "tiempo de espera de sesión" genérico (descrito abajo). En este punto del protocolo no se puede diferenciar cuál

ocurrió.

"k_g invalid" - La clave K_g ingresada (o una clave K_g nula si no se ingresó ninguna) no es correcta. También es posible que la clave K_g no esté configurada correctamente en el BMC

remoto.

"privilege level insufficient" - Un comando IPMI requiere un nivel de privilegio de usuario más alto que el con el que se autenticó. Intente autenticarse con un nivel de privilegio más alto. Esto puede requerir autenticarse con un usuario diferente que tenga un privilegio máximo más

alto.

"privilege level cannot be obtained for this user" - El nivel de privilegio con el que intenta autenticarse es más alto que el máximo permitido para este usuario. Intente de nuevo con un privilegio más bajo. También es posible que el nivel máximo de privilegio permitido para un usuario no esté configurado correctamente en el BMC

remoto.

"authentication type unavailable for attempted privilege level" - El tipo de autenticación con el que desea autenticarse no está disponible para este nivel de privilegio. Intente de nuevo con un tipo de autenticación alternativo o un nivel de privilegio alternativo. También es posible que los tipos de autenticación disponibles con los que puede autenticarse no estén configurados correctamente en el BMC

remoto.

"cipher suite id unavailable" - El id de suite de cifrado con el que desea autenticarse no está disponible en el BMC remoto. Intente de nuevo con un id de suite de cifrado alternativo. También es posible que los ids de suite de cifrado disponibles no estén configurados correctamente en el BMC

remoto.

"ipmi 2.0 unavailable" - No se detectó IPMI 2.0 en la máquina remota. Intente usar IPMI 1.5 en su

lugar.

"connection timeout" - La comunicación IPMI inicial falló. Hay varios errores potenciales posibles, incluyendo un nombre de host inválido especificado, una dirección IP de IPMI que no se puede resolver, IPMI no está habilitado en el servidor remoto, la conexión de red es deficiente, etc. Verifique la configuración y la

conectividad.

"session timeout" - La sesión IPMI ha expirado. Reconéctese. Si este error ocurre con frecuencia, es posible que desee aumentar el tiempo de espera de retransmisión. Algunos BMCs remotos son considerablemente más lentos que

otros.

"device not found" - No se pudo encontrar el dispositivo especificado. Verifique la configuración o las entradas e intente de

nuevo.

"driver timeout" - La comunicación con el controlador o el dispositivo ha expirado. Intente de

nuevo.

"message timeout" - La comunicación con el controlador o el dispositivo ha expirado. Intente de

nuevo.

"BMC busy" - El BMC está ocupado actualmente. Puede estar procesando información o tener demasiadas sesiones simultáneas para gestionar. Espere e intente de

nuevo.

"could not find inband device" - No se pudo encontrar un dispositivo de banda interna. Verifique la configuración o especifique un dispositivo o controlador específico en la línea de

comandos.

"driver timeout" - El controlador de banda interna ha expirado en la comunicación con el BMC o el procesador de servicio local. El BMC o el procesador de servicio puede estar ocupado o (en el peor de los casos) posiblemente no

funcionando.

"internal IPmi error" - Ha ocurrido un error IPMI que Fr

eeIPMI no sabe cómo manejar. Envíe un correo electrónic
o a <freeipmi-users@gnu.org> para informar del problema.

SOLUCIONES

ALTERNATIVAS

Con tantos proveedores diferentes implementando sus propias soluciones IPMI, diferentes proveedores pueden implementar sus protocolos IPMI incorrectamente. A continuación se describen varias soluciones alternativas actualmente disponibles para manejar problemas de cumplimiento descubiertos. Cuando sea posible, las soluciones alternativas se han implementado para que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se use una solución alternativa mediante la opción

-W.

El hardware listado a continuación puede indicar solo el hardware en el que se descubrió un problema. Las versiones más nuevas de hardware pueden corregir los problemas indicados a continuación. Máquinas similares de otros proveedores pueden o no exhibir los mismos problemas. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede valer la pena probar las soluciones alternativas listadas a continuación incluso si su placa base no está

listada.

Si cree que su hardware tiene un problema de cumplimiento adicional que necesita que se implemente una solución alternativa, contacte a los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.org>

.

assumeio - Esta opción de solución alternativa asumirá que las interfaces de banda interna se comunican con las E/S del sistema en lugar de estar mapeadas en memoria. Esto solucionará sistemas que reportan direcciones base inválidas. Los que encuentren este problema pueden ver errores de "device not supported" o "could not find inband device". Problema observado en HP ProLiant DL145

G1.

spinpoll - Esta opción de solución alternativa informará a algunos controladores de banda interna (notoriamente el controlador KCS) que giren mientras hacen sondeos en lugar de poner el proceso a dormir. Esto puede mejorar significativamente el tiempo de ejecución real de las herramientas porque la granularidad del planificador del sistema operativo puede ser mucho mayor que el tiempo que toma realizar una única transacción de mensaje IPMI. Sin embargo, al girar, su sistema puede estar realizando un trabajo menos útil al no cambiar el contexto de la herramienta para una tarea más

útil.

authcap - Esta opción de solución alternativa omitirá las verificaciones tempranas de capacidades de nombre de usuario, capacidades de autenticación y soporte de K_g, y permitirá que la autenticación IPMI tenga éxito. Soluciona múltiples problemas en los que el sistema remoto no reporta correctamente las capacidades de nombre de usuario, las capacidades de autenticación o el estado de K_g. Los que encuentren este problema pueden ver errores de "username invalid", "authentication type unavailable for attempted privilege level" o "k_g invalid". Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML, y Sun Fire 2200/4150/4450 con

ELOM.

nochecksumcheck - Esta opción de solución alternativa le dirá a FreeIPMI que no verifique las sumas de comprobación devueltas por las respuestas de los comandos IPMI. Soluciona sistemas que devuelven sumas de comprobación inválidas debido a errores de implementación, pero el paquete es válido de otro modo. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina la validación de la integridad del paquete en varias circunstancias. Sin embargo, es poco probable que sea un problema en la mayoría de las situaciones. Los que encuentren este problema pueden ver errores de "connection timeout", "session timeout" o "password verification timeout". En conexiones IPMI 1.5, la solución alternativa "noauthcodecheck" también puede ser necesaria. Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F, y Supermicro

X9DRFR.

idzero - Esta opción de solución alternativa permitirá que el cliente acepte IDs de sesión vacíos. Soluciona sesiones IPMI que reportan IDs de sesión vacíos al cliente. Los que encuentren este problema pueden ver errores de "session timeout". Problema observado en Tyan S2882 con BMC

M3289.

unexpectedauth - Esta opción de solución alternativa permitirá que los códigos de autenticación no nulos inesperados se verifiquen como si se esperaran. Soluciona un problema cuando los paquetes contienen datos de autenticación no nulos cuando deberían ser nulos debido a la autenticación por mensaje deshabilitada. Los que encuentren este problema pueden ver errores de "session timeout". Problema observado en Dell PowerEdge 2850, SC1425. Confirmado corregido en firmware más

nuevo.

forcepermsg - Esta opción de solución alternativa forzará el uso de la autenticación por mensaje sin importar lo que anuncie el sistema remoto. Soluciona un problema cuando la autenticación por mensaje se anuncia como deshabilitada en el sistema remoto, pero en realidad es requerida por el protocolo. Los que encuentren este problema pueden ver errores de "session timeout". Problema observado en IBM eServer

325.

endianseq - Esta opción de solución alternativa invertirá el orden de los bytes de los números de secuencia de sesión para permitir que la sesión continúe correctamente. Soluciona números de secuencia de sesión IPMI 1.5 con el orden de bytes incorrecto. Los que encuentren este problema pueden ver errores de "session timeout". Problema observado en algunos Sun ILOM 1.0/2.0 (depende del orden de bytes del procesador de servicio)

.

noauthcodecheck - Esta opción de solución alternativa le dirá a FreeIPMI que no verifique los códigos de autenticación devueltos por las respuestas de los comandos IPMI 1.5. Soluciona sistemas que devuelven códigos de autenticación inválidos debido a errores de hash o de implementación. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina una verificación de autenticación que valida la integridad de un paquete. Sin embargo, en la mayoría de las organizaciones, es poco probable que sea un problema de seguridad. Los que encuentren este problema pueden ver errores de "connection timeout", "session timeout" o "password verification timeout". Problema observado en Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell, y Wiwynn

Windmill.

intel20 - Esta opción de solución alternativa solucionará varios problemas de autenticación IPMI 2.0 de Intel. Los problemas cubiertos incluyen el relleno de nombres de usuario y el truncamiento de contraseñas si el algoritmo de autenticación es HMAC-MD5-128. Los que encuentren este problema pueden ver errores de "username invalid", "password invalid" o "k_g invalid". Problema observado en Supermicro H8QME con tarjeta hija SIMSO. Confirmado corregido en firmware más

nuevo.

sun20 - Esta opción de solución alternativa solucionará varios problemas de autenticación IPMI 2.0 de Sun. Los problemas cubiertos incluyen claves hash de longitud inválida, claves hash incorrectamente calculadas y registros de suite de cifrado inválidos. Los que encuentren este problema pueden ver errores de "password invalid" o "bmc error". Problema observado en Sun Fire 4100/4200/4500 con ILOM. "opensesspriv".
