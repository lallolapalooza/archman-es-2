NOMBRE

ipmiconsole - Utilidad de consola IPMI

SINOPSIS

ipmiconsole [OPCIÓN...]

DESCRIPCIÓN

ipmiconsole es una utilidad de consola Serial-over-LAN (SOL). Se puede utilizar para establecer sesiones de consola a máquinas remotas utilizando el protocolo IPMI 2.0 SOL. Ipmiconsole se comunica con el controlador de placa base (BMC) de una máquina remota para establecer una sesión de consola. Antes de que pueda tener lugar cualquier comunicación SOL, el BMC de la máquina remota debe estar configurado correctamente. La herramienta FreeIPMI ipmi-config(8) puede ser utilizada para realizar esta configuración.

A menudo (aunque no siempre), la redirección de consola también debe estar configurada correctamente en la BIOS y/o el sistema operativo. Ambos deben estar configurados para redirigir el tráfico de consola a través del puerto COM apropiado. Consulte la documentación de su placa base y sistema operativo para obtener instrucciones sobre la configuración adecuada.

A continuación se enumeran las opciones generales de IPMI, las opciones específicas de la herramienta, la información de resolución de problemas, la información de soluciones alternativas, ejemplos y problemas conocidos. Para una introducción general a FreeIPMI, consulte freeipmi(7).

OPCIONES GENERALES

Las siguientes opciones son opciones generales para configurar la comunicación IPMI y ejecutar comandos generales de la herramienta.

-h IPMIHOST, --hostname=IPMIHOST[:PUERTO]
Especifica el host remoto con el que comunicarse. Se puede especificar un puerto opcional, que puede ser útil en situaciones de reenvío de puertos o similares. Si se especifica una dirección IPv6 y un puerto, utilice el formato [DIRECCIÓN]:PUERTO.
-u, --username=NOMBREDEUSUARIO
Especifica el nombre de usuario a utilizar al autenticarse con el host remoto. Si no se especifica, se asume un nombre de usuario nulo (es decir, anónimo). El usuario debe tener un nivel de privilegios suficiente para establecer una sesión SOL y tener las capacidades de sesión SOL.
-p CONTRASEÑA, --password=CONTRASEÑA
Especifica la contraseña a utilizar al autenticarse con el host remoto. Si no se especifica, se asume una contraseña nula. La longitud máxima de la contraseña es de 16 para IPMI 1.5 y 20 para IPMI 2.0.
-P, --password-prompt
Solicita la contraseña para evitar la posibilidad de incluirla en las listas de procesos.
-k K_G, --k-g=K_G
Especifica la clave K_g del BMC a utilizar al autenticarse con el host remoto para IPMI 2.0. Si no se especifica, se asume una clave nula. Para introducir la clave en formato hexadecimal, prefije la cadena con '0x'. Por ejemplo, la clave 'abc' se puede introducir con la cadena 'abc' o la cadena '0x616263'.
-K, --k-g-prompt
Solicita k-g para evitar la posibilidad de incluirlo en las listas de procesos.
--session-timeout=MILISEGUNDOS
Especifica el tiempo de espera de la sesión en milisegundos. El valor predeterminado es 60000 milisegundos (60 segundos) si no se especifica.
--retransmission-timeout=MILISEGUNDOS
Especifica el tiempo de espera de retransmisión de paquetes en milisegundos. El valor predeterminado es 500 milisegundos (0,5 segundos) si no se especifica.
-I, --cipher-suite-id=ID-DEL-SUITE-DE-CIFRADO
Especifica el ID del conjunto de cifrado IPMI 2.0 a utilizar. El ID del conjunto de cifrado identifica un conjunto de algoritmos de autenticación, integridad y confidencialidad a utilizar para la comunicación IPMI 2.0. El algoritmo de autenticación identifica el algoritmo a utilizar para la configuración de la sesión, el algoritmo de integridad identifica el algoritmo a utilizar para las firmas de paquetes de la sesión y el algoritmo de confidencialidad identifica el algoritmo a utilizar para el cifrado de la carga útil. El valor predeterminado es el ID del conjunto de cifrado 3 si no se especifica. El usuario debe tener en cuenta que solo los IDs de conjuntos de cifrado 3, 8 y 12 cifran las cargas útiles de la consola. La información de la consola se enviará en claro si se selecciona un ID de conjunto de cifrado alternativo. Los siguientes IDs de conjuntos de cifrado son compatibles actualmente:

0 - Algoritmo de autenticación = Ninguno; Algoritmo de integridad = Ninguno; Algoritmo de confidencialidad = Ninguno

1 - Algoritmo de autenticación = HMAC-SHA1; Algoritmo de integridad = Ninguno; Algoritmo de confidencialidad = Ninguno

2 - Algoritmo de autenticación = HMAC-SHA1; Algoritmo de integridad = HMAC-SHA1-96; Algoritmo de confidencialidad = Ninguno

3 - Algoritmo de autenticación = HMAC-SHA1; Algoritmo de integridad = HMAC-SHA1-96; Algoritmo de confidencialidad = AES-CBC-128

6 - Algoritmo de autenticación = HMAC-MD5; Algoritmo de integridad = Ninguno; Algoritmo de confidencialidad = Ninguno

7 - Algoritmo de autenticación = HMAC-MD5; Algoritmo de integridad = HMAC-MD5-128; Algoritmo de confidencialidad = Ninguno

8 - Algoritmo de autenticación = HMAC-MD5; Algoritmo de integridad = HMAC-MD5-128; Algoritmo de confidencialidad = AES-CBC-128

11 - Algoritmo de autenticación = HMAC-MD5; Algoritmo de integridad = MD5-128; Algoritmo de confidencialidad = Ninguno

12 - Algoritmo de autenticación = HMAC-MD5; Algoritmo de integridad = MD5-128; Algoritmo de confidencialidad = AES-CBC-128

15 - Algoritmo de autenticación = HMAC-SHA256; Algoritmo de integridad = Ninguno; Algoritmo de confidencialidad = Ninguno

16 - Algoritmo de autenticación = HMAC-SHA256; Algoritmo de integridad = HMAC_SHA256_128; Algoritmo de confidencialidad = Ninguno

17 - Algoritmo de autenticación = HMAC-SHA256; Algoritmo de integridad = HMAC_SHA256_128; Algoritmo de confidencialidad = AES-CBC-128

-l NIVEL-DE-PRIVILEGIO, --privilege-level=NIVEL-DE-PRIVILEGIO
Especifica el nivel de privilegio a utilizar. Los niveles de privilegio actualmente disponibles son USUARIO, OPERADOR y ADMINISTRADOR. El valor predeterminado es ADMINISTRADOR si no se especifica.
--config-file=ARCHIVO
Especifica un archivo de configuración alternativo.
-W SOLUCIONES-ALTERNATIVAS, --workaround-flags=SOLUCIONES-ALTERNATIVAS
Especifica soluciones alternativas para problemas de cumplimiento del proveedor. Se pueden especificar varias soluciones alternativas separadas por comas. Una opción de línea de comandos especial "none" indicará que no hay soluciones alternativas (puede ser útil para anular los valores predeterminados configurados). Consulte SOLUCIONES ALTERNATIVAS a continuación para obtener una lista de las soluciones alternativas disponibles.
--debug
Activar la depuración.
-?, --help
Muestra una lista de ayuda y sale.
--usage
Muestra un mensaje de uso y sale.
-V, --version
Muestra la versión del programa y sale.

OPCIONES DE IPMICONSOLE

Las siguientes opciones son específicas de ipmiconsole.

-e CARÁCTER, --escape-char=CARÁCTER
Especifica un carácter de escape alternativo (carácter predeterminado '&').
--dont-steal
No robar una sesión SOL si ya se detecta que una está en uso. En la mayoría de las circunstancias, si se detecta que SOL está en uso, ipmiconsole intentará robar la sesión SOL a la sesión anterior. Este comportamiento predeterminado existe por varias razones, sobre todo porque las sesiones SOL anteriores pueden no haberse podido desactivar correctamente.
--deactivate
Desactiva la sesión SOL si se detecta que está en uso y sale.
--serial-keepalive
Envía periódicamente caracteres NUL para detectar conexiones seriales inactivas. Esta opción es particularmente útil para aquellos que pretenden ejecutar ipmiconsole sin mucha interacción, como para fines de registro. Si bien las conexiones IPMI aún pueden estar activas, algunas placas base han presentado errores en los que los datos seriales subyacentes ya no se pueden enviar/recibir. GENERAL

TROUBLESHOOTING

Most often, IPMI problems are due to configuration

problems.

IPMI over LAN problems involve a misconfiguration of the remote machine's BMC. Double check to make sure the following are configured properly in the remote machine's BMC: IP address, MAC address, subnet mask, username, user enablement, user privilege, password, LAN privilege, LAN enablement, and allowed authentication type(s). For IPMI 2.0 connections, double check to make sure the cipher suite privilege(s) and K_g key are configured properly. The ipmi-config(8) tool can be used to check and/or change these configuration

settings.

In addition to the troubleshooting tips below, please see WORKAROUNDS below to also if there are any vendor specific bugs that have been discovered and worked

around.

Listed below are many of the common issues for error messages. For additional support, please e-mail the <freeipmi-users@gnu.org> mailing

list.

"username invalid" - The username entered (or a NULL username if none was entered) is not available on the remote machine. It may also be possible the remote BMC's username configuration is

incorrect.

"password invalid" - The password entered (or a NULL password if none was entered) is not correct. It may also be possible the password for the user is not correctly configured on the remote

BMC.

"password verification timeout" - Password verification has timed out. A "password invalid" error (described above) or a generic "session timeout" (described below) occurred. During this point in the protocol it cannot be differentiated which

occurred.

"k_g invalid" - The K_g key entered (or a NULL K_g key if none was entered) is not correct. It may also be possible the K_g key is not correctly configured on the remote

BMC.

"privilege level insufficient" - An IPMI command requires a higher user privilege than the one authenticated with. Please try to authenticate with a higher privilege. This may require authenticating to a different user which has a higher maximum

privilege.

"privilege level cannot be obtained for this user" - The privilege level you are attempting to authenticate with is higher than the maximum allowed for this user. Please try again with a lower privilege. It may also be possible the maximum privilege level allowed for a user is not configured properly on the remote

BMC.

"authentication type unavailable for attempted privilege level" - The authentication type you wish to authenticate with is not available for this privilege level. Please try again with an alternate authentication type or alternate privilege level. It may also be possible the available authentication types you can authenticate with are not correctly configured on the remote

BMC.

"cipher suite id unavailable" - The cipher suite id you wish to authenticate with is not available on the remote BMC. Please try again with an alternate cipher suite id. It may also be possible the available cipher suite ids are not correctly configured on the remote

BMC.

"ipmi 2.0 unavailable" - IPMI 2.0 was not discovered on the remote machine. Please try to use IPMI 1.5

instead.

"connection timeout" - Initial IPMI communication failed. A number of potential errors are possible, including an invalid hostname specified, an IPMI IP address cannot be resolved, IPMI is not enabled on the remote server, the network connection is bad, etc. Please verify configuration and

connectivity.

"session timeout" - The IPMI session has timed out. Please reconnect. If this error occurs often, you may wish to increase the retransmission timeout. Some remote BMCs are considerably slower than

others.

"internal IPMI error" - An IPMI error has occurred tha

t FreeIPMI does not know how to handle. Please e-
mail <freeipmi-users@gnu.org> to report the issue.

IPMICONSOLE

TROUBLESHOOTING

The following are common issues for error messages in ipmiconsole

.

"SOL unavailable" - SOL is not configured for use on the remote BMC. It may be not configured in general or for the specific user specified. Authenticating with a different user may be sufficient, however the IPMI protocol does not reveal detail on what is not configured on the remote

BMC.

"SOL in use" - SOL is already in use on the remote BMC. If you do not specify the --dont-steal option, ipmiconsole will attempt to steal the SOL session away from the other session. Not all BMCs support the ability to steal away a SOL

session.

"SOL session stolen" - Your SOL session has been stolen by another session. You may wish to try and steal the session back by

reconnecting.

"SOL requires encryption" - SOL requires a cipher suite id that includes encryption. Please try to use cipher suite id 3, 8, or 12. It may also be possible the encryption requirements are not configured correctly on the remote

BMC.

"SOL requires no encryption" - SOL requires a cipher suite id that does not use encryption. Please try to use cipher suite id 0, 1, 2, 6, 7, or 11. It may also be possible the encryption requirements are not configured correctly on the remote

BMC.

"BMC Implementation" - The BMC on the remote machine has a severe problem in its implementation. Please see the WORKAROUNDS section below for possible workarounds. If additional vendor workarounds are required, please contact the

authors.

"excess retransmissions sent" - An excessive number of retransmissions of SOL packets has occurred and ipmiconsole has given up. This may be due to network issues or SOL issues. Some of the same issues involved with "connection timeout" or "session timeout" errors may be involved. Please try to

reconnect.

"excess errors received" - An excessive number of SOL packet errors has occurred and ipmiconsole has given up. This may be due to network issues or SOL issues. Please try to

reconnect.

"BMC Error" - This error usually means a vendor SOL implementation requires a combination of authentication, encryptio

n, privilege, etc. that have not been met by the user's choices. Please try a combination of different cipher suite
s, privileges, etc. to resolve the problem. Please see the WORKAROUNDS section below for possible workarounds too.

WORKAROUND

S

With so many different vendors implementing their own IPMI solutions, different vendors may implement their IPMI protocols incorrectly. The following describes a number of workarounds currently available to handle discovered compliance issues. When possible, workarounds have been implemented so they will be transparent to the user. However, some will require the user to specify a workaround be used via the -W

option.

The hardware listed below may only indicate the hardware that a problem was discovered on. Newer versions of hardware may fix the problems indicated below. Similar machines from vendors may or may not exhibit the same problems. Different vendors may license their firmware from the same IPMI firmware developer, so it may be worthwhile to try workarounds listed below even if your motherboard is not

listed.

If you believe your hardware has an additional compliance issue that needs a workaround to be implemented, please contact the FreeIPMI maintainers on <freeipmi-users@gnu.org> or <freeipmi-devel@gnu.org>

.

authcap - This workaround flag will skip early checks for username capabilities, authentication capabilities, and K_g support and allow IPMI authentication to succeed. It works around multiple issues in which the remote system does not properly report username capabilities, authentication capabilities, or K_g status. Those hitting this issue may see "username invalid", "authentication type unavailable for attempted privilege level", or "k_g invalid" errors. Issue observed on Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML, and Sun Fire 2200/4150/4450 with

ELOM.

nochecksumcheck - This workaround flag will tell FreeIPMI to not check the checksums returned from IPMI command responses. It works around systems that reconvierta sumas de verificación inválidas debido a errores de implementación, pero el paquete es de otro modo válido. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina la validación de la integridad del paquete en una serie de circunstancias. Sin embargo, es poco probable que sea un problema en la mayoría de las situaciones. Aquellos que se encuentren con este problema pueden ver errores de "connection timeout", "session timeout" o "password verification timeout". En las conexiones IPMI 1.5, también puede ser necesaria la solución alternativa "noauthcodecheck". Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F y Supermicro

X9DRFR.

intel20 - Esta bandera de solución alternativa resolverá varios problemas de autenticación de IPMI 2.0 de Intel. Los problemas cubiertos incluyen el relleno de nombres de usuario y la truncación de contraseñas si el algoritmo de autenticación es HMAC-MD5-128. Aquellos que se encuentren con este problema pueden ver errores de "username invalid", "password invalid" o "k_g invalid". Problema observado en Intel SE7520AF2 con Intel Server Management Module (Professional Edition)

.

supermicro20 - Esta bandera de solución alternativa resolverá varios problemas de autenticación de IPMI 2.0 de Supermicro en placas base con firmware IPMI de Peppercon. Los problemas cubiertos incluyen el manejo de códigos de autenticación de longitud inválida. Aquellos que se encuentren con este problema pueden ver errores de "password invalid". Problema observado en Supermicro H8QME con tarjeta hija SIMSO. Confirmado como corregido en firmware más

reciente.

sun20 - Esta bandera de solución alternativa resolverá varios problemas de autenticación de IPMI 2.0 de Sun. Los problemas cubiertos incluyen claves de hash de longitud inválida, claves con hash incorrecto y registros de suite de cifrado inválidos. Aquellos que se encuentren con este problema pueden ver errores de "password invalid" o "bmc error". Problema observado en Sun Fire 4100/4200/4500 con ILOM. Esta solución alternativa incluye automáticamente la solución alternativa

"opensesspriv".

opensesspriv - Esta bandera de solución alternativa alterará ligeramente el protocolo de conexión IPMI 2.0 de FreeIPMI para solucionar un algoritmo de hash inválido utilizado por el sistema remoto. El nivel de privilegio enviado durante la etapa de Apertura de Sesión de una conexión IPMI 2.0 se utiliza para las claves de hash en lugar del nivel de privilegio enviado durante la etapa de conexión RAKP1. Aquellos que se encuentren con este problema pueden ver errores de "password invalid", "k_g invalid", "bad rmcpplus status code" o "privilege level cannot be obtained for this user". Problema observado en Sun Fire 4100/4200/4500 con ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220 y el software BMC OpenIPMI. Esta solución alternativa se activa automáticamente con la solución alternativa

"sun20".

integritycheckvalue - Esta bandera de solución alternativa resolverá un valor de verificación de integridad inválido durante el establecimiento de una sesión IPMI 2.0 al usar el ID de Suite de Cifrado 0. El valor de verificación de integridad debería tener una longitud de 0, sin embargo, la placa base remota responde con un campo no vacío. Aquellos que se encuentren con este problema pueden ver errores de "k_g invalid". Problema observado en Supermicro X8DTG, Supermicro X8DTU, Intel S5500WBV/Penguin Relion 700 e Intel S2600JF/Appro

512X.

solpayloadsize - Esta bandera de solución alternativa no comprobará los tamaños de carga útil de SOL válidos y asumirá un conjunto adecuado. Soluciona sistemas remotos que informan tamaños de carga útil de SOL de IPMI 2.0 inválidos. Aquellos que se encuentren con este problema pueden ver errores de "BMC Implementation". Problema observado en Asus P5M2/RS162-E4/RX4, Intel SR1520ML/X38ML, Inventec 5441/Dell Xanadu II, Sun x4100, Supermicro X8DTH, Supermicro X8DTG, Supermicro X8DTU y Quanta QSSC-S4R//Appro

GB812X-CN.

solport - Esta bandera de solución alternativa ignorará los puertos SOL alternativos especificados durante el protocolo. Soluciona sistemas remotos que informan puertos SOL alternativos inválidos. Aquellos que se encuentren con este problema pueden ver errores de "connection timeout". Problema observado en Asus P5MT-R y Supermicro

X8DTH-iF.

solstatus - Esta bandera de solución alternativa no comprobará el estado de activación actual de SOL durante la configuración del protocolo. Soluciona sistemas remotos que no admiten correctamente este comando. Aquellos que se encuentren con este problema pueden ver errores de "BMC Error". Problema observado en Supermicro

X8SIL-F.

solchannelsupport - Esta bandera de solución alternativa no comprobará si SOL está soportado en el canal actual. Soluciona sistemas remotos que no admiten correctamente este comando. Aquellos que se encuentren con este problema pueden ver errores de "BMC Error". Problema observado en Intel Windmill, Quanta Winterfell y Wiwynn

Windmill.

serialalertsdeferred - Esta opción de solución alternativa hará que las alertas seriales se difieran en lugar de que sean fallos. Esto soluciona placas base que realizan IPMI a través de serie junto con IPMI serie sobre LAN. Aquellos que se encuentren con este problema pueden ver "excess retransmissions sent" cuando intenten introducir datos a través de SOL. Problema observado en Intel Windmill, Quanta Winterfell y Wiwynn

Windmill.

solpacketseq - Esta opción de solución alternativa incrementará el número de secuencia de paquetes de la carga útil de SOL bajo circunstancias extremas. Normalmente, SOL nunca debería hacer esto, sin embargo, algunas placas base han demostrado "atascarse" debido a un error interno en

la placa base. Esta solución alternativa puede ayudar a desatascar el BMC. Aquellos que se encuentren con este problema pueden ver "excess retr
ansmissions sent" cuando intenten introducir datos a través de SOL. Problema observado en Intel Windmill, Quanta Winterfell y Wiwynn Windmill.

PROBLEMAS

CONOCIDOS

En sistemas operativos antiguos, si introduce su nombre de usuario, contraseña y otra información potencialmente relevante para la seguridad en la línea de comandos, esta información puede ser descubierta por otros usuarios al usar herramientas como la comando ps(1) o mirando en el sistema de archivos /proc. Generalmente es más seguro introducir información de contraseña con opciones como las opciones -P o -K. Configurar información relevante para la seguridad en el archivo de configuración de FreeIPMI también sería una forma apropiada de ocultar esta

información.

Para prevenir ataques de fuerza bruta, algunos BMC se "bloquearán" temporalmente después de un número de errores de autenticación remota. Puede que necesite esperar un tiempo para que este "bloqueo" temporal pase antes de que pueda autenticarse de

nuevo.

Algunas placas base definen un tiempo de inactividad SOL OEM para las sesiones SOL. Si las sesiones SOL permanecen inactivas durante largos períodos de tiempo, las sesiones de ipmiconsole pueden cerrarse abruptamente, lo que probablemente resulte en errores de tiempo de espera de sesión. Consul

te las notas OEM para obtener información sobre cómo modificar este
parámetro si desea que las sesiones permanezcan activas más tiempo.

NOTAS DE HARDWARE

ESPECÍFICAS

Intel SR1520ML/X38ML: Después de un reinicio, la sesión SOL parece "desconectarse" de la placa base pero permanece viva. Los datos de caracteres introducidos desde el cliente ipmiconsole es aceptado por la máquina remota, pero nunca se envían datos de caracteres ni datos de consola de vuelta desde la máquina remota. La

sesión SOL es posteriormente inútil. Actualmente no hay ninguna solución alter
nativa implementada para manejar esto. La sesión debe cerrarse y reiniciarse.
