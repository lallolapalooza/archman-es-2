DESCRIPCIÓ

N

Ipmi-dcmi se utiliza para ejecutar comandos de extensión IPMI de la Interfaz de Gestionabilidad de Centros de Datos (a menudo denominada DCM o DCMI). Las extensiones DCMI incluyen soporte para la gestión de activos y la gestión del uso de energía. La mayoría de los usuarios estarán interesados en DCMI por sus características de gestión de energía. Al configurar una acción de excepción, un límite de potencia y un límite de tiempo de corrección, el uso de energía en un centro de datos puede gestionarse de manera más efectiva. Consulte la opción --set-power-limit a continuación para obtener más información. DCMI también puede configurarse utilizando la categoría dcmi en ipmi-config(8). La especificación DCMI abarca muchas características IPMI tradicionales que no se implementan directamente en esta herramienta. Consulte ipmiconsole(8) para soporte de Serial-over-LAN (SOL), ipmi-chassis(8) para estado de energía, control de energía, identificación e información de estado de energía ACPI, ipmipower(8) para estado y control de energía, ipmi-sel(8) para información del Registro de Eventos del Sistema (SEL), bmc-info(8) para información de dispositivo e identificador único global (guid), ipmi-sensors(8) para lecturas de sensores, y ipmi-config(8) para

configuración.

A continuación se enumeran las opciones IPMI generales, las opciones específicas de la herramienta, información de resolución de problemas, información de soluciones alternativas, ejemplos y problemas conocidos. Para una introducción general a FreeIPMI, consulte free

ipmi
(7).

SOPORTE DE RANGO DE

HOSTS

Se pueden introducir múltiples hosts ya sea como listas explícitas de hosts separadas por comas o como un rango de nombres de host en la forma general: prefijo[n-m,l-k,...], donde n < m y l < k, etc. La última forma no debe confundirse con las clases de caracteres de expresiones regulares (también denotadas por []). Por ejemplo, foo[19] no representa foo1 o foo9, sino que representa un rango degenerado:

foo19.

Esta sintaxis de rango está destinada solo como una conveniencia en clústeres con una convención de nombres prefijoNN y la especificación de rangos no debe considerarse necesaria -- la lista foo1,foo9 podría especificarse como tal, o mediante el rango foo[1,9]

.

A continuación se muestran algunos ejemplos de uso de

rangos: 
    foo[01-05] en lugar de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] en lugar de foo7,foo9,foo10
    foo[0-3] en lugar de foo0,foo1,foo2,
foo3

Como recordatorio para el lector, algunos intérpretes de comandos interpretarán los corchetes ([ y ]) para la coincidencia de patrones. Dependiendo de su intérprete de comandos, puede ser necesario encerrar las listas de rangos entre

comillas.

Cuando el usuario especifica múltiples hosts, se ejecutará un subproceso para cada host en paralelo hasta la distribución configurada (que se puede ajustar mediante la opción -F). Esto permitirá la comunicación con un gran número de nodos mucho más rápidamente que si se hiciera de forma

serial.

De forma predeterminada, la salida estándar de cada nodo especificado se mostrará con el nombre de host antepuesto a cada línea. Aunque esta salida es legible en muchas situaciones, puede ser difícil de leer en otras situaciones. Por ejemplo, la salida de múltiples nodos puede mezclarse. Las opciones -B y -C se pueden utilizar para cambiar este valor

predeterminado.

Se utilizará la comunicación IPMI en banda cuando se

especifica el host "localhost". Esto permite al usuar
io añadir el localhost a la salida de rango de hosts.

SOLUCIÓN DE PROBLEMAS

GENERAL

La mayoría de las veces, los problemas de IPMI se deben a problemas de

configuración.

Los problemas de IPMI sobre LAN implican una configuración incorrecta del BMC de la máquina remota. Verifique dos veces para asegurarse de que lo siguiente esté configurado correctamente en el BMC de la máquina remota: dirección IP, dirección de dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio LAN, habilitación LAN y tipo(s) de autenticación permitidos. Para conexiones IPMI 2.0, verifique dos veces para asegurarse de que el/los privilegio(s) de la suite de cifrado y la clave K_g estén configurados correctamente. La herramienta ipmi-config(8) se puede utilizar para verificar y/o cambiar estos ajustes de

configuración.

Los problemas de IPMI en banda suelen ser causados por controladores mal configurados o BMC no

estándar.

Además de los consejos de solución de problemas que se enumeran a continuación, consulte SOLUCIONES más abajo para ver también si se han descubierto y solucionado errores específicos del

proveedor.

A continuación se enumeran muchos de los problemas comunes para los mensajes de error. Para obtener soporte adicional, envíe un correo electrónico aenvíe a la lista de correo <freeipmi-users@gnu.org>

.

"username invalid" (nombre de usuario no válido) - El nombre de usuario introducido (o un nombre de usuario NULL si no se introdujo ninguno) no está disponible en la máquina remota. También es posible que la configuración del nombre de usuario del BMC remoto sea

incorrecta.

"password invalid" (contraseña no válida) - La contraseña introducida (o una contraseña NULL si no se introdujo ninguna) no es correcta. También es posible que la contraseña del usuario no esté configurada correctamente en el BMC

remoto.

"password verification timeout" (tiempo de espera de verificación de contraseña agotado) - La verificación de la contraseña ha expirado. Ha ocurrido un error "password invalid" (descrito anteriormente) o un "session timeout" genérico (descrito más abajo). En este punto del protocolo no se puede diferenciar cuál de los dos

ocurrió.

"k_g invalid" (K_g no válido) - La clave K_g introducida (o una clave K_g NULL si no se introdujo ninguna) no es correcta. También es posible que la clave K_g no esté configurada correctamente en el BMC

remoto.

"privilege level insufficient" (nivel de privilegio insuficiente) - Un comando IPMI requiere un nivel de privilegio de usuario más alto que el con el que se ha autenticado. Por favor, intente autenticarse con un nivel de privilegio más alto. Esto puede requerir autenticarse con un usuario diferente que tenga un privilegio máximo más

alto.

"privilege level cannot be obtained for this user" (no se puede obtener el nivel de privilegio para este usuario) - El nivel de privilegio con el que intenta autenticarse es más alto que el máximo permitido para este usuario. Por favor, intente de nuevo con un privilegio más bajo. También es posible que el nivel de privilegio máximo permitido para un usuario no esté configurado correctamente en el BMC

remoto.

"authentication type unavailable for attempted privilege level" (tipo de autenticación no disponible para el nivel de privilegio intentado) - El tipo de autenticación con el que desea autenticarse no está disponible para este nivel de privilegio. Por favor, intente de nuevo con un tipo de autenticación alternativo o un nivel de privilegio alternativo. También es posible que los tipos de autenticación disponibles con los que puede autenticarse no estén configurados correctamente en el BMC

remoto.

"cipher suite id unavailable" (id de suite de cifrado no disponible) - El id de suite de cifrado con el que desea autenticarse no está disponible en el BMC remoto. Por favor, intente de nuevo con un id de suite de cifrado alternativo. También es posible que los ids de suite de cifrado disponibles no estén configurados correctamente en el BMC

remoto.

"ipmi 2.0 unavailable" (IPMI 2.0 no disponible) - No se ha descubierto IPMI 2.0 en la máquina remota. Por favor, intente usar IPMI 1.5 en su

lugar.

"connection timeout" (tiempo de espera de conexión agotado) - La comunicación IPMI inicial ha fallado. Es posible que haya ocurrido varios errores potenciales, incluyendo un nombre de host no válido especificado, una dirección IP de IPMI que no se puede resolver, IPMI no está habilitado en el servidor remoto, la conexión de red es deficiente, etc. Por favor, verifique la configuración y la

conectividad.

"session timeout" (tiempo de espera de sesión agotado) - La sesión IPMI ha expirado. Por favor, reconéctese. Si este error ocurre con frecuencia, es posible que desee aumentar el tiempo de espera de retransmisión. Algunos BMCs remotos son considerablemente más lentos que

otros.

"device not found" (dispositivo no encontrado) - El dispositivo especificado no se pudo encontrar. Por favor, verifique la configuración o las entradas e intente de

nuevo.

"driver timeout" (tiempo de espera del controlador agotado) - La comunicación con el controlador o el dispositivo ha expirado. Por favor, intente de

nuevo.

"message timeout" (tiempo de espera del mensaje agotado) - La comunicación con el controlador o el dispositivo ha expirado. Por favor, intente de

nuevo.

"BMC busy" (BMC ocupado) - El BMC está actualmente ocupado. Puede que esté procesando información o tenga demasiadas sesiones simultáneas que gestionar. Por favor, espere e intente de

nuevo.

"could not find inband device" (no se pudo encontrar el dispositivo inband) - No se pudo encontrar un dispositivo inband. Por favor, verifique la configuración o especifique un dispositivo o controlador específico en la línea de

comandos.

"driver timeout" (tiempo de espera del controlador agotado) - El controlador inband ha expirado en la comunicación con el BMC o el procesador de servicio local. El BMC o el procesador de servicio puede estar ocupado o (en el peor de los casos) posiblemente no

funcionando.

"internal IPMI error" (error IPMI interno) - Ha ocurrido un error

IPMI que FreeIPMI no sabe cómo manejar. Por favor, envíe un correo
electrónico a <freeipmi-users@gnu.org> para informar del problema.

SOLUCIONES

ALTERNATIVAS

Con tantos proveedores diferentes implementando sus propias soluciones IPMI, es posible que diferentes proveedores implementen sus protocolos IPMI incorrectamente. Lo siguiente describe una serie de soluciones alternativas actualmente disponibles para manejar problemas de cumplimiento descubiertos. Cuando es posible, las soluciones alternativas se han implementado para que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se use una solución alternativa mediante la opción

-W.

El hardware listado a continuación puede indicar únicamente el hardware en el que se descubrió un problema. Las versiones más recientes del hardware pueden corregir los problemas indicados a continuación. Máquinas similares de otros proveedores pueden o no exhibir los mismos problemas. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede valer la pena probar las soluciones alternativas listadas a continuación aunque su placa base no esté

listada.

Si cree que su hardware tiene un problema de cumplimiento adicional que necesita que se implemente una solución alternativa, por favor, contacte con los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.org>

.

assumeio - Esta bandera de solución alternativa asumirá que las interfaces inband se comunican con las E/S del sistema en lugar de estar mapeadas en memoria. Esto solucionará el problema de los sistemas que reportan direcciones base no válidas. Aquellos que se encuentren con este problema pueden ver errores "device not supported" o "could not find inband device". Problema observado en HP ProLiant DL145

G1.

spinpoll - Esta bandera de solución alternativa informará a algunos controladores inband (el controlador KCS, notablemente) que hagan un bucle activo (spin) mientras hacen sondeos en lugar de poner el proceso a dormir. Esto puede mejorar significativamente el tiempo de ejecución real de las herramientas porque la granularidad del planificador de un sistema operativo puede ser mucho mayor que el tiempo que lleva realizar una única transacción de mensaje IPMI. Sin embargo, al hacer un bucle activo, su sistema puede estar realizando un trabajo menos útil al no cambiar el contexto de la herramienta para una tarea más

útil.

authcap - Esta bandera de solución alternativa omitirá las comprobaciones iniciales de capacidades de nombre de usuario, capacidades de autenticación y soporte de K_g, y permitirá que la autenticación IPMI tenga éxito. Soluciona múltiples problemas en los que el sistema remoto no reporta correctamente las capacidades de nombre de usuario, las capacidades de autenticación o el estado de K_g. Aquellos que se encuentren con este problema pueden ver errores "username invalid", "authentication type unavailable for attempted privilege level" o "k_g invalid". Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML, y Sun Fire 2200/4150/4450 con

ELOM.

nochecksumcheck - Esta bandera de solución alternativa le dirá a FreeIPMI que no verifique las sumas de comprobación (checksums) devueltas por las respuestas de los comandos IPMI. Soluciona sistemas que devuelven sumas de comprobación no válidas debido a errores de implementación, pero el paquete es válido por lo demás. Se recomienda precaución a los usuarios en el uso de esta opción, ya que elimina la validación de la integridad del paquete en una serie de circunstancias. Sin embargo, es poco probable que sea un problema en la mayoría de las situaciones. Aquellos que se encuentren con este problema pueden ver errores "connection timeout", "session timeout" o "password verification timeout". En conexiones IPMI 1.5, también puede ser necesaria la solución alternativa "noauthcodecheck". Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F, y Supermicro

X9DRFR.

idzero - Esta bandera de solución alternativa permitirá que el cliente acepte IDs de sesión vacíos. Soluciona sesiones IPMI que reportan IDs de sesión vacíos al cliente. Aquellos que se encuentren con este problema pueden ver errores "session timeout". Problema observado en Tyan S2882 con BMC

M3289.

unexpectedauth - Esta bandera de solución alternativa permitirá que se verifiquen códigos de autenticación (authcodes) no nulos inesperados como si se esperaran. Soluciona un problema cuando los paquetes contienen datos de autenticación no nulos cuando deberían ser nulos debido a la autenticación por mensaje deshabilitada. Aquellos que se encuentren con este problema pueden ver errores "session timeout". Problema observado en Dell PowerEdge 2850, SC1425. Confirmado como corregido en firmware más

nuevo.

forcepermsg - Esta bandera de solución alternativa forzará el uso de la autenticación por mensaje sin importar lo que anuncie el sistema remoto. Soluciona un problema cuando la autenticación por mensaje se anuncia como deshabilitada en el sistema remoto, pero en realidad es requerida por el protocolo. Aquellos que se encuentren con este problema pueden ver errores "session timeout". Problema observado en IBM eServer

325.

endianseq - Esta bandera de solución alternativa cambiará el orden de bytes (endian) de los números de secuencia de sesión para permitir que la sesión continúe correctamente. Soluciona números de secuencia de sesión IPMI 1.5 que tienen el orden de bytes incorrecto. Aquellos que se encuentren con este problema pueden ver errores "session timeout". Problema observado en algunos Sun ILOM 1.0/2.0 (depende del orden de bytes del procesador de servicio)

.

noauthcodecheck - Esta bandera de solución alternativa le dirá a FreeIPMI que no verifique los códigos de autenticación devueltos por las respuestas de los comandos IPMI 1.5. Soluciona sistemas que devuelven códigos de autenticación no válidos debido a errores de hash o de implementación. Se recomienda precaución a los usuarios en el uso de esta opción, ya que elimina una verificación de autenticación que valida la integridad de un paquete. Sin embargo, en la mayoría de las organizaciones, es poco probable que sea un problema de seguridad. Aquellos que se encuentren con este problema pueden ver errores "connection timeout", "session timeout" o "password verification timeout". Problema observado en Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell, y Wiwynn

Windmill.

intel20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación IPMI 2.0 de Intel. Los problemas cubiertos incluyen el relleno (padding) de nombres de usuario y el truncamiento de la contraseña si el algoritmo de autenticación es HMAC-MD5-128. Aquellos que se encuentren con este problema pueden ver errores "username invalid", "password invalid" o "k_g invalid". Problema observado en Intel SE7520AF2 con Intel Server Management Module (Professional Edition)

.

supermicro20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación IPMI 2.0 de Supermicro en placas base con firmware IPMI de Peppercon. Los problemas cubiertos incluyen el manejo de códigos de autenticación de longitud no válida. Aquellos que se encuentren con este problema pueden ver errores "password invalid". Problema observado en Supermicro H8QME con tarjeta hija SIMSO. Confirmado como corregido en firmware más

nuevo.

sun20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación IPMI 2.0 de Sun. Los problemas cubiertos incluyen claves hash de longitud no válida, claves con hash incorrecto y registros de suite de cifrado no válidos. Aquellos que se encuentren con este problema pueden ver errores "password invalid" o "bmc error". Problema observado en Sun Fire 4100/4200/4500 con ILOM. Esta solución alternativa incluye automáticamente la solución alternativa

"opensesspriv".

opensesspriv - Esta bandera de solución alternativa alterará ligeramente el protocolo de conexión IPMI 2.0 de FreeIPMI para solucionar un algoritmo de hash no válido utilizado por el sistema remoto. El nivel de privilegio enviado durante la etapa de Apertura de Sesión (Open Session) de una conexión IPMI 2.0 se utiliza para el hash de lasys en lugar del nivel de privilegio enviado durante la etapa de conexión RAKP1. Aquellos que se encuentren con este problema pueden ver errores "password invalid", "k_g invalid", "bad rmcpplus status code" o "privilege level cannot be obtained for this user". Problema observado en Sun Fire 4100/4200/4500 con ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220, y el software BMC OpenIPMI. Esta solución alternativa se activa automáticamente con la solución alternativa

"sun20".

integritycheckvalue - Esta bandera de solución alternativa funcionará para un valor de verificación de integridad no válido durante el establecimiento de una sesión IPMI 2.0 cuando se utiliza el Cipher Suite ID 0. El valor de verificación de integridad debería tener una longitud de 0, sin embargo, la placa base remota responde con un campo no vacío. Aquellos que se encuentren con este problema pueden ver errores "k_g invalid". Problema observado en Supermicro X8DTG, Supermicro X8DTU, y Intel S5500WBV/Penguin Relion 700, y Intel S2600JF/Appro

512X.

Sin soporte para IPMI 1.5 - Se ha descubierto que algunas placas base que soportan IPMI 2.0 no soportan IPMI 1.5. Aquellos que se encuentren con este problema pueden ver errores "ipmi 2.0 unavailable" o "connection timeout". Este problema se puede solucionar utilizando IPMI 2.0 en lugar de IPMI 1.5 especificando --driver-type=LAN_2_0. Problema observado en un núme

ro de placas ba
se HP y Supermicro.

PROBLEMAS

CONOCIDOS

En sistemas operativos antiguos, si ingresa su nombre de usuario, contraseña y otra información potencialmente relevante para la seguridad en la línea de comandos, esta información puede ser descubierta por otros usuarios al usar herramientas como el comando ps(1) o al mirar en el sistema de archivos /proc. Generalmente es más seguro ingresar información de contraseña con opciones como las opciones -P o -K. Configurar información relevante para la seguridad en el archivo de configuración de FreeIPMI también sería una forma apropiada de ocultar esta

información.

Para prevenir ataques de fuerza bruta, algunos BMC se "bloquearán" temporalmente desp

ués de un número de errores de autenticación remota. Puede que necesite esperar un t
iempo para que este "bloqueo" temporal pase antes de que pueda autenticarse de nuevo.
