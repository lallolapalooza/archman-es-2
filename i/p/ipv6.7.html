DESCRIPCIÓ

N

Linux 2.2 implementa opcionalmente el Protocolo de Internet, versión 6. Esta página man contiene una descripción de la API básica de IPv6 tal como es implementada por el kernel de Linux y glibc 2.1. La interfaz está basada en la interfaz de sockets BSD; ver socket(

7).

La API de IPv6 pretende ser mayormente compatible con la API de IPv4 (ver ip(7)). En esta página man solo se describen las

diferencias.

Para enlazar un socket AF_INET6 a cualquier proceso, la dirección local debería ser copiada desde la variable in6addr_any que tiene el tipo in6_addr. En inicializaciones estáticas, IN6ADDR_ANY_INIT también puede ser usada, la cual se expande a una expresión constante. Ambas están en orden de bytes de

red.

La dirección de loopback de IPv6 (::1) está disponible en la variable global in6addr_loopback. Para inicializaciones, IN6ADDR_LOOPBACK_INIT debería ser

usada.

Las conexiones IPv4 pueden ser manejadas con la API v6 usando el tipo de dirección v4-mapped-on-v6; así que un programa solo necesita soportar este tipo de API para soportar ambos protocolos. Esto es manejado transparentemente por las funciones de manejo de direcciones en la biblioteca

C.

IPv4 e IPv6 comparten el espacio de puertos local. Cuando usted recibe una conexión IPv4 o un paquete a un socket IPv6, su dirección de origen será mapeada a

v6.

Formato de

dirección 
struct sockaddr_in6 {
    sa_family_t     sin6_family;   /* AF_INET6 */
    in_port_t       sin6_port;     /* número de puerto */
    uint32_t        sin6_flowinfo; /* información de flujo IPv6 */
    struct in6_addr sin6_addr;     /* dirección IPv6 */
    uint32_t        sin6_scope_id; /* ID de ámbito (nuevo en Linux 2.4) */
};
struct in6_addr {
    unsigned char   s6_addr[16];   /* dirección IPv6 */
}
;

sin6_family siempre se establece a AF_INET6; sin6_port es el puerto del protocolo (ver sin_port en ip(7)); sin6_flowinfo es el identificador de flujo de IPv6; sin6_addr es la dirección IPv6 de 128 bits. sin6_scope_id es un ID que depende del ámbito de la dirección. Es nuevo en Linux 2.4. Linux lo soporta solo para direcciones link-local, en cuyo caso sin6_scope_id contiene el índice de interfaz (ver netdevice

(7))

IPv6 soporta varios tipos de dirección: unicast para direccionar un solo host, multicast para direccionar un grupo de hosts, anycast para direccionar al miembro más cercano de un grupo de hosts (no implementado en Linux), IPv4-on-IPv6 para direccionar un host IPv4, y otros tipos de dirección

reservados.

La notación de dirección para IPv6 es un grupo de 8 números hexadecimales de 4 dígitos, separados con un ':'. "::" representa una cadena de bits 0. Las direcciones especiales son ::1 para loopback y ::FFFF:<dirección IPv4> para IPv4-mapped-on-IPv6

.

verdadero.

VERSIONE

S

Linux 2.4 romperá la compatibilidad binaria para sockaddr_in6 en hosts de 64 bits al cambiar la alineación de in6_addr y añadir un campo adicional sin6_scope_id. Las interfaces del núcleo permanecen compatibles, pero un programa que incluya sockaddr_in6 o in6_addr en otras estructuras puede no serlo. Esto no es un problema para hosts de 32 bits como

i386.

El campo sin6_flowinfo es nuevo en Linux 2.4. El núcleo lo pasa/lee de forma transparente cuando la longitud de la dirección pasada lo co

ntiene. Algunos programas que pasan un búfer de dirección más largo y lu
ego comprueban la longitud de la dirección de salida pueden fallar.

NOTA

S

La estructura sockaddr_in6 es más grande que la genérica sockaddr. Los programas que asumen que todos los tipos de dirección pueden almacenarse de forma segura en un struct sockaddr deben modificarse para usar struct sockaddr_storage en su

lugar.

SOL_IP, SOL_IPV6, SOL_ICMPV6 y otras opciones de socket SOL_* son variantes no portables de IPPROTO_*. Ver también ip(

7
).
