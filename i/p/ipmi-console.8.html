DESCRIPCIÓ

N

ipmiconsole es una utilidad de consola Serial-over-LAN (SOL). Puede usarse para establecer sesiones de consola con máquinas remotas usando el protocolo IPMI 2.0 SOL. Ipmiconsole se comunica con el Controlador de Gestión de la Placa Base (BMC) de una máquina remota para establecer una sesión de consola. Antes de que pueda tener lugar cualquier comunicación SOL, el BMC de la máquina remota debe configurarse correctamente. La herramienta FreeIPMI ipmi-config(8) puede usarse para realizar esta

configuración.

A menudo (aunque no siempre), la redirección de la consola también debe configurarse correctamente en la BIOS y/o el sistema operativo. Ambos deben configurarse para redirigir el tráfico de la consola a través del puerto COM apropiado. Consulte la documentación de su placa base y SO para obtener instrucciones sobre la configuración

adecuada.

A continuación se enumeran las opciones generales de IPMI, las opciones específicas de la herramienta, información de solución de problemas, información de soluciones alternativas, ejemplos y problemas conocidos. Para una introducción general a FreeIPMI, consulte free

ipmi
(7).

IPMICONSOLE

Las siguientes opciones son específicas de ipmiconsole

-e CHAR, --escape-char=CH

Especifica un carácter de escape alternativo (carácter predeterminado

--dont-ste
al
No robar una sesión SOL si ya se detecta que una está en uso. Bajo la mayoría de las circunstancias, si se detecta que SOL está en uso, ipmiconsole intentará robar la sesión SOL de la sesión anterior. Este comportamiento predeterminado existe por varias razones, la más notable es que las sesiones SOL anteriores pueden no haberse podido desactivar
correctamente.
--deactiva
te
Desactiva la sesión SOL si se detecta que una está en uso y
sale.
--serial-keepal
ive
Envía ocasionalmente caracteres NUL para detectar conexiones seriales inactivas. Esta opción es particularmente útil para aquellos que pretenden ejecutar ipmiconsole sin mucha interacción, como para fines de registro. Aunque las conexiones IPMI pueden seguir vivas, algunas placas base han mostrado errores en los que los datos seriales subyacentes ya no pueden enviarse/recibirse. Desde el punto de vista de ipmiconsole, los datos simplemente no se envían fuera del sistema remoto y este problema solo se detecta una vez que hay interacción del usuario. Al enviar lossional NUL character, the underlying loss of serial data transfer can be detected far more quickly. There is some risk with this option, as the NUL character byte may affect the remote system depending on what data it may or may not be expecting. For example, a NUL character received by getty(8) and its descendants (such as agetty(8)) will cause a baud rate change, which may lock up the
terminal.
--serial-keepalive-em
pty
This option is identical to --serial-keepalive except that SOL packets will contain no NUL character data. On some motherboards, this may be sufficient to deal with a hanging IPMI session without the risk of regularly sending a NUL character byte may have. However, some systems may not ACK a SOL packet without character data in it, meaning these keepalive packets do
nothing.

Specify the SOL payload instance number. The default value is 1, valid values range from 1 to 15. Most systems only support a single instance, however a few allow users to access

SOLUCIÓN DE PROBLEMAS

GENERAL

La mayoría de las veces, los problemas de IPMI se deben a problemas de

configuración.

Los problemas de IPMI sobre LAN implican una configuración incorrecta del BMC de la máquina remota. Verifique dos veces para asegurarse de que lo siguiente esté configurado correctamente en el BMC de la máquina remota: dirección IP, dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio LAN, habilitación LAN y tipo(s) de autenticación permitido(s). Para conexiones IPMI 2.0, verifique dos veces para asegurarse de que el(los) privilegio(s) de la suite de cifrado y la clave K_g estén configurados correctamente. La herramienta ipmi-config(8) puede usarse para verificar y/o cambiar estos ajustes de

configuración.

Además de los consejos de solución de problemas a continuación, consulte SOLUCIONES ALTERNATIVAS a continuación para ver también si hay errores específicos del proveedor que hayan sido descubiertos y para los que existan soluciones

alternativas.

A continuación se enumeran muchos de los problemas comunes para los mensajes de error. Para soporte adicional, por favor envíe un correo electrónico a la lista de correo <freeipmi-users@gnu.org>

.

"username invalid" - El nombre de usuario introducido (o un nombre de usuario NULL si no se introdujo ninguno) no está disponible en la máquina remota. También es posible que la configuración del nombre de usuario del BMC remoto sea

incorrecta.

"password invalid" - La contraseña introducida (o una contraseña NULL si no se introdujo ninguna) no es correcta. También es posible que la contraseña del usuario no esté configurada correctamente en el BMC

remoto.

"password verification timeout" - La verificación de la contraseña ha expirado. Se produjo un error "password invalid" (descrito arriba) o un "session timeout" genérico (descrito abajo). Durante este punto del protocolo no se puede diferenciar cuál

ocurrió.

"k_g invalid" - La clave K_g introducida (o una clave K_g NULL si no se introdujo ninguna) no es correcta. También es posible que la clave K_g no esté configurada correctamente en el BMC

remoto.

"privilege level insufficient" - Un comando IPMI requiere un privilegio de usuario más alto que el con el que se autenticó. Por favor, intente autenticarse con un privilegio más alto. Esto puede requerir autenticarse con un usuario diferente que tenga un privilegio máximo más

alto.

"privilege level cannot be obtained for this user" - El nivel de privilegio con el que intenta autenticarse es más alto que el máximo permitido para este usuario. Por favor, intente de nuevo con un privilegio más bajo. También es posible que el nivel de privilegio máximo permitido para un usuario no esté configurado correctamente en el BMC

remoto.

"authentication type unavailable for attempted privilege level" - El tipo de autenticación con el que desea autenticarse no está disponible para este nivel de privilegio. Por favor, intente de nuevo con un tipo de autenticación alternativo o un nivel de privilegio alternativo. También es posible que los tipos de autenticación disponibles con los que puede autenticarse no estén configurados correctamente en el BMC

remoto.

"cipher suite id unavailable" - El id de la suite de cifrado con el que desea autenticarse no está disponible en el BMC remoto. Por favor, intente de nuevo con un id de suite de cifrado alternativo. También es posible que los ids de suite de cifrado disponibles no estén configurados correctamente en el BMC

remoto.

"ipmi 2.0 unavailable" - No se descubrió IPMI 2.0 en la máquina remota. Por favor, intente usar IPMI 1.5 en su

lugar.

"connection timeout" - La comunicación IPMI inicial falló. Son posibles varios errores potenciales, incluyendo un nombre de host inválido especificado, una dirección IP de IPMI que no puede resolverse, IPMI no está habilitado en el servidor remoto, la conexión de red es deficiente, etc. Por favor, verifique la configuración y la

conectividad.

"session timeout" - La sesión IPMI ha expirado. Por favor, reconéctese. Si este error ocurre con frecuencia, es posible que desee aumentar el tiempo de espera de retransmisión. Algunos BMCs remotos son considerablemente más lentos que

otros.

"internal IPMI error" - Se ha producido un error IPMI que F

reeIPMI no sabe cómo manejar. Por favor, envíe un correo electró
nico a <freeipmi-users@gnu.org> para informar del problema.

SOLUCIÓN DE PROBLEMAS DE

IPMICONSOLE

Los siguientes son problemas comunes para los mensajes de error en ipmiconsole

.

"SOL unavailable" - SOL no está configurado para su uso en el BMC remoto. Puede que no esté configurado en general o para el usuario específico especificado. Autenticarse con un usuario diferente puede ser suficiente, sin embargo el protocolo IPMI no revela detalles sobre lo que no está configurado en el BMC

remoto.

"SOL in use" - SOL ya está en uso en el BMC remoto. Si no especifica la opción --dont-steal, ipmiconsole intentará robar la sesión SOL de la otra sesión. No todos los BMCs admiten la capacidad de robar una sesión

SOL.

"SOL session stolen" - Su sesión SOL ha sido robada por otra sesión. Es posible que desee intentar robar la sesión de vuelta

reconectándose.

"SOL requires encryption" - SOL requiere un id de suite de cifrado que incluya cifrado. Por favor, intente usar el id de suite de cifrado 3, 8 o 12. También es posible que los requisitos de cifrado no estén configurados correctamente en el BMC

remoto.

"SOL requires no encryption" - SOL requiere un id de suite de cifrado que no use cifrado. Por favor, intente usar el id de suite de cifrado 0, 1, 2, 6, 7 o 11. También es posible que los requisitos de cifrado no estén configurados correctamente en el BMC

remoto.

"BMC Implementation" - El BMC en la máquina remota tiene un problema grave en su implementación. Por favor, consulte la sección SOLUCIONES ALTERNATIVAS a continuación para posibles soluciones alternativas. Si se requieren soluciones alternativas adicionales del proveedor, por favor, contacte con los

autores.

"excess retransmissions sent" - Se ha producido un número excesivo de retransmisiones de paquetes SOL y ipmiconsole ha renunciado. Esto puede deberse a problemas de red o problemas con SOL. Algunos de los mismos problemas involucrados con los errores "connection timeout" o "session timeout" pueden estar involucrados. Por favor, intente

reconectarse.

"excess errors received" - Se ha producido un número excesivo de errores de paquetes SOL y ipmiconsole ha renunciado. Esto puede deberse a problemas de red o problemas con SOL. Por favor, intente

reconectarse.

"BMC Error" - Este error usualmente significa que una implementación SOL de un proveedor requiere una combinación de autenticación, cifrado, privi

legio, etc. que no han sido cumplidos por las elecciones del usuario. Por favor, intente una combinación de diferentes suites de cifrado, privilegios
, etc. para resolver el problema. Por favor, consulte también la sección SOLUCIONES ALTERNATIVAS a continuación para posibles soluciones alternativas.

SOLUCIONES

ALTERNATIVAS

Con tantos proveedores diferentes implementando sus propias soluciones de IPMI, diferentes proveedores pueden implementar sus protocolos IPMI incorrectamente. Lo siguiente describe un número de soluciones alternativas actualmente disponibles para manejar problemas de cumplimiento descubiertos. Cuando sea posible, las soluciones alternativas han sido implementadas para que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se use una solución alternativa mediante la opción

-W.

El hardware enumerado a continuación puede solo indicar el hardware en el que se descubrió un problema. Versiones más nuevas del hardware pueden corregir los problemas indicados a continuación. Máquinas similares de los proveedores pueden o no exhibir los mismos problemas. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede valer la pena probar las soluciones alternativas listadas a continuación incluso si su placa base no está

listada.

Si cree que su hardware tiene un problema de cumplimiento adicional que necesita que se implemente una solución alternativa, por favor, contacte con los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.org>

.

authcap - Este indicador de solución alternativa omitirá las comprobaciones tempranas de capacidades de nombre de usuario, capacidades de autenticación y soporte de K_g y permitirá que la autenticación IPMI tenga éxito. Soluciona múltiples problemas en los que el sistema remoto no informa correctamente las capacidades del nombre de usuario, las capacidades de autenticación o el estado de K_g. Aquellos que encuentren este problema pueden ver errores "username invalid", "authentication type unavailable for attempted privilege level" o "k_g invalid". Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML y Sun Fire 2200/4150/4450 con

ELOM.

nochecksumcheck - Este indicador de solución alternativa le dirá a FreeIPMI que no verifique las sumas de verificación devueltas por las respuestas de los comandos IPMI. Soluciona sistemas que rdevuelven sumas de verificación inválidas debido a errores de implementación, pero el paquete es de otro modo válido. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina la validación de la integridad de los paquetes en una serie de circunstancias. Sin embargo, es poco probable que sea un problema en la mayoría de las situaciones. Aquellos que se encuentren con este problema pueden ver errores de "connection timeout" (tiempo de espera de conexión), "session timeout" (tiempo de espera de sesión) o "password verification timeout" (tiempo de espera de verificación de contraseña). En las conexiones IPMI 1.5, también puede ser necesaria la solución alternativa "noauthcodecheck". Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F y Supermicro

X9DRFR.

intel20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación de Intel IPMI 2.0. Los problemas cubiertos incluyen el relleno de nombres de usuario y la truncación de contraseñas si el algoritmo de autenticación es HMAC-MD5-128. Aquellos que se encuentren con este problema pueden ver errores de "username invalid" (nombre de usuario no válido), "password invalid" (contraseña no válida) o "k_g invalid" (k_g no válido). Problema observado en Intel SE7520AF2 con Intel Server Management Module (Professional Edition)

.

supermicro20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación de Supermicro IPMI 2.0 en placas base con firmware IPMI de Peppercon. Los problemas cubiertos incluyen el manejo de códigos de autenticación de longitud no válida. Aquellos que se encuentren con este problema pueden ver errores de "password invalid" (contraseña no válida). Problema observado en Supermicro H8QME con tarjeta hija SIMSO. Confirmado como corregido en firmware más

reciente.

sun20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación de Sun IPMI 2.0. Los problemas cubiertos incluyen claves hash de longitud no válida, claves con hash incorrecto y registros de suite de cifrado no válidos. Aquellos que se encuentren con este problema pueden ver errores de "password invalid" (contraseña no válida) o "bmc error" (error de BMC). Problema observado en Sun Fire 4100/4200/4500 con ILOM. Esta solución alternativa incluye automáticamente la solución alternativa

"opensesspriv".

opensesspriv - Esta bandera de solución alternativa alterará ligeramente el protocolo de conexión IPMI 2.0 de FreeIPMI para solucionar un algoritmo de hash no válido utilizado por el sistema remoto. El nivel de privilegio enviado durante la etapa de Apertura de Sesión de una conexión IPMI 2.0 se utiliza para las claves de hash en lugar del nivel de privilegio enviado durante la etapa de conexión RAKP1. Aquellos que se encuentren con este problema pueden ver errores de "password invalid" (contraseña no válida), "k_g invalid" (k_g no válido), "bad rmcpplus status code" (código de estado rmcpplus incorrecto) o "privilege level cannot be obtained for this user" (no se puede obtener el nivel de privilegio para este usuario). Problema observado en Sun Fire 4100/4200/4500 con ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220 y el software BMC OpenIPMI. Esta solución alternativa se activa automáticamente con la solución alternativa

"sun20".

integritycheckvalue - Esta bandera de solución alternativa solucionará un valor de comprobación de integridad no válido durante el establecimiento de una sesión IPMI 2.0 al usar el ID de Suite de Cifrado 0. El valor de comprobación de integridad debería tener una longitud de 0, sin embargo, la placa base remota responde con un campo no vacío. Aquellos que se encuentren con este problema pueden ver errores de "k_g invalid" (k_g no válido). Problema observado en Supermicro X8DTG, Supermicro X8DTU, Intel S5500WBV/Penguin Relion 700 e Intel S2600JF/Appro

512X.

solpayloadsize - Esta bandera de solución alternativa no comprobará los tamaños de carga útil de SOL válidos y asumirá un conjunto adecuado. Soluciona sistemas remotos que informan tamaños de carga útil de SOL IPMI 2.0 no válidos. Aquellos que se encuentren con este problema pueden ver errores de "BMC Implementation" (implementación de BMC). Problema observado en Asus P5M2/RS162-E4/RX4, Intel SR1520ML/X38ML, Inventec 5441/Dell Xanadu II, Sun x4100, Supermicro X8DTH, Supermicro X8DTG, Supermicro X8DTU y Quanta QSSC-S4R//Appro

GB812X-CN.

solport - Esta bandera de solución alternativa ignorará los puertos SOL alternativos especificados durante el protocolo. Soluciona sistemas remotos que informan puertos SOL alternativos no válidos. Aquellos que se encuentren con este problema pueden ver errores de "connection timeout" (tiempo de espera de conexión). Problema observado en Asus P5MT-R y Supermicro

X8DTH-iF.

solstatus - Esta bandera de solución alternativa no comprobará el estado de activación actual de SOL durante la configuración del protocolo. Soluciona sistemas remotos que no admiten correctamente este comando. Aquellos que se encuentren con este problema pueden ver errores de "BMC Error" (error de BMC). Problema observado en Supermicro

X8SIL-F.

solchannelsupport - Esta bandera de solución alternativa no comprobará si SOL es compatible en el canal actual. Soluciona sistemas remotos que no admiten correctamente este comando. Aquellos que se encuentren con este problema pueden ver errores de "BMC Error" (error de BMC). Problema observado en Intel Windmill, Quanta Winterfell y Wiwynn

Windmill.

serialalertsdeferred - Esta opción de solución alternativa hará que las alertas seriadas se difieran en lugar de que sean fallos. Esto soluciona placas base que realizan IPMI a través de serie junto con IPMI serie sobre LAN. Aquellos que se encuentren con este problema pueden ver "excess retransmissions sent" (exceso de retransmisiones enviadas) cuando intentan introducir datos a través de SOL. Problema observado en Intel Windmill, Quanta Winterfell y Wiwynn

Windmill.

solpacketseq - Esta opción de solución alternativa incrementará el número de secuencia del paquete de carga útil de SOL en circunstancias extremas. Normalmente, SOL nunca debería hacer esto, sin embargo, algunas placas base han demostrado "atascarse" debido a un error interno en la placa base. Esta s

olución alternativa puede ayudar a desatascar el BMC. Aquellos que se encuentren con este problema pueden ver "excess retransmissions sent" (exceso de
retransmisiones enviadas) cuando intentan introducir datos a través de SOL. Problema observado en Intel Windmill, Quanta Winterfell y Wiwynn Windmill.

PROBLEMAS

CONOCIDOS

En sistemas operativos antiguos, si introduce su nombre de usuario, contraseña y otra información potencialmente relevante para la seguridad en la línea de comandos, esta información puede ser descubierta por otros usuarios al usar herramientas como la comando ps(1) o mirando en el sistema de archivos /proc. Generalmente es más seguro introducir información de contraseña con opciones como las opciones -P o -K. Configurar información relevante para la seguridad en el archivo de configuración de FreeIPMI también sería una forma apropiada de ocultar esta

información.

Para prevenir ataques de fuerza bruta, algunos BMC se "bloquearán" temporalmente después de un número de errores de autenticación remota. Puede que necesite esperar un tiempo para que este "bloqueo" temporal pase antes de que pueda autenticarse de

nuevo.

Algunas placas base definen un tiempo de espera de inactividad SOL OEM para las sesiones SOL. Si las sesiones SOL permanecen inactivas durante largos períodos de tiempo, las sesiones de ipmiconsole pueden cerrarse abruptamente, lo que probablemente resulte en errores de tiempo de espera de sesión. Consulte l

as notas OEM para obtener información sobre cómo modificar este parám
etro si desea que las sesiones permanezcan activas durante más tiempo.

ESPECÍFICAS

Intel SR1520ML/X38ML: Después de un reinicio, la sesión SOL parece "desconectarse" de la placa base pero permanece activa. n SOL es posteriormente inútil. Actualmente no hay ninguna solución alterna
tiva implementada para manejar esto. La sesión debe cerrarse y reiniciarse.
