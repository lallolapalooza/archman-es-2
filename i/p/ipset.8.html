INTRODUCCIÓ

N

Un tipo de conjunto comprende el método de almacenamiento mediante el cual se almacenan los datos y el tipo(s) de dato(s) que se almacenan en el conjunto. Por lo tanto, el parámetro TYPENAME del comando create sigue la

sintaxis

TYPENAME := método:tipodedato[,tipodedato[,tipodeda

to]]

donde la lista actual de los métodos son bitmap, hash y list, y los tipos de datos posibles son ip, net, mac, port y iface. La dimensión de un conjunto es igual al número de tipos de datos en su nombre de

tipo.

Al añadir, eliminar o probar entradas en un conjunto, debe usarse la misma sintaxis de datos separada por comas para el parámetro de entrada de los comandos, es

decir
ipset add fo
o ipaddr,po
rtnum,ipaddr

Si se usan nombres de host o nombres de servicio con guiones en el nombre en lugar de direcciones IP o números de servicio, entonces el nombre de host o el nombre de servicio debe ir encerrado entre corchetes.

Ejemplo:
ipset add foo
[test-hostnam
e],[ftp-data]

En el caso de los nombres de host, el resolutor DNS es llamado internamente por ipset, pero si devuelve múltiples direcciones IP, solo se usa la

primera.

Los tipos bitmap y list usan un almacenamiento de tamaño fijo. Los tipos hash usan un hash para almacenar los elementos. Para evitar colisiones en el hash, un número limitado de encadenamiento, y si esto se agota, se realiza la duplicación del tamaño del hash al añadir entradas mediante el comando ipset. Cuando se añaden entradas mediante el objetivo SET de iptables/ip6tables, el tamaño del hash es fijo y el conjunto no será d

uplicado, incluso si la nueva entrad
a no puede ser añadida al conjunto.

OPCIONES GENÉRICAS DE CREACIÓN Y

ADICIÓN

timeou

t

Todos los tipos de conjunto soportan el parámetro opcional timeout al crear un conjunto y añadir entradas. El valor del parámetro timeout para el comando create significa el valor de tiempo de espera (timeout) por defecto (en segundos) para nuevas entradas. Si un conjunto se crea con soporte para timeout, entonces la misma opción timeout puede ser usada para especificar valores de timeout no por defecto al añadir entradas. Un valor de timeout de cero significa que la entrada se añade permanentemente al conjunto. El valor de timeout de elementos ya añadidos puede ser cambiado re-añadiendo el elemento usando la opción -exist. El valor de timeout más grande posible es 2147483 (en segundos).

Ejemplo:
ipset create test hash:ip timeout
300
ipset add test 192.168.0.1 timeout
60
ipset -exist ad
d test 192.168.
0.1 timeout 600

Al listar el conjunto, el número de entradas impreso en la cabecera puede ser mayor que el número de entradas listada

s para conjuntos con extensiones de timeout: el número de entradas en el conjunto es actualizado cuando se añaden/bo
rran elementos al conjunto y periódicamente cuando el recolector de basura elimina las entradas con timeout expirado.

counters, packets,

bytes

Todos los tipos de conjunto soportan la opción opcional counters al crear un conjunto. Si se especifica la opción, entonces el conjunto se crea con soporte para contadores de paquetes y bytes por elemento. Los contadores de paquetes y bytes se inicializan a cero cuando los elementos son (re-)añadidos al conjunto, a menos que los valores de los contadores de paquetes y bytes sean explícitamente especificados por las opciones packets y bytes. Un ejemplo cuando un elemento es añadido a un conjunto con valores de contador distintos de

cero:
ipset create foo hash:ip
counters
ipset add fo
o 192.168.1.
1 packets 4
2 bytes 1024

commen

t

Todos los tipos de conjunto soportan la extensión opcional comment. Habilitar esta extensión en un ipset le permite anotar una entrada de ipset con una cadena arbitraria. Esta cadena es completamente ignorada tanto por el kernel como por ipset mismo y es puramente para proporcionar un medio conveniente para documentar la razón de la existencia de una entrada. Los comentarios no deben contener comillas y el carácter de escape habitual (\) no tiene significado. Por ejemplo, el siguiente comando de shell es

ilegal:
ipset add foo 1.1.1.
1 comment "this comme
nt is \"bad\""

En lo anterior, su shell por supuesto escapará las comillas y ipset verá las comillas en el argumento para el comentario, lo que resultará en un error de análisis. Si está escribiendo su propio sistema, debería evitar crear comentarios que contengan una comilla si no desea romper "ipset save" y "ipset restore", sin embargo, el kernel no le impedirá hacerlo. Lo siguiente es perfectamente

aceptable:
ipset create foo hash:ip
comment
ipset add foo 192.168.1.1/24 comment "allow access to SMB share on
\\\\fileserv\\"
lo anterior aparece
ría como: "allow ac
cess to SMB share on
\\fileserv\"

skbinfo, skbmark, skbprio,

skbqueue

Todos los tipos de conjunto soportan la extensión opcional skbinfo. Esta extensión le permite almacenar la metainformación (marca de firewall, clase tc y cola de hardware) con cada entrada y mapearla a paquetes mediante el uso del objetivo netfilter SET con la opción --map-set. formato de la opción skbmark: MARK o MARK/MASK, donde MARK y MASK son números hexadecimales de 32 bits con prefijo 0x. Si solo se especifica mark, se usa la máscara 0xffffffff. la opción skbprio tiene el formato de clase tc: MAJOR:MINOR, donde los números major y minor son hexadecimales sin prefijo 0x. la opción skbqueue es solo un número

decimal.
ipset create foo hash:ip
skbinfo
ipset add foo 192.16
8.0.1 skbmark 0x1111/
0xff00ffff skbprio 1:
10 skbqueue 10

El tipo de conjunto hash:net,net utiliza un hash para almacenar pares de direcciones de red IP de diferentes tamaños. Tenga en cuenta que el primer parámetro tiene prioridad sobre el segundo, por lo que una entrada nomatch podría ser ineficaz si existiera un primer parámetro más específico con un segundo parámetro adecuado. NAME

ipset — adminstration utility for IP sets

SYNOPSIS

ipset command [options] [element(s) ...]

ipset help [command]

DESCRIPTION

ipset is a utility for administration of IP sets. IP set is a framework, which can be used to set how Linux kernel should treat flows based on a list of specified parameters. IP sets are used in conjunction with iptables(8). A set is a collection of objects of the same type. The objects are typically IP addresses, network prefixes or MAC addresses. A set can be referenced in an iptables rule, just like a single IP address or network prefix.

OPTIONS

The main commands are:

create
Create a new set. Syntax: ipset create setname settype [create-options]
add
Add an element to a set. Syntax: ipset add setname element [add-options]
del
Delete an element from a set. Syntax: ipset del setname element [del-options]
test
Test if an element is in a set. Syntax: ipset test setname element [test-options]
destroy
Destroy a set. Syntax: ipset destroy setname
list
List sets or elements in a set. Syntax: ipset list [setname] [list-options]
save
Save sets to the specified file. Syntax: ipset save [file]
restore
Restore sets from the specified file. Syntax: ipset restore [file]
flush
Remove all elements from a set or all sets. Syntax: ipset flush [setname]
rename
Rename a set. Syntax: ipset rename oldname newname
swap
Swap two sets. Syntax: ipset swap set1 set2
help
Show help messages. Syntax: ipset help [command]

INTRODUCTION

This man page describes the ipset utility and the netfilter kernel module interaction.

GENERIC CREATE AND ADD OPTIONS

create command options:

family value
Sets the protocol family for the set. Possible values: inet (IPv4), inet6 (IPv6), link (MAC addresses). Default is inet.
size value
The number of elements the set might contain. This is a hint for the implementation, not a hard limit. Default is 1024.
timeout value
The element timeout is specified in seconds. Default is 0 (never expire).
counters
Enable packet and byte counters for the set members. Default is off.
comment
Optional comment for the set. Default is off.
skbinfo
Store packet metadata (mark, queue-number, priority) for the set members. Default is off.

add command options:

packets value
Manually set packet counter for the element. Default is 0.
bytes value
Manually set byte counter for the element. Default is 0.
comment string
Optional comment for the element. Default is empty.
skbmark value
Store packet mark for the element.
skbprio value
Store packet priority for the element.
skbqueue value
Store packet queue number for the element.

hash:net,iface

Stores network prefixes associated with interface names. The lookup time is constant on average, O(1).

CREATE-OPTIONS := [ family (inet|inet6) ] [ size value ] [ timeout value ] [ counters ] [ comment ] [ skbinfo ]

ADD-ENTRY := network/mask,iface

ADD-OPTIONS := [ timeout value ] [ packets value ] [ bytes value ] [ comment string ] [ skbmark value ] [ skbprio value ] [ skbqueue value ]

The direction parameter of the set match and SET target modules corresponds to the incoming/outgoing interface: src to the incoming one (similar to the -i flag of iptables), while dst to the outgoing one (similar to the -o flag of iptables). When the interface is flagged with physdev:, the interface is interpreted as the incoming/outgoing bridge port.

The lookup time grows linearly with the number of the different prefix values added to the set.

The internal restriction of the hash:net,iface set type is that the same network prefix cannot be stored with more than 64 different interfaces in a single set.

Examples:

ipset create foo hash:net,iface
ipset add foo 192.168.0/24,eth0
ipset add foo 10.1.0.0/16,eth1
ipset test foo 192.168.0/24,eth0

list:set

The list:set type uses a simple list in which you can store set names.

CREATE-OPTIONS := [ size value ] [ timeout value ] [ counters ] [ comment ] [ skbinfo ]

ADD-ENTRY := setname [ { before | after } setname ]

ADD-OPTIONS := [ timeout value ] [ packets value ] [ bytes value ] [ comment string ] [ skbmark value ] [ skbprio value ] [ skbqueue value ]

DEL-ENTRY := setname [ { before | after } setname ]

TEST-ENTRY := setname [ { before | after } setname ]

Optional create options:

size value
The size of the list, the default is 8. The parameter is ignored since ipset version 6.24.

By the ipset command you can add, delete and test set names in a list:set type of set.

By the set match or SET target of netfilter you can test, add or delete entries in the sets added to the list:set type of set. The match will try to find a matching entry in the sets and the target will try to add an entry to the first set to which it can be added. The number of direction options of the match and target are important: sets which require more parameters than specified are skipped, while sets with equal or less parameters are checked, elements added/deleted. For example if a and b are list:set type of sets then in the command

iptables -m set --match-set a src,dst -j SET --add-set b src,dst

the match and target will skip any set in a and b which stores data triples, but will match all sets with single or double data storage in a set and stop matching at the first successful set, and add src to the first single or src,dst to the first double data storage set in b to which the entry can be added. You can imagine a list:set type of set as an ordered union of the set elements.

Please note: by the ipset command you can add, delete and test the setnames in a list:set type of set, and not the presence of a set's member (such as an IP address).

GENERAL RESTRICTIONS

Zero valued set entries cannot be used with hash methods. Zero protocol value with ports cannot be used.

COMMENTS

If you want to store same size subnets from a given network (say /24 blocks from a /8 network), use the bitmap:ip set type. If you want to store random same size networks (say random /24 blocks), use the hash:ip set type. If you have got random size of netblocks, use hash:net.

Matching on destination MAC addresses using the dst parameter of the set match netfilter kernel modules will only work if the destination MAC address is available in the packet at the given processing stage, that is, it only applies for incoming packets in the PREROUTING, INPUT and FORWARD chains, against the MAC address as originally found in the received packet (typically, one of the MAC addresses of the local host). This is not the destination MAC address a destination IP address resolves to, after routing. If the MAC address is not available (e.g. in the OUTPUT chain), the packet will simply not match.

Backward compatibility is maintained and old ipset syntax is still supported.

The iptree and iptreemap set types are removed: if you refer to them, they are automatically replaced by hash:ip type of sets.
