DESCRIPCIÓ

N

Ipmi-sel se utiliza para ver y gestionar entradas del Registro de Eventos del Sistema (SEL). Los registros SEL almacenan información de eventos del sistema y pueden ser útiles para depurar problemas. Ipmi-sel no informa al usuario si un evento es particularmente bueno o malo, solo que el evento ocurrió. Los usuarios pueden desear usar la opción --output-event-state para generar la salida del estado

analizado.

A continuación se enumeran las opciones generales de IPMI, las opciones específicas de la herramienta, información de solución de problemas, información de soluciones alternativas, ejemplos y problemas conocidos. Para una introducción general a FreeIPMI, consulte freeipmi(7). Para realizar una gestión avanzada de SEL, consulte bmc-d

evic
e(8).

SOPORTE DE RANGO DE

HOSTS

Se pueden introducir múltiples hosts ya sea como listas explícitas de hosts separadas por comas o como un rango de nombres de host en la forma general: prefijo[n-m,l-k,...], donde n < m y l < k, etc. La última forma no debe confundirse con las clases de caracteres de expresiones regulares (también denotadas por []). Por ejemplo, foo[19] no representa foo1 o foo9, sino que representa un rango degenerado:

foo19.

Esta sintaxis de rango está destinada solo como una comodidad en clústeres con una convención de nombres prefijoNN y la especificación de rangos no debe considerarse necesaria -- la lista foo1,foo9 podría especificarse como tal, o por el rango foo[1,9]

.

A continuación se muestran algunos ejemplos de uso de

rangos: 
    foo[01-05] en lugar de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] en lugar de foo7,foo9,foo10
    foo[0-3] en lugar de foo0,foo1,foo2,
foo3

Como recordatorio para el lector, algunos shells interpretarán los corchetes ([ y ]) para la coincidencia de patrones. Dependiendo de su shell, puede ser necesario encerrar las listas de rangos entre

comillas.

Cuando el usuario especifica múltiples hosts, se ejecutará un hilo para cada host en paralelo hasta el fanout configurado (que puede ajustarse mediante la opción -F). Esto permitirá la comunicación con un gran número de nodos mucho más rápidamente que si se hiciera en

serie.

Por defecto, la salida estándar de cada nodo especificado se emitirá con el nombre de host antepuesto a cada línea. Aunque esta salida es legible en muchas situaciones, puede ser difícil de leer en otras situaciones. Por ejemplo, la salida de múltiples nodos puede mezclarse. Las opciones -B y -C se pueden utilizar para cambiar este comportamiento por

defecto.

Se utilizará la comunicación IPMI en banda cuando se

especifica el host "localhost". Esto permite al usuari
o añadir el localhost a la salida del rango de hosts.

SOLUCIÓN DE PROBLEMAS

GENERAL

La mayoría de las veces, los problemas de IPMI se deben a problemas de

configuración.

Los problemas de IPMI sobre LAN implican una configuración incorrecta del BMC de la máquina remota. Verifique dos veces para asegurarse de que lo siguiente está configurado correctamente en el BMC de la máquina remota: dirección IP, dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio LAN, habilitación LAN y tipo(s) de autenticación permitidos. Para conexiones IPMI 2.0, verifique dos veces para asegurarse de que el(los) privilegio(s) de la suite de cifrado y la clave K_g están configurados correctamente. La herramienta ipmi-config(8) se puede utilizar para comprobar y/o cambiar estos ajustes de

configuración.

Los problemas de IPMI en banda suelen estar causados por controladores mal configurados o BMC no

estándar.

Además de los consejos de solución de problemas que se indican a continuación, consulte SOLUCIONES ALTERNATIVAS más abajo para ver también si se han descubierto y solucionado errores específicos del

proveedor.

A continuación se enumeran muchos de los problemas comunes para los mensajes de error. Para obtener soporte adicional, envíe un correo electrónico a la lista de correo <freeipmi-users@gnu.org>

.

"username invalid" - El nombre de usuario introducido (o un nombre de usuario NULL si no se introdujo ninguno) no está disponible en la máquina remota. También es posible que la configuración del nombre de usuario del BMC remoto sea

incorrecta.

"password invalid" - La contraseña introducida (o una contraseña NULL si no se introdujo ninguna) no es correcta. También es posible que la contraseña del usuario no esté configurada correctamente en el BMC

remoto.

"password verification timeout" - La verificación de la contraseña ha agotado el tiempo de espera. Ha ocurrido un error "password invalid" (descrito anteriormente) o un "session timeout" genérico (descrito más abajo). En este punto del protocolo no se puede diferenciar cuál

ocurrió.

"k_g invalid" - La clave K_g introducida (o una clave K_g NULL si no se introdujo ninguna) no es correcta. También es posible que la clave K_g no esté configurada correctamente en el BMC

remoto.

"privilege level insufficient" - Un comando IPMI requiere un privilegio de usuario más alto que el con el que se autenticó. Intente autenticarse con un privilegio más alto. Esto puede requerir autenticarse con un usuario diferente que tenga un privilegio máximo más

alto.

"privilege level cannot be obtained for this user" - El nivel de privilegio con el que intenta autenticarse es más alto que el máximo permitido para este usuario. Inténtelo de nuevo con un privilegio más bajo. También es posible que el nivel de privilegio máximo permitido para un usuario no esté configurado correctamente en el BMC

remoto.

"authentication type unavailable for attempted privilege level" - El tipo de autenticación con el que desea autenticarse no está disponible para este nivel de privilegio. Inténtelo de nuevo con un tipo de autenticación alternativo o un nivel de privilegio alternativo. También es posible que los tipos de autenticación disponibles con los que puede autenticarse no estén configurados correctamente en el BMC

remoto.

"cipher suite id unavailable" - El id de la suite de cifrado con el que desea autenticarse no está disponible en el BMC remoto. Inténtelo de nuevo con un id de suite de cifrado alternativo. También es posible que los ids de suite de cifrado disponibles no estén configurados correctamente en el BMC

remoto.

"ipmi 2.0 unavailable" - No se detectó IPMI 2.0 en la máquina remota. Intente usar IPMI 1.5 en su

lugar.

"connection timeout" - La comunicación IPMI inicial ha fallado. Son posibles varios errores potenciales, incluyendo un nombre de host no válido especificado, que no se pueda resolver la dirección IP de IPMI, que IPMI no esté habilitado en el servidor remoto, que la conexión de red sea deficiente, etc. Verifique la configuración y la

conectividad.

"session timeout" - La sesión IPMI ha agotado el tiempo de espera. Reconéctese. Si este error ocurre con frecuencia, es posible que desee aumentar el tiempo de espera de retransmisión. Algunos BMC remotos son considerablemente más lentos que

otros.

"device not found" - No se pudo encontrar el dispositivo especificado. Compruebe la configuración o las entradas e inténtelo de

nuevo.

"driver timeout" - La comunicación con el controlador o dispositivo ha agotado el tiempo de espera. Inténtelo de

nuevo.

"message timeout" - La comunicación con el controlador o dispositivo ha agotado el tiempo de espera. Inténtelo de

nuevo.

"BMC busy" - El BMC está ocupado actualmente. Puede estar procesando información o tener demasiadas sesiones simultáneas que gestionar. Espere e inténtelo de

nuevo.

"could not find inband device" - No se pudo encontrar un dispositivo en banda. Compruebe la configuración o especifique un dispositivo o controlador específico en la línea de

comandos.

"driver timeout" - El controlador en banda ha agotado el tiempo de espera comunicándose con el BMC o el procesador de servicio local. El BMC o el procesador de servicio puede estar ocupado o (en el peor de los casos) posiblemente no

funcionando.

"internal IPMI error" - Ha ocurrido un error de IPMI que FreeIPMI no sabe cómo manejar. Envíe un correo electrónico a <freeipmi-users@gnu.org>o report the issue.

Solución de problemas del IPMI-SEL

Algunas marcas de tiempo en el SEL pueden informar una fecha de 1-ene-1970, la época para las marcas de tiempo del SEL. Esta marca de tiempo no es necesariamente incorrecta. Por lo general, indica un evento de hardware que ocurrió antes de que se inicializara una marca de tiempo en el firmware. Por ejemplo, ciertos componentes de hardware tendrán sus relojes internos reiniciados durante un ciclo de energía.

Sin embargo, si el reloj interno del SEL parece ser regularmente incorrecto, es posible que necesite establecer la hora del SEL. Esto se puede hacer usando bmc-device(8).

Los siguientes son mensajes comunes relacionados con el SEL.

"sel config file parse error" - Se encontró un error de análisis en el archivo de configuración de interpretación de eventos del sel. Consulte freeipmi_interpret_sel.conf(5).

Soluciones

Con tantos proveedores diferentes implementando sus propias soluciones IPMI, diferentes proveedores pueden implementar sus protocolos IPMI incorrectamente. Lo siguiente describe una serie de soluciones actualmente disponibles para manejar los problemas de cumplimiento descubiertos. Cuando sea posible, las soluciones se han implementado para que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se utilice una solución a través de la opción -W.

El hardware que se enumera a continuación puede indicar solo el hardware en el que se descubrió un problema. Las versiones más recientes de hardware pueden corregir los problemas indicados a continuación. Las máquinas similares de diferentes proveedores pueden o no presentar los mismos problemas. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede valer la pena probar las soluciones que se enumeran a continuación, incluso si su placa base no está en la lista.

Si cree que su hardware tiene un problema de cumplimiento adicional que requiere una solución, póngase en contacto con los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.org>.

assumeio - Esta bandera de solución asumirá que las interfaces in-band se comunican con la E/S del sistema en lugar de ser accedidas a través de memoria mapeada. Esto solucionará sistemas que informan direcciones base inválidas. Aquellos que experimenten este problema pueden ver errores de "dispositivo no compatible" o "no se pudo encontrar el dispositivo in-band". Problema observado en HP ProLiant DL145 G1.

spinpoll - Esta bandera de solución indicará a algunos controladores in-band (principalmente el controlador KCS) que giren mientras hacen polling en lugar de poner el proceso a dormir. Esto puede mejorar significativamente el tiempo de ejecución del reloj de pared de las herramientas, ya que la granularidad del planificador del sistema operativo puede ser mucho mayor que el tiempo que se tarda en realizar una sola transacción de mensaje IPMI. Sin embargo, al girar, su sistema puede estar realizando un trabajo menos útil al no cambiar el contexto de la herramienta por una tarea más útil.

authcap - Esta bandera de solución omitirá las verificaciones tempranas de las capacidades del nombre de usuario, las capacidades de autenticación y el soporte K_g, y permitirá que la autenticación IPMI tenga éxito. Soluciona múltiples problemas en los que el sistema remoto no informa correctamente las capacidades del nombre de usuario, las capacidades de autenticación o el estado K_g. Aquellos que experimenten este problema pueden ver errores de "nombre de usuario inválido", "tipo de autenticación no disponible para el nivel de privilegio intentado" o "k_g inválido". Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML y Sun Fire 2200/4150/4450 con ELOM.

nochecksumcheck - Esta bandera de solución le indicará a FreeIPMI que no verifique las sumas de verificación devueltas por las respuestas de los comandos IPMI. Soluciona sistemas que devuelven sumas de verificación inválidas debido a errores de implementación, pero el paquete es válido en otros aspectos. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina la validación de la integridad del paquete en varias circunstancias. Sin embargo, es poco probable que sea un problema en la mayoría de las situaciones. Aquellos que experimenten este problema pueden ver errores de "tiempo de espera de conexión", "tiempo de espera de sesión" o "tiempo de espera de verificación de contraseña". En conexiones IPMI 1.5, también puede ser necesaria la solución "noauthcodecheck". Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F y Supermicro X9DRFR.

idzero - Esta bandera de solución permitirá que se acepten identificadores de sesión vacíos por parte del cliente. Soluciona sesiones IPMI que informan identificadores de sesión vacíos al cliente. Aquellos que experimenten este problema pueden ver errores de "tiempo de espera de sesión". Problema observado en Tyan S2882 con M3289 BMC.

unexpectedauth - Esta bandera de solución permitirá que los códigos de autenticación inesperados no nulos se verifiquen como si fueran esperados. Soluciona un problema en el que los paquetes contienen datos de autenticación no nulos cuando deberían ser nulos debido a que la autenticación por mensaje está deshabilitada. Aquellos que experimenten este problema pueden ver errores de "tiempo de espera de sesión". Problema observado en Dell PowerEdge 2850, SC1425. Confirmado que se corrigió en firmware más reciente.

forcepermsg - Esta bandera de solución forzará el uso de la autenticación por mensaje independientemente de lo que anuncie el sistema remoto. Soluciona un problema en el que la autenticación por mensaje se anuncia como deshabilitada en el sistema remoto, pero en realidad es requerida para el protocolo. Aquellos que experimenten este problema pueden ver errores de "tiempo de espera de sesión". Problema observado en IBM eServer 325.

endianseq - Esta bandera de solución invertirá el orden de los números de secuencia de sesión para permitir que la sesión continúe correctamente. Soluciona números de secuencia IPMI 1.5 que tienen un orden equivocado. Aquellos que experimenten este problema pueden ver errores de "tiempo de espera de sesión". Problema observado en algunos Sun ILOM 1.0/2.0 (depende del orden del procesador de servicio).

noauthcodecheck - Esta bandera de solución indicará a FreeIPMI que no verifique los códigos de autenticación devueltos por las respuestas de comandos IPMI 1.5. Soluciona sistemas que devuelven códigos de autenticación inválidos debido a errores de hash o implementación. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina una verificación de autenticación que valida la validez de un paquete. Sin embargo, en la mayoría de las organizaciones, es poco probable que sea un problema de seguridad. Aquellos que experimenten este problema pueden ver errores de "tiempo de espera de conexión", "tiempo de espera de sesión" o "tiempo de espera de verificación de contraseña". Problema observado en Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell y Wiwynn Windmill.

intel20 - Esta bandera de solución solucionará varios problemas de autenticación IPMI 2.0 de Intel. Los problemas cubiertos incluyen el relleno de nombres de usuario y la truncación de contraseñas si el algoritmo de autenticación es HMAC-MD5-128. Aquellos que experimenten este problema pueden ver errores de "nombre de usuario inválido", "contraseña inválida" o "k_g inválido". Problema observado en Intel SE7520AF2 con Intel Server Management Module (Professional Edition).

supermicro20 - Esta bandera de solución solucionará varios problemas de autenticación IPMI 2.0 de Supermicro en placas base con firmware IPMI Peppercon. Los problemas cubiertos incluyen el manejo de códigos de autenticación de longitud inválida. Aquellos que experimenten este problema pueden ver errores de "contraseña inválida". Problema observado en Supermicro H8QME con tarjeta hija SIMSO. Confirmado que se corrigió en firmware más reciente.

sun20 - Esta bandera de solución solucionará varios problemas de autenticación IPMI 2.0 de Sun. Los problemas cubiertos incluyen claves hash de longitud inválida, claves hasheadas incorrectamente y registros de suite de cifrado inválidos. Aquellos que experimenten este problema pueden ver errores de "contraseña inválida" o "error de bmc". Problema observado en Sun Fire 4100/4200/4500 con ILOM. Esta solución incluye automáticamente la solución "opensesspriv".

opensesspriv - Esta bandera de solución alterará ligeramente el protocolo de conexión IPMI 2.0 de FreeIPMI para solucionar un algoritmo de hash inválido utilizado por el sistema remoto. El nivel de privilegio enviado durante la etapa de Apertura de Sesión de una conexión IPMI 2.0 se utiliza para hashear claves en lugar del nivel de privilegio enviado durante la etapa de conexión RAKP1. Aquellos que experimenten este problema pueden ver errores de "contraseña inválida", "k_g inválido", "código de estado rmcpplus incorrecto" o "no se puede obtener el nivel de privilegio para este usuario". Problema observado en Sun Fire 4100/4200/4500 con ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220 y el BMC de software OpenIPMI. Esta solución se activa automáticamente con la solución "sun20".

integritycheckvalue - Esta bandera de solución solucionará un valor de verificación de integridad inválido durante el establecimiento de una sesión IPMI 2.0 cuando se utiliza la Suite de Cifrado ID 0. El valor de verificación de integridad debería tener una longitud de 0, sin embargo, la placa base remota responde con un campo no vacío. Aquellos que experimenten este problema pueden ver errores de "k_g inválido". Problema observado en Supermicro X8DTG, Supermicro X8DTU e Intel S5500WBV/Penguin Relion 700, e Intel S2600JF/Appro 512X.

assumemaxsdrrecordcount - Esta solución indicará a la lectura de SDR que deje de leer después de que se haya leído un número máximo conocido de registros SDR. Esto solucionará sistemas que tienen funciones de lectura SDR mal implementadas. Aquellos que experimenten este problema pueden ver errores de "recuento de registros SDR inválido". Problema observado en placa base Inspur no especificada.

assumesystemevent - Esta opción de solución asumirá que los tipos de registro SEL inválidos son registros de eventos del sistema. Los registros pueden estar formateados correctamente pero informar tipos de registro inválidos. Aquellos que experimenten este problema pueden ver errores de "Tipo de registro SEL desconocido". La salida puede ser desconocida, cruce los dedos. Se confirma que esta opción soluciona problemas de cumplimiento en las placas base HP DL 380 G5.

Sin soporte IPMI 1.5 - Se ha descubierto que algunas placas base que soportan IPMI 2.0 no soportan IPMI 1.5. Aquellos que experimenten este problema pueden ver errores de "ipmi 2.0 no disponible" o "tiempo de espera de conexión". Este problema se puede solucionar utilizando IPMI 2.0 en lugar de IPMI 1.5 especificando --driver-type=LAN_2_0. Problema observado en varias placas base HP y Supermicro.

EXAMPLES

# ipmi-sel

Muestra todos los registros SEL en la máquina local.

# ipmi-sel -h ahost -u myusername -p mypassword

Muestra todos los registros SEL de una máquina remota utilizando IPMI sobre LAN.

# ipmi-sel -h mycluster[0-127] -u myusername -p mypassword

Muestra todos los registros SEL en un clúster utilizando IPMI sobre LAN.

# ipmi-sel --delete=44,82

Elimina los registros SEL 44 y 82 en la máquina local.

# ipmi-sel --delete-all

Elimina todas las entradas SEL en la máquina local.

# ipmi-sel --delete-range=12-42

Elimina las entradas SEL en el rango de 12 a 42 en la máquina local.

DIAGNOSTICS

Al ejecutarse correctamente, el estado de salida es 0. En caso de error, el estado de salida es 1.

Si se especifican múltiples hosts para la comunicación, el estado de salida es 0 si y solo si todos los objetivos se ejecutan correctamente. De lo contrario, el estado de salida es 1.

KNOWN ISSUES

En sistemas operativos más antiguos, si introduce su nombre de usuario, contraseña y otra información potencialmente relevante para la seguridad en la línea de comandos, esta información puede ser descubierta por otros usuarios al usar herramientas como el comando ps(1) o al mirar en el sistema de archivos /proc. Generalmente es más seguro introducir la información de contraseña con opciones como las opciones -P o -K. Configurar información relevante para la seguridad en el archivo de configuración de FreeIPMI también sería una forma apropiada de ocultar esta información.

Para prevenir ataques de fuerza bruta, algunos BMC (Baseboard Management Controller) se "bloquearán" temporalmente después de un número de errores de autenticación remota. Es posible que necesite esperar un tiempo para que este "bloqueo" temporal pase antes de que pueda autenticarse nuevamente.
