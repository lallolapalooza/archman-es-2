IP-MONITOR(8) Linux IP-MONITOR(8)

NOMBRE

ip monitor, rtmon - monitorización de estado

SINOPSIS


ip monitor [ all | LISTA-DE-OBJETOS ] [ file NOMBRE-ARCHIVO ] [ label ] [ all-nsid ] [ dev DISPOSITIVO ]

OPCIONES

-t, -timestamp
Imprime una marca de tiempo antes del mensaje del evento en una línea separada en el formato:
Timestamp: <Día> <Mes> <DD> <hh:mm:ss> <AAAA> <usegundos> usec
<EVENTO>
-ts, -tshort
Imprime una marca de tiempo corta antes del mensaje del evento en la misma línea en el formato:
[<AAAA>-<MM>-<DD>T<hh:mm:ss>.<ms>] <EVENTO>

DESCRIPCIÓN

La utilidad ip puede monitorizar el estado de dispositivos, direcciones y rutas de forma continua. Esta opción tiene un formato ligeramente diferente. En concreto, el comando monitor es el primero en la línea de comandos y luego sigue la lista de objetos:

ip monitor [ all | LISTA-DE-OBJETOS ] [ file NOMBRE-ARCHIVO ] [ label ] [ all-nsid ] [ dev DISPOSITIVO ]

LISTA-DE-OBJETOS es la lista de tipos de objetos que queremos monitorizar. Puede contener link, address, route, mroute, maddress, acaddress, prefix, neigh, netconf, rule, stats, nsid y nexthop. Si no se proporciona el argumento file, ip abre RTNETLINK, escucha en él y vuelca los cambios de estado en el formato descrito en secciones anteriores.

Si se establece la opción label, se muestra un prefijo antes de cada mensaje para indicar la familia del mensaje. Por ejemplo:


[NEIGH]10.16.0.112 dev eth0 lladdr 00:04:23:df:2f:d0 REACHABLE [LINK]3: eth1: <BROADCAST,MULTICAST> mtu 1500 qdisc pfifo_fast state DOWN group default
link/ether 52:54:00:12:34:57 brd ff:ff:ff:ff:ff:ff

Si se establece la opción all-nsid, el programa escucha en todos los espacios de nombres de red que tienen un nsid asignado en el espacio de nombres de red donde se está ejecutando el programa. Se muestra un prefijo para indicar el espacio de nombres de red del que procede el mensaje. Ejemplo:


[nsid 0]10.16.0.112 dev eth0 lladdr 00:04:23:df:2f:d0 REACHABLE

Si se proporciona la opción file, el programa no escucha en RTNETLINK, sino que abre el archivo especificado y vuelca su contenido. El archivo debe contener mensajes RTNETLINK guardados en formato binario. Dicho archivo puede ser generado con la utilidad rtmon. Esta utilidad tiene una sintaxis de línea de comandos similar a ip monitor. Idealmente, rtmon debería iniciarse antes de que se emita el primer comando de configuración de red. Por ejemplo, si inserta:


rtmon file /var/log/rtmon.log

en un script de inicio, podrá ver el historial completo más tarde.

Sin embargo, es posible iniciar rtmon en cualquier momento. Antepone al historial una instantánea del estado volcada en el momento de su inicio.

Si se proporciona la opción dev, el programa imprime solo eventos relacionados con ese dispositivo.
