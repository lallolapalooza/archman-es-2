DESCRIPCIÓN

La utilidad iptables se utiliza para configurar las tablas de correspondencia de paquetes de la cadena de firewall de Linux. Se pueden definir diferentes tablas para diferentes propósitos. Cada tabla contiene varias cadenas y cada cadena contiene varias reglas. Cada regla especifica una serie de criterios de coincidencia de paquetes y un objetivo que se seguirá si los criterios coinciden. Una regla es una tupla de:

[match] [target]

El argumento chain es uno de los siguientes:

       *filter
              This table contains the rules which perform filtering of
              packets. This is the only table which is available when
              you choose to compile iptables as a module.

       *nat
              This table contains the rules which perform packet mangling.
              This includes destinations (dst-nat) and sources (src-nat)
              for altering the trajectory of packets as well as the MAS-
              QUERADE target to automatically use a pool of one outgoing
              IP address.

       *mangle
              This table is used for special packet processing. It was
              intended for anything that wasn't covered by the nat table.
              One example is the re-routing of packets to firewall-marked
              connections.

       *raw
              This table is used mainly for configuring a notion of state
              freezing, i.e. marks not to be SNATed, M-SNATed or teleported.
              Only the PREROUTING chain is valid in this table.

La acción -A añade una regla al final de la cadena especificada. La acción -C comprueba si una regla existe en la cadena especificada. La acción -D elimina una regla de la cadena especificada. La acción -I inserta una regla al principio de la cadena especificada. La acción -L lista todas las reglas de la cadena especificada. La acción -F borra todas las reglas de la cadena especificada. La acción -X elimina la cadena especificada. La acción -E renombra la cadena especificada.

TARGETS

Un objetivo es una acción que se realizará cuando una coincidencia se realiza con una regla. Los objetivos disponibles incluyen:

ACCEPT
Aceptar el paquete.
DROP
Descartar silenciosamente el paquete.
REJECT
Enviar una respuesta al remitente (por ejemplo, ICMP port-unreachable). Esto es más útil que DROP para la depuración.
MASQUERADE
Para NAT de origen de salida. La dirección IP de origen se sustituye por la dirección IP de la interfaz de salida. Esto es útil cuando la interfaz de salida tiene una dirección IP dinámica.
SNAT
NAT de origen. La dirección IP de origen se sustituye por la dirección IP especificada.
DNAT
NAT de destino. La dirección IP de destino se sustituye por la dirección IP especificada.
LOG
Registrar la coincidencia del paquete (imprimir un mensaje en el registro del kernel).

TABLES

Hay cuatro tablas en iptables.

filter
Esta es la tabla estándar y contiene las reglas para el filtrado de paquetes. Las cadenas predeterminadas son INPUT, FORWARD y OUTPUT.
nat
Esta tabla se utiliza para la traducción de direcciones de red (NAT). Las cadenas predeterminadas son PREROUTING, OUTPUT y POSTROUTING.
mangle
Esta tabla se utiliza para la manipulación especial de paquetes. Las cadenas predeterminadas son PREROUTING y OUTPUT.
raw
Esta tabla se utiliza para la configuración de un estado de congelación libre de estado. La única cadena válida en esta tabla es PREROUTING.

LOCK FILE

iptables utiliza el archivo /run/xtables.lock para tomar un bloqueo exclusivo al inicio.

La variable de entorno XTABLES_LOCKFILE se puede utilizar para anular la configuración predeterminada.

MATCH AND TARGET EXTENSIONS

iptables puede utilizar módulos de coincidencia y objetivo de paquetes extendidos. Una lista de estos está disponible en la página del manual iptables-extensions(8).

DIAGNOSTICS

Se imprimen varios mensajes de error en la salida de error estándar. El código de salida es 0 para el funcionamiento correcto. Los errores que parecen ser causados por parámetros de línea de comandos inválidos o abusados ​​causan un código de salida de 2. Los errores que indican una incompatibilidad entre el kernel y el espacio de usuario causan un código de salida de 3. Los errores que indican un problema de recursos, como un bloqueo ocupado, una asignación de memoria fallida o mensajes de error del kernel, causan un código de salida de 4. Finalmente, otros errores causan un código de salida de 1.

BUGS

¿Errores? ¿Qué es esto? ;-) Bueno, es posible que desees consultar https://bugzilla.netfilter.org/ iptables saldrá inmediatamente con un código de error de 111 si descubre que se llamó como un programa setuid-a-root. iptables no se puede utilizar de forma segura de esta manera porque confía en las bibliotecas compartidas (coincidencias, objetivos) cargadas en tiempo de ejecución, la ruta de búsqueda se puede establecer utilizando variables de entorno.

COMPATIBILITY WITH IPCHAINS

Este iptables es muy similar a ipchains de Rusty Russell. La principal diferencia es que las cadenas INPUT y OUTPUT solo se recorren para los paquetes que llegan al host local y se originan desde el host local, respectivamente. Por lo tanto, cada paquete solo pasa a través de una de las tres cadenas (excepto el tráfico de loopback, que involucra las cadenas INPUT y OUTPUT); anteriormente, un paquete reenviado pasaría por las tres.

La otra diferencia principal es que -i se refiere a la interfaz de entrada; -o se refiere a la interfaz de salida, y ambas están disponibles para los paquetes que entran en la cadena FORWARD.

Las diversas formas de NAT se han separado; iptables es un filtro de paquetes puro cuando se utiliza la tabla `filter' predeterminada, con módulos de extensión opcionales. Esto debería evitar gran parte de la confusión sobre la combinación de enmascaramiento IP y filtrado de paquetes vista anteriormente. Por lo tanto, las siguientes opciones se manejan de manera diferente:

 -j MASQ
 -M -S
 -M -L
Hay varios otros cambios en iptables.
