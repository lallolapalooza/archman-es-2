NOMBRE

ip-vrf - ejecutar un comando contra un vrf

SINOPSIS


ip vrf { COMANDO | help }

ip vrf show [ NOMBRE ]

ip vrf identify [ PID ]

ip vrf pids NOMBRE

ip vrf exec [ NOMBRE ] comando...

DESCRIPCIÓN

Un VRF proporciona aislamiento de tráfico en la capa 3 para el enrutamiento, similar a cómo se utiliza una VLAN para aislar el tráfico en la capa 2. Fundamentalmente, un VRF es una tabla de enrutamiento separada. Los dispositivos de red se asocian con un VRF al "esclavizar" el dispositivo al VRF. En ese momento, las direcciones de red asignadas al dispositivo son locales al VRF, y las rutas de host y conectadas se mueven a la tabla asociada con el VRF.

Un proceso puede especificar un VRF utilizando varias APIs: vinculando el socket al dispositivo VRF con SO_BINDTODEVICE, estableciendo la asociación VRF con IP_UNICAST_IF o IPV6_UNICAST_IF, o especificando el VRF para un mensaje específico usando IP_PKTINFO o IPV6_PKTINFO.

Por defecto, un proceso no está vinculado a ningún VRF. Una asociación se puede establecer explícitamente haciendo que el programa use una de las APIs mencionadas anteriormente, o implícitamente usando un ayudante para establecer SO_BINDTODEVICE para todos los sockets IPv4 e IPv6 (AF_INET y AF_INET6) cuando se crea el socket. Este comando ip-vrf es un ayudante para ejecutar un comando contra un VRF específico con la asociación VRF heredada de padre a hijo.

ip vrf show [ NOMBRE ] - Mostrar todos los VRF configurados

Este comando lista todos los VRF y sus IDs de tabla correspondientes. Si se proporciona NOMBRE, solo se mostrará ese VRF y su ID de tabla. Este último comando es útil para scripts donde se necesita el ID de tabla de un VRF.

ip vrf exec [ NOMBRE ] cmd ... - Ejecutar cmd contra el VRF nombrado

Este comando permite ejecutar aplicaciones que no son conscientes de VRF contra un VRF distinto del VRF predeterminado (tabla principal). Un comando puede ejecutarse contra el VRF predeterminado pasando "default" como nombre del VRF. Esto es útil si el shell actual está asociado con otro VRF (por ejemplo, VRF de administración).

Este comando requiere que el sistema se inicie con cgroup v2 (por ejemplo, con systemd, agregue systemd.unified_cgroup_hierarchy=1 a la línea de comandos del kernel).

Este comando también requiere ejecutarse como root. Alternativamente, puede ser ejecutado por un usuario no privilegiado si se otorgan las siguientes capacidades(7):

CAP_BPF
Para cargar el programa BPF.
CAP_NET_ADMIN
Para establecer el socket en el cgroup.
CAP_DAC_OVERRIDE
Para crear el subdirectorio cgroup en /sys.
Si estas capacidades se agregan y si ip(8) se compila con libcap(3), entonces estas capacidades se eliminarán antes de que cmd sea ejecutado por ip vrf exec. Para cualquier otra invocación no privilegiada de ip(8), todas las capacidades se eliminarán.

NOTA: las capacidades **NO** se eliminarán si CAP_NET_ADMIN se establece en HEREDABLE para evitar interrumpir programas con capacidades ambientales que llaman a ip.

ip vrf identify [PID] - Informar la asociación VRF para el proceso

Este comando muestra la asociación VRF del proceso especificado. Si no se especifica PID, se utiliza el ID del proceso actual.

ip vrf pids NOMBRE - Informar los procesos asociados con el VRF nombrado

Este comando muestra todos los IDs de proceso que están asociados con el VRF dado.

ADVERTENCIAS

Este comando requiere un kernel compilado con CGROUPS y CGROUP_BPF habilitados.

El ayudante VRF *solo* afecta a los sockets de la capa de red.

EJEMPLOS

ip vrf exec red ssh 10.100.1.254

Ejecuta ssh a 10.100.1.254 contra la tabla VRF red.

VER TAMBIÉN

ip(8), ip-link(8), ip-address(8), ip-route(8), ip-neighbor(8)
