DESCRIPCIÓ

N

Antes de que muchas herramientas IPMI puedan utilizarse a través de una red, el Controlador de Gestión de la Placa Base (BMC) de una máquina debe ser configurado. La configuración puede ser bastante intimidante para aquellos que no saben mucho sobre IPMI. Esta página de manual espera proporcionar suficiente información sobre la configuración del BMC para que pueda configurar el BMC de su sistema. Cuando sea apropiado, se sugerirán configuraciones típicas de

BMC.

El siguiente es un ejemplo de archivo de configuración parcialmente generado al ejecutar la opción --checkout con el comando ipmi-config(8). Esta configuración proviene de la categoría core de valores de configuración (la predeterminada). Esta configuración de ejemplo debería ser suficiente para la mayoría de los usuarios después de introducir las direcciones IP y MAC locales apropiadas. Siguiendo este ejemplo, secciones separadas de esta página de manual discutirán las diferentes secciones del archivo de configuración con más detalle, con explicaciones de cómo el BMC puede configurarse para diferentes

entornos.

Tenga en cuenta que muchas opciones pueden o no estar disponibles en su máquina en particular. Por ejemplo, Serial-Over-Lan (SOL) solo está disponible en máquinas IPMI 2.0. Por lo tanto, si está buscando configurar una máquina IPMI 1.5, muchas de las opciones relacionadas con SOL o IPMI 2.0 no estarán disponibles para usted. El número de usuarios configurables también puede variar para su máquina en

particular.

El archivo de configuración siguiente y la mayor parte de esta página de manual asumen que el usuario está interesado en configurar un BMC para su uso con IPMI sobre LAN. Varias opciones de configuración de ipmi-config(8) se han omitido o saltado porque se considera innecesario. Las futuras versiones de esta página de manual intentarán incluir más

información.

Sección User1, User2, ..

.

Las Secciones de usuario del archivo de configuración del BMC son para la configuración de nombres de usuario para la comunicación IPMI sobre LAN. El número de usuarios disponibles para configurar en su sistema variará según el fabricante. Con la excepción del Nombre de usuario para User1, todas las secciones son

idénticas.

El(los) nombre(s) de usuario que desea configurar en el BMC se definen con Username. El primer nombre de usuario bajo la Sección User1 es típicamente el nombre de usuario NULL y no puede ser modificado. La contraseña para el nombre de usuario se puede especificar con Password. Puede dejarse vacío para definir una contraseña NULL. Cada usuario que desee habilitar debe ser habilitado a través de la opción de configuración Enable_User. Se recomienda que todos los nombres de usuario tengan contraseñas no NULL o estén deshabilitados por razones de

seguridad.

Lan_Enable_Ipmi_Msgs se usa para habilitar o deshabilitar el acceso IPMI sobre LAN para el usuario. Esto debe establecerse en "Yes" para permitir que las herramientas IPMI sobre LAN

funcionen.

Lan_Privilege_Limit especifica el límite máximo de nivel de privilegio al que se permite al usuario. Diferentes comandos IPMI tienen diferentes restricciones de privilegio. Por ejemplo, determinar el estado de energía de una máquina solo requiere el nivel de privilegio "User". Sin embargo, el ciclo de energía requiere el privilegio "Operator". Típicamente, querrá asignar al menos un usuario con un límite de privilegio de "Administrator" para que todas las funciones del sistema estén disponibles para al menos un usuario a través de IPMI sobre

LAN.

Lan_Session_Limit especifica el número de sesiones IPMI simultáneas permitidas para el usuario. La mayoría de los usuarios querrán establecer esto en "0" para permitir un número ilimitado de sesiones IPMI simultáneas. Este campo es considerado opcional por los estándares de IPMI, y puede resultar en errores cuando se intenta configurarlo a un valor distinto de cero. Si ocurren errores, establecer el valor de nuevo a 0 debería resolver los

problemas.

SOL_Payload_Access especifica si un usuario en particular está permitido conectarse con Serial-Over-LAN (SOL). Esto debe establecerse en "Yes" para permitir que este nombre de usuario use

SOL.

La configuración de ejemplo anterior deshabilita "User2" pero habilita el usuario "NULL" (es decir, anónimo) predeterminado. Muchas herramientas IPMI (tanto de código abierto como de proveedores) no permiten al usuario ingresar un nombre de usuario y asumen el nombre de usuario NULL por defecto. Si las herramientas que le interesan usar permiten ingresar nombres de usuario, se recomienda que uno de los nombres de usuario no NULL sea habilitado y el nombre de usuario NULL deshabilitado por razones de seguridad. Se recomienda que deshabilite el nombre de usuario NULL en la sección User1, para que se requiera a los usuarios especificar un nombre de usuario para la comunicación IPMI sobre

LAN.

Algunas placas madre pueden requerir un Username para ser configurado antes de que otros campos sean leídos/escritos. Si este es el caso, esos campos se establecerán en <username-no

t-set
-yet>.

Sección

Lan_Channel

La sección Lan_Channel configura una variedad de parámetros de configuración de IPMI sobre LAN. Tanto las configuraciones Volatile como Non_Volatile pueden ser establecidas. Las configuraciones Volatile son configuradas inmediatamente en el BMC y tendrán un efecto inmediato en el sistema. Las configuraciones Non_Volatile solo están disponibles después del siguiente reinicio del sistema. Generalmente, tanto Volatile como Non_Volatile deben ser configurados de manera

idéntica.

El parámetro Access_Mode configura la disponibilidad de IPMI sobre LAN en el sistema. Típicamente esto debería establecerse en "Always_Available" para habilitar IPMI sobre

LAN.

El Privilege_Limit establece el privilegio máximo que cualquier usuario del sistema puede tener al realizar IPMI sobre LAN. Esto debería establecerse al nivel de privilegio máximo configurado para un nombre de usuario. Típicamente, esto debería establecerse en "Administrator"

.

Típicamente User_Level_Auth y Per_Message_Auth deberían establecerse en "Yes" para mayor seguridad. Deshabilitar User_Level_Auth permite que comandos IPMI con privilegio "User" se ejecuten sin autenticación. Deshabilitar Per_Message_Auth permite que menos mensaj

es IPMI individuales re
quieran autenticación.

Sección

Lan_Conf

Aquellos familiarizados con la configuración de redes deberían encontrar la mayoría de los campos en esta sección autoexplicativos. La configuración de BMC de ejemplo anterior ilustra la configuración de una dirección IP estática. El campo IP_Address_Source se configura con "Static". La dirección IP, la máscara de subred y las direcciones IP de la puerta de enlace de la máquina son configuradas respectivamente con los campos IP_Address, Subnet_Mask, Default_Gateway_Ip_Address, y Backup_Gateway_Ip_Address. Las direcciones MAC respectivas para las direcciones IP se configuran bajo Mac_Address, Default_Gateway_Mac_Address, y Backup_Gateway_Mac_Address

.

No es necesario configurar el IP_Address del BMC para que sea el mismo P_Address usado por su sistema operativo para esa interfaz de red. Sin embargo, si elige usar una dirección diferente, puede ser necesario configurar una configuración ARP

alternativa.

Para configurar en su lugar la información de red de su BMC a través de DHCP, el campo IP_Address_Source debería configurarse con

"Use_DHCP".

Se recomienda que se configuren direcciones IP estáticas por razones de resolución de direcciones. Vea Lan_Conf_Misc más abajo para una

explicació
n más detallada.

Sección

Lan_Conf_Auth

Esta sección determina qué tipos de mecanismos de autenticación de contraseña se permiten para los usuarios en diferentes niveles de privilegio bajo el protocolo IPMI 1.5. Los métodos de autenticación actualmente soportados para IPMI 1.5 son None (no se requiere nombre de usuario/contraseña), Straight_Password (las contraseñas se envían en claro), MD2 (las contraseñas se hashean con MD2), y MD5 (las contraseñas se hashean con MD5). Diferentes nombres de usuario en diferentes niveles de privilegio pueden estar permitidos para autenticarse de manera diferente a través de esta configuración. Por ejemplo, un nombre de usuario con privilegios "User" puede estar permitido autenticarse con una contraseña en claro, pero un nombre de usuario con privilegios "Administrator" puede estar permitido autenticarse solo con

MD5.

La configuración de ejemplo anterior soporta MD2 y MD5 autenticación para todos los usuarios en los niveles de privilegio "User", "Operator", y "Administrator". Todos los mecanismos de autenticación han sido deshabilitados para el nivel de privilegio

"Callback".

En términos generales, no querrá permitir que ningún usuario se autentique con None o Straight_Password por razones de seguridad. MD2 y MD5 son algoritmos de firma digital que pueden cifrar contraseñas mínimamente. Si ha elegido soportar el nombre de usuario NULL (User1 habilitado) y contraseñas NULL (contraseña NULL para User1), tendrá que habilitar los campos de autenticación None anteriores para permitir que los usuarios se conecten a través de No

ne
.

Sección

Lan_Conf_Misc

Esta sección lista opciones de configuración misceláneas de IPMI sobre LAN. Estas son opciones de configuración IPMI opcionales que no están implementadas en todos los

BMC.

Normalmente, un cliente no puede resolver la dirección MAC de ethernet sin el sistema operativo remoto en ejecución. Sin embargo, IPMI sobre LAN no funcionaría cuando una máquina esté apagada o si la dirección IP usada por el sistema operativo para esa interfaz de red difiere de la dirección IP del BMC. Una forma de solucionar esto es a través de ARPs gratuitos. Los ARPs gratuitos son paquetes ARP generados por el BMC y enviados para anunciar la dirección IP y MAC del BMC. Otras máquinas en la red pueden almacenar esta información en su caché ARP local para una posterior resolución de IP/nombre de host. Esto permitiría que IPMI sobre LAN funcione cuando la máquina remota esté apagada. La opción Enable_Gratuitous_Arps le permite habilitar o deshabilitar esta característica. La opción Gratuitous_Arp_Interval le permite configurar la frecuencia a la que se envían ARPs gratuitos a la

red.

En lugar de ARPs gratuitos, algunos BMC son capaces de responder a peticiones ARP, incluso cuando están apagados. Si se ofrece, esta característica puede habilitarse a través de la opción Enable_Arp_Response

.

En términos generales, activar los ARPs gratuitos es aceptable. Sin embargo, aumentará el tráfico en su red. Si está usando IPMI en un gran clúster, los ARPs gratuitos pueden inundar fácilmente su red. Deben ser ajustados para ocurrir con menos frecuencia o deshabilitados. Si se deshabilitan, la dirección MAC de la máquina remota debería almacenarse permanentemente en la caché ARP local a través de arp(8)

.

Vea bmc-watchdog(8) para un método que permite que los ARPs gratuitos se deshabiliten cuando

el sistema operativo esté en ejecución, pero se
habiliten cuando el sistema esté apagado.

Sección Rmcpplus_Conf_Privileg

e

Esta sección soporta la configuración de los IDs de suite de cifrado de IPMI 2.0 (incluyendo Serial-over-LAN). Si su máquina no soporta IPMI 2.0, los campos no serán

configurables.

Cada ID de suite de cifrado describe una combinación de un algoritmo de autenticación, un algoritmo de integridad y un algoritmo de cifrado para IPMI 2.0. El algoritmo de autenticación se usa para la autenticación de usuarios con el BMC. El algoritmo de integridad se usa para generar firmas en paquetes IPMI. El algoritmo de confidencialidad se usa para cifrar datos. La configuración en esta sección permite habilitar o deshabilitar ciertos IDs de suite de cifrado, y el nivel de privilegio máximo que un usnombre de usuario puede

autenticarse.

En general, los algoritmos basados en HMAC-SHA1 son más fuertes que los HMAC-MD5, que a su vez son mejores que los algoritmos MD5-128. Los algoritmos de confidencialidad AES-CBC-128 son más fuertes que los algoritmos xRC4-128, que son mejores que los algoritmos xRC4-40. Por lo tanto, el ID de suite de cifrado 3 se considera generalmente el más seguro. Algunos usuarios pueden desear asignar el ID de suite de cifrado 3 a un nivel de privilegio y deshabilitar todos los demás ID de suite de

cifrado.

La configuración de ejemplo anterior ha decidido permitir que cualquier usuario con privilegios de "Administrator" utilice cualquier conjunto de algoritmos de suite de cifrado que requiera un algoritmo de autenticación, integridad y confidencialidad. Generalmente, el nivel de privilegio máximo configurado para un nombre de usuario debe establecerse para al menos un ID de suite de cifrado. Generalmente, este es el privilegio "Administrator"

.

Se implementan opcionalmente varios ID de suit

e de cifrado, por lo que los ID de suite de ci
frado disponibles en su sistema pueden variar.

Sección

SOL_Conf

Esta sección es para configurar Serial-Over-Lan (SOL) y solo estará disponible para la configuración en esas máquinas. SOL se puede habilitar con el campo Enable_SOL. El nivel de privilegio mínimo requerido para conectarse con SOL se especifica mediante SOL_Privilege_Level. Este debe establecerse al nivel de privilegio máximo configurado para un nombre de usuario que tenga SOL habilitado. Generalmente, este es el privilegio "Administrator". La autenticación y el cifrado se pueden forzar o no utilizando los

campos

Force_SOL_Payload_Authentication y Force_SOL_Payload_Encryption respectivamente. Se recomienda que estos estén activados. Sin embargo, el soporte de autenticación y/o cifrado forzado depende de los ID de suite de cifrado soportados. Las opciones Character_Accumulate_Interval, Character_Send_Threshold, SOL_Retry_Count y SOL_Retry_Interval se utilizan para establecer las velocidades de salida de caracteres de SOL. Character_Accumulate_Interval determina con qué frecuencia se deben enviar regularmente los datos seriales y Character_Send_Threshold indica el recuento de caracteres que, si se supera, forzará el envío de los datos

seriales.

SOL_Retry_Count indica cuántas veces se deben retransmitir los paquetes si no se reciben acuses de recibo. SOL_Retry_Interval indica el intervalo de tiempo de espera. Generalmente, los números recomendados por el fabricante serán suficientes. Sin embargo, puede experimentar con estos valores para una mayor velocidad de SOL. Las opciones Non_Volatile_Bit_Rate y Volatile_Bit_Rate determinan la velocidad de baudios que debe usar el BMC. Esta debe coincidir con la velocidad de baudios establecida en el BIOS y el sistema operativo,

como

agetty(8). En general, las opciones Volat

y

Non_Volatile deben establecerse de forma

idéntica.
