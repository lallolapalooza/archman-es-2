IPMI-FRU(8) Comandos del Sistema IPMI-FRU(8)

NOMBRE

ipmi-fru - muestra información FRU

SINOPSIS

ipmi-fru [OPCIÓN...]

DESCRIPCIÓN

Ipmi-fru muestra Información de Unidad Reemplazable en Campo (FRU). La FRU puede contener una variedad de información, como información del dispositivo, información de hardware, números de serie y números de parte.

A continuación se enumeran las opciones generales de IPMI, las opciones específicas de la herramienta, la información de solución de problemas, la información de soluciones alternativas, ejemplos y problemas conocidos. Para una introducción general a FreeIPMI, consulte freeipmi(7).

OPCIONES GENERALES

Las siguientes opciones son generales para configurar la comunicación IPMI y ejecutar comandos generales de la herramienta.

-D CONTROLADOR_IPMI, --driver-type=CONTROLADOR_IPMI
Especifica el tipo de controlador a utilizar en lugar de realizar una selección automática. Los controladores externos disponibles actualmente son LAN y LAN_2_0, que realizan IPMI 1.5 e IPMI 2.0 respectivamente. Los controladores internos disponibles actualmente son KCS, SSIF, OPENIPMI, SUNBMC e INTELDCMI.
--disable-auto-probe
No sondear dispositivos IPMI internos en busca de configuraciones predeterminadas.
--driver-address=DIRECCION_CONTROLADOR
Especifica la dirección del controlador interno a utilizar en lugar del valor sondado. DIRECCION_CONTROLADOR debe ir precedida por "0x" para un valor hexadecimal y "0" para un valor octal.
--driver-device=DISPOSITIVO
Especifica la ruta del dispositivo del controlador interno a utilizar en lugar de la ruta sondada.
--register-spacing=ESPACIADO_REGISTRO
Especifica el espaciado de registros del controlador interno en lugar del valor sondado. El argumento está en bytes (es decir, espaciado de registro de 32 bits = 4)
--target-channel-number=NUMERO_CANAL
Especifica el número de canal de destino del controlador interno al que enviar las solicitudes IPMI.
--target-slave-address=DIRECCION_ESCLAVO
Especifica el número de esclavo de destino del controlador interno al que enviar las solicitudes IPMI.
-h HOSTIPMI1,HOSTIPMI2,..., --hostname=HOSTIPMI1[:PUERTO],HOSTIPMI2[:PUERTO],...
Especifica el(los) host(s) remotos(s) con los que comunicarse. Se pueden separar varios nombres de host por comas o especificarse en formato de rango; consulte SOPORTE DE RANGOS DE HOST a continuación. Se puede especificar un puerto opcional con cada host, lo que puede ser útil en situaciones de reenvío de puertos o similares. Si especifica una dirección IPv6 y un puerto, utilice el formato [DIRECCION]:PUERTO.
-u NOMBRE_USUARIO, --username=NOMBRE_USUARIO
Especifica el nombre de usuario a utilizar al autenticarse con el host remoto. Si no se especifica, se asume un nombre de usuario nulo (es decir, anónimo). El usuario debe tener al menos privilegios de USUARIO para que esta herramienta funcione completamente.
-p CONTRASENA, --password=CONTRASENA
Especifica la contraseña a utilizar al autenticarse con el host remoto. Si no se especifica, se asume una contraseña nula. La longitud máxima de la contraseña es 16 para IPMI 1.5 y 20 para IPMI 2.0.
-P, --password-prompt
Solicita la contraseña para evitar la posibilidad de incluirla en las listas de procesos.
-k CLAVE_K_G, --k-g=CLAVE_K_G
Especifica la clave K_g BMC a utilizar al autenticarse con el host remoto para IPMI 2.0. Si no se especifica, se asume una clave nula. Para introducir la clave en formato hexadecimal, prefije la cadena con "0x". Por ejemplo, la clave "abc" se puede introducir con la cadena "abc" o con la cadena "0x616263".
-K, --k-g-prompt
Solicita la clave k-g para evitar la posibilidad de incluirla en las listas de procesos.
--session-timeout=MILISEGUNDOS
Especifica el tiempo de espera de la sesión en milisegundos. El valor predeterminado es 20000 milisegundos (20 segundos) si no se especifica.
--retransmission-timeout=MILISEGUNDOS
Especifica el tiempo de espera de retransmisión de paquetes en milisegundos. El valor predeterminado es 1000 milisegundos (1 segundo) si no se especifica. El tiempo de espera de retransmisión no puede ser mayor que el tiempo de espera de la sesión.
-a TIPO_AUTENTICACION, --authentication-type=TIPO_AUTENTICACION
Especifica el tipo de autenticación IPMI 1.5 a utilizar. Los tipos de autenticación disponibles actualmente son NONE, STRAIGHT_PASSWORD_KEY, MD2 y MD5. El valor predeterminado es MD5 si no se especifica.
-I ID_SUITE_CIFRADO, --cipher-suite-id=ID_SUITE_CIFRADO
Especifica el ID de la suite de cifrado IPMI 2.0 a utilizar. El ID de la Suite de Cifrado identifica un conjunto de algoritmos de autenticación, integridad y confidencialidad a utilizar para la comunicación IPMI 2.0. El algoritmo de autenticación identifica el algoritmo a utilizar para la configuración de la sesión, el algoritmo de integridad identifica el algoritmo a utilizar para las firmas de paquetes de sesión y el algoritmo de confidencialidad identifica el algoritmo a utilizar para el cifrado de carga útil. El valor predeterminado es el ID de la suite de cifrado 3 si no se especifica. Los siguientes ID de suites de cifrado son compatibles actualmente:

0 - Algoritmo de Autenticación = Ninguno; Algoritmo de Integridad = Ninguno; Algoritmo de Confidencialidad = Ninguno

1 - Algoritmo de Autenticación = HMAC-SHA1; Algoritmo de Integridad = Ninguno; Algoritmo de Confidencialidad = Ninguno

2 - Algoritmo de Autenticación = HMAC-SHA1; Algoritmo de Integridad = HMAC-SHA1-96; Algoritmo de Confidencialidad = Ninguno

3 - Algoritmo de Autenticación = HMAC-SHA1; Algoritmo de Integridad = HMAC-SHA1-96; Algoritmo de Confidencialidad = AES-CBC-128

6 - Algoritmo de Autenticación = HMAC-MD5; Algoritmo de Integridad = Ninguno; Algoritmo de Confidencialidad = Ninguno

7 - Algoritmo de Autenticación = HMAC-MD5; Algoritmo de Integridad = HMAC-MD5-128; Algoritmo de Confidencialidad = Ninguno

8 - Algoritmo de Autenticación = HMAC-MD5; Algoritmo de Integridad = HMAC-MD5-128; Algoritmo de Confidencialidad = AES-CBC-128

11 - Algoritmo de Autenticación = HMAC-MD5; Algoritmo de Integridad = MD5-128; Algoritmo de Confidencialidad = Ninguno

12 - Algoritmo de Autenticación = HMAC-MD5; Algoritmo de Integridad = MD5-128; Algoritmo de Confidencialidad = AES-CBC-128

15 - Algoritmo de Autenticación = HMAC-SHA256; Algoritmo de Integridad = Ninguno; Algoritmo de Confidencialidad = Ninguno

16 - Algoritmo de Autenticación = HMAC-SHA256; Algoritmo de Integridad = HMAC_SHA256_128; Algoritmo de Confidencialidad = Ninguno

17 - Algoritmo de Autenticación = HMAC-SHA256; Algoritmo de Integridad = HMAC_SHA256_128; Algoritmo de Confidencialidad = AES-CBC-128

-l NIVEL_PRIVILEGIO, --privilege-level=NIVEL_PRIVILEGIO
Especifica el nivel de privilegio a utilizar. Los niveles de privilegio disponibles actualmente son USER, OPERATOR y ADMIN. El valor predeterminado es USER si no se especifica.
--config-file=ARCHIVO
Especifica un archivo de configuración alternativo.
-W SOLUCIONES_ALTERNATIVAS, --workaround-flags=SOLUCIONES_ALTERNATIVAS
Especifica soluciones alternativas para problemas de cumplimiento del proveedor. Se pueden especificar varias soluciones alternativas separadas por comas. Un indicador especial de línea de comandos de "none" indicará que no hay soluciones alternativas (puede ser útil para anular los valores predeterminados configurados). Consulte SOLUCIONES ALTERNATIVAS a continuación para obtener una lista de las soluciones alternativas disponibles.
--debug
Activa la depuración.
-?, --help
Muestra una lista de ayuda y sale.
--usage
Muestra un mensaje de uso y sale.
-V, --version
Muestra la versión del programa y sale.

OPCIONES DE RANGO DE

HOSTS

Las siguientes opciones manipulan la salida de rangos de hosts. Vea SOPORTE DE RANGO DE HOSTS más abajo para información adicional sobre rangos de

hosts.
-B, --buffer-out
put
Almacena en búfer la salida de rangos de hosts. Para cada nodo, almacena la salida estándar hasta que el nodo haya completado su operación IPMI. Al especificar esta opción, los datos pueden parecer mostrarse más lentos al usuario ya que la operación IPMI completa debe finalizar antes de que se pueda mostrar algún dato. Vea SOPORTE DE RANGO DE HOSTS más abajo para información
adicional.
-C, --consolidate-out
put
Consolida la salida de rangos de hosts. La salida estándar completa de cada nodo especificado se consolidará para que los nodos con salida idéntica no se muestren dos veces. Un encabezado listará aquellos nodos con la salida consolidada. Cuando se especifica esta opción, no se puede ver ninguna salida hasta que las operaciones IPMI a todos los nodos hayan finalizado. Si el usuario interrumpe el programa antes de tiempo, toda la salida consolidada actualmente se volcará. Vea SOPORTE DE RANGO DE HOSTS más abajo para información
adicional.
-F NUM, --fanout=NU
M
Especifica el fanout (distribución) de múltiples hosts. Se usa un algoritmo de "ventana deslizante" (o fanout) para la comunicación IPMI paralela de modo que los nodos más lentos o los nodos con tiempo de espera agotado no obstaculicen la comunicación paralela. El número máximo de hilos disponibles al mismo tiempo está limitado por el fanout. El valor por defecto es
64.
-E, --elimina
te
Elimina hosts determinados como no detectados por ipmidetect. Esto intenta eliminar el problema común de que la ejecución con rangos de hosts agote el tiempo de espera debido a que varios nodos han sido retirados del servicio en un gran clúster. El demonio ipmidetectd debe estar ejecutándose en el nodo que ejecuta el
comando.
--always-pre
fix
Siempre antepone el prefijo a la salida, incluso si solo se especifica un host o se comunica in-band. Esta opción es principalmente útil para propósitos de scripting. La opción se ignorará si se especifica con la opci
ón
-
C.

SOPORTE DE RANGO DE

HOSTS

Múltiples hosts pueden introducirse ya sea como listas explícitas de hosts separadas por comas o como un rango de nombres de host en la forma general: prefijo[n-m,l-k,...], donde n < m y l < k, etc. La última forma no debe confundirse con las clases de caracteres de expresiones regulares (también denotadas por []). Por ejemplo, foo[19] no representa foo1 o foo9, sino que representa un rango degenerado:

foo19.

Esta sintaxis de rangos está pensada solo como una conveniencia en clústeres con una convención de nombres prefijoNN y la especificación de rangos no debe considerarse necesaria -- la lista foo1,foo9 podría especificarse como tal, o por el rango foo[1,9]

.

Algunos ejemplos de uso de rangos a

continuación: 
    foo[01-05] en lugar de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] en lugar de foo7,foo9,foo10
    foo[0-3] en lugar de foo0,foo1,foo2,
foo3

Como recordatorio para el lector, algunos shells interpretarán los corchetes ([ y ]) para la coincidencia de patrones. Dependiendo de su shell, puede ser necesario encerrar las listas de rangos entre

comillas.

Cuando el usuario especifica múltiples hosts, se ejecutará un hilo para cada host en paralelo hasta el fanout configurado (que puede ajustarse mediante la opción -F). Esto permitirá la comunicación con un gran número de nodos mucho más rápidamente que si se hiciera en

serie.

Por defecto, la salida estándar de cada nodo especificado se mostrará con el nombre de host antepuesto a cada línea. Aunque esta salida es legible en muchas situaciones, puede ser difícil de leer en otras situaciones. Por ejemplo, la salida de múltiples nodos puede mezclarse. Las opciones -B y -C pueden usarse para cambiar este valor por

defecto.

Se usará la comunicación IPMI in-band cuando se especi

fica el host "localhost". Esto permite al usuario a
ñadir el localhost a la salida de rangos de hosts.

SOLUCIÓN DE PROBLEMAS

GENERAL

La mayoría de las veces, los problemas de IPMI se deben a problemas de

configuración.

Los problemas de IPMI sobre LAN implican una mala configuración del BMC de la máquina remota. Verifique dos veces para asegurarse de que lo siguiente está configurado correctamente en el BMC de la máquina remota: dirección IP, dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio LAN, habilitación LAN y tipo(s) de autenticación permitido(s). Para conexiones IPMI 2.0, verifique dos veces para asegurarse de que el/los privilegio(s) de la suite de cifrado y la clave K_g están configurados correctamente. La herramienta ipmi-config(8) puede usarse para verificar y/o cambiar estos ajustes de

configuración.

Los problemas de IPMI in-band típicamente son causados por controladores mal configurados o BMCs no

estándar.

Además de los consejos de solución de problemas siguientes, por favor vea SOLUCIONES ALTERNATIVAS más abajo para ver también si hay errores específicos del proveedor que hayan sido descubiertos y

solucionados.

A continuación se listan muchos de los problemas comunes para mensajes de error. Para soporte adicional, por favor envíe un correo a la lista de correo <freeipmi-users@gnu.org>

.

"username invalid" - El nombre de usuario introducido (o un nombre de usuario NULL si no se introdujo ninguno) no está disponible en la máquina remota. También es posible que la configuración del nombre de usuario del BMC remoto sea

incorrecta.

"password invalid" - La contraseña introducida (o una contraseña NULL si no se introdujo ninguna) no es correcta. También es posible que la contraseña del usuario no esté configurada correctamente en el BMC

remoto.

"password verification timeout" - La verificación de la contraseña ha agotado el tiempo de espera. Ocurrió un error "password invalid" (descrito arriba) o un "session timeout" genérico (descrito más abajo). Durante este punto del protocolo no se puede diferenciar cuál

ocurrió.

"k_g invalid" - La clave K_g introducida (o una clave K_g NULL si no se introdujo ninguna) no es correcta. También es posible que la clave K_g no esté configurada correctamente en el BMC

remoto.

"privilege level insufficient" - Un comando IPMI requiere un privilegio de usuario más alto que el con el que se autenticó. Por favor, intente autenticar con un privilegio más alto. Esto puede requerir autenticarse con un usuario diferente que tenga un privilegio máximo más

alto.

"privilege level cannot be obtained for this user" - El nivel de privilegio con el que intenta autenticar es más alto que el máximo permitidopara este usuario. Por favor, inténtelo de nuevo con un privilegio más bajo. También es posible que el nivel de privilegio máximo permitido para un usuario no esté configurado correctamente en el BMC

remoto.

"authentication type unavailable for attempted privilege level" - El tipo de autenticación con el que desea autenticar no está disponible para este nivel de privilegio. Por favor, inténtelo de nuevo con un tipo de autenticación alternativo o un nivel de privilegio alternativo. También es posible que los tipos de autenticación disponibles con los que puede autenticar no estén configurados correctamente en el BMC

remoto.

"cipher suite id unavailable" - El id de suite de cifrado con el que desea autenticar no está disponible en el BMC remoto. Por favor, inténtelo de nuevo con un id de suite de cifrado alternativo. También es posible que los ids de suite de cifrado disponibles no estén configurados correctamente en el BMC

remoto.

"ipmi 2.0 unavailable" - IPMI 2.0 no se descubrió en la máquina remota. Por favor, intente usar IPMI 1.5 en su

lugar.

"connection timeout" - La comunicación IPMI inicial falló. Hay varios errores potenciales posibles, incluyendo un nombre de host especificado no válido, una dirección IP de IPMI que no se puede resolver, IPMI no está habilitado en el servidor remoto, la conexión de red es deficiente, etc. Por favor, verifique la configuración y la

conectividad.

"session timeout" - La sesión IPMI ha expirado. Por favor, reconéctese. Si este error ocurre con frecuencia, es posible que desee aumentar el tiempo de espera de retransmisión. Algunos BMC remotos son considerablemente más lentos que

otros.

"device not found" - El dispositivo especificado no se pudo encontrar. Por favor, verifique la configuración o las entradas e inténtelo de

nuevo.

"driver timeout" - La comunicación con el controlador o el dispositivo ha expirado. Por favor, inténtelo de

nuevo.

"message timeout" - La comunicación con el controlador o el dispositivo ha expirado. Por favor, inténtelo de

nuevo.

"BMC busy" - El BMC está actualmente ocupado. Puede estar procesando información o tener demasiadas sesiones simultáneas para gestionar. Por favor, espere e inténtelo de

nuevo.

"could not find inband device" - No se pudo encontrar un dispositivo inband. Por favor, verifique la configuración o especifique un dispositivo o controlador específico en la línea de

comandos.

"driver timeout" - El controlador inband ha expirado comunicándose con el BMC o el procesador de servicio local. El BMC o el procesador de servicio puede estar ocupado o (en el peor de los casos) posiblemente no

funcionando.

"internal IPMI error" - Ha ocurrido un error de IPMI que Fre

eIPMI no sabe cómo manejar. Por favor, envíe un correo elect
rónico a <freeipmi-users@gnu.org> para reportar el problema.

SOLUCIONES

ALTERNATIVAS

Con tantos proveedores diferentes implementando sus propias soluciones IPMI, diferentes proveedores pueden implementar sus protocolos IPMI incorrectamente. A continuación se describen varias soluciones alternativas actualmente disponibles para manejar problemas de cumplimiento descubiertos. Cuando sea posible, se han implementado soluciones alternativas para que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se use una solución alternativa a través de la opción

-W.

El hardware listado a continuación puede solo indicar el hardware en el que se descubrió un problema. Las versiones más nuevas de hardware pueden corregir los problemas indicados a continuación. Máquinas similares de otros proveedores pueden o no exhibir los mismos problemas. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede ser útil probar las soluciones alternativas listadas a continuación incluso si su placa base no está

listada.

Si cree que su hardware tiene un problema de cumplimiento adicional que necesita que se implemente una solución alternativa, por favor, contacte a los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.org>

.

assumeio - Esta bandera de solución alternativa asumirá que las interfaces inband se comunican con las E/S del sistema en lugar de estar mapeadas en memoria. Esto solucionará sistemas que reportan direcciones base no válidas. Aquellos que se encuentren con este problema pueden ver errores "device not supported" o "could not find inband device". Problema observado en HP ProLiant DL145

G1.

spinpoll - Esta bandera de solución alternativa informará a algunos controladores inband (notablemente el controlador KCS) que giren mientras hacen sondeo en lugar de poner el proceso a dormir. Esto puede mejorar significativamente el tiempo de ejecución real de las herramientas porque la granularidad del planificador del sistema operativo puede ser mucho mayor que el tiempo que toma realizar una única transacción de mensaje IPMI. Sin embargo, al girar, su sistema puede estar realizando menos trabajo útil al no cambiar el contexto de la herramienta para una tarea más

útil.

authcap - Esta bandera de solución alternativa omitirá las verificaciones tempranas de capacidades de nombre de usuario, capacidades de autenticación y soporte de K_g, y permitirá que la autenticación IPMI tenga éxito. Soluciona múltiples problemas en los que el sistema remoto no reporta correctamente las capacidades de nombre de usuario, las capacidades de autenticación o el estado de K_g. Aquellos que se encuentren con este problema pueden ver errores "username invalid", "authentication type unavailable for attempted privilege level" o "k_g invalid". Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML, y Sun Fire 2200/4150/4450 con

ELOM.

nochecksumcheck - Esta bandera de solución alternativa le dirá a FreeIPMI que no verifique las sumas de verificación devueltas por las respuestas de los comandos IPMI. Soluciona sistemas que devuelven sumas de verificación no válidas debido a errores de implementación, pero el paquete es de otro modo válido. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina la validación de la integridad del paquete en varias circunstancias. Sin embargo, es improbable que sea un problema en la mayoría de las situaciones. Aquellos que se encuentren con este problema pueden ver errores "connection timeout", "session timeout" o "password verification timeout". En conexiones IPMI 1.5, la solución alternativa "noauthcodecheck" también puede ser necesaria. Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F, y Supermicro

X9DRFR.

idzero - Esta bandera de solución alternativa permitirá que el cliente acepte IDs de sesión vacíos. Soluciona sesiones IPMI que reportan IDs de sesión vacíos al cliente. Aquellos que se encuentren con este problema pueden ver errores "session timeout". Problema observado en Tyan S2882 con BMC

M3289.

unexpectedauth - Esta bandera de solución alternativa permitirá que los códigos de autenticación no nulos inesperados se verifiquen como si se esperaran. Soluciona un problema cuando los paquetes contienen datos de autenticación no nulos cuando deberían ser nulos debido a la autenticación por mensaje deshabilitada. Aquellos que se encuentren con este problema pueden ver errores "session timeout". Problema observado en Dell PowerEdge 2850, SC1425. Confirmado como corregido en firmware más

nuevo.

forcepermsg - Esta bandera de solución alternativa forzará el uso de la autenticación por mensaje sin importar lo que anuncie el sistema remoto. Soluciona un problema cuando la autenticación por mensaje se anuncia como deshabilitada en el sistema remoto, pero en realidad es requerida para el protocolo. Aquellos que se encuentren con este problema pueden ver errores "session timeout". Problema observado en IBM eServer

325.

endianseq - Esta bandera de solución alternativa invertirá el orden de bytes de los números de secuencia de sesión para permitir que la sesión continúe correctamente. Soluciona números de secuencia de sesión de IPMI 1.5 que tienen el orden de bytes incorrecto. Aquellos que se encuentren con este problema pueden ver errores "session timeout". Problema observado en algunos Sun ILOM 1.0/2.0 (depende del orden de bytes del procesador de servicio)

.

noauthcodecheck - Esta bandera de solución alternativa le dirá a FreeIPMI que no verifique los códigos de autenticación devueltos por las respuestas de los comandos IPMI 1.5. Soluciona sistemas que devuelven códigos de autenticación no válidos debido a errores de hashing o implementación. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina una verificación de autenticación que valida la integridad de un paquete. Sin embargo, en la mayoría de las organizaciones, es improbable que sea un problema de seguridad. Aquellos que se encuentren con este problema pueden ver errores "connection timeout", "session timeout" o "password verification timeout". Problema observado en Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell, y Wiwynn

Windmill.

intel20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación de IPMI 2.0 de Intel. Los problemas cubiertos incluyen el relleno de nombres de usuario y el truncamiento de contraseñas si el algoritmo de autenticación es HMAC-MD5-128. Aquellos que se encuentren con este problema pueden ver errores "username invalid", "password invalid" o "k_g invalid". Problema observado en Intel SE7520AF2 con Intel Server Management Module (Professional Edition)

.

supermicro20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación de IPMI 2.0 de Supermicro en placas base con firmware IPMI de Peppercon. Los problemas cubiertos incluyen el manejo de códigos de autenticación de longitud no válida. Aquellos que se encuentren con este problema pueden ver errores "password invalid". Problema observado en Supermicro H8QME con tarjeta hija SIMSO. Confirmado como corregido en firmware más

nuevo.

sun20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación de IPMI 2.0 de Sun. Los problemas cubiertos incluyen claves de hash de longitud no válida, claves hash incorrectamente calculadas y registros de suite de cifrado no válidos. Aquellos que se encuentren con este problema pueden ver errores "password invalid" o "bmc error". Problema observado en Sun Fire 4100/4200/4500 con ILOM. Esta solución alternativa incluye automáticamente la solución alternativa

"opensesspriv".

opensesspriv - Esta bandera de solución alternativa alterará ligeramente el protocolo de conexión IPMI 2.0 de FreeIPMI para solucionar un algoritmo de hashing no válido utilizado por el sistema remoto. El nivel de privilegio enviado durante la etapa de Apertura de Sesión de una conexión IPMI 2.0 se usa para calcular las claves de hash en lugar del nivel de privilegio enviado durante la etapa de conexión RAKP1. Aquellos que se encuentren con este problema pueden ver errores "password invalid", "k_g invalid", "bad rmcpplus status code" o "privilege level cannot be obtained for this user". Problema observado en Sun Fire 4100/4200/4500 con ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220, y el software BMC OpenIPMI. Esta solución alternativa se activa automáticamente con la solución alternativa

"sun20".

integritycheckvalue - Esta bandera de solución alternativa solucionará un valor de verificación de integridad no válido durante el establecimiento de una sesión IPMI 2.0 al usar el ID de Suite de Cifrado 0. El valor de verificación de integridad debería tener una longitud de 0, sin embargo la placa base remota responde con un campo no vacío. Aquellos que se encuentren con este problema pueden ver errores "k_g invalid". Problema observado en Supermicro X8DTG, Supermicro X8DTU, y Intel S5500WBV/Penguin Relion 700, y Intel S2600JF/Appro

512X.

assumemaxsdrrecordcount - Esta solución alternativa informará a la lectura de SDR que deje de leer después de que se hayan leído un número máximo conocido de registros SDR. Esto solucionará sistemas que tienen funciones de lectura de SDR mal implementadas. Aquellos que se encuentren con este problema pueden ver errores "SDR record count invalid". Problema observado en Inspur

motherboard.

skipchecks - Esta opción de solución temporal omitirá las comprobaciones de suma de verificación (checksum) de FRU. Algunos FRU tienen sumas de verificación incorrectas, pero los datos del FRU son correctos. Quienes se encuentren con este problema pueden ver errores de "checksum invalid" en su salida de FRU. La salida puede ser desconocida, oren por lo mejor. Se ha confirmado que esta opción soluciona problemas de cumplimiento en las placas base Inventec 5441/Dell Xanadu II, Dell Poweredge R610 y Dell Poweredge

R710.

Sin soporte para IPMI 1.5 - Se ha descubierto que algunas placas base que soportan IPMI 2.0 no soportan IPMI 1.5. Quienes se encuentren con este problema pueden ver errores de "ipmi 2.0 unavailable" o "connection timeout". Este problema se puede solucionar utilizando IPMI 2.0 en lugar de IPMI 1.5 especificando --driver-type=LAN_2_0. Este problema se ha observado en

un número de placas
base HP y Supermicro.

DIAGNÓSTICO

S

Tras una ejecución exitosa, el estado de salida es 0. En caso de error, el estado de salida es

1.

Si se especifican múltiples hosts para la comunicación, el e

stado de salida es 0 si y solo si todos los objetivos se ej
ecutan con éxito. De lo contrario, el estado de salida es 1.

PROBLEMAS

CONOCIDOS

En sistemas operativos antiguos, si introduce su nombre de usuario, contraseña y otra información potencialmente relevante para la seguridad en la línea de comandos, esta información puede ser descubierta por otros usuarios al usar herramientas como el comando ps(1) o al mirar en el sistema de archivos /proc. Generalmente es más seguro introducir la información de la contraseña con opciones como las opciones -P o -K. Configurar la información relevante para la seguridad en el archivo de configuración de FreeIPMI también sería una forma apropiada de ocultar esta

información.

Para prevenir ataques de fuerza bruta, algunos BMC se "bloquearán" temporalmente des

pués de un número de errores de autenticación remota. Puede que necesite esperar un
tiempo para que este bloqueo temporal pase antes de que pueda autenticarse de nuevo.
