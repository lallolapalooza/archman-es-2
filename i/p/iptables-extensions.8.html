hashlimit

hashlimit utiliza cubos hash para expresar una coincidencia de limitación de velocidad (como la coincidencia limit) para un grupo de conexiones que utilizan una **única** regla de iptables. La agrupación se puede hacer por grupo de hosts (dirección de origen y/o destino) y/o por puerto. Le da la capacidad de expresar "N paquetes por quantum de tiempo por grupo" o "N bytes por segundo" (vea a continuación algunos ejemplos).

Se requiere una opción de hash limit (--hashlimit-upto, --hashlimit-above) y --hashlimit-name.

--hashlimit-upto cantidad[/segundo|/minuto|/hora|/día]
Coincide si la tasa es inferior o igual a cantidad/quantum. Se especifica como un número, con un sufijo opcional de quantum de tiempo (el predeterminado es 3/hora), o como cantidadb/segundo (número de bytes por segundo).
--hashlimit-above cantidad[/segundo|/minuto|/hora|/día]
Coincide si la tasa está por encima de cantidad/quantum.
--hashlimit-burst cantidad
Número máximo inicial de paquetes para coincidir: este número se recarga una vez cada vez que no se alcanza el límite especificado anteriormente, hasta este número; el valor predeterminado es 5. Cuando se solicita una coincidencia de tasa basada en bytes, esta opción especifica la cantidad de bytes que pueden exceder la tasa dada. Esta opción debe usarse con precaución: si la entrada caduca, el valor de ráfaga también se restablece.
--hashlimit-mode {srcip|srcport|dstip|dstport},...
Una lista de objetos separados por comas a tener en cuenta. Si no se proporciona ninguna opción --hashlimit-mode, hashlimit actúa como limit, pero a costa de realizar la gestión de hash.
--hashlimit-srcmask prefijo
Cuando se utiliza --hashlimit-mode srcip, todas las direcciones de origen encontradas se agruparán según la longitud del prefijo dada y la subred creada de este modo estará sujeta a hashlimit. prefijo debe estar entre (inclusive) 0 y 32. conntrack

This module matches IP packets based on connection tracking state. It is only available if the kernel module nf_conntrack is loaded.

[!] --ctstate statelist
Matches if the packet is in any of the states in statelist. statelist is a comma-separated list of keywords. Known states are:
INVALID
The packet is not recognized by the conntrack subsystem.
UNTRACKED
The packet is not tracked at all.
UNKNOWN
The packet is tracked, but the state is unknown.
FRAGMENTS
The packet is part of a fragment that has not been reassembled yet.
{
Matches packets for new connections. The first packet of a connection.
ESTABLISHED
Matches packets that are part of an already existing connection.
RELATED
Matches packets that are related to an existing connection, but are not part of it. For example, FTP data connections.
B
Matches packets that are part of an already existing connection.
D
Matches packets that are part of a connection that is already established.
[!] --ctproto protocol
Matches if the protocol of the packet is one of the specified protocols. The protocol must be specified by name (e.g. tcp, udp, icmpv6) or by number.
[!] --ctsource address[/mask]
Matches if the source address is one of the specified addresses.
[!] --ctdestination address[/mask]
Matches if the destination address is one of the specified addresses.
[!] --ct-timeout value
Matches if the connection timeout is less than or equal to the specified value. Unit is seconds.
[!] --ct-timeout-mask value
Matches if the connection timeout is less than or equal to the specified value. Unit is seconds. The value is treated as a mask.
[!] --ct-expect-timeout value
Matches if the expected connection timeout is less than or equal to the specified value. Unit is seconds.
[!] --ct-expect-timeout-mask value
Matches if the expected connection timeout is less than or equal to the specified value. Unit is seconds. The value is treated as a mask.
[!] --ct-loose-match
This is only used in the mangle table. Match packets that are related to an existing connection.
[!] --ct-mark mark[/mask]
Matches if the firewall mark is set.
[!] --ct-notrack
Matches if the packet is not tracked.
[!] --ct-layer3 proto
Matches the layer 3 protocol.
[!] --ct-layer4 proto
Matches the layer 4 protocol.

You can specify more than one address, protocol, timeout, mark or state. If you specify more than one, it is implicitly an OR operation.

iptables -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -p tcp --ctsource 192.168.1.0/24 -j ACCEPT

Este objetivo se puede usar para identificar cuándo las interfaces han estado inactivas durante un cierto período de tiempo. Este es el tiempo en segundos que activará la notificación.
--label string

Activa el registro en el kernel de los paquetes coincidentes. MASQUERADE

Este objetivo solo es válido en la tabla nat, en la cadena POSTROUTING. Solo debe usarse con conexiones IP asignadas dinámicamente (conexiones dial-up): si tienes una dirección IP estática, debes usar el objetivo SNAT. Masquerading es equivalente a especificar un mapeo a la dirección IP de la interfaz de salida del paquete, pero también tiene el efecto de que las conexiones se olvidan cuando la interfaz se cae. Este es el comportamiento correcto cuando es poco probable que la siguiente conexión dial-up tenga la misma dirección de interfaz (y, por lo tanto, se pierden todas las conexiones establecidas de todos modos).

Esto especifica un rango de puertos de origen a usar, reemplazando las heurísticas de selección de puertos de origen SNAT predeterminadas (ver arriba). Esto solo es válido si la regla también especifica uno de los siguientes protocolos: tcp, udp, dccp o sctp.
--random
Aleatoriza el mapeo del puerto de origen (kernel >= 2.6.21). Desde el kernel 5.0, --random es idéntico a --random-fully.
--random-fully
Aleatoriza completamente el mapeo del puerto de origen (kernel >= 3.13).

NFLOG

Este objetivo proporciona registro de paquetes coincidentes. Cuando se establece este objetivo para una regla, el kernel de Linux pasará el paquete al backend de registro cargado para registrar el paquete. Esto se usa generalmente en combinación con nfnetlink_log como backend de registro, que transmitirá en multidifusión el paquete a través de un socket de netlink al grupo de multidifusión especificado. Uno o más procesos del espacio de usuario pueden suscribirse al grupo para recibir los paquetes. Al igual que LOG, este es un objetivo que no termina, es decir, la travesía de reglas continúa en la siguiente regla.

--nflog-group nlgroup
El grupo netlink (0–2^16-1) al que se envían los paquetes (solo aplicable para nfnetlink_log). El valor predeterminado es 0.
--nflog-prefix prefijo
Una cadena de prefijo para incluir en el mensaje de registro, de hasta 64 caracteres de longitud, útil para distinguir mensajes en los registros.
--nflog-range tamaño
Esta opción nunca ha funcionado, use --nflog-size en su lugar
--nflog-size tamaño
El número de bytes que se copiarán al espacio de usuario (solo aplicable para nfnetlink_log). Las instancias de nfnetlink_log pueden especificar su propio rango, esta opción lo anula.
--nflog-threshold tamaño
Número de paquetes a poner en cola dentro del kernel antes de enviarlos al espacio de usuario (solo aplicable para nfnetlink_log). Valores más altos resultan en menos sobrecarga por paquete, pero aumentan el retraso hasta que los paquetes llegan al espacio de usuario. El valor predeterminado es 1.

NFQUEUE

Este objetivo pasa el paquete al espacio de usuario utilizando el manejador nfnetlink_queue. El paquete se coloca en la cola identificada por su número de cola de 16 bits. El espacio de usuario puede inspeccionar y modificar el paquete si lo desea. El espacio de usuario debe entonces descartar o reinyectar el paquete en el kernel. Consulte libnetfilter_queue para obtener detalles. nfnetlink_queue se agregó en Linux 2.6.14. La opción queue-balance se agregó en Linux 2.6.31, queue-bypass en 2.6.39.

--queue-num valor
Esto especifica el número de COLA a utilizar. Los números de cola válidos son de 0 a 65535. El valor predeterminado es 0.
--queue-balance valor:valor
Esto especifica un rango de colas a utilizar. Luego, los paquetes se equilibran entre las colas dadas. Esto es útil para sistemas multinúcleo: inicie múltiples instancias del programa de espacio de usuario en las colas x, x+1, .. x+n y use "--queue-balance x:x+n". Los paquetes que pertenecen a la misma conexión se colocan en la misma nfqueue. Debido a detalles de implementación, un valor de rango inferior de 0 limita el valor de rango superior a 65534, es decir, solo se puede equilibrar entre un máximo de 65535 colas.
--queue-bypass
Por defecto, si ningún programa de espacio de usuario está escuchando en una NFQUEUE, todos los paquetes que deben encolarse se descartan. Cuando se usa esta opción, la regla NFQUEUE se comporta como ACCEPT en su lugar, y el paquete pasará a la siguiente tabla.
--queue-cpu-fanout
Disponible a partir del kernel de Linux 3.10. Cuando se usa junto con --queue-balance, utilizará la ID de CPU como índice para mapear paquetes a las colas. La idea es que se puede mejorar el rendimiento si hay una cola por CPU. Esto requiere que se especifique --queue-balance.

REJECT (específico de IPv6)

Esto se utiliza para enviar un paquete de error en respuesta al paquete coincidente: de lo contrario, es equivalente a DROP, por lo que es un OBJETIVO que termina la coincidencia, finalizando la travesía de la regla. Este objetivo solo es válido en las cadenas INPUT, FORWARD y OUTPUT, y en las cadenas definidas por el usuario que solo se llaman desde esas cadenas. La siguiente opción controla la naturaleza del paquete de error devuelto:

--reject-with tipo
El tipo dado puede ser icmp6-no-route, no-route, icmp6-adm-prohibited, adm-prohibited, icmp6-addr-unreachable, addr-unreach, o icmp6-port-unreachable, que devuelven el mensaje de error ICMPv6 apropiado (icmp6-port-unreachable es el predeterminado). Finalmente, la opción tcp-reset se puede usar en reglas que solo coinciden con el protocolo TCP: esto hace que se envíe un paquete TCP RST de vuelta. Esto es principalmente útil para bloquear sondas de ident (113/tcp) que ocurren con frecuencia al enviar correo a hosts de correo defectuosos (que de lo contrario no aceptarán su correo). tcp-reset solo se puede usar con versiones del kernel 2.6.14 o posteriores.

Advertencia: No debe aplicar indiscriminadamente el objetivo REJECT a paquetes cuyo estado de conexión se clasifica como INVALID; en su lugar, solo debe descartarlos.

Considere un host de origen que transmite un paquete P, con P experimentando tanta demora en su ruta que el host de origen emite una retransmisión, P_2, con P_2 logrando llegar a su destino y avanzando el estado de la conexión normalmente. Es concebible que el P que llega tarde pueda considerarse que no está asociado con ninguna entrada de seguimiento de conexión. La generación de una respuesta de rechazo para un paquete clasificado de esa manera terminaría la conexión saludable.

Por lo tanto, en lugar de:

-A INPUT ... -j REJECT

considere usar:

-A INPUT ... -m conntrack --ctstate INVALID -j DROP
-A INPUT ... -j REJECT

SNAT

Este objetivo solo es válido en la tabla nat, en las cadenas POSTROUTING e INPUT, y en cadenas definidas por el usuario que solo se llaman desde esas cadenas. Especifica que la dirección de origen del paquete debe modificarse (y todos los paquetes futuros en esta conexión también serán manipulados), y que las reglas deben dejar de examinarse. Toma las siguientes opciones:

--to-source [ipaddr[-ipaddr]][:puerto[-puerto]]
que puede especificar una sola nueva dirección IP de origen, un rango inclusivo de direcciones IP. --random-fully

SNPT (Específico de IPv6)

--src-pfx [prefijo/longitud]

--dst-pfx [prefijo/longitud]
Establece el prefijo de destino que desea usar en la traducción y la longitud

SYNPROXY

Este objetivo procesará el handshake de tres vías TCP en el contexto de netfilter para proteger el sistema local o el backend. Este objetivo requiere seguimiento de conexiones porque los números de secuencia deben traducirse. La capacidad del kernel para absorber SYNFLOOD mejoró enormemente a partir de Linux 4.4, por lo que este objetivo ya no debería ser necesario para proteger servidores Linux.

--mss tamaño_segmento_máximo
Tamaño máximo de segmento anunciado a los clientes. Esto debe coincidir con el backend.
--wscale escala_ventana
Escala de ventana anunciada a los clientes. Esto debe coincidir con el backend.
--sack-perm
Pasa la opción de acuse de recibo selectivo del cliente al backend (se deshabilitará si no está presente).
--timestamps
Pasa la opción de marca de tiempo del cliente al backend (se deshabilitará si no está presente, también es necesaria para el acuse de recibo selectivo y la escala de ventana).

TCPMSS

Este objetivo modifica el valor MSS de los paquetes SYN TCP, para controlar el tamaño máximo para esa conexión (generalmente limitándolo a la MTU de su interfaz de salida menos 40 para IPv4 o 60 para IPv6, respectivamente). Por supuesto, solo se puede usar junto con -p tcp.

Este objetivo se utiliza para superar ISPs o servidores criminalmente estúpidos que bloquean los paquetes "ICMP Fragmentation Needed" o "ICMPv6 Packet Too Big". Los síntomas de este problema son que todo funciona bien desde su firewall/router Linux, pero las máquinas detrás de él nunca pueden intercambiar paquetes grandes:

1.
Los navegadores web se conectan, luego se cuelgan sin recibir datos.
2.
El correo pequeño funciona bien, pero el correo grande se cuelga.
3.
ssh funciona bien, pero scp se cuelga después del handshake inicial.

Solución alternativa: active esta opción y agregue una regla a la configuración de su firewall como:


iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN
-j TCPMSS --clamp-mss-to-pmtu
--set-mss valor

--clamp-mss-to-pmtu

Este objetivo marca los paquetes para que el núcleo registre cada regla que coincida con los paquetes a medida que estos recorren las tablas, cadenas y reglas. Solo puede usarse en la tabla r

aw.

Con iptables-legacy, un backend de registro, como ip(6)t_LOG o nfnetlink_log, debe estar cargado para que esto sea visible. Los paquetes se registran con el prefijo de cadena: "TRACE: tablename:chainname:type:rulenum " donde type puede ser "rule" para una regla simple, "return" para una regla implícita al final de una cadena definida por el usuario, y "policy" para la política de las cadenas

incorporadas.

Este es el predecesor obsoleto y solo para IPv4 del objetivo NFLOG. Proporciona registro en el espacio de usuario de los paquetes que coinciden.
