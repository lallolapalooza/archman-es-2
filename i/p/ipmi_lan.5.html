ipmi_lan(5) Archivo de configuración de la interfaz IPMI LAN ipmi_lan(5)

NOMBRE

ipmi/lan.conf - Archivo de configuración de la interfaz IPMI LAN

SINOPSIS

/etc/ipmi/lan.conf

DESCRIPCIÓN

Los comandos ipmi_sim e ipmilan se configuran utilizando este archivo de configuración.

ELEMENTOS DE CONFIGURACIÓN

Los siguientes campos se utilizan en muchos comandos:

booleano Puede ser "verdadero", "falso", "encendido" u "apagado".

priv Un nivel de privilegio de IPMI. Puede ser "callback", "usuario", "operador" o "admin".

auth Un tipo de autorización IPMI. Puede ser "none" para ninguna autenticación, "straight" para autenticación de contraseña directa, sin cifrar, "md2" para usar autenticación de resumen de mensajes MD2, o "md5" para usar autenticación de resumen de mensajes MD5.

ESTRUCTURA DEL ARCHIVO

Las líneas en blanco y las líneas que comienzan con `#` se ignoran.

Los siguientes comandos están permitidos en el archivo de configuración:

nombre "nombre"
Establece un nombre para el BMC. Esto controlará otras cosas, como el valor predeterminado del archivo de comandos de inicio de ipmi_sim y el lugar donde se almacenan los datos persistentes.
usuario número_usuario habilitado nombre_usuario contraseña priv_max sesiones_max
número_usuario especifica el número de usuario para el usuario. Tenga en cuenta que el número de usuario 0 no es válido, y el número de usuario 1 es el usuario especial "anónimo", cuyo nombre de usuario se ignora. Este valor puede ser hasta 63, el usuario IPMI máximo posible. Si desea acceso anónimo, debe tener un número de usuario 1.

habilitado es un booleano que especifica si el usuario está habilitado o no.

nombre_usuario especifica el nombre del usuario, definido como un nombre.

contraseña especifica la contraseña del usuario, definida como un nombre.

priv_max especifica el nivel máximo de privilegio permitido para el usuario.

sesiones_max especifica el número máximo de sesiones que el usuario puede abrir.

cmd_inicio "comando"
especifica un comando a ejecutar cuando se solicita un encendido. Esto permite iniciar una máquina virtual que luego puede conectarse al simulador. El simulador gestiona el proceso aquí, y el estado de encendido del proceso depende de si el proceso existe o no. Si se solicita un apagado, si el proceso está conectado a una interfaz serie de VM, se solicita primero un apagado elegante. Si el proceso no termina en un período de tiempo especificado, se envía una señal SIGTERM al proceso. La señal SIGTERM se envía inmediatamente si no hay conexión. Si el proceso no desaparece en otro período de tiempo especificado, se envía una señal SIGKILL.
inicio_ahoraverdadero|falso
Si es verdadero, inicia el `cmd_inicio` al iniciar el simulador. De lo contrario, espera hasta que se emita un encendido.
espera_apagado segundos
especifica la cantidad de tiempo a esperar para que `cmd_inicio` realice un apagado elegante en una solicitud de apagado. El simulador enviará una solicitud al destino, esperará esta cantidad de tiempo y luego realizará un `kill` SIGTERM en el proceso. Si es cero, no se realizará SIGTERM (ni SIGKILL). Tenga en cuenta que si el simulador no tiene una conexión con la VM, se omitirá el apagado elegante y se enviará un SIGTERM inmediatamente. El tiempo predeterminado es de 60 segundos.
espera_kill segundos
especifica la cantidad de tiempo a esperar para que SIGTERM finalice el proceso. Si el proceso no termina en este período de tiempo, se enviará un `kill` SIGKILL. Si es cero, no se enviará SIGKILL. El tiempo predeterminado es de 20 segundos.
consola dirección puerto
especifica que se abra un puerto de consola en la dirección y el puerto dados. Puede conectarse a la consola mediante telnet y ejecutar comandos de emulación. Tenga en cuenta que este es un agujero de seguridad bastante grande, solo debe usarse para depuración en un entorno controlado.
serie canal dir puerto [opción [opción [...]]]
canal especifica el número o tipo de canal. Puede ser kcs, smic, o bt o puede ser 15. Actualmente, solo se soporta el canal de interfaz del sistema (canal 15) para interfaces serie; si se especifican otros, es el canal 15 y la interfaz dada se informa en los comandos de configuración del canal.

dir especifica la dirección IP en la que escuchar las conexiones.

puerto especifica el puerto en el que escuchar las conexiones.

Las opciones válidas son:

nombre_codec especifica qué codec usar en el puerto serie. Las opciones válidas son: TerminalMode, Direct, RadisysAscii y VM. Los tres primeros son implementaciones de interfaces serie IPMI en ciertos sistemas y podrían usarse para simulaciones de ese sistema. VM es probablemente la más interesante; está diseñada para usarse con una máquina virtual como qemu.

nombre_oem especifica la implementación de algunos comandos y opciones personalizados de OEM en la interfaz. Las opciones válidas son PigeonPoint y Radisys.

attn c1[,c2[...]] especifica una lista de caracteres, separados por comas, para usar como carácter de atención en la interfaz. Generalmente, el valor predeterminado es correcto. Los caracteres se especifican como dígitos decimales, octales o hexadecimales en estilo C.

dir_ipmb especifica la dirección IPMI de la interfaz. El valor predeterminado, 0x20, suele ser correcto, pero cuando se emulan sistemas ATCA, esto podría ser necesario.

sol dispositivo baud_predet [history=tamaño[,archivo_respaldo=nombre_archivo]] [historyfru=num_fru]

Permite una conexión Serial Over LAN (SOL) al dispositivo dado. Esto será a través de la interfaz 1 para el MC.

dispositivo es la ruta completa al nombre del dispositivo. También puede tener el formato "tcp:dirección:puerto" o "telnet:dirección:puerto" para realizar conexiones a través de tcp (con o sin procesamiento telnet). Esto es útil para proporcionar acceso SOL a puertos qemu.

baud_predet establece la velocidad en baudios predeterminada inicial a usar. Esto se anula con la configuración SOL persistente.

history crea un dispositivo de historial en la interfaz SOL 2. El tamaño es el tamaño del búfer. Los datos del dispositivo se almacenan en el búfer de historial todo el tiempo. Conectarse a la interfaz SOL 2 provocará que se vuelque todo el búfer de historial. Si se especifica archivo_respaldo, el historial se vuelve persistente. Sin embargo, solo se almacena cuando se realiza una señal capturable o un apagado normal, por lo que un apagado forzado o una señal fatal provocarán la pérdida de datos.

historyfru hace que el historial esté disponible a través del número de FRU dado en el MC.

Tenga en cuenta que si la conexión falla al establecerse, el simulador seguirá intentando conectarse. De esta manera, puede arreglar puertos serie UDP o sesiones qemu y se reconectará automáticamente.

cargar_lib "modulo" ["opciones"]

Carga el objeto compartido dado en el programa.

modulo es la ruta completa al módulo. Debe estar entre comillas.

opciones es una cadena opcional entre comillas que pasa opciones al módulo. El contenido de la cadena no se especifica, el módulo lo define.

NAME

ipmi_lan.conf — IPMI LAN configuration file format

SYNOPSIS

/etc/ipmi_lan.conf

DESCRIPTION

The ipmi_lan.conf file is used to configure the IPMI LAN interfaces for the ipmi_sim simulator. This file contains configuration items that are processed by the ipmi_sim daemon.

The file is divided into sections. There are global configuration items and then sections for each LAN interface.

CONFIGURATION ITEMS

The following configuration items are supported:

module module_name
Specifies the module to load. Only one module may be loaded. The module must implement the functions described below.
module_param name=value
Passes a parameter to the loaded module. The module may print it's version. You must provide this function.
ipmi_sim_module_init(sys_data_t *sys, char *options)
is called after the configuration file is read and before any other initialization is done. The module should do most of its initialization here. You must provide this function.
ipmi_sim_module_post_init(sys_data_t *sys)
is called after ipmi_sim has finished initializing. This function is optional.

sys parameter is used for most functions interfacing to the main ipmi_sim code, like logging, timers, and a few of the MC calls. The contents are opaque to the module.

startlan channel
Starts a LAN configuration area. This specifies the settings for a LAN connection using the given channel. This may be specified more than once in a file to support multiple LAN connections. Commands following this, up to endlan, are LAN-specific commands listed below. channel specifies the channel to set the LAN configuration for.

LAN CONFIGURATION COMMANDS

The following commands are only valid inside a startlen area.

addr IP-address [UDP-port]
IP-address specifies the IP address to use for an IP port. Up to 4 addresses may be specified. If no address is specified, it defaults to one port at 0.0.0.0 (for every address on the machine) at port 623.

UDP-port specifies an optional port to listen on. It defaults to 623 (the standard port).

PEF_alerting boolean
Turn PEF alerting on or off (not currently supported).
per_msg_auth boolean
Turn per-message authentication on or off.
priv_limit priv
The maximum privilege allowed on this interface.
allowed_auths_callback [auth [auth [...]]]
auth specifies allowed authorization levels for the callback privilege level. Only the levels specified on this line are allowed for the authorization level. If this line is not present, callback authorization cannot be used.
allowed_auths_user [auth [auth [...]]]
auth specifies allowed authorization levels for the user privilege level. Only the levels specified on this line are allowed for the authorization level. If this line is not present, user authorization cannot be used.
allowed_auths_operator [auth [auth [...]]]
auth specifies allowed authorization levels for the operator privilege level. Only the levels specified on this line are allowed for the authorization level. If this line is not present, operator authorization cannot be used.
allowed_auths_admin [auth [auth [...]]]
auth specifies allowed authorization levels for the admin privilege level. Only the levels specified on this line are allowed for the authorization level. If this line is not present, user authorization cannot be used.
guid name
Allows the 16-byte GUID for the IPMI LAN connection to be specified. If this is not specified, then the GUID command is not supported.

FILES

/etc/ipmi_lan.conf
