Soporte de tipo VLAN
Para un enlace de tipo VLAN se admiten los siguientes argumentos adicionales:

ip link add link DEVICE name NAME type vlan [ protocol VLAN_PROTO ] id VLANID [ reorder_hdr { on | off } ] [ gvrp { on | off } ] [ mvrp { on | off } ] [ loose_binding { on | off } ] [ bridge_binding { on | off } ] [ ingress-qos-map QOS-MAP ] [ egress-qos-map QOS-MAP ]


protocol VLAN_PROTO - 802.1Q o 802.1ad.

id VLANID - especifica el Identificador VLAN a usar. Tenga en cuenta que los números con un prefijo "0" u "0x" se interpretan como octales o hexadecimales, respectivamente.

reorder_hdr { on | off } - especifica si las cabeceras Ethernet se reordenan o no (el valor predeterminado es on).


Si reorder_hdr está on, la cabecera VLAN no se insertará inmediatamente, sino solo antes de pasar al dispositivo físico (si este dispositivo no soporta descarga VLAN). Lo mismo ocurre en la dirección RX: por defecto, el paquete se desetiquetará antes de ser recibido por el dispositivo VLAN. La reordenación permite acelerar el etiquetado en la salida y ocultar la cabecera VLAN en la entrada, de modo que el paquete parezca un paquete Ethernet normal, pero puede ser confuso para la captura de paquetes ya que la cabecera VLAN no existe dentro del paquete.

La descarga VLAN se puede comprobar con ethtool(8):

ethtool -k <phy_dev> | grep tx-vlan-offload


donde <phy_dev> es el dispositivo físico al que está enlazado el dispositivo VLAN.

gvrp { on | off } - especifica si esta VLAN debe registrarse utilizando el Protocolo de Registro de VLAN GARP.

mvrp { on | off } - especifica si esta VLAN debe registrarse utilizando el Protocolo de Registro de VLAN Múltiple.

loose_binding { on | off } - especifica si el estado del dispositivo VLAN está enlazado al estado del dispositivo físico.

bridge_binding { on | off } - especifica si el estado del enlace del dispositivo VLAN sigue el estado de los puertos del puente que son miembros de la VLAN.

ingress-qos-map QOS-MAP - define un mapeo del campo de prioridad de la cabecera VLAN a la prioridad interna de paquetes de Linux en los tramas entrantes. El formato es DE:A con múltiples mapeos separados por espacios.

egress-qos-map QOS-MAP - define un mapeo de la prioridad interna de paquetes de Linux al campo de prioridad de la cabecera VLAN, pero para tramas salientes. El formato es el mismo que para ingress-qos-map.

La prioridad de paquetes de Linux se puede establecer con iptables(8):

iptables -t mangle -A POSTROUTING [...] -j CLASSIFY --set-class 0:4


y esta prioridad "4" se puede usar en el mapeo QoS de salida para establecer la prioridad VLAN "5":


ip link set veth0.10 type vlan egress 4:5


Soporte de tipo VXLAN
Para un enlace de tipo VXLAN se admiten los siguientes argumentos adicionales:

ip link add DEVICE type vxlan id VNI [ dev PHYS_DEV ] [ { group | remote } IPADDR ] [ local { IPADDR | any } ] [ ttl TTL ] [ tos TOS ] [ df DF ] [ flowlabel FLOWLABEL ] [ dstport PORT ] [ srcport MIN MAX ] [ reserved_bits VALUE ] [ [no]learning ] [ [no]proxy ] [ [no]rsc ] [ [no]l2miss ] [ [no]l3miss ] [ [no]udpcsum ] [ [no]udp6zerocsumtx ] [ [no]udp6zerocsumrx ] [ [no]localbypass ] [ ageing SECONDS ] [ maxaddress NUMBER ] [ [no]external ] [ gbp ] [ gpe ] [ [no]vnifilter ] [ [no]mcroute ]


id VNI - especifica el Identificador de Red VXLAN (o Identificador de Segmento VXLAN) a usar.

dev PHYS_DEV - especifica el dispositivo físico a usar para la comunicación del punto final del túnel.

group IPADDR - especifica la dirección IP multicast a la que unirse. Este parámetro no puede especificarse con el parámetro remote.

remote IPADDR - especifica la dirección IP de destino unicast a usar en los paquetes salientes cuando la dirección de capa de enlace de destino no se conoce en la base de datos de reenvío del dispositivo VXLAN. Este parámetro no puede especificarse con el parámetro group.

local IPADDR - especifica la dirección IP de origen a usar en los paquetes salientes.

ttl TTL - especifica el valor TTL a usar en los paquetes salientes.

tos TOS - especifica el valor TOS a usar en los paquetes salientes.

df DF - especifica el uso del bit de la bandera "Don't Fragment" (DF) en los paquetes salientes con cabeceras IPv4. El valor inherit hace que el bit se copie de la cabecera IP original. Los valores unset y set hacen que el bit se establezca o se elimine siempre, respectivamente. Por defecto, el bit no se establece.

flowlabel FLOWLABEL - especifica la etiqueta de flujo a usar en los paquetes salientes.

dstport PORT - especifica el puerto de destino UDP a usar para comunicarse con el punto final del túnel VXLAN remoto.

srcport MIN MAX - especifica el rango de números de puerto a usar como puertos de origen UDP para comunicarse con el punto final del túnel VXLAN remoto.

reserved_bits VALUE - por defecto, el kernel rechaza los paquetes que tienen bits establecidos fuera de los campos requeridos por las características habilitadas en el netdevice VXLAN. reserved_bits es una cantidad de 64 bits que especifica qué bits deben ser posibles de establecer en una cabecera VXLAN. Cada bit establecido en el valor es un bit tolerado establecido en un paquete.

[no]learning - especifica si las direcciones de capa de enlace de origen y las direcciones IP desconocidas se introducen en la base de datos de reenvío del dispositivo VXLAN.

[no]rsc - especifica si el acortamiento de ruta (route short circuit) está activado.

[no]proxy - especifica si el proxy ARP está activado.

[no]l2miss - especifica si se generan notificaciones de falta de LLADDR de netlink.

[no]l3miss - especifica si se generan notificaciones de falta de ADDR IP de netlink.

[no]udpcsum - especifica si se calcula la suma de control UDP para los paquetes transmitidos sobre IPv4.

[no]udp6zerocsumtx - omite el cálculo de la suma de control UDP para los paquetes transmitidos sobre IPv6.

[no]udp6zerocsumrx - permite paquetes UDP entrantes sobre IPv6 con campo de suma de control cero.

[no]localbypass - si el destino FDB es local, con nolocalbypass activado, reenvía los paquetes encapsulados a la pila de red del espacio de usuario. Si hay un proceso en el espacio de usuario escuchando estos paquetes, tendrá la oportunidad de procesarlos. Si localbypass está activo (por defecto), se omite la pila de red del kernel y se inyectan los paquetes en el dispositivo VXLAN de destino, asumiendo que existe uno.

ageing SECONDS - especifica la vida útil en segundos de las entradas FDB aprendidas por el kernel.

maxaddress NUMBER - especifica el número máximo de entradas FDB.

[no]external - especifica si se debe usar un plano de control externo (por ejemplo, ip route encap) o la FDB interna.

[no]vnifilter - especifica si el dispositivo vxlan es capaz de filtrar VNI. Solo funciona con un dispositivo vxlan con el flag externo activado. una vez habilitado, se utiliza el comando bridge vni para gestionar la tabla de filtrado VNI en el dispositivo. El dispositivo solo puede recibir paquetes con VNI configurados en la tabla de filtrado VNI.

[no]mcroute - cuando el túnel VXLAN tiene un destino multicast, si los paquetes de la capa subyacente deben

deben enviarse directamente al dispositivo físico (el valor predeterminado), o si deben ser enrutados por multicast. En este último caso, para los fines de coincidir con una ruta multicast, (S,G) son, respectivamente, la dirección local y remota del túnel, y iif es el dispositivo físico

del túnel.

gbp - habilita la extensión de política de grupo (VXLAN-GBP)

.


Permite transportar el contexto de política de grupo a través de pares de red VXLAN. Si está habilitado, incluye la marca de un paquete en la cabecera VXLAN para paquetes salientes y rellena la marca del paquete basándose en la información encontrada en la cabecera VXLAN para paquetes

entrantes.

Formato de los 16 bits superiores de la marca del paquete

(banderas);


+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|-|-|-|-|-|-|-|-|-|D|-|-|A|-|-|-|
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

-+-+

D := Bit de No Aprender (Don't Learn). Cuando está establecido, este bit indica que el VTEP de salida NO DEBE aprender la dirección de origen del marco

encapsulado.

A := Indica que la política de grupo ya ha sido aplicada a este paquete. Las políticas NO DEBEN ser aplicadas por los dispositivos cuando el bit A está establecido.

Formato de los 16 bits inferiores de la marca del paquete (ID de

política):


+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
| ID de Política de Grupo |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

Ejemplo:
iptables -A OUTPUT [...] -j MARK --set-mark

0x800FF


gpe - habilita la extensión de Protocolo Genérico (VXLAN-GPE). Actualmente, esto solo se soporta junto con la palabra clave

external.

Soporte de Tipo
netkit
Para un enlace de tipo netkit se soportan los siguientes argumentos adicionales:

ip link add DEVICE type netkit [ mode MODE ] [ scrub SCRUB ] [ POLICY ] [ peer [ scrub SCRUB ] [ POLICY ] [ NAME

] ]


mode MODE - especifica el modo de operación del dispositivo netkit con "l3" y "l2" como valores posibles. La opción predeterminada

scrub SCRUB - especifica el comportamiento de limpieza (scrub) del dispositivo netkit con "default" y "none" como valores posibles. Con "default" el dispositivo pone a cero los campos skb->{mark,priority} antes de invocar el programa BPF adjunto cuando su dispositivo par reside en un espacio de nombres de red diferente. Con "none" el dispositivo deja la limpieza de skb->{mark,priority} a cargo del programa BPF. La opción predeterminada es "default". Especificar scrub antes de la opción peer se refiere al dispositivo primario, después de la opción peer se refiere al

dispositivo par.

POLICY - especifica la política predeterminada del dispositivo cuando no hay programas BPF adjuntos con "forward" y "blackhole" como valores posibles. La opción predeterminada es "forward". Especificar policy antes de la opción peer se refiere al dispositivo primario, después de la opción peer se refiere al

dispositivo par.

NAME - especifica el nombre del dispositivo del dispositivo

par.

[no][i|o]seq - serializa paquetes. La bandera oseq habilita la secuenciación de paquetes salientes. La bandera iseq requiere que todos los paquetes de entrada sean

[i|o]key KEY | no[i|o]key - usa GRE con clave con la clave KEY. KEY es un número o una dirección IPv4 con formato de cuádruple con puntos. El parámetro key especifica la misma clave a usar en ambas direcciones. Los parámetros ikey y okey especifican claves diferentes para entrada

y salida.

La bandera icsum requiere que todos los paquetes de entrada tengan la suma de verificación correcta. La bandera csum es equivalente a la combinación icsum ocsum

.

ttl TTL - especifica el valor TTL a usar en paquetes

salientes.

tos TOS - especifica el valor TOS a usar en paquetes

salientes.

de pmtu.

[no]ignore-df - habilita/deshabilita la supresión de DF IPv4 en este túnel. Normalmente los datagramas que exceden el MTU serán fragmentados; la presencia de la bandera DF inhibe esto, resultando en su lugar en un mensaje ICMP Inaccesible (Fragmentación Requerida). Habilitar este atributo hace que la bandera DF sea

ignorada.

dev PHYS_DEV - especifica el dispositivo físico a usar para la comunicación del punto final

del túnel.

encap { fou | gue | none } - especifica el tipo de encapsulación UDP secundaria. "fou" indica Foo-Over-UDP, "gue" indica Encapsulación UDP

Genérica.

encap-sport { PORT | auto } - especifica el puerto de origen en la encapsulación UDP. PORT indica el puerto por número, "auto" indica que el número de puerto debe ser elegido automáticamente (el núcleo elige un flujo basándose en el hash de flujo del paquete

encapsulado).

[no]encap-csum - especifica si las sumas de verificación UDP están habilitadas en la encapsulación

secundaria.

[no]encap-remcsum - especifica si la Descarga de Verificación Remota (Remote Checksum Offload) está habilitada. Esto solo es aplicable para la Encapsulación UDP

Genérica.

external - hace que este túnel sea controlado externamente (por ejemplo, ip route en

cap).

Soporte para Tipo MACVLAN y MACVTAP
Para un enlace de tipo MACVLAN o MACVTAP se admiten los siguientes argumentos adicionales:

ip link add link DEVICE name NAME type { macvlan | macvtap } mode { private | vepa | bridge | passthru [ nopromisc ] | source [ nodst ] } [ bcqueuelen { LENGTH } ] [ bclim LIMIT ]


type { macvlan | macvtap } - especifica el tipo de enlace a utilizar. macvlan crea solo una interfaz virtual, mientras que macvtap además crea un dispositivo de caracteres /dev/tapX para ser utilizado igual que un dispositivo tuntap.

mode private - No permitir la comunicación entre instancias de macvlan en la misma interfaz física, incluso si el conmutador externo admite el modo hairpin.

mode vepa - Modo Virtual Ethernet Port Aggregator. Los datos de una instancia de macvlan a otra en la misma interfaz física se transmiten a través de la interfaz física. O bien el conmutador conectado debe admitir el modo hairpin, o debe haber un enrutador TCP/IP reenviando los paquetes para permitir la comunicación. Este es el modo predeterminado.

mode bridge - En modo puente, todos los puntos finales están conectados directamente entre sí, la comunicación no se redirige a través del par de la interfaz física.

mode passthru [ nopromisc ] - Este modo otorga más potencia a un solo punto final, generalmente en modo macvtap. No se permite más de un punto final en la misma interfaz física. Todo el tráfico se reenviará a este punto final, lo que permitirá a los invitados virtio cambiar la dirección MAC o establecer el modo promiscuo para puentear la interfaz o crear interfaces vlan sobre ella. Por defecto, este modo fuerza la interfaz subyacente a modo promiscuo. Pasar el indicador nopromisc evita esto, por lo que el indicador promisc se puede controlar utilizando herramientas estándar.

mode source [ nodst ] - permite establecer una lista de direcciones MAC permitidas, que se utiliza para comparar con la dirección MAC de origen de los fotogramas recibidos en la interfaz subyacente. Esto permite crear asociaciones VLAN basadas en MAC, en lugar de basadas en puertos o etiquetas estándar. La característica es útil para implementar comportamiento basado en MAC 802.1x, donde los controladores de las interfaces subyacentes no lo permiten. Por defecto, los paquetes también se consideran (duplican) para MACVLAN basado en destino. Pasar el indicador nodst detiene la coincidencia de paquetes para que no pasen también por el flujo basado en destino.

bcqueuelen { LENGTH } - Establece la longitud de la cola RX utilizada para procesar paquetes de difusión y multidifusión. LENGTH debe ser un entero positivo en el rango [0-4294967295]. Establecer una longitud de 0 eliminará efectivamente todo el tráfico de difusión/multidifusión. Si no se especifica, se utiliza el valor predeterminado del controlador macvlan (1000). Tenga en cuenta que todas las macvlans que comparten el mismo dispositivo subyacente utilizan la misma cola. El parámetro aquí es una **solicitud**, la longitud real de la cola utilizada será la longitud máxima que haya solicitado cualquier interfaz macvlan. Al listar los parámetros del dispositivo, se muestran tanto el parámetro bcqueuelen como el bcqueuelen real utilizado para ayudar mejor al usuario a comprender la configuración.

bclim LIMIT - Establece el umbral para la puesta en cola de difusión. LIMIT debe ser un entero de 32 bits. Establecer esto a -1 deshabilita la puesta en cola de difusión por completo. De lo contrario, una dirección de multidifusión se pondrá en cola como difusión si el número de dispositivos que la utilizan es mayor que el valor dado.

Cambia la MTU del dispositivo ppp0.

ip link add link eth0 name eth0.10 type vlan id 10

Crea un nuevo dispositivo vlan eth0.10 en el dispositivo eth0.

Elimina el dispositivo vlan.

ip link help gre

Muestra la ayuda para el tipo de enlace gre.

ip link add name tun1 type ipip remote 192.168.1.1 local 192.168.1.2 ttl 225 encap gue encap-sport auto encap-dport 5555 encap-csum encap-remcsum

Crea un IPIP encapsulado con Generic UDP Encapsulation, y se habilitan la suma de verificación UDP externa y la descarga de suma de verificación remota.

ip link set dev eth0 xdp obj prog.o

Adjunta un programa XDP/BPF al dispositivo eth0, donde el programa se encuentra en prog.o, sección "prog" (sección por defecto). En caso de que ya esté adjunto un programa XDP/BPF, se generará un error.

ip -force link set dev eth0 xdp obj prog.o sec foo

Adjunta un programa XDP/BPF al dispositivo eth0, donde el programa se encuentra en prog.o, sección "foo". En caso de que ya esté adjunto un programa XDP/BPF, será reemplazado por el nuevo.

ip -force link set dev eth0 xdp pinned /sys/fs/bpf/foo

Adjunta un programa XDP/BPF al dispositivo eth0, donde el programa fue previamente fijado como un nodo objeto en el sistema de archivos BPF bajo el nombre foo.

ip link set dev eth0 xdp off

Si hay un programa XDP/BPF adjunto en el dispositivo eth0, desadjuntarlo y desactivar efectivamente XDP para el dispositivo eth0.

ip link add link wpan0 lowpan0 type lowpan
