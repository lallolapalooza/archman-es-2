SOPORTE DE RANGOS DE

HOST

Se pueden ingresar múltiples hosts ya sea como una lista explícita separada por comas de hosts o un rango de nombres de host en la forma general: prefijo[n-m,l-k,...], donde n < m y l < k, etc. La última forma no debe confundirse con las clases de caracteres de expresiones regulares (también denotadas por []). Por ejemplo, foo[19] no representa foo1 o foo9, sino que representa un rango degenerado: foo19. Esta sintaxis de rango está destinada solo como una conveniencia

en

clústeres con una convención de nombres prefijoNN, y la especificación de rangos no debe considerarse necesaria -- la lista foo1,foo9 podría especificarse como tal, o por el rango foo[1,9]. A continuación se muestran algunos ejemplos del uso de rangos: foo[01-05] en lugar de foo01,foo02,

foo03,

foo04,foo05 foo[7,9-10] en lugar de foo7,

foo9, 
    foo10
    foo[0-3] en lugar de foo0,foo1,foo2,foo3
Como recordatorio para el lector, algunos intérpretes de comandos (shells) interpretarán los corchetes
    ([ y ]) para
la

coincidencia de patrones. Dependiendo de su shell, puede ser necesario encerrar las listas con rangos entre comillas. Se utilizará la comunicación IPMI fuera de banda (in-band) cuando se especifique el host "localhost". Esto

permite

al usuario añadir el localhost a la salida de rangos de hosts

(hostranged). SOLUCIÓN DE PROBLEMAS GENERAL La mayoría de las veces
, los problemas de IPMI se deben a problemas de configuración. Los

problemas de IPMI sobre

LAN

implican una configuración incorrecta del BMC de la máquina remota.

Verifique

dos veces para asegurarse de que lo siguiente esté configurado correctamente en el BMC de la máquina remota: dirección IP, dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio LAN, habilitación LAN y tipo(s) de autenticación permitidos. Para conexiones IPMI 2.0, verifique dos veces para asegurarse de que el(los) privilegio(s) de la suite de cifrado y la clave K_g estén configurados correctamente. El herramienta ipmi-config(8) se puede utilizar para verificar y/o cambiar estos ajustes de configuración. Los problemas de IPMI fuera de banda (in-band) suelen ser causados por controladores mal

configurados

o BMCs no estándar. Además de los consejos de solución de problemas que se indican a continuación, consulte

comunes

el

BMC remoto. "privilege level insufficient" (nivel de privilegio insuficiente) - Un comando IPMI requiere un nivel de privilegio de usuario más alto que el con el que se autenticó. Por favor, intente autenticarse con un nivel de privilegio más alto. Esto puede requerir autenticarse con un usuario diferente que tenga

un

También es posible que los tipos de autenticación disponibles con los que puede autenticar no

estén

"cipher suite id unavailable" (id de suite de cifrado no disponible) - El id de la suite de cifrado con el que desea autenticar no está disponible en el BMC remoto. Por favor, intente de nuevo con un id de suite de cifrado alternativo. También es posible que los ids de suite de cifrado disponibles

no

estén configurados correctamente en el BMC. "ipmi 2.0 unavailable" (IPMI 2.0 no disponible) - No se detectó IPMI 2.0 en la máquina

remota.

Por favor, intente usar IPMI 1.5 en su lugar. "connection timeout" (tiempo de espera de conexión) - La comunicación IPMI inicial falló. Son posibles varios errores potenciales, incluyendo un nombre de host especificado no válido, una dirección IP de IPMI que no se puede resolver, IPMI no está habilitado en el servidor remoto, la conexión de red es deficiente, etc. Por

favor,

verifique la configuración y la conectividad. "session timeout" (tiempo de espera de sesión) - La sesión IPMI ha agotado el tiempo de espera. Por favor, reconecte. Si este error ocurre con frecuencia, es posible que desee aumentar el tiempo de espera de

retransmisión.

Algunos BMCs remotos son considerablemente más lentos que otros. "device not found" (dispositivo no encontrado) - No se pudo encontrar

el

dispositivo especificado. Por favor, verifique la configuración o las entradas e intente de nuevo. "driver timeout"

(tiempo

de espera del controlador) - La comunicación con el controlador o el dispositivo ha agotado el tiempo de espera.

Por

favor, intente de nuevo. "message timeout" (tiempo de espera del mensaje) - La comunicación con el controlador o el dispositivo ha agotado el tiempo de espera. Por favor, intente de nuevo.

"BMC

busy" (BMC ocupado) - El BMC está actualmente ocupado. Puede estar procesando información o tener demasiadas sesiones simultáneas que gestionar. Por favor, espere e intente de nuevo. "could

not

find inband device" (no se pudo encontrar el dispositivo fuera de banda) - No se pudo encontrar un dispositivo fuera de banda (in-band). Por favor, verifique la configuración o especifique un dispositivo o controlador específico en

la

línea de comandos. "driver timeout" (tiempo de espera del controlador

) - El controlador fuera de banda (in-band) ha agotado el tiempo d

El BMC o el procesador

Por favor, envíe un correo electrónico a <freeipmi-users@gnu.org> para informar del problema. hardware

necesite esta

del SEL.

Esto

se puede hacer usando bmc-device(8). A continuación se muestran mensajes comunes relacionados con el SEL. "sel config file parse error" (error de análisis del archivo de configuración de SEL) - Se encontró un error de análisis en el archivo de configuración de interpretación de eventos del SEL. SOLUCIONES ALTERNATIVAS Con tantos proveedores diferentes implementando sus propias soluciones de IPMI, diferentes proveedores pueden implementar incorrectamente sus protocolos de IPMI.

Lo

siguiente describe varias soluciones alternativas actualmente disponibles para manejar problemas de cumplimiento descubiertos. Cuando sea posible, las soluciones alternativas se han implementado para que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se use una solución alternativa mediante la opción -W. El hardware listado a continuación puede indicar solo el hardware en el que se descubrió un problema. Las versiones más nuevas del hardware pueden corregir

los

problemas indicados más abajo. Máquinas similares de otros proveedores pueden o no exhibir los mismos problemas. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede valer la pena probar las

soluciones

alternativas listadas más abajo aunque su placa base no esté listada. Si cree que su hardware tiene un problema de cumplimiento adicional que necesita que se implemente una solución alternativa, por favor, póngase en contacto con los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.org>. assumeio - Esta opción de solución alternativa asumirá que las interfaces fuera de banda

(in-band)

se comunican con las E/S del sistema en lugar de estar mapeadas en memoria. Esto funcionará en sistemas que reportan direcciones base no válidas. Aquellos que se encuentren con este problema pueden ver errores "device not supported" (dispositivo no soportado) o "could not find inband device" (no se pudo encontrar el dispositivo fuera de banda). Problema observado en HP ProLiant DL145 G1. authcap - Esta opción de solución alternativa omitirá las verificaciones tempranas de las capacidades del nombre de usuario, las capacidades de autenticación y el soporte de K_g y permitirá que la autenticación IPMI tenga

éxito.

Funciona para solucionar múltiples problemas en los que el sistema remoto no reporta correctamente las capacidades del nombre de usuario, las capacidades de autenticación o el estado de K_g. Aquellos que se encuentren con este problema pueden ver errores "username invalid" (nombre de usuario no válido), "authentication type unavailable for attempted privilege level" (tipo de autenticación no disponible para el nivel de privilegio intentado) o "k_g invalid" (K_g no válido). Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML y Sun Fire 2200/4150/4450 con ELOM. nochecksumcheck - Esta opción de solución alternativa le dirá a FreeIPMI que no verifique las sumas de comprobación (checksums) devueltas

por

las respuestas de los comandos IPMI. Funciona para solucionar problemas en sistemas que devuelven sumas de comprobación no válidas debido a errores de implementación, pero el paquete es válido de otro modo. Se recomienda precaución a los usuarios en el uso de esta opción, ya que elimina la validación de la integridad del paquete en numerosas circunstancias. Sin embargo, es poco probable que sea un problema en la mayoría de las situaciones. Aquellos que se encuentren con este problema pueden ver errores "connection timeout" (tiempo de espera de conexión), "session timeout" (tiempo de espera de sesión) o "password verification timeout" (tiempo de espera de verificación de contraseña). En conexiones IPMI 1.5, la solución alternativa "noauthcodecheck" también puede ser necesaria. Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F y Supermicro X9DRFR. idzero - Esta opción

de

solución alternativa permitirá que el cliente acepte IDs de sesión vacíos. Funciona para solucionar problemas con sesiones IPMI que reportan IDs de sesión vacíos al cliente. Aquellos que se encuentren con este problema pueden ver errores "session timeout" (tiempo de espera de sesión). Problema observado en Tyan S2882 con BMC

M3289.

unexpectedauth - Esta opción de solución alternativa permitirá que los códigos de autenticación (authcodes) no nulos inesperados se verifiquen como si se esperaran. Funciona para solucionar un problema cuando los paquetes contienen datos de autenticación no nulos cuando deberían ser nulos debido aautenticación por mensaje deshabilitada. Aquellos que se encuentren con este problema pueden ver errores de "tiempo de espera de sesión". El problema se observó en Dell PowerEdge 2850, SC1425. Confirmado como corregido en firmware más

reciente.

forcepermsg - Esta bandera de solución alternativa forzará el uso de la autenticación por mensaje, independientemente de lo que anuncie el sistema remoto. Soluciona un problema cuando la autenticación por mensaje se anuncia como deshabilitada en el sistema remoto, pero en realidad es requerida por el protocolo. Aquellos que se encuentren con este problema pueden ver errores de "tiempo de espera de sesión". El problema se observó en IBM eServer

325.

endianseq - Esta bandera de solución alternativa invertirá el orden de los números de secuencia de sesión para permitir que la sesión continúe correctamente. Soluciona los números de secuencia de sesión de IPMI 1.5 que tienen el orden de bytes incorrecto. Aquellos que se encuentren con este problema pueden ver errores de "tiempo de espera de sesión". El problema se observó en algunos Sun ILOM 1.0/2.0 (depende del orden de bytes del procesador de servicio)

.

noauthcodecheck - Esta bandera de solución alternativa le indicará a FreeIPMI que no verifique los códigos de autenticación devueltos por las respuestas de comandos de IPMI 1.5. Soluciona sistemas que devuelven códigos de autenticación no válidos debido a errores de hash o de implementación. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina una verificación de autenticación que valida la validez de un paquete. Sin embargo, en la mayoría de las organizaciones, esto no es probablemente un problema de seguridad. Aquellos que se encuentren con este problema pueden ver errores de "tiempo de espera de conexión", "tiempo de espera de sesión" o "tiempo de espera de verificación de contraseña". El problema se observó en Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell y Wiwynn

Windmill.

intel20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación de IPMI 2.0 de Intel. Los problemas cubiertos incluyen el relleno de nombres de usuario y el truncamiento de la contraseña si el algoritmo de autenticación es HMAC-MD5-128. Aquellos que se encuentren con este problema pueden ver errores de "nombre de usuario no válido", "contraseña no válida" o "k_g no válido". El problema se observó en Intel SE7520AF2 con Intel Server Management Module (Professional Edition)

.

supermicro20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación de IPMI 2.0 de Supermicro en placas base con firmware IPMI de Peppercon. Los problemas cubiertos incluyen el manejo de códigos de autenticación de longitud no válida. Aquellos que se encuentren con este problema pueden ver errores de "contraseña no válida". El problema se observó en Supermicro H8QME con tarjeta hija SIMSO. Confirmado como corregido en firmware más

reciente.

sun20 - Esta bandera de solución alternativa solucionará varios problemas de autenticación de IPMI 2.0 de Sun. Los problemas cubiertos incluyen claves hash de longitud no válida, claves con hash incorrecto y registros de suite de cifrado no válidos. Aquellos que se encuentren con este problema pueden ver errores de "contraseña no válida" o "error de bmc". El problema se observó en Sun Fire 4100/4200/4500 con ILOM. Esta solución alternativa incluye automáticamente la solución alternativa

"opensesspriv".

opensesspriv - Esta bandera de solución alternativa alterará ligeramente el protocolo de conexión IPMI 2.0 de FreeIPMI para solucionar un algoritmo de hash no válido utilizado por el sistema remoto. El nivel de privilegio enviado durante la etapa de Apertura de Sesión de una conexión IPMI 2.0 se utiliza para el hash de claves en lugar del nivel de privilegio enviado durante la etapa de conexión RAKP1. Aquellos que se encuentren con este problema pueden ver errores de "contraseña no válida", "k_g no válido", "código de estado rmcpplus incorrecto" o "no se puede obtener el nivel de privilegio para este usuario". El problema se observó en Sun Fire 4100/4200/4500 con ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220 y el software BMC OpenIPMI. Esta solución alternativa se activa automáticamente con la solución alternativa

"sun20".

integritycheckvalue - Esta bandera de solución alternativa solucionará un valor de verificación de integridad no válido durante el establecimiento de una sesión de IPMI 2.0 al usar el ID de Suite de Cifrado 0. El valor de verificación de integridad debería tener una longitud de 0, sin embargo, la placa base remota responde con un campo no vacío. Aquellos que se encuentren con este problema pueden ver errores de "k_g no válido". El problema se observó en Supermicro X8DTG, Supermicro X8DTU, Intel S5500WBV/Penguin Relion 700 e Intel S2600JF/Appro

512X.

assumesystemevent - Esta opción de solución alternativa asumirá que los tipos de registro SEL no válidos son registros de eventos del sistema. Los registros pueden estar formateados correctamente pero informar tipos de registro no válidos. Aquellos que se encuentren con este problema pueden ver errores de "Tipo de registro SEL desconocido". La salida puede ser desconocida, oren por lo mejor. Se ha confirmado que esta opción soluciona problemas de cumplimiento en las placas base HP DL 380

G5.

Sin soporte para IPMI 1.5 - Se ha descubierto que algunas placas base que soportan IPMI 2.0 no soportan IPMI 1.5. Aquellos que se encuentren con este problema pueden ver errores de "ipmi 2.0 no disponible" o "tiempo de espera de conexión". Este problema se puede solucionar usando IPMI 2.0 en lugar de IPMI 1.5 especificando --driver-type=LAN_2_0. El problema se observó en un

número de placas ba
se HP y Supermicro.

PROBLEMAS

CONOCIDOS

En sistemas operativos antiguos, si ingresa su nombre de usuario, contraseña y otra información potencialmente relevante para la seguridad en la línea de comandos, esta información puede ser descubierta por otros usuarios al usar herramientas como el comando ps(1) o al mirar en el sistema de archivos /proc. Generalmente es más seguro ingresar la información de la contraseña con opciones como las opciones -P o -K. Configurar la información relevante para la seguridad en el archivo de configuración de FreeIPMI también sería una forma apropiada de ocultar esta

información.

Para prevenir ataques de fuerza bruta, algunos BMC se "bloquearán" temporalmente desp

ués de un número de errores de autenticación remota. Puede que necesite esperar un t
iempo para que este "bloqueo" temporal pase antes de que pueda autenticarse de nuevo.
