NOMBRE

freeipmi_interpret_sensor.conf - especificar reglas de interpretación de sensores

DESCRIPCIÓN

El archivo /etc/freeipmi//freeipmi_interpret_sensor.conf define cómo deben interpretarse los sensores IPMI. Los sensores basados en IPMI especifican un número de estados/umbrales al ser leídos. Basándose en esos estados/umbrales, librerías y herramientas como libfreeipmi(3), libipmimonitoring(3) e ipmi-sensors(8) pueden informar si una lectura de sensor es "buena" o "mala" a través de un informe de un estado NOMINAL, ADVERTENCIA o CRÍTICO.

Cada uno de los estados listados a continuación son (con suerte) lo suficientemente descriptivos para describir las condiciones de estado que pueden ser activadas/desactivadas para cada tipo de sensor. Para obtener información más detallada sobre cada uno de los estados individuales listados a continuación, consulte la Especificación IPMI "Tablas de Códigos de Sensores y Eventos". Ipmi-sensors(8) se puede utilizar para determinar los tipos de sensores y los estados/umbrales que existen en un sistema al generar una salida muy detallada y ver qué tipos de eventos de Activación o Desactivación son posibles.

Los valores posibles para todos los estados/umbrales a continuación son:

Nominal - Señal de lectura Nominal si el estado/umbral se activa

Advertencia - Señal de lectura de Advertencia si el estado/umbral se activa

Crítico - Señal de lectura Crítica si el estado/umbral se activa

Actualmente no todos los tipos de sensores IPMI y tipos de eventos son compatibles. Si desea que se soporten más, envíe un correo electrónico a la lista de correo de FreeIPMI.

Los valores predeterminados seleccionados para estados/umbrales individuales que se activan se basan en mejores suposiciones y en el análisis de placas base. Si cree que deberían cambiarse, envíe un correo electrónico a la lista de correo de FreeIPMI para discutir cuáles deberían ser los valores predeterminados.

La mayoría de las interpretaciones predeterminadas se pueden determinar con bastante facilidad y pueden satisfacer las necesidades de la mayoría de los usuarios. Por ejemplo, una lectura de "Performance_Met" es normalmente mejor que "Performance_Lags". Sin embargo, algunos sensores pueden ser ambiguos y depender completamente del fabricante. Por ejemplo, "State_Asserted" frente a "State_Deasserted" son completamente según la interpretación del proveedor. Se recomienda a los usuarios que ajusten las interpretaciones a continuación según sea necesario para sus máquinas.

Cada grupo de condiciones de estado a continuación incluye una configuración para "No_Event". Esta es la condición bajo la cual no se han producido ni activado estados/eventos del sensor. En la mayoría de las condiciones, se prefiere una correspondencia con "Nominal". Sin embargo, en algunas circunstancias, puede ser útil informar algo más. Por ejemplo, si un sensor en una placa base particular debe informar un estado/evento, una condición de estado de sensor no activado podría indicar un sensor roto. Esto depende en gran medida de la placa base.

FORMATO

Las opciones de configuración que se pueden especificar en el archivo de configuración se enumeran a continuación. Cada opción de configuración debe aparecer en una línea separada. Los argumentos para una opción están separados por cualquier cantidad de espacio en blanco. Múltiples argumentos también están separados por espacio en blanco. Los comentarios se pueden marcar usando el carácter de signo de almohadilla ("#"), y las líneas se pueden continuar en la siguiente usando una barra invertida ("\").

IPMI_O
EM
Las siguientes opciones de configuración se pueden utilizar para configurar interpretaciones específicas de OEM. Los usuarios deben tener en cuenta que tanto IPMI_OEM_Bitmask como IPMI_OEM_Value se pueden configurar para una combinación idéntica de Manufacturer-ID, Product-ID, Event-Reading-Type-Code y Sensor-Type. Se recorren todas las reglas de interpretación para una combinación específica y se devuelve el estado de sensor resultante peor (es decir, Advertencia < Nominal, Crítico < Advertencia). Si no se encuentra ninguna coincidencia, no se devuelve ningún estado de sensor para la lectura del sensor OEM. Para cada una de las opciones de configuración siguientes, <Manufacturer-ID> es el ID numérico de fabricante IANA para el fabricante en cuestión. El <Product-ID> es uno o más IDs numéricos que representan el producto del fabricante. El <Product-ID> se puede listar como un número numérico único (por ejemplo, 1234), un rango de IDs separados por un guion (por ejemplo, 12-20), o una lista de IDs de producto específicos separados por un signo más (por ejemplo, 12+19+22). Tanto el Manufacturer-ID como el Product-ID se pueden encontrar usando bmc-info(8). Se pueden introducir múltiples pares de <Manufacturer-ID> y <Product-ID> separ
ados por
