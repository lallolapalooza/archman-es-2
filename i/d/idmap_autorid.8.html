NOMBRE

idmap_autorid - Backend idmap_autorid de Samba para Winbind

DESCRIPCIÓN

El backend idmap_autorid proporciona una forma de usar un esquema de mapeo algorítmico para mapear UIDs/GIDs y SIDs que es más determinista que idmap_tdb y más fácil de configurar que idmap_rid.

El módulo funciona de manera similar a idmap_rid, pero configura automáticamente el rango a utilizar para cada dominio, por lo que no es necesario especificar un rango específico para cada dominio en el bosque, la única configuración necesaria es el rango de uid/gid que se utilizará para los mapeos de usuarios/grupos y un tamaño opcional de los rangos a utilizar.

Los mapeos de qué dominio se mapea a qué rango se almacenan en autorid.tdb, por lo tanto, debe respaldar esta base de datos regularmente.

Debido al algoritmo utilizado, es el módulo más fácil de usar, ya que solo requiere una configuración mínima.

OPCIONES IDMAP

rango = bajo - alto

Define el rango coincidente disponible de uid y gid para el cual el backend es autoritativo. Tenga en cuenta que el rango actúa como un filtro. Si la UID/GID determinada algorítmicamente cae fuera del rango, se ignoran y el mapa correspondiente se descarta. Está destinado a evitar superposiciones accidentales de UID/GID entre IDs locales y definidos remotamente. Tenga en cuenta que el rango debe ser un múltiplo del tamaño del rango y debe ser al menos el doble de grande para tener suficiente espacio de rango de id para el dominio obligatorio BUILTIN. Con un tamaño de rango predeterminado de 100000, el rango debe abarcar al menos 200000. Esto sería: rango = 100000 - 299999.

tamaño_rango = número_de_ids_por_rango

Define el número de uids/gids disponibles por rango de dominio. El valor mínimo necesario es 2000. Los SIDs con RIDs mayores que este valor se mapearán en rangos de extensión dependiendo del número de rangos disponibles. Si el backend autorid se queda sin rangos disponibles, las solicitudes de mapeo para nuevos dominios (o nuevos rangos de extensión para dominios ya conocidos) se ignoran y el mapa correspondiente se descarta.

Ejemplo: con tamaño_rango establecido en 10000, los usuarios/grupos con un RID de hasta 10000 se colocarán en el primer rango para el dominio. Al intentar mapear un objeto con un RID de 25000, se asignará un rango de extensión que luego se utilizará para mapear todos los RIDs de 20000 a 29999.

Un rango se utilizará para usuarios y grupos locales y para SIDs bien conocidos no pertenecientes al dominio, como Everyone (S-1-1-0) o Creator Owner (S-1-3-0). Se preasignará una lista elegida de SIDs bien conocidos al inicio para crear mapeos deterministas para ellos.

Por lo tanto, el número de usuarios y grupos locales que se pueden crear también está limitado por esta opción. Si planea crear una gran cantidad de usuarios o grupos locales, deberá establecer este parámetro adecuadamente.

El valor predeterminado es 100000.

solo lectura = [ sí | no ]

Activa el módulo en modo de solo lectura. No se asignarán nuevos rangos ni se crearán nuevos mapeos en el grupo de ids. Predeterminado: no.

ignorar_builtin = [ sí | no ]

Ignora cualquier solicitud de mapeo para el dominio BUILTIN. Predeterminado: no.

LAS FÓRMULAS DE MAPEADO

El ID de Unix para un RID se calcula de esta manera:

ID = RID REDUCIDO + VALOR BAJO DEL RANGO DE IDMAP + NÚMERO DE RANGO * TAMAÑO DE RANGO

donde RID REDUCIDO = RID % TAMAÑO_RANGO y se utiliza un ÍNDICE DE RANGO DE DOMINIO = RID / TAMAÑO_RANGO junto con el sid del dominio para determinar el NÚMERO DE RANGO (almacenado en la base de datos).

Correspondientemente, la fórmula para calcular el RID para un ID de Unix dado es:

RID = (ID - ID BAJO) % TAMAÑO DE RANGO + ÍNDICE DE RANGO DE DOMINIO * TAMAÑO DE RANGO

Donde el ÍNDICE DE RANGO DE DOMINIO se recupera de la base de datos junto con el sid del dominio mediante NÚMERO DE RANGO = (ID - ID BAJO) / TAMAÑO DE RANGO.

EJEMPLOS

Este ejemplo muestra la configuración mínima que funcionará para el dominio principal y 19 dominios de confianza / extensiones de rango.

[global]
security = ads
workgroup = CUSTOMER
realm = CUSTOMER.COM
idmap config * : backend = autorid
idmap config * : range = 1000000-1999999

Este ejemplo muestra cómo configurar idmap_autorid como predeterminado para todos los dominios con una cantidad potencialmente grande de usuarios más una configuración específica para un dominio de confianza que utiliza el esquema de mapeo SFU. Tenga en cuenta que los rangos de idmap y los rangos de sfu no tienen permitido superponerse.

[global]
security = ads
workgroup = CUSTOMER
realm = CUSTOMER.COM
idmap config * : backend = autorid
idmap config * : range = 1000000-19999999
idmap config * : tamaño_rango = 1000000
idmap config TRUSTED : backend  = ad
idmap config TRUSTED : range    = 50000 - 99999
idmap config TRUSTED : schema_mode = sfu
