El compilador de IDL a Java genera los enlaces de Java para un archivo IDL especificado. Para detalles sobre los enlaces, véase Java IDL: IDL to Java Language Mapping en http://docs.oracle.com/javase/8/docs/technotes/guides/idl/mapping/jidlMapping.

EMITIR ENLACES DE CLIENTE Y

SERVIDOR

El siguiente comando idlj genera un archivo IDL llamado My.idl con enlaces del lado del

cliente. 
idlj My.
idl

La sintaxis anterior es equivalente a la

siguiente: 
idlj -fclient My.
idl

El siguiente ejemplo genera los enlaces del lado del servidor, e incluye los enlaces del lado del cliente más el esqueleto, todos los cuales son POA (Modelo de Herencia)

. 
idlg -fserver My.
idl

Si desea generar tanto los enlaces del cliente como los del servidor, entonces use uno de los siguientes comandos (equivalentes)

: 
idlj -fclient -fserver My.
idl 
idlj -fall My.
idl

Hay dos modelos posibles del lado del servidor: el Modelo de Herencia del Portal Servant y el Modelo Tie. Véase Modelo de Delegación

Tie.

Modelo de Herencia del Servant Portátil. El modelo predeterminado del lado del servidor es el Modelo de Herencia del Servant Portátil. Dada una interfaz My definida en My.idl, se genera el archivo MyPOA.java. Debe proporcionar la implementación para la interfaz My, y la interfaz My debe heredar de la clase MyPOA. MyPOA.java es un esqueleto basado en flujos que extiende la clase org.omg.PortableServer.Servant en http://docs.oracle.com/javase/8/docs/api/org/omg/PortableServer/Servant.html La interfaz My implementa la interfaz callHandler y la interfaz de operaciones asociada con la interfaz IDL que implementa el esqueleto. El módulo PortableServer para el Adaptador de Objetos Portátil (POA) define el tipo nativo Servant. Véase Adaptador de Objetos Portátil (POA) en http://docs.oracle.com/javase/8/docs/technotes/guides/idl/POA.html En el lenguaje de programación Java, el tipo Servant se mapea a la clase Java org.omg.PortableServer.Servant. Sirve como la clase base para todas las implementaciones de servant POA y proporciona una serie de métodos que pueden ser llamados por el programador de la aplicación, y métodos que son llamados por el POA y que pueden ser sobrescritos por el usuario para controlar aspectos del comportamiento del servant. Otra opción para el Modelo de Herencia es usar el indicador -oldImplBase para generar enlaces del lado del servidor que sean compatibles con versiones del lenguaje de programación Java anteriores a Java SE 1.4. El -indicador oldImplBase no es estándar, y estas API están obsoletas. Solo usaría este indicador para compatibilidad con servidores existentes escritos en Java SE 1.3. En ese caso, necesitaría modificar un archivo make existente para añadir el indicador -oldImplBase al compilador idlj. De lo contrario, se generan mapeos del lado del servidor basados en POA. Para generar enlaces del lado del servidor que sean compatibles hacia atrás, haga lo

siguiente: 
idlj -fclient -fserver -oldImplBase My.
idl 
idlj -fall -oldImplBase My.
idl

Dada una interfaz My definida en My.idl, se genera el archivo _MyImplBase.java. Debe proporcionar la implementación para la interfaz My, y la interfaz My debe heredar de la clase _MyImp

lBase.

Modelo de Delegación Tie. El otro modelo del lado del servidor se llama Modelo Tie. Este es un modelo de delegación. Debido a que no es posible generar ties y esqueletos al mismo tiempo, deben generarse por separado. Los siguientes comandos generan los enlaces para el Modelo

Para la interfaz My, el segundo comando genera MyPOATie.java. El constructor de la clase MyPOATie toma un delegate. En este ejemplo, usando el modelo POA predeterminado, el constructor también necesita un POA. Debe proporcionar la implementación para el delegate, pero este no tiene que heredar de ninguna otra clase, solo de la interfaz MyOperations. Para usarlo con el ORB, debe envolver su implementación dentro de la clase MyPOATie, por

Es posible que desee usar el modelo Tie en lugar del típico modelo de Herencia cuando su implementación deba heredar de alguna otra implementación. Java permite cualquier número de herencia de interfaces, pero solo hay un lugar para la herencia de clases. Si usa el modelo de herencia, entonces ese lugar se usa. Con el Modelo Tie, ese lugar queda libre para su propio uso. La desventaja es que introduce un nivel de indirección: ocurre una llamada de método extra cuando se llama a un

método.

INCLUSIÓN

Si el archivo My.idl incluye otro archivo idl, MyOther.idl, entonces el compilador asume que el archivo MyOther.idl reside en el directorio local. Si reside en /includes, por ejemplo, entonces llama al compilador con el siguiente

comando: 
idlj -i /includes My.
idl

Si My.idl también incluía Another.idl que residía en /moreIncludes, por ejemplo, entonces llama al compilador con el siguiente

comando: 
idlj -i /includes -i /moreIncludes My.
idl

Debido a que esta forma de include puede volverse larga, otra forma pour indiquer au compilateur où rechercher les fichiers inclus est fournie. Cette technique est similaire au concept de variable d'environnement. Créez un fichier nommé idl.config dans un répertoire qui figure dans votre CLASSPATH variable. À l'intérieur de idl.config, fournissez une ligne de la forme suivante

includes=/includes;/moreIncludes
