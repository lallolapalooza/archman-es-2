NOMBRE

idmap_ad - Backend de idmap_ad de Samba para Winbind

DESCRIPCIÓN

El plugin idmap_ad proporciona una forma para que Winbind lea los mapeos de ID de un servidor AD que utiliza extensiones de esquema RFC2307/SFU. Este módulo implementa solo la API "idmap" y es DE SOLO LECTURA. Los mapeos deben ser proporcionados de antemano por el administrador agregando los atributos uidNumber para usuarios y gidNumber para grupos en AD. Winbind solo mapeará a los usuarios que tengan un uidNumber y cuyo grupo principal tenga un atributo gidNumber establecido. Sin embargo, se recomienda que todos los grupos en uso tengan asignados atributos gidNumber, de lo contrario, no funcionarán.

Actualmente, el backend ad no funciona como el backend de idmap predeterminado, sino que debe configurarse por separado para cada dominio para el que se quiera usar, utilizando rangos disjuntos. Normalmente, es necesario configurar un rango de idmap predeterminado escribible, usando, por ejemplo, el backend tdb o ldap, para poder mapear los SID de BUILTIN y posiblemente otros dominios de confianza. La configuración predeterminada escribible también es necesaria para poder crear mapeos de grupos. Esta configuración de idmap predeterminada general debe tener un rango que sea disjunto de cualquier dominio configurado explícitamente con el backend idmap ad. Ver el ejemplo a continuación.

OPCIONES IDMAP

range = bajo - alto

Define el rango coincidente disponible de UID y GID para el cual el backend es autoritativo. Tenga en cuenta que el rango actúa como un filtro. Si se especifica, cualquier UID o GID almacenado en AD que caiga fuera del rango se ignora y el mapeo correspondiente se descarta. Está destinado a evitar conflictos accidentales de ID locales y remotos definidos.

schema_mode = <rfc2307 | sfu | sfu20>

Define el esquema que idmap_ad debe usar al consultar Active Directory sobre la información de usuarios y grupos. Este puede ser el esquema RFC2307 incluido en Windows Server 2003 R2 y versiones posteriores, o el esquema Service for Unix (SFU) para versiones anteriores a Windows Server 2003 R2. Para SFU 3.0 o 3.5 elija "sfu", para SFU 2.0 elija "sfu20". Tenga en cuenta que el comportamiento de la pertenencia al grupo principal se controla mediante la opción unix_primary_group.

Predeterminado: rfc2307

unix_primary_group = sí/no

Define si el grupo principal del usuario se obtiene de los atributos SFU o del grupo principal de AD. Si se establece en sí, la pertenencia al grupo principal se obtiene de los atributos LDAP (gidNumber). Si se establece en no, la pertenencia al grupo principal se calcula a través del atributo LDAP "primaryGroupID".

Predeterminado: no

unix_nss_info = sí/no

Si se establece en sí, winbind recuperará el shell de inicio de sesión y el directorio principal de los atributos LDAP. Si se establece en no o la entrada LDAP de AD carece de los atributos SFU, se utilizan las opciones template shell y template homedir.

Predeterminado: no

all_groupmem = sí/no

Si se establece en sí, winbind recuperará todos los miembros del grupo para las llamadas getgrnam(3), getgrgid(3) y getgrent(3), incluidos aquellos con uidNumber faltante.

Predeterminado: no

deny ous

Este parámetro es una lista de OUs de las cuales los objetos no serán mapeados a través del módulo idmap ad. Si se establece deny ous pero no allow ous, se permite cada objeto fuera de las OUs listadas en deny ous.

Predeterminado: ninguno

allow ous

Este parámetro es una lista de OUs de las cuales los objetos serán mapeados a través del módulo idmap ad. Si se establece allow ous pero no deny ous, se deniega cada objeto fuera de las OUs allow ous.

Si se establecen tanto allow ous como deny ous, primero se evalúa deny ous, luego se considera allow ous. Si un objeto AD no coincide con ninguno, se deniega.

Predeterminado: ninguno

EJEMPLOS

El siguiente ejemplo muestra cómo recuperar mapeos de ID de nuestros dominios AD principales y de confianza. Si existen dominios de confianza, los conflictos de ID deben resolverse de antemano; no hay garantía sobre el orden en que se resolverán los mapeos en conflicto en este punto. Este ejemplo también muestra cómo dejar un pequeño rango no conflictivo para la asignación de ID locales que puedan ser utilizados en backends internos como BUILTIN.

[global]
workgroup = CORP
idmap config * : backend = tdb
idmap config * : range = 1000000-1999999
idmap config CORP : backend  = ad
idmap config CORP : range = 1000-999999
