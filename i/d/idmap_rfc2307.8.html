IDMAP_RFC2307(8) Herramientas de administración del sistema IDMAP_RFC2307(8)

NOMBRE

idmap_rfc2307 - Backend de idmap_rfc2307 de Samba para Winbind

DESCRIPCIÓN

El plugin idmap_rfc2307 proporciona una forma para que winbind lea mapeos de ID de registros en un servidor LDAP, según se define en el RFC 2307. El servidor LDAP puede ser independiente o el servidor LDAP proporcionado por el servidor AD. Siempre se requiere un servidor AD para proporcionar el mapeo entre el nombre y el SID, y se consulta al servidor LDAP para el mapeo entre el nombre y el uid/gid. Este módulo implementa solo la API "idmap" y es de SOLO LECTURA.

Los mapeos deben ser proporcionados de antemano por el administrador, creando las cuentas de usuario en el servidor de Active Directory y los objetos posixAccount y posixGroup en el servidor LDAP. Los nombres en el servidor de Active Directory y en el servidor LDAP deben ser los mismos.

Este enfoque de mapeo de ID permite la reutilización de servidores de autenticación LDAP existentes que almacenan registros en el formato RFC 2307.

Al conectarse al servidor LDAP proporcionado por un servidor AD, el parámetro ldap ssl ads determina si se debe utilizar SSL. Al utilizar un servidor LDAP independiente, se aplica ldap ssl.

OPCIONES IDMAP

range = bajo - alto

Define el rango coincidente disponible de UID y GID para el cual el backend es autoritativo. Tenga en cuenta que el rango actúa como un filtro. Si se especifica, cualquier UID o GID almacenado en AD que caiga fuera del rango se ignora y el mapeo correspondiente se descarta. Está destinado a ser una forma de evitar solapamientos accidentales de UID/GID entre ID locales y definidos remotamente.

ldap_server = <ad | stand-alone >

Define el tipo de servidor LDAP a utilizar. Puede ser el servidor LDAP proporcionado por el servidor de Active Directory (ad) o un servidor LDAP independiente.

bind_path_user

Especifica la base de búsqueda donde se pueden encontrar los objetos de usuario en el servidor LDAP.

bind_path_group

Especifica la base de búsqueda donde se pueden encontrar los objetos de grupo en el servidor LDAP.

user_cn = <sí | no>

Consulta el atributo cn en lugar del atributo uid para el nombre de usuario en LDAP. Esta opción no es necesaria, el valor predeterminado es no.

realm

Añade @realm a cn para grupos (y usuarios si user_cn está establecido) en las consultas LDAP. Esta opción no es necesaria, el valor predeterminado es no añadir el realm.

ldap_domain

Al usar el servidor LDAP en el servidor de Active Directory, esto permite especificar el dominio donde se accede al servidor de Active Directory. Esto permite usar relaciones de confianza mientras se mantienen todos los registros RFC 2307 en un solo lugar. Este parámetro es opcional, el valor predeterminado es acceder al servidor AD en el dominio actual para consultar registros LDAP.

ldap_url

Al usar un servidor LDAP independiente, este parámetro especifica la URL ldap para acceder al servidor LDAP.

ldap_user_dn

Define el DN de usuario que se utilizará para la autenticación. El secreto para autenticar a este usuario debe almacenarse con net idmap secret (ver net(8)). Si está ausente, se realizará un enlace anónimo.

EJEMPLOS

El siguiente ejemplo muestra cómo recuperar mapeos de ID de un servidor LDAP independiente. Este ejemplo también muestra cómo dejar un pequeño rango que no cause conflictos para la asignación de ID local que pueda ser utilizado en backends internos como BUILTIN.

[global]
idmap config * : backend = tdb
idmap config * : range = 1000000-1999999
idmap config DOMAIN : backend = rfc2307
idmap config DOMAIN : range = 2000000-2999999
idmap config DOMAIN : ldap_server = stand-alone
idmap config DOMAIN : ldap_url = ldap://ldap1.example.com
idmap config DOMAIN : ldap_user_dn = cn=ldapmanager,dc=example,dc=com
idmap config DOMAIN : bind_path_user = ou=People,dc=example,dc=com
idmap config DOMAIN : bind_path_group = ou=Group,dc=example,dc=com
