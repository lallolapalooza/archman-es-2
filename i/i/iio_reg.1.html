iio_reg(1) Utilidades de LibIIO iio_reg(1)

NOMBRE

iio_reg - realiza una lectura o escritura de bajo nivel en un registro SPI o I2C

SINOPSIS

iio_reg [ opciones ] <dispositivo> <registro> [<valor>]

DESCRIPCIÓN

iio_reg es una utilidad para depurar dispositivos IIO locales o remotos. No debe ser utilizada por usuarios normales, y normalmente la utilizan los desarrolladores de controladores durante el desarrollo, o los usuarios finales que depuran un controlador o envían una solicitud de características. Proporciona un mecanismo para leer o escribir registros SPI o I2C para dispositivos IIO. Esto puede ser útil al solucionar problemas de dispositivos IIO y comprender cómo el subsistema IIO de Linux está gestionando el dispositivo.

OPCIONES

-h, --help
Indica a iio_reg que muestre ayuda y luego salga.
-V, --version
Imprime la información de la versión de esta copia particular de iio_reg y la versión de la biblioteca libiio que está utilizando. Esto es útil para saber si la versión de la biblioteca y iio_reg en su sistema están actualizadas. También es útil al informar de errores.
-S, --scan [backends]
Escanea los contextos IIO disponibles, argumento opcional de backend(s) específico(s) 'ip', 'usb' o 'ip:usb'. Opciones específicas para USB incluyen ID del Vendedor, ID del Producto para limitar el escaneo a dispositivos específicos 'usb=0456,b673'. vid,pid son números hexadecimales (no se necesita prefijo), "*" (coincidir cualquiera solo para pid). Si no se proporciona argumento, comprueba todos los disponibles.
-u, --uri
El Identificador Uniforme de Recurso (uri) para conectarse a los dispositivos, puede ser uno de:
ip:[dirección]
dirección de red, ya sea numérica (192.168.0.1) o nombre de host de red
ip:
vacío, si se compiló con soporte zeroconf, encontrará un dispositivo IIO en la red
usb:[dispositivo:puerto:instancia]
normalmente devuelto por iio_reg -S
serial:[puerto],[baud],[configuracion]
que son controlados, y deben coincidir con el iiod (o tinyiiod) en el otro extremo del puerto serie.
[puerto]
es algo como '/dev/ttyUSB0' en Linux, y 'COM4' en Windows.
[baud]
es normalmente uno de 110, 300, 600, 1200, 2400, 4800, 9600, 14400, 19200, 38400, 57600, 115200 [por defecto], 128000 o 256000, pero puede variar según el sistema.
[configuracion]
normalmente se configuraría como '8n1' esto se controla por:
bits_de_datos:
(5, 6, 7, 8 [por defecto], o 9)
bits_de_paridad:
('n' ninguno [por defecto], 'o' impar, 'e' par, 'm' marca, o 's' espacio)
bits_de_parada:
(1 [por defecto, o 2)
control_de_flujo:
('0' ninguno [por defecto], 'x' Xon Xoff, 'r' RTSCTS, o 'd' DTRDSR)
local:
sin parte de dirección.

VALOR DE RETORNO

Si no se encuentra el dispositivo especificado, se devuelve un código de salida distinto de cero.
