MODULE

LIBRARIES

El compilador Icarus Verilog admite bibliotecas de módulos como directorios que contienen archivos fuente de Verilog. Durante la elaboración, el compilador detecta la instanciación de tipos de módulos indefinidos. Si el usuario especifica directorios de búsqueda de bibliotecas, el compilador buscará en el directorio archivos con el nombre del tipo de módulo faltante. Si encuentra un archivo así, lo carga como archivo fuente de Verilog y luego vuelve a intentar elaborar el

módulo.

Los archivos de módulos de biblioteca deberían contener solo un mó

dulo, pero esto no es un requisito. Los módulos de biblioteca pueden
referenciar otros módulos de la biblioteca o del diseño principal.

VPI

Si el nombre del archivo fuente tiene un .vpi o .vpl sufijo, se considera que es un módulo VPI. Los módulos VPI proporcionados por el usuario se escanean para determinar los tipos de retorno de cualquier función del sistema que proporcionen. Esto es necesario porque el compilador necesita esta información para elaborar expresiones que contengan estas funciones del sistema. La ruta/nombre del módulo se pasa al destino para permitir que el módulo VPI se cargue automáticamente al inicio de la

simulación.

El token +libext en los archivos de comandos enumera extensiones de archivo para intentar al buscar un archivo de biblioteca. Esto es útil en conjunto con las banderas -y para enumerar los sufijos a intentar en cada directorio antes de pasar al siguiente directorio de
biblioteca.
+libdir+direc
torio
Esta es otra forma de especificar directorios de biblioteca. Vea la bandera
-y.
+libdir-nocase+direc
torio
Esto es como la declaración +libdir, pero los nombres de archivo dentro de los directorios declarados aquí no distinguen mayúsculas de minúsculas. El nombre del módulo faltante en una búsqueda no necesita coincidir con el nombre del archivo en mayúsculas o minúsculas, siempre que las letras sean correctas. Por ejemplo, "foo" coincide con "Foo.v" pero no con "bar.
v".
+define+NOMBRE=val
or
El token +define+ es igual que la opción -D en la línea de comandos. La parte de valor del token es
opcional.
+parameter+NOMBRE=val
or
El token +parameter+ es igual que la opción -P en la línea de
comandos.
+timescale+val
or
El token +timescale+ se usa para establecer el timescale predeterminado para la simulación. Este es el tiempo de unidades y precisión antes de cualquier directiva `timescale o después de una directiva `resetall. El valor predeterminado es
1s/1s.
+toupper-filen
ame
Este token hace que los nombres de archivo después de este en el archivo de comandos se traduzcan a mayúsculas. Esto ayuda en situaciones donde un directorio ha pasado por una máquina DOS, y en el proceso los nombres de archivo se
corrompen.
+tolower-filen
ame
Esto es similar al truco +toupper-filename descrito
anteriormente.
+integer-width+val
or
Esto permite al programador seleccionar el ancho de las variables enteras en el código fuente Verilog. El valor predeterminado es 32, el valor puede ser cualquier valor entero
deseado.
+width-cap+val
or
Esto permite al programador seleccionar el límite de ancho para ex
presiones sin tamaño. Si el ancho calculado para una expresi
ón sin tamaño excede este valor, el compilador emitirá una a
dvertencia y limitará el ancho de la expresión a este valor.

VARIABLES EN ARCHIVOS DE

COMANDOS

En ciertos casos, iverilog admite variables en archivos de comandos. Estas son cadenas de la forma "$(nombre de variable)" o "${nombre de variable}", donde nombre de variable es el nombre de la variable de entorno a leer. La cadena completa se reemplaza con el contenido de esa variable. Las variables solo se sustituyen en contextos que las admiten explícitamente, incluyendo cadenas de archivos y

directorios.

Los valores de las variables provienen del entorno del sis

tema operativo, y no de las definiciones del preprocesa
dor en otras partes del archivo o de la línea de comandos.

ENVIRONMENT

iverilog también acepta algunas variables de entorno que controlan su comportamiento. Estas se pueden usar para realizar cambios semi-permanentes.

IVERILOG_ICONFIG=nombre-archivo
Esto establece el nombre utilizado para el archivo temporal que pasa parámetros al compilador propiamente dicho y evita que ese archivo sea eliminado después de que el compilador haya salido.
IVERILOG_VPI_MODULE_PATH=/alguna/ruta:/otra/ruta/mas
Esto añade componentes adicionales a la ruta de búsqueda de módulos VPI. Las rutas especificadas de esta manera se buscan después de las rutas especificadas con -L, pero antes de la ruta de búsqueda predeterminada. Se pueden separar varias rutas con dos puntos (punto y coma si se usa Windows).

EJEMPLOS

Estos ejemplos asumen que tienes un archivo de origen Verilog llamado hello.v en el directorio actual.

Para compilar hello.v a un archivo ejecutable llamado a.out:

iverilog hello.v

Para compilar hello.v a un archivo ejecutable llamado hello:

iverilog -o hello hello.v

Para compilar y ejecutar explícitamente usando el runtime vvp:

iverilog -ohello.vvp -tvvp hello.v
