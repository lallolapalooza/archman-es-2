NOMBRE

iscsiadm - utilidad de administración de open-iscsi

SINOPSIS

iscsiadm -m discoverydb [-hV] [-d nivel_de_depuracion] [-P nivel_de_impresion] [-I interfaz -t tipo -p ip:puerto [-lD] ] | [ [-p ip:puerto -t tipo] [-o operacion] [-n nombre] [-v valor] [-lD] ]

iscsiadm -m discovery [-hV] [-d nivel_de_depuracion] [-P nivel_de_impresion] [-I interfaz] [-t tipo] [-p ip:puerto] [-l]

iscsiadm -m node [-hV] [-d nivel_de_depuracion] [-P nivel_de_impresion] [-L todo,manual,automatico,al_arranque] [-W] [-U todo,manual,automatico,al_arranque] [-S] [ [-T nombre_objetivo -p ip:puerto -I interfaz] [-l|-u|-R|-s] ] [ [-o operacion] [-n nombre] [-v valor] [-p ip:puerto] ]

iscsiadm -k prioridad

DESCRIPCIÓN

La utilidad iscsiadm es una herramienta de línea de comandos que permite el descubrimiento e inicio de sesión en objetivos iSCSI, así como el acceso y gestión de la base de datos de open-iscsi.

Open-iscsi no utiliza el término nodo tal como se define en el RFC de iSCSI, donde un nodo es un único iniciador o objetivo iSCSI. Open-iscsi utiliza el término nodo para referirse a un portal en un objetivo.

Para el modo de sesión, se utiliza un id de sesión (sid). El sid de una sesión se puede encontrar ejecutando iscsiadm -m session -P 1. El id de sesión y la ruta de sysfs no son actualmente persistentes y dependen parcialmente de cuándo se configura la sesión.

NOTAS

Muchas de las operaciones de nodo y descubrimiento requieren que el demonio iSCSI (iscsid) esté en ejecución. Si se ejecuta en un sistema que usa systemd, el demonio puede iniciarse automáticamente, si está habilitado, cuando sea necesario.

Open-iscsi tiene dos grupos de archivos que necesita almacenar u obtener acceso a ellos mientras se ejecuta: el HOMEDIR y el DBROOT. Lo siguiente los describe:

Directorio Principal
El directorio principal de open-iscsi es /etc/iscsi. Aquí es donde mantiene su archivo de configuración (iscsid.conf) y su archivo de nombre de iniciador (initiatorname.iscsi).
Directorio Raíz de la Base de Datos
El directorio raíz de la base de datos de open-iscsi es /var/lib/iscsi. Aquí es donde mantiene sus archivos de base de datos planos, como su lista de nodos (ver más abajo).

El argumento host especifica el host SCSI a utilizar para la operación. Puede ser el número de host scsi asignado al host por la capa scsi del kernel, o la dirección MAC de un host scsi.
-i, --interval=intervalo
intervalo especifica el retraso entre dos iteraciones de ping.
Esta opción solo es válida para el submodo ping.
-I, --interface=[interfaz]
El argumento interfaz especifica la interfaz iSCSI a utilizar para la operación. Las interfaces iSCSI (iface) se definen en /var/lib/iscsi/ifaces. Para iSCSI de hardware (por ejemplo, qla4xxx) la configuración de interfaz debe tener la dirección de hardware (iface.hwaddress = MAC del puerto) y el nombre del driver/transporte (iface.transport_name). El nombre de la interfaz es entonces el nombre del archivo de configuración de la interfaz. Para iSCSI de software, la configuración de la interfaz debe tener la dirección de hardware (iface.hwaddress), o el nombre de la interfaz de la capa de red (iface.net_ifacename), y debe tener el nombre del driver/transporte.
Los drivers/iscsi_transports disponibles son tcp (iSCSI de software sobre TCP/IP), iser (iSCSI de software sobre InfiniBand), qla4xxx (HBAs QLogic 4XXXX y 82XXX), cxgb3i y cxgb4i (adaptadores Chelsio T3 y T4), bnx2i (adaptadores QLogic Netextreme II), be2iscsi (adaptador Emulex 10G), qedi (adaptador QLogic QEDI de 25/40/100 Gb) y ocs (Emulex One Connect storage). Algunos de estos se consideran experimentales, ya que no están completamente probados.
La dirección_hw es la dirección MAC o para iSCSI de software puede ser el valor especial default que indica al iniciador que no enlace la sesión a un recurso de hardware específico y en su lugar permita que la capa de red o InfiniBand decida qué hacer. No es necesario crear una configuración de interfaz con el comportamiento predeterminado. Si no especifica una interfaz, se utiliza el comportamiento predeterminado.
Como se mencionó anteriormente, existe un nombre de interfaz especial default. Hay otros que no enlazan la sesión a una tarjeta específica, sino que enlazan la sesión al transporte: iser, cxgb3i,

TIPOS DE DESCUBRIMIENTO

iSCSI define 3 tipos de descubrimiento: SendTargets, SLP, e iSNS. SLP no está ampliamente soportado, y no está soportado por este paquete. El soporte de SNS depende de las opciones de compilación, pero está habilitado por defecto.

También se soporta un tipo de descubrimiento especial llamado fw (para firmware), para descubrir interfaces de firmware y poblar la base de datos de interfaces en el proceso.

SendTargets
Un protocolo iSCSI nativo que permite que cada objetivo iSCSI envíe una lista de objetivos disponibles al iniciador.
iSNS
iSNS (Internet Storage Name Service) registra información sobre volúmenes de almacenamiento dentro de una red más grande. Para utilizar iSNS, pase la dirección y, opcionalmente, el puerto del servidor iSNS para realizar el descubrimiento.
fw
Modo firmware. Varias NICs y sistemas contienen un mini iniciador iSCSI que puede usarse para el arranque. Para obtener los valores usados para el arranque, se puede usar la opción fw . Hacer un descubrimiento fw no almacena registros persistentes en la base de datos de node o de descubrimiento, porque los valores están almacenados en los recursos del sistema o de la NIC.
Realizar un descubrimiento fw imprimirá los portales, como con otros métodos de descubrimiento. Para ver otros ajustes como los valores CHAP y los ajustes del iniciador, como lo haría en el modo node , ejecute iscsiadm -m fw.

ESTADO DE SALIDA

Se devuelve 0 en caso de éxito. En caso de error se devolverá uno de los códigos de retorno siguientes.

Los comandos que operan sobre múltiples objetos (sesiones, registros, etc.), iscsiadm/iscsistart devolverán el primer error que se encuentre. iscsiadm/iscsistart intentará ejecutar la operación sobre los objetos que pueda. Si no se encuentran objetos, se devuelve ISCSI_ERR_NO_OBJS_FOUND.

EJEMPLOS

Descubrir objetivos en una dirección IP dada:

sh# iscsiadm --mode discoverydb --type sendtargets --portal 192.168.1.10 --discover

Iniciar sesión, debe usar un id de registro de node encontrado por el descubrimiento:

sh# iscsiadm --mode node --targetname iqn.2001-05.com.doe:test --portal 192.168.1.1:3260 --login

Cerrar sesión:

sh# iscsiadm --mode node --targetname iqn.2001-05.com.doe:test --portal 192.168.1.1:3260 --logout

Listar registros de node:

sh# iscsiadm --mode node

Mostrar todos los datos de un registro de node dado:

sh# iscsiadm --mode node --targetname iqn.2001-05.com.doe:test --portal 192.168.1.1:3260

Listar todas las sesiones:

sh# iscsiadm --mode session

Listar todas las sesiones en formato de árbol:

sh# iscsiadm --mode session --print
