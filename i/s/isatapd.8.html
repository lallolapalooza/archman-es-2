isatapd(8) Cliente ISATAP para Linux isatapd(8)

NOMBRE

isatapd - Cliente ISATAP para Linux

SINOPSIS

isatapd --help
isatapd [ --daemon ] [ --link dispositivo ] [ opciones ] [ router ] [ ... ]

DESCRIPCIÓN

isatapd es un programa o demonio de espacio de usuario que configura y mantiene un túnel cliente ISATAP utilizando las capacidades ISATAP del núcleo, introducidas por primera vez con la versión 2.6.25.

El programa creará el túnel, consultará periódicamente los routers especificados, los añadirá a la lista de routers potenciales , enviará solicitudes periódicas de router y analizará los anuncios de router. isatapd intentará mantener el túnel activo y funcionando, incluso si la topología de la red cambia.

Vea NOTAS más abajo para más información.

OPCIONES

-n --name nombre
Nombre de la interfaz del túnel. Por defecto es is0.
-l --link dispositivo
Dispositivo de enlace del túnel. Si se especifica, el túnel se restringirá a ese dispositivo, permitiendo múltiples instancias de isatapd con diferentes túneles. El túnel solo puede existir mientras el dispositivo de enlace esté activo y tenga configurada una dirección IPv4.

Si no se especifica o se usa 'auto' , la dirección IPv4 de salida se deducirá para el primer router y el túnel se creará en consecuencia. El dispositivo del túnel solo se creará si hay una posible dirección IPv4 de origen para alcanzar al primer router.

-m --mtu bytes
Establece la MTU a bytes para el dispositivo del túnel, el mínimo es 1280. Si no se especifica, 'auto' o 0, el núcleo elegirá la MTU, generalmente 1480.
-t --ttl hoplimit
Establece el hoplimit del túnel, por defecto es 64. Especificar 'auto' o 'inherit' hará que el túnel herede el ttl del dispositivo enlazado.
-N --nopmtudisc
Desactiva el Descubrimiento de MTU de Ruta (IPv4) en este túnel. Para que esto funcione, --ttl debe establecerse en inherit. Por defecto: realizar el Descubrimiento de MTU de Ruta para reducir la fragmentación redundante.
-r --router router
Establece un router potencial. isatapd resolverá el nombre de host, añadirá la dirección IPv4 al PRL y enviará mensajes periódicos de solicitud de router. Se pueden especificar hasta 10 routers potenciales, el valor por defecto es el nombre de dominio no calificado "isatap".
-i --interval segundos
Intervalo por defecto para enviar solicitudes de router. Si la vida útil del router es menor o el intervalo es 'auto' , el intervalo será el 80% de la vida útil del router. Se puede usar para forzar solicitudes con un intervalo más corto.

Por defecto: auto

-D --check-dns segundos
Intervalo para realizar la resolución DNS de los routers configurados y recrear el PRL, si es necesario. Establecer a 0 para desactivar.

Por defecto: 3600 seg = 1 hora

-d --daemon
se divide en segundo plano. Aún no hay registro disponible.
-p --pid archivo
Almacena el pid como texto plano en archivo. El archivo de pid será bloqueado para escritura para evitar múltiples instancias en ejecución. Útil para scripts y al ejecutar isatapd como demonio.
--user nombre de usuario
Reduce los privilegios a este usuario al ejecutar el bucle de solicitudes.

Por defecto: nobody

-v --verbose
aumenta la verbosidad
-q --quiet
disminuye la verbosidad
-h --help
imprime el uso
--version
imprime la versión

ESTADO DE SALIDA

En caso de éxito se devuelve cero , de lo contrario se devuelve un valor distinto de cero .

SEÑALES

SIGHUP
Fuerza el envío de solicitudes de router y recrea el túnel, si es necesario.
SIGINT SIGTERM
Cierra el dispositivo del túnel de forma ordenada y termina.

SYSLOG

isatapd registra en stderr cuando se ejecuta en primer plano y en syslog(3), utilizando la facilidad LOG_DAEMON. La verbosidad puede controlarse con los interruptores -v y -q .

NOTAS

Los datos de red serán procesados por isatapd con privilegios de un usuario no privilegiado para minimizar el impacto de errores en el código de red. Para crear y mantener el dispositivo del túnel, se necesitan privilegios de root.

Cada vez que la interfaz de enlace del túnel se caiga o la dirección de origen para el punto final local del túnel cambie, el dispositivo del túnel será destruido y recreado, si es posible. Tenga en cuenta que hasta entonces su túnel podría estar en un estado inutilizable.
