ISOINFO(8) System Manager's Manual ISOINFO(8)

NOMBRE

devdump, isoinfo, isovfy, isodump - Programas utilitarios para volcar y verificar imágenes iso9660.

SINOPSIS

devdump isoimage

isodump isoimage

isoinfo [ opciones ] [ find [ expresión find ]]

isovfy isoimage

DESCRIPCIÓN

devdump es una utilidad rudimentaria para mostrar interactivamente el contenido de imágenes de dispositivos o sistemas de archivos. La pantalla inicial muestra los primeros 256 bytes del primer sector de 2048 bytes. Los comandos son los mismos que con isodump.

isodump es una utilidad rudimentaria para mostrar interactivamente el contenido de imágenes iso9660 para verificar la integridad de directorios. La pantalla inicial muestra la primera parte del directorio raíz, y el prompt le indica el número de extensión y el desplazamiento dentro de la extensión.

Puede usar los comandos 'a' y 'b' para moverse hacia atrás y hacia adelante dentro de la imagen. El comando 'g' le permite ir a una extensión arbitraria, y el comando 'f' especifica una cadena de búsqueda que se utilizará. El comando '+' busca hacia adelante la siguiente instancia de la cadena de búsqueda, y el comando 'q' sale de devdump o isodump.

isoinfo es una utilidad para realizar listados de directorios similares a los de imágenes iso9660.

isovfy es una utilidad para verificar la integridad de una imagen iso9660. La mayoría de las pruebas en isovfy se añadieron después de que se descubrieran errores en versiones tempranas de mkisofs. No está muy claro cuán útil es esto ahora, pero no hace daño tenerlo disponible.

OPCIONES

Las opciones comunes a todos los programas son -help,-h,-version, i=nombre,dev=nombre. El programa isoinfo tiene opciones adicionales de línea de comandos. Las opciones son:

-help
-h
imprime un resumen de todas las opciones.
-d
Imprime información del descriptor de volumen primario (PVD) de la imagen iso9660. Esto incluye información sobre las extensiones Rock Ridge, Joliet y la información de arranque Eltorito si están presentes.
-f
genera la salida como si se hubiera ejecutado el comando 'find . -print' en la imagen iso9660. No debe usar la imagen -l con la opción -f. La misma salida se crea llamando a isoinfo con -find -print
-find expresión find
Esta opción actúa como un separador. Si se utiliza, todas las opciones de isoinfo deben estar a la izquierda de la opción -find. A la derecha de la opción -find, mkisofs acepta solo la sintaxis de línea de comandos de find. Si la expresión find incluye un primario -print o -ls, el -l de isoinfo se ignora. Si la expresión find se evalúa como verdadera, se realiza la acción seleccionada (por ejemplo, listar el directorio ISO-9660).
-i iso_image
Especifica la ruta de la imagen iso9660 que deseamos examinar. Las opciones -i y dev=target son mutuamente excluyentes.
-ignore-error
Ignora errores. Por defecto, los comandos se abortan en varios errores, como errores de lectura. Con esta opción activa, los comandos intentan continuar. Úselo con cuidado.
dev=target
Establece el objetivo SCSI para la unidad, ver notas anteriores. Una especificación de dispositivo típica es dev=6,0. Si se debe proporcionar un nombre de archivo junto con la especificación numérica del objetivo, el nombre de archivo depende de la implementación. El nombre de archivo correcto en este caso se puede encontrar en los manuales específicos del sistema operativo de destino. En un sistema FreeBSD sin soporte CAM, necesita usar el dispositivo de control (por ejemplo, /dev/rcd0.ctl). Una especificación de dispositivo correcta en este caso puede ser dev=/dev/rcd0.ctl:@.

En Linux, las unidades conectadas a un adaptador de puerto paralelo se mapean a un bus SCSI virtual. Diferentes adaptadores se mapean a diferentes objetivos en este bus SCSI virtual.

Si no está presente la opción dev, el programa intentará obtener el dispositivo del entorno CDR_DEVICE.

Si el argumento de la opción dev= no contiene los caracteres ',', '/', '@' o ':', se interpreta como un nombre de etiqueta que puede encontrarse en el archivo /etc/default/cdrecord (ver sección ARCHIVOS).

Las opciones -i y dev=target son mutuamente excluyentes.

-debug
Imprime información de depuración adicional. Esto habilita, por ejemplo, la impresión de todas las entradas de directorio si un archivo tiene más de una entrada de directorio y la impresión de más información del descriptor de volumen primario.

En modo de depuración, la información Rock Ridge se analiza con -R incluso si no cumple con los estándares.

-l
genera la salida como si se hubiera ejecutado el comando 'ls -lR' en la imagen iso9660. No debe usar la imagen -f con la opción -l.

Los números entre corchetes son el número de sector de inicio como número decimal (basado en 2048 bytes por sector) y las banderas del directorio iso9660 como número hexadecimal según se indica a continuación:

0x00
Un archivo normal (no es realmente una bandera).
0x01
Ocultar el nombre del archivo de las listas de directorios.
0x02
Un directorio.
0x04
Un archivo asociado (por ejemplo, una bifurcación de recursos de Apple).
0x08
Se utiliza el formato de registro en atributos extendidos.
0x10
Sin permiso de lectura/ejecución en atributos extendidos.
0x20
reservado
0x40
reservado
0x80
No es la última entrada de un archivo multisesión.
-N sector
Hack rápido para ayudar a examinar archivos de sesión única que se escribirán en un disco multisesión. El número de sector especificado es el número de sector en el que se escribirá la imagen iso9660 al enviarla al grabador de CD. No se usa para la primera sesión del disco.
-p
Imprime información de la tabla de rutas.
-R
Extrae información de las extensiones Rock Ridge (si están presentes) para permisos, nombres de archivo y posesiones.
-s
Imprime información del tamaño del archivo en múltiplos del tamaño del sector (2048 bytes).
-J
Extrae información de las extensiones Joliet (si están presentes) para nombres de archivo.
-j charset
Convierte los nombres de archivo Joliet (si están presentes) al conjunto de caracteres proporcionado. Ver mkisofs(8) para detalles.
-T sector
Hack rápido para ayudar a examinar imágenes multisesión que ya se han grabado en un disco multisesión. El número de sector especificado es el número de sector para el inicio de la sesión que deseamos mostrar.
-X
Extrae archivos de la imagen y los coloca en el sistema de archivos. Si la opción -find no se utiliza, se extraen todos los archivos.

El programa isoinfo soporta la extracción de todos los archivos, incluso archivos multisesión (archivos > 4 GB).

Antes de extraer archivos utilizando la opción -X, se recomienda cambiar el directorio actual a un directorio vacío para evitar sobrescribir archivos existentes.

-x pathname
Extrae el archivo especificado a stdout. El pathname debe comenzar con una barra ('/') y, en el caso de nombres iso9660, debe coincidir con la ruta completa del archivo, incluido el número de versión (generalmente ';1'). Si se ha especificado la opción -R y el sistema de archivos tiene atributos Rock Ridge, el pathname debe coincidir con la ruta completa de Rock Ridge del archivo.

MEJORAS FUTURAS

Estas utilidades son realmente soluciones rápidas, que son muy útiles para depurar problemas en mkisofs o en un sistema de archivos iso9660. A largo plazo, sería bueno tener un demonio que exportase NFS una imagen iso9660.

El programa isoinfo es probablemente el programa que es de mayor utilidad para el usuario general.

ENTORNO

CDR_DEVICE
Puede contener un identificador de dispositivo adecuado para la llamada open de la biblioteca de transporte SCSI o una etiqueta en el archivo /etc/default/cdrecord.
RSH
Si está presente el entorno RSH, la conexión remota no se creará a través de rcmd(3) sino llamando al programa apuntado por RSH. Use por ejemplo RSH=/usr/bin/ssh para crear una conexión segura de shell.

Tenga en cuenta que esto obliga al programa a crear una tubería con el programa rsh(1) y no permite al programa acceder directamente al socket de red con el servidor remoto. Esto hace imposible establecer parámetros de rendimiento y ralentiza la conexión en comparación con una conexión rcmd(3) iniciada por root.

RSCSI
Si está presente el entorno RSCSI, el servidor SCSI remoto no será el programa /opt/schily/sbin/rscsi sino el programa apuntado por RSCSI. Tenga en cuenta que el nombre del programa servidor SCSI remoto se ignorará si inicia sesión con una cuenta que se ha creado con un programa servidor SCSI remoto como shell de inicio de sesión.

ARCHIVOS

/etc/default/cdrecord
Los valores predeterminados se pueden establecer para las siguientes opciones en /etc/default/cdrecord.
CDR_DEVICE
Puede contener un identificador de dispositivo adecuado para la llamada open de la biblioteca de transporte SCSI o una etiqueta en el archivo /etc/default/cdrecord que permite identificar una unidad específica en el sistema.
Cualquier otra etiqueta
es un identificador para una unidad específica en el sistema. Dicho identificador no puede contener los caracteres ',', '/', '@' o ':'.

Cada línea que sigue a una etiqueta contiene una lista de elementos separados por TAB. Actualmente, se reconocen cuatro elementos: el ID SCSI de la unidad, la velocidad predeterminada que se debe usar para esta unidad, el tamaño FIFO predeterminado que se debe usar para esta unidad y opciones específicas de la unidad. Los valores para velocidad y tamaño_fifo pueden establecerse en -1 para indicar al programa que use los valores predeterminados globales. El valor para driveropts puede establecerse en "" si no se usan driveropts. Una línea típica puede verse así:

teac1= 0,5,0 4 8m ""

yamaha= 1,6,0 -1 -1 burnfree

Esto le dice al programa que una unidad llamada teac1 está en el bus SCSI 0, destino 5, lun 0 y debe usarse con velocidad 4 y un tamaño FIFO de 8 MB. Una segunda unidad puede encontrarse en el bus SCSI 1, destino 6, lun 0 y utiliza la velocidad predeterminada y el tamaño FIFO predeterminado.
