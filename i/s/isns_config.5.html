DESCRIPCIÓ

N

Todas las utilidades de Open-iSNS leen su configuración de un archivo en /etc/isns. Hay un archivo de configuración separado para cada aplicación, isnsd, isnsadm, y isnsdd. La sintaxis y el conjunto de opciones admitidas es idéntica, aunque algunas opciones son específicas de, por ejemplo, el servidor. Salvo que se indique, las opciones se aplican a todas las

utilidades.

Un archivo de configuración de Open-iSNS contiene pares de palabra clave-argumento, uno por línea. Todas las palabras clave no distinguen mayúsculas de

minúsculas.

Un carácter # introduce un comentario, que se extiende hasta el final de la línea. Las líneas vacías se

ignoran.

No hay continuaciones de línea, y no puede usar comillas alrededor de los

argumentos.

Algunas opciones especifican valores de tiempo de espera, que se dan en unidades de segundos de forma predeterminada. Sin embargo, puede especificar una unidad explícita, como d (días), h (horas), m (minutos), o s (segundos)

.

Opciones

genéricas
HostNa
me
De forma predeterminada, las aplicaciones de Open-iSNS obtendrán el nombre de host de la máquina utilizando la llamada al sistema gethostname(3), y usarán una búsqueda DNS para buscar el nombre canónico. Utilizando la opción HostName, puede anular esto. Esta opción rara vez es
necesaria.
SourceNa
me
Esta opción es obligatoria para todas las aplicaciones de Open-iSNS. Debe ser un nombre que identifique al cliente de forma única. Hay dos interpretaciones de la RFC 4171; una requiere que este sea un nombre calificado iSCSI como iqn.2001-04.com.example.host, mientras que otro lenguaje de la RFC sugiere que esto es prácticamente una cadena de for
mato libre que solo tiene que ser única (usando, por eje
mplo, el nombre de dominio totalmente calificado del cliente).
Al usar autenticación DSA, Open-iSNS actualmente requiere que el nombre de origen coincida con el identificador de clave (SPI) de la clave pública del
cliente.
Si se deja vacío, el nombre de origen se deriva del nombre de iniciador predeterminado en /etc/iscsi/initiatorname.iscsi o, si no, del nombre de host del cliente utilizando la opción IQNPrefix para generar un
nombre c
alificado iSCSI.
IQNPref
ix
Especifica el prefijo del nombre calificado iSCSI; debe tener la forma iqn.AAAA-MM con AAAA siendo el año y MM el
mes.

Esta opción especifica el nombre de host o la dirección d

::1].
Al especificar un número de puerto, puede usar el puerto numérico o un nombre de cadena para buscar en /etc/services. Cuando se omite el puerto, el valor predeterminado es 3205, el número de puerto asignado por IANA a

Si se usa la cadena especial SLP:, el cliente intentará localizar

Esta opción se usa para especificar cómo se almacena la base de datos. Establecer esto en una ruta de archivo absoluta hará que isnsd guarde su base de datos en

Si deja esto vacío, isnsd guardará su base de datos en memoria.
Esta es también la confi

DefaultDiscoveryDom

iSNS limita la visibilidad de otros nodos utilizando los llamados Dominios de Descub

de almacenamiento B si ambos son miembros del mismo dominio de descubrimiento.
Así que si se registra un nodo de almacenamiento que no forma parte de ningún dominio de descubrimiento, no verá ningún otro
nodo.
Estableciendo DefaultDiscoveryDomain=1, puede indicar a isnsd que cree un dominio de descubrimiento "predeterminado" virtual, que contiene todos los nodos que no forman parte de ningún dominio de descubrimiento configurado administrativame

De forma predeterminada, no

El servidor iSNS puede purgar entidades registradas después de un cierto período de

que registran objetos deben refrescar su registro dentro de este período.
El valor predeterminado es 1 hora. Estab
lecerlo en 0 desactiva la caducidad de

ESIRetri
es
Open-iSNS es capaz de monitorear la accesibilidad de los nodos de almacenamiento y sus portales mediante una característica de protocolo llamada ESI (E
ntity status inquiry). Los clientes solicitan el monitoreo ESI registrando un puerto ESI junto con cada portal. El servidor enviará mensajes ESI
a estos portales a intervalos regulares. Si el portal no responde varias veces seguidas, se considera muerto y se eliminará de la base de datos.
ESIRetries especifica el número máximo de intentos que el servidor hará para contactar con el portal antes de declararlo muerto. Si se establece en 0, el servidor desactivará ESI y rechazará cualquier registro que especifique un puerto ESI con un código de error de "ESI not
supported".
El valor p
redetermi
nado es 3.

Opciones relacionadas con la

seguridad

El estándar iSNS define un método de autenticación basado en el algoritmo DSA. Los participantes en un intercambio de mensajes autentican los mensajes añadiendo un "bloque de autenticación" que contiene una marca de tiempo, una cadena que identifica la clave utilizada y una firma digital del mensaje. El mismo método también es utilizado por SLP, el Protocolo de Ubicación de

Servicios.

La cadena contenida en el bloque de autenticación se conoce como el Índice de Política de Seguridad (SPI). Esta cadena puede ser utilizada por el servidor para buscar la clave pública del cliente por cualquier mecanismo; por lo tanto, la cadena podría usarse como el nombre de un archivo de clave pública en un directorio, o para recuperar un certificado X509 de

LDAP.

Desde la perspectiva de las aplicaciones cliente de Open-iSNS, solo hay dos claves: la clave (privada) del propio cliente, utilizada para firmar los mensajes que envía al servidor, y la clave pública del servidor, utilizada para verificar las firmas de los mensajes entrantes del

servidor.

El servidor iSNS necesita, además de su propia clave privada, acceso a todas las claves públicas de los clientes que se comunicarán con él. Estas últimas se guardan en lo que se denomina un almacén de claves (key store). Los almacenes de claves y su funcionamiento se discutirán en la sección Almacenes de claves y políticas más

abajo.

Las siguientes opciones de configuración controlan la

autenticación:
Securi
ty
Esto habilita o deshabilita la autenticación DSA. Cuando se
establece en 1, el cliente firmará todos los mensajes y e
sperará que todos los mensajes del servidor estén firmados.
Al habilitar la seguridad en el servidor, los mensajes entrantes se comprueban para ver si contienen un bloque de autenticación. Si no hay ninguno presente, o si el servidor no puede encontrar una clave pública correspondiente al SPI, el mensaje se trata como originado por una fuente anónima. Si el SPI es conocido pero la firma es incorrecta, el mensaje se descarta
silenciosamente.
A los mensajes de una fuente anónima se les asignará una política muy restrictiva que solo permite consultas a la base de
datos.
Establecer esta opción en 0 desactivará la
autenticación.
El valor por defecto es -1, lo que indica a iSNS que us
e autenticación si las claves requeridas están instalad
as, y que use iSNS sin autenticación en caso contrario.
AuthNa
me
Esta es la cadena que se usará como SPI en todos los mensajes salientes que tengan un bloque de autenticación. Por defecto es el nombre del host (por favor, consulte la opción HostNam
e).
AuthKeyFi
le
Esta es la ruta de un archivo que contiene una clave DSA codificada en PEM. Esta clave se utiliza para firmar los mensajes salientes. El valor por defecto es /etc/isns/aut
h_key.
ServerKeyFi
le
Esta opción solo la utilizan las aplicaciones cliente y especifica la ruta de un archivo que contiene una clave DSA codificada en PEM. Esta clave se utiliza para autenticar las respuestas del servidor. El valor por defecto es /etc/isns/server_
key.pub.
KeySto
re
Esta opción del lado del servidor esp
ecifica el almacén de claves a utiliz
ar, descrito en la siguiente sección.

Las siguientes dos opciones controlan cómo iSNS verificará la marca de tiempo contenida en el bloque de autenticación, que se supone que previene los ataques de repetición (replay)

.
Auth.
ReplayWindow
Para compensar la deriva del reloj entre dos hosts que intercambian mensajes iSNS, Open-iSNS aplicará un pequeño margen de error al c
omparar la marca de tiempo contenida en el mensaje con la hora local del sistema. Si la diferencia entre la marca de tiempo y la hora
local del sistema es menor que el número de segundos indicado por esta opción, el mensaje es aceptable. De lo contrario, se rechaza.
El valor por defecto es 5m
.
Auth.
TimestampJitter
Al verificar los mensajes entrantes, Open-iSNS comprueba que las marcas de tiempo enviadas por el par aumenten monótonamente. Para compensar el reordenamiento de los mensajes por la red (por ejemplo, al usar UDP como transporte), se acepta cierto margen de error en la marca de tiempo. Si la marca de tiempo de un mensaje entrante no es anterior a TimestampJitter segundos antes de la última marca de tiempo recibi
da, entonces el mensaje es aceptable
. De lo contrario, se rechaza.
El valor por defecto es 1
s
.

Almacenes de claves y

políticas

La implementación actual soporta dos tipos de almacenes de

claves.

El almacén de claves simple utiliza un directorio plano para almacenar las claves públicas, cada clave en su propio archivo. Se espera que el archivo contenga la clave pública del cliente codificada en PEM, y debe usar el SPI del cliente como nombre. Este tipo de almacén de claves no es realmente recomendado, ya que no almacena ninguna información de

política.

Un almacén de claves simple se puede configurar estableciendo la opción KeyStore a la ruta del

directorio.

El enfoque recomendado es usar la base de datos como almacén de claves. Este utiliza objetos de política específicos del proveedor para vincular la cadena SPI, la clave pública, el nombre de la entidad, el nombre de origen y otros aspectos de la política, y almacenarlos de forma

persistente.

El almacén de claves de la base de datos se configura estableciendo la opción KeyStore al valor reservado DB:, que también es el valor por

defecto.

Actualmente, los objetos de política de Open-iSNS tienen los siguientes atributos, además del

SPI:
Sourc
e:
Este es el nombre del nodo de origen que el cliente debe usar. Por defecto es la cadena del
SPI.
Function
s:
Este es un mapa de bits que detalla qué funciones tiene permitido invocar el cliente. Los nombres de los bits corresponden a los nombres abreviados utilizados en RFC 4171, como DevAttrReg, DevAttrQry, etc. Por defecto se permite el registro, la consulta y la anulación del registro, así como
SCNRegister.
Nombre de la
entidad:
Este es el nombre de la entidad asignado al cliente. Si está establecido, al cliente no se le permite usar un nombre de entidad diferente en un registro. Si el cliente envía un registro sin identificador de entidad, el servidor asignará el nombre de la entidad dado en la política. Por defecto no se restringe el nombre de la
entidad.
Acceso a
objetos:
Este es un campo de bits que describe los permisos de acceso para cada tipo de objeto. Para cada tipo de objeto, puedes conceder permisos de Lectura y/o Escritura. El acceso de lectura se aplica a las llamadas Query y GetNext; todas las demás operaciones requieren permiso de escritura. Por defecto se concede acceso de lectura y escritura a los objetos de tipo Entidad, Nodo de Almacenamiento, Portal y Grupo de Portal; y acceso de lectura a los Dominios de
Descubrimiento.
Tipos de
nodos:
Este campo de bits describe qué tipos de nodos de almacenamiento tiene permitido registrar un cliente; los nombres de bits válidos son target, initiator y control. Por defecto se restringe
a los nodos par
a que solo regist
ren iniciadores.
