NOMBRE

iscsi-test-cu - suite de pruebas para iSCSI/SCSI

SINOPSIS

iscsi-test-cu [ OPCIONES ] <PORTAL_ISCSI>

iscsi-test-cu [-i --nombre-iniciador=<IQN>] [-I --nombre-iniciador-2=<IQN>] [-l --listar] [-t --test=<familia>|*[.<suite>|*[.<test>|*]]] [-d --perdida-datos] [-s --permitir-sanitizar] [-V --Verbose-scsi] [-x --xml] [-? --ayuda]

DESCRIPCIÓN

iscsi-test-cu es una suite de pruebas para iSCSI/SCSI.

FORMATO URL PORTAL ISCSI

El formato del portal iSCSI es 'iscsi://[<usuario>[%<contraseña>]@]<host>[:<puerto>]/<nombre-iqn>/<lun>'

El puerto es el puerto TCP en el destino al que conectarse. Por defecto es 3260.

El nombre de usuario y la contraseña solo son necesarios si el destino requiere autenticación CHAP. Opcionalmente, puede especificar el nombre de usuario y la contraseña a través de las variables de entorno LIBISCSI_CHAP_USERNAME y LIBISCSI_CHAP_PASSWORD.

El host puede especificarse como un nombre de host, una dirección IPv4 o una dirección IPv6. Ejemplos:

	iscsi://192.0.2.1/iqn.ronnie.test/1
	iscsi://[2001:DB8::1]:3261/iqn.ronnie.test/1
	iscsi://ronnie%password@iscsi.example.com/iqn.ronnie.test/1

OPCIONES

-i --nombre-iniciador=<IQN>

Todas las pruebas utilizan al menos una conexión iSCSI al destino y este es el nombre del iniciador utilizado para esa sesión principal y, por defecto, es 'iqn.2007-10.com.github:sahlberg:libiscsi:iscsi-test'

Este argumento se utiliza para cambiar el nombre del iniciador que se usará para la sesión principal.

-I --nombre-iniciador-2=<IQN>

Algunas pruebas utilizan una segunda conexión al destino, como las 'pruebas de pérdida de nexos it'. El nombre por defecto utilizado para esta segunda conexión es 'iqn.2007-10.com.github:sahlberg:libiscsi:iscsi-test-2'

Este argumento se utiliza para cambiar el nombre del iniciador que se usará para la sesión secundaria.

-l --listar

Este argumento lista todas las pruebas disponibles.

Las pruebas se dividen en 'familias', 'suites' y 'pruebas' separadas por '.'.

iscsi-test-cu -l
ALL
ALL.CompareAndWrite
ALL.CompareAndWrite.Simple
ALL.CompareAndWrite.Miscompare
ALL.GetLBAStatus
ALL.GetLBAStatus.Simple
ALL.GetLBAStatus.BeyondEol
...

-t --test=<familia>|*[.<suite>|*[.<test>|*]]

Este argumento especifica una lista separada por comas de las expresiones de prueba a ejecutar. Si se omite este argumento, se ejecutarán todas las pruebas. También puede especificar un nombre de archivo del que leer la lista de pruebas. 
Para ejecutar todas las pruebas:
iscsi-test-cu --test=ALL iscsi://192.0.2.1/iqn.ronnie/test/1
Para ejecutar la suite de pruebas READ16:
iscsi-test-cu --test=SCSI.Read16.* \
  iscsi://192.0.2.1/iqn.ronnie/test/1
Para ejecutar solo una prueba específica:
iscsi-test-cu --test=iSCSI.iSCSIResiduals.Read10Invalid \
  iscsi://192.0.2.1/iqn.ronnie/test/1
Ejecutar todas las pruebas en la suite TestUnitReady y también la prueba Reaqd16.Flags
iscsi-test-cu --test=SCSI.TestUnitReady.*,SCSI.Read16.Flags \
  iscsi://192.0.2.1/iqn.ronnie/test/1
Ejecutar todas las pruebas listadas en el archivo ~/tests-to-run
iscsi-test-cu --test=~/tests-to-run
  iscsi://192.0.2.1/iqn.ronnie/test/1

-d --perdida-datos

Por defecto, la herramienta de prueba solo ejecutará pruebas no destructivas. Para probar comandos que mutan los datos, como las pruebas Write*, debe especificar la bandera --perdida-datos.

Las pruebas que requieren --perdida-datos sobrescribirán los datos en el LUN y cualquier dato en ese LUN se destruirá al ejecutar estas pruebas.

-s --permitir-sanitizar

Se espera que la operación SBC SANITIZE tarde un tiempo considerable antes de completarse, por lo que las pruebas para esta operación no son adecuadas para ejecuciones normales de pruebas.

Por defecto, se omitirán todas las pruebas de SBC SANITIZE. Utilice estos argumentos si realmente desea realizar pruebas de SANITIZE.

-V --Verbose-scsi

Las pruebas intentan ser auto-documentadas. Al especificar la bandera -V, la herramienta de prueba imprimirá todos los comandos SCSI que se envían al dispositivo, los argumentos y el resultado esperado.

Si una prueba falla, vuelva a ejecutar la prueba que falla con el argumento -V para ver por qué falló. Si eso también falla, es hora de usar Wireshark y ver qué sucedió.

iscsi-test-cu --test SCSI.Read10.BeyondEol iscsi://192.0.2.1/iqn.ronnie.test/1 -V
Suite: Read10
  Test: BeyondEol ... 
    Test READ10 1-256 blocks one block beyond the end
    Send READ10 (Expecting LBA_OUT_OF_RANGE) LBA:2097152 blocks:1 rdprotect:0 dpo:0 fua:0 fua_nv:0 group:0
    [OK] READ10 returned ILLEGAL_REQUEST/LBA_OUT_OF_RANGE.
...

-x --xml

Esta opción produce resultados de prueba en formato legible por máquina para pruebas automatizadas.

iscsi-test-cu puede producir resultados de prueba legibles por máquina para que los consuma su servidor de CI. Utilice la opción --xml con cualquier suite de pruebas, y se escribirá un archivo llamado CUnitAutomated-Results.xml en su directorio de trabajo actual. Estos resultados se pueden convertir al formato JUnit usando este script: http://git.cyrusimap.org/cyrus-imapd/plain/cunit/cunit-to-junit.pl

El estado de retorno del script refleja si las pruebas fueron exitosas o no. Si prefiere que el script devuelva un estado que refleje si la conversión de cunit a junit fue exitosa, puede parchear el script con esto:

diff --git a/cunit-to-junit.pl.orig b/cunit-to-junit.pl
index 7cf9320..9182ff0 100644
--- a/cunit-to-junit.pl.orig
+++ b/cunit-to-junit.pl
@@ -226,4 +226,4 @@ foreach my $s (@suites)
 }
 print "$0: ran $nrun tests, $nfailed failed\n";
-exit(1) if ($nfailed > 0);
+#exit(1) if ($nfailed > 0);

-? --ayuda

Muestra un texto de ayuda básico.
