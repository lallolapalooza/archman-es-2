integer function ilaenv (integer ispec, character*( * ) name, character*( * ) opts, integer n1, integer n2, integer n3, integer n4)

ILAENV

Propósito:

!>
!> ILAENV devuelve parámetros dependientes del problema para el entorno local.
!> Vea ISPEC para una descripción de los parámetros.
!>
!> En esta versión, los parámetros dependientes del problema están contenidos en
!> el arreglo de enteros IPARMS en el bloque común CLAENV y el valor
!> con índice ISPEC se copia a ILAENV. Esta versión de ILAENV se
!> utilizará junto con XLAENV en TESTING y TIMING.
!>

Parámetros

ISPEC 
!>          ISPEC es INTEGER
!>          Especifica el parámetro que se devolverá como valor de
!>          ILAENV.
!>          = 1: el tamaño de bloque óptimo; si este valor es 1, un algoritmo
!>               no bloqueado dará el mejor rendimiento.
!>          = 2: el tamaño de bloque mínimo para el cual la rutina bloqueada
!>               debe usarse; si el tamaño de bloque utilizable es menor que
!>               este valor, se debe usar una rutina no bloqueada.
!>          = 3: el punto de cruce (en una rutina bloqueada, para N menor
!>               que este valor, se debe usar una rutina no bloqueada)
!>          = 4: el número de desplazamientos, utilizado en las rutinas de
!>               valores propios no simétricos
!>          = 5: el tamaño de columna mínimo para el cual se utilizará el
!>               bloqueo; los bloques rectangulares deben tener una dimensión
!>               de al menos k por m, donde k viene dado por ILAENV(2,...) y
!>               m por ILAENV(5,...)
!>          = 6: el punto de cruce para SVD (al reducir una matriz m por n
!>               a forma bidiagonal, si max(m,n)/min(m,n) excede
!>               este valor, se usa primero una factorización QR para reducir
!>               la matriz a una forma triangular).
!>          = 7: el número de procesadores
!>          = 8: el punto de cruce para los métodos QR y QZ multidesplazamiento
!>               para problemas de valores propios no simétricos.
!>          = 9: el tamaño máximo de los subproblemas en la parte inferior del
!>               árbol de cómputo en el algoritmo divide y vencerás
!>          =10: la aritmética NaN ieee puede ser de confianza para no
!>               detectar trampas
!>          =11: la aritmética infinita puede ser de confianza para no
!>               detectar trampas
!>
!>          Se pueden agregar otras especificaciones (hasta 100) más adelante.
!>

NAME

!>          NAME es CHARACTER*(*)
!>          El nombre de la subrutina que llama.
!>

OPTS

!>          OPTS es CHARACTER*(*)
!>          Las opciones de caracteres para la subrutina NAME, concatenadas
!>          en una sola cadena de caracteres. Por ejemplo, UPLO = 'U',
!>          TRANS = 'T', y DIAG = 'N' para una rutina triangular se
!>          especificarían como OPTS = 'UTN'.
!>

N1

!>          N1 es INTEGER
!>

N2

!>          N2 es INTEGER
!>

N3

!>          N3 es INTEGER
!>

N4

!>          N4 es INTEGER
!>
!>          Dimensiones del problema para la subrutina NAME; puede que no todas
!>          sean necesarias.
!>

Devuelve

ILAENV 
!>          ILAENV es INTEGER
!>          >= 0: el valor del parámetro especificado por ISPEC
!>          < 0:  si ILAENV = -k, el k-ésimo argumento tenía un valor ilegal.
!>

Detalles Adicionales:

!>
!>  Las siguientes convenciones se han utilizado al llamar a ILAENV desde las
!>  rutinas LAPACK:
!>  1)  OPTS es una concatenación de todas las opciones de caracteres de la
!>      subrutina NAME, en el mismo orden en que aparecen en la lista de
!>      argumentos para NAME, incluso si no se utilizan para determinar
!>      el valor del parámetro especificado por ISPEC.
!>  2)  Las dimensiones del problema N1, N2, N3, N4 se especifican en el orden
!>      en que aparecen en la lista de argumentos para NAME. N1 se usa
!!>      primero, N2 segundo, y así sucesivamente, y las dimensiones del
!>      problema no utilizadas se pasan con un valor de -1.
!>  3)  El valor del parámetro devuelto por ILAENV se verifica en cuanto a
!>      validez en la subrutina de llamada. Por ejemplo, ILAENV se utiliza
!>      para recuperar el tamaño de bloque óptimo para STRTRI de la siguiente
!>      manera:
!>
!>      NB = ILAENV( 1, 'STRTRI', UPLO // DIAG, N, -1, -1, -1 )
!>      IF( NB.LE.1 ) NB = MAX( 1, N )
!>
