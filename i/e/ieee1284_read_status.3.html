ieee1284_read_status(3)

Paquete: libieee1284

Licencias: GPL-2.0-or-later

IEEE1284_STATUS(3) Funciones IEEE1284_STATUS(3)

NOMBRE

ieee1284_read_status, ieee1284_wait_status - analizar líneas de estado

SINOPSIS

#include <ieee1284.h>

int ieee1284_read_status(struct parport *port);

int ieee1284_wait_status(struct parport *port, unsigned char mask, unsigned char val, struct timeval *timeout);

DESCRIPCIÓN

Hay cinco líneas de estado, una de las cuales suele estar invertida en los puertos tipo PC. Donde difieren, libieee1284 opera sobre los valores IEEE 1284, no sobre los valores invertidos tipo PC. Las líneas de estado se representan mediante la siguiente enumeración:

enum ieee1284_status_bits
{
  S1284_NFAULT = 0x08,
  S1284_SELECT = 0x10,
  S1284_PERROR = 0x20,
  S1284_NACK   = 0x40,
  S1284_BUSY   = 0x80,
  /* Para convertir esos valores a valores de registro tipo PC, usa esto: */
  S1284_INVERTED = S1284_BUSY,
};

Todas estas funciones actúan sobre el puerto paralelo asociado a port, el cual debe estar reclamado.

El propósito de ieee1284_wait_status es esperar hasta que líneas de estado particulares tengan valores especificados. Su parámetro timeout puede ser modificado al regresar.

VALOR DE RETORNO

Para ieee1284_read_status, el valor de retorno es un entero no negativo con los bits establecidos según corresponda, representando las líneas de estado. Un resultado negativo indica un error.

Para ieee1284_wait_status, el valor de retorno es E1284_OK si las líneas de estado ahora reflejan los valores deseados (es decir, status & mask es val), o un resultado negativo que indica un error.

Códigos de error posibles:

E1284_NOTIMPL

El port carece de la capacidad requerida. Esto podría ser debido a una limitación de esta versión de libieee1284, o una limitación de hardware.

E1284_NOTAVAIL

El acceso a las líneas de estado no está disponible en este tipo de puerto.

E1284_TIMEDOUT

El timeout ha expirado.

E1284_INVALIDPORT

El parámetro port es inválido (por ejemplo, quizás el port no está reclamado).

NOTAS

El pin nAck a menudo puede disparar interrupciones en la máquina host. Con ayuda del sistema operativo, estas interrupciones pueden ser visibles para la aplicación a través del descriptor de archivo devuelto por ieee1284_get_irq_fd.

Bajo Linux, las condiciones son que el controlador del puerto paralelo sepa qué línea de interrupción usar y la esté usando, y que el nodo de dispositivo /dev/parport relevante sea accesible y esté respaldado por un controlador de dispositivo.
