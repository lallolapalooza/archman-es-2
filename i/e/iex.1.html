NOMBRE

iex — El shell de Elixir

SINOPSIS

iex [OPCIONES]

DESCRIPCIÓN

El shell interactivo se utiliza para la evaluación, depuración e introspección del sistema de tiempo de ejecución de Elixir. También es posible usar el programa para probar el funcionamiento de pequeños fragmentos de código sin pasar por la etapa de guardar el código en un archivo.

OPCIONES

Tenga en cuenta que muchas de las opciones mencionadas aquí fueron tomadas del shell de Erlang, por lo tanto erl(1) puede usarse como fuente adicional de información sobre las opciones.

-h, --help
Muestra el mensaje de ayuda en el error estándar (stderr) y sale.
-v, --version
Muestra la versión de Elixir en la salida estándar (stdout) y sale.
-e, --eval expression
Evalúa la expresión especificada (véase la opción --rpc-eval opción).
-r file
Requiere el archivo especificado. En otras palabras, se comprueba la existencia del archivo al inicio de iex.
-S script
Ejecuta el script especificado.
-pa directory
Añade el directorio especificado al principio de la ruta de código. Si el directorio ya existe, se eliminará de su posición antigua y se pondrá al principio.

Véase también la función Code.prepend_path/1.

-pr file
Hace lo mismo que -r (véase arriba) pero en paralelo.
-pz directory
Añade el directorio especificado al final de la ruta de código. Si el directorio ya existe, no se eliminará de su posición antigua ni se pondrá al final.

Véase también la función Code.append_path/1.

--app application
Inicia la aplicación especificada y todas sus dependencias.
--boot file
Especifica el nombre del archivo de arranque, file.boot, que se utiliza para iniciar el sistema. A menos que File contenga una ruta absoluta, el sistema busca file.boot en los directorios actuales y $ROOT/bin.

Por defecto es $ROOT/bin/start.boot.

La opción es equivalente a la de Erlang -boot.

--boot-var var dir
Si el script de arranque contiene una variable de ruta var distinta de $ROOT, esta variable se expande a dir. Se usa cuando las aplicaciones están instaladas en un directorio distinto de $ROOT/lib.

La opción es equivalente a la de Erlang -boot_var.

Véase también la función :systools.make_script/1,2 en SASL.

--erl parameters
Sirve el mismo propósito que ELIXIR_ERL_OPTIONS (véase la sección ENTORNO)
--erl-config file
Especifica el nombre de un archivo de configuración, file.config, que se utiliza para configurar las aplicaciones. Tenga en cuenta que el archivo de configuración debe estar escrito en Erlang.

La opción es equivalente a la de Erlang -config.

--cookie value
Especifica el valor de la cookie mágica. Si el valor no se especifica mediante la opción cuando el nodo se inicia, se tomará del archivo ~/.erlang.cookie (véase la sección ARCHIVOS). Los nodos distribuidos solo pueden interactuar entre sí cuando sus cookies mágicas son iguales.

Véase también la función Node.set_cookie/2.

--hidden
Inicia un nodo oculto.

Las conexiones entre nodos son transitivas. Por ejemplo, si el nodo A está conectado al nodo B, y el nodo B está conectado al nodo C, entonces el nodo A está conectado al nodo C. La opción --hidden permite crear un nodo que pueda conectarse a otro nodo, evitando conexiones redundantes.

La función Node.list/0 permite obtener la lista de nodos conectados al nodo de destino; sin embargo, la lista no incluirá los nodos ocultos. Dependiendo del parámetro de entrada, la función Node.list/1 permite obtener la lista que contiene solo nodos ocultos (el parámetro :hidden) o tanto nodos ocultos como no ocultos (el parámetro :connected).

--logger-otp-reports val
Habilita o deshabilita los informes de OTP (val puede ser true o false).
--logger-sasl-reports val
Habilita o deshabilita los informes de SASL (val puede ser true o false).
--sname name
Da a un nodo un nombre corto y lo inicia. Los nombres cortos tienen la forma de name@host, donde host es el nombre del host de destino (hostname(1)) que ejecuta el nodo. Los nodos con nombres cortos solo pueden interactuar entre sí en la misma red local.
--name name
Da a un nodo un nombre largo y lo inicia. Los nombres largos tienen la forma de name@host, donde host es la dirección IP del host que ejecuta el nodo. A diferencia de los nodos con nombres cortos, los nodos con nombres largos no están limitados por los límites de una red local (véase arriba).
--pipe-to pipedir logdir
Inicia la VM de Erlang como un pipedir y logdir con nombre (solo para sistemas operativos tipo Unix).
--rpc-eval node expression
Evalúa la expresión especificada en el nodo especificado (véase la opción --eval opción).
--vm-args file
Lee los argumentos de la línea de comandos de file y los pasa a la VM de Erlang.

La opción es equivalente a la de Erlang -args_file.

OPCIONES

--dot-iex archivo
Carga el archivo especificado en lugar de .iex.exs (ver la SECCIÓN DE ARCHIVOS).
--remsh nodo
Se conecta al nodo especificado que se inició con las opciones --sname o --name (ver arriba).
--
Separa las opciones pasadas al compilador de las opciones pasadas al código ejecutado.

NOTAS

Las siguientes opciones pueden especificarse más de una vez: --boot-var, --erl-config, --eval, --rpc-eval.

ENTORNO

ELIXIR_ERL_OPTIONS
Permite pasar parámetros al tiempo de ejecución de Erlang.

ARCHIVOS

~/.erlang.cookie
Almacena el valor de la "magic cookie" que solo se utiliza cuando no se especificó mediante la opción --cookie (ver arriba). Si el archivo no existe al iniciar un nodo, se creará.
.iex.exs
Después de que iex se inicia, busca el archivo .iex.exs y, si tiene éxito, ejecuta el código del archivo en el contexto del shell. Primero, la búsqueda comienza en el directorio de trabajo actual; luego, si es necesario, continúa en el directorio de inicio.
