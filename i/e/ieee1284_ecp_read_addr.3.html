DESCRIPCIÓ

N

Este conjunto de funciones sirve para transferir bytes en el modo de transferencia correspondiente. Para los modos ECP y EPP son posibles dos tipos de transferencia: datos y dirección (generalmente denominado canal en ECP)

.

El port proporcionado debe ser un puerto

reclamado.

El buffer proporcionado debe tener al menos len bytes de longitud. Al leer, los datos transferidos se almacenan en el buffer; al escribir, los datos que se van a transferir se toman del

buffer.

Para lecturas (del periférico al host): si no hay datos disponibles y F1284_NONBLOCK no está activo, se inicia el temporizador de inactividad. Si se disponen de datos antes de que expire el tiempo de inactividad, se leen; de lo contrario, el valor de retorno será E1284_TIMEDOUT

.

Para escrituras (del host al periférico): si el periférico no está dispuesto a aceptar datos y F1284_NONBLOCK no está activo, se inicia el temporizador de inactividad. Si el periférico indica que está dispuesto a aceptar datos antes de que expire el tiempo de inactividad, se envían; de lo contrario, el valor de retorno será E1284_TIMEDOU

T

Los flags pueden alterar ligeramente el

comportamiento:

F1284_NONBLOC

K
Para lecturas (del periférico al host): si no hay datos disponibles, se retorna inmediatamente (con E1284_TIMEDOUT).

Para escrituras (del host al periférico): si el periférico no está dispuesto a aceptar datos, se retorna inmediatamente (con E1284_TI

MEDO
UT).

F1284_SW

E
No usar asistencia de hardware para la transferencia, sino configurar los pines del puerto paralelo según el protocolo de
línea.

F1284_RLE (solo para

ECP)
Usar codificación por longitud de ejecución (RLE). Si el periférico está en modo ECP con RLE, las llamadas a ieee1284_ecp_read_data deben establecer esta bandera para que el RLE del periférico se interprete correctamente, y las llamadas a ieee1284_ecp_write_data pueden establecer esta bandera para aprovechar el
RLE.

F1284_FASTEPP (solo para

EPP)
Usar transferencias multibyte. Varios bytes se transfieren a la vez usando asistencia de hardware, si hay hardware compatible. El precio de esta mayor velocidad es que el valor de retorno será menos fiable cuando se use esta
bandera.

En el modo ECP, una dirección determinada está activa en un momento dad

o, y corresponde a la aplicación asegurarse de que solo escribe cuando
está en modo directo (forward) y lee cuando está en modo inverso (reverse).

VALOR DE

RETORNO

El valor de retorno es el número de bytes transferidos con éxito o, si es negativo, uno de los

siguientes:

E1284_NOTIMP

L
Esta combinación de modo de transferencia y flags aún no está implementada en
libieee1284.

E1284_TIMEDOU

T
Tiempo de espera agotado esperando el handshake del
periférico.

E1284_NOME

M
No hay suficiente memoria
disponible.

E1284_SY

S
Hubo un problema a nivel del sistema operativo. La variable global errno se ha establecido
adecuadamente.

E1284_INVALIDPOR

T
El parámetro port es inválido (por ejemplo, quizás el port no está reclamado)
.

Si se transfieren algunos bytes con éxito, se retorna ese número. Se retorna un error solo si no se transfieren

bytes.

Para transferencias del host al perifé

rico, todos los datos están en el
periférico cuando la llamada retorna.
