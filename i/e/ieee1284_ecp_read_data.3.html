DESCRIPCIÓN

Este conjunto de funciones sirve para transferir bytes en el modo de transferencia relevante. Para los modos ECP y EPP son posibles dos tipos de transferencia: datos y dirección (comúnmente referido como canal en ECP).

El port proporcionado debe ser un puerto reclamado.

El buffer proporcionado debe tener al menos len bytes de longitud. Al leer, los datos transferidos se almacenan en el buffer; al escribir, los datos a transferir se toman del buffer.

Para lecturas (periférico a host): si no hay datos disponibles y F1284_NONBLOCK no está activo, se inicia el temporizador de inactividad. Si los datos están disponibles antes de que expire el tiempo de espera de inactividad, se leen; de lo contrario, el valor de retorno será E1284_TIMEDOUT.

Para escrituras (host a periférico): si el periférico no está dispuesto a aceptar datos y F1284_NONBLOCK no está activo, se inicia el temporizador de inactividad. Si el periférico indica que está dispuesto a aceptar datos antes de que expire el tiempo de espera de inactividad, se envían; de lo contrario, el valor de retorno será E1284_TIMEDOUT.

Las flags pueden alterar el comportamiento ligeramente:

F1284_NONBLOCK

Para lecturas (periférico a host): si no hay datos disponibles, retornar inmediatamente (con E1284_TIMEDOUT).

Para escrituras (host a periférico): si el periférico no está dispuesto a aceptar datos, retornar inmediatamente (con E1284_TIMEDOUT).

F1284_SWE

No usar asistencia de hardware para la transferencia, sino establecer los pines del puerto paralelo de acuerdo con el protocolo de cableado.

F1284_RLE (solo para ECP)

Usar codificación por longitud de ejecución (RLE). Si el periférico está en modo ECP con RLE, las llamadas a ieee1284_ecp_read_data deben establecer esta bandera para que la RLE del periférico se interprete correctamente, y las llamadas a ieee1284_ecp_write_data pueden establecer esta bandera para aprovechar la RLE.

F1284_FASTEPP (solo para EPP)

Usar transferencias de múltiples bytes. Se transfieren varios bytes a la vez utilizando asistencia de hardware, si hay hardware de soporte presente. El precio de esta mayor velocidad es que el valor de retorno será menos fiable cuando se utilice esta bandera.

Para el modo ECP, una dirección dada está en vigor en un momento determinado, y depende de la aplicación asegurarse de que solo se está escribiendo en modo directo (forward) y leyendo en modo inverso (reverse).

VALOR DE RETORNO

El valor de retorno es el número de bytes transferidos exitosamente o, si es negativo, uno de:

E1284_NOTIMPL

Esta combinación de modo de transferencia y banderas no está implementada todavía en libieee1284.

E1284_TIMEDOUT

Tiempo de espera agotado esperando que el periférico haga handshake.

E1284_NOMEM

No hay suficiente memoria disponible.

E1284_SYS

Hubo un problema a nivel del sistema operativo. La variable global errno se ha establecido apropiadamente.

E1284_INVALIDPORT

El parámetro port es inválido (por ejemplo, quizás el port no está reclamado).

Si se transfieren bytes con éxito, se devuelve ese número. Se devuelve un error solo si no se transfieren bytes.

Para transferencias de host a periférico, todos los datos están en el periférico en el momento en que la llamada retorna.
