IEEE1284_NEGOTIATION(3) Funciones IEEE1284_NEGOTIATION(3)

NOMBRE

ieee1284_negotiate, ieee1284_terminate - Negociación IEEE 1284

SINOPSIS

#include <ieee1284.h>

int ieee1284_negotiate(struct parport *port, int mode);

void ieee1284_terminate(struct parport *port);

DESCRIPCIÓN

Estas funciones son para negociar a y terminar desde modos de transferencia de datos IEEE 1284. El modo por defecto se llama modo de compatibilidad, o en otras palabras, protocolo de impresora normal. Es solo un modo de host a periférico. Existen modos especiales que permiten la transferencia de periférico a host, a los que se puede negociar usando ieee1284_negotiate. La negociación IEEE 1284 es un proceso mediante el cual el host solicita un modo de transferencia y el periférico lo acepta o rechaza. Un dispositivo compatible con IEEE 1284 requerirá una negociación exitosa a un modo particular antes de ser utilizado para la transferencia de datos (pero los dispositivos más simples pueden no hacerlo si solo hablan un modo de transferencia).

Para terminar el modo especial y volver al modo de compatibilidad, use ieee1284_terminate.

Estas funciones actúan sobre el puerto paralelo asociado con port, el cual debe estar reclamado.

Con un dispositivo que cumpla estrictamente con IEEE 1284, necesitará llamar a ieee1284_terminate entre dos llamadas a ieee1284_negotiate para modos distintos de M1284_COMPAT.

MODOS DISPONIBLES

Modos unidireccionales

•M1284_COMPAT: Modo de compatibilidad. Protocolo de impresora normal. Este no es un modo negociado, sino el modo por defecto en ausencia de negociación. ieee1284_negotiate(port, M1284_COMPAT) es equivalente a ieee1284_terminate(port). Este modo de host a periférico se usa para enviar datos a impresoras, y es históricamente el modo que se ha utilizado para ello antes de IEEE 1284.
•M1284_NIBBLE: Modo Nibble. Este modo de periférico a host utiliza las líneas de estado para leer datos del periférico de cuatro bits a la vez.
•M1284_BYTE: Modo Byte. Este modo de periférico a host utiliza las líneas de datos en modo inverso para leer datos del periférico de un byte a la vez.

Modos bidireccionales

•M1284_ECP: Modo ECP. Al entrar en modo ECP es un modo de host a periférico (es decir, hacia adelante), pero puede configurarse en modo inverso usando ieee1284_ecp_fwd_to_rev(3). Es común que el hardware de PC proporcione asistencia con este modo mediante el uso de una FIFO que el host (o, en modo inverso, el periférico) puede llenar, de modo que el hardware pueda realizar el handshaking por sí mismo.
•M1284_EPP: Modo EPP. En este modo bidireccional, la dirección de la transferencia de datos se señala en cada byte.

Variaciones de modo

•M1284_FLAG_DEVICEID: Recuperación de ID de dispositivo. Esta bandera puede combinarse con un modo nibble, byte o ECP para notificar al dispositivo que envíe su ID de dispositivo IEEE 1284 cuando se le solicite datos.
•M1284_BECP: ECP limitado es una modificación de ECP que lo hace más robusto en el punto en que se cambia la dirección. (Desafortunadamente, aún no está implementado en el controlador del kernel de Linux).
•M1284_ECPRLE: ECP con codificación de longitud de ejecución. En este modo, bytes de datos consecutivos del mismo valor pueden transferirse en solo unos pocos ciclos.

VALOR DE RETORNO

E1284_OK

La negociación fue exitosa.

E1284_NOTAVAIL

La negociación no está disponible con este tipo de puerto.

E1284_REJECTED

La negociación fue rechazada por el periférico.

E1284_NEGFAILED

La negociación falló por alguna razón. Quizás el dispositivo no es compatible con IEEE 1284.

E1284_SYS

Ocurrió un error del sistema durante la negociación.

E1284_INVALIDPORT

El parámetro port es inválido (por ejemplo, quizás el port no está reclamado).
