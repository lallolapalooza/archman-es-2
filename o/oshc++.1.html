OPCIONES

Las siguientes opciones se aplican a todos los compiladores envoltorio:

•
--showme: Esta opción tiene varias variantes (ver abajo). Ninguna de las variantes invoca al compilador subyacente; todas proporcionan información sobre cómo se habría invocado el compilador subyacente si --showme no se hubiera utilizado. La opción básica --showme muestra la línea de comandos que se ejecutaría para compilar el programa.

NOTA:

Si se pasa un argumento que no es un nombre de archivo en la línea de comandos, la opción --showme *no* mostrará ninguna bandera adicional. Por ejemplo, tanto "oshcc --showme como oshcc --showme my_source.c mostrarán todas las banderas proporcionadas por el envoltorio. Pero oshcc --showme -v solo mostrará el nombre del compilador subyacente y -v.
  • --showme:compile: Muestra las banderas del compilador que se habrían proporcionado al compilador subyacente.
  • --showme:link: Muestra las banderas del enlazador que se habrían proporcionado al enlazador subyacente.
  • --showme:command: Muestra el comando del compilador subyacente (que puede ser uno o varios tokens).
  • --showme:incdirs: Muestra una lista de directorios delimitada por espacios (pero por lo demás sin decorar) que el compilador envoltorio habría proporcionado al compilador subyacente para indicar dónde se encuentran los archivos de cabecera relevantes.
  • --showme:libdirs: Muestra una lista de directorios delimitada por espacios (pero por lo demás sin decorar) que el compilador envoltorio habría proporcionado al enlazador subyacente para indicar dónde se encuentran las librerías relevantes.
  • --showme:libs Muestra una lista de nombres de librerías delimitada por espacios (pero por lo demás sin decorar) que el compilador envoltorio habría utilizado para enlazar una aplicación. Por ejemplo: mpi open-pal util.
  • --showme:version: Muestra el número de versión de Open MPI.
  • --showme:help: Muestra un breve mensaje de ayuda de uso.

Consulte la página del manual de su compilador subyacente para ver otras opciones que se pueden pasar a través de oshcc.

DESCRIPCIÓN

Conceptualmente, el papel de estos comandos es bastante simple: agregar transparentemente las banderas de compilación y enlace relevantes a la línea de comandos del usuario que son necesarias para compilar / enlazar programas OpenSHMEM, y luego invocar al compilador subyacente para realizar realmente el comando.

Como tales, estos comandos a menudo se denominan compiladores "envoltorio" porque en realidad no compilan ni enlazan aplicaciones por sí mismos; solo agregan banderas a la línea de comandos e invocan al compilador de backend.

ANTECEDENTES

Open MPI proporciona compiladores envoltorio para varios idiomas:

  • oshcc, shmemcc: C
  • oshc++, oshcxx, shmemc++, shmemcxx`:: C++
  • oshfort, shmemfort: Fortran

Los compiladores envoltorio para cada uno de los idiomas son idénticos; se pueden usar indistintamente. Los diferentes nombres se proporcionan únicamente por compatibilidad con versiones anteriores.

NOTAS FORTRAN

El compilador envoltorio de Fortran para OpenSHMEM (oshfort y shmemfort) puede compilar y enlazar aplicaciones OpenSHMEM que usan cualquiera/todas las enlaces de Fortran de OpenSHMEM.

Sin embargo, tenga en cuenta que el compilador de Fortran puede requerir opciones de línea de comandos adicionales para imponer un dialecto de Fortran específico. Por ejemplo, en algunas versiones del compilador IBM XLF, si xlf90 es el compilador de Fortran subyacente, puede ser necesario -qfixed para compilar archivos fuente de Fortran de formato fijo.

Finalmente, tenga en cuenta que oshfort será inoperante y devolverá un error al usarse si el soporte de Fortran no se compiló en la capa de OpenSHMEM.

VISIÓN GENERAL

oshcc y shmemcc son envoltorios de conveniencia para el compilador C subyacente. La traducción de un programa OpenSHMEM requiere el enlace de las librerías específicas de OpenSHMEM que pueden no residir en uno de los directorios de búsqueda estándar de ld(1). También a menudo requiere la inclusión de archivos de cabecera que pueden no encontrarse en una ubicación estándar.

oshcc y shmemcc pasan sus argumentos al compilador C subyacente junto con las opciones -I, -L y -l requeridas por los programas OpenSHMEM.

Lo mismo ocurre con todos los demás compiladores envoltorio de idiomas.

El Equipo de OpenSHMEM *insta* encarecidamente a usar los compiladores envoltorio en lugar de intentar enlazar las librerías de OpenSHMEM manualmente. Esto permite que la implementación específica de OpenSHMEM cambie sin forzar cambios en las directivas del enlazador en los Makefiles de los usuarios. De hecho, el conjunto específico de banderas y librerías utilizadas por los compiladores envoltorio depende de cómo se configuró y compiló OpenSHMEM; los valores pueden cambiar entre diferentes instalaciones de la misma versión de OpenSHMEM.

De hecho, dado que los envoltorios son simplemente capas delgadas sobre un compilador subyacente, hay muy, muy pocas razones convincentes para *no* usar oshcc. Cuando no es posible usar los envoltorios directamente, se deben usar las opciones --showme:compile y --showme:link para determinar qué banderas usarían los envoltorios. Por ejemplo:

shell$ cc -c file1.c `shmemcc --showme:compile`
shell$ cc -c file2.c `shmemcc --showme:compile`
shell$ cc file1.o file2.o `shmemcc --showme:link` -o my_oshmem_program

NOTAS

Es posible hacer que los compiladores envoltorio sean conscientes de múltiples bibliotecas. Es decir, las bibliotecas e inclusiones especificadas pueden diferir según las banderas del compilador especificadas (por ejemplo, con los compiladores GNU en Linux, se puede usar una ruta de biblioteca diferente si se ve -m32 en comparación con si se ve -m64). Este no es el comportamiento predeterminado en una compilación estándar, pero puede activarse (por ejemplo, en un paquete binario que proporcione soporte para 32 y 64 bits). Se puede encontrar más información aquí.

ARCHIVOS

Las cadenas que los compiladores envoltorio insertan en la línea de comandos antes de invocar al compilador subyacente se almacenan en un archivo de texto creado por OpenSHMEM y instalado en $pkgdata/NOMBRE-wrapper-data.txt, donde:

  • $pkgdata suele ser $prefix/share/openmpi
  • $prefix es el directorio de instalación superior de OpenSHMEM
  • NOMBRE es el nombre del compilador envoltorio (por ejemplo, $pkgdata/shmemcc-wrapper-data.txt)

Raramente es necesario editar estos archivos, pero se pueden examinar para obtener información sobre qué banderas colocan los envoltorios en la línea de comandos.

VARIABLES DE ENTORNO

Por defecto, los envoltorios utilizan los compiladores que fueron seleccionados cuando OpenSHMEM fue configurado. Estos compiladores fueron encontrados automáticamente por el script “configure” de Open MPI, o fueron seleccionados por el usuario en las variables de entorno CC, CXX y/o FC antes de que se invocara configure. Adicionalmente, otros argumentos específicos del compilador pueden haber sido seleccionados por configure.

Estos valores pueden ser anulados selectivamente editando los archivos de texto que contienen esta información de configuración (ver la sección ARCHIVOS), o estableciendo variables de entorno seleccionadas.

ENVIRONMENT VARIABLES

The oshc++ command supports a number of environment variables that can be used to control the behavior of the underlying compiler and linker. These variables are often used by build systems to configure how the Open SHMEM C++ wrapper compiler is invoked. All environment variables are of the form oshmem_value.

Valid value names are:

  • CPPFLAGS: Flags added when invoking the preprocessor (C or C++)
  • LDFLAGS: Flags added when invoking the linker (C, C++, or Fortran)
  • LIBS: Libraries added when invoking the linker (C, C++, or Fortran)
  • CC: C compiler
  • CFLAGS: C compiler flags
  • CXX: C++ compiler
  • CXXFLAGS: C++ compiler flags
  • FC: Fortran compiler
  • FCFLAGS: Fortran compiler flags
