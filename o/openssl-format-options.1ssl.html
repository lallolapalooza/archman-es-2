NOMBRE

openssl-format-options - Opciones de formato de entrada y salida del comando OpenSSL

SINOPSIS

openssl comando [ opciones ... ] [ parámetros ... ]

DESCRIPCIÓN

Varios comandos de OpenSSL pueden aceptar entrada o generar salida en una variedad de formatos.

Desde OpenSSL 3.0, las claves, los certificados individuales y los CRL se pueden leer de archivos en formatos DER, PEM o P12. Ya no es necesario especificar su formato de entrada, y los comandos de openssl intentarán automáticamente todos los formatos posibles. Sin embargo, si se especifica el formato de entrada DER o PEM, se aplicará.

Para acceder a una clave a través de un motor, se puede usar el formato de entrada ENGINE; alternativamente, el identificador de clave en el argumento <uri> de la opción de clave respectiva puede ir precedido por "org.openssl.engine:". Consulte "Engine Options" en openssl(1) para ver un ejemplo de uso de este último.

OPCIONES

Opciones de formato

Las opciones para especificar el formato son las siguientes. Consulte la página del manual individual para ver qué opciones se aceptan.

-inform formato, -outform formato
El formato de los flujos de entrada o salida.
-keyform formato
Formato de una fuente de entrada de clave privada.
-CRLform formato
Formato de una fuente de entrada de CRL.

Argumentos de opciones de formato

Los posibles argumentos de formato se describen a continuación. Se aceptan tanto mayúsculas como minúsculas.

La lista de argumentos de formato aceptables y el valor predeterminado se describe en la documentación de cada comando.

DER
Un formato binario, codificado o analizado según las Reglas de Codificación Distinguida (DER) del lenguaje de datos ASN.1.
ENGINE
Se utiliza para especificar que el material criptográfico está en un motor de OpenSSL. Se debe configurar o especificar un motor utilizando la opción -engine. Se puede proporcionar una contraseña o PIN al motor utilizando la opción -passin.
P12
Un archivo codificado en DER que contiene un objeto PKCS#12. Podría ser necesario proporcionar una contraseña de descifrado para recuperar la clave privada.
PEM
Un formato de texto definido en las RFC 1421 y 7468 de IETF. Brevemente, este es un bloque de codificación base-64 (definido en la RFC 4648 de IETF), con líneas específicas utilizadas para marcar el inicio y el final: 
El texto antes de la línea BEGIN se ignora.
----- BEGIN tipo-objeto -----
OT43gQKBgQC/2OHZoko6iRlNOAQ/tMVFNq7fL81GivoQ9F1U0Qr+DH3ZfaH8eIkX
xT0ToMPJUzWAn8pZv0snA0um6SIgvkCuxO84OkANCVbttzXImIsL7pFzfcwV/ERK
UM6j0ZuSMFOCr/lGPAoOQU0fskidGEHi1/kW+suSr28TqsyYZpwBDQ==
----- END tipo-objeto -----
El texto después de la línea END también se ignora

El tipo-objeto debe coincidir con el tipo de objeto que se espera. Por ejemplo, un "BEGIN X509 CERTIFICATE" no coincidirá si el comando está intentando leer una clave privada. Los tipos compatibles incluyen:

ANY PRIVATE KEY
CERTIFICATE
CERTIFICATE REQUEST
CMS
DH PARAMETERS
DSA PARAMETERS
DSA PUBLIC KEY
EC PARAMETERS
EC PRIVATE KEY
ECDSA PUBLIC KEY
ENCRYPTED PRIVATE KEY
PARAMETERS
PKCS #7 SIGNED DATA
PKCS7
PRIVATE KEY
PUBLIC KEY
RSA PRIVATE KEY
SSL SESSION PARAMETERS
TRUSTED CERTIFICATE
X509 CRL
X9.42 DH PARAMETERS

Los siguientes tipo-objeto heredados también son compatibles para la compatibilidad con versiones anteriores:

DSA PRIVATE KEY
NEW CERTIFICATE REQUEST
RSA PUBLIC KEY
X509 CERTIFICATE
SMIME
Un objeto S/MIME como se describe en la RFC 8551 de IETF. Las versiones anteriores se conocían como CMS y son compatibles. Tenga en cuenta que el análisis es simple y podría no lograr analizar datos legales.
