NOMBRE

ocamlc - El compilador de bytecode de OCaml

SINOPSIS

ocamlc [ opciones ] nombre_archivo ...

ocamlc.opt [ opciones ] nombre_archivo ...

DESCRIPCIÓN

El compilador de bytecode de OCaml ocamlc(1) compila archivos fuente de OCaml a archivos objeto de bytecode y enlaza estos archivos objeto para producir archivos ejecutables de bytecode independientes. Estos archivos ejecutables son luego ejecutados por el intérprete de bytecode ocamlrun(1).

El comando ocamlc(1) tiene una interfaz de línea de comandos similar a la de la mayoría de los compiladores C. Acepta varios tipos de argumentos y los procesa secuencialmente, después de que se hayan procesado todas las opciones:

Los argumentos que terminan en .mli se toman como archivos fuente para las interfaces de unidades de compilación. Las interfaces especifican los nombres exportados por las unidades de compilación: declaran nombres de valores con sus tipos, definen tipos de datos públicos, declaran tipos de datos abstractos, etc. A partir del archivo x.mli, el compilador ocamlc(1) produce una interfaz compilada en el archivo x.cmi.

Los argumentos que terminan en .ml se toman como archivos fuente para las implementaciones de unidades de compilación. Las implementaciones proporcionan definiciones para los nombres exportados por la unidad, y también contienen expresiones que se evaluarán por sus efectos secundarios. A partir del archivo x.ml, el compilador ocamlc(1) produce un archivo de objeto de bytecode compilado en el archivo x.cmo.

Si existe el archivo de interfaz x.mli, la implementación x.ml se verifica contra la interfaz compilada correspondiente x.cmi, que se supone que existe. Si no se proporciona una interfaz x.mli, la compilación de x.ml produce un archivo de interfaz compilada x.cmi además del archivo de objeto compilado x.cmo. El archivo x.cmi producido corresponde a una interfaz que exporta todo lo que se define en la implementación x.ml.

Los argumentos que terminan en .cmo se toman como bytecode de objeto compilado. Estos archivos se enlazan juntos, junto con los archivos objeto obtenidos al compilar los argumentos .ml (si los hay), y la biblioteca estándar de OCaml, para producir un programa ejecutable independiente. El orden en que se presentan los argumentos .cmo y .ml en la línea de comandos es relevante: las unidades de compilación se inicializan en ese orden en tiempo de ejecución, y es un error de tiempo de enlace usar un componente de una unidad antes de haberla inicializado. Por lo tanto, un archivo x.cmo dado debe venir antes que todos los archivos .cmo que se refieren a la unidad x.

Los argumentos que terminan en .cma se toman como bibliotecas de bytecode de objeto. Una biblioteca de bytecode de objeto empaqueta en un solo archivo un conjunto de archivos de bytecode de objeto (.cmo files). Las bibliotecas se construyen con ocamlc -a (ver la descripción de la opción -a abajo). Los archivos objeto contenidos en la biblioteca se enlazan como archivos .cmo regulares (ver arriba), en el orden especificado cuando se construyó el archivo .cma. La única diferencia es que si un archivo objeto contenido en una biblioteca no es referenciado en ningún lugar del programa, entonces no se enlaza.

Los argumentos que terminan en .c se pasan al compilador C, que genera un archivo objeto .o. Este archivo objeto se enlaza con el programa si se establece el indicador -custom (ver la descripción de -custom abajo).

Los argumentos que terminan en .o o .a se suponen archivos objeto y bibliotecas C. Se pasan al enlazador C al enlazar en modo -custom (ver la descripción de -custom abajo).

Los argumentos que terminan en .so se suponen bibliotecas compartidas C (DLLs). Durante el enlace, buscan funciones C externas referenciadas desde el código OCaml, y sus nombres se escriben en el ejecutable de bytecode generado. El sistema de tiempo de ejecución ocamlrun(1) luego las carga dinámicamente en el momento de inicio del programa.

La salida de la fase de enlace es un archivo que contiene bytecode compilado que puede ser ejecutado por el intérprete de bytecode de OCaml: el comando ocamlrun(1). Si caml.out es el nombre del archivo producido por la fase de enlace, el comando ocamlrun caml.out arg1 arg2 ... argn ejecuta el código compilado contenido en caml.out, pasándole como argumentos las cadenas de caracteres arg1 a argn. (Ver ocamlrun(1) para más detalles).

En la mayoría de los sistemas, el archivo producido por la fase de enlace se puede ejecutar directamente, como en: ./caml.out arg1 arg2 ... argn. El archivo producido tiene el bit ejecutable activado, y se las arregla para lanzar el intérprete de bytecode por sí mismo.

ocamlc.opt es el mismo compilador que ocamlc, pero compilado con el compilador de código nativo ocamlopt(1). Por lo tanto, se comporta exactamente como ocamlc, pero compila más rápido. ocamlc.opt puede no estar disponible en todas las instalaciones de OCaml.

OPCIONES

Las siguientes opciones de línea de comandos son reconocidas por ocamlc(1).

-a
Construye una biblioteca (.cma file) con los archivos objeto (.cmo files) dados en la línea de comandos, en lugar de enlazarlos en un archivo ejecutable. El nombre de la biblioteca debe establecerse con la opción -o.
Si se pasan las opciones -custom, -cclib o -ccopt en la línea de comandos, estas opciones se almacenan en la biblioteca .cma resultante. Luego, enlazar con esta biblioteca añade automáticamente las opciones -custom, -cclib y -ccopt como si hubieran sido proporcionadas en la línea de comandos, a menos que se dé la opción -noautolink. Adicionalmente, una subcadena $CAMLORIGIN dentro de una opción -ccopt será reemplazada por la ruta completa a la biblioteca .cma, excluyendo el nombre del archivo.
-absname
Mostrar nombres de archivo absolutos en mensajes de error.
-no-absname
No intentar mostrar nombres de archivo absolutos en mensajes de error.
-annot
Obsoleto desde 4.11. Por favor, use -bin-annot en su lugar.
-bin-annot
Volcar información detallada sobre la compilación (tipos, enlaces, llamadas a cola, etc.) en formato binario. La información para el archivo src.ml se coloca en el archivo src.cmt. En caso de un error de tipo, volcar toda la información inferida por el verificador de tipos antes del error. Los archivos de anotación producidos por -bin-annot contienen más información y son mucho más compactos que los archivos producidos por -annot.
-c
Solo compilar. Suprimir la fase de enlace de la compilación. Los archivos de código fuente se convierten en archivos compilados, pero no se produce ningún archivo ejecutable. Esta opción es útil para compilar módulos por separado.
-cc ccomp
Usar ccomp como enlazador C al enlazar en modo de "tiempo de ejecución personalizado" (ver la opción -custom) y como compilador C para compilar archivos .c.
-cclib -llibname
Pasar la opción -llibname al enlazador C al enlazar en modo de "tiempo de ejecución personalizado" (ver la opción -custom). Esto hace que la biblioteca C dada se enlace con el programa.
-ccopt opción
Pasar la opción dada al compilador y enlazador C, al enlazar en modo de "tiempo de ejecución personalizado" (ver la opción -custom). Por ejemplo, -ccopt -Ldir hace que el enlazador C busque bibliotecas C en el directorio dir.
-color modo
Habilitar o deshabilitar colores en los mensajes del compilador (especialmente advertencias y errores). Los siguientes modos son compatibles:

auto usa heurísticas para habilitar colores solo si la salida los soporta (un terminal tty compatible con ANSI);

always habilita colores incondicionalmente;

never deshabilita la salida en color.

La variable de entorno "OCAML_COLOR" se considera si no se proporciona -color. Sus valores son auto/always/never como arriba.

Si no se proporciona -color, "OCAML_COLOR" no está configurado y la variable de entorno "NO_COLOR"

; está configurado, entonces color la salida está deshabilitada. De lo contrario, la configuración predeterminada es auto y la heurística actual verifica que la variable de entorno "TERM" exista y no esté vacía o sea "dumb", y que isatty(stderr) sea verdadero.

-error-style modo
Controla la forma en que se imprimen los mensajes de error y advertencia. Los siguientes modos son compatibles:

short solo imprime el error y su ubicación;

contextual igual que "short", pero también muestra el fragmento de código fuente correspondiente a la ubicación del error.

La configuración predeterminada es contextual.

Se considera la variable de entorno "OCAML_ERROR_STYLE" si no se proporciona -error-style. Sus valores son short/contextual como se describe anteriormente.

-compat-32
Verifica que el ejecutable de bytecode generado pueda ejecutarse en plataformas de 32 bits y señaliza un error si no puede. Esto es útil al compilar bytecode en una máquina de 64 bits.
-config
Imprime el número de versión de ocamlc(1) y un resumen detallado de su configuración, luego sale.
-config-var
Imprime el valor de una variable de configuración específica de la salida de -config, luego sale. Si la variable no existe, el código de salida es distinto de cero.
-custom
Enlaza en modo de "runtime personalizado". En el modo de enlace predeterminado, el enlazador produce bytecode destinado a ser ejecutado con el sistema de runtime compartido, ocamlrun(1). En el modo de runtime personalizado, el enlazador produce un archivo de salida que contiene tanto el sistema de runtime como el bytecode del programa. El archivo resultante es más grande, pero puede ser ejecutado directamente, incluso si el comando ocamlrun(1) no está instalado. Además, el modo de "runtime personalizado" permite enlazar código OCaml con funciones C definidas por el usuario.

Nunca use el comando strip(1) en ejecutables producidos por ocamlc -custom, esto eliminaría la parte de bytecode del ejecutable.

Advertencia de seguridad: nunca establezca los bits de "setuid" o "setgid" en ejecutables producidos por ocamlc -custom, esto los haría vulnerables a ataques.

-depend ocamldep-args
Calcula las dependencias, como lo haría ocamldep.
-dllib -lnombre-lib
Organiza para que la biblioteca C compartida dllnombre-lib.so sea cargada dinámicamente por el sistema de runtime ocamlrun(1) en el momento de inicio del programa.
-dllpath dir
Agrega el directorio dir a la ruta de búsqueda del runtime para bibliotecas C compartidas. En tiempo de enlace, las bibliotecas compartidas se buscan en la ruta de búsqueda estándar (la que corresponde a la opción -I). La opción -dllpath simplemente almacena dir en el archivo ejecutable producido, donde ocamlrun(1) puede encontrarla y usarla.
-for-pack ruta-modulo
Genera un archivo objeto (.cmo) que luego puede ser incluido como un sub-módulo (con la ruta de acceso dada) de una unidad de compilación construida con -pack. Por ejemplo, ocamlc -for-pack P -c A.ml generará a.cmo que luego puede ser utilizado con ocamlc -pack -o P.cmo a.cmo. Nota: aún puedes empaquetar un módulo que se compiló sin -for-pack pero en ese caso las excepciones se imprimirán con nombres incorrectos.
-g
Agrega información de depuración durante la compilación y el enlace. Esta opción es necesaria para poder depurar el programa con ocamldebug(1) y para producir rastreos de pila cuando el programa termina con una excepción no capturada.
-no-g
No registra información de depuración (predeterminado).
-i
Hace que el compilador imprima todos los nombres definidos (con sus tipos inferidos o sus definiciones) al compilar una implementación (.ml file). No se producen archivos compilados (.cmo y .cmi files). Esto puede ser útil para verificar los tipos inferidos por el compilador. Además, dado que la salida sigue la sintaxis de las interfaces, puede ayudar a escribir una interfaz explícita (.mli file) para un archivo: simplemente redirige la salida estándar del compilador a un archivo .mli y edita ese archivo para eliminar todas las declaraciones de nombres no exportados.
-cmi-file nombre-archivo
Verifica el tipo de la implementación fuente a compilar contra el archivo de interfaz especificado (omite la búsqueda normal de archivos .mli y .cmi).
-I directorio
Agrega el directorio dado a la lista de directorios buscados para archivos de interfaz compilados (.cmi), archivos de código objeto compilado (.cmo), bibliotecas (.cma) y bibliotecas C especificadas con -cclib -lxxx. Por defecto, se busca primero el directorio actual, luego el directorio de la biblioteca estándar. Los directorios agregados con -I se buscan después del directorio actual, en el orden en que se proporcionaron en la línea de comandos, pero antes del directorio de la biblioteca estándar. Ver también la opción -nostdlib.

Si el directorio dado comienza con +, se toma relativo al directorio de la biblioteca estándar. Por ejemplo, -I +compiler-libs agrega el subdirectorio compiler-libs de la biblioteca estándar a la ruta de búsqueda.

-impl nombre-archivo
Compila el archivo nombre-archivo como un archivo de implementación, incluso si su extensión no es .ml.
-intf nombre-archivo
Compila el archivo nombre-archivo como un archivo de interfaz, incluso si su extensión no es .mli.
-intf-suffix cadena
Reconoce nombres de archivo que terminan en cadena como archivos de interfaz (en lugar del predeterminado .mli).
-keep-docs
Mantiene las cadenas de documentación en los archivos .cmi generados.
-keep-locs
Mantiene las ubicaciones en los archivos .cmi generados.
-keywords version+lista
Establece las palabras clave según la especificación version+lista.

Esta especificación comienza con un número de versión opcional, que define el conjunto base de palabras clave, seguido de una lista separada por + de palabras clave adicionales para agregar a este conjunto base. Sin un número de versión explícito, el conjunto base de palabras clave es el conjunto de palabras clave en la versión actual de OCaml. Las palabras clave adicionales que no coinciden con ninguna palabra clave conocida en la versión actual del lenguaje generan un error cada vez que están presentes en el código fuente.

-labels
Las etiquetas no se ignoran en los tipos, las etiquetas se pueden usar en aplicaciones y los parámetros etiquetados se pueden dar en cualquier orden. Este es el comportamiento predeterminado.
-linkall
Fuerza que se enlacen todos los módulos contenidos en las bibliotecas. Si esta bandera no se proporciona, los módulos no referenciados no se enlazan. Al construir una biblioteca (opción -a), establecer la opción -linkall fuerza que todos los enlaces posteriores de programas que involucren esa biblioteca enlacen todos los módulos contenidos en la biblioteca. Al compilar un módulo (opción -c), establecer la opción -linkall asegura que este módulo siempre se enlazará si se coloca en una biblioteca y esta biblioteca se enlaza.
-make-runtime
Construye un sistema de runtime personalizado (en el archivo especificado por la opción -o) que incorpora los archivos objeto C y las bibliotecas dadas en la línea de comandos. Este sistema de runtime personalizado se puede usar más tarde para ejecutar ejecutables de bytecode producidos con la opción ocamlc -use-runtime nombre-runtime.
-match-context-rows
Establece el número de filas de contexto utilizadas durante la compilación de coincidencia de patrones. Valores más bajos causan una compilación más rápida, pero un código menos optimizado. El valor predeterminado es 32.
-no-alias-deps
No registra dependencias para alias de módulos.
-no-app-funct
Desactiva el comportamiento aplicativo de los functores. Con esta opción, cada aplicación de functor genera nuevos tipos en su resultado y la aplicación del mismo functor dos veces al mismo argumento produce dos estructuras incompatibles.
-noassert
No compila las comprobaciones de aserciones. Tenga en cuenta que la forma especial assert false siempre se compila porque se tipifica especialmente. Esta bandera no tiene efecto al enlazar archivos ya compilados.
-noautolink
Al enlazar bibliotecas .cma, ignora las opciones -custom, -cclib y -ccopt potencialmente contenidas en las bibliotecas (si estas opciones se dieron al construir las bibliotecas). Esto puede ser útil si una biblioteca contiene especificaciones incorrectas de bibliotecas C u opciones C; en este caso, durante el enlace, establezca -noautolink y pase las bibliotecas C y opciones correctas en la línea de comandos.
-nolabels
Ignora las etiquetas no opcionales en los tipos. Las etiquetas no se pueden usar en aplicaciones, y el orden de los parámetros se vuelve estricto.
-nostdlib
No agrega automáticamente el directorio de la biblioteca estándar a la lista de directorios buscados para archivos de interfaz compilados (.cmi), archivos de código objeto compilado (.cmo), bibliotecas (.cma) y bibliotecas C especificadas con -cclib -lxxx. Ver también la opción -I.
-o archivo-ejecutable
Especifica el nombre del archivo de salida producido por el enlazador. El nombre de salida predeterminado es a.out, siguiendo la tradición Unix. -warn-error lista-de-advertencias
Marca como errores las advertencias especificadas en el argumento lista-de-advertencias. El compilador se detendrá con un error cuando se emita una de estas advertencias. La lista-de-advertencias tiene el mismo significado que para la opción -w: un signo + (o una letra mayúscula) marca las advertencias correspondientes como fatales, un signo - (o una letra minúscula) las vuelve advertencias no fatales, y un signo @ activa las advertencias correspondientes y las marca como fatales.

Nota: no se recomienda usar la opción -warn-error en código de producción, ya que casi con seguridad impedirá compilar su programa con versiones posteriores de OCaml cuando estas añadan nuevas advertencias o modifiquen las existentes.

La configuración predeterminada es -warn-error -a (ninguna advertencia es fatal).
