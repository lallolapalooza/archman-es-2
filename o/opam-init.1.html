NOMBRE

opam-init - Inicializa el estado de opam, o establece opciones de inicialización.

SINOPSIS

opam init [OPCIÓN]… [NOMBRE] [DIRECCIÓN]

DESCRIPCIÓN

Inicializa el estado de opam, o actualiza las opciones de inicialización de opam

El comando init inicializa una "raíz de opam" local (por defecto, ~/.opam/ a menos que se anule con --root o la variable de entorno OPAMROOT) que contiene los datos y paquetes de opam. Este es un paso necesario para el funcionamiento normal de opam. Los repositorios de software iniciales se obtienen y también se puede instalar un 'switch' inicial, de acuerdo con la configuración y las opciones. Estos pueden ser configurados posteriormente usando opam switch y opam repository.

El repositorio inicial y los valores predeterminados se pueden establecer a través de un archivo de configuración encontrado en ~/.opamrc o /etc/opamrc.

Además, este comando permite personalizar algunos aspectos de la integración de opam con el shell, cuando se ejecuta inicialmente (evitando el diálogo interactivo), pero también en cualquier momento posterior.

ARGUMENTOS

DIRECCIÓN
Dirección del repositorio de paquetes inicial, al crear una nueva raíz de opam.
NOMBRE (ausente=por defecto)
Nombre del repositorio inicial, al crear una nueva raíz de opam.

OPCIONES

-a, --auto-setup
Realiza automáticamente una configuración completa, incluyendo la adición de una línea a tus archivos de inicialización del shell.
--bare
Inicializa el estado de opam, pero no configura ningún switch de compilador todavía.
--bypass-checks
Omite las verificaciones de herramientas requeridas o recomendadas, y asume que todo está bien.
-c PACKAGE, --compiler=PACKAGE
Establece el compilador a instalar (al crear un switch inicial).
--config=ARCHIVO
Usa el archivo de configuración de inicialización dado. Si se repite, el último tiene la mayor prioridad (es decir, cada campo obtiene su valor de donde fue definido por última vez). También se permite especificar una URL que apunte a un archivo de configuración.
--cygwin-extra-packages=PAQUETES_CYGWIN
Solo Windows (Experimental). Especifica paquetes adicionales para instalar con --cygwin-internal-install
--cygwin-internal-install
Solo Windows (Experimental). Permite a opam configurar y gestionar una instalación interna de Cygwin (recomendado).
--cygwin-local-install
Solo Windows (Experimental). Usa una instalación preexistente de Cygwin.
--cygwin-location=DIR
Solo Windows (Experimental). Especifica la ubicación raíz de Cygwin.
--disable-completion
Deshabilita la finalización de comandos en los scripts de inicialización de opam.
--disable-sandboxing
Usa una configuración predeterminada con el sandboxing deshabilitado (ten en cuenta que esto puede ser anulado por `opamrc' si no se especifica --no-opamrc o se usa --config). Úsalo bajo tu propio riesgo, sin sandboxing es posible que un script de paquete defectuoso elimine todos tus archivos.
--disable-shell-hook
Deshabilita el registro de un hook de shell en los scripts de inicialización de opam.
--dot-profile=NOMBREARCHIVO
Nombre del archivo de configuración a actualizar en lugar de ~/.profile o ~/.zshrc basándose en la detección del shell.
--enable-completion
Configura la finalización de comandos en los scripts de inicialización de opam, para shells compatibles.
--enable-shell-hook
Configura los scripts de inicialización de opam para registrar un hook de shell que mantendrá automáticamente el entorno del shell actualizado en cada prompt.
--git-location=DIR
Solo Windows (Experimental). Especifica el directorio binario de git. Asegúrate de que no contenga bash en el mismo directorio.
-i, --interactive
Ejecuta la configuración interactivamente (este es el comportamiento predeterminado para una ejecución inicial, o cuando no se especifican opciones más específicas).
-k TIPO, --kind=TIPO
Especifica el tipo de repositorio a utilizar (uno de http, local, git, darcs o hg).
-n, --no-setup
No actualiza la configuración del shell del usuario para configurar opam. También implica --disable-shell-hook, a menos que se especifique --interactive o de otra manera.
--no-cygwin-setup
Experimental. No configura Cygwin.
--no-git-location
Experimental. No especifica ni pide especificar el directorio binario de git.
--no-opamrc
No lee `/etc/opamrc' ni `~/.opamrc': usa la configuración predeterminada y solo los archivos especificados a través de --config.
--reinit
Vuelve a ejecutar las comprobaciones y la configuración iniciales, de acuerdo con opamrc, incluso si no es una nueva raíz de opam.
--shell=SHELL
Establece el modo de configuración del entorno opam apropiado para SHELL. Uno de bash, sh, csh, zsh, fish, pwsh, cmd o powershell. Se adivina a partir de los procesos padre y la variable $SHELL por defecto.
--shell-setup
Configura automáticamente el shell del usuario para opam, por ejemplo, agregando una línea al archivo `~/.profile'.
--show-default-opamrc
Imprime la configuración predeterminada integrada en la salida estándar y sale.

ARCHIVO DE CONFIGURACIÓN

Cualquier campo de la configuración inicial integrada puede ser anulado a través de ~/.opamrc, /etc/opamrc, o un archivo suministrado con --config. La configuración predeterminada para esta versión de opam se puede obtener usando --show-default-opamrc.

OPCIONES DE CONSTRUCCIÓN DE PAQUETES

--assume-depexts
Omite el paso de instalación para cualquier paquete de sistema faltante e intenta continuar con la compilación de los paquetes opam de todos modos. Si la instalación es exitosa, opam no volverá a preguntar sobre estos paquetes de sistema. Solo tiene sentido si el manejo de dependencias externas está habilitado.
-b, --keep-build-dir
Conserva los directorios de construcción después de compilar los paquetes. Esto es equivalente a establecer $OPAMKEEPBUILDDIR a "true".
--build-doc
Eliminado en 2.1, usa --with-doc en su lugar.
--build-test
Eliminado en 2.1, usa --with-test en su lugar.
-d, --with-doc
Construye la documentación del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Esto es equivalente a establecer $OPAMWITHDOC (o el obsoleto $OPAMBUILDDOC) a "true".
--dry-run
Simula el comando, pero no realiza ningún cambio real. Esto también se puede establecer con la variable de entorno $OPAMDEBUG.
--fake
Esta opción registra las acciones en la base de datos de opam, sin realizarlas realmente. ADVERTENCIA: Esta opción es peligrosa y es probable que rompa tu entorno opam. Probablemente quieras usar --dry-run. Has sido advertido.
--ignore-constraints-on[=PAQUETES] (predeterminado=)
Fuerza a opam a ignorar las restricciones de versión en todas las dependencias de los paquetes listados. Esto se puede usar para probar la compatibilidad, pero espera que las compilaciones fallen al usarlo. Ten en cuenta que la disponibilidad de los paquetes, así como las restricciones de versión en dependencias opcionales y conflictos, no se ven afectadas. Esto es equivalente a establecer $OPAMIGNORECONSTRAINTS.
--inplace-build
Al compilar un paquete cuya fuente está vinculada a un directorio local, procesa las acciones de construcción e instalación directamente en ese directorio, en lugar de hacerlo en una copia limpia manejada por opam. Esto solo afecta a los paquetes que se enumeran explícitamente en la línea de comandos. Esto es equivalente a establecer $OPAMINPLACEBUILD a "true".
-j JOBS, --jobs=JOBS
Establece el número máximo de trabajos concurrentes a utilizar. El valor predeterminado se calcula a partir del número de núcleos. También puedes establecerlo usando la variable de entorno $OPAMJOBS.
--lock-suffix=SUFIJO (ausente=locked)
Establece el sufijo de los archivos bloqueados a SUFIJO.
--locked
En comandos que usan archivos opam encontrados a partir de fuentes fijadas, si se encuentra una variante del archivo con una extensión .locked añadida (por ejemplo, foo.opam.locked además de foo.opam.

La opción lock se puede usar para generar tales archivos, basándose en las versiones de las dependencias actualmente instaladas en el host. Esto es equivalente a establecer la variable de entorno $OPAMLOCKED. Tenga en cuenta que esta opción generalmente no afecta a los paquetes ya fijados.
-m MAKE, --make=MAKE
Eliminado en la versión 2.1, use opam config set[-global] make MAKE en su lugar.
--no-checksums
No verificar la suma de verificación de los archivos descargados. Esto es equivalente a establecer $OPAMNOCHECKSUMS a "true".
--no-depexts
Deshabilita temporalmente el manejo de dependencias externas. Esto se puede usar si un paquete no está disponible en el gestor de paquetes de su sistema, pero usted instaló la dependencia requerida manualmente. Implica --assume-depexts, y almacena las excepciones tras el éxito también.
--require-checksums
Rechazar la instalación de paquetes que no proporcionan una suma de verificación para los archivos de origen. Esto es equivalente a establecer $OPAMREQUIRECHECKSUMS a "true".
--reuse-build-dir
Reutiliza los directorios de compilación existentes (mantenidos con --keep-build-dir), en lugar de compilar desde una copia fresca del código fuente. Esto puede ser más rápido, pero también puede provocar fallos si los sistemas de compilación de los paquetes no manejan bien las actualizaciones de las dependencias. Esto es equivalente a establecer $OPAMREUSEBUILDDIR a "true".
--show-actions
Llama al resolvedor y muestra las acciones. No realiza ningún cambio. Esto es equivalente a establecer $OPAMSHOW.
--skip-updates
Al ejecutar una instalación, actualización o reinstalación en paquetes fijados desde el código fuente, normalmente se actualizan primero desde su origen. Esta bandera deshabilita ese comportamiento y los mantendrá en su versión en caché. Esto es equivalente a establecer $OPAMSKIPUPDATE.
-t, --with-test
Compila y ejecuta las pruebas unitarias del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Esto es equivalente a establecer $OPAMWITHTEST (o el obsoleto $OPAMBUILDTEST) a "true".
--unlock-base
Eliminado en la versión 2.1, use --update-invariant en su lugar.
--update-invariant
Permite cambios en los paquetes establecidos como base del switch (típicamente, el compilador principal). Úselo con precaución. Esto es equivalente a establecer la variable de entorno $OPAMUNLOCKBASE.
--verbose-on=PACKAGES
Sea más detallado en paquetes específicos. Esto es equivalente a establecer $OPAMVERBOSE.
--with-dev-setup
Incluye dependencias solo de herramientas de desarrollo.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No falle si no se pueden instalar todos los paquetes solicitados: intente instalar tantos como sea posible. Tenga en cuenta que no todos los resolvedores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Use la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Destinado a cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. El flag no estaba disponible en opam 2.0, así que para seleccionar la CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUANDO
Colorea la salida. CUANDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o unsafe-yes. Se puede especificar más de una vez. Si también se proporcionan --yes o --no, se toma en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especifique preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje admitido y los resolvedores externos disponibles, vea http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre cómo usar las preferencias del resolvedor se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al resolvedor en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al resolvedor durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está configurada (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FMT] (por defecto=auto)
Muestra esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%`, será reemplazado por un índice que no sobrescribirá un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Vea también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en la versión 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deberían definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Use ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegúrese de que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de completado, por ejemplo. Fallará siempre que se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifique el resolvedor CUDF a utilizar para resolver problemas de instalación de paquetes. Este es un resolvedor predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentre un error en la definición de un paquete o un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--switch=SWITCH
Use SWITCH como el switch de compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier resolvedor externo y usa el interno (esto requiere que opam se haya compilado con un resolvedor interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sea más detallado. Un -v muestra todos los comandos de paquetes, repita para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra la información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes vinculados a un directorio local, controlado por versiones, actualícelos al estado de trabajo actual de su código fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio de código fuente se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Vea también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

OPAMBREAK

OPAMBUILDCMD

OPAMBUILDJOBS

Force the output colorization. Can be always, never or auto. Default is `auto', which tries to guess from the locale.

Force the output colorization to auto. Overrides OPAMCOLOR when set.

Force the output colorization to always. Overrides OPAMCOLOR when set.

VERSIÓN DE LA CLI

Todos los scripts e invocaciones programáticas de opam deben usar `--cli' para garantizar que funcionen sin problemas con versiones futuras del cliente opam. Además, las publicaciones de blogs u otra documentación pueden beneficiarse, ya que evita que la información se vuelva obsoleta.

Aunque opam solo admite raíces (~/.opam/) para la versión actual, proporciona compatibilidad retroactiva para su interfaz de línea de comandos.

Dado que el soporte de la versión de la CLI solo se agregó en opam 2.1, use OPAMCLI para seleccionar el soporte 2.0 (ya que opam 2.0 simplemente lo ignorará) y `--cli=2.1' para versiones 2.1 (o posteriores), ya que una variable de entorno que controle el análisis de sintaxis es frágil. Para ello, opam muestra una advertencia si OPAMCLI especifica una versión válida que no sea 2.0, y también si se especifica `--cli=2.0'.

La versión de la línea de comandos se selecciona utilizando la opción `--cli' o la variable de entorno OPAMCLI. `--cli' puede especificarse más de una vez, donde la última instancia tiene prioridad. OPAMCLI solo se inspecciona si no se proporciona `--cli'.

opam init --help

2.4.1

NAME

opam-init --help

opam-init help page

SYNOPSIS

opam init [OPTION]... [PLUGIN]...

DESCRIPTION

This command initialises opam. It asks configuration questions and initialises the switch, repository and configuration files.

It is intended to be run by the user, or by another program which then wants to control the opam installation.

If no arguments are given, it will try to find and activate the compiler to use. It will then use the found compiler and create a new switch with it.

You can also give it a list of plugins to use, or configuration options.

ARGUMENTS

PLUGIN: any of the available opam plugins, see opam --help

OPTIONS

--help, -h: Print this help page and exit.

--version, -V: Print opam version and exit.

--root DIR: Set the ROOT directory to DIR.

--disable-shell-hook: Do not set up shell hooks.

--no-setup: Do not setup the switch, repository and configuration files.

--no-solver: Do not install the solver if missing.

--confirm-command: ask for confirmation before running commands.

--solver NAME: Use NAME as solver, or no solver if NAME is `none`.

--force: Override any existing configuration.

--wrapper NAME: Set opam to run in wrapper mode NAME.

--color WHEN: specify the color mode: auto, always, never.

--ascii: use ascii characters only.

--debug: output debug information.

--verbose, -v: output verbose information.

--quiet, -q: output less information.

--no-progress: Do not display progress information.

--log-file FILE: Log all output to FILE.

--log-level LEVEL: set the log level (see --log-file).

--no-backup: Do not create backup files.

CONFIGURATION FILE

The configuration file is a text file at the root of the opam installation, typically $HOME/.config/opam/opamrc.

The options are stored in the file and are applied at every invocation of opam.

PACKAGE BUILD OPTIONS

When installing packages, opam may use environment variables, which are defined in the build commands of the package. These include:

EXTRAA
Additional flags to pass to the compiler.
PREFIX
The installation prefix, which is --prefix.
BUILD
The directory to build in. This is usually --build-dir.
CONFIG
The name of the configuration file for the package.
TARGET
The target architecture.

COMMON OPTIONS

Most of these options are common to all commands and are described in opam(1).

ENVIRONMENT

See opam(1)

CLI VERSION
