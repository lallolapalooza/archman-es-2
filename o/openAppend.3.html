Descripción Detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es para usuarios avanzados y experimentados. No lo necesita a menos que realmente sepa lo que está haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se limitaban a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivos de archivo.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo que PhysicsFS no proporciona directamente: quizás algún formato propietario que solo su aplicación necesita entender.

Internamente, todo el soporte de archivo incorporado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver son el código fuente de PhysicsFS mismo.

Un archivador se añade al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automático con PHYSFS_mount(); si un archivo dado puede ser manejado con su archivador, se le dará el control según corresponda.

Estos métodos tratan con manejadores de directorios. Tiene una instancia de su archivador, y genera un manejador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archivador (no de un archivo) es generalmente la vida útil completa del proceso, y se asume que es un singleton, no proporcionamos datos de instancia para el archivador en sí; la aplicación puede simplemente usar variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para verificar los enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en ello.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de retornar. PhysicsFS pasará estos errores a la aplicación sin modificar en la mayoría de los casos.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Archiver sean seguras para hilos en sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador dado dentro de la biblioteca, pero no promete que usar el mismo PHYSFS_File desde dos hilos a la vez sea seguro para hilos; como tal, su PHYSFS_Archiver puede asumir que el bloqueo se maneja por usted siempre que el PHYSFS_Io que devuelva de PHYSFS_open* no cambie ningún estado de su Archivador, ya que el PHYSFS_Io no estará protegido de manera tan agresiva.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruir un archivo previamente abierto. Cerrar este archivo y liberar cualquier memoria asociada, incluyendo el PHYSFS_Io original y (opaque) en sí, si aplica. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Listar todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se realiza una copia si es apropiado, para que pueda desecharla al retornar de la devolución de llamada. (dirname) está en notación independiente de la plataforma. Si tiene un error, llame a PHYSFS_SetErrorCode() con el código que parezca apropiado y retorne PHYSFS_ENUM_ERROR. Si la devolución de llamada retorna PHYSFS_ENUM_ERROR, por favor llame a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y luego retorne PHYSFS_ENUM_ERROR también. No llame a la devolución de llamada de nuevo en ninguna circunstancia. Si la devolución de llamada retorna PHYSFS_ENUM_STOP, deje de enumerar y retorne PHYSFS_ENUM_STOP también. No llame a la devolución de llamada de nuevo en ninguna circunstancia. No establezca un código de error en este caso. Las devoluciones de llamada solo deben retornar un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene un comportamiento indefinido. Mientras la devolución de llamada haya retornado PHYSFS_ENUM_OK y usted no haya experimentado ningún error propio, continúe enumerando hasta que haya terminado y luego retorne PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate retorna cero o no cero (éxito o fracaso), ¡así que tenga en cuenta que este puntero de función retorna valores diferentes!

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Esto se utiliza para identificar su archivo y se devuelve en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crear un directorio en el archivo. Si la aplicación intenta crear varios directorios, PhysicsFS los dividirá en varias llamadas antes de pasarlos a su controlador. Si el archivo es de solo lectura, esta operación debería fallar. Retorne un valor distinto de cero en caso de éxito, cero en caso de fracaso. Este nombre de archivo está en notación independiente de la plataforma. En caso de fracaso, llame a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abrir un archivo en este archivo para añadir. Si el archivo no existe, debe crearse. La posición de escritura debe ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de la plataforma. Retorna NULL en caso de fracaso y llama a PHYSFS_setErrorCode(). Retorna no NULL en caso de éxito. El puntero devuelto se pasará como el parámetro "opaque" para futuras llamadas a archivos.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Abre un archivo en este archivo para lectura. Este nombre de archivo, (fnm), está en notación independiente de la plataforma. Falla si el archivo no existe. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaco" para llamadas de archivo posteriores.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Abre un archivo en este archivo para escritura. Si el archivo no existe, debe crearse. Si existe, debe truncarse a cero bytes. El desplazamiento de escritura debe ser el inicio del archivo. Si el archivo está de solo lectura, esta operación debe fallar. Este nombre de archivo está en notación independiente de la plataforma. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaco" para llamadas de archivo posteriores.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Elimina un archivo o directorio en el archivo. Esta misma llamada se usa tanto para archivos como para directorios; no hay una llamada separada rmdir(). Los directorios solo deben eliminarse si están vacíos. Si el archivo está de solo lectura, esta operación debe fallar.

Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtiene metadatos básicos del archivo. En caso de éxito, completa todos los campos en (stat), utilizando valores predeterminados razonables para los campos que se aplican a su archivo.

Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Información de compatibilidad binaria. Debe establecerse en cero en este momento. Las versiones futuras de esta estructura incrementarán este campo, para que sepamos qué soporta una implementación determinada. Presumiblemente, seguiremos admitiendo versiones anteriores a medida que ofrezcamos nuevas características.
