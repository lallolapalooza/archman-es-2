DESCRIPCIÓN

El comando cmp es una implementación cliente para el Protocolo de Gestión de Certificados (CMP) tal como se define en RFC4210. Puede usarse para solicitar certificados de un servidor CA, actualizar sus certificados, solicitar la revocación de certificados y realizar otros tipos de solicitudes CMP.

OPCIONES

-help
Muestra un resumen de todas las opciones.
-config archivo
Archivo de configuración a utilizar. Una cadena vacía "" significa ninguno. El nombre de archivo predeterminado proviene de la variable de entorno "OPENSSL_CONF".
-section nombres
Sección(es) a utilizar dentro del archivo de configuración que definen las opciones CMP. Una cadena vacía "" significa que no hay sección específica. El valor predeterminado es "cmp".

Se pueden dar múltiples nombres de sección, separados por comas y/o espacios en blanco (donde en este último caso el argumento completo debe estar entre comillas "..."). El contenido de las secciones nombradas posteriormente puede anular el contenido de las secciones nombradas antes. En cualquier caso, como de costumbre, la sección "[default]" y finalmente la sección sin nombre (en la medida de lo posible) pueden proporcionar valores de reserva por opción.

-verbosity nivel
Nivel de verbosidad para el registro, salida de errores, etc. 0 = EMERG, 1 = ALERT, 2 = CRIT, 3 = ERR, 4 = WARN, 5 = NOTE, 6 = INFO, 7 = DEBUG, 8 = TRACE. El valor predeterminado es 6 = INFO.

Opciones genéricas de mensaje

-cmd ir|cr|kur|p10cr|rr|genm
Comando CMP a ejecutar. Los comandos implementados actualmente son:
ir   - Petición de Inicialización
cr   - Petición de Certificado
p10cr - Petición de Certificación PKCS#10 (para compatibilidad con versiones anteriores)
kur   - Petición de Actualización de Clave
rr   - Petición de Revocación

CMP command options

genm - Mensaje General

ir solicita la inicialización de una entidad final en una jerarquía PKI mediante la emisión de un primer certificado.

cr solicita la emisión de un certificado adicional para una entidad final ya inicializada en la jerarquía PKI.

p10cr solicita la emisión de un certificado adicional de forma similar a cr pero utilizando el formato CSR PKCS#10 heredado.

kur solicita una actualización (de clave) para un certificado existente.

rr solicita la revocación de un certificado existente.

genm solicita información utilizando un Mensaje General, donde opcionalmente se pueden incluir InfoTypeAndValues para indicar qué información interesa. Al recibir la Respuesta General, la información sobre todos los infoTypes de ITAV recibidos se imprime en la salida estándar.

-infotype nombre
Establece el nombre InfoType a utilizar para solicitar información específica en genm, por ejemplo, "signKeyPairTypes". Existe soporte específico para "caCerts", "rootCaCert", "certReqTemplate" y "crlStatusList" (recuperación de actualización de CRL).
-profile nombre
Nombre de un perfil de certificado a colocar en el campo generalInfo de PKIHeader de los mensajes de solicitud.
-geninfo valores
Una lista separada por comas de InfoTypeAndValue para colocar en el campo generalInfo del PKIHeader de los mensajes de solicitud. Cada InfoTypeAndValue proporciona un OID y un valor entero o de cadena de la forma OID:int:número o OID:str:texto, por ejemplo, '1.2.3.4:int:56789, id-kp:str:name'.
-template nombre_archivo
El archivo donde guardar cualquier certTemplate CRMF en formato DER recibido en un mensaje genp con id-it-certReqTemplate.
-keyspec nombre_archivo
Es opcional y se utiliza para especificar el archivo donde guardar cualquier keySpec si está presente en un mensaje genp con id-it-keyGenParameters.

Nota: el contenido de cualquier campo keySpec recibido se registra como INFO.

Opciones de inscripción de certificados

-newkey nombre_archivo|uri
La fuente de la clave privada o pública para el certificado que se solicita. Por defecto, la clave pública en el CSR PKCS#10 proporcionado con la opción -csr, la clave pública del certificado de referencia, o la clave de cliente actual.

La parte pública de la clave se coloca en la solicitud de certificado.

A menos que se especifique -cmd p10cr, -popo -1 o -popo 0, la clave privada también será necesaria para proporcionar la prueba de posesión (POPO), donde la opción -key puede proporcionar una alternativa.

-newkeypass arg
Fuente de la frase de contraseña para la clave proporcionada con la opción -newkey. Si no se proporciona aquí, se solicitará la contraseña si es necesario.

Para más información sobre el formato de arg, consulte openssl-passphrase-options(1).

-centralkeygen
Solicita la generación central de claves para la inscripción de certificados. Esto se aplica a -cmd ir|cr|kur|p10cr.
-newkeyout nombre_archivo
Archivo donde guardar la clave privada generada centralmente, en formato PEM.
-subject nombre
Nombre Distinguido (DN) X.509 a utilizar como campo de sujeto en la plantilla de certificado solicitada en los mensajes IR/CR/KUR. Si se proporciona el DN NULL ("/"), no se colocará ningún sujeto en la plantilla. Por defecto, es el DN del sujeto de cualquier CSR PKCS#10 proporcionado con la opción -csr. Para KUR, una alternativa adicional es el DN del sujeto del certificado de referencia (ver -oldcert) si se proporciona. Esta alternativa se utiliza para IR y CR solo si no se establecen SANs.

Si se proporciona y no se da ninguna de las opciones -cert, -oldcert o -csr, el DN del sujeto se utiliza como remitente de respaldo de los mensajes CMP salientes.

El argumento debe tener el formato /type0=value0/type1=value1/type2=.... Los caracteres especiales pueden escaparse con "\" (barra invertida); los espacios en blanco se conservan. Se permiten valores vacíos, pero el tipo correspondiente no se incluirá. Proporcionar una única "/" dará como resultado una secuencia vacía de RDNs (un DN NULL). Los RDNs multivalorados se pueden formar colocando un carácter "+" en lugar de un "/" entre las Afirmaciones de Valor de Atributo (AVAs) que especifican los miembros del conjunto. Ejemplo:

"/DC=org/DC=OpenSSL/DC=users/UID=123456+CN=John Doe"

-days número
Número de días que se solicita que el nuevo certificado sea válido, contando desde el momento actual del host. También activa la solicitud explícita de que el período de validez comience desde el momento actual (según lo visto por el host).
-reqexts nombre
Nombre de la sección en el archivo de configuración de OpenSSL que define las extensiones de la solicitud de certificado. Si está presente la opción -csr, estas extensiones complementan las extensiones contenidas en el CSR PKCS#10 dado, reemplazando cualquier extensión con los mismos OIDs.
-sans espec
Una o más direcciones IP, direcciones de correo electrónico, nombres DNS o URIs separadas por comas o espacios en blanco (donde en este último caso el argumento completo debe estar entre comillas) para agregar como extensión de nombre(s) alternativo(s) del sujeto (SAN) en la solicitud de certificado. Si se proporciona el elemento especial "critical", los SANs se marcarán como críticos. No se puede usar si alguna extensión de nombre alternativo del sujeto está configurada a través de -reqexts.
-san_nodefault
Cuando los Nombres Alternativos del Sujeto no se proporcionan a través de -sans ni se definen a través de -reqexts, se copian por defecto del certificado de referencia (ver -oldcert). Esto se puede deshabilitar proporcionando la opción -san_nodefault.
-policies nombre
Nombre de la sección en el archivo de configuración de OpenSSL que define las políticas a establecer como extensión de la solicitud de certificado. Esta opción no se puede utilizar junto con -policy_oids.
-policy_oids nombres
Uno o más OID(s), separados por comas y/o espacios en blanco (donde en este último caso el argumento completo debe estar entre comillas) para agregar como extensión de solicitud de políticas de certificado. Esta opción no se puede utilizar junto con -policies.
-policy_oids_critical
Marca las políticas proporcionadas con -policy_oids como críticas.
-popo número
Método de prueba de posesión (POPO) a utilizar para IR/CR/KUR; valores: -1..<2> donde -1 = NONE, lo que implica generación central de claves, 0 = RAVERIFIED, 1 = SIGNATURE (por defecto), 2 = KEYENC.

Tenga en cuenta que solo se puede producir un POPO basado en firma si se proporciona una clave privada a través de las opciones -newkey o -key.

-csr nombre_archivo
CSR PKCS#10 en formato PEM o DER que contiene una solicitud de certificado. Con -cmd p10cr se utiliza directamente en un mensaje P10CR heredado.

Cuando se utiliza con -cmd ir, cr o kur, se transforma en la solicitud CMP regular correspondiente. En este caso, se debe proporcionar una clave privada (con -newkey o -key) para la prueba de posesión (a menos que se utilicen -popo -1 o -popo 0) y la clave pública correspondiente se colocará en la solicitud de certificado (en lugar de tomar la clave pública contenida en el CSR PKCS#10).

La entrada CSR PKCS#10 también puede usarse con -cmd rr para especificar el certificado a revocar a través del nombre de sujeto y la clave pública incluidos. Su sujeto se utiliza como remitente de respaldo en las cabeceras de los mensajes CMP si no se proporcionan -cert y -oldcert.

Certificado(s) de confianza a utilizar para validar el certificado recién inscrito. Durante esta validación, se deshabilitan todas las comprobaciones de estado del certificado.

Opciones de inscripción y revocación de certificados

-oldcert nombre_archivo|uri
El certificado que se va a actualizar (es decir, renovar o volver a clave) en los mensajes de Solicitud de Actualización de Clave (KUR) o que se va a revocar en los mensajes de Solicitud de Revocación (RR). Para KUR, el certificado a actualizar por defecto es -cert, y el certificado resultante se denomina certificado de referencia. Para RR, el certificado a revocar también se puede especificar usando -csr. Se ignora -oldcert y -csr si se proporcionan -issuer y -serial.

El certificado de referencia, si existe, también se utiliza para derivar el DN del sujeto por defecto y los Nombres Alternativos del Sujeto, así como la entrada del emisor por defecto en la plantilla del certificado solicitado de un IR/CR/KUR. Su clave pública se utiliza como reserva en la plantilla de las solicitudes de certificación. Su sujeto se utiliza como remitente de los mensajes salientes si no se proporciona -cert. Su emisor se utiliza como destinatario por defecto en las cabeceras de los mensajes CMP si no se proporciona -recipient, -srvcert o -issuer.

-issuer nombre
Nombre Distinguido (DN) X.509 que se colocará en el campo del emisor en la plantilla del certificado solicitado en los mensajes IR/CR/KUR/RR. Si se proporciona el NULL-DN ( "/") entonces no se coloca ningún emisor en la plantilla.

Si se proporciona y no se proporcionan ni -recipient ni -srvcert, el DN del emisor se utiliza como destinatario de reserva de los mensajes CMP salientes.

El argumento debe tener el formato /tipo0=valor0/tipo1=valor1/tipo2=.... Para más detalles, véase la descripción de la opción -subject.

-serial número
Especifica el número de serie del certificado a revocar en la solicitud de revocación. El número de serie puede ser decimal o hexadecimal (si va precedido de "0x").
-revreason número
Establece el motivo de la CRL (CRLReason) que se incluirá en la solicitud de revocación (RR); valores: 0..10 o -1 para ninguno (que es el valor por defecto).

Los números de motivo definidos en RFC 5280 son:

CRLReason ::= ENUMERATED {
     unspecified             (0),
     keyCompromise           (1),
     cACompromise            (2),
     affiliationChanged      (3),
     superseded              (4),
     cessationOfOperation    (5),
     certificateHold         (6),
     -- el valor 7 no se utiliza
     removeFromCRL           (8),
     privilegeWithdrawn      (9),
     aACompromise           (10)
 }

Opciones de transferencia de mensajes

-server [http[s]://][userinfo@]host[:puerto][/ruta][?consulta][#fragmento]
El nombre de dominio o dirección IP del host y, opcionalmente, el puerto del servidor CMP al que conectarse usando HTTP(S). La dirección IP puede ser para v4 o v6, como 127.0.0.1 o "[::1]" para localhost. Si la cadena de host es una dirección IPv6, debe ir entre corchetes "[" y "]".

Esta opción excluye -port y -use_mock_srv. Se ignora si se proporciona -rspin con suficientes argumentos de nombre de archivo.

Si se proporciona el esquema "https", se implica la opción -tls_used. Cuando se utiliza TLS, el puerto por defecto es 443, de lo contrario 80. Los componentes opcionales de userinfo y fragmento se ignoran. Cualquier componente de consulta proporcionado se maneja como parte del componente de ruta. Si se incluye una ruta, proporciona el valor por defecto para la opción -path.

-proxy [http[s]://][userinfo@]host[:puerto][/ruta][?consulta][#fragmento]
El servidor proxy HTTP(S) a utilizar para acceder al servidor CMP, a menos que aplique -no_proxy (ver más abajo). Si la cadena de host es una dirección IPv6, debe ir entre corchetes "[" y "]". El puerto del proxy por defecto es 80 o 443 si el esquema es "https"; aparte de eso, se ignoran el prefijo opcional "http://" o "https://" (tenga en cuenta que el uso de TLS puede ser requerido por -tls_used o -server con el prefijo "https"), así como cualquier componente de ruta, userinfo, consulta y fragmento. Por defecto, utiliza la variable de entorno "http_proxy" si está establecida, de lo contrario "HTTP_PROXY" en caso de que no se utilice TLS, de lo contrario "https_proxy" si está establecida, de lo contrario "HTTPS_PROXY". Esta opción se ignora si no se proporciona -server.
-no_proxy direcciones
Lista de direcciones IP y/o nombres DNS de servidores para los que no se debe usar un proxy HTTP(S), separados por comas y/o espacios en blanco (en cuyo caso el argumento completo debe ir entre comillas "..."). Por defecto, proviene de la variable de entorno "no_proxy" si está establecida, de lo contrario "NO_PROXY". Esta opción se ignora si no se proporciona -server.
-recipient nombre
Nombre Distinguido (DN) a utilizar en el campo del destinatario de las cabeceras de los mensajes de solicitud CMP, es decir, el servidor CMP (generalmente la CA a la que se dirige).

El campo destinatario en la cabecera de un mensaje CMP es obligatorio. Si no se proporciona explícitamente, el destinatario se determina en el siguiente orden: el sujeto del certificado del servidor CMP proporcionado con la opción -srvcert, la opción -issuer, el emisor del certificado proporcionado con la opción -oldcert, el emisor del certificado del cliente CMP (opción -cert), en la medida en que cualquiera de estos esté presente, de lo contrario el NULL-DN como último recurso.

El argumento debe tener el formato /tipo0=valor0/tipo1=valor1/tipo2=.... Para más detalles, véase la descripción de la opción -subject.

-path ruta_remota
Ruta HTTP en el servidor CMP (también conocido como alias CMP) a utilizar para las solicitudes POST. Por defecto, cualquier ruta proporcionada con -server, de lo contrario "/".
-keep_alive valor
Si el valor proporcionado es 0, las conexiones HTTP se cierran después de cada respuesta (lo que sería el comportamiento por defecto de HTTP 1.0) incluso si una transacción CMP necesita más de un viaje de ida y vuelta. Si el valor es 1 o 2, se solicita una conexión persistente para cada transacción. Si el valor es 2, se requiere una conexión persistente, es decir, se produce un error si el servidor no la concede. El valor por defecto es 1, lo que significa que se prefiere mantener la conexión abierta.
-msg_timeout segundos
Número de segundos que se permite que un viaje de ida y vuelta de mensaje de solicitud-respuesta CMP dure antes de que se devuelva un error de tiempo de espera. Un valor <= 0 significa que no hay limitación (espera indefinida). Por defecto, se utiliza la configuración de -total_timeout.
-total_timeout segundos
Número máximo total de segundos que puede durar una transacción, incluyendo sondeos, etc. Un valor <= 0 significa que no hay limitación (espera indefinida). Por defecto es 0.

NAME

openssl-cmp - Client for the Certificate Management Protocol (CMP)

SYNOPSIS

openssl-cmp [-verbose] [-debug] [-msglen] [-prompt] [-certout filename] [-pemout] [-outform fmt] [-cert filename|uri] [-key filename|uri] [-passin type[:value]] [-certprop] [-subjectName subject] [-subject subject] [-issuer issuer] [-serial number] [-new] [-recipient recipient] [-expected_sender name] [-expect_sender name] [-ignore_keyusage] [-unprotected_errors] [-no_cache_extracerts] [-srvcertout filename] [-extracertsout filename] [-cacertsout filename] [-oldwithold filename] [-newwithnew filename] [-newwithold filename] [-oldwithnew filename] [-crlcert filename] [-oldcrl filename] [-crlout filename] [-ref value] [-secret arg] [-own_trusted filenames|uris] [-version] [-help] command [args...]

DESCRIPTION

openssl-cmp implements the Certificate Management Protocol (CMP) as described in RFC 4210, RFC 4211, and RFC 4212. It can operate as a CMP client, sending requests to a CMP server, or as a mock CMP server, processing requests from a CMP client.

The CMP protocol can be used for certificate lifecycle management, including enrollment, revocation, and update.

The following sections describe the CMP specific options.

CMP message options

-recipient recipient
The recipient of CMP requests. Defaults to the subject DN of the pinned -srvcert, if any. If not specified, and no -srvcert is pinned, then the recipient is taken from the PKI target of the CMP server configuration.
-expected_sender name
Distinguished Name (DN) expected in the sender field of incoming CMP messages. Defaults to the subject DN of the pinned -srvcert, if any.

DESCRIPTION

The openssl-cmp utility is a client and server implementation of the Certificate Management Protocol (CMP) as specified in RFC 4210 and its relevant successors.

CMP is an infrastructure protocol for certificate management. It allows a client to request enrollment, renewal, and revocation of certificates from a Certificate Authority (CA). It also supports other certificate management operations.

The openssl-cmp utility can be used in several modes:

  • As a CMP client sending requests to a CMP server.
  • As a mock CMP server receiving requests from a CMP client.
  • As a mock CMP server reading requests from and writing responses to files.
  • As a CMP client reading requests from and writing responses to files.

This manual page covers the options for the openssl-cmp utility. It is split into several sections based on the functionality of the options.

DESCRIPCIÓN

El comando openssl cmp es un cliente para el protocolo de inscripción de certificados (CMP, RFC 4210).

El protocolo CMP se utiliza para la inscripción y gestión de certificados X.509. Permite a un cliente (por ejemplo, un dispositivo o una aplicación) solicitar certificados a una autoridad de certificación (CA).

Este comando es una herramienta versátil que puede realizar diversas operaciones CMP, como:

  • Solicitar un nuevo certificado.
  • Obtener un certificado existente.
  • Revocar un certificado.
  • Realizar pruebas de presencia de clave (POP).
  • Gestionar certificados para tarjetas inteligentes.
  • Interactuar con servidores SCEP (Simple Certificate Enrollment Protocol) y otros servicios CMP.

El comando admite varios formatos de entrada y salida, la autenticación del cliente, la validación del certificado del servidor y la configuración de certificados proxy.

NOTAS

Esta herramienta es compleja y puede requerir una comprensión detallada del protocolo CMP y de los requisitos de la infraestructura de clave pública (PKI).

Se recomienda utilizar las opciones de verificación de certificados del servidor para garantizar la autenticidad del servidor CMP.

Las opciones específicas y sus combinaciones dependen de las capacidades del servidor CMP y de los requisitos de la operación.

EJEMPLOS

Solicitar un nuevo certificado de un servidor CMP:

openssl cmp -server_cert_url https://example.com/cmp -cert client.pem -key client.key -new -certreq

Revocar un certificado:

openssl cmp -server_cert_url https://example.com/cmp -cert client.pem -key client.key -revreq -cert_to_revoke cert.pem
