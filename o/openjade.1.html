NOMBRE

openjade - aplica una hoja de estilos DSSSL a un documento SGML o XML

SINOPSIS

openjade [-vCegG2s] [-b codificación] [-f archivo_errores]
         [-c sysid_catálogo] [-D directorio] [-a tipo_enlace]
         [-A archivo] [-E max_errores] [-i entidad]
         [-w tipo_advertencia] [-d espec_dsssl] [-V variable=valor]
         [-t tipo_salida] [-o archivo_salida] [sysid...]

DESCRIPCIÓN

openjade es una implementación del lenguaje DSSSL estándar ISO/IEC 10179:1996. El motor DSSSL recibe como entrada un documento SGML o XML y lo transforma a formatos como:

* Representación XML del árbol de objetos de flujo.

* Formato RTF que puede ser renderizado e impreso con Word Viewer 97 gratuito de Microsoft

* Formato TeX

* Formato MIF que puede ser renderizado e impreso con Framemaker

* Formato SGML o XML. Esto se utiliza en conjunción con clases de objetos de flujo no estándar para generar SGML, permitiendo así que openjade se utilice para transformaciones SGML/XML.

El identificador del sistema del documento a procesar se especifica como un argumento para openjade. Si se omite, se leerá la entrada estándar.

openjade determina el identificador del sistema para la especificación DSSSL de la siguiente manera:

1. Si se especifica la opción -d, usará el argumento como identificador del sistema.

2. De lo contrario, buscará instrucciones de procesamiento en el prólogo del documento. Se reconocen dos tipos de instrucciones de procesamiento:

<?stylesheet href="sysid" type="text/dsssl">

El identificador del sistema de la instrucción de procesamiento se analiza como una etiqueta de inicio SGML. Se analizará utilizando la sintaxis concreta de referencia, independientemente de la sintaxis concreta real del documento. El nombre que inicia la instrucción de procesamiento puede ser stylesheet, xml-stylesheet o xml:stylesheet. La instrucción de procesamiento se ignorará a menos que el valor del atributo type sea uno de text/dsssl, text/x-dsssl, application/dsssl o application/x-dsssl. El valor del atributo href es el identificador del sistema de la especificación DSSSL.

<?dsssl sysid>

El identificador del sistema es la porción de los datos del sistema de la instrucción de procesamiento que sigue al nombre inicial y a cualquier espacio en blanco.

Aunque la instrucción de procesamiento solo se reconoce en el prólogo, no tiene por qué aparecer en la entidad del documento. Por ejemplo, podría aparecer en una DTD. El identificador del sistema se interpretará en relación con dónde ocurre la instrucción de procesamiento.

3. De lo contrario, usará el identificador del sistema del documento con cualquier extensión cambiada a .dsl.

Un documento de especificación DSSSL puede contener más de una especificación de estilo. Si el identificador del sistema de la especificación DSSSL va seguido de #id, entonces openjade usará la especificación-de-estilo cuyo identificador único sea id. Esto está permitido tanto con la opción -d como con las instrucciones de procesamiento.

La especificación DSSSL debe ser un documento SGML que cumpla con la arquitectura DSSSL. Como ejemplo, véase dsssl/demo.dsl.

openjade admite las siguientes opciones además de las opciones normales de OpenSP (ver onsgmls(1)) (tenga en cuenta que todas las opciones distinguen entre mayúsculas y minúsculas, es decir, -g y -G son opciones diferentes):

-d espec_dsssl
Esto especifica que espec_dsssl es el identificador del sistema de la especificación DSSSL a utilizar.
-G
Modo de depuración. Cuando ocurre un error en la evaluación de una expresión, openjade mostrará un rastreo de pila. Tenga en cuenta que esto deshabilita la optimización de llamadas de cola.
-c nombre_archivo
Los argumentos de nombre_archivo especifican archivos de catálogo en lugar de la entidad del documento. La entidad del documento se especifica mediante la primera entrada DOCUMENT en los archivos de catálogo.
-s
Modo de cumplimiento estricto. Actualmente, el único efecto es que jade no utiliza ningún nombre de carácter predefinido, mapeos de entidad sdata ni caracteres de nombre. Esto es útil para comprobar que su hoja de estilos es portable a otras implementaciones DSSSL y que cumple estrictamente con las especificaciones DSSSL.
-t tipo_salida
tipo_salida especifica el tipo de salida de la siguiente manera:

fot Una representación XML del árbol de objetos de flujo

rtf rtf-95 RTF (utilizado para transformaciones de SGML/XML a RTF) Formato de texto enriquecido de Microsoft. rtf-95 produce salida optimizada para Word 95 en lugar de Word 97.

tex TeX (utilizado para transformaciones de SGML/XML a TeX)

sgml sgml-raw SGML (utilizado para transformaciones de SGML/XML a SGML). sgml-raw no emite saltos de línea en las etiquetas.

xml xml-raw XML (utilizado para transformaciones de SGML/XML a XML). xml-raw no emite saltos de línea en las etiquetas.

html HTML (utilizado para transformaciones de SGML/XML a HTML)

mif MIF (utilizado para transformaciones de SGML/XML a MIF)

-o archivo_salida
Escribir la salida en archivo_salida en lugar del valor por defecto. El nombre de archivo por defecto es el nombre del último archivo de entrada con su extensión reemplazada por el nombre del tipo de salida. Si no hay nombre de archivo de entrada, la extensión se añade a jade-out.
-V variable
Esto es equivalente a hacer (define variable #t) excepto que esta definición tendrá prioridad sobre cualquier definición de variable en una hoja de estilos.
-V variable=valor
Esto es equivalente a hacer (define variable "valor") excepto que esta definición tendrá prioridad sobre cualquier definición de variable en una hoja de estilos.
-V (define variable valor)
Esto es equivalente a hacer (define variable valor) excepto que esta definición tendrá prioridad sobre cualquier definición de variable en una hoja de estilos. Tenga en cuenta que probablemente tendrá que utilizar algún mecanismo de escape para los espacios para que la expresión scheme completa se analice como un único argumento de línea de comandos.
-wtipo
Controla advertencias y errores. Se permiten múltiples opciones -w. Los siguientes valores de tipo habilitan advertencias:

xml Advierte sobre construcciones que no están permitidas por XML.

mixed Advierte sobre modelos de contenido mixto que no permiten #pcdata en ninguna parte.

sgmldecl Advierte sobre varias construcciones dudosas en la declaración SGML.

should Advierte sobre varias recomendaciones hechas en ISO 8879 que el documento no cumple. (Las recomendaciones se expresan con ``should'', a diferencia de los requisitos que suelen expresarse con ``shall''.)

default Advierte sobre referencias por defecto.

duplicate Advierte sobre declaraciones de entidades duplicadas.

undefined Advierte sobre elementos no definidos: elementos utilizados en la DTD pero no definidos.

unclosed Advierte sobre etiquetas de inicio y fin no cerradas.

empty Advierte sobre etiquetas de inicio y fin vacías.

net Advierte sobre etiquetas de inicio que habilitan la red y etiquetas de fin nulas.

min-tag Advierte sobre etiquetas de inicio y fin minimizadas. Equivalente a una combinación de advertencias unclosed, empty y net.

unused-map Advierte sobre mapas de referencias cortas no utilizados: mapas que se declaran con una declaración de mapeo de referencias cortas pero que nunca se utilizan en una declaración de uso de referencias cortas en la DTD.

unused-param Advierte sobre entidades de parámetro que se definen pero no se utilizan en una DTD. Las entidades de parámetro internas no utilizadas cuyo texto es INCLUDE o IGNORE no generarán la advertencia.

notation-sysid Advierte sobre notaciones para las que no se pudo generar un identificador de sistema.

all Advierte sobre condiciones que normalmente deberían evitarse (en opinión del autor). Equivalente a: mixed, should, default, undefined, sgmld

ADVERTENCIAS

Las advertencias se habilitan con la opción -w seguida de un tipo de advertencia. Por ejemplo, -wduplicate avisa sobre declaraciones de entidades duplicadas. Los tipos de advertencia soportados actualmente son: duplicate, empty, ecl, unused-map, unused-param, empty y unclosed.

Una advertencia puede deshabilitarse usando su nombre prefijado con no-. Así, -wall -wno-duplicate habilitará todas las advertencias excepto las de declaraciones de entidades duplicadas.

Los siguientes valores para warning_type deshabilitan errores:

no-idref No emitir un error para un valor de referencia ID que ningún elemento tenga como su ID. El efecto será como si cada atributo declarado como valor de referencia ID hubiera sido declarado como un nombre.

no-significant No emitir un error cuando un carácter que no es un carácter significativo en la sintaxis concreta de referencia ocurre en un literal en la declaración SGML. Esto puede ser útil en conjunción con ciertos conjuntos de pruebas erróneos.

no-valid No requerir que el documento sea tipo-válido. Esto tiene el efecto de cambiar la declaración SGML para especificar VALIDITY NOASSERT e IMPLYDEF ATTLIST YES ELEMENT YES. Una opción -wvalid tiene el efecto de cambiar la declaración SGML para especificar VALIDITY TYPE e IMPLYDEF ATTLIST NO ELEMENT NO. Si no se especifica ni -wvalid ni -wno-valid, se utilizarán los valores de VALIDITY e IMPLYDEF especificados en la declaración SGML.

ENTORNO

OpenJade ignora las variables de entorno SP_CHARSET_FIXED y SP_SYSTEM_CHARSET y siempre usa Unicode como su conjunto de caracteres interno, como si SP_CHARSET_FIXED fuera 1 y SP_SYSTEM_CHARSET estuviera sin definir. Por lo tanto, solo la variable de entorno SP_ENCODING es relevante para el manejo de conjuntos de caracteres de OpenJade.

EXTENSIONES DE OPENJADE

Los siguientes procedimientos externos están disponibles. Estos procedimientos externos se definen mediante un prototipo de la misma manera que en el estándar. Para usar uno de estos procedimientos externos, debe utilizar el procedimiento estándar external-procedure, usando un identificador público de "UNREGISTERED::James Clark//Procedure::name" donde name es el nombre dado aquí, típicamente incluyendo lo siguiente en la especificación DSSSL:

(define name (external-procedure "UNREGISTERED::James Clark//Procedure::name"))

Tenga en cuenta que external-procedure devuelve #f si no conoce el identificador público especificado. Puede usar esto para que sus especificaciones DSSSL funcionen correctamente con otras implementaciones que no admiten estas extensiones.

Para los procedimientos externos añadidos por el equipo de OpenJade, utilice un identificador público de la forma "UNREGISTERED::OpenJade//Procedure::name".

Una forma fácil de acceder a todos los procedimientos externos es utilizar la especificación de estilo dsssl/extensions.dsl#procedures. El archivo dsssl/extensions.dsl también contiene especificaciones de estilo que hacen que las clases de objetos de flujo no estándar y las características heredadas soportadas por los backends estén disponibles de manera conveniente.

Depuración

(debug obj)

Genera un mensaje que incluye el valor de obj y luego devuelve obj.

Control de encabezado/pie de página de simple-page-sequence

(if-first-page sosofo1 sosofo2)

Esto solo se puede usar en la especificación del valor de una de las características de encabezado/pie de página de simple-page-sequence. Devuelve un sosofo que se mostrará como sosofo1 si la página es la primera página de la simple-page-sequence y como sosofo2 en caso contrario.

(if-front-page sosofo1 sosofo2)

Esto solo se puede usar en la especificación del valor de una de las características de encabezado/pie de página de simple-page-sequence. Devuelve un sosofo que se mostrará como sosofo1 si la página es una página frontal (es decir, de la derecha, de número impar) y como sosofo2 si es una página trasera (es decir, de la izquierda, de número par).

Numeración

(all-element-number)

(all-element-number osnl)

Esto es lo mismo que element-number, excepto que cuenta elementos con cualquier identificador genérico. Si osnl no es un elemento, devuelve #f; de lo contrario, devuelve 1 más el número de elementos que comenzaron antes de osnl. Esto proporciona una forma eficiente de crear un identificador único para cualquier elemento de un documento.

Acceso a entidades externas

(read-entity string)

Esto devuelve una cadena que contiene el contenido de la entidad externa con el identificador del sistema string. Esto solo debe usarse para entidades textuales (CDATA y SDATA), y no para entidades binarias (NDATA).

Acceso a la configuración regional POSIX

(language lang country)

Este procedimiento devuelve un objeto de tipo language, si el sistema soporta el lenguaje especificado. lang es una cadena o símbolo que indica el código de idioma de dos letras. country es una cadena o símbolo que indica el código de país de dos letras.

Este procedimiento utiliza la configuración regional POSIX. Es una adición de OpenJade. No es compatible con todos los sistemas operativos.

Procedimientos estándar extendidos

(sgml-parse sysid #!key active: parent: architecture:)

Esto le permite especificar una arquitectura SGML con respecto a la cual se debe analizar el documento. Es una adición de OpenJade.

(expt q k)

Esto le permite elevar una cantidad a una potencia entera. Es una adición de OpenJade.

LIMITACIONES

Esta sección describe las limitaciones del front-end (el motor DSSSL de propósito general); cada backend también tiene sus propias limitaciones.

openjade no permite definiciones internas al principio de los cuerpos y la variante (test => recipient) de las cláusulas cond.

openjade solo soporta un único plan de árbol fijo que comprende los siguientes módulos:

* baseabs

* prlgabs0

* prlgabs1

* instabs

* basesds0

* instsds0

* subdcabs

No implementa las siguientes partes de SDQL: soporte HyTime, análisis auxiliar, expresiones regulares de nodos.

Las reglas de consulta, la sincronización de sosofo, los sosofos indirectos, los valores de referencia, las áreas de decoración y las propiedades de fuente no son compatibles.

Tenga en cuenta que solo se pueden especificar las características heredadas que sean aplicables a algún objeto de flujo compatible.

Manejo de caracteres/glifos

Solo soporta un único repertorio de caracteres predefinido. Un nombre de carácter de la forma U-XXXX donde XXXX son cuatro dígitos hexadecimales en mayúsculas, se reconoce como referencia al carácter Unicode con ese código. Para muchos caracteres, también es posible usar el nombre ISO/IEC 10646 en minúsculas con palabras separadas por guiones.

Se reconocen y mapean algunos nombres de entidades SDATA comunes de los conjuntos de entidades ISO a caracteres. Además, un nombre de entidad SDATA de la forma U-XXXX, donde XXXX son cuatro dígitos hexadecimales en mayúsculas, se mapea al carácter Unicode con ese código.

OpenJade ahora soporta las formas de elemento de declaración standard-chars, map-sdata-entity, add-name-chars, add-separator-chars y char-repertoire, permitiendo que una hoja de estilo defina nombres de caracteres adicionales, mapeos de entidades sdata, caracteres de nombre (es decir, caracteres permitidos en identificadores) y caracteres separadores. Actualmente, el único repertorio de caracteres reconocido es el repertorio incorporado. Tiene el identificador público "UNREGISTERED::OpenJade//Character Repertoire::OpenJade".

Validación

Varias cosas que sería deseable verificar no se verifican:

* Cuando el valor permitido de una característica heredada es un símbolo, OpenJade solo verifica que el valor sea un símbolo que está permitido como valor de alguna característica; #t y #f se tratan como un tipo especial de símbolo en este caso.

* OpenJade no verifica si un objeto de flujo está ocurriendo en un contexto donde está permitido.

* OpenJade no impide que los objetos de flujo se adjunten al puerto principal de un objeto de flujo cuando el objeto de flujo no debería tener un puerto principal.

* La mayor parte de la verificación de tipos se realiza en tiempo de ejecución, no en tiempo de compilación.

* OpenJade no verifica las características no heredadas que se requieren especificar.

* No verifica que las características opcionales que se han utilizado se hayan declarado en la forma features.

Otras limitaciones

Los siguientes primitivos son solo stubs:

char-script-case Siempre devuelve el último argumento.

address-visited? Siempre devuelve #f.

EJEMPLOS

Dado un archivo SGML file.sgml, usar la hoja de estilos file.dsl y publicar como un archivo rtf.

openjade -t rtf file.sgml

Usando una hoja de estilos diferente:

openjade -t rtf -d docbook.dsl

Usando la especificación de estilo print contenida dentro de la hoja de estilos

openjade -t rtf -d docbook.dsl#print file.sgml

Y usar la especificación html dentro de la hoja de estilos para convertir a html

openjade -t sgml -i html -d docbook.dsl#html file.sgml

openjade(1)

openjade - un procesador SGML/XML de software libre

SINOPSIS

openjade [OPCIONES]... [ARCHIVO]

DESCRIPCIÓN

openjade es un procesador SGML/XML de software libre que genera archivos de salida a partir de archivos de entrada. Soporta la mayoría de las características del estándar SGML y un subconjunto de XML. Puede ser extendido para soportar formatos de marcado personalizados.

OPCIONES

Se pueden encontrar opciones detalladas en la página del manual de OpenJade.

AMBIENTE

Las variables de entorno relevantes para openjade se documentan en su página del manual.

EXTENSIONES DE OPENJADE

openjade soporta varias extensiones que van más allá del estándar SGML/XML, permitiendo una mayor flexibilidad y personalización.

LIMITACIONES

Como cualquier software, openjade tiene sus limitaciones, que pueden incluir rendimiento en archivos muy grandes o soporte para estándares muy específicos.

EJEMPLOS

openjade -t html input.sgml

openjade -o output.fo input.xml

VER TAMBIÉN

jade(1), sgml(5), xml(5)
