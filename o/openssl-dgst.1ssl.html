NOMBRE

openssl-dgst - realiza operaciones de resumen

SINOPSIS

openssl dgst|resumen [-resumen] [-list] [-help] [-c] [-d] [-debug] [-hex] [-binary] [-xoflen longitud] [-r] [-out nombre_archivo] [-sign nombre_archivo|uri] [-keyform DER|PEM|P12|ENGINE] [-passin arg] [-verify nombre_archivo] [-prverify nombre_archivo] [-signature nombre_archivo] [-sigopt nm:v] [-hmac clave] [-mac alg] [-macopt nm:v] [-fips-fingerprint] [-engine id] [-engine_impl id] [-rand archivos] [-writerand archivo] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq] [archivo ...]

DESCRIPCIÓN

Este comando genera el resumen del mensaje de uno o varios archivos suministrados en formato hexadecimal, y también genera y verifica firmas digitales utilizando resúmenes de mensajes.

El nombre genérico, openssl dgst, puede usarse con una opción que especifique el algoritmo a utilizar. El resumen predeterminado es sha256. Un nombre de resumen soportado también puede usarse como nombre del subcomando. Para ver la lista de algoritmos soportados, usa "openssl list -digest-algorithms"

OPCIONES

-help
Imprime un mensaje de uso.
-resumen
Especifica el nombre de un resumen soportado a ser utilizado. Ver la opción -list abajo:
-list
Imprime una lista de resúmenes de mensajes soportados.
-c
Imprime el resumen en grupos de dos dígitos separados por dos puntos, solo relevante si la opción -hex también se da.
-d, -debug
Imprime información de depuración de BIO.
-hex
El resumen se mostrará como un volcado hexadecimal. Este es el caso predeterminado para un resumen "normal" en contraposición a una firma digital. Ver NOTAS abajo para firmas digitales usando -hex.
-binary
Muestra el resumen o la firma en formato binario.
-xoflen longitud
Establece la longitud de salida para algoritmos XOF, como shake128 y shake256. Esta opción no es compatible con operaciones de firma.

Para los proveedores de OpenSSL, es necesario establecer este valor para los algoritmos shake, ya que los valores predeterminados anteriores solo se establecieron para suministrar la mitad de la resistencia de seguridad máxima.

Para garantizar la máxima resistencia de seguridad de 128 bits, el xoflen para shake128 debe establecerse en al menos 32 (bytes). Para compatibilidad con versiones anteriores de OpenSSL, puede establecerse en 16, lo que resulta en una resistencia de seguridad de solo 64 bits.

Para garantizar la máxima resistencia de seguridad de 256 bits, el xoflen para shake256 debe establecerse en al menos 64 (bytes). Para compatibilidad con versiones anteriores de OpenSSL, puede establecerse en 32, lo que resulta en una resistencia de seguridad de solo 128 bits.

-r
Muestra el resumen en el formato "coreutils", incluyendo saltos de línea. Usado por programas como sha1sum(1).
-out nombre_archivo
Nombre del archivo de salida, o salida estándar por defecto.
-sign nombre_archivo|uri
Firma digitalmente el resumen usando la clave privada dada.

Tenga en cuenta que para algoritmos que solo admiten firma de un solo paso (como Ed25519, ED448, ML-DSA-44, ML-DSA-65 y ML-DSA-87) el resumen no debe ser establecido. Para estos algoritmos, la entrada se almacena en búfer (y no se resume) antes de firmar. Para estos algoritmos, si la entrada es mayor a 16MB ocurrirá un error.

-keyform DER|PEM|P12|ENGINE
El formato de la clave para firmar; no especificado por defecto. Ver openssl-format-options(1) para detalles.
-sigopt nm:v
Pasa opciones al algoritmo de firma durante las operaciones de firma o verificación. Los nombres y valores de estas opciones son específicos del algoritmo y se documentan en "Parámetros de firma" en provider-signature(7).
-passin arg
La fuente de la contraseña de la clave privada; Para más información sobre el formato de arg ver openssl-passphrase-options(1).
-verify nombre_archivo
Verifica la firma usando la clave pública en "nombre_archivo". La salida es "Verified OK" o "Verification Failure".
-prverify nombre_archivo
Verifica la firma usando la clave privada en "nombre_archivo".
-signature nombre_archivo
La firma real a verificar.
-hmac clave
Crea un MAC (Message Authentication Code) hasheado usando "clave".

Se debería preferir el comando openssl-mac(1) al uso de esta opción de línea de comandos.

-mac alg
Crea un MAC (Message Authentication Code) con clave. El algoritmo MAC más popular es HMAC (MAC basado en hash), pero existen otros algoritmos MAC que no se basan en hash, por ejemplo el algoritmo gost-mac, soportado por el motor gost. Las claves MAC y otras opciones deben ser configuradas mediante el parámetro -macopt.

Se debería preferir el comando openssl-mac(1) al uso de esta opción de línea de comandos.

-macopt nm:v
Pasa opciones al algoritmo MAC, especificado por la clave -mac. Las siguientes opciones son soportadas tanto por HMAC como por gost-mac:
key:cadena
Especifica la clave MAC como una cadena alfanumérica (usar si la clave contiene solo caracteres imprimibles). La longitud de la cadena debe cumplir con cualquier restricción del algoritmo MAC, por ejemplo, exactamente 32 caracteres para gost-mac.
hexkey:cadena
Especifica la clave MAC en formato hexadecimal (dos dígitos hexadecimales por byte). La longitud de la clave debe cumplir con cualquier restricción del algoritmo MAC, por ejemplo, exactamente 32 caracteres para gost-mac.

Se debería preferir el comando openssl-mac(1) al uso de esta opción de línea de comandos.

-fips-fingerprint
Calcula HMAC usando una clave específica para ciertas operaciones OpenSSL-FIPS.
-rand archivos, -writerand archivo
Ver "Opciones de estado aleatorio" en openssl(1) para detalles.
-engine id
Ver "Opciones de motor" en openssl(1). Esta opción está en desuso.

El motor no se usa para resúmenes a menos que se use la opción -engine_impl o esté configurado para hacerlo, ver "Módulo de configuración del motor" en config(5).

-engine_impl id
Cuando se usa con la opción -engine, especifica usar también el motor id para operaciones de resumen.

NAME

openssl-dgst

digest message digests

SYNOPSIS

openssl dgst [-sha1] [-sha224] [-sha256] [-sha384] [-sha512]
    [-sha512-224] [-sha512-256] [-sha3-224] [-sha3-256] [-sha3-384] [-sha3-512]
    [-shake128] [-shake256] [-md4] [-md5] [-blake2b512] [-blake2s256]
    [-rc4] [-des] [-des3] [-des-ede3-cbc] [-idea] [-idea-cbc] [-bf] [-bf-cbc]
    [-cast] [-cast-cbc] [-aes-128-cbc] [-aes-192-cbc] [-aes-256-cbc]
    [-aes-128-ecb] [-aes-192-ecb] [-aes-256-ecb] [-camellia-128-cbc]
    [-camellia-192-cbc] [-camellia-256-cbc] [-dh] [-dss] [-ec] [-ecdsa]
    [-ecdh] [-rsa] [-aria-128-cbc] [-aria-192-cbc] [-aria-256-cbc]
    [-seed] [-seed-cbc] [-ghash]
    [-cipher ] [-variant ] [-mac ]
    [-macopt ] [-provider ] [-provider-path ]
    [-provarg ] [-propquery ] [-propfile ]
    [-ciphers ] [-s2k-cipher-algo ] [-s2k-digest-algo ]
    [-waldp ] [-waldpfile ] [-waldp_iter ]
    [-iter ] [-pbkdf2 ] [-pbkdf2opt ] [-pbkdf2_iter ]
    [-digest ] [-text] [-hex] [-binary] [-crlf]
    [-verify  | -verify_rsa ] [-signature ]
    [-hmac ] [-old-hmac] [-evp] [-sign  | -sign_rsa ]
    [-keyform ] [-passin ] [-passout ]
    [-rand ] [-engine ] [-engine_impl ]
    [-check] [-list] [-help] [-version]

DESCRIPTION

The dgst command is a general purpose message digest and signature generator. It can compute and verify message digests using any of the digest algorithms, symmetric ciphers, or digest algorithms that have been supplied by the OpenSSL providers.

A message digest (also known as a hash) is a fixed-size string of bytes that is generated from a larger piece of data. This is done using a cryptographic hash function. Digests are typically used to verify data integrity. For example, if you download a file and its MD5 checksum, you can calculate the MD5 checksum of the file you downloaded. If it matches the one provided, you can be reasonably sure that the file was not corrupted during download.

Digital signatures provide authentication, integrity, and non-repudiation. A signature is generated by first computing a digest of the data to be signed, and then encrypting that digest with a private key. To verify a signature, the digest is decrypted using the corresponding public key, and then compared with a digest computed independently from the data.

OPTIONS

The following options are available:

-sha1, -sha224, -sha256, -sha384, -sha512, -sha512-224, -sha512-256, -sha3-224, -sha3-256, -sha3-384, -sha3-512, -shake128, -shake256, -md4, -md5, -blake2b512, -blake2s256, -rc4, -des, -des3, -des-ede3-cbc, -idea, -idea-cbc, -bf, -bf-cbc, -cast, -cast-cbc, -aes-128-cbc, -aes-192-cbc, -aes-256-cbc, -aes-128-ecb, -aes-192-ecb, -aes-256-ecb, -camellia-128-cbc, -camellia-192-cbc, -camellia-256-cbc, -aria-128-cbc, -aria-192-cbc, -aria-256-cbc, -seed, -seed-cbc, -ghash
Specifies the digest algorithm to use. If no algorithm is specified, then SHA256 is used by default. The supported algorithms are listed by openssl list -digest-algorithms.
-cipher ciphername
Specifies a cipher name, e.g. -aes-256-cbc. This option is equivalent to specifying the cipher name directly, e.g. openssl dgst -aes-256-cbc. This option is mostly useful for compatibility with older versions of OpenSSL. It can also be used to specify digests not typically associated with the dgst command, such as stream ciphers.
-variant variant
Specifies the variant for certain algorithms, e.g. openssl dgst -sha512 -variant 512/224. Currently supported for SHA-512.
-mac macname
Specifies a Message Authentication Code (MAC) algorithm. The supported MACs are listed by openssl list -mac-algorithms.
-macopt opt=val
Specifies MAC-specific options. See openssl-mac(1) for a list of available options.
-provider name
-provider-path path
-provparam [name:]key=value
-propquery propq
See "Provider Options" in openssl(1), provider(7), and property(7).
file ...
File or files to digest. If no files are specified then standard input is used.

EXAMPLES

To create a hex-encoded message digest of a file:

openssl dgst -md5 -hex file.txt
or
openssl md5 file.txt

To sign a file using SHA-256 with binary file output:

openssl dgst -sha256 -sign privatekey.pem -out signature.sign file.txt
or
openssl sha256 -sign privatekey.pem -out signature.sign file.txt

To verify a signature:

openssl dgst -sha256 -verify publickey.pem \
-signature signature.sign \
file.txt

NOTES

The digest mechanisms that are available will depend on the options used when building OpenSSL. The "openssl list -digest-algorithms" command can be used to list them.

New or agile applications should use probably use SHA-256. Other digests, particularly SHA-1 and MD5, are still widely used for interoperating with existing formats and protocols.

When signing a file, this command will automatically determine the algorithm (RSA, ECC, etc) to use for signing based on the private key's ASN.1 info. When verifying signatures, it only handles the RSA, DSA, or ECDSA signature itself, not the related data to identify the signer and algorithm used in formats such as x.509, CMS, and S/MIME.

A source of random numbers is required for certain signing algorithms, in particular ECDSA and DSA.

The signing and verify options should only be used if a single file is being signed or verified.

Hex signatures cannot be verified using openssl. Instead, use "xxd -r" or similar program to transform the hex signature into a binary signature prior to verification.

The openssl-mac(1) command is preferred over the -hmac, -mac and -macopt command line options.

HISTORY

The default digest was changed from MD5 to SHA256 in OpenSSL 1.1.0. The FIPS-related options were removed in OpenSSL 1.1.0.

The -engine and -engine_impl options were deprecated in OpenSSL 3.0.
