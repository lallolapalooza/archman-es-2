Descripción detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es para usuarios avanzados y experimentados. No lo necesitas a menos que sepas realmente lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se han limitado a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivos de archivo.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo que PhysicsFS no proporciona directamente: quizás algún formato propietario que solo tu aplicación necesite entender.

Internamente, todo el soporte de archivo incorporado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver son el código fuente de PhysicsFS.

Un archivador se añade al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automáticamente con PHYSFS_mount(); si un archivo dado puede ser gestionado por tu archivador, se le dará el control según corresponda.

Estos métodos tratan con identificadores de directorio. Tienes una instancia de tu archivador, y genera un identificador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archiver (no de un archivo) es generalmente la vida útil del proceso, y se asume que es un singleton, no proporcionamos ningún dato de instancia para el propio archivador; la aplicación puede simplemente usar algunas variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para comprobar los enlaces simbólicos y tomará una decisión sobre si continuar llamando a otros métodos basándose en eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de devolver. PhysicsFS pasará estos errores a la aplicación sin modificación en la mayoría de los casos.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Archiver sean seguras para hilos en sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador dado dentro de la biblioteca, pero no promete que usar el mismo PHYSFS_File desde dos hilos a la vez sea seguro para hilos; como tal, tu PHYSFS_Archiver puede asumir que el bloqueo se maneja por ti siempre que el PHYSFS_Io que devuelves de PHYSFS_open* no cambie ningún estado de tu Archiver, ya que el PHYSFS_Io no estará tan agresivamente protegido.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruye un archivo previamente abierto. Cierra este archivo y libera toda la memoria asociada, incluido el PHYSFS_Io original y el propio (opaque), si procede. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Lista todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, para que puedas desecharla al regresar de la llamada de retorno. (dirname) está en notación independiente de plataforma. Si tienes un error, llama a PHYSFS_SetErrorCode() con el código que parezca apropiado y devuelve PHYSFS_ENUM_ERROR. Si la llamada de retorno devuelve PHYSFS_ENUM_ERROR, llama a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y devuelve también PHYSFS_ENUM_ERROR. No llames a la llamada de retorno nuevamente bajo ninguna circunstancia. Si la llamada de retorno devuelve PHYSFS_ENUM_STOP, deja de enumerar y devuelve también PHYSFS_ENUM_STOP. No llames a la llamada de retorno nuevamente bajo ninguna circunstancia. No establezcas un código de error en este caso. Las llamadas de retorno solo deben devolver un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene un comportamiento indefinido. Mientras la llamada de retorno haya devuelto PHYSFS_ENUM_OK y no hayas experimentado ningún error propio, sigue enumerando hasta que termines y luego devuelve PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate devuelve cero o no cero (éxito o fallo), ¡así que ten en cuenta que este puntero de función devuelve valores diferentes!

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Esto se utiliza para identificar tu archivo y se devuelve en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crea un directorio en el archivo. Si la aplicación está intentando crear varios directorios, PhysicsFS los dividirá en varias llamadas antes de pasarlos a tu controlador. Si el archivo es de solo lectura, esta operación debería fallar. Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abre un archivo en este archivo para añadir. Si el archivo no existe, debería crearse. El desplazamiento de escritura debería ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de plataforma. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto se pasará como el parámetro "opaque" para futuras llamadas de archivo.

Abre un archivo en este archivo para escritura. Si el archivo existe, debería ser truncado. Si el archivo no existe, debería crearse. Si el archivo es de solo lectura, esta operación debería fallar. El puntero devuelto se pasará como el parámetro "opaque" para futuras llamadas de archivo.

Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. En caso de fallo, llama a PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Elimina un archivo o directorio en el archivo. Esta misma llamada se usa tanto para archivos como para directorios; no hay una llamada separada rmdir(). Los directorios solo deben eliminarse si están vacíos. Si el archivo es de solo lectura, esta operación debe fallar.

Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a **PHYSFS_setErrorCode()**.
