NOMBRE

opam-config - Muestra las opciones de configuración para los paquetes.

SINOPSIS

opam config [OPCIÓN]… [COMANDO] [ARG]…

DESCRIPCIÓN

Este comando utiliza el estado de opam para mostrar información sobre cómo usar las bibliotecas instaladas, actualizar el PATH, y sustituir variables usadas en los paquetes de opam.

Aparte de opam config env, la mayoría de estos comandos son utilizados internamente por opam, y son de interés limitado para el usuario casual.

COMANDOS

env
Devuelve los enlaces para las variables de entorno establecidas en el cambio actual, por ejemplo PATH, en un formato destinado a ser evaluado por un shell. Con -v, añade comentarios que documentan la razón o el paquete de origen para cada enlace. Esto se usa más útilmente como eval $(opam config env) para que los comandos posteriores del shell sean evaluados en el contexto adecuado de opam. También se puede acceder a través de opam env.
revert-env
Revierte los cambios de entorno realizados por opam, por ejemplo eval $(opam config revert-env) deshace lo que hizo eval $(opam config env), tanto como sea posible.
list [PAQUETE]...
Sin argumento, imprime una lista documentada de todas las variables disponibles. Con PAQUETE, lista todas las variables disponibles para esos paquetes.
expand CADENA
Expande las interpolaciones de variables en la cadena dada
subst ARCHIVO...
Sustituye variables en los archivos dados. Las cadenas %{var}% se reemplazan por el valor de la variable var (ver var).
report
Imprime un resumen de tu configuración, útil para informes de errores.
cudf-universe [ARCHIVO]
Muestra el universo de paquetes disponible actualmente en formato CUDF.
pef-universe [ARCHIVO]
Muestra el universo de paquetes actual en formato PEF.
exec [--] COMANDO [ARG]...
Eliminado en 2.1, usa opam exec en su lugar.
set VAR VALOR
Eliminado en 2.1, usa opam var en su lugar.
unset VAR
Eliminado en 2.1, usa opam var en su lugar.
set-global VAR VALOR
Eliminado en 2.1, usa opam var en su lugar.
unset-global VAR
Eliminado en 2.1, usa opam var en su lugar.
var VAR
Eliminado en 2.1, usa opam var en su lugar.

OPCIONES

--inplace-path
Al actualizar la variable PATH, reemplaza cualquier ruta de opam preexistente en el lugar en lugar de colocar la nueva ruta al frente. Esto significa que los programas instalados en opam que estaban enmascarados seguirán siéndolo después de opam env.
--set-root
Con los subcomandos env y exec, también establece la variable OPAMROOT, asegurando que las llamadas posteriores a opam usarán la misma raíz.
--set-switch
Con los subcomandos env y exec, también establece la variable OPAMSWITCH, asegurando que las llamadas posteriores a opam usarán el mismo cambio que este.
--sexp
Imprime el entorno como una s-expresión en lugar de en formato de shell
--shell=SHELL
Establece el modo de configuración para el entorno de opam apropiado para SHELL. Uno de bash, sh, csh, zsh, fish, pwsh, cmd o powershell. Se adivina a partir de los procesos padres y la variable $SHELL por defecto.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Previsto para cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam de la misma serie MAYOR se comportará como para la versión MENOR especificada. El flag no estaba disponible en opam 2.0, por lo que para seleccionar la CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o sí-no-seguro. Se puede especificar más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL`.
--criteria=CRITERIOS
Especifica las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje soportado y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre el uso de las preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Igual que --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está establecida (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FMT] (predeterminado=auto)
Muestra esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable de entorno TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora pines adicionales requeridos por paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%`, se reemplazará por un índice que no sobrescribirá un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade

Answer yes to all opam yes/no questions without prompting. See also --confirm-level. This is equivalent to setting $OPAMYES to "true".

NAME

opam-config - modify opam configuration options

SYNOPSIS

opam-config [OPTIONS] [--config | --editor | --list | --path | --root | --shell | --solver-path | --switch] [VAR[=VALUE] ...]

DESCRIPTION

This command modifies settings in the opam configuration file.

COMMANDS

If no command is specified, defaults to --list.

--config
Set or query a configuration variable.
--editor
Set or query editor command.
--list
List all configuration variables and their current values.
--path
Set or query opam root path.
--root
Set or query opam root path.
--shell
Set or query shell settings.
--solver-path
Set or query the solver executable path.
--switch
Set or query the current switch settings.

OPTIONS

See also COMMON OPTIONS.

--help, -h
Display help.
--version, -v
Display version.

COMMON OPTIONS

These options are common to most opam commands.

--assume-already-locked
Assume the operation is already protected by a lock file.
--confirm-level=LEVEL
Set the confirmation level. Level can be low, medium, high, or none. Default is medium.
--dry-run, -n
Do not perform any changes, just show what would be done.
--json
Output results in JSON format.
--minimal-distro
Omit runtime dependencies when installing packages. Implies --with-doc and --with-test are disabled.
--no-auto
Disable automatic tasks, such as automatic update of the repository when required.
--no-backup
Do not backup files before modifying them.
--no-checks
Skip checks that could be performed before some operations.
--no-depexts
Do not install system dependencies.
--no-install
Do not install packages, only update the lock file.
--no-jbuild
Do not build packages using jbuilder, always use dune.
--no-partial
Disable partial installs. If a package cannot be fully installed, the operation fails.
--no-path-update
Do not update PATH environment variable with the bin directory of the installed packages.
--no-pin-depends
Do not pin dependencies of packages that are already pinned.
--no-shared-libs
Do not add shared libraries to the system library search path.
--no-source-only
Do not install packages marked as source-only.
--no-sync
Do not synchronise repositories before operating.
--no-trunc
Do not truncate package names to fit the terminal width.
--no-update-invariant
Do not check for update invariants.
--no-user-conf
Ignore user configuration files.
--no-verify
Do not verify package files.
--path=DIR
Use DIR as the opam root directory.
--pin-file=FILE
Use FILE as the source of pins.
--prefix=DIR
Use DIR as the installation prefix.
--solver=SOLVER
Use SOLVER as the dependency solver.
--solver-path=FILE
Use FILE as the solver executable.
--strict
Use strict checking, causing more errors to be raised.
--switch=SWITCH
Use SWITCH as the current switch.
--sync
Synchronise repositories before operating.
--testing-paths
Use testing paths for repositories.
--verbose, -v
Increase verbosity.
--verbose-on=COMMAND
Enable verbose mode for COMMAND.
--version-lag-power=N
Set the version lag power to N.
--with-dev-setup
Install development files.
--with-doc
Install documentation files.
--with-test
Install test files.
--working-dir=DIR
Set the working directory.
--yes, -y
Automatically confirm operations.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
