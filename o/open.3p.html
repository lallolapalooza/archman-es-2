OPEN(3P) Manual del programador de POSIX OPEN(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

open, openat — abrir archivo

SINOPSIS

#include <sys/stat.h>
#include <fcntl.h>
int open(const char *path, int oflag, ...);
int openat(int fd, const char *path, int oflag, ...);

DESCRIPCIÓN

La función open() establecerá la conexión entre un archivo y un descriptor de archivo. Creará una descripción de archivo abierto que se refiere a un archivo y un descriptor de archivo que se refiere a esa descripción de archivo abierto. El descriptor de archivo se utiliza para otras funciones de E/S para referirse a ese archivo. El argumento path apunta a un nombre de ruta que nombra el archivo.

La función open() devolverá un descriptor de archivo para el archivo nombrado, asignado como se describe en la Sección 2.14, Asignación de Descriptores de Archivo. La descripción del archivo abierto es nueva y, por lo tanto, el descriptor de archivo no la compartirá con ningún otro proceso en el sistema. La bandera de descriptor de archivo FD_CLOEXEC asociada con el nuevo descriptor de archivo se borrará a menos que la bandera O_CLOEXEC esté establecida en oflag.

El desplazamiento del archivo utilizado para marcar la posición actual dentro del archivo se establecerá al principio del archivo.

Las banderas de estado del archivo y los modos de acceso al archivo de la descripción del archivo abierto se establecerán de acuerdo con el valor de oflag.

Los valores para oflag se construyen mediante una OR inclusiva a nivel de bits de las banderas de la siguiente lista, definidas en <fcntl.h>. Las aplicaciones especificarán exactamente uno de los primeros cinco valores (modos de acceso al archivo) en el valor de oflag:

O_EXEC
Abrir solo para ejecución (archivos no directorios). El resultado no está definido si esta bandera se aplica a un directorio.
O_RDONLY
Abrir solo para lectura.
O_RDWR
Abrir para lectura y escritura. El resultado no está definido si esta bandera se aplica a una FIFO.
O_SEARCH
Abrir directorio solo para búsqueda. El resultado no está definido si esta bandera se aplica a un archivo que no es un directorio.
O_WRONLY
Abrir solo para escritura.

Se puede usar cualquier combinación de las siguientes:

O_APPEND
Si está establecida, el desplazamiento del archivo se establecerá al final del archivo antes de cada escritura.
O_CLOEXEC
Si está establecida, se establecerá la bandera FD_CLOEXEC para el nuevo descriptor de archivo.
O_CREAT
Si el archivo existe, esta bandera no tiene ningún efecto excepto como se indica en O_EXCL a continuación. De lo contrario, si O_DIRECTORY no está establecida, el archivo se creará como un archivo regular; el ID de usuario del archivo se establecerá en el ID de usuario efectivo del proceso; el ID de grupo del archivo se establecerá en el ID de grupo del directorio padre del archivo o en el ID de grupo efectivo del proceso; y las banderas de permiso de acceso del archivo (ver <sys/stat.h>) del modo de archivo se establecerán en el valor del argumento siguiente al argumento oflag tomado como tipo mode_t modificado de la siguiente manera: se realiza una operación AND a nivel de bits sobre los bits del modo de archivo y los bits correspondientes en el complemento de la máscara de creación de modo de archivo del proceso. Por lo tanto, todos los bits en el modo de archivo cuyo bit correspondiente en la máscara de creación de modo de archivo esté establecido se borrarán. Cuando se establezcan bits distintos de los bits de permiso de archivo, el efecto no está definido. El argumento siguiente al argumento oflag no afecta si el archivo se abre para lectura, escritura o ambas cosas. Las implementaciones proporcionarán una forma de inicializar el ID de grupo del archivo al ID de grupo del directorio padre. Las implementaciones pueden, pero no están obligadas a, proporcionar una forma definida por la implementación para inicializar el ID de grupo del archivo al ID de grupo efectivo del proceso que llama.
O_DIRECTORY
Si path se resuelve a un archivo que no es un directorio, falle y establezca errno en [ENOTDIR].
O_DSYNC
Las operaciones de E/S de escritura en el descriptor de archivo se completarán según lo definido por la finalización de integridad de datos de E/S sincronizada.
O_EXCL
Si O_CREAT y O_EXCL están establecidos, open() fallará si el archivo existe. La verificación de la existencia del archivo y la creación del archivo si no existe será atómica con respecto a otros hilos que ejecuten open() nombrando el mismo nombre de archivo en el mismo directorio con O_EXCL y O_CREAT establecidos. Si O_EXCL y O_CREAT están establecidos, y path nombra un enlace simbólico, open() fallará y establecerá errno en [EEXIST], independientemente del contenido del enlace simbólico. Si O_EXCL está establecido y O_CREAT no lo está, el resultado no está definido.
O_NOCTTY
Si está establecido y path identifica un dispositivo terminal, open() no hará que el dispositivo terminal se convierta en el terminal de control del proceso. Si path no identifica un dispositivo terminal, O_NOCTTY se ignorará.
O_NOFOLLOW
Si path nombra un enlace simbólico, falle y establezca errno en [ELOOP].
O_NONBLOCK
Al abrir una FIFO con O_RDONLY o O_WRONLY establecido:
*
Si O_NONBLOCK está establecido, una open() para solo lectura devolverá sin demora. Una open() para solo escritura devolverá un error si ningún proceso tiene actualmente el archivo abierto para lectura.
*
Si O_NONBLOCK está borrado, una open() para solo lectura bloqueará el hilo que llama hasta que un hilo abra el archivo para escritura. Una open() para solo escritura bloqueará el hilo que llama hasta que un hilo abra el archivo para lectura.

Al abrir un archivo especial de bloque o un archivo especial de carácter que admita aperturas no bloqueantes:

*
Si O_NONBLOCK está establecido, la función open() devolverá sin bloquear para que el dispositivo esté listo o disponible. El comportamiento subsiguiente del dispositivo es específico del dispositivo.
*
Si O_NONBLOCK está borrado, la función open() bloqueará el hilo que llama hasta que el dispositivo esté listo o disponible antes de devolver.

De lo contrario, la bandera O_NONBLOCK no provocará un error, pero no está definido si las banderas de estado del archivo incluirán la bandera O_NONBLOCK.

O_RSYNC
Las operaciones de E/S de lectura en el descriptor de archivo se completarán al mismo nivel de integridad que el especificado por las banderas O_DSYNC y O_SYNC. Si O_DSYNC y O_RSYNC están establecidos en oflag, todas las operaciones de E/S en el descriptor de archivo se completarán según lo definido por la finalización de integridad de datos de E/S sincronizada. Si O_SYNC y O_RSYNC están establecidos en flags, todas las operaciones de E/S en el descriptor de archivo se completarán según lo definido por la finalización de integridad de archivo de E/S sincronizada.
O_SYNC
Las operaciones de E/S de escritura en el descriptor de archivo se completarán según lo definido por la finalización de integridad de archivo de E/S sincronizada.

La bandera O_SYNC será compatible con archivos regulares, incluso si la opción de Entrada y Salida Sincronizadas no es compatible.

O_TRUNC
Si el archivo existe y es un archivo regular, y el archivo se abre correctamente O_RDWR o O_WRONLY, su longitud se truncará a 0, y el modo y el propietario permanecerán sin cambios. No tendrá ningún efecto en los archivos especiales FIFO ni en los archivos de dispositivos terminales. Su efecto en otros tipos de archivos depende de la implementación. El resultado de usar O_TRUNC sin O_RDWR ni O_WRONLY no está definido.
O_TTY_INIT
Si path identifica un dispositivo terminal que no sea un pseudoterminal, el dispositivo no está abierto actualmente en ningún proceso, y ya sea O_TTY_INIT está establecido en ofla

No se especifica si O_TTY_INIT tiene algún efecto si el dispositivo ya está abierto en algún proceso. Si path identifica el lado esclavo de un pseudo-terminal que aún no está abierto en ningún proceso, open() establecerá cualquier parámetro de terminal no estándar de la estructura termios a un estado que proporcione un comportamiento conforme, independientemente de si O_TTY_INIT está establecido. Si path no identifica un dispositivo de terminal, O_TTY_INIT se ignorará.

Si se establecen O_CREAT y O_DIRECTORY y el modo de acceso solicitado no es O_WRONLY ni O_RDWR, el resultado no está especificado.

Si se establece O_CREAT y el archivo no existía previamente, tras una finalización exitosa, open() marcará para actualización las marcas de tiempo del último acceso a datos, última modificación de datos y último cambio de estado del archivo, así como las marcas de tiempo de la última modificación de datos y último cambio de estado del directorio padre.

Si se establece O_TRUNC y el archivo existía previamente, tras una finalización exitosa, open() marcará para actualización las marcas de tiempo de la última modificación de datos y último cambio de estado del archivo.

Si se establecen las banderas O_SYNC y O_DSYNC, el efecto es como si solo se hubiera establecido la bandera O_SYNC.

Si path se refiere a un archivo STREAMS, oflag se puede construir a partir de O_NONBLOCK OR'ed con O_RDONLY, O_WRONLY u O_RDWR. Otros valores de bandera no son aplicables a los dispositivos STREAMS y no tendrán ningún efecto sobre ellos. El valor O_NONBLOCK afecta la operación de los controladores STREAMS y ciertas funciones aplicadas a descriptores de archivo asociados con archivos STREAMS. Para los controladores STREAMS, la implementación de O_NONBLOCK es específica del dispositivo.

La aplicación deberá asegurarse de especificar la bandera O_TTY_INIT en la primera apertura de un dispositivo de terminal desde el arranque del sistema o desde que el dispositivo fue cerrado por el proceso que lo tuvo abierto por última vez. La aplicación no necesita especificar la bandera O_TTY_INIT al abrir pseudo-terminales. Si path nombra el lado maestro de un dispositivo pseudo-terminal, no se especifica si open() bloquea el lado esclavo para que no pueda ser abierto. Las aplicaciones conformes deberán llamar a unlockpt() antes de abrir el lado esclavo.

El valor más grande que se puede representar correctamente en un objeto de tipo off_t se establecerá como el máximo de desplazamiento en la descripción del archivo abierto.

La función openat() será equivalente a la función open() excepto en el caso en que path especifique una ruta relativa. En este caso, el archivo a abrir se determinará en relación con el directorio asociado con el descriptor de archivo fd en lugar del directorio de trabajo actual. Si el modo de acceso de la descripción del archivo abierto asociado con el descriptor de archivo no es O_SEARCH, la función verificará si las búsquedas de directorio están permitidas utilizando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la verificación.

El parámetro oflag y el cuarto parámetro opcional corresponden exactamente a los parámetros de open().

Si a openat() se le pasa el valor especial AT_FDCWD en el parámetro fd, se utilizará el directorio de trabajo actual y el comportamiento será idéntico al de una llamada a open().

VALOR DE RETORNO

Tras una finalización exitosa, estas funciones abrirán el archivo y devolverán un entero no negativo que representa el descriptor de archivo. De lo contrario, estas funciones devolverán -1 y establecerán errno para indicar el error. Si se devuelve -1, no se crearán ni modificarán archivos.

ERRORES

Estas funciones fallarán si:

EACCES
Se deniega el permiso de búsqueda en un componente del prefijo de ruta, o el archivo existe y se deniegan los permisos especificados por oflag, o el archivo no existe y se deniega el permiso de escritura para el directorio padre del archivo a crear, o se especifica O_TRUNC y se deniega el permiso de escritura.
EEXIST
O_CREAT y O_EXCL están establecidos, y el archivo nombrado existe.
EINTR
Se capturó una señal durante open().
EINVAL
La implementación no admite E/S sincronizada para este archivo.
EIO
El argumento path nombra un archivo STREAMS y ocurrió una desconexión o error durante open().
EISDIR
El archivo nombrado es un directorio y oflag incluye O_WRONLY u O_RDWR, o incluye O_CREAT sin O_DIRECTORY.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path, o se especificó O_NOFOLLOW y el argumento path nombra un enlace simbólico.
EMFILE
Todos los descriptores de archivo disponibles para el proceso están abiertos actualmente.
ENAMETOOLONG

La longitud de un componente de un nombre de ruta es mayor que {NAME_MAX}.
ENFILE
El número máximo de archivos permitidos está actualmente abierto en el sistema.
ENOENT
O_CREAT no está establecido y un componente de path no nombra un archivo existente, o O_CREAT está establecido y un componente del prefijo de ruta de path no nombra un archivo existente, o path apunta a una cadena vacía.
ENOENT o ENOTDIR

O_CREAT está establecido, y el argumento path contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> al final. Si path sin los caracteres de <barra> al final nombrara un archivo existente, no ocurrirá un error [ENOENT].
ENOSR
El argumento path nombra un archivo basado en STREAMS y el sistema no puede asignar un STREAM.
ENOSPC
El directorio o sistema de archivos que contendría el nuevo archivo no puede ser expandido, el archivo no existe, y se especifica O_CREAT.
ENOTDIR
Un componente del prefijo de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio; o O_CREAT y O_EXCL no están especificados, el argumento path contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> al final, y el último componente del nombre de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio; o se especificó O_DIRECTORY y el argumento path se resuelve a un archivo que no es un directorio.
ENXIO
O_NONBLOCK está establecido, el archivo nombrado es una FIFO, O_WRONLY está establecido, y ningún proceso tiene el archivo abierto para lectura.
ENXIO
El archivo nombrado es un archivo especial de caracteres o de bloques, y el dispositivo asociado con este archivo especial no existe.
EOVERFLOW
El archivo nombrado es un archivo regular y el tamaño del archivo no se puede representar correctamente en un objeto de tipo off_t.
EROFS
El archivo nombrado reside en un sistema de archivos de solo lectura y O_WRONLY, O_RDWR, O_CREAT (si el archivo no existe) u O_TRUNC está establecido en el argumento oflag.

La función openat() fallará si:

EACCES
El modo de acceso de la descripción del archivo abierto asociado con fd no es O_SEARCH y los permisos del directorio subyacente a fd no permiten búsquedas de directorio.
EBADF
El argumento path no especifica una ruta absoluta y el argumento fd no es AT_FDCWD ni un descriptor de archivo válido abierto para lectura o búsqueda.
ENOTDIR
El argumento path no es una ruta absoluta y fd es un descriptor de archivo asociado con un archivo que no es un directorio.

Estas funciones pueden fallar si:

EAGAIN
El argumento path nombra el lado esclavo de un dispositivo pseudo-terminal que está bloqueado.
EINVAL
El valor del argumento oflag no es válido.
ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un nombre de ruta excede {PATH_MAX}, o la resolución de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.
ENOMEM
El argumento path nombra un archivo STREAMS y el sistema no puede asignar recursos.
EOPNOTSUPP
El argumento path nombra un socket.
ETXTBSY
El archivo es un archivo de procedimiento puro (texto compartido) que se está ejecutando y oflag es O_WRONLY u O_RDWR.

EJEMPLOS

Abrir un Archivo para Escritura por el Propietario

El siguiente ejemplo abre el archivo /tmp/file, ya sea creándolo (si no existe) o truncándolo si ya existe, y lo abre para escritura.

NAME

open - abrir un archivo o dispositivo

SYNOPSIS

#include <fcntl.h>

int open(const char *path, int oflag, ...);

DESCRIPTION

La llamada al sistema open() es la primera llamada de un programa para abrir un archivo o dispositivo. Determina los permisos de acceso para el archivo especificado por path y su estado, y devuelve un descriptor de archivo no negativo que se puede usar para acceder al archivo. El descriptor de archivo devuelto es el entero más pequeño disponible.

La llamada al sistema open() se puede usar para abrir un archivo para leer, escribir o ambos. Los indicadores en el argumento oflag controlan el tipo de acceso solicitado y las opciones de apertura.

El argumento oflag está compuesto por indicadores que se pueden combinar usando el operador OR bit a bit (|). Los indicadores que controlan el modo de acceso al archivo son:

O_RDONLY
Abrir para lectura solamente.
O_WRONLY
Abrir para escritura solamente.
O_RDWR
Abrir para lectura y escritura.

Solo se debe especificar uno de los indicadores de acceso al archivo. Si no se especifica ninguno, el comportamiento es indefinido.

Los siguientes indicadores se pueden combinar con los indicadores de acceso al archivo:

O_APPEND
Adjuntar al final del archivo. Cada operación de escritura escribe al final del archivo, independientemente de la posición del puntero de archivo.
O_CREAT
Si el archivo no existe, crear el archivo. El nuevo archivo se creará con los permisos especificados por el argumento mode. Si el archivo ya existe, esta bandera no tiene efecto.
O_DIRECTORY
Si path no es un directorio, se producirá un error. Esta bandera solo se puede usar con indicadores de solo lectura (O_RDONLY, O_RDWR). Cuando se usa con O_RDONLY, se abre el directorio para iterar sobre sus entradas.
O_EXCL
Si el archivo ya existe, y se especifica tanto O_CREAT como O_EXCL, la llamada al sistema fallará. Esta bandera se puede usar para detectar si un archivo ya existe antes de crearlo.
O_LARGEFILE
Permitir que el archivo se abra como un archivo grande. Esto permite que las operaciones de archivo superen los límites de tamaño de archivo de 32 bits. En los sistemas que admiten archivos grandes de forma nativa, esta bandera es redundante. Sin embargo, en sistemas que no admiten archivos grandes de forma nativa, esta bandera es necesaria para abrir archivos grandes.
O_NOCTTY
Si path hace referencia a un terminal, no se convertirá en el terminal de control del proceso que llama. Esto es útil para procesos daemon o similares que abren un terminal para E/S pero no quieren que se convierta en su terminal de control.
O_NOFOLLOW
Si path es un enlace simbólico, la llamada al sistema fallará. Esto evita que las aplicaciones abran archivos a los que apuntan enlaces simbólicos, lo que podría ser un riesgo de seguridad.
O_NONBLOCK
Abrir el archivo en modo no bloqueante. Si una llamada a read() o write() en el descriptor de archivo devuelto se bloquearía, la llamada retornará inmediatamente con un error [EAGAIN].
O_RANDOM
Indica que los accesos al archivo se realizarán de forma aleatoria. Esto puede permitir que el sistema operativo optimice el rendimiento del acceso al archivo. Esta bandera no se implementa universalmente.
O_SEARCH
Abrir el archivo para búsqueda. Esto permite verificar los permisos de ejecución en un directorio sin abrirlo para lectura o escritura. Solo se aplica a directorios.
O_SYNC
Mantener las características de sincronización de E/S. Las operaciones de escritura devuelven solo después de que se hayan transferido físicamente los datos físicos a los medios de almacenamiento subyacentes. Las operaciones de lectura y escritura garantizarán que los datos sean físicamente escritos en el medio antes de que la operación retorne. Se garantiza que todas las modificaciones a los metadatos del archivo que sean necesarias para dar soporte a la transferencia de contenido del archivo también se realicen físicamente en el almacenamiento subyacente.
O_TRUNC
Si el archivo ya existe y se abre para escritura, truncar el archivo a una longitud de 0 bytes. Si el archivo no existe, esta bandera no tiene efecto.
O_TTY_INIT
Cuando se abre un dispositivo de terminal (que no sea un pseudo-terminal), establezca los parámetros asociados con el terminal a un estado conforme. Esto se usa para garantizar que el dispositivo se establezca en un estado inicial conforme.
O_WRONLY
Abrir para escritura solamente.

Si se especifican los indicadores O_CREAT y O_TRUNC, y el archivo ya existe, se truncará su longitud a 0. En el primer caso, si la llamada crea un archivo nuevo, los bits de permiso de acceso en el modo de archivo del archivo se establecerán para permitir la lectura y escritura por parte del propietario, y para permitir la lectura solo por parte de los miembros del grupo y otros.

Si la llamada a open() es exitosa, el archivo se abre para escritura.

#include <fcntl.h>
...
int fd;
mode_t mode = S_IRUSR | S_IWUSR | S_IRGRP | S_IROTH;
char *pathname = "/tmp/file";
...
fd = open(pathname, O_WRONLY | O_CREAT | O_TRUNC, mode);
...

Abrir un archivo usando una verificación de existencia

El siguiente ejemplo utiliza la función open() para intentar crear el archivo LOCKFILE y abrirlo para escritura. Dado que la función open() especifica la bandera O_EXCL, la llamada falla si el archivo ya existe. En ese caso, el programa asume que alguien más está actualizando el archivo de contraseñas y sale.

#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#define LOCKFILE "/etc/ptmp"
...
int pfd; /* Entero para el descriptor de archivo devuelto por la llamada a open(). */
...
if ((pfd = open(LOCKFILE, O_WRONLY | O_CREAT | O_EXCL,
    S_IRUSR | S_IWUSR | S_IRGRP | S_IROTH)) == -1)
{
    fprintf(stderr, "No se puede abrir /etc/ptmp. Intente de nuevo más tarde.\n");
    exit(1);
}
...

Abrir un archivo para escritura

El siguiente ejemplo abre un archivo para escritura, creando el archivo si aún no existe. Si el archivo existe, el sistema trunca el archivo a cero bytes.

#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#define LOCKFILE "/etc/ptmp"
...
int pfd;
char pathname[PATH_MAX+1];
...
if ((pfd = open(pathname, O_WRONLY | O_CREAT | O_TRUNC,
    S_IRUSR | S_IWUSR | S_IRGRP | S_IROTH)) == -1)
{
    perror("No se puede abrir el archivo de salida\n"); exit(1);
}
...

USO DE LA APLICACIÓN

POSIX.1‐2008 no requiere que los parámetros del terminal se establezcan automáticamente en ningún estado en la primera apertura, ni que se restablezcan después del último cierre. Es posible que una aplicación no conforme deje un dispositivo de terminal en un estado en el que el siguiente proceso que utilice ese dispositivo lo encuentre en un estado no conforme, pero no tiene forma de determinarlo. Para garantizar que el dispositivo se establezca en un estado inicial conforme, las aplicaciones que realicen una primera apertura de un terminal (que no sea un pseudo-terminal) deben hacerlo utilizando la bandera O_TTY_INIT para establecer los parámetros asociados con el terminal a un estado conforme.

Excepto como se especifica en este volumen de POSIX.1‐2017, las banderas permitidas en oflag no son mutuamente excluyentes y se puede usar cualquier número de ellas simultáneamente. No todas las combinaciones de banderas tienen sentido. Por ejemplo, usar O_SEARCH | O_CREAT abrirá correctamente un directorio preexistente para búsqueda, pero si no existe un archivo con ese nombre, no se especifica si se creará un archivo regular. De manera similar, si se devuelve un descriptor de archivo que no es un directorio, no se especifica si ese descriptor tendrá permisos de ejecución como si fuera O_EXEC (tenga en cuenta que no se especifica si O_EXEC y O_SEARCH tienen el mismo valor).

FUNDAMENTO

Algunas implementaciones permiten abrir FIFOs con O_RDWR. Dado que los FIFOs podrían implementarse de otras maneras, y dado que se pueden usar dos descriptores de archivo para el mismo efecto, esta posibilidad se deja como no definida.

Consulte getgroups() sobre el grupo de un archivo recién creado.

El uso de open() para crear un archivo regular es preferible al uso de creat(), ya que este último es redundante y se incluye solo por razones históricas.

El uso de la bandera O_TRUNC en FIFOs y directorios (los pipes no se pueden abrir con open()) debe ser permisible sin efectos secundarios inesperados (por ejemplo, creat() en un FIFO no debe eliminar datos). Dado que los archivos especiales de terminal pueden tener datos en cola de tipo en el búfer, O_TRUNC no debe afectar su contenido, especialmente si un programa que normalmente abre un archivo regular debe abrir el terminal de control actual en su lugar. Otros tipos de archivo, particularmente los definidos por la implementación, se dejan definidos por la implementación.

POSIX.1‐2008 permite que [EACCES] se devuelva para condiciones distintas de las enumeradas explícitamente.

La bandera O_NOCTTY se agregó para permitir que las aplicaciones eviten adquirir inadvertidamente un terminal de control como efecto secundario de abrir un archivo de terminal. Este volumen de POSIX.1‐2017 no especifica cómo se adquiere un terminal de control, pero permite que una implementación proporcione esto en open() si la bandera O_NOCTTY no está establecida y se cumplen otras condiciones especificadas en el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 11, Interfaz General de Terminal.

En implementaciones históricas, el valor de O_RDONLY es cero. Debido a eso, no es posible detectar la presencia de O_RDONLY y otra opción. Las implementaciones futuras deberían codificar O_RDONLY y O_WRONLY como banderas de bits para que:

O_RDONLY | O_WRONLY == O_RDWR

O_EXEC y O_SEARCH se especifican como dos de los cinco modos de acceso a archivos. Dado que O_EXEC no se aplica a directorios, y O_SEARCH solo se aplica a directorios, sus valores no necesitan ser distintos. Dado que O_RDONLY históricamente ha tenido el valor cero, las implementaciones no pueden distinguir entre O_SEARCH y O_SEARCH | O_RDONLY, y de manera similar para O_EXEC.

En general, la función open() sigue el enlace simbólico si path apunta a un enlace simbólico. Sin embargo, la función open(), cuando se llama con O_CREAT y O_EXCL, debe fallar con [EEXIST] si path apunta a un enlace simbólico existente, incluso si el enlace simbólico se refiere a un archivo inexistente. Este comportamiento es necesario para que las aplicaciones privilegiadas puedan crear un nuevo archivo en una ubicación conocida sin la posibilidad de que un enlace simbólico cause la creación del archivo en una ubicación diferente.

Por ejemplo, una aplicación privilegiada que debe crear un archivo con un nombre predecible en un directorio que el usuario puede escribir, como el directorio principal del usuario, podría verse comprometida si el usuario crea un enlace simbólico con ese nombre que apunta a un archivo inexistente en un directorio del sistema. Si el usuario puede influir en el contenido de un archivo, el usuario podría comprometer el sistema creando un nuevo archivo de configuración del sistema o un archivo spool que luego sería interpretado por el sistema. La prueba de un enlace simbólico que apunta a un archivo inexistente debe ser atómica con la creación de un nuevo archivo.

Además, la función open() se niega a abrir directorios si se establece la bandera O_DIRECTORY. Esto evita condiciones de carrera en las que un usuario podría comprometer el sistema sustituyendo un enlace duro a un archivo sensible (por ejemplo, un dispositivo o un FIFO) mientras se ejecuta una aplicación privilegiada, donde abrir un archivo incluso para acceso de lectura podría tener efectos secundarios indeseables.

Además, la función open() no sigue los enlaces simbólicos si se establece la bandera O_NOFOLLOW. Esto evita condiciones de carrera en las que un usuario podría comprometer el sistema sustituyendo un enlace simbólico a un archivo sensible (por ejemplo, un dispositivo) mientras se ejecuta una aplicación privilegiada, donde abrir un archivo incluso para acceso de lectura podría tener efectos secundarios indeseables.

El estándar POSIX.1‐1990 requería que el ID de grupo de un archivo recién creado se estableciera en el ID de grupo de su directorio padre o en el ID de grupo efectivo del proceso que lo crea. FIPS 151‐2 requería que las implementaciones proporcionaran una forma de que el ID de grupo se estableciera en el ID de grupo del directorio que lo contiene, pero no prohibía que las implementaciones también admitieran una forma de establecer el ID de grupo en el ID de grupo efectivo del proceso que lo crea. Las aplicaciones conformes no deben asumir qué ID de grupo se utilizará. Si es importante, una aplicación puede usar chown() para establecer el ID de grupo después de que se crea el archivo, o determinar bajo qué condiciones la implementación establecerá el ID de grupo deseado.

El propósito de la función openat() es permitir abrir archivos en directorios distintos del directorio de trabajo actual sin riesgos de condiciones de carrera. Cualquier parte de la ruta de un archivo podría ser modificada en paralelo a una llamada a open(), lo que resultaría en un comportamiento indefinido. Al abrir un descriptor de archivo para el directorio de destino y utilizar la función openat(), se puede garantizar que el archivo abierto se encuentra relativo al directorio deseado. Algunas implementaciones utilizan la función openat() para otros fines también. En algunos casos, si el parámetro oflag tiene la bandera O_XATTR establecida, el descriptor de archivo devuelto proporciona acceso a atributos extendidos. Esta funcionalidad no está estandarizada aquí.

open (3p)

Open a file for reading or writing - Linux man page

PROLOG

This page is a Linux man page.

NAME

open - open and possibly create a file or special file

SYNOPSIS

#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>

int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);

DESCRIPTION

The open() function returns a new file descriptor for the specified pathname. The file descriptor is a non-negative integer that can be used in subsequent system calls (such as read(2), write(2), close(2), and fcntl(2)).

The value of the argument flags must be the inclusive OR of zero or more of the following access modes:

O_RDONLY
Open for reading only.
O_WRONLY
Open for writing only.
O_RDWR
Open for reading and writing.

The following access mode flags can be combined (inclusive OR) with one of the above three basic flags:

O_APPEND
Append mode. The file offset for the end of the file is found before each write(2) I/O operation, so that data is always appended to the end of the file. Portable applications should not use this option if the file belongs to a text file with shared mapping. If O_APPEND is set, the position of the file offset is not changed by the read(2) or write(2) calls.
O_CREAT
If the file does not exist, create it as a regular file. The owner ID of the created file is set to the effective user ID of the process. The group ID of the created file is set to the group ID of the parent directory. If the set-GID attribute is enabled on the parent directory, the group ID is inherited from the parent directory. The permissions of the created file are determined by the mode argument, which is bitwise-ORed with the process's umask(2) value. If the file exists, this flag has no effect, except as noted under O_EXCL.
O_DIRECT
Attempt to minimize the cache effects of the I/O subsystem. When a O_DIRECT flag is set, the validity of the data in the cache is not guaranteed. This may also affect the performance of I/O operations. Direct I/O is not supported for all file types. Applications which use this flag are likely to be non-portable.
O_DIRECTORY
If the name specified is not a directory, the call fails with the error ENOTDIR. This flag is used in conjunction with other flags like openat(2) to open directories themselves. If O_DIRECTORY is specified without O_RDONLY, O_WRONLY, or O_RDWR, the behavior is undefined.
O_DSYNC
Write I/O is to be completed synchronously. That is, for write I/O, the operation is complete when the physical write from the operating system has completed. This option is similar to O_SYNC, but it only affects write I/O. It has no effect on read I/O.
O_EXCL
This flag can only be used in conjunction with O_CREAT. If the file exists and O_CREAT is specified, open() fails and returns -1 with the error EEXIST, and the contents of the file modified. If the file does not exist, the file is created, set to exist, and opened. This behaviour is intended to be used to provide atomic file creation.
O_LARGEFILE
This flag is obsolete. On systems that support large files, this flag is ignored. Applications should use appropriate data types (e.g., off_t) to handle large files.
O_NOATIME
Do not update access times. This flag is intended to be used for devices that might be affected by access time updates. This behavior is useful for removable media, but it should not be used for general files. If the file is opened with O_NOATIME, the access time is not updated when the file is read.
O_NOCTTY
If pathname refers to a terminal device, open the terminal device for this process. Normally, if the terminal device is already associated with another process, open() will fail. However, if O_NOCTTY is specified, the call will succeed, but the terminal will not be associated with the calling process. This flag is intended to be used by daemons and other processes that should not be associated with a controlling terminal.
O_NONBLOCK
Open the file in non-blocking mode. If O_NONBLOCK is set, the open call returns immediately without blocking for the I/O device to become ready. If the file is a FIFO or a block special device, this flag causes the open call to return without blocking for the device to be ready or available. If the file is a character special device, then the call returns without blocking for the device to be ready or available.
O_RSYNC
Synchronize read I/O. This flag is intended to be used for devices that might be affected by read I/O. This behavior is useful for removable media, but it should not be used for general files.
O_SYNC
Synchronize entire I/O. Write I/O is to be completed synchronously. That is, for write I/O, the operation is complete when the physical write from the operating system has completed. This option is similar to O_DSYNC, but it affects both read and write I/O.
O_TRUNC
If the file exists and has been opened successfully, truncate it to zero length. The file is then opened for writing according to the flags specified. The permissions of the file are not changed. If O_TRUNC is specified without O_WRONLY or O_RDWR, the behavior is undefined.
O_CLOEXEC
Enable the close-on-exec flag for the new file descriptor. See fcntl(2) for more information.

If the file specified by pathname does not exist, and O_CREAT is not specified, then open() fails and returns -1 with the error ENOENT.

If pathname is a symbolic link, it is interpreted unless O_NOFOLLOW is specified (but not used). This behavior is described in the following paragraph.

If pathname is not a directory, and the O_DIRECTORY flag is specified, the call fails with the error ENOTDIR.

If pathname is a symbolic link, and the O_NOFOLLOW flag is specified, the call fails with the error ELOOP.

If pathname refers to a directory, the result of the open call depends on the flags specified:

  • If O_RDWR, O_WRONLY, or O_RDONLY is specified, the call succeeds and returns a file descriptor which refers to the directory. This file descriptor can be used for operations such as fcntl(2) and fstat(2), but not for read and write operations.

  • If O_TRUNC is specified along with O_RDWR or O_WRONLY, the call fails with the error EISDIR. The file is not truncated.

If pathname refers to a device, the behavior depends on the device. For example, opening a terminal device, or a character special file.

The mode argument specifies the permissions to be set for a newly created file. It is bitwise-ORed with the process's umask(2) value to determine the actual permissions of the file. The mode argument is only used if the O_CREAT flag is specified. Otherwise, it is ignored.

The permissions are interpreted as follows:

S_IRUSR
Read permission for owner.
S_IWUSR
Write permission for owner.
S_IXUSR
Execute permission for owner.
S_IRGRP
Read permission for group.
S_IWGRP
Write permission for group.
S_IXGRP
Execute permission for group.
S_IROTH
Read permission for others.
S_IWOTH
Write permission for others.
S_IXOTH
Execute permission for others.

The file descriptor returned by a successful call to open() is the lowest numbered file descriptor not currently open by the process. The close-on-exec flag associated with the new file descriptor is set according to the O_CLOEXEC flag. If O_CLOEXEC is specified, the file descriptor will be closed when a new program is executed by this process. Otherwise, the file descriptor will remain open across calls to execve(2).

RETURN VALUE

On success, open() returns a non-negative integer representing the lowest-numbered file descriptor available. On failure, open() returns -1, and errno is set to indicate the error.

ERRORS

EACCES
Search permission is denied for a component of the required pathname, or the required permissions (for reading and/or writing) are denied. Or O_CREAT and O_EXCL are specified, and the file has mandatory locking set, and is already locked.
EBADF
The flags argument includes O_TMPFILE but the effective user ID of the process is not 0, and the file system does not allow unprivileged users to create temporary files.
EBUSY
The file specified by pathname is a device, and it is busy.
ECHILD
A thread called open() with the O_CLOEXEC flag set, but the calling thread is not the thread that created the file descriptor.
EDEADLK
The file has mandatory locking set, and the calling process would cause a deadlock.
EEXIST
The file exists and O_CREAT and O_EXCL were specified. Or the file system does not support the O_TMPFILE flag.
EFBIG
The file is a regular file, and pathname is too large to be opened.
EINTR
The call was interrupted by a signal.
EINVAL
The flags argument is invalid (e.g., it contains undefined bits, or it specifies both O_WRONLY and O_RDWR).
EISDIR
The name specified is a directory and the O_TRUNC flag was specified.
ELOOP
Too many symbolic links encountered while processing pathname. Or O_NOFOLLOW was specified and pathname was a symbolic link.
EMFILE
The process has reached its limit of open file descriptors.
EMLINK
The file specified by pathname has too many links.
ENAMETOOLONG
The length of pathname exceeds PATH_MAX, or a pathname component exceeds NAME_MAX.
ENODEV
The file specified by pathname does not exist on the current file system, or the file system does not support the requested flags.
ENOENT
The file does not exist and O_CREAT was not specified. Or O_TMPFILE was specified, and the directory specified by pathname does not exist.
ENOMEM
Not enough kernel memory was available.
ENOSPC
The file system is out of disk space.
ENOTDIR
A component of the required pathname was not a directory. Or O_DIRECTORY was specified, and pathname was not a directory.
ENXIO
The file is a device special file and no corresponding device existed.
EOVERFLOW
The file is a regular file or the O_NOATIME flag is specified, and the file is too large to be opened.
EROFS
The file resides on a read-only file system and write access was requested.
ESPIPE
The file specified by pathname is a pipe or FIFO, and the specified flags are invalid for a pipe or FIFO.
ETXTBSY
The file is a regular file that is being executed from memory, so opening it for writing is forbidden.
EXDEV
The file resides on a different file system than the specified pathname.
UNKNOWN_ERR
An unknown error occurred.

EXAMPLES

Create a file named mktemp.tmp, open it for reading and writing, and set its permissions to read and write for the owner, and read for group and others:

int fd;
mode_t mode = S_IRUSR | S_IWUSR | S_IRGRP | S_IROTH;

fd = open("mktemp.tmp", O_CREAT | O_RDWR, mode);
if (fd == -1) {
    perror("open");
    exit(EXIT_FAILURE);
}

/* ... use the file descriptor fd ... */

if (close(fd) == -1) {
    perror("close");
    exit(EXIT_FAILURE);
}

Open an existing file for reading:

int fd;

fd = open("existing_file.txt", O_RDONLY);
if (fd == -1) {
    perror("open");
    exit(EXIT_FAILURE);
}

/* ... read from fd ... */

if (close(fd) == -1) {
    perror("close");
    exit(EXIT_FAILURE);
}

Open an existing file for writing, truncating it first:

int fd;

fd = open("existing_file.txt", O_WRONLY | O_TRUNC);
if (fd == -1) {
    perror("open");
    exit(EXIT_FAILURE);
}

/* ... write to fd ... */

if (close(fd) == -1) {
    perror("close");
    exit(EXIT_FAILURE);
}

APPLICATION USAGE

When using O_CREAT, the mode argument is crucial for setting the correct permissions on the newly created file. It is important to consider the process's umask setting when specifying the mode.

The O_EXCL flag, when combined with O_CREAT, is useful for safely creating files that should not already exist. This is often used for creating lock files or temporary files.

Non-blocking I/O with O_NONBLOCK should be used carefully, as it requires special handling to manage situations where I/O operations might block.

RATIONALE

The open() function is a fundamental system call for file manipulation. It provides a flexible interface for opening files with various access modes and creation options. The different flags allow applications to control how files are accessed, created, and modified, including aspects like buffering, appending, and synchronization.

The POSIX standard defines the behavior of open() and its flags to ensure portability across different Unix-like systems. The Linux implementation adheres to these standards while also providing some extensions.

The separation of access modes (read, write, read-write) and other flags (create, append, truncate, etc.) allows for a clear and powerful way to specify file open operations.

The inclusion of the mode argument when creating files is essential for security and proper file management, allowing users to specify initial permissions while respecting the system-wide umask.

FUTURE DIRECTIONS

Future developments in file systems and operating systems may introduce new flags or modify the behavior of existing ones. For example, new flags related to resource management, asynchronous I/O, or advanced file system features might be added.

The trend towards more fine-grained control over file operations may lead to new flags for managing file attributes, such as extended attributes, file locking modes, or specific I/O scheduling behaviors.

As operating systems evolve, the interaction between flags like O_DIRECT, O_SYNC, and cache management strategies might be further optimized or changed to adapt to new hardware and software paradigms.
