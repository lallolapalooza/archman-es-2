NOMBRE

openipmi_cmdparms - Parámetros de conexión para OpenIPMI

SINOPSIS

smi smi-num

lan [-U nombre_usuario] [-P contraseña] [-p[2] puerto] [-A tipo_autenticación] [-L privilegio] [-s] [-Ra alg_aut] [-Ri alg_int] [-Rc alg_conf] [-Rl] [-Rk clave_bmc] [-H nombre_hack] host [ host]

DESCRIPCIÓN

Los parámetros de conexión para OpenIPMI varían dependiendo del tipo de conexión. Este documento describe los tipos de conexión estándar; otros pueden estar disponibles de los OEM.

OPCIONES

smi-num
La interfaz SMI para la conexión local. Puede haber más de una conexión BMC en un sistema y generalmente se numeran, como /dev/ipmi0, /dev/ipmi1, etc.
-U nombre_usuario
Usa el nombre_usuario dado para la conexión LAN. Si no se proporciona ninguno, entonces no se usa nombre de usuario.
-P contraseña
La contraseña a usar para la conexión. Si no se proporciona ninguna, se asume que el usuario tiene una contraseña vacía.
-p[2] puerto
El puerto UCP al que conectarse. Por defecto es el puerto estándar 623, por lo que no es necesario a menos que se requiera un puerto especial. Tenga en cuenta que como puede tener dos conexiones (hosts), -p es para el primer host y -p2 es para el segundo host.
-A tipo_autenticación
El tipo de autenticación a usar, uno de rmcp+, md5, md2, straight, o none. Si no se proporciona esto, se elige el más seguro disponible, en el orden dado en la lista anterior.
-L privilegio
El privilegio a usar para la conexión. Los privilegios inferiores no pueden ejecutar algunos comandos. Los privilegios son: callback, user, operator, admin, y oem. El valor por defecto es admin.
-Ra algoritmo_autenticación
Establece el algoritmo de autenticación RMCP+ a usar. Las opciones son: bmcpick, rakp_none, rakp_hmac_sha1, y rakp_hmac_md5. La opción bmcpick se usa por defecto, lo que significa que el BMC elige el algoritmo que desea usar.
-Ri algoritmo_integridad
El algoritmo de integridad RMCP+ a usar. Esto asegura que los datos no han sido alterados entre el remitente y el receptor. Las opciones válidas son: bmcpick, none, hmac_sha1, hmac_md5, y md5. La opción bmcpick se usa por defecto, lo que significa que el BMC elige el algoritmo que desea usar.
-Rc algoritmo_confidencialidad
El algoritmo de confidencialidad (cifrado) RMCP+ a usar. Esto evita que los fisgones vean los datos. Los valores válidos son: bmcpick, aes_cbc_128, xrc4_128, y xrc_40. La opción bmcpick se usa por defecto, lo que significa que el BMC elige el algoritmo que desea usar.
-Rl
Si se especifica esto, el nombre de usuario se busca utilizando el nivel de privilegio junto con el nombre de usuario. Esto permite que el mismo nombre tenga contraseñas diferentes con diferentes niveles de privilegio.
-Rk Clave_BMC
Si el sistema requiere búsquedas de dos claves, esto especifica la segunda clave (la clave BMC) a usar. Esto se ignora si las búsquedas de dos claves no están habilitadas por el BMC.
-H nombre_hack
Bueno, siempre sucede. Las cosas en el campo no funcionan exactamente como se supone que deben. Hubo cierta vaguedad en las primeras especificaciones de IPMI y diferentes proveedores interpretaron RMCP+ de diferentes maneras. Esto permite que se soporten diferentes opciones. Pruebe diferentes hacks si sus sistemas RMCP+ no se autentican correctamente. Estos son:
rakp3_wrong_rolem
Algunos sistemas usan el campo incorrecto Role(m) en un mensaje de autenticación específico (el mensaje RAKP3). Este es un problema común.
rmcpp_integ_sik
La especificación original de IPMI 2.0 especificó la clave incorrecta a usar para la clave de integridad. Esto fuerza el uso de la Clave de Inicio de Sesión. El valor por defecto es usar K(1)
-s
Realiza dos conexiones al BMC. Esto significa que el BMC tiene dos direcciones IP/puertos diferentes que son equivalentes. Si se especifica esto, se debe proporcionar un segundo host. Esto no es lo mismo que dos conexiones a dos BMC diferentes. Debe ser una conexión al mismo BMC.
host
La dirección IP (ya sea por búsqueda de nombre o especificada directamente) a la que conectarse. Si se especifica -s, se deben proporcionar dos hosts.

Las opciones -Ra, -Ri, -Rc, -Rk y -Rl solo se aplican a las conexiones RMCP+ y se ignorarán si la conexión no soporta RMCP+ o si se especifica un tipo de autenticación que no sea RMCP+.
