omshell(1) Manual de comandos generales omshell(1)

NOMBRE

omshell - Shell de comandos OMAPI

SINOPSIS

omshell

DESCRIPCIÓN

La Shell de comandos OMAPI, omshell, proporciona una forma interactiva de conectarse, consultar y posiblemente cambiar, el estado del servidor DHCP de ISC a través de OMAPI, la API de gestión de objetos. Al usar OMAPI y omshell, no tiene que detener, realizar cambios y luego reiniciar el servidor DHCP, sino que puede realizar los cambios mientras el servidor está en ejecución. Omshell proporciona una forma de acceder a OMAPI.

OMAPI es simplemente un mecanismo de comunicación que le permite manipular objetos. Para *usar* realmente omshell, *debe* comprender qué objetos están disponibles y cómo usarlos. La documentación sobre los objetos OMAPI se puede encontrar en la documentación del servidor que los proporciona, por ejemplo, en la página del manual dhcpd(1) y la página del manual dhclient(1).

OBJETOS LOCALES Y REMOTOS

A lo largo de este documento, hay referencias a objetos locales y remotos. Los objetos locales son los creados en omshell con el comando new. Los objetos remotos son los del servidor: concesiones, hosts y grupos que el servidor DHCP conoce. Los objetos locales y remotos se asocian entre sí para permitir la visualización y modificación de los atributos de los objetos. Además, se pueden crear nuevos objetos remotos para que coincidan con los objetos locales.

ABRIENDO UNA CONEXIÓN

omshell se inicia desde la línea de comandos. Una vez iniciado omshell, hay varios comandos que se pueden emitir:

server dirección

donde dirección es la dirección IP del servidor DHCP al que conectarse. Si no se especifica, el servidor predeterminado es 127.0.0.1 (localhost).

port número

donde número es el puerto en el que OMAPI escucha. Por predeterminado, este es 7911.

key nombre secreto

Esto especifica la clave TSIG a utilizar para autenticar las transacciones OMAPI. nombre es el nombre de una clave definida en dhcpd.conf con la declaración omapi-key. El secreto es la clave secreta generada a partir de dnssec-keygen u otro programa de generación de claves. Se asume que el algoritmo de clave es HMAC-MD5. Si se especificó un algoritmo diferente en el archivo dhcpd.conf para la clave, entonces debe especificarse a través de la declaración key-algorithm.

key-algorithm algoritmo

Esto especifica el algoritmo criptográfico para la clave utilizada al autenticar las transacciones OMAPI. Los valores compatibles para algoritmo son: 
        HMAC-MD5
        HMAC-SHA1
        HMAC-SHA224
        HMAC-SHA256
        HMAC-SHA384
        HMAC-SHA512
El valor predeterminado es HMAC-MD5. (El valor no distingue entre mayúsculas y minúsculas).

connect

Esto inicia la conexión OMAPI al servidor según lo especificado por la declaración server.

CREANDO OBJETOS LOCALES

Cualquier objeto definido en OMAPI puede ser creado, consultado y/o modificado. Los tipos de objetos disponibles para OMAPI se definen en dhcpd(8) y dhclient(8). Al usar omshell, los objetos se definen primero localmente, se manipulan según se desee y luego se asocian con un objeto en el servidor. Solo se puede manipular un objeto a la vez. Para crear un objeto local, use

new tipo-objeto

tipo-objeto es uno de group, host o lease.

En este punto, ahora tiene un objeto en el que puede establecer propiedades. Por ejemplo, si se creó un nuevo objeto de concesión con new lease, cualquiera de los atributos de una concesión se puede establecer de la siguiente manera:

set nombre-atributo = valor

Los nombres de atributo se definen en dhcpd(8) y dhclient(8). Los valores deben entrecomillarse si son cadenas. Por lo tanto, para establecer la dirección IP de una concesión, haría lo siguiente: set ip-address = 192.168.4.50

ASOCIANDO OBJETOS LOCALES Y REMOTOS

En este punto, puede consultar al servidor información sobre esta concesión, mediante

open

Ahora, el objeto de concesión local que creó y para el cual estableció la dirección IP está asociado con el objeto de concesión correspondiente en el servidor DHCP. Todos los atributos de concesión del servidor DHCP son ahora también los atributos del objeto local, y se mostrarán en omshell.

VIENDO UN OBJETO REMOTO

Para consultar una concesión de la dirección 192.168.4.50 y averiguar sus atributos, después de conectarse al servidor, siga estos pasos:

new lease

Esto crea un nuevo objeto de concesión local.

set ip-address = 192.168.4.50

Esto establece la dirección IP del objeto *local* en 192.168.4.50

open

Ahora, si existe una concesión con esa dirección IP, verá toda la información que el servidor DHCP tiene sobre esa concesión en particular. Cualquier dato que no sea texto fácilmente legible aparecerá en valores hexadecimales separados por dos puntos. En este ejemplo, la salida de vuelta del servidor para toda la transacción podría verse así:

> new "lease"
obj: lease
> set ip-address = 192.168.4.50
obj: lease
ip-address = c0:a8:04:32
> open
obj: lease
ip-address = c0:a8:04:32
state = 00:00:00:02
dhcp-client-identifier = 01:00:10:a4:b2:36:2c
client-hostname = "wendelina"
subnet = 00:00:00:06
pool = 00:00:00:07
hardware-address = 00:10:a4:b2:36:2c
hardware-type = 00:00:00:01
ends = dc:d9:0d:3b
starts = 5c:9f:04:3b
tstp = 00:00:00:00
tsfp = 00:00:00:00
cltt = 00:00:00:00

Como puede ver aquí, la dirección IP se representa en hexadecimal, al igual que las horas de inicio y fin de la concesión.

MODIFICANDO UN OBJETO REMOTO

Los atributos de los objetos remotos se actualizan usando el comando set como antes, y luego emitiendo un comando update. El comando set establece los atributos en el objeto local actual, y el comando update envía esos cambios al servidor.

Continuando con el ejemplo anterior, si se emitiera un comando set client-hostname = "something-else", seguido de un comando update, la salida se vería aproximadamente así:

> set client-hostname = "something-else"
obj: lease

hardware-type = 00:00:00:01
ends = dc:d9:0d:3b
starts = 5c:9f:04:3b
tstp = 00:00:00:00
tsfp = 00:00:00:00
cltt = 00:00:00:00
> update
obj: lease
ip-address = c0:a8:04:32
state = 00:00:00:02
dhcp-client-identifier = 01:00:10:a4:b2:36:2c

NUEVOS OBJETOS REMOTOS

Los nuevos objetos remotos se crean de manera muy similar a como se modifican los objetos de servidor existentes. Cree un objeto local usando new, establezca los atributos como desee y luego cree el objeto remoto con las mismas propiedades utilizando

create

Ahora existe un nuevo objeto en el servidor DHCP que coincide con las propiedades que le dio a su objeto local. Los objetos creados a través de OMAPI se guardan en el archivo dhcpd.le

NAME

omshell - OMAPI command-line interpreter

SYNOPSIS

omshell [-d] [-v] [-p port] [-s server]

DESCRIPTION

The Internet Systems Consortium DHCP server (DHCPD) provides a protocol known as OMAPI (OMNI API) which allows remote administration of the DHCP server's internal state. This state includes the server's internal configuration, such as the definition of hosts and networks, and also the dynamic state of the server, such as the current set of leases.

OMAPI is implemented as a simple object-oriented protocol. All objects have a type and a set of attributes. For example, a host object might have attributes such as name, hardware address, and IP address.

OMAPI is typically used by the DHCP failover protocol, but it can also be used for direct administration. The omshell program is a simple OMAPI client which allows an administrator to interact with the DHCP server using the OMAPI protocol.

The omshell program presents the user with a command prompt, where they can type OMAPI commands. These commands are sent to the DHCP server, which performs the requested action and returns a response.

The omshell program can connect to the DHCP server either directly, using TCP/IP, or via a local Unix domain socket, depending on how the DHCP server is configured.

The OMAPI protocol is documented in the omapi(5) manual page.

Command line arguments are:

-d
Enable debugging output.
-v
Enable verbose output.
-p port
The port number to connect to. The default is port 7. Note that this is only used when connecting via TCP/IP. The OMAPI port is specified in dhcpd.conf(5) using the omapi-port statement.
-s server
The name or IP address of the server to connect to. The default is localhost. Note that this is only used when connecting via TCP/IP.

CONTRIBUTIONS

The omshell program currently only supports the following object types:

  • host
group
subnet
class
pool
    For a complete description of these objects, please see the dhcpd.conf(5) manual page.

LOCAL AND REMOTE OBJECTS

There are two kinds of objects in OMAPI: local and remote. Local objects are objects that exist only within the omshell program. Remote objects are objects that exist on the DHCP server. You can examine and modify remote objects using OMAPI.

When you use the new command, you create a local object. When you use the open command, you associate a local object with a remote object.

OPENING A CONNECTION

To do anything with the DHCP server, you must first open a connection to it. This is done using the connect command:

> connect
Connected to 127.0.0.1 port 7.
>

If the connection fails, you will see an error message. If it succeeds, you will see the command prompt again.

If the DHCP server is configured to listen on a Unix domain socket instead of a TCP port, you can connect to it using the connect command followed by the name of the socket file:

> connect /var/run/dhcpd.sock
Connected via /var/run/dhcpd.sock
>

CREATING LOCAL OBJECTS

You can create a new local object using the new command. For example, to create a new host object:

> new host
obj: host
>

The obj: prompt indicates that you are now working with a local host object. You can set attributes of this object using the set command.

ASSOCIATING LOCAL AND REMOTE OBJECTS

Once you have created a local object, you can associate it with a remote object by using the open command. You must specify the name of the remote object you wish to open. For example, to open a host object named "some-host":

> open host some-host
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
>

If the host object does not exist on the server, you will get an error message. Once an object is open, you can modify its attributes.

VIEWING A REMOTE OBJECT

You can view a remote object by using the lookup command. This command takes the object type and the object name as arguments.

> lookup host some-host
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
>

This command is equivalent to creating a local object and then opening it.

MODIFYING A REMOTE OBJECT

To modify a remote object, first open it, then use the set command to change the desired attributes. After changing the attributes, you must use the update command to send the changes to the DHCP server.

obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
> set ip-address = 192.168.4.50
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:32
> update
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:32
>

If you try to update an object without opening it first, you will get an error.

NEW REMOTE OBJECTS

You can create new remote objects using the create command. This command takes the object type as an argument. You must first create a local object, set its attributes, and then use the create command to create the remote object.

For example, to create a new host with the IP address of 192.168.4.40 it would be done as follows:

> new host
obj: host
> set name = "some-host"
obj: host
name = "some-host"
> set hardware-address = 00:80:c7:84:b1:94
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
> set hardware-type = 1
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 1
> set ip-address = 192.168.4.40
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 1
ip-address = c0:a8:04:28
> create
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
>

Your dhcpd.leases file would then have an entry like this in it:

host some-host {
  dynamic;
  hardware ethernet 00:80:c7:84:b1:94;
  fixed-address 192.168.4.40;
}

The dynamic; line is to denote that this host entry did not come from dhcpd.conf, but was created dynamically via OMAPI.

RESETTING ATTRIBUTES

If you want to remove an attribute from an object, you can do this with the unset command. Once you have unset an attribute, you must use the update command to update the remote object. So, if the host "some-host" from the previous example will not have a static IP address anymore, the commands in omshell would look like this:

obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
> unset ip-address
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = <null>
>

REFRESHING OBJECTS

A local object may be refreshed with the current remote object properties using the refresh command. This is useful for object that change periodically, like leases, to see if they have been updated. This isn't particularly useful for hosts.

DELETING OBJECTS

Any remote object that can be created can also be destroyed. This is done by creating a new local object, setting attributes, associating the local and remote object using open, and then using the remove command. If the host "some-host" from before was created in error, this could be corrected as follows:

obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
> remove
obj: <null>
>

HELP

The help command will print out all of the commands available in omshell, with some syntax pointers.
