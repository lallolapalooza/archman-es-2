Nombre

org.bluez.AdvertisementMonitor - Documentación de la API AdvertisementMonitor de BlueZ D-Bus

Descripción

Esta API permite a un cliente especificar un trabajo de monitoreo de anuncios registrando la raíz de la jerarquía y luego exponiendo monitores de anuncios bajo la raíz con condiciones de filtrado, umbrales de RSSI y temporizadores de umbrales de RSSI.

Una vez que un trabajo de monitoreo es activado por bluetoothd(8), el cliente puede esperar ser notificado sobre los anuncios dirigidos, sin importar si hay una sesión de descubrimiento en curso (ver StartDiscovery() en org.bluez.Adapter(5)).

Métodos

void Release() [noreply]

Se llama como una señal para que el cliente realice la limpieza cuando:

  • El monitor no se puede activar después de haber sido expuesto.
  • El monitor ha sido desactivado.

void Activate() [noreply]

Después de que un monitor ha sido expuesto, se llama como una señal para que el cliente acuse recibo cuando un monitor ha sido activado, de modo que el cliente pueda esperar recibir llamadas en DeviceFound() o DeviceLost().

void DeviceFound(object device) [noreply]

Se llama para notificar al cliente que ha encontrado el dispositivo dirigido.

Una vez recibida la llamada, el cliente debe comenzar a monitorear el dispositivo correspondiente para recuperar los cambios en el RSSI y el contenido del anuncio.

void DeviceLost(object device) [noreply]

Se llama para notificar al cliente que ha perdido el dispositivo dirigido.

Una vez recibida esta llamada, el cliente debe dejar de monitorear el dispositivo correspondiente.

Propiedades

string Type [solo lectura]

El tipo de monitor. Ver SupportedMonitorTypes en org.bluez.AdvertisementMonitorManager(5) para las opciones disponibles.

int16 RSSILowThreshold [solo lectura, opcional]

Se utiliza junto con RSSILowTimeout para determinar si un dispositivo queda fuera de rango.

El rango válido es de -127 a 20 (dBm), mientras que 127 indica que no está establecido.

int16 RSSIHighThreshold [solo lectura, opcional]

Se utiliza junto con RSSIHighTimeout para determinar si un dispositivo entra en rango.

El rango válido es de -127 a 20 (dBm), mientras que 127 indica que no está establecido.

uint16 RSSILowTimeout [solo lectura, opcional]

El tiempo que se tarda en considerar un dispositivo como fuera de rango. Si transcurren esta cantidad de segundos sin recibir ninguna señal al menos tan fuerte como RSSILowThreshold, un dispositivo actualmente dentro del rango se considerará fuera de rango (perdido). El rango válido es de 1 a 300 (segundos), mientras que 0 indica que no está establecido.

uint16 RSSIHighTimeout [solo lectura, opcional]

El tiempo que se tarda en considerar un dispositivo como dentro de rango. Si transcurren esta cantidad de segundos mientras recibimos continuamente señales al menos tan fuertes como RSSIHighThreshold, un dispositivo actualmente fuera de rango se considerará dentro de rango (encontrado).

El rango válido es de 1 a 300 (segundos), mientras que 0 indica que no está establecido.

uint16 RSSISamplingPeriod [solo lectura, opcional]

Reglas de agrupación sobre cómo propagar los paquetes de anuncios recibidos al cliente.

Valores posibles:

0
Se propagarán todos los paquetes de anuncios de dispositivos dentro del rango.
255
Solo se propagará el primer paquete de anuncio de los dispositivos dentro del rango. Si el dispositivo se pierde, el primer paquete cuando se encuentre de nuevo también se propagará.
1 a 254
Los paquetes de anuncios se agruparán en un período de tiempo de 100 ms * N. Los paquetes del mismo grupo solo se informarán una vez, y el valor RSSI se promediará.

Actualmente, esto no está implementado en el espacio de usuario, por lo que el valor solo se utiliza para ser reenviado al kernel.

array{(uint8, uint8, array{byte})} Patterns [solo lectura, opcional]

Si la propiedad Type se establece en "or_patterns", entonces esta propiedad debe existir y tener al menos una entrada en la matriz.

La estructura de un patrón contiene lo siguiente:

uint8 start_position
El índice en un campo de datos AD donde debe comenzar la búsqueda. El principio de un campo de datos AD es el índice 0.
uint8 AD_data_type
Ver https://www.bluetooth.com/specifications/assigned-numbers/ perfil genérico de acceso/ para el valor permitido.
array{byte} content_of_pattern
Este es el valor del patrón. La longitud máxima de los bytes es 31.
