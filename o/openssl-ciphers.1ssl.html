openssl-ciphers(1ssl)

Paquete: openssl

Licencias: Apache-2.0

OPENSSL-CIPHERS(1ssl) OpenSSL OPENSSL-CIPHERS(1ssl)

NOMBRE

openssl-ciphers - visualización de cifrados SSL y comando de lista de cifrados

SINOPSIS

openssl ciphers [-help] [-s] [-v] [-V] [-ssl3] [-tls1] [-tls1_1] [-tls1_2] [-tls1_3] [-psk] [-srp] [-stdname] [-convert nombre] [-ciphersuites valor] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq] [lista_cifrados]

DESCRIPCIÓN

Este comando convierte listas de cifrados OpenSSL textuales en listas de preferencia de cifrado SSL ordenadas. Se puede usar para determinar la lista de cifrados apropiada.

OPCIONES

-help
Imprime un mensaje de uso.
-provider nombre
-provider-path ruta
-provparam [nombre:]clave=valor
-propquery propq
Ver "Opciones del proveedor" en openssl(1), provider(7) y property(7).
-s
Solo lista los cifrados soportados: aquellos consistentes con el nivel de seguridad y la versión mínima y máxima del protocolo. Esto se acerca más a la lista de cifrados real que una aplicación soportará.

Los cifrados PSK y SRP no están habilitados por defecto: requieren -psk o -srp para habilitarlos.

Tampoco cambia la lista predeterminada de algoritmos de firma soportados.

En un servidor, la lista de cifrados soportados también podría excluir otros cifrados dependiendo de los certificados configurados y la presencia de parámetros DH.

Si esta opción no se usa, se listarán todos los cifrados que coincidan con la lista de cifrados.

-psk
Cuando se combina con -s, incluye suites de cifrado que requieren PSK.
-srp
Cuando se combina con -s, incluye suites de cifrado que requieren SRP. Esta opción está obsoleta.
-v
Salida detallada: Para cada suite de cifrado, lista detalles como los proporcionados por SSL_CIPHER_description(3).
-V
Al igual que -v, pero incluye los valores oficiales de la suite de cifrado en hexadecimal.
-tls1_3, -tls1_2, -tls1_1, -tls1, -ssl3
En combinación con la opción -s, lista los cifrados que podrían usarse si se negociara el protocolo especificado. Tenga en cuenta que no todos los protocolos y banderas pueden estar disponibles, dependiendo de cómo se compiló OpenSSL.
-stdname
Anteponer a cada suite de cifrado su nombre estándar.
-convert nombre
Convierte un nombre de cifrado estándar a su nombre OpenSSL.
-ciphersuites valor
Establece la lista de suites de cifrado TLSv1.3. Esta lista se combinará con cualquier suite de cifrado TLSv1.2 e inferior que se haya configurado. El formato para esta lista es una lista simple de nombres de suites de cifrado TLSv1.3 separados por dos puntos (":"). Por defecto, este valor es: 
TLS_AES_256_GCM_SHA384:TLS_CHACHA20_POLY1305_SHA256:TLS_AES_128_GCM_SHA256
lista_cifrados
Una lista de cifrados TLSv1.2 e inferiores para convertir en una lista de preferencias de cifrado. Esta lista se combinará con cualquier suite de cifrado TLSv1.3 que se haya configurado. Si no se incluye, se utilizará la lista de cifrados predeterminada. El formato se describe a continuación.

FORMATO LISTA CIFRADOS

La lista de cifrados consta de uno o más strings de cifrado separados por dos puntos. Las comas o los espacios también son separadores aceptables, pero normalmente se usan los dos puntos.

El string de cifrado puede hacer referencia a un cifrado utilizando su nombre estándar del Registro de Suites de Cifrado TLS de IANA (https://www.iana.org/assignments/tls-parameters/tls-parameters.xhtml#tls-parameters-4).

El string de cifrado real puede adoptar varias formas diferentes.

Puede consistir en una única suite de cifrado, como RC4-SHA.

Puede representar una lista de suites de cifrado que contienen un cierto algoritmo, o suites de cifrado de un cierto tipo. Por ejemplo, SHA1 representa todas las suites de cifrado que utilizan el algoritmo de hash SHA1 y SSLv3 representa todos los algoritmos de SSL v3.

Las listas de suites de cifrado se pueden combinar en un único string de cifrado usando el carácter +. Esto se usa como una operación lógica y. Por ejemplo, SHA1+DES representa todas las suites de cifrado que contienen SHA1 y los algoritmos DES.

Cada string de cifrado puede ir precedido opcionalmente por los caracteres !, - o +.

Si se usa !, los cifrados se eliminan permanentemente de la lista. Los cifrados eliminados nunca podrán reaparecer en la lista, incluso si se especifican explícitamente.

Si se usa -, los cifrados se eliminan de la lista, pero algunos o todos los cifrados pueden volver a añadirse mediante opciones posteriores.

Si se usa +, los cifrados se mueven al final de la lista. Esta opción no añade cifrados nuevos, solo mueve los existentes que coinciden.

Si ninguno de estos caracteres está presente, el string se interpreta simplemente como una lista de cifrados que se añadirán a la lista de preferencias actual. Si la lista incluye cifrados ya presentes, se ignorarán: es decir, no se moverán al final de la lista.

El string de cifrado @STRENGTH puede usarse en cualquier punto para ordenar la lista de cifrados actual según la longitud de clave del algoritmo de cifrado.

El string de cifrado @SECLEVEL=n puede usarse en cualquier punto para establecer el nivel de seguridad a n, que debe ser un número entre cero y cinco, inclusive. Consulte SSL_CTX_set_security_level(3) para una descripción de lo que significa cada nivel.

La lista de cifrados puede ir precedida por la palabra clave DEFAULT, que habilita la lista de cifrados predeterminada tal como se define a continuación. A diferencia de los strings de cifrado, este prefijo no se puede combinar con otros strings usando el carácter +. Por ejemplo, DEFAULT+DES no es válido.

El contenido de la lista predeterminada se determina en tiempo de compilación y normalmente corresponde a ALL:!COMPLEMENTOFDEFAULT:!eNULL.

STRINGS CIFRADO

A continuación se muestra una lista de todos los strings de cifrado permitidos y sus significados.

COMPLEMENTOFDEFAULT
Los cifrados incluidos en ALL, pero no habilitados por defecto. Actualmente incluye todos los cifrados RC4 y anónimos. Tenga en cuenta que esta regla no cubre eNULL, que no está incluido en ALL (use COMPLEMENTOFALL si es necesario). Tenga en cuenta que las suites de cifrado basadas en RC4 no están integradas en OpenSSL por defecto (consulte la opción enable-weak-ssl-ciphers de Configure).
ALL
Todas las suites de cifrado excepto los cifrados eNULL (que deben habilitarse explícitamente si es necesario). A partir de OpenSSL 1.0.0, las suites de cifrado ALL están ordenadas sensatamente por defecto.
COMPLEMENTOFALL
Las suites de cifrado no habilitadas por ALL, actualmente eNULL.
HIGH
Suites de cifrado de cifrado "alto". Actualmente significa aquellas con longitudes de clave superiores a 128 bits, y algunas suites de cifrado con claves de 128 bits.

CIPHER STRING EQUIVALENTS

The following lists give the most common cipher string names and their OpenSSL equivalents.

HIGH
A predefined string that selects a strong cipher suite. Currently, this is equivalent to the cipher string ''DEFAULT'':@STRENGTH''.
MEDIUM
"Medium" encryption cipher suites, currently some of those using 128 bit encryption.
LOW
"Low" encryption cipher suites, currently those using 64 or 56 bit encryption algorithms but excluding export cipher suites. All these cipher suites have been removed as of OpenSSL 1.1.0.
eNULL, NULL
The "NULL" ciphers that is those offering no encryption. Because these offer no encryption at all and are a security risk they are not enabled via either the DEFAULT or ALL cipher strings. Be careful when building cipherlists out of lower-level primitives such as kRSA or aECDSA as these do overlap with the eNULL ciphers. When in doubt, include !eNULL in your cipherlist.
aNULL
The cipher suites offering no authentication. This is currently the anonymous DH algorithms and anonymous ECDH algorithms. These cipher suites are vulnerable to "man in the middle" attacks and so their use is discouraged. These are excluded from the DEFAULT ciphers, but included in the ALL ciphers. Be careful when building cipherlists out of lower-level primitives such as kDHE or AES as these do overlap with the aNULL ciphers. When in doubt, include !aNULL in your cipherlist.
kRSA, aRSA, RSA
Cipher suites using RSA key exchange or authentication. RSA is an alias for kRSA.
kDHr, kDHd, kDH
Cipher suites using static DH key agreement and DH certificates signed by CAs with RSA and DSS keys or either respectively. All these cipher suites have been removed in OpenSSL 1.1.0.
kDHE, kEDH, DH
Cipher suites using ephemeral DH key agreement, including anonymous cipher suites.
DHE, EDH
Cipher suites using authenticated ephemeral DH key agreement.
ADH
Anonymous DH cipher suites, note that this does not include anonymous Elliptic Curve DH (ECDH) cipher suites.
kEECDH, kECDHE, ECDH
Cipher suites using ephemeral ECDH key agreement, including anonymous cipher suites.
ECDHE, EECDH
Cipher suites using authenticated ephemeral ECDH key agreement.
AECDH
Anonymous Elliptic Curve Diffie-Hellman cipher suites.
aDSS, DSS
Cipher suites using DSS authentication, i.e. the certificates carry DSS keys.
aDH
Cipher suites effectively using DH authentication, i.e. the certificates carry DH keys. All these cipher suites have been removed in OpenSSL 1.1.0.
aECDSA, ECDSA
Cipher suites using ECDSA authentication, i.e. the certificates carry ECDSA keys.
TLSv1.2, TLSv1.0, SSLv3
Lists cipher suites which are only supported in at least TLS v1.2, TLS v1.0 or SSL v3.0 respectively. Note: there are no cipher suites specific to TLS v1.1. Since this is only the minimum version, if, for example, TLSv1.0 is negotiated then both TLSv1.0 and SSLv3.0 cipher suites are available.

Note: these cipher strings do not change the negotiated version of SSL or TLS, they only affect the list of available cipher suites.

AES128, AES256, AES
cipher suites using 128 bit AES, 256 bit AES or either 128 or 256 bit AES.
AESGCM
AES in Galois Counter Mode (GCM): these cipher suites are only supported in TLS v1.2.
AESCCM, AESCCM8
AES in Cipher Block Chaining - Message Authentication Mode (CCM): these cipher suites are only supported in TLS v1.2. AESCCM references CCM cipher suites using both 16 and 8 octet Integrity Check Value (ICV) while AESCCM8 only references 8 octet ICV.
ARIA128, ARIA256, ARIA
Cipher suites using 128 bit ARIA, 256 bit ARIA or either 128 or 256 bit ARIA.
CAMELLIA128, CAMELLIA256, CAMELLIA
Cipher suites using 128 bit CAMELLIA, 256 bit CAMELLIA or either 128 or 256 bit CAMELLIA.
CHACHA20
Cipher suites using ChaCha20.
3DES
Cipher suites using triple DES.
DES
Cipher suites using DES (not triple DES). All these cipher suites have been removed in OpenSSL 1.1.0.
RC4
Cipher suites using RC4.
RC2
Cipher suites using RC2.
IDEA
Cipher suites using IDEA.
SEED
Cipher suites using SEED.
MD5
Cipher suites using MD5.
SHA1, SHA
Cipher suites using SHA1.
SHA256, SHA384
Cipher suites using SHA256 or SHA384.
aGOST
Cipher suites using GOST R 34.10 (either 2001 or 94) for authentication (needs an engine supporting GOST algorithms).
aGOST01
Cipher suites using GOST R 34.10-2001 authentication.
kGOST
Cipher suites, using VKO 34.10 key exchange, specified in the RFC 4357.
GOST94
Cipher suites, using HMAC based on GOST R 34.11-94.
GOST89MAC
Cipher suites using GOST 28147-89 MAC instead of HMAC.
PSK
All cipher suites using pre-shared keys (PSK).
kPSK, kECDHEPSK, kDHEPSK, kRSAPSK
Cipher suites using PSK key exchange, ECDHE_PSK, DHE_PSK or RSA_PSK.
aPSK
Cipher suites using PSK authentication (currently all PSK modes apart from RSA_PSK).
SUITEB128, SUITEB128ONLY, SUITEB192
Enables suite B mode of operation using 128 (permitting 192 bit mode by peer) 128 bit (not permitting 192 bit by peer) or 192 bit level of security respectively. If used these cipherstrings should appear first in the cipher list and anything after them is ignored. Setting Suite B mode has additional consequences required to comply with RFC6460. In particular the supported signature algorithms is reduced to support only ECDSA and SHA256 or SHA384, only the elliptic curves P-256 and P-384 can be used and only the two suite B compliant cipher suites (ECDHE-ECDSA-AES128-GCM-SHA256 and ECDHE-ECDSA-AES256-GCM-SHA384) are permissible.
CBC
All cipher suites using encryption algorithm in Cipher Block Chaining (CBC) mode. These cipher suites are only supported in TLS v1.2 and earlier. Currently it's an alias for the following cipherstrings: SSL_DES, SSL_3DES, SSL_RC2, SSL_IDEA, SSL_AES128, SSL_AES256, SSL_CAMELLIA128, SSL_CAMELLIA256, SSL_SEED.

NOMBRE

openssl-ciphers - mostrar o convertir listas de cifrado

SINOPSIS

openssl ciphers [-v] [-s] [-V] [-stdname] [-convert] [cipherlist]

DESCRIPCIÓN

El comando openssl ciphers se utiliza para obtener una lista de los cifrados que puede utilizar OpenSSL. Se pueden especificar una o más listas de cifrado para filtrar la salida.

Si no se especifica ninguna lista de cifrado, se imprimen todos los cifrados conocidos por la biblioteca OpenSSL.

La salida es una cadena separada por dos puntos. Cada cifrado individual tiene un formato estándar.

La entrada es un conjunto de reglas de filtrado, separadas por dos puntos. La primera regla se aplica a la lista completa de cifrados. Las reglas subsiguientes se aplican a los resultados de las reglas anteriores. Por ejemplo, ALL:!aNULL:!eNULL muestra todos los cifrados excepto aquellos que son anónimos (aNULL) o no tienen cifrado (eNULL).

Los operadores de comparación son:

ALL
Todos los cifrados.
eNULL
Cifrados sin cifrado.
aNULL
Cifrados sin autenticación.
SSLv3
Cifrados que se pueden usar con SSLv3.
TLSv1.2
Cifrados que se pueden usar con TLSv1.2.
TLSv1.3
Cifrados que se pueden usar con TLSv1.3.
COMPLEMENTOFALL
Todos los cifrados excepto los cifrados no nulos.
COMPLEMENTOFDEFAULT
Todos los cifrados excepto los cifrados predeterminados.
DEFAULT
Los cifrados predeterminados.

Los operadores de lista son:

+
Añadir cifrados.
-
Eliminar cifrados.
:
Separador.

OPCIONES

-v
Modo detallado. Imprime el nombre estándar IANA y el nombre antiguo si está disponible.
-s
Imprime la lista de cifrado especificada por el nivel de seguridad seleccionado.
-V
Muestra la versión de OpenSSL y la arquitectura subyacente.
-stdname
Las cadenas de cifrado se imprimen en el formato estándar IANA, en lugar de los nombres más cortos utilizados internamente por OpenSSL.
-convert
Las cadenas de cifrado se imprimen en el formato más corto utilizado internamente por OpenSSL, en lugar de los nombres estándar IANA.

FORMATO DE LISTA DE CIFRADO

Una lista de cifrado es una lista separada por dos puntos de protocolos y algoritmos que pueden ser utilizados durante una conexión SSL/TLS. El formato general es:

<cipher><cipher_type><prefix><suffix>

donde:

<cipher>
El algoritmo de cifrado utilizado, por ejemplo, AES, DES, 3DES, RC4, etc.
<cipher_type>
El tipo de cifrado, por ejemplo, NULL, CBC, GCM, etc.
<prefix>
El prefijo que indica el tipo de intercambio de claves, por ejemplo, ECDHE, DHE, PSK, RSA, etc.
<suffix>
El sufijo que indica el algoritmo de autenticación/resumen, por ejemplo, SHA, SHA1, SHA256, SHA384, etc.

EJEMPLOS

Listado detallado de todos los cifrados de OpenSSL, incluidos los cifrados NULL:

openssl ciphers -v 'ALL:eNULL'

Incluir todos los cifrados excepto NULL y DH anónimo, luego ordenar por fuerza:

openssl ciphers -v 'ALL:!ADH:@STRENGTH'

Incluir todos los cifrados excepto los que no tienen cifrado (eNULL) o no tienen autenticación (aNULL):

openssl ciphers -v 'ALL:!aNULL'

Incluir solo cifrados 3DES y luego colocar los cifrados RSA al final:

openssl ciphers -v '3DES:+RSA'

Incluir todos los cifrados RC4 pero excluir aquellos sin autenticación:

openssl ciphers -v 'RC4:!COMPLEMENTOFDEFAULT'

Incluir todos los cifrados con autenticación RSA pero excluir los cifrados sin cifrado.

openssl ciphers -v 'RSA:!COMPLEMENTOFALL'

Establecer el nivel de seguridad en 2 y mostrar todos los cifrados consistentes con el nivel 2:

openssl ciphers -s -v 'ALL:@SECLEVEL=2'

HISTORIA

La opción -V se añadió en OpenSSL 1.0.0.

La opción -stdname solo está disponible si OpenSSL se compila con seguimiento habilitado ( argumento enable-ssl-trace para Configure) antes de OpenSSL 1.1.1.

La opción -convert se añadió en OpenSSL 1.1.1.

El soporte para nombres estándar IANA en listas de cifrado se añadió en OpenSSL 3.2.0.

El soporte para cifrados de solo integridad de TLS v1.3 se añadió en OpenSSL 3.4.
