option(n) Comandos integrados de Tk option(n)

NOMBRE

option - Añadir/recuperar opciones de ventana de/a la base de datos de opciones

SINOPSIS

option add patrón valor ?prioridad?
option clear
option get ventana nombre clase
option readfile nombreArchivo ?prioridad?

DESCRIPCIÓN

El comando option permite añadir entradas a la base de datos de opciones de Tk o recuperar opciones de la base de datos. La forma add del comando añade una nueva opción a la base de datos. Patrón contiene la opción que se está especificando, y consiste en nombres y/o clases separadas por asteriscos o puntos, en el formato habitual de X (ver FORMATO DE PATRÓN). Valor contiene una cadena de texto para asociar con patrón; este es el valor que se devolverá en las llamadas a Tk_GetOption o en las invocaciones del comando option get. Si se especifica prioridad, indica el nivel de prioridad para esta opción (ver más abajo los valores legales); por defecto es interactive. Este comando siempre devuelve una cadena vacía.

El comando option clear limpia la base de datos de opciones. Las opciones predeterminadas (de la propiedad RESOURCE_MANAGER o del archivo .Xdefaults) se recargarán automáticamente la próxima vez que se añada o elimine una opción de la base de datos. Este comando siempre devuelve una cadena vacía.

El comando option get devuelve el valor de la opción especificada para ventana bajo nombre y clase. Si varias entradas en la base de datos de opciones coinciden con ventana, nombre y clase, el comando devuelve la que se creó con el nivel de prioridad más alto. Si hay varias entradas coincidentes al mismo nivel de prioridad, devuelve la entrada que se introdujo más recientemente en la base de datos de opciones. Si no hay entradas coincidentes, se devuelve la cadena vacía.

La forma readfile del comando lee nombreArchivo, que debe tener el formato estándar para una base de datos de recursos de X como .Xdefaults, y añade todas las opciones especificadas en ese archivo a la base de datos de opciones. Si se especifica prioridad, indica el nivel de prioridad con el que se introducirán las opciones; prioridad por defecto es interactive.

El archivo se lee a través de un canal con codificación "utf-8", las secuencias de bytes inválidas se convierten automáticamente en válidas. Esto significa que codificaciones como ISO 8859-1 o cp1252 funcionarán con alta probabilidad, pero esto no se puede garantizar. Esto no se puede cambiar, la configuración de [encoding system] no tiene efecto.

Los argumentos de prioridad para el comando option se especifican normalmente de forma simbólica utilizando uno de los siguientes valores:

widgetDefault
Nivel 20. Se utiliza para los valores predeterminados codificados en los widgets.
startupFile
Nivel 40. Se utiliza para las opciones especificadas en archivos de inicio específicos de la aplicación.
userDefault
Nivel 60. Se utiliza para las opciones especificadas en archivos de preferencias específicos del usuario, como .Xdefaults, bases de datos de recursos cargadas en el servidor X, o archivos de inicio específicos del usuario.
interactive
Nivel 80. Se utiliza para las opciones especificadas interactivamente después de que la aplicación comience a ejecutarse. Si no se especifica prioridad, por defecto es este nivel.

Cualquiera de las palabras clave anteriores puede abreviarse. Además, las prioridades pueden especificarse numéricamente usando enteros entre 0 y 100, inclusive. La forma numérica probablemente sea una mala idea excepto para nuevos niveles de prioridad distintos de los indicados anteriormente.

FORMATO DE PATRÓN

Los patrones consisten en una secuencia de palabras separadas por puntos, “.”, o asteriscos “*”. El patrón general también puede ir opcionalmente precedido por un asterisco.

Cada palabra en el patrón convencionalmente comienza con una letra mayúscula (en cuyo caso denota la clase de un widget o una opción) o cualquier otro carácter, cuando denota el nombre de un widget o opción. La última palabra del patrón siempre indica la opción; las anteriores restringen a qué widgets se buscará la opción.

Cuando dos palabras están separadas por un punto, el widget posterior debe ser un hijo directo del anterior (o la opción debe aplicarse solo a los widgets indicados). Cuando dos palabras están separadas por un asterisco, cualquier profundidad de widgets puede estar entre el widget anterior y el posterior (y la opción se aplica a todos los widgets que son hijos del widget anterior).

Si el patrón general está precedido por un asterisco, entonces el patrón general se aplica en cualquier lugar que pueda en toda la jerarquía de widgets. De lo contrario, la primera palabra del patrón coincide con el nombre y la clase del “.” toplevel, que normalmente se establecen mediante opciones para wish.

EJEMPLOS

Instruir a todos los botones de la aplicación para que tengan texto rojo, a menos que se anule explícitamente, estableciendo el foreground para la clase Button (tenga en cuenta que en algunas plataformas la opción se ignora):

option add *Button.foreground red startupFile

Permitir a los usuarios controlar lo que sucede en un widget Entry cuando se presiona la tecla Intro, especificando un script en la base de datos de opciones y añadiendo una opción predeterminada que hace sonar la alarma:

entry .e
bind .e <Return> [option get .e returnCommand Command]
option add *.e.returnCommand bell widgetDefault
