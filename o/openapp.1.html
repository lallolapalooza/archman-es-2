openapp(1) Manual del sistema GNUstep openapp(1)

NOMBRE

openapp - lanzar aplicaciones desde la línea de comandos

SINOPSIS

openapp [--find] [--debug [--gdb= depurador]] [ --library-combo=combo-librerias ] aplicacion [argumentos...]

DESCRIPCIÓN

El comando openapp te permite lanzar aplicaciones gráficas GNUstep desde la línea de comandos.

aplicacion es el nombre completo o relativo del programa aplicación con o sin la extensión .app, como Ink.app.

argumentos son los argumentos pasados a la aplicación.

openapp primero comprueba si la aplicación está en el directorio de trabajo actual. Si no, busca en las carpetas de Aplicaciones de los dominios de GNUstep en el siguiente orden: Usuario (es decir, ~/GNUstep/Applications), Local, Red, Sistema. La primera coincidencia gana.

OPCIONES

--find aplicacion
imprimirá la ruta completa del ejecutable de la aplicación que se ejecutaría, sin ejecutarla realmente. También listará todas las rutas que se intentan.
--debug aplicacion
inicia la aplicación en el depurador. Por defecto gdb, pero esto se puede cambiar con el argumento --gdb= o a través de la variable del shell GDB.
--library-combo=combo-librerias
Inicia la aplicación con la combinación de librerías especificada. Esta es una opción raramente utilizada en una configuración no aplanada. Consulte la página del manual de library-combo(7) para obtener más información sobre las diferentes combinaciones de librerías.
--help
imprime la descripción de uso anterior.

EJEMPLOS

Iniciar Ink.app sin parámetros adicionales:

openapp Ink.app

Lanzar Ink.app y pasarle el argumento --debug:

openapp --debug Ink.app

Para determinar qué ejecutable es lanzado por openapp, escribe:

openapp --find Ink.app

La salida del comando anterior podría ser algo como: /usr/GNUstep/Local/Applications/Ink.app/Ink

AMBIENTE

GNUSTEP_CONFIG_FILE
se utiliza para determinar dónde se encuentra el archivo de configuración GNUstep.sh. Si la variable no está establecida, openapp intenta localizarlo en la carpeta donde se inició openapp, luego en el dominio del usuario, y como último recurso en el dominio del sistema (o realmente en el lugar que configuraste (--with-config-file=) durante la compilación).
GDB
Establece el depurador a usar cuando se utiliza --debug.
