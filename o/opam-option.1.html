OPAM-OPTION(1) Manual de Opam OPAM-OPTION(1)

NOMBRE

opam-option - Configuración global y de entorno de trabajo de las opciones

SINOPSIS

opam option [--global] [OPCIÓN]… [CAMPO[(=|+=|-=)[VALOR]]]

DESCRIPCIÓN

Sin argumentos, lista todos los campos configurables. Si se proporciona el nombre de un campo CAMPO, muestra su contenido. De lo contrario, establece o actualiza el campo dado en el archivo de configuración global/de entorno de trabajo. Para la configuración global, CAMPO se restablece a su valor inicial predeterminado, como después de una inicialización nueva (use `opam init show-default-opamrc` para mostrarlo).

ARGUMENTOS

CAMPO[(=|+=|-=)[VALOR]]
Si solo se proporciona CAMPO, muestra su valor asociado. Si VALOR está ausente, el valor de CAMPO se revierte. De lo contrario, su valor se actualiza: sobrescritura (=), adición (+=) o eliminación de un elemento (-=).

OPCIONES

--global
Actuar sobre la configuración global.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intente instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utilice la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Destinado a cualquier uso persistente de opam (scripts, publicaciones de blogs, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. El indicador no estaba disponible en opam 2.0, por lo que para seleccionar el CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de utilizar este parámetro.
--color=CUÁNDO
Colorear la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o unsafe-yes. Se puede especificar más de una vez. Si --yes o --no también se proporcionan, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL`.
--criteria=CRITERIOS
Especificar las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el idioma compatible y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general para usar las preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: Guardar las solicitudes CUDF enviadas al solucionador en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprimir mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprimir la versión git de opam, si está establecida (es decir, si está utilizando una versión de desarrollo), y salir.
--help[=FMT] (predeterminado=auto)
Mostrar esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignorar pines adicionales requeridos por paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guardar los resultados de la ejecución de opam en un archivo legible por máquina. Si el nombre de archivo contiene el carácter `%`, se reemplazará por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responder no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deberían definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato anterior. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Use ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegúrese de que nada se actualizará ni se reescribirá automáticamente. Útil para llamarlo desde scripts de finalización, por ejemplo. Fallará cuando se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el solucionador CUDF a utilizar para resolver problemas de instalación de paquetes. Este es un solucionador predefinido (esta versión de opam admite builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Fallar siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--switch=SWITCH
Use SWITCH como el entorno de trabajo del compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo y utiliza el interno (esto requiere que opam haya sido compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Ser más detallado. Un -v muestra todos los comandos de paquetes, repita para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Mostrar información de la versión.
-w, --working-dir
Cuando se actualizan paquetes que están vinculados a un directorio local y controlado por versiones, actualizar al estado de trabajo actual de su fuente en lugar de al último estado confirmado, o a la referencia a la que apuntan. Como el directorio de origen se copia tal cual, si no está limpio, puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede configurar con $OPAMWORKINGDIR.
-y, --yes
Responder sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

AMBIENTE

Opam utiliza las variables de entorno enumeradas aquí. Las variables booleanas deben establecerse en "0", "no", "false" o la cadena vacía para deshabilitar, "1", "yes" o "true" para habilitar.

OPAMALLPARENS rodea todos los filtros con paréntesis.

OPAMASSUMEDEPEXTS ver la opción `--assume-depexts'.

OPAMAUTOREMOVE ver la opción remove

VARIABLES DE ENTORNO DE OPAM

Las siguientes variables de entorno pueden usarse para modificar el comportamiento de opam:

OPAM_AUTO_REMOVE
ver la opción --auto-remove.
OPAMBESTEFFORT
ver la opción --best-effort.
OPAMBESTEFFORTPREFIXCRITERIA
establece la cadena que debe anteponerse a los criterios cuando se establece la opción --best-effort, y se espera que maximice la propiedad `opam-query' en la solución.
OPAMBUILDDOC
Eliminado en 2.1.
OPAMBUILDTEST
Eliminado en 2.1.
OPAMCLI
ver la opción --cli.
OPAMCOLOR
cuando se establece en always o never, establece un valor predeterminado para la opción --color.
OPAMCONFIRMLEVEL
ver la opción --confirm-level. OPAMCONFIRMLEVEL tiene prioridad sobre OPAMYES y OPAMNO.
OPAMCRITERIA
especifica las preferencias del usuario para la resolución de dependencias. El valor predeterminado depende de la versión del resolvedor, use `config report' para conocer la configuración actual. Ver también la opción --criteria.
OPAMCUDFFILE
guarda el grafo cudf en el archivo file-actions-explicit.dot.
OPAMCUDFTRIM
controla el filtrado de paquetes no relacionados durante el preprocesamiento de CUDF.
OPAMCURL
puede usarse para seleccionar un programa `curl' dado. Ver OPAMFETCH para más opciones.
OPAMDEBUG
ver las opciones --debug y --debug-level.
OPAMDEBUGSECTIONS
si se establece, limita los mensajes de depuración a la lista separada por espacios de secciones. Las secciones opcionalmente pueden tener un nivel de depuración específico (por ejemplo, CLIENT:2 o CLIENT CUDF:2), pero de lo contrario usan `--debug-level'.
OPAMDIGDEPTH
define la agresividad de la búsqueda de conflictos durante el preprocesamiento de CUDF.
OPAMDOWNLOADJOBS
establece el número máximo de descargas simultáneas.
OPAMDROPWORKINGDIR
anula los paquetes previamente actualizados con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se nombraran explícitamente en la línea de comandos.
OPAMDRYRUN
ver la opción --dry-run.
OPAMEDITOR
establece el editor a usar para editar archivos opam, anula $EDITOR y $VISUAL.
OPAMERRLOGLEN
establece el número de líneas de registro impresas cuando un subproceso falla. 0 para imprimir todas.
OPAMEXTERNALSOLVER
ver la opción --solver.
OPAMFAKE
ver la opción --fake.
OPAMFETCH
especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor de 'download-command' del archivo de configuración principal.
OPAMFIXUPCRITERIA
igual que OPAMUPGRADECRITERIA, pero específico para fixup y reinstalación.
OPAMIGNORECONSTRAINTS
ver la opción de instalación `--ignore-constraints-on'.
OPAMIGNOREPINDEPENDS
ver la opción --ignore-pin-depends.
OPAMINPLACEBUILD
ver la opción --inplace-build.
OPAMJOBS
establece el número máximo de trabajadores paralelos a ejecutar.
OPAMJSON
registra la salida json en el archivo dado (use el carácter `%' para indexar los archivos).
OPAMKEEPBUILDDIR
ver la opción de instalación `--keep-build-dir'.
OPAMKEEPLOGS
indica a opam que no elimine algunos registros de comandos temporales y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener backtraces más fiables.
OPAMLOCKED
combinación de las opciones `--locked' y `--lock-suffix'.
OPAMLOGS
logdir establece el directorio de registros, el predeterminado es un directorio temporal en /tmp
OPAMMAKECMD
establece el comando make del sistema a usar.
OPAMMERGEOUT
fusiona las salidas de procesos, stderr en stdout.
OPAMNO
responde no a cualquier pregunta hecha, ver las opciones `--no` y `--confirm-level`. OPAMNO se ignora si OPAMCONFIRMLEVEL o OPAMYES está establecido.
OPAMNOAGGREGATE
con `opam admin check', no agregar paquetes.
OPAMNOASPCUD
Obsoleto.
OPAMNOAUTOUPGRADE
deshabilita la actualización automática interna de repositorios en un formato anterior al actual, en 'update' o 'init'.
OPAMNOCHECKSUMS
habilita la opción --no-checksums cuando esté disponible.
OPAMNODEPEXTS
deshabilita el manejo de dependencias del sistema, ver la opción `--no-depexts'.
OPAMNOENVNOTICE
Interno.
OPAMNOSELFUPGRADE
ver la opción `--no-self-upgrade'
OPAMPINKINDAUTO
establece si los sistemas de control de versiones deben detectarse al fijar a una ruta local. Habilitado por defecto desde 1.3.0.
OPAMPRECISETRACKING
seguimiento de directorios de grano fino.
OPAMPREPRO
establezca esto en falso para deshabilitar el preprocesamiento de CUDF. Menos eficiente, pero podría ayudar a depurar problemas del resolvedor.
OPAMREPOSITORYTARRING
almacena internamente los repositorios como archivos tar.gz. Esto puede ser mucho más rápido en sistemas de archivos que no manejan bien el escaneo de árboles grandes pero que tienen una buena caché en /tmp. Sin embargo, esto es más lento en el caso general.
OPAMREQUIRECHECKSUMS
habilita la opción `--require-checksums' cuando esté disponible (por ejemplo, para `opam install').
OPAMRETRIES
establece el número de intentos antes de fallar las descargas.
OPAMREUSEBUILDDIR
ver la opción `--reuse-build-dir'.
OPAMROOT
ver la opción `--root'. Esto se establece automáticamente mediante `opam env --root=DIR --set-root'.
OPAMROOTISOK
no se queje al ejecutarse como root.
OPAMSAFE
ver la opción `--safe'.
OPAMSHOW
ver la opción `--show'.
OPAMSKIPUPDATE
ver la opción `--skip-updates'.
OPAMSKIPVERSIONCHECKS
omite algunas comprobaciones de versión. Inseguro, solo para pruebas de compatibilidad.
OPAMSOLVERALLOWSUBOPTIMAL
(predeterminado `true') permite que algunos resolvedores devuelvan una solución incluso cuando alcanzan el tiempo límite; aunque se garantiza que la solución sigue siendo consistente, no hay garantía en este caso de que cumpla los criterios de optimización esperados. Si es `true', opam continuará con una advertencia, si es `false', un tiempo límite es un error. Actualmente, solo el backend builtin-z3 maneja este caso degradado.
OPAMSOLVERTIMEOUT
cambia el tiempo permitido para el resolvedor. El valor predeterminado es 60.0, establézcalo en 0 para ilimitado. Tenga en cuenta que no todos los resolvedores pueden admitir esta opción.
OPAMSOLVERTOLERANCE
cambia la tolerancia hacia el resolvedor al elegir una solución no optimizada (es decir, puede descargar paquetes desactualizados). Los valores típicos varían de 0.0 (mejor solución conocida por el resolvedor) a 1.0 (solución no optimizada). El predeterminado es 0.0. Esta opción es útil en caso de que el resolvedor no pueda encontrar una solución en un tiempo razonable (ver $OPAMSOLVERTIMEOUT). Tenga en cuenta que no todos los resolvedores pueden admitir esta opción.
OPAMSTATS
Eliminado en 2.4.
OPAMSTATUSLINE
muestra una línea de estado dinámica que indica lo que está sucediendo en el terminal. (una de always, never o auto)
OPAMSTRICT
falla ante inconsistencias (lectura de archivos, importación de switch, etc.).
OPAMSWITCH
ver la opción `--switch'. Se establece automáticamente mediante `opam env --switch=SWITCH --set-switch'.
OPAMUNLOCKBASE
ver la opción de instalación `--unlock-base'.
OPAMUPGRADECRITERIA
especifica las preferencias del usuario para la resolución de dependencias al realizar una actualización. Anula OPAMCRITERIA en las actualizaciones si ambos están establecidos. Ver también la opción --criteria.
OPAMUSEINTERNALSOLVER
ver la opción `--use-internal-solver'.
OPAMUSEOPENSSL
Eliminado en 2.2.
OPAMUTF8
usa caracteres UTF8 en la salida (uno de always, never o auto). Por defecto `auto', que se determina del locale).
OPAMUTF8MSGS
usa caracteres UTF8 extendidos (camellos) en los mensajes de opam. Implica OPAMUTF8. Esto se establece por defecto solo en macOS.
OPAMVALIDATIONHOOK
si se establece, usa el comando `%{hook%}' para validar una actualización del repositorio opam.
OPAMVERBOSE
ver la opción `--verbose'.
OPAMVERBOSEON
ver la opción --verbose-on
OPAMVERSIONLAGPOWER
no usar.
OPAMWITHDEVSETUP
ver la opción de instalación `--with-dev-setup'.
OPAMWITHDOC
ver la opción de instalación `--with-doc'.
OPAMWITHTEST
ver la opción de instalación `--with-test.
OPAMWORKINGDIR
ver la opción `--working-dir'.
OPAMYES
ver las opciones `--yes` y `--confirm-level`. OPAMYES tiene prioridad sobre OPAMNO y se ignora si OPAMCONFIRMLEVEL está establecido.
OPAMVAR_var
anula el contenido de la variable var al sustituir cadenas `%{var}%' en archivos `opam`.
OPAMVAR_package_var
anula el contenido de la variable package:var al sustituir cadenas `%{package:var}%' en archivos `opam`.

VERSIÓN DEL CLI

Todos los scripts e invocaciones programáticas de opam deben usar `--cli' para garantizar que funcionen sin problemas con versiones futuras del cliente opam. Además, las publicaciones de blog u otra documentación pueden beneficiarse, ya que evita que la información se vuelva obsoleta.

Aunque opam solo admite raíces (~/.opam/) para la versión actual, proporciona retrocompatibilidad para su interfaz de línea de comandos.

Dado que la compatibilidad con la versión CLI se agregó solo en opam 2.1, use OPAMCLI para seleccionar la compatibilidad 2.0 (ya que opam 2.0 simplemente la ignorará), y `--cli=2.1' para versiones 2.1 (o posteriores), ya que una variable de entorno que controle el análisis de sintaxis es frágil. Para ello, opam muestra una advertencia si OPAMCLI especifica una versión válida distinta de 2.0, y también si se especifica `--cli=2.0'.

La versión de línea de comandos se selecciona usando la opción `--cli' o la variable de entorno OPAMCLI. `--cli' puede especificarse más de una vez, donde la última instancia tiene prioridad. OPAMCLI solo se inspecciona si no se proporciona `--cli'.

ESTADO DE SALIDA

Como excepción a lo siguiente, el comando `exec' devuelve 127 si el comando no se encontró o no se pudo ejecutar, y el valor de salida del comando en caso contrario.

0
Éxito, o verdadero para consultas booleanas.
1
Falso. Devuelto cuando se espera un valor de retorno booleano, por ejemplo, al ejecutarse con --check, o para consultas como opam lint.
2
Argumentos de línea de comandos incorrectos, o argumentos de línea de comandos que apuntan a un contexto inválido (por ejemplo, archivo que no sigue el formato esperado).
5
No encontrado. Solicitó algo (paquete, versión, repositorio, etc.) que no se pudo encontrar.
10
Abortado. La operación requirió confirmación, la cual no fue dada.
15

ESTADO DE SALIDA

Los siguientes códigos de salida son producidos por opam:

0
en caso de éxito.
10
Error de bloqueo. No se pudieron adquirir los bloqueos necesarios para la operación.
20
No hay solución para la solicitud del usuario. Esto puede deberse a que se intentan instalar dos paquetes incompatibles, por ejemplo.
30
Error en la definición del paquete u otros archivos de metadatos. El uso de --strict genera este error con más frecuencia.
31
Error en el script del paquete. Algunas operaciones del paquete no se realizaron con éxito. Puede ser un error en los paquetes o una incompatibilidad con su sistema. Puede ser un error parcial.
40
Error de sincronización. No se pudieron obtener algunos remotos de la red. Puede ser un error parcial.
50
Error de configuración. La configuración de opam o del sistema no permite la operación y necesita ser corregida.
60
Fallo del solucionador. El solucionador no pudo devolver una respuesta sólida. Puede deberse a un solucionador externo defectuoso o a un error en la configuración del solucionador.
99
Error interno. Algo salió mal, probablemente debido a un error en opam mismo.
130
Interrupción del usuario. Se recibió SIGINT, generalmente debido a que el usuario presionó Ctrl-C.
123
en errores indiscriminados reportados en la salida estándar.
124
en errores de análisis de línea de comandos.
125
en errores internos inesperados (bugs).
