GDBSERVER(1) Herramientas de Desarrollo GNU GDBSERVER(1)

NOMBRE

gdbserver - Servidor Remoto para el Depurador GNU

SINOPSIS

gdbserver comm prog [args...]

gdbserver --attach comm pid

gdbserver --multi comm

DESCRIPCIÓN

gdbserver es un programa que permite ejecutar GDB en una máquina diferente a la que está ejecutando el programa que se está depurando.

Uso (lado del servidor (objetivo)):

Primero, necesitas tener una copia del programa que quieres depurar en el sistema objetivo. El programa puede ser despojado (stripped) para ahorrar espacio si es necesario, ya que gdbserver no se preocupa por los símbolos. Todo el manejo de símbolos es realizado por el GDB que se ejecuta en el sistema host.

Para usar el servidor, inicia sesión en el sistema objetivo y ejecuta el programa gdbserver. Debes indicarle (a) cómo comunicarse con GDB, (b) el nombre de tu programa y (c) sus argumentos. La sintaxis general es:

objetivo> gdbserver <comm> <programa> [<args> ...]

Por ejemplo, usando un puerto serie, podrías decir:

objetivo> gdbserver /dev/com1 emacs foo.txt

Esto le dice a gdbserver que depure emacs con el argumento foo.txt, y que se comunique con GDB a través de /dev/com1. gdbserver ahora espera pacientemente a que el GDB del host se comunique con él.

Para usar una conexión TCP, podrías decir:

objetivo> gdbserver host:2345 emacs foo.txt

Esto dice prácticamente lo mismo que el último ejemplo, excepto que vamos a comunicarnos con el GDB "host" vía TCP. El argumento "host:2345" significa que esperamos ver una conexión TCP desde "host" al puerto TCP local 2345. (Actualmente, la parte "host" se ignora.) Puedes elegir cualquier número para el número de puerto siempre que no entre en conflicto con ningún puerto TCP existente en el sistema objetivo. Este mismo número de puerto debe usarse en el comando "target remote" del GDB del host, que se describirá en breve. Ten en cuenta que si eliges un número de puerto que entra en conflicto con otro servicio, gdbserver imprimirá un mensaje de error y saldrá.

gdbserver también puede adjuntarse a programas en ejecución. Esto se logra a través del argumento --attach. La sintaxis es:

objetivo> gdbserver --attach <comm> <pid>

pid es el ID de proceso de un proceso en ejecución actualmente. No es necesario apuntar gdbserver a un binario del proceso en ejecución.

Para iniciar "gdbserver" sin proporcionar un comando inicial para ejecutar o un ID de proceso al que adjuntarse, usa la opción de línea de comandos --multi. En tal caso, deberías conectarte usando "target extended-remote" para iniciar el programa que quieres depurar.

objetivo> gdbserver --multi <comm>

Uso (lado del host):

Necesitas una copia sin despojar (unstripped) del programa objetivo en tu sistema host, ya que GDB necesita examinar sus tablas de símbolos y similares. Inicia GDB como lo harías normalmente, con el programa objetivo como primer argumento. (Puede que necesites usar la opción --baud si la línea serie se está ejecutando a una velocidad distinta de 9600 baudios). Esto es "gdb TARGET-PROG", o "gdb --baud BAUD TARGET-PROG". Después de eso, el único comando nuevo que necesitas conocer es "target remote" (o "target extended-remote"). Su argumento es un nombre de dispositivo (generalmente un dispositivo serie, como /dev/ttyb), o un descriptor "HOST:PORT". Por ejemplo:

(gdb) target remote /dev/ttyb

se comunica con el servidor a través de la línea serie /dev/ttyb, y:

(gdb) target remote the-target:2345

se comunica a través de una conexión TCP al puerto 2345 en el host `the-target', donde previamente iniciaste gdbserver con el mismo número de puerto. Ten en cuenta que para conexiones TCP, debes iniciar gdbserver antes de usar el comando `target remote', de lo contrario podrías obtener un error como `Connection refused'.

gdbserver también puede depurar múltiples inferiores a la vez, descrito en el manual de GDB en el nodo "Inferiors Connections and Programs" -- comando de shell "info -f gdb -n 'Inferiors Connections and Programs'". En tal caso, usa la variante del comando GDB "extended-remote":

(gdb) target extended-remote the-target:2345

La opción --multi de gdbserver puede ser utilizada o no en este caso.

OPCIONES

Hay tres modos diferentes para invocar gdbserver:

  • Depurar un programa específico especificado por su nombre de programa: 
    gdbserver <comm> <prog> [<args>...]

    El parámetro comm especifica cómo debe comunicarse el servidor con GDB; es el nombre de un dispositivo (para usar una línea serie), un número de puerto TCP (":1234"), o "-" o "stdio" para usar la entrada/salida estándar de "gdbserver". Especifica el nombre del programa a depurar en prog. Cualquier argumento restante se pasará al programa tal cual. Cuando el programa termine, GDB cerrará la conexión y "gdbserver" saldrá.

  • Depurar un programa específico especificando el ID de proceso de un programa en ejecución: 
    gdbserver --attach <comm> <pid>

    El parámetro comm es como se describe arriba. Proporciona el ID de proceso de un programa en ejecución en pid; GDB hará todo lo demás. Al igual que con el modo anterior, cuando el proceso pid termine, GDB cerrará la conexión y "gdbserver" saldrá.

  • Modo multiproceso -- depurar más de un programa/proceso: 
    gdbserver --multi <comm>

    En este modo, GDB puede instruir a gdbserver qué comando(s) ejecutar. A diferencia de los otros 2 modos, GDB no cerrará la conexión cuando un proceso que se está depurando termine, por lo que puedes depurar varios procesos en la misma sesión.

En cada uno de los modos, puedes especificar estas opciones:

--help
Lista todas las opciones, con explicaciones breves.
--version
Esta opción hace que gdbserver imprima su número de versión y salga.
--attach
gdbserver se adjuntará a un programa en ejecución. La sintaxis es: 
objetivo> gdbserver --attach <comm> <pid>

pid es el ID de proceso de un proceso en ejecución actualmente. No es necesario apuntar gdbserver a un binario del proceso en ejecución.

--multi
Para iniciar "gdbserver" sin proporcionar un comando inicial para ejecutar o un ID de proceso al que adjuntarse, usa esta opción de línea de comandos. Luego puedes conectarte usando "target extended-remote" e iniciar el programa que quieres depurar. La sintaxis es: 
objetivo> gdbserver --multi <comm>
--debug[=opción1,opción2,...]
Instruye a "gdbserver" para que muestre información de estado adicional sobre el proceso de depuración. Esta opción está destinada al desarrollo de "gdbserver" y para informes de errores a los desarrolladores.

Cada opción es el nombre de un componente para el cual se debe habilitar la depuración. La lista de opciones posibles es all, threads, event-loop, remote. La opción especial all habilita todos los componentes. La lista de opciones se procesa de izquierda a derecha, y una opción puede ir precedida por el carácter "-" para deshabilitar la salida para ese componente, por lo que podrías escribir:

objetivo> gdbserver --debug=all,-event-loop

para activar la salida de depuración para todos los componentes excepto event-loop. Si no se pasan opciones a --debug, esto se trata como equivalente a --debug=threads

--debug-file=nombre_archivo
Instruye a "gdbserver" para que envíe cualquier salida de depuración al nombre_archivo proporcionado. Esta opción está pensada para el desarrollo de "gdbserver" y para reportar errores a los desarrolladores.
--debug-format=opcion1[,opcion2,...]
Instruye a "gdbserver" para que incluya información adicional en cada línea de salida de depuración.
--wrapper
Especifica un envoltorio para lanzar programas para depuración. La opción debe ir seguida por el nombre del envoltorio, luego cualquier argumento de línea de comandos para pasar al envoltorio, luego "--" indicando el fin de los argumentos del envoltorio.
--once
Por defecto, gdbserver mantiene el puerto TCP de escucha abierto, de modo que sean posibles conexiones adicionales. Sin embargo, si inicia "gdbserver" con la opción --once, dejará de escuchar cualquier intento de conexión adicional después de conectarse a la primera sesión de GDB.

VER TAMBIÉN

La documentación completa de GDB se mantiene como un manual Texinfo. Si los programas "info" y "gdb" y la documentación Texinfo de GDB están correctamente instalados en su sitio, el comando

info gdb

debería darle acceso al manual completo.
