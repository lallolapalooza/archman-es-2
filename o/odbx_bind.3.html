odbx_bind(3)

Paquete: opendbx

Licencias: LGPL

odbx_bind(3) OpenDBX odbx_bind(3)

NOMBRE

odbx_bind, odbx_bind_simple - Autenticación de usuario para una conexión de base de datos

SINOPSIS

#include <opendbx/api.h>


int odbx_bind
(odbx_t* handle, const char* database, const char* who, const char* cred, int method);


int odbx_bind_simple
(odbx_t* handle, const char* database, const char* who, const char* cred);

DESCRIPCIÓN

odbx_bind() asocia una conexión creada por odbx_init() a una base de datos específica después de que el servidor verificara y aceptara las credenciales del usuario. Todas las operaciones posteriores (normalmente) solo afectarán a las tablas y registros dentro de esta base de datos. Las operaciones pueden limitarse a un subconjunto determinado según los privilegios otorgados a la cuenta de usuario dada. Si la vinculación a la instancia de la base de datos tuvo éxito, odbx_bind() también habilita la compatibilidad con el estándar ANSI SQL si esto es posible para la implementación del servidor de base de datos.

odbx_bind_simple() realiza las mismas tareas que odbx_bind() pero no puede hacer nada más que la autenticación simple de nombre de usuario / contraseña. No debe usarse en aplicaciones que enlacen con la biblioteca OpenDBX versión 1.1.1 o posterior y será eliminada de la biblioteca en una etapa posterior.

Ambas funciones aceptan casi los mismos parámetros. El parámetro handle siempre debe ser un puntero a un objeto de conexión válido asignado por odbx_init(). La disponibilidad de ciertas opciones o el comportamiento de la conexión asociada al puntero odbx_t dado se puede consultar llamando a odbx_get_option() o cambiar llamando a odbx_set_option(). Los cambios deben realizarse antes de llamar a odbx_bind() para que surtan efecto. Ejemplos de opciones son la seguridad de hilos de la biblioteca cliente de base de datos nativa o el soporte para enviar múltiples sentencias a la vez.

database es necesario para que el servidor de base de datos sepa qué base de datos se utilizará para ejecutar todas las solicitudes futuras. En combinación con los parámetros de autenticación who y cred, generalmente permite o deniega operaciones en tablas y registros dentro de esta base de datos. Por el contrario, SQLite no utiliza who y cred, sino que depende de los permisos del sistema de archivos para otorgar acceso a todo el archivo de la base de datos. Si se utilizan, los valores proporcionados para los tres parámetros deben ser cadenas terminadas en cero y deben estar exactamente en mayúsculas y minúsculas como las almacena el gestor de base de datos. De lo contrario, si no se utilizan, también pueden ser NULL. Algunas bibliotecas de base de datos también admiten valores predeterminados proporcionados por un archivo de configuración si un parámetro es NULL.

method especifica el mecanismo para autenticar una cuenta de usuario antes de que pueda realizar operaciones en tablas y registros. Actualmente, todos los módulos de backend de base de datos solo admiten el método ODBX_BIND_SIMPLE, que proporciona autenticación básica de nombre de usuario / contraseña. En este caso, el parámetro who debe ser el nombre de una cuenta de usuario, mientras que cred debe ser la contraseña que pertenece a la cuenta dada.

Un objeto de conexión ya asociado puede desvincularse de la base de datos y volver a vincularse al mismo servidor de base de datos. Es posible vincularlo a otra base de datos, con otra cuenta de usuario y otras opciones establecidas desvinculando primero el objeto de conexión con odbx_unbind() antes de invocar odbx_bind() nuevamente con los mismos o diferentes parámetros.

VALOR DE RETORNO

odbx_init() devuelve ODBX_ERR_SUCCESS, o un código de error cuyo valor es menor que cero si alguna de las operaciones no pudo completarse exitosamente. Los códigos de error posibles se enumeran en la sección de errores y pueden alimentarse a odbx_error() y odbx_error_type() para obtener más detalles.

ERRORES

-ODBX_ERR_BACKEND
El módulo backend devolvió un error porque no pudo conectarse a la base de datos o la autenticación utilizando los parámetros proporcionados falló
-ODBX_ERR_PARAM
Uno de los parámetros proporcionados es inválido o es NULL y esto no está permitido en el módulo backend utilizado o en la biblioteca cliente de base de datos nativa
-ODBX_ERR_NOMEM
La asignación de memoria adicional requerida falló
-ODBX_ERR_SIZE
La longitud de una cadena superó el tamaño del búfer disponible
-ODBX_ERR_NOTSUP
El método de autenticación proporcionado no es compatible con el módulo backend
