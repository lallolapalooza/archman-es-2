DESCRIPCIÓN

objdump muestra información sobre uno o más archivos objeto. Las opciones controlan qué información específica se muestra. Esta información es principalmente útil para programadores que trabajan en las herramientas de compilación, en contraposición a los programadores que solo quieren que su programa compile y funcione.

archivo_objeto... son los archivos objeto a examinar. Cuando se especifican archivos de biblioteca (archives), objdump muestra información sobre cada uno de los miembros del archivo de biblioteca.

OPCIONES

Las formas largas y cortas de las opciones, que se muestran aquí como alternativas, son equivalentes. Se debe proporcionar al menos una opción de la lista -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x.

-a
--archive-headers
Si alguno de los archivos archivo_objeto son archivos de biblioteca, muestra la información de la cabecera del archivo de biblioteca (en un formato similar a ls -l). Además de la información que podrías listar con ar tv, objdump -a muestra el formato del archivo objeto de cada miembro del archivo de biblioteca.
--adjust-vma=offset
Al mostrar información, primero suma offset a todas las direcciones de las secciones. Esto es útil si las direcciones de las secciones no corresponden a la tabla de símbolos, lo que puede ocurrir al colocar secciones en direcciones particulares cuando se utiliza un formato que no puede representar direcciones de sección, como a.out.
-b nombre_bfd
--target=nombre_bfd
Especifica que el formato del código objeto para los archivos objeto es nombre_bfd. Es posible que esta opción no sea necesaria; objdump puede reconocer muchos formatos automáticamente.

Por ejemplo,

objdump -b oasys -m vax -h fu.o

muestra información resumida de las cabeceras de sección (-h) de fu.o, que se identifica explícitamente (-m) como un archivo objeto VAX en el formato producido por los compiladores Oasys. Puedes listar los formatos disponibles con la opción -i.

-C
--demangle[=estilo]
Decodifica (demangle) los nombres de símbolos de bajo nivel en nombres de nivel de usuario. Además de eliminar el guion bajo inicial añadido por el sistema, esto hace que los nombres de funciones C++ sean legibles. Diferentes compiladores tienen diferentes estilos de mangling. El argumento opcional de estilo de demangling puede usarse para elegir un estilo de demangling apropiado para tu compilador.
--recursion-limit
--no-recursion-limit
Habilita o deshabilita un límite en la cantidad de recursión realizada al demanglar cadenas. Dado que los formatos de mangling de nombres permiten un nivel infinito de recursión, es posible crear cadenas cuya decodificación agote la cantidad de espacio de pila disponible en la máquina anfitriona, provocando un fallo de memoria. El límite intenta evitar que esto suceda restringiendo la recursión a 2048 niveles de anidación.

Por defecto, este límite está habilitado, pero deshabilitarlo puede ser necesario para demanglar nombres verdaderamente complicados. Ten en cuenta, sin embargo, que si el límite de recursión está deshabilitado, es posible la agotamiento de pila y cualquier informe de error sobre tal evento será rechazado.

-g
--debugging
Muestra información de depuración. Esto intenta analizar la información del formato de depuración STABS almacenada en el archivo y la imprime usando una sintaxis similar a C. Si no se encontró depuración STABS, esta opción recurre a la opción -W para imprimir cualquier información DWARF en el archivo.
-e
--debugging-tags
Similar a -g, pero la información se genera en un formato compatible con la herramienta ctags.
-d
--disassemble
--disassemble=símbolo
Muestra los mnemónicos del ensamblador para las instrucciones de máquina del archivo de entrada. Esta opción solo desensambla las secciones que se espera que contengan instrucciones. Si se proporciona el argumento opcional símbolo (quizás varias veces), entonces muestra los mnemónicos del ensamblador comenzando en (todos los) símbolo. Si símbolo es un nombre de función, el desensamblado se detendrá al final de la función, de lo contrario se detendrá cuando se encuentre el siguiente símbolo. Si no hay coincidencias para ningún símbolo, no se mostrará nada.

Nota: si la opción --dwarf=follow-links está habilitada, entonces se leerán las tablas de símbolos en archivos de información de depuración enlazados y se utilizarán al desensamblar.

-D
--disassemble-all
Muestra los mnemónicos del ensamblador para todas las instrucciones de máquina en el archivo de entrada. Esto desensambla todas las secciones que contienen código ejecutable.

La opción -d solo desensambla las secciones que el formato del archivo objeto considera que contienen código, como la sección `.text`.

-EB
--endian={big | little }
Especifica que el código objeto está codificado en orden de bytes big-endian o little-endian. Esto anula el orden de bytes predeterminado para el tipo de archivo que se está examinando.
-EL
Especifica que el código objeto está codificado en orden de bytes little-endian.
-f
--file-headers
Muestra información de la cabecera del archivo objeto. Esto incluye el formato del archivo, la arquitectura y el tipo de máquina.
-F
--file-offsets
Muestra las ubicaciones de los archivos de datos que se encuentran dentro del archivo de entrada. Esto es útil para encontrar datos de depuración o información de DWARF.
--file-start-context
Similar a --file-offsets, pero muestra solo la información de contexto del inicio del archivo.
-h
--section-headers
--headers
Muestra la tabla de cabeceras de sección. Esto incluye el nombre, tamaño, dirección y atributos de cada sección en el archivo objeto.
-i
--info
Lista los formatos de archivos objeto que BFD (la biblioteca que utiliza objdump) conoce, y las arquitecturas para las que BFD tiene soporte. Esto es útil para determinar qué nombre_bfd o máquina se puede usar con las opciones -b y -m.
-j sección
--section=sección
Muestra solo la información de la sección especificada. Puedes usar esta opción varias veces para especificar múltiples secciones. Si se utilizan opciones de desensamblado, esta opción restringe la visualización a las instrucciones dentro de la sección especificada.
-l
--line-numbers
Mapea las direcciones de las instrucciones a los nombres de archivo y números de línea correspondientes. Esto requiere que la información de depuración esté presente en el archivo objeto. Se puede combinar con -d o -D para mostrar números de línea junto con el código desensamblado.
-S
--source
Intenta mostrar el código fuente correspondiente a las instrucciones desensambladas. Esto requiere que la información de depuración con información de línea de comandos esté presente en el archivo objeto. Si se combina con -d o -D, muestra el código fuente en lugar de las instrucciones del ensamblador. Si no se puede encontrar el código fuente, se muestra un mensaje de error.
--source-comment=texto
Establece el texto del comentario para las líneas de código fuente que se muestran cuando se usa la opción -S.
-m máquina
--architecture=máquina
Especifica la arquitectura de la máquina para el archivo objeto. Esto es útil cuando el archivo objeto puede ser de una arquitectura que no es la del sistema en el que se está ejecutando objdump, o cuando el formato del archivo no permite determinar la arquitectura. Puedes listar las arquitecturas disponibles con la opción -i.
-M opciones
--disassembler-options=opciones
Pasa opciones específicas al desensamblador. El formato y las opciones disponibles dependen del desensamblador que se esté utilizando.
-p
--private-headers
Muestra cualquier cabecera privada específica del formato de archivo que no se muestra con otras opciones. Esto puede incluir información específica de DWARF, CTF o STABS.
-P opciones
--private=opciones
Muestra información privada específica del formato de archivo, similar a -p, pero con la capacidad de especificar qué tipos de información privada mostrar.
-r
--reloc
Muestra la tabla de reubicaciones del archivo objeto. Esto incluye la información sobre cómo se deben ajustar las direcciones de los símbolos cuando el código se enlaza o se carga en memoria.
-R
--dynamic-reloc
Muestra la tabla de reubicaciones dinámicas. Esto es relevante para los archivos objeto que se enlazarán dinámicamente.
-s
--full-contents
Muestra el contenido completo de todas las secciones del archivo objeto. Esto puede ser útil para examinar datos o código en formato binario.
-Z
--decompress
Intenta descomprimir cualquier sección comprimida dentro del archivo objeto antes de mostrarla. Esto es útil para archivos que utilizan compresión de sección.
-W[lLiaprmfFsoORtUuTgAck]
--dwarf[=rawline,=decodedline,=info,=abbrev,=pubnames,=aranges,=macro,=frames,=frames-interp,=str,=str-offsets,=loc,=Ranges,=pubtypes,=trace_info,=trace_abbrev,=trace_aranges,=gdb_index,=addr,=cu_index,=links]
Muestra información de depuración en formato DWARF. Se pueden especificar varias subopciones para controlar qué partes de la información DWARF se muestran. Por ejemplo, -Wl muestra información de línea rawline, mientras que -Wf muestra información de frames (pila).
-WK
--dwarf=follow-links
Cuando se procesa información DWARF, sigue los enlaces a otras unidades de compilación o archivos de depuración.
-WN
--dwarf=no-follow-links
Evita seguir enlaces a otras unidades de compilación o archivos de depuración al procesar información DWARF.
-wD
--dwarf=use-debuginfod
Utiliza el servicio debuginfod para obtener información DWARF faltante.
-wE
--dwarf=do-not-use-debuginfod
No utiliza el servicio debuginfod para obtener información DWARF.
-L
--process-links
Procesa enlaces simbólicos y otras referencias a archivos externos al mostrar información DWARF.
--ctf=sección
Muestra información del formato CTF (Compact Type Format) de la sección especificada.
--sframe=sección
Muestra información de frames (pila) del formato CTF de la sección especificada.
-G
--stabs
Muestra información de depuración en formato STABS. Esto es un formato más antiguo de información de depuración que todavía se utiliza en algunos sistemas.
-t
--syms
Muestra la tabla de símbolos del archivo objeto. Esto incluye los nombres de los símbolos, sus direcciones y tipos.
-T
--dynamic-syms
Muestra la tabla de símbolos dinámicos. Esto es relevante para los archivos objeto que se enlazarán dinámicamente.
-x
--all-headers
Muestra todas las cabeceras disponibles para el formato de archivo especificado. Esto es equivalente a usar todas las opciones de cabecera disponibles.
-w
--wide
Formatea la salida para que quepa en una pantalla ancha (80 columnas o más). Esto es útil cuando la salida es muy extensa y se corta en pantallas más estrechas.
--start-address=dirección
Comienza a mostrar información desde la dirección especificada. Esto se puede usar para limitar la salida a una parte específica del archivo objeto.
--stop-address=dirección
Deja de mostrar información en la dirección especificada. Se puede usar en combinación con --start-address para especificar un rango de direcciones.
--no-addresses
No muestra las direcciones de las instrucciones desensambladas.
--prefix-addresses
Prefija las direcciones mostradas con el nombre de la sección a la que pertenecen.
--show-raw-insn
Muestra las instrucciones de máquina en formato hexadecimal junto con el código desensamblado.
--no-show-raw-insn
No muestra las instrucciones de máquina en formato hexadecimal.
--adjust-vma=offset
Ajusta las direcciones virtuales de las secciones sumando el valor de offset. Esto puede ser útil si el archivo objeto se ha cargado en una dirección diferente a la que se compiló.
--show-all-symbols
Muestra todos los símbolos, incluidos los símbolos no exportados o privados.
--dwarf-depth=n
Limita la profundidad de anidamiento al procesar información DWARF. n es el número máximo de niveles de anidamiento.
--dwarf-start=n
Comienza a procesar información DWARF desde la entrada de índice n.
--ctf-parent=sección
Especifica la sección de "padre" para la información CTF. Esto se usa para enlaces entre diferentes estructuras de tipo.
--no-recurse-limit
Deshabilita el límite de recursión al decodificar nombres demanglados. Ver la descripción de --recursion-limit.
--recurse-limit
Habilita el límite de recursión al decodificar nombres demanglados. Ver la descripción de --recursion-limit.
--special-syms
Muestra símbolos especiales que son utilizados por el enlazador o el sistema operativo.
--prefix=prefijo
Añade un prefijo a todos los nombres de archivo mostrados.
--prefix-strip=nivel
Elimina un número especificado de componentes de directorio del prefijo de los nombres de archivo mostrados.
--insn-width=ancho
Establece el ancho de las instrucciones de máquina mostradas en columnas. Esto afecta cómo se formatea la salida del desensamblador.
--visualize-jumps[=color|=extended-color|=off]
Visualiza los saltos (jumps) en el código desensamblado. Se pueden usar opciones de color para resaltar los saltos.
--disassembler-color=[off|terminal|on|extended]
Controla el uso de colores en la salida del desensamblador. Las opciones off, terminal (color básico), on (color estándar) y extended (color avanzado) están disponibles.
-U método
--unicode=método
Especifica el método para manejar caracteres Unicode en la salida. Esto es útil si el código objeto contiene cadenas o identificadores en Unicode.
-V
--version
Muestra la información de la versión de objdump y sale.
-H
--help
Muestra un mensaje de ayuda y sale.

archivo_objeto...

--disassemble-all
Igual que -d, pero desensambla el contenido de todas las secciones no vacías que no son bss, no solo aquellas que se espera que contengan instrucciones. Se puede usar -j para seleccionar secciones específicas.

Esta opción también tiene un efecto sutil en el desensamblado de instrucciones en secciones de código. Cuando la opción -d está activa, objdump asumirá que cualquier símbolo presente en una sección de código ocurre en el límite entre instrucciones y se negará a desensamblar a través de dicho límite. Sin embargo, cuando la opción -D está activa, esta suposición se suprime. Esto significa que la salida de -d y -D puede diferir si, por ejemplo, los datos se almacenan en secciones de código.

Si el objetivo es una arquitectura ARM, este interruptor también tiene el efecto de forzar al desensamblador a decodificar fragmentos de datos encontrados en secciones de código como si fueran instrucciones.

Tenga en cuenta que si la opción --dwarf=follow-links está habilitada, entonces se leerán las tablas de símbolos en archivos de información de depuración enlazados y se utilizarán al desensamblar.

--no-addresses
Al desensamblar, no imprima direcciones en cada línea ni para símbolos y desplazamientos de reubicación. En combinación con --no-show-raw-insn esto puede ser útil para comparar la salida del compilador.
--prefix-addresses
Al desensamblar, imprima la dirección completa en cada línea. Este es el formato de desensamblado más antiguo.
-EB
-EL
--endian={big|little}
Especifique la distribución de bytes (endianness) de los archivos objeto. Esto solo afecta al desensamblado. Puede ser útil al desensamblar un formato de archivo que no describe la información de distribución de bytes, como los S-records.
-f
--file-headers
Muestre información resumida de la cabecera general de cada uno de los archivos objfile.
-F
--file-offsets
Al desensamblar secciones, cada vez que se muestre un símbolo, muestre también el desplazamiento del archivo de la región de datos que se va a volcar. Si se están omitiendo ceros, entonces cuando se reanude el desensamblado, informe al usuario cuántos ceros se omitieron y el desplazamiento del archivo de la ubicación desde donde se reanuda el desensamblado. Al volcar secciones, muestre el desplazamiento del archivo de la ubicación desde donde comienza el volcado.
--file-start-context
Especifique que al mostrar el código fuente/desensamblado intercalado (asume -S) de un archivo que aún no se ha mostrado, se extienda el contexto hasta el inicio del archivo.
-h
--section-headers
--headers
Muestre información resumida de las cabeceras de sección del archivo objeto.

Los segmentos de archivo pueden ser reubicados a direcciones no estándar, por ejemplo, utilizando las opciones -Ttext, -Tdata o -Tbss para ld. Sin embargo, algunos formatos de archivo objeto, como a.out, no almacenan la dirección de inicio de los segmentos de archivo. En esas situaciones, aunque ld reubica las secciones correctamente, usar objdump -h para listar las cabeceras de sección del archivo no puede mostrar las direcciones correctas. En su lugar, muestra las direcciones habituales, que son implícitas para el objetivo.

Tenga en cuenta que, en algunos casos, es posible que una sección tenga establecidos los atributos READONLY y NOREAD. En tales casos, el atributo NOREAD tiene prioridad, pero objdump informará ambos ya que la configuración exacta de los bits de la bandera podría ser importante.

-H
--help
Imprima un resumen de las opciones de objdump y salga.
-i
--info
Muestre una lista que muestre todas las arquitecturas y formatos de objeto disponibles para especificar con -b o -m.
-j name
--section=nombre
Muestre información para la sección nombre. Esta opción se puede especificar varias veces.
-L
--process-links
Muestre el contenido de las secciones no de depuración que se encuentran en archivos de información de depuración separados que están enlazados al archivo principal. Esta opción implica automáticamente la opción -WK, y solo se mostrarán las secciones solicitadas por otras opciones de línea de comandos.
-l
--line-numbers
Etiquete la visualización (usando información de depuración) con el nombre del archivo y los números de línea de origen correspondientes al código objeto o las reubicaciones mostradas. Solo es útil con -d, -D o -r.
-m máquina
--architecture=máquina
Especifique la arquitectura a utilizar al desensamblar archivos objeto. Esto puede ser útil al desensamblar archivos objeto que no describen información de arquitectura, como los S-records. Puede listar las arquitecturas disponibles con la opción -i.

Para la mayoría de las arquitecturas es posible proporcionar un nombre de arquitectura y un nombre de máquina, separados por dos puntos. Por ejemplo, foo:bar se referiría al tipo de máquina bar en la arquitectura foo. Esto puede ser útil si objdump ha sido configurado para soportar múltiples arquitecturas.

Si el objetivo es una arquitectura ARM, este interruptor tiene un efecto adicional. Restringe el desensamblado solo a aquellas instrucciones compatibles con la arquitectura especificada por máquina. Si es necesario usar este interruptor porque el archivo de entrada no contiene información de arquitectura, pero también se desea desensamblar todas las instrucciones, use -marm.

-M opciones
--disassembler-options=opciones
Pase información específica del objetivo al desensamblador. Solo se admite en algunos objetivos. Si es necesario especificar más de una opción del desensamblador, se pueden usar múltiples opciones -M o se pueden agrupar en una lista separada por comas.

Para ARC, dsp controla la impresión de instrucciones DSP, spfp selecciona la impresión de instrucciones FP de precisión simple FPX, dpfp selecciona la impresión de instrucciones FP de precisión doble FPX, quarkse_em selecciona la impresión de instrucciones especiales QuarkSE-EM, fpuda selecciona la impresión de instrucciones de asistencia de punto flotante de doble precisión, fpus selecciona la impresión de instrucciones FP de precisión simple FPU, mientras que fpud selecciona la impresión de instrucciones FP de doble precisión FPU. Además, se puede elegir que todos los inmediatos se impriman en hexadecimal usando hex. Por defecto, los inmediatos cortos se imprimen usando la representación decimal, mientras que los valores inmediatos largos se imprimen en hexadecimal.

cpu=... permite forzar una ISA particular al desensamblar instrucciones, anulando el valor de -m o lo que sea que haya en el archivo ELF. Esto podría ser útil para seleccionar la ISA ARC EM o HS, ya que la arquitectura es la misma para ambas y el desensamblador depende de datos privados de la cabecera ELF para decidir si el código es para EM o HS. Esta opción podría especificarse varias veces; solo se usará el último valor. Los valores válidos son los mismos que para la opción -mcpu=... del ensamblador.

Si el objetivo es una arquitectura ARM, este interruptor se puede utilizar para seleccionar qué conjunto de nombres de registros se utiliza durante el desensamblado. Especificar -M reg-names-std (el valor predeterminado) seleccionará los nombres de registros como se usan en la documentación del conjunto de instrucciones de ARM, pero con el registro 13 llamado 'sp', el registro 14 llamado 'lr' y el registro 15 llamado 'pc'. Especificar -M reg-names-apcs seleccionará el conjunto de nombres utilizado por el ARM Procedure Call Standard, mientras que especificar -M reg-names-raw simplemente usará r seguido del número de registro.

Hay también dos variantes del esquema de nombres de registros APCS habilitadas por -M reg-names-atpcs y -M reg-names-special-atpcs que utilizan las convenciones de nombres del estándar de llamada de procedimientos ARM/Thumb. (Ya sea con los nombres de registros normales o los nombres de registros especiales).

Esta opción también se puede utilizar para arquitecturas ARM para forzar al desensamblador a interpretar todas las instrucciones como instrucciones Thumb utilizando el interruptor --disassembler-options=force-thumb. Esto puede ser útil al intentar desensamblar código Thumb producido por otros compiladores.

--syms
Imprime las entradas de la tabla de símbolos del archivo. Esto es similar a la información proporcionada por el programa nm, aunque el formato de visualización es diferente. El formato de la salida depende del formato del archivo que se está volcando, pero hay dos tipos principales. Uno se ve así: 
[  4](sec  3)(fl 0x00)(ty   0)(scl   3) (nx 1) 0x00000000 .bss
[  6](sec  1)(fl 0x00)(ty   0)(scl   2) (nx 0) 0x00000000 fred

donde el número dentro de los corchetes es el número de la entrada en la tabla de símbolos, el número sec es el número de sección, el valor fl son los bits de bandera del símbolo, el número ty es el tipo del símbolo, el número scl es la clase de almacenamiento del símbolo y el valor nx es el número de entradas auxiliares asociadas con el símbolo. Los dos últimos campos son el valor del símbolo y su nombre.

El otro formato de salida común, que generalmente se ve con archivos basados en ELF, se ve así:

00000000 l    d  .bss   00000000 .bss
00000000 g       .text  00000000 fred

Aquí el primer número es el valor del símbolo (a veces denominado su dirección). El siguiente campo es en realidad un conjunto de caracteres y espacios que indican los bits de bandera que están activados en el símbolo. Estos caracteres se describen a continuación. A continuación, se encuentra la sección con la que está asociado el símbolo o *ABS* si la sección es absoluta (es decir, no está conectada con ninguna sección), o *UND* si la sección se referencia en el archivo que se está volcando, pero no se define allí.

Después del nombre de la sección viene otro campo, un número, que para símbolos comunes es la alineación y para otros símbolos es el tamaño. Finalmente, se muestra el nombre del símbolo.

Los caracteres de bandera se dividen en 7 grupos como sigue:

"l"
"g"
"u"
"!"
El símbolo es local (l), global (g), global único (u), ni global ni local (un espacio) o tanto global como local (!). Un símbolo puede no ser ni local ni global por una variedad de razones, por ejemplo, porque se usa para depuración, pero probablemente sea una indicación de un error si alguna vez es tanto local como global. Los símbolos globales únicos son una extensión de GNU al conjunto estándar de enlaces de símbolos ELF. Para un símbolo de este tipo, el enlazador dinámico se asegurará de que en todo el proceso solo haya un símbolo con este nombre y tipo en uso.
"w"
El símbolo es débil (w) o fuerte (un espacio).
"C"
El símbolo denota un constructor (C) o un símbolo ordinario (un espacio).
"W"
El símbolo es una advertencia (W) o un símbolo normal (un espacio). El nombre de un símbolo de advertencia es un mensaje que se mostrará si el símbolo que sigue al símbolo de advertencia se referencia alguna vez.
"I"
"i"
El símbolo es una referencia indirecta a otro símbolo (I), una función que se evaluará durante el procesamiento de relocalización (i) o un símbolo normal (un espacio).
"d"
"D"
El símbolo es un símbolo de depuración (d) o un símbolo dinámico (D) o un símbolo normal (un espacio).
"F"
"f"
"O"
El símbolo es el nombre de una función (F) o un archivo (f) o un objeto (O) o simplemente un símbolo normal (un espacio).

Imprime las entradas de la tabla de símbolos dinámicos del archivo. Esto solo es significativo para objetos dinámicos, como ciertos tipos de bibliotecas compartidas. Esto es similar a la información proporcionada por el programa nm cuando se le da la opción -D (--dynamic).

El formato de salida es similar al producido por la opción --syms, excepto que se inserta un campo adicional antes del nombre del símbolo, que proporciona la información de versión asociada con el símbolo. Si la versión es la versión predeterminada que se utilizará al resolver referencias sin versión al símbolo, entonces se muestra tal cual, de lo contrario se coloca entre paréntesis.

--special-syms
Al mostrar símbolos, incluye aquellos que el destino considera especiales de alguna manera y que normalmente no serían de interés para el usuario.
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Controla la visualización de caracteres multibyte codificados en UTF-8 en cadenas. El valor predeterminado (--unicode=default) es no darles ningún tratamiento especial. La opción --unicode=locale muestra la secuencia en la configuración regional actual, que puede o no soportarla. Las opciones --unicode=hex y --unicode=invalid las muestran como secuencias de bytes hexadecimales encerradas entre corchetes angulares o llaves.

La opción --unicode=escape las muestra como secuencias de escape (\uxxxx) y la opción --unicode=highlight las muestra como secuencias de escape resaltadas en rojo (si el dispositivo de salida lo soporta). El coloreado está destinado a llamar la atención sobre la presencia de secuencias unicode donde no se esperarían.

-V
--version
Imprime el número de versión de objdump y sale.
-x
--all-headers
Muestra toda la información de encabezado disponible, incluida la tabla de símbolos y las entradas de relocalización. Usar -x es equivalente a especificar todas las opciones -a -f -h -p -r -t.
-w
--wide
Formatea algunas líneas para dispositivos de salida que tienen más de 80 columnas. Tampoco trunca los nombres de los símbolos cuando se muestran.
-z
--disassemble-zeroes
Normalmente, la salida de desensamblado omitirá bloques de ceros. Esta opción indica al desensamblador que desensamble esos bloques, al igual que cualquier otro dato.
-Z
--decompress
La opción -Z está pensada para ser utilizada junto con la opción -s. Instruye a objdump para descomprimir cualquier sección comprimida antes de mostrar su contenido.
@archivo
Lee las opciones de la línea de comandos de archivo. Las opciones leídas se insertan en lugar de la opción @archivo original. Si archivo no existe o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter de espacio en blanco puede incluirse en una opción rodeando la opción completa entre comillas simples o dobles. Cualquier carácter (incluido una barra invertida) puede incluirse precediendo el carácter a incluir con una barra invertida. El archivo puede contener opciones adicionales @archivo; tales opciones se procesarán recursivamente.
