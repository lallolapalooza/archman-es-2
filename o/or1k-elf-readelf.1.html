NOMBRE

readelf - muestra información sobre archivos ELF

SINOPSIS

[-h|--file-header]
[-l|--program-headers|--segments]
[-S|--section-headers|--sections]
[-g|--section-groups]
[-t|--section-details]
[-e|--headers]
[-s|--syms|--symbols]
[--dyn-syms|--lto-syms]
[--sym-base=[0|8|10|16]]
[--demangle=estilo|--no-demangle]
[--quiet]
[--recurse-limit|--no-recurse-limit]
[-U método|--unicode=método]
[-X|--extra-sym-info|--no-extra-sym-info]
[-n|--notes]
[-r|--relocs]
[-u|--unwind]
[-d|--dynamic]
[-V|--version-info]
[-A|--arch-specific]
[-D|--use-dynamic]
[-L|--lint|--enable-checks]
[-x <número o nombre>|--hex-dump=<número o nombre>]
[-p <número o nombre>|--string-dump=<número o nombre>]

[-z|--decompress]
[-c|--archive-index]

DESCRIPCIÓN

readelf muestra información sobre uno o más archivos objeto con formato ELF. Las opciones controlan qué información particular se debe mostrar.

archivoelf... son los archivos objeto a examinar. Se admiten archivos ELF de 32 y 64 bits, así como archivos que contienen archivos ELF.

Este programa realiza una función similar a objdump pero entra en más detalles y existe independientemente de la biblioteca BFD, por lo que si hay un error en BFD, readelf no se verá afectado.

OPCIONES

Las formas largas y cortas de las opciones, mostradas aquí como alternativas, son equivalentes. Se debe dar al menos una opción además de -v o -H.

-a
--all
Equivalente a especificar --file-header, --program-headers, --sections, --symbols, --relocs, --dynamic, --notes, --version-info, --arch-specific, --unwind, --section-groups y --histogram.

Nota: esta opción no habilita --use-dynamic en sí misma, por lo que si esa opción no está presente en la línea de comandos, los símbolos dinámicos y las relocalizaciones dinámicas no se mostrarán.

-h
--file-header
Muestra la información contenida en la cabecera ELF al inicio del archivo.
-l
--program-headers
--segments
Muestra la información contenida en las cabeceras de segmento del archivo, si las tiene.
--quiet
Suprime el diagnóstico de "no symbols".
-S
--sections
--section-headers
Muestra la información contenida en las cabeceras de sección del archivo, si las tiene.
-g
--section-groups
Muestra la información contenida en los grupos de secciones del archivo, si los tiene.
-t
--section-details
Muestra la información detallada de la sección. Implica -S.
-s
--symbols
--syms
Muestra las entradas en la sección de tabla de símbolos del archivo, si la tiene. Si un símbolo tiene información de versión asociada, esta se muestra también. La cadena de versión se muestra como un sufijo del nombre del símbolo, precedido por un carácter @. Por ejemplo foo@VER_1. Si la versión es la versión predeterminada a usar al resolver referencias no versionadas al símbolo, se muestra como un sufijo precedido por dos caracteres @. Por ejemplo foo@@VER_2.
--dyn-syms
Muestra las entradas en la sección de tabla de símbolos dinámicos del archivo, si la tiene. El formato de salida es el mismo que el formato usado por la opción --syms.
--lto-syms
Muestra el contenido de cualquier tabla de símbolos LTO en el archivo.
--sym-base=[0|8|10|16]
Fuerza que el campo de tamaño de la tabla de símbolos utilice la base dada. Cualquier opción no reconocida se tratará como 0. --sym-base=0 representa el comportamiento predeterminado y heredado. Esto mostrará los tamaños como decimal para números menores de 100000. Para tamaños de 100000 y mayores se usará notación hexadecimal con prefijo 0x. --sym-base=8 dará los tamaños de símbolo en octal. --sym-base=10 siempre dará los tamaños de símbolo en decimal. --sym-base=16 siempre dará los tamaños de símbolo en hexadecimal con prefijo 0x.
-C
--demangle[=estilo]
Decodifica (demangle) nombres de símbolos de bajo nivel en nombres de nivel de usuario. Esto hace que los nombres de funciones C++ sean legibles. Diferentes compiladores tienen diferentes estilos de mangling. El argumento opcional de estilo de demangling se puede usar para elegir un estilo de demangling apropiado para su compilador.
--no-demangle
No decodificar nombres de símbolos de bajo nivel. Este es el valor predeterminado.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Habilita o deshabilita un límite en la cantidad de recursión realizada al decodificar cadenas. Dado que los formatos de mangling de nombres permiten un nivel infinito de recursión, es posible crear cadenas cuya decodificación agote el espacio de pila disponible en la máquina anfitriona, provocando un fallo de memoria. El límite intenta evitar que esto suceda restringiendo la recursión a 2048 niveles de anidamiento.

El valor predeterminado es que este límite esté habilitado, pero deshabilitarlo puede ser necesario para decodificar nombres verdaderamente complicados. Tenga en cuenta, sin embargo, que si el límite de recursión está deshabilitado, es posible el agotamiento de la pila y cualquier informe de error sobre tal evento será rechazado.

OPTIONS

--debug-dump=section
Dump the specified debug section. Supported values for section are irregulars, which can be specified in multiple ways:
--debug-dump=rawline
Displays the contents of the .debug_line section in a raw format.
--debug-dump=L
--debug-dump=decodedline
Displays the interpreted contents of the .debug_line section.
--debug-dump=m
--debug-dump=macro
Displays the contents of the .debug_macro and/or .debug_macinfo sections.
--debug-dump=o
--debug-dump=loc
Displays the contents of the .debug_loc and/or .debug_loclists sections.
--debug-dump=O
--debug-dump=str-offsets
Displays the contents of the .debug_str_offsets section.
--debug-dump=p
--debug-dump=pubnames
Displays the contents of the .debug_pubnames and/or .debug_gnu_pubnames sections.
--debug-dump=r
--debug-dump=aranges
Displays the contents of the .debug_aranges section.
--debug-dump=R
--debug-dump=Ranges
Displays the contents of the .debug_ranges and/or .debug_rnglists sections.
--debug-dump=s
--debug-dump=str
Displays the contents of the .debug_str, .debug_line_str and/or .debug_str_offsets sections.
--debug-dump=t
--debug-dump=pubtype
Displays the contents of the .debug_pubtypes and/or .debug_gnu_pubtypes sections.
--debug-dump=T
--debug-dump=trace_aranges
Displays the contents of the .trace_aranges section.
--debug-dump=u
--debug-dump=trace_abbrev
Displays the contents of the .trace_abbrev section.
--debug-dump=U
--debug-dump=trace_info
Displays the contents of the .trace_info section.

Note: displaying the contents of .debug_static_funcs, .debug_static_vars and debug_weaknames sections is not currently supported.

--dwarf-depth=n
Limit the dump of the ".debug_info" section to n children. This is only useful with --debug-dump=info. The default is to print all DIEs; the special value 0 for n will also have this effect.

With a non-zero value for n, DIEs at or deeper than n levels will not be printed. The range for n is zero-based.

--dwarf-start=n
Print only DIEs beginning with the DIE numbered n. This is only useful with --debug-dump=info.

If specified, this option will suppress printing of any header information and all DIEs before the DIE numbered n. Only siblings and children of the specified DIE will be printed.

This can be used in conjunction with --dwarf-depth.

-P
--process-links
Display the contents of non-debug sections found in separate debuginfo files that are linked to the main file. This option automatically implies the -wK option, and only sections requested by other command line options will be displayed.
--ctf[=section]
Display the contents of the specified CTF section. CTF sections themselves contain many subsections, all of which are displayed in order.

By default, display the name of the section named .ctf, which is the name emitted by ld.

--ctf-parent=member
If the CTF section contains ambiguously-defined types, it will consist of an archive of many CTF dictionaries, all inheriting from one dictionary containing unambiguous types. This member is by default named .ctf, like the section containing it, but it is possible to change this name using the "ctf_link_set_memb_name_changer" function at link time. When looking at CTF archives that have been created by a linker that uses the name changer to rename the parent archive member, --ctf-parent can be used to specify the name used for the parent.
--ctf-symbols=section
--ctf-strings=section
Specify the name of another section from which the CTF file can inherit strings and symbols. By default, the ".symtab" and its linked string table are used.

If either of --ctf-symbols or --ctf-strings is specified, the other must be specified as well.

-I
--histogram
Display a histogram of bucket list lengths when displaying the contents of the symbol tables.
-v
--version
Display the version number of readelf.
-W
--wide
Don't break output lines to fit into 80 columns. By default readelf breaks section header and segment listing lines for 64-bit ELF files, so that they fit into 80 columns. This option causes readelf to print each section header resp. each segment one a single line, which is far more readable on terminals wider than 80 columns.
-T
--silent-truncation
Normally when readelf is displaying a symbol name, and it has to truncate the name to fit into an 80 column display, it will add a suffix of "[...]" to the name. This command line option disables this behaviour, allowing 5 more characters of the name to be displayed and restoring the old behaviour of readelf (prior to release 2.35).
-H
--help
Display the command-line options understood by readelf.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
