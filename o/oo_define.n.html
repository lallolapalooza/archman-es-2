oo_define(n)

Paquete: tcl

Licencias: TCL

define(n) Comandos de TclOO define(n)

NOMBRE

oo::define, oo::objdefine, oo::Slot - definir y configurar clases y objetos

SINOPSIS

package require TclOO
oo::define clase scriptDefinicion
oo::define clase subcomando arg ?arg ...?
oo::objdefine objeto scriptDefinicion
oo::objdefine objeto subcomando arg ?arg ...?
oo::Slot arg...

JERARQUÍA DE CLASES

oo::object
   → oo::Slot

DESCRIPCIÓN

El comando oo::define se utiliza para controlar la configuración de las clases, y el comando oo::objdefine se utiliza para controlar la configuración de los objetos (incluidas las clases como objetos de instancia), con la configuración aplicada a la entidad nombrada en el argumento clase u objeto. La configuración de una clase también actualiza la configuración de todas las subclases de la clase y de todos los objetos que son instancias de esa clase o que la mezclan (según lo modificado por cualquier configuración por instancia). La forma en que se realiza la configuración se controla mediante el argumento scriptDefinicion o mediante el subcomando y los arg siguientes; cuando este último está presente, es exactamente como si todos los argumentos desde subcomando en adelante se convirtieran en una lista y esa lista se usara como argumento scriptDefinicion.

CONFIGURACIÓN DE CLASES

Los siguientes comandos son compatibles en el scriptDefinicion para oo::define, cada uno de los cuales también puede usarse en la forma de subcomando:

constructor listaArg cuerpoScript
Esto crea o actualiza el constructor para una clase. Los argumentos formales al constructor (definidos utilizando el mismo formato que para el comando Tcl proc) serán listaArg, y el cuerpo del constructor será cuerpoScript. Cuando se evalúa el cuerpo del constructor, el espacio de nombres actual del constructor será un espacio de nombres que es único para el objeto que se está construyendo. Dentro del constructor, el comando next debe usarse para llamar a los constructores de las superclases. Si cuerpoScript es la cadena vacía, el constructor se eliminará.
deletemethod nombre ?nombre ...?
Esto elimina cada uno de los métodos llamados nombre de una clase. Los métodos deben haber existido previamente en esa clase. No afecta a las superclases de la clase, ni afecta a las subclases o instancias de la clase (excepto cuando tienen una cadena de llamada a través de la clase que se está modificando) ni al objeto de clase en sí.
destructor cuerpoScript
Esto crea o actualiza el destructor para una clase. Los destructores no toman argumentos, y el cuerpo del destructor será cuerpoScript. El destructor se llama cuando se eliminan los objetos de la clase, y cuando se llama, tendrá el espacio de nombres único del objeto como espacio de nombres actual. Los destructores deben usar el comando next para llamar a los destructores de las superclases. Tenga en cuenta que los destructores no se llaman en todas las situaciones (por ejemplo, si se destruye el intérprete). Si cuerpoScript es la cadena vacía, el destructor se eliminará.
Tenga en cuenta que los errores durante la evaluación de un destructor no se devuelven al código que causa la destrucción de un objeto. En su lugar, se pasan al manejador bgerror definido actualmente.
exportar nombre ?nombre ...?
Esto organiza para que cada uno de los métodos nombrados, nombre, sea exportado (es decir, utilizable fuera de una instancia a través del comando del objeto de instancia) por la clase que se está definiendo. Tenga en cuenta que los métodos en sí pueden ser definidos por una superclase; las exportaciones de subclase anulan la visibilidad de la superclase, y pueden ser anuladas por las instancias.
filtro ?-operacionRanura? ?nombreMetodo ...?
Esta ranura (ver DEFINICIONES CON RANURAS a continuación) establece o actualiza la lista de nombres de métodos que se utilizan para proteger si las llamadas a métodos a instancias de la clase pueden ser llamadas y cuáles son los resultados del método. Cada nombreMetodo nombra un único método de filtrado (que puede o no ser expuesto); no es un error nombrar un método inexistente, ya que pueden ser definidos por subclases. Por defecto, esta ranura funciona por adición.
reenviar nombre nombreCmd ?arg ...?
Esto crea o actualiza un método reenviado llamado nombre. El método se define para ser reenviado al comando llamado nombreCmd, con argumentos adicionales, arg, etc., añadidos antes de los argumentos especificados por el llamador del método. El nombreCmd siempre se resolverá utilizando las reglas de los espacios de nombres de los objetos involucrados, es decir, cuando nombreCmd no está completamente calificado, el comando se buscará en el espacio de nombres de cada objeto, utilizando la ruta del espacio de nombres de las instancias, o buscando en el espacio de nombres global. El método será exportado si nombre comienza con una letra minúscula, y no exportado de lo contrario.
metodo nombre listaArg cuerpoScript
Esto crea o actualiza un método que se implementa como un script similar a un procedimiento. El nombre del método es nombre, los argumentos formales del método (definidos utilizando el mismo formato que para el comando Tcl proc) serán listaArg, y el cuerpo del método será cuerpoScript. Cuando se evalúa el cuerpo del método, el espacio de nombres actual del método será un espacio de nombres que es único para el objeto actual. El método será exportado si nombre comienza con una letra minúscula, y no exportado de lo contrario; este comportamiento puede ser anulado a través de exportar y noexportar.
mezclar ?-operacionRanura? ?nombreClase ...?
Esta ranura (ver DEFINICIONES CON RANURAS a continuación) establece o actualiza la lista de clases adicionales que se mezclarán en todas las instancias de la clase que se está definiendo. Cada argumento nombreClase nombra una clase que se va a mezclar. Por defecto, esta ranura funciona por reemplazo.
renombrarmetodo nombreDesde nombreHasta
Esto renombra el método llamado nombreDesde en una clase a nombreHasta. El método debe haber existido previamente en la clase, y nombreHasta no debe referirse previamente a un método en esa clase. No afecta a las superclases de la clase, ni afecta a las subclases o instancias de la clase (excepto cuando tienen una cadena de llamada a través de la clase que se está modificando), o al objeto de clase en sí. No cambia el estado de exportación del método; si se exportó antes, se exportará después.
si_mismo subcomando arg ...
si_mismo script
Este comando es equivalente a llamar a oo::objdefine en la clase que se está definiendo (ver CONFIGURACIÓN DE OBJETOS a continuación para una descripción de los valores compatibles de subcomando). Sigue el mismo patrón general de manejo de argumentos que los comandos oo::define y oo::objdefine, y “oo::define cls si_mismo subcomando ...” opera idénticamente a “oo::objdefine cls subcomando ...”.
superclase ?-operacionRanura? ?nombreClase ...?
Esta ranura (ver DEFINICIONES CON RANURAS a continuación) permite la modificación de las superclases de la clase que se está definiendo. Cada argumento nombreClase nombra una clase que será superclase de la clase definida. Tenga en cuenta que los objetos no deben cambiarse de clases a no clases o viceversa, que una clase padre vacía es equivalente a oo::object, y que las clases padre de oo::object y oo::class no pueden modificarse. Por defecto, esta ranura funciona por reemplazo.
noexportar nombre ?nombre ...?
Esto organiza para que cada uno de los métodos nombrados, nombre, no sea exportado (es decir, no utilizable fuera de la instancia a través del comando del objeto de instancia).

CONFIGURACIÓN DE OBJETOS

Los siguientes comandos son compatibles en el scriptDefinicion para oo::objdefine, cada uno de los cuales también puede usarse en la forma de subcomando:

campo nombre valor
Esto crea o actualiza un campo (también conocido como ranura o variable de instancia) llamado nombre, y le asigna el valor especificado. Si el campo ya existía en la clase del objeto o en una de sus superclases, su valor se sobrescribirá en este objeto específico. Si no existía, se creará un nuevo campo para este objeto específico.
metodo nombre listaArg cuerpoScript
Esto crea o actualiza un método para este objeto específico. El nombre del método es nombre, los argumentos formales del método (definidos utilizando el mismo formato que para el comando Tcl proc) serán listaArg, y el cuerpo del método será cuerpoScript. Cuando se evalúa el cuerpo del método, el espacio de nombres actual del método será un espacio de nombres que es único para el objeto actual. El método será exportado si nombre comienza con una letra minúscula, y no exportado de lo contrario; este comportamiento puede ser anulado a través de exportar y noexportar.
noexportar nombre ?nombre ...?
Esto organiza para que cada uno de los métodos nombrados, nombre, no sea exportado (es decir, no utilizable fuera de la instancia a través del comando del objeto de instancia) por este objeto específico.
exportar nombre ?nombre ...?
Esto organiza para que cada uno de los métodos nombrados, nombre, sea exportado (es decir, utilizable fuera de una instancia a través del comando del objeto de instancia) por este objeto específico.
si_mismo subcomando arg ...
si_mismo script
Esto es equivalente a llamar a oo::define en la clase del objeto (ver CONFIGURACIÓN DE CLASES anterior para una descripción de los comandos compatibles). El comportamiento es el mismo que se describe para oo::define self.

DEFINICIONES CON RANURAS

Algunas de las opciones de configuración para oo::define y oo::objdefine (actualmente mezclar, superclase y filtro) son implementadas como "ranuras". Estas son simplemente campos especializados que se utilizan para configurar una clase o un objeto, y que pueden ser gestionados por medio de una serie de subcomandos y que permiten modificaciones incrementales en lugar de requerir un reemplazo completo.

Las ranuras admiten un conjunto de operaciones comunes, cada una de las cuales es invocada añadiendo el argumento -operacionRanura. Las operaciones admitidas son:

-agregar
Los argumentos que siguen a esta opción se añaden a la lista actual de elementos de la ranura. Por ejemplo, para añadir una clase a la lista de superclases de MiClase, se usaría oo::define MiClase -agregar superclase OtraClase.
-quitar
Los argumentos que siguen a esta opción se eliminan de la lista actual de elementos de la ranura. Por ejemplo, para eliminar una clase de la lista de superclases de MiClase, se usaría oo::define MiClase -quitar superclase OtraClase.
-reemplazar
Los argumentos que siguen a esta opción reemplazan completamente la lista actual de elementos de la ranura. Por ejemplo, para establecer las superclases de MiClase como solo OtraClase, se usaría oo::define MiClase -reemplazar superclase OtraClase.
-obtener
Esta operación devuelve la lista completa de elementos actualmente almacenados en la ranura especificada. Por ejemplo, para obtener la lista de superclases de MiClase, se usaría oo::define MiClase -obtener superclase.
-adjuntar
Los argumentos que siguen a esta opción se adjuntan al final de la lista actual de elementos de la ranura. Esto es similar a -agregar, pero el orden de los elementos añadidos es el mismo que el de los argumentos, y los elementos existentes se desplazan al principio de la lista.

Si no se especifica ninguna opción de operación, el valor por defecto es -reemplazar para mezclar y superclase, y -adjuntar para filtro.

Las ranuras sólo pueden ser modificadas por oo::define. oo::objdefine sólo puede obtener información de las ranuras.

La ranura oo::Slot es un caso especial que se utiliza para definir campos para una clase.

EJEMPLOS

package require TclOO
oo::class create MiClase {
    method hola {nombre} {
        puts "¡Hola, $nombre! Soy MiClase."
    }
}
oo::objdefine MiClase hola {
    puts "¡Hola, $nombre! Soy una instancia de MiClase."
}
MiClase hola mundo
package require TclOO
oo::class create Persona {
    field nombre
    field edad

    constructor {nombre edad} {
        set edad $edad
        set nombre $nombre
    }
    method presentar {} {
        puts "Me llamo $nombre y tengo $edad años."
    }
}
oo::class create Empleado {
    superclass Persona
    field puesto
    field salario

    constructor {nombre edad puesto salario} {
        next $nombre $edad
        set puesto $puesto
        set salario $salario
    }
    method presentar {} {
        next
        puts "Mi puesto es $puesto y mi salario es $salario."
    }
}
set pepe [Persona new {Pepe} {30}]
$pepe presentar
set ana [Empleado new {Ana} {25} {Desarrolladora} {50000}]
$ana presentar

Esto permite cambiar la clase de un objeto después de su creación. Tenga en cuenta que los constructores de la clase no se llaman cuando se hace esto, por lo que el objeto puede estar en un estado inconsistente a menos que se realicen trabajos de configuración adicionales.

Cada nombre de variable no debe tener separadores de espacio de nombres y no debe parecer un acceso a un array. Por defecto, esta ranura funciona añadiendo.

DEFINICIONES CON RANURAS

Algunas de las definiciones configurables de una clase u objeto son definiciones con ranuras. Esto significa que la configuración se implementa mediante un objeto de ranura, que es una instancia de la clase oo::Slot, que gestiona una lista de valores (nombres de clases, nombres de variables, etc.) que componen el contenido de la ranura.

La clase oo::Slot define tres operaciones (como métodos) que pueden realizarse en la ranura:

ranura -append ?miembro ...?
Esto añade los elementos miembro dados a la definición de la ranura.
ranura -clear
Esto establece la definición de la ranura a la lista vacía.
ranura -set ?miembro ...?
Esto reemplaza la definición de la ranura con los elementos miembro dados.

Una consecuencia de esto es que cualquier uso de la operación por defecto de una ranura donde el primer argumento miembro comience con un guion será un error. Una de las operaciones anteriores debe usarse explícitamente en esas circunstancias.

Solo necesita crear una instancia de oo::Slot si está definiendo su propia ranura que se comporte como una ranura estándar.

IMPLEMENTACIÓN DE RANURAS

Internamente, los objetos de ranura también definen un método --default-operation que se reenvía a la operación por defecto de la ranura (por lo tanto, para la ranura de clase “variable”, esto se reenvía a “my -append”), y estos métodos que proporcionan la interfaz de implementación:

ranura Get
Devuelve una lista que es el contenido actual de la ranura. Este método siempre debe ser llamado desde un marco de pila creado por una llamada a oo::define u oo::objdefine.
ranura Resolve elemento
Esto convierte un elemento de la colección con ranura en su forma resuelta; para un valor simple, podría simplemente devolver el valor, pero para una ranura que contiene referencias a comandos o clases, debería convertir esos en sus formas completamente cualificadas (para que puedan compararse con string equals): eso podría hacerse reenviando a namespace which o similar.
ranura Set listaDeElementos
Establece el contenido de la ranura a la lista listaDeElementos y devuelve la cadena vacía. Este método siempre debe ser llamado desde un marco de pila creado por una llamada a oo::define u oo::objdefine.

La implementación de estos métodos depende de la ranura (y es responsable de acceder a la parte correcta de la definición de clase u objeto). Las ranuras también tienen un manejador de métodos desconocidos para unir todas estas piezas, y ocultan su método destroy para que no se invoque inadvertidamente. Se recomienda que cualquier cambio realizado por el usuario en el propio mecanismo de ranura se limite a definir nuevas operaciones cuyos nombres comiencen con un guion.

Tenga en cuenta que no se espera que las instancias de ranura contengan el almacenamiento para la ranura que gestionan; eso estará en o adjunto a la clase o objeto que gestionan. Esas instancias deben proporcionar sus propias implementaciones de los métodos Get y Set (y opcionalmente Resolve; este último por defecto es un paso directo sin hacer nada).

NAME

oo::objdefine, oo::renamemethod, oo::renamevar, oo::slot, oo::mix - Define and modify object instances

SYNOPSIS

oo::objdefine ?-noslot? objectName ?arg ...?
oo::renamemethod objectName oldName newName
oo::renamevar objectName oldName newName
oo::slot objectName ?slotName ...?
oo::mixin objectName className ?-append?

CLASS HIERARCHY

The oo::objdefine command is part of the TclOO object system.

DESCRIPTION

The oo::objdefine command is used to define the slots and methods of an existing object instance, and to rename its methods and variables. It is the object-oriented analogue of the oo::class define command.

The oo::objdefine command operates on an existing object instance, named by the objectName argument. The subsequent arguments specify the definitions to be applied to the object instance. The available definitions are:

method name ?args ...? body
Defines a method named name for the object instance. The method has the specified arguments and body. If a method with the same name already exists, it is overridden.
proc name ?args ...? body
Defines a procedure named name for the object instance. This is equivalent to defining a method, but the name is not automatically added to the object's method list. This is useful for defining private helper procedures.
variable name ?value?
Defines an instance variable named name for the object instance. If a value is provided, the variable is initialized with that value. If the variable already exists, its value is updated.
renamemethod oldName newName
Renames an existing method from oldName to newName.
renamevar oldName newName
Renames an existing instance variable from oldName to newName.
slot ?slotName ...?
Specifies that the given slotNames should be created as slots for the object instance. If no slot names are provided, it returns the names of all slots currently defined for the object instance.
mixin className ?-append?
Mixes in the methods and variables of the class named className into the object instance. If the -append option is given, the methods and variables from className are appended to the existing ones; otherwise, they are prepended. Prepending allows the object instance to override methods and variables from the mixin class.

If the -noslot option is provided, the object instance is not automatically created as a slot in its own class. This is typically used when defining methods or variables that are intended to be private to the object instance.

SLOTTED DEFINITIONS

When oo::objdefine is used to define methods or variables, these definitions are associated with the object instance itself, rather than its class. This means that each object instance can have its own unique set of methods and variables, independent of its class definition.

When using the mixin command, the methods and variables of the specified class are copied into the object instance. If the -append option is used, the mixin definitions are added after any existing definitions. This allows the object instance to override methods and variables from the mixin class.

EXAMPLES

foo sayhello           → error "unknown method sayhello"
oo::objdefine foo {
    method sayhello {} {
        puts "hello world"
    }
}

oo::objdefine foo {
    renamemethod sayhello goodbye
}
foo goodbye            → prints "hello world"
foo sayhello           → error "unknown method sayhello"
oo::objdefine foo {
    variable x 10
}
oo::objdefine foo {
    method getx {} {
        return $x
    }
}
foo getx               → returns 10
oo::objdefine foo {
    renamevar x y
}
foo getx               → error "unknown method getx"
foo gety               → returns 10
oo::objdefine foo {
    slot s1
}
oo::objdefine foo {
    method useslot {val} {
        set s1 $val
    }
}
foo useslot 20
puts $foo::s1          → prints 20

oo::object create lollipop
oo::objdefine lollipop {
    method greet {} {
        puts "hello world"
    }
}

oo::objdefine bar {
    mixin lollipop
}
bar greet              → prints "hello world"
oo::objdefine bar {
    renamemethod greet hi
}
bar hi                 → prints "hello world"
oo::objdefine bar {
    renamevar hi bye
}
bar bye                → prints "hello world"
oo::objdefine bar {
    renamemethod bye foo
}
bar foo                → error "unknown method foo"
oo::objdefine bar {
    renamemethod bar lollipop
}
oo::objdefine lollipop method sayhello {} {puts "hello world"}
oo::objdefine bar {
    mixin -append oo::object
}
bar sayhello           → prints "hello world"

This example shows how additional classes can be mixed into an object. It also shows how mixin is a slot that supports appending:

oo::object create inst
inst m1              → error "unknown method m1"
inst m2              → error "unknown method m2"
oo::class create A {
    method m1 {} {
        puts "red brick"
    }
}
oo::objdefine inst {
    mixin A
}
inst m1              → prints "red brick"
inst m2              → error "unknown method m2"
oo::class create B {
    method m2 {} {
        puts "blue brick"
    }
}
oo::objdefine inst {
    mixin -append B
}
inst m1              → prints "red brick"
inst m2              → prints "blue brick"
