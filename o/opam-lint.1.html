OPAM-LINT(1) Manual de Opam OPAM-LINT(1)

NOMBRE

opam-lint - Comprueba y valida los archivos de descripción de paquetes ('opam').

SINOPSIS

opam lint [OPCIÓN]… [ARCHIVOS]…

DESCRIPCIÓN

Dado un archivo opam, realiza varias comprobaciones de calidad sobre él y muestra recomendaciones, advertencias o errores en stderr.

ARGUMENTOS

ARCHIVOS
Nombre de los archivos opam a comprobar, o directorio que los contiene. Directorio actual si no se especifica.

OPCIONES

--check-upstream
Comprueba el upstream, la disponibilidad del archivo y la(s) suma(s) de verificación
--normalise
Genera una versión normalizada del archivo opam en stdout
--package=PKG
Realiza el linting de la definición actual del paquete dado en lugar de especificar un archivo opam directamente.
--recursive
Permite búsquedas recursivas de archivos *.opam. Ver también --subpath.
-s, --short
Solo imprime los números de advertencia/error, separados por espacios, si los hay
--subpath=RUTA
Los archivos *.opam se obtienen del directorio secundario dado en lugar del directorio principal. Las fuentes se toman entonces del subdirectorio objetivo, y internamente solo se copia/descarga este subdirectorio. Se puede combinar con --recursive para tener una búsqueda recursiva en la subruta.
-W WARNS, --warnings=WARNS
Selecciona las advertencias a mostrar u ocultar. WARNS debe ser una concatenación de +N, -N, @N, +N..M, -N..M, @N..M para habilitar, deshabilitar o habilitar-como-error la advertencia o el número de error N o todas las advertencias con números entre N y M inclusive. Todas las advertencias están habilitadas por defecto, a menos que WARNS comience con + o @, lo que deshabilita todas excepto las seleccionadas.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Está pensado para cualquier uso persistente de opam (scripts, blogs, etc.), cualquier versión de opam de la misma serie MAYOR se comportará como para la versión MENOR especificada. La opción no estaba disponible en opam 2.0, por lo que para seleccionar la interfaz de línea de comandos 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de always, never o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar varias veces. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL`.
--criteria=CRITERIOS
Especifica las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje compatible y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Un g general

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

--cudf=FILENAME
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en FILENAME-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración a stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=LEVEL
Al igual que --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está establecida (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FMT] (predeterminado=auto)
Muestra esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable de entorno TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora dependencias adicionales requeridas por paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=FILENAME
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre de archivo contiene el carácter `%`, será reemplazado por un índice que no sobrescribirá un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en la versión 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato anterior. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo que se encuentre en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Usa ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegura que nada se actualizará o reescribirá automáticamente. Útil para llamarlo desde scripts de autocompletado, por ejemplo. Fallará siempre que sea necesaria una operación de este tipo; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el solucionador CUDF a utilizar para resolver problemas de instalación de paquetes. Esto es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentra un error en la definición de un paquete o en un archivo de configuración. La predeterminación es continuar silenciosamente si es posible.
--switch=SWITCH
Usa SWITCH como el cambio de compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo y usa el interno (esto requiere que opam se haya compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más verboso. Una vez -v muestra todos los comandos de paquete, repetir para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Cuando se actualizan paquetes vinculados a un directorio local controlado por versiones, actualiza al estado de trabajo actual de su fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio fuente se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

ENTORNO

Opam utiliza las variables de entorno listadas aquí. Las variables booleanas deben establecerse en "0", "no", "false" o la cadena vacía para deshabilitar, "1", "yes" o "true" para habilitar.

OPAMALLPARENS encierra todos los filtros con paréntesis.

OPAMASSUMEDEPEXTS ver la opción `--assume-depexts'.

OPAMAUTOREMOVE ver la opción remove `--auto-remove'.

OPAMBESTEFFORT ver la opción `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA establece la cadena que debe anteponerse a los criterios cuando se establece la opción `--best-effort', y se espera que maximice la propiedad `opam-query' en la solución.

OPAMBUILDDOC Eliminado en la versión 2.1.

OPAMBUILDTEST Eliminado en la versión 2.1.

OPAMCLI ver la opción `--cli'.

OPAMCOLOR cuando se establece en always o never, establece un valor predeterminado para la opción `--color'.

OPAMCONFIRMLEVEL ver la opción `--confirm-level`. OPAMCONFIRMLEVEL tiene prioridad sobre OPAMYES y OPAMNO.

OPAMCRITERIA especifica las preferencias del usuario para la resolución de dependencias. El valor predeterminado depende de la versión del solucionador, use `config report' para conocer la configuración actual. Ver también la opción --criteria.

OPAMCUDFFILE guarda el grafo cudf en file-actions-explicit.dot.

OPAMCUDFTRIM controla el filtrado de paquetes no relacionados durante el preprocesamiento de CUDF.

OPAMCURL se puede usar para seleccionar un programa 'curl' dado. Ver OPAMFETCH para más opciones.

OPAMDEBUG ver las opciones `--debug' y `--debug-level'.

OPAMDEBUGSECTIONS si está establecido, limita los mensajes de depuración a la lista de secciones separadas por espacios. Las secciones pueden tener opcionalmente un nivel de depuración específico (por ejemplo, CLIENT:2 o CLIENT CUDF:2), pero de lo contrario usan `--debug-level'.

OPAMDIGDEPTH define cuán agresiva es la búsqueda de conflictos durante el preprocesamiento de CUDF.

OPAMDOWNLOADJOBS establece el número máximo de descargas simultáneas.

OPAMDROPWORKINGDIR anula los paquetes previamente actualizados con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se mencionaran explícitamente en la línea de comandos.

OPAMDRYRUN ver la opción `--dry-run'.

OPAMEDITOR establece el editor a utilizar para editar archivos opam, anula $EDITOR y $VISUAL.

OPAMERRLOGLEN establece el número de líneas de registro que se imprimen cuando un subproceso falla. 0 para imprimir todas.

OPAMEXTERNALSOLVER ver la opción `--solver'.

OPAMFAKE ver la opción `--fake'.

OPAMFETCH especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor de 'download-command' del archivo de configuración principal.

OPAMFIXUPCRITERIA igual que OPAMUPGRADECRITERIA, pero específico para corrección y reinstalación.

OPAMIGNORECONSTRAINTS ver la opción de instalación `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS ver la opción `--ignore-pin-depends'.

OPAMINPLACEBUILD ver la opción `--inplace-build'.

OPAMJOBS establece el número máximo de procesos de trabajo paralelos a ejecutar.

OPAMJSON registra la salida json en el archivo dado (usa el carácter `%` para indexar los archivos).

OPAMKEEPBUILDDIR ver la opción de instalación `--keep-build-dir'.

OPAMKEEPLOGS indica a opam que no elimine algunos registros de comandos temporales y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener rastreos de pila más fiables.

OPAMLOCKED combinación de las opciones `--locked' y `--lock-suffix'.

OPAMLOGS logdir establece el directorio de registros, el valor predeterminado es un directorio temporal en /tmp

OPAMMAKECMD establece el comando make del sistema a utilizar.

OPAMMERGEOUT fusiona las salidas de proceso, stderr en stdout.

OPAMNO responde no a cualquier pregunta realizada, ver las opciones `--no` y `--confirm-level`. OPAMNO se ignora si OPAMCONFIRMLEVEL o OPAMYES están establecidos.

OPAMNOAGGREGATE con `opam admin check', no agrupa paquetes.

OPAMNOASPCUD Obsoleto.

OPAMNOAUTOUPGRADE deshabilita la actualización interna automática de repositorios en un formato anterior al actual, en 'update' o 'init'.

OPAMNOCHECKSUMS habilita la opción --no-checksums cuando está disponible.

OPAMNODEPEXTS deshabilita el manejo de dependencias del sistema, ver la opción `--no-depexts'.

OPAMNOENVNOTICE Interno.

OPAMNOSELFUPGRADE ver la opción `--no-self-upgrade'

OPAMPINKINDAUTO establece si los sistemas de control de versiones deben detectarse al fijar a una ruta local. Habilitado por defecto desde la versión 1.3.0.

OPAMPRECISETRACKING seguimiento de directorios de grano fino.

OPAMPREPRO establece esto a falso para deshabilitar el preprocesamiento de CUDF. Menos eficiente, pero podría ayudar a depurar problemas del solucionador.

OPAMREPOSITORYTARRING almacena internamente los repositorios como archivos tar.gz. Esto puede ser mucho más rápido en sistemas de archivos que no manejan bien la exploración de árboles grandes pero tienen una buena caché en /tmp. Sin embargo, es más lento en el caso general.

OPAMREQUIRECHECKSUMS Habilita la opción `--require-checksums' cuando está disponible (por ejemplo, para `opam install').

OPAMRETRIES establece el número de intentos antes de fallar las descargas.

ENVIRONMENT

OPAMBUILDDIR specifies the directory to use for building packages. Defaults to ~/.opam/build.

OPAMCACHE specifies the directory where downloaded files are cached. Defaults to ~/.opam/cache.

OPAMCOLORS sets the colors for opam output. It is a comma separated list of settings. For example: red:blue,bold:green. Possible elements are: colors (e.g. red, blue), attributes (e.g. bold, underline), and default ( default). The color and attribute names are not specified here.

OPAMCONFIRMLEVEL is a numerical value that determines whether opam asks for confirmation for actions. See also option --confirm-level.

OPAMCRYPTOHASH hash algorithm for package archive verification. Defaults to sha512.

OPAMDEBUG enables debug logging. Possible values are true, false, or a list of debug categories.

OPAMDEVMODE Enable development mode. This implies OPAMKEEPBUILDDIR, OPAMKEEPALLDOCS, OPAMKEEPTTESTS and turns off optimization.

OPAMDISABLECOMMANDS Commands that should be skipped when running opam install or opam upgrade. Possible values are configure, build, install, test, remove.

OPAMDOWNLOADCMD command to use to download files. See --download-cmd.

OPAMEDIT editor to use for editing package definitions. Defaults to $EDITOR.

OPAMEMPTYYES Ignored. Use OPAMYES or OPAMNO instead.

OPAMENVFORMAT format for opam env output. See --env-format.

OPAMGLOBALCONFIGDIR opam global configuration directory. Defaults to ~/.config/opam.

OPAMINSTALLKEEPBUILDDIR see option --keep-build-dir.

OPAMINSTALLKEEPTESTS see option --keep-tests.

OPAMKEEPALLDOCS see option --keep-docs.

OPAMKEEPBUILDDIR see option --keep-build-dir.

OPAMKEEPTESTS see option --keep-tests.

OPAMKEEPDEPS see option --keep-deps.

OPAMLINTCODE_ALL opam lint ignores checks specified in this variable. This variable is used if no subcommand is specified.

OPAMLISTFORMAT format for opam list output. See --list-format.

OPAMNO see options --yes and --confirm-level. If OPAMNO is set, opam will refuse to run any command that requires confirmation.

OPAMOFFLINE Ignore network access. All commands requiring network access will fail.

OPAMORDER see option --order.

OPAMPINDIR The directory containing opam binaries. This directory is prepended to the PATH environment variable when running opam commands. Defaults to %s/bin.

OPAMPROFILE Load a given profile. Profiles are files in ~/.opam/config that define variables for opam commands.

OPAMPROMPTCOMMAND Set a command to run after each opam command. Useful for shell integration.

OPAMROOT see option --root. This is automatically set by opam env --root=DIR --set-root.

OPAMSAFE see option --safe.

OPAMSHOW see option --show.

OPAMSKIPUPDATE see option --skip-updates.

OPAMSKIPVERSIONCHECKS bypasses some version checks. Unsafe, for compatibility testing only.

OPAMSOLVERALLOWSUBOPTIMAL (default true) allows some solvers to still return a solution when they reach timeout; while the solution remains assured to be consistent, there is no guarantee in this case that it fits the expected optimisation criteria. If true, opam willcontinue with a warning, if false a timeout is an error. Currently only the builtin-z3 backend handles this degraded case.

OPAMSOLVERTIMEOUT change the time allowance of the solver. Default is 60.0, set to 0 for unlimited. Note that all solvers may not support this option.

OPAMSOLVERTOLERANCE changes the tolerance towards the solver choosing an unoptimized solution (i.e. might pull outdated packages). Typical values range from 0.0 (best solution known to the solver) to 1.0 (unoptimized solution). Default is 0.0. This option is useful in case the solver can't find a solution in a reasonable time (see $OPAMSOLVERTIMEOUT). Note that all solvers may not support this option.

CLI VERSION

All scripts and programmatic invocations of opam should use --cli in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and --cli=2.1 for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if --cli=2.0 is specified.

The command-line version is selected by using the --cli option or the OPAMCLI environment variable. --cli may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if --cli is not given.

EXIT STATUS

As an exception to the following, the exec command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).

Arch Linux PKGBUILD Example

PKGBUILD Example

Este es un ejemplo de un archivo PKGBUILD para Arch Linux. Un PKGBUILD es un script de shell que contiene metadatos e instrucciones sobre cómo compilar un paquete de software desde fuente y prepararlo para la instalación utilizando Pacman.

Estructura Básica

Un PKGBUILD típico incluye las siguientes variables:

  • pkgname: El nombre del paquete.
  • pkgver: La versión del paquete.
  • pkgrel: La versión de lanzamiento del paquete (incrementa si el PKGBUILD cambia pero la versión del software no).
  • pkgdesc: Una descripción corta del paquete.
  • arch: Una matriz de arquitecturas de CPU soportadas (ej. 'x86_64', 'i686').
  • url: La URL del proyecto upstream.
  • license: La licencia del software (ej. 'GPL').
  • depends: Una matriz de dependencias necesarias para ejecutar el paquete.
  • makedepends: Una matriz de dependencias necesarias para construir el paquete.
  • source: Una matriz de URLs a los archivos fuente (tarballs, repositorios git, etc.).
  • sha256sums: Una matriz de sumas de verificación (hashes) para los archivos fuente.

Funciones Clave

Un PKGBUILD también define varias funciones que se ejecutan en diferentes etapas del proceso de compilación e instalación:

  • prepare(): Preparación del entorno de compilación (aplicar parches, etc.).
  • build(): Compilación del software.
  • check(): Ejecución de pruebas (si están disponibles).
  • package(): Instalación del software compilado en una estructura de directorios temporal que simula la instalación en el sistema raíz.

Ejemplo Simplificado

# Contribuye a la comunidad de Arch Linux
# Visita https://wiki.archlinux.org/title/PKGBUILD para más información

pkgname=ejemplo
pkgver=1.0
pkgrel=1
pkgdesc="Un paquete de ejemplo simple"
arch=('x86_64')
url="https://example.com/project"
license=('MIT')
depends=('some-dependency')
makedepends=('gcc')
source=("${pkgname}-${pkgver}.tar.gz")
sha256sums=('CHECKSUM_HERE')

build() {
  cd "${srcdir}/${pkgname}-${pkgver}"
  ./configure --prefix=/usr
  make
}

package() {
  cd "${srcdir}/${pkgname}-${pkgver}"
  make DESTDIR="${pkgdir}" install
}

Este ejemplo muestra la estructura básica de un PKGBUILD. Para un paquete real, las variables `source` y `sha256sums` contendrían las URLs y los hashes correctos para los archivos fuente del software que se está empaquetando. La función `build()` y `package()` contendrían los comandos específicos necesarios para compilar e instalar el software.

Para construir este paquete, usarías la herramienta makepkg en tu sistema Arch Linux. Por ejemplo: makepkg -si.

Este contenido es un ejemplo y no representa un paquete real. La información específica de los paquetes puede variar según lo especificado en el paquete correspondiente de Arch Linux.
