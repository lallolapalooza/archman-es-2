NOMBRE

ossl-guide-quic-server-block - Guía de OpenSSL: Cómo escribir un servidor QUIC simple bloqueante

EJEMPLO DE SERVIDOR QUIC SIMPLE BLOQUEANTE

Esta página presentará varios ejemplos de código fuente que demuestran cómo escribir una aplicación de servidor QUIC de "eco" simple y no concurrente, que acepta una conexión de cliente a la vez, devolviendo la entrada del cliente al mismo cliente. Una vez que el cliente actual se desconecta, se acepta la siguiente conexión de cliente.

El servidor solo acepta solicitudes HTTP/1.0, lo cual no es estándar y no será compatible con los servidores del mundo real. Esto es solo para fines demostrativos.

Tanto el socket de aceptación como las conexiones de cliente son "bloqueantes". Un servidor más típico podría usar sockets no bloqueantes con un bucle de eventos y callbacks para eventos de E/S.

El código fuente completo para este servidor QUIC bloqueante de ejemplo está disponible en el directorio demos/guide de la distribución de código fuente de OpenSSL en el archivo quic-server-block.c. También está disponible en línea en https://github.com/openssl/openssl/blob/master/demos/guide/quic-server-block.c.

Suponemos que ya tiene OpenSSL instalado en su sistema; que ya tiene una comprensión fundamental de los conceptos de OpenSSL y QUIC (ver ossl-guide-libraries-introduction(7) y ossl-guide-quic-introduction(7)); y que sabe cómo escribir y compilar código C y enlazarlo contra las bibliotecas libcrypto y libssl que proporciona OpenSSL. También asume que tiene una comprensión básica de UDP/IP y sockets.

Creación de los objetos SSL_CTX y SSL

El primer paso es crear un objeto SSL_CTX para nuestro servidor. Usamos la función SSL_CTX_new(3) para este propósito. Pasamos como argumento el valor de retorno de la función OSSL_QUIC_server_method(3). Debe usar este método siempre que esté escribiendo un servidor QUIC.

/*
 * Un SSL_CTX contiene información de configuración compartida para múltiples
 * conexiones SSL posteriores por cliente. Aquí cargamos específicamente un método
 * de servidor QUIC.
 */
ctx = SSL_CTX_new(OSSL_QUIC_server_method());
if (ctx == NULL)
    goto err;

Los servidores necesitan una clave privada y un certificado. A menudo se requieren certificados de CA emisores intermedios, y tanto el certificado del servidor (entidad final o EE) como los certificados del emisor ("cadena") se configuran más fácilmente en un único "archivo de cadena". A continuación, cargamos dicho archivo de cadena (el certificado EE debe aparecer primero) y luego cargamos la clave privada correspondiente, verificando que coincida con el certificado del servidor. No se realizan comprobaciones para verificar la integridad de la cadena (firmas de CA o fechas de caducidad de certificados, por ejemplo), pero sí verificamos la consistencia de la clave privada con el certificado correspondiente.

/*
 * Carga el archivo de cadena de certificado del servidor (formato PEM), que incluye
 * no solo el certificado del servidor de hoja (entidad final), sino también cualquier
 * certificado de CA emisor intermedio. El certificado de hoja debe ser el
 * primer certificado del archivo.
 *
 * En casos de uso avanzados, esto se puede llamar varias veces, una por cada algoritmo
 * de clave pública para el que el servidor tenga un certificado correspondiente.
 * Sin embargo, la clave privada correspondiente (ver abajo) debe cargarse primero,
 * *antes* de pasar al siguiente archivo de cadena.
 */
if (SSL_CTX_use_certificate_chain_file(ctx, cert_path) <= 0) {
    fprintf(stderr, "no se pudo cargar el archivo de certificado: %s\n", cert_path);
    goto err;
}
/*
 * Carga la clave privada correspondiente, esto también verifica que la clave
 * privada coincida con el certificado de entidad final recién cargado. No verifica
 * si la cadena de certificados es válida, los certificados podrían estar
 * caducados, o de lo contrario podrían fallar al formar una cadena que un cliente pueda
 * validar.
 */
if (SSL_CTX_use_PrivateKey_file(ctx, key_path, SSL_FILETYPE_PEM) <= 0) {
    fprintf(stderr, "no se pudo cargar el archivo de clave: %s\n", key_path);
    goto err;
}

La mayoría de los servidores, incluido este, no solicitan certificados de cliente. Por lo tanto, no necesitamos un "almacén de confianza" y permitimos que el handshake se complete incluso cuando el cliente no presenta un certificado. Nota: Incluso si un cliente presentara un certificado de confianza, para que fuera útil, la aplicación del servidor aún necesitaría código personalizado para usar la identidad verificada para otorgar acceso no predeterminado a ese cliente en particular. Algunos servidores otorgan acceso a todos los clientes con certificados de una CA privada, esto requiere el procesamiento de listas de revocación de certificados para desautorizar a un cliente. A menudo es más simple y seguro mantener una lista de claves públicas autorizadas en su lugar.

Aunque esta es la configuración predeterminada, llamamos explícitamente a la función SSL_CTX_set_verify(3) y le pasamos el valor SSL_VERIFY_NONE. El argumento final de esta función es una función de callback que puede proporcionar opcionalmente para anular el manejo predeterminado de la verificación de certificados. La mayoría de las aplicaciones no necesitan hacer esto, por lo que se puede establecer seguramente en NULL para obtener el manejo predeterminado.

/*
 * Los clientes rara vez emplean autenticación basada en certificados, y por lo tanto no
 * requerimos autenticación TLS "mutua" (de hecho, no hay forma de saber
 * si y cómo el cliente autenticó al servidor, por lo que el término "mutuo"
 * es potencialmente engañoso).
 *
 * Dado que no solicitamos ni procesamos certificados de cliente, no
 * necesitamos configurar un almacén de certificados de confianza, por lo que no es necesaria
 * una llamada a SSL_CTX_set_default_verify_paths(). Se asume que la cadena de
 * certificados del propio servidor es válida.
 */
SSL_CTX_set_verify(ctx, SSL_VERIFY_NONE, NULL);

QUIC también dicta el uso de la Negociación de Protocolo a Nivel de Aplicación (ALPN) para seleccionar un protocolo de aplicación. Usamos SSL_CTX_set_alpn_select_cb(3) para este propósito. Podemos pasar una función de callback que se llamará para cada conexión para seleccionar un ALPN que el servidor considere aceptable.

/* Configura el callback de negociación ALPN para decidir qué ALPN se acepta. */
SSL_CTX_set_alpn_select_cb(ctx, select_alpn, NULL);

En este caso, solo aceptamos "http/1.0" y "hq-interop".

/*
* Cadenas ALPN para el handshake TLS. Solo se aceptan 'http/1.0' y 'hq-interop'.
*/
static const unsigned char alpn_ossltest[] = {
    8,  'h', 't', 't', 'p', '/', '1', '.', '0',
    10, 'h', 'q', '-', 'i', 'n', 't', 'e', 'r', 'o', 'p',
};
static int select_alpn(SSL *ssl, const unsigned char **out,
                       unsigned char *out_len, const unsigned char *in,
                       unsigned int in_len, void *arg)
{
    if (SSL_select_next_proto((unsigned char **)out, out_len, alpn_ossltest,
                              sizeof(alpn_ossltest), in,
                              in_len) == OPENSSL_NPN_NEGOTIATED)
        return SSL_TLSEXT_ERR_OK;
    return SSL_TLSEXT_ERR_ALERT_FATAL;
}

Eso es todo lo que necesitamos configurar para el SSL_CTX. A continuación, creamos un socket UDP y lo enlazamos en localhost.

/* Obtiene el descriptor de archivo para un nuevo socket UDP */
if ((fd = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP)) < 0) {
    fprintf(stderr, "no se puede crear el socket");
    goto err;
}
sa.sin_family = AF_INET;
sa.sin_port = htons(port);
/* Enlaza al nuevo socket UDP en localhost */
if (bind(fd, (const struct sockaddr *)&sa, sizeof(sa)) < 0) {
    fprintf(stderr, "no se puede enlazar a %u\n", port);
    BIO_closesocket(fd);
    goto err;
}

Para ejecutar el servidor QUIC, creamos un SSL_LISTENER para escuchar las conexiones entrantes. Le proporcionamos el puerto UDP enlazado para comenzar explícitamente a escuchar nuevas conexiones.

/*
 * Crea un nuevo listener QUIC. Los listeners, y otros objetos QUIC, por defecto
 * operan en modo bloqueante. El comportamiento configurado es heredado por
 * objetos hijos.
 */
if ((listener = SSL_new_listener(ctx, 0)) == NULL) {
    goto err;
}
/* Proporciona al listener nuestro socket UDP. */
if (!SSL_set_fd(listener, fd))
    goto err;
/* Comienza a escuchar. */
if (!SSL_listen(listener))
    goto err;

Bucle del servidor

El servidor entra ahora en un bucle "infinito", manejando una conexión de cliente a la vez. Antes de cada conexión, limpiamos la pila de errores de OpenSSL para que cualquier informe de error esté relacionado solo con la nueva conexión.

/* Pila de errores prístina para cada nueva conexión */
ERR_clear_error();

NAME

ossl-guide-quic-server-block — Simple blocking QUIC server example

SIMPLE BLOCKING QUIC SERVER EXAMPLE

This section shows a simplified blocking QUIC server example. The server listens for incoming connections, accepts one, and then echoes any data received back to the client.

Server Setup

The server starts by setting up a listening socket and configuring an SSL_CTX. This involves loading the certificate and private key.

/* ... server setup code ... */

/* Create an SSL_CTX object */
ctx = SSL_CTX_new(TLS_server_method());
if (ctx == NULL) {
    goto err;
}

/* Load certificate and private key */
if (SSL_CTX_use_certificate_file(ctx, cert_file,
                                SSL_FILETYPE_PEM) <= 0) {
    fprintf(stderr, "Error loading certificate file\n");
    goto err;
}
if (SSL_CTX_use_PrivateKey_file(ctx, privkey_file,
                                SSL_FILETYPE_PEM) <= 0) {
    fprintf(stderr, "Error loading private key file\n");
    goto err;
}

/* ... setup listening socket ... */

/* Create a listener object */
listener = SSL_new(ctx);
if (listener == NULL) {
    fprintf(stderr, "Failed to create listener SSL object\n");
    goto err;
}

/* Bind the listener to the socket and start listening */
if (SSL_set_fd(listener, fd) <= 0) {
    fprintf(stderr, "Failed to set file descriptor for listener\n");
    goto err;
}
if (SSL_bind(listener, (struct sockaddr *)&addr, sizeof(addr)) <= 0) {
    fprintf(stderr, "Failed to bind listener\n");
    goto err;
}
if (SSL_listen(listener, 5) <= 0) {
    fprintf(stderr, "Failed to start listening\n");
    goto err;
}

Accepting Client Connections

The server then enters a loop to accept incoming client connections. SSL_accept_connection is a blocking call that waits for a connection and performs the QUIC handshake.

/* Block while waiting for a client connection */
conn = SSL_accept_connection(listener, 0);
if (conn == NULL) {
    fprintf(stderr, "error while accepting connection\n");
    goto err;
}

Echoing Client Data

With the handshake complete, the server echoes client input back to the client in a loop.

while (SSL_read_ex(conn, buf, sizeof(buf), &nread) > 0) {
    if (SSL_write_ex(conn, buf, nread, &nwritten) > 0 &&
        nwritten == nread) {
        continue;
    }
    fprintf(stderr, "Error echoing client input");
    break;
}

Closing the Connection

Once the client closes its connection, we signal the end of the stream by using SSL_stream_conclude(3). This will send a final Finished packet to the client.

/* Signal the end of the stream. */
if (SSL_stream_conclude(conn, 0) != 1) {
    fprintf(stderr, "Unable to conclude stream\n");
    SSL_free(conn);
    goto err;
}

We then shut down the connection with SSL_shutdown_ex(3), which may need to be called multiple times to ensure the connection is shutdown completely.

while (SSL_shutdown_ex(conn, 0, &shutdown_args,
                       sizeof(SSL_SHUTDOWN_EX_ARGS)) != 1) {
    fprintf(stderr, "Re-attempting SSL shutdown\n");
}

Finally, we free the SSL connection, and the server is now ready to accept the next client connection.

SSL_free(conn);

Final clean up

If the server somehow manages to break out of the infinite loop and be ready to exit, it would deallocate the constructed SSL.

SSL_free(listener);

And in the main function, it would deallocate the constructed SSL_CTX.

SSL_CTX_free(ctx);
BIO_closesocket(fd);
res = EXIT_SUCCESS;
return res;
