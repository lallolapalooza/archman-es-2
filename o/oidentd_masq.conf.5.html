NOMBRE

oidentd_masq.conf - archivo de configuración NAT de oidentd

DESCRIPCIÓN

Si el soporte NAT está habilitado con la opción --masquerade, oidentd lee el archivo /usr/local/etc/oidentd_masq.conf para determinar las respuestas de Ident a las consultas destinadas a otras máquinas. También es posible reenviar consultas a servidores Ident en las máquinas que se conectan a través de la máquina en la que se ejecuta oidentd. Para más información sobre el reenvío, por favor consulte la opción --forward en oidentd(8).

El archivo de configuración NAT contiene una regla por línea. Las líneas se leen de arriba a abajo, y solo se utiliza la primera regla que coincide. Las líneas que comienzan con un signo de almohadilla ("#") se ignoran.

FORMATO DE REGLA

Las reglas deben tener el siguiente formato:

host[/mask] respuesta tipo-sistema

El campo host especifica el nombre de host o la dirección IP del host que es propietario de la conexión para la cual se recibió una consulta Ident. Este host debe conectarse a través de la máquina en la que se ejecuta oidentd. El host puede especificarse como una dirección IP o un nombre de host.

Si se especifica una máscara de red usando el campo mask, la regla se aplica a todos los hosts en la subred dada. Las máscaras de red pueden especificarse en notación de puntos (por ejemplo, "255.255.192.0") o en notación CIDR (por ejemplo, "18").

El campo response especifica la respuesta que se enviará al recibir una consulta para el host o subred especificada.

El campo system-type especifica el sistema operativo que se enviará junto con la respuesta Ident. Consulte la opción --other en oidentd(8) para más información.

EJEMPLOS

# host[/mask]           respuesta  tipo-sistema
10.0.0.1                usuario1   UNIX
servidor.interno        usuario2   UNIX-BSD
10.0.0.0/24             usuario3   UNIX
10.0.0.0/255.255.0.0    usuario4   DESCONOCIDO

Tenga en cuenta que el orden de las reglas es importante en este ejemplo. Debido a que las líneas se leen de arriba a abajo, las reglas más específicas deben preceder a las más generales. Por ejemplo, la regla para "10.0.0.1" no coincidiría con ninguna conexión si estuviera precedida por el más general "10.0.0.0/24".
