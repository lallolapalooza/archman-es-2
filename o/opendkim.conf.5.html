opendkim.conf(5) Manual de Formatos de Archivo opendkim.conf(5)

NOMBRE

opendkim.conf - Archivo de configuración para opendkim

UBICACIÓN

/etc/opendkim/opendkim.conf

DESCRIPCIÓN

opendkim(8) implementa la especificación DKIM para firmar y verificar mensajes de correo electrónico de forma individual por dominio. Este archivo es su archivo de configuración.

Las líneas en blanco se ignoran. Las líneas que contienen un carácter de hash ("#") se truncan en el carácter de hash para permitir comentarios en el archivo.

El resto del contenido debe ser el nombre de un parámetro, seguido de espacios en blanco, seguido del valor de ese parámetro, cada uno en una línea separada.

Para parámetros que son Booleanos por naturaleza, solo se procesa el primer byte del valor. Para valores positivos, se aceptan: "T", "t", "Y", "y", "1". Para valores negativos, se aceptan: "F", "f", "N", "n", "0".

Muchos de estos parámetros, aunque no todos, también están disponibles como opciones de línea de comandos para opendkim(8). Sin embargo, generalmente no se agregan nuevos parámetros como opciones de línea de comandos, por lo que el conjunto completo de opciones está disponible aquí, y por lo tanto, se fomenta el uso del archivo de configuración. En alguna versión futura, es probable que el conjunto de opciones de línea de comandos disponibles se reduzca.

Consulte la página del manual de opendkim(8) para obtener detalles sobre cómo y cuándo se recargan los contenidos del archivo de configuración.

Algunos de estos parámetros se enumeran como de tipo "dataset". Consulte la página del manual de opendkim(8) para obtener una descripción de dichos parámetros.

A menos que se indique lo contrario, los valores Booleanos por defecto son "false", los valores enteros por defecto son 0, y los valores de cadena y conjunto (dataset) por defecto no están definidos.

PARÁMETROS

AllowSHA1Only (Booleano)
Permite el modo de verificación cuando solo hay soporte SHA1 disponible. RFC6376 requiere que los verificadores implementen soporte SHA1 y SHA256. Establecer esta característica cambia la ausencia de soporte SHA256 de un error a una advertencia.
AlwaysAddARHeader (Booleano)
Agrega un campo de encabezado "Authentication-Results:" incluso a mensajes sin firmar de dominios sin una política de "firmar todo". El resultado DKIM informado será "none" en tales casos. Normalmente, el correo sin firmar de dominios no estrictos no provoca la adición del campo de encabezado de resultados.
AuthservID (cadena)
Establece el "authserv-id" a usar al generar el campo de encabezado Authentication-Results: después de verificar un mensaje. Por defecto, se usa el nombre del MTA que procesa el mensaje. Si se proporciona la cadena "HOSTNAME", se usará el nombre del host que ejecuta el filtro (según lo devuelve la función gethostname(3)).
AuthservIDWithJobID (Booleano)
Si es "true", solicita que la parte authserv-id de los campos de encabezado Authentication-Results: agregados contenga el ID del trabajo del mensaje que se está evaluando.
AutoRestart (Booleano)
Reinicia automáticamente en caso de fallos. Úselo con precaución; si el filtro falla instantáneamente después de iniciarse, esto puede causar un bucle cerrado de fork(2).
AutoRestartCount (entero)
Establece el número máximo de reinicios automáticos. Después de este número de reinicios automáticos, el filtro se rendirá y terminará. Un valor de 0 implica ningún límite; este es el valor por defecto.
AutoRestartRate (cadena)
Establece la tasa máxima de reinicio automático. Si el filtro comienza a reiniciarse más rápido que la tasa definida aquí, se rendirá y terminará. Esta es una cadena de la forma n/t[u] donde n es un entero que limita el recuento de reinicios en el intervalo dado y t[u] define el intervalo de tiempo a través del cual se calcula la tasa; t es un entero y u define las unidades representadas ("s" o "S" para segundos, por defecto; "m" o "M" para minutos; "h" o "H" para horas; "d" o "D" para días). Por ejemplo, un valor de "10/1h" limita los reinicios a 10 en una hora. No hay valor por defecto, lo que significa que la tasa de reinicio no está limitada.
Background (Booleano)
Hace que opendkim se bifurque y salga inmediatamente, dejando el servicio ejecutándose en segundo plano. El valor por defecto es "true".
BaseDirectory (cadena)
Si se establece, instruye al filtro para que cambie al directorio especificado usando chdir(2) antes de hacer cualquier otra cosa. Esto significa que cualquier archivo referenciado en otras partes del archivo de configuración se puede especificar en relación con este directorio. También es útil para asegurar que cualquier volcado de errores se guarde en una ubicación específica.
BodyLengthDB (conjunto de datos)
Solicita que opendkim incluya una etiqueta de longitud del cuerpo "l=" cuando el conjunto contenga alguna de las direcciones del destinatario del sobre. Las direcciones presentadas se prueban contra la base de datos en varias formas, como se describe en la configuración SigningTable (abajo). Esta característica del protocolo existe para mejorar la probabilidad de que una firma sobreviva al tránsito a través de un servidor de listas de correo, ya que comúnmente agregan pies de página a los mensajes. Tenga en cuenta, sin embargo, que esto crea un problema de seguridad potencial, ya que alguien podría agregar texto arbitrario al mensaje firmado y la firma aún validaría. Consulte la especificación DKIM para obtener detalles.
BogusKey (cadena)
Instruye al filtro para que trate una firma que pasa asociada con una clave falsa (forjada) de una manera especial. Los valores posibles son neutral (devuelve un resultado "neutral"), none (no realiza ninguna acción especial) y fail (devuelve un resultado "fail"; este es el valor por defecto). (No habilitado para esta instalación).
CaptureUnknownErrors (Booleano)
Cuando está configurado, y en sistemas donde la cuarentena de MTA está disponible, el filtro solicitará la cuarentena de un mensaje que resulte en un error interno o agotamiento de recursos.
Canonicalization (cadena)
Selecciona el(los) método(s) de canonización a utilizar al firmar mensajes. Al verificar, el campo de encabezado DKIM-Signature: del mensaje especifica el método de canonización. Los valores reconocidos son relaxed y simple según lo definido por la especificación DKIM. El valor por defecto es simple. El valor puede incluir dos canonizaciones diferentes separadas por un carácter de barra ("/"), en cuyo caso la primera se aplicará a la cabecera y la segunda al cuerpo.
ChangeRootDirectory (cadena)
Solicita que el sistema operativo cambie el directorio raíz efectivo del proceso al especificado aquí antes de comenzar la ejecución. chroot(2) requiere acceso de superusuario. Se generará una advertencia si UserID tampoco está configurado.
ClockDrift (entero)
Establece la tolerancia en segundos a aplicar al determinar si una firma había expirado o se generó en el futuro. El valor por defecto es 300.
Diagnostics (Booleano)
Solicita la inclusión de etiquetas "z=" en las firmas, que codifican el conjunto de campos de encabezado original para que los verificadores lo utilicen al diagnosticar fallos de verificación. No se recomienda para operaciones normales.
DiagnosticDirectory (cadena)
BadSignatureLog (string)
Directorio en el que escribir los informes de diagnóstico cuando la verificación del mensaje falla en un mensaje que lleva una etiqueta "z=". Si no se establece (por defecto), estos archivos no se generan.
DisableCryptoInit (Boolean)
Si se establece, omite la inicialización de los pasos de inicialización de la biblioteca SSL, que normalmente se requieren en entornos multihilo. Esto asume que alguna otra biblioteca que opendkim está utilizando realizará la inicialización y el cierre requeridos.
DNSConnect (Boolean)
Solicita que el resolvedor asíncrono comience a usar TCP inmediatamente en lugar de usar UDP hasta que TCP sea realmente necesario. No funciona con todos los resolvedores.
DNSTimeout (integer)
Establece el tiempo de espera de DNS en segundos. Un valor de 0 provoca una espera infinita. El valor por defecto es 5. Se ignora si no se utiliza un paquete de resolución asíncrono. Consulte también la sección de NOTAS a continuación.
Domain (dataset)
Un conjunto de dominios cuyo correo debe ser firmado por este filtro. El correo de otros dominios se verificará en lugar de ser firmado.

Este parámetro no es necesario si se está utilizando una SigningTable; en ese caso, la lista de dominios firmados se infiere de las líneas de ese archivo.

Este parámetro se ignora si se define una KeyTable.

DomainKeysCompat (boolean)
Si se establece, se habilita la compatibilidad con versiones anteriores de los registros de claves de DomainKeys (RFC4870). Cuando no se establece, dichas claves se consideran sintácticamente inválidas.
DontSignMailTo (dataset)
Un conjunto de direcciones de correo electrónico a las que el correo nunca debe ser firmado por el filtro. Tenga en cuenta que esta es una característica de "cualquiera"; si alguno de los destinatarios del mensaje coincide con un miembro de esta lista, el mensaje no se firmará.
EnableCoredumps (boolean)
En sistemas que tienen dicho soporte, se realiza una solicitud explícita al kernel para volcar núcleos cuando el filtro falla por alguna razón. Algunos sistemas UNIX modernos suprimen los volcamientos de núcleo durante fallos por razones de seguridad si el ID de usuario ha cambiado durante la vida del proceso. Actualmente solo soportado en Linux.
ExemptDomains (dataset)
Especifica un conjunto de dominios, cuyo correo debe ser ignorado por completo por el filtro. Esto es similar a la configuración de PeerList, excepto que basa su decisión en el remitente del mensaje identificado a partir de los campos de encabezado u otros datos del mensaje, no en la identidad del cliente SMTP que envía el mensaje.
ExternalIgnoreList (dataset)
Identifica un conjunto de hosts "externos" que pueden enviar correo a través del servidor como uno de los dominios de firma sin las credenciales correspondientes. Esto tiene el efecto de suprimir los mensajes de registro de "el host externo (hostname) intentó enviar correo como (dominio)". Las entradas en el conjunto de datos deben tener el mismo formato que las de la opción PeerList a continuación. El conjunto está vacío por defecto.
FinalPolicyScript (string)
Proporciona el nombre de un script Lua que debe ejecutarse después de que se haya recibido el mensaje completo. Esto se puede utilizar para aplicar decisiones de política local como el rechazo del mensaje, la cuarentena, el reenvío, etc., basándose en las firmas encontradas en el mensaje, los resultados de los intentos de verificarlas y otras propiedades del mensaje o las firmas. Consulte opendkim-lua(3) para obtener detalles. (No habilitado para esta instalación).
FixCRLF (Boolean)
Solicita que la biblioteca DKIM convierta CRs y LFs sin formato en CRLFs durante la canonicación del cuerpo, anticipando que un MTA en algún lugar antes de la entrega realizará esa conversión de todos modos. El valor predeterminado es dejarlos como están.
IdentityHeader (string)
Esto especifica el campo de encabezado donde se almacena una identidad. (Característica experimental no habilitada para esta instalación).
IdentityHeaderRemove (Boolean)
Elimina el IdentityHeader después de firmar. (Característica experimental no habilitada para esta instalación).
IgnoreMalformedMail (boolean)
Pasa silenciosamente mensajes malformados sin alteración. Esto incluye mensajes que fallan la verificación de RequiredHeaders, si está habilitada. El valor predeterminado es pasar esos mensajes pero agregar un campo Authentication-Results que indique que estaban mal formados.
Include (string)
Nombra un archivo para abrir y leer como un archivo de configuración adicional. Se permite anidamiento hasta un máximo de cinco niveles.
InternalHosts (dataset)
Identifica un conjunto de hosts internos cuyo correo debe ser firmado en lugar de verificado. Las entradas en este conjunto de datos siguen el mismo formato que las de la opción PeerList a continuación. Si no se especifica, se aplica el valor predeterminado de "127.0.0.1". Naturalmente, proporcionar un valor aquí anula el valor predeterminado, por lo que si el correo de 127.0.0.1 debe ser firmado, la lista proporcionada aquí debe incluir esa dirección explícitamente.
KeepAuthResults (boolean)
Suprime la eliminación de los campos de encabezado Authentication-Results que contienen resultados de DKIM aparentemente agregados por este filtro (generalmente el resultado de una mala configuración o una falsificación).
KeepTemporaryFiles (boolean)
Instruye al filtro para que cree archivos temporales que contengan las canonicaciones de encabezado y cuerpo de los mensajes que se firman o verifican. La ubicación de estos archivos se puede establecer utilizando el parámetro TemporaryDirectory. Destinado solo a la depuración de problemas de verificación.
KeyFile (string)
Proporciona la ubicación de una clave privada en formato PEM que se utilizará para firmar todos los mensajes. Se ignora si se define una KeyTable.
KeyTable (dataset)
Proporciona la ubicación de un archivo que mapea nombres de claves a claves de firma. Si está presente, anula cualquier configuración de KeyFile en el archivo de configuración. El conjunto de datos denominado aquí mapea cada nombre de clave a tres valores: (a) el nombre del dominio a utilizar en el valor "d=" de la firma; (b) el nombre del selector a utilizar en el valor "s=" de la firma; y (c) una clave privada o una ruta a un archivo que contiene una clave privada. Si el primer valor consiste únicamente en un signo de porcentaje ("%"), se reemplazará por el dominio aparente del remitente al generar una firma. Si el tercer valor comienza con un carácter de barra ("/"), o "./" o "../", entonces se presume que se refiere a un archivo del cual se debe leer la clave privada, de lo contrario, es en sí misma una clave privada codificada en PEM o una clave privada DER codificada en base64; un "%" en el tercer valor en este caso se reemplazará por el nombre de dominio aparente del remitente. La SigningTable (ver más abajo) se utiliza para seleccionar registros de esta tabla que se utilizarán para agregar firmas basadas en el remitente del mensaje.
LDAPAuthMechanism (string)
Nombra el mecanismo de autenticación a utilizar al conectarse a un servidor LDAP. El valor predeterminado es una cadena vacía, lo que significa que se debe realizar la autenticación "simple".
LDAPAuthName (string)
Especifica el nombre de autenticación a utilizar al usar SASL para autenticarse en un servidor LDAP. Requiere que el soporte SASL esté instalado en el sistema local. No hay valor predeterminado.
LDAPAuthRealm (string)
Especifica el reino de autenticación a utilizar al usar SASL para autenticarse en un servidor LDAP. Requiere que el soporte SASL esté instalado en el sistema local. No hay valor predeterminado.
LDAPAuthUser (string)
Especifica el usuario de autenticación a utilizar al usar SASL para autenticarse en un servidor LDAP. Requiere que el soporte SASL esté instalado en el sistema local. No hay valor predeterminado.
LDAPBindPassword (string)
Especifica la contraseña a utilizar al realizar una operación de "bind" LDAP. No hay valor predeterminado.
LDAPBindUser (string)
Especifica el ID de usuario a utilizar al realizar una operación de "bind" LDAP. No hay valor predeterminado.
LDAPDisableCache (Boolean)
Suprime la creación de una caché local delante de las consultas LDAP.
LDAPKeepaliveIdle (integer)
Establece el número de segundos que una conexión a un servidor LDAP debe permanecer inactiva antes de que TCP comience a enviar sondas de mantenimiento de conexión. Si no se especifica, se utiliza el valor predeterminado de la biblioteca LDAP.
LDAPKeepaliveInterval (integer)
Establece el intervalo en segundos entre las sondas de mantenimiento de conexión TCP. Si no se especifica, se utiliza el valor predeterminado de la biblioteca LDAP.
LDAPKeepaliveProbes (integer)
Establece el número máximo de sondas de mantenimiento de conexión que TCP debe enviar antes de abandonar la conexión. Si no se especifica, se utiliza el valor predeterminado de la biblioteca LDAP.
LDAPTimeout (integer)
Establece el tiempo en segundos después del cual se debe abandonar una operación LDAP. El valor predeterminado es 5.

On-NoSignature (cadena)
Selecciona la acción a tomar cuando llega un mensaje sin firmar. Los valores posibles son los mismos que los de On-BadSignature. El valor predeterminado es accept.
On-Security (cadena)
Selecciona la acción a tomar cuando llega un mensaje que contiene propiedades que pueden ser una preocupación de seguridad. Los valores posibles son los mismos que los de On-BadSignature. El valor predeterminado es tempfail.
On-SignatureError (cadena)
Selecciona la acción a tomar cuando un mensaje no puede ser firmado debido a problemas con el mensaje o con la clave proporcionada para la firma. Los valores posibles son los mismos que los de On-BadSignature. El valor predeterminado es reject.
OversignHeaders (conjunto de datos)
Especifica un conjunto de campos de encabezado que deben incluirse en todas las listas de encabezados de firma (la etiqueta "h=") una vez más que el número de veces que estuvieron realmente presentes en el mensaje firmado. El conjunto está vacío por defecto. El propósito de esto, y especialmente de listar un campo de encabezado ausente, es evitar la adición de campos importantes entre el firmante y el verificador. Dado que el verificador incluiría ese campo de encabezado al realizar la verificación si hubiera sido agregado por un intermediario, el mensaje firmado y el mensaje verificado serían diferentes y la verificación fallaría. Tenga en cuenta que listar un nombre de campo aquí y no listarlo en la lista SignHeaders probablemente generará firmas inválidas.
PeerList (conjunto de datos)
Identifica un conjunto de "peers" que identifica a los clientes cuyas conexiones deben ser aceptadas sin procesamiento por este filtro. El conjunto debe contener en cada línea un nombre de host, un nombre de dominio (por ejemplo, ".example.com"), una dirección IP, una dirección IPv6 (incluida una dirección IPv4 mapeada) o una especificación de IP de estilo CIDR (por ejemplo, "192.168.1.0/24").

Una entrada que comienza con un signo de exclamación ("!") significa "no", lo que permite excluir hosts específicos que de otro modo serían miembros de conjuntos más grandes. Los nombres de host y dominio se comparan primero, luego la dirección IP o IPv6 según el tipo de conexión. Las entradas más precisas se prefieren sobre las menos precisas, es decir, "192.168.1.1" coincidirá antes que "!192.168.1.0/24".

La forma de texto de las direcciones IPv6 se forzará a minúsculas cuando se consulten (RFC5952), por lo que el contenido de este conjunto de datos también debe usar minúsculas. La notación CIDR debe usar 0 para todos los bits no enmascarados (por ejemplo, "10.0.0.1/8" nunca coincidirá). Las direcciones IPv6, ya sean únicas o en notación CIDR, deben aparecer en la forma producida por inet_ntop(3), que reemplaza los ceros consecutivos con "::" (por ejemplo, "0:0:0:0:0:0:0:1" nunca coincidirá). La parte de la dirección IP de una entrada puede contener opcionalmente corchetes; se comprobarán ambas formas (con y sin).

NAME

opendkim.conf

configuration file for OpenDKIM

LOCATION

/etc/opendkim.conf

DESCRIPTION

The configuration file is used to control the operation of the OpenDKIM milter. The file is a plain ASCII file that is parsed based on keywords and values. Blank lines and lines starting with the hash character (#) are ignored. Keywords are case sensitive.

Most keywords are followed by a value, which may be a string, an integer, a boolean, or a list of values. Values that contain spaces must be quoted. Booleans can be indicated by true/false, yes/no, or 1/0. Lists are typically colon-separated.

The configuration file is searched for in the following locations:

  • The current working directory.
  • The directory specified by the -c command line option.
  • The directory specified by the OpenDKIM_CONFIG_DIR environment variable.
  • The default location of /etc/opendkim.conf.

If no configuration file is found, OpenDKIM will use its built-in defaults.

UMask (integer)
Requests a specific permissions mask to be used for file creation. This only really applies to creation of the socket when Socket specifies a UNIX domain socket, and to the PidFile (if any); temporary files are created by the mkstemp(3) function that enforces a specific file mode on creation regardless of the process umask. See umask(2) for more information.
UnprotectedKey (string)
Instructs the filter to treat a passing signature associated with a key found in an insecure (i.e. not protected by DNSSEC) DNS record in a special way. Possible values are neutral (return a "neutral" result), none (take no special action; this is the default) and fail (return a "fail" result). (Not enabled for this installation.)
UserID (string)
Attempts to become the specified userid before starting operations. The value is of the form userid[:group]. The process will be assigned all of the groups and primary group ID of the named userid unless an alternate group is specified.
VBR-Certifiers (string)
The default certifiers if not specified in X-VBR-Certifiers header field. (Experimental feature not enabled for this installation.)
VBR-PurgeFields (string)
If set, arranges to remove X-VBR-Certifiers and X-VBR-Type fields on messages prior to sending them. (Experimental feature not enabled for this installation.)
VBR-TrustedCertifiers (string)
A colon or comma sparated list of trusted certifiers to accept when verifying VBR-Info header field. (Experimental feature not enabled for this installation.)
VBR-TrustedCertifiersOnly (Boolean)
By default, the certifiers that are in both the trusted certifiers list (above) and those in the message's VBR-Info header field will be checked for vouching. With this option set, the trusted certifiers will be checked and the ones claimed by the message will be ignored. (Experimental feature not enabled for this installation.)
VBR-Type (string)
This default VBR type if not specified in the X-VBR-Type header field. (Experimental feature not enabled for this installation.)
WeakSyntaxChecks (Boolean)
Requests that the library continue processing messages even if syntax errors are discovered early in message analysis. This means, for example, that a signed message with a mangled From: field will still proceed to verification even if the author's domain could not be determined.

NOTES

When using DNS timeouts (see the DNSTimeout option above), be sure not to use a timeout that is larger than the timeout being used for interaction between sendmail and the filter. Otherwise, the MTA could abort a message while waiting for a reply from the filter, which in turn is still waiting for a DNS reply.

Features that involve specification of IPv4 addresses or CIDR blocks will use the inet_addr(3) function to parse that information. Users should be familiar with the way that function handles the non-trivial cases (for example, "192.0.2/24" and "192.0.2.0/24" are not the same thing).
