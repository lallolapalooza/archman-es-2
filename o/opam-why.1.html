OPAM-WHY(1) Manual de Opam OPAM-WHY(1)

NOMBRE

opam-why - Un alias para tree --rev-deps.

SINOPSIS

opam why [--recursive] [--subpath=RUTA] [OPCIÓN]… [PAQUETES]…

DESCRIPCIÓN

opam why es un alias para opam tree --rev-deps.

Ver opam tree --help para detalles.

OPCIONES DE FILTRADO DE ÁRBOLES

--leads-to
Mostrar solo las ramas que conducen a uno de los PAQUETES.
--roots-from
Mostrar solo los árboles que tienen sus raíces en uno de los PAQUETES (este es el valor predeterminado).

OPCIONES DE CONSTRUCCIÓN DE ÁRBOLES

--deps
Dibujar un bosque de dependencias, comenzando desde los paquetes que no son requeridos por ningún otro paquete (este es el valor predeterminado).
--rev-deps
Dibujar un bosque de dependencias inversas, comenzando desde los paquetes que no tienen dependencias.

OPCIONES DE SELECCIÓN DE PAQUETES

--dev
Incluir paquetes de desarrollo en las dependencias.
--no-switch
Ignorar el switch activo y simular la instalación de paquetes desde un switch vacío para dibujar el bosque.
--post
Incluir dependencias etiquetadas como post.
-t, --with-test, --test
Incluir dependencias solo de prueba.
--with-dev-setup
Incluir dependencias solo de desarrollo.
--with-doc, --doc
Incluir dependencias solo de documentación.

OPCIONES DE FORMATO DE SALIDA

--no-constraint
No mostrar las restricciones de versión, por ejemplo (>= 1.0.0).

ARGUMENTOS

PAQUETES
Lista de nombres de paquetes, con una versión o restricción opcional, por ejemplo `pkg', `pkg.1.0' o `pkg>=0.5'; o nombres de archivos o directorios que contienen descripciones de paquetes, con directorio explícito (por ejemplo, `./foo.opam' o `.').

OPCIONES

--recursive
Permitir búsquedas recursivas de archivos *.opam. Cf. --subpath también.
--subpath=RUTA
Los archivos *.opam se obtienen del directorio secundario dado en lugar del directorio principal. Las fuentes se toman del subdirectorio objetivo, y internamente solo se copia/descarga este subdirectorio. Se puede combinar con --recursive para realizar una búsqueda recursiva en el subdirectorio.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Usar la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Pensado para cualquier uso persistente de opam (scripts, publicaciones de blogs, etc.), cualquier versión de opam de la misma serie MAYOR se comportará como para la versión MENOR especificada. La bandera no estaba disponible en opam 2.0, por lo que para seleccionar la CLI de 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorear la salida. CUÁNDO debe ser uno de always, never o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar más de una vez. Si --yes o --no también se proporcionan, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especificar preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje admitido y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general para usar preferencias de solucionadores se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: Guardar las solicitudes CUDF enviadas al solucionador en NOMBRE_ARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprimir mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprimir la versión git de opam, si está establecida (es decir, si está usando una versión de desarrollo), y salir.
--help[=FORMATO] (predeterminado=auto)
Mostrar esta ayuda en formato FORMATO. El valor FORMATO debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain cuando la variable de entorno TERM es dumb o indefinida.
--ignore-pin-depends
Ignorar pines adicionales requeridos por paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guardar los resultados de la ejecución de opam en un archivo legible por máquina. Si el nombre de archivo contiene el carácter `%`, se reemplazará por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responder no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato anterior. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=RAÍZ
Usar RAÍZ como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a RAÍZ.
--safe, --readonly
Asegurarse de que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de finalización, por ejemplo. Fallará siempre que dicha operación sea necesaria; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especificar el solucionador CUDF a usar para resolver problemas de instalación de paquetes. Este es un solucionador predefinido (esta versión de opam admite builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Fallar siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--test
Equivalente a --with-test.
--unfiltered
No filtrar los paquetes que no se corresponden con el nombre del paquete.
-v, --verbose
Imprimir mensajes detallados a stderr.
--version
Mostrar información sobre la versión y salir.
--yes
Responder sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

VER TAMBIÉN

opam-tree(1), opam(1).

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

--switch=SWITCH
Use SWITCH como el compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo y usa el incorporado (esto requiere que opam haya sido compilado con un solucionador incorporado). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más verboso. Una llamada a -v muestra todos los comandos de paquetes, repite para también mostrar los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.). Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Cada vez que actualices paquetes que estén vinculados a un directorio local controlado por versión, actualiza al estado de trabajo actual de su fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio de origen se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

ENTORNO

Opam utiliza las variables de entorno listadas aquí. Las variables booleanas deben establecerse en "0", "no", "false" o la cadena vacía para deshabilitar, "1", "yes" o "true" para habilitar.

OPAMALLPARENS rodea todos los filtros con paréntesis.

OPAMASSUMEDEPEXTS ver opción `--assume-depexts'.

OPAMAUTOREMOVE ver opción de eliminación `--auto-remove'.

OPAMBESTEFFORT ver opción `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA establece la cadena que debe anteponerse al criterio cuando se establece la opción `--best-effort', y se espera que maximice la propiedad `opam-query' en la solución.

OPAMBUILDDOC Eliminado en 2.1.

OPAMBUILDTEST Eliminado en 2.1.

OPAMCLI ver opción `--cli'.

OPAMCOLOR cuando se establece en always o never, establece un valor predeterminado para la opción `--color'.

OPAMCONFIRMLEVEL ver opción `--confirm-level`. OPAMCONFIRMLEVEL tiene prioridad sobre OPAMYES y OPAMNO.

OPAMCRITERIA especifica las preferencias del usuario para la resolución de dependencias. El valor predeterminado depende de la versión del solucionador, usa `config report' para conocer la configuración actual. Ver también la opción --criteria.

OPAMCUDFFILE guarda el gráfico cudf en el archivo -actions-explicit.dot.

OPAMCUDFTRIM controla el filtrado de paquetes no relacionados durante el preprocesamiento de CUDF.

OPAMCURL se puede usar para seleccionar un programa 'curl' dado. Ver OPAMFETCH para más opciones.

OPAMDEBUG ver opciones `--debug' y `--debug-level'.

OPAMDEBUGSECTIONS si está establecido, limita los mensajes de depuración a la lista de secciones separadas por espacios. Las secciones pueden tener opcionalmente un nivel de depuración específico (por ejemplo, CLIENT:2 o CLIENT CUDF:2), pero de lo contrario utilizan `--debug-level'.

OPAMDIGDEPTH define cuán agresiva es la búsqueda de conflictos durante el preprocesamiento de CUDF.

OPAMDOWNLOADJOBS establece el número máximo de descargas simultáneas.

OPAMDROPWORKINGDIR anula los paquetes actualizados previamente con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se nombren explícitamente en la línea de comandos.

OPAMDRYRUN ver opción `--dry-run'.

OPAMEDITOR establece el editor a usar para editar archivos opam, anula $EDITOR y $VISUAL.

OPAMERRLOGLEN establece el número de líneas de registro impresas cuando falla un subproceso. 0 para imprimir todas.

OPAMEXTERNALSOLVER ver opción `--solver'.

OPAMFAKE ver opción `--fake'.

OPAMFETCH especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor de 'download-command' del archivo de configuración principal.

OPAMFIXUPCRITERIA igual que OPAMUPGRADECRITERIA, pero específico para correcciones e reinstalaciones.

OPAMIGNORECONSTRAINTS ver opción de instalación `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS ver opción `--ignore-pin-depends'.

OPAMINPLACEBUILD ver opción `--inplace-build'.

OPAMJOBS establece el número máximo de trabajadores paralelos a ejecutar.

OPAMJSON registra la salida json en el archivo dado (usa el carácter `%' para indexar los archivos).

OPAMKEEPBUILDDIR ver opción de instalación `--keep-build-dir'.

OPAMKEEPLOGS le dice a opam que no elimine algunos registros temporales de comandos y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener backtraces más fiables.

OPAMLOCKED combinación de las opciones `--locked' y `--lock-suffix'.

OPAMLOGS logdir establece el directorio de registro, el valor predeterminado es un directorio temporal en /tmp

OPAMMAKECMD establece el comando make del sistema a usar.

OPAMMERGEOUT fusiona las salidas del proceso, stderr en stdout.

OPAMNO responde no a cualquier pregunta realizada, ver opciones `--no` y `--confirm-level`. OPAMNO se ignora si OPAMCONFIRMLEVEL o OPAMYES están establecidos.

OPAMNOAGGREGATE con `opam admin check', no agrega paquetes.

OPAMNOASPCUD Obsoleto.

OPAMNOAUTOUPGRADE deshabilita la actualización automática interna de repositorios en un formato anterior al actual, en 'update' o 'init'.

OPAMNOCHECKSUMS habilita la opción --no-checksums cuando esté disponible.

OPAMNODEPEXTS deshabilita el manejo de dependencias del sistema, ver opción `--no-depexts'.

OPAMNOENVNOTICE Interno.

OPAMNOSELFUPGRADE ver opción `--no-self-upgrade'

OPAMPINKINDAUTO establece si los sistemas de control de versiones deben detectarse al fijar a una ruta local. Habilitado por defecto desde 1.3.0.

OPAMPRECISETRACKING seguimiento detallado de directorios.

OPAMPREPRO establece esto en false para deshabilitar el preprocesamiento de CUDF. Menos eficiente, pero puede ayudar a depurar problemas del solucionador.

OPAMREPOSITORYTARRING almacena internamente los repositorios como archivos tar.gz. Esto puede ser mucho más rápido en sistemas de archivos que no manejan bien el escaneo de árboles grandes pero que tienen una buena caché en /tmp. Sin embargo, es más lento en el caso general.

OPAMREQUIRECHECKSUMS Habilita la opción `--require-checksums' cuando esté disponible (por ejemplo, para `opam install').

OPAMRETRIES establece el número de intentos antes de fallar las descargas.

OPAMREUSEBUILDDIR ver opción `--reuse-build-dir'.

OPAMROOT ver opción `--root'. Esto se establece automáticamente mediante `opam env --root=DIR --set-root'.

OPAMROOTISOK no se queja al ejecutarse como root.

OPAMSAFE ver opción `--safe'.

OPAMSHOW ver opción `--show'.

OPAMSKIPUPDATE ver opción `--skip-updates'.

OPAMSKIPVERSIONCHECKS omite algunas verificaciones de versión. Inseguro, solo para pruebas de compatibilidad.

OPAMSOLVERALLOWSUBOPTIMAL (predeterminado `true') permite que algunos solucionadores devuelvan una solución cuando alcanzan el tiempo de espera; si bien se garantiza que la solución es coherente, no hay garantía en este caso de que se ajuste a los criterios de optimización esperados. Si es `true', opam continuará con una advertencia, si es `false' un tiempo de espera es un error. Actualmente solo el backend builtin-z3 maneja este caso degradado.

OPAMSOLVERTIMEOUT cambia el tiempo de asignación del solucionador. El valor predeterminado es 60.0, establecido en 0 para ilimitado. Tenga en cuenta que no todos los solucionadores pueden admitir esta opción.

OPAMSOLVERTOLERANCE cambia la tolerancia hacia la elección de una solución no optimizada por parte del solucionador (es decir, podría extraer paquetes obsoletos). Los valores típicos van desde 0.0 (mejor solución conocida por el solucionador) hasta 1.0 (solución no optimizada). El valor predeterminado es 0.0. Esta opción es útil en caso de que el solucionador no pueda encontrar una solución en un tiempo razonable (ver $OPAMSOLVERTIMEOUT). Tenga en cuenta que no todos los solucionadores pueden admitir esta opción.

OPAMSTATS Eliminado en 2.4.

OPAMSTATUSLINE muestra una línea de estado dinámica que muestra lo que está sucediendo actualmente en la terminal. (uno de always, never o auto)

OPAMSTRICT falla ante inconsistencias (lectura de archivos, importación de switch, etc.).

OPAMSWITCH ver opción `--switch'. Se establece automáticamente mediante `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE ver opción de instalación `--unlock-base'.

OPAMUPGRADECRITERIA especifica las preferencias del usuario para la resolución de dependencias al realizar una actualización. Anula OPAMCRITERIA en las actualizaciones si ambas están establecidas. Ver también la opción --criteria.

OPAMUSEINTERNALSOLVER ver opción `--use-internal-solver'.

OPAMUSEOPENSSL Eliminado en 2.2.

OPAMUTF8 utiliza caracteres UTF8 en la salida (uno de always, never o auto). Por defecto `auto', que se determina del locale).

OPAMUTF8MSGS utiliza caracteres UTF8 extendidos (camellos) en los mensajes de opam. Implica OPAMUTF8. Esto está configurado por defecto solo en macOS.

OPAMVALIDATIONHOOK si está establecido, utiliza el comando `%{hook%}' para validar una actualización del repositorio opam.

OPAMVERBOSE ver opción `--verbose'.

OPAMVERBOSEON ver opción --verbose-on

OPAMVERSIONLAGPOWER no usar.

OPAMWITHDEVSETUP ver opción de instalación `--with-dev-setup'.

OPAMWITHDOC ver opción de instalación `--with-doc'.

OPAMWITHTEST ver opción de instalación `--with-test.

OPAMWORKINGDIR ver opción `--working-dir'.

OPAMYES ver opciones `--yes' y `--confirm-level`. OPAMYES tiene prioridad sobre OPAMNO y se ignora si OPAMCONFIRMLEVEL está establecido.

OPAMVAR_var anula el contenido de la variable var al sustituir cadenas `%{var}%` en archivos `opam`.

OPAMVAR_package_var anula el contenido de la variable package:var al sustituir cadenas `%{package:var}%` en archivos `opam`.

VERSIÓN_CLI

VERSIÓN DEL CLI

Todos los scripts y las invocaciones programáticas de opam deben usar `--cli' para garantizar que funcionen sin problemas con las futuras versiones del cliente de opam. Además, las entradas de blog u otra documentación pueden beneficiarse, ya que evita que la información se vuelva obsoleta.

Aunque opam solo admite raíces (~/.opam/) para la versión actual, proporciona retrocompatibilidad para su interfaz de línea de comandos.

Dado que la compatibilidad con la versión del CLI solo se añadió en opam 2.1, use OPAMCLI para seleccionar la compatibilidad con 2.0 (ya que opam 2.0 simplemente la ignorará), y `--cli=2.1' para las versiones 2.1 (o posteriores), ya que una variable de entorno que controla el análisis de la sintaxis es frágil. Con este fin, opam muestra una advertencia si OPAMCLI especifica una versión válida distinta de 2.0, y también si se especifica `--cli=2.0'.

La versión de la línea de comandos se selecciona mediante la opción `--cli' o la variable de entorno OPAMCLI. Se puede especificar `--cli' más de una vez, donde la última instancia tiene prioridad. OPAMCLI solo se inspecciona si no se proporciona `--cli'.

ESTADO DE SALIDA

Como excepción a lo siguiente, el comando `exec' devuelve 127 si el comando no se encontró o no se pudo ejecutar, y el valor de salida del comando en caso contrario.

0
Éxito, o verdadero para consultas booleanas.
1
Falso. Devuelto cuando se espera un valor booleano, por ejemplo, al ejecutar con --check, o para consultas como opam lint.
2
Argumentos de línea de comandos incorrectos, o argumentos de línea de comandos que apuntan a un contexto inválido (por ejemplo, un archivo que no sigue el formato esperado).
5
No encontrado. Solicitó algo (paquete, versión, repositorio, etc.) que no se pudo encontrar.
10
Abortado. La operación requería confirmación, que no se proporcionó.
15
No se pudieron adquirir los bloqueos necesarios para la operación.
20
No hay solución para la solicitud del usuario. Esto puede ser causado por solicitar la instalación de dos paquetes incompatibles, por ejemplo.
30
Error en la definición del paquete u otros archivos de metadatos. El uso de --strict genera este error con más frecuencia.
31
Error en el script del paquete. Algunas operaciones del paquete no tuvieron éxito. Esto puede ser un error en los paquetes o una incompatibilidad con su sistema. Este puede ser un error parcial.
40
Error de sincronización. No se pudieron obtener algunos remotos de la red. Este puede ser un error parcial.
50
Error de configuración. La configuración de Opam o del sistema no permite la operación y necesita ser corregida.
60
Fallo del solucionador. El solucionador no pudo devolver una respuesta sólida. Puede ser debido a un solucionador externo roto o a un error en la configuración del solucionador.
99
Error interno. Algo salió mal, probablemente debido a un error en el propio opam.
130
Interrupción del usuario. Se recibió SIGINT, generalmente debido a que el usuario presionó Ctrl-C.
0
en caso de éxito.
123
en errores indiscriminados reportados en la salida estándar.
124
en errores de análisis de línea de comandos.
125
en errores internos inesperados (bugs).
