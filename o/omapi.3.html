omapi(3) Manual de funciones de biblioteca omapi(3)

NOMBRE

OMAPI - Interfaz de Programación de Aplicaciones de Gestión de Objetos

DESCRIPCIÓN

OMAPI es una capa de programación diseñada para controlar aplicaciones remotas y consultarlas sobre su estado. Actualmente es utilizada por el servidor DHCP de ISC y este resumen aborda las partes de OMAPI apropiadas para los clientes del servidor DHCP. Lo hace describiendo también el uso de una API delgada sobre OMAPI llamada `dhcpctl`.

OMAPI utiliza TCP/IP como transporte para la comunicación del servidor, y la seguridad se puede imponer haciendo que el cliente y el servidor firmen criptográficamente los mensajes utilizando un secreto compartido.

dhcpctl funciona presentando al cliente identificadores para objetos que actúan como sustitutos de los objetos reales en el servidor. Por ejemplo, un cliente creará un identificador para un objeto de concesión y solicitará al servidor que complete el estado del identificador de concesión. La aplicación cliente puede luego extraer detalles como la hora de expiración de la concesión del identificador de concesión.

Las modificaciones se pueden realizar en el estado del servidor creando identificadores para nuevos objetos o modificando atributos de identificadores para objetos existentes, y luego instruyendo al servidor para que se actualice de acuerdo con los cambios realizados.

USO

La aplicación cliente siempre debe llamar a dhcpctl_initialize() antes de realizar llamadas a otras funciones de dhcpctl. Esto inicializa varias estructuras de datos internas.

Para crear la conexión con el servidor, el cliente debe utilizar la función dhcpctl_connect(). Además de establecer la conexión física, también configurará las estructuras de datos de conexión para realizar la autenticación en cada mensaje, si es necesario.

Todas las funciones de dhcpctl devuelven un valor entero de tipo isc_result_t. Una llamada exitosa producirá un resultado de ISC_R_SUCCESS. Si la llamada falla por una razón local al cliente (por ejemplo, memoria local insuficiente o argumentos inválidos para la llamada), el valor de retorno de la función dhcpctl lo mostrará. Si la llamada tiene éxito pero el servidor no pudo procesar la solicitud, el valor de error del servidor se devuelve de otra manera, como se muestra a continuación.

La forma más fácil de entender dhcpctl es viéndolo en acción. El siguiente programa es completamente funcional, pero se ha eliminado casi toda la verificación de errores para hacerlo más corto y fácil de entender. Este programa consultará al servidor que se ejecuta en localhost los detalles de la concesión para la dirección IP 10.0.0.101. Luego imprimirá la hora en que expira la concesión.

#include <stdarg.h>
#include <sys/time.h>
#include <sys/socket.h>
#include <stdio.h>
#include <netinet/in.h>
#include <isc/result.h>
#include <dhcpctl/dhcpctl.h>
int main (int argc, char **argv) {
	dhcpctl_data_string ipaddrstring = NULL;
	dhcpctl_data_string value = NULL;

Todas las modificaciones de identificadores y todos los accesos a datos de identificadores se realizan a través de objetos dhcpctl_data_string.

dhcpctl_handle connection = NULL;
dhcpctl_handle lease = NULL;
isc_result_t waitstatus;
struct in_addr convaddr;
time_t thetime;
dhcpctl_initialize ();

Primer paso requerido.

dhcpctl_connect (&connection, "127.0.0.1",
		 7911, 0);

Establece la conexión con el servidor. El servidor normalmente escucha en el puerto 7911 a menos que esté configurado de otra manera.

dhcpctl_new_object (&lease, connection,
		    "lease");

Aquí creamos un identificador para una concesión. Esta llamada solo configura la estructura de datos local. El servidor aún no ha establecido ninguna asociación entre la estructura de datos del cliente y ninguna concesión que tenga.

memset (&ipaddrstring, 0, sizeof
	ipaddrstring);
inet_pton(AF_INET, "10.0.0.101",
	  &convaddr);
omapi_data_string_new (&ipaddrstring,
		       4, MDL);

Crea una nueva cadena de datos para almacenar en el identificador.

memcpy(ipaddrstring->value, &convaddr.s_addr, 4);
dhcpctl_set_value (lease, ipaddrstring,
		   "ip-address");

Estamos estableciendo el atributo ip-address del identificador de concesión a la dirección dada. No hemos establecido ningún otro atributo, por lo que cuando el servidor haga la asociación, la dirección IP será todo lo que utilizará para buscar la concesión en sus tablas.

dhcpctl_open_object (lease, connection, 0);

Aquí iniciamos la conexión con la solicitud para buscar la concesión en el servidor y llenar el identificador local con los atributos que el servidor enviará en su respuesta.

dhcpctl_wait_for_completion (lease,
			     &waitstatus);

Esta llamada hace que el mensaje se envíe al servidor (el mensaje para buscar la concesión y enviar los valores de los atributos en la respuesta). El valor en la variable waitstatus cuando la función regrese será el resultado del servidor. Si el mensaje no pudo ser procesado correctamente por el servidor, el error se reflejará aquí.

if (waitstatus != ISC_R_SUCCESS) {
	/* server not authoritative */
	exit (0);
}
dhcpctl_data_string_dereference(&ipaddrstring,
				MDL);

Limpia la memoria que ya no necesitamos.

dhcpctl_get_value (&value, lease, "ends");

Obtiene el atributo llamado "ends" del identificador de concesión. Es un entero de 4 bytes de la hora (en segundos de la época Unix) en que expirará la concesión.

	memcpy(&thetime, value->value, value->len);
	dhcpctl_data_string_dereference(&value, MDL);
	fprintf (stdout, "ending time is %s",
		 ctime(&thetime));
}

AUTENTICACIÓN

Si el servidor exige conexiones autenticadas, antes de abrir la conexión, el usuario debe llamar a dhcpctl_new_authenticator.

		dhcpctl_handle authenticator = NULL;
		const char *keyname = "a-key-name";
		const char *algorithm = "hmac-md5";
		const char *secret = "a-shared-secret";
		dhcpctl_new_authenticator (&authenticator,
                                           keyname,
                                           algorithm,
                                           secret,
					   strlen(secret) + 1);

El nombre de clave (keyname), el algoritmo (algorithm) y el secreto (secret) deben coincidir con lo especificado en el archivo dhcpd.conf del servidor, excepto que el secreto debe aparecer en forma "cruda" (raw), no en base64 como estaría en dhcpd.conf:

key "a-key-name" {
	algorithm hmac-md5;
	secret "a-shared-secret";
};
# Set the omapi-key value to use
# authenticated connections
omapi-key a-key-name;

El identificador de autenticación que se crea con la llamada a dhcpctl_new_authenticator debe pasarse como el último (el cuarto) argumento a la llamada a dhcpctl_connect(). Todos los mensajes se firmarán entonces con la cadena secreta dada utilizando el algoritmo especificado.
