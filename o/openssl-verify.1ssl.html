NOMBRE

openssl-verify - comando de verificación de certificados

SINOPSIS

openssl verify [-help] [-CRLfile archivo|uri] [-crl_download] [-show_chain] [-verbose] [-trusted archivo|uri] [-untrusted archivo|uri] [-vfyopt nm:v] [-nameopt opción] [-CAfile archivo] [-no-CAfile] [-CApath dir] [-no-CApath] [-CAstore uri] [-no-CAstore] [-engine id] [-allow_proxy_certs] [-attime timestamp] [-no_check_time] [-check_ss_sig] [-crl_check] [-crl_check_all] [-explicit_policy] [-extended_crl] [-ignore_critical] [-inhibit_any] [-inhibit_map] [-partial_chain] [-policy arg] [-policy_check] [-policy_print] [-purpose propósito] [-suiteB_128] [-suiteB_128_only] [-suiteB_192] [-trusted_first] [-no_alt_chains] [-use_deltas] [-auth_level num] [-verify_depth num] [-verify_email email] [-verify_hostname hostname] [-verify_ip ip] [-verify_name name] [-x509_strict] [-issuer_checks] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]key=valor] [-propquery propq] [--] [certificado ...]

DESCRIPCIÓN

Este comando verifica cadenas de certificados. Si una cadena de certificados tiene varios problemas, este programa intenta mostrarlos todos.

OPCIONES

-help
Muestra un mensaje de uso.
-CRLfile archivo|uri
El archivo o URI debe contener una o más CRLs en formato PEM o DER. Esta opción se puede especificar varias veces para incluir CRLs de múltiples fuentes.
-crl_download
Intenta descargar información de CRL para certificados a través de sus entradas CDP.
-show_chain
Muestra información sobre la cadena de certificados que se ha construido (si tiene éxito). Los certificados en la cadena que provienen de la lista no confiable se marcarán como "no confiable".
-verbose
Muestra información adicional sobre las operaciones que se están realizando.
-trusted archivo|uri
Un archivo o URI de certificados (más o menos) confiables. Consulte openssl-verification-options(1) para más información sobre la configuración de confianza.

Esta opción se puede especificar varias veces para cargar certificados de múltiples fuentes.

-untrusted archivo|uri
Un archivo o URI de certificados no confiables para usar en la construcción de la cadena. Esta opción se puede especificar varias veces para cargar certificados de múltiples fuentes.
-vfyopt nm:v
Pasa opciones al algoritmo de firma durante las operaciones de verificación. Los nombres y valores de estas opciones son específicos del algoritmo.
-nameopt opción
Esto especifica cómo se muestran los nombres del sujeto o del emisor. Consulte openssl-namedisplay-options(1) para detalles.
-engine id
Consulte "Opciones de motor" en openssl(1). Esta opción está obsoleta.

Para cargar certificados o CRLs que requieren soporte de motor, especifique la opción -engine antes de cualquiera de las opciones -trusted, -untrusted o -CRLfile.

-CAfile archivo, -no-CAfile, -CApath dir, -no-CApath, -CAstore uri, -no-CAstore
Consulte "Opciones de certificado confiable" en openssl-verification-options(1) para detalles.
-allow_proxy_certs, -attime, -no_check_time, -check_ss_sig, -crl_check, -crl_check_all, -explicit_policy, -extended_crl, -ignore_critical, -inhibit_any, -inhibit_map, -no_alt_chains, -partial_chain, -policy, -policy_check, -policy_print, -purpose, -suiteB_128, -suiteB_128_only, -suiteB_192, -trusted_first, -use_deltas, -auth_level, -verify_depth, -verify_email, -verify_hostname, -verify_ip, -verify_name, -x509_strict -issuer_checks
Establece varias opciones de verificación de la cadena de certificados. Consulte "Opciones de verificación" en openssl-verification-options(1) para detalles.
-provider nombre
-provider-path ruta
-provparam [nombre:]key=valor
-propquery propq
Consulte "Opciones de proveedor" en openssl(1), provider(7) y property(7).
--
Indica la última opción. Todos los argumentos que siguen se asumen que son archivos de certificado. Esto es útil si el nombre del primer archivo de certificado comienza con un -.
certificado ...
Uno o más certificados objetivo a verificar, uno por archivo. Si no se proporcionan certificados, este comando intentará leer un único certificado de la entrada estándar.

DIAGNÓSTICOS

Cuando una operación de verificación falla, los mensajes de salida pueden ser algo crípticos. La forma general del mensaje de error es:

server.pem: /C=AU/ST=Queensland/O=CryptSoft Pty Ltd/CN=Test CA (1024 bit)
error 24 at 1 depth lookup:invalid CA certificate

La primera línea contiene el nombre del certificado que se está verificando, seguido del nombre del sujeto del certificado. La segunda línea contiene el número de error y la profundidad. La profundidad es el número del certificado que se está verificando cuando se detectó un problema, comenzando con cero para el certificado objetivo (hoja) en sí, luego 1 para la CA que firmó el certificado objetivo, y así sucesivamente. Finalmente, se presenta una versión textual del número de error.

Una lista de los códigos y mensajes de error se puede encontrar en X509_STORE_CTX_get_error(3); la lista completa está definida en el archivo de cabecera <openssl/x509_vfy.h>.

Este comando ignora muchos errores, para permitir que se determinen todos los problemas con una cadena de certificados.

VER TAMBIÉN

openssl-verification-options(1), openssl-x509(1), ossl_store-file(7)

HISTORIA

La opción -show_chain se añadió en OpenSSL 1.1.0.

La opción -engine fue obsoleta en OpenSSL 3.0.
