DESCRIPCIÓN

La utilidad GNU objcopy copia el contenido de un archivo objeto a otro. objcopy utiliza la Biblioteca GNU BFD para leer y escribir los archivos objeto. Puede escribir el archivo objeto de destino en un formato diferente al del archivo objeto de origen. El comportamiento exacto de objcopy se controla mediante opciones de línea de comandos. Tenga en cuenta que objcopy debería ser capaz de copiar un archivo completamente enlazado entre dos formatos cualesquiera. Sin embargo, copiar un archivo objeto relocable entre dos formatos cualesquiera puede no funcionar como se espera.

objcopy crea archivos temporales para realizar sus traducciones y los elimina después. objcopy utiliza BFD para realizar todo su trabajo de traducción; tiene acceso a todos los formatos descritos en BFD y, por lo tanto, es capaz de reconocer la mayoría de los formatos sin que se le indique explícitamente.

objcopy se puede utilizar para generar registros S utilizando un objetivo de salida de srec (por ejemplo, use -O srec).

objcopy se puede utilizar para generar un archivo binario sin formato utilizando un objetivo de salida de binary (por ejemplo, use -O binary). Cuando objcopy genera un archivo binario sin formato, producirá esencialmente un volcado de memoria del contenido del archivo objeto de entrada. Se descartará toda la información de símbolos y relocalización. El volcado de memoria comenzará en la dirección de carga de la sección más baja copiada al archivo de salida.

Al generar un archivo de registro S o un archivo binario sin formato, puede ser útil usar -S para eliminar secciones que contienen información de depuración. En algunos casos, -R será útil para eliminar secciones que contienen información que no es necesaria para el archivo binario.

Nota---objcopy no puede cambiar la endianidad de sus archivos de entrada. Si el formato de entrada tiene una endianidad (algunos formatos no la tienen), objcopy solo puede copiar las entradas a formatos de archivo que tengan la misma endianidad o que no tengan ninguna endianidad (por ejemplo, srec). (Sin embargo, consulte la opción --reverse-bytes).

-b byte
--byte=byte
Si se ha habilitado el intercalado mediante la opción --interleave, entonces comienza el rango de bytes a conservar en el byte-ésimo byte. byte puede estar en el rango de 0 a ancho-1, donde ancho es el valor dado por la opción --interleave.
-i [ancho]
--interleave[=ancho]
Copia solo un rango de cada ancho bytes. (Los datos de cabecera no se ven afectados). Selecciona qué byte del rango inicia la copia con la opción --byte. Selecciona el ancho del rango con la opción --interleave-width.

Esta opción es útil para crear archivos para programar ROM. Se suele usar con un destino de salida "srec". Ten en cuenta que objcopy se quejará si no especificas también la opción --byte.

El ancho de intercalado predeterminado es 4, por lo que con --byte establecido a 0, objcopy copiaría el primer byte de cada cuatro bytes de la entrada a la salida.

--interleave-width=ancho
Cuando se usa con la opción --interleave, copia ancho bytes a la vez. El inicio del rango de bytes a copiar se establece con la opción --byte, y la extensión del rango se establece con la opción --interleave.

El valor predeterminado para esta opción es 1. El valor de ancho más el valor byte establecido por la opción --byte no debe exceder el ancho de intercalado establecido por la opción --interleave.

Esta opción se puede usar para crear imágenes para dos memorias flash de 16 bits intercaladas en un bus de 32 bits pasando -b 0 -i 4 --interleave-width=2 y -b 2 -i 4 --interleave-width=2 a dos comandos objcopy. Si la entrada fuera '12345678', las salidas serían '1256' y '3478' respectivamente.

--preserve-dates
Establece las fechas de acceso y modificación del archivo de salida para que sean las mismas que las del archivo de entrada.

Set or change the LMA address of any sections matching sectionpattern. The LMA address is the address where the section will be loaded into memory at program load time. Normally this is the same as the VMA address, which is the address of the section at program run time, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. Set or change the VMA address of any section matching sectionpattern. The VMA address is the address where the section will be located once the program has started executing. Normally this is the same as the LMA address, which is the address where the section will be loaded into memory, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. --set-section-flags sectionpattern=flags
Set the flags for any sections matching sectionpattern. The flags argument is a comma separated string of flag names. The recognized names are alloc, contents, load, noload, readonly, code, data, rom, exclude, share, debug, and large. You can set the contents flag for a section which does not have contents, but it is not meaningful to clear the contents flag of a section which does have contents--just remove the section instead. Not all flags are meaningful for all object file formats. In particular the share flag is only meaningful for COFF format files and not for ELF format files. The ELF x86-64 specific flag large corresponds to SHF_X86_64_LARGE.

The option can be specified more than once.

The option can be specified more than once.

Note - it is possible to use --rename-section and --update-section to both update and rename a section from one command line. In this case, pass the original section name to --update-section, and the original and new section names to --rename-section.
