DESCRIPCIÓN

Este comando maneja datos en formato CMS como mensajes de correo S/MIME v3.1. Puede cifrar, descifrar, firmar, verificar, comprimir, descomprimir e imprimir mensajes.

OPCIONES

Hay una serie de opciones de operación que establecen el tipo de operación a realizar: encrypt, decrypt, sign, verify, resign, sign_receipt, verify_receipt, digest_create, digest_verify, compress, uncompress, EncryptedData_encrypt, EncryptedData_decrypt, data_create, data_out, o cmsout. La relevancia de las otras opciones depende del tipo de operación y su significado puede variar según esta.

-help
Muestra un mensaje de uso.

Opciones generales

-in nombre_archivo
El mensaje de entrada para cifrar o firmar, o el mensaje para descifrar o verificar.
-out nombre_archivo
El texto del mensaje que ha sido descifrado o verificado, o el mensaje de salida en formato MIME que ha sido firmado o verificado.
-config archivo_config
Ver "Opciones de configuración" en openssl(1).

Opciones de operación

-encrypt
Cifra datos para los certificados de destinatario dados. El archivo de entrada es el mensaje a cifrar. El archivo de salida son los datos cifrados en formato MIME. El tipo CMS real es EnvelopedData.

Tenga en cuenta que no se realiza ninguna comprobación de revocación para el certificado del destinatario, por lo que si esa clave ha sido comprometida, otros podrán descifrar el texto.

-decrypt
Descifra datos utilizando el certificado y la clave privada proporcionados. Espera datos cifrados en formato MIME para el archivo de entrada. Los datos descifrados se escriben en el archivo de salida.
-sign
Firma datos utilizando el certificado y la clave privada proporcionados. El archivo de entrada es el mensaje a firmar. Los datos firmados en formato MIME se escriben en el archivo de salida.
-verify
Verifica datos firmados. Espera datos firmados en la entrada y produce los datos firmados. Se admiten tanto la firma de texto claro como la opaca.

Por defecto, la validación de los certificados del firmante y su cadena se realiza respecto al propósito de firma S/MIME ("smimesign"). Para más detalles, ver "Extensiones de certificado" en openssl-verification-options(1).

-resign
Vuelve a firmar un mensaje: toma un mensaje existente y uno o más firmantes nuevos.
-sign_receipt
Genera y produce un recibo firmado para el mensaje proporcionado. El mensaje de entrada debe contener una solicitud de recibo firmado. La funcionalidad es similar a la operación -sign.
-verify_receipt recibo
Verifica un recibo firmado en el archivo recibo. El mensaje de entrada debe contener la solicitud de recibo original. La funcionalidad es similar a la operación -verify.
-digest resumen
Cuando se utiliza con -sign, proporciona el resumen en formato hexadecimal en lugar de calcularlo a partir del contenido del mensaje original. No se puede combinar con -in o -nodetach.

Esta operación es el equivalente CMS de firmar con openssl-pkeyutl(1). Al firmar un resumen precalculado, la seguridad depende del resumen y de la confianza en su cálculo a partir del mensaje original.

-digest_create
Crea un tipo CMS DigestedData.
-digest_verify
Verifica un tipo CMS DigestedData y produce el contenido.
-compress
Crea un tipo CMS CompressedData. OpenSSL debe estar compilado con soporte zlib para esta operación.
-uncompress
Descomprime datos de un tipo CMS CompressedData. OpenSSL debe estar compilado con soporte zlib para esta operación.
-EncryptedData_encrypt
Crea un tipo CMS EncryptedData.
-EncryptedData_decrypt
Descifra un tipo CMS EncryptedData.
-data_create
Crea un tipo CMS Data.
-data_out
Imprime el contenido de un tipo CMS Data.
-cmsout
Produce una salida CMS en lugar de una salida S/MIME.

Opciones de formato de archivo

-inform DER|PEM|SMIME
El formato del archivo de entrada.
-outform DER|PEM|SMIME
El formato del archivo de salida.
-rctform DER|PEM|SMIME
El formato de los recibos de entrada y salida.
-stream
Procesa la entrada y salida como un flujo. Esto puede ser útil para archivos muy grandes, pero no permite la comprobación de que el contenido de entrada coincida con el contenido de los datos firmados.
-indef
Utiliza longitudes indefinidas para los objetos de salida. Esto requiere que la entrada sea procesada completamente antes de que se pueda escribir la salida.
-noindef
Utiliza longitudes definidas para los objetos de salida.
-binary
El archivo de entrada está en modo binario.
-crlfeol
Las líneas de fin de archivo se representan como CRLF en lugar de LF.
-asciicrlf
Convierte los saltos de línea LF a CRLF en la salida. Esto se utiliza para garantizar la compatibilidad con los sistemas que esperan finales de línea CRLF, como algunos sistemas S/MIME.

Opciones de cifrado

-originator archivo
Especifica el certificado del remitente. Debe incluirse al cifrar datos que deben ser descifrados por un destinatario específico que no tiene acceso a un certificado de remitente preexistente.
-recip archivo
Especifica el certificado del destinatario. Debe incluirse al descifrar datos cifrados con el modo EncryptedData y una clave secreta. El certificado del destinatario se utiliza para derivar la clave secreta utilizada para cifrar los datos.
certificado_destinatario ...
Uno o más certificados de destinatario utilizados para cifrar datos. Cada certificado especifica un destinatario para los datos cifrados.
-cifrado
Especifica el algoritmo de cifrado a utilizar. Si no se proporciona, se usa un valor predeterminado (generalmente AES-256-CBC).
-kekcipher cifrado
Especifica el algoritmo de cifrado de clave envuelta (KEK) a utilizar. Si no se proporciona, se utiliza un valor predeterminado (generalmente AES-256-CBC).
-wrap cifrado
Especifica el algoritmo de envoltura de clave a utilizar.
-aes128-wrap
Utiliza AES-128 para la envoltura de clave.
-aes192-wrap
Utiliza AES-192 para la envoltura de clave.
-aes256-wrap
Utiliza AES-256 para la envoltura de clave.
-des3-wrap
Utiliza DES-EDE3-CBC para la envoltura de clave.
-debug_decrypt
Imprime información detallada sobre el proceso de descifrado.
-recip_kdf kdf
Especifica la función de derivación de clave (KDF) a utilizar al derivar la clave de contenido del secreto del destinatario.
-recip_ukm ukm
Especifica los datos de uso de clave (UKM) a utilizar al derivar la clave de contenido del secreto del destinatario.

Opciones de formato de archivo

-inform DER|PEM|SMIME
El formato de entrada de la estructura CMS (si se está leyendo alguna); por defecto es SMIME. Ver openssl-format-options(1) para más detalles.
-outform DER|PEM|SMIME
El formato de salida de la estructura CMS (si se está escribiendo alguna); por defecto es SMIME. Ver openssl-format-options(1) para detalles.
-rctform DER|PEM|SMIME
El formato del recibo firmado para usar con -receipt_verify; por defecto es SMIME. Ver openssl-format-options(1) para detalles.
-stream, -indef
Las opciones -stream y -indef son equivalentes y habilitan la E/S en streaming para operaciones de codificación. Esto permite el procesamiento de datos en una sola pasada sin necesidad de mantener todo el contenido en memoria, soporte potencial para archivos muy grandes. El streaming se establece automáticamente para la firma S/MIME con datos adjuntos si el formato de salida es SMIME; actualmente está desactivado por defecto para todas las demás operaciones.
-noindef
Deshabilita la E/S en streaming donde produciría una codificación construida de longitud indefinida. Esta opción actualmente no tiene ningún efecto. En el futuro el streaming se habilitará por defecto en todas las operaciones relevantes y esta opción lo deshabilitará.
-binary
Normalmente el mensaje de entrada se convierte a formato "canónico" que efectivamente utiliza CR y LF como fin de línea: según lo requiere la especificación S/MIME. Cuando esta opción está presente no ocurre ninguna traducción. Esto es útil cuando se manejan datos binarios que pueden no estar en formato MIME.
-crlfeol
Normalmente el archivo de salida usa un solo LF como fin de línea. Cuando esta opción está presente se usa CRLF en su lugar.
-asciicrlf
Al firmar usa la canonización en formato ASCII CRLF. Esto elimina los espacios en blanco al final de todas las líneas, elimina las líneas en blanco al final del archivo y establece el tipo de contenido encapsulado. Esta opción se usa normalmente con contenido adjunto y un formato de salida de firma DER. Esta opción normalmente no es necesaria al verificar, ya que se habilita automáticamente si se detecta el formato de contenido encapsulado.

Opciones de claves y contraseñas

-pwri_password contraseña
Especifica la contraseña para el destinatario.
-secretkey clave
Especifica la clave simétrica a usar. La clave debe proporcionarse en formato hexadecimal y ser coherente con el algoritmo utilizado. Soportado por las opciones -EncryptedData_encrypt, -EncryptedData_decrypt, -encrypt y -decrypt. Cuando se usa con -encrypt o -decrypt la clave proporcionada se utiliza para envolver o desenvolver la clave de cifrado de contenido utilizando una clave AES en el tipo KEKRecipientInfo.
-secretkeyid id
El identificador de clave para la clave simétrica proporcionada para el tipo KEKRecipientInfo. Esta opción debe estar presente si la opción -secretkey se usa con -encrypt. Con operaciones de -decrypt el id se utiliza para localizar la clave relevante si no se proporciona, entonces se intenta descifrar cualquier estructura KEKRecipientInfo.
-inkey nombre_archivo|uri
La clave privada a usar al firmar o descifrar. Debe coincidir con el certificado correspondiente. Si esta opción no se especifica, entonces la clave privada debe incluirse en el archivo de certificado especificado con el archivo -recip o -signer. Al firmar, esta opción se puede usar múltiples veces para especificar claves sucesivas.
-passin arg
La fuente de la contraseña de la clave privada. Para más información sobre el formato de arg ver openssl-passphrase-options(1).
-keyopt nombre:parámetro
Para firmar y cifrar esta opción se puede usar múltiples veces para establecer parámetros personalizados para la clave o certificado anterior. Actualmente se puede usar para establecer RSA-PSS para firmar, RSA-OAEP para cifrar o para modificar los parámetros por defecto para ECDH.
-keyform DER|PEM|P12|ENGINE
El formato del archivo de clave privada; no especificado por defecto. Ver openssl-format-options(1) para detalles.
-engine id
Ver "Opciones de motores" en openssl(1). Esta opción está obsoleta.
-provider nombre
-provider-path ruta
-provparam [nombre:]clave=valor
-propquery propq
Ver "Opciones de proveedores" en openssl(1), provider(7), y property(7).
-rand archivos, -writerand archivo
Ver "Opciones de estado aleatorio" en openssl(1) para detalles.

Opciones de cifrado y descifrado

-originator archivo
Un certificado del originador del mensaje cifrado. Necesario para descifrar cuando se utiliza el Acuerdo de Clave para una clave compartida. Actualmente, no permitido para el cifrado.
-recip archivo
Al descifrar un mensaje, esto especifica el certificado del destinatario. El certificado debe coincidir con uno de los destinatarios del mensaje.

Al cifrar un mensaje, esta opción puede usarse múltiples veces para especificar cada destinatario. Esta forma debe usarse si se requieren parámetros personalizados (por ejemplo, para especificar RSA-OAEP).

Esta opción solo soporta certificados que contienen claves RSA, Diffie-Hellman o EC.

cert-destinatario ...
Esta es una alternativa al uso de la opción -recip al cifrar un mensaje. Se pueden dar uno o más nombres de archivo de certificado.
-cifrador
El algoritmo de cifrado a utilizar. Por ejemplo, AES (256 bits) - -aes256 o triple DES (168 bits) - -des3. Cualquier nombre de algoritmo estándar (como se usa en la función EVP_get_cipherbyname()) también se puede usar precedido por un guion, por ejemplo -aes-128-cbc. Ver openssl-enc(1) para una lista de cifradores soportados por su versión de OpenSSL.

Actualmente, las variantes de AES con modo GCM son los únicos algoritmos AEAD soportados.

Si no se especifica, se usa AES-256-CBC como valor por defecto. Solo se usa con los comandos -encrypt y -EncryptedData_create.

-kekcipher cifrador
Algoritmo de cifrado a utilizar para el cifrado de clave de contraseña. Esta opción es relevante cuando se proporciona una contraseña para información del destinatario de contraseña usando -pwri_password, y se selecciona un algoritmo de cifrado AEAD. En tales casos, se debe especificar un algoritmo que no sea AEAD usando esta opción.
-wrap cifrador
Algoritmo de cifrado a utilizar para el envoltorio de clave al cifrar el mensaje usando Acuerdo de Clave para transporte de clave. El algoritmo especificado debe ser adecuado para el envoltorio de clave.
-aes128-wrap, -aes192-wrap, -aes256-wrap, -des3-wrap
Usa AES128, AES192, AES256 o 3DES-EDE, respectivamente, para envolver la clave. Dependiendo de las opciones de compilación de OpenSSL utilizadas, -des3-wrap puede no ser soportado.
-debug_decrypt
Esta opción establece el indicador CMS_DEBUG_DECRYPT. Esta opción debe usarse con precaución: ver las notas a continuación.
-recip_kdf
Esta opción establece el KDF utilizado para generar la clave de cifrado de clave en el tipo KEMRecipientInfo. Cualquier KDF
que toma los parámetros OSSL_KDF_PARAM_KEY y OSSL_KDF_PARAM_INFO y está definido en lo demás completamente por su nombre o OID puede ser utilizado, por ejemplo HKDF-SHA256.
-recip_ukm
Esta opción establece el material de clave de usuario (UKM) opcional del tipo KEMRecipientInfo en formato hexadecimal. El UKM será codificado, junto con otra información, en el parámetro OSSL_KDF_PARAM_INFO del KDF del tipo KEMRecipientInfo.

Opciones de firma

-md digest
Algoritmo de resumen (digest) a utilizar al firmar o volver a firmar. Si no se presenta, se utilizará el algoritmo de resumen por defecto para la clave de firma (generalmente SHA1).
-signer file
Un certificado de firma. Al firmar o volver a firmar un mensaje, esta opción se puede usar varias veces si se requiere más de un firmante.
-certfile file
Permite especificar certificados adicionales. Al firmar, estos se incluirán con el mensaje. Al verificar, se buscarán certificados de firmante y se utilizarán para la construcción de la cadena.

La entrada puede estar en formato PEM, DER o PKCS#12.

-cades
Cuando se usa con -sign, agrega un atributo firmado ESS signingCertificate o ESS signingCertificateV2 a SignerInfo, para que la firma cumpla con los requisitos de una Firma Electrónica Básica CAdES (CAdES-BES).
-nodetach
Al firmar un mensaje, utiliza firma opaca: esta forma es más resistente a la traducción por retransmisiones de correo, pero no puede ser leída por agentes de correo que no admiten S/MIME. Sin esta opción, se utiliza firma de texto plano con el tipo MIME multipart/signed.
-nocerts
Al firmar un mensaje, normalmente se incluye el certificado del firmante. Con esta opción, se excluye. Esto reducirá el tamaño del mensaje firmado, pero el verificador debe tener una copia del certificado del firmante disponible localmente (pasada usando la opción -certfile, por ejemplo).
-noattr
Normalmente, al firmar un mensaje, se incluye un conjunto de atributos que incluyen la hora de firma y los algoritmos simétricos admitidos. Con esta opción, no se incluyen.
-nosmimecap
Excluye la lista de algoritmos admitidos de los atributos firmados; otras opciones como el tipo de contenido y (opcionalmente) la hora de firma todavía se incluyen.
-no_signing_time
Excluye la hora de firma de los atributos firmados; otras opciones como el tipo de contenido todavía se incluyen.
-receipt_request_all, -receipt_request_first
Para la opción -sign, incluye una solicitud de recibo firmado. Indica que las solicitudes deben ser proporcionadas por todos los destinatarios o por los destinatarios de primer nivel (aquellos a los que se les envía directamente y no de una lista de distribución). Se ignora si se incluye -receipt_request_from.
-receipt_request_from emailaddress
Para la opción -sign, incluye una solicitud de recibo firmado. Agrega una dirección de correo electrónico explícita donde se deben suministrar los recibos.
-receipt_request_to emailaddress
Agrega una dirección de correo electrónico explícita a la que se deben enviar los recibos firmados. Esta opción debe ser suministrada si se solicita un recibo firmado.

Opciones de verificación

-signer file
Si un mensaje ha sido verificado con éxito, los certificados del firmante se escribirán en este archivo si la verificación fue exitosa.
-content filename
Esto especifica un archivo que contiene el contenido separado para operaciones que toman entrada S/MIME, como el comando -verify. Esto solo es utilizable si la estructura CMS está utilizando la forma de firma separada donde el contenido no está incluido. Esta opción anulará cualquier contenido si el formato de entrada es S/MIME y utiliza el tipo de contenido MIME multipart/signed.
-no_content_verify
No verificar las firmas de contenido firmado.
-no_attr_verify
No verificar las firmas de atributos firmados.
-nosigs
No verificar la firma del mensaje.
-noverify
No verificar el certificado del firmante de un mensaje firmado.
-nointern
Al verificar un mensaje, normalmente los certificados (si los hay) incluidos en el mensaje se buscan para encontrar el certificado de firma. Con esta opción, solo se utilizan los certificados especificados en la opción -certfile. Los certificados proporcionados aún pueden usarse como CAs no confiables.
-cades
Cuando se usa con -verify, requiere y verifica el resumen del certificado del firmante. Consulte la sección NOTAS para más detalles.
-verify_retcode
Salir con valor distinto de cero en caso de fallo de verificación.
-CAfile file, -no-CAfile, -CApath dir, -no-CApath, -CAstore uri, -no-CAstore
Consulte "Trusted Certificate Options" en openssl-verification-options(1) para detalles.

Opciones de salida

-keyid
Utiliza el identificador de clave del sujeto para identificar certificados en lugar del nombre del emisor y el número de serie. El certificado proporcionado debe incluir una extensión de identificador de clave del sujeto. Soportado por las opciones -sign y -encrypt.
-econtent_type type
Establece el tipo de contenido encapsulado a type si no se proporciona, se utiliza el tipo Data. El argumento type puede ser cualquier nombre OID válido en formato de texto o numérico.
-text
Esta opción agrega encabezados MIME de texto plano (text/plain) al mensaje proporcionado si se está cifrando o firmando. Si se está descifrando o verificando, elimina los encabezados de texto; si el mensaje descifrado o verificado no es del tipo MIME text/plain, se produce un error.
-certsout file
Cualquier certificado contenido en el mensaje de entrada se escribe en file.
-to, -from, -subject
Los encabezados de correo electrónico relevantes. Estos se incluyen fuera de la porción firmada de un mensaje, por lo que pueden incluirse manualmente. Si se firma, muchos clientes de correo S/MIME verifican que la dirección de correo electrónico del certificado del firmante coincida con la especificada en la dirección From:.

Opciones de impresión

-noout
Para la operación -cmsout, no muestre la estructura CMS analizada. Esto es útil si se está verificando la sintaxis de la estructura CMS.
-print
Para la operación -cmsout, imprima todos los campos de la estructura CMS. Esto implica -noout. Esto es principalmente útil para fines de prueba.
-nameopt option
Para la operación -cmsout, cuando la opción -print está en uso, especifica las opciones de impresión para campos de cadena. Para la mayoría de los casos, utf8 es un valor razonable. Consulte openssl-namedisplay-options(1) para detalles.
-receipt_request_print
Para la operación -verify, imprima el contenido de cualquier solicitud de recibo firmado.

Opciones de validación

-allow_proxy_certs, -attime, -no_check_time, -check_ss_sig, -crl_check, -crl_check_all, -explicit_policy, -extended_crl, -ignore_critical, -inhibit_any, -inhibit_map, -no_alt_chains, -partial_chain, -policy, -policy_check, -policy_print, -purpose, -suiteB_128, -suiteB_128_only, -suiteB_192, -trusted_first, -use_deltas, -auth_level, -verify_depth, -verify_email, -verify_hostname, -verify_ip, -verify_name, -x509_strict -issuer_checks
Establece varias opciones de verificación de la cadena de certificados. Consulte "Verification Options" en openssl-verification-options(1) para obtener detalles.

Cualquier error de validación provocará que el comando termine.

NOTAS

El mensaje MIME debe enviarse sin ninguna línea en blanco entre las cabeceras y la salida. Algunos programas de correo agregarán automáticamente una línea en blanco. Canalizar el correo directamente a sendmail es una forma de lograr el formato correcto.

El mensaje proporcionado para ser firmado o cifrado debe incluir las cabeceras MIME necesarias o muchos clientes S/MIME no lo mostrarán correctamente (o en absoluto). Puede usar la opción -text para agregar automáticamente encabezados de texto plano.

NAME

openssl-cms - CMS cryptographic message syntax utility

SYNOPSIS

openssl cms [-help] [-in arg] [-inform arg] [-out arg] [-outform arg] [-text] [-certify] [-crl_check] [-crl_check_only] [-nameopt opt] [-issuer_grep arg] [-subject_grep arg] [-in_ ckfile arg] [-sign] [-signer arg] [-inkey arg] [-nobuiltin_oid] [-md arg] [-policy arg] [-policy_check] [-policy_print] [-verify] [-partial_verify] [-cert_chain] [-CAfile arg] [-CApath arg] [-crl_check] [-crl_check_only] [-no_alt_chains] [-digest arg] [-verify_once] [-certopt opt] [-x509_user_cert] [-connloss] [-engine arg] [-encrypt] [-recipient arg] [-recip arg] [-recip_kdf arg] [-recip_ukm arg] [-recipient_certfile arg] [-content arg] [-aes128] [-aes192] [-aes256] [-des3] [-set_orig] [-camellia128] [-camellia192] [-camellia256] [-cmsout] [-decrypt] [-recip arg] [-inkey arg] [-passin arg] [-nocert] [-noverify] [-stream] [-indef] [-no_cont] [-content_ f arg] [-compression_oid arg] [-encrsadata] [-encrl] [-seal] [-debug_decrypt] [-smime] [-copy_attributes] [-resign] [-add_signed_attr] [-add_unsigned_attr] [-delete_signed_attr] [-delete_unsigned_attr] [-cades] [-cmsout] [-print] [-binary] [-inform arg] [-outform arg] [-text] [-certopt opt] [-cert_chain] [-CAfile arg] [-CApath arg] [-verify] [-partial_verify] [-crl_check] [-crl_check_only] [-nameopt opt] [-issuer_grep arg] [-subject_grep arg] [-no_alt_chains] [-digest arg] [-verify_once] [-engine arg] [-C arg] [-S arg] [-nomerge] [-nosmime] [-out arg] [-debug] [-keyopt opt]

DESCRIPTION

The openssl cms command is a utility for processing CMS (Cryptographic Message Syntax) data.

CMS is a successor to PKCS#7. CMS can be used to encapsulate data for various purposes including digital signatures and encryption. It is defined in RFC 3852.

The command can perform the following operations:

-sign
Creates a digital signature for the input data. This can be a cleartext signature (where the original data is included with the signature, usually in a MIME message) or an opaque signature (where the original data is encapsulated within the CMS structure).
-verify
Verifies the digital signature of the input data. It can also be used to extract the signed data and signer's certificate.
-encrypt
Encrypts the input data for one or more recipients. The recipients' certificates are used for this purpose.
-decrypt
Decrypts data that was previously encrypted using the -encrypt option. The appropriate recipient's private key and certificate are required.
-digest
Computes a message digest of the input data. This is typically used as part of the signing process.
-hash
Same as -digest.
-cmsout
Prints the output CMS structure in human-readable form. This is useful for debugging.
-copy_attributes
Copies signed attributes from existing signers to a new signer when resigning. This is useful for maintaining consistency across multiple signers.
-cades
Adds CAdES-BES (Basic Electronic Signature) extensions to the signature. This is used for enhanced electronic signature validation according to ETSI standards.
-resign
Adds a new signature to an existing CMS message. The original message digest is reused.

A signed message is one where a signed message is then encrypted. This can be produced by encrypting an already signed message: see the examples section.

This version of the program only allows one signer per message but it will verify multiple signers on received messages. Some S/MIME clients choke if a message contains multiple signers. It is possible to sign messages "in parallel" by signing an already signed message.

The options -encrypt and -decrypt reflect common usage in S/MIME clients. Strictly speaking these process CMS enveloped data: CMS encrypted data is used for other purposes.

The -resign option uses an existing message digest when adding a new signer. This means that attributes must be present in at least one existing signer using the same message digest or this operation will fail.

The -stream and -indef options enable streaming I/O support. As a result the encoding is BER using indefinite length constructed encoding and no longer DER. Streaming is supported for the -encrypt operation and the -sign operation if the content is not detached.

Streaming is always used for the -sign operation with detached data but since the content is no longer part of the CMS structure the encoding remains DER.

If the -decrypt option is used without a recipient certificate then an attempt is made to locate the recipient by trying each potential recipient in turn using the supplied private key. To thwart the MMA attack (Bleichenbacher's attack on PKCS #1 v1.5 RSA padding) all recipients are tried whether they succeed or not and if no recipients match the message is "decrypted" using a random key which will typically output garbage. The -debug_decrypt option can be used to disable the MMA attack protection and return an error if no recipient can be found: this option should be used with caution. For a fuller description see CMS_decrypt(3)).

CADES BASIC ELECTRONIC SIGNATURE (CADES-BES)

A CAdES Basic Electronic Signature (CAdES-BES), as defined in the European Standard ETSI EN 319 122-1 V1.1.1, contains:

  • The signed user data as defined in CMS (RFC 3852);
  • Content-type of the EncapsulatedContentInfo value being signed;
  • Message-digest of the eContent OCTET STRING within encapContentInfo being signed;
  • An ESS signingCertificate or ESS signingCertificateV2 attribute, as defined in Enhanced Security Services (ESS), RFC 2634 and RFC 5035. An ESS signingCertificate attribute only allows for SHA-1 as digest algorithm. An ESS signingCertificateV2 attribute allows for any digest algorithm.
  • The digital signature value computed on the user data and, when present, on the signed attributes.

    NOTE that the -cades option applies to the -sign or -verify operations. With this option, the -verify operation also requires that the signingCertificate attribute is present and checks that the given identifiers match the verification trust chain built during the verification process.

EXIT CODES

0
The operation was completely successfully.
1
An error occurred parsing the command options.
2
One of the input files could not be read.
3
An error occurred creating the CMS file or when reading the MIME message.
4
An error occurred decrypting or verifying the message.
5
The message was verified correctly but an error occurred writing out the signers certificates.

COMPATIBILITY WITH PKCS#7 FORMAT

openssl-smime(1) can only process the older PKCS#7 format. openssl cms supports Cryptographic Message Syntax format. Use of some features will result in messages which cannot be processed by applications which only support the older format. These are detailed below.

The use of the -keyid option with -sign or -encrypt.

The -outform PEM option uses different headers.

The -compress option.

The -secretkey option when used with -encrypt.

The use of PSS with -sign.

The use of OAEP or non-RSA keys with -encrypt.

Additionally the -EncryptedData_create and -data_create type cannot be processed by the older openssl-smime(1) command.

EXAMPLES

Create a cleartext signed message:

openssl cms -sign -in message.txt -text -out mail.msg \
       -signer mycert.pem

Create an opaque signed message

openssl cms -sign -in message.txt -text -out mail.msg -nodetach \
       -signer mycert.pem

Create a signed message, include some additional certificates and read the private key from another file:

openssl cms -sign -in in.txt -text -out mail.msg \
       -signer mycert.pem -inkey mykey.pem -certfile mycerts.pem

Create a signed message with two signers, use key identifier:

openssl cms -sign -in message.txt -text -out mail.msg \
       -signer mycert.pem -signer othercert.pem -keyid

Send a signed message under Unix directly to sendmail, including headers:

openssl cms -sign -in in.txt -text -signer mycert.pem \
       -from steve@openssl.org -to someone@somewhere \
       -subject "Signed message" | sendmail someone@somewhere

Verify a message and extract the signer's certificate if successful:

openssl cms -verify -in mail.msg -signer user.pem -out signedtext.txt

Send encrypted mail using triple DES:

openssl cms -encrypt -in in.txt -from steve@openssl.org \
       -to someone@somewhere -subject "Encrypted message" \
       -des3 user.pem -out mail.msg

Sign and encrypt mail:

openssl cms -sign -in ml.txt -signer my.pem -text \
       | openssl cms -encrypt -out mail.msg \
       -from steve@openssl.org -to someone@somewhere \
       -subject "Signed and Encrypted message" -des3 user.pem

Note: the encryption command does not include the -text option because the message being encrypted already has MIME headers.

Decrypt a message:

openssl cms -decrypt -in mail.msg -recip mycert.pem -inkey key.pem

The output from Netscape form signing is a PKCS#7 structure with the detached signature format. You can use this program to verify the signature by line wrapping the base64 encoded structure and surrounding it with:

-----BEGIN PKCS7-----
-----END PKCS7-----

and using the command,

openssl cms -verify -inform PEM -in signature.pem -content content.txt

alternatively you can base64 decode the signature and use

openssl cms -verify -inform DER -in signature.der -content content.txt

Create an encrypted message using 128 bit Camellia:

openssl cms -encrypt -in plain.txt -camellia128 -out mail.msg cert.pem

Add a signer to an existing message:

openssl cms -resign -in mail.msg -signer newsign.pem -out mail2.msg

Sign a message using RSA-PSS:

openssl cms -sign -in message.txt -text -out mail.msg \
       -signer mycert.pem -keyopt rsa_padding_mode:pss

Create an encrypted message using RSA-OAEP:

openssl cms -encrypt -in plain.txt -out mail.msg \
       -recip cert.pem -keyopt rsa_padding_mode:oaep

Use SHA256 KDF with an ECDH certificate:

openssl cms -encrypt -in plain.txt -out mail.msg \
       -recip ecdhcert.pem -keyopt ecdh_kdf_md:sha256

Print CMS signed binary data in human-readable form:

openssl cms -in signed.cms -binary -inform DER -cmsout -print

BUGS

The MIME parser isn't very clever: it seems to handle most messages that I've thrown at it but it may choke on others.

The code currently will only write out the signer's certificate to a file: if the signer has a separate encryption certificate this must be manually extracted. There should be some heuristic that determines the correct encryption certificate.

Ideally a database should be maintained of a certificates for each email address.

The code doesn't currently take note of the permitted symmetric encryption algorithms as supplied in the SMIMECapabilities signed attribute. this means the user has to manually include the correct encryption algorithm. It should store the list of permitted ciphers in a database and only use those.

No revocation checking is done on the signer's certificate.
