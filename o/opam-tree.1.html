NOMBRE

opam-tree - Dibuja el bosque de dependencias de los paquetes instalados.

SINOPSIS

opam tree [--recursive] [--subpath=RUTA] [OPCIÓN]… [PAQUETES]…

DESCRIPCIÓN

Este comando muestra el bosque de paquetes actualmente instalados como arte Unicode/ASCII.

Sin argumentos, dibuja el bosque de dependencias de los paquetes sin dependientes. Con argumentos de paquetes, dibuja el bosque de los paquetes especificados. Cuando se especifican paquetes no instalados en los argumentos, intentará simular su instalación antes de dibujar el bosque.

Cuando se utiliza la opción --rev-deps, dibuja el bosque de dependencias inversas en su lugar. Sin argumentos, dibuja el bosque de paquetes sin dependencias. Con argumentos de paquetes, dibuja el bosque de los paquetes especificados. Tenga en cuenta que los paquetes no instalados se ignoran cuando se utiliza esta opción.

Cuando un paquete aparece dos o más veces en el bosque, las apariciones segundas o posteriores del paquete en cuestión se marcarán como duplicados y se anotarán con el símbolo [*]. Cualquier subárbol que parta de dichos duplicados se truncará para evitar redundancia.

Consulte la sección OPCIONES DE FILTRADO DEL ÁRBOL y OPCIONES DE SELECCIÓN DE PAQUETES para conocer todas las formas de seleccionar los paquetes a mostrar, y la sección OPCIONES DE FORMATO DE SALIDA para personalizar el formato de la salida.

Para una lista plana de paquetes que pueden no estar instalados, consulte opam list.

ARGUMENTOS

PAQUETES
Lista de nombres de paquetes, con una versión o restricción opcional, p.ej. `pkg', `pkg.1.0' o `pkg>=0.5'; o nombres de archivos o directorios que contienen descripciones de paquetes, con directorio explícito (p.ej. `./foo.opam' o `.').

OPCIONES DE CONSTRUCCIÓN DEL ÁRBOL

--deps
Dibuja un bosque de dependencias, comenzando desde los paquetes que no son requeridos por ningún otro paquete (este es el valor por defecto).
--rev-deps
Dibuja un bosque de dependencias inversas, comenzando desde los paquetes que no tienen dependencias.

OPCIONES DE FILTRADO DEL ÁRBOL

Estas opciones solo tienen efecto cuando están presentes los PAQUETES.

--leads-to
Muestra solo las ramas que conducen a uno de los PAQUETES.
--roots-from
Muestra solo los árboles cuyas raíces provienen de uno de los PAQUETES (este es el valor por defecto).

OPCIONES DE SELECCIÓN DE PAQUETES

--dev
Incluye paquetes de desarrollo en las dependencias.
--no-switch
Ignora el switch activo y simula la instalación de paquetes desde un switch vacío para dibujar el bosque.
--post
Incluye dependencias etiquetadas como post.
-t, --with-test, --test
Incluye dependencias solo de prueba.
--with-dev-setup
Incluye dependencias solo de desarrollo.
--with-doc, --doc
Incluye dependencias solo de documentación.

OPCIONES DE FORMATO DE SALIDA

--no-constraint
No muestra las restricciones de versión, p.ej. (>= 1.0.0).

OPCIONES

--recursive
Permite búsquedas recursivas de archivos *.opam. Véase también --subpath.
--subpath=RUTA
Los archivos *.opam se obtienen del subdirectorio dado en lugar del directorio principal. Las fuentes se toman entonces del subdirectorio objetivo, copiándose/descargándose internamente solo este subdirectorio. Se puede combinar con --recursive para tener una búsqueda recursiva en la subruta.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utiliza la sintaxis y semántica de interfaz de línea de comandos de MAYOR.MENOR. Destinado a cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam de la misma serie MAYOR se comportará como para la versión MENOR especificada. La bandera no estaba disponible en opam 2.0, por lo que para seleccionar la CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de always, never o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar varias veces. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especifica las preferencias del usuario para la resolución de dependencias en esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje soportado, y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general para usar preferencias de solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBRE_ARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Como --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está configurada (es decir, si está utilizando una versión de desarrollo), y sale.
--help[=FORMATO] (por defecto=auto)
Muestra esta ayuda en el formato FORMATO. El valor FORMATO debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o no esté definida.
--ignore-pin-depends
Ignora los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por ordenador. Si el nombre de archivo contiene el carácter `%', se reemplazará por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deberían definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato anterior. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

--no-aspcud
Desactiva el solucionador externo y usa el interno (esto requiere que opam haya sido compilado con un solucionador interno). Es equivalente a establecer la variable de entorno $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
--no-checksums
No verifique las sumas de verificación de los archivos descargados. Esto anula la opción --require-checksums.
--no-depexts
No instale dependencias del sistema. Es equivalente a establecer la variable de entorno $OPAMNODEPEXTS.
--no-path
No modifique las variables de entorno exportadas por opam. Es equivalente a establecer la variable de entorno $OPAMNOBUILD.
--no-self-upgrade
No actualice automáticamente opam a una versión más nueva. Es equivalente a establecer la variable de entorno $OPAMNOSELFUPGRADE.
--no-test
No ejecute las pruebas de los paquetes después de la instalación. Es equivalente a establecer la variable de entorno $OPAMNOTEST.
--only-dep
Solo instale dependencias, no el paquete en sí. Es equivalente a establecer la variable de entorno $OPAMONLYDEP.
-o, --opam-file=OPAMFILE
Use OPAMFILE como archivo opam principal. Si este argumento se proporciona, opam asumirá que está trabajando en un directorio que contiene solo un paquete.
--partial-upgrade
Permite actualizaciones parciales de paquetes. Esto es equivalente a establecer la variable de entorno $OPAMPARTIALUPGRADE.
--path=PATH
Establezca la ruta de acceso al sistema de archivos para los archivos de opam. Es equivalente a establecer la variable de entorno $OPAMPATH.
--pin=PKG[=URL]
Fije el paquete PKG a una versión local o a una URL. Si la URL se omite, opam intentará detectar el control de versiones y fijarlo al directorio de trabajo actual.
--pin-depends=PKG[=URL]
Fije las dependencias de PKG a una versión local o a una URL.
--pin-file=FILE
Fije el paquete descrito en FILE a una versión local.
--prompt-level=N
Establezca el nivel de confirmación de 0 (no preguntar) a 3 (preguntar todo). Es equivalente a establecer la variable de entorno $OPAMPROMPTLEVEL.
-q, --quiet
Sea menos verboso. Desactiva --verbose.
-r, --repo=REPO
Especifique el repositorio de paquetes que se utilizará. Esto es equivalente a establecer la variable de entorno $OPAMREPO.
--recursive-pin
Fije también las dependencias de los paquetes fijados recursivamente. Es equivalente a establecer la variable de entorno $OPAMRECURSIVEPIN.
--remove
Elimine los paquetes especificados. Es equivalente a establecer la variable de entorno $OPAMREMOVE.
--remove-lock
Elimine los archivos de bloqueo de paquetes.
--remove-test
Elimine los paquetes que no son necesarios para la compilación.
--require-checksums
Exija las sumas de verificación de los archivos descargados. Esto anula la opción --no-checksums.
--root=ROOT
Use ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegúrese de que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de finalización, por ejemplo. Fallará siempre que se necesite una operación de este tipo; también evita esperar por bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifique el solucionador CUDF a utilizar para resolver problemas de instalación de paquetes. Este es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falle siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--switch=SWITCH
Use SWITCH como el conmutador del compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Desactive cualquier solucionador externo y use el interno (esto requiere que opam haya sido compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sea más verboso. Un -v muestra todos los comandos de los paquetes, repita para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.) Repetir *n* veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestre información de la versión.
-w, --working-dir
Siempre que actualice paquetes que estén vinculados a un directorio local controlado por versiones, actualice al estado de trabajo actual de su código fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio de código fuente se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responda sí a todas las preguntas de sí/no de opam sin preguntar. Vea también --confirm-level. Esto es equivalente a establecer la variable de entorno $OPAMYES a "true".

OPAMSHOW vea la opción `--show'.

OPAMSKIPVERSIONCHECKS omite algunas verificaciones de versión. Peligroso, solo para pruebas de compatibilidad.

OPAMSOLVERALLOWSUBOPTIMAL (predeterminado `true') permite que algunos solucionadores devuelvan una solución cuando alcanzan el tiempo de espera; si bien la solución sigue garantizada como consistente, no hay garantía en este caso de que cumpla los criterios de optimización esperados. Si es `true', opam continuará con una advertencia, si es `false' un tiempo de espera es un error. Actualmente, solo el backend builtin-z3 maneja este caso degradado.

OPAMSOLVERTIMEOUT cambia el tiempo de asignación del solucionador. El valor predeterminado es 60.0, establecido en 0 para ilimitado. Tenga en cuenta que no todos los solucionadores pueden admitir esta opción.

OPAMSOLVERTOLERANCE cambia la tolerancia hacia el solucionador que elige una solución no optimizada (es decir, puede extraer paquetes desactualizados). Los valores típicos van de 0.0 (mejor solución conocida por el solucionador) a 1.0 (solución no optimizada). El valor predeterminado es 0.0. Esta opción es útil en caso de que el solucionador no pueda encontrar una solución en un tiempo razonable (vea $OPAMSOLVERTIMEOUT). Tenga en cuenta que no todos los solucionadores pueden admitir esta opción.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
