NOMBRE

oci-hooks - directorios de configuración de hooks de OCI

SINOPSIS

/usr/share/containers/oci/hooks.d/*.json

DESCRIPCIÓN

Proporciona una forma para que los usuarios configuren los hooks previstos para los contenedores de la Open Container Initiative, de modo que solo se ejecuten para los contenedores que necesitan su funcionalidad, y solo para las etapas en las que son necesarios.

Directorios

Los hooks se configuran con archivos JSON (que terminan con la extensión .json) en una serie de directorios de hooks. El directorio predeterminado es /usr/share/containers/oci/hooks.d, pero las herramientas que consumen este formato pueden cambiar ese valor predeterminado, incluir directorios adicionales o proporcionar a sus llamadores formas de ajustar los directorios de configuración.

Si se configuran varios directorios, un nombre de archivo JSON en un directorio preferido enmascara las entradas con el mismo nombre de archivo en directorios con menor precedencia. Por ejemplo, si una herramienta consumidora observa hooks en /etc/containers/oci/hooks.d y /usr/share/containers/oci/hooks.d (en orden de precedencia decreciente), entonces una definición de hook en /etc/containers/oci/hooks.d/01-my-hook.json enmascarará cualquier definición en /usr/share/containers/oci/hooks.d/01-my-hook.json.

Las herramientas que consumen este formato también pueden optar por monitorear los directorios de hooks en busca de cambios, en cuyo caso notarán adiciones, cambios y eliminaciones de archivos JSON sin necesidad de ser reiniciadas o señaladas de otra manera. Cuando la herramienta monitorea múltiples directorios de hooks, la precedencia discutida en el párrafo anterior todavía se aplica. Por ejemplo, si una herramienta consumidora observa hooks en /etc/containers/oci/hooks.d y /usr/share/containers/oci/hooks.d (en orden de precedencia decreciente), entonces escribir una nueva definición de hook en /etc/containers/oci/hooks.d/01-my-hook.json enmascarará el hook cargado previamente desde /usr/share/containers/oci/hooks.d/01-my-hook.json. Los cambios posteriores en /etc/containers/oci/hooks.d/01-my-hook.json no afectarán a la herramienta consumidora mientras exista /etc/containers/oci/hooks.d/01-my-hook.json. La eliminación de /etc/containers/oci/hooks.d/01-my-hook.json recargará el hook desde /usr/share/containers/oci/hooks.d/01-my-hook.json.

Los hooks se inyectan en el orden obtenido al ordenar los nombres de los archivos JSON, después de convertirlos a minúsculas, basándose en sus puntos de código Unicode. Por ejemplo, un hook coincidente definido en 01-my-hook.json se inyectaría antes que los hooks coincidentes definidos en 02-another-hook.json y 01-UPPERCASE.json. Se recomienda encarecidamente hacer que el orden de ordenación sea inequívoco dependiendo de un prefijo solo ASCII (como el 01/02 anterior).

Cada archivo JSON debe contener un objeto con uno de los siguientes esquemas.

Esquema de hook 1.0.0

version (cadena requerida)
Establece la versión de la definición del hook. Para esta versión del esquema, el valor debe ser 1.0.0.

hook (objeto requerido)
El hook a inyectar, con el esquema de entrada del hook definido por la Especificación de Runtime OCI 1.0.2.

when (objeto requerido)
Condiciones bajo las cuales se inyecta el hook. Se pueden especificar las siguientes propiedades, y debe especificarse al menos una:

  • always (booleano opcional)
    Si se establece en true, esta condición coincide.
  • annotations (objeto opcional)
    Si todos los pares clave/valor de annotations coinciden con un par clave/valor de las anotaciones configuradas, esta condición coincide.
    Tanto las claves como los valores deben ser expresiones regulares extendidas POSIX.
  • commands (matriz de cadenas opcional)
    Si el process.args[0] configurado coincide con una entrada, esta condición coincide.
    Las entradas deben ser expresiones regulares extendidas POSIX.
  • hasBindMounts (booleano opcional)
    Si hasBindMounts es verdadero y el llamador solicitó montajes de vinculación de host a contenedor, esta condición coincide.

stages (matriz de cadenas requerida)
Etapas en las que se debe inyectar el hook. Las entradas deben elegirse de las etapas de hook de la Especificación de Runtime OCI 1.0.2 o de las etapas de extensión admitidas por el consumidor del paquete.

Si coinciden *todas* las condiciones establecidas en when, entonces el hook debe ser inyectado para las etapas establecidas en stages.

Esquema de hook 0.1.0

hook (cadena requerida)
Establece path en el hook inyectado.

arguments (matriz de cadenas opcional)
Argumentos adicionales para pasar al hook. Los args del hook inyectado son hook con los arguments añadidos.

stages (matriz de cadenas requerida)
Etapas en las que se debe inyectar el hook. stage es un sinónimo permitido para esta propiedad, pero no debes establecer ni stages ni stage. Las entradas deben elegirse de las etapas de hook de la Especificación de Runtime OCI 1.0.2 o de las etapas de extensión admitidas por el consumidor del paquete.

cmds (matriz de cadenas opcional)
El hook debe inyectarse si el process.args[0] configurado coincide con una entrada. cmd es un sinónimo permitido para esta propiedad, pero no debes establecer ni cmds ni cmd. Las entradas deben ser expresiones regulares extendidas POSIX.

annotations (matriz de cadenas opcional)
El hook debe inyectarse si una entrada de annotations coincide con un valor de las anotaciones configuradas. annotation es un sinónimo permitido para esta propiedad, pero no debes establecer ni annotations ni annotation. Las entradas deben ser expresiones regulares extendidas POSIX.

hasbindmounts (booleano opcional)
El hook debe inyectarse si hasBindMounts es verdadero y el llamador solicitó montajes de vinculación de host a contenedor.

EJEMPLO

Esquema de hook 1.0.0

La siguiente configuración inyecta oci-systemd-hook en las etapas prestart y poststop si process.args[0] termina en /init o /systemd:

$ cat /etc/containers/oci/hooks.d/oci-systemd-hook.json
{
  "version": "1.0.0",
  "hook": {
    "path": "/usr/libexec/oci/hooks.d/oci-systemd-hook"
  },
  "when": {
    "commands": [".*/init$" , ".*/systemd$"]
  },
  "stages": ["prestart", "poststop"]
}

El siguiente ejemplo inyecta oci-umount --debug en la etapa prestart si el contenedor está configurado para montar directorios del host en el contenedor mediante vinculación:

$ cat /etc/containers/oci/hooks.d/oci-umount.json
{
  "version": "1.0.0",
  "hook": {
    "path": "/usr/libexec/oci/hooks.d/oci-umount",
    "args": ["oci-umount", "--debug"],
  },
  "when": {
    "hasBindMounts": true
  },
  "stages": ["prestart"]
}

El siguiente ejemplo inyecta nvidia-container-runtime-hook prestart con variables de entorno particulares en la etapa prestart si el contenedor está configurado con una entrada de annotations cuya clave coincide con ^com\.example\.department$ y cuyo valor coincide con .*fluid-dynamics.*.

$ cat /etc/containers/oci/hooks.d/nvidia.json
{
  "version": "1.0.0",
  "hook": {
    "path": "/usr/sbin/nvidia-container-runtime-hook",
    "args": ["nvidia-container-runtime-hook", "prestart"],
    "env": [
      "NVIDIA_REQUIRE_CUDA=cuda>=9.1",
      "NVIDIA_VISIBLE_DEVICES=GPU-fef8089b"
    ]
  },
  "when": {
    "annotations": {
      "^com\\.example\\.department$": ".*fluid-dynamics$"
    }
  },
  "stages": ["prestart"]
}

Esquema de hook 0.1.0

La siguiente configuración inyecta oci-systemd-hook en las etapas prestart y poststop si process.args[0] termina en /init o /systemd:

$ cat /etc/containers/oci/hooks.d/oci-systemd-hook.json
{
  "cmds": [".*/init$" , ".*/systemd$"],
  "hook": "/usr/libexec/oci/hooks.d/oci-systemd-hook",
  "stages": ["prestart", "poststop"]
}

NAME

oci-hooks.d — OCI hook configuration directories

SYNOPSIS

/etc/containers/oci/hooks.d/

/usr/share/containers/oci/hooks.d/

DESCRIPTION

The OCI hook manager looks for hook configuration files in these directories.

Files in /etc/containers/oci/hooks.d/ take precedence over files with the same name in /usr/share/containers/oci/hooks.d/.

The hook configuration files must be named *.json. The contents of the files are JSON objects which define the hooks to be executed.

The hook configuration files are processed in alphabetical order by filename.

The following fields are supported in the JSON configuration files:

hook
Path to the hook executable. This field is mandatory.
client_flags
An array of strings representing flags to be passed to the OCI runtime client. This field is optional.
container_flags
An array of strings representing flags to be passed to the hook executable when it is invoked as a container hook. This field is optional.
annotations
An array of strings representing POSIX extended regular expressions. If the container is configured with annotations that match any of these regular expressions, the hook will be executed. This field is optional.
hasbindmounts
A boolean value indicating whether the hook requires bind mounts. If set to true, the hook will be executed even if the container has no bind mounts. This field is optional.
stages
An array of strings indicating the stages in which the hook should be executed. The supported stages are prestart, createRuntime, poststart, poststop, prestop. This field is optional, and if not specified, the hook will be executed in all stages.

See OCI Runtime Specification for more details.

Directories

/etc/containers/oci/hooks.d/
Local system configuration directory for OCI hooks. Files in this directory are not managed by any package and should be used for system-specific hook configurations.
/usr/share/containers/oci/hooks.d/
System-wide configuration directory for OCI hooks. Files in this directory are typically installed by packages and may be managed by the system's package manager.

EXAMPLE

The following example configures the oci-umount hook to be executed in the prestart stage if the container has bind mounts. The --debug flag is passed to the hook executable.

$ cat /etc/containers/oci/hooks.d/oci-umount.json
{
  "hook": "/usr/libexec/oci/hooks.d/oci-umount",
  "arguments": ["--debug"],
  "hasbindmounts": true,
  "stages": ["prestart"]
}

The following example injects nvidia-container-runtime-hook prestart in the pre-start stage if the container is configured with an annotations entry whose value matches .*fluid-dynamics.*.

$ cat /etc/containers/oci/hooks.d/osystemd-hook.json
{
  "hook": "/usr/sbin/nvidia-container-runtime-hook",
  "arguments": ["prestart"],
  "annotations": ["*.fluid-dynamics.*"],
  "stages": ["prestart"]
}
