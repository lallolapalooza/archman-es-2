Descripción detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es material avanzado y complejo. No lo necesitas a menos que realmente sepas lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo, y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se han limitado a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivos de archivador.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo de archivador que PhysicsFS no proporciona directamente: quizás algún formato propietario que solo tu aplicación necesite entender.

Internamente, todo el soporte de archivador incorporado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver son el código fuente de PhysicsFS mismo.

Un archivador se añade al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automáticamente con PHYSFS_mount(); si un archivador dado puede ser manejado por tu archivador, se le dará el control según corresponda.

Estos métodos tratan con manejadores de directorios. Tienes una instancia de tu archivador, y genera un manejador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archivador (no de un archivo) es generalmente la vida útil completa del proceso, y se asume que es un singleton, no proporcionamos datos de instancia para el archivador en sí; la aplicación puede usar variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para verificar los enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de devolver. PhysicsFS pasará estos errores a la aplicación sin modificar en la mayoría de los casos.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Archiver sean seguras para hilos por sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador determinado dentro de la biblioteca, pero no promete que usar el mismo PHYSFS_File desde dos hilos a la vez sea seguro para hilos; como tal, tu PHYSFS_Archiver puede asumir que el bloqueo se maneja por ti siempre que el PHYSFS_Io que devuelves desde PHYSFS_open* no cambie ningún estado de tu Archivador, ya que el PHYSFS_Io no estará tan agresivamente protegido.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruir un archivo previamente abierto. Cierra este archivo y libera cualquier memoria asociada, incluido el PHYSFS_Io original y el propio (opaco), si corresponde. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Listar todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, para que puedas desecharla al regresar de la llamada de retorno. (dirname) está en notación independiente de la plataforma. Si tienes un fallo, llama a PHYSFS_SetErrorCode() con el código que parezca apropiado y devuelve PHYSFS_ENUM_ERROR. Si la llamada de retorno devuelve PHYSFS_ENUM_ERROR, llama a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y luego devuelve PHYSFS_ENUM_ERROR también. No llames a la llamada de retorno de nuevo bajo ninguna circunstancia. Si la llamada de retorno devuelve PHYSFS_ENUM_STOP, deja de enumerar y devuelve PHYSFS_ENUM_STOP también. No llames a la llamada de retorno de nuevo bajo ninguna circunstancia. No establezcas un código de error en este caso. Las llamadas de retorno solo deben devolver un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene un comportamiento indefinido. Mientras la llamada de retorno haya devuelto PHYSFS_ENUM_OK y no hayas experimentado ningún error propio, sigue enumerando hasta que hayas terminado y luego devuelve PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate devuelve cero o no cero (éxito o fracaso), ¡así que ten en cuenta que este puntero de función devuelve valores diferentes!

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Se utiliza para identificar tu archivo y se devuelve en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crear un directorio en el archivador. Si la aplicación intenta crear varios directorios, PhysicsFS los dividirá en varias llamadas antes de pasarlos a tu controlador. Si el archivo es de solo lectura, esta operación debería fallar. Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abrir un archivo en este archivador para añadir. Si el archivo no existe, debe crearse. La posición de escritura debe ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de la plataforma. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve un valor distinto de NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaco" para llamadas de archivo posteriores.

PHYSFS_Archiver::openRead - physfs

NAME

PHYSFS_Archiver::openRead - Open a file in an archive for reading

SYNOPSIS

#include <physfs.h>

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque,
    const char *fnm);

DESCRIPTION

This function is a callback for the PHYSFS_mount(3) function. The PHYSFS_mount(3) function iterates through a list of PHYSFS_Archiver(3) structures, calling this function on each one until one returns non-NULL. The PHYSFS_mount(3) function will also pass an opaque pointer to the PHYSFS_Archiver(3) structure that successfully opened the archive. This opaque pointer will be passed to all subsequent calls to other functions in the same PHYSFS_Archiver(3) structure.

The PHYSFS_mount(3) function will then call openRead(), openWrite(), enumerate(), stat(), and delete() on this PHYSFS_Archiver(3) structure as needed. Finally, PHYSFS_mount(3) will call closeArchive() when the archive is unmounted.

The opaque parameter is a pointer to the PHYSFS_ArchiveInfo(3) structure that was returned by the PHYSFS_Archiver::openArchive() call that successfully mounted this archive. It is NULL if PHYSFS_mount(3) is opening the archive directly (which it will do if no archiver claims it).

The fnm parameter is the filename to open. This filename is always in platform-independent notation. Fail if the file does not exist. Return NULL on failure and set the error code via PHYSFS_setErrorCode(). Return non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls.

RETURN VALUES

Returns non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls. Returns NULL on failure, and calls PHYSFS_setErrorCode().
