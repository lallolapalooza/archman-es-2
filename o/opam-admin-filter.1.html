OPAM ADMIN-FILTER(1) Manual de administración de Opam OPAM ADMIN-FILTER(1)

NOMBRE

opam admin filter - Filtra un repositorio para mantener solo los paquetes seleccionados

SINOPSIS

opam admin filter [--dry-run] [--environment=VAR=VALOR[,VAR=VALOR]] [--remove] [OPCIÓN]… [PATRONES]…

DESCRIPCIÓN

Este comando elimina todas las definiciones de paquetes que no coinciden con los criterios de búsqueda (especificados de manera similar a 'opam admin list') de un repositorio.

SELECTORES SENSIBLES AL ORDEN

-a, --available
Lista solo los paquetes que están disponibles según el entorno definido. Sin --environment, esto incluirá cualquier paquete para el cual la disponibilidad no se pueda resolver en este momento.
-A, --all
Incluir todo, incluso paquetes no instalados o no disponibles.
--installable
Lista solo los paquetes que son instalables según el entorno definido (esto llama al solucionador y puede ser más costoso; un paquete que depende de uno no disponible puede estar disponible, pero nunca es instalable).
--latests-only
Lista solo la última versión de cada paquete.

ARGUMENTOS

PATRONES
Patrones de paquetes con comodines. Coinciden contra NOMBRE o NOMBRE.VERSIÓN

OPCIONES

--dry-run
Lista los comandos de eliminación, sin ejecutarlos realmente.
--environment=VAR=VALOR[,VAR=VALOR]
Utiliza el entorno de opam dado, en forma de una lista de enlaces 'var=valor' separados por comas, al resolver variables. Esto se utiliza, por ejemplo, al calcular paquetes disponibles: si no se define, la disponibilidad de los paquetes se asumirá tan pronto como no se pueda resolver puramente a partir de variables definidas globalmente. Tenga en cuenta que, a menos que se anule, las variables como 'root' o 'opam-version' pueden tomarse de la instalación de opam actual. Lo que se define en ~/.opam/config siempre se ignora.
--remove
Invierte el comportamiento y elimina los paquetes coincidentes, conservando los que no coinciden.

OPCIONES DE SELECCIÓN DE PAQUETES

--coinstallable-with=PAQUETES
Lista solo los paquetes que son compatibles con todos los de PAQUETES.
--conflicts-with=PAQUETES
Lista los paquetes que han declarado conflictos con al menos uno de la lista dada. Esto incluye conflictos definidos por los paquetes de la lista, por el otro paquete o por un campo común conflict-class:.
--depends-on=PAQUETES
Lista solo los paquetes que dependen de uno de los PAQUETES (separados por comas).
--depopts
Incluye dependencias opcionales en las solicitudes de dependencias.
--dev
Incluye paquetes de desarrollo en las dependencias.
--field-match=CAMPO:PATRÓN
Filtra paquetes con una coincidencia para PATRÓN en el CAMPO dado.
--has-flag=FLAG
Incluye solo paquetes que tienen establecida la bandera dada. Las banderas de paquete son una de: light-uninstall verbose plugin compiler conf
--has-tag=TAG
Incluye solo paquetes que tienen establecida la etiqueta dada.
--nobuild
Excluye las dependencias de compilación (se incluyen por defecto).
--or
En lugar de seleccionar paquetes que coinciden con todos los criterios, selecciona paquetes que coinciden con cualquiera de ellos.
--post
Incluye dependencias etiquetadas como post.
--recursive
Con `--depends-on' y `--required-by', muestra todas las dependencias transitivas en lugar de solo las dependencias directas.
--required-by=PAQUETES
Lista solo las dependencias de PAQUETES (separados por comas).
--resolve=PAQUETES
Restringe a una solución para instalar PAQUETES (separados por comas), es decir, un conjunto consistente de paquetes que incluye esos. Esto es sutilmente diferente de `--required-by --recursive`, que es más predecible y no puede fallar, pero enumera todas las dependencias de forma independiente sin garantizar la consistencia. Sin `--installed`, la respuesta es autocontenida e independiente de la instalación actual. Con `--installed', se calcula a partir del conjunto de paquetes actualmente instalados. `--no-switch' hace que la solución sea independiente de los paquetes fijados actualmente, la arquitectura y la versión del compilador. La combinación con `--depopts' no es compatible.
-t, --with-test, --test
Incluye dependencias solo de prueba.
--with-dev-setup
Incluye dependencias solo para desarrolladores.
--with-doc, --doc
Incluye dependencias solo de documentación.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intente instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Previsto para cualquier uso persistente de opam (scripts, publicaciones de blogs, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. La bandera no estaba disponible en opam 2.0, por lo que para seleccionar la interfaz de línea de comandos 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de always, never o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especifica las preferencias del usuario para la resolución de dependencias en esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje admitido y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general para usar preferencias de solucionadores se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Igual que --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está configurada (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FORMATO] (default=auto)
Muestra esta ayuda en formato FORMATO. El valor FORMATO debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por máquina. Si el nombre del archivo contiene el carácter `%', se reemplazará por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

OPTIONS

--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO en "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato anterior. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Usa ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT en ROOT.
--safe, --readonly
Asegúrate de que nada se actualice o reescriba automáticamente. Útil para llamadas desde scripts de completado, por ejemplo. Fallará cada vez que sea necesaria dicha operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el solucionador CUDF a usar para resolver problemas de instalación de paquetes. Este es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentra un error en la definición de un paquete o un archivo de configuración. Por defecto, continúa silenciosamente si es posible.
--switch=SWITCH
Usa SWITCH como el cambio de compilador actual. Esto es equivalente a establecer $OPAMSWITCH en SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo y usa el interno (esto requiere que opam se haya compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más verboso. Un -v muestra todos los comandos de paquetes, repetir para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.). Repetir n veces es equivalente a establecer $OPAMVERBOSE en "n".
--version
Mostrar información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes que están vinculados a un directorio local, controlado por versionamiento, actualiza al estado de trabajo actual de su fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio de origen se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES en "true".

ENTORNO

Opam hace uso de las variables de entorno listadas aquí. Las variables booleanas deben establecerse en "0", "no", "false" o la cadena vacía para deshabilitar, "1", "yes" o "true" para habilitar.

OPAMALLPARENS rodea todos los filtros con paréntesis.

OPAMBUILDDOC Eliminado en 2.1.

OPAMBUILDTEST Eliminado en 2.1.

OPAMCLI ver la opción `--cli'.

OPAMCOLOR cuando se establece en always o never, establece un valor predeterminado para la opción `--color'.

OPAMCONFIRMLEVEL ver la opción `--confirm-level`. OPAMCONFIRMLEVEL tiene prioridad sobre OPAMYES y OPAMNO.

OPAMCRITERIA especifica las preferencias del usuario para la resolución de dependencias. El valor predeterminado depende de la versión del solucionador, use `config report' para conocer la configuración actual. Ver también la opción --criteria.

OPAMCUDFFILE guarda el grafo cudf en archivo-actions-explicit.dot.

OPAMCUDFTRIM controla el filtrado de paquetes no relacionados durante el preprocesamiento de CUDF.

OPAMDEBUG ver las opciones `--debug' y `--debug-level'.

OPAMDEBUGSECTIONS si se establece, limita los mensajes de depuración a la lista de secciones separadas por espacios. Las secciones opcionalmente pueden tener un nivel de depuración específico (por ejemplo, CLIENT:2 o CLIENT CUDF:2), pero de lo contrario usan `--debug-level'.

OPAMDIGDEPTH define cuán agresiva es la búsqueda de conflictos durante el preprocesamiento de CUDF.

OPAMDOWNLOADJOBS establece el número máximo de descargas simultáneas.

OPAMDROPWORKINGDIR anula los paquetes actualizados previamente con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se nombren explícitamente en la línea de comandos.

OPAMDRYRUN ver la opción `--dry-run'.

OPAMEDITOR establece el editor a usar para editar archivos opam, anula $EDITOR y $VISUAL.

OPAMERRLOGLEN establece el número de líneas de registro impresas cuando un subproceso falla. 0 para imprimir todas.

OPAMEXTERNALSOLVER ver la opción `--solver'.

OPAMFAKE ver la opción `--fake'.

OPAMFETCH especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor 'download-command' del archivo de configuración principal.

OPAMIGNORECONSTRAINTS ver la opción de instalación `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS ver la opción `--ignore-pin-depends'.

OPAMINPLACEBUILD ver la opción `--inplace-build'.

OPAMJOBS establece el número máximo de trabajadores paralelos a ejecutar.

OPAMJSON registra la salida JSON en el archivo dado (usa el carácter `%' para indexar los archivos).

OPAMKEEPBUILDDIR ver la opción de instalación `--keep-build-dir'.

OPAMKEEPLOGS indica a opam que no elimine algunos registros de comandos temporales y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener trazas de pila más confiables.

OPAMLOCKED combinación de las opciones `--locked' y `--lock-suffix'.

OPAMMAKECMD establece el comando make del sistema a usar.

OPAMMERGEOUT fusiona las salidas del proceso, stderr en stdout.

OPAMNO responde no a cualquier pregunta, ver las opciones `--no` y `--confirm-level`. OPAMNO se ignora si OPAMCONFIRMLEVEL o OPAMYES están establecidos.

OPAMNOAGGREGATE con `opam admin check', no agregues paquetes.

OPAMNOCHECKSUMS habilita la opción --no-checksums cuando esté disponible.

OPAMNODEPEXTS deshabilita el manejo de dependencias del sistema, ver la opción `--no-depexts'.

OPAMNOENVNOTICE Interno.

OPAMROOTISOK no se queja al ejecutarse como root.

OPAMSAFE ver la opción `--safe'.

OPAMSHOW ver la opción `--show'.

OPAMSKIPUPDATE ver la opción `--skip-updates'.

OPAMSKIPVERSIONCHECKS omite algunas verificaciones de versión. Inseguro, solo para pruebas de compatibilidad.

OPAMSOLVERALLOWSUBOPTIMAL (predeterminado `true') permite que algunos solucionadores aún devuelvan una solución cuando alcanzan el tiempo de espera; mientras la solución sigue asegurada de ser consistente, en este caso no hay garantía de que cumpla los criterios de optimización esperados. Si es `true', opam continuará con una advertencia, si es `false' un tiempo de espera es un error. Actualmente solo el backend builtin-z3 maneja este caso degradado.

OPAMSOLVERTIMEOUT cambia el tiempo de asignación del solucionador. El valor predeterminado es 60.0, se establece en 0 para ilimitado. Tenga en cuenta que no todos los solucionadores pueden soportar esta opción.

OPAMSOLVERTOLERANCE cambia la tolerancia hacia el solucionador que elige una solución no optimizada (es decir, podría descargar paquetes desactualizados). Los valores típicos van de 0.0 (mejor solución conocida por el solucionador) a 1.0 (solución no optimizada). El valor predeterminado es 0.0. Esta opción es útil en caso de que el solucionador no pueda encontrar una solución en un tiempo razonable (ver $OPAMSOLVERTIMEOUT). Tenga en cuenta que no todos los solucionadores pueden admitir esta opción.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
