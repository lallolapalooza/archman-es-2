OPAM-REMOTE(1) Manual de Opam OPAM-REMOTE(1)

NOMBRE

opam-remote - Un alias para repository.

SINOPSIS

opam remote [--kind=TIPO] [--rank=RANGO] [--short] [OPCIÓN]… [COMANDO] [ARG]…

DESCRIPCIÓN

opam remote es un alias para opam repository.

Ver opam repository --help para detalles.

OPCIONES DE ESPECIFICACIÓN DE ALCANCE

-a, --all-switches
Actuar sobre las selecciones de todos los switches configurados
--dont-select
No actualizar ninguna selección
--on-switches=SWITCHES
Actuar sobre las selecciones de la lista dada de switches
--set-default
Actuar sobre la selección del repositorio por defecto que se utiliza para los switches recién creados
--this-switch
Actuar sobre las selecciones para el switch actual (este es el valor predeterminado)

OPCIONES

-k TIPO, --kind=TIPO
Especificar el tipo de repositorio a usar (uno de http, local, git, darcs o hg).
--rank=RANGO (ausente=1)
Establecer el rango del repositorio en la lista de repositorios configurados. Las definiciones de paquetes se buscan en los repositorios en orden ascendente de rango, por lo tanto, 1 es la prioridad más alta. Se pueden usar enteros negativos para seleccionar desde la prioridad más baja, siendo -1 el último. De lo contrario, se puede usar set-repos para establecer explícitamente la lista de repositorios de una vez.
-s, --short
Mostrar listas de nombres sin formato, una por línea, omitiendo cualquier detalle.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Usar la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Destinado a cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. El flag no estaba disponible en opam 2.0, por lo que para seleccionar la interfaz de línea de comandos 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorear la salida. CUÁNDO debe ser uno de always, never o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar varias veces. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especificar las preferencias del usuario para la resolución de dependencias en esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje soportado y los solucionadores externos disponibles, ver http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre el uso de preferencias de solucionadores se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: Guardar las solicitudes CUDF enviadas al solucionador en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Mostrar mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Mostrar la versión git de opam, si está configurada (es decir, si está usando una versión de desarrollo), y salir.
--help[=FMT] (predeterminado=auto)
Mostrar esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignorar pines adicionales requeridos por paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guardar los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%`, se reemplazará por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responder no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deberían definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato anterior. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Usar ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegurarse de que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de completado, por ejemplo. Fallará siempre que se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especificar el solucionador CUDF a utilizar para resolver problemas de instalación de paquetes. Este es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Fallar siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--switch=SWITCH
Usar SWITCH como el switch del compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilitar cualquier solucionador externo y usar el incorporado (esto requiere que opam haya sido compilado con un solucionador incorporado). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Ser más verboso. Una -v muestra todos los comandos de paquetes, repetir para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Mostrar información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes que están vinculados a un directorio local controlado por versión, actualice al estado de trabajo actual de su fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio fuente se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede configurar con $OPAMWORKINGDIR.
-y, --yes
Responder sí a todas las preguntas de sí/no de opam

ENTORNO

Opam utiliza las variables de entorno listadas aquí. Las variables booleanas deben establecerse en "0", "no", "false" o la cadena vacía para deshabilitar, "1", "yes" o "true" para habilitar.

OPAMALLPARENS rodea todos los filtros con paréntesis.

OPAMASSUMEDEPEXTS véase la opción `--assume-depexts'.

OPAMAUTOREMOVE véase la opción de eliminación `--auto-remove'.

OPAMBESTEFFORT véase la opción `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA establece la cadena que debe anteponerse a los criterios cuando se establece la opción `--best-effort', y se espera que maximice la propiedad `opam-query' en la solución.

OPAMBUILDDOC Eliminado en 2.1.

OPAMBUILDTEST Eliminado en 2.1.

OPAMCLI véase la opción `--cli'.

OPAMCOLOR cuando se establece en always o never, establece un valor predeterminado para la opción `--color'.

OPAMCONFIRMLEVEL véase la opción `--confirm-level`. OPAMCONFIRMLEVEL tiene prioridad sobre OPAMYES y OPAMNO.

OPAMCRITERIA especifica las preferencias del usuario para la resolución de dependencias. El valor predeterminado depende de la versión del solucionador, utilice `config report' para conocer la configuración actual. Véase también la opción --criteria.

OPAMCUDFFILE guarda el grafo cudf en file-actions-explicit.dot.

OPAMCUDFTRIM controla el filtrado de paquetes no relacionados durante el preprocesamiento de CUDF.

OPAMCURL puede utilizarse para seleccionar un programa 'curl' determinado. Véase OPAMFETCH para más opciones.

OPAMDEBUG véase las opciones `--debug' y `--debug-level'.

OPAMDEBUGSECTIONS si se establece, limita los mensajes de depuración a la lista de secciones separadas por espacios. Las secciones pueden tener opcionalmente un nivel de depuración específico (por ejemplo, CLIENT:2 o CLIENT CUDF:2), pero de lo contrario utilizan `--debug-level'.

OPAMDIGDEPTH define cuán agresiva es la búsqueda de conflictos durante el preprocesamiento de CUDF.

OPAMDOWNLOADJOBS establece el número máximo de descargas simultáneas.

OPAMDROPWORKINGDIR anula los paquetes actualizados previamente con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se nombraran explícitamente en la línea de comandos.

OPAMDRYRUN véase la opción `--dry-run'.

OPAMEDITOR establece el editor que se utilizará para editar archivos opam, anula $EDITOR y $VISUAL.

OPAMERRLOGLEN establece el número de líneas de registro que se imprimen cuando falla un subproceso. 0 para imprimir todas.

OPAMEXTERNALSOLVER véase la opción `--solver'.

OPAMFAKE véase la opción `--fake'.

OPAMFETCH especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor de 'download-command' del archivo de configuración principal.

OPAMFIXUPCRITERIA igual que OPAMUPGRADECRITERIA, pero específico para correcciones e reinstalaciones.

OPAMIGNORECONSTRAINTS véase la opción de instalación `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS véase la opción `--ignore-pin-depends'.

OPAMINPLACEBUILD véase la opción `--inplace-build'.

OPAMJOBS establece el número máximo de trabajadores paralelos a ejecutar.

OPAMJSON registra la salida json en el archivo dado (use el carácter `%` para indexar los archivos).

OPAMKEEPBUILDDIR véase la opción de instalación `--keep-build-dir'.

OPAMKEEPLOGS indica a opam que no elimine algunos registros temporales de comandos y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener rastreos de pila más fiables.

OPAMLOCKED combinación de las opciones `--locked' y `--lock-suffix'.

OPAMLOGS logdir establece el directorio de registros, el valor predeterminado es un directorio temporal en /tmp

OPAMMAKECMD establece el comando make del sistema a utilizar.

OPAMMERGEOUT fusiona las salidas del proceso, stderr en stdout.

OPAMNO responde no a cualquier pregunta formulada, véase las opciones `--no` y `--confirm-level`. OPAMNO se ignora si se establece OPAMCONFIRMLEVEL o OPAMYES.

OPAMNOAGGREGATE con `opam admin check', no agrupar paquetes.

OPAMNOASPCUD Obsoleto.

OPAMNOAUTOUPGRADE deshabilita la actualización automática interna de repositorios en un formato anterior al actual, en 'update' o 'init'.

OPAMNOCHECKSUMS habilita la opción --no-checksums cuando esté disponible.

OPAMNODEPEXTS deshabilita el manejo de dependencias del sistema, véase la opción `--no-depexts'.

OPAMNOENVNOTICE Interno.

OPAMNOSELFUPGRADE véase la opción `--no-self-upgrade'

OPAMPINKINDAUTO establece si los sistemas de control de versiones deben detectarse al fijar a una ruta local. Habilitado por defecto desde 1.3.0.

OPAMPRECISETRACKING seguimiento detallado de directorios.

OPAMPREPRO establézcase esto a false para deshabilitar el preprocesamiento de CUDF. Menos eficiente, pero podría ayudar a depurar problemas del solucionador.

OPAMREPOSITORYTARRING almacena internamente los repositorios como archivos tar.gz. Esto puede ser mucho más rápido en sistemas de archivos que no manejan bien el escaneo de árboles grandes pero que tienen una buena caché en /tmp. Sin embargo, esto es más lento en el caso general.

OPAMREQUIRECHECKSUMS Habilita la opción `--require-checksums' cuando esté disponible (por ejemplo, para `opam install').

OPAMRETRIES establece el número de intentos antes de fallar las descargas.

OPAMREUSEBUILDDIR véase la opción `--reuse-build-dir'.

OPAMROOT véase la opción `--root'. Esto se establece automáticamente mediante `opam env --root=DIR --set-root'.

OPAMROOTISOK no se queja al ejecutarse como root.

OPAMSAFE véase la opción `--safe'.

OPAMSHOW véase la opción `--show'.

OPAMSKIPUPDATE véase la opción `--skip-updates'.

OPAMSKIPVERSIONCHECKS omite algunas comprobaciones de versión. Inseguro, solo para pruebas de compatibilidad.

OPAMSOLVERALLOWSUBOPTIMAL (predeterminado `true') permite que algunos solucionadores devuelvan una solución cuando alcanzan el tiempo límite; si bien se garantiza que la solución es coherente, en este caso no hay garantía de que se ajuste a los criterios de optimización esperados. Si es `true', opam continuará con una advertencia, si es `false' un tiempo límite es un error. Actualmente solo el backend builtin-z3 maneja este caso degradado.

OPAMSOLVERTIMEOUT cambia el tiempo de asignación del solucionador. El valor predeterminado es 60.0, establecido en 0 para ilimitado. Tenga en cuenta que es posible que no todos los solucionadores soporten esta opción.

OPAMSOLVERTOLERANCE cambia la tolerancia hacia el solucionador que elige una solución no optimizada (es decir, podría extraer paquetes obsoletos). Los valores típicos van de 0.0 (mejor solución conocida por el solucionador) a 1.0 (solución no optimizada). El valor predeterminado es 0.0. Esta opción es útil en caso de que el solucionador no pueda encontrar una solución en un tiempo razonable (véase $OPAMSOLVERTIMEOUT). Tenga en cuenta que es posible que no todos los solucionadores soporten esta opción.

OPAMSTATS Eliminado en 2.4.

OPAMSTATUSLINE muestra una línea de estado dinámica que indica lo que está sucediendo actualmente en la terminal. (uno de always, never o auto)

OPAMSTRICT falla ante inconsistencias (lectura de archivos, importación de cambios, etc.).

OPAMSWITCH véase la opción `--switch'. Se establece automáticamente mediante `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE véase la opción de instalación `--unlock-base'.

OPAMUPGRADECRITERIA especifica las preferencias del usuario para la resolución de dependencias al realizar una actualización. Anula OPAMCRITERIA en las actualizaciones si ambas están establecidas. Véase también la opción --criteria.

OPAMUSEINTERNALSOLVER véase la opción `--use-internal-solver'.

OPAMUSEOPENSSL Eliminado en 2.2.

OPAMUTF8 utiliza caracteres UTF8 en la salida (uno de always, never o auto). Por defecto `auto', que se determina a partir de la configuración regional).

OPAMUTF8MSGS utiliza caracteres UTF8 extendidos (camellos) en los mensajes de opam. Implica OPAMUTF8. Esto está activado por defecto solo en macOS.

OPAMVALIDATIONHOOK si se establece, utiliza el comando `%{hook%}' para validar una actualización del repositorio de opam.

OPAMVERBOSE véase la opción `--verbose'.

OPAMVERBOSEON véase la opción --verbose-on

OPAMVERSIONLAGPOWER no usar.

OPAMWITHDEVSETUP véase la opción de instalación `--with-dev-setup'.

OPAMWITHDOC véase la opción de instalación `--with-doc'.

OPAMWITHTEST véase la opción de instalación `--with-test.

OPAMWORKINGDIR véase la opción `--working-dir'.

OPAMYES véase las opciones `--yes' y `--confirm-level`. OPAMYES tiene prioridad sobre OPAMNO y se ignora si OPAMCONFIRMLEVEL está establecido.

OPAMVAR_var anula el contenido de la variable var al sustituir cadenas `%{var}%` en archivos `opam`.

OPAMVAR_package_var anula el contenido de la variable package:var al sustituir cadenas `%{package:var}%` en archivos `opam`.

VERSIÓN CLI

Todos los scripts e invocaciones programáticas de opam deben usar `--cli' para garantizar que funcionen sin problemas con versiones futuras del cliente opam. Además, las publicaciones de blog u otra documentación pueden beneficiarse, ya que evita que la información se vuelva obsoleta.

Aunque opam solo admite raíces (~/.opam/) para la versión actual, proporciona retrocompatibilidad para su interfaz de línea de comandos.

Dado que el soporte de versiones de CLI solo se agregó en opam 2.1, use OPAMCLI para seleccionar el soporte 2.0 (ya que opam 2.0 simplemente lo ignorará), y `--cli=2.1' para versiones 2.1 (o posteriores), ya que una variable de entorno que controla el análisis de sintaxis es frágil. Para este fin, opam muestra una advertencia si OPAMCLI especifica una versión válida distinta de 2.0, y también si se especifica `--cli=2.0'.

La versión de la línea de comandos se selecciona utilizando la opción `--cli' o la variable de entorno OPAMCLI. `--cli' puede especificarse más de una vez, donde la última instancia tiene precedencia. OPAMCLI solo se inspecciona si no se proporciona `--cli'.

ESTADO DE SALIDA

Como excepción a lo siguiente, el comando `exec` devuelve 127 si el comando no se encontró o no se pudo ejecutar, y el valor de salida del comando de lo contrario.

0
Éxito, o verdadero para consultas booleanas.
1
Falso. Devuelto cuando se espera un valor de retorno booleano, por ejemplo, al ejecutar con --check, o para consultas como opam lint.
2
Argumentos de línea de comandos incorrectos, o argumentos de línea de comandos que apuntan a un contexto inválido (por ejemplo, archivo que no sigue el formato esperado).
5
No encontrado. Solicitaste algo (paquete, versión, repositorio, etc.) que no se pudo encontrar.
10
Abortado. La operación requirió confirmación, la cual no se dio.
15
No se pudieron adquirir los bloqueos requeridos para la operación.
20
No hay solución a la solicitud del usuario. Esto puede ser causado por solicitar instalar dos paquetes incompatibles, por ejemplo.
30
Error en la definición del paquete, u otros archivos de metadatos. Usar --strict genera este error con más frecuencia.
31
Error en el script del paquete. Algunas operaciones del paquete no fueron exitosas. Esto puede ser un error en los paquetes o una incompatibilidad con tu sistema. Esto puede ser un error parcial.
40
Error de sincronización. No se pudieron obtener algunos remotos de la red. Esto puede ser un error parcial.
50
Error de configuración. La configuración de Opam o del sistema no permite la operación y necesita ser corregida.
60
Fallo del solucionador. El solucionador no pudo devolver una respuesta válida. Puede ser debido a un solucionador externo roto, o un error en la configuración del solucionador.
99
Error interno. Algo salió mal, probablemente debido a un error en opam en sí mismo.
130
Interrupción del usuario. Se recibió SIGINT, generalmente debido a que el usuario presionó Ctrl-C.
0
en caso de éxito.
123
en errores indiscriminados reportados en la salida estándar.
124
en errores de análisis de línea de comandos.
125
en errores internos inesperados (bugs).
