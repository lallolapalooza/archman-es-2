OPAM ADMIN-ADD-HASHES(1) Manual de administración de Opam OPAM ADMIN-ADD-HASHES(1)

NOMBRE

opam admin-add-hashes - Añade hashes de archivo a un repositorio opam.

SINOPSIS

opam admin add-hashes [--packages=PAQUETES] [--replace] [OPCIÓN]… ALGO_HASH…

DESCRIPCIÓN

Este comando escanea las definiciones de paquetes y añade los hashes solicitados (descargando los archivos si es necesario). Se genera una caché en <opamroot>/download-cache/hash-cache para ejecuciones posteriores.

ARGUMENTOS

ALGO_HASH (obligatorio)
El hash, o hashes a añadir

OPCIONES

-p PAQUETES, --packages=PAQUETES
Añadir hashes solo para los paquetes dados
--replace
Reemplazar los hashes existentes en lugar de añadirlos.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Usar la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Destinado a cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam de la misma serie MAYOR se comportará como para la versión MENOR especificada. La opción no estaba disponible en opam 2.0, así que para seleccionar la CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en su lugar.
--color=CUÁNDO
Colorear la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o unsafe-yes. Se puede especificar más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especificar las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje admitido y los solucionadores externos disponibles, véase http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre el uso de preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBRE_ARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprimir mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Al igual que --debug, pero permite especificar el nivel de depuración (--debug lo establece a 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprimir la versión git de opam, si está establecida (es decir, si está utilizando una versión de desarrollo), y salir.
--help[=FMT] (default=auto)
Mostrar esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable de entorno TERM sea dumb o indefinida.
--ignore-pin-depends
Ignorar pines adicionales requeridos por paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guardar los resultados de la ejecución de opam en un archivo legible por ordenador. Si el nombre del archivo contiene el carácter `%', este será reemplazado por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responder no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en la versión 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato más antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
-q, --quiet
Deshabilita --verbose.
--root=RAÍZ
Usar RAÍZ como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a RAÍZ.
--safe, --readonly
Asegurarse de que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de finalización, por ejemplo. Fallará siempre que se necesite una operación de este tipo; también evita esperar por bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especificar el solucionador CUDF a usar para resolver problemas de instalación de paquetes. Puede ser un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Fallar siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. Por defecto, continúa silenciosamente si es posible.
--switch=SWITCH
Usar SWITCH como el switch del compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilitar cualquier solucionador externo y usar el interno (esto requiere que opam haya sido compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Ser más detallado. Una vez -v muestra todos los comandos de paquetes, repetir para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Mostrar información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes vinculados a un directorio local y controlado por versiones, actualizar al estado de trabajo actual de su código fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio de código fuente se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responder sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

VERSIÓN DE CLI

Todos los scripts e invocaciones programáticas de opam deben usar `--cli' para garantizar que funcionen sin problemas con versiones futuras del cliente opam. Además, las publicaciones de blog u otra documentación pueden beneficiarse, ya que evita que la información se vuelva obsoleta.

Aunque opam solo admite raíces (~/.opam/) para la versión actual, proporciona retrocompatibilidad para su interfaz de línea de comandos.

Dado que el soporte de la versión CLI solo se agregó en opam 2.1, use OPAMCLI para seleccionar el soporte 2.0 (ya que opam 2.0 lo ignorará), y `--cli=2.1' para versiones 2.1 (o posteriores), ya que una variable de entorno que controla el análisis de sintaxis es frágil. Para ello, opam muestra una advertencia si OPAMCLI especifica una versión válida distinta de 2.0, y también si se especifica `--cli=2.0'.

La versión de la línea de comandos se selecciona utilizando la opción `--cli' o la variable de entorno OPAMCLI. `--cli' puede especificarse más de una vez, donde la última instancia tiene prioridad. OPAMCLI solo se inspecciona si no se proporciona `--cli'.

ESTADO DE SALIDA

0
Éxito, o verdadero para consultas booleanas.
1
Falso. Devuelto cuando se espera un valor booleano de retorno, por ejemplo, al ejecutarse con --check, o para consultas como opam lint.
2
Argumentos de línea de comandos incorrectos, o argumentos de línea de comandos que apuntan a un contexto inválido (por ejemplo, un archivo que no sigue el formato esperado).
5
No encontrado. Solicitaste algo (paquete, versión, repositorio, etc.) que no se pudo encontrar.
10
Abortado. La operación requirió confirmación, la cual no se dio.
15
No se pudieron adquirir los bloqueos requeridos para la operación.
20
No hay solución para la solicitud del usuario. Esto puede ser causado por solicitar la instalación de dos paquetes incompatibles, por ejemplo.
30
Error en la definición del paquete, u otros archivos de metadatos. Usando

NAME

opam-admin -- manage opam(1) administration files

SYNOPSIS

opam-admin cache list [--sha256]

opam-admin display [--dev-info] [--dev-deps] [--dev-conflicts] [--dev-version-overrides] [--dev-all] package

opam-admin export [--switch=switch] [--root=dir] [--file=file] [--all-switches]

opam-admin import [--switch=switch] [--root=dir] [--file=file] [--all-switches] [--force]

opam-admin pin [--all-switches] [--root=dir] [--file=file] pkg [ver]

opam-admin make-uninstall-script [--root=dir] [--file=file] [--all-switches] [--all-packages]

opam-admin check [--root=dir] [--all-switches]

opam-admin switch-creation-vars [--root=dir] [--name=name] [--base=base] [--extra-repositories=repo,...]

opam-admin dev-pkg depend [--root=dir] [--switch=switch] pkg ver

opam-admin dev-pkg install [--root=dir] [--switch=switch] pkg [ver]

opam-admin dev-pkg remove [--root=dir] [--switch=switch] pkg

opam-admin dev-pkg update [--root=dir] [--switch=switch] pkg

opam-admin dev-pkg build [--root=dir] [--switch=switch] pkg

opam-admin dev-pkg clean [--root=dir] [--switch=switch] pkg

opam-admin dev-pkg diff [--root=dir] [--switch=switch] pkg

DESCRIPTION

This subcommand is a collection of utility commands for package developers and system administrators.

ARGUMENTS

files...
For add-hashes, one or more files to process.
name
For config, the name of the configuration variable.
package
For display, the name of the package.
pkg
For pin, the name of the package to pin.
ver
For pin, the version to pin the package to. If not specified, the current version is used.
name
For switch-creation-vars, the name of the switch.
base
For switch-creation-vars, the base switch to copy from.
repo,...
For switch-creation-vars, a comma-separated list of extra repositories to add.
old
For upgrade, the old version of opam.
new
For upgrade, the new version of opam.

For add-hashes, automatically answer yes to any prompts.
-f, --force

--check

--keep-old

--diff

--output=file

--show-value

--dev-info

--dev-deps

--dev-conflicts
For display, show development conflicts.
--dev-version-overrides

--dev-all

--switch=switch

--file=file
