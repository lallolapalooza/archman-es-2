OPAM-SHOW(1) Manual de Opam OPAM-SHOW(1)

NOMBRE

opam-show - Muestra información sobre paquetes específicos.

SINOPSIS

opam show [OPCIÓN]… [PAQUETES]…

DESCRIPCIÓN

Este comando muestra el bloque de información para el(los) paquete(s) seleccionado(s).

El bloque de información consta del nombre del paquete, la versión instalada si este paquete está instalado en el compilador actualmente seleccionado, la lista de versiones disponibles (instalables) y una descripción completa.

opam list se puede usar para mostrar la lista de paquetes disponibles así como una breve descripción para cada uno.

También se pueden especificar rutas a archivos de definición de paquetes o a directorios que contengan definiciones de paquetes, en cuyo caso se mostrarán los metadatos correspondientes.

Nota: en terminales que lo soporten, los números de versión se pueden colorear de las siguientes maneras:

-
Magenta y negrita: versiones instaladas en el switch actual
-
Negrita: versiones instaladas en otros switches
-
Rojo y tachado: versiones no disponibles en la plataforma actual
-
Gris: versiones etiquetadas con el flag avoid-version o deprecated

ARGUMENTOS

PAQUETES
Lista de nombres de paquetes, con una versión o restricción opcional, por ej. `pkg', `pkg.1.0' o `pkg>=0.5' ; o nombres de archivos o directorios que contengan la descripción del paquete, con directorio explícito (por ej. `./foo.opam' o `.')

OPCIONES

--all-versions
Muestra la información de todos los paquetes que coinciden con PAQUETES, no restringido a un solo paquete que coincida con las restricciones de PAQUETES.
--empty-fields
Muestra campos que están vacíos. Esto se implica cuando se proporciona --field.
-f CAMPOS, --field=CAMPOS
Solo muestra los valores de estos campos. Los campos se pueden seleccionar entre name, version, package, synopsis, synopsis-or-target, description, <campo>, <campo>:, installed-version, pin, source-hash, opam-file, all-installed-versions, available-versions, all-versions, repository, installed-files, vc-ref, depexts. Se pueden separar múltiples campos con comas, en cuyo caso se imprimirán los títulos de los campos; el valor crudo de cualquier campo de opam-file se puede consultar combinando con --raw
--file=ARCHIVO (ausente=-)
Eliminado en la versión 2.1, usa --just-file en su lugar.
--just-file
Carga y muestra información de los archivos dados (los PAQUETES permitidos son rutas de archivos o directorios), sin tener en cuenta los repositorios o el estado del paquete. Esto implica --raw a menos que se use --fields. Solo se pueden consultar campos crudos de opam-file. Si no se proporciona ningún argumento de PAQUETES, lee el archivo opam de la entrada estándar.
--list-files
Lista los archivos instalados por el paquete. Equivalente a --field=installed-files, y solo disponible para paquetes instalados
--no-lint
No emite advertencias o errores de linting al leer desde archivos
--normalise
Imprime los valores de los campos opam normalizados (sin saltos de línea, sin corchetes implícitos)
--raw
Imprime el archivo opam crudo para este paquete
--sort
Ordena los campos opam
--where
Imprime la ubicación del archivo opam utilizado para este paquete

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no todos los paquetes solicitados pueden ser instalados: intenta instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utiliza la sintaxis y semántica de la línea de comandos de MAYOR.MENOR. Diseñado para cualquier uso persistente de opam (scripts, publicaciones de blogs, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. La bandera no estaba disponible en opam 2.0, por lo que para seleccionar la CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de always, never o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL`.
--criteria=CRITERIOS
Especifica las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje soportado y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general para utilizar las preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: guarda las solicitudes CUDF enviadas al solucionador en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Igual que --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está configurada (es decir, si está utilizando una versión de desarrollo), y sale.
--help[=FMT] (predeterminado=auto)
Muestra esta ayuda en el formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora pines adicionales requeridos por paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%`, se reemplazará por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en la versión 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo que se encuentre en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=RAÍZ
Usa RAÍZ como la ruta de raíz actual. Esto es equivalente a establecer $OPAMROOT a RAÍZ.
--safe, --readonly
Asegúrate de que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de completado, por ejemplo. Fallará siempre que sea necesaria dicha operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer el entorno

OPTIONS

-a, --all
Show all installed packages, including those that have been removed from the repositories. This is equivalent to setting $OPAMALL.
--all-switches
Operate on all switches.
--as-needed
Only keep packages that are currently needed by installed packages, or dependencies of packages with development files. This is equivalent to setting $OPAMASNEEDED.
--assume-depexts
Assume that system packages have been installed. This is equivalent to setting $OPAMASSUMEDEPEXTS.
--auto-remove
Remove packages that are no longer needed. This is equivalent to setting $OPAMAUTOREMOVE.
--best-effort
Try to find a solution even if it doesn't exactly match the requirements. This is equivalent to setting $OPAMBESTEFFORT.
--build-within-switch
Build packages within the switch directory, rather than in a separate build directory. This is equivalent to setting $OPAMBUILDWITHINSWITCH.
-C, --chdir=DIR
Change directory to DIR before proceeding. This is equivalent to setting $OPAMWORKDIR.
--check-only
Only check for errors, do not perform any actions. This is equivalent to setting $OPAMCHECKONLY.
--cli=CMD
Specify the command-line interface to use. This is equivalent to setting $OPAMCLI.
--color=MODE
Set color mode to MODE (always, never, auto). This is equivalent to setting $OPAMCOLOR.
--confirm-level=LEVEL
Set the confirmation level to LEVEL. Possible values are: low, medium, high, never. This is equivalent to setting $OPAMCONFIRMLEVEL.
--criteria=CRITERIA
Specify user preferences for dependency solving. This is equivalent to setting $OPAMCRITERIA.
--curl=CMD
Specify the curl program to use. This is equivalent to setting $OPAMCURL.
-d, --debug
Enable debugging output. This is equivalent to setting $OPAMDEBUG to 1.
--debug-level=LEVEL
Set the debugging level to LEVEL. This is equivalent to setting $OPAMDEBUG to LEVEL.
--debug-sections=SECTIONS
Limit debugging output to the specified sections. This is equivalent to setting $OPAMDEBUGSECTIONS.
-D, --dev
Install development files for packages. This is equivalent to setting $OPAMDEV.
--digdepth=DEPTH
Set the depth for digging into dependency conflicts. This is equivalent to setting $OPAMDIGDEPTH.
--download-jobs=NUM
Set the maximum number of simultaneous downloads to NUM. This is equivalent to setting $OPAMDOWNLOADJOBS.
--dry-run
Show what would be done, without actually doing it. This is equivalent to setting $OPAMDRYRUN.
--editor=CMD
Specify the editor command to use. This is equivalent to setting $OPAMEDITOR.
--errloglen=LEN
Set the number of log lines to print when a sub-process fails. This is equivalent to setting $OPAMERRLOGLEN.
--fake
Perform operations in a simulated environment. This is equivalent to setting $OPAMFAKE.
--fetch=CMD
Specify the command to use for fetching files. This is equivalent to setting $OPAMFETCH.
--fixup-criteria=CRITERIA
Specify user preferences for dependency solving when fixing up packages. This is equivalent to setting $OPAMFIXUPCRITERIA.
-f, --force
Force operations, even if it means overwriting existing files or ignoring warnings. This is equivalent to setting $OPAMFORCE.
-i, --install-as-is
Install packages without checking for conflicts or missing dependencies. This is equivalent to setting $OPAMINSTALLASIS.
--inplace-build
Build packages in their source directory. This is equivalent to setting $OPAMINPLACEBUILD.
--jobs=NUM
Set the maximum number of parallel workers to NUM. This is equivalent to setting $OPAMJOBS.
--keep-build-dir
Keep the build directory after a package has been built. This is equivalent to setting $OPAMKEEPBUILDDIR.
--keep-logs
Keep build logs and temporary files. This is equivalent to setting $OPAMKEEPLOGS.
--lock-suffix=SUFFIX
Use the specified suffix for lock files. This is equivalent to setting $OPAMLOCKED.
-y, --yes
Answer yes to all opam yes/no questions without prompting. See also --confirm-level. This is equivalent to setting $OPAMYES to "true".
--no
Answer no to all opam yes/no questions without prompting. This is equivalent to setting $OPAMNO to "true".
--no-aggregate
Disable aggregation of packages. This is equivalent to setting $OPAMNOAGGREGATE.
--no-auto-upgrade
Disable automatic upgrade of repositories. This is equivalent to setting $OPAMNOAUTOUPGRADE.
--no-checksums
Do not check package checksums. This is equivalent to setting $OPAMNOCHECKSUMS.
--no-depexts
Do not install system dependencies. This is equivalent to setting $OPAMNODEPEXTS.
--no-self-upgrade
Do not automatically upgrade opam itself. This is equivalent to setting $OPAMNOSELFUPGRADE.
--no-solver-check
Do not check the solver compatibility. This is equivalent to setting $OPAMNOSOLVERCHECK.
--opam-root=DIR
Use DIR as the root directory for opam. This is equivalent to setting $OPAMROOT.
--pin-kinda-auto
Enable automatic detection of version control systems when pinning to a local path. This is equivalent to setting $OPAMPINKINDAUTO.
--repository-tarring
Store repositories as tar.gz files. This is equivalent to setting $OPAMREPOSITORYTARRING.
--reuse-build-dir
Reuse the build directory if it already exists. This is equivalent to setting $OPAMREUSEBUILDDIR.
--safe
Perform operations in a safe environment. This is equivalent to setting $OPAMSAFE.
--solver=CMD
Specify the CUDF solver to use for resolving package installation problems. This is either a predefined solver (this version of opam supports builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), or a custom command that should contain the variables %{input}%, %{output}%, %{criteria}%, and optionally %{timeout}%. This is equivalent to setting $OPAMEXTERNALSOLVER.
--strict
Fail whenever an error is found in a package definition or a configuration file. The default is to continue silently if possible.
--switch=SWITCH
Use SWITCH as the current compiler switch. This is equivalent to setting $OPAMSWITCH to SWITCH.
--use-internal-solver
Disable any external solver, and use the built-in one (this requires that opam has been compiled with a built-in solver). This is equivalent to setting $OPAMNOASPCUD or $OPAMUSEINTERNALSOLVER.
-v, --verbose
Be more verbose. One -v shows all package commands, repeat to also display commands called internally (e.g. tar, curl, patch etc.) Repeating n times is equivalent to setting $OPAMVERBOSE to "n".
--version
Show version information.
-w, --working-dir
Whenever updating packages that are bound to a local, version-controlled directory, update to the current working state of their source instead of the last committed state, or the ref they are pointing to. As source directory is copied as it is, if it isn't clean it may result on a opam build failure. This only affects packages explicitly listed on the command-line. It can also be set with $OPAMWORKINGDIR.
-y, --yes
Answer yes to all opam yes/no questions without prompting. See also --confirm-level. This is equivalent to setting $OPAMYES to "true".

ENVIRONMENT

Opam makes use of the environment variables listed here. Boolean variables should be set to "0", "no", "false" or the empty string to disable, "1", "yes" or "true" to enable.

OPAMALLPARENS surround all filters with parenthesis.

OPAMASSUMEDEPEXTS see option `--assume-depexts'.

OPAMAUTOREMOVE see remove option `--auto-remove'.

OPAMBESTEFFORT see option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA sets the string that must be prepended to the criteria when the `--best-effort' option is set, and is expected to maximise the `opam-query' property in the solution.

OPAMBUILDDOC Removed in 2.1.

OPAMBUILDTEST Removed in 2.1.

OPAMCLI see option `--cli'.

OPAMCOLOR when set to always or never, sets a default value for the `--color' option.

OPAMCONFIRMLEVEL see option `--confirm-level`. OPAMCONFIRMLEVEL has priority over OPAMYES and OPAMNO.

OPAMCRITERIA specifies user preferences for dependency solving. The default value depends on the solver version, use `config report' to know the current setting. See also option --criteria.

OPAMCUDFFILE save the cudf graph to file-actions-explicit.dot.

OPAMCUDFTRIM controls the filtering of unrelated packages during CUDF preprocessing.

OPAMCURL can be used to select a given 'curl' program. See OPAMFETCH for more options.

OPAMDEBUG see options `--debug' and `--debug-level'.

OPAMDEBUGSECTIONS if set, limits debug messages to the space-separated list of sections. Sections can optionally have a specific debug level (for example, CLIENT:2 or CLIENT CUDF:2), but otherwise use `--debug-level'.

OPAMDIGDEPTH defines how aggressive the lookup for conflicts during CUDF preprocessing is.

OPAMDOWNLOADJOBS sets the maximum number of simultaneous downloads.

OPAMDROPWORKINGDIR overrides packages previously updated with --working-dir on update. Without this variable set, opam would keep them unchanged unless explicitly named on the command-line.

OPAMDRYRUN see option `--dry-run'.

OPAMEDITOR sets the editor to use for opam file editing, overrides $EDITOR and $VISUAL.

OPAMERRLOGLEN sets the number of log lines printed when a sub-process fails. 0 to print all.

OPAMEXTERNALSOLVER see option `--solver'.

OPAMFAKE see option `--fake'.

OPAMFETCH specifies how to download files: either `wget', `curl' or a custom command where variables %{url}%, %{out}%, %{retry}%, %{compress}% and %{checksum}% will be replaced. Overrides the 'download-command' value from the main config file.

OPAMFIXUPCRITERIA same as OPAMUPGRADECRITERIA, but specific to fixup and reinstall.

OPAMIGNORECONSTRAINTS see install option `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS see option `--ignore-pin-depends'.

OPAMINPLACEBUILD see option `--inplace-build'.

OPAMJOBS sets the maximum number of parallel workers to run.

OPAMJSON log json output to the given file (use character `%' to index the files).

OPAMKEEPBUILDDIR see install option `--keep-build-dir'.

OPAMKEEPLOGS tells opam to not remove some temporary command logs and some backups. This skips some finalisers and may also help to get more reliable backtraces.

OPAMLOCKED combination of `--locked' and `--lock-suffix' options.

OPAMLOGS logdir sets log directory, default is a temporary directory in /tmp

OPAMMAKECMD set the system make command to use.

OPAMMERGEOUT merge process outputs, stderr on stdout.

OPAMNO answer no to any question asked, see options `--no` and `--confirm-level`. OPAMNO is ignored if either OPAMCONFIRMLEVEL or OPAMYES is set.

OPAMNOAGGREGATE with `opam admin check', don't aggregate packages.

OPAMNOASPCUD Deprecated.

OPAMNOAUTOUPGRADE disables automatic internal upgrade of repositories in an earlier format to the current one, on 'update' or 'init'.

OPAMNOCHECKSUMS enables option --no-checksums when available.

OPAMNODEPEXTS disables system dependencies handling, see option `--no-depexts'.

OPAMNOENVNOTICE Internal.

OPAMNOSELFUPGRADE see option `--no-self-upgrade'

OPAMPINKINDAUTO sets whether version control systems should be detected when pinning to a local path. Enabled by default since 1.3.0.

OPAMPRECISETRACKING fine grain tracking of directories.

OPAMPREPRO set this to false to disable CUDF preprocessing. Less efficient, but might help debugging solver issue.

OPAMREPOSITORYTARRING internally store the repositories as tar.gz files. This can be much faster on filesystems that don't cope well with scanning large trees but have good caching in /tmp. However this is slower in the general case.

OPAMREQUIRECHECKSUMS Enables option `--require-checksums' when available (e.g. for `opam install').

OPAMRETRIES sets the number of tries before failing downloads.

OPAMREUSEBUILDDIR see option `--reuse-build-dir'.

OPAMROOT see option `--root'. This is automatically set by `opam env --root=DIR --set-root'.

OPAMROOTISOK don't complain when running as root.

OPAMSAFE see option `--safe'.

OPAMSHOW see option `--show'.

OPAMSKIPUPDATE see option `--skip-updates'.

OPAMSKIPVERSIONCHECKS bypasses some version checks. Unsafe, for compatibility testing only.

OPAMSOLVERALLOWSUBOPTIMAL (default `true') allows some solvers to still return a solution when they reach timeout; while the solution remains assured to be consistent, there is no guarantee in this case that it fits the expected optimisation criteria. If `true', opam willcontinue with a warning, if `false' a timeout is an error. Currently only the builtin-z3 backend handles this degraded case.

OPAMSOLVERTIMEOUT change the time allowance of the solver. Default is 60.0, set to 0 for unlimited. Note that all solvers may not support this option.

OPAMSOLVERTOLERANCE changes the tolerance towards the solver choosing an unoptimized solution (i.e. might pull outdated packages). Typical values range from 0.0 (best solution known to the solver) to 1.0 (unoptimized solution). Default is 0.0. This option is useful in case the solver can't find a solution in a reasonable time (see $OPAMSOLVERTIMEOUT). Note that all solvers may not support this option.

OPAMSTATS Removed in 2.4.

OPAMSTATUSLINE display a dynamic status line showing what's currently going on on the terminal. (one of one of always, never or auto)

OPAMSTRICT fail on inconsistencies (file reading, switch import, etc.).

OPAMSWITCH see option `--switch'. Automatically set by `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE see install option `--unlock-base'.

OPAMUPGRADECRITERIA specifies user preferences for dependency solving when performing an upgrade. Overrides OPAMCRITERIA in upgrades if both are set. See also option --criteria.

OPAMUSEINTERNALSOLVER see option `--use-internal-solver'.

OPAMUSEOPENSSL Removed in 2.2.

OPAMUTF8 use UTF8 characters in output (one of one of always, never or auto). By default `auto', which is determined from the locale).

OPAMUTF8MSGS use extended UTF8 characters (camels) in opam messages. Implies OPAMUTF8. This is set by default on macOS only.

OPAMVALIDATIONHOOK if set, uses the `%{hook%}' command to validate an opam repository update.

OPAMVERBOSE see option `--verbose'.

OPAMVERBOSEON see option --verbose-on

OPAMVERSIONLAGPOWER do not use.

OPAMWITHDEVSETUP see install option `--with-dev-setup'.

OPAMWITHDOC see install option `--with-doc'.

VERSIÓN CLI

Todos los scripts e invocaciones programáticas de opam deben usar `--cli' para asegurar que funcionen sin problemas con versiones futuras del cliente opam. Adicionalmente, las entradas de blog u otra documentación pueden beneficiarse, ya que evita que la información se vuelva obsoleta.

Aunque opam solo admite raíces (~/.opam/) para la versión actual, proporciona compatibilidad retroactiva para su interfaz de línea de comandos.

Dado que el soporte de la versión CLI se añadió solo en opam 2.1, use OPAMCLI para seleccionar el soporte 2.0 (ya que opam 2.0 simplemente lo ignorará), y `--cli=2.1' para versiones 2.1 (o posteriores), ya que una variable de entorno que controla el análisis de sintaxis es frágil. Con este fin, opam muestra una advertencia si OPAMCLI especifica una versión válida distinta de 2.0, y también si se especifica `--cli=2.0'.

La versión de la línea de comandos se selecciona utilizando la opción `--cli' o la variable de entorno OPAMCLI. `--cli' puede especificarse más de una vez, donde la última instancia tiene precedencia. OPAMCLI solo se inspecciona si `--cli' no se proporciona.

ESTADO DE SALIDA

Como excepción a lo siguiente, el comando `exec' devuelve 127 si el comando no se encontró o no se pudo ejecutar, y el valor de salida del comando en caso contrario.

0
Éxito, o verdadero para consultas booleanas.
1
Falso. Devuelto cuando se espera un valor booleano, por ejemplo, al ejecutar con --check, o para consultas como opam lint.
2
Argumentos incorrectos de la línea de comandos, o argumentos de la línea de comandos que apuntan a un contexto inválido (por ejemplo, archivo que no sigue el formato esperado).
5
No encontrado. Solicitaste algo (paquete, versión, repositorio, etc.) que no se pudo encontrar.
10
Abortado. La operación requirió confirmación, la cual no se dio.
15
No se pudieron adquirir los bloqueos necesarios para la operación.
20
No hay solución para la solicitud del usuario. Esto puede ser causado por solicitar la instalación de dos paquetes incompatibles, por ejemplo.
30
Error en la definición del paquete, u otros archivos de metadatos. Usar --strict genera este error con más frecuencia.
31
Error en el script del paquete. Algunas operaciones del paquete no tuvieron éxito. Esto puede ser un error en los paquetes o una incompatibilidad con tu sistema. Esto puede ser un error parcial.
40
Error de sincronización. No se pudieron obtener algunos remotos de la red. Esto puede ser un error parcial.
50
Error de configuración. La configuración de Opam o del sistema no permite la operación y necesita ser corregida.
60
Fallo del solucionador. El solucionador no pudo devolver una respuesta sólida. Puede deberse a un solucionador externo roto o a un error en la configuración del solucionador.
99
Error interno. Algo salió mal, probablemente debido a un error en opam en sí.
130
Interrupción del usuario. Se recibió SIGINT, generalmente debido a que el usuario presionó Ctrl-C.
0
en caso de éxito.
123
en errores indiscriminados reportados en la salida estándar de error.
124
en errores de análisis de línea de comandos.
125
en errores internos inesperados (bugs).
