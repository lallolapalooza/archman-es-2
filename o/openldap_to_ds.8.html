NOMBRE

openldap_to_ds

SINOPSIS

openldap_to_ds [-h] [-v] [--confirm] [--ignore-overlay [IGNORE_OVERLAY ...]] [--ignore-schema-oid [IGNORE_SCHEMA_OID ...]] [--ignore-attribute [IGNORE_ATTRIBUTE ...]] [-D BINDDN] [-w BINDPW] [-W] [-y PWDFILE] [-Z] instancia slapd_config [slapd_ldif ...]

DESCRIPCIÓN

Migrar de OpenLDAP a 389 Directory Server.

Este comando automatiza el proceso de conversión de un servidor OpenLDAP a una instancia de 389 Directory Server. Es un esfuerzo de "mejor intento" ya que OpenLDAP y 389 Directory Server no son idénticos, por lo que algunas características aún pueden requerir migración manual o no se pueden migrar en absoluto. Esta herramienta tiene como objetivo migrar la mayoría del contenido principal, como datos de la base de datos, configuración de índices, esquema y algunas capas (plugins).

Contenido que podemos migrar:

* Esquema * Contenido de la base de datos (desde copia de seguridad ldif) * Índices de la base de datos * Capa MemberOf (memberof) * Capa de Integridad Referencial (refint) * Capa de Atributo Único (unique)

Algunos contenidos que *no* se pueden migrar incluyen algunas capas (plugins), controles de acceso y configuración de replicación. Ejemplos de plugins que no se pueden migrar:

* Registro de Acceso/Auditoría (integrado en 389-ds por defecto) * Encadenamiento (Requiere migración manual, puede no ser equivalente) * Restricciones (No hay plugin equivalente) * Servicios de Directorio Dinámico (Requiere migración manual a la Capa de Clases de Servicio) * Grupos/Listas Dinámicos (Requiere migración manual a la Capa de Roles) * Caché Proxy (No hay plugin equivalente, 389-ds soporta réplicas de solo lectura) * Política de Contraseñas (Integrada en 389-ds, requiere migración manual) * Rewrite/Remap (No hay plugin equivalente) * Proveedor Sync (Requiere migración manual a la Replicación O Capa de Sincronización de Contenido) * Ordenación de Valores (No hay plugin equivalente)

Esto debe ejecutarse en el servidor que ejecuta la instancia de Directorio 389, ya que requiere acceso al sistema de archivos. Debe ejecutar esta herramienta como el usuario root o dirsrv.

Se requiere lo siguiente de su instancia de openldap:


* Directorio de configuración slapd.d en formato ldif/dinámico
* (opcional) copia de seguridad del archivo ldif de la base de datos desde slapcat

Estos se pueden crear en el host de OpenLDAP y copiar al host del Directorio 389. No se aplican acciones destructivas a la instancia de OpenLDAP.

Si ya está utilizando el formato ldif/dinámico de /etc/openldap/slapd.d, debe hacer una copia de este para usarla en la migración.


cp -a /etc/openldap/slapd.d /root/slapd.d

Si está utilizando el archivo de configuración slapd.conf, puede convertirlo a la configuración dinámica sin afectar su instancia en ejecución con:


slaptest -f /etc/openldap/slapd.conf -F /root/slapd.d

Para permitir opcionalmente que el contenido de su base de datos sea migrado, puede crear una copia de seguridad ldif del contenido que 389 Directory Server pueda importar. Debe ejecutar esto para cada backend (sufijo) de su instancia con el comando:


# Si usa el formato de configuración slapd.conf
slapcat -f /etc/openldap/slapd.conf -b SUFFIX -l /root/suffix.ldif
# Si usa el formato de configuración slapd.d
slapcat -F /etc/openldap/slapd.d -b SUFFIX -l /root/suffix.ldif

Ya debe tener un 389 Directory Server en el que quiera importar. Puede crearlo con la herramienta `dscreate`. Los datos y la configuración en esta instancia SERÁN modificados o eliminados (es decir, acciones potencialmente destructivas).

Se recomienda encarecidamente probar esta herramienta en un sistema no productivo primero para asegurarse de que el proceso y los cambios se entiendan.

Esto solo necesita ejecutarse en la primera instancia en una topología de 389 Directory Server. Todas las demás réplicas deben configurarse a partir de esta instancia después de la migración.

instancia
El nombre de la instancia de 389-ds a la que se migrarán los datos de openldap
slapd_config
La ruta a la configuración slapd.d de openldap que se migrará
slapd_ldif
La ruta a los LDIF exportados de la base de datos que se importarán.

OPCIONES

-v, --verbose
Mostrar rastreo de operaciones detallado durante la ejecución del comando
--confirm
Confirmar que desea aplicar estas acciones de migración a la instancia de 389-ds. Por defecto, no se toman acciones.
--ignore-overlay [IGNORE_OVERLAY ...]
Ignorar la migración de la configuración de las siguientes capas de openldap a plugins equivalentes de 389-ds. Las opciones válidas son memberof, refint, unique.
--ignore-schema-oid [IGNORE_SCHEMA_OID ...]
Ignorar la migración de los siguientes OIDs de atributos o clases de esquema de openldap a 389-ds. Esto *puede* crear un esquema inconsistente que podría causar que la migración falle. Usar con precaución.
--ignore-attribute [IGNORE_ATTRIBUTE ...]
Ignorar los siguientes atributos de las entradas que se cargan desde el LDIF. Por ejemplo, es posible que no desee importar hash de contraseñas de usuario.
-D BINDDN, --binddn BINDDN
La cuenta de 389 Directory Server para enlazar para ejecutar operaciones de migración
-w BINDPW, --bindpw BINDPW
Contraseña para binddn
-W, --prompt
Solicitar la contraseña para el DN de enlace
-y PWDFILE, --pwdfile PWDFILE
Especifica un archivo que contiene la contraseña para el binddn
-Z, --starttls
Conectarse a 389 Directory Server con StartTLS
