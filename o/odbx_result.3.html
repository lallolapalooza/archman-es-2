NOMBRE

odbx_result - Recupera un conjunto de resultados del servidor de base de datos

SINOPSIS

#include <opendbx/api.h>


int odbx_result
(odbx_t* handle, odbx_result_t** result, struct timeval* timeout, unsigned long chunk);

DESCRIPCIÓN

Recupera el resultado de una sentencia de consulta enviada por odbx_query() desde el servidor de base de datos. Después de que una sentencia se haya ejecutado correctamente, un objeto asignado dinámicamente que representa el conjunto de resultados se almacena en result, el cual debe ser liberado posteriormente por odbx_result_finish(). Los conjuntos de resultados para sentencias tipo SELECT devueltos con éxito por esta función pueden ser procesados llamando a odbx_row_fetch() hasta que todas las filas sean recuperadas. Si la sentencia fue un INSERT, UPDATE, DELETE o una sentencia similar, el número de filas afectadas está disponible a través de odbx_rows_affected().

Si ocurre un tiempo de espera o un error, el puntero result se establece a NULL. En caso de tiempo de espera, se debe llamar de nuevo a odbx_result() porque la consulta no se cancela. Esta función debe ser llamada varias veces hasta que devuelva cero, incluso si la consulta contiene solo una sentencia. De lo contrario, se producirá una fuga de memoria y odbx_query() devolverá un error.

El tercer parámetro (timeout) restringe el tiempo que la función espera un resultado del servidor. Puede ser NULL para esperar hasta que llegue un resultado. De lo contrario, puede contener cualquier número de segundos y microsegundos en una estructura timeval para esperar. La estructura timeval debe establecerse cada vez antes de llamar a odbx_result() porque su contenido puede ser modificado por la función. Si el servidor no responde dentro del tiempo de espera, ¡la consulta no se cancela! En su lugar, la siguiente llamada a esta función esperará el mismo conjunto de resultados. La espera del tiempo especificado puede ser implementada por los backends si es posible, pero no hay garantía. Si no, odbx_result() no devolverá hasta que llegue una respuesta.

Dependiendo de la biblioteca nativa de la base de datos, puede ser posible recuperar todas las filas a la vez (si chunk es cero), una por una o más de una fila a la vez. Todos los valores positivos, incluido el cero, son permitidos como valores para chunk. Si la paginación (más de una fila a la vez) no es compatible con el backend, usará "una por una" o "todas a la vez" si esta es la única opción proporcionada.

VALOR DE RETORNO

odbx_result() devuelve ODBX_RES_ROWS ("3") si hay un conjunto de resultados disponible y cero si no se devolverán más resultados para la última cadena de consulta enviada a través de odbx_query() exitosamente. ODBX_RES_NOROWS ("2") se devuelve si la sentencia se ejecutó correctamente pero no devolverá un conjunto de resultados (como para sentencias INSERT, UPDATE y DELETE) y ODBX_RES_TIMEOUT ("1") indica un tiempo de espera. Tan pronto como se devuelve ODBX_RES_DONE ("0"), se procesaron los conjuntos de resultados disponibles. Las constantes nombradas están disponibles desde OpenDBX 1.3.2 y los números entre paréntesis deben usarse en su lugar si una versión anterior es la base para el desarrollo de la aplicación.

Devuelve un código de error cuyo valor es menor que cero si una de las operaciones no se pudo completar con éxito. Los códigos de error posibles se enumeran en la sección de errores y pueden ser alimentados a odbx_error() y odbx_error_type() para obtener más detalles. En este caso, los backends son responsables de liberar las estructuras de datos que asignaron dentro de la función y de limpiar el conjunto de resultados erróneo si hay uno disponible. Los backends también establecerán el puntero result dado a NULL antes de devolver el error. Sin embargo, si ocurrió un error no fatal, es posible recuperar más conjuntos de resultados y esto es necesario antes de llamar a odbx_query() en la misma conexión nuevamente.

ERRORES

-ODBX_ERR_BACKEND
La biblioteca nativa de la base de datos devolvió un error
-ODBX_ERR_PARAM
handle o result son NULL o handle es inválido
-ODBX_ERR_NOMEM
Falló la asignación de memoria requerida para el resultado
-ODBX_ERR_RESULT
Esperar una respuesta del servidor falló porque la conexión se perdió
